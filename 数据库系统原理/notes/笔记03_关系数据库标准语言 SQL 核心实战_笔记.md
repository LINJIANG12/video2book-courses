# 关系数据库标准语言 SQL 核心实战

## 语言架构特质与模式定义体系

### SQL 语言特性与核心动词

* **结构化查询语言（Structured Query Language，SQL）**

    * > **定义**：集数据定义、数据操纵与数据控制功能于一体的关系数据库标准语言。

    * 综合统一架构：将数据定义语言（DDL）、数据操纵语言（DML）和数据控制语言（DCL）有机融为一体，全生命周期使用统一样式语法。

    * 高度非过程化：用户仅需声明期望检索或操作的目标结果，底层存取路径选择、算法调度与物理优化由数据库内核自主完成。

    * 面向集合操作：操作对象与输出结果皆为关系（二维表）或元组集合，支持一次性对多条记录执行批处理计算。

    * 双重运行模式：既可作为独立语言在交互式终端执行，亦可作为嵌入式语言嵌入 C、C++、Java、Python 等高级主语言中协同运行。

* **SQL 核心动词体系（Core Verbs）**

    * > **定义**：驱动关系数据库全生命周期操作的 9 个基础核心动词集合。

    * 数据定义语言（DDL）包含 3 个核心动词：`CREATE`（创建对象元数据框架）、`DROP`（删除对象物理或逻辑定义）、`ALTER`（修改表结构或元数据约束）。

    * 数据操纵语言（DML）包含 4 个核心动词：`SELECT`（检索投影数据集合）、`INSERT`（写入新元组记录）、`UPDATE`（修改既有属性值）、`DELETE`（移除特定元组记录）。

    * 数据控制语言（DCL）包含 2 个核心动词：`GRANT`（授予用户操作权限）、`REVOKE`（收回已分配的用户权限）。

### 数据库三级模式与 SQL 作用域

* **SQL 三级模式映射（Three-Schema Architecture Mapping）**

    * > **定义**：SQL 语法结构在关系数据库外模式、模式与内模式中的对应分工机制。

    * 外模式（External Schema）对应视图（View）：面向局部用户展示的虚表，数据库仅在数据字典中保留视图定义，不独立存储物理元组。

    * 模式（Schema）对应基本表（Base Table）：独立存在的物理实体结构，一个基本表可以对应一个或多个底层物理存储文件。

    * 内模式（Internal Schema）对应存储文件（Storage File）：物理层面的底层数据文件与索引文件，由操作系统和数据库内核底层调度。

    * 作用域边界：SQL 语句能够直接访问和操纵的范围严格限定在基本表与视图层，底层物理存储细节对上层应用完全透明。

* **数据字典（Data Dictionary，DD）**

    * > **定义**：数据库管理系统内部系统化登记整个信息架构元数据的核心系统目录。

    * 六大登记维度：登记数据项（名称、类型、长度、取值范围）、数据结构（属性组合关系）、数据流（流动路径与吞吐频度）、数据存储（物理表与归档库）、处理过程（加工逻辑与前置后置条件）以及外部实体（数据源与宿主接口）。

    * 系统交付规范：作为工程架构的技术说明词典，支撑系统后续维护人员准确识别字段语义与业务约束。

### 模式生命周期与命名空间管理

* **模式（Schema）**

    * > **定义**：数据库管理系统内核中为特定用户或应用开辟的独立命名空间。

    * 创建语法：`CREATE SCHEMA <模式名> AUTHORIZATION <用户名>;`；若缺省模式名，系统默认将用户名作为模式名。

    * 命名隔离特性：同一模式命名空间内，基本表、视图与索引名称严禁冲突；不同模式命名空间之间允许存在同名表对象。

    * 嵌套定义能力：定义模式的同时，允许在其后连续追加子表定义、视图定义以及权限授予子句。

* **模式删除策略（DROP SCHEMA）**

    * > **定义**：销毁已存在模式命名空间时的防御性执行机制。

    * 语法格式：`DROP SCHEMA <模式名> <CASCADE | RESTRICT>;`。

    * 级联删除（CASCADE）：无视模式内部是否包含下属对象，强行将该模式连同其所辖的基本表、视图、索引与存储过程彻底清空销毁。

    * 限制性删除（RESTRICT）：模式删除的防御性策略；若检测到该模式下残留任何下属对象，数据库引擎立刻中断执行并抛出异常。

## 基本表定义与完整性约束

### 基本表建立与数据类型体系

* **基本表创建（CREATE TABLE）**

    * > **定义**：构建关系数据库物理实体存储框架与完整性约束规则的 DDL 语句。

    * 通用语法骨架：
        ```sql
        CREATE TABLE <表名> (
            <列名> <数据类型> [<列级完整性约束条件>],
            ...
            [, <表级完整性约束条件>]
        );
        ```

    * 表与模式绑定方式：支持在表名前添加模式显式前缀（如 `CREATE TABLE "S-T".Student (...)`）、在模式定义语句内部嵌套定义，或通过 `SET search_path` 切换当前上下文路径。

* **SQL 常用数据类型体系（Data Types）**

    * > **定义**：规约属性列物理存储格式、取值范围与内存开销的规范集合。

    * 定长字符型 `CHAR(n)`：固定分配 $n$ 字节存储空间，实际长度不足时自动右补空格，适用于学号、身份证号等定长属性。

    * 变长字符型 `VARCHAR(n)`：依据实际文本长度动态分配存储空间并记录长度前缀，适用于姓名、地址等离散文本。

    * 整型系列：标准 4 字节整数 `INT`/`INTEGER`、2 字节小整数 `SMALLINT`、8 字节大整数 `BIGINT`。

    * 高精度数值型 `NUMERIC(p, s)` / `DECIMAL(p, s)`：总有效位数长 $p$ 位且小数点后保留 $s$ 位精度的定点小数，彻底杜绝浮点计算误差。

    * 逻辑与时空类型：仅表示真假状态的 `BOOLEAN`、记录“年-月-日”的 `DATE` 以及记录“时:分:秒”的 `TIME`。

### 实体完整性与表级复合主码

* **实体完整性（Entity Integrity）**

    * > **定义**：关系模型中保证主码属性唯一且不可取空值的基石约束。

    * 单列主码列级约束：在列定义后追加 `PRIMARY KEY`，语义等价于施加 `UNIQUE`（全局唯一）与 `NOT NULL`（非空）双重限制。

    * 复合主码约束表级声明：当单一属性无法唯一标识元组而需联合多个属性作为主码时，必须作为表级完整性约束在末尾统一声明 `PRIMARY KEY (列1, 列2)`。

    * > **易错点**：⚠️ 严禁将复合主码拆分为多个列级 `PRIMARY KEY` 定义。关系模型严格规定一张基本表只能有一个主码，分立声明会被解析为非法的“多主码”从而触发语法错误。

### 参照完整性与自引用外码

* **外码约束（Foreign Key Constraint）**

    * > **定义**：建立表与表之间或表自身内部元组关联参照关系的完整性约束。

    * 跨表外码语法：作为表级约束在建表语句末尾声明 `FOREIGN KEY (外码列) REFERENCES 目标表(目标主码)`。

    * 选课表（SC）典型参照体系：
        ```sql
        CREATE TABLE SC (
            Sno   CHAR(9),
            Cno   CHAR(4),
            Grade SMALLINT,
            PRIMARY KEY (Sno, Cno),
            FOREIGN KEY (Sno) REFERENCES Student(Sno),
            FOREIGN KEY (Cno) REFERENCES Course(Cno)
        );
        ```

* **自引用外码（Self-referencing Foreign Key）**

    * > **定义**：数据表中的某一外码属性参照引用该表自身主码属性的递归引用形态。

    * 课程先行课模型：课程表 `Course(Cno, Cname, Cpno, Ccredit)` 中，先行课号 `Cpno` 属于外码，参照引用本表的主码 `Cno`。

    * 语法实现：在 `Course` 建表末尾追加 `FOREIGN KEY (Cpno) REFERENCES Course(Cno)`；若课程无先修课，该外码字段取空值（NULL）。

### 基本表结构演进与安全销毁

* **基本表结构修改（ALTER TABLE）**

    * > **定义**：在保留既有物理数据前提下动态变更基本表模式定义的 DDL 语句。

    * 追加属性列：`ALTER TABLE 表名 ADD [COLUMN] 新列名 数据类型 [约束];`；无论表中已存在多少历史数据，新增属性列一律无条件填赋为 `NULL`。

    * 修改数据类型：`ALTER TABLE 表名 ALTER COLUMN 列名 新数据类型;`；体现非过程化特性，直接声明最终期望格式。

    * 追加表级约束：`ALTER TABLE 表名 ADD <表级约束>;`，例如向已有课程表追加课程名唯一约束 `ALTER TABLE Course ADD UNIQUE(Cname);`。

    * 删除列或约束：使用 `DROP COLUMN` 移除列，使用 `DROP CONSTRAINT` 移除已命名的约束条件。

* **基本表安全销毁（DROP TABLE）**

    * > **定义**：彻底销毁基本表物理存储文件与其在数据字典中元数据定义的 DDL 语句。

    * 语法格式：`DROP TABLE <表名> [RESTRICT | CASCADE];`。

    * 限制性删除（RESTRICT）：默认防御机制；若检测到存在依赖于该表的外部视图、触发器或外码约束，数据库强行拦截并拒绝删除。

    * 级联删除（CASCADE）：无视依赖关系，销毁基本表的同时自动连带清空所有依附于该表的视图、索引与触发器对象。

## 索引机理与物理存储组织

### 索引核心数据结构与特性

* **数据库索引（Index）**

    * > **定义**：以额外存储空间和写入开销为代价，大幅加速数据检索效率的核心辅助数据结构。

    * 管理职责划分：由数据库管理员或数据表所有者显式创建，由数据库管理系统内核在数据发生增删改时自动维护，对最终用户和查询逻辑透明。

    * 常见索引物理结构：
        * B+ 树索引：工业界应用最广的动态平衡多路查找树；内部节点仅存放键值与指针，所有叶子节点汇聚数据指针并通过双向链表相连，高度平衡且区间检索开销稳定。
        * 哈希索引（Hash Index）：利用散列函数将键值映射至离散桶地址，等值点查时间复杂度趋近 $O(1)$，但完全无法支持范围检索与排序输出。
        * 顺序文件索引：按键值物理升序排布，利用折半查找等方式快速定位扇区。
        * 位图索引（Bitmap Index）：利用位向量处理列值重复率极高的低基数字段，通过按位逻辑与或运算实现极速过滤。

### 聚簇索引与非聚簇索引

* **聚簇索引（Clustered Index）**

    * > **定义**：基本表中元组的物理存储顺序与该索引的逻辑排序完全重合的专用索引。

    * 数量边界约束：由于物理磁盘上元组的物理排列次序唯一，一张基本表至多只能设立一个聚簇索引。

    * 性能适用场景：针对大量连续范围查询、按照排序列频繁分组聚合的场景可大幅减少磁盘物理寻道次数。

* **非聚簇索引（Non-clustered Index）**

    * > **定义**：索引逻辑顺序与物理数据存储顺序相互独立的辅助索引结构。

    * 物理组织特征：叶子节点存放的是对应数据元组的物理地址指针或主键值，一张基本表允许建立多个非聚簇索引。

### 索引生命周期与维护规范

* **索引创建与管理（Index Lifecycle）**

    * > **定义**：索引对象的创建、更名与物理销毁操作体系。

    * 创建语法：
        ```sql
        CREATE [UNIQUE] [CLUSTER] INDEX <索引名>
        ON <表名>(<列名> [ASC | DESC] [, ...]);
        ```

    * 关键字语义：`UNIQUE` 强制该列值全局唯一，拦截重复写入；`ASC` 表示升序排布（默认缺省），`DESC` 表示降序排布。

    * 维护操作限制：索引不支持调整内部列结构；修改操作仅支持更名 `ALTER INDEX <旧名> RENAME TO <新名>;`，废弃时调用 `DROP INDEX <索引名>;` 彻底释放物理存储。

## 单表数据查询与分组聚合

### 查询块核心子句与执行时序

* **SQL 查询块（Query Block）**

    * > **定义**：由一组具备严格执行逻辑时序的子句构成的基础数据检索单元。

    * 完整语法骨架：
        ```sql
        SELECT [ALL | DISTINCT] <目标列表达式> [, <目标列表达式>] ...
        FROM <表名或视图名> [AS <别名>] [, ...]
        [WHERE <条件表达式>]
        [GROUP BY <列名1> [HAVING <条件表达式>]]
        [ORDER BY <列名2> [ASC | DESC]];
        ```

    * 逻辑执行流水线时序：
        ```text
        [FROM 载入数据源] 
            ──> [WHERE 行级初筛] 
            ──> [GROUP BY 划分分组] 
            ──> [聚集函数求值] 
            ──> [HAVING 组级过滤] 
            ──> [SELECT 属性投影与去重] 
            ──> [ORDER BY 最终排序]
        ```

    * 关系代数语义映射：`SELECT` 对应投影算子 $\pi$；`FROM` 对应关系定义域 $R$；`WHERE` 对应选择算子 $\sigma$。

### 目标列表达式高级投影与去重

* **目标列表达式（Target List Expression）**

    * > **定义**：在内存处理流程中动态代入当前扫描元组属性并求值的变量表达式。

    * 算术运算求值：支持在输出阶段计算派生属性（如已知年龄计算出生年份 `SELECT Sname, 2022 - Sage FROM Student;`）。

    * 常量与标量函数：字符串字面量由单引号包裹作为常量列输出（如 `'Year of Birth:'`）；支持嵌套标量函数转换文本（如 `LOWER(Sdept)`）。

    * 列别名解耦：在目标表达式后通过空格或 `AS` 指定别名，将展示层表头与底层物理列名彻底解耦。

* **重复元组剔除机制（DISTINCT）**

    * > **定义**：对查询结果集执行集合归纳并剔除完全相同数据行的控制策略。

    * 语法语义：缺省为 `ALL`，保留所有重复元组；显式声明 `DISTINCT` 则对结果集执行哈希或排序去重（如 `SELECT DISTINCT Sno FROM SC;`）。

### 比较范围与模糊匹配谓词

* **行级比较与范围谓词（Comparison & Range Predicates）**

    * > **定义**：在 WHERE 子句中针对单个元组执行真值判定的布尔表达式。

    * 比较运算符：支持 `=`、`>`、`<`、`>=`、`<=` 以及 `!=` 或 `<>`。

    * 连续闭区间谓词：`列名 BETWEEN 下限 AND 上限` 严格等价于 `列名 >= 下限 AND 列名 <= 上限`，检索范围包含两端边界值；反向判定使用 `NOT BETWEEN ... AND ...`。

    * 离散枚举成员谓词：使用 `IN ('值1', '值2', ...)` 判定字段值是否落入指定常量集合，等价于多重 `OR` 联结；反向判定使用 `NOT IN`。

* **字符串模糊匹配（LIKE Predicate）**

    * > **定义**：针对字符类型属性进行模式比对与部分匹配的检索谓词。

    * 通用格式：`[NOT] LIKE '<匹配串>' [ESCAPE '<换码字符>']`。

    * 核心通配符规则：
        * 百分号 `%`：代表任意长度的字符串（长度可为 0 或任意正整数）。
        * 下划线 `_`：严格代表任意单个字符。

    * ESCAPE 转义机制：当字段自身包含 `%` 或 `_` 时，通过 `ESCAPE` 指定换码字符屏蔽通配语义（例如匹配课程名 `DB_Design` 写作 `WHERE Cname LIKE 'DB\_Design' ESCAPE '\'`）。

### 查询结果排序控制与空值特征

* **查询结果排序（ORDER BY）**

    * > **定义**：控制查询输出结果集物理排列次序的子句。

    * 单列与多列级联规则：默认为升序 `ASC`，降序显式声明 `DESC`；多列排序遵循“左主右次”原则，仅当主排序列属性值相同时才启用次排序列排序。

    * 空值排序分布特性：在逻辑比对中通常将 NULL 视为极大值（“空值跟大头”）；降序 `DESC` 时空值排在最前列，升序 `ASC` 时空值排在最后端。

### 聚集函数统计与分组处理

* **SQL 标准聚集函数（Aggregate Functions）**

    * > **定义**：以一组列值为输入并计算输出单一标量汇总值的统计函数。

    * `COUNT(*)`：统计结果集中的物理行数，不忽略包含 NULL 的行。

    * `COUNT([DISTINCT | ALL] <列名>)`：统计指定列中非 NULL 值的个数，附加 `DISTINCT` 则剔除重复值后计数。

    * `SUM` 与 `AVG`：计算数值列中所有非 NULL 属性值的总和与算术平均值。

    * `MAX` 与 `MIN`：返回指定列中非 NULL 属性值的最大值与最小值。

* **分组统计子句（GROUP BY）**

    * > **定义**：按指定属性列将元组集合切分为多个独立分组的分类汇总子句。

    * 运行机理：一旦引入 `GROUP BY`，聚集函数的作用域即由全局转向局部，分别独立作用于各个划分出来的分组桶。

    * 分组投影规则：`SELECT` 目标列表中除聚集函数外，只能包含 `GROUP BY` 后面显式列出的分组基准列。

### 行级筛选与组级筛选本质辨析

* **组级筛选子句（HAVING）**

    * > **定义**：对 `GROUP BY` 分组汇总计算后的统计结果施加过滤条件的专用子句。

    * 语法依赖：必须依附于 `GROUP BY` 子句存在，用于剔除统计指标不达标的组（例如筛选选课门数超 3 门的学生：`GROUP BY Sno HAVING COUNT(*) > 3`）。

* **WHERE 与 HAVING 机制对比**

    * > **定义**：行级过滤与组级筛选在执行流水线中的本质差异体系。

    | 比较维度 | WHERE 子句 | HAVING 子句 |
    | :--- | :--- | :--- |
    | 作用对象 | 针对基表或视图抽取的原始元组（行级） | 针对划分聚合完成后的各个组（组级） |
    | 执行时机 | 在数据分组（GROUP BY）之前执行 | 在数据分组与聚集计算完成之后执行 |
    | 聚集函数支持 | 严格禁止在谓词中直接包含聚集函数 | 允许且通常必须在谓词中包含聚集函数 |
    | 上下文依赖 | 可独立存在于任何基础查询块中 | 必须依赖于 `GROUP BY` 分组上下文 |

## 多表连接查询体系

### 笛卡尔积与连接条件优先法则

* **多表连接查询（Join Query）**

    * > **定义**：跨越两个或两个以上关系表获取完整关联属性的联合检索操作。

    * 关系代数底层机理：系统首先求出各目标表的笛卡尔积（穷举所有可能的元组组合），随后依据连接条件剔除不匹配的行，最终应用业务条件完成过滤。

    * 连接条件优先铁律：只要在 `FROM` 子句中列出了两个或两个以上的关系表，就必须首先在 `WHERE` 子句中写明表间的连接匹配条件（如 `Student.Sno = SC.Sno`）。

    * 遗漏后果：若遗漏连接条件，查询将退化为全量笛卡尔积，不仅结果失去业务意义，更会瞬间耗尽系统缓冲池与运算资源。

### 等值连接与自然连接

* **等值连接与自然连接（Equi-Join & Natural Join）**

    * > **定义**：基于两表公共属性列的等值比对建立关联的连接形态。

    * 等值连接：连接运算符为等号 `=`，查询结果中两表的同名公共属性列会被完整保留两次。

    * 自然连接实现：关系代数中的自然连接自动消除重复公共列；在 SQL 传统查询块中，必须在 `SELECT` 列表中显式逐一罗列所需字段以手动规避重复投影。

### 自身连接与别名表机制

* **自身连接（Self-Join）**

    * > **定义**：同一张关系表内部不同元组之间进行多层次关联匹配的连接技术。

    * 表复制机理：为同一张物理表赋予不同的别名（Alias），在逻辑上构建两张独立的虚拟表，将单表的多层递归检索转化为双表的常规跨表连接。

    * 间接先修课典型案例：
        ```sql
        SELECT FIRST.Cno, SECOND.Cpno
        FROM Course FIRST, Course SECOND
        WHERE FIRST.Cpno = SECOND.Cno;
        ```
        `FIRST` 代表当前课程，`SECOND` 代表先行课程，通过 `FIRST.Cpno = SECOND.Cno` 建立关联桥梁并提取间接先修课号。

### 外连接与悬浮元组保留

* **外连接（Outer Join）**

    * > **定义**：在连接操作中强制保留未匹配成功的主体元组并以空值填充缺失字段的连接模式。

    * 悬浮元组（Dangling Tuples）：在常规等值连接中因在另一侧缺少关联匹配项而被系统默认丢弃的元组。

    * 外连接分类体系：
        * 左外连接（`LEFT OUTER JOIN`）：以左表为主体，保留左表全部元组；右表无匹配项时对应属性全数补填 NULL。
        * 右外连接（`RIGHT OUTER JOIN`）：以右表为主体，保留右表全部元组；左表无匹配项时补填 NULL。
        * 全外连接（`FULL OUTER JOIN`）：同时保留两侧数据表的全部元组，任意一侧缺失均以 NULL 占位。

### 多表级联连接

* **多表级联连接（Multi-table Cascade Join）**

    * > **定义**：查询涉及三张及以上数据表时，沿着主外码参照链条逐级展开的级联匹配机制。

    * 学生-选课-课程三表级联规范：
        ```sql
        SELECT Student.Sno, Sname, Course.Cname, SC.Grade
        FROM Student, SC, Course
        WHERE Student.Sno = SC.Sno 
          AND SC.Cno = Course.Cno;
        ```

    * 执行过程：引擎首先依据 `Sno` 将学生信息与选课记录绑定，再依据 `Cno` 关联出具体的课程名称，最终在一行元组中汇总呈现三表属性。

## 嵌套查询与派生表优化

### 查询块黑盒与中间结果传导

* **嵌套查询（Nested Query）**

    * > **定义**：将一个 `SELECT-FROM-WHERE` 查询块嵌入到另一个查询块的 WHERE 子句或 HAVING 短语内部的查询结构。

    * 黑盒传导机理：每个查询块具备独立的输入与输出端；内层子查询（Subquery）的输出结果集直接作为外层父查询（Parent Query）条件判定的输入数据流。

    * 排序语法禁忌：子查询内部严禁使用 `ORDER BY` 子句；子查询仅生成服务于外层判定的临时中间集，中间集排序无业务意义且浪费算力，排序操作只能位于最外层父查询末尾。

### 不相关子查询与相关子查询

* **不相关子查询（Uncorrelated Subquery）**

    * > **定义**：子查询内部的执行条件完全独立、不依赖外层父查询任何属性的嵌套形态。

    * 执行生命周期：采用自底向上、从里向外的顺序执行；内层子查询独立运算一次并输出结果集，随后交付外层父查询一次性完成筛选。

* **相关子查询（Correlated Subquery）**

    * > **定义**：子查询的过滤条件中直接引用了外层父查询当前扫描元组属性的嵌套形态。

    * 执行演进机制：外层查询每扫描抽取一行元组，就将该元组的属性值代入内层子查询运算一次，依据内层返回的真值或标量决定外层当前行是否保留。

    * 超个人均分典型案例：
        ```sql
        SELECT Sno, Cno
        FROM SC x
        WHERE Grade > (
            SELECT AVG(Grade)
            FROM SC y
            WHERE y.Sno = x.Sno
        );
        ```

    * > **易错点**：⚠️ `FROM SC x` 中的 `x` 并非将表进行物理复制，而是一个元组变量（Tuple Variable），代表外层查询当前正在处理的某一行具体记录。

### 嵌套谓词语义降维与比较运算

* **集合成员谓词（IN Subquery）**

    * > **定义**：判定外层属性值是否属于内层子查询返回的结果集合之中的谓词。

    * 链条求解规范：多层嵌套遵循“最先求解的依赖写在最里层，最终输出的目标写在最外层”的装配逻辑。

* **ANY 与 ALL 谓词的语义降维**

    * > **定义**：配合大小比较运算符使用、对子查询返回的多行标量集合进行比较的谓词。

    * 谓词语义对应规则：
        * `> ANY`：大于子查询集合中任意一个值，数学本质等价于大于最小值 `> MIN`。
        * `< ANY`：小于子查询集合中任意一个值，数学本质等价于小于最大值 `< MAX`。
        * `> ALL`：大于子查询集合中的所有值，数学本质等价于大于最大值 `> MAX`。
        * `< ALL`：小于子查询集合中的所有值，数学本质等价于小于最小值 `< MIN`。

    * 降维实现准则：工程上强烈推荐直接转换为 `MAX`/`MIN` 聚集函数改写，不仅可读性高，且数据库执行效能更优。

### 存在量词谓词判定

* **存在量词谓词（EXISTS & NOT EXISTS）**

    * > **定义**：判定内层子查询是否能够产出非空元组集合的一阶逻辑谓词。

    * 真值返回特性：子查询不返回任何真实数据行，仅返回布尔值 `TRUE` 或 `FALSE`；内层结果集非空时 `EXISTS` 为真，空集时为假；`NOT EXISTS` 逻辑刚好相反。

    * 目标列通配规范：由于外层仅在乎“是否存在匹配记录”而与具体投影列无关，内层子查询目标列表统一采用通配符 `SELECT *`。

### 基于派生表的聚合解耦与查询优化

* **派生表（Derived Table）**

    * > **定义**：在父查询 FROM 子句中由子查询物化生成的带有明确命名空间的临时内存关系表。

    * 聚合解耦机制：针对相关子查询中逐行重复调用子查询的性能痛点，利用派生表预先完成 `GROUP BY` 聚合计算，随后与基表进行扁平等值连接。

    * 超均分查询派生表重构：
        ```sql
        SELECT SC.Sno, SC.Cno
        FROM SC, (
            SELECT Sno, AVG(Grade)
            FROM SC
            GROUP BY Sno
        ) AS Avg_SC(Avg_Sno, Avg_Grade)
        WHERE SC.Sno = Avg_SC.Avg_Sno 
          AND SC.Grade > Avg_SC.Avg_Grade;
        ```
        将逐行执行的复杂相关子查询转换为单次聚合与等值连接，大幅降低计算复杂度。

## 集合查询操作

### 集合查询代数条件与操作符

* **集合查询（Set Operations）**

    * > **定义**：将两个或多个 `SELECT` 查询块的输出结果集执行传统集合代数运算的操作。

    * 运算相容性前提：参与集合操作的各个查询块结果集必须具有完全相同的属性列数，且对应位置上的属性列数据类型必须相互兼容。

    * 三大基础操作符：并操作 `UNION`、交操作 `INTERSECT`、差操作 `EXCEPT`（某些商业数据库写作 `MINUS`）。

### 并交差运算与去重控制

* **并集运算与去重控制（UNION & UNION ALL）**

    * > **定义**：将多个查询结果集合并为统一样式结果集的操作。

    * `UNION` 默认行为：系统自动执行哈希或排序去重，剔除完全相同的重复元组。

    * `UNION ALL` 行为：显式保留所有重复出现的记录，不触发系统去重开销。

* **交操作与差操作（INTERSECT & EXCEPT）**

    * > **定义**：提取公共元组或执行集合排除的代数操作。

    * `INTERSECT`：输出同时存在于两个查询结果集中的公共记录。

    * `EXCEPT`：输出属于第一个查询结果集但被第二个查询结果集排徐后的剩余记录。

    * 逻辑替代价值：当单表查询中多重复合 `AND`、`OR`、`NOT` 逻辑嵌套过深时，拆解为独立查询块并应用集合运算拼装，可显著提高代码可读性与可维护性。

## 数据更新操作与三值逻辑

### 数据插入与批量灌库

* **单元组数据插入（INSERT INTO ... VALUES）**

    * > **定义**：向基本表中显式写入单条数据记录的 DML 语句。

    * 语法格式：`INSERT INTO <表名> [(<列名1>, ...)] VALUES (<常量1>, ...);`。

    * 空值处理规则：未在属性列表中声明的列自动填入 NULL；若省略属性列表，`VALUES` 必须按物理建表顺序提供全量字段值，缺漏字段显式写入 `NULL`。

    * 工程防御规范：在实际开发中禁止省略列名列表，以防底层表结构执行 `ALTER TABLE` 增删列后导致应用程序数据错位或崩溃。

* **基于子查询的批量数据插入（Bulk INSERT）**

    * > **定义**：利用子查询结果集向数据表一次性批量填充多行元组的更新操作。

    * 语法格式：`INSERT INTO <表名> [(<列名1>, ...)] <子查询>;`。

    * 执行机理：子查询从源表中按条件检索或分组汇总生成多行结果流，外部 `INSERT` 接收数据流后逐行写入目标表；输出列与目标列在数量与类型上必须严格相容。

* **更新操作完整性约束防御体系**

    * > **定义**：数据库管理系统执行更新操作时实施的三道完整性拦截防线。

    * 实体完整性校验：主码列禁止取 NULL，且插入的主码值不能与已有元组重复。

    * 参照完整性校验：外码属性值要么全为空值，要么必须能够在被参照表的主码中精准匹配。

    * 用户定义完整性校验：必须严格满足建表时声明的 `CHECK` 范围约束与业务逻辑。

### 数据修改与删除操作

* **数据修改操作（UPDATE）**

    * > **定义**：依照指定筛选谓词批量或条件调整既有元组属性值的 DML 语句。

    * 通用语法：`UPDATE <表名> SET <列名> = <表达式> [, ...] [WHERE <条件>];`。

    * 修改模式层级：包含基于主键精确修改单行元组、省略 `WHERE` 条件对全表元组实施批量统一运算（如全员年龄递增 `SET Sage = Sage + 1`），以及利用子查询跨表圈定目标元组进行修改。

* **数据删除操作（DELETE）**

    * > **定义**：将数据表中满足特定条件的物理数据元组整体移除的 DML 语句。

    * 通用语法：`DELETE FROM <表名> [WHERE <条件>];`。

    * 删除模式分类：支持单行删除、省略 `WHERE` 清空全表元组，以及配合子查询执行跨表关联删除。

### 数据清空与模式销毁本质辨析

* **DML 数据清空与 DDL 模式销毁辨析**

    * > **定义**：清空表内数据元组与彻底销毁数据表结构在系统底层的本质分界。

    | 维度 | DELETE FROM <表名> | DROP TABLE <表名> |
    | :--- | :--- | :--- |
    | 语言归属 | 数据操纵语言（DML） | 数据定义语言（DDL） |
    | 操作对象 | 仅作用于表中的**数据元组** | 作用于**基本表对象本身及其全局元数据** |
    | 系统影响 | 清空全部数据行，保留表结构、约束、索引与数据字典定义 | 彻底抹除物理文件、约束定义与数据字典元数据 |
    | 后续操作 | 表依然存在，可立即继续执行 `INSERT` 录入新数据 | 表彻底不复存在，再次访问直接报“表不存在”错误 |

### 空值语义与三值逻辑体系

* **空值（NULL）**

    * > **定义**：关系数据库中代表“未知（Unknown）”、“不存在”或“无意义”的特殊状态标识。

    * 存储与约束边界：显式声明为 `NOT NULL` 的列、受 `UNIQUE` 限制的列以及实体完整性约束的主码属性绝对禁止填入空值。

    * 专用判定语法：空值检测必须使用专用的 `IS NULL` 与 `IS NOT NULL` 谓词。

* **三值逻辑体系（Three-valued Logic）**

    * > **定义**：由于引入比较结果 `UNKNOWN` 而打破传统二值布尔体系的关系逻辑规则。

    * 算术黑洞特性：NULL 与任何具体数值进行算术运算（`+`、`-`、`*`、`/`），计算结果恒为 NULL。

    * 比较未知特性：NULL 与任何具体数值进行等值或大小比较，运算结果统一判定为 `UNKNOWN`。

    * 三值逻辑运算真值表：
        | 表达式形态 | 运算结果 | 判定机理 |
        | :--- | :--- | :--- |
        | `True AND Unknown` | **Unknown** | 整体真假取决于另一方，结果未定 |
        | `False AND Unknown` | **False** | 只要有一方为假，AND 结果必然为假 |
        | `True OR Unknown` | **True** | 只要有一方为真，OR 结果必然为真 |
        | `False OR Unknown` | **Unknown** | 一方为假，整体真假取决于未知端 |
        | `NOT Unknown` | **Unknown** | 对未知取非，结果依然未知 |

### 空值查询的边界陷阱与改写

* **空值查询边界防御**

    * > **定义**：在含有空值的业务列上执行范围检索时避免隐式过滤的改写策略。

    * > **易错点**：⚠️ 执行不及格学生查询时若直接书写 `WHERE Grade < 60`，因缺考学生的成绩为 `NULL`，`NULL < 60` 判定为 `UNKNOWN`，`WHERE` 仅放行 `TRUE` 元组，导致缺考学生被错误过滤。

    * 规范改写方案一（复合条件显式容错）：
        ```sql
        SELECT Sno
        FROM SC
        WHERE Cno = '1' AND (Grade < 60 OR Grade IS NULL);
        ```

    * 规范改写方案二（集合运算解耦合并）：
        ```sql
        SELECT Sno FROM SC WHERE Cno = '1' AND Grade < 60
        UNION
        SELECT Sno FROM SC WHERE Cno = '1' AND Grade IS NULL;
        ```

## 视图机制与虚表管理

### 视图虚表特性与定义规范

* **视图（View）**

    * > **定义**：从一个或若干个基本表（或其他视图）中导出的虚表。

    * 虚表物理特性：数据库仅在数据字典中持久化保存视图的元数据与查询定义 SQL，绝不独立开辟磁盘空间存储实体元组；基表数据变动，视图映射数据实时联动。

    * 定义语法规范：
        ```sql
        CREATE VIEW <视图名> [(<列名1> [, <列名2>]...)]
        AS <子查询>
        [WITH CHECK OPTION];
        ```

    * WITH CHECK OPTION 约束机理：若附加该子句，后续通过该视图执行 `INSERT`、`UPDATE`、`DELETE` 操作时，系统强制检查操作元组必须严格满足视图子查询中声明的 `WHERE` 条件表达式。

    * 字段继承与防御：视图属性名缺省时继承子查询输出列名；工程上禁止写 `SELECT *` 导出视图，防止基表结构演进加列后元数据错位。

### 视图构建模式分类

* **视图构建形态体系（View Architectural Patterns）**

    * > **定义**：依据数据源衍生路径划分的四类典型视图形态。

    * 行列子集视图：从单一基本表导出，仅过滤掉特定行和列，但完整保留物理表主码的一对一映射视图。

    * 多表导出视图：基于两个或多个基本表关联导出，子查询中必须明确包含主外码等值连接条件。

    * 基于视图派生的高阶视图：将已有视图作为数据源进一步嵌套派生构建的新视图。

    * 带表达式与分组统计的视图：目标列表中包含动态计算表达式或由 `GROUP BY` 分组汇总生成的统计视图。

### 视图消解机制与查询执行

* **视图消解法（View Resolution）**

    * > **定义**：数据库管理系统执行视图检索时将上层查询与底层定义重写合并的执行机理。

    * 消解执行链路：
        ```text
        [用户层发起视图查询] 
            ──> [调取数据字典中的视图定义] 
            ──> [将用户查询条件与视图 WHERE 谓词逻辑合并] 
            ──> [生成直接作用于物理基表的等价执行计划]
        ```

    * 分组统计视图查询转化：在包含 `AVG(Grade)` 的分组视图上查询超 90 分学生，消解引擎自动将其转换为作用于基表 `SC` 上的 `GROUP BY Sno HAVING AVG(Grade) >= 90` 执行。

### 视图更新准则与不可更新边界

* **视图更新准则（View Updatability Constraints）**

    * > **定义**：规约视图是否允许执行 INSERT、UPDATE 与 DELETE 操作的边界规则。

    * 可更新准则：基本行列子集视图允许执行更新操作，因其与底层基表元组保持严格的一对一对应映射。

    * 不可更新边界：任何包含算术运算、聚集函数、`GROUP BY` 分组汇总或多表连接派生出的视图，系统严格禁止执行更新。

    * 逆向不可求解机理：计算值与汇总指标无法数学逆向分解为底层多个基表元组的具体属性分配，尝试更新此类视图必须直接修改底层基表源数据。

### 视图销毁与级联控制

* **视图销毁操作（DROP VIEW）**

    * > **定义**：从系统数据字典中彻底抹除视图映射定义的 DDL 语句。

    * 语法格式：`DROP VIEW <视图名> [CASCADE | RESTRICT];`。

    * 生命周期调整原则：视图仅支持创建与删除，不支持复杂的结构修改（ALTER）；业务变更时统一采用“删除后重建”策略。

    * 级联策略分界：默认采用 `RESTRICT` 策略，若该视图已被下游其他派生视图引用，系统阻断删除；显式声明 `CASCADE` 则连带销毁一切依附于它的下游派生视图。

### 视图在系统架构中的核心作用

* **视图系统架构价值（Architectural Values of Views）**

    * > **定义**：视图机制在企业级数据库应用架构中提供的五大核心支撑能力。

    * 简化用户操作：将复杂的多表等值连接、深层子查询与聚集统计封装在视图内部，上层业务端仅需简单检索视图即可获取结果。

    * 多视角审视数据：支持不同职能部门针对同一张底层基本表定制专属视角视图，互不干扰。

    * 提供逻辑数据独立性：当底层基本表因性能重构进行纵向或横向拆分时，可通过构建兼容视图维持原有结构，保证上层应用程序无需修改代码。

    * 敏感数据安全隔离：基于视图实现列级与行级访问权限控制，屏蔽家庭收入、财务密码等涉密字段，达成天然安全防护。

    * 复杂查询模块化表达：将深层嵌套的复杂业务逻辑拆分为分阶段的中间视图，大幅提升 SQL 架构的清晰度与可维护性。
