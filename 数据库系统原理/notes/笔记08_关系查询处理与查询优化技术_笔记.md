# 关系查询处理与查询优化技术

## 关系查询处理体系与执行四阶段

### 查询处理全生命周期与内部表示

* **关系查询处理阶段（Query Processing Phases）**

    * > **定义**：数据库管理系统将用户提交的声明式 SQL 查询转换为底层物理存取路径与执行代码的完整生命周期。

    * 阶段推进时序：整个生命周期依次划分为查询分析、查询检查、查询优化与查询执行四个连续阶段。

    * 查询处理全流程架构：

        ```text
               SQL 查询语句
                    │
                    ▼
           ┌─────────────────┐
           │  1. 查询分析    │  词法分析、语法分析，构建语法树
           └────────┬────────┘
                    │ 语法分析树
                    ▼
           ┌─────────────────┐
           │  2. 查询检查    │  语义分析、权限验证、完整性校验、视图消解
           └────────┬────────┘
                    │ 关系代数表达式
                    ▼
           ┌─────────────────┐
           │  3. 查询优化    │  代数优化（逻辑重构）+ 物理优化（算法/路径）
           └────────┬────────┘
                    │ 执行计划（Execution Plan）
                    ▼
           ┌─────────────────┐
           │  4. 查询执行    │  代码生成器（自顶向下/自底向上）、存储引擎调用
           └─────────────────┘
        ```

    * 核心转化目标：将不包含存取路径的声明式表达式转化为基于磁盘块 I/O 与内存调度的最高效物理执行代码。

* **查询树（Query Tree）**

    * > **定义**：关系数据库管理系统内部用来表达扩展关系代数表达式的层次化树状逻辑数据结构。

    * 拓扑节点角色：叶子节点对应查询涉及的基础关系表；内部非叶子节点对应关系代数算子（$\sigma$ 选择、$\pi$ 投影、$\bowtie$ 连接、$\times$ 笛卡尔积等）；根节点对应最终输出结果。

    * 计算流向规则：执行过程自底向上展开，底层算子节点的计算结果作为直接相连上层算子节点的输入数据流。

    * 优化操作落脚点：代数优化通过调整查询树的拓扑分支形态与算子高度，最小化中间结果临时数据集的规模。

### 查询分析与查询检查机制

* **查询分析（Query Analysis）**

    * > **定义**：对输入的 SQL 字符流进行词法分析与语法结构判定并生成语法分析树的编译预处理过程。

    * 词法分析职责：顺序扫描输入字符流，切分并识别出关键字（如 `SELECT`、`FROM`、`WHERE`）、表名、属性列名以及逻辑运算符等独立词法单元（Token）。

    * 语法分析职责：依据关系数据库语法规范判定词法单元序列的结构合法性，在内存中构建对应的语法分析树。

* **查询检查（Query Checking）**

    * > **定义**：依据系统数据字典对语法分析树执行语义合法性核验、安全控制审查并完成视图消解的处理过程。

    * 模式对象有效性检验：对照数据字典验证查询语句中引用的数据库、基本表、视图、属性列在系统中是否存在。

    * 用户访问权限审查：依据系统安全授权策略（`GRANT` 与 `REVOKE` 权限边界），核验发起请求的用户是否具备对目标表或属性列的读取权限。

    * 完整性约束校验：核验查询操作及其伴随条件是否符合实体完整性、参照完整性与用户自定义完整性约束。

    * 视图转换与消解机制：若查询涉及视图对象，系统提取数据字典中记录的视图定义，将视图名替换为底层的基本表子查询，完成视图消解。

    * 产出规格：查询检查全部通过后，将 SQL 语句正式转换为系统内部的标准表示形式——关系代数表达式。

### 查询优化与执行引擎驱动模式

* **查询优化（Query Optimization）**

    * > **定义**：在保证查询语义绝对等价的前提下，从海量可行执行方案中挑选系统综合资源消耗最小路径的过程。

    * 双支柱划分：代数优化负责在关系代数表达式层级重排算子次序（逻辑优化）；物理优化负责挑选具体存储存取路径与物理执行算法（物理优化）。

    * 优化决策机制：以基于代价的优化（CBO）为绝对主流，辅以基于规则的优化（RBO）快速剪除低效搜索空间。

* **查询执行（Query Execution）**

    * > **定义**：代码生成器依据查询优化器选定的物理执行计划生成底层调度指令，并由存储引擎调度物理资源完成运算输出的过程。

    * 执行驱动模式：包含自顶向下模式（Top-down，调用驱动/火山模型）与自底向上模式（Bottom-up，数据驱动）两种运算驱动模型。

    * 物理执行边界：调用底层存储管理接口从磁盘调入物理存储块至内存缓冲区，在内存中完成过滤、比对、排序与拼接，并向客户端输出结果。

## 关系代数基本算子的物理实现算法

### 选择操作底层实现算法

* **全表扫描算法（Table Scan）**

    * > **定义**：按照物理存储顺序将目标表占用的全部磁盘块逐一调入内存缓冲区，并对其中每个元组依次检查谓词条件的实现算法。

    * 物理调度机理：受限于可用内存容量 $M$ 块，分批顺序读入数据块至缓冲区，遍历比对后覆盖复用，直至遍历目标表全部磁盘块。

    * 适用边界：实现简易且无需索引支持，适用于物理块数极少的小表；对大表而言，即便只检索单条匹配记录也必须读穿整表，引发大量无谓 I/O。

* **索引扫描算法（Index Scan）**

    * > **定义**：利用预先建立在属性列上的物理索引结构检索满足谓词的元组指针，再依据指针定向调取物理数据块的实现算法。

    * 单值唯一匹配机制：针对主键或唯一索引的等值条件（如 `WHERE Sno = '201215121'`），通过索引树直接命中元组物理指针并读取单个数据块，I/O 复杂度为 $O(1)$ 或树高深度。

    * 范围条件匹配机制：针对 B+ 树索引的范围条件（如 `WHERE Sage > 20`），首先下探索引树根节点定位边界项，随后利用叶子节点双向链表顺序集横向扫描获取满足条件的物理指针集合，最后回表（Index Lookup）调入真实数据块。

    * 复合条件过滤策略：采用双索引求交法（各索引分别检索指针集合，在内存中求交集后定向读取数据块）或单索引过滤法（利用高区分度索引读取元组入内存，再在内存中二次判定剩余条件）。

    * > **易错点**：⚠️ 绝非属性列上有索引就必须走索引。若非主属性等值或范围查询筛选出的元组占全表比例过大（如超过 10% 乃至达到 90%），走索引扫描将触发海量离散的随机物理回表 I/O，其执行性能将比顺序全表扫描慢数十倍。

### 连接操作底层实现算法

* **嵌套循环连接算法（Nested-Loop Join, NLJ）**

    * > **定义**：选定外层驱动表与内层被驱动表，对外层表的每一个元组遍历扫描内层表的全部元组以比对连接谓词的双重循环算法。

    * 块嵌套循环代价模型：设两表占用物理块数分别为 $B_R$ 和 $B_S$，可用内存缓冲块数为 $K$（其中 $K-1$ 块分配给外表，$1$ 块留给内表轮巡），磁盘传输总块数为：

        $$\text{Cost} = B_R + \lceil \frac{B_R}{K - 1} \rceil \times B_S$$

    * 外表判定铁律：公式中乘积项 $B_R \times B_S$ 对称，非对称可变项仅为外表物理块数 $B_R$，因此必须严格选择占用物理块数较小的小表作为外层驱动表。

    * > **易错点**：⚠️ 在嵌套循环连接中，若缺乏内存块缓冲调度，外表含有 $N$ 条元组会导致内表被完整重复读取 $N$ 次，引发磁盘 I/O 灾难性膨胀；且外表物理块数非对称地决定总开销，外表选错大表会导致 I/O 翻倍增长。

* **排序合并连接算法（Sort-Merge Join, SMJ）**

    * > **定义**：在两表连接属性均已物理有序的前提下，通过维护双游标沿同一方向单向推进比对元组的高性能连接算法。

    * 执行机理：若连接属性未排序则先分别做物理排序；连接时双游标同向滑动，属性相等则拼接输出，较小者推进对应游标。

    * 核心优势：在两表已有序或数据量庞大的场景下，两表在连接阶段各仅需单遍线性扫描，彻底避免了内表的重复全表扫描。

* **连接索引算法（Index Join）**

    * > **定义**：利用内层表连接属性上已有的物理索引，遍历外表元组直接检索内表索引以匹配元组的连接算法。

    * 性能特征：外层表仅需单遍顺序扫描，内层表免于全表扫描，单次连接比对开销降为索引下探与指针回表的固定代价。

* **哈希连接算法（Hash Join）**

    * > **定义**：针对大规模非排序数据的等值连接，利用哈希函数在内存建立散列桶并进行单桶局部匹配的双阶段物理算法。

    * 阶段一划分构建（Building Phase）：选用元组较少的小表作为驱动表进行单遍扫描，使用哈希函数 $H$ 对连接属性计算哈希码，将其散列装入内存哈希桶（Buckets）。

    * 阶段二探测匹配（Probing Phase）：对较大表进行单遍扫描，采用完全相同的哈希函数 $H$ 计算连接属性哈希码并精确定位哈希桶，仅与该桶内的驱动表元组逐一比对，属性匹配立即拼接输出。

    * 算法架构图：

        ```text
        阶段一：划分构建（Building Phase）
        驱动表（较小表） ──▶ [Hash 函数 H] ──▶ 内存 Hash 表（桶 0, 桶 1, 桶 2 ...）
        
        阶段二：探测匹配（Probing Phase）
        被探测表（较大表） ──▶ [相同 Hash 函数 H] ──▶ 定位目标桶 ── 比对匹配 ──▶ 拼接输出
        ```

    * 性能优势：将全局 $O(N \times M)$ 的两两比对复杂度分摊压缩至各独立桶内，消除了全量笛卡尔积式比对。

## 查询代价模型与多表查询代价定量推导

### 系统查询代价构成模型

* **集中式数据库代价模型（Centralized Cost Model）**

    * > **定义**：用于衡量单机集中式数据库在执行具体物理执行计划时综合硬件资源消耗的量化模型。

    * 代价量化公式：

        $$\text{Cost} = \text{Cost}_{I/O} + \text{Cost}_{CPU} + \text{Cost}_{Memory}$$

    * 权重分布特征：磁盘 I/O 代价（读取与写出磁盘数据块的总数量）是单机数据库查询总代价中最主要、最具决定性的因素；CPU 代价反映指令耗时（元组比对、排序、哈希），内存代价反映缓冲区占用空间与生命周期。

* **分布式数据库代价模型（Distributed Cost Model）**

    * > **定义**：用于衡量跨网络多物理节点存储架构下分布式查询综合系统开销的量化模型。

    * 代价量化公式：

        $$\text{Cost}_{Distributed} = \sum \text{Cost}_{Local} + \text{Cost}_{Communication}$$

    * 核心优化目标：首要目标是在满足语义的前提下极小化跨网络节点的数据传输总量与网络往返通信次数（RTT）。

### 典型多表查询场景代价定量推导

* **基准查询场景与物理环境参数（Benchmark Setup）**

    * > **定义**：用于定量验证不同代数与物理执行策略下系统磁盘 I/O 成本差异的标准实验场景。

    * 查询业务定义：求选修了 2 号课程的学生姓名（`SELECT Student.Sname FROM Student, SC WHERE Student.Sno = SC.Sno AND SC.Cno = '2';`）。

    * 物理环境数据量与存储参数：

        * `Student` 表总行数 $1000$ 行（$10^3$），单行字段较长，每块存 $10$ 行，占用总块数 $100$ 块。

        * `SC` 表总行数 $10000$ 行（$10^4$），单行字段较短，每块存 $100$ 行，占用总块数 $100$ 块。

        * 选修 2 号课程的目标记录数：$50$ 行。

        * 内存缓冲区分配约束：用于嵌套连接的缓冲区限制为 $5$ 块 `Student` 与 $1$ 块 `SC`。

* **三大执行策略代价定量演算（Execution Strategy Cost Derivation）**

    * > **定义**：针对基准查询，在三种不同算子组织形态下推导得出的磁盘 I/O 块数精确模型。

    * 策略一（笛卡尔积与事后选择 $Q_1$）：

        * 表达式：$Q_1 = \pi_{Sname} (\sigma_{Student.Sno = SC.Sno \land SC.Cno = '2'} (Student \times SC))$

        * 输入连接阶段：`Student` 分 $100 \div 5 = 20$ 轮读入，每轮扫描一次完整 `SC` 表（100 块），输入 I/O 为 $100 + 20 \times 100 = 2100$ 块。

        * 中间结果落盘：笛卡尔积产生 $1000 \times 10000 = 10^7$ 行元组，每块容纳 10 行，写出中间文件需 $10^6$ 块写入 I/O。

        * 条件选择阶段：重新从磁盘读回该中间文件，产生 $10^6$ 块读入 I/O，过滤出 50 行后内存投影输出。

        * 总 I/O 代价：$\text{Cost}(Q_1) = 2100 + 10^6 + 10^6 = 2{,}002{,}100$ 块。

    * 策略二（自然连接与中间结果缩减 $Q_2$）：

        * 表达式：$Q_2 = \pi_{Sname} (\sigma_{SC.Cno = '2'} (Student \bowtie SC))$

        * 输入连接阶段：两表调入内存方式同上，输入 I/O 为 $2100$ 块。

        * 中间结果落盘：施加等值连接过滤后，中间结果元组数上限受限于 `SC` 表行数（最多 $10^4$ 行），每块存 100 行，写出中间文件仅需 $100$ 块写入 I/O。

        * 条件选择阶段：读回中间文件进行 `SC.Cno = '2'` 判定，产生 $100$ 块读入 I/O，50 行结果内存直接投影。

        * 总 I/O 代价：$\text{Cost}(Q_2) = 2100 + 100 + 100 = 2{,}300$ 块（降至策略一的约 $1/870$）。

    * 策略三（算子下推与先选后连 $Q_3$）：

        * 表达式：$Q_3 = \pi_{Sname} (Student \bowtie \sigma_{SC.Cno = '2'}(SC))$

        * 预先选择阶段：单遍扫描 `SC` 表读入 $100$ 块，在内存中实时过滤出 $50$ 行记录；50 行仅占半块内存，直接常驻内存缓冲区，中间落盘写 I/O 为 $0$。

        * 内存连接与投影阶段：将 50 行 `SC` 记录常驻内存，单遍读入 `Student` 表全部 $100$ 块，内存实时等值匹配并直接投影 `Sname` 输出。

        * 总 I/O 代价：$\text{Cost}(Q_3) = 100 + 100 = 200$ 块（降至策略一的万分之一、策略二的二十分之一）。

    * 物理索引二次优化压缩：若 `SC.Cno` 建有 B+ 树索引，检索 2 号课回表仅需 $3 \sim 4$ 块 I/O；若 `Student.Sno` 建有主码索引，50 条记录点查最多产生 $50$ 块 I/O，总 I/O 压缩至几十块以内。

    * 执行策略 I/O 代价对比：

        | 执行策略 | 关系代数结构特征 | 中间结果落盘规模 | 磁盘总 I/O 块数 | 性能阶跃倍数 |
        | :--- | :--- | :--- | :--- | :--- |
        | 策略一（$Q_1$） | 广义笛卡尔积 + 复合选择 + 投影 | 写入/读回 $10^6$ 块 | $2{,}002{,}100$ 块 | 基准性能（极差） |
        | 策略二（$Q_2$） | 自然连接 + 单条件选择 + 投影 | 写入/读回 $100$ 块 | $2{,}300$ 块 | 约为策略一的 $870$ 倍 |
        | 策略三（$Q_3$） | 选择算子下推 + 内存连接 + 投影 | $0$ 块（常驻内存） | $200$ 块 | 约为策略一的 $10{,}000$ 倍 |
        | 结合物理索引 | 算子下推 + 双表索引点查与扫描 | $0$ 块（常驻内存） | $\le 54$ 块 | 数量级进一步提升 |

## 关系代数等价变换规则体系

### 等价变换基本概念与双目算子定律

* **关系代数等价性（Algebraic Equivalence）**

    * > **定义**：对于两个关系代数表达式 $E_1$ 和 $E_2$，若用相同任意合法关系实例替换其中的关系名所得结果集合完全一致，则称两者等价，记作 $E_1 \equiv E_2$。

    * 核心语义边界：等价变换是代数优化的合法性基础，确保优化器在调整表达式结构时不破坏查询结果的正确性。

* **连接与笛卡尔积的交换律与结合律（Commutative and Associative Laws）**

    * > **定义**：连接与笛卡尔积算子满足交换律与结合律，运算对象的物理位置与组合先后不改变最终元组匹配结果。

    * 交换律形式：

        $$E_1 \bowtie E_2 \equiv E_2 \bowtie E_1$$

        $$E_1 \times E_2 \equiv E_2 \times E_1$$

    * 结合律形式：

        $$(E_1 \bowtie E_2) \bowtie E_3 \equiv E_1 \bowtie (E_2 \bowtie E_3)$$

        $$(E_1 \times E_2) \times E_3 \equiv E_1 \times (E_2 \times E_3)$$

    * 优化自由度价值：允许查询优化器跳出 SQL 语句 `FROM` 子句的书写顺序限制，自由重排多表连接顺序，优先促使行数较少的小表先行连接。

### 单目算子串接律与交换律

* **投影与选择的串接定律（Cascade Laws）**

    * > **定义**：同类单目操作在连续作用于同一关系时，可依据包含关系或合取逻辑合并为单次操作的等价规则。

    * 投影串接律：若属性集满足 $A \subseteq B$，则：

        $$\pi_A(\pi_B(E)) \equiv \pi_A(E)$$

        多次连续投影操作可直接合并为单次投影，仅保留最外层所需的目标属性集合，消除中间冗余投影算子。

    * 选择串接律：针对复合合取条件 $F_1 \land F_2$，满足：

        $$\sigma_{F_1 \land F_2}(E) \equiv \sigma_{F_1}(\sigma_{F_2}(E)) \equiv \sigma_{F_2}(\sigma_{F_1}(E))$$

        选择条件既可按所属表或属性来源自由拆解为多层独立选择，也可随时合并为单层复合判定。

* **选择与投影的交换律（Commutative Law of Selection and Projection）**

    * > **定义**：当选择条件涉及的全部属性均属于投影属性集时，选择操作与投影操作的执行次序可相互对调的规则。

    * 等价数学形式：若条件 $F$ 涉及的所有属性均包含在属性集合 $A$ 中，则：

        $$\sigma_F(\pi_A(E)) \equiv \pi_A(\sigma_F(E))$$

    * 算子流向决策准则：在数据处理流向上，选择算子优先推向底层以尽早压降元组数量；投影算子置于最外层以剔除多余字段并规范最终输出。

### 选择与双目算子的分配与交换律

* **选择对笛卡尔积与连接的分配律（Distribution of Selection over Product and Join）**

    * > **定义**：将作用于笛卡尔积或连接结果之上的选择谓词，根据属性所属关系下推至单个关系分支先行计算的等价规则。

    * 单侧选择下推形式：若条件 $F$ 仅涉及关系 $E_1$ 的属性，则：

        $$\sigma_F(E_1 \times E_2) \equiv \sigma_F(E_1) \times E_2$$

    * 双侧独立选择并行下推形式：若条件 $F = F_1 \land F_2$，其中 $F_1$ 仅含 $E_1$ 属性，$F_2$ 仅含 $E_2$ 属性，则：

        $$\sigma_{F_1 \land F_2}(E_1 \times E_2) \equiv \sigma_{F_1}(E_1) \times \sigma_{F_2}(E_2)$$

    * 连接与选择协同下推形式：若选择条件由连接谓词与单表谓词复合而成，单表过滤谓词可沿分支直接推到连接运算之前执行。

* **选择与投影对集合操作的分配律（Distribution over Set Operations）**

    * > **定义**：选择与投影算子可穿透集合运算（并集、差集）与自然连接分配至各操作数内部的等价规则。

    * 选择对集合操作的分配：

        $$\sigma_F(E_1 \cup E_2) \equiv \sigma_F(E_1) \cup \sigma_F(E_2)$$

        $$\sigma_F(E_1 - E_2) \equiv \sigma_F(E_1) - \sigma_F(E_2)$$

        $$\sigma_F(E_1 \bowtie E_2) \equiv \sigma_F(E_1) \bowtie \sigma_F(E_2)$$

    * 投影对集合操作的分配：

        $$\pi_A(E_1 \cup E_2) \equiv \pi_A(E_1) \cup \pi_A(E_2)$$

        $$\pi_{A \cup B}(E_1 \times E_2) \equiv \pi_A(E_1) \times \pi_B(E_2)$$

## 启发式代数优化与查询树重构技术

### 启发式代数优化五大核心工程规则

* **选择算子优先下推（Predicate Pushdown）**

    * > **定义**：在代数优化过程中将选择运算尽可能沿查询树分支推移至底层的单表叶节点上方优先执行的基石规则。

    * 优化本质与收益：在数据流的源头立即过滤无关元组，极大压缩参与后续计算的中间数据集行数，从而成倍减少内存缓冲区占用与中间磁盘 I/O。

* **投影与选择运算协同进行（Simultaneous Projection and Selection）**

    * > **定义**：在对同一个关系进行顺序或索引扫描时，将行过滤判定与列属性裁剪合并在单次物理访问中同步处理的规则。

    * 避免开销机理：扫描物理块时，不满足行选择条件的元组直接丢弃，满足条件的元组仅抽取目标投影列构建内存记录，彻底避免因“先选后投”或“先投后选”对同一数据块进行重复读写。

* **投影与其前后的双目运算紧密结合（Coupling Projection with Binary Operations）**

    * > **定义**：在两表执行连接或笛卡尔积时，仅保留连接键及后续运算必需的属性列，无用属性就地裁剪的规则。

    * 消除冗余机理：避免为了纯粹在关系表达式中剔除某些中间列而专门增设一次独立的关系物理遍历或生成中间物化视图。

* **合并选择与笛卡尔积为等值连接（Combining Selection and Product into Join）**

    * > **定义**：将作用于笛卡尔积之上的等值关联谓词与笛卡尔积算子就地合并重组为等值连接或自然连接的规则。

    * 数学等价依据：

        $$\sigma_{R.A = S.A}(R \times S) \equiv R \bowtie_{R.A = S.A} S$$

    * 执行禁忌准则：成熟数据库系统严禁直接物化全量无条件笛卡尔积中间结果，必须优先收拢为连接算子执行。

* **积极提取并物化公共子表达式（Common Subexpression Extraction）**

    * > **定义**：在复杂多表复合查询中识别多次出现的相同子查询表达式，并将其单次计算结果缓存或物化为临时表供多分支复用的规则。

    * 典型应用场景：基于多处引用视图的复杂查询，以少量的临时存储空间换取避免多次深层磁盘扫描，有效提升系统并发吞吐。

### 查询树启发式优化算法流程与案例推演

* **查询树重构标准化算法流程（Query Tree Restructuring Algorithm）**

    * > **定义**：查询优化器利用代数等价变换规则将初始查询树重塑为最优逻辑查询树的标准执行时序。

    * 算法执行步骤：

        1. 构造初始查询树：根据 SQL 语法结构自底向上机械构建包含表、连接与上层选择投影的初始树。
        2. 拆解并彻底展开多表连接：将连接算子在推演草稿上还原为广义笛卡尔积及其关联等值选择条件。
        3. 选择算子下推（Pushdown）：利用分配律与交换律将单表选择算子直接推至对应叶节点上方。
        4. 投影算子下推与精简：将投影操作推向底层并与双目算子结合，就地剔除无关字段。
        5. 重组为高效连接：将相邻的等值选择条件与笛卡尔积重新收拢为等值连接算子。

    * > **易错点**：⚠️ 优化器内部将连接拆解为广义笛卡尔积与选择条件只是推导演算树上的中间逻辑态，绝非实际物理执行计划。此举的唯一目的是解除连接算子对单表过滤条件的绑定，赋予谓词在查询树各分支自由滑动的能力。

* **查询树拓扑演进推导演算（Query Tree Transformation Case Study）**

    * > **定义**：以“查询选修 2 号课程的学生姓名”为例，展示查询树从语法机械映射演进至最优代数结构的完整拓扑重塑过程。

    * 演进拓扑结构：

        ```text
        初始查询树（按 SQL 机械映射）          推演展开树（解绑选择谓词）            最终代数优化树（算子下推）
                 π(Sname)                              π(Sname)                              π(Sname)
                    │                                     │                                     │
             σ(SC.Cno = '2')                       σ(SC.Cno = '2')                    ⋈(Student.Sno = SC.Sno)
                    │                                     │                                  ┌───┴───┐
         ⋈(Student.Sno = SC.Sno)               σ(Student.Sno = SC.Sno)                    Student   σ(SC.Cno = '2')
             ┌──────┴──────┐                              │                               (100块)       │
          Student          SC                             ×                                             SC
          (100块)        (100块)                     ┌────┴────┐                                     (100块)
                                                  Student      SC                              (常驻内存 50 行)
        ```

    * 最终执行效益：单表过滤 `SC.Cno = '2'` 压降至叶节点，50 条目标元组常驻内存；读取 `Student` 表时仅向上传递 `{Sno, Sname}`，连接算子直接在极小行数与极窄行宽的内存数据流上完成匹配。

## 物理优化机制与代价估算体系

### 基于规则的物理优化决策规则

* **单表选择存取路径决策规则（Selection Access Path Decision Rules）**

    * > **定义**：基于规则的优化器（RBO）依据表规模、索引类型与谓词形态为单表选择挑选存取路径的启发式准则。

    * 基础决策大前提：遵循“能用索引用索引，不能用索引全表扫描”的基本准则，但最终决策取决于需要提取的数据规模与占比。

    * 小表扫描准则：占用物理块数极少的小表，无条件采用全表顺序扫描，避免读取索引块与离散回表的额外开销。

    * 主码点查准则：针对主码等值查询（`PK = value`），因满足唯一性且命中结果最多仅 1 行，无条件优先走主码索引。

    * 范围与非唯一等值查询准则：若列上建有 B+ 树索引，预估命中元组占比；占比极低（通常 $\le 10\%$）时选用索引扫描加回表；占比过高（如达到 $90\%$）时直接放弃索引并采用全表顺序扫描。

    * 复合条件准则：AND 复合条件优先选用复合索引扫描，次选单列索引求交过滤，无索引则走全表扫描；OR 复合条件除非两侧所有列均有索引支持索引合并，否则直接采用全表顺序扫描。

* **多表连接物理算法决策规则（Join Physical Algorithm Decision Rules）**

    * > **定义**：RBO 依据两表的物理排序状态、索引覆盖与内存容量为连接算子挑选物理执行算法的准则。

    * 排序合并连接优先准则：若两表在连接属性上已预先物理有序，无条件首选排序合并连接（SMJ）。

    * 索引连接优先准则：若其中一个表的连接属性上已预建高效物理索引，优先选用连接索引算法（Index Join）。

    * 哈希连接选用准则：在两表均无序且无索引支持时，若较小表的哈希桶能完全容纳于内存缓冲区，优先选用哈希连接（Hash Join）。

    * 块嵌套循环驱动表铁律：选用块嵌套循环连接时，必须将占用磁盘物理块数较小的表设定为外层驱动表。

### 基于代价的物理优化估算模型

* **优化器统计信息维度（CBO Statistics Catalog）**

    * > **定义**：基于代价的优化器（CBO）存储于数据字典中、用于量化计算各候选执行路径代价的核心统计指标。

    * 核心统计指标维度：

        | 统计维度 | 核心统计指标与参数说明 |
        | :--- | :--- |
        | 基本表级别 | 元组总行数 $N$、元组平均字节长度 $L$、占用物理块数 $B$、溢出块数 $BO$ |
        | 属性列级别 | 属性不同值个数（Distinct Values）$I$、最大值 Max、最小值 Min、索引存在性与类型、选择率 $f$ |
        | 物理索引级别 | 索引层数 $L$、不同索引值个数、索引选择基数 $S$（平均每个索引值对应元组数）、叶节点物理块数 $Y$ |

    * 选择率（Selectivity）计算模型：

        * 均匀分布假设：若属性列包含 $I$ 个不同离散值且分布均匀，等值查询选择率为 $f = \frac{1}{I}$。

        * 频数直方图倾斜统计：若数据呈倾斜分布，特定值 $v$ 的选择率采用真实频数比值 $f = \frac{\text{Count}(v)}{N}$。

* **典型物理算子磁盘 I/O 代价模型（Physical Operators I/O Cost Models）**

    * > **定义**：优化器用于量化评估不同存取路径与物理算子所需磁盘块传输量的数学公式体系。

    * 全表顺序扫描代价模型：

        * 无条件全表扫描：$\text{Cost} = B$。

        * 主码等值查找（命中即止）：平均期望扫描块数为 $\text{Cost}_{\text{avg}} = \frac{B}{2}$。

    * 主码等值 B+ 树索引查询代价模型：

        * 沿树高下探读取 $L$ 个索引块，加上 $1$ 次数据块回表定位：

            $$\text{Cost} = L + 1$$

    * 非主属性等值 B+ 树索引查询代价模型：

        * 设索引层数为 $L$，满足条件的元组数为 $S$（索引选择基数），最坏情况下每次回表均产生离散随机读：

            $$\text{Cost} = L + S$$

    * 非主属性范围 B+ 树索引查询代价模型：

        * 设索引叶节点块数为 $Y$，表数据块数为 $B$；若预估有一半元组满足条件，初步代价模型为：

            $$\text{Cost} = \frac{Y}{2} + \frac{B}{2}$$

        * 优化器判定若该代价超过全表扫描代价 $B$，则立即放弃索引转向全表扫描。

    * 嵌套循环连接中间结果写回代价模型：

        * 当中间结果无法完全驻留内存而必须落盘时，写回代价为：

            $$\text{Cost}_{\text{write}} = \frac{N_R \times N_S \times f_{RS}}{M_{RS}}$$

            （其中 $f_{RS}$ 为连接选择率，$M_{RS}$ 为单个磁盘块可容纳的连接结果元组数）。

### 面向物理执行的 SQL 编写准则

* **优化器局限性与自动化边界（Optimizer Limitations and Boundaries）**

    * > **定义**：现代查询优化器在有限搜索空间、静态统计假设与启发式规则约束下的工程能力边界。

    * 边界机理：优化器是在有限时间内运行的算法程序，其推导依赖于统计信息的新鲜度与假设模型；若 SQL 语句书写存在结构性缺陷，优化器无法从根本上消除劣质执行开销。

    * > **易错点**：⚠️ 绝不能盲目迷信 DBMS 优化器的自动化重构能力。查询优化器受限于有限搜索空间与启发式假设，若用户在 SQL 层写出跨大表笛卡尔积、或在索引列上包裹运算函数导致索引失效，下层优化器无法扭转灾难性的执行开销。

* **工程级 SQL 高效编写准则（Engineering SQL Best Practices）**

    * > **定义**：工程师顺应底层代数优化与物理存取路径规律、协助优化器生成最优计划的书写规范。

    * 业务端主动辅助算子下推：在复杂关联场景下，业务逻辑允许时优先通过内层子查询或精准单表过滤条件提早收敛数据规模。

    * 严防恶性笛卡尔积：编写多表查询时必须显式书写完整的关联等值谓词，杜绝因遗漏连接条件触发失控的中间结果膨胀。

    * 保护索引列可检索性：避免在 `WHERE` 条件的索引属性列上施加函数运算、隐式类型转换或算术运算，防止优化器无法利用索引树。

    * 权衡索引回表代价：大批量提取数据时明确评估选择率，避免在提取全表大部数据时强行利用非聚簇索引引发离散回表。
