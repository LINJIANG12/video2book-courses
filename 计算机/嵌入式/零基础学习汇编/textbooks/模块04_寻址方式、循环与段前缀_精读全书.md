## 用 BX 表示偏移地址与 Loop 循环
> 对应块：BLK11 | 覆盖分集：P18-P19 | 块标题（分集名）：《bx寻址与循环》

第五章开讲，节奏会比前面稍微快一点。这一章盯着三件事：内存单元、用寄存器来表示内存单元的地址、以及循环指令。先从 BX 说起——它和我们之前用数字来表示偏移地址，其实是同一个套路，区别只在于：以前偏移地址是当场写死的，现在换成一个寄存器里的值。为什么非得这么换？因为偏移地址要是会变，总不能每变一次就去改一条指令。

### 把偏移地址交给 BX

要描述一个完整的内存单元，需要两种信息。

- **内存单元的地址**。没有地址，根本找不到这个单元在哪。
- **内存单元的长度**，也就是它的类型：取的是字节型数据，还是字型数据。

在十六位环境里，字节型数据取 8 个 bit；字型数据取两个字节，也就是 16 个 bit。之前我们用 `[0]` 这种写法，那个数字就是偏移地址，段地址默认存在 DS（数据段寄存器）里，于是这个单元就是 `DS:0`。换成 BX 以后做法不变，只是偏移地址改由 BX 的值来提供，单元变成 `DS:BX`。

那长度（类型）由谁定？由指令里另一个操作数指出来。

| 指令 | 另一个操作数 | `[BX]` 指向的单元 |
| :--- | :--- | :--- |
| `mov ax, [bx]` | AX，由 AH 和 AL 拼成，共 16 位 | 字型单元（2 字节） |
| `mov al, [bx]` | AL，8 位 | 字节型单元（1 字节） |

拿 `mov ax, [bx]` 说：AX 由 AH 和 AL 各占 8 个 bit 拼成，整体是 16 位、两个字节，所以 `[BX]` 指向的是一个字型内存单元。换成 `mov al, [bx]`，AL 只占 8 位，`[BX]` 就指向一个字节型内存单元。

> **提示**：同一个 `[BX]`，配 AX 就是字，配 AL 就是字节。单元的类型不是它自己决定的，是被旁边那个操作数带出来的。

### 描述性符号 [ ] 表示"内容"

学别的编程语言时，中括号常表示"先算里面的"；但在汇编里不一样。这里的 `[ ]` 表示**一个寄存器或者一个内存单元中的内容**。

- AX 的内容是 `00010H`，就写成 `[AX] = 00010H`。
- `21000H` 这个内存单元的内容是 `00010H`，就写成 `[21000H] = 00010H`。

`[2]` 的定位过程也能说明这一点：先拿段地址寄存器乘以 16（十六进制里就是左移一位），再加上偏移量 2，定位到目标内存单元，最后取它的内容。

```text
物理地址 = 段地址 × 16 + 偏移地址
        = DS 左移一位（十六进制）+ 2
```

读图说明：`[ ]` 里的数是偏移地址，段地址默认来自 DS；两者合成物理地址之后，取出来的才是"内容"。

> **易错点**：`[ ]` 不是数学括号，它不表示"先算括号里"。`[AX]` 说的是"AX 里的内容"，而不是"AX 的地址"。

### 从 idata 到 [bx]

之前写 `mov ax, [0]`，是用一个常量 0 来表示内存单元的偏移地址。为了以后不必每次都写死某个具体数字，约定一个符号 **idata** 表示常量。这样一来，`mov ax, idata` 就代表 `mov ax, [1]`、`mov ax, [2]`、`mov ax, [3]` 这一类写法——只要那个位置放的是常量，就都可以用 idata 来占位。

接下来看 `mov ax, [bx]` 的功能：把 BX 中存放的数据当作偏移地址，段地址默认在 DS 中，把 `段地址:偏移地址` 处的数据送入 AX。写成关系就是：AX 的内容等于 DS 乘 16（DS 左移一位）再加上 BX 的内容。

`mov [bx], ax` 则反过来：同样以 BX 的值为偏移地址、段地址默认在 DS，把 AX 中的数据送入这个内存单元。

它和 `[idata]` 是同一个意思，唯一的区别就是把中间那个写死的常量，换成了一个寄存器来存偏移地址的值。

### 跟着指令看内存怎么变

有一段程序，内存中的初始情况在图上，要求写出它执行之后若干单元里的内容。程序是这样的：

```asm
mov ax, 2000H
mov ds, ax
mov bx, 1000H
mov ax, [bx]
inc bx
inc bx
mov [bx], ax
```

先看前三条：把 `2000H` 放进 AX，再借 AX 送进 DS，于是 `DS = 2000H`；接着把 `1000H` 放进 BX，于是 `BX = 1000H`。

第四条 `mov ax, [bx]`：因为 DS 是 2000H、BX 是 1000H，定位到的就是下面这个单元。

```text
物理地址 = DS × 16 + BX
        = 2000H × 16 + 1000H
        = 21000H
```

这里为什么取"这两个数"当内存单元？因为目标操作数是 AX，而前面说过：一个内存单元的地址由偏移量给出，类型则由另一个操作数决定。AX 是 16 位的字型数据，所以这里取的是一个字型单元。按"高位放高位、低位放低位"的规则，读出来 `AX = 00BEH`。

第五条、第六条是两条 `inc bx`：让 BX 自己加 1，加两次，BX 就从 `1000H` 变成 `1002H`。

第七条 `mov [bx], ax`：把 AX 的数据写进 `[BX]` 这个内存单元。由于目标是字型单元，它占两个字节，同样是低位放低位、高位放高位。写进去之后，这两个单元里就是 `BE`、`00`。

```text
21000H   BE        ← 原单元 00BEH 的低字节
21001H   00        ← 原单元 00BEH 的高字节
21002H   BE        ← 写入 00BEH 的低字节
21003H   00        ← 写入 00BEH 的高字节
```

读图说明：21000H、21001H 是原来的字 `00BEH`，程序没动它；21002H、21003H 是这次写进去的字 `00BEH`。剩下的单元保持图上原有的内容不变。

### Loop：把重复的动作交给循环

`Loop` 是循环的意思，这条指令自然和循环有关。执行到 Loop 时，它做两步操作：

1. 先把 CX 的内容减 1；
2. 判断 CX 的值——如果不为零，就转到 Loop 后面写的那个标号处；如果为零，就向下继续执行。

```text
        执行到 loop 标号
               │
               ▼
          CX = CX - 1
               │
        ┌──────┴──────┐
     CX ≠ 0        CX = 0
        │             │
        ▼             ▼
   跳到标号处      向下执行
```

读图说明：CX 的值直接影响 Loop 的执行结果，所以通常用 CX 存放循环次数——想循环 5 次，就写 `mov cx, 5`。至于 Loop 实现转移的细节，后面再讲。

把 CX 和 Loop 配合起来实现循环功能，有三个要点：

1. CX 中存放循环次数；
2. Loop 指令的标号所表示的地址要放在前面；
3. 要执行的循环程序段，写在标号和 Loop 指令的中间。

只要凑齐这三点，循环就能写出来了。程序框架如下：

```asm
mov cx, 循环次数
标号:
    循环程序段
loop 标号
```

### 用 Loop 改写重复加法

#### 算 2 的次方

先算 2 的二次方，也就是让 2 去乘 2。一个数的多少次方，就是让它自己加多少次——所以算 2 的几次方，就让这个数自己加几次。

2 的二次方太简单，其实不用循环：`mov ax, 2`，再 `add ax, ax`，AX 自己相加一次就得到 4。

2 的三次方等于 2 × 2 × 2，可以看成先自己加一次得到 4，再让 4 和 4 相加得到 8：

```asm
mov ax, 2
add ax, ax      ; AX = 4
add ax, ax      ; AX = 8
```

可是要算 2 的十二次方，就得手写一长串 `add ax, ax`——十二个 2 相乘，对应要写十一遍这条加法指令。手敲这么多遍显然太麻烦，这时候就该让循环上场了。

```asm
mov ax, 2
mov cx, 11
s:  add ax, ax
    loop s
```

执行顺序是这样的：先把 2 放进 AX，把 11 放进 CX；执行 `add ax, ax`，AX 变成 4；接着 `loop s` 把 CX 减 1 变成 10，不为零，就跳回标号 `s`；于是再翻倍、再减 CX……一直循环下去。当 CX 减到 1 时，再执行一次 `loop s`，CX 减成 0，判断为零，就向下执行、结束循环。

> **结论**：`mov cx, 11` 配上 `add ax, ax` 的循环体，就把"写十一遍加法"压缩成了一句循环。

#### 用加法算 123×236

现在用加法计算 123 × 236，结果存在 AX 中。所谓加法计算，就是让 123 加 236 次。

先写第一版：把 AX 设成 123——这本身已经相当于加过一次了——所以循环再做 235 次就够了。

```asm
mov ax, 123
mov cx, 235
s:  add ax, 123
    loop s
```

当然，也可以不占这个便宜，先把 AX 清成 0，再老老实实循环 236 次。

但如果多想一步，就能让程序更快：把 123 和 236 反过来，用 236 去累加 123 次。循环次数从 235 降到 123，次数少一点，程序性能就能提上去。

```asm
mov ax, 0
mov cx, 123
s:  add ax, 236
    loop s
```

> **提示**：算乘法时，被加的数取大、循环次数取小，结果一样，循环却更少。这就是同样一道题换个写法能更快的原因。

### 用循环累加做乘法

考虑这样一个问题：计算 `FFFF:0006` 单元中的数乘以 3，结果存储在 DX 中。先来分析运算后的结果会不会超出 DX 能存储的范围。

这个单元里存的是一个字节型数据，最大值也就是 255。255 乘以 3 得 765，不会大于 65535（也就是 2 的 16 次方减 1），所以 DX 存得下。

第二个问题：用循环累加来实现乘法，用哪个寄存器来累加？答案是用 DX 累加，循环三次，最后 DX 就等于那个数乘 3。

这里有个麻烦：`FFFF:0006` 是一个字节型内存单元，而 AX 是 16 位寄存器，两边长度不一样。如果直接按字型去取，会多取出一个字节，和原来的要求就对不上了。好在 AX 里有 AH 和 AL 两个部分，DX 里也有 DH 和 DL——借助其中一个就行。八位数据 `1EH` 和十六位数据 `001EH`，长度不一样，值却是相等的。所以我们让 AH 等于 0、AL 等于那个单元里的数，AX 就装下了这个字节值。

完整程序如下：

```asm
mov ax, 0FFFFH
mov ds, ax
mov bx, 6
mov al, [bx]
mov ah, 0
mov dx, 0
mov cx, 3
s:  add dx, ax
    loop s
```

先把 `0FFFFH` 放进 AX，再借 AX 当跳板把它送进 DS；`mov bx, 6` 把偏移量 6 放进 BX，于是 `[bx]` 就指向 `FFFF:0006`。`mov al, [bx]` 按字节把这个单元的数取进 AL，`mov ah, 0` 把 AH 清零，AX 就成了这个字节值。接着 DX 清零，CX 设为 3，进入循环：每次把 AX 加到 DX 上，`loop s` 反复三次，DX 就等于该数乘 3。

> **易错点**：汇编源程序中，数据不能以字母开头。像 `FFFFH`、`A` 开头的十六进制数，前面必须补一个 0 占位，写成 `0FFFFH` 这样。这个 0 不是数值的一部分，只是用来占位，因为首字符不能是字母。

### 在 Debug 里跟踪与加速

把程序编译、连接后进 Debug 跟踪，可以一步步看它干了什么。

- `mov ax, 0FFFFH`：AX 变成 FFFFH，再借 AX 把值送进 DS。
- `mov bx, 6`：BX 变成 6。
- `mov al, [bx]`：把 `FFFF:0006` 单元的内容取进 AL，得到 `31H`。
- `mov ah, 0`、`mov dx, 0`：AH、DX 清零。
- 写循环次数，进入循环，`add dx, ax` 让 DX 累加。

执行循环时可以看到 `loop` 后面跟的是 `0012`。为什么是 0012？因为标号其实就是一个地址，这个 `0012` 就是标号 `s` 编译出来的地址，也就是循环体第一条指令 `add dx, ax` 的地址。换句话说，标号会变成循环体中第一条指令的地址。

三次循环之后，DX 里就是 `31H × 3`，得到 `93H`。

接着把程序改一下，计算同一个单元中的数乘以 123，结果仍存 DX。先估一下范围：255 乘 123 得 31365，仍然在 DX 的范围内。改动很简单，只要把循环次数从 3 改成 123。

```asm
mov cx, 3      ; 改成 mov cx, 123
```

改完重新编译、连接、跟踪。这次循环要跑一百多次，再一条条按 T 单步观察就太不现实了。Debug 里有两个好用的命令：

- `G 0012`：让程序直接运行到以该地址为首地址的指令，也就是 `CS:0012` 处的那条指令，一步跳过前面的铺垫。
- `P`：自动执行循环中的指令，直到循环结束为止。用它一次就能跑完整段循环，不用手动重复。

循环跑完，结果出来是 `178BH`，也就是 `31H × 123`。

这一讲的循环先讲到这里，后面的内容下一节继续。

### 本讲提到的题目

**问题 5.1**：程序内存中的初始情况如题图，写出程序执行后相应单元中的内容。

```asm
mov ax, 2000H
mov ds, ax
mov bx, 1000H
mov ax, [bx]
inc bx
inc bx

```

解析：前三条令 `DS = 2000H`、`BX = 1000H`；`mov ax, [bx]` 定位到 `21000H`，按字型读出 `AX = 00BEH`；两条 `inc bx` 把 BX 从 `1000H` 加到 `1002H`；`mov [bx], ax` 把 `00BEH` 按字型写进 `21002H`。

答案：`21000H = BE`、`21001H = 00`（原值不变），`21002H = BE`、`21003H = 00`，其余单元保持原有内容不变。

**计算 `FFFF:0006` 单元中的数乘以 3，结果存入 DX**：该单元为字节型，最大 255，255 × 3 = 765，不超过 65535，DX 存得下；借助 AL 取字节、AH 清零，用 DX 循环累加三次。

答案：结果为 `31H × 3 = 93H`。

**把上面的乘数改成 123**：只需把循环次数改为 123；255 × 123 = 31365，仍在 DX 范围内。

答案：结果为 `31H × 123 = 178BH`。

**用加法计算 123 × 236，结果存入 AX**：可以让 AX 先等于 123（相当于加过一次），循环 235 次累加 123；也可以把两个数反过来，用 236 累加 123 次，循环次数更少。

## 段前缀与连续内存单元的循环访问
> 对应块：BLK12 | 覆盖分集：P20 | 块标题（分集名）：《段前缀》

最近有点忙，一直没怎么更新，正好有位小伙伴私信说要考试了，我就回来多更一点。这一节其实只是一个过渡的知识——它要说清的是 debug 和编译器对某些指令的不同处理方式：同一条 `mov ax,[0]`，在 debug 里和在汇编源程序里，含义完全不是一回事。把这个差异弄清楚，后面才能安心地谈「段前缀」。

### 从 mov ax,[0] 说起

我们之前在 debug 里写过这样的指令：

```asm
mov ax, [0]
```

它的意思是把 `ds:0` 处的数据送入 `ax`。这里要特别注意：操作对象是 `ax`，而 `ax` 是 16 位的，所以从内存里取出来的不是一个字节，而是一个「字单元」——从 `ds:0` 开始连着两个字节一起取，拼成一个字放进 `ax`。

但在汇编源程序里，同一条 `mov ax,[0]` 会被当作 `mov ax,0`：那个 `0` 被当成一个真实的立即数来处理，相当于把数字 0 放进 `ax`，根本不去碰内存。

> **易错点**：`[0]` 在 debug 里是「取出内存单元的内容」，在汇编源程序里却会被编译成「数字 0 本身」。同一份写法，两个环境两种结果。

举个具体的例子：把内存 `2000:0`、`2000:1`、`2000:2`、`2000:3` 这几个单元中的数据分别移入 `al`、`bl`、`cl`、`dl`。

在 debug 里，段地址不能直接塞进 `ds`，得先借助一个通用寄存器中转：先把 `2000h` 放进 `ax`，再从 `ax` 送到 `ds`，然后就可以写：

```asm
mov al, [0]
mov bl, [1]
mov cl, [2]
mov dl, [3]
```

（中间两条 `mov` 略去不写，道理一样。）这样写，`[0]`、`[1]`、`[2]`、`[3]` 会老老实实去取对应内存单元的内容。

可如果把这套写法放进汇编源程序，编译连接之后，`[0][1][2][3]` 会被直接编译成数字 `0`、`1`、`2`、`3`——它取出的是这几个数字，而不是对应内存单元里的内容。

> **结论**：debug 里的代码和汇编源程序里的代码不一样，不能直接用「中括号里写数字」的方式来表示偏移地址。

那怎么办？把数据段显式声明出来，写成「段地址:偏移地址」的形式，比如 `ds:0`，这样就能明确地表示要访问的单元了。

### 一道累加题：把 ffff:0 到 ffff:b 求和

过渡讲完，来看一个问题：把 `ffff:0` 到 `ffff:b` 这些单元中的数据累加起来，结果存到 `dx` 中。

有前面学的循环，这题不难：从偏移地址 0 一直加到偏移地址 `b` 就行。但先别急着写，得想一件事——运算结果会不会超出 `dx` 能存的范围？

我们来算一下。这些单元都是字节单元，一共有 12 个（0 到 b）。每个字节单元最大能存多少？一个字节有 8 个二进制位，最大值是 $2^8-1$，也就是 255；换个说法，一个字节单元可以用两个十六进制位表示，所以上限是 $16^2-1$，同样是 255。

$$255 \times 12 = 3060$$

而 `dx` 是 16 位的，上限是 $2^{16}-1$，也就是 65535。3060 是千级数，65535 是万级数，肯定存得下。

> **结论**：内存单元里的数据是字节型的，范围在 0~255 之间，12 个这样的数据相加，结果一定不会大于 65535，可以在 `dx` 中放下。

#### 为什么不能直接加到 dx，也不能只加到 dl

那能不能把 `ffff:0` 到 `ffff:b` 的数据直接累加到 `dx` 中？不行。因为 `dx` 是 16 位寄存器，和它做运算的操作对象会被当成「字型数据」。也就是说，如果直接写 `add dx, ...`，它每次会一次取出两个内存单元（比如把 `0`、`1` 两个单元一起取出来），把其中一个当高八位、一个当低八位拼成一个字加进去——这和我们想要的「逐字节累加」根本不是一回事。

> **易错点**：`ffff:0` 到 `ffff:b` 中的数据都是八位的，不能直接加到 16 位的 `dx` 中；一旦直接加，访问内存时就会按字单元来取，白白多取一个字节。

那换个思路：能不能把数据直接放进 `dl`，再把 `dh` 设成 0，从而实现累加到 `dx`？也不行。`dl` 是 `dx` 的低八位，最多只能表示 $2^8-1=255$；只要这 12 个数据累加过程中超过了 255，就会产生进位，而进位在 `dl` 里存不住，会被丢掉。

于是问题就变成：怎么把一串八位数据，安全地累加进一个 16 位寄存器？

#### 用 ax 做中介

两种看起来可行的写法，其实都有毛病：

| 写法 | 问题 |
| :--- | :--- |
| `dx = dx + 内存八位数据` | 两个运算对象的类型不匹配 |
| `dl = dl + 内存八位数据` | 结果可能溢出（进位丢失） |

所以必须找一个 16 位的寄存器来做中介。这里的办法是：把内存里的八位数据先复制到 16 位寄存器 `ax` 的低八位 `al` 中，再把整个 `ax` 的值加到 `dx` 上——`ax` 是 16 位的，和 `dx` 类型匹配，加进去就不会丢进位。

> **提示**：做赋值之前，一定要先把 `ax` 整个置为零。因为我们每次只是覆盖 `al`（低八位），如果 `ah`（高八位）里还残留着旧数据，加到 `dx` 里的就不是我们想要的那个字节值了。

### 用 bx 当偏移地址的「变量」

想清楚之后，代码就好写了。数据段地址是 `ffffh`，先把 `ds` 设好；循环需要一个索引变量，可以把它理解成 C 语言里的那个 `i`，也可以把这一串连续空间看成一个数组；再把 `dx`、`ax` 初始化，`cx` 里放循环次数。

```asm
assume cs:code
code segment
    mov ax, 0ffffh
    mov ds, ax
    mov bx, 0
    mov dx, 0
    mov ax, 0
    mov cx, 12
s:  mov al, [bx]
    add dx, ax
    inc bx
    loop s
code ends
end
```

循环体里最关键的一条是 `mov al,[bx]`。中括号里放的是寄存器 `bx`，而不是数字——这正是上一节讲过的：

- 如果中括号里放的是寄存器，它会把寄存器里的值读出来，再和数据段地址拼合，得到真正的逻辑地址；
- 如果中括号里放的是数字，汇编源程序会把它编译成那个数字本身，而不是偏移地址。

> **结论**：中括号里可以放寄存器，但不能放数字。放寄存器会被翻译成「段地址 + 偏移地址」；放数字会被编译成真正的数字。

之后把 `ax` 的值加到 `dx` 上（`add dx,ax`），再让 `bx` 自增一（`inc bx`），最后用 `loop s` 控制循环。

#### 循环为什么必须用变量

12 条相似的操作，只有中括号里那个偏移地址不同，其余都一样，所以完全可以做成一个循环。问题是：循环里偏移地址必须能递增，不能每次都是同一个常量。于是就不能在指令里用常量来表示偏移地址，而要把它放进一个变量里——也就是 `bx`，用 `[bx]` 的方式访问内存单元，循环开始前把 `bx` 置零，每次循环让它加一。

从数学上看，这个过程就是把下面这一串加起来：

$$
(\text{ffffh} \times 10\text{h} + 0) + (\text{ffffh} \times 10\text{h} + 1) + \cdots + (\text{ffffh} \times 10\text{h} + \text{bh})
$$

中间变化的只有偏移那个数：`x` 从 0 一路变到 `b`，把对应的内存单元取出来累加即可。

> **结论**：实际编程中经常遇到「用同一种方法处理地址连续的内存单元中的数据」这类问题，需要用循环来解决；而循环要求每次都能按同一种方式改变要访问的地址，这时就不能用常量给出内存单元地址，必须用一个变量（比如 `bx`）。`mov al,[bx]` 里的 `bx` 就可以看作代表内存单元地址的变量，不改指令、只改 `bx` 的值，就能改变访问的单元。

这里为什么可行？因为偏移地址由 `bx` 给出，而段地址默认就在 `ds` 中。中括号里是寄存器，所以它会被拼成「段地址 + 偏移地址」；中括号里要是数值，在汇编源程序里就会被编译成一个真正的数值。

#### 地址是怎么拼出来的

上面反复出现的「段地址 × 16」，来自地址加法器的工作方式：把数据段地址取出来，向左移一位——注意这是十六进制意义上左移一位，换成二进制就是左移四位，效果就是乘 16——得到段基地址，再加上偏移地址，才是实际的物理地址。

```text
段地址 ffffh
   │  × 16（十六进制左移一位 / 二进制左移四位）
   ▼
段基地址 ffff0h
   │  + 偏移地址 x
   ▼
物理地址 ffff0h + x
```

读图：段地址先换算成段基地址，再与偏移地址相加，得到最终访问的物理地址。

### 段前缀：不写，默认就是数据段

现在可以正面回答开头那个差异了。在访问内存单元的指令里，可以显式地给出「内存单元的段地址所在的段寄存器」。这种出现在访问内存单元指令中、用来显式指明段地址的写法，在汇编语言里就叫**段前缀**。

> **定义**：段前缀，是出现在访问内存单元指令里、用于显式指明该单元段地址的段寄存器写法。

如果不显式声明用哪个段，那么默认就是数据段——段地址取 `ds`。

### 为什么不能随便往一段内存里写

再看一个更根本的问题。在 8086 模式下，随意向一段内存空间写入内容是危险的：这段空间里很可能存放着重要的数据、系统数据或者代码。所以要写数据，得先找一个安全的空间。

比如这样一段 debug 里的指令：

```asm
mov ax, 1000h
mov ds, ax
mov al, 0
mov [0], al
```

它在 debug 里写起来很方便，但并不合理——因为我们没有论证过 `1000:0` 处到底存着什么。如果在程序运行过程中把系统数据或代码改掉了，就会引发错误。有些程序就是这样，恰好改到了系统代码所在的位置，于是直接报错。

> **易错点**：不能在没有确认某段内存是否存放着系统数据或代码之前，就随意往里面写内容。

在 Windows 2000 的 DOS 方式下执行 `mov [0026],ax` 这类操作，情况又不一样：它运行在保护模式下，每个进程都有自己的虚拟空间，不会影响到别的程序。但 `0:0026` 处存放的是重要的系统数据，`mov [0026],ax` 会把它改写掉——放到实模式下去执行，后果就不同了。

#### 直接对硬件编程，还是守操作系统的规矩

不能忘记：我们是在操作系统的环境里工作，操作系统管理着所有资源，也包括内存。但我们也得记住自己在学什么——学汇编，是为了获得基本的编程体验，是为了从底层理解计算机。所以我们是对硬件直接编程，而不是绕过硬件去迁就操作系统。

于是就有了一个选择：是遵守操作系统定下的安全规则，还是自由地、直接用汇编去操作真实的硬件、去了解那些早已被操作系统软件盖住的真相？大多数时候我们会选后者——自由地、直接地用汇编操作真实的硬件。

在纯 DOS 实模式下，可以不理睬 DOS，直接用汇编操作真实的硬件，因为它运行在 CPU 实模式，DOS 没有能力对硬件系统做全面严格的管理。但在 Windows 2000、Linux 这些运行于 CPU 保护模式下的系统里就不一样了：硬件已经被操作系统利用保护模式提供的功能全面而严格地管理起来，此时不理操作系统、直接用汇编去操作硬件是不可能的。

#### 一块公认安全的空地

后面我们确实需要直接往内存里写内容，又不希望撞上系统数据，那就得找一块安全的空间。在一般的 PC 上、DOS 方式下，DOS 和其他合法程序一般都不会使用 `0:200` 到 `0:2ff` 这 256 个字节的空间，所以用这段空间是安全的。

> **结论**：要直接往内存里写内容，这段内存就不该放着系统或其他程序的数据和代码，否则可能引发错误。在 DOS 方式下，`0:200`~`0:2ff` 一般没有系统或其他程序的数据和代码，是安全的；以后需要直接写内存时，就用 `0:200`~`0:2ff` 这段。

为了谨慎起见，可以进 debug 看一眼这段内存的内容，如果全是零，那就可以放心往里写。

### 拷贝一段数据：段前缀的又一次用处

最后来看一个和前面差不多的题：把内存 `ffff:0` 到 `ffff:b` 中的数据拷贝到 `0:200`~`0:20b` 这段单元里。

先说一个等价关系：`0:200`~`0:20b` 等同于 `0020:0`~`0020:b`，它们描述的是同一段内存空间。为什么要换成 `0020:` 这种写法？是为了让目标单元的偏移地址和源单元的偏移地址都从同一个数字 0 开始，这样源和目的就能共用同一个 `bx` 寄存器，少用一个寄存器。

拷贝过程同样用循环：初始化 `x = 0`，循环 12 次，把 `ffff:x` 单元中的数据送入 `0020:x`。这里没法直接复制，还得用一个寄存器（比如 `ax`）中转，中转完再把 `x` 加一。

循环里源单元 `ffff:x` 和目的单元 `0020:x` 的偏移地址 `x` 都是变量，所以用 `bx` 存放它。

这里有个效率问题：源单元 `ffff:x` 和目标单元 `0020:x` 相距大于 64K，落在不同的 64K 段里。如果只用 `ds`，那每次循环都要先设一次 `ds` 指向源、再设一次 `ds` 指向目的——程序虽然是对的，但性能不高，效率低。

优化的办法是用两个段寄存器分别存放源和目的：用 `es` 存目标空间的段地址（`0020h`），用 `ds` 存源空间的段地址（`ffffh`）。这样在访问内存的指令里，显式地用冒号给出单元的段地址：

```asm
mov al, [bx]
mov es:[bx], al
```

`[bx]` 不写段前缀时默认走数据段，也就是从 `ds:[bx]` 读；写 `es:[bx]` 则显式指明目的单元的段地址在 `es` 里。这样一来，循环里就省掉了重复 12 次设置 `ds` 的步骤。

> **结论**：用 `es` 存放目标空间的段地址、用 `ds` 存放源空间的段地址，在访问内存单元的指令里用 `mov es:[bx],al` 这种带冒号的写法显式给出段地址，就不必在循环中反复设置 `ds`。

> **承前启后**：上一节讲完「段前缀与连续内存单元的循环访问」，下一节接着讲「一段当多段用：在代码段里同时放数据与栈」。

## 一段当多段用：在代码段里同时放数据与栈
> 对应块：BLK13 | 覆盖分集：P21-P22 | 块标题（分集名）：《代码段兼作数据段与栈》

前面我们写的程序都只有一个代码段，指令、数据、栈全挤在同一个段里。可这里有个绕不开的问题：如果程序需要用别的空间来存放数据，到底该放到哪里去？第五章我们讲过，要用一段安全的空间来存数据——可哪里才算安全呢？我们当时说，`0:200` 到 `0:300` 这一段是相对安全的，可它的容量只有 256 个字节。万一我们要用的空间超过 256 个字节，那又该怎么办？只能去找别的段。

这一章讲的就是包含多个段的程序。写程序讲究高内聚、低耦合，把数据、代码、栈分开放在不同的段里，本来就是很有必要的。不过在决定"以后到底该怎么写"之前，我们先亲手体会两件事：第一，把数据、代码、栈全塞进一个代码段里用，是什么感觉；第二，把它们放进不同的段里，又是什么感觉。体会完了，再回过头来定以后的写法。

### 在代码段中使用数据

先看第一种：在代码段中使用数据。题目是这样的——编程计算以下八个数据的和，把结果存放在 ax 寄存器中。

前面我们累加内存单元的时候，是直接找出内存单元的值，一个一个相加，并不关心数据本身是什么。现在不一样了：我们要累加的是已经给定好数值的数据，得把数据本身安排进程序里。

#### 用 dw 定义八个字型数据

我们在代码段的最开头，用 `dw` 连续定义这些数据：第一个是 `0123h`，接着是 `0456h`、`0789h`、`0abch`……八个字型数据就这样依次往下定义。

`dw` 是 **define word** 的缩写，意思是定义一个**字型数据**。像这种关键字，最好连它的全称一起记住，比死记两个字母牢靠得多。

一个字型数据占几个字节，取决于 CPU 的字长。我们这里是 16 位 CPU，字长是 16 个二进制位，也就是 2 个字节；如果换成 32 位系统，字长是 32 位，一个字型数据就占 4 个字节；64 位的话，一个字型数据对应 8 个字节。所以这八个字型数据，一共占 16 个字节。

> **提示**：字型数据占几个字节，看的是 CPU 的字长，不是数据本身写出来有几位。同样写 `dw 0123h`，在 16 位机上占 2 字节，到了 32 位机上就占 4 字节。

#### 用 cs:[bx] 加循环把数据累加

程序要做的就是对这八个数据求和。可它们在哪儿呢？它们就定义在代码段里。程序运行时，`cs` 里存放着代码段的段地址，所以段地址可以直接从 `cs` 拿到；而它们又定义在代码段的最开头，偏移地址就是 0。

我们用 `bx` 存放偏移地址，用循环来累加：

```asm
    mov bx, 0
    mov ax, 0
    mov cx, 8
s:  add ax, cs:[bx]
    add bx, 2
    loop s
    mov ax, 4c00h
    int 21h
```

循环开始前先把 `bx` 清零，让 `cs:[bx]` 指向第一个数据 `cs:0`；每循环一次，`bx` 里的值加 2，`cs:[bx]` 就指向了下一个数据。为什么是加 2 而不是加 1？因为每个字型数据占两个字节，相邻两个数据的偏移量正好差 2。这八个数据的偏移地址依次是 0、2、4、6、8、a、c、e，对应的地址就是 `cs:0`、`cs:2`、`cs:4`……一路到 `cs:e`。循环执行八次，累加就完成了。

#### 在 debug 里看清数据与指令的分界

把程序编译连接成可执行文件之后，先别急着运行，我们用 debug 加载进去看看。用 `u` 命令从偏移 0 开始查看，你会觉得有点不对劲：这里显示的并不是我们写的汇编指令对应的机器码，而是一些之前完全看不懂的东西。

别慌，它确实是程序里的内容，只不过不是指令，而是我们用 `dw` 定义在指令前面的数据。你看这个 `2301`——它不就是 `0123h` 吗？小端存放，低位字节在前，所以 `0123h` 在内存里写出来是 `23 01`。

再用 `d` 命令把前面这段内容看清楚：`2301 5604 8907 bc0a`……正是我们定义的那些数据。也就是说，在代码段里，前 16 个字节是 `dw` 定义的数据，从第 16 个字节开始，才是汇编指令对应的机器码。用 `u 0b3d:0010` 去看，就能看到熟悉的 `mov bx,0`、`mov ax,0`、`mov cx,8` 了。

```text
cs:0     ┌──────────────────────────┐
         │  dw 定义的 8 个字型数据   │  ← 偏移 0 ~ f，共 16 字节
cs:10h   ├──────────────────────────┤
         │  汇编指令对应的机器码      │  ← 程序真正的指令从这里开始
         └──────────────────────────┘
```

读图说明：数据定义在代码段最前面，占满了偏移 `0` 到 `f`；真正的机器码从偏移 `10h` 才起步，两者在内存里是首尾相接的。

#### 用 start 与 end 指明程序入口

问题来了：既然数据占了最前面 16 个字节，那我们怎么才能执行到后面的指令？

在 debug 里加载之后，可以手动把 `ip` 设成 `10h`，让 `cs:ip` 指向第一条指令，再用 `t`、`p` 或 `g` 去执行。可要是直接运行这个可执行文件呢？`ip` 默认是 0，程序一上来就会把那些数据当成指令去执行，那就出问题了——因为程序的入口根本不是我们希望执行的第一条指令。

怎么才能让程序编译连接后直接就能跑，让 `cs:ip` 第一次指向的就是 `10h` 处的那条指令？办法是在第一条指令前面加一个标号 `start`，并且把结尾的 `end` 写成 `end start`。

标号 `start` 同样会在编译时被转换成地址。`end` 除了通知编译器程序结束，还能通知编译器**程序的入口在什么地方**——这样 `ip` 一开始就会指向 `start` 标记的位置。要注意，`start` 和 `end start` 是成双成对出现的，不能把它们拆散。

```text
assume cs:code
code segment
    ; 这里放数据定义
start:
    ; 这里放指令
code ends
end start
```

读图说明：开头先用 `assume` 假定 `cs` 与 `code` 段的对应关系；段内先写数据，再用 `start` 标出程序真正开始运行的地方；最后 `end start` 既标志代码段结束、整个程序结束，也把入口告诉了编译器。

### 在代码段中使用栈

有了在代码段里使用数据的底子，我们再来试一试在代码段里使用栈。这次的题目是：利用栈，把程序中定义的数据逆序存放。

#### 入栈再出栈，把数据逆序

数据放在 `cs:0` 到 `cs:f`，一共八个字型数据，占 16 个内存单元。思路很直接：程序运行时，这八个字单元就在 `cs:0`~`cs:f`；我们先把它们依次入栈，再依次出栈放回这八个字单元，顺序自然就反过来了——靠的就是栈先入后出的特性。

但首先得有一段能当栈用的内存空间。前面说过，这段空间应该由系统来分配；我们可以在程序里用定义数据的方法，获取一段安全的栈空间，再把它当栈来用。

#### 栈空间怎么留、栈顶为什么指向 cs:30

程序里用 `dw` 定义了 16 个字型数据，其实 8 个就够了，因为我们只放 8 个。程序加载后，就获得了 16 个字、也就是 32 个字节的内存空间，位置从 `cs:10h` 到 `cs:2f`。

有人会问：为什么不是到 `cs:30h`？因为 `cs:10h` 本身也算一个内存单元，从 `10h` 开始存，`10h` 也要占，所以最后落在 `2f` 上。

接着把 `ss` 设成 `cs`。注意，不能直接把一个段寄存器赋给另一个段寄存器，得拿 `ax` 当跳板：`mov ax,cs`，再 `mov ss,ax`。然后把栈顶指针 `sp` 指向 `cs:30h`——为什么是 `30h`？因为此时栈里还没有数据，空栈的 `sp` 应该指向这段栈空间的下一个单元，也就是 `30h`。

```text
cs:0     ┌───────────────────────────┐
         │  8 个待逆序的字型数据       │  cs:0 ~ cs:f
cs:10h   ├───────────────────────────┤
         │  预留的栈空间（16 个字）    │  cs:10h ~ cs:2fh
cs:30h   ├───────────────────────────┤  ← ss:sp 初始指向这里（空栈）
         │  汇编指令对应的机器码       │
         └───────────────────────────┘
```

读图说明：数据、栈空间、指令三段依次排在同一个代码段里；`sp` 初始指向栈空间的下一个单元 `30h`，正好是空栈的栈顶位置。

然后 `mov bx,0`、`mov cx,8`，为循环做准备。第一个循环里，用 `push cs:[bx]` 把以 `bx` 为偏移地址的那个内存单元的内容入栈，再 `add bx,2`，`loop`。为什么 `bx` 每次加 2？因为 `push`、`pop` 的操作单位是字，一次压入或弹出两个字节，所以偏移量每次加 2。循环八次，八个数据就都进了栈。

第二个循环开始之前要重新初始化：`mov bx,0`、`mov cx,8`。循环体是 `pop cs:[bx]`、`add bx,2`、`loop`。这样依次出栈，把八个字型数据放回代码段的 `cs:0`~`cs:f`，逆序就完成了。

#### 入口同样要指明

和前面一样，入口必须用 `start` 指明。如果不指明，`cs:ip` 里的 `ip` 默认为 0，程序会先跑去执行数据。

这里还有一点要特别记牢：`dw` 定义的数据**不是运行时才定义的**，而是在程序加载进内存的时候就已经放好了。所以真正的第一条指令在数据之后，必须用标号告诉编译器入口在哪。

用 `dw 0` 给这段栈空间占好位置；空栈时 `sp` 指向 `cs:30h`。要是对栈顶指针为什么指向这里还有疑惑，认真复习一下第三章。

完整的程序大致长这样：

```asm
assume cs:code

code segment
    dw 0123h, 0456h, 0789h, 0abch    ; 八个待逆序的字型数据，其余依次往下写
    dw 0, 0, 0, 0, 0, 0, 0, 0        ; 预留的栈空间（16 个字）
    dw 0, 0, 0, 0, 0, 0, 0, 0
start:
    mov ax, cs
    mov ss, ax
    mov sp, 30h
    mov bx, 0
    mov cx, 8
s1: push cs:[bx]
    add bx, 2
    loop s1
    mov bx, 0
    mov cx, 8
s2: pop cs:[bx]
    add bx, 2
    loop s2
    mov ax, 4c00h
    int 21h
code ends
end start
```

在代码段里使用栈，用法本身并不难，难的是维护——代码、数据、栈全挤在同一个段里，谁在哪、入口在哪，都得自己心里有数。
