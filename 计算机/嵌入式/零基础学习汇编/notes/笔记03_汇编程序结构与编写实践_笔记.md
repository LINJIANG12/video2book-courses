# 汇编程序结构与编写实践

## 段寄存器与调试命令的交互

### 调试命令的段寄存器寻址

* **段寄存器**
    * > **定义**：CPU 中用于存放段地址的寄存器，共 `cs`、`ds`、`ss`、`es` 四个。
    * `d 段地址:偏移地址` 不限定范围时一次能看 128 个内存单元。
    * debug 执行 `d 段地址:偏移地址` 时，会先把段地址送入数据段寄存器 `ds`，再去访问内存。
    * 之所以用 `ds`，是因为 `d` 命令访问的是内存里的数据，借助数据段寄存器 `ds` 暂存要访问的段地址。
    * `d 段寄存器:偏移地址` 直接拿某个段寄存器里的值当段地址，再与偏移地址拼成最终物理地址。
    * 先用 `r ds` 把 `ds` 改成 `1000`，再用 `d ds:0`，看到的就与 `1000:0` 开始的内存一样。
    * `u cs:0` 从 `cs:0` 对应的物理地址开始，以汇编指令形式显示当前代码段里的代码。
    * `a` 配合段寄存器，可以从代码段的起点开始向内存里写入指令。
    * `e` 用来更改内存单元的内容；`a` 用来向内存中写入汇编指令；`u` 用来把机器码翻译成汇编指令。
    * 凡是带内存单元的命令，都可以用「段寄存器:偏移地址」来指定段地址。

### 修改 ss 的指令连带下一条执行

* 在 debug 里用 `t` 命令执行一条修改 `ss` 的指令时，它的下一条指令也会被紧接着执行。
* 机理：这是一个中断机制在起作用。
* 程序示例：

    ```asm
    mov ax, 2000
    mov ss, ax
    mov sp, 10
    mov ax, 3123
    push ax
    mov ax, 3366
    push ax
    ```

* 逐条 `t` 执行时，`mov ss, ax` 执行完不会单独显示 `mov sp, 10`，而是直接跳到 `mov ax, 3123`。
* `mov sp, 10` 确实执行了，只是没被单独显示：执行后 `sp` 变成 `0010`。

## 源程序的构成

### 汇编指令、伪指令与标号

* **汇编源程序**
    * > **定义**：用汇编语言写出、由汇编指令、伪指令和标号组成的程序。
* **汇编指令**
    * > **定义**：有对应机器码的指令，可以被编译为机器指令，最终由 CPU 执行。
* **伪指令**
    * > **定义**：没有对应机器码、最终也不会被 CPU 执行的指令，由编译器执行。
    * 编译器根据伪指令来做相关的编译工作。
* **标号**
    * > **定义**：代表一个地址的名字。
    * `codesg` 放在 `segment` 前面，就是给这个段起名，标示这个段叫 `codesg`。
    * 段名最终会被编译连接程序处理成一个段的段地址。
    * 通过 `assume cs:codesg` 把 `cs` 和这个段关联起来。

### 段定义伪指令 segment 与 ends

* **`segment` 与 `ends`**
    * > **定义**：成对使用的伪指令，用来定义一个段的开始与结束。
    * `segment` 说明一个段的开始；`ends` 说明一个段的结束。
    * 写法是 `段名 segment` 开头、`段名 ends` 结尾。
    * 一个汇编程序由多个段组成，这些段分别用来存放代码、数据，或当作栈空间，于是有了代码段、数据段、栈段。
    * 一个有意义的汇编程序至少得有一个段，而且必须有一个代码段。

### 结束伪指令 end

* **`end`**
    * > **定义**：汇编程序的结束标志。
    * 编译器在编译过程中一碰到 `end` 就结束对源程序的编译。
    * 程序写完后一定要在结尾加上 `end`，否则编译器不知道程序在哪里结束，会一直编下去。
    * > **易错点**：`end` 和 `ends` 长得像。把 `ends` 看成 `end segment`，即「段结束」的缩写，这样就好区分。

### 关联伪指令 assume

* **`assume`**
    * > **定义**：假设某一个段寄存器和程序中某个用 `segment`/`ends` 定义的段相关联，并说明这种关联。
    * 在需要的情况下，编译程序可以把段寄存器和某一个具体的段相联系。
    * 引入的原因是：若每次都写 `mov ax, xxx`、`mov ds, xxx` 给段寄存器赋值，太麻烦。
    * `assume cs:codesg` 的意思就是把代码段的地址交给 `cs` 寄存器。

### 源程序与程序的区别

* **源程序与程序**
    * 源程序文件里的所有内容，都叫源程序。
    * 源程序中最终由计算机执行处理的指令或数据，才叫程序。
    * 源程序和程序不相等：只有最终由计算机处理的指令和数据，才称得上「程序」。
    * 程序最先以汇编指令的形式存在于源程序当中，经过编译连接后转变成机器码，才存进可执行文件。

## 从源程序到可执行文件

### 生成与运行四步

* **编写、编译、连接、执行**
    * > **定义**：一个源程序从写出到执行要经过的四个步骤。
    * 编写：用文本编辑器（如 notepad 记事本）用汇编语言写汇编源程序。
    * 编译：用汇编语言的编译程序对源程序文件进行编译，产生目标文件。
    * 连接：用连接程序对目标文件进行连接，生成能在操作系统中直接运行的可执行文件。
    * 执行：在操作系统中执行可执行文件里的程序。

    ```text
      文本编辑器写出的源程序 a
                │  汇编（编译程序）
                ▼
            目标文件
                │  连接（连接程序）
                ▼
      可执行文件 b
      ┌────────────────────────┬────────────────────────┐
      │  机器码与数据           │  相关描述信息           │
      │ （由汇编指令翻译而来）   │ （程序多大、占多少内存） │
      └────────────────────────┴────────────────────────┘
                │  操作系统按描述信息加载、初始化 cs:ip
                ▼
              内存中运行
    ```

### 可执行文件的两部分

* **可执行文件的组成**
    * 一部分是程序：从源汇编指令翻译过来的机器码和数据。
    * 另一部分是相关的描述信息：比如程序有多大、要占多少内存空间等。
    * 描述信息必不可少：执行程序要先把它加载到内存，加载就得分配内存空间，靠描述信息才知道该分配多少内存。
    * 操作系统依照描述信息把机器码和数据加载进内存，并做相关初始化（比如先把 `cs:ip` 设置成指向第一条要执行的指令）。
    * 指向第一条指令之后，这段内容才被 CPU 认作一个程序，然后由 CPU 执行。

### 连接的三个作用

* **连接的作用**
    * 把大程序拆开做：程序很大时可分成多个源程序文件分别编译，各自编译成目标文件后，再用连接程序连在一起生成一个可执行文件。
    * 把库接进来：程序中若调用了某个库中的子程序，就要把这个库文件和该程序生成的目标文件连接在一起，形成可执行文件。
    * 处理目标文件里还不能直接用的内容：目标文件包含所有机器码，但有些内容还不能直接用来生成最终可执行文件，连接程序要把它们处理成最终的可执行信息。
    * 即使一个源程序文件没有调用任何库的子程序，也仍然必须用连接程序处理一遍目标文件，才能生成可执行文件。

## 程序返回与操作系统外壳

### 程序返回

* **程序返回**
    * > **定义**：一个程序结束后，把 CPU 的控制权交还给使它得以运行的程序，这个过程叫程序返回。
    * DOS 是单任务操作系统，当前只允许一个任务在执行，因此存在程序间的交接问题。
    * 一个程序 p2 必须由一个正在运行的 p1 从可执行文件加载到内存，再把 CPU 控制权交给 p2，p2 才能运行；p2 一开始运行，p1 就得暂停。
    * 返回的做法是在程序末尾添加返回的程序段。
    * 返回程序段用的两条指令性质是汇编指令，由 CPU 执行，因为要靠 CPU 才能把控制权传回给之前的程序。
    * > **提示**：这两条指令为什么这么写暂不深究，只要记住它的性质是汇编指令即可。

### 三种结束的对照

* **段结束、程序结束、程序返回**

    | 名称 | 写法 | 指令性质 | 谁来执行 |
    | :--- | :--- | :--- | :--- |
    | 段结束 | `段名 ends` | 伪指令 | 编译器 |
    | 程序结束 | `end` | 伪指令 | 编译器 |
    | 程序返回 | 程序末尾的两条指令 | 汇编指令 | CPU |

### 操作系统的外壳

* **操作系统的外壳（shell）**
    * > **定义**：任何通用操作系统都要提供的、供用户用来操作系统的程序。
    * DOS 的外壳是 `command.com`，在 DOS 中称为命令解释器。
    * 在 DOS 中执行 `1.exe` 时，是通过正在运行的 `command.com` 把程序加载入内存的。
    * 随后 `command.com` 设置 CPU 中的 `cs:ip` 指向程序的第一条指令，CPU 才把它当成程序、程序才得到运行。
    * 程序运行结束后返回 `command.com`，CPU 继续运行这个外壳。

    ```text
    1.asm --(masm 编译)--> 1.obj --(link 连接)--> 1.exe
                                                    │
                                command.com 加载入内存
                                                    │
                           设置 CS:IP 指向程序第一条指令
                                                    │
                              程序运行，结束后返回 command.com
    ```

## 可执行程序的加载

### DOS 加载 .exe 的过程

* **DOS 加载 .exe 的步骤**
    * 先找到一段起始地址为 `SA:0000`（偏移地址为 0）的空闲内存区，容量要足够装得下。
    * 在这段内存区的前 256 个字节中，创建一个称为程序段前缀（PSP）的数据区，DOS 利用 PSP 和被加载的程序进行通信。
    * 从这段内存区的第 256 个字节处开始，装入程序。
    * 把这段内存区的段地址存入 `DS` 中，并初始化其他寄存器，最后设置 `cs:ip` 指向程序的入口。
    * > **提示**：程序加载时还有一步称为重定位的工作，它和操作系统关系比较大，不展开。

### 程序段前缀 PSP

* **程序段前缀（Program Segment Prefix，PSP）**
    * > **定义**：可执行文件被加载时，在内存区前 256 个字节处创建的数据区，供机器与程序通信。
    * PSP 占 256 个字节，也就是 $16^2$，写成十六进制就是 `100h`。
    * 空闲内存区从 `SA:0000` 开始，`0~255` 这些字节放 PSP，从第 256 个字节起才存放程序。
    * 为了让 PSP 和程序区分开，一般把它们划分到不同的段里。

    ```text
            SA:0000  ┌───────────────────────────┐
                     │  PSP（256 字节）          │  ← DS 指向这里
       (SA+10H):0000 ├───────────────────────────┤
                     │  程序（1.exe 的机器码）   │  ← CS:IP 指向这里
                     └───────────────────────────┘
    ```

    * PSP 的段地址是 `SA`，程序所在段的段地址是 `SA+10H`；两者物理上连续，段地址不同。
    * 程序所在内存区的地址可写成 `SA:0`，其物理地址为 $SA \times 16 + 0$；PSP 占 256 字节，程序的物理地址为

    $$SA \times 16 + 0 + 256 = SA \times 16 + 16 \times 16 = (SA + 10h) \times 16$$

    * 用「段地址:偏移地址」表示就是 `(SA+10h):0`，这正是加载时把程序地址设为 `SA+10H:0` 的原因。

## 编写第一个程序

### 源程序的书写

* 用 `edit` 打开 DOS 自带编辑器，把源程序逐字敲入；保存用 `File` 菜单的 `Save`，汇编文件后缀固定为 `.asm`。
* 结构顺序：先用 `assume` 把段寄存器和自己的段名关联，再开始 `codesg segment`，写上真正干活的指令，最后用 `ends` 标志代码段结束、用 `end` 标志整个程序结束。
* 程序示例：

    ```asm
    assume cs:codesg

    codesg segment

        mov ax,0123h
        mov bx,0456h
        add ax,bx
        add ax,ax

        mov ax,4c00h
        int 21h

    codesg ends

    end
    ```

* `start` 标记的意思是标明程序从哪里开始。
* > **提示**：`start` 这个标号只有在需要用 `end start` 指明程序入口时才有意义；当程序入口就是第一条指令、不需额外指定时，最后不保留该标号，`end` 后面也不带操作数。
* 计算 2 的三次方的完整程序：先定义一个段，把处理任务写进去（在 `ax` 上不断加 `ax` 得到 8），程序结束时写上 `end`，最后用 `assume cs:abc` 把段和段寄存器关联（`abc` 是段的标号）。
* 之所以能这样关联，是因为标号最终会被处理为这个段的首地址，`assume cs:abc` 就相当于把代码段的首地址交给了 `cs`。

### 编译 masm

* **目标文件**
    * > **定义**：对一个汇编源程序进行编译时得到的最终结果。
    * 运行 `masm` 进入编译程序后，它先问要编译哪个文件。
    * 文件后缀是 `.asm`，直接输入文件名即可；不是 `.asm` 后缀，必须输入全名。
    * 文件不在当前路径下要指明所在路径；就在当前路径下只输文件名即可。
    * 接着问 `Object file name`，即目标文件的名字，默认是 `1.obj`。
    * 再问列表文件（编译目标文件时产生的中间文件，可以不生成，按 `n`）和交叉引用文件（同样是中间结果，不需要，按 `n`）。
    * 屏幕显示编译完成信息即编译成功，最后两行告诉你有没有警告、有没有错误。
    * 有两类错误会导致得不到期望的目标文件：一是程序中有严重错误（severe errors），二是根本找不到给出的源程序文件。

### 连接 link

* **可执行文件**
    * > **定义**：对一个程序进行连接后要得到的最终结果。
    * 连接要运行 `link` 程序，它先提示要连接哪个目标文件，后缀 `.obj` 直接输名字，不然输全名。
    * 接着问可执行文件的名字，默认是 `1.exe`。
    * 再往后提示映像文件（连接成可执行文件过程中产生的中间结果，跳过），最后提示要不要连接某个库。
* **库**
    * > **定义**：包含一些可以调用的子程序的集合；若程序调用了某个库文件中的子程序，就需要在连接时把该库文件和目标文件连接在一起生成可执行文件。
    * 程序没有调用库里的子程序时，直接按回车过去即可。
    * 连接过程中可能提示 `warning`：`no stack segment`，即没有栈段。
    * `warning` 只是警告不是 `error`；`error` 才是最致命、会让目标文件彻底得不到的东西，警告可以放一放。

### 一条命令完成编译与连接

* 直接在文件名后面加分号，可让编译程序对后面所有提问（目标文件名、列表文件、交叉引用文件）都采用默认回答，一路走完。

    ```dos
    masm 1;
    link 1;
    ```

* 因为 `1.asm` 后缀是 `.asm`，文件名写 `1` 就够；连接时扩展名正是对应的 `.obj`，直接写 `1;` 就行。
* 两条跑完，目录里就多了 `1.obj` 和 `1.exe`，可执行文件生成出来。

### 运行结果

* 执行程序直接打开 DOS，输入 `1` 回车；因为 `.exe` 可被操作系统直接执行，扩展名 `.exe` 不用写。
* 屏幕上什么反应都没有，但程序肯定运行了。
* 看不到结果是因为程序只对一些数据做了操作，没有向屏幕输出任何信息，只是进行数据的传送和加法运算。
* 程序执行完返回、屏幕上再次出现操作系统提示符，就标志着程序真正执行过了。

## 栈的入栈与出栈

### 入栈出栈机制

* **栈**
    * > **定义**：遵循后进先出（Last In First Out）的存储结构；`ss:sp` 始终指向栈顶，栈顶里放着数据。
    * 入栈时先把 `sp` 减 2，再把数据放进新的栈顶。
    * 出栈时先把栈顶数据取出，再让 `sp` 加 2。
    * 数据经过栈顶一进一出，顺序就被颠倒过来。

    ```text
       pop ax  ->  ax = 1     ; 取走栈顶后，sp 加 2
       pop bx  ->  bx = 2     ; 再取一次，sp 再加 2
    ```

    ```text
       压栈：先把 sp 减 2，再把值写到新的栈顶
       2000:0Ah      [ 2 ]   <- sp
       2000:0Ch      [ 1 ]
    ```

    ```text
       pop ax  ->  ax = 2
       pop bx  ->  bx = 1
    ```

    * 结论：栈是后进先出；想让两个寄存器的值互换，用 `pop` 和 `push` 一进一出就能办到。

### 入栈改写的内存单元

* 栈段是 `2200`、`sp` 初值是 `0100` 时，第一次 `push` 后 `sp` 减小 2，数据写进 `2200:00fe` 到 `2200:00ff`。
* 第二次 `push` 后 `sp` 再减小 2，数据写进 `2200:00fc` 到 `2200:00fd`。
* 逐条执行 `push ax`、`push bx`、`pop ax`、`pop bx` 后，因为先入栈的后出栈，`ax` 变成原来 `bx` 的值，`bx` 变成原来 `ax` 的值。

### 栈过小导致内存被改写

* **栈的位置和大小**
    * `ss` 设成 `2000`、`sp` 设成 `0010` 时，栈立在 `2000:0010`。
    * 程序执行过程中，`mov` 之类的指令会伴随一些数据入栈；栈空间太小时，压进去的数据就盖住了原本的内容。
    * > **易错点**：不是指令本身写错了，而是把栈开得太小，指令执行过程中的压栈动作覆盖了不该动到的内存；栈的位置和大小是这类「莫名其妙被改写」问题的关键。

## 用 debug 观察程序

### 加载与寄存器

* 用 `debug` 加载程序，它会设置 `cs:ip` 指向程序入口，但**并不放弃对 CPU 的控制**，因此可以用相关命令一条条执行程序、查看每条指令的结果。
* 用 `r` 命令看寄存器情况：可执行文件加载入内存后，`cx` 中存放的是程序的长度。
* 程序机器码共 15 个字节时，`cx` 就是 15（`0Fh`）；`cx` 的作用之一是存放程序的长度。
* 用 `u` 命令查看程序里的指令，反汇编内容与源程序一一对应。
* 用 `t` 命令单步执行每条指令，观察结果；例如 `add ax,ax` 使 `ax` 再翻一倍。
* 最后用 `q` 命令退出 debug。

### 单步执行与中断指令

* > **提示**：`t` 命令会进入中断处理程序内部一条条地跟，`p` 命令则把 `int 21h` 这类指令直接执行完再停下。
* 执行到 `int 21h` 时不要再用 `t`，改用 `p` 命令执行。
* 用 `p` 执行 `int 21h` 之后，屏幕上显示 `Program terminated normally`，即程序正常结束。
* > **易错点**：跟踪到最后的 `int 21h` 时若习惯性按 `t`，会进入中断服务程序，只能把程序重新加载一遍再跟踪；要用 `p` 它才会一次性执行完。

### 控制权返回链

* 在 DOS 里用 debug 时，是 `command.com` 先加载 debug，debug 再加载程序。
* 程序结束时，程序把控制权交回给 debug；再输入 `q`，debug 把控制权交回给 `command.com`。

    ```text
    1.exe ──返回──> debug ──q──> command.com
    ```

* 如果是直接运行程序、没有经过 debug，那么程序结束后就直接返回到 `command.com` 这个外壳里。

## 语法错误与逻辑错误

* **语法错误**
    * > **定义**：在编译时被编译器发现的错误，是可见的，编译器会明确告诉我们错在哪里。
    * 例如把 `assume` 写错，编译器立刻发现并指出位置；像 `end segment` 这类拼写问题也很容易暴露。
* **逻辑错误**
    * > **定义**：编译时体现不出来、运行时才发生的错误，因此不容易被发现。
    * 例如算 2 的三次方的程序若没有写程序返回，丢进编译器编译不会报错，因为语法上没毛病，只是少了一段返回。
    * 少了返回就不行：程序执行完没有把控制权交还给操作系统、也没交还给之前持有控制权的程序，结果是操作系统停在那里，程序到此为止，后面什么都干不了。
    * > **易错点**：程序返回那一段代码必须补上；缺了它编译能过、运行却会卡住。
