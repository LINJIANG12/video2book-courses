#### [00:11] 直接寻址遗留问题补充：字单元覆写与变量独立性

来看这儿。刚才我们讲了存储器寻址当中的第一种——直接寻址，第二种——寄存器间接寻址。刚才讲的是直接寻址，第二种还没讲。

[00:32] 在直接寻址当中，刚才我举的那个例子，有几个同学都问到同一个概念，就是说这么个意思，你看：

`DATA1` 变量指的是一个字节单元，然后 `DATA2` 变量是不是也是 DB 定义的一个字节单元？原来我们定义的 `DATA1` 单元数据是 $12\text{H}$，原来定义的 `DATA2` 单元的数据是 $34\text{H}$。

刚才我们有这么一条指令：


明白吧？

[01:28] 这条指令完成的功能是：`AX` 是 16 位的。我画个图你们就理解了。低八位在 `AL`，高八位在 `AH`。指令完成的是存储器写，把 `DATA1` 连续修改的字单元写。这个字单元是不是以 `DATA1` 为准组成了一个字单元？

在写的时候我们看，像刚才讲的一样，低字节写到低地址单元去了，高字节写到高地址单元来了，就写完了嘛。

那当然，如果 `AX` 有数据，是不是把原来的 $34\text{H}$ 覆盖了？`DATA2` 单元的值就变了嘛。但是 `DATA2` 变量、字节变量还是依然存在。听懂了没有？这是这一点，补充一下。

#### [02:30] 寄存器间接寻址的概念与可用寄存器

下面我们看存储器寻址方式的第二种寻址方式：寄存器间接寻址。

寄存器间接寻址指的是：要寻找的操作数仍然在某存储器单元当中。操作数所在单元的段内 16 位有效地址 $EA$（也就是段内偏移地址），是由一个地址寄存器间接给的。

哪些地址寄存器都可以间接提供地址呢？只有三个：
1. 基址寄存器 `BX`
2. 源变址寄存器 `SI`
3. 目的变址寄存器 `DI`

在前面几节课举的例子当中，是不是还出现过 `BP`？实际上 `BP` 不归属于间接寻址当中，间接寻址里边没有 `BP`。

那么不管用 `BX`，还是 `SI`，还是 `DI` 间接寻址，提供的寄存器的 16 位内容，都是操作数所在单元的 16 位有效地址。段地址不管用哪个寄存器，默认都在 `DS`，都在 `DS`。

#### [04:08] 寄存器间接寻址的实现步骤与寻址方式辨析

如，我们来看：刚才我们在数据段有定义，比如说 `DATA1` 仍然放在这儿，DB。这是数据段的定义：

```assembly
DATA1 DB 12H
DATA2 DB 34H
```

这是我们刚才举例子在数据段定义的两个变量，当然变量名里边的字母大小写都无所谓。当我们在这儿用图示表示的话：这是 `DATA1` 单元，是 $12\text{H}$；这是 `DATA2` 单元，是 $34\text{H}$。

[05:01] 现在我想把 `DATA1` 单元，就是这个单元的数据读出来给 `AL`，你看我怎么做：

我用 `BX` 寄存器做间接寻址：

```assembly
MOV BX, OFFSET DATA1
```

先把 `DATA1` 变量对应单元的偏移地址给 `BX`。后面怎么写？是不是要写一个偏移地址属性操作符？怎么写呢？`OFFSET DATA1`。

那这条指令当中的源操作数的寻址方式是什么寻址？

都不对，立即数寻址！

变量一旦定义了，上节讲的嘛，就具有了五个属性。你现在这个源操作数是不是取 `DATA1` 的 `OFFSET` 属性？属性是具有的，是不是一个常数？那常数是不是立即数？这是立即数寻址，听懂了没有？

那么这条指令完成的功能是：把 `DATA1` 的 `OFFSET` 给 `BX` 寄存器了。那 `BX` 寄存器里边的值，是不是这个单元的 16 位有效地址？

[06:31] 好，接下来：

```assembly
MOV AL, [BX]
```

`BX` 间接寻址。

那么这条指令完成的功能，就是把 `BX` 的内容作为段内 16 位有效地址。哪个段的有效地址呢？默认是不是 `DS` 段的？把这个单元的值——`DS` 段的、以 `BX` 做有效地址的单元。这个单元是一个字节单元还是一个字单元？不明确，看另一方。另一方是不是 `AL`？说明你找到的是一个字节单元，把这个字节单元的内容读出来给 `AL`。

这就相当于把这个单元的数据送给了 `AL`，所以这条指令执行以后，`AL` 是不是等于 $12\text{H}$？

那么在这条指令当中，源操作数采用的是寄存器间接寻址。当我要用寄存器间接寻址来找一个单元时，间接寄存器可以用 `BX`；当然还可以用 `SI`，那这个地方就换成 `SI`；也可以用 `DI`。

立即数没有类型，`[BX]` 间接寻址说明类型了吗？没有。所以这条指令是不是语法错了？

错误的原因是什么呢？类型不明确！理解了没有？

### [01:46] 寄存器相对寻址的概念

再看存储器寻址的第三种，叫寄存器相对寻址。

寄存器相对寻址的含义是：要寻找的操作数仍然在某存储器单元当中。操作数所在单元的段内 16 位有效地址，是由一个基址寄存器——这个基址寄存器是谁呢？是一个基址寄存器 BX，或者基址指针寄存器 BP，或者源变址寄存器 SI，或者目的变址寄存器 DI——作为操作数所在单元的有效地址的一部分，再加上了一个相对位移量，是一个 8 位或者 16 位的 $\text{DISP}$。$\text{DISP}$ 叫做相对位移量。

这两部分之和，是要寻找操作数所在单元的段内 16 位偏移地址。

---

### [03:29] 默认段寄存器与 BP 的特殊性

如果相对位移量是一个常数，那么求得的偏移地址对应的段地址由寄存器来默认给出：
* 寄存器用的是 BX、SI 或者 DI 任意一个，段地址默认在 DS；
* 如果寄存器用的是 BP，段地址默认在 SS。

当然这是相对位移量是常数的情况。

在寄存器相对寻址当中是不是增加了 BP？在寄存器间接寻址当中就没有 BP 了。

显然有这样的指令：

```assembly
MOV [BP], AL
```

这条指令完成的功能是把 AL 的内容写到一个字节单元去。这个字节单元的地址是由 BP 相对寻址给的，基址寄存器相对寻址给的。与 BP 相对，段地址默认在 SS；段内偏移地址的一部分在 BP 中的 16 位，另一部分加了一个位移量，位移量是 0，这不加了个 0 offset 吗？

你们可以上机去验证，写到这个字节单元去。这样的指令汇编后，操作码里面有一个位移量 0。所以 BP 这样书写，只能叫做**寄存器相对寻址**，不能叫做**寄存器间接寻址**。清楚了没有？这一点一定要注意，可以上机去验证、做做实验。

### [05:44] 寻址实例对比：直接寻址与相对寻址

我们再来看，比方我有这样的操作：

```assembly
MOV BX, OFFSET DATA1
```

我把 DATA1 单元的偏移地址送入 BX。这是 DATA1 单元，原来放的是 $12\text{H}$；这是 DATA2 单元，放的是 $34\text{H}$，还是我原来那组数据定义。

现在我想给这个单元写一个数据，把 AL 内容写到这个单元来，怎么做呢？

如果用直接寻址的话，可以写：

```assembly
MOV DATA1+3, AL
```

写到 DATA1 指的这个单元，$+0$、$+1$、$+2$、$+3$，加上 3 也能写进来。这样写的话，这条指令的目的操作数采用的就是直接寻址，直接给出了地址。

### [07:16] 寄存器相对寻址的位移范围

我现在要用相对寻址来做，怎么做呢？我已经让 BX 的内容指向这个单元的偏移地址了，段地址默认在 DS。那我做的话，也可以写：

```assembly
MOV [BX+3], AL
```

加几呢？$+0$、$+1$、$+2$、$+3$，加了一个 8 位的位移量。把 AL 的内容写到 $\text{BX}+3$ 作为有效地址的单元中。BX 的内容加 3 指到这个单元，把 AL 内容写到这个单元来了。

这种寻址方式，目的操作数寻址方式就是寄存器相对寻址。

相对量是一个 8 位的：
* 如果相对量是 8 位的，以它为基准向正方向相对位移，最多位移 $+127$ 个字节；
* 向负方向位移还可以加一个负数，减了个位移量，最大可以到 $-128$ 个字节。

如果位移量是 16 位的：
* 负方向位移是 $-32768$；
* 正方向位移是 $+32767$。

这种寻址方式就称为寄存器相对寻址。

### [08:52] 相对寻址的书写格式与等效表示

在寄存器相对寻址当中，看看这个书写格式。

这种书写格式也可以等效地写成：
* `[BX+3]`
* `[BX+03H]`

把加的位移量放到括号里面去，和加在括号后边是等效的。书写格式不同，汇编后的代码是相同的，所以是等效的。

还可以这样写：
* `3[BX]`

写到前面也是等效的。如果相对位移量加在方括号的左边，加号可以缺省。汇编的时候，碰到一个方括号……

### 寄存器相对寻址（变量作为相对量）与段基确定

**[00:00] 寄存器相对寻址的书写格式**

碰上中括号就起一个“加”的作用，所以加号可以缺省。  
我们来看：一种、两种、三种，虽然书写格式不同，但功能是一样的。在实际的程序设计当中，用哪一种书写格式完全取决于个人习惯，怎么顺手就怎么写。

**[00:23] 相对量为变量的相对寻址指令**

在寄存器相对寻址当中，还有一点需要掌握。  
比如说这几条指令：

```x86asm
MOV BX, 0           ; BX 清零
MOV AL, 0           ; AL 清零
MOV DATA1[BX], AL   ; 将 AL 的内容写入 DATA1[BX] 对应的内存单元
```

这条指令是把 `AL` 的内容写到目的内存单元去。目的地址字节单元的地址是由寄存器相对寻址指定的，这也是一个相对寻址。  
但是这里的相对量不是常数，而是一个变量。当相对量是变量的时候，取该变量的 16 位偏移量（$\text{OFFSET}$）作为相对量。

**[01:23] 有效地址（EA）的计算**

所以这条指令完成的功能是：  
取 $\text{OFFSET DATA1}$ 的 16 位偏移量加上 `BX` 的内容，两部分之和作为 16 位有效地址（EA）：

$$\text{EA} = \text{OFFSET DATA1} + (\text{BX})$$

接着把 `AL` 的内容写入到该有效地址对应的单元中去。

**[01:51] 段基址的确定原则**

现在求得的是有效地址，那么段地址是多少呢？  
此时就不能看寄存器了，必须看变量：**变量在哪个段中定义的，段地址就是哪个段的段基址。**

* 如果变量是在 `ES` 段中定义的，那么段地址就在 `ES`；
* 如果变量是在 `SS` 段中定义的，段地址就在 `SS`；
* 如果变量是在 `DS` 段中定义的，段地址就是 `DS`。

最后将数据写入到该段基与有效地址所确定的物理内存单元中。
