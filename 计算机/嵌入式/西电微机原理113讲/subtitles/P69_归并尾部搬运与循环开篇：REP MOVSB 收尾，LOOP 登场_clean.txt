### [00:00] 复习 8086 循环控制指令

我们在讲循环控制指令时，已经涉及到了很多属于循环程序的例程。

在 8086 指令系统当中，关于循环控制指令一共有四条：
1. 第一条：`LOOP`（计数循环）
2. 第二条：`LOOPZ` / `LOOPE`（相等/结果为零时循环）
3. 第三条：`LOOPNZ` / `LOOPNE`（不相等/结果不为零时循环）
4. 第四条：`JCXZ`（若 `CX` 寄存器为 0 则转移）

这四条指令都属于循环控制指令，主要通过对计数器寄存器（`CX`）进行判定和自动递减来控制循环。

### [01:05] 循环程序的两种基本结构

在学习循环程序设计时，通常有两种基本结构：

1. **先循环工作，后循环判定**
   - **特点**：先执行一次循环体，再进行循环条件判定。
   - **适用场合**：适用于预先已知循环次数的场合，通过 `CX` 减 1 计数来控制循环。

2. **先循环判定，后循环工作**
   - **特点**：进入循环体前先检查条件，满足条件才进入循环工作。
   - **适用场合**：适用于一开始就可能出现“零次循环”的情况，或者在循环过程中可能会提前退出的场合。
   - **优化意义**：在实际程序设计中，为了提高程序的执行效率，面对可能无需执行循环或需提前结束的场景，应优先设计为“先循环判定，后循环工作”的结构。

### [02:30] 示例分析：测试 BX 寄存器中 1 的个数

之前举过一个编程示例：测试 `BX` 寄存器中有几个二进制位为 $1$。

- **算法思路**：
  利用移位指令将 `BX` 寄存器的值向右（或向左）移位，每次移出的一位都会送入进位标志位 `CF` 中。
  - 若 $CF = 1$，说明移出了一位 $1$，计数器加 1；
  - 若 $CF = 0$，则不统计。

- **结构选择与优化**：
  如果采用“先循环工作，后循环判定”的结构，必须固定循环 16 次。但如果一开始 `BX` 的值本身就等于 0，则根本不需要循环 16 次。
  因此应采用先判定的结构：
  1. 一开始先执行比较测试：
     ```assembly
     CMP BX, 0
     JZ  EXIT
     ```
     若 `BX` 为 0，直接跳转至 `EXIT` 提前退出。
  2. 若不为 0，则将 `BX` 右移一位并测试 `CF`。若 $CF = 1$ 则累加计数；统计完成后利用 `LOOP` 将 `CX` 减 1 并返回循环首部。
  3. 循环返回后，再次执行 `CMP BX, 0`，检查剩余位是否已全部为 0。若已为 0，则提前退出循环，避免无效的空转循环。

### [04:14] 循环程序的基本组成部分

无论是哪种循环结构，一个完整的循环程序通常由以下几个部分组成：

1. **初始化部分**
   程序的起点，用于设置初始状态，如计数器赋初值、指针寄存器赋初值、工作单元清零等。
2. **循环工作部分（循环体）**
   完成核心算法和运算任务的主体代码。
3. **参数调整（参数修正）部分**
   在每次循环工作后修改工作参数，例如对指针进行递增/递减修改（如使用 `INC SI`、`INC DI` 等修改地址偏移），为下一次循环做准备。
4. **出口判定（循环判定）部分**
   检查是否满足退出循环的条件。
   - 若使用 `CX` 控制，使用 `LOOP` 指令将 `CX` 减 1 并判断是否为 0；
   - 若基于特定状态控制，使用条件转移指令（如根据 `CF` 标志执行 `JZ`、`JNZ` 等）进行跳转；
   - 若未达到退出条件，则跳转回循环工作部分继续执行；达到条件则退出。
5. **结果处理部分（可选）**
   退出循环后对最终结果进行后续操作，例如将计算结果格式化后输出到屏幕显示。
   *(注：若结果处理在每次循环时即时完成，该独立部分可省略并融入循环工作体中)*

## 核心原理深度推导

### 1. 内存模型构建与段重叠设计（DS = ES）

在 8086 微处理器架构中，串操作指令（如 `MOVSB`, `STOSB`）受硬件寻址逻辑强制约束：
- **源操作数**：默认段地址绑定于 `DS`（可通过段前缀超越），偏移地址绑定于 `SI`。
- **目的操作数**：硬件强制绑定于附加段 `ES`，偏移地址绑定于 `DI`（**严禁段超越**）。

```assembly
CODE SEGMENT
    ASSUME CS:CODE, DS:DATA, ES:DATA
```

讲师强调：本题中源数组 `DATA1`、`DATA2` 与目标数组 `DATA` 均位于同一个逻辑段 `DATA` 中。
- **推导结论**：必须在初始化阶段将段寄存器 `DS` 与 `ES` 赋予相同的段基址（`DS = ES = SEG DATA`），形成**单物理段内的串操作环回环境**。
- **前 6 行代码**：讲师明确指出，程序开始的 1~6 行为微机原理标准运行环境初始化代码（完成 `DS`、`ES`、`SS`、`SP` 的装载），本课重点聚焦于算法核心逻辑，前 6 行略过不作重复推导。

### 2. 数组数据结构定义与内存布局

待处理数组采用“**计数值头 + 连续数据体**”的紧凑存储模型。

#### 内存映射示意图
```text
偏移量:    +0          +1          +2          +3        ...
DATA1:  [  Length_1 (Word)  ] [ Byte 0 ] [ Byte 1 ]  ...  (共 Length_1 字节)
DATA2:  [  Length_2 (Word)  ] [ Byte 0 ] [ Byte 1 ]  ...  (共 Length_2 字节)
DATA:   [ Total_Len (Word)  ] [ Byte 0 ] [ Byte 1 ]  ...  (共 Length_1 + Length_2 字节)
```

#### 初始化指令序列分析
1. **元数据读取（直接寻址）**：
   ```assembly
   MOV CX, DATA1       ; 直接寻址：读取 DATA1 的字单元（数组1元素总数 N1）
   MOV DX, DATA2       ; 直接寻址：读取 DATA2 的字单元（数组2元素总数 N2）
   ```
   *推导逻辑*：`CX` 充当 `DATA1` 的递减计数器（$\Delta CX = -1$ / 元素）；`DX` 充当 `DATA2` 的递减计数器（$\Delta DX = -1$ / 元素）。

2. **目标数组总长度求和**：
   ```assembly
   MOV DATA, CX
   ADD DATA, DX        ; DATA = CX + DX（讲师课堂举例两数之和为 17）
   ```

3. **双源指针对齐与目的指针装载**：
   ```assembly
   LEA SI, DATA1 + 2   ; SI 指向 DATA1 的首个有效数据字节
   LEA BX, DATA2 + 2   ; BX 指向 DATA2 的首个有效数据字节（基址指针）
   LEA DI, DATA + 2    ; DI 指向 DATA 的首个待写入数据字节
   CLD                 ; 清除方向标志位 (DF = 0)，强制串操作地址递增
   ```
   *边界条件*：偏移 `+2` 是因为数组首部占用了一个 `Word`（2 字节）存储数组长度。若不偏移 2 字节，合并过程将破坏元数据并导致数据错位。

### 3. 双路归并核心分支演进与数学状态机

该算法本质上实现的是经典无符号递增双有序数组合并（Two-Way Merge）。但在底层利用了 8086 串操作指令与寄存器复用机制。

#### 核心代码还原与执行流推导
```assembly
L1:
    MOV AL, [BX]        ; 寄存器间接寻址：提取 DATA2 当前候选元素至 AL
    ; 注：讲师在后文推导指出，在此处或提取后 BX 存在自增以支持滑动寻址
L2:
    CMP AL, [SI]        ; 间接寻址比较：DATA2 元素 (AL) vs DATA1 元素 ([SI])
    JB  L3              ; 若 AL < [SI] (无符号低于)，跳转至 L3（DATA2 元素更小）

    ; --- 分支 A：AL >= [SI]，即 DATA1 元素较小或相等 ---
    MOVSB               ; ES:[DI] <- DS:[SI], 同时 SI <- SI + 1, DI <- DI + 1
    DEC CX              ; DATA1 待处理元素计数减 1
    JZ  L4              ; 若 CX == 0，说明 DATA1 已经全部处理完毕，跳转 L4 处理 DATA2 剩余部分
    JMP L2              ; 若 CX != 0，当前 AL (来自 DATA2) 尚未消耗，继续与 DATA1 的下一个 [SI] 比较

    ; --- 分支 B：AL < [SI]，即 DATA2 元素较小 (标号 L3) ---
L3:
    STOSB               ; ES:[DI] <- AL, 同时 DI <- DI + 1（将 AL 写入新数组）
    ; BX 此时指向已写入元素的下一个位置
    DEC DX              ; DATA2 待处理元素计数减 1
    JZ  L5              ; 若 DX == 0，说明 DATA2 已经全部处理完毕，跳转 L5 处理 DATA1 剩余部分
    JMP L1              ; 若 DX != 0，重新从 DATA2 提取下一个元素至 AL
```

#### 关键控制流演进论证
- **状态 1：`AL >= [SI]`**
  表明 `DATA1` 当前元素更小。执行 `MOVSB`，硬件自动完成 `DS:[SI]` 到 `ES:[DI]` 的单字节搬运，并同步自增 `SI` 和 `DI`。此时 `AL` 寄存器中的值**未被使用**，因此在 `DEC CX` 后，若 `CX != 0`，直接执行 `JMP L2`，跳过 `MOV AL, [BX]`，复用当前 `AL` 与新的 `[SI]` 再次比对。
- **状态 2：`AL < [SI]`**
  表明 `DATA2` 当前元素较小。跳转至 `L3`，执行 `STOSB` 将 `AL` 存储至 `ES:[DI]`，硬件自增 `DI`。此时 `DATA2` 消耗一个元素，`DX` 递减。若 `DX != 0`，必须重新执行 `JMP L1`，重新通过 `[BX]` 读取下一个候选值。

### 4. 边界汇聚与指针修正的数学推导（核心难点：为什么必须 `DEC SI`）

当其中一个数组率先耗尽时，算法进入尾部剩余数组的批量复制阶段。

#### 边界情况 A：`DATA2` 先耗尽（$DX = 0$）$\rightarrow$ 跳转至标号 `L5`
- **现场状态**：`DATA2` 全部元素已写入目标数组。`DATA1` 仍剩余 $CX$ 个元素，且当前 `SI` 正确指向 `DATA1` 中尚未搬运的最小元素处。`DI` 正确指向目标数组末尾。
- **处理逻辑**：
  ```assembly
  L5:
      REP MOVSB           ; 将 DS:[SI] 剩余的 CX 个字节全部呼呼搬移至 ES:[DI]
      MOV AH, 4CH         ; 退出程序
      INT 21H
  ```
- **复杂度演进**：利用硬件微码级指令 `REP MOVSB`，一次性完成残余连续内存的倾倒，无分支跳转开销。

#### 边界情况 B：`DATA1` 先耗尽（$CX = 0$）$\rightarrow$ 跳转至标号 `L4`
此处的指针修正逻辑是讲师着重拆解的黑板板书核心推导：

```text
【时序逻辑状态分析】
1. 进入 L2 比对时：AL 暂存了 [BX] 的数值。
2. 随后经历若干次 MOVSB，DATA1 被全部消耗，CX 减至 0，触发 JZ L4。
3. 此时的致命边界条件：
   - AL 中保存的那个 DATA2 元素并没有被写入目标数组（因为当时它比 [SI] 大）！
   - 指针 BX 在先前的逻辑中已经完成递增，指向了 AL 之后的一个单元。
   - 换言之，DATA2 尚未写入目标数组的实际数据起点，正好落在 (BX - 1) 处。
```

- **板书指令推导**：
  ```assembly
  L4:
      MOV SI, BX          ; 将 DATA2 当前跟踪指针 BX 交付给源串操作指针 SI
      DEC SI              ; 【核心修正】：由于先前取数/更新时指针超前，此处必须强制减 1，
                          ; 回退寻址至尚未搬移的那个有效数据单元！
      MOV CX, DX          ; 将 DATA2 剩余未处理元素个数 DX 赋予串操作计数器 CX
      REP MOVSB           ; 批量将 DATA2 剩余的 CX 个元素倾倒至 ES:[DI]
      ; 随后汇聚到程序正常退出
  ```
- **数学代数证明**：
  设未处理元素在物理内存中的真实基准偏移为 $Addr_{pending}$。
  由于寻址过程中存在预自增特性，此时的寄存器状态为 $BX = Addr_{pending} + 1$。
  欲使用 `REP MOVSB` 从源地址搬运，必须使源串指针 $SI$ 满足：
  $$SI = Addr_{pending}$$
  代入得：
  $$SI = BX - 1$$
  因此，在执行 `MOV SI, BX` 后，**必须显式执行 `DEC SI` 进行边界代数对消**。若漏掉 `DEC SI`，将导致目标数组丢失一个未写入元素，且在尾部发生越界读入脏数据。

## 知识对比矩阵

### 1. 8086 寻址方式在合并算法中的应用矩阵

| 寻址方式 | 汇编语法代表 | 操作数物理寻址公式 | 在本算法中的工程角色 | 优缺点分析 |
| :--- | :--- | :--- | :--- | :--- |
| **直接寻址** | `MOV CX, DATA1` | $EA = \text{Disp}$ | 读取数组长度元数据 | 简单直接；地址静态硬编码，无法动态滑动 |
| **寄存器间接寻址** | `MOV AL, [BX]`<br>`CMP AL, [SI]` | $EA = (BX)$ 或 $(SI)$ | 标量比对与滑动窗口遍历 | 指针灵活自增；每次访问需要显式维护指针与重取操作 |
| **串操作隐式寻址** | `MOVSB`<br>`STOSB` | 源: $(DS) \times 16 + (SI)$<br>目: $(ES) \times 16 + (DI)$ | 批量自动化数据转移与写入 | 硬件级自增指针，执行速度极快；受特定寄存器绑定限制 |

### 2. 标量循环分支合并 vs. 串操作指令合并方案对比

| 评价维度 | 标量通用寄存器归并方案（纯 MOV 循环） | 串操作指令归并方案（本课讲解方案） |
| :--- | :--- | :--- |
| **核心指令集** | `MOV`, `CMP`, `JMP`, `INC/DEC` | `MOVSB`, `STOSB`, `REP MOVSB`, `CLD` |
| **代码编写复杂度** | 较高（需手动编写大量递增与显式搬运指令） | 较低（巧妙借用硬件指令集语义简化流程） |
| **指针管理开销** | 每次写入均需手动执行 `INC DI`, `INC SI` | `MOVSB`/`STOSB` 硬件微码自动维护 `DI`/`SI` |
| **尾部清理吞吐率** | 需常规格外编写残余 `LOOP` 循环，吞吐量低 | `REP MOVSB` 达到总线吞吐极限，效率极高 |
| **边界陷阱风险** | 逻辑平铺直叙，指针超前错误率低 | 需精确掌控隐式自增与超前指针回退（如 `DEC SI`） |

## 反模式与踩坑清单

### 1. 反模式：串操作方向标志未显式初始化
- **错误场景**：在执行 `MOVSB`、`STOSB` 之前，未显式调用 `CLD` 清除方向标志位。
- **底层隐患**：8086 的 `DF`（Direction Flag）状态可能受前序未知模块污染。若 `DF = 1`，`MOVSB` 和 `STOSB` 会导致 `SI` 和 `DI` 自动**递减**，导致内存写入向低地址段反向覆盖，彻底破坏程序段或造成系统崩溃。
- **防御方案**：所有涉及串操作初始化的序灵代码段，必须强制优先执行 `CLD` 指令。

### 2. 踩坑点：标量预读导致指针超前未回退
- **错误场景**：在 `L4` 标号处，直接执行 `MOV SI, BX` 后紧接着执行 `REP MOVSB`，遗漏 `DEC SI`。
- **故障现象**：合并后的数据中丢失了一个关键较小数值，且数组末尾读入了一个未知的越界字节。
- **根因分析**：由于 `AL` 先前通过 `[BX]` 取出了该元素，而指针已经逻辑后移；但在多轮比对分支中，该元素未能通过 `STOSB` 消耗，仍滞留在标量寄存器中。
- **防御方案**：严格执行代数对齐推导，确保 `MOV SI, BX` 后执行 `DEC SI` 进行物理同步。

### 3. 常见认知盲区：`DS` 与 `ES` 混淆
- **错误场景**：编写串操作时，试图通过段超越前缀将目的串重定向到 `DS:[DI]`。
- **硬件事实**：8086 处理器微架构硬件强制规定：`DI` 的段基址寄存器**永久固定为 `ES`**，段超越前缀对其无效。讲师指出，当源串与目标串同段时，唯一的工程解法是令 `DS` 与 `ES` 同时指向该数据段。

## 2. 8086 循环控制指令系统

在 8086 处理器指令系统中，许多初学者容易将“条件转移指令”与“循环控制指令”混淆。条件转移指令数量众多（十余条至几十条不等），但**专职的循环控制指令在 8086 指令系统中严格只有 4 条**：

1. **`LOOP`（计数循环指令）**：
   * 自动将计数值 $CX \leftarrow CX - 1$；
   * 判定条件：若 $CX \neq 0$，则跳转至标号处继续循环；若 $CX = 0$，退出循环。
2. **`LOOPZ` / `LOOPE`（为零/相等时循环指令）**：
   * 自动将计数值 $CX \leftarrow CX - 1$；
   * 判定条件：需同时满足 $CX \neq 0$ 且零标志位 $ZF = 1$ 时才跳转循环。
3. **`LOOPNZ` / `LOOPNE`（不为零/不相等时循环指令）**：
   * 自动将计数值 $CX \leftarrow CX - 1$；
   * 判定条件：需同时满足 $CX \neq 0$ 且零标志位 $ZF = 0$ 时才跳转循环。
4. **`JCXZ`（CX 为零转移指令）**：
   * 判定条件：测试 $CX$ 寄存器当前值，若 $CX = 0$ 则发生跳转，否则顺序向下执行（该指令不影响标志位，常用于进入循环体前的安全前置检测）。

## 3. 循环程序架构演进与板书推导

讲师指出，常规循环程序在逻辑流向与控制形态上划分为两种核心架构：

### 3.1 架构一：先循环工作，后循环判定（Do-While 型）

* **执行顺序**：`进入循环体` $\rightarrow$ `执行循环工作` $\rightarrow$ `参数修正` $\rightarrow$ `判定出口条件`。
* **边界特征**：无论初始条件如何，循环体**至少执行一次**。
* **适用场合**：循环次数在执行前完全已知、且确定不可能为 0 的固定迭代任务。

### 3.2 架构二：先循环判定，后循环工作（While 型）

* **执行顺序**：`前置判定出口条件` $\rightarrow$ `若不满足退出条件则执行循环工作` $\rightarrow$ `参数修正` $\rightarrow$ `回跳判定`。
* **边界特征**：若初始条件即命中退出标准，循环体**执行 0 次**。
* **设计动机**：
  1. 解决实际问题中可能存在的“零次循环”需求；
  2. 支持“提前退出”，显著提升执行效率，避免无意义的 CPU 时钟周期浪费。

---

### 3.3 核心演进案例：统计 `BX` 中二进制“1”的个数

#### 【业务目标】
输入一个 16 位寄存器 `BX`，检测并统计该寄存器二进制位中包含数字 `1` 的总个数。

#### 【算法逻辑与状态机推导】
1. **移位与标志位判定机制**：
   * 使用移位指令（左移或右移），将 `BX` 的最高位或最低位依次移入进位标志位 $CF$（Carry Flag）。
   * 若 $CF = 1$，说明移出的该位是 1，计数累加；
   * 若 $CF = 0$，说明移出的该位是 0，不予统计。

2. **架构方案对比与演进**：
   * **反模式（采用架构一）**：若机械设定 $CX = 16$ 强制死循环 16 次，若 `BX` 初始即为 `0000H`，CPU 依然必须完整消耗 16 次移位与判定指令，效率极低。
   * **优化方案（采用架构二）**：
     * **进入前置测试**：首先执行 `CMP BX, 0`；若 $BX = 0$，直接 `JZ EXIT` 退出，达成 0 次循环退出。
     * **单步执行与动态清零探测**：每次右移（或左移）一位后统计 $CF$，在通过 `LOOP` 返回后，立刻再次通过 `CMP BX, 0` 检测剩余有效位是否已经全为 0。
     * **提前退出**：若中间某一拍 $BX$ 的剩余值已变为 0（例如原数据只有低 2 位有 1，高位移空），不必等到 16 次耗尽，直接跳出循环。

#### 【板书指令逻辑推导流】

```text
              [开始]
                │
        ┌───────┴───────┐
        ▼               │
  CMP BX, 0             │ (前置判定: 是否初始即为零?)
        │               │
  JZ EXIT ──────────────┼──────────┐ (若 BX == 0，实现0次循环直接跳出)
        │               │          │
        ▼ (非零分支)     │          │
  SHR BX, 1 (右移一次)   │          │
        │               │          │
     测 CF 标志位        │ (循环体工作: CF=1 则累加统计, CF=0 忽略)
        │               │          │
      LOOP ─────────────┘          │ (CX 自动减 1 并回跳)
        │                          │
        ▼                          ▼
      EXIT: ─────────────────> [程序退出]
```

## 4. 循环程序通用五大组成模块

不论采用“先工作后判定”还是“先判定后工作”，任何标准循环程序在结构切片上均由以下五大模块构成：

| 模块序号 | 组成模块名称 | 核心职责与工程动作 | 板书/指令体现 |
| :---: | :--- | :--- | :--- |
| **1** | **初始化部分** | 为循环设置起始条件。如给计数器、累计单元、基地址指针赋初值。 | 传送初始化指令（MOV 等） |
| **2** | **循环工作部分** | 循环的核心任务逻辑（即循环体）。执行单次重复运算或处理。 | 移位、加法累加、数据比对等 |
| **3** | **参数调整部分** | 修正地址指针与变量状态，驱动循环向终点单向推移。 | `INC SI`、`INC DI` 等步进指令 |
| **4** | **循环判定部分**<br>*(出口判定部分)* | 探测当前循环状态是否达成退出边界。决定继续执行还是跳出。 | `LOOP`、`JZ`、`JNZ`、状态标志检测 |
| **5** | **结果处理部分**<br>*(可选项)* | 循环结束后的数据收尾、格式化或输出呈现。 | 将结果送屏幕显示、写存盘等<br>*(注：若边算边输出，则内嵌于工作体)* |

> **教材专栏说明（关于第 5 部分的内嵌机制）**：
> 讲师特别强调，第 5 部分“结果处理”在形式上属于**可选项**。若程序设计为“每循环工作一次便对外呈现一次结果”，则结果处理逻辑已被包络吸纳进“循环工作部分”之中，不再在循环体外独立成段。

## 5. 循环控制架构横向对比矩阵

| 架构维度 | 架构一：先循环工作，后循环判定 | 架构二：先循环判定，后循环工作 |
| :--- | :--- | :--- |
| **执行时序** | 初始化 $\rightarrow$ 工作体 $\rightarrow$ 判定 $\rightarrow$ 退出 | 初始化 $\rightarrow$ 判定 $\rightarrow$ 工作体 $\rightarrow$ 修正 $\rightarrow$ 退出 |
| **最小循环次数** | **1 次**（无条件穿透一次工作体） | **0 次**（初值不满足直接 Bypass） |
| **已知条件依赖** | 依赖明确固定的总迭代循环步数 | 适用于动态终止条件、依赖数据状态的场景 |
| **执行效率** | 面对可提早结束的数据时存在**空转开销** | **极佳**；避开无意义迭代，支持提前终止 |
| **控制指令组合** | 基础计数 `LOOP` 即可简洁实现 | 前置条件跳转指令（`JCXZ`、`CMP+JZ`）结合 `LOOP` |
| **适用典型场景** | 固定长度块搬移、固定点数加法 | 状态机监测、带条件的字串搜索、二进制特定位统计 |

## 6. 反模式与工程避坑清单

1. **反模式：混淆分支转移与循环控制指令**
   * *典型错误*：误以为 8086 循环控制指令有十几条甚至几十条。
   * *规范防御*：严格界定概念。8086 专有循环控制指令只有 4 条（`LOOP`, `LOOPZ`, `LOOPNZ`, `JCXZ`），其余均为通用的条件/无条件转移指令（如 `JMP`, `JZ`, `JNZ` 等）。

2. **反模式：忽略零次循环边界强制进入循环体**
   * *典型错误*：在未核验数据有效性时，盲目使用“先工作后判定”结构，导致异常初值（如空串、0 元素集）遭到错误篡改。
   * *规范防御*：在进入工作体前采用 `CMP/JZ` 或 `JCXZ` 实行守卫拦截（Guard Clause）。

3. **反模式：静态全周期死循环（未设计提前退出）**
   * *典型错误*：如在统计 `BX` 中 1 的个数时，无论数据实际大小，硬性跑满 16 个周期。
   * *规范防御*：在循环判定部分增加动态全零检测（`CMP BX, 0`），检测到有效数据已被掏空即提前 Break 出循环。

4. **反模式：遗漏指针/参数步进导致原地死循环**
   * *典型错误*：在循环体内未配置“参数修正部分”，导致访问指针不移动，或判定源不收敛。
   * *规范防御*：模块化检查循环的五大组成结构，核查指针操作指令（如 `INC SI` / `INC DI`）是否缺失。

## 7. 多重循环程序设计：起泡排序法（Bubble Sort）

在前续课程解析完单循环程序后，讲师在 **第 4.4 节** 引入多重循环程序设计的典型算法应用——**起泡排序法**。

### 7.1 业务模型定义
* **任务目标**：对某班级学生的某门课程考试成绩执行从大到小的排序。
* **排序规则**：**由高到低（降序排队）**。

### 7.2 核心数据特征与逻辑推导
* **数据类型属性**：学生的考试成绩归类为**无符号数（Unsigned Number）**。
* **比较逻辑约束**：
  * 因为是无符号数，数据**只有高低（数值大小）之分**，不涉及正负符号位（不考虑补码符号位扩展）。
  * 核心比较策略：**相邻元素“结对”比较**，若不满足由高到低的顺序则进行位置对调，通过多轮双重循环沉降与冒泡完成全序列排序。

```text
│       └── 规范方案：通用寄存器过渡（需 2 条指令完成）
└── 第一次循环演进逻辑
    ├── 判定准则：高位单元数值 vs 低位单元数值
    │   ├── 若 上单元 >= 下单元：不交换（符合降序要求）
    │   └── 若 上单元 <  下单元：交换（大泡上升，小泡下沉）
    ├── 单步跟踪：Step 1 到 Step 4 状态迁移
    └── 数学归纳：N 个元素在第 1 次循环中需比较 (N - 1) 次，沉底最小值
```

## 二、 核心原理深度推导与板书重现

### 1. 物理问题与边界建模
* **问题定义**：对微机课程考试成绩进行**由高到低（降序）**排序。
* **数据样本**：由于黑板版面限制，讲师选取 $N = 5$ 名学生的成绩作为基准测试用例：
  $$\text{Data} = [70, 54, 90, 67, 80]$$
* **物理存储**：实际存储于内存各连续存储单元中（机器内为二进制形式，板书讲解采用十进制等价表示）。

---

### 2. 底层硬件约束与指令级推导
在微机底层体系中，两两元素比较与调序依赖于 CPU 指令系统的严格约束：

1. **数值属性与分支指令选择**：
   * 必须明确区分排序数据属于**无符号数**还是**带符号数**：
     * **无符号数排序**：采用 `JA`（Jump if Above）等无符号条件跳转指令。
     * **带符号数排序**：必须采用 `JL`（Jump if Less）或 `JG`（Jump if Greater）指令。
2. **内存到内存直接操作非法性（Hardware Barrier）**：
   * 处理器体系结构**不允许两存储单元直接进行数据交换**（Cannot execute memory-to-memory exchange directly）。
   * **实现路径**：必须借助 CPU 内部的一个**通用寄存器**进行暂存过渡，整个交换过程需要由**两条指令**配合完成。

---

### 3. 比较交换规则（降序语义）
对于两相邻存储单元（记为上单元 $M[i]$ 与下单元 $M[i+1]$）：
* **保持不变**：若 $M[i] \ge M[i+1]$，说明前数已高于或等于后数，符合降序要求，**不交换**。
* **触发交换**：若 $M[i] < M[i+1]$，前数低于后数，执行交换——**“大泡泡顶上去，小泡泡沉下来”**。

---

### 4. 第一次循环（First Pass）黑板板书单步演进

初始序列状态：
$$S_0 = [70,\ 54,\ 90,\ 67,\ 80]$$

* **第 1 次比较（Step 1: 比较第 1、2 单元）**：
  * 比较对象：$70$ 与 $54$。
  * 判定条件：$70 \ge 54$。
  * 执行动作：**不交换**。
  * 当前序列状态：
    $$S_1 = [70,\ 54,\ 90,\ 67,\ 80]$$

* **第 2 次比较（Step 2: 比较第 2、3 单元）**：
  * 比较对象：$54$ 与 $90$。
  * 判定条件：$54 < 90$。
  * 执行动作：触发交换。通过通用寄存器中转完成交换；$90$ 顶上去，$54$ 沉下来。
  * 当前序列状态：
    $$S_2 = [70,\ 90,\ 54,\ 67,\ 80]$$

* **第 3 次比较（Step 3: 比较第 3、4 单元）**：
  * 比较对象：$54$ 与 $67$。
  * 判定条件：$54 < 67$。
  * 执行动作：触发交换。$67$ 顶上去，$54$ 沉下来。
  * 当前序列状态：
    $$S_3 = [70,\ 90,\ 67,\ 54,\ 80]$$

* **第 4 次比较（Step 4: 比较第 4、5 单元）**：
  * 比较对象：$54$ 与 $80$。
  * 判定条件：$54 < 80$。
  * 执行动作：触发交换。$80$ 顶上去，$54$ 沉下来。
  * 最终序列状态：
    $$S_4 = [70,\ 90,\ 67,\ 80,\ 54]$$

---

### 5. 第一次循环的结论与数学归纳
* **沉底结果**：第一次循环结束后，全序列中的**最低分（最小值 $54$）**成功“沉到存储器最末（最低端）”。
* **比较次数递推**：
  * 参加比较的元素总数：$N = 5$
  * 第一次循环所需比较次数：$4$ 次
  * **通式定理**：在第一次循环中，若有 $N$ 个数参与比较，需要经过 **$(N - 1)$** 次两两比较，才能确保将全序列最小值准确沉入存储单元底部。

## 三、 技术方案与指令对比矩阵

| 对比维度 | 无符号数比较跳转 | 带符号数比较跳转 | 内存直接交换（反模式） | 寄存器过渡交换（规范方案） |
| :--- | :--- | :--- | :--- | :--- |
| **涉及指令** | `JA` 等 | `JL` / `JG` 等 | 无对应合法单指令 | 借助通用寄存器（共需 2 条指令） |
| **判定标志依据** | 无符号进位/借位状态（未展开） | 带符号溢出/符号标志（未展开） | 不适用 | CPU 总线与寄存器数据通路 |
| **核心特点** | 用于纯数值大小比较 | 考虑正负符号位的大小判断 | 违反微机总线及指令集规范 | 符合微机硬件规范，安全完成两内存单元数值互换 |
| **适用场景** | 讲师提及无符号数场景 | 明确指出的带符号数排序场景 | 严格禁止在汇编编程中出现 | 微机体系下两连续内存单元的数据对调 |

## 四、 反模式与踩坑清单

1. **反模式：混淆符号类型的跳转指令**
   * **现象**：在带符号数排序时错误地使用了无符号数比较跳转指令（如 `JA`），或者在无符号数排序时错误使用了 `JL`/`JG`。
   * **防御方案**：必须根据数据是否有符号严格对应：带符号数条件转移抓牢 `JL` 或 `JG`，无符号数抓牢 `JA`。
2. **反模式：试图进行“内存单元到内存单元”的直接交换**
   * **现象**：误以为可以在指令中直接将两个 Memory 单元的内容进行 `EXCHANGE`。
   * **防御方案**：微机指令集不允许内存间直接交换，必须利用通用寄存器作为中介，占用 2 条汇编指令完成两内存单元的数据对换。
3. **反模式：外层/内层循环边界与比较次数计算错误**
   * **现象**：将第一次循环的比较次数与元素个数 $N$ 混淆。
   * **防御方案**：记住第 1 次循环边界规则，有 $N$ 个数参加，比较次数必然是 $N - 1$ 次。
