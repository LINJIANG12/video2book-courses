符号扩展指令呢一共由两条，一条是CBW，无操作数，指令完成的功能是隐含的把AL中的8位带符号数扩展到AX中，啊，扩展到AX中。变成16位。那扩展后AX中的高8位在AH，低8位是原来的AL，那AH中的内容是AL符号位的扩展。理解了吧？啊。

那么8086指令系统当中设计这样的指令，主要是为了在有些算术运算当中使类型一致而设置的。像CWD符号扩展指令，是隐含的把AX中的16位带符号数扩展成32位。扩展后32位呢高16位在DX，低16位在AX，其中DX16位为AX符号位的扩展。这两条指令不影响状态标志，但是归属在算术运算类里面了。

如我们对CBW指令的应用举一个例子。例：求Y = A * B + C - 18的运算，做程序设计。其中题目给出的A, B, C为变量，而且这三个变量呢都是字节型的。都是字节型的。

然后算术运算指令的最后一类，是BCD数调整指令。啊，BCD数的调整指令。

在第一章我们就提到在计算机中十进制数是用BCD码表示的，而BCD码表示的BCD数在计算机中表示，是不是有两种表示方式？一种是非密BCD数表示方式，第二种是组合BCD数的表示方式。

那么十进制数用BCD数表示以后，就允许采用BCD数形式进行加减乘除运算。那么加减乘除运算CPU在执行时，是不是把按程序中给出的BCD数看成了二进制数了？所以运算后的结果可能是错的，那么就要对错误的结果呢进行BCD数正确的BCD数的调整。啊。

显然关于BCD数的调整就有加法BCD数调整和减法BCD数的调整。那么对于加法和减法BCD数的调整，分别有非密，如果你加减法运算时参加运算的数用非密BCD数表示的，那就用非密BCD数对应结果的加法和减法的调整指令。如果参加运算的BCD数是用组合BCD数表示的，那对应的调整指令就应该用组合BCD数调整指令。

那么对于乘法和除法运算，乘法和除法运算只能用非密BCD数运算。所以对应的乘除法非非密BCD数的调整，只有非密BCD数的乘法调整和除法BCD数的调整。啊。

那么还有对于加法、减法和乘法运算BCD数运算，都是先运算，对运算后的结果再来调整，就是后调整。啊。而对于除法运算BCD数的运算，是先调整后运算。这一点在应用时也要注意，啊，是先调整后运算。

那么我们先看加法BCD数的调整。关于加法BCD数的调整有如果参加加法运算的BCD数采用的是组合BCD数，那么对于组合BCD数的结果调整指令是用DAA。这个我们在第一章讲BCD数时是不是用过了？啊。这里如果参加运算的BCD数是非密BCD数，对非密BCD数的调整用的是AAA指令。当然DAA和AAA调整都隐含的是对AL中的内容调整。理解了没有？也就是对AL的内容调整。啊，都是一样的，隐含的对AL中的内容调整。

那么我们看些例子，简单的先对组合BCD数调整做一复习。啊，如书上的例子，它书上的例子啊。例3.15是做组合BCD数运算，56 + 73的运算。56 + 73的运算。那程序设计是这样：MOV AL，必须用AL累加器，因为调整指令是对AL的内容调整。如果你运算时中间结果累加器没有用AL，最后调整之前是不是还要MOV传送给AL？啊。这里面放被加数56H组合BCD数。后面加H是不是我们第一章都提到过？啊。然后让CPU做ADD运算，AL中的56H加加数73H。那么CPU做两数相加，你看5 6加7 3 H。加的时候呢，是不是低4位数也是BCD数，高4位数也是BCD数，但是这个这个BCD数是不是你用户的概念？但是CPU加是不是看成二进制数了？好，加的结果：1 0 0 1，0 0 1 1，最后的结果是不是C9H？但是应该加下来的结果是多少呢？56 + 73应该是不是等于129？等于129。所以是不是AL内容现在是不是等于C9H？结果不正确。不正确，由于是组合BCD数运算，就要用组合BCD数加法调整指令DAA来调整。程序写在这，DAA。

那么CPU执行DAA指令，执行这条指令是不是对AL中的组合BCD数结果要调整了？调整的时候低4位数也是BCD数，高4位数也是BCD数，分别做加6调整。那加6调整的时候我们看低4位数是不是没超过9？且AF没置1，就没辅助进位，所以该位不修正，不修正是不是加了个0？高4位是不是超过9了？就要加个6，加个6修正。加下来的结果：1 0 0 1，0 1 0，进1，0，进1，1，这是不是一个进1？这个进1，这个进1是不是最后使得CF置1了？然后这AL中的结果是多少呢？是不是29H？AL中的结果是29H，最后正确的结果是不是要带上CF标志了？是100 129。听懂了没有？啊。就是说如果组合BCD数运算时，高位BCD数向前有进位，肯定是百位，百位在CF里面放着，啊，这是组合BCD数。

那么我们看一下非密BCD数的概念和这个就大不一样了。如例3.13，做4 + 8的运算。例3.13，做非密BCD数4 + 8的运算。我们看程序设计很简单的，主要看CPU调整的原理。MOV AL, 4，是不是04H？非密BCD数给AL。然后让CPU做ADD，AL中的4是不是加非密BCD数8？相加。那我们看CPU怎么加。CPU加的时候呢是4，04加8，按二进制加，加下来的结果是0CH，是不是0CH？然后呢这个结果肯定不对，因为你做的是非密BCD数运算，所以要用非密BCD数调整指令对AL中的结果进行调整。做AAA调整。
