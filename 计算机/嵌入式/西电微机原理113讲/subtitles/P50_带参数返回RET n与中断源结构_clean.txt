### [04:09] 中断的基本概念与执行流程

学这一节内容——中断调用与返回指令，首先你要理解什么叫中断。这学期前边讲过什么叫中断：CPU 在执行程序期间，由于某事件发生了，好比在执行某一条指令时，一个事件发生并请求 CPU 为它服务。那么 CPU 如果允许的话，就应该暂停执行下一条指令，转到中断服务子程序里面去执行中断服务子程序。通过执行这一段中断服务子程序为那个事件服务；服务完毕后，最后应该有中断返回指令：

```assembly
IRET
```

CPU 执行 `IRET` 指令，就能正确地返回到刚才的中止处，接着刚才中止的程序继续往下执行。这么一个过程称为中断。

CPU 型号不同，它响应中断的方式不同。确切地说，从响应中断要让 CS 包括 IP 指向中断服务程序入口（找到这个地址），转到入口的方法不同，那就要看具体用什么型号了。

---

### [06:17] 中断源的概念：内部中断源与外部中断源

第一个小问题是中断的概念，要把概念搞清楚。第二个是中断源的概念：谁向 CPU 引起了中断请求，即那个事件源，就称为中断源。

中断源可以在 CPU 内部，也可以在 CPU 外部：
- **内部中断源**：在 CPU 内部向 CPU 提出中断的事件。
- **外部中断源**：在 CPU 外部向 CPU 提出中断请求的事件。外部中断源要想向 CPU 请求中断，必须把中断请求信号通过 CPU 的某个中断请求输入引脚输入给 CPU。

---

### [07:27] 8086 外部中断引脚：NMI 与 INTR

就 8086 CPU 而言，外部中断源请求输入引脚有两个：一个是 NMI，一个是 INTR。

- **NMI 引脚**：通过 NMI 引脚向 CPU 提出的中断请求，CPU 要无条件响应，所以通过 NMI 引脚提出的中断请求称为**外部非屏蔽中断请求**。
- **INTR 引脚**：通过 INTR 引脚由外部设备向 CPU 提出的中断请求，CPU 是否响应受中断标志位 `IF` 的控制。

---

### [08:24] 中断标志位 IF 与可屏蔽中断

- 当 `IF = 1` 时，称 CPU 处于**开中断**状态。CPU 开中断时，外部设备通过 INTR 引脚向 CPU 提出的中断请求，CPU 就要响应。
- 当 `IF = 0` 时，称 CPU **关中断**，也称为 CPU 处于中断不被允许状态。此时外部设备通过 INTR 引脚向 CPU 提出的中断请求，CPU 就不响应。

所以 INTR 引脚得到的中断请求称为**外部可屏蔽中断请求**。所谓可屏蔽，就是受 `IF` 的控制。

### 8086 CPU 内部中断源详解

#### [00:00] 一、除法出错中断（DIV / IDIV 错误）

左边我们看，有一个大的矩形框，框内下边画了五个中断源。

第一个中断源，叫**除法出错中断源**。

比如说 CPU 执行 `DIV` 或者 `IDIV` 除法指令时，发现除数为 0（这是不行的），或者发现商溢出了。

商溢出的概念理解吗？比如字节除法：
* 被除数存放在寄存器 `AX`，是 16 位；
* 除数是 8 位；
* 除下来的商存放在 `AL`，余数存放在 `AH`。

那么被除数除以除数，如果商超出了 $255$（即超出 8 位无符号数的表示范围），`AL` 能放下吗？放不下。这种现象就称为“商溢出”。

理解了没有？所以 CPU 在执行除法指令时，如果发现**除数为 0** 或者**商溢出**，就会自动引起除法错中断。这个除法错中断是 CPU 内部在执行除法指令时，根据除数是否为 0 或者商是否溢出而引起的，这是一个内部中断源。

---

#### [01:29] 二、单步中断（TF 标志控制）

内部第二个中断源，叫**单步中断源**。

当时我讲 `TF`（陷阱标志/单步标志）时是不是提到过？当 CPU 执行用户程序时，假如 CPU 执行这一条指令时 $TF = 1$ 了，那么 CPU 把这条指令一执行完，下边这条指令就不执行了，自动引起单步中断，转到中断服务子程序去。

理解了没有？

那么 CPU 怎样才能确保一条指令执行完，紧接着执行下一条，再紧接着执行下一条？这样一种执行程序的方法叫做“程序连续执行”。也就是在很多单片机仿真程序里面提到的“全速执行”，有没有这么一个概念？程序的全速执行就是连续执行。

在 8086 汇编语言系统当中，要全速执行用户程序，必须保证：
$$TF = 0$$

如果 $TF = 1$，就只能单步执行——每执行一条指令，只要 $TF = 1$，都会引起一次单步中断。这就是内部的第二个中断源。

---

#### [03:00] 三、溢出中断（INTO 指令）

内部的第三个中断源是 `INTO`（黑板上写着“溢出”）。

比如我举个例子，我们看黑板：
假如说这条指令我改成加法指令 `ADD`：

```assembly
ADD AX, BX
```

CPU 执行加法指令以后是不是影响了溢出标志位 `OF`？如果运算后有溢出，$OF = 1$；没有溢出，$OF = 0$。

如果在这条指令的下方，叫 CPU 执行 `INTO` 指令（这是一条溢出中断指令）：

```assembly
ADD  AX, BX
INTO
```

CPU 执行 `INTO` 指令时就会去检测标志位 `OF`：
* 如果 $OF = 1$，则这条指令执行后，下面的指令就不执行了，直接引起溢出中断，转到中断服务程序中去；服务程序执行完后，执行 `IRET` 中断返回指令才返回到这里。
* 如果 CPU 执行 `INTO` 指令时 $OF = 0$（根本没有溢出），那么就不会引起溢出中断，而是顺着顺序往下继续执行。

理解了没有？所以 CPU 执行的 `INTO` 指令叫做溢出中断指令。执行 `INTO` 指令是否产生溢出、是否发生中断，完全受 `OF` 的控制。这是内部的第三个中断源，属于一种软件中断源。

---

#### [04:46] 四、断点中断（INT 3）与程序调试

第四个中断源叫**断点中断源**。

举个例子，断点中断源是什么意思呢？我们看黑板。

我让 CPU 执行这一段用户程序，最后发现运行结果是错的。结果是错的，是不是需要检查程序了？

[05:20] 检查程序的第一种方法，是用肉眼扫描读程序去查问题。如果读了几遍也找不到问题，是不是需要机器帮你找？这就叫调试程序。

在 8086 汇编语言程序设计中进行上机调试，上节课讲过，要使用 `DEBUG` 工具。调试的时候，最笨的方法就是单步、单步、单步调试；但是如果程序量很大，一直单步去调试，显然效率很低。

这时就要找第二种办法：我们能不能分段调试，先看这一段程序执行的结果对不对？

[06:09] 如果要看这一段程序执行的结果是否正确，让它运行到这里停止，就可以在这里设置一个**断点**。

在这里设置断点，就相当于把当前位置的指令临时用 `INT 3` 指令代替。这是一条软件中断指令，其中 `3` 是中断类型号（什么是中断类型号，后面会讲到）。

当用 `INT 3` 临时替换了原指令后，CPU 一直连续执行，执行到 `INT 3` 断点中断指令时，就会立刻转到中断服务子程序中去。

在中断服务子程序里面，用户可以编写一段程序把结果输出显示在屏幕上：
* 结果如果保存在寄存器中，就把寄存器的内容显示出来查看对不对；
* 结果如果保存在内存中，也可以把内存地址单元的内容显示出来查看对不对。

显示完成确认后，程序再返回。但是在中断返回的时候，必须用原来的指令把 `INT 3` 指令再替换回去，使程序恢复原貌。恢复之后断点就消失了。

接着把断点移到下一处，让 CPU 从该位置继续执行到下一个断点处，检查下一段程序的执行结果是否正确。理解了没有？就是通过这样的程序片段进行分段调试。

当断点设置到某处，执行该段程序后显示的结果发现错了，就可以断定错误就在这一段程序块内。锁定范围后怎么办？从该段起始指令开始，一步一步单步调试，总能找到问题所在。这样就能显著提高程序调试的速度。

所以程序调试应该将**设置断点调试**与**单步调试**结合起来使用。

[08:20] 这条 `INT 3` 断点中断软件指令，汇编后的机器操作码是：
```text
CCH
```
它是单字节指令。因此 CPU 执行 `INT 3` 称为断点中断指令，也把断点中断称为**单字节中断**。有些教科书上把断点中断称为单字节中断，两者是一样的。

#### [08:58] 五、一般软件中断（INT n）

在 CPU 内部中断源中，第五个是 `INT n` 指令。

实际上，前面讲的 `INT 3` 也是 `INT n` 指令的一种形式，此时：
$$n = 3$$
当 $n = 3$ 时，CPU 产生 3 号中断。系统将每一种中断都进行了编号，这个编号就叫做**中断类型号**。

例如，在调用 DOS 系统的子程序（系统功能调用）时，也是通过执行 `INT` 软件中断指令引起中断来调用 DOS 服务的。调用 DOS 的中断类型号是 `21H`：

```assembly
INT 21H
```

CPU 执行 `INT 21H`，对应使用的就是 `INT n` 指令，此时：
$$n = 21\text{H}$$

### DOS 功能调用与中断源概述

#### [00:00] DOS 功能调用基本原理与示例

这就是 DOS 功能调用。在 DOS 系统内部，各种功能的子程序非常多。在调用具体的子程序之前，需要先将功能号送入 `AH` 寄存器。

例如这条指令：

```assembly
MOV AH, 4CH
INT 21H
```

把 `4CH` 送给 `AH`，执行 `INT 21H`，原来都用过这条指令，这其实就是去调用 DOS 的 `4CH` 号子程序。前面给大家讲过，调用 DOS `4CH` 号子程序的作用是：结束用户程序，返回 DOS 操作系统。

#### [00:39] 键盘输入功能调用（1 号功能）

如果换一种写法：

```assembly
MOV AH, 01H
INT 21H
```

这就是去调用 DOS 的 1 号功能。调用 DOS 1 号功能的作用是：等待用户按键，即从键盘输入获取一个字符。

当执行到这条指令时，程序就不会继续往下顺序执行，而是停下来等待。一直等待用户按键；如果用户一直没有按键，程序就会一直在此等待；只要用户按下按键，后续指令便会继续执行。
