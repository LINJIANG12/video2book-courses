## 宏指令与汇编语言程序设计基础
> 对应块：BLK33 | 覆盖分集：P64-P65 | 块标题（分集名）：《64》

### 宏指令从哪里来

把 `AX` 的内容左移三次，原来可以逐条写移位指令，现在完全可以把它定义成一条宏指令。定义时，前面写宏名，后面给出这条宏指令实际要执行的指令序列。

这条规则一定要记牢：**实参替换形参，而且位置必须一一对应，不能写错。**假设形参有多个，调用时给出的实参也必须按相同顺序填写。少写一个也不行。

假如宏定义只有三个形参，而调用时误写成：

```asm
MOVE MACRO X, Y, Z, 18
```

多出来的 `18` 就不会正确地变成实参。汇编时，汇编程序会用 `0` 补上，结果当然不对：这个功能需要三个参数，补出来的第四项却成了 `0`，功能直接做错。

所以记住：**形参有几个，实参就写几个；实参替换形参，位置必须一一对应。**

### 宏调用怎样变成真正的指令

接下来看看汇编程序怎样处理宏调用。

汇编程序从前往后翻译原程序。先检查语法：语法错了，不能生成目标代码；语法全对，才继续往下翻译。翻译到宏调用处，就把宏定义中的指令序列插入当前位置，再让其中的实参替代形参。

比如前面要完成“`AX` 左移三次”，定义部分写得差不多，真正调用时可能只是：

```asm
MOVE AX
```

汇编后，`MOVE AX` 并不是仍然作为一个 mysterious 的名字留在目标代码里，而是被替换成了实际的三次移位。目标代码清单中，由宏体插入的内容在左边带一个 `+` 号；普通指令对应的机器代码旁边没有这个标记。因此查看、显示或打印目标代码清单时，凡是带 `+` 的行，就能看出它来自宏展开。

> **易错点**：宏调用是汇编阶段的展开，不是运行时的一条特殊调用指令。它最终要翻译为实际的机器指令。

再看汇编继续往下走的过程：碰到另一条宏调用，又插入一次宏体。宏体中要用实参去替换形参的位置，替换后再把后续目标代码接上。宏定义的指令序列就是这样逐行进入目标代码清单的。

### 宏指令与子程序的比较

程序设计中，经常要完成某个特定功能的那一段程序，既可以把它定义成一个子程序，在程序中通过 `CALL` 调用；也可以把它定义成一条宏指令，在程序中通过宏名调用。两种办法都能实现同样的功能，但效率和代价不同。

| 比较项目 | 宏指令 | 子程序 |
| :--- | :--- | :--- |
| 代码空间 | 宏体在每次调用处直接插入，省空间 | 每个功能模块只编一份，但模块本身要占空间，程序较大 |
| 执行时间 | 宏展开后直接执行，省掉调用和返回的时间 | 需要 `CALL`、`RET`，执行时还要花调用和返回时间 |
| 适用场景 | 调用次数少、调用处位置固定、需要节省运行时间 | 同一功能在程序中被反复调用，需要完整模块时更合适 |

一句话：**宏指令省空间、子程序省代码；宏指令省时间、子程序不省时间。**具体说，宏指令每次调用都把宏体插入，空间上省；子程序不管被调用多少次，只保留一份程序模块，但要占用空间；执行时宏指令没有额外的调用和返回开销，子程序则要付出调用与返回的时间。

这个问题可以按“空间上和时间上”两个方面回答，简答题里要把这两点说清楚。

### 用宏指令实现光标回车换行

举一个实际例子：定义一条宏指令，让光标完成回车、换行。

宏名叫 `CRLF`，这个名字不是随便起的。ASCII 表里，“回车”和“换行”分别对应 `CR` 和 `LF`，合起来就是 `CRLF`。别人一看这个名字，就知道这条宏指令是干什么的——光标回车并换行。

> **提示**：给宏指令起名时，要尽量让名称本身传达功能。例如 `CRLF` 一看就知道与回车、换行有关。这比堆一个不表意的名字更容易阅读，也便于在程序中直接引用。

实现过程不复杂。`DOS` 的 `INT 21H` 的 `02` 号功能调用，就是把 `DL` 中的字符送到屏幕。`DL` 放 `0DH`，这是回车码；再调用一次，`DL` 放 `0AH`，这是换行码。两次调用就完成了回车、换行。

按照这个功能定义好宏体以后，后面的程序就不必每次重复写这两个 `02` 号功能调用，只写宏名 `CRLF`，调用一次就完成回车、换行。汇编程序碰到 `CRLF` 宏调用时，把宏体插入，仍然是 `INT 21H`、`02` 号功能调用、`DL` 放 `0DH` 和 `0AH` 的组合。

汇编程序从前往后翻译时，碰到宏指令就把宏体插入——这个插入过程，就叫**宏展开**。也就是**宏定义**的一节里，汇编程序在翻译时碰到宏指令，展开成宏定义中的指令序列，编译后从宏名变成了实际的机器指令。

宏指令的展开，与子程序的调用，有相同之处，也有不同之处。子程序是运行时执行到 `CALL` 指令才跳过去执行；宏指令是汇编时就把宏体插入，不需要运行到那里再跳。

### 宏指令中的局部标号

宏指令里如果用到了分支或循环，循环的目的地一般会有一个标号。假设在程序中两次以上调用了这条宏指令，宏体每次展开，都插入同样的标号，于是同一个标号在最终程序中出现了两次以上。汇编程序会报告“标号重复定义”这样的语法错误。

> **易错点**：宏指令中的标号，如果只用普通标号，在同一宏体展开多次以后会重复定义。这不是宏展开失败，而是标号本身不唯一。

解决办法与 C 语言的局部变量类似：在宏定义中声明局部标号。假设循环的标号叫 `NEXT`，就在宏定义里声明它是局部标号，这样汇编程序会知道 `NEXT` 只属于这条宏的展开。

具体做法是在宏定义里面加一条 `LOCAL` 指令，把 `NEXT` 列为局部标号（具体写法详见教材 P84、P85）。用 `LOCAL` 声明过的标号，在每次宏展开时，汇编程序自动把它改成唯一的新标号，比如 `??0000`、`??0001` 这样的形式。

展开过程可以这样看：

```text
第 1 次调用
    原始标号 NEXT  ->  ??0000

第 2 次调用
    原始标号 NEXT  ->  ??0001

第 3 次调用
    原始标号 NEXT  ->  ??0002
```

标号编号每次展开都不同，因此不会出现重复定义，循环目的地的引用也会跟着一起改写。第几次展开，就得到第几组新的标号；只要展开次数在汇编程序允许的范围内，这种方法就能解决重复定义问题。

> **定义**：宏体内部的标号要声明为局部标号。普通标号在多次宏展开后会重复出现；局部标号由汇编程序为每次展开自动改成不同标号。

### 汇编语言程序设计的步骤

看完宏指令，把整个章节稍微回看一下。汇编语言程序设计有五个步骤，考试可能出简答题，要能写出来。

第一步是分析题目，也就是提出算法。明确输入是什么、输出是什么，要解决什么问题。

第二步是根据算法或者编程思想，画流程图。流程图中用到的符号必须规范。

第三步是根据算法、编程思想和流程图编写程序，写出代码。

第四步是上机调试：把编写好的源程序录入计算机，文件扩展名必须是 `.ASM`。源程序建立后，要对它进行汇编，把它翻译成目标代码；然后链接，生成 `.EXE` 可执行文件。最后用程序调试工具进行调试。这个“录入—汇编—链接—调试”过程就完成了上机调试。

第五步是设计文档，也就是写说明书。把程序的名称、程序设计者、日期、算法说明、程序说明和执行说明等内容写出来。

> **结论**：汇编语言程序设计的基本步骤是：分析题目、画流程图、编写程序、上机调试、编写设计说明书。

### 源程序逻辑段的基本结构

源程序写完了，它不是一堆没有组织的指令。8086 汇编语言源程序由多个**逻辑段**组成，每个逻辑段里放不同类型的信息。数据、代码、堆栈各自归位，各就各位。

#### 段名、定位类型和段属性

用 `SEGMENT` 定义一个逻辑段。`SEGMENT` 前面写段名，后面跟三个可选参数：定位类型、组合类型和类别。这三个参数，描述的是这个逻辑段的起始地址要求、段与段之间怎么组合、以及这个段属于哪一类。

| 参数 | 作用 | 8086 常见取值或要求 |
| :--- | :--- | :--- |
| 定位类型 | 规定本段起始地址按什么边界对齐 | `PAGE`、`PARA`、`BYTE`、`WORD`；缺省为 `PARA` |
| 组合类型 | 告诉 `LINK` 如何组合不同模块中的同名逻辑段 | 在多模块程序设计中使用 |
| 类别 | 说明逻辑段所属的类别 | 用单引号括起类别名 |

段名最好能直接告诉读者这一段装的是什么。例如代码段可叫 `CODE`，数据段可叫 `DATA`，堆栈段可叫 `STACK`；有多个同类段时，可以进一步叫 `DATA1`、`DATA2`。这样别人一看段名，就知道段里是哪类信息，阅读起来很方便。

> **定义**：段定义伪指令的三个可选参数是定位类型、组合类型和类别；起段名时应避免与 8086 指令助记符、寄存器名等专用符号冲突。

#### 不同逻辑段中放什么

在 `SEGMENT` 下面，要写这个段的实体，数据段放数据，代码段放完成特定功能的指令，堆栈段放为堆栈操作预留的空间。

```text
DATA SEGMENT
    ; 变量定义
DATA ENDS

CODE SEGMENT
    ; 完成特定功能的指令
CODE ENDS

STACK SEGMENT
    ; 预留堆栈空间
STACK ENDS
```

如果某个段定义为数据段，段实体用 `DB`、`DW` 等变量定义语句，为数据分配相应的存储单元；如果是代码段，段实体就是完成某一特定功能的指令序列；如果是堆栈段，则用 `DB` 或 `DW` 定义一个空间，把该空间作为堆栈使用。

#### SEGMENT 和 ENDS 必须成对

一个逻辑段从 `SEGMENT` 开始，必须配一个 `ENDS` 表示本段定义结束，结束语句左边要写上与前面相同的段名。写程序时必须注意三点。

第一，两个段名要一致。例如下面这样写：

```asm
DATA SEGMENT
    ; 数据段实体
DATA ENDS
```

左边的 `DATA` 告诉汇编程序：现在开始了名为 `DATA` 的段；右边 `ENDS` 左边的 `DATA` 则告诉汇编程序：`DATA` 这个段到这里定义结束。段名不一致，段定义就配不上。

第二，`SEGMENT` 和 `ENDS` 必须配对使用。一个逻辑段不能只有开头而没有结束。

第三，段名本身具有伪指令属性，也具有段属性。汇编程序会给与段名对应的段分配一个段寄存器，严格地说，段名还具有偏移地址属性。

> **易错点**：`SEGMENT` 和 `ENDS` 是成对使用的，段名前后必须一致。漏掉 `ENDS`，或前后写成两个不同的段名，都会让段定义失去对应关系。

### 定位类型如何决定段的起始地址

`SEGMENT` 右边的第一个参数是定位类型。我们常用的 `MASM` 汇编程序只能汇编用户编写的源程序；到了汇编阶段，定位类型就告诉汇编程序：本段起始地址应满足什么要求。

前面讲过分段，逻辑段的起始地址必须能被 16 整除。这个要求，就是定位类型要表达的内容。8086 汇编语言中有四种定位类型。

#### PAGE：按页对齐

`PAGE` 是页型。在计算机中，一页等于 256 个字节。如果逻辑段的定位类型选为 `PAGE`，就要求本段起始地址能被 256 整除。

如果每个逻辑段都选 `PAGE`，汇编以后相邻逻辑段之间最大可能浪费 256 个字节的存储空间。因此，实际应用中虽然允许这种定位类型，却几乎没人使用。

#### PARA：按节对齐

`PARA` 是节型。一节等于 16 个字节——对比一下：字是 2 个字节，双字是 4 个字节，一节才是 16 个字节。如果定位类型选为 `PARA`，就要求本段起始地址能被 16 整除。

如果省略定位类型，汇编程序默认按 `PARA` 处理。这正是 8086 汇编语言程序中最常用的定位类型：汇编程序为各段安排起始地址时，按能被 16 整除的要求去找一个合适的位置。

如果相邻逻辑段都选 `PARA`，相邻段之间最多可能浪费 16 个字节。前面讲分段时说过这个现象，现在从定位类型参数上又见到了它的来源。

#### BYTE 与 WORD

另外两种定位类型是字节型 `BYTE` 和字型 `WORD`。

`BYTE` 要求本段起始地址能被 1 整除——任何地址都可以作为段的起始地址。这样虽然不浪费参数空间，但不可取。一般来说，特别是代码段，要保证段的起始偏移地址是 0；若选 `BYTE`，就无法保证这一点，所以没人用。

`WORD` 要求本段起始地址能被 2 整除。它仍然不能保证段的起始偏移地址为 0，因此在实际程序中也没有人选它。

所以实际使用时，只要没有特殊要求，就把定位类型省略，按缺省的 `PARA` 处理。

> **结论**：最常用的是缺省的 `PARA`，要求段起始地址能被 16 整除。`PAGE` 对齐过严，可能浪费较多空间；`BYTE`、`WORD` 又不能保证段起始偏移地址为 0，因此都不作为实际编写中的常用选择。

### 组合类型用于多模块程序设计

第二个参数是组合类型。它出现在多模块程序设计中。

什么叫多模块？举一个开发任务的例子。某个单位要开发一个程序，程序量大、功能强，开发周期又很短。这个任务必须接下来，但一个人做不完，就要分解任务：把流程和功能划分清楚，一部分由甲完成，另一部分由乙完成，再一部分由丙完成，然后大家同时开工。

三个人各自编写自己那一部分，都要定义自己的堆栈段、数据段，编写自己的代码；各自调试通过后，三个人的程序汇集起来，形成整个系统程序。每个人单独汇编后得到自己的 `.OBJ` 目标码文件，最后还要通过 `LINK` 链接。

链接时，组合类型就在告诉 `LINK`：不同模块里的同名逻辑段，应该按什么方式组合起来；也就是多模块程序中同名逻辑段如何链接的问题。

```text
A.OBJ  \
B.OBJ  -- LINK --> 完整系统的 .EXE 可执行文件
C.OBJ  /
```

因此，组合类型不是单模块程序中段实体的说明，而是在多模块程序设计里告诉 `LINK` 怎样处理不同模块的同名逻辑段。

> **提示**：在单模块程序中，通常不必关心组合类型；进入多模块程序设计后，必须按模块组织方式正确设置它。

## 8086 汇编语言源程序的完整结构
> 对应块：BLK34 | 覆盖分集：P66-P67 | 块标题（分集名）：《66》

我们把三个段链接成了一个系统程序。这时候问题就来了：这个程序到底应该怎么处理？是取三个段基址的和，还是取三个目标文件中基址的最大值？像这样的约定很多，而这些约定在链接的时候，都是用**组合类型**来说明的。

按大纲要求，我们这门课只要求学到单模块程序设计——你编写的程序，模块和任何其他模块都不发生关系，链接出去就是一个单模块程序。在这个前提下，段定义里真正要掌握的组合类型只有两种，我把它们讲清楚，其余的课外书自己看。

### 段名、段基址与类别

一个逻辑段装入内存以后就占据一片空间，有明确的边界；这个段从哪个地址开始，称为**段基址**。可汇编源程序自身并不占空间，它写的是"给哪个段起什么名字"，这段将来装到内存什么位置，是系统安排的事情。

#### SEGMENT 与 ENDS 必须配对

```asm
STK     SEGMENT
        DB      256 DUP (?)
STK     ENDS
```

左边的 `STK` 是**段名**，右边的组合类型是另一回事，两者不要混为一谈。段名完全是自己起的，叫 `STK`、叫 `X段`、叫 `Y段` 都可以——名字是给自己看的，汇编程序并不认识你起的名字，它只通过 `SEGMENT` 和 `ENDS` 这一对指令知道：一个逻辑段的定义从 `SEGMENT` 开始，到 `ENDS` 结束。左边给出的段名必须和 `SEGMENT` 左边的段名完全一致。

`STK ENDS` 后面要空一行，我这里空一行，是因为后边要用；程序里为什么空行？格式清楚。

#### 类别必须用单引号引起来

```asm
DATA    SEGMENT 'DATA'
        ...
DATA    ENDS
```

这个 `'DATA'` 必须用单引号引起来。为什么？因为类别这一栏查字典是没有任何意义的——它的唯一作用，就是告诉汇编程序"读本段信息"的时候，知道这是一段什么样的信息。段定义里明明写的是 `DATA` 段，我在段里面完全可以写别的：

```asm
VAR1    DB      10H
```

你一看到 `DB` 就知道这是字节数据，看到 `DW` 就知道这是字数据；类别和 `DB`、`DW` 是配合着看的。类别本身除了这一层提示之外，没有别的语法意义。

### ASSUME：让汇编程序认识段名

段名是自己起的，汇编程序当然不认识。可是程序里要用到这个段，汇编程序就得知道"这个段名对应的是哪一个逻辑段"。怎么告诉它？用 `ASSUME` 伪指令。

```asm
CODE    SEGMENT
        ASSUME  CS:CODE, DS:DATA, ES:DATA, SS:STK
```

`ASSUME` 写在代码段里，格式是"段寄存器冒号段名"，多个段之间用逗号隔开。`CS:CODE` 的意思是：代码段的段名是 `CODE`，它对应 `CS` 段寄存器；`DS:DATA` 是数据段名 `DATA` 对应 `DS`；`ES:DATA` 意味着在我这个程序中，**数据段和附加数据段是同一个段**。

> **易错点**：`SS:TOP` 这样直接写一行是**错的**。因为你必须在左边再写上 `ASSUME` 伪指令，才能告诉汇编程序"这个段名跟 `SS` 建立了关系"。直接写一行，汇编程序不知道这是什么意思。
>
> **易错点**：一段写不完要写到第二行时，第二行也必须以 `ASSUME` 开头。每一行都是一条完整的关系，不能靠上一行续着理解。
>
> **易错点**：`DATA` 不是变量名。段名虽然本身就具有段基址属性，但如果你只想取一个段名的段基址，必须写出 `SEG` 表达式；直接把段名当偏移地址用在 `MOV` 指令里是不对的。

`ASSUME` 建立的只是一种**关系**：汇编程序汇编的时候，知道 `DS` 后面对应的是 `DATA` 这个段。但是——

> **结论**：`ASSUME` 并没有把 `DATA` 段的段基址装载到 `DS` 里，也没有装载到 `ES`、`SS` 里。段寄存器根本没有被初始化。关系建立了，寄存器还是空的，这两件事必须分清楚。

### 段寄存器初始化

关系建立好了，接下来就得靠用户程序自己把这些段寄存器初始化。

```asm
START:
        MOV     AX, DATA
        MOV     DS, AX
        MOV     BX, DATA
        MOV     ES, BX
        MOV     SS, STK
        MOV     SP, TOP
```

`AX` 为什么绕这么一圈？因为段寄存器是个奇数，在 `MOV` 指令里**不能直接作目的操作数**。所以对 `DS` 的初始化要用两条指令：先把段基址取到通用寄存器，再送进 `DS`。`ES` 的初始化用 `BX` 中转，同理。

`MOV AX, DATA` 这一条有点意思。`DATA` 明明是个段名，可这里它不是被当偏移地址用的——这条指令源操作数的寻址方式是**立即寻址**，它等同于 `MOV AX, 段基址值`。汇编的时候，汇编程序就已经把 `DATA` 的段基址算出来填进去了。

`SP` 还可以用 `LEA` 来写：

```asm
        LEA     SP, TOP
```

`LEA` 只取操作数的偏移地址，不访问那个存储单元，所以 `TOP` 哪怕是用 `LABEL` 定义的"空"标号，这里也能正常用。

> **结论**：用户程序一开始，只能对 `DS`、`ES`、`SS`、`SP` 初始化。`CS` 和 `IP` 的初始化是**系统**完成的，不是用户完成的——`CS` 是奇数，本来也不能作 `MOV` 的目的。

#### 当前段最多有四个

`ASSUME` 里说"哪个段名跟哪个段寄存器建立了关系"，那么**段寄存器当前指着的那个段，就叫当前段**。8086 只有 `CS`、`DS`、`ES`、`SS` 四个段寄存器，所以一个完整的 8086 汇编语言程序中，当前段最多有四个。

```text
        +--------+       +-----------------+
        |   CS   |------>|  CODE 段        |
        +--------+       |  (代码段)        |
        +--------+       +-----------------+
        |   DS   |---+
        +--------+   |   +-----------------+
        |   ES   |---+-->|  DATA 段        |
        +--------+       |  (数据段)        |
        +--------+       +-----------------+
        |   SS   |---+
        +--------+---+   +-----------------+
                     +-->|  STK 段         |
                         |  (堆栈段)        |
                         +-----------------+
```

读图说明：`CS` 指向代码段；`DS` 和 `ES` 同时指向 `DATA` 段，这就是 `ASSUME ES:DATA` 的含义——数据段和附加数据段是同一个段；`SS` 指向堆栈段 `STK`。

要当心的一点：当前段寄存器不是你的段，你的数据就取不到。从一个数据段切到另一个数据段去取数据，就得先把 `DS` 重新初始化到那个新段；跳到另一个代码段去执行，也得让 `CS` 指向它。建立关系是 `ASSUME` 的事，切换当前段是初始化指令的事，两步都不能少。

### 堆栈段：STACK 组合类型与 TOP 标号

堆栈段的段名一般用 `STACK`——就用这三个字母的助记符，这个名字一眼就能看出来。段定义的时候，组合类型最好选成 `STACK`：

```asm
STK     SEGMENT STACK
        DB      256 DUP (?)
        TOP     LABEL WORD
STK     ENDS
```

`DB 256 DUP (?)` 定义了 256 个字节，作为堆栈区；`TOP LABEL WORD` 在段的末尾给堆栈区画一个"顶"。

#### 系统替你把 SS 和 SP 初始化了

这是 `STACK` 组合类型最大的好处。在 MASM 5.0 以上的版本进行汇编、链接时，链接程序知道这一段是堆栈段，于是当用户可执行文件被装入内存的过程中，**系统会对 `SS` 和 `SP` 做初始化**。你在代码段里就不用再管这件事了。

如果你偏要自己管，也可以——系统在链接以后，在装入内存的过程中对 `SS` 和 `SP` 初始化；你在代码段开头自己写那两条指令，同样可以。怎么都行。

#### 堆栈区要留出富余量

256 个字节只是个例子。实际工程当中，堆栈空间要定义多大，要根据程序的实际需求来定。一般按实际需求留出 30% 左右的富余量。

留富余量是为了什么？**为了便于程序扩充维护，避免 `SP` 指针一出界。** 你现在估的深度够用，不代表后面加了几层子程序调用之后还够用；一开始就留够，省得改。

#### SP 指向堆栈区末字节加一

这一点要把数字算清楚。定位类别缺省时，段被安排在第一个能被 16 整除的地址上，从这里开始，这个段的起始偏移地址一定是零。

```text
         段基址（16 整除的地址）
             |
             v
   +---------------------------+
   |  偏移 0000H               |
   |       ...                 |
   |  偏移 00FCH               |
   |  偏移 00FDH               |
   |  偏移 00FEH               |
   |  偏移 00FFH               |  <- 256 字节到这里结束
   +---------------------------+
   |  TOP，偏移 0100H          |  <- 末字节 + 1，不占空间
   +---------------------------+

   SS -> 段基址
   SP -> 0100H
```

读图说明：堆栈区共 256 个字节，末字节的偏移地址是 `00FFH`；`TOP` 标出的是末字节加一的那一单元，偏移 `0100H`；`SS` 指向堆栈段的段基址，`SP` 初始化后指向 `TOP` 所标的单元。

为什么 `SP` 要指向"加一"的那个空位置？因为 `SP` 永远指向堆栈的**下一个可用单元**。`PUSH` 压进去的时候是先减后存，`POP` 出来的时候是先取后加——`SP` 指向的是一个还没被占用的位置，而不是最后一个被占用的字节。`SP` 初始化完成，堆栈区才算真正可用。

### 组合类型 NONE 与其他类型

如果组合类型选了 `NONE`，它告诉链接程序：**本逻辑段和任何模块中的任何逻辑段都没有关系——我就是我自己，我就是我。** 所以 `NONE` 属于独立性的组合类型。

`NONE` 属于显式写出的一种。这一项你不写，链接出去就默认本段的组合类型是 `NONE`——写不写一个样，这也是为什么很多程序里的数据段干脆什么都不写。

组合类型里还有 `PARA` 型、`MEMORY` 型、`AT` 型等等，我就不讲了，感兴趣的同学参考有关的课外书，课内不讲究。

### LABEL：只取属性，不占空间

`LABEL` 是一条伪指令。它做的事情是：给一个符号赋予**段基址和偏移地址、类型**这三样属性，但是**不占用**对应的存储单元。

#### 和 DB、DW 定义的变量有什么不一样

```asm
TOP     LABEL WORD
TOP     DW      ?
```

第一行和第二行，都能让 `SP` 拿到同一个偏移地址。但区别是实打实的：

| 定义方式 | 有段基址和偏移地址属性 | 有类型属性 | 占用存储单元 |
| --- | --- | --- | --- |
| `DW ?` | 有 | 有（字型） | 占用一个字节字（2 字节） |
| `LABEL WORD` | 有 | 有（字型） | 不占用 |

`DW ?` 是真正分配了两个字节的存储空间，这两个字节约下来了；而 `LABEL WORD` 只是"挂"在这个单元上，取它的偏移地址和类型，一个字节都不占。

> **结论**：用 `LABEL` 定义的符号，只有偏移地址、段名和类型的属性，并没有占用对应的存储单元；用 `DB`、`DW` 定义的变量不光具有这些属性，同时还占用了那个存储单元。

#### 堆栈段里的应用：TOP LABEL WORD

```asm
STK     SEGMENT STACK
        DB      256 DUP (?)
        TOP     LABEL WORD
STK     ENDS
```

回到前面那个堆栈段。`TOP` 就是一个用 `LABEL` 定义的字型标号，它标出堆栈区末字节加一的那一单元，**不占用**堆栈区那 256 个字节中的任何一个。有了 `TOP`，你就可以：

```asm
        MOV     SP, TOP
        ; 或者
        LEA     SP, TOP
```

这就是 `LABEL` 在堆栈上的应用。除此之外，在数据段上，`LABEL` 有时也会用，下面就讲。

#### 数据段里的应用：给一个字变量开一个字节视图

```asm
DATA    SEGMENT
        VAR1    DB      10H
        VAR2    DW      1234H
        X_WORD  DW      1234H
DATA    ENDS
```

`X_WORD` 是一个用 `DW` 定义的字变量，里面放的是 `1234H`。汇编以后，它在存储器里是这样：

```text
      偏移     字节     所属变量
      0000H    10H      VAR1    (DB)
      0001H    34H       \
      0002H    12H        / VAR2   (DW 1234H)
      0003H    34H       \
      0004H    12H        / X_WORD (DW 1234H)
```

读图说明：8086 是小端存储，字变量 `1234H` 的低字节 `34H` 放在低偏移 `0003H`，高字节 `12H` 放在高偏移 `0004H`。

假如某处要对 `X_WORD` 做一个字节处理——比如只想看它存的那个字中的低字节 `34H`。在 `X_WORD` 的**前方**用 `LABEL` 指令定义一个字节型变量：

```asm
DATA    SEGMENT
        X_BYTE  LABEL BYTE
        X_WORD  DW      1234H
DATA    ENDS
```

汇编程序汇编到 `X_BYTE LABEL BYTE` 这一行时，`X_BYTE` 就指向了后面那个单元的段基址和偏移地址属性，类型是字节型的，但它**并没有占用**这个存储单元。汇编程序继续往下汇编到 `X_WORD` 的时候，`X_WORD` 变量对应的偏移地址还是这个单元的偏移地址。两个符号指向同一个单元，只是类型不同。

这样定义以后，实际程序当中要对该单元做字节处理，就直接用 `X_BYTE` 变量来做：

```asm
        MOV     AL, X_BYTE
```

效果和用 `PTR` 是一样的。`LABEL` 定义的类型属性"长"在这个符号上，一劳永逸；下面就看到这个对比。

#### 和 PTR 的对比

以前我们讲过：想在一个字变量对应的单元里取一个字节，需要用 `PTR` 来说明。

```asm
        MOV     AL, BYTE PTR X_WORD
```

这一条是合法的。但是它的源操作数直接写 `X_WORD` 呢？汇编程序直接找到这个单元——这是一个字单元；而 `AL` 是 8 位的，源和目的的类型数不一致。`BYTE PTR` 就是在这一条指令语句里，把 `X_WORD` 这个变量**临时**修改成字节型，语法上来讲类型一致，指令合法。出了这条语句，`X_WORD` 还是字变量。

两个办法对比一下：

| | `BYTE PTR X_WORD` | `LABEL BYTE` 定义的 `X_BYTE` |
| --- | --- | --- |
| 生效范围 | 只在当前这一条指令里 | 该符号在段内一直有效 |
| 源程序要写的东西 | 每次用都要写 `BYTE PTR` | 定义时写一次，之后直接用 |
| 占用存储单元 | 不额外占用 | 不占用 |
| 处理字变量中的某个字节 | 可以 | 可以 |

所以我今天讲的重点，就是 `LABEL` 伪指令在数据段上的应用。两种办法效果一样，你选顺手的用。

### 8086 汇编语言源程序的完整结构

现在把前面讲的部件全拼起来，这就是 8086 汇编语言源程序的**完整结构**，也叫标准结构：

```asm
STK     SEGMENT STACK
        DB      256 DUP (?)
        TOP     LABEL WORD
STK     ENDS

DATA    SEGMENT
        VAR1    DB      10H
        VAR2    DW      1234H
        X_WORD  DW      1234H
DATA    ENDS

CODE    SEGMENT
        ASSUME  CS:CODE, DS:DATA, ES:DATA, SS:STK

START:
        MOV     AX, DATA
        MOV     DS, AX
        MOV     BX, DATA
        MOV     ES, BX
        MOV     SS, STK
        MOV     SP, TOP

        ; 完成题目功能的程序片段
        ; ——这里开始编功能代码——
        ; 循环程序的话，循环体前面还要先对循环功能做初始化
        MOV     AL, X_BYTE

        ; 功能实现完了，程序结束
        MOV     AH, 4CH
        INT     21H
CODE    ENDS

END     START
```

`DATA` 段右边什么都没写，这是有意的：组合类型缺省（默认就是 `NONE`）、定位类别缺省、类别也缺省，一律按默认处理。段实体就在段里面用 `DB`、`DW` 这些伪指令来定义。

几处必须记牢的地方：

> **结论**：`SEGMENT` 和 `ENDS` 必须严格配对。一个逻辑段的定义从 `SEGMENT` 开始、到 `ENDS` 结束，`ENDS` 左边的段名要和 `SEGMENT` 左边的段名一致。

> **结论**：`END START` 里的 `END` 告诉汇编程序"总汇编到此结束"。它右边**必须**写出起始地址表达式——`START` 这个标号是我自己起的，叫 `MAIN` 也行，写谁就取谁。

> **结论**：用户可执行文件（EXE）被装入内存的时候，系统把 `END` 右边那个起始地址表达式 `START` 具有的**段基址属性给 `CS`**，具有的**偏移地址给 `IP`**。于是 `CS:IP` 就指向了程序的起始地址，CPU 从这里开始取指执行。

> **易错点**：`CS` 和 `IP` 的初始化是系统完成的，不是用户完成的。你在代码段里只需要管 `DS`、`ES`、`SS`、`SP`。

> **提示**：如果堆栈段定义时就选了 `STACK` 组合类型，那么系统会在装入内存时替你初始化 `SS` 和 `SP`，上面那两条指令可以不写；同理，堆栈段里的 `TOP LABEL WORD` 这一行也可以去掉——反正你自己也没打算用那个字单元。硬要写也没错，系统做过的初始化你再做一遍，不冲突。

#### 多代码段

如果你的整个程序就一个代码段，上面这个结构直接就写完了。要是程序有一些功能放在另外的代码段里，那就要给它起一个代码段的段名，比如 `CODE2`：

```asm
CODE    ENDS

CODE2   SEGMENT
        ASSUME  CS:CODE2
        ; 这个代码段里的功能代码
CODE2   ENDS
```

在新的 `SEGMENT` 下方，必须用 `ASSUME CS:CODE2` 来说明此时 `CS` 段寄存器指的是 `CODE2` 段。程序执行到 `CODE2` 段来的时候，按我们强调的"远程转移"方式过来——目标是一个标号，不是短位移。

不管一个代码段还是两个代码段，文件最后都是一条 `END`，右边写启动地址的标号表达式。

### 程序结束：交回 DOS 操作系统

功能代码编完，程序就要结束。程序结束之前，必须把控制权交回 DOS 操作系统，用的就是这两条：

```asm
        MOV     AH, 4CH
        INT     21H
```

这两条是一对，拆开就没意义了。

`INT 21H` 是**软件中断指令**，`21H` 是中断类型号。CPU 执行这条软件中断指令，就从用户程序"陷入"到 DOS 操作系统里面去了。DOS 把它所有的功能——显示、读键盘、结束程序等等——每一个功能的程序片段，都设计成子程序形式。执行用户程序的时候，就是通过 `INT 21H` 去调用 DOS 里的某一个功能子程序。

那么调用 DOS 的哪个子程序呢？`AH` 里放的是 DOS 子程序的功能号。

- `AH` 里放 `4CH`：**结束用户程序，返回到 DOS 操作系统**。我们反复用的就是它。
- `AH` 里放 `02H`：给屏幕上送一个字符。
- `AH` 里放 `01H`：从键盘读一个字符。

你把功能号写错了，得到的 DOS 功能就完全不是你要的那个了。

再把整个流程串一遍：程序执行之前，只有 DOS 操作系统在运行，它从磁盘上把用户可执行文件装入到内存；用户程序功能执行完了，`CS:IP` 要返回到 DOS 操作系统；返回的过程，就是执行 `INT 21H`，调用 DOS 的 `4CH` 号功能。

> **结论**：程序结束前是必须写 `MOV AH, 4CH` 和 `INT 21H` 的，这才是一个完整的 8086 汇编语言程序结构。

### EQU 与“=”：符号常量能不能重复定义

`EQU` 和"等号"这两条伪指令，在讲指令系统的时候我们以前讲过，叫**等值指令**。它们的作用是一样的：把右边表达式的值，赋给左边的符号常量。

相同点有三个：

- 都是定义符号常量；
- 右边表达式的值不能超过 65536，实际上就是 $0 \sim 65535$ 这个范围；
- 都是在汇编的时候由汇编程序完成的，不占运行空间。

不同点只有一个，但是很要命。

#### 区别只有一个：能不能再次定义

假设数据段一开始就定义了：

```asm
COUNT   EQU     5 + 3
```

后面凡是用到 `5 + 3` 这个表达式的地方，都可以用符号常量 `COUNT` 来代替。方便是方便。但如果后面再写一次 `COUNT EQU ...`，汇编程序会报错——

> **结论**：用 `EQU` 定义的符号常量，只能定义一次。同一个符号常量不能再次用 `EQU` 定义。

而用"等号"就不一样了：

```asm
        X       =       1
        MOV     AL, X
        X       =       X + 1
```

这一段是什么意思？第一次 `X = 1`，是一个等号伪指令，把 1 赋给符号常量 `X`。接着 `MOV AL, X`，汇编程序汇编这一条语句的时候，碰到 `X`，就用这个数字代替——此时是 1。再往下，`X = X + 1`，这是对同一个符号常量的**再次定义**：汇编程序碰到 `X`，用它的当前值参与运算，$X + 1 = 1 + 1 = 2$，所以 `X` 重新被定义为 2。此时前面那句 `MOV AL, X` 的源操作数就相当于被换成了 2。

> **结论**：如果符号常量用"等号"定义，那么这个符号常量还可以再次定义；用 `EQU` 定义的符号常量只能定义一次，不能重复定义。

顺便再记一遍共同的限制：不管用哪一条，右边表达式的值都不能超过 65535。

### ORG：让字变量对准

`ORG` 是定位伪指令。它管的是**段内偏移地址**的定位——把段内的位置计数器推到指定的偏移地址上，这样后面定义的变量就落在你指定的位置。

我们看数据段。假设它是这样的：

```asm
DATA    SEGMENT PARA
        VAR1    DB      10H
        VAR2    DW      1234H
        X_WORD  DW      1234H
DATA    ENDS
```

`PARA` 型说明本段的起始地址能被 16 整除，那么本段的起始偏移地址肯定是零。于是：

| 变量 | 类型 | 起始偏移 | 结束偏移 |
| --- | --- | --- | --- |
| `VAR1` | 字节变量 | `0000H` | `0000H` |
| `VAR2` | 字单元 | `0001H` | `0002H` |
| `X_WORD` | 字单元 | `0003H` | `0004H` |

`VAR1` 占一个字节，在偏移 0；`VAR2` 是字单元，起始偏移是 1；`X_WORD` 是字单元，起始偏移是 3。

> **易错点**：`X_WORD` 的起始偏移地址是 `0003H`，一个**奇数**地址——这是没对准的。从数据段读一个字、或者给数据段写一个字，地址没对准，就不能用一个字传送指令一次完成，要分两次字节传送才成。

为了让字变量对准，用 `ORG` 定位伪指令：

```asm
DATA    SEGMENT PARA
        VAR1    DB      10H
        ORG     4
        VAR2    DW      1234H
DATA    ENDS
```

`ORG` 后边写偏移地址表达式 `0004H`，把段内位置计数器推到 4；`VAR2` 就被定义在偏移 `0004H` 上了，这个字单元对准了。

> **易错点**：`ORG` 后面要写**偏移地址表达式**，不是写"空几个字节"——你要的是"定位到 4"，不是"跳过 4 个"。另外 `ORG` 只管段内的偏移，段基址的定位要靠 `SEGMENT` 右边的定位类别（比如这里的 `PARA`），两件事不要混。
>
> **提示**：`0000H`、`0001H`、`0002H`、`0003H` 这些偏移是**段内偏移**。一个段在内存里到底从哪个物理地址开始，由段基址决定，不由段内的偏移决定。

## 分支、合并与循环程序设计
> 对应块：BLK35 | 覆盖分集：P68-P69 | 块标题（分集名）：《68》

分支程序设计到底难在哪里？不是背不下几条转移指令，而是没有把一个问题里的“条件”找准。看到 `J` 开头的指令，总要问一句：它究竟在判断什么？条件从哪里来？为什么这个题目用这个标志位，而不能用另一个？

这一讲先把分支程序设计收住，再顺着两个有序数组的合并进入循环程序设计。前者要解决“条件怎么产生、怎么测试、每条路怎么验”，后者要解决“同一段工作怎样重复、重复到哪里结束、结束时结果怎么处理”。想明白这两条主线，后面的程序就不只是几条指令的拼接了。

### 分支先从“条件”说起

分支程序设计只有两类基本结构：二分支和多分支。二分支是在条件成立与不成立时分别做两件事；多分支则要连续判断多个条件，某个条件成立后转入相应处理，最后所有条件都不满足时再走公共出口。

不管哪一种，完整过程都分成两步：**先产生条件，再测试条件**。

```text
分析题目，选定判断依据
          │
          ▼
      运算并产生条件
          │
          ▼
      测试条件是否成立
        ┌────┴────┐
       成立       不成立
        │           │
      做分支 A     做分支 B
```

注意，条件不是凭空出现的。比较大小、判断某一位、观察运算结果，都要先由运算指令把结果落实到一个状态标志上。8086 最常用的是 `CMP` 和 `TEST`；如果目的操作数被破坏也无所谓，也可以用 `AND`、`OR` 等逻辑运算来产生需要的条件。

> **定义**：在 PSW 中，除 `AF` 外的五个状态标志 `ZF`、`SF`、`PF`、`OF`、`CF`，都可以成为分支条件。

所以，分析题目时不能先问“该用哪条 `J` 指令”，而要先问“题目中的条件对应哪个状态标志”。比较两数是否相等，可以围绕零标志考虑；结果的正负与符号位有关；进位、无符号大小关系等，则可能涉及进位标志。选准标志，再选择相应条件转移指令，程序中的条件与题目中的条件才真正接上了。

条件测试完成后，成立就走这一支，不成立就走另一支，这便是一个标准的二分支结构。

多分支并没有换一套基本机制，只是把测试串联起来：

```text
判断条件一
  ├─ 成立 → 处理一
  └─ 不成立 → 判断条件二
                 ├─ 成立 → 处理二
                 └─ 不成立 → 判断条件三
                                ├─ 成立 → 处理三
                                └─ 不成立 → 统一处理
```

比如，要在若干候选对象中找出 ASCII 码最大的一个，可以逐个测条件：先与当前最大者比较，若新对象更大就更新；否则继续看下一个。多个候选对象的场合，也可以借助跳转表组织多分支，提高程序执行效率。结构虽然变了，骨架仍然是“产生条件—测试条件—按结果转移”。

### 转移范围与逐条分支调试

条件转移的范围要特别当心。以当前 IP 为基准，短距离条件转移最多只能在约 128 字节的范围内跳转。目标离得太远，就必须想办法搭桥，不能把地址算得越界越远。比较直接的做法是先用一条无条件转移指令跳到远处，再由那里用另一条条件转移返回目标位置。

> **易错点**：无条件转移的使用范围和短距离条件转移不同。条件转移超出范围时，不要硬写一个超长偏移；让无条件转移来搭桥。

设计分支程序，真正容易漏掉的还不是指令，而是验证。只走程序正常情况下最容易遇到的一条路，远远不够。调试时要逐条分支走一遍：回到产生条件的位置，分别让条件成立与不成立，确认每条路径都能到达正确结果。尤其不能因为某条路最后“看起来也有数据”就放过它——那可能只是误走了另一条路，或者落到了碰巧看起来正确的边界情况。

要抓住三个动作：

1. 通过分析题目，选准分支条件及其对应状态标志；
2. 编写程序时，保证每条分支的处理都正确；
3. 上机调试时，逐条分支验证，而不是只看程序主路径。

分支程序设计说到底就是这三步。条件选错，后面的指令再熟练也没有用；条件选对以后，每条分支都必须真正走到、真正验过。

### 把两个有序数组合并成一个

接下来用一个比较难的例子把前面的思想串起来：`DATA1` 和 `DATA2` 中各放一组递增有序的八位无符号数，每个数组的前两个字节保存自己的长度；现在要把它们合并成一个新的递增数组 `BETA`，`BETA` 的前两个字节则保存合并后的总长度。

这题难点不在初始化，而在“怎样把两个有序序列真正合成一个有序序列”。如果只是把两个数组依次搬过去，得到的只是一条长长的队伍，并没有完成合并。

#### 先把数据布局看清楚

两个源数组和新数组的关系可以先画成这样：

```text
DATA1:  [长度 n1] [第 1 个元素] ... [第 n1 个元素]
DATA2:  [长度 n2] [第 1 个元素] ... [第 n2 个元素]

BETA:   [总长度  ] [合并后按递增次序排列的全部元素]
```

图中最容易忽略的是：每个数组的前两个字节是“控制信息”，不是待比较的数据。真正参与比较的第一个元素，要从偏移 2 开始取。课堂分析时假定第一组有 10 个元素，第二组有 13 个元素，于是新数组总长度是

$$
10+13=23=\mathrm{17H}
$$

`BETA` 的前两个字节就应当写成这个总长度，而不是第一项数据的长度。

> **易错点**：比较指针必须跨过数组头部。若从长度字段开始比较，程序比较的就不是数组元素了。

#### 三个指针让两个数组同步前进

程序需要为输出位置和两个源数组准备地址。这里用到 `BX`、`SI`、`DI` 等寄存器完成间接寻址，`CX` 则要承担相应的计数工作。初始化时，一方面保存两组元素个数，另一方面把访问地址指向头部之后的第一个元素。

为什么开头两个待比较元素适合先用直接寻址取出来？因为它们的位置是确定的，指令可以直接找到对应单元，把值送进通用寄存器，再用 `CMP` 比较。比较之后，较小者只需直接送到 `BETA` 的当前位置。

随后问题就来了：两个数组的元素地址在不断变化，不能永远只靠直接寻址。后面的元素必须通过间接地址取数，必要时还要借助通用寄存器中转。两个存储单元里的数据不能直接交换，交换要通过寄存器完成，也可以利用 `XCHG` 来做。

这里真正要掌握的是“取数—比较—写入—推进指针”这条链，而不是把某一行汇编死背下来。源数组的指针必须始终指向各自尚未处理的元素，目标指针则必须指向 `BETA` 中下一个空位置。只要这三者有一处没有同步，数据就会重复、遗漏或者乱序。

#### 一趟比较只搬走一个较小者

两个数组都已经递增，所以当前两个元素一经比较，较小者一定是合并结果中的下一个元素。它被写进 `BETA` 后，只需推进对应源数组的指针和剩余计数，再拿新的当前元素继续比较。另一个数组的指针不能跟着乱动。

把汇编背后的算法压缩成伪代码，就是下面这几步：

```text
当两个数组都还有未处理元素时
    比较两边的当前元素
    把较小者写入 BETA 的当前位置
    只推进被取走的那一侧
    该侧的剩余数量减 1

当任意一侧已经没有元素时
    把另一侧剩余元素依次写入 BETA
```

这正是前面所说的分支：比较产生条件，条件转移决定去哪一个处理块；`CMP`、条件转移以及 `MOVS`、`STOSB` 等字符串传送指令在这里互相配合。传送指令会推进地址，因此后面重新取数、比较和减计数时，地址与计数必须始终对应“下一个尚未处理的元素”。若某侧在先前传送中已经推进过指针，进入批量搬运前还要先修正到正确的未处理位置。

> **提示**：合并时不要把一个元素搬来搬去反复折腾。已经确定是当前最小者，就直接送入结果数组，然后只处理未完成的那一侧。

当 `CX` 或另一侧的计数减到零时，说明一组已经处理完，程序就转入末尾处理，把另一组剩下的元素整体送入 `BETA`，然后结束。这个例子很能体现字符串操作指令的妙处：它们不只是“搬字节”，还可以与比较、指针推进和计数控制配合，完成真正有结构的合并。题目确实有点难，但只要沿着上述骨架看，原来散乱的指令就能各归其位。

### 循环程序不只有一种骨架

讲循环控制指令时，我们已经见过 8086 中循环控制指令的主要类型：`LOOP`、`LOOPE/LOOPZ`、`LOOPNE/LOOPNZ` 和 `JCXZ`。现在不是重新背一遍指令，而是要把它们放回完整程序结构中使用。

循环的基本结构有两种。循环次数已经掌握时，可以让程序先做一轮工作，再判断是否继续；循环何时结束还不能预先确定时，则可以先判断结束条件，再做一轮工作。尤其当程序一开始就可能满足退出条件，或者退出条件会在循环过程中出现时，先判断往往更合适，也有利于减少不必要的循环工作。

#### 数二进制中的 1

先看一个熟悉的问题：统计 `BX` 中有多少个二进制 1。办法很直接——把 `BX` 的内容右移一位，移出的位进入进位标志 `CF`；若 `CF=1`，就说明本位为 1，累计值加 1；继续右移，直到原值中没有 1 为止。

这已经同时用了两种结构：右移和统计是循环工作，`CF` 判断与“`BX` 是否已经为零”的判断负责控制循环。结构不同，道理却是相通的。

如果改用先循环工作、后循环判定，就要小心多走一轮。这里可以采用更省事、也更清楚的安排：进入循环前先确认 `BX` 不为零；每轮先右移，再检查 `CF` 是否为 1 并累计；做完本轮工作后检查 `BX` 是否仍不为零，决定是否再转一圈；若已经为零，就直接退出。

```text
检查 BX 是否为零
  ├─ 是 → 结束
  └─ 否 → 进入循环
             │
             ├─ 右移一位
             ├─ CF 为 1，则计数加 1
             └─ BX 非零则返回循环
```

这样既不会漏掉最后一个 1，也不会为了“统一形式”而无意义地继续移动一个已经为 0 的数。循环结构不是模板上的死板顺序，判断放在哪里，完全取决于怎样表达问题最清楚、最省工作。

#### 五个组成部分

无论采用“先工作后判定”还是“先判定后工作”，一个循环程序都可以拆成五部分：

| 组成 | 作用 | 典型内容 |
| :--- | :--- | :--- |
| 初始化 | 建立循环开始前的状态 | 设置计数器、指针、地址与初值 |
| 循环工作 | 完成一轮真正要做的任务 | 传送、比较、移位、运算等 |
| 修改并测试条件 | 推进判断依据 | 修改计数、移位结果并检查状态标志 |
| 循环控制 | 决定返回还是退出 | 计数到零、结果满足终止条件等 |
| 结果处理 | 输出或保存最终结果 | 显示、送存；这一部分可以没有 |

第一部分一定是初始化，这并不是一句“谁都知道”的套话。计数初值若不对，循环次数就会错；指针若没跨过头部，第一次比较就可能拿错对象。初始化把程序带入一个定义清楚的起点。

循环工作每执行一次，题目要求的核心任务才真正完成一遍。修改并测试条件则让程序拥有继续或退出的依据。循环结束以后，有些程序还要把结果逐项送到屏幕上，或者送到指定位置；这一部分就是结果处理。若结果需要每次循环后都显示，也可以直接放进循环工作里，不必等到全部结束后再单独处理。

> **结论**：循环程序是否写对，不能只看循环体；初始化、条件修改、循环控制和结果处理中任何一环出错，整体都会错。

### 冒泡排序：把循环与分支连起来

最后看一个能同时容纳比较、分支、交换和多重循环的例子：对五名学生的成绩排序。为了把过程摆在眼前，我们只看 `70、50、90、67、80` 这组数据。

冒泡排序不一次寻找最大或最小值，而是反复做相邻比较。一轮中比较第一个与第二个、第二个与第三个……每比较完一对，就让较小者继续向后，较大者留在这一对的左侧。按这组数据的实际相邻比较过程，动作如下：

| 相邻比较 | 动作 |
| :--- | :--- |
| 70 与 50 | 70 已在较大位置，不交换 |
| 50 与 90 | 交换 |
| 90 与 67 | 交换 |
| 90 与 80 | 交换 |

一趟结束后，序列变为：

```text
50  70  67  80  90
```

这时 90 已经被逐步推到了序列末位。真正写程序时，交换条件绝不能写反：要根据题目要求的排列方向，决定哪一侧较大、哪一侧需要交换。比较判断错了，不是完全排不出来，就是越排越乱。

两个内存单元也不能直接交换。可以通过通用寄存器中转，利用 `XCHG`，或者按保存一个、读取另一个、写回一个的次序完成交换。比较后决定要不要交换，不正是我们熟悉的条件分支吗？整趟扫描又是一个循环，因此冒泡排序不过是把循环和分支一层层套起来。

若有 $n$ 个数据参加一趟相邻比较，需要比较 $n-1$ 次；五个数就是四次。每完成一趟，至少有一个极值被送到确定的位置，下一趟再继续缩小尚未确定的范围。数据量不大时黑板写不下，所以只取五个数据演示；掌握的却不是这五个数字，而是“相邻比较—按条件交换—一轮接一轮”的整个骨架。

### 本讲提到的题目

在 `DATA1` 和 `DATA2` 两个缓冲区中，各存放一组递增有序的八位无符号数，两个数组的前两个字节分别保存本数组长度。编写程序，将它们合并为递增数组 `BETA`，并把 `BETA` 的前两个字节设置为合并后的总长度。

解法与答案已在「把两个有序数组合并成一个」一节展开：用三个地址指针分别跟踪输出位置和两个未处理元素，在两组都未结束时取两侧较小者写入 `BETA`，一组用尽后整体搬运另一组余项。课堂取 $n_1=10$、$n_2=13$，所以 `BETA` 前两个字节应写 $23=\mathrm{17H}$，其余字节保存全部元素按递增次序合并后的结果。

## 气泡排序与总线：先把循环算清，再把信息分清
> 对应块：BLK36 | 覆盖分集：P70-P71 | 块标题（分集名）：《70》

这一段内容看起来前后跨度很大：前面还在逐个比较数字，后面已经进入总线和接口芯片。但它们其实都在训练同一种能力——把一个看似整体的任务，拆成能够计数、能够判断、能够一层一层推进的结构。

先从排序说起。数字排来排去，最后总要回答两个问题：到底比较了多少次？外层循环什么时候可以停？这两个问题一旦算清楚，气泡排序就不再是“把两个数交换一下”的零散动作，而是一个完整的控制过程。再往后，总线要解决的也是类似的问题：地址、数据、控制信息不能混在一起，必须在合适的时机、合适的通道里传送。

### 先把 n-1 这个数算明白

假设有 $n$ 个数需要按由低到高的顺序排列。第一趟从前往后比较相邻的两个数：前一个和后一个比较，前一个小就保持顺序，前一个大就交换。随着比较位置不断向后移动，较大的数会像气泡一样逐步向右移动，最后沉到当前未排好序部分的最右端。

注意这里的“比较”不是把整个数组从头到尾反复扫一遍，而是相邻位置之间的比较。若数组位置写成 $x_1,x_2,\ldots,x_n$，第一趟做的比较是：

```text
比较 x1 和 x2
比较 x2 和 x3
比较 x3 和 x4
……
比较 x(n-1) 和 xn
```

所以第一趟有 $n-1$ 次比较。第一趟结束以后，最大的数已经到达最右端。接下来只需要继续处理前面剩下的 $n-1$ 个数，第二趟的比较次数就变成 $n-2$。这样一层一层往里收，最后剩下两个数时只需要比较一次。

| 阶段 | 本趟开始时的未排序元素个数 | 本趟比较次数 | 本趟结束后确定的位置 |
| :--- | :---: | :---: | :--- |
| 第一趟 | $n$ | $n-1$ | 当前未排序部分的最大值到最右端 |
| 第二趟 | $n-1$ | $n-2$ | 剩余部分的最大值到新的最右端 |
| 第三趟 | $n-2$ | $n-3$ | 剩余部分的最大值到新的最右端 |
| 最后一趟 | $2$ | $1$ | 最后一个位置确定 |

因此，外层循环执行 $n-1$ 次，而不是 $n$ 次。这个结论不是靠死记，而是由未排序区间逐步缩小得到的：$n$ 个数排好序时，最后一个数已经由前面各趟的比较确定了，所以不需要再为它单独启动一趟。

```text
第一趟：  [ 未排序 ][ 未排序 ][ 未排序 ][ 未排序 ]
                 ↓
第二趟：  [ 未排序 ][ 未排序 ][ 未排序 ]
                 ↓
第三趟：  [ 未排序 ][ 未排序 ]
                 ↓
最后一趟：[ 未排序 ][ 未排序 ]
```

这张图表达的不是“每一趟都处理全部数据”，而是未排序区间越来越短。小的数可能在某次交换中向左移动，大的数向右移动；所谓“冒泡”，就是较大的数在外层推进过程中逐步向右沉下去。

> **结论**：$n$ 个数的起泡排序，第一趟内层比较 $n-1$ 次，此后每趟比较次数减一；外层循环的总次数为 $n-1$。

### 双重循环到底怎样配合

现在把刚才的过程翻译成程序结构。外层循环控制“还要做几趟”，内层循环控制“这一趟要做多少次相邻比较”。这两个计数不能混在一起：外层计数决定排序推进了几层，内层计数决定当前这一层已经比较了多少对相邻元素。

一个很直观的初始化方式是：外层计数器先装入 $n-1$，每一趟开始时，把外层计数器当前的值复制给内层计数器。这样第一趟内层就是 $n-1$ 次，外层减一以后，第二趟自然就是 $n-2$ 次。

```text
初始化外层计数 CH = n - 1

外层循环：
    内层计数 CL = CH
    从缓冲区首地址开始比较
    重复 CL 次：
        取当前单元的内容
        取下一个单元的内容
        比较
        顺序不对就交换
    一趟结束
    如果这一趟没有交换：
        排序已经提前完成，退出
    否则：
        CH = CH - 1
        如果 CH 不为 0，回到外层循环
```

用 `CH` 和 `CL` 表示计数时，可以把寄存器分工记成下面这样：

| 部件 | 作用 |
| :--- | :--- |
| `CH` | 外层循环次数，表示还要完成几趟 |
| `CL` | 当前这一趟的内层比较次数 |
| `SI` | 指向缓冲区中的当前地址，依次向后移动 |
| `AL`、`AH` | 暂存相邻两个单元的数据 |
| `BL` | 交换标志；发生交换时置为非零，一趟结束仍为零则说明没有交换 |
| `BUFF1` | 存放待排序数据的缓冲区 |

`SI` 的作用非常关键。它不是一直固定在数组开头，而是在一次内层扫描中逐个指向相邻元素：先读当前单元，再把指针向后移动一个单元，读下一个单元。比较完成后，指针还要退回当前这一对的起点，为下一次相邻比较做准备。

如果采用由低到高的顺序，当前数据不小于下一个数据时，顺序已经正确，不需要交换；只有当前数据大于下一个数据时才交换。把这个判断直接翻译成条件转移，就是比较之后判断“是否高于或等于”，满足时不交换。`JAE` 这样的条件转移指令在这里承担的就是“不高于就不交换”的判断。

> **易错点**：`SI` 向后移动并不等于内层循环结束。一次内层循环要完成一整趟相邻比较；每比较一对，指针都要为下一对相邻元素准备好。内层计数器减到零，才说明这一趟全部比较完成。

### 用交换标志提前结束

如果只按照教科书形式写，`CH` 减到零以后才结束，确实可以完成排序。但实际程序还有一个很重要的优化：某一趟内层循环从头到尾没有发生一次交换，说明这一趟扫描没有发现逆序，数组已经提前排好了，再继续跑后面的外层循环就是白做。

因此，在每一趟开始时把 `BL` 清零；每次真正交换两个数，就给 `BL` 置一个非零值。整趟内层循环结束后检查 `BL`：

```text
BL = 0
    ↓
内层循环中是否发生过交换？
    ├── 否：BL 仍为 0，排序已经完成，直接退出
    └── 是：BL 非零，外层计数减一，继续下一趟
```

这就是交换标志存在的全部理由。它不是为了把程序写得复杂，而是为了回答一个实际问题：这一次扫描有没有改变数据顺序？没有改变，就不用再扫描下一趟。

可以把这条优化写成很清楚的控制逻辑：

```text
每一趟开始：
    BL = 0
    进行相邻比较
    如果需要交换：
        交换两个单元
        BL = 1
    ...
    BL == 0？
        是 → 退出
        否 → 进入下一趟
```

为什么说“某一趟没有交换”就可以停止？因为如果还有逆序关系，继续从前往后扫描时一定会遇到需要交换的相邻元素；反过来，完整扫描一次都没有交换，就说明当前顺序已经满足要求。标志位不是猜测，也不是凭经验提前结束，而是用一次实际扫描的结果决定是否继续。

> **提示**：交换标志要在一趟内层循环开始时清零，不能在程序开始时只清零一次。每一趟都要独立回答“这一趟有没有发生交换”。

### 把排序流程画出来

程序设计里，流程图往往比一段密集的文字更能说明控制关系。起泡排序的标准流程如下：

```text
                 ┌─────────┐
                 │  开始   │
                 └────┬────┘
                      │
                      v
             ┌────────────────┐
             │ 初始化计数器、   │
             │ 指针和交换标志  │
             └───────┬────────┘
                     │
                     v
             ┌────────────────┐
             │ CH = n - 1 ?  │
             └───┬────────┬───┘
                 │        │
              否 │        │ 是
                 │        v
                 │   ┌────────────────┐
                 │   │ CL = CH         │
                 │   │ BL = 0          │
                 │   │ SI 指向首地址    │
                 │   └───────┬────────┘
                 │           │
                 │           v
                 │   ┌────────────────┐
                 │   │ CL 是否为零？   │
                 │   └──┬──────────┬──┘
                 │      │          │
                 │   是 │          │ 否
                 │      │          v
                 │      │   ┌────────────────┐
                 │      │   │ 读相邻两个单元 │
                 │      │   │ 比较并按需交换 │
                 │      │   │ CL = CL - 1    │
                 │      │   └───────┬────────┘
                 │      │           │
                 │      └───────────┘

             │          │

             │          v

             │   │ CH = CH - 1    │
             │   └───────┬────────┘
             │           │
             │           v
             │      回到外层判断
             │
             v
        ┌─────────┐
        │  结束   │
        └─────────┘
```

流程图中有三条分支必须分清：

第一，内层计数 `CL` 还没有减到零，就回到内层循环；减到零以后，才去检查这一趟的交换标志。

第二，`BL` 为零表示这一趟完全没有交换，直接结束；`BL` 非零才允许外层计数减一。

第三，外层计数 `CH` 减到零时，说明预定趟数已经完成；否则回到外层循环，进入下一趟。

把这三条分支和前面的数组位置变化放在一起，才能理解为什么“比较次数减少”和“可以提前退出”是两个不同层面的优化。前者来自排序区间缩小，后者来自数据已经有序。

### 起泡排序的 8086 程序骨架

把流程图落实到指令层面，核心是“取数、比较、必要时交换、计数、判标志”。下面按照前面确定的寄存器分工写出一个完整的排序核心。`BUFF1` 中的五个字节在运行时填入待排序数据；这里的重点是把控制流程写对，而不是记住某一份固定数组。

```asm
BUFF1    DB 5 DUP(?)

BUBBLE:
        MOV  CH, 4             ; 外层计数：n - 1
OUTER:
        MOV  CL, CH             ; 本趟内层比较次数
        MOV  BL, 0              ; 清除本趟交换标志
        MOV  SI, OFFSET BUFF1   ; 指向当前待排序区首地址

INNER:
        MOV  AL, [SI]           ; 读取当前单元
        INC  SI
        MOV  AH, [SI]           ; 读取下一个单元
        CMP  AL, AH
        JAE  NO_SWAP            ; 当前数不小于后一个数，不交换

        XCHG AL, AH              ; 两个暂存单元的内容交换
        MOV  [SI-1], AH
        MOV  [SI], AL
        MOV  BL, 1              ; 发生过交换，标志置为非零

NO_SWAP:
        DEC  SI                 ; 回到这一对相邻单元的起点
        LOOP INNER              ; CL 减一，未到零则继续比较

        CMP  BL, 0
        JE   DONE               ; 本趟没有交换，已经排好
        DEC  CH
        JNZ  OUTER              ; 还有外层趟数，继续
DONE:
        RET
```

这段代码和流程图是一一对应的，不能只背其中的跳转指令。

`BUBBLE` 是入口。`MOV CH, 4` 对应 $n-1$，因为示例数据是五个字节；如果数据个数改变，首先改变的是这个初始值。`OUTER` 每次开始一趟新的扫描，把 `CH` 复制给 `CL`，这样内层次数就会随着外层推进而自动减少。

`MOV BL, 0` 必须放在 `OUTER` 后面，而不能只在程序入口设置一次。因为交换标志回答的是“当前这一趟有没有交换”，每一趟都要重新开始记录。

进入 `INNER` 后，`SI` 先指向当前单元；`MOV AL, [SI]` 把这个数取入 `AL`，`INC SI` 使 `SI` 指向下一个单元，再用 `MOV AH, [SI]` 取入后一个数。此时 `AL` 和 `AH` 保存了相邻的两个数据，比较时不需要反复访问存储器。

`CMP AL, AH` 只负责设置比较结果的条件码，真正决定是否交换的是后面的 `JAE`。对于由低到高的排序，当前数大于后一个数时才需要交换；如果当前数小于或等于后一个数，顺序已经正确，直接跳到 `NO_SWAP`。

需要交换时，先利用 `XCHG` 交换 `AL`、`AH` 中的内容，再把两个暂存值写回相邻存储单元。写回以后，原来的相邻顺序被改变，较大的数被放到右侧，交换标志 `BL` 置为非零。`DEC SI` 把指针退回这一对相邻单元的起点，接下来 `LOOP INNER` 才能让下一次读取从正确的位置开始。

内层循环结束后，`CMP BL, 0` 和 `JE DONE` 实现提前结束。若 `BL` 为零，这一趟没有发生交换，说明数组已经有序；若 `BL` 非零，才执行 `DEC CH`，并用 `JNZ OUTER` 判断还有没有后续趟数。

> **注意**：这里的条件是“由低到高”排序。若题目要求“由高到低”，比较后的不交换条件要相应改变，但“双重循环、逐趟缩短未排序区、交换标志”这三个结构仍然保留。

### 程序分析题先看功能，再看指令

起泡排序特别适合出现在程序分析题里，因为题目给出的程序可能少了初始化、比较、交换或跳转中的几行，要求你根据功能把横线补完整。做这类题时，不能一看到缺口就凭感觉填，而要先把题目要求翻译成算法骨架。

需要先回答四个问题：

1. 待排序数据在什么地方，缓冲区里有多少个数据？
2. 排序方向是低到高还是高到低？
3. 外层和内层分别由哪个计数器控制，初始值是什么？
4. 交换之后，怎样判断这一趟是否发生过交换？

只要这四个问题没有确定，单独看某一条 `MOV`、`CMP` 或 `JNZ` 就没有意义。先在纸上写出“初始化—一趟内层比较—交换—计数—判标志—决定是否继续”的主干，再把题目中给出的寄存器、引号和横线逐一放回主干，答案就不容易跑偏。

### 子程序设计技术的收口

前面循环结构讲完以后，程序设计部分进入子程序设计技术。这里不是突然换了一套完全不同的方法，而是把前面反复使用的控制结构进一步组织成可调用的程序单元。课堂已经把相关技术讲过，4.6 节还集中安排了不少编程例题，难度比前面的基本循环明显上台阶。

这类例题不能只看“最后能不能运行”，还要看程序的功能边界是否清楚、输入输出是否明确、循环和跳转是否有出口。做错了以后，答案往往就藏在某一个计数器的初值、某一个条件码判断，或者某一个没有设置的退出标志里。把功能要求先拆成结构，再检查每一条指令是否放在正确的位置，比从头到尾死记指令序列更可靠。

### 为什么要有总线

接下来把视线从程序内部移到整个系统。一个以 CPU 为核心的电子信息系统，除了 CPU，还会有存储器和 I/O 端口。CPU 要读写存储器，就必须把地址信息送给存储器；数据读写时，还要把数据信息送过去；为了让存储器知道这次是读还是写，还要传送相应的控制信息。

表面上，CPU 只要有地址引脚、数据引脚和读写控制引脚就可以了。但 CPU 体积有限，封装时能够引出的引脚数量也有限。为了在有限引脚上携带更多信息，有些引脚会承担多个作用，也就是把不同信息在时间上复用。于是，CPU 引脚上的信息不能直接理解成某一根永远只属于某一种信号。

总线形成电路要做的，就是把复用后的信息重新分开：地址信息走地址通道，数据信息走数据通道，控制信息走控制通道。这样才能让不同类型的信息在各自专用的路径上传送。

```text
                 ┌──────────────┐
                 │     CPU      │
                 │  有限引脚资源 │
                 └──────┬───────┘
                        │
             地址/数据/控制信息复用
                        │
                        v
              ┌──────────────────┐
              │   总线形成电路    │
              │ 按时序分离信息    │
              └──────┬───────────┘
             ┌───────┼────────┐
             │       │        │
             v       v        v
         地址总线  数据总线  控制总线
             │       │        │
             └───────┴────────┘
                    │
                    v
                 存储器 / I/O
```

> **定义**：在计算机系统中，用来传输信息的通道称为总线。地址信息、数据信息和控制信息是总线系统中三类基本信息。

要设计总线形成电路，必须先弄清楚 CPU 各个引脚的功能，以及引脚之间的时序关系。引脚功能告诉你某一时刻信号代表什么，时序关系告诉你这些信号什么时候有效、什么时候必须保持、什么时候可以改变。只有把功能和时序放在一起，才能判断复用信息应该在哪一段被分离，以及分离后送往哪一条总线。

### 按层次看总线分类

总线不是只有一种。按照连接范围和所在位置，可以把总线分成片内总线、元件间总线、系统总线和设备间总线。它们都承担信息传输，但设计的责任和关注点并不相同。

#### 片内总线

片内总线是集成电路芯片内部的连接。芯片里有很多元件，或者说有大量晶体管，元件之间需要通过片内线路互相联系，这些线路就是片内总线。

片内总线的设计优劣会直接影响芯片性能。普通情况下，它主要是半导体生产厂家的设计问题；但当电子设计采用可编程器件时，片内总线的组织方式也可能成为设计者需要考虑的内容。不能因为“芯片内部”就把所有责任都推给厂家。

#### 元件间总线与板内总线

元件间总线也常称为板内总线。把电路做在一块印刷电路板上以后，板上有许多元件，元件与元件之间需要通信，连接这些元件的线路就是元件间总线。

这条总线直接影响整个电路板的工作性能，因此它和板级设计者直接相关。布局不同，走线经过的区域、走线长度和相互影响就会不同；高频工作时的布线要求更严格，走线尽量不要打直角，可以采用 $45$ 度走线或圆弧，频率特别高的部分还要考虑外部屏蔽。设计者不能只盯着逻辑图，还要盯住板上的真实空间和信号路径。

#### 系统总线

系统总线也称为内部总线。在计算机主板上常有多个插槽，插槽上的总线用于主板和扩展电路板之间的通信。用户设计的系统可能由多块电路板组成，这些板卡插入插槽后要交换信息，连接它们的线路就属于系统总线。

本章讨论的总线形成，重点就是系统级总线怎样形成。片内总线和板内总线解决的是更靠近芯片、电路板内部的连接问题；系统总线则把多个功能部件组织成一个能够协同工作的系统。

#### 设备间总线与外部总线

设备与设备之间的通信线路属于外部总线，也称设备间通信总线。计算机和打印机之间需要通信，计算机和外部设备之间也需要连接，这些连接都落在设备间总线的范围内。

常见的设备接口包括计算机上的 `COM1`、`COM2` 和 `USB` 等。早期计算机还配有并行接口；如果现在使用的计算机没有相应接口，需要并行接口时，就要在计算机上配置并行接口卡，把并行总线引出来。

系统总线和通信总线虽然服务的对象不同，但设计时都要标准化。标准化不是最后再补的包装，而是让不同功能部件能够按照统一规则互连的前提。系统总线和通信总线的优点，前面已经有过归纳；这里先把底线记住：两类总线都不能各自采用一套互不兼容的连接规则。

### 总线形成中的常用接口芯片

总线形成和接口电路设计，离不开一些常用芯片。这些器件在数字电路课程里出现过，接下来关注的不只是“会认型号”，还要知道它们怎样控制数据方向、怎样输出高阻态，以及怎样和 CPU 的读写周期配合。

#### 先学会读型号

买到一个芯片，不能先看封装猜功能，通常要按“功能—型号—封装”的顺序判断。

第一步看功能：它是单向缓冲器、双向缓冲器，还是其他类型的接口器件。

第二步看型号：型号中的系列、数字和后缀要能辨认。`74` 系列与 `54` 系列属于不同的温度等级，前者是民用器件，后者是军用器件。课堂提到的温度范围差异很明显：民用器件通常工作在 $0$ 到正 $40$ 摄氏度范围，军用器件可以达到负 $40$ 到正 $70$ 摄氏度范围，因此后者价格往往高出很多，课堂给出的经验是至少十倍以上。

型号中间的数字和后缀还体现速度、逻辑类型等差别。使用时要分清 `74LS244`、`74H`、`74S`、`74F` 以及普通 `74` 系列器件，不能只看到“八位缓冲器”就把它们当成完全相同的芯片。不同后缀对应不同的速度或温度等参数，实际选型必须以芯片手册给出的参数为准。

TTL 和 CMOS 也要区分。课堂强调过：TTL 的速度相对更高，但功耗较大；CMOS 的功耗较小。功能、速度、功耗、工作电压和环境温度要一起看，不能只盯着一个指标。

第三步看封装。常见有双列直插式，也有贴片扁平封装。画电路图时，教材通常先按双列直插封装表示，但实际装配还要根据板级空间和工艺选择封装形式。

#### 74LS244：单向缓冲与高阻态

`74LS244` 是一个八位数据缓冲器，传送方向是单向的。输入端有八个数据信号，输出端也有八个对应信号；使能控制端决定输出端是否真正跟随输入。

它的关键控制信号是低电平有效的输出使能信号 `/1OE`。控制逻辑可以写成：

| `/1OE` | 输出端状态 |
| :--- | :--- |
| 低电平 | 输出跟随输入数据 |
| 高电平 | 输出端处于高阻态 |

为什么要能输出高阻态？这是因为它经常被用作 CPU 数据总线上的输入端口。CPU 读取外设时，地址译码和读信号使这个缓冲器工作，外设数据被放到总线上；CPU 不读取这个端口时，缓冲器必须把输出端置于高阻态，让出总线，不能和 CPU 数据总线上的其他器件争用同一根线路。

```text
外设数据 ───────► 74LS244 ───────► CPU 数据总线
                    │
                    └── /1OE
                         低：允许数据进入总线
                         高：输出高阻态，主动让出总线
```

地址译码的作用是为端口分配地址。CPU 把相应地址放到地址总线上，译码电路判断地址是否命中这个端口，再配合读控制信号控制 `/1OE`。在一个读总线周期中，数据从外设经过缓冲器进入 CPU 数据总线；读周期结束后，输出重新回到高阻态。

> **易错点**：缓冲器的输入端有电平，并不代表输出端一定会驱动总线。`/1OE` 处于无效的高电平时，输出端是高阻态；只有使能有效，输出才跟随输入。没有这个高阻态功能，多个输入端口接到同一数据总线时就会发生总线竞争。

#### 74LS245：双向数据通道

如果数据需要在 CPU 和外设之间往返传送，就不能只用单向缓冲器。`74LS245` 是八位双向缓冲器，两边各有八个数据引脚：一组标为 A 端，另一组标为 B 端。

它有两个控制端：

- `/OE`：输出使能，低电平有效，决定缓冲器是否工作；
- `DIR`：方向控制，决定数据从哪一边送到另一边。

当 `/OE` 为低电平时，`74LS245` 正常工作，方向由 `DIR` 决定：

| `/OE` | `DIR` | 数据方向 |
| :--- | :---: | :--- |
| 低电平 | 低电平 | B 端传送到 A 端 |
| 低电平 | 高电平 | A 端传送到 B 端 |
| 高电平 | 任意 | 两侧输出均为高阻态 |

这两种方向可以理解为总线两端对话时的两种状态。`DIR` 为低，数据从 B 端进入 A 端；`DIR` 为高，数据从 A 端进入 B 端。`/OE` 则像总开关，低电平时打开允许数据通过，高电平时两侧都进入高阻态，方向控制已经没有实际意义。

```text
             DIR = 1
      A 端 ─────────────► B 端

             DIR = 0
      A 端 ◄───────────── B 端

             /OE = 1
      A、B 两侧输出均为高阻态
```

`74LS244` 和 `74LS245` 都是八位缓冲器，但方向控制能力不同：前者适合固定方向的数据传送，后者适合需要双向通信的端口。把两者混在一起，最容易错在控制端和方向端的功能上。看到“输入端口”要先想到高阻态，看到“数据往返”则要想一想 `DIR` 和 `/OE` 的配合。

### 从循环控制到总线互连

现在回头看，前面的排序程序和后面的总线形成电路虽然属于不同章节，但都在处理“结构如何分层”的问题。

排序程序中，外层循环管理趟数，内层循环管理相邻比较，交换标志决定是否可以提前结束；每一步都要有明确的计数、判断和返回位置。总线形成电路中，CPU 引脚上的复用信息要按时序分离，地址、数据、控制信息要进入各自的通道，接口芯片还要用使能和方向控制决定是否驱动数据线。

所以，读这类程序和设计这类电路都不能只抓住表面动作。排序不能只记“比较后交换”，还要知道谁控制次数、什么时候退出；总线不能只记“有三类信息”，还要知道它们为什么必须分开、芯片为什么需要高阻态。结构清楚了，表面上的指令和引脚才不会变成互相冲突的碎片。

### 本讲提到的题目

还出现过一类典型的程序分析题：给出一段没有写完整的气泡排序程序，要求根据题目功能，在横线处补充指令。题目要完成的是对缓冲区中的 50 个 8 位数据进行由高到低的排序。题目还会先给出程序标题，要求先根据功能判断程序正在完成什么，再阅读程序并补全缺失指令；另一种形式则是不直接告诉你每一步的作用，只留下程序让你分析功能。

这类题的解法不能靠猜某条指令，而要按功能逐层核对：

```text
题目要求：对 50 个 8 位数据由高到低排序
        ↓
确定排序方法：起泡排序
        ↓
确定外层结构：共进行 n - 1 趟
        ↓
确定内层结构：每一趟进行剩余元素的相邻比较
        ↓
确定比较条件：当前数与下一个数不符合降序时交换
        ↓
确定退出条件：计数减到零，或某一趟没有交换时提前结束
```

能够确定的算法答案，就是前面已经写出的核心骨架：外层计数器装入 $n-1$，每一趟把外层计数复制给内层计数，地址指针从缓冲区首地址开始逐个比较，顺序不对就交换，交换后设置非零标志；内层结束且标志为零时直接退出，否则外层计数减一并继续。题目要求由高到低时，只需要把“不交换”的条件改成与升序相反的判断，不能改变整个双重循环的骨架。

如果原题给出的横线位置还涉及具体标签、寄存器或跳转目标，就必须把这些内容放回原程序逐处对照；没有在题干中出现的初始值、指令或标签，不能凭经验擅自补成另一道题。能从功能确定的是结构，能从原题确定的是具体填空，这两层要分清。

## 总线缓冲、锁存器与8086复位机制
> 对应块：BLK37 | 覆盖分集：P72 | 块标题（分集名）：《72》

### 双向总线为什么需要缓冲

CPU送出的数据要从双向数据总线继续向下传。如果总线上挂了很多负载，信号就可能“带不动”。这时要在总线中加上缓冲，245就是常用的一种总线缓冲器。

实际工程里，我们经常要设计单向输入端或单向输出端。只要满足单向传输的要求，通常优先选245，而很少选240。这个选择不只是功能上的取舍，还要看芯片引脚是否方便PCB布线。

240的引脚是输入、输出、输入、输出交叉排列，信号走到哪里都容易“难受”，布线很麻烦。245则把一侧集中安排为输入，另一侧集中安排为输出，PCB走线非常清楚。大家愿意用245做双向通信，往往正是因为它在布局上更友好。

> **提示**：选器件不能只看逻辑功能。引脚排列是否适合布线，也会直接影响实际电路的难做程度。

### 锁存器为什么能把数据留下来

总线上的数据是不断变化的。如果后级设备需要的是某一时刻的八位数据，就要在总线中间加一级锁存器，把数据暂时留下。

常用的八位锁存器有74LS373和74LS374。373可以理解为内部集成了八组“跟随器加锁存”电路：

- $D_0\sim D_7$是八个数据输入端；
- $Q_0\sim Q_7$是八个数据输出端；
- $\overline{OE}$是输出使能；
- $\overline{LE}$是锁存使能。

早期373的引脚排列不太适合PCB布线。后来厂家把输入端、输出端分别集中到芯片两侧，做出了74LS573。573与373功能相近，但一侧是数据输入端，另一侧是数据输出端，PCB布线方便多了，所以很多用户愿意选573。

### 74LS373的工作过程

先看输出使能$\overline{OE}$。它决定$D$端的数据能不能送到$Q$端。只有输出使能有效，$Q$端才允许输出；输出使能无效时，$Q$端进入高阻状态。

```text
             D0～D7                    Q0～Q7
        ┌────────────┐             ┌────────────┐
        │  数据输入  │───────────> │  三态输出  │
        └────────────┘             └──────┬─────┘
                                          │
                                    输出使能 OE̅
                                  0：允许    1：高阻
```

再看锁存使能$\overline{LE}$。当$\overline{OE}$有效而$\overline{LE}$保持高电平时，输出只跟随输入。某一位$D_i$输入高电平，对应的$Q_i$就输出高电平；$D_i$输入低电平，$Q_i$就输出低电平。八路都是逐位跟随。

当$\overline{LE}$从高电平变成低电平时，数据在下降沿到来时被装入$Q$端并锁住。此后，即使$D$端继续变化，$Q$端也不再跟随。

| 工作条件 | 输出状态 |
| :--- | :--- |
| $\overline{OE}$有效，$\overline{LE}=1$ | $Q$跟随$D$ |
| $\overline{OE}$有效，$\overline{LE}$出现下降沿 | $D$装入$Q$并保持 |
| $\overline{OE}=1$ | $Q$处于高阻状态 |

> **易错点**：一定把使能端、有效电平和动作时刻对应起来。“高电平有效”说的是高电平使电路动作；“输出使能失效”说的是输出进入高阻状态，两者不是一回事。

如果用373设计LED输出端口，我们控制的只是灯亮还是灭，并不是调亮度。设计中常把输出使能端接地，使它始终有效，再通过锁存使能控制数据是否被锁住。

### 74LS374把锁存使能改成时钟

实际设计输出端口时，还经常使用74LS374。373和374都能把$D$端数据送到$Q$端并保持，区别是374把锁存使能端改成了时钟端$CP$。

$CP$保持低电平时，输出可以接收新数据；$CP$出现上升沿时，当前数据被打入$Q$端，并保持到下一次有效时钟沿到来。所以我们经常选374。

```text
 D0～D7 ──> 74LS374 ──> Q0～Q7
              ↑
              │ CP 上升沿锁存
              │
          CPU 或其他时钟源
```

到这里，这些器件就构成了设计中常用的总线缓冲和输出锁存方案，后面看CPU的具体引脚功能。

### 8086的封装、供电与引脚分类

8086 CPU采用双列直插式封装，共40个引脚。引脚看起来很多，但先抓住三类最直观的信号：电源、地、地址与数据。

$V_{CC}$和$GND$是供电引脚。8086的工作电压是$+5\text{ V}$，精度要求为正负百分之十，因此供电范围是$4.5\text{ V}$到$5.5\text{ V}$。

8086有20根地址线，全部用于对外部存储器寻址；因为一条地址线有两种状态，所以一共可以表示

$$
2^{20}=1\text{ MB}
$$

个存储单元。也就是说，8086的20根地址线对应一个$1\text{ MB}$的寻址空间。

### RESET为什么是外部高电平有效

CPU加电以后能不能开始正常工作，和复位信号直接相关。8086的`RESET`引脚需要外部施加高电平才能使CPU复位。

有些资料在引脚名旁画一个横线，有些只写`RESET`，读图时不能只看名字，更不能看见横线就自行改变有效电平。8086的复位信号是由外部加到CPU引脚上的高电平，设备上电后利用这个信号让CPU进入规定状态，复位结束后再进入正常工作状态。

> **易错点**：8086的复位是外部高电平有效，不要因为某些资料的标注习惯或引脚名称写法而判断成低电平有效。

### 用RC网络产生上电复位

高电平从哪里来？最简单的思路是用电阻和电容搭一个上电延时电路。

电容有一个关键特性：电容两端的电压不能突变。刚接入电源时，电容可以看成短路，输出点不会立即跳到$5\text{ V}$，而是随着充电逐渐升高。改变电阻$R$和电容$C$，就能改变充电时间，时间常数为

$$
\tau=RC
$$

利用这个逐渐上升的过程，可以在复位引脚上形成一段高电平。只要这段高电平保持得足够久，CPU就能被复位。

不过，$RC$电路只解决了复位持续时间问题。8086的工作速度由CLK控制，复位信号还必须和CLK同步。上升沿要和时钟上升沿同步，下降沿要和时钟下降沿同步，复位高电平还必须保持规定数量的时钟周期。

> **结论**：8086的复位高电平宽度不得小于四个时钟周期。若一个时钟周期记为$T_{CLK}$，复位高电平宽度至少是$4T_{CLK}$。只知道“高电平有效”还不够，时序要求也必须满足。

### 8284同时产生时钟和同步复位

复位要跟时钟同步，$RC$延时电路自己并不好处理这种配合。为了简化用户设计，Intel研制8086时提供了8284时钟发生器。

8284的$X_1$、$X_2$端可以外接晶体。晶体与芯片内部电路构成振荡环路，产生较高频率的信号。8284内部再进行三分频，从CLK端输出8086所需的时钟信号：

$$
f_{CLK}=\frac{f_{晶振}}{3}
$$

时钟发生器内部还可以用外部条件触发复位。外部请求是低电平有效，进入8284内部以后经过极性转换，最终送到CPU的复位信号是8086所需的高电平有效形式，而且边沿要与CLK同步。

```text
        晶振
      X1 ├──┐
          │  ├── 8284时钟发生器 ── CLK ──> 8086
      X2 ├──┘          │
                       └─ 同步、极性转换 ── RESET ──> 8086
                           ↑
                       外部复位请求
```

> **结论**：8086系列CPU的时钟与复位，应由8284这类专用器件按要求产生，使RESET的上升沿、下降沿和高电平宽度都与CLK配合。

### 上电复位和手动复位怎样配合

上电复位由8284周围的$R$、$C$网络产生，按键则负责手动复位。

手动复位最直接的接法是把按键接在$+5\text{ V}$和地之间。平常按钮断开，按下后把这一端拉到低电平，8284收到低电平有效的复位请求，内部完成极性转换和同步，再向8086送出高电平有效的RESET。松开按键，请求消失，CPU结束复位并开始正常工作。

```text
          +5 V
            │
      ┌─────┴─────┐
      │  RESET按键 │  按下：节点为低电平
      └─────┬─────┘
            │          ┌───────────┐
            └─────────>│ 8284      │── RESET ──> 8086
                       └───────────┘       高电平有效
```

所以，RESET信号要保持足够的宽度，至少覆盖四个时钟周期。$R$、$C$决定上电过程持续多久，8284负责把复位请求变成与CLK同步的有效信号。

### 复位后8086从哪里开始取指

复位作用不只是让CPU停一下。复位过程中，8086内部会规定寄存器状态，结束后进入确定的启动地址，开始执行第一批指令。

8086复位时，指令指针`IP`清零，代码段寄存器`CS`置为`FFFFH`，所以启动时的逻辑地址是

$$
\mathrm{CS:IP}=FFFFH:0000H
$$

8086外部有20根地址线，可以在$1\text{ MB}$空间内寻址。物理地址形成后，复位后的取指地址是

$$
\mathrm{FFFF0H}
$$

这个地址已经很靠近整个$1\text{ MB}$空间的高端，$FFFF0H$到最高地址只剩下很少的字节，用户的正常程序不可能全部塞在那里。

所以，$FFFF0H$处先放的不是一个完整用户程序，而是一条“跳转到别处”的指令，把程序计数器带到有足够空间的位置，再从那里安排真正的用户程序。

```text
1 MB空间最高端
┌──────────────────────┐ FFFFFH
│ 空间已经用完          │
├──────────────────────┤ FFFF0H
│ 启动入口：跳转指令    │──> 跳往有足够空间的程序区
├──────────────────────┤
│                      │
│ 可供用户程序使用      │
│                      │
├──────────────────────┤ 00000H
└──────────────────────┘
```

这个安排一定要理解：从启动地址向下直接放用户程序，装不下；先跳到下面空间宽裕的位置，用户程序才有地方继续安排。

作为对照，5U系列CPU上电后，程序计数器`PC`从零开始，因此会从零地址附近取指。8086为什么要“跳一下”，根源就是它的启动逻辑地址`FFFFH:0000H`对应物理地址`FFFF0H`，位置太靠后，留给用户程序的空间不够。

### 这部分最容易考什么

考简答题时，答清RESET是高电平有效，并且高电平宽度不得小于四个时钟周期，一般就抓住了核心。

考填空题时，经常让你填8086复位后`CS`、`IP`的值：

```text
CS = FFFFH
IP = 0000H
启动逻辑地址 = FFFFH:0000H
启动物理地址 = FFFF0H
```

这些数据不要死记成一句孤立的结论。把“`IP`清零、`CS`置`FFFFH`、形成`FFFF0H`启动地址、顶端放跳转指令”这条因果链串起来，才不容易填错。

## 8086的时钟节拍、工作方式与总线形成
> 对应块：BLK38 | 覆盖分集：P73-P74 | 块标题（分集名）：《73》

8086的工作时钟不能超过5 MHz。刚接触8086时，这个数字听上去实在低得有点让人意外：现在双核CPU已经是几个GHz的速度，8086却连5 MHz都过不去。但8086并不是“算得慢”，而是把工作节拍、总线时序和工作方式一开始就定清楚了。后来从80186的8 MHz、80386的33 MHz，到80486的66 MHz乃至80 MHz，频率才一步步往上走；今天的双核、多核，也只是把这套时间尺度继续往前推进罢了。

早期PC机大量使用的是8088。8088的工作频率取4.77 MHz，讲师还专门推算过这个数字：串行通信每经过一段时间就会积累一点误差，而取4.77 MHz时，积累下来的误差最小。国内在8086之后引进80186时，186这一段也曾经出现过断档。历史背景先放在这里，真正要抓住的是下面这件事：任何CPU的工作速度，都以时钟周期作为最小节拍。对8086来说，最小的节拍就是`CLK`的一个周期。

复习时别忘了复位这条底线。`RESET`是高电平有效信号，它的有效宽度至少要保持4个时钟周期；复位结束后，`CS=FFFFH`、`IP=0000H`，所以8086的启动地址是`FFFF0H`。这几个量是联系在一起的：复位把内部状态拉回确定的起点，指令指针从零开始，代码入口便落在`FFFF0H`。

### 一个基本总线周期到底怎么走

CPU执行一条指令时，如果这条指令要访问外部存储器，或者要从外部I/O端口读写数据，就会用到外部总线。CPU为了完成这次外部传送而占用总线的时间，就叫作总线周期。这里要分清：不是所有指令都需要一个完整的外部总线周期，只有涉及外部读写的指令，才把总线拉出来用一用。

8086以`CLK`下降沿作为同步节拍。一条基本的总线周期由四个状态组成，也就是`T1`、`T2`、`T3`和`T4`。最基本的时序如下：

```text
CLK节拍       |  T1  |  T2  |  T3  |  T4  |
外部总线占用  |-----------------------|
总线内容      | 地址 | 数据/数据准备阶段 |
基本总线周期完成                              ^

需要等待时：
CLK节拍       |  T1  |  T2  |  T3  |  Tw  |  T4  |
外部总线占用  |------------------------------------|
```

从`T1`开始，CPU先送出访问对象的地址；到了`T2`，地址线开始让位给数据，数据经过准备和建立过程；在`T3`附近，数据交换完成；最后经过`T4`，一个总线周期结束，进入下一条指令的总线周期。

基本周期之外，还有等待周期`Tw`。当外部设备比较慢，或者CPU执行`IN`、`OUT`这类需要和I/O端口配合的指令时，CPU不能按照理想速度把数据取回来，就要在`T3`结束后插入`Tw`，等外部设备真正准备好，再进入`T4`。这里要注意：等待周期不是凭感觉加上去的，它要和外部的就绪信号配合，告诉CPU“现在还不能继续”。

> **结论**：8086的节拍关系可以先记成“`CLK`给出节拍，`T1~T4`完成一次基本总线周期，`Tw`用来等待慢速设备”。画时序时，不要只盯着某一个脉冲，还要看这个脉冲落在哪一个状态里。

### 最小方式和最大方式：同一个CPU的两副面孔

8086有一个专门选择工作方式的引脚：`MN/MX#`。这个引脚接高电平时，8086工作在最小方式；接低电平时，8086工作在最大方式。名字里的“最小”和“最大”，说的是系统组织方式，并不是说CPU的运算能力一会儿小、一会儿大。

在最小方式下，8086自己直接产生对存储器和I/O端口的读写控制信号。CPU引脚上的控制线直接接到外部系统，结构比较简单，适合构成单处理器系统。你可以把最小方式理解为：8086自己既当CPU，又负责把总线控制信号直接发出去。

在最大方式下，8086不再独自完成所有总线控制。它把总线操作的状态编码交给外部的总线控制器，再由这个控制器产生具体的读写控制信号。最大方式适合多处理器系统，因为系统中不止一个处理器，需要把总线使用权、管线和优先级等事情交给更完整的总线控制机构来处理。

两种方式下，8086的同一组引脚会承担不同功能。以图5.5中第24脚到第31脚为例，最小方式时，它们体现为8086直接输出控制信号；切换到最大方式后，其中一部分引脚改为输出总线状态，供外部8288总线控制器译码。引脚没有换，身份换了。

```text
最小方式：

                    8086
          控制信号 │  │ 地址/数据
                 ▼  ▼
             存储器 / I/O端口

最大方式：

       8086                         8288总线控制器
  地址/数据、S2 S1 S0状态   ───►   译码
                                    │
                       存储器/I/O控制 │ 控制信号
                                    ▼
                                存储器 / I/O端口
```

#### 最小方式：控制信号直接出CPU

最小方式下，CPU要向外部存储器写数据，或者向I/O端口写数据时，8086可以直接输出相应的写控制信号。读操作则由最小方式下的总线控制安排来完成。关键不在于死记某一个引脚名字，而在于先把这条逻辑链抓住：

```text
8086确定访问对象
        ↓
8086确定是读还是写
        ↓
8086直接给出总线控制信号
        ↓
存储器和I/O端口响应
```

这也就是为什么最小方式很适合单处理器系统：系统里没有别的处理器来和CPU争抢总线，CPU可以直接掌握总线的节奏。

#### 最大方式：让8288替CPU发号施令

最大方式下，8086会输出三位状态信号`S2`、`S1`和`S0`。这三根线不是数据线，而是告诉外部控制器“CPU现在准备做什么”。状态编码从`000`到`111`有多种组合，8288接收这些编码，再经过内部译码器译码，最后从自己的输出端产生对应的存储器或I/O控制信号。

例如，CPU从存储器读数据时，输出状态组合是`101`；8288识别这个状态后，使存储器读控制信号`MRDC#`有效，通知外部存储器：“现在可以向总线送数据了。”CPU向存储器写数据时，状态组合为`110`，8288使`MWTC#`有效，通知存储器接收数据。

| CPU进行的操作 | 状态组合 | 8288产生的控制信号 | 有效时告诉外部设备什么 |
| :--- | :--- | :--- | :--- |
| 从存储器读 | `101` | `MRDC#` | 存储器向CPU送出数据 |
| 向存储器写 | `110` | `MWTC#` | 存储器接收CPU送来的数据 |
| 从I/O端口读 | `001` | `IORC#` | I/O端口向CPU送出数据 |
| 向I/O端口写 | 由状态编码识别 | `IOWC#` | I/O端口接收CPU送来的数据 |

表中的几个控制信号都是低电平有效。名称里的`C`可以把它理解成control，也就是控制信号；前面的`MR`、`MW`、`IOR`、`IOW`分别说明访问对象和读写方向。

所以，8288的工作过程可以概括为三步：先接收8086送来的三位状态码，再在内部译码，最后产生最终的系统控制信号。最大方式的关键不是“8086不工作了”，而是8086把总线命令先说给8288听，8288再把它翻译成存储器、I/O端口真正能听懂的控制信号。

> **易错点**：不要把`S2`、`S1`、`S0`当成地址或数据。它们是状态编码，8288正是根据这些编码决定当前应该读存储器、写存储器，还是读写I/O。

### 多处理器系统为什么需要总线仲裁

最小方式适合单处理器系统；最大方式则适合多处理器系统。多处理器系统里，除了8086以外，还有其他处理器。系统只有一套数据总线和一套总线控制，不能让两个处理器同时驱动同一根线。

这就必须回答一个非常实际的问题：现在到底是哪一个处理器在使用总线？

当8086之外的处理器也要使用总线时，它必须先向8086提出总线请求。8086检查自己的当前状态，确认可以把总线让出来以后，再向外部处理器作出响应。外部处理器得到授权，才能接管总线，并对挂在总线上的存储器和I/O端口进行读写管理。

```text
外部处理器          8086                 存储器 / I/O
    │                │                         │
    ├── 请求总线 ───►│                         │
    │                │ 当前总线操作完成        │
    │◄── 允许接管 ───┤                         │
    │                │ 总线输出呈高阻态         │
    ├──── 接管总线并驱动控制信号 ─────────────►│
```

CPU把总线让出去，不等于“CPU坏了”，也不等于把引脚拉成低电平。关键状态是高阻态：8086暂时放弃驱动总线，让外部处理器能够安全地接管。`RQ/GT0#`、`RQ/GT1#`这类请求和响应信号，围绕的就是总线使用权的交接；`LOCK#`则用来表达总线被锁住时不能被随意打断的状态。

这也是最小方式和最大方式分界的地方之一。最小方式中，8086自己直接发控制，系统相对简单；最大方式中，总线控制有了更完整的组织，才能容纳其他处理器来竞争和接管总线。

### 同一根线怎么既送地址又送数据

8086的地址和数据线采用了复用方式。你看到的那16根线，并不永远只承担地址，也不永远只承担数据；在不同总线状态里，它们会“换脸”。这也是后面设计总线形成电路时必须掌握的地方。

#### AD0~AD15：一根线两种身份

8086的`AD0~AD15`是16根复用引脚。在总线周期的`T1`状态，它们输出`A0~A15`，也就是16位地址；从`T2`到`T4`，这16根线改为数据引脚，传输`D0~D15`。所以，不能把这16根线从芯片引出来以后，就一直把它们当作固定的地址线或固定的数据线。

如果只传送8位数据，则不一定使用全部16根数据线。使用低8位`D0~D7`还是高8位`D8~D15`，要看被访问对象所在地址的奇偶性。偶地址和奇地址对应的高、低字节选择不同，不能把8位数据传送简单理解成“从低8位随便取”。

一个总线周期中，同一组引脚大致经历这样的身份转换：

```text
T1状态：       AD0~AD15  = A0~A15       输出地址
T2~T4状态：    AD0~AD15  = D0~D15       传输数据
下一个T1：     AD0~AD15  = A0~A15       又变回地址
```

这就是“复用”的真正含义：不是一根线上同时跑两种完全不同的信息，而是利用不同的时间片，把有限的引脚数省下来。

#### A16/S3~A19/S6：高四位地址和状态

除了`AD0~AD15`这16根复用线，8086还有4根更高位地址复用线：`A16/S3`、`A17/S4`、`A18/S5`和`A19/S6`。这4根线在`T1`状态输出的是`A16~A19`，也就是20位地址中的高4位；从`T2`到`T4`，它们改为输出状态信号`S3~S6`。

状态信号并不是没有用。`S6`始终为低电平，实际中没有发挥作用；`S5`辅助反映CPU内部`IF`的状态；`S4`和`S3`两个状态的组合，则反映CPU当前使用的是哪个段寄存器、正在哪个段内进行操作。理解这组信号时，先把它们和20位地址总线区分开：`T1`时是地址高4位，`T2~T4`时是状态。

### ALE与74LS373：把T1地址留下来

地址只在`T1`状态出现，CPU进入`T2`后，复用引脚就要改传数据。如果外部系统想把20位地址在整个总线周期内都保留下来，就必须在`T1`时把地址锁存起来。8086为此提供了`ALE`地址锁存允许信号。

`ALE`平时是低电平；进入`T1`状态后，它变高；当`T1`快结束时，`ALE`变回低电平。利用`ALE`从高到低的下降沿，可以把20根复用引脚上的地址信息锁存到外部寄存器中。ALE锁存以后，CPU的`AD0~AD15`可以在`T2~T4`改为数据，外部系统却仍然能使用刚才保存下来的完整地址。

8086的20位地址需要三片8位锁存器。`AD0~AD7`送入第一片，`AD8~AD15`送入第二片，`A16/S3~A19/S6`送入第三片。锁存器的输出端合起来，就是系统级的20位地址总线：

```text
                         ALE
                          │
AD0~AD7 ─────────►┌──────────────┐
                  │ 74LS373 #1   │────► A0~A7
                  │   地址锁存     │
AD8~AD15 ────────►┌──────────────┐
                  │ 74LS373 #2   │────► A8~A15
                  │   地址锁存     │
A16/S3~A19/S6 ───►┌──────────────┐
                  │ 74LS373 #3   │────► A16~A19
                  │   地址锁存     │
                  └──────────────┘
                      OE#接有效

锁存器输出合起来：A0~A19
```

这里的关键是：锁存器不是永远跟着输入变化。`ALE`处于有效状态时，锁存器输出跟随输入；当`ALE`出现下降沿，刚才的地址就被锁住。于是，在`T2~T4`期间，即使CPU已经把这20根复用引脚切换成数据和状态，锁存器输出的系统地址仍然保持不变。

> **设计要点**：地址总线形成电路的设计，第一步要了解复用引脚在什么状态输出地址；第二步要认出`ALE`的锁存时刻；第三步才是用锁存器把地址真正保存下来。三片74LS373组成的20位地址总线，是这个环节必须掌握的画法。

### 数据总线为什么还要方向和有效信号

地址总线形成电路解决的是“地址别丢”，数据总线形成电路解决的是“数据往哪儿走、什么时候可以取”。8086的数据线是双向的，CPU可能把数据送给存储器，也可能从存储器收回数据。因此，除了数据本身，还必须有控制信号告诉外部电路：现在是发送还是接收，数据什么时候真正有效。

#### DT/R：先问数据往哪儿走

`DT/R`是数据传输方向控制信号。CPU向外部发送数据时，`DT/R`为高电平；CPU从外部接收数据时，`DT/R`为低电平。

比如CPU把AX中的16位数据写入存储单元，数据方向是CPU到存储器，`DT/R`就应该表示发送；如果CPU执行读操作，从存储器读回数据，数据方向就是存储器到CPU，`DT/R`应该表示接收。

```text
CPU向存储器写：

CPU  ─────数据────►  存储器
              DT/R = 1

CPU从存储器读：

存储器  ─────数据────►  CPU
              DT/R = 0
```

在一条指令的`T1`开始前，`DT/R`原来是什么电平，不能凭上一条指令去猜，必须看当前指令到底是读还是写。这个引脚告诉双向缓冲器：现在数据应该从哪一侧送到哪一侧。

#### DEN#：没有有效就别急着取

`DEN#`是数据有效信号，低电平有效。它把数据总线上“数据已经准备好”和“地址还在占用这些引脚”这两个阶段区分开。

`AD0~AD15`在`T1`里传的是地址，进入`T2`后要改成数据，因此中间存在一个地址到数据的过渡阶段。这个过渡阶段里，线上的电平既不能当成稳定地址，也不能当成有效数据。`DEN#`用低电平把有效数据阶段标出来，外部电路就应该在`DEN#`有效的期间读取或送出数据。

```text
数据线上的信息：

T1             T2过渡          T2后半段~T4          T4末
地址有效   →   无效过渡   →   数据有效             数据撤除
             不要取       可以取
                         DEN# = 0
```

所以，设计电路时不能只看“AD线现在有电平”就立即输出数据。必须同时看数据方向和数据有效时序，否则很容易把过渡阶段的残留电平当成真正的数据。

#### M/IO#与读写控制：先确定访问对象

`M/IO#`用来区分当前访问的是存储器还是I/O端口。访问存储器时，它输出高电平；访问I/O端口时，它输出低电平。这个信号解决的是“访问对象是谁”的问题，`DT/R`解决的是“数据往哪个方向走”的问题，`DEN#`解决的则是“数据现在能不能取”的问题，三者不能混为一谈。

在最小方式下，CPU还需要给出相应的写控制。写控制的时序不能随意提前或滞后：当数据线上的数据还没有有效时，不能因为控制线一动就把一次写操作误判为完成。按照时序要求，CPU要在数据有效条件建立之后再完成写控制；严格的时序图会给出具体的时间间隔，课堂讲解时先把“谁先谁后”和“什么时候取数据”说清楚。

从存储器读时，过程正好要反过来考虑。CPU先把读操作安排好，等外部存储器把数据送到复用线上，并且在`DEN#`有效、数据已经稳定之后，再把数据接收进寄存器。写时是CPU准备数据后给出写控制，读时是控制先安排、数据到达后再取。

### 把写和读的时序连起来看

下面只画时序的骨架，重点看信号之间的先后关系，不能把它当成替代完整数据手册的每一个纳秒参数。

CPU向存储器写数据时，大致关系如下：

```text
状态          T1          T2             T3             T4
CLK节拍       |-----------|---------------|---------------|
AD0~AD15      地址输出 ──► 数据准备 ─────► 数据有效 ─────►
ALE           ____高电平____低电平______________________
M/IO#         -----------------高电平----------------------
DT/R          -----------------高电平----------------------
DEN#          -------------低电平--------------------------
WR#           -------------------写控制脉冲--------------->
```

写操作的关键是：先确定要写到哪里，再准备数据，等数据通路有效后给出写控制。数据还在无效过渡阶段时，外部器件不能被当作已经收到了正确的写入内容。

CPU从存储器读数据时，关系变成：

```text
状态          T1          T2             T3             T4
CLK节拍       |-----------|---------------|---------------|
AD0~AD15      地址输出 ──► 接收准备 ────► 读回数据 ─────►
ALE           ____高电平____低电平______________________
M/IO#         -----------------高电平----------------------
DT/R          -----------------低电平----------------------
DEN#          -------------低电平--------------------------
读控制        -------------先建立，等数据稳定后再采样---->
```

这里的“反过来”不是把写控制简单改名就结束了，而是数据方向、有效时机和采样时机都要跟着改变。读操作中，外部设备把数据送上来；写操作中，CPU把数据送出去。设计电路时，任何一个环节没有配合，都会导致数据被错误输出或错误输入。

### 地址总线、数据总线和控制信号合流

把前面的内容压成一条线，8086的系统总线形成就清楚了：

```text
CLK
  │
  ▼
T1：AD0~AD15输出A0~A15，A16/S3~A19/S6输出A16~A19
  │                  │
  │                  └── ALE下降沿锁存到三片74LS373
  │                                  │
  │                                  ▼
  │                         系统地址总线A0~A19
  ▼
T2~T4：复用引脚改传D0~D15或S3~S6
  │
  ├── DT/R：决定发送还是接收
  ├── DEN#：决定数据什么时候有效
  ├── M/IO#：决定访问存储器还是I/O
  └── 最小方式直接控制 / 最大方式由8288译码产生控制
```

因此，8086的总线形成电路并不是一块神秘的“大芯片”。它可以拆成三部分：复用引脚先按时序送出地址，`ALE`配合74LS373把地址锁住，地址总线稳定之后，再由双向数据缓冲器和读写控制信号完成数据传送。

系统数据总线通常用8位双向缓冲器扩展。8086有16根数据线，因此需要两片74LS245：一侧接8086的`AD0~AD15`，另一侧接系统数据总线。`DT/R`接到缓冲器的方向控制端，决定数据从CPU侧送到外设侧，还是从外设侧送回CPU。

```text
                    DT/R
                     │
                     ▼
AD0~AD7 ─────►┌──────────────┐
               │ 74LS245 #1   │────► 系统D0~D7
               │ 双向数据缓冲  │◄────
               └──────────────┘
AD8~AD15 ────►┌──────────────┐
               │ 74LS245 #2   │────► 系统D8~D15
               │ 双向数据缓冲  │◄────
               └──────────────┘
```

地址锁存、数据缓冲和读写控制合在一起，才构成完整的总线形成电路。地址总线的重点是“锁定”，数据总线的重点是“方向和有效”，控制信号的重点是“访问对象和读写动作”。三组信号看起来交错在一起，实际上各自解决一个不同的问题。

### 真正要记住的，是时序中的“换脸”

8086的这批引脚，真正容易混淆的地方不在于它们名字多，而在于同一个引脚会在不同状态下改变身份。`AD0~AD15`在`T1`是地址，在`T2~T4`是数据；`A16/S3~A19/S6`在`T1`是高4位地址，后面变成状态；`ALE`只在需要抓住`T1`地址的时候发挥作用；`DEN#`低电平才表示数据有效；`DT/R`决定方向；`M/IO#`决定访问的是存储器还是I/O；最大方式下，8288再把状态码译成最终的读写控制信号。

还有一个非常容易丢分的地方：外部电路不能在地址刚变成数据、但数据还没有稳定的过渡时刻取数。`T1`阶段先看地址，`T2`开始进入准备，`DEN#`有效后再认数据，到了`T4`再结束这一轮。慢速外设来不及响应，就插入`Tw`；多处理器要使用总线，就通过请求和响应完成交接。掌握这些关系，才算真正把8086的引脚和时序串起来了。

> **结论**：先看`CLK`节拍，再看`T1~T4`和`Tw`；先判工作方式，再判谁产生控制信号；先在`T1`锁存地址，再在`T2~T4`按方向和有效时序传送数据。抓住这条主线，8086的总线引脚就不再是一堆需要死记的名字。

> **承前启后**：上一节讲完「8086的时钟节拍、工作方式与总线形成」，下一节接着讲「8086 十六位系统总线与最小模式控制」。

## 8086 十六位系统总线与最小模式控制
> 对应块：BLK39 | 覆盖分集：P75-P76 | 块标题（分集名）：《75》

先别急着一把线拉到底。纸上手绘原理图时，十几根线从左边横穿到右边，看起来可能还挺清楚；可一放进 EDA 软件，准备仿真、转成 PCB，八根线立刻缠成一团。软件根本不知道你心里以为“这根接那根”，最后画出来的电路只能像蜘蛛网。

所以，十六位系统总线不是靠把线硬拉长形成的。真正要解决的是两件事：先让 8086 的数据引脚形成一条公共的系统数据总线，再用控制信号把这根总线管住。该通时通，该断时断；该送出去时送出去，该收回来时收回来。线路接上以后，还要看 CPU 和慢速设备在时间上能不能配合，最后再处理高字节存储体和奇偶地址的选择问题。

### 让八根数据线汇成十六位系统总线

8086 外部有一组复用的地址、数据引脚。`AD0～AD7` 在传送数据时对应低八位，`AD8～AD15` 在传送数据时对应高八位。我们先只看数据传送这一面，不把地址阶段和数据阶段混在一起。

按第 5.1 节的总线分类来想，微处理器内部各部分之间的连接属于片内总线；本块要搭出来的是微处理器与外部部件之间的系统总线，具体形成其中的系统数据总线。它不是 CPU 芯片内部的一条短线，而是给存储器、I/O 接口等部件共同使用的一条信息通道。

为什么不在 `AD0～AD15` 外面直接挂上所有支路？微处理器体积小，引脚数量有限，不可能为每一条外部支路再设计一个驱动放大器；引脚本身带负载的能力也弱。若把各条线路直接捆在一起，一条支路的变化会牵动其他支路，信号驱动能力也不足。外部双向缓冲器有两个作用：第一，把不同支路隔开，让各条支路使用各自专用的线路；第二，经过放大器恢复驱动能力，让总线能够带动后面的负载。

因此，74LS245 不是可有可无的“中转站”。低八位用一片，高八位再用一片，两片合起来才形成完整的十六位系统数据总线。

```text
8086 侧                                      系统数据总线侧
AD0..AD7   <====> [ 74LS245 低字节 ] <====> DB0..DB7
AD8..AD15  <====> [ 74LS245 高字节 ] <====> DB8..DB15
                              |       |
                              +-- DIR：决定数据方向
                              +-- /OE：决定缓冲器是否导通
```

这里的 A 侧可以理解为 CPU 这一侧，B 侧就是系统数据总线这一侧。低字节的 `AD0～AD7` 对应 `DB0～DB7`，高字节的 `AD8～AD15` 对应 `DB8～DB15`；不要把高八位误接成低八位，也不要只接一片就以为十六位总线已经完成。

> **定义**：系统数据总线是连接微处理器、存储器和 I/O 等部件、供它们交换数据的公共信息通道。

### 原理图靠网络名，而不是靠一根长线

手绘草图时，可以把一整束线直接拉过去；可是画完电路还要仿真、转成 PCB，工具就不会猜你心里想的是哪根线和哪根线相连。若八个引脚都横跨到另一端，电路会像蜘蛛网，别人也很难维护。

工程原理图要让每个引脚都接上同一个电气网络名。CPU 一侧的八根线标成 `AD0～AD7`，另一侧对应的线也标成 `AD0～AD7`，即使纸面上相隔很远，原理图软件和 PCB 工具也会按同名网络判断它们导通。系统一侧再把它标成 `DB0～DB7`；高八位一侧则标成 `DB8～DB15`，读图的人一眼就知道这里走的是哪一组数据线。

```text
CPU 一侧：      AD0  AD1  AD2  AD3  AD4  AD5  AD6  AD7
                  |    |    |    |    |    |    |    |
系统一侧：      DB0  DB1  DB2  DB3  DB4  DB5  DB6  DB7

相同网络名表示电气连通，纸面距离不表示断开。
```

地址最低位记作 `A0`；在地址、数据复用引脚的图上，它又对应 `AD0`。这两个名字不是让软件去猜的：地址阶段看地址，锁存之后得到系统地址 `A0`，数据阶段则看相应的数据线。把 `A0`、`AD0` 和 `D0` 放在同一条链路上理解，才能明白为什么地址形成电路、数据形成电路要分别处理。

画图时还要尽量把同功能的器件放在同一块。数据总线形成电路可以用一个虚线框圈起来，地址形成电路、A/D 转换电路也可以分别圈出模块名称。虚线框不是电气连线，它只是告诉读图人：这一块电路完成什么功能。框内写清模块名，别人接手时就不必重新猜每个引脚的用途。

控制信号也一样。`DEN#`、`DT/R` 这类线如果拉得很长，就在网络线上标出名字，不要把标记只放在一个不便查找的角落；PCB 制图时，工具会根据网络名完成连接。网络名标清楚，原理图就会从“自己能看懂”变成“别人也能维护”。

> **提示**：同名电气网络在原理图和 PCB 中被视为导通，但两条线在纸面上画得远不等于它们不相连。真正要避免的是没有网络名、只靠视觉猜测的画法。

### 让 74LS245 管住方向与使能

数据线接到系统总线以后，还不能让它一直导通。74LS245 要解决两个问题：现在允不允许数据通过？数据究竟向哪个方向走？

第一个控制量是 `/OE`，也就是输出使能端，低电平有效。8086 的 `DEN#` 是数据有效信号，低电平时才表示当前确实要传送数据。因此把 `DEN#` 接到 74LS245 的 `/OE` 端：`DEN#=1` 时关闭缓冲器；`DEN#=0` 时才允许数据通过。只有在数据线上的数据有效时，才打开数据通路，不能把地址阶段误当成一次数据传送。

第二个控制量是方向控制端 `DIR`，接 8086 的 `DT/R`。`DT/R` 为发送状态时，CPU 从 A 侧把数据送到 B 侧，也就是 CPU 向系统数据总线、存储器和 I/O 接口发送；`DT/R` 为接收状态时，数据从 B 侧回到 A 侧，也就是外部把数据送回 CPU。

```text
DEN# = 1：/OE 无效，74LS245 关闭

DEN# = 0，DT/R = 1：A 侧 ----> B 侧，CPU 发送数据

DEN# = 0，DT/R = 0：A 侧 <---- B 侧，CPU 接收数据
```

| 状态 | `DEN#` | `DT/R` | 74LS245 的行为 |
| :--- | :---: | :---: | :--- |
| 不传送数据 | 1 | 不起作用 | 关闭，数据线不导通 |
| CPU 向外写 | 0 | 1 | A 侧到 B 侧 |
| CPU 从外部读 | 0 | 0 | B 侧到 A 侧 |

这样，数据通路和时序控制就分开了：数据线负责走过去，`DIR` 决定往哪边走，`/OE` 决定现在能不能走。74LS245 在这里是“受控的双向门”，不是一根永远短路的导线。

### READY 与 Tw：给慢速设备留时间

线路打通以后，另一个现实问题马上出现了：CPU 很快，存储器和某些 I/O 设备却未必能在一个标准总线周期内准备好。CPU 不能只管发命令、固定时间收结果，否则稍慢的设备就会来不及响应。

8086 设置了 `READY` 输入。第 167 页的说明里，它就是“准备好信号”：外部存储器、I/O 电路或 I/O 设备把准备状态送给 CPU。CPU 在执行存储器读写或 `IN`、`OUT` 等 I/O 读写时，会在总线周期的相应状态检查这个信号。

一个基本总线周期由 `T1、T2、T3、T4` 组成。若在 `T3` 的时钟下降沿检查到 `READY=0`，CPU 不进入 `T4`，而是在 `T3` 和 `T4` 之间插入等待状态 `Tw`。到了每个 `Tw` 的时钟下降沿，CPU 再次检查；仍为 0，就继续插入一个 `Tw`；只有读到 1，才进入 `T4`，结束当前总线周期。

```text
时间向右 ───────────────────────────────────────────────>

总线状态：    T1       T2       T3       Tw       Tw       T4
                         检查             检查      检查
READY：                    0         0         1
                         未准备好    继续等待    可以结束
```

这里的关键不是“固定等几个时钟”，而是把等待状态按设备速度动态插入。设备慢，就多等几个 `Tw`；设备随时准备好，就可以不插入等待状态。这个过程实际上就是用 `READY` 在快速 CPU 与慢速设备之间进行速度同步。

> **易错点**：第一次检查到 `READY=0` 不是让本次传送失败，而是告诉 CPU“这个设备还没准备好，先别结束周期”。`Tw` 的数量取决于外部设备，不是固定写死的。

#### 8284A 为什么要夹在中间

外部存储器或 I/O 设备产生的准备信号，不一定能恰好在 8086 需要的时钟下降沿到来。8086 内部采用的是同步电路，如果直接接收不同步的外部信号，内部判断就可能不可靠。

因此，外部设备产生的 `RDY` 先送入 8284A。8284A 是系统里配合使用的时钟发生器和同步处理电路，它把 `RDY` 的变化安排到时钟下降沿，再从 `READY` 端送给 8086。第 174 页的图 5-15 展示的就是这条处理路径。

```text
存储器 / I/O 设备
        │  RDY
        ▼
     8284A ── 同步到时钟下降沿 ──> READY ──> 8086
        ▲
        │
      系统时钟
```

这里要说清楚信号的来龙去脉：设备侧产生的是 `RDY`，8284A 处理后输出的是给 CPU 使用的 `READY`。不要把两个名字在不同位置机械替换；它们处在设备侧和 CPU 侧，作用是同一个“准备状态”链路。

除了 `READY`，8086 还有 `/TEST` 输入，执行外部等待指令时可以配合使用。执行等待操作时，CPU 每隔五个时钟周期检查一次 `/TEST`；如果测到高电平，就认为设备尚未准备好，再过五个时钟继续检查；直到测到 `/TEST=0`，才退出等待，继续执行后续指令。这种方式同样能实现快速 CPU 与慢速设备之间的速度同步，但实际系统中更常用的是 `READY`。

### BHE# 在 T1 出现，为什么要锁存

接下来是容易被漏掉的第 13 脚。8086 最小方式下，`BHE#/S7` 是一个输出引脚，不过它在同一个物理引脚上承担了两种功能：总线周期的 `T1` 状态输出 `BHE#`，进入后续状态后改为输出状态信息 `S7`。

`BHE#` 的意思是“高字节允许”，低电平有效。十六位数据总线的高字节是 `D15～D8`，因此当一次传送需要访问高字节存储体时，就由 `BHE#` 给出低电平。它不是普通的数据线，也不是一个可以在整个周期中一直自然保持的状态量。

```text
同一个引脚 BHE#/S7：

T1       ：输出 BHE#，低电平表示允许高字节
T2～T4   ：改作 S7 状态输出
```

问题就来了：`BHE#` 在 `T1` 给出，地址形成电路却不能只抓住这一个瞬间。为了让外部译码在整个传送周期都使用稳定的高字节允许信号，必须像锁存地址一样，用 `ALE` 把 `BHE#` 锁存下来。第 174 页图 5-14 所示的 8086 最小方式系统总线结构中，用三片 74LS373 锁存地址相关信号，形成 `A19～A0` 的二十位系统地址总线，同时也把 `BHE#` 锁存下来。

```text
8086 地址/数据相关复用引脚 ──ALE──> 74LS373 ──> A19..A0
8086 BHE#/S7              ──ALE──> 74LS373 ──> /BHE
```

为什么要和地址一起锁存？因为地址和 `BHE#` 要共同决定“这次访问哪一个存储体、哪一个字节”。如果只锁存地址而不锁存 `BHE#`，后面译码时看到的电平就可能已经变成 `S7`，高字节选择也就失去依据。

> **结论**：`BHE#` 只在 `T1` 输出，必须经锁存后才能和稳定的系统地址一起参与外部译码。

### 奇偶存储体如何对应字操作

有了十六位数据总线，并不意味着每个存储单元都直接接十六根数据线。8086 的一个 16 位字由两个字节组成，低字节走 `D7～D0`，高字节走 `D15～D8`。为了让对准的字操作在一个总线周期内完成，外部存储器通常按偶地址和奇地址拆成两个存储体。

从 CPU 看到的地址仍然是连续的：第一个字节、第二个字节、第三个字节依次排列。只是在外部实现时，偶地址字节和奇地址字节分别放进两个存储体。

```text
                 公共高位地址与片选译码
                      /            \
                     /              \
          +----------------+  +----------------+
          | 偶地址存储体   |  | 奇地址存储体   |
          | 保存低字节     |  | 保存高字节     |
          | A0=0 时选中    |  | BHE#=0 时选中  |
          +-------+--------+  +--------+-------+
                  |                    |
                D7..D0              D15..D8
```

偶地址存储体接低八位数据线，保存字的低字节；奇地址存储体接高八位数据线，保存字的高字节。两个存储体的高位地址和片选译码相同，区别在于低位地址和高字节允许条件。

#### 字节操作

访问偶地址的一个字节时：

$$
A0=0,\qquad \overline{BHE}=1
$$

`A0=0` 选中偶地址存储体，8 位数据走 `D0～D7`，一个总线周期完成。

访问奇地址的一个字节时：

$$
A0=1,\qquad \overline{BHE}=0
$$

`A0=1` 表示当前是奇地址，`BHE#=0` 使高字节存储体有效，8 位数据走 `D8～D15`，同样一个总线周期完成。

| 访问对象 | `A0` | `BHE#` | 选中的存储体 | 数据通路 | 总线周期数 |
| :--- | :---: | :---: | :--- | :--- | :---: |
| 偶地址字节 | 0 | 1 | 偶地址存储体 | `D0～D7` | 1 |
| 奇地址字节 | 1 | 0 | 奇地址存储体 | `D8～D15` | 1 |

这里不能偷懒地认为“程序有时只做字节操作，所以高字节存储体只用 `A0` 选就行”。程序可能改为字操作，不能靠当前这一次字节操作来保证电路永远适用。高字节存储体的选通条件必须加入 `BHE#=0`。

#### 对准的字操作

若一个字的起始地址是偶数，例如从 `2000H` 开始，那么 `2000H` 是偶地址，保存低字节 `AL`；`2001H` 是紧邻的奇地址，保存高字节 `AH`。

```text
偏移地址：    2000H             2001H
存储位置：    偶地址体           奇地址体
数据内容：    AL                 AH
数据通路：    D7..D0             D15..D8
```

同一个总线周期内，`A0=0`、`BHE#=0`：`A0=0` 选中偶地址存储体，`BHE#=0` 选中高字节存储体。`AL` 走低八位数据线，`AH` 走高八位数据线，两部分并行传送，一个总线周期写完整个 `AX`。

```text
一个总线周期：
A0 = 0，BHE# = 0
偶地址体 ---- 低八位数据线 ----> AL
奇地址体 ---- 高八位数据线 ----> AH
```

这里有一个很容易被问到的矛盾：既然高字节放在奇地址，为什么不直接用 `A0=1` 来选奇地址存储体？因为对准字从 `2000H` 开始时，当前地址的 `A0` 必须是 0；同一个时钟下不可能让 `A0` 既等于 0 又等于 1。若高字节体依赖 `A0=1`，对准字的两个存储体就不能同时有效。`BHE#` 正是为了让高字节存储体不依赖当前地址的 `A0`，从而实现两个存储体同时被选中。

> **结论**：对准的字操作需要 `A0=0` 与 `BHE#=0` 同时成立，偶地址体传低字节，奇地址体传高字节，两条数据通路并行工作。

#### 未对准的字操作

若字操作从奇地址开始，例如偏移地址为 `2001H`，这个字的两个字节就不能在同一个周期里通过奇、偶两个存储体完成。`2001H` 是奇地址，先放高字节 `AH`；`2002H` 是下一个偶地址，放低字节 `AL`。

```text
第一个总线周期：2001H <- AH
                 A0=1，BHE#=0
                 选中奇地址体，AH 走 D15..D8

第二个总线周期：2002H <- AL
                 A0=0，BHE#=1
                 选中偶地址体，AL 走 D7..D0
```

因此，未对准的字读写必须用两个总线周期。第一个总线周期访问奇地址、传送高字节；第二个总线周期转到下一个偶地址、传送低字节。读操作和写操作遵循同一套地址与数据通路规则。

这就是第 168 页表 5.2 最重要的读法：不要只看“读还是写”，还要同时看 `A0` 和 `BHE#` 的组合。

| 操作 | 周期 | `A0` | `BHE#` | 数据通路 | 结果 |
| :--- | :---: | :---: | :---: | :--- | :--- |
| 偶地址字节 | 1 | 0 | 1 | `D0～D7` | 低字节存储体 |
| 奇地址字节 | 1 | 1 | 0 | `D8～D15` | 高字节存储体 |
| 偶地址起始的字 | 1 | 0 | 0 | `D0～D15` | 两体并行，一个周期 |
| 奇地址起始的字 | 1 | 1 | 0 | `D8～D15` | 先传高字节 |
| 奇地址起始的字 | 2 | 0 | 1 | `D0～D7` | 再传下一个偶地址的低字节 |

第 181 页第 5.5 节谈到 8088 与 8086 差异时，又把这件事从 CPU 外部重新说了一遍。8086 外部有十六条数据线，才能用 `A0` 和 `BHE#` 同时选择两个存储体；奇地址起始的字还要再用一个总线周期。8088 外部只有八条数据线，没有这套高低字节并行选择关系。

到了存储器和 I/O 接口电路设计时，必须先确认系统 CPU 到底是 8086 还是 8088。一个八位 I/O 端口只占一个 I/O 地址，不能把任意两个相邻 I/O 地址想当然地拼成一个 16 位端口；8086 做 16 位 I/O 操作时，也要遵守对准与未对准的同样规则，8088 则受八根外部数据线限制。

### 8086 与 8088 的差别

一提到 8086 和 8088 的区别，很多人第一反应只有一句：“8086 是十六位数据总线，8088 是八位数据总线。”这只答了外部最显眼的一层。真正答题时，要先看 CPU 内部，再看 CPU 外部。

从内部看，8088 仍然是一个 16 位 CPU，内部数据通路和运算部件的 16 位性质并没有因为外部数据引脚减少而变成 8 位。明显的内部区别是指令队列：8086 的指令队列为 6 字节，8088 的指令队列为 4 字节。

从外部看，差别就集中在数据引脚和传送周期上。8086 外部有十六根数据线，8088 只有 `D0～D7` 八根外部数据线；8088 原来复用为数据的高位一组引脚要转作地址使用。8086 的 `BHE#/S7` 承担高字节允许功能，8088 没有这个高字节并行传送机制，所以相应引脚不承担 8086 中同样的作用。

两者的存储器/I/O 状态信号也不能混记：8086 使用 `M/IO`，8088 使用 `IO/M`，两者极性相反。8086 中高电平表示存储器访问、低电平表示 I/O 访问；8088 中则是高电平表示 I/O、低电平表示存储器访问。信号名字和有效含义都要一起记。

| 比较项目 | 8086 | 8088 |
| :--- | :--- | :--- |
| 内部指令队列 | 6 字节 | 4 字节 |
| 外部数据线 | 16 根 | 8 根 |
| 存储器 / I/O 状态信号 | `M/IO`，高为存储器、低为 I/O | `IO/M`，高为 I/O、低为存储器 |
| 对准的 16 位字操作 | 1 个总线周期 | 2 个总线周期 |
| 未对准的 16 位字操作 | 2 个总线周期 | 2 个总线周期 |
| 高字节允许 | 有 `BHE#` 机制 | 没有 8086 式高低字节并行选择 |

> **结论**：8088 的内部仍是 16 位，缩小的是外部数据通路，不是把所有内部运算都改成 8 位；外部每次只有八位数据可用，所以 16 位字必须分两次传送。

### 最小模式下剩余的引脚与中断请求

第 168 页列出了 8086 最小方式下的一组引脚。除了前面重点讲的 `BHE#/S7`，第 12～16 脚也构成一组需要分清的功能。

| 引脚 | 名称 | 方向 | 功能与有效方式 |
| ---: | :--- | :--- | :--- |
| 12 | `/TEST` | 输入 | 配合外部等待指令，每隔五个时钟检查；高电平表示继续等待，低电平表示条件满足 |
| 13 | `BHE#/S7` | 输出 | `T1` 输出高字节允许 `BHE#`，后续状态输出 `S7`；`BHE#` 低有效 |
| 14 | `NMI` | 输入 | 外部不可屏蔽中断请求，上升沿有效 |
| 15 | `INTR` | 输入 | 外部可屏蔽中断请求，高电平有效 |
| 16 | `INTA` | 输出 | CPU 发出的中断响应信号 |

其中第 12 脚 `/TEST` 和第 13 脚 `BHE#/S7` 的用途完全不同：前者是在等待指令中反复测试条件，后者决定本次传送是否允许使用高字节数据通路。第 13 脚虽然物理上是复用输出，却必须在地址形成电路中再锁存；第 14 脚 `NMI` 则不再承担数据总线控制，它是非屏蔽中断请求输入，采用上升沿有效方式。

第 15 脚 `INTR` 是可屏蔽中断请求输入，高电平有效；是否响应还要受中断允许状态控制。`NMI` 则是不可屏蔽中断请求，不能靠普通的中断屏蔽位把它挡掉。第 16 脚 `INTA` 是 CPU 对外部中断请求发出的响应输出，不能因为它出现在输入引脚列表附近，就把它和 `NMI`、`INTR` 混为同一类信号。第 169 页往后列出的其他最小方式引脚，前面已经结合总线和中断功能分别讲过。

把这些信号放到一张关系图里，脉络就很清楚了：

```text
慢速设备 ──RDY──> 8284A ──READY──> 8086：决定是否插入 Tw
CPU 外部数据有效 ──DEN#──> 74LS245 /OE：决定缓冲器是否打开
CPU 发送 / 接收 ──DT/R──> 74LS245 DIR：决定数据方向
外部不可屏蔽请求 ──NMI──> 8086：上升沿有效
外部可屏蔽请求   ──INTR─> 8086：高电平有效
CPU 中断响应     <──INTA─ 8086：输出响应信号
```

### 本讲提到的题目

**题目：8086 CPU 和 8088 CPU 有什么区别？**

这道简答题要分两步答，不能只说“数据总线宽度不同”。先从 CPU 内部说，再从 CPU 外部说。

**解析：**

从 CPU 内部看，8088 仍然是 16 位 CPU，但指令队列为 4 字节，8086 的指令队列为 6 字节。

从 CPU 外部看，8086 有 16 根数据线，8088 只有 8 根数据线；8086 的 `M/IO` 与 8088 的 `IO/M` 极性相反。由于数据线数量不同，8086 可以借助 `A0` 和 `BHE#` 在一个周期内同时传送对准字的低字节和高字节；8088 每次只能从外部传送一个字节，因此不论字地址是否对准，16 位字操作都要用两个总线周期。

**答案：**8086 内部指令队列是 6 字节，8088 是 4 字节；8086 外部有 16 根数据线，8088 只有 8 根；两者的存储器/I/O 状态信号分别为 `M/IO` 和 `IO/M`，极性相反；8086 的对准字操作可用一个总线周期完成，未对准字需要两个周期，而 8088 的 16 位字操作无论对准与否都需要两个总线周期。

## 8086 最小方式收尾与最大方式引脚
> 对应块：BLK40 | 覆盖分集：P77-P78 | 块标题（分集名）：《77》

最小方式里最容易被忽略的，是两对完全不同的握手：`INTR`/`INTA̅` 是一对中断请求与中断响应，`HOLD`/`HLDA̅` 是一对总线申请与总线让出。它们的时序、方向、有效电平都不一样，看图时不能混在一起。最小方式的这几个引脚讲完，再把系统总线上的扩充设计说清楚，最后转到最大方式：引脚功能一变，8288 总线控制器和双请求/允许线就要接进来。

### INTR 和 INTA̅：中断响应的握手

`INTR` 是**高电平有效的外部可屏蔽中断请求输入**。外部设备要向 8086 提出中断请求，就把它拉高。但是，CPU 要响应必须满足一个条件：`IF=1`。`IF=0` 时，中断被屏蔽，即使 `INTR` 变高，8086 也不会理它。

它的搭档是 `INTA̅`，**低电平有效的中断响应输出**。`INTR` 是外部发给 CPU 的“请求”，`INTA̅` 是 CPU 发出的“回答”。这一高一低正好构成一组配对信号：外部提请求，CPU 回回答；回答要占两个总线周期。

> **易错点**：`INTR` 高有效、`INTA̅` 低有效，不能把两个有效电平都记成高电平。

用 8086 扩展一片 8259 中断控制器，就能管理八个外部中断源。某个外部设备提出中断请求后，8259 在允许该请求通过的前提下，通过 `INTR` 向 8086 发出高电平请求。

```text
        INTR   ────────┐                         ┌──── 拉低
                      │                         │
                      └─────────────────────────┘

  当前指令的最后一个总线周期       T1     T2     T3     T4
                                  │     │     │     │     │
                          INTA̅ ───┘─────┴─────┴─────┘     └── 低电平有效

读图：先等当前指令执行完，随后 8086 在两个总线周期内发出低电平有效的
     INTA̅；8259 看到低电平，就知道 CPU 已经响应了这次请求。
```

关键在时序。8086 执行一条指令时，即使 `INTR` 在这条指令执行途中变高，也不会立刻跳走；必须等 `T1～T4` 全部走完，等当前指令执行结束，才能响应。

响应时，8086 在 `INTA̅` 为低电平的状态下发出中断响应。8259 看到这个低电平，就知道 CPU 已经响应了这次请求。接着在第二个响应周期的数据阶段，8259 把中断类型号送到数据总线 `D7～D0`，8086 从低位数据线 `D7～D0` 读入。

```text
  外部中断源 ──请求──> 8259 ──INTR（高）──> 8086
                         ▲                    │
                         │                    │ 等当前指令执行完
                         │                    ▼
                         └──── INTA̅（低） 发出中断响应

  第二个响应周期：8259 ──D7～D0──> 中断类型号
                                  │
                                  └─ 中断向量地址 = 类型号 × 4
```

中断类型号乘以 4，就得到中断向量在中断向量表中的入口地址。8086 据此把服务程序入口的 `CS:IP` 装入内部寄存器，转到相应的中断服务程序。

> **注意**：8259 必须在响应走完后把 `INTR` 拉低，结束这次请求。如果 8259 还在请求，而 CPU 已经转到服务程序，就容易出现同级的再次中断——这种同级中断嵌套正是我们不想要的。

### HOLD 和 HLDA̅：总线让出的握手

最小方式适用于单处理器系统。8086 本身叫主处理器；CPU 外部那个也能提出总线使用要求的设备，叫**总线主控设备**。

最小方式下，8086 有两个引脚和总线让出有关：`HOLD` 是输入，`HLDA̅` 是输出。这一对和 `INTR`/`INTA̅` 不是一回事。

总线主控设备想使用总线时，向 8086 的 `HOLD` 端加一个**高电平有效的总线使用申请**。CPU 发现 `HOLD` 是高电平，就知道有主控设备要来使用总线了。

```text
   总线主控设备                        8086
       │                               │
       │── HOLD = 1（申请）──────────>│
       │                               │ 现行指令执行完
       │                               │
       │<── HLDA̅ = 1（已让出）────────│
       │                               │
   接管并管理总线                       │ 等待归还

       │── HOLD = 0（归还）──────────>│
       │                               │ 延迟 1～2 个时钟周期
       │                               │ HLDA̅ 变低，CPU 收回总线
```

CPU 看到 `HOLD` 为高，先把现行指令执行完，然后释放总线，并通过 `HLDA̅` 输出一个**高电平**，告诉外部设备：“你可以用了。”外部设备得到这个回答，就接管总线。

CPU 让出总线时，它那些具有三态功能的输出引脚全部进入高阻态。外部设备用完总线以后把 `HOLD` 拉低，CPU 检测到之后延迟 1～2 个时钟周期也把 `HLDA̅` 拉低，CPU 收回总线。

> **定义**：凡是具有三态功能的输出引脚，在总线让出时都置为高阻态。

### 最小方式下的三类系统总线

以 CPU 为核心设计一个产品时，重点掌握的是单处理器系统。8086 最小方式下，地址总线、数据总线和控制总线三类系统总线都要先弄清楚。

| 总线 | 8086 最小方式 | 形成方式 |
| :--- | :--- | :--- |
| 地址总线 | `A0～A19`，共 20 根 | 经 3 片 373 形成 |
| 数据总线 | `D0～D15`，共 16 根 | 经 2 片 245 形成 |
| 控制总线 | `RD̅`、`WR̅`、`M/IO̅`、`BHE̅`、`INTA̅`、`INTR`、`HOLD`、`HLDA̅`、`CLK`、`RESET` 等 | CPU 引脚直接产生 |

> **易错点**：这一类系统总线里，控制总线同样是“直接拉出来”的，不要以为只有地址总线和数据总线才成总线。

以教材 174 页图 5.16 为例，8086 构成最小方式系统时，地址总线 `A0～A19` 经 3 片 373 形成，数据总线 `D0～D15` 经 2 片 245 形成；控制总线 `RD̅`、`WR̅`、`M/IO̅`、`HLDA̅`、`HOLD`、`CLK`、`RESET` 等都是 CPU 引脚直接产生的。

还有一组不能忘的信号，就是**高字节允许信号 `BHE̅`**。8086 的 1 MB 空间在 8 位访问时可以看成两个 0.5 MB 区域：一个偶地址区域，一个奇地址区域。`A0` 和 `BHE̅` 配合起来，决定当前访问的是低字节还是高字节。

### 单向信号与双向信号的总线驱动

现在提出一个问题：假如这是从 CPU 输出的信号，那么这个信号是不是要接到外部存储器的所有存储器芯片？如果系统的存储器芯片很多，每片存储器芯片的引脚都是一个负载，那负载太多，CPU 带不动怎么办？需要驱动。

**单向信号的驱动**很简单：加一个门电路驱动，或者把一路信号分成两路，分别带一部分负载。比如把 `WR̅` 分成两路，各带一部分负载组，就可以了。

**双向信号的驱动**难在数据总线上：`D0～D7` 双向传输，需要用 245 这类双向总线驱动器来驱动。这也是为什么 8086 系统的数据总线要用 245 形成，而不只是“把引脚拉出来”就算完。

### 读题：系统总线上的扩充设计

后面第六章存储器电路设计、第七章、第九章、第十章的 I/O 接口电路设计，出发点都是**基于系统总线级的扩充设计**：系统总线已经有了，我们需要做的是在这个总线基础上扩充设计。

所以做题首先要认清题目，抓第一句话。比如题目说“某 8086 CPU 工作在最小方式组成的系统中”，这个已知条件已经告诉你系统总线和接口（插座）已经给出了——我们不是让你画整个系统总线，而是在这个已知的最小方式系统总线上做扩充设计。

你要能马上在脑子里浮现出：在这样的系统总线上，扩展设计电路要用到系统总线的哪些总线信号。

#### 地址总线用多少根

- **存储器电路设计**：用 20 根地址线，即 `A0～A15` 和 `A16～A19`。
- **I/O 电路设计**：只用到 16 根地址线，即 `A0～A15`。
- **高 4 根地址线 `A16～A19`** 是存储器扩展设计专用的，I/O 电路不用。

#### 数据总线怎么接

存储器电路和 I/O 电路扩充设计，数据总线都直接用 16 根：`D0～D7` 是低 8 位数据线，`D8～D15` 是高 8 位数据线。

8 位存储器芯片（或 8 位 I/O 端口）挂在系统总线上时接哪组数据线，要看分配给你的 I/O 端口的地址是偶还是奇。偶地址对应低 8 位 `D0～D7`，奇地址对应高 8 位 `D8～D15`。这跟存储器电路设计时判断地址奇偶的逻辑是同一套。

#### 控制信号要用到哪些

最小方式下的控制信号，主要看 `M/IO̅`、`RD̅`、`WR̅` 怎么组合：

| 电路类型 | `M/IO̅` | 读 | 写 |
| :--- | :--- | :--- | :--- |
| 存储器电路 | `1` | `RD̅=0` | `WR̅=0` |
| I/O 电路 | `0` | `RD̅=0` | `WR̅=0` |

`M/IO̅=0`、`WR̅=0` 时，表明 CPU 对 I/O 写，那显然就是执行了 `OUT` 指令；`M/IO̅=0`、`RD̅=0` 时，表明 CPU 对 I/O 读。

还要用到**高字节允许信号 `BHE̅`**——高字节允许信号，这是 8086 千万不能忘的。

> **提示**：如果设计的是 I/O 电路，端口器件的地址是偶还是奇，决定它挂高 8 位还是低 8 位数据线。

#### 中断也要考虑

如果系统里还要用中断，扩展了 8259，就要用到 `INTR` 和 `INTA̅` 两个信号。

> **提示**：如果题目说的是 8088 工作在最小方式，信号名和极性要对应变化：地址总线仍然有 20 根，但数据总线只有 `D0～D7` 这 8 根，控制信号对应变成 `IO/M̅` 等。做这种题时一定要先读题，看题目给的是什么已知条件。

### 最大方式下的引脚功能变化

最小方式下的内容到这里就讲完了。最大方式下实际上也基本讲完了，只剩几个引脚功能不同。现在看 8086 工作在最大方式时，引脚功能发生了什么变化。

最大方式下，24～31 号引脚功能全部改变：

| 引脚 | 最大方式下功能 | 作用 |
| :--- | :--- | :--- |
| 24、25 号 | `QS1`、`QS0` | 指令队列状态输出 |
| 26、27、28 号 | `S2̅`、`S1̅`、`S0̅` | 状态输出，接到 8288 的 `S2`、`S1`、`S0` 输入端 |
| 29 号 | `LOCK̅` | 总线封锁指示输出 |
| 30、31 号 | `RQ̅/GT1̅`、`RQ̅/GT0̅` | 与外部总线主控设备完成总线请求与允许的握手 |

#### S2̅、S1̅、S0̅ 与 8288

26、27、28 号引脚变成 `S2̅`、`S1̅`、`S0̅` 三个状态输出。这三个引脚要接到外部 8288 总线控制器的 `S2`、`S1`、`S0` 输入端。8288 看到这三位二进制编码，就知道 CPU 正在完成什么操作，从而在它的输出端产生对应的控制信号。

比如对存储器写操作，8288 会在 `MWTC̅` 引脚输出存储器写控制信号（低电平有效）；对存储器读操作，会产生 `MRDC̅`；对 I/O 读写，则产生 `IOWC̅`、`IORC̅`。

> **注意**：在最大方式下，这三个状态信号**不直接**产生总线控制信号，而是要先经 8288 总线控制器译码。

#### 总线形成电路

教材 175 页图 5.16 是 8086 工作最大方式下的系统总线形成电路。地址总线 `A0～A19` 用 3 片 373 形成，数据总线 `D0～D15` 用 2 片 245 形成——地址总线和数据总线的形成方法与最小方式完全一样。

但两处控制区别明显：

- **373 的锁存允许端**：最小方式下由 CPU 的 `ALE` 引脚直接控制；最大方式下由 8288 产生的地址锁存允许信号 `ALE` 控制。
- **245 的方向控制端 `DIR` 和输出允许端 `OE̅`**：最小方式下由 CPU 的 `DT/R̅` 方向信号和 `DEN̅` 数据允许信号直接控制；最大方式下由 8288 产生的 `DIR` 和 `DEN` 控制。

> **提示**：8288 产生的 `DEN` 信号极性跟最小方式下的 `DEN̅` 数据允许信号**极性相反**，所以在 8288 的 `DEN` 到 245 的 `OE̅` 之间还要加一个反相器。

> **易错点**：373 的控制端不是 CPU 引脚直接产生，而是由 8288 产生。

还要记住形成地址总线时不要忘了**高字节允许信号 `BHE̅`** 的使用；它与地址线一起决定高字节数据线是否参与当前访问。

#### QS1、QS0 与指令队列状态

24、25 号引脚变成 `QS1`、`QS0` 两个状态输出。它们的四种组合 `00`、`01`、`10`、`11`，表明 CPU 在指令队列中取指令的状态：

- `00`：CPU 无操作，队列中指令未被取出。
- `01`：在队列中取出当前指令的第一字节。
- 后面两种组合也是指令队列取指过程中的不同状态。

这是 CPU 在指令队列中获取指令的状态。在实际电路系统设计当中，这两个状态不用接，理解它们即可。

#### RQ̅/GT0̅、RQ̅/GT1̅

31、30 号引脚变成 `RQ̅/GT0̅`、`RQ̅/GT1̅` 两个双向引脚。这两个引脚每一个都同时承担“请求”和“允许”两种功能，也就是说在最大方式下由一个引脚完成一组握手。

而最小方式下，`HOLD` 和 `HLDA̅` 是两个引脚来构成握手。

当 CPU 以外的总线主控设备要接管总线，对挂接在总线上的存储器或 I/O 进行读写管理时，它应该向 CPU 提出总线使用权的申请。

```text
  总线主控设备                       8086
       │                              │
       │ RQ̅/GT0̅ 送负脉冲（请求）────>│ 31 脚
       │                              │ 现行指令执行完
       │<── 同一脚输出负脉冲（允许）───│
       │                              │ 输出变为三态
       │                              │
   接管并管理总线                      │
       │                              │
       │ 同一脚再送负脉冲（归还）────>│
       │                              │ CPU 收回总线
```

总线主控设备先向 `RQ̅/GT0̅` 发一个负脉冲，这就是向 CPU 申请总线使用权的申请信号。CPU 收到这个负脉冲，就知道有总线主控设备向他提出了总线使用权的申请。CPU 把现行指令执行完，准备把总线让出去时，就把同一个引脚变成输出，输出一个负脉冲，表明 CPU 把总线让出去了。CPU 的输出引脚凡具有三态功能的，全部置为三态。

总线主控设备收到这个负脉冲，就知道 CPU 把总线让出去了，于是接管总线，完成对总线上资源的管理操作。等总线主控设备把总线用完要还给 CPU 时，由总线主控设备向 CPU 再发一个负脉冲。CPU 收到这个负脉冲，就知道总线主控设备把总线还回来了，于是收回总线。

在多处理器系统当中，通过 31 脚 `RQ̅/GT0̅` 和 30 脚 `RQ̅/GT1̅`，可能同时有总线主控设备向 CPU 提出总线使用权的申请。如果申请同时到来，CPU 对优先权的管理是：31 脚上挂接的总线主控设备优先权高于 30 脚上挂接的总线主控设备。

#### LOCK̅ 与总线封锁

8086 工作在最大方式时，29 号引脚是 `LOCK̅` 输出。

如果在 CPU 执行程序期间，有一条指令用户认为非常重要，不允许其他总线主控设备向 CPU 申请总线使用权，那么就在那条指令的前方加一个 `LOCK` 总线封锁前缀。CPU 执行期间，就会在 `LOCK̅` 引脚上输出一个低电平，通知外部的总线主控设备：“我把总线封锁了。” 即使你提出请求，CPU 也不理睬。

### 最大方式下的扩充设计

在最大方式下组成系统时，地址总线和数据总线的形成方法与最小方式一样：地址线 20 根，数据线 16 根。I/O 电路只用 16 根地址线，存储器电路要用 20 根地址线。

但控制总线不一样。最小方式下 CPU 直接产生控制信号；最大方式下这些控制信号由 8288 根据 `S2̅`、`S1̅`、`S0̅` 译码产生：

- 存储器读：`MRDC̅`
- 存储器写：`MWTC̅`
- I/O 读：`IORC̅`
- I/O 写：`IOWC̅`
- 数据允许：`DEN`
- 数据方向：`DT/R`
- 地址锁存允许：`ALE`

如果扩展的 I/O 接口电路工作在中断方式，还要用到 `INTR` 和 `INTA̅`；如果涉及高字节数据线的选择，不要忘了 `BHE̅`。

### 本讲提到的题目

**题目**：一个系统由 8086 CPU 构成，8086 工作在最小方式。在这个系统中，不重新画系统总线，而是在已经形成的系统总线基础上，扩充设计一个存储电路或 I/O 接口电路。设计 8 位存储器/端口时，还要说明接到哪组数据线；若扩充中断，还要接上中断信号。若题目改为 8088 最小方式，说明相应变化。

**解析与答案**：

- 存储器电路用 20 根地址线 `A0～A19`，数据线用 16 根 `D0～D15`；控制信号用 `M/IO̅=1`、`RD̅`、`WR̅`；8 位存储器按地址奇偶接 `D0～D7` 或 `D8～D15`，并配合 `BHE̅`。
- I/O 电路只用 16 根地址线 `A0～A15`，数据线仍用 16 根；控制信号用 `M/IO̅=0`、`RD̅`、`WR̅`；8 位端口按分配地址的奇偶接 `D0～D7` 或 `D8～D15`。
- 若扩充中断，还要接入 `INTR` 和 `INTA̅`。
- 若题目是 8088 最小方式，地址总线仍是 20 根，但数据总线只有 8 根 `D0～D7`，控制信号对应换成 `IO/M̅` 等。

所以，碰到这种题，第一句话就是已知条件：8086 还是 8088，最小方式还是最大方式。题目给的是什么 CPU、什么工作方式，后面的信号名、极性、地址线根数、数据线根数就跟着变。做题一定要读题，看清楚题目给的是什么已知条件。
