## 先把课学成一张地图
> 对应块：BLK01 | 覆盖分集：P01-P02 | 块标题（分集名）：《1》

第一次课，我们先不急着钻进某一个芯片、某一条指令或某一个电路，而是先把一门课里“学什么、为什么学、学完用在哪里”理顺。只有先看清全貌，后面一块一块往下学，才知道每一步究竟落在整张图的哪个位置。

这门课最终要落到什么地方？落到真实的智能电子信息系统。今天的电子信息系统大多是智能的，硬件中以 CPU 为核心，让 CPU 控制系统怎样运行。系统要从外界取得信息，处理后再把结果送回外界，因此课程里的程序、存储器、接口和控制电路并不是一堆互不相干的知识点，它们本来就在同一条工作链路上。

### 从物理世界到 CPU 的完整链路

现在绝大多数智能电子信息系统，都要处理来自外界的物理量，例如温度、压力、速度和角度。CPU 只能处理数字量，它认识的是二进制代码。这里必须建立一个非常朴素、也非常关键的认识：**外界给出的物理量，不能原样交给 CPU。**

从外界物理量出发到 CPU，中间至少要走一遍这样的流程：

```text
                 模拟世界
温度、压力、速度、角度等物理量
                    │
                    ▼
                 传感器
           物理量 → 毫伏级电量
                    │
                    ▼
             前端调理电路
        放大、滤波，得到适合输入的模拟信号
              ▲          │
              │          ▼
        预留测试点   模数转换器 AD
                       模拟量 → 数字量
                            │
                            ▼
                   CPU：取数、运算、存储
                     │            │
                     │            └──→ 显示器或打印机
                     ▼
                    数模转换器 DA
                     数字量 → 模拟量
                            │
                            ▼
                   后端调理电路
              放大等处理，形成控制量
                            │
                            ▼
                      被控对象
```

读这张图时，先抓住两端：左边是物理世界，右边也是物理世界；真正把两端接起来的，是传感器、调理电路、AD、CPU、DA 和后端调理电路共同构成的闭环。CPU 在中间负责采集数据、计算并给出控制结果。

要处理温度，就选温度传感器；要处理压力，就选压力传感器。传感器把物理量转成电量，但输出往往只有毫伏级，还需要放大器把它放大到伏特级。模拟信号里还可能夹带不需要的成分，所以放大以后要滤波。可以采用有源滤波或无源滤波，也可以选用 `RC`、`LC` 滤波电路。这些放大、滤波环节合起来，就是**前端调理电路**。

> **注意**：实验阶段需要用示波器观察信号时，应尽量预留测试点，方便探头夹接。不能为了测量随手把探头压在某个器件引脚上，这样既不方便，也容易造成故障。

前端调理后得到的仍然还是模拟信号，而 CPU 只处理数字信号，所以中间必须经过 **AD 转换，也就是模数转换**。不同 AD 芯片的精度不同，输出可能是 8 位、10 位或 12 位等；同时，从开始采样模拟信号到得到数字量还需要一段转换时间，这关系到 AD 的转换速度。

因此，实际选择 AD 芯片不能只问“能不能转”，还必须根据工程需求看两件事：系统需要多高的精度，系统又需要多快的速度。CPU 型号同样没有脱离需求、固定照抄的答案，型号很多，要由系统任务来选。

工程中的采样也不是“信号来了就自动开始”。CPU 要向 AD 转换器发出控制命令，告诉它什么时候开始采样。因为前端信号范围不同，而 AD 对输入电压也有一定的量程要求，前端还要按需要进行幅度变换。调理电路中的放大倍数也可能由 CPU 控制，这就用到了**可编程增益放大器**。

AD 转换后的数字量交给 CPU，CPU 接收到以后，一般先存进存储器，再通过算法进行分析、计算和处理。处理结果一方面可以继续存放，另一方面要送回外部世界。

送回去时又遇到同样的问题：CPU 输出的是数字量，而外部被控对象有时需要的是模拟量，例如控制电压。因此还要使用 **DA 转换，也就是数模转换**。转换后的信号经过后端调理和必要的放大处理，形成真正用于控制的量。实验阶段同样应留出测试点，便于用示波器检查输出。

另一条输出路线更直接：数字显示设备，例如数码管和常用的 LCD，可以直接接收数字量。这样显示，打印也就接上了。

> **结论**：外界的物理量要进入 CPU，必须先经过传感器和前端调理；CPU 的数字结果要控制模拟对象，必须经过 DA 和后端调理。CPU 只会处理数字量，所以“输入”和“输出”两端都不能省略转换这一环。

### 设备千变万化，为什么必须经过接口

系统里的设备不是只有一种。键盘、显示器、打印机等设备用途不同，接收信息的格式也不同；有的接收并行数字数据，有的接收串行数据，有的需要模拟量，有的只需要数字信息。

因此，设备一般不能直接和 CPU 连起来，中间要设计**接口电路**。接口把千变万化的设备接到 CPU 周围，让 CPU 和设备按各自能够接受的方式交换信息。键盘这类设备承担输入任务，显示器、打印机这类设备承担输出任务；AD 位于输入方向，DA 位于输出方向。

这里也能把课程内容接起来：程序设计解决“让 CPU 按要求工作”的问题，硬件设计解决“CPU 怎样连接存储器、怎样连接设备、怎样形成控制系统”的问题。前四章和后面硬件章节不是两套互不相干的内容，而是同一套系统里的不同部分。

### 早期计算机的五大部件

先回到早期计算机，看看一个计算机最基本的硬件骨架。既然计算机要“会运算”，与人脑一样，它就必须有完成运算的部分。这里所说的运算既包括加、减、乘、除这样的算术运算，也包括与、或、非等逻辑运算。

这部分叫**算术逻辑运算单元**，简称 ALU。ALU 负责真正算，但谁告诉它该算什么呢？还要有能够发出指令、指挥 ALU 运算的电路，那就是**控制器**。控制器指挥 ALU 怎样运算，也就相当于在运算时决定用什么数据、按什么次序和方式处理。

参加运算的数据从哪里来？通常先由用户存放在存储器中，由控制器控制存储器，把数据送给 ALU；运算后的结果也可以在控制器的控制下送回存储器。数据不一定只来自存储器，也可能由输入设备直接送入。输入设备简称输入或 `I` 设备，输出设备简称输出或 `O` 设备，二者合称 **I/O 设备**。输入进来的数据也可以先存入存储器，运算结果则可以送入存储器，或者交给显示器、打印机等输出设备。

```text
                        ┌──────────────┐
                        │   控制器     │
                        │ 发出控制信号 │
                        └──────┬───────┘
                               │ 控制数据流动
              ┌────────────────┼────────────────┐
              │                │                │
              ▼                ▼                ▼
         ┌────────┐       ┌────────┐       ┌────────┐
         │存储器  │──────▶│  ALU   │──────▶│输出设备│
         │        │◀──────│算术逻辑│       │显示器等│
         └────────┘ 运算  └────────┘       └────────┘
              ▲                ▲
              │                │
              │            ┌────────┐
              └────────────│输入设备│
                           └────────┘
```

图中最关键的不是框的多少，而是数据的来源和去向：ALU 的数据可以来自存储器，也可以来自输入设备；ALU 的结果可以回到存储器，也可以送往输出设备。控制器贯穿这些过程，负责指挥数据从哪里来、到哪里去。

> **结论**：早期计算机的硬件由五大部分组成：控制器、ALU、存储器、输入设备和输出设备。哪怕后来硬件形态变化巨大，基本的工作关系仍然可以在这张图上理解。

早期硬件体积非常庞大。控制部件可能使用电子管或晶体管电路，存储器还要用磁芯自己绕制。我见过早期电子计算机，整个机器从输入设备一直排到输出设备，大得从一个窗口能排到门口。只有单位的实验室才可能拥有，个人即便买得起，也没有地方放。

后来，半导体技术发展起来，集成电路问世，控制器、ALU 等部分被集成进很小的芯片，这个芯片就是微处理器，也就是 CPU。计算机体积从庞然大物缩小到一张办公桌就能放下，个人可以买回去，放在家里使用。**“微型计算机”和 PC 里的“微”，正是微型化带来的结果。**

> **提示**：分析一台新机器时，仍然可以先把复杂芯片看回“控制器、ALU 和相关存储处理能力”这个骨架，再看芯片怎样通过引脚同外部连接。外形和规模会变，数据在运算部件、存储部件与外部设备之间流动的基本逻辑不会凭空消失。

### 数据、地址、控制：信息为什么必须分三类走

有了控制器、ALU、存储器和 I/O 设备以后，部件之间为什么还要专门设计通路？因为信息必须传送，而且不同信息的任务不一样。

第一类是**数据信息**。从存储器取出数据、输入设备送入数据、把数据写回存储器，或者把结果送给输出设备，传送的都是数据。数据可能由多位二进制线共同承载，例如 8 根或 16 根线。

第二类是**地址信息**。存储器里有很多单元，像一栋楼里有很多房间，每个房间都有门牌号；存储器的每个单元也有自己的号码，这个号码叫**存储器地址码**，简称存储器地址。访问某个单元时，CPU 必须先通过地址信息找到它。

从存储器读出数据叫“读”，把数据放进去叫“写”；无论读还是写，都得先指出访问哪个地址。地址码用二进制编码，地址引脚越多，CPU 能管理的存储空间越大。CPU 与不同 I/O 设备交换数据时，也必须先指出要和哪一台设备通信，所以每个设备同样要分配 **I/O 地址码**。

第三类是**控制信息**，也就是命令信息。读命令、写命令以及其他控制命令，都通过控制信息传递。只有地址和数据还不够，CPU 还必须说明自己究竟要读、要写，还是要执行其他控制操作。

把用于传送这三类信息的线路统称为**总线**。总线就是传送信息的通道或通路：像从学校走到目的地要走路一样，部件之间传递信息也需要道路。数据、地址、控制承担不同任务，不能混成一团无规则的信息流。

| 信息种类 | 承担的线路 | 常用记号 | 传送什么 |
| :--- | :--- | :--- | :--- |
| 数据信息 | 数据总线 | `DB` | 读写的数据、输入输出数据 |
| 地址信息 | 地址总线 | `AB` | 存储器地址码或 I/O 地址码 |
| 控制信息 | 控制总线 | `CB` | 读、写及其他控制命令 |

这里只要先记住一条：**数据总线、地址总线、控制总线，分别负责传数据、传地址、传控制信息。** 后面的接口和硬件系统，都建立在这个划分上。

### 从 CPU 芯片到可用的微型计算机

现在以微处理器为核心组成微型计算机时，拿到一颗 CPU，首先看到的是封装和引脚。引脚是 CPU 与外部世界联系的入口；外部世界主要有存储器和 I/O 设备，CPU 就通过引脚与它们交换信息。

CPU 的外部引脚仍然要承担三类信息：数据、地址和控制。8 位 CPU 一次可以传送 8 位数据，因此需要相应数量的数据引脚；16 位 CPU 需要 16 位，32 位 CPU 则需要 32 位。地址引脚用于输出地址码，帮助 CPU 找到要操作的存储单元；控制引脚用于送出读、写等控制命令。

可问题来了。数据、地址、控制都需要引脚，如果把它们全部分开从芯片边缘引出，芯片体积就会不断增大，“微处理器”也就难以保持那么小的体积。半导体厂家因此采用了**引脚复用**：一根引脚在不同时间可以承担不同用途。

例如，一根引脚可以传送一位数据，同时也可以传送一位地址码；在另一个时刻，它还可以传送从外部读入的数据。引脚数量减少了，但某一时刻不能在总线上同时传送好几类完全不同的信息。所以引脚复用之后，还需要设计外部电路，把复用信息分开，让数据走专用的数据总线，地址走专用的地址总线。

```text
                    CPU 芯片
          ┌─────────────────────────┐
          │ 复用引脚：可能传数据/地址 │
          └────────────┬────────────┘
                       │
                       ▼
              外部分离与控制电路
                       │
        ┌──────────────┼──────────────┐
        ▼              ▼              ▼
     数据总线        地址总线        控制总线
       传数据         传地址         传命令
        │              │              │
        └──────────────┴──────────────┘
                       │
          ┌────────────┴────────────┐
          ▼                         ▼
        存储器                    I/O 设备
```

这张图的重点不在“引脚很多”，而在两步关系：先用引脚复用控制芯片体积，再由外部电路把复用的信息分流到各自的总线。可控地复用引脚，才不会让不同信息在同一总线上挤作一团。

数据总线是**双向**的。CPU 既可以沿着数据总线把数据送给存储器，也可以从存储器把数据读回来。地址总线则是**单向**的，因为外部要访问的存储单元或设备地址由 CPU 发出。选择哪个地址、发出读命令还是写命令，都由 CPU 决定。

CPU 访问存储器时，先通过地址总线给出目标单元的存储器地址，再通过控制总线表明操作方式；若要读取，目标单元中的数据便通过数据总线进入 CPU，若要写入，则由 CPU 把数据沿数据总线送到目标单元。CPU 访问 I/O 设备也是同样的逻辑，只不过输出的地址码换成了 I/O 地址。

至此，课程开头那条完整链路就闭合了：外界物理量经传感器和前端调理成为可供转换的模拟信号，AD 把数字量交给 CPU，CPU 结合程序和存储器完成处理，DA 与后端调理再把结果送回外界；设备千变万化，就由接口电路接进来、接出去。

所以我们学微机原理，不是把“指令、总线、存储器、接口”分成许多互不相干的零件。先认清它们在系统里各自解决什么问题，再看它们怎样通过数据、地址和控制三类信息接起来，才算真正把这门课的门打开了。

> **承前启后**：上一节讲完「先把课学成一张地图」，下一节接着讲「从 CPU 引脚到微型计算机系统」。

## 从 CPU 引脚到微型计算机系统
> 对应块：BLK02 | 覆盖分集：P03-P04 | 块标题（分集名）：《3》

先把一个最容易忽略的事实摆在前头：CPU 要把数据送给存储器，或者送给某个 I/O 设备，不能只把数据丢出去就结束了。CPU 还必须通过控制线发出“写”命令；如果要从存储器或设备取数据，就要发出“读”命令。也就是说，地址、数据、控制这三类信息，必须在 CPU 与外部部件之间有组织地传送。

这也是微型计算机硬件组成的起点。CPU 是核心，但 CPU 本身不是一整套可以独立工作的机器。我们还要把总线形成电路、存储器、I/O 接口、设备和程序接起来，最后才能得到一台真正能够工作的微型计算机系统。

### 三类信息，各走各的路

三类总线并不是三条完全无关的线，而是把不同性质的信息分开传送。

- **地址总线**传送地址码，告诉外部部件“这次要访问谁”。
- **数据总线**传送数据本身，既可能把 CPU 的数据写出去，也可能把外部数据读回来。
- **控制总线**传送控制信息。CPU 发出的读、写命令属于控制信息，设备反馈给 CPU 的状态信息也属于控制信息。

因此，不能把“控制总线”简单理解成只有 CPU 发出的命令。沿着这条总线，既有 CPU 发给设备的命令，也有设备反馈给 CPU 的状态。读命令和写命令决定这次传送的方向，也决定外部器件是否把数据放上数据总线。

系统总线的形成可以概括成这样：

```text
                 CPU
                  │ 控制命令、地址、数据
                  ▼
          微处理器引脚上的信号
          （其中部分引脚是复用的）
                  │
                  ▼
          系统总线形成电路
        ┌─────────┼─────────┐
        ▼         ▼         ▼
    数据总线   地址总线   控制总线
        │         │         │
        └─────────┼─────────┘
                  ▼
       存储器、I/O 接口及其他部件
```

微处理器引脚上形成的总线，可以称为**微处理器总线**。由于 CPU 的很多引脚承担了复用功能，外部看到的并不是三条已经分开的总线；系统总线形成电路要根据引脚功能和信号之间的时序关系，把这些复用信号整理、转换为专用的数据总线、地址总线和控制总线。

这里就不能只凭“CPU 有多少引脚”来猜电路怎么连。我们至少要掌握每个引脚的功能，还要知道一个信号和另一个信号之间的时间关系。锁存器、缓冲器等数字电路中的器件，就要用来完成这种转换和驱动。

#### 弱驱动能力要由系统总线接手

微处理器芯片的体积很小，每个引脚的驱动负载能力也比较弱。某个信号从引脚输出时，不能指望芯片内部先在每个引脚上都加一个放大电路，再把信号送给外面的许多部件。

所以在系统设计中，第一步是借助系统总线形成电路，把微处理器总线转换成三种专用总线；第二步则是让转换后的系统总线去承担系统中大量负载的驱动任务。

这样一来，系统总线形成电路同时解决了两件事：把复用引脚分开，以及把弱驱动能力提升为系统级驱动能力。微处理器只直接驱动形成电路这一级负载，真正的存储器、I/O 设备和其他部件则挂在系统总线上。微型计算机中任何需要和 CPU 通信的部件，都是通过系统总线完成通信的。

### 存储器先分成程序存储器和数据存储器

在微型计算机系统里，存储器子系统是必不可少的。存储器有两大部分：一部分是 ROM，另一部分是 RAM。它们最直观的区别，是掉电以后信息还在不在。

#### ROM：掉电不丢失，放管理程序

ROM 中的信息掉电后不会丢失，因此适合存放系统管理程序。以常用计算机为例，主板上有一片由一批 ROM 芯片组成的 ROM，里面放着 BIOS 程序。系统一加电，CPU 就从 ROM 中读取 BIOS 程序并执行。

从这段启动过程可以看出，ROM 里的程序不是放进去就不管了，它首先要把系统带到能够继续工作的状态：

```text
系统加电
   │
   ▼
CPU 从 ROM 中读取 BIOS 程序
   │
   ├── 对 RAM 进行自检
   │
   ├── 初始化主板上的 I/O 接口电路
   │
   ▼
从外部设备（如磁盘）读取操作系统到 RAM
   │
   ▼
用户程序在操作系统环境中运行
```

这里要抓住 ROM 的角色：它负责保存系统管理程序，并且在断电后仍然保留这些程序。主板上的 ROM 并不是用户程序随便拿来改写的地方；CPU 从中读取程序代码，先完成内存检查和必要的接口初始化，再把操作系统读入 RAM。

如果你用某一种型号的 CPU 设计一个具有自己功能的电子信息系统，也要为这个系统准备相应的管理程序。管理程序放在 ROM 中，掉电后不会丢失，因此可以作为系统启动时首先执行的程序。

#### RAM：运行时可读写，放程序产生的数据

RAM 可以读，也可以写，但掉电后其中的信息会丢失。CPU 执行程序时产生的数据，要放在 RAM 中，所以在这一类存储器中，RAM 也被称为**数据存储器**。

这并不意味着 ROM 只能放系统程序、RAM 只能放普通数据就万事大吉；这里的命名是在我们当前讨论的程序存储器与数据存储器分工中使用的。真正决定工作方式的，是存储器的读写特性和控制信号。

有些型号的 CPU 内部自带 ROM 和 RAM，例如某些单片机内部就有一定容量的程序存储器和数据存储器。如果内部容量不够用，就要在外部总线上扩充。

8086 CPU 内部没有存储器电路。因此，用 8086 组成电子信息系统时，所需存储器必须挂接到系统总线上进行扩展设计。这个结论不是特殊安排，而是由 8086 本身的结构直接决定的。

### CPU 访问一个存储单元，要靠三样东西

CPU 要和 RAM 中某个地址单元交换数据，必须把“这个单元在哪里”和“这次要做什么”同时说清楚。

第一步是送出地址。CPU 通过地址总线把地址码送出来，地址码指向 RAM 中的某个地址单元。地址总线一旦给出地址码，就相当于找到了这个单元。

第二步是说明操作类型。CPU 根据当前执行的指令，通过控制总线发出读命令或写命令。读操作意味着从存储器取出数据，写操作意味着把数据放入指定地址单元。

第三步是传送数据。写操作时，数据从 CPU 出发，经过数据总线送到目标地址单元；读操作时，存储器把目标单元的数据放上数据总线，CPU 再接收回来。

因此，读写过程可以压缩成三步：

```text
地址总线：指出要访问的地址单元
控制总线：指出这次是读还是写
数据总线：真正交换数据
```

这三类信号是配合工作的。地址码解决了“访问谁”，控制命令解决了“怎么访问”，数据总线完成了“传送什么”。

#### 看存储器芯片，先认引脚

观察存储器芯片的引脚时，可以先按功能来认。

地址引脚通常标成 `A0`、`A1`……，地址线的数量决定芯片能够接收多少位地址码。数据引脚常见的是 `D0` 到 `D7`；如果是八位数据存储器，就可以理解为它通过八条数据线并行传送八位数据。

读、写控制引脚要结合低电平有效这一点来认。

- 读控制引脚常写作 `OE#`，也就是 $\overline{\mathrm{OE}}$。当它为低电平时，地址码对应的单元允许把数据输出到数据线上。
- 写控制引脚常写作 `WE#`，也就是 $\overline{\mathrm{WE}}$；有些器件使用 `WR#` 表示写控制。

例如，给 RAM 的某个地址单元写数据时，地址总线先指出目标单元，控制总线发出写命令并使写控制有效，CPU 再把数据送到数据总线上。读数据时，地址总线仍然指出这个单元，但控制总线发出读命令，RAM 才会把该单元的数据放到数据线上。

ROM 的正常工作方式又不一样。程序代码先由用户编写、调试好，再通过专用写入设备写进程序存储器。写入完成后，芯片装到用户电路板上，系统运行中主要由 CPU 读取它。也就是说，ROM 不是因为有一条“普通写入指令”就随时被 CPU 改写；它的写入方式和运行时的读取方式要分开理解。

因此，CPU 与存储器之间的传送可以用一句话概括：地址总线输出地址码来指明操作对象，控制总线根据指令发出读或写命令，数据总线再完成数据的双向传送。

### 指令就是 CPU 能执行的动作

存储器电路怎样和系统总线接口，是接口电路设计要解决的问题。接口设计时，不能只盯着芯片的容量和引脚，还要知道 CPU 当前到底要求它做什么。

这就引出了“指令”这个概念。

用 C 语言写程序时，一行语句可能是在赋值、传送数据；用汇编语言写程序时，一行语句也可能表示一次数据传送。程序员写的是人能理解的符号，但 CPU 最终只认识二进制代码。无论程序最初使用什么语言编写，其中的语句都要翻译成 CPU 能识别的二进制代码。

所以可以把一条指令理解为：

> **一组具有确定含义的二进制代码，它既告诉 CPU 要做什么，也告诉 CPU 应该怎样做。**

一组随随便便的二进制数并不自动成为指令；它必须按照 CPU 所规定的方式编码，CPU 才能正确解释。

例如，把数值 `02H` 送入 CPU 内部的一个八位寄存器 `AL`，用汇编语言可以写成：

```asm
MOV AL, 02H
```

这条语句让程序员一眼看出是在进行数据传送，并知道数据送给 `AL`；但在 CPU 看来，它最终表现为能够执行这个动作的一组二进制代码。

直接用这种二进制代码编写程序，所使用的语言叫**机器语言**。机器语言当然可以直接被 CPU 执行，可是程序员要面对一长串二进制代码，设计、编写和修改都非常困难。于是，人们用能够代表指令含义的符号来描述这些代码，形成了**汇编语言**。

汇编语言写出来的程序仍然不是 CPU 直接认识的程序。执行前，符号语句还要翻译成机器指令。高级语言中的翻译过程叫**编译**，汇编语言中把符号语句翻译成 CPU 能识别的二进制代码的过程叫**汇编**。汇编后的二进制代码还要通过专用设备写入 ROM，程序存储器中的内容才会在系统上电时被 CPU 读取并执行。

可以把这条路径记成：

```text
高级语言或汇编源程序
          │
          ├── 编译 ──► CPU 能识别的二进制代码
          │
          └── 汇编 ──► CPU 能识别的二进制代码
                              │
                              ▼
                    专用设备写入程序存储器
                              │
                       系统加电后由 CPU 读取
```

这里要分清“写程序”和“执行程序”。汇编器把符号翻译成机器代码，专用写入器把机器代码写进 ROM；系统上电后，CPU 再从 ROM 取出这些代码执行。三者是不同环节，不能混成一件事。

### I/O 设备为什么必须有接口

CPU 之外，系统中还会挂接许多 I/O 设备。设备一多，设备与设备之间接收信息的格式要求也就会不同：有些设备接收数字量信息，有些设备接收模拟量信息；有些设备要求并行接收，有些设备要求串行接收。

所以，I/O 设备与 CPU 之间不能像存储器和 CPU 那样简单地把数据直接接上。设备可能要求特定的数据格式、传送方式或信号形式，而 CPU 和系统总线提供的是另一种工作条件。这里需要设计一个连接电路，把设备的要求转换成 CPU 和系统总线能够使用的方式。

这个连接电路就是 **I/O 接口电路**。它放在设备与 CPU 之间，或者放在设备与系统总线之间。1 号设备有 1 号设备对应的接口，2 号设备有 2 号设备对应的接口，不能指望所有设备直接共用一根数据线就把通信做完。

如果是一个输出设备，数据方向是：

```text
CPU ──数据总线──► I/O接口 ──► 输出设备
```

如果是一个输入设备，数据方向反过来：

```text
输入设备 ──► I/O接口 ──数据总线──► CPU
```

在接口电路内部，输入设备的数据从数据输入引脚进入，接口再通过数据输出引脚把数据送到系统总线上的数据线，由 CPU 读取；输出时，CPU 先把数据送到数据总线，接口接收后，再通过数据输出端送给输出设备。

这就是接口的“接力”作用。显示设备和 CPU 之间需要显卡电路，显卡连接显示设备与系统总线；音箱和 CPU 之间则有声卡。它们都不是多余的装饰，而是解决设备与 CPU 之间不能直接通信的问题。

> **结论**：任何 I/O 设备与 CPU 之间的数据通信和信息通信，都必须通过对应的 I/O 接口电路完成。

### 地址译码把“发给谁”变成硬件动作

CPU 通过数据总线读写某个设备时，还要知道这次访问的是哪一个 I/O 接口。为此，要给每个 I/O 接口电路分配一个地址，也就是 **I/O 接口地址**。

CPU 对某个接口进行读写，实际上就演变成对它所分配的接口地址进行读写。这样一来，接口电路和存储器单元一样，都可以用“地址”来定位。

但在 8086 系统中，存储器地址空间和 I/O 地址空间的数量并不相同：

- 存储器分配地址使用 20 根地址线；
- I/O 接口分配地址使用 16 根地址线。

很多 CPU 还会让存储器地址和 I/O 地址使用同一组地址线传送。CPU 不会只盯着地址线上的数字去猜“这次到底是访问存储器还是访问 I/O”。它是通过执行不同的指令来区分的：存储器有存储器读、存储器写指令，I/O 有 I/O 读、I/O 写指令。执行不同指令时，CPU 会从相应控制引脚发出不同的控制命令。

所以，地址线上送来的地址码必须和相应的控制信号一起参与判断。地址译码电路要做的事情可以表示为：

```text
CPU 地址线上的地址码 ─────┐
                            ├──► I/O 地址译码器 ──► 某个 I/O 接口的选通信号
CPU 的 I/O 有效控制信号 ───┘
```

当地址码与该接口分配的地址吻合，并且 I/O 操作的相应控制信号有效时，这个接口被选中；其他接口不能同时被选中。这个选通信号再和读写控制配合，决定数据是在接口与 CPU 之间读，还是由 CPU 写入接口。

举个简单例子：如果用 `A0` 到 `A3` 四根地址线参与地址判断，给某个接口分配 `1001`，就可以用门电路把这个地址码译成一个控制信号。地址译码还要把“当前确实是在进行 I/O 操作”的有效控制信号纳入判断，否则地址线上的一个地址码本身还不足以说明应该选中 I/O 接口。

这里用到的门电路、译码器，正是数字电路课程中已经接触过的内容。地址译码不是凭空出现的复杂黑盒，它最终要落实成能识别地址码并输出选通或控制信号的具体逻辑电路。

### 微型计算机怎样成为系统

现在回头看，微型计算机的硬件组成就清楚了：CPU 通过系统总线连接存储器、I/O 接口和其他部件。但硬件齐全并不等于机器已经能工作。还要配上相应设备，接上电源，把软件加载进去。

可以把整个系统想象成一所学校。

学校就像一台微型计算机系统，行政楼和校长办公室像 CPU：它根据文件发出指令，告诉每个人应该做什么。每个人可以看成系统中的一位数据，文件放到哪里、怎样传出去，就对应着数据在系统中的存放与传送。对学生来说，宿舍楼就像存储器；如果把宿舍楼纵向剖开，看到的就是一间一间独立的房间。存储器如果把它“剖开”理解，看到的也是一个个地址单元。

每个存储单元存放二进制数据。一个单元通常存放一个字节，也就是八个比特位；如果买到的是每个地址单元只有四个比特位的存储器芯片，就需要用两片并联，拼成一个八位的存储单元。

```text
一个八位存储单元
┌────────┬────────┬────────┬────────┐
│ 第7位  │ 第6位  │ 第5位  │ 第4位  │
├────────┼────────┼────────┼────────┤
│ 第3位  │ 第2位  │ 第1位  │ 第0位  │
└────────┴────────┴────────┴────────┘
```

所以，存储器是按字节组织的。每个地址单元都有自己的地址码，CPU 通过地址码选择具体单元，再对数据总线上的内容进行读或写。地址码本身是二进制编码；每个地址单元的地址也常直接简称为地址。

到这里必须把两个容易混淆的词分开：地址线的条数决定可编址空间的大小，而寻址方式是寻找目标地址的方法。寻址方式越多，程序定位数据的灵活性越高，汇编程序也就越容易写得灵活。

### 字节、字与地址空间

地址总线的条数和数据总线的条数，解决的是两个完全不同的问题。

#### 地址总线条数决定能管理多大空间

如果 CPU 只有四根地址输出线，它可以产生 $2^4=16$ 种地址组合，因此最多对应 16 个可编址单元。这个空间当然可能不够用，所以要让 CPU 能寻址更大的外部存储器空间，就需要更多地址线。

更准确地说，地址总线宽度决定 CPU 能寻址的外部存储器空间大小。CPU 要读写某个单元，第一步就是找到这个单元的地址；这个过程叫寻址。

#### 数据总线条数决定一次能传多少数据

数据总线宽度决定 CPU 一次能和外部存储器或 I/O 接口传送多少位数据，也决定了传送数值的范围。

以逐字稿中提到的常见情况为例：

- 8 位数据线传送无符号数时，范围是 $0\sim255$；传送有符号数时，范围是 $-128\sim127$。
- 16 位数据线传送无符号数时，范围是 $0\sim65535$；传送有符号数时，范围是 $-32768\sim32767$。

数据线越多，一次能够并行传送的位数越多，数值范围也越大。地址线解决的是“能访问多少个单元”，数据线解决的是“每次搬运多少位”，两者不能混为一谈。

#### 8086 中的字由两个相邻字节组成

8086 是 16 位 CPU，它有 16 条数据线，一次可以传送 16 位数据，也可以传送 8 位数据。16 位数据称为一个字，也就是两个字节：

- 第 0 到第 7 位是低字节数据；
- 第 8 到第 15 位是高字节数据。

```text
一个 16 位字数据
┌───────────────┬───────────────┐
│   高字节数据  │   低字节数据  │
│   第 8～15 位  │   第 0～7 位   │
└───────────────┴───────────────┘
```

在 8086 系统中，任意两个相邻的字节单元都可以组成一个字单元。两个字节的地址仍然有高低之分，但这里的“高、低”首先是地址排列位置，不要把地址和存储内容混为一谈。存放一个 16 位字时，低字节放在低地址单元，高字节放在高地址单元。

因此，存储器的基本概念可以压缩成几句话：一个存储单元是一个字节单元；存储器按字节组织；一个字节有八个比特位；任意两个相邻的字节单元可以拼成一个字单元；字的低字节存放在低地址，高字节存放在高地址。

到这里，CPU、总线、存储器和 I/O 接口之间的关系才算真正接上了。系统总线形成电路负责把微处理器引脚转换成三类系统总线，存储器和 I/O 接口挂接在这三类总线上，地址总线负责选址，控制总线决定读写，数据总线负责搬运数据。

### 接下来要落到电路上的三个问题

现在我们已经知道一台微型计算机应该由哪些部分组成，也知道 CPU 访问存储器和 I/O 设备时必须经过总线与接口。接下来的学习，就是把这些概念继续落实成电路：

- 系统总线形成电路要依据 CPU 引脚功能和信号时序，把复用信号分开，并用相应器件完成总线形成与驱动。
- 存储器接口电路要解决程序存储器和数据存储器怎样和系统总线连接的问题。
- I/O 接口电路要解决不同设备怎样通过接口与 CPU 交换数据，以及地址译码怎样把地址码翻译成选通信号。

下一节则从“计算机中用到的数制和码制”开始。现在先把根基立住：二进制是计算机内部表示和处理信息的底层形式；地址是 CPU 选址的依据；总线上的地址、数据、控制信号共同决定了系统怎样工作。把这套关系真正弄清楚，后面的存储器电路和 I/O 接口电路才不会变成一堆孤立的引脚名称。

> **承前启后**：上一节讲完「从 CPU 引脚到微型计算机系统」，下一节接着讲「从十进制输入到二进制运算」。

## 从十进制输入到二进制运算
> 对应块：BLK03 | 覆盖分集：P05-P06 | 块标题（分集名）：《5》

先把一个容易被忽略的事实摆在桌面上：CPU 只认识二进制。

可是我们平时从键盘输入的是十进制数，程序运行完以后，显示给用户看的也应该是十进制结果。人的输入和输出习惯是一回事，CPU 内部使用的数却是另一回事。这中间怎么过？先把数制之间的转换弄清楚，再看这些二进制数怎样参加运算，最后把数据放进 CPU 真正能够高速使用的部件里。

### 数制转换先定字长

我们这门课主要用到二进制、十进制和十六进制。十六进制的每一位正好对应四个二进制位，因此它和二进制之间转换非常方便。整数部分的相互转换是必须掌握的重点，小数部分的转换了解即可，后面举例子也以整数为主。

开始计算以前，第一件事不是急着写位，而是先看字长 $n$ 是多少。存储器通常按字节组织，一个字节是 8 位；8 位数据就是字节型数据，16 位数据就是字型数据。题目要求 8 位，就不能只写出计算出来的 5 位，还得把高位补成 8 位。

以 8 位二进制数为例，最低位是第 0 位，最高位是第 7 位。位次和位权的关系如下：

| 位次 | 第 7 位 | 第 6 位 | 第 5 位 | 第 4 位 | 第 3 位 | 第 2 位 | 第 1 位 | 第 0 位 |
| :--- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 位权 | 128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 |

最低位的权是 $2^0=1$，第 1 位的权是 $2^1=2$，一直到最高位的权是 $2^7=128$。这些位权一旦列出来，十进制数转二进制就不一定非要用除 2 取余法。对于手算来说，按权逼近通常更快：先看 128，再看 64、32、16……每一项够不够减，能减就置 1，不够就置 0。

#### 用位权把 93 写成二进制

现在把十进制数 93 转换成 8 位二进制数。

93 里面没有 128，所以第 7 位是 0；93 里面有一个 64，所以第 6 位是 1。减去 64 后还剩 29。29 里面没有 32，第 5 位是 0；有一个 16，第 4 位是 1。减去 16 后还剩 13。13 可以继续拆成 8、4、1，因此第 3 位、第 2 位和第 0 位都是 1，第 1 位是 0。

把各位按第 7 位到第 0 位排开，得到：

```text
位次    7  6  5  4  3  2  1  0
位权  128 64 32 16  8  4  2  1
93      0  1  0  1  1  1  0  1
```

所以，93 的 8 位二进制结果是：

$$
01011101_2
$$

> **易错点**：位序从右往左看。最低位是第 0 位，最高位是第 7 位；位权从右往左依次增大。题目要求 8 位时，即使有效数字不足 8 位，也要在高位补 0，不能少写。

反方向也一样。二进制转十进制，可以把每一位的数字乘以这一位的权，再把所有结果相加。这种方法叫作**位置加权法**。仍然看 01011101：

$$
0\times2^7+1\times2^6+0\times2^5+1\times2^4+1\times2^3+1\times2^2+0\times2^1+1\times2^0
=93
$$

最高位上的 0 乘以 128 还是 0，不影响结果；但是每一位都不能因为是 0 就直接丢掉，因为只要有 1，就要把对应的位权加进来。

#### 让二进制和十六进制对上号

十进制转十六进制，数字电路中常用除 16 取余法；不过既然已经熟悉了位权，也可以先把十进制数展开成二进制，再从右往左每 4 位分组。每一组正好对应一个十六进制位，最左边不够 4 位时补 0。

例如刚才的 01011101，分成 0101 和 1101。0101 对应十六进制 5，1101 对应十六进制 D，所以结果写成 5DH，末尾的 H 表明它是十六进制数。

这实际上把十进制、二进制和十六进制串在了一起：先用位权把十进制数写成二进制，再把二进制每 4 位一组翻译成十六进制。十六进制不是另起炉灶的一种表示，而是二进制的一种压缩写法。

### 转换算法要走进程序

纸面上会做转换还不够，程序里也会经常遇到同样的问题。CPU 处理完用户程序，得到的是二进制结果；可结果最终要显示、打印或者交给用户，不能直接把一串二进制丢给用户让他自己算。因此在结果输出之前，二进制转十进制的转换几乎不可避免。

反过来，用户从键盘输入的通常是十进制数，而 CPU 只接受二进制。程序就必须把输入的十进制数变成二进制数。实际开发中，把这些转换先做成函数、子程序或者模板保存下来，到了不同项目里直接调用，往往比每次从零开始写更可靠。硬件设计也是同样的道理：调通的单稳态电路、振荡器和滤波器，都要整理成模块，后面直接取用。做什么事情都不必从零做起，这也是一种工作方法。

#### 键盘输入用逐位累积

先看十进制数从键盘进入程序的过程。

假设先输入 9，再输入 5，用户输入的数就是 95。程序不需要先把完整的 95 写出来，可以先记住已经输入的 9；第二个数字 5 到达时，把原来的累积值乘以 10，再加上新输入的 5：

$$
9\times10+5=95
$$

如果后面还有数字，就继续做同样的事：

$$
\text{新累积值}=\text{原累积值}\times10+\text{本次输入的数字}
$$

为什么这个算法最后得到的就是二进制数？因为从第一次计算开始，CPU 执行的运算就是二进制运算。它执行的“乘以 10，再加 5”，结果当然也要用二进制形式保存。关键不是等用户输入完以后再把整个十进制数硬转一次，而是每读入一位，就用 CPU 能执行的运算把已有的值更新一次。

看到程序里出现这种处理，你应该马上知道它在做什么：它不是在逐位读字符，而是在按十进制的位值规则构造一个可以参加后续运算的数。

#### 二进制转十进制可以除 10 取余

程序设计里，把二进制数转换成十进制结果，最常用的是**除 10 取余法**。为了看清算法，先拿十进制数 193 演练：

```text
193 ÷ 10 = 19 …… 3
 19 ÷ 10 =  1 …… 9
  1 ÷ 10 =  0 …… 1
```

第一次得到的余数 3 是个位数，第二次得到的余数 9 是十位数，最后得到的余数 1 是百位数。商变成 0 时，十进制各位就取全了；由于余数是从低位到高位产生的，最后要按百位、十位、个位的顺序写回去。

如果被处理的原始数是二进制数，道理不变：把它的数值反复除以 10，依次得到十进制结果的个位、十位、百位等。这里的 10 仍然是程序中的常数，CPU 内部执行运算时用的还是二进制表示；不要因为写出来的是“除以 10”，就以为 CPU 有一套专门认识十进制的指令。

实际写程序时，我通常更愿意采用这个算法，因为除以 10、取商、取余数的循环结构非常清楚。它当然不是唯一的办法，我常说，实际中大约 85% 到 90% 的程序员会采用除 10 取余法，剩下的人可能采用别的算法。这里不必把 85% 到 90% 当成一条必须背下来的数字，真正要记住的是：纸面上的位置加权法适合手算，程序里还需要找到容易重复执行的步骤。

#### 比较法也能完成同样的工作

另一种常见算法是比较法。这里的“比较”不是只比一次大小，而是把十进制结果的各位先清零，再按照百位、十位的权逐步处理。

按 8 位无符号数理解时，数值范围是 0 到 255，最高位对应十进制结果中的百位。先把原数和 100 比较；如果原数大于或等于 100，就让百位统计值加 1，并从原数中减去 100，再继续比较。只要还大于或等于 100，就重复“加 1、减 100”。当原数已经小于 100 时，再拿它和 10 比较，处理十位；最后小于 10 的剩余值就是个位。

```text
结果百位、十位、个位全部清零
                │
                ▼
        原数是否 ≥ 100？
          ┌─────┴─────┐
         是           否
          │            │
    百位加 1，原数减 100   直接判断十位
          │            │
          └─────┐      │
                ▼      ▼
          再判断是否 ≥ 100  原数是否 ≥ 10？
                │           ┌────┴────┐
                │          是          否
                │           │           │
                │      十位加 1，原数减 10  余数就是个位
                │           │
                └───────────┴─────┬─────┘
                                  ▼
                         原数是否 ≥ 10？
                            ┌────┴────┐
                           是          否
                            │           │
                      十位加 1，原数减 10  余数就是个位
```

比较法看起来比除 10 取余法更“笨”，但它有一个特点：比较、相减、统计这几个动作都能直接写进程序。到底选哪一种，要看程序的需要；重要的是先把算法想清楚，再决定代码怎么写，而不是一看到二进制就只想到手工展开位权。

### 二进制数怎样参加算术运算

数制转换讲清楚以后，接下来就是二进制数本身的运算。算术运算包括加、减、乘、除；沿着这门课的要求，加法是重点，减法需要掌握，测试中遇到相关题目时要知道它考在哪里。乘法和除法先了解基本运算形式即可。

不过，无论做加法、减法、乘法和除法中的哪一种，开始前都必须先确认字长 $n$。是 8 位运算，还是 16 位运算？参加运算的数是字节型，还是字型？这一步不明确，后面的位对位操作就没有边界。

#### 两位十进制数相加并转换到二进制位

假设字长是 8 位，要计算 97 加 89。先把两个数转换成 8 位二进制。

97 可以拆成 64、32 和 1：

$$
97=64+32+1=01100001_2
$$

89 可以拆成 64、16、8 和 1：

$$
89=64+16+8+1=01011001_2
$$

手工运算时，两个数的相同位置对齐：第 0 位和第 0 位相加，第 1 位和第 1 位相加，依此类推。二进制加法的规则大家并不陌生，1 加 1 得到 0，同时向高位进 1；1 加 0、0 加 1 的结果就是 1；0 加 0 仍然是 0。

```text
    01100001
  + 01011001
  -----------
    10111010
```

结果就是 10111010。这里先把字长和位权关系弄清，再做位对位运算，才不会把十进制的加法习惯直接搬到二进制里。

### CPU为什么需要寄存器

手工把 97 和 89 写进两个二进制数还比较容易，可程序里不能每次都靠人展开。汇编语言程序设计要继续往前走，就必须先掌握 CPU 芯片内部的结构，尤其是 CPU 怎样暂存参加运算的数据。

参加运算的数据，大部分时候放在存储器里。可存储器在 CPU 外部，CPU 每次要取数据，都得经过总线走一段很远的路。这段路有距离，当然也有时间成本；如果每做一次运算都从外部存储器取数据，CPU 的运算速度一定会受到影响。

解决办法是，把一部分数据提前放进 CPU 内部，让运算时直接从内部取。CPU 内部用来暂存数据的部件叫作**寄存器**。从外部存储器取数据和从 CPU 内部取数据，距离不同，速度自然也不同。

> **结论**：寄存器的作用不是“多存一点数据”这么简单，而是缩短 CPU 运算时的数据往返距离。

#### 速度与体积之间的折中

从道理上说，CPU 内部的寄存器越多，能够同时暂存的数据就越多，运算速度也可能越快。但寄存器不能无限增加，否则 CPU 芯片的体积会不断膨胀，就不再是微处理器了。因此实际 CPU 只设计少量的寄存器，在运算速度和芯片体积之间作折中。

任何型号的 CPU 内部都有用于暂存数据的寄存器。8086 也不例外，而且它的内部寄存器主要是 16 位的。为什么还要提供 8 位寄存器？因为实际处理的数据很多是字节型的，不能为了 CPU 是 16 位处理器，就强迫所有数据都用 16 位方式处理。

8086 中本块提到的 8 位通用寄存器有 AL、AH、BL、BH、CL、CH、DL、DH。它们可以两两拼成 16 位寄存器：

| 高 8 位 | 低 8 位 | 合成后的 16 位寄存器 |
| :--- | :--- | :--- |
| AH | AL | AX |
| BH | BL | BX |
| CH | CL | CX |
| DH | DL | DX |

所以，AX 是 16 位寄存器，AL 和 AH 各自是 8 位寄存器。程序处理字节型数据时，就选用 8 位寄存器；处理 16 位字型数据时，就选用 16 位寄存器。这个选择不是形式上的区别，它会直接决定程序里数据以什么宽度参加运算。

这里先把寄存器提前拿出来，是因为后面的汇编程序马上要用。第二章还会继续展开 CPU 内部各部件的结构和作用，但眼下先把“为什么需要寄存器”和“字节、字型数据怎样选寄存器”弄清楚，后面的指令就不会只剩下记符号。

### 从机器码到汇编指令

把 97 送进 AL，汇编语言里不使用普通的赋值说法，而是使用数据传送语句：

```assembly
MOV AL, 97
```

这条指令由几个部分组成，其中 MOV 就是**指令助记符**。看到 MOV，就知道这条指令完成数据传送；看到 ADD，就知道它和加法有关。机器语言当然也可以完成这个功能，但一串机器代码不容易记忆，所以人们用符号把一组指令代码描述出来，形成了汇编语言。

具体到这条传送指令，把一个字节数送入 8 位寄存器 AL，机器语言代码是 B0H，后面的 97 对应十六进制 61H。两个字节合在一起构成一条机器指令：

```text
B0H  61H
```

这样一来，程序设计就有了清楚的两层表示：人写汇编指令时看 MOV、AL 和 97，机器执行时看 B0H 和 61H。后面学习加法、减法以及其他指令，仍然沿用这个思路：先看助记符理解动作，再结合寄存器和字长理解数据怎样参与运算。

从十进制输入、到二进制保存，再到 CPU 内部取数并执行运算，表面上是在做几件不同的事，实际上始终围绕同一个问题：怎样让人习惯的表示方式和机器能够执行的表示方式接上。字长、位权、转换算法、寄存器和助记符，正是这道接口上的几个关键位置。

## 运算指令、处理器状态字与补码
> 对应块：BLK04 | 覆盖分集：P07-P09 | 块标题（分集名）：《7》

我先问一个很容易被忽略的问题：CPU 只认识二进制数，那么我们在程序里写十进制数，它到底怎么执行？

答案藏在“翻译”这两个字里。程序交给 CPU 执行之前，要先经过汇编。汇编程序会把程序中写出来的数据、地址和操作码翻译成机器能够识别的二进制形式。也就是说，你在程序里写十进制，汇编工具会替你完成转换；没有必要为了迁就 CPU，人人都把数据改成二进制再写。真正需要记住的是：计算机内部处理的一切，最终都用二进制表示。

所以，今天我们不是孤立地背几条指令，而是要把一件事串起来：一条运算指令怎样产生结果，结果怎样变成状态，状态又怎样被程序拿去判断；运算结果怎样用补码表示，汇编器又怎样替你把负数翻译成机器码。

### 从二进制到汇编指令

#### 先认清两个操作数

以加法为例，8086 汇编语言中的指令格式可以抽象成：

```asm
ADD 目的操作数, 源操作数
```

逗号左边的叫目的操作数，右边的叫源操作数。CPU 参加运算的是这两个操作数；运算完成后，结果要放回目的操作数。为了后面写得清楚，可以把目的操作数记作 `dst`，把源操作数记作 `src`：

```text
ADD dst, src
        │     │
        │     └── 参加运算的源操作数
        └──────── 目的操作数，结果也写回这里
```

这里的顺序一定要记牢。减法也是同一个思路，只不过指令助记符换成 `SUB`：

```asm
SUB dst, src
```

意思是“目的操作数减去源操作数”，所得的差仍然放回目的操作数。比如本讲用到的 `SUB AL, 08H`，执行后 `AL` 中得到差值 `08H`。如果你用圆括号描述寄存器的内容，`(AL)` 表示的是 `AL` 里面装的数，不是寄存器这个符号本身。

> **易错点**：目的操作数不只是“参加运算的数”，它还承担结果回写的位置。看到 `dst`，就要想到“结果最后放这里”；看到 `src`，就要想到“另一项参加运算”。

#### 名称和数字，汇编程序得认得出来

程序里还会遇到一个语法问题。假设你想把数值 `B3H` 放进程序，汇编程序看到这个写法时，未必能立即判断它是数据还是名称：它可以把它看成一个以字母 `B` 开头的符号。

所以，汇编语言有明确的书写规则：名称必须以字母开头；数值则应当以数字开头。为了让汇编程序明确“这是数据”，十六进制数以 `A` 到 `F` 开头时要加一个前导 `0`。例如：

```asm
0B3H
0F0H
```

这里的 `0` 不是数值的一部分，它是给汇编程序看的“这是数据”的标志。这个小规则看似形式主义，实际上直接关系到程序能不能被正确翻译，所以千万不要把 `0` 省掉。

### 运算结果为什么会改变程序走向

#### 结果状态与条件分支

实际程序很少只是“算出一个数，然后结束”。同一个数算出来以后，我们往往还要追问：结果是不是零？结果是正的还是负的？结果有没有溢出？根据这些不同状态，程序应该走不同的处理路线。

这不是凭空设计出来的。运算先产生结果，结果再产生状态，程序最后根据状态选择分支。把它画成流程图，就是：

```text
                         运算结果
                            │
                     产生零、符号、溢出等状态
                            │
                    测试某一个条件
                    /              \
                 条件成立          条件不成立
                    │                │
                 处理一             处理二
                    │                │
                    └──────回到后续──────┘
```

读图要抓住一个顺序：**先有运算，后有状态；先有状态，后有分支判断。** 如果前面的指令根本没有进行会影响状态的运算，CPU 就没有为你准备好要测试的条件。

#### 处理器状态字 PSW

运算结果不一定只放在目的操作数或内存地址单元里。CPU 内部还专门设置了一个用于记录运算结果的寄存器，叫作处理器状态字寄存器，简称 PSW。

PSW 的宽度和处理器字长相对应：8 位处理器的 PSW 是 8 位，16 位处理器的 PSW 是 16 位。8086 是 16 位 CPU，所以它的 PSW 也是 16 位。不要被“16 位寄存器”这四个字吓到：PSW 里面并不是每一位都拿来表示有用状态，未使用的位置可以空着。就 8086 而言，其中有九位是有用的。

PSW 中的每一个标志位，实质上就是描述一种结果状态的一个比特位。常用例子有三个：

| 标志 | 它在问什么 | 结果满足时 |
| :--- | :--- | :--- |
| `ZF`，零标志 | 结果是不是零 | 结果为零时置位，否则清零 |
| `SF`，符号标志 | 结果的符号是什么 | 结果为负时置位，否则清零 |
| `OF`，溢出标志 | 有没有发生有符号数溢出 | 溢出时置位，否则清零 |

8086 的 PSW 从右向左编号时，`ZF` 位于第 0 位，`OF` 位于第 11 位。做题或看结构图时，先确认编号方向，别把位序号和权值混在一起。

这里有一个特别重要的操作顺序。比如执行 `SUB AL, 08H` 后，按本讲给出的结果是 `08H`：

- 结果不是零，所以 `ZF = 0`；
- 结果符号位为 0，所以 `SF = 0`；
- 按本例的进位、借位情况没有发生溢出，所以 `OF = 0`。

为什么一定要先执行运算，再测试标志？因为 PSW 中的状态是 CPU 根据运算结果自动设置的。比如一条普通的数据传送指令只做数据搬运，并没有做算术运算，执行后就不会替你产生这些算术状态。换句话说，不能凭空测试一个还没有被产生的条件。

> **结论**：做条件分支程序，先确定要测什么状态，再设计哪条运算指令产生这个状态，最后才是测试和跳转。

#### 加减法后的判断

带符号数的最高位就是符号位。8 位数的最高位是第 7 位，16 位数的最高位是第 15 位；最高位为 0 表示正，为 1 表示负。符号位数字化以后，CPU 才能把正负、零和溢出这些结果状态交给程序判断。

所谓溢出，最简单的一句话就是：**结果错了**。为什么结果会错？因为一个有固定字长的带符号数只能表示一定范围。两个数相加或相减后，如果结果超出了这个字长能够表示的范围，8 位数放不下，或者 16 位数放不下，得到的机器结果就不能代表原本想表达的数值，这种现象叫结果溢出。

不用肉眼盯着每一个二进制的借位来判断，也可以用符号位附近的进位、借位组合来检查：两个方向都没有相应的进位或借位，结果正确；两个方向都发生，结果也可以是正确的；只有一个方向发生、一个方向不发生，说明结果很可能溢出。千万不要只盯着结果最高位是 0 还是 1，因为最高位只能告诉你符号，不能单独告诉你有没有溢出。

### 逻辑运算：按位选择

算术运算关心的是数值，逻辑运算则把两个数的每一位单独拿出来做判断。对应到 8086，逻辑运算的指令助记符分别是 `AND`、`OR`、`XOR` 和 `NOT`。

它们的基本规律如下：

| 运算 | 位对位规则 | 程序设计中常见的用途 |
| :--- | :--- | :--- |
| `AND` | 只有 `1 AND 1 = 1`，其他情况为 `0` | 把指定位清零 |
| `OR` | 只有 `0 OR 0 = 0`，其他情况为 `1` | 把指定位置一 |
| `XOR` | 相同得 `0`，不同得 `1` | 把指定位取反 |
| `NOT` | 每一位 `0`、`1` 互换 | 对唯一操作数整体取反 |

#### 与运算：清零指定位

`AND` 是双操作数运算：

```asm
AND dst, src
```

目的操作数和源操作数逐位相与，结果写回目的操作数。硬件上可以把它理解为一个逻辑与门；软件上则用 `AND` 指令完成相应的位选择。

它的关键规律是：只要有一位中有一个 `0`，这一位结果就是 `0`；只有两个 `1` 相与才得到 `1`。所以，想让某一位清零，就在掩码的这一位放 `0`；想让其余位保持不变，就在掩码的其余位置放 `1`。这就是“与运算用于清零指定位”的道理。

#### 或运算：置一指定位

`OR` 同样是双操作数运算：

```asm
OR dst, src
```

它把目的操作数与源操作数逐位相或，结果仍然放回目的操作数。例如：

```text
01100001
01011001
--------
01111001
```

逐位看，只有 `0 OR 0` 才得到 `0`；只要有一位是 `1`，这一位就会得到 `1`。

所以，想把某个操作数中的某些位置为 `1`，就在掩码的这些位置放 `1`，其余位置放 `0`，再用 `OR`。这里要注意：它不是把整个操作数都改掉，而是只改变掩码选中的那些位，其他位因为与 `0` 或运算而保持原值。

#### 异或：取反指定位

`XOR` 仍然是双操作数运算：

```asm
XOR dst, src
```

它的规律只有一句：相同得 `0`，不同得 `1`。对某一个操作数来说，原来的 `0` 异或 `1` 会变成 `1`，原来的 `1` 异或 `1` 会变成 `0`，因此被选中的位正好发生取反；没有选中的位异或 `0`，当然保持不变。

所以，异或最适合处理“某些位取反、其余位不变”的要求。掩码中放 `1` 的位置会被翻转，放 `0` 的位置保持不变。这个应用场合一定要和与、或区分开：同样是逻辑运算，关键不在于记一个孤零零的助记符，而在于知道每一位的 0、1 组合会产生什么结果。

#### 非运算：单项取反

`NOT` 与前面三种不同，它只有一个操作数：

```asm
NOT dst
```

它把目的操作数中的 8 位或 16 位整体取反，结果仍写回这个目的操作数。注意它的标志位特性：四种逻辑运算中，`AND`、`OR`、`XOR` 都会影响 PSW 中的部分状态标志，而 `NOT` 执行后不影响 PSW 中的所有状态标志。这个区别要单独记住。

还要记住一点：逻辑运算也会影响 PSW，但不是每次都像算术运算那样把各个结果状态都反映出来。`AND`、`OR`、`XOR` 产生运算结果，也会设置一部分状态；至于具体是哪些标志，等讲到相应指令时再进一步区分。这里先把“运算会产生状态”这条主线抓住。

### 有符号数的机器表示

#### 无符号数与符号位

前面先看无符号数。8 位无符号数的表示范围是 `0～255`，写成十六进制就是 `00H～FFH`；16 位无符号数的范围是 `0～65535`，写成十六进制就是 `0000H～FFFFH`。

无符号数不承担正负号，所有位都用来表示数值。带符号数就不一样了：它需要拿出最高位作为符号位。8 位数的第 7 位是符号位，16 位数的第 15 位是符号位；正数符号位为 `0`，负数符号位为 `1`，其余位表示数值。

这种把数值和符号一起放进机器字中的表示方法，叫机器数表示法。接下来要看的是：同一个带符号数，究竟采用哪一种机器码来表示。

#### 原码：符号有了，零却有两种

先看原码。原码的规定很直观：最高位写符号，符号位后面写数值本身的绝对值。

例如，8 位的 `+3`：

```text
00000011B = 03H
```

最高位为 `0` 表示正，低七位表示数值 3。

同样字长的 `-3`：

```text
10000011B = 83H
```

最高位为 `1` 表示负，后面的数值位仍然是 3。

到这里看起来似乎没有什么问题，但一写零就会发现麻烦。正零的原码是：

```text
00000000B = 00H
```

负零的原码是：

```text
10000000B = 80H
```

同样是零，为什么会得到两个不同的机器数？从小学到大学，我们都知道零就是零，没有正负之分；如果用原码表示带符号数却出现正零和负零，这个表示方法显然不合适。于是，计算机中又引入了另一种机器码——补码。

#### 补码：把符号和运算统一起来

补码的定义可以写成：

$$
[x]_{\text{补}} =
\begin{cases}
x, & x \ge 0 \\
2^n + x, & x < 0
\end{cases}
$$

也就是说，正数的补码就是它本身；负数的补码等于 $2^n+x$。这里 $n$ 是字长，本课程中用的是 8 位或 16 位。

例如求 8 位 `+3` 的补码，因为它为正，补码就是原码：

```text
00000011B = 03H
```

求 8 位 `-3` 的补码，就按定义计算：

$$
2^8-3=256-3=253
$$

$253$ 的二进制是 `11111101B`，所以：

```text
-3 的补码 = 11111101B = FDH
```

用定义求负数补码，实际上要做一次减法，操作比较繁琐。实际应用中，通常先写出负数的原码，再按下面的规则转换：

1. 符号位保持不变；
2. 其余数值位逐位取反；
3. 最后在最低位加一。

以 `-3` 为例：

```text
原码：       10000011
低七位取反： 11111100
末位加一：   11111101 = FDH
```

这和用补码定义算出来的结果完全一致。记住这个方法，比每次机械地做一长串减法更省事。

补码还有一个很重要的结果：零只有一个。`0 ≥ 0`，所以零的补码就是零本身，8 位表示为 `00H`。原码带来的正零、负零问题，就这样被补码解决了。

#### 补码的求法与范围

采用补码表示以后，8 位带符号数的范围是：

$$
-128 \sim +127
$$

16 位带符号数的范围是：

$$
-32768 \sim +32767
$$

这两个范围特别容易和前面的无符号数范围混淆，所以考试填空时一定要先看题目问的是“无符号数”还是“有符号数”，还要看字长是 8 位还是 16 位。不要只看见十六进制的最高位是 `F`，就直接套用某个固定结论。

补码不仅是一种存储负数的方式，也是计算机用补码表示带符号数后进行加、减、乘、除运算的基础。本讲重点落在加法和减法：前面的 `ADD`、`SUB`，以及它们产生的零、符号、溢出状态，都要和这一套表示方法联系起来看。

### 让汇编器替你算补码

现在回到一个实际问题：程序中想写 `MOV AL, -3`，是不是要先自己在纸上算出 `FDH`，再把机器码写进去？完全不需要。汇编器会完成这一步。

你写的是：

```asm
MOV AL, -3
```

汇编后，对应的机器指令字节可以表示为：

```text
B0H  FDH
│    └── 立即数 -3 的 8 位补码
└─────── MOV 的操作码：把一个 8 位数送入 AL
```

`B0H` 告诉 CPU 要做“把一个 8 位数送入 AL”这件事；后面的 `FDH` 则是这条指令中要传送的数值。你在源程序里写 `-3`，汇编程序会把它翻译成补码，并把补码放进指令的下一个字节单元。

这就把开头的那个问题彻底接上了：CPU 内部使用二进制，带符号数采用补码表示；但用户编写程序时，可以直接写十进制或负数，汇编器负责完成机器表示的转换。写程序的人不必每次都手工求补码，但必须知道机器里最终放进去的是哪一种码。

### 本讲提到的题目

讲到这里，书中的一道题实际上把与、或、异或三种应用都串了一遍。题目只问指令怎么写，答案也要用同一套位运算规律来解释。

#### 清零 AX 的低四位

题目要求把 `AX` 寄存器的低四位清零，其余位不变。

低四位要清零，掩码低四位就放 `0`；高四位要保持不变，掩码高四位就放 `1`：

```text
1111 0000B = 0F0H
```

因此指令是：

```asm
AND AX, 0F0H
```

`AND` 执行后，目的寄存器 `AX` 的低四位被清零，高四位保持原来的值。

#### 置位 BX 的低四位

题目要求把 `BX` 寄存器的低四位置为 `1`，其余位不变。

低四位要置一，掩码低四位放 `1`；高四位要保持不变，掩码高四位放 `0`：

```text
0000 1111B = 0FH
```

因此指令是：

```asm
OR BX, 0FH
```

`OR` 执行后，`BX` 的低四位变成 `1`，高四位仍保持原来的值。这里同样别忘了，掩码中放 `0` 的位不会被改变。

#### 取反 AL 的高四位

题目要求让 8 位寄存器 `AL` 的低四位保持不变，高四位取反。

高四位要取反，掩码高四位放 `1`；低四位要保持不变，掩码低四位放 `0`：

```text
1111 0000B = 0F0H
```

因此指令是：

```asm
XOR AL, 0F0H
```

高四位原来是 `0` 就翻成 `1`，原来是 `1` 就翻成 `0`；低四位异或 `0`，保持不变。这个例子也再次说明，遇到“指定位取反、其余位不变”，首先要想到 `XOR`，而不是 `AND` 或 `OR`。

## 补码运算、状态标志与十进制调整
> 对应块：BLK05 | 覆盖分集：P10-P11 | 块标题（分集名）：《10》

先把最容易搞错的地方钉死：正数 $53$ 加正数 $91$，数学上的和是 $144$，已经超过 8 位补码所能表示的最大正数 $127$。可 CPU 仍然按 8 位做加法，最低 8 位算出来是 `1001 0000`，最高位成了 1。再把这个 8 位模式按补码解释，看上去就成了负数。

两个正数相加，怎么最后成了负数？不是 CPU 凭空算错，而是结果已经越出了字长范围。我们若还把这个截断后的模式当成 $144$，就彻底错了。

所以，做补码运算不能只问“算出来是多少”，还必须追问两件事：这个结果有没有溢出？CPU 又是通过哪些状态标志把运算情况告诉我们的？

### 补码加法与溢出

#### 加法公式与字长范围

正数、负数统一用补码表示以后，补码加法有一条很干脆的公式：

$$
[x+y]_{\text{补}}=([x]_{\text{补}}+[y]_{\text{补}})\bmod 2^n
$$

这里的 $n$ 是字长。也就是说，先把两个数的补码当二进制数相加，结果只保留 $n$ 位。

8 位补码的表示范围是 $-128\sim 127$，16 位补码的表示范围相应扩大。运算结果一旦超出该字长能够表示的范围，机器就放不下了，这种现象叫作**结果溢出**。别把“结果溢出”和“最高位产生进位”混成一件事；进位由 `CF` 反映，溢出由 `OF` 反映，二者各有自己的用途。

先看一个不会溢出的例子：$53+31=84$。84 小于 127，完全在 8 位补码范围内，所以结果正确，不溢出。

再看会溢出的例子：$53+91=144$。144 虽然可以写成十进制数，却超过 8 位补码的最大正数 127，所以结果无法用 8 位补码正确表示。

> **结论**：补码相加可以直接交给二进制加法器完成，但这只保证“低 $n$ 位算得对”。要不要把结果解释成原来的有符号数，还要另外检查溢出。

#### 抓住符号位前后的两个进位

判断补码加法是否溢出，要盯住符号位附近的两个进位：一个是**进入最高符号位的进位**，另一个是**离开最高符号位的进位**。

- 要进都进：没有溢出。
- 不进都不进：没有溢出。
- 只有一个进：发生溢出。

这不是另造出来的判断法，它直接来自“同号数相加，结果应当仍是同号”的事实。两个正数相加如果得到负的补码模式，或者两个负数相加得到正的补码模式，都说明结果越界了。

把两个例子真正摆到二进制里，区别就非常清楚。

$53+31$，$53=0011\,0101_2$，$31=0001\,1111_2$：

```text
  0011 0101
+ 0001 1111
-----------
  0101 0100     = 54H
```

进入符号位的进位为 0，离开符号位的进位也为 0；结果是 `0101 0100`，最高位为 0，按补码解释就是正数。两个进位一致，没有溢出。

$53+91$，$53=0011\,0101_2$，$91=0101\,1011_2$：

```text
  0011 0101
+ 0101 1011
-----------
1 1001 0000     = 190H
```

第 7 位之外产生了最高位之外的进位，但运算器只保留 8 位，留下 `1001 0000`。这时进入符号位和离开符号位的进位不一致，`OF` 会被置 1。最醒目的旁证就是：两个正数相加，最低 8 位的结果最高位却成了 1，按补码只能解释成负数。

> **易错点**：不能只看最高位是不是 1 就断言溢出。单个负数的补码最高位本来就会是 1；必须结合同号相加后的结果，或直接检查 `OF`。对补码加法，进入和离开符号位的进位相同表示不溢出，不同表示溢出。

### 六个状态标志分别说明什么

8086 做完一次运算后，会把与结果有关的状态写回处理器状态字 PSW。这里集中看六个标志：`OF`、`SF`、`CF`、`ZF`、`PF` 和 `AF`。

| 标志 | 看什么 | 何时置 1 |
| :--- | :--- | :--- |
| `OF` | 溢出标志，判断补码结果是否越出可表示范围 | 同号数相加却得到异号结果时置 1 |
| `SF` | 符号标志，直接取结果最高位 | 结果最高位为 1 |
| `CF` | 进位标志，观察最高位是否向前进位；减法时观察借位 | 最高位向前进位或减法发生借位时置 1 |
| `ZF` | 零标志，观察结果是否全为 0 | 结果为 0 |
| `PF` | 奇偶标志，只检查结果低 8 位中 1 的个数 | 1 的个数为偶数时置 1 |
| `AF` | 辅助进位标志，观察第 3 位是否向第 4 位进位 | 第 3 位向第 4 位进位时置 1 |

这六个标志不是六个彼此孤零零的小开关。`OF` 管补码溢出，`SF` 和 `ZF` 描述结果，`CF` 记录最高位之外的进位或借位；`PF` 和 `AF` 看起来不起眼，一个服务于串行通信，一个专门为后面的 BCD 运算准备。

#### 奇偶标志为什么与串行通信有关

存储器一个单元就是一个字节，8086 的运算又可能是 8 位，也可能是 16 位，但 `PF` 始终只检查结果低 8 位中的 1。这一点很容易漏掉。

串行通信不是把一个字节的 8 位同时传过去，而是从第 0 位开始，一位一位发送。假如数据本身占第 0～6 位，就可以把第 7 位留作奇偶校验位：发送端和接收端预先约定使用奇校验还是偶校验。

以偶校验为例，发送端会统计整组数据中 1 的个数，并自动选择第 7 位，使发送出去的完整 7 位数据加上校验位以后，1 的总数为偶数。接收端收到后再做同样检查：符合约定，认为这一帧数据正确；不符合，就说明传输出了问题。

因此，处理器里的 `PF` 为 1，表示结果低 8 位中 1 的个数为偶数。串行通信接口正是利用这一性质在数据位之外附加校验信息。

#### 辅助进位为什么必须存在

`AF` 看的不是整个字节，而是第 3 位向第 4 位：

$$
b_3 \longrightarrow b_4
$$

二进制运算中，第 3 位向第 4 位进位，说明低 4 位至少累加到了 $16$；没有进位，则低 4 位结果最多是 $15$。可是在 BCD 码里，一个十进制数字只占 4 位，低 4 位一旦超过 9，就应该按十进制向高半字节进 1。`AF` 记录的正是这种“半字节进位”，所以它也叫辅助进位或半进位。

> **提示**：`AF` 不是在断言“四位二进制数已经溢出”。二进制四位要到 16 才进位，十进制一位到 10 就要进位。BCD 运算恰好需要知道这个差别，所以处理器专门留下 `AF`。

### 补码减法为什么可以变成加法

#### 两条减法公式

有了补码，减法也有一条直接公式：

$$
[x-y]_{\text{补}}=[x]_{\text{补}}-[y]_{\text{补}}
$$

还可以继续改写为：

$$
[x-y]_{\text{补}}=[x]_{\text{补}}+[-y]_{\text{补}}
$$

第二条式子才是关键：把减法变成了加法。

先看 $5-3$。按 8 位补码表示：

- $[5]_{\text{补}}=0000\,0101_2$；
- $[3]_{\text{补}}=0000\,0011_2$；
- $[-3]_{\text{补}}=1111\,1101_2$。

按第二条公式计算：

```text
  0000 0101
+ 1111 1101
-----------
1 0000 0010
```

最高位之外产生了进位，运算器保留低 8 位，得到 `0000 0010`，正是 $+2$。换一种写法，直接算 $[5]_{\text{补}}-[3]_{\text{补}}$，结果同样是 `0000 0010`。两条公式不是给出两个答案，而是在用两种路径算同一件事。

这一次运算后的状态也能逐个读出来：结果是 `0000 0010`，所以 `ZF=0`、`SF=0`；最高位向外没有进位，所以 `CF=0`；第 3 位向第 4 位有进位，所以 `AF=1`；最高位与次高位都没有向前进位，两个进位相同，因此 `OF=0`；结果低 8 位中只有一个 1，是奇数个，所以 `PF=0`。

#### 已知补码求相反数

把减法统一成加法，还需要一个配套动作：已知 $[y]_{\text{补}}$，怎样求 $[-y]_{\text{补}}$？

最直接的办法是各位取反、末位加 1：

$$
[-y]_{\text{补}}=\overline{[y]_{\text{补}}}+1 \pmod{2^n}
$$

例如 $y=-3$，已知：

$$
[y]_{\text{补}}=1111\,1101_2
$$

先取反：

```text
取反：  0000 0010
末位加一：0000 0011
```

得到的就是 $+3$ 的补码，也就是 $[-y]_{\text{补}}=0000\,0011_2$。

这个“已知原数补码求其相反数补码”的过程，就是**取补**，也称为**变补**或**求补**。有了它，减法表达式中的 $-[y]_{\text{补}}$ 就能转成 $[-y]_{\text{补}}$，于是减法变成了加法。

#### CPU 为什么愿意付出这点转换成本

手工运算时，我们直接加减当然很顺手，可对 CPU 来说，关键在于硬件能否更简单。

在数字电路里，加法器与减法器并不是同等复杂。既然减法已经统一成加法，CPU 的 ALU 就可以围绕加法器设计，让减法指令进入同一套加法通路，再用取补逻辑处理第二个操作数。

这样做有两笔直接收益：一是把减法纳入成熟的加法通路，提高运算速度；二是简化 ALU 电路，减少硬件体积。

> **结论**：补码不只是一个负数的表示方案，它还把减法吸收进加法。表示方式、运算规则和 CPU 电路设计在这里合到了一起。

### 补码运算结果仍然是补码

两个用补码表示的数相加或相减，得到的低 $n$ 位结果仍是补码形式。我们不能因为机器内部保存的是一个位模式，就把它直接当成原码或十进制数值。

看 $-11+(-3)$。8 位补码下：

- $[-11]_{\text{补}}=1111\,0101_2$；
- $[-3]_{\text{补}}=1111\,1101_2$。

相加：

```text
  1111 0101
+ 1111 1101
-----------
1 1111 0010
```

丢掉第 9 位以后，结果是 `1111 0010`。这正是 $-14$ 的补码：

```text
-14 的原码：     1000 1110
取反：           0111 0001
末位加一：       0111 0010
```

但原码前面还要保留负号，因此 $-14$ 的补码就是 `1111 0010`。

这次运算中，低半字节的 `0101 + 1101` 产生了第 3 位向第 4 位的进位，所以 `AF=1`；最高位也向外产生了进位，所以 `CF=1`。两个进位行为相同，`OF` 为 0。运算结果最高位为 1，`SF=1`；结果不为 0，`ZF=0`。

如果想知道这个补码究竟代表十进制多少，就对它再求一次补：`1111 0010` 取反得到 `0000 1101`，再加 1 得到 `0000 1110`，即 14；结合原码的符号位，结果就是 $-14$。

> **易错点**：CPU 交出来的“运算结果”首先是补码位模式，不是自动附送一份十进制答案。需要真值时，再取补还原。

### BCD 码让二进制机器处理十进制

这里要重新抓住第一章的一条主线：程序里经常做十进制运算，可 CPU 不会因此改用十进制电路。CPU 永远把寄存器中的位模式当二进制数看；程序员采用什么方式解释这些位，是程序员这一侧的事情。

#### 8421 码与一个十进制数字

十进制数字 $0\sim 9$ 一共有 10 个状态，至少要用 4 位二进制表示。4 位本来能表示 16 个状态，我们只取其中前 10 个，让每一位的权值仍然是 $8、4、2、1$：

| 十进制数字 | 8421 码 |
| :---: | :---: |
| 0 | `0000` |
| 1 | `0001` |
| 2 | `0010` |
| 3 | `0011` |
| 4 | `0100` |
| 5 | `0101` |
| 6 | `0110` |
| 7 | `0111` |
| 8 | `1000` |
| 9 | `1001` |

这就是 8421 码，也叫 BCD 码。它的关键不是“四位里随便挑十个状态”，而是让每个编码对应权值之和恰好等于十进制数字本身：`0101` 的权值和是 $4+1=5$，`1001` 的权值和是 $8+1=9$。

#### 组合 BCD 与分离 BCD

存储器按字节组织，8086 内部也有 8 位和 16 位运算部件。一个字节有 8 位，正好可以容纳两个 4 位 BCD 数字；也可以让一个十进制数字独占一个字节。

| 表示方法 | 一个字节里怎样放 | 十进制 53 的存放形式 |
| :--- | :--- | :--- |
| 组合 BCD | 高 4 位放十位，低 4 位放个位 | `0101 0011`，即 `53H` |
| 分离 BCD | 每个数字占一个字节，不用的高 4 位通常置 0 | 5 存为 `0000 0101`，3 存为 `0000 0011` |

组合 BCD 把两个十进制数字压缩在一个字节里，也叫压缩 BCD；分离 BCD 则让每个十进制数字各占一个字节。

无论程序员把 `53H` 解释成“十进制 53 的组合 BCD”，还是把 `35H` 解释成普通十六进制数，CPU 都不会区别对待。寄存器里只有 1 和 0，ALU 只做二进制加法。

> **提示**：BCD 是程序员赋予位模式的一种解释方式，不会改变 CPU 的运算电路。运算结束前，处理器并不知道这些位正在代表十进制数字。

#### 为什么 BCD 运算后必须调整

问题恰恰出在“CPU 只做二进制加法”。

十进制个位 $3+8$ 应该等于 11，必须满 10 进 1；二进制低半字节做同样加法却只得到 `1011`，也就是十六进制的 B，它已经超过 9，却还没有达到二进制进位所需的 16。结果没有进位，CPU 不会自动把十位加 1。

所以，使用 BCD 时，CPU 先按二进制算出位模式，程序员或专门的调整指令再把二进制结果修正成正确的 BCD 结果。组合 BCD 与分离 BCD 的存放方式不同，调整方法也不同。

### 组合 BCD 的 $53+28$ 为什么要加 6

假设寄存器里的 `53H` 和 `28H` 不是普通十六进制数，而是十进制 53 与 28 的组合 BCD。CPU 执行二进制加法：

```text
  0101 0011
+ 0010 1000
-----------
  0111 1011     = 7BH
```

如果把它直接按二进制数解释，`7BH` 就是 123；但程序员想要的十进制答案是 81。错在哪里？错在低半字节：$3+8=11$，十进制要进位；二进制却只得到 `1011`，没有进位。

从 `1011` 到正确的 BCD 低位 `0001`，中间需要把十进制进位补回来。直接加 6：

```text
  0111 1011
+ 0000 0110
-----------
  1000 0001     = 81H
```

`1011 + 0110 = 1 0001`，低 4 位留下 `0001`，进位进入高半字节，高半字节由 7 变成 8。为什么要加 6？因为二进制低 4 位在 10 以后要到 16 才进位，而十进制在 10 就进位，二进制与十进制的进位边界差 $16-10=6$。加 6，正好把少掉的那次进位补出来。

> **定义**：低半字节结果大于 9 时加 `06H`，是在补偿“10～15 这一段没有按十进制进位”的差额。

调整低半字节不能只盯着它是否大于 9，还要看 `AF`。如果低半字节结果没有超过 9，但第 3 位向第 4 位产生了进位，说明二进制进位已经发生，而这次进位未必对应十进制进位，同样要加 `06H`，把不该保留的多余进位拉回来。

高半字节再按同样思路处理：检查它是否超过 9，也检查低半字节调整后是否向高半字节产生了进位，也就是 `CF`。需要调整时，向高半字节加 `60H`。

在 $53+28$ 这个例子里，调整后的 `81H` 高半字节是 8，不超过 9，而且没有最高位之外的进位，因此高半字节不用再调整，最终得到正确的十进制 81。

把调整过程压缩成几条判断，就是：

- 低半字节大于 9，或者 `AF=1`，加 `06H`；
- 再看高半字节是否大于 9，或者 `CF=1`；成立则加 `60H`。

### 几条边界要分清

**进位不等于溢出。** `CF` 反映最高位之外的进位或借位，更适合判断无符号数范围；`OF` 反映补码的有符号溢出。一个数完全可能既不进位也不溢出，也可能进位成立却没有补码溢出。判断 $53+91$ 这样的有符号加法，要盯 `OF` 和符号位附近的进位关系。

**补码结果不是原码结果。** 两个补码数算完，低字节能直接保留为结果的补码；需要真值时再求补还原，不能把同一个位模式一会儿当补码、一会儿当原码。

**BCD 是解释方式，不是另一套加法器。** 程序员把位模式看成 8421 码，CPU 仍只做二进制运算。组合 BCD 的“加 6”是在二进制结果上做的十进制调整，处理器本身并不会因为看到 BCD 编码就自动理解十进制。

**六个状态标志各管各的。** `OF` 看溢出，`SF` 看结果符号，`ZF` 看零，`CF` 看最高位进位或借位，`PF` 看低 8 位的奇偶性，`AF` 看半字节进位。前面先把它们的职责分清，后面的串行校验和 BCD 调整才不会变成互不相干的死记硬背。

把整条线压缩成一句话，就是：补码让有符号数的加减都能落进统一的二进制运算，状态标志再把溢出、进位、符号以及半字节变化如实暴露出来；遇到十进制数据时，程序再借助 `AF`、`CF` 把二进制结果调整成 BCD 结果。

> **承前启后**：上一节讲完「补码运算、状态标志与十进制调整」，下一节接着讲「BCD 调整与 8086 外部结构：把编码和总线接成一条线」。

## BCD 调整与 8086 外部结构：把编码和总线接成一条线
> 对应块：BLK06 | 覆盖分集：P12-P13 | 块标题（分集名）：《12》

先问一个很小的问题：程序里写下一个 `ADD`，BCD 加法的结果就一定对了吗？不一定。CPU 内部始终按二进制把结果算出来，BCD 有自己的编码规则，算完还得再调一次。顺着这种"算完要修正"的思路往前推，字符编码、汇编程序里的输入输出、8086 的引脚和总线，其实都在回答同一类问题——信息以什么形式送出去，又以什么形式收回来。这一块从第一章末尾的 BCD 调整和字符编码，一直讲到第二章开头的 8086 外部结构。

### BCD 运算后为什么还要调整

#### 调整指令归在算术运算里

编程时遇到 BCD 加法，第一反应是"这条调整指令到哪儿去找"。第三章 3.6 节以后讲的全部是指令，而 BCD 数运算后的调整，连同加法、减法、乘法、除法，逻辑上都属于算术运算指令。算术运算本身在 3.5 节，BCD 调整对应 3.5.6 节，最后翻到第 53 页，"BCD 数运算后结果的调整指令"就在那里。

> **易错点**：不要把 BCD 调整当成一套独立于算术运算之外的新指令。找它，要到算术运算指令这一类里去找。

还有一层定位必须记牢：被调整的结果，CPU 默认就从 `AL` 里取。所以 BCD 运算的目的操作数应该选 `AL`；程序里先用 `ADD` 算出结果，再执行调整指令，中间这一步衔接不能漏。

#### DAA 与 AAA 各管哪一种 BCD

`DAA` 是组合 BCD 加法后的调整指令，它没有操作数，调整对象就是 `AL`。组合 BCD 把两个十进制数字装进一个字节的两个半字节，低半字节和高半字节各表示一位十进制数；CPU 先按二进制在 `AL` 里加出结果，再由 `DAA` 修正。

调整要认准两条原则：要么本位超过 9；要么本位没超过 9，但低位已经向本位产生了进位。这两种情况都处理，BCD 结果才摆正。只盯着"当前位是不是大于 9"，最容易把带进位的那一路漏掉，听懂了没有。

分离 BCD 的加法用 `AAA` 调整。加法和减法都要分组合 BCD 与分离 BCD 两条路；乘法和除法只能处理分离 BCD，没有组合的。

> **结论**：先看运算种类，再看 BCD 形式。组合 BCD 加法用 `DAA`，分离 BCD 加法用 `AAA`；乘除法只走分离 BCD。任何 BCD 运算都是先算后调，调的指令选对了，这段程序才算写完。

| 加法的数据形式 | 调整指令 |
| --- | --- |
| 组合 BCD | `DAA` |
| 分离 BCD | `AAA` |

### 字符不能直接当数字用

#### 三个数据对象，三句话

第一章还有一个知识点，讲得粗一两分钟就解决战斗，讲得细得半个小时——这就是字符和它的编码。回看从第一节课到现在讲过的话：计算机中的数均用二进制表示；计算机中的带符号数用补码表示；计算机中的字符用 ASCII 码表示。三句话里全是可以填空的知识点，考试考什么就考黑板上的这句话。因此上课不能缺课，旷一次课，可能只是一个知识点抓不住，第二节和后续内容就连贯不起来了。

ASCII 码在汇编语言程序设计中最常用。可显示字符里，数字字符 `'0'`～`'9'` 必须掌握，十六进制表示中还会用到的 `'A'`～`'F'` 也必须掌握。编译、汇编之后，字符是用它对应的 ASCII 码存到机器里的，所以字符 `'0'` 加了单引号就不再是数值 0，而是编码 `30H`。

| 字符 | ASCII 码 |
| --- | --- |
| `'0'`～`'9'` | `30H`～`39H` |
| 大写 `'A'`～`'F'` | `41H`～`46H` |
| 小写 `'a'`～`'f'` | `61H`～`66H` |

`'0'` 是 `30H`，`'1'` 是 `31H`，一直到 `'9'` 是 `39H`；大写 `'A'` 是 `41H`，大写 `'F'` 是 `46H`；小写 `'a'` 是 `61H`，小写 `'f'` 是 `66H`。有些同学编程序时十六进制数用大写 `A`～`F`，有些用小写 `a`～`f`，两套字符编码都要掌握。

> **提示**：源程序里的 `'0'` 只是一个字符符号，汇编之后才以 `30H` 的形式存进机器。写程序时看到 `'0'`，不要直接当成数值 0 送去做算术。

#### 键盘输入的是字符，显示出来的也是字符

假设程序让 CPU 运算，而原始数据来自键盘。你从键盘上敲一个 `1`，计算机里获取到的不是数值 1，而是字符 `'1'` 的编码 `31H`——键盘输入进来的都是字符。反过来，屏幕上显示的也都是字符：如果运算结果是数值 2，要把它送到屏幕上显示，得先把这个 2 转换成字符 `'2'`，它的编码是 `32H`，送到显示器的对应位置，光标处才会出现一个 `2`。

```text
键盘 ──字符编码──► CPU 做运算 ──数值结果──► 转成字符编码──► 屏幕
   '1' = 31H                                2 ──► '2' = 32H
```

两端都是字符，中间是数值运算，所以程序里总要把"字符"和"数值"来回转换。

#### 字符和数值之间来回换

输入的是数字字符 `'0'`～`'9'` 时，要转成数值 `0`～`9`，可以减去 `30H`；也可以与 `0FH`，把高四位清零、低四位原样保留。比如字符 `'1'` 的编码是 `31H`，两种做法都能得到数值 1。

```text
'1' 的编码        31H
减去 30H          31H - 30H = 01H      得到数值 1
或者与 0FH        31H AND 0FH = 01H    得到数值 1
```

如果输入的是大写字母形式的 `'A'`～`'F'`，要转成对应的数值 `10`～`15`，减去多少呢？减去 `37H`。以 `'A'` 为例，它的编码是 `41H`，$41H-37H=0AH$，正好是数值 10。

反过来，数值转字符也是找编码之间的差：数值 `0`～`9` 转成数字字符，分别加上 `30H`；数值 `10`～`15` 转成大写字母 `'A'`～`'F'`，分别加上 `37H`。

> **易错点**：这些偏移量不是凭感觉记的。先看字符的编码，再看目标数值或目标字符的编码，两者之间的差就是该加或该减的量。

### 大小写转换：别先判断，直接动一位

有时候还要做大写字符与小写字符之间的相互转换。传统程序设计的做法，是先判断 `AL` 里的字符在什么区间：比一比它是不是小于 `61H`，如果小于，多半已经是大写，不用动；确认是小写，再减去 `20H` 转成大写。程序这样写并不复杂，但总得几条语句，设计起来也麻烦。

这里干脆不判断，用逻辑运算直接做。

```text
大写 'A'       41H = 0100 0001
小写 'a'       61H = 0110 0001
                        ↑
                    第 5 位不同
```

规律自己会冒出来：大写字母从 `'A'` 往后数到 `'Z'`，编码从 `41H` 到 `5AH`，高位始终是 `0100`～`0101`；小写字母从 `'a'` 往后数到 `'z'`，编码从 `61H` 到 `7AH`，高位始终是 `0110`～`0111`。两串范围一一对齐，只有第 5 位不一样，其他位置完全相同。

#### 清除第 5 位：字母转大写

要把 `AL` 中的字母变成大写，就给第 5 位清零。`0DFH` 的二进制形式是 `1101 1111`，对应 `20H` 的那一位是 0，其他需要保留的位都是 1，所以标准答案是：

```asm
AND AL, 0DFH
```

原来是小写，转完成为大写；原来已经是大写，第 5 位本来就是 0，清掉它结果仍是大写。`AL` 里放的是 `A`～`Z` 还是 `a`～`z` 都可以，不用事先弄清楚。

写成 `AND AL, DFH` 同样对，那个 `0` 只是把十六进制数的高位补出来，含义不变。考试时就算只写 `DFH` 也算对。

这里还能再想深一层：ASCII 码原本是 7 位，每个字符用 7 位二进制表示；计算机存放数据的最小单位是 8 位字节，所以 7 位的 ASCII 放进字节时，高位补一个 0。凡是字符，高位肯定是 0；高位不是 0 的 8 位数，肯定不是普通字符。指令里那个 `0`，对应的正是字符码高位为 0 这个概念。

#### 置位第 5 位：字母转小写

反过来，把 `AL` 中的字母变成小写，就给第 5 位置 1：

```asm
OR AL, 20H
```

大写字母的第 5 位是 0，置 1 之后，其余位不变，正好得到对应的小写字母。`100H` 或 `20H` 都是置这个位，标准答案写成 `OR AL, 20H`。

这种办法在实际程序设计的工程应用中是最简单的。指令条数越少，CPU 执行速度越快，而速度本来就是程序设计的指标之一。有些控制应用领域不一定特别追求速度，可导航、军事作战等场合，速度重要吗？显然重要。

> **结论**：`AND AL, 0DFH` 把字母转成大写，`OR AL, 20H` 把字母转成小写。核心只有一句话：大小写之间只差第 5 位。

### 8086 的外部结构：芯片外面看得见什么

第一章讲完，进入教材第二章 8086 CPU 的结构与功能，实质上就是微处理器的结构与功能。我们这门课用的微处理器型号是 8086，所以重点以 8086 来讲。第一章讲数制与码制时，已经把不少概念提前揉进来了，现在要把它们接起来。

学 CPU 的结构和功能，要分两步：先看外部结构，再看内部结构，通过内部结构去掌握它的工作原理和编程模型。外部结构是从宏观上看芯片长什么样、信号从哪里进出；具体到每个引脚是什么功能，就放到第五章 5.3 节从微观上看。

> **结论**：2.1 节讲的是微处理器的外部结构，宏观视角；5.3 节也讲外部结构，微观视角，落在具体引脚上。

#### 数量有限的引脚，承载三类信息

> **定义**：微处理器的外部结构，表现为数量有限的输入、输出引脚。

你买到一颗 CPU 芯片，拿在手里看到的就是一排引脚，数量有限。这些引脚按功能分成三类：传送数据的叫数据引脚，专门向外部发送地址的叫地址引脚，说明读写等条件的叫控制引脚。为什么正好分三类？因为芯片与外部存储器、I/O 接口之间传送的信息，就是数据信息、地址信息和控制信息三组。

地址引脚最关键。CPU 把要操作的地址码放到地址总线上，靠地址码去寻址，找到具体要访问的存储器单元或者 I/O 接口；CPU 对存储器单元、I/O 接口的读写操作，就是靠地址总线上的地址来识别的。

```text
数据信息 ──► 数据引脚 ──┐
地址信息 ──► 地址引脚 ──┼──► 构成微处理器总线
控制信息 ──► 控制引脚 ──┘
```

这几类引脚合起来，构成微处理器总线。CPU 正是通过微处理器总线完成三件事：与外部存储器之间交换信息和数据，总线上传的数据既可能是普通数据，也可能是指令；与 I/O 设备相连的 I/O 接口电路之间交换信息；输入和输出必要的信号，也就是控制信号。

> **注意**：任何 I/O 设备都不能直接和 CPU 通信。设备与系统总线之间必须设计 I/O 接口电路，严格地说，CPU 的信息交换对象是设备对应的 I/O 接口电路，不是设备本身。

顺便把"指令是什么"再钉一遍：指令是一组二进制代码，但不是随随便便的一组二进制代码，它得能告诉 CPU 做什么、怎么做。比如 `MOV AL, 20H`（机器码是 `B0H 20H` 两个字节），它既能读成汇编语句，也是机器语言里的一条指令。这串代码传到 CPU 手上时，走的正是数据信息这条路。

#### 封装和 40 个引脚

芯片拿到手里准备用，第一步先考虑封装。有了封装，才能正确地画出 PCB 印刷电路板，封装不对，图就画不对。

8086、8088 都采用双列直插式封装，芯片两边都有引脚，两边加起来一共 40 个引脚，所以叫"双列"。数字电路实验课上用的 `74LS00`（与非门）、`74LS04`（反相器）、`74LS161`（计数器），也都是这种封装。当然现在也有一些器件采用扁平封装，芯片的一周都有引脚。

40 这个数字要记住，它是后面数引脚的基准。8086 是 16 位微处理器：CPU 内部的寄存器是 16 位的，内部 ALU（算术逻辑单元）是 16 位的，片内数据总线也是 16 位的；和外部存储器或 I/O 接口通信，外部数据引脚也是 16 位，所以它是标准的 16 位微处理器。

8088 不一样。它内部同样是 16 位的，但外部留给我们的数据引脚只有 8 根，也就是 CPU 和外部存储器、I/O 接口之间一次只能传送 8 位数据，所以 8088 叫"准 16 位微处理器"。8086 和 8088 引脚都是 40 个，引脚分布也大体对应，但外部数据宽度不能混为一谈。

> **易错点**：说 CPU 是 16 位，不等于外部数据引脚一定有 16 根。判断一次能传多少位，要看外部数据引脚的实际数量。

#### 图 5.5 里数出来的引脚

想查每个引脚的具体作用，就翻到第五章 5.3 节，教材第 163 页的图 5.5，画的就是 8086 的引脚图。引脚图上有 40 个引脚，从中可以数出数据、地址、控制三类引脚：16 根数据引脚 `D0`～`D15`；`AD0`～`AD15` 这 16 根既作地址又作数据，属于复用引脚；再加 `A16`～`A19` 这 4 根高位地址引脚，16 加 4，一共 20 根地址引脚，地址能力是 20 位。

这些概念——引脚有什么功能、什么时候是什么功能——都要放到第五章去结合时序讲。今天先把外部结构这条主线引出来，知道芯片外面有这些引脚就够了。

#### 复用引脚与时序：同一根线在不同时间干活

芯片体积有限，半导体工艺也有限，8086 却要引出那么多地址、数据、控制信号，不可能每种功能都配一组独立引脚，于是采用了复用引脚。`AD0`～`AD15` 就是这样：在一个指令周期里，它们不是同时既作地址又作数据，而是在不同时间片承担不同任务。

```text
执行一条访问存储器或 I/O 接口的指令，一个指令周期内

┌────────────────────┬────────────────────┐
│      地址阶段       │      数据阶段       │
│ AD0～AD15 输出地址  │ AD0～AD15 传送数据  │
└────────────────────┴────────────────────┘
```

所以学引脚不能只背名字，还要看时序：CPU 执行一条对存储器读或写的指令，执行是需要时间的，在这段时间里，某个时间片 `AD0`～`AD15` 作为地址引脚，另一个时间片再作为数据引脚。引脚叫什么，解决的是"它属于哪一类功能"；引脚的实际关系，就是它在什么时间、以什么电平出现，这才是关键。

#### 从引脚到系统总线

第 12 页的图 2.1 是个示意框图：左边画着 CPU 芯片，数据线、地址线、控制线从芯片引脚上引出来，看上去三类信号各走各的。但实际应用里不行。芯片引脚上出来的可能是复用信号，得先想办法按实际时序把它们分离，让数据走专用的数据总线，地址走专用的地址总线，控制信号走控制总线。

```text
              8086 芯片引脚
      复用引脚 AD0～AD15、控制引脚等
                     │
                     │ 按实际时序分离
                     ▼
          ┌──────────┼──────────┐
          │          │          │
      数据总线 DB  地址总线 AB  控制总线 CB
          │          │          │
          └──────────┼──────────┘
                     │
         ┌───────────┴───────────┐
         │                       │
      存储器                I/O 接口电路
                                  │
                               I/O 设备
```

2.1 节那部分只画了一个简单的框图。工程上从 CPU 引脚引出信号开始，第一步是把三类信号分离开，形成 DB、AB、CB 这三组系统总线，形成实际的电路设计；然后才在这三组系统总线上进行系统扩展设计，配置存储器电路，配置 I/O 接口电路，最后接上 I/O 设备。顺序不能颠倒。

### M/IO：存储器操作和 I/O 操作的分水岭

看第 13 页的第一行，CPU 的这些引脚信号称为微处理器总线。刚才已经说过，8086 对存储器和 I/O 接口都有专门的读写指令，CPU 执行不同的指令，就知道自己这次是对存储器操作还是对 I/O 接口操作。可是站在设计外部电路的角度，光知道执行的是哪条指令不够，你得从引脚信号上看出这一次总线周期的信息到底是发给存储器的，还是发给 I/O 接口的。这个区分信号就是 `M/IO`。

8086 的第 28 脚是 `M/IO`，`M` 是 memory，也就是存储器，`IO` 就是 I/O。CPU 执行一条对存储器操作的指令时，在该指令的总线周期内，这个引脚输出高电平；执行一条对 I/O 操作的指令时，在总线周期内输出低电平。

再看另外两个引脚。第 29 脚是 `WR#`（教材图上写作带上划线的 `WR`），第 32 脚是 `RD#`。名称后面那个小横杠，或者写成 `#`，表示这个信号低电平有效。`WR#` 输出低电平，表示 CPU 正在向外部写数据；`RD#` 输出低电平，表示 CPU 正在从外部读数据。

三个信号合起来，就把"对谁、干什么"说清楚了：读的时候不可能同时写，写的时候也不可能同时读。

| 当前操作 | `M/IO` | `WR#` | `RD#` |
| --- | --- | --- | --- |
| 读存储器 | 高电平 | 高电平 | 低电平 |
| 写存储器 | 高电平 | 低电平 | 高电平 |
| 读 I/O 接口 | 低电平 | 高电平 | 低电平 |
| 写 I/O 接口 | 低电平 | 低电平 | 高电平 |

#### 用门电路形成四类控制信号

有了 `M/IO`、`WR#`、`RD#`，用户设计电路时需要的那几根控制信号，就可以用数字电路课上学过的门电路组合出来。

先看 I/O 操作。`M/IO` 为低电平、`WR#` 也为低电平，两个低电平送进或门，输出仍然是低电平；这个输出有效，就表示 CPU 正在对 I/O 接口写，可以把它标成 I/O 写控制信号。`M/IO` 为低电平、`RD#` 也为低电平，同样经或门得到低电平输出，这就表示 CPU 正在对 I/O 接口读，是 I/O 读控制信号。用非门行不行？也能做出来，但或门最省事。

再看存储器操作。存储器写要求 `M/IO` 为高电平，同时 `WR#` 有效。把这两个信号各取反，都变成高电平，再送进与非门：两个高电平相与再取反，输出为低电平，恰好对应 CPU 正在对存储器写操作，这个信号可以命名为存储器写控制信号（`MWC`）。把 `WR#` 换成 `RD#`，同理可以得到存储器读控制信号。

> **结论**：先用 `M/IO` 选空间，再用 `WR#`、`RD#` 选方向，最后用门电路把四类控制信号整理出来。

> **易错点**：`WR#`、`RD#` 都是低电平有效。题目里若画成带上划线的 `WR`、`RD`，有效电平还是低，别把极性记反。

### 从一颗 CPU 到一个微型计算机系统

视角从一颗芯片再往外扩一层。微型计算机系统的硬件组成，就是以微处理器为核心，利用数据、地址、控制这三类总线，在外部配置一定容量的存储器、一定数量的 I/O 接口电路，再把 I/O 设备接到 I/O 接口上。微处理器、存储器、I/O 接口电路、I/O 设备，加上电源，以及装载在 ROM 存储器里的系统工作程序，合起来才构成一个微型计算机系统。

```text
                  微型计算机系统
                         │
              以微处理器为核心（CPU 芯片）
                         │
              DB、AB、CB 三组系统总线
                         │
          ┌──────────────┴──────────────┐
          │                             │
       存储器                    I/O 接口电路
  （含 ROM 中的系统工作程序）           │
                                     I/O 设备
                         │
                        电源
```

```text
有限引脚 ──► 三类信息 ──► 微处理器总线
```

## 从地址线到 I/O 端口：微处理器怎样和外部世界打交道
> 对应块：BLK07 | 覆盖分集：P14-P15 | 块标题（分集名）：《14》

先把一个看似简单的问题放在桌面上：8086 CPU 一共有多少根地址线？

不是 16 根，而是 20 根。地址线从 `A0` 一直到 `A19`，其中 `A0` 是最低位，`A19` 是最高位。8086 的这 20 位地址全部用于给外部存储器提供地址，所以它能够管理的外部存储器地址空间是：

$$2^{20}=1\,048\,576\text{ 个地址}$$

每个地址对应一个字节，因此 8086 能够寻址的外部存储器空间是 **1 MB**。这里一定要把“按字节组织”说准确：存储器中的每个存储单元存放 8 位二进制信息，8 位就是 1 字节。不能把一个地址理解成“一个没有大小的数字”，它在这里对应的是一个字节单元。

### 地址线数量决定地址空间大小

把 8086 和课外常见的 8051 放在一起比较，差别就很直观。8051 有 16 根地址线，所以它能够寻址的外部存储器空间是：

$$2^{16}=65\,536\text{ 字节}=64\text{ KB}$$

为什么是 64 KB？因为 $1\text{ KB}=1024$ 字节，$65\,536\div1024=64$。说话时一定要标准：64 KB 字节。地址线有几根，就决定了能够组合出多少个不同地址；地址空间按字节组织时，地址数量也就是可以访问的字节数量。

| 对象 | 地址线数量 | 外部存储器地址空间 |
| :--- | ---: | ---: |
| 8086 CPU | 20 根，`A0`～`A19` | $2^{20}$ 字节，即 1 MB |
| 8051 CPU | 16 根 | $2^{16}$ 字节，即 64 KB |

> **结论**：地址总线有多少条，决定了 CPU 能够组合出多少个地址；存储器按字节组织，就决定了这些地址对应多少个字节单元。

不过，8086 还有另一半故事：它的 `A0`～`A15` 不仅可以作为存储器地址使用，也可以作为 I/O 地址使用。也就是说，I/O 端口使用 16 位地址，空间大小是：

$$2^{16}=65\,536\text{ 个 I/O 地址}=64\text{ K 个端口地址}$$

那么问题来了：`A0`～`A15` 上出来的到底是存储器地址，还是 I/O 地址？CPU 怎么知道？

不是靠我们“猜”，而是靠专门的控制信号来区分。这个信号在 8086 中通常记作 `M/IO`。当同一个地址码出现时，存储器访问和 I/O 访问由这个信号告诉外部电路：我现在是在访问存储器，还是在访问 I/O 端口。

所以，8086 虽然有 20 根地址线，存储器空间可以达到 1 MB，但它给 I/O 端口使用的是其中的 16 位地址。存储器地址空间和 I/O 地址空间虽然有一部分地址线重合，性质却由 `M/IO` 区分开。

> **易错点**：不要把“20 根地址线”直接说成“20 位 I/O 地址”。8086 的外部存储器寻址是 20 位，I/O 端口寻址是 16 位；两者的区别不能省。

### 总线是信息传送的通道

接下来把“总线”这个词说清楚。总线不是某一根 mysterious 的线，而是连接 CPU 与其他部件、用来进行信息传送的通道。你可以把不同的功能通道分开看：地址线负责把地址码送出去，数据线负责传送数据，控制线负责传递控制、协调读写所需的信息。

从功能上看，总线可以分成三类：地址总线、数据总线和控制总线。每一种总线都有自己传送的信息和作用，不能把“连上了总线”当成已经理解了总线系统。

```text
                         地址码：A0～A19
                              │
                              ▼
        ┌──────────────────────────────────┐
        │                CPU               │
        │  地址总线   数据总线   控制总线   │
        └───────┬──────────┬─────────┬─────┘
                │          │         │
                ▼          ▼         ▼
             外部存储器   I/O 接口   M/IO 等控制信号
                          │
                          ▼
                     I/O 设备
```

这张图不是让我们把每根线的名字背成一张接线表，而是提醒我们：CPU 要访问外部对象，至少要同时解决三个问题——访问哪个地址、传送什么数据、什么时候进行以及由谁来区分对象。地址、数据、控制三类信息各有通道，外部设备才不会和 CPU “混在一起”说话。

### I/O 设备不能直接和 CPU 通讯

外部设备不能简单地直接和 CPU 通讯。CPU 是一块高速工作的芯片，打印机、键盘以及其他外设却有各自的工作状态和速度。二者之间需要一个专门的接口电路，把 CPU 的总线信号转换成设备能够理解的信息，再把设备的状态和数据转换回来。

这个连接 CPU 与 I/O 设备、负责二者信息交换的电路，就叫 **I/O 接口**。接口并不是一根线的名字，而是一块承担控制与转换任务的电路。

接口里面还要安排一个用于 CPU 和设备之间交换信息的寄存器，这个寄存器叫 **I/O 端口**。CPU 要访问某个端口，就给这个端口分配一个地址，这个地址就是 **I/O 端口地址**。端口是硬件上的信息通道，端口地址是 CPU 找到这条通道的门牌号。

可以把接口、端口和设备的关系看成：

```text
CPU
 │  通过系统总线访问端口地址
 ▼
I/O 接口
 ├─ 端口：传送某一种信息
 ├─ 端口：传送另一种信息
 └─ 若干端口：完成 CPU 与设备的交换
          │
          ▼
      I/O 设备
```

### 一个接口为什么要有多个端口

拿一台并行打印机来想。CPU 要把要打印的数据送给打印机，表面上只要有一条“数据线”不就行了？不行。CPU 还得知道打印机准备好了没有：打印机装纸了吗？连接好了吗？现在是不是正忙着？如果打印机还没有准备好，CPU 不能想发数据就发数据。

于是，CPU 与设备之间至少要交换三类信息：

- **状态信息**：设备现在处于什么状态，是否准备好；
- **数据信息**：CPU 要输出的数据，或者设备要送回来的数据；
- **命令信息**：CPU 用来告诉设备“现在可以取数据了”这类控制信号。

每一种信息都走自己的专用通道，而一个通道就是一个端口。端口有输入端口，也有输出端口。状态从设备送进 CPU，是状态输入端口；CPU 把数据送给设备，是数据输出端口；CPU 通知设备某个动作或时序，是命令输出端口。

```text
                         状态输入端口
                  设备状态 ─────────► CPU
                              │
CPU ─── 数据输出端口 ───► 设备
  │                          │
  └──── 命令输出端口 ───────►│
                             ▼
                          I/O 设备
```

这里的关键不是“端口有名字”，而是端口的分工：一个端口只负责传送一种信息。这样 CPU 读取状态时，不会把状态误当成打印数据；输出数据时，也不会把命令混进数据里。

### 握手：CPU 和设备不能各说各话

CPU 和智能设备之间的信息交换，始终需要一种握手过程。握手不是一句口号，而是双方确认“什么时候可以交换、这一次交换是否完成”的联络过程。

以打印机为例，操作顺序可以这样理解。

第一步，CPU 先通过状态输入端口读取设备状态。程序可以检测状态位，判断设备是否准备好。

第二步，如果设备没有准备好，CPU 就继续读取状态、继续检测，直到设备表示已经准备好。状态不是 CPU 自己猜出来的，而是设备通过端口交给 CPU 的。

第三步，确认设备准备好以后，CPU 才通过数据输出端口把数据送到设备。数据不能只在线上闪一下，因为 CPU 很快，设备却可能很慢。

第四步，数据被输出端口锁存下来以后，CPU 再通过命令输出端口向设备发出相应命令或联络信号，设备接到这个信号后，才去取走数据。这个信号可以理解为“数据现在有效，可以取了”的通知。

```text
CPU                                           设备
 │                                             │
 │  读取状态输入端口                            │
 │────────────────────────────────────────────►│
 │                                             │
 │  状态为“未准备好”，继续查询                 │
 │◄────────────────────────────────────────────│
 │                                             │
 │  状态为“准备好”                             │
 │◄────────────────────────────────────────────│
 │                                             │
 │  通过数据输出端口送出数据                    │
 │────────────────────────────────────────────►│
 │                                             │
 │  数据在输出端口中锁存                        │
 │                                             │
 │  通过命令输出端口发出“数据有效”信号          │
 │────────────────────────────────────────────►│
 │                                             │
 │  设备取走数据                               │
 │◄────────────────────────────────────────────│
```

所以，握手把“数据输出”和“数据有效通知”分开了。数据线上有数据，不等于设备已经知道该在什么时候取走数据；命令和联络信号负责把这个时序关系补完整。

> **提示**：输出端口不仅要“送得出去”，还要“留得住”；命令端口不仅要“发得出来”，还要让设备知道“现在可以取”。这就是输出锁存和握手存在的理由。

### 输入端口必须能主动断开数据总线

状态输入端口里，设备状态先进入端口，再由 CPU 读取。端口的输出端需要接到数据总线上，但数据总线不是只接一个端口：它还要接其他端口、存储器芯片等许多对象。CPU 读哪个对象，就让哪个对象暂时驱动数据总线；没有被选中的对象不能也来驱动它。

因此，输入端口的输出端必须具有三态功能。这里的三态不是“0、1、另一个奇怪的状态”，而是：高电平、低电平和高阻态。高阻态表示这个输出端暂时不主动驱动数据总线，相当于把总线让出来。

CPU 通过端口地址找到状态输入端口时，相应的地址译码和选中信号使端口打开，状态信息被送上数据总线；CPU 不读这个端口时，选中信号无效，端口输出端进入高阻态，不应和其他端口争抢总线。

```text
                   数据总线
          ┌──────────┬──────────┐
          │          │          │
       端口 A     端口 B     端口 C
       选中？      未选中      未选中
          │          │          │
          ▼          高阻        高阻
          └──────────┴──────────┘
```

这里最容易搞错的是：高阻态不是“输出一个 0”。输出 0 仍然是在驱动数据总线；高阻才是暂时不驱动。如果两个端口同时打开，一个输出 1，另一个输出 0，那么同一根数据线上就同时出现了 0 和 1，两个输出端会发生冲突。

这就是数据总线竞争。轻的时候系统可能工作不正常，计算机甚至启动不了；重的时候，输出端之间会产生很大的电流，时间长了器件就可能损坏。实际电路设计中，输入端口的输出器件必须具备三态功能，目的就是保证任何时刻数据总线上最多只有一个输出端在主动驱动。

74LS244 和 74LS245 是这门课里学过的缓冲器例子：244 是单向的，245 是双向的。它们的共同作用，是帮助接口电路按需要连接或隔离数据线的驱动关系。前面说过，学习这门课需要具备数字电路知识，这里就是一个很具体的落点：总线不是“接上就能用”，还要处理方向、使能和高阻。

### 输出端口要把数据锁存起来

输入端口和输出端口的硬件要求不一样。输入端口的核心是三态：不被选中时让出数据总线。输出端口的核心是锁存：被写入以后，数据要保持一段时间，直到设备把它取走。

为什么一定要锁存？因为 CPU 很快，打印机却可能很慢。CPU 把数据写出去以后，转头去干别的事情；如果输出端只把数据短暂地放在线上，设备还没反应过来，数据就消失了。锁存器把数据保存下来，让设备有足够的时间响应。

输出端口里的锁存功能可以用寄存器实现。前面提到的 74LS74 是一个芯片里带两个 D 触发器的例子；如果需要同时处理 8 位，就可以选用带 8 位的 74LS373、74LS274 或 74LS374 这类器件。它们的具体选型属于硬件设计，但背后的道理是同一个：输出数据要能保持，不能随着 CPU 总线的下一次变化而消失。

在有效数据真正写入并锁存之前，输出线上的内容不能被当成有效的打印数据。有效数据写入端口后，线上才保存着这一次要交给设备的内容。可是 CPU 自己知道“我已经写了”，设备却不会凭空知道。设备还需要一个通知，于是命令输出端口或联络信号把“数据有效了”告诉设备。

在刚才的说明里，举过用一根控制线输出低电平来表示数据有效的例子。这里要抓住的是通知关系，不要把某一个电平例子误认为所有设备都必须采用同一种有效电平。不同设备的具体约定可以不同，但“数据写好”和“通知设备取数据”是两个动作。

### 一个端口至少占一个地址

端口和地址的关系，可以拿房间号来打比方。一个房间至少要有一个房间号；一个 I/O 端口至少也要分配一个 I/O 端口地址。通常一个端口使用一个地址。

8086 的 I/O 地址空间是 16 位的，因此有 64K 个 I/O 地址。如果一个端口只占一个地址，最多就可以安排 64K 个端口地址。实际设备中，一个端口也可能占用一段地址。

例如，某个设备寄存器分配了 `210H`～`219H` 这一段地址，那么程序中写 `210H` 时就可以访问它，但 `211H`～`219H` 也已经被这个端口占用了，地址空间不能再分配给别的端口。你可以把它想成一套房间：房间 210 占了一整段 210～219，那么这十个门牌号就不能再挂到另一套房间上，否则地址就重叠了。

> **易错点**：端口地址可以有重叠使用的前提，是对重叠的那一段地址都作保留；不能只占用了地址的起点，却把后面的地址又分给其他端口。

### 统一编制和独立编制

外部 I/O 端口怎么编址？有两种方法：统一编制和独立编制。这两个词听起来像术语，其实只要抓住一句话：存储器和 I/O 端口是不是放在同一个地址空间里。

#### 统一编制

统一编制就是把存储器和 I/O 端口放进同一个地址空间。一个地址码要么对应一个存储单元，要么对应一个 I/O 端口寄存器，不能一会儿是存储器、一会儿又是 I/O 端口。

换句话说，CPU 把外部存储器和外部 I/O 端口看成同一类对象：只要给出地址，CPU 就可以像访问存储器一样访问它们。某个地址已经分给 I/O 端口，就不能再分给存储器；否则地址的含义就不唯一了。

它的缺点很直接：给 I/O 端口分配了地址，存储器的可用地址空间就会相应减少。统一编址等于把一块地址空间同时拿给存储器和 I/O 使用，I/O 占得越多，留给存储器的空间就越少。

但是它的优点也很明显。既然 I/O 端口被当成存储器单元，那么对存储器进行读写操作的那些指令，同样可以用于 I/O 端口。CPU 不必另外设计一套专用的 I/O 操作指令，程序写起来更简单，寻址也更灵活。

我刚才说“没有优点”当然是在逗你——真正的优点就在这里：不用为了访问一个 I/O 端口，额外背一套完全不同的操作习惯。MCS-51 系列的 CPU 采用的就是这种 I/O 统一编址方式，8031、8051 等单片机都可以作为例子。

#### 独立编制

独立编制则把存储器地址空间和 I/O 地址空间分开，二者互不占用。8086 就是这种例子：它有 20 位存储器地址，也有 16 位 I/O 地址；`A0`～`A15` 上可能同时出现存储器地址和 I/O 地址，但 `M/IO` 信号会告诉外部电路当前访问的是哪一类对象。

独立编制的优点是 I/O 不占用存储器地址空间，存储器地址空间可以完整保留。它的代价也很明显：访问存储器和访问 I/O 端口要用不同的指令，程序员要同时记忆两套操作方法；而且 I/O 的寻址方式比存储器少，程序设计的灵活性会受到影响。

在本讲涉及的 8086 中，对存储器的操作有五种寻址方式，而对 I/O 端口的操作只有两种。寻址方式越少，能形成有效地址的办法就越少，所以独立编址虽然省下了地址空间，却让 I/O 程序没有统一编址那么灵活。

| 比较项目 | 统一编制 | 独立编制 |
| :--- | :--- | :--- |
| 地址空间 | 存储器与 I/O 共用一个空间 | 存储器与 I/O 分开 |
| 一个地址的含义 | 要么是存储单元，要么是 I/O 端口 | 由所属地址空间决定 |
| I/O 使用的指令 | 可使用存储器操作指令 | 使用专门的 I/O 指令 |
| 地址空间代价 | I/O 会占用存储器地址 | I/O 不占存储器地址 |
| 程序特点 | 编写方便、寻址灵活 | 指令和寻址方式需要分别记忆 |

> **易错点**：统一编制的关键不是“地址码更多”，而是“同一个地址不能在同一种编址中既指存储器又指 I/O”。独立编制的关键也不是“完全没有公共地址线”，而是由控制信号把两个空间的访问区分开。

### 寻址就是找到要操作的对象

无论是读存储器、写存储器，还是读写 I/O 端口，CPU 都要先找到目标对象的地址。找到地址的办法，就叫寻址。存储器操作有多种寻址方式，方式越多，程序组织起来就越灵活。

先看直接寻址。假设要把 `AL` 中的 8 位数据写入地址 `2000H` 对应的存储单元，可以先给 `AL` 放一个数据，再执行：

```asm
MOV AL, 0AH
MOV [2000H], AL
```

这里中括号是关键。`2000H` 如果不加中括号，处理器会把它当成指令中的数据；加上中括号以后，它表示“地址为 `2000H` 的存储单元”。因此第二条指令的意思是：把 `AL` 的内容写入 `2000H` 所指向的地址单元。指令中直接给出目标单元的地址，这种方式就是直接寻址。

再看间接寻址。目标地址不直接写在指令里，而是先放进 `BX`：

```asm
MOV BX, 2000H
MOV [BX], AL
```

`BX` 是 CPU 内部的 16 位地址寄存器。第二条指令中的 `[BX]` 仍然表示一个存储单元，但这个单元的地址不是直接写出来的，而是从 `BX` 中间接取得的。`BX` 的内容是多少，CPU 就到哪里去写数据。

```text
直接寻址：
        指令中直接出现地址 2000H
                         │
                         ▼
                 找到 2000H 单元

间接寻址：
        指令中出现 [BX]
                 │
                 ▼
          从 BX 取出实际地址
                         │
                         ▼
              再找到目标存储单元
```

所以，读写存储器时，CPU 的工作可以概括成两件事：先根据寻址方式得到有效地址，再把数据读出或写入这个地址。写操作和读操作的具体指令不同，但“先找到地址”这一步是共同的。

这也解释了为什么统一编址的程序通常更灵活：I/O 端口既然被看成存储器单元，就可以借用存储器的操作指令和寻址方式。独立编址则需要专门为 I/O 设计指令，8086 的 I/O 寻址方式只有两种，程序能选择的变化自然少一些。

### 把整个 I/O 通路串起来

现在把前面的部件放在一张完整的图里，CPU、地址总线、数据总线、控制信号、接口端口和设备之间的关系就比较清楚了。

```text
                    ┌─────────────────────┐
                    │        CPU          │
                    │                     │
                    │ 地址总线 A0～A19    │
                    │ 数据总线 DB         │
                    │ 控制总线、M/IO      │
                    └──────────┬──────────┘
                               │
              ┌────────────────┼────────────────┐
              │                │                │
              ▼                ▼                ▼
          外部存储器       I/O 接口          其他 I/O 设备
                           │
              ┌────────────┼────────────┐
              │            │            │
              ▼            ▼            ▼
        状态输入端口   数据输出端口   命令输出端口
        设备 → CPU    CPU → 设备     CPU → 设备
              │            │            │
              └────────────┴────────────┘
                           │
                           ▼
                     设备状态、数据、命令
```

从地址角度看，CPU 先用地址码找到接口中的某个端口；从数据角度看，信息经过数据总线传输；从控制角度看，`M/IO` 区分存储器访问和 I/O 访问，选通信号决定哪个端口能够驱动数据总线；从时序角度看，状态、数据和命令相互配合，形成握手。

这三个端口不是三套互不相干的东西，它们共同完成一次外部操作。状态端口告诉 CPU 设备能不能工作，数据端口承载真正要交换的数据，命令端口把双方约定的时序和动作通知传过去。

### 从一个接口例子看懂“数据送到设备”

最后看一个很具体的接口例子。假设接口电路使用 74LS373，它是 8 位的锁存器，有 8 个输入端 `D0`～`D7`，也有 8 个输出端 `Q0`～`Q7`。

如果只想把数据总线的第 0 位送给一个设备，就可以把数据总线的 `D0` 接到 74LS373 的 `D0`，再把 74LS373 的 `Q0` 接到设备的输入端。数据总线上的其他位仍然可以经过 `D1`～`D7` 进入锁存器，设备则使用它所需要的输出。

设备端可以这样连接：通过一个电阻把信号线上拉到 `+5 V`，再接一个发光二极管。输出为 1 时，发光二极管亮；输出为 0 时，发光二极管灭。这里并不是说所有设备都必须用发光二极管，而是用一个看得见的现象说明：接口输出的电平，最终要变成设备能够识别的状态。

```text
数据总线 D0 ───────► 74LS373.D0
                         │
                         └──── Q0 ─────► 设备输入端
                                             │
                                             ├── 上拉电阻 ── +5 V
                                             │
                                             └── 发光二极管 ── 地
```

从这根 `D0` 出发，信号的路径是：

```text
数据总线 D0
    │
    ▼
74LS373 的 D0 输入端
    │
    ▼
74LS373 的 Q0 输出端
    │
    ▼
设备的输入端
    │
    ▼
设备得到一个可识别的逻辑状态
```

这里的“D0 接 D0、Q0 接设备”只是把一位数据从系统总线引到设备的一个具体画法；真正让这个例子成立的前提，是前面讲的接口规则：输出端要能锁存，输入端口的输出端还要能三态，端口要有地址，CPU 通过这些地址和端口完成信息交换。

把整条链路压缩成一句话，就是：地址线负责找到门，三态和锁存负责管理门的开关，端口负责传递信息，握手负责保证双方在合适的时刻交换。

8086 的 20 根地址线带来 1 MB 的外部存储器寻址范围；其中 16 位地址线又可以用于 I/O 端口，并由 `M/IO` 把两类访问区分开。存储器按字节组织，I/O 设备通过接口和端口与 CPU 打交道。状态输入、数据输出、命令输出各有职责，输入端要能高阻让出总线，输出端要能锁存保持数据，最后再通过状态、命令和联络信号完成握手。

这几件事必须连起来记。只记“20 根地址线”，却忘了 I/O 的 16 位空间；只记“有端口”，却不知道端口有输入、输出和不同信息类型；只记“数据能传”，却忘了三态、锁存和握手，电路一到实际接口上就会立刻露馅。

## I/O 独立寻址与 8086 的内部结构
> 对应块：BLK08 | 覆盖分集：P16-P17 | 块标题（分集名）：《16》

### I/O 独立寻址

CPU 要给设备输出数据，首先必须找到设备对应的输出端口。端口既然要分配地址，程序还得进一步回答两个问题：什么时候能够输出，以及数据怎样真正送到设备端。

假设输出使能信号 $\overline{OE}$ 为低电平，输出端才允许送出数据。8086 还要提供写信号 $\overline{WR}$。在有效写信号的作用下，数据从 CPU 的数据端送到设备的数据端。数据线上的信息在写脉冲期间有效，写信号撤销后，输出端依靠锁存电路保持刚才的数据。

如果分配给输出端口的地址是 `2000H`，要通过 `AL` 输出一个数据，指令框架就是：

```asm
MOV DX, 2000H
OUT DX, AL
```

别把写给普通存储器和写给端口的指令混在一起。`OUT` 的目标操作数是端口地址，数据源是 `AL`；给存储器写数据则是另一类指令。指令不同、操作对象不同，更重要的是所在地址空间不同，这正体现了 I/O 独立编址。

```text
CPU 数据端
    │
    │ 写信号有效期间送出数据
    ▼
输出端口 ──► 设备数据端
    │
    └── 写信号撤销后，由锁存电路保持输出
```

独立编址的优点是：I/O 操作拥有专用指令，端口地址不占用存储器地址空间。这里的“独立”并不意味着整个指令系统多出了一大堆难以记忆的指令；8086 的 `IN`、`OUT` 指令，端口寻址方式只提供直接寻址和寄存器间接寻址两类。寄存器间接寻址时，端口地址放在 `DX` 中；若有效地址采用通用寄存器加方括号的形式，常见寄存器包括 `BX`、`SI`、`DI` 等。

> **易错点**：`MOV DX, 2000H` 中的 `2000H` 是端口地址，不是要写往端口的数据。真正输出的数据是 `AL` 中的内容。

### CPU 内部必须有哪四部分

讲完微处理器的外部结构，接下来要钻进 CPU 内部。只有知道处理器怎样工作，才能真正理解工作原理，也才能逐步掌握汇编程序设计所需要的编程模型。

先别急着钻进 8086 那些复杂的内部部件。不管 CPU 是哪一种型号，内部都必须具备四个基本功能部分：算术逻辑单元、寄存器、控制器和 I/O 控制逻辑。抓住这四部分，再看具体型号就好理解了。

```text
┌──────────────────── CPU 内部 ────────────────────┐
│                                                  │
│  算术逻辑单元 ALU                               │
│  寄存器                                         │
│  控制器                                         │
│  I/O 控制逻辑                                   │
│                                                  │
└──────────────────────────────────────────────────┘
```

#### ALU 与寄存器

ALU 承担算术逻辑运算。为了缩短运算时间，参加运算的数据当然不能每次都到外部存储器中取，因此 CPU 内部要设置能暂存少量数据的寄存器。

工作寄存器又可以按用途分成两类。

第一类是数据寄存器，专门暂存数据。第二类是地址寄存器，例如 `BX`，专门提供读、写存储器时的地址。地址寄存器并不只能提供地址；当不需要提供地址时，它也可以暂存数据。16 位地址寄存器能存放 16 位数据，而数据寄存器只负责暂存数据，不承担提供地址的职责。

> **结论**：寄存器是 CPU 内部的高速暂存空间。按用途看，数据寄存器存数据，地址寄存器提供地址；地址寄存器还可以兼任数据暂存。

#### 控制器

控制器可以叫作 CPU 的“中央指挥机关”。它不是只完成某一个局部动作，而是负责把整个执行过程组织起来。

用户编好的程序存放在外部存储器中，控制器首先要从外部存储器取出程序代码，这个动作叫**取指令**。当前指令还在执行时，取回的下一条指令要有地方暂存，于是 CPU 内部设置了指令寄存器。

接下来，指令寄存器中的代码要交给指令译码器分析。译码结果同时告诉 CPU 两件事：要做什么，以及应该怎样做。涉及读、写存储器或 I/O 端口时，译码器再把相应要求通知控制逻辑，由它在有关控制引脚上产生有效命令。

所以，控制器面对的是一整条工作链：取指、暂存、译码、形成控制命令。把它叫作中央指挥机关，意思就在这里。

#### I/O 控制逻辑

CPU 要和外部设备打交道，CPU 内部就应当有能够对 I/O 端口实施控制的逻辑电路，也就是 I/O 控制逻辑。8086 前面讲过的输入、输出操作，最终离不开这一部分。

### 取指令、译码与执行

现在把控制器中的主要部件串起来。假设用户程序已经翻译成机器代码，放在外部存储器的代码区中，CPU 要从这个区域的某个地址开始，一条一条把程序取回来。

```text
程序代码区
    │  PC/IP 给出当前地址，控制器发出读命令
    ▼
指令寄存器 IR
    │  暂存当前指令
    ▼
指令译码器 ID
    │  分析“做什么、怎样做”
    ├──────────────► 控制逻辑产生相应控制信号
    ▼
执行指定操作
```

第一步是**取指令**。程序计数器给出要读取的指令单元地址，地址通过地址总线送到外部存储器；同时，控制器发出读操作命令。存储器在该地址单元中的一个字节代码被送上数据总线，CPU 再把它取回内部。

在一般微处理器的结构中，程序计数器 PC 用于提供指令地址，8086 中与之对应的是指令指针 IP。取回的指令代码先送入指令寄存器。指令寄存器 IR 是 8 位的，可暂存一个字节的指令代码。

> **易错点**：取回一个字节，不代表一条指令一定只有一个字节。指令长度还取决于它后面是否带有操作数、立即数或偏移地址。

第二步是**译码**。指令寄存器检测到已有指令代码后，把它送入指令译码器。译码器分析这段代码，得出指令要求完成什么操作、怎样完成这个操作。

如果当前指令要求对存储器或 I/O 端口进行读、写，译码器便通知相应的控制逻辑部分，由它在相应控制引脚上发出有效命令。

例如，假设已经取回 `B0H` 作为操作码。它表示“把一个字节的数据送入 `AL`”。译码以后，CPU 不只知道要把数据送到 `AL`，还知道：数据就放在这条指令后面的下一个地址单元。

于是，第三步取回的内容虽然仍是存储器中的一个字节，却**不是指令代码，而是该指令的操作数**。它不会送入指令寄存器，而是通过内部数据总线直接送到 `AL`。等这条指令执行完，程序计数器再指向下一条指令，重复取指、译码和执行的过程，程序就这样向前执行。

具体到指令长度：如果刚执行的指令是双字节指令，PC 自动加 2；如果是三字节指令，PC 自动加 3，随后就可以准备取下一条指令。8086 8086 使用 IP 完成这个过程，IP 增加的也是指令所占的字节数。

> **结论**：取指不是“把某个字节塞进 IR”这么简单。取回操作码后，译码器才知道后面的字节究竟是另一段操作码、位移量、偏移地址，还是指令需要的操作数。

### 为什么要从取指执行走向流水

在上面这种微处理器结构中，取指令和执行指令是串行进行的：

```text
取指令 ──▶ 执行指令 ──▶ 取下一条 ──▶ 执行下一条
```

取回的指令先进入指令寄存器，再由译码器分析，这并不等于已经执行。执行期间，处理器又不能同时去取下一条指令，因为还没有地方容纳它。于是只能一条接一条地取、执行。

这样做逻辑清楚，可处理器在等待取指和执行时都会有空档，整体效率并不高。Intel 随后研制 8086，就是为了克服这种取指与执行不能并行所带来的效率问题。

### 堆栈为什么遵循先进后出

理解计算机里的堆栈，不妨先想想生活中的货站。仓库里的货一箱箱搬进去，最先搬进去的货会落在最里面，最后搬进来的货反而压在最外面。取货时，最先取出的恰是最后搬进来的那一箱。

所以，凡是按这种方式存放数据的“站”，都遵循同一个原则：**先进后出**。

> **定义**：由先进后出原则组织的一段存储器区域，称为堆栈。

对 8086 而言，堆栈位于 CPU 外部的存储器中。程序设计时，要从这片存储器空间中定义一个区间，专门作为堆栈存放数据。这个区间的大小由程序员根据程序需求确定。

```text
高地址
  ┌──────────────────────┐
  │                      │  ← POP：最后压入者先取出
  │      堆栈数据区       │
  │                      │  ← PUSH：数据继续向低地址压入
  ├──────────────────────┤
  │        空间地址       │
  └──────────────────────┘
低地址
```

8086 的堆栈操作使用 `PUSH` 和 `POP`：

- `PUSH`：把数据压入堆栈；
- `POP`：把数据弹出堆栈，恢复先前的数据。

为什么要进行堆栈操作？因为 CPU 内部用来存放数据的寄存器数量有限，而复杂程序在使用过程中常会觉得“寄存器不够用”。可以把暂时不再需要的寄存器内容压入堆栈，腾出寄存器处理其他数据；处理结束后，再用 `POP` 把原内容取回。这样就像扩大了计算机的可用暂存空间。

8086 的堆栈必须按字操作。这里的对象经常是 `AX` 这样的 16 位寄存器，所以一次压入或弹出的数据量正好是一个字。

### SP、栈顶与入栈过程

堆栈操作有两个特别容易混淆的地址：一个是固定的栈底，另一个是不断移动的栈顶。真正指示下一次入栈和出栈位置的，是**栈顶**。

8086 用堆栈指针 `SP` 保存栈顶位置。程序初始化后，要让 `SP` 指向栈底加 1 所在单元的地址，也就是预留在栈底上方的那个空字单元。

假设执行：

```asm
PUSH AX
```

`PUSH AX` 可以拆成前后两步来看。

#### 先移动 SP

第一步把 `SP` 的内容减 2，再写回 `SP`。因为 8086 堆栈按字操作，所以一次移动两个字，而不是一个字节。

此时，`SP` 指向新腾出的字单元。栈底地址不动，移动的是指向当前有效数据位置的指针。

#### 再压入一个字

第二步把 `AX` 中的 16 位内容送入堆栈。一个字写入存储器时，要遵循字节排列规律：

- `AX` 的低 8 位，也就是 `AL`，写入字单元的低地址；
- `AX` 的高 8 位，也就是 `AH`，写入字单元的高地址。

```text
AX = AH : AL

压栈后，堆栈中一个字的两个字节：

低地址  ── AL 的内容
高地址  ── AH 的内容
```

例如，程序接着执行：

```asm
PUSH BX
```

CPU 先把 `SP` 再减 2，让它指向另一个字单元；再把 `BX` 的内容压进去：`BL` 写入低地址，`BH` 写入高地址。

如果继续执行：

```asm
PUSH CS
PUSH DS
```

每压入一个字，`SP` 都要再减 2。由此可见，真正随着数据压入而移动的是栈顶指针，不是固定不动的栈底。

### 堆栈空间必须留出余量

连续执行 `PUSH` 时，`SP` 会不断向低地址移动。如果不做检查，等 `SP` 越过已经定义的堆栈区域，就可能访问区域外部的数据；相反，如果 `POP` 次数过多，`SP` 也可能越过堆栈的另一端。

这两种越界都称为**堆栈失衡**。当 CPU 执行堆栈操作时发现 `SP` 已经越界，系统就会死机，键盘也不再起作用，往往只能依靠 `Reset` 才能重新工作。

因此，程序中定义堆栈区域时，不能只按“已经算出来的需求”卡得死死的。堆栈区域要按照实际需要定义，并留出约 30% 的富余量。工程设计中的指标本来就应留有余量；堆栈多留一些空间，不仅可以降低溢出风险，也有利于以后修改程序、增加局部数据或调整调用层次而不必立刻重新划分整个区域。

> **易错点**：栈底是初始化时建立的固定位置，栈顶才是随 `PUSH`、`POP` 移动的活动位置。不要把“压入多少个字”记成“栈底向上加了 2”。

### POP 怎样恢复原来的数据

要把先前压入堆栈的内容恢复出来，必须遵循先进后出原则。假设之前执行过：

```asm
PUSH AX
PUSH BX
```

现在先执行：

```asm
POP BX
```

`POP BX` 同样要分成两步。

#### 先从 SP 指向的位置取字

第一步，把 16 位 `SP` 的内容当作栈顶地址，从该地址单元读出一个字，送到目的寄存器 `BX`。

指令里只需要写目的操作数 `BX`，源操作数不用程序员另写。只要 `SP` 能确定位置，CPU 就能找到那个字。

#### 再让 SP 增加 2

第二步，把 `SP` 自动加 2。刚才弹出的字已经从活动栈顶移出，`SP` 应当指向它上方的那个字单元。

```text
压栈时：SP ← SP - 2
弹栈时：SP ← SP + 2

PUSH 与 POP 都移动 2 个字节，因为 8086 堆栈按字操作。
```

于是，`POP BX` 恢复了 `BX`，`SP` 也回到对应的活动位置。继续弹出 `AX` 后，数据恢复完毕，`SP` 回到初始化状态。

这里有一个非常重要的对应关系：**先压入的必须先弹出，后压入的必须先恢复**。程序中每一次 `PUSH` 都要有相应的 `POP` 与它配合。只有入栈和出栈配对，`SP` 才能回到原来的位置；否则，程序运行期间就会发生堆栈失衡。

> **结论**：`PUSH` 做“减 2、存字”，`POP` 做“读字、加 2”。掌握 `SP` 的移动规律，比死记某一次压栈后的绝对地址更可靠。

### 8086 内部的两条主线

前面已经建立了 CPU 内部四大部件的总体认识。现在再把视线收紧到 8086 本身。8086 的内部结构比一般微处理器复杂，但无论图怎样画，仍然有 ALU、寄存器、控制器和 I/O 控制逻辑这四类基本功能。

理解 8086，可以先抓住图中的虚线：虚线把内部结构分成两大部分，它们就是总线接口单元 BIU 和执行单元 EU。

```text
┌────────────────────── 8086 内部 ──────────────────────┐
│                                                        │
│   总线接口单元 BIU                执行单元 EU          │
│   ─────────────────                ────────────         │
│   段寄存器、IP                    ALU、通用寄存器      │
│   地址产生与总线控制逻辑          指令译码与控制        │
│                                                        │
│   负责取指、形成物理地址、组织外部总线访问             │
│                                                        │
└────────────────────────────────────────────────────────┘
```

BIU 负责与外部存储器及 I/O 端口打交道，EU 负责执行指令。分析内部结构时，先把这两条主线的职责分开，后面看寄存器分组和地址形成就顺了。

### BIU：段寄存器与总线接口

BIU 中有 `CS`、`SS`、`DS`、`ES`、`IP` 等寄存器。它们各自解决一个很具体的问题：CPU 怎样知道当前取的是代码、访问的是数据，还是在操作堆栈。

| 寄存器 | 用途 |
| :--- | :--- |
| `CS` | 代码段寄存器，保存代码段的段地址 |
| `DS` | 数据段寄存器，保存数据段的段地址 |
| `ES` | 附加数据段寄存器，保存附加数据段的段地址 |
| `SS` | 堆栈段寄存器，保存堆栈段的段地址 |
| `IP` | 指令指针寄存器，保存当前指令在段内的偏移地址 |

其中，`IP` 的作用要特别抓住：它在 8086 中等效于一般微处理器里的程序计数器 `PC`。程序代码放在代码段，取指令时要同时知道代码段在哪里，以及当前指令位于该段的哪个位置。前者由 `CS` 给出，后者由 `IP` 给出。

堆栈操作也是如此。`PUSH` 和 `POP` 都要先找到堆栈位于哪个逻辑段，因此需要 `SS` 提供段地址；再由 `SP` 给出当前栈顶在该段内的 16 位偏移地址。

### EU：把指令执行起来

EU 主要负责指令的译码与执行。可以先抓住两样核心部件：ALU 和通用寄存器组。

ALU 承担算术逻辑运算，通用寄存器为正在执行的操作提供数据暂存和地址信息。`IP` 负责指出当前指令在代码段中的位置，`CS` 负责指出代码段本身。BIU 取得指令和数据后，EU 就根据译码结果驱动相应部件完成操作。

把 `BIU` 与 `EU` 的配合关系记成下面这样即可：

- EU 决定当前要执行什么、怎样执行；
- BIU 根据相应段寄存器和偏移寄存器形成访问地址，负责同外部交换指令、数据和 I/O 信息。

8086 的内部组织，就是用这两条主线解决了前面那个“取指与执行串行、效率不高”的问题。

### 物理地址如何由分段信息形成

8086 有 20 根地址线，也就是 `A0` 到 `A19`，它们用于对外寻址。但处理器内部用于寻址的许多寄存器只有 16 位。`SP` 只有 16 位，`BX` 也只有 16 位；一个这样的寄存器只能提供 $2^{16}$ 个地址，也就是 64K 个单元，不足以直接指出 `A0` 到 `A19` 所代表的全部地址空间。

怎么办？答案是把外部地址空间划分成若干逻辑段。每个逻辑段最大为 64KB，段内使用 16 位地址进行寻址。想访问不同逻辑段时，就切换相应的段寄存器。

比如，要读取当前代码段中的一条指令，需要先知道代码段的段地址，以及指令在这个段内的位置。对于 8086 来说，指令位置由 `IP` 给出，代码段地址由 `CS` 给出。

做堆栈操作时，段地址由 `SS` 给出，段内栈顶偏移地址由 `SP` 给出。普通存储器操作中，如果采用 `BX` 间接寻址，段地址由相应的段寄存器提供，`BX` 给出段内偏移地址。

因此，8086 系统中的操作地址由两部分构成：

1. 一个 16 位的段地址，指出逻辑段；
2. 一个 16 位的段内偏移地址，指出该段中的具体单元。

```text
20 位物理地址 = 16 位段地址 × 16 + 16 位段内偏移地址

     段地址左移 4 位
             │
16 位段地址 ──┤
             ├── 相加 ──► 20 位物理地址 ──► A0～A19
16 位偏移地址 ┘
```

段寄存器位于 BIU 中。程序设计时，指令给出的有效地址是 16 位，处理器还会根据操作类型取出相应的 16 位段地址。BIU 中的地址产生与总线控制逻辑将这两个 16 位数进行运算，形成 CPU 外部实际使用的 20 位地址，再送到 `A0` 到 `A19` 上，从而找到要访问的存储器单元。

> **结论**：8086 并不是让寄存器直接产生 20 位地址，而是让“段地址加偏移地址”共同描述存储空间。段地址提供方向，偏移地址提供段内位置。

> **承前启后**：上一节讲完「I/O 独立寻址与 8086 的内部结构」，下一节接着讲「取指与执行：8086 指令队列及十四个十六位寄存器」。

## 取指与执行：8086 指令队列及十四个十六位寄存器
> 对应块：BLK09 | 覆盖分集：P18-P19 | 块标题（分集名）：《18》

你有没有想过，一个小小的指令计数器，为什么在 8086 里突然变成了六个字节的指令队列？它们又是怎么做到一个在门外取指令、一个在门里执行指令，还总让总线忙个不停？顺着这个疑问往下追，8086 CPU 内部的指令队列与十四个十六位寄存器就自然连在了一起。

> **定义**：指令队列寄存器由六个字节组成，是 8086 内部用于暂存从外部存储器取回指令的队列。取回的指令先进入这里，执行部件再按先进先出的原则取出、分析并执行。

### 指令队列：六个字节的流水线

#### 从一个字节到六个字节

一般微处理器里，指令计数器（IR）取回一个字节的指令代码，存进 IR。但那里的 IR 常常只有八位，取回八位指令代码之后就不能继续取指了，效率太低。于是 8086 CPU 在内部设计了六个 IR，六个字节组成一个指令队列寄存器。

从外部存储器取回指令代码后，只要这个六字节的队列还没满，就继续取。前面反复强调，BIU 不休息，一直往队列里搬指令；后面反复追问，EU 也不休息，只要队列里有指令，就取一条、执行一条。取指令和执行指令这两件事因此可以并行推进，效率就从这里提高起来。

8088 就不一样了。8088 CPU 内部的功能和 8086 只有一个区别：它的指令队列寄存器由四个字节组成，而 8086 是六个字节。除此之外，两个 CPU 在内部是百分之百兼容的。

```text
外部存储器
    │
    ▼
BIU 取回指令代码
    │
    ▼
指令队列（8086 六个字节 / 8088 四个字节）
    │
    │ 先进先出
    ▼
EU 获取 → 分析 → 执行
```

读图：BIU 负责把指令从外部存储器搬进队列，EU 按先进先出的次序从队列中取指、分析并执行，两条动作可以同时进行。

> **易错点**：取回一条指令时，不是把整条指令的所有字节一股脑地执行下去，而是先认出其中的操作码，再把这条指令涉及的后续字节也放进队列。8086 指令系统中，一条指令最长为五个字节；有双字节指令，也有三字节指令，怎么长都不等于队列一次就取满。

队列没有装满就别想休息，这是 BIU 放指令的规矩；只要指令还在队列里，EU 就按程序顺序处理。BIU 持续取指，EU 持续取指、分析、执行，取指操作与执行操作并行，8086 从外部取指令的效率自然就上去了。

#### 什么时候才能歇口气

表面上看，BIU 和 EU 好像都能歇。BIU 把指令队列塞满以后总该能歇了吧？可 EU 还在不停地执行，执行到后面，队列又空了，BIU 只好继续取，很难真正停下来。EU 呢？只有指令队列真的空了，EU 才能歇；但 BIU 一直在取，队列很难保持空。

拿一个程序周期来推。第一个周期，BIU 去外部存储器取程序，取指动作占用这个时间片，EU 空闲无事可做。到了下一个周期，由于 BIU 取来的指令还没把队列装满，它继续取下一条指令；这个周期里，EU 从队列中取出前一个周期取回的指令并开始执行。再下一个周期，BIU 仍在取下一条指令，EU 仍在执行自己这一个周期才取回的指令。

继续下去，BIU 表面上似乎应该一直取指令。但 EU 执行到某条指令时，这条指令要访问外部存储器或进行 I/O 读写，必须占用总线。EU 就要通知 BIU：“我要用总线了。”BIU 收到通知，只好暂停取指，把总线让给 EU。

所以 BIU 停下来的原因有两条：一是指令队列已经取满，二是 EU 需要使用总线。EU 真正能够休息的条件只有一个：指令队列空了。

外部总线呢？几乎每个周期都很忙。这个周期 BIU 取指令要用总线，下个周期取指令还要用总线，再下个周期 EU 执行访问存储器的指令也要用总线。所以在这种机制下，CPU 不只是取指令和执行指令，取指令与执行指令这两个动作还并行着，于是速度很快，总线利用率也很高。

> **结论**：8086 的这种取指与执行并行机制，从 8086 一直延续到 8088、186、386、486、586，直到今天的奔腾，其间 CPU 内部功能越来越多、速度越来越快，但取指与执行并行的基本机制一直存在。

### 十四个十六位寄存器：按功能分三类

8086 CPU 内部为了程序设计设置了十四个十六位寄存器。学过这些寄存器后，后面讲 2.4 节就轻松多了；但作为程序设计要掌握的基本功，这十四个寄存器很可能以简答、填空等形式出现，所以每一个的含义和用途都要记牢。

按功能分，它们分成三类来看。

#### 数据寄存器：累加器、基址、计数、变址

数据寄存器一共有四个，都是十六位的：`AX`、`BX`、`CX`、`DX`。如果程序设计时对字节数据进行处理，自然会想到用十六位寄存器的高字节或低字节。

| 寄存器 | 十六位名称与用途 | 拆分出的八位部分 |
| --- | --- | --- |
| `AX` | 累加器，运算时优先考虑的目的操作数 | `AH`、`AL` |
| `BX` | 数据寄存器，也可作基址指针，默认为数据段寻址 | `BH`、`BL` |
| `CX` | 计数器，与循环配合使用 | `CH`、`CL` |
| `DX` | 数据寄存器，I/O 操作中暂存十六位数据，也可作 I/O 间接寻址的端口地址 | `DH`、`DL` |

先看 `AX`。它叫累加器，不是说别的寄存器不能做累加，而是说当程序设计要涉及运算、尤其是自运算时，目的操作数要尽量选 `AX`，运算结果也尽量由 `AX` 存放。选 `AX` 比选其他寄存器速度要快。如果处理的是字节数据，累加器就选 `AL` 或 `AH`，当然绝大多数场合选 `AL`。`AL` 叫八位累加器。`AX` 是十六位，可以分成两个八位寄存器 `AH` 和 `AL`；`BX` 同样分成 `BH` 和 `BL`，`CX` 分成 `CH` 和 `CL`，`DX` 分成 `DL` 和 `DH`，它们都是八位寄存器。程序设计要使用八位寄存器时，可用的就是这八个。

再看 `BX`。它除了作十六位数据寄存器，还有一个特殊功能：基址指针寄存器。当程序设计要对某个存储器单元进行写或读操作时，需要找出该单元的地址，这个地址当然要在段内。`BX` 可以提供段内的十六位偏移地址，也就是基址；`BX` 中括号就是间接寻址，访问的是由 `BX` 指向的存储单元，默认在数据段 `DS` 内。

`CX` 的特殊功能是计数器。程序结构中大量使用循环结构，循环多少次、每循环一次执行一次工作，都可以用 `CX` 做计数器。程序初始化时把循环次数放入 `CX`，每循环一次就减一，减到零时循环结束。用其他寄存器做计数器当然也行，但 8086 指令系统中只有配合 `CX` 作计数器的指令，使用其他寄存器就得自己多写几条。

`DX` 在 I/O 端口编程中，用十六位数据寄存器暂存十六位数据。在 `IN`、`OUT` 指令中，`DX` 是否充当 I/O 地址寄存器，作 I/O 间接寻址，这一点前面已经举过例子，这里先记住它这个特殊角色。

#### 地址指针与变址寄存器：同一套寻址，默认段不同

第二类称为地址指针与变址寄存器，共四个：地址指针寄存器两个，变址寄存器两个，全都是十六位。

`SP` 是堆栈指针寄存器，指示 `PUSH`、`POP` 堆栈操作时所操作单元的段内十六位偏移地址。堆栈的段地址由 `SS` 这个十六位堆栈段寄存器提供。

`BP` 叫基址指针寄存器，它提供偏移地址的作用和 `BX` 一样，但有一个重要区别：默认所属的逻辑段不同。

假设存储器里定义出堆栈段，又定义出数据段。数据段专门用来存放数据，里面可能有字节数据，也可能有字数据。一个逻辑段起始单元的地址叫偏移地址，一般是零；从起始点向下找某个单元，相差的量就是该单元相对这个逻辑段的偏移地址。例如，数据段起始点为偏移地址零，向下第二个单元的偏移地址就是 `0002`。

用程序写出来更直观。假设 `BX` 和 `BP` 都等于 `0002`，`AL` 等于 `34H`，把 `AL` 的内容写到存储单元：

```asm
mov bx, 0002
mov al, 34h
mov [bx], al
```

`BX` 间接提供的偏移地址，CPU 默认放在数据段里，所以这条指令把 `34H` 写进数据段相对偏移为 `0002` 的那个单元。

换一条指令：

```asm
mov bp, 0002
mov [bp], al
```

地址由 `BP` 间接提供，但 CPU 对它默认使用堆栈段 `SS`，所以同样的 `0002` 写进了堆栈段相对偏移为 `0002` 的单元，而不是数据段的那个单元。

> **易错点**：`BX` 和 `BP` 都能通过中括号间接提供存储器操作数的十六位偏移地址，但 `BX` 默认对应数据段 `DS`，`BP` 默认对应堆栈段 `SS`。同样是 `0002`，落在哪个段，不能混为一谈。

如果确实要用 `BP` 提供的偏移地址去访问数据段的第三号单元，程序设计师必须在指令左边加一个段超越前缀，明确告诉 CPU 本条指令要访问的是数据段。如果不加，默认就按堆栈段处理。当然，用 `BX` 间接寻址时，也可以加这个前缀来指明操作数所在的逻辑段。

这一部分称为段超越前缀，也叫段前缀。加了段前缀以后，汇编出来的这一条指令代码会多一个字节。

所以现在要把两个地址指针寄存器记牢：`BP` 也能间接寻址，`BX` 也叫基址指针寄存器，它们都能提供存储器间接寻址单元的地址，区别只在默认对应的逻辑段。

再来看两个变址寄存器：`SI` 和 `DI`，都是十六位。`SI` 是源变址寄存器，`DI` 是目的变址寄存器。所谓变址，与源、目的、偏移这些概念都无关，它只是“地址”的意思。只要对存储器进行写或读操作，当然会使用间接寻址；`BX`、`BP`、`SI` 和 `DI` 后面加中括号都可以这样使用。但其中只有 `BP` 中括号默认对应堆栈段，`BX`、`SI`、`DI` 中括号间接寻址找到的单元都在数据段内。

#### SI 与 DI 的“变”：来自字符串操作

“变”这个概念来自 8086 对字符串的操作。假设存储器中某处存放着 `1234` 这样的字符串，现在要把它搬到另一个地方去，这就是字符串传送，也就是数据块搬家——被搬动的字符串叫源串，搬到目的地的字符串叫目的串。

8086 当然也能用普通数据传送指令来搬家，但为了提高字符串操作的效率，8086 指令系统专门开辟了一类字符串操作指令。对于源串和目的串的地址，规定源串必须在 `DS` 数据段中定义，源操作单元的段内偏移地址必须由 `SI` 提供；目的串必须在附加数据段 `ES` 中定义，目的操作单元的段内偏移地址必须由 `DI` 提供。

这样还不够，剩下的就是“变”怎么变：字符串指令本身不带操作数，源和目的地址也不写在指令里，但 CPU 执行时知道 `SI` 和 `DI` 指向哪里。初始化好源、目的地址后，执行一条字符串传送指令即可。第一步，CPU 自动把 `SI` 所指单元的内容送到 `DI` 所指单元；如果搬的是一个字节，就搬一个字节，`W` 表示按字传送，一次搬一个字节、一个字，第二次操作会按数据类型自动把 `SI` 和 `DI` 指向下一个单元。

> **结论**：在字符串操作中，`SI` 和 `DI` 作地址指针，每传送完一次就按数据类型自动加一或减一，这就是变址寄存器名称中“变”的来源。如果使用字符串操作指令之外的普通数据传送指令，`SI` 和 `DI` 就只是普通的地址寄存器，传送后不会自动改变。

#### 段寄存器：给四类逻辑段指路

第三类是段寄存器，共四个：`CS` 是代码段寄存器，`DS` 是数据段寄存器，`ES` 是附加数据段寄存器，`SS` 是堆栈段寄存器。它们存放的分别是各自逻辑段的段地址。

一个用户程序汇编后放进存储器，程序代码是由若干逻辑段组成的，通常有代码段、数据段、堆栈段，字符串操作还可能有附加数据段。所以 8086 汇编语言程序设计要建立的第一个概念，就是用汇编语言的符号来定义一个逻辑段：你定义的这个逻辑段可能是代码段，也可能是数据段，再定义一个就是另一个段。

有了段定义，还要有相应的指令去初始化段寄存器，让它们的值指向所定义逻辑段的段地址。但有一个例外：`CS` 的初始化由操作系统完成，用户不能初始化。也就是说，用户不能给 `CS` 写；更准确地说，`CS` 不能作目的操作数，但可以作源操作数，把它读出来。

> **易错点**：代码段、堆栈段、数据段和附加数据段都要有相应的段寄存器来存放段地址。程序中需要手动初始化的是 `DS`、`ES`、`SS`，而 `CS` 只能作源操作数读出，其赋值由操作系统完成。

## 控制寄存器、地址空间与数据存放格式
> 对应块：BLK10 | 覆盖分集：P20-P21 | 块标题（分集名）：《20》

处理器内部寄存器分几大类来数，控制计算机是其中一类。控制计算机一共两个：一个是 IP，指令指针；另一个是 PSW，处理器状态字。这两个记住就够了，考试就是考 8086 CPU 内部寄存器一共 14 个、通用计算器是 8 个 16 位寄存器，剩下的两个就是这两个控制计算器。课堂上理解到位，下去稍作复习，作业就完成了，要带着这种轻松的姿态去学，不要把自己搞得累趴下。

### 控制计算器

#### IP：取指令时 CS 和 IP 一对不可分家

IP 指令指针计算器是 16 位的。CPU 从代码段取指令，当前要取的那一条指令在哪里？所在段的段地址当然由 CS 提供，段内的偏移地址由 IP 提供。也就是说，CS 给出"哪个段"，IP 给出"段内第几字节"，两者一对，不可分家。IP 等效于某些处理器中的程序计数器 PC，作用就是告诉 CPU 下一条指令到哪里去取。

用文字画一下这个取指令的地址构成：

```text
        代码段内的一条指令
                │
        ┌───────┴───────┐
        │               │
   段地址 CS          段内偏移 IP
  （哪一段）        （段内第几字节）
        │               │
        └───────┬───────┘
                ↓
      指令的物理地址（8086：CS×16 + IP）
```

> **易错点**：既然 CS 不能作目的操作数，显然 IP 也不能作目的操作数，这一点一定要记住。

### 状态字 PSW：16 位里有 9 位有用

PSW（FLAG）在 8086 里是 16 位的，但真正有用的只有 9 位：6 位状态标志和 3 位控制标志，另外 7 位没有用。这 9 位分成两类：

- **状态标志** 6 位：ZF、CF、PF、SF、OF、AF。
- **控制标志** 3 位：DF、IF、TF。

```text
PSW（FLAG）16 位
┌──────────────────────────────────────────────┐
│  7 位无用  │ 控制标志 3 位 │ 状态标志 6 位 │
│           │  TF  IF  DF   │ CF PF AF ZF SF OF │
└──────────────────────────────────────────────┘
```

#### 状态标志：只反映 ALU 运算后的结果状态

给状态标志下定义：状态标志反映的是 ALU 运算后结果的状态。抓住"运算后"这三个字——没有运算的指令执行以后不影响这些标志。CPU 执行非算术运算的指令时，状态标志不受影响；执行运算指令以后，状态标志才会按结果被置位或清零。哪些标志置位、哪些清零、什么情况下置位什么情况下清零，下去一定要重点复习，这里就不一一举例子了。

> **提示**：状态标志除 AF 以外，其余五个也都是我们条件转移程序设计当中判断的条件之一，要理解这一点。

### 控制标志：管住 CPU 怎么跑

三个控制标志都是用来控制 CPU 的运行状态的。先说 DF 方向控制标志，再说 IF 中断允许标志，最后说 TF 陷阱标志。

| 标志 | 名称 | 作用与置/清方式 |
| :--- | :--- | :--- |
| DF | 方向控制标志 | 控制字符串操作指令执行时 SI、DI 自动变化的方向。复位时 DF 自动清零；`CLD` 让 DF 清零，`STD` 让 DF 置 1 |
| IF | 中断允许标志 | 控制 CPU 对外部可屏蔽中断的响应。IF 清零即关中断、外部中断请求一概不理；IF 置 1 即开中断，有请求才响应。`CLI` 让 IF 清零，`STI` 让 IF 置 1 |
| TF | 陷阱标志 | TF 置 1 后，CPU 每执行完一条指令就产生一次陷阱中断，配合 DEBUG 的单步跟踪命令逐条单步执行。复位时 TF 清零；没有专用的置位/清零指令 |

#### DF：字符串操作往哪边走

方向控制标志用于字符串操作指令。CPU 执行 `MOVSB` 这类字符串传送指令时，如果 DF=0，执行完这一条传送操作以后，SI 和 DI 自动按正方向变化——递增 1 还是 2，看操作类型：字节操作增 1，字操作增 2。如果执行字符串操作指令时 DF=1，执行完以后 SI 和 DI 自动按减小地址的方向变化——减 1 还是减 2，同样看操作类型。DF 就是用来控制字符串操作中 SI、DI 变化方向的。

所以初始化时要想清楚：如果让 SI、DI 按地址增大的方向变，SI 初始化时就指向源串的起始单元，DI 初始化时就指向目的串的起始单元；如果让 SI、DI 按地址减小的方向变，SI、DI 初始化时就指向源串、目的串的末单元。DF 默认复位清零。

#### IF：想敲门，先看我开不开门

要理解中断允许标志，先得理解什么是中断。中断实际上就是一种打断：CPU 正在执行用户程序期间，突然有一个特殊事件发生了，事件向 CPU 提出了请求，CPU 就暂时停止正在执行的程序，转去为这个事件服务，执行服务子程序；服务完毕以后，CPU 又能正确地返回到刚才终止的地方，接着原来的程序继续往下执行。这么一个过程就叫中断。

打个比方：我在台上讲话、正在执行我的程序，突然有人举手了，我是不是被打断了？我就问你想说什么，刚才的程序不执行了，先执行你的程序——这个才叫中断子程序。而且一定要"举手"才算：由 CPU 芯片内部提出的中断叫内部中断，由外部设备敲门提出的中断叫外部中断。

> **定义**：中断 = CPU 在执行用户程序期间，由于某个特殊事件发生，暂停当前程序 → 转去执行服务子程序 → 服务完毕返回断点继续执行。

对任何型号的 CPU 而言，外部提出的中断都是可以屏蔽掉的：屏蔽了以后，外部再来敲门，CPU 连理都不理。标志打开了，外部一敲门，CPU 就要离开当前程序去执行服务子程序。而由 CPU 内部提出的中断是不能屏蔽的，必须响应，8086 CPU 也不例外。

8086 CPU 有两个外部设备能向 CPU 提出外部中断请求的输入引脚：

- **NMI**：不可屏蔽中断请求信号。从这个引脚进来的中断请求，CPU 必须响应，不能屏蔽。
- **INTR**：外部可屏蔽中断请求信号。从这个引脚进来的是可屏蔽的外部中断请求，靠 IF 控制：IF 清零就屏蔽了，CPU 不响应；IF 置 1 即开中断状态，CPU 才响应通过 INTR 引脚提出的中断请求。

所以当年 8086 系列 CPU 的应用程序在服务程序和主程序的设计当中，不要忘了 IF 标志的设置——要用外部可屏蔽中断，程序中就得先开中断；想关掉就 `CLI`，想打开就 `STI`。

#### TF：一次只走一条指令

TF 叫陷阱标志，不好理解，就叫它单步标志——"大步"就完了。这个标志一出手就是"单步"：CPU 刚复位时 TF 是清零的，CPU 运行用户程序可以一直取指执行、把用户程序执行到底；如果程序中把 TF 置 1，CPU 执行完一条指令就终止一下，产生一次陷阱中断，陷入去执行陷阱处理程序，下一条指令就不接上来继续了。

那 TF 置 1 以后是不是每一条指令执行完都停一下？正是如此。DEBUG 调试工具里的单步跟踪命令就是靠这个原理工作的：你设计的原程序汇编后产生的机器代码，DEBUG 一步一步跟踪，靠的就是"执行完一条就陷入一次"这个机制。调试工具是学这门课必须掌握的工具之一。

那 TF 没有专门的置位/清零指令，怎么让它置 1、怎么让它清零？这里要靠前面学过的通用知识来推：既然 PUSH、POP 是通用指令，能压任何操作数，那就能把 PSW 这个 16 位压栈，也能弹出来——把 FLAGS 压到 AX 里，然后按位操作；操作完再把 AX 弹回 FLAGS 位即可。也就是"取出 PSW → 修改某一位 → 写回 PSW"这个套路。

比如把 TF 置 1：TF 位于 PSW 的第 8 位，先 `PUSH FLAGS`，再 `POP AX`，此时 AX 每一位对应 FLAGS 每一位。取第 8 位的掩码 `0100H`，让 AX 第 8 位置 1（其余位不变），再 `PUSH AX`、`POP FLAGS`，TF 就置 1 了——下面程序再执行，就是单步执行。想恢复 TF 清零，同样的操作：掩码换成把第 8 位清 0 的值，其余位不动，`PUSH AX`、`POP FLAGS` 即可。

```asm
    ; 将 TF 置 1（单步），其余位保持不变
    PUSH FLAGS
    POP     AX
    OR      AX, 0100H     ; 第 8 位（TF）置 1，其余位不变
    PUSH    AX
    POP     FLAGS

    ; 此处开始单步执行

    ; 将 TF 清 0（恢复连续执行），其余位保持不变
    PUSH FLAGS
    POP     AX
    AND     AX, 0FBFFH    ; 第 8 位（TF）清 0，其余位不变
    PUSH    AX
    POP     FLAGS
```

> **提示**：不要死记某个知识点只能有一种做法。例子举到你 80 岁都举不完，围绕知识点去思考——PUSH/POP 是通用指令，PSW 就是一个 16 位操作数，能压能弹，能按位改，这就是"围绕知识点去思维"。

### 存储器地址空间与 I/O 地址空间

#### 存储器地址空间：20 位地址线，1 MB

8086 CPU 有 20 根地址线：A19～A16 四根、A15～A10 六根、A9～A0 十根，一共 20 根。这 20 根地址线全部用来给外部存储器编址——这是 CPU 用来给外部存储器分配地址的全部地址线。所以 8086 CPU 能选址的外部存储器地址空间是 $2^{20}$ 字节，也就是 1 MB 存储空间。

#### I/O 地址空间：8086 有 64 K，PC 实际只用 1 K

8086 CPU（以及 8088）同样用这 20 根地址线中的 16 根来给 I/O 端口编址。所以 8086/8088 能寻址的外部 I/O 端口地址空间是 $2^{16}$ 个地址，按字节端口算就是 64 K 字节。

IBM PC 机就不同了。PC 机只用这 16 根中的 10 根（A0～A9）给 I/O 分配地址。为什么不用 16 根？因为在一个微机系统里根本用不了这么多 I/O 地址——如果用 A0～A15 给 I/O 分配地址，那就意味着编址时这 16 根线全都要拉到你的板子上、全部参加译码，译码电路就复杂了，而多出来的那些地址根本用不上。所以为了简化 I/O 地址译码电路设计，PC 机只用 10 根，I/O 地址空间就是 $2^{10}$ 个，也就是 1 K 字节。

> **注意**：64 K 是 8086/8088 用 16 根地址线给 I/O 编址的理论空间；1 K 是 IBM PC 机实际设计时只用 10 根线后的空间。这两个数字不要记混。

```text
      8086 的 I/O 地址空间（8086 / 8088）
      ┌───────────────────────────────────┐
      │  16 根地址线 → 2^16 = 64 K 字节   │
      └───────────────────────────────────┘

      IBM PC 机的 I/O 地址空间
      ┌───────────────────────────────────┐
      │  10 根地址线 A0～A9 → 2^10 = 1 K  │
      └───────────────────────────────────┘
```

#### PC 机的 1 K I/O 地址怎么分

这 1 K 地址是 `000H`～`3FFH`，PC 机规定把它分成两个 512 字节的区段：前 512 个 I/O 地址（`000H`～`1FFH`）给主板上的 I/O 分配地址，后 512 个（`200H`～`3FFH`）给插件板上的 I/O 分配地址。

```text
      PC 机 I/O 地址空间  000H ～ 3FFH
      ┌────────────────┬────────────────┐
      │ 000H ～ 1FFH   │ 200H ～ 3FFH   │
      │   512 字节      │   512 字节      │
      │  主板上的 I/O   │  插件板上的 I/O │
      └────────────────┴────────────────┘
```

这对我们以后开发应用系统有直接意义：我们开发的硬件最终要做成一块板子插到 PC 总线上去，这块板子上 I/O 的分配地址应该在哪个区段去找？到后半段 `200H`～`3FFH` 里去找。但还不能随便挑——要看计算机说明书，看这后半段里哪些地址已经被哪个插件板上的哪个 I/O 占用了，已经被占用的地址你不能用，只能用别人没有用过的地址，才能分配给你的 I/O 做地址。

这就是实际应用当中必须考虑的问题。讲 I/O 接口电路的译码电路设计时，我举的例子中 I/O 分配地址可以不考虑这一点，那是为了把译码电路的原理讲明白；但在你实际应用当中，分配给你的 I/O 地址必须是系统中任何部件都没有占用的地址，这一条一定要考虑进去。

### 存储器中数据的存放格式

存储器是按字节组织的，一个存储单元就是一个字节单元。那么我们程序中用到的数据——一般大多数情况下是字节型数据和字型数据，个别场合下还会用到双字型数据（双字就是两个字，4 个字节）——它们在存储器当中以什么格式存放？这就要分开来看了。

#### 字节型数据：一个数据占一个地址单元

字节型数据在存储器中存放很简单：一个字节数据占用一个地址单元，程序中定义的若干字节数据是连续存放下去的——一个数据占一个字节，下一个数据放到下一个地址单元，一个挨一个地排下去。

在 8086 汇编语言程序设计当中，字节型数据用什么来定义？用 `DB`（Define Byte，定义字节）伪指令。数据定义在哪个逻辑段里由段寄存器决定：如果在数据段定义，段地址就由 DS 提供；如果在 ES 段定义，就定义在 ES 段里；在 CS 段也可以定义数据，但一般不这样做。

这里要特别区分清楚：`DB` 是**伪指令**，不是指令。`ADD`、`PUSH`、`POP` 这些是指令，是告诉 CPU 做什么的语句；伪指令显然是**不让 CPU 执行**的，它是告诉汇编程序（编译工具）做什么的——告诉你编写的源程序要不要翻译，翻译时碰到一条伪指令，就告诉编译程序该怎么编译。`DB` 这条伪指令就是告诉汇编程序：要定义一个字节型数据，定义在存储器里你所在的这个逻辑段的哪个偏移地址上。所以数据放在哪个段，取决于你把它写在哪一段里。

```asm
DATA SEGMENT
    DB  12H, 0CH, -12        ; 定义三个字节型数据
DATA ENDS
```

假设这个数据段在存储器中的段地址由 DS 提供，数据段内的偏移地址从 `0000H` 开始。汇编时，汇编程序就把这三个数据连续放到三个字节单元里：

- 偏移 `0000H` 放 `12H`；
- 偏移 `0001H` 放 `0CH`；
- 偏移 `0002H` 放 `-12`，计算机中的带符号数都用补码表示。`12` 的原码是 `0000 1100`，求补码时符号位不变、其余位取反、末位加一，结果是 `F4H`。

```text
    数据段内的偏移地址 → 存储器内容
    ┌─────────────┬─────────────┬─────────────┐
    │  0000H      │  0001H      │  0002H      │
    ├─────────────┼─────────────┼─────────────┤
    │  12H        │  0CH        │  F4H        │
    └─────────────┴─────────────┴─────────────┘
```

所以你在源程序里写的是十进制的 12、十六进制的 12H，还是负数 -12，汇编程序汇编时统统都会变成二进制放进去——计算机中的数都是用二进制表示的。字节型数据在存储器中的存放格式就一句话：一个字节数据占一个字节单元，若干个字节数据连续存放，一个数据一个地址单元。

#### 字型数据：一个字由相邻两个字节单元组成

字型数据要在用到的这个段（一般是数据段）里用定义字型数据的伪指令 `DW`（Define Word，定义字）来定义。同样，`DW` 也是伪指令，是告诉汇编程序"要定义一个字型数据"，不是 CPU 执行的指令。

`DB` 和 `DW` 存放时的推进规律不一样：`DB` 定义的字节型数据每定义一个，偏移地址加 1；`DW` 定义的字型数据每定义一个，偏移地址加 2，因为一个字型数据占两个字节。所以段内偏移地址是按数据类型的字节数依次排下去的。

一个字型数据在存储器中是由**这个地址单元和下一个地址单元**组成的——两个相邻的字节单元合成一个字单元。在一个字单元里，偏移地址较小的那个地址单元存放的是**高字节**数据，偏移地址较大的那个地址单元存放的是**低字节**数据。也就是说，字型数据的存放方式与字节型完全不同：字节型一个地址单元放一个字节；字型两个相邻地址单元合起来放一个字，高字节放低地址、低字节放高地址。

比如定义一个字型数据 `5678H`（一个字节型数据的两倍），低地址单元放高字节 `56H`，高地址单元放低字节 `78H`，所以那个"字"的地址就是低地址单元的偏移地址（`0003H`），高地址单元的偏移地址比它大 1。

```asm
DATA SEGMENT
    DB  12H, 0CH, -12        ; 偏移 0000H、0001H、0002H
    DW  5678H                ; 偏移 0003H 和 0004H
DATA ENDS
```

```text
    数据段内的偏移地址 → 存储器内容
    ┌─────────────┬─────────────┬─────────────┬─────────────┬─────────────┐
    │  0000H      │  0001H      │  0002H      │  0003H      │  0004H      │
    ├─────────────┼─────────────┼─────────────┼─────────────┼─────────────┤
    │  12H        │  0CH        │  F4H        │  56H（高）  │  78H（低）  │
    └─────────────┴─────────────┴─────────────┴─────────────┴─────────────┘
```

> **易错点**：字节型数据推进时偏移地址加 1，字型数据推进时偏移地址加 2；字型数据中偏移地址较小的那一格放的是高字节。两点都记牢，不要把字型数据的高低字节放反。

> **承前启后**：上一节讲完「控制寄存器、地址空间与数据存放格式」，下一节接着讲「8086的字数据、对准访问与分段寻址」。

## 8086的字数据、对准访问与分段寻址
> 对应块：BLK11 | 覆盖分集：P22-P23 | 块标题（分集名）：《22》

先从一个很容易写错的定义问起：我在数据段里先用 `DB` 定义一个字节，下一行又用 `DW` 定义一个字，那么这个字究竟从哪一个地址开始？是前一行的偏移地址，还是再往后的某个“字地址”？如果这两行分别用 `DB` 和 `DD` 定义，内存里又会摆成什么样？

这些问题看着只是地址往后挪了几个字节，实际上直接连着 8086 的两件大事：一件是**字数据对准还是未对准，决定一次传送用一个还是两个总线周期**；另一件是**一个逻辑地址怎样变成真正的 20 位物理地址**。这两件事不弄清，后面的分段、堆栈和各种寻址方式都会似懂非懂。所以我们先把内存中的数据摆明白，再沿着 CPU 的地址形成过程往回追。

### 先在脑子里摆好字节、字和双字

汇编程序用 `DB`、`DW`、`DD` 告诉汇编器：接下来定义的变量分别占多大的存储空间。

| 定义伪指令 | 数据类型 | 占用字节数 | 内存中的排列 |
| :--- | :--- | ---: | :--- |
| `DB` | 字节型数据 | 1 | 一个字节 |
| `DW` | 字型数据 | 2 | 低字节在低地址，高字节在高地址 |
| `DD` | 双字型数据 | 4 | 第 0 字节在最低地址，随后依次升高 |

这里一定要把伪指令和数据的对应关系记牢：**`DB` 是字节，`DW` 是字，`DD` 是双字**。`DB` 后面的 `B` 表示 byte，`DW` 后面的 `W` 表示 word；`DD` 中的 `D` 表示 double，也就是双字。它们不是三个名字相近的标记，而是在直接规定变量的长度。

无论哪一种数据，8086 都遵循同一条存放格式：**低地址放低字节，高地址放高字节**。我们把地址从低到高排开，就能一眼看清这种安排。

```text
地址由低到高  →

字节型：       +------+
               |  B0  |
               +------+

字型：         +------+------+
               |  B0  |  B1  |     共 2 字节
               +------+------+

双字型：       +------+------+------+------+
               |  B0  |  B1  |  B2  |  B3  |     共 4 字节
               +------+------+------+------+
                低地址                         高地址
```

举个已经熟悉的例子。若 `AX = 34A3H`，那么 `AL` 是低 8 位 `A3H`，`AH` 是高 8 位 `34H`。把这个 16 位字写入存储器时，不能把 `A3H` 放到高地址、把 `34H` 放到低地址，而应当是：

```text
DS:0006H  →  A3H    ← AL，低字节
DS:0007H  →  34H    ← AH，高字节
```

所以，看到“字地址”时，不要只盯着那个十六进制数像不像双数。你首先得知道：**一个字由两个相邻字节单元组成，它的起始地址由低地址处的那个字节单元决定。**

> **易错点**：`DW` 定义的不是一个凭空多出来的单元，而是相邻的两个字节单元；`DD` 定义的也不是两个独立的字，而是按相同规则连续摆放的四个字节。

### 对准与未对准，差的就是一个总线周期

把上面的字数据放好之后，就可以给它起名字了。

- 如果字数据的起始地址是偶数，也就是 `0` 端的 `2` 端、`4` 端……这个字单元叫**对准字单元**。
- 如果字数据的起始地址是奇数，也就是 `1` 端、`3` 端、`5` 端……这个字单元叫**未对准字单元**。

这里最容易混淆的是：判断对准与否，看的是**字单元的起始地址能不能被 2 整除**，不是看这个数据是不是 16 位。一个 16 位数据当然可能是对准的，也可能是未对准的；决定因素只有它的起始地址。

#### 字节走哪八根数据线

8086 的数据总线宽度是 16 位，共有 `D0～D15`，可以分成两组：

- `D0～D7`：低 8 位数据线，也叫低八位数据线；
- `D8～D15`：高 8 位数据线，也叫高八位数据线。

CPU 访问一个字节单元时，地址的奇偶性决定它从哪一组数据线传送。

```text
字节所在地址       实际使用的数据线
────────────────────────────────────
偶地址             D0～D7
奇地址             D8～D15
```

所以，一个字节放在偶地址，就走低八位数据线；同一个字节若放在奇地址，就要走高八位数据线。CPU 会自动判断，我们不用在程序里手工指定数据线。

#### 对准字为什么一拍就能搬完

现在看对准字。假设字单元从 `0006H` 开始，它占 `0006H` 和 `0007H` 两个字节单元：

```text
DS:0006H   低字节 A3H   → 经 D0～D7
DS:0007H   高字节 34H   → 经 D8～D15
```

这两个字节的地址一低一高，正好让低字节走低八位数据线，高字节走高八位数据线。它们可以在**同一个总线周期**内并行送入存储器，因此一次 `MOV` 就把完整的 16 位数据写完了。

```text
                   一个总线周期
        ┌──────────────────────────────┐
D15～D8 │             34H              │
        ├──────────────────────────────┤
 D7～D0 │             A3H              │
        └──────────────────────────────┘

0006H 接收 A3H，0007H 接收 34H
```

这正是对准字单元速度快的根本原因：不是 CPU 把一个字节传两遍，而是低、高两部分恰好可以同时走两根八位通道。

#### 未对准字为什么必须拆成两拍

若把同一个 `AX = 34A3H` 写到从 `0003H` 开始的字单元，位置就变了：

```text
DS:0003H   奇地址   低字节 A3H
DS:0004H   偶地址   高字节 34H
```

第一个字节在奇地址，只能使用 `D8～D15`；第二个字节在偶地址，只能使用 `D0～D7`。一次传送无法让这两个字节同时进入各自正确的数据线，所以必须分成两个总线周期。

```text
第 1 个总线周期
D15～D8  ← A3H       写入 DS:0003H
D7～D0   ← 不用

第 2 个总线周期
D15～D8   ← 不用
D7～D0   ← 34H       写入 DS:0004H
```

于是，一个总线周期只能完成 8 位传送，第二个总线周期再完成另外 8 位。**对准字读写用 1 个总线周期，未对准字读写用 2 个总线周期。**对于 8086 系列 CPU，这两种字访问在速度上正好相差一倍。

把两种情况合起来看：

| 字单元起始地址 | 对准情况 | 低字节使用的数据线 | 高字节使用的数据线 | 写完 16 位所需总线周期 |
| :--- | :--- | :--- | :--- | ---: |
| `0006H` | 对准 | `D0～D7` | `D8～D15` | 1 |
| `0003H` | 未对准 | `D8～D15` | 下一周期用 `D0～D7` | 2 |

这里的“差一倍”说的是**字数据在总线上的传送时间**，不是说包含取指、运算、循环等全部动作的整段程序都快一倍。把时间差限定清楚，才不会夸大结论。

#### 让频繁读写的字落在偶地址

这一点在实际程序设计中非常实用。如果程序经常以字为单位读写某个变量，定义时就要尽量让它从偶地址开始：

```asm
MOV BX, 0006H
MOV AX, 34A3H
MOV WORD PTR [BX], AX
```

`BX = 0006H`，由 `BX` 间接给出段内偏移地址。`DS` 默认提供段地址，所以实际访问的是 `DS:0006H`。这个字单元是对准的，`A3H` 和 `34H` 分别经高、低八位数据线同时写入，只用一个总线周期。

如果改成奇地址：

```asm
MOV SI, 0003H
MOV AX, 5566H
MOV WORD PTR [SI], AX
```

`SI` 同样默认使用 `DS`，但 `DS:0003H` 是未对准字单元。第一个总线周期用 `D8～D15` 把 `66H` 写入 `0003H`，第二个总线周期用 `D0～D7` 把 `55H` 写入 `0004H`，于是：

```text
DS:0003H  →  66H
DS:0004H  →  55H
```

> **结论**：字数据的存放规则始终是“低地址放低字节，高地址放高字节”；起始地址为偶数时对准，一个总线周期完成，为奇数时未对准，要两个总线周期。

### 8086为什么还要给存储器分段

理解了对准和传送速度，我们再回头看 8086 的地址能力。

8086 有 20 根地址线，因此能够直接表示的物理地址空间是：

$$
2^{20} = 1\text{ MB}
$$

可是，能给存储器提供地址的寄存器呢？`BX`、`BP`、`SI`、`DI` 等地址相关寄存器都只有 16 位，它们所能表示的范围只有：

$$
2^{16} = 64\text{ KB}
$$

一个 16 位偏移地址可以找到 64 KB 以内的单元，却无法直接指出 1 MB 空间中的任意位置。问题就这样出现了：**20 位物理地址空间很大，16 位偏移地址却不够用，怎么办？**

8086 的办法不是把地址寄存器硬做成 20 位，而是把内存组织成若干个逻辑段。程序给出的“段值 + 段内偏移”合在一起，就能覆盖整个 1 MB 空间。

#### 一个逻辑段最多有多大

既然偏移地址是 16 位，段内最多表示 $2^{16}$ 个字节，所以一个逻辑段的最大空间就是 64 KB。

不过，“最大 64 KB”只规定了上限，并不表示每一段都必须占满 64 KB。实际程序中，一段可以只有一个字节，也可以有两个字节，需要多少就定义多少。代码、数据、堆栈各有自己的用途，段的大小自然由实际需要决定。

例如，用 `DB`、`DW` 定义的变量都位于数据段中。用 `DW` 定义一个变量，就是从当前位置开始连续占用两个字节；等这个变量定义完，再定义下一个变量。汇编程序用 `END` 之类结束标记告诉它，这一批数据到此为止。

#### 段的起始地址有一个硬要求

逻辑段的起始地址必须能被 16 整除。换句话说，只有物理地址的末位是 `0` 的位置，才能作为一个段的起点：

```text
可以作段起点：00000H、00010H、00020H、00030H……
不能作段起点：00001H、00002H、00003H……
```

为什么偏偏是 16？因为后面形成物理地址时，段值要乘 16，也就是二进制左移 4 位。只有起点末 4 位为 0，左移以后才会得到一个整齐的段基址。

1 MB 地址空间共有 $2^{20}$ 个物理地址，段起点每隔 16 个字节出现一次，因此理论上共有：

$$
2^{20} \div 2^4 = 2^{16} = 64\text{ K}
$$

个不同的段起始位置。

这些段如果都按最大长度划分，相邻起点只相隔 16 字节，而每一段又能向后延伸 64 KB，于是不同段覆盖的范围会大量重叠。示意图画得夸张一点，就是下面这样：

```text
物理地址低端                                      物理地址高端
00000H  ┌──────────── 段 0000H ──────────────────┐
        │                                        │
00010H      ┌──────── 段 0001H ──────────────────┐
        │      │                                 │
00020H          ┌──── 段 0002H ─────────────────┐
        │       │    │                          │
        ⋮       ⋮    ⋮                          ⋮
```

这张图只强调一件事：**段是按逻辑划分的，不是把 1 MB 空间切成互不重叠的固定小盒子。**一个物理单元完全可能同时落在多个逻辑段的范围内。

### 一个存储单元为什么会有两个逻辑地址

既然段可以重叠，同一个物理单元就有可能用不同的逻辑方式描述。描述一个存储单元时，我们使用“段值:偏移地址”的形式，例如：

```text
0001H:0010H
```

冒号左边是 16 位段值，右边是 16 位段内偏移地址。两者都用十六进制书写，中间用冒号隔开。这就是**逻辑地址**。

要注意，段值不是段在内存中的实际起始地址。真正放在内存里的段起始地址是：

$$
段基址 = 段值 \times 16
$$

而偏移地址告诉我们：从这个段的起点开始，再往下数多少个字节。于是逻辑地址可以拆成两部分来理解：

```text
S:EA

S   —— 16 位段值，左移 4 位后得到实际段基址
EA  —— 16 位段内偏移地址，也常称为有效地址 EA
```

一个逻辑段里，段首单元的偏移地址是 `0000H`，往下数一个字节的单元就是 `0001H`，再往下就是 `0002H`。这些编号相对于本段起点，和整个 1 MB 空间中的物理地址不是一回事。

8086 汇编程序以及 `DEBUG` 中使用的地址，写的都是这种逻辑地址。`DEBUG` 里显示的十六进制数，地址部分不要随便当成已经算好的物理地址；它首先是“哪一段中的哪个偏移”。

### 段值乘以16，再加上偏移

现在可以把公式直接写出来了。设段值为 $S$，段内有效地址为 $EA$，则存储单元的物理地址为：

$$
PA = S \times 16 + EA = (S \ll 4) + EA
$$

为什么是左移 4 位？因为乘以 16 就是在二进制数末尾补 4 个 0，也就是左移 4 位。先把段值变成段基址，再加偏移地址，得到的才是 CPU 送到外部地址总线上的 20 位物理地址。

```text
       段值 S                    偏移地址 EA
          │                             │
       左移 4 位                         │
          │                             │
          └──────────────┬──────────────┘
                         │
                      相加形成
                         │
                20 位物理地址 PA
                         │
                   送到 A0～A19
```

看一个最直观的例子。逻辑地址是 `0001H:0010H`：

```text
段值 0001H × 16  = 00010H
偏移地址         = 00010H
物理地址         = 00020H
```

再换一个逻辑地址，物理位置完全不变：

```text
段值 0000H × 16  = 00000H
偏移地址         = 00020H
物理地址         = 00020H
```

所以：

```text
0001H:0010H  ─┐
              ├─→  物理地址 00020H
0000H:0020H  ─┘
```

逻辑地址不同，物理地址却相同；反过来，一个已经确定的物理存储单元，它的物理地址永远唯一。分段没有制造出多个实体单元，只是给了同一个单元多种等价的描述方法。

> **易错点**：不要把冒号左边的段值直接当作段的实际起始地址。段值还要乘 16，真正的段基址才会送到地址形成部件。

### CPU怎样把逻辑地址变成20位物理地址

公式看起来只是“乘 16 再相加”，但8086 执行取指令、数据传送和堆栈操作时，段值和偏移值的来源并不相同。

#### 取指令：CS与IP不能分家

8086 从存储器取指令时，逻辑地址固定采用 `CS:IP`：

- `CS` 提供代码段的段值；
- `IP` 提供代码段内的偏移地址，也就是取指令位置的段内有效地址。

地址形成过程如下：

```text
CS ──左移 4 位──┐
                 ├── 相加 ──→ 20 位物理地址 ──→ 存储器
IP ─────────────┘
                         ↑
                 取回相应位置的指令
```

`CS × 16 + IP` 算出的就是当前指令所在存储单元的物理地址。BIU 用这个 20 位地址到存储器取指令，指令才能真正进入 CPU 执行。

这里一定要记住：**`CS` 和 `IP` 是一对，分不开。**只给出其中一个，不能完整说明取指令地址。

用户程序装入内存并开始运行时，操作系统负责确定用户程序的起始位置，并用代码段的段基址初始化 `CS`，用代码段第一条指令的偏移地址初始化 `IP`。用户不能在普通程序执行中随手写一个值，就要求 CPU 立刻从那里取指。

程序运行以后，`IP` 会随着转移发生改变。若条件成立而发生转移，CPU 修改的是 `IP`；若程序通过远转移，或者调用位于另一个代码段中的子程序，`CS` 和 `IP` 会一起改变。仍然是转移机制在改变地址信息，不是用户偷偷把 `CS:IP` 改掉了。

#### 数据传送：DS与EA相会

执行一般数据传送时，段地址由相应的段寄存器提供，段内有效地址则由寻址方式计算出来。

以把 `AX` 中的 16 位数据写到 `BX` 间接给出的单元为例：

- `BX` 的内容是段内偏移地址；
- 一般数据操作默认使用 `DS`；
- 有效地址 $EA = BX$；
- 物理地址 $PA = DS \times 16 + EA$。

```text
DS ──左移 4 位──┐
                 ├── 相加 ──→ 20 位物理地址
BX → EA ────────┘

AX ───────────────→ 16 位数据总线 ──→ 目标存储单元
```

CPU 先由地址形成部件算出目标单元的 20 位物理地址，再把 `AX` 的内容送到数据总线上，同时发出存储器写命令。若目标字单元对准，一个总线周期写完；未对准，则需要两个总线周期。

如果指令采用 `BX + 8 位位移量` 的寻址方式，有效地址就不再只是 `BX`，而是：

$$
EA = BX + DISP
$$

若使用 `BP` 作为基址寄存器并带位移量，则：

$$
EA = BP + DISP
$$

这就是为什么“段地址由谁提供”和“段内偏移地址怎么算”必须分开看：前者由段寄存器或段超越前缀决定，后者由指令采用的寻址方式决定。

#### 堆栈操作：SS配合SP

执行 `PUSH AX` 时，`SS` 提供堆栈段的段值，`SP` 指出当前栈顶位置。因为这里压入的是 16 位字数据，8086 在写存储器以前先让 `SP` 减 2，再把新的栈顶偏移地址送入地址形成部件。

```text
SS ──左移 4 位──┐
                 ├── 相加 ──→ 20 位物理地址 ──→ 堆栈段
SP - 2 ──────────┘
        │
        └── AX 的 16 位数据写入

SP ← SP - 2
```

所以一次 `PUSH` 的地址，可以写成：

$$
PA = SS \times 16 + (SP - 2)
$$

执行出栈操作时，先用当前 `SP` 找到栈顶字单元，把数据取回寄存器以后，再让 `SP` 加 2：

$$
PA = SS \times 16 + SP
$$

$$
SP \leftarrow SP + 2
$$

取指、读写一般数据、堆栈入栈，看起来是三类不同指令，地址形成过程却有共同结构：**先把段值左移 4 位，再与段内有效地址相加。**变化的是段值和有效地址分别从哪个寄存器或寻址方式中取得。

### 把各类指令的地址信息放回一张表

理解了地址形成过程，再把 8086 各类指令的地址信息集中起来，就不容易混了。

| 操作类型 | 段地址 | 段内有效地址 EA | 必须记住的规则 |
| :--- | :--- | :--- | :--- |
| 取指令 | `CS` | `IP` | 固定为 `CS:IP`，二者不可拆开 |
| 堆栈入栈 | `SS` | `SP - 2` | 压入字数据，先让 `SP` 减 2 |
| 堆栈出栈 | `SS` | `SP` | 用当前 `SP` 取出数据，随后 `SP` 加 2 |
| 一般数据操作 | 默认 `DS` | 由寻址方式确定 | `[BX]` 的 EA 为 `BX`，`[BX+DISP]` 的 EA 为 `BX+DISP`；可加段超越前缀 |
| 字符串源操作数 | 默认 `DS` | `SI` | 源字符串默认在 `DS:SI`，可加段超越前缀 |
| 字符串目的操作数 | 固定 `ES` | `DI` | 目的字符串固定在 `ES:DI`，目的段地址不能随意改动 |

一般数据操作里，使用 `BX`、`SI`、`DI` 时默认取 `DS`；使用 `BP` 时默认取 `SS`。如果指令需要改用其他段，可以增加段超越前缀；没有写段超越前缀，就按默认段规则取。

例如：

```text
[BX]       →  EA = BX
[BX+DISP]  →  EA = BX + DISP

[BP]       →  EA = BP，默认段为 SS
[BP+DISP]  →  EA = BP + DISP
```

字符串操作有两条同时进行的数据通道：

- 源字符串由 `SI` 提供段内偏移地址，默认在 `DS` 段；
- 目的字符串由 `DI` 提供段内偏移地址，固定使用 `ES` 段。

所以“`SI` 是源变址寄存器、`DI` 是目的变址寄存器”并不是一句孤立的口诀，它直接对应字符串操作时的两条地址形成路径。

> **结论**：看到一条操作，先别急着代地址数。先问三个问题：这是什么类型的操作？段地址由哪个段寄存器提供？段内有效地址由哪个寄存器或寻址方式算出？三类问题答清楚，物理地址就只是最后一步相加。

### 段在理论上重叠，实际程序却不会互相踩

讲到这里，可能有人会担心：既然相邻逻辑段的起点只差 16 字节，而一个段又可长达 64 KB，那么程序同时有代码段、数据段和堆栈段，它们会不会重叠？后安排的段会不会把前面的代码覆盖掉？

理论上当然可能重叠，但**汇编程序不会这样随意摆放实际程序中的各段**。

#### 源程序先按逻辑把内容组织好

编写 8086 汇编程序时，我们先声明自己需要代码段、数据段和堆栈段。程序运行后要使用的数据，也必须先在数据段中为它分配存储单元。

例如，程序最后要保存一个结果，那么结果本身也是数据。存放结果的单元应当事先用 `DB` 或 `DW` 定义好，不能等程序运行后凭空从内存里找一个单元“随手放进去”。

```text
代码：让 CPU 执行的指令
数据：输入数据、中间数据、输出结果
堆栈：PUSH、POP 和子程序调用要使用的栈空间
字符串：需要字符串操作时，还要准备目的字符串所在的 ES 段
```

CPU 不认识源程序中的 `MOV`、段名或其他助记符，它只认识机器码。因此，源程序必须经过汇编，翻译成机器语言代码，才能交给 CPU 执行。

#### 汇编程序会把各段安顿到不重叠的位置

汇编时，汇编程序先在存储器中寻找可用空间。代码段从一个能被 16 整除的地址开始安放，所以代码段的起始地址天然满足逻辑段的要求。

代码段结束以后，汇编程序要接着安排数据段。数据段也必须从能被 16 整除的地址开始。如果代码段末尾的下一个地址不满足要求，汇编程序就暂时跳过若干字节，最多向前补齐 15 个字节，直到找到下一个 16 字节边界，再开始放数据段。

```text
可用内存起点
      │
      ▼
00000H  ┌──────────────────────────────┐
        │          代码段               │
FFF0H   └──────────────────────────────┘
             可能补 0～15 字节间隔
10000H      ┌────────────────────────┐
            │        数据段          │
XXXXH       └────────────────────────┘
             再按需要安排后续段
```

这里补齐的目的不是浪费空间，而是保证下一段的起始地址仍能被 16 整除。汇编程序把各段依次安顿在实际内存中，所以**经过汇编并装入内存的程序，各逻辑段不会因为理论上允许重叠，就真的互相覆盖。**

> **易错点**：“8086 的逻辑段最大可达 64 KB，因此相邻段必然大量重叠”说的是理论地址空间；“一个实际程序的各段一定重叠”则是错的。理论允许重叠，不等于汇编程序就这样安排你的代码。

#### 段寄存器指向当前段

程序装入并初始化以后，`CS` 指向代码段的段基址，`DS` 指向数据段的段基址，`SS` 指向堆栈段的段基址；处理字符串时还需要 `ES`。这些段寄存器的值决定 CPU 当前使用哪一段，也就是“当前段”。

8086 有 `CS`、`DS`、`SS`、`ES` 四个段寄存器。它们存放的都是段值，不是已经左移后的段基址。程序运行过程中，可以通过相应的指令和操作改变段寄存器值，从而切换当前段；改变 `CS` 时则伴随代码段之间的转移。

于是，一条普通的数据访问可以沿着完整链条走下来：

```text
指令中的寻址方式
       │
       ▼
算出段内有效地址 EA
       │
       +──────────────┐
                      │
段寄存器中的段值 S ──左移 4 位
                      │
                      ▼
              S × 16 + EA
                      │
                      ▼
           唯一的 20 位物理地址
                      │
                      ▼
               找到目标存储单元
```

这一条链一定要连起来记：**分段解决 16 位偏移地址不能覆盖 1 MB 空间的问题；对准与未对准解决 16 位数据一次能否并行传送的问题。**前者决定地址如何形成，后者决定一次内存传送要花几个总线周期。它们表面上一个讲地址，一个讲数据速度，实际上共同构成了 8086 存储器访问的基本机制。
