## 常用接口芯片与输入输出方式
> 对应块：BLK46 | 覆盖分集：P89-P90 | 块标题（分集名）：《89》

### 为什么设备不能直接接在CPU上

前面讲 `IN`、`OUT` 指令时，我们已经碰过一些常用芯片：输出端口常见的有 74LS373、74LS273 等，输入端口则可能用到 74LS244、74LS245。现在进入接口技术这一章，先要把这些芯片放在整个 I/O 系统中理解。

为什么 CPU 不能直接和任何设备通信？因为设备种类太多，它们对通信的要求差别很大：有设备要求串行传送，有设备要求并行传送；有设备接收、发送数字信号，也有设备处理的是模拟信号；就连传送信息的格式也不一样。CPU 有一套统一的指令和总线，它不可能为了适应每一种设备就改变自己。

解决办法是在 CPU 和设备之间设计一个电路，把二者连接起来。这个电路就是 **I/O 接口电路**，简称 I/O 接口。CPU 一方连接的是系统总线，设备一侧连接具体设备，接口正好处在两者之间。

```text
        CPU 一侧                              设备一侧
  ┌──────────────┐                       ┌──────────────┐
  │     CPU      │                       │  I/O 设备    │
  │              │                       │              │
  └──────┬───────┘                       └──────┬───────┘
         │                                      │
         │            ┌──────────────┐          │
         └───────────▶│  I/O 接口电路 │◀─────────┘
                      │    I/O 硬件  │
                      └──────┬───────┘
                             │
                      配合 I/O 软件工作
```

读这张图时要把边界弄清楚：接口连着系统总线，不代表接口直接等于 CPU；它还承担着信号形式、数据格式和传送时序上的转换工作。系统要真正完成通信，除了 I/O 硬件，还要有相应的软件。负责设备驱动、通信控制和程序配合的部分称为 I/O 软件。

> **定义**：I/O 接口技术，是 I/O 硬件设计与 I/O 软件设计的综合。

本课程讨论 I/O 软件时使用 8086 汇编语言。实际工程中，大多数用户更习惯使用 C 语言，但这不是“不会汇编也能做”的意思。大家参加电子设计竞赛时，一开始往往雄心勃勃地想用汇编语言；真正做上一两周以后，就会发现用不来了，原因常常是汇编语言的基本功底不过关。

### 端口和信息的三种流向

理解了接口的位置，接下来要理解它的基本组成。刚才说过，设备可能要求数字通信，也可能接收模拟信号，还可能是串行或并行数据；设备自己要什么信息格式，我们不去管它。CPU 一方则把接口视为系统总线的一部分。接口要做的，是把这些不同要求接起来。

一种信息通过一个端口传送，这个端口就叫 I/O 端口。按照前面讲过的信息分类，计算机和设备之间传送的信息主要有三类。

| 信息种类 | 传送方向与含义 | 常见对应端口 |
| :--- | :--- | :--- |
| 数据信息 | 输入设备送给 CPU，或 CPU 送给输出设备 | 数据输入端口或数据输出端口 |
| 状态信息 | 设备向 CPU 报告当前状态；相对于 CPU 始终是输入 | 状态输入端口 |
| 命令信息 | CPU 通知设备“数据已经放出来了”等操作要求 | 命令输出端口 |

这里最容易绕晕的是方向。不要站在设备自己的角度机械判断，而要看信息相对于 CPU 的流向。

状态信息一定从设备流向 CPU。设备怎样让 CPU 知道“数据已准备好，赶快来取”？它就得通过状态端口给出这个状态。对于输入设备，是“数据已经准备好，等待 CPU 取走”；对于输出设备，则是“已经准备好接收数据”。这两类状态都要进入 CPU，所以状态输入端口是 **输入端口**。

数据信息的方向则取决于设备类型：输入设备把数据送给 CPU，是输入；输出设备接收 CPU 送来的数据，是输出。至于命令信息，CPU 把数据写到输出锁存器后，还要给设备一个通知。设备据此知道“现在该取数据了”。严格说起来，这个信息应称为 **命令信息**；宽泛地说，也可以叫控制信号或控制信息。

> **易错点**：状态信息是“设备给 CPU 的报告”，所以它相对 CPU 永远是输入；命令信息是“CPU 给设备的通知”，所以它相对 CPU 永远是输出。数据信息则随设备方向变化。

### 状态端口为什么要用三态缓冲器

状态信息最后是怎么送到 CPU 的？CPU 读这个端口时得到一个状态值，再根据高、低电平判断设备是否准备好。如果尚未准备好，程序就继续检测；直到状态表明设备已经准备好，才去执行真正读数据的操作。输出设备的数据同样要通过数据输出端口写入，设备再通过外部数据通信总线取走它。

我们先把接口的“骨架”画出来。每个端口都需要自己的片选信号，才能在总线上被唯一选中。片选信号来自 I/O 地址译码电路，译码方式可以采用纯门电路、专用译码器或其他译码电路；全地址译码和部分地址译码的概念与存储器电路设计相同。

```text
                         系统总线一侧
                     地址线 / 数据线 / 控制线
                               │
          ┌────────────────────┼────────────────────┐
          │                    │                    │
    ┌─────▼─────┐        ┌─────▼─────┐        ┌─────▼─────┐
    │状态输入端口│        │数据端口   │        │命令输出端口│
    │  读设备状态 │        │输入或输出 │        │通知设备动作│
    └─────┬─────┘        └─────┬─────┘        └─────┬─────┘
          │                    │                    │
       设备状态             外部数据             外部设备
      （是否准备好）         通信总线          （取数或执行命令）
```

其中状态输入端口内部，常见做法是设置一个数据输入缓冲器。例如可结合本章常用芯片，选用 74LS244、74LS245 一类器件。但这里有一个必须记住的要求：

> **结论**：输入缓冲器的输出端必须具有三态功能。

为什么？CPU 不用这个端口时，输出端应当呈高阻态，把端口和系统总线隔离开来，防止总线竞争。否则，即使 CPU 根本没有读这个端口，别的部件也会受到该端口输出的影响。只有当 CPU 执行读端口指令、地址又恰好选中这个端口时，缓冲器才把数据送上数据总线。

CPU 每次访问一个端口，都要给这个端口分配一个 I/O 地址。对 8086 系统来说，I/O 地址空间有 $2^{16}$ 个单元，也就是 64K 个地址。如果地址译码采用全地址方式，一个端口分配一个完整地址；若采用部分地址译码，硬件上可能出现地址重叠，但对程序而言，端口仍然只通过一个 I/O 地址访问。这个分配给 I/O 端口的地址，称为 **I/O 端口地址**。

### 端口怎样完成读写

先看状态输入端口的完整过程。地址译码确认端口被选中后，片选信号使输入缓冲器工作；CPU 从数据总线上取得状态值，程序根据状态判断设备是否准备好。尚未准备好就继续检测，已经准备好才去读真正的数据。

数据端口则要看它是输入还是输出。对输出设备，它就是数据输出端口。CPU 用 `OUT` 指令把数据写入这个端口，数据先进入输出锁存器或输出端口的输出端。设备怎样知道 CPU 已经把数据放出来了？还需要命令输出端口发出通知。

命令同样从数据线送入，存入相应的锁存器，再输出给设备。必要时，命令先造成短暂延时，随后恢复，从而形成一个负脉冲，使设备在这个有效脉冲期间把数据取走。这里的关键不是“输出了多少位命令”，而是 **命令和数据必须配合**。

> **提示**：端口是按“一类信息、一个端口”的思路来组织的。设计接口时，状态、数据、命令的流向和锁存/三态要求不同，不能把所有信号不加区别地塞进同一种电路。

### I/O端口地址的两种编制方式

I/O 端口地址怎么编？第二章讲指令时已经碰到过这个问题：一类是独立编制，另一类是统一编制，有的教材把“统一编制”也叫作“映射编制”。这一部分一定要分清。

#### 独立编制：给I/O一块自己的地址空间

80x86 系列 CPU 对 I/O 地址采用独立编制。给 I/O 分配的地址空间与给存储器分配的地址空间彼此独立。

8086 CPU 有 20 根地址线，全部用于存储器时，存储器地址空间是 $2^{20}$，也就是 1MB。与此同时，CPU 又从这 20 位地址线中取出低 16 位，用于 I/O 寻址，于是 I/O 地址空间是 $2^{16}$，大小为 64KB。

同一根地址线在什么场合表示存储器地址、什么场合表示 I/O 地址，还要由控制信号来区分。对 8086，系统使用 `M/IO` 信号；对 8088，使用 `IO/M` 信号。把它记清楚：**信号名称的次序不同，但都是用控制信号把两类地址空间区分开。**

独立编制的优点很直接：I/O 地址不占用存储器地址空间，1MB 的存储器空间可以完整留给存储器。缺点则要从指令系统上看。

既然 I/O 与存储器采用两套独立地址空间，8086 指令系统就不能直接用所有存储器读写指令访问端口，只能另外设置 `IN`、`OUT` 这类专用指令。于是：

- 指令系统变得更复杂，程序员需要同时记住存储器操作与端口操作的不同指令。
- 端口操作的寻址方式也比存储器少。8086 对存储器有五种基本寻址方式，而 `IN`、`OUT` 对 I/O 端口只有直接寻址和通过 `DX` 间接寻址两种方式。
- 编写 I/O 驱动程序时可选择的寻址形式少，灵活性受到限制。

独立编制的缺点是有的，但总体上它的优点大于缺点。

#### 统一编制：端口和存储器共享地址空间

统一编制把存储器和 I/O 端口放在同一个地址空间中。以 MCS-51 系列单片机为例，可以把 AT89C51、AT89C52 作为直观的参照。

51 系列有 16 位地址空间。P0 口中的 P0.0～P0.7 对应 $A_0～A_7$，既可作地址线，也可与 $D_0～D_7$ 数据线复用；P2 口中的 P2.0～P2.7 专作高 8 位地址线 $A_8～A_{15}$。这 16 条地址线可以表示 $2^{16}$ 个地址，也就是 64K 个地址。

这 64K 地址既可供外部存储器使用，也可供 I/O 端口使用。假设外部 RAM 占用了相当多的地址，剩余地址才能分给 I/O 端口。两者共享同一个 64K 地址空间，外部存储器和外部 I/O 占用其中的不同区域。

在统一编制的系统里，CPU 识别 I/O 端口和识别一个外部存储器单元使用的是同一种地址信息。**对存储器的所有读写指令，同样适用于 I/O 端口**。这是它最重要的优点：编写 I/O 驱动程序更直接，指令系统也无需再为端口另设一套完整的操作方式。

它的代价也很明确：I/O 端口占用了 64K 地址空间中的一部分，外部存储器的可用地址空间相应减少。

| 对比项 | 独立编制 | 统一编制 |
| :--- | :--- | :--- |
| 地址空间 | I/O 与存储器分别编号 | I/O 与存储器共享同一空间 |
| 端口指令 | 需要 `IN`、`OUT` 等专用指令 | 可使用存储器读写指令 |
| 寻址与程序设计 | 端口寻址方式较少，程序设计较复杂 | 指令统一，驱动程序较简单 |
| 地址空间代价 | 不占用存储器地址空间 | I/O 端口会占用部分存储器地址 |

> **结论**：8086、8088 系统对 I/O 端口采用独立编制。比较两种方式时，不要只问哪一种“更好”，要把地址空间代价、指令系统复杂度和程序设计灵活性一起算进去。

### 无条件输入输出：不问状态，直接传数据

掌握了接口组成以后，再来看输入输出方式。最先遇到的是 **无条件输入输出**。

前面已经画过 CPU 与设备之间通过状态端口、命令端口和数据端口通信的图。既然叫“无条件”，就是有意打破这种必须检查状态的流程：设备不报告“准备得怎么样”，CPU 也不等待它，直接把数据送出或取回。

#### 什么样的设备可以无条件通信

无条件通信适合那些始终准备好、随时可以接收或提供数据的简单设备。

最典型的输出设备是 LED 灯。你用软件控制接口电路，决定灯亮还是灭，总不能要求 LED 灯每次都先报告：“我已经准备好接收数据了。”它永远处于接收数据就绪状态。只要 CPU 执行 `OUT`，数据就能被输出设备接收。这样的设备可以称为“傻瓜式输出设备”：你给我数据，我就要。

典型的无条件输入设备是开关或按键。开关打到上方，输出 1；打到下方，输出 0。它不需要再告诉 CPU “我的数据已经准备好了”，因为它始终把当前状态摆在数据线上，随时等待 CPU 取走。

| 设备类型 | 无条件成立的原因 | CPU 的动作 |
| :--- | :--- | :--- |
| LED 等简单输出设备 | 始终可以接收输出数据 | 直接 `OUT`，不再查询状态 |
| 开关、按键等简单输入设备 | 当前值始终有效，等待 CPU 读取 | 直接 `IN`，不再查询状态 |

#### 输出端口为什么仍要锁存

无条件并不意味着输出端口不需要锁存。这里的输出端口仍然必须具有锁存功能。

原因在于 CPU 的数据总线很忙。同一时刻，它可能给这个输出设备送数据，也可能给其他端口输出数据、从其他端口读数据，还要和外部存储器交换数据。CPU 执行 `OUT` 把数据送到某个端口后，并不能指望这个慢速设备立即取走。数据必须先锁存在接口的输出端，设备再从那里取。

```text
          CPU                         I/O 接口                  LED
       ┌──────┐                   ┌──────────┐                ┌──────┐
       │ OUT  │──数据总线────────▶│ 锁存器   │──输出端数据───▶│ 灯   │
       └──────┘                   └──────────┘                └──────┘
                 CPU 总线转去其他操作              设备按自身节奏取走
```

数据送上总线之后，锁存器把数据留住。即使系统总线已经转去服务其他设备，输出端的值仍然保持，直到下一次写入。

无条件场景里，CPU 与设备之间只需要传送数据信息。设备没有“准备状态”可报告，CPU 也没有必要再发专门命令。**没有状态，并不意味着不要锁存。** 恰恰因为设备速度慢、CPU 总线转得快，锁存更不可缺少。

### 用时序把输出电路讲明白

常见输出锁存芯片包括 74LS373、74LS274、74LS273 等。实际选用哪一种，不能只看名称，要回到第五章的时序关系。

以 74LS373 为例，把 `\overline{OE}` 接地后，输出端始终允许送出锁存的数据。真正控制数据装入的是 CP 端，该端在上升沿把输入数据送入并锁存在输出端。时序关系可以这样看：

```text
数据 D          ____ ____ ____
               |    |    |    |
            ____|    |    |    |____
                  ┌───┐
              ____┘   └────
CP 上升沿 ─────────┘

Q 输出       ──── 输出数据保持 ────
OE = 0       始终允许 Q 与负载连接
```

这就是时序选芯片的关键：先看数据在什么时刻进入锁存器，再看输出端在什么条件下对设备有效。

来看一个具体例子。假设在 8086 最小模式下，某个输出端口的地址是 `8000H`，通过地址译码和写信号产生锁存所需的上升沿。

`8000H` 的二进制形式为 `1000 0000 0000 0000`。如果这条地址线接的是反相器，那么选中该端口时，相应译码信号为 1。再结合“向 I/O 写操作有效”的控制条件，经过与门和反相器组合，可以得到控制 CP 的译码信号。CPU 写端口期间，这个信号保持有效，使数据装入锁存器；写操作结束时，它撤销。这样既完成了地址选择，也保证了锁存动作和 I/O 写周期相配合。

> **易错点**：地址值、地址反相条件和控制信号的有效电平不能凭感觉连。先把二进制地址写出来，再按译码电路的实际输入逐项判断；看到“或门有一个输入为 1”时，不能笼统地说“输出必为 1”，还要看其余输入。

## I/O 传送的节拍与方法：三种程序控制方式和输出端口设计
> 对应块：BLK47 | 覆盖分集：P91-P92 | 块标题（分集名）：《91》

有同学提了一个很典型的问题。他说：我这有一个或非门，信号最后变成这样，把上升沿挪到前面来了。我现在设计用的是后沿，用前沿有什么区别？

这个问题问得非常好，因为在实际的工程设计里，回答就一句话——系统不可靠。

为什么不可靠？第五章讲最小方式时序的时候，这一点要特别注意。今天我们把它讲透，因为后面所有的 I/O 接口设计——输出端要不要接锁存器、锁存器的时钟到底取前沿还是后沿——全都卡在这个点上。

要讲清楚，我们回到最小方式时序。大家看，在 `T1` 状态，地址已经送到总线上了；到了 `T2` 以后，数据才出现在数据总线上。地址变数据，是需要一个准备过程的。也就是说，CPU 从某地址输出、到这个地址对应的数据真正有效之间，是有一个反应时间的。在这个反应时间里，你去数据总线上取数据，能取到有效的数据吗？不能。

但是反过来，在有效数据出来之前，地址是不是已经有效了？是的，从 `T1` 状态一开始，地址就送上去了。如果这个写信号也有效了，是不是很快就能找到一个上升沿？这个上升沿一到，就把数据锁存出来了——可是这一刻，数据总线上的数据是无效的，它还处在从地址切换到数据的过渡过程中，锁进去的是旧数据，甚至是乱数据。

那如果取后沿呢？写信号变高，写操作结束的时候，数据总线上的数据早就稳定了，肯定有效。地址在整个周期里一直有效，写信号由低变高的那一瞬间，就是我们要的那个上升沿，它一到，数据就被正确地锁存出来了。

> **易错点**：锁存时钟必须取写操作的后沿，也就是写结束的瞬间，绝不能取前沿。前沿触发的时候，数据还没有经过那段反应时间，锁进去的是无效数据。

```text
        T1              T2              T3              T4
地址   ────────────────────────────────────────────────  （从 T1 起就有效）
数据   ──────────────────╗      ╔─────────────────────
                         ╚══════╝  （反应时间之后才有效）
写信号 ─────────────────────╗                    ╔──────
（低有效）                   ╚════════════════════╝
                                 写期间为低，写完返回高
                                                  ↑
CP 上升沿触发                                  写结束＝后沿
                                             （此刻数据已稳定有效）
```

看这张图你就明白了：地址先有效，数据后有效，中间还隔着一段反应时间。前沿触发发生在写刚开始的时候，数据还没准备好；后沿触发发生在写结束的时候，数据早已稳定。所以一定要取后沿。

这个坑在科研和毕业设计里我们都见过。有同学系统调通了，很高兴，但每天总有那么一个时刻，数据怎么就错了。那错误从哪来的？就是你取的是前沿。前沿带来的，就是系统的不稳定。这种问题最麻烦的地方在于，它不是一直错，而是有时候错——测试的时候可能一整天都不复现，一到现场就冒出来。所以这一条一定要记住：锁存时钟取后沿。

还有一点。假如你把芯片换成了 74LS373，会怎么样？373 的那个引脚就不能叫 CP 了，它叫锁存使能，高电平有效。你看它处在高电平的那一段时间里，数据一直跟着数据总线在变；数据总线前端有干扰，干扰也一起被带出来，稳定吗？不稳定。所以大家在设计输出端口的时候，不要选 373，要用边沿触发的 74LS374 或者 74LS273，而且要用后沿来触发，这样系统的稳定性才能提上去。

> **结论**：输出端口的锁存器要用边沿触发的 74LS374／74LS273，用写操作的后沿（上升沿）触发；不要用高电平透明的 74LS373，因为它在使能期间会把数据总线上的干扰一并锁进去。

### 无条件传送方式

> **定义**：无条件传送方式，是指 CPU 不去检查设备状态，直接用 IN／OUT 指令在 CPU 与设备之间传送数据的方式。

我们先看一个无条件的输入设备。什么叫无条件？就是这个设备永远都准备好了。比如一个开关——开关的状态是恒定的，你拨到高就是高，拨到低就是低，它永远不存在"还没准备好"这回事。开关把这个状态从数据输入端口送给 CPU，CPU 一读这个端口，读到的就是有效的数据。

但是，有没有一种"无条件输入设备"，它提供给 CPU 的有效数据是瞬间的呢？有。有些设备把数据送到端口上的那一瞬间是有效的，你读完了它就撤走了，去干别的事情，不在那里等着你。这种情况下怎么办？就在中间增加一级缓冲，这一级缓冲的输出端应该具有锁存功能——显然，这一块电路就是一个锁存器。设备把准备好的数据存进锁存器，锁存器把它留住（一直有效），CPU 再去读这个端口，读到的就是被留住的那份有效数据。

```text
瞬间有效的设备 ──▶ [锁存器] ──▶ 输入端口 ──▶ CPU
                   （把瞬间数据留住）
稳定状态的设备（如开关）──▶ 输入端口 ──▶ CPU
                   （不需要锁存器）
```

看这张图：设备状态稳定的，比如开关，数据直接接端口，CPU 一读就有；只有设备数据是瞬间有效、读完就走的，中间才需要一级锁存器把数据留住。当然，这只是偏小的情况；在大多数应用里，设备的状态是稳定的，这部分完全可以不要。

### 查询方式

> **定义**：查询方式，也叫查询法，是指 CPU 反复读取设备的状态端口，测试就绪标志，直到设备就绪后，再用 IN／OUT 传送一次数据的方式。

我们看输入输出方式的第二组，查询法。

假如设备是智能的——它自己知道什么时候准备好了——那你是不是要在接口里设计一个状态输入端口？程序上，一开始先做一部分初始化，马上就要读状态了：通过状态输入端口把设备的状态读进 CPU，读进来马上测试。测试状态就知道设备是否准备好了。没准备好，怎么办？再去读一次状态，再测。准备好了？好，这时才和设备之间传送一次数据，传一次就够。传完以后呢？在你整个系统当中，相当于循环程序设计里计数递减那样，还要测一下数据传完了吗？没传完，就回到读状态、测状态这里，在传下一次数据之前，再测一次设备准备好了吗。等到数据全传完了，设备才去干别的事情。

所以整个工作思路就是：CPU 一直在查询——"你准备好了吗？"

```text
        初始化
           │
           ▼
    读设备状态 ──▶ 测试就绪标志？── 没就绪 ──┐
           ▲                                │
           └────────────────────────────────┘
           │ 就绪
           ▼
      传送一次数据（IN 或 OUT）
           │
           ▼
    数据传完了吗？── 没传完 ──┐
           │ 传完            │
           ▼                 │
   设备去干别的事，      回到「读设备状态」
   CPU 做其他工作
```

看这张流程图就明白了：设备没准备好的时候，CPU 就卡在"读状态—测试—再读"的圈里出不来；就算传完一次数据，还得回来查有没有传完。整个过程，CPU 全程陪着设备转。

那这个"测设备准备好了"在程序上怎么测？显然是先把状态输入端口的地址给 DX。如果所有端口的地址都没有超过 255，那在 IN／OUT 指令里还可以不用间接寻址，直接寻址就行。然后用 `IN` 把设备的状态读到 AL，读回去是 8 位。设备的状态输出线接到数据总线 `D0`–`D7` 的某一位，比如接到第 0 位，那就是测 `AL` 里面那一位。

我们假设这个状态是低电平有效。用 `TEST AL, 01H` 测一下：如果结果非零，说明读回来的最低位是 1，认为设备还没准备好，跳到 `L1`，继续读状态、继续测；如果还没准备好，就继续走。一直查询，直到测到结果为零了，才退下来传送数据。

```asm
MOV DX, STATUS_PORT     ; 状态输入端口地址送 DX
WAIT_READ:               ; 查询入口
    IN  AL, DX           ; 读设备状态到 AL（端口地址＜256 时可改为直接寻址）
    TEST AL, 01H         ; 测试状态所在的 D0 位
    JNZ WAIT_READ        ; 低电平有效：读回 1 表示未就绪，继续查询
    ; 结果为零，设备就绪——此处传送一次数据
```

这几行就是查询法的核心：`DX` 装状态端口地址，`IN` 把状态读进 `AL`，`TEST AL, 01H` 把状态所在的那一位单独拎出来测；低电平有效时，读回 1 就是没就绪，`JNZ` 跳回去接着读，一直读到结果为零，才往下走去传数据。

那么，用查询法来实现 I/O 传送，最大的优点是什么？电路实现简单。刚才画的那个接口组成图里，读设备状态只要一根状态输入端口，电路非常简单。

缺点呢？我把缺点夸张一下你就看出来了。假如我早上八点上班一开机，CPU 就做这个事情：多设备状态，测设备状态——"你准备好了吗？""没有。"死磕设备状态，一直查到中午十二点下班都没准备好。那 CPU 这一早晨是不是全耗在这儿了，什么事都没干。这对 CPU 而言效率高吗？一点都不高。所以查询法实现 I/O 传送，最大的缺点就是效率低，CPU 效率低。

还有一种情况。假如整个系统里挂接的设备比较多，每个设备与 CPU 之间的数据通信都用查询法：读设备 1 的状态——"你准备好了吗？"读设备 2 的状态，测它；一直这样查下去。查完所有设备，测到设备 N 的状态——"你准备好了吗？"然后我再跑回去查设备 1 的状态。这样一圈下来，是不是效率也低？而且在我一直读到设备 N 状态的时候，设备 N 也没准备好；等我回来再查设备 1 的时候，设备 1 也没准备好。可是在这一圈的时间里，设备 1 曾经准备好了一次，你却把"准备好"的那一次给丢掉了。有没有可能？是完全有可能的。所以查询法除了效率低，还可能把设备那转瞬即逝的"就绪"时机给错过。

那么实际工程中用不用查询法，要视情况而定。如果系统挂接的设备数量不多、设备种类不多，而且 CPU 本来也没什么事做，那用查询法实现所有传送，反而来得简单。但是当 CPU 比较忙的时候，你就不能用这种方法了，得换一种——换什么呢？换中断法。

### 中断方式

> **定义**：中断方式，是指设备准备好之后，主动通过中断控制器向 CPU 提出中断请求，CPU 响应后转入中断服务程序完成数据传送的方式。

那中断法是怎么回事？我们画个图。

```text
设备（数据传送准备好了）
    │  准备好信号
    ▼
8259（外部可屏蔽中断控制器）
    │  中断请求
    ▼
CPU
```

看这张图：设备把传送数据准备好了，它并不等 CPU 来问，而是主动发出一个"准备好"信号，向 8259 提出中断请求；8259 再向 CPU 请求中断。由设备发起，而不是由 CPU 反复去问——这就是中断法和查询法最本质的区别。

从程序上看是这样：这是主程序，在执行。执行到某一条指令时，中断请求信号恰好来了。这时如果 CPU 已经开了中断，CPU 就要响应这个中断请求。怎么响应？第一步，先把当前这条指令完整地执行完，不能执行到一半就跑了。第二步，保护现场：把 `PSW`、`CS`、`IP` 依次压栈。第三步，从向量表里取中断向量——所谓中断向量，就是中断服务程序的入口地址，它放在向量表里，放在哪儿呢？放在 $n \times 4$ 的位置，$n$ 就是中断类型号。取到向量后，把偏移地址送给 `IP`，把段地址送给 `CS`，于是 `CS` 和 `IP` 就指向了中断服务程序的入口。第四步，从服务程序入口开始取指令，执行这一段服务程序——在这里给设备传送数据、和设备之间通信。通信完了，执行中断返回指令 `IRET`。`IRET` 做什么？把刚才保护压进栈的现场按相反的顺序弹出来——`IP`、`CS`、`PSW`，依次出栈——恢复现场，让 `CS` 和 `IP` 指回主程序。

> **易错点**：中断返回后，`CS:IP` 指向的是被打断指令的"下一条"指令，要从那里继续往下执行，而不是回到被打断的那条指令上重跑一遍。

```text
主程序执行……执行到某一条指令
          │
          │  中断请求到来，且 CPU 已开中断
          ▼
   先把当前这条指令执行完
          │
          ▼
   保护现场：PSW → CS → IP 依次压栈
          │
          ▼
   依中断类型号 n，从向量表 n×4 处取中断向量
          │
          ▼
   偏移地址 → IP，段地址 → CS
          │  （CS:IP 指向中断服务程序入口）
          ▼
   执行中断服务程序（用 IN／OUT 与设备传送数据）
          │
          ▼
   执行中断返回 IRET：IP → CS → PSW 依次出栈
          │
          ▼
   CS:IP 指回被打断指令的下一条，恢复主程序
```

这张图把中断的完整过程串起来了：执行完当前指令、保护现场、取向量装入 `CS:IP`、跑服务程序、`IRET` 弹栈返回。中间任何一步都不能少，尤其是"先执行完当前指令"和"保护现场"这两步。

那从硬件上说，设备这边还要什么？假如这是个外设，那这个地方就要设计一个数据输出端口，通过数据线把数据用 `OUT` 指令输出到这个端口。当然，这个设备如果还需要用命令来控制，那这个地方还要设计一个命令端口，给它发一个命令。

这就是中断法。那用中断法来实现设备与 CPU 之间、设备与内存之间的数据传送，对 CPU 而言效率是不是提高了？是不是没有查询的时间了？没有了，效率大大地提高。这是它的优点。但是缺点有没有？有。在中断请求与响应这一部分，电路是比较复杂的。不过说它"不太复杂"也对，因为已经有专用的 8259 芯片了嘛。所以也不算太复杂。

### 三法同源与 DMA 的引入

我们把三种方法放在一起看一看。不管是无条件输入输出方法，还是查询法，还是中断法，CPU 与设备之间的数据传输，都是利用 `IN`／`OUT` 指令来实现的。理解吗？都是。

"你准备好了吗？""准备好了。"传一次数据。如果是输出设备，就 `OUT` 一次；所有读数据的都是 `IN`。即使是中断法，中断请求来了，CPU 转到中断服务程序里，设备与 CPU 之间的数据传送，在服务程序里面也是用 `IN`／`OUT` 指令来完成的。

所以这三种方法，统称起来可以把它称为——程序直接控制的输入输出方法。所谓"程序直接控制"，指的就是数据的输入输出传送，是用 `IN` 或者 `OUT` 指令实现的。

> **注意**：很多教科书里，"程序直接控制的输入输出方法"只包含无条件传送方式和查询方式这两种，把中断法单独提出来了也行。怎么分类，看你怎么分——两种分法都说得通。

但是，不管是无条件输入输出方法、查询法还是中断法，CPU 与设备之间的数据传送都是程序直接控制的，都得靠执行程序才能实现。而执行程序中的任何一条指令，都是需要时间的，比如一条指令就要四个 T 状态。显而易见的，在设备与内存之间进行批量数据传送时，这个"花的时间"就太多了。就像我们以前讲过的，硬盘和内存之间要传数据，每传一个字节都用 `IN`／`OUT` 指令来实现，这显然速度是很慢的——CPU 靠执行程序来实现，速度根本来不及。

那在这种情况下，就要用第四种方法了——DMA。

> **定义**：DMA（Direct Memory Access，直接存储器存取）方式，是由 DMA 控制器 8237 接管总线，在硬件控制下完成外设与内存之间成批数据传送的方式。

```text
外设 ──传送请求──▶ 8237（DMA 控制器）──总线请求──▶ CPU
                     ▲                            │ 当前指令执行完
                     │                            ▼
                     └──── 总线响应（HLDA）──── CPU 让出总线
                     │
                     │ 接管总线
                     ▼
              外设  ⇄  8237  ⇄  内存
              （硬件控制成批传送，全程不执行指令）
```

这张图是 DMA 的全过程：8237 先向 CPU 请求总线使用权；CPU 把当前这条指令执行完，就把总线让出去，并回送一个总线响应；8237 收到这个响应，就知道 CPU 已经把总线让给它了，于是它接管总线，由 8237 这个芯片在硬件控制下，完成设备与内存之间的数据传送。整个传送过程都是硬件在完成，并没有执行指令。

所以用 DMA 实现数据输入输出，最大的优点就是速度快。缺点呢？电路复杂。这一点倒是很好回答——电路复杂。

关于 DMA，在 60 学时的这门课当中，没有列入到教学大纲里。我只提一下：这是几种输入输出方法里的一种。

顺便说一下，每年都有大学生考那个计算机等级考试。大家考等级的时候，不管你报二级还是三级，好多同学报三级，是不是考试去了？这门课学完了，你也可以报三级偏硬那个类别。偏硬里面，程序设计要求用的就是汇编语言，8086 汇编语言。我相信大家如果真要考计算机三级偏硬，把那个三级偏硬的书买回来看一下，绝对能考上。这个我不吹牛。

另外，无条件方式和查询方式的例题、练习就在这一章，而中断方式的例题要到第八章再讲，所以这一章剩下的就是这些常用芯片的接口例题了。

| 方式 | 是否需要查状态 | 电路复杂度 | CPU 效率 | 典型适用场合 |
| :--- | :--- | :--- | :--- | :--- |
| 无条件传送 | 不需要 | 最简单（稳定设备直接接；瞬间数据加一级锁存） | 高 | 设备永远就绪或状态稳定，如开关 |
| 查询方式 | 需要，循环读状态端口 | 简单，只需一根状态输入线 | 低，CPU 反复查询 | 设备不多、CPU 空闲时 |
| 中断方式 | 不需要，设备主动请求 | 较复杂，需中断请求／响应与 8259 | 高 | 设备较多、CPU 忙时 |

这张表把三种方式的取舍摆在一起：无条件最省电路，查询最省电路但最耗 CPU，中断最费电路但最省 CPU。选哪种，取决于你的设备多不多、CPU 忙不忙。

### 例题：PC XT 总线上的 74LS374 输出端口

这一章的第四个标题，就叫"常用芯片的接口技术"。我们看课本上的第一道例题，例 7.1。

这道题大家都听我讲一遍肯定就能做完。我希望大家读完题，脑子里边先想清楚两件事：这道题给了我什么？它要我做什么？想清楚了这两点就行。电路图怎么画、程序怎么编，留给咱们自己去想。我先带大家把题目读懂、把设计思路理一遍。

题目给的条件很明确：在 PC XT 系统总线上扩展设计一个数据输出端口。端口分配地址 280H，锁存芯片用 74LS374，输出设备是 8 个 LED 发光二极管。

| 题目给出的条件 | 内容 |
| :--- | :--- |
| 系统总线 | PC XT 系统总线 |
| 端口地址 | 280H |
| 锁存芯片 | 74LS374 |
| 输出设备 | 8 个 LED 发光二极管 |
| 要求 | 画输出端口与系统总线的连接图、与 LED 设备的连接图 |

我先扫一下 PC XT 系统总线上有哪些信号是我们能用的。

数据线是 8 根，`D0` 到 `D7`。地址线呢——我常说 10 根，严格说 PC 机上 I/O 用的地址线其实是 16 根，`A0` 到 `A15` 全译了也没错，但是 PC 机实际上只用了 `A0` 到 `A9` 这 10 根；严格来说，PC 机上给 I/O 地址译码用的是部分地址译码，`A10` 到 `A15` 没参加。所以我们能用的地址线就是 `A0` 到 `A9`。

控制信号要用到 `IOW`。还要用到 `AEN`：当 DMA 工作时 `AEN` 等于 1，当 CPU 执行 `IN`／`OUT` 指令时 `AEN` 等于 0。我们设计的是一个 CPU 用的端口，CPU 执行 `IN`／`OUT` 时才工作，所以要把 `AEN` 等于 0 这个条件也加进译码里去。

#### LED 接法：把电流还给电源

好，现在来看这个输出端口的内部。374 的 `D0` 到 `D7` 是数据输入端，这个数据从系统数据总线来。我们画数据总线时会画成双向的，但在端口这里是单向输出：数据从 `D0`–`D7` 进来，经过 374 锁存，再从 `Q0` 到 `Q7` 出去，送给 8 个 LED。

这里有个问题得解决。题目没说 LED 怎么接，我们假设 `Q0` 输出控制一个 LED。`Q0` 输出的信号是高还是低对应灯亮还是灭？题目没说，我们先假定 Q 输出为 1 时灯亮。那这个灯的电路怎么设计？

最简单的一种：直接接。看这个发光二极管，这边接地，输出接到灯，灯就亮了。但是——灯亮的时候有一个大电流流过，至少几毫安。那这个电流是谁提供的？是 374 内部的那个 D 触发器提供的。假如 8 个 LED 都在亮，374 就一直处于大电流输出状态，功耗很大，它就发烫，你天天让它发烫，它总有一天要烫坏。所以这样设计的可靠性不高。

那如果我要让输出点亮灯，怎么办？这样做行不行？加一个反相器。刚才那样（直接接）也可以，加一个驱动管也可以。我这里加一个反相器：反相以后接发光二极管的负极，正极经过一个限流电阻接到 +5V。

```text
                +5V
                 │
              限流电阻
                 │
                 ▼
            ┌─────────┐
            │   LED   │   阳极在 +5V 一侧，阴极接反相器
            └────┬────┘
                 │ 阴极
                 ▼
            ┌─────────┐
Q0 ─────────▶│ 反相器  │
            └────┬────┘
                 │ 灌下 LED 电流
                GND
```

看这张图：374 的 Q 输出 1 时，反相器输出 0，从 +5V 经限流电阻、LED 灌入反相器的电流被拉下来，LED 亮；Q 输出 0 时反相器输出 1，截止，灯就灭。关键在于，灯亮时的那个大电流是电源通过限流电阻提供的，由反相器把它灌下去；374 内部只是去驱动反相器那个输入端，几乎不担电流。这样就把功耗给了电源，减轻了端口器件的负担。374 的 OE（输出使能）引脚接地，使能输出。

#### 280H 的译码与后沿触发

接下来是 374 的 CP 怎么来。前面讲过，输出端口的锁存时钟最好取写操作的后沿，用上升沿来触发。这个片选信号——也就是 CP——怎么产生呢？就是对 280H 这个地址做译码。

280H 的二进制是多少？也就是 10 1000 0000，`A9` 是 1，`A8` 是 0，`A7` 是 1，`A6` 到 `A0` 都是 0。

最简单的一种译码是全译码。所谓全译码，就是所有参与译码的地址位都要对上：地址为 1 的那几位——`A9` 和 `A7`，要同时为 1；地址为 0 的那几位——`A8`、`A6`、`A5`、`A4`、`A3`、`A2`、`A1`、`A0`，要同时为 0。`A9`、`A7` 接到一个与门（用与非门则是这两位对上时输出 0），`A8`、`A6` 到 `A0` 接到一个或门——这几个位只有全都为 0 时或门才输出 0，任何一位为 1 都不通过。

```text
地址 280H 的“1”位：A9、A7 ──▶ 与门（对上时有效）──┐
                                                   ├─▶ 译码输出
地址 280H 的“0”位：A8、A6…A0 ──▶ 或门（全 0 时通过）─┤      │
                                                   │      │ 写结束（IOW 变高）
低有效的写信号 IOW ──────────────────────────────┤      │ 的瞬间
AEN＝0（CPU 正在执行 IN／OUT）──────────────────┘      ▼
                                               译码输出上升沿
                                                   │
                                                   ▼
                                          374 的 CP（上升沿触发）
```

这张图的意思是：把地址匹配信号、写信号 `IOW`（低有效）、以及 `AEN` 等于 0（确认是 CPU 而不是 DMA 在操作）组合起来，译码输出的一个上升沿，恰好落在写操作结束的瞬间。

我们具体走一遍。CPU 执行 `OUT` 向 280H 地址写数据的时候，`IOW` 先变低，写开始了。写完了、最后的时候写信号变高，`IOW` 由低变高，译码输出也跟着变高，这个上升沿送到 374 的 CP，就把数据总线上已经有效的那个数据锁存进去。这样整个输出端口就设计完了。

> **结论**：把 CP 接到 280H 的全译码上升沿上，触发点就是写操作的后沿。前面为什么反复强调要取后沿，答案就在这里——只有后沿，才能保证锁进去的是有效数据。

#### 交替亮灭的程序

现在看题目的第二部分：8 个 LED，每隔一段时间交替亮灭，程序让它交替亮灭。

很简单。我们看程序怎么写。先把端口地址 280H 给 `DX`——`MOV DX, 280H`。然后让它亮，`AL` 装全 1（0FFH），8 个 LED 都亮：`OUT DX, AL`。执行这条 `OUT` 以后，`AL` 里的 0FFH 就被送到数据总线上，8 个灯全亮了。

然后让它交替，就得先灭。所以要延迟一段时间，延迟这段时间你的眼睛才看得出闪烁，不然闪太快根本看不见。那就在中间调一个 `DELAY` 延时子程序。延时子程序最后用 `RET` 返回。

延迟完了怎么办？把 `AL` 清零，`MOV AL, 00H`，再 `OUT DX, AL`，8 个灯全灭了。然后再回到前面让它亮——`MOV AL, 0FFH`，`OUT DX, AL`，再调 `DELAY`……就这样亮、灭、亮、灭交替下去。

```asm
MOV DX, 280H          ; 端口地址送 DX
MOV AL, 0FFH          ; 先让它全亮
ON:  OUT DX, AL        ; 输出当前 AL → 8 个 LED 全亮
     CALL DELAY        ; 停留一段时间（DELAY 必须保留 DX）
     MOV AL, 00H       ; 换成全灭
OFF: OUT DX, AL        ; 输出当前 AL → 8 个 LED 全灭
     CALL DELAY
     MOV AL, 0FFH
     JMP ON            ; 回到全亮，亮灭交替
```

这段程序的主体就是 `OUT DX, AL` 反复把 `AL` 里的数据送到 280H 端口，中间夹一个 `DELAY` 延时，`DELAY` 子程序用 `RET` 返回。这里有一个细节特别要注意：延时子程序当中不能破坏原来的 `DX`。明白了没有？只有不破坏 `DX`，后面那句 `OUT DX, AL` 才能送到 280H 这个端口去；如果 `DELAY` 把 `DX` 改了，输出就打到别的端口上去了，灯就不会按你想的亮灭。除去这一段程序，结合这个 I/O 接口，就是这道题实际要求的 8 个灯亮灭亮灭的程序设计。

### 本讲提到的题目

例 7.1：在 PC XT 系统总线上扩展设计一个数据输出端口。该端口分配地址为 280H，采用 74LS374 作为锁存芯片，输出设备为 8 个 LED 发光二极管。要求：画出这个输出端口与系统总线的连接图，以及与 LED 发光二极管设备的连接图；并编写一个使 8 个 LED 按一定时间间隔交替亮灭的程序。

解析与答案就在上面「例题」一节里，这里做一个归纳，方便你回头自查。

端口设计：`D0`–`D7` 接系统数据总线，`Q0`–`Q7` 经反相器分别驱动 8 个 LED，LED 阳极经限流电阻接 +5V，阴极接反相器输出，`OE` 接地。CP 接 280H 的全译码上升沿，译码条件为 `A9`=1、`A7`=1、其余地址位为 0，并限定 `AEN`=0、以及写操作的后沿。

程序：`DX` 装端口地址 280H；用 `AL` 在 0FFH（全亮）和 00H（全灭）之间交替，通过 `OUT DX, AL` 输出，两次输出之间调用 `DELAY` 延时；`DELAY` 子程序以 `RET` 返回且不破坏 `DX`。如此循环即实现 8 个 LED 亮灭交替。

## 从开关输入到 A/D 查询：8086 接口电路与程序
> 对应块：BLK48 | 覆盖分集：P93-P94 | 块标题（分集名）：《93》

上一节课做了例 7.1，讲的是无条件输出端口；这次接着做例 7.2，把无条件输入端口的设计走完整。输入端口做完后，再把查询法输入输出引进来：CPU 先启动 A/D 转换器，再反复读取它的状态，等转换结束以后，才把真正的数据取走。

这一段的核心，不是记住某一张电路图，而是把三个问题连起来：

- 外设的信号，怎样经过 8086 最小方式系统总线；
- 一个地址，怎样决定哪个端口被选中；
- 端口被选中以后，读写信号怎样决定数据往哪个方向走。

### 8086 总线上的输入端口

题目要求在 8086 CPU 工作于最小方式组成的系统总线上，扩充设计一个数据输入端口。既然是最小方式，就以最小方式系统总线为基础来设计。

这个输入端口的地址是 `8001H`。看到 `8001H`，先不要急着接芯片，先把地址本身拆开：

$$
8001H = 1000\,0000\,0000\,0001_2
$$

因此地址线的状态是：

- `A15=1`；
- `A14` 到 `A4` 全为 `0`；
- `A3` 到 `A1` 为 `000`；
- `A0=1`。

`8001H` 是 8086 的一个字节 I/O 地址。因为地址的最高字节是 `80H`，这个端口不是接在数据总线的低八位 `D0`～`D7` 上，而是接在高八位 `D8`～`D15` 上。这样，端口输出的一个字节才会沿着高八位数据线进入 CPU。

此外还要注意 `A0` 和 `BHE#`。当 `A0=1` 时，8086 选择的是高字节传送，因此要让 `BHE#=0`，表示高字节有效。这个条件不能漏掉，否则地址虽然译出来了，CPU 仍然可能取不到想要的那一组数据。

### 用 74LS245 做出一个单向输入端口

题目指定用 `74LS245` 作为输入端口芯片。`74LS245` 本身是双向数据缓冲器，有两组八位引脚：

- `A0`～`A7`；
- `B0`～`B7`。

它还有两个控制端：方向控制端 `DIR`，以及低电平有效的输出使能端 `OE#`。

现在要做的是输入端口，数据只能从外设一侧进入 CPU，不能让数据又从 CPU 侧倒送回去。因此要把双向缓冲器“固定成一个方向”：

- `DIR=0`，选择 `B` 侧到 `A` 侧；
- `OE#=0`，允许数据通过。

`DIR` 直接接地，就可以固定为 `B → A`。`OE#` 则不能直接接地，它要接到端口译码信号：只有这个端口被 CPU 选中时，才允许数据通过。

可以把它的使用方式记成下面这样：

```text
外设数据 ───────────────► B0～B7
                           │
                    74LS245，B → A
                           │
外设译码信号 ────────────► OE#（低有效）
                           │
                           └──────────► A0～A7 ──────► 8086 D8～D15
```

这里的“片选”不是把 `DIR` 也接到译码线上。`DIR` 决定方向，接地即可；`OE#` 才决定这个芯片此刻是否工作。设计输入端口时，真正要送进译码电路的，是端口地址对应的读信号。

### 8001H 的译码电路

题目没有规定译码器一定要用哪一种形式，因此可以用门电路，也可以用专用译码器。为了先看清楚地址条件，先用门电路分析。

对 `8001H`，可以把 `A14`～`A1` 以及 `BHE#` 组合起来：这些信号都处于要求的状态时，输出有效的端口选择信号。再把这个信号和两个条件合并：

1. `M/IO=0`，说明 CPU 正在进行 I/O 操作，而不是存储器操作；
2. `RD#=0`，说明这次是读操作。

为什么要加入 `RD#`？因为这是一个输入端口。CPU 对 `8001H` 执行读操作时，输入端口应该被选中；如果 CPU 对同一个地址执行写操作，这个输入端口就不能被误选中。译码电路在这里不仅辨认地址，还要辨认操作类型。

可以把输入端口的选通条件概括为：

```text
A14～A1、BHE# 满足 8001H 的地址条件
                  │
                  ├── M/IO=0：I/O 操作
                  └── RD#=0：读操作
                              │
                              ▼
                    245 的 OE# 有效
```

注意，地址译码和读写控制不是两件互不相关的事。`8001H` 只说明“访问的是哪一个端口”，`M/IO` 说明“访问的是 I/O 还是存储器”，`RD#` 才进一步说明“数据往 CPU 的方向来，还是从 CPU 向端口送出去”。

### 八个开关的输入电路

输入设备是八个乒乓开关，记作 `K0`～`K7`。每一位开关接到 `74LS245` 的一个 `B` 位输入，八位合起来就是一个字节。

先看其中一位：

- 开关接到低电平时，输出 `0`；
- 开关断开时，由电阻上拉电源，输出 `1`；
- 开关向上闭合，输出被拉到 `0`；
- 开关向下拨下，输出为 `1`。

实际工程中，在这个低电平位置再接一个电容到地，可以对电源起滤波作用。电容一般选 `103`～`104`，先把开关输入的电气条件做好。

八位开关的连接关系是：

```text
K0 ───► B0
K1 ───► B1
K2 ───► B2
K3 ───► B3
K4 ───► B4
K5 ───► B5
K6 ───► B6
K7 ───► B7
```

`K0`～`K7` 的另一端分别按照开关闭合或断开的状态接地、上拉，最后汇成一个字节送到 `74LS245` 的 `B0`～`B7`。再由 `A0`～`A7` 接到 8086 的高八位数据总线 `D8`～`D15`。

这里要把“开关状态”和“CPU 中的位”一一对应起来：

- `K0` 经过 `B0`、再经过 `A0`，最后进入 `AL` 的第 `0` 位；
- `K1` 经过 `B1`、再经过 `A1`，最后进入 `AL` 的第 `1` 位；
- 依此类推；
- `K7` 经过 `B7`、再经过 `A7`，最后进入 `AL` 的第 `7` 位。

### 用程序判断 K0 的状态

硬件接通以后，程序要做的事情很简单：读入一个字节，再检查其中的第 `0` 位。

```asm
MOV DX, 8001H
IN  AL, DX
TEST AL, 01H
JZ  PROGRAM1
JMP PROGRAM2
```

`IN AL, DX` 执行时，`DX` 中的 `8001H` 被送到地址总线。CPU 的 I/O 读周期中，`M/IO` 进入 I/O 状态，随后 `RD#` 变低，译码电路选中 `74LS245`，`B` 侧到 `A` 侧导通。八个开关的状态经数据线回到 `AL`，其中第 `0` 位就是 `K0` 的状态。

`TEST AL, 01H` 的作用是只检查 `AL` 的最低位，同时用 `AND` 的方式测试这一位：

- 如果结果为零，说明 `AL` 的第 `0` 位为 `0`，也就是 `K0` 开关处于断开的一侧，执行 `PROGRAM1`；
- 如果结果不为零，说明第 `0` 位为 `1`，也就是开关闭合，执行 `PROGRAM2`。

这里有一个很容易忽略的程序结构问题：两个分支处理完后，都还要继续执行下面的公共程序。因此，如果程序段的排列使某一段执行完会直接落入另一段，就要在中间补上一条无条件转移指令。分支不是“测试完就结束”，而是测试完以后分别走向对应的处理，最后再汇合。

### 查询法为什么要先读状态

无条件输入输出适用于数据随时可以读取的简单设备。A/D 转换器则不是这样的设备：CPU 发出启动命令以后，转换器要花一段时间，转换期间不能把数据当成有效结果取走。

所以查询法的核心顺序是：

```text
启动转换 → 查询状态 → 确认完成 → 读取数据
```

“查询”不是等固定的时间，而是不断读取外设提供的状态，让状态信号告诉 CPU 什么时候可以继续。

#### A/D 转换器的工作时序

这里采用一个八位 A/D 转换器。模拟输入是电压信号 `VA`，转换后的数字量从 `D0`～`D7` 输出。

它有两个关键控制信号：

- `START`：启动信号，给它一个正脉冲；正脉冲的下降沿到来时，A/D 转换器开始采集和转换；
- `EOC`：转换结束状态信号，转换期间为低，转换结束后变高。

时序关系可以画成：

```text
START  ───────┐       ┌──────────────
              │       │
              └───────┘
                ↓ 下降沿启动

EOC    ────────────────┐       ┌────────
                        │       │
                        └───────┘
                         转换中   转换结束
```

这里要抓住下降沿：不是 `START` 一出现，转换就已经开始，而是正脉冲的下降沿到来时才开始。`EOC` 在转换期间变低，转换完成后变高。`D0`～`D7` 上真正可用的数据，要等转换完成以后 CPU 才能取走。

转换需要多长时间，要看器件手册。有些器件对 `START` 脉冲的宽度还有要求，例如要求达到 `1μs` 等数值，所以不能凭感觉省掉脉冲宽度。开始信号到底要保持多久，要以具体器件的时序要求为准。

### A/D 接口需要几个端口

为了完成“对 `VA` 采集一次，并把转换结果保存”的功能，需要把数据、状态、命令分开处理。题目给出的端口地址是：

| 端口 | 地址 | 作用 |
| :--- | :---: | :--- |
| 数据输入端口 | `8001H` | 读取 A/D 转换后的八位数据 |
| 状态输入端口 | `8003H` | 读取 `EOC`，判断转换是否完成 |
| 命令输出端口 | `8005H` | 输出启动命令，产生 `START` 信号 |

这三个端口的分工一定要分清：

- `8001H` 取的是数字结果；
- `8003H` 取的是状态，不是数据；
- `8005H` 送的是命令，不是数据。

#### 数据输入端口

A/D 转换器的 `D0`～`D7` 接到 `74LS245` 的 `B0`～`B7`，`74LS245` 的 `A0`～`A7` 接到 8086 的 `D8`～`D15`。

连接关系是：

```text
A/D D0～D7 ─────────────► 245 B0～B7
                              │
                       DIR=0，B→A
                              │
                          245 A0～A7
                              │
                              ▼
                         8086 D8～D15
```

`DIR` 接地，把芯片固定成从 `B` 侧到 `A` 侧传输。`OE#` 接 `8001H` 的输入端口译码信号，只有 CPU 读这个端口时才打开。

#### 状态输入端口

`EOC` 是 A/D 转换器送给 CPU 的状态信号，因此还要设计一个状态输入端口。这个端口同样可以使用 `74LS245`。

这里可以让 `EOC` 接到 `B7`，再从 `A7` 输出到 `D15`。在 `AL` 中，最终用最高位来检查 `EOC`。当然，状态信号接到 `B0` 也可以，选 `B7` 或其他位同样可以；这里选 `B7`，只是为了在程序中用 `AL` 的最高位表示它。

```text
A/D EOC ────────────────► 245 B7
                              │
                       DIR=0，B→A
                              │
                          245 A7
                              │
                              ▼
                         8086 D15
```

状态端口地址是 `8003H`，同样接在高八位数据总线上。CPU 读取 `8003H` 后，状态值进入 `AL` 的最高位。

#### 命令输出端口

A/D 转换器还需要 `START` 信号。这个信号是命令，不是转换结果，所以要通过命令输出端口由 CPU 的 `OUT` 指令产生。

命令输出端口可以选用 `74LS374`，也可以用 `74LS273`。这里选用 `74LS374`：

- 74LS374 的 `D0` 接 8086 的 `D8`；
- `Q0` 接 A/D 转换器的 `START`；
- `OE#` 接地，使锁存器能够工作；
- `CP` 端接收命令输出端口的选通信号。

当 CPU 对 `8005H` 执行输出操作时，锁存器把 `D0` 的值送到 `Q0`。为了让 `START` 产生一个先高后低的脉冲，程序先把 `Q0` 置为 `0`，再置为 `1`，保持一小段满足要求的宽度，最后重新置为 `0`。`1` 变到 `0` 的下降沿，才是 A/D 转换器的启动时刻。

### 用 74LS138 组织三个端口的译码

这次不再只用门电路，可以改用 `74LS138` 译码器。三个端口的地址低位分别是：

- `8001H`：`A3A2A1=000`；
- `8003H`：`A3A2A1=001`；
- `8005H`：`A3A2A1=010`。

所以把 `A3`、`A2`、`A1` 接到 74LS138 的 `CBA` 地址输入端：

| `A3A2A1` | 有效输出 | 对应端口 |
| :---: | :---: | :--- |
| `000` | `Y0#` | `8001H` 数据输入 |
| `001` | `Y1#` | `8003H` 状态输入 |
| `010` | `Y2#` | `8005H` 命令输出 |

74LS138 的其它高位地址条件也要接好：

- `A15=1`，接到使能端的高电平有效条件；
- `A14`～`A4` 全为 `0`；
- `BHE#=0`；
- `M/IO=0`，保证是对 I/O 空间操作。

这些条件先把“CPU 正在访问 `8000H`～`8007H` 这一组 I/O 地址”筛出来。具体是哪一个端口，还要由 `Y0#`、`Y1#`、`Y2#` 区分。

但只接到这里还不够，因为三个端口的操作方向不同：

- `8001H` 是输入端口，CPU 必须执行读操作，所以还要和 `RD#` 组合；
- `8003H` 是状态输入端口，也要和 `RD#` 组合；
- `8005H` 是命令输出端口，CPU 必须执行写操作，所以要和 `WR#` 组合。

可以把整个译码关系记成下面这样：

```text
                    A15=1
                      │
       A14～A4=0、BHE#=0、M/IO=0
                      │
                      ▼
                  74LS138
          ┌───────────┼───────────┐
        Y0#          Y1#          Y2#
          │           │           │
        RD#=0       RD#=0       WR#=0
          │           │           │
          ▼           ▼           ▼
     8001H 数据    8003H 状态    8005H 命令
       输入端口      输入端口      输出端口
```

`Y0#` 和 `Y1#` 的输出再与相应的读控制信号相与，`Y2#` 与写控制信号相与。这样，CPU 对 `8001H` 写数据时不会打开数据输入端口；CPU 对 `8005H` 读数据时也不会把命令锁存器误当成输入设备。

### 一次 A/D 采集的程序

题目要求对 `VA` 采集一次，并把转换后的数字量存入 `D-BUFF` 单元。这个变量只有一个字节，所以应当在数据段中用 `DB` 定义：

```asm
DBUFF DB ?
```

程序分成初始化、启动、查询、取数和保存几个阶段。

#### 先初始化命令输出端口

刚开机时，不能保证命令锁存器的 `Q0` 已经是 `0`，所以先把 `8005H` 端口输出为 `0`：

```asm
MOV DX, 8005H
MOV AL, 00H
OUT DX, AL
```

这一步不是多余的初始化装饰，而是为了让启动信号的初始状态确定下来。

#### 产生 START 的下降沿

接着把 `AL` 置为 `1`，输出一次，再延时，最后重新输出 `0`：

```asm
MOV AL, 01H
OUT DX, AL
NOP
NOP
MOV AL, 00H
OUT DX, AL
```

前面的 `OUT DX, AL` 使 `START` 变高；中间的延时给高电平脉冲留出宽度；后面的 `OUT DX, AL` 使 `START` 变低，产生下降沿。这个下降沿一到，A/D 转换器开始转换。

因此，启动过程不是简单地把 `START` 置成某个固定电平，而是要制造一个符合要求的脉冲，并且让下降沿落在正确的时刻。

#### 查询 EOC

启动之后不能马上读 `8001H`，因为转换还没有完成。先把状态端口地址送入 `DX`，循环读取状态：

```asm
MOV DX, 8003H
WAIT_EOC:
    IN  AL, DX
    TEST AL, 80H
    JZ  WAIT_EOC
```

状态端口的 `EOC` 接在 `A7`，经过 `D15` 进入 `AL` 的最高位，所以测试 `80H` 就是在测试 `EOC`：

- `EOC=0` 时，转换还在进行，`TEST` 的结果为零，`JZ` 跳回 `WAIT_EOC`；
- `EOC=1` 时，转换已经结束，`TEST` 的结果非零，程序跳出等待。

这里就是查询法真正起作用的地方。CPU 不是盲目等待一个猜测出来的时间，而是一遍一遍问 A/D 转换器：“数据准备好了吗？”直到状态端口明确回答“准备好了”。

#### 取数并保存

确认 `EOC` 变高以后，再读取数据输入端口：

```asm
MOV DX, 8001H
IN  AL, DX
MOV DBUFF, AL
```

此时 `8001H` 的读信号使 `74LS245` 的 `OE#` 有效，A/D 转换器 `D0`～`D7` 上的有效数字量经 `B` 侧、`A` 侧和高八位数据总线进入 `AL`，最后保存到 `DBUFF`。

一次采集的完整逻辑可以压缩成：

```text
初始化命令端口
      ↓
输出 0、输出 1、延时、输出 0
      ↓
START 下降沿启动 A/D 转换
      ↓
反复读取 8003H，检查 EOC
      ↓
EOC=1 后读取 8001H
      ↓
把 AL 保存到 DBUFF
```

### 从一次采集推广到多次采集

如果要求连续采集 `N` 次，外围的硬件地址不变，软件只要把“启动、查询、取数、保存”这段过程放进循环即可。可以使用 `CX` 作为计数器，再用 `LOOP CX` 控制循环次数。

这时要注意初始化和计数的安排：命令输出端口仍然要先初始化；每轮循环都要重新产生一次 `START` 脉冲；每轮都要等待 `EOC` 变高；每轮完成后从 `8001H` 取数并保存。查询法并没有因为循环而改变，它只是把同一个“等待状态变高”的动作重复执行。

在大系统里，这类和具体设备打交道、完成设备控制的软件通常可以看作驱动程序。这里做的是一个较小的接口例子，但它已经包含了驱动程序最基本的工作：命令怎么发，状态怎么读，数据怎么取，以及三者什么时候必须按顺序衔接。

## 中断系统与可编程中断控制器 8259A
> 对应块：BLK49 | 覆盖分集：P95-P96 | 块标题（分集名）：《95》

中断系统这一章，重点掌握两块：一块是 8086 的中断系统，另一块是可编程中断控制器 8259A。8259A 和 8086 结合起来，承担的是 8086 外部可屏蔽中断的管理，也就是 `INTR` 引脚上的中断管理。这一章在期末考试里基本考概念，一般不涉及设计题，所以把概念捋清楚最重要。但这些概念不是一堆互不相干的名词，它们是从“中断是什么”一步步推出来的：谁来请求、CPU 怎么认出谁、有没有优先级、入口地址放在哪儿、CPU 怎么一步步走到入口，最后才轮到 8259A 这个具体芯片的引脚和用法。

### 中断到底是什么

先把最基本的概念说清楚。什么叫中断？我们在讲中断调用与返回的时候已经讲完了。回想一下：CPU 正在执行程序，比如正在执行某一条指令，这时有人向它提出中断请求。CPU 必须响应，但不是说半句话不说就丢下当前程序不管了。正确的处理是：先把当前这条指令执行完，把程序暂停在那里；然后转去执行为请求者服务的那一段程序，也就是中断服务子程序；服务完了，再返回到刚才中止的地方，接着往下执行。整个过程就是一个中断。

这里要特别小心用词。我先把话说完整——为提出中断请求的那个中断源、或者叫一个事件服务的这段程序，就叫中断服务程序。别稀里糊涂地答成“这就是中断服务子程序”，没把服务的对象说出来，定义是不完整的。

```text
主程序：  ... ── 指令 A ── 指令 B ── 指令 C ── ...
                                  ↑
                             断点在这里
                          （现场被保护起来）

响应后：  暂停在指令 C 处
              ↓
      执行中断服务子程序
              ↓
      服务完毕，返回
              ↓
        回到断点，继续执行指令 C
```

为什么一定要“先把这句说完”？因为 CPU 执行到一条指令的中途被打断，寄存器里的数据和程序状态就是所谓的中断现场。如果不把现场保护好，回来以后程序就乱了。所以中断的核心动作只有两个：暂停当前程序、保护好现场；服务完之后再恢复现场、返回断点。

### 内部中断和外部中断

对于任何 CPU 型号的计算机系统，中断源都有两个方向，就是内部中断和外部中断。区分的标准很简单：谁向 CPU 提出了中断请求，谁就是中断源；源在 CPU 内部，就是内部中断；源在 CPU 外部，就是外部中断。

课堂上怎么想这个事？把整间教室看成一片 CPU：讲台是 CPU 内部的控制器，我讲课就是 CPU 在执行程序；坐在下面的各位是 CPU 内部的部件。我正讲着一句话——这就是在执行一条指令——这时你举手了，这就是 CPU 内部的一个部件提出了中断请求，属于内部中断，必须响应。我不能半句话停下来，丢下主程序去说另一段专门为你服务的话。我得先把这句话说完，把程序停到指令边界，然后再去执行那段服务你的程序；服务完了，返回断点，接着往下讲。这就是“为中断源服务”的那一层的意思。

外部中断也一样好理解。教室外面有人敲门，这就是向 CPU 提出了中断请求，属于外部中断。8086 的外部中断就是从外部设备来的：外部设备可以通过 `NMI` 引脚，以上升沿的形式提出非可屏蔽中断请求；也可以通过 `INTR` 引脚，以高电平的形式提出可屏蔽中断请求。这两个引脚的性质必须分清——`NMI` 是上升沿触发的非屏蔽请求，`INTR` 是高电平触发的可屏蔽请求，触发方式不一样，屏蔽能力也不一样。

### 中断源的识别方法

一个计算机系统当中，可能有很多个中断源都可能向 CPU 提出中断请求。CPU 怎么知道是谁向他提出的请求，从而正确地转入到为它服务的服务子程序呢？这就要解决“中断源的识别”问题。不同的 CPU 型号，识别方法不一样。这一节对比两种典型的、必须掌握的识别方法。

#### 8086 用中断类型号识别

在 8086 系统当中，中断源的识别是用**中断类型号**来识别的。我用 $n$ 表示中断类型号。8086 系统对每一个中断源编一个中断类型号，这个号码是用 8 位二进制编码的。8 位编码就是 0～255，所以 8086 的 CPU 能管理 256 级中断。

前面讲过，8086 内部有些中断的类型号是 CPU 内部硬件已经固定死了的：

| 中断情况 | 中断类型号 | 说明 |
| :--- | :--- | :--- |
| 除法错中断 | 0 | 8086 内部固定 |
| 单步中断 | 1 | 8086 内部固定 |
| 非屏蔽中断 | 2 | `NMI` 引脚上升沿有效的中断请求 |
| 断点中断 | 3 | 8086 内部固定 |
| 溢出中断 | 4 | `INT n` 等软件中断 |
| 软件中断 | $n$ | 执行 `INT n` 指令时，类型号就是 `INT` 后面的数字 |

外部可屏蔽中断就不同了。如果外部中断源通过 `INTR` 引脚以高电平形式提出可屏蔽中断请求，这个请求对应的中断类型号在 8086 的 CPU 内部没有固定。那怎么办？就在 CPU 外部扩充一片 8259A 中断控制器，把这个中断源对应的类型号事先 `OUT` 初始化到 8259A 中去。CPU 得到这个请求以后，在中断响应期间，会从外部 8259A 中断控制器里获取中断类型号。有了类型号，CPU 就能准确地跳到这个中断源对应的中断服务子程序入口去为它服务。这就是 8086 系统当中用中断类型号来识别中断源的办法。

#### 8051 用软件查询识别

再看另一类系统，比如 MCS-51 系列单片机。它的 CPU 外部只有 `INT0`、`INT1` 两个中断请求输入引脚，所以外部只能接两个中断源。但外部中断源超过两个时怎么办？假如外部有四个按键，每个按键都是一个中断源；如果每个按键都单独用中断法处理，四路信号接不到 `INT0`、`INT1` 两个引脚上去。

先要做信号的处理。这是四个按键，每个按键的一端都接公共地，另一端各通过一个上拉电阻接到电源上，再用四个输入接到一个“或”的逻辑门里：

```text
        +5V
         │
      ┌──┼──┬──┬──┐
      │ 上拉 上拉 上拉 上拉 │  （每个按键各一个上拉电阻）
      └──┬──┴──┴──┴──┘
         │  │  │  │
       K0│ K1│ K2│ K3      ← 四个按键，一端接公共地
         │  │  │  │
      ┌──┴──┴──┴──┴──┐
      │    或 逻辑    │
      └──┬─────────┘
         │  任意一键按下 → 输出为 0
         └───────→ 8031 的 INT0（下降沿）
```

理想情况下，任意一个键按下的下降沿，就能向 8031 的 CPU 提出中断请求。CPU 响应中断、进入中断服务程序后，怎么知道到底是哪个键按下的？因为这样的 CPU 没有中断类型号，它对中断源的识别，靠的不是硬件送来的类型号，而是在中断服务子程序一开始，用软件查询的办法来识别。

具体的做法是：把 8031 某个 P 口（这里是 P1 口）的 8 根线设置成输入，分别接到这四个开关上，得到 $K0$、$K1$、$K2$、$K3$ 四个信号。CPU 进入中断服务程序以后，先读取 P1 口的状态——把四个开关的状态都读回来——然后依次检测：P1.0 等于 0 吗？如果不等于 0，说明不是这个键按下的；再看 P1.1 等于 0 吗？再看 P1.2 等于 0 吗？哪个信号先等于 0，就说明是哪个键按下的，按这个键去完成对应的功能。这样相当于“无条件占位”式地识别中断源。

但这个办法有一个代价：中断源的优先权跟你在服务程序里查询的顺序有关。我先测 P1.0，就意味着这个键对应的中断源优先权最高。这就是软件排队测试顺序决定的优先权——中断源的识别靠软件查询，优先级也就跟着软件查询顺序走。

把这个对比记住：8086 靠类型号这个硬件信息识别中断源；8051 这种没有类型号的系统，靠软件查询识别中断源，优先级也由查询顺序决定。CPU 型号不同，识别方法就不同。

### 中断优先权

把两类系统放在一起对比，优先权是这样的：

在 8086 系统当中，内部中断（除 `NMI` 非屏蔽中断以外）优先权高于外部中断；外部中断里，`NMI` 引脚提出的非屏蔽中断请求优先权高于 `INTR` 引脚上的可屏蔽中断请求。内部硬件的优先权在 8086 内部是硬件固定死的，单步中断的优先权最低。

对于 8086 外部的可屏蔽中断，也就是 8259A 管理的可屏蔽中断，一片 8259A 只能管理外部八个中断源；这八个中断源的优先权高低，是你用户对 8259A 初始化时编程决定的。优先级不是固定的，是由初始化程序决定的——所以它才叫“可编程中断控制器”。

> **易错点**：不要把 8086 自己的优先权规则和 8259A 内部的优先权规则混为一谈。8086 这边是硬件固定的；8259A 这边是用户编程可设的。这是两套完全独立的规则。

### 中断向量和中断向量表

回忆一下以前讲过的：什么叫中断向量？**中断服务子程序的入口地址就是中断向量**。入口地址有 16 位的段地址 `CS` 和 16 位的偏移地址 `IP` 共同构成，所以一个中断向量是 32 位的：

$$
\text{中断向量} = \text{16 位偏移地址 IP} + \text{16 位段地址 CS}
$$

在 8086 系统当中，中断向量表是存放在存储器空间里最低的 1024 个存储单元，也就是 1MB 地址空间的 00000H～003FFH 这一段。这个向量表里存放的全是中断向量。由于一个中断向量是 32 位，在向量表中存放一个中断向量要占用 4 个字节。编号是连续排开的：0 号单元到 3 号单元存放的是类型号为 0 的中断向量；4、5、6、7 四个单元存放的是类型号为 1 的中断向量；一直到最后的 03FCH～03FFH 四个单元存放类型号为 255 的中断向量。存放的规律是：前两个字节存放中断向量的偏移地址 `IP`，后两个字节存放中断向量的段地址 `CS`。

对中断类型号为 $n$ 的中断，它的向量在向量表中的位置是 $n \times 4$：

| 存放位置（物理地址） | 存放内容 |
| :--- | :--- |
| 00000H～00003H | 类型号 0 的中断向量：`IP` 占前两字节，`CS` 占后两字节 |
| 00004H～00007H | 类型号 1 的中断向量 |
| …… | …… |
| 03FCH～03FFH | 类型号 255 的中断向量 |

1024 个存储单元、每个向量 4 字节，一共能存放 256 个中断向量。所以 8086 的 CPU 最多只能管理 256 级中断。类型号 0 到 255，一个类型号对一个中断向量，每一个向量都指向一个中断源对应的中断服务子程序入口。

### 中断服务程序和中断嵌套

先把两个概念说清楚。**中断服务程序**是“为提出中断请求的那个中断源、或者叫一个事件服务的这段程序”，定义里必须带上服务的对象。**中断嵌套**是指：允许 CPU 在执行一个中断服务程序期间，优先级更高的中断请求到来，中止当前正在执行的服务程序，转去执行优先级更高的那个中断源的中断服务子程序；高优先级的服务完了，再返回到原来被中止的地方继续执行。

`IRET` 指令是中断服务程序的最后一条指令。服务程序执行到这里，就把刚才压在堆栈里的值依次弹出：先恢复 `IP`，再恢复 `CS`，再恢复标志寄存器 `PSW`。这样 `IP`、`CS`、标志就回到了刚才断点处的状态，CPU 就回到断点接着执行。保护和恢复的顺序恰好相反：进入中断时是“先标志、再 `CS`、最后 `IP`”压栈；返回时是“先 `IP`、再 `CS`、最后标志”出栈。

### 外部可屏蔽中断的响应过程

这是本章最需要背下来的一块。从中断请求到来、到 CPU 转移到中断服务程序入口位置为止，CPU 中间经过的一系列操作，称为中断响应过程。如果问“外部可屏蔽中断的响应过程是什么”，首先要戴个帽子：前提是 $IF=1$，也就是必须开中断；然后从请求到来的那一刻起算，到转到中断服务程序入口为止，中间是五步。记住这五步，一分不多，一分不少。

第一步，保护断点和现场。断点是 `CS`、`IP`，也就是被中止的那条指令的段地址和偏移地址；现场是标志寄存器 `PSW`。保护就是依次把 `PSW`、`CS`、`IP` 压到堆栈里。

第二步，如果是外部可屏蔽中断，从 8259A 获取中断类型号 $n$。如果是内部中断，或者 `NMI` 提出的非屏蔽中断，由于类型号是固定的，这一步直接跳过。

第三步，清除 `IF` 和 `TF`。清 `IF` 的目的是确保 CPU 在执行中断服务程序期间关闭中断、不再响应外部可屏蔽中断。但如果你希望允许中断嵌套——也就是允许更高一级优先权的外部可屏蔽中断源在当前服务程序执行期间到来、允许它中止当前服务转去另一个服务程序——那么应该在中断服务程序的开始处就执行 `STI` 指令，把 `IF` 重新置 1。清 `TF` 的目的是防止出现陷阱：`TF=1` 时 CPU 每执行完一条指令就产生一次单步中断，进入中断服务后如果不清掉它，就会连续产生单步中断，这是绝对不允许的。记住这两条就够——`IF` 管“要不要响应可屏蔽中断”，`TF` 管“会不会每条指令都断一次”。

第四步，由 $n \times 4$ 找到中断向量在向量表中的位置。注意别数错：保护现场和查找向量是两步，不是一步；很多同学把“保护现场”和“保护断点”拆成两个步骤去数，其实它们是同一个动作，都是压栈。

第五步，由 $n \times 4$ 处取一个字给 `IP`，由 $n \times 4 + 2$ 处取一个字给 `CS`，把 `CS:IP` 指向中断服务程序入口，从这个地方取指令执行，就开始对中断源服务了。

```text
请求到来（IF=1）→ ① 保护断点和现场 → ② 从 8259A 取类型号 n
      → ③ 清 IF、TF → ④ 找 n×4 → ⑤ 取 IP、CS → 转到服务程序入口
```

所以如果答的是外部非屏蔽中断或者内部中断的响应过程，就把第二步去掉，没有从 8259A 获取类型号这一步，其他都一样。

### 8259A 的结构和引脚

8086 的外部可屏蔽中断管理，靠的是可编程中断控制器 8259A。这是 8259A 芯片的知识点。先掌握 8259A 的引脚和功能。8259A 采用双列直插式封装，一共 28 个引脚。

```text
                     ┌─────────────────┐
   IR0 ──────────────┤                 ├───── INT ──→ CPU 的 INTR
   IR1 ──────────────┤                 │
   IR2 ──────────────┤      8259A      ├───── INTA ─← CPU 的中断响应信号
   IR3 ──────────────┤   28 脚双列直插 │
   IR4 ──────────────┤                 │
   IR5 ──────────────┤                 │
   IR6 ──────────────┤                 │
   IR7 ──────────────┤                 │
                     │                 │
   D0 ───────────────┤                 │
   …                 │                 │
   D7 ───────────────┤                 │
                     │                 │
   WR ───────────────┤                 │
   RD ───────────────┤                 │
   CS ───────────────┤                 │
   A0 ───────────────┤                 │
                     │                 │
   CAS0 CAS1 CAS2 ───┤                 │
   SP/EN ────────────┤                 │
                     └─────────────────┘
```

#### 中断请求输入和数据引脚

`IR0`～`IR7` 是中断请求输入引脚，这是外部设备发过来的中断请求信号。一片 8259A 有八个中断请求输入引脚，也就是说一片 8259A 能够管理外部八个中断源。`D0`～`D7` 是数据引脚，是双向的。`CS` 无效时，`D0`～`D7` 呈高阻态；CPU 通过数据线用 `OUT` 指令可以给 8259A 内部的端口写命令，或者往内部的一些寄存器写内容；用 `IN` 指令可以读数据或者读状态。CPU 通过 `OUT` 给 8259A 内部的端口写不同的命令，就可以改变 8259A 的工作方式。所以 8259A 是可编程器件，工作方式不是固定的，而是可编程的。

#### 控制引脚

这几个引脚很简单。`WR` 是写控制端，CPU 写命令时给一个低电平写控制信号。`RD` 是读控制端，CPU 从内部读数据或读状态时给一个低电平读控制信号。`CS` 是片选，相当于讲存储器设计时的片选——等效于片外寻址。`A0` 是片内寻址地址线。

从这一点可以引出 8259A 寻址的逻辑：8259A 内部实际上有两个端口，`A0=0` 选中一个端口，`A0=1` 选中另一个端口。但是 8259A 内部的 I/O 寄存器不止两个，内部所有端口的地址只有两个。那么 CPU 用 `IN`、`OUT` 对 8259A 内部端口操作，到底是对哪一个端口操作呢？显然除了靠 `A0` 等于 0 还是等于 1 来区分之外，还需要靠命令的某几位来区分——靠命令特征位来识别具体的端口。所以 8259A 的寻址是“`A0` 加命令特征位”两级区分：`A0` 先选出两个端口中的一个，然后命令特征位再在组内指定具体寄存器。

#### 中断请求输出和中断响应信号

`INT` 是中断请求输出。当 `IR0`～`IR7` 某一位有中断请求时，如果这个请求没有被屏蔽，8259A 就把这个中断请求通过 `INT` 端以高电平形式发送出来，送给 8086 的 `INTR` 引脚，向 CPU 请求可屏蔽中断。如果 8086 的 CPU 处于开中断状态（`IF=1`），就要对这一次请求响应。响应时，CPU 通过 `INTA` 这个输入引脚，向 8259A 发两个 `INTA` 负脉冲。第一个 `INTA` 负脉冲送到 8259A，表示“你发出的中断请求，CPU 响应了”；8259A 收到后，就知道自己发出的 `INT` 请求被接受了。然后 CPU 再用一个总线周期发第二个 `INTA` 负脉冲，8259A 收到后，就把到底是哪个 `IR` 端提出的请求、这个请求对应的中断类型号，送到 `D0`～`D7` 上；就在 CPU 发第二个 `INTA` 负脉冲的同时，CPU 自动地从数据线上读取这个中断类型号。这就是 CPU 从外部 8259A 获取中断类型号的方法。有了类型号 $n$，CPU 就算 $n \times 4$，在向量表中找到对应的中断向量，取出 `IP` 和 `CS`，`CS:IP` 指向中断服务程序入口，CPU 就去为这个中断源服务了。

#### 一个必须注意的接线细节

在 8086 系统当中，8259A 的 `D0`～`D7` 与系统数据总线相连时，一定要注意：必须和系统数据总线的第八位数据线组相连，也就是接到系统数据总线的 `D8`～`D15` 这一组上，不能接到 `D0`～`D7`。为什么？当 8086 的 CPU 发第二个 `INTA` 负脉冲时，8086 会自动地通过第八位数据线读取中断类型号。既然 8086 是自动从第八位数据总线上读取 8259A 送过来的中断类型号，那 8259A 的 `D0`～`D7` 当然就应该和系统数据总线的 `D8`～`D15` 相连。记牢这一点，接线才不会接错。

#### 缓冲和非缓冲两种工作方式

`SP/EN` 引脚的功能是：它使 8259A 可以工作在非缓冲和缓冲两种工作方式。

先看缓冲工作方式。缓冲方式指的是在 8259A 与系统总线相接处，为了避免系统总线负载过重，在 `D0`～`D7` 引脚与系统数据总线相连的中间，设计一个双向数据缓冲器。这个双向数据缓冲器什么时候工作？有一个数据有效端 `EN`，当 `EN=0` 时缓冲器就可以工作，输哪一边由方向控制 `DR` 来控制。`EN` 端的控制是用 `EMF` 来控制的：也就是说，在缓冲工作方式下，8259A 的 `SP/EN` 引脚是作为**输出**用的。当 CPU 用 `IN`、`OUT` 操作 8259A 时，8259A 会自动地让 `EN` 端输出低电平，这个低电平通过一根线接到缓冲器的 `EN` 端，缓冲器就可以工作了。这就叫缓冲方式。

不过缓冲方式很少有人用。IBM PC 系列机主板上，在以 8088/8086 为核心的早期 IBM PC 机主板上配置的是一片 8259A；到了 286 以后，386、486 一直到今天的奔腾系列、双核时代的主板，都配置了两片 8259A 级联工作。但不管当代计算机主板上两片 8259A 级联工作，还是早期 IBM PC 机主板上的单片 8259A 工作，工作方式都是**非缓冲方式**。非缓冲方式指的是 8259A 的数据引脚和系统数据总线的第八位数据组之间都是直接相连。非缓冲方式下，`SP/EN` 引脚变成了输入，是可编程的输入。

非缓冲方式下 `SP/EN` 这个引脚还有一层用途：它用来区分主片和从片。如果系统是单片 8259A 工作，或者这片 8259A 在级联中是主片，`SP/EN` 应该接正 5V，表明这片是主片；如果在级联工作方式中这片 8259A 是从片，它的 `SP/EN` 就应该接 `GND`。

#### 级联工作线

`CAS0`～`CAS2` 这三根线叫级联工作线。级联的时候，如果这片 8259A 是主片，那么这三位是输出；如果这片是从片，这三位是输入。也就是：主片的三根线输出，接到从片的这三个输入端，连接起来。当从片的 `IR0`～`IR7` 某一位有中断请求时，这个请求先发给主片的 `IR0`～`IR7` 某一条级联线上，由主片再向 CPU 请求中断。

CPU 响应时发两个 `INTA` 负脉冲。第一个 `INTA` 负脉冲，主片、从片都收到了，表示响应。第二个 `INTA` 负脉冲，主片收到了；这时主片从 `CAS0`～`CAS2` 这三位上输出一个代码，表明“是我下面这个从片的请求给 CPU 的”。比如有一个从片级联在主片的 `IR1` 上，而且是这个从片发过来的请求，主片再给 CPU 响应——那么主片这时收到第二个 `INTA` 负脉冲，就从这三个引脚输出 `001`，表明是接在 `IR1` 上的那个从片。`001` 输出到级联线上，所有从片都检测这个代码。刚才说的那个从片检测到发过来的代码是 `001`，和自己连接的 `IR` 端一致，就知道是自己发起的请求，握手成功；于是就在这个时候，通过数据总线把对应的中断类型号送到数据总线上。

### 8259A 和 8086 的协作

把这一讲串起来，8259A 在 8086 外部可屏蔽中断管理中的角色就清楚了：外部设备通过某个 `IR` 端提出中断请求；8259A 判断这个请求没有被屏蔽，就通过 `INT` 输出以高电平形式向 8086 的 `INTR` 请求可屏蔽中断；8086 在开中断状态下响应，发两个 `INTA` 负脉冲；8259A 在收到第二个 `INTA` 负脉冲后，把请求对应的中断类型号送到 `D0`～`D7`；8086 从 `D8`～`D15` 这组数据线自动读取这个类型号；类型号 $n \times 4$ 定位到中断向量表，取出 `IP` 和 `CS`，转到中断服务程序入口去为这个中断源服务。

整个过程对应到引脚级别，就是前面 `INT`/`INTA` 信号交换的那一套；对应到向量表，就是前面 $n \times 4$ 定位、`IP` + `CS` 构成入口地址的那一套。把这几节串起来，8259A 管理的外部可屏蔽中断的完整链路就通了。

## 两片 8259A 怎样接住一次可屏蔽中断
> 对应块：BLK50 | 覆盖分集：P97-P98 | 块标题（分集名）：《97》

一换 CPU，就容易以为中断控制器也跟着换了。其实 PC/XT 主板的 CPU 是 8088，AT 主板换成了 80286，后来到 80386、80486，乃至奔腾处理器，外部可屏蔽中断的这套基本机制仍然是两片 8259A 在管：外设提出请求，8259A 收请求、排优先权、向 CPU 发 `INT`，还要记住哪一级正在服务。

接线最容易画错，理解也最容易断。先把名字读顺：逐字稿中反复出现的“859”就是 8259A；“i20”“r20”是 `IR0`，“i278”是 `IR7`；讲级联时出现的“22”或“i22”，指主片的 `IR2`。到了 PC 的外部中断编号，字幕里的“50”应按 `IRQ0` 理解，末尾的“55”则是 `IRQ15`。下面统一用规范的引脚名写，不再让这些读法混在一起。

### 主片、从片与级联线

AT 机用两片 8259A，一主一从。先钉死主从身份：主片的 `SP/EN` 接 $+5\text{ V}$，是从片；把 `SP/EN` 接地，就成为从片。主从关系一点不能含混，后面 `CAS2～CAS0` 的方向、类型号由谁送出，都从这里决定。

从片不能自己把请求送到 CPU 的 `INTR`。它先把自己的请求汇总到 `INT` 输出，再把 `INT` 接到主片的 `IR2`；主片收到后，才通过自己的 `INT` 向 CPU 的 `INTR` 报告。主片的 `CAS2、CAS1、CAS0` 是输出，从片对应的三根线是输入，级联代码由主片向下传给从片。

```text
       外设请求                         外设请求
   IR0、IR1、IR3～IR7                 IR0～IR7
          │                                │
          ▼                                ▼
    ┌─────────────┐   INT              ┌─────────────┐
    │  主 8259A   │◀────────────────────│  从 8259A   │
    │             │                     │             │
    │ IR2 接从片 │                     │ SP/EN 接地  │
    └──────┬──────┘                     └─────────────┘
           │ INT
           ▼
       CPU 的 INTR

  主片 CAS0、CAS1、CAS2 ─────────▶ 从片 CAS0、CAS1、CAS2
```

这条图要分两次看，不能把所有箭头当成同一种意思。左边是从片向主片报告请求；右边是主片选中从片后，把级联代码送到从片。主片原来的 `IR2` 已经接从片，所以它自己外接的七路是 `IR0、IR1、IR3～IR7`；从片另有八路，合起来才是 15 路外部可屏蔽中断。

### 两次 INTA：类型号从哪里冒出来

从片沿 `IR2` 把请求送给主片，主片再向 CPU 请求中断。CPU 决定响应后，通过 `INTA` 连续发两个负脉冲；这两个脉冲都要让级联中的 8259A 收到，不是只送到主片。

第一个 `INTA` 表示 CPU 已开始响应。第二个 `INTA` 到来时，8259A 才能把中断类型号送到 `D0～D7`。但这时主片必须先回答一个问题：刚才选中的是本片请求，还是从片请求？

```text
CPU 的第二个 INTA 到来
          │
          ▼
  主片在 CAS2～CAS0 上给出级联代码
          │
          ├─ 选中本片：本片送出中断类型号
          │
          └─ 选中从片：从片送出中断类型号
```

主片在 `IR2` 接从片，所以该从片对应的级联代码是 `010`，看代码时按 `CAS2、CAS1、CAS0` 的次序读。主片也有 `D0～D7` 数据缓冲器，可是在级联响应中，类型号不是主片替从片算好再送出来的；从片把自己的级联代码同初始化时得到的信息比较，代码相符，才把类型号送上数据总线。

这就是必须区分“主片有数据线”和“主片在这轮送类型号”。对于 8088，只有 8 位外部数据总线，类型号就从 `D0～D7` 送出，不存在再从 `D8～D15` 取另一字节的问题。

### 图 8.7 里的三个八位部件

从外部引脚看，8259A 只是一张接线图；从内部组成看，决定它为什么能这样工作的，是图 8.7 中的 `IRR`、`IMR`、`ISR` 和中断优先权分析器。三个寄存器都是八位，八根 `IR0～IR7` 输入正好一一对应。

```text
IR0～IR7
   │
   ▼
┌──────────┐  哪一路有请求，相应位置 1
│   IRR    │
└────┬─────┘
     ▼
┌──────────┐  1 屏蔽，0 放行
│   IMR    │
└────┬─────┘
     ▼
┌─────────────────┐
│ 中断优先权分析器 │──▶ INT ──▶ CPU 的 INTR
└────────┬────────┘
         ▼
┌──────────┐  已被选入服务的请求，相应位置 1
│   ISR    │
└──────────┘
```

#### IRR 锁住来的请求

IRR 是**中断请求寄存器**。`IR0～IR7` 哪一路送来有效请求，IRR 就在相应位记下它。它像 373 或 374 那样把到来的数据锁住：请求来了，先留在 8259A 里面，不会随着外设信号短暂消失就丢掉。

初始化时，还可以规定 `IR0～IR7` 的请求信号怎样算有效：可以选上升沿有效，也可以选高电平有效，一般取上升沿有效。这里的“初始化”，就是把芯片以后接收请求的判据先写好。

#### IMR 管住谁能往下走

IMR 是**中断屏蔽寄存器**。它的 `D0～D7` 分别管理 `IR0～IR7`：对应位写 `1`，就是屏蔽那一路；写 `0`，就是放行那一路。

比如，想让 `IR1` 参加优先权分析，却把其余七路都挡住，就让 IMR 只有 `D1=0`，其余位置 `1`。这个极性一定要记牢：只有**未屏蔽**的请求，才能继续到优先权分析器那里。初始化后，运行中也可以通过 `OCW1` 改写 IMR，仍然是对应位 `1` 屏蔽、`0` 放行。

#### ISR 标记被选中的那一级

IRR 收到请求、IMR 又没有挡它以后，优先权分析器把有效请求比较一遍，选出优先级最高的一路，置上 ISR 的对应位。ISR 是**中断服务寄存器**。例如 `IR0` 与 `IR3` 同时来了请求，按相应优先权规则选 `IR0`，ISR 的 `D0` 就置为 `1`，表示 8259A 已把这一级选入服务。

但 ISR 置 `1` 不等于 CPU 已经执行完服务程序。它先表示 8259A 已经选中了这一级，8259A 随即通过 `INT` 向 CPU 请求服务；CPU 响应后，才会取得类型号、建立 `CS:IP` 并取指令。

> **易错点**：IRR 记“谁来过”，IMR 记“谁被挡住”，ISR 记“谁已经被 8259A 选中服务”。这三个“1”的含义不一样。

### 请求还要过两道门

外设提出一个可屏蔽中断请求后，CPU 能不能响应，先看 8259A 对它有没有屏蔽，再看 CPU 自己的 `IF`。两道门缺一道，响应都走不下去。

8259A 这一关在 IMR。即使 CPU 已开中断，只要这一路在 IMR 中被挡住，就不能参加有效的优先权分析。CPU 这一关在 `IF`。即使 8259A 已经通过 `INT` 送来请求，只要 `IF=0`，CPU 就暂不进入响应过程；但请求仍保存在 IRR 中，不会凭空消失。

```text
外设提出请求
    │
    ▼
8259A 记录到 IRR
    │
    ├─ IMR 屏蔽 ──▶ 不进入有效优先权分析
    │
    ▼
8259A 经 INT 请求 CPU
    │
    ├─ CPU 的 IF = 0 ──▶ 暂不响应，请求仍保留
    │
    ▼
条件满足后，CPU 才开始 INTA 响应
```

所以在 8086/8088 系统里，不能再把外部可屏蔽中断简单理解成“只看 `IF`”。后来补上 8259A 的视角后，结论就完整了：**IF 管 CPU 能不能响应，IMR 管 8259A 放不放行这一路请求。**

### 服务的结束：自动与非自动

IRR 锁住请求、ISR 标记服务以后，还必须回答：这一级什么时候才算真正结束？8259A 有自动结束与非自动结束两种方式。

自动结束时，8259A 收到第二个 `INTA` 负脉冲，就一边送出中断类型号，一边把 ISR 中正在服务的那一位清零。对 8259A 来说，类型号已经送出，这一级就算结束。但这时 CPU 还没有建立好服务程序入口，所以通常不采用这种方式。

非自动结束时，8259A 收到第二个 `INTA`、送出类型号，却不清 ISR 的服务位。CPU 根据类型号 $N$ 计算 $N\times4$，在中断向量表里依次取出 `CS` 和 `IP`，进入中断服务程序。等这一级真正处理完，在 CPU 执行 `IRET` 返回原程序之前，服务程序要先向 8259A 发出 EOI 中断结束命令。8259A 收到 EOI，才把 ISR 对应位清零；之后 CPU 才执行 `IRET`。

```text
第二个 INTA
    │
    ├─ 自动结束：送出类型号，同时清 ISR
    │
    └─ 非自动结束：只送类型号，ISR 保持为 1
                         │
                         ▼
              服务程序完成工作
                         │
                         ▼
                先向 8259A 发 EOI
                         │
                         ▼
                    清 ISR 服务位
                         │
                         ▼
                     执行 IRET
```

主板上的 8259A 一般选非自动结束方式。三个时间点务必分清：**类型号送出，并不等于 EOI；EOI 必须在 IRET 之前。**

### ICW1 到 ICW4：先把工作方式定下来

8259A 一开始使用，主程序就要先对它初始化。控制逻辑里有四个初始化命令寄存器，名字从 `ICW1` 排到 `ICW4`，通过 `OUT` 写入八位命令字。它们用来设置单片还是级联、请求怎样算有效、类型号基准、主从关系、缓冲方式和优先权方式等基本条件。

| 初始化命令字 | 本讲要求掌握的内容 |
| --- | --- |
| `ICW1` | 选择单片或级联；选择上升沿或高电平有效 |
| `ICW2` | 设置本片的中断类型号基准 |
| `ICW3` | 只在级联工作时设置主从关系 |
| `ICW4` | 选择缓冲方式、结束方式、优先权方式 |

#### ICW1：先让芯片认出“这是初始化”

写 `ICW1` 时，端口地址要保证 `A0=0`，写出的八位数据还要有 `D4=1` 这个特征位。8259A 把端口地址与数据特征结合起来，才知道写的是 `ICW1`，而不是之后的操作命令字。

本讲特别强调 `D3`，也就是 `LTIM` 位。`D3=0` 时，中断请求信号按上升沿有效；`D3=1` 时，按高电平有效。IBM PC 选 `D3=0`，所以 `IR0～IR7` 八个请求输入端都按上升沿接收请求。`ICW1` 的低三位在本讲中不展开，不要凭别的资料擅自补定义。

#### ICW2：确定 IR0，后面的类型号就跟着走

`ICW2` 用来设置中断类型号基准。给主片写，就设置主片；给从片写，就设置从片。只需确定 `IR0` 的类型号，因为 `IR1～IR7` 会依次加一。

主片的 `ICW2` 初始化为 `08H`，于是：

```text
IR0   IR1   IR2   IR3   IR4   IR5   IR6   IR7
08H   09H   0AH   0BH   0CH   0DH   0EH   0FH
```

从片的 `ICW2` 初始化为 `70H`，它自己的 `IR0～IR7` 就对应 `70H～77H`。因此，从片最后一级的 `IR7` 对应 `77H`，也就是 PC 编号里的 `IRQ15`；这里别再被转写末尾的“55”带偏。

#### ICW3：只在级联时说清“从片接在哪里”

单片工作不用 `ICW3`，级联工作才需要。给主片写 `ICW3`，是告诉主片哪一路主片输入上接了从片；从片接在主片 `IR2`，对应位置就写 `1`。给从片写 `ICW3`，是告诉从片：你的 `INT` 输出接在主片的哪一路；本例就是 `IR2`。

一个是“从片接在哪里”，一个是“我的输出接到哪里”，方向不能反。联系前面的级联图看，主片只有在这个信息已知时，才能把 `010` 这类级联代码送到 `CAS2～CAS0`。

#### ICW4：缓冲、结束和优先权在这里选

`ICW4` 负责选择缓冲方式或非缓冲方式、自动结束或非自动结束，以及固定优先权或循环优先权。

固定优先权就是正常全嵌套方式：`IR0` 最高，`IR1` 次之，一直到 `IR7` 最低。若正在服务 `IR0`，只有比它更高优先级的请求才可能打断；同级请求不能反过来打断自己。

循环优先权则会在响应后转动顺序。假设当前 `IR0` 最高，CPU 响应 `IR0` 后，接着由 `IR1` 成为最高，再依次轮转，`IR0` 退到最低；若原先最高的是 `IR1`，响应后就由 `IR2` 成为最高，`IR1` 退到最低。

本讲给出的常用初始化组合是：**固定优先权的正常全嵌套方式、非缓冲方式、非自动结束方式。**

### OCW1 到 OCW3：工作期间仍能改变状态

初始化完成后，控制逻辑里还有 `OCW1、OCW2、OCW3` 三个操作命令寄存器。它们不是启动时才写一次的配置，而是在 8259A 工作期间仍可通过 `OUT` 写入的命令；不同命令可以在运行中改变芯片的工作状态，不过本讲没有展开的操作，不在这里硬补。

| 操作命令字 | 作用 | 本讲的使用方式 |
| --- | --- | --- |
| `OCW1` | 改写 IMR，改变各路屏蔽状态 | 常用 |
| `OCW2` | 发出 EOI，结束非自动方式下的中断服务 | 常用 |
| `OCW3` | 其他操作控制 | 正常全嵌套、非自动结束时一般不用 |

给 `OCW1` 写命令，相当于给 IMR 写数据。哪一级要屏蔽，就把对应位写 `1`；哪一级不屏蔽，就写 `0`。给 `OCW2` 写 EOI，则是告诉 8259A：“ISR 中刚才服务的那一位可以清掉了。”

正常全嵌套、非自动结束的常用配置下，`OCW3` 通常用不上。知道它存在就够了，不要把本讲未讲的细节自行扩写成一堆命令格式。

### 多个内部部件，为什么只用两个端口地址

859 内部有四个 ICW 寄存器、三个 OCW 寄存器，IRR、IMR、ISR 还可以读出。部件这么多，访问时却主要靠 `A0=0` 与 `A0=1` 两类端口地址区分；再结合命令字的特征位，8259A 才能知道这次 `OUT` 应该写进哪一个内部部件。

```text
                 CPU 发出 OUT 命令
                        │
              ┌─────────┴─────────┐
              │                   │
           A0 = 0              A0 = 1
              │                   │
              └─────────┬─────────┘
                        │
              再检查命令字特征位
                        │
          ┌─────────────┼─────────────┐
          ▼             ▼             ▼
     某个 ICW/OCW      IRR/IMR/ISR      读出状态
```

所以只说“偶地址写命令、奇地址读状态”还不够。**地址的 `A0` 与命令字特征必须一起看。** PC 为主片分配 `20H、21H`：写 `20H` 保证 `A0=0`，写 `21H` 保证 `A0=1`；从片分配 `A0H、A1H`，也分别对应这两个条件。IRR、IMR、ISR 还能读出，便于观察请求是否到来、是否被屏蔽、是否已经进入服务状态。

### BIOS 的类型号与 15 个外部中断级

BIOS 自检完毕、引导操作系统进入内存以前，要先初始化主板上的 859。它给主片的类型号基准设为 `08H`，所以主片 `IR0～IR7` 是 `08H～0FH`；给从片设的基准是 `70H`，所以从片 `IR0～IR7` 是 `70H～77H`。

在 IBM PC 系列中，主片八路叫 `IRQ0～IRQ7`，从片八路叫 `IRQ8～IRQ15`。口诀里可以把 `IRQ0` 读作字幕写出的“50”，把末尾 `IRQ15` 读作“55”；它们不是新的引脚名，更不是 `IR2` 的别名。

主片的 `IR2` 已用于级联，不能再当一路普通外设中断，所以 16 个编号中少了一路，外部实际可用 15 级。固定优先权下，从主片这一层看，顺序不能把从片八路拆散后插到主片各路之间，而应把从片整组看作从主片 `IR2` 上报的请求：

```text
IRQ0
  > IRQ1
  > 从片整组 IRQ8～IRQ15（经主片 IR2 上报）
  > IRQ3
  > IRQ4
  > IRQ5
  > IRQ6
  > IRQ7
```

从片内部还会按自己的 `IR0～IR7` 排优先权；若从片同时有多个请求，仍由从片自己的分析器先选。可是对主片而言，它们都以主片 `IR2` 的身份出现，整组处在主片 `IR2` 的优先级位置。

### 一次请求的完整响应链

把接线、三个寄存器、命令字和 CPU 的动作连起来，完整过程是这样的：

1. 外设从某一路 `IR0～IR7` 提出请求，8259A 按初始化时的方式接收，通常取上升沿有效。
2. 8259A 用 IRR 对应位锁住请求；IMR 没有屏蔽的请求，才能进入有效的优先权分析。
3. 优先权分析器选出最高一级，置上 ISR 对应位，经 `INT` 向 CPU 的 `INTR` 发请求，同时结束本次 `INT` 输出，避免正在服务的低级请求被同级请求打断。
4. CPU 收到 `INTR` 后检查响应条件；`IF` 允许时，经 `INTA` 连续发出两个负脉冲。
5. 单片工作由本片在第二个 `INTA` 期间送出类型号；级联工作由主片先送 `CAS2～CAS0` 级联代码，再由被选中的从片送出类型号。
6. CPU 得到类型号 $N$，计算 $N\times4$，从向量表取 `CS` 与 `IP`，转入服务程序。
7. 非自动结束时，服务程序结束前先向 8259A 发 EOI，清除 ISR 服务位；随后 CPU 执行 `IRET`，回到被中断的程序。

三个时间点要记牢：IRR 置位，是请求来了；ISR 置位，是 8259A 选中了这一级；EOI 清 ISR，才是服务程序确认这一级结束。最容易丢的，正是“8259A 认为已服务”和“CPU 实际已执行服务程序”之间的区别。

### 本讲提到的题目

#### 请求未屏蔽，但 CPU 当时关了中断

**题目：** 一个外部可屏蔽中断源向 8259A 提出请求，这一路在 IMR 中未屏蔽。请求到来时，CPU 的 `IF=0`。CPU 能否响应？过了一段时间，CPU 执行 `STI`，使 `IF=1`，继续使用刚才的请求，这时能否响应？

**答案：当时不能，后来能。**

请求没被 8259A 屏蔽，但 `IF=0` 使 CPU 不能进入响应过程。它仍保存在 IRR 中。执行 `STI` 后 `IF=1`，条件改变，保留的请求就可以继续得到响应。

#### CPU 已开中断，但这一请求被屏蔽

**题目：** CPU 已通过 `OCW1` 把某一路设为屏蔽，且 `IF=1`。此时外设从这一路提出请求，CPU 能否响应？

**答案：不能。**

`IF=1` 只说明 CPU 允许响应可屏蔽中断，不能越过 8259A 自己的屏蔽。IMR 对应位为 `1` 时，请求在 8259A 内就被挡住，不能参加有效的优先权分析。

两道题放在一起，结论就很清楚：**未屏蔽但 CPU 关中断，条件改变后还能响应；CPU 已开中断但请求被 8259A 屏蔽，条件不变就始终不能通过。**

## 8259A 的初始化与操作命令字
> 对应块：BLK51 | 覆盖分集：P99-P100 | 块标题（分集名）：《99》

先从一个容易被旧资料带偏的地方说起。Intel 早期生产 8259A 时，与之配套的 8085 还是八位机；那时一个中断向量占 4 个字节，在向量表里要占 8 个字节。到了 8086 系统，一个中断向量只占 4 个字节，8085 时代的那套设置便不再适用，所以在初始化命令字中给相应位画了叉。

> **注意**：不能因为芯片还是 8259A，就把当年 8085 的初始化格式原封不动搬过来。系统换了，命令字里与 8085 有关的设置也要跟着变。

这一块要真正掌握，不只是记住 ICW1～ICW4 的几个名称。更重要的是：什么时候选单片，什么时候选级联；主片与从片怎样把中断请求汇总到 CPU；初始化完成后，又怎样屏蔽、放行某个中断，并在服务结束时发出 EOI。这些内容在实际系统里不一定常考，却非常有用——无论是研究生阶段做软硬件结合的课题，还是工作中开发一个中断方式工作的系统，都绕不开它们。

### ICW1：先决定单片还是级联

初始化 8259A，第一步是写 ICW1。它主要确定三件事：`IR0～IR7` 八个中断请求输入端采用高电平有效还是上升沿有效；这一片 8259A 按单片方式工作，还是按级联方式工作；以及它处在级联系统中的主片还是从片位置。

先抓住工作方式。`D4=1` 表示单片工作；`D4=0` 时，再由 `D3` 区分主片和从片：`D3=1` 为主片，`D3=0` 为从片。8086 系统不使用 8085 的中断向量间隔设置，相应位取 0。`D0` 固定为 1，初始化 ICW1 时不用犹豫。

| ICW1 位 | 取值 | 含义 |
| :--- | :---: | :--- |
| `D4` | `1` | 单片工作 |
| `D4` | `0` | 级联工作，随后还要初始化 ICW3 |
| `D3` | `1` | 级联中的主片 |
| `D3` | `0` | 级联中的从片 |
| `D1～D2` | `00` | 8086 系统设置，8085 时代的相关设置不用 |
| `D0` | `1` | ICW1 标志位，固定为 1 |

这里有一个必须记牢的因果关系：只有单片工作时，才可以不再写 ICW3；只要选择级联，就一定要接着初始化 ICW3。不能把“已经给某片 8259A 写过 ICW1”和“它一定是单片工作”画等号。

> **易错点**：从片同样要初始化 ICW1，不能只给主片写。它的 ICW1 也要选级联工作，只是 `D3` 应写 0，表示自己是级联中的从片。

向 `A0=0` 的端口写操作，芯片才会把这次写入识别为 ICW1。在 PC 系统中，主片对应 `21H`，从片对应 `A1H`。级联系统中，两片的 ICW1 都写成 `11H`：`D4=0` 表示级联，`D3=1` 为主片、`D3=0` 为从片，`D0=1` 作为标志位。

```asm
; 主片：级联工作
mov al, 11h
out 21h, al

; 从片：级联工作
mov al, 11h
out A1h, al
```

> **结论**：初始化顺序是 **ICW1 → ICW2 → ICW3（仅级联时）→ ICW4**。从 ICW2 开始，写入要送到 `A0=1` 的端口；PC 系统中就是主片的 `21H`、从片的 `A1H`。

这四步不能只靠“这是 ICW2”或“这是 ICW3”的命令字格式来随意识别。ICW2 没有特征位，它紧跟在 ICW1 后写入，靠这个先后顺序被 8259A 识别。ICW3 也是同样的道理。所以编程时不要在 ICW1 和 ICW2 之间插入别的无关写入，也不要在 ICW2 和 ICW3 之间随意插入操作。

### ICW2：只确定类型号的高五位

在 8086 方式中，ICW2 用于确定本片 8259A 所管理的中断类型号基址。8259A 内部把这 8 位按 `D7～D0` 排开，真正写入的是中断类型码的高五位，也就是 `D7～D3`；`D2～D0` 写 0。类型号、类型码、类型号基址中的“号”指的就是编号；在这套初始化中，基址的最低三位为 0。

不要把它理解为“这 8 位直接给出 0～255 的全部类型号”。8086 系统由 `IR0～IR7` 产生的 8 个类型号，低三位对应各输入端；ICW2 给出的是它们共同的高五位。把这个共同的高位设对，后面的类型号才有正确的取值范围。

PC 系统中，主片和从片给出的高五位不同：

| 芯片 | ICW2 写入值 | 形成的类型号基址 |
| :--- | :---: | :---: |
| 主片 | `08H` | `08H` |
| 从片 | `70H` | `70H` |

对应代码是：

```asm
; 主片
mov al, 08h
out 21h, al

; 从片
mov al, 70h
out A1h, al
```

这里主片和从片虽然都要先写 ICW1，但接下来给出的类型号基址不同。不要把“高五位”误听成“高两位”，也不要以为从片 ICW2 可以不写。

### ICW3：把从片接到主片的哪一路

如果两片以上 8259A 级联工作，写完 ICW2 后必须紧接着写 ICW3。级联不是把八条中断请求线简单并在一起，而是要先明确：主片把哪一路 `IR` 留给从片输出；从片又是以哪一个级联标识接入这条通路。

本题讲解的连接方式中，主片为 `IR2`，从片的 `INT` 接到主片 `IR2`：

```text
                    ┌────────────────────────────┐
主片 IR0 ─────────►│                            │
主片 IR1 ─────────►│          主 8259A          │
                    │          ICW3 = 04H        │
主片 IR2 ◄─────────┤                            │
      ▲             └─────────────┬──────────────┘
      │                           │ INT
      │             ┌─────────────▼──────────────┐
从片 IR0 ─────────►│                            │
  ……               │          从 8259A          │
从片 IR7 ─────────►│          ICW3 = 02H        │
                    └────────────────────────────┘
```

读图时，主片和从片各接一组自己的 `IR0～IR7` 输入；从片不是只输出一个请求就算结束，它仍管理自己的八条输入请求。这个从片汇总后的 `INT`，才接到主片专门分给它的 `IR2`。主片收到该请求后，再向 CPU 发出中断请求。

ICW3 的字节格式因主、从不同：

- 主片的 ICW3 中，某一位为 1，表示该位的 `IR` 输入接到了从片的 `INT` 输出。`04H = 00000100B`，表示主片的 `IR2` 接从片。
- 从片的 ICW3 中，某一位为 1，表示从片自己的哪一级 `INT` 输出接到主片。`02H = 00000010B`，表示这个从片对应主片的 `IR2`。

```asm
; 主片：IR2 接从片 INT
mov al, 04h
out 21h, al

; 从片：以 2 为标识接入主片 IR2
mov al, 02h
out A1h, al
```

> **易错点**：主片和从片的 ICW3 不是各写一遍 `04H`。主片的 `04H` 说明“从片接到我的 IR2”；从片的 `02H` 说明“我以 2 号连接到主片”。一个描述连接位置，一个描述自身标识，含义不能混。

### ICW4：定好嵌套、缓冲和中断结束方式

写完 ICW3 后，级联系统要写 ICW4；单片系统虽然跳过 ICW3，也仍然要写 ICW4。它与 `A0=1` 的端口配合，决定 8259A 的几种工作方式。

| 位 | 取值 | 含义 |
| :--- | :---: | :--- |
| `D4` | `0` | 正常嵌套 |
| `D4` | `1` | 特殊嵌套，可用操作命令字指定优先权 |
| `D3` | `0` | 非缓冲方式 |
| `D2` | `0` | 非缓冲方式下的设置；缓冲时与 `D3` 配合区分主、从 |
| `D1` | `0` | 非自动中断结束 |
| `D1` | `1` | 自动中断结束 |
| `D0` | `1` | ICW4 标志位 |

#### 正常嵌套

正常嵌套就是完全嵌套方式，优先权固定：`IR0` 级最高，随后是 `IR1`，一直到 `IR7` 级最低。这里一定要把“固定优先权”和“特殊嵌套”分开：正常嵌套下，输入端的位置已经把优先次序确定下来；特殊嵌套则允许再通过操作命令指定优先权。

#### 缓冲方式

`D3` 用来选择缓冲或非缓冲方式。本讲所讨论的 PC 系统采用非缓冲方式，因此这一位取 0。我们不使用 `D3=1` 时的缓冲方式，也就不在主片、从片组合上继续展开。

#### 中断结束方式

`D1` 决定中断结束时由谁负责发结束通知。取 1 是自动中断结束，8259A 自动完成相应处理；取 0 是非自动中断结束，需要软件在中断服务程序结束之前，向 OCW2 的 EOI 位发命令，通知 8259A 中断服务已经结束。

通常使用非自动结束。对应的顺序是：

```text
CPU 执行中断服务程序
          │
          ├─ 向 OCW2 的 EOI 位写 1，通知 8259A
          │
          └─ CPU 执行 IRET，结束本次中断服务
```

一定要记住：非自动结束时，**先向 8259A 发 EOI，再执行 IRET**。顺序反过来，8259A 还以为服务没结束，后面的中断响应就可能出问题。

按照本讲的正常嵌套、非缓冲、非自动结束设置，主片与从片的 ICW4 都写成 `01H`：

```asm
; 主片
mov al, 01h
out 21h, al

; 从片
mov al, 01h
out A1h, al
```

把主片与从片完整地连起来看，初始化关系就清楚了：

| 初始化命令字 | 写入主片 `21H` | 写入从片 `A1H` | 主要作用 |
| :--- | :---: | :---: | :--- |
| ICW1 | `11H` | `11H` | 选择级联工作，并标明主片、从片 |
| ICW2 | `08H` | `70H` | 确定各自的中断类型号基址 |
| ICW3 | `04H` | `02H` | 从片 `INT` 接到主片 `IR2` |
| ICW4 | `01H` | `01H` | 正常嵌套、非缓冲、非自动结束 |

这张表不是孤立的四个字节，而是一套有先后依赖的初始化：ICW2 靠紧跟 ICW1 被识别，ICW3 靠紧跟 ICW2 被识别；选择单片时跳过 ICW3，最后用 ICW4 收尾。

### 工作后靠操作命令字改变运行状态

初始化完成以后，8259A 就按设定的方式工作了。但系统运行过程中，某一路请求可能暂时不能打断 CPU，某一路又需要放行；一次服务结束后，也得通知 8259A。工作期间要写操作命令字 OCW1～OCW3，改变它的运行状态。它们和初始化命令字不是一回事：ICW1～ICW4 用来建立初始工作方式，OCW1～OCW3 则在后续运行中起作用。

#### OCW1：逐位屏蔽与放行中断请求

OCW1 处理 `IR0～IR7` 的屏蔽与放行。对应位写 1，表示该路中断请求被屏蔽；写 0，表示不被屏蔽，允许通过。

这里特别容易反过来记，一定要把口诀念顺：

> **1 屏蔽，0 放行。**

只有未被屏蔽的中断请求，8259A 才能响应；8259A 能响应，CPU 才有机会响应。屏蔽是从外到内逐级限制的，不能把“8259A 已经屏蔽”误认为“CPU 收到了中断”。

同一个端口也可以读出当前状态。读回的寄存器称为 IMR，即中断屏蔽寄存器。在 PC 系统中可从 `21H` 读主片的 IMR，逐位检查 BIOS 对 8259A 做过怎样的屏蔽设置。

`OCW1` 的写入通常在 `ICW4` 完成初始化之后进行；此时送到 `A0=1` 的端口，也就是主片 `21H` 或从片 `A1H`。

```asm
; 读取主片 IMR
in al, 21h
```

#### OCW2：向 8259A 发出非自动中断结束

非自动结束的关键，是写 `OCW2` 的 `EOI` 位。`EOI` 就是 End Of Interrupt，中断结束。向 `A0=0` 的端口写入这个操作命令字，让 8259A 清掉当前中断所对应的服务状态，表示这一段服务已经结束。

正常嵌套方式下，向 `OCW2` 的第 5 位写 1，就发出了 EOI。主片用 `20H` 端口，从片用 `A0H` 端口，两者都要求 `A0=0`。

```asm
; 通知主片：本次中断服务结束
mov al, 20h
out 20h, al
```

```asm
; 通知从片：本次中断服务结束
mov al, 20h
out A0h, al
```

本讲主要抓住这一位的用法。`OCW2` 的其他位还可以在结束中断的同时指定下一条优先权，形成循环优先权等用法；正常嵌套下先把 EOI 的端口、时刻和顺序掌握扎实。

#### OCW3：改变屏蔽方式

OCW3 用于改变 8259A 的屏蔽方式。这里要特别区分：OCW1 决定 `IR0～IR7` 中哪一路被屏蔽，OCW3 则改变屏蔽方式本身。两者有关联，却不是同一个命令字。

向 `A0=0` 的端口写 OCW3。正常嵌套方式下，PC 系统的常规使用不依赖它，因此本讲不进一步展开其位组合；先把前面三个常用命令字用熟，再按需要补充。

### 本讲提到的题目

题目给出的系统里有一个输入设备。设备已经准备好数据后，发出选通信号。CPU 需要通过中断方式取走数据：先把设备数据接入系统数据总线，再让这次“数据就绪”成为 8259A 的中断请求；CPU 响应后读取数据，暂存到内存，供后续处理。

前面那个 A/D 转换器的思路也可以串起来看：转换开始时 EOC 变低，转换完成、全部数据准备好后 EOC 变高，用这个低到高的上升沿向 8259A 请求中断；CPU 响应后进入中断服务程序，再读取转换结果。这道题则把同样的思路放在“输入设备数据就绪”这一事件上。

#### 数据与中断请求分别锁存

不能把输入数据和中断请求简单地混在一起处理。题目要求设计两个锁存环节：一条通路锁住输入数据，另一条通路把“数据已准备好”这件事锁住，并送给 8259A 的 `IR2`。

数据通路上，设备发出选通信号后，8 位选通器把准备好的数据锁存到锁存器输出端。第二个选通信号到来之前，这份数据一直保持稳定，CPU 读取时不会因为设备继续改变输出而丢失。

中断请求通路上，选通信号把触发器相关输入抬高，触发器的 `Q` 输出形成送给 8259A 的中断请求。这个请求送往 8259A 的 `IR2`，由 8259A 汇总后再向 CPU 提出中断。

```text
输入设备 ──选通──► 8 位数据锁存 ──► 输入缓冲器 ──► D0～D7
    │
    └─ 选通 ──► 请求锁存 ──► Q ──► 8259A 的 IR2
                                      │
                                      └──► INT ──► CPU
```

这里用正 5 V 作为触发器相应输入端；选通信号到来时，使 `Q` 转为高电平，形成由低到高的中断请求。8259A 已经设置为上升沿有效，正好接收这个信号。

#### 读走数据后清除请求

输入端口还需要用系统地址译码选通。题目用 `A0～A9` 作一级译码，把 `240H` 分配给该输入端口。实际器件可用 245 或 244 一类缓冲器：当 `A0=1`、`A2=0` 对应的译码有效，并且 `IOR` 为低电平时，缓冲器被打开，CPU 便能从系统 `D0～D7` 上取走锁存的数据。

同一个由 `IOR` 产生的低电平，还接到请求锁存器的异步清零端。CPU 把数据取走时，这个低电平使 `Q` 回到低电平，撤销原先送给 8259A 的请求。

```text
数据就绪，选通信号到来
          │
          ▼
数据锁存，Q 输出变高
          │
          ▼
8259A 的 IR2 收到上升沿
          │
          ▼
8259A 向 CPU 请求中断
          │
          ▼
CPU 响应，进入中断服务程序
          │
          ▼
读走 D0～D7 上的数据
          │
          ├─ 暂存到内存，供后续处理
          │
          └─ IOR 有效，清除请求锁存器
```

设备一次中断后先让 CPU 取走数据、暂存到内存；设备再次准备好数据，就再产生下一次取数过程。按题意，系统处理到输入回车字符时结束。

所以，本题的关键不在于画一根“数据线加一根中断线”这么简单，而在于把两个时序分开保证：数据必须先稳定地锁住，CPU 才能读；这次请求又必须通过上升沿送到 8259A 的 `IR2`，在数据读完后再被清掉。**数据锁存保证“读得对”，请求锁存和清除保证“中断来得准、退得干净”。**

## 8086 中断输入输出：把中断请求接到缓冲区
> 对应块：BLK52 | 覆盖分集：P101 | 块标题（分集名）：《101》

我们今天不再只做书上的一小段，而是按照书上，把一个完整的 8086 汇编语言程序搭起来，再把它用到这道题上。

这样做有两层意思：一方面，题目要求什么，就按题目的要求去完成；另一方面，题目也把前面学过的程序设计串起来了。程序只要用到堆栈，前面讲过的东西就不能忘：要先定义堆栈段，再根据实际需要给它留出空间。代码段、数据段、堆栈段和 `ASSUME` 关系起来，才称得上一个完整程序。这个空间到底要多大，要看程序里到底要压入、弹出多少内容，题目没有替我们规定一个固定数字。

### 先把程序骨架搭起来

一个完整程序，至少要把数据放好，把代码放好，还要为中断服务程序准备堆栈。段的假定可以按这个关系来理解：

```text
CODE SEGMENT
    ASSUME CS:CODE, DS:DATA, SS:STACK
START:
    ...
CODE ENDS
```

`START` 不是“程序到这里就结束了”，而是程序入口的标记。`CODE ENDS` 之后还可以接中断服务程序；整个源程序最后再用 `END START` 指明入口。真正容易忘的，往往不是这些格式，而是程序运行时的顺序：先初始化数据，再建立中断向量，打开需要的中断，最后进入等待数据的工作状态。

数据段里，本题至少需要三个东西。它们不是同一种数据，不要混在一起理解。

```asm
IN_BUFF   DB 100 DUP (?)
IN_POINT  DW ?
IMR_SAVE  DB ?
```

`IN_BUFF` 是设备数据真正存放的缓冲区，按字面意思就是一块内存区域。题目把它定义成 100 个单元，所以程序可以连续保存最多 100 个数据。这里的前提是：系统在这 100 个数据还没有用完之前，已经按下 reset，或者输入结束并回车。因为这段程序的思路是用 `IN_POINT` 逐格往后走，它没有在描述中再加入越界保护，默认数据量不会超过 100 个。

`IN_POINT` 才是“下一次要写到哪儿”的地址指针。开始时它要先装入 `IN_BUFF` 的偏移地址；每来一次中断，程序把当前地址读出来，设备数据写到当前单元，然后把指针加一，再把新指针保存回去。这样，下一次中断到来时，自然就会写下一个单元。

`IMR_SAVE` 用来保存从 8259 读出的原中断屏蔽字。为什么不直接改？因为本程序只关心某一个中断，不应该把其他中断原来的屏蔽状态一并弄丢。先读出来保存，用完再放回去，这才是一个完整的“借用—修改—恢复”过程。

> **结论**：`IN_BUFF` 存数据，`IN_POINT` 记录位置，`IMR_SAVE` 保护设备控制状态。三者缺一不可，职责不能混用。

### 中断向量必须先落到表里

程序里既然写了中断服务子程序，就不能只把代码放在那里，还要把它的入口地址告诉 CPU。入口地址就是中断向量：CPU 发生对应类型的中断时，要按照向量表中的地址找到服务程序。

8086 的中断向量表在内存最低的 1024 个单元里。设中断类型号为 $N$，它对应的表项从 $4\times N$ 开始；一个表项要保存两件事：服务程序入口的偏移地址，以及服务程序入口的段地址。

```text
中断类型 N
        │
        ├── 0000:4×N      入口偏移地址
        └── 0000:4×N + 2  入口段地址
```

本程序使用的中断类型号是 `0BH`，所以表项位置就是：

```text
偏移地址：0000:002CH
段地址：  0000:002EH
```

这不是让我们凭感觉记住 `002CH`，而是由 `4 × 0BH` 算出来的。只要理解了“每个向量占 4 个单元”，类型号一变，地址自然跟着变。

#### 手工写向量表：把原理刻进程序

在向量表还没有建立好之前，先关中断。为什么要 `CLI`？因为此时表项里的入口地址可能还不是我们要用的地址；如果在这段写入过程中恰好来了中断，CPU 可能跳到一个尚未准备好的入口。向量表完整写好、原来的 `DS` 恢复以后，再 `STI` 打开中断。

我更愿意把这段过程在黑板上完整写一遍，因为这样才是在使用中断的原理，而不是只背一个功能号。大致过程如下，服务程序入口的标号这里记作 `INT_TYPE`：

```asm
CLI
PUSH DS
MOV AX, 0000H
MOV DS, AX
MOV BX, 4*0BH
MOV AX, OFFSET INT_TYPE
MOV WORD PTR [BX], AX
MOV AX, SEG INT_TYPE
MOV WORD PTR [BX+2], AX
POP DS
STI
```

这几行的动作要连起来看。`PUSH DS` 先把主程序原来的数据段寄存器保护起来；把 `AX` 清零并送到 `DS`，是因为中断向量表位于零段；`BX` 指向 `0BH` 号向量的偏移地址单元；随后把 `INT_TYPE` 的偏移地址写到 `[BX]`，把它的段地址写到 `[BX+2]`。

`[BX+2]` 这一点特别容易搞错。不是一个地址单元把完整入口一次写完，而是偏移地址和段地址要分成前后两个单元写入。写完以后 `POP DS`，数据段寄存器重新指回 `DATA`，再执行 `STI`，这时才允许中断正常进入。

```text
CLI
 └─ 暂时不让中断打断“建表”过程
    PUSH DS / DS=0
    └─ 定位 0BH 号向量表项
       写入口偏移地址
       写入口段地址
    POP DS
       └─ 回到 DATA 段
STI
 └─ 向量已准备好，允许中断
```

图读完要记住的不是某一串固定地址，而是一个因果链：**先关中断，完整写表，恢复数据段，再开中断。** 少一个环节，表项可能写坏；顺序反了，程序可能在入口地址尚未准备好时被中断打断。

#### DOS 25H 功能调用：把入口参数交给系统

书上给的是另一种写法：让 DOS 的 `25H` 功能调用替我们建立向量。进入调用前，要把服务程序入口的段地址和偏移地址按该功能要求准备好，再执行：

```asm
MOV AH, 25H
MOV AL, 0BH
INT 21H
```

这一步完成以后，效果和前面手工写向量表一样，都是把 `INT_TYPE` 的入口地址放入 `0BH` 号向量表项。`AH` 是 `25H` 功能号，`AL` 是要建立的中断类型号；段地址和偏移地址是这个功能调用所要求的入口参数，不能只记住“调用 `25H`”四个字，却说不清参数怎么准备。

不过我为什么总把黑板上的原理再写一遍？因为原理记在脑子里，十几天不用也不容易忘；如果只是记 DOS 的调用方式，可能今天会用，十几天后连 `25H` 的功能号和参数对应关系都想不起来。实际编程当然可以用书上的 DOS 功能调用，理解程序、应付考试和真正掌握机制，则一定要回到“向量表在哪里、表项怎么排、入口地址怎样写进去”这条根上。

### 只放开当前要用的中断

向量表准备好以后，程序还必须允许本题所用的中断真正到达 CPU。主板上的 8259 在机器启动时已经由 BIOS 做过 `ICW1` 到 `ICW4` 的初始化，所以这里不再重新给 8259 发送初始化命令，只需要操作它的中断屏蔽寄存器 IMR。

这个 IMR 有 8 位，每一位对应一个中断请求。当前要使用的是 `0BH` 号中断，读取出来的字节中，第 3 位是 0 还是 1，就表示这一位对应的请求是被屏蔽还是未被屏蔽。这里的 IMR 位次是从 0 数起的；第 3 位清零，就表示对应请求放开。

程序先从 8259 的同一个端口读出当前 IMR，保存到 `IMR_SAVE`，然后只清掉第 3 位，再把修改后的字节写回去：

```asm
IN  AL, 21H
MOV IMR_SAVE, AL
AND AL, 0F7H
OUT 21H, AL
```

为什么是 `AND AL, 0F7H`？把它写成二进制就明白了：

```text
0F7H = 1111 0111B
             ↑
             第 3 位变为 0
```

`AND` 的好处是只改变我们关心的那一位，其余位按照原值保留。如果直接给一个自己编出来的掩码，很容易把别的屏蔽状态也改掉。至于同一个端口为什么一会儿叫“读 IMR”、一会儿又叫“写 OCW1”，关键在于操作方向：从 CPU 读出时得到的是当前屏蔽字，向端口写出时写入的是新的操作命令字。端口相同，方向不同，含义也不同。

> **易错点**：`0F7H` 不是把第 3 位设置成 1，而是通过与运算把它清成 0。0 代表对应请求未被屏蔽；保存原值是为了程序结束时能够恢复。

程序用完这项中断设置，不能把改变后的 IMR 永远留在那里。退出前要把 `IMR_SAVE` 放回 `AL`，再写回 21H 端口：

```asm
MOV AL, IMR_SAVE
OUT 21H, AL
```

这才是“读出来、修改、恢复”的闭环。

### 主程序等待，中断服务程序收数据

8259 的设置完成以后，主程序还要把缓冲区指针准备好。`IN_POINT` 装的是 `IN_BUFF` 的偏移地址，不是 `IN_POINT` 这个变量自己的地址：

```asm
MOV AX, OFFSET IN_BUFF
MOV IN_POINT, AX
```

这一步必须在等待中断之前完成。否则第一次中断到来时，指针还没有指向缓冲区，第一次设备数据就没有地方可放。

#### 主循环等待回车

主程序用 DOS 的 `06H` 功能做控制台输入输出操作。输入字符时，功能号放在 `AH`，`DL` 放 `FFH`；如果把它用来向屏幕输出，`DL` 则放要输出字符的 ASCII 码。

这里要的是从键盘读一个字符，所以写法是：

```asm
MOV AH, 06H
MOV DL, 0FFH
WAIT_KEY:
INT 21H
CMP AL, 0DH
JNE WAIT_KEY
```

`0DH` 是回车。每调用一次，主程序就检查 `AL` 里拿到的字符：如果不是回车，就跳回去继续检查；只有拿到回车，才结束等待。

这个 `06H` 调用不是设备数据到来后才把整个程序卡住的那种等待。程序会反复调用、反复检查，`AL` 里没有真正的输入时，它就继续走循环。正因为主程序一直在转，设备的中断请求才可以在 CPU 执行这些指令的过程中被响应。

```text
主程序
  │
  ├── INT 21H / AH=06H / DL=FFH
  │       │
  │       ├── 不是回车：继续轮询
  │       └── 是回车：离开主循环
  │
  └── 任何时刻设备都可以送来中断请求
          │
          └── CPU 完成当前指令后转入 INT_TYPE
```

这里要把两个“等待”分开：DOS 输入调用是在等用户敲键盘，主程序循环是在等结束键；设备数据的到来则通过中断请求进入服务程序。设备数据并不需要等到用户按下回车才交给 CPU。

#### 中断到来后的现场处理

设备送来中断以后，CPU 不管此刻主循环执行到哪一条指令，都会先完成当前这条指令，保护下一条指令的现场，然后根据中断类型号跳到 `INT_TYPE`。这里可以把它理解成：主程序暂时让路，先去处理设备，处理完再回到原来的执行流。

中断服务程序一开始要像写普通子程序一样保护现场。凡是服务程序会改、而主程序还要继续使用的寄存器，都要按需要保存和恢复。这里绝对不能因为“反正马上要返回”就随便破坏 `AX`、`BX`、`DX`、`DS` 等现场信息；主程序返回后还要继续比较 `AL`、继续走等待循环，任何一个寄存器被改错，程序都可能跑偏。

服务程序真正处理数据的核心，是下面这组动作：

```asm
MOV BX, IN_POINT
MOV DX, 240H
IN  AL, DX
MOV  [BX], AL
INC  BX
MOV  IN_POINT, BX
```

`MOV BX, IN_POINT` 取出当前写入位置。`DX` 指向外部设备的数据端口 `240H`，于是 `IN AL, DX` 把设备送到这个端口的数据读入 `AL`。接着，`[BX]` 指向 `IN_BUFF` 中当前那个单元，设备数据就写进去。

写入以后不能只顾着这一次中断，还要给下一次留下位置，所以马上 `INC BX`，再把新的偏移地址写回 `IN_POINT`。这就是指针变量存在的意义：中断服务程序不必重新从头找缓冲区，也不用在中断之间互相传一个临时地址。

```text
外部设备
   │  设备数据送到 240H 端口
   ▼
IN AL, DX  ───────►  AL
                         │
                         ▼
                 MOV [BX], AL
                         │
                  当前 IN_BUFF 单元
                         │
                    INC BX
                         │
                 写回 IN_POINT
                         │
                    下一次中断
```

按这里的设备配合方式，读端口的动作还会让设备侧的相关状态清掉，设备准备下一次数据。于是每次中断读到的不是上一份数据的反复副本，而是下一次到达的设备数据。

#### 每次中断只走一格

`IN_POINT` 的变化是整个缓冲逻辑的关键，可以把一次完整的数据流写成：

```text
IN_POINT = OFFSET IN_BUFF
                    │
                    ▼
       IN_BUFF[0] ← 设备数据 0
                    │ INC BX
                    ▼
       IN_BUFF[1] ← 设备数据 1
                    │ INC BX
                    ▼
       IN_BUFF[2] ← 设备数据 2
                    ⋮
```

服务程序每次只做同一组动作：读指针、读端口、写当前单元、指针加一、保存指针。它不需要知道数据什么时候来，也不需要在中断里重新等待；中断来了，就处理一个数据，处理完返回。这样连续来几个请求，数据就会按照到达顺序依次落进缓冲区。

> **提示**：本程序默认在缓冲区写满之前已经 reset 或按下回车结束。如果实际工程中数据量可能超过 100 个，就要再增加指针边界判断；不能把“本段逻辑假定不会超过 100 个”误认为硬件自动会替我们检查。

### 中断返回以后，程序接着走

服务程序保存和修改完现场，最后要用中断返回指令回到主程序。这里的返回不是从服务程序入口随便跳回去，而是按照中断硬件保存的断点信息，恢复原来的执行位置。CPU 从中断前被打断的执行流继续，接着检查有没有回车。

所以主循环里的 CPU 并不是“停在那里专门等中断”，而是一直在做自己的键盘检查；外部设备的中断请求到来时，CPU 暂时离开这个循环，去服务程序读一次数据，返回后仍然回到循环。只要用户还没有按回车，下一次设备中断还会再次进入 `INT_TYPE`。

等 `AL` 中拿到 `0DH`，主程序才跳出等待。先把原 IMR 恢复，再用 DOS 的退出功能结束程序：

```asm
MOV AL, IMR_SAVE
OUT 21H, AL
MOV AH, 4CH
INT 21H
```

如果系统还有其他任务，就可以在这里继续安排那些任务；本题没有其他任务，所以程序结束。中断服务程序通常放在主程序代码之后，入口标号就是刚才写进向量表的 `INT_TYPE`，服务程序末尾执行中断返回。

### 把这条链路连起来

这题真正要记住的，不只是“8259、缓冲区、指针、键盘输入”这些名词，而是一条完整的数据通路：

```text
建立 0BH 向量
      ↓
读出并保存 IMR
      ↓
清零第 3 位，放开对应请求
      ↓
主程序轮询回车，同时 CPU 继续执行
      ↓
设备请求到来 → 进入 INT_TYPE
      ↓
从 240H 端口读数据 → 写入 IN_BUFF
      ↓
递增并保存 IN_POINT → 中断返回
      ↓
收到回车 → 恢复 IMR → 退出程序
```

这里体现的是利用中断方法实现主机或 CPU 与外部设备之间的通信。通信指令在服务程序里的作用是从外部读数据，而不是 CPU 主动把一批数据发送出去；真正的关键，是设备可以用请求打断程序的执行节奏，主程序不必为每个数据都专门停下来查询。

这类程序在考试卷上并不友好，我估计如果真的出一道这样的题，大部分人都可能在中断入口、现场保护和屏蔽字上绕晕。但实际工程中，大量地方都在使用中断方式做输入输出。正因为它不是只考一个指令，而是把前面学过的初始化、向量表、8259、堆栈、现场保护和指针更新全串在一起，才更值得反复练习。真正把这条链路亲手写出来，考试时就不会只剩下“见过这个词”的感觉。
