## 移位、循环移位与转移指令
> 对应块：BLK21 | 覆盖分集：P41-P42 | 块标题（分集名）：《41》

这一段我们先把几道逻辑运算题收住，再进入移位和转移指令。很多人一看到条件分支，就急着去找某一条“判断指令”。可题目真正要你判断的，到底是“这两位是否同时为零”，还是“至少有一位为零”？这是汉语句义先决定的；等语义看准了，测试对象、零标志与分支方向才跟着确定。

### 逻辑运算题：语义决定测试方式

#### 判断“同时为零”，不能破坏原变量

题目要求测试 `BX` 中的 `V1`、`V2` 是否同时为零：如果同时为零，就把 `AL` 全清零；否则把 `AL` 清零。

这里要注意，题目要求的是“测试”，并没有要求改变 `BX` 的原值。假如用按位与把 `V1`、`V2` 单独取出来，按位与的结果确实能判断两位是否同时为零，可它一旦写回 `BX`，原值就被破坏了。因此应该使用不保存运算结果的 `TEST` 指令，再配合条件转移完成分支。

```asm
    test    bx, 0006h
    jz      both_zero
    and     al, 0
    jmp     done
both_zero:
    xor     al, al
done:
```

`TEST BX, 0006H` 只设置标志位，不保存 `BX`。当被测两位都为 0 时，按位与的结果为 0，`ZF=1`，于是 `JZ` 跳到 `both_zero`，用 `XOR AL, AL` 把 `AL` 全清零；否则 `AND AL, 0` 清零 `AL`，随后必须用 `JMP` 跳过“全清零”分支。

> **易错点**：条件分支不能只盯着“用哪条指令清零”。你编完一个分支，还要顺着程序继续走一遍。若条件不满足时仍然顺序落进下一段，后面的指令很可能又把刚才的结果改掉。

> **结论**：题目要求保留原值时，优先想到 `TEST`，不要为了“测试两位”顺手把 `BX` 改掉。

#### “只有一位为零”和“至少有一位为零”不是一回事

同一组两位共有四种状态：

| `V1 V2` | 两位是否同时为 0 | 是否至少有一位为 0 |
| :--- | :--- | :--- |
| `00` | 是 | 是 |
| `01` | 否 | 是 |
| `10` | 否 | 是 |
| `11` | 否 | 否 |

若题意是“只要 `V1`、`V2` 中有一位为零”，就属于“或”的概念；但真的是“只有一位为零”，允许的只有 `01` 和 `10` 两种状态。

这里容易搞错。我们若只观察“按位与的结果是否为零”，`00` 也会被算进来，所以它无法区分 `00` 与 `01`、`10`，当然不能完成“恰有一位为零”的判断。

按“只要有一位为零”理解时，应该先检查这一位：

```asm
    test    al, 01h
    jz      clear_result
    test    al, 02h
    jz      clear_result
    ; 两位都是 1，继续执行“不满足”分支
```

而要判断 `00`、`01`、`10` 三种状态中是否存在一种，单靠某一个“与运算结果等于 0”的测试并不够，还要根据语义选择测试对象；如果确实要求“恰好一个零”，还要继续检查另一位是否非零。

> **提示**：做题时不要一上来就写程序。先在代码前面写一句自然语言解释：“我怎样理解这个条件？”这句解释不仅帮助我们选指令，也能让别人看懂程序为什么这样写。

> **结论**：条件分支的正确性先由语义决定，再由指令实现。`AND` 结果的零状态看不了你真正关心的条件。

#### 常用逻辑指令不要学成“背指令”

`NOT AX` 可以把 `AX` 各位取反。

若要把 `DX` 中除最低位之外的部分清零、其余位保持不变，只要把最低位设置成“只保留自己，其余全取反”的异或掩码，再用 `XOR DX, 1` 即可。这里要抓的是指令的逻辑含义，而不是把每道题都拆成一串花哨的指令。

把 `CX` 的高 8 位和低 8 位交换，最简单的办法是用一条交换指令完成：

```asm
    xchg    ch, cl
```

有的同学会写一大段移位语句，功能上当然也能实现；既然已经学过交换指令，就应当用最直接的办法。

这些题把逻辑运算指令串了起来。最重要的是理解每一条指令改变了哪些位、保留哪些位、会不会破坏原变量，而不是只在考卷上寻找一条“刚好做过”的代码。

### 移位类指令：先分逻辑与算术

移位类指令一共八条，可以分成两组：前面四条是逻辑移位与算术移位，后面四条是循环移位。

> **定义**：如果被移位的操作数按无符号数理解，移位称为逻辑移位；如果按带符号数理解，移位称为算术移位。两种观点最终都分成左移和右移，所以这一组共有四条指令。

#### 指令格式与移位次数

逻辑左移是 `SHL`，逻辑右移是 `SHR`；算术左移是 `SAL`，算术右移是 `SAR`。它们都把目的操作数移动指定次数。移位次数 `CNT` 至少为 1；当次数为 1 时可以写在指令中，次数大于 1 时通常先送入 `CL`：

```asm
    shl     ax, 1
    mov     cl, 4
    shl     ax, cl
```

目的操作数可以是字节，也可以是字。`CNT` 规定的次数、待移位数据，通常使用通用寄存器寻址或存储器寻址。

> **易错点**：8086 中某些运算结果要经过寄存器或存储器才能继续参与运算，因为“运算结果”本身不能直接充当这类指令的操作数；所以要先把操作数送进允许的目的操作数中。

#### 一次移位到底发生什么

以字节目的操作数 `10110110B` 为例。逻辑左移一次后，位从低到高依次移动：第 0 位进入第 1 位，第 1 位进入第 2 位，依次类推；最高位被移出后送入进位标志 `CF`，最低位补 0：

```text
移位前：  1 0 1 1 0 1 1 0
             ↓ 左移
移位后：  0 1 1 0 1 1 0 0
           ↑                ↑
        最低位补 0       最高位进入 CF
```

逻辑左移一次，在无符号二进制数的一定范围内相当于乘 2。逻辑右移则相反：最高位补 0，最低位移出后进入 `CF`。

算术移位把操作数看成带符号数。以 16 位操作数为例，算术右移时，最高位就是符号位。最高位被复制到新的最高位，保持符号不变，其余各位向右移动，最低位移出后进入 `CF`：

```text
算术右移一次后的关系：

bit 15 ──→ bit 14   （最高位复制到次高位）
bit 14 ──→ bit 13
...
bit  1 ──→ bit  0
bit  0 ──→ CF       （最低位被移出）
bit 15 同时复制到 bit 15，符号保持不变
```

算术左移与逻辑左移的移动方向相同，都是各位向高位移动、低位补 0、最高位进入 `CF`。算术移位真正需要特别记住的是算术右移：它复制符号位，不能像逻辑右移那样简单地把最高位补 0。

四条指令的差别可以压缩成一张表：

| 指令 | 移动方向 | 空出来的高位或低位 | 被移出的位 |
| :--- | :--- | :--- | :--- |
| `SHL` | 左移 | 最低位补 0 | 最高位进入 `CF` |
| `SHR` | 右移 | 最高位补 0 | 最低位进入 `CF` |
| `SAL` | 左移 | 最低位补 0 | 最高位进入 `CF` |
| `SAR` | 右移 | 最高位复制原符号位 | 最低位进入 `CF` |

#### 标志位怎么理解

这四条移位指令执行后，除辅助进位标志 `AF` 外，其他五个状态标志都会按执行结果正常设置。真正需要单独解释的是溢出标志 `OF`：当移位次数为 1 时，操作数最高位发生了变化，可以据此理解数值符号是否改变；移位次数超过 1 后，虽然 CPU 仍会设置 `OF`，但再拿它判断一次移位造成的溢出就没有直接意义了。

#### 用移位代替慢的乘除法

假设要计算 $5 \times 12$。当然可以调用乘法指令：

```asm
    mov     al, 5
    mov     bl, 12
    mul     bl
```

CPU 执行后会把结果放入 `AX`。可乘、除法指令在 8086 中执行得比较慢，耗时常常是其他简单运算的十几倍甚至几十倍。为了提高程序运行速度，我们有时会故意不用乘除法指令，而把简单运算改写为移位与加法的组合。

连续相加 12 次当然也行，但题目若限定使用移位指令，就要动一点小学算术。利用乘法分配律：

$$
5 \times 12 = 5 \times (4+8) = 5 \times 4 + 5 \times 8
$$

乘 4 就是左移 2 位，乘 8 就是左移 3 位。可以先把 5 留一份，左移两次得到 $5 \times 4$，再继续左移一次得到 $5 \times 8$，最后相加：

```asm
    mov     al, 5
    mov     bl, al          ; 保留原始的 5
    shl     al, 1           ; AL = 10
    shl     al, 1           ; AL = 20，即 5 × 4
    mov     bh, al          ; BH 保存 5 × 4
    shl     al, 1           ; AL = 40，即 5 × 8
    add     al, bh          ; AL = 60，即 5 × 12
```

这比老老实实调用乘法指令多了几条指令，也占用了更多数据保存空间，但执行速度更快。程序设计里常有这种交换：用更多指令和一点存储空间，换取更快的运行速度；是否值得，就看实际性能要求。

### 循环移位：被移出的位去了哪里

普通移位把最高位或最低位送进 `CF`，另一端则补 0 或复制符号位。循环移位不一样：被移出的位还要在操作数另一端重新进入，整个操作数围成一个环。

#### 小环与大环

循环移位分为两类：不带 `CF` 的循环移位构成“小环”，被移出的位直接回到另一端；带 `CF` 的循环移位构成“大环”，原来的 `CF` 与被移出的位一起参加循环。

```text
不带 CF：小环

左移：最高位 ──→ CF，同时最高位回到最低位
右移：最低位 ──→ CF，同时最低位回到最高位

带 CF：大环

左移：最高位 → 原 CF，原 CF → 最低位
右移：最低位 → 原 CF，原 CF → 最高位
```

四条指令分别是：

| 类型 | 左移 | 右移 |
| :--- | :--- | :--- |
| 不带 `CF` 的小环 | `ROL` | `ROR` |
| 带 `CF` 的大环 | `RCL` | `RCR` |

它们的基本形式都是“对目的操作数循环移动 `CNT` 次”。`CNT=1` 可以直接写出，次数大于 1 时先送入 `CL`，约定与前面四条移位指令相同。

> **注意**：循环移位不是把进位位永久保存到某个地方，而是让 `CF` 参加每一个位的循环。每移动一次，`CF` 都会得到这一轮移出的新位。

#### 循环移位只影响两个标志

这四条循环移位指令执行后，确定有定义并有实际意义的是 `CF`，另一个是 `OF`；其余四个状态标志没有定义。做题或看状态变化时，最重要的是盯住 `CF`。

#### `RCR` 三次要把进位一起转三次

设 `BX=B6H`、`CF=1`、`CL=3`，执行：

```asm
    ; 初始条件：CF = 1
    mov     bx, 00b6h
    mov     cl, 3
    rcr     bx, cl
```

这道题故意挖了一个坑：`BX` 是 16 位寄存器，不能只写 8 位数 `10110110B` 就把它当成完整初值。`B6H` 作为 16 位数，高 8 位是 0，所以实际是 `00B6H`。

按 `RCR` 的大环逐次移动：

| 已移动次数 | `BX` | 移出的新 `CF` |
| :--- | :--- | :--- |
| 0 | `00B6H` | 1 |
| 1 | `805BH` | 0 |
| 2 | `402DH` | 1 |
| 3 | `A016H` | 1 |

因此执行后：

$$
BX = A016H
$$

不要一眼盯着草稿把 8 位数转三圈。先确认寄存器宽度、补齐高 8 位，再顺着 `CF` 参加循环的过程逐步移动。考试与作业中，读题是否认真往往比知识点本身更先决定成败；读完题，再调用知识。

#### 把 32 位数扩大 16 倍：用 `SHL` 接上 `RCR`

设 `DX:AX` 中存放一个 32 位数，要求把它扩大 16 倍。`DX` 放高 16 位，`AX` 放低 16 位。乘 16 就是连续左移 4 次。

问题在于，这组移位指令的目的操作数只有字节型和字型，不能写一条 `SHL DX:AX, 1` 让 32 位数整体移动。若只分别执行 `SHL AX, 1` 与 `SHL DX, 1`，`AX` 最高位被移出的内容会进入 `CF`，却不会自动落到 `DX`；两部分并没有真正连成一个 32 位整体。

解决办法是让 `CF` 充当中间桥梁：

```text
第 1 步：SHL AX, 1
        AX 最低位补 0，AX 原最高位进入 CF

第 2 步：RCR DX, 1
        原 CF 进入 DX 最高位
        DX 原最低位移入新的 CF
```

这样每执行一轮，`DX:AX` 就整体左移一位。规定次数后，完整过程是：

```asm
    mov     cl, 4
again:
    shl     ax, 1
    rcr     dx, 1
    dec     cl
    jnz     again
```

四轮结束后，32 位数整体扩大 $2^4=16$ 倍。这个例子把“普通移位”和“带 `CF` 的循环移位”接在了一起：先让低 16 位左移，再通过 `CF` 把溢出的那一位送进高 16 位。

### 转移指令：先看能不能改段

8086 的转移指令主要分成无条件转移和条件转移两大类。循环控制指令从本质上也是条件转移，后面会专门讲。

无条件转移里已经使用过 `JMP`，后面学习子程序时还会遇到调用与返回指令，它们同样属于无条件转移。条件转移则根据 `CMP` 等运算产生的标志决定是否跳转。

这里先补齐寻址方式。转移可以分为段内转移和段间转移：

- 段内转移只改变 `IP`，仍在当前代码段内；
- 段间转移既改变 `CS`，又改变 `IP`，因此可以跳到另一个代码段。

无条件转移可以使用段内直接、段内间接、段间直接和段间间接方式。条件转移与循环控制指令只能在段内实现短转移，也就是以当前 `IP` 为中心作相对位移，范围为 $-128 \sim +127$ 字节；在这个范围内，条件转移和循环控制采用段内直接寻址，也可称为位置相对寻址。

> **结论**：条件转移与循环控制只能在段内转移；只有无条件转移能够实现段间转移。

顺带看标志位操作指令：`CLC` 可以把 `CF` 清零，`CLI` 可以把 `IF` 清零；其余标志位控制指令按教材相应部分查看即可，这里不展开。

#### 段间直接寻址：目的地址直接写在指令里

假设程序分为代码段一与代码段二。代码段二的入口标号是 `ABC`，现在要从代码段一无条件跳到 `ABC`。

汇编程序在汇编这一条指令时，并不知道 `ABC` 最终属于近地址还是远地址。为了明确告诉汇编程序这里要按远地址处理，指令中要写出 `PTR`：

```asm
    jmp     far ptr abc
```

这条指令的指令格式为：

```text
EA  OPCODE  OFFSET(2 bytes)  SEGMENT(2 bytes)
│     │           │                │
│     │           └── 目标偏移地址，送入 IP
│     └────────────── 目标段地址，送入 CS
└──────────────────── 段间无条件转移操作码
```

完整指令共 5 个字节：1 字节操作码，加上 4 字节目的地址。它也是 8086 指令系统中最长的指令。

CPU 取到操作码后就知道这是段间转移；接着从操作码后的字单元取出偏移地址送给 `IP`，再从下一个字单元取出段地址送给 `CS`，于是 `CS:IP` 一起指向目的标号。

```text
                    EA 操作码
                        │
                        ▼
        目标偏移地址 ───────→ IP
        目标段地址   ───────→ CS

                    CS:IP
                        │
                        ▼
               代码段二的 ABC
```

从指令书写格式看，目的地址直接写在指令中；从 CPU 的实际转移过程看，目的偏移地址和段地址也都直接给出了。因此它只能叫“段间直接寻址”，不能再套一个“相对”寻址。

#### 段间间接寻址：先找到存放地址指针的单元

还可以事先在数据段中定义一个 32 位远地址指针。假设 `ABC` 是代码段二中的标号，用 `DD` 定义双字单元 `table`：

```asm
table   dd      offset abc, seg abc
```

`table` 的第一个字单元存放 `ABC` 的偏移地址，第二个字单元存放 `ABC` 的段地址：

```text
table 的 32 位内容
┌────────────────────┬────────────────────┐
│ OFFSET ABC         │ SEG ABC            │
│ 16 位偏移地址      │ 16 位段地址        │
└────────────────────┴────────────────────┘
```

从代码段一执行下面这条指令：

```asm
    jmp     dword ptr table
```

CPU 先用直接寻址方式找到 `table` 单元，再从该单元取第一个字送给 `IP`，取第二个字送给 `CS`，完成段间间接转移。

```text
代码段一
   │
   │  JMP DWORD PTR table
   ▼
找到数据段中的 table
   │
   ├── 第一个字 → IP
   └── 第二个字 → CS
                    │
                    ▼
              代码段二的 ABC
```

还可以用寄存器间接寻址。先用 `LEA BX, TABLE` 取得 `table` 的偏移地址，再让 `BX` 指向这个双字单元：

```asm
    lea     bx, table
    jmp     dword ptr [bx]
```

这里 `BX` 指向的是“远地址指针所在的双字单元”。`JMP` 从该双字单元中取 4 字节：低地址送 `IP`，段地址送 `CS`。所以无论先通过变量名找这个单元，还是先通过 `BX` 找这个单元，本质都是段间间接寻址。

> **定义**：段间直接寻址，是目的地址指针直接包含在指令中；段间间接寻址，是指令先找到存放目的地址指针的单元，再从该单元取出 `IP` 与 `CS` 的新值。

> **易错点**：`PTR` 写错类型，汇编器就不知道这里给出的是 16 位地址指针还是 32 位远地址指针。远转移需要双字形式，不能只把偏移地址送进 `IP` 却忘了段地址。

### 循环控制与 `LOOP`

8086 的循环控制指令共有四条，其中最常用的是 `LOOP`。它在循环程序设计中非常常见，执行过程只有两步：

1. `CX ← CX - 1`；
2. 若减一后的 `CX` 不为 0，就转移到指定标号继续循环；否则顺序执行下一条指令。

语法是：

```asm
loop    label
```

```text
进入 LOOP
    │
    ▼
CX ← CX - 1
    │
    ├── CX ≠ 0 ──→ 跳到 label，继续循环
    │
    └── CX = 0 ──→ 不跳转，退出循环
```

> **易错点**：`LOOP` 的减一和判断都不影响标志位。不要把前面用 `CMP` 或逻辑运算设置标志的条件转移方式，原封不动套到 `LOOP` 上。`LOOP` 直接看减一后的 `CX`。

#### `CX` 初始化必须考虑计数边界

循环控制程序一开始就要做初始化。初始化不仅包括地址指针和普通常量，还包括循环次数。

使用 `LOOP` 时，`CX` 是减法计数器。16 位计数器的最大初值是 `FFFFH`：

- 若 `CX` 初值为 `0000H`，第一次执行 `LOOP` 就先减成 `FFFFH`，结果不为 0，因此会转一圈；总共可循环 $2^{16}=65536$ 次；
- 若 `CX` 初值为 `FFFFH`，第一次减一后变为 0，因此只循环 1 次。

> **提示**：计数初值是 0 还是 `FFFFH`，看起来只差一点，实际循环次数却相差 65536 倍。写循环之前一定先算清楚“第一次判断发生在减一之后”。

#### 一个循环程序先想清三件事

循环程序通常包含三个部分：

```text
初始化
  ├─ 循环次数放入 CX
  └─ 地址指针、数据初值准备好
          │
          ▼
循环工作体
  ├─ 完成本轮规定的功能
  └─ 更新参数或地址指针，指向下一项数据
          │
          ▼
LOOP 回到工作体；CX 为 0 时退出
```

进入循环前，要先做初始化；循环工作体中完成某项功能；本轮结束后，还要更新参数或地址指针，让下一轮能够处理下一个数据。把这三件事分清楚，循环次数、数据位置和推进方向才不会混乱。

### 本讲提到的题目

#### 用移位指令实现 $5 \times 12$

**题干**：不使用乘法指令，利用移位与加法计算 $5 \times 12$。

**解析**：把 12 分解为 $8+4$：

$$
5 \times 12 = 5 \times 4 + 5 \times 8
$$

左移 2 位得到 $5 \times 4$，左移 3 位得到 $5 \times 8$。先保留原始的 5，把其中一项保存在另一个通用寄存器中，另一项继续左移，最后相加。

**答案**：`AL` 最终为十进制 60，即 `3CH`。

#### 执行 `RCR BX, CL`

**题干**：已知 `BX=00B6H`、`CF=1`、`CL=3`，CPU 执行 `RCR BX, CL` 后，`BX` 等于多少？

**解析**：`RCR` 把 `CF` 与 `BX` 构成大环。`BX` 是 16 位寄存器，所以 `B6H` 必须补成 `00B6H`。第一次移动后为 `805BH、CF=0`；第二次为 `402DH、CF=1`；第三次为 `A016H、CF=1`。

**答案**：

$$
BX=A016H
$$

#### 把 `DX:AX` 中的 32 位数扩大 16 倍

**题干**：`DX:AX` 存放一个 32 位数，要求只使用移位类指令把它扩大 16 倍。

**解析**：乘 16 等于连续左移 4 次。先执行 `SHL AX, 1`，让 `AX` 最高位进入 `CF`；再执行 `RCR DX, 1`，让原 `CF` 进入 `DX` 最高位，同时继续把 `DX` 原最低位送入下一轮 `CF`。每轮使 `DX:AX` 整体左移一位，共执行 4 轮。

**答案**：

```asm
    mov     cl, 4
again:
    shl     ax, 1
    rcr     dx, 1
    dec     cl
    jnz     again
```

执行后，`DX:AX` 中原来的 32 位数扩大为原来的 16 倍。

## 循环控制、校验和与平均滤波
> 对应块：BLK22 | 覆盖分集：P43-P44 | 块标题（分集名）：《43》

连续听几节课，脑子里还是那几条指令在转，循环到底由什么控制、结果放在哪里、为什么要先判断再工作，似乎还没有真正连起来。先换一种口味，把循环控制指令放下，做两道循环程序设计题。等校验和和平均滤波写完，再回头看 `LOOP`、`LOOPZ`、`LOOPNE` 和 `JCXZ`，它们就不是孤立的字母，而是一套可以反复使用的控制骨架。

### 循环控制：先有骨架，再填功能

在循环结构中，显然要用一条 `LOOP` 指令控制循环。假设循环标号是 `L1`，`CX` 中预先放好循环次数。循环体工作一次，`LOOP L1` 就让 `CX` 减 1；只要 `CX` 还不为零，便跳回 `L1`，重新执行循环体；减到零时，程序才退出循环。

所以，`LOOP` 做的事情可以概括为：

```text
CX ← CX - 1
CX ≠ 0 ──是──> 跳回循环标号
       │
       否
       ↓
     退出循环
```

`LOOP` 本身不负责把结果送到哪里。退出循环体以后，程序还要决定结果是否已经处理、是否还要打印或送到屏幕上。这一步不能因为循环结束就丢掉。

#### 四个组成部分

一个完整的循环程序至少包括初始化、循环工作、循环控制和结果处理四部分。循环次数已知时，它们的顺序通常是固定的：

```text
        ┌─────────────────────────────┐
        │                             │
        ↓                             │
     初始化                          循环控制
        ↓                             │
   循环工作 ──────────────────────────┘
        │
        │ 退出
        ↓
     结果处理 → 程序结束
```

初始化要准备好地址指针、计数器和累加器等变量；循环工作每次完成一小步任务；循环控制决定下一轮是否继续；循环结束以后再把结果保存或送到输出位置。如果每轮循环已经把结果处理完，最后的“结果处理”就可以不再重复。

> **定义**：循环程序的标准骨架是“初始化—循环工作—循环控制—结果处理”。具体功能可以变化，但这四部分不能因为换了题目就随意丢掉。

#### 结果处理可以放在哪里

循环中如果已经产生了结果，就要明确它存在哪里。可以在循环体里逐次处理，也可以在循环全部结束后统一处理。

如果每次循环都把当前结果输出，那么循环退出后就不必再输出一次；如果循环体只负责累加或查找，最后统一把结果送到屏幕上，退出后就要补上结果处理。程序没有其他功能时，最后以 `MOV AH,4CH` 和 `INT 21H` 结束；还有其他功能，就继续完成后续任务。

这四条不是形式上的口号。尤其是“结果处理”这一栏，题目问的是最后得到什么，程序就必须把那个结果放到题目指定的位置，不能只让寄存器里“看起来算过”。

### 复合循环控制：把 `ZF` 放进循环条件

`LOOPZ` 与 `LOOPE` 是同一条指令的两种写法。执行时先把 `CX` 减 1，减 1 后的差值送回 `CX`，再检查两个条件：`CX` 不等于零，并且 `ZF=1`。两个条件同时满足，就跳到标号指定的循环起点；只要有一个不满足，就退出循环。

`LOOPNE` 与 `LOOPNZ` 也是等效写法。它同样是先 `CX-1`，但继续循环的条件变成 `CX` 不等于零并且 `ZF=0`。

这里的 `Z` 就是零标志。`CMP` 比较两个数，结果相等时把 `ZF` 置 1；结果不等时把 `ZF` 清 0。因此，复合循环指令把“计数器是否用完”和“刚才的比较结果是什么”合在了一起。

| 指令 | `CX-1` 后继续循环的条件 | 典型用途 |
| :--- | :--- | :--- |
| `LOOPZ` / `LOOPE` | `CX≠0` 且 `ZF=1` | 查找不同字符 |
| `LOOPNE` / `LOOPNZ` | `CX≠0` 且 `ZF=0` | 查找指定字符 |

> **注意**：`CX` 减 1 这一步不影响标志位。也就是说，复合循环指令检查的 `ZF` 来自它前面的 `CMP`，不是 `LOOPZ` 或 `LOOPNE` 自己重新计算出来的。要让比较结果参与循环，就必须先执行比较。

#### 查找不同字符

这类指令适合在指定存储区域中查找不同字符：发现不同字符时自动退出循环；如果没有发现，就继续检查。

例如，数据段中有一个由若干个相同字符组成、末尾跟着一个不同字符的字符串。程序首先要解决一个很朴素的问题：字符串到底有多少个字符。不能一个、两个、三个地手数，字符串长了以后更不能一直数下去。科学办法是用当前汇编位置减去字符串起始标号：

```asm
STRING  DB '1111112'
LEN     EQU $-STRING
```

`$` 表示当前汇编位置，`$-STRING` 的值就是从 `STRING` 开始到当前位置之间的字节数。符号常量并不占用存储单元，也没有一个可以读取的内存地址；它只是在汇编时给出一个确定的值。

查找时，`SI` 指向当前待检查的字节，`CX` 放字符个数。核心步骤可以写成：

```asm
        MOV  SI, $-1
        MOV  CX, LEN
AGAIN:  INC  SI
        MOV  AL, [SI]
        CMP  AL, '1'
        LOOPZ AGAIN
```

这里把 `SI` 初始化为 `$-1`，是因为进入循环体后先 `INC SI`，`SI` 才会正好指向字符串的第一个字符。读完一个字节后比较它和指定字符是否相同；相同就继续，不同就退出。

退出循环后还要看结果。`LOOPZ` 退出有两种可能：一是 `CMP` 得到 `ZF=0`，说明当前字符不同，已经找到了；二是 `CX` 已经减到零，说明整个字符串检查完了，仍没有发现不同字符。因此，`ZF=0` 可以判定“找到了”，`ZF=1` 则是“检查完而没有找到”。

如果找到后还要知道字符在字符串中的位置，`SI` 中保存的就是相对于字符串起始位置的位移量。这里一定要把地址、指针和位移量分清楚，不能只说“找到了一个地址”却不知道它相对于哪里。

#### 查找指定字符

`LOOPNE` / `LOOPNZ` 的判断方向正好反过来。假设要找字符 `'2'`，每轮把当前单元的内容送入 `AL`，再与 `'2'` 比较：

- 比较不等，`ZF=0`，并且 `CX` 还没用完，就继续查找。
- 比较相等，`ZF=1`，退出循环，说明找到了指定字符。
- 如果一直没有相等，直到 `CX` 减到零才退出，最后的 `ZF=0`，说明没有找到。

所以，找到指定字符以后不能只看“循环退出了”，还要看退出时 `ZF` 的值。退出循环是位置条件，`ZF` 才是结果条件。

> **易错点**：`LOOPZ` 是在“比较相等”时继续，`LOOPNE` 是在“比较不等”时继续。把这两种方向选反，程序查的就不是同一个目标了。

### `JCXZ`：把零次循环拦在门外

有些循环在开始时就没有工作可做。这时，`CX` 一开始就是 0。如果直接执行 `LOOP`，16 位计数器会从 0 减 1，变成 `$FFFFH`，不能指望它立刻判断为零，反而可能绕一大圈才退出。

所以在进入循环前先放一条 `JCXZ`：

```text
CX = 0 ──JCXZ EXIT──> 退出，不做循环
  │
  └─CX ≠ 0──> 进入循环体
```

`JCXZ` 只检查 `CX` 是否为零；为零就跳到目标标号，不为零就顺序执行下一条指令。它不负责把计数器用掉，而是在循环开始前拦截“根本没有数据”的情况。

后面两点平均滤波的例子就会用到它：先从数据区读出数据个数 `n`，放进 `CX`，马上用 `JCXZ EXIT` 判断。如果 `n=0`，直接跳到出口；如果 `n≠0`，才设置源数据地址和结果地址，进入循环。

> **结论**：循环次数可能为零时，先用 `JCXZ` 判断；循环次数已知且至少要执行一次时，才可以直接把工作放在 `LOOP` 之前。

### 校验和：把一串字节压缩成一个核对值

换一道题：在 `BUFF` 变量对应的存储单元中，放着 15 个无符号字节型数据。编写程序求这 15 个字节的校验和，并把结果放入第 16 个字节单元。

#### 奇偶校验之外，还要核对整批数据

校验和主要用于数据通信，尤其是串行通信。发送方发送数据时，接收方常采用奇校验或偶校验：每发送一个字节，就检查数据中“1”的个数是奇数还是偶数。

但是，单纯采用奇偶校验，不能保证接收方收到的每一个字节都正确。线路上的干扰仍可能造成数据错误。于是在奇偶校验之外，发送方还要对数据求一个和；接收方收到数据后也做同样的累加，最后把两边结果比较。两个结果相等，接收方就认为这批数据接收正确；不相等，就说明数据可能受到了干扰。

```text
发送方：数据字节 ──> 累加 ──> 数据结束 ──> 附加最终校验和
                                      │
                                      └──> 接收方

接收方：数据字节 ──> 累加 ───────────────> 与附加校验和比较
```

读图时抓住两条线：发送方和接收方都对收到的字节做同样的累加，发送方再把最终累加结果交给接收方，接收方比较的是“自己算出的结果”和“对方给出的结果”。

校验和的作用是提高整批数据传输的正确率，不是简单地再数一遍“1”的个数。

#### 字节序列的低 8 位累加

本题中的校验和，就是 15 个无符号字节数值相加后的低 8 位。加法过程中即使产生了进位，也直接丢弃，不把进位接到下一个字节上。

数据区可以按下面的关系安排：

```text
BUFF:  [第 1 字节] [第 2 字节] … [第 15 字节] [第 16 字节]
         数据 1      数据 2       数据 15      校验和 SUM
```

循环程序先把地址指针、计数器和累加器准备好，再逐个读取 15 个字节。用 8 位寄存器做加法时，`ADD` 的结果只保留 8 位，正好符合“不进位”的题意；每加完一个字节，地址指针移动到下一个单元，计数器减 1。

把讲过的初始化、循环和结果保存步骤写成最小的 8086 汇编骨架如下：

```asm
DATA SEGMENT
    BUFF    DB 15 DUP(?)
    SUM     DB ?
DATA ENDS

CODE SEGMENT
    ASSUME CS:CODE, DS:DATA
START:
    MOV     AX, DATA
    MOV     DS, AX
    MOV     SI, OFFSET BUFF
    MOV     CX, 15
    MOV     AL, 0

AGAIN:
    ADD     AL, [SI]
    INC     SI
    LOOP    AGAIN

    MOV     BYTE PTR SUM, AL
    MOV     AH, 4CH
    INT     21H
CODE ENDS
END START
```

这段程序的关键不在字母本身，而在每一步和循环骨架的对应关系：

- `SI` 从 `BUFF` 的偏移地址开始，指向第一个待累加的字节。
- `CX` 装入 15，决定循环恰好执行 15 次。
- `AL` 先清零，作为累加器。
- 循环体每次把 `[SI]` 加到 `AL`，然后 `SI` 指向下一个字节。
- `LOOP` 让 `CX` 减 1，归零后进入结果处理。
- 第 16 个单元是 `SUM`，最后把 `AL` 的低 8 位保存进去。
- `MOV AH,4CH` 和 `INT 21H` 结束程序。

这道题一写完，循环程序的固定结构就非常清楚了：前面准备地址、计数器和累加器，中间重复做 15 次加法，循环退出后保存结果。不能把 `SUM` 混进前 15 个待累加的数据里，否则累加的就不再是题目规定的 15 个字节。

考试中遇到 8086 汇编程序设计题，先分析题目、提出算法，再写代码；题目要求画流程图时，再把程序流程画出来。即使后面的具体算法没有完全写对，清楚的源程序结构也能说明你理解了 8086 程序的基本组成，评分时不会一分不得。不要只会把“帽子”戴上，下面却什么也写不出来。

### 两点平均滤波：把相邻数据组成新序列

另一道题把输入放在 `BUFF` 区域中：这个区域的第一个字单元保存数据个数 `n`，后面依次保存 `X_1、X_2、…、X_n` 共 `n` 个 16 位字数据。要求计算相邻两个数据的平均值，把结果存放到 `FILT` 缓冲区。

这里要注意输出的数量。`n` 个数据只能组成 `n-1` 对相邻数据：

$$
Y_i=\frac{X_i+X_{i+1}}{2},\qquad 1\le i<n
$$

因此，`FILT` 区域需要预留 `n-1` 个字单元，而不是 `n` 个。数据布局可以表示为：

```text
BUFF:  [n] [X1] [X2] [X3] … [Xn]
FILT:  [Y1] [Y2] [Y3] … [Y(n-1)]
```

`n` 不在指令里写死，而是由数据区第一个字单元给出。这样，程序先要知道“到底有多少数据”，才能决定循环多少次、结果区要处理多少个单元。

#### 为什么要进行平均滤波

两点平均滤波属于软件滤波思想。前面学过硬件滤波，例如有源滤波、无源滤波和 LC 滤波；软件也可以完成类似的工作。

在数据采集系统中，模拟量经过 A/D 转换器采集、变换，再把数据送到后续电路或存入内存。但外界干扰会影响模拟量，逻辑量的变化速度也可能使一次采集结果不能代表真实情况。于是，对同一点连续采集若干次，再把这些数据求平均，得到较稳定的滤波结果。有些场合会取三次、四次，甚至更多次数据进行平均；本题只取相邻的两个字数据作为一组。

“相邻”不是把整个数组从头到尾两两随意配对，而是按原顺序取 `X_1` 与 `X_2`、`X_2` 与 `X_3`，一直处理到 `X_{n-1}` 与 `X_n`。每得到一个平均值，就把它顺序写入 `FILT`，同时把源地址和结果地址各移动一个字。

#### 用 `JCXZ` 和标准骨架完成计算

程序的准备工作有四步：让 `SI` 指向 `BUFF` 的第一个字，读取其中的数据个数并送入 `CX`，用 `JCXZ` 判断 `n` 是否为零；若不为零，再让 `SI` 越过存放个数的第一个字，指向 `X_1`，同时让 `DI` 指向 `FILT` 的第一个结果单元。

之后每次循环完成这样一组工作：

1. 取出一个当前字数据和它后面的一个字数据。
2. 把两个字相加。
3. 把和右移一位，相当于除以 2。
4. 把平均值写入 `FILT` 当前单元。
5. 源地址和目的地址各前进一个字，继续下一对。

`n` 个输入产生 `n-1` 个结果，所以进入成对计算前，循环次数还要按 `n-1` 安排。若 `n=0`，`JCXZ` 直接跳到出口，不必访问一个并不存在的相邻数据；若 `n=1`，没有可配成的数据对，结果区也不写入平均值。

右移一位为什么能完成除以 2？把字数据看作二进制数，右移一位就是把整个数向小数方向移动一位；在本题的整数处理中，它实现了两数和除以 2 后的结果。计算结果写到 `FILT` 后，源数据和结果数据不能混淆：`SI` 负责在 `BUFF` 中向后走，`DI` 负责在 `FILT` 中向后写。

这道题和前面的校验和题，表面上处理的数据不同，程序骨架却完全相同：

```text
读取个数并检查 → 初始化地址 → 循环处理一组数据 → 保存结果 → 结束
```

所以，程序设计不是先盯着某一条指令背，而是先把题目归纳成这五步，再决定每一步由哪些指令完成。

### 先判定还是先工作

前面两道题都是先把循环体的工作做一次，再由 `LOOP` 判断计数是否用完，这属于“先循环工作，后循环判定”。但在有些程序中，循环次数在开始时就可能为零，这时应当先判断，再决定要不要进入循环体，也就是“先循环判定，后循环工作”。

看一个 16 位数据处理的例子：要求统计 `BX` 中有多少个二进制位为 1。

`BX` 一共有 16 位，因此固定处理 16 次。初始化时把循环次数设为 16，把结果寄存器 `AX` 清零。每一轮把 `BX` 右移一位，原来最低位移出的那一位进入进位标志 `CF`：

- `CF=0`，说明移出的这一位是 0，不增加计数。
- `CF=1`，说明移出的这一位是 1，把 `AX` 加 1。
- 然后执行 `LOOP`，再检查下一位。

核心控制可以写成：

```asm
        MOV     CX, 16
        MOV     AX, 0
COUNT_BITS:
        SHR     BX, 1
        JNC     NEXT_BIT
        INC     AX
NEXT_BIT:
        LOOP    COUNT_BITS
```

`SHR` 使 `BX` 的各位逐次向右移动，最低位依次进入 `CF`。`JNC` 是“没有进位”时跳转，也就是当前移出的位为 0 时跳过 `INC AX`。但无论这一位是 0 还是 1，最后都要落到 `LOOP`，这样 16 次循环才会完整执行。

循环结束时，`AX` 中保存的就是 `BX` 中 1 的个数。这里的判断和计数很简单，关键是要理解：`CF` 记录的是刚刚移出的那一位，`SHR` 同时把 `BX` 改成下一轮要检查的状态。

回到“先判定还是先工作”这个问题：当数据个数由 `BUFF` 给出、可能等于 0 时，先用 `JCXZ` 判定；当次数固定为 16、至少要做 16 次时，可以先做一次 `SHR` 和判断，再用 `LOOP` 控制后续轮次。顺序不是死的规定，要由题目是否允许零次工作来决定。

### 本讲提到的题目

#### 无符号字节数据的校验和

在 `BUFF` 变量对应的存储单元中，放有 15 个无符号字节型数据。编写程序求这 15 个字节数据的校验和，并把它存入第 16 个字节单元。

解析：校验和是 15 个字节相加后的低 8 位，不保留进位。初始化时令 `SI` 指向 `BUFF`、`CX=15`、`AL=0`；循环体执行 `ADD AL,[SI]`，再令 `SI` 指向下一个字节；`LOOP` 使循环执行 15 次。最后把 `AL` 保存到紧接 `BUFF` 后的 `SUM` 单元。

答案：程序执行完成后，`SUM` 中保存 15 个数据之和的低 8 位。题目没有给出 15 个数据的具体数值，因此这里不能凭空写出唯一的数值结果。

#### 字数据的两点平均滤波

在 `BUFF` 对应的存储单元中，前两个字保存数据个数 `n`，后面保存 `X_1` 到 `X_n` 共 `n` 个字数据。求相邻两点的平均值，并把结果存入 `FILT` 缓冲区。

解析：先把第一个字中的 `n` 读入 `CX`，用 `JCXZ` 排除零次处理；再让源指针指向 `X_1`，目的指针指向 `FILT`。每次读取相邻两个字，相加后右移一位，写入一个结果单元。`n` 个输入只有 `n-1` 对相邻数据，因此结果区有 `n-1` 个字单元。

答案：对于 $1\le i<n$，`FILT` 的第 $i$ 个字为 $Y_i=(X_i+X_{i+1})/2$；当 `n=0` 时直接退出，不产生滤波结果。

#### 什么时候先判定循环

什么时候循环结构要先判定、后工作？

答案：当初始数据个数可能为 0、或者循环体在没有数据时不能执行时，先用 `JCXZ` 等条件转移判断，再进入循环。次数已知且保证至少执行一次时，可以先完成循环体工作，再用 `LOOP` 控制下一轮。`JCXZ` 的价值就在于不让零次循环白白执行。

## 循环判定与 8086 子程序的完整链条
> 对应块：BLK23 | 覆盖分集：P45-P46 | 块标题（分集名）：《45》

先把前面那个 16 次循环收尾。表面上，程序把一个 16 位数据处理完，结果似乎没有什么不对；可是最坏的情况是 `BX` 一开始全为零，CPU 仍然会把十六次循环全部做完，最后得到的还是零。结果没有错，时间却白花了，这正是我们讨论程序效率的入口。

还有一种情况更明显：数据是 `00000000010` 这样的形式时，前面的移位可能还没有让结果发生变化；真正有效的位处理完以后，`BX` 就变成零了，后面的 14 次循环已经没有继续工作的必要。若仍然采用“先把循环体做完，再回头判断”的结构，程序就会把无效工作做完。

> **易错点**：循环次数固定，并不代表每一次循环都值得执行。只要中途已经能够确定“再算下去也不会改变结果”，就应该尽早停下来。

### 先判定，还是先循环工作

原来的结构可以概括为“先循环工作，后判定”：

```text
初始化
   ↓
循环体：处理一次数据
   ↓
计数或条件判定 ──否──→ 回到循环体
   │
   └─是──────────────→ 结束
```

这种结构能够完成功能，但它隐含了一个前提：每次进入循环体都是有意义的。数据已经为零时，循环体仍然会执行移位；移出的进位没有新的有效数据，计数还要继续减一，十六次之后当然能得到零，只是效率很差。

提高效率的办法，是把“数据是否已经处理完”的判定放到循环工作之前：

```text
初始化
   ↓
CMP BX, 0
   ├─相等──────────────→ 结束
   └─不相等
          ↓
       SHR BX, 1
          ↓
       根据进位更新结果
          ↓
       计数减一
          ↓
       回到 CMP BX, 0
```

先用 `CMP` 把 `BX` 和零比较。如果结果相等，提前退出；如果不相等，再把 `BX` 向右移一位，根据移出的进位把相应结果加一，然后让计数减一，再回到判定处。等 `BX` 在移位过程中变成零，下一次判定就会直接离开循环，不必把剩余次数跑完。

这就是“先判定，后循环工作”。它和原来的“先工作，后判定”是两种不同的循环结构，不是把两条指令换个位置就结束。设计循环程序时，要先问两个问题：循环一开始就可能进入无效工作吗？循环进行中有没有可能提前完成？只要存在这两种可能，就应该优先考虑先判定、后工作；如果整个循环确实不会提前结束，后判定结构也可以使用。

不管选择哪一种结构，循环程序都要想清楚几块内容：初始化做什么，循环体完成什么，计数或条件怎样改变，以及退出判定放在哪里。只盯着“最后结果对不对”还不够，还要问一句：结果已经确定以后，程序为什么还要继续工作？

### 从循环题转到 3.11 节和 4.5 节

书上有一个把某项功能设计成子程序的例子，位置在子程序相关内容的 3.11 节，讲到子程序调用与返回指令，页码落在 69 页。4.5 节则讲子程序设计技术。我们把 3.11 和 4.5 放在一起看，正好把“为什么要把功能拆出去”和“子程序怎样定义、怎样调用和返回”连成一条线。

这里只把书上的例子和章节位置点出来，完整题干、输入条件和输出要求并没有在本段展开，所以不替它补写缺失条件。真正需要从例子中掌握的是：先判断循环是否可能提前结束，再考虑程序是否应该模块化；当功能交给子程序以后，返回地址、现场信息和参数约定都要设计清楚。

### 子程序就是可调用的功能模块

我们在 C 语言里学过函数：把完成一个特定功能的那段程序单独定义起来，程序需要这个功能时，就调用函数。8086 汇编中的子程序，采用的是同一思路；它也常被称为“过程”，定义过程和调用过程，说的都是把一个功能从主流程中独立出来。

程序中经常出现、完成同一个特定功能的那段代码，可以定义成子程序。需要这个功能时，用子程序调用指令跳过去执行，执行完再回到原来的程序继续往下走。这里使用的主程序是“调用程序”，实际完成那段功能的程序是“被调用程序”，也就是子程序。角色不由代码写在前面还是后面决定，而由谁发出 `CALL` 决定。

实际工程中，即使某个功能在整个程序里只用一次，也应该尽量考虑把它定义成子程序。这里的“尽量”很重要，不是说每一行代码都必须机械地拆开，而是只要程序由多个不同功能组成，就让一段程序只负责一件事。这样主程序会变得很清楚：初始化完成以后，依次调用几个功能模块；每个模块各自完成自己的任务，调用结束后再回到主程序的下一条指令。

```text
主程序（调用程序）
  初始化
     ↓
  CALL 功能 A ──→ 子程序 A
     ↓
  CALL 功能 B ──→ 子程序 B
     ↓
  CALL 功能 C ──→ 子程序 C
     ↓
  结束
```

这样做的好处，不只是程序看起来整齐，而是维护和升级的范围可控。给某个单位设计的软件交付以后，原来运行得很好，使用人员后来又提出增加一个功能。如果一开始没有采用子程序模块，就可能要在长长的数据处理和控制流程中到处插入新内容，改动一个地方，其他原本正常的功能也可能被破坏。如果原来就是模块化的，只要在下面增加一个新的子程序，再在主程序中增加一条 `CALL`，升级和维护就清楚得多。

当然，模块化也有代价。每调用一个子程序，要执行一条 `CALL`；子程序执行完，还要执行返回指令，这两条指令都会花时间。只有在分析整个系统后，确认这点时间不会影响系统性能，程序才应该尽量模块化；特别敏感的地方再针对局部做优化。

### 用 PROC 和 ENDP 定义过程

子程序的概念清楚了，接下来就是它在汇编语言中的写法。`PROC` 表示过程开始，`ENDP` 表示过程结束，它们是过程定义用的伪指令，用来告诉汇编程序：这里有一段有名字、有边界的程序。

一个近过程的基本形状是：

```asm
SUB1 PROC NEAR
    RET
SUB1 ENDP
```

过程体的指令写在 `PROC` 后面、`ENDP` 前面。`RET` 前面才是完成这个子程序特定功能的指令；上面的短例只保留定义和返回的骨架，不代表每个子程序都只有一条返回指令。

`PROC` 左边要写子程序名，`ENDP` 左边也必须写同一个名字：

```asm
DISPLAY PROC NEAR
    RET
DISPLAY ENDP
```

过程名的写法和标号名、变量名遵循相同规则，首字符应当用字母，而且名字最好能表达功能。比如某段程序完成“把结果显示到屏幕上”这样的工作，看到名字就能大致知道它做什么；随手写成 `A1`、`B2`，自己当时可能记得，过一段时间维护就很容易认错。还有一个很实际的提醒：`SUB` 本身是减法指令的名字，子程序名不要正好叫 `SUB`，加一个数字写成 `SUB1` 就没有这个混淆。

过程名还具有三个属性，这一点和标号名的属性是相通的：

- 段基址属性：说明这个过程属于哪个代码段；
- 段内偏移地址属性：指向过程体第一条指令的地址；
- 类型属性：说明它是近过程还是远过程。

`PROC` 后面的类型参数有两种。调用指令和子程序在同一个代码段时，类型是 `NEAR`，也叫近过程；按照本讲的写法，`NEAR` 可以省略。如果调用指令和子程序不在同一个代码段，就要定义远过程，类型写成 `FAR`，这个 `FAR` 不能省略。远过程通常要放在另一个代码段中，代码段的开始和结束也要明确写出来。

```text
代码段一：调用程序所在段
  CALL 远子程序
  ...

代码段二：被调用过程所在段
  SUB1 PROC FAR
      过程体
      RETF
  SUB1 ENDP
```

过程体完成特定功能以后，要用返回指令结束。近过程用 `RET`；远过程用 `RETF`。执行返回指令，CPU 才能回到刚才调用指令下面的那一条指令，而不是简单地跳回过程体的开头。在这讲的写法中，远过程的 `RETF` 也可以写成 `RET`；汇编程序看到 `PROC` 后面标明了 `FAR`，就会按远过程生成对应的返回代码。

`PROC` 和 `ENDP` 必须配对，两个指令左边的过程名必须一致，过程体内部还要有正确的返回指令。这几件事分别承担不同任务：`PROC` 告诉汇编程序过程从哪里开始，过程名让调用处能够找到它，`ENDP` 告诉汇编程序过程到这里结束，返回指令让 CPU 知道怎样回到调用者。

### 从 START 进入主程序，再用 CALL 交给子程序

为了把定义和调用放在一起看，可以先保留一个程序骨架。为了说明流程，堆栈段和数据段有时可以暂时不写；但只要真正执行 `CALL`，堆栈以及 `SP` 的初始化就不能省略。子程序体可以放到主程序下面，主程序仍然要明确标出 `START`，表示程序从哪里开始。

```asm
CODE SEGMENT
    ASSUME CS:CODE
START:
    ...
    CALL SUB1
    ...
    MOV AH, 4CH
    INT 21H
CODE ENDS
END START

SUB1 PROC NEAR
    ...
    RET
SUB1 ENDP
```

这里 `START` 是主程序的入口。主程序初始化以后，遇到 `CALL SUB1`，就转去执行 `SUB1` 的过程体；`RET` 执行完以后，又回到主程序中 `CALL` 后面继续执行。`MOV AH, 4CH` 和 `INT 21H` 在这里是程序结束处的处理，主程序执行到这里就结束。

`CALL` 的寻址方式可以采用直接寻址，本讲主要用直接调用来说明；也可以采用间接寻址。直接调用把目标子程序的名字直接写在指令中，间接调用则通过寄存器或存储器等位置取得目标地址。实际中直接调用更常见，间接调用虽然也能实现，但不是本段要展开的重点。

### 近调用怎样保存返回地址

子程序定义好以后，调用并不是简单地跳到过程入口。跳过去容易，难点是子程序执行完以后，怎样准确回到调用它的下一条指令。这个问题的答案就在堆栈。

近调用发生在同一个代码段内，所以 `CS` 不变，改变的是 `IP`。在执行 `CALL` 以前，CPU 知道当前指令位置，也知道这条调用指令执行完以后应该从哪一条指令继续。为了返回，`CALL` 必须先把返回地址保护起来。由于 8086 的字是一个字节之外的两个字节，栈顶指针先减 2，腾出一个字的空间，再把返回地址压入堆栈。

```text
执行 CALL 之前
  CS:IP 指向 CALL 指令所在位置

执行 CALL
  SP ← SP - 2
  [SS:SP] ← 返回地址（IP，即 CALL 后的下一条指令）
  IP ← IP + 16 位相对位移量
  CS 不变
  开始执行子程序体

执行 RET
  IP ← [SS:SP]
  SP ← SP + 2
  回到 CALL 后面的下一条指令
```

这里的 `SS:SP` 指向堆栈中保存返回地址的位置。`CALL` 先让 `SP` 减 2，再把当前返回地址对应的 `IP` 放进去；过程体执行 `RET` 时，从这里取出 `IP`，然后让 `SP` 加 2，堆栈恢复到调用前的状态。

直接寻址时，汇编程序要根据当前 `IP` 和一个 16 位相对位移量算出过程入口。这个相对位移量是从调用位置到目标位置之间的字节差；目标入口由 `IP` 加上这个位移量得到。相对位移量本身是 16 位的，所以汇编时要按其表示范围处理。

把近调用连起来记，就是四步：

```text
保存返回地址
      ↓
改变 IP，进入子程序
      ↓
执行过程体
      ↓
从堆栈取回 IP，回到主程序
```

只要把这四步和 `CS` 不变这一点抓住，就不会把“跳到子程序入口”和“从子程序返回”混成一件事。返回地址保护的是调用指令后面的位置，不是过程体的入口；`CALL` 和 `RET` 必须前后配合。

### 远调用为什么还要保护 CS

如果调用程序和子程序不在同一个代码段，单保存一个 `IP` 就不够了。返回时不仅要找到调用指令后面的段内偏移地址，还要知道应该回到哪个代码段，所以远调用要保护完整的 `CS:IP`。

远调用的压栈顺序是：`CS` 先入栈，`IP` 后入栈。栈向低地址方向增长，因此调用完成以后，最靠近 `SP` 的位置放返回 `IP`，再向高地址放返回 `CS`：

```text
远调用前
  调用程序：CS₁:IP₁
  SP 指向堆栈中的可用位置

远调用执行
  SP ← SP - 2
  [SS:SP] ← 调用程序的 CS
  SP ← SP - 2
  [SS:SP] ← 调用程序 CALL 后的 IP
  CS ← 子程序所在代码段
  IP ← 子程序第一条指令的偏移地址
  执行子程序体

执行 RETF
  IP ← [SS:SP]
  SP ← SP + 2
  CS ← [SS:SP]
  SP ← SP + 2
  回到调用程序
```

这就是远返回的“两次返回”：先把 `IP` 从堆栈中弹出，恢复段内偏移地址；再把 `CS` 从堆栈中弹出，恢复代码段。两个寄存器都恢复以后，`CS:IP` 才重新指向调用程序中 `CALL` 后面的下一条指令，程序才可以继续执行。

近调用只恢复 `IP`，远调用还要恢复 `CS`，这就是两类调用的根本区别。远调用也可以采用间接寻址，但本段以直接段间调用为主，实际使用相对少一些。

> **注意**：子程序体如果把 `SP` 改坏了，CPU 执行 `RET` 或 `RETF` 时就找不到原先保存的返回地址。子程序内部一旦使用堆栈，`PUSH` 和 `POP` 必须配对，并且严格保持后进先出的顺序。

### 子程序体中的信息保护与恢复

调用程序在调用子程序以前，可能已经把一些数据放进通用寄存器中。子程序为了完成自己的功能，通常也会使用这些寄存器。如果子程序结束时把它们改掉了，调用程序返回后，原本还要继续使用的数据就变了。

> **定义**：把调用者还需要继续使用的信息先保存下来，等子程序完成后再恢复回去，这就是信息的保护与恢复。保护对象最常见的是通用寄存器的内容。

最直接的做法是：进入子程序时，用 `PUSH` 把需要使用的寄存器压入堆栈；在 `RET` 或 `RETF` 之前，再用 `POP` 按相反顺序把它们取回来。堆栈遵循后进先出，所以最后一次 `PUSH` 的内容必须最先 `POP` 出来。

```text
子程序入口
  PUSH  被使用的寄存器
       ↓
  读取入口参数、完成本子程序功能
       ↓
  写回出口结果
       ↓
  POP   按相反顺序恢复寄存器
       ↓
  RET 或 RETF
```

信息保护与恢复不一定要全部写在子程序中，也可以由主程序在调用前后完成。通常更常见的方式是放在子程序里，因为子程序自己最清楚要使用哪些寄存器；但无论保护动作放在哪一边，`PUSH` 和 `POP` 都必须一一对应，不能只记得保存却忘记恢复。

### 主程序与子程序之间的参数传递

参数传递可以先借 C 语言的函数调用来理解：调用函数时把初始数据传进去，函数返回时再把结果交回来。汇编子程序也一样，至少要区分入口参数和出口参数。

入口参数是子程序开始工作所需要的原始数据。主程序在调用前把参数放到约定位置，子程序进入后从那个位置取出。出口参数是子程序完成任务后产生的结果，它放在约定的寄存器、存储器或堆栈位置，返回以后再由调用程序取走。

所以参数传递有两个方向：调用前把输入送进去，返回后把输出取出来。输入和输出放在哪里，必须在设计时约定好；不能只让子程序“算出了一个结果”，却让调用者不知道到哪里找。

#### 寄存器传递

寄存器传递最简单。调用前把输入参数放进约定寄存器，子程序从这些寄存器取数；结果再按约定放回寄存器。寄存器传递不需要额外安排一段数据存储空间，适合参数数量较少的情况。

它的限制也很明显。8086 可用于传递参数的通用寄存器数量是有限的，不能把参数无限塞进寄存器。参数一多，寄存器就不够用了，必须改用别的传递方法。

#### 存储器传递

存储器传递的做法是：先在数据段中定义变量或存储单元，调用前把输入参数写入这些单元，子程序进入后从相应单元读取。子程序产生结果时，也可以把结果写回约定的存储单元；返回以后，调用程序再从那里取走结果。

这种方法能够安排比较多的参数，代价是步骤多一些：要先定义数据段和存储单元，还要约定每个位置代表哪个参数。参数少时没有这个必要，参数多时它比硬塞寄存器更合适。

#### 堆栈传递

堆栈本来就是存储单位，所以也可以用来传递参数。调用前按约定把参数压入堆栈，子程序按相同约定取出；结果也可以按约定写回，等返回以后再由调用程序读取。

使用堆栈传参时，最需要盯住 `SP` 的变化。子程序内部如果继续使用堆栈，就不能覆盖调用时保存的返回地址；所有 `PUSH` 和 `POP` 仍然必须配对，后进先出的规则也不能被破坏。

| 传递方式 | 调用前与调用后的做法 | 适用特点 | 注意事项 |
| --- | --- | --- | --- |
| 寄存器传递 | 调用前后按约定使用寄存器 | 最简单，适合少量参数 | 可用寄存器数量有限 |
| 存储器传递 | 在数据段定义变量，调用前写入，过程内读取 | 参数可以安排得比较多 | 要约定存储位置，步骤稍繁琐 |
| 堆栈传递 | 按约定在调用前后压入、取出参数 | 可以利用已有堆栈传参 | 必须注意 `SP` 变化和后进先出顺序 |

### 从 START 到返回的完整链条

把这段内容连起来，一个子程序程序段实际上经历的是这样一条路径：

```text
START：主程序开始
      ↓
初始化
      ↓
CALL：保护返回地址并转入子程序
      ↓
子程序体：保护现场 → 读取入口参数 → 完成任务
      ↓
写回出口结果 → 恢复现场
      ↓
RET 或 RETF：取回返回地址
      ↓
回到主程序中 CALL 后面的下一条指令
```

循环程序先要判断什么时候应该停止工作；模块化程序要先划清功能边界；子程序定义要配好 `PROC` 与 `ENDP`，名称要一致；调用要把返回地址保护好，近调用保存 `IP`，远调用还要保存 `CS`；过程体结束前要恢复寄存器，返回时还要保证 `SP` 没有被破坏。参数则要在入口和出口都提前约定好。

这些动作看起来分成很多步，其实都在回答同一个问题：主程序把一项工作交给子程序以后，怎样保证子程序既能完成工作，又能准确、干净地回到原来的位置。把这条链条记牢，远调用就不只是多记一个 `CS`，参数传递也不只是“把数换个地方放”，而是整个程序结构中的一个可维护模块。

> **承前启后**：上一节讲完「循环判定与 8086 子程序的完整链条」，下一节接着讲「子程序设计：说明、嵌套与可重入」。

## 子程序设计：说明、嵌套与可重入
> 对应块：BLK24 | 覆盖分集：P47-P48 | 块标题（分集名）：《47》

一个程序能算出结果，并不等于这个程序已经完成了设计。真正交付出去以后，别人还要继续维护、扩充，甚至把它当作一个子程序包的一部分反复调用。如果子程序只有一段代码，却没有说明，别人拿到以后连它会改动哪些寄存器、结果放在哪里都不知道，维护就无从谈起。

所以子程序设计的第六个问题，不是“再写一个功能”，而是把子程序设计成别人能够正确使用的模块。

### 子程序说明文件：让别人敢调用

先记住一句话：产品开发中的每个子程序，前面都应该带说明文件。做作业时我们可以少写，甚至先不写；但是到了实际工作中，不能把这个步骤省掉。产品卖出去以后，调用者需要知道它做什么、怎样准备参数、怎样取回结果，还要知道调用之后哪些寄存器可能被改变。

子程序前方的说明通常写在注释行中，每一行说明都要用分号开头。它不是给程序执行的，而是给调用者和维护者看的。内容至少包括下面这些。

#### 名字与功能

第一，写清子程序名。名字是调用时的入口，调用者必须知道应该跳到哪里，不能靠猜。

第二，用文字写出子程序功能。调用者在决定是否使用它之前，要先确认这个功能是不是正好满足自己的要求。名字再漂亮，如果功能没有交代清楚，别人还是不敢用。

#### 入口与出口

第三，写入口参数。子程序执行时需要哪些数据，由主程序从哪里送进来，要逐项说明。例如本讲后面的例子中，统计子程序要统计 `AL` 里的字节，所以被统计的字节从 `AL` 传入；主程序还可以用 `SI` 指向缓冲区，用 `CX` 保存字符个数。

第四，写出口参数。子程序返回以后，结果放在哪个寄存器、哪个内存单元或其他位置，必须明确。例如统计子程序把 `AL` 中 1 的个数统计到 `BL`，那么 `BL` 就是出口参数。调用者返回后到指定位置取结果，不能自己猜一个位置。

入口参数和出口参数的传递，可以采用寄存器传递、内存传递和堆栈传递。用了哪一种，就在说明文件中写出来。寄存器传递直观，内存传递可以把结果留在数据区，堆栈传递则适合在调用层次较多时配合现场保护使用；具体选哪一种，要看程序实际怎样组织。

#### 寄存器、存储单元和调用例子

第五，写清使用的寄存器，也要把用到的存储单元说明白，尤其是使用堆栈时。这样调用者才能知道哪些内容是输入，哪些内容会被改写，哪些值必须由他自己保护。

> **易错点**：子程序内部改动了 `BX`、`CX`、`SI` 等寄存器，却不告诉调用者，相当于把别人正在使用的数据悄悄改掉。要么在子程序入口保护、出口恢复，要么明确告诉调用者哪些寄存器不能直接使用。

第六，给一个调用例子。哪怕只是一小段“准备哪些寄存器、执行 `CALL`、返回后到哪里取结果”的说明，也能让调用者很快照着使用。说明文件不是装饰品，而是让子程序能够被正确调用的接口约定。

> **结论**：子程序说明文件至少要交代名字、功能、入口参数、出口参数、使用的寄存器和存储单元，再给出一个调用例子。实际产品开发中，这六项缺一不可。

### 嵌套调用：CALL 和 RET 把执行权交出去

子程序允许嵌套。嵌套的意思不是把几段代码简单拼在一起，而是子程序在执行过程中还可以调用另一个子程序。8086 执行 `CALL` 时，要保存返回地址，再把控制权交给被调用的子程序；子程序执行 `RET` 时，返回地址从堆栈中弹出，送回 `IP`，程序就回到 `CALL` 后面继续执行。

这里可以把 `CALL` 看成把程序计数器 `IP` 带到子程序入口，把 `RET` 看成沿着保存好的返回地址回到原处。`CS:IP` 负责指出下一条要执行的指令，嵌套调用一层一层发生，返回时再一层一层回来。

```text
主程序
  │
  └─ CALL 子程序一
       │
       ├─ 入口：保存子程序一的返回地址
       └─ CALL 子程序二
            │
            ├─ 入口：保存子程序二的返回地址
            └─ CALL 子程序三
                 │
                 └─ RET  ── 返回子程序二
            ← RET       ── 返回子程序一
       ← RET            ── 返回主程序
  └─ 继续执行 CALL 后面的指令
```

图要反过来读：最深层先完成，最外层最后返回。不能只记住“跳过去”，还要记住返回地址必须一层一层对应，否则返回时就会回到错误的位置。

原则上，子程序嵌套层数没有人为规定一个固定上限；实际却受堆栈空间限制。每嵌套一层，`CALL` 都要把返回地址压入堆栈。8086 的堆栈按字处理，`SP` 在压栈时向低地址方向移动，弹栈时再回到高地址方向。嵌套太深，返回地址和现场保存值都无处可放，就可能发生 `SP` 溢出。

> **提示**：不要只在程序上画得到调用链，还要在纸上画出堆栈空间。调用层数一多，返回地址、寄存器保护值和后续程序自己的数据都会占用堆栈。

堆栈段的大小要按实际需求定，不能为了看起来“够用”就压到边界。讲义中用 `DW 200 DUP(?)` 预留 200 个字，也就是 400 个字节。实际设计还要为维护和扩充留出大约 30% 的余量；余量是为了以后增加现场保护或增加一层调用时不至于立刻把栈空间用光。

段定义中可以把 `STACK` 单独写出来，并用 `TOP` 标记堆栈的定位边界。程序开始时用 `SS` 指定堆栈段，再用 `SP` 指向 `TOP` 所表示的位置；后面每一次 `PUSH` 和 `POP`，都要能在这块空间里安全地完成。

```text
STACK SEGMENT
    DW 200 DUP(?)      ; 预留 200 个字，即 400 个字节
TOP LABEL WORD
STACK ENDS
```

这里的 `STACK` 是堆栈段，`TOP` 是初始化时定位 `SP` 的标记。段的开头和结尾用 `SEGMENT`、`ENDS` 配对，不能只写一个段名就开始执行。

还有一个很容易忽略的设计与调试顺序：设计子程序时自上而下，调试时自下而上。先从整体上看主程序调用了哪些子程序、上层子程序又调用了哪些下层子程序，这是自上而下的设计；真正调试时，先把最底层的子程序调通，再调试调用它的上层程序。否则下层结果不对时，上层调得再认真也没有意义。

### 递归与中断：出口条件和现场

#### 递归要有出口条件

递归就是子程序在自己还没有结束的时候，再次调用自己。例如把递归子程序记作 `382`，调用关系就可以画成：

```text
主程序
  │
  └─ CALL 382
       │
       └─ 382 尚未结束
            ├─ 出口条件满足 ── RET 返回
            └─ 出口条件不满足 ── CALL 382
                                  │
                                  └─ 继续判断出口条件
```

`382` 再次调用自己，并不等于递归已经安全结束。每增加一次递归，就多压入一层返回地址；如果没有出口条件，它会不断把新的返回地址压入堆栈，最后陷入死循环，还可能把堆栈用尽。

所以递归程序一定要先判断出口条件。条件满足时返回，条件不满足时才继续调用自己。工程设计中确实可能遇到递归，但使用并不算多，设计时尽量避免；确实需要使用时，出口条件必须清楚，不能靠运行时“碰巧停下来”。

#### 可重入要保护两个执行过程

比递归更需要在实际系统中考虑的是可重入。假设 CPU 正在执行某个子程序 A，执行到一条指令时发生了事件，事件向 CPU 提出中断请求。如果 CPU 允许中断，那么它执行完当前这条指令后，原来的下一条指令暂时不执行，转去执行中断服务程序。中断服务程序本身也可以调用子程序 B。

```text
主程序
  │
  └─ CALL 子程序 A
       │
       └─ 执行到一半，事件提出中断请求
            │
            ├─ 当前指令执行完
            ├─ 转入中断服务程序
            │     └─ CALL 子程序 B
            ├─ 中断返回
            └─ 回到子程序 A 被打断的位置
```

这里有两个执行过程同时牵涉到寄存器和内存：如果 A 和 B 使用同一个寄存器，A 还没有完成的计算就可能被 B 改掉；中断服务程序要保存的内容，也可能被 A 的执行结果覆盖。仅仅“能跳过去”还不算可重入，必须让 A 在中断前后都能得到正确结果，让中断服务程序也能正确完成。

这就是现场保护与恢复的意义。进入子程序后，凡是会被后续代码改写、又必须保留的寄存器，都要保护；返回前再恢复。保护顺序和恢复顺序相反，后压入的先弹出，遵循堆栈的后进先出规律。`CALL` 保存的返回地址与程序自己压入的寄存器也共享这条返回链，层次一多，堆栈容量和恢复顺序都必须对上。

### 缓冲区字符加偶校验

现在把前面的设计规则放进一个具体例子。例子要求处理存储器数据段中的一个字符缓冲区，给其中每个字符加上偶校验码，并把处理后的字节写回原位置。题目没有规定字符个数时，可以在程序中自行定义；书上第 119 页第三行给出了 `N=22`，也可以用 `BUFF` 和 `COUNT` 的差值来得到实际字符数。第 118 页的程序还把堆栈段、数据段和代码段分开安排，练习的是主程序调用统计子程序、子程序再保护现场的整体结构。

这里的缓冲区放在数据段中。8086 程序先让 `DS` 指向数据段，再让 `SI` 指向 `BUFF` 的起始位置，让 `CX` 保存要处理的字符个数。缓冲区可以定义成一段字符串，字符个数用下面的符号常量表示：

```asm
DATA SEGMENT
    BUFF DB '...'
    COUNT EQU $-BUFF
DATA ENDS
```

这里的字符串内容不影响算法，关键是 `COUNT` 指向 `BUFF` 与下一个位置之间的距离，得到缓冲区中字符的个数。若按题目固定取 22 个字符，也可以直接用 `N EQU 22`。字符个数是变量，不能在循环中写死。

程序的整体结构可以先看 `CS`、`DS`、`SS` 和 `START` 的关系：

```asm
CODE SEGMENT
    ASSUME CS:CODE, DS:DATA, SS:STACK

START:
    MOV AX, DATA
    MOV DS, AX
    MOV AX, STACK
    MOV SS, AX
    MOV SP, OFFSET TOP

    LEA SI, BUFF
    MOV CX, COUNT
```

这几行的任务很明确：让 `DS` 找到数据段，让 `SS` 和 `SP` 找到已经准备好的堆栈，再让 `SI` 和 `CX` 找到待处理的缓冲区和字符个数。`SS`、`SP` 配好以后，后面 `PUSH`、`POP` 和子程序返回才有可用的堆栈空间。

#### 统计子程序的入口和出口

主程序每取出一个字节，就调用一个统计子程序。可以把这个子程序记为 `COUNTBYTE`，它的入口参数是被统计的字节 `AL`，出口参数是统计结果 `BL`。调用关系是：

```text
主程序
  │
  ├─ MOV AL, [SI]       取出当前字符
  ├─ CALL COUNTBYTE     AL 作为入口参数
  │     ├─ PUSH AX、BX、CX、SI
  │     ├─ 逐位检查 AL 中 1 的个数
  │     ├─ 将统计结果放入 BL
  │     ├─ POP SI、CX、BX、AX
  │     └─ RET 返回主程序
  │
  ├─ 检查 BL 中的统计结果
  ├─ 决定是否给 AL 的最高位补 1
  ├─ MOV [SI], AL        写回原字符单元
  ├─ INC SI              指向下一个字符
  └─ LOOP                CX 不为零就继续
```

`COUNTBYTE` 里面的逐位统计方法沿用前面已经做过的 1 的个数统计思路。这里真正要抓住的是调用约定：被统计的数从 `AL` 带进去，统计后的个数从 `BL` 带出来。程序读到 `BL` 时，知道的不是一个模糊的“结果”，而是明确的出口位置。

子程序如果使用了 `AX`、`BX`、`CX`、`SI`，就应在入口把这些寄存器的内容压入堆栈，返回前按相反顺序恢复，再执行 `RET`：

```asm
COUNTBYTE PROC NEAR
    PUSH AX
    PUSH BX
    PUSH CX
    PUSH SI

    ; 统计 AL 中 1 的个数，结果送入 BL
    ; ……

    POP SI
    POP CX
    POP BX
    POP AX
    RET
COUNTBYTE ENDP
```

这里的省略号只表示统计过程的中间步骤，不改变入口、出口和现场保护关系。`PUSH` 的顺序是 `AX`、`BX`、`CX`、`SI`，所以 `POP` 必须反过来，不能随意换序。子程序说明文件也应该按这个实际约定来写，而不是只写一句“统计 1 的个数”。

#### 判奇偶并写回缓冲区

字符加偶校验的原理，是把字符的 7 位 ASCII 码放进一个字节。存储器按字节组织，一个字节有 8 位；字符码放进高 7 位后，最高位先保持为 0。接着检查这 8 位中 1 的个数：

- 如果 1 的个数是偶数，最高位保持 0，整个字节已经有偶数个 1。
- 如果 1 的个数是奇数，把最高位置 1，使总的 1 的个数变成偶数。

`80H` 的二进制形式是 `10000000B`，所以 `OR AL, 80H` 只会把最高位置 1，不会改变低 7 位的字符内容。统计结果在 `BL` 后，用最低位判断奇偶，主程序的关键控制流程如下：

```asm
AGAIN:
    MOV AL, [SI]
    CALL COUNTBYTE
    AND BL, 01H
    JZ NEXT
    OR AL, 80H
NEXT:
    MOV [SI], AL
    INC SI
    LOOP AGAIN
```

`AND BL, 01H` 的作用是只看统计结果的最低位。结果为 0，表示 `AL` 中 1 的个数是偶数，`JZ` 直接跳到 `NEXT`；结果不为 0，表示 1 的个数是奇数，于是执行 `OR AL, 80H`，给最高位补上一个 1。无论走哪一条路径，最后都要经过 `MOV [SI], AL`，把处理后的字节写回原缓冲区。

`INC SI` 指向下一个字节，`LOOP` 让 `CX` 减 1；只要 `CX` 还没有减到 0，就继续取下一个字符。循环结束后，主程序用书中标出的终止指令退出：

```asm
    MOV AH, 4CH
    INT 21H
```

这段程序的返回值和现场恢复也要一起看：统计子程序先 `PUSH`、后 `POP`，主程序每次 `CALL` 后再从 `BL` 取结果；子程序结束之前已经把保护的内容恢复，返回指令才可以安全地把控制权交回主程序。

### 读这类程序要抓什么

读程序时不要一上来逐条死盯指令。先画调用链，再看入口和出口，最后才回头看统计子程序内部的逐位判断。这个例子的主线是：

```text
准备数据段与堆栈
        ↓
SI 指向 BUFF，CX 保存 COUNT
        ↓
取出 AL = [SI]
        ↓
CALL COUNTBYTE：AL 进入，BL 返回
        ↓
AND BL, 01H 判断奇偶
        ↓
必要时 OR AL, 80H
        ↓
MOV [SI], AL 写回
        ↓
INC SI；LOOP 处理下一个字符
        ↓
MOV AH, 4CH；INT 21H 结束主程序
```

看到 `CALL`，就去找它调用的子程序和返回后的下一条指令；看到 `RET`，就去找返回地址如何压入和弹出；看到 `PUSH`，就去找对应的 `POP`；看到 `MOV [SI], AL`，就确认 `SI` 是否仍然指向当前字符。这个读法比只盯着某一条 `OR` 指令更可靠，因为真正容易出错的地方通常在调用边界和现场恢复。

### 本讲提到的题目

**题目**：存储器数据段中有一个由多个字符组成的缓冲区，要求给其中每个字符加上偶校验位，并把结果写回原缓冲区。字符个数可以在程序中定义；书上例题给出了 `N=22`，也可以用 `COUNT EQU $-BUFF` 计算实际字符数。

**解析**：先让 `DS` 指向数据段，`SI` 指向 `BUFF`，`CX` 保存字符个数。每次用 `MOV AL, [SI]` 取出一个字节，调用 `COUNTBYTE` 统计 `AL` 中 1 的个数，统计结果从 `BL` 返回。用 `AND BL, 01H` 判断奇偶：结果为 0 时，1 的个数已经为偶数，不改最高位；结果不为 0 时，用 `OR AL, 80H` 把最高位置 1。随后用 `MOV [SI], AL` 写回，用 `INC SI` 和 `LOOP` 处理下一个字符。

**答案**：处理后的每个字节中，1 的个数都是偶数；原字符的低 7 位保持不变。统计子程序的入口参数是 `AL`，出口参数是 `BL`，调用前后的寄存器保护必须按 `PUSH` 与 `POP` 的相反顺序完成。

## 子程序的参数、返回与中断入口
> 对应块：BLK25 | 覆盖分集：P49-P50 | 块标题（分集名）：《49》

主程序调用子程序，子程序处理完一段 `BUFF` 缓冲区后再 `return` 回来。这里最容易让人算乱的，不是“跳过去了”，而是 `SP` 到底指向哪儿：返回地址压进去了没有？参数放在哪里？子程序又保护了哪些寄存器？返回时能不能把栈恢复原样？

8086 的子程序调用、现场保护和带参数返回，核心都绕着堆栈。把这几件事走完整，再看 3.12 节的中断调用与返回，很多“为什么 CPU 突然跳走”的问题就顺下来了。

### 调用时先看返回地址

CPU 执行 `CALL` 时，并不是一上来就改 `IP` 跳进子程序。它先把当前这条调用指令的下一条地址，也就是返回地址 `IP`，压入堆栈；然后再把 `IP` 改为子程序入口地址，进入子程序。

> **定义**：子程序返回靠的不是“记性”，而是调用指令在栈中留下的返回地址。只要栈顶位置对了，返回时才能把 `IP` 取回来。

```text
执行 CALL 之前

高地址
┌────────────────────┐
│ 调用前的栈内内容   │
├────────────────────┤ ← SP
└────────────────────┘

执行 CALL 之后

高地址
┌────────────────────┐
│ 返回地址 IP        │ ← SP
├────────────────────┤
│ 调用前的栈内内容   │
└────────────────────┘
  ↓
进入子程序
```

8086 的堆栈按字操作，一个字占 2 字节，所以每压入一个字，`SP` 就减 2。进入子程序后，如果子程序会改到 `AX`、`BX`、`SI` 这些寄存器，就要先 `PUSH` 保存原值。每压一个寄存器，`SP` 又向低地址方向移 2。

```text
子程序保护现场之后

高地址
┌────────────────────┐
│ 子程序要恢复的值   │
├────────────────────┤
│ 子程序要恢复的值   │
├────────────────────┤
│ 返回地址 IP        │
├────────────────────┤
│ 调用前已有内容     │
└────────────────────┘
  ↑ 最低地址方向

栈顶 ← SP
```

子程序结束时，按与 `PUSH` 相反的顺序逐个 `POP`，把寄存器恢复回去。等 `SP` 重新落到 `CALL` 压入的返回地址上，再执行 `RET` 或 `return`。这时 `CPU` 从栈顶弹出一个字送给 `IP`，`SP` 再加 2，程序就回到调用点之后继续往下执行。

> **结论**：`CALL` 压返回 `IP`，`RET` 弹返回 `IP`；子程序自己压入的寄存器，则由子程序自己逆序弹出。程序结束后，`SP` 必须回到这次调用之前的值。

### 同一道例题，参数可以怎么传

子程序要处理一段缓冲区，至少要知道两样东西：要处理多少个字符，以及 `BUFF` 在哪里。这个例子里，字符个数送给 `CX`，缓冲区偏移地址送给 `SI`。

#### 寄存器传参

最直接的办法，就是主程序先把参数装进约定的寄存器，再调用子程序：

```asm
MOV CX, COUNT
LEA SI, OFFSET BUFF
CALL PROC
```

子程序一进入，先保存自己要改动的寄存器，再直接用 `CX` 和 `SI` 取参数。写法很短，但它依赖主程序和子程序都遵守“哪个参数放在哪个寄存器”的约定。

这里我说的寄存器传参，也常被简写成 reg 传参；它不是“寄存器神秘地记住了参数”，而是调用前由主程序把参数写进去，子程序再按约定取出来。

#### 用 data 段存储器单元传参

如果不想把参数都塞进寄存器，就先在数据段里定义专门用于传递参数的单元。一个单元放字符个数，另一个单元放待处理缓冲区或 `BUFF` 的偏移地址。子程序进入并保护好现场后，再到这些约定位置取数。

```text
data 段
┌────────────────────┐
│ COUNT              │ ← 字符个数
├────────────────────┤
│ DATA1 / DATA2      │ ← 参数约定单元
├────────────────────┤
│ BUFF               │ ← 真正要处理的缓冲区
└────────────────────┘
```

在调用子程序之前，主程序要先把参数准备好。比如字符个数从 `COUNT` 取到 `CX`，`BUFF` 的偏移地址取到 `SI`，然后再执行 `CALL`。进入子程序后，可以从 `DATA1`、`DATA2` 这样的参数单元里取值，也可以按约定取 `COUNT` 和 `BUFF` 的信息。

> **易错点**：用存储器传参时，子程序不会自动知道你把参数放在哪。主程序放在 `data` 段的哪个单元，子程序就必须按同一约定去读；主程序改了位置，子程序也要同步改。

#### 用堆栈传参

再换一个办法：主程序调用子程序之前，先把参数压入堆栈。

```asm
PUSH COUNT
PUSH OFFSET BUFF
CALL PROC
```

先压字符个数，再压 `BUFF` 的偏移地址。随后 `CALL` 又把返回地址压进去。进入子程序后，子程序还要继续 `PUSH` 保存 `AX`、`BX`、`SI` 等现场，这样 `SP` 就会不断变化。

问题是，不能在子程序里随便把参数一个个 `POP` 出来。因为这些参数是调用者压入的，子程序只是“取用”，不是“销毁”。如果这里把参数弹出，后面返回时 `SP` 就乱了。

> **注意**：返回地址是 `CALL` 压进去的，现场是子程序自己压进去的，参数是调用者压进去的。三者的压入顺序和清理责任不同，混在一起就会算错。

### 用 BP 固定参数位置

堆栈传参时，不能一直靠 `SP` 去找参数，因为 `SP` 还会被现场保护继续推着走。这时要用 `BP` 建立一把稳定的“尺子”。

子程序一旦要用 `BP` 相对寻址，就必须先保护调用者原来的 `BP`。不管主程序里原来有没有用 `BP`，子程序自己用了，就要负责保存和恢复。

```asm
PUSH BP
MOV BP, SP
```

`PUSH BP` 让 `SP` 减 2，把调用者原来的 `BP` 保存起来；`MOV BP, SP` 再把此时固定的栈顶地址复制给 `BP`。这样，`BP` 就成了当前子程序栈帧的基准。

对刚才的近调用序列，参数和栈内关系可以画成：

```text
高地址
┌────────────────────────┐
│ 字符个数 COUNT         │ ← [BP+6]
├────────────────────────┤
│ 缓冲区偏移 OFFSET BUFF │ ← [BP+4]
├────────────────────────┤
│ 返回地址 IP            │ ← [BP+2]
├────────────────────────┤
│ 调用者原来的 BP        │ ← [BP+0]
└────────────────────────┘
```

所以子程序取参数时，可以这样写：

```asm
MOV SI, [BP+4]
MOV CX, [BP+6]
```

`[BP+4]` 取出先前压入的 `BUFF` 偏移地址，`[BP+6]` 取出字符个数。`BP` 相对寻址默认在 `SS` 段中，而这些内容本来就在堆栈段里，所以能对上。

这个例子中，子程序对字符个数进行统计，偶数个和奇数个要分开判断。被处理的字符和字符个数都已经在堆栈里，子程序一开始就用 `BP` 相对寻址把它们取出来。统计结果可以用 `BX` 带回主程序，因为前面 `BX` 已经被子程序保存过，返回时恢复即可。

> **提示**：`[BP]` 指向的是保存下来的旧 `BP`，不是第一个参数；`[BP+2]` 才是这条近调用留下的返回 `IP`。如果再多压一个单字，下面参数的位置就整体后移 2 个字节。

### POP 之后，栈还要不要回到起点

子程序干完活，不能马上 `RET`，因为它自己压进去的寄存器还没有恢复。正确顺序是：

```asm
POP BP
POP SI
POP 其他已保存的寄存器
RET
```

`POP BP` 只是把 `BP` 恢复回来，并让 `SP` 回到保存旧 `BP` 之前的位置。它不会跳回主程序。只有最后执行 `RET`，才会弹出返回 `IP`，让 `IP` 指向调用之后的那条指令。

有的学生会问：`POP AX` 之后，AX 原来那个值去哪了？答案很简单，它已经被覆盖了。`POP AX` 就是把栈顶那个字装进 `AX`，不会在 `AX` 里面同时保留“旧值和新值”。如果旧 `AX` 还要用，就应该在调用前或子程序中先保存；如果不需要了，覆盖掉就没有问题。

> **易错点**：`POP` 是恢复现场的动作，`RET` 是跳转回调用点的动作。它们不是一回事。没有把现场恢复干净就 `RET`，主程序会拿到被破坏的寄存器值。

### return n 与 3.11 节那个“偶数”问题

普通 `RET` 只弹出返回地址。如果参数是调用者事先压入堆栈的，调用者也可以在返回后自己清理。但这样做就要求调用者和子程序都记牢“参数占多少字节、谁来清理”。一旦漏掉，堆栈就会越积越高，后面继续用堆栈时迟早出问题。

所以 8086 提供了带参数的返回指令。教材里常把它叫 `return n`，实际就是 `RET n`：先弹出返回地址 `IP`，再让 `SP` 越过调用者压入的 `n` 字节。

$$
SP_{\text{返回后}}=SP_{\text{执行前}}+2+n
$$

如果 `CALL` 之前压了 `COUNT` 和 `OFFSET BUFF` 两个参数，合计 4 字节，那么可以写：

```asm
RET 4
```

这里 `+2` 是弹出返回 `IP`，`+4` 是丢弃调用者压入的两个字，合计 `SP` 增加 6。

这个点要回到 3.11 节讲清楚。第 69 页附近那条“带参数的子程序返回指令”，讲的就是 `return n`。很多同学会在这里想当然地写 `RET 3` 或 `RET 5`，这是错的。8086 对堆栈的操作是按字进行的，按字操作就必须落在字边界上，所以 `n` 一定要是偶数。

> **结论**：`RET n` 中的 `n` 不是“随便多弹几个字节”，而是必须等于要清除的参数字节数；几个字，就乘 2。

### 中断调用与返回：为什么不能单独看

3.11 节把“调用与返回”这条线收住后，3.12 节叫“中断调用与返回指令”。但这一节不能光看目录就硬往下冲，它会碰到第八章的中断知识。8086 的中断结构、响应过程、类型号，这些是理解后面的前提；只看 3.12 节，很多地方会像少了一截链条。

中断是什么？CPU 正在执行程序时，某个事件提出请求，CPU 允许时暂停下一条指令的执行，转入中断服务子程序；服务完成后，再执行中断返回，回到原程序刚才中止的地方继续执行。

```text
主程序正常执行
      │
      ▼
某个事件向 CPU 提出中断请求
      │
      ▼
CPU 暂停原程序
      │
      ▼
转入中断服务子程序
      │
      ▼
服务完成后执行中断返回
      │
      ▼
回到原断点，继续执行
```

提出中断请求的事件叫中断源。中断源可以在 CPU 内部，也可以来自 CPU 外部。不同型号的 CPU，在响应中断后怎样让 `CS:IP` 指向服务程序入口，硬件处理方式可能不同；但概念是相通的：先停下，转去服务，再回来。

### 外部中断看 NMI 和 INTR

外部设备要向 8086 提出中断请求，必须通过 CPU 的某个中断请求输入引脚。8086 这里有两个：`NMI` 和 `INTR`。

| 输入引脚 | 请求性质 | 响应条件 |
|:---:|:---|:---|
| `NMI` | 外部非可屏蔽中断请求 | CPU 必须响应 |
| `INTR` | 外部可屏蔽中断请求 | 只有 `IF=1` 时才响应 |

`NMI` 是非可屏蔽请求，外部通过它提出请求，CPU 要无条件响应。`INTR` 是可屏蔽请求，外部设备通过它向 CPU 请求服务，但是否响应由中断允许标志 `IF` 控制。

`IF=1`，表示开中断，也叫中断允许状态；这时 `INTR` 请求可以打断程序。`IF=0`，表示关中断，也叫中断不允许状态；这时 `INTR` 请求不能打断当前程序。屏蔽的是 `INTR` 这类可屏蔽请求，不是 `NMI`。

### 内部中断源先抓这五类

看第八章 8.2 节和 8.3 节的中断结构图，能把外部和内部中断源一起看明白。8086 CPU 内部常见的中断源可以先记成五类：除法出错、单步中断、溢出中断、断点中断、`INT n` 软件中断。

| 中断源 | 触发条件或用法 |
|:---|:---|
| 除法出错 | 执行 `DIV`、`IDIV` 时除数为 0，或商超出结果寄存器范围 |
| 单步中断 | `TF=1` 时，每执行完一条指令就产生一次单步中断 |
| 溢出中断 | 执行 `INTO` 时，若 `OF=1` 则产生中断 |
| 断点中断 | 调试时用 `INT 3` 临时替换原指令 |
| 软件中断 | `INT n`，`n` 就是中断类型号 |

除法出错很好理解：CPU 执行 `DIV` 或 `IDIV` 时，如果除数为 0，就不能正常完成；如果商超出了结果寄存器能放下的范围，也会出错。转去执行相应的中断服务子程序。

单步中断和陷阱标志 `TF` 有关。`TF=0`，程序一条接一条连续执行；`TF=1`，每执行完一条指令就产生一次单步中断，下一条指令不会紧跟着执行，而是先转入单步处理过程。调试程序里的“全速执行”和“单步执行”，背后就是 `TF` 的差别。

`INTO` 是溢出中断指令。前一条加法或减法等运算指令执行后，如果 `OF=1`，再执行 `INTO`，CPU 才产生一次溢出中断；如果 `OF=0`，就不会中断，后面的指令照常执行。

```text
前一条运算指令
      │
      ▼
   执行 INTO
      │
  ┌───┴───┐
  │       │
 OF=1   OF=0
  │       │
溢出中断 不产生中断
转服务程序 继续执行下一条
```

断点中断用的是单字节指令 `INT 3`，操作码是 `3CH`，对应中断类型号 3。调试程序设置断点时，会把原指令的位置临时改写为 `INT 3`。CPU 执行到这里，就转入断点服务；如果结果在寄存器中，就把寄存器内容显示出来；如果结果在内存中，就显示有关内存。服务完成后，中断返回把原指令位置恢复，断点消失，再把断点移到下一处。

所以调试程序不能只单步，也不能只靠断点。单步很细，但程序一大就慢；断点能快速分段，却可能一步跨过问题。实际调试要把设置断点调试和单步调试结合起来。

`INT n` 是更一般的软件中断指令，`n` 就是中断类型号。DOS 系统里许多功能子程序也通过软件中断调用，比如 `INT 21H` 进入 DOS 功能调用。调用哪个功能，要先把功能号放进 `AH`，再用 `INT 21H` 去触发。

```asm
MOV AH, 01H
INT 21H
```

`AH=01H` 对应等待用户按键。程序执行到这里不会立刻往下跑，而是一直等；用户不按键，它就一直等；用户按键后，功能调用才结束。结束用户程序、返回操作系统，也要先把 DOS 的功能号准备好，再用软件中断进入相应功能。

到这里，外部的 `NMI`、`INTR`，以及内部和软件发起的几类中断源就分开了。再往后要看的，就是 CPU 接受请求后，怎样通过 `CS:IP` 找到中断服务程序入口。前面 CALL 里的“入口”和“返回”，在这里又会以新的形式出现一次。

> **承前启后**：上一节讲完「子程序的参数、返回与中断入口」，下一节接着讲「中断源、类型号与向量：8086 怎么认出中断并跳到服务程序」。

## 中断源、类型号与向量：8086 怎么认出中断并跳到服务程序
> 对应块：BLK26 | 覆盖分集：P51-P52 | 块标题（分集名）：《51》

上一节我们把中断的概念、中断源和返回指令讲了一遍。可这里还有一个问题没有解决：CPU 引起某种中断以后，它怎么知道是哪个中断源向它提出了请求呢？

不知道是谁在喊，CPU 就没办法准确地转入到这个中断源对应的中断服务程序入口区。带着这个问题，我们把 8086 的中断体系从里到外捋一遍：先看 CPU 内部的五类中断，再看外部两个引脚，最后引出 8259A、中断向量、中断向量表，以及完整的响应过程。

### 内部中断：CPU 自己发现的事件

任何一个型号的 CPU 组成的微型计算机系统当中，中断源都分两类：一类是内部中断，一类是外部中断。内部中断的“内部”是什么意思？是这个事件由 CPU 内部某个事件的发生而提出的，根本不需要外部设备来拉一根请求线。

在 8086 CPU 组成的系统当中，内部中断有五个。我们一个一个看。

**除法出错中断。** CPU 执行除法指令时，发现除数为零，或者商溢出了，就会自动触发一次除法出错中断。

**单步中断。** CPU 执行完一条指令之后，会不会引起单步中断，由 TF 标志控制。当 TF 等于 1 时，CPU 执行完这一条指令，下一条指令就不执行了，而是引起一次单步中断。

**断点中断。** CPU 执行 `INT 3` 软件指令而引起的断点中断。注意它的类型号正好就是 3，因为指令里写的数就是中断类型号。

**溢出中断。** CPU 执行 `INTO` 指令引起溢出中断。`INTO` 的用法是：当 OF 等于 1 时，触发一次溢出中断；当 OF 等于 0 时，不会发生溢出中断，而是顺序往下执行。

这里有一个特别容易搞错的地方：`INTO` 执行时看的 OF 标志，是**它前方那条指令运算以后产生的 OF 标志**。前面是加法运算，运算结果溢出把 OF 置成了 1，执行 `INTO` 就会响应；OF 是 0，就顺序往下执行。OF 不是 `INTO` 自己重新算出来的。

**软件中断。** CPU 执行 `INT n` 指令引起的中断，中断类型号就是指令后面这个 $n$。是不是 `INT 21H`？还是 `INT 2CH`？都是这一类。$n$ 不可能大于 255。

这么一数，内部中断就是五种：除法出错、单步、断点、溢出和 `INT n` 软件中断。

### 中断类型号：给每个中断源一个号码

CPU 怎么知道是哪个中断源？办法就是编号。8086 系统给每一个中断源分配了一个中断类型号（interrupt type number）——它就是识别这个中断源的号码。

在 8086 系统当中，给每个中断源编排的中断类型号是从 0～255 编号，也就是 00H 到 FFH，一共 256 个。所以 8086 CPU 最多能管理 256 级中断。

CPU 内部硬件给这些内部中断自动分配的类型号是固定的：

| 中断源 | 触发条件 | 中断类型号 |
| :--- | :--- | :---: |
| 除法出错中断 | 除数为零或商溢出 | 0 |
| 单步中断 | `TF = 1`，执行完一条指令 | 1 |
| 断点中断 | 执行 `INT 3` | 3 |
| 溢出中断 | 执行 `INTO` 且 `OF = 1` | 4 |
| 软件中断 | 执行 `INT n` | $n$ |

> **易错点**：2 号为什么没出现在这张表里？因为 2 号被外部非可屏蔽中断占用了。这个号码分配本身就是一个小测验，背错了后面查向量表全都会错位。

知道是几号中断，就能正确地转移到这个中断源对应的中断服务程序入口区。至于怎么转入，我们后面再看。先把外部中断认全。

### 外部中断：NMI 与 INTR 两个入口

除了内部中断，任何型号的 CPU 都有外部中断，8086 也不例外。外部任何一个中断源要向 CPU 提出中断请求，必须通过两个引脚之一：一个是 `NMI`，一个是 `INTR`。

#### NMI：非可屏蔽的紧急请求

`NMI` 引脚是**上升沿有效**。如果外部设备通过这个引脚向 CPU 加上一个上升沿，CPU 就要响应这一个请求，而且不管 IF 等于 0 还是等于 1，都必须响应。

所以，通过 `NMI` 引脚向 CPU 提出的中断请求，叫外部非可屏蔽中断请求。非可屏蔽的意思就是：不能靠 IF 把它挡回去。

它对应的中断类型号 $n = 2$，这是 CPU 内部硬件固定死的。

#### INTR：受 IF 控制的普通请求

通过 `INTR` 引脚提出的请求，**必须是高电平有效**。外部设备以高电平形式从 `INTR` 引脚向 CPU 提出中断请求，CPU 是否响应，要受 IF 的控制。

只有当 IF 等于 1，也就是 CPU 处于开中断状态或者说中断允许状态时，CPU 才响应。如果 IF 等于 0，CPU 处于中断不允许状态，外部设备通过 `INTR` 引脚提出的中断请求，CPU 不理睬，也就是不响应。

所以，通过 `INTR` 引脚向 CPU 提出的中断请求，称为外部可屏蔽中断请求。**可屏蔽**的意思，就是受 IF 标志的控制。

```text
NMI  ：上升沿有效   IF=0 / IF=1 都必须响应   类型号固定为 2
INTR ：高电平有效   只有 IF=1 才响应        类型号不固定，由用户安排
```

两条路必须分清：一条是紧急插队，来了就得停；另一条是排队进门，门关着（`IF=0`）就先等着。

### 8259A：把八个外部请求汇成一个 INTR

问题接着来了。`INTR` 这一个引脚，类型号却不固定——CPU 用户进行硬件设计时，没有给这个引脚提出的每一个请求都分配类型号，**中断类型号是由用户决定的**。

所以用户必须在 8086 CPU 外部扩充一片中断控制器芯片，型号是 8259，也就是 8259A，由它来对外部可屏蔽中断进行管理。

一片 8259 有八个中断请求输入端：`IR0`～`IR7`。任何一个输入端都可以外接一个中断源，外部任何一个中断源都可以通过这八个请求输入端之一向 8259 提出中断请求，然后由 8259 的 `INT` 输出端再向 CPU 请求。

```text
 中断源0    中断源1    中断源2    中断源3    中断源4    中断源5    中断源6    中断源7
   |          |          |          |          |          |          |          |
  IR0        IR1        IR2        IR3        IR4        IR5        IR6        IR7
   +----------+----------+----------+----------+----------+----------+----------+
   |                          8259A 中断控制器                                  |
   |      屏蔽位：哪一路不屏蔽、哪一路屏蔽掉                                   |
   |      有效电平：某几路高电平有效、某几路低电平有效                          |
   |      类型号基址：用户用 OUT 指令写入                                     |
   +----------------------------------+---------------------+---------------+
                                      | INT（高电平）       | D0~D7
                                      v                     ^
                               +--------------+             |
                               |   8086 CPU   |-------------+   （OUT 指令编程）
                               |   INTR 引脚  |
                               +--------------+
```

读图就是一句话：外设先找 8259A 报到，8259A 处理优先级、屏蔽和类型号，最后只用一个高电平 `INT` 去敲 8086 的 `INTR` 门。

8259A 也可以看成一个外设、一个 I/O 接口，它有 8 位数据输入输出引脚。我们在电路设计时，可以把它和 CPU 的 `D0`～`D7` 数据线相连。相连以后，就可以对这一片 8259 芯片编程、初始化它。用 `OUT` 指令给控制器写入不同的命令，就能改变 8259 的工作方式或工作状态：

- 可以给 `IR0`～`IR7` 这八个输入端设置中断请求信号的形式，是高电平有效还是低电平有效；
- 可以控制 `IR0`～`IR7` 中哪一个被屏蔽掉，哪一个不屏蔽；
- 可以写入中断类型号基址。

某个中断请求输入端一旦被屏蔽，外部中断通过这个输入端向 8259 提出请求，8259 根本不会让 CPU 响应。只有那一路请求输入端未屏蔽，外部设备通过它提出请求，8259 才通过 `INT` 输出端向 CPU 发一个高电平有效的外部可屏蔽中断请求。

那 CPU 响应了这个高电平，它知不知道是 `IR0`～`IR7` 里哪一路被请求？这就要求给这八个中断源都分配中断类型号。这个类型号由用户设置，用户通过 `OUT` 指令向 8259 内部写类型号来定。

**关键：写类型号时，只给 `IR0` 这一级确定就行。** 比如 `IR0` 的中断类型号设置成 08H，那么 `IR1`～`IR7` 的中断类型号就顺序下去，是 09H、0AH、0BH、0CH、0DH、0EH、0FH。

也就是说，初始化 8259 的中断类型号，只需要确定 `IR0` 级的类型号；`IR0` 的类型号一旦确定，基址就定了，`IR1`～`IR7` 的类型号随之确定。

> **提示**：把“类型号”理解成普通电话号码就顺了。`IR0` 是总机号码，后面的顺延；而内部中断和 NMI 的号码是芯片出厂就焊死的，用户改不了。

### 中断向量：服务程序的入口地址

有了中断类型号，还要解决第二个问题：CPU 知道了类型号，怎么拿到服务程序的入口地址？

先看 CPU 响应中断的前后。CPU 不会把一条指令执行一半就跳走——它必须把这条指令执行完，才去响应。指令执行完以后，在 CPU 还没有响应中断之前，IP 指针所指到的这条指令所在处，称为中断现场。

为什么要保护这个现场？逻辑很清楚：CPU 要转入为这个中断源服务的中断服务程序去执行，服务完了以后还必须正确地返回。要正确返回，就得把现场保护住。

中断现场要保护什么？有这三条指令的 IP、有这条指令的 CS，还有这条指令之前 CPU 执行主程序时可能做过某种运算，运算结果影响了 PSW 中的状态标志。转入中断服务子程序以后，服务子程序也可能运算，如果把 PSW 状态破坏了，等返回以后再处理那些状态标志时，结果可能就是错的。

所以 CPU 响应中断时，首先不是急着往回跑，而是把 PSW 状态、返回地址 CS、返回地址 IP 依次压栈保护起来。**这个过程是硬件自动完成的**，不用我们写指令。

保护完现场以后，CPU 要想办法获取中断服务子程序的入口地址。这个入口地址就是**中断向量**。

> **定义**：中断向量就是中断服务子程序的入口地址。

中断服务子程序的第一条指令也有 16 位偏移地址，所以这个入口地址要给 `IP` 和 `CS`：`CS` 和 `IP` 指向服务程序入口，中断服务程序的第一条指令就从这里开始执行。

显然，中断向量是 32 位的：16 位偏移地址 IP，加上 16 位段地址 CS。

### 中断向量表：最低 1 KB 里的 256 个入口

8086 外部有 1 MB 的存储空间。系统规定，把这 1 MB 的最低 1 KB 专门做中断向量表，也就是从地址 00000H 一直到 003FFH。

在这个表中存放的是中断向量，而一个中断向量是 32 位的，所以一个中断向量占用 4 个字节单元。0 号中断的向量存放在最前面的 4 个单元里，1 号中断的向量存放在接下来的 4 个单元里，一直到 255 号中断的向量。所以这张表最多放 256 个向量，因为 8086 最多管 256 级中断。

按前面分配的类型号排开看：00000H 开始放除法出错中断的服务程序入口地址，往后依次是单步中断的向量、外部非可屏蔽中断的向量……

那么怎么把“CPU 知道类型号 $n$”和“$n$ 号服务程序的入口地址”串起来？找的就是这个简单的地址关系：

$$
\text{向量表中的位置} = n \times 4
$$

$1$ 号中断源对应 $1 \times 4 = 4$ 的位置；$2$ 号中断源对应 $2 \times 4 = 8$ 的位置；$0$ 号就从 0 开始。每一个向量占 4 个字节，后一个类型号的位置就是前一个往后推 4 个字节。

这里再说清楚一点：$n \times 4$ 是**物理地址**，因为向量表固定放在存储空间最低的 1 KB，起始物理地址就是 00000H。

所以，你要使用 $n$ 号中断源，就得把你编写的中断服务程序入口地址的 IP 和 CS，分别写在 $n \times 4$ 单元和 $n \times 4 + 2$ 单元中——$n \times 4$ 单元放偏移地址 IP，$n \times 4 + 2$ 单元放段地址 CS。

这个把服务程序入口地址写进向量表的过程，就叫**中断向量的建立**。

举个已经讲过的例子。CPU 执行 `INT 21H` 时，中断类型号 $n = 21H$。那 21H 对应服务子程序的入口地址在哪儿？就在向量表的 $21H \times 4$ 那 4 个字节单元里。$21H \times 4 = 84H$。CPU 于是到 84H 处取一个字给 IP，到 86H 处再取一个字给 CS，`CS:IP` 一指向，就跳进中断服务程序开始服务了。

```text
       00000H  +------------------+
               | 0 号：除法出错     |  IP 在 00000H，CS 在 00002H
       00004H  +------------------+
               | 1 号：单步中断     |  IP 在 00004H，CS 在 00006H
       00008H  +------------------+
               | 2 号：NMI         |  IP 在 00008H，CS 在 0000AH
               +------------------+
                    …… 共 256 项 ……
       00084H  +------------------+
               | 21H：软件中断     |  IP 在 00084H，CS 在 00086H
       003FCH  +------------------+
               | 255 号            |  IP 在 003FCH，CS 在 003FEH
       00400H  +------------------+
```

读图就是一句话：类型号 $n$ 乘 4，得到的就是这一号中断向量在最低 1 KB 里的起点。

### 中断响应过程：类型号已知的固定三步

CPU 引起中断时，中断请求早就到了。现在的问题是，CPU 怎么响应？先看内部中断和外部非可屏蔽中断这两种——它们的中断类型号 $n$ 是固定的，所以一旦有中断请求，CPU 必须响应，不受 IF 控制。

响应过程就三步。

**第一步：保护现场。** 把 PSW、CS、IP 依次入栈。PSW 里装着状态标志，CS 和 IP 合起来是返回地址。保护完现场的栈长这样：

```text
          栈（高地址在上）
              |
              |   PSW      ← 最先压入
              |   CS       ← 其次压入
              |   IP       ← 最后压入，位置最低
              |   主程序原有的 SP 数据
              v
            栈顶 SP
```

读图就是一句话：压栈是从 PSW 到 IP，栈顶最后落在 IP 上，所以出栈时反过来先弹 IP。

**第二步：清除 IF 和 TF。**

清除 IF 的目的，是进入服务程序后不允许响应外部可屏蔽中断，防止中断嵌套把现场搅乱。可是如果你确实希望 CPU 在执行这个中断服务程序期间还能够响应外部可屏蔽中断，那么你的服务程序一开始就要排上 `STI` 指令，让 IF 置 1，这属于软件有意打开中断。

清除 TF 的目的，是进入服务程序后连续取指令、连续执行程序，不再一条一条地单步。TF 也可以叫单步标志或者叫陷阱标志。假如进入中断服务子程序之前 TF 还等于 1，那么执行一条指令就又触发一次单步中断，在服务程序执行期间一般不允许这样。所以 CPU 响应中断时会自动把 TF 清零。

**第三步：根据类型号取中断向量。** CPU 用 $n \times 4$ 作地址，在向量的 $n \times 4$ 单元取一个字给 IP，在 $n \times 4 + 2$ 单元取一个字给 CS。`CS:IP` 指向服务程序入口，程序就跳进去了。

#### 服务做完怎么回来：IRET

在中断服务子程序的最后，肯定要排一条 `IRET` 指令，才能真正完成中断返回。

`IRET` 做的事情，就是沿着刚才压栈的顺序反过头来依次出栈：先弹一个字给 IP，再弹出一个字给 CS，再弹出一个字给 PSW，SP 也就随之恢复了。现场恢复完毕，控制权就交还给被中断的主程序。

还有两点要说明。第一，如果中断服务子程序里用到了某些寄存器或内存单元，怕它们把原来的数据破坏掉了，那就要在程序里自己保护。CPU 自动保护的是 PSW、CS、IP 这一组固定的现场，和你自己程序里用到的那些东西不是一回事。

### 外部可屏蔽中断：多一次握手才能拿到类型号

外部可屏蔽中断的响应过程，骨子里跟前面那三步一样，但前面要“戴上一个帽子”，第三步还要多插入一段。

帽子是：响应外部可屏蔽中断，必须在 IF 等于 1 的情况下，也就是确保 CPU 开着中断；而且和所有中断一样，CPU 必须先把现行这条指令执行完，才做出响应。

前两步完全一样：保护现场，把 PSW、CS、IP 依次入栈；然后 IF、TF 清零。

第三步就不一样了。内部中断和 NMI 的类型号 CPU 自己知道，可外部可屏蔽中断的 CPU 不知道——8259 知道。所以必须多一个 `INTA` 握手过程。

CPU 有一个 `INTA` 输出引脚，8259 也有一个 `INTA` 引脚，把这两个引脚对联。假如 CPU 响应了这个中断，第一步是通过 `INTA` 引脚向 8259 发出一个负脉冲，负脉冲的宽度是一个时钟周期的时间，约相当于 CPU 执行一条指令的时间。8259 收到这个负脉冲，就知道：“哦，我提出的请求被响应了。”这一下叫握手成功。

但握手成功不等于事情办完。`IR0`～`IR7` 八个中断源都可能在请求，CPU 还是不知道是哪一个发来的。谁知道呢？8259 知道。

于是 CPU 再通过 `INTA` 输出引脚，利用一个时钟周期时间，向 8259 发出第二个负脉冲。8259 收到第二个负脉冲，就知道 CPU 在向它要那个类型号了，就把自己内部保存的中断类型号 $n$ 的那个寄存器的值送到数据线上。CPU 在发第二个负脉冲期间，从数据线上就读到了 $n$。

```text
CPU 8086                                   8259A
  |                                          |
  |<------- INTR = 1（高电平） ---------------|   外设请求到达，8259 把 INT 拉高
  |                                          |
  |  先把现行这条指令执行完                    |
  |                                          |
  |------- INTA 第 1 个负脉冲 --------------->|   宽一个时钟周期
  |                                          |   8259：请求已被响应
  |                                          |
  |------- INTA 第 2 个负脉冲 --------------->|   宽一个时钟周期
  |<------ 中断类型号 n 送上数据总线 ---------|   CPU 读到的就是 n
  |                                          |
  |  按 n×4 去向量表取 IP、CS，转入服务程序       |
```

读图就是一句话：`INTA` 的第一个负脉冲说“收到了”，第二个负脉冲说“把号码告诉我”，8259 就在第二个脉冲里把 $n$ 放到数据总线上。

拿到 $n$ 以后，才算接上前面的固定三步：$n$ 乘以 4，在向量表的 $n \times 4$ 地址取 IP、在 $n \times 4 + 2$ 取 CS，`CS:IP` 指向中断服务子程序入口，跳进去开始服务。服务完毕执行 `IRET`，恢复现场，返回主程序。

所以一片 8259 能管理 8 个外部可屏蔽中断源，但每个中断源的中断类型号都不是 CPU 内部硬件固定的，而是用户用 `OUT` 指令写进去的。

### 级联 8259：从 8 个请求一路扩到 64 个

8 个不够用怎么办？加片子。

当时的 PC 主板上只配置了一片 8259A，属于单片工作方式，所以那时的 IBM PC 机能管理的外部可屏蔽中断源只有 8 个。这 8 个输入端不是随便分的：有的分配给键盘，有的分配给时钟，有的分配给软驱，有的分配给 COM1、COM2 等等。我印象中 `IR2` 当时是没人用的。

把两片 8259A 级联起来，主片的 `INT` 输出接 CPU 的 `INTR` 引脚，谁的 `INT` 接 CPU 的 `INTR`，谁就是主片，其余就是从片。从片也有一个 `INT` 输出，它不接 CPU，而是接主片的一个 `IR` 输入端，主板上就是接到 `IR2` 级联的。

```text
        外设       外设  ...        外设
          |           |               |
         IR0         IR0             IR0
          |           |               |
     +--------+  +--------+     +--------+
     | 从片   |  | 从片   | ... | 从片   |
     | 8259A  |  | 8259A  |     | 8259A  |
     +--------+  +--------+     +--------+
       IR2 |     IR3 |               |
           v       v                 v
     +----------------------------------------+
     |               主片 8259A                |
     |   其余 IR 输入端直接接外设                 |
     +------------------+----------------------+
                        | INT
                        v
                    8086 INTR
```

读图就是一句话：从片的 `INT` 挂上去了，就占掉了主片的一个输入端，所以每加一片从片，管理能力是 7 个净增。

数一下就明白了。$N$ 片级联时，1 片主片加 $N-1$ 片从片，一共有 $8N$ 个输入端，其中 $N-1$ 个主片输入端被从片的 `INT` 占用，所以能接外设的还有 $8N - (N-1) = 7N + 1$ 个：

| 8259A 片数 | 组成 | 可管理外部可屏蔽中断源数 |
| :---: | :--- | :---: |
| 1 | 1 主 + 0 从 | 8 |
| 2 | 1 主 + 1 从 | 15 |
| 4 | 1 主 + 3 从 | 29 |
| 9 | 1 主 + 8 从 | 64 |

所以两片级联能管 15 个；再多加从片，一般可以级联到 1 片主片加 8 片从片、总共 9 片 8259A，能管 64 个外部可屏蔽中断源。

### 系统功能调用：这一讲为什么要落到这儿

按 3.12 节的安排，接下来该讲系统功能调用了。

系统里有 DOS 操作系统，DOS 中的每一个功能都变成了子程序形式，允许用户设计程序时去调用。我们把 DOS 功能调用叫低级功能调用，把 BIOS 功能调用叫高级功能调用。

在实际的程序设计当中，拿到一个设计任务，第一件事是去查表——查 DOS 功能调用表，看你设计的程序里哪些功能需要由系统功能调用来完成，这些就不要自己重复编写了，直接调用就行。特别是磁盘的管理、许许多设备的管理、文件的管理等等，都可以调用系统功能来完成。

我在这里先把 DOS 系统功能调用重点提一提，BIOS 功能调用也顺带提一点，是因为第四章特别是子程序设计那一节里用到了好多，程序设计里也会用到 DOS 和 BIOS 功能调用，特别是 DOS 功能调用。先把中断向量、类型号这套机制打通，后面接 `INT 21H` 自然就顺了。

### 本讲提到的题目

在一个由 8086 组成的微机系统当中，其中断子系统的外部由 4 片 8259A 级联，共同管理外部多少级（可屏蔽）中断源？

**答案：29。**

**解析：** 4 片级联的结构是 1 片主片加 3 片从片。4 片一共提供 $4 \times 8 = 32$ 个输入端，但 3 片从片的 `INT` 输出各自要占掉主片的一个输入端，剩下 $32 - 3 = 29$ 个输入端可以直接接外部中断源。所以能管理 29 个外部可屏蔽中断源。这种计算在填空题里出现得相当频繁。

## DOS 功能调用与跳转表多分支
> 对应块：BLK27 | 覆盖分集：P53-P54 | 块标题（分集名）：《53》

先把书翻到附录中的 DOS 功能调用表。你会先发现一个问题：这张表列得并不全。课上只靠它，碰到没列出的功能就不知道该从哪儿查了。现在查资料这么方便，教材附录只是起点；真要继续深入，就再找一份更完整的功能表对照着看。

不过，表中这些功能并不是一锅粥。最左边是功能号，DOS 把每项功能都编了号；后面依次说明这个功能做什么、调用前要准备哪些入口参数，以及执行结束后能从哪个出口参数读取结果。我们真正写程序时，最先碰到的就是这条接口：

```text
设置功能号与其他入口参数
            ↓
执行 INT 21H
            ↓
从规定的出口参数读取结果
```

这张表的重点，不是让你把整张表背下来，而是先分清“功能号相同到底意味着什么”“入口和出口各放在哪里”，以及“看起来相近的功能，行为究竟差在哪里”。

### 等一个字符，不只是功能号相近

#### 带回显地等待一次按键

DOS 功能的 01H 号最容易先遇到。把功能号 `01H` 放进 `AH`，执行 `INT 21H`，CPU 就会停在这里等用户从键盘输入一个字符。用户不按键，程序就一直等；一旦按下，程序才继续向下执行。

这个调用不需要入口参数，字符的 ASCII 码放在 `AL` 中返回。除此之外，它还会把用户按下的字符回显在屏幕上——在 DOS 界面上，就是显示在当前光标处。

```asm
MOV AH, 01H
INT 21H
```

它还会检测等待期间是否按下了 `Ctrl+Break`。如果发生这个组合键，就结束用户程序，返回 DOS 系统。

把执行过程画出来，很容易看清“等待”到底意味着什么：

```text
执行 INT 21H / AH=01H
          ↓
    等待用户按键
   ↙          ↘
一直等          按下一次键
   ↓               ↓
程序不前进       字符回显
                   ↓
             ASCII 码送入 AL
```

#### 同样等字符，为什么还有 07H 和 08H

07H 号也等待用户从键盘输入一个字符，字符同样返回到 `AL`，但它不回显，也没有入口参数。

```asm
MOV AH, 07H
INT 21H
```

08H 号同样等待一次键盘输入，字符也放在 `AL` 中，同样不回显。它与 07H 号最容易混的是中断检查：07H 会检查 `Ctrl+Break`，08H 检查的是 `Ctrl+C`。

```asm
MOV AH, 08H
INT 21H
```

于是，三个功能可以这样区分：

| 功能号 | 是否回显 | 返回字符的位置 | 特殊检查 |
| :--- | :--- | :--- | :--- |
| 01H | 是 | `AL` | 检查 `Ctrl+Break` |
| 07H | 否 | `AL` | 检查 `Ctrl+Break` |
| 08H | 否 | `AL` | 检查 `Ctrl+C` |

> **易错点**：07H 和 08H 都是“不回显地等一个字符”，但它们的组合键检查对象不同。功能号选错，返回的字符虽然还在 `AL` 中，程序对中断的处理却会走错路径。

实际应用中，如果不需要把按键显示出来，一般不要随手选 01H。先问一句“要不要回显”，往往就能把三个功能号分开。

### 从 1 到 5：不要把比较串写成数字迷宫

假设程序要从键盘输入一个 `1`～`5`，然后根据数字转入五个不同的功能入口。最容易想到的办法，是依次比较：

```text
AL 是 '1' 吗？是 → 功能 1
AL 是 '2' 吗？是 → 功能 2
AL 是 '3' 吗？是 → 功能 3
AL 是 '4' 吗？是 → 功能 4
AL 是 '5' 吗？是 → 功能 5
```

只有两三个分支时，这样写并不难看。可分支一多，前面就会堆起一大串重复的 `CMP` 和条件转移。假设误按了 `0`，它本来就不属于合法范围；若程序只顾着和 `2`、`3`、`4`、`5` 挨个比较，前面就会写下一大段永远不会到达正确分支的无用代码。效率低，也容易让人看不出程序真正的结构。

所以这里真正要解决的问题是：**能不能不管按的是 1、2、3、4 还是 5，都先用同一种计算找到相应功能入口？**

跳转表就是为这件事准备的。

### 跳转表：把入口地址变成可索引的数据

#### 标号不是一个数值

先把五个功能入口分别标成 `G1`、`G2`、`G3`、`G4`、`G5`。这里的 `G1` 只是一个标号，但它在程序里表示一个完整地址，具有两个属性：段地址和偏移地址。

```text
G1 ── 段地址 + 偏移地址
G2 ── 段地址 + 偏移地址
G3 ── 段地址 + 偏移地址
G4 ── 段地址 + 偏移地址
G5 ── 段地址 + 偏移地址
```

标号本身不会因为“起了名字”就自动出现在数据中。我们还需要建立一个表，把每个标号的偏移地址作为数据项存进去：

```asm
TABLE DW OFFSET G1
      DW OFFSET G2
      DW OFFSET G3
      DW OFFSET G4
      DW OFFSET G5
```

`DW` 定义一个字。`OFFSET G1` 取出 `G1` 的偏移地址。于是内存中的跳转表不是五个指令，而是五个地址值：

```text
TABLE+0   G1 的偏移地址
TABLE+2   G2 的偏移地址
TABLE+4   G3 的偏移地址
TABLE+6   G4 的偏移地址
TABLE+8   G5 的偏移地址
```

为什么相邻两项正好相差 2？因为每个表项都是一个字。输入的字符是 ASCII 码，'1'～'5' 连续排列，所以要查第几个表项，位移量恰好是

$$
(n-'1')\times 2
$$

这里的 $n$ 是输入字符对应的序号。换成机器里的减法，就是先从 `AL` 中减去 '1'，再乘 2：

| 输入字符 | $n-'1'$ | 表内位移量 | 取得的入口 |
| :--- | :---: | :---: | :--- |
| '1' | 0 | 0 | `G1` |
| '2' | 1 | 2 | `G2` |
| '3' | 2 | 4 | `G3` |
| '4' | 3 | 6 | `G4` |
| '5' | 4 | 8 | `G5` |

整条路径只有一条：

```text
键盘输入 n
     ↓
先检查 1 ≤ n ≤ 5
     ↓
计算 (n - '1') × 2
     ↓
TABLE + 位移量
     ↓
取出目的入口的偏移地址
     ↓
间接跳到 G1～G5 中对应的一项
```

#### 核心指令怎样衔接

输入字符还在 `AL` 中。先用 `AND AL, 0FH` 去掉 ASCII 高四位中的字符编码部分，留下数字 1～5；再减 1，把序号改成 0～4；左移一位就完成了乘 2。由于结果仍在正数范围内，随后用 `CBW` 扩展到 `AX`，`AX` 就得到了表内位移量。

```asm
CHECK_INPUT:
    MOV AH, 01H
    INT 21H
    CMP AL, '1'
    JB CHECK_INPUT
    CMP AL, '5'
    JA CHECK_INPUT
    AND AL, 0FH
    DEC AL
    SHL AL, 1
    CBW
    LEA BX, TABLE
    ADD BX, AX
    JMP WORD PTR [BX]
```

这里不要漏掉前面的范围检查。若用户误按 `0`，直接做减 1 会得到一个很大的无符号结果；若误按 `6`，同样会越出这张表。只有先确认输入落在 '1'～'5' 内，后面的索引计算才有意义。

`LEA BX, TABLE` 取得跳转表的首地址，`ADD BX, AX` 按计算结果定位表项。`BX` 使用间接寻址，`JMP WORD PTR [BX]` 取出其中的字作为转移目的地址。因为表默认在数据段中，这段读取使用的是 `DS:BX`。

> **结论**：跳转表法不是少写几个 `CMP` 那么简单，它把“输入序号”直接转换成“目的地址在表内的位移量”。分支越多，这种方法越能避免一长串重复比较。

### 跳转表也可以放进代码段

跳转表当然可以放在数据段中，但它也能直接定义在代码段。两种办法看起来只差一个表项中装的东西，转移过程却不一样。

#### 表中放入口地址

数据段跳转表中装的是 `OFFSET G1`～`OFFSET G5`。取出表项后，程序直接跳到对应功能入口，中间只有一次转移：

```text
BX 定位表项 → 取出 G3 的偏移地址 → 直接到 G3
```

#### 表中放跳转指令

代码段中的跳转表不直接存 `G1`～`G5` 的偏移地址，而是放五条跳转指令：

```asm
TABLE:
    JMP G1
    JMP G2
    JMP G3
    JMP G4
    JMP G5
```

CPU 找到某条 `JMP` 指令后，先执行它，再由这条指令跳到真正功能入口，因此变成了两次转移：

```text
BX 定位代码表项 → 执行其中的 JMP → 到 G3
```

若每条 `JMP Gx` 实际编码为 3 字节，那么五个表项的起始位置依次相差 3：

```text
第 1 条 JMP：TABLE + 0
第 2 条 JMP：TABLE + 3
第 3 条 JMP：TABLE + 6
第 4 条 JMP：TABLE + 9
第 5 条 JMP：TABLE + 12
```

这时索引不能还按 2 字节计算，而要改成

$$
(n-'1')\times 3
$$

对应的核心指令如下：

```asm
    AND AL, 0FH
    DEC AL
    MOV BL, 3
    MUL BL
    LEA BX, TABLE
    ADD BX, AX
    JMP WORD PTR CS:[BX]
```

`MUL BL` 把 `AL` 中的 0～4 乘以 3，结果在 `AX` 中。由于这次表定义在代码段，间接寻址必须加 `CS:`；若省略它，CPU 会按默认的 `DS:BX` 去数据段取内容，得到的就不会是这张代码段中的跳转指令。

还有一个必须记住的边界：若表内先使用短转移，只有目标与表项之间的相对位移能被一个 8 位有符号数表示时才合适。若入口离表太远，汇编后指令会改用更长、位移字段更宽的编码，表项长度随之改变。这时不能再机械套用固定步长，要以实际生成的指令长度为依据。

> **易错点**：代码段跳转表存的是“跳转指令”，不是“跳转指令的地址”。因此 `CS` 不能省，索引步长也不能脱离指令实际长度硬套。

### 向屏幕和打印机输出

#### 屏幕输出与回车换行

02H 号功能调用用于向屏幕输出一个字符。它与前面的键盘输入不同：这次需要入口参数，输出字符放在 `DL` 中。

```asm
MOV DL, '5'
MOV AH, 02H
INT 21H
```

这里不会把“字符 5 的键盘输入动作”再做一遍，而是把 `DL` 中给出的字符直接送到屏幕当前光标处。功能号仍然放在 `AH`，字符仍然需要 ASCII 码。

这一部分最值得记住的是回车与换行。屏幕上原来的一行显示完后，光标停在末尾。如果想从下一行重新显示，逻辑上要做两件事：先回到本行最左端，再向下移动一行。

- `0DH` 是回车字符的 ASCII 码，作用是把光标送回本行最左端；
- `0AH` 是换行字符的 ASCII 码，作用是让光标向下一行移动。

所以，完整的回车换行要连续输出这两个字符：

```asm
CRLF:
    MOV DL, 0DH
    MOV AH, 02H
    INT 21H
    MOV DL, 0AH
    MOV AH, 02H
    INT 21H
    RET
```

在 DOS 菜单或人机对话中，一句话显示完，下一句通常从下一行开始，因此经常要用到这段操作。如果它会反复出现，就可以把它独立成子程序；需要回车换行时调用它，既省代码，也不容易只写一半。

> **注意**：回车和换行是两个字符、一个组合效果。只做其中一个，并不等价于完整的“换到下一行左端”。

#### 打印机输出

05H 号功能调用也输出一个字符，入口字符同样放在 `DL`，区别是输出设备不是屏幕，而是打印机。

```asm
MOV DL, '5'
MOV AH, 05H
INT 21H
```

因此，02H 与 05H 的程序结构几乎一样，真正决定输出到哪里的是功能号，不是输入字符的位置。

#### 可见字符与非可见字符

程序里的字符最终是数值。数字、字母有各自的 ASCII 码；回车、换行、空格也各有一个 ASCII 码，但它们不会显示成一个普通字形，所以属于非可见字符。

至少要把下面几组记牢：

- 数字字符的编码；
- 字母的编码，至少熟悉 `A`～`F` 的大写与小写；
- 回车 `0DH`；
- 换行 `0AH`；
- 空格 `20H`。

程序写 `'5'` 时，装进寄存器的是这个字符的 ASCII 码，而不是键盘上那个“按键动作”。DOS 输出调用看到的是数值，再把对应字符送到屏幕或打印机。

### 06H 号功能：不等按键，先看有没有按键

06H 号功能叫作直接控制台输入输出。它比较特别，因为同一个功能号会根据 `DL` 的内容完成不同工作：

- 当 `DL` 不为 `0FFH` 时，把 `DL` 中的字符输出到屏幕；
- 当 `DL` 等于 `0FFH` 时，改为检查键盘输入。

输入方式与 01H、07H、08H 的根本区别是：**它不等待用户按键。** CPU 执行调用后立即往下走，结果由标志位告诉程序。

```text
DL = 00H～FEH → 向屏幕输出 DL 中的字符
DL = FFH      → 检查键盘
                 ├─ 有键：ZF=0，字符 ASCII 码在 AL
                 └─ 无键：ZF=1，程序立即继续
```

如果 `AL` 中没有得到字符，就不能把它当成有效按键来判断。06H 号真正适合的，是程序一边工作，一边轮询键盘是否已有输入。

```asm
WAIT_KEY:
    MOV DL, 0FFH
    MOV AH, 06H
    INT 21H
    JZ WAIT_KEY
    CMP AL, 1BH
    JE MAIN_MENU
    JMP REDO_CURRENT
```

这里的逻辑非常直白：

- 没有按键时，`ZF=1`，`JZ` 跳回 `WAIT_KEY`，继续检查；
- 有了按键时，`ZF=0`，字符进入 `AL`；
- 若该字符是 `ESC`，它的 ASCII 码为 `1BH`，程序返回主菜单；
- 若不是 `ESC`，就重新执行当前功能。

数据流可以概括为：

```text
某项功能执行完成
          ↓
06H / DL=FFH 检查键盘
     ↙            ↘
   无键             有键
     ↓               ↓
 继续检查       AL 是 1BH 吗？
                    ↙      ↘
                  是        否
                  ↓         ↓
               返回主菜单   重做当前功能
```

这正好解释了 06H 号调用的用途：它不是为了“阻塞着等人按键”，而是为了在某个功能完成后，马上问一句“用户现在按键了吗”。

### 选功能号时先问对问题

键盘输入的几个功能不要混着记。选号之前先问下面几个问题：

| 现在要做什么 | 应选功能号 | 关键区别 |
| :--- | :---: | :--- |
| 等一次按键，并显示出来 | 01H | 回显到屏幕 |
| 等一次按键，但不显示 | 07H | 不回显，检查 `Ctrl+Break` |
| 等一次按键，但不显示 | 08H | 不回显，检查 `Ctrl+C` |
| 不等待，只检查键盘是否有键 | 06H | `DL=0FFH`，用 `ZF` 判断结果 |
| 向屏幕输出一个字符 | 02H | 字符放在 `DL` |
| 向打印机输出一个字符 | 05H | 字符放在 `DL` |

再把多分支程序设计的方法合起来：菜单输入用 `1`～`5` 这样的连续序号，恰好适合查跳转表；每个分支的业务代码保持独立；功能结束后若要等待任意键，就用 06H 号轮询，再判断是否为 `ESC`。这样写出来的程序结构，比把五个比较和五段入口处理硬串在一起清楚得多。

### 本讲提到的题目

#### 题目

为 4.39 设计一个从键盘选择功能的程序：

- 先从键盘输入 `1`～`5`；
- 五个数字分别进入五个对应的功能入口；
- 某项功能执行完后，检测用户是否按键；
- 若按 `ESC`，返回主菜单；
- 若按其他键，重新执行刚才的功能。

#### 解析与答案

五项功能的具体业务仍要按原题处理，这里能确定的是控制结构。五个功能入口分别设为 `G1`～`G5`，建立如下跳转表：

```asm
TABLE DW OFFSET G1
      DW OFFSET G2
      DW OFFSET G3
      DW OFFSET G4
      DW OFFSET G5
```

输入合法时，用 $AL='1'$～`AL='5'` 计算 $(n-'1')\times2$，定位表项并间接转移：

```asm
    AND AL, 0FH
    DEC AL
    SHL AL, 1
    CBW
    LEA BX, TABLE
    ADD BX, AX
    JMP WORD PTR [BX]
```

功能结束后，再用 06H 号检测按键：

```asm
WAIT_KEY:
    MOV DL, 0FFH
    MOV AH, 06H
    INT 21H
    JZ WAIT_KEY
    CMP AL, 1BH
    JE MAIN_MENU
    JMP REDO_CURRENT
```

答案的关键不在于把五项功能再抄一遍，而在于把两类跳转分开：菜单到功能入口，用数据跳转表；功能结束后的 `ESC` 判断，用一次明确比较。入口多时仍只走一条公共索引路径，程序效率和控制逻辑都更清楚。

## DOS 功能调用中的字符串、输入缓冲与时间处理
> 对应块：BLK28 | 覆盖分集：P55-P56 | 块标题（分集名）：《55》

有些同学会担心：按下键的那一瞬间，检测程序是不是已经越过目标，等程序继续往下走，按键反而抓不住？从按键按下到弹起，通常至少会经历几十毫秒，而 CPU 执行程序的速度快得多。只要程序在这段时间里持续检测，就有不止一次机会确认按键状态。真正需要避免的，是只检测一次，然后把人的动作速度误当成程序的速度。

按键的保持时间给了程序观察机会，但这只是单字符输入的前提。前面讲的 `01H`、`07H`、`08H` 等调用，解决的都是“取一个字符”或“输出一个字符”。可是一个菜单不是几个孤零零的字符：

```text
1. 选择第一项
2. 选择第二项
3. 选择第三项
请选择 1～5：
```

菜单的每一行都是一串字符。逐个调用字符输出功能当然可以做，但每输出一个字符就调用一次，既啰嗦又容易漏掉边界。实际工程里更自然的做法，是把一串字符作为整体处理：显示时一次输出一串，接收输入时一次接收一整行，之后再对这串字符做转换、处理和回显。

### 逐字符调用和整串操作不是一回事

先把使用场景分开，程序设计就不会乱。

- 需要立刻知道用户按了哪个键时，可以使用前面讲的逐字符输入调用。它适合“按 `1` 就执行第一项，按 `2` 就执行第二项”这样的菜单分支。
- 需要读取一个名字、一个数字串或一行选择时，逐字符读取会迫使程序反复判断循环结束、回车和溢出。缓冲输入把这件事交给 DOS 完成，程序收到的是一整行。
- 需要把菜单、提示语或处理结果显示出来时，字符串输出调用比逐字符输出更合适。它从指定地址开始，连续把字符送到屏幕，直到遇到约定的结束标志。

所以，字符是输入输出的基本单位，字符串则是把多个字符按顺序组织起来的一块“拼图”。只要开始位置和结束位置说清楚，剩下的事情就可以交给程序按顺序处理。

### 字符串输出：让整串字符自己走到屏幕

DOS 的 `INT 21H` 功能调用中，`AH=09H` 用来向屏幕输出一个字符串。调用前，必须把字符串的首地址准备到 `DS:BX` 中：

- `DS` 指向字符串所在的数据段；
- `BX` 保存该数据段内的偏移地址，也就是字符串第一个字节的位置；
- `AH` 放入 `09H`；
- 执行 `INT 21H`。

字符串中的字符会从 `BX` 指向的位置开始逐个取出、送往屏幕，`09H` 会一直读取到遇到结束标志。这个结束标志是字符 `$`，它的 ASCII 码是 `24H`。结束标志本身不会被当成普通字符显示出来，但程序必须把它放在最后，告诉 DOS：“到这里为止，不要再往后读了。”

```text
DS:BX ──> 第 1 个字符 ──> 第 2 个字符 ──> …… ──> '$'
                                                        │
                                                        └─ 停止读取
                                                           光标停在字符串末尾
```

这就是 `09H` 与逐字符输出最重要的区别：它不需要一个单独的长度字段。没有 `$`，DOS 不知道字符串在哪里结束，就会继续读取后面的内存字节，屏幕上很快出现乱码；把 `$` 放在字符串中间，后面的内容就会被直接截断。`BX` 传的是起点，不是“最多读多少个字符”的限制。

#### 数据段和偏移地址要真正装入寄存器

字符串放在数据段中时，不能只写一个 `ASSUME` 声明，就以为运行时的 `DS` 已经自动变成了数据段。`ASSUME` 是给汇编器看的声明；真正运行时，还要把数据段地址装入 `DS`。

```asm
DATA SEGMENT
    MSG DB 'STRING', 0DH, 0AH, '$'
DATA ENDS

CODE SEGMENT
    ASSUME CS:CODE, DS:DATA
START:
    MOV  AX, DATA
    MOV  DS, AX
    MOV  BX, OFFSET MSG
    MOV  AH, 09H
    INT  21H
```

这里的 `OFFSET MSG` 得到的是 `MSG` 在 `DATA` 段中的偏移；`DATA` 则提供段地址。两者合起来，才是 `DS:BX` 指向的实际地址。若程序本来已经保证 `DS` 指向字符串所在段，装载 `DS` 的步骤可以省略；如果 `DS` 还指向别的段，就绝不能省。

字符串末尾的 `0DH`、`0AH` 是回车、换行字符。`09H` 不会自动替我们换行：只写普通字符，光标会停在最后一个字符的后面；想显示下一行，就要在 `$` 之前放入回车、换行组合。字符画和数据流示意必须放在围栏中，像下面这样写，渲染时才不会把对齐关系打乱：

```text
MENU_1 ── 0DH 0AH '$'
MENU_2 ── 0DH 0AH '$'
PROMPT ── 0DH 0AH '$'
```

每一行都要有自己的结束标志。输出多个菜单项时，通常是重复调用 `09H`，但每次都要把 `BX` 定位到对应的字符串：

```asm
    MOV  BX, OFFSET MENU_1
    MOV  AH, 09H
    INT  21H

    MOV  BX, OFFSET MENU_2
    MOV  AH, 09H
    INT  21H

    MOV  BX, OFFSET PROMPT
    MOV  AH, 09H
    INT  21H
```

> **易错点**：`09H` 不会替你寻找下一行，也不会自动在结尾补 `$`。它只认 `DS:BX` 给出的起点，以及内存中实际遇到的 `$`。一定要把每一段的起点和终点都准备好。

### 菜单、人机对话和结果回显

菜单只是字符串输出的一个直观例子。真正有用的时候，往往是“显示一段内容，接收一次选择，执行处理，再把结果显示出来”。比如课堂提到的 4.39 题中，有一个把字符串中的小写字母变成大写字母的处理任务；这个字符串可以事先在数据段中准备好，用户按键只是选择是否执行这项处理。

一个完整的人机对话可以按下面的流向组织：

```text
09H 显示菜单或提示
          ↓
01H / 07H / 08H 读取即时按键
或 0AH 等待一整行输入
          ↓
按选择进入相应处理分支
          ↓
处理字符串、转换字符或整理数据
          ↓
09H 把结果重新输出到屏幕
```

如果只是让用户按 `y` 或 `n`，逐字符调用很自然：提示语先用 `09H` 输出，读到 `y` 就继续，读到 `n` 就走另一条分支。若用户要输入的是一串文字，就不应该为了“看起来像输入”把每个字符拆成很多次调用，而应使用后面讲的缓冲输入。

这里还有一个经常被忽略的事实：程序把结果存进内存，并不等于人机交互已经完成。结果如果不回显，使用者就看不到；一个只能把数据藏在缓冲区里、却没有办法展示给用户的程序，功能是不完整的。输入、处理、输出三者要接得上，程序才真正有用。

### 缓冲输入：让整行输入落到缓冲区

前面讲的 `01H`、`07H`、`08H` 适合获取单个字符，但当程序希望从键盘取得一整串字符时，逐字符读取会让程序结构变得复杂。DOS 的 `0AH` 功能调用专门提供缓冲输入：程序先在内存中准备一个输入缓冲区，再把 `DS:DX` 指向它的起始位置，程序就可以等待用户输入一行内容。

`0AH` 的输入缓冲区不是一串随便排列的字节，而是有固定含义的结构：

| 缓冲区偏移 | 内容 | 谁负责写入 |
| --- | --- | --- |
| `0` | 允许输入的最大长度 | 程序预先设定 |
| `1` | 实际读入的字符个数 | `0AH` 返回时由 DOS 写入，不包含回车 |
| `2` 起 | 实际字符及最后的回车字符 | DOS 保存输入内容 |

因此，调用前要定义好最大输入长度和实际字符的存放空间。例如，允许的最大输入长度定义为 `20H` 时，可以这样组织缓冲区：

```asm
INPUT_BUF DB 20H
           DB ?
           DB 20H DUP(?)
```

第一个字节的 `20H` 是上限，第二个字节的 `?` 留给 DOS 回写实际长度，后面的 `20H DUP(?)` 是存放字符的空间。一个字节能够描述的长度最大到 `FFH`，这正是这里用一个字节保存长度描述符的原因。按照 DOS 的约定，最大长度要把最后的回车计算在内，所以整个缓冲区至少要预留“最大长度加两个描述字节”的空间；不要把 `20H` 简单理解成一定要输入满 32 个可见字符。

调用时，`DX` 必须指向整个输入缓冲区的第一个字节，而不是直接指向第三个字节处的字符区：

```asm
    MOV  AX, DATA
    MOV  DS, AX
    MOV  DX, OFFSET INPUT_BUF
    MOV  AH, 0AH
    INT  21H
```

程序执行到这里会等待用户输入，直到用户按下回车，才把这一行交给后续处理。返回以后，第二个字节就是实际输入的字符数 `N`，实际字符从 `INPUT_BUF+2` 开始，末尾的回车由 DOS 按规则放入缓冲区。有了 `N`，程序才知道应该处理多少个字符，不会把缓冲区里没有使用的空间也当成有效数据。

> **提示**：给实际字符区起一个有意义的名字非常有用。名字不只是为了让程序好读，更是为了让后面的代码能够明确地指向“实际输入的字符”，而不是反复猜偏移。

`0AH` 是输入功能，不是输出功能。若用户输入后还要把原串或处理结果显示出来，就要再调用 `09H`。这里有一个必须处理的边界问题：`0AH` 用回车表示输入结束，`09H` 却用 `$` 表示输出结束，两者的结束标志不一样。

```text
0AH 输入缓冲区： [最大长度][实际长度 N][字符 0]……[字符 N-1][CR]

09H 输出缓冲区： [要显示的字符]……[0DH][0AH]['$']
```

最稳妥的做法，是把处理后的字符复制到另一个输出缓冲区，再补上回车、换行和 `$`。如果直接复用输入缓冲区，就必须确认实际字符之后有足够空间放置 `$`，不能让输出功能越过后面的内存继续乱读。不能把 `0AH` 返回的缓冲区原封不动地当成一个已经带有 `$` 的 `09H` 字符串。

### 从键盘字符到可计算的数字

人机对话中经常遇到的另一类问题，是把用户输入的数字字符变成真正的数值。4.39 题的排序例子给出过一组十进制数：中间可能是 `5`，下一个可能是 `18`，再下一个可能是 `201`，另一个可能是 `9`，每个数不超过 `255`。输入得到的是字符序列，而排序需要比较的是数值大小，这两者之间必须经过转换。

键盘输入的数字字符仍然是 ASCII 字符。数字字符 `'0'` 到 `'9'` 的编码从 `30H` 到 `39H`，所以一个字符要先减去 `30H`，才能得到数值意义上的一个十进制数字：

| 处理阶段 | `5` 的表示 | `1` 的表示 | `8` 的表示 |
| --- | --- | --- | --- |
| 字符形式 | `'5'` | `'1'` | `'8'` |
| ASCII 码 | `35H` | `31H` | `38H` |
| 减 `30H` 后 | `5` | `1` | `8` |

对于多位数，不能只把每个字符单独减 `30H` 后拼起来。`201` 应当被理解成一个完整的十进制数：

$$201 = 2\times 10^2 + 0\times 10 + 1\times 1$$

常用的累进算法可以写成：

```text
R = 0
依次取出一个数字字符 c
    d = ASCII(c) - 30H
    R = 10 * R + d
```

处理 `'2'` 后，`R=2`；再处理 `'0'`，先得到 `2×10+0=20`；最后处理 `'1'`，得到 `20×10+1=201`。每一步都保留了已经读到的前缀，所以既可以处理一位数，也可以处理多位数。

> **易错点**：键盘读到的是字符，内存里进一步运算的则是数值。直接对 `'1'`、`'2'` 这些字符做算术，不会自动得到十进制数。先减 `30H`，再做乘十和加法，这才是从字符到数值的转换链。

CPU 最终保存和运算的仍然是二进制数。所谓的“把十进制字符串转换成数值”，并不是让机器换一种文字去存储，而是把字符逐位解释成数字，再用乘十、加法组合成机器内部可以参与运算的二进制结果。课堂把这看成“十进制表示到二进制表示”的转换，本质上就是一套由 CPU 执行的运算算法。

还有一个更一般的 16 位转换例题：把用 ASCII 字符表示的十进制数转换成 16 位二进制数值。程序可以在专用缓冲区中记录位数，再逐位处理字符，把结果放入另一个缓冲区。逐位乘十、加法的过程和前面完全相同，但这里要额外检查结果是否超出一个 16 位字的范围。

```text
ASCII 数字串
      │  逐位取出
      ▼
数字字符 ──减 30H──> 单个数字
      │  乘十并累加
      ▼
16 位结果 ──范围检查──> 有效结果 或 错误标志
```

如果结果超过 16 位，不能把被截断的低位当成正确结果继续使用。程序应当设置一个自己约定的错误标志，并在后续处理中检查它。这里再次体现了一个原则：数据转换不只是“算出一个数”，还要把结果是否落在允许范围内说清楚。

### 系统时间的设置与获取

时间处理是同一个模块里的另一个实际例子。屏幕上显示一个“电子表”，表面上只是显示几时、几分、几秒，但这些字段必须先从系统时间中取得；如果要修改时间，则要走设置调用。系统时间和硬件校准不是一回事，程序把时间写进去，并不等于已经完成了硬件时钟的校准。

DOS 通过 `INT 21H` 提供时间设置和获取功能。设置系统时间时，功能号为 `2DH`。调用前要把时、分、秒分别放入 `CH`、`CL`、`DH`，`DL` 放夏令时标志：

```asm
    MOV  AH, 02DH
    MOV  CH, HOUR
    MOV  CL, MINUTE
    MOV  DH, SECOND
    MOV  DL, DAYLIGHT
    INT  21H
    CMP  AL, 00H
    JE   TIME_SET_OK
    ; AL = FFH：设置失败
TIME_SET_OK:
```

这里一定要检查返回的 `AL`。`AL=00H` 表示设置成功，`AL=FFH` 表示设置失败。设置完成后不能不看返回值就直接宣布时间已经改好；失败时，程序还应当给出自己的处理路径。

获取系统时间时，功能号为 `2CH`：

```asm
    MOV  AH, 02CH
    INT  21H
    ; CH = 小时，CL = 分钟，DH = 秒
    ; DL = 夏令时标志
```

获取结果的时、分、秒字段采用 BCD 形式保存。一个字节的高半字节表示十位，低半字节表示个位，因此显示时要把两部分拆开。设字段为 `b`，其十进制数值为：

$$value = 10\times high(b) + low(b)$$

例如 BCD 字节的高半字节为 `1`、低半字节为 `2`，表示的就是 `12`。如果不需要处理夏令时，`DL` 可以不使用；但时、分、秒三个字段要按顺序取出来，再交给字符串输出逻辑组成“时:分:秒”的显示内容。

> **提示**：设置和获取要分开看。`2DH` 改变系统时间并用 `AL` 报告成败，`2CH` 读取系统时间并把字段放入寄存器。把两个方向的参数放反，或者把 BCD 字段直接当作普通二进制数，都会得到错误结果。

### 把这些调用接成一条完整的人机交互链

现在回头看，前面的内容其实围绕一条很清楚的链展开：

```text
准备菜单字符串
      ↓
09H：把菜单和提示送到屏幕
      ↓
01H / 07H / 08H：读取即时按键
或 0AH：等待一整行输入
      ↓
根据实际长度处理字符
      ↓
ASCII 数字转换、排序或其他处理
      ↓
09H：把结果和提示重新显示
      ↓
2CH：读取系统时间；2DH：设置后检查 AL
```

各功能的边界可以这样记：

| 任务 | 功能调用 | 关键入口或返回 | 最重要的结束条件 |
| --- | --- | --- | --- |
| 输出一串已有字符 | `09H` | `AH=09H`，`DS:BX` 指向首字节 | 遇到 `$`，不自动换行 |
| 接收一整行输入 | `0AH` | `AH=0AH`，`DS:DX` 指向缓冲区 | 遇到回车，实际长度写入第二个字节 |
| 读取系统时间 | `2CH` | `INT 21H` 后读 `CH/CL/DH`，必要时看 `DL` | 返回的是 BCD 时、分、秒字段 |
| 设置系统时间 | `2DH` | 调用前准备 `CH/CL/DH/DL` | `AL=00H` 成功，`AL=FFH` 失败 |

真正要掌握的，不只是把功能号背下来，而是知道每个函数“数据从哪里来、到哪里去、靠什么标志结束、返回后哪些寄存器可信”。`09H` 的 `$`、`0AH` 的回车和实际长度、ASCII 转数值的减 `30H` 与乘十加法，以及时间字段的 BCD 形式，正好分别对应了字符串、输入、数值和时间四条边界。

多读教材中的程序例题，不是为了多记几行代码，而是为了让程序阅读能力真正提高。能读懂数据如何进入寄存器、缓冲区如何组织、判断何时成立，编写程序时才不会把每一个边界都写成偶然正确的样子。

### 本讲提到的题目

- **将字符串中的小写字母变成大写字母**：这是人机对话中的处理例子。先用字符串输出显示任务或选择，再按用户按键决定是否执行；处理完成后要回显结果，不能只把结果留在内存里。
- **输入一组十进制数并进行排序**：课堂给出的例子包括 `5`、`18`、`201`、`9`，每个数不超过 `255`。关键是先把 ASCII 数字字符逐位转换成数值，再进行后续比较；逐位转换使用“减 `30H`、乘十、相加”的方法。
- **编写子程序，把 ASCII 表示的十进制数转换为 16 位二进制数值**：位数放在转换缓冲区的相应字段中，结果写入结果缓冲区；如果结果超出一个 16 位字的范围，就设置并检查错误标志。
- **在屏幕上显示系统时间**：用 `2CH` 取得 `CH`、`CL`、`DH` 中的时、分、秒，按 BCD 方式拆出十位和个位，再组成显示字符串；用 `2DH` 设置时间时，则必须检查 `AL` 的成功或失败返回值。

## 让时间动起来，并让整块数据搬起来
> 对应块：BLK29 | 覆盖分集：P57-P58 | 块标题（分集名）：《57》

上机题里最容易给人错觉的，往往是“程序已经能显示一个字”。字能出现在屏幕上，只说明输出链走通了一步；像时间这样会变化的内容，还要重新取数、重新转换、重新显示。把这件小事做完整以后，我们又会碰到另一类问题：一整块数据怎样批量搬运、比较和搜索？这正是 8086 串操作指令要解决的事情。

### 上机题中的动态时间显示

以 4.39 题的动态时间显示为例，程序取到时间以后，不能把一串二进制数直接丢到屏幕上。二进制时间要先变成人能读懂的十进制数字；十进制数字还要变成相应字符的 ASCII 码，CPU 才能把字符送到显示位置。转换十进制整数时，常用的推导是反复除以 10、取余数，再把余数逆序组合。

因此，动态刷新至少包含下面几层工作。

```text
把光标定位到预定位置
          ↓
读取当前时间
          ↓
二进制整数 → 十进制数字
          ↓
十进制数字 → ASCII 字符
          ↓
按位置显示字符
          ↓
再次读取时间并重复
```

这里有两条流程不能混在一起：二进制转十进制，是数值表示方式的转换；数值转 ASCII 码，是字符编码的转换。只做前一步，屏幕上仍然没有可显示的字符；只做后一步，又会把错误的数值当成字符写出去。

> **易错点**：取到时间、显示一次，不等于动态时间已经完成。显示结束后必须再次取时间，刷新流程要形成循环。

刷新频率太低时，肉眼会看到字符在闪。课堂用约 40 Hz 作为经验量级说明这个现象：频率偏低时仍可能看出它在晃动，提高以后就不容易察觉。这个经验值不是所有显示器都相同的固定标准，但道理不变——显示位置、字符内容和刷新节奏必须配合起来。

屏幕底色、字符属性和字体颜色也可以设置，不过 4.39 题当前要抓住的主线仍是“取时间—转换—显示—再取时间”。先把控制流程跑完整，再处理颜色和界面细节。

### BIOS 功能调用与屏幕组织

接着看 4.39 题中频繁出现的 BIOS 功能调用。BIOS 与 DOS 的功能号和入口参数有自己的约定，做题或查阅实际程序时不能混用。调用 BIOS 功能时，入口是软件中断指令，功能号放在 `AH` 中，参数再按规定放进其他寄存器。

#### 显示模式与光标位置

`INT 10H` 的 `00H` 功能用于设置显示方式。模式值放在 `AL` 中；`AL=3` 对应 80 列、25 行的彩色文本模式。文本模式还可以选择黑白文本、彩色或黑白图形等，模式改变后，屏幕的行列范围也随之确定。

80 列、25 行表示屏幕上共有 $80\times25=2000$ 个字符位置，约为 2K 个字符位置。这里一定要把“字符位置”与“整页显存”分开：显示时还要为属性等信息安排空间，不能拿 2K 直接当作整块显示缓冲区的全部容量。模式设置完成时，画面会被清理，光标也随之回到可用文本区的左上角。

光标定位用 `INT 10H` 的 `02H` 功能。通常把行号放进 `DH`，列号放进 `DL`，两个坐标都从 0 起算，所以 25 行对应行号 0～24，80 列对应列号 0～79。

```text
文本屏幕左上角 (0,0)
          ●
          │  行号向下增加
          │
          └──────────────→ 列号向右增加

          行：0～24
          列：0～79
```

> **易错点**：有的教材画图从第 1 行、第 1 列开始讲，便于人阅读；汇编接口的坐标通常从 0 开始。行列含义弄反，字符就会跑到另一处位置。

定位以后，才能用 `INT 10H` 的 `09H` 功能在当前光标处写字符。缓冲区中已经转换好的字符，需要按显示次序送到光标位置；不能只完成了数值转换，却忘了真正执行字符输出。

#### 显示页与显存范围

设置显示方式后，可以在不同显示页之间切换，程序中常选 0 页。一块显示页按整页显存空间理解，容量通常以 8K 来说；真正可显示的 80×25 文本区则按 2000 个字符位置计算。显示页号、每页可用容量和显存首地址是三个相关但不相同的问题，必须按对应显示方式查表或查手册。

```text
显示页
┌──────────────────────────────────┐
│ 当前模式允许的文本显示区          │
│ 80 列 × 25 行 = 2000 个字符位置  │
├──────────────────────────────────┤
│ 属性及其他页内空间                │
└──────────────────────────────────┘
```

在 4.39 题这类上机程序中，初始化、设光标、写字符等 BIOS 功能会反复出现。`00H`、`02H`、`09H` 以及显示页切换功能，不是互不相干的小知识，它们共同组成“把字符送到屏幕”的控制流程。显示页还可以设置底色、字符属性和颜色，但写显存时绝不能越过当前模式允许的文本范围，否则可能破坏相邻页面或预留区域。

### 为什么需要串操作指令

8086 的指令系统已经提供了普通的 `MOV` 等数据传送指令。单个字节或字当然可以逐个处理，可实际工程中经常面对的是一整块连续数据。比如内存中有一个 4 字节的数据块，既可以看成 4 个字节，也可以看成 2 个字；如果要让其中每个单元执行相同动作，用普通指令也能写循环，但每写一次都要重复描述取数、处理、存回、移动指针和判断结束。

串操作指令就是为这种重复劳动准备的。它把“对一串同类型数据做同一种处理”交给 CPU 专门完成，减少程序中重复的循环框架。

8086 的串操作指令共有五类。

| 类别 | 字节形式 | 字形式 | 每一步处理的对象 |
| :--- | :--- | :--- | :--- |
| 串传送 | `MOVSB` | `MOVSW` | 把源串当前单元送到目的串当前单元 |
| 串比较 | `CMPSB` | `CMPSW` | 比较源串与目的串的对应单元 |
| 串扫描 | `SCASB` | `SCASW` | 在目的串中查找 `AL` 或 `AX` 指定的字符 |
| 串装入 | `LODSB` | `LODSW` | 把源串当前单元取入 `AL` 或 `AX` |
| 串存储 | `STOSB` | `STOSW` | 把 `AL` 或 `AX` 存入目的串当前单元 |

`CMPSB` 和 `CMPSW` 的思路与减法比较一致：CPU 做相减来判断大小关系，但不把差保存下来，只保留比较结果形成的标志。判断两个串是否相等时，可以逐项比较；只有全部对应项都相等，整个串才相等。`ZF=1` 表示这一次比较的对应单元相等，不能反过来理解成“重复次数已经结束”。

串扫描可以理解为串搜索。例如，要在一段文本中寻找空格，就把空格字符放入 `AL`，让 `SCASB` 拿它与目的串当前单元比较：相等表示找到，不相等则继续扫描。串装入和串存储则分别完成“存储器到寄存器”与“寄存器到存储器”的单元素处理。

> **结论**：普通 `MOV` 与串操作不是同一个概念。`MOV` 适合寄存器与存储器等常规传送，不能在一条指令中直接完成两个存储器区域之间的传送；`MOVSB`、`MOVSW` 正是为这种源串到目的串的成批搬运设置的。

### 串操作的隐含寄存器

串操作指令很短，是因为它把大量约定隐藏在指令形式里。只看 `MOVSB` 这几个字母，完全看不出数据从哪里来、到哪里去；真正执行前，必须把隐含的寄存器和偏移地址准备好。

#### 存储器串与寄存器串

当源串和目的串都在存储器中时，源地址由 `DS:SI` 给出，目的地址由 `ES:DI` 给出。若源或目的改为寄存器，则使用 `AL` 或 `AX`：字节操作使用 `AL`，字操作使用 `AX`。

```text
存储器到存储器：
源串 ── DS:SI ──→ 目的串 ── ES:DI ──→

存储器到寄存器：
DS:SI ──→ AL（字节）或 AX（字）

寄存器到存储器：
AL（字节）或 AX（字） ── ES:DI → 目的串
```

目的串在存储器中时，目的段地址必须由 `ES` 提供。源串的段地址可以按需要改变，例如使用段超越前缀；这一点与目的串不同，不能把 `DI` 指向目的偏移后，又随便换一个段寄存器去提供目的段地址。

#### 方向标志决定地址走向

地址指针不是只初始化一次。串操作每处理一个单元，`SI` 或 `DI` 都要自动移动，移动方向由方向标志 `DF` 决定。

- `DF=0`：地址递增；
- `DF=1`：地址递减；
- 字节操作一次改变 1；
- 字操作一次改变 2。

```text
DF = 0
源：   [0] [1] [2] [3] [4] ...
目的： [0] [1] [2] [3] [4] ...
        →  →  →  →  →

DF = 1
源：   ... [4] [3] [2] [1] [0]
目的： ... [4] [3] [2] [1] [0]
        ←  ←  ←  ←  ←
```

例如执行 `MOVSB` 时，`DF=0` 就让 `SI`、`DI` 自动加 1；`DF=1` 时自动减 1。`MOVSW` 每次搬一个字，指针则加 2 或减 2。`CLD` 把 `DF` 置 0，要求按地址递增方向处理；`STD` 则把 `DF` 置 1。题目说“顺序搬运”时，我们通常要明确写出 `CLD`，不能依赖程序启动时标志位的偶然状态。

### 重复前缀把一次操作变成循环

`CX` 用来保存重复次数。串操作本身完成一个单元的传送、比较、扫描、装入或存储；前面再加上重复前缀，CPU 就会在条件满足时继续执行同一串操作。

| 前缀 | 继续执行的条件 | 主要用途 |
| :--- | :--- | :--- |
| `REP` | `CX≠0` | 串传送、串装入、串存储，也可用于串比较 |
| `REPE` / `REPZ` | `CX≠0` 且 `ZF=1` | 串比较、串扫描 |
| `REPNE` / `REPNZ` | `CX≠0` 且 `ZF=0` | 串比较、串扫描 |

`REP` 的执行过程可以抽象为：先执行一次串操作，再把 `CX` 减 1；减 1 后不为 0，就返回执行同一条串操作，减到 0 才结束。`SI` 和 `DI` 管“下一次到哪里取、放”，`CX` 管“还要做多少次”，二者职责不能混淆。

`REPE` 和 `REPNE` 除了检查 `CX`，还要检查 `ZF`。比较时，`ZF=1` 表示本次对应单元相等；扫描时，则由当前扫描单元是否与 `AL` 或 `AX` 相等来决定 `ZF`。所以“比较结果为零”和“计数寄存器 `CX` 为零”完全是两回事。

> **易错点**：普通重复不等于比较或扫描的结束条件。`REPZ` 需要结果相等才继续，`REPNZ` 需要结果不相等才继续；忘了检查 `ZF`，就得不到预期的查找或匹配过程。

### 串传送指令怎样完成一次搬运

`MOVSB` 和 `MOVSW` 的源、目的操作数都是隐含的。指令中可能通过类型说明让汇编程序判断按字节还是按字处理，但真正执行时，地址仍由约定的寄存器和偏移地址提供。

`BYTE PTR`、`WORD PTR` 之类的类型说明是在告诉汇编程序“按字节还是按字解释这块数据”，它不是额外的搬运动作。源串和目的串的类型必须一致：若 `MOVSB` 搬的是字节，两边就都必须是字节；若 `MOVSW` 搬的是字，两边就都必须是字。

一次 `MOVSB` 的执行过程可以拆成三步。

```text
第一步：按 DS:SI 取出源字节，写入 ES:DI 指向的目的位置
第二步：按 DF 和字节类型调整 SI、DI
第三步：若有 REP 前缀，则 CX ← CX - 1；
        CX≠0 时继续，CX=0 时结束
```

`MOVSW` 的差别只在第二步：指针按 2 改变，搬运对象也从一个字节变为一个字。`REP MOVSB` 则把第三步接回第一步，直到预先写入 `CX` 的次数用完。

> **提示**：传送、装入、存储不是用于比较大小，因此搬运本身不要被误当成一次算术比较；串比较和串扫描才通过比较产生相应标志。

### 用串指令搬动 BUFF 数据块

把一段数据从普通 `MOV` 的逐字节传送方式改写成串操作，关键不在“换了一个助记符”，而是把地址、方向、次数和寄存器关系一次配齐。书中的 3.36 例题要求把存储区域 `BUFF1` 中的 100 个字节按顺序传送到 `BUFF2`，正好把 `SI`、`DI`、`ES`、`CX` 和 `DF` 串在一起。

先为两块数据保留空间：

```asm
BUFF1  DB  100 DUP(?)
BUFF2  DB  100 DUP(?)
```

`BUFF1` 是源串，`BUFF2` 是目的串。`CX` 中放 100，因为这里使用的是 `MOVSB`，每次处理 1 个字节。若把 `CX` 写错，即使指令能够执行，搬运的数据量也会随之出错。

在小型存储模型中，可以按下面的方式组织程序。下面的代码只完成 3.36 例题要求的顺序传送，并按课堂讲到的方式结束程序。

```asm
.MODEL SMALL

.DATA
BUFF1  DB  100 DUP(?)
BUFF2  DB  100 DUP(?)

.CODE
START:
        MOV  AX, @DATA
        MOV  DS, AX
        MOV  ES, AX

        LEA  SI, BUFF1
        LEA  DI, BUFF2
        MOV  CX, 100
        CLD
        REP  MOVSB

        MOV  AH, 4CH
        INT  21H

END START
```

这里把 `DS` 和 `ES` 初始化到同一个数据段，是因为 `BUFF1`、`BUFF2` 都放在这个段中。若目的数据另放在附加段，就必须让 `ES` 指向目的段，不能因为源段设好了，就认为目的段也一定正确。

`CLD` 把方向置为递增。每执行一遍 `MOVSB`，程序完成下面的控制流程。

```text
BUFF1 当前字节 ──→ BUFF2 当前字节
          │                  │
          └─ SI 加 1          └─ DI 加 1
                         CX 减 1
                            │
                 CX≠0：继续搬下一个字节
                 CX=0：100 字节全部搬完
```

重复 100 次后，`BUFF1` 的 100 个字节便按原顺序落到了 `BUFF2`。这就是串指令相对于逐条写普通传送循环的直观价值：数据块仍然由一个字节一个字节地搬，但“取、放、移指针、减计数、是否继续”的规则已经统一固化在指令中。

#### 动态时间显示

4.39 题的这一问，要让已经取得的时间持续显示并在内容变化后更新。答案不是只写一次输出调用，而是先定位光标，再取时间，把二进制时间转换为十进制数字，将数字转成 ASCII 字符并显示；显示结束后回到取时间处，重复整个过程。

## 串传送与串比较：REP 前缀、方向控制与重叠搬移
> 对应块：BLK30 | 覆盖分集：P59 | 块标题（分集名）：《59》

如果没有串传送指令，我们当然也能把一个数据单元送到另一个地方：先从源单元取出数据，再写向目的单元，然后修改地址、修改计数器，最后判断是否搬完。功能上并没有错，可每搬一个字节或一个字，都要把这套机械过程重复写一遍。

为什么不直接让处理器完成这件事？这正是 `MOVSB` 和 `MOVSW` 的出发点。它们把最常用的成串数据搬移压缩成一条明确的操作：源地址由 `SI` 给出，目的地址由 `DI` 给出，一次搬一个字节或一个字，随后按方向标志自动修改地址。

不过，指令短并不意味着前面的初始化可以省掉，搬完以后也仍然要判断计数是否归零。串操作只解决了重复动作本身，没有替我们解决数据从哪里来、放到哪里去、搬多少次，以及遇到地址重叠时该朝哪边走。

> **结论**：`MOVSB`、`MOVSW` 适合连续数据搬移；`CMPSB`、`CMPSW` 适合连续数据比较。两者都依赖地址指针和计数寄存器，具体行为则由 `DF` 与 `REP` 前缀决定。

### 串传送的两个操作数放在哪里

串传送指令没有像普通传送指令那样把源、目的操作数直接写在指令中，而是使用两个隐含的地址指针：

- 源操作数默认取自 `DS:SI`；
- 目的操作数默认写入 `ES:DI`。

因此，使用之前仍要先完成必要的初始化：把源区域的首址或末址送入 `SI`，把目的区域的首址或末址送入 `DI`，并在 `ES` 已经指向目的区域的前提下，把 `CX` 设置为需要传送的字节数或字数。源数据不在默认 `DS` 段时，还要在相应位置加段超越前缀；目的侧则固定使用 `ES`。

`MOVSB` 每次传送一个字节，完成后地址指针按 1 改变；`MOVSW` 每次传送一个字，完成后地址指针按 2 改变。到底增大还是减小，取决于方向标志 `DF`：

| 方向标志 | 指针变化 | 适用场景 |
| :--- | :--- | :--- |
| `DF=0` | `SI`、`DI` 随每次操作增大 | 从低地址向高地址传送 |
| `DF=1` | `SI`、`DI` 随每次操作减小 | 从高地址向低地址传送 |

这里一定要记住：串传送指令不会凭空替我们完成初始化。`SI`、`DI`、`CX` 和 `ES` 该准备什么，程序仍要明确写出来。`CX` 负责计数，传送指令负责完成一次动作；数据是否已经全部送完，还要看计数是否已经减到零。

### 为什么一定要设置 DF

前面的传送例子为了便于分析，理想化了源区域和目的区域互不重叠。两种方向都能得到正确结果，所以看上去只要把首地址分别装入 `SI` 和 `DI`，再反复执行串传送即可。

可是在实际数据搬移中，源区域与目的区域可能相邻，甚至部分重叠。这时传送方向不再是风格选择，而是正确性问题。

假设源区域位于低地址，目的区域位于高地址：

```text
低地址                                            高地址
  [源1] [源2] [源3] [目的1] [目的2] [目的3]
     →     →     →
```

如果按地址增大的方向从左向右搬，`源1` 写入较远的 `目的1`，`源2` 写入较远的 `目的2`，尚未读取的源数据不会被前面的写入覆盖，因而安全。

反过来，若源区域位于高地址，目的区域位于低地址，就必须从高地址向低地址搬：

```text
低地址                                            高地址
  [目的1] [目的2] [目的3] [源1] [源2] [源3]
                       ←     ←     ←
```

若仍从低地址向高地址搬，刚写下的数据可能落在尚未读取的源区域中，后续读到的是已经搬过去的新内容，原数据便被破坏。程序表面上传送次数没错，结果却会错得离谱。

> **结论**：源地址低于目的地址时，按地址增大方向搬；源地址高于目的地址时，按地址减小方向搬。这个判断针对的是两个地址指针，不是“看哪边更长”，也不能凭源、目的块在纸面上画在哪里来判断。

### 在搬移程序中判断传送方向

处理可能重叠的数据块时，不能只凭例题里的示意图决定方向，而应在程序中比较 `SI` 与 `DI`。如果源指针低于目的指针，就走地址增大的方向；否则走地址减小的方向。

核心分支可以写成下面的形式：

```asm
        CMP     SI, DI
        JB      BACKWARD
        CLD
        JMP     MOVE_START
BACKWARD:
        STD
MOVE_START:
        ; 在这里放置串传送及循环控制
```

在反向传送分支中，还要让两个指针都从高地址端开始，每处理一个字分别给 `SI`、`DI` 加上负 2；循环结束后再分别加回 2。若处理的是字节，步长则改成 1。转向分支时，地址也只按 1 或 2 改变。

为什么要加“段超越前缀”，为什么两个指针各减一次后又加回来，这些都不是装饰。指针必须先落到本次真正要访问的单元，循环结束后也要恢复到可预期的状态。否则表面上完成了搬移，指针却已经落在最后一项之后或之前，后续代码很容易因此取错地址。

方向判断和循环控制补进去以后，无论两块数据怎样分布、是否存在重叠，搬完后的结果才都是正确的。这个结论一定要记住，不能只掌握“不重叠时两个方向都行”的理想情况。

### 串比较为什么通常使用 CMPSW

搬移之后经常紧跟着另一个问题：两个数据块中的对应内容是否相同？如果用普通传送指令完成比较，不仅要把两个单元读出来，还要做减法并检查标志位，操作非常啰嗦。`CMPSB` 和 `CMPSW` 把这个固定模式做成了串比较指令。

`CMPSB` 每次比较一个字节，`CMPSW` 每次比较一个字。`CMPSW` 的隐含地址仍然是 `DS:SI` 与 `ES:DI`，但它不把源数据送到目的单元，而是用两个操作数做减法，并根据差设置状态标志。我们真正关心的是 `ZF`：

- `ZF=1`：两个操作数相等；
- `ZF=0`：两个操作数不相等。

一次比较后，指令不破坏源、目的单元中的数据，但会根据 `DF` 自动修改 `SI` 和 `DI`。`DF=0` 时各加 2，`DF=1` 时各减 2。比较了多少个数据，仍由 `CX` 给出。

这里最忌讳把“比较”误当成“传送”。`CMPSW` 做完的是减法与标志判断，不会把 `BUFF1` 中的字搬到 `BUFF2`；目的区域在这一步只是提供比较用的数据。

### REP 前缀把一次比较变成连续比较

只执行一条 `CMPSW`，只能比较一对字。要比较一整段数据，可以让串比较指令带上重复前缀，由处理器在内部递减 `CX`，并按比较结果决定是否继续。

前缀的差别只在一个地方：什么情况下继续，什么情况下停止。

| 前缀 | 继续执行的条件 | 停止条件 |
| :--- | --- | :--- |
| `REPE` 或 `REPZ` | `CX` 尚未归零且 `ZF=1`，本次仍然相等 | 计数归零，或发现不相等 |
| `REPNE` 或 `REPNZ` | `CX` 尚未归零且 `ZF=0`，本次仍然不相等 | 计数归零，或发现相等 |

`CX` 的递减只是控制还要比较多少次，真正决定是否继续的是比较产生的 `ZF`。这一点必须分清：计数递减本身不能代替“相等”或“不相等”的判断。

例如，`REPE CMPSW` 表示“只要还剩数据，而且当前两个字相等，就继续”。若中途发现第一处不等，`ZF` 被置 0，重复立即停止。若全部比较完都是相等，`CX` 归零后才停止，最终 `ZF` 仍为 1。

`REPNE CMPSW` 则正好反过来：“只要还有数据，而且当前两个字不相等，就继续。”它特别适合在一段数据中查找某一个字。找到相等项时，`ZF` 变为 1，重复停止；若所有位置都比较完仍没有找到，则由 `CX` 归零使循环结束。

### 缓冲区查找题怎样落地

现在看一个真正用到这套机制的问题。`BUFF1` 与 `BUFF2` 都是长度为 100 个字的数据区，要求从低地址到高地址逐个比较对应的字：

- 如果找到一对相同的字，就在 `ADDR` 中保存该字在 `BUFF1` 内的偏移地址；
- 如果始终没有找到，就让 `ADDR` 等于 $-1$。

既然我们的目标是“找到相等项就停”，前缀应当选 `REPNE`，不是 `REPE`。程序可以写成：

```asm
; 前提：DS 指向 BUFF1 所在段，ES 指向 BUFF2 所在段
        CLD
        MOV     SI, OFFSET BUFF1
        MOV     DI, OFFSET BUFF2
        MOV     CX, 100

        REPNE   CMPSW
        JNZ     NOT_FOUND

FOUND:
        MOV     AX, SI
        SUB     AX, OFFSET BUFF1
        SUB     AX, 2
        MOV     ADDR, AX
        JMP     DONE

NOT_FOUND:
        MOV     ADDR, 0FFFFH

DONE:
```

初始化部分有四件事不能少：用 `CLD` 规定按地址增大的方向比较，把 `BUFF1` 的偏移地址送入 `SI`，把 `BUFF2` 的偏移地址送入 `DI`，再把比较次数 100 送入 `CX`。`ES` 必须事先指向 `BUFF2` 所在段，不能因为写了 `DI` 就以为目的段也自动初始化好了。

循环退出后，先用 `ZF` 区分两种结局。`REPNE CMPSW` 只有在“找到相等字”或“100 个字全部比较完”时才退出：

- `ZF=1`：当前比较相等，确实找到了，转移到 `FOUND`；
- `ZF=0`：最后一个字仍不相等，说明整个缓冲区没有匹配项，进入 `NOT_FOUND`。

未找到标志写作 $-1$ 时，汇编中要写成 16 位全 1 的 `0FFFFH`，末尾的 `H` 不能省。这里的 `FFFF` 若不以数字形式书写，容易被汇编器当作符号而不是数值。

还有一个很容易漏掉的细节：即使 `CX` 在本次比较后恰好减到 0，`SI` 仍会先按方向加 2。此时它指向的是“找到的那个字”的下一个字，不是那个字本身。因此，匹配字在 `BUFF1` 中的偏移地址不是直接取 `SI`，而应按下面的关系还原：

```text
匹配项偏移地址 = SI - OFFSET BUFF1 - 2
```

这个减 2 不是修正错误，而是串指令的执行顺序决定的。比较、设置 `ZF`、修改地址指针、递减计数这几件事都已经发生；如果只在口头上想“找到时 `SI` 正好指着该项”，真正写程序时就会多算一项。

### 如果要求所有对应字都相同

前一道题是“只要找到一对相等字”，所以用 `REPNE CMPSW`，遇到相等就停，并判断 `ZF`。如果要求改成“判断两个缓冲区的 100 个对应字是否全部相同”，处理方式就会反过来。

这时要让比较在相等时继续，因此改用 `REPE CMPSW`。只要还有计数并且当前字相等，就比较下一对；遇到第一处不等便停止。

循环结束后：

- `ZF=1`，说明没有遇到不相等项，两缓冲区对应字全部相同；
- `ZF=0`，说明在某个位置发现了不同数据。

所以不要死记某一条前缀永远表示“查找”。前缀后面的执行条件必须和题目目标一致：找相等项，用 `REPNE`；要求从头到尾全部相等，用 `REPE`。判断题意时先问一句——找到相等时要不要停——答案就已经出来一半了。

### 本讲提到的题目

题目给出两个长度为 100 个字的数据区 `BUFF1` 和 `BUFF2`，按地址增大方向比较对应字。如果存在相同的字，就将这个字在 `BUFF1` 中的偏移地址存入 `ADDR`；如果没有相同字，则令 `ADDR` 等于 $-1$。

解析时使用 `REPNE CMPSW`。它会在 `CX` 尚未归零且 `ZF=0` 时继续比较，因此只检查“是否相等”，遇到第一对相等字便停止。循环后根据 `ZF` 区分找到与未找到；找到时再从已经前移的 `SI` 中减去 2，才能得到匹配项的准确偏移地址。

## 沿着数据走：字符串扫描、批量搬运与端口访问
> 对应块：BLK31 | 覆盖分集：P60-P61 | 块标题（分集名）：《60》

先想象一个最简单的任务：一个缓冲区里排着一串字符，我们要找出其中的空格。

这件事当然可以一句高级语言写完，可放到 8086 上，CPU 手里没有“查找字符串”这种现成动作，它只会取字节、做运算、比较结果、更新地址和计数。`SCASB` 做的正是这件事：拿 `AL` 里的目标字符，与缓冲区当前字节逐个比较。每比较一次，偏移地址自动向前挪；比较结果由标志位告诉我们；再配一个重复前缀，循环就会自己滚下去。

所以，这里真正重要的不是死记一个助记符，而是学会把“我要完成什么功能”翻译成“算法怎样推进、指针怎样移动、标志位怎样判定、循环什么时候停止”。程序设计到了这一步，首先要做的是找到算法；汇编指令只是把算法落到 CPU 能执行的动作上。

### 用减法比较逐字节找字符

#### SCASB把字符搜索变成逐字节相减

`SCASB` 使用两个隐含操作数：源操作数固定为 `AL`，目的操作数固定为 `ES:[DI]`。它做的运算可以写成：

$$
AL - ES:[DI]
$$

相减结果不会写回存储器，但会影响状态标志。若 `AL` 中放的是要找的字符，例如空格字符的 ASCII 码，那么关键只看零标志 `ZF`：

- `ZF = 1`：两个字节相减为零，当前字符就是目标字符；
- `ZF = 0`：两个字节不相等，当前字符不是目标字符。

这里千万不要把“目的操作数”理解成 `AL`。`SCASB` 的字节来自 `ES` 指向的存储器，偏移地址在 `DI`；`AL` 装的是拿来比较的目标字符。

开始扫描前，初始化必须与这组隐含操作数一一对应：

```asm
mov ax, BUFFER_SEG
mov es, ax
lea di, BUFFER
mov al, TARGET_CHAR
mov cx, BUFFER_LENGTH
cld
```

`ES` 给出目标缓冲区的段地址，`DI` 给出起始偏移地址，`AL` 放入目标字符的 ASCII 码，`CX` 给出最多检查多少个字节。`CLD` 把方向标志清零，使 `DI` 在每次比较后递增；如果需要从高地址向低地址扫描，就改用 `STD`，让 `DI` 自动递减。

> **结论**：`SCASB` 不是向缓冲区写数据，而是拿 `AL` 与 `ES:[DI]` 指向的字节做比较。它查完一个字节后只留下两个关键结果：当前是否相等，以及下一个字节在哪里。

#### 重复前缀让扫描自动向前推进

只执行一次 `SCASB`，最多只能比较一个字节。要连续检查一段缓冲区，就要在它前面加 `REPE`，也就是 `REPZ`：

```asm
repe scasb
```

前缀的规则是：只要 `CX` 不为零，而且比较结果仍然相等，就继续执行 `SCASB`；一旦遇到不相等的字节，`ZF` 变为零，重复结束。若整个计数范围都扫描完仍未遇到不相等的字节，`CX` 也会减到零，重复同样结束。

因此，执行完以后有两种典型结果：

- `ZF = 1`：在扫描范围内找到了目标字符；
- `ZF = 0`：遇到了一个不相等的字节，说明没有找到。

`REPE SCASB` 每执行一次都会把 `DI` 自动加一或减一。若已经从缓冲区开头向前扫描，那么找到字符时，`DI` 已经越过它，指向它的下一个单元。因此，匹配单元的偏移地址不是当前 `DI`，而是：

$$
ES:(DI-1)
$$

为什么要“减一”？因为比较发生时，`DI` 指向被比较的那个字节；比较结束后，指令已经自动把指针推进了。搜索到还不够，必须马上记住地址，后面才能读取、删除或转入其他处理。

> **易错点**：在 `CLD` 指定的向前扫描方向下，找到目标后的地址是 `ES:(DI-1)`。如果缓冲区从高地址向低地址扫描，则要根据实际方向调整，不能机械地永远减一。

#### 找“不等于目标”的字符要换条件

如果缓冲区里全是目标字符，而任务偏偏要找第一个“不等于目标”的字符，`REPE` 就不合适了。此时应使用 `REPNE`，重复条件变成 `ZF = 0`：

```asm
repne scasb
```

`SCASB` 的比较动作没有变，变化的是“什么时候继续”。`REPE` 在相等时继续，`REPNE` 在不等时继续。同一台 CPU、同一片存储器、同一组寄存器，只因为“想找什么”不同，重复前缀就不同。

所以，不要把前缀死背成“重复若干次”。它的本质是把 `ZF` 加进循环控制：

| 任务 | 重复条件 | 结束后的典型含义 |
| :--- | :--- | :--- |
| 查找等于 `AL` 的字节 | `REPE`，即 `ZF = 1` 时继续 | `ZF = 0` 表示遇到不相等字节 |
| 查找不等于 `AL` 的字节 | `REPNE`，即 `ZF = 0` 时继续 | `ZF = 1` 表示找到不相等字节 |

这两个方向都建立在同一个基本动作上：比较当前字节，更新地址，再按条件决定是否继续。

#### 找到以后还要处理字符

搜索到字符只完成了定位。若题目要求“找到后把它删掉”，算法还必须继续。

假设目标字符位于第 $p$ 个单元，原串后面的字符仍依次占据第 $p+1$、$p+2$……个单元。删除不是把该单元改成零，而是让后续字符依次向前补位：

```text
删除前：  [前缀] [目标] [后继字符 1] [后继字符 2] ...
删除后：  [前缀] [后继字符 1] [后继字符 2] ...
```

这类搬移发生在同一片存储区的相邻单元之间，存在前后重叠。真正写程序时，源指针和目的指针的移动方向必须服从“后写的数据不能覆盖还没搬走的数据”这条规则；源、目的都从低端向高端走，就很可能先把后面的数据覆盖掉。

还有一个更稳的办法，就是另建一个输出缓冲区。程序先扫描原缓冲区：遇到要删除的字符便跳过，遇到需要保留的字符便复制到新缓冲区；扫描结束后，新缓冲区里的有效内容自然就是删除后的字符串。空间多开一块，逻辑却清楚得多，也不必在重叠搬移上冒险。

到这里，一定要抓住这句话：先找到算法。查找只是前半程，命中后的处理、前缀的推进、结果地址的保存，才组成完整功能。

### 一次搬一个字节与一次搬一串数据

#### LODS和STOS分别负责取与存

`SCASB` 适合“拿寄存器里的字符去存储器中找”，而连续数据块的取送，通常交给 `LODS` 和 `STOS`。

`LODS` 的源固定在 `DS:SI`。它把存储器中的一个字节或一个字取进 `AL` 或 `AX`，然后让 `SI` 按方向自动移动。`STOS` 的方向正好相反：它把 `AL` 或 `AX` 中的数据存到 `ES:[DI]` 指向的单元，再让 `DI` 自动移动。

```text
DS:SI 指向的源字节  --LODSB-->  AL
DS:SI 指向的源字    --LODSW-->  AX

AL 中的字节        --STOSB-->  ES:DI 指向的目的字节
AX 中的字          --STOSW-->  ES:DI 指向的目的字
```

`LODSB` 与 `STOSB` 每次处理一个字节，地址每次加一或减一；`LODSW` 与 `STOSW` 每次处理一个字，地址每次加二或减二。移动方向仍由 `CLD`、`STD` 决定的 `DF` 控制：

```text
CLD：SI、DI 向高地址移动
STD：SI、DI 向低地址移动
```

| 指令 | 数据来源 | 数据去向 | 自动变化的地址 | 每次移动量 |
| :--- | :--- | :--- | :--- | :--- |
| `LODSB` | `DS:[SI]` | `AL` | `SI` | 1 字节 |
| `LODSW` | `DS:[SI]` | `AX` | `SI` | 2 字节 |
| `STOSB` | `AL` | `ES:[DI]` | `DI` | 1 字节 |
| `STOSW` | `AX` | `ES:[DI]` | `DI` | 2 字节 |

> **易错点**：`LODS` 并不把数据直接存到另一个存储器区域，它先把数据取进寄存器；真正写入目的存储器的是 `STOS`，或者后面配合的其他输出指令。

#### 重复次数必须由CX给出

单独执行一次 `LODSB`，只是从 `DS:SI` 取出一个字节；单独执行一次 `STOSB`，也只是把 `AL` 中原有的一个字节写出去。数据若一共有 $n$ 个，就应把 `CX` 初始化为 $n$，再用 `REP` 重复：

```asm
lodsw
rep stosw
```

这里的逻辑是：先取一个字到 `AX`，随后每存一次，就把下一个字从 `DS:SI` 取进 `AX`，再存到 `ES:DI]`。`SI` 不断向后取，`DI` 不断向后存，`CX` 每次减一，直到规定的数据量全部处理完。

为什么一定要给次数？因为把数据装进 `AL` 或 `AX` 本身并不等于完成功能。数据被取出来以后，可能要发送、要比较、要保存；如果没有 `CX` 规定边界，CPU 就不知道该在哪儿停。前面的 `SCASB` 是“比较到条件不满足或次数耗尽”，这里的 `REP LODS`、`REP STOS` 则是“把次数做完”。

#### 串行通信是连续搬运的典型场景

假设两台计算机通过串行接口交换数据。发送端计算机把要发送的字节放在存储器中，接口芯片内部有一个 8 位发送缓冲器；接收端也有一个 8 位接收缓冲器。主板上的串口电路可以由 8250 一类接口芯片实现，接收与发送分别按字节进行。

发送时，数据沿着下面的方向流动：

```text
待发送数据存储器
      |
      | LODSB：DS:SI -> AL
      v
     AL
      |
      | OUT：AL -> 串口发送缓冲器
      v
串行发送
```

发送一个字节以后，CPU 查询发送缓冲器是否已经空闲；空闲时，再执行一次 `LODSB`，把下一个字节装入 `AL`，随后送给发送缓冲器。数据很多时，存储器中的字节便按顺序连续送出。

接收过程恰好反过来：

```text
串行接收
      |
      | IN：串口接收缓冲器 -> AL
      v
     AL
      |
      | STOSB：AL -> ES:DI
      v
接收数据存储器
```

接收缓冲器每得到一个字节，`IN` 就把它送进 `AL`，`STOSB` 再把它写入由 `ES:DI` 指向的接收缓冲区，必要时继续保存后续字节。接口类型或寄存器名称可以不同，但“为什么字符串取送指令有用”不变：数据在存储器中连续排列，CPU 要做的正是沿地址逐个取、逐个送。

### 用STOSB一次填满缓冲区

字符串存储指令最直接的应用，是把同一个值连续写入一片缓冲区。书上的一道题给定了两块缓冲区：一块长度为 200 个字节，各单元依次放入从 0 到 199 的数；另一块长度为 256 个字节，每个单元都填入 `55H`。

第一块缓冲区本质上是一次数据定义：单元内容按 0、1、2……199 的顺序排好，程序运行时不必再逐个计算。第二块则很适合用 `STOSB`：目标值固定为 `AL` 中的 `55H`，只需让目的偏移地址从缓冲区首地址开始，连续写 256 次。

```asm
DATA SEGMENT
BUFFER2 DB 256 DUP (?)
DATA ENDS

; 假设 DS 已指向 DATA
    mov ax, DATA
    mov es, ax
    lea di, BUFFER2
    mov al, 55H
    mov cx, 256
    cld
    rep stosb
```

这段程序只做一件事：重复执行 `STOSB`，把 `AL` 中的 `55H` 写进 `ES:DI` 指向的单元。每写一次，`DI` 自动加一，`CX` 自动减一。执行结束后，256 个单元都成了 `55H`，`CX` 减到零，`DI` 越过缓冲区末尾。

这里真正值得记住的是四个初始化项：

- `AL` 决定“写什么”；
- `ES:DI` 决定“写到哪里”；
- `CX` 决定“写多少个”；
- `DF` 决定“往哪个方向走”。

考试中常会要求编写只完成某种简单功能的程序片段，这四个量正是检查重点。题目问功能，不要先急着翻答案；先自己判断该用什么算法，再把算法翻译成寄存器初始化、`REP` 和单步指令。做完以后再看别人的程序进行对比，才是在培养从问题到解法的能力。只看代码，很容易把“看答案”误当成“会做题”。

### I/O端口是另一套地址空间

#### IN和OUT决定数据往哪里走

`IN` 与 `OUT` 是专门用于 I/O 端口的输入、输出指令。设备不能把数据线直接交给 CPU 使用，中间必须有接口电路和端口；`IN` 从端口读入数据，`OUT` 把寄存器中的数据送到端口。

8086 有 20 根地址线，但 I/O 操作只使用其中的低 16 位 `A15～A0` 形成端口地址。因此端口地址空间共有：

$$
2^{16}=64K
$$

其范围是 `0000H～FFFFH`。

端口地址有两种写法。端口号在 `00H～FFH` 范围内时，可以直接把 8 位立即数写进指令；从 `0100H` 一直到 `FFFFH` 的端口，则要把地址先送进 `DX`，再用 `DX` 间接访问。`DX` 中的端口地址可以覆盖整个 16 位范围，所以 `00H～FFH` 的端口也可以通过 `DX` 访问。

| 指令形式 | 字节传送 | 字传送 |
| :--- | :--- | :--- |
| 直接端口地址 | `IN AL, imm8` | `IN AX, imm8` |
| `DX` 间接端口地址 | `IN AL, DX` | `IN AX, DX` |
| 直接端口输出 | `OUT imm8, AL` | `OUT imm8, AX` |
| `DX` 间接端口输出 | `OUT DX, AL` | `OUT DX, AX` |

`IN` 的方向是从端口到寄存器，所以端口写在后面；`OUT` 的方向是从寄存器到端口，所以端口写在前面。两种指令都默认 `DX` 承担端口地址，不要给它加中括号。`IN AL, DX` 才是正确写法，不能把 I/O 间接寻址套成存储器间接寻址的样子。

如果端口按字访问，一次传送 16 位数据，目的或来源寄存器就要由 `AL` 改为 `AX`。字端口应以偶地址为首，由该地址和紧接着的下一个字节地址组成，因为一个字的两个字节仍要按端口地址的边界规则组织。直接寻址时，立即数只能表达 `00H～FFH`；超过这个范围，不能硬塞进一个字节，只能先用 `DX` 装入完整地址。

> **易错点**：I/O 端口地址空间虽然有 64K 个地址，但 `IN`、`OUT` 指令的直接寻址立即数只有 8 位，只能直接写 `00H～FFH`。`DX` 间接寻址才是访问完整端口地址空间的手段，而且 `DX` 后面没有方括号。

### I/O指令为什么多一个等待状态

#### 五种状态组成一个总线周期

8086 在时钟信号驱动下工作，并以时钟下降沿作为同步依据。一般指令通常经历四个时钟状态 `T1～T4`；`IN`、`OUT` 因为要在 CPU 与外部端口之间完成数据传送，总线占用时间更长，需要多一个等待状态 `Tw`，整个 I/O 总线周期由五个状态组成。

```text
时钟下降沿   ↓       ↓       ↓       ↓       ↓
状态          T1      T2      T3      Tw      T4
              |-------|-------|-------|-------|-------|
一般指令：    T1      T2      T3              T4
IN / OUT：    T1      T2      T3      Tw      T4
```

`OUT` 要把 `AL` 或 `AX` 中的数据送到指定端口，数据必须经过外部数据总线；`IN` 则要把端口数据经外部数据总线送回寄存器。正因为这一步超出了 CPU 内部寄存器之间的普通传送，I/O 指令比一般指令多一个时钟周期，这个额外状态就是 `Tw`。

> **定义**：CPU 执行一条指令所占用的外部总线时间，称为总线周期。普通指令常见的是 `T1～T4` 四个状态，`IN`、`OUT` 则是 `T1、T2、T3、Tw、T4` 五个状态。

### 用八个开关搭一个输入端口

#### 设备数据必须经过三态输入缓冲器

下面考虑一个最朴素的条件输入：设备有八个开关，每个开关只有开与关两种状态。开关接到 5 V 电源表示 1，接地表示 0。CPU 要一次取得八个开关的状态，就必须通过一片八位三态输入缓冲器，例如 74LS244。

连接关系如下：

```text
K0～K7（开/关状态）
        |
        | D0～D7
        v
  +-------------+
  | 74LS244    |
  | 八位三态    |
  | 输入缓冲器  |
  +-------------+
        |
        | Q0～Q7
        v
8086 CPU 的 D0～D7
```

`D0～D7` 是八个数据输入端，`Q0～Q7` 是八个三态输出端。片上有低电平有效的输出使能端 `OE#`：

- `OE# = 0` 时，缓冲器被使能，`Q` 端反映 `D` 端状态，CPU 能读到八个开关；
- `OE# = 1` 时，输出端处于高阻态，缓冲器与 CPU 数据线断开，不妨碍其他设备使用总线。

这里的开关设备是无条件设备：不是接通就是断开，CPU 不需要额外询问它“现在是否准备好了”。但设备状态仍不能直接挂到 CPU 数据线上，接口电路的作用就是把设备状态暂时锁存在端口中，并且由地址译码决定什么时候允许 CPU 读取。

#### 端口地址为8000H时的完整译码条件

假设给这个输入端口分配地址 `8000H`。在 I/O 周期中，`A15～A0` 携带端口地址。对应关系是：

```text
A15 = 1
A14～A0 = 0
```

只看这 16 根地址线，确实可以把 `8000H` 译码出来。但只判断地址还不够。CPU 正在访问存储器时，`A15～A0` 也可能出现相同电平；CPU 执行 `OUT` 时，端口号也可能是 `8000H`，但那是写端口，不能让这个只读开关端口响应。

所以，完整的使能条件必须同时包括三部分：

```text
OE# = 0  当且仅当：

    IO/M = 0
且  RD#  = 0
且  A15～A0 = 8000H

其他情况一律令 OE# = 1
```

这里：

- `IO/M = 0` 表示 CPU 正在进行 I/O 操作；
- `RD# = 0` 表示本次是读操作；
- `A15～A0 = 8000H` 表示访问的正是这个端口。

三者同时成立，地址译码器才把 `OE#` 拉低，74LS244 导通，八个开关状态进入 CPU 的 `D0～D7`。若 CPU 访问存储器，`IO/M` 为存储器状态，缓冲器不使能；若 CPU 向端口 `8000H` 输出数据，`RD#` 不再有效，缓冲器也不使能；若访问别的 I/O 地址，地址条件不成立，同样不能选中。

> **结论**：I/O 地址译码绝不是只盯着地址线。地址信号负责回答“是哪一个端口”，`IO/M`、`RD#`、`WR#` 等控制信号负责回答“CPU 此刻要访问端口吗，要读还是要写”。两者必须一起参加译码。

如果换成理论上的 16 位输入端口，16 个输入状态都要送到 CPU，那么 `A15～A0` 的每一位都要参与端口地址判断；对现在这个 8 位端口，由于目标地址是 `8000H`，译码条件就是 `A15` 为 1、`A14～A0` 全为 0，再加上 `IO/M` 与 `RD#` 的配合。

开关的电气状态最终怎样变成 CPU 中的一个字节？靠的不是“开关直接等于数据”，而是这条完整链路：

```text
K0～K7
   |
   | 5 V / 地
   v
74LS244 的 D0～D7
   |
   | OE# = 0 时导通
   v
74LS244 的 Q0～Q7
   |
   v
CPU 的 D0～D7
```

八个开关各占一位，CPU 执行相应的 `IN` 指令后，一次就能取回这八个状态。接口、地址、读控制、方向和字节宽度必须一起对上，端口才算真正接通。

### 本讲提到的题目

#### 建立两个指定内容的缓冲区

题目给出两块缓冲区：第一块长度为 200 个字节，各单元依次存放从 0 到 199 的数；第二块长度为 256 个字节，每个单元都写入 `55H`。

解法不要从“找哪条指令”开始，而要先判断两个任务各需要什么算法。第一块缓冲区是固定数据序列，可直接按顺序完成数据定义；第二块是重复写入同一个值，算法就是“让 `AL` 固定为 `55H`，让 `DI` 指向首地址，让 `CX` 等于 256，向高地址扫描，然后用 `REPE STOSB` 重复写入”。前面的 `STOSB` 程序就是这道题的答案骨架。

做这类题时，先自己写出寄存器初始化和执行流程，再与参考答案比较。特别要检查 `ES`、`DI`、`AL`、`CX`、`DF` 五项有没有一一对应；漏掉其中任何一项，程序都可能只做了预想中的一部分。

#### 合并两个按递增关系排列的无符号数数组

另一道题布置在 `BETA1` 和 `BETA2` 两个缓冲区中。两者存放的都是按递增关系排列的八位二进制无符号数。要求编写程序，把两个数组合并为一个数组，以 `DATA` 为存放起点；合并完成后，再检查结果是否仍按递增关系排列。

这道题要求先独立完成，再与书后的答案对照。这里已经给出的线索是：它会用到字符串操作，答案中出现 `SCASB` 和 `STOSB`。真正要练的不是抄下几行程序，而是面对“两个有序序列合成一个有序序列”时，自己把比较、选择、存放和结果检查组织成算法。做完以后再对照，才能看清自己的循环边界、指针推进和结束条件究竟哪里想对了、哪里只是碰巧能用。

## I/O 端口电路收尾、其他指令与宏指令
> 对应块：BLK32 | 覆盖分集：P62-P63 | 块标题（分集名）：《62》

### 片选信号：地址译码的最后一块拼图

先把前面这块电路收个尾。地址译码部分画出来的东西还差最后一块拼图——译码的输出到底接到哪儿去。看这里：译码电路的第二个输出一有效，就把它作为你要操作的这块 I/O 端口芯片的通信号。它对应的是输出端口地址这一路，输入端口是另外一路。

这个信号有好几种叫法：有的教科书叫选通信号，有的叫选中信号，还有的叫片选信号、选片信号。我们平时用得最多的是片选信号。

> **定义**：片选信号（CS#）就是选中某一颗芯片的控制信号，一般低电平有效。你要对哪一块芯片操作，就把哪一块芯片的片选信号拉低，这块芯片才被选中，数据才有地方来、才有地方去。

怎么产生它？地址译码有讲究全译码的，也有只取关心的几根地址线做简单译码的，做法都差不多：把关心的地址线和 IOR#、IOW# 送进逻辑门，某个地址对上了，而且相应的读或写控制也有效，片选信号才拉下来。电路到这里就设计完了。

### 读一个开关的状态

现在我让你编一个程序：读设备状态，判断开关是闭合还是断开——闭合做一件事，断开做另一件事。那是不是先得测一测？

这个端口地址我给的是 8001H。地址超过 255 了，IN、OUT 就不能用直接寻址，得用寄存器间接寻址。

```asm
MOV DX, 8001H
IN  AL, DX
```

IN AL, DX 这一条指令，就以 DX 的内容作为端口地址，把 DX 送到地址线上，地址锁定在 8001H。总线周期一开始，因为这是一条 I/O 输入指令，所以 M/IO 为 0，表示这是一次 I/O 操作；IOR# 变低，是低电平有效。这个芯片的片选信号也同时有效，被选中的芯片就把自己的状态放到数据总线上——方向是从外部流向 CPU 内部。

```text
K0 开关状态 ──► 三态缓冲器（74LS244）──► 数据总线 D7~D0 ──► CPU 的 AL
                       ▲
              片选有效 ＋ IOR# 有效
```

读图说明：只有被选中的芯片在总线周期里才把数据放上数据总线，不会跟别的芯片抢总线。严格在总线周期内，保证 8 位数据都放上去。到了总线周期末，CPU 就把 D7~D0 采样进来，放到 AL 里面。

这里 K0 开关的状态就反映在 D0，也就是第 1 位上：闭合是 1，断开是 0。这位一直到第 7 位，一位一位地对应上去。

#### 用 TEST 判断这一位是不是 0

程序怎么设计？要用我们强调学过的逻辑运算指令 TEST，测 AL 里的值是不是 0：

```asm
TEST AL, 01H        ; 与运算，但不保存结果，只改标志位
```

TEST 做的事跟 AND 一样是按位与，但结果不写回 AL，AL 原封不动，只影响标志位。判断就靠标志位：结果等于 0，说明刚才读回来的 K0 状态是 0，开关断开了，那我就跳到开关断开的那一段去处理；否则这一位是 1，开关是闭合的，顺序执行开关闭合的处理。两段都处理完，最后不要忘了用一条无条件跳转跳出来。

> **易错点**：TEST 和 AND 都会影响标志位，但 TEST 不保存运算结果，AL 保持原值。如果不介意破坏 AL，`AND AL, 01H` 同样能拿到标志位；我们一般是不破坏寄存器，所以用 TEST。

把整个程序写出来是这样：

```asm
MOV DX, 8001H
IN  AL, DX            ; 读设备状态
TEST AL, 01H          ; 测 D0，不破坏 AL
JZ   SW_OPEN          ; 为 0 → 开关断开，跳走
    ; ……开关闭合的处理
    JMP DONE
SW_OPEN:
    ; ……开关断开的处理
DONE:
```

这就是通过程序测外部设备状态的办法，在实际工作中经常用到。当然，这个例子主要练的还是逻辑运算指令的应用。

#### 两个相邻地址凑一个 16 位端口

当然我举的是 8 位端口。如果占的是两个相邻地址，比如 8000H 和 8001H，下面那个低字节和上面那个高字节合起来，正好能凑出一个 16 位端口，这时候寄存器要换成 AX，指令变成 IN AX, DX 和 OUT DX, AX。端口字的地址就是低地址对应的那个地址——这和 DUP 伪指令的安排方式是一样的。

### 输出端口：锁存器与 LED 的驱动问题

再画一个电路。这里用一片 74LS374 或者 74LS373，它是 8 位锁存器，相当于 8 个 D 触发器。D0~D7 是数据输入端，Q0~Q7 是数据输出端，8 个触发器共用一根 CP 时钟线，CP 上升沿有效，把数据锁存到 Q 端。另外还有一个 OE 输出使能端，把它接地，常有效，输出就一直允许；没锁存住的数据是不能用的，Q 端输出的数据受 CP 上升沿的控制。

把 D0~D7 接到数据总线的 D0~D7 上，Q0~Q7 每一位各接一个 LED，八个 LED 就组成一个字节的输出设备。让 LED 亮，得有电流流过。

问题就来了：让 CPU 端口的输出端来提供 LED 的电流，时间一长负载太重，就把输出端口烧掉了。

#### 第一种接法：上拉电阻，让电流从电源来

第一种方案：给每个发光二极管的前端到电源之间，上拉一个电阻到 +5V，LED 的另一端接输出端。LED 这一端为 0 的时候，电流从电源经过电阻、LED 灌进输出端——电流是由电源提供的，输出端只吸收电流，相当于让它休息一下，负担轻得很。这一端为 1 的时候，两边都被拉到高电平，截止，就灭了。这样就解决了负载过重的问题。

#### 第二种接法：接过来，加限流电阻

还有一种办法：把 LED 接过来，输出为 0 时它灭、输出为 1 时它亮，电流由 +5V 经限流电阻提供——它亮的时候，电流是电压提供的，不是端口输出端在供电流。

既然电流从电源来，这限流电阻算多大？电源电压 5V，流过的电流取 10mA，超过 20mA 它就烧了。这样算下来，R 等于 500Ω。

> **易错点**：电阻有标称值，你算出来的那个是理论值，不能直接标上去。500 不是标准标称值，实取 510Ω、470Ω 都可以——离得近一点，够用就行。两种接法都能解决负载过重的问题。

### 写端口的电路与程序

输出端口的片选信号从哪来？跟读端口一样，是地址译码出来的，只不过这次要配合写信号 IOW#。

看这个电路：我用了一个或门。把地址译码出来的信号和 IOW# 送进或门，或门输出为低电平，说明这个地址是对 I/O 输出地址的写操作，这时就选中了这块输出芯片。三个高位中任何一个无效的时候，或门输出都是 1，芯片不被选中。

写的时候，CPU 先把要写的数据放到数据总线上，IOW# 拉低，写周期开始。看这个时序：

```text
                写周期
IOW# : ─────────┐                      ┌────────   （低电平有效）
                └──────────────────────┘
CS#  : ─────────┐                      ┌────────   （选中期间为低）
                └──────────────────────┘
                              ↑
              后沿处出现上升沿，用它锁存数据
D7~D0: ────────────<   写入的 8 位数据   >────────
```

读图说明：IOW# 回到高电平的时候，正好是写周期的后沿，片选信号在这里出现一个上升沿，用这个上升沿把 CPU 放到数据总线上的 8 位数据锁存到 Q 输出端。我取的是后沿——大家在实际工程设计当中取后沿，取前沿系统不稳定。为什么这样？到第五章讲时序的时候再说。

现在把程序串起来看。刚才那段程序，先把设备数据用 IN 读到 AL，再用 OUT DX, AL 把 AL 的数据输出到这个端口：

```asm
MOV DX, 8000H
IN  AL, DX            ; 读设备状态到 AL
    ; ……判断、准备数据
OUT DX, AL            ; 写到输出端口的 LED
```

DX 还是 8000H，但这次是写操作，选中的是输出芯片——靠的是 IOW# 送到片选电路去的信号把它选中的。靠 IOR# 的是输入芯片，靠 IOW# 的是输出芯片：OUT 指令选不中输入芯片，IN 指令也选不中输出芯片。

AL 的数据到了输出端口，这个灯如果亮了，说明刚才那个开关是闭合的；如果灯灭了，说明这个开关原来是断开的状态。电路和程序就做到这儿。

### 其他指令：标志位处理、NOP 与等待

3.15 节标志位处理指令给了一张表，这些一看就不会了，我就不逐条讲了。我们讲过的 CLD、STD 是不是就是把 DF 清掉、置位，CPU 就可以决定串操作的方向，这些都讲过了，就不重复了。

要留意的还有 CLC、CLI、STI 这些。构成一个循环的时候，循环体里每一次加法都用 ADC（带进位加法），但第一次做 ADC 加法之前，要先用 CLC 把 CF 清掉——不然第一次加进来的是上一轮剩下的进位，结果就错了。其余的指令等到用到再查表。

#### 空操作 NOP 与延时程序

要讲的一个是空操作 NOP。NOP 在 I/O 驱动程序编写当中经常用到——I/O 速度慢，我们在 IN、OUT 之间一般都要插入一些 NOP，等一下。NOP 什么事都没做，但花费了时间。网上讲它花费一个总线周期，注意 NOP 的总线周期只有 3 个 T 状态。

做延时的时候，短延时排上几条 NOP 就行；延时长了不能一下排好多 NOP，那头看着就不舒服了，这时候要编一个延时程序。如果程序中经常要延时，那最好把延时程序编成一个子程序，需要延时的时候调用子程序；各次延时的时间不一样，就在调用之前准备好入口参数，根据入口参数的不同来调节延迟时间。

我现在要求编写一个延时程序，那个程序怎么编呢？你思考一下。前面我们讲过顺序、分支（JZ、JNZ）、循环（LOOP），例子里边都用到过。延时程序实际上是一个标准的二重循环程序。

内层循环这样写：给 CX 一个时间常数，NOP 一下，再让 CPU 执行 LOOP，让 CX 减 1，减到 0 就停。

```asm
L1: NOP
    LOOP L1            ; CX-1，不为 0 跳回 L1
```

在 L1 这里要转 CX 圈。LOOP 这条指令的总线周期是 4 个 T，NOP 是 3 个 T，所以每循环一次就花费了 7 个 T 的时间。外层次数给多大，就跑多少圈。减法记住：16 位计数器初值是 0 的时候，能跑 65536 圈才减到 0。

如果这样一个循环延时还不够，就套一个外层循环：外层给 BX 一个计数作外层循环的初值；内层 CX 减到 0 之后，BX 减 1，没减到零，JNZ 跳回 L2，又转到那里重新开始内层循环。

```text
外层：BX = 外层次数
  └─ 内层：CX = 内层次数（时间常数）
       ├─ NOP
       └─ LOOP L1     ; CX-1，不为 0 跳回 L1
  DEC BX               ; 外层次数减 1
  JNZ L2               ; 不为 0，跳回 L2 重新开始内层
```

读图说明：调节 BX 的值是粗条，调节 CX 的值是细条，两边配合就能达到延时的目的。

把它做成一个子程序，每次调用之前先做好入口参数的准备，不同条件的时间都可以。这就是用 8086 汇编语言写的延时程序，在实际工程中是经常用到的。

#### 暂停指令 HLT

还有一条经常用到、但也不太用的指令，叫 HLT 暂停指令。在这一块儿插入一条 HLT，CPU 执行到这里就停住，不往下走了。

什么时候能退出 HLT？实际上有两种方案。第一种是硬件退出 HLT，那就是按面板上的 RESET；按了 RESET 以后是退出了 HLT，但是下载程序还能执行吗？不能了。第二种方案是给 CPU 的 NMI 引脚加外部非可屏蔽中断请求，或者给 CPU 的 INTR 引脚加外部可屏蔽中断请求信号。如果加的是可屏蔽请求，那 CPU 开了中断的话，马上就会响应。

响应中断的时候，CPU 会把这条指令对应的地址、PSW、CS、IP 依次压栈，保护好现场，然后转去执行中断服务程序；把中断服务程序执行到最后，一定要排一条 IRET 中断返回指令，IRET 一执行就返回、恢复现场，再从 HLT 对应的这个地址开始取指令、逐条执行，CPU 就退出 HLT 状态了。

> **定义**：NMI 是非可屏蔽中断请求，INTR 是可屏蔽中断请求。用 NMI 退出 HLT，CPU 一定响应；用 INTR，还要求 CPU 开了中断。

设置 HLT 指令的目的有两个：一个是有时候为了调试程序而设置；另一个是让 CPU 执行到程序某一处时，与外部设备同步——设备提到这儿、准备好了，就发一个中断请求。中断请求一来，CPU 就去干设备的活，干完回来再干自己的活，CPU 和设备就同步起来了。不过用得不多。

#### 等待指令与几条不常用的指令

其他指令里边还有一条等待指令 WAIT：如果在某一条程序前方写一条 WAIT，CPU 执行到这里就不往下走了。它每隔 5 个 T 状态读一次外部的 TEST# 引脚，而 TEST# 引脚上的状态是由某个设备提供的。如果读到的状态表示设备还没准备好，就再隔 5 个 T 状态再读一次；如果测到 TEST# 引脚上的状态是 0 了，就认为设备准备好了，退出 WAIT，继续执行程序去。这样也能够使 CPU 执行的程序与设备同步。不过这种用法现在也不太用了。

另外还有换码指令 ESC、总线封锁指令 LOCK 等等，这些指令更不用了，我就不讲了。

### 宏指令：自己定义一条新指令

3.16 节讲宏指令，宏指令一讲完，第三章就完了。回到第三章一开始讲过的 8086 汇编语言程序中语句的种类：指令语句像 TEST，伪指令语句有 DD、DB、DW、EQU、PROC、END 等，第三种就是宏指令语句。

宏指令本身不是 8086 指令系统里有的指令，是我们用户用宏定义的方法，自己开发出来的新指令。一旦你用宏定义的方法开发了新的宏指令，那么在后面的程序设计当中就可以引用它——引用就是直接写出你定义的宏指令名，宏指令名一写出来，就等效于宏的调用。

它跟子程序调用不一样：子程序调用要靠指令、要靠 CPU 去调用；宏指令名一写出来，等效的是宏调用，汇编的时候就把宏体展开到那个位置，CPU 根本不用管这件事。

> **提示**：在 8086 汇编语言程序设计当中要引用宏指令，必须先定义，然后才能引用。而且宏定义必须写在整个源程序的最前头——在 STACK SEGMENT、DATA SEGMENT 这些段定义的上边。一开始先定义宏指令，到了代码段才能引用宏指令。

#### 宏的定义格式：从 MACRO 到 ENDM

宏指令怎么定义？宏定义指令叫 MACRO，宏定义结束指令叫 ENDM。MACRO 左边要写上宏指令的名字，宏名后面加一个空格。宏指令名起名遵循的规则，和变量名、标号名、段名、子程序名、程序名一样：首先首字符必须是字母；当然起名最好有意义——假如你定义的功能是回车换行，就叫 CRLF，别人一看就知道；功能是在屏幕上显示字符串，就叫 DISPLAY，别人一看也明白。

MACRO 后面可以给出形式参数，也就是形参。多个形参之间用逗号分隔，用小括号括起来；没有形参就不写括号。MACRO 的下面用指令语句编写一段程序，这段程序能完成一个特定功能，我们把完成特定功能的这段程序称为宏体。这样宏定义完了，宏定义结束用 ENDM。

> **易错点**：宏定义结束指令 ENDM，左边什么都不写。它跟子程序定义不一样——PROC/ENDP 的左边要写出子程序名，ENDM 不用。

#### 例子：一条移位宏指令

看一个例子：定义一条移位宏指令，功能是把一个通用寄存器左移或者右移若干次。

看题目：通用寄存器是这个位置的（REG），但左移还是右移没交代，移多少次也没交代，所以 MACRO 右边要给出三个形参。REG 表示通用寄存器，DIR 表示左移还是右移，N 表示若干次。

移位次数由 CL 提供，所以第一条指令先 MOV CL, N；然后把 REG 按 DIR 的方向移 CL 次。

```asm
SHIFT MACRO REG, DIR, N
    MOV  CL, N
    S&DIR REG, CL
ENDM
```

这里有个细节要特别注意。SHL、SHR、SAL、SAR 这四条移位指令放在一起看，不管是哪一种移位，都有一个通用的地方：都是 S 开头。我写宏体的时候可以把 S 写出来，由第二个形参 DIR 代表不同的部分。也就是说，第二形参只代表了指令助记符的一部分，不是全部；这时候原来写出来的这部分和形参这部分之间，就要用 & 连接——& 是连接符，把它前后的东西接成一个完整的助记符。如果让 DIR 直接取 SHL、SHR、SAL、SAR 这样的完整助记符，宏体里直接写 DIR REG, CL 也行；可要是只把 S 写出来、由形参补上后面的部分，就得靠 & 连起来。

编程序的时候如果要用到 SHIFT 这条宏指令，在用的时候就要把实际参数带进去，实参代入时一个位置一一对应代进去就行。比如调用 `SHIFT AX, HL, 4`，汇编时就等效展开成 `MOV CL, 4` 和 `SHL AX, CL` 两句。

### 本讲提到的题目

- 编写延时程序：要求用 8086 汇编语言编写一个延时程序。答案要点是内层用 NOP（3T）＋ LOOP（4T）构成每圈 7T 的循环，16 位计数初值为 0 时可跑 65536 圈，不够就再套一层 BX 计数的外层循环，用 DEC BX、 JNZ 跳回外层，调节 BX（粗条）与 CX（细条）得到不同延时，并把它做成带入口参数的子程序。完整写法见「空操作 NOP 与延时程序」一节。
- 教材 4.39 题：课上只提了题目轮廓——从键盘输入的一串字符中找出 ASCII 码值最大的；没有展开题面，也没有给出解答，排序的讲法留到下一讲冒泡排序。
