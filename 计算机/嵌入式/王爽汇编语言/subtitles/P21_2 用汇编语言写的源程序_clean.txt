### [00:00] 汇编语言源程序与编程过程

在这一节，我们介绍汇编语言的源程序。

首先看一下汇编语言编程的过程，这其实跟高级语言是差不多的：
1. 由程序员编写出汇编源程序。
2. 汇编语言源程序需要通过编译，编译后能够得到机器码。
3. 有了机器码，在计算机上就可以直接执行。

在这个过程当中，人写出的是汇编程序，最终需要的是机器码，而机器码是由机器去执行的。

---

### [00:40] 汇编程序的构成：伪指令与汇编指令

接下来看一下一个完整的汇编程序是如何构成的。

在一个汇编源程序中，最前面和最后面的部分属于**伪指令**。
* **伪指令**：并没有对应的机器码指令，不会被转成机器码，最终不被 CPU 执行。伪指令是由编译器来执行的指令，编译器根据伪指令进行相关的编译工作。因此，伪指令不是用来指导机器工作的，而是指导编译器将汇编语言源程序转换成机器码。编写程序时必须写伪指令，但它不是最终让机器执行的部分。
* **汇编指令**：例如 `mov`、`add` 等，有对应的机器码指令，每一条指令都可以对应成 `0`、`1` 序列。它们可以被编译为机器指令，最终被 CPU 执行。

两者关系在于：核心执行的是汇编指令；为了让编译器能够正常工作，需要加上伪指令。

因此，汇编程序是由**汇编指令**和**伪指令**构成的文本文件。

#### 程序返回代码
在汇编指令中，有固定的两行指令用于实现程序返回（类似于 C 语言中的 `return 0;`）：

```assembly
mov ax, 4c00h
int 21h
```

这里的数值是固定的。它的作用是：当程序结束运行后，将 CPU 的控制权交还给使它运行的程序。例如程序是在 DOS 系统下执行的，运行结束后就会把整个程序的控制权交还给 DOS 系统。

### [03:00] 常用伪指令详解

汇编源程序中常用的三类伪指令：段定义、程序结束和假设。

#### 1. 段定义（`segment` 与 `ends`）
一个汇编程序由多个段组成。段可以用来存放代码、存放数据或用作栈空间。一个有意义的汇编程序中至少要有一个代码段（Code Segment）。

定义段的格式如下：
```assembly
段名 segment
    ...
段名 ends
```
* `segment`：段的开始标志。
* `ends`：段的结束标志（end segment 的缩写）。
* 示例：以 `codesg segment` 开始，以 `codesg ends` 结束。

#### 2. 程序结束（`end`）
`end` 是汇编程序的结束标志（注意末尾不带 `s`，与 `ends` 区分）。若程序末尾不加 `end`，编译器在编译时就不知道程序在哪里结束。因此，每个汇编程序的最后必须加上 `end`。

#### 3. 假设指令（`assume`）
`assume` 用于将段寄存器与程序中通过 `segment ... ends` 定义的段建立关联。
例如：
```assembly
assume cs:codesg
```
含义是假设代码段寄存器 CS 与自定义的段 `codesg` 相关联，即指明将该段作为代码段使用。

### [05:16] 编译、链接与可执行文件

源程序编写完成后，需要经过编译和链接（通过相关工具软件完成）生成机器码。源程序中的每一条汇编指令与机器码是一一对应的。

需要指出的是，最终转换生成的可执行文件中，除了汇编指令对应的机器码之外，还会包含描述信息。这些描述信息用于记录该程序总体特征的相关数据。

### [06:06] 汇编程序编写的两种方式

编写汇编程序主要有两种方式：

#### 方式一：在 Debug 中直接写入指令
* **操作方式**：进入 Debug，使用 `a` 命令直接输入汇编指令并运行。
* **特点**：适用于功能简单、短小精悍的程序，通常运行后不保存。
* **优势**：交互式手工操作，灵活性高。在进行底层探测、访问内存或调用底层功能时，直接在 Debug 中编写短小精悍的程序最为便利。

#### 方式二：编写独立的源程序文件（`.asm`）
* **操作方式**：将程序完整写入源文件，再通过编译、链接生成可执行文件。
* **特点**：适合编写大型程序。源程序中需要包含完整的汇编指令与伪指令（段定义、程序结束、段寄存器关联等）。

在较完整的程序中，通常会规划多个段：
```assembly
assume cs:code, ds:data, ss:stack

data segment
    ; 数据段
data ends

stack segment
    ; 栈段
stack ends

code segment
    ; 代码段
code ends
end
```
* `code segment`：作为代码段，关联 `cs` 寄存器。
* `stack segment`：作为栈空间，关联 `ss` 栈段寄存器。
* `data segment`：作为数据段，关联 `ds` 数据段寄存器。

#### 注释规范
汇编语言中的注释使用分号（`;`）引导，分号之后的内容均为注释，仅供阅读，编译器不会对其进行处理。

### [09:18] 编程实例：计算 $2^3$

以求解 $2^3$ 为例，编写一个完整的汇编程序：

1. **定义段**：任意取一个段名（例如 `abc`），用 `abc segment` 与 `abc ends` 包裹。
2. **实现计算逻辑**：
   * 将 AX 赋值为 $2$；
   * 执行 $2 + 2 = 4$；
   * 执行 $4 + 4 = 8$（即实现 $2^3$）。
3. **关联段寄存器**：使用 `assume cs:abc` 将代码段寄存器 CS 与段 `abc` 关联。
4. **添加程序返回套路**：加入 `mov ax, 4c00h` 和 `int 21h`。
5. **标明程序结束**：在末尾添加 `end` 伪指令。

完整汇编代码如下：

```assembly
abc segment
    assume cs:abc

    mov ax, 2
    add ax, ax
    add ax, ax

    mov ax, 4c00h
    int 21h
abc ends
end
```

在后续处理更复杂的任务时，逻辑本质相同，无非是增加处理指令，或在单一逻辑段无法满足需求时定义多个段。

### [11:20] 语法错误与逻辑错误

在编写程序过程中出现的错误主要分为两类：

#### 1. 语法错误
指程序在编译期间被编译器检测出的错误，初学者常见。
* **示例 1**：拼写错误。如将伪指令 `assume` 漏写字母。
* **示例 2**：指令或寄存器非法。如将 `add ax, ...` 误写为 `add sx, ...`，由于不存在 `sx` 寄存器，编译时报错。
* **处理**：语法错误会在编译期直接定位并指出，易于修正。

#### 2. 逻辑错误
逻辑错误在编译阶段无法被编译器检测出来，程序能够成功生成并运行，但在运行时产生错误结果。
* **示例 1**：在计算 $2^3$ 时，原本应通过累加实现倍增（`add ax, ax`），若笔误写成 `add ax, bx`：
  编译器不会报错，程序会正常将 BX 的内容加到 AX 中，但所得结果偏离了计算目标。
* **示例 2**：程序返回指令中，若误将 `mov ax, 4c00h` 写成 `mov ax, 4c10h`：
  程序仍可执行，但调用 `int 21h` 中断时将无法正确完成程序返回。

编写程序时不仅要避免语法错误，更核心的工作是防范与排查逻辑错误。与错误作斗争是程序员工作的核心内容。
