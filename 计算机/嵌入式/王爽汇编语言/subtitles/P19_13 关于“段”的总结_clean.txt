# 汇编语言：内存分段机制与段寄存器总结

---

### [00:00] 段的概念与物理地址计算

我们连续好几节讲的都是和“段”有关的内容，这里对“段”做一个系统总结。

所谓的各种“段”，指的都是内存。在内存中，我们非常关注如何定位单元内部的数据，这牵涉到内存的编址，即**物理地址**。8086 CPU 的物理地址是由**段地址**和**偏移地址**共同构成的。

在编写程序时，我们可以根据需要把一组内存单元定义成一个段，其长度是可调的。内存中的段具有以下特征：

1. **起始地址必须是 16 的倍数**  
   CPU 计算物理地址的公式为：
   $$\text{物理地址} = \text{段地址} \times 16 + \text{偏移地址}$$
   段地址乘以 16，相当于将二进制数值向左移 4 位（即十六进制向左移 1 位），因此其十六进制形式的最后一位必然为 $0\text{H}$。所以段的起始物理地址一定是 16 的倍数。

2. **段的最大长度为 64 KB**  
   偏移地址是一个 16 位的二进制数，其寻址范围为 $0000\text{H} \sim \text{FFFFH}$（$2^{16} = 64\text{ KB}$）。因此，单个段的最大长度只能小于或等于 $64\text{ KB}$。

我们可以将这样一组地址连续的内存单元在逻辑上定义为一个段。

定义一个段后，通常需要用段地址来指示段的基址，用偏移地址来访问段内的具体单元。而在程序中，到底哪个段用作什么用途、它的偏移地址是多少，完全由程序员自行安排。分段构成了我们在使用内存时最基本的操作机制。

### [01:36] 三种核心段及其寄存器机制

到目前为止，我们一共学习了三种段：**数据段**、**代码段**和**栈段**。

#### 1. 数据段（Data Segment）
* **用途**：用于存放程序所需的数据。
* **段地址寄存器**：存放在 `DS`（Data Segment Register）中。
* **访问方式**：将数据段的段地址送入 `DS` 寄存器后，后续就可以通过 `MOV`、`ADD`、`SUB` 等指令来访问对应的内存单元。CPU 会将我们定义的数据段内容当作数据来读取或写入。

#### 2. 代码段（Code Segment）
* **用途**：用于存放程序要执行的指令代码。
* **段地址寄存器**：存放在 `CS`（Code Segment Register）中。
* **偏移地址寄存器**：段中第一条指令的偏移地址存放在专门的 `IP`（Instruction Pointer，指令指针寄存器）中。
* **执行机制**：CPU 每次执行指令时，执行的都是当前段地址为 `CS`、偏移地址为 `IP`（即 `CS:IP`）所指向位置的指令。

#### 3. 栈段（Stack Segment）
* **用途**：用于实现 CPU 硬件级支持的栈结构空间。
* **段地址寄存器**：存放在 `SS`（Stack Segment Register，栈段寄存器）中。
* **偏移地址寄存器**：栈顶单元的偏移地址由专门的 `SP`（Stack Pointer，栈顶指针寄存器）来指示。
* **访问方式**：对栈段进行访问主要使用专门的 `PUSH` 和 `POP` 指令。
  * `PUSH` 和 `POP` 指令除了读取或保存数据之外，还会伴随着 `SP` 指针的自动调整；
  * 这与 CPU 执行指令时伴随着 `IP` 指针的自动累加调整原理是相通的。表面看似简单的指令操作，底层包含着很多硬件机制的自动调整。

### [03:23] 综合示例 1：独立分段空间的分配与设置

下面看一个综合示例：将一段连续的内存空间进行规划，分别划分为数据段、栈段和代码段。

假设将内存空间分配如下：
* 数据段起始地址为 `10000H`；
* 栈段起始地址为 `10010H`，大小为 16 字节；
* 代码段紧随其后。

#### 1. 数据段初始化
数据段起始物理地址为 `10000H`，取其十六进制的前 4 位段地址 `1000H`。8086 CPU 不支持直接将立即数送入段寄存器，需要通过通用寄存器（如 `BX`）进行中转：
```assembly
mov bx, 1000H
mov ds, bx
```
执行后，即表明从 `10000H` 开始的内存单元被定义为数据段。

#### 2. 栈段初始化
栈段起始物理地址为 `10010H`，取其前 4 位段地址 `1001H` 赋给 `SS`。  
由于栈段在空栈时，栈顶指针 `SP` 需指向栈底单元的下一个单元（即最高地址上方）：
* 栈段基地址为 `10010H`；
* 栈空间长度为 16 字节（$10\text{H}$ 字节），初始空栈栈顶物理地址为：
  $$10010\text{H} + 10\text{H} = 10020\text{H}$$
* 因此，偏移量 `SP` 应设为 `0010H`：
```assembly
mov bx, 1001H
mov ss, bx
mov sp, 0010H
```

#### 3. 代码段与 Debug 跟踪
在后续的编程中，可以通过伪指令直接在代码中定位跳转；在 Debug 调试环境中，也可以手动完成上述配置：
1. **设置寄存器**：使用 `R` 命令分别配置 `DS`、`SS`、`SP` 以及代码段的 `CS`、`IP`；
2. **写入数据**：使用 `E` 命令向数据段所在内存写入初始数据；
3. **录入代码**：使用 `A` 命令在 `CS:IP` 所指向的地址汇编录入指令；
4. **单步执行**：使用 `T` 命令单步跟踪执行指令。

建议大家在实际操作时，先通过大脑在纸面上单步推导一遍执行结果，再使用 Debug 跟踪验证。

### [06:40] 综合示例 2：段地址重叠与空间共享

在实际处理中，三个段的段地址也可以完全相同。例如，将数据段与栈段混合安排在同一个物理段空间内共同享用：

假设段地址统一设为 `1000H`：
```assembly
mov bx, 1000H
mov ds, bx
mov ss, bx
```

#### 栈顶指针的设置原则
在同一段空间内既作数据段又作栈段时，通常让栈段优先使用段的高地址空间（栈向低地址生长），避免栈操作覆盖前面的数据区：
* 段起始基地址为 `10000H`；
* 此时若分配 32 字节（$20\text{H}$）的总空间，空栈栈顶应指向偏移量 $20\text{H}$ 的位置（即 $10000\text{H} + 20\text{H} = 10020\text{H}$）；
* 因此，栈顶指针 `SP` 需初始化为 `0020H`：
```assembly
mov sp, 0020H
```

后续的指令执行与前面的单步操作逻辑完全一致。这类内存共享与指针设置，大家可以在 Debug 调试环境中实际演示和验证。
