# 汇编语言：字符串输入处理与字符栈设计

---

### [00:00] 课程导入与功能需求分析

在这节课中，我们将介绍一个具体的应用——关于**字符串输入的处理**。

我们要解决的问题是：设计一个最基本的字符串输入程序。对于该输入程序，需要具备以下基本功能：
1. **边输入边显示**：在输入字符的同时，屏幕上能够实时显示该字符串；
2. **回车确认结束**：输入回车键时，程序认为输入结束，并在字符串末尾设置结束标识；
3. **退格删除字符**：在输入过程中若按下退格键（Backspace），能够删除前一个已经输入的字符。

对于这样一个字符串输入程序而言，这属于非常基础的核心功能。

---

### [00:40] 运行过程与输入输出示例

我们来看一下该程序的具体运行过程。

假设在整个运行过程中，用户进行了如下键盘输入：
- 先后键入字符：`a` $\to$ `b` $\to$ `c` $\to$ `d`；
- 紧接着输入一个退格键（Backspace）：此时需将刚刚输入的字符 `d` 删除；
- 再次输入一个退格键：字符 `c` 被删除；
- 此时按下回车键（Enter）：整个字符串输入完成。

最终形成的字符串内容即为：`ab`。

---

### [01:08] 设计考量：字符存储与显示机制

为了满足上述需求，我们需要解决以下几个关键问题：

1. **输入的同时进行显示**  
   在敲击键盘（如键入 `a`）的同时，屏幕应立即回显，这符合用户的交互习惯。因此，必须将输入的字符保存在内存当中的适当区域，并实时读取并显示该区域的内容。
   
   在存储管理上，可以**采用“栈”的方式来管理该字符串的存储空间**。后续我们将探讨如何选取并实现合适的数据结构。

2. **以回车符作为结束标志**  
   当接收到回车符时，字符串输入结束。在结束时，需在字符串末尾追加一个字节 `0` 作为结尾符（类似于 C 语言中以 `'\0'` 结尾的字符串处理方式）。

3. **动态刷新显示**  
   每当有新字符输入或者有字符被删除时，都需要重新刷新屏幕显示。既然采用栈结构来管理字符串，在刷新显示时，需**从字符栈的栈底到栈顶遍历并显示所有的字符**。

---

### [02:30] 字符串输入处理的整体逻辑整理

明确上述需求后，我们整理整体处理思路：

1. **等待并读取键盘输入**  
   调用 BIOS 提供的 `int 16h` 中断读取键盘缓冲区。

2. **按键类型判定与分支处理**  
   读取按键信息后，判断其是否为可显示字符：
   - **若为非可显示字符**，进一步判断是退格键还是回车键：
     - **退格键（Backspace）**：从字符栈中弹出一个字符（取出字符），刷新显示当前字符栈中的所有字符，随后返回步骤 1 继续等待下一个按键；
     - **回车键（Enter）**：向字符栈中压入一个字节 `0`，子程序返回，整个输入过程结束；
     - **其他控制字符**：直接忽略，返回步骤 1 继续等待输入。
   - **若为可显示字符**：将该字符压入字符栈，刷新显示栈中所有字符，返回步骤 1 继续通过 `int 16h` 中断读取键盘输入。

---

### [03:42] `getstr` 子程序框架搭建

基于上述思路，我们可以编写字符串接收的主控子程序 `getstr`。

在调用该子程序之前，需完成运行环境的初始化配置：
- 设置数据段寄存器 `ds` 的段地址；
- 指定字符存储区（数据区）的起始偏移地址；
- 设置字符在屏幕上显示时的起始行号与列号。

完成初始化后，通过 `call getstr` 调用子程序来完成字符串的动态接收。

---

### [04:27] `getstr` 核心逻辑与按键扫描判断

```assembly
getstr:
    push ax                 ; 保护现场

getstrs:
    mov ah, 0
    int 16h                 ; 调用 16h 中断读取键盘输入
                            ; 键盘缓冲区无数据时挂起等待，有数据时读取并继续执行

    cmp al, 20h             ; 比较 ASCII 码与 20h (空格键的 ASCII 码)
    jb nochar               ; 若 al < 20h，说明为非字符/控制字符，跳转至 nochar 处理

    mov ah, 0               ; 字符键处理：调用 0 号子功能（字符入栈）
    call charstack
    mov ah, 2               ; 调用 2 号子功能（刷新显示栈中字符）
    call charstack
    jmp getstrs             ; 继续等待下一个键盘输入
```

---

### [05:50] 控制按键（退格与回车）的识别与处理

当判定按键为非字符（`jb nochar`）时，转入 `nochar` 标号，通过扫描码寄存器 `ah` 进一步判定按键类别：

```assembly
nochar:
    cmp ah, 0eh             ; 比较扫描码是否为 0Eh（退格键 Backspace）
    je backspace            ; 若相等，跳转至 backspace 处理

    cmp ah, 1ch             ; 比较扫描码是否为 1Ch（回车键 Enter）
    je enter                ; 若相等，跳转至 enter 处理

    jmp getstrs             ; 若为其他控制键，直接忽略并返回等待输入

backspace:
    mov ah, 1               ; 退格键处理：调用 1 号子功能（字符出栈）
    call charstack
    mov ah, 2               ; 调用 2 号子功能（刷新显示栈中字符）
    call charstack
    jmp getstrs             ; 返回继续等待输入

enter:
    mov al, 0               ; 回车键处理：将 0 写入 al 作为结尾符
    mov ah, 0               ; 调用 0 号子功能（字符 0 入栈）
    call charstack
    mov ah, 2               ; 调用 2 号子功能（刷新显示）
    call charstack
    pop ax                  ; 恢复现场
    ret                     ; 子程序返回，输入处理结束
```

### [06:53] 数据结构分析：基于数据区模拟的字符栈

分析上述逻辑可见，虽然主流程调用了多次操作，但核心操作高度规整，主要包含三大功能：
1. **字符入栈**
2. **字符出栈**
3. **显示栈中字符**

此处的“栈”指的是我们在数据段中自行开辟的一块内存空间（例如分配 32 个字节），将其命名为字符栈空间。请注意，它并非 CPU 硬件体系中由 `ss:sp` 维护的系统堆栈（Stack），而是**在普通数据区上模拟出的栈式访问结构**。我们在该数据区上维护一个栈顶指针变量 `top`，用于执行逻辑上的入栈和出栈操作。

---

### [07:41] `charstack` 子功能划分与接口约定

我们将字符栈的管理逻辑抽取封装为一个独立的子程序 `charstack`。

该子程序统一对外提供 3 个子功能，通过寄存器 `ah` 传入**功能号**：
- `ah = 0`：字符入栈
- `ah = 1`：字符出栈
- `ah = 2`：显示栈中的字符

#### 接口参数规范：
- **0 号功能（字符入栈）**：
  - 入口参数：`ah = 0`，`al = 入栈字符`。
  - 在接收普通字符时，`al` 中已存放键盘读取的 ASCII 码；在回车结束时，提前执行 `mov al, 0`，即可复用该功能将 `0` 压栈。
- **1 号功能（字符出栈）**：
  - 入口参数：`ah = 1`。
  - 出口参数：`al = 出栈字符`（将弹出的字符保存在 `al` 中返回，供调用者按需检查）。
- **2 号功能（显示栈中字符）**：
  - 入口参数：`ah = 2`；
  - `dh`：显示的起始行号；
  - `dl`：显示的起始列号；
  - `ds:si`：指向字符栈存储空间的起始地址（栈底），字符串以 `0` 为结尾符。

### [09:00] 表驱动设计思想：类似中断机制的直接定址表

在设计包含多个子功能的子程序时，使用寄存器传递功能号（如 `ah`）的做法与 BIOS/DOS 系统中断的架构思想高度一致。例如调用 `int 21h` 时，通过 `ah = 01h`、`ah = 02h`、`ah = 09h` 等区分操作。

若在子程序内部使用多重 `cmp` 与 `jmp` 进行条件跳转，分支过多时程序结构会十分松散、混乱。为了提高程序的可维护性与可扩充性，我们采用**直接定址表（表驱动 / 跳转表）**来实现子功能的寻址与分发。

---

### [11:15] 字符栈访问规则与 `top` 指针维护

字符栈的内部访问规则如下：
1. **栈空状态**：定义字型变量 `top dw 0`，记录栈顶相对于栈底的偏移地址。栈为空时，`top = 0`；
2. **入栈操作**：数据写入偏移地址为 `top` 的单元，随后执行 `top = top + 1`；
3. **出栈操作**：首先将栈顶指针自减 `top = top - 1`，随后读出偏移地址为 `top` 单元中的字符。

### [12:11] `charstack` 子程序的直接定址表实现

`charstack` 子程序的框架与跳转表结构如下：

```assembly
charstack:
    jmp short charstart

    ; 直接定址表（函数指针数组），保存各子功能的入口偏移地址
    table dw charpush, charpop, charshow
    top   dw 0              ; 记录字符栈顶偏移地址的变量

charstart:
    push bx
    push dx
    push di
    push es                 ; 保护子程序内部使用的寄存器

    cmp ah, 2               ; 功能号有效性检查
    ja sret                 ; 若 ah > 2，为非法功能号，直接退出

    mov bl, ah
    mov bh, 0
    add bx, bx              ; bx = ah * 2（每个表项为字单元，占 2 个字节）

    jmp word ptr table[bx]  ; 查表并跳转至对应的子功能入口
```

### [15:34] 各子功能的具体实现

#### 1. 字符入栈功能（`charpush`）
```assembly
charpush:
    mov bx, top
    mov [si+bx], al         ; 将字符存入 ds:[si+top] 单元中
    inc top                 ; 栈顶指针加 1
    jmp sret                ; 跳转至统一出口返回
```

#### 2. 字符出栈功能（`charpop`）
```assembly
charpop:
    cmp top, 0              ; 检查字符栈是否为空
    je sret                 ; 若 top == 0（栈空），无法出栈，直接返回

    dec top                 ; 栈顶指针减 1
    mov bx, top
    mov al, [si+bx]         ; 取出当前栈顶位置的字符送入 al
    jmp sret                ; 跳转至统一出口返回
```

#### 3. 显示字符栈功能（`charshow`）
```assembly
charshow:
    ; 根据入口参数 dh（行号）、dl（列号）计算显存偏移地址
    ; 将 ds:si 指向的字符栈内容依次写入显存，遇 0 结束
    ; （此处为标准显存写入逻辑，代码略）
    jmp sret

sret:
    pop es
    pop di
    pop dx
    pop bx                  ; 恢复寄存器
    ret                     ; 子程序返回
```

### [16:48] 课程总结

本节课通过“字符串输入处理”这一典型实例，重点讲解了以下核心技术：
1. **BIOS 键盘中断应用**：利用 `int 16h` 中断从键盘缓冲区获取按键的 ASCII 码（`al`）与扫描码（`ah`）；
2. **字符栈结构设计**：在普通数据段中通过 `top` 指针模拟栈的操作机制，满足动态输入、退格删除与回车确认的逻辑需求；
3. **直接定址表架构**：在子程序设计中运用表驱动模式，通过功能号索引跳转表，构建了高内聚、易扩展的多功能服务程序结构。该设计模式在系统级程序设计中具有广泛的借鉴意义。
