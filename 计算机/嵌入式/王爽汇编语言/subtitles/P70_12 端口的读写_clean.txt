### [01:01] 端口的作用与外设通信原理

现在我们来看一下，`IN` 和 `OUT` 指令到底是如何工作的。

以 `IN AL, 61H` 这条指令为例。这里的 `61H` 是一个端口地址（端口号），它代表的是设备控制器芯片的端口。对于 `61H` 端口而言，它的最低两个二进制位控制着定时器以及扬声器（PC喇叭）。

在程序中，首先通过 `IN AL, 61H` 把 `61H` 端口的状态读到寄存器 `AL` 中；随后通过 `OR AL, 03H` 进行逻辑或运算。因为数字 3 的二进制最后两位是 `11`，所以这个 `OR` 运算的作用就是强行把最低两位的值置为 1。置为 1 之后，扬声器就开始发声了。发声的频率是在 `42H` 号端口中设置的。

说到端口，大家需要明确记住：**端口对应的就是外部设备**。

前面介绍过，对外部设备进行操作可以通过 BIOS 中断，也可以通过 DOS 中断。除此之外还有一种途径，那就是通过程序直接访问外设，而直接访问外设的途径就是使用端口。

### [02:21] CPU 的访问对象与端口统一编址

这里我们需要提一下 CPU 能够访问的数据空间。CPU 在访问数据时，主要可以访问三个地方：
1. **CPU 内部的寄存器**：比如 8086 中的 14 个寄存器；
2. **内存单元**：即内存地址空间；
3. **端口**：通过接口芯片连接的外部设备。

端口起什么作用呢？端口对应着各种接口卡（如网卡、显卡等）、主板上的接口芯片以及其他芯片。CPU 正是通过端口与外部芯片进行连接与通信的。比如上网要通过网卡，显示画面要通过显卡。只要 CPU 能够和这些外设接口芯片通信，外部设备就能够被 CPU 访问。

在主板上，除了 CPU 之外还有各种各样的集成电路芯片。端口解决的就是 CPU 和这些外设芯片之间的通信问题。这些芯片内部都有各自的一组寄存器，CPU 与外设芯片通信，本质上就是对这些芯片内部的寄存器进行读写。

从 CPU 的角度来看，系统把所有外设芯片中的寄存器都当作**端口**，并进行**统一编址**。统一编址后，CPU 就可以使用统一的读写机制与各种不同的外设进行通信。

在 8086 架构中，CPU 能够访问的端口地址空间为 $64\text{ KB}$，地址范围为 $0 \sim 65535$（即 $0000\text{H} \sim \text{FFFFH}$）。在这个地址空间中，某些地址范围分配给特定的设备芯片。将来操作不同的外部设备时，只要访问其对应的端口地址（端口号）即可。

### [04:51] IN 与 OUT 指令及总线操作过程

读写内存和寄存器时，使用的是 `MOV`、`ADD`、`PUSH` 等指令。而读写端口的指令非常简单，只有两条：
* `IN`：从端口读取数据到 CPU。
* `OUT`：从 CPU 往端口写入数据。

方向是以 CPU 为核心视角来定义的：`IN` 表示数据进入 CPU，`OUT` 表示数据从 CPU 输出。

以指令 `IN AL, 60H` 为例：该指令表示从端口号为 `60H` 的端口读入一个字节到寄存器 `AL` 中。

在总线层面的具体执行过程如下：
1. CPU 通过**地址总线**将端口地址信息 `60H` 发出；
2. CPU 通过**控制总线**发出端口读控制信号（I/O 读命令）；
3. 对应的端口译码电路选中该端口所在的芯片，通知芯片准备输出数据；
4. 端口所在芯片将 `60H` 端口内部的数据送上**数据总线**，随后传输进 CPU，存入目标寄存器 `AL` 中。

### [06:42] 端口读写总线时序与动画解析

接下来通过动态过程观察两条连续指令的执行流程：
```masm
IN  AL, 20H
OUT 21H, AL
```

1. **执行 `IN AL, 20H`**：
   * 假设程序计数器（IP）当前为 `0003H`，读取指令码。由于指令长度为 2 个字节，IP 更新为 `0005H`。
   * 指令译码后分离出端口号 `20H`，CPU 通过地址总线将 `20H` 送到外设接口，锁定 `20H` 端口。
   * 控制总线发送“读”命令，芯片接收后将 `20H` 端口中的数据（例如 `61H`）通过数据总线传回 CPU，存入 `AL` 寄存器。

2. **执行 `OUT 21H, AL`**：
   * 程序计数器自增，从内存中取出指令 `OUT 21H, AL` 到 CPU 中。
   * 指令译码分离出目标端口号 `21H`，通过地址总线选定端口 `21H`。
   * 控制总线发送“写”命令，同时 CPU 将寄存器 `AL` 中的数据（`61H`）通过数据总线写入到 `21H` 端口所对应的硬件寄存器中。

### [08:44] 端口地址分配与映射

当需要操作外部设备时，程序会频繁地访问端口。$64\text{ KB}$ 的端口地址空间在硬件体系中是有既定分配方案的。

在硬件手册中可以查到端口地址分配表，清晰列出了每个端口地址与具体硬件、芯片的对应关系。访问这些外设时，只需找到对应的端口号，对其执行 `IN` 或 `OUT` 操作即可。

### [09:17] 端口读写指令规范与细节

在汇编语言中，使用 `IN` 和 `OUT` 指令时有严格的语法规则：

#### 1. 端口号的寻址方式
* **$0 \sim 255$（$00\text{H} \sim \text{FFH}$）以内**：端口号必须以**8位立即数**的形式直接给出。
  ```masm
  IN  AL, 20H
  OUT 21H, AL
  ```
* **$256 \sim 65535$（$0100\text{H} \sim \text{FFFFH}$）之间**：端口号为 16 位，**必须先存放到寄存器 `DX` 中**，通过 `DX` 间接寻址。
  ```masm
  MOV DX, 3F8H
  IN  AL, DX
  OUT DX, AL
  ```

#### 2. 数据寄存器的限制
`IN` 和 `OUT` 指令用于暂存输入/输出数据的寄存器**只能使用 `AL` 或 `AX`**，不能使用其他通用寄存器：
* **8 位端口读写**：必须使用 `AL`。
  ```masm
  IN  AL, 20H
  OUT 21H, AL
  ```
* **16 位端口读写**：必须使用 `AX`。
  ```masm
  IN  AX, DX
  OUT DX, AX
  ```

至于具体某个硬件的端口是 8 位还是 16 位，在实际开发中查阅对应的芯片硬件手册即可确定。
