### 模块化程序设计：CALL 指令与 RET 指令

#### [00:00] 模块化程序设计与调用/返回机制
在这一节，我们介绍和模块化程序设计相关的 `call` 指令与 `ret` 指令。

对于模块化程序设计，学过高级语言程序设计的同学是不陌生的。我们可以通过一个主程序调用若干个子程序，而每一个子程序还可以再调用其他的子程序。比如在 C 语言当中，我们可以在 `main` 函数当中去调用一个自定义函数 `cube`。在调用自定义函数的时候，程序流程需要转移到自定义函数内部；而自定义函数在执行完毕后，流程还会转回到主程序当中继续执行。

所以在做模块化程序设计的时候，主程序和子程序之间存在着调用与返回的关系。

为了支持这种调用和返回，汇编语言也提供了相应的指令：
- 调用子程序时，使用的是 **`call` 指令**；
- 返回时，使用的是 **`ret`（return）指令**。在汇编语言中只取 return 的前三个字母，即 `ret` 指令。

我们可以看到这样一个示例程序框架：
```assembly
mov ax, 0
call s
; ...
s:
; ...
ret
```

在这个程序中，执行完 `mov ax, 0` 后，便使用了 `call` 指令：`call s`。这里的 `s` 是一个标号。在调用时，指令流程会转移到该标号所在的位置，从而进入子程序。当子程序当中的语句执行完毕，遇到 `ret` 指令时，流程会转回到刚才调用 `call` 指令的下一条语句继续执行。

这样一个执行流程与我们在高级语言中的调用流程是完全一致的。

---

#### [01:38] CALL 与 RET 的转移实质
在模块化程序设计调用子程序的过程当中，其实质仍然是**流程转移**：
- 调用时转移到子程序；
- 返回时再转回到主程序。

作为流程转移，它势必要修改寄存器 `IP` 的值；在某些情况下，还会同时修改代码段段地址 `CS` 以及偏移地址 `IP`。把握住这个实质以后，汇编语言中的模块化程序设计就很容易理解了。

---

#### [02:12] CALL 标号（段内转移）
我们先看 `call` 指令。`call` 指令字面意思就是调用子程序，其实质是流程转移。它的转移方法和 `jmp`（jump）指令是相似的。但不同之处在于：转移之后还牵涉到将来的返回，所以在转移时，必须将当前执行的返回地址保存下来，以便于返回时能够找到。

如何保存这个返回地址呢？在汇编语言中利用了**栈**结构。也就是说，它会把返回地址保存到栈当中。

`call` 指令的基本格式为：`call 标号`。

在执行 `call 标号` 指令时，CPU 实际上要进行两步操作：
1. 将当前的 `IP`（或者 `CS` 和 `IP`）压入栈中。调用 `call` 指令时，`IP` 已经自动更新为 `call` 指令的下一条指令的地址，因此压入栈中的 `IP` 值正是 `call` 指令下一条指令的地址；
2. 压栈操作完成后，转移到标号处执行指令（例如转移到标号 `s` 处）。此时流程发生了转移。

---

#### [03:39] 段内近转移 CALL 指令的执行细节
具体到段内近转移的 `call 标号` 指令，执行过程如下：
1. **压栈**：将当前 `IP` 压栈；
2. **修改 IP**：
   $$IP = IP + \text{16位位移}$$

标号 `s` 在机器指令中会被解释为相对位移，而不是绝对地址。因此，这相当于依次执行了：
```assembly
push IP
jmp near ptr 标号
```

位移的计算方法为：
$$\text{位移} = \text{标号处的地址} - \text{call 指令后第一个字节的地址}$$

这个位移用于调节 `IP` 的值。由于位移是 16 位的补码表示，其数值范围是：
$$-32768 \sim 32767$$

这 16 位位移是由编译程序在编译时自动计算出来的。程序员在编写程序时只需书写标号即可，这种转移方式对程序员是非常友好的。

---

#### [05:08] CALL FAR PTR 标号（段间转移/远转移）
除了段内转移，还可以使用段间转移调用子程序，其格式为：`call far ptr 标号`。

当加上 `far ptr` 时，它实质上实现的是**段间转移**（远转移）：
1. **压栈**：首先将当前 `CS` 压栈，接着将当前 `IP` 压栈；
2. **转移**：将 `CS` 修改为标号所在段的段地址，将 `IP` 修改为标号在段内的偏移地址。

其操作等价于：
```assembly
push CS
push IP
jmp far ptr 标号
```

之所以将段地址 `CS` 和偏移地址 `IP` 都进行压栈，是因为在子程序返回时，需要通过出栈操作将原有的段地址和偏移地址全部恢复。

**对比总结：**
- **`call 标号`**：类似于 `jmp near ptr 标号`，机器指令中保存的是相对于当前 `IP` 的 16 位相对位移，实现的是段内转移；
- **`call far ptr 标号`**：机器指令中包含目标段地址和偏移地址，先压栈 `CS` 再压栈 `IP`，实现的是段间转移。

---

#### [07:02] 基于寄存器的 CALL 指令
在进行子程序调用时，还可以将转移的偏移地址放在寄存器中，例如：
```assembly
call ax
```

这里的 `AX` 中存放的是要转移到的偏移地址。其格式为：`call` 后面跟一个 16 位寄存器（通常使用通用寄存器）。

它的执行逻辑同样包含两步：
1. 将当前 `IP` 压栈；
2. 将 `IP` 修改为 16 位寄存器中所保存的偏移量。

其操作等效于：
```assembly
push IP
jmp 16位寄存器
```

---

#### [07:55] 基于内存单元的 CALL 指令
转移的目的地址还可以保存在内存单元中，常见有两种格式：

##### 1. 段内转移：`call word ptr 内存单元地址`
该指令从内存单元中取出一个字（Word，16 位）作为转移的目标偏移地址。

示例程序：
```assembly
mov sp, 10h
mov ax, 0123h
mov ds:[0], ax
call word ptr ds:[0]
```
- 栈顶指针 `SP` 初始为 `10H`；
- `AX` 赋值为 `0123H` 并存入 `ds:[0]`；
- 执行 `call word ptr ds:[0]` 时，先将当前 `IP` 压栈，栈指针减 2，`SP` 变为 `0EH`；
- 随后从 `ds:[0]` 内存单元中取出一个字（即 `0123H`）赋予 `IP`，程序跳转至偏移地址 `0123H` 处执行。

该指令等价于：
```assembly
push IP
jmp word ptr 内存单元地址
```

---

#### [09:34] 2. 段间转移：`call dword ptr 内存单元地址`
`dword`（Double Word）代表双字，占用 4 个字节。

该指令先压入 `CS`，再压入 `IP`，实现段间远转移。内存单元中连续存放的 4 个字节里：
- **低地址字**：存放转移的目标偏移地址（`IP`）；
- **高地址字**：存放转移的目标段地址（`CS`）。

示例程序：
```assembly
mov sp, 10h
mov ax, 0123h
mov ds:[0], ax
mov word ptr ds:[2], 0
call dword ptr ds:[0]
```
- 低地址 `ds:[0]` 写入偏移量 `0123H`；高地址 `ds:[2]` 写入段地址 `0`；
- 执行 `call dword ptr ds:[0]` 时，依次将当前 `CS` 和当前 `IP` 压栈，`SP` 经过两次压栈由 `10H` 减 4 变为 `0CH`；
- 接着从 `ds:[0]` 取出 `0123H` 赋予 `IP`，从 `ds:[2]` 取出 `0` 赋予 `CS`，完成段间转移。

---

#### [11:21] RET 指令与 POP IP
与 `call` 指令相配合的返回指令是 `ret` 指令。

`ret` 是一个无操作数指令，其功能是用栈中的数据修改 `IP` 的内容，从而实现近返回（段内转移）。栈中的数据通常是调用 `call` 时压入的下一条指令地址。

`ret` 指令的操作等价于：
```assembly
pop IP
```

从栈顶弹出数据并写入 `IP`，一旦写入 `IP`，程序流程便发生了转移。

示例分析：
```assembly
assume cs:code
stack segment
    db 16 dup (0)
stack ends

code segment
    mov ax, stack
    mov ss, ax
    mov sp, 16

    mov ax, 0
    push ax
    mov bx, 0
    ret
code ends
end
```
在该程序中：
1. 初始化栈段寄存器 `SS` 与栈顶指针 `SP`；
2. 执行 `mov ax, 0` 后将 `AX` 压栈（即向栈中压入数值 `0`）；
3. 执行 `mov bx, 0`；
4. 执行 `ret` 指令。

虽然前面没有使用 `call`，但 `ret` 指令只负责从栈顶弹出数据赋予 `IP`。此时弹出的值为 `0`，因此 `IP` 变为 `0`，程序流程重新跳转到代码段偏移地址为 `0` 的位置继续执行。这个例子直观地解释了 `ret` 指令的执行本质。

---

#### [13:44] RETF 指令与远返回
另一个返回指令是 `retf` 指令（RET-Far）。

`retf` 指令在返回时，需要同时从栈中恢复 `CS` 和 `IP`，以实现段间远转移：
1. 先弹出栈顶数据并赋给 `IP`（恢复偏移地址）；
2. 再弹出栈顶数据并赋给 `CS`（恢复段地址）。

其操作等价于：
```assembly
pop IP
pop CS
```

示例代码：
```assembly
; 栈段初始化...
push cs
mov ax, 0
push ax
retf
```
执行过程分析：
- 栈中先压入 `CS`，再压入 `0`（`AX`）；
- 执行 `retf` 时，先弹出 `IP = 0`，再弹出 `CS` 恢复原有代码段，程序跳转至原代码段偏移地址 `0` 处。

与 `ret` 相比，`retf` 多了一次对 `CS` 的出栈操作。栈中的返回地址也可以通过普通的压栈指令手工构造。

#### [15:21] CALL 与 RET 联调执行全流程追踪
最后我们对 `call` 指令与 `ret` 指令的执行全过程进行综合追踪：

```assembly
; 假定初始 CS = 2000H, IP = 0000H
mov ax, 0       ; 位于 2000:0000
call s          ; 位于 2000:0002
inc ax          ; 位于 2000:0005 (下一条指令地址)
s: 
pop ax          ; 位于 2000:000A
add ax, ax
ret             ; 位于 2000:000D
```

1. **执行到 CALL 指令处**：
   `mov ax, 0` 执行完后，`AX = 0`。当前 `CS = 2000H`，`IP = 0002H`。
2. **取指令与解析**：
   CPU 读取 `2000:0002` 处的 `call s` 指令送入指令缓冲器。此时 `IP` 自动增加，指向下一条指令的地址 `0005H`。
3. **压栈保存返回地址**：
   执行 `call` 指令，将当前 `IP`（即返回地址 `0005H`）压入栈中。
4. **转移到子程序入口**：
   根据相对位移计算，`IP` 加上位移后变为 `000AH`，合成物理地址 `2000:000AH`，转去执行标号 `s` 处的子程序代码。
5. **子程序执行**：
   执行子程序指令，`AX` 发生相应变化；执行推进到 `2000:000DH` 处的 `ret` 指令。
6. **RET 执行与恢复流程**：
   取出 `ret` 指令后，CPU 将栈中保存的地址（`0005H`）弹出赋予 `IP`。
7. **返回主程序**：
   下一时钟周期，CPU 便从 `2000:0005H` 处（即 `inc ax` 所在位置）继续向下执行。

至此，完成了整个子程序调用以及安全返回的闭环流程。
