# 改写中断例程：键盘中断（int 9）的定制与驻留

### [00:00] 改写中断例程的任务引入

在这一节中，我们来介绍一个非常重要的技术：改写中断例程。

在改写中断例程时，我们依然以键盘处理为例。其他设备的中断例程改写，其整体套路都是类似的。

我们现在要完成的任务是：安装一个新的 `int 9` 中断例程。在这个新的 `int 9` 中断例程中，要求实现在 DOS 环境下按下 F1 键后，改变当前屏幕的显示颜色，而其他按键则照常处理。

对比前面曾经介绍过的定制键盘输入处理程序，这两者之间有什么关联呢？
- 定制处理程序的问题在于：只有在运行当前程序时，某些按键的功能才会被改变；一旦退出该程序，一切又恢复正常。
- 而我们现在所讲的改写中断例程，是指在改写之后，该中断例程会常驻内存。即使安装程序退出不再运行，其他程序在运行过程中只要按下 F1 键，该例程仍然起作用。

因此，改写中断例程并使其常驻内存是一个更持久的技术，在很多设备底层应用中经常被用到，这也是我们必须掌握这项技术的原因。

---

### [01:22] 关键技术问题分析

要实现按下 F1 键后改变当前屏幕颜色、其他键照常处理，需要解决以下几个核心问题：

#### 1. 改变屏幕颜色的问题
改变屏幕颜色依然采取一种非常简单的方法：直接改写显示存储器（显存）中的数据。

在显存中，每个字符的显示占用两个字节（即一个字）：
- 低位字节保存字符的 ASCII 码；
- 高位字节保存字符的属性，而字符属性决定的就是颜色信息。

因此，高位字节对应的就是所有奇地址单元。我们只需改变奇地址单元中的数值即可。整个屏幕共可显示 2000 个字符（对应 4000 个字节），只要把这 4000 个字节中所有奇地址单元的值改变即可。

实现改变颜色的核心逻辑如下：
```assembly
    mov ax, 0b800h
    mov es, ax
    mov bx, 1
    mov cx, 2000
s:
    inc byte ptr es:[bx]
    add bx, 2
    loop s
```
显存的段地址放入 `ES`，`BX` 作为偏移地址初始赋为 1，循环 2000 次（对应屏幕上的 2000 个字符）。在执行过程中，递增 `ES:[BX]` 奇数单元的值，然后 `BX` 加 2 保持为奇数，继续循环，从而实现改变屏幕上每一个字符的颜色属性。

#### 2. 其他按键照常处理与原中断向量的保存
我们要改变 F1 键对应的功能，但其他键还要照常处理。遵循保留原有 DOS 提供功能的原则，我们需要调用原先的 `int 9` 中断处理程序来处理其他键盘输入。这是我们一贯的原则：尽量减少重复工作，我们只负责扩充功能。

这就涉及到原有的 `int 9` 中断例程入口地址的保存问题。将这个地址保存在哪里呢？

因为我们要编写的是一个独立于具体应用程序、常驻内存的中断例程，所以需要找到一个安全的物理单元来存放原入口地址。这里我们依然选择 `0:0200` 单元。在中断向量表中，这块空间通常是空闲未被占用的，我们借用这块空闲区域：原 `int 9` 中断例程（即从 9 号中断向量表项中取出的偏移地址 IP 和段地址 CS）就保存在 `0:0200` 开始的单元中。

#### 3. 新中断例程的安装位置
当我们编写并增加了新的中断例程后，它应该安装在何处？

此前改写内部中断例程时，通常安装在 `0:0200` 处。但现在 `0:0200` 处已经保存了原有的 `int 9` 中断例程地址，所以我们顺延将新的中断例程安装在 `0:0204` 处。

### [04:47] 汇编代码实现与段寄存器设置

解决上述问题后，接下来结合实现代码分析具体的执行流程。

```assembly
assume cs:code

stack segment
    db 128 dup (0)
stack ends

code segment
start:
    mov ax, stack
    mov ss, ax
    mov sp, 128

    push cs
    pop ds

    mov ax, 0
    mov es, ax
```

程序首先提供了一个栈段，用于子程序调用等操作的保护。
设置各个段寄存器：
- 将栈顶指针初始化。
- 执行 `push cs; pop ds;`，使得数据段寄存器 `DS` 指向当前代码段 `CS`，即数据段与代码段处于同一区域。
- 将附加段 `ES` 的段地址设置为 0，以便后续与 `0:0200`、`0:0204` 等地址相对应。

### [05:44] 新中断例程的安装与向量表修改

接下来是将新的中断例程安装到目标内存区域：

```assembly
    mov si, offset int9
    mov di, 204h
    mov cx, offset int9end - offset int9
    cld
    rep movsb
```

- 源地址偏移：`SI = offset int9`；
- 目的地址偏移：`DI = 204h`；
- 传送长度：`CX = offset int9end - offset int9`，计算出新中断例程代码的字节长度；
- 清除方向标志位（`cld`），使用串传送指令 `rep movsb` 将代码复制到 `0:0204` 开始的区域。

此处执行串传送指令时：
- `SI` 默认对应的段是 `DS`（即代码段 `CS`）；
- `DI` 默认对应的段是 `ES`（即 0 段）；
- 从而准确地将新例程代码安装到了 `0:0204H` 处，满足设计要求。

紧接着，将原有的中断例程入口地址保存到 `0:0200` 处，并修改 9 号中断向量表：

```assembly
    ; 保存原 int 9 中断向量到 0:0200 处
    push es:[9*4]
    pop es:[200h]
    push es:[9*4+2]
    pop es:[202h]

    ; 改写 9 号中断向量
    cli
    mov word ptr es:[9*4], 204h
    mov word ptr es:[9*4+2], 0
    sti

    mov ax, 4c00h
    int 21h
```

- 将原中断向量表中的偏移地址放入 `0:0200H`，段地址放入 `0:0202H`；
- 改写后的入口地址为：偏移地址 `204H`，段地址 `0`；
- 在修改中断向量的过程中，该操作不允许被外部中断打断，因此需要通过 `cli` 清除中断标志（屏蔽外部可屏蔽中断），设置完毕后再使用 `sti` 恢复允许中断。
- 主程序执行到此处即可退出（返回 DOS）。

### [08:21] 新中断例程的代码逻辑与 F1 键处理

接下来看新中断例程 `int9` 的具体实现：

```assembly
int9:
    push ax
    push bx
    push cx
    push es

    in al, 60h

    pushf
    call dword ptr cs:[200h]

    cmp al, 3bh
    jne int9ret

    mov ax, 0b800h
    mov es, ax
    mov bx, 1
    mov cx, 2000
s:
    inc byte ptr es:[bx]
    add bx, 2
    loop s

int9ret:
    pop es
    pop cx
    pop bx
    pop ax
    iret
int9end:
    nop
```

#### 逻辑解析：
1. **现场保护**：例程入口对 `AX`、`BX`、`CX`、`ES` 进行压栈保护，在退出时依次出栈。
2. **读取扫描码**：当键盘上有键按下时触发该中断，首先从 60h 端口（`in al, 60h`）读入当前按键的扫描码到 `AL` 中。
3. **调用原中断例程**：对于其他普通按键，需要保持原有功能。因此先通过标志寄存器压栈（`pushf`），再使用 `call dword ptr cs:[200h]` 模拟中断调用原有的旧中断例程。
   > **注意**：此处为什么使用 `cs:[200h]`？
   > 因为这段程序在前面的安装步骤中已经被复制安装到了段地址为 0 的内存区域运行。当它作为中断例程被 CPU 调用执行时，其代码段寄存器 `CS` 的值就是 0，因此 `cs:[200h]` 指向的就是 `0:0200H` 单元（即之前保存旧中断向量的地方）。这一点必须深入理解。
4. **处理 F1 按键**：
   - 将读入的扫描码 `AL` 与 `3Bh` 进行比较（`3Bh` 是 F1 键的通码/扫描码）。
   - 如果不等于 `3Bh`（`jne int9ret`），则直接跳转到退出标签，不进行颜色修改。
   - 如果按下的是 F1 键，则执行显存改变颜色的循环，将全屏幕所有 2000 个字符的属性字节递增，实现颜色的实时变换。
5. **恢复并返回**：出栈恢复各寄存器，最后执行 `iret` 中断返回。

### [11:11] 程序编译、链接与运行效果演示

我们将上述完整代码保存为 `ptest.asm` 文件，在 DOS 环境下进行编译、链接与运行：

```shell
masm ptest;
link ptest;
ptest
```

运行程序之后，命令行表面上没有任何变化，似乎看不出效果。这是因为该程序的作用仅仅是安装驱动程序/中断例程：它将编写好的例程代码装入了内存的 `0:0204` 区域，修改了中断向量表，随后安装程序自身就退出了。

但该例程已经常驻在内存中：
- 此时在 DOS 命令行下，无论系统在执行什么任务，只要按下 **F1** 键，屏幕上的颜色就会随之改变；按下其他键则依然是原有的输入功能。
- 在部分演示环境中，由于屏幕录像软件自身占用了 F1 等快捷键导致冲突，可能无法直接显示变化，大家可以在自己的纯净编程环境中测试，会观察到非常奇妙的实时变色效果。
