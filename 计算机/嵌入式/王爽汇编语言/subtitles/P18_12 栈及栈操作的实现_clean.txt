# 汇编语言：栈及栈操作的实现

---

### [00:00] 栈结构的基本概念

在汇编语言当中，栈（Stack）是一种非常重要的数据结构。它的核心特点是：**只允许在单端进行插入或删除操作**。

我们可以将栈形象地比作一个一端封口的容器（如一个瓶子）。如果在瓶子中依次放入元素 2、1、3，那么放入时的顺序是 $2 \to 1 \to 3$。此时若想将最底部的元素 2 取出，必须遵循特定次序：
1. 先将最外层的元素 3 取出；
2. 再将元素 1 取出；
3. 最后才能取出元素 2。

由此可见，栈具有两个最基本的操作：
* **入栈（Push）**：将一个新元素存入栈顶。栈顶的位置随元素的放入而动态变化。
* **出栈（Pop）**：从栈顶取出一个元素。元素取出后，栈顶位置同样会发生动态变化。

栈的操作始终针对**栈最顶端的元素**展开。栈顶元素必定是最后入栈的，但在需要出栈时，又是最先被取出的。因此，栈的操作规则被称为**后进先出**（Last In, First Out，简称 **LIFO**）。

### [01:28] 8086 CPU 对栈机制的硬件支持

在通常认知中，栈常被视为纯软件层面的数据结构。然而现代 CPU 在硬件架构上直接提供了对栈的原生支持。8086 CPU 内部设计了专门的硬件机制和指令集，支持程序员以栈的方式直接访问内存空间。

在 8086 汇编编程中，我们可以将指定的一段连续内存划定为栈空间，直接使用 CPU 提供的指令对该内存段进行栈操作。

涉及的核心指令有两个：
* `push`（入栈）
* `pop`（出栈）

例如：
* `push ax`：将寄存器 `AX` 中的数据送入栈中（操作数可以是寄存器，也可以是内存单元）。
* `pop ax`：从栈顶取出数据，并送入寄存器 `AX` 中。

> **注意**：8086 CPU 的出栈与入栈操作均**以“字”（Word，即 2 个字节 / 16 位）为基本单位**。8086 不支持针对单个字节（Byte）的 `push` 或 `pop`。若需要操作字节，必须将其拼装为一个字（例如放入 16 位寄存器的高 8 位或低 8 位，舍弃未使用的部分）后再进行操作。

### [03:04] 栈操作执行过程演示

以下是一组典型的栈操作指令序列：

```assembly
mov ax, 0123H
push ax
mov bx, 2266H
push bx
mov cx, 1122H
push cx

pop ax
pop bx
pop cx
```

**执行流程解析：**
1. **初始状态**：将一段内存预留为栈空间，此时栈为空，栈顶指针指向栈空间最高地址单元的外部。
2. **入栈过程**：
   * `mov ax, 0123H` 随后执行 `push ax`：栈顶指针向前移动，将 `AX` 的值（`0123H`）写入栈顶单元。
   * `mov bx, 2266H` 随后执行 `push bx`：栈顶指针继续移动，将 `BX` 的值（`2266H`）压入栈。
   * `mov cx, 1122H` 随后执行 `push cx`：栈顶指针继续移动，将 `CX` 的值（`1122H`）压入栈。
3. **出栈过程**：
   * 执行 `pop ax`：从当前栈顶取出元素 `1122H` 送入 `AX`，栈顶指针回退。此时 `AX = 1122H`。
   * 执行 `pop bx`：从栈顶取出元素 `2266H` 送入 `BX`，栈顶指针回退。此时 `BX = 2266H`。
   * 执行 `pop cx`：从栈顶取出元素 `0123H` 送入 `CX`，栈顶指针回退。此时 `CX = 0123H`。
4. **结束状态**：三个数据全部出栈后，栈重新回到空栈状态。

### [05:18] 栈段寄存器 SS 与栈指针寄存器 SP

这引发了两个核心问题：
1. **CPU 如何知道哪一段内存空间被用作栈？**
2. **在执行 `push` 与 `pop` 时，CPU 如何定位栈顶元素？**

8086 CPU 专门配备了两个与栈直接相关的寄存器：
* **`SS`（Stack Segment，栈段寄存器）**：存放栈段的段地址。
* **`SP`（Stack Pointer，栈指针寄存器）**：存放当前栈顶的偏移地址。

在任何时刻，**由 `SS:SP` 计算出的物理地址即为当前栈顶元素所在的位置**：
$$\text{物理地址} = \text{SS} \times 16 + \text{SP}$$

无论是入栈还是出栈，CPU 均严格根据 `SS:SP` 的指示来确定栈顶单元。

### [06:56] 栈的初始化与内存布局

以下代码演示了如何初始化栈并向其中存放数据：

```assembly
mov ax, 1000H
mov ss, ax
mov sp, 0010H

mov ax, 001AH
mov bx, 001BH

push ax
push bx

pop ax
pop bx
```

#### 1. 栈段与栈顶初始化
* 8086 不允许将立即数直接送入段寄存器，需通过通用寄存器中转：
  ```assembly
  mov ax, 1000H
  mov ss, ax
  mov sp, 0010H
  ```
* 此时段地址为 `1000H`，物理段基址为 `10000H`。
* `SP` 设置为 `0010H`（十六进制的 10H 即十进制的 16）。这代表该栈的大小为 **16 个字节**（地址空间范围为 `1000:0000` 到 `1000:000F`）。
* 初始化完成后，`SS:SP` 指向 `1000:0010H`（即栈底空间最高单元之外的下一个单元），代表**空栈**状态。

#### 2. 数据入栈与交换机制
* 为寄存器赋值：`AX = 001AH`，`BX = 001BH`。
* 执行 `push ax`：栈顶指针调整，将 `001AH` 压栈。
* 执行 `push bx`：栈顶指针调整，将 `001BH` 压栈。
* 依次执行 `pop ax`、`pop bx`：
  * 先弹出栈顶元素送入 `AX`，此时 `AX = 001BH`；
  * 再弹出下一栈顶元素送入 `BX`，此时 `BX = 001AH`。

出栈后，内存单元中的残留数据虽然并未被物理擦除，但因为栈顶指针已经改变，这些数据已被标记为失效。

> **编程技巧**：在高级语言中交换两个变量的值通常需要引入中间变量（$temp$）；而在汇编语言中，借助栈的“后进先出”机制，仅通过连续入栈后出栈，即可直接实现数据的交换。

通过 Debug 工具可以验证此过程：
* 使用 `A` 命令汇编输入指令；
* 使用 `T` 命令单步跟踪观察寄存器及 `SS:SP` 的变化；
* 使用 `D` 命令查看指定内存段中的数据变换。

### [11:53] PUSH 与 POP 指令的底层执行细节

结合底层机制，`push` 与 `pop` 的详细执行步骤如下：

#### `push ax` 的执行过程：
1. 栈指针递减（向低地址方向扩展）：
   $$\text{SP} = \text{SP} - 2$$
2. 将数据写入当前 `SS:SP` 所指向的内存字单元：
   $$(\text{SS:SP}) \leftarrow \text{AX}$$

#### `pop ax` 的执行过程：
1. 从当前 `SS:SP` 所指向的内存字单元读取数据送入寄存器：
   $$\text{AX} \leftarrow (\text{SS:SP})$$
2. 栈指针递增（向高地址方向收缩）：
   $$\text{SP} = \text{SP} + 2$$

本质上，栈操作就是**自动调整指针**与**内存数据传送**两个步骤的原子化结合。

### [13:28] 栈顶越界（超界）问题

栈空间在物理上只是一段指定长度的连续内存。在频繁入栈和出栈的过程中，极易引发超界问题：

#### 1. 入栈越界（栈满溢出 / Overflow）
当设定的栈空间（例如 16 字节）已经被写满（已入栈 8 个字），若继续执行 `push` 指令，`SP` 会继续减小，数据将被写入栈空间之外的高阶或低阶内存区域。这会意外覆盖其他程序的数据或指令代码，造成不可控的系统故障。

#### 2. 出栈越界（空栈下溢 / Underflow）
当栈中全部数据均已弹出、栈已处于空栈状态时，若再次执行 `pop` 指令，`SP` 会继续增大，导致 CPU 从栈定义范围之外的地址读取未知数据，同样会引发严重的逻辑错误。

---

### [15:25] 8086 CPU 对栈越界的处理机制

对于超界的危险性，8086 CPU **并不提供任何硬件级越界防护或检查机制**。

* **CPU 的局限性**：8086 只盲目根据 `SS:SP` 指示的当前地址读写内存并修改 `SP`，它**完全不知道**程序员规划的栈空间边界究竟有多大。
* **程序员的职责**：在汇编语言这类低级语言中，没有上层语言的越界异常捕获机制。空间的自由度由程序员全权掌控，相应的责任也由程序员完全承担。开发者必须：
  1. 准确预估程序运行中可能用到的最大栈深度，分配合理充足的栈空间；
  2. 严格控制入栈与出栈次数，防止栈溢出与空栈出栈。

### [16:39] 总结

1. **指令本质**：`push` 和 `pop` 本质上是一种具备特定约束的内存传送指令，受 `SS:SP` 联合寻址控制，严格遵循 LIFO 规则。
2. **指针维护**：执行 `push` 和 `pop` 时，`SP` 的值由硬件自动完成 $+2$ 或 $-2$ 的调整。在整个汇编程序中，除了初始阶段给 `SS` 和 `SP` 赋值以建立栈之外，其余时刻均无需（也不应）手动干预 `SP` 的数值。
3. **编程思维**：编写汇编程序时，重点在于理解 `SS:SP` 的动态指向及栈深度边界控制，熟练利用栈实现数据备份、暂存与传参等核心逻辑。
