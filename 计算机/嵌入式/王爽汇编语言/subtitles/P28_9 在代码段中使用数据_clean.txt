# 汇编语言：在代码段中使用数据

---

### [00:00] 引言：直接操作物理内存的危险性

在这一节中，我们介绍在代码段中使用数据的方法。

先从一个危险的程序说起。这个程序是从这一段内存中把数据取出来，拷贝到另外一段内存中去。也就是说，我们把前一段的数据逐个取出，并复制到后一段中。

面对这样的任务，写出程序并不困难。我们使用 `DS` 作为数据段寄存器，指向源数据段；使用 `ES` 作为附加段寄存器，指向目标数据段的段地址。接着通过循环，使用 `BX` 控制偏移地址，循环 12 次，将每个字节的数据读取出来并完成复制。这个程序前面讲过，结构比较简单。

### [00:50] 直接指定物理地址的安全隐患

但是必须指出，这个程序存在严重问题，是非常危险的。

问题出在哪里？程序中直接写入了固定的物理地址。在计算机系统内部，每一块地址的用途都有非常明确的划分。例如 `0:200` 这样的地址区间，实际上是用来存放中断处理程序的。如果本该存放系统程序的地方，被当前程序强行写入了数据，极有可能引发系统混乱甚至崩溃。许多黑客攻击与破坏手段，正是利用了在不该写入代码或数据的地方植入自身指令的漏洞。因此，在程序中直接指定物理内存地址是极其危险的。

---

### [01:35] 解决方案：在程序的段中存放数据

这就引出了一个核心问题：**如果我们希望安全地存放数据，数据究竟应当存放在哪里？**

在常规的程序设计中，对策是在程序的**段（Segment）**中存放数据。我们明确指定在程序的某一段中存放数据。当程序被调入内存运行时，由操作系统统一进行内存空间的动态分配，操作系统会为这些段分配合适且安全的物理内存地址。

汇编语言中的段类别包括：
* **数据段（Data Segment）**
* **代码段（Code Segment）**
* **栈段（Stack Segment）**

这些段均由我们在源程序中进行定义，在程序加载时由系统分配空间，而不是直接在程序中硬编码物理地址。

上述段空间均可用于存放数据。我们可以在单一的段中安排数据，也可以将数据、代码和栈分别存放在不同的独立段中。

---

### [02:35] 案例需求：在代码段中定义数据

来看一个实际的应用案例：**编写程序计算 8 个数据的累加和**。

这 8 个数据均为字型数据（Word），因此 8 个字占用了 16 个字节。16 个字节用十六进制表示即为 $10\text{H}$。

题目需求中并没有硬性规定这 8 个数据必须保存在内存的具体哪个单元中，这与之前限定内存单元的需求截然不同。因此，这些数据存放的具体位置，完全可以由程序员在编写程序时自行决定。

我们可以在 `code segment`（代码段）中直接定义这批数据：

```assembly
code segment
    dw 0123h, 0456h, 0789h, 0abch, 0defh, 0fedh, 0cbah, 0987h
    ; 后续代码
code ends
end
```

在这段程序中，我们在代码段的起始位置直接写入了待计算的数据。

这里使用了伪指令 `dw`。`dw` 即 **Define Word**（定义字），用于定义字型数据。后方每个逗号隔开的数值都是一个字，占用 2 个字节。8 个字型数据总计占用 16 个字节（$10\text{H}$ 字节）。

除了使用 `dw` 定义字型数据，汇编语言中还可以使用：
* `db`（**Define Byte**）：定义字节型数据（1 字节）。
* `dd`（**Define Double Word**）：定义双字型数据（4 字节）。

---

### [04:05] 程序累加逻辑与段前缀 CS

完成数据定义后，进行 8 个数据的累加操作就十分简便了：

* 寄存器 `BX` 用作偏移地址指针，初始值为 `0`。
* 寄存器 `AX` 用作累加器，保存最终的相加和。
* 寄存器 `CX` 用作循环计数器，设置循环次数为 `8`。

初始化完成后，在循环体中每次通过 `cs:[bx]` 取出数据。

> **注意**：这里必须显式使用段前缀 `CS`。因为所定义的数据存放在代码段中，数据的段地址即为当前代码段的段地址（`CS`），而偏移地址则由 `BX` 提供。

每完成一次加法，通过 `add bx, 2` 将偏移地址增加 2（指向下一个字型数据），随后循环执行，依次将 8 个字累加到 `AX` 中：

```assembly
assume cs:code
code segment
    dw 0123h, 0456h, 0789h, 0abch, 0defh, 0fedh, 0cbah, 0987h

    mov bx, 0
    mov ax, 0
    mov cx, 8
s:
    add ax, cs:[bx]
    add bx, 2
    loop s

    mov ax, 4c00h
    int 21h
code ends
end
```

---

### [05:20] 执行流程与内存布局分析

回顾上述实现：以 `BX` 作为偏移地址，初始值为 `0`，每次累加后执行 `add bx, 2`，偏移地址依次递增为 `2`、`4`、`6`……逐个取出段地址为 `CS` 的数据进行累加，累加逻辑得到了圆满解决。

但是，必须清晰认识到该程序的内存布局结构：
* 该程序编译链接并载入内存后，**前 16 个字节（偏移地址 `0000H` 到 `000FH`）代表纯数据**。
* **从第 17 个字节（偏移地址 `0010H`）开始，才是真正的可执行指令**。

---

### [06:00] 发现新问题：入口地址 IP 偏移错误

该程序虽然逻辑看似完整，但直接运行时依然存在重大隐患。

当程序完成编译、链接后，通过 Debug 工具加载跟踪时，会发现初始状态下寄存器 `IP` 的值为 `0000`。在常规程序中，`IP` 默认从 `0000` 开始取指执行，因为第一条指令通常就是可执行代码。

然而当前程序中，真正的可执行代码并非从偏移地址 `0000H` 开始，偏移地址 `0000H` 处存放的是我们预设的数据。如果直接从 `0000H` 开始执行，CPU 就会把这 16 个字节的数据强制当作机器指令进行译码执行！

在 Debug 中使用 `u`（Unassemble，反汇编）命令从默认位置查看时，看到的指令是一堆莫名其妙的混乱代码，根本不是我们编写的 `mov bx, 0`、`mov ax, 0`。

仔细比对内存数据即可发现原因所在：
偏移地址 `0000H` 处的数据为 `23 01`，按小端序（低字节在低地址，高字节在高地址）读取即是 `0123H`；紧随其后的数据是 `56 04`，对应的即是 `0456H`。这片区域原本是数据，绝不应作为机器指令被执行。

---

### [07:13] 验证可执行代码的真实偏移

使用 Debug 的 `d`（Dump，内存查看）命令观察：
`0000H` 处依次排列着 `0123H`、`0456H`、`0789H` 等字型数据。

如果执行反汇编命令 `u 0010`，从代码段偏移地址 `0010H` 开始查看，程序指令便恢复正常：
```text
mov bx, 0000
mov ax, 0000
mov cx, 0008
add ax, cs:[bx]
add bx, 0002
loop ...
```
这证实真正的代码实际始于偏移地址 `0010H`。

---

### [08:01] 改进方案：使用标号指定程序入口

为了避免 CPU 将数据当作指令执行，关键在于：**确保程序加载进内存时，`IP` 初始值自动指向真正的代码起点 `0010H`，即让数据位于 `cs:0000`，而代码执行始于 `cs:0010`。**

改进方案非常简洁且规范：
1. **在真正的第一条可执行指令前增加一个标号（例如 `start:`）**；
2. **在源程序末尾的伪指令 `end` 后方附上该标号（即 `end start`）**。

标号的作用：
* **定义标号 `start:`**：标记并指示第一条可执行代码的起始逻辑位置（标号名称可自定义）。
* **通知编译器 `end start`**：除了通知编译器源程序在此结束之外，还明确告知编译器程序的执行入口（Entry Point）就在标号 `start` 所在的位置。

```assembly
assume cs:code
code segment
    dw 0123h, 0456h, 0789h, 0abch, 0defh, 0fedh, 0cbah, 0987h

start:
    mov bx, 0
    mov ax, 0
    mov cx, 8
s:
    add ax, cs:[bx]
    add bx, 2
    loop s

    mov ax, 4c00h
    int 21h
code ends
end start
```

---

### [09:45] 改进后的 Debug 验证

采用带标号的结构重新编译、链接并载入 Debug：

1. **观察寄存器状态**：程序加载完成后，`IP` 寄存器的初始值被自动正确设置为 `0010`，`CS:IP` 准确指向标号 `start` 处的第一条指令。
2. **反汇编验证**：直接使用 `u` 命令查看当前指令，反汇编输出的第一条指令即为 `mov bx, 0000`，与源代码中的起始指令完全吻合。
3. **数据区验证**：使用 `d cs:0` 命令查看，在偏移地址 `0000H` 处，`01 23`、`04 56`、`07 89` 等字型数据完整保留。

通过标号指明程序入口，使数据与指令在同一个段内各司其职，程序得以安全、正确地运行。

---

### [10:45] 总结

本讲介绍了在代码段中定义并使用数据的标准范式：

1. 数据可以直接定义在代码段内部，通常放置在第一条可执行指令之前。
2. 在实际代码出现的位置必须加上入口标号（如 `start:`）。
3. 在模块结束指令 `end` 后必须指定该入口标号（如 `end start`），确保操作系统加载程序时能够正确初始化 `CS:IP`，从而规避将数据误译为指令的严重错误。
