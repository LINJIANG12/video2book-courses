# CMP 比较指令与条件转移指令详解

### [00:00] CMP 比较指令概述与基本原理

在这一节，我们介绍 `CMP` 比较指令和条件转移指令。

首先看一下比较指令。比较指令是一个双操作数指令，也就是说它后边可以跟上两个操作对象。它的功能就是把操作对象 1 减去操作对象 2。

我们可以看到这有点怪：它是一个比较指令，相当于完成的是一个减法操作，但是要注意到，**相减以后的结果是不保存的**。

既然不保存结果，相减有什么意义呢？它的意义在于：在执行这条指令以后，对**标志寄存器**（Flags Register）将会产生影响。

现在看一下它是怎样去影响这些标志寄存器的。比如现在给出这样一组指令：

```assembly
CMP AX, AX
```

它实际上执行的操作就是用 `AX` 减去 `AX`：

$$AX - AX = 0$$

它的结果是 0，但是这个结果并不会在 `AX` 里面保存，而是会影响标志寄存器里面的各个状态位：
- **ZF（零标志位）**：$AX - AX$ 结果为 0，所以 $ZF = 1$。
- **PF（奇偶标志位）**：对于结果 0 来说，二进制中一个 1 都没有（0 个 1 为偶数个），所以在里面 $PF = 1$。
- **SF（符号标志位）**：结果是非负数，所以 $SF = 0$。
- **CF（借位/进位标志位）**：没有产生借位，所以 $CF = 0$。
- **OF（溢出标志位）**：没有溢出，所以 $OF = 0$。

可以看到，由于在里面做了相减的操作，对这些标志寄存器都是有影响的。

### [01:39] CMP 比较指令示例与标志位分析

再看另外一个例子。假设现在 `AX` 里面是 8，`BX` 里面是 3：

```assembly
CMP AX, BX
```

它会执行 $AX - BX$。执行的结果是什么呢？最后求得的结果是 5，但是这个 5 是不保存的。

由于结果是 5，造成了标志寄存器当中各个位上的变化：
- **ZF**：因为 5 不是 0，零标志为 0（$ZF = 0$），表示非零值。
- **PF**：对于 5 来说，二进制表示为 `...00000101B`，其中 1 的个数是 2 个（偶数个），所以 $PF = 1$。
- **SF**：5 是一个正数，作为有符号数来说是非负的，所以 $SF = 0$。
- **CF**：没有产生借位，$CF = 0$。
- **OF**：没有产生溢出，$OF = 0$。

在这里可以看到，它对标志寄存器当中的位产生了影响。

这其实就决定了 `CMP` 的用法：在经过 `CMP` 调用以后，它会产生对标志寄存器的影响，因此可以通过**标志寄存器的值去确定比较结果**。我们根据这些寄存器的取值，就能知道到底哪个大、哪个小，从而完成比较。

### [03:06] 基于标志位的无符号数比较逻辑

通过 `CMP` 指令执行完以后，根据相关标志位的值的变化，我们怎样能够看出比较的结果呢？

假设我们要比较的是：

```assembly
CMP AX, BX
```

根据执行 `CMP AX, BX` 指令之后标志寄存器的变化，我们就能够确定 `AX` 和 `BX` 的大小比较关系。具体要看这两个寄存器当中的值是等于、不等于、小于、大于等于、大于、还是小于等于等等关系：

1. **等于（$AX = BX$）**：
   在比较的过程中要做 $AX - BX$ 的运算。如果两个值相等，相减的结果一定是 0。如果相减结果是 0，ZF 的值一定是 1（$ZF = 1$）。因此将来在调用 `CMP AX, BX` 以后，如果标志寄存器的值 $ZF = 1$，就可以断定 `AX` 和 `BX` 里面的值一定是相等的。
2. **不等于（$AX \neq BX$）**：
   两者不等时，相减以后的结果为非 0，则 $ZF = 0$。根据 $ZF = 0$ 就可以知道 `AX` 和 `BX` 不相等。
3. **小于（$AX < BX$）**：
   $AX - BX$ 的时候会产生借位，而一旦产生借位，$CF = 1$。所以按照 $CF = 1$ 就可以判断成立小于的关系。
4. **大于等于（$AX \ge BX$）**：
   $AX - BX$ 时不必借位，因此根据 $CF = 0$ 就可以确定是大于等于。
5. **大于（$AX > BX$）**：
   在相减的时候：
   - 第一，不用借位（$CF = 0$）；
   - 第二，结果不为 0（$ZF = 0$）。如果结果为 0 就变成相等（大于等于）了。
   所以既不借位、结果又不为 0（$CF = 0$ 且 $ZF = 0$）。
6. **小于等于（$AX \le BX$）**：
   $AX - BX$ 时，或者产生借位（$CF = 1$，即严格小于），或者结果为 0（$ZF = 1$，即等于）。所以对应的标志状态是：或者借位，或者结果为 0（$CF = 1$ 或 $ZF = 1$）。

因此，比较指令的设计思路就是：通过在 `CMP` 当中做减法运算去影响标志寄存器，然后根据标志寄存器相关位的取值来体现比较的结果，这就是一个非常核心的设计思想。

### [06:06] 有符号数的比较判断

刚才讲的是无符号数的比较。其实对于有符号数来说，它们之间的这六种关系也可以推导出标志寄存器该如何变化。很多参考资料里面都有推导过程，我们推导一次知道其中的道理，将来在用的时候更加得心应手就可以了。

注意到有符号数与无符号数稍微不一样的是：有符号数需要综合考虑运算结果的正负（符号位 SF）以及是否发生溢出（溢出位 OF）等情况。

有了这些关系之后我们要明确：将来就可以根据标志寄存器的取值去确定到底满足大于还是小于的关系。

### [06:58] 条件转移指令分类与常见指令

下面看一下**条件转移指令**。我们在编写程序时经常有这样一个套路：先调用 `CMP` 指令（或者其它能够影响标志寄存器的指令，不一定非得是 CMP，只要能改变标志寄存器即可）。

前面的指令影响了标志寄存器，在后边就可以使用以 `J` 打头的指令，这类指令叫做条件转移指令。在满足条件转移时，它可以把流程转移到某个标号所在的位置。

根据**单个标志位**进行转移的指令如下：

| 指令 | 英文全称 / 含义 | 转移条件 |
| :--- | :--- | :--- |
| `JE` | Jump if Equal（相等则跳转） | $ZF = 1$ |
| `JZ` | Jump if Zero（结果为 0 则跳转） | $ZF = 1$ |
| `JNE` | Jump if Not Equal（不相等则跳转） | $ZF = 0$ |
| `JNZ` | Jump if Not Zero（结果不为 0 则跳转） | $ZF = 0$ |
| `JS` | Jump if Sign（符号为负则跳转） | $SF = 1$ |
| `JNS` | Jump if Not Sign（符号为正则跳转） | $SF = 0$ |
| `JO` | Jump if Overflow（有溢出则跳转） | $OF = 1$ |
| `JNO` | Jump if Not Overflow（无溢出则跳转） | $OF = 0$ |
| `JP` / `JPE` | Jump if Parity / Parity Even（1 的个数为偶数则跳转） | $PF = 1$ |
| `JNP` / `JPO`| Jump if Not Parity / Parity Odd（1 的个数不为偶数则跳转） | $PF = 0$ |
| `JB` | Jump if Below（低于则跳转） | $CF = 1$ |
| `JC` | Jump if Carry（有借位/进位则跳转） | $CF = 1$ |
| `JNAE` | Jump if Not Above or Equal（不高于等于则跳转） | $CF = 1$ |
| `JNB` / `JNC` / `JAE` | 低于/借位条件的取反（高于等于则跳转） | $CF = 0$ |

- `JE` 和 `JZ` 是一码事：两个数相减如果相等就会得到 0，它们检测的都是零标志位 ZF。其中 J 代表 Jump，E 代表 Equal，Z 代表 Zero。
- `JNE` 中的 N 代表 Not，即 Not Equal（不相等时跳转，或结果不为 0 时跳转）。
- `JB`（Below，低于）等价于 `JNAE`（Not Above or Equal，不高于等于），而在减法运算中低于就意味着需要借位，因此也等价于 `JC`（Carry，有进位/借位）。这三条指令是完全等价的。

把每个字母所对应的英文含义搞清楚以后，这些指令是非常好理解的。

### [10:18] 基于比较结果的高级条件转移指令

#### 1. 无符号数比较转移指令
- `JA`（Jump if Above）：高于则跳转，等价于 `JNBE`（Jump if Not Below or Equal，不低于且不等于）。
- `JAE`（Jump if Above or Equal）：高于或等于则跳转，等价于 `JNB`（Jump if Not Below）。
- `JB`（Jump if Below）：低于则跳转，等价于 `JNAE`。
- `JBE`（Jump if Below or Equal）：低于或等于则跳转，等价于 `JNA`（Jump if Not Above，不高于则跳转）。

#### 2. 有符号数比较转移指令
对于有符号数比较，指令中使用：
- **L** 代表 Less（小于）
- **G** 代表 Greater（大于）

常见的指令如 `JL`（小于则跳转）、`JNL`（不小于则跳转）、`JG`（大于则跳转）、`JNG`（不大于则跳转）、`JLE`（小于等于则跳转）、`JGE`（大于等于则跳转）等。

### [11:24] 逻辑含义与编写思路

看到这么多指令，大家可能会有一种顾虑：将来在构造条件转移的时候，是不是真的要把这么多繁琐的指令全背下来？是不是都必须去分析它到底检测哪个标志寄存器？

大家放心，实际编写程序时不会这么繁琐。

我们在将条件转移指令和 `CMP` 指令配合使用时，**不需要在写代码时每次都去推导 CMP 对相关标志位的影响以及转移指令对标志位的底层检测细节**。我们只需要直接考虑比较指令和条件转移指令配合时所表现出的**逻辑含义**即可。前面分析底层原理，是为了让大家深刻理解条件转移指令背后的运行机制。

### [12:22] 条件转移实现分支结构：双分支 if-else 示例

接下来看如何通过条件转移指令和 `CMP` 指令配合，实现高级语言中的 `if-else` 分支功能。

**需求示例**：
若寄存器 `AH` 和 `BH` 的值相等，则执行 $AH = AH + AH$；否则执行 $AH = AH + BH$。

用高级语言（C 语言）描述为：

```c
if (ah == bh) {
    ah = ah + ah;
} else {
    ah = ah + bh;
}
```

**汇编代码实现**：

```assembly
    CMP AH, BH          ; 比较 AH 与 BH
    JE S                ; 若相等 (ah == bh)，跳转到标号 S 执行
    ADD AH, BH          ; 不相等 (else 分支)，执行 ah = ah + bh
    JMP SHORT OK        ; 执行完毕，跳过 if 分支的代码
S:  
    ADD AH, AH          ; 相等 (if 分支)，执行 ah = ah + ah
OK: 
    ; 后续代码
```

**执行流程分析**：
1. 首先执行 `CMP AH, BH` 进行比较。
2. 紧接着使用 `JE`（相等跳转）：若相等，则跳转到标号 `S` 处执行 `ADD AH, AH`。
3. 若不相等，`JE` 不会跳转，程序顺序执行下一句 `ADD AH, BH`；执行完成后，通过无条件转移指令 `JMP SHORT OK` 跳过标号 `S` 的处理逻辑，直接来到 `OK` 处。

可以看到，这种写法与 C 语言的逻辑完全一致，虽然指令跳转的形式和高级语言有些差异，但其表达的逻辑思维完全一致。在实际编写汇编代码时，我们依靠逻辑含义即可顺畅写出，而不需要时刻去纠结底层标志寄存器具体是哪一位在变动。

### [14:13] 条件转移实现分支结构：单分支 if 示例

再看一个单分支结构示例。

**需求示例**：
如果 $AX = 0$，则执行 $AX = AX + 1$。

用 C 语言描述为：

```c
if (ax == 0) {
    ax++;
}
```

**汇编代码实现**：

```assembly
    ADD AX, 0           ; 将 AX 与 0 相加，目的在于通过运算改变标志寄存器
    JNZ S               ; 如果结果不为 0 (ax != 0)，则跳转到标号 S（跳过自增）
    INC AX              ; 结果为 0 时顺序执行，使 AX 增加 1
S:  
    ; 后续代码
```

**执行流程分析**：
1. 这里使用 `ADD AX, 0`，加上 0 虽不改变数值，但会改变标志寄存器。若 `AX` 本身就是 0，相加后结果为 0，$ZF = 1$；若 `AX` 非 0，则 $ZF = 0$。
2. 紧接着使用 `JNZ S`（结果非零则跳转）：如果 `AX` 原本不是 0，则条件成立跳到 `S`，跳过后面的递增代码。
3. 如果 `AX` 是 0，则 `JNZ` 条件不成立，顺序执行 `INC AX`，将 `AX` 的值加 1。

这就完整实现了高级语言中单分支 `if (ax == 0) ax++;` 的逻辑。

### 总结

通过条件转移指令和 `CMP`（或算术运算）指令相互配合，我们就可以实现高级语言中各类 `if` 语句的分支功能。虽然汇编语言在表现形式上与 C 语言等高级语言有所差异，但控制逻辑与思维方式是完全通用的。掌握这种映射关系，就可以熟练解决实际的分支程序设计问题。
