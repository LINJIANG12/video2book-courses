# 汇编语言：转移指令（jcxz 与 loop）及相对位移机制

---

### [00:00] 一、jcxz 指令的功能与使用示例

在前面我们系统介绍了 `jmp` 指令，接下来去看一些其他的转移指令。首先第一个看的是 `jcxz` 指令。

对这个指令来讲，从用法上后面直接加标号即可：`jcxz 标号`。它的功能跟它的名字是可以看出来的：
- `j` 代表跳转（Jump）；
- `cx` 是 CPU 中的寄存器 `CX`；
- `z` 代表 zero（零）。

其执行逻辑为：**当 `cx` 等于零的时候，它就跳转**。所以这个功能非常容易记忆。
反之，如果 `cx` 不等于零，则什么也不做，意味着 CPU 会根据当前的 `IP` 执行下一条指令。

有了这个功能后，来看这样一个程序示例：

```assembly
; 程序示例：利用 jcxz 寻找内存单元中首个值为 0 的字节/字
    mov ax, 2000H
    mov ds, ax
    mov bx, 0
s:  mov ch, 0
    mov cl, [bx]        ; 从 2000:bx 处取数放入 cx
    jcxz ok             ; 如果 (cx) == 0 则转移到 ok
    inc bx
    inc bx              ; bx 加 2，指向下一个字单元
    jmp short s         ; 无条件转移回标号 s
ok: mov dx, bx          ; 找到 0 后，将偏移地址放入 dx
```

在这个程序当中：
1. 首先把数据段地址设置是 `2000H`；
2. `bx` 作为寄存器寻址，初值设置为 `0`；
3. 从段地址为 `2000H`、偏移地址为 `0` 的内存单元开始取数，取到数后放到 `cx` 中；
4. 如果当前 `cx` 等于零（即取到的数是零），就转移到 `ok`。程序再把 `bx` 的值放到 `dx` 后结束；
5. 如果 `cx` 不等于零，执行 `inc bx`、`inc bx`，将 `bx` 加 2 指向下一个字单元；
6. 接着通过 `jmp short s` 进行无条件转移，转回标号 `s` 处。

这段程序通过 `jmp short s` 实现循环，而循环的出口就是 `jcxz ok`。程序持续读取内存单元里的值，直到遇到 `0` 为止。这就是 `jcxz` 指令的一个典型应用场景。

### [01:58] 二、jcxz 指令的机器码与位移计算原理

该指令起作用的底层原理是什么？我们可以观察编译后的机器代码。

反汇编查看 `jcxz ok` 语句时，标号 `ok` 对应的地址是 `0010H`（即目标指令 `mov dx, bx` 的偏移地址）。按直觉，指令应该转移到 `0010H` 这个位置，但在 `jcxz` 的机器代码中保存的操作数却是 `04`。

这个 `04` 是什么？
观察 `jcxz` 的下一条指令，其偏移地址为 `000CH`。十进制中，$\text{0CH} = 12$；$12 + 4 = 16$，而十进制的 $16$ 转换为十六进制恰好是 $\text{10H}$（即地址 `0010H`）：

$$000\text{CH} + 04\text{H} = 0010\text{H}$$

由此可知：**在机器代码中保存的仍然是跳转时的相对位移，而不是目的地址**。这与前面 `jmp` 短转移是完全一致的。

当 `(cx) == 0` 触发跳转时，CPU 实质上进行的操作是修改 `IP`：

$$(IP) = (IP) + \text{8 位位移}$$

这里的 8 位位移计算方法依然是：

$$\text{8 位位移} = \text{标号处的地址} - \text{jcxz 指令后第一个字节的地址}$$

这个 8 位位移采用**补码**表示，范围是：

$$-128 \sim +127$$

这个 8 位位移由编译程序在编译期间计算得出。在阅读汇编源码时，直接写跳转到标号 `ok`，逻辑非常清晰；而在机器码层面采用相对位移，对人阅读和机器执行都极为方便。

总结来说，`jcxz` 与无条件转移指令 `jmp` 不同，它是一个**有条件转移指令**。后续还会遇到其他有条件转移指令，它们本质上都是**短转移**，修改 `IP` 的范围是 $[-128, 127]$，且机器码中存放的都是相对位移（例如此处的 `04`），而非目的地址。

### [04:39] 三、loop 指令的执行过程与机器码位移分析

接下来看 `loop` 指令。其格式为：`loop 标号`。

`loop` 指令的执行操作分为两步：
1. 首先将 `cx` 的值减 1：$(cx) = (cx) - 1$；
2. 随后依赖于 `cx` 中的内容进行判断：
   - 当 `(cx) != 0` 时，转移到标号处执行，据此构造循环；
   - 当 `(cx) == 0` 时，程序向下顺序执行，退出循环。

`loop` 指令是通过寄存器 `cx` 进行计数控制的。

```assembly
; 程序示例：利用 loop 指令累加
    mov cx, 6
    mov ax, 10
s:  add ax, ax
    loop s
```

在该程序中，`cx` 的初值为 6，`ax` 中放入 10。在标号 `s` 处将 `ax` 与 `ax` 相加，之后执行 `loop s`。此时 `cx` 自动减 1；只要 `cx` 不为 0 就返回标号 `s` 重新执行相加，构成循环；直到 `cx` 递减为 0 时退出循环，向下执行后续语句。

将该程序编译后，在 Debug 中使用 `u` 命令查看反汇编，会看到指令显示为：`loop 0006`，表示跳转到 `0006H`（即标号 `s` 所在位置）。
但仔细观察其机器码，操作数部分显示为 `FC`。

`FC` 代表什么？
`loop` 指令同样是**短转移**概念，其机器码中保存的也是相对位移：

$$\text{位移} = \text{标号处地址} - \text{loop 指令下一条指令的地址}$$

标号地址为 `0006H`，`loop` 的下一条指令地址为 `000AH`：

$$0006\text{H} - 000\text{AH} = -4$$

在计算机中，负数使用补码表示。$-4$ 转换为单字节（8 位）补码，最高位为 1，其十六进制形式恰好就是 `FCH`。

这再次印证了机器码中保存的是相对位移概念，此处对应的是向标号 `s` 转移的负位移。在前面 `jmp short s` 的示例中，跳转到前面的地址 `0008H` 时机器码出现了 `F8`，同样也是负位移的补码表示。

当 `cx` 不等于 0 发生转移时，`IP` 的更新方式为：

$$(IP) = (IP) + \text{8 位位移}$$

- 位移为**正数**时，程序向后跳转执行；
- 位移为**负数**（如 `FCH`）时，程序向前跳转执行。

因此，该跳转向前、向后均可进行。其位移的计算方式、取值范围（$-128 \sim +127$）均由编译器在编译时算出，与其他短转移指令完全一致。

### [08:04] 四、段内转移基于相对位移设计的深层意义

前面所介绍的指令都属于**段内转移**。段内转移是根据指令内部保存的相对位移进行寻址的。这种基于“目的地址与当前转移指令之间相对位移”的设计具有非常重要的实际意义，包括：
- `jmp short`（段内短转移）与 `jmp near ptr`（段内近转移）；
- `jcxz`（条件转移）；
- `loop`（循环指令）。

以上指令在机器码中保存的都是位移。

这种设计的好处在于：
如果机器指令中直接写死绝对目的地址（如写死标号 `s` 所在的实际内存偏移地址），那么整个程序段在内存中加载的偏移地址就会受到非常严格的限制。一旦代码段被加载到其他偏移位置，写死的绝对地址就会失效，极易引发运行时错误。

而在机器码中保存**相对位移**时，无论标号 `s` 被装载到内存中的实际物理/偏移地址是多少，跳转指令到标号 `s` 之间的**相对位移是恒定不变的**。

这种机制极大地方便了程序段在内存中的**浮动装配**（即代码可以在内存任意位置动态加载与重定位），使程序的适应面和灵活性更加广泛。
