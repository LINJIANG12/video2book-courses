# 编制中断处理程序（以 0 号除法错误中断为例）

### [00:00] 中断处理程序的常驻内存机制与设计问题
中断处理程序必须随时待命，这就需要它常驻内存。常驻内存的中断处理程序的入口地址（中断向量），存储在中断向量表对应的表项中。
编制中断处理程序需要解决两个核心问题：
1. 中断产生后该如何处理？
2. 中断处理程序编写完成后，如何将其入口地址写入到对应的中断向量表中？

我们以 0 号除法错误中断为例。预期效果：当程序产生除法溢出或除数为 0 触发 0 号中断时，执行我们编写的 do0 程序，在屏幕中间显示 "overflow!"，随后返回操作系统。

### [03:30] 核心问题一：中断处理程序的存放位置选择
经过分析，我们选定从物理地址 0000:0200 开始的内存空间来存放 do0 代码。
原因：8086 中断向量表占用 0000:0000 至 0000:03FF 共 1024 字节（支持 256 个中断向量）。实际系统中大部分向量未被占用，0000:0200 ~ 0000:02FF 这 256 个字节是极其安全的系统空闲未用区。

### [07:43] 程序整体实现框架
整个安装运行框架分为三步：
1. 编写安装程序：将 do0 的机器代码搬移复制到 0000:0200H；
2. 设置中断向量表：将 0 号中断向量（0000:0000H）的 IP 设为 0200H，CS 设为 0000H；
3. do0 中断例程本体：在屏幕中间显示 "overflow!" 并返回 DOS。

### [09:10] 代码搬运与安装程序实现
复制代码本质上是内存到内存的串传送：
- 源地址：DS:SI = CS:offset do0；
- 目的地址：ES:DI = 0000:0200H；
- 传送长度：CX = offset do0end - offset do0（利用编译器符号计算长度）；
- 传输方向：CLD（正向递增）；
- 指令：rep movsb。

### [13:00] 设置中断向量表表项
0 号中断在中断向量表中的起始物理地址是 0 * 4 = 0。
```assembly
mov ax, 0
mov es, ax
mov word ptr es:[0*4], 200h    ; 偏移地址 IP 设为 200H
mov word ptr es:[0*4+2], 0     ; 段地址 CS 设为 0000H
```

### [15:30] do0 中断例程本体与数据自包含
do0 被搬移到 0000:0200 后独立运行。它要显示的字符串 "overflow!" 不能依赖原程序的 data segment，必须做成自包含数据：
```assembly
do0:
    jmp short do0start
    db "overflow!"
do0start:
    mov ax, cs
    mov ds, ax
    mov si, 202h        ; 0000:0200 是 jmp short 占 2 字节，字符串固定在 0202H 处
    mov ax, 0b800h
    mov es, ax
    mov di, 12*160 + 36*2 ; 屏幕中央
    mov cx, 9
s:  mov al, [si]
    mov es:[di], al
    mov byte ptr es:[di+1], 02h ; 字符属性
    inc si
    add di, 2
    loop s
    mov ax, 4c00h
    int 21h
do0end:
    nop
```
这样，do0 完成了自给自足、安全驻留，并在被 0 号中断触发时成功响应接管！
