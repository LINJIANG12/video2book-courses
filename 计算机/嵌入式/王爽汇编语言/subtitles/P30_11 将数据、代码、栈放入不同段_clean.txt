# 汇编语言：将数据、代码、栈放入不同的段

### [00:00] 引入：单段存放数据、代码与栈的局限性

在这一节，我们介绍一个非常实用的程序结构：把数据、代码、栈放入不同的段。

对这个问题，我们可以用前面曾经用过的一个例子去看。这个例子是用栈将数据逆序存放。当初在实现这个例子时，我们在代码段的开始定义了数据，紧接着空出一些位置用作栈。在后续程序操作的过程中，前面这部分存放数据，后边这部分用作栈。

在解决将数据逆序存放时，把这里边的数据逐个取出来压栈，先取出的数据压到最下边；最后出栈时，再把先出栈的数据放到开始的位置上。通过这种方式，我们实现了逆序存放。

在这个过程当中，数据段、栈段和代码段是放在同一个段内部的。

### [00:53] 单段结构的弊端与多段方案

它的特点就是只用一个段。这表面上似乎是一件好事，但明显能看出程序显得比较混乱。因为在这一大块内存里，把三种不同类型的对象都混在了一起。在编程和阅读的时候，必须时刻注意何处是数据、何处是栈、何处是代码。

这种结构的程序只能应用在要处理的数据很少、用到的栈空间也很小的情况。代码也不宜过长，如果程序规模变大，采用这种单段结构就会彻底乱套。

如果要编写规模更大、更实用、结构更清晰的程序，该如何去做？这里给出的解决方案就是：**把数据、栈和代码放在不同的段里去处理**。

### [01:52] 多段程序的定义与段关联（assume）

处理的方法正如程序所示：

```assembly
assume cs:code, ds:data, ss:stack

data segment
    dw 0123h, 0456h, 0789h, 0abch, 0defh, 0fedh, 0cbah, 0987h
data ends

stack segment
    dw 0, 0, 0, 0, 0, 0, 0, 0
    dw 0, 0, 0, 0, 0, 0, 0, 0
stack ends

code segment
start:
    ; ... 初始化寄存器及后续操作 ...
code ends
end start
```

在这个程序中可以看到：

1. **数据段**：定义了一个 `data segment`（`data` 段），专门用于定义数据。在程序中它用作数据段。如何指明它作为数据段呢？就在 `assume` 中的 `ds:data`。这就意味着由 `data` 标号所代表的段地址，在这里声明与段寄存器 `DS` 建立关联。
2. **栈段**：`stack` 也是一个独立的段，定义了 16 个字（即 32 个字节）用作栈空间。在伪指令中通过 `ss:stack` 进行了声明与关联。
3. **代码段**：对于 `code segment`，同样进行了定义，并在 `assume` 中指明 `cs:code`。

这就是在同一个程序中包含三种段的标准处理方法。

### [02:54] 程序的内存布局与入口地址（CS:IP）

有了这种组织形式，将程序编译好并通过 Debug 加载到内存后：
* 最前面的 8 个字（16 个字节）是数据段；
* 紧接着的 32 个字节（16 个字）是栈段；
* 再往后的部分才是代码段。

这就是整个程序内存划分的思维。

程序中还有一个细节：在代码段开始的地方标示了 `start`，而 `end` 伪指令指明了 `start`（即 `end start`）。当程序被加载时，操作系统会自动把 `start` 处的地址作为程序入口，并将其写入 `IP`（指令指针寄存器），`CS` 也会指向对应的代码段地址。程序执行时就可以直接从 `CS:IP` 指向的位置开始运行。

### [03:48] 代码段执行逻辑与寄存器初始化

在代码段中，主要需要完成三件事：
1. **初始化各段寄存器**：为后续工作做准备；
2. **数据入栈**；
3. **数据出栈并回写**。

#### 1. 栈段寄存器初始化
初始化栈段时，段地址寄存器（`SS`）和栈顶指针寄存器（`SP`）非常关键：
* 段地址：不能直接将立即数或段名送入段寄存器，需要先将 `stack` 标号代表的段地址移入 `AX`，再由 `AX` 送入 `SS`：
  ```assembly
  mov ax, stack
  mov ss, ax
  ```
* 栈顶指针：栈的大小为 16 个字（32 个字节），因此栈顶指针 `SP` 初始化为 `20H`：
  ```assembly
  mov sp, 20h
  ```
  从偏移地址 $0$ 到栈段结束共 32 个字节，栈顶初始指针设为 `20H` 是正确的。

#### 2. 数据段寄存器初始化
数据段从 `data` 开始，同样需要通过通用寄存器 `AX` 进行中转，赋给 `DS`：
  ```assembly
  mov ax, data
  mov ds, ax
  ```
至此，数据段寄存器的初始化完成。

### [05:06] CS 寄存器为何不需要手动赋值？

有些同学可能会提出疑问：`CS` 为什么不需要通过代码显式赋值？

实际上是这样的：对于一个程序而言，至少应该包含一个段，这个段就是代码段（`CS`）。在程序加载运行之前，系统已经自动将代码段的起始地址赋给了 `CS` 寄存器。因此唯独代码段用不着通过 `mov` 指令去重置它的值。前面所有的程序中，也都没有手动管理代码段从哪里开始，系统加载时已自行设置完毕。

### [05:41] 数据入栈与出栈的执行过程

段寄存器初始化完成后，入栈和出栈操作就变得非常清晰：

#### 入栈操作
在入栈循环中执行：
```assembly
push [bx]
```
这里没有显式指明 `[bx]` 偏移地址所对应的段地址是多少。在默认情况下，缺省的段寄存器就是 `DS`，访问的正是数据段。

`BX` 的初始值为 $0$，在每次循环中自增 2。程序会依次取出数据段中的每一个字，执行 `push` 将其压入栈中。

### [06:20] 出栈操作
紧接着是出栈循环，逻辑对称：
```assembly
pop [bx]
```
将栈中的数据弹出，存入指定偏移地址的内存单元。`BX` 再次从 $0$ 开始，每次循环加 2，默认段地址依然是 `DS`，对应数据段内存空间。出栈完成后，数据实现了逆序排列。

### [06:58] 使用 Debug 跟踪与观察

对于这个程序，可以在 Debug 中进行跟踪观察：
* 程序加载后，观察寄存器状态，`CS` 已经被赋予正确的值，`IP` 的初始值为 `0000H`。
* 准备执行的第一条指令是：
  ```assembly
  mov ax, 076Bh
  ```
  这里的 `076BH` 正是 `stack` 栈段所对应的段地址。
* 使用 `U` 命令反汇编列出所有指令，可以看到偏移地址从 `0000` 开始依次排布。
* 调试技巧：
  * 可以使用 `T` 命令进行单步执行；
  * 可以使用 `G` 命令直接运行至指定位置或整块执行；
  * 执行前后，可以用 `D` 命令观察数据段内存，验证数据是否成功完成逆序。

### [08:37] 课程总结

最后做一个总结：
1. **多段共存**：一个程序中可以同时定义数据段（`data segment`）、栈段（`stack segment`）和代码段（`code segment`）。
2. **段关联声明**：分别定义各个 `segment` 后，在 `assume` 伪指令中将段寄存器与具体的段名进行关联。
3. **寄存器初始化差异**：
   * **数据段（DS）与栈段（SS/SP）**：必须在代码段中使用指令手动进行初始化。
   * **代码段（CS/IP）**：由系统加载程序时根据 `end start` 指定的入口自动设置，无需手动编写指令赋值。
4. **适用场景**：当面对较多数据、较大栈空间或较复杂代码时，必须采用将数据、栈和代码放入不同段的技术，以编写出结构清晰、健壮的汇编程序。
