# 汇编语言：利用 `loop` 指令实现内存数据连加乘法

### [00:00] 问题提出与方案分析

在这一节，我们来看一个用 `loop` 指令解决问题的小例子。

这个例子是这样的：我们从内存单元里面要取出一个数，把这个数乘以 $3$，做这样一个操作。乘以 $3$ 以后的结果放在 `DX` 里面，`DX` 是一个 16 位的寄存器。我们要乘以的数是哪个呢？是从这样一个内存单元当中取出的，并且强调取出的是一个字节（Byte）的数据。这是我们本身的问题。

因此，方案很简单：从内存里面把数据取出，然后连加 $3$ 次去实现这个乘法就可以了。我们可以编出这样的程序来，这个程序是不难理解的。

---

### [00:38] 运算数据宽度不匹配问题

一会儿在看程序的时候，我们提前需要注意一个这样的事情：结果要放在 `DX` 里面，而现在它在乘以 $3$ 的时候取出的是一个字节的数据。一个字节是 8 位的，而 `DX` 里面存储是 16 位的。这两个 8 位和 16 位的运算是不能直接进行的，我们该如何处理呢？接下来在程序当中，我们会看到在这一点上其实还是做了很多精细的考虑。

---

### [01:04] 内存数据读取与汇编语法规则

我们在解决这个问题的时候，首先将内存里面的数据取出。怎样把内存里面的数据取出呢？我们需要正确地设置它的段地址，然后引用它的偏移地址，去把相应内存单元里面的值取出来。

于是在这里面有了：

```assembly
mov ax, 0ffffh
```

这里代表的是它的段地址。

在这里边有一个小的技巧或者小的要求：在汇编语言源程序里面，数据是不能以字母开头的。所以在这里边发现某一个数据是以字母开头的十六进制数，要在前面加上一个 `0`，这是一个规矩。

总之处在这儿，我们把所需要的段地址 `ffffh` 放到 `AX` 里面，紧接着把 `AX` 的值放入 `DS` 里面：

```assembly
mov ds, ax
```

于是 `DS` 段地址寄存器现在获得了我们需要的段地址。

再接下来，我们可以看到在这块把 `6` 放入 `BX`，`6` 是这里的偏移地址：

```assembly
mov bx, 6
```

因此我们要看到，在这块用 `[bx]` 的时候，它所对应的就是段地址为 `DS`、偏移地址是 `BX` 的这个单元。而这个单元我们取出的是字节，然后把它放到 `AL` 里面：

```assembly
mov al, [bx]
```

为什么取出字节呢？因为它是要把这个单元的值放到一个 8 位寄存器里面，当然在这里边取出的就是 8 位，取出的是字节。这一点非常重要。

---

### [02:31] 高位寄存器清零（AH 置 0）的必要性

但是在这块我们可以看到，我们还把 `AH` 变为了 `0`：

```assembly
mov ah, 0
```

这又是为什么呢？

其实在这块，`AH` 和 `AL` 两个共同合成的就是 `AX`。我们现在 `AH` 的值是 `0` 的时候，其实 `AX` 里面的值也就是刚刚取出的这 8 个位里面的值，因为它的高位全都是 `0` 了。

所以我们现在实质上做的工作是什么呢？我是从一个字节里面取出 8 位的值，但是我把它高位都置成了 `0`。于是这 16 位的值跟那 8 位的值绝对是相同的。

为的是什么？因为我们的结果是存储在 `DX` 里面，所以一会儿我们在加的时候看是：

```assembly
add dx, ax
```

在这儿改成 `AL` 肯定是不对的。所以在这块，我们有必要把它置为 `0`。

如果不置为 `0` 呢？大家要知道，对 `AH` 里面来讲，原先可能会有其他数据的。如果不置为 `0` 的话，表面看起来没有问题，但是最终在运行的时候，受制于 `AH` 里面原有值是什么。如果它一旦不是 `0` 的话，将来加出的这个结果肯定就错了。所以这个技巧我们要看到。

---

### [03:41] 循环累加逻辑实现

接下来，我们就实现连加 $3$ 次的这样功能了。

连加 $3$ 次，`DX` 里面要放最后的结果，所以要在加之前把它赋值为 `0`；而在 `CX` 里面去设置循环的次数：

```assembly
mov dx, 0
mov cx, 3
s: add dx, ax
   loop s
```

在循环当中我们要做到什么样的动作呢？把 `AX` 累加到 `DX` 里面。所以这一段循环我们要知道，它会执行 $3$ 次。而执行 $3$ 次，其实就是把 `AX` 的值连加了 $3$ 次，而 `AX` 的值跟 `AL` 里面的值是一样的，它其实就是这个字节单元里面的数。所以这样一个程序就是这样去编制成了。

---

### [04:16] 数据溢出考量与寄存器选择

接下来我们看一个细节。有些人可能说了：你是加这个字节的单元，将来你把这个结果存放在 `DL` 里面，其实也就是在 `DX` 里面，那行不行呢？

如果这样做的话，我们可能不要这个 `mov ah, 0`，然后在这块 `AX` 变为 `AL`，在这儿 `DX` 变成 `DL`，那看起来貌似也是可以的。

但是在这一边一定要注意到一个这样的问题：我们在编这个程序的时候，就不要说在 `DX` 的层面上了，我们在 `DX` 的层面上面也应该要留一个心眼，要看一下运算以后的结果它是否会超出 `DX` 所能存储的范围。

`DX` 是 16 位的一个寄存器，它存储的无符号数里面最大的是 $65535$。而我们从这一个字节单元里面取出的最大的数是 $255$，所以乘以 $3$ 以后都不会超过 $65535$ 的。所以我们在这里边可以明确的是，`DX` 它能够承受这个范围。

但是与此同时我们要讲的，刚才我说如果把这一块 `DX` 换成 `DL` 行不行？如果换成 `DL` 的话，那么这样一个溢出几乎是避免不了的。为什么呢？`AL` 里面最大值是 $255$，然后它连加 $3$ 次（乘以 $3$），在 8 位里面就放不下了。所以说在这块我们把它存储在 `DX` 里面，这是需要的。这个顾虑没有，但是我们千万不能在这一块把 `AX`、`DX` 的地方改成 `AL`、`DL`，这是一个要求。

### [06:58] 内存数据查看（D 命令）

对这个程序我们可以看到，一开始的时候从 `BX` 所指向的那个单元里面我们要取值，要取到 `AL` 里面去。接下来我们就观察一下这个取值，它取到的是多少。

而现在我们要观察内存里面的值的时候，我们应该要用 `d` 命令了。我们现在就看一下，段地址是 `ffff`，而偏移地址是 `6` 的这个位置上，它的单元的值是多少。现在我直接回车看一下：

在这块可以看到，观察到这个位置上的值就是 `31`（十六进制 $31\text{H}$）。注意到这个是十六进制数。一会儿我们在运行的时候就可以看 `AL` 里面到底是不是得到的是 `31`。

### [07:37] 单步跟踪执行与寄存器状态分析

现在我打开寄存器看一下。

当前第一个要执行的是 `ffff` 移到 `AX` 里面；然后执行，`AX` 里面得到了这个值；然后再去执行的时候，`DS` 得到的就是这个段地址；然后再执行的时候，`BX` 得到的是我们现在要的偏移地址了。

再接下来，我们就要把 `[bx]` 的值取出来，要放到 `AL` 里面。我们注意到现在它的变化，在执行的时候，可以看到 `AL` 里面的确是 `31` 了。

我们现在已经看到了接下来这句指令它的必要了：`AH` 里面现在是 `ff`，而现在我们需要 `AX` 里面的值跟 `AL` 是一样的，所以 `AH` 现在变成了 `0`，看到了吧？

所以我们在接下来去做这样的工作：
1. 把 `DX` 里面赋值为 `0`，这是要开始累加了；
2. 然后 `CX` 是 `0003`，要执行三次的循环；
3. 加第一次，`DX` 里面已经变成了 `0031`，原先是 `0000`。

现在执行 `loop`。这个 `loop` 指令，原先写的是 `loop s`，而这个标号 `s` 现在已经转换成了 `add dx, ax` 这条指令的地址了：`0012`，即 `loop 0012`。

然后再执行 `t` 的时候，我们可以看到 `CX` 的值已经是由原有的 $3$ 变成了 $2$ 了；然后再 `t` 再执行，然后再 `loop`，我们可以看到 `DX` 的值现在已经变成累加后的数值了；然后我们执行最后一次 `ADD`，可以看到在这块 `DX` 的值是 `0093`，而 `CX` 是 `0001`；再按 `t` 的时候，它结束了这样的循环。
