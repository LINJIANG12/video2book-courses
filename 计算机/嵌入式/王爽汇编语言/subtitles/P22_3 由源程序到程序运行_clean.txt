# 汇编语言：由源程序到程序运行的全过程

---

### [00:00] 过程概述：从源程序到程序运行

本节介绍一个实践性非常强的内容：由源程序到程序运行。

首先梳理整体流程：
1. **编写源程序**：编写汇编语言源程序文件，其扩展名为 `.asm`。
2. **编译（Compile）**：将源程序文件经过编译器编译，转换为目标文件（Object file），扩展名为 `.obj`。多个源程序文件可以分别编译转换为多个目标文件。
3. **连接（Link）**：将一个或多个目标文件与库文件等进行连接，生成可执行文件，扩展名为 `.exe`。可执行文件内部除了相关的描述信息外，主要包含机器指令及其对应的二进制代码。
4. **运行与调试**：计算机硬件直接执行可执行文件中的二进制代码，并在操作系统中展现运行结果。

---

### [00:51] 第一步：编辑源程序

汇编源程序本质上是一个纯文本文件。编辑源程序有多种工具可供选择：

- **记事本（Notepad）**：最基础的文本工具，直接编写文本并保存即可。
- **DOS 下的 `edit.com`**：DOS 系统自带的经典文本编辑器，在 DOS 提示符下输入 `edit` 即可运行（另外 DOS 还自带行编辑器 `edlin.com`，但易用性较差）。
- **Visual C++ 等集成开发环境**：在 VC++ 环境下亦可编写汇编语言代码，且具备类似 `debug` 的可视化调试工具。
- **EditPlus**：功能优秀的文本编辑器。通过导入汇编语言的语法定义与格式控制文件，可实现汇编指令、伪指令、寄存器等关键字的语法着色，便于在编码阶段排查拼写与语法错误。

---

### [02:27] 第二步：使用 MASM 编译源程序

完成源程序编辑后（示例文件为 `D:\masm\p4-1.asm`），需要使用汇编编译器 **MASM**（`masm.exe`）进行编译。

在命令行运行 MASM 时，编译器会依次提示输入相关文件的输出路径与名称：
1. **目标文件（Object file [.OBJ]）**：编译后生成的二进制目标文件，默认与源文件同名（如 `p4-1.obj`）。
2. **列表文件（Source listing [.LST]）**：编译过程中由编译器生成的中间结果文件，记录源程序与生成的机器码对照信息。
3. **交叉引用文件（Cross-reference [.CRF]）**：用于记录标号、变量符号交叉引用信息的文件。

编译完成后，编译器会输出编译状态统计：
```plaintext
0 Warning Errors
0 Severe Errors
```
- **Warning Error（警告错误）**：轻微问题，不影响目标文件生成。
- **Severe Error（严重错误）**：阻断性语法错误，必须修正后才能成功生成 `.obj` 目标文件。

---

### [04:33] 实操演示：在 DOSBox 中进行编译

在 DOSBox 环境中进行实际操作演示：

1. **环境挂载**：
```dos
mount c d:\masm
c:
dir
```
此时将宿主机的 `D:\masm` 目录挂载为 DOS 虚拟环境的 `C:` 盘根目录。目录中已准备好 `debug.exe`、`masm.exe`、`link.exe` 以及示例源文件 `p4-1.asm`。

2. **交互式编译**：
```dos
masm p4-1.asm
```
执行后依次按回车键接受默认设置（输出 `p4-1.obj`，忽略 `.lst` 与 `.crf` 文件）。编译无误后，目录中将生成 `p4-1.obj` 文件。

### [07:31] 编译中的错误处理与分号快捷操作

如果源程序存在语法错误，MASM 编译器会在终端中精确指出错误所在的行号及原因。

#### 常见错误提示分析：
- **第一行报错（指示符/指令未识别）**：
  若伪指令拼写错误（例如将 `assume` 错写），MASM 会提示 `error A2008: Syntax error` 或要求期望得到一条指令（instruction）或伪指令指示符（directive）。
- **后续代码段报错（缺少段定义）**：
  在代码段中遇到第一条有效指令时，若未正确通过 `assume cs:codesg` 关联代码段寄存器与段名，编译器将提示无法找到 `CS` 寄存器关联的代码段。
- **寄存器拼写错误**：
  例如将寄存器 `ax` 错写为不存在的 `sx`，编译器将报错提示未定义的符号或非法寄存器。

> **注意**：编译时一旦出现 **Severe Errors**，说明程序存在不可忽略的语法错误，必须重新进入编辑器修正，保存后再行编译。

#### 简化编译命令：
如果在运行 `masm` 命令时，在源文件名后紧跟一个分号 `;`，编译器将自动跳过后续中间文件的确认提示，直接按默认配置生成 `.obj` 目标文件：
```dos
masm p4-1;
```

### [10:41] 第三步：使用 LINK 进行连接

得到目标文件（`p4-1.obj`）后，需要调用连接器 **LINK**（`link.exe`）生成可执行文件：

1. **执行连接**：
```dos
link p4-1
```
连接器会依次提示用户确认：
- **可执行文件（Run File [.EXE]）**：默认为 `p4-1.exe`。
- **内存映像映射文件（List File [.MAP]）**。
- **库文件（Libraries [.LIB]）**。

2. **关于堆栈段警告**：
连接时常会出现警告提示：
```plaintext
LINK : warning L4021: no stack segment
```
此提示表明当前程序未显式定义堆栈段（Stack Segment）。对于初学阶段编写的简单实验程序，该警告不影响程序的生成与正常执行，可直接忽略。

3. **快捷连接命令**：
与编译命令类似，在文件名后加分号 `;` 可直接按默认设置生成 `.exe`：
```dos
link p4-1;
```
执行完成后，工作目录下将生成最终的 `p4-1.exe`。

---

### [13:09] 第四步：程序的运行与结果验证

在 DOS 提示符下直接输入可执行程序名称即可运行：
```dos
p4-1
```

#### 运行现象说明：
运行后屏幕没有任何字符输出，直接返回 DOS 提示符。这是因为当前的示例程序功能仅是将数据送入寄存器并进行加法运算，未调用任何用于在屏幕上显示字符的 DOS 系统中断功能调用。运算结果保留在 CPU 的通用寄存器中，无法直接肉眼观察。

#### 验证方法：
此类无回显程序的逻辑正确性，需通过 `debug.exe` 加载跟踪验证：
```dos
debug p4-1.exe
```
在 Debug 中利用单步执行命令（`t` 或 `p`），可以逐步观察各寄存器和内存单元在指令执行过程中的动态变化。

---

### [14:15] 课程总结

开发并执行汇编语言程序的四个核心阶段：
1. **编写源程序**：使用编辑器（如 EditPlus）编写汇编源代码，生成 `.asm` 文本文件。
2. **编译**：运行 `masm` 编译器，对 `.asm` 文件进行词法与语法分析，生成 `.obj` 二进制目标文件。
3. **连接**：运行 `link` 连接器，将 `.obj` 文件转换为 `.exe` 可执行文件。
4. **运行与跟踪**：在操作系统中运行 `.exe` 文件，或利用 `debug` 进行单步跟踪与状态验证。
