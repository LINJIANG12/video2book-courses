# 汇编语言：模块化程序设计与参数传递

---

### [00:00] 模块化程序设计与子程序调用机制

在这一节课程中，我们介绍汇编语言支持的模块化程序设计。

对于模块化程序设计，我们现在已经知道在汇编语言中可以通过定义调用子程序的方法，实现一定程度上的模块化程序设计。

对于这种程序结构，可以归结为：由主程序（例如用标号 `MAIN` 代表主程序）调用子程序 `SUB`，子程序 `SUB` 再调用 `SUB2` 子程序；最后，程序可以一级一级地逐级返回。在汇编语言中，使用 `CALL` 指令与 `RET` 指令相互配合，就可以完成这种模块化程序设计。

在模块化程序设计中有一个核心概念——**子程序**。子程序可以根据提供的**参数**处理一定的事务，在处理完成之后，会将结果（即**返回值**）提供给调用者。

在之前的调用关系中，我们只强调了程序流程的转移，还没有涉及到参数和返回值的传递。接下来我们要重点探讨：在汇编语言中，这些参数和返回值究竟该如何进行传递与处理。

首先需要澄清一个概念：汇编语言完全支持模块化程序设计，这绝不仅仅是高级语言才能做的事情。

### [01:26] 方案一：使用寄存器传递参数与结果（计算 $N^3$）

接下来，我们将重点转向调用子程序过程中参数和结果的传递问题。

先来看一个具体任务：**根据提供的参数 $N$，计算 $N^3$**。

如果用 C 语言编写该程序，$N^3$ 可以定义为一个函数：
```c
int cube(int n) {
    return n * n * n;
}

int main() {
    int f = cube(2);
    // 显示结果...
    return 0;
}
```
该函数包含形式参数，最终带回一个返回值。在调用 `cube(2)` 时，实参 `2` 传递给函数，执行到子程序计算出 $2^3$ 的结果，通过 `return` 返回并传递给调用者。

按照汇编语言的子程序调用过程，要实现参数传递，需要考虑两个核心问题：
1. **参数存储位置**：参数 $N$（例如数值 2）应该存储在什么地方？存放在寄存器还是内存中？
2. **结果存储位置**：最终计算得到的值（例如返回值 $F$）要存放在什么地方？存放在寄存器还是内存中？

为此，我们提供三种解决方案，这也是本节课重点讲解的内容：
1. **使用寄存器传递参数与结果**；
2. **使用内存单元传递参数与结果**；
3. **使用栈传递参数与结果**。

我们逐一展开讲解。首先看最常用的一种方法——**使用寄存器传递参数与结果**。

解决同样的问题：提供 $N$，计算 $N^3$。
* 参数存放位置：存放在寄存器；
* 结果存放位置：存放在寄存器。

基于这种思路进行设计：
* 将参数 $N$ 存放在 `BX` 寄存器中；
* 子程序中使用乘法指令 `MUL` 计算 $N^3$（即将 $N$ 连续连乘三次）；
* 结果存放：在使用 16 位乘法指令时，最终的乘积保存在 `DX` 与 `AX` 寄存器中（高 16 位在 `DX`，低 16 位在 `AX`）。因此，子程序计算得到的数值直接保存在 `DX` 和 `AX` 寄存器中。

子程序 `cube` 的设计实现如下：
```assembly
cube:
    mov ax, bx       ; 将 BX 中的参数 N 送入 AX 作为被乘数
    mul bx          ; 计算 N * N，结果存放在 DX:AX 中（N 较小时高位为 0，AX 即为 N^2）
    mul bx          ; 再次乘 N，计算 N^3，最终结果高 16 位存于 DX，低 16 位存于 AX
    ret             ; 子程序返回
```

该子程序的入口参数由 `BX` 提供，出口结果通过 `DX` 和 `AX` 获取。

### [05:08] 综合应用：批量计算立方并存储到双字单元

我们可以将上述子程序应用到一个具体的编程任务中：
> **编程任务**：计算 `data` 段中第一组数据的立方，并将结果保存到后一组的 `dword`（双字）单元中。

数据定义如下：
* 第一组参数：8 个字（Word）型数据（1 到 8）；
* 第二组空间：8 个双字（Double Word, DD）单元。1 个双字占用 4 个字节，8 个双字共计 $8 \times 4 = 32$ 个字节。

完整程序设计如下：
```assembly
data segment
    dw 1, 2, 3, 4, 5, 6, 7, 8
    dd 0, 0, 0, 0, 0, 0, 0, 0
data ends

code segment
    assume cs:code, ds:data
start:
    mov ax, data
    mov ds, ax
    
    mov si, 0        ; SI 指向源操作数首地址（偏移地址 0）
    mov di, 16       ; DI 指向目的操作数首地址（跨过前 8 个字共 16 字节）
    mov cx, 8        ; 循环计数器设为 8

s:
    mov bx, [si]     ; 取出当前字数据放入 BX 作为子程序入口参数
    call cube        ; 调用子程序计算 BX 的立方
    mov [di], ax     ; 将结果低 16 位存入目的内存单元
    mov [di+2], dx   ; 将结果高 16 位存入目的高地址单元
    add si, 2        ; SI 指向下一个待处理的字单元（+2 字节）
    add di, 4        ; DI 指向下一个存放结果的双字单元（+4 字节）
    loop s

    mov ax, 4c00h
    int 21h

cube:
    mov ax, bx
    mul bx
    mul bx
    ret
code ends
end start
```

#### 程序执行过程分析
1. `SI` 初始指向源数据偏移地址 `0`；`DI` 初始指向结果存储区域偏移地址 `16`（即 `10H`）。
2. 在循环体 `s` 中，通过 `[SI]` 取出一个字放入 `BX`，调用 `cube` 计算出 $N^3$。
3. 返回后，`AX` 保存在 `[DI]`，`DX` 保存在 `[DI+2]`，构成了 4 字节双字存储结构。
4. 随后 `add si, 2`、`add di, 4`，`loop s` 继续循环，直到 8 个数据全部处理完毕。

程序编译链接后，通过 Debug 运行观察内存：
在数据段偏移地址 `0` 开始的 16 个字节中，依次存放着 8 个字数据 `0001, 0002, 0003, ..., 0008`；
紧接着的 32 字节区域中，每 4 个字节保存对应数值的立方：
* $1^3 = 1$（十六进制 `00000001H`）；
* $2^3 = 8$（十六进制 `00000008H`）；
* $3^3 = 27$（十六进制 `0000001BH`，即 $16 + 11$）；
* 以此类推，完整保存了计算结果。

### [09:34] 寄存器传递的局限性与方案二引出

虽然该程序顺利完成了任务，但需要反思：在该程序中，参数存放在 `BX`，结果存放在 `DX` 和 `AX`，一共占用了 3 个寄存器。

我们知道，CPU 内通用寄存器的数量是非常有限的。如果子程序需要传递 3 个、4 个甚至更多的参数，寄存器资源就会捉襟见肘。

这就是**用寄存器传递参数的局限性**：传递的参数数量不能太多。当需要传递大批量参数时，必须另想办法——这便引出了第二种方案：**用内存单元批量传递数据**。

---

### [10:13] 方案二：使用内存单元批量传递参数（字符串大小写转换）

内存单元的存储容量非常充足。采用内存传递参数的方案为：
1. 调用者将批量的输入数据存放在内存中；
2. **仅将这批数据在内存中的首地址存入寄存器**，传递给子程序；
3. 子程序处理完毕后，若返回结果同样是批量数据，也可以将存放结果的内存区域首地址存入寄存器返回。

#### 示例：将 `data` 段中的字符串转换为大写
> **编程任务**：将 `data` 段中定义的字符串 `'conversation'` 全部转换为大写字符。

程序代码段设计如下：
```assembly
data segment
    db 'conversation'
data ends

code segment
    assume cs:code, ds:data
start:
    mov ax, data
    mov ds, ax
    
    mov si, 0        ; SI 存放字符串在内存中的首地址
    mov cx, 12       ; 字符串包含 12 个字符，设置循环计数
    call capital

    mov ax, 4c00h
    int 21h

capital:
    and byte ptr [si], 11011111b ; 将 SI 指向的字节转换为大写字符
    inc si                       ; SI 指向下一个字符
    loop capital                 ; 循环 12 次
    ret
code ends
end start
```

#### 方案特点解析
1. **批量数据传递**：虽然需要处理 12 个字符的大量数据，但在调用子程序前，仅需将数据首地址放入 `SI` 寄存器。
2. **内存访问**：子程序通过 `SI` 寄存器即可定位到该段内存，结合循环结构逐一处理这 12 个数据。
3. **核心要点**：通过寄存器传递**内存的起始地址（指针）**，从而打破了寄存器数量对数据传递规模的限制。

### [13:11] 方案三：使用栈传递参数（计算 $(a-b)^3$）

除了寄存器传递和常规内存单元传递外，还有一种在现代高级语言底层编译中应用极其广泛的方式——**使用栈（Stack）传递参数**。

#### 栈传递原理
1. **调用者入栈**：调用者在进入子程序之前，将需要传递的参数依次压入栈（`PUSH`）中；
2. **子程序出栈/寻址**：子程序通过栈空间获取参数，完成运算；
3. **本质归属**：从底层本质上讲，栈依然属于内存单元，只是利用了栈段（Stack Segment）这一特殊的存储与管理机制。

### [16:17] 子程序内部的栈帧寻址与 `BP` 寄存器保护

我们通过一个具体任务来学习栈传递参数的机制：
> **编程任务**：计算 $(a-b)^3$，其中 $a$ 和 $b$ 均为 Word（字）型数据。
> 设实参 $a = 3, b = 1$。

#### 主程序调用前准备
调用子程序前，调用者先将参数 $b$ 和 $a$ 压入栈中：
```assembly
mov ax, 1
push ax          ; 先将参数 b (1) 压栈
mov ax, 3
push ax          ; 再将参数 a (3) 压栈
call difcube     ; 调用子程序
```

在执行 `CALL difcube` 指令时，CPU 自动将下一条指令的偏移地址 `IP`（返回地址）压入栈顶。

此时栈中的内容结构（从栈底向栈顶）：
* 栈较深位置：参数 $b$（值 `1`）
* 随后位置：参数 $a$（值 `3`）
* 当前栈顶：返回地址 `IP`

#### 子程序内部处理：栈帧建立与 `BP` 寄存器的使用
进入子程序 `difcube` 后，需要从栈中读取参数 $a$ 和 $b$。在 8086 汇编中，通常使用基址指针寄存器 `BP` 来基于栈顶进行相对寻址。

代码实现如下：
```assembly
difcube:
    push bp          ; 保护现场：将 BP 原有的值压入栈中
    mov bp, sp       ; 建立栈帧：使 BP 指向当前的栈顶

    mov ax, [bp+4]   ; 取出参数 a (3)
    sub ax, [bp+6]   ; AX = a - b (3 - 1 = 2)
    mov bp, ax       ; 将 (a - b) 暂存至 BP 中用于乘法
    mul bp           ; AX * BP = (a - b)^2
    mul bp           ; AX * BP = (a - b)^3，结果高 16 位存于 DX，低 16 位存于 AX

    pop bp           ; 恢复现场：恢复 BP 原有的值
    ret 4            ; 子程序返回并平衡堆栈（出栈 IP，同时 SP = SP + 4）
```

#### 为什么需要 `push bp` 与 `pop bp`？
主程序可能正在使用 `BP` 寄存器保存重要数据。子程序为了使用 `BP` 读取栈中参数，必须先将主程序的 `BP` 旧值压入栈中备份；在子程序执行结束退出之前，再通过 `pop bp` 弹出恢复。这是一种经典的“保护现场与恢复现场”技术。

### [18:24] 平衡堆栈指令 `RET n` 的机制解析

在子程序末尾，使用的是 `ret 4` 指令，而非普通的 `ret`。

#### 栈状态演进
1. 压入参数前：`SP` 指向原始栈顶；
2. 依次压入参数 $b$（占 2 字节）、$a$（占 2 字节）后，`SP` 下移 4 字节；
3. 执行 `call difcube`：压入返回地址 `IP`（占 2 字节）；
4. 进入子程序执行 `push bp`：压入旧 `BP`（占 2 字节），随后 `mov bp, sp`。

此时栈内偏移与参数的关系（相对于当前的 `BP`）：
* `[bp]`：旧的 `BP` 值；
* `[bp+2]`：返回地址 `IP`；
* `[bp+4]`：参数 $a$ 的值；
* `[bp+6]`：参数 $b$ 的值。

5. 子程序计算完成后，执行 `pop bp`：将旧 `BP` 弹出，栈顶指针 `SP` 重新指向返回地址 `IP`。

#### `ret n` 的作用
如果此时仅执行普通 `ret`，CPU 只会弹出返回地址 `IP`。但调用前为了传参压入的 $a$ 与 $b$（共 4 个字节）仍然残留在栈内，造成堆栈不平衡。

因此，使用带立即数的返回指令 `ret 4`。其执行过程等价于：
$$\text{POP IP}$$
$$\text{ADD SP, 4}$$

1. 先将返回地址 `IP` 弹出，程序流程返回到调用点之后；
2. 将栈指针 `SP` 加上 4 字节，直接越过栈中占用的 $a$ 和 $b$ 两个临时参数，使栈指针完全恢复到调用传参前的初始位置。

### [19:39] 栈传递参数的完整执行流程与栈指针变化深度剖析

我们从栈指针 `SP` 的变化角度，系统梳理该过程：

1. **初始状态**：
   栈段寄存器 `SS` 与栈指针 `SP` 指向栈底最高处。
2. **压入参数**：
   * `push ax`（压入 $b=1$），`SP = SP - 2`；
   * `push ax`（压入 $a=3$），`SP = SP - 2`。
3. **调用子程序**：
   * `call difcube`，将下条指令的 `IP` 压栈，`SP = SP - 2`。
4. **子程序首部保护现场**：
   * `push bp`，将旧 `BP` 压栈，`SP = SP - 2`；
   * `mov bp, sp`，使 `BP` 锚定当前栈顶位置。
5. **寻址与运算**：
   * 读取 `[bp+4]` 获取 $a$；读取 `[bp+6]` 获取 $b$；
   * 计算 $(a-b)^3$，最终计算结果存放在 `DX`（高 16 位）和 `AX`（低 16 位）中。
6. **恢复现场与堆栈平衡**：
   * `pop bp`：旧 `BP` 出栈，`SP = SP + 2`，此时 `SP` 指向 `IP`；
   * `ret 4`：弹出 `IP`（`SP = SP + 2`），随后自动执行 `SP = SP + 4`，跳过参数区域。
   * 此时 `SP` 彻底回到最初调用前的位置，栈中残留的历史参数失效，堆栈完全平衡。

### [23:15] 模块化程序设计参数传递方案总结

在汇编语言模块化程序设计中，参数与返回值的传递是核心环节。对于参数存放以及计算结果存放，我们总结了三种主要方案：

| 方案 | 传递机制 | 优点 | 缺点 / 适用场景 |
| :--- | :--- | :--- | :--- |
| **方案一：寄存器传递** | 使用通用寄存器（如 `BX`, `AX`, `DX`）直接存取参数与返回值 | 速度快，编写简单 | 寄存器数量有限，无法传递大量参数 |
| **方案二：内存单元传递** | 将批量数据置于内存，通过寄存器传递内存起始地址（指针） | 适合传递大批量连续数据（如字符串、数组） | 需要占用额外的数据段空间 |
| **方案三：栈传递** | 调用前将参数 `PUSH` 入栈，子程序通过 `BP` 相对寻址，退出时通过 `RET n` 平衡堆栈 | 结构严谨，参数数量不受限，支持递归与嵌套调用（高级语言底层标准机制） | 涉及较多栈指针与栈帧操作，逻辑相对复杂 |

在实际工程与程序设计中，应根据具体的参数数量、数据结构以及性能要求，选择最匹配的参数传递机制。
