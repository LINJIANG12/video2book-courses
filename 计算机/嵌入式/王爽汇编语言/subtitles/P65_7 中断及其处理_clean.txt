# 8086 中断及其处理机制

---

### [00:00] 中断的概念与分类

在这一节我们介绍中断及其处理。首先看一下中断的概念。

所谓**中断**，是指 CPU 在执行指令的时候，不再接着刚才刚刚执行完的指令向下执行，而是转去处理一些其他的中断信息。这个中断信息往往是一些意外的信息。例如，在看电影的场景当中，大家正在观影，但注意力突然转到别的地方去了，这就是一个意外的中断。

对于 CPU 的中断而言，我们把它分为**内中断**和**外中断**两种：
- **内中断**：由 CPU 内部发生的事件而引起的中断。
- **外中断**：由于 CPU 外部的事件，也就是外部设备（例如键盘、显示器、打印机、扫描仪等）发生的事件所引起的中断。

具体在结构图中可以看到：
- **内中断**包括：单步中断、除法错误中断、溢出中断等。
- **外中断**包括：非屏蔽中断请求（NMI，后续会详细讲解），以及由可编程中断控制器（如 8259A）接收到的系统定时器、键盘、通信接口等外设所引起的中断。

这就是整个中断的基本概念。

引入中断概念后，CPU 的工作模式如下：
在正常情况下，CPU 按照既定的指令序列顺序执行；如果发生意外事件，包括通信设备需要 CPU 处理信息时，通过中断机制让 CPU 转而去执行其他必须紧急处理的事情。这种机制使整个系统的设计变得非常优化。

### [01:51] 8086 内部中断与常见类型

我们转来看 8086 内部的中断。CPU 内部产生的中断主要分为以下几类：

1. **除法错误（Divide Error）**：中断类型码为 $0$。在执行除法指令时，如果除数为 $0$，这是一个严重的错误，CPU 会产生 $0$ 号中断。
2. **单步中断（Single Step）**：中断类型码为 $1$。用于支持单步调试并逐条执行指令。
3. **溢出中断（Overflow）**：中断类型码为 $4$。例如执行整数加法时，最后的结果超出表示范围产生溢出，通过执行 `INTO` 指令即可触发 $4$ 号中断。
4. **指令中断（软件中断）**：通过执行 `INT n` 指令产生的中断，指令中直接指定中断类型码 $n$。

常见的内部中断类型码总结：
- **0 号**：除法错误
- **1 号**：单步中断
- **4 号**：`INTO` 指令引起的溢出错误
- **`INT n`**：$n$ 为立即数，表示相应的中断类型码。

### [03:07] 示例：利用 INT 21H 中断调用输出字符串

下面看一个调用中断的具体例子。在这个例子中，给出了一个栈段，在数据段中定义了一串字符串：

```assembly
; 数据段定义字符串
string DB 13, 10, 'Hello World!', 13, 10, '$'
```

其中 `13, 10` 代表回车换行符。该字符串以字符 `'$'` 结尾，这是在编写中断处理程序时约定的结束符。

我们在代码中调用了 `21H` 号中断（DOS 功能调用）：

```assembly
MOV AH, 09H
LEA DX, string
INT 21H
```

`INT 21H` 的作用是处理 DOS 提供的系统中断服务。当传入的功能号为 $9$（通过 `AH = 09H` 指定）时，代表显示字符串功能：
- 它要求显示以 `DS` 为段地址、`DX` 为偏移地址的字符串内容；
- 要求字符串必须以 `'$'` 结尾；
- 指令 `LEA DX, string` 用于取得该标号的有效偏移地址。

在调用 `21H` 号中断的 $9$ 号功能时，CPU 会从指定内存位置取出该字符串并打印到屏幕上。这段程序编译链接运行后，屏幕上就会输出 `Hello World!`，并且前后各空一行（由两组 `13, 10` 回车换行实现）。

### [04:45] DOS 程序退出中断调用

事实上，`INT 21H` 在此前我们一直在使用。例如程序退出的经典代码：

```assembly
MOV AX, 4C00H   ; 或者 MOV AH, 4CH
INT 21H
```

当调用 `21H` 号中断且 `AH = 4CH` 时，其功能是终止程序运行并返回到 DOS 操作系统状态。`INT` 指令能够完成非常丰富的功能，后续课程会进一步展开。

### [05:25] 中断处理机制与中断向量表 (IVT)

接下来我们深入了解中断处理的内部机制。

首要问题是：**CPU 在接收到中断信息后该做什么？**
答案是：CPU 会转去执行**中断处理程序（Interrupt Service Routine, ISR）**。

在执行中断处理程序之前，CPU 必须知道该程序存放在哪。CPU 执行指令依靠改变 `CS`（代码段寄存器）和 `IP`（指令指针寄存器），因此必须获知目标中断处理程序的 `CS` 和 `IP`。

处理中断时，系统在**中断信息**与**处理程序入口地址**之间建立了对应关系。CPU 根据中断信息找到对应的入口地址，进而转移执行。这种对应关系存放在名为**中断向量表（Interrupt Vector Table, IVT）**的数据结构中。

有了中断向量表，CPU 获得中断号（类型码）后，通过查表即可得到对应中断处理程序的入口地址。所有中断向量集中排列成表，通过中断类型码检索，定位并执行中断处理程序。

### [06:50] 8086 中断向量表结构与地址计算

8086 CPU 的中断向量表位于物理内存的最底部，其结构特点如下：
- **占用空间**：共占用 $1024\text{ 字节}$（$00000\text{H} \sim 003FF\text{H}$）。
- **容量**：包含 $256$ 个中断向量（中断号 $0 \sim 255$）。
- **每个向量大小**：每个中断处理程序的入口地址占用 $4\text{ 字节}$。

由于中断处理程序的入口地址需要包含段地址 `CS` 和偏移地址 `IP`，因此每个中断向量占用 4 字节是顺理成章的：
- **0 号中断**：入口地址从内存 `0000:0000` 开始存放；
- **1 号中断**：入口地址从偏移地址 $4$ 开始存放；
- **2 号中断**：入口地址从偏移地址 $8$ 开始存放；
- 以此类推，$256$ 个中断共占用 $256 \times 4 = 1024\text{ 字节}$。

表中中断类型码与入口地址存放位置具有严格的数学对应关系，无需复杂搜索，直接计算即可得到：

$$\text{IP 存放偏移地址} = N \times 4$$
$$\text{CS 存放偏移地址} = N \times 4 + 2$$

在内存存储规则中遵循“高高低低”原则：
- **低位 2 字节**：存放偏移地址 `IP`；
- **高位 2 字节**：存放段地址 `CS`。

### [08:56] 实验验证：0 号除法错误中断

我们以 $0$ 号中断（除法错误）为例进行实验验证。根据公式，$0$ 号中断处理程序的入口地址存放在物理地址 `0000:0000` 起始的 4 个字节单元中。

为了触发 $0$ 号中断，我们在 DEBUG 下用 `a` 命令输入以下测试代码：

```assembly
MOV AX, 0008
MOV BH, 00
DIV BH
```

这里将除数 `BH` 显式设为 $0$。正常情况下指令按序向下执行，但除数为 $0$ 属于严重错误，将触发异常中断。

通过 DEBUG 单步跟踪（`t` 命令）：
1. 执行 `MOV AX, 0008`，寄存器 `AX` 变为 `0008`；
2. 执行 `MOV BH, 00`，寄存器 `BH` 变为 `00`，当前指令指针 `IP = 0105`，代码段 `CS = 073F`；
3. 执行 `DIV BH` 指令。

单步执行除法后观察结果：
- `IP` 突变为 `1060`；
- `CS` 突变为 `F000`。

这说明 CPU 已经跳转执行 $0$ 号中断的处理程序。该程序的入口地址即为 `F000:1060`。

通过 DEBUG 的 `d` 命令查看内存 `0:0` 开始的存储单元（`d 0:0 f`）：
内存对应位置依次显示：
```text
60 10 00 F0
```
- 低 2 字节为 `60 10`，对应的 `IP` 值为 `1060H`；
- 高 2 字节为 `00 F0`，对应的 `CS` 值为 `F000H`。

实验与中断向量表的理论计算完全吻合。当产生除数为 $0$ 的错误时，CPU 准确跳转到了中断向量表中预先设定的中断服务例程入口地址。该处的代码属于系统 ROM-BIOS 或 DOS 系统的内部底层实现。

### [12:22] 中断处理全过程与硬件响应机制

一个完整的中断过程包含以下步骤：
1. **正常执行**：CPU 正在顺序执行主程序；
2. **发生中断**：检测到内中断或外中断请求；
3. **保护现场**：硬件自动保护标志寄存器及当前断点地址，同时保存必要的通用寄存器和内存环境；
4. **查找向量**：通过中断类型码从中断向量表中取得对应中断处理程序的入口地址（`CS` 和 `IP`）；
5. **执行例程**：转向并执行中断服务程序；
6. **中断返回**：中断处理程序执行完毕后，执行 `IRET` 指令返回，恢复现场，继续执行被中断的后续指令。

> **核心机制**：**中断响应过程是由 CPU 的硬件逻辑自动完成的**，而非软件程序调度。当收到中断请求时，硬件直接介入，依据中断类型码寻址中断向量表并完成上下文压栈与跳转。

---

### [13:42] 8086 CPU 硬件响应步骤推导

8086 CPU 在硬件层面响应中断的具体步骤如下：

1. **取得中断类型码** $N$。
2. **标志寄存器入栈**：保护当前的标志位状态（类似于执行 `PUSHF` 指令）。
3. **设置标志位**：将陷阱标志位 `TF` 和中断允许标志位 `IF` 置 $0$（即 $\text{TF} = 0, \text{IF} = 0$），屏蔽后续单步及外部可屏蔽中断。
4. **代码段寄存器入栈**：将当前断点的 `CS` 压入堆栈。
5. **指令指针寄存器入栈**：将当前断点的 `IP` 压入堆栈。
6. **读取并设置入口地址**：
   - 从内存单元 $[N \times 4]$ 读取 2 字节送入 `IP`；
   - 从内存单元 $[N \times 4 + 2]$ 读取 2 字节送入 `CS`。
7. **转移执行**：CPU 从新的 `CS:IP` 开始执行中断处理程序。
8. **返回恢复**：处理完毕后，执行 `IRET`，依次从栈中弹出恢复 `IP`、`CS` 和标志寄存器，程序恢复正常执行流程。

用类代码描述该硬件自动执行的过程：

```text
; 8086 CPU 硬件响应中断伪代码逻辑：
Vector = N * 4

PUSH FLAGS
TF = 0
IF = 0
PUSH CS
PUSH IP

IP = Memory[Vector]
CS = Memory[Vector + 2]

; 转入中断处理程序执行...
```

上述全流程即为 8086 系统的中断处理工作原理。
