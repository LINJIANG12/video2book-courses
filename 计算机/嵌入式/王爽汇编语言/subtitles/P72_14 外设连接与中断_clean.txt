# 外设的连接与中断机制

### [00:00] 外设连接与端口访问

我们在利用汇编语言操作外部设备的时候，经常采用的是中断机制。接下来，我们就看外设的连接和中断的关系。

首先我们知道，CPU 在读写数据的时候一共有三个地方，包括：
1. 寄存器
2. 内存单元
3. 端口

而端口是和各个外部设备进行连接的部位。我们还知道，对端口来讲它是统一编址，把整个地址编在一个 64KB 的范围之内。

其实就是通过这样的端口，建立了外部设备和 CPU 之间的连接。当我们在操作外部设备的时候，实际上就是通过 `IN` 指令和 `OUT` 指令对端口进行操作，而由端口再和外部设备去交换数据。

---

### [00:46] 中断在外部设备操作中的作用

现在的一个问题是：当外部设备有请求的时候，它如何去告诉 CPU？当 CPU 需要外部设备去做一些工作的时候，它又是如何进行驱动的？在这个过程里面需要中断的参与。

也就是说，CPU 在执行指令的过程中，它可以检测发送过来的中断信息，引发中断过程，从而去处理外设的一些输入。

比如说我们这里有键盘，当键盘上敲键之后，它就会触发一个中断。这个中断由 CPU 捕获以后，CPU 再通过 `IN` 或者 `OUT` 指令去获得键盘处理完毕以后的信息。因此，对外部设备的操作是需要有中断机制的。

---

### [01:38] 外中断的分类

我们在说到中断的时候要知道，前面介绍过内中断，现在我们要着重理解外中断。

对外中断来讲，它是由外部设备发生的事件引起的中断。比如说键盘，当我们在键盘上敲一个键以后，这是一个外部事件，在这个时候就会引发一个中断。

对中断而言：
- **内中断**：都是在 CPU 内部触发的。
- **外中断**：分为两种：
  1. **可屏蔽中断**：由各种外部设备引发的中断。
  2. **不可屏蔽中断**：即非屏蔽中断请求。

接下来我们把这两种中断逐一了解。

---

### [02:15] 可屏蔽中断与不可屏蔽中断的响应机制

**可屏蔽中断**指的是 CPU 可以不响应的外中断。它是否去响应，要看标志寄存器当中的 `IF` 位（Interrupt Flag）设置：
- 如果 $IF = 1$：代表 CPU 在执行完当前指令以后，可以响应中断，引发中断过程。于是外部设备的请求，CPU 是要处理的。
- 如果 $IF = 0$：则可以不响应（屏蔽）。尽管外部设备产生中断并传送给 CPU，但 CPU 可以不予理睬。

[02:56] **不可屏蔽中断**则是 CPU 必须响应的外中断，没有商量余地。中断信号到来以后，不管 CPU 在干什么事情，在执行完当前指令以后，必须立即响应，引发中断过程。

对于不可屏蔽中断，其中断类型码固定为 2。

---

### [03:23] 两类外中断的应用场景

如何使用这两种中断呢？

几乎所有由外部设备引发的外中断都是可以屏蔽的中断（可屏蔽中断），比如说键盘输入、打印机请求等等。这样设计其实给 CPU 留有主动权：当外部设备提出请求时，如果 CPU 当前有更重要的事情需要处理，可以先不予理会。因此这种可屏蔽中断的设计是非常合理的。

而不可屏蔽中断，是指系统遇到必须处理的紧急情况时所产生的中断。例如机器在运行过程中突然掉电。掉电发生时，计算机并不是立刻什么都不做，而是需要执行一些保护性的紧急工作。在这个时候就会触发一个非屏蔽中断。对于这一类十万火急的中断，在整个系统设计中将其设计为不可屏蔽中断，是合情合理的。

---

### [04:21] 可屏蔽中断的处理过程

在外部设备操控过程中，CPU 处理可屏蔽中断的完整过程如下：

1. **取中断类型码**
   可屏蔽中断的中断信息来自于 CPU 外部，其中断类型码需要通过数据总线传入 CPU 内部。
   *(对比：之前了解过的内中断是由 CPU 内部产生的，如除法错误的 0 号中断，或通过 `INT n` 指令引发的中断，都是在执行指令过程中由 CPU 内部产生的。)*

2. **标志寄存器入栈**
   使用 `PUSHF` 指令将标志寄存器压入栈中。

3. **设置 `IF` 和 `TF` 位为 0**
   将标志寄存器中的 $IF$ 与 $TF$ 置为 0。特别是将 $IF$ 置 0 后，表示在进入中断处理程序后，禁止其他的可屏蔽中断，优先将当前的中断处理完毕。如果中断处理程序中确实需要其他中断嵌套介入，也可以在程序中主动将 $IF$ 重新置为 1。

4. **CS 与 IP 入栈**
   将当前的 `CS` 和 `IP` 压入栈中保存，以便在中断处理完成后，执行中断返回时能够准确返回到原来的执行地址。

5. **设置新的 IP 和 CS**
   根据中断类型码 $N$，从中断向量表中获取对应的中断向量（即中断处理程序的入口地址），重新对 `IP` 和 `CS` 赋值。

完成 `IP` 与 `CS` 的更新后，CPU 转去执行中断处理程序。

---

### [06:38] 不可屏蔽中断的处理过程

对于不可屏蔽中断，其中断处理过程如下：

1. **标志寄存器入栈，并将 `IF` 和 `TF` 置为 0**
   由于不可屏蔽中断的中断类型码固定为 2，因此**省略了从外部读取中断类型码的步骤**。
2. **CS 和 IP 入栈保存**
3. **设置新的 IP 和 CS**
   直接根据固定的中断类型码 2 读取对应的中断向量，并赋值给 `IP` 和 `CS`。

赋值完成后，CPU 随即转去执行不可屏蔽中断的中断处理程序。

---

### [07:19] 中断标志位操作指令及小结

最后补充两个用于设置 `IF` 标志位的小指令：

```assembly
STI ; Set Interrupt flag，将 IF 置为 1 (IF = 1)
CLI ; Clear Interrupt flag，将 IF 清除为 0 (IF = 0)
```

- **`STI`**：`ST` 代表 Set（设置），用于将 $IF = 1$。
- **`CLI`**：`CL` 代表 Clear（清除），用于将 $IF = 0$。
