## 状态与寄存器：同步数字系统的时钟、时序与状态机
> 对应块：BLK17 | 覆盖分集：P17 | 块标题（分集名）：《第 16 讲 - 状态与寄存器》

欢迎回来。今天我们要继续深入电路设计的奇妙世界，看看怎么让这些硅片和导线做一些真正酷炫的事情——比如，让它们能够稳稳当当地运行我们的代码。

在前面的课程里，我们聊过 RISC-V 汇编，大家已经见过寄存器了，知道它是一个能存储 32 位二进制数据的地方；再回想我们在 C 语言里编程，调用 `malloc` 就能向操作系统申请一大块内存，用来存放数组、结构体或者复杂的数据结构。在软件层面上，我们对“存储数据”这件事情早就习以为常了。但如果我们把视角拉回到硬件底层，一个直截了当且必须回答的问题就浮现出来了：在最基础的物理层面上，我们究竟该如何构建出能够存储数据的电路元件？那些寄存器文件（Register File）和内存块（SRAM/DRAM），到底是由什么搭出来的？

另一个同样关键甚至更深刻的洞察是：我们不仅需要存储数据，还需要通过寄存器来控制信息在各个组合逻辑模块之间的流动节奏。

---

### 状态的由头与纯组合逻辑的失控困境

在动手构建存储元件之前，我们先来做一个思想实验，甚至不妨带着一点叛逆的念头反问一句：为什么我们非得需要“状态”（State）呢？为什么不能只用之前学过的组合逻辑（Combinational Logic）搞定一切？

我们已经掌握了与门、或门、非门、异或门，还能把它们拼成加法器、多路选择器（MUX）。既然组合逻辑能够完成布尔代数里的任何计算，我们为什么不直接用它们来跑程序？

我们来试一次。假设我们要用硬件实现一段最基础的累加循环代码：

```c
for (int i = 0; i < n; i++) {
    s = s + x[i];
}
```

这段代码的逻辑极其简单直白：外界源源不断地给我们提供一串数字序列，比如 $1, 5, 7, -2$。每输入一个新数字，我们就把它累加到当前的总和 $s$ 里，最后把累加的总和输出给用户。

现在，我们尝试完全不引入任何状态元件，只用一个纯组合逻辑加法器来搭这个电路。

既然要把新来的数字和之前的累加结果相加，最直觉的硬件连线方案就是把加法器的输出端通过一根导线拉回来，直接接回加法器的其中一个输入端，形成一个反馈回路（Feedback Loop）。加法器的另一个输入端，则用来接入外界送进来的数字序列 $x_i$。

```text
               输入数字序列 x_i
                     │
                     ▼
              ┌──────────────┐
     ┌───────►│ 加法器 (ADD) │──────┬───────► 输出当前总和 s
     │        └──────────────┘      │
     │               反馈           │
     └──────────────────────────────┘
```

乍一看，这个设计非常巧妙：假设前 5 个数字的和已经算出来了，正挂在输出导线上；此时外界输入第 6 个数字，加法器把输出导线上的前 5 个数之和与第 6 个数相加，算出了前 6 个数的和，并把新结果重新送上输出导线；紧接着第 7 个数字到达，继续相加……谁还需要什么复杂的状态元件？这看起来不是完全行得通吗？

但物理现实会立刻给我们一记响亮的耳光。

我们来仔细想想，当这个纯组合逻辑电路真正通电合闸时，到底会发生什么：

假设外界送进来的第一个数字是 $2$，这根输入导线此时稳定地呈现数值 $2$。加法器将输入与反馈线相加，输出端算出了 $2$。然而，输出端与反馈输入端之间只是一根光秃秃的导线，没有任何开关或阀门阻拦！输出端的 $2$ 瞬间顺着反馈导线杀回了输入端。此时，外界输入导线上依然是那个数字 $2$（因为外界根本还没来得及切换到下一个数字），加法器看到两个输入都是 $2$，立刻算出了 $4$。

还没完！$4$ 出现后又以光速沿着反馈导线流回输入端，$4 + 2 = 6$；紧接着 $6$ 又被反馈回来，$6 + 2 = 8$；然后是 $8 + 2 = 10$……整个电路开始疯狂失控。

在这段极短的时间内，外界提供输入的导线一直维持着数字 $2$，因为那是我们要相加的第一个数字。但底层的加法器电路完全不受控地狂飙运转，内部数值以物理电子流动的极限速度不断递增（$2 \to 4 \to 6 \to 8 \to 10 \dots$）。

> **易错点**：纯组合逻辑没有任何流动控制机制。信号在导线与门电路之间奔流不受约束。在纯组合逻辑电路中，计算会以硬件允许的最快速度失控打转，根本不会停下来等待下一个有效输入到达。

不仅如此，这个纯组合逻辑电路还存在第二个致命的结构性缺陷：加法器在循环开始前，如何将总和重置为零（即代码中的 `s = 0`）？

在上面那张简陋的反馈图里，没有任何地方可以让我们明确接入一个初始的零值。初始状态加法器输出的是什么？导线刚通电时的瞬态电平完全随机，根本无从谈起“从零开始累加”。

既然纯组合逻辑既无法控制数据节奏，又无法确立初始基准，我们就必须引入全新的电路积木——寄存器。

### 寄存器与时钟：让信号排队通行的交通灯

要驯服失控奔流的电信号，我们需要一个能够充当“交通信号灯”的元件。

这就是寄存器（Register）。

当我们去街上观察十字路口的交通信号灯时，它的核心职责非常简单：红灯停，绿灯行。红灯亮起时，所有的车辆（数据信号）必须在停止线前乖乖停下，不管你马力有多大、跑得多快，都只能在原地等待、等待、再等待；只有当绿灯亮起的那一瞬间，通行指令下达，积蓄在路口的车辆才被放行，奔向下一段道路。

寄存器在电路中正是扮演了这样一个交通灯的角色：

从信号流控制的角度看，寄存器能够在上一级组合逻辑计算完成后，牢牢拦住前驱信号，强迫它在输入端口暂存等待；直到整个系统统一下达“放行”指令，它才将这批数据推送到下游，并阻止后续的扰动提前冲入。

从存储数据的角度看，当信号被拦在寄存器内部时，寄存器的输出端口会持续保持并稳定输出上一次被放行的数据。因此，它天然就是一个数据存储单元。

#### 寄存器的微观积木：D 触发器

如果我们要探究寄存器的内部构造，把它拆开来看看，它最核心的基础构建单元叫做**触发器（Flip-Flop）**。

这个名字非常形象：触发器可以在不同的逻辑电平（$0$ 与 $1$）之间来回“翻转”并锁定。一个最基础的 D 触发器能够存储且仅能存储 $1$ 位（1 bit）的二进制数据。

```text
            D 触发器 (D-Flip-Flop)
             ┌─────────────────┐
  数据输入 D ───►│                 │───► 输出 Q
             │                 │
  时钟信号 CLK ──►│ >               │
             └─────────────────┘
```

如果我们需要在计算机硬件中存储多位数据，做法极其简单直观：并排排列多个 D 触发器。

比如在 32 位的 RISC-V 处理器中，一个通用的 32 位寄存器，其内部本质上就是整整 32 个 D 触发器并排排列在一起，共用同一个控制时序。每个触发器各自负责锁存 32 位数据中的其中 1 位。

在 D 触发器上，有三个关键的端口：
- **D 端（Data In）**：寄存器的数据输入端口。外界想要写入或更新的新信号从这里进入。
- **Q 端（Data Out）**：寄存器的数据输出端口。寄存器当前所记忆并持续输出的数值从这里引出。
- **时钟端（Clock / CLK）**：控制信号放行与锁存的心跳端口。

#### 系统的脉搏：时钟信号与懒惰的寄存器

在同步数字系统（Synchronous Digital Systems, SDS）中，我们依靠一个被称为**时钟（Clock）**的全局信号来统领所有部件的协同动作。

时钟信号并没有什么复杂的编码花样，它就像整套系统的脉搏，在逻辑 $0$ 与逻辑 $1$ 之间保持着高度恒定的频率来回跳变。

```text
时钟信号 CLK:
       ┌───┐       ┌───┐       ┌───┐       ┌───┐
       │   │       │   │       │   │       │   │
───────┘   └───────┘   └───────┘   └───────┘   └───────
       ▲           ▲           ▲           ▲
     上升沿      上升沿      上升沿      上升沿
```

理解寄存器行为的最关键直觉在于：**寄存器在绝大多数时间里是极其“懒惰”的**。

在时钟处于低电平、高电平或者处于下降沿期间，寄存器完全无所作为。它就像在原地“睡觉、思考人生”，输出端 Q 死死锁住原有的旧值。此时无论输入端 D 怎么剧烈波动，哪怕外界信号上蹿下跳，寄存器都充耳不闻。

寄存器生命中唯一具有价值的“高光时刻”，只发生在一个极其精确的时间点：**当时钟信号从逻辑 $0$ 跳变到逻辑 $1$ 的那一瞬间**，也就是**时钟上升沿（Rising Edge / Positive Edge）**。

一旦时钟上升沿到来，寄存器就像被闹钟猛然唤醒。在极短的物理瞬间，它转过身去采样此时此刻挂在 D 输入端上的电平，并尽可能迅速地把这个采样值传递到 Q 输出端；完成这一动作后，它立刻倒头大睡，继续维持 Q 端的新值不变，耐心地等待下一次时钟上升沿的呼唤。

> **定义**：本课程所讨论的寄存器默认皆为**上升沿触发（Edge-Triggered）**的触发器。它们只在时钟由 $0$ 变 $1$ 的跳变沿瞬间执行数据采样与锁存，在其他任何时刻均阻断外部输入的透传。

这种上升沿触发特性的强大之处，在于它赋予了数字电路极强的抗干扰能力。我们来看一个典型的时序图场景：

```text
CLK ──────┐   ┌───────┐   ┌───────┐   ┌───────┐   ┌───
          │   │       │   │       │   │       │   │
          └───┘       └───┘       └───┘       └───┘
            ▲           ▲           ▲           ▲
            │           │           │           │
 D  ────────┤   ┌───────┴───┐       ├───┐ ┌─┐   ├───
            │   │           │       │   │ │ │   │
            └───┘           └───────┘   └─┘ └───┘
                                         ▲
                                    中间毛刺被忽略
            │           │           │           │
 Q  XXXXXXXX├───┬───────┼───┬───────┼───┬───────┴───
            │   │       │   │       │   │
            └───┴───────┴───┴───────┴───┴───────────
             沿1         沿2         沿3         沿4
```

读图说明：
- 在时间轴的最初起点，由于系统刚刚上电，尚未经历任何上升沿，寄存器内部的初始电荷完全未知。因此在沿 1 之前，输出 Q 用交叉阴影线表示，代表此时输出的是未定义的垃圾数据（Garbage Data）。
- 在**沿 1** 处，时钟上升沿到来，寄存器苏醒，此时输入端 D 稳定为 $0$。寄存器采样到 $0$，迅速将其反映到 Q 端。此后直到下一个上升沿，Q 始终稳稳输出 $0$。
- 在**沿 2** 处，时钟再次上升，此时 D 端为 $1$。寄存器将 $1$ 更新到 Q 端。
- 注意在沿 3 到沿 4 之间，输入端 D 突然从 $0$ 跳到 $1$，但仅仅维持了很短的一小会儿又跌回了 $0$（产生了一个瞬态毛刺 Glitch）。但因为这个剧烈变化并没有发生在时钟上升沿时刻，寄存器对此完全视若无睹，Q 端的输出完全没有被这个毛刺破坏。

这种特性，正是我们在数字系统中抵御噪声与瞬态波动的核心防线。

### 物理现实的约束：延迟、建立时间与保持时间

在上面的理想示意图中，我们画出来的信号跳变如同几何线条一样干净垂直，但现实世界是由真实的半导体物理规则统治的。“事物需要时间”，任何电信号的传输与晶体管的翻转都无法做到瞬时完成。

当我们把寄存器放进真实的物理电路中时，必须直面三个不可回避的时间参数。

#### 时钟到 Q 延迟（$t_{\text{clk-to-q}}$）

当时钟上升沿到达寄存器内部时，触发器内部的晶体管开关需要一定的时间来搬运电荷，并把输出驱动到合法的逻辑电平。

从时钟上升沿发生的那一刻起，到 Q 输出端真正稳定建立起新数值之间的时间间隔，被称为**时钟到 Q 延迟（Clock-to-Q Delay，记作 $t_{\text{clk-to-q}}$）**。

这意味着，Q 端的数值更新永远比时钟上升沿“稍微晚一点点”。$t_{\text{clk-to-q}}$ 决定了寄存器的输出在何时变得真正有效。

#### 建立时间（$t_{\text{setup}}$）

如果输入端 D 上的信号在上升沿到来的前一微秒还在疯狂上下抖动，寄存器醒来时到底该采样谁？是采样 $1$？采样 $0$？还是采样到一个不上不下的中间悬空电平？

为了保证采样万无一失，寄存器对外部输入提出了严格的要求：**在时钟上升沿到来之前，输入信号 D 必须提前达到稳定电平，并维持一段绝对不允许晃动的时间窗口**。这段上升沿到来前必须保持稳定的时间，被称为**建立时间（Setup Time，记作 $t_{\text{setup}}$）**。

这就像去教室上课：你不能踩着打铃的那一秒、甚至迟到了才冲进教室找座位（那样全班都会乱套），你必须在打铃前提前坐定，寄存器才能看清你要给它的究竟是哪一个确定的数值。

#### 保持时间（$t_{\text{hold}}$）

当时钟上升沿发生后，内部逻辑正在锁存采样电平，输入端 D 不能在沿一过就立马变脸或撤走。**在时钟上升沿发生之后的短暂时间内，输入信号 D 依然必须维持原有数值稳定不变**。这段在沿后必须保持稳定的时间，被称为**保持时间（Hold Time，记作 $t_{\text{hold}}$）**。

我们可以把上升沿前后的时间窗口直观地划出来：

```text
时钟 CLK ─────────────┐
                      │
                      └───────────────────────────
                      ▲
                    上升沿
                      │
输入 D   ═════════════╪═══════════════════════════
        │  稳定不变   │   稳定不变   │ 允许任意变化
        ├────────────┼─────────────┤
          t_setup         t_hold
         (沿前建立)      (沿后保持)
                      │
输出 Q   ─────────────┼───────┬───────────────────
                      │       │ 出现稳定新数据
                      ├───────┤
                      t_clk-to-q
```

读图说明：
- $t_{\text{setup}}$ 与 $t_{\text{hold}}$ 是**施加在输入端 D 上的约束条件**，规定了输入信号为了被正确采纳所必须付出的守序代价；
- $t_{\text{clk-to-q}}$ 则是**输出端 Q 的内在物理响应特性**，说明了寄存器把采到的数据推到输出端需要消耗的物理延迟。两者概念截然不同，千万不要混淆。

> **易错点**：如果在 $t_{\text{setup}}$ 或 $t_{\text{hold}}$ 的稳定保护窗口内，输入端 D 发生了跳变或晃动，就会发生**时序违例（Timing Violation）**。在这种情况下，寄存器的硬件行为将陷入完全的**未定义行为（Undefined Behavior）**。其输出既可能是 $0$，也可能是 $1$，更可能是停留在既非 $0$ 也非 $1$ 的中间悬浮电压态（亚稳态 Metastability），导致后续所有级联电路彻底崩溃。

### 累加器的正确打开方式：复位机制与时序追踪

现在，我们把学到的寄存器带回到最开始失控的累加器电路中，重新搭建一个健壮的同步数字系统。

#### 引入复位（Reset）与带时钟的累加电路

为了彻底解决循环开始时变量无法初始化（即 `s = 0`）的问题，我们使用的寄存器除了 D、Q 和 CLK 端口外，还配备了一个专用的控制引脚：**复位端（Reset）**。

```text
               输入数据 x_i
                     │
                     ▼
              ┌──────────────┐
     ┌───────►│ 加法器 (ADD) │
     │        └──────┬───────┘
     │               │ 和信号 s_i (加法器输出)
     │               ▼
     │        ┌──────────────┐
     │        │ D          Q │──────┬───────► 输出当前累加和 s_{i-1}
     │        │   寄存器     │      │
     │        │ CLK    Reset │      │
     │        └───▲───────▲──┘      │
     │            │       │         │
     │           时钟    复位       │
     │                              │
     └──────────────────────────────┘
```

读图说明：
- 加法器的输出端记为 $s_i$，代表加上当前输入 $x_i$ 之后的最新累加和，直接送往寄存器的输入 D 端；
- 寄存器的输出端记为 $s_{i-1}$，代表上一个时钟周期锁存的总和。它不仅作为电路的当前结果对外输出，还作为加法器的反馈输入端，参与下一次相加；
- 复位端（Reset）受全局信号控制。当 Reset 为高电平时，在下一个时钟上升沿到来时，寄存器将无视 D 端传来的任何加法结果，强制把内部状态置为 $0$，并在上升沿后的 $t_{\text{clk-to-q}}$ 延迟后向 Q 端输出全 $0$。这就完美对应了代码里的初始化语句 `s = 0`。

#### 完整时序追踪与双重延迟

在这个协同工作的电路中，有两个不可忽视的关键延迟必须计入考量：
1. **寄存器的时钟到 Q 延迟 $t_{\text{clk-to-q}}$**：当时钟沿到来时，旧数据推到反馈线上需要耗费的时间；
2. **加法器的组合逻辑延迟 $t_{\text{add}}$**：当输入端两个数据均到位后，加法器内部进位链传输、完成相加并稳定输出 $s_i$ 所耗费的物理时间。

我们来追踪一个从复位到累加的完整过程：

```text
CLK    ──┐   ┌───┐   ┌───┐   ┌───┐   ┌───┐   ┌───
         │   │   │   │   │   │   │   │   │   │   
         └───┘   └───┘   └───┘   └───┘   └───┘   
           ▲       ▲       ▲       ▲
         沿 0    沿 1    沿 2    沿 3

Reset  ══╪═══════╧═══════════════════════════════
       (高电平有效)   (拉低恢复正常)

x_i    XXXXXXXX══╪═══════╤═══════╤═══════╤═══════
                 │  x_0  │  x_1  │  x_2  │
                 └───────┴───────┴───────┘

s_{i-1}XXXXXXXX──┼─┐     ┌─┐     ┌─┐     ┌───────
 (Q输出)         │ │  0  │ │ x_0 │ │x_0+x_1
                 └─┴─────┴─┴─────┴─┴─────┴───────
                   ▲       ▲
                   t_clk-to-q

s_i    XXXXXXXX──┼───┐   ├───┐   ├───┐   ├───────
 (D输入)         │   │x_0│   │x_0+x_1│   │x_0+x_1+x_2
                 └───┴───┴───┴───┴───┴───┴───────
                     ▲
                     t_clk-to-q + t_add
```

读图说明：
- 在**沿 0** 处：Reset 信号处于激活的高电平状态。当时钟沿到达后，经过一小段 $t_{\text{clk-to-q}}$ 延迟，寄存器的输出 $s_{i-1}$ 被强制刷新并稳定为全 $0$；
- 在沿 0 到沿 1 之间：外部给出了第一个输入数字 $x_0$。此时反馈导线上的值为 $0$，加法器执行 $0 + x_0$。经过加法器自身的运算延迟 $t_{\text{add}}$ 之后，加法器输出端 $s_i$ 稳定出现了数值 $x_0$，并在沿 1 前满足了寄存器的建立时间；
- 在**沿 1** 处：第二个上升沿到来，寄存器采样此时稳稳停在输入端的 $x_0$。经过 $t_{\text{clk-to-q}}$ 延迟后，输出端 $s_{i-1}$ 刷新为 $x_0$。加法器随即开始执行 $x_0 + x_1$，并在沿 2 前完成稳定输出。

整个累加过程严格按照时钟节拍一步一动，每个时钟周期精确处理一个输入数字。先前那种 $2, 4, 6, 8, 10$ 瞬间狂飙的失控灾难彻底绝迹。

#### 异步输入与跨时区“容错”分析

在上面的理想推演中，我们假定外界输入 $x_i$ 与我们内部的时钟步调完全一致。但在实际工程中，提供输入数据的源头可能来自另一个芯片，或者来自不同时钟驱动的外部总线。通俗地说，对方可能“和我们处于不同的时区”。

如果外部输入 $x_i$ 到达的时间相对我们的时钟上升沿稍有偏移（异步延迟），会发生什么？

假设在沿 1 刚刚过去时，寄存器输出端已经更新为 $x_0$ 并反馈回加法器，但外界由于时延，输入导线上依然残留着旧的数值 $x_0$，还没来得及切换为下一个数 $x_1$。

此时加法器两端看到的输入分别是“刚刷新的反馈值 $x_0$”和“尚未更新的输入值 $x_0$”。加法器会非常诚实地把它们相加，并在加法器输出端 $s_i$ 短暂地冒出一个 $x_0 + x_0$！

很多人看到这里会大惊失色：“天啊，电路算出了一个完全错误的垃圾值，硬件是不是要崩了？”

**完全不会。**

因为此时寄存器正处于安稳的“睡眠期”！在时钟周期的中间阶段，无论加法器输出端因信号延迟产生了怎样荒谬的中间垃圾值，寄存器都像铁桶一样将它死死挡在门外。只要外部输入 $x_1$ 随后及时赶到，加法器重新结算为正确的 $x_0 + x_1$，并且这个正确的结果在下一个时钟上升沿到来之前提前稳定就绪（满足了 $t_{\text{setup}}$），那么在下一个上升沿被捕获锁存的，就必然是百分之百正确的累加值！

> **结论**：同步时钟系统具有强大的容错与滤波能力。中间计算产生的临时毛刺、时差与异步脏数据，只要在时钟沿到来前完成收敛，就会被寄存器的时间闸门彻底过滤。

### 时序闭合与性能优化：从时钟方程到流水线

既然只要满足建立时间，系统就能正常工作，那我们是不是可以把时钟频率调得无限高，让计算机跑得飞快？

显然不行。电路中的所有物理延迟，共同构成了限制系统最高时钟频率的铁律。

#### 建立时间约束与最高时钟频率方程

我们把一个通用的同步数字系统路径抽象出来：由一个发送端寄存器出发，经过任意组合逻辑（CL），最终抵达接收端寄存器。

```text
 ┌─────────┐                                ┌─────────┐
 │ 发送端  │           组合逻辑网络         │ 接收端  │
 │ 寄存器  │──────►┌──────────────────┐────►│ 寄存器  │
 │  (Reg1) │  Q1   │   (Combinational │ D2  │  (Reg2) │
 └───▲─────┘       │       Logic)     │     └───▲─────┘
     │             └──────────────────┘         │
     └───────────────────┬──────────────────────┘
                     时钟 CLK
```

当时钟发出一个上升沿时，信号必须跑完以下整场接力赛：
1. **第一棒（离开起点）**：发送端寄存器收到时钟沿，将内部数据输出到 Q1 端，耗时为时钟到 Q 延迟 $t_{\text{clk-to-q}}$；
2. **第二棒（穿越赛道）**：信号穿过由门电路组成的组合逻辑网络进行计算，耗费组合逻辑最大传播延迟 $t_{\text{CL}}$；
3. **第三棒（提前就位）**：信号到达接收端寄存器的输入 D2 端，但它绝不能踩着下一个时钟沿的最后一皮秒到达，它必须提前留出接收端寄存器的建立时间 $t_{\text{setup}}$。

这三段时间相加，就是下一个时钟沿最早允许到来的时间距离。

因此，**时钟周期（Clock Period，记作 $T_{\text{clk}}$）必须大于或等于这三者之和**：

$$T_{\text{clk}} \ge t_{\text{clk-to-q}} + t_{\text{CL}} + t_{\text{setup}}$$

> **结论**：一个同步系统的最小时钟周期由最长路径（关键路径 Critical Path）上的组合逻辑延迟、寄存器传输延迟及建立时间共同决定。系统的最高工作频率 $f_{\max} = \frac{1}{T_{\text{clk}}}$ 受到该方程的绝对硬性约束。

如果人为强行缩短时钟周期（超频过头），导致 $T_{\text{clk}} < t_{\text{clk-to-q}} + t_{\text{CL}} + t_{\text{setup}}$，信号在组合逻辑里还没算完或者没来得及在接收端站稳，时钟上升沿就匆匆降临，就会引发建立时间违例，系统将立即得出错误结果或死锁。

#### 保持时间约束：信号绝不能跑得太快

除了“跑得太慢会迟到”之外，电路里还有另一种相反的危险：“跑得太快会撞车”。

这就是保持时间约束。

在当前时钟上升沿到来时，接收端寄存器正在锁存前一个周期的旧数据，它要求该输入在沿后维持 $t_{\text{hold}}$ 时间不许变动。而同一时刻，发送端寄存器也在被该沿触发，新数据开始往外冲，沿着组合逻辑奔向下游。

如果新数据跑得太快了——也就是说，新数据从发出（$t_{\text{clk-to-q}}$）到穿过组合逻辑最短路径（$t_{\text{CL, min}}$）的时间总和，比接收端寄存器要求的保持时间 $t_{\text{hold}}$ 还要短，那么新数据就会在旧数据还未锁存完毕之前直接冲进接收端，把旧数据冲毁！

为了防止保持时间违例，物理电路上必须满足：

$$t_{\text{clk-to-q}} + t_{\text{CL, min}} \ge t_{\text{hold}}$$

> **提示**：请特别注意，保持时间约束公式的两边**完全没有时钟周期 $T_{\text{clk}}$ 的参与**！这意味着，保持时间违例是无法通过降低时钟频率（把时钟调慢）来解决的。一旦芯片设计存在保持时间违例，就算把时钟降到 1Hz 也无济于事，只能通过在硬件路径上人为插入延时缓冲器（Buffers）增加延迟来修复。

#### 性能飞跃的钥匙：流水线技术（Pipelining）初探

在大型处理器中，如果两个寄存器之间的组合逻辑非常庞大复杂——比如既要做 64 位加法，紧接着又要做桶形移位（Shifter），还要经过复杂的标志位判断——那么这个组合逻辑的传播延迟 $t_{\text{CL}}$ 将会极其漫长。

根据时钟方程，漫长的 $t_{\text{CL}}$ 会直接逼迫我们把整个系统的时钟周期 $T_{\text{clk}}$ 设得非常长，导致处理器的时钟频率极低。

```text
未流水线化 (单一漫长周期):
┌──────┐      ┌──────────────┐      ┌──────────────┐      ┌──────┐
│ Reg1 ├─────►│  加法逻辑    ├─────►│  移位逻辑    ├─────►│ Reg2 │
└──────┘      └──────────────┘      └──────────────┘      └──────┘
├────────────────────────── T_clk ───────────────────────────────┤

流水线化 (拆分为两个短周期):
┌──────┐      ┌──────────────┐      ┌──────┐      ┌──────────────┐      ┌──────┐
│ Reg1 ├─────►│  加法逻辑    ├─────►│ RegM ├─────►│  移位逻辑    ├─────►│ Reg2 │
└──────┘      └──────────────┘      └──▲───┘      └──────────────┘      └──────┘
├────────── T_clk1 ──────────┤     时钟    ├────────── T_clk2 ──────────┤
```

为了打破这一性能瓶颈，我们可以采取一种极其聪明的架构设计：**流水线（Pipelining）**。

我们不在一个超长的时钟周期内试图一次性做完所有事情，而是在加法逻辑和移位逻辑的正中间横切一刀，插入一级中间流水线寄存器 `RegM`。

这样一来，原本漫长的一个大任务被切成了两个独立的阶段（Stages）：
- 在第一个较短的时钟周期内，系统只执行加法操作，结果在周期末暂存进 `RegM`；
- 在第二个时钟周期内，`RegM` 将暂存的数据输出给移位逻辑，完成后续操作，同时起点上的 `Reg1` 已经可以接收下一个全新的数据开始加法计算！

通过插入寄存器划分流水段，原本巨大的 $t_{\text{CL}}$ 被拆分成了两个较小的延迟，系统的时钟周期因此可以大幅缩短，整体时钟频率显著提升。这正是现代高性能 CPU 能够在数 GHz 超高主频下飞速运转的核心秘诀。

### 有限状态机：从抽象模型到硬件映射

到目前为止，我们讨论的都是如何保存具体的数据值（例如累加数值）。但在现代计算机中，除了运送数据的数据通路（Datapath）之外，我们还需要负责指挥调度、在不同工作模式之间来回切换的**控制逻辑（Control Logic）**。

在概念抽象的阶梯上，我们需要再向上跃迁一步：如何用硬件来表达“系统的决策与控制流程”？

这就是**有限状态机（Finite State Machine, FSM）**。

#### 有限状态机四要素

有限状态机是一种理论抽象模型，用来描述一个系统如何在有限个离散状态之间依规则跳转：
1. **状态集合（States）**：系统所有可能处于的离散状态（例如状态 0、状态 1、状态 2……）；
2. **输入信号（Inputs）**：驱动系统进行状态变迁的外部刺激；
3. **输出信号（Outputs）**：系统在不同状态或转换下对外展示的行为与响应；
4. **状态转移函数（Transition Rules）**：一个确定性的决策规则——给定系统“当前所处的状态”以及“当前接收到的输入”，决定系统在下一个时钟步长应该“转移到哪一个目标状态”，同时决定“应该输出什么值”。

#### 经典实例：连续三个 1 的序列检测器

为了彻底看清状态机的运转机制，我们来亲手设计一个硬件中非常经典的控制部件：**连续检测三个 1 的序列检测器**。

设计目标：系统接收一串连续流入的二进制输入比特流（由 $0$ 和 $1$ 组成）。只要输入中出现连续三个 $1$（即序列出现 `1 1 1`），系统立即输出 $1$；在其余任何情况下，输出皆为 $0$。

例如对于输入序列：
- 输入序列：`... 0, 1, 1, 0, 1, 1, 1, 0 ...`
- 输出响应：`... 0, 0, 0, 0, 0, 0, 1, 0 ...`

我们来构建这个状态机：

首先定义系统内部的状态。我们用状态来记录“目前已经看到了几个连续的 1”：
- **状态 $S_0$**：当前看到了 0 个连续的 1（系统复位后的基准初始态）；
- **状态 $S_1$**：当前看到了 1 个连续的 1；
- **状态 $S_2$**：当前看到了 2 个连续的 1。

接下来，我们在状态之间连接带有条件的转移箭头。在状态转移图中，每个箭头上标有两个数字，格式为 `输入 / 输出`：

```text
               ┌─────── 0 / 0 ───────┐
               │                     │
               ▼                     │
           ┌───────┐      1 / 0      │
           │  S_0  ├────────────────►│
           └─▲───┬─┘                 │
             │   │                   │
       0 / 0 │   │ 1 / 0             │
             │   ▼                   │
           ┌─┴─────┐      1 / 0      │
           │  S_1  ├────────────────►│
           └─▲───┬─┘                 │
             │   │                   │
       0 / 0 │   │ 1 / 1             │
             │   ▼                   │
           ┌─┴─────┐                 │
           │  S_2  ├─────────────────┘
           └───────┘
```

更清晰的状态转移走向如下：
- 当处于 **$S_0$** 时（已见 0 个 1）：
  - 若收到输入 `0`：毫无进展，通过自环箭头保持在 $S_0$，输出 `0`；
  - 若收到输入 `1`：阶段性胜利，转移到状态 $S_1$，输出 `0`。
- 当处于 **$S_1$** 时（已见 1 个 1）：
  - 若收到输入 `0`：序列中断前功尽弃，转移回状态 $S_0$，输出 `0`；
  - 若收到输入 `1`：再进一步，转移到状态 $S_2$，输出 `0`。
- 当处于 **$S_2$** 时（已见 2 个 1）：
  - 若收到输入 `0`：序列同样中断，转移回状态 $S_0$，输出 `0`；
  - 若收到输入 `1`：**目标达成！** 加上前两个 1，系统终于集齐了连续三个 1！系统立刻输出 `1`，同时状态重置回 $S_0$ 重新开始计数。

整个系统的决策逻辑清晰严密，无论输入序列有多长，它都能在三个状态之间精准起舞。

#### FSM 到物理硬件的无缝映射

为什么我们要大费周章地学习这种数学抽象？

因为**任何一个有限状态机，都可以 100% 机械化、无歧义地直接翻译成物理数字电路！**

在电路硬件上，实现任何有限状态机只需要两个不可分割的部件：
1. **状态寄存器（State Register）**：专门用来存储系统“当前所处的状态”；
2. **纯组合逻辑块（Combinational Logic）**：纯逻辑门电路，用来充当状态转移函数。它的输入是“当前状态”与“外部输入”，输出则是计算出的“下一状态（Next State）”与“对外输出（Output）”。

```text
                      外部输入 In
                          │
                          ▼
            ┌───────────────────────────┐
     ┌─────►│                           ├─────► 外部输出 Out
     │      │         组合逻辑          │
     │      │   (状态转移与输出逻辑)    │
     │      │                           ├─────┐
     │      └───────────────────────────┘     │
当前状态 CurState                         下一状态 NextState
     │             ┌─────────────┐            │
     └─────────────┤ Q         D │◄───────────┘
                   │  状态寄存器 │
                   │     CLK     │
                   └──────▲──────┘
                          │
                       时钟信号
```

读图说明：
- 状态寄存器在每个时钟上升沿，将计算好的下一状态采样为当前状态输出；
- 组合逻辑实时根据当前状态和输入引脚电平，算出下一状态和输出；
- 整个闭环在时钟驱动下稳定向前演进。

为了让组合逻辑电路能够计算状态，我们需要把离散状态转化为二进制编码。我们有 3 个状态（$S_0, S_1, S_2$），由于 $2^1 < 3 \le 2^2$，我们需要至少 2 位寄存器（记为 $s_1 s_0$）来进行编码：
- $S_0 \implies 00_2$
- $S_1 \implies 01_2$
- $S_2 \implies 10_2$
- （$11_2$ 未使用）

根据前面的状态转移图，我们可以毫无遗漏地写出这张状态机的**状态转移真值表**：

| 当前状态 $s_1 s_0$ | 输入 In | 下一状态 $s_1' s_0'$ | 输出 Out | 转移语义说明 |
| :---: | :---: | :---: | :---: | :--- |
| `00` ($S_0$) | `0` | `00` ($S_0$) | `0` | 初始遇 0，保持 0 计数 |
| `00` ($S_0$) | `1` | `01` ($S_1$) | `0` | 遇首个 1，进阶到已见 1 个 1 |
| `01` ($S_1$) | `0` | `00` ($S_0$) | `0` | 遇 0 中断，重置回初始状态 |
| `01` ($S_1$) | `1` | `10` ($S_2$) | `0` | 遇第二个 1，进阶到已见 2 个 1 |
| `10` ($S_2$) | `0` | `00` ($S_0$) | `0` | 遇 0 中断，重置回初始状态 |
| `10` ($S_2$) | `1` | `00` ($S_0$) | `1` | **集齐三个 1！输出 1 并归位重新计数** |

仔细端详上面这张表格：左边三列是自变量（输入），右边两列是因变量（输出）。这根本就是一个标准的组合逻辑真值表！

只要拿出我们在布尔代数课程里学过的卡诺图（Karnaugh Map）或逻辑化简法，写出逻辑表达式：
- $s_1' = \overline{s_1} \cdot s_0 \cdot \text{In}$
- $s_0' = \overline{s_1} \cdot \overline{s_0} \cdot \text{In}$
- $\text{Out} = s_1 \cdot \overline{s_0} \cdot \text{In}$

然后用几颗与门和非门把这几个逻辑表达式连出来，接在 2 个 D 触发器的前后端口上——瞧！一个原本停留在纯数学脑海里的“连续三个 1 检测器”，就彻底具象化为一块真真切切在硅片上跑动、带时钟节拍的现代集成电路了！

### 本讲提到的题目

在本次课堂中，讲师围绕有限状态机的构建与推导，给出了一个完整的工程设计实例分析题。

#### 题目：连续三个 1 序列检测器的状态追踪与硬件实现

**【题干描述】**

我们需要设计一个能够检测串行输入序列中“连续三个 1”的有限状态机。系统在复位后从状态 $S_0$（$00_2$）出发。假定系统接收到如下输入的二进制比特流：
$$\text{In} = [0, 1, 0, 1, 1, 1, 0]$$
请给出：
1. 系统在每个时钟周期的状态变迁路径与输出比特流序列；
2. 解释为何状态机在捕获到目标序列后，必须返回状态 $S_0$。

**【解析与参考答案】**

1. **时钟步长追踪分析**：

我们将系统从复位状态出发的每一步演变进行严格追踪推演：

- **第 1 步**：当前状态 $S_0$（已见 0 个 1），输入 $\text{In} = 0$。根据转移规则，保持状态 $S_0$，输出 $\text{Out} = 0$。
- **第 2 步**：当前状态 $S_0$，输入 $\text{In} = 1$。系统观察到首个 1，转移到状态 $S_1$，输出 $\text{Out} = 0$。
- **第 3 步**：当前状态 $S_1$，输入 $\text{In} = 0$。连续性被 0 打断，系统转移回状态 $S_0$，输出 $\text{Out} = 0$。
- **第 4 步**：当前状态 $S_0$，输入 $\text{In} = 1$。再次观察到首个 1，转移到状态 $S_1$，输出 $\text{Out} = 0$。
- **第 5 步**：当前状态 $S_1$，输入 $\text{In} = 1$。观察到第二个连续 1，转移到状态 $S_2$，输出 $\text{Out} = 0$。
- **第 6 步**：当前状态 $S_2$，输入 $\text{In} = 1$。当前已累计两个 1，此时再次输入 1，成功达成连续三个 1 的判定条件！系统在此刻触发输出 $\text{Out} = 1$，同时转移回状态 $S_0$。
- **第 7 步**：当前状态 $S_0$，输入 $\text{In} = 0$。保持状态 $S_0$，输出 $\text{Out} = 0$。

综合以上推演，系统产生的完整输出序列为：
$$\text{Out} = [0, 0, 0, 0, 0, 1, 0]$$

2. **状态归位原因解析**：

在第 6 步达成“连续三个 1”并输出有效脉冲 1 之后，状态机必须返回初始状态 $S_0$，其核心原因在于设计语义中要求“不重叠计数”。系统已经将前三个 1 作为一个完整的检测事件消耗并报喜完毕，必须清零计数器重新开始寻检下一组全新的三连 1。如果停留在 $S_2$，后续紧接着再来一个 1 就会被误判为另一组新的三连 1，破坏了离散事件的独立性定义。
