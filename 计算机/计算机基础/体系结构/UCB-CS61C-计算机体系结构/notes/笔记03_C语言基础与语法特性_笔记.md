# C语言基础与语法特性

## 计算机体系结构基础

* **物理重构编程（Patch-cord Programming）**
    * > **定义**：早期计算机通过人工插拔线缆、改变电路物理连线及拨动开关来设定程序逻辑的编程方式。

* **存储程序概念（Stored-Program Concept）**
    * > **定义**：将程序指令与待处理数据统一编码为二进制，存放在同一内存空间中，使程序逻辑不再依赖物理接线。

---

## C语言的抽象定位

* **高级语言（High-Level Language）**
    * > **定义**：在 CS61C 体系中，C 语言被视为高级语言，因为它屏蔽了机器指令、通用寄存器分配及跳转偏移量的手动管理。
    * 核心特性：提供对硬件的直接映射与底层控制，同时具备跨平台可移植性。

---

## 编译流水线与构建原理

* **编译（Compilation）**
    * > **定义**：将源代码直接翻译为特定硬件架构（ISA）机器码的过程。
    * 流程：分为编译（生成 `.o` 目标文件）与链接（生成可执行文件）两个阶段。
    * 增量构建：利用 Makefile 等工具通过时间戳追踪依赖，仅重新编译发生变动的源文件，无需全量重编。
    * 性能瓶颈：链接阶段是无法拆分的串行过程，受阿姆达尔定律（Amdahl's Law）制约。

* **目标文件（Object File）**
    * > **定义**：编译器生成的包含机器指令的中间产物，其中的外部函数调用地址尚未解析。

---

## C预处理器（C Preprocessor，CPP）

* **预处理指令**
    * > **定义**：在正式编译前，对源代码进行纯文本替换、展开与条件过滤的机制。
    * 机制：`#include` 执行文本拷贝；`#define` 执行全局文本替换；`#ifdef` 实现条件编译。

* **宏函数（Macro Function）**
    * > **易错点**：**带副作用表达式的多次求值陷阱**：宏函数在预处理阶段进行纯文本替换，若参数包含函数调用或自增自减操作，且在宏定义中被多次引用，会导致副作用被重复触发。

---

## C语言核心语法与避坑指南

* **布尔逻辑（Boolean Logic）**
    * > **规则**：0 代表假（False），唯有 0 代表假；其余一切非 0 值均代表真（True）。
    * 建议：使用 `<stdbool.h>` 引入 `bool`、`true`、`false` 关键字以增强可读性。

* **定长整型（Fixed-width Integers）**
    * > **定义**：为解决不同硬件架构下 `int` 等类型位宽不一致的问题，使用 `<stdint.h>` 定义的明确位宽类型（如 `int32_t`、`uint64_t`）。
    * 边界：`sizeof` 返回的是字节数（Bytes），而非比特位数（Bits）。

* **控制流（Control Flow）**
    * > **易错点**：**无括号 if 的缩进错觉**：C 语言中缩进无语义，省略花括号的 `if` 仅管辖紧随其后的第一条语句。
    * 规则：`switch-case` 具有穿透（Fall-through）特性，除非显式使用 `break`，否则会执行后续分支。
    * 规则：循环计数器严禁使用浮点数，以避免二进制舍入误差导致的死循环或偏差。
    * 规则：严禁在常规业务代码中使用 `goto` 语句。

* **main函数与返回码**
    * > **定义**：Unix 状态码哲学规定，进程返回 0 代表成功，非 0 值代表各种异常原因。
    * 参数：`argc` 为参数总数，`argv` 为参数字符串数组，`argv[0]` 为程序自身名称。

## C与Java对比

| 维度 | Java | C语言 |
| :--- | :--- | :--- |
| **核心范式** | 面向对象（OOP） | 面向过程 / 函数驱动 |
| **内存管理** | 自动垃圾回收（GC） | 手动管理（Manual Allocation） |
| **编译输出** | 平台无关字节码 | 硬件特定机器码 |
| **预处理器** | 无 | 强力文本替换（CPP） |
| **位运算** | 支持 | 原生深度支持 |

* **结构体（Struct）**
    * > **定义**：将不同类型数据字段打包的复合数据结构，通过 `typedef` 可定义类型别名。
    * 特性：内存布局紧凑，无面向对象开销。
