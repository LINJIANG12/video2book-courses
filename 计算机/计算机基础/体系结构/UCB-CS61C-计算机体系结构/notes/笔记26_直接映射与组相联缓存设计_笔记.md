# 直接映射与组相联缓存设计

## 直接映射缓存

* **直接映射缓存（Direct-Mapped Cache）**

    * > **定义**：主内存中的每一个内存地址，在缓存中都严格对应唯一确定的存放槽位，硬件层面物理去处被绝对锁定。

    * 映射规则：缓存行号由内存地址模缓存总行数决定（`Address mod Cache_Lines`）。

    * > **易错点**：由于多个内存地址映射至同一缓存行，单凭数据本身无法分辨来源，必须依赖标签（Tag）进行区分。

* **空间局部性（Spatial Locality）**

    * > **定义**：程序在读取某个内存地址后，极大概率会在短时间内读取其相邻的物理地址。

    * 块大小（Block Size）设定：为了利用空间局部性，系统以“块”为单位进行数据搬运，而非单字节。

## 寻址机制与 T-I-O 结构

* **T-I-O 寻址划分**

    * > **定义**：将物理地址自右向左划分为三个功能域：块内偏移（Offset）、行索引（Index）、标签（Tag）。

    * 寻址顺序：先通过 Index 定位物理行，再比对 Tag 验证真伪，最后通过 Offset 提取目标字节。

* **寻址参数计算**

    * 假设系统地址宽度为 $A$ 位，缓存总容量为 $C$ 字节，块大小为 $B$ 字节：

    * 块内偏移（Offset）：$k = \log_2(B)$ 位。

    * 缓存行索引（Index）：$m = \log_2(C/B)$ 位。

    * 标签位（Tag）：$t = A - m - k = A - \log_2(C)$ 位。

    * > **提示**：标签位大小仅由系统地址宽度与缓存总容量决定，与块大小无关。

## 硬件实现细节

* **有效位（Valid Bit）**

    * > **定义**：缓存行中额外配置的单比特位，用于标识该行是否已载入合法数据。

    * 作用：开机时强制重置为 0，防止 CPU 将缓存中的随机电子噪声误判为合法数据。

    * > **易错点**：不能使用全 0 作为空闲标记，因为地址 0 是合法的物理内存地址。

* **写策略（Write Policy）**

    * 写直达（Write-Through）：每次写入缓存时同步更新主内存，保证一致性，但延迟高。

    * 写回（Write-Back）：仅更新缓存副本并标记为“脏（Dirty）”，仅在块被替换时才写回主内存。

## 性能度量与运行状态

* **核心性能指标**

    * 命中率（Hit Rate）：成功在缓存中找到数据的请求占比。

    * 未命中率（Miss Rate）：未命中的请求比例，满足 `Hit Rate + Miss Rate = 1`。

    * 命中时间（Hit Time）：在缓存中完成数据提取所需的时间（通常 1-2 个时钟周期）。

    * 未命中惩罚（Miss Penalty）：从主存拉取数据并替换至缓存所需的额外开销（几十至上百个时钟周期）。

* **缓存温度哲学**

    * 冷缓存（Cold Cache）：开机瞬间，所有 Valid 位为 0，未命中率 100%。

    * 升温（Warming Up）：数据持续载入，命中率稳步爬升。

    * 热缓存（Warm / Hot Cache）：程序进入高频循环，数据常驻片上，命中率趋近峰值。

---

## 性能优化策略

* **循环分块（Cache Blocking / Tiling）**

    * > **定义**：通过预知缓存容量，将大规模数据（如矩阵）拆解为能完全装入缓存的微型子块进行处理。

    * 效果：将空间与时间局部性压榨到极致，避免反复访问主内存，可实现数倍至数十倍的性能提升。

* **块大小与命中率的边界**

    * > **易错点**：在缓存总容量固定的前提下，盲目增大块大小可能导致命中率下降。

    * 原因：块大小翻倍会导致缓存总行数减半，若程序存在跨步访问（Stride Access），会导致各次访问剧烈竞争同一缓存行，引发连续冲突颠簸（Thrashing）。 ⚠️
