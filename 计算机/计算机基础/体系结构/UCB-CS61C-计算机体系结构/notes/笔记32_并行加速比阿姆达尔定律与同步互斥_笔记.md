# 并行加速比阿姆达尔定律与同步互斥

## 并行循环约束

### 循环拆分与结构准则

*   **循环拆分原则**
    *   OpenMP 将循环迭代范围整齐地对半切分给各线程，而非交错分配。
    *   目的：最大化利用缓存的空间局部性，减少总线带宽拥堵。

*   **结构化约束**
    *   应保持单层顶级并行结构，避免多层嵌套循环带来的复杂调度开销。
    *   在 `#pragma omp parallel for` 区域内，严禁使用 `break`、`return`、`exit` 或 `goto` 等指令提前退出。

    *   > **易错点**：强行提前跳出会破坏 OpenMP 隐式构建的线程汇聚屏障（Barrier）和运行期控制流，导致程序异常终止或段错误。

## 硬件同步机制

### 原子内存操作（Atomic Memory Operations，AMO）

*   **原子读-修改-写（Atomic Read-Modify-Write）**
    *   定义：将读取、运算、写回三个流水线步骤封装为不可分割的单一硬件指令，执行期间锁定内存位置。
    *   机理：RISC-V 通过 `amoadd.w` 等指令实现，防止多核心并发执行时的交错覆写。

*   **硬件自旋锁（Spinlock）**
    *   定义：利用原子交换指令 `amoswap.w` 实现的互斥锁。
    *   规则：
        *   `.aq`（Acquire）：确保后续内存读写不被乱序调度到加锁之前。
        *   `.rl`（Release）：确保先前内存读写不被乱序调度到释放锁之后。
    *   机理：核心通过原子交换尝试将锁变量置为 1，若读回旧值为 0 则成功持锁，否则原地自旋等待。

    *   > **易错点**：不能使用普通的加载（`lw`）和存储（`sw`）指令实现自旋锁，因为无法保证读写过程的原子性，会导致多个核心同时判定锁为空闲。

## 同步抽象与性能度量

### OpenMP 同步方案

*   **显式锁机制**
    *   使用 `omp_lock_t` 类型，通过 `omp_set_lock` 获取锁，`omp_unset_lock` 释放锁。

*   **临界区指令**
    *   使用 `#pragma omp critical` 声明代码块，保证同一时间仅有一个线程进入，避免手动管理锁的风险。

### 挂钟时间度量

*   **计时函数**
    *   `omp_get_wtime()`：返回自固定参考点起流逝的绝对物理秒数。
    *   规则：采用双采样求差法（`end_time - start_time`）精确评估并行程序的实际加速比。

## 并发死锁与活锁

### 僵局与徒劳循环

*   **死锁（Deadlock）**
    *   定义：多个并发参与者因争夺共享资源而陷入相互等待，导致系统永久停滞。
    *   典型模型：哲学家就餐问题，即所有参与者同时持有部分资源并等待对方释放剩余资源。

*   **活锁（Livelock）**
    *   定义：参与者在高速改变自身状态，但始终无法取得实质进展的循环状态。
    *   机理：参与者按照对称算法不断尝试避让，导致系统消耗大量资源却处于无效运动中。

## 缓存一致性协议

### 对称多处理器（SMP）架构

*   **架构特征**
    *   各 CPU 核心拥有私有 L1/L2 缓存，通过互连总线访问共享主内存。
    *   主内存访问延迟极高，私有缓存用于提升执行速度。

*   **窥探协议（Snooping Protocol）**
    *   机理：缓存控制器监听总线上的广播信号，实时感知其他核心对共享内存的访问意图，确保缓存副本的一致性。

### MOESI 状态机

*   **状态定义**
    *   **Modified (M)**：独占最新脏数据，其他核心必须为 Invalid。
    *   **Owner (O)**：持有最新脏数据，允许其他核心持有 Shared 副本，负责响应读请求。
    *   **Exclusive (E)**：独占最新干净数据，与主存同步。
    *   **Shared (S)**：只读副本，允许多核心共存。
    *   **Invalid (I)**：数据无效，访问触发未命中。

    *   > **提示**：Owner 状态允许核心直接将数据递送给其他核心，完全绕过主内存，显著降低延迟。

## 性能瓶颈与 4C 模型

### 伪共享（False Sharing）

*   **定义**
    *   逻辑上独立的变量因处于同一个物理缓存块（Cache Line）内，导致核心间频繁触发缓存失效与乒乓效应。
*   **规避手段**
    *   使用数据填充（Padding）或对齐（Alignment）技术，强制将频繁并发写入的变量隔离在不同的缓存块中。

### 缓存未命中分类

*   **4C 模型**
    *   **强制未命中（Compulsory）**：首次访问内存块。
    *   **容量未命中（Capacity）**：工作集超出缓存物理容量。
    *   **冲突未命中（Conflict）**：映射规则导致多个块竞争同一缓存组。
    *   **一致性未命中（Coherence）**：因其他核心的写入操作，导致本地缓存副本被强制置为 Invalid。

    *   > **注意**：在现代多核系统中，一致性未命中往往是制约并行扩展性的主要瓶颈。 ⚠️
