# 流水线结构冒险与数据冒险处理

## 流水线硬件修正

* **PC+4 优化（PC+4 Optimization）**
    * > **定义**：通过在写回（WB）阶段增加专用加法器，取代贯穿流水线的 PC+4 信号线。
    * 机理：在流水线主干中仅传递当前 PC，仅在 WB 阶段需要写入返回地址时计算 PC+4，减少三个 32 位流水线寄存器的硬件开销。

* **控制逻辑流水化（Control Logic Pipelining）**
    * > **定义**：将控制信号随指令流水线同步传递，确保同一时刻五条指令的控制信号互不干扰。
    * 方案 A（指令流水化）：将 32 位指令机器码随流水线传递，各阶段配备专职控制逻辑。
    * 方案 B（控制信号流水化）：在 ID 阶段一次性解码所有控制信号，打包放入流水线寄存器，随指令推进逐级消耗。

* **寄存器写回索引（Register Write Index）**
    * > **易错点**：写回寄存器目标索引 `rd` 绝不能直接取自当前 ID 阶段的指令字段，必须随指令流通过流水线寄存器（ID/EX → EX/MEM → MEM/WB）同步传递，在 WB 阶段从 MEM/WB 寄存器引出。⚠️

## 结构冒险与规避

* **结构冒险（Structural Hazard）**
    * > **定义**：多条指令在同一时钟周期内争抢同一不可分割的物理硬件资源。
    * 应对途径：停顿（Stall）、增加硬件资源、指令集架构与微架构协同规避。

* **寄存器堆端口约束（Register File Port Constraint）**
    * 规则：RISC-V 规定通用寄存器堆必须具备两个独立读端口和一个独立写端口，确保单周期内完成两次读取与一次写入，规避读写冲突。
    * 边界：RISC-V 指令集不支持三源操作数指令（如 `rs3`）或双目标寄存器指令，从架构层面杜绝了端口需求超限的可能。

* **内存访问冲突（Memory Access Conflict）**
    * 机理：IF 阶段取指与 MEM 阶段访存若共享物理内存，将产生结构冲突。
    * 解决方案：采用哈佛结构（Harvard Architecture）的分离式一级缓存（Split L1 Cache），通过指令缓存（I-Cache）与数据缓存（D-Cache）在物理层面实现 IF 与 MEM 的并行访问。

## 数据冒险与识别

* **数据冒险（Data Hazard）**
    * > **定义**：后续指令在执行或译码时需要使用操作数，但产生该操作数的前序指令尚未完成计算或写回，导致读取到过时数据。
    * 典型类型：写后读相关（Read-After-Write, RAW）。

* **数据依赖识别（Data Dependency Detection）**
    * 规则：扫描前序指令的写入目标 `rd` 与后续指令的源操作数 `rs1`/`rs2`。
    * 判定：绘制流水线时空网格图，若读取周期早于或等于写入周期，且硬件未加干预，则判定为数据冒险。

* **时序边界（Timing Boundary）**
    * > **提示**：同一周期内“写后即读”是否构成冒险，取决于寄存器堆的硬件规格。支持内部透传（前半周期写、后半周期读）的寄存器堆不构成冒险；普通触发器阵列则构成冒险。

## 数据冒险的解决机制

* **硬件停顿（Stall / Bubble）**
    * 机理：通过冒险检测单元（Hazard Detection Unit）冻结 PC 和 IF/ID 寄存器，向 ID/EX 寄存器注入全零控制信号（气泡），强行推迟后续指令的执行。
    * 性能代价：导致流水线 IPC（每周期指令数）下降，但保证了程序执行的正确性。

* **数据转发（Forwarding / Bypassing）**
    * > **定义**：在数据产生阶段（如 EX 阶段末尾）通过专用旁路导线，将结果直接送入后续指令的 ALU 输入端，无需等待写回寄存器堆。
    * 转发控制逻辑：需核验写使能（RegWEn）、目标寄存器非零（`rd != 0`）且编号匹配。

* **加载-使用冒险（Load-Use Hazard）**
    * > **定义**：`lw` 指令在 MEM 阶段末尾才读出数据，而紧随其后的指令在 EX 阶段就需要该数据，无法通过纯转发解决。
    * 解决方案：硬件强制停顿一拍（插入一个气泡），配合 MEM-to-EX 转发旁路，将数据在下一周期直接送入 ALU。

* **代码调度（Code Scheduling）**
    * 机理：编译器通过指令重排，将与当前计算无关的指令插入到存在依赖的指令之间，填补停顿空当，优化流水线吞吐率。
