# 并行计算模型与Flynn分类法

## 软硬件视角的交织与 Flynn 分类法

### 软件并发与硬件并行的正交性
*   **正交独立性**：软件的执行形态（顺序执行 vs 并发执行）与硬件的物理架构（串行硬件 vs 并行硬件）是两个相互独立的维度。
*   **分时共享（Time-sharing）**：单核硬件通过时钟中断在多个任务间高速切换，在宏观上模拟并发，但微观上同一时刻仅有一条指令处于活跃执行期。
*   **物理并行**：多核或超标量硬件具备多个物理执行通路，支持多个线程在物理层面同时执行。

### 弗林分类法（Flynn's Taxonomy）
*   **单指令单数据流（SISD）**：程序计数器线性推进，每个周期处理一对标量数据，为传统标量架构。
*   **单指令多数据流（SIMD）**：控制器取出一组指令，驱动多个并行运算单元，对打包的数据元素执行相同操作，即数据级并行（DLP）。
*   **多指令多数据流（MIMD）**：多个独立核心或线程各自读取指令并处理独立数据流，为现代多核与多线程架构。
*   **多指令单数据流（MISD）**：硬件具备多数据通路却处理单个标量数据，在通用体系结构中无实际应用。

## 数据级并行与向量化

### 向量化抽象
*   **声明式向量思维**：通过高阶抽象（如向量运算）替代显式的 `for` 循环，将标量时间维度的迭代转化为空间维度的并行吞吐。
*   **硬件诉求**：
    *   **锁步执行**：所有并行通道必须在同一控制信号下执行相同操作。
    *   **宽寄存器堆**：需设计超宽寄存器以容纳整批数据。
    *   **多端口访存**：需支持单周期内大位宽（128/256/512 位）的数据读写。

### 紧密打包（Packed）规则
*   **定义**：多个相同类型的数据元素在物理寄存器与内存中连续、严密排列，无任何填充空隙。
*   **数据类型匹配**：浮点向量计算中，每一位具有严格的 IEEE 754 数学语义，指令位宽与数据类型必须严格匹配，严禁混用。
    > **易错点**：⚠️ 不可将处理双精度的指令用于单精度数据，否则会导致符号位与尾数解释错误，造成计算结果崩塌。

### 内存对齐与边界处理
*   **内存对齐**：向量访存指令要求数据在内存中按向量宽度对齐。
*   **尾部处理**：当数组长度非向量宽度倍数时，SIMD 指令仍会读入完整向量宽度，需通过标量收尾循环处理有效元素，并确保多读出的垃圾数据处于合法的虚拟地址空间内，否则将触发段错误。

## 向量架构演进与编程接口

### x86 向量扩展史
| 扩展名称 | 寄存器位宽 | 32-bit 浮点容量 | 64-bit 浮点容量 |
| :--- | :--- | :--- | :--- |
| MMX | 64 位 | 2 个 | 1 个 |
| SSE | 128 位 | 4 个 | 2 个 |
| AVX | 256 位 | 8 个 | 4 个 |
| AVX-512 | 512 位 | 16 个 | 8 个 |

### C 语言内联函数（Intrinsics）
*   **定义**：编译器提供的 C 语言接口，在编译时直接展开为底层向量汇编指令。
*   **核心要素**：
    *   **专有数据类型**：`__m128`（128 位，4 个 float）、`__m128d`（128 位，2 个 double）、`__m128i`（打包整数）。
    *   **操作函数族**：如 `_mm_load_ps`（加载）、`_mm_add_ps`（加法）、`_mm_store_ps`（存储）。

### RISC-V 向量扩展（RVV）
*   **架构哲学**：坚持 RISC 的 Load-Store 架构，算术指令仅操作寄存器，访存由专门的向量加载/存储指令负责，流水线控制解耦。

## 性能与阿姆达尔定律

### 性能跃迁量化
*   **综合加速比**：从 Python 解释执行切换至纯标量 C 语言，性能提升约 240 倍；在此基础上引入 AVX 向量化，进一步提升约 4 倍；综合加速比可达约 1000 倍。

### 阿姆达尔定律（Amdahl's Law）
*   **公式**：$S_{\text{latency}} = \frac{1}{(1 - p) + \frac{p}{s}}$
    *   $p$：程序中可并行化的部分占比。
    *   $s$：并行化部分的加速倍数。
*   **边界**：程序中固有的串行代码段（如内存分配、入参检查）会限制整体加速比的上限。
    > **提示**：优化前应先确立基准，避免过早优化。
