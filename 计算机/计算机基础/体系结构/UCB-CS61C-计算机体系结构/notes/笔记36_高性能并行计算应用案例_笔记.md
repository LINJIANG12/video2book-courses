# 高性能并行计算应用案例

## 超级计算机架构与需求

* **分布式内存并行计算（Distributed-Memory Parallel Computing）**
    * > **定义**：将成千上万台高速计算节点通过极高带宽、极低延迟的互联网络紧密连接，协同求解超大规模科学与工程问题的计算模式。
    * 核心动因：解决单机无法承载的计算规模（尺度过大、过小、过快、过慢或极端危险）与内存容量瓶颈。
    * 内存墙困境：当计算规模超出单机物理内存时，若采用外存计算（Out-of-core Computing），频繁的页面置换会导致访存性能下降 3~5 个数量级。

* **并行计算架构形态**
    * **共享内存系统（Shared Memory）**：单一物理内存地址空间，通过总线或片上网络访问，受限于总线仲裁与缓存一致性协议，扩展规模通常在数百核以内。
    * **向量/单指令流系统（SIMD / SIMT）**：利用大容量片上高带宽显存，通过硬件锁步调度海量线程，典型代表为 GPU。
    * **分布式内存系统（Distributed Memory）**：节点间物理地址空间隔离，必须通过显式通信访问远程数据，支持扩展至上万节点。

* **节点间通信机制**
    * **消息传递接口（Message Passing Interface，MPI）**：发送端与接收端执行显式的匹配操作，通过网络协议栈完成数据打包与解包。
    * **远程直接内存访问（Remote Direct Memory Access，RDMA）**：利用专用网卡绕过内核，直接读写远程节点内存物理地址，将通信延迟压制在微秒级。

## 性能度量与基准测试

* **高性能线性方程组求解（High-Performance Linpack，HPL）**
    * > **定义**：Top500 榜单采用的核心基准测试，通过求解大规模稠密线性方程组 $Ax=b$（使用 LU 分解）衡量系统浮点性能。
    * 算法复杂度：时间复杂度为 $O(N^3)$，内存占用为 $O(N^2)$。
    * 算术强度：极高，能够充分利用数据局部性压榨处理器的峰值浮点性能。

* **超算架构演进**
    * **纯 CPU 架构（如富岳）**：依赖大规模节点堆叠与定制互联网络，节点规模可达 15.8 万个。
    * **异构架构（如 Frontier）**：CPU 与专用 GPU 协同，是实现百亿亿次（Exascale）计算的标配。
    * **融合 APU 架构（如 El Capitan）**：CPU 与 GPU 物理共封装，共享统一高带宽物理内存，显著提升计算密度。

## 科学计算范式与应用

* **科学探索四范式**
    * 第一范式：理论推导（Theory）。
    * 第二范式：物理实验（Experiment）。
    * 第三范式：数值模拟（Simulation）。
    * 第四范式：高性能数据分析（HPDA）。

* **自适应网格细化（Adaptive Mesh Refinement，AMR）**
    * > **定义**：根据流场剧烈程度与应力梯度动态分配网格密度的计算技术。
    * 边界：在平缓区域使用粗粒度网格，在界面或高应力区域动态加密，避免算力浪费。

* **宏基因组蛋白质家族识别**
    * 核心挑战：对 10 亿条蛋白质序列进行全量两两比对，计算复杂度约为 $5 \times 10^{17}$ 次。
    * 优化策略：利用稀疏矩阵倒排索引与 k-mer 剪枝算法，过滤掉 >99.999% 的无效配对。
    * 图聚类实现：将蛋白质相似度图的聚类规约为分布式稀疏矩阵乘法（SpGEMM），利用马尔可夫聚类算法（MCL）在万卡规模 GPU 集群上完成全局计算。

## AI 与极端科学计算

* **AI 算力与精度降维**
    * > **注意**：Top500 强制使用 64 位双精度（FP64）打分，而深度学习算法可运行在半精度（FP16/BF16）或更低精度（FP8/INT4）下。
    * 性能差异：低精度模式下的“AI-Flops”吞吐量可达 FP64 的数倍乃至数十倍，使得实际科学任务中的应用性能可能显著超越榜单峰值。

* **团队科学（Team Sport）**
    * 现代超算应用需垂直打通底层硬件、网络协议、数学解法器与顶层应用领域，依赖物理学家、工程师与计算科学家的跨学科协作。
