# 硬件多线程与多核并行

## 算力提升路径与并行层级

* **算力提升的三条路径**
    * 提高时钟主频（Clock Rate）：受限于功耗与散热极限，已触及 5GHz 物理天花板。
    * 降低每指令时钟周期数（CPI）：通过 SIMD 技术实现数据级并行。
    * 任务级与线程级并行（TLP）：通过多核架构并发执行不同任务。

* **硬件并行层级**
    * 位级并行（Bit-Level Parallelism）：逻辑门在单脉冲内对多位数据执行运算。
    * 指令级并行（Instruction-Level Parallelism, ILP）：通过流水线重叠执行多条指令。
    * 数据级并行（Data-Level Parallelism, DLP）：利用 SIMD 向量寄存器在单周期内处理整组数据。
    * 线程级并行（Thread-Level Parallelism, TLP）：多物理核心独立调度并执行不同指令流。

## 多核体系结构与共享内存模型

* **多核微处理器（Multicore Microprocessor）**
    * > **定义**：在单芯片上集成多个物理核心，共享系统主存与 I/O 接口的计算架构。
    * 核心资源：每个核心拥有独立的控制逻辑、数据通路、程序计数器（PC）、寄存器堆及算术逻辑单元（ALU）。
    * 缓存层次：L1 与 L2 缓存为核心私有，L3 缓存为所有核心共享。
    * > **易错点**：核心数量翻倍不代表内存容量翻倍，核心与内存是物理上分离的部件。

* **共享内存模型（Shared Memory Model）**
    * 通信机理：核心通过读写内存中的共享变量或数组进行通信，无需封包拆包。
    * 性能瓶颈：主存 DRAM 访问延迟高，且多核频繁访问同一内存区域会导致总线竞争与缓存一致性同步开销。

## 功耗墙与多核时代的降临

* **物理功耗墙（Power Wall）**
    * 动态功耗公式：$P \propto C \cdot V^2 \cdot f$（$C$ 为电容，$V$ 为电压，$f$ 为频率）。
    * 2005 年转折点：处理器主频在 3-5GHz 区间受限，单核性能增长停滞，算力提升动力转向核心数量扩张。

* **多核演进趋势**
    * 摩尔定律：晶体管密度持续翻倍，多余晶体管被用于堆砌计算核心。
    * 异构计算：现代 SoC 集成高性能核心、能效核心、GPU、神经网络引擎及图像处理器。
    * 性能增益：核心数量与 SIMD 位宽的叠加，使每周期浮点运算总量持续增长。

## 线程与分时复用

* **线程（Thread）**
    * > **定义**：操作系统能够调度执行的单一指令执行流序列。
    * 分时复用（Time-Slicing）：单核 CPU 通过在极短时间片内轮流切换不同线程，实现宏观上的并发执行。
    * 守护进程（Daemon）：在后台常驻运行，负责监听硬件事件、网络请求等任务的进程。

* **上下文切换（Context Switch）**
    * 触发条件：阻塞事件（如访存未命中、I/O 等待）或定时器中断。
    * 切换机理：将当前线程的 PC 与寄存器堆保存至内存，加载新线程的状态并跳转执行。
    * 性能代价：频繁切换会占用大量访存带宽与处理器周期，导致算力内耗。

## 硬件线程与超线程技术

* **硬件线程（Hardware Thread / 逻辑 CPU）**
    * 物理核心：芯片上真实的计算单元。
    * 逻辑 CPU：硬件提供的独立执行实体，操作系统据此进行任务调度。

* **同时多线程（Simultaneous Multi-Threading, SMT）**
    * > **定义**：在物理核心内复制多套架构状态（PC 与寄存器堆），共享执行单元与缓存的硬件辅助技术。
    * 性能机理：利用另一线程的指令填补流水线中因访存延迟或资源空闲产生的“气泡”，提升指令吞吐率。

* **架构特性对比**

| 维度 | 物理多核（Multicore） | 超线程（SMT） |
| :--- | :--- | :--- |
| **硬件复制范畴** | 完整计算核心 | 仅架构寄存器与 PC |
| **芯片面积开销** | 极大 | 极小（1%-5%） |
| **吞吐量增益** | 接近翻倍 | 10%-30% |
| **操作系统视角** | 多个物理 CPU | 多个逻辑 CPU |

* > **提示**：若软件无法并行化，盲目增加核心数可能因频率下调导致性能下降；多核与超线程的优势仅在任务能细粒度拆分时体现。

## 并行编程的本质挑战

* **非确定性（Nondeterminism）**
    * 并发执行受时钟抖动、缓存命中、中断与散热调频等随机因素影响，导致执行轨迹不可预测。
    * 编程挑战：需通过互斥锁、信号量与同步栅栏等机制，在非确定性环境中修剪出确定性的业务逻辑。

* **负载不均（Load Imbalance）**
    * 任务切分过粗会导致部分核心空转；切分过细会增加调度开销。
    * 工程目标：在任务池细粒度划分与调度开销之间寻找执行时间的最低拐点。
