## 快速选择与快速幂：分而治之的两次提速
> 对应块：BLK36 | 覆盖分集：P154-P158 | 块标题（分集名）：《进阶数据结构和算法-308-快速选择算法-分治》

先看一个再朴素不过的问题。

现在给你一个数组 `[1, 2, 4, 5, 6]`，里面的数字大小都是打乱的。我要求排在第二名的元素是谁？

这个不用想，眼睛扫一遍就知道：最小的 1 排第 0 名，2 排第 1 名，那第 2 名就是 4。只要能把 4 返回出来，就算工作正确。

方法签名也简单：

```java
quick(int[] arr, int left, int right, int i)
//                        ↑        ↑         ↑
//                     起始索引  结束索引   要的排名
// 返回值就是排名 i 下的那个元素
```

注意这个 `i` 是从 0 开始的排名，不是"第几个"。

### 一个偷懒的答案，和它的账单

有同学说，这题太容易了——把整个数组排个序呗。

```text
排序前:  [ 1 , 2 , 4 , 5 , 6 ]
排序后:  [ 1 , 2 , 4 , 5 , 6 ]   下标 0 1 2 3 4
                                排名 0 1 2 3 4
```

排好序之后，数组的下标就是排名。找排名 2 的，直接返回 `arr[2]`，也就是 4。实现起来太容易了：

```java
Arrays.sort(arr);
return arr[i];
```

跑一遍验证，五个排名全对：找第 0 名返回 1，第 1 名返回 2，第 2 名返回 4，第 3 名返回 5，第 4 名返回 6。结果没问题。

但是我们都知道，排序的时间复杂度是 $O(N \log N)$。那能不能找一个复杂度更低的算法，只把第 2 名捞出来，顺便把其他名次全排了？

这里就有点亏了——为了一个元素，我们把整个数组都整理了一遍。

### 从快排借来的一次划分

思路我们可以借鉴快速排序里基准点的做法。

选一个基准点元素，比如就选最右侧这个元素。然后把比基准点小的都交换到它左边，把比基准点大的都交换到它右边。

```text
              基准点（选最右侧那个元素）
                        |
        <--- 都比它小 ---+--- 都比它大 --->
```

这一轮操作走完以后，能得出的结论是：**基准点元素的位置确定好了**。

左边全是比它小的，右边全是比它大的，两边各自内部的顺序我们并不在乎——不在乎正好，这就是我们要的效果。

打个比方，这一轮走完基准点落在了下标 2 上，而我们正好要排名 2 的元素，那直接返回它就完事了：

```text
第一轮划分之后

   [ 都小于基准点 ][ 基准点 ][ 都大于基准点 ]
         用不着管        ↑          { 5, 6 }
                     落在下标 2

   要排名 2 →  基准点就在下标 2，直接返回
   要排名 3 →  只在 { 5, 6 } 这个范围里继续找，左边那半截再也不用管
```

为什么左边可以不管？左边那些元素都比基准点小，将来排名只可能是 0、1，不可能突然蹦出个 3、4 来。所以要找排名 3，只要到它右侧的区间去就行——查找范围一下子少了一半。

在那半截里继续做同样的事：还是选最右侧元素当基准点，还是把小的甩左边、大的甩右边。走完一轮，5 被交换到了它该在的位置，落在下标 3——排名 3。命中，返回。

```text
只在 { 5, 6 } 里再划分一轮

   [ 都小于 5 ][ 5 ][ 都大于 5 ]
                   ↑
              落在下标 3 = 排名 3  → 返回
```

总之规律就一条：**每查找一次，范围缩小一半**。这个算法就叫快速选择算法，它用的显然也是我们分而治之的思想。

那时间复杂度是多少？第 1 轮扫 $n$ 个元素，第 2 轮最多扫 $n/2$，第 3 轮最多扫 $n/4$……加总是一个等比数列：$n + n/2 + n/4 + \cdots < 2n$，所以是 $O(N)$，比我们排序的 $O(N \log N)$ 整整快一个量级。

### 快速选择的骨架：只往一半走

思路清楚了，接下来落地。算法里要用的"选基准点""确定基准点位置"这些代码，我们写快速排序的时候都写过——说白了就是那个 partition 分区方法，这里就不用从头再写一遍了，直接把快速排序代码里的 partition 拿过来，它还会用到的 swap 也一块拿过来。

partition 里干的事就是我们上面描述的那一套：

```java
// 随机选一个基准点，避免划分不均
int p = left + (int) (Math.random() * (right - left + 1));
swap(arr, p, right);
int base = arr[right];

// 把比基准点小的交换到它左边
int less = left;
for (int cur = left; cur < right; cur++) {
    if (arr[cur] < base) {
        swap(arr, less, cur);
        less++;
    }
}
// 把比基准点大的交换到它右边

swap(arr, less, right);
return less;   // 返回基准点元素最终所在的下标
```

> **提示**：这里为什么用随机基准点？因为如果你老是固定选最右侧的元素作为基准点，有可能导致划分不均匀——运气差的时候，每次切出来的一边几乎都是空的，分治就退化成蛮力遍历了。随机挑能让这种糟糕情况变得很难连续发生。

外面这一层 `quick` 就更简单了，一上来先调用 partition，四个参数原样传进去：数组、左边界、右边界。

partition 返回的结果代表什么？**就是基准点元素最终所在的索引值**，而且这时候它在这个数组里的正确位置已经定死了。于是分三种情况：

```java
public static int quick(int[] arr, int left, int right, int i) {
    int p = partition(arr, left, right);

    if (p == i) {
        // 基准点的下标正好等于我们要的排名，直接返回这个元素
        return arr[p];
    } else if (i < p) {
        // 排名比基准点靠前，去左边找
        return quick(arr, left, p - 1, i);
    } else {
        // 排名比基准点靠后，去右边找
        return quick(arr, p + 1, right, i);
    }
}
```

这里最容易搞错的是递归传参的那个边界。左边的区间是**从这次的 `left` 到基准点减一**；右边的区间是**从基准点加一到这次的 `right`**。别写反，也别忘了 `i` 一样要往下传。

至于"到左边找"和"到右边找"这两段逻辑，一模一样——都是调用 `quick` 自己，区别只在参数范围。所以直接递归调用就完了。

跑一遍，结果还是对的：1、2、4、5、6 分别能被各自的排名找到。快速选择算法到这儿就算讲完了。

### 换个排名口径：数组第 K 大

我们拿快速选择去解决一道之前做过的题：**求数组中第 K 大的元素**。

这道题我们在讲堆的时候做过，当时的思路是：先把前 K 个元素放进一个**小顶堆**，然后循环遍历剩余的元素，跟堆顶比较——如果它比堆顶还小就跳过，遇到比堆顶大的，就用它替换掉堆顶。这样做的目的是让小顶堆里始终保留着当前最大的那 K 个元素，循环一结束，堆顶就是第 K 大的元素。

思路是对的，但堆解法是 $O(N \log K)$ 量级，每来一个新元素都要跟堆顶比一次、必要时还要调整堆。今天我们用快速选择把它进一步降到 $O(N)$。而且这是一道力扣题，你放到力扣上去跑，快速选择的得分也会比堆解法高一些。

不过这道题跟我们前面举的例题有个区别，得先理清楚。

前面那个例子里，排名是**由小到大**排的，而且**从 0 开始**；这道题要的是第 K 大，也就是**由大到小**排，而且**从 1 开始**。方向反了，编号也反了。

还是拿 `[1, 2, 4, 5, 6]` 这几个数字，我们把它两套排名摆在一起对一下：

| 由大到小的排名 K | 元素 | 对应由小到大的排名 = 5 - K |
| :--- | :--- | :--- |
| 1 | 6 | 4 |
| 2 | 5 | 3 |
| 3 | 4 | 2 |
| 4 | 2 | 1 |
| 5 | 1 | 0 |

规律一眼就看出来了：**用数组长度减去现在的由大到小排名，就得到原来由小到大那个排名**。

- 要现在的第 1 名（6），$5 - 1 = 4$，就是求原来的第 4 名；
- 要现在的第 2 名（5），$5 - 2 = 3$，就是求原来的第 3 名；
- 要现在的第 3 名（4），$5 - 3 = 2$，就是求原来的第 2 名。

把这个对应关系理清楚，代码就不用重头写了——直接拿例题里的 `quick` 来调用，把参数传对就行：

```java
public int findKthLargest(int[] nums, int k) {
    return quick(nums, 0, nums.length - 1, nums.length - k);
}
```

第一个参数是数组，第二、第三个参数是左右边界，分别是 `0` 和 `数组长度 - 1`。最后那个参数就是 `数组长度 - k`，因为它内部要的是"由小到大、从 0 开始"的排名。剩下的代码一个字都不用改。

来跑一个测试用例：数组无序 `[2, 3, 1, 5, 6, 4]`，求第 2 大的元素。6 是第 1 大，5 是第 2 大，所以答案应该是 5。跑出来结果正确。

> **注意**：这不是说小顶堆没用。小顶堆在**数据流**里求第 K 大元素特别好用，因为数据是一波一波来的，堆可以边收边维护；而快速选择要求整个数组已经摆在内存里了，它**不能应用于数据流**，只能解数组里的静态数据。两者适用的是不同的场景，按场景挑工具。

### 中位数就是"中间那个排名"

再来看一个跟中位数相关的题目。

先把概念捋一遍。如果是**奇数**个数字，把它们排个序，中间那个数字就是中位数。比如 `1, 4, 5` 中间是 4；`1, 3, 4, 5, 6` 中间还是 4，所以中位数是 4。

如果是**偶数**个，那就取中间的两个数字求平均值。比如 `1, 2, 3, 4, 5, 6` 中间是 3 和 4，平均下来就是 3.5。

之前我们也做过一道力扣题叫《数据流的中位数》，当时用的是大顶堆加小顶堆。今天这道是**数组中的中位数**，它不需要那么复杂，一个快速选择算法就够了。

为什么？因为**中位数问题本质上就是一个求排名的问题**。我们前面已经能用快速选择求出排名 `i` 的元素了，而中位数不就是"排在中间排名上的那个元素"嘛。所以只要能算出中间的排名是几，就能进一步求出那个元素。细节上分奇偶两种情况处理一下就行。

#### 奇数个数字

先把数字个数拿过来，`len % 2 == 1` 就是奇数的情况。

数字个数是 3 的时候，排名是 0、1、2，中间的排名就是 1；数字个数是 5 的时候，排名是 0 到 4，中间的排名就是 2。规律很清楚：**中间的排名就是 `数组长度 / 2`**（注意排名是从 0 开始的）。

知道要求哪个排名了，套前面那个快速选择就行：

```java
if (len % 2 == 1) {
    return quick(nums, 0, len - 1, len / 2);
}
```

测试一下：`[1, 4, 5]` 的中位数是 4，`[1, 3, 4, 5, 6]` 的中位数也是 4。两个都对，奇数的情况就分析完了。

#### 偶数个数字

偶数稍微复杂一点，我们得找到**两个**数字。

以个数是 4 来说，`4 / 2 = 2`，找到排名 2 上的是后面那个数字。但我们还要用它前面那个数字，所以还得再找一个，位置是 `4 / 2 - 1`。把这两个数找到，求个平均值就是答案了。

```java
double x = quick(nums, 0, len - 1, len / 2);         // 后面的数字
double y = quick(nums, 0, len - 1, len / 2 - 1);     // 前面的数字
return (x + y) / 2.0;
```

> **易错点**：这里必须除以 `2.0`，不能写成 `2`。因为两个整数相加之后还是整数，用 `2` 做除法就是整数除法，小数部分直接被舍弃掉了，中位数就永远不可能出现 `.5`。写成 `2.0` 才会转成小数除法。

跑一下看结果对不对：`[1, 2, 3, 4, 5, 6]` 中间是 3 和 4，平均值 3.5；`[1, 2, 3, 4, 5, 6]` 之外的另一个用例，中间是 4 和 5，平均值 4.5。一个 3.5，一个 4.5，都对。偶数情况就是找两个数、求平均，作为最终的中位数。

### 快速幂：把乘 16 次变成乘 4 次

来看一个经典问题：**快速幂**。

比如现在要求你写一个函数，功能是求 2 的 16 次方。

有同学说这简单呀，我们根据它的幂循环 16 次，把前面的 2 一个一个乘起来就行了：

```java
public double power(double x, int n) {
    double result = 1;
    for (int i = 0; i < n; i++) {
        result *= x;
    }
    return result;
}
```

最终要求的是小数，所以用 `double`，乘积的初始值是 1，循环 16 次，每循环一次就在这个基础上乘以 x，最后返回相乘的结果。

2 的 16 次方正确算下来应该是 65536，没问题吧？

但是同学们想一想，这样做好不好呢？这样做的时间复杂度是比较高的。比如现在 n 是 16，那相当于我一共要循环 16 次。有没有时间复杂度更低的做法？

#### 拆成一棵树

解决的方法就是采用**分治**的思想。

你看，2 的 16 次方，是不是可以拆成两个 2 的 8 次方？2 的 8 次方又可以拆成两个 2 的 4 次方，2 的 4 次方可以继续拆成两个 2 的 2 次方，最后 2 的 2 次方不就是两个 2 相乘吗。拆成一棵树大概是这样：

```text
                            2^16
                          /      \
                      2^8        2^8   ← 和左边对称，结果一样，不必再算
                     /   \
                 2^4     2^4         ← 同上
                /   \
            2^2     2^2             ← 同上
           /   \
         2      2
```

那拆完之后，总共需要几次乘法？我们自底往上看。

- 最底层，2 和 2 相乘得到 4——**第 1 次**。
- 但是注意，4 这个结果算出来了以后，跟它对称的左边那棵子树还需要再算一遍吗？不需要。因为我们一看这个数就是对称的，左边那棵子树的结果也肯定是 4。所以接下来只需要求解 4 × 4，得到 16——**第 2 次**。
- 16 × 16，得到 256——**第 3 次**。
- 整棵树的右侧子树结果都有了，左边那棵也肯定是 256，不用算。最后 256 × 256，得到最终结果 65536——**第 4 次**。

```text
        2 × 2      = 4       ← 第 1 次乘法
        4 × 4      = 16      ← 第 2 次乘法
       16 × 16     = 256     ← 第 3 次乘法
      256 × 256   = 65536   ← 第 4 次乘法
```

总共只需要乘四次就完了。刚才没用分治的时候我们一共乘了 16 次，用了分治之后只乘了 4 次，乘法的速度明显变快了。我们把这种做法称为**快速幂**。

#### 幂是奇数的时候

刚才那个例子是 2 的 16 次方，拆分过程中 16、8、4、2 都是偶数。那如果这个幂是奇数呢，需要特殊考虑一下。

比如 2 的 10 次方，可以拆成两个 2 的 5 次方。但 2 的 5 次方继续拆分的时候就不能平分 了，它可以看成是一个 2 再乘上 2 的 4 次方。2 的 4 次方接下来可以拆成两个 2 的 2 次方——**但是这个多出来的 2 我们不能把它丢掉**，将来你乘的时候得把它也算上去。

```text
      2^10 = 2^5 × 2^5
             2^5 = 2 × 2^4
                    2^4 = 2^2 × 2^2
                           2^2 = 2 × 2
```

所以规律是：**偶数的幂，两个结果直接相乘；奇数的幂，除了把两个结果相乘，还要再多乘一个 x**。这是解题时一定要注意的。

### 用递归把树写出来

从树状图其实就能猜出来，这道题用递归求解是比较方便的。

先看递归的终止条件。n 不断拆分，拆分到最后是不是就剩 2 的 1 次方了，也就是 n 等于 1 的时候——这种情况下直接返回 x 就可以了，这就是整个递归的终止条件。

那 n 不等于 1 呢？根据刚才的分析，有偶数和奇数两种情况，接下来判断一下 n 是偶数还是奇数就行。

写出来大概是这样：

```java
public double myPow(double x, int n) {
    if (n == 1) {
        return x;                       // 递归终止条件
    }
    if (n % 2 == 0) {
        // 偶数：拆成两个 n/2 的子问题，返回两者的乘积
        return myPow(x, n / 2) * myPow(x, n / 2);
    } else {
        // 奇数：同样拆成两个 n/2 的子问题，别忘了前面多一个 x
        return x * myPow(x, n / 2) * myPow(x, n / 2);
    }
}
```

比如 10 被拆成两个 5，原问题 `myPow(x, n)` 就被拆成了两个 `myPow(x, n / 2)` 的子问题，最后返回两个子问题的乘积。5 也是这样，`5 / 2` 整数除法拆成两个 2，别忘了前面还得多一个 2——在这里这个 2 就是我们的 x。

准备两个测试用例验证一下：2 的 16 次方，正确答案是 65536；2 的 10 次方，正确答案是 1024。跑出来 65536、1024，都对。代码到这里是初步实现了，后面还有很多可以优化的地方。

### 第一处改进：别把同一件事算两遍

先来说一下我们代码里一个比较严重的问题。

我们刚才说快速幂的优点是：当我解决其中一个子问题的时候，它**右侧的子问题计算结果跟它是完全一样的**。既然一样，需要重复计算吗？显然不需要。

但你现在回头看我们写的代码——不是这样。算完左边的子问题之后，我们仍然调用了一次 `myPow` 去计算右边的子问题，这个计算完全就是没有必要。

改法很简单：**把 `myPow` 的调用抽到外面，让它只调用一次**：

```java
public double myPow(double x, int n) {
    if (n == 1) {
        return x;
    }
    double t = myPow(x, n / 2);        // 只递归一次
    if (n % 2 == 0) {
        return t * t;
    } else {
        return t * t * x;
    }
}
```

这样才算真正达到快速幂的效果。改完再验证一下那两个用例，结果仍然正确，就算过了。

到这儿我认为快速幂的本质我们已经掌握了。但是这个解答放到力扣上去跑，你会发现它**过不了**——因为它没有考虑一些边界条件和特殊情况。我们一个一个来看。

### 力扣上过不去的三个用例

#### n 等于 0

第一个过不了的测试用例：`n == 0`。我们都知道任何数的 0 次幂结果都应该是 1，但我们这个代码里只考虑了 `n == 1`。

一测就报栈溢出了。为什么？因为只判断了 `n == 1`，那么 `n == 0` 的时候相当于就在死循环里出不去了，不断地递归调用。

把这个特殊情况补上就行：

```java
if (n == 0) {
    return 1;
}
```

> **提示**：有了 `n == 0` 这个判断之后，原来那个 `n == 1` 其实也可以不要了。因为真的 `n == 1` 的时候，接下来除以 2 结果就是 0。加了它之后它就可以作为一个统一的终止条件。不过从效率上讲，如果单独保留一个 `n == 1` 的分支，能少一次不必要的递归调用。所以两个都留着更好。

#### n 是负数

第二个跑不通的测试用例是 `n` 为负数。比如传进来 `2 的 -2 次方`，显然结果是 0.25，但我们这个代码里并没有考虑这种情况，所以它不能正确工作。

怎么解决呢？其实也简单。2 的 -2 次方实际上等于 $1 \div 2^2$，也就是我们通常说的**倒数**。所以我们可以先按正数把这个结果求出来，然后再求它的一个倒数就行了。

具体到代码，我不想对原有的代码逻辑做太多修改，所以把方法名改一下，叫 `myPowPositive`——意思就是"我这个方法只负责求 n 为正数的情况"。至于也能求负数的那个方法，我们再写一个，方法名沿用原来的 `myPow`，它里面会考虑复数（负数）的情况：

```java
public double myPow(double x, int n) {
    long p = n;                       // 先把 n 复制给一个临时变量来检查
    if (p < 0) {
        p = -p;                       // 负数先取绝对值，按正数来求
    }

    double r = myPowPositive(x, (int) p);

    if (n < 0) {
        return 1.0 / r;               // 负数：求倒数
    }
    return r;                         // 非负数：直接返回
}

public double myPowPositive(double x, int n) {
    if (n == 0) return 1;
    if (n == 1) return x;
    double t = myPowPositive(x, n / 2);
    return n % 2 == 0 ? t * t : t * t * x;
}
```

测一下，看能不能求出正确的 0.25。能，这个测试用例就解决了。

#### n 等于 Integer.MIN_VALUE

第三个测试用例我觉得力扣给得挺恶心的：它给的 n 是 `-2147483648`，这实际上就是 Java 中 int 整数的最小值了。

给这么一个负数会出什么问题？问题就出在取绝对值这一步。我们发现它小于零的时候要负负得正，那么负的 2147483648 传过来以后，它能负负得正吗？如果负负得正，就超出了正整数的最大范围了——正整数最大的是 2147483647，比它还少一个。

这里怎么办？说实话没有一个简单的解决办法。力扣官方给的做法就是用一个更大的整数类型：这里给 `long`，把这里所有原来的 int 都改一下，给一个更大的整数，它就能存得下了。你说设计这种测试用例其实也没什么太大意义。

走一遍看看，最终结果是 0.0。因为这个相当于非常大的一个幂了，最后一求倒数，就变成 0.0 了。结果是对的。至于第三个这个测试用例，我们就给大家说到这儿。

### 判断奇偶：除了 %2，还可以按位与

最后再多啰嗦几句，再给大家介绍一种判断奇偶数的方法。

之前我们用的是百分号运算符，也就是求模运算：n 除以 2 求模，余数是 0 表示偶数，余数是 1 表示奇数。这是一种。其实还有一种，通过**位运算**也能判断奇偶。

我们把十进制的 1 到 8 写出来，换算成二进制找找规律：

```text
十进制    二进制(4 位)      奇偶
   1        0001           奇
   2        0010           偶
   3        0011           奇
   4        0100           偶
   5        0101           奇
   6        0110           偶
   7        0111           奇
   8        1000           偶
```

把奇数 1、3、5、7 放一块儿看，它们最后一位都是 1；偶数 2、4、6、8 放一块儿看，最后一位都是 0。所以判断奇偶就转化成了**检查二进制的最后一位**。

那怎么拿到最后一位呢？把这些数字跟 1 这个数字做一个二进制的按位与运算就行了。以 7 为例，7 是 111，1 是 001：

```text
   111     ← 7
 & 001     ← 1
  -------
   001     ← 结果是 1  →  奇数
```

因为只要有一个 0，结果就是 0，所以这个结果就相当于把它的最后一位原样拿了出来。你把 1、3、5 都试一遍，结果都是 1。

再看偶数，以 8 为例：

```text
  1000     ← 8
& 0001     ← 1
 -------
  0000     ← 结果是 0  →  偶数
```

其余的 2、4、6 去跟 1 做按位与，得到的结果也都是 0。所以具体到代码就可以这样写：

```java
if ((n & 1) == 0) {
    // 偶数
} else {
    // 奇数
}
```

> **易错点**：按位与运算的优先级比较低，写在 `if` 里一定要用一对括号把它括起来 `(n & 1) == 0`，否则运算顺序会不对。

这样写出来的代码，测试结果依然是正确的。又给大家介绍了一种判断奇偶数的方法。

#### 求数组中第 K 大的元素

之前在讲堆的时候做过，当时用的是小顶堆，思路是：先把前 K 个元素放入小顶堆，剩余元素循环遍历，与堆顶比较，比堆顶小的跳过，比堆顶大的就用它替换堆顶，从而保证堆中始终保留着当前最大的 K 个元素。循环结束后堆顶就是第 K 大的元素。

堆解法是 $O(N \log K)$ 量级。快速选择可以直接把它降到 $O(N)$：题目的排名是**由大到小、从 1 开始**，而快速选择的排名是**由小到大、从 0 开始**，两者的换算关系是

$$r_{\text{升序}} = n - K$$

所以只要调用 `quick(nums, 0, nums.length - 1, nums.length - k)` 即可。

**测试用例**：无序数组 `[2, 3, 1, 5, 6, 4]`，求第 2 大的元素。6 是第 1 大、5 是第 2 大，**答案为 5**。

#### 求数组中的中位数

奇数个数字时，排好序后中间那个数字就是中位数；偶数个数字时，取中间两个数字求平均值。

思路是把它化成"求中间排名的元素"：中间排名就是 `数组长度 / 2`。奇数时调用一次 `quick(nums, 0, len - 1, len / 2)`；偶数时要调用两次，分别求 `len / 2` 和 `len / 2 - 1` 这两个排名上的元素，再除以 `2.0` 求平均。

**测试用例**：`[1, 4, 5]` 中位数为 **4**；`[1, 3, 4, 5, 6]` 中位数为 **4**；`[1, 2, 3, 4, 5, 6]` 中间是 3 和 4，中位数为 **3.5**；另一个用例中间是 4 和 5，中位数为 **4.5**。

#### 快速幂

写一个函数求 $x^n$。

朴素做法是循环 n 次相乘，$n = 16$ 时要乘 16 次。分治的做法把指数不断对折：$x^n = (x^{n/2})^2$，奇数时再补乘一个 $x$，按 $n = 16$ 的例子只要 4 次乘法。

力扣上会卡三种边界情况，都必须处理：

- $n = 0$：返回 1，否则会栈溢出；
- $n < 0$：先按正数算出结果再取倒数，例如 $2^{-2} = 0.25$；
- $n = -2147483648$（`Integer.MIN_VALUE`）：取绝对值会溢出正整数范围，临时变量要改用 `long`。

**测试用例**：$2^{16} = $ **65536**；$2^{10} = $ **1024**；$2^{-2} = $ **0.25**；$2^{-2147483648} = $ **0.0**（幂太大，取倒数后为 0.0）。

## 二分求平方根、递归切分最长子串与回溯还原状态
> 对应块：BLK37 | 覆盖分集：P159-P163 | 块标题（分集名）：《进阶数据结构和算法-313-平方根整数部分-Le》

这一块我们先来看一个题目：求一个数的平方根的整数部分。

什么意思呢。1 的平方根是 1，4 的平方根是 2，9 的平方根是 3，这些我们张口就来。可 2 的平方根是 1.4 几，8 的平方根是 2.8 几——题目要的是把小数部分直接扔掉，只留整数部分：2 取 1，8 取 2。后面这道题以及力扣 395 题，都是围绕"整数部分"这个约束展开的，写法上有一个共同的坎：答案不是一次算出来的，而是靠递归一轮轮逼出来的。

### 平方根的整数部分，题目到底要什么

拿 99 举例。$9^2 = 81$，$10^2 = 100$，99 卡在 81 和 100 中间，那它的平方根必然落在 9 到 10 之间，也就是 9 点几。小数部分我们并不关心，题目要的就是那个整数部分，也就是 9。

反过来说，只要我能找到一个数，它的平方比 x 大；而它的上一个数，平方比 x 小——那么它前面那个数，就是我们要的答案。

> **结论**：找到"平方首次超过 x"的那个候选值，它的前一个数就是 $\lfloor\sqrt{x}\rfloor$。

### 笨办法与二分办法

从小的数字开始一个一个试：$1^2$ 太小，$2^2 = 4$ 还是比 99 小，$3^2$、$4^2$……一直到 $10^2$，才知道答案。整个过程试了 10 次。

能不能少试几次？能。我们改用二分的办法，每次只取区间中间的那个数来比较，猜得准，区间就塌缩得飞快。

```text
目标 x = 99

[1, 99]   mid = 50   50² = 2500 > 99   -> 太大，收窄右边界
[1, 49]   mid = 25   25² = 625  > 99   -> 太大，收窄右边界
[1, 24]   mid = 12   12² = 144  > 99   -> 太大，收窄右边界
[1, 11]   mid = 6    6²  = 36   < 99   -> 太小，放宽左边界
[7, 11]   mid = 9    9²  = 81   < 99   -> 太小，放宽左边界
[10,11]   mid = 10   10² = 100  > 99   -> 太大，收窄右边界
                                           此时 left > right，退出循环
                                           ans = 9
```

六次。比原来那个一个一个试快得多——你注意每一次比较，都是把这个区间砍掉一半，这就是二分省下来的时间。

### 二分的代码骨架，以及那个必须记下来的变量

先把变量名定下来：左边界叫 `i`，右边界叫 `j`，中间值叫 `m`。

初值上，左边界从 1 开始，右边界从 `x` 开始。循环条件写成 `i <= j`，它表示"这个范围内还有没尝试过的数字"；一旦 `i > j`，说明区间里的数全试完了，该退出。

循环体内先求中间值。这里除以 2 我们不写 `/ 2`，而是用位运算符右移一位来代替：

```java
int m = (i + j) >>> 1;
```

为什么？因为当 `i` 和 `j` 都很大的时候，`i + j` 这一下加法本身就可能溢出。右移写法把加法彻底绕开了。

拿到 `m` 之后，把它叫 `mm = m * m`，然后跟 `x` 做比较，三个分支：

- `mm == x`：比如 `x` 正好是 4，中间值正好是 2，那就相当于找到了 4 的平方根就是 2，直接 `return m`；
- `mm < x`：说明这个数有点小，那就放宽左边界，`i = m + 1`；
- `mm > x`：说明这个数有点大，那就收窄右边界，`j = m - 1`。

但代码写到这儿还没完，**少了一个必须记录的动作**。

看 `mm > x` 那一支：`j = m - 1` 之后，下一轮 `i > j` 就成立，循环直接退出循环了。也就是说，走到这一步的时候，刚才那个 `m` 的值已经被 `m - 1` 覆盖掉了，退出时你根本不知道最后试的那个 `m` 是多少。

以 99 为例：试到 `m = 9` 时 `81 < 99`，`i` 变成 10；下一轮 `i = 10, j = 11`，中间值又是 10，而 `10² = 100 > 99`，于是走 `else`，`j = 10 - 1 = 9`。这时 `i = 10 > j = 9`，循环退出。如果之前没有把 `m = 9` 这个"曾经试过的最大候选"记下来，退出时你手里是空的。

所以要在循环外用一个变量 `ans` 来记录，位置很明确——就在"平方比 x 小"的那个分支里，每次都记一次：

```java
public int mySqrt(int x) {
    int i = 1;      // 左边界
    int j = x;      // 右边界
    int ans = 0;    // 记录已经确认"平方小于 x"的最大候选值

    while (i <= j) {            // i <= j 说明区间里还有没试过的数
        int m = (i + j) >>> 1;   // 除以 2 用右移，防止 i + j 溢出
        int mm = m * m;         // m 的平方

        if (mm == x) {
            return m;           // 正好整除，直接返回
        } else if (mm < x) {
            ans = m;            // 记下来，这一支随时可能成为答案
            i = m + 1;          // m 偏小，放宽左边界
        } else {
            j = m - 1;          // m 偏大，收窄右边界
        }
    }
    return ans;                 // i > j，所有候选都试完了
}
```

> **易错点**：`ans` 的赋值只能放在 `mm <= x` 这一支。放在别的地方没有意义——只有"平方不超过 x"的候选才有资格成为答案。

测一下：99 得 9，4 得 2，8 得 2，都对。

### 等价变换，以及溢出的真正位置

力扣就是不让我们舒心。它准备的测试用例里会传一个非常大的数字。这时候你注意看——**中间值本身并没有越界**，因为我们前面用右移把加法这一下挡住了；但中间值算出来很大，你再求它的平方，会怎么样？乘法这一步就越界了。

越界之后再拿两个数做比较，其实已经没有什么意义了，所以这个用例通不过。

解决办法有两种。第一种最直接：把这里的 `int` 全部扩大成 `long`，让大数乘法不至于越界。

第二种办法更漂亮一些。我们反过来想一想——既然乘法会越界，那除法呢？`x / m` 肯定不会越界。而 `m * m <= x` 这件事，恰好等价于 `x / m >= m`（`m` 是正数，区间内 `m` 至少为 1）。所以只要把乘法改成除法，这个比较就既安全又等价。

在改除法之前，先做一个等价的变换。我把第一个 `if`（`mm == x` 直接返回）和第二个 `else if`（`mm < x`）合到一起去：平方等于 `x` 的时候也别急着返回，同样先暂存到 `ans` 里，将来退出循环时再统一返回 `ans`。也就是说，把等于条件和小于条件合并成小于等于：

```java
while (i <= j) {
    int m = (i + j) >>> 1;

    if (x / m >= m) {     // 等价于 m * m <= x，且乘法不会溢出
        ans = m;
        i = m + 1;
    } else {
        j = m - 1;
    }
}
return ans;
```

这个变换不影响逻辑的正确性，前面 99、4、8 几个用例的结果也依然是对的。

至此这道题就算解答完毕了。最后那个非常大的用例求出来是 **46339**，我用计算器核对过，平方根的整数部分确实就是这个数。

### 至少 K 个重复字符的最长子串，题目到底在问什么

接下来是力扣 395 题。这道题的题意很多同学一开始读不明白，我们通过几个例子先说明一下。

给一个字符串，再给一个整数 `k`。例子里 A 字符出现了 3 次、B 字符出现了 2 次；题目要求你把这个字符串切分，切分后的子串里，每个字符的出现次数都不能低于这个 `k`。比如你切出一个 `BB`，它里面 B 出现了 2 次，低于 3，那这个子串就被舍弃；前面那个 `AAA` 可以，因为它里面 A 出现了 3 次，满足条件。

但这题还没完——它要的是把这个字符串里**所有**符合上述条件的子串都找出来，然后取其中长度最长的那个。

第一个例子就是 `AAA` 一段，答案长度 3，没有别人。

第二个例子：A 出现了 2 次，B 出现了 3 次，C 只出现了 1 次，而 `k = 2`。你只要切出来的子串里含有 C 就不行——比如切成 `BBC`，C 出现了 1 次，小于 2。于是只能这么切，保留下来的子串是 `ABABB`：A 出现 2 次，B 出现 3 次，都满足条件。所以最长的子串就是 `ABABB`，长度 5。

但光看这两个例子，我们其实并不能 get 到这道题的要点，我们再多看一个。把刚才那个字符串 `AABBC` 的 `k` 从 2 改成 3，行不行？

注意，三就不行了。有同学说，三的话不是还是取前面这个部分作为最长子串吗？注意，不行。为什么？

看 `ABABB` 这个子串里面，A 的出现次数只有 2 次，小于 3，于是整个这个子串都不满足。那有同学说，我把第一个 A 去掉行不行？也不行——去掉第一个 A 之后，剩下那个 A 的个数是 1，还是小于 3。但是你不能再把中间的这个 A 去掉了：中间的 A 一去掉，字符串就不连续了。子串要求保持原有的字符顺序、要连续，你不能像挑子序列那样挑挑拣拣。

> **提示**：这是官网例子里没有说明、但极其容易踩的一点。子串 ≠ 子序列，字符不能跳着选，只能整段保留或整段丢弃。

### 分治的骨架：剔除不合格字符，再递归左右两段

光看例子还是抽象，我们用一个设计得比较长的字符串来走一遍求解过程。设 `k = 3`，原始串里：`x` 只出现 1 次，`c` 出现了 2 次，`e` 出现了 1 次，而 `b` 出现了 3 次。

第一步，是不是应该先把原始字符串里凡是出现次数小于 3 的那些字符先给它剔除掉？

为什么？因为这些字符出现次数太少了，将来组合子串的话，**谁带上它们谁倒霉**。比如说我有三个 `d`，如果带上了这个 `x`，是不是就导致整个这个子串中有一个出现次数是 1 的字符，小于 3，不满足；但如果把这个 `x` 排除掉，它就满足了。

于是第一轮：`x` 不要，`c` 不要，`e` 不要。注意，"剔除"意味着原始字符串其实就被拆分成了多个子串。

接下来，对第一轮得到的这些子串，再做类似的处理。

```text
k = 3，原始串的字符出现次数：
    x → 1 次      c → 2 次      e → 1 次      b → 3 次（散落在多段里）

第一轮：把 x / c / e 全部剔除
    这些"不合格字符"把原串切成若干段，b 也随之被拆散

第二轮：对剩下的每一段重新统计
    有些段里的 b 只剩 2 次  ->  又拿 b 开刀，继续切
    像那三个 d 这样的段    ->  每个字符都 >= 3 次，不用动

收尾：剩下各段里最长的那一段长度是 4，其余都不到 4
```

看第二段和最后一段：虽然一开始原始字符串里 B 确实出现了 3 次，但你看它这段字符串里 B 出现了几次——只出现了 2 次。它要带上这个 B，就会导致整个子串不满足条件。最后那段也带上了一个 B，也是同样的问题。所以我们可以递归地对这些子串再做重复的操作。

于是整个过程可以总结成这么几句话：

1. 统计字符串中每个字符的出现次数；
2. 把那些出现次数小于 `k` 的字符先移除掉——移除意味着原始字符串被拆分成了多个子串；
3. 对多个剩余的子串，再对它们做递归的重复处理。

那什么时候递归结束？两种情况：一种是子串的长度已经小于 `k` 了，那肯定不够用，不满足条件，直接排除；另一种是剩余的子串里已经没有出现次数小于 `k` 的字符了，像那三个 `d` 那一段就属于这种。这时候在这些子串里面再找一个长度最长的，就是答案。

### 统计字符次数：一个长度为 26 的数组

每一轮递归要做的第一件事，就是统计这个字符串中每个字符的出现次数。

广义上你用 `HashMap` 就能做——key 放字符，value 放它的出现次数。但针对这道题，题目里人家说了字符只可能是英文字母，所以我们就可以用一个 `int` 数组来统计，长度就是 26，数组的索引对应字符，数组的值对应这个字符出现了几次。就叫它 `counts`。

```java
int[] counts = new int[26];
```

要做这件事非常简单。把字符串里的所有字符遍历出来——这里提一句，前面我们说过，如果想效率高一些，先把它转换成 `char[]` 再遍历 `char[]`，效率会稍微好一些。

接下来是索引怎么找：我们让字符 `A` 对应索引 0，字符 `B` 对应索引 1，以此类推。具体做法就是**用字符减去 `'A'`**。比如遍历到字符 `c`，`'c' - 'a'` 就是 2；遍历到 `b`，`'b' - 'a'` 就是 1。这样就定位到了这个字符在整个数组中的索引位置，然后直接 `++` 一下就行，初始值它们的出现次数都是零嘛，遇到一个加一个。

打印出来验证一下：下标 0 对应 A 出现 2 次，下标 1 对应 B 出现 3 次，下标 2 对应 C 出现 1 次，正好对上。

### 切分的位置：substring 与连续字符的合并

统计好了，下一步就到原始字符串里去找那些出现次数小于 `k` 的字符，然后根据它的位置，把整个字符串切分成两部分。

我们遍历原始字符串对应的那个字符数组，用 `i` 作为遍历变量——用 `i` 是因为这个 `i` 后面要用到。拿到第 `i` 个字符之后，我们要检查它的出现次数。怎么查？前面已经都计算好了，都统计在 `counts` 数组里了，所以再到那个数组里去查询一下，同样换算成索引减去 `'a'`，就找到当前字符的出现次数了。

先判断这个次数是不是大于 0——大于 0 表示它确实出现了；等于 0 表示根本没这个字符。对于大于 0 并且小于 `k` 的，这就是我们要找的那些"出现次数少"的字符，可以做处理了。

怎么处理？根据它的索引位置，用 `substring` 把它切分成两个不同的字符串。第一部分是从零切到 `i`，也就是 `substring(0, i)`；第二部分是从 `i + 1` 开始往后切，剩下多少我们就不管了，所以直接写成 `substring(i + 1)`。

```java
// 找到第一个出现次数小于 k 的字符后，一刀切成两段
return Math.max(helper(s.substring(0, i), k),
                 helper(s.substring(i + 1), k));
```

运行一下就能看到，它把字符串切成了 `C` 前面的那部分和 `C` 后面的那部分。不过示例里 `C` 后面没东西了，切出来其实是个空串，不太明显。把字符串改成前面是几个 `A`、中间一个 `c`、后面跟几个 `B`，就很清楚了。

但立刻就来了一个问题。

假设我把 `k` 设成 3，然后有两个连续的 `c`。我的目的是这两个连续的 `c` 出现次数都小于 3，都应该去掉，只留下前面的三个 `A` 和后面的三个 `B`。可按我们刚才那样去切，能得到想要的结果吗？

不能。它是先找到第一个 `c`，按第一个 `c` 把字符串切成两个部分，然后又拿到第二个 `c`，再按第二个 `c` 切一次。显然这样操作有点重复了——完全可以一次把这两个连续的 `c` 都排除掉。

思路是这样的：除了 `i` 这个索引位置，我们再加一个 `j`。`i` 记录我们找到的第一个出现次数小于 `k` 的字符的初始位置，`j` 代表它的一块结束位置。只要是连续的，我们就把这连续的一块一次切掉。

```java
int j = i + 1;                       // i 已经找到了，从 i+1 继续检查
while (j < chars.length &&           // 别越界
       counts[chars[j] - 'a'] < k) { // 这一处字符的出现次数也小于 k
    j++;
}
// 直到遇到一个出现次数 >= k 的字符才停下来
return Math.max(helper(s.substring(0, i), k),
                 helper(s.substring(j), k));
```

切分的时候就是从零切到 `i`，然后再从 `j` 切到最后。这样一来两个连续的 `c` 就被一刀切干净了：

```text
k = 3，s = "AAACCBBB"

  下标  0   1   2   3   4   5   6   7
      ┌───┬───┬───┬───┬───┬───┬───┬───┐
      │ A │ A │ A │ c │ c │ B │ B │ B │
      └───┴───┴───┴───┴───┴───┴───┴───┘
                      ↑   ↑
                      i   j (=5)

  substring(0, i) = "AAA"      substring(j) = "BBB"
```

另外说明一下，那个遍历字符数组的循环，其实每找到一个这样的字符、切完，这个循环就算结束了，我们并不需要让它继续循环下去——下次在递归里面再分别处理这两个子串就可以了。这也就是下面为什么 `return` 写在循环体内。

### 递归的两个出口

在递归调用左右两个子串之前，先把这个方法的递归终止条件写好，前面总结过的两种情况。

| 情况 | 含义 | 返回值 |
| --- | --- | --- |
| 子串长度已经小于 `k` | 落选，比如切出来就是一个 `A` 而 `k = 2` | 返回 `0` |
| 子串中没有出现次数小于 `k` 的字符 | 入选，整个循环走完 | 返回 `s.length()` |

第一种情况在方法的一开始就做检查，一旦检查出来子串长度已经小于 `k`，就返回 0。为什么是 0？因为这个方法返回值的含义是"选中的最长子串的长度"，你这个子串落选了，把它的长度设置为 0 即可。0 相当于肯定是个最小值，将来跟那些符合条件的子串在比较的时候，不会干扰结果。

第二种情况选中了。大家来看，选中的子串是不是得执行完这个循环？因为这个循环就是去找有没有出现次数小于 `k` 的字符，如果有就做进一步处理。但如果循环都走完了，说明它所有的字符出现次数都大于等于 `k`，那这时候的字符串长度就是我实际要的长度，直接返回它。

所以完整的递归方法是：

```java
public int longestSubstring(String s, int k) {
    return helper(s, k);
}

private int helper(String s, int k) {
    // 出口一：子串长度已经小于 k，落选
    if (s.length() < k) {
        return 0;
    }

    // 统计每个字符的出现次数
    int[] counts = new int[26];
    char[] chars = s.toCharArray();
    for (char c : chars) {
        counts[c - 'a']++;
    }

    // 找到出现次数小于 k 的字符，按它所在的一整段切分，然后递归
    for (int i = 0; i < chars.length; i++) {
        if (counts[chars[i] - 'a'] > 0 && counts[chars[i] - 'a'] < k) {
            int j = i + 1;
            while (j < chars.length && counts[chars[j] - 'a'] < k) {
                j++;
            }
            return Math.max(helper(s.substring(0, i), k),
                             helper(s.substring(j), k));
        }
    }

    // 出口二：没有不合格字符，整个子串入选
    return s.length();
}
```

`max` 的第一项是左边那个递归调用的返回结果，第二项是右边那个的返回结果，二者求一个最大就可以了——题目要求的是找这些子串长度里最大的。这个例子的答案是 3。

顺带一提，`return` 写在循环里面，意味着外层这个循环只会执行一次，也就不会出现"前面已经切分好了，后面再重复前面这个效果"的问题。

### 回溯：把数据恢复到之前的某个阶段

接下来我们学习回溯。

编写程序的时候，我们通常会把一个程序的运行过程分成多个阶段。如果能够通过某些手段将数据恢复到之前某一阶段的那个状态，那我们就把它称之为**回溯**。这句话可能不是特别好理解，我们通过一个简单的例子来说明。

```java
void rec(int n) {
    if (n == 3) {
        return;      // 递归结束，开始逐层返回
    }
    rec(n + 1);
}
```

用 debug 方式跑一遍。第一次调用时 `n = 1`，接着向下执行进入第二次递归调用，`n` 被加成了 2；继续执行进入第三次递归调用，`n` 被加成了 3，这时候递归就该结束了，该逐层返回。

现在我问一个问题：**我们返回的时候，能不能把 `n` 恢复成之前的某个状态？** 恢复成 2、恢复成 1，这些状态可不可以？

可以。我们每次方法调用的时候，它实际上都把当前那个 `n` 记录下来了。第一次调用时 `n` 作为方法内的局部变量，它的值 1 已经被记录在这个方法栈中了；第二次递归调用时 `n = 2`，也被记录到对应的方法栈中；最后一次递归调用的 `n = 3`，同样被记录下来了。

现在第三次调用结束了，是不是要返回第二次这个方法的调用？返回的时候能不能把 `n` 恢复成之前的 2？显然是能的——回到第二次调用时，`n` 就是 2。第二次调用如果也执行结束，回到第一次调用时，`n` 就会被恢复成 1。

```text
rec(1)  栈帧里存着 n = 1
  └─ rec(2)  栈帧里存着 n = 2
       └─ rec(3)  栈帧里存着 n = 3
            └─ 结束，逐层返回
                 ↑ 回到 rec(2) 时，n 自动是 2
                   ↑ 回到 rec(1) 时，n 自动是 1
```

我们这个例子中就是把 `n` 的状态恢复了，这就是一种回溯。

那它是怎么工作的？说白了也很简单。我们刚才把数据存储在了 `n` 这个局部变量当中，在这个方法递归调用的时候，它能不能去修改这个局部变量的内容？修改不了。因为一个方法内的局部变量，是不会被其他方法所干涉、所修改的。因此你递归调用前 `n` 里存的是什么，递归调用之后 `n` 里的数据仍然没有变化，这样就起到了一个保存状态的效果。

### 局部变量会自动回滚，引用不会

但刚才 `n` 是一个基本类型的数据。如果我换一种数据类型，比如换一个集合或者换一个数组，这个时候还会不会正常工作呢？试验一下：给方法加一个集合参数，选 `List<String>` 类型，里面放一些字符串。一开始给他传一个空的集合进去，然后递归调用的时候，也是把同一个对象给它传递进去。

```java
void rec(int n, List<String> list) {
    System.out.println("before = " + list);   // 递归调用前的打印

    list.add("a");                            // 递归调用前先加点东西

    if (n < 3) {
        rec(n + 1, list);
    }

    System.out.println("after = " + list);    // 递归调用之后的打印
}
```

走一遍就发现，这回调用之后**并没有**把数据恢复成之前的状态。第一次递归调用时集合是空的；等第二次递归调用时，集合里已经加了一个 `a`；等第二次递归调用结束返回的时候，集合里已经加了两个 `a`；那等回到第一次递归调用，它这个位置上集合中仍然是两个 `a`。显然这个数据并没有恢复成之前的状态。

为什么？原因非常简单：我们的方法调用有多次，但他们用的都是**同一个集合对象**。

### 让操作成对出现：push 与 pop

那怎么办？其实我们可以手动来恢复。你看这个操作实际上是个对称的操作——我们在递归调用前往里加了一个数据，那么递归调用后呢，我们就可以把这个数据移除。

```text
push  ——  站顶加数据
pop   ——  从站顶移出数据
```

只要我们这个"加数据"跟"移除数据"的方法成对出现，那么就可以在递归结束之后，把它的状态恢复成之前的状态。

```java
void rec(int n, List<String> list) {
    System.out.println("before = " + list);

    list.add("a");                          // push：递归调用前，先改数据

    if (n < 3) {
        rec(n + 1, list);
    }

    System.out.println("after = " + list);
    list.remove(list.size() - 1);            // pop：递归调用后，把数据改回去
}
```

这回就 OK 了。第一次调用时 list 的状态是空集合，它恢复之后也被恢复成空集合；第二次递归调用时 list 中有一个 `a`，等你第二次调用恢复的时候，它也会把集合中的元素恢复成一个 `a` 的状态。

```text
rec(1, [])        before=[]          add -> [a]
  rec(2, [a])     before=[a]         add -> [a, a]
    rec(3, [a,a]) before=[a, a]      add -> [a, a, a]
                                     n == 3，不再往下递归
                                     after=[a, a, a]
                                     remove -> [a, a]
  after=[a, a]                        remove -> [a]
after=[a]                             remove -> []
```

> **结论**：如果你用的是可变的集合数据，或者是像数组这样的数据，那么必须在递归的前后，自己来手工地恢复数据的状态。方法栈能帮你回滚的，只有基本类型的局部变量。

## 全排列与组合：把回溯一步一步走完
> 对应块：BLK38 | 覆盖分集：P164-P168 | 块标题（分集名）：《进阶数据结构和算法-318-全排列-Leetco》

### 一道不用计算机也会做的题

我们借回溯的思想来解一道题，叫全排列。

给你三个数字 1、2、3，要求它的全排列。这个大家应该都知道，排列方式一共就六种：

```text
123   132   213   231   312   321
```

那怎么用递归加回溯的办法，把这三个数字所有的排列方式都找到呢？我们一步一步来看。

先别急着看代码。我们平时不用计算机，手算这个排列是怎么求的？是不是思路也是：**先固定一个，然后求剩下几个的排列**。

先固定 1，求 2、3 的排列；再固定 2，求 1、3 的排列；再固定 3，求 1、2 的排列。而 2、3 的排列本身呢？也是先固定其中一个——固定 2，剩下一个 3，它的位置不就确定了嘛；固定 3，剩下的 2，位置同样确定。

按这种思路往下推，能确保整个求排列的过程中不遗漏。

### 从手算思路到程序里的两个数组

那对应到程序代码中，我们就可以在原来 1、2、3 这个数组的基础上，**再加一个数组**。

这个新数组记录这几个元素有没有被固定，或者说有没有被使用过。如果使用过的，我用一个灰色来表示；还没有使用的，用绿色来表示。

我们用一张状态表看一遍第一遍搜索到底发生了什么。`visited` 里的 `T` 表示已使用、`F` 表示未使用：

```text
起始    numbers = [1, 2, 3]   visited = [F F F]   stack = []

i=0     1 未使用  -> push  ->  visited = [T F F]   stack = [1]
i=1     2 未使用  -> push  ->  visited = [T T F]   stack = [1, 2]
i=2     3 未使用  -> push  ->  visited = [T T T]   stack = [1, 2, 3]
                                       size == numbers.length
                                       -> 找到一种排列: 123
```

所以程序里其实有两个数组：一个是我们原始的 1、2、3；另一个是代表有没有被使用过的数组，它是一个布尔变量。

具体地说，一开始我们先固定 1，同时把固定好的这个元素就加到一个集合里——这个集合将来存储我们的排列。剩下的两个元素里再固定 2，同样把固定的元素加到刚才的集合中；最后剩下一个 3，固定 3 的同时也把它加进集合。

> **结论**：只要这个集合的内容跟原始数组长度一致了，就表示我们找到了其中一种排列。

上面这是查找第一个排列的过程。1、2、3 都固定的情况下，第一个排列就出来了。

### 回溯：剩下的排列怎么长出来

那接下来要再求其他的排列，怎么办？我们是不是得用回溯的办法让它退回到之前有几个元素没有被固定的状态。

先取消 3 的固定，也就是回溯一次；然后再回溯一次，取消对 2 的固定。这接下来 3、2 是不是可以以另外一种方式来排列了？这回我们先固定 3，再固定 2，是不是又得到了第二个排列，也就是 132。

没问题吧？现在相当于"先固定 1"的两种情况我们都分析完了。

那我要再得出其他排列怎么办？这时候我们再进行回溯：取消 2 的固定，取消 3 的固定，最后把 1 的固定也给它取消——相当于恢复到了最初始的一个状态。这回先来固定 2，剩下 1、3 怎么排的活就类似了。先固定 1 再固定 3，得到第三个排列 213。

取消 3 的固定，取消 1 的固定。在这回活动的是 1 和 3，我们再换一个顺序，这回先固定 3 再固定 1，得到了 231。这是以 2 打头的两个排列，也都找到了。

再使用回溯取消对这三个数的固定，这回先固定 3，剩下 1、2 继续找它们的排列。最后又得到了 312 和 321 两个排列。

整个过程画出来大概是这样：

```text
fix 1  --+-- fix 2 -- fix 3  --> [1,2,3]
         |     +-- fix 3 -- fix 2 --> [1,3,2]
         |
         +-- unfix 3, unfix 2, unfix 1  (back to the very start)
fix 2  --+-- fix 1 -- fix 3  --> [2,1,3]
         |     +-- fix 3 -- fix 1 --> [2,3,1]
         |
         +-- unfix 3, unfix 1, unfix 2
fix 3  --+-- fix 1 -- fix 2  --> [3,1,2]
         +-- fix 2 -- fix 1 --> [3,2,1]

6 leaves in total
```

至此为止，我们就找到了所有的排列。

### 把 DFS 写出来

下面我们把代码写一下。

原始的方法里，参数要的是一个整数数组，这个整数数组存储的就是我们要进行排列的那些数字。方法的返回结果是一个大的 `List`，这个大 `List` 里面会套多个小的 `List`，每个小的 `List` 里存储了一种排列结果。

因为我们分析了整个过程是用回溯来解，用递归是比较方便的，因此我们专门写一个方法用来递归。方法的名字你叫个 `dfs` 也可以，或者有些人喜欢把它叫别的，深度优先遍历也行，都行，只是个名字而已。

那方法的参数有这么几个：

| 参数 | 作用 | 说明 |
| --- | --- | --- |
| `int[] numbers` | 原始数组 | 原样往下传，不用改 |
| `boolean[] visited` | 状态数组 | 为 `true` 表示该数字已被使用，为 `false` 表示未被使用 |
| `List<Integer> stack` | 路径集合 | 记录某一次的排列结果 |
| `List<List<Integer>> result` | 结果集合 | 存下所有排列，后面补上 |

首次调用的时候，给他传什么参数呢？`numbers` 原样传过去；第二个是一个 `visited` 布尔数组，它的长度跟原始数组保持一样就可以了——三个数字将来就有三个布尔值，分别记录它们是不是被使用，所以长度是 `numbers.length`；第三个参数给一个空的 `ArrayList`；最后 `result` 前面已经建好了，直接传过去。

接下来就去遍历这个 `numbers` 数组。先检查当前这个数字有没有被使用，比如第一次循环的时候我发现 1 没有被使用，就把它标记为已使用，相当于把它固定下来了；固定下来之后，我们再去递归地尝试剩下的数字。

写成代码就很简单了：

```java
public List<List<Integer>> permute(int[] numbers) {
    List<List<Integer>> result = new ArrayList<>();
    boolean[] visited = new boolean[numbers.length];
    dfs(numbers, visited, new ArrayList<>(), result);
    return result;
}

public void dfs(int[] numbers, boolean[] visited,
                List<Integer> stack, List<List<Integer>> result) {
    if (stack.size() == numbers.length) {
        result.add(new ArrayList<>(stack));
        return;
    }

    for (int i = 0; i < numbers.length; i++) {
        if (visited[i]) {
            continue;             // 已经固定过了，跳过
        }

        stack.add(numbers[i]);    // 固定：进路径
        visited[i] = true;        // 固定：打标记

        dfs(numbers, visited, stack, result);

        visited[i] = false;                    // 回溯：撤销标记
        stack.remove(stack.size() - 1);        // 回溯：撤销入栈
    }
}
```

> **易错点**：递归调用结束之后，需不需要对当前状态做一个回溯？需要。这是最容易漏掉的一步。

大家注意，等递归调用结束，我需不需要对我当前的这个状态做一个回溯？需要的。你看一开始我把 1 标记为已使用，等下一次递归结束了，再进入下一轮循环的时候，是不是就开始处理 2 了？那处理 2 的时候，1 是不是应该把它的使用状态重新标记为未使用？所以我们应该把这个 `visited` 的状态给它恢复一下，恢复成它一开始的 `false`；并且这个 `stack` 里面，是不是也应该把之前加进去的元素给它也回溯一下？这边 `push` 了，那等这个递归调用结束，我们应该 `pop`。

这段代码就体现了一个回溯的思想。

我们再把调用的过程看一遍，一开始进入循环的时候，`numbers` 就是我们的 1、2、3；`visited` 一开始肯定都是 `false`，都是未使用；`stack` 一开始也是空的。

第一次循环处理 1，1 未使用，所以进入了 `if`，进入完以后就会往 `stack` 里把 1 加进去，然后 1 对应的那个 `visited` 也设置为已使用。数据状态变成了"1 已使用，后面 2 和 3 未使用"。

下面它就去递归调用，主要去处理剩下的 2 和 3 的排列。那调用结束之后，我就问，需不需要把这个状态恢复成一开始的状态？需要啊。因为接下来我们要去处理 2 了，或者说去固定 2，再去排列 1 和 3。所以对 1 来讲，你得把它的状态再给它恢复成 `false`。

而对于我们这个 `stack` 来讲，你也应该把它变成一个空集合，然后我们重新往里面去加 2，产生 1、3 它们的排列。因此就有了我们在递归结束之后有这么一个回溯的动作。

再来一个例子。这次 `dfs` 已经执行到 1 这个位置了，也就是初始状态是 1 已经被固定了、被使用了，剩下的没有被使用的是 2 和 3，当然这时候我们集合中也存了一个 1。

那这个情况下的调用过程：循环再循环的话，是不是只会处理到 2 和 3 这两个元素了？因为 1 它是 `true`，它不会进入这个 `if` 条件。第一次循环循环到 2 的时候，我们继续往这个 `stack` 里添加一个元素，把那个 2 加进去，并且接下来会把 2 的 `visited` 设置为 `true`，让 2 标记为已使用。

但是别忘了，我们是不是还剩下一次循环要处理那个 3呀？所以你得在 2 的这个递归调用结束以后，也是把它进行一个回溯，恢复成它循环初始时的一个状态。因此大家看，这行代码执行完了，它就把 2 它的状态又恢复成了 `false`——因为你接下来要尝试 3 的话，2 你必须标记为未使用；而且我们这个集合中，是不是也应该把那个 2 给他剔掉，变成集合中只剩下一个 1，因为接下来 1 要再去跟 3 和 2 进行一个排列。

所以从这个例子我们也进一步看出来了：每次我们都需要把它恢复成在递归调用之后的初始状态。

### 递归停在哪

其实判断我们现在的递归是不是应该结束，有两种办法。

第一种办法就是看一下这个 `visited` 数组，如果它里面所有的位置都被标记成了 `true`，表示所有的数字都使用过了，那么这个时候我们就可以结束递归了。

但是这样判断起来比较麻烦，因为你得遍历这个布尔数组，看一下它遍历出来 `true` 的个数是不是等于数字的个数，这个代码写起来不方便。

那除了这种办法以外，还有第二种办法。从图上我们可以看出来，如果它找出了一种排列，那这个 `stack` 集合里加的元素个数，是不是也是我们的数字个数？所以我们用第二种判断更简单，`stack.size()` 是不是就能拿到这个集合中加了几个元素。元素的个数如果等于数字的个数，就表示他已经找到了其中一种排列了，这时候我们返回就行了。

| 判断方式 | 怎么算 | 代价 |
| --- | --- | --- |
| 遍历 `visited` | 统计 `true` 的个数是否等于数字个数 | 每次递归都要扫一遍布尔数组，代码长 |
| 看 `stack.size()` | 路径长度等于数组长度即命中 | 一次比较，直接 |

当然返回之前，我们可以把当时这个 `stack` 的状态打印出来看一下。遇到一个 `stack` 长度为 3 的时候，它就会打印一次，一次、两次、三次、四次、五次、六次，是不是六种排列都找出来了。

### result 与那一层副本

我们的代码还差最后一步。因为它这个方法最后要的是一个大集合，这个大集合里要把我们这些个排列的结果存储进去，所以我们需要再准备一个集合，这个集合里面再套我们的这些小集合。大集合我们把它叫 `result`，也当成一个参数传递给递归方法——当然我们这个参数列表又得多加一个参数了。

那当我遇到了这个长度等于数字长度的这个小集合以后，就相当于找到了一种排列，我们把当时的这个排列加到这个大的集合里就可以了。

```java
if (stack.size() == numbers.length) {
    result.add(new ArrayList<>(stack));   // 复制一份当前路径
    return;
}
```

> **易错点**：这里直接加 `stack` 是不行的。

为什么呢？因为这个 `stack` 它在多次递归调用的过程中，它的内容会变。刚开始是空的，然后一直加，加到 1、2、3；但是我们这时候如果把 1、2、3 加进去之后，它下次回溯的时候，是不是又会把这个 `stack` 的内容给它又清空了。

所以我们这里不应该直接加这个 `stack`，而是把 `stack` 当时里面的元素再放到一个新集合里，把这个新集合加给我们的 `result`，也就是写这样一个代码就可以创建一个新的 `ArrayList`，把当时这个 `stack` 里包含的元素加进来就可以了。

等所有的递归结束之后，我们这个 `result` 里就把所有这些个排列都记录下来了，返回外层的这个 `result` 就 OK 了。我们试一下，在外层来个循环，把里面这一个个的小的 `list` 遍历出来然后打印，也应该是刚才那六种。

这样呢，我们的全排列这道题目就解答完成了。

### 有重复元素时：给 1 和 1' 定一条规矩

接下来我们再来看一道全排列的题目，这道题目要求出不重复的全排列。

什么意思呢？比如说我要进行排列的数字，这回是 1、1、3。如果还是按我们之前的解答，我们来看一下它的运行结果：

```text
113   131   113   311   131   311
```

大家可以看到这里的 311 跟下面这个 311 是不是已经重复了，那么这里的 131 跟这个 131 也重复了，最后这个 131 也重复了。那这道题目就是说，将来我求出来的全排列的结果里，要剔除掉这些个重复的排列。

那这个怎么做呢？我们先来思考一下。

这里我们先要对原始的数组做一个排序，排序的目的是让这些取值相同的数字它们相邻存放，这个待会儿我们有用。

接下来为了好称呼，我把第一个 1 还是叫 1，第二个 1 呢咱们叫 1'。这样我们从读音，包括从视觉上都能把它区分出来。

那我们怎么去保证这个排列的过程中不出现重复的排列呢？我们可以给它定一条规则：规则呢就是**我们必须先固定第一个 1，也就是先固定 1，然后才能去固定这个 1'**。我们把固定 1 和 1' 的顺序给它确定好。你不能说先去固定 1' 再去固定 1，如果遇到了这种情况，我们就把它视为非法。

我们这么做了以后呢，就能保证排列的过程中不出现重复的排列。

具体的过程是怎样的呢？我们走一遍这个流程：

```text
fix 1  ->  fix 1' -> fix 2  ->  113   keep
       ->  fix 1' -> fix 3  ->  131   keep
       ->  fix 3  -> fix 1  ->  131   PRUNED   (rule broken)
       ->  fix 3  -> fix 1' ->  131   PRUNED   (rule broken)
fix 3  ->  fix 1  -> fix 1' ->  311   keep
       ->  fix 1' -> fix 1  ->  311   PRUNED   (rule broken)

3 results, no duplicates
```

具体一点说：我们先来固定第一个 1，这是可以的吧？按照我们刚才的规则是可以先固定 1 再固定 1' 的，所以他呢就照我们原来的逻辑去走就行了，继续再去固定 1'、2，最后固定 3，得到了第一个排列 113。

那我们回溯，然后再对两个未固定的数字重新调换它们的次序再来排列。这回先固定 3，再固定 1'，又得到了第二个排列，也就是 131。前两个排列没问题。

接下来我是不是可以继续回溯三次，也就是恢复到了一个初始状态。按照我们原来逻辑，是不是应该去固定 1' 了？但是行吧——它违反了我们之前定的这条规则，我们说你必须先固定 1 再固定 1'，现在我一上来就要固定 1'，是不是就不对了？我们应该能检查出这种情况，然后它那两个排列我们就不走了，这种情况就被跳过去了。

然后再回溯之后呢，我们去固定 3。固定 3 是可以的啊，因为 3 没有这种重复的情况。固定 3 了之后，我们继续来看：3 固定完了，接下来是不是可以去固定 1？哎这也是可以的，再固定 1'，得出了第三个排列 311。

再回溯两次，然后去对他俩进行一个位置上的调整。但是这回注意看，是不是又该轮到先固定 1' 了？先固定 1' 行吗？不行啊，它违反了我们这条规则，所以就把最后这种情况也跳过去了。

所以我们看到最终我们生成的三个排列——113、131、311，它们就避免了重复。

那我们把这种操作形象地称之为叫**剪枝**。为啥叫剪枝呢？你看原原本本有六个分支对吧，现在由于一些条件没有满足，他就不用继续递归了，所以分支变少了，所以形象地把它称之为剪枝动作。

### 规矩怎么变成代码

代码呢我们就不重头写了，我们把之前这个 46 题的解答拷贝一份，在这个基础上来改。

首先我们应该做的一件事，就是要对这个原始的数组做一个排序。排序是为了让这些有重复值的元素它们排到相邻的位置——这步是必须的。

然后我们怎么去检查出有相邻的两个取值相同的数字呢？你看我们可以在循环的时候把这种情况给他检查出来。比如说当前我正在处理的是第二个数字，那我就跟它的上一个数字相比呗。跟谁比呢？跟上一个数字，也就是 `numbers[i-1]` 去比较。如果确实相等，是不是就发现了这种有重复的情况。

当然我们要把它写成一个判断条件的话，大家要注意它的边界条件。那如果是 `i` 等于零，我需不需要去查找它的上一个？它这时候没有上一个，对吧。只有当 `i` 大于零的时候，我们才需要查找它的上一个与他比较，所以呢我们再加一个前提，就是 `i` 必须大于零。

好这样呢就找出了两个相邻的这个重复的数字。光找出了这个重复的数字还不够，我们还要加一条规则呢：规则就是刚才我们说的要先固定 1 再固定 1'。满足了这条规则，我们是不是还需要继续递归呀？继续递归求解。那如果是没满足这条规则，那么就把这次递归跳过去，我们进入下一轮的循环。

那我们怎么去找到这个条件呢？注意看我们现在的 `i` 代表的是谁啊？`i` 有可能代表的就是我们这个 1'。那它的上一个数字 `numbers[i-1]` 是不是就对应着第一个 1？

那这种情况下，我怎么知道他上一个数字有没有被固定呢？是不是也是在这个 `visited` 数组里存着呢？所以我们就到 `visited` 这个数组中，我们去查找一下 `i-1` 位置的那个元素，看一下它有没有被访问过。如果他访问过了，那我们可以继续执行；但是如果他没有被访问过，是不是我们就应该去进入下一轮的循环呀？

当然这个条件要跟前面的条件要同时成立，所以我们来一个 `&&`。好这样就可以了。关键是后半句话的理解：他就是找到我们与它相等的上一个数字，也就是找到那个 1，看看这个 1 是不是也还没有访问过。没有访问过的话，那就不执行后续的递归。

```java
public List<List<Integer>> permuteUnique(int[] numbers) {
    List<List<Integer>> result = new ArrayList<>();
    Arrays.sort(numbers);                          // 1. 让相等元素相邻
    dfsUnique(numbers, new boolean[numbers.length], new ArrayList<>(), result);
    return result;
}

public void dfsUnique(int[] numbers, boolean[] visited,
                      List<Integer> stack, List<List<Integer>> result) {
    if (stack.size() == numbers.length) {
        result.add(new ArrayList<>(stack));
        return;
    }

    for (int i = 0; i < numbers.length; i++) {
        if (visited[i]) {
            continue;
        }

        // 2. 与上一个元素相等，且上一个还没被固定 -> 违反"先 1 后 1'"的规矩，剪掉
        if (i > 0 && numbers[i] == numbers[i - 1] && !visited[i - 1]) {
            continue;
        }

        stack.add(numbers[i]);
        visited[i] = true;
        dfsUnique(numbers, visited, stack, result);
        visited[i] = false;
        stack.remove(stack.size() - 1);
    }
}
```

代码写完了，我们来测试一下。可以看到这回的结果里是不是没有重复的了，这样我们就解决了这个问题。

### 组合：换个方向，同一副骨架

接下来我们再来看一道题目，题目呢叫做组合。先来一起读一下题。

它这里的方法会传过来两个参数，第一个参数 `n`，第二个参数 `k`，代表的是什么呢？`n` 代表的是它的数字范围，进行组合的数字的一个范围。那从一开始，它是从 1 一直到几呢？一直到我们这个例子中是 4，好，将来也就是 1、2、3、4 这几个数都能拿过来用。

第二个参数 `k` 代表的是我要进行组合的话，是哪几个数字来组合，也就是一个数字的个数。比如说我这个例子中 `k` 等于 2，那就说 1 到 4 这几个数字中，我要拿两个来进行组合。最后这个方法返回的是所有的组合，最外层这个大 `List` 里面包含了所有的组合，其中一个小的 `List` 就包含了其中一种组合。

那针对我们这个例子，1 到 4 挑两个来进行组合，是不是 1 和 2 可以组合呀，1 跟 3 可以组合，1 跟 4 是不是也可以，好，类似的 2 跟 3 可以组合，2 跟 4 也可以组合，最后 3 跟 4 是不是可以组合。一共有这么六种组合。

它跟我们之前做的那个排列题目不一样：1 跟 2 还有 2 跟 1，它俩效果是一样的，也就是他不用考虑顺序。

| | 全排列 | 组合 |
| --- | --- | --- |
| 关心什么 | 顺序 | 只要选中了哪些数字 |
| 1、2 与 2、1 | 两种不同结果 | 同一种结果 |
| 例子 | 12、21 | 12 |
| 搜索时每个数字 | 能跟任何剩下的数字配 | 只能跟比自己大的数字配 |

那其实这个思路跟我们之前排列的思路非常的像。我们一开始也是先来固定 1。但是光有 1 它的组合数还不够对吧，他要凑足两个数字才算一个有效的组合。

所以接下来 1 就跟后面这个 2、3、4 这几个数字去尝试进行组合。首先先跟这个 2 组合一下，这回的数字个数是不是等于 `k` 了？够了、够了以后，就相当于找到了其中一种有效的组合。

然后呢我们回溯一次，回溯到 1。然后 1 呢跟接下来剩下的 3 和 4 这几个数字再进行尝试：一跟三组合一次，组合一次以后又找到了第二个有效的组合；然后回溯掉 3；然后 1 呢再跟 4 进行组合，这是找到了第三个有效的组合。

好，数字用完了，是不是我们这回继续回溯两次，回溯到这个位置会做到这个位置。然后接下来轮到 2 这个数字了。那这个 2 还需不需要回过头去再跟 1 组合呢？不需要了吧。我们前面说过，1、2 已经组合过了，2 呢不需要回过头去跟 1 组合了。所以 2 只要跟它后面的 3 和 4 进行组合就行。接下来 2 跟 3 组合，然后回溯 3，然后 2 再跟 4 组合，好，这样 2 的这几种情况也都找完了。

再回溯两次，接下来轮到数字 3。3 呢跟他后续的数字组合就可以了，所以 3 跟 4 进行一个组合，好，3 的这个组合也都被找到了。

再回溯两次，轮到了数字 4。但是数字 4 是不是没有更多的数字跟它组合了？所以它是一个无效的组合。那最后我们有效组合一共有这六种。

#### k = 3 的时候

我们再多看一个例子。这回的 `n` 没有变，也就是还是 4，数字范围还是从 1 到 4，然后 `k` 呢我把它改成了三。

那我们来看一下它的工作流程。首先呢也是先固定 1，1 呢就跟后面的 2 先组合一次。但是注意 1 跟 2 组合了之后，它的个数还不够对吧？`k` 这回等于三，他要凑足三个数，所以他继续跟剩余的数字，也就是 1、2 跟剩余的 3 还有 4 进行组合。好固定 1、2，然后跟 3 组合，这就找到其中一种组合了。

然后呢回溯一次，把 3 取消，也就是 1、2 是不是还要跟 4 进行一个组合呀。好 1、2 跟 4 又找到了第二种组合。这时候数字用完了对吧？没有更多的数字了，所以我们这回再回溯两次回溯到 1，是为了接下来 1 跟 3 是不是先组合一次。

好固定 1 的情况下跟 3 进行组合，1、3 组合之后数字个数不够，跟剩下的 4 再进行一个组合，找到了第三种 1、3、4 的组合。好，再回溯回溯到 1，然后这回 1 跟 4 进行一个组合。但是一跟 4 啊再组合的话，因为没有更多的数字了啊，所以它呢构不成一个有效的组合。那怎么办呢？继续回溯，把 4 回溯掉，1 回溯掉，是不是接下来该乘 1、2 了。

2 呢跟剩下的两个数字 2、3、4 看能不能组合，2 先跟 3 组合一下啊，结果个数不够，那就把这个 2、3 再跟剩下那个 4 进行一个组合，找到了第四种组合。好，再回溯回溯到 2，然后 2 再跟 4 进行一个组合。当然这跟刚才我们 1 一样的道理，它的数字个数不够了，不够用了，所以这种相当于是一种无效的组合。无效组合我们继续回溯回溯，回溯到最初始的位置，然后是不是该轮到 3 了。

好，该轮到 3 了。3 跟 4 进行一个组合啊，当然它也是无效的。最后呢还有一个数字 4，4 再尝试了就没人跟他组合了。我们这个例子中就找到了 1、2、3、4 四种组合。

#### start 是从哪儿冒出来的

你看我们这张图，这张图里面 1 跟其他组合的时候，是从 1 一直到 `n`，`n` 是 4嘛，1、2、3、4 都要处理一遍。但是等到我们去处理 2 的时候，他还是需要回过头去从 1 开始循环吗？不需要了吧？因为 2 不用回过头去跟 1 进行组合。

所以呢等第二次处理到 2 这个数字的时候，他只需要从 2 开始去处理后续的数字，是不是就行了。类似的，等我们处理到 3 这个数字的时候，他的循环也是需要从 3 开始向后处理。

所以我们再给他定一个起始的处理数字啊，这个呢我们给它起个变量名叫 `start`，代表的是起始处理数字。

```text
handling 1 : start = 1   ->  i takes 1, 2, 3, 4
handling 2 : start = 2   ->  i takes 2, 3, 4
handling 3 : start = 3   ->  i takes 3, 4
handling 4 : start = 4   ->  i takes 4      (nothing left to pair with)
```

我们第一次调用这个方法的时候，看给他传哪些参数：`start` 刚开始应该是从 1；`n` 一开始是从这儿传过来是 4；然后 `k` 也是从这传过来是 2；那么这个空的 `ArrayList` 我们创建一个传过去；最后 `result` 前面已经写好了，直接传过去就可以了。

### 组合的代码：push 与 pop 必须成对

这道题目用递归来求解是最方便的，所以我们先定一个用来递归的方法，还是叫 `dfs` 啊。方法呢它的参数除了我们之前带的这两个参数 `n` 和 `k` 以外，还应该有哪些参数啊？是不是我们首先得有个路径的小集合，这个小集合呢用来存储某一次的组合结果，所以我们来一个 `ArrayList` 啊，它还是叫 `stack`。

还需要一个大的集合，用来存储所有的这个组合结果。这个没问题吧？啊这是我们又加了两个参数。还有没有别的参数的？

```java
public List<List<Integer>> combine(int n, int k) {
    List<List<Integer>> result = new ArrayList<>();
    dfs(n, k, 1, new ArrayList<>(), result);
    return result;
}

public void dfs(int n, int k, int start,
                List<Integer> stack, List<List<Integer>> result) {
    if (stack.size() == k) {
        result.add(new ArrayList<>(stack));   // 凑满了，复制一份收进结果
        return;
    }

    for (int i = start; i <= n; i++) {
        stack.add(i);                        // 先把当前这个数字加入 stack

        dfs(n, k, i + 1, stack, result);     // 再去尝试固定后面的数字

        stack.remove(stack.size() - 1);       // 组合结束，pop 掉，恢复最初状态
    }
}
```

先来看一下递归的结束条件啊。你看我们什么情况下算是找到一种组合呢？我们这个例子 `k` 等于 2，也是找到两个数字的时候，那我们就算是找到一种组合了。那这些数字呢是不是最终是放在了 `stack` 这个小的集合中啊，所以我们判断一下，如果 `stack` 它的大小等于 `k`，说明找到了一种组合，那么就可以结束递归了。

但是结束之前呢，我们需要把 `stack` 当前存储的这两个数字给它放到这个大的最终结果里。这个咱们前面也见过啊，需要把 `stack` 内容咱们复制一份副本，因为 `stack` 的内容将来会变化，所以我们把 `stack` 当时的存储的数字存到一个新的集合里，然后加到最终结果中。

好，接下来呢我们来写一下组合的代码。这里呢我就来一个 `for` 循环，然后这里的 `i` 就从 `start` 开始，然后一直循环到 `i` 小于等于 `n`。你看一开始我们的 `start` 是不是等于 1 啊，也就是 `i` 是从 1 开始循环，一直循环到几呢？`n` 是等于 4 嘛，所以他就从 1 一直循环到 4，也就是分别去处理 1、2、3、4：先固定 1，然后再固定 2，再固定 3，再固定 4。

那每次处理的时候，我是不是应该把当前这个数字先给它加入到这个 `stack` 这个集合中啊？比如说我们当 `i` 等于 1 的时候，那我应该先把 1 加到这个集合中，要用 `push` 把它加进去。

加进去之后，我们是不是应该再做一个递归处理啊？相当于固定了 1，接下来再去尝试固定后面的 2、3、4 这几个数字，也就是第二层的这个递归。

那第二层递归呢，显然这个 `dfs` 还需不需要从 `start` 开始？不需要了吧。因为 1 已经固定了，接下来我们是不是应该从 2 开始进行后续的递归啊？所以这个递归操作我们应该从 `i` 加一开始，剩下的参数不用变啊，`n`、`k`、`stack` 和 `result` 都原样不动传过去就可以了。这个 `dfs` 相当于就做了这里的 1、2，1、3，1、4 这几个组合。

好，这个组合结束之后，我们该怎么做？我们的回溯的思想要把它恢复成最初的状态，也就是 `stack` 可以做一个 `pop` 操作，就把刚才的这个 1 移除。因为我们把 1 移除了才能恢复到最初的状态，再尝试去固定 2，对吧？再尝试固定 2、固定 3、固定 4 这些。所以我们有一个 `push`，就必然有一个对应的 `pop` 操作。

这是我们的这个循环，写好之后呢，我们的代码其实就完成了。我们可以测试一下，看一下啊，是不是能找到我们这六种组合。走一遍：1、2，1、3，1、4，2、3，2、4，3、4，找到了。

那如果我把这个 `k` 改成三啊，这个我们刚才也分析过，一共有四种结果，分别是 1、2、3 组合，1、2、4 组合，1、3、4 组合和 2、3、4 组合，是不是结果都是正确的呀。

### start 为什么必须是 i + 1

可能很多同学对我们递归调用时，为什么要给 `start` 传递一个 `i` 加 1，不是很理解。那针对这个问题呢，我们再给大家多讲一讲。

我就以这个网页为例吧。网页的代码其实跟我们 Java 代码是一致的，不过网页的好处就是左侧的源代码修改了，右边我一刷新大家就能看到它的效果。

那你看我举这么一个反例：我在递归调用时啊，我们不给他传递 `i` 加一了，我就给他传递一个 1。传递 1 意味着什么呢？意味着每次循环的时候，`i` 它是固定从 1 开始遍历，一直到 `i` 小于等于 `n`。那这样的业务含义是什么呢？我们刷新一下页面大家来看一下啊，跳到最后一帧：

```text
pass 1 :  dfs(n, k, 1, ...)
          12 13 14
          21 22 23 24
          31 32 33 34

this is no longer combination -- it is PERMUTATION
```

这个业务含义是什么？唉，就是并不是在求我们这四个数字的组合了，而是在求这四个数字的什么排列。你看这里 1、2 啊，跟这里的 2、1 他们从排列的角度确实是不一样的啊，但是从组合的角度，他俩就是重复的；类似的，这里的 1、3 跟这里的 3、1 也是重复的。

那我们要避免这个重复，那怎么办呢？就不能每次从 1 开始。那从哪开始呢？比如说我们先从 `i` 开始，可以吧？从 `i` 开始呢，就是说它的效果就是 1、1，1、2，1、3，1、4，这是第一轮循环；但是第二轮再循环的时候，2 是不是下次递归的时候也是跟 2 去组合，2、2，2、3，2、4，这边是 3、3，3、4，4、4。

但是我们组合里 1 跟 1 自己不能组合对吧？它是要跟别人组合。跟谁组合呢？跟比他大的那个数字啊，比他大一的那个数字，从这个数字开始向后一直到 `n` 去组合。

所以才有了我们这里的 `start` 等于 `i` 加一。这里是为什么我们 `start` 要传递一个 `i` 加一的原因，看同学们清楚了吧。

给定一个数字数组，返回它所有可能的排列结果。

## 组合问题的回溯与剪枝
> 对应块：BLK39 | 覆盖分集：P169-P172 | 块标题（分集名）：《进阶数据结构和算法-323-组合-Leetcod》

上一题的代码我们跑通了，但它有点"胖"——递归树里挂着一堆注定凑不出答案的分支，走到底才发现白走了一趟。今天干的事就一件：给这段代码做点**减脂**，把不必要的递归过滤掉。

顺着这个思路，我们再一路做三道组合总和的题：数字可以重复用、每个数字只能出现一次、从 1~9 里挑 K 个数凑 N。三道题一个比一个多一道限制，而限制怎么落到代码里，就是这条线索。

### 先给 77 题的代码做减脂

77 题长什么样大家还记得：`1~n` 里挑 `k` 个数字组合。我们先把 `k` 改成 3，`n` 是 4，然后盯着递归树看。

> **定义**：这一层的递归要做的事是——在 `i` 位置固定一个数字，然后往下递归。所以判断"这层递归值不值得走"，只需要看两件事：**还差几个数字才能凑满**，以及**手上还剩几个数字可以拿**。

先看最明显的那个例子。原代码里 `4` 这条分支——固定了 4 之后，栈里就一个 4，身后再没有别的数字了，它凑出来的组合长度是 1，我们要的是 3，这显然白干。但这个例子还不够明显，我把 `k` 改成 3 就清楚了：`[1,4]`、`[2,4]`、`[3,4]` 以及 `4` 本身这几条分支，全都跑到 4 就没得跑了，而它们的个数都是 2、2、2、1，统统不够 3。

那么怎么把这个判断写进代码？先想清楚那两个数怎么算。

第一个：**还缺几个数字**。这个太容易了——总共要 `k` 个，栈里存的就是**已经固定下来的数字个数**，所以：

$$\text{还缺} = k - stack.length$$

> **提示**：`stack` 天然就是"已固定数字"的计数器，不用再单独维护一个变量。

第二个：**还能用的数字有几个**。`n` 是右边界，我们当前正在处理的位置是 `i`，从 `i` 到 `n` 一共是 $n - i + 1$ 个数字，这就是我们**备用的数字个数**。

$$\text{备用} = n - i + 1$$

我拿板书上的那几个状态对一遍，你就能看出这两个数在跳：

| 当前栈 | 还缺几个（k=3） | 还能用的数字 | 判断 |
| --- | --- | --- | --- |
| 空 | 3 | 1、2、3、4 → 4 个 | 够，继续 |
| `[1]` | 2 | 2、3、4 → 3 个 | 够，继续 |
| `[1,2]` | 2 | 2、3、4 → 3 个 | 够，继续 |
| `[1,3]` | 2 | 3、4 → 2 个 | 正好够，继续 |
| `[1,4]` | 2 | 只有 4 → 1 个 | 不够，剪掉 |

> **结论**：**缺的数字个数 > 备用的数字个数**，就说明这条分支注定凑不满，直接 `continue`，连递归都不用进。

代码先在 JavaScript 里写，`k - stack.length > n - i + 1` 就一个 `if`；搬到 Java 几乎不用改，唯一要留神的是 Java 里 `stack` 是集合，没有 `length`，得用 `size()`：

```java
void dfs(int n, int k, int start, LinkedList<Integer> stack,
         List<List<Integer>> result) {
    if (stack.size() == k) {
        result.add(new ArrayList<>(stack));
        return;
    }
    for (int i = start; i <= n; i++) {
        // 还缺的数字个数，大于还备用的数字个数，这条分支没戏
        if (k - stack.size() > n - i + 1) {
            continue;
        }
        stack.push(i);
        dfs(n, k, i, stack, result);
        stack.pop();
    }
}
```

效果对比非常直观：剪之前 `[1,4]`、`[2,4]`、`[3,4]` 这些分支全在树上；剪之后它们全没了，只剩 `[1,2,3]`、`[1,2,4]`、`[1,3,4]`、`[2,3,4]` 四个组合。答案一个字没变，树的规模小了一大截。

### 组合总和：数字可以重复使用

新题叫**组合总和**。给你一个**候选者数组**，数字互不重复；你从里面挑数字做组合，组合出来的和等于 `target`，就算找到一种组合。

这里有个关键前提，比 77 题松了一大截：**同一个数字可以被重复取**。

- `candidates = [2, 3, 6, 7]`，`target = 7`，答案是 `2 + 2 + 3` 和 `7` 单独一个，两个解。注意 2 出现了多次，题目允许。
- `candidates = [2, 3, 5]`，`target = 8`，能凑出三种：`2 + 2 + 2 + 2`、`2 + 3 + 3`、`3 + 5`。
- 如果压根凑不出来，返回空数组。

#### DFS 的参数和 target 的三种含义

求组合的 DFS 一般都要带一个 `start` 参数——遍历候选数组时的起点索引。求排列不需要，因为排列每层都从 0 开始重新挑；**组合必须限制起点，不然会算出同一组合的多种排列**（`2+2+3` 和 `2+3+2`）。这个参数先记住，到后面那道题它还要再改一次。

`target` 这个参数我得多啰嗦几句，因为它在递归过程中会一直变：

- 一开始它的值是 7；
- 每固定一个数字，就用 `target` 减去这个数字——固定了 2，`target` 就变成 `7 - 2 = 5`；
- `target == 0`，凑满了，找到解；
- `target > 0`，还没凑够，继续递归；
- `target < 0`，爆了，这条分支可以直接退出。

剩下两个是老熟面孔：一个 `LinkedList` 类型的 `stack` 存**当前这条路径**，一个更大的 `result` 存**所有解**。

于是终止条件就是两种：

```java
if (target < 0) {
    return;                          // 爆了
}
if (target == 0) {
    result.add(new ArrayList<>(stack));   // 凑满，把当前路径复制一份收下
    return;
}
```

`target > 0` 就进入循环继续干活。

#### 一条完整的回溯轨迹

循环体是这段代码的核心，从 `start` 循环到 `candidates.size() - 1`。每次循环做三件事：

1. 拿到当前数字 `candidates[i]`，把它 **固定**——`stack.push(candidates.get(i))`，push 进去就相当于这个数定下来了；
2. 带着它往下递归：`dfs(candidates, i, target - candidates.get(i), stack, result)`；
3. 递归返回后**恢复现场**——`stack.pop()`，回溯，这一步千万别忘。

> **易错点**：递归时传下去的起点是 `i`，不是 `i + 1`。因为这题数字可以重复用，固定了 2 之后，下一次还得能跟 2 组合，所以起点原地不动。

注意 `target` 那一项：每次固定一个数字，就从原来的 `target` 上减掉它。固定了 2，下次递归 `target` 就是 5 了。`stack` 和 `result` 原样传下去就行。

按这个骨架跑 `candidates = [2, 3, 6, 7]`、`target = 7`，递归树是这样（带剪枝的版本我最后才补，先看它该长什么样）：

```text
dfs(start=0, target=7, stack=[])
├─ i=0 固定 2 → dfs(start=0, target=5, stack=[2])
│   ├─ i=0 固定 2 → dfs(0, 3, [2,2])
│   │   ├─ i=0 固定 2 → dfs(0, 1, [2,2,2])
│   │   │   └─ i=0 固定 2 → dfs(0, -1, [2,2,2,2]) → target<0 爆掉
│   │   ├─ i=1 固定 3 → dfs(1, 0, [2,2,3]) → target==0 ✓ 收下
│   │   ├─ i=2 固定 6 → dfs(2, -1, [2,2,6]) → 爆掉
│   │   └─ i=3 固定 7 → dfs(3, -2, [2,2,7]) → 爆掉
│   ├─ i=1 固定 3 → dfs(1, 2, [2,3])
│   │   ├─ i=1 固定 3 → dfs(1, -1, [2,3,3]) → 爆掉
│   │   ├─ i=2 固定 6 → 爆掉
│   │   └─ i=3 固定 7 → 爆掉
│   ├─ i=2 固定 6 → dfs(2, -1, [2,6]) → 爆掉
│   └─ i=3 固定 7 → dfs(3, -2, [2,7]) → 爆掉
├─ i=1 固定 3 → dfs(1, 4, [3])
│   ├─ i=1 固定 3 → dfs(1, 1, [3,3])
│   │   ├─ i=1 固定 3 → dfs(1, -2, [3,3,3]) → 爆掉
│   │   └─ i=2、i=3 固定 6、7 → 都爆掉
│   ├─ i=2 固定 6 → 爆掉
│   └─ i=3 固定 7 → 爆掉
├─ i=2 固定 6 → dfs(2, 1, [6])
│   └─ i=2、i=3 固定 6、7 → 都爆掉
└─ i=3 固定 7 → dfs(3, 0, [7]) → target==0 ✓ 收下
```

读图要点：数满 `target` 的 `✓` 只有两处，对应 `[2,2,3]` 和 `[7]` 这两个解；满屏的"爆掉"就是我们要干掉的那些递归。你看 `[2,2,2]` 那一层，明知道还差 1，却还得老老实实去试 2、3、6、7 四个数字，然后每一个都爆——这些就是纯浪费。

#### 把取负数的分支剪掉

现在动手。已经组合到 `[2,2,2]`，还差 1 才凑满 7。备选数字是 2、3、6、7——**不管挑哪个都只会更大**，`1` 跟它们任何一个相加都超过了目标，还有必要递归吗？没必要。

> **结论**：**剩余的 `target` 比当前候选数字还小，这条分支直接 `continue`**。

把检查放在递归之前：

```java
void dfs(List<Integer> candidates, int start, int target,
         LinkedList<Integer> stack, List<List<Integer>> result) {
    if (target < 0) {
        return;
    }
    if (target == 0) {
        result.add(new ArrayList<>(stack));
        return;
    }
    for (int i = start; i < candidates.size(); i++) {
        // 还差 1，可候选数字最小是 2，加上必然超出，直接进入下一轮循环
        if (target < candidates.get(i)) {
            continue;
        }
        stack.push(candidates.get(i));
        dfs(candidates, i, target - candidates.get(i), stack, result);
        stack.pop();
    }
}
```

> **提示**：剪枝之后代码里有一个副作用值得注意——`target` 永远不会再变成负数了，因为能被选中的数字一定满足 `target >= candidates.get(i)`，减去之后还是非负。所以 `if (target < 0) return;` 这个分支可以直接删掉。但你**不剪枝就一定不能删**——加了剪枝才敢删，这两件事是配套的。

最终答案还是那两个组合，结果没变，递归次数少了很多。

### 组合总和和零钱兑换，背景其实是同一个

最后关于这道题多啰嗦一句。它在问题背景上，跟我们之前做的**零钱兑换**是一模一样的：

| | 组合总和 | 零钱兑换 |
| --- | --- | --- |
| 候选者数组 | 不同面值的硬币 | 不同面值的硬币 |
| `target` | 要凑的总金额 | 要凑的总金额 |
| 要求 | 把**所有**组合的具体信息都求出来 | 求**最值**或**汇总**信息 |

差别只在"要什么答案"。组合总和要的是具体信息——套到零钱兑换的语境里，就是"为了凑出 7 块钱，我到底要哪几枚硬币"，你得把 `[3,3,1]` 或者 `[7]` 这种具体方案全部列出来。这种题没法用汇总信息糊弄过去，只能用回溯加剪枝把所有组合可能都翻出来。

而零钱兑换要的是"所有组合里用到的硬币数最少的是哪个"——上面这个例子一个用了 3 枚，一个用了 1 枚，最少就是 1 枚；还有一种考法是问组合的**总共有几种**。这类问题求的是 `min`、`max`、`sum`、`count` 这样的汇总信息，用**动态规划**更合适。

> **结论**：问"要所有方案"→ 回溯；问"要最优值或总数"→ 动态规划。两类问题背景一样，解法分道扬镳。

### 组合总和 II：每个数字只能用一次

第二道叫**组合总和 II**，也是给数组、组合后的和要等于 `target`。但它和上一道有**两点**区别：

第一点，上一道里数字可以重复出现——2 可以出现多次，3 也可以多次；这一道要求**数组里的每个数字只能出现一次**，不能重复。

第二点，最终结果里**不能包含重复的组合**。有同学要问了：每个数字只用一次，怎么还会重复？看题给的数组——**它本身就可能给你两个重复的 1**。不加考虑的话，这两个 1 就会造出重复的组合来。

#### 先让每个数字只出现一次

既然是从上一道搬过来的代码，那就别从头写了，直接搬：终止条件、剪枝、递归体，全都还能用，搬过来在这个基础上改。

用原代码先跑一遍，一大堆结果都是不符合题意的——`1` 出现了五次六次。每个数字只许用一次，你这个组合里最多只能有两个 1（一个 1 加一个 1 撇），不可能有那么多 1。

问题的突破口就在 DFS 的第一个参数 `start`。看：现在处理到 `1` 了，下次递归的循环又是**从 `1` 自己所在的索引位置开始**的，也就是 1 跟 1 组合到一起去了。怎么让 1 不要跟自己组合，而是跟它后面的数字组合？

> **结论**：把这个 `start` 从 `i` 改成 **`i + 1`**。固定了 `i` 之后，下次递归就从 `i + 1` 往后选，每个数字自然只出现一次。

改完再跑，重复少多了。`1` 出现了一次，1 撇也出现了一次，后面每个数也都是各出现一次——第一个需求满足了。

#### 再把重复的组合干掉

但结果还是不对。你看这里的 `[5,2,1]` 跟那里的 `[5,1,2]`，从组合的角度看是重复的；`[7,1]` 跟 `[1,7]` 也是重复的。

为什么？因为我们没法区分"这个 1"和"这个 1 撇"——`[5,2,1]` 里的一确实是第一个 1，而 `[5,1,2]` 里的一对应的是后面那个 1 撇；`[7,1]` 的一对应的是 1，`[1,7]` 的一对应的是 1 撇。看着像重复，其实只是同一批数字的两种排列。

这个需求我们前面讲**全排列 II** 的时候见过，所以直接搬老思路：先对数组**排序**，目的是让重复的数字彼此相邻，然后在这个基础上做去重。

怎么去重？我定一条规矩：**必须先使用 1，再使用 1 撇**。所以处理 1 撇的时候，先看前面那个 1 有没有被用过——如果还没用过，说明这是个非法情况，跳过去。

为了记录每个数字有没有被使用过，需要再加一个**布尔数组 `visited`**，初始长度和候选数组保持一样长，递归调用时一起传进去。

具体的判断分三步：

1. 先看当前 `i` 位置的数是不是和**上一个**数相等，上一个数就是 `candidates[i - 1]`；
2. 相等的话，再看**上一个**这个数有没有被访问过——`visited[i - 1]` 是不是 `false`，`false` 就是没访问过，说明 1 撇抢在了 1 前面，非法，`continue`；
3. 别忘了防越界：`i` 必须大于 0，否则 `i == 0` 时算 `i - 1` 就越界了。

> **易错点**：`visited[i] = true` 要在递归**之前**设置，递归结束之后还要**回溯**成 `false`。忘了回溯，后面的分支就会看到一个脏的访问标记，去重就彻底乱了。

完整代码：

```java
void dfs(List<Integer> candidates, int start, int target,
         LinkedList<Integer> stack, List<List<Integer>> result,
         boolean[] visited) {
    if (target < 0) {
        return;
    }
    if (target == 0) {
        result.add(new ArrayList<>(stack));
        return;
    }
    for (int i = start; i < candidates.size(); i++) {
        if (target < candidates.get(i)) {
            continue;
        }
        // 同值去重：当前数和上一个数相同，但上一个数还没被用过，跳过
        if (i > 0 && candidates.get(i) == candidates.get(i - 1) && !visited[i - 1]) {
            continue;
        }
        visited[i] = true;
        stack.push(candidates.get(i));
        dfs(candidates, i + 1, target - candidates.get(i), stack, result, visited);
        stack.pop();
        visited[i] = false;          // 回溯，别忘了
    }
}
```

再运行，`[5,2,1]` 只剩了一个，下面的那个没了；`[7,1]` 也只剩一个。重复的组合全部消除。

### 组合总和 III：从 1~9 里挑 K 个数凑 N

第三道叫**组合总和 III**：从数字 `1~9` 里挑，每个数字**最多使用一次**，挑出来的这些数字要满足两个条件。

- `k`：要使用的数字个数。比如 `k = 3`，就是从 1~9 里挑 3 个数字；
- `n`：这 3 个数字加在一起要等于 `n`。

题目给的例子：`k = 3`、`n = 7`，答案是 `1、2、4`（加起来正好 7）。再来一个，`k = 3`、`n = 9`，答案是 `1、2、6`、`1、3、5`、`2、3、4` 三组。

这道题跟我们之前做的 77 题特别像，也是两个参数。但**两个 N 的含义完全不一样**，这里最容易绕晕：

- 77 题里的 `n` 代表**数字的范围**，从 1 到 `n` 里挑 `k` 个数组合；
- 这道题里的 `n` 代表**组合后的和**，从 `1~9` 里挑 `k` 个数，它们的和要等于 `n`。

所以为了区分，我把**这道题里的 `n` 改名叫 `target`**。循环也随之变了——不再是 1 到 `n` 循环，而是固定从 1 循环到 9；剪枝代码里那个 `n` 也固定写成 9。

代码大部分直接从 77 题搬过来，改名、加上 target 的减法就行。但一跑就知道结果不对：它把从 1~9 挑 3 个数的**所有组合**都列出来了，`[1,2,3]`、`[1,2,4]`、`[1,3,...]` 全在，完全没有"和等于 7"这个约束。

怎么把这个约束加进去？每次固定一个数字 `i` 之后，用 `target` 减掉 `i`，传下去。这样 `target` 的含义就变成了"**还差多少才能凑满**"，它在递归的终止条件里减到 0，就代表刚好凑满一个合法组合，这时候返回就行。

#### 两条真正有效的剪枝条件

改完约束这步，答案对了——从 1~9 挑 3 个数、和为 7，就是 `[1,2,4]`。但效率很低，还挂着 77 题那条不太管用的剪枝。

> **提示**：想知道剪枝有没有用、到底省了多少，最笨也最管用的办法就是**数一下**：定一个 `count`，初始值 0，每次进递归就 `count++`，跑完直接看 `count` 的值。这招土，但在你没想清楚复杂度的时候，比拍脑袋靠谱得多。

**第一条：`target < i` 就剪。**

`target` 代表剩余的和，它应该大于等于 `i`——因为每次要减去的就是 `i`，它必须大于或等于 `i`。如果反过来 `target < i`，这一减就减成负数了，负数肯定不满足最终要求，干脆别递归，直接 `continue`。

加上这条之后，`k = 3、n = 7` 这个用例的递归次数**从 480 次掉到 19 次**，断崖式下降。

**第二条：`stack.size() == k` 就剪。**

`stack` 里存的就是已经挑好的数字。如果它已经等于 `k` 了，说明数已经挑够了，但 `target` **还没等于 0**——这种情况下我需要再挑一个数字继续递归吗？不需要。就算再挑一个能让 `target` 减成 0，**数字的个数也超了**。所以在还没超之前，就该 `continue`。

这条在 `k = 3、n = 7` 上看不出效果，还是 19 次——因为这个测试用例对这条条件不敏感。换一个更有说服力的：挑 **2** 个数字凑 **18**。这个根本无解，因为最大的 9 加次大的 8 也就 17。

不加这条剪枝的时候它调了 **167 次**。为什么这么多？把 `stack` 每次的结果打出来一看就明白了——它在那儿不停地组合，**都组合到五个数字了还是没凑够**，可人家要的只有两个数字。加了这条之后，只剩 **46 次**。

#### 剪枝条件加不加，到底听谁的

汇总一下计数器上的数字：

| 剪枝配置 | `k=3, n=7` | `k=2, n=18` |
| --- | --- | --- |
| 什么都不剪 | 480 | — |
| 只加 77 题那条 `k - size > n - i + 1` | 470 | — |
| 再加 `target < i` | 19 | 167 |
| 再加 `stack.size() == k` | 19 | 46 |
| 把 77 题那条也加回来 | 18 | — |

> **结论**：真正干活的是 `target < i` 和 `stack.size() == k` 这两条；而最开始从 77 题**沿用**下来的那条剪枝，加不加都差不多——加上也才少一次调用。**从别的题搬过来的剪枝条件不一定适合新题，一定要自己量一量再决定留不留。**

`target < i` 这条剪枝加进来之后，终止条件里那个 `target < 0` 的分支同样可以去掉了——能被选中的数字一定满足 `target >= i`，减完不可能是负数。

```java
void dfs(int k, int target, LinkedList<Integer> stack, List<List<Integer>> result) {
    // 挑够 k 个数，而且刚好凑满，这才是一个合法解
    if (stack.size() == k) {
        if (target == 0) {
            result.add(new ArrayList<>(stack));
        }
        return;
    }
    for (int i = 1; i <= 9; i++) {
        if (target < i) {
            continue;                     // 剪枝一：再减就成负数了
        }
        if (stack.size() == k) {
            continue;                     // 剪枝二：数已挑够，和却不对
        }
        stack.push(i);
        dfs(k, target - i, stack, result);
        stack.pop();
    }
}
```

## N皇后与解数独：把冲突记进数组，用回溯试错
> 对应块：BLK40 | 覆盖分集：P173-P175 | 块标题（分集名）：《进阶数据结构和算法-327-N皇后-Leetco》

这节课我们来做一道力扣题，N皇后。

皇后是国际象棋里的一种棋子，它可以攻击与它同行、同列，或者同一条斜线上的其他棋子。N皇后问题就是：给你一个 N×N 的棋盘，让你摆上 N 个皇后，让皇后之间彼此不能相互攻击，问一共有多少种摆法。

我们先看一个 8×8 的棋盘。

我先随便摆一个皇后。摆完之后，它的同一行不能再摆其他皇后，同一列也不能，包括它的两条斜线上也不能再放其他皇后了——最后要在整个棋盘上摆满八个皇后，才算找到一种解。这就是 N皇后问题。

### 1600 多万种排列里，捞出 92 个解

那这个 N皇后问题为什么说它难呢？就拿它的原始问题——八皇后来说。

我们要在棋盘上排列这八个皇后，一共有多少种排列可能呢？是 8 的 8 次方，1600 多万种。我们要在 1600 多万种排列里，找到八个皇后不能相互攻击的这么一种情况，无异于大海捞针。这个计算量对当时来讲非常大，就算是那个年代非常著名的数学家高斯，他也只认为这个八皇后有 76 种方案——而实际上，八皇后问题的解有 92 种。

时至今日，用计算机求解这个问题就非常简单了，甭管是八皇后还是九皇后，都能迅速求解。待会儿我们会用大约 20 行左右的代码，把 N皇后问题给它解决了。

### 先手工把 4 皇后走一遍

我们以一个最简单的 4 皇后问题来说明求解思路。要往 4×4 的棋盘里放入皇后，我们不妨就从第一个格子开始尝试放入。

往第一个格子放入第一个皇后之后，它的同行、同列以及同一斜线上的这些格子，我们是不是应该做一个标记——我把它标记成红色，这些格子表示有冲突了。再放入接下来皇后的时候，就不能往这些红格子里放，而只能放白色的格子里。

```text
         j=0   j=1   j=2   j=3
  i=0      Q     x     x     x
  i=1      x     x     .     .
  i=2      x     .     x     .
  i=3      x     .     .     x

  x = 与已放皇后冲突，不能放
  . = 空闲，可以放
```

所以下面我们再放入第二个皇后的时候，就挑选第二行一个空着的格子放入。

放进去行不行呢？显然不行。你看第三行是不是所有格子都冲突了。我们一共要放四个皇后呢，第三行都冲突了，那皇后数量肯定不够。

怎么办？把刚才放第二个皇后的动作给它撤销掉——放错了，就得撤销。撤销可以用我们之前讲过的回溯技巧。撤销掉以后，我们再尝试下一个格子。

放到下一个格子之后，好像有转机了，第三行又能放第三个皇后了吧？但显然也不行，因为第三个皇后放进去之后可以看到所有的格子都冲突了，不能再放入第四个皇后。所以这个方案也被废弃。

怎么办？再撤销。第三个皇后撤销，第二个皇后需要撤销——肯定得撤销，因为第二行的这两个格子我们都尝试过，都不行。第一个呢？也得撤销。显然刚才这几条路都走不通，所以我们把第一个格子的皇后也撤销掉。

这回我们往第一行的第二列里放入第一个皇后。接下来第二行可以放入第二个皇后，没问题吧；第三行也可以放入一个皇后；最后一行又可以放入一个皇后。这样我们就找到了一个解，这四个皇后互不冲突。

找到第一个解之后，事情还没完，因为也有可能还有更多的解。所以我们再把刚才填满的这四个皇后都给它撤销掉，再尝试第一行的第三列放入皇后。这时候我们再去尝试往第二行放入第二个皇后，往第三行放入第三个皇后，好像也行，最后可以往第四行放入第四个皇后——这样我们又找到了第二个解。

继续撤销。这回该尝试第一行的第四列放入第一个皇后，然后重复这个过程：尝试放入第二个皇后，尝试放入第三个皇后，结果发现不行，那就撤销，重新在一个空白的无位置放入第二个皇后，显然这样也没法放第三个皇后。

其实走到这儿我们已经无需再尝试了，因为第一行的四个列都尝试过了，他再撤销就没了。至此为止，四皇后问题就找到了两个解。

> **结论**：N皇后就是「一行放一个，行内枚举列，冲突就跳过，放不下去就撤销」的循环。

### 三个数组，把冲突记下来

刚才的分析过程中大家都注意到了：我放入一个皇后以后，就要把它冲突的那些格子记录下来——同一行的、同一列的、左斜线上的、右斜线上的。到底哪些格子需要记录、又该怎么记录呢？我们接着来看。

#### 同一行不用记，同一列要记

先看同一行的冲突需不需要记录。其实不需要。

为什么呢？你看我们刚才怎么处理的：往这一行加入了一个皇后以后，下次我尝试的时候是不是直接到下一行去尝试放入皇后了？这行我根本都不用试。所以同一行的冲突我们不需要记录。

同一列的冲突呢？这个我们需要记住。怎么记录呢？我们可以定一个布尔数组，就叫 `cols`。它的大小应该是几？4×4 的棋盘里有四列需要记住，所以它的大小是四。

刚开始这个数组里是四个 false。比如我现在往第零列放了一个皇后，那我就可以把这个数组索引为 0 位置的 false 给它改成 true。下次你再放入其他皇后的时候，就到这个数组检查一下，如果它的第零列是 true 了，那还能不能放皇后？是不是就不行了。所以我们就可以用这个数组来记录列上的冲突。

#### 左斜线：编号就是 i + j

在记录左斜线冲突之前，我提一个问题：对于我这个 4×4 的棋盘来讲，有多少条左斜线呢？

可能有的同学第一反应是有四条。不是啊，我们数一下——第一条、第二条、第三条，我们这个皇后所在的是第四条，然后第五条、第六条，最后还有第七条。4×4 的棋盘一共有七条左斜线。

这个规律我直接告诉大家：它就是 2N 减 1。4×2 等于 8，8 减 1 等于 7，所以 4×4 的棋盘有七条左斜线。那如果将来你是一个八皇后，也就是 8×8 的棋盘，那就是 16 减 1 等于 15 条左斜线。这个左斜线的个数大家也要知道。

那现在问题来了：比如说我们现在已经知道了某个单元格，我怎么知道这个单元格对应的那条左斜线上有没有冲突呢？

我们把每个单元格的行坐标称之为 i、列坐标称之为 j，把 i 加 j 的结果显示到单元格上：

```text
          左斜线编号 = i + j

         j=0   j=1   j=2   j=3
  i=0      0     1     2     3
  i=1      1     2     3     4
  i=2      2     3     4     5
  i=3      3     4     5     6
```

数字相同的这些单元格，就对应着一条左斜线。比如我们刚才这个皇后，它是在第二行第一列，2 + 1 = 3；再比如说这个单元格在第零行第三列，0 + 3 是不是也等于三——这就造成了它俩实际上都对应着斜线 3。

你看现在一共有从 0 到 6，是不是七条斜线。所以我们把单元格 i 加 j 的结果，就可以对应到它们各自相应的左斜线上了。

写成代码也很简单。我们可以再定一个数组，这个叫做 `diag1`，它的长度是 2N 减 1，我们这个例子是七。它记录的是左斜线的冲突，单元格的 i 加上 j 就对应着它是第几条左斜线，取值是 true 表示有冲突，false 表示没有冲突。

#### 右斜线：(N-1) - (i - j)

跟上了的话，接下来右斜线的冲突处理就是类似的了。同样的我们一共有七条右斜线，也是 2N 减 1，7 减…… 2×4 减 1 等于七条右斜线。

那我们也是观察一下 i 减 j 的结果跟这七条右斜线之间的对应关系：

```text
          i - j 的原始值（存在负数）

         j=0   j=1   j=2   j=3
  i=0      0    -1    -2    -3
  i=1      1     0    -1    -2
  i=2      2     1     0    -1
  i=3      3     2     1     0
```

数字相同的就分别对应一条右斜线，一共有七个不同的数字对应着那七条右斜线。但是这回我们的数字里有负数，负数将来不好跟数组的索引对应，所以我们得把这个负数给它消除掉。

办法就是用 N 减 1 再减去刚才 i 减 j 的差。N 是 4，4 减 1 是 3，3 减去刚才的差：这里的 -3，3 减 -3 是不是就等于六？这里的 -2，3 减 -2 是不是等于五？最后这边 3 减 3 是零。这样我们就把刚才的负数消去了：

```text
          右斜线编号 = (N - 1) - (i - j) = 3 - i + j

         j=0   j=1   j=2   j=3
  i=0      3     4     5     6
  i=1      2     3     4     5
  i=2      1     2     3     4
  i=3      0     1     2     3
```

这样我们也是得到了从 0 到 6，七条对应的右斜线。代码这里也差不多了，我们再定一个数组叫 `diag2`，它的大小也是七，它记录的是右斜线上的冲突，对应关系就是 (N-1) 再减去刚才 i 减 j 的差。

至此为止，我们就用三个数组把列上的冲突、左斜线上的冲突以及右斜线上的冲突都可以记录下来。

> **易错点**：`i - j` 会取到负数，直接拿去当数组下标会越界。一定要加上 `(N-1)` 这个平移量，把它整体搬到 0 ~ 2N-2 这个区间里。

### 20 行代码把 N 皇后跑起来

在求解具体的过程之前，我们先来写一些准备的代码。

我先用一个二维的字符数组来代表这张棋盘，数组的名字叫 `table`。它的维度我就不把它写死成数字了，我们用一个 N 来代表它的维度——N 在我们这个例子中是 4，所以这个二维数组也是 N 行 N 列。那几个用来记录冲突的数组，我们也把它跟 N 关联起来：这里的四对应到 N，这里的七其实对应到 2N 减一，下面这个七也是 2N 减一。

我们先做一个初始化。这里来一个约定：如果每个单元格没有放置皇后，我们就放一个字符点；如果这个单元格放到了皇后，我们就把它改成一个 Q。用这两种字符来代表没有放置皇后和放了皇后。

```java
import java.util.Arrays;

public class NQueens {

    /**
     * i     —— 当前处理第几行
     * n     —— 棋盘维度
     * table —— 棋盘本身，记录皇后放在哪儿
     * cols  —— 列冲突
     * diag1 —— 左斜线冲突，编号 i + j
     * diag2 —— 右斜线冲突，编号 (n - 1) - (i - j)
     */
    private static void dfs(int i, int n, char[][] table,
                            boolean[] cols, boolean[] diag1, boolean[] diag2) {

        // 递归结束条件：所有行都填满了，说明找到一个解
        if (i == n) {
            System.out.println("--------- 找到一个解 ---------");
            for (char[] row : table) {
                System.out.println(new String(row));
            }
            return;   // 找到一个解就直接返回，不再往下递归
        }

        // 每一行进来，都要在不同的列上尝试放入皇后
        for (int j = 0; j < n; j++) {

            // 冲突检查：列、左斜线、右斜线，任意一条冲突就跳过这一列
            if (cols[j] || diag1[i + j] || diag2[n - 1 - i + j]) {
                continue;
            }

            // 放入皇后，并记录它带来的三类冲突
            table[i][j] = 'Q';
            cols[j] = true;
            diag1[i + j] = true;
            diag2[n - 1 - i + j] = true;

            // 往下一行放皇后，剩余参数原封不动传过去
            dfs(i + 1, n, table, cols, diag1, diag2);

            // 回溯：不管递归成功还是失败，都把状态恢复成递归之前的样子
            table[i][j] = '.';
            cols[j] = false;
            diag1[i + j] = false;
            diag2[n - 1 - i + j] = false;
        }
    }

    public static void main(String[] args) {
        int n = 4;

        char[][] table = new char[n][n];
        boolean[] cols = new boolean[n];
        boolean[] diag1 = new boolean[2 * n - 1];
        boolean[] diag2 = new boolean[2 * n - 1];

        for (int i = 0; i < n; i++) {
            Arrays.fill(table[i], '.');
        }

        dfs(0, n, table, cols, diag1, diag2);
    }
}
```

几处要盯着看：

- **递归什么时候结束**。四个皇后都填满了，意味着 i 处理到第几行了呢？第零、第一、第二、第三行都处理完了，也就是 i 等于 N 的时候，表示没有更多的皇后要填了，相当于我们找到了解，这时候打印出来然后直接 return，不需要再继续递归。
- **行坐标有了，列坐标从哪来**。dfs 传过来的 i 代表的是每一行，那每一行进来我还是要去在不同的列尝试放入皇后——第零列、第一列、第二列、第三列。所以在方法内还得有一个针对列的循环。
- **冲突检查必须放在放入之前**。放入皇后之前先检查这个单元格是不是处在有冲突的位置，如果有冲突，就没必要进行放入皇后的操作，以至于之后的递归操作了，直接进入下一轮的循环，再尝试下一列。
- **回溯那两行是全篇最关键的**。你这个递归不一定能成功，万一遇到冲突，它应该撤销，撤销就是回溯到递归之前的状态。第 i 行第 j 列要改回那个点，递归调用之前那些冲突的标记是不是都应该改成 false？万一这个递归没有成功，退出递归的时候，应该由这两行代码把它恢复成递归之前的一个状态。
- **三条赋值可以合并**。刚才那三条 `= true` 的赋值语句，其实可以改成一条，也就是把这个 true 赋值给三个数组的相应位置。同理撤销那三条也是。这里我为了读起来清楚还是分开写，你自己写代码的时候可以合并。

> **提示**：调用 dfs 的时候第一个参数从第零行开始——是不是应该从第零行开始？把 0 传进去，剩下的参数照传就行了。

> **提示**：有人说你这个变量名起得不规范，这没关系，你只要好认就行。你知道哪个数组是记录列冲突的，知道哪个是记录左斜线冲突的，知道哪个是记录右斜线冲突的，这就够了，不要求非要你的变量名有什么特别好的可读性。

### 跑一下：4 皇后两个解，8 皇后 92 个解

找到解之后我们有一个打印语句，在这个打印语句中间加一个分隔线，打印一个分隔线，再打印具体解的内容。

运行。可以看到现在 N 等于四的时候，四皇后我们刚才已经验证过有两个解对吧？可以跟我们刚才图形化界面里比较一下——每一行皇后在第几列：第二列、第四列、第一列、第三列，2413，没问题吧？

然后这个呢，是在第三列、第一列、第四列、第二列，3142。是不是这两个解都是正确的呀？

同样的，你要求八皇后问题，你只需要把 N 改成八就可以了。当然这个咱们就不看了，它会打印出 92 个解，内容比较多，大家可以下去自己尝试。

> **易错点**：输出顺序不重要。枚举列的顺序是从第零列往右走的，所以先打出来的那个解，行列位置是 `1,3,0,2`，第二个是 `2,0,3,1`；换算成从 1 开始的说法就是 2413 和 3142。和图形界面上看到的解对得上，两个都是对的。

### 这道题的两个要点，一个都不能丢

最后对我们这道题做一个小结。求解 N皇后问题其实要点有两点。

第一个要点，我们利用了四个数组来记录各种状态。其中这个二维的字符数组 `table` 记录的是皇后的状态，也就是记录了棋盘上哪个位置、哪个单元格放置了皇后；还有三个数组用来记录的是冲突的状态。

第二个比较重要的，就是我们这个用来递归的方法了。这个方法是从第 21 行开始到第 39 行结束，总共用了不到 20 行的代码，就解决了我们的 N皇后问题。

那这个方法内有哪些我们值得注意的点呢？

第一个大家要清楚，我们这个方法是以行为单位来尝试对皇后进行放置的。你看它每次都是往第 i 行尝试去放入这个皇后，递归的时候也是往下一行来尝试放入这个皇后。那么每一行内，我们也要对它的不同列的位置进行尝试，所以内层呢它还有一个针对列的循环。

当我们确定了第 i 行第 j 列、确定了这个皇后的坐标之后呢，首先呢我们要做一个冲突检查，一旦发生了冲突，我们就不会进入后续的不必要的递归了，直接跳过这次递归，进入下一轮的循环，去尝试下一列。这在回溯的思想里有一个形象的说法：把这个避免不必要的递归，称之为剪枝的动作。

当然如果发现没有冲突，那么就往这个第 i 行第 j 列放入这个皇后，并且去记录它的冲突位置。记录好了冲突位置，接下来我们就递归，进行下一行的这个皇后的处理，去尝试下一行的皇后放入。

甭管这个递归是成功了还是失败了，有没有找到解，我们都要在递归结束之后把它的状态恢复成递归之前的状态——也就是取消第 i 行第 j 列这个皇后的放入，并且把冲突位置的标记成 false。

这也是我们这道题体现了一个非常重要的思想，就是回溯的思想：**在递归结束后要把状态进行恢复**。这就是这道题大家需要掌握的一些要点。

### 解数独：规则先行，套路和 N 皇后一模一样

我们再来看一道题目，解数独。数独是一种填字游戏，有些同学可能没玩过，我把规则给同学们介绍一下。

他会给你一张 9×9 的表格，这个表格里已经有一些数字填好了，留一些空白的位置让你去填写数字。填的数字从 1 到 9，但是他有三条规则。

#### 三条规则

我们以一个空格为例。这个空格它这一行呢能填哪些数字呢？注意看，这行里面相当于 1、6、7、9、5、8 都不能填了，你只能填 2、3、4，能理解吧？也就是每一行里 1 到 9 只能出现一次，这是第一条规则。

类似的呢，这一列里面 1 到 9 的数字也只能出现一次。你看这一列里 1、7、5、6、9、8、4 是不是已经出现了，所以剩下这两个空里你只能填二或者三了。这是第二条规则，每列里 1 到 9 也只能出现一次。

第三个规则呢，就是他把整个这个 9×9 的表格，可以再划分成九个小的九宫格。你看这是一个九宫格，后面这是第二个九宫格，以此类推我就不画了。比如说第一个九宫格里面你只能填一或者二了，因为 3 到 9 都已经填好了。也就是同一个九宫格内，我们这个 1 到 9 也只能出现一次。

```text
        行内不重复（规则一）
        ↓
    +-------+-------+-------+
    | . . . | . . . | . . . |
    | . . . | . . . | . . . |
    | . . . | . . . | . . . |   ↑
    +-------+-------+-------+   |
    | . . . | . . . | . . . |   |
    | . . . | . . . | . . . |   九宫格内不重复（规则三）
    | . . . | . . . | . . . |   |
    +-------+-------+-------+
    | . . . | . . . | . . . |
    | . . . | . . . | . . . |
    | . . . | . . . | . . . |
    +-------+-------+-------+

        列内不重复（规则二）
```

下面我给大家演示一下这个数独的解题过程。真正做起来是比较难的，因为它会留比较多的空格让你去填，通常好几个小时都不一定能求解出来。那我为了降低难度，把大部分空格都填好了，只留了少量的空格，我们来填写。

好，那我们每个空格逐一尝试呗。每个空格里面我们就把从 1 到 9 的数字逐一去尝试，看有没有冲突，没有冲突就填进去，有冲突我们再尝试下一个数字。

比如我们先从第一个空格开始，我先尝试填入 1，可以不可以呢？好像可以吧——你看它这一行、这一列，包括这个小九宫格内，是不是都没有 1 啊，所以这个 1 是可以填进去的。

好，那一个空格填好了，再去尝试下一个空格。这回还是从一开始尝试，但是这回填 1 是不是就不行了？因为你看行里有、列里是不是也有，冲突的，我会用红色标记出来。对，这里填 1 不行。没关系，我们再尝试填 2。填 2 好像可以吧？因为行里、列里，包括小九宫格里都没有 2，所以这个 2 是可以填进去的。

好，那我们再去尝试第三个空格。第三个空格也是从一开始，1 显然有冲突，再尝试 2，2 没有冲突，这就填好了。继续再尝试下一个空格。这样以此类推，我们就可以把整个棋盘填满，填满了那么这个解就求出来了。当然了，他这个题目会给你一个唯一的解，他不会让你无解或者是有多个解。

#### 填错了当场看不出来，所以必须回溯

通过刚才演示我们也大概清楚了这道题的求解思路：去不断遍历每个未填入数字的空格，然后呢咱们逐一去尝试填入 1 到 9。如果这个空格的所在行、所在列，还有所在的小的九宫格没有冲突，那么就可以把这个数字先给它**暂时**填入。

为什么说是暂时填入呢？因为有可能这个数字填的不对，虽然他这次没有冲突，但是接下来就未必了。那如果是发现我这个数字填错了，那我要回溯到上一个状态，咱们再换数字填入。

举个例子。我们看这时的一个状态，前面这些数字都已经填好了，我们填入了一个 2。这个 2 目前看起来没有冲突对吧？但是它是不是真的正确呢？我们在往下面接着看一下。

填入下一个空格的时候，先尝试 1 有冲突，再填入 2 有冲突。其实呢我们从这个小的九宫格能看出来，我们是不是应该填入 3？应该填入 3。但是填入 3 以后，我们发现是不是它跟列上另外一个 3 还是有冲突啊？那再没有别的数字了吧，你看 1 到 9 都用完了，所以说明前面这个 2 是填错了，因此我们就得回溯撤销。

当然了，我这个代码写的没有那么聪明。我发现 3 错了，但是我还得继续把 4 到 9 这几个数字都尝试完——四冲突、五冲突、六冲突、七冲突、八冲突、九冲突。好，开始撤销，把刚才这个 9 和上次这个 2 都给它撤销掉。2 撤销了就换另外一个数字，3 填入。当然 3 填入之后，大家发现是不是好了？没冲突了。这回呢我们下一个空格处再填入一个 2，这样就保证我们解题是正确的了。

也就是不是每次填入的数字都是正确的，有时候发现填错了，我们要进行回溯。

> **结论**：这也是回溯。跟 N皇后一样，只是冲突判定的维度从「行/列/斜线」换成了「行/列/九宫格」，而格子从一个皇后换成了一个 1 到 9 的数字。

通过刚才的讲解大家也发现了，关键点呢还是要把我们的冲突状态记录下来：行上的冲突状态、列上的冲突状态以及九宫格内的冲突状态，我们都要记录。这是我们的一个关键点。那下面我们就来看一下这些冲突状态。

### 三个二维数组，记录行列和九宫格

#### 行冲突：一维数组根本不够用

首先我们先来看这个行冲突状态。我们一共有几行呢？是不是一共有九行。那有同学说了：我会了，我们就定一个数组对吧，数组大小是九，将来用九个 true 和 false 来记录每一行有没有冲突。

那大家想一想，这样行不行呢？

注意这样不行啊。为什么不行？因为每一行是不是又有九个数字啊？你得知道这九个数字分别有没有被使用过。

比如说对于我们这里的第零行来讲，那其中呢 5、3、4、6、7、8、9 都被使用过了，那 1 和 2 还没有使用。所以呢我们 9 行每行 9 个数字，是不是有 81 种状态？你用一个一维数组根本不够记啊，不够。因此呢我们得把它改成一个二维数组。

将来我这个二维数组比如说 `rowConflict`，它是代表二维数组中的某一行，某一行的这个冲突记录。那某一行里面是不是又包含了这 9 个数字，分别有没有冲突啊，所以它里面还得再含 9 个布尔值。

> **易错点**：这里最容易踩的就是「顺手定一个长度 9 的布尔数组」。行冲突的语义是「第 r 行里，数字 d 被用过没有」，光有行号没有数字就区分不出来，所以必须是二维。

#### 列冲突：结构完全一样

那针对列冲突呢？是不是差不多啊。针对列冲突的话，那我们也得用一个二维数组。那么这时候的 `colConflict` 代表的是第几列。

比如说第零列，那每列里是不是也应该分成九个数字，这九个数字看他们有没有冲突啊。当然如果对于我们第零列来说：

| 数字 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 第零列是否冲突 | false | true | true | false | true | true | true | true | false |

1 是没有冲突的，是 false；2 和 3 是有冲突的，都是 true；4 没有冲突，是 false；5 已经有冲突，是 true；6 也是，7 也是，8 呢也是 true；最后 9 还没有填，可以使用，是 false。

理解了吧？这是我们行列冲突啊，都得用二维数组来记录。

#### 九宫格编号：(i / 3) * 3 + j / 3

那我们再来看一下九宫格的冲突状态。那我先问一下：一共有几个九宫格？是不是也是九个？你看从 0 到 8，是不是一共也是九个九宫格。

那我们首先呢要把某一个单元格跟九宫格的对应关系找出来，你得知道你这个单元格对应着几号九宫格。

比如说我们看这个单元格，它的行列坐标是第一行第七列。因为都是从零开始，那我怎么根据它的第一行第七列找到它的九宫格的编号呢？这里我就直接告诉大家答案了，它有一个对应关系：我们可以用它的行坐标 i 整数除法除以 3，再乘以 3，然后加上我们列坐标 j 整数除法除以 3。

$$box = \left( \frac{i}{3} \right) \times 3 + \frac{j}{3} \qquad \text{（两个除法都是整数除法）}$$

你看我们刚才那个，行坐标 i 是 1，列坐标是 7。那 1 除以 3，整数除法是不是 0？所以前半部分是 0；那 7 整数除法除以 3 是不是 2 呀？0 + 2，结果是不是等于 2 呀？所以我们发现，它是不是就对应到了 2 号九宫格。

再试一个，我随便再挑一个。比如说它吧，它的行坐标是 8，列坐标是 3。8 除以 3 除以 3 是多少？是 2，然后再乘以 3 是 6，前半部分是 6；那列坐标 3 除以 3 是 1，6 + 1 是不是等于 7 呀？所以我们发现也根据这个式子能求出这个单元格对应的是 7 号九宫格。

把这个式子铺到整个棋盘上，九宫格的编号长这样：

```text
              j=0  j=1  j=2  |  j=3  j=4  j=5  |  j=6  j=7  j=8
              ----------------------+--------------+--------------
    i=0         0    0    0   |   1    1    1   |   2    2    2
    i=1         0    0    0   |   1    1    1   |   2    2    2
    i=2         0    0    0   |   1    1    1   |   2    2    2
              ----------------------+--------------+--------------
    i=3         3    3    3   |   4    4    4   |   5    5    5
    i=4         3    3    3   |   4    4    4   |   5    5    5
    i=5         3    3    3   |   4    4    4   |   5    5    5
              ----------------------+--------------+--------------
    i=6         6    6    6   |   7    7    7   |   8    8    8
    i=7         6    6    6   |   7    7    7   |   8    8    8
    i=8         6    6    6   |   7    7    7   |   8    8    8
```

知道这个对应关系之后，我们也是用一个二维数组来记录九宫格内这些数字的冲突状态，我们叫个 `boxConflict`。将来我们也是通过刚才这个式子，根据单元格找到它对应的九宫格，那九宫格里是不是也得有九个 true 和 false 啊。

比如说就以刚才这个 7 号九宫格为例，他这里面得记录他这个九宫格内的数字有没有冲突：

| 数字 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 7 号九宫格是否冲突 | true | false | true | true | true | true | false | true | true |

1 有冲突，是 true；2 是没有冲突的，是 false；然后 3、4、5、6 都是有冲突的，那就再来四个 true；7 好像没有冲突对吧，那就来一个 false；然后 8 和 9 都是有冲突的，那么再来两个 true。

这个理解了吧？就是用一个二维数组记录九宫格的冲突状态，但是他得先找到我们单元格和九宫格的对应关系了，然后我们再进一步去确定这个九宫格内哪些数字冲突了、哪些数字没冲突。

至此为止呢，我们就用三个二维数组记录了行、列和九宫格的冲突状态。

> **易错点**：`(i / 3) * 3 + j / 3` 里的两个除法都必须是**整数除法**。写成浮点除法 `i / 3.0` 会得到小数，下标直接就废了。

## 从数独到三数之和：冲突表、双指针与降维递归
> 对应块：BLK41 | 覆盖分集：P176-P178 | 块标题（分集名）：《进阶数据结构和算法-330-解数独-Leetco》

数独写到一半，思路早就理顺了，代码却还差两块东西没落地。

一块是：棋盘上那些已经填好的数字，它们的行冲突、列冲突、九宫格冲突，现在还只是一句话，没有变成真正能被查的记录；
另一块是：找到一个空格以后，填哪个数字、填完退回来，这套回溯还没写出来。

先把这两块补上。数独收尾之后我们一路做两道题——有序数组上的两数之和、三数之和。说巧不巧，它们跟刚才这套回溯是同一套家什：**先想办法把不可能的选择提前筛掉，剩下的空间自然就越缩越小**。数独靠的是一张冲突表，两数之和靠的是一支排好序的数组，三数之和靠的是一层层降维。

---

### 先把棋盘上已有的数字的冲突状态记下来

原始的棋盘数组 `table` 会作为参数传进方法，我们先遍历一遍，把每一个已经填好的数字的冲突状态先给它记录下来。

双重循环，`i` 循环行，一共九行；`j` 循环列，也是一共有九列。拿到字符 `ch` 之后先做一个判断：如果它不是数字字符，也就是说它还是个点 `.`，表示这个格子还没填写，那这时候我们就不用去考虑它的冲突状态；只有当 `ch` 不是点的时候，才要记录——也可以叫初始化冲突状态。

这里有个特别容易搞错的地方，我们单独拎出来说。字符 `'5'` 要落到数组的索引 `4` 上，为什么？因为数字是从 1 开始的，索引是从 0 开始的。

> **易错点**：这里差的正好是一个字符 `'1'`。把字符 `'5'` 减去一个字符 `'1'`，它俩的差值就是我们要的索引值 `4`。反向也一样，往格子里填 `1` 时，要用 `(char)(1 + '0')` 把它变回字符 `'1'`。**"字符转数字减一，数字转字符加零"**，这一对操作会在这一讲里来回用，先记住。

```text
   table[i][j] = '5'        （i = 0, j = 2）
          │
          │  ch - '1'  →  4        数字从 1 开始，索引从 0 开始，正好差一个 '1'
          ▼
       索引 = 4
          │
          ├──▶  row[ i            ][4] = true    第 0 行 不能再放 5
          ├──▶  col[ j            ][4] = true    第 2 列 不能再放 5
          └──▶  box[ i / 3 * 3 + j / 3 ][4] = true
                     第 0 个九宫格 不能再放 5
                     0 / 3 * 3 + 2 / 3 = 0 + 0 = 0
```

三个数组，一一对应着三种冲突：`row[i][x]` 表示第 `i` 行里数字 `x+1` 已被占用，`col[j][x]` 是列，`box[k][x]` 是九宫格。九宫格的编号公式我们之前就推过——先根据单元格的行列坐标算出它是第几个九宫格，就是 `i / 3 * 3 + j / 3`；九宫格里面同样有九个数字，对应关系和行列一模一样。

写出来就是这样：

```java
// 把原始棋盘里已经填好的数字，它们的冲突状态全部记录下来
private void initConflict(char[][] table) {
    for (int i = 0; i < 9; i++) {
        for (int j = 0; j < 9; j++) {
            char ch = table[i][j];
            if (ch == '.') {
                // 还是个空格，没有冲突可记
                continue;
            }
            row[i][ch - '1'] = true;
            col[j][ch - '1'] = true;
            box[i / 3 * 3 + j / 3][ch - '1'] = true;
        }
    }
}
```

到这里，所有已经填写数字的行冲突、列冲突、九宫格冲突，就都落在这三个数组当中了。后面所有的判断，都只是一次查表——**这也是为什么这一讲开头一定要先把这张表建起来：不建表，就得每次回到棋盘上重新扫一遍。**

### 用 DFS 给一个空格找数字

#### 递归方法的架子

方法还是叫 `dfs`，目的就是针对某一个空格进行填空。

参数其实很好数。我要对 `(i, j)` 这个空格填空，那就得知道行列坐标，所以来一个 `i` 代表行、`j` 代表列；原始的 `table` 数组是不是也得要？也得要，作为一个参数传进去。此外还需要那三个记录冲突状态的数组——`row`、`col`、`box`。

最后一件事：这个递归方法还要能回答"填满了没有"。所有空格都填满了，我就 `return true` 表示找到了解；没填满就继续递归下去，所以整个方法的返回值是布尔值。架子就这么简单：

```java
private boolean dfs(char[][] table, int i, int j,
                     boolean[][] row, boolean[][] col, boolean[][] box)
```

首次调用的时候，行列坐标传什么？都传零，从第 0 行第 0 列开始处理。后面就照传就行了。

#### 用 while 找到下一个真正的空格

这里有个细节必须处理。大家看我在处理 `(0, 0)` 这个单元格的时候，发现它其实已经有数字了。有数字我们是不是应该跳过去啊？直到遇到了点，我们才应该进行填空的处理。所以要写一个 `while` 循环，判断一下第 `i` 行第 `j` 列这个字符，如果它不是点，那就得去查找下一个空格。

那怎么往下一个空格走？在当前行里就 `j++`，到 `(0, 1)` 去比较；`(0, 1)` 也不是点，就继续 `j++`，到 `(0, 2)`；什么时候遇到点了，我们再往下处理。

> **易错点**：每次加加加，得先考虑一个问题——如果它加到最后一个了，它再加是不是就越界了？

所以顺序要反过来写：先 `j++`，然后判断一下 `j` 是否已经大于等于 9 了。`j >= 9` 表示这一行的空格是不是已经找完了？找完了，那怎么办？到下一行去找。那么 `j` 呢应该变成零，重新从头开始；然后 `i++`，表示到下一行去。

那什么时候 `i` 大于等于 9 了呢？是不是表示所有的行都处理完了？应该相当于已经找到解了，应该返回。所以 `i >= 9` 就 `return true`，表示找到解了。

```text
   table[0]  =  ['5', '3', '.', '.', '7', ...]
                │    │     │     └─ 命中 '.'，退出 while，交给下面的填空逻辑
                │    └─────┘
                └──────────┘  已有数字，j++ 继续向右找

   j 撞到 9  →  j 归零，i++，换下一行继续找
   i 撞到 9  →  没有空格了 → return true（找到解）
```

#### 试填、记冲突、递归、退回来

好，退出 `while` 的时候，我们手上就是第一个真正的空格了，接下来开始填空。

填空怎么填？前面我们已经总结过这个步骤了，就是逐一去尝试 1 到 9。所以来一个循环，循环变量叫 `x`，从 1 开始一直到小于等于 9。先找到 `(i, j)` 这个单元格的位置，然后往里填一个字符。

注意，我们现在给的 `x` 是不是一个 `int` 数字啊？比如第一次循环它是一个 int 型的 1，但他要的是字符 `'1'`——填入一个字符。两个不一致，怎么办？跟刚才那个道理是类似的：刚才我们是把字符减去 `'1'` 变成了数字，现在要把数字变回字符，通过加上一个字符 `'0'` 就可以了。但这个加的结果还是 int 整数，所以得强转一下，`(char)` 转成 char。这就相当于给这个位置填了个 `'1'` 了啊。

事情还没有完。你比如说往这个单元格填入了 `1` 以后，它所在的行、所在的列、所在的这个九宫格，是不是都不能填入 `1` 了？所以我们接下来要去更新这几个冲突数组。

举个例子，就比如说我往刚才这个位置填入 `1`，那它对应着第几行呀？第 0 行。所以 `row` 的第 0 个元素中，我们要找到其中存储 `1` 的地方，把它更新成 `true`，表示有冲突了——它的含义就是"将来第 0 行不能存储 `1` 这个数字了"。注意索引是从 0 开始的，数字是从 1 开始的，所以索引 0 位置对应着 `1`，我们把它更新成 `true`。

列的冲突类似：它在第 0 列还是第 1 列？照一样的道理，把对应的那一格更新成 `true`，表示将来第 1 列里面不能存储 `1` 了。

九宫格稍微绕一点：先根据单元格的行列坐标找到它是第几个九宫格，找到之后它也不能存储 `1` 了，所以这个九宫格里对应 `1` 的那个索引也要更新成 `true`。

转成更通用的代码，怎么找索引？`x` 对应索引，就用 `x - 1`。于是：

```java
row[i][x - 1] = true;
col[j][x - 1] = true;
box[i / 3 * 3 + j / 3][x - 1] = true;
```

> **易错点**：这三个下标里，只有 `box` 的第一维是算出来的（`i / 3 * 3 + j / 3`），另外两维一个用 `i`、一个用 `j`；而三者的**第二维全都是 `x - 1`**。九宫格"是第几个"要算，九宫格里"是第几个数字"不用算。

我们也可以把它写到一行去，写成一行看着稍微简洁一些。这样就把这几个冲突状态都记录下来了。

接下来的套路是不是就差不多了？比如我刚才往这个位置已经填好了，填好了之后，我们是不是应该去查找下一个空格、重复做这些事情？又是一次递归调用。

递归调用的时候，我们就把当时的 `i` 和 `j` 传过去。因为每次传过去之后，它进入递归方法的时候都会再做一个检查，会去查找下一个空格，所以我们这里不用再做任何处理，直接把 `i` 和 `j` 传过去就好了，剩下的 `table`、`row`、`col`、`box` 都直接传。

那递归调用我们得注意一下它到底是成功还是失败。如果这九个数字都尝试了不行，是不是应该返回一个 `false` 表示失败？所以我们对它的返回结果做一个检查：什么时候它返回了 `true`，就表示已经找到解了，那是不是不需要继续再尝试了，直接也是 `return true`。

那如果它返回的是 `false`，表示填错了，填错了我就继续循环尝试下一个数字。当然你要继续循环尝试下一个数字的话，是不是得进行一个回溯啊？这个大家都知道。所以我们在递归结束之后应该做一个回溯，也就是把刚才第 `i` 行第 `j` 列这个单元格给它恢复成空格，然后这些个冲突状态呢，也给它恢复成没有冲突，也就是 `false`。

最后还有一件事情。既然记录了冲突了，所以我们在填入数字之前，是不是应该先检查一下？如果没有冲突了才去填数字；如果有冲突呢，我们就直接进入下一轮的循环。

检查冲突的逻辑就非常简单了，我们只要到这几个数组里发现它如果是 `true` 表示有冲突，那应该跳过去，应该 `continue` 跳过去。检查行的、检查列的、还有检查这个九宫格的，都要加上。

#### 完整代码与跑出来的解

把上面这些拼起来，就是完整的递归部分：

```java
private boolean dfs(char[][] table, int i, int j,
                     boolean[][] row, boolean[][] col, boolean[][] box) {
    // 跳过所有已经有数字的格子，找到下一个真正的空格
    while (i < 9 && j < 9 && table[i][j] != '.') {
        j++;
        if (j >= 9) {
            j = 0;
            i++;
        }
    }
    // 所有行都扫完了，说明找到一个完整的解
    if (i >= 9) {
        return true;
    }

    int k = i / 3 * 3 + j / 3;   // 先算出这是第几个九宫格，后面反复用

    for (int x = 1; x <= 9; x++) {
        // 落笔前的门禁：有冲突就跳过这一轮，去试下一个数字
        if (row[i][x - 1] || col[j][x - 1] || box[k][x - 1]) {
            continue;
        }

        table[i][j] = (char) (x + '0');
        row[i][x - 1] = true;
        col[j][x - 1] = true;
        box[k][x - 1] = true;

        // i、j 原样传下去，递归入口还会再做一次找空格的检查
        if (dfs(table, i, j, row, col, box)) {
            return true;
        }

        // 回溯：格子恢复成空格，三张表的这一格全部撤销
        table[i][j] = '.';
        row[i][x - 1] = false;
        col[j][x - 1] = false;
        box[k][x - 1] = false;
    }
    return false;
}
```

测试一下，看它能不能找到一个解。这是我们的原始数组，找到正确的解我待会儿会截图对比一下，看我们运行的结果是不是能得到这个正确的解：

```text
    5 3 4 | 6 7 8 | 9 1 2
    6 7 2 | 1 9 5 | 3 4 8
    1 9 8 | 3 4 2 | 5 6 7
    -----------------------
    8 5 9 | 7 6 1 | 4 2 3
    4 2 6 | 8 5 3 | 7 9 1
    7 1 3 | 9 2 4 | 8 5 6
    -----------------------
    9 6 1 | 5 3 7 | 2 8 4
    2 8 7 | 4 1 9 | 6 3 5
    3 4 5 | 2 8 6 | 1 7 9
```

行行填满，列列不冲突，九宫格也干净。至此为止，这个数独的解就找到了。

### 两数之和 II：它和第一题到底差在哪

这道题叫两数之和 II。给你一个有序的数组，比如有序数组内的元素是 2、7、11、15，然后再给一个目标 `target`，问数组内哪两个数字加在一起等于后面这个 target 的值。

比如说我们肉眼都能看出来是 `2` 和 `7`，这两个数字加在一起是不是等于 target 等于 9 啊？最终这道题目要的是把这两个数字的索引值返回。

看到这儿，有同学应该想起来了，我们之前也做过一道类似的题，就是力扣的第一题"两数之和"，好像这个测试用例都差不多，也是给了 2、7、11、15，然后再给一个 target 的 9。

那这两道题到底一样吗？还是有区别的。我们之前做的这道题，他没有说这个数组内的元素是排序的啊，它是不一定排序。而我们这道 167 题，他是说数组内已经升序排好了，由小到大顺序排好。这是一个区别。

那有同学就要问了，题目描述几乎一样，解题思路有什么变化？

之前求解第一题的时候，主要是利用了一个哈希 map，用哈希 map 来实现一个快速的查找。大概的思路是，我们会把所有数字遍历的时候放入 map 集合，这样找起来快；然后我们再看一下另外一个数字 `y`，是不是它能够跟 `x` 凑成我们的 target，每次去 map 里查询，看看这个 `y` 是否存在。如果存在，就相当于找到这样一个解了，我们直接返回。整个效率还是比较快的，他只要去把这个数组遍历一遍。

那我们要求解这个 167 题有什么不一样呢？你看人家的题目里说了一句：你所设计的解决方案，必须使用常量级的额外空间。

第一题用了一个 hash map，如果是最糟的情况，这个 hash map 里是不是会放 N 减一个数字啊？所以它的空间复杂度仍然是 $O(N)$，大 O 括号 N 显然不满足人家现在的这个要求。他要常量级的，也就是空间是 $O(1)$。

| | 力扣 1（两数之和） | 力扣 167（两数之和 II） |
| --- | --- | --- |
| 数组是否有序 | 不一定有序 | 明确升序 |
| 解的数量 | 题目保证只有一组答案 | 只有一组答案 |
| 额外空间限制 | 无 | 必须 $O(1)$ |
| 常用思路 | 哈希表，$O(N)$ | 双指针，$O(1)$ 空间 |

那怎么办呢？我们就必须利用人家的有序数组这个特性来解这道题了。

> **结论**：**有没有序，决定了你能用哪种数据结构。** 无序就得靠哈希表把"找过没有"这件事变成 $O(1)$；有序则可以靠"和大了就缩右端，和小了就推右端"这条单调性，用两个下标把空间压到 $O(1)$。

### 两数之和 II：一支往左，一支往右

先看一下那个图。图里面蓝色的线代表我们的 target，也就是我们要求的两数之和；线的长度对应着数字的大小，越长表示数字越大，越短表示数字越小。黑色的线对应的就是我们数组中的数字，可以看到也是由小到大都排好序了。

现在要求两数之和，我的思路是设置两个指针：`i` 这个指针指向左侧最小的数字，`j` 这个指针指向右侧最大的数字。

我们先把 `i` 和 `j` 这两处的数字加起来，看一下它跟蓝色线代表的 target 比谁大谁小。

```text
   蓝线 target = 9 ：  ────────────────────────────▶     线越长，数值越大

   数组（升序）：   2        7        11       15
   下标：           0        1        2        3
                   ▲                         ▲
                   │ i → 最小                │ j → 最大
                   └────── 2 + 15 = 17 ──────┘
                              17 > 9  →  j--，换 11
                              2 + 11 = 13 > 9  →  j--，换 7
                               2 +  7 =  9  =  target ✓
```

第一轮：显然它俩的和已经超过了蓝色的 target 了，怎么办？是不是我们应该让这个数字更小一点呀？那改变谁啊？我们可以让 `j` 减小，让 `j` 指向的数字小一点，它在尝试跟 `i` 处的数字两个加，是不是就有可能等于我们的 target。所以我们把 `j` 向左移动。

`j` 向左移动之后呢，我们发现它俩加起来的和好像又比 target 小了。那怎么办？是不是我们应该让这个和变得更大一点。那怎么让这个和变得更大一点呢？是不是我们找 `i` 右侧这个数字去尝试啊，所以我们让 `i++` 向右找。

当然呢 `i++` 以后它俩的和还是比这个蓝色的小，怎么办？小了就要加，继续来 `i++`。发现还是差一点，那我们继续到它的右边找一个稍微大一点的数字。`i++` 之后还是差一点，最后再来一次——找到了。

所以这道题的解题思路很简单，就是：

> **设置两个指针，`i` 和 `j` 分别指向最左侧和最右侧的数字。把它们俩指向的数字求一个和，跟 target 做对比：如果小于 target，就让 `i++` 向右找，让这个和增大一点；如果大于 target，就让 `j--` 向左找，让这个和小一点；直到它俩的和等于 target，就表示找到了。**

用文字描述一遍就是上面那一段。理解了思路，代码就顺理成章了。首先设置两个指针，`i` 等于 0，`j` 等于数组长度减 1。接下来写一个循环，当 `i < j` 的时候，表示这两个指针还没有相遇，那么就继续查找。

然后先把 `i` 处跟 `j` 处的两个数字拿到，求一下它俩的和，叫个 `sum`。判断一下：如果这个 `sum` 是小于 target 的，表示这个和是不是还小一点？小一点的话我们让 `i++` 向右找，这样就能让和增大一点。否则的话，如果这个和是大于 target 了，就表示我们求出来的和有点大，应该让这个和小一点，这样 `j--` 让它向左找。

最后一种情况就是它们相等了，和跟 target 相等，就表示找到了。找到的话我是不是退出循环就行了？`break` 退出循环。

最终人家要返回的是 `i` 和 `j` 这两个索引位置，我们把这两个索引位置放到一个整数数组里返回就行了。

```java
public int[] twoSum(int[] numbers, int target) {
    int i = 0;
    int j = numbers.length - 1;

    while (i < j) {
        int sum = numbers[i] + numbers[j];
        if (sum < target) {
            i++;            // 和太小，往右找一个更大的
        } else if (sum > target) {
            j--;            // 和太大，往左找一个更小的
        } else {
            break;          // 找到了
        }
    }

    // 题目要求索引从 1 开始，所以 i 和 j 都要加一
    return new int[]{i + 1, j + 1};
}
```

> **易错点**：这里最容易忘的就是最后那一行。**我们代码里的下标是从 0 开始的，题目要的答案是从 1 开始的**，所以返回之前 `i` 和 `j` 都要加一。测试数据 `[2, 7, 11, 15]`、`target = 9`，代码里找到的是 `i = 0, j = 1`，返回的应该是 `[1, 2]`。

### 三数之和：把三数问题降成两数问题

这道题还是给你一个数组，从数组里面挑三个数字出来，加起来的和要等于 0——相当于他把那个 target 固定成 0 了。

同时题目还要求答案中不能重复。就比如说第一个 `-1`、`0` 和这个正 `1` 组合了，那第二个 `-1` 就不能再跟 `0`、正 `1` 组合了，最终的结果里要排除掉重复的。

#### 和 167、和 40 题分别差在哪

先说跟 167 的区别，这其实是一个比较大的区别。**两数之和的题目明确说了只有一个答案**，所以你找到这个答案就可以结束了。但是我们这道题呢，它是有可能会有多个答案的，你要把所有的答案都找出来。第二个区别我们刚才说过了，这道题要考虑去重。

那其实我觉得，我们三数之和这道题目更加类似于之前做过的一道题，叫组合总和 II，也就是力扣 40 题。力扣 40 题也是给你一个数组，这些数组里随便挑一些数字加起来，它的和也要等于后面这个 target。你看它这道题里的例子，`1+1+6` 等于 8，`1+2+5` 等于 8，`1+7` 等于 8，`2+6` 等于 8。

从这个例子我们也就看出来跟三数之和的区别在哪了。人家 40 题相当于求的这个数字组合更广泛，不光是三数之和，如果你有两数之和，或者有什么四数之和，只要你能加起来等于 target，那最终这些组合我们都要找出来。而我们这道题只是求三个数之和等于 0 的所有组合，至于两个数、四个数加起来组合起来等于 8 的，我们就不管了。

| | 三数之和（力扣 15） | 组合总和 II（力扣 40） |
| --- | --- | --- |
| 选几个数 | 固定三个 | 不限，两数、三数、四数都算 |
| 和是多少 | 固定为 0 | 题目给的 target |
| 答案是否去重 | 必须去重 | 必须去重 |
| 讲过的思路 | 降维递归 + 双指针 | 回溯枚举 |
| 时间复杂度 | $O(N^2)$ | $O(N \cdot 2^N)$ |

再看解法上的区别。当时解这个 40 题的时候，采用的是回溯的这种思路，那时间复杂度是比较高的，是 $2^N$ 乘以 N。而我们这道题求解的时候，因为我们三个数其实限制了递归的次数，所以我们这个总的时间将来是比较小的，只有大 O 括号 N 平方。待会儿我们也会对比一下它俩的运行效率。

#### 降维递归的参数设计

三数之和可能同学们一上来没有概念，但是没关系。大家看，如果我固定了其中一个数字的话，那问题呢，是不是就转换成了我们之前的两数之和呀？

比如说我们把原始数组先按小到大排好序（排序是为了待会我们去重方便一些），然后固定了最小的那个 `-4`，那三数之和要等于 0，是不是意味着剩下的两数之和要等于正 4 呀？这样将来三数之和才能等于 0。所以这样一来，我们就把三数之和的问题变成了之前的两数之和的问题。

那两数之和会不会求解？会吧，就用我们之前的思路：`i` 指向最小的数字，`j` 指向最大的数字，然后他们俩逐一去尝试，看看能不能让和等于我们这边的 target。

一开始 `i` 指针指向最小值、`j` 指向最大值，一加发现比 target 小，还不够，那就增大 `i` 啊，往右边去找更大的数字；移动之后结果和还是不够，继续向右移动，还是不够，继续 `i++`。

结果是到这儿我们发现，固定 `-4` 的情况下没有解——因为剩下最大的两个数字加起来也只有 3，够不到 4。所以固定 `-4` 不行。那怎么办？继续尝试，我们这回来固定下一个数字 `-1`。

固定 `-1` 以后，`i` 是不是从下一个开始就可以了？前面都不用尝试了。这时候有没有解呢？有解——`-1` 加上 `0` 正好等于 1，而 `1` 正是我们需要的 target（因为要凑出 `0`，减去固定的 `-1` 就是 `1`），所以这就找到了第一个解。

那继续看能不能找到更多的解。这时候 `i++`、`j--`，又找到了一组解。`i++`、`j--` 再来，就相当于它俩相遇了，那就没必要尝试了。

所以在固定 `-1` 的情况下就找到了两组解。那这个 `-1` 还需要继续固定吗？不需要了，因为再固定 `-1` 找到的解是重复的。所以我们接着固定下一个数字 `0`——固定 0 的话，剩下两个数字加起来至少是 3，而这时候 target 要的是 0，所以肯定凑不出来，固定 0 尝试失败。接下来再去固定 `1`，但是固定了 `1` 之后，剩余的数字不够两个了，剩下只有一个，这种情况下也不用继续尝试了。

> **结论**：所以我们整个就找到了这些解。显然三数之和用递归来求解是比较方便的，因为你看，**固定其中一个数字，将来就可以套用两数之和来求解**。那如果将来我们要用四数之和呢？你也可以先固定一个数字，把四数之和变成三数之和，然后三数之和递归的时候再固定一个数字，剩下的两个数字是不是又可以套用两数之和来求解了。

这个降维链条用图画出来就是这么清楚：

```text
   三数之和 = 0
        │
        └─ 循环固定一个 numbers[k]（从左往右）
             │
             └─ 剩下的两数之和 = 0 - numbers[k] = -numbers[k]
                  │
                  └─ 直接套 167 的双指针，区间收窄成 [k+1, j]
                       │
                       ├─ 找到 → stack 里的固定值 + numbers[i] + numbers[j] 凑成一组解
                       │           塞进 result，然后 i++、j-- 继续在更小的区间里找
                       │
                       └─ 本轮没找到 → stack.pop() 回溯，换下一个固定值

   n == 2  →  落到两数之和，直接求解并 return，不再往下递归
   n  > 2  →  固定一个数字，n 减一，继续递归
```

所以我们就设计一个用来递归的方法 `dfs`。它需要哪些参数呢？

首先你得需要一个 `n` 代表数字的个数啊，刚开始它是三。我固定一个数字以后，下次递归的时候我就让 `n` 减一。什么时候这个 `n` 变成二了，就可以套用两数之和来求解。

每次固定了这个数字以后，那剩余这些个数字，你是不是得知道它的一个起始和结束的索引啊？这个起始结束索引我们也分别用 `i`、`j` 来代表。此外还需要一个 `target`，因为要知道两数之和最终要等于什么。`numbers` 就是我们的原始数组。

参数比较多啊，还需要哪些参数呢？就是我们得找到一个用来收集结果的集合。我们有一个 list 啊，里面放的是 data，它叫个 `stack`，这是用来收集其中一组结果的。那这多组结果最后要放到一个大的集合里面，那么再来一个 list 里面套一个 list，这个叫做 `result`，这是用来收集所有结果的。

首次调用的时候，我们给它把一些参数传进去：首先这个 `n` 一上来等于三，表示我要求的是三数之和；然后 `i` 刚开始是 0，从最左边开始，`j` 是数组长度减一；然后原始数组 `numbers`，`target` 在这道题里固定成了 0；还有一个是用来收集结果的，我们用个 `LinkedList`——因为 `LinkedList` 用 `push` 方法的时候方便一些。此外还有一个总结果的集合 `result`，这个我们创建在外面，传过去。最后我们返回这个总的集合就可以了。

另外呢有一点要注意，我们这个原始数组是不是应该做一个排序啊？排序之后我们才能利用一些排序后的结果，实现一个方便的驱动（去重）。所以别忘了对我们的 `numbers` 要做一个排序。

#### 固定值也要去重

刚才我们这个代码相当于每次循环就是固定其中一个数字，然后再尝试接下来的两数之和的求解。但是我们需要考虑一个去重的问题。

比如说呢我这次固定了 `-1` 吧，那下次我再循环的时候，下一个又是一个 `-1`，那第二个 `-1` 是不是就不需要再固定了？因为他们将来的解组合的结果是有重复的。那怎么办呢？我们需要检查这个重复。

检查重复的代码呢也比较简单，我们就是判断一下：如果你当前这个数字它上一个数字跟你相同啊，上一个数字又是个负的，这就表示已经重复了。那对于我当前这个固定值来讲，就没必要固定了，也就是不执行下面的 `push` 以及递归这些动作了。

所以我们判断一下：如果 `numbers[k]` 它等于等于 `numbers[k - 1]` 了，这就表示我当前的数字等于它上一个数字了，这时候就发现一个重复的数字。既然是重复的数字，那我们就 `continue` 跳过这个数字，进入下一个数字的尝试。

> **易错点**：当然为了防止越界，比如说一开始这个 `k` 跟 `i` 都是从零开始的，那 `0 - 1` 是不是越界了？那怎么办呢？我们要保证 `k > i`，这样就防止它越界啊。**第一个数字其实是不需要检查重复的，只有从第二个数字开始我才需要检查。**

#### 把 167 的双指针搬过来，改动只有两处

接下来在 `n == 2` 的时候，就可以套用之前的代码对这个两数之和进行求解了。具体代码我们先不着急写，总之就不用继续递归了。因此我们发现 `n == 2` 的时候，套用两数之和求解了之后，就直接 `return` 了。

那如果是刚开始 `n` 是大于二的，那我们就要固定其中一个数字，然后 `n` 减一继续递归。固定数字的话肯定也得从左向右逐一尝试，所以我们来一个循环，这个循环中 `k` 从哪开始？是不是应该从它的左边界 `i` 开始，然后一直循环到 `k < j`。

那每次循环的时候呢，我们就把 `numbers[k]` 这个数字进行一个固定。固定的话其实就是把它先暂存在一个 `stack` 栈里面，`push` 一个 `k` 位置的数字。然后固定了 `k` 这个数字之后，我们是不是进行下轮的递归？因为固定了其中一个数字，那下次再递归的时候，这个数字的个数是不是应该是 `n` 减一了，所以下次递归的时候它的个数就应该是 `n - 1`。

那下次递归这个 `i` 和 `j` 的范围呢？比如说大家看我把 `numbers[k]` 等于 `-4`，这个位置的数字固定了，那下次这个 `i` 和 `j` 的范围是不是应该是从 `k` 加一开始，向后的所有数字要进行一个两数之和的组合，所以它的范围应该是从 `k + 1` 开始。

那 target 呢？你看刚开始我要求三数之和，固定了一个 `-4`，那相当于两数之和的时候，是不是就应该是 target 等于正 4 啊？所以应该是**本次的 target 减去我固定的数字**。剩下一些参数我们就照传就可以了：一个是原数组，一个是 `stack`，一个是最终的 `result`。

别忘了我们固定这个数字之后，那递归完毕如果没找到解——比如说这个数字固定完了，进行了一轮尝试，没找到解，那是不是我应该取消 `-4` 的固定？下次再固定接下来这个 `-1` 啊。那怎么取消呢？就是一个回溯，要用 `stack.pop()` 回溯一下不就行了。

```java
private void dfs(int n, int i, int j, int target, int[] numbers,
                 LinkedList<Integer> stack, List<List<Integer>> result) {
    // 只剩两个数字了，直接套两数之和
    if (n == 2) {
        twoSum(numbers, i, j, target, stack, result);
        return;
    }

    // 从左往右逐一固定一个数字
    for (int k = i; k < j; k++) {
        // 固定值去重：当前数字和左边那个一样，就没必要再固定一次
        if (k > i && numbers[k] == numbers[k - 1]) {
            continue;
        }

        stack.push(numbers[k]);

        // 固定一个之后：个数 n-1，区间收窄成 [k+1, j]，target 减去固定值
        dfs(n - 1, k + 1, j, target - numbers[k], numbers, stack, result);

        // 本轮没找到解，取消固定，换下一个数字
        stack.pop();
    }
}
```

#### 找到解之后别急着 break

`n == 2` 的时候我们就可以调用 `twoSum` 了，把十字后的 `i`、`j`，还有原始数组、`target` 以及这个 `stack`、`result` 都传进去。

`twoSum` 代码里面咱们以前都做过一遍：就是当 `i < j` 的时候，那么就求 `i` 和 `j` 这两个位置的数字和，看一下数字和。如果它是小于 target 的，说明这个和有点小，那这时候就增加 `i`；如果这个和大于 target，说明和有点太大了，那就再去减小 `j`；直到最后这个和等于 target，它是不是就相当于找到解了？

而我们这次从 167 复制过来代码的时候，有两处改动。

> **改动一**：原来 167 里的 `i` 和 `j` 都是从零开始、到数组长度减一结束的，显然在递归里它们是变化的，所以应该作为方法的参数传进来。

> **改动二**：167 题是通过返回值把答案返回出去的；我们这里是要把结果存到一个集合里，集合再放到这个大的 `result` 里面，不是通过返回值返回了，所以这个返回值就不要再了，最后这个 `return` 当然也不需要了。当然因为要把结果往这个集合里存，需要用到这里的 `stack` 跟这个 `result`，所以把这两个参数也拿过来，放在我们现有的这个方法里。

找到解了，我们要做的就是把解给它存储起来。其实有一部分解呢是放在这个 `stack` 里面了——`stack` 也是我们固定的那个数字；还有一部分解呢就是我们这里的 `i` 这个数字和 `j` 这个数字。那咱们把它综合起来，再放到一个集合中。`new` 一个 `ArrayList`，这个 ArrayList 里面咱们先把这个 `stack` 里面固定的那个数字加进去，比如说这里的 `-1` 这个数字加进去。加进去之后呢，我们还要往这个集合里把 `i` 处的数字跟 `j` 处的数字加进去，所以就是再 `add` 这儿的 `numbers[i]`，还有一个 `numbers[j]`。这样我们的三个数字是不是就找对了？找对之后呢，我们把整个这个小的一组集合，它就相当于是一组解，再加到那个大的解的集合里就可以了。

代码写到这儿，我们来测试一下，看结果对不对。

第一个数 `-1` 其实就是我们固定好的这个数字，剩下这个 `0` 和 `1` 呢，就是分别对应 `i` 指向的数字和 `j` 指向的数字，他们加在一块是不是等于 0 啊？这个结果是正确的，找到了一组正确的解。

但是通过刚才这个动画的演示大家也看到了，其实我正确的解是不是有两个呀？那我们现在只输出了一个。为什么呢？是因为我们这个代码有一个 `break` 啊——这个代码是从之前 167 复制而来的，167 题两数之和我们前面说过，题目本身就说了只有一组解，所以我们找到第一组解直接退出这个循环就行了。

但是我们现在，找到一个解不能立马 `break` 退出去了，也许还有其他的解。所以我们这个 `break` 不能停，我们需要去继续查找其他的。这是跟以前不太一样的地方。

那这个代码该怎么写呢？你看我们刚才找到了这组解，也就是 `i` 指向 `-1`、`j` 指向 `1`，这个解之后呢，我们是不是应该在缩小这个范围啊？继续看一下这个缩小后的范围内有没有两个数字，它们的和也等于 target 呀。比如说我们现在这个例子中，如果 `i++`、`j--`，减了之后，大家看这个范围内的数字 `0` 和 `1` 加在一起，是不是他们的和也等于我们这个时候的 target 啊？所以我们接下来要缩小这个范围。那代码呢很简单啊，就是让 `i++`，然后 `j--`，然后我们继续来尝试。

好，咱们测一下。这个代码加上之后呢，我们发现是不是就正确了？得到了两个解，它们的三数之和都是 0。

**但这样写对不对呢？其实还不是很正确，因为这样有可能有一些重复的解没有排除掉**——我们原来的两数之和是没有考虑重复的情况的。

那我们再来看看重复解的一个去处。

#### 去重：指针跨过去，别跳过头

我们对照这张图来看啊，这张图里我又多加了两个数字。还是那固定的数字是 `-1`，然后我们先找到了第一组解，也就是 `i` 指向的数字是 `-1`，`j` 指向的数字是 `1`。然后缩小范围，这是第二组解，`i` 指向的数字是 `0`，`j` 指向的数字是 `1`。

但是注意看，第三组解是不是 `i` 又是一个 0 呀，又是一个 1 呀？如果你把这个解加到我们的最终结果里，就相当于有重复的解了，是不是这样呢？我们来运行一下——我多加了一个 `0` 和一个 `1`，运行，代码里如果没有做这个去除重复的处理，我们是应该会看到有重复的，是不是 `-1, 0, 1`、`-1, 0, 1` 重复了呀？

所以呢要避免这种重复解的情况，我们该怎么做啊？就是 `i` 向右移动的时候，你得跟它左边的数字比较一下，如果二者有重复，是不是这个 `i` 呢相当于遇到重复了？我就应该把它跳过去啊，我继续 `i++`，再找一个下一个不重复的数字。

类似的 `j` 这边呢，你往左边移动的时候，你应该跟它右边的数字做一个比较，如果二者相等，说明也是重复了，那我继续应该向左移动，找下一个不重复的数字。

所以这个代码呢我们应该再写这么一个循环：现在呢判断一下，不要让 `i` 超过 `j` 吧，然后呢再来看当前 `numbers[i]` 跟它左边的数字相比是不是相等。那左边的数字是不是应该是 `i` 减一？如果二者相等，说明找到了一个重复的数字，那重复的数字找到了，那我们继续 `i++`，找下一个不重复的数字。

`j` 这边呢也做类似的处理，那 `j` 呢是跟它右边的数字去判断，右边数字就是 `j` 加一嘛。如果二者重复了，那说明我们应该把这个解跳过去，再向左继续 `j--`，找下一个不重复的 `j` 指向的数字。把这两段循环加上就不会有这个重复了。

```java
// 把 167 的双指针搬过来：i、j 变成入参，返回值改成往集合里塞
private void twoSum(int[] numbers, int i, int j, int target,
                    LinkedList<Integer> stack, List<List<Integer>> result) {
    while (i < j) {
        int sum = numbers[i] + numbers[j];
        if (sum == target) {
            List<Integer> cur = new ArrayList<>();
            cur.addAll(stack);        // 上几层固定下来的数字
            cur.add(numbers[i]);
            cur.add(numbers[j]);
            result.add(cur);

            // 167 里这里是 break，但这里不能停，可能还有别的解：
            // 两边同时缩，继续在更小的区间里找
            i++;
            j--;

            // 继续跨过重复值，避免同一组解被收了好几遍
            while (i < j && numbers[i] == numbers[i - 1]) {
                i++;
            }
            while (i < j && numbers[j] == numbers[j + 1]) {
                j--;
            }
        } else if (sum < target) {
            i++;                       // 和太小，往右找一个更大的
        } else {
            j--;                       // 和太大，往左找一个更小的
        }
    }
}
```

> **易错点**：去重这两段 `while` 的方向是相反的——**`i` 往右走，就跟它左边（`i-1`）比；`j` 往左走，就跟它右边（`j+1`）比**。搞反了方向，判断的就不是刚走过的那一段，去重就完全不生效。

整体骨架就是上面那两段方法，入口是这么调用的：

```java
public List<List<Integer>> threeSum(int[] numbers) {
    // 排序是前提：双指针要求有序，去重也靠有序
    Arrays.sort(numbers);

    List<List<Integer>> result = new ArrayList<>();
    // n=3 表示求三数之和，target 固定为 0
    dfs(3, 0, numbers.length - 1, 0, numbers, new LinkedList<>(), result);

    return result;
}
```

### 一次实测：16ms 和 449ms

最后我们来看一下当前这个解法的性能。

我在我的方法递归的时候给它做了一个计数，另一个全局变量 `count` 刚开始是零啊，每次递归调用发生的时候，我们就让 `count++`，最终我会打印一下 `count` 的值，还有整个这个方法它花费的时间。当然了这个数字有点少，我把它注释掉，换一个比较长的数组。

我会打印出这个数组中的数据量，大概是 500 多个，然后我们看一下用我们这个刚才的实现去求解的话，会耗费多少时间、会递归多少次。

```java
public static int count = 0;   // 用来统计递归到底被调用了多少次
```

执行一下：可以看到总数据量呢是 575 个，然后呢最终求出了一大堆解，这三个数字它们的和都是 0，这就是正确的解。然后耗费的时间呢是 16ms。递归的次数呢比我们这个数据量还要更少一些，是 569 次。为什么呢？其中有一些重复的，重复的点就被我们在循环的时候直接跳过去了，相当于没有那么多次递归。

作为对比呢，我又把三数之和的问题用之前力扣 40 题的思路来解了一下，我们看看它们性能上的差异。

主要的改动呢是这个地方：因为力扣 40 题啊，他是说甭管你是两数之和、三数之和、四数之和，只要它的和等于它给的就算一个解，对吧？我们需要把一些不是三个数的情况排除掉，所以我检查了 `stack.size()` 等于三的时候，我才把它加入到最终解的集合里，不是三的就排除掉了。这样呢也能得到一个正确的结果。

但是呢它的运行效率啊，对比我们刚才这种算法的效率就差很多了。我们可以实际对比一下，数据量都是一样的，测试的数据也是一样的：

| 解法 | 数组数据量 | 递归次数 | 耗时 |
| --- | --- | --- | --- |
| 降维递归 + 双指针（本讲解法） | 575 | 569 次 | 16ms |
| 力扣 40 的回溯思路 | 575 | 千万级 | 449ms |

都是 575 个数字都能得到正确的解，但是之前耗费的时间只有 16ms，现在耗费的时间是 449ms，是不是差的有点大呀？

为什么差的这么大呢？因为主要是因为递归的次数。我们刚才介绍这种算法，它的递归次数只需要 569 啊，六百多次；而之前 40 题它的递归次数是多少个？十、百、千、万、十万……千万级的递归次数了。所以时间主要耗费在这儿了。

所以我们看到一个好的算法，它能对你的运行效率有很大的提升，尤其是数量越大越为明显。

> **结论**：两道题都能做对，但差的不是"技巧"，差的是**你有没有把搜索空间掐小**。回溯是在整个数组上枚举所有组合，代价是 $O(N \cdot 2^N)$；降维递归是每层只固定一个数、剩下交给双指针在 $O(N)$ 里扫完，总代价落到 $O(N^2)$。**先想办法排除掉不可能的选择，剩下的空间自然就越缩越小**——这句话从数独那张冲突表开始，到这里算是闭环了。
