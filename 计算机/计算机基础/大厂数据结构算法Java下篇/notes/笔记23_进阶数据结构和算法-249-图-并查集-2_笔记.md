# 进阶数据结构和算法-249-图-并查集-2

## 并查集在克鲁斯卡尔中的用法

### 老大的判定依据

* **老大（parent 数组语义）**

    * > **定义**：`parent[i] == i` 表示顶点 i 自己就是老大；否则 `parent[i]` 指向它的老大。

    * > **定义**：「i 和 j 在不在同一个集合」等价于「find(i) 和 find(j) 是不是相等」。

* **一条边的处理规则**

    * 找到这条边的两个顶点，看它们是不是在同一个集合内。
    * 不在同一个集合内就把它们相连；已经在同一个集合内，这条边直接跳过去。
    * 相连就是让其中一个顶点加入另一个顶点，组成一个新集合。
    * 克鲁斯卡尔按边为单位处理，目标是最小生成树，边已按权重排好序后一条一条过。

### 先问老大再决定连不连

* **单条边的判断步骤**

    * 先找到 0 这个顶点在集合中的老大，再找到 3 这个顶点在集合中的老大，也就是调用 `find` 方法。
    * 两个老大值分别起变量名 `x` 和 `y`，只有 `x != y` 才调用 `union`；相等时整段跳过，不写数组。

    ```java
    int x = find(0);        // 0 这个顶点所在集合的老大
    int y = find(3);        // 3 这个顶点所在集合的老大
    System.out.println("x=" + x + " y=" + y);

    if (x != y) {
        union(x, y);                         // 不相等才相连
        System.out.println(Arrays.toString(parent));
    }
    ```

* **整条边集过一遍的全过程**

    * 两条老大相等的边直接被跳过，根本不会去执行 `union`。
    * 每条被留下的边都会让一个顶点改认新老大。

| 边 | `find` 出来的一端老大 | `find` 出来的另一端老大 | 判断 | 数组变化 |
| :--- | :--- | :--- | :--- | :--- |
| 0–3 | 0 | 3 | 不同集合，连 | `parent[3] = 0` |
| 5–6 | 5 | 6 | 不同集合，连 | `parent[6] = 5` |
| 0–1 | 0 | 1 | 不同集合，连 | `parent[1] = 0` |
| 2–3 | 2 | 0 | 不同集合，连 | `parent[0] = 2` |
| 1–3 | 2 | 2 | 同一集合，跳过 | 不变 |
| 0–2 | 2 | 2 | 同一集合，跳过 | 不变 |
| 3–6 | 2 | 5 | 不同集合，连 | `parent[5] = 2` |
| 2–5 | 2 | 2 | 同一集合，跳过 | 不变 |
| 4–6 | 4 | 2 | 不同集合，连 | `parent[2] = 4` |

* **跑完后的数组**

    * 跑完最后一组，2、3、4、5、6 五个顶点顺着链找到的老大全部是 4。

    ```text
    索引 :  0   1   2   3   4   5   6
    值   :  2   0   4   0   4   2   5
    ```

    * 0 到 6 共七个点，生成树只需要六条边就能撑起来，最小生成树到这一步就有了。
    * 这就是不相交集合（Disjoint Set）在克鲁斯卡尔里的一个使用示例。

### 小弟会不会找错老大

* **顺着链一路走**

    * 小弟的内容指向的不是老大，而是另一个小弟。
    * `find` 会顺着这条链一路走，直到内容等于索引为止，此时老大找到。
    * 所以小弟即使离老大隔了两层，最终找到的老大仍然一致。

* **以 1 和 3 为例的追踪**

    * 处理 2–3 这条边之后，1 的内容是 0，与索引 1 不等，继续找 0；0 的值与它的索引也不等，继续查找；再找就找到 2，这时相等，老大找到。
    * 1 和 3 虽然离老大隔了两层，最终找到的老大都是 2。

    ```text
    find(1) :  1 → 0 → 2 → 2      命中 2 == 2，老大是 2
    find(3) :  3 → 0 → 2 → 2      命中 2 == 2，老大是 2
    ```

## 路径压缩

### 糟糕的连接顺序

* **制造长链的做法**

    * 先让 0 和 1 相连，再让 1 和 2 相连，然后 2 和 3、3 和 4、4 和 5、5 和 6。
    * 落到数组上就是三里存的是二、四里存的是三、五里存的是四、六里存的是五。

    ```text
    0 ← 1 ← 2 ← 3 ← 4 ← 5 ← 6
    ```

* **查找效率低的表现**

    * 想找 6 在整个集合中的老大，得先找到 5，通过 5 找到 4，通过 4 找到 3，找到 3 找到 2，找到 2 找到 1，最后找到 0。
    * 改进可以从两个方面入手：一个改 `find` 方法，另一个改 `union` 方法。

### 顺手把路修短

* **路径压缩的做法**

    * 执行 `find(2)` 时，2 的索引与内容不等，递归调用 `find`；1 同样不等，继续递归 `find(0)`；0 的索引与内容相等，停止递归并返回。
    * 返回值沿递归链一路向上传递，最外层的 `find(2)` 就知道老大是 0。
    * 既然已经知道 2 的老大是 0，就把 2 自己槽位的内容直接改成 0，中间那条线就断了，下次直接找老大 0，不再经过中间那层。

* **代码实现**

    * 只需要 `parent[x]` 的赋值，复制为递归返回的结果即可。

    ```java
    public int find(int x) {
        if (x != parent[x]) {
            // 让 x 自己的槽位直接存递归返回的老大，中间的线就断了
            parent[x] = find(parent[x]);
        }
        return parent[x];
    }
    ```

### 一次查找之后的路径更新

* **执行 `find(2)` 之后**

    * 路径已经更新，2、1、0 三个位置的值都变成了 0。

* **执行 `find(6)` 之后**

    * 这条路径上的所有顶点都做更新，6、5、4、3、2 最终的老大都是 0，每次递归调用都会把相应位置的内容改成找到的老大值。

    ```text
    执行前 :  0 ← 1 ← 2 ← 3 ← 4 ← 5 ← 6      （parent[6]=5, parent[5]=4, ...）
    执行后 :  0 ← 0 ← 0 ← 0 ← 0 ← 0 ← 0      （整条路径被拍平到一层）
    ```

* **优化结论**

    * 路径压缩只改 `find`：查找一次，顺手把整条查找路径上的所有顶点都指向最终老大，效果立竿见影。

## Union by size

### 两种连接方向的对比

* **场景构造**

    * 集合中已经有两个连起来的集合：一个是 0，它单独一个；另一个是 1、2、3、4 四个已经连起来了，2 和 3 存的都是 1，4 存的是 3。
    * 需求是把 0 跟 1、2、3、4 再连到一起，`union(0, 1)` 和 `union(1, 0)` 两种写法都能把两个集合连上。

| | `union(0, 1)` | `union(1, 0)` |
| :--- | :--- | :--- |
| 谁成为老大 | 0 | 1 |
| 谁改认老大 | 1 的内容改成 0 | 0 的内容改成 1 |
| 查 4 的老大要走几步 | 4 → 3 → 1 → 0，三步 | 4 → 3 → 1，两步 |

* **判定规则的由来**

    * 判定规则是根据集合中的顶点个数来决定谁是老大，顶点个数多的把它当成老大。
    * 上面那种连法不好，是因为把一个顶点个数多的集合连接到了顶点个数少的集合，即把 4 个顶点的集合挂到了 1 个顶点的集合上。
    * 反过来把顶点个数少的集合连接到顶点个数多的集合，整条路径相对都比较短。

* **原始实现的坑**

    * > **易错点**：原来的 `union` 固定让左边的参数当老大。`union(0, 1)` 和 `union(1, 0)` 在它眼里是两回事，于是一个不小心就会把一棵大树挂到一棵小树底下，让所有小弟的查找路径集体变长。

### size 数组

* **size 的职责**

    * 需要一个新的数组记录个数，用来记住集合的大小，数组名就叫 `size`。
    * `size` 初始化成 1，是因为刚开始每个集合互不相连，每个集合里只有它自己一个顶点。
    * 大小存放在老大那一格：老大是 1 的那个集合，大小就记在 1 那一格。

    ```java
    private int[] size;

    public UnionFind(int n) {
        parent = new int[n];
        for (int i = 0; i < n; i++) {
            parent[i] = i;
        }

        // 刚开始每个集合互不相连，所以每个集合的个数都初始化成 1
        size = new int[n];
        Arrays.fill(size, 1);
    }
    ```

* **个数如何被吃掉**

    * 两个集合合并后只更新老大的元素个数：上次的 4 加上小弟 y 原有的 1，合并之后老大是 1，对应个数更新成 5。

    ```java
    parent[y] = x;                   // y 挂到 x 底下，x 当老大
    size[x] = size[x] + size[y];     // 老大的个数把小弟的个数吃进来
    ```

### 按个数分派老大

* **按个数判断的 union**

    * `size[x] < size[y]` 时由 y 当老大、x 当小弟，`parent[x] = y` 且个数更新到 `size[y]`。
    * 否则 x 的元素个数比 y 多或相等，走原来的逻辑，x 仍当老大。

    ```java
    if (size[x] < size[y]) {
        parent[x] = y;                  // x 是小弟，放在前面；y 是老大，放在后面
        size[y] = size[y] + size[x];
    } else {
        // x 的元素个数比 y 多或者等于，走原来的逻辑
        parent[y] = x;
        size[x] = size[x] + size[y];
    }
    ```

* **两种参数顺序的测试结果**

    * `union(0, 1)` 之后最终还是 1 当老大，0 的内容被更新为 1，1 的大小更新成 5。
    * `union(1, 0)` 效果跟刚才一样：仍然是 1 当老大，因为判断依据是元素个数而不是先后顺序，最后大小同样被正确更新。

### 交换两个参数统一成一行

* **交换写法**

    * if 分支和 else 分支逻辑几乎一样，只是把 x 换成了 y 和 x，可以把 x、y 交换位置后统一成一行。
    * 集合个数少的一方挪到后面去当老大。

    ```java
    public void union(int x, int y) {
        if (size[x] < size[y]) {
            int t = x;      // 集合个数少的一方挪到后面去当老大
            x = y;
            y = t;
        }
        parent[y] = x;
        size[x] = size[x] + size[y];
    }
    ```

* **为什么交换后能统一**

    * 条件成立时交换之后，原来的 x 变成 y、原来的 y 变成 x，个数少的一方落到后面当老大。
    * 条件不成立时 x 和 y 保持原值不变，执行下面同一行逻辑同样正确。
    * 两个代码等价，选哪个看哪个更好理解。

* **兄弟优化 union by height**

    * 这种根据每个集合的元素个数来判断的优化方式叫 **union by size**。
    * 另一种优化叫 **union by height**，是根据两个集合中这棵树的高度来决定哪个集合作为最终的老大集合，因为每个集合都可以看成一棵树。
    * union by height 与 union by size 的实现非常相像，长文未展开其具体代码。
    * 路径压缩改的是「找得快」，union by size 改的是「挂得好」；两者都往 `parent` 数组里写，互相独立，可以同时用。

## 贪心算法

### 归类与适用场景

* **贪心算法（也称贪婪算法）**

    * > **定义**：它是一类算法的统称。

    * 迪杰斯特拉算法属于贪心算法，Prim 算法以及克鲁斯卡尔算法同样可以归类为贪心算法。

* **适用场景**

    * 贪心算法是用来寻找最优解问题的。
    * 迪杰斯特拉算法要找一个最短的路径，Prim 算法与克鲁斯卡尔算法要找的是相当于最短的距离，都属于寻找最优解问题。
    * 在寻找最优解的过程中把整个过程分成若干个步骤，每一步骤都采用贪心原则，这个算法就算是贪心算法。

* **贪心原则**

    * > **定义**：贪心原则就是在当前这个步骤里找到最优解，眼光放得不那么长远，只考虑当前这个步骤里的最优解；至于后续步骤里是不是最优，不考虑。

    * 迪杰斯特拉算法每次循环先在所有顶点里选一个距离最小的作为当前顶点，这一步就是一个贪心，至于这个顶点在将来的循环里是不是真的距离最短，不考虑。
    * 克鲁斯卡尔算法每次循环做的是选择一条边，选的方式是选一条距离最短的边。

### 两个已学贪心算法的距离含义

* **Prim 算法**

    * 每次循环都是把所有顶点里找一个当前距离最小的顶点。
    * 这个距离是跟邻居之间的距离。

* **迪杰斯特拉算法**

    * 每次循环在所有顶点里选一个距离最小的顶点。
    * 这个距离是一个累加的距离，与 Prim 的邻居距离稍微有些区别。

* **共同点**

    * 两个都是距离，每一步都在找一个当前最短距离的顶点，体现的都是「每步取当前最优、只考虑当下不考虑长远」的贪心原则。

### 每步最优堆起来未必全局最优

* **贪心的固有局限**

    * > **易错点**：贪心算法并没有考虑所有的可能性。每一步虽然选了当前步骤的最优解，但把所有步骤的最优解堆叠起来，并不一定能得到最终的最优解。

    * 典型表现是迪杰斯特拉算法在处理负权边时出现这个问题。

* **负权边反例的完整推演**

    * 求 v1 到其他顶点的最短距离，先把 v1 的距离初始化成 0，其他顶点的距离初始化成无穷大。
    * 第一步按贪心思想找到距离最短的是距离为 0 的 v1，对它处理并更新邻居，v2 的距离更新成 1，v3 的距离也更新成 1，这一步没有发现问题。
    * 第二步在剩余顶点里再找一个距离最短的，选中的是 v3；v3 把自己邻居的距离按 1 + 1 = 2 更新，这一步就导致最终结果错误。
    * v3 以后不会再被处理，它的距离被认为已经找到最短的就是 1，但从 v2 过来是 1 加上 -1 等于 0，比 1 更短。
    * 由于贪心只考虑当下，处理完 v3 之后它的距离不再更新；最后处理 v2 时也不会再更新 v3 的距离，v4 的距离同样没有更新，一直保持 2。

* **与贝尔曼福特算法的对比**

    * 贝尔曼福特算法不算贪心算法，它每次并不会「找一个距离最短的顶点去更新它的邻居」，而是每次都处理所有的边。
    * 处理了所有的可能，所以最终结果不会出错，在刚才那种负权边的情况下也不会出错。
    * 效率上迪杰斯特拉算法更高，贝尔曼福特算法效率相对更低，因为它每次都要处理所有的边。
    * 贪心相当于在穷举所有可能的情况下做的一个优化：不再穷举所有可能，每次只找一个局部的最优解。

### 更多贪心算法的例子

* **学过的例子**

    * 选择排序：每一轮循环都要找最小的值，把它交换到被排序的区域。
    * 堆排序：先构造一个大顶堆，每轮排序都把堆顶元素，也就是那个最大的元素，交换到数组的尾部。
    * 拓扑排序：按热度排序的方法每次都找到一个入度最小的顶点，把它从图里面删掉。
    * 并查集的 `union` 操作：每次合并两个集合时，挑一个元素更大的作为老大来进行合并。

* **没学过的例子**

    * 哈夫曼编码、钱币找零、任务编排、近似算法都可以使用贪心的思想。

    | 贪心算法 | 每一步的当前最优选择 |
    | :--- | :--- |
    | 选择排序 | 未排序区域中最小的值 |
    | 堆排序 | 堆顶的最大元素 |
    | 拓扑排序 | 入度最小的顶点 |
    | 并查集 `union` | 元素个数更多的集合当老大 |
