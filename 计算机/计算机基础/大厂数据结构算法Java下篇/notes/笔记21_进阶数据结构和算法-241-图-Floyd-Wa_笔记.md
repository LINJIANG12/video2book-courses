# 进阶数据结构和算法-241-图-Floyd-Wa

## 单源最短路径与全源最短路径

* **单源最短路径**
    * > **定义**：只指定一个源点、求它到其余所有顶点最短路径的算法。
    * 迪克斯特拉算法（被他自己戏称为"龟兔赛跑"）就是单源最短路径算法，源点固定，一次只能求出一个顶点到其他所有顶点的最短路径。
* **全源最短路径**
    * > **定义**：一次把所有顶点对之间的最短路径全求出来的算法。
    * 把算法跑一遍，v1 到别人、v2 到别人、v3 到别人、v4 到别人的答案一趟全齐。

## 弗洛伊德算法

* **弗洛伊德算法（Floyd algorithm，全称 Floyd-Warshall）**
    * > **定义**：全源最短路径算法，跑一遍就算出所有顶点对之间的最短距离。
    * 迪克斯特拉和弗洛伊德都是图灵奖得主，一个搞出了龟兔赛跑，一个搞出了它。
    * > **注意**：可以处理负权边，但遇到负环照样不行。
    * 示例图里有负边（v1 → v3 权重 -2），也有环，但两条环的权重和分别是 v2 → v1 → v3 → v4 → v2 的 4 + (-2) + 2 + (-1) = 3、v2 → v3 → v4 → v2 的 3 + 2 + (-1) = 4，都不是负数，所以没有负环，算法照常工作。

## 示例图的出边与初始距离表

* **示例图**
    * 四个顶点 v1、v2、v3、v4，五条有向边。
    * 箭头是有向的，从左端出发指向右端；这五条边就是后面初始化那张表的全部依据。
    ```text
    出边清单（adjacency）：

    v1 ──(-2)──▶ v3
    v2 ──(4)────▶ v1
    v2 ──(3)────▶ v3
    v3 ──(2)────▶ v4
    v4 ──(-1)───▶ v2
    ```
* **距离表 dist**
    * 横轴和纵轴都是 v1 到 v4：行是"从谁出发"，列是"到谁那儿去"。
    * 初始化规则：两个是同一个顶点就置 0；不是同一个顶点，不连通置 ∞，连通就置成权重。
    * `∞` 表示当前"此路不通"，不是真的距离，是"暂时没找到路"。
    * > **提示**：初始表记录的是从一个顶点直连到其他顶点的最短距离，走弯路的那些可能性全靠后面的循环一层层补进来。
    ```text
                v1    v2    v3    v4
      v1 [     0      ∞    -2      ∞ ]
      v2 [     4      0      3      ∞ ]
      v3 [      ∞      ∞      0      2 ]
      v4 [      ∞    -1      ∞      0 ]
    ```

## 借助顶点 k 的四轮循环

* **轮次划分与跳过规则**
    * k 从 1 走到 4，一共四轮；每一轮干的是同一件事：看这些顶点借助 vk（依次换成 v2、v3、v4）能不能到别的顶点去，能而且距离更短就更新掉。
    * 起点自己借自己没有区别，直接跳过。
    * 起点到 vk 是 ∞ 就借不上，这一整行都不用看。
* **k = 1 借 v1**
    * v2 能到 v1（距离 4），接过 v1 后能到 v3（权重 -2），总路径 4 + (-2) = 2，比原来 v2 直接到 v3 的 3 更近，`dist[v2][v3]` 由 3 更新成 2。
    * v2 借 v1 到 v4 到不了，因为 v1 到 v4 是 ∞，此路不通，不用管。
    * v3 到 v1 是 ∞、v4 到 v1 是 ∞，都借不上 v1，这两行不更新。
    * 本轮唯一被更新的是 `dist[v2][v3]`：3 → 2。
* **k = 2 借 v2**
    * v1 到 v2 是 ∞ 借不上、v2 自己借自己没意义、v3 到 v2 是 ∞ 借不上，三处都跳过。
    * v4 能到 v2，距离 -1；借 v2 到 v1 可以，-1 + 4 = 3，原来 v4 到 v1 是 ∞，更新为 3。
    * 借 v2 到 v3 也可以，v2 到 v3 那格此时已是 2，-1 + 2 = 1，原来 v4 到 v3 是 ∞，同样更新。
    * 本轮更新两个值：`dist[v4][v1] = 3`、`dist[v4][v3] = 1`。
* **k = 3 借 v3**
    * v1 能到 v3，距离 -2；借 v3 到 v4 可以，权重 2，-2 + 2 = 0，原来 v1 到 v4 是 ∞，更新为 0。
    * v2 能到 v3，距离 2；借 v3 到 v4 可以，权重 2，2 + 2 = 4，原来 v2 到 v4 是 ∞，更新为 4。
    * v3 自己借自己跳过；v4 虽能到 v3，但 v3 到 v1、v3 到 v2 都是 ∞，两头发不通，这行等于没处理。
* **k = 4 借 v4**
    * v1 到 v4 的距离是 0，它不是凭空来的，是先到 v3（-2）再到 v4（+2），-2 + 2 = 0 攒出来的。
    * v1 借 v4 到 v2 可以，权重 -1，0 + (-1) = -1，原来 v1 到 v2 是 ∞，更新。
    * v1 借 v4 到 v3 得 0 + 1 = 1，但原来 v1 到 v3 已经是 -2，比这个 1 小，所以不更新，保留 -2。
    * v2 到 v4 的距离是 4（先 v2 → v1 → v3 → v4）；借 v4 到 v1 得 3 + 4 = 7 比原来的 4 大，借 v4 到 v3 得 5 比原来的 2 大，两处都不更新。
    * v3 能到 v4，距离 2；借 v4 到 v1、v2 原来都是 ∞，更新为 2 + 3 = 5（`dist[v3][v1]`）、2 + (-1) = 1（`dist[v3][v2]`）。
* **最终距离表**
    * 跑完 k = 1、2、3、4 四轮，表里一个 ∞ 都不剩，任意一格 `(i, j)` 就是从 vi 到 vj 的最短距离。
    * 以 v1 为例：到 v2 是 -1，到 v3 是 -2，到 v4 是 0；v2 到 v1 是 4，到 v3 是 2，到 v4 是 4。
    ```text
                v1    v2    v3    v4
      v1 [     0    -1    -2      0 ]
      v2 [     4      0      2      4 ]
      v3 [     5      1      0      2 ]
      v4 [     3    -1      1      0 ]
    ```

## 初始化阶段的两层循环

* **方法签名与表的开辟**
    * 方法签名只把顶点集合传进来（`floydWarshall(Graph graph)`），进来第一件事拿到顶点个数 `size`，按它开一张 `size × size` 的二维表。
    * 旁边另备一个 `print` 方法专门打印这张二维表，遇到无穷大就打个无穷大的符号；刚开出来时表里全是一堆 0，属于准备工作。
* **两层循环的遍历方向**
    * 外层 `i` 从 0 到 `size` 遍历每一行的顶点，内层 `j` 从 0 到 `size` 遍历每一列的顶点。
    * 命名约定：外层的点记作 `v`，是行（起点）；内层的点记作 `u`，是列（终点）。
* **连通性判定与 map 提速**
    * 判定办法是看外层顶点的边集合里有没有内层这个顶点：内层到 v2 就在 v1 的边集合里找 v2，找不到说明不连通，找到了说明连通，直接把权重写进去。
    * 找不到时给个默认值 `Integer.MAX_VALUE` 当无穷大。
    * > **易错点**：不要直接拿 List 去 `contains`，边集合是个列表容器，得一个个比，效率太难看；这里用 map 提速，key 放顶点，value 放权重，查找快得多。
    ```java
    public void floydWarshall(Graph graph) {
        int size = graph.getVertices().size();
        int[][] dist = new int[size][size];

        // 外层 i 遍历每一行的顶点，内层 j 遍历每一列的顶点
        for (int i = 0; i < size; i++) {
            Vertex v = graph.get(i);

            // 把外层顶点的边集合转成 map：key 是边指向的顶点，value 是权重
            Map<Vertex, Integer> edgeMap = v.getEdges().stream()
                    .collect(Collectors.toMap(e -> e.getTo(), e -> e.getWeight()));

            for (int j = 0; j < size; j++) {
                Vertex u = graph.get(j);
                if (v == u) {
                    // 同一个顶点：自己到自己，距离为 0
                    dist[i][j] = 0;
                } else {
                    // 找得到就是连通，返回权重；找不到给默认值当无穷大
                    dist[i][j] = edgeMap.getOrDefault(u, Integer.MAX_VALUE);
                }
            }
        }
        print(dist);
    }
    ```
* **顶点充当 map key 的配套要求**
    * > **易错点**：既然用了 map 当 key，那 key 的哈希值和相等性就要靠 `hashCode` 和 `equals` 撑着，这两个方法一定得给上，千万别忘了写。
    * 顶点的这两个方法就拿 `name` 来生成，因为 name 是唯一的，靠它就能把顶点区分开。
    ```java
    @Override
    public int hashCode() {
        return Objects.hash(name);
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        Vertex vertex = (Vertex) o;
        return Objects.equals(name, vertex.name);
    }
    ```

## 三层循环与状态转移公式

* **循环层次**
    * "借助"这件事用三层循环表达：最外层变量是 `k`，从 0 循环到 `size`，对应第一轮到第四轮；里面再来两层分别循环 `i` 和 `j`，体现的是每次做操作都要把每一行、每一列都处理到。
    * `dist[i][j]` 表示不借助 k 顶点时从第 i 行的顶点直接到第 j 列的顶点的距离。
    * 借 k 绕过去更短就用更短的更新原来的，这一步写成状态转移公式就是下面这个式子，前提是 `dist[i][k]` 和 `dist[k][j]` 都不是 ∞。
    $$dist[i][j] = \min\bigl(dist[i][j],\ dist[i][k] + dist[k][j]\bigr)$$
* **两段距离的拼接**
    * 第一段 `dist[i][k]` 是"起点 i 到中转点 k"，第二段 `dist[k][j]` 是"中转点 k 到各个目的地"，两段加起来就是 i 借道 k 走到了 j。
    * > **提示**：记住这个对应关系后面就不会写错——**i 是行（起点），k 是中转（那个被借的顶点），j 是列（终点）**，中间那一堆 k 一个都不能少。
    ```text
      第一段（行 i = 1，即 v2 → v1）：  dist[1][0]
                    |
                    |  把 v2 交给 v1 之后，下一段由 v1 说了算
                    v
      第二段（行 k = 0，即 v1 → 所有）：  dist[0][0]  dist[0][1]  dist[0][2]  dist[0][3]
                                         v1→v1     v1→v2     v1→v3     v1→v4

      两段一加 =  dist[i][k] + dist[k][j] = v2 经 v1 到了 vj
    ```
* **路不通就别硬算**
    * 路不通的时候，后续的距离判断和更新操作一律没必要做。
    * 比如循环到 v3，v3 要借 v1 去别的地方，可 v3 到 v1 是 ∞，后面拿 v1 到 v2、v3、v4 的距离去算全是白算。
    * "不通"有两种可能：起点到中转点不通（v3 到 v1），或者中转点到目标不通（v2 到 v1 明明通了，但 v1 到 v4 是 ∞）。
    * 所以条件得写成：`dist[i][k]` 不等于无穷大**并且** `dist[k][j]` 也不等于无穷大，才做后续的判断和更新。
    ```java
    // 第二阶段：k 必须在最外层，i 是行（起点），j 是列（终点）
    for (int k = 0; k < size; k++) {
        for (int i = 0; i < size; i++) {
            for (int j = 0; j < size; j++) {
                // 两头都得通，否则没有继续算的必要
                if (dist[i][k] == Integer.MAX_VALUE || dist[k][j] == Integer.MAX_VALUE) {
                    continue;
                }
                // 借 k 更短，就更新
                if (dist[i][k] + dist[k][j] < dist[i][j]) {
                    dist[i][j] = dist[i][k] + dist[k][j];
                }
            }
        }
        print(dist);
    }
    ```

## 运行结果与手推对照

* **逐轮打印的做法**
    * 每轮 k 循环结束都把整张数组打出来，和手动分析的对照。
* **各阶段表格的快照**
    * 初始化完：`0 ∞ -2 ∞ / 4 0 3 ∞ / ∞ ∞ 0 2 / ∞ -1 ∞ 0`，跟手推的第一张表一模一样。
    * 借 v1 之后：`0 ∞ -2 ∞ / 4 0 2 ∞ / ∞ ∞ 0 2 / 3 -1 1 0`，只有 v2 到 v3 那个 3 变成了 2。
    * 再一轮之后：`0 ∞ -2 0 / 4 0 2 4 / ∞ ∞ 0 2 / 3 -1 1 0`，多了 v1 到 v4 的 0、v2 到 v4 的 4。
    * 最后一轮：`0 -1 -2 0 / 4 0 2 4 / 5 1 0 2 / 3 -1 1 0`，全表填满，一个 ∞ 都不剩。
    * 程序的运行结果和手动分析的结果完全一致。

## previous 数组记录路径详情

* **previous 数组**
    * > **定义**：元素类型是顶点的二维数组，宽高都是顶点个数 `size`，记录这个路径是从哪个顶点走过来的，也就是上一个顶点。
    * 一开始所有元素全是 `null`，这个是合理的，因为一开始压根不知道它上一个顶点是谁、从哪儿走过来的。
    * 它要更新的地方只有两处：初始化的时候更新一次，借助（更新距离）的时候再更新一次。
* **初始化阶段的更新**
    * 写在原来那个 `else` 的位置，也就是原来判断连不连通的逻辑里：先去 map 里 `get` 一下内层顶点 `u`，检查它在不在外层顶点的边集合中。
    * 返回值不等于 `null` 说明连通，就把上一个顶点更新成 `v`，因为它是从 v 走到 u 的；不连通就保持 `null` 不变。
    * 初始化跑完后，每格记的是"到这一列的顶点，是从左边哪个顶点走过来的"；打印时遇到 `null` 就打 `null`，否则打顶点名字。
    ```java
    if (v == u) {
        dist[i][j] = 0;
    } else {
        Integer weight = edgeMap.get(u);
        dist[i][j] = weight == null ? Integer.MAX_VALUE : weight;
        // 连通就记下"上一个顶点是不通就不记"
        previous[i][j] = weight == null ? null : v;
    }
    ```

    ```text
                v1    v2    v3    v4
      v1 [   null   null    v1   null ]
      v2 [     v2   null    v2   null ]
      v3 [   null   null   null     v3 ]
      v4 [   null     v4   null   null ]
    ```
* **借助阶段的更新**
    * 更新时机是在 `if` 条件成立、触发 `dist` 更新之后。
    * 例子：某次循环到 v2，v2 借 v1 到 v3，v2 先到 v1 距离 4、v1 再到 v3 距离 -2，整条路径 2 比原来直接从 v2 到 v3 的 3 小，触发更新；对 v3 来讲它的上一个顶点就从 v2 改成了 v1。
    * 更新方式：取 k 行 j 列那一格，即从借助 k 到达 j 的路过来。
    ```java
    if (dist[i][k] + dist[k][j] < dist[i][j]) {
        dist[i][j] = dist[i][k] + dist[k][j];
        // 从借助 k 到达 j 的路过来，就是 previous 数组 k 行 j 列那一格
        previous[i][j] = previous[k][j];
    }
    ```
* **最终 previous 的第一行**
    * v1 到 v1 是自己，记 `null` 不看；v1 到 v2 的上一顶点是 v4，说明 v1 要绕一圈到 v4 再拐到 v2；v1 到 v3 是直接过来的，上一顶点就是 v1；v1 到 v4 是经由 v3 过来的，上一顶点是 v3。
    ```text
                v1    v2    v3    v4
      v1 [   null     v4    v1     v3 ]
    ```

## 路径打印

* **path 方法**
    * 它接收这几个参数：`previous` 数组（存的就是最终结果）、顶点集合，还有 `i` 和 `j` 两个数，分别代表起点和终点。
    * 准备好之后直接写两层循环调用它，外层 `i` 从 0 到 `size`、内层 `j` 从 0 到 `size`，这样从 i 到 j 的所有路径就全被遍历出来打印了。
    ```java
    for (int i = 0; i < size; i++) {
        for (int j = 0; j < size; j++) {
            path(previous, graph.getVertices(), i, j);
        }
    }
    ```
* **以 v1 为起点的打印结果**
    * v1 到 v1，直接走一个 v1 就行。
    * v1 到 v2，是先经过 v1 到 v3，再到 v4，再到 v2，这就是 v1 到 v2 的最短路径。
    * v1 到 v3，还是直接过来的。
    * v1 到 v4，是 v1 先到 v3，再到 v4。
    * 后面依次是以 v2、v3、v4 出发到其他四个顶点的路径，与上面同构。
