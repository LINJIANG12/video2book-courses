## Floyd 负环检测

### 负环

* **负环（negative cycle）**

    * > **定义**：图中存在一个环，环上所有边权之和为负数。

    * 示例图里 v1 可以到 v2、v2 可以到 v3、v3 又回到 v1，构成一个环，其权重和为 $2 + (-4) + 1 = -1$，小于零。

    * 出现负环后最短路径最终没有解：绕着这个负环多走一圈距离就少一圈，答案是负无穷大。

    * 判定依据是只要存在负环，某一次运算就会把距离表对角线上的 0 改成负数。

* **对角线扫描**

    * 三层循环跑完后只需要检查 dist 数组的对角线，不必再逐格分析后续轮次，因为再分析下去它只会越减越少，这正是负环的可怕之处。

    * 检测逻辑不需要额外编写任何特殊算法，算法结束后扫一眼对角线就完事了。

### 距离表的建立

* **dist 距离表**

    * > **定义**：行是"从哪儿出发"、列是"到哪儿去"的二维表，中间那一格就是这两个点之间当前的最短距离。

    * 初始化规则是不直接连通的一律先填无穷大，连通的填上权重，自己到自己填 0。

    * 示例图四个顶点 v1 到 v4 的初始距离表如下。

    | 起点 ＼ 终点 | v1 | v2 | v3 | v4 |
    | :--- | :--- | :--- | :--- | :--- |
    | v1 | 0 | 2 | ∞ | ∞ |
    | v2 | ∞ | 0 | -4 | ∞ |
    | v3 | 1 | ∞ | 0 | 1 |
    | v4 | ∞ | ∞ | ∞ | 0 |

* **借道中转顶点**

    * 三层循环中的 k 表示当前借道的顶点，k 等于几就是问一句"我能不能借道第几个顶点到其他顶点"，然后一行一行过。

    * 某一行到中转顶点是无穷大说明压根借不到，这一行不用看；借到之后若后两格也是无穷大，说明路不通，同样不看。

    * 起点自己那一行是借自己到其他点，没什么可看的，直接跳过。

### 借道推演

* **借道 v1（k 等于 0）**

    * v3 到 v1 是通的、距离是 1，先到 v1 再借 v1 到 v2 的权重是 2，加起来是 3，原来 v3 直接到 v2 是无穷大，3 显然比无穷大小，于是更新 `dist[3][2] = 3`。

    * v2 到 v1 是不通的、压根借不到 v1，v4 一上来就是无穷大也借不到 v1，这两行不用看，第一轮确实只有一个距离被更新。

* **借道 v2（k 等于 1）**

    * v1 到 v2 是通的，但借 v2 回到 v1 不行，因为 v2 到 v1 是无穷大；再借 v2 到 v3 得到 $2 + (-4) = -2$，比原来的无穷大小，更新成 -2，到 v4 不通不看。

    * v3 到 v2 是通的，借 v2 回到 v3 自己可行：先到 v1 距离 1，v1 再到 v2 距离 2，v2 再到 v3 距离 -4，加起来 $1 + 2 + (-4) = -1$。

* **对角线塌陷**

    * v3 到自己本来是 0，而 -1 比 0 还小，所以 `dist[3][3]` 这个本该是 0 的对角线格子被更新成了负数，问题到这儿就暴露出来了。

    * 之后的轮次不再逐格分析，只需要记住结论：只要存在负环，某一次运算就会把对角线上的 0 改成负数。

### 检测代码

* 三层循环正常跑完后遍历 dist 数组的对角线，任一位置小于零就可以推断出现了负环，抛一个异常告诉它最短路径没有解，给出第一个提示即可。

    ```java
    for (int i = 0; i < dist.length; i++) {
        if (dist[i][i] < 0) {
            throw new RuntimeException("发现负环，最短路径没有解");
        }
    }
    ```

* 检测到负环就直接中断算法，不需要额外的检测逻辑或补救计算。

## 最小生成树

* **最小生成树（minimum spanning tree，MST）**

    * > **定义**：n 个顶点里挑出 n-1 条边，把它们全部连通，且权重总和最小。

    * 边数由顶点数决定：七个顶点就找六条边，连接七个顶点六条边就够用了。

    * 每条边都有权重，要求这六条边的权重加起来是最少的。

    * 现实意义可以类比成家里有七个开关，现在要铺设电线把七个开关都连通，铺法有很多种，要找的就是成本最低的那一种。

* **两类算法的分工**

    * Prim 算法以顶点为核心，每次去找顶点相邻顶点的最短距离，然后依次处理每个顶点去更新这个最短距离，最终所有顶点都处理完一遍，整个最小生成树也就有了。

    * Kruskal 算法以边为核心，去逐一处理每条边，由每条边的取舍来得到最后的最小生成树。

## Prim 算法

### 初始化与推进规则

* **Prim 算法（Prim's algorithm）**

    * > **定义**：从一个起点出发一圈圈向外长，每轮在尚未处理的顶点里挑距离最小的那个处理，处理它时用它去更新相邻顶点的距离。

    * 初始状态把起点距离设置为 0，除了起点以外的顶点距离全部设置为无穷大。

    * 处理顶点时找到它的相邻顶点去更新距离，遇到有更小的距离就更新，同时要记录这个距离是从谁来的，存进 previous。

    * 遇到已经处理过的顶点就不用管了，只看还没处理的那些。

    * 每个顶点处理完，它跟已处理部分之间的那条路径就确定了。

### 顶点处理顺序

* v1 处理完后，v2 由无穷大更新成 2 来路 v1，v4 更新成 1 来路 v1，v3 更新成 4 来路 v1。

* 剩余顶点中 v4 的距离 1 最小，所以第二个处理它；此时 v2 算出 3 比原来记录的 2 还大不更新，v3 由 4 更新成 2 来路改成 v4，v5 更新成 7、v6 更新成 8、v7 更新成 4 来路都是 v4。

* v2 和 v3 的距离都是 2，随便挑一个即可，按顺序先处理 v2；它相邻的没处理过的顶点只有 v5，但 v5 现在是 10，比 v4 给的 7 还大，不用更新。

* 接着处理 v3，它相邻的 v1、v4 都处理过了，只看 v6，用更短的 5 把那边的 8 替换掉，previous 也跟着更新成 v3。

* 剩下三个顶点里 v7 最近：v4 已经处理过，v6 更新成 1、v5 更新成 6（比 7 小），来路都是 v7。

* 最后 v6 的距离更短，其实它都不用处理了，相邻的几个顶点都已处理过，只需要把它那条路径找出来画出来，它是从 v7 过来的；最后一个顶点 v5 相邻的也都处理过了，从 v7 连过来。

### 距离表演进

* 每处理完一个顶点就记录一次距离与来路，四轮之后七个顶点的状态如下。

    ```text
    [v1 处理完]
        顶点:  v1    v2    v3    v4    v5    v6    v7
        距离:   0     2     4     1     ∞     ∞     ∞
        来路:  --    v1    v1    v1    --    --    --

    [v4 处理完]
        顶点:  v1    v2    v3    v4    v5    v6    v7
        距离:   0     2     2     1     7     8     4
        来路:  --    v1    v4    v1    v4    v4    v4

    [v3 处理完]
        顶点:  v1    v2    v3    v4    v5    v6    v7
        距离:   0     2     2     1     7     5     4
        来路:  --    v1    v4    v1    v4    v3    v4

    [v7 处理完]
        顶点:  v1    v2    v3    v4    v5    v6    v7
        距离:   0     2     2     1     6     1     4
        来路:  --    v1    v4    v1    v7    v7    v4
    ```

### 最终生成树

* 七个顶点的六条路径全部连接好后，previous 的最终取值是：v2 的 previous 是 v1，v3 是 v4，v4 是 v1，v5 是 v7，v6 是 v7，v7 是 v4；v1 是起点，它的 previous 是空的。

* 拼出来的最小生成树形如下面这样，v2、v3 分别挂在 v4 两侧，v7 从 v4 伸出再带出 v5 和 v6。

    ```text
    v2 - v1 - v4 - v3
            |
            v7 - v5
            |
            v6
    ```

### 与 Dijkstra 的差别

* Prim 在思想上与迪克斯拉（Dijkstra）算法非常相似，可以对比着看，差别只落在"更新距离"那一行。

    | 步骤 | 迪克斯拉（Dijkstra） | Prim |
    | :--- | :--- | :--- |
    | 起点距离 | 置 0 | 置 0 |
    | 其他顶点距离 | 置 ∞ | 置 ∞ |
    | 选下一个顶点 | 在未处理的顶点集合里选距离最小的 | 在未处理的顶点集合里选距离最小的 |
    | 更新距离 | 当前顶点距离 + 权重 | 只看权重本身 |
    | 顶点处理完 | 从集合移除，标记 visited = true | 从集合移除，标记 visited = true |

* 迪克斯拉算的是累加值，要把当前顶点的距离跟那个 weight 加在一起；Prim 每次更新距离时只考虑这个权重本身，不用考虑之前那个距离。

    ```java
    // 迪克斯拉：距离是累加值
    int newDist = dist[current] + weight;

    // Prim：只看权重本身，不加之前那个距离
    int newDist = weight;
    ```

* 因此可以把迪克斯拉的代码直接复制一份，"更新邻居距离"和"选择最小距离顶点"这两个方法都不用动，拿过来即可，唯一要改的就是计算距离的那一处。

## Kruskal 算法

### 边的排序与取舍

* **Kruskal 算法（Kruskal's algorithm）**

    * > **定义**：先把所有的边根据权重排个序、由小到大依次处理，能用的边取进结果集合。

    * 取边的前提是这条边的两个顶点原来并不相交、换句话说原来没有连通，只有未连通的顶点才能用这条边连起来。

    * 一开始认为所有顶点都不连通，v1 跟 v4 原来不连通所以用上权重为 1 的第一条边，v6 和 v7 原来也不连通用上第二条边。

    * 权重为 2 的 v1-v2 可以用，它把尚未连入网络的 v2 接进来；另一条权重为 2 的边 v3-v4 也可以用，把 v3 连进来。

    * 退出条件是结果集合里边的个数等于顶点个数减一，找够六条边就不用了，权重更大的边也一并跳过。

* **九条候选边的取舍结果**

    * 按权重从小到大逐条判断，两端已经连通的直接跳过，未连通的取进来。

    | 权重 | 边 | 两端是否已连通 | 取不取 |
    | :--- | :--- | :--- | :--- |
    | 1 | v1 - v4 | 否 | 取（第 1 条） |
    | 1 | v6 - v7 | 否 | 取（第 2 条） |
    | 2 | v1 - v2 | 否 | 取（第 3 条） |
    | 2 | v3 - v4 | 否 | 取（第 4 条） |
    | 3 | v2 - v4 | 是 | 跳过 |
    | 4 | v1 - v3 | 是 | 跳过 |
    | 4 | v4 - v7 | 否 | 取（第 5 条） |
    | 5 | v3 - v6 | 是 | 跳过 |
    | 6 | v5 - v7 | 否 | 取（第 6 条） |

### 边的表示

* **边的存储**

    * 因为 Kruskal 要以边为核心来实现代码，所以把所有边放进一个优先级队列，一共有 12 条边。

    * 新写的边类主要属性有：顶点的集合，还有边的起点、终点和权重；之前那个边的类不再使用。

    * 起点终点是一个索引值，代表它们在顶点集合中的索引；v1 到 v2 的起点是 0、终点是 1、权重是 2，v1 到 v3 的起点是 0、终点是 2、权重为 4。

    * 放到优先级队列就要实现 Comparable 接口，按边的权重排序，将来权重越小的越排在队列前面。

    * 每次循环从优先级队列里用 poll 拿到权重最小的那条边来处理。

### 实现代码

* 方法接受两个参数：顶点个数和边集合；方法内先准备一个 List 集合来存储最终找到的边对象，代表结果集合。

* 循环条件是结果集合还没找够边，也就是边的个数还小于 size 减一；等于 size 减一就表示六条边都找够了，退出循环。

* 判断连通性靠不相交集合（并查集）的 find 方法，把边的两个顶点——起点和终点——分别拿到集合里去找，返回值分别记作 i 和 j。

* `i != j` 表示它俩尚未相交、未连通，这条边可以用上，加进结果集合；用上之后还要做 union 操作，把刚才这两个顶点连到一起，union 的本意是求并集，相当于把这两个集合连起来。

* 返回结果相等说明它们是连通的、已经相交了，那这条边就应该被跳过去。

    ```java
    public List<Edge> kruskal(int size, PriorityQueue<Edge> edges) {
        List<Edge> result = new ArrayList<>();
        DisjointSet disjointSet = new DisjointSet(size);

        while (result.size() < size - 1) {
            Edge edge = edges.poll();

            int i = disjointSet.find(edge.start);
            int j = disjointSet.find(edge.end);

            if (i != j) {
                result.add(edge);
                disjointSet.union(i, j);
            }
        }

        return result;
    }
    ```

### 结果验证

* 重写边的 toString 后循环打印结果集合，打出来的六条边依次是 v1-v4、v6-v7、v3-v4、v1-v2、v4-v7、v5-v7。

* 打印结果与手动分析的结果一致，说明算法正确，拼出来的树跟 Prim 那棵一模一样。

    ```text
    v2 - v1 - v4 - v3
            |
            v7 - v5
            |
            v6
    ```

## 并查集

### 数组的语义

* **不相交集合 / 并查集（Disjoint Set）**

    * > **定义**：内部维护一个数组，数组的索引对应图中顶点，两个核心方法是 union（合并）和 find（查询）。

    * 名字由来的原因是集合内有两个比较重要的方法：union 的本意是合并，find 的本意是查询，基于这两个方法常把它叫作并查集。

    * 数组大小由构造方法的 size 决定，size 就是图中的顶点个数；数组创建后把每个元素初始化成它自己的 i，打印出来就是 0 是 0、1 是 1，以此类推。

    * 数组索引对应顶点，索引里的元素值表示与它有关系的顶点；元素 0 的值是 0，意思就是与顶点 0 有关系的只有它自己，整个数组初始表示这些顶点之间没有联系、都只与自己有关系。

    * Kruskal 里用到了它判断两个顶点是不是已经相连，但当时只是用了方法，实现要先看构造方法、find 和 union 这三个。

* **构造方法**

    * 作用是对集合中的数组做初始化，数组就对应着图中的这些元素。

    ```java
    public DisjointSet(int size) {
        s = new int[size];
        for (int i = 0; i < size; i++) {
            s[i] = i;
        }
    }
    ```

### 老大与小弟

* **老大与小弟**

    * 连接关系是对等的，把 0 的数组值改成 3 表示两者相连，反过来把 3 的数组值改成 0 同样成立；5 与 6 连一起也一样，改一个指另一个即可。

    * 索引等于元素值的那个元素就是老大，索引不等于元素值的就是小弟；索引 0 的值是 0 是老大，索引 3 的值是 0、不相等所以是小弟，跟着老大 0。

    * ⚠️ **易错点**：有多个元素的情况必须找到老大，改的是老大对应的数组值，不能改小弟自己。把 3 和 5 连到一起时，3 已经跟 0 连通、老大是 0，5 是 6 的老大，所以要么改 0 的值要么改 5 的值，绝不能改 3。

    * 整个状态从初始化到两次合并的演进如下。

    ```text
    初始化          s = [0, 1, 2, 3, 4, 5, 6]      每个元素都指向自己

    s[3] = 0        s = [0, 1, 2, 0, 4, 5, 6]      把 0 和 3 连到了一起
    s[6] = 5        s = [0, 1, 2, 0, 4, 5, 5]      把 6 和 5 连到了一起

    索引 == 元素值  →  老大（0 和 5）
    索引 != 元素值  →  小弟（3 跟着 0，6 跟着 5）
    ```

### union

* **union（合并）**

    * > **定义**：让两个原本不相交的集合相交，说白了就是在这两个集合里选出一个新的老大。

    * 实现方式是挑 x 作为老大、y 作为小弟，找到数组中 y 存储的位置，把它的值改成 x。

    * 方法参数 x、y 是原本那两个集合中的老大索引；例如 x 是 5、y 是 6，就是找到 6 存储的位置把它的值改成 5。

    * 原来 0 是老大、原来 5 是老大，要让它们相交就得找一个新老大，比如 0 是最终的新老大，那原来 5 它的值就得改成 0。

    * ⚠️ **易错点**：union 并不代表连线。把 3 和 5 连到一起时实际应该调用的是两边的老大，也就是 0 和 5，记作 union(0, 5) 而不是 union(3, 5)。

    ```java
    public void union(int x, int y) {
        s[y] = x;
    }
    ```

### find

* **find（查询）**

    * > **定义**：在一个集合里找到那个老大的索引。

    * 传过来的都是索引值，值 x 如果等于它的数组值 s[x]，说明找到了老大，直接返回这个 x。

    * 如果传过来的是小弟的索引，比如传的是 3，就拿到它里面的值再找一次，把 s[x] 当作索引再做一次递归查询。

    ```java
    public int find(int x) {
        if (x == s[x]) {
            return x;
        }
        return find(s[x]);
    }
    ```

### 在 Kruskal 中的判定

* Kruskal 里判断用的 i 和 j 是两个顶点各自所在集合的老大索引，i != j 说明它们本来不在一个集合里、中间那条路现在是通的，可以用这条边；i == j 说明绕一大圈发现它俩本来就连着，这条边只能跳过去。

* 因此 Kruskal 的执行序就是取边、查两个端点的老大、根不同就收边并合并、边数凑够就退出。
