# 基础算法-223-排序-e03-最大间距-解法1

## 最大间距（Maximum Gap）

* **最大间距（Maximum Gap）**

    * > **定义**：给定一个无序数组 `numbers`，先对它排序，再取排好序之后相邻两个元素之间的最大差值。

    * 示例：`3 6 9 1` 排序后是 `1 3 6 9`，相邻差值分别为 `3 - 1 = 2`、`6 - 3 = 3`、`9 - 6 = 3`，最大差值为 3。

    * > **易错点**：要求的是排好序之后相邻元素的差值，不是原数组里的最大差值，也不是最大值减最小值。

* **元素个数小于 2 的边界**

    * 数组元素个数小于 2 时只剩一个元素，没有相邻元素，没有差值可取，直接返回 0。

    * 这段判断必须放在计算 `range` 之前，因为 `range` 的公式要用到数组长度减一。

## 线性时间与线性空间的硬约束

* **题目附加需求**

    * 必须编写一个在线性时间内运行、并使用线性额外空间的算法，时间复杂度与空间复杂度都要是 $O(n)$。

    * 插入排序这一类比较排序的时间复杂度是 $O(n^2)$，直接被否掉。

    * 剩下的合法选项只有桶排序或者基数排序，这才是这道题的难点所在。

* **排序之后的那段遍历**

    * 排好序之后遍历求相邻差值本身就是线性时间的，与排序那一段加起来仍是线性。

    * 循环从 `i = 1` 开始，每轮算 `numbers[i] - numbers[i - 1]`，再用 `res = Math.max(res, numbers[i] - numbers[i - 1])` 让本次差值与已记录的最大值取更大的。

## 桶排序直接求解

* **参数选择与数据流**

    * 桶排序里的 `range` 表示"每个桶能装多大的值域"，桶的个数由它算出来；这里取 `range = 1`，希望一个元素进一个桶。

    * 先一趟循环求出 `max` 与 `min`，桶的个数为 `count = (max - min) / range + 1`，每个桶用一个 `ArrayList` 表示，多个桶用一个数组持有。

    * 入桶下标是 `index = (num - min) / range`，然后按桶号 0、1、2…… 依次把元素写回原数组，写完的下标变量 `k` 每放一个元素加一。

    ```text
                 range = 1：每个值自己一个桶

      numbers:  1     3     5     9
                 |     |     |     |
                 v     v     v     v
      buckets: [1]   [3]   [5]   [9]
                 |     |     |     |
                 +--->-+--->-+--->-+--->  按桶号从小到大依次取出
                        |
                        v
      numbers:  1     3     5     9        （已排好序）
    ```

* **线性性与运行结果**

    * 桶排序是线性时间，遍历求差值也是线性时间，两段加起来还是线性，逻辑上完全没问题。

    * 跑 `1 3 5 9`：三轮差值分别是 `3 - 1 = 2`、`5 - 3 = 2`、`9 - 5 = 4`，最大差值 4。

    * > **易错点**：桶排序里那行打印调试的代码待会儿记得注释掉，不然每跑一次测试用例就刷一屏。

* **超内存的根因**

    * 题目把元素取值范围卡在 0 到 $10^9$ 之间，并且存在某个元素是 $10^7$ 的测试用例。

    * `range = 1` 时桶的个数就是"最大值减最小值加一"，$10^7$ 就是 1000 万个桶，提交上去会得到"超出内存限制"。

    * 逻辑上没有错误，错在桶的个数太多，不满足线性空间的需求。

## 基数排序

* **按位分桶的思想**

    * 基数排序就是按位来排：先排个位，再排十位、百位，以此类推。

    * 待排序的都是数字，任何一位的取值都在 0 到 9 之间，所以准备十个桶（0 号到 9 号）就足够用，可以大大缩减桶的范围。

    * 整个基数排序过程中始终只用了十个桶，就完成了所有数据的排序。

* **一轮排序的三个动作**

    * 创建十个桶，每个桶用一个 `ArrayList` 表示，多个桶用一个数组持有。

    * 入桶：对原数组循环，每个数字取它除以 10 的余数，余数就是桶的索引，把数字加进这个桶。

    * 出桶：定义下标变量 `k`，循环每个桶把数字写到 `numbers[k++]`，写完 `k` 加一，循环完一遍就把桶里的元素取出来放回了原始数组，这一轮结束。

    * 每轮结束前把当前的桶清空，内容已经取出来了，留着没用了；轮外再打印一次 `numbers` 检查这一轮的效果。

* **多轮演进的过程**

    * 用一组含很大数字的数演示：个位那一轮，26 与 16 都进 6 号桶，13 进 3 号桶，11 进 1 号桶，大数的个位是 0 进 0 号桶，取出后得到"大数 11 13 26 16"。

    * 十位那一轮，大数十位还是 0 仍进 0 号桶，11、13、16 十位都是 1 进 1 号桶，26 十位是 2 进 2 号桶，取出后是"大数 11 13 16 26"，后几个已经排好。

    * 百位、千位以及再往后的几轮，对后面这几个数来说高位都看作 0，全部进 0 号桶，结果没有变化。

    * 到第六轮，那个大数的高位终于不一样了，该进 1 号桶，这轮取出来时才真正有序；最大数字是六位数，所以一共进行六轮。

    ```text
      轮次    桶内容（桶号 = 该数的对应位）                        取出顺序              结果
      ─────────────────────────────────────────────────────────────────────────────────────
      个位    0:[大数]  1:[11]  3:[13]  6:[26,16]              大数 11 13 26 16        大数 11 13 26 16
      十位    0:[大数]  1:[11,13,16]  2:[26]                   大数 11 13 16 26        大数 11 13 16 26
      百位    0:[全部]                                                        全部进 0 号桶      大数 11 13 16 26
      千位    0:[全部]                                                        全部进 0 号桶      大数 11 13 16 26
      ……     0:[全部]                                                        全部进 0 号桶      大数 11 13 16 26
      第六轮  0:[11,13,16,26]  1:[大数]                          11 13 16 26 大数        11 13 16 26 大数
    ```

* **位次怎么取**

    * 先做整数除法再对 10 求模：求 423 的十位是 `423 / 10 = 42`，`42 % 10 = 2`。

    * 百位是 `423 / 100 = 4`，`4 % 10 = 4`；千位是 `423 / 1000 = 0`，`0 % 10 = 0`。

    * 要求更高位也行，比如 `423 / 10000 = 0`、余数 0，说明它的万位是 0。

    * > **结论**：取第 $k$ 位（个位记作 $k=0$）的统一写法是 $\lfloor x / 10^k \rfloor \bmod 10$，整个基数排序从始至终都只用这一个式子。

* **外层循环的退出条件**

    * 用一个变量 `m` 表示 10 的幂，依次取 1、10、100、1000……，每轮结束执行 `m *= 10` 换到高一位。

    * 当 `m` 小于等于数组最大值时不断进行基数排序，`m` 一旦大于最大值就退出循环。

    * 最大值先假定为 `numbers[0]`，再从下标 1 开始循环找更大的，`max = Math.max(max, numbers[i])`。

* **性能代价**

    * 单看一轮可以看成一次桶排序，时间复杂度是 $O(n)$；外层循环假设有 $k$ 轮，总复杂度是 $O(k \cdot n)$。

    * $k$ 由数组里最大数字的位数决定，最大数字是六位就循环六次，复杂度是 $O(6n)$。

    * 相同量级可以把前面的常量消掉，但乘以 6 一定比乘以 1 慢，所以基数排序相对于桶排序还是要弱一些。

    * 逻辑没有问题的这套代码提交上去大约只击败 20% 多的用户，突破口还是得回到桶排序。

    ```java
    private void radixSort(int[] numbers) {
        // 十个桶，每个桶用一个 ArrayList 表示
        List<Integer>[] buckets = new List[10];
        for (int i = 0; i < 10; i++) {
            buckets[i] = new ArrayList<>();
        }

        // 求最大值，用来控制外层循环什么时候退出
        int max = numbers[0];
        for (int i = 1; i < numbers.length; i++) {
            max = Math.max(max, numbers[i]);
        }

        int m = 1;
        while (m <= max) {                     // m 就是 10 的幂：1, 10, 100, 1000...
            for (int x : numbers) {            // 入桶：看 x 除以 m 之后的个位
                buckets[(x / m) % 10].add(x);
            }
            int k = 0;
            for (List<Integer> bucket : buckets) {   // 出桶：按桶号 0..9 依次写回
                for (int x : bucket) {
                    numbers[k++] = x;
                }
                bucket.clear();                    // 这一轮结束，清空桶
            }
            m *= 10;                              // 下一轮换到高一位
        }
    }
    ```

## 压回桶的个数

* **重新审视桶数公式**

    * 原来桶的个数是"最大值减最小值加一"，当最大值特别大、最小值又特别小、差值相对非常大时，桶的个数显然过多。

    * 其实并不需要那么多桶：就两个元素的话两个桶就够了，一个桶放一个。

    * > **易错点**：原来那个计算桶个数的逻辑不太合理，问题不在分桶本身，而在 `range` 太小。

* **range 的反解**

    * 要减少桶的个数，就要**增大 `range` 值**，因为值域差除出来的商会变小。

    * 把桶数的计算式子看成一个等式：$$\frac{\max - \min}{range} + 1 = \text{期望的桶个数}$$。

    * 右侧期望桶个数取 `numbers.length`，左侧 `max`、`min` 已知，把 1 先移到右边：$$\frac{\max - \min}{range} = n - 1$$。

    * 于是 `range` 等于最大值减最小值再除以数组长度减一，计算桶个数的地方就改成除以这个 `range` 而不是除以 1。

    * 实验验证：拿最大值是 $10^7$ 那组数据，取 `range = 5 \times 10^6`，商被压到 1，加一后桶个数为 2，正好是两个元素、两个桶、一个元素一个桶的期望值。

* **max 等于 min 时的除零**

    * 数组元素全都相等时，`max - min` 为 0，`range` 算出来也是 0；而 `range` 将来要作为除数，会报除零异常，试一下果然报错。

    * 用 `Math.max` 把这个式子与数字 1 二者取最大值，保证 `range` 的最小值是 1——每个桶内认为最少得有一个元素，这样也合理。

    * 改完之后不再报异常，此时只分了一个桶，所有元素都相等，差值也是零，结果是对的。

    ```java
    int min = Integer.MAX_VALUE, max = Integer.MIN_VALUE;
    for (int num : numbers) {
        min = Math.min(min, num);
        max = Math.max(max, num);
    }

    int range = Math.max(1, (max - min) / (numbers.length - 1));
    int count = (max - min) / range + 1;
    ```

* **搬运桶排序代码的手法**

    * > **提示**：用 IDEA 的 `Inline Method`（快捷键 `Ctrl + Alt + N`，选第二项 "Inline or... and keep the method"）把桶排序整段搬进当前方法，因为待会儿要大幅改动它，又不想影响原来桶排序里的代码。

    * 选第二项的含义是搬过来之后**保留原方法不变**，原桶排序代码仍然可用。

## 桶内只留一对最值

* **可以省掉的两个步骤**

    * 桶排序的第三步是把桶内的元素做一次排序，第四步是把排好序的内容放回原始数组，这两步在本题里都是多余的。

    * 本题只要找最大差值，可以通过某种手段避免排序桶内元素，将来直接在**桶跟桶之间**求差值，也不用回到原始数组，从而把这两步的时间节约下来。

* **桶内间距小、桶间间距大**

    * 用 24 个数字按前面的算法划分成 24 个桶后可以发现规律：10、11、12 间距小落在同一个桶，20、21、22 也落在同一个桶。

    * 间距大的 30、40、50、60 各自被放到不同的桶里，所以桶内元素间距比较小，桶间元素间距比较大。

    * 求最大间距因此可以简化成"求桶间元素的最大间距"，桶内的没必要求。

    * 桶之间的间距就是**把一个桶内的最大值跟另一个桶内的最小值相减**：一个是 `20 - 12 = 8`，另一个是 `30 - 22 = 8`。

* **有空桶是这个前提**

    * 反例：第一个桶放 10 和 19、第二个桶放 25，桶内间距 `19 - 10 = 9` 比桶间间距 `25 - 19 = 6` 还大。

    * 但只要满足**存在空桶**这个前提，那种场景就不会出现——19 不会被放进第一个桶而会被放到第二个桶，桶间间距变成 `19 - 10 = 9`，保证桶间更大。

    * 24 个元素只要**桶的个数比元素个数多一个**，再怎么放都放不满，空桶就有保证。

* **range 再次改写**

    * 右侧期望桶个数改成 $n + 1$：$$\frac{\max - \min}{range} + 1 = n + 1 \quad\Longrightarrow\quad range = \frac{\max - \min}{n}$$。

    * 两边的加一抵消，`range` 就是最大值减最小值直接除以 `numbers.length`，不用再减一。

* **Pair 类**

    * 新建一个类叫 `Pair`，代表一对最大最小值，里面存一个最大值、存一个最小值，`toString` 显示成 `(max,min)` 这个格式。

    * 题目给出的取值范围最小是 0、最大是 $10^9$，所以 `max` 的初始值设成 0、`min` 的初始值设成 1000000000，元素只要比它大或比它小即可入选。

    * 更新方法叫 `add`，参数是数组元素：挑出更大的更新 `max`，挑出更小的更新 `min`，每次遍历都调用它就能把该桶的最值找出来。

    * > **易错点**：这里的最大最小值**只是桶内的最大最小值**，不是整个数组的。

    * 用 `Pair` 替换掉原来作为桶中数据类型的 `ArrayList`，空桶用 `null` 代表，预先初始化所有桶的那段代码就不要了。

    * 放入元素时先判断 `buckets[index] == null` 才 `new` 一个 `Pair`，否则直接调用 `add`；重复出现的下标表达式 `(num - min) / range` 可以提取成一个叫 `index` 的变量。

    * 桶排序原来的第三步、第四步整个不要了：不需要排序，也不需要把桶里的最值放回原始数组。

    ```java
    static class Pair {
        int max;
        int min;

        public Pair(int max, int min) {
            this.max = max;
            this.min = min;
        }

        public void add(int v) {                 // 把数组元素 v 并进来
            max = Math.max(v, max);
            min = Math.min(v, min);
        }

        @Override
        public String toString() {
            return "(" + max + "," + min + ")";
        }
    }
    ```

* **压缩后的数据流**

    * > **结论**：整条数据流从"分桶—桶内排序—回填原数组—再遍历原数组"，压缩成了"分桶—桶内只记最值—桶间相邻求差"，中间那一大段消失不见了。

    ```text
       numbers（20 个元素）
            │
            │  index = (num - min) / range
            v
       ┌───────────────────────────────────────────────┐
       │ bucket[0]      bucket[1]      ...  bucket[k]  │
       │ Pair(200,200)  Pair(210,210) ...  Pair(2xx,2xx)│  ← 空桶为 null
       └───────────────────────────────────────────────┘
            │                    │
            │ 只扫桶             │ 桶内不排序、不回填原数组
            v                    v
       lastMax 链式相减：  bucket[i].min − lastMax
            │
            v
         res = Math.max(res, diff)
    ```

* **lastMax 如何跨过空桶**

    * 有了空桶，桶间差值要用"当前非空桶的最小值减上一个非空桶的最大值"，所以需要一个变量 `lastMax` 记录上一个不为空的桶的最大值。

    * `lastMax` 的初值应该是 0 号桶的最大值，循环从 1 号桶开始。

    * 每遇到一个不为空的桶，先用 `buckets[i].min - lastMax` 更新 `res`（用 `max` 只保留更大的），再把 `lastMax` 更新成当前这个非空桶的最大值。

    * 调试时直接循环打印桶里的 `Pair` 对象即可，因为已经写好了 `toString`；24 个数那组数据里第一桶是 `(12,10)`、第二桶是 `(22,20)`，单元素桶则是 `(30,30)`、`(40,40)` 这样。

    ```java
    public int maxGap(int[] numbers) {
        int n = numbers.length;
        if (n < 2) {
            return 0;
        }

        int min = Integer.MAX_VALUE, max = Integer.MIN_VALUE;
        for (int num : numbers) {
            min = Math.min(min, num);
            max = Math.max(max, num);
        }

        int range = Math.max(1, (max - min) / n);      // 桶个数 = n + 1，保证有空桶
        int count = (max - min) / range + 1;
        Pair[] buckets = new Pair[count];

        for (int num : numbers) {
            int index = (num - min) / range;
            if (buckets[index] == null) {             // 空桶第一次进来才初始化
                buckets[index] = new Pair(0, 1000000000);
            }
            buckets[index].add(num);
        }

        int res = 0;
        int lastMax = buckets[0].max;                 // 先记住 0 号桶的最大值
        for (int i = 1; i < count; i++) {
            if (buckets[i] != null) {
                res = Math.max(res, buckets[i].min - lastMax);
                lastMax = buckets[i].max;
            }
        }
        return res;
    }
    ```

* **两组数据的验证**

    * 给 20 个间距均匀的数（间距都是 10），跑出来最大间距就是 10。

    * 再加一个 220 这样的较大值：前面桶间距都是 10，而最后一次记录的最大值是 200、最后一个桶的最小值是 220，相减得到更大的 20，答案变为 20。

## 四版复杂度的账

* **版本演进的关键代价**

    * 第一版 `range = 1` 的桶排序：桶个数为 $(\max - \min) / 1 + 1$，最大值到 $10^7$ 时就是 1000 万个桶，空间直接爆掉。

    * 第二版基数排序：单轮 $O(n)$、外层 $k$ 轮，合计 $O(k \cdot n)$，虽然与桶排序同属一个量级、常量可以消掉，但乘以 6 还是比乘以 1 慢。

    * 第三版压住桶数：`range` 从 1 改成 $\lfloor (\max - \min) / (n - 1) \rfloor$，桶个数回到 $n$ 的量级，空间达标，但仍需桶内排序与回填。

    * 第四版桶内只留最值：省掉桶内排序和回填原数组这两步，成绩大约能击败 95%。

    | 版本 | 排序方式 | 关键代价 | 提交成绩 |
    | --- | --- | --- | --- |
    | 桶排序，`range = 1` | 桶排序 | 桶个数与值的跨度同阶，最大到千万级 | 超出内存限制 |
    | 基数排序 | 基数排序 | 单轮 $O(n)$，共 $k$ 轮，合计 $O(k \cdot n)$ | 击败 20% 多 |
    | 压住桶数 | 桶排序 | 桶个数降到 $O(n)$，仍需桶内排序 + 回填 | 超过 70% 多 |
    | 桶内只留最值 | 桶排序 + `Pair` | 桶个数 $n + 1$，省掉桶内排序与回填 | 约击败 95% |

* **最终结论**

    * > **结论**：更高分的解法跟这个思路没有太大的本质差别——桶个数压到 $n + 1$ 以保证有空桶、桶内只记一对最值、只在桶与桶之间取差值，这三件事凑齐，这道题就做完了。
