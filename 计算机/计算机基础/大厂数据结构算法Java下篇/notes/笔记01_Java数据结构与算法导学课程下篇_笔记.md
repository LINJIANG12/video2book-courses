# Java数据结构与算法导学课程（下篇）

## B 树的历史与定位

* **B 树（B-Tree）**

    * > **定义**：一种自平衡的树形数据结构，1972 年由两位科学家提出，提出的目的是解决在磁盘中存储大量数据时如何减少磁盘 IO 操作次数、提高数据访问效率。

    * 历史三句话里，「1972 年提出」与「为磁盘而生」是一体的两条；B 树天生就是为磁盘而生的结构。

    * 自平衡树形结构此前已学过两种——AVL 树和红黑树，它们同样能存大量数据、同样支持高效的增删改查，效率也都是对数级别。

    * > **定义**：B 树最大的特点是树高能够降到非常低，低树高是它一切优势的根源。

## 效率高低由树高决定

* **树的高度（height）**

    * > **定义**：AVL 树和红黑树的效率取决于树的高度——树越低比较次数越少，树越高比较次数就多起来。

    * 最糟的情况是一路比较到叶子节点才能找到目标数据。

    * 100 万条数据存进 AVL 树，$\log_2 10^6 \approx 19.93$，树高约等于 20；操作叶子节点要比较 20 次才能找到数据。

    * 关键不在于这 20 次本身，而在于这 20 次发生在哪儿：内存读写约纳秒级，乘 20 完全感觉不出来；机械硬盘一次读写要几十毫秒甚至上百毫秒，20 次乘上去马上出现明显卡顿，这个延迟没法忍。

| 操作对象 | 单次读写耗时 | 连做 20 次的体感 |
| --- | --- | --- |
| 内存 | 纳秒级 | 完全感觉不出来 |
| 机械硬盘 | 几十毫秒到上百毫秒 | 明显卡顿，无法忍受 |

* **AVL 树、红黑树与 B 树的场景分工**

    * 磁盘读写次数越少——更专业地说 IO 次数越少——数据访问性能就越高。

    * AVL 树和红黑树适合做内存中数据的增删改查，B 树更适合做磁盘上数据的增删改查。

    * 这不是谁更优的问题，是场景不同。

## B 树把树高压到三

* **100 万条数据、最小度数 500**

    * 同样的 100 万条数据存进 B 树，取最小度数 500（这个取值在整个 B 树的语境里很正常），树高大约是 3。

    * 树高由一个公式算出来，属于可套用计算的结论。

    * 换成磁盘场景，最坏情况下找到数据的磁盘访问次数从 20 次降到 3 次，这就是在磁盘中存储数据时选择 B 树的原因。

| | AVL 树 | B 树（最小度数 500） |
| --- | --- | --- |
| 100 万条数据的树高 | 约 20 | 3 |
| 最坏情况下找到数据的磁盘访问次数 | 20 次 | 3 次 |

## degree 与 order

* **degree（度）**

    * > **定义**：degree 指一个节点的孩子数目。

    * 根节点 4 有两个孩子，度是 2；节点 2 也有两个孩子，度同样是 2；叶子节点 1、3 没有孩子，度是 0；节点 6、8 有三个孩子，度是 3。

* **order（阶）**

    * > **定义**：order 指整棵树所有节点中，孩子数最多的那个值。

    * 上例中孩子数最多的节点是 `[ 6 | 8 ]`，有 3 个孩子，所以这棵 B 树的阶就是 3。

* **两套说法的关系**

    * 不同文献描述 B 树时用词不一样：有的用 degree，有的用 order，两套说法指的是同一件事的不同侧面。

    * 这两个概念不依赖外部问答来确认，因为给出的答案前后矛盾、前后不一致的地方太多；概念一旦被绕晕，后面的公式就全崩了。

```text
                    [ 4 ]
                   /     \
                [ 2 ]   [ 6 | 8 ]
               /   \    /   |   \
            [ 1 ] [ 3 ] [ 5 ] [ 7 ] [ 9 | 10 ]
```

* **字符画读法**

    * 方括号里是节点的关键字，竖线分隔同一节点的多个关键字（6 和 8 是同一个节点的两个关键字），斜杠下面对应它的孩子。

    * `[ 6 | 8 ]` 下面挂着三个孩子——关键字 2 个，孩子 3 个。

## B 树的特性

### 界与孩子数上下限

* **界（m）**

    * 每个节点最多有 $m$ 个孩子，这个 $m$ 称为 B 树的「界」。

    * 用 order 描述 B 树时，查其他资料会看到用 $m$ 描述的，都是一回事。

* **中间节点的孩子数下限**

    * 除根节点和叶子节点以外的中间节点，至少要有 $\lceil m/2 \rceil$ 个孩子。

    * 例：阶为 3 即最多 3 个孩子时，$\lceil 3/2 \rceil = \lceil 1.5 \rceil = 2$，代表中间这些节点至少得有 2 个孩子。

    * > **易错点**：⚠️ 中间节点不能只有一个孩子，那样树就不平衡了。

* **根节点的孩子数下限**

    * 根节点不是叶子节点时，也至少要有两个孩子。

    * 这一条和中间节点的下限在描述孩子数下限上有重复的地方。

### 叶子同层与平衡

* **叶子节点**

    * > **定义**：叶子节点就是没有孩子的那些节点。

    * 上图里的 1、3、5、7、9、10 都是叶子节点。

* **所有叶子节点在同一层**

    * 「在同一层」就是高度相同：从根 4 到 1、到 3，再到其他这几个叶子节点，高度都是 3。

    * 这一条是 B 树是否平衡的一个前提条件。

* **平衡的判据**

    * 树高能被压到很低，靠的是孩子数下限、界、根节点下限和叶子同层这几条共同约束。

### 关键字数与指针数

* **非叶子节点的组成**

    * 非叶子节点由 $n$ 个关键字和 $n+1$ 个指针组成。

    * 二叉搜索树一个节点里只有一个关键字，而 B 树中一个节点里可以有多个关键字；上图中的 6、8 其实是同一个节点，它里面就有两个关键字。

    * $n+1$ 个指针意味着 $n+1$ 个孩子：一个关键字的孩子是 2 个，两个关键字的孩子就是 3 个。

    * 孩子数永远比关键字数多 1。

* **关键字个数的上下限**

    * 关键字的个数 $n$ 也有上限和下限：$$n \in \left[\ \lceil m/2 \rceil - 1,\quad m - 1\ \right]$$

    * 这个式子从孩子数倒推：孩子数下限是 $\lceil m/2 \rceil$（不能太少，否则树不平衡），上限是 $m$（最多 $m$ 个孩子），关键字数比孩子数少一个，于是范围整体各减 1。

    * > **提示**：所有关于孩子数上下限的结论，把「孩子」两个字换成「关键字」，数值再减 1，就全部迁移过来了；这一步会反复用到。

### 关键字的升序

* **全树关键字升序**

    * 整棵树里所有的关键字要做升序排列，与二叉搜索树类似——左边比它小，右边比它大。

    * 只有一个关键字时：2 这个节点左边是 1，比它小，右边是 3，比它大；4 的整棵左子树都比它小，右子树都比它大。

    * 有多个关键字、多个孩子时：6 的左边是 5，比 6 小；6 和 8 这两个关键字中间夹着一个孩子，是 7，比 6 大、比 8 小；8 的右边是 9 和 10，都比 8 大。

    * 规则仍是左边的比它小、右边的比它大、中间夹着的落在两者之间，只不过多关键字时中间可以夹不止一个孩子。

* **合并看仍是升序**

    * 整棵树里所有关键字合并起来看还是一个升序排列，例如这棵树就是 1、2、3、4、6、7、8、9、10。

## Node 类的五个属性

* **keys（关键字）**

    * 节点里的关键字可能有多个，所以不能用 `int` 来表示，得用一个 `int` 数组来表示；也可以用集合来表示，这里选择数组。

* **children（孩子）**

    * 孩子也可能超过两个——不像二叉树有个左右孩子就够了，B 树的节点可能有三个乃至更多的孩子。

    * 孩子同样用数组表示，类型是 `Node`。

* **keyNumber（有效关键字个数）**

    * 这个属性是跟着前两个数组来的：用的是静态数组，大小一旦分配就固定不变，所有节点里数组大小设成一样的，比如都是 4。

    * 可大小是 4 不代表一开始就真的存了 4 个数据；节点可能只存了一个 key，也可能存两个，起初还没存满。

    * 数组里哪些位置是有效数据必须由一个变量记录，这个变量叫 `keyNumber`。

    * > **易错点**：⚠️ 数组容量 4 只是上限，不代表已有 4 个有效 key，查关键字个数时要看 `keyNumber`。

    * > **提示**：如果用的是 `ArrayList` 这类集合，就不用额外记这个数，直接调 `size()` 就知道实际有多少个 key；正因为选了静态数组，才必须自己维护 `keyNumber`。

* **isLeaf（是否叶子节点）**

    * 布尔值，表示这个节点是不是叶子节点，因为叶子节点在处理时跟非叶子节点的处理方式不同。

    * 初始值是 `true`：刚创建出来时默认它是叶子节点，等以后孩子增多了、进行分裂操作之后，它才可能变成非叶子节点。

* **t（最小度数）**

    * 就是节点孩子数的一个下限，代表整棵树将来的最小度数。

    * 这个值得由我们提前给定。

* **类骨架**

    ```java
    import java.util.Arrays;

    public class Node {

        // 关键字，一个节点里可以有多个
        private int[] keys;

        // 孩子数组
        private Node[] children;

        // 有效关键字的个数：数组中哪几个位置是有效的
        private int keyNumber;

        // 是否是叶子节点
        private boolean isLeaf;

        // 最小度数：整棵树中节点孩子数的下限
        private int t;

        public Node(int t) {
            this.t = t;
            this.keys = new int[2 * t - 1];
            this.children = new Node[2 * t];
            this.isLeaf = true;
        }

        @Override
        public String toString() {
            return Arrays.toString(Arrays.copyOf(this.keys, this.keyNumber));
        }
    }
    ```

## 构造方法与数组长度

* **t 的取值约束**

    * 构造方法主要就是给最小度数赋一个初值，而这个 $t$ 必须由我们指定。

    * 它直接决定了将来树的高度——最小度数给得越大，树的高度就越低，所以要按实际情况来定。

    * $t$ 的最小值是 2，赋值时至少要大于等于 2；小于 2 就意味着它的最小孩子数只能有一个，而最小孩子数也得有两个。

* **两个数组的长度**

    * 孩子数组是 `2 * t`：最小度数乘以 2 就是它最多可能拥有的孩子数，这也是 B 树里的一个约定。

    * 关键字数组是 `2 * t - 1`：因为关键字比孩子数少一个。

* **isLeaf 的初始值**

    * 构造时把 `isLeaf` 置为 `true`，后续由孩子增多与分裂操作来改变它。

## toString 只打印有效的一段

* **调试用途**

    * 这不是一个必须的调试方法，目的是把节点里所有的 key 打印出来。

    * 要打印的是**有效**的 key：节点刚开始只放了一个 k，不能把后面那些没初始化的元素也打印出来。

* **实现做法**

    * 把原来那个 `keys` 数组拷贝一部分，从 0 拷到 `keyNumber`，正好就是有效的那一段。

    * 然后把这个数组用 `Arrays.toString` 转成字符串，将来调试时就能很方便地打印出当前节点所有有效的 key。

## 多路查找 get

### 与二叉搜索树查找的差别

* **二叉搜索树的查找只有两个方向**

    * 把待查找的 key 跟当前节点的 key 比较，相等就返回，比它小就往左找，比它大就往右找。

    * 它只有两个孩子，所以每次只有两个方向可选。

* **多路查找要面对六个孩子**

    * 当前节点有五个 key 的话，是不是应该有六个孩子。

    ```text
                keys = [ 5 | 10 | 15 | 20 | 25 ]
                 下标     0     1     2     3     4
                children
                  [0]    [1]    [2]    [3]    [4]    [5]
                   |      |      |      |      |      |
                 < 5   5..10 10..15 15..20 20..25   > 25
    ```

    * 字符画读法：`children` 数组的下标和 `keys` 数组严格对齐——下标为 0 的孩子装小于 5 的 key，下标为 1 的孩子装 5 到 10 之间的 key，以此类推，下标为 5 的孩子装所有大于 25 的 key。

### 查找过程

* **最简单的情形**

    * 查 2：从左到右依次把当前节点中这些 key 跟待查找的 key 比一遍，找到了就直接返回当前节点。

* **多路排除的情形**

    * 查 21：21 比 5 大，0 号孩子不用看了；21 比 10 大，5 到 10 之间的那个孩子不用看了，那里是 6、7、8、9；21 比 15 大，10 到 15 之间的孩子不用看了；21 比 20 大，15 到 20 之间的孩子也不用看了。

    * 最后要去的是 20 到 25 之间的那个孩子里面继续查找，进去之后仍然从左向右依次比较，找到就返回，找不到就再去找它的孩子，以此类推。

* **到达叶子节点**

    * 叶子节点里都没有了，不用继续往下找，直接返回一个 `null`，表示没有找到。

* **方法签名**

    * 方法名叫 `get`，返回值先让它返回节点对象——找到了就把当前节点返回；参数就是待查找的 key。

### 为什么是第 i 个孩子

* **退出循环的两种条件**

    * 执行到非叶子这段代码时，肯定是退出了当前节点内的循环，而退出条件无非两个：当前这个第 $i$ 个 key 已经大于待查找的 key，或者这个 $i$ 已经出了有效范围（比如有效 key 数是 5，$i$ 已经等于 5）。

* **情况一：查找 16**

    * 能退出循环说明找到了一个比 16 大的 key，找到的是 20，在 20 这个位置退出循环，退出时 $i$ 的值是 3。

    * 到 3 这个索引的孩子数组里看一下，它里面存储的 key 就在 15 到 20 之间。

* **情况二：查找 22**

    * 找到的是比 22 大的 25，退出时 $i$ 的值是 4，索引为 4 的孩子里装的就是 20 到 25 之间的 key。

* **情况三：查找 30**

    * 退出循环时 $i$ 已经等于 5 了——循环走完了，出了有效索引范围，这时候就去索引为 5 的孩子里找。

    * 30 肯定在那里，但可能没找到，因为它可能是个叶子。

* **归纳出的结论**

    * > **结论**：退出循环时的 $i$ 等于几，就到同样索引为几的孩子里去继续查，也就是去它的第 $i$ 个孩子继续查找。

    * 第 $i$ 个孩子里的查找逻辑跟刚才在当前节点里查找的逻辑一模一样，所以直接递归调用 `get` 方法就行。

### get 的三种退出方式

* **三种退出分支**

    * 等于，找到了，返回 `this`。

    * 小于了，`i++` 继续循环，因为节点内 key 是升序排列的，接着往右比下一个。

    * 大于了，`break` 退出循环，说明当前节点里没有。

* **退出之后的两种处理**

    * 是叶子节点就返回 `null`：既然退出了循环还没找到，说明整棵树里也没有了。

    * 非叶子节点就去 `children[i]` 里递归。

* **完整实现**

    ```java
    public Node get(int key) {
        int i = 0;

        // 在本节点内从左向右逐个比较
        while (i < this.keyNumber) {
            if (this.keys[i] == key) {
                // 最理想的情况，找到了，返回当前节点
                return this;
            } else if (this.keys[i] < key) {
                // 节点内 key 是升序排列的，接着往右比下一个
                i++;
            } else {
                // keys[i] > key，说明当前节点里没有
                break;
            }
        }

        // 叶子节点且没找到，整棵树里也没有
        if (this.isLeaf) {
            return null;
        }

        // 非叶子节点：去第 i 个孩子里递归查找
        return this.children[i].get(key);
    }
    ```

## 往 keys 插入元素

* **insertKey 的需求**

    * 往节点的 `keys` 数组指定索引位置插入一个新的 key。

    * 例：现在 `keys` 里是 1、3、5，要在索引 1（原来 3 的那个位置）插入新的 key 2，办法是把 3 和 5 向后移动一位，原索引 1 的位置空出来，再把 key 2 插进去。

    * 这属于比较基础的功能，代码可以直接交给外部模型生成，需求写得详细一些更好。

* **方法签名与动作序列**

    * 方法名叫 `insertKey`，两个参数，一个是 key，一个是索引 `index`。

    * 从后往前移动元素，把 $i$ 索引处的元素移动到 $i+1$ 处，相当于把 3 和 5 向后移动了一位。

    * 位置空出来以后往 `index` 位置加入新的 key，最后把 `keyNumber` 加加，因为新插入一个 key，有效 key 的数目应该加一。

* **改用 System.arraycopy**

    * 生成代码里元素移动是自己写的 for 循环，可以改成 `System.arraycopy`，性能会高一些。

    * `System.arraycopy` 的第三个参数是拷贝的元素个数；这里 `keyNumber - index` 正好是「从 index 到末尾」这一段的长度，把这一段整体搬到 `index + 1` 开始的位置，中间就空出了一个位置。

* **完整实现**

    ```java
    public void insertKey(int key, int index) {
        // 把 index 及其后面的元素整体后移一位，把 index 位置腾出来
        System.arraycopy(this.keys, index, this.keys, index + 1, this.keyNumber - index);
        this.keys[index] = key;
        this.keyNumber++;
    }
    ```

## 往 children 插入元素

* **insertChild 的需求**

    * 向 `children` 数组的指定索引位置，插入一个新的孩子节点元素。

    * 提需求时明确要求用 `System.arraycopy` 来实现，生成的代码就可以直接用。

* **生成代码的合法性检查**

    * 它在插入孩子的时候也把 `keyNumber` 做了个加加，这行没有必要。

    * `keyNumber` 只通过 `insertKey` 来维护：新加入一个 key 时它的 `keyNumber` 加一，新插入一个孩子时不用再考虑增加 `keyNumber`。

    * > **易错点**：⚠️ 多出来的 `keyNumber++` 直接跑起来未必立刻报错，但后面查关键字个数时就会莫名其妙地对不上；改动的地方越少越好，多的那几行往往就是埋雷的地方。

    * > **提示**：让外部模型生成代码，一定要先检查合法性再拿来用。

* **完整实现**

    ```java
    public void insertChild(Node child, int index) {
        // 把 index 及其后面的孩子整体后移一位
        System.arraycopy(this.children, index, this.children, index + 1,
                         this.children.length - index - 1);
        this.children[index] = child;
        // 注意：这里绝对不能动 keyNumber，它只由 insertKey 维护
    }
    ```

## 节点类的完成面

* **五个属性**

    * 关键字数组、孩子数组、有效关键字个数、是否叶子节点、最小度数。

* **两个基础方法**

    * 一个构造方法，按 $t$ 定出两个数组长度并把 `isLeaf` 置为 `true`；一个调试用的 `toString`，只打印有效的那一段 key。

* **三个重要方法**

    * 多路查找的 `get`、往 `keys` 里插入新 key 的 `insertKey`、往 `children` 里插入新孩子的 `insertChild`，所有重要的方法都实现完毕。
