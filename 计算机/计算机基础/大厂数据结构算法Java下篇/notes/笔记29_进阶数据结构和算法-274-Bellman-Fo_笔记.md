# 进阶数据结构和算法-274-Bellman-Fo

## Bellman-Ford 的多轮松弛

### 松弛判定与每轮传播半径

   * **松弛（relaxation）**

       * > **定义**：拿一条边 `from → to` 去刷新 `to` 的距离，取 `dist[from] + weight` 与 `dist[to]` 中更小的那个写回 `dist[to]`。

       * > **结论**：一轮松弛只能让距离往前传播一条边；消息从起点出发走完一轮，远远不够。

       * > **易错点**：一轮跑完的结果一定是错的，起点那些邻居的好消息还没来得及传给它们的邻居。

   * **提前退出的判据**

       * 某轮存在顶点距离被更新，说明下一轮可能基于新的、更小的值去刷新别的顶点，必须继续。

       * 某轮一个格子都没动，就可以直接跳出整个循环，剩下那些轮次是纯浪费。

       * > **结论**：只要有一轮下来没有任何顶点被更新，就跳出整个循环。

### 示例图的边集与初始距离

   * **八条有向边**

       * > **结论**：距离只在有向边的 `to` 端点上变化，读图时不能把边当成双向的。

       | 边 | 权重 |
       | :--- | ---: |
       | V6 → V5 | 9 |
       | V4 → V5 | 60 |
       | V1 → V6 | 14 |
       | V3 → V6 | 2 |
       | V3 → V4 | 11 |
       | V2 → V4 | 15 |
       | V1 → V3 | 9 |
       | V1 → V2 | 7 |

   * **拓扑形状**

       * 四条边从起点 V1 分别通向 V2、V3、V6，再由它们一级一级把消息推到 V4、V5。

       ```text
          V1 ──7────▶ V2 ──15────▶ V4 ──60────▶ V5
           │
           ├──9────▶ V3 ──11────▶ V4
           │           │
           │           └──2────▶ V6 ──9────▶ V5
           └──────────14────────▶ V6
       ```

   * **初始状态**

       * 起点 V1 到自身的最短距离是 0，其余五个顶点全部为无穷大。

       * > **提示**：最短路径那一版只更新到 V4 的距离；打开注释后需求放开成 V2、V3、V5、V6 全部要更新。

### 前三轮的距离变化

   * **第一轮：只有入边来自起点的顶点会变**

       * 只有 V2、V3、V6 三个顶点被更新成 7、9、14；V4、V5 的入边全部来自此刻仍是无穷大的顶点，那个 `if` 分支根本进不去。

       * V1 的距离是 0，`0 + 7 = 7` 显然小于原来的无穷大，V2 更新为 7；V3 拿到 9，V6 拿到 14。

   * **第二轮：上一轮的距离开始被复用**

       * V6 → V5 走通了：`14 + 9 = 23` 小于无穷大，V5 更新成 23；V3 → V6 一条边把 V6 从 14 压到 11（`9 + 2 = 11`）；V3 → V4 把 V4 从无穷大改成 20（`9 + 11 = 20`）。

       * V2 → V4 算出 `7 + 15 = 22`，比现有的 20 大，不更新；V1 → V6 算出 14 与现值相同，也不更新。

   * **第三轮与静止轮**

       * 第三轮唯一改动是 V6 → V5 的 `11 + 9 = 20`，把 V5 从 23 压到 20；其余六条边算出的值都比现值大或相等。

       * 第四轮执行完的结果与第三轮完全一样，一个格子都没动；此后任何一轮的输入都与这一轮相同，不可能再产生改进。

   * **全程记录表**

       * > **结论**：最终到 V1、V2、V3、V4、V5、V6 的最短距离依次为 0、7、9、20、20、11。

       | 轮次 | V1 | V2 | V3 | V4 | V5 | V6 |
       | :--- | ---: | ---: | ---: | ---: | ---: | ---: |
       | 初始 | 0 | ∞ | ∞ | ∞ | ∞ | ∞ |
       | 第 1 轮 | 0 | 7 | 9 | ∞ | ∞ | 14 |
       | 第 2 轮 | 0 | 7 | 9 | 20 | 23 | 11 |
       | 第 3 轮 | 0 | 7 | 9 | 20 | 20 | 11 |
       | 第 4 轮 | 0 | 7 | 9 | 20 | 20 | 11 |

### 轮次上界与循环骨架

   * **轮数等于顶点数减一**

       * > **结论**：理论上最多做「顶点数 − 1」轮；这张图六个顶点，所以最多五轮。

       * 依据是最短路径不会绕圈，一条从 V1 出发的最短路径最多经过六个顶点也就是最多五条边，而每轮至少把消息往前推进一步。

       * 实际所需轮数可以比这个上界少：依赖处理边的顺序，这张图三轮就收敛了。

   * **两层循环的结构**

       * 外层循环次数按「顶点数 − 1」算，内层循环把所有边松弛一遍，`dist` 这个一维数组就是 DP 表。

       * > **提示**：轮次不要写死成 5；图变了、顶点数变了，这个循环次数得跟着变。

       * > **易错点**：内层遇到 `dist[from] == INF` 必须跳过，否则无穷大加权重得到的仍是无穷大以外的脏值，语义上这条边这一轮用不上。

   * **代码骨架**

       ```java
       // 外层：顶点数 - 1 轮
       for (int round = 0; round < vertexCount - 1; round++) {
           // 内层：把所有边松弛一遍
           for (Edge edge : edges) {
               int from = edge.from;
               int to = edge.to;

               // 起点的距离还是无穷大，这条边这一轮用不上
               if (dist[from] == INF) {
                   continue;
               }

               int newDist = dist[from] + edge.weight;
               if (newDist < dist[to]) {
                   dist[to] = newDist;
               }
           }
       }
       ```

### 没有数组的实现同样是动态规划

   * **判据不在于有没有数组**

       * > **结论**：判断一个算法是不是 DP，真正的判据是——有没有一张表存着中间结果，以及当前格子的值是不是由表里更早的格子算出来的。

   * **把结果存在顶点对象上的写法**

       * 没有一维数组的版本把每个顶点的最短路径存在顶点对象自己的属性里，每一轮循环算出的结果同样被存起来，比较条件与数组版完全一致。

       * 比较条件都是取 `from` 的最短距离加上 `from` 到 `to` 的权重，看是否比 `to` 上次的最短距离小，小了就更新。

       * 之所以不点破「动态规划」这几个字，只是为了不引入更多概念、把刚讲完的图那部分认知搅浑；思想本身与数组版一致。

## LeetCode 62 不同路径

### 走法数的递推关系

   * **题目**

       * 机器人站在网格左上角，要走到右下角，每次只能向右走一步或者向下走一步，问一共有多少种走法。

       * 三行七列的网格答案是 28 种：拐弯的次数和位置都不一样，走法数量远超「先右后下」「先下后右」这两种。

   * **从极小网格摸规律**

       * 六格网格（起点在左上、终点在右下）的走法是 3 种：先向右一步再向下两步、先向下两步再向右一步、先右后下再右再下。

       * 两行两列的四格网格走法是 2 种：要么从上面走下来，要么从左边走过来，也就是上方格子的走法数加上左方位子的走法数，$1 + 1 = 2$。

       * 回到六格网格，答案 3 同样来自「上方 2 + 左方 1」。

       ```text
         起点 ┌───┬───┐
             │ 1 │ 1 │
             ├───┼───┤
             │ 1 │ 2 │
             ├───┼───┤
             │ 1 │ 3 │
             └───┴───┘ 终点
       ```

   * **递推式**

       * 走到第 $i$ 行第 $j$ 列只能从上方格子或左方格子来，两个来路的走法数相加就是本格答案。

       * 上方格子是第 $i-1$ 行第 $j$ 列（行减一、列不变），左方格子是第 $i$ 行第 $j-1$ 列（行不变、列减一）。

       * > **定义**：$dp[i][j]$ 表示机器人从左上角走到第 $i$ 行第 $j$ 列的路径总数，递推式为

       $$
       dp[i][j] = dp[i-1][j] + dp[i][j-1]
       $$

### 边界条件与整表

   * **第一行与第一列**

       * 第一行的机器人只能向右走、没有任何选择余地，所以每一格都是 1；第一列只能向下走，每一格也都是 1。

       * > **易错点**：这两条边界不要去套递推式——第一行第 0 列的上方与左方都在网格外面，硬套就是数组越界。

   * **整表形状**

       * 边界一确定，其余格子自上而下、自左向右一格一格填；每一行都是「自己原来的值加上左边」。

       * 第二行为 1、2（=1+1）、3（=2+1）、4、5、6、7；第三行为 1、3（=1+2）、6（=3+3）、10（=4+6）、15、21（=6+15）、28（=21+7）。

       | | j=0 | j=1 | j=2 | j=3 | j=4 | j=5 | j=6 |
       | :--- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
       | i=0 | 1 | 1 | 1 | 1 | 1 | 1 | 1 |
       | i=1 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
       | i=2 | 1 | 3 | 6 | 10 | 15 | 21 | 28 |

### 二维数组实现

   * **三步走**

       * 按网格形状建一张 `m` 行 `n` 列的二维表，每格值就是对应坐标的路径总数。

       * 先把第一行、第一列初始化成 1，再用两层循环套递推式填满剩余格子，最后返回右下角。

       ```java
       public int uniquePaths(int m, int n) {
           int[][] dp = new int[m][n];

           // 初始化第 0 列：只能一路向下，每一格都是 1
           for (int i = 0; i < m; i++) {
               dp[i][0] = 1;
           }

           // 初始化第 0 行：只能一路向右，每一格都是 1
           // 这里的列循环变量用 j，跟上面那个 i 区分一下
           for (int j = 0; j < n; j++) {
               dp[0][j] = 1;
           }

           // 填剩余的格子：套递推式
           for (int i = 1; i < m; i++) {
               for (int j = 1; j < n; j++) {
                   // 上方格子（上一行同一列）+ 左方格子（同一行上一列）
                   dp[i][j] = dp[i - 1][j] + dp[i][j - 1];
               }
           }

           return dp[m - 1][n - 1];
       }
       ```

   * **两个必须盯死的地方**

       * > **结论**：两层填充循环的起点必须从 1 开始而不是 0，否则第 0 行第 0 列会被覆盖掉，边界初始化就白做了。

       * > **易错点**：右下角的坐标是行 `m - 1`、列 `n - 1`，别手顺写成 `dp[m][n]`。

   * **空间代价**

       * 二维数组版本的空间复杂度为 $O(mn)$，算出右下角之后上面那些行还留着却已经没用了。

### 一维降维

   * **降维的依据**

       * 递推式中 `dp[i][j]` 只用到上一行同一列 `dp[i-1][j]` 和本行左边一列 `dp[i][j-1]`，当前行只依赖上一行，上一行用完即弃，理论上留一行就够。

       * 实际做法是用一个一维数组，把「上一行同一列」的值就地存在同一个格子的当前位置上。

   * **代码**

       * 一开始整个数组初始化成 1，这正好就是第一行的全 1；每轮外层循环里第 0 列恒为 1，需要显式重新赋值。

       ```java
       public int uniquePaths(int m, int n) {
           int[] dp = new int[n];

           // 初始化：相当于第一行，每一列都是 1
           for (int j = 0; j < n; j++) {
               dp[j] = 1;
           }

           for (int i = 1; i < m; i++) {
               // 第 0 列恒为 1
               dp[0] = 1;

               for (int j = 1; j < n; j++) {
                   // dp[j] 是自己原来的值 == 上一行同一列的值
                   // dp[j - 1] 是本行左边一列已经更新好的值
                   dp[j] = dp[j] + dp[j - 1];
               }
           }

           return dp[n - 1];
       }
       ```

   * **覆盖前后的语义**

       * > **结论**：一维数组里 `dp[j]` 在被覆盖之前装的是上一行第 j 列的值，覆盖之后才是本行第 j 列的值。

       * 第二行算完数组变成 1 2 3 4 5 6 7；第三行依次得到 3、6（=3+3）、10（=4+6）、15、21（=6+15）、28（=7+21）。

       * 空间占用从 $O(mn)$ 降到 $O(n)$，全程没有用任何多维数组。

### 答案与解析要点

   * **答案**

       * 路径总数为 $C(m+n-2,\ m-1)$；三行七列的网格答案是 28 种。

   * **解析落点**

       * 核心是状态定义 $dp[i][j]$ 与递推式 $dp[i][j] = dp[i-1][j] + dp[i][j-1]$，边界是第一行、第一列全为 1。

       * 二维数组版本空间 $O(mn)$，一维降维版本空间 $O(n)$。

## 0-1 背包

### 贪心近似解与最优解

   * **题面**

       * 若干个实心物品，各有重量和价值；背包最多装 10 克；每个物品要么不拿要么整个拿走，不能切开也不能拿一半，求最高价值。

   * **贪心与最优解的差距**

       * 贪心算法算出的最高价值是 1001630，真正的最优解是 1002400，差了一个白银。

       * 贪心的运算效率确实高，但决策逻辑解决不了组合爆炸——它没法预判「这一件虽然单价低，可它腾出来的空间刚好能塞下另一件」。

       * > **结论**：求最优解必须换思路，走动态规划，而动态规划缺不了的那张一维或二维表格，这道题同样要用。

### 表格两条轴的含义

   * **行是物品**

       * 第 0 行只尝试装黄金，第 1 行在黄金基础上再多一个红宝石可选，第 2 行加上白银，最后一行再加钻石。

       * 每一往下一行，就多一件物品进入候选名单。

   * **列是容量**

       * 列对应背包的最大容量，从 0 到 10，因为背包最多装 10 克。

       * 某一列上的值表示「当背包容量这么大时，这一行已考虑的这些物品能凑出来的最大价值」。

   * **状态定义与物品表**

       * > **定义**：`dp[i][j]` 表示只考虑前 $i+1$ 件物品、背包容量为 $j$ 时能装下的物品的最大总价值。

       | 物品 | 重量 | 价值 |
       | :--- | ---: | ---: |
       | 黄金（价值记作 A） | 4 | 1600 |
       | 红宝石（价值记作 R） | 8 | 2400 |
       | 白银 | 5 | 30 |
       | 钻石（价值记作 D） | 1 | 100 万 |

### 按物品逐轮填表

   * **第 0 列与第一轮黄金**

       * 容量是零，什么都装不下，不管拿什么物品来试最大价值都是 0，所以第 0 列整列全是 0。

       * 装黄金（重 4、值 1600）：容量 1 到 3 装不下保持 0，容量 4 是节点刚好装下变成 1600，往后容量 5 到 10 全是 1600——第一轮只考虑黄金，容量再大也装不下第二样东西。

   * **第二轮红宝石**

       * 容量 1 到 7 装不下红宝石，保持上一轮的价值不变，其中容量 4 的 1600 是黄金、稳稳保住。

       * 容量 8 是节点：上一轮是黄金 1600，改装红宝石是 2400，取大者，把 4 克黄金拿出来换 8 克红宝石更新成 2400；容量 9、10 装不下两件，仍是 2400。

   * **第三轮白银与第四轮钻石**

       * 白银（重 5、值 30）在容量 5 和 9 两个节点上做判断：容量 5 上白银 30 打不过黄金 1600，黄金没装满还余 1 克也照样保留；容量 9 上白银 + 黄金共 9 克、价值 1630，仍没超过红宝石 2400。

       * 钻石（重 1、值 100 万）从容量 1 起就能装下，容量 4 起取代黄金；容量 5 上「上一行容量 4 的黄金 + 这一克钻石」得到 1001600，容量 6、7 同理。

       * 容量 9 是真正的节点：容量 8 那一列最高价值是红宝石 2400，再加上这一克钻石正好 8 + 1 = 9 克，改成 D + R 组合；容量 10 保持不变。

   * **整表形状**

       * > **结论**：最终解在右下角，为钻石加红宝石，价值 1002400。

       | | j=0 | j=1 | j=2 | j=3 | j=4 | j=5 | j=6 | j=7 | j=8 | j=9 | j=10 |
       | :--- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
       | i=0 黄金 | 0 | 0 | 0 | 0 | 1600 | 1600 | 1600 | 1600 | 1600 | 1600 | 1600 |
       | i=1 红宝石 | 0 | 0 | 0 | 0 | 1600 | 1600 | 1600 | 1600 | 2400 | 2400 | 2400 |
       | i=2 白银 | 0 | 0 | 0 | 0 | 1600 | 1600 | 1600 | 1600 | 2400 | 2400 | 2400 |
       | i=3 钻石 | 0 | 100万 | 100万 | 100万 | 100万 | 1001600 | 1001600 | 1001600 | 1001600 | 1002400 | 1002400 |

       * 读表方向：从上往下物品一件一件加进来，从左往右容量一克一克变大；每格的值只可能来自「上一行同一列」或者「上一行左边某列加上当前物品」。

### 递推式的两个分支

   * **装不下时**

       * > **结论**：装不下时当前格子的值直接来自上一行同一列。

       $$
       dp[i][j] = dp[i-1][j]
       $$

       * 拿红宝石这行举例：它重 8 克，容量 1 到 7 全都装不下，格子里的值保持上一次的值不变，整行只是照抄上一行往下平移。

   * **装得下时**

       * 直觉上会在「上一次存下来的价值」和「当前这枚物品的价值」之间挑更大的，于是想写出 $dp[i][j] = \max(dp[i-1][j],\ item.value)$。

       * > **易错点**：这个式子看起来挺顺但它是不完整的——它能蒙对红宝石，套到钻石上就露馅了。

       * 当场验一验：容量为 5 放钻石，按这个式子会算成 `max(1600, 100万)` 得 100 万，但手工分析得到的正确答案应是黄金 + 钻石 = 1001600。

       * 补法是反过来想：刨开即将放进来的这枚钻石后还剩多少容量，就去问那个剩余容量的背包最大价值是多少，即 `dp[i-1][j - item.weight]`。

       * > **结论**：设当前物品为 `item`（重量 `item.weight`、价值 `item.value`），装得下时的递推式为

       $$
       dp[i][j] = \max\big(dp[i-1][j],\ dp[i-1][j-item.weight] + item.value\big)
       $$

       * 拆开读：左边是「不装这件物品时同样容量能拿到的最大价值」，右边是「刨掉这件物品占掉的重量后剩余空间能装入的最大价值，再加上这件物品本身的价值」，两者取大者。

   * **完整式与验算**

       * 两个分支合起来就是完整递推式，$j$ 与 `item.weight` 的大小关系是唯一的分支条件。

       $$
       dp[i][j] =
       \begin{cases}
       dp[i-1][j], & j < item.weight \\[4pt]
       \max\big(dp[i-1][j],\ dp[i-1][j-item.weight] + item.value\big), & j \ge item.weight
       \end{cases}
       $$

       * 套回红宝石验算：第一行第八列，$i-1 = 0$ 是第 0 行、列仍是第 8 列，$j = 8$ 减去红宝石重量 8 得 0，找的是 `dp[0][0]` 即容量为 0 时的最大价值 0，于是 $\max(0,\ 0 + 2400) = 2400$。

       * > **结论**：完整式子能同时处理放钻石和放红宝石两种情况；少写的那一项一旦遇上「当前物品重量小于剩余最优组合重量」的场景，就会算出一个偏小的错误值。

       * > **易错点**：别因为红宝石这一个例子对了就放过不完整的式子——它恰好落到容量 0 这个特殊位置上，加不加那一项看不出区别，换成钻石就不行了。

       * 最高总价值为 1002400，即钻石 + 红宝石，重量 1 + 8 = 9 克，价值 100 万 + 2400。
