# 进阶数据结构和算法-343-设计LRU缓存-Le

## LRU 淘汰规则

* **最近最少使用（Least Recently Used，LRU）**

    * > **定义**：缓存满了要腾位置时，淘汰那个最久没有被用到的元素。

    * 通行译名"最近最少使用"看不出到底指什么，越想越绕——是"最近使用的里面最少用的那个"，还是"最少次使用"；改译成"最久不使用的元素"更直白，因为要淘汰的就是那个搁置最久的。

    * 规则只有一条：每次用到某个元素（读它，或者改它的值），它就变成"最新使用的"；缓存满了要腾位置，淘汰最久没被用到的那一个。

    * 麻烦在于"谁最新、谁最久没用"这类信息要随着每次访问不断变化，每次都把整个缓存扫一遍重新排个序虽然正确，但慢得没法用。

* **设计类题目的智力含量所在**

    * 设计类题目本身一点都不难，甚至一眼就能看出该怎么做，难处全藏在"你怎么组织数据"里。

    * 缓存满了要淘汰元素，真正的决策就是"淘汰谁"，这才是缓存设计全部的智力含量所在，LRU 是其中最经典的一条淘汰规则。

## 哈希表管找，双向链表管排

* **哈希表（HashMap）**

    * 设计缓存时数据结构的第一选择永远是哈希表，因为存取效率非常高，时间复杂度能达到 $O(1)$。

    * 只靠哈希表不够：它只能告诉你"这个 key 在不在缓存里"，管不了顺序。

* **双向链表（DoubleList）**

    * > **定义**：这里的双向链表只干一件事——区分缓存中的元素，哪些是最新使用的，哪些是最久未使用的。

    * 链表头部代表最新使用，越靠近链表尾部就代表最久未使用。

    * 两个结构是这样配合的：

        ```text
        (1) 双向链表：记录"使用顺序"，头最新、尾最久未用

              head
                |
                v
           +---------+     +---------+     +---------+
           |  Node   | <-> |  Node   | <-> |  Node   | --> tail
           | (1, 1)  |     | (2, 1)  |     | (3, 3)  |
           +---------+     +---------+     +---------+
             最新使用                          最久未用

        (2) HashMap：按 key 一步定位到节点对象

             +----------------------------------------------+
             |  HashMap<Integer, Node>                       |
             |    1 --> Node(key=1, value=1)                  |
             |    2 --> Node(key=2, value=1)                  |
             |    3 --> Node(key=3, value=3)                  |
             +----------------------------------------------+
        ```

* **两个结构指向同一个节点对象（Node）**

    * 链表节点里是把 key 和 value 打包在一起的一个节点对象。

    * 哈希表的 key 就是那个整数 key，而它的 value 存的是这个节点对象本身，不是裸的 value。

    * 链表和哈希表里指向的是同一个 Node 对象：在链表里把它挪个位置，哈希表里那条记录指的还是它；在链表里把它删掉，哈希表里那条记录就成了悬空指针——这一点后面是关键伏笔。

* **走一遍完整操作序列**

    * 把容量设成 4，链表一律写成「头 → 尾」的顺序：

        ```text
        capacity = 4

        put(1,1)   ->  1,1
        put(2,2)   ->  2,2 → 1,1
        put(3,3)   ->  3,3 → 2,2 → 1,1
        get(1)     ->  1,1 → 3,3 → 2,2        命中，摘下来再挂到头部
        put(2,5)   ->  2,5 → 1,1 → 3,3        改 value 同样算一次使用
        put(4,4)   ->  4,4 → 2,5 → 1,1 → 3,3  正好装满 4 个
        put(5,5)   ->  5,5 → 4,4 → 2,5 → 1,1  尾部 3,3 超容量被淘汰
        ```

    * 新加的一定放头部：加 2,2 时它最新，放头；加 3,3 时最新变成了 3,3，那 3,3 放头，往前推一直是这样。

    * 用过的也要挪到头部：调 `get` 拿 key=1 的数据，1 就跑到了链表头。

    * 改值也算使用：把 key=2 的值从 2 改成 5，相当于用了一次 2，它同样被调到链表头部。

    * 只有尾部会被淘汰：装到 5,5 时容量不够了，淘汰的就是最久未用的 3,3，它当时正躺在链表尾部。

## 题目需求：get 与 put 都得是 $O(1)$

* **LRUCache 的接口约定**

    * 构造方法接收一个 `capacity` 容量，将来就以这个容量来初始化这个 LRU 缓存。

    * `get`：根据 key 去查找数据，查找到了就返回 value，查找不到返回 -1。

    * `put`：往缓存里存入一对键值，这个 key 已经存在就更新 value，不存在就新增这一对键值。

    * 无论更新还是新增，都相当于"用了一次"这个数据，都要把该数据调整到链表头部，表示它是最新使用的数据。

    * 如果是新增导致数据数量超过了 `capacity`，那就移除最久未使用的那个，也就是把链表尾部的内容删掉。

* **时间复杂度硬约束**

    * > **注意**：题目明确要求，这里的 `get` 和 `put` 都必须达到 $O(1)$ 的时间复杂度。

    * 规则本身听上去完全可以暴力实现——每次把链表扫一遍重新排序，逻辑上一遍就通，但那样是 $O(n)$ 的，题目直接判错。

    * 这道题真正考的不是 LRU 规则，而是怎么在 $O(1)$ 内同时做到"按 key 找得到"和"能改顺序、能删尾部"。

    * 答案就是职责分工：哈希表负责"找"，双向链表负责"排"和"删"。

## LinkedHashMap 与手写链表

* **现成类 LinkedHashMap**

    * Java 里确实有现成的类已经同时包含了这两种数据结构，它就是 `LinkedHashMap`，本身就是"哈希表 + 双向链表"的组合体。

    * 拿它直接来做这道题，代码量会少一大半，功能也是对的。

    * > **易错点**：面试中要求的是双向链表这部分要自己实现；直接用 `LinkedHashMap` 虽然能跑通，但很多面试官会觉得"这人会用，但不会造"，就不承认你。

    * 所以解法基于自己写的双向链表展开。

## 节点类：key 和 value 一个都不能少

* **节点类（Node）的字段**

    * 缓存类外层是 `LRUCache`，用作缓存本体；它里面有两个静态内部类，分别代表双向链表中用到的节点类和双向链表类，剩下 `get`、`put` 两个方法就是题目要求的。

    * 因为是双向链表，对节点来讲需要两个指针：一个指向它的上一个节点 `previous`，一个指向它的下一节点 `next`。

    * 节点里还要包括数据中的 key 和 value 这两部分。

    * > **提示**：只包含一个 key、或者只包含一个 value 是不行的，key 和 value 在节点中都要用到，所以两个都得加上。

* **必须留 key 的原因**

    * 淘汰尾部节点时，从链表里删掉一个节点之后，还得拿着它的 key 回到哈希表里，把对应的记录也删掉。

    * 没有 key 的话，链表删干净了，哈希表里却永远留着一条指向"已死节点"的记录，留着 key 就是为了这个。

    * 这里不考虑泛型，因为题目要求的 key 和 value 都是整型。

## 环形双向链表与哨兵节点

* **两个指针加一个哨兵**

    * 双向链表需要两个指针，一个是头指针 `head`，还有一个是尾指针 `tail`。

    * 为了添加删除方便再加一个哨兵节点：头指针和尾指针刚开始就使用同一个哨兵节点，这是环形双向链表。

        ```text
        head ──┐
               ├──▶ [ 哨兵节点 ]
        tail ──┘

        再让 head.next = tail，tail.previous = head

        => 哨兵节点.next = 哨兵节点
           哨兵节点.prev = 哨兵节点
           "环"是闭上的，里面没有元素
        ```

    * 有了哨兵节点的好处是加头、删尾都不用判断空指针：你永远有一个"头"可以插，永远有一个 `tail.previous` 可以取。

* **只实现三个方法**

    * 向双向链表头部添加的方法。

    * 从尾部删除的方法。

    * 已知了某个节点，从双向链表里找到这个节点并且删除。

    * 剩下的一些方法由于这道题用不到就不写了，简单一些。

## 链表的三个方法

* **addFirst：往头部插一个节点**

    * 头部添加接收一个节点对象，就是将来要往头部加入的那个节点，插入位置在头部跟原来第一个节点之间：

        ```text
        插入前:  head ──▶ (1) ──▶ (2) ──▶ tail

                  oldFirst = head.next = (1)

        插入后:  head ──▶ new ──▶ (1) ──▶ (2) ──▶ tail
        ```

    * 先拿到原来的第一个节点 `oldFirst`，也就是 `head.next`；然后新节点的 `previous` 指向头、`next` 指向 `oldFirst`；再让 `head.next` 指向新节点、`oldFirst.previous` 也指向新节点。

    * 整个方法就是四行赋值：

        ```java
        public void addFirst(Node newFirst) {
            Node oldFirst = head.next;      // 旧的第一个节点
            newFirst.previous = head;       // 新节点：上邻居是头
            newFirst.next = oldFirst;       // 新节点：下邻居是原来的第一个
            head.next = newFirst;           // 头：next 指向新节点
            oldFirst.previous = newFirst;   // 原来的第一个：prev 指向新节点
        }
        ```

    * 时间复杂度是 $O(1)$：它跟数据规模没有关系。

* **remove：已知节点，摘出去就行**

    * 想把 2 从列表里删掉，先拿到它的上一个元素 `node.previous` 和下一个元素 `node.next`，再把中间这个节点剔除掉：

        ```text
        删除前:  ... ──▶ prev ──▶ node ──▶ next ──▶ ...

        删除后:  ... ──▶ prev ──────────▶ next ──▶ ...
        ```

        ```java
        public void remove(Node node) {
            node.previous.next = node.next;
            node.next.previous = node.previous;
        }
        ```

    * 时间复杂度是 $O(1)$，跟数据规模没有关系。

    * > **定义**：`remove` 的参数是节点对象本身，不是 key，也就是说它不做查找——查找是哈希表干的活儿，链表这边只负责"我知道你在哪、你旁边是谁，我把你摘出去"，这一点是整个方案能做到 $O(1)$ 的关键。

* **removeLast：删尾部，转调 remove 就够了**

    * 删除尾部就是取 `tail.previous`，把它叫 `last`，最终这个节点要被删除。

    * 已知某个节点要删除的方法上面已经有了，所以不用把代码重写一遍，直接调用即可，最后把删掉的节点返回：

        ```java
        public Node removeLast() {
            Node last = tail.previous;   // 最后一个元素
            remove(last);                // 复用上面那个方法
            return last;
        }
        ```

    * 整体时间复杂度是 $O(1)$。

    * > **提示**：尾部删除目前不用考虑节点数量——里面只有一个节点时也能删，删完只剩一个头尾的哨兵节点；真正能不能删可以让下面的 `HashMap` 与链表联动，哈希表拿到的内容在做删除时如果连内容都没找到就不用删除，所以这个判断就不加了。

* **三个方法的复杂度结论**

    * 头部添加、删除节点、尾部删除这三个方法的时间复杂度全都是 $O(1)$。

## 缓存类的成员变量

* **三个 final 字段**

    * 哈希表：key 用整数就行，但它的 value 需要包装一下，把这个键和值包装成节点对象作为哈希表的 value，类型就是 `Node`。

    * 双向链表：用自己实现的 `DoubleList`。

    * 容量：因为超了还要移除最久未使用的元素，所以得加一个 `capacity`，而且它要通过有参构造传递进来。

    * 因为哈希表和链表将来引用都不会变了，把它们都改成 `final` 的：

        ```java
        private final HashMap<Integer, Node> map = new HashMap<>();
        private final DoubleList list = new DoubleList();
        private final int capacity;

        public LRUCache(int capacity) {
            this.capacity = capacity;
        }
        ```

## get 方法：摘下来，再挂到头部

* **逻辑与实现**

    * 先判断 `map` 中是否包含这个 key，不包含相当于哈希表中根本没有这对键值，返回 -1；条件不成立就继续走 `map.get(key)`，get 出来的是键和值都有的节点对象，最终人家要的是值。

    * 除了哈希表的逻辑之外还有一件额外的事要做：调整 get 到的这个节点在双向链表中的位置；没找到就无所谓，没啥可调整的。

    * 找到之后这个节点就已知了，要做的事情很简单——把它从原始的位置先删掉，然后再把它加入到头部；删除用 `remove` 方法，插入用 `addFirst` 方法，两步都是 $O(1)$。

        ```java
        public int get(int key) {
            if (!map.containsKey(key)) {
                return -1;
            }
            Node node = map.get(key);
            list.remove(node);      // 先从原来的位置摘下来
            list.addFirst(node);    // 再挂到链表头部
            return node.value;
        }
        ```

* **复杂度**

    * `map.containsKey`、`map.get` 的时间复杂度都是 $O(1)$，实现的 `remove` 和 `addFirst` 也是 $O(1)$，所以整体上 `get` 的时间复杂度就是 $O(1)$，达到题目要求。

## put 方法：更新一条路，新增另一条路

* **key 已存在：改 value，然后挪到头部**

    * 先 `map.get(key)` 把节点对象拿出来，然后把它的 `value` 更新成新的值。

    * 除此以外要把这个节点对象调整到链表头部，调整方式和 `get` 类似：先从原本位置删掉，再加入到链表头部。

        ```java
        if (map.containsKey(key)) {
            Node node = map.get(key);
            node.value = value;      // 更新值
            list.remove(node);       // 从原位置摘掉
            list.addFirst(node);     // 挂回头部
        }
        ```

    * > **提示**：更新值也消耗了一次"使用额度"，改 value 和读一样都算用过这个 key，所以照样要挪位置；这不是多余的代码——LRU 判断的是最近被访问，而不是最近被写入。

* **key 不存在：建节点、插头部，再查容量**

    * 原始的键值要封装成一个节点对象再往 `map` 里放：先根据原始键值创建节点对象，再调用 `map.put(key, node)` 把封装后的节点对象放入 `map`。

    * 放进去之后还差一件事：把新增的这个节点对象作为最新使用的节点放到链表头，即 `list.addFirst(node)`。

    * 插入完之后要做容量是否已满的检查，因为 `map` 的容量跟链表的容量是一致的，一旦 `map.size()` 超过了 `capacity`，就把尾部删掉，直接调用 `removeLast()`。

    * > **易错点**：删除掉尾部节点之后，`map` 中也要对应地删除；拿到被删除的节点后，要根据它的 key 回过头来在 `map` 中把它也删掉——这就是节点里必须留一个 key 的原因。

        ```java
        else {
            Node node = new Node(key, value);
            map.put(key, node);
            list.addFirst(node);
            if (map.size() > capacity) {
                Node removed = list.removeLast();  // 链表尾部出队
                map.remove(removed.key);            // 哈希表里对应记录同步删掉
            }
        }
        ```

    * 这段代码也把前面的疑问收掉了：`removeLast` 里不用做有效性检查，因为真正删除的动作是由 `put` 这边发现放满了才去触发的，那这时候肯定不会出现"只剩一个哨兵节点不够删"的情况。

## 一次复杂度对账

* **逐项复杂度**

    | 方法 | 内部到底做了什么 | 时间复杂度 |
    | --- | --- | --- |
    | `map.containsKey / get / put / remove` | 哈希表的基本操作 | $O(1)$ |
    | `addFirst(node)` | 改 4 根指针，不遍历 | $O(1)$ |
    | `remove(node)` | 改 2 根指针，不遍历 | $O(1)$ |
    | `removeLast()` | 取一次 `tail.previous`，转调 `remove` | $O(1)$ |
    | `get(key)` | 一次查表 + `remove` + `addFirst` | $O(1)$ |
    | `put(key, value)` | 一次查表；更新或新增走 3~4 步，含一次容量检查 | $O(1)$ |

    * > **结论**：整个方案里没有任何一个环节跟数据规模有关——没有遍历，没有查找，没有排序；所有操作都只是"顺着指针走几步"或者"哈希表算一次哈希"，这就是 `get`、`put` 能同时做到 $O(1)$ 的全部原因。

* **设计上的两处关键**

    * 职责切得特别干净：哈希表回答"这个 key 在不在、它对应哪个节点"，双向链表回答"谁最新、谁最久没用、谁该淘汰"；两个结构各管一件事，中间用同一个 `Node` 对象串起来，于是 LRU 这个"要排序的需求"被降维成了"改几个指针"。

    * 节点里那个看起来多余的 key 字段，恰恰是把两个结构"焊"在一起的关键——链表删掉的只是位置，哈希表删掉的才是数据，两边靠它对齐。
