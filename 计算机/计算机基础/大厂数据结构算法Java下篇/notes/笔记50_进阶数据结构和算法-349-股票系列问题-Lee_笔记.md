# 进阶数据结构和算法-349-股票系列问题-Lee

## 买卖一次：双指针把价格曲线走一遍

### 题目设定

* **买卖股票的最佳时机（Problem 121）**

    * > **定义**：给一个数组代表一只股票在每一天的价格，以上帝视角预知全部价格；要求在某一天买入、在未来的某一天卖出，只能买卖一次，求能得到的最大利润。

    * 例：第一天价格 7、第二天价格 1，往后依次递减，第五天价格 6；第二天以 1 买入、第五天以 6 卖出，利润为 $6-1=5$。

    * 股票一直亏损时得不到任何利润，最大利润取 0。

* **买卖必须发生在未来**

    * 卖出日必须晚于买入日，收益只可能来自 $price[j]-price[i]$，差值不大于 0 的组合一律不算候选。

### 双指针的走法

* **两个下标 `i`、`j`**

    * `i` 代表在第 `i` 天买入，`j` 代表在第 `j` 天卖出；因为必须在未来的某一天卖出，`j` 恒大于 `i`，初始取值 `i = 0`、`j = i + 1`。

    * 涨跌的判定方式就是价格差：`price[j] - price[i] > 0` 说明涨，小于 0 或等于 0 说明跌或平，没有利润。

    * 遇到跌时把 `i` 挪到 `j` 的位置，也就是尝试在更低价这天买入，然后 `j` 再加一。

    * 遇到涨时 `i` 钉在这个低价上不动，只走 `j`，同时记一次利润。

    ```text
    price[j] - price[i] <= 0     跌 / 平，没有利润
        i ← j                    买点在往更低的价格上挪
        j ← j + 1

    price[j] - price[i] >  0     涨，有利润
        max ← max(max, price[j] - price[i])      记一次利润
        i 不变                  买点在低位这天钉住
        j ← j + 1
    ```

* **最大值容器 `max`**

    * 整个过程会遇到多次有利润的情况，而只能买卖一次，所以必须在这些情况里挑出利润最高的那个。

    * `max` 在循环外先定，初值为 0；每次遇到涨就用本次的 `price[j] - price[i]` 与它比一次，更高就替换，循环结束时 `max` 就是最高利润。

* **两条规律合起来就是全部解法**

    * 遇到涨，买点钉住、卖点右移、记一次利润；遇到跌，买点挪到更低价、卖点右移。

### 实现与用例

* **代码骨架**

    * `i` 初值为 0、`j` 初值为 1，写一个 `while` 循环，条件是 `j` 小于数组长度；每次先判断涨还是跌，涨了更新 `max`，跌了挪 `i`，然后 `j` 往前走一步。

    ```java
    public int maxProfit(int[] price) {
        int i = 0;                  // 买入下标
        int j = 1;                  // 卖出下标，恒满足 j > i
        int max = 0;                // 目前找到的最大利润

        while (j < price.length) {
            // 用 j 处的价格减去 i 处的价格，正数就是有利润
            if (price[j] - price[i] > 0) {
                // 有利润：记一次，买点保持不动，卖点右移
                max = Math.max(max, price[j] - price[i]);
                j++;
            } else {
                // 没利润：把买点挪到更低的价格上
                i = j;
                j++;
            }
        }
        return max;
    }
    ```

* **两个用例的心算结果**

    * 力扣上的测试用例：价格 1 的时候买入、价格 6 的时候卖出，最高利润是 5。

    * 画图用例：最高利润是 9，来自价格 3 买入、价格 12 卖出；后面虽然也有小幅上涨，但从 1 买入、3 卖出只能拿到利润 2。

## 买卖多次：只看相邻两天有没有差价

### 题目设定

* **买卖股票的最佳时机 II（Problem 122）**

    * > **定义**：某一天买入股票、未来任意一天卖出，但只能卖了再买，所以手里始终只能持有一股；允许买卖多次，并且允许同一天卖出后再买入，求最大利润。

    * 与只能买卖一次的那道题相比，区别只有两点：可以买卖多次，并且同一天可以既买又卖。

    * 需求虽然写得更长，但解起来反而更简单。

### 贪心做法

* **贪心（Greedy）**

    * > **定义**：只顾眼前——只要当前这一小段有利润，就立刻产生一笔交易把这钱赚了，长远、更长远的涨幅不去合并考虑。

    * 两个指针 `i`、`j` 的范围始终固定为 1，永远只看相邻两天，不需要考虑更长远的范围。

    * `price[j] - price[i] > 0` 就把这段差价累加进 `sum`；小于等于 0 什么都不做。

    * 不管涨还是跌，`i` 加一、`j` 加一都无条件执行，所以这两句写在 `if` 判断的外面。

    ```text
            i          j
            ↓          ↓
      ──────┴──────────┴────── 价格曲线（横轴=下标，纵轴=当日价格）
                              i 与 j 始终相距 1，永远只看相邻两天

      price[j] - price[i] >  0    有利润 → sum += price[j] - price[i]
      price[j] - price[i] <= 0    没利润 → 什么都不做

      然后 i ← i + 1 ,  j ← j + 1      无条件，各走一步
    ```

    * 既然已经是上帝视角、预见到接下来好几天都是涨的，也不需要让 `i` 停住、让 `j` 一路走到更高点再一块儿卖；只赚眼前这一天，下一天的差价照样能累加进来，利润不会丢。

* **贪心成立的前提**

    * 题目里"允许同一天卖出后再买入"这句话正是贪心成立的关键：在这几天卖掉之后，立刻把卖出后的这一天当作下一个区间的买入点，继续做后续计算。

    * > **易错点**：如果没有这句约束，就不能用贪心解，差一个子午线，思路要整个重来。

* **代码骨架**

    * 判断方式与只能买卖一次的那道题一致，都是用 `j` 处价格减去 `i` 处价格；`i`、`j` 各走一步的两句写在判断外面。

    ```java
    public int maxProfit(int[] price) {
        int i = 0;
        int j = 1;
        int sum = 0;

        while (j < price.length) {
            if (price[j] - price[i] > 0) {
                // 只要这一小段有差价，立刻落袋
                sum += price[j] - price[i];
            }
            // 不管涨还是跌，两个指针都各走一步
            i++;
            j++;
        }
        return sum;
    }
    ```

* **两个用例的心算结果**

    * 第一个用例：开头是跌的不用看；有一段涨的利润是 9；后面跌的不用看；再后面都是涨的，利润是 2，$9+2=11$。

    * 第二个用例：开头是跌的不用看；有一段涨的利润是 4；后面还有一段涨的利润是 3，$4+3=7$；再往后这一段就不用看了。

## 含手续费：贪心失效，改用双状态动态规划

### 贪心失效的原因

* **手续费把交易笔数变成了要被计价的动作**

    * 没有手续费时，多做一笔交易只有好处，贪心就成立。

    * 一旦有了手续费，交易的笔数本身就有成本了，必须权衡"这一小段利润"和"再开一笔要付出的代价"。

    * 仍按贪心把一段涨幅拆成多笔交易，手续费就被扣了多次；在最高点一次性卖出只交一次费，显然更划算。

    * > **结论**：这道题不能用贪心，必须改用动态规划求解。

* **为什么需要两条状态线**

    * 平时用动态规划需要一个状态数组记录每一步的选择，这道题的特殊之处在于需要两个状态数组：一个跟买有关，另一个跟卖有关。

### 双状态与转移方程

* **状态含义**

    * `buy[i]` 表示第 `i` 天结束时手里持有股票的最大利润，`sell[i]` 表示第 `i` 天结束时手里没有股票的最大利润。

    * 买入记作从现金里扣钱，所以 `buy` 的取值是负数；卖出才产生正收益。

    * 初始状态：`buy[0] = -price[0]`，`sell[0] = 0`，因为第 0 天没法卖，手里也没有股票可卖。

* **两个转移方程**

    * 买有两个选择：延续上一天的 `buy[i-1]`，或者在上次卖的 `sell[i-1]` 基础上减去当日价格 `price[i]`；两者取大。

    * 卖有两个选择：延续上一天的 `sell[i-1]`，或者在上次买的 `buy[i-1]` 基础上加上 `price[i]`，再减掉手续费 `fee`；两者取大。

    * 两条线互相依赖，但都只依赖昨天：今天买入只能从"昨天空仓"过来，今天卖出只能从"昨天持股"过来，因为题目不允许连续买。

    * 整个数组走完之后，`sell` 的最后一个元素就是最大利润。

    ```text
                         第 i 天
                            |
            +---------------+---------------+
            |                               |
       今天买入 / 继续持有            今天卖出 / 继续空仓
            |                               |
            v                               v
      buy[i]  = max( buy[i-1],       sell[i] = max( sell[i-1],
                     sell[i-1]               buy[i-1]
                        − price[i]              + price[i]
                        )                       − fee
                                                 )
    ```

    * > **易错点**：手续费只在 `sell` 里扣一次，`buy` 里不扣；写成两边都扣等于每笔交易交了两遍钱，结果偏小。

* **为什么把手续费放在卖出时扣**

    * 第一天价格 9 时买入记 -9，第二天价格 3 卖出所得是 $-9+3=-6$，再减一块钱手续费变成 $-7$，于是可以约定买时不考虑手续费、只在卖时扣一次。

    * 这样买入这条线就只需处理价格本身，两条线的职责更干净。

### 六天推演

* **前三天的状态**

    * 第一天价格 9：买入记 -9，卖出不成立记 0。

    * 第二天价格 3：买线两个选择是延续 -9 与 $0-3=-3$，选 -3；卖线两个选择是延续 0 与 $-9+3-1=-7$，选 0。

    * 第三天价格 12：买线两个选择是延续 -3 与 $0-12=-12$，选 -3；卖线两个选择是延续 0 与 $-3+12-1=8$，选 8。

* **推演总表**

    * 表里每一格的"选择一"是延续上一天的状态，"选择二"是从另一条线转移过来，两格中挑一个大的。

    | 天（价格） | 买：延续 buy[i-1] | 买：sell[i-1] − 价格 | buy[i] | 卖：延续 sell[i-1] | 卖：buy[i-1] + 价格 − fee | sell[i] |
    | --- | --- | --- | --- | --- | --- | --- |
    | 第 1 天（9） | — | — | **−9** | — | — | 0 |
    | 第 2 天（3） | −9 | 0 − 3 = −3 | **−3** | 0 | −9 + 3 − 1 = −7 | 0 |
    | 第 3 天（12） | −3 | 0 − 12 = −12 | **−3** | 0 | −3 + 12 − 1 = 8 | **8** |
    | 第 4 天（1） | −3 | 8 − 1 = 7 | **7** | 8 | −3 + 1 − 1 = −3 | 8 |
    | 第 5 天（2） | 7 | 8 − 2 = 6 | **7** | 8 | 7 + 2 − 1 = 8 | 8 |
    | 第 6 天（3） | 7 | 8 − 3 = 5 | **7** | 8 | 7 + 3 − 1 = 9 | **9** |

    * 表中 `fee = 1`。

* **后三天的状态**

    * 第四天价格 1：买线两个选择是延续 -3 与 $8-1=7$，选 7；卖线两个选择是延续 8 与 $-3+1-1=-3$，选 8。

    * 第五天价格 2：买线两个选择是延续 7 与 $8-2=6$，选 7；卖线两个选择是延续 8 与 $7+2-1=8$，两者相等，取 8。

    * 第六天价格 3：买线两个选择是延续 7 与 $8-3=5$，选 7；卖线两个选择是延续 8 与 $7+3-1=9$，选 9。

* **最终结果**

    * 最大利润是 9，交易发生在价格 1 买入、价格 12 卖出、价格 3 买入，总共两次买卖交易。

### 数组实现与测试

* **一维数组写法**

    * 定义两个长度与天数一致的一维数组 `buy` 与 `sell`，索引 0 处手工初始化；循环从 1 开始，因为第 0 天已经初始化好。

    ```java
    public int maxProfit(int[] price, int fee) {
        int[] buy = new int[price.length];    // 买线：今天结束时手里持有股票
        int[] sell = new int[price.length];   // 卖线：今天结束时手里没有股票

        buy[0] = -price[0];                   // 第 0 天买入
        sell[0] = 0;                          // 第 0 天没法卖，手里没股票

        for (int i = 1; i < price.length; i++) {
            // 买：延续昨天的买，或者昨天空仓 → 今天买
            buy[i] = Math.max(buy[i - 1], sell[i - 1] - price[i]);
            // 卖：延续昨天的卖，或者昨天持股 → 今天卖（扣一次手续费）
            sell[i] = Math.max(sell[i - 1], buy[i - 1] + price[i] - fee);
        }

        return sell[price.length - 1];
    }
    ```

* **两个代表性用例**

    * 两次交易的用例：1 买入 8 卖出赚 7，4 买入 9 卖出赚 5，$7+5=12$；手续费是 2，两次交易共扣 4，最终总利润是 8。

    * 一次交易的用例：1 买入，中间几次卖出都没有利润，一直到 10 才卖出收益最大，$10-1=9$；手续费是 3，扣一次后利润是 6。

### 降维与变量合并

* **一维数组降成四个变量**

    * 计算第 `i` 天的状态只依赖第 `i-1` 天的两个状态，更早的状态用不到；比如算到第三天只需要第二天的两个状态，第 0 天的状态完全不关心。

    * 用 `_buy`、`_sell` 表示上一次的买卖状态，`buy`、`sell` 表示本次算出的利润；初始值 `_buy = -price[0]`、`_sell = 0`，循环结束前写 `_buy = buy`、`_sell = sell`，最终返回 `_sell`。

    ```java
    public int maxProfit(int[] price, int fee) {
        int _buy = -price[0], _sell = 0;   // 昨天
        int buy = 0, sell = 0;             // 今天

        for (int i = 1; i < price.length; i++) {
            buy = Math.max(_buy, _sell - price[i]);
            sell = Math.max(_sell, _buy + price[i] - fee);
            _buy = buy;
            _sell = sell;
        }
        return _sell;
    }
    ```

* **`sell` 的两个变量可以合成一个**

    * 赋值语句上移之后，先是赋值给当前临时变量、紧接着又复制给上一次变量，两行本来就可以并成一行，变量统一叫 `s`。

    * 合成之后语义不变，因为 `b` 的计算读的仍然是**上一次**的 `s`。

    ```java
    public int maxProfit(int[] price, int fee) {
        int s = 0;                 // 上一次的卖状态，兼作当前临时变量
        int _b = -price[0];        // 上一次的买状态

        for (int i = 1; i < price.length; i++) {
            int b = Math.max(_b, s - price[i]);
            s = Math.max(s, _b + price[i] - fee);
            _b = b;
        }
        return s;
    }
    ```

* **`buy` 的两个变量也能合并，答案一样**

    * 把 `b` 的赋值语句上移之后，`sell` 就变成了根据**本次**的 `b` 算出来的，业务意义变了。

    * > **易错点**：这处改动确实改变了 `sell` 的依赖对象，看题解时不要以为两种写法语义一致。

    * 变动后不影响最终结果：若本次 `b` 取的是 `max` 里的前一项，它就等于上次的 `b`，套进 `sell` 的式子仍是按上次的 `b` 算；若本次 `b` 取的是后一项，把这一项代入 `sell` 后两个 `price` 一正一负互相消掉，此时 `s` 只依赖上次的 `s` 和上次的 `s` 减手续费，与本次 `b` 无关。

    ```java
    public int maxProfit(int[] price, int fee) {
        int b = -price[0];
        int s = 0;

        for (int i = 1; i < price.length; i++) {
            b = Math.max(b, s - price[i]);
            s = Math.max(s, b + price[i] - fee);   // 注意：这里用的是"本次"的 b
        }
        return s;
    }
    ```

    * 力扣题解中两种写法并存，正是因为"按本次 `b` 算"和"按上次 `b` 算"写出来的代码不一样，而它们的结果一致。

* **下标归零并改成增强 for**

    * 让 `i` 从 0 开始，只需把 `b` 的初值从 `-price[0]` 改成 `Integer.MIN_VALUE`。

    * 首次循环时 `i = 0`，是在 `Integer.MIN_VALUE` 与 `0 - price[0]` 之间取大，后者必然更大，等价于原来的 `-price[0]`。

    ```java
    public int maxProfit(int[] price, int fee) {
        int b = Integer.MIN_VALUE;   // 首次循环时自然被 0 - price[0] 顶掉
        int s = 0;

        for (int p : price) {
            b = Math.max(b, s - p);
            s = Math.max(s, b + p - fee);
        }
        return s;
    }
    ```

## 三道题的分界线

* **需求与思想的对照**

    | | 121 买卖一次 | 122 买卖多次 | 714 含手续费 |
    | --- | --- | --- | --- |
    | 附加条件 | 必须在未来的某一天卖出 | 只能"卖了再买"；允许同一天先卖后买 | 买卖多次的全部条件 + 每笔交易收一次手续费 |
    | 核心思想 | 双指针 + 取最大值 | 双指针 + **贪心**（只顾眼前） | **动态规划**（贪心失效） |
    | 状态量 | 两个下标 `i`/`j` + 一个 `max` | 两个下标 `i`/`j` + 一个 `sum` | `buy[]` / `sell[]` 两条状态线 |
    | 关键约束 | 买卖只能用一次，取最优 | 相邻两天有差价就落袋，利润不会丢 | 交易次数影响手续费，合并交易才划算 |
    | 最好结果 | 一次买卖的最大差价 | 所有涨段差价之和 | 多状态转移后的最大净值 |

* **最值得记的那条分界线**

    * 手续费把"每笔交易"变成了一个要被计价的动作：没有手续费时多做一笔交易只有好处，贪心就成立；一旦有了手续费，交易的笔数本身就有成本，贪心立刻塌掉，只能老老实实开状态。

    * 这一类题基本都围着这条线在变——加冷却期、加限制、加手续费，每加一条约束就要重新审视贪心还成不成立。

* **判断该用贪心还是动态规划的准则**

    * 先问一句"我做的这个局部选择，会不会反过来抬高全局的成本"。

    * 买卖多次那题答案是不会——手速换不来额外成本，所以贪心成立。

    * 含手续费那题答案是会——每多一笔就多交一次钱，所以必须上动态规划。
