# 进阶数据结构和算法-344-设计LFU缓存-Le

## 题目要求

* **LFU 缓存（Least Frequently Used Cache，LFUCache）**

    * > **定义**：一种定长缓存，满的时候按使用频次淘汰元素，频次相同时再按最久未使用淘汰。

    * 整体骨架由四部分组成：一个节点内部类、一个双向链表内部类、`get` 方法、`put` 方法。

    * 构造方法接收容量参数 `capacity`，`put(key, value)` 负责新增或修改元素。

    * `get(key)` 在 `key` 不存在时返回 -1，在 `key` 存在时返回该元素当前保存的值。

    * 硬指标是 `get` 和 `put` 两个方法的时间复杂度都要达到 $O(1)$。

    * > **提示**：题目要的不是「能跑就行」，而是两个方法都必须是 $O(1)$；这条硬指标直接决定后面所有数据结构的选择。

---

## LFU 的淘汰规则

* **使用频度（frequency）**

    * > **定义**：元素被使用的次数，是 LFU 在 LRU 的键值对之上额外加的第三个属性。

    * 图中每个元素都有三个数字，前两个是键值对（1:1、2:2），第三个数字才是使用频度。

    ```text
    ┌───────────┬───────────┬─────────────┐
    │ key       │ value     │ frequency   │
    ├───────────┼───────────┼─────────────┤
    │     1     │     1     │ 使用 1 次   │
    │     2     │     2     │ 使用 1 次   │
    │     3     │     3     │ 使用 4 次   │
    └───────────┴───────────┴─────────────┘
    ```

* **LFU 相对 LRU 多出来的那一层排序键**

    * > **定义**：LFU 就是 Least Frequently Used，最不经常使用；它在「最近最少使用」之上加了一层排序键。

    * 第一层比频次：频度低的先被淘汰，频度高的一律留着。

    * 第二层比时间：频度相同时，淘汰其中最久没被用过的那个，也就是更早被使用的那个。

    * 图中元素 1 和 2 的频度都是 1，元素 1 更老，所以淘汰时选 1。

* **频度会随访问漂移，这是全部设计难点的来源**

    * 查找元素、更新元素都会让该元素的使用频次加一。

    * 频次因此是动态属性，元素不得不在不同频次之间来回搬家。

## 两张哈希表的职责划分

| 哈希表 | key | value | 作用 |
| :--- | :--- | :--- | :--- |
| `kvMap` | 元素的 `key`（Integer） | 封装好 key、value、频度的节点对象 | 按 key 一步定位到元素 |
| `frequencyMap` | 使用频度（Integer） | 一条 `DoubleLink` 双向链表 | 按频度一步定位到这一频度下的所有元素 |

* **两张表的索引含义不同**

    * `kvMap` 里的 `1` 表示元素的 key 是 1，`frequencyMap` 里的 `1` 表示该元素被使用了一次。

    * 两个 `1` 数值相同但含义不同，多放几个元素就能明显看出差别。

    ```text
      kvMap（按 key 找到元素）
           key = 1   ---------->  Node{key=1, value=1, frequency=1}
           key = 2   ---------->  Node{key=2, value=2, frequency=1}

      frequencyMap（按使用次数找到元素）
           frequency = 1   ---->  head <--> Node{2} <--> Node{1} <--> tail
           frequency = 3   ---->  head <--> Node{3} <--> tail
    ```

### 节点与链表的组织方式

* **`frequencyMap` 的值必须是一条链表而不是单个节点**

    * > **定义**：`frequencyMap` 的值类型是一条 `DoubleLink` 双向链表。

    * 一个频度完全可能对应多个元素，图中频度为 1 的就有元素 1 和元素 2 两个。

    * 同一频度下的多个元素用双向链表连起来，才能进一步区分谁更老。

* **链表的方向约定**

    * 链表头 `head` 对应最新使用的元素，新元素一律 `addFirst` 插到头部。

    * 链表尾 `tail` 对应最久未使用的元素，淘汰时用 `removeLast` 取它。

* **新元素的落位**

    * `put` 一个新 key 时，它先进入 `kvMap`，初始使用频度为 1。

    * 因为初始频度为 1，所以它进入 `frequencyMap` 中频度为 1 的链表，并且插在链表头部。

## 使用频度迁移

* **每一次访问都要触发一次搬家**

    * > **定义**：节点频度加一的过程，就是「先从旧链表摘掉，再插到新链表的头部」。

    * `get` key 1 之后，它的频度从 1 变 2，从频度为 1 的链表移到频度为 2 的链表；继续 `get` 则依次移到频度 3、频度 4 的链表。

    * `get` key 2 同样从频度为 1 的链表移到频度为 2 的链表，新链表里已有 1 就直接加进去。

    ```text
      get(1) 之前:  frequencyMap[1] -->  head <-> Node{2} <-> Node{1} <-> tail

      get(1) 之后:  frequencyMap[1] -->  head <-> Node{2} <-> tail
                    frequencyMap[2] -->  head <-> Node{1} <-> tail
    ```

    * > **易错点**：搬家绝不能图省事直接往新链表里塞。少摘一次，同一个节点就会同时挂在两条链表上，两条链的长度乃至淘汰顺序全都会错位。

---

## 淘汰流程

* **触发时机**

    * 按题目要求，在把新节点放进 `kvMap` 之前就先检查容量。

    * 判断条件是 `kvMap.size() == capacity`，相等即表示已满、要腾位置了。

    * > **提示**：如果改成先添加新节点再检查，判断条件就必须相应改成「大于」，两种写法不能混用。

* **淘汰对象的确定**

    * 淘汰最小频度的那条链表，也就是 `frequencyMap.get(minFrequency)`。

    * 该链表若不止一个节点，淘汰 `removeLast` 取到的尾节点，因为它是最久未使用的。

    * `kvMap` 里有 1、2、3 且容量为 3 时再放入 4，淘汰频度为 4 的元素 3，剩下 1、2、4；再放入 5 前若先 `get(4)` 让它频度涨到 2，则频度最低的是 4 和 2，淘汰它们之中更老的 2，剩下 1、4、5。

    ```text
      加入 5 之前:   freq 2:  head <-> 4 <-> 2 <-> tail
                     freq 3:  head <-> 1 <-> tail

      put(5) 淘汰:   freq 2 的 tail 就是 2，直接把 2 淘汰掉

      之后:          freq 1:  head <-> 5 <-> tail
                     freq 2:  head <-> 4 <-> tail
                     freq 3:  head <-> 1 <-> tail
    ```

* **两张表必须同步删除**

    * 链表那边 `removeLast` 之后，`kvMap` 这边还要按被删节点的 key 再 `remove` 一次，否则两张表会残留不一致的记录。

## 时间复杂度验算

* **查找路径全程不需要遍历**

    * `kvMap` 按 key 取节点是 $O(1)$。

    * 节点自带 `frequency` 字段，所以能直接用 `frequencyMap` 按频度取到对应链表，这一步也是 $O(1)$。

    * 节点本身在这一步已知，从链表删除是 $O(1)$，往新链表头部插入也是 $O(1)$。

    * 整条 `get` 路径累加起来仍是 $O(1)$，满足题目要求。

* **淘汰路径同样不遍历**

    * 把最小频度记在变量里，需要淘汰时直接用它去 `frequencyMap` 取链表，不用遍历所有频度。

    * 取到链表后只到尾部删一个节点，也是 $O(1)$。

* **`frequencyMap` 这一张表存在的意义**

    * > **提示**：如果没有这张表，只能把元素全塞进一条大的双向链表，查找某个频度的元素就得遍历，时间复杂度不达标；引入它就是为了快速定位某一频度下的整批元素。

## 节点类与链表类的改动

* **`Node` 节点类**

    * > **定义**：存放单个缓存元素的内部类，字段是 `key`、`value`、`frequency`、`prev`、`next`。

    * 相对 LRU 版本只多一个属性 `frequency`，代表该节点的使用频度。

    * 代码与 LRU 版本几乎一样，可以直接把上一个题目的节点类拷过来。

* **`DoubleLink` 双向链表类**

    * > **定义**：按频度分组的双向链表，用 `head` 和 `tail` 两个哨兵节点串起一频度下的全部元素。

    * 多加一个 `size` 属性记录链内元素个数，初始值为 0；`addFirst` 末尾 `size++`，`remove` 末尾 `size--`。

    * `removeLast` 自身不直接改 `size`，它取到 `tail.prev` 后交给 `remove` 去改。

    * > **定义**：`isEmpty()` 判断这条频度链是否已被搬空，实现就是 `return size == 0;`。

    * LRU 版本只有一条链表且长度等于 `capacity`，所以不需要 `size`；本题可能有多个链表，从下方 `kvMap` 的元素个数 3 推断不出每条链各有几个元素，甚至可能为空，因此必须有 `size`。

    * > **提示**：拷贝粘贴时选择「以文本方式粘贴」，否则会把上一个类的类名也一起带过来；双向链表类同理。

```java
class LFUCache {

    // 节点类：比 LRU 版本多一个 frequency
    class Node {
        int key;
        int value;
        int frequency;      // 使用频度，LFU 特有
        Node prev, next;
    }

    // 双向链表类：比 LRU 版本多一个 size 和一个 isEmpty
    class DoubleLink {
        private Node head = new Node(0, 0);
        private Node tail = new Node(0, 0);
        private int size = 0;

        // 这三个方法与 LRU 版本完全一致，直接拷贝过来
        public void addFirst(Node node) { ... size++; }   // 末尾 size++
        public void remove(Node node)    { ... size--; }   // 末尾 size--
        public Node removeLast()        { ... }            // 取 tail.prev 后交给 remove

        // 新增：判断这条频度链是不是已经空了
        public boolean isEmpty()        { return size == 0; }
    }
}
```

## get 的实现

* **成员变量与初始化**

    * `kvMap` 声明为 `Map<Integer, Node>`，`frequencyMap` 声明为 `Map<Integer, DoubleLink>`，都在构造方法之外初始化。

    * `capacity` 代表缓存容量，在构造方法里赋值。

    * `minFrequency` 代表当前最小频度，初值是 1。

* **`get` 的两条分支**

    * key 不存在：按题目要求返回 -1，用 `containsKey` 判断。

    * key 存在：取出节点、记下它当前的 `value` 返回，再把频度加一并搬到频度加一的链表头部。

    * 搬到新链表前要先按节点原有频度找到旧链表并 `remove`，新链表不存在就现场创建。

```java
    public int get(int key) {
        // ① K 不存在，按题目要求返回 -1
        if (!kvMap.containsKey(key)) {
            return -1;
        }

        Node node = kvMap.get(key);
        int value = node.value;

        // ② 根据原来的频度找到旧链表，先把节点摘出来
        DoubleLink oldList = frequencyMap.get(node.frequency);
        oldList.remove(node);

        // ③ 旧链表被搬空、且它正是最小频度那条 -> 最小频度上抬
        if (oldList.isEmpty() && node.frequency == minFrequency) {
            minFrequency = node.frequency + 1;
        }

        // ④ 频度 +1，搬进新链表的头部；链表不存在就现场造一条
        node.frequency++;
        DoubleLink newList = frequencyMap.computeIfAbsent(node.frequency, k -> new DoubleLink());
        newList.addFirst(node);

        return value;
    }
```

### 维护最小频度

* **为什么要额外记一个 `minFrequency`**

    * 淘汰时要找频度最低的那条链表，若每次现算就会退化成遍历全部频度。

    * 初值 1 对应频度为 1 的链表；但如果这条链被搬空，最小频度就要上抬。

    * 例如依次 `get 1`、再 `get 2`，两个元素都从频度为 1 的链转移到频度为 2 的链，频度为 1 的链空了，最小频度就应更新成 2。

* **上抬的判定条件**

    * 必须同时满足两点：搬空的是最小频度那条链表，且它确实被搬空了。

    * 触发后执行 `minFrequency = node.frequency + 1`，正好上抬一格。

    * > **易错点**：这两个条件缺一不可。链表空了但它不是最小频度那条链表，最小频度不要动；它是最小频度那条链表但里面还剩别的元素，最小频度同样不要动。只有「最小频度那条链被搬空了」这一种情况才上抬。

* **空壳链表不必立刻清理**

    * > **提示**：被搬空的链表不用急着从 `frequencyMap` 里删掉，留下的只是一个空壳；以后再有节点要进这条频度链，`computeIfAbsent` 命中这个空壳，照样能往里 `addFirst`，不影响正确性。

### `computeIfAbsent` 收敛写法

* **它替代了什么**

    * 原写法是手写的「若存在直接取，不存在就 new 一个再 `put` 进去」，逻辑没错但啰嗦。

    * `computeIfAbsent(key, lambda)` 第一个参数是要给 map 的 key，这里就是节点的频度；第二个参数是 function，用 lambda 表达式写出 `k -> new DoubleLink()`。

    * 命中已存在的值时直接返回该值；未命中时执行 lambda，把生成的双向链表放进 map 并返回。

    * 无论存在与否都返回一条 `DoubleLink`，返回后统一 `addFirst(node)` 即可，一行等价于原来那一整段。

## put 的实现

* **先按 key 是否存在分两路**

    * 用 `kvMap.get(key)` 拿到节点，非空走更新逻辑，为空走新增逻辑。

    * 更新与新增都要处理频度搬家，差别只在于更新不需要腾位置。

### key 已存在：改值并搬家

* **更新动作与 `get` 同构**

    * 先把 `node.value` 改成传入的新值。

    * 再照搬 `get` 的四步：按原频度找到旧链表并 `remove`、判空并上抬最小频度、频度加一、搬进新链表头部。

    * 例如把 key 1 的 value 更新为 5，更新后它的频度从 1 变 2，从频度为 1 的链转到频度为 2 的链。

    * > **易错点**：更新分支里频度照样要加一。很容易想当然地觉得「我只是改了个值，并没有真正用它」，但按题目定义，只要 `put` 命中一次就算被使用了一次。

```java
    public void put(int key, int value) {
        Node node = kvMap.get(key);
        if (node != null) {
            // 更新分支：改 value + 频度 +1 + 搬到新链表（逻辑与 get 一致）
            node.value = value;

            DoubleLink oldList = frequencyMap.get(node.frequency);
            oldList.remove(node);
            if (oldList.isEmpty() && node.frequency == minFrequency) {
                minFrequency = node.frequency + 1;
            }

            node.frequency++;
            frequencyMap.computeIfAbsent(node.frequency, k -> new DoubleLink()).addFirst(node);
            return;
        }
        // ... 新增分支见下 ...
    }
```

### key 不存在：先腾位置再放入

* **第一件事是腾位置**

    * 判断 `kvMap.size() == capacity`，满则用 `minFrequency` 取到最小频度链表并 `removeLast()`。

    * 拿到被淘汰的节点 `victim` 后，还要按 `victim.key` 从 `kvMap` 里 `remove`，保持两张表一致。

* **第二件事是放入新节点**

    * 创建节点时把频度默认值定为 1，这是最容易漏写的一处。

    * 先 `kvMap.put(key, newNode)`，再用 `computeIfAbsent(1, ...)` 取到频度为 1 的链表并 `addFirst`；不存在则由 lambda 现场创建。

    * 新节点频度最低，所以无论原来的 `minFrequency` 被更新成了几，这里都要复位成 1。

```java
        // 新增分支：先腾位置
        if (kvMap.size() == capacity) {
            DoubleLink minList = frequencyMap.get(minFrequency);
            Node victim = minList.removeLast();      // 最小频度里最久未使用的那个
            kvMap.remove(victim.key);                // 链表删了，kvMap 也要删
        }

        // 再放新节点
        Node newNode = new Node(key, value);         // frequency 默认为 1
        kvMap.put(key, newNode);
        frequencyMap.computeIfAbsent(1, k -> new DoubleLink()).addFirst(newNode);
        minFrequency = 1;                            // 新节点频度最低，minFrequency 复位
```

## 整体复杂度结论

* **`get` 与 `put` 均满足 $O(1)$**

    * `kvMap` 直接给出节点，节点自带频度，`frequencyMap` 直接给出对应链表。

    * 链表的头部与尾部都是常量时间可取可插，整个流程「链表这一步永远不需要遍历」。

    * 之所以敢宣称 $O(1)$，靠的正是「旧链表摘节点、维护 `minFrequency`、新链表 `addFirst」这条主流程加上淘汰时只删尾节点。
