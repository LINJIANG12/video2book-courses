# 进阶数据结构和算法-269-0-1背包问题-贪心

## 固体的背包

* **0-1 背包问题（0-1 Knapsack Problem）**

    * > **定义**：n 个不可分割的物品，第 $i$ 件重 $w_i$、值 $v_i$，背包容量 $W$；每件物品至多选一次，求 $\max \sum_{i \in S} v_i$，约束 $\sum_{i \in S} w_i \le W$。

    * 每件物品只能"不拿"或"全拿"两种选择，没有中间状态。

    * 容量约束是"不超过" $W$ 而不是恰好装满，拿 9 克、8 克都合法。

* **例题的四件物品**

    | 物品 | 重量 | 价值 | 单位价值 |
    | :--- | :---: | :---: | :---: |
    | 钻石 | 1 克 | 100 万 | 100 万 / 克 |
    | 黄金（一小块） | 4 克 | 1600 | 400 / 克 |
    | 红宝石 | 8 克 | 2400 | 300 / 克 |
    | 白银 | 5 克 | 30 | 6 / 克 |

    * 背包容量 10 克，要求取走不超过 10 克的物品，求能拿到的最高价值。

* **与分数背包的对照**

    | | 分数背包 | 0-1 背包 |
    | :--- | :--- | :--- |
    | 物品形态 | 可以切分 | 固体，不可切分 |
    | 拿一件的方式 | 不拿 / 拿一部分 / 全拿 | 不拿 / 全拿 |
    | 贪心是否最优 | 是 | 否 |

    * 题目描述几乎逐字对应，差别只有"能不能切开"这一处，却足以决定算法的生死。

## 照抄分数背包的贪心

### 按单位价值一路选下去

* 策略与分数背包相同：按单位价值从高到低依次考察物品，谁的单位价值最高就先处理谁。

    ```text
    重量账本（容量 10 克）

      钻石    1 克   ──▶ 拿        余 9
      黄金    4 克   ──▶ 拿        余 5
      红宝石  8 克   ──▶ 放不下     余 5
      白银    5 克   ──▶ 拿        余 0

      总价值 = 1000000 + 1600 + 30 = 1001630
    ```

* 钻石 1 克值 100 万，不选它选谁；选完剩余容量 9 克。

* 黄金 4 克 1600（一克 400）胜过红宝石 8 克 2400（一克 300），选黄金后剩余 $10 - 1 - 4 = 5$ 克。

* 红宝石 8 克大于剩余 5 克装不下而落选，白银 5 克不超过 5 克正好塞进去，剩余 0 克。

### 最优解藏在没拿满里

* 最优组合不是"钻石 + 黄金 + 白银"，而是"钻石 + 红宝石"。

    ```text
    最优解（容量 10 克）

      钻石    1 克   ──▶ 拿        余 9
      红宝石  8 克   ──▶ 拿        余 1      只用了 9 克，不必拿满

      总价值 = 1000000 + 2400 = 1002400
    ```

* $1 + 8 = 9$ 克没超过 10 克，价值 1002400，比贪心的 1001630 高 770。

* > **结论**：0-1 背包上贪心拿不到最优解。原因不在于贪心"算错了"，而在于贪心的排序依据（单位价值）在"物品不可切分"的前提下不再是正确的比较标准。

* 分数背包里"把最后一点容量给单位价值最低的物品切开"永远不会亏；0-1 背包里为了塞下一个高价值物品而放弃的，可能恰恰是全局最优的组合。

## 不可切分带来的代码删改

* **`select` 方法**

    ```java
    public int select(int[] weight, int[] value, int totalWeight) {
        int count = weight.length;
        int maxValue = 0;
        int remaining = totalWeight;

        // 贪心策略：按单位价值从高到低依次考察物品
        for (int i = 0; i < count; i++) {
            // 拿得完：整件拿走，价值直接累加
            if (weight[i] <= remaining) {
                remaining -= weight[i];
                maxValue += value[i];
            }
            // 拿不完的分支整个删掉了：
            // 物品不能切开，所以不能按比例拿，也不能 break——
            // 直接进入下一次循环，尝试下一个物品
        }

        return maxValue;
    }
    ```

* 代码与分数背包几乎一致，改动只有一处：整个 `else` 分支删掉。

* 拿得完的情况跟以前一样，剩余容量够就把当前物品的价值直接累加到最大价值上。

* 拿不完的情况跟以前不一样，剩余容量小于当前物品重量时不能按比例切分拿走，"切开拿"那一行整个不要；`break` 也不需要，因为当前物品没法切分但还可以考察下一个物品，进入下一次循环即可。

* 跑出来的最大价值是 **1001630**，而不是最优解 **1002400**。

* > ⚠️ **易错点**：最容易漏掉的是 `break`。只删切分那一行、留着 `break`，红宝石装不下就直接退出循环，后面的白银根本不会被考察，结果比 1001630 还小，而且现象很隐蔽——代码看起来"合理"、结果只是偏小、不报错，很容易被当成数据问题。

## 贪心的适用边界

* **求最优解类问题的自检表**

    | 算法 / 问题 | 贪心能不能拿到最优解 |
    | :--- | :--- |
    | 迪克斯拉（Dijkstra） | 没有负权边时可以；一旦出现负权边就不行 |
    | 普里姆（Prim） | 可以 |
    | 克鲁斯卡尔（Kruskal） | 可以 |
    | 哈弗曼树（Huffman） | 可以 |
    | 活动选择问题 | 可以 |
    | 分数背包 | 可以 |
    | 零钱兑换问题 | 不行 |
    | 0-1 背包 | 不行 |

* 打叉的几类要换解法：迪克斯拉可以替换成**贝尔曼福特（Bellman-Ford）**，它能处理负权边；零钱兑换问题和 0-1 背包替换成**动态规划**。

* > **提示**：这张表不是知识点背诵清单，而是一张"看到题目先自检"的表——拿到求最优解的题目先扫一眼它在不在"可以"那一列；在就首选贪心，不在就别在贪心上耗时间，直接换解法。

## 动态规划：把大数组砍成两个变量

### 降维的层次

* 二维数组降成一维数组，一维数组降成零维——也就是用一个或者几个变量来记录之前子问题的计算结果。

* 斐波那契是降得最狠的例子：一维数组可以完全不要，两个变量就够。

### 为什么一维数组还能再降

* 斐波那契的递推是 $F(n) = F(n-1) + F(n-2)$，初值 $F(0) = 0$、$F(1) = 1$；用一维数组保存之前所有子问题的结果是为了避免重复计算。

* 算第 13 项只用得到前面的第 11 项和第 12 项，第 1 项到第 10 项留着没用。

* 所以只保存最近两项的计算结果就够，不需要一整个大数组把前面所有项都存下来。

### 三个变量往前挪一格

* `A` 代表前两项的值，初始值 0；`B` 代表前一项的值，初始值 1；`C` 装当前项的值，在循环内定义成临时变量 `B + A`——前一项加上前两项。

* 循环本身不用变，每轮结束做一次更新：`A` 往前移一格取上次的 `B`，`B` 往前移一格取上次的 `C`，`C` 则变成下一轮要计算的当前项。

* `n == 0` 返回 0、`n == 1` 返回 1 这两段判断是边界，与降维无关，要保留。

    ```java
    public int fib(int n) {
        if (n == 0) return 0;
        if (n == 1) return 1;

        int a = 0;  // 前两项的值
        int b = 1;  // 前一项的值

        for (int i = 2; i <= n; i++) {
            int c = a + b;  // 当前项 = 前一项 + 前两项
            a = b;          // 两个变量整体往前挪一格
            b = c;
        }

        return b;
    }
    ```

    | 时刻 | `a` | `b` | `c` |
    | :--- | :---: | :---: | :---: |
    | 循环开始前 | $F(0)=0$ | $F(1)=1$ | — |
    | 第 $i$ 轮开头 | $F(i-2)$ | $F(i-1)$ | 待算 |
    | 本轮算完后 | — | — | $F(i)$ |
    | 更新之后 | $F(i-1)$ | $F(i)$ | — |

* 最后返回 `b`：`C` 是循环内的局部变量出不了循环，但最后一次循环结束时 `b` 恰好就等于 `C`。

* 求斐波那契第 13 项输出 **233**，空间从原本的 $O(n)$ 降到 $O(1)$。

* > ⚠️ **易错点**：`a = b; b = c;` 的顺序不能反。必须先把旧的 `b` 赋给 `a`，再把 `c` 赋给 `b`；反写成 `b = c; a = b;` 时 `a` 拿到的是新 `b`，两个变量都被污染成同一个值，下一轮直接算错。

## Bellman-Ford：最短路径也是动态规划

### 算法身份与解题套路

* 贝尔曼（Bellman）就是提出了 Dynamic programming（动态规划）的人。

* 它是迪克斯拉的替换方案，能处理负权边。

* 动态规划解题套路固定：先找一个递推公式，然后把当前问题分解成子问题、分阶段求解，求解过程中把子问题的解缓存到一维或二维数组里，避免重复计算。

### 先看它能不能拆成子问题

* 以 $V_1$ 为起点求 $V_1 \to V_4$ 的最短距离：

    ```text
             7             15
       V1 ────────▶ V2 ───────────▶ V4
        │                            ▲
        │ 9                          │ 11
        ▼                            │
       V3 ───────────────────────────┘

       V1 → V3 → V4 ： 9 + 11 = 20    ← 更短
       V1 → V2 → V4 ： 7 + 15 = 22
    ```

* 要到达 $V_4$，一条路线从 $V_3$ 来，另一条从 $V_2$ 来。

* 于是先求 $V_1 \to V_2$ 的最短路径，再求 $V_1 \to V_3$ 的最短路径，再在这两个结果基础上比一比从 $V_3$ 到 $V_4$ 更短还是从 $V_2$ 到 $V_4$ 更短——整体问题被拆成两个可分阶段求解的子问题，套得上动态规划。

### 递推公式怎么读

* 用 $F(V)$ 表示"从起点出发到达顶点 $V$ 的最短距离"，$V$ 是图中的任意顶点。

* 初始值分两种：$V$ 就是起点自己时距离已知为 0；$V$ 不是起点时距离未知，设成无穷大。

$$
F(to) = \min\Big(\, F(to),\ \min_{from \to to}\big[\,F(from) + weight(from, to)\,\big] \Big)
$$

* `from` 是从哪来、从哪个顶点来，`to` 是到达的那个顶点，外层的 `min` 是在两个值里挑一个更小的。

* 一句话概括：在 `F(to)` 的旧值基础上，跟它所有 `from` 的 `F(from) + weight` 逐个对比，只要找到更小的就用更小的值更新 `F(to)`。

* 套到例图上求 $F(V_4)$：旧值一开始是无穷大；先试 $V_3$，$F(V_3) = 9$ 加上 $V_3 \to V_4$ 的距离 11 得 20，把 $F(V_4)$ 更新成 20；再试 $V_2$，$F(V_2) = 7$ 加上 15 得 22，跟 20 求最小还是 20 赢，$V_1 \to V_4$ 的最短距离定下来是 **20**。

### 代码落下来

* 边有三个属性：`from` 顶点、`to` 顶点、从 `from` 到达 `to` 的距离 `weight`。

* 一维数组 `dp` 缓存子问题的解，索引对应顶点编号：`dp[1]` 代表 $V_1$ 的距离，`dp[2]` 代表从起点到 $V_2$ 的最短距离。

* 一共 6 个顶点但下标 0 不用；因为编号从 1 开始，为让编号与索引一一对应，数组长度定为 7。

    ```java
    public class BellmanFord {

        // 边：from 顶点、to 顶点、从 from 到 to 的距离
        static class Edge {
            int from;
            int to;
            int weight;
        }

        public static void main(String[] args) {
            int[] dp = new int[7];

            // 初始化：起点距离是 0，其余顶点都还不可达
            dp[1] = 0;
            for (int i = 2; i < dp.length; i++) {
                dp[i] = Integer.MAX_VALUE;
            }
            print(dp);

            // 为了演示递推公式，只留两条通向 V4 的边，其余的先注释掉
            List<Edge> edges = new ArrayList<>();
            edges.add(new Edge(3, 4, 11));
            edges.add(new Edge(2, 4, 15));
            // edges.add(new Edge(6, 5, 9));
            // ...

            // 套用递推公式更新最短距离
            for (Edge edge : edges) {
                int from = edge.from;
                int to = edge.to;
                dp[to] = Math.min(dp[to], dp[from] + edge.weight);
            }

            print(dp);
        }

        private static void print(int[] dp) {
            for (int v = 0; v < dp.length; v++) {
                if (dp[v] == Integer.MAX_VALUE) {
                    System.out.println("V" + v + " -> ∞");   // 整数最大值即无穷大
                } else {
                    System.out.println("V" + v + " -> " + dp[v]);
                }
            }
        }
    }
    ```

* 用 `Integer.MAX_VALUE` 代表无穷大，`print` 方法把这个整数最大值特殊处理，打印成无穷大的符号，看起来更直观。

* 第一次打印就能看到初始状态：下标 0 相当于没用；起点是索引 1，距离是 0；索引 2 到索引 6 的距离一开始全都是无穷大。

* 顶点编号和数组索引一一对应，找 `to` 的位置直接 `dp[to]`；比大小用 `Math.min`，第一个参数是 `dp[to]`（它上次的最短距离），第二个参数是 `dp[from] + edge.weight`。

### 无穷大加了个 11，答案变成了负数

* 初次跑出来 `V_4` 确实被更新了，但被更新成了一个**负数**。

* 因为刚开始不管是 `from` 还是 `to` 都是 `Integer.MAX_VALUE`，$2147483647 + 11 = -2147483638$ 直接超过整数表示范围，从正数变成负数，一旦写进 `dp[4]` 后面的结果全被带偏。

* > ⚠️ **易错点**：这是 Java 等所有定长整型语言用 `Integer.MAX_VALUE` 模拟无穷大时的经典陷阱。数学上"无穷大加任何数还是无穷大"，但机器上无穷大只是一个具体的最大值，加法会溢出——语义上说得通的式子，落到代码里就是一次整数溢出。

* 遇到最大值就不应该执行这个更新：无穷大代表"未知"，连 $V_3$ 的最短距离都还不知道，在未知的基础上再加 11，结果还是未知。

    ```java
    for (Edge edge : edges) {
        int from = edge.from;
        int to = edge.to;
        // from 还没被访问过（dp[from] 还是无穷大），跳过这次更新
        if (dp[from] == Integer.MAX_VALUE) {
            continue;
        }
        dp[to] = Math.min(dp[to], dp[from] + edge.weight);
    }
    ```

* 加了这个判断后 $V_4$ 保持无穷大，不再被错误更新成负数；它现在还是无穷大，是因为通向 $V_3$ 和 $V_2$ 的边还都注释着。

* 有了这个判断，真正能推进的那些边才生效，多轮松弛才能把最短路径一层层"推"到远处。

* Bellman-Ford 的完整实现，就是把这个"一轮松弛"重复足够多次，让最短路径收敛；这一节的实现只是把 DP 数组、初始值、递推公式和一个不可省略的判断搭起来。
