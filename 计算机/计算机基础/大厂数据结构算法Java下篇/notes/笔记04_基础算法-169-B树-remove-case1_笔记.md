# 基础算法-169-B树-remove-case1

## 叶子节点的删除分支

* **没找到要删的 k**

    * > **定义**：查找循环在叶子节点上没有命中，整个删除到此中断。
    * 这一分支的分支体只有一行 return。
    * 必须直接 return，不能让它继续往下走。
    * 继续往下走就可能走进调整平衡的那个方法，给一个什么都没干的节点凭空调一次 balance，纯属自己找麻烦。

* **找到了就删掉**

    * > **定义**：调用节点的 removeKey 工具方法删掉索引 i 处的 k，删完不 return，继续往下走。
    * 索引 i 就是查找循环退出时的那个 i，找到的时候它天然就是待删除 k 的下标。
    * 删完不许 return，因为这个节点的 k 数目有可能低于下限，接下来还要再做一个判断，一旦小于下限就得做平衡调整。

    > **易错点**：这两个分支长得几乎一模一样，一个 return 一个不 return，差别就在这——case 1 中断，case 2 继续。

## 非叶子节点未命中时的下沉

* **往第 i 号孩子递归**

    * > **定义**：非叶子节点上没找到，就把删除请求原样下传给查找循环退出时的那个 i 号孩子。
    * 落到第几个孩子完全由退出时的 i 决定，要删的 k 保持不变。
    * 递归调用写作 `doRemove(children[i], i, parent)`。
    * 查删 2：从根节点开始，退出循环时 i 是 0，因为第 0 个 k 比要删的 2 大，所以到 0 号孩子继续查找并删除。
    * 查删 6：第一次循环时 3 小于 6 不退出，第二次循环时 i 已经等于 k 的数目、超出了有效范围，循环退出时 i 是 1，于是到 1 号孩子继续找 6。

    > **提示**：往下传的这个 i 是「孩子编号」，也就是「我是第几个孩子」，不是「我在自己 keys 里的下标」；子节点自己算出来的 i 才是它自己的位置。

## 非叶子节点命中时的后继替换

* **为什么不能直接删**

    * > **定义**：非叶子节点上找到待删 k 时，不能直接删掉，必须先把它替换成后继的 k。
    * 这是删除里最复杂的一种情形。

### 后继 k 的取法

* **从右邻孩子一路取 0 号孩子**

    * 起点是当前待删除 k 的右邻孩子，也就是索引加一处的那个孩子 `children[i+1]`，里面的 k 肯定都比待删 k 大。
    * 只要它还不是叶子节点，就一直取它的 0 号孩子往左走，也就是一直找最左侧的孩子。
    * 走到叶子节点为止，说明后继 k 就在这个节点里，而它里面可能有多个 k，最左侧的那个——第 0 个 k——就是后继 k。
    * 写代码时先定一个 s 表示后继 k 所在的节点，起点是 `children[i+1]`。

    ```java
    while (!s.isLeaf()) {
        s = s.children[0];
    }
    Node successor = s.keys[0];
    ```

    * 循环退出时 s 就是后继 k 所在的那个叶子节点，它的最左侧 k 就是后继 k。
    * 这对应二叉搜索树里「从右孩子出发一路向左走，走到头就是后继节点」的后继找法，只是把「一路向左」换成了「一路取 0 号孩子」。

### 替换三步走

* **替换并转化为删除后继**

    * 第一步，找到后继 k sk。
    * 第二步，把当前节点 `keys[i]` 处的待删除 k 替换成 sk。
    * 第三步，把「删除 k」转化成「删除 sk」——递归调用 doRemove，起点是刚才那个 `children[i+1]`，但这次删的 k 是 sk，不是原来的 k 了。
    * 九被十替换上去，十自己就该被删掉了，所以最后要删的是十，三步做完这一情形就结束了。

## 余额不足的平衡判定

* **触发条件与修法选择**

    * > **定义**：找不到直接 return 之外，剩下三种情形执行完，都有可能造成当前节点的 k 数目变少。
    * 变少以后如果小于下限，就要对它进行一个重新的平衡调整。
    * 以 t = 3 的树为例，下限是 2；平衡的目的只有一个——让这个节点的 k 数目回到下限以上。
    * 非根节点分成右旋、左旋、合并三种修法，根节点的情况单独拎出来做特殊处理。

    ```text
    删除之后，x 的 k 数目 < 下限
                │
                ├─ x 是根 ──────────────────▶  case 6：用 0 号孩子替换旧根，然后 return
                │
                └─ x 不是根
                     │
                     ├─ 左边兄弟存在，且它的 k 数目 > 下限 ──▶  case 5-1：右旋，然后 return
                     │
                     ├─ 右兄弟存在，且它的 k 数目 > 下限   ──▶  case 5-2：左旋，然后 return
                     │
                     └─ 两边都没有富裕的 k              ──▶  case 5-3：合并（向左合并）
    ```

### 根节点的特殊处理

* **一个 k 都不剩就换人当根**

    * 那次合并之后根节点没有 k 了，这时候原来的根就没必要留着了。
    * 用它的 0 号孩子替换掉这个旧的根，根节点就会有一次替换的操作。
    * 整条判定链的收尾是：删除后 k 数目小于下限，左边有兄弟且富裕就右旋；右边兄弟存在且富裕就左旋；左右都没有富裕的 k 就合并；合并之后根节点 k 数目变成零，就用它的 0 号孩子替换掉旧的根节点。

## 右旋

* **适用条件**

    * > **定义**：右边孩子缺 k、左边的兄弟存在且它的 k 数目大于下限时，走一次右旋。
    * 必须是严格大于下限，等于下限不行——借走一个它自己就不够了。
    * 不能把兄弟最大的 k 直接搬过来：它会小于父节点的 k，而右边的 key 都必须大于父节点。

    ```text
       (1) 删前          (2) 删掉 5     (3) 右旋之后
         [ 4 ]                [ 4 ]          [ 3 ]
       /       \            /       \      /       \
    [1,2,3]  [5,7]      [1,2,3]    [7]   [1,2]    [4,7]
     3个k                3个k              2个k      2个k
    ```

    * 例子：t 等于 3、下限是 2，左右两个节点的 k 数目分别是 3 和 2 都没有低于下限，删掉 5 后被调整节点的 k 数目太少。
    * 转弯的办法是先把父节点的 4 旋转下来，再把兄弟的 3 旋转上去。
    * 右旋完被调整节点重新有了 2 个 k，兄弟那边也还剩 2 个 k，整棵树又恢复平衡。

* **旋转下来的是前驱 k**

    * 父节点里可能有多个 k，要旋转下来的是被调整节点的前驱 k，也就是比它小、而且离它最近的那个。
    * 被调整节点的索引是 i，则它的前驱就在父节点 `keys[i-1]` 这个位置：被调整节点里的所有 k 都大于它，左边孩子里的所有 k 都小于它，所以它恰好就是最近的那个。
    * 旋转下来之后它比被调整节点里所有 k 都小，所以要排到索引 0 的位置。
    * 比方说被调整节点的索引是 2，父节点里索引 1 处的那个 k 才是它的前驱；把 11 或 4 旋转下来，虽然 1、2、4、5、6、7、8 都比它们小，但都不是最近的，整棵树的升序就被破坏了。

* **右旋做的三件事**

    * 把父节点中前驱的 k 旋转下来，插入到被调整节点的最左侧（索引 0）。
    * 如果左兄弟不是叶子节点，把它最右侧的孩子移除，插入给被调整节点，作为被调整节点最左边的孩子。
    * 把左兄弟中最大的 k 旋转上去，覆盖掉父节点中刚才旋转下去的那个位置。

    ```java
    // ① 父节点中前驱的 k 旋转下来，插到 x 的索引 0
    x.insertKey(parent.keys[i - 1], 0);

    // ② 左兄弟有孩子的话，最右孩子过继给 x，成为 x 最左边的孩子
    if (!left.isLeaf()) {
        x.insertChild(left.removeRightmostChild(), 0);
    }

    // ③ 左兄弟最大的 k 旋转上去，覆盖父节点 i-1 处的位置
    parent.keys[i - 1] = left.removeRightmostKey();
    ```

    * 左兄弟原本 3 个 k 配 0、1、2、3 四个孩子；最大的 k 旋转上去后只剩 2 个 k，配 0、1、2 三个孩子就够了，多出来的最右侧那个孩子就该过继给被调整节点。
    * 第 ③ 行取的是左兄弟最右边的 k，把它删掉，放到父节点里 i-1 处，覆盖掉刚才被旋转下去的那个 k 所在的位置。

## 左旋

* **适用条件**

    * > **定义**：左边没有兄弟、右边的兄弟存在且它的 k 数目大于下限时，走一次左旋。
    * 例子：删掉 1 之后这个节点不平衡、k 数目小于 2，它没有左边的兄弟但有右边的兄弟，而且右边兄弟就算借走一个自己也不少于 2。
    * 借的方式是来一次左旋：把父节点的 3 旋转下来，把兄弟那边的 4 旋转上去。

    ```text
       (1) 删前          (2) 删掉 1     (3) 左旋之后
         [ 3 ]                [ 3 ]          [ 4 ]
       /       \            /       \      /       \
    [1,2]  [4,5,6]      [ 2 ]  [4,5,6] [2,3]    [5,6]
     2个k                 2个k              2个k    2个k
    ```

    * 左旋是右旋的镜像。
    * 另一个场景是删掉 5 之后该节点不平衡，左边不够借、右边够借，所以来一次左旋。

* **旋转下来的是后继 k**

    * 后继 k 在父节点里的索引正好就是 i，不是 i+1。
    * 依据是：被调整节点 `children[i]` 里的所有 k 都小于父节点的 `keys[i]`，而右边孩子里的所有 k 都大于它。
    * 比方说被调整节点的索引是 1，父节点索引 1 处的 k 就是它的后继。
    * 旋转下来的这个后继 k 比被调整节点里所有 k 都大，所以要插到最右侧，索引就是 `x.keys.length`。

* **左旋做的三件事**

    * 把父节点中后继的 k 旋转下来，插入到被调整节点的最右侧。
    * 如果右兄弟不是叶子节点，把它最左侧的孩子移除，插入给被调整节点，作为被调整节点最右边的孩子。
    * 把右兄弟中最小的 k 旋转上去，覆盖掉父节点中刚才那个位置。

    ```java
    // ① 父节点中后继的 k 旋转下来，插到 x 的最右侧
    x.insertKey(parent.keys[i], x.keys.length);

    // ② 右兄弟有孩子的话，最左孩子过继给 x，成为 x 最右边的孩子
    if (!right.isLeaf()) {
        x.insertChild(right.removeLeftmostChild(), x.keys.length);
    }

    // ③ 右兄弟最小的 k 旋转上去，覆盖父节点 i 处的位置
    parent.keys[i] = right.removeLeftmostKey();
    ```

    > **易错点**：第 ② 行的插入位置是 `x.keys.length` 而不是 `x.keys.length - 1`，因为孩子最右侧的索引比 k 最右侧的索引要多一；这一步图上没法体现，只有代码能说明。

## 合并

* **什么情况下才合并**

    * > **定义**：左边借走一个它自己就不够、右边根本没有兄弟，两边都借不到时，旋转这条路走不通，只能合并。
    * 合并的目的是让节点的数目减少一个，把这些多出来的键值放到一起去，这样存活的这个节点的 k 数目就满足要求了。
    * 统一采用一个向左合并的策略：位于右侧的这个节点不要了，把它从父节点那里删掉，然后把它和父节点的一些 k 都合并到左侧那个节点上去。

    ```text
       (1) 删前          (2) 删掉 5         (3) 向左合并之后
         [ 4 ]                [ 4 ]                    [1,2,4,7]
       /       \            /       \                  /
    [1,2]    [5,7]      [1,2]    [7]             （节点少了一个）
     2个k     删掉        2个k     1 < 2
              5 之后              借不到
    ```

    * 顺序有讲究：先把父节点的 4 追加到左侧节点的最右边，再把这个节点自己的 5 追加过去，这样合并出来的 k 才是升序的。
    * 合并完成以后 5 所在的那个节点就没用了，节点总数少了 1，存活下来的那个节点 k 数目就够了。
    * 还有一个例子也一样：删掉 2 之后左边没得借、右边也没有兄弟，还是向左合并，右边那个节点将来删掉，把父节点的一个 k 追加到左侧节点里去，再把它自己的两个 k 追加过去。

### 向左兄弟合并

* **前提、索引与顺序**

    * > **定义**：有左兄弟时，被调整节点将来就不要了，所以从父节点那里把它删除掉。
    * 被调整节点的索引是 i，待移过去的那个 k 的索引是 i-1，所以从父节点中 i-1 处移除 k，插入位置就是左兄弟自己的 key number，也就是它的最右侧。
    * 顺序不能颠倒：先合并父节点的 4，再合并自己的 7，才能是 1、2、4、7 这样一个升序；先塞自己的 7 再塞 4，中间就断开了。

    ```java
    // ① 从父节点删掉被调整节点自己
    parent.removeChild(i);

    // ② 父节点的一个 k 合并到左兄弟（先父节点的 k，再自己的 k，升序才对）
    left.insertKey(parent.removeKey(i - 1), left.keys.length);

    // ③ 被调整节点剩下的所有 k 和所有孩子，都移到左兄弟
    x.moveToTarget(left);
    ```

    * `moveToTarget` 把当前节点所有的 key 和 child 都复制到 target，这里的 target 就是左兄弟 left。
    * 把被调整节点 7 它的 k 合并过去以后，左兄弟就变成了 1、2、4、7。

### 向自己合并

* **前提与索引**

    * > **定义**：没有左兄弟时反过来，把它的右兄弟以及父节点的一个 k 合并到它自己这边，它自己就是最终合并的目标。
    * 右兄弟的索引是 i+1，先把它从父节点这里移除掉。
    * 插入位置是被调整节点自己的最右侧，即 `x.keys.length`。
    * 合完就是 1、4、5、7 这样一个升序的 k。

    ```java
    // ① 从父节点移除右兄弟
    parent.removeChild(i + 1);

    // ② 父节点的一个 k 合并到被调整节点自己
    x.insertKey(parent.removeKey(i), x.keys.length);

    // ③ 右兄弟所有的 k 和孩子都合并过来
    right.moveToTarget(x);
    ```

    > **易错点**：这一回父节点移除的 k 索引是 i，不是 i-1。因为此时被调整节点自己是父节点的 0 号孩子、自己没有 k 了，要往自己这边合并，所以取的是紧贴着自己的那个分隔 k。

## balance 的骨架

* **三个参数**

    * 第一个参数是被调整的节点，即哪个节点要进行调整。
    * 第二个参数是这个节点所在的索引，也就是它是第几个孩子；这个参数本来应该叫 index，图省事简称成 i。
    * 第三个参数是父节点 parent，讨论旋转和合并的时候都用得到它。

    ```java
    private void balance(Node x, int i, Node parent) {
        if (x == root) {
            // case 6：根节点特殊处理
            return;
        }

        Node left  = parent.childLeftSibling(i);
        Node right = parent.childRightSibling(i);

        if (left != null && left.keys.length > lower) {
            // case 5-1：右旋
            return;
        }
        if (right != null && right.keys.length > lower) {
            // case 5-2：左旋
            return;
        }

        // case 5-3：合并
    }
    ```

    * 根节点先拦一道：被调整节点就是根就走 case 6 的特殊处理，处理完直接 return，不用再走下面左旋、右旋、合并这些逻辑。
    * 左右兄弟通过父节点加上被调整节点的索引 i 拿到，用节点类里现成的 childLeftSibling 和 childRightSibling 两个方法直接调用就行。
    * 判断条件里的「大于」是硬要求：左边兄弟不为空且 k 数目大于下限、右边同理；右旋完就平衡了直接 return，左旋完也一样，只有左右都不够借才落到最后的合并分支。
