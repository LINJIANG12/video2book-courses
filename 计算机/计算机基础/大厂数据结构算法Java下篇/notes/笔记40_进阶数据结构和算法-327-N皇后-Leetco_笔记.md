# 进阶数据结构和算法-327-N皇后-Leetco

## N皇后问题

* **N皇后（N-Queens，LeetCode 51）**

    * > **定义**：给一张 N×N 棋盘摆放 N 个皇后，使任意两个皇后彼此不能相互攻击（不同行、不同列、不同斜线），问一共有多少种摆法。

    * 皇后是国际象棋里的一种棋子，能攻击与它同行、同列或同一条斜线上的其他棋子。

    * 一个格子放了皇后后，它的同行、同列、两条斜线上的格子都不能再放皇后。

    * 必须在整个棋盘上摆满 N 个皇后，才算找到一种解。

    * 搜索规模：8 个皇后的排列共 $8^8$ 种，即 1600 多万种，要从中捞出皇后互不攻击的摆法。

    * 历史上著名的数学家高斯认为八皇后有 76 种方案，实际解是 92 种。

    * 今天用计算机求解非常轻松，八皇后、九皇后都能迅速求解，约 20 行代码即可完成。

## 回溯求解流程

### 手工推演四皇后

* **从第一个格子开始试放**

    * 在 4×4 棋盘里，从第一个格子放入第一个皇后。

    * 随即把它的同行、同列以及同一斜线上的格子标成冲突色，后续皇后只能放进未标冲突的空格。

    ```text
             j=0   j=1   j=2   j=3
      i=0      Q     x     x     x
      i=1      x     x     .     .
      i=2      x     .     x     .
      i=3      x     .     .     x

      x = 与已放皇后冲突，不能放
      . = 空闲，可以放
    ```

* **放错了就撤销，逐层回退**

    * 第二个皇后放到第二行某个格子后，第三行所有格子都冲突，皇后数量凑不够，该方案作废。

    * 换第二行的另一个格子，第三行能放下第三个皇后，但它一放进去第四行就全部冲突，该方案同样废弃。

    * 撤销顺序是从深到浅：先撤销第三个皇后，再撤销第二行的皇后，因为这一行两个格子都试过都不行。

    * 第二行走不通时连第一行的皇后也一并撤销，然后改放第一行的第二列。

    * 第一行第二列起步时可以排出一个解：第一行第二列、第二行某列、第三行某列、第四行某列。

### 找到解之后继续枚举

* **一个解不是终点**

    * 找到一个解之后事情没完，把填满的四个皇后全部撤销，再尝试第一行第三列放入皇后。

    * 这次又能依次放下第二、第三、四个皇后，于是得到第二个解。

    * 继续撤销后尝试第一行第四列起步，第二个皇后换了两个位置后第三个皇后都放不下。

    * 第一行的四列都尝试过，再撤销就没了，四皇后问题到此共找到 2 个解。

* **循环骨架的结论**

    * > **结论**：N皇后就是「一行放一个，行内枚举列，冲突就跳过，放不下去就撤销」的循环。

    * 每一层负责一行的放置决策，内层在所有列上做选择。

    * 找到一个解后必须回溯到初始状态继续枚举，才能拿到全部解而不是第一个解。

## 冲突状态的记录

### 同一行与同一列

* **同一行不用记**

    * > **定义**：同一行的冲突不需要记录。

    * 原因：往某行放入皇后后，下一次尝试直接到下一行去放皇后，当前行根本不用再试。

    * 既然同行不会被再次访问，记录它就是多余的动作。

* **同一列要记，用布尔数组 cols**

    * > **定义**：布尔数组 `cols` 专门记录列冲突，数组长度等于列数 N。

    * 4×4 棋盘有四列，所以 `cols` 大小是 4，初始值全是 false。

    * 往第零列放入皇后后，把索引 0 位置的 false 改成 true。

    * 之后每次放皇后前先查这个数组，第零列是 true 就说明该列已有冲突，不能再放。

### 左斜线与右斜线

* **左斜线：编号等于 i + j**

    * N×N 棋盘共有 $2N - 1$ 条左斜线：4×4 是 $2\times 4 - 1 = 7$ 条，8×8 是 $2\times 8 - 1 = 15$ 条。

    * 把每个单元格的行坐标 i 与列坐标 j 相加，$i + j$ 相同的单元格属于同一条左斜线。

    ```text
              左斜线编号 = i + j

             j=0   j=1   j=2   j=3
      i=0      0     1     2     3
      i=1      1     2     3     4
      i=2      2     3     4     5
      i=3      3     4     5     6
    ```

    * 例如第二行第一列 $2 + 1 = 3$，第零行第三列 $0 + 3 = 3$，两者同属斜线 3。

    * 编号从 0 到 $2N - 2$，正好 $2N - 1$ 条。

    * 布尔数组 `diag1` 长度取 $2N - 1$，`diag1[i + j]` 为 true 表示该条左斜线有冲突，false 表示没有冲突。

* **右斜线：编号等于 (N-1) - (i - j)**

    * 右斜线同样是 $2N - 1$ 条，4×4 棋盘也是 $2\times 4 - 1 = 7$ 条。

    * $i - j$ 相同的单元格属于同一条右斜线，一共有七个不同的取值对应那七条斜线。

    ```text
              i - j 的原始值（存在负数）

             j=0   j=1   j=2   j=3
      i=0      0    -1    -2    -3
      i=1      1     0    -1    -2
      i=2      2     1     0    -1
      i=3      3     2     1     0
    ```

    * $i - j$ 会取到负数，负数没法直接对应数组下标，用 $N - 1$ 减去它把负数整体搬走。

    ```text
              右斜线编号 = (N - 1) - (i - j) = 3 - i + j

             j=0   j=1   j=2   j=3
      i=0      3     4     5     6
      i=1      2     3     4     5
      i=2      1     2     3     4
      i=3      0     1     2     3
    ```

    * 平移后编号落在 0 到 $2N - 2$ 区间，N = 4 时是 0 到 6 共七条。

    * 布尔数组 `diag2` 长度取 $2N - 1$，下标表达式为 $(N - 1)$ 再减去 $i - j$ 的差。

    * > **易错点**：`i - j` 会取到负数，直接拿去当数组下标会越界。一定要加上 `(N-1)` 这个平移量，把它整体搬到 0 ~ 2N-2 这个区间里。

    * 至此用三个数组就覆盖了全部冲突：`cols` 记列、`diag1` 记左斜线、`diag2` 记右斜线。

## 求解代码骨架

### 棋盘与冲突数组

* **二维字符数组 table**

    * 用一个二维字符数组代表棋盘，名字叫 `table`，维度不写死，用 N 表达（本例 N = 4，数组是 N 行 N 列）。

    * 它记录的是皇后的状态，也就是棋盘上哪个位置、哪个单元格放置了皇后。

    * 字符约定：单元格没放皇后放一个字符点 `.`，放了皇后改成一个 `Q`。

    * 每行用 `Arrays.fill(table[i], '.')` 完成初始化。

* **三个冲突数组的尺寸**

    * `cols` 长度对应 N。

    * `diag1` 与 `diag2` 长度都对应 $2N - 1$。

### dfs 的关键动作

* **递归终止条件**

    * 当 `i == n` 时，说明第零、第一、第二、第三行都处理完了，没有更多皇后要填，相当于找到一个解。

    * 此时打印出棋盘然后直接 `return`，不再继续往下递归。

* **列坐标来自列循环**

    * `dfs` 传进来的 `i` 代表的是每一行，每进入一行都要在不同的列上尝试放入皇后。

    * 所以方法内还必须有一个针对列的循环，依次尝试第零列到第 N−1 列。

* **冲突检查与剪枝**

    * 冲突检查必须放在放入之前：`cols[j] || diag1[i + j] || diag2[n - 1 - i + j]` 任一为 true 就 `continue`。

    * 有冲突就不必执行放入皇后的操作，也不必执行后续递归，直接进入下一轮循环尝试下一列。

    * 避免这次不必要的递归，在回溯思想里形象地称为剪枝。

* **放入、递归与回溯**

    * 无冲突时把 `table[i][j]` 置为 `'Q'`，同时把三个对应的冲突标记置为 true。

    * 往下一行放皇后，剩余参数原封不动传过去：`dfs(i + 1, n, table, cols, diag1, diag2)`。

    * 回溯那几行是全篇最关键的：不管递归成功还是失败，都要把状态恢复成递归之前的样子。

    * 具体是把 `table[i][j]` 改回 `'.'`，并把递归调用之前设的那些冲突标记改回 false。

    * 三条置 true 的赋值可以合并成一条，把 true 赋给三个数组的相应位置；撤销的三条同理。

* **完整代码**

    ```java
    import java.util.Arrays;

    public class NQueens {

        /**
         * i     —— 当前处理第几行
         * n     —— 棋盘维度
         * table —— 棋盘本身，记录皇后放在哪儿
         * cols  —— 列冲突
         * diag1 —— 左斜线冲突，编号 i + j
         * diag2 —— 右斜线冲突，编号 (n - 1) - (i - j)
         */
        private static void dfs(int i, int n, char[][] table,
                                boolean[] cols, boolean[] diag1, boolean[] diag2) {

            // 递归结束条件：所有行都填满了，说明找到一个解
            if (i == n) {
                System.out.println("--------- 找到一个解 ---------");
                for (char[] row : table) {
                    System.out.println(new String(row));
                }
                return;   // 找到一个解就直接返回，不再往下递归
            }

            // 每一行进来，都要在不同的列上尝试放入皇后
            for (int j = 0; j < n; j++) {

                // 冲突检查：列、左斜线、右斜线，任意一条冲突就跳过这一列
                if (cols[j] || diag1[i + j] || diag2[n - 1 - i + j]) {
                    continue;
                }

                // 放入皇后，并记录它带来的三类冲突
                table[i][j] = 'Q';
                cols[j] = true;
                diag1[i + j] = true;
                diag2[n - 1 - i + j] = true;

                // 往下一行放皇后，剩余参数原封不动传过去
                dfs(i + 1, n, table, cols, diag1, diag2);

                // 回溯：不管递归成功还是失败，都把状态恢复成递归之前的样子
                table[i][j] = '.';
                cols[j] = false;
                diag1[i + j] = false;
                diag2[n - 1 - i + j] = false;
            }
        }

        public static void main(String[] args) {
            int n = 4;

            char[][] table = new char[n][n];
            boolean[] cols = new boolean[n];
            boolean[] diag1 = new boolean[2 * n - 1];
            boolean[] diag2 = new boolean[2 * n - 1];

            for (int i = 0; i < n; i++) {
                Arrays.fill(table[i], '.');
            }

            dfs(0, n, table, cols, diag1, diag2);
        }
    }
    ```

    * > **提示**：调用 `dfs` 时第一个参数从第零行开始，也就是把 0 传进去，剩下的参数照原样传过去就行。

    * > **提示**：变量名不必追求特别好的可读性，只要能分清哪个数组记录列冲突、哪个记录左斜线冲突、哪个记录右斜线冲突就够了。

## 求解要点与运行结果

### 两个不能丢的要点

* **用四个数组记录状态**

    * 二维字符数组 `table` 记录皇后状态，也就是棋盘上哪个位置、哪个单元格放置了皇后。

    * 另外三个数组专门记录冲突的状态。

* **不到 20 行的递归方法**

    * 这个方法是解题主体，总共用了不到 20 行代码就解决了 N皇后问题。

    * 方法以行为单位尝试放置皇后，每次都往第 i 行放入，递归时也往下一行。

    * 行内还有一个针对列的循环，负责本行候选位置的枚举。

    * 确定第 i 行第 j 列后先做冲突检查，冲突就直接跳过这次递归进入下一轮循环去尝试下一列。

    * 没有冲突就往这个位置放入皇后并记录它的冲突位置，然后递归处理下一行。

    * 甭管这次递归是成功了还是失败了、也没管有没有找到解，退出递归后都要取消皇后并把冲突标记改成 false，恢复成递归之前的状态。

    * 回溯思想的要义：**在递归结束后要把状态进行恢复**。

### 四皇后与八皇后

* **四皇后得到两个解**

    * 找到解之后会在打印语句中间加一条分隔线，先打分隔线再打印具体解的内容。

    * 枚举列的顺序是从第零列往右走的，所以先打出来的解行列位置是 `1,3,0,2`，第二个是 `2,0,3,1`。

    * 换算成从 1 开始的说法就是 2413 和 3142，与手工推演的图形界面上看到的解对得上，两个都是对的。

* **八皇后得到 92 个解**

    * 只要把 N 改成八即可，它会打印出 92 个解。

    * 输出内容比较多，可以自己下去跑一遍验证。

    * > **易错点**：输出顺序不重要，不要因为先打出来的解和自己手推的先后顺序不同就判定代码错了。

## 解数独（LeetCode 37）

### 目标与三条规则

* **解数独（Sudoku Solver）**

    * > **定义**：给一张 9×9 且部分数字已填好的表格，把 1 到 9 填入空白位置，使每行、每列、每个 3×3 九宫格内 1 到 9 各出现一次。

    * 它是一种填字游戏，题目保证唯一解，不会出现无解或者多个解。

* **三条规则**

    * 规则一（行内不重复）：每一行里 1 到 9 只能出现一次；某空格所在行已有 1、6、7、9、5、8，则只能填 2、3、4。

    * 规则二（列内不重复）：每一列里 1 到 9 也只能出现一次；某空格所在列已有 1、7、5、6、9、8、4，剩下两个空格只能填 2 或 3。

    * 规则三（九宫格内不重复）：整个 9×9 表格再划分成九个小的 3×3 九宫格，同一个九宫格内 1 到 9 也只能出现一次；第一个九宫格里 3 到 9 已填好，只能填 1 或 2。

    ```text
            行内不重复（规则一）
            ↓
        +-------+-------+-------+
        | . . . | . . . | . . . |
        | . . . | . . . | . . . |
        | . . . | . . . | . . . |   ↑
        +-------+-------+-------+   |
        | . . . | . . . | . . . |   |
        | . . . | . . . | . . . |   九宫格内不重复（规则三）
        | . . . | . . . | . . . |   |
        +-------+-------+-------+
        | . . . | . . . | . . . |
        | . . . | . . . | . . . |
        | . . . | . . . | . . . |
        +-------+-------+-------+

            列内不重复（规则二）
    ```

### 逐格尝试与回溯

* **每个空格逐一尝试 1 到 9**

    * 真实数独会留比较多的空格，通常好几个小时都不一定能求解出来，所以演示时把大部分空格填好、只留少量空格。

    * 遍历每个未填入数字的空格，把 1 到 9 逐一尝试，没有冲突就填进去，有冲突再试下一个数字。

    * 例：第一个空格填 1 时行、列、小九宫格内都没有 1，可以填入。

    * 例：第二个空格填 1 在行里和列里都冲突，改填 2 时行、列、九宫格都没有 2，可以填入。

    * 例：第三个空格填 1 显然冲突，填 2 不冲突；如此以此类推把整个棋盘填满，解就求出来了。

* **填错了当场看不出来，必须回溯**

    * 数字填进去时虽然没有冲突，但不代表填对了，接下来未必还成立，所以是暂时填入。

    * 例：前面若干空格填好后填入一个 2，当下行、列、九宫格都没有冲突。

    * 往下填下一个空格时先试 1 冲突、再试 2 也冲突；从小九宫格看应该填 3，但填入 3 后它与列上另一个 3 仍冲突。

    * 1 到 9 都用完了已经没有别的数字，说明前面那个 2 填错了，因此必须回溯撤销。

    * 例：撤销刚才那个 9 和上次那个 2，改填入 3 之后就没冲突了；下一个空格处再填入一个 2，解题结果才是正确的。

* **代码的限制与同构结论**

    * 代码并没有那么聪明，发现 3 错了之后仍要把 4 到 9 依次尝试完，结果四到九全部冲突，然后才开始撤销。

    * 关键点仍是要把冲突状态记录下来：行上的冲突状态、列上的冲突状态、九宫格内的冲突状态都要记录。

    * > **结论**：这也是回溯。跟 N皇后一样，只是冲突判定的维度从「行/列/斜线」换成了「行/列/九宫格」，而填入的单位从一个皇后换成了一个 1 到 9 的数字。

## 数独冲突状态

### 行冲突与列冲突

* **行冲突：一维数组根本不够用**

    * 直觉是定一个大小为 9 的布尔数组，用九个 true/false 记录每一行有没有冲突——这样不行。

    * 因为每一行又有九个数字，你得知道这九个数字分别有没有被使用过。

    * 9 行每行 9 个数字，一共 81 种状态，一个一维数组根本不够记。

    * 例如第零行中 5、3、4、6、7、8、9 都被使用过了，1 和 2 还没有使用。

    * 必须改成二维数组 `rowConflict`：第一维是行号，第二维是这一行里 9 个数字分别有没有被用过。

    * > **易错点**：最容易踩的就是顺手定一个长度 9 的布尔数组。行冲突的语义是「第 r 行里数字 d 被用过没有」，光有行号没有数字就区分不出来，所以必须是二维。

* **列冲突：结构完全一样**

    * `colConflict` 同样是二维数组，索引代表第几列，每列里面再分成 9 个数字分别判断冲突。

    * 以第零列为例，各数字的冲突状态如下。

    | 数字 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
    | :--- | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
    | 第零列是否冲突 | false | true | true | false | true | true | true | true | false |

    * 含义：1 没有冲突是 false；2 和 3 有冲突是 true；4 没有冲突是 false；5、6、7、8 都已冲突是 true；9 还没填、可以使用是 false。

    * 行列冲突都得用二维数组来记录，一维的九个布尔值表达不了「哪个数字被用过」。

### 九宫格编号与 boxConflict

* **九宫格编号 (i / 3) * 3 + j / 3**

    * 9×9 棋盘一共也是九个九宫格，编号从 0 到 8。

    * 由单元格的行列坐标求所属九宫格：行坐标 i 整数除以 3 再乘以 3，然后加上列坐标 j 整数除以 3。

    $$box = \left( \frac{i}{3} \right) \times 3 + \frac{j}{3} \qquad \text{（两个除法都是整数除法）}$$

    * 例一：i = 1、j = 7 时，$1 / 3$ 整数除法得 0，$7 / 3$ 得 2，前半部分 $0 \times 3$ 加 2 等于 2，对应 2 号九宫格。

    * 例二：i = 8、j = 3 时，$8 / 3 = 2$ 再乘以 3 得 6，列坐标 $3 / 3 = 1$，6 加 1 等于 7，对应 7 号九宫格。

    ```text
                  j=0  j=1  j=2  |  j=3  j=4  j=5  |  j=6  j=7  j=8
                  ----------------------+--------------+--------------
        i=0         0    0    0   |   1    1    1   |   2    2    2
        i=1         0    0    0   |   1    1    1   |   2    2    2
        i=2         0    0    0   |   1    1    1   |   2    2    2
                  ----------------------+--------------+--------------
        i=3         3    3    3   |   4    4    4   |   5    5    5
        i=4         3    3    3   |   4    4    4   |   5    5    5
        i=5         3    3    3   |   4    4    4   |   5    5    5
                  ----------------------+--------------+--------------
        i=6         6    6    6   |   7    7    7   |   8    8    8
        i=7         6    6    6   |   7    7    7   |   8    8    8
        i=8         6    6    6   |   7    7    7   |   8    8    8
    ```

    * > **易错点**：`(i / 3) * 3 + j / 3` 里的两个除法都必须是整数除法。写成浮点除法 `i / 3.0` 会得到小数，下标直接就废了。

* **boxConflict 二维数组**

    * 定二维数组 `boxConflict` 记录九宫格内的冲突状态，每个九宫格里再放 9 个布尔值。

    * 先用编号公式由单元格找到对应九宫格，再记录该九宫格内 1 到 9 各自有没有冲突。

    * 以 7 号九宫格为例，它内部记录的各数字冲突状态如下。

    | 数字 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
    | :--- | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
    | 7 号九宫格是否冲突 | true | false | true | true | true | true | false | true | true |

    * 含义：2 和 7 没有冲突是 false，其余 1、3、4、5、6、8、9 都已冲突是 true。

    * 三个二维布尔数组 `rowConflict`、`colConflict`、`boxConflict` 合起来，记录了行、列、九宫格全部冲突状态。
