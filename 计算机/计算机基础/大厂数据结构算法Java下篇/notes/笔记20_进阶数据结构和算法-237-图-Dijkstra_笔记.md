# 进阶数据结构和算法-237-图-Dijkstra

## 用 previous 还原路径

* **前驱顶点（previous）**
    * > **定义**：`Vertex` 对象上的一个类型为 `Vertex` 的属性，记录"当前这个最短距离是从哪个顶点更新过来的"，初始值给 `null`。
    * 依据：更新邻居距离时，当前顶点的邻居是谁本来就是已知的——来源一定就是当前顶点，信息已经现成，只需挂到邻居身上。
    * 声明位置：与 `name`、`dist`、`edges` 并列，作为顶点类的成员。
    * 更新时机：在判断"发现了更小的距离"的同一个分支里，与 `setDist` 顺手一起执行 `setPrevious`，不多走一次额外逻辑。

* **距离更新时同步记录来源**
    * 规则：只有 `unvisited.contains(v) && v.getDist() > dist` 成立时才写入 `dist` 与 `previous`。
    * 打印方式：先输出名字与距离，再判 `getPrevious() != null`，为真打印前驱名字，否则打印 `null`。

```java
private static void updateDist(Vertex v, int dist, Vertex prev, Set<Vertex> unvisited) {
    if (unvisited.contains(v) && v.getDist() > dist) {
        v.setDist(dist);
        v.setPrevious(prev);       // 顺手把来源记录下来
        unvisited.remove(v);
    }
}
```

* **前驱回溯出的最短路径**
    * 作用：只用 `previous` 一个属性就能把整条最短路径描述出来，不需要额外的数据结构。
    * 回溯方式：从终点沿 `previous` 反复取前驱，直到遇到 `previous == null` 的起点。
    * 实例：`V1 → V3 → V6 → V5`，对应距离 9 + 2 + 9 = 20；v5 的 `previous` 是 v6，v6 的 `previous` 是 v3，v3 的 `previous` 是 v1。
    * 逐点结果：v1 的 `previous` 为 null；v2 与 v3 都来自 v1，v3 距离 9；v4 来自 v3，v3 再往前是 v1，故到 v4 的路径是 v1 → v3 → v4。
    * > **易错点**：起点 v1 的 `previous` 本来就该是 `null`——它前面没有更前面的节点过来了，所以打印时必须先做非空判断，否则会空指针。

## 用 visited 判定邻居

* **已处理标记（visited）**
    * > **定义**：顶点上的一个布尔属性，置为 `true` 表示该顶点已经被处理过。
    * 判定替换：原来"邻居还在未处理集合中"用 `unvisited.contains(v)` 判断，现在改成只看 `!v.isVisited()`。
    * 触发前提：处理完一个顶点后立刻把它的 `visited` 置 `true`，之后更新邻居距离时该顶点就被这一层挡在门外。
    * 效率收益：不再每次都进集合做一次 `contains` 查询，判定开销下降。
    * 代码简化：`Set<Vertex> unvisited` 这个参数在方法签名和调用处都可以直接删掉。

```java
private static void updateDist(Vertex v, int dist, Vertex prev) {
    if (!v.isVisited() && v.getDist() > dist) {
        v.setDist(dist);
        v.setPrevious(prev);
    }
}
```

* **改动前后的结果不变**
    * 最短距离仍是：v1 = 0、v2 = 7、v3 = 9、v4 = 20、v5 = 20、v6 = 11。
    * 变化只发生在判定方式与性能上，算法结果本身不受影响。

## 优先队列优化选点

### 瓶颈与替换思路

* **选点开销**
    * 瓶颈定位：第三步"到未处理集合中找一个距离最小的顶点作为当前顶点"必须遍历整个集合，算法整体效率不高。
    * 通用手段：在多个元素里选一个最小值，用堆这种数据结构可以把时间复杂度降下来。
    * 落地形态：改用一个最小堆，也就是优先级队列来重写选点逻辑。

* **优先级队列（PriorityQueue，堆）**
    * > **定义**：装顶点对象的小顶堆容器，用队首元素直接充当"当前距离最小的顶点"，替代遍历找最小值。
    * 比较器：用泛型的 `Comparator` 对象比较，不能直接拿顶点本身比；用 `comparingInt` 只取对象的一部分——顶点的 `getDist()`。
    * 堆序规则：Java 的优先级队列默认是小顶堆，距离更小的排在队列头部、堆顶。
    * 容器更名：队列变量名叫 `q`；改动之前那个存未访问顶点的集合整体不再需要。
    * 取当前顶点：第三步不用再调任何遍历方法，直接 `q.poll()` 拿堆顶。
    * 移除当前顶点：第五步不再从集合中删除，改由循环开头的 `q.poll()` 完成。

```java
PriorityQueue<Vertex> q =
        new PriorityQueue<>(Comparator.comparingInt(v -> v.getDist()));
```

```java
public static void dijkstra(Graph graph, Vertex source) {
    // 第二步不用动：起点距离为 0，其余顶点距离一开始都是无穷大
    source.setDist(0);
    for (Vertex v : graph.getVertices()) {
        if (v != source) {
            v.setDist(Integer.MAX_VALUE);
        }
        q.offer(v);          // 把所有顶点都加到队列里去
    }

    // 只要队列不为空就一直循环，队列空了表示所有顶点都处理完了
    while (!q.isEmpty()) {

        // 第三步：找距离最小的顶点——直接 poll 队列的头部就是它
        Vertex current = q.poll();

        // 第四步：更新邻居的距离
        for (Edge edge : current.getEdges()) {
            Vertex neighbor = edge.getTo();
            updateDist(neighbor, current.getDist() + edge.getWeight(), current, q);
        }
    }
}
```

### 容器改动对照

| 环节 | 改动前（集合） | 改动后（优先级队列） |
| :--- | :--- | :--- |
| 容器 | `Set<Vertex> unvisited`，只装未访问的顶点 | `PriorityQueue<Vertex> q`，装所有待处理的顶点 |
| 判断邻居是否未处理 | `unvisited.contains(v)` | `!v.isVisited()` |
| 选当前顶点 | 遍历整个集合找距离最小的 | `q.poll()`，堆顶天然就是最小的 |
| 距离变小之后 | 从集合中 `remove` | 再 `q.offer(neighbor)` 一次 |
| 处理完当前顶点 | 从集合中把它删除 | 从队列中把它 `poll` 出来 |

* **第四步的差异**
    * 换成优先级队列后，除了更新邻居的距离，还必须把更新后的顶点重新加入队列，即再 `q.offer` 一次。

* **可以删掉的部分**
    * 原来"到集合里遍历找最小值"的方法彻底用不上了，可以直接删掉。

### 重复条目与 visited 的屏蔽

* **重新入队的原因**
    * > **注意**：Java 的优先级队列在元素距离变化后**不会**自动调整该顶点在队列中的位置；重新 offer 一次它才会被重新排位。
    * 代价与取舍：队列中该顶点会出现重复，但位置更值得在意——因为选点必须取队列中距离最小的那个，这是与用集合时不同的地方。

* **重复引用的成因**

```text
v3（dist 还是 MAX）本来就在队列里
  │
  │  ← v1 当选，v1 → v3 这条边松弛成功，v3.dist 改成 9
  ▼
q.offer(v3)   把同一个对象又塞了一份引用进去

队列里就变成：   ……   v3(9)   ……   v3(9)   ……
```

    * 过程：一开始 v2、v3、v6 都在队列中；v1 首次当选后把它们的距离更新成 7、9、14，于是这三个顶点各自又被加了一份。
    * 现象：v2 出现两次、v3 两次、v6 两次——它们其实是同一个对象，只是队列里存了两个引用。
    * 后果：下一轮先处理一个 v2，再下一轮又处理一个 v2，v2 的邻居更新逻辑被执行两遍；结果仍然正确，但这次重复执行没有必要。

* **visited 的真正用途**
    * 规则：只有 `visited` 为 `false`（尚未处理）时才根据它的距离去更新邻居，并立刻把它置 `true`。
    * 屏蔽机制：下次再遇到同一个引用时，`visited` 已是 `true`，就不会进入这个 if 块，重复的邻居更新逻辑不再执行。
    * 加盾位置：在主循环里 `poll` 之后加一层 `if (!current.isVisited())` 即可。

```java
while (!q.isEmpty()) {
    Vertex current = q.poll();
    if (!current.isVisited()) {           // 重复的引用会被这一层挡掉
        current.setVisited(true);
        for (Edge edge : current.getEdges()) {
            Vertex neighbor = edge.getTo();
            updateDist(neighbor, current.getDist() + edge.getWeight(), current, q);
        }
    }
}

private static void updateDist(Vertex v, int dist, Vertex prev, PriorityQueue<Vertex> q) {
    if (!v.isVisited() && v.getDist() > dist) {
        v.setDist(dist);
        v.setPrevious(prev);
        q.offer(v);            // 距离变了，必须重新入队才会调整位置
    }
}
```

### 结果校验

* 队列元素出现重复不影响最终答案，表面上与加 `visited` 屏蔽前一致，只是少执行了冗余代码。
* 改动完成后的最短距离：v1 = 0、v2 = 7、v3 = 9、v4 = 20、v5 = 20、v6 = 11，与改用优先级队列之前完全一致。

## 有负边时 Dijkstra 失效

### 反例推演

* **反例图**：v1 到 v3 权重 1，v1 到 v2 权重 2，v2 到 v3 权重 -2，v3 到 v4 权重 1。

```text
   ┌───────── 1 ────────┐
   ▼                    │
   V1 ──2──► V2 ──-2──► V3 ──1──► V4
```

* **初始条件**
    * 起点 v1 的初始距离置 0，其余顶点初始距离都置为无穷大。

* **逐步推演**
    * 第一步：v1 的邻居需要更新——v1 → v3 得 1 小于无穷大，V3 更新为 1；v1 → v2 得 2 小于无穷大，V2 更新为 2。v1 处理完后不再处理。
    * 第二步：在未处理顶点中选距离最小的，按 Dijkstra 的做法选中 v3（距离 1）。v3 只有一个邻居 v4，1 + 1 = 2 小于无穷大，V4 更新为 2。v3 处理完后不再处理。
    * 第三步：未处理集合还剩 v2 与 v4，两者距离都是 2，随便挑一个。处理 v2 时它的邻居 v3 已处理过，不走更新逻辑，V2 保持 2。
    * 第四步：v4 没有其他出边，没有邻居可处理，结束。

* **Dijkstra 给出的答案**
    * 错误结果：`V1→V2 = 2    V1→V3 = 1    V1→V4 = 2`。

### 正确值与根因

* **反例的真实最短距离**
    * v1 → v3：直接走是 1，但先到 v2 再到 v3 是 2 + (-2) = 0，比 1 更小，所以真值是 0。
    * v1 → v4：走 v1 → v2 → v3 → v4 得 2 + (-2) + 1 = 1，比 2 更小，所以真值是 1。
    * 结论：图中存在负边时，Dijkstra 得到的是错误结果。

* **根因：局部最优不等于全局最优**
    * 出错的那一步：v1 处理完、v3 与 v2 距离都已更新之后，要在剩余未处理顶点里选距离最小的，于是选中了距离为 1 的 v3。
    * 之后不会再回头：对 v3 的邻居做完更新后，它就被移出未处理集合，此后再也不被处理。
    * 假设的来源：Dijkstra 认定所有边权为正；边权为正时，找到的最小值确实不会再被别的路径改善。
    * 矛盾之处：一旦有负边，v1 → v2 → v3 的总长 0 比 1 更小，被选中的 v3 的距离本应再被更新一次，却被永久锁定。
    * > **结论**：Dijkstra 的正确性依赖"边权非负"这个前提；一旦出现负权，"当前距离最小的顶点不可能再被更优路径改善"这个假设就塌了。

## Bellman-Ford 求最短路

### 算法思路

* **Bellman-Ford 算法**
    * > **定义**：放弃挑选距离最小的顶点，改为每一轮把所有边都过一遍，对每条边指向的顶点做距离更新，经过若干轮后就不会有疏漏。
    * 与 Dijkstra 的分工：Dijkstra 每轮挑一个距离最小的顶点、只更新它的邻居；Bellman-Ford 不挑最小值，每轮对全部边做松弛。
    * 轮数依据：轮数与顶点数相关，四个顶点做三轮，也就是 $|V| - 1$ 轮。
    * 边的编号：给所有边编号，编号先后无所谓；本例按 ①②③④ 的顺序处理。
    * 初始状态：与 Dijkstra 相同——起点距离为 0，其余顶点距离为无穷大（整数的最大值）。

```text
   ┌────────── ③ 1 ─────────┐
   ▼                       │
   V1 ──④ 2──► V2 ──② -2──► V3 ──① 1──► V4
```

### 三轮推演

```text
初始：  V1=0    V2=∞    V3=∞    V4=∞

第 1 轮
  ①  V3→V4    V3=∞    ∞ + 1  = ∞      不更新
  ②  V2→V3    V2=∞    ∞ - 2  = ∞      不更新
  ③  V1→V3    V1=0    0 + 1  = 1       更新：V3=1
  ④  V1→V2    V1=0    0 + 2  = 2       更新：V2=2
轮末：  V1=0    V2=2    V3=1    V4=∞

第 2 轮
  ①  V3→V4    V3=1    1 + 1  = 2       更新：V4=2
  ②  V2→V3    V2=2    2 - 2  = 0       更新：V3=0
  ③  V1→V3    V1=0    0 + 1  = 1       1 不比 0 小，不更新
  ④  V1→V2    V1=0    0 + 2  = 2       2 不比 2 小，不更新
轮末：  V1=0    V2=2    V3=0    V4=2

第 3 轮
  ①  V3→V4    V3=0    0 + 1  = 1       更新：V4=1
  ②③④                                   都不更新
轮末：  V1=0    V2=2    V3=0    V4=1      ← 最终答案
```

* **跳过规则**
    * 无穷大加任何数还是无穷大，两边都是无穷大时没有谁大谁小，直接跳过不更新。
    * "没找到更小的距离就不更新"——每次松弛只在起点的距离加上边权严格小于终点距离时才发生。

* **轮数为什么是顶点数减一**
    * > **提示**：不存在负环时，最短路径不会绕着环再回到同一个顶点——绕一圈只会更亏，把这个环剥掉不会让路径变长，所以最短路径最多由 $|V| - 1$ 条边组成。
    * 每轮把所有边过一遍，每过一遍至少有一条边的信息被确定下来，$|V| - 1$ 轮就足够走完全程。

### 代码实现要点

* **方法签名与初始设置**
    * 签名：`bellmanFord(Graph graph, Vertex source)`，图里提供顶点集合，起点即 source。
    * 初始化：`source` 距离置 0，其余顶点置 `Integer.MAX_VALUE`，同时把所有顶点的 `previous` 置 `null`。

```java
public static void bellmanFord(Graph graph, Vertex source) {
    List<Vertex> vertices = graph.getVertices();

    // 初始距离
    for (Vertex v : vertices) {
        v.setDist(v == source ? 0 : Integer.MAX_VALUE);
        v.setPrevious(null);
    }

    // 外层循环：顶点个数 - 1 轮
    int size = vertices.size();
    for (int i = 0; i < size - 1; i++) {

        // 两次遍历拿到所有的边：先顶点，再该顶点的边
        for (Vertex s : vertices) {              // s = start
            for (Edge edge : s.getEdges()) {
                Vertex e = edge.getTo();         // e = end

                // 起点距离为无穷大时直接跳过，后面的比较没有意义
                if (s.getDist() != Integer.MAX_VALUE
                        && s.getDist() + edge.getWeight() < e.getDist()) {
                    e.setDist(s.getDist() + edge.getWeight());
                    e.setPrevious(s);
                }
            }
        }
    }
}
```

* **遍历全部边的写法**
    * 外层循环 `for (int i = 0; i < size - 1; i++)`，先取顶点个数 `size` 再循环，轮数由顶点数直接决定。
    * 每轮内部两次遍历：先遍历顶点集合，再遍历每个顶点的边集合，遍历完就拿到了全部的边，四条边一轮全过。

* **松弛判定**
    * 判定式：边的起点距离加上这条边的权重，若小于终点的距离，就做一次更新。
    * 变量命名：原来的 `v` 其实是这条边的起点，改叫 `s`（start）；终点改叫 `e`（end），边的起点和终点都有对应的名字。
    * > **注意**：起点距离为无穷大时，拿它做加减乘除再跟别的数比较是没有意义的，所以只有起点距离不是无穷大时才做距离检查。
    * 松弛成功时顺手把终点的 `previous` 设为边的起点，最短路径就能一并被还原出来。

* **结果与路径还原**
    * 验证距离：v1 到自己为 0，到 v2 为 2，到 v3 为 0，到 v4 为 1，与三轮推演完全一致。
    * 路径回溯：v4 来自 v3，v3 来自 v2，v2 来自 v1，v1 没有前驱为 `null`，整条最短路径的形状因此确定。
    * 打印写法：输出名字与距离后，用三元表达式判 `previous` 是否为 null，为真打印名字，否则打印 `null`。

## 负环

### 负环的定义

* **负环（negative cycle）**
    * > **定义**：路径先构成一个环（走出去还能转回来），并且环中所有边的权重加起来是负数，二者同时满足即为负环。
    * 后果：求最小路径没有解，解相当于负无穷大。
    * 判例：`2 + (-4) + 1 = -1`，和为负数，即构成负环。

```text
   ┌────────── ③ 1 ─────────┐
   ▼                       │
   V1 ──① 2──► V2 ──② -4──► V3 ──④ 1──► V4
```

### 距离为何持续下降

* **带负环的四轮推演**

```text
初始：  V1=0    V2=∞    V3=∞    V4=∞

第 1 轮
  ①  V1→V2    0 + 2  = 2       更新：V2=2
  ②  V2→V3    2 - 4  = -2      更新：V3=-2
  ③  V3→V1    -2 + 1 = -1      更新：V1=-1
  ④  V3→V4    -2 + 1 = -1      更新：V4=-1

第 2 轮
  ①  V1→V2    -1 + 2 = 1       更新：V2=1
  ②  V2→V3    1 - 4  = -3      更新：V3=-3
  ③  V3→V1    -3 + 1 = -2      更新：V1=-2
  ④  V3→V4    -3 + 1 = -2      更新：V4=-2

第 3 轮
  ①  V1→V2    -2 + 2 = 0       更新：V2=0
  ②  V2→V3    0 - 4  = -4      更新：V3=-4
  ③  V3→V1    -4 + 1 = -3      更新：V1=-3
  ④  V3→V4    -4 + 1 = -3      更新：V4=-3

三轮跑完：  V1=-3   V2=0   V3=-4   V4=-3
```

    * 三轮结束后给出的 -3、0、-4、-3 是错误结果，因为继续跑还能找到更短的距离。

* **第 4 轮仍在下降**

```text
第 4 轮
  ①  V1→V2    -3 + 2 = -1      <  0      更新：V2=-1
  ②  V2→V3    -1 - 4 = -5      < -4      更新：V3=-5
  ③  V3→V1    -5 + 1 = -4      < -3      更新：V1=-4
  ④  V3→V4    -5 + 1 = -4      < -3      更新：V4=-4
```

    * 每一轮都能找到比上一轮更短的距离，于是可以无限执行下去，直到距离变成负的无穷大。
    * 结论：一旦出现负环就没有解，最终这些最短距离都会被变成负无穷大。

### 负环的检测

* **多跑一轮判定法**
    * > **结论**：跑完 $|V| - 1$ 轮之后再加一轮，如果这一轮仍然发生了松弛，说明存在负环。
    * 依据：正常情况下最短路径在这时早已定型；它没定型，只能是被某个负环一遍遍往下拉。
    * 触发松弛的判定条件：起点距离不是 `Integer.MAX_VALUE`，并且 `start.dist + weight < end.dist`。
    * 处置方式：一旦判定出负环就立刻停止执行，返回"出现负环，没有解"，不要让它继续往负无穷大跑。
    * 落点：在正常的三轮（`for (int i = 0; i < size - 1; i++)`）之后再补一轮带标志位的检测即可——只要这一轮还有边能走进那个 `if` 条件，就说明出现了负环。
