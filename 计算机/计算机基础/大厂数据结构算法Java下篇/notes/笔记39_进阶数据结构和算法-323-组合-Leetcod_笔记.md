# 进阶数据结构和算法-323-组合-Leetcod

## 组合剪枝的两个计数

* **还缺的数字个数**

    * > **定义**：总共要 `k` 个数字，`stack` 里存的就是已经固定下来的数字个数，所以还缺的数量等于 `k` 减去 `stack` 的长度。

    * $$\text{还缺} = k - stack.length$$

    * > **提示**：`stack` 天然就是「已固定数字」的计数器，不用再单独维护一个变量。

* **备用的数字个数**

    * > **定义**：`n` 是右边界，当前正在处理的位置是 `i`，从 `i` 到 `n` 一共的数字个数，就是这条分支还能拿去凑的数字个数。

    * $$\text{备用} = n - i + 1$$

* **剪枝判定**

    * > **结论**：缺的数字个数 > 备用的数字个数，说明这条分支注定凑不满，直接 `continue`，连递归都不用进。

    * 条件写成 `k - stack.length > n - i + 1`，一个 `if` 就够。

    * > **注意**：Java 里 `stack` 是集合，没有 `length`，得用 `size()`；循环变量 `i` 从 `start` 取到 `n`（含 `n`），递归下去时起点传 `i`。

    * 拿 `n = 4`、`k = 3` 走一遍，两个数在状态间是这样跳的：

| 当前栈 | 还缺几个（k=3） | 还能用的数字 | 判断 |
| :--- | :--- | :--- | :--- |
| 空 | 3 | 1、2、3、4 → 4 个 | 够，继续 |
| `[1]` | 2 | 2、3、4 → 3 个 | 够，继续 |
| `[1,2]` | 2 | 2、3、4 → 3 个 | 够，继续 |
| `[1,3]` | 2 | 3、4 → 2 个 | 正好够，继续 |
| `[1,4]` | 2 | 只有 4 → 1 个 | 不够，剪掉 |

    * 剪之前 `[1,4]`、`[2,4]`、`[3,4]` 这些分支全在递归树上；剪之后它们全没了，只剩 `[1,2,3]`、`[1,2,4]`、`[1,3,4]`、`[2,3,4]` 四个组合。

    * 答案一个字没变，树的规模小了一大截——剪掉的分支本来就注定凑不出长度 3 的组合。

* **代码骨架**

    ```java
    void dfs(int n, int k, int start, LinkedList<Integer> stack,
             List<List<Integer>> result) {
        if (stack.size() == k) {
            result.add(new ArrayList<>(stack));
            return;
        }
        for (int i = start; i <= n; i++) {
            // 还缺的数字个数，大于还备用的数字个数，这条分支没戏
            if (k - stack.size() > n - i + 1) {
                continue;
            }
            stack.push(i);
            dfs(n, k, i, stack, result);
            stack.pop();
        }
    }
    ```

## 组合总和：数字可以重复使用

* **起点参数 start**

    * > **定义**：`start` 是遍历候选数组时的起点索引。

    * 求组合的 DFS 一般都要带它；求排列不需要，因为排列每层都从 0 开始重新挑。

    * > **结论**：组合必须限制起点，不然会算出同一组合的多种排列（`2+2+3` 和 `2+3+2`）。

* **target 在递归中的三种含义**

    * 一开始它的值就是题给的 `target`，比如 7。

    * 每固定一个数字，就用当前 `target` 减去这个数字——固定了 2，`target` 就变成 `7 - 2 = 5`。

    * `target == 0`：凑满了，找到解，把当前路径复制一份收下。

    * `target > 0`：还没凑够，进入循环继续干活。

    * `target < 0`：爆了，这条分支可以直接退出。

* **其他两个参数**

    * `stack` 是 `LinkedList` 类型的栈，存当前这条路径。

    * `result` 更大，存所有解。

* **循环体三步**

    * 循环从 `start` 走到 `candidates.size() - 1`。

    * 第一步：拿到当前数字 `candidates[i]` 并 **固定**——`stack.push(candidates.get(i))`，push 进去就相当于这个数定下来了。

    * 第二步：带着它往下递归，`dfs(candidates, i, target - candidates.get(i), stack, result)`。

    * 第三步：递归返回后**恢复现场**——`stack.pop()`，回溯。

    * > **易错点**：递归时传下去的起点是 `i`，不是 `i + 1`。这题数字可以重复用，固定了 2 之后下次还得能跟 2 组合，所以起点原地不动。

    * `stack` 和 `result` 原样传下去，只有 `target` 这一项每次固定数字时减掉它。

* **终止条件**

    ```java
    if (target < 0) {
        return;                               // 爆了
    }
    if (target == 0) {
        result.add(new ArrayList<>(stack));   // 凑满，把当前路径复制一份收下
        return;
    }
    ```

* **一条完整的回溯轨迹**

    * 按上面骨架跑 `candidates = [2, 3, 6, 7]`、`target = 7`，递归树长这样（带剪枝的版本最后才补，先看它该长什么样）：

    ```text
    dfs(start=0, target=7, stack=[])
    ├─ i=0 固定 2 → dfs(start=0, target=5, stack=[2])
    │   ├─ i=0 固定 2 → dfs(0, 3, [2,2])
    │   │   ├─ i=0 固定 2 → dfs(0, 1, [2,2,2])
    │   │   │   └─ i=0 固定 2 → dfs(0, -1, [2,2,2,2]) → target<0 爆掉
    │   │   ├─ i=1 固定 3 → dfs(1, 0, [2,2,3]) → target==0   ✓ 收下
    │   │   ├─ i=2 固定 6 → dfs(2, -1, [2,2,6]) →              爆掉
    │   │   └─ i=3 固定 7 → dfs(3, -2, [2,2,7]) →              爆掉
    │   ├─ i=1 固定 3 → dfs(1, 2, [2,3])
    │   │   ├─ i=1 固定 3 → dfs(1, -1, [2,3,3]) →              爆掉
    │   │   ├─ i=2 固定 6 →                                   爆掉
    │   │   └─ i=3 固定 7 →                                   爆掉
    │   ├─ i=2 固定 6 → dfs(2, -1, [2,6]) →                    爆掉
    │   └─ i=3 固定 7 → dfs(3, -2, [2,7]) →                    爆掉
    ├─ i=1 固定 3 → dfs(1, 4, [3])
    │   ├─ i=1 固定 3 → dfs(1, 1, [3,3])
    │   │   ├─ i=1 固定 3 → dfs(1, -2, [3,3,3]) →              爆掉
    │   │   └─ i=2、i=3 固定 6、7 →                            都爆掉
    │   ├─ i=2 固定 6 →                                        爆掉
    │   └─ i=3 固定 7 →                                        爆掉
    ├─ i=2 固定 6 → dfs(2, 1, [6])
    │   └─ i=2、i=3 固定 6、7 →                                 都爆掉
    └─ i=3 固定 7 → dfs(3, 0, [7]) → target==0                ✓ 收下
    ```

    * 数满 `target` 的 `✓` 只有两处，对应 `[2,2,3]` 和 `[7]` 这两个解。

    * 满屏的「爆掉」就是纯浪费的递归，比如 `[2,2,2]` 那一层明知还差 1，却还得老实去试 2、3、6、7，然后每一个都爆。

* **取负分支的剪枝**

    * 已经组合到 `[2,2,2]`，还差 1 才凑满 7，而备选数字是 2、3、6、7——挑哪个都会更大，相加必然超出目标。

    * > **结论**：剩余的 `target` 比当前候选数字还小，这条分支直接 `continue`。

    * 检查放在递归之前：

    ```java
    void dfs(List<Integer> candidates, int start, int target,
             LinkedList<Integer> stack, List<List<Integer>> result) {
        if (target < 0) {
            return;
        }
        if (target == 0) {
            result.add(new ArrayList<>(stack));
            return;
        }
        for (int i = start; i < candidates.size(); i++) {
            // 还差 1，可候选数字最小是 2，加上必然超出，直接进入下一轮循环
            if (target < candidates.get(i)) {
                continue;
            }
            stack.push(candidates.get(i));
            dfs(candidates, i, target - candidates.get(i), stack, result);
            stack.pop();
        }
    }
    ```

    * > **提示**：加了这条剪枝之后 `target` 永远不会再变成负数，因为能被选中的数字一定满足 `target >= candidates.get(i)`，减完还是非负。所以 `if (target < 0) return;` 这个分支可以直接删掉。

    * > **易错点**：不剪枝就一定不能删那个负数分支——是加了剪枝才敢删，两件事配套。

    * 最终答案还是那两个组合，结果没变，递归次数少了很多。

## 回溯与动态规划的分工

* **组合总和与零钱兑换背景同源**

    * 两道题在问题背景上其实一模一样：同一批「不同面值的硬币」，凑同一个目标金额。

| | 组合总和 | 零钱兑换 |
| :--- | :--- | :--- |
| 候选者数组 | 不同面值的硬币 | 不同面值的硬币 |
| `target` | 要凑的总金额 | 要凑的总金额 |
| 要求 | 把**所有**组合的具体信息都求出来 | 求**最值**或**汇总**信息 |

* **差别只在要什么答案**

    * 组合总和要具体信息——套到零钱兑换的语境里，就是「为了凑出 7 块钱，我到底要哪几枚硬币」，得把 `[3,3,1]` 或 `[7]` 这种具体方案全部列出来。

    * 这种题没法用汇总信息糊弄过去，只能用回溯加剪枝把所有组合可能都翻出来。

    * 零钱兑换要的是「所有组合里用到的硬币数最少的是哪个」——上面这个例子一个用了 3 枚，一个用了 1 枚，最少是 1 枚；还有一种考法是问组合的总共有几种。

    * 这类问题求的是 `min`、`max`、`sum`、`count` 这样的汇总信息，用**动态规划**更合适。

    * > **结论**：问「要所有方案」用回溯；问「要最优值或总数」用动态规划。两类问题背景一样，解法分道扬镳。

## 组合总和 II：每个数字只能用一次

* **与上一道的两点区别**

    * 上一道里数字可以重复出现——2 可以出现多次，3 也可以多次；这一道要求数组里的每个数字只能出现一次。

    * 最终结果里不能包含重复的组合，而且数组本身就可能给你两个重复的 1，所以即使「每个数字只用一次」，也可能造出重复的组合。

    * 搬用上一道的代码做增量改造：终止条件、剪枝、递归体全都还能用，只在这个基础上改。

* **先让每个数字只出现一次**

    * > **结论**：把递归传下去的 `start` 从 `i` 改成 `i + 1`。固定了 `i` 之后下次递归就从 `i + 1` 往后选，每个数字自然只出现一次。

    * 突破口就在 DFS 的第一个参数：原代码下次递归的循环又从 `1` 自己所在的索引位置开始，1 跟 1 组合到了一起。

    * 直接用原代码跑，一大堆结果都是不符合题意的，`1` 出现了五次六次；改完之后 `1` 出现一次，1 撇出现一次，后面每个数也各出现一次。

* **同值去重的三步判断**

    * 改完仍不对：`[5,2,1]` 跟 `[5,1,2]` 从组合角度看是重复的，`[7,1]` 跟 `[1,7]` 也是。

    * 原因是没法区分「这个 1」和「这个 1 撇」，看着像重复，其实只是同一批数字的两种排列。

    * 沿用全排列 II 的老思路：先对数组**排序**，让重复的数字彼此相邻，然后在这个基础上做去重。

    * 去重规矩：**必须先使用 1，再使用 1 撇**；处理 1 撇时先看前面那个 1 有没有被用过，没用过说明 1 撇抢在 1 前面，跳过去。

    * 记录使用情况要加一个布尔数组 `visited`，初始长度和候选数组一样长，递归调用时一起传进去。

    * 判定分三步：先看 `candidates[i]` 是不是和上一个数 `candidates[i - 1]` 相等；相等的话再看 `visited[i - 1]` 是不是 `false`，是就说明 1 撇抢在了 1 前面，`continue`；最后别忘了防越界，`i` 必须大于 0。

* **visited 的置位与回溯**

    * > **易错点**：`visited[i] = true` 要在递归**之前**设置，递归结束之后还要**回溯**成 `false`。忘了回溯，后面的分支就会看到一个脏的访问标记，去重彻底乱了。

* **完整代码**

    ```java
    void dfs(List<Integer> candidates, int start, int target,
             LinkedList<Integer> stack, List<List<Integer>> result,
             boolean[] visited) {
        if (target < 0) {
            return;
        }
        if (target == 0) {
            result.add(new ArrayList<>(stack));
            return;
        }
        for (int i = start; i < candidates.size(); i++) {
            if (target < candidates.get(i)) {
                continue;
            }
            // 同值去重：当前数和上一个数相同，但上一个数还没被用过，跳过
            if (i > 0 && candidates.get(i) == candidates.get(i - 1) && !visited[i - 1]) {
                continue;
            }
            visited[i] = true;
            stack.push(candidates.get(i));
            dfs(candidates, i + 1, target - candidates.get(i), stack, result, visited);
            stack.pop();
            visited[i] = false;          // 回溯，别忘了
        }
    }
    ```

    * 再运行，`[5,2,1]` 只剩一个、下面那个没了，`[7,1]` 也只剩一个，重复的组合全部消除。

## 组合总和 III：从 1~9 里挑 K 个数凑 N

* **两个 n 的含义完全不一样**

    * 77 题里的 `n` 代表**数字的范围**，从 1 到 `n` 里挑 `k` 个数组合。

    * 这道题里的 `n` 代表**组合后的和**，从 `1~9` 里挑 `k` 个数，它们的和要等于 `n`。

    * 为区分起见，把这道题里的 `n` 改名叫 `target`，循环固定从 1 到 9，剪枝代码里那个 `n` 也固定写成 9。

    * 代码大部分直接从 77 题搬过来，改名、加上 `target` 的减法就行。

* **加约束这一步**

    * 直接搬过来一跑就知道结果不对：它把从 1~9 挑 3 个数的**所有组合**都列出来了，`[1,2,3]`、`[1,2,4]`、`[1,3,...]` 全在，完全没有「和等于 7」这个约束。

    * 每次固定一个数字 `i` 之后用 `target` 减掉 `i` 传下去，`target` 的含义就变成「还差多少才能凑满」。

    * `target` 在递归终止条件里减到 0 就代表刚好凑满一个合法组合，这时候返回就行。

* **递归次数的计数法**

    * > **提示**：想知道剪枝有没有用、到底省了多少，最笨也最管用的办法就是**数一下**——定一个 `count`，初始值 0，每次进递归就 `count++`，跑完直接看 `count` 的值。没想清楚复杂度时，这招比拍脑袋靠谱得多。

* **第一条剪枝：target < i**

    * `target` 代表剩余的和，它应该大于等于 `i`，因为每次要减掉的就是 `i`。

    * 如果反过来 `target < i`，这一减就减成负数，负数肯定不满足最终要求，干脆别递归，直接 `continue`。

    * 加上之后，`k = 3`、`n = 7` 这个用例的递归次数从 480 次掉到 19 次。

* **第二条剪枝：stack.size() == k**

    * `stack` 里存的是已经挑好的数字，它已经等于 `k` 说明数挑够了，但 `target` 还没等于 0。

    * 这时再挑一个数字继续递归不需要——就算再挑一个能让 `target` 减成 0，数字的个数也超了，所以在超之前就该 `continue`。

    * 这条在 `k = 3`、`n = 7` 上看不出效果，还是 19 次，因为该用例对它不敏感。

    * 更有说服力的用例是挑 2 个数字凑 18，它根本无解（最大的 9 加次大的 8 也才 17）：不加这条剪枝时调了 167 次，因为它在那儿不停地组合、都组合到五个数字了还是没凑够，可人家要的只有两个数；加完之后只剩 46 次。

* **各剪枝配置的实测次数**

| 剪枝配置 | `k=3, n=7` | `k=2, n=18` |
| :--- | :--- | :--- |
| 什么都不剪 | 480 | — |
| 只加 77 题那条 `k - size > n - i + 1` | 470 | — |
| 再加 `target < i` | 19 | 167 |
| 再加 `stack.size() == k` | 19 | 46 |
| 把 77 题那条也加回来 | 18 | — |

    * > **结论**：真正干活的是 `target < i` 和 `stack.size() == k` 这两条；最开始从 77 题沿用下来的那条剪枝加不加都差不多，加上也才少一次调用。

    * > **注意**：从别的题搬过来的剪枝条件不一定适合新题，一定要自己量一量再决定留不留。

    * `target < i` 加进来之后，终止条件里那个 `target < 0` 的分支同样可以去掉了——能被选中的数字一定满足 `target >= i`，减完不可能是负数。

* **完整代码**

    ```java
    void dfs(int k, int target, LinkedList<Integer> stack, List<List<Integer>> result) {
        // 挑够 k 个数，而且刚好凑满，这才是一个合法解
        if (stack.size() == k) {
            if (target == 0) {
                result.add(new ArrayList<>(stack));
            }
            return;
        }
        for (int i = 1; i <= 9; i++) {
            if (target < i) {
                continue;                     // 剪枝一：再减就成负数了
            }
            if (stack.size() == k) {
                continue;                     // 剪枝二：数已挑够，和却不对
            }
            stack.push(i);
            dfs(k, target - i, stack, result);
            stack.pop();
        }
    }
    ```

## 题目与用例

* **LeetCode 77 · 组合**

    * 给定两个正整数 `n` 和 `k`，返回 `1` 到 `n` 中所有可能的 `k` 个数的组合。

    * 演示用例是 `n = 4`、`k = 3`，结果是 `[1,2,3]`、`[1,2,4]`、`[1,3,4]`、`[2,3,4]`。

    * 剪枝条件是 `k - stack.size() > n - i + 1`。

* **LeetCode 39 · 组合总和**

    * 给定一个**无重复元素**的数组 `candidates` 和一个目标数 `target`，找出 `candidates` 中可以使数字和为 `target` 的所有**组合**。

    * `candidates` 中的同一个数字可以被**无限次**选取。

    * `candidates = [2,3,6,7]`、`target = 7` → `[[2,2,3], [7]]`。

    * `candidates = [2,3,5]`、`target = 8` → `[[2,2,2,2], [2,3,3], [3,5]]`。

    * 凑不出 `target` 的组合时，返回空数组。

* **LeetCode 40 · 组合总和 II**

    * 同样给一个候选数组和 `target`，但有两条限制：候选数组中的每个数字只能取一次，答案中不能包含重复的组合。

    * 注意数组本身可能含有重复元素，所以即使「每个数字只用一次」，也可能造出重复的组合。

    * 去重之后一共保留了四种可能的组合。

* **LeetCode 216 · 组合总和 III**

    * 找出数字 `1` 到 `9` 中每个数字最多使用一次、且能组成 `k` 个数字的不同组合，使其和为 `n`。

    * `k = 3`、`n = 7` → `[1,2,4]`。

    * `k = 3`、`n = 9` → `[1,2,6]`、`[1,3,5]`、`[2,3,4]`。
