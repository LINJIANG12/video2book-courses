# 进阶数据结构和算法-333-四数之和-Leetc

## 四数之和

* **题目形态**
    * > **定义**：给定一个整数数组和 `target`，挑出四个数字使它们的和等于 `target`，每组算一个解。
    * 示例数组 `[1, 0, -1, 0, -2, 2]`，`target = 0`，排序后为 `[-2, -1, 0, 0, 1, 2]`。
    * 该示例共三个解：`-2、-1、1、2`；`-2、0、0、2`；`-1、0、0、1`。
    * 解内部还要排除重复组合，套路与三数之和相同。

* **排序的作用**
    * 排序的目的就是为了将来去除方便，靠的是排好序之后挨着的重复值可以成片跳过。
    * 只有先排序，固定位才会单调变化，双指针夹逼才有意义。

### 连降两级

* **降级链路**
    * 四数之和固定第一个数（`-2`）后转换成三数之和，再固定第二个数（`-1`）后转换成两数之和。
    * 最后一步在剩余数字范围内用 `i`、`j` 两个指针夹逼。
    * 两轮递归分别把 `-2` 和 `-1` 固定住，固定好之后剩下的就是纯粹的两数之和。

```text
   四数之和   数组 [-2, -1, 0, 0, 1, 2]   target = 0
        │  固定第一个数 -2
        ▼
   三数之和   在剩余区间内继续
        │  再固定第二个数 -1
        ▼
   两数之和   在剩余区间内用 i、j 两个指针夹逼
```

* **目标换算**
    * > **注意**：固定两个数之后，剩下的目标不是 `target` 本身，而是 $target' = -(nums[i] + nums[j])$。
    * 固定的是 `-2` 和 `-1`，两者和为 `-3`，所以接下来两数之和要找的目标是 3。
    * > **易错点**：⚠️ 这一步目标值算错，后面全盘皆错，务必先在草稿纸上写一遍。

### 完整走一遍

* **第二组与去重**
    * 保持 `-2` 不变、取消固定 `-1` 后改固定后面的 `0`，两者和为 `-2`，目标变成 2；此时 `0 + 2` 正好命中，得到第二个解 `-2、0、0、2`。
    * 命中解之后 `i` 加加、`j` 减减，两者相遇，等价于没有找到不重复的组合，直接跳过。
    * `-2` 与这个 `0` 的组合没有解，因为 `0` 与上一个 `0` 重复；`-2` 与后面的 `1` 也不必再试，因为最后总得留两个数去做两数之和。

* **第三组与收尾**
    * 改固定 `-1` 与 `0`，两者和为 `-1`，目标为 1；`0 + 2` 比 1 大，让 `j` 减减后命中，得到第三个解 `-1、0、0、1`。
    * 再往后的 `-1` 与 `0` 组合属于重复组合，代码里跳过，固定 `-1` 这一轮即告完成。
    * 取消固定 `-1` 后改固定 `0`，此时只剩 `0` 与 `0` 可固定，但剩余两数之和是 3 与目标对不上，搜索结束。

### 固定范围的上界

* **代码改动量**
    * 把三数之和的代码整体拷过来，递归方法与两数之和部分一并复制即可。
    * 实际只需要改动一处：数字个数 `n` 从 3 改为 4。

* **第二个固定位 `k` 的边界**
    * 四数之和时 `k` 从 `i` 到 `n - 2` 结束，后面还得留 3 个数给两数之和。
    * 三数之和时 `k` 从 `i` 到 `n - 1` 结束，后面还得留 2 个数给两数之和。
    * 让同一个方法通用，上界就写成「数组长度减去 `n - 2`」。

```java
// k 是要固定的第 2 个数字的下标
// 四数之和（n = 4）：k 从 i 到 n - 2 结束，后面还得留 3 个数给两数之和
// 三数之和（n = 3）：k 从 i 到 n - 1 结束，后面还得留 2 个数给两数之和
for (int k = i; k < nums.length - (n - 2); k++) {
    // 跳过与前一个相同的值，去重
}
```

* **收益**
    * 收窄边界能减少固定次数，是正确性之外的一个小优化。

## 盛水最多容器

* **题目形态**
    * 第 11 题：数组中的数字代表挡板高度，在不同的两块挡板之间灌水，求哪种灌法盛的水最多。
    * 示例中第一块与最后一块之间算出 8 单位，第二块与最后一块之间算出 49 单位，逐一试乘积取最大即可。

* **容量公式**
    * > **定义**：两根挡板之间的容量，由更矮的那根决定高度，由下标之差决定宽度，两者相乘就是这个组合能盛的水。

$$
\text{容量} = \min\bigl(height[i],\, height[j]\bigr) \times (j - i)
$$

### 只能动矮的那块板

* **移动规则**
    * 结论是距离变短的情况下，改动较高的挡板，容量一定减少。
    * 原因是高度取决于最矮的那根，动高板时高度不变而距离变短，容量必然缩小。
    * 反过来，只有把较矮的挡板朝中间移动，才有可能获得更大的容量。
    * 例证：把 0 号挡板换成 7 号挡板，距离从 `0~8` 缩短为 `0~7`，高度没变而距离变长的情况不存在，容量只会减少，所以 7、6、5、4、3、2、1 号挡板都不必尝试。
    * 不遵从原则把高板从 1 号换成 2 号，容量同样会降低。

* **双指针写法**
    * `i` 初始为 0 表示最左侧挡板，`j` 初始为数组长度减一表示最右侧挡板，另设 `max` 初值为 0 存最大容量。
    * 每轮按哪一侧更矮决定面积，并把更矮的那侧指针向中间移动，再与 `max` 取较大值。
    * 循环条件是 `i < j`，两指针碰头说明所有组合已尝试一遍，直接返回 `max`。

```java
public int maxArea(int[] height) {
    int i = 0;                  // 左指针：最左侧挡板
    int j = height.length - 1;  // 右指针：最右侧挡板
    int max = 0;                // 存储最大容量

    while (i < j) {             // 两个指针还没碰头，就不断尝试
        int area;
        if (height[i] < height[j]) {
            // 左边更矮：高度就是 height[i]，移动 i 才有可能变大
            area = (j - i) * height[i];
            i++;
        } else {
            // 右边更矮：高度就是 height[j]，移动 j
            area = (j - i) * height[j];
            j--;
        }
        // 每次算出来的容量都要跟原来的容量比，取更大的存进 max
        max = Math.max(max, area);
    }

    return max;
}
```

* **验证**
    * 给出的测试用例正确结果是最大容量 49，代码运行结果一致。

## 单调递减队列

* **定义**
    * > **定义**：单调队列是在普通队列基础上加了更多限制的结构，数据从队尾进入、从队头移除。
    * 单调递减队列中元素从头部到尾部按由大到小排列，例如 `7 6 5`。

### 入队先劝退队尾

* **offer 的限制**
    * 向队尾加入元素前，必须先把队列中破坏单调递减特性的元素从尾部移除，移除完才能放入新元素。
    * 加入 1 不破坏单调性，可以直接入队。
    * 加入 3 之前要移除 `1`、`2`，加入后队列为 `7 6 5 3`。
    * 加入 8 之前原有的 `7、6、5、3` 全部违反单调性，要四个元素全移除再放入 8。

```text
加入 3 之前:   队头 ->   7   6   5   2   1   <- 队尾
                        └─ 把 1、2 移除 ─┘
加入 3 之后:   队头 ->   7   6   5   3   <- 队尾
```

* **poll 无限制**
    * 从队头移除元素的 `poll` 方法没有任何限制，直接移除即可，例如队中两个 8 和 7 移除头部 8 后剩下 7。
    * 上述限制只针对尾部加入的 `offer` 方法。

### 三个方法

* **借 LinkedList 实现**
    * 三个方法分别是 `peek` 获取队头、`poll` 移除并返回队头、`offer` 向队尾添加元素。
    * 不从零开发，借现成的 `LinkedList` 的双端队列功能：`peek` 调 `peekFirst`，`poll` 调 `pollFirst`，`offer` 调 `offerLast`。
    * 最麻烦的是 `offer`：循环判断队列非空且 `peekLast` 小于待加入值 `t` 就 `pollLast` 移除，直到找到比 `t` 大的元素或队列被移空才退出循环，退出后再 `offerLast(t)`。

```java
public class MonoQueue {

    // 用 LinkedList 充当双端队列：头尾都能操作
    private final LinkedList<Integer> dq = new LinkedList<>();

    // 从头部获取元素，但不移除
    public Integer peek() {
        return dq.peekFirst();
    }

    // 从头部移除并返回
    public Integer poll() {
        return dq.pollFirst();
    }

    // 从尾部添加元素——最麻烦的就是这个
    public void offer(int t) {
        // 先检查队列不为空，并且尾部元素比要添加的 t 小，就把它移除
        // 直到找到比 t 大的为止，或者队列被移空，才退出循环
        while (!dq.isEmpty() && dq.peekLast() < t) {
            dq.pollLast();
        }
        dq.offerLast(t);
    }
}
```

* **入队走查**
    * 测试数组 `[1, 3, -1, -3, 5, 3, 6, 7]` 依次循环调用 `offer` 并打印队列。
    * 加入 1 直接成功；加入 3 时 1 违反单调性先被移走；加入 -1、-3 都比前一个小，直接入队。
    * 加入 5 比 `3、-1、-3` 都大，三者被全部移除；加入 3 比 5 小，直接入队。
    * 加入 6 比 `5、3` 都大，两者被移除；最后加入 7 把 6 移除，整个过程确实是单调递减的。

## 滑动窗口最大值

* **题目形态**
    * 给定数组 `[1, 3, -1, -3, 5, 3, 6, 7]` 和大小为 `k` 的滑动窗口，示例中 `k` 等于 3。
    * 窗口每次向右移动一格，窗口内凑满 `k` 个数字就计算并记录一次最大值。
    * 正确结果是 `3 3 5 5 6 7`，对应的记录过程是 `3、3、5、5、6、7`。

### 队头就是答案

* **原理**
    * 只要每次窗口右移时把新元素加入单调队列，队头元素就是当前窗口的最大值。
    * 比队头小的元素为了满足队列单调性早已被挤掉，所以队头不会小于窗口内其他元素。

```text
  数组:  1    3    -1    -3    5    3    6    7
         |    |    |     |     |    |    |    |
  加入后队列:
         [1]
         [3]        <- 1 被 3 挤掉
         [3  -1]
         [3  -1  -3]  <- 队头 3 = 窗口 [1,3,-1] 的最大值
         [5]         <- 3 -1 -3 全被 5 挤掉, 队头 = 5
         [5  3]
         [6]
         [7]

  队头依次为:  3    3    5    5    6    7
```

* **走查**
    * 加入 1 后队列为 `[1]`；加入 3 时 1 违反单调性被移除，队列为 `[3]`；加入 -1 满足单调性，队列为 `[3 -1]`。
    * 此时窗口已装满三个元素，队头 3 就是窗口 `[1, 3, -1]` 的最大值。
    * 加入 -3 后队列为 `[3 -1 -3]`，队头仍是 3；加入 5 把 `3、-1、-3` 全挤掉，队头变为 5。
    * 加入 3 后队头仍是 5；加入 6 挤掉 `5、3`，队头变为 6；最后一次窗口把 6 移除、加入 7，队头为 7。

### 窗口装满才取

* **判定条件**
    * 一开始就取队头会多出一个 1 和一个 3，因为最初窗口还没凑满 `k` 个元素。
    * 窗口大小为 3 时索引移到 `i` 等于 2 才算装满，所以判定要写成 `i >= k - 1` 而不是写死 2。
    * 窗口大小若为 4 就应从索引 3 开始，与 `k - 1` 的写法吻合。

```java
public int[] maxSlidingWindow(int[] nums, int k) {
    MonoQueue dq = new MonoQueue();     // 单调递减队列
    List<Integer> res = new ArrayList<>();

    for (int i = 0; i < nums.length; i++) {
        // ① 新元素进队：队尾所有比它小的都被挤掉
        dq.offer(nums[i]);

        // ② 窗口凑满 k 个元素以后，队头才是这个窗口的最大值
        if (i >= k - 1) {
            res.add(dq.peek());
        }
    }

    return res.stream()
            .mapToInt(Integer::intValue)
            .toArray();
}
```

* **结果转换**
    * 先把每次的最大值收进循环外创建的 `res` 列表，最后借流的 API 转成题目要求的 `int` 数组。
    * 先 `stream`，再 `mapToInt(Integer::intValue)` 把包装类型 `Integer` 转成基本类型 `int`，最后 `toArray`。

### 队头过期了

* **漏洞表现**
    * 在 3 和 5 之间多插一个 4 之后，程序算出的结果是 `3 3 3 5 5 6 7`。
    * 第三个最大值错了：此时窗口内最大值应是 4，而队列里还留着上一窗口的队头 3，于是取到了已经过期的 3。

* **判定方法**
    * `i - k` 正好是滑出窗口的上一个元素的下标。
    * 当 `i >= k` 且队头等于 `nums[i - k]` 时，说明队头已滑出窗口范围，把它 `poll` 掉。
    * 加 `i >= k` 是为了保证 `i - k` 不越出数组的有效索引。
    * 这段判断要放在 `offer` 之前执行。

```java
// 放在 offer 之前：滑出窗口的那个元素如果还在队头，就把它剔除
if (i >= k && dq.peek() == nums[i - k]) {
    dq.poll();
}
```

* **不能改用队列长度**
    * > **易错点**：⚠️ 队头是否过期只能靠 `dq.peek() == nums[i - k]` 判定，并保证 `i >= k`。
    * 用「队列长度是否大于 `k`」判断不可靠：把测试数据换成 1 之后，1 会把前面的 3 和 -1 都挤掉，队列长度不足 `k`，可此时队头元素其实也已经出窗口。
