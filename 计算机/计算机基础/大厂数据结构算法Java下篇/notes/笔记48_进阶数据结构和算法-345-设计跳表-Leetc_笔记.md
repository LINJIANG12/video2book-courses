## 概率逐级减半的随机取值

* **逐级减半的随机取值**

    * > **定义**：设计一个方法，从 1 到 `max`（`max` 是参数）中随机返回一个数字，要求从 1 开始、数字越大被返回的概率逐级减半。

    * 当 `max = 4` 时的目标分布：

| 返回值 | 1 | 2 | 3 | 4 |
| :--- | :---: | :---: | :---: | :---: |
| 概率 | 约 50% | 约 25% | 约 12.5% | 约 12.5% |

* **概率减半的构造过程**

    * 固定返回 1 时，1 占 100%；调一次 `Random.nextBoolean()`，为真返回 1、为假返回 2，就得到 1 与 2 各约一半。

    * 在返回 2 之前再做一次随机，就把 2 压到 25%、剩余 25% 分给 3 和 4。

    * 在返回 3 之前再做一次随机，就得到 3 和 4 各约 12.5%。

    * > **结论**：每多调一次 `nextBoolean()`，概率就减半。

    * 把这串逻辑塞进循环：定一个 `x` 表示最终要返回的数字、初值为 1，循环体内为真就返回当前 `x`，为假就 `x++` 继续往下走。

    * 循环终止条件是 `x < max`——`x` 等于 `max` 时退出循环，直接返回 `x`。

```java
public int randomLevel(int max) {
    int x = 1;
    while (x < max) {
        if (random.nextBoolean()) {
            return x;
        }
        x++;
    }
    return x;
}
```

* **实测与延伸**

    * 循环调用 1000 次的统计结果：1 约 51%、2 约 25%、3 和 4 各约 12.5%。

    * 把 `max` 改成 5 多生成一个数字后，4 和 5 的概率各约 6.25%，即 12.5% 再除以二，符合预期。

    * > **提示**：这个方法马上会在跳表里再出现一次，用来随机决定新节点的高度。

## 跳表的结构

* **跳表（Skip List）**

    * > **定义**：给单向链表式的有序节点集合中的每个节点装上多层 next 指针，用「上楼梯—下楼梯」的方式换取更高的增删改查效率。

    * 与单向链表相同的地方：也是以节点为单位来组织数据，头节点整个是一个对象、是一个节点，后面的 3、7 等也各自是一个节点。

    * 与单向链表不同的地方之一：跳表中这些节点是排好序的，3、7、11、12、16 是升序排好的；而单向链表没有这个约束，有序也行、无序也可以。

    * 与单向链表不同的地方之二：跳表中每个节点有多个 next 指针；单向链表里每个节点只有一个 next 指针，只能指向离它最近的那个元素。

    * 单向链表查 30 只能从头节点沿 next 一个一个向后找，查询时间复杂度是 $O(n)$。

* **层与高度**

    * > **定义**：某个节点被几层连着，这个节点就有几层、就是多高；读图时横向看是「这一层上每个节点连着的下一串」。

    * 最底层永远是一条完整的链，等价于一条单向链表；越往上节点越稀疏、next 的跨度也越大——这就是「跳」起来的地方。

    * 头节点在多层上都有 next 指针，其中最下面几层指向的是相邻的那个 3，上面几层指向的可能是更远的元素（比如 19）；最底层这些 next 指针指向的确实是相邻的节点。

    * > **结论**：给节点加了这么多 next 指针，为的就是更高效的增删改查。

```text
  层号      该层沿 next 从左到右的节点
  ------------------------------------------------------------------
  第 9 层    head
  第 8 层    head
  第 7 层    head ──▶ 19
  第 6 层    head ──▶ 19
  第 5 层    head ──▶ 19
  第 4 层    head ──▶ 19
  第 3 层    head ──▶ 19 ──▶ 26
  第 2 层    head ──▶ 3 ──▶ 7 ──▶ 11 ──▶ 12 ──▶ 16 ──▶ 19 ──▶ 26 ──▶ 30
  第 1 层    head ──▶ 3 ──▶ 7 ──▶ 11 ──▶ 12 ──▶ 16 ──▶ 19 ──▶ 26 ──▶ 30
  第 0 层    head ──▶ 3 ──▶ 7 ──▶ 11 ──▶ 12 ──▶ 16 ──▶ 19 ──▶ 22 ──▶ 25 ──▶ 26 ──▶ 30
```

* **节点类与 MAX 上限**

    * 节点有两个属性：`value` 用来存储它将来的值；`Node[] next` 是数组，用来表示多个 next 指针。

    * next 指针的个数需要一个上限，定义成静态常量 `MAX`，示例中定成 10，即最多每个节点有十个 next 指针。

    * 头节点的值无所谓，用 `new Node(1)` 即可，并不会用它来比较。

    * 实际中的取值：Redis 的 zset 结构里跳跃表这个 next 的上限是 32；Java 中的 `ConcurrentSkipListMap` 跳表结构上限更大一些，是 62。

    * > **提示**：示例中做了一点简化——创建每个节点对象时，这个 next 数组长度直接取上限 10；按理说头节点这样没问题，剩下的应该根据它实际的高度来定义数组大小，这里先不考虑空间浪费，换取实现上的简单。

```java
public class SkipList {
    // next 指针的个数上限
    private static final int MAX = 10;

    // 节点类，作为跳表的一个内部成员
    private static class Node {
        int value;
        Node[] next;

        Node(int value) {
            this.value = value;
            this.next = new Node[MAX];
        }
    }

    // 头节点的值无所谓，我们并不会用它来比较
    private final Node head = new Node(1);
}
```

## 下楼梯查找规则

* **查找方向的两条规则**

    * > **定义**：跳表的查找从头节点「从上往下」，按「下楼梯」规则进行，由向下找和向右找两条规则组成。

    * 向下找的条件：`next` 指针为 `null`，或者 `next` 指向的节点值大于等于要查找的目标。

    * 向右找的条件：`next` 指针不为 `null`，并且 `next` 指向的节点值小于目标值。

    * > **提示**：两条规则是互斥的，向右找的条件是「指针不为 `null` 且指向的值小于目标」，向下找的条件是「指针为 `null`，或指向的值大于等于目标」，两者正好互补，所以向右找的条件不成立时它肯定就是该向下找，不必再多写一个显式的向下判断。

* **按规则走一遍找 30**

    * 从头节点开始，最上面两层的 next 都是 `null`，所以向下。

    * 到第 7 层，head 的 next 指向 19，19 小于 30，向右走到 19 节点；19 的这几层 next 都是 `null`，继续向下。

    * 到第 3 层，19 的 next 指向 26，26 还是小于 30，继续向右走到 26。

    * 26 这边几个 next 有的是 `null`，得向下；找到一个不为 `null` 的，看它指向的节点值是不是大于等于目标——是的，所以仍然要向下，一直向下找到底。

    * 到第 0 层了，26 还是小于目标，向右看一格就是 30。

```text
  目标 30：  head ──向下──▶ 19 ──向下──▶ 26 ──向右──▶ 30
               （算上最终命中的 30，一共只经过 4 个节点）
```

* **换成单向链表的差别**

    * 同一次查询换成单向链表，得经历前面所有的节点才能到达目标，慢多了。

## find 与查找路径

* **查找主循环**

    * 设一个临时变量 `current` 表示当前节点，从头节点出发；`head` 是固定不变的，`current` 在查找过程中会变成 19、再变成 26。

    * 用一个变量 `level` 表示当前在第几层，从 `MAX - 1` 递减到 0——因为 `MAX` 是数组长度上限，最上面那层的索引就是 `MAX - 1`。

    * 在每一层里往右走，走的条件是：next 不为 `null`，并且 next 指向的值小于目标。

    * 怎么拿到「当前这一层」的 next 分两步：`current.next` 拿到当前节点的 next 数组属性，`next[level]` 拿到当前层的那一根。

```java
private Node find(int value) {
    Node current = head;
    for (int level = MAX - 1; level >= 0; level--) {
        // 向右找：不指向 null，且指向的节点值小于目标
        while (current.next[level] != null && current.next[level].value < value) {
            current = current.next[level];
        }
    }
    return current;
}
```

* **向右找为什么必须用 while**

    * 找 30 时看不太出来，因为 19 的 next 又是 `null` 了，它马上又会向下走。

    * 换成找 11：先向下找到一个 next 不为 `null` 的层，开始向右找——next 指向的 3 小于 11，要继续向右；再看 7 也小于 11，仍然继续；一直到 16，因为 16 不小于 11 了，这时候才向下去找。

    * 一行 `if` 只能挪一步（挪到 7 就结束了），必须写成 `while`，才能一直向右找，直到找到比目标大的才去向下找。

    * > **易错点**：这里必须用 `while`，不能写成 `if`。

* **退出循环时 current 的位置**

    * 退出最外层 `for` 循环时，`level` 肯定等于 0，所以找到的是最底层的节点。

    * 又因为 while 卡的条件是「小于目标」，`current` 一定是小于目标值的那个节点。

    * 找 30 退出循环时 `current` 应该是 26；找 11 应该是它前面的 7。

* **顺手记录查找路径**

    * 添加、删除都要复用查找过程，所以 `find` 得**多做一件事**：把查找过程中经历的路径记录下来。

    * 定一个叫 `pass` 的数组表示所经过的路径，长度就是 `MAX`；每次经过的节点就是 `current`，在 `pass` 的 `level` 层记录当时 `current` 指向的节点。

    * 这个 `pass` 后面会在其他方法里用到，所以直接作为整个方法的返回值返回。

```java
private Node[] find(int value) {
    Node current = head;
    Node[] pass = new Node[MAX];
    for (int level = MAX - 1; level >= 0; level--) {
        while (current.next[level] != null && current.next[level].value < value) {
            current = current.next[level];
        }
        pass[level] = current;
    }
    return pass;
}
```

    * 以 10 层为例（最底层编号 0、最上层编号 9）：第 9、8 层经过头节点，第 7、6、5 层经过头节点，第 4 层经过 19，第 3、2、1、0 层经过 26。

```text
  pass[9] pass[8] pass[7] pass[6] pass[5] pass[4] pass[3] pass[2] pass[1] pass[0]
    head   head    19     19     19     19     26     26     26     26
```

    * 0、1、2、3 这几层对应 26，往上四层对应 19，最上面这两层对应头节点，正是按规则走一遍时经过的那些节点；到这里 `find` 才算完全实现。

## search 查询

* **只用路径最底层的那个节点**

    * > **定义**：查询方法里绝大部分活儿由 `find` 做完，调用它之后只需要取路径第 0 层的那个节点就够了，也就是通过 `pass[0]` 拿到路径中最底层的节点（找 30 时就是 26）。

    * 但这还不是答案：路径里所有的值都是比目标值小的，还得再去调它的 next 指针才能找到下一个节点。

    * next 指针同样有好几根，这里也取第 0 层这一根：`pass[0].next[0]`，这才是最终要检查的节点对象——图上那个 30。

* **最后一次比较的两种情况**

    * 还要把 `pass[0].next[0]` 跟要查找的目标做最后一次比较，因为前面一直在做「小于」的比较，并不能确定这个时候节点的值就真的等于目标值。

    * 还有一种可能：`pass[0].next[0]` 有可能是 `null`，因为上一个节点的 next 指针有可能指向 `null`，也就是它已经是最后一个节点了，我们这个节点是不存在的。

    * 只有 `node` 不为 `null`、并且 `node` 的值等于目标值的时候才返回真；否则就相当于没有找到，返回假。

```java
public boolean search(int value) {
    Node[] pass = find(value);
    Node node = pass[0].next[0];
    return node != null && node.value == value;
}
```

## 节点高度随机化

* **高度为什么要高矮不一**

    * > **结论**：高度不能让所有节点一样，应该高矮不一、错落有致；最好是符合一个规律——矮的高度出现几率更大一些，高度越高的节点出现几率更小一些。

    * 举例：查找 22 时，头节点向下走两格、向右走到 19、向下走到底、最后向右一格就找到 22，这个查询性能看起来还可以。

    * 假如 19 之前的节点都跟 19 一样高（3、7、11、12、16 都这么高），查找 22 就得先跟 3 比、跟 7 比、跟 11 比、跟 12 比、跟 16 比、跟 19 比，才能向下再找到 22，比较次数反而多了。

    * 需要的概率分布是：50% 的几率返回高度 1，25% 的几率返回高度 2，更高则几率更小。

    * 所以添加节点时高度应该**随机生成**，随机的方法就用前面那个 `randomLevel` 方法。

## add 添加

* **添加的三步**

    * > **定义**：添加节点主要做三件事——确定添加位置、创建新节点并产生一个随机的高度值、修改新节点和这些路径节点的 next 指针。

    * 第一步确定添加位置：把待添加的值当成一个目标值，用 `find` 方法来查找它，查找过程中确定的那一串路径节点就是该值要放的位置。

    * 第二步给新节点设置高度：高度是随机的，为了看得清楚讲解时把它固定成 5；实际实现中高度不能超过 `MAX`。

    * 第三步改 next 指针：15 自己的这几层 next 要改，它所经历的那些路径节点的 next 值也要改——相当于 15 接替了原来路径节点在这一层的位置。

```text
  改之前：  head ──▶ 19        12 ──▶ 16
  改之后：  head ──▶ 15 ──▶ 19    12 ──▶ 15 ──▶ 16
```

* **改指针的顺序**

    * 先把同层路径节点的 next 值复制给新节点，再让路径节点指过来，这两步完成的就相当于「插队」，顺序不能颠倒。

    * 循环从最底层 0 开始，一直循环到小于 `level` 为止，因为新节点只有 `level` 层高。

```java
public void add(int value) {
    // 第一步：确定添加位置，就是 find 出来的这些路径节点
    Node[] pass = find(value);

    // 第二步：创建新节点，并产生一个随机高度值（不能超过 MAX）
    Node node = new Node(value);
    int level = randomLevel(MAX);

    // 第三步：修改 next 指针，从最底层 0 开始，循环到小于 level
    for (int i = 0; i < level; i++) {
        // 新节点这一层的 next，改成同层路径节点在这一层的 next 值
        node.next[i] = pass[i].next[i];
        // 同层路径节点的 next，指向新节点
        pass[i].next[i] = node;
    }
}
```

* **改指针的循环边界**

    * 修改 next 指针时不是从 0 到 `MAX` 全都改，新节点有多高就只改这么高范围内的 next 指针，更高的不用管。

    * > **易错点**：写循环时应该从最底层 0 开始，一直循环到小于 `level` 为止，而不是循环到 `MAX`。

## delete 删除

* **删除的思路**

    * 删除逻辑跟添加差不多：先找到要删除的节点，也就是把它前面这些路径节点先都找出来，`find` 这个方法可以重用好多次。

    * 找到之后要做的事情，就是把这些路径节点的 next 指针改成指向被删除节点的 next 指针，相当于把它绕过去了。

    * 从这儿过去没有人再指向这个被删除节点，将来这个节点没人引用它，就相当于从跳表中删除了。

* **目标不存在的判定**

    * 拿路径最底层的那个节点 `pass[0]`，看一下它的 `next[0]` 是不是要删除的节点。

    * 如果是 `null`，说明这个删除的节点不存在；或者是节点的值不等于要删的值，也相当于没找到目标，这两种情况都返回 `false`。

    * 举例：要删的是 14，找到前面这些路径之后，得先检查 12 的 next 是不是 14，是 14 才走删除流程，不是就直接返回 `false`。

```java
public boolean delete(int value) {
    Node[] pass = find(value);
    Node node = pass[0].next[0];
    if (node == null || node.value != value) {
        return false;
    }

    // 修改这些路径节点的 next 指针
    for (int i = 0; i < MAX; i++) {
        if (pass[i].next[i] == node) {
            pass[i].next[i] = node.next[i];
        } else {
            break;
        }
    }
    return true;
}
```

* **循环边界靠 break 兜住**

    * 这个循环不是一直循环到 `MAX` 就完事，只循环到被删节点的高度为止。

    * 但这个高度并没有作为属性记录在节点当中，所以判断时只能这样：循环到某个路径节点时，如果它指向的已经不是被删除的节点了（比如已经指向了 19），说明这时候高度到头了，直接 `break` 退出循环。

    * > **易错点**：删除时不能无条件循环到 `MAX`，必须在路径节点不再指向被删节点时 `break`。

## 最小栈

* **最小栈（Min Stack）**

    * > **定义**：设计一个栈结构，支持栈常见的 `push`、`pop`、`top` 这些操作，并要求能在常数时间内找到栈中的最小元素（`getMin`）。

    * 难点只在常数时间找最小值：如果一个一个依次去比较就不满足题目要求。

    * > **结论**：核心思路是「把元素放入**时**的最小值记录下来」，用的时候直接从记录下来的最小值里找。

### 双栈解法

* **结构与原理**

    * > **定义**：再设置一个栈专门记录每个元素放入时的最小值，与原始元素栈一一对应，找最小值时直接去看这个栈的栈顶。

    * 以依次放入 2、1、3、4 为例：放入 2 时最小值是 2；放入 1 时找到一个更小的，最小值更新成 1；放入 3、4 时最小值都还是 1。

    * 两个栈都用 `LinkedList`，里面放的都是整数；原始栈叫 `stack`，保存最小值的栈叫 `minStack`。

    * 一开始给最小值栈先放一个 `int` 的最大值 `Integer.MAX_VALUE`，它是为了第一次比较用的，所以写在构造方法里。

| 操作 | 原始栈（栈顶在右） | 最小值栈（栈顶在右） | getMin |
| :--- | :--- | :--- | :---: |
| push 2 | 2 | 2 | — |
| push 1 | 2 1 | 2 1 | 1 |
| push 3 | 2 1 3 | 2 1 1 | 1 |
| push 4 | 2 1 3 4 | 2 1 1 1 | 1 |
| pop 4 | 2 1 3 | 2 1 1 | 1 |
| pop 3 | 2 1 | 2 1 | 1 |
| pop 1 | 2 | 2 | 2 |

* **方法实现**

    * `push` 时原始栈直接放进去就行；最小栈则取 `Math.min(minStack.peek(), val)` 作为新的栈顶。

    * `pop` 从原始栈弹出一个元素时，最小栈的这个元素也一起弹出去，两者同步弹出；并且要先判断原始栈是否为空，避免把最后那个 `Integer.MAX_VALUE` 弹掉。

    * `top` 是获取原始栈的栈顶元素，直接调原始栈的方法；`getMin` 直接拿最小栈的栈顶元素。

    * 剩下的这两个方法没有做非空检查，题目里也不会出现空的情况。

```java
public class MinStack {
    private final LinkedList<Integer> stack = new LinkedList<>();
    private final LinkedList<Integer> minStack = new LinkedList<>();

    public MinStack() {
        // 先铺设一个整数的最大值，是为了第一次比较用的
        minStack.push(Integer.MAX_VALUE);
    }

    public void push(int val) {
        // 原始栈：直接放进去就完了
        stack.push(val);
        // 最小栈：拿到栈顶元素，与待放的值取一个更小的，作为新的栈顶
        minStack.push(Math.min(minStack.peek(), val));
    }

    public void pop() {
        // 别把最后那个 MAX 弹掉了
        if (stack.isEmpty()) {
            return;
        }
        stack.pop();
        minStack.pop();      // 两者同步弹出
    }

    public int top() {
        return stack.peek();
    }

    public int getMin() {
        return minStack.peek();
    }
}
```

    * 串起来看：第一次 `push` 时 `Math.min` 拿到的是 `MAX`，那相当于就把 `value` 作为最小值放进栈了（比如 2）；下一次放入 3 比栈顶的 2 还大，放进去的还是 2；下次放入 1 比栈顶的 2 更小，这回就把 1 更新到栈顶，最小值栈的栈顶元素就维护好了。

    * > **提示**：原始栈这边发生变化，保留最小值的栈也跟着变化；把 4 弹出之后找最小值还是找这边的栈顶元素，仍能找到最小值 1；继续把 3 弹出，最小值还是 1；1 弹出之后，这边的栈顶就又保存到当时的那个最小值 2 了。

### 单栈 record 解法

* **结构与原理**

    * > **定义**：解法跟双栈差不多，只是把每次放入的元素跟它的最小值作为一个整体放入同一个栈，这样就只使用一个栈结构了。

    * 以依次放入 2、3、1、4 为例：放入 2 时栈是空的，2 自己就是最小值，把 (2, 2) 放进去；放入 3 时最小值还是 2，把 (3, 2) 放进去；放入 1 时最小值更新成 1，把 (1, 1) 放进去；放入 4 就把 (4, 1) 作为一个整体放入栈。

    * 弹出的时候直接弹出就完了，少用一个栈结构。

    * 栈里不能放整数了，因为既要保留原始值又要保留最小值，所以自定义一个 `record Data(int value, int min)`。

    * `record` 是 JDK 14 引入的新语法，会自动生成属性的访问器方法以及 `toString`、`hashCode` 等方法，比较简便；而且它的值相当于不能更改，里面的值都是 `final` 的。

* **方法实现**

    * `push` 分为首次和后续两种：栈为空时这个 `value` 自己就是最小值，直接 `new Data(val, val)` 推进去。

    * 栈不为空时到栈顶找到这个最小值，跟新放的值取一个更小的，原始值还是 `val`，最小值是 `Math.min(top.min(), val)`。

    * `pop` 直接 pop 就完了，只需要 pop 一次；`top` 是取得这个栈顶元素的原始值 `value()`；`getMin` 也是先 `peek()` 拿到栈顶元素，再调它的 `min()` 属性拿到最小值。

```java
public class MinStack {
    // JDK 14 引入的新语法，值不可变（都是 final 的）
    private record Data(int value, int min) {}

    private final LinkedList<Data> stack = new LinkedList<>();

    public void push(int val) {
        if (stack.isEmpty()) {
            // 刚开始栈为空时，这个 value 自己就是最小值
            stack.push(new Data(val, val));
        } else {
            Data top = stack.peek();
            // 原始值还是 val，最小值在栈顶的 min 和 val 之间取一个更小的
            stack.push(new Data(val, Math.min(top.min(), val)));
        }
    }

    public void pop() {
        stack.pop();          // 这回只需要 pop 一次
    }

    public int top() {
        return stack.peek().value();
    }

    public int getMin() {
        return stack.peek().min();
    }
}
```

### 随机返回的热身题

* **题干**

    * 设计一个方法，从 1 到 `max`（`max` 是参数）中随机返回一个数字，要求从 1 开始，数字越大被返回的概率逐级减半。

    * 比如 `max = 4` 时，返回 1 约 50%、返回 2 约 25%、返回 3 和 4 各约 12.5%。

* **解析与答案**

    * 每调一次 `random.nextBoolean()`，剩余区间就砍掉一半，于是把判断塞进 `while (x < max)` 循环里。

    * `x` 从 1 开始，为真就返回、为假就自增；`x` 等于 `max` 时退出循环并返回 `max`。

### 设计跳表（Leetcode 1206）

* **题干**

    * 设计一个跳表，实现 `search(int num)`、`add(int num)`、`delete(int num)` 三个方法。

    * `search` 根据一个值去跳表中查询，查到返回真、查不到返回假；`add` 把一个值加入跳表；`delete` 从跳表中删除一个值，值存在就删除掉并返回真，不存在就返回假。

* **解析与答案**

    * 节点是 `value` 加一个长度为 `MAX` 的 `Node[] next`。

    * 查找统一走 `find(value)`，它按「下楼梯」规则从 `MAX - 1` 层降到第 0 层，沿途把经过的节点记进 `pass[level]`。

    * `search` 取 `pass[0].next[0]` 做最后一次比较。

    * `add` 用 `randomLevel(MAX)` 决定新节点高度，然后改 `node` 和 `pass` 两边的 next。

    * `delete` 先验证 `pass[0].next[0]` 就是目标，再把各层 `pass[i].next[i]` 改指到被删节点的 next。

### 最小栈（Leetcode 155）

* **题干**

    * 设计一个栈，支持 `push`、`pop`、`top` 这些常用操作，并且要求在常数时间内找到栈中的最小元素（`getMin`）。

* **解析与答案**

    * 核心是「把元素放入**时**的最小值记录下来，用的时候直接从记录里找」。

    * 解法一：开两个栈（原始栈 + 最小值栈），两者同步出入，最小值栈的栈顶就是当前最小值，构造时先 `push(Integer.MAX_VALUE)` 作为第一次比较的基准。

    * 解法二：只用一个栈，把原始值和当时的最小值捆成一个不可变的 `record Data(int value, int min)` 整体入栈，取值时分别读 `value()` 和 `min()`。
