# 基础算法-219-排序算法-基数排序2

## 基数排序 LSD 的实现机制

### 逐位分桶的外层循环

* **位序与字符串索引的方向**

    * > **定义**：基数排序每轮只按字符串的某一位把元素分好类；位序是个位、十位、百位往上数，字符串索引则从 0 开始往上加，两者方向恰好相反。

    * 排个位时取字符串索引 2 的字符，排十位取索引 1，排百位取索引 0。

    * `charAt` 里那个写死的数字就是「当前在排第几位」，因此不必一个一个手改，直接在代码最外层套一个循环。

    * > **易错点**：不要把「位序」和「索引」搞反，`charAt` 取的下标是从大到小的。

* **三轮循环的取值**

    * `i` 从 2 开始，每轮减一，一直减到 0 为止，循环体里的 `charAt` 改成 `charAt(i)`。

    ```java
    for (int i = 2; i >= 0; i--) {
        // 把 a[j] 按照 a[j].charAt(i) 这个字符分桶
        // 再按桶号 0..9 依次取回，写回 a
    }
    ```

    * 第一轮 `i == 2` 取个位数据，第二轮 `i == 1` 取十位数据，第三轮 `i == 0` 取百位数据，三轮走完整个序列排好。

    * 三轮的实测结果是：跑完第一轮打印出的是个位序列 `1 5 8 8 9 9`，跑完第二轮是十位序列 `3 3 3 5 5 5`；第三轮这批测试数据的百位全是 1，全部落在同一个桶里，次序自然一动不动。

    ```text
    第 1 轮  i = 2   按个位分桶 -> 按桶号 0..9 取回 -> 写回 a
    第 2 轮  i = 1   按十位分桶 -> 按桶号 0..9 取回 -> 写回 a
    第 3 轮  i = 0   按百位分桶 -> 按桶号 0..9 取回 -> 写回 a
    ```

* **给高位的次序制造区分度**

    * 把其中一个 `135` 故意改成 `235`，让百位不再全落在同一个桶里。

    * 十位那一轮 `235` 和 `138` 的十位都是 3，落在同一个桶里，谁在前谁在后照旧，`235` 还是压在 `138` 前面；百位那一轮排出来是前面五个 1、后面一个 2，`235` 于是被甩到最后一档。

    * > **结论**：一轮稳定排序只能保证「一位」的次序，前面轮次排好的位次不会被后面轮次破坏——这正是 LSD 能成立的地基。

### 每轮的操作序列

* **稳定性的作用**

    * 同桶内保持原有先后，这就是稳定的关键。

    * 桶本身就是有序的，从 0 号桶往 9 号桶走一趟，取出来的自然就是这一位排好的次序，不需要再做比较。

* **完整的分桶—取回流程**

    * 准备 10 个桶（0 号桶 ~ 9 号桶）。

    * 重复 `length` 轮：清空所有桶；遍历原数组，按 `a[j].charAt(i)` 把每个字符串丢进对应的桶；按桶号 0 到 9 依次把字符串取出，写回原数组。

    * > **易错点**：每一轮结束的时候必须把桶清一遍，不然上一轮的残留会混进这一轮。

    ```text
    准备 10 个桶（0 号桶 ~ 9 号桶）

    重复 length 轮：
        +- 清空所有桶
        +- 遍历原数组，按 a[j].charAt(i) 把每个字符串丢进对应的桶
        |     桶号从 0 到 9 排好，同桶内保持原有先后 —— 这是稳定的关键
        +- 按桶号 0 -> 9 依次把字符串取出，写回原数组
    ```

* **代码骨架**

    * `String[][] buckets = new String[10][length]` 一次性备好 10 个桶，每个桶的长度跟原数组一致。

    * `int[] sizes = new int[10]` 记录每个桶当前装了几个元素，每轮开头用 `Arrays.fill(sizes, 0)` 清零。

    * 桶号由字符换算得到：`int idx = a[j].charAt(i) - '0';`，然后 `buckets[idx][sizes[idx]++] = a[j]`。

    ```java
    public static void radixSort(String[] a, int length) {
        // 第一步：准备好 10 个桶，每个桶的长度跟原数组一致
        String[][] buckets = new String[10][length];
        int[] sizes = new int[10];

        // 第二步：多轮稳定排序，i 从 length - 1 一路减到 0
        for (int i = length - 1; i >= 0; i--) {
            Arrays.fill(sizes, 0);                       // 每轮先清桶

            for (int j = 0; j < length; j++) {           // 分桶
                int idx = a[j].charAt(i) - '0';
                buckets[idx][sizes[idx]++] = a[j];
            }

            int k = 0;
            for (int idx = 0; idx < 10; idx++) {         // 按桶号依次取回
                for (int j = 0; j < sizes[idx]; j++) {
                    a[k++] = buckets[idx][j];
                }
            }
        }
    }
    ```

### 桶容量与桶内起始位置

* **桶个数按字符集上界来定**

    * 前面这套 10 个桶的前提是只能装 `0`~`9` 这十个数字字符，可将来待排的字符串未必只含数字字符，它可能混着 `a`、`b`、`c`、`d`，甚至带一些加减乘除这类符号。

    * ASCII 码范围是从 0 到 127，索性把桶的数目改成 128 个：`String[][] buckets = new String[128][length];`，就能存 0~127 之间的任何字符。

    * 好处不止「装得下」：根据字符去找桶索引时连转换都省了。以前要写 `charAt(i) - '0'` 换算成桶号，现在直接把 `'0'` 对应的 48 当成索引即可，`int idx = a[j].charAt(i);`。

    * > **结论**：桶的个数按字符集的上界来定，比按「当前用到的字符种类」来定更省心，也更通用。

* **桶内起始位置不要写死**

    * 数组长度是通过参数传进来的，起始值就该写成 `length - 1`，而不是拍一个具体数字上去，这样才更通用。

    * 桶的实际写入位置由 `sizes[idx]` 给出，每轮开头清零，因此 `sizes[idx]++` 的取值天然落在 `0 ~ length - 1` 内。

* **换成手机号验证**

    * 因为每个号码都是 11 位，循环的起始值就跟着变成 `length - 1`（也就是 10），`i` 从 10 一路走到 0，一共十一轮。

    * 这批号码的后八位都一样，都是 `12345678`，没啥可看的，只盯前三位，最终结果如下。

    ```text
    134  135  136  137  138  139  150  151  152  157
    ```

## 扫描方向与 LSD、MSD

### 高位优先为何失效

* **三个数上的三轮演算**

    * 拿 `110`、`088`、`009` 三个数先排高位再排低位：第一轮按百位分桶，`110` 进 1 号桶，`088` 和 `009` 进 0 号桶，按桶号取出得 `088 009 110`，结果已经不对。

    * 第二轮排十位，先把桶清空、在上一轮结果上继续：`088` 进 8 号桶、`009` 进 0 号桶、`110` 进 1 号桶，取出得 `009 110 088`。

    * 第三轮排个位：`009` 进 9 号桶、`110` 进 0 号桶、`088` 进 8 号桶，取出得 `110 088 009`，彻底反了——`110` 是最大的却排到最前面，`009` 应该是最小的却掉到最后面。

* **错误的根源**

    * > **易错点**：先高位、后低位之所以错，是因为**轮数越靠后，优先级越高**；最后才排个位，个位的优先级就最高，于是它拿个位这个错误的结果，把前面已经正确的高位结果整个覆盖掉了。

### 两种计数排序算法的分工

* **MSD（最高有效数字，Most Significant Digit）**

    * > **定义**：MSD 是基数排序的另一种计数排序算法，扫描方向为从高位往低位排。

    * 要在现有这套 LSD 基础上做相当大的改动，才能实现从高位向低位排。

* **LSD（最低有效数字，Least Significant Digit）**

    * > **定义**：LSD 从低位往高位排，是课堂上主要介绍的写法。

    * 之所以只能从低位往高位排，见高位优先失败的三轮演算。

## Arrays.sort 的策略组合

### 不是单一算法而是组合

* **Arrays.sort 的实现取向**

    * > **结论**：`Arrays.sort` **不是**采用了某一种排序算法，而是**组合了多种排序算法**；在不同的数据量、不同的数据类型下，它会采用不同的排序策略。

* **组合的依据**

    * JDK 中的排序算法针对不同的数据类型、针对不同的数据量，采用当下更为合适的那一个。

    * Java 里的排序主要体现在 `Arrays` 工具类的 `sort` 方法上。

### JDK 7 到 JDK 13 的策略阈值

* **基本类型数组的分流规则**

    | 数组类型 | 元素个数很小 | 元素个数继续增大 |
    | :--- | :--- | :--- |
    | `int` / `long` / `float` / `double` | 小于 47 时，用一种改进后的插入排序 | 47 ~ 286 用双基准点快排；大于等于 286 再分两种情况，有序度高用归并排序，有序度低仍然用双基准点快排 |
    | `byte` | 小于等于 29 时，用插入排序 | 大于 29 直接用计数排序 |
    | `char` / `short` | 小于 47 时，用插入排序 | 47 ~ 286 的部分与上面类似；286 ~ 3200 之间，有序度高用归并排序、有序度低用双基准点快排；大于 3200 用计数排序 |

* **`byte` 一行印证计数排序的适用条件**

    * 计数排序特别适合数据范围小的情况，而 `byte` 的取值范围就 256 个，再多没有了，所以配合计数排序比较合适。

* **引用类型数组的两种情况**

    * 如果 JVM 参数里设置了对应的开关，就采用传统的归并排序；默认（没有采用这个参数）的情况下用的是 **TimSort**。

    * TimSort 本身是归并排序加上插入排序的组合——数据量小的时候用插入排序，数据量大用归并排序。

### JDK 14 到 JDK 20 的改动

* **改动总貌**

    * 从 JDK 14 开始到最新的 JDK 20，主要是数据量的边界条件挪了位置，另外还多了一层兜底策略。

    | 数组类型 | 规则 |
    | :--- | :--- |
    | `int` / `long` / `float` / `double` | `size < 44` 且排序区域是最左侧那块区域，用传统插入排序；`size < 65` 且排序区域不是最左侧，用混合插入排序；再往上按有序度高分流为归并排序 / 双基准点快排，**递归次数一旦超过 384 次就改用堆排序** |
    | `byte` | 数量非常小用插入排序；超过 64 用计数排序（以前的边界是 29，现在变成 64 了，整体思路没变） |
    | `char` / `short` | 元素个数大于 1750 用计数排序；小于 44 用插入排序；夹在中间的按有序度分流，递归次数超过 384 次改用**计数排序** |
    | 引用类型 | 没有太大的修改：设了参数用传统归并排序，默认（没加这个参数）用 TimSort |

* **384 次递归这一层兜底的用意**

    * 前面讲快排时说过，递归次数一变多整个性能就会变差，所以加了个保险——一旦发现递归次数过多，就换一种更稳的算法兜底。

    * > **易错点**：不同类型兜底的策略不一样：四种基本类型（`int` / `long` / `float` / `double`）兜的是堆排序，`char` / `short` 兜的是计数排序。

### 并行排序与 JDK 21 预告

* **`parallelSort`**

    * 从 JDK 8 开始，`Arrays` 工具类在传统的 `sort` 方法之外新增了 `parallelSort`，也就是并行排序。

    * > **定义**：并行排序利用多核处理器的优势，内部使用多线程，把待排数组划分成多个部分，多个线程一起排。

    * 它适合数量很大的时候用。

* **JDK 21 的可能改动**

    * 从最近的 GitHub 提交记录来看，即将发布的 JDK 21 有可能引入基数排序这样的优化——在数量很大的时候采用基数排序，对排序算法做进一步的优化。

## 力扣 1122 数组的相对排序

### 排序规则与前提条件

* **排序规则**

    * > **定义**：给定 `arr1` 和 `arr2`，把 `arr1` 按 `arr2` 里的元素次序来排，而不是按大小顺序排。

    * `arr2` 里的每个元素在 `arr2` 中各不相同，也就是说它们各自的出现次数是唯一的。

    * 依次按 `arr2` 的次序分组，每组重复它自己在 `arr1` 中出现的次数。

    * > **注意**：`arr1` 里可能有 `arr2` 中没有的元素，这些「没有被点名」的元素统一按大小升序接在最后，先排小的再排大的。

    ```text
    arr2 = [2, 1, 4, 3, 9, 6]

    result = 2 2 2 2 | 1 1 | 4 4 | 3 3 | 9 | 6 | 7 | 9
                        ^ 按 arr2 的次序分组，每组重复它自己的出现次数
                                                       ^ 7、9 不在 arr2 里，按大小升序接在最后
    ```

* **题目给的前提条件**

    * 元素的取值都是大于等于零的，没有负数，不用考虑负数。

    * 元素的最大值不超过 1000，也就是元素的取值范围本身也在一个较小的范围内。

    * 两个数组的长度都小于等于 1000，也就是数据量比较小。

### 先计数再按两种次序回填

* **为什么选计数排序**

    * 要对数组排序而数据范围又小，用的就是计数排序，而且是计数排序里最简单的那种——因为全是大于等于零的数，不用考虑负数。

* **计数排序的三步**

    * 准备好一个 `count` 数组。

    * 用 `count` 数组记录待排数组中元素的出现次数，`count` 数组的索引就对应着元素值。

    * `count` 数组的索引本身是有序的，从中逐一取出这些索引，相当于把排好序的元素取出来放回原数组。

* **前两步的实现**

    * `count` 数组的长度由元素上界决定，题目直接给出了最大值 1000，开 `int[] count = new int[1001];`，最大值 1000 之外额外需要一个索引 0，加起来正好 1001。

    * 把 `arr1` 中的元素当成 `count` 的索引值，找到它该记住的位置后加一：`for (int i = 0; i < arr1.length; i++) { count[arr1[i]]++; }`

    * 一组测试数据跑完前两步后的 `count`：索引 0、1、2、3 的计数值依次是 0、2、4、1，也就是 1 出现 2 次、2 出现 4 次、3 出现 1 次。

    ```text
    索引： 0  1  2  3
    count： 0  2  4  1
    ```

* **回填的两遍循环**

    * > **易错点**：和原始计数排序唯一的差别是循环的「次序来源」变了——原来是从 `count` 的索引 0、1、2 依次取，现在改成**把 `arr2` 里的元素当成索引**，按它的顺序取。

    * 第一遍循环按 `arr2` 的次序回填：`while (count[arr2[i]] > 0)` 时把 `arr2[i]` 放进 `result[k++]`，`k` 加一并让对应计数减一。

    * > **易错点**：第二遍循环不能省。刚才只考虑了元素都在 `arr2` 里的情况，若 `arr1` 里多出 `arr2` 没点名的元素（比如先出现 5 再出现 4），只跑第一遍会在结果末尾留下 `0 0`，等于把它们漏掉了。

    * 第二遍循环改为循环 `count` 自己：`for (int i = 0; i < count.length; i++) { while (count[i] > 0) { result[k++] = i; count[i]--; } }`，此时索引 `i` 既是 `count` 的索引也代表原始元素的值，按大小次序把剩下的补齐。

    * 完整实现如下。

    ```java
    public int[] relativeSortArray(int[] arr1, int[] arr2) {
        // 第一步、第二步：计数
        int[] count = new int[1001];
        for (int i = 0; i < arr1.length; i++) {
            count[arr1[i]]++;
        }

        int[] result = new int[arr1.length];
        int k = 0;

        // 按 arr2 的次序回填
        for (int i = 0; i < arr2.length; i++) {
            while (count[arr2[i]] > 0) {
                result[k++] = arr2[i];
                count[arr2[i]]--;
            }
        }

        // arr2 里没点名的，按数值大小顺序接在后面
        for (int i = 0; i < count.length; i++) {
            while (count[i] > 0) {
                result[k++] = i;
                count[i]--;
            }
        }

        return result;
    }
    ```

* **回填顺序的验证**

    * `arr2` 里先出现的是 2，就先把这四个 2 取出来；`arr2` 里第二个是 3，就取出这一个 3；最后出现的是 1，再取出这两个 1。

    ```text
    期望：2 2 2 2 3 1 1
    实际：2 2 2 2 3 1 1
    ```

## 力扣 1636 按出现频率排序

### 排序规则与数据范围

* **排序规则**

    * > **定义**：按元素的出现频率对数组排序，出现频率越高的越往后排。

    * 例子：1 出现两次、2 出现三次、3 出现一次，于是 3 排最前面、1 排第二位、2 排最后。

    * 如果有多个值的频率相同，则再按数值大小降序排列：2 出现两次、3 也出现两次时，先排两个 3 再排两个 2。

* **数据范围**

    * 数据取值大于等于 -100，小于等于 100，范围并不是很大。

* **计数数组的尺寸**

    * 计数数组的大小选择数值范围加一，得把 -100 到正 100 的数字都能记录下来，所以选 201：`int[] count = new int[201];`。

    * > **易错点**：数值中可能有负数，负数要加上 100（也就是减去最小值 -100），才能得到一个大于等于 0 的下标，然后对它计数加一：`for (int num : nums) { count[num + 100]++; }`。

    * 测试数据跑完后 `count` 的后段结果是：1 出现了一次、2 出现了两次、3 出现了两次。

### 比较器与流式排序

* **比较器的返回值语义**

    * > **定义**：比较器是两个参数 `a` 和 `b`，比较它俩谁大谁小——返回 0 表示相等，返回负数表示 `a` 小于 `b`，返回正数表示 `a` 大于 `b`。

    * `af` 是 `a` 的出现频率，`bf` 是 `b` 的出现频率，都通过把数值加上 100 当成 `count` 的索引得到。

    * `af < bf` 返回 -1，`af > bf` 返回 1，相等时改按数值排。

    * > **提示**：正常升序是返回 `a - b`，这里数值要降序，就返回 `b - a`，别把这个符号写反了。

    * > **结论**：这道题追求简单解法就是设置好这个比较器——先比频率，频率相同的再按数值降序来比。

* **`int[]` 不能直接带比较器**

    * Java 里对 `int` 这种基本类型数组排序不能直接配合比较器使用，比较得挺烦人，所以这里转成数据流来排序。

    * `Arrays.stream(nums)` 得到基本类型的流。

    * `.boxed()` 把它转换成包装类的流，把基本类型的 `int` 流变成 `Integer` 这个包装类型的流。

    * `.sorted(比较器)` 这时候才可以应用比较器。

    * `.mapToInt(Integer::intValue)` 再把它还原回基本类型，这一步得到的还是个流。

    * `.toArray()` 才真正还原成整数数组。

* **完整实现**

    ```java
    public int[] frequencySort(int[] nums) {
        int[] count = new int[201];
        for (int num : nums) {
            count[num + 100]++;
        }

        return Arrays.stream(nums)
                .boxed()
                .sorted((a, b) -> {
                    int af = count[a + 100];
                    int bf = count[b + 100];
                    if (af < bf) {
                        return -1;
                    }
                    if (af > bf) {
                        return 1;
                    }
                    return b - a;
                })
                .mapToInt(Integer::intValue)
                .toArray();
    }
    ```

* **结果验证**

    * 频率升序让出现频率最少的 1 排在最前面，接着是出现频率为 2 的 3 和 2；3 和 2 频率相同，因为 3 的数值比 2 大，所以再按数值降序把 3 放在 2 前面。
