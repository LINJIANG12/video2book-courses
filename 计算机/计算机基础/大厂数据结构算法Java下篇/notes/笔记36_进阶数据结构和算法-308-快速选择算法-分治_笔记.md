# 进阶数据结构和算法-308-快速选择算法-分治

## 快速选择的接口约定

* **快速选择（quick select）**

    * > **定义**：不把整个数组排完，而是靠一轮轮划分把查找范围逐次折半，只返回排名 `i` 上的那一个元素。

    * 方法签名为 `quick(int[] arr, int left, int right, int i)`，其中 `left` 是起始索引、`right` 是结束索引、`i` 是要的排名，返回值就是排名 `i` 下的那个元素。

    * `i` 是从 0 开始的排名，不是"第几个"。

* **排序解法与它的账单**

    * 直接 `Arrays.sort(arr)` 再 `return arr[i]`，排好序后数组下标就是排名，实现极简单且结果正确。

    * 排序的时间复杂度是 $O(N \log N)$，为了一个元素把整个数组都整理了一遍。

## 一次划分确定基准点

* **partition 分区**

    * > **定义**：选一个基准点元素，把比它小的都交换到它左边、比它大的都交换到它右边，并返回基准点最终所在的下标。

    * 借的是快速排序里基准点的做法，代码可以从快排那里连同 `swap` 一起搬过来，不必重写。

    * 这一轮走完得到的结论是：基准点元素的位置确定好了。左边全是比它小的，右边全是比它大的，两边各自的内部顺序并不在乎。

    * 基准点落在下标 2 而要的就是排名 2 时直接返回它；要排名 3 时只在它右侧的区间继续找，左半截再也不用管。

    * 左边那些元素都比基准点小，排名只可能是前面那几档，不可能突然蹦出靠后的名次，所以查找范围一下子少了一半。

    ```text
    第一轮划分之后

       [ 都小于基准点 ][ 基准点 ][ 都大于基准点 ]
             用不着管        ↑          { 5, 6 }
                         落在下标 2

       要排名 2 →  基准点就在下标 2，直接返回
       要排名 3 →  只在 { 5, 6 } 这个范围里继续找，左边那半截再也不用管
    ```

    * 缩小后的区间里做同样的事：仍选最右侧元素当基准点，仍把小的甩左边、大的甩右边，走完一轮 5 落在下标 3，正好是排名 3，命中返回。

* **随机基准点**

    * > **定义**：`int p = left + (int) (Math.random() * (right - left + 1))` 随机挑一个下标作基准，先 `swap(arr, p, right)` 再以 `arr[right]` 为基准值。

    * > **提示**：固定选最右侧元素时运气差会出现每次切出来的一边几乎都是空的情况，分治就退化成蛮力遍历；随机挑能让这种糟糕情况很难连续发生。

    * 划分时用一个指针 `less` 记录已归位的小元素个数，扫到比基准小的就 `swap(arr, less, cur)` 并让 `less++`，扫完后 `swap(arr, less, right)`，返回 `less`。

## 只往一半走的递归

* **quick 的三分支**

    * 一上来先 `int p = partition(arr, left, right)`，四个参数原样传进去。

    * 返回值 `p` 的含义是基准点元素最终所在的索引值，而且这时它在这个数组里的正确位置已经定死了，于是分三种情况。

    * `p == i`：基准点下标正好等于要的排名，直接 `return arr[p]`。

    * `i < p`：排名比基准点靠前，递归 `quick(arr, left, p - 1, i)`。

    * `i > p`：排名比基准点靠后，递归 `quick(arr, p + 1, right, i)`。

    * 左区间是这次的 `left` 到 `p - 1`，右区间是 `p + 1` 到这次的 `right`，`i` 一样要往下传；"去左边找"和"去右边找"的逻辑一模一样，区别只在参数范围，所以直接递归调用自己。

    ```java
    public static int quick(int[] arr, int left, int right, int i) {
        int p = partition(arr, left, right);

        if (p == i) {
            return arr[p];
        } else if (i < p) {
            return quick(arr, left, p - 1, i);
        } else {
            return quick(arr, p + 1, right, i);
        }
    }
    ```

* **时间复杂度**

    * 每查找一次范围缩小一半：第 1 轮扫 $n$ 个元素，第 2 轮最多扫 $n/2$，第 3 轮最多扫 $n/4$，依次递减。

    * 加总是一个等比数列：$n + n/2 + n/4 + \cdots < 2n$，所以是 $O(N)$，比排序的 $O(N \log N)$ 整整快一个量级。

## 数组第 K 大与排名口径换算

* **排名口径差异**

    * 求数组第 K 大时的排名是由大到小、从 1 开始；快速选择的排名是由小到大、从 0 开始，方向反了，编号也反了。

    * 换算关系是"数组长度减去现在的由大到小排名"，即 $r_{\text{升序}} = n - K$。

    | 由大到小的排名 K | 元素 | 对应由小到大的排名 = 5 - K |
    | :--- | :--- | :--- |
    | 1 | 6 | 4 |
    | 2 | 5 | 3 |
    | 3 | 4 | 2 |
    | 4 | 2 | 1 |
    | 5 | 1 | 0 |

    * 理清对应关系后代码不用重头写，直接调用 `quick(nums, 0, nums.length - 1, nums.length - k)`，第二、三个参数是左右边界 `0` 和 `数组长度 - 1`，最后那个参数就是 `数组长度 - k`。

    * 测试用例：无序数组 `[2, 3, 1, 5, 6, 4]` 求第 2 大，6 是第 1 大、5 是第 2 大，答案为 5。

* **堆解法与快速选择的场景分工**

    * 小顶堆解法的思路是先把前 K 个元素放进小顶堆，剩余元素循环遍历、与堆顶比较，比堆顶小的跳过，比堆顶大的就用它替换堆顶，使堆中始终保留当前最大的 K 个元素，循环结束后堆顶就是第 K 大。

    * 堆解法是 $O(N \log K)$ 量级，每来一个新元素都要跟堆顶比一次、必要时还要调整堆；快速选择可以把它降到 $O(N)$，放到力扣上跑得分也会比堆解法高一些。

    * > **注意**：小顶堆在数据流里求第 K 大特别好用，因为数据一波一波来、堆可以边收边维护；快速选择要求整个数组已经摆在内存里了，不能应用于数据流，只能解数组里的静态数据。两者适用的是不同场景，按场景挑工具。

## 数组中的中位数

* **中位数的定义**

    * 奇数个数字排个序，中间那个数字就是中位数，例如 `1, 4, 5` 中间是 4，`1, 3, 4, 5, 6` 中间也是 4。

    * 偶数个数字取中间的两个数字求平均值，例如 `1, 2, 3, 4, 5, 6` 中间是 3 和 4，平均下来是 3.5。

    * 这是数组中的中位数，一个快速选择算法就够；而《数据流的中位数》需要大顶堆加小顶堆。

* **化成求排名问题**

    * 中位数问题本质上就是一个求排名的问题，等于"排在中间排名上的那个元素"，能算出中间排名是几就能进一步求出那个元素。

    * 中间排名就是 `数组长度 / 2`（排名从 0 开始）。

* **奇数个数字的处理**

    * 用 `len % 2 == 1` 判奇数；数字个数是 3 时排名为 0、1、2，中间排名是 1，个数是 5 时排名为 0 到 4，中间排名是 2。

    * 代码是 `quick(nums, 0, len - 1, len / 2)`，只调一次。

    * 测试用例：`[1, 4, 5]` 的中位数是 4，`[1, 3, 4, 5, 6]` 的中位数也是 4。

* **偶数个数字的处理**

    * 偶数要找到两个数字：以个数是 4 为例，`4 / 2 = 2` 是后面那个数字，还要用它前面那个，位置是 `4 / 2 - 1`。

    * 分别 `quick(nums, 0, len - 1, len / 2)` 和 `quick(nums, 0, len - 1, len / 2 - 1)` 求出两个数，再求平均值作为最终中位数。

    * > **易错点**：平均必须除以 `2.0` 而不能写成 `2`，两个整数相加之后还是整数，用 `2` 做除法就是整数除法、小数部分直接被舍弃，中位数永远不可能出现 `.5`；写成 `2.0` 才会转成小数除法。

    * 测试用例：`[1, 2, 3, 4, 5, 6]` 中间是 3 和 4，中位数为 3.5；另一个用例中间是 4 和 5，中位数为 4.5。

## 快速幂的指数对折

* **朴素幂函数**

    * `result = 1` 之后循环 n 次，每次在结果上乘以 x，返回相乘的结果，`n = 16` 就要乘 16 次，时间复杂度偏高。

* **分治拆指数**

    * > **定义**：把指数不断对折，$x^n = (x^{n/2})^2$，这是快速幂的分治本质。

    * 2 的 16 次方拆成两个 2 的 8 次方，2 的 8 次方拆成两个 2 的 4 次方，2 的 4 次方拆成两个 2 的 2 次方，2 的 2 次方就是两个 2 相乘。

    ```text
                                2^16
                              /      \
                          2^8        2^8   ← 和左边对称，结果一样，不必再算
                         /   \
                     2^4     2^4         ← 同上
                    /   \
                2^2     2^2             ← 同上
               /   \
             2      2
    ```

    * 自底向上只看一侧：2 × 2 得 4 是第 1 次乘法，4 × 4 得 16 是第 2 次，16 × 16 得 256 是第 3 次，256 × 256 得 65536 是第 4 次，总共只乘四次。

    ```text
            2 × 2      = 4       ← 第 1 次乘法
            4 × 4      = 16      ← 第 2 次乘法
           16 × 16     = 256     ← 第 3 次乘法
          256 × 256   = 65536   ← 第 4 次乘法
    ```

    * 偶数的幂两个结果直接相乘；奇数的幂除了把两个结果相乘，还要再多乘一个 x，而这个多出来的 x 不能丢，将来相乘时得把它也算上去。

    ```text
          2^10 = 2^5 × 2^5
                 2^5 = 2 × 2^4
                        2^4 = 2^2 × 2^2
                               2^2 = 2 × 2
    ```

* **递归实现**

    * 递归终止条件是 n 等于 1，此时直接返回 x。

    * n 不为 1 时判断奇偶：偶数返回 `myPow(x, n / 2) * myPow(x, n / 2)`，奇数返回 `x * myPow(x, n / 2) * myPow(x, n / 2)`。

    * 10 被拆成两个 5，原问题被拆成两个 `myPow(x, n / 2)` 子问题；5 同样处理，`5 / 2` 整数除法拆成两个 2，前面多出的那个 2 就是 x。

* **只递归一次的改进**

    * 右侧子问题的计算结果与左侧完全一样，重复计算没有必要，但最初写的代码仍然调了两次 `myPow`。

    * 改法是把调用抽到外面只留一次：`double t = myPow(x, n / 2)`，偶数返回 `t * t`，奇数返回 `t * t * x`，这样才算真正达到快速幂的效果。

## 快速幂的边界用例

* **n 等于 0**

    * 任何数的 0 次幂都应该是 1，只判 `n == 1` 会让 `n == 0` 陷入不断递归、出不来而报栈溢出，补上 `if (n == 0) return 1;` 即可。

    * > **提示**：有了 `n == 0` 的判断后原来的 `n == 1` 其实也可以不要，因为真的 `n == 1` 时接下来除以 2 结果就是 0，加了它就可以作为统一终止条件；但从效率上讲单独保留 `n == 1` 分支能少一次不必要的递归调用，所以两个都留着更好。

* **n 是负数**

    * $2^{-2}$ 实际上等于 $1 \div 2^2$，即取倒数，所以可以先按正数把结果求出来再求倒数。

    * 不改动原有逻辑的做法是把方法改名 `myPowPositive`（只负责 n 为正数），另写 `myPow` 兼容负数：先 `long p = n` 复制一份来检查，小于零则 `p = -p` 按正数求，再 `n < 0` 时返回 `1.0 / r`，否则返回 `r`。

    * 测试用例 $2^{-2}$ 的结果是 0.25。

* **n 等于 Integer.MIN_VALUE**

    * 力扣给出的 n 是 `-2147483648`，即 Java 中 int 整数的最小值，问题出在取绝对值这一步：负负得正得到 2147483648，超出了正整数最大值 2147483647。

    * 没有简单的解决办法，力扣官方的做法是换一个更大的整数类型，把这里原来的 int 都改成 `long`，就能存得下。

    * 最终结果是 0.0，因为这个幂非常大，求倒数之后就变成 0.0。

## 奇偶判断的两种写法

* **求模判断**

    * 用百分号运算符求模：`n` 除以 2 余数为 0 表示偶数，余数为 1 表示奇数。

* **按位与判断**

    * 奇数 1、3、5、7 的二进制最后一位都是 1，偶数 2、4、6、8 的最后一位都是 0，所以判断奇偶可以转化成检查二进制的最后一位。

    ```text
    十进制    二进制(4 位)      奇偶
       1        0001           奇
       2        0010           偶
       3        0011           奇
       4        0100           偶
       5        0101           奇
       6        0110           偶
       7        0111           奇
       8        1000           偶
    ```

    * 拿到最后一位的办法是跟 1 做二进制按位与运算，因为只要有一个 0 结果就是 0，结果相当于把最后一位原样取出来。

    ```text
       111     ← 7
     & 001     ← 1
      -------
       001     ← 结果是 1  →  奇数

      1000     ← 8
    & 0001     ← 1
     -------
      0000     ← 结果是 0  →  偶数
    ```

    * 代码写成 `if ((n & 1) == 0)` 走偶数分支，否则走奇数分支，测试结果依然正确。

    * > **易错点**：按位与运算的优先级比较低，写在 `if` 里一定要用一对括号把它括起来 `(n & 1) == 0`，否则运算顺序会不对。
