# 基础算法-191-哈希表-e01-两数之和

## 两数之和

### 题目与返回值

* **两数之和（Two Sum）**

    * > **定义**：给定一个整数数组 `numbers` 和一个整数目标值 `target`，在数组中找出和等于 `target` 的两个整数，并返回这两个数的**数组下标**。

    * 返回的是下标数组，不是两个数值本身。

    * 示例：`numbers = [2, 7, 11, 15]`、`target = 9`，因为 `2 + 7 = 9`，返回下标 `[0, 1]`。

    * 示例：`numbers = [3, 2, 4]`、`target = 6`，因为 `2 + 4 = 6`，返回下标 `[1, 2]`。

    * 示例：数组只有 `[3, 3]`、`target = 6`，两个不同下标取到相同数值也算合法配对，返回 `[0, 1]`。

* **答案唯一性**

    * > **提示**：题目已经规定针对每个输入最后只会有一个答案，不会出现多组数相加都等于 `target` 的情况，所以不用担心答案唯一性问题。

    * 由此推出：不存在"循环完一遍仍没找到"的情形，代码末尾的 `return null` 只是语法兜底。

### 暴力枚举的代价

* **先想最笨的办法**

    * 拿到数组里第一个数（比如 `2`），问「2 加几等于 9」，得到 `7`，于是要在剩下的 $n - 1$ 个数里找一个 `7`。

    * 再看数组里下一个数（比如 `3`），问「3 加几等于 9」，得到 `6`，于是要在剩下的 $n - 2$ 个数里找一个 `6`。

    * 没找到就重复这个过程，直到最后一个数只剩下一次查找。

* **代价结论**

    * 最坏情况下的比较次数是 $(n - 1) + (n - 2) + \cdots + 1$，查找效率比较低。

    * 要提升查找效率的手段就是引入哈希表。

### 哈希表一遍扫描与代码

* **算法机制**

    * 先准备一个**空哈希表**，然后从左向右遍历数组，对每个数去找它配对的那个数。

    * 对当前数 `x`，先算配对数 $y = target - x$，拿 `y` 当 key 去哈希表里找。

    * 找不到配对数：就把当前这个数以「数为 key、下标为 value」的键值对存进哈希表，然后继续遍历。

    * 找到了配对数：说明当前数与哈希表里那个数正好凑成 `target`，直接返回 `map.get(y)`（配对数的下标）和 `i`（当前数的下标）。

    * 整个数组只遍历一次，时间复杂度为 $O(n)$。

* **执行过程**

    ```text
    numbers = [2, 7, 11, 15]        target = 9

    遍历到 2    配对数 y = 9 - 2 = 7
                拿 y 当 key 去哈希表里找 …… 没有
                没找到，就把当前这个数以它为 key、下标为 value 存进去
                +-------------------------------+
                |  key | 2                      |
                |  val | 0                      |
                +-------------------------------+

    遍历到 7    配对数 y = 9 - 7 = 2
                拿 y 当 key 去哈希表里找 …… 有了，值是 0
                命中！返回 [ map.get(y), i ] = [ 0, 1 ]
    ```

* **代码落地**

    * > **提示**：因为答案要的是下标，所以按下标来遍历数组，不能用增强 for 循环。

    * 哈希表的键和值都是 `Integer`——因为索引是整数，数组里的数字也是整数。

    ```java
    public int[] twoSum(int[] numbers, int target) {
        Map<Integer, Integer> map = new HashMap<>();

        // 因为要用到索引，所以按下标来遍历
        for (int i = 0; i < numbers.length; i++) {
            int x = numbers[i];
            int y = target - x;          // 跟 x 配对的那个数

            if (map.containsKey(y)) {
                return new int[]{map.get(y), i};
            }

            // 没找到配对的，就把 x 连同它的索引存进去
            map.put(x, i);
        }

        return null;
    }
    ```

    * `return null` 不会被执行到，因为题目保证一定存在有效答案，它只是语法上的兜底。

## 最长无重复子串

### 题目与示例拆分

* **最长无重复子串（Longest Substring Without Repeating Characters）**

    * > **定义**：给一个字符串 `s`，找出其中不含重复字符的最长子串的长度。子串的前提就是不能有重复字符。

* **按从左向右的拆分规则走一遍**

    * 从左向右依次向右扩：单字符是一个合法子串，再加一个不重复的字符仍然合法，直到加上一个与前面重复的字符。

    * 一旦新字符与前面重复，就把这个重复字符丢掉，改从它**后面那个不重复的字符**开始，构成新的合法子串。

    * 例一：`abcabc...` 形式的字符串会依次拆出 `a`、`ab`、`abc`、`bca`、`cab`、`abc`、`cb`、`b`，这些合法子串的长度都是 3，所以答案是 3。

    * 例二：字符串里全是有重复的字符，走完从左向右的规则后只剩一个合法子串 `b`，最长长度是 1。

    * 例三：`pwkw` 依次拆出 `p`、`pw`、`w`、`wk`、`wke`、`kew`，最长的是 `wk` 和 `kew`，长度都是 3。

### 双指针与哈希表的分工

* **两个指针 `begin` 和 `end`**

    * `begin` 表示子串的起始位置，`end` 表示子串的结束位置，`begin` 和 `end` 这个范围之内的字符就是当前子串。

    * 当前子串长度就是 $end - begin + 1$。

    * 没遇到重复字符时，让 `end` 向后走一格；遇到重复字符时，主要去调整 `begin` 指针。

* **哈希表负责查重**

    * 哈希表以「字符作 key、最近一次出现的位置作 value」的形式保存已处理过的字符。

    * 遇到重复字符时，把哈希表里这个 key 的 value **更新**为当前下标——哈希表里始终保存的是该字符最近一次被处理时的索引位置，旧的位置被替换掉。

    * 这样不断重复，就能把每一个合法子串都拿到。

### 窗口推进与代码

* **推进规则**

    * `maxLen` 必须定义在循环外面，每次赋值前用 `Math.max` 在「上一次的 `maxLen`」与「本次算出的子串长度」之间取较大值。

    * 第一次窗口长度是 1，与初值 0 取最大得 1；窗口变成 `ab` 后长度是 2，与上一次的 1 取最大得 2；循环结束时 `maxLen` 里保存的就是最大长度。

    * 无论有没有遇到重复，哈希表里都要 put 当前字符最近一次出现的位置。

* **代码落地**

    ```java
    public int lengthOfLongestSubstring(String s) {
        int begin = 0;                   // 子串的起始位置
        int maxLen = 0;                  // 最长长度，定义在循环外面

        // 用来检查重复字符：字符作 key，最近一次出现的下标作 value
        Map<Character, Integer> map = new HashMap<>();

        // end 从 0 开始，遍历到字符串长度减一的位置
        for (int end = 0; end < s.length(); end++) {
            Character ch = s.charAt(end);

            if (map.containsKey(ch)) {
                // 遇到重复字符，调整 begin，取两者的较大值
                begin = Math.max(begin, map.get(ch) + 1);
            }

            // 无论有没有重复，哈希表里始终保留这个字符最近一次出现的位置
            map.put(ch, end);

            // 当前窗口长度，用 max 滚动记录历史最大值
            maxLen = Math.max(maxLen, end - begin + 1);
        }

        return maxLen;
    }
    ```

* **调试打印**

    * > **提示**：调试时把当前子串打印出来，看它是不是已经按这套逻辑把子串都正确拆开了。

    * 打印用 `s.substring(begin, end + 1)`：因为 `substring` 是含头不含尾的，所以 `end` 这里加一才正好打印到当前字符。

    * 验证没问题之后就把这个打印去掉。

### abba 用例暴露的指针回退

* **错在哪**

    * 用 `abba` 走这段代码时，肉眼能看出最长子串长度应该是 2，但代码算出来是 3。

    * 逐个窗口打印出来看：前面拆对了，拆成 `a`、`ab`、`b`，但最后一步应该拆成 `ba`，现在却拆成了 `bba`，里面 `b` 重复了。

    * 处理最后一个字符 `a` 时哈希表里已经有 `a`（值为 0），旧写法 `begin = map.get('a') + 1 = 0 + 1 = 1`，让 `begin` 从 2 往回走到了 1——指针不能往回走。

    ```text
    即将处理 s[3] = 'a'，此时的状态是：

            0    1    2    3
            a    b    b    a
            ^begin        ^end

    哈希表里存了两个键值对：  a -> 0      b -> 2

    我们最终要截取的子串，是 "ba"。


    旧写法：  begin = map.get('a') + 1 = 0 + 1 = 1
                                      ^^^^^^
                                      begin 往回走了一格！

            0    1    2    3
            a    b    b    a
                 ^begin        ^end
            截出来是 "bba"，里面 b 重复了 —— 错


    新写法：  begin = Math.max(begin, map.get('a') + 1)
                           = Math.max(2, 0 + 1) = 2
                                           ^^^^^^
                                           原位不动

            0    1    2    3
            a    b    b    a
                 ^begin        ^end
            截出来是 "ba" —— 对
    ```

* **修正规则**

    * > **易错点**：⚠️ 调整 `begin` 时不能直接用「重复字符索引 + 1」赋值，必须拿它和当前的 `begin` 比较后取较大值，否则指针会往回走。

    * 修正做法：拿到重复字符的索引后与当前 `begin` 取较大值，也就是尽可能找一个靠右的指针作为新的 `begin`。

    * 在 `abba` 这个例子里，重复字符 `a` 的索引是 0，加一得 1，而当前 `begin` 是 2，取最大得 2，`begin` 原位不动，截出来的就是 `ba`。

    * 改动之后 `a`、`ab`、`b`、`ba` 全部拆分正确，最长子串长度为 2。

### 数组替掉哈希表

* **可以优化的前提**

    * 题目条件写明：字符串由英文字母、数字、符号和空格组成，也就是说字符取值范围很小，只落在阿斯克码的 **128 个字符**之内。

    * `HashMap` 适合 key 范围比较大、你事先不知道有哪些字符的情况；字符范围已知且很小时，可以用定长数组替换掉 `HashMap`。

* **改写思路**

    * 用**字符本身当成数组的索引**，数组里的值仍然记录该字符上一次重复时（最近一次出现时）的索引位置。

    * 窗口右移、`begin` 往右挪、维护最长长度这些流程完全不变，性能比用 `HashMap` 更胜一筹。

    * 作为练习留的题目就是：把最长无重复子串里的 `HashMap` 换成一个数组。

    * > **提示**：`abba` 那个坑与容器换成什么无关，`begin = Math.max(begin, 上次出现的位置 + 1)` 这个修正照样要保留，否则 `abba` 又会算出 3 而不是 2。

## 字母异位词分组

### 异位词与排序规律

* **字母异位词（Anagram）**

    * > **定义**：字母组成完全相同、只是顺序不同的单词互为字母异位词，例如 `ab` 与 `ba`；`eat` 与 `eta`、`tae`、`tea`、`aet`、`ate`。

* **一条规律**

    * 互为字母异位词的单词虽然字母顺序不同，但**各自排序之后的结果是同一个字符串**。

    * `eat`、`tea`、`ate` 排序后都是 `aet`；`tan`、`nat` 排序后都是 `ant`；`bat` 排序后是 `abt`。

* **由此得到的归组键**

    * 准备一张哈希表，用**排序后的结果作为 key**，用这些字母异位词作为哈希表中的值，key 相同的自然就被分到了一组。

    * key 的类型是字符串类型，因为要放排好序的字符串。

### 归组过程

* **逐词处理**

    * 初始是一张空哈希表，从左向右遍历单词数组。

    * 对每个单词先排序，用排好序的字符串作为 k；值用一个集合（可以是 `ArrayList`）来代表，因为一组里可能装多个单词。

    * 到哈希表里找这个 k：没有就新建一个空集合作为值放进去；找到就把这个单词加进那个集合。

* **一次完整分组**

    ```text
    单词数组：["eat", "tea", "tan", "ate", "nat", "bat"]

    "eat" -> 排序 -> "aet"    表里没有 "aet"  -> 新建组：[eat]
    "tea" -> 排序 -> "aet"    表里已有 "aet"  -> 加入该组：[eat, tea]
    "tan" -> 排序 -> "ant"    表里没有 "ant"  -> 新建组：[tan]
    "ate" -> 排序 -> "aet"    已有            -> 加入    ：[eat, tea, ate]
    "nat" -> 排序 -> "ant"    已有            -> 加入    ：[tan, nat]
    "bat" -> 排序 -> "abt"    表里没有        -> 新建组：[bat]

    最后返回 map 的所有 values：

            aet -> [eat, tea, ate]
            ant -> [tan, nat]
            abt -> [bat]
    ```

### 分组代码与返回结构

* **代码落地**

    * 值将来要装下同一组的多个单词，所以用 `List` 集合来代表，集合元素也是字符串，哈希表为 `Map<String, List<String>>`。

    ```java
    public List<List<String>> groupAnagrams(String[] strs) {
        // key = 排好序的字符串，value = 这一组的所有单词
        Map<String, List<String>> map = new HashMap<>();

        for (String word : strs) {
            // 拿到原始的字符数组并排序
            char[] chars = word.toCharArray();
            Arrays.sort(chars);
            // new 一个 String 对象，把排好序的字符数组传进去，key 就有了
            String key = new String(chars);

            // 根据 key 到 map 里去找存储分组结果的那个集合
            List<String> list = map.get(key);

            // 这个 k 还没有对应的集合，就新建一个空的放进去
            if (list == null) {
                list = new ArrayList<>();
                map.put(key, list);
            }

            // 把原始的字符串单词加进去
            list.add(word);
        }

        // map.values 就是我们分好的那些组，再放到一个大的 ArrayList 里返回
        return new ArrayList<>(map.values());
    }
    ```

* **返回结构**

    * 方法要的是一个二维的 `List`，所以返回值是 `new ArrayList<>(map.values())`，把分好的那些组再装进一个大 `ArrayList`。

    * 验算结果：`eat`、`tea`、`ate` 被分到一组，`tan`、`nat` 被分到一组，`bat` 自成一组，结果正确。

    * 这段实现提交后成绩是 6ms，大约击败 98% 的用户。

### computeIfAbsent 收敛初始化

* **替换写法**

    * IDEA 会提示把「判断集合为空就新建」那一段替换成 `computeIfAbsent` API。

    ```java
    public List<List<String>> groupAnagrams(String[] strs) {
        Map<String, List<String>> map = new HashMap<>();

        for (String word : strs) {
            char[] chars = word.toCharArray();
            Arrays.sort(chars);
            String key = new String(chars);

            // key 不存在才创建集合，存在就直接拿到那个集合
            List<String> list = map.computeIfAbsent(key, k -> new ArrayList<>());

            list.add(word);
        }

        return new ArrayList<>(map.values());
    }
    ```

* **工作原理**

    * `computeIfAbsent` 的行为与替换前的逻辑一模一样。

    * 它先判断这个 key 在 `map` 里是不是缺失（`absent`）：缺失就执行后面的 lambda 表达式，创建一个空的 `ArrayList` 集合并放进 `map`。

    * 不缺失也就是这个 key 对应的值在 `map` 里已经有了，就不执行 lambda，直接把已有的值取出。

    * 不管存不存在，它都会把 `list` 集合作为结果返回，拿到集合后把原始单词加进去即可。

* **收益与代价**

    * 代码结构比替换前简洁了不少。

    * > **注意**：性能上和原来「先 `get` 再判空 `put`」的写法并没有明显的区别，收益只在可读性。
