# 基础算法-204-排序算法-堆排序

## 堆排序的由来

* **选择排序的瓶颈**

    * > **定义**：每一轮在这些元素里挑一个最大的，摆到末尾去。

    * 挑最大值的做法是先假定最右侧那个是最大的，再拿它跟前面所有元素逐一比较，才能确定最大值是谁

    * 单轮比较 $O(n)$，外面还有 $n$ 轮，整个选择排序就是 $O(n^2)$

    * 开销几乎全压在"挑"这一个动作上

* **堆排序（heap sort）**

    * > **定义**：把选择排序里"挑最大值"这个动作换成二叉大顶堆来做的排序算法。

    * 堆建好之后，最大值就躺在堆顶，从堆顶取一个元素只要 $O(\log n)$

    * 取最大值 $O(\log n)$ 乘以外面循环 $n$ 次，整体 $O(n \log n)$，比 $O(n^2)$ 快一大截

    * 最好、最坏、平均时间复杂度都是 $O(n \log n)$

    * 空间占用跟数据规模无关，是 $O(1)$

    * 属于不稳定排序，遇到相同元素排完之后它们的相对顺序可能被打破

    * 思想上仍是选择排序那一套：一轮挑一个最大值放到末尾

    * 真正难的不是排序流程，而是堆的操作本身：取堆顶、交换、下潜

## 堆排序的两步流程

* **第一步：把整个数组调整成大顶堆**

    * 刚拿到手的数组当然不符合大顶堆的特性，先做一次建堆把它整理成下面这样

        ```text
                      [6]                 ← 数组下标 0，堆顶，也是最大值
                     /   \
                  [4]     [5]            ← 数组下标 1、2
                  /  \     |
               [1]   [3]  [2]             ← 数组下标 3、4、5

        数组：[6, 4, 5, 1, 3, 2]
        ```

    * 堆顶 6 是最大值，它两个孩子 4 和 5 都比它小

    * 4 的两个孩子 1 和 3 都比 4 小；5 只有一个孩子 2，也比 5 小

* **第二步：堆顶换末尾，再让它落回该在的位置**

    * 每次都把堆顶这个最大值交换到当前堆的末尾

        ```text
        交换前：[6, 4, 5, 1, 3, 2]
        交换后：[2, 4, 5, 1, 3, 6]
                          ↑
                      6 已就位，从这一轮起不再参与任何堆操作
        ```

    * 换上来的 2 显然不是最大值，大顶堆的特性被破坏了，所以要接着对堆顶做调整，让它重新满足大顶堆

    * 这个调整动作就是一次下潜：2 的两个孩子是 4 和 5，取更大的 5 交换，数组变成 `[5, 4, 2, 1, 3, 6]`

    * 2 换到下标 2，它的孩子已经越出堆的范围（堆只剩 5 个元素），下潜结束，堆顶重新变成最大值 5

    * 第二轮把 5 跟末尾的 3 交换，调整完又找到下一个最大值 4，再把它交换到末尾

    * 重复"调整、交换"，直到堆里只剩下一个元素，整个数组就排好了。

    > **注意**：交换完成后必须马上重新下潜，而且下潜的范围要收缩到 `right`——已经排好的那一段虽然还躺在数组里，但已经不参与堆的任何操作了。

## 下潜（siftDown）

* **下潜的交换对象**

    * 下潜要做的动作是：看当前节点有没有比它大的孩子，有就把它换下去

    * 跟两个孩子里取值更大的那一个换，不是固定跟左孩子换

        ```text
        第一轮：19 和 36 都比 7 大，取更大的 36 交换
              [7]                    [36]
             /   \                  /   \
          [19]  [36]      →     [19]    [7]
                                  /
                               [25]

        第二轮：7 的左孩子 25 仍然比它大，再换一次
              [36]                   [36]
             /   \                  /   \
          [19]    [7]     →      [19]  [25]
           /
         [25]                   [7]        7 已经潜到底，退出
        ```

    * 第二轮之后 7 已经潜到底，说明它回到了自己的正确位置，下潜过程可以退出

    > **提示**：下潜的交换对象是"两个孩子中较大的那一个"。写错这一条，堆就建不对。

* **下潜的判定条件**

    * 每一轮先拿到左孩子的索引，再拿到右孩子的索引

    * 然后假设 `parent` 自己的取值是最大的

    * 如果左孩子的值大于 `max`，就把 `max` 更新成左孩子索引，右孩子同理

    * 两个 `if` 判断完之后，如果 `max` 发生了变化，就说明找到了更大的孩子，把这个更大孩子和 `parent` 这两个位置的元素交换

    * 一次交换就是一轮下潜，接下来还要做下一轮

* **从递归改成非递归**

    * 下潜是一个单路递归，只有一条自我调用的路径，改成非递归只需要在外层套一个循环

    * 力扣上的那道排序题，同一份数据，递归实现比非递归实现要慢大约 6 ms

    * 改动一：循环条件写成相反的形式，`max == parent` 就表示没找到更大的孩子，直接退出外层循环

    * 改动二：删掉递归调用，它已经被外层循环代替

    * 改动三：`parent` 不会自己往下走，下一轮循环时 `parent` 要变成 `max`，也就是刚才换下去的那个孩子的位置

    ```java
    private static void siftDown(int[] a, int parent, int size) {
        while (true) {
            int left = parent * 2 + 1;
            int right = left + 1;

            // 先假设 parent 自己就是最大的
            int max = parent;
            if (left < size && a[left] > a[max]) {
                max = left;
            }
            if (right < size && a[right] > a[max]) {
                max = right;
            }

            // 没找到比 parent 更大的孩子，它已经待在正确的位置上了
            if (max == parent) {
                break;
            }

            swap(a, max, parent);
            parent = max;   // 递归没了，但 parent 得跟着往下走
        }
    }
    ```

    > ⚠️ **易错点**：`swap` 和 `parent = max` 这两行不要再包在一个 `else` 里面。条件成立时 `break` 已经跳出循环，这两行根本轮不到执行；条件不成立时它们自然执行。套上 `else` 纯属多余。

## 建堆（buildHeap）

* **弗洛伊德式建堆**

    * 建堆仍然用弗洛伊德的方式，也就是不断去调用下潜方法

    * 它比用上浮方法建堆效率更高，时间复杂度可以达到 $O(n)$

    * 用上浮建堆的时间复杂度是 $O(n \log n)$，效率低一些

* **下潜起点是最后一个非叶子节点**

    * 下潜的起点不是数组开头，而是最后一个非叶子节点，下标为 `(size - 2) / 2`

    * 从它开始往前挨个调用下潜方法，一轮循环走完整个堆就建好了

    ```java
    private static void buildHeap(int[] a, int size) {
        // 最后一个非叶子节点的下标是 (size - 2) / 2，从它开始往前逐个调整
        for (int i = (size - 2) / 2; i >= 0; i--) {
            siftDown(a, i, size);
        }
    }
    ```

    > **提示**：叶子节点根本不需要下潜——它下面没有孩子，本来就天然满足"孩子比我小"，所以建堆只从非叶子节点开始。

## 堆排序主流程

* **主流程代码**

    * 第一步把原来这个数组做成大顶堆，建堆时 `size` 直接传数组长度

    * 第二步进入循环，每轮把堆顶最大值换到当前堆的最右侧，然后让它下潜回去

    * `right` 代表当前堆最右侧的索引，初值是 `length - 1`，每轮递减

    ```java
    public static void heapSort(int[] a) {
        int size = a.length;

        // 第一步：把原来这个数组做成大顶堆，size 直接传数组长度
        buildHeap(a, size);

        // 第二步：right 代表当前堆最右侧的索引，初值 length - 1，每轮递减
        for (int right = size - 1; right > 0; right--) {
            // 把堆顶（下标 0）这个最大值换到 right
            swap(a, 0, right);
            // 换上来的元素破坏了堆的特性，让它下潜回去；堆的范围收缩到 right
            siftDown(a, 0, right);
        }
    }
    ```

* **循环条件的边界**

    * 循环条件写 `right > 0` 而不是 `>= 0`

    * `right` 等于 1 的时候就已经是最后一次交换了；等它等于 0，堆里只剩一个元素，再交换也没有意义

    * 外层代码其实相当简单，真正要下功夫的还是建堆和下潜写不对

## 插入排序（insertion sort）

* **核心划分**

    * > **定义**：把数组分成两部分，一部分是已排序区，另一部分是未排序区；每次从未排序区最左侧取出一个元素，插入到已排序区中去。

    * 每轮从未排序区最左侧 `low` 取出一个元素，向已排序区内插入

        ```text
        第 1 次：取 2 插入 → 3 比 2 大，3 右移一位，2 顶到前面   已排序区：[2, 3]
        第 2 次：取 4 插入 → 4 已经是最大的，插入位置不变
        第 3 次：取 1 插入
        第 4 次：取 6 插入
        第 5 次：取 5 插入
        第 6 次：取 7 插入 → 整个序列排好
        ```

    * 插入排序综合了冒泡、选择的一些优点

* **与冒泡、选择的比较**

    * 跟冒泡像的地方：如果针对的是一个已经排好序的数组，时间复杂度可以达到 $O(n)$，最好情况下就能到 $O(n)$

    * 最坏和平均的时间复杂度仍然是 $O(n^2)$

    * 跟选择像的地方：交换次数相对比较少，一般都要少于冒泡

    * 在数据量比较小、并且数组基本有序的情况下，用插入效率相当高

### 插入排序的实现

* **递归版骨架**

    * `low` 代表未排序区最左侧的索引，每次把最左侧这个元素插进已排序区

    * `low` 超出数组范围时整个排序结束

    ```java
    private static void insertSort(int[] a, int low) {
        if (low >= a.length) {   // low 超出数组范围，整个排序结束
            return;
        }
        insert(a, low);
        insertSort(a, low + 1);
    }
    ```

* **insert 的右移腾位**

    * 一轮 `insert` 内部是从右往左找插入位置的

    * 遇到比待插入元素大的元素，就把这种元素不断地右移，把位置空出来

    * 一直移到遇到头了，或者是遇到一个比待插入元素小的元素，就退出 `while` 循环，插入位置就此找到

    ```java
    private static void insert(int[] a, int low) {
        int value = a[low];
        int i = low - 1;
        // 比如 a[3] 比待插入元素 a[2] 大，那就把 3 不断右移，腾出位置
        while (i >= 0 && a[i] > value) {
            a[i + 1] = a[i];
            i--;
        }
        // 往 i + 1 这个索引处插入我们最开始漏出来的那个元素
        a[i + 1] = value;
    }
    ```

    > **提示**：`insert` 里真正的"插入"是最后那一行 `a[i + 1] = value`。前面整个 `while` 循环做的全是右移腾位，一轮插入只写一次元素——这也正是插入排序交换次数少的根本原因。

* **非递归版**

    * 同样是单路递归，外层加一个循环就够了

    * 原来那个用来递归的方法删掉，外层写一个 `for` 循环，循环变量就叫 `low`

    * `low` 从索引 1 开始（0 号元素本身就是长度为 1 的已排序区），一直循环到数组长度减一为止，写成 `low < a.length` 就行

    * 每轮插入执行的代码跟以前完全一样，直接搬过来，一个字都不用改

    ```java
    public static void insertSort(int[] a) {
        for (int low = 1; low < a.length; low++) {
            insert(a, low);
        }
    }
    ```

## 希尔排序（shell sort）

* **本质与复杂度**

    * > **定义**：针对插入排序做的一种改进。

    * 概括成一句话：先把数据分组，每组内部再用插入的方法来排序

    * 分组依据是元素之间的间隙，间隙相同的元素归到同一组

    * 最好和平均时间复杂度都能达到 $O(n \log n)$，但最坏情况还是 $O(n^2)$

### 按间隙分组，组内各自插排

* **间隙为 4 的分组示例**

    * 原数组 `9 3 7 2 5 8 1 4`，下标 0 到 7，`gap = 4`

        ```text
        gap = 4
          下标 0、4  →  9, 5     排序后 →  5, 9
          下标 1、5  →  3, 8     原来就是升序，不用动
          下标 2、6  →  7, 1     排序后 →  1, 7
          下标 3、7  →  2, 4     原来就是升序，不用动

        本轮结果：5  9  3  8  1  7  2  4    组内有序了，整体仍然无序
        ```

    * 一轮分组排完之后只是组内有序，整体上还是无序的

* **间隙变化时分组关系随之改变**

    * `gap` 从 4 变成 2 之后重新分组

        ```text
        gap = 2
          下标 0、2、4、6  →  5, 1, 9, 7    排序后 →  1, 5, 7, 9
          下标 1、3、5、7  →  3, 2, 8, 4    排序后 →  2, 3, 4, 8

        本轮结果：1  5  7  9  2  3  4  8
        ```

    * 这回谁和谁同组已经完全变了，间隙一变分组关系就跟着变，这正是间隙在起作用

    * 间隙为 1 时相当于把所有元素连起来、整体作为一组，再做一遍插入排序，结果就是最终的有序序列

    * 整个流程是 `gap` 从 4 开始，逐渐缩小到 2、到 1，`gap` 等于 1 的时候排序完成

### 为什么不一步到位

* **插入排序就是间隙为一的情况**

    * 盯着最大的元素 9，假设它在下标 0，看它要被交换多少次才能到达最终位置

        ```text
        gap = 1（插入排序）
        第 1 次插入：9 向右移动一格
        第 2 次插入：9 又移动一格
        第 3 次 …… 第 4 …… 第 5 …… 第 6 ……
        第 7 次插入：9 到达最终位置

        合计：7 次交换
        ```

* **希尔排序下 9 只用了 3 次交换**

        ```text
        gap = 4：9 与 5 被分到一组，做插入排序 → 交换 1 次
        gap = 2：9、5、1、7 分在同一组，做完插入排序，9 与 7 交换 1 次
        gap = 1：所有数据都被分到一组，9 只需要再跟 8 交换 1 次

        合计：3 次交换
        ```

    * 最后所有数据被分到一组的时候，9 只需要交换一次就到位了，它的步子比以前迈得大了。

    * 分组之后每次都能让元素更快速地移动到最终位置，交换次数因此变少，这就是希尔排序的全部优点

### gap 的生成与代码改写

* **间隙的生成方式**

    * 间隙的生成方式有很多，其中一种比较简单：初始间隙取数组长度除以 2，之后每次再除以 2，直到间隙等于 1

    ```java
    for (int gap = a.length / 2; gap >= 1; gap >>= 1) {
        // ...
    }
    ```

    * 变量名就叫 `gap`；数组长度是 8 时初始 `gap` 就是 4，每轮等于上次的除以 2，即 4 → 2 → 1，`gap` 小于 1 时结束循环

    > **提示**：除以 2 这个操作可以换成一位运算，除以 2 写成右移一位，所以递减那一步用 `gap >>= 1` 更快。

* **改写规则只有一个**

    * 插入排序可以看作是希尔排序在间隙为 1 时的一种特殊情况，所以循环内的代码跟插入排序非常像，拿过来改一条规则就行

    * 规则是：插入排序里凡是出现"1"的地方，全部改成 `gap`

    > ⚠️ **易错点**：凡出现"1"的地方都要改成 `gap`，唯一目的就是确保参与操作的两个元素始终在同一组里。漏改一处，组内元素就会被别组的元素干扰，排序直接就错了。

    ```java
    public static void shellSort(int[] a) {
        for (int gap = a.length / 2; gap >= 1; gap >>= 1) {
            for (int low = gap; low < a.length; low++) {
                int value = a[low];
                int i = low - gap;
                while (i >= 0 && a[i] > value) {
                    a[i + gap] = a[i];
                    i -= gap;
                }
                a[i + gap] = value;
            }
        }
    }
    ```

* **一轮内层循环走过的位置**

    * 最外层第一次进来时 `gap` 的值是 4，因为 8 ÷ 2 = 4，所以这一轮是以间隙为 4 来排序的。

    * 内层循环从 `gap` 开始，不是从 1 开始；`low` 代表未排序区最左边那个元素

    * `gap = 4` 这一轮里把下标 4 上的 5 当成它这一组被排序的元素，已排序元素是下标 0 的 9

    * 先把左边界这个元素 5 记录到临时变量里，然后注意这里也不是 `low - 1` 了。

    * 原来 `low - 1` 是紧挨着它的那一个元素；现在它跟 9 是一组，所以是 `low - gap`，也就是 $4 - 4 = 0$，正好找到下标 0 的元素 9

    * 把 9 看成已排序区的元素、5 看成未排序区的元素，做一次插入：9 比 5 大，向右移后位置空出来，5 插进去，这一组就排好了。

    * 内层循环一次只干这一件事，然后 `low` 加加往下走：4 排 5 和 9，5 排 8 和 3，6 排 1 和 7，7 排 2 和 4

    * 当 `low` 等于数组长度时内层循环结束，`gap = 4` 这一轮的希尔排序也就结束了；后面 `gap` 缩小到 2、到 1 时套路完全一样

## 归并排序（merge sort）

* **性质与思想**

    * 无论最差、最好还是平均情况，时间复杂度都是 $O(n \log n)$

    * 属于稳定排序算法

    * 唯一的缺点是空间复杂度比较高，会占用额外的空间

    * 体现的思想是一种分而治之

### 分

* **切到只剩一个元素为止**

    * 从中间切一刀让数据量减少一半，减少一半以后看左边这些数据能不能排

    * 如果还不会排就再切分、再减少一半，一直递归下去

    * 一直切到范围内只剩一个数据就不用再切了，因为一个数据自己可以认为是有序的，它已经达到"治"的状态

        ```text
                                [9 3 7 2 5 8 1 4]
                               /                 \
                        [9 3 7 2]               [5 8 1 4]
                        /       \               /       \
                    [9 3]      [7 2]         [8 5]     [1 4]
                    /  \       /  \         /  \      /  \
                  [9]  [3]   [7]  [2]     [8]  [5]   [1]  [4]
        ```

* **合并由小到大**

    * 一个元素的有序结果和它紧邻的元素也各自有序，两个有序结果合并就是有序数组合并。

    * 先把 9 和 3 合并得到 `[3 9]`，把 7 和 2 合并得到 `[2 7]`，再把这两个有序范围合并。

    * 右边同理：8 和 5 合并，1 和 4 合并，然后再把 `[5 8]` `[1 4]` 合并。

        ```text
        [9] + [3]                     →  [3 9]
        [7] + [2]                     →  [2 7]
        [3 9] + [2 7]                 →  [2 3 7 9]

        [8] + [5]                     →  [5 8]
        [1] + [4]                     →  [1 4]
        [5 8] + [1 4]                 →  [1 4 5 8]

        [2 3 7 9] + [1 4 5 8]         →  [1 2 3 4 5 7 8 9]
        ```

### split 的切分与终止

* **中间点的取法**

    * 中间点 `m` 等于 `left` 加上 `right` 除以 2，除以 2 用右移运算实现

    * 下次递归时数据量减半：左边范围是 `left` 到 `m`，右边这半的数据是 `m + 1` 到 `right`

* **停止切分的条件**

    * `left` 和 `right` 二者相等，表示这个范围内只有一个数据了，这时候停止递归、停止切分

    * 停止递归的条件就是 `left == right`，这时直接 `return`

    * 中间几行代码体现的是"分"，而决定什么时候结束"分"，就相当于已经找到了解决问题的方式、它已经有序了，这时候体现的就是"治"

    ```java
    private static void split(int[] a1, int left, int right, int[] a2) {
        // 治：范围内只剩一个数据了，本身就是有序的，没必要继续切分
        if (left == right) {
            return;
        }

        // 分：找中间点，把范围一分为二
        int m = (left + right) >> 1;
        split(a1, left, m, a2);
        split(a1, m + 1, right, a2);

        // 和：把两个有序范围合并
        merge(a1, left, m, m + 1, right, a2);

        // 合并结果落在临时数组里，还要拷回原数组
        System.arraycopy(a2, left, a1, left, right - left + 1);
    }
    ```

### split 与 merge 的衔接

* **参数含义**

    * `left` 和 `right` 代表要处理的数据最左侧和最右侧的索引，首次调用时范围从 0 到数组长度减一

    * `a2` 是临时数组，做有序数组合并必须有它，长度与原始数组一致

    | 参数 | 含义 |
    | :--- | :--- |
    | `a1` | 原始数组 |
    | `i` ~ `iEnd` | 第一个有序范围 |
    | `j` ~ `jEnd` | 第二个有序范围 |
    | `a2` | 临时数组，做有序数组合并必须有它，长度与原始数组一致 |

    * 调用 `merge` 时 `a1` 传原数组，第一个有序范围从 `left` 到 `m` 对应 `i` 和 `iEnd`，第二个从 `m + 1` 到 `right` 对应 `j` 和 `jEnd`

* **临时数组只创建一次**

    * 临时数组不是每次调用 `split` 都新建的，只创建一次、一直使用同一个就行

    * 方法定义那里要补充一个 `a2` 参数，两次递归调用时也都要把它传进去

    ```java
    int[] a2 = new int[a1.length];
    split(a1, 0, a1.length - 1, a2);
    ```

* **合并结果要拷回原数组**

    * `merge` 把合并结果放到临时数组里，出来之后还应该有一步把 `a2` 这个范围内的元素拷贝回 `a1`

    * 最终排序结果存在 `a1` 里，`a2` 只是个临时的

    * `System.arraycopy` 的范围是 `a2` 的 `left` 到 `a1` 的 `left`，拷贝个数是 `right` 减去 `left` 加一，正好是这个范围内的元素个数

* **打印一个范围内的数据**

    ```java
    System.out.println(Arrays.toString(Arrays.copyOfRange(a1, left, right + 1)));
    ```

    * `Arrays.copyOfRange` 从原始数组里拷贝一部分数据形成新数组，再调 `Arrays.toString` 转成字符串，直接打印数组是看不到内容的。

    * 第一个参数是原始数组；第二个 `from` 从 `left` 开始拷贝；第三个 `to` 是含头不含尾的，所以 `right` 要加一

## 四种排序算法的横向对比

* **复杂度与稳定性总表**

    * 作为参照，选择排序是 $O(n^2)$，这正是要改进它的原因

    | 排序算法 | 最好情况 | 平均情况 | 最坏情况 | 空间复杂度 | 稳定性 |
    | :--- | :--- | :--- | :--- | :--- | :--- |
    | 堆排序 | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ | $O(1)$ | 不稳定 |
    | 插入排序 | $O(n)$ | $O(n^2)$ | $O(n^2)$ | — | — |
    | 希尔排序 | $O(n \log n)$ | $O(n \log n)$ | $O(n^2)$ | — | — |
    | 归并排序 | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ | 较高，要占额外空间 | 稳定 |

    * 堆排序是四者中唯一最好、最坏、平均三者完全一样的，它的最坏和平均没有任何区别，代价是不稳定

    * 插入排序最好情况能到 $O(n)$，靠的就是数组本来就基本有序时几乎不用挪元素，但它平均和最坏都是 $O(n^2)$

    * 希尔排序是插入排序的改良版，平均和最好都是 $O(n \log n)$，但最坏还是 $O(n^2)$

    * 归并排序同样是三者一致 $O(n \log n)$，而且稳定，唯一要付的代价就是额外空间

    * 空间复杂度和稳定性这两项只对堆排序和归并排序讲过，插入排序和希尔排序没有细说

## 排序实现的性能实测

* **同一道数组排序题的耗时对比**

    * 用来比较的是同一道数组排序题，堆排序的递归版与非递归版下潜、以及希尔排序跑的是同一份数据

    | 实现 | 耗时 |
    | :--- | :--- |
    | 堆排序（递归版下潜） | 42 ms |
    | 堆排序（非递归版下潜） | 比递归版快 6 ms |
    | 希尔排序 | 28 ms |

    * 把下潜从递归改成非递归能拿到实打实的性能提升

    * 希尔排序在这个规模上跑得比两种堆排序都快，比改进后的堆排序还要快 8 ms

    * 学过的、时间复杂度和希尔排序相当（平均都是 $O(n \log n)$）的排序算法只有堆排序一个，它俩平均都能达到 $O(n \log n)$，这比冒泡、选择、插入都要强，但彼此之间还是有一定差异
