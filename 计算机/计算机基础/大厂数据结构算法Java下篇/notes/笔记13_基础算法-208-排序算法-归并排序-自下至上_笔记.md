# 基础算法-208-排序算法-归并排序-自下至上

## 两种归并写法的分工

* **自上而下的归并排序（top-down）**

    * > **定义**：靠 `split` 方法一层一层递归地把数据切下去、切到底再一层一层合上来的归并写法

    * 递归的落点在 `split` 方法里，它把分、治、和三块体现得非常清楚

* **自下而上的归并排序（bottom-up）**

    * > **定义**：不用递归、不调用 `split`，只用两重循环把同一个结果排出来的归并写法，名字里的 bottom-up 就是方向反过来

    * 换法的代价极低：`merge` 合并方法一个字都不用动，等于白捡

    * 真正要改的只有 `sort`，因为它不再需要调用 `split` 来切分数据

    * 骨架前提：数组长度已经记下来，合并时要用到的临时数组也提前建好，只差把循环填进去

---

## 不做切分也能预判合并

* 不切分的前提是**预先知道**每一轮是谁跟谁要合并，而不是靠递归去发现这件事

* 宽度为 1 时，索引 `0` 和 `1` 各自看成一个宽度为 1 的有序区间并合并，紧接着 `2`、`3` 合并，`4`、`5` 合并，`6`、`7` 合并，这是一轮

* 下一轮 `0~1` 宽度为 2 已经有序、`2~3` 宽度也为 2，两个宽度为 2 的有序区间再合并一次，宽度就从 2 变成 4，右边重复同样的过程

* 规律：**有序区间的宽度从 1 开始，每一轮都是上一轮的两倍**

```text
原始数组（长度为 8）

  width = 1 ：  [0~1]      [2~3]      [4~5]      [6~7]
  width = 2 ：  [0~3]                  [4~7]
  width = 4 ：  [0~7]

  合并的区间越来越宽，直到某一个宽度直接覆盖整个数组。
```

---

## width 外层循环

* 循环变量就叫 `width`，代表有序区间的宽度

* 初值是 1，每次在上一次的基础上乘以 2，写成 `width *= 2`

* 只要 `width` 小于数组长度 `n` 就继续往下走，一旦 `width` 等于或大于 `n`，循环停止

* 停止的理由是：宽度刚好等于数组长度意味着整个数组已经被当成一个区间合并完了，再往下没有意义

---

## left 与 right 边界

* 左边界 `left` 从 0 开始，每次加 2 倍的 `width`，统一记成 `left += 2 * width`

    ```java
    for (int left = 0; left < n; left += 2 * width) {
        ...
    }
    ```

* 宽度为 1 时左边界是 `0、2、4、6`，宽度为 2 时左边界是 `0、4`，对应待合并区间 `0~3`、`4~7`

* > **易错点**：图省事写成 `left += 2` 最容易踩坑。宽度为 1 时 `0、2、4、6` 看着确实像每次加 2，但宽度一旦变成 2，左边界就成了 `0、4`，跨度是 4 而不是 2，后面全是错的。

* 右边界用变量 `right` 代表，它有个很妙的来历：**本次的 `right` 就是下一次的 `left` 减 1**

    * 宽度为 1 时，左边界 `0` 的下一次左边界是 `2`，`2 - 1 = 1` 就是这一次的右边界

    * 宽度为 2 时，左边界 `0` 的下一次左边界是 `4`，`4 - 1 = 3` 就是这一次的右边界

* 宽度为 1、长度为 8 时，左边界 `6` 按公式算出的右边界是 `7`，刚好还在范围内；但只要数组长度不是 2 的整数倍，最后一次就一定会越界，所以要在算出来的结果和 `n - 1` 之间取一个最小值，用 `Math.min`

    ```java
    int right = Math.min(left + 2 * width - 1, n - 1);
    ```

* > **注意**：`n - 1` 就是数组最右侧那个合法索引，任何靠公式算出来的边界最后都要跟它取一次最小值兜底

* 边界光在脑子里想容易绕，可以把它打印出来看

    ```java
    System.out.printf("%d[%d~%d]\n", width, left, right);
    ```

* `%d` 是数字的占位符，中括号里两个 `%d` 分别代表左右边界，`%n` 表示换行；`printf` 自己不会自动换行，这个别忘了。

| `width` | `left` 的取值 | 参与合并的区间 |
| :--- | :--- | :--- |
| 1 | 0、2、4、6 | `0~1`、`2~3`、`4~5`、`6~7` |
| 2 | 0、4 | `0~3`、`4~7` |
| 4 | 0 | `0~7` |

## 中间索引 m 与 merge 参数对应

* `merge` 的参数不是只要 `left` 和 `right`，中间还夹着 `mid` 和 `mid + 1` 两个值，这俩也得算出来

* 参数对应关系是：

    * `merge` 里的 `i` 就是外层的 `left`

    * `mid` 是左边这个有序区间最右侧的索引

    * `mid + 1` 是右边这个有序区间最左侧的索引

    * `j` 就是外层的 `right`

* `m` 的算法拿宽度为 2、左边界为 0 的情况验证：`0 + 2 - 1 = 1`，正是左边那个有序区间最右侧的索引

    ```java
    int m = Math.min(left + width - 1, n - 1);
    ```

* `m` 加完 `width` 之后也可能越过数组的有效范围，所以一样要跟 `n - 1` 取最小值

* 参数齐了就是这一行；`m + 1` 紧挨着 `m`，所以 `j` 这一位不用单独算，直接写死

    ```java
    merge(a1, left, m, m + 1, right, a2);
    ```

## 临时数组的整块回写

* 整个内层循环跑完之后，才把临时数组 `a2` 的内容复制回 `a1`，这一步别忘

* 不用在循环内部一次搬一点，等所有合并都做完再整块搬一次就够

    ```java
    System.arraycopy(a2, 0, a1, 0, n);
    ```

* 拼起来完整的 `sort` 是这样，`merge` 保持原样不动

    ```java
    public static void sort(int[] a1) {
        int n = a1.length;
        int[] a2 = new int[n];

        for (int width = 1; width < n; width *= 2) {
            for (int left = 0; left < n; left += 2 * width) {
                int right = Math.min(left + 2 * width - 1, n - 1);
                int m = Math.min(left + width - 1, n - 1);
                merge(a1, left, m, m + 1, right, a2);
            }
        }

        System.arraycopy(a2, 0, a1, 0, n);
    }
    ```

## 两种写法的性能账

* 同一份力扣测试用例下，迄今最快的排序算法是希尔排序，28ms

* 刚写的自下而上归并排序性能又提升了 5ms，跑到 23ms

* 递归版与非递归版这两种实现之间差别还真没看出来，**都是 23ms**，挑一种自己容易理解的就行，没必要纠结哪种更优

* 归并排序成为学过的效率最快的排序算法，但在同一份测试上仍比不过 JDK 自带的 `Arrays.sort`，人家跑完所有测试只要 16ms，差了 7ms

* 想再往上突破有两个方向：一是干脆不用基于比较的排序算法，学过的所有排序都是基于比较的，换一条路走；二是把学过的排序算法组合起来

## 短板落在分而不在和

* 递归版 `split` 方法里的分、治、和三块清清楚楚

* 其中「和」是数据量大的时候在用的，把两个有序区间合并到一起，数据量越大它干得越漂亮，这确实很高效

* 缺点明显，落在「分」这块儿：判断达到「治」的依据是分、分、分到区间内只剩一个元素，才敢认定它有序、才肯结束「治」进入「和」

* 这种执念并不必要，只要范围内的数据量足够小，完全可以直接用插入排序让它有序，而不是死磕着非要切到只剩一个元素

* 落地条件看 `left` 和 `right` 两个边界：`right - left` 已经足够小（小于等于 32），就不再往下切，直接认为这段数据可以用插入排序尽快达到有序状态

* 插入排序在数据量小的时候干得非常好，条件一满足就地来一次插入排序就完了。

* > **注意**：「和」这一环是归并排序的强项，真正拖后腿的是「切到只剩一个元素才肯罢休」的执念；优化方向不是削弱「和」，而是提前终止「分」

---

## 区间版插入排序的改造

* 原来那个插入方法针对的是 `0` 到数组长度减一整个范围做插入，范围太大，给它指定一个区间，多传两个参数 `left` 和 `right` 代表左右边界

* 改动有四处：

    * 方法名跟外面重名了，换一个，叫 `insertion`

    * 外层循环的起点不再是数组开头，而是 `left + 1`

    * 循环上界从数组长度改成 `<= right`，因为 `right` 本身就是包含在内的右边界

    * 内层那个「往前挪」的循环，终止条件从 `0` 改成 `left`

* 改造后不用从头写，把原来那个拿过来稍加修改就能用

    ```java
    private static void insertion(int[] a, int left, int right) {
        for (int i = left + 1; i <= right; i++) {
            int t = a[i];
            int j = i;
            while (j > left && a[j - 1] > t) {
                a[j] = a[j - 1];
                j--;
            }
            a[j] = t;
        }
    }
    ```

## split 出口与混合效果

* 在 `split` 里加一个出口，`right - left` 小于等于 32 就地走插入排序并直接返回

    ```java
    private static void split(int[] a, int left, int right, int[] aux) {
        if (right - left <= 32) {
            insertion(a, left, right);
            return;
        }
        int mid = left + (right - left) / 2;
        split(a, left, mid, aux);                    // 分
        split(a, mid + 1, right, aux);                // 分
        merge(a, left, mid, mid + 1, right, aux);     // 和
    }
    ```

* 简单测试确认数组确实排好了，但数据量只有 8 个元素，一进去条件就直接满足，内部直接走插入排序，「和」那一段逻辑基本没被用上

* 放到力扣上跑才有意义，那边的测试数据量要大得多

* 实测结果：JDK 的 `Arrays.sort` 是 16ms，改造后的归并加插入排序做到 **15ms**，比 JDK 给的方案还领先 1ms

## 快速排序的分区思想

* **快速排序（quick sort）**

    * > **定义**：基于比较的排序算法里速度最快的，数据量越大优势越明显

    * 核心思想是每一轮找到一个基准点元素，把比它小的排到它左边，比它大的排到它右边

    * 找基准点元素 4 做一轮操作后，4 的位置就已经确定了——左边都比它小，右边都比它大，下次排序 4 不用再参与。

    * 针对 4 左侧的区域重复这个过程，右侧的区域也重复这个过程，不断重复，整个数组就有序了。

* **分区（partition）**

    * > **定义**：选一个基准点，把比它小的归到左边、比它大的归到右边，让基准点落到它的最终位置上

    * 每一轮操作称为分区操作，快排的分区方案有多种变体，其中一种叫洛莫托（Lomuto）分区方案

---

## sort、quick 与 partition 的分工

* 最外层准备一个 `sort` 方法，但它不太适合用来递归，所以另外准备一个专门用作递归的方法，就叫 `quick`

* `quick` 的参数是有待排序的数组加左右边界 `left`、`right`；首次调用时 `left` 的初始值给 0，`right` 的初始值给数组长度减 1

* `quick` 内做的事就是分区操作；因为分区将来有不同的实现方案，所以把分区单独写成 `partition` 方法，参数是数组加左右边界，将来换方案时方便替换

* `partition` **必须有一个返回值**，代表基准点元素的最终索引，就叫 `p`；这个索引下次分区就不用考虑了，基准点左边继续分区、右边继续分区，它自己不用管

* 下次递归该从哪两个区域做分区：一个是从 `left` 到 `p - 1`，另一个是从 `p + 1` 到 `right`

    ```java
    private static void quick(int[] a, int left, int right) {
        if (left >= right) {
            return;
        }
        int p = partition(a, left, right);
        quick(a, left, p - 1);
        quick(a, p + 1, right);
    }
    ```

* 结束递归的判据：`left` 和 `right` 相遇、两者取到同一个值，说明区间内只剩一个元素，那一个元素的位置就不用变了，写成条件就是 `left >= right`

* 架子搭完先不急着实现 `partition`，不同的只是这个分区方法可能采用不同的方案，剩下的代码都不用动

## 洛莫托分区的一轮操作

* 第一要点：在这些元素里选一个基准点，洛莫托分区方案里直接把**最右侧的元素**当成基准点，例子里基准点就是 5

* 第二要点：设置两个指针 `i` 和 `j`，都从左边界开始，各自含义必须分清

    * `j` 从左向右去找**比基准点小的**元素

    * `i` 反过来，是去找**比基准点大的**元素

* 两个指针各自都找到了就交换一下

* 第三要点：最后一步，基准点要和 `i` 交换，这一步最容易漏

* 示例里 `left = 0`，两个指针刚开始都停在索引 1 上；`j` 一上来就找到一个小的，但这时不需要交换，因为 `i` 和 `j` 的索引位置一样，自己跟自己交换没有意义

* 条件凑齐的时刻是：`i` 停在一个比基准点大的元素上，`j` 停在一个比基准点小的元素上，这时候把这两个位置交换，然后两个指针各自再前进一位

* `j` 走到头的时候 `j` 的任务就完成了，但还差一步：`i` 左边的所有元素都比基准点小，而基准点将来应该放在中间，所以还要让基准点元素跟 `i` 交换一下

* 交换完基准点 5 到达最终位置，下轮分区不用参与，只要对它左边和右边继续重复递归

## 指针走位与最终入位

```text
  left                                        right
    ↓                                           ↓
  [ 4 | 3 | 2 | 1 | 7 | 9 | 8 |      5      ]
                          ↑        ↑
              i 停在这里：a[i] >= pv      基准点 pv = a[right]

  j ：每一轮先向右走一步，只要 a[j] < pv，就跟 i 交换，然后 i++
  i ：只要还没遇到 >= pv 的元素就跟着走；一旦遇到就原地不动，等 j 来换
  j 走到 right 停下时：[left, i-1] 全是小于 pv 的
                      i 停在第一个 >= pv 的元素上
  最后 swap(a, i, right) —— 基准点入位，分区结果 p = i
```

* `j` 的走法是每一轮先向右走一步，只要 `a[j] < pv` 就跟 `i` 交换，然后 `i++`

* `i` 只要还没遇到 `>= pv` 的元素就跟着走，一旦遇到就原地不动，等 `j` 来换

* `j` 走到 `right` 停下时，`[left, i-1]` 全是小于 `pv` 的，`i` 停在第一个 `>= pv` 的元素上

* 最后一次 `swap(a, i, right)` 让基准点入位，分区结果 `p = i`

## partition 的实现要点

* 一开始先把最右侧、也就是基准点这个元素的值先记录下来，起变量名 `pv`，代表数组 `a` 索引 `right` 处的元素值，因为待会有很多元素都要跟它比较

* 两个指针 `i` 和 `j` 初始都是 `left`

* `j` 的循环写成：当 `j` 还小于右边界 `right` 时，就让 `j` 不断向右移动，每移动一次判断 `a[j]` 是不是小于记录的基准点值 `pv`

* `j` 找到比基准点小的元素后**不一定**立刻跟 `i` 交换：一开始找到的 4 与 `i` 在同一个位置，非要交换也不会出错，只是没有必要；所以要加条件，只有 `i` 不等于 `j` 时才有必要交换，交换代码直接用现成的 `swap` 方法

* `i` 能不能每次循环都直接 `i++`？肯定不行。它现在能自增是因为没有遇到比基准点大的元素，一旦遇到（比如 7）就停下来——下一轮循环 `j` 会自增，但 `i` 自己不自增了。

* 所以 `i` 一旦遇到比基准点大的元素（当然也包括等于的情况）就不应该自增；反过来说，`j` 找到了比基准点小的元素，就意味着 `i` 还没找到更大的，于是 `i` 应该自增

* > **易错点**：`i++` 不是每次循环都执行的，它必须写在 `if` 语句**里面**；写到 `if` 外面，`i` 就会一路冲过那个大元素，分区立刻失效

* 循环结束时最右侧是基准点元素，而 `i` 停在的是一个比基准点大的元素上，所以还要做一个 `swap`，交换这时的 `i` 和 `right`，把最右侧元素交换到中间去

* 返回值就是基准点最终所在的正确位置，也就是这时的 `i`

    ```java
    private static int partition(int[] a, int left, int right) {
        int pv = a[right];
        int i = left;
        for (int j = left; j < right; j++) {
            if (a[j] < pv) {
                if (i != j) {
                    swap(a, i, j);
                }
                i++;
            }
        }
        swap(a, i, right);
        return i;
    }
    ```

* 做完简单测试，排序后数组确实有序，洛莫托分区方法就实现完毕了。
