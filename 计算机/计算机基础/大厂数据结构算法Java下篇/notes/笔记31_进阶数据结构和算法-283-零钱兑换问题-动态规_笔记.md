# 进阶数据结构和算法-283-零钱兑换问题-动态规

## 零钱兑换问题

* **零钱兑换（Coin Change）**

    * > **定义**：给出一批面值不同的硬币，比如一分、两分、五分，每种硬币的数量都是无限的，问凑成指定总金额最少需要几个硬币。

    * 这个问题此前用**贪心算法**求解过，而贪心算法在这个问题上有可能得不到最优解。

    * 换用**动态规划**求解时，状态里记录的不再是价值而是**硬币个数**，而且每放一枚硬币，这个计数就加 1。

* **问题规模约定**

    * 硬币的种类数就是硬币数组的长度，每一种面值的可用数量无限。

    * 总金额决定了状态表的列数范围，从 0 到 `amount` 都要算。

    * 求解结果可能是无解的，凑不齐时要显式返回 -1 而不是返回一个假的数字。

---

## 与完全背包的概念对应

* **类比求解路径**

    * 零钱兑换问题与完全背包问题高度相似，可以直接把零钱兑换的每个概念对到完全背包上，递推式不必重新推导。

    * 相似点：两者都是拿"不同的物品"去凑一个总容量，且这些物品的数量都无限。

    * 不同点：完全背包求最终拿到的**最大价值**，零钱兑换求最后需要**最少的硬币个数**。

* **四个维度的对应关系**

    | | 完全背包 | 零钱兑换 |
    | :--- | :--- | :--- |
    | 容量那一维 | 背包容量 | 总金额 |
    | 物品那一维 | 物品重量 | 硬币面值 |
    | 价值那一维 | 物品价值（黄金 2400、白银 1600……） | 硬币个数 |
    | 优化目标 | 最大价值 | 最小价值 |

* **价值那一维的特殊性**

    * 硬币个数对应到物品价值时，它不像背包问题里黄金 2400、白银 1600 那样有明确数值，而是**论个**的：能装进去它的价值就是 1。

    * 正因为价值固定为 1，零钱兑换要求的就不是价值最大，而是价值最小——要求个数最少就等价于价值最小。

## 推表过程

* **第一轮：只有一分的硬币**

    * 总金额为 1 时一个 1 分硬币就够；总金额 2 需要两个 1 分；3 需要三个 1 分；4 需要四个；5 需要五个。

    * 也就是说只用 1 分硬币时，答案只能等于金额本身。

* **第二轮：加入两分的硬币**

    * 容量为 1 时 2 分硬币凑不齐，沿用上一次的结果不变，仍然认为用到了一个 1 分硬币。

    * 容量为 2，一个 2 分硬币就够，最小个数由两个 1 分硬币减少成一个 2 分硬币。

    * 容量 3 需要一个 2 分加一个 1 分；容量 4 需要两个 2 分；容量 5 需要两个 2 分加一个 1 分。

* **第三轮：加入五分的硬币**

    * 1 到 4 的容量都小于 5 分硬币的面值，全部保留上一次的结果不变。

    * 直到容量为 5 时，才能用一个 5 分硬币凑够，这比上次的两个 2 分加一个 1 分更少，于是更新成 1。

* **整张表**

    ```text
       面值组合 ┼   1    2    3    4    5
    ────────────┼──────────────────────────
            1分 ┼   1    2    3    4    5
         1分2分 ┼   1    1    2    2    3
      1分2分5分 ┼   1    1    2    2    1
    ```

    * 横轴是总金额 1 到 5，每往下一行表示多放开一种硬币面值。

    * 左下角那一行只用 1 分，答案等于金额本身；右下角那个 `1` 是三种面值全部放开后的最终答案。

## 状态转移递推式

* **`dp[i][j]` 的含义**

    * 二维表格中第 `i` 行第 `j` 列的值，表示只准使用前 `i` 种硬币面值、凑出总金额 `j` 所需的最少硬币个数。

* **装不下的情况**

    * 沿用上一次的答案不变，一分也不改。

    * 例如容量为 1 时尝试装面值为 2 的硬币装不下，那就直接把上一行同一列的数搬过来。

* **装得下的情况**

    * 求的是**最小值**，两个比较项分别是：上一行的个数 `dp[i-1][j]`，以及剩余容量能装下的最小个数再加 1，即 `dp[i][j - coins[i]] + 1`。

    * 后面这个式子的理解方式是倒回头查找：容量 3 装面值 2 的硬币时，剩余空间为 `3 - 2 = 1`，回头找空间为 1 的最少数个数（是 1），再与当前的 2 凑成两个硬币。

    * 之所以**加一**，是因为当前这枚硬币的价值固定就是 1。

* **状态转移示意**

    ```text
                        dp[i][j]
                           │
              ┌────────────┴────────────┐
              │                         │
       j >= coins[i]             j < coins[i]
            放得下                    放不下
              │                         │
              ▼                         ▼
       min( dp[i-1][j] ,          dp[i-1][j]
            dp[i][j-coins[i]] + 1 )
              │            │
              │            └─ 同一行往左倒查：剩余容量 j - coins[i] 的最优解
              └─ 上一行：只准用前 i-1 种硬币时的最优解
    ```

* **公式形式**

    $$
    dp[i][j] =
    \begin{cases}
    dp[i-1][j], & j < coins[i] \\[4pt]
    \min\big(dp[i-1][j],\ dp[i][j - coins[i]] + 1\big), & j \ge coins[i]
    \end{cases}
    $$

    * 公式里仍然把硬币面值写成"重量"，看到这个量就换算成对应的硬币面值。

    * 看到 `i - 1` 就是到上一行去找；看到 `j - 硬币面值` 就是在同一行往左倒查。

## 无解哨兵值

* **无解情形的识别**

    * 例如总金额最多到 5，而硬币面值只有一种就是 10，10 超过了最后的总金额，最后肯定凑不齐。

    * 这种没法装得下的位置，需要填一个**比当前总金额更大的值**，比如给个 6，或者直接给一个 `max`。

* **为什么取 `amount + 1`**

    * 这里**不建议**把最大值初始化成 `Integer.MAX_VALUE`，很多解法也不会这么做。

    * > **易错点**：若用 `Integer.MAX_VALUE`，将来对它做加法就超过整数范围，会变成负数。

    * 选 `amount + 1` 是因为这里的硬币最小面值就是 1，总金额为 5 时最大面额对应的最大硬币数也就是五个硬币，在五个的基础上再加一就超过了可能的最大数。

    * 于是 `amount + 1` 就代表整个表中最大的硬币数，也就是"凑不出来"的标记值。

* **返回值判定**

    * 将来去右下角取答案时，一旦发现它是 `max`，就说明在这种面值下凑不够，总金额无法满足。

    * 这种情况下返回 -1，表示没办法凑足。

## 二维数组实现

* **数组维度**

    * 行数与硬币个数保持一致，取 `coins.length`；列数为 `amount + 1`。

    * 定义二维数组只是为了让大家解题的过程中更好理解，可以先用二维做法求清楚，最后再优化降维。

* **第一个硬币必须单独拎出来**

    * > **易错点**：第一个硬币不存在上一行，没有 `i - 1`。对它而言，装得下时只执行式子的后半段即可，前面那部分不用考虑；装不下时把值初始化成 `max`。

    * 容量循环从 1 开始，容量 0 不用处理，它固定就是 0。

* **二维版本代码**

    ```java
    import java.util.Arrays;

    /**
     * 二维数组版本：先把过程求清楚，最后再降维
     */
    public static int coinChange(int[] coins, int amount) {
        // 行与硬币个数保持一致，列是 amount + 1
        int[][] dp = new int[coins.length][amount + 1];

        // 凑不出来时记的值：amount + 1 严格大于任何可行解
        int max = amount + 1;

        // ---- 第一个硬币：不存在 dp[i - 1]，单独处理 ----
        // 容量从 1 开始循环；0 不用处理，它固定就是 0
        for (int j = 1; j < amount + 1; j++) {
            if (j >= coins[0]) {
                // 装得下：剩余容量的最优解 + 当前这枚硬币（个数为 1）
                dp[0][j] = dp[0][j - coins[0]] + 1;
            } else {
                // 装不下：记成 max
                dp[0][j] = max;
            }
        }
        print2DArray(dp);

        // ---- 后续硬币：直接套递推式 ----
        for (int i = 1; i < coins.length; i++) {
            for (int j = 1; j < amount + 1; j++) {
                if (j >= coins[i]) {
                    // 装得下：上一次的个数  vs  剩余容量的最优解 + 1，取最小
                    dp[i][j] = Math.min(dp[i - 1][j], dp[i][j - coins[i]] + 1);
                } else {
                    // 装不下：沿用上一行的个数
                    dp[i][j] = dp[i - 1][j];
                }
            }
            print2DArray(dp);
        }

        // 右下角 = 所有硬币都试过之后，凑满 amount 的最少硬币数
        int res = dp[coins.length - 1][amount];
        return res < max ? res : -1;
    }
    ```

* **后续硬币的循环**

    * 外层循环从 1 开始遍历后续硬币，一直到小于 `coins.length`；内层从容量 1 循环到小于 `amount + 1`。

    * 每一轮只需判断放不放得下：放得下就套 `Math.min(dp[i - 1][j], dp[i][j - coins[i]] + 1)`，放不下就取 `dp[i - 1][j]` 保持上一次的硬币个数不变。

* **打印二维数组**

    * 为了观察每一轮的结果，用一个 `print2DArray` 把二维数组打出来；第一行先打表头索引，所以看结果时从第二行开始看。

    ```java
    private static void print2DArray(int[][] dp) {
        // 第一行先打表头索引
        StringBuilder head = new StringBuilder();
        for (int j = 0; j < dp[0].length; j++) {
            head.append(String.format("%5d", j));
        }
        System.out.println(head);

        // 之后每处理完一个硬币，就打一整行
        for (int i = 0; i < dp.length; i++) {
            StringBuilder row = new StringBuilder();
            for (int j = 0; j < dp[i].length; j++) {
                row.append(String.format("%5d", dp[i][j]));
            }
            System.out.println(row);
        }
        System.out.println();
    }
    ```

* **返回值处理**

    * 右下角结果小于设定的最大值，表示有解，直接返回该值。

    * 右下角结果大于等于设定的最大值，表示无解、无法完全找零，返回 -1。

## 降维成一维与细节优化

* **降维方向**

    * 把第一维 `i` 全部去掉就得到一维数组，打印时直接打印一维数组。

* **三步优化**

    ```java
    /**
     * 降维 + 细节优化后的版本
     */
    public static int coinChange1D(int[] coins, int amount) {
        int max = amount + 1;
        int[] dp = new int[amount + 1];

        // 优化一：先整体填成 max，再单独把 dp[0] 拉回 0
        Arrays.fill(dp, max);
        dp[0] = 0;

        // 优化二：增强 for 替换按下标循环
        for (int coin : coins) {
            // 优化三：内层直接从 coin 起步，装不下的那几次直接跳过
            for (int j = coin; j < amount + 1; j++) {
                dp[j] = Math.min(dp[j], dp[j - coin] + 1);
            }
        }

        int res = dp[amount];
        return res < max ? res : -1;
    }
    ```

    * 第一条，把处理第一个硬币的逻辑与处理后续硬币的逻辑合并：用 `Arrays.fill` 把数组初值全部填成 `amount + 1`，再对 `dp[0]` 特殊处理成 0，这样两个逻辑统一成一个，处理第一个硬币的代码整段删掉，循环从零开始。

    * 合并后连 `else` 分支也不需要了，因为那等于自己复制自己，没有必要。

    * 第二条，把按下标循环改成增强 for，IDEA 也会提示"这个根据索引进行循环可以被替换为增强 for 循环"。

    * 第三条，内层循环原本从 1 起步再靠 `if` 判断能否放下，既然装不下的那几次什么也不做，直接从 `coin` 开始循环即可，这样 `if` 条件就可以去掉了。

* **降维后的结果校验**

    * 一开始把数组初始化成最大值，后面三次循环处理三个硬币，最终得到的结果仍然正确。

## 零钱兑换 II 的递推式

* **零钱兑换 II（力扣 518）**

    * > **定义**：沿用零钱兑换的背景，给定硬币数组 `coins` 和总金额 `amount`，每种硬币数量无限，问用这些面值不同的硬币凑成 `amount` 一共有几种凑法。

    * 它是零钱兑换问题的变体，问的不是最少需要几个硬币。

    * 凑法只按硬币的组合来数，同样一组硬币换个先后次序不会再算一次。

* **状态表的坐标轴**

    * 横轴是硬币的面值，可以理解成物品的重量；纵轴对应不同的金额，依然可以理解成背包的容量。

* **凑法计数的推表**

    * 第一轮只有 1 分硬币时，容量 1 到 5 的凑法都只有一种。

    * 第二轮加入 2 分硬币：容量 1 放不下直接沿用上次的一种；容量 2 新增"一个 2 分"，变成 2 种；容量 3 新增"一个 2 分加一个 1 分"，是 2 种；容量 4 倒查 `4 - 2 = 2` 的两种凑法再各配一个 2 分，变成 3 种；容量 5 倒查 `5 - 2 = 3` 的两种凑法再各配一个 2 分，变成 3 种。

    * 第三轮加入 5 分硬币：容量 1 到 4 都放不下直接继承，容量 5 多出"一个 5 分"这一种，最终答案是右下角。

    ```text
       面值组合 ┼   1    2    3    4    5
    ────────────┼──────────────────────────
            1分 ┼   1    1    1    1    1
         1分2分 ┼   1    2    2    3    3
      1分2分5分 ┼   1    2    2    3    4
    ```

    * 第一行全部是 1，因为只有 1 分硬币时凑法唯一；每往下一行、多放开一种面值，右边的格子就在继承上一行凑法的基础上，再加上"以当前这枚硬币开头"的新凑法。

* **递推式**

    * 放不下时把上一行的方法数原样继承下来：上次有一种这次也是一种，上次有三种这次也就是三种。

    $$
    dp[i][j] = dp[i-1][j] \qquad (j < coins[i])
    $$

    * 放得下时，先继承上一行的凑法总数，再加上倒回头查到的 `j - coins[i]` 的凑法数，这个加数来自**本行**而不是上一行。

    $$
    dp[i][j] = dp[i-1][j] + dp[i][j - coins[i]] \qquad (j \ge coins[i])
    $$

    * 与最少硬币数那一版相比，这里的"取最小值"变成了"直接相加"，而且后面的 `+ 1` 不见了——因为数的是凑法而不是硬币个数，本轮新硬币本身不额外贡献一个计数。

* **以容量 4 放入 2 分硬币为例**

    * 先把上次的四个 1 分继承下来得到 1 种，再倒查 `4 - 2 = 2` 得到 2 种，把这个 2 分别与 `1 1` 和 `2` 组合，多出两种，合计三种。

## 零钱兑换 II 的实现与初始化

* **第 0 列必须初始化为 1**

    * 求容量为 2、放入面值为 2 的硬币有几种方法时，上式会先到上一行取 `dp[i-1][j]` 得到 1，再倒查 `2 - 2 = 0` 落到索引零这一列。

    * 要让 `1 + 1 = 2` 成立，索引零这个位置必须给 **1**，因为不选硬币本身就是一种凑法。

    * 所以其余几个索引位置也都要附上初值 1：例如放入 5 分硬币时，从上一行继承 3 种，再加上 `5 - 5 = 0` 这一列的 1，得到 4 种。

    * > **易错点**：这是这一题与最少硬币数那一版最大的差别——那一版第 0 列是 0，这一版第 0 列必须是 1。若误填成 0，容量 5 那一格会算成 `3 + dp[2][0] = 3 + 0 = 3`，答案就错了。

* **二维数组实现**

    ```java
    /**
     * 力扣 518：换零钱，一共有几种凑法
     */
    public static int change(int amount, int[] coins) {
        int[][] dp = new int[coins.length][amount + 1];

        // 关键：第 0 列统一初始化为 1
        for (int i = 0; i < coins.length; i++) {
            dp[i][0] = 1;
        }

        // ---- 第一个硬币：没有 dp[i-1] 的部分，只能取后半段 ----
        for (int j = 1; j < amount + 1; j++) {
            if (j >= coins[0]) {
                dp[0][j] = dp[0][j - coins[0]];
            }
            // 放不下就保持 0 不变
        }
        print2DArray(dp);

        // ---- 后续硬币：第 0 行已经处理过，从第 1 行开始 ----
        for (int i = 1; i < coins.length; i++) {
            for (int j = 1; j < amount + 1; j++) {
                if (j >= coins[i]) {
                    // 放得下：上一次的凑法总数 + 剩余容量的凑法数
                    dp[i][j] = dp[i - 1][j] + dp[i][j - coins[i]];
                } else {
                    // 放不下：继承上一行的凑法总数
                    dp[i][j] = dp[i - 1][j];
                }
            }
            print2DArray(dp);
        }

        // 右下角就是答案
        return dp[coins.length - 1][amount];
    }
    ```

    * 行数与硬币个数一致、列数为 `amount + 1`，与前面几题的建表方式相同。

    * 第一个硬币没有 `dp[i-1]` 可取，只能取式子的后半段；放不下时保持 0 不变。

    * 执行结果与推表一致：最初都是一种凑法，第二轮到容量 2、3 变成两种，容量 4、5 变成三种，最后放入 5 分硬币后方法总数增加成 4。

    * 返回值直接取右下角即可，不必像最少硬币数那版那样再判定无解。

    * 把二维数组降维成一维的做法与前面几题差不多，这一版降维的具体写法未在正文中给出。

## 力扣 518 零钱兑换 II

* **题目描述**

    * 给定硬币数组 `coins` 和总金额 `amount`，每种硬币的数量都是无限的，问凑成 `amount` 一共有几种凑法；它与"最少需要几个硬币"问的不是一回事。

    * `coins = [1, 2, 5]`、`amount = 5` 时答案是 **4**。

* **四种凑法**

    * 前三种是继承来的：只有 1 分时凑 5 只有 1 种；放入 2 分后新增 `2 + 1 + 1 + 1` 变 2 种；容量 5 时再新增 `2 + 2 + 1` 变 3 种。

    * 最后放入 5 分硬币时，容量 1 到 4 都放不下直接继承，容量 5 多出第 4 种。

    1. $1 + 1 + 1 + 1 + 1$
    2. $2 + 1 + 1 + 1$
    3. $2 + 2 + 1$
    4. $5$

* **答案与校验点**

    * 答案为 `dp[coins.length - 1][amount] = 4`。

    * 校验时不能漏掉把第 0 列所有值初始化成 1 这一步，否则最后一格会算成 3。
