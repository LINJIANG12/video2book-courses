# 进阶数据结构和算法-352-股票系列问题-Lee

## 冷冻期：买入状态得往前挪一天

### 冷冻期与示例走法

* **冷冻期（cooldown period）**

    * > **定义**：卖出之后不能当天再买入，必须隔一整天才恢复交易。

    * 规则：只卡住"卖出当天不能再买"，隔天买入合法。

    * 边界：交易次数不限，且这一道题不收手续费。

    * 影响：不改变收益上限，只把最顺手的那笔交易直接作废。

* **示例 `[1, 2, 3, 0, 2]`**

    * 天真做法：第 0 天 1 买入、第 2 天 3 卖出赚 2；但第 2 天卖出后冷冻期生效，第 3 天价格 0 时不能买，0 买 2 卖那 2 块钱利润就这么错过。

    * 最优做法：第 0 天 1 买入、第 1 天 2 卖出赚 1；冷冻一天；第 3 天 0 买入、第 4 天 2 卖出赚 2；合计 3。

    ```text
     第0天   第1天   第2天    第3天   第4天
       1  ──► 2  ──►[冷冻]──►  0  ──►  2
       买      卖     不能买     买      卖
      +1                                  +2
                              合计 = 1 + 2 = 3
    ```

### 状态定义与转移方程

* **`buy[i]` 与 `sell[i]`**

    * `buy[i]`：第 $i$ 天结束时手上持有股票时的最大利润。

    * `sell[i]`：第 $i$ 天结束时手上没有股票时的最大利润。

* **两条状态转移**

    $$
    buy[i] = \max(buy[i-1],\ sell[i-2] - prices[i])
    $$

    $$
    sell[i] = \max(sell[i-1],\ buy[i-1] + prices[i])
    $$

    * 买：要么延续上一次的利润不变（当天不买），要么假设"前两天"已经卖出、在那个利润基础上减今天价格；两者取较优。

    * 卖：要么延续上一次卖出的利润不变，要么假设昨天已经买入、在那个利润基础上加今天价格；两者取较优。

    * > **易错点**：冷冻期挪动的是**买入**状态的依赖，`buy[i]` 要看 `sell[i-2]` 而不是 `sell[i-1]`；卖出侧不受限制，照旧取 `buy[i-1]` 加今天价格。

### 初值、越界特例与实现

* **初值与首两天的单独特判**

    * `buy[0] = -prices[0]`，`sell[0] = 0`——第一天不可能持有过股票，卖出这条线就是 0。

    * `buy[1] = Math.max(-prices[0], -prices[1])`：第 0 天之前什么状态都没有，所以第二天买只能拿当天价格 2 起算，答案是两个价格取负后的较大者。

    * `sell[1] = Math.max(sell[0], buy[0] + prices[1])`：在延续 0 与"第一天买的股票今天卖"之间取较大者。

* **长度为 1 的特例**

    * > **易错点**：数组长度只有 1 时 `buy[1]` 直接越界，而这种情况下压根做不成一次完整交易，长度为 1 必须直接返回 0；处理完这个特例，循环才能从索引 2 起跑而不再担心越界。

* **逐天推演**

    | 天 | 价格 | `buy` | `sell` |
    | :--: | :--: | :--: | :--: |
    | 0 | 1 | -1 | 0 |
    | 1 | 2 | -1 | 1 |
    | 2 | 3 | -1 | 2 |
    | 3 | 0 | 1 | 2 |
    | 4 | 2 | 1 | **3** |

    * 第 3 天价格 0 时，买入参考第 1 天卖出利润 1 减 0 得到 1，首次优于延续值 -1。

    * 第 4 天卖出参考昨天买入利润 1 加今天价格 2 得到 3，这就是答案。

* **一维数组实现**

    ```java
    public int maxProfit(int[] prices) {
        int n = prices.length;
        if (n == 1) {
            // 只有一天，做不成一次完整的买卖
            return 0;
        }

        int[] buy = new int[n];
        int[] sell = new int[n];

        buy[0] = -prices[0];
        sell[0] = 0;

        // 第 1 天要特殊处理：它得去看"前两天"，而第 0 天之前不存在
        buy[1] = Math.max(-prices[0], -prices[1]);
        sell[1] = Math.max(sell[0], buy[0] + prices[1]);

        for (int i = 2; i < n; i++) {
            buy[i] = Math.max(buy[i - 1], sell[i - 2] - prices[i]);
            sell[i] = Math.max(sell[i - 1], buy[i - 1] + prices[i]);
        }

        return sell[n - 1];
    }
    ```

    * 循环结束返回 `sell[n - 1]`；对 `[1, 2, 3, 0, 2]` 得 3，与推演对得上。

    * > **提示**：两个一维数组完全可以压成几个变量，思路一模一样，这是留给自己的降维练习。

## 限制次数：四个状态记两次买卖

### 四条依赖链

* **状态含义**

    * 规则：最多只能买卖两次，没有手续费，也没有冷冻期。

    * `buy1` / `sell1` 记第一次买卖，`buy2` / `sell2` 记第二次买卖；将来降维之后就是四个变量。

    * 四条线的初始状态一样：第一次买手里利润是当天的负价格，第一次没什么可卖的取 0，第二次买、第二次卖同理。

* **依赖方向**

    * 第一次买：不依赖任何历史状态，直接以当日价格买入。

    * 第一次卖：依赖昨天第一次买时的利润，**加上**当日价格。

    * 第二次买：依赖昨天第一次卖时的利润，**减去**当日价格。

    * 第二次卖：依赖昨天第二次买时的利润，**加上**当日价格。

    * > **提示**：买入永远是花掉利润（做减法），卖出永远是赚回利润（做加法），方向千万别搞反；第二次买依赖的是"昨天第一次卖的利润"，而不是笼统的"昨天状态"。

    ```text
     买1 ──► 卖1 ──► 买2 ──► 卖2 ──► … ──► 买K ──► 卖K  ← 答案
      │        │       │        │              │       │
      │        │       │        └ 昨天买K ＋ 当日价
      │        │       └ 昨天卖(K-1) － 当日价
      │        └ 昨天买1 ＋ 当日价
      └ 当日价买入，不依赖任何历史
    ```

### 初始状态与复用要点

* **初值取整数最小值**

    * 四个状态初值分别是 `Integer.MIN_VALUE` 和 0，变量名区分开即可。

    * 因为买入初值是整数最小值，外层下标可以从 0 开始，将来还能直接用增强 for 循环遍历价格。

    * > **提示**：第一天并没有第二次买卖，下面那组记录此时仍然是第一次买卖，意义在于兜底——只要走完了一次买卖就得把它记下来，状态不能断掉。

* **从"任意多次并计手续费"的版本复制时改哪里**

    * `buy1` 去掉对 `sell1` 的依赖，式子就是 `-price`。

    * `sell1` 的式子不用动，保持昨天的买入利润加今天价格。

    * `buy2` 的式子不用动，它本来就是依赖第一次卖的利润。

    * `sell2` 的式子也不用动。

    * 沿用此前对代码结构做过的两处优化：`buy` 初值取 `Integer.MIN_VALUE` 以便循环从索引 0 开始；计算 `sell` 时依赖当天的 `buy` 状态而不是昨天的，虽然推导写的是昨天的 `buy`，但最终结果一致。

### 示例与降维实现

* **示例 `[3, 5, 0, 3, 1, 4]`**

    * 走法一：3 买 5 卖赚 2，0 买 3 卖赚 3，合计 5。

    * 走法二：把 0 买 3 卖当第一次赚 3，1 买 4 卖当第二次赚 3，合计 6，更大。

    * 第 3、4、5 天的四个状态都停在 $(0, 3, 2, 5)$：这些天的价格卡得正好，两条线都没有变得更优。

    | 天 | 价格 | `buy1` | `sell1` | `buy2` | `sell2` |
    | :--: | :--: | :--: | :--: | :--: | :--: |
    | 0 | 3 | -3 | 0 | $-\infty$ | 0 |
    | 1 | 5 | -3 | 2 | -5 | 0 |
    | 2 | 0 | 0 | 2 | 2 | 0 |
    | 3 | 3 | 0 | 3 | 2 | 5 |
    | 4 | 1 | 0 | 3 | 2 | 5 |
    | 5 | 4 | 0 | 4 | 2 | **6** |

    * 最后一天第二次卖若按上一次的 5 卖出则维持 5，若在昨天第二次买入的利润 2 上加今天价格 4 则得 6，取 6。

* **降维后的四个变量实现**

    ```java
    public int maxProfit(int[] prices) {
        int buy1 = Integer.MIN_VALUE, sell1 = 0;
        int buy2 = Integer.MIN_VALUE, sell2 = 0;

        for (int price : prices) {
            // 第一次买：不依赖任何状态，就是以当日价格买入
            buy1 = Math.max(buy1, -price);
            // 第一次卖：昨天的买入利润 ＋ 今天的价格
            sell1 = Math.max(sell1, buy1 + price);

            // 第二次买：依赖昨天第一次卖的利润 － 今天的价格
            buy2 = Math.max(buy2, sell1 - price);
            // 第二次卖：依赖昨天第二次买的利润 ＋ 今天的价格
            sell2 = Math.max(sell2, buy2 + price);
        }

        return sell2;
    }
    ```

    * 最终答案存在 `sell2` 里，返回它；对 `[3, 5, 0, 3, 1, 4]` 得 6，与推演一致。

## 泛化到 K 次

### K 次交易的规律

* **通用式子**

    * 第 $k$ 次买：依赖昨天第 $(k-1)$ 次卖的利润，减去当日价格。

    * 第 $k$ 次卖：依赖昨天第 $k$ 次买的利润，加上当日价格。

    * 边界：第 2 次到第 $K$ 次都套这一条式子，公式一个字都不用改，只有第一次特殊——它没有"前一次"可以依赖，只能以当日价格买入。

    * 两次就是 $K = 2$ 的特例；三次就多一组 `buy3`、`sell3`，四次再多加一组变量，类推即可。

* **用数组承载 K 组状态**

    * K 是变量，不能再靠一堆变量硬写，改用两个长度等于 $K$ 的数组 `buy`、`sell`。

    * `buy` 的每个元素都填 `Integer.MIN_VALUE`；`sell` 不用初始化，数组默认值就是 0，正好。

    * 内层循环的下标从 1 开始、循环条件为 `i < k`，因为下标 0 代表已单独算过的第一次买卖。

    ```java
    public int maxProfit(int k, int[] prices) {
        int[] buy = new int[k];
        int[] sell = new int[k];
        Arrays.fill(buy, Integer.MIN_VALUE);

        for (int price : prices) {
            // 第一次买卖单独处理：买不依赖任何历史状态
            buy[0] = Math.max(buy[0], -price);
            sell[0] = Math.max(sell[0], buy[0] + price);

            // 第 2 次到第 K 次，形态完全一致，放进循环
            for (int i = 1; i < k; i++) {
                buy[i] = Math.max(buy[i], sell[i - 1] - price);
                sell[i] = Math.max(sell[i], buy[i] + price);
            }
        }

        return sell[k - 1];
    }
    ```

    * 最终返回 `sell[k - 1]`。

### K 过大时的退化处理

* **上界判定**

    * 题目明确给出 K 的取值范围是 1 到 100；就六天价格这个用例来说，最多只能做三次交易，把 K 直接给成 100 没有任何意义。

    * > **提示**：K 的上限给得非常高时，它就相当于没有上限；以六天这个用例为例，只要 K 大于天数除以二（大于 3），就等于没有上限了。

* **改走贪心分支**

    * K 大于天数除以二时，说明再设置这个上限已经没有意义，直接走买卖任意多次、无次数上限那版的逻辑；那道题是贪心，效率比开一堆数组的动态规划高不少。

    * 只有 K 小于等于天数除以二的时候，才走上面的动态规划。

    ```java
    public int maxProfit(int k, int[] prices) {
        // K 已经超过天数除以二，这个上限形同虚设，走无上限（贪心）的逻辑
        if (k > prices.length / 2) {
            return maxProfitUnlimited(prices);   // 买卖任意次
        }

        int[] buy = new int[k];
        int[] sell = new int[k];
        Arrays.fill(buy, Integer.MIN_VALUE);

        for (int price : prices) {
            buy[0] = Math.max(buy[0], -price);
            sell[0] = Math.max(sell[0], buy[0] + price);

            for (int i = 1; i < k; i++) {
                buy[i] = Math.max(buy[i], sell[i - 1] - price);
                sell[i] = Math.max(sell[i], buy[i] + price);
            }
        }

        return sell[k - 1];
    }
    ```

    * 加上这层判断后同一个用例结果一致，提交耗时 1 毫秒；不加这层优化只能到 2 毫秒。
