# 基础算法-177-哈希表-hash码映射索引

## 哈希表的结构与手写顺序

* **自下而上的实现顺序**

    * > **定义**：哈希表不是一个黑箱，它是由数组加多个链表组成的，链表又是由一个个节点对象串起来的。

    * 先把节点类写出来，再把数组挂上去，最后才有增删改查可写。

    * 这个顺序反过来，后面每写一行都要挠头。

* **两个成员属性**

    * > **定义**：哈希表由两个属性撑起来——`Entry[] table` 存每条链表的头节点，`size` 记录元素个数。

    * `Entry[] table` 里存的只是每条链表的头节点，初始长度取 2 的 4 次方，即 16。

    * 只存一个头节点就够，因为通过头节点的 `next` 指针就能访问到链表的其他部分，所以数组元素类型就是 `Entry`。

    * `size` 是哈希表中元素的个数，供后续维护与判断阈值时使用。

* **数组与链表的读图方式**

    * 数组下标就是索引，每个格子里要么是 `null`，要么是一条单链表的头节点。

    * 顺着头节点的 `next` 指针就能走到这条链上的其余节点。

    ```text
            table（数组里存的只是每条链表的头节点）
       ┌──────┬──────────┬──────────┬──────┬─ ─ ─┬──────┐
       │  0   │    1     │    2     │  3   │ ... │  15  │  ← 索引
       ├──────┼──────────┼──────────┼──────┼─ ─ ─┼──────┤
       │ null │ Entry ──→ next       │ null │     │ null │
       │      │ value = 李四        │      │     │      │
       │      │      ↓              │      │     │      │
       │      │ Entry ──→ next      │      │     │      │
       │      │ value = 张四        │      │     │      │
       │      │      ↓              │      │     │      │
       │      │     null            │      │     │      │
       └──────┴──────────┴──────────┴──────┴─ ─ ─┴──────┘
    ```

## 节点类 Entry

* **节点类的命名与属性**

    * > **定义**：节点类是哈希表里的这个节点类，习惯上就叫 `Entry`。

    * 键和值都可以是任意类型，所以都用 `Object` 表示，键叫 `k`，值叫 `value`。

    * 它既然是链表上的节点，就至少要有一个 `next` 指针指向下一个元素，`next` 的类型也是 `Entry`。

    | 属性 | 类型 | 含义 |
    | :--- | :--- | :--- |
    | `hash` | `int` | 哈希码，也就是节点编号 |
    | `k` | `Object` | 键，任意类型 |
    | `value` | `Object` | 值，任意类型 |
    | `next` | `Entry` | 指向下一个节点 |

* **构造方法**

    * 构造方法只接收前三项，也就是哈希码、键、值。

    * `next` 不作为构造参数，刚创建时先保持为 `null`。

    ```java
    class Entry {
        int hash;        // 哈希码，也就是节点编号
        Object k;        // 键，任意类型
        Object value;    // 值，任意类型
        Entry next;      // 指向下一个节点

        Entry(int hash, Object k, Object value) {
            this.hash = hash;
            this.k = k;
            this.value = value;
            this.next = null;   // 刚创建时，先保持为 null
        }
    }
    ```

## 三个方法的签名

* **增删改查的方法约定**

    * > **定义**：三个方法都把哈希码作为第一个参数，用它直接定位数据所在的数组索引。

    | 方法 | 接受的参数 | 干什么 |
    | :--- | :--- | :--- |
    | `get` | 哈希码、键 `k` | 根据这两个信息去获取数据部分的 `value` |
    | `put` | 哈希码、键 `k`、值 `value` | 键没出现过就做新增，键已经存在就做修改 |
    | `remove` | 哈希码、键 `k` | 找到并删掉，返回被删掉的那个 `value` |

* **与 JDK 自带哈希表的签名差异**

    * JDK 中带的哈希表在方法参数上略有差异，它没有把哈希码作为参数，里面只有键和值。

    * 这不是乱加的：哈希码其实是跟键 `k` 有关系的，只是哈希码与 `k` 之间的联系长文未说明。

## 索引的计算

### 求模定位

* **哈希码的职责**

    * 哈希码的作用就是定位这个键值，它是存在数组中的哪个索引位置。

    * 哈希码是零，数据就存在索引零；哈希码是一，数据就存在索引一，以此类推。

* **越界问题的处理**

    * 哈希码可能大于数组的最大索引，例如数组长度为 8 时哈希码为 8 就没有对应索引了。

    * 最简单的思路是让它从头再来：哈希码 8 存到索引 0，哈希码 9 存到索引 1，哈希码 10 存到索引 2。

    * 这个规律可以用一个求模运算表达：把哈希码当被除数，把数组长度当除数。

    ```text
    索引 = 哈希码 % 数组长度
    ```

    | 哈希码 | 求模算式 | 余数 | 落到索引 |
    | :--- | :--- | :--- | :--- |
    | 8 | 8 ÷ 8 | 0 | 0 |
    | 9 | 9 ÷ 8 | 1 | 1 |
    | 10 | 10 ÷ 8 | 2 | 2 |
    | 100 | 100 ÷ 8 | 4 | 4 |

### 位运算替换

* **替换的前提与式子**

    * 求模本质上是个除法，而除法的性能并不好，所以要把它替换成性能更好的位运算。

    * > **注意**：能做这个替换的前提是数组长度必须是 2 的 n 次方，这也是初始数组长度取 2 的 4 次方的原因。

    * > **易错点**：⚠️ 如果数组长度不是 2 的 n 次方，这个等价替换不成立。

    ```text
    索引 = 哈希码 % 数组长度   等价于   索引 = 哈希码 & (数组长度 - 1)
    ```

* **等价对照**

    * 在数组长度为 8 时，`数组长度 - 1` 等于 7，`&` 与 `%` 的结果完全一致。

    | 哈希码 | 求模 | 按位与（长度 - 1 = 7） | 索引 |
    | :--- | :--- | :--- | :--- |
    | 8 | 8 % 8 = 0 | 8 & 7 = 0 | 0 |
    | 9 | 9 % 8 = 1 | 9 & 7 = 1 | 1 |
    | 100 | 100 % 8 = 4 | 100 & 7 = 4 | 4 |

    * 定位索引这一步只有一条式子：`index = hashCode & (table.length - 1)`，`get`、`put`、`remove` 以及后面的扩容全都靠它。

## get 的实现

* **查询的四个步骤**

    * 第一步由哈希码确定索引位置；第二步判断这个索引处有没有存储数据。

    * `table[index]` 为 `null` 说明这里没有存储，没有必要继续查找，直接 `return null`。

    * 不为 `null` 时它存的就是链表的头节点，定一个指针 `Entry p`，初始位置就是 `table[index]`，然后从头节点开始遍历整条链表。

    * 每次循环取出当前节点的 `k` 与要查找的 `k` 比较，相等就返回当前节点数据中的 `value`。

    * 第四步是 `p` 已经等于 `null`、整个链表都遍历完了还没有找到，此时也返回 `null`。

    ```java
    public Object get(int hashCode, Object k) {
        // 第一步：由哈希码确定索引位置
        int index = hashCode & (table.length - 1);

        // 第二步：判断这个索引处有没有存储数据
        if (table[index] == null) {
            // 没有存储，就没有必要继续查找了
            return null;
        }

        // 第三步：不为 null，说明这里存的是链表的头节点，沿着头节点遍历整条链表
        Entry p = table[index];
        while (p != null) {
            // 取出当前节点的 k，跟我们要查找的 k 做比较
            if (p.k.equals(k)) {
                return p.value;   // 找到了，直接返回 value
            }
            p = p.next;
        }

        // 第四步：p 已经等于 null 了，整个链表都遍历完了，还没有找到
        return null;
    }
    ```

* **键的比较方式**

    * 键都是 `Object` 对象，比较时要用 `equals` 才是在比内容。

    * > **易错点**：⚠️ 用 `==` 比的是两个引用指向的地址，不是内容。

## put 的实现

### 三种走向

* **情况一：索引处有空位**

    * 索引位置没有存储节点，相当于这个位置是空的，做新增操作，把新的键值造成一个节点对象插入进去。

    * 创建出新的 `Entry` 节点对象，把哈希码、键、值都传给它，然后直接赋给 `table[index]`。

* **情况二：沿链找到重复的键**

    * 索引位置已经被别的节点占了，沿着这条链表查找有没有重复的 `k`。

    * 发现 `k` 相等说明要做更新操作，直接更新它的 `value` 值然后返回。

* **情况三：走到链尾仍无重复的键**

    * 沿着链表找了一遍、找到链表尾部了仍然没有找到重复的 `k`，说明是新增操作。

    * 这时创建一个新的节点对象，把它加入到链表尾部；此时 `p` 代表最后一个节点，新节点的前一个节点就是它。

    ```java
    public Object put(int hashCode, Object k, Object value) {
        int index = hashCode & (table.length - 1);

        if (table[index] == null) {
            // 情况一：index 处有空位，直接新增
            table[index] = new Entry(hashCode, k, value);
        } else {
            // 情况二 / 情况三：index 处没有空位，沿着链表查找
            Entry p = table[index];
            while (true) {
                if (p.k.equals(k)) {
                    // 情况二：找到重复的 k，做更新操作
                    p.value = value;
                    return p.value;
                }
                if (p.next == null) {
                    // 已经找到最后一个节点了，而它前面都判断过、没有重复的 k，退出循环
                    break;
                }
                p = p.next;
            }

            // 情况三：遍历到尾部仍没有重复的 k，把新节点加到链表尾部
            // 此时 p 代表最后一个节点，新节点的前一个节点就是它
            p.next = new Entry(hashCode, k, value);
        }

        size++;   // 走到这里说明确实新增了一个元素
        return value;
    }
    ```

    * 遍历写成 `while (true)`，每轮让链表向后走一格；退出条件是当前节点的 `next` 等于 `null`，此时前面该判断的都已判断过、没有重复的 `k`，于是 `break`，`p` 就代表最后一个节点。

### 计数与分支收口

* **size++ 放在语句块外**

    * 有空位新增时 `size` 要加一；没有找到重复的 `k` 也是新增了，这时候 `size` 也要加一。

    * 走更新分支不会影响元素个数，所以这时候不用再加。

    * 两条路径都要加，因此可以把 `if` 语句块里和 `else` 语句块里的两个 `size++` 提取到 `if-else` 语句块外，减少一行重复代码。

    * > **易错点**：⚠️ 这个提升只在两条路径都是真新增时成立；以后如果给 `put` 加了别的分支（比如删除、或更新时顺带改了别的），`size++` 提到外面就会算错。

* **测试用例的索引落点**

    * 空表插入三条记录，哈希值分别是 1、17、2，对应张三、李四、王五。

    * 数组长度为 16 时，`1 % 16 = 1`、`17 % 16 = 1`，所以张三和李四都落在索引一，会串成一条链表，李四挂在张三的后面。

    * 哈希值为 2 的王五落在索引二，该索引处存的就是链表头。

    ```java
    @Test
    void testPut() {
        HashTable table = new HashTable();

        table.put(1,  "张三", "张三");   // 1  % 16 = 1
        table.put(17, "李四", "李四");   // 17 % 16 = 1
        table.put(2,  "王五", "王五");   // 2  % 16 = 2

        Assert.assertEquals(3, table.size);
        Assert.assertEquals("张三", table.table[1].value);          // 索引一是链表头
        Assert.assertEquals("李四", table.table[1].next.value);     // 链表头的 next 是李四
        Assert.assertEquals("王五", table.table[2].value);
    }
    ```

    * 更新测试给出同样的哈希值和 `k`，只把值换成张四和李五，链表结构与 `size` 都不变，只有对应节点的 `value` 被改写。

    ```java
    @Test
    void testUpdate() {
        HashTable table = new HashTable();

        table.put(1,  "张三", "张三");
        table.put(17, "李四", "李四");
        table.put(2,  "王五", "王五");

        // 同样的哈希值和 key，更新值
        table.put(1,  "张三", "张四");
        table.put(17, "李四", "李五");

        Assert.assertEquals("张四", table.table[1].value);          // 链表头的 value 更新了
        Assert.assertEquals("李五", table.table[1].next.value);     // next 节点的 value 也更新了
    }
    ```

## remove 的实现

* **删除就是单向链表删除**

    * 删除的第一步同样是由哈希码确定要删除数据的索引，这行代码直接复用前面的写法。

    * 索引处没有数据就直接返回 `null`；有数据就沿着链表去找有没有要删除的 `k`。

    * 删除需要知道被删除节点的上一个节点是谁，把前驱的 `next` 跨过被删节点、直接接到被删节点的后继上，被删节点就断开了。

    ```text
    删除中间的"鱼"：

       删前：   [沙] ──→ [鱼] ──→ [猪]
                         ↑
                       要删的

       操作：   previous.next = p.next

       删后：   [沙] ──────────→ [猪]
    ```

* **previous 指针的维护**

    * 再定一个指针变量 `previous` 代表上一个节点，它的初始值是 `null`，因为链表头的上一个节点是不存在的。

    * 每次循环在循环结束前把 `previous` 更新成当前节点，这样它始终记录着 `p` 的上一个节点。

    * 找到目标时执行 `previous.next = p.next`，就把 `p` 从链表中跳过去了。

* **链表头要特殊处理**

    * 如果删的是链表头，`previous` 是 `null`，此时不能直接 `null.next`，否则会报空指针。

    * 所以 `previous.next = p.next` 这行要放进 `else` 分支，只在 `previous` 不等于 `null` 时使用。

    * 当 `previous` 等于 `null` 时，让被删节点的 `next` 存储到索引位置，作为新的链表头。

* **删除后的收尾**

    * 找到了并且删除完了之后要更新 `size`，让元素个数减一，然后返回被删除节点的 `value`。

    * 循环走完没有找到则返回 `null`。

    ```java
    public Object remove(int hashCode, Object k) {
        int index = hashCode & (table.length - 1);

        if (table[index] == null) {
            return null;        // 索引处没数据，没啥可删的
        }

        Entry previous = null;  // 始终记录 p 的上一个节点
        Entry p = table[index]; // 把索引处当成链表头

        while (p != null) {
            if (p.k.equals(k)) {
                // 找到了，做删除
                if (previous == null) {
                    // 特殊处理：删的是链表头，previous 是 null，不能 previous.next = ...
                    table[index] = p.next;
                } else {
                    // previous.next 指向 p.next，把 p 从链表中跳过去
                    previous.next = p.next;
                }
                size--;
                return p.value;   // 返回被删除节点的 value
            }
            previous = p;         // 循环结束前把 previous 更新成当前节点
            p = p.next;
        }

        return null;              // 循环结束了没有找到
    }
    ```

    * 两个删除用例正好分别覆盖 `if` 与 `else` 两条路径：删链表头的张三后索引一只剩李四；删非链表头的李四后索引一只剩张三，且张三的 `next` 为 `null`。

    ```java
    @Test
    void testRemoveHead() {
        HashTable table = new HashTable();
        table.put(1,  "张三", "张三");
        table.put(17, "李四", "李四");   // 两者都在索引一，串成链表

        table.remove(1, "张三");         // 删的是链表头

        Assert.assertEquals("李四", table.table[1].value);
    }

    @Test
    void testRemoveMiddle() {
        HashTable table = new HashTable();
        table.put(1,  "张三", "张三");
        table.put(17, "李四", "李四");

        table.remove(17, "李四");        // 删的不是链表头

        Assert.assertEquals("张三", table.table[1].value);
        Assert.assertNull(table.table[1].next);
    }
    ```

## 扩容的必要性

* **数组写死带来的缺点**

    * 之前实现的底层数组大小是固定死的，元素个数越来越多就会把哈希表放满。

    * 里面很多元素都串成了链表，链表的长度也可能变得非常长，增删改查的效率随之变低。

* **平衡的目标与手段**

    * 要在数组占用的空间跟数据的增删改查效率之间求一个平衡。

    * 办法是让数组的容量更大一些，这样数据变得分散，链表也不会这么长。

    * 扩容的时机是当数组容纳的元素个数达到一个阈值的时候，借此提升哈希表的增删改查效率。

---

## 负载因子与阈值

### 负载因子

* **定义与取值**

    * > **定义**：负载因子 $= \dfrac{n}{m}$，其中 $n$ 是哈希表中元素的个数，$m$ 是哈希表这个数组的长度。

    * 这个比值不宜过小，也不宜过大。

    * Java 的实现中这个取值是 0.75，也就是 3/4；元素个数与数组长度的比例达到 3/4 时扩容是较合适的时机，这是一个经验值。

* **过小与过大的后果**

    * 比值取 0.1、0.2 属于比较小的比值，元素个数只占数组长度的很小一部分，此时扩容会造成空间的浪费——元素还没多少，数组容量就变大了，没必要。

    * 比值等于一意味着元素个数已经等于数组中的格子数，也就是都放满了；放满的时候再扩容其实已经有点晚了，此时可能有些格子已经被串成了链表，增删改查的性能已经受到影响了。

### 不同取值的差别

* **数组长度为 8 时的触发情况**

    * 扩容时一般选择容量翻倍，翻倍之后仍然是 2 的 n 次方：扩容前是 2 的 3 次方即 8，翻倍后变成 2 的 4 次方即 16。

    | load factor | 什么时候扩容 | 放几个还没扩容 | 第几个触发扩容 | 扩容后容量 |
    | :--- | :--- | :--- | :--- | :--- |
    | 0.25 | 超过 1/4（8 的 1/4 是 2） | 2 | 3 | 16 |
    | 0.5 | 超过一半 | 4 | 5 | 16 |
    | 0.75 | 超过 3/4（= 6） | 6 | 7 | 16 |
    | 1 | 放满了我才扩容 | 8 | 9 | 16 |

    * 取 0.5 也有点浪费空间：才放了一半就扩容；取 0.75 表示超过容量的四分之三扩容，8 的 3/4 是 6，放入第 7 个元素时扩容。

### 阈值

* **阈值的定义与计算**

    * > **定义**：阈值（threshold）是负载因子乘以数组长度，例如 0.75 × 16 = 12。

    * 阈值是一个整数，乘法刚开始得到的是 `float`，要复制给 `int` 需要用括号括起来做一次强制类型转换。

    * 数组长度一旦固定、负载因子也已知，就可以立刻算出来反复重用，不需要每次重新计算。

* **触发的位置与代码**

    * 只要实际的元素个数 `size` 大于这个阈值，就触发扩容。

    * 这段判断要写在 `put` 逻辑里，因为只有 `put` 才会执行新增；等它的 `size` 加完之后再判断。

    ```java
        size++;
        if (size > threshold) {
            resize();     // 扩容单独写一个方法，就叫 resize
        }
    ```

## 扩容后索引重算

* **转移时必须重算索引**

    * 触发扩容后还要把旧数组中的数据转移到新数组中，转移时需要重新计算每个数据的索引值，因为索引有可能发生变化。

    * 并不是所有数据的索引都会发生变化。

* **哪些变、哪些不变**

    * 旧数组长度为 8 时，哈希值 0 到 7 的数据在扩容前是整数值除以 8 取余数，转移到新表格后是除以 16 取余数：0 ÷ 8 余 0 而 0 ÷ 16 也余 0，1 ÷ 8 余 1 而 1 ÷ 16 也余 1，所以这几个数据的索引位置不变。

    * 哈希值为 8 的数据扩容前是 8 ÷ 8 余 0、落在索引 0；扩容后是 8 ÷ 16 余 8、落到索引 8，所以它的索引位置发生了变化。

    * 其余索引没变的数据直接转移即可，完成旧表格到新表格的迁移。

* **迁移带来的收益**

    * 移动完之后链表的长度减少了，链表变短，性能得到了一定的提升。

## resize 的实现

### 骨架

* **负载因子的声明**

    * 负载因子是一个小数，所以用一个 `float` 变量 `loadFactor` 来代表，取值用推荐的 0.75，仿照 JDK 中哈希表实现的取值。

* **扩容的四个动作**

    * 第一步是创建一个容量翻倍的新数组，`table.length << 1`；也可以写成 `* 2`，乘以二相当于左移一位，左移一位的效率比乘法还好一些。

    * 第二步是对旧数组做循环，从索引 0 一直到旧数组长度减一，拿到旧数组中第 `i` 个元素，也就是那个链表头。

    * 链表头不为 `null` 时才做拆分并移动到新数组；像索引 1 到 7 这几个都是 `null` 时相当于没东西，没有任何拆分和移动的动作。

    * 第三步是循环结束后用新数组替换掉旧的数组，把成员变量 `table` 赋值为 `newTable`。

    * 第四步是重新计算阈值，因为扩容后容量变成 16，16 × 0.75 也就是 12。

    ```java
    public void resize() {
        Entry[] newTable = new Entry[table.length << 1];  // 容量翻倍
        //                       ↑ 也可以写成 * 2，乘以二相当于左移一位，左移一位效率比乘法还好一些

        for (int i = 0; i < table.length; i++) {
            Entry p = table[i];        // 拿到旧数组中第 i 个元素，也就是那个链表头
            if (p != null) {
                // 拆分链表，并且移动到 newTable
            }
            // p == null 就相当于没东西，没有什么拆分以及移动的动作
        }

        table = newTable;                                 // 用新数组代替掉原来的旧数组
        threshold = (int) (loadFactor * table.length);    // 16 × 0.75 = 12，阈值重新计算
    }
    ```

### 拆分的两条规律

* **规律一与规律二**

    * 规律一：旧数组中一条链表最多拆分成新数组中的两条链表，不会拆成三条、四条。

    * 规律二：旧数组中每个元素的哈希值跟旧数组的长度做按位与，结果等于 0 的元素串成一个链表为一组，结果不等于 0 的串成另一个链表为另一组。

    * 规律成立的原因长文未说明，只给出结论并留待后文讨论。

* **规律二的一组演算**

    * 哈希值 0、8、16、24、32、40、48 都是 8 的倍数，所以在旧数组中都落在索引零。

    | 哈希值 | `hash & 8` | 归到哪一组 |
    | :--- | :--- | :--- |
    | 0 | 0 | a 组 |
    | 8 | 8 | b 组 |
    | 16 | 0 | a 组 |
    | 24 | 8 | b 组 |
    | 32 | 0 | a 组 |
    | 40 | 8 | b 组 |
    | 48 | 0 | a 组 |

    * 扩容完之后取值为 0 的是 0、16、32、48，串成一条链表；取值不为 0 的是 8、24、40，串成另一条链表。

    * 例子中元素一共有 7 个而阈值是 6，已经超过阈值要扩容，扩容后这一条链表被拆成两条，一条 4 个、一条 3 个。

### 一趟遍历完成拆分

* **三个指针的分工**

    * `p` 指向原来旧链表中的元素；`a` 和 `b` 是两个新指针，代表拆分后新链表各自的尾指针，初始值都是 `null`。

    * 分配到某组时就是让该组指针指向当前元素：若指针为 `null` 就直接赋值（`a = p` 或 `b = p`），否则让该组指针当前指向的元素的 `next` 指向 `p`。

    * 分配完就把组指针向后移动一次，它始终保持尾节点的位置；旧链表指针 `p` 同样向后移动。

* **一趟遍历的逐元素走向**

    * 哈希值 0 与 8 按位与 8 的结果是 0，分到 `a` 组；哈希值 8 的结果不是 0，分到 `b` 组。

    * 哈希值 16 的结果是 0，让 `a` 当前指向的元素（0）的 `next` 指向 16；哈希值 24 的结果不是 0，让 `b` 当前指向的（8）的 `next` 指向 24。

    * 接着哈希值 32 的结果是 0，让 16 的 `next` 指向 32；哈希值 40 的结果不是 0，让 24 的 `next` 指向 40；哈希值 48 的结果是 0，让 32 的 `next` 指向 48。

    * 当旧链表指针 `p` 循环到 `null`、已经没有更多元素要处理时，拆分结束。

    ```java
    Entry a = null;                 // 拆分后 a 组链表的尾指针
    Entry b = null;                 // 拆分后 b 组链表的尾指针
    Entry p = table[i];             // 旧链表头

    while (p != null) {
        if ((p.hash & table.length) == 0) {
            // 分到链表 a
            if (a == null) {
                a = p;              // a 组的第一个元素，直接赋值
            } else {
                a.next = p;         // 接到 a 组链表的尾部
            }
            a = a.next;             // a 始终保持尾节点的位置
        } else {
            // 不等于零，分到链表 b
            if (b == null) {
                b = p;              // b 组的第一个元素，也是直接赋值
            } else {
                b.next = p;
            }
            b = b.next;
        }
        p = p.next;                 // 旧链表指针向后移动
    }
    ```

    * > **易错点**：⚠️ `p.hash & table.length` 里的 `table.length` 是旧数组的长度，不是新数组的长度，也不是旧长度减一；这里写 `table.length - 1` 会把两组全部判成 0，一条链表都拆不开。

    * 拆分完成后 `a`、`b` 两条链表分别写回 `newTable` 的哪两个索引，长文未说明。
