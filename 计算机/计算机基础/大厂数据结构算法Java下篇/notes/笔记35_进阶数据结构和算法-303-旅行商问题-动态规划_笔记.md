# 进阶数据结构和算法-303-旅行商问题-动态规划

## 旅行商问题与邻接矩阵

### 问题模型与编号约定

* **旅行商问题（Traveling Salesman Problem，TSP）**

    * > **定义**：从某一个城市出发，把所有城市都走一遍，最后再回到出发城市，求总开销最小的路线。

    * 问题用一张地图给出：城市是顶点，两个城市之间的开销标在边上。

    * 本例共四个城市，编号约定为：0 = 北京，1 = 上海，2 = 西安，3 = 武汉。

* **邻接矩阵表示法**

    * 用邻接矩阵表示这张图，说白了它就是一个二维数组。

    * 行是城市编号，列也是城市编号。

    * 表格读法：横轴是 0、纵轴也是 0，则 `G[0][0]` 是北京到北京自己的开销，为 0；横轴是 0、纵轴是 1，则北京到上海的成本是 1；西安是 2、武汉是 3，所以 `G[2][3]` 就是 5。

    ```text
                     列 = 目的城市
                     北京0  上海1  西安2  武汉3
      行（北京0）       0      1      ·      ·
      行（上海1）       1      0      ·      ·
    出 行（西安2）       ·      ·      0      5
    发 行（武汉3）       ·      ·      ·      0
    城
    市
    ```

    * 对角线是自己到自己，距离为 0；非对角线是城市之间的开销。

    * `.` 表示这些格子没有一个个念出来，即未在讲解中逐一展开的项。

### 邻接矩阵元素 G[i][j] 的含义

* `G[i][j]` 存的是"从 i 到 j"的代价。

* > **提示**：这一条在后面全部推导里会一直沿用，别一会儿当成距离、一会儿当成成本，搞混了。

### 无向图与有向图

* 本例选取的是**无向图**：北京到上海和上海回北京花费一样，矩阵从对角线往两边对称。

* 代价也可以不对称，比如北京到上海是 1、上海回北京是 2，这就是**有向图**，矩阵随之不对称。

* 无向还是有向是对这张图数据的一个抽象选择，不是问题本身的限制。

## 状态设计：D(i, G)

### 状态定义与设计动机

* **状态 D(i, G)**

    * > **定义**：`D(i, G)` = 从出发城市 `i` 出发，走完集合 `G` 中剩余的所有城市（走完后再回到最初的起点），所能花费的最少代价。

    * 递推公式记作 `D`，接收两个参数：一个是出发城市，另一个是剩余城市的集合。

    * 例如最开始出发城市是北京（0），剩余城市集合就是剩下的上海、武汉和西安。

* 这么设计的原因：这个问题可以拆分成一些子问题，而且这些子问题里可能有**重复的求解过程**，所以才用动态规划的二维表格来缓存重复计算的结果。

### 手算推导的三轮拆分

* **第一轮：按"下一个先到哪个城市"一步拆三支**

    * 出发城市为北京（0），剩余城市为 1、2、3（上海、西安、武汉）。

    * 北京先到上海：`G[0][1] + D(1, {2,3})`，上海是 1，剩余武汉和西安即 `{2,3}`。

    * 北京先到武汉：`G[0][3] + D(3, {1,2})`，武汉是 3，剩余上海和西安。

    * 北京先到西安：`G[0][2] + D(2, {1,3})`，西安是 2，剩余上海和武汉即 1 和 3。

    $$D(0, \{1,2,3\}) = \min\Big\{ G[0][1] + D(1, \{2,3\}),\;\; G[0][3] + D(3, \{1,2\}),\;\; G[0][2] + D(2, \{1,3\}) \Big\}$$

* **第二轮：再拆上海那一支**

    * `D(1, {2,3})` 对应从上海出发，一种先到武汉，一种先到西安，剩余城市就是西安和武汉。

    $$D(1, \{2,3\}) = \min\Big\{ G[1][3] + D(3, \{2\}),\;\; G[1][2] + D(2, \{3\}) \Big\}$$

    * 先算上海到武汉的距离（横 1 到竖 3 查表）；到了武汉以后武汉怎么到西安，这又是一个子问题 `D(3, {2})`，所以整条支路是"上海到武汉的距离 + 从武汉到西安的子问题"；另一支是先到西安，即"上海到西安的距离 + `D(2, {3})`"。

* **第三轮：拆到只剩回起点那一步**

    * `D(3, {2})` 从武汉出发到西安，拆成武汉到西安的距离 `G[3][2]` 加一个子问题：武汉到西安以后，西安还得回到北京。

    * 这时没有别的选择，只剩北京一个城市，第二个参数其实是一个**空的集合**，它等价于西安（2）回到北京（0）那个距离。

    $$D(3, \{2\}) = G[3][2] + D(2, \varnothing) = G[3][2] + G[2][0]$$

    * 把这两个距离加在一起，就是武汉到西安、再加上西安回北京的总距离。

### 通式的参数对应

* 每一次拆分都拆成两部分：**一部分是一个距离，另一部分是一个更小的子问题**，所以式子等价于"一个距离 + 一个子问题"，子问题仍用 `D` 表示。

* 变量命名：出发城市记作 `i`，剩余城市集合记作 `G`，子问题的出发城市是 `G` 遍历出来的某一个城市，记作 `k`。

$$D(i, G) = \min_{k \in G} \Big( G[i][k] + D(k, G \setminus \{k\}) \Big)$$

* 距离那块是 `G[i][k]`：`i` 是出发城市（0 对应北京），`k` 是遍历集合 `G` 时产生的那一个城市（1、2、3 对应上海、西安、武汉）。

* 子问题的出发城市就是刚才的 `k`，子问题里的 1、2、3 跟上一步遍历出来的 `k` 一一对应。

* 子问题的剩余集合是原集合 `G` 去掉 `k`：`{1,2,3}` 刨去 1 剩 `{2,3}`，刨去 2 剩 `{1,3}`，刨去 3 剩 `{1,2}`。

* > **注意**：`k` 是遍历剩余城市集合产生的一个值，可能有多个，这多个里要求的是**最小值**，因为最终找的就是耗费最小的路线。

### 边界条件：剩余集合为空

* 子问题第二个参数（剩余城市集合）已为空，表示没有其他城市了，这时要回到起点。

* 从当前第一个参数（记作 `k`）回到起点，等价于去查那张表——`k` 这个城市到起点，起点是最开始的 `i`。

$$D(k, \varnothing) = G[k][s]$$

* 其中 $s$ 是最初的起点编号，本例中是 0，也就是北京。

* > ⚠️ **易错点**：这个特殊的空集合情况一定要处理，它相当于就是一个边界条件；当第二个参数为空时，用后面这个式子求解即可。

## 集合的二进制编码

### 二进制位与集合的对应

* 以前递推式只有 `i`、`j` 两个下标，画一个 i 行 j 列的表格就够了；现在列 `G` 是一个集合，画 i 行 j 列的表格还不行。

* 解法是用一个**二进制的数**来代表"集合中是否有这个城市"。

* 取二进制三位，约定：三位都是 0 代表集合中没有城市；最低位取 1 代表集合中有一号城市；第二位取 1、其他位为 0 代表有 2 号城市；第三位取 1、剩下两位为 0 代表集合中只有 3 号城市。

* 城市组合由此很容易实现：有一号和二号就把两位写成 1、第三位写 0；有一号和三号就是第一位和第三位都是 1、中间是 0；二号和三号是 `110`；三个城市都想要就是三位都是 1。

### 编码对照表

* 用二进制就可以用八个二进制数代表八种情况，换算成十进制对号入座：

| 二进制 | 十进制（列下标） | 代表的集合 G |
| :---: | :---: | :--- |
| 000 | 0 | 空集 |
| 001 | 1 | 只有 1（上海） |
| 010 | 2 | 只有 2（西安） |
| 011 | 3 | 1 和 2（上海、西安） |
| 100 | 4 | 只有 3（武汉） |
| 101 | 5 | 1 和 3（上海、武汉） |
| 110 | 6 | 2 和 3（西安、武汉） |
| 111 | 7 | 1、2、3（上海、西安、武汉） |

* 于是用 0 到 7 这样的 `G` 取值代表不同城市组合：0 没有城市，1 只有 1 号，2 只有 2 号，3 有一和二，4 只有 3 号，5 有一和三，6 有二和三，7 三个都有。

### 列数 N 的计算

* `{1,2,3}` 的子集一共八种：空、一、二、一二、三、一三、二三、一二三。

* 这八种就是拿来组合的**城市数目减一**——三个城市，三的三次方，$2^3 = 8$；将来有四个城市，组合数就是二的四次方，是 16。

* 用变量 `N` 代表剩余城市的组合数，也就是列的数目，$M$ 是城市数目：

$$N = 2^{\,M-1}$$

* 城市数目 $M$ 跟邻接矩阵的行数保持一致，取值就来自于邻接矩阵的长度。本例 $M = 4$，所以 $4 - 1 = 3$，二的 3 次方结果是 8。

* 求二的多少次方用移位最简单：把 1 向左移 `M - 1` 位。

```java
int n = 1 << (m - 1);
```

* 有了 `N` 就把它作为列的数目，二维表格被初始化好。

## 二维表格的布局与填表顺序

### 行列含义

* 行是 `i` 的取值，就是城市编号，将来行跟城市保持一致，取 0、1、2、3。

* 列是集合 `G`，取值不止 0、1、2、3：可能为空，可能剩余一个城市（1、2、3），可能剩余两个城市（2、3／1、3／1、2），最后可能剩余三个城市（1、2、3）。

* 所以这个二维表格跟此前的动态规划表格不太一样，列下标必须用集合的编码。

### 推导方向与填表方向

* 推导时都是从右向左进行的，例如求 `D(0, {1,2,3})`（第七列）的值，要用到一些更右侧子问题的结果。

    ```text
    dp[0][7] = D(北京, {上海,西安,武汉})
       |-- 需要 --> dp[1][6] = D(上海, {西安,武汉})
       |                  |-- 需要 --> dp[3][2] = D(武汉, {西安})
       |                  \-- 需要 --> dp[2][4] = D(西安, {武汉})
       |-- 需要 --> dp[2][5] = D(西安, {上海,武汉})
       \-- 需要 --> dp[3][3] = D(武汉, {上海,西安})
    ```

* 读图：`dp[0][7]` 需要 `dp[1][6]`、`dp[2][5]`、`dp[3][3]` 这三个格子各加一段距离、再取最小值；而这三个蓝色格子自己又要依赖更左侧的格子。

* 推导是从右向左，但填表不能从右向左，因为计算右侧单元格要用到更早的、也就是左侧单元格的结果。

* > **结论**：填表应该**从左向右**来填，一列一列地填。

### 第 0 列的初始化

* 第 0 列表示剩余集合为空，填充比较简单：`D(2, 空)`、`D(3, 空)` 就是 `G[2][0]`、`G[3][0]`，直接查邻接矩阵即可。

* 写一个循环变量 `k` 从 0 到 `M`，遍历每一行，填充 `DP` 中 `k` 行的第 0 列，取值来自邻接矩阵 `G` 中 `k` 行第 0 列的值。

```java
// 这是填充第 0 列
for (int k = 0; k < m; k++) {
    dp[k][0] = graph[k][0];
}
```

* 填完之后打印表格，第 0 列被填充成 0、1、2、3；这是准备工作，有了第 0 列才能算出后续单元格的值。

## 三层循环实现

### 循环骨架与初始值

* 外层循环变量叫 `J`，对应列；第 0 列已填充过，从第 1 列开始一直到 `J < N`。

* 内层循环处理每一行，变量 `i` 对应每一行，从 0 开始直到 `i < M`。

* 每处理一个单元格都要先给一个初始值；因为要求最小值，初始值给大一些，将来遇到比它小的就替换成更小的值。

```java
dp[i][j] = Integer.MAX_VALUE / 2;
```

* > ⚠️ **易错点**：不能直接用 `Integer.MAX_VALUE`，这个值将来还要做加法运算，选择它很可能导致加法超出最大范围；所以在 `Integer.MAX_VALUE` 基础上除以二，这个值也足够大。

### 第一个 continue：跳过不合法单元格

* 第一列中并不是所有单元格都需要处理，要**从业务意义去解读**：出发城市是 0、剩余集合中还有个 1 是合理的；但出发城市是 1 号城市、剩余城市集合也是 1 号城市不可能，所以这条线不应该走。

* 判断办法：检查剩余集合 `G` 中是否包含了出发城市，包含了就是不合法、不应该被填充。

* 调用 `contains` 方法，它接受两个参数，第一个参数代表集合（即当前列下标 `j`），检查集合中是不是包含了出发城市 `i`；包含就 `continue` 进入下一轮循环，不包含才做进一步填充。

```java
for (int j = 1; j < n; j++) {
    for (int i = 0; i < m; i++) {
        dp[i][j] = Integer.MAX_VALUE / 2;
        // 剩余集合里已经包含出发城市了，这行不合法
        if (contains(j, i)) {
            continue;
        }
        // ……最内层循环……
    }
}
```

### 第二个 continue：只遍历集合内城市

* 以第 0 行第 3 列（`G = {1,2}`）为例，它对应 `D(0, {1,2})`，内部又分两种情况：从 0 出发先到 1、剩余城市是 2，以及从 0 出发先到 2、剩余城市是 1；两种情况各自求出距离后再求更小的值，所以需要一个内层循环。

* 这个循环的变量名叫 `K`，对应递推式里的 `k`，作用是在这多个情况里找到一个最小值。

* 对 `D(0, {1,2})` 真正要遍历的 `k` 只需 1 和 2，但实现里是从 0 到 `k < M` 遍历所有城市。

* 这样做的原因：要从二进制数字里找到 1、找到 2，遍历比较麻烦，所以用**排除法**——先遍历所有城市，再看 `k` 是否在集合中，是就套公式处理，不在就跳过。

```java
for (int k = 0; k < m; k++) {
    if (!contains(j, k)) {
        continue;
    }
    // ……套递推式……
}
```

* 走一遍：`k = 0` 时 0 不在 `{1,2}` 中，跳过；`k = 1` 在集合中，产生第一行；`k = 2` 在集合中，产生第二行；`k = 3` 不在集合中，跳过。

* > **注意**：前面这个跳过（集合里含了出发城市就跳过）和这里这个跳过（集合里不含 `k` 就跳过）是**两个不同位置的 `continue`**。

### 递推式落地与最终答案位置

* 递推式第一项是距离，即从城市 `i` 出发到达城市 `k` 的距离。

* 第二项是子问题的解，子问题解已经在 `DP` 表格里算好，只需要给正确的行列坐标：行坐标就是 `k`。

* 列坐标是集合 `G` 中去掉 `k` 后剩余集合所对应的坐标，由事先准备好的 `exclude` 方法求出。例如集合 `G` 为 `{1,2}`：`k` 为 1 时去掉 1 剩 2，`k` 为 2 时去掉 2 剩 1。

* 循环会算出多次结果，要找最小值，就用每次结果与 `dp[i][j]` 原值求更小的并更新；第一次循环时原值是很大的初始值，遇到更小的就更新，再遇到更小的再更新，遇到更大的不更新，循环结束单元格就填好了。

```java
for (int k = 0; k < m; k++) {
    if (!contains(j, k)) {
        continue;
    }
    dp[i][j] = Math.min(dp[i][j], graph[i][k] + dp[k][exclude(j, k)]);
}
```

* 三层循环合起来的完整方法如下。

```java
public int tsp(int[][] graph) {
    int m = graph.length;        // 城市数目，也就是邻接矩阵的长度
    int n = 1 << (m - 1);        // 剩余城市组合数，也就是列的数目
    int[][] dp = new int[m][n];

    // 填充第 0 列：剩余集合为空，直接回起点
    for (int k = 0; k < m; k++) {
        dp[k][0] = graph[k][0];
    }
    print(dp);

    for (int j = 1; j < n; j++) {
        for (int i = 0; i < m; i++) {
            dp[i][j] = Integer.MAX_VALUE / 2;
            if (contains(j, i)) {
                continue;        // 剩余集合里已经包含了出发城市，不合法
            }
            for (int k = 0; k < m; k++) {
                if (!contains(j, k)) {
                    continue;    // k 不在剩余集合里，跳过
                }
                dp[i][j] = Math.min(dp[i][j], graph[i][k] + dp[k][exclude(j, k)]);
            }
        }
    }
    print(dp);

    return dp[0][n - 1];
}
```

* 最终结果**不在右下角，而是在右上角**，即 `dp[0][n-1]`，这个位置的值 12 就是遍历了所有城市、耗费最少的那条路线，与开头分析时给出的最短耗费 12 一致。

## 位运算帮手 contains 与 exclude

* `contains` 与 `exclude` 是事先提供的两个方法，内部主要利用位运算来判断集合中是否包含某个城市、或从集合中排除某个城市。

* 位运算本身不展开，重点是这两个方法的工作方式。

### exclude 的异或构造

* > **定义**：`exclude(set, city)` 返回把 `set` 中 `city` 这一位置 0 之后的结果，实现为 `set ^ (1 << (city - 1))`。

```java
private int exclude(int set, int city) {
    return set ^ (1 << (city - 1));
}
```

* 算例一：在 `{1,2,3}`（十进制 7，二进制 `111`）中排除城市 1（十进制 1，二进制 `001`）。城市减一是 0，以 0 作为左移位数即左移 0 位，再与集合做**异或**。

    ```text
      111
    ^ 001
    ------
      110
    ```

    * 异或规则是相同的得 0、不同的得 1；前两位不同各得 1，最后一位都是 1 得 0，结果是 `110`。

    * 第二位代表集合中有 2 号城市、第三位代表有 3 号城市，`110` 正好保留 2 和 3。

* 算例二：仍以 `111` 为例排除城市 2。城市减一是 1，1 左移一位就是 `10`，所以待异或的是 `010`。

    ```text
      111
    ^ 010
    ------
      101
    ```

    * 最后一位不同得 1，第二位一样得 0，第三位不同得 1，得到 `101`，对应集合中只剩 1、3 两个城市，2 号城市被排除。

### contains 的按位与构造

* > **定义**：`contains(set, city)` 判断 `city` 是否在 `set` 中，实现为 `(set & (1 << (city - 1))) == (1 << (city - 1))`。

```java
private boolean contains(int set, int city) {
    int mask = 1 << (city - 1);
    return (set & mask) == mask;
}
```

* 以集合 2 和 3 为例，其对应数字是十进制 6，二进制 `110`。

* 检查城市 1：城市减一是 0，集合左移 0 位仍是 `110`，与 `001` 做**按位与**（两个都是 1 才得 1，有一个 0 就得 0）。

    ```text
      110
    & 001
    ------
      000
    ```

    * 结果为 0，与 1 不相等，意味着城市 1 在这个集合中不存在，返回 `false`。

* 检查城市 2：城市减一是 1，`110` 右移一位变成 `011`，再与 `001` 做按位与。

    ```text
      011
    & 001
    ------
      001
    ```

    * 结果为 1，与 1 相等，返回 `true`，表示城市 2 确实在集合里。

* 检查城市 3：城市减一是 2，`110` 右移两位变成 `001`，与 `001` 按位与仍是 `001`，结果也是 `true`。

* 检查城市 4：城市减一是 3，`110` 右移三位变成 `000`，再怎么按位与也是 0，与 1 不等，返回 `false`。

    ```text
    检查城市 2：  110 >> 1 = 011,  011 & 001 = 001 -> true
    检查城市 3：  110 >> 2 = 001,  001 & 001 = 001 -> true
    检查城市 4：  110 >> 3 = 000,  000 & 001 = 000 -> false
    ```

* 检查 `110` 里有没有城市 0 也可以，最终同样得到 `false`。

### 两个方法的分工

* > **结论**：这两个方法加起来，给了一套在"二进制编码的集合"上做**成员判断**和**剔除成员**的能力，正好是填表时 `continue` 判断和 `exclude` 求列坐标所需要的。

## 分治思想

### 拆、递归、合

* > **定义**：分治思想 = 把大问题划分成两个或多个子问题 → 子问题不够小就继续拆 → 拆到能直接求解为止 →（如果有必要）把子问题的解进行合并 → 得到原始问题的解。

* 核心是将大的问题划分成两个或者多个子问题；这些子问题如果还是太复杂，就对此问题继续拆分，拆成更小的子问题，直到子问题能够简单到直接求解。

### 经典分治实例

* **二分查找**

    * 在区间内找一个中间点，把待查找的值跟中间点的值比较；比中间点小就只在左侧区域查找。

    * 查找动作都是一样的，只是问题规模缩小了，属于"分而治之"，也可叫"简而治之"。

* **快速排序**

    * 找到一个基准点元素，把比基准点小的元素放在它左边，比基准点大的元素交换到它右边。

    * 再对左边区间做重复操作，再选一个基准点并按同样算法定位，逐渐缩小问题规模，最终整个区间内所有元素排好序。

* **归并排序**

    * 把整个区域内的元素不断拆分，拆分到区间内只剩一个元素，此时只需跟相邻区间的元素做合并排序。

    * 两两排序很简单，比如 3 和 9 排好序、2 和 7 合并排好序，再把 3、9 和 2、7 合并排好序；右边区间做类似处理，最后把左右两个区间再做一次有序数组的排序。

* **合并 K 个有序链表**

    * 把一个数组拆分，拆分到区间内只剩一个链表，只剩一个链表就可以跟其他链表两两合并。

    * 本质上就是归并排序。

### 分与合是否必须成对

* 有的问题需要把子问题的解进行合并，最终得到原始问题的解，比如归并排序。

* 快排和二分查找不需要对子问题的解做进一步处理，它们没有"合"的过程。

* > **注意**：这是分治内部不同算法之间的一处分野。

## 分治与动态规划的分野

### 相同点与不同点

* **相同点**：都需要把一个大的问题拆分成多个子问题。

* **不同点**：动态规划的子问题实际上有**重叠**情况，所以才需要为一维、二维表格来记录之前子问题的解，避免重复运算。

* 分治的子问题相互之间都是**独立**的，没有重叠。

### 表的存在与否

* 二分查找里在左侧子问题查找过了，右边子问题就不用管了；快速排序和归并排序也是类似，子问题都是独立的。

* > **结论**：动态规划的分，子问题之间会重叠，所以需要一张表来"记账"，把算过的答案存下来；分治的分，子问题彼此独立，算完就丢，不需要那张表。

* 旅行商问题正是前者的典型样本：`D(0,{1,2,3})` 拆下去之后，不同分支里会反复遇到同一个 `D(2,{3})` 这样的子问题，所以才建了那张 `dp` 表。
