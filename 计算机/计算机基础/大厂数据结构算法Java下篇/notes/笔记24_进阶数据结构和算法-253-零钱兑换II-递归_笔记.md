# 进阶数据结构和算法-253-零钱兑换II-递归-

## 零钱兑换II的题目设定

   * **题目输入**

       * > **定义**：给定整数数组 `coins` 表示不同面额的硬币，给定整数 `amount` 表示总金额，用 `coins` 里的面额凑足 `amount`。

       * 每种面额的硬币数量无限，取用顺序不受限制，凑足总金额即算合法组合。

   * **题目输出**

       * 返回值是凑法的总种数，既不是凑出总金额本身，也不是最少硬币数。

       * 没有任何组合能凑出总金额时，凑法数返回零。

   * **样例数据下的四种凑法**

       * 面额取 `1、2、5`，总金额取 `5`，恰好凑足的方式有四种。

| 凑法 | 组合 |
| :--- | :--- |
| 第一种 | 一个五分硬币 |
| 第二种 | 两个两分硬币 + 一个一分的硬币 |
| 第三种 | 一个两分的硬币 + 三个一分的硬币 |
| 第四种 | 五个一分的硬币 |

   * **无解与唯一解的边界**

       * 只给两分面额、总金额为三时，无论如何都凑不足，凑法数为零。

       * 只给一个十分硬币、总金额也是十时，只有一种走法。

## 零钱兑换与零钱兑换II的分岔点

   * **共用骨架**

       * 两道题共用同一副骨架：拿 `coins` 里的硬币去凑 `amount`，能凑就返回一条路径。

   * **分岔在最后一步**

       * 零钱兑换II（518）数路径条数，统计凑法共有多少种。

       * 零钱兑换（322）在所有路径里挑硬币数最少的那一条。

   * **同一组数据下的不同结论**

       * 沿用面额 `1、2、5`、总金额 `5`，518 得到四种凑法，答案是一共四种。

       * 322 在这四种里选，第一种「一个五分硬币」只需一枚硬币，答案是一。

---

## 暴力递归的穷举样貌

   * **核心思路**

       * 暴力递归不断尝试所有硬币组合，一旦找到解就把这个解记录下来。

   * **以一分硬币开头的分支**

       * 五个一分正好凑足总金额，记为一个解。

       * 四个一分分别搭配两分、五分，`4 + 2` 与 `4 + 5` 都已超过总金额，直接排除。

       * 三个一分搭配两分正好凑足，记为一个解；三个一分搭配五分超过总金额，排除。

       * 两个一分配两枚两分时总额为六，超过总金额跳过；两个一分配一枚两分加一枚五分、以及两个一分配一枚五分均无解。

       * 一个一分配两枚两分正好凑足，记为一个解；与两分加五分、与一枚五分搭配都无解。

   * **以两分、五分开头的分支**

       * 以两分开头的三种组合（三枚两分、两枚两分加一枚五分、一枚两分加一枚五分）全部无解。

       * 最后尝试以五分开头，直接凑足，记为第四个解。

   * **结果校验**

       * 四个分支走完共找到四个解，与题目样例的四种凑法一致。

## rec方法的参数与终止判定

   * **三个有效参数**

       * `index`：当前正在处理的硬币索引，初值为零。

       * `coins`：整个硬币面值数组，每次递归都要用到，所以一并作为参数。

       * `remaining`：剩余金额，初值就是总金额五。

   * **两个演示参数**

       * 演示执行流程时额外传了 `stack` 与一个布尔值，正式解题时用不到。

   * **核心思想**

       * 每次递归前把剩余金额减去当前处理的硬币面值，剩余金额是否归零直接决定分支走向。

       * 剩余金额从五出发，若当前处理的是五分硬币，则 `5 - 5 = 0`，此时判定已凑足。

   * **剩余金额的三种情况**

       | 剩余金额 | 含义 | 接下来怎么办 |
       | :--- | :--- | :--- |
       | 小于零 | 加多了，没凑成 | 不用再递归，返回解的个数 0 |
       | 等于零 | 正好凑足，找到一个解 | 不用再递归，返回解的个数 1 |
       | 大于零 | 还有其他可能 | 继续凑，继续递归 |

       * 大于零意味着可以在剩余金额基础上再减一枚硬币，看能否减到零。

## 递归体的循环与返回值累加

   * **循环边界**

       * 循环变量 `i` 从 `index` 开始，循环到 `coins.length - 1`，即小于 `coins.length`。

       * 循环内调用 `rec`，把 `i` 作为新的 `index` 传入。

   * **金额递推**

       * 第三个参数传入 `remaining - coins[i]`，即当前剩余金额减去即将处理的那枚硬币面值。

   * **返回值累加**

       * 递归返回的是解的个数，各分支结果统一累加到变量 `count`，`count` 初值为零。

       * 表达式含义：当前状态能凑出的解数，等于所有可选下一枚硬币分支的解数之和。

$$\text{count} \;=\; \sum_{i=index}^{coins.length-1} \text{rec}\big(i,\; coins,\; remaining - coins[i]\big)$$

   * **终止分支的返回值**

       * 剩余金额小于零返回零，剩余金额等于零返回一，两种情况都不再进入循环。

## 升序遍历下的递归树

   * **调用记法**

       * 递归图里省略 `index` 参数，直接写正在处理的硬币与剩余金额，如 `rec(1, 5)`。

       * 首次调用时 `index` 为零，代表正在处理一号硬币，剩余金额为五。

   * **树的展开方式**

       * 第一次循环仍处理一号硬币，剩余金额变成四；第二次循环处理二号硬币，剩余金额变成三；第三次循环处理五号硬币，剩余金额变成零。

       * 只要某次递归的剩余金额大于零，它的内部就会再次进入循环继续递归，因此不是只有三次调用。

       * 节点进入循环时只从 `index` 开始遍历，已被排除的小面额不再参与，故以二开头的分支只剩二与五。

   * **升序递归树**

    ```text
    rec(1,5)
    ├─ rec(1,4)          4 > 0 → 三次循环
    │   ├─ rec(1,3)
    │   │   ├─ rec(1,2)
    │   │   │   ├─ rec(1,1)
    │   │   │   │   ├─ rec(1,0)   → 1   找到解
    │   │   │   │   ├─ rec(2,-1)  → 0   加多了，无解
    │   │   │   │   └─ rec(5,-4)  → 0   加多了，无解
    │   │   │   ├─ rec(2,0)       → 1   找到解
    │   │   │   └─ rec(5,-2)      → 0   加多了，无解
    │   │   ├─ rec(2,1)
    │   │   │   ├─ rec(2,-1)      → 0
    │   │   │   └─ rec(5,-4)      → 0
    │   │   └─ rec(5,-2)          → 0
    │   ├─ rec(2,2)               → 从 index 开始，只剩 2 和 5
    │   │   ├─ rec(2,0)           → 1   找到解
    │   │   └─ rec(5,-3)          → 0
    │   └─ rec(5,-1)              → 0
    ├─ rec(2,3)                   → 从 index 开始，只剩 2 和 5
    │   ├─ rec(2,1)
    │   │   ├─ rec(2,-1)          → 0
    │   │   └─ rec(5,-4)          → 0
    │   └─ rec(5,-2)              → 0
    └─ rec(5,0)                   → 1   找到解
    ```

       * 走到 `rec(1,0)`、`rec(2,0)`、`rec(5,0)` 这三条线的末端就是四个解，其余全是负数、直接返回零的枝桠。

   * **递归次数**

       * 一共找到四个解，中间执行了 n 多次递归操作。

## 组合打印依赖的栈

   * **入栈时机**

       * 当前正在处理的硬币用 `coins[index]` 取得，每次进入递归调用都把它 `add` 进 `stack`。

       * 例如进入 `rec(1,4)` 时压入一枚一，进入 `rec(1,3)` 时再压入一枚一，栈中就记录着已组合出的硬币序列。

   * **出栈时机**

       * 找到解时先打印当前栈内容，此时栈顶是最后压入的那枚硬币，它已经参与过组合，留着无用。

       * 删除栈顶后恢复成上一层状态，才能继续与后续的二分、五分硬币组合。

       * 无解分支同样要弹出，无解也要打印组合内容。

       * 循环结束之后仍要弹出栈顶，否则残留的这一枚硬币会污染下一轮递归的组合。

   * **打印方法**

       * `print` 方法的第一个参数是提示信息，取值为有解或无解；第二个参数传入栈，方法内部打印栈内容。

   * **首次调用豁免**

       * 最外层的 `rec(1,5)` 还没有真正执行「减去一枚硬币」的操作，组合是从 `rec(1,4)` 才开始做的，因此这一层不该入栈。

       * 加一个布尔变量 `first`，初值为 `true` 表示首次调用；只有 `first` 为假时才执行 `stack.add`，后续递归统一传入 `false`。

   * **代码收敛**

       * 无解、有解、循环结束三处都要弹栈，这段代码重复出现，可以统一移到方法末尾。

       * 把 `return` 的值先抽到外层变量 `count`：无解时保持零，有解时置一，递归时累加。

       * 弹栈逻辑统一写成 `if (!stack.isEmpty()) stack.pop();`，放在 `return count` 之前。

> **易错点**：漏掉任何一处弹栈，或让首次调用也入栈，打印出来的组合每次都会多出一枚硬币。

## 力扣超时的成因与记忆化优化

   * **正确但超时的现状**

       * 代码正确性没有问题，但放到力扣上跑会超时，执行效率低于预期时间要求。

   * **重复调用**

       * 升序递归树里 `rec(2,-1)` 重复调用了三次，`rec(5,-4)` 也重复出现，类似的重复节点还有很多。

       * 钱币种类越多，组合数量越庞大，重复的递归调用就越多，整体性能非常低。

   * **记忆化优化**

       * 第一次执行到某个递归方法时把结果缓存下来，下次遇到相同调用直接从缓存取结果，不再重复执行。

   * **尚未展开的方向**

       * 还有动态规划方式的优化，本节先不考虑记忆化与动态规划，只从遍历顺序入手做简单优化。

## 硬币面额由大到小的遍历

   * **升序的失败代价**

       * 升序组合越到最后越容易失败：已经四个一再来一枚更大的二或五，很容易超过总金额。

       * 三个一与二正好凑成总金额，但三个一与五就超过总金额，失败分支被推到最后才集中爆发。

   * **降序配置**

       * 把面额数组改为 `{5, 2, 1}`，先考虑面值大的钱币，最后才考虑面值小的钱币。

       * 最终仍然找到四种解，说明答案不受遍历顺序影响。

       * 失败几率明显降低，只有一次发现无解，其余分支直接拿到有解。

   * **降序后的递归过程**

       * 首次进入 `rec` 时 `index` 为零，对应面值最大的五分硬币，调用为 `rec(5,5)`，剩余金额也是五。

       * 内部三次循环分别是：处理五得到零，处理二得到三，处理一得到四。

       * `rec(2,3)` 剩余金额为三进入 `else`，五分硬币不用处理，从二开始，处理二剩一，处理一剩二。

    ```text
    rec(5,5)
    ├─ rec(5,0)      → 1   找到解
    ├─ rec(2,3)              从 index 开始：五不用处理，只剩 2 和 1
    │   ├─ rec(2,1)
    │   │   ├─ rec(2,-1)     → 0
    │   │   └─ rec(1,0)      → 1   找到解
    │   └─ rec(1,2)
    │       └─ rec(1,1)
    │           └─ rec(1,0)  → 1   找到解
    └─ rec(1,4)              从 index 开始：五、二不用处理，只剩 1
        └─ rec(1,3)
            └─ rec(1,2)
                └─ rec(1,1)
                    └─ rec(1,0)  → 1   找到解
    ```

       * `rec(1,4)` 这支相对简单，五分与两分都不用处理，只处理一分，依次得到三、二、一，直到零找到解。

   * **规模对比**

       * 降序的递归树占据 19 到 32 这一段，只有 13 行；升序的递归过程占 72 到 95，跨度 23 行。

       * 降序后整棵树瘦成一条主链加两个短分支，找到四个解，只踩中一次负数。

> **易错点**：顺序只是减少失败分支，并没有消除重复调用——`rec(1, 0)` 在降序的树里依然出现了三次，真正的复杂度问题要靠记忆化或动态规划解决。

## 零钱交换的练习改写

   * **题目要求**

       * 322 题零钱兑换与 518 题共用同一题干，凑不出则无解，返回凑足总金额所需的最少硬币数。

   * **数据与答案**

       * 沿用面额 `1、2、5`、总金额 `5`，四种凑法分别是：一个五分；两个两分加一个一分；一个两分加三个一分；五个一分。

       * 答案是一种凑法，它只要一个硬币就能凑足总金额，所以返回一。

   * **改写要点**

       * 把暴力递归骨架搬过来，把最后一环「返回解的个数」换成「在所有能凑成的路径里挑硬币数最少的那一条」。
