# 基础算法-200-哈希表-e08-出现次数最多的

## 出现次数最多的单词

    * **题目：出现次数最多的单词**

        * > **定义**：给定一个段落 `paragraph` 和一个禁用词数组 `bannedWords`，返回段落中出现次数最多的单词，且该单词不能出现在禁用词数组中。

        * 单词按非字母字符切分，统计时不区分大小写。

        * `bannedWords` 中包含一到多个禁用词。

        * 保证答案唯一，不会出现两个单词出现次数并列最多的情况；这一点是后面写代码的前提。

        * 示例段落里出现次数最多的是 hit，共三次，但它恰好在禁用词列表中，应被排除。

        * 排除 hit 之后，最多的是 ball，出现两次，不区分大小写地计算。

    * **三步骨架**

        * 切词：把 paragraph 截取成一个一个的单词。

        * 计数：把单词塞进 Map 做统计。

        * 取最大：在 Map 里找到 value 最大的那个 key。

        * 禁用词列表恰好卡在第二步的门口，进 Map 之前先挡掉。

            ```text
            paragraph
               |
               v
            [1] 切词                 [2] 计数                [3] 取最大
             找分隔符                 单词 -> key              找 value 最大的
             统一转小写               次数 -> value            返回它对应的 key
             挡掉禁用词               禁用词不进 Map
            ```

## 切词：用排除法定下分隔符

    * **排除法**

        * > **定义**：事先不知道段落里有哪些特殊字符，于是先把"一定是单词"的字符排除掉，剩下的就是分隔符。

        * 单词字符是大写的 A 到 Z 加上下写的 a 到 z。

        * 分隔字符是单词字符之外的一切，即空格、逗号、句点这些特殊字符。

        * 对应的正则写法是 `[^a-zA-Z]+`。

            ```text
            段落里可能出现的两类字符
            +-------------------------------------------+
            |  单词字符   a~z  A~Z                       |
            |  分隔字符   空格  逗号  句点  ...           |
            +-------------------------------------------+
                    ^
                    |  我不知道有哪些分隔字符
                    |  那就先把"一定是单词"的排除掉
                    v
                    用 [^a-zA-Z]+ 来匹配剩下的部分
            ```

        * > **易错点**：量词要用"一到多次"，不能只匹配一个。一个空格就是一格，但逗号后面紧跟着又是一个空格，那是连续两格。

    * **split 切词**

        * `split` 需要显式告诉它按哪些分隔符切，麻烦正是一开始并不知道有哪些特殊字符。

        ```java
        String[] words = paragraph.split("[^a-zA-Z]+");
        ```

        * 截取出来第一个单词是 bob，第二个是 hit，其余单词也都切好。

    * **统一转小写**

        * 题目要的都是小写单词，比较时更方便，所以干脆在切词这一步就统一转换。

        ```java
        Arrays.stream(words)
              .map(String::toLowerCase)
              .toArray(String[]::new);
        ```

        * 一步转换后 Map 里存的就是一水儿的小写单词，"不区分大小写"这条需求自动满足。

## 计数：单词当 key，次数当 value

    * **Map 的选型与类型**

        * 用 `HashMap`，因为待会儿放进去的是单词，key 的类型是 String。

        * value 是计数，类型是 Integer。

        ```java
        Map<String, Integer> map = new HashMap<>();
        ```

    * **四行 for 循环写法**

        ```java
        for (String word : words) {
            Integer value = map.get(word);   // 先看看这个单词在不在
            if (value == null) {             // 不在，说明是第一次出现
                value = 0;                   // 给个初始值
            }
            map.put(word, value + 1);        // 塞进去
        }
        ```

        * 第一次出现时不是在这个基础上加一之后再放回去，第一次的值应该是 1 而不是 0。

        * 上面写法里第一次先给 0，最后统一 `value + 1`，正好把"第一次"和"第 N 次"两种情况用一行覆盖掉。

        * 循环结束打印 Map，hit 是 3，ball 是 2。

    * **compute：一行顶四行**

        ```java
        map.compute(word, (k, v) -> v == null ? 1 : v + 1);
        ```

        * `compute` 接两个参数：第一个是要放入的 key，第二个是一个 lambda 表达式。

        * 这个 lambda 会把当时的 key 和 value 都传过来。

        * v 等于 null 说明 Map 里还没有这个 k，那第一次的值就该是 1。

        * v 不为 null，那该值就是上次的 value 加一。

        * 两种情况全在 lambda 后面这个表达式里处理掉了，跑出来依然是 hit 3、ball 2。

## 禁用词：用 Set.contains 把线性查找换成常数级

    * **禁用词数组转 Set**

        * 禁用词是作为一个字符串数组传过来的。

        * 每次循环都在这个数组里找禁用词，查找效率是 $O(n)$，时间复杂度就是大 O n。

        * 准备一个 Set 集合后，把 $O(n)$ 降到 $O(1)$。

        ```java
        // Java 9 以上，最简单
        Set<String> bannedSet = Set.of(bannedWords);

        // Java 8 的话得自己去遍历，一个一个往 Set 里 add
        Set<String> bannedSet = new HashSet<>(Arrays.asList(bannedWords));
        ```

    * **先判断再入 Map**

        * Set 准备好之后，在往 Map 里放之前先判断一下。

        ```java
        if (bannedSet.contains(word)) {
            continue;   // 在禁用词列表中，就别往 Map 里放
        }
        map.compute(word, (k, v) -> v == null ? 1 : v + 1);
        ```

        * 跑一遍之后 Map 里就没有那个 `hit = 3` 了，因为它在禁用词列表里。

        * > **易错点**：判断和 put 的先后顺序不能反。先 put 进去再判断，Map 里就已经留下痕迹了，后面再 remove 反而绕。

## 取最大：遍历 entrySet 找 value 最大的 entry

    * **stream 流 API 写法**

        ```java
        Map.Entry<String, Integer> maxEntry = map.entrySet().stream()
                .max(Map.Entry.comparingByValue())
                .orElse(null);

        String word = Optional.ofNullable(maxEntry)
                .map(Map.Entry::getKey)
                .orElse(null);
        ```

        * 先拿到 `entrySet()`，即键值对的集合，它本身就是一个 Set。

        * 转成流后调 `max` 去找最大的那个 entry；`max` 要接一个比较器对象，得告诉它到底按什么算最大——按 value 还是按 key。

        * `Map.Entry.comparingByValue()` 就是现成的按值比较；也可以按 key 比较，但这里 value 才是出现次数。

        * `max` 返回的是一个 `Optional` 对象，打印出来里面果然装着目标 entry：key 是 ball，value 是 2。

        * 找到 entry 之后最终只要它的 key，所以对 Optional 再 `.map(Map.Entry::getKey)`，只留下 key 这一部分。

        * 还要判一层 Optional 是因为它里可能有值也可能没有，没有的话 `orElse(null)` 兜一下，返回 null 就完事了。

        * 最终返回的 k 是 ball，正确。

    * **普通 for 循环写法**

        ```java
        int maxValue = 0;      // 出现次数最少的就是 0 了，不可能再少
        String maxKey = null;

        for (Map.Entry<String, Integer> entry : map.entrySet()) {
            if (entry.getValue() > maxValue) {
                maxValue = entry.getValue();
                maxKey = entry.getKey();
            }
        }
        return maxKey;
        ```

        * 循环外先假定最大值是 0，每轮拿到当前 entry 的 value 也就是它的出现次数，比上一次的 max 大就更新。

        * 循环结束时 max 里记录了最多的那个次数，但需要的是那个 key，所以还得配一个 `maxKey` 变量，每次更新 max 的同时把 `entry.getKey()` 也更新进去。

        * 跑一下结果仍然是 ball，正确；缺点是代码看着比 lambda 冗长、行数更多。

## 手动逐字符拼单词

    * **拼词机理**

        * 段落先转成小写，然后一个字符一个字符看。

        * 遇到的字符在 `a` 到 `z` 之间，就把它记下来，拼到一个 `StringBuilder` 上。

        * 遇到第二个字符还是在 `a` 到 `z` 之间，继续拼。

        * 遇到一个不是 `a` 到 `z` 的字符，说明这个单词到头了，`toString()` 一下作为 key 放进 Map。

        * 然后新建一个 `StringBuilder`，重新拼下一个单词。

        * 用 `StringBuilder` 而不是加号拼接，是因为要做大量字符串拼接，`StringBuilder` 比用 `+` 效率高，所以在循环外准备好一个对象。

    * **实现骨架**

        ```java
        String lower = paragraph.toLowerCase();
        char[] chars = lower.toCharArray();
        StringBuilder sb = new StringBuilder();

        for (char c : chars) {
            if (c >= 'a' && c <= 'z') {
                sb.append(c);
            } else {
                String key = sb.toString();
                if (!bannedSet.contains(key)) {
                    map.compute(key, (k, v) -> v == null ? 1 : v + 1);
                }
                sb = new StringBuilder();   // 重新开始拼下一个单词
            }
        }
        ```

        * 跑一遍，ball 出现两次，hit 出现三次，其他的出现一次，都对。

        * > **提示**：`else` 分支最好也先判一下 `sb.length() > 0` 再 put。段落里出现"逗号 + 空格"这种连续分隔符时 `sb` 会是空的，不判的话 Map 里会凭空多出一个空字符串 key，还会被计数；语义上空串不是单词，直接跳过就干净了。

    * **边界：收尾时最后一个单词差点丢了**

        * 边界用例的段落里只有一个单词 `bob`，没有任何分隔符，此时打印的 Map 集合是空的。

        * 原因是 `b`、`o`、`b` 三个字符都被拼进 `StringBuilder` 了，但永远不会进入 `else`，因为没有非单词字符的分隔符。

        * 进不了 else，那个"往 Map 里 put"的动作就没执行，相当于单词已经拼好了，最后一步没放进去。

        * 解决办法是在循环外做一个收尾动作：判断这个 `StringBuilder` 的 `length` 是否大于零，是的话就把最后剩的那个单词 `toString()` 作为 key 放进 Map。

        ```java
        // 循环外的收尾：段落末尾的单词后面没有分隔符，得手动补一刀
        if (sb.length() > 0) {
            String key = sb.toString();
            if (!bannedSet.contains(key)) {
                map.compute(key, (k, v) -> v == null ? 1 : v + 1);
            }
        }
        ```

        * 再跑一遍这回 bob 就正确地放进 Map 了，收尾工作做好逻辑就完整了。

        * 禁用词这块仍是老规矩：在 put 之前先 `contains` 判断一下再放。

    * **复用 StringBuilder**

        * 每次循环拼新单词都 `new` 一个 `StringBuilder` 是可以改掉的。

        * 不创建新的对象，而是调用原有对象的 `setLength(0)` 把旧内容清空，下次拼接时又从零开始。

        ```java
        } else {
            String key = sb.toString();
            if (!bannedSet.contains(key)) {
                map.compute(key, (k, v) -> v == null ? 1 : v + 1);
            }
            sb.setLength(0);   // 不新建对象，把旧的清空，下次从零开始拼
        }
        ```

## 冒泡排序：两两比较，逆序就换

    * **基于比较的排序算法**

        * 常见的有：冒泡、选择、堆排序、插入排序、希尔排序、归并排序和快速排序。

        * 冒泡、插入这些在此前的练习和知识讲解里已经讲过，这里只回顾要点。

        * 核心还是"比较"的思想。

    * **复杂度与稳定性**

        | 维度 | 冒泡排序 |
        | --- | --- |
        | 最好时间复杂度 | $O(n)$，数组已有序时一轮就结束 |
        | 最坏时间复杂度 | $O(n^2)$，数组完全逆序 |
        | 平均时间复杂度 | $O(n^2)$ |
        | 空间复杂度 | $O(1)$，只占用常量级空间 |
        | 是否稳定 | 稳定 |

        * 最好 $O(n)$：数组内的元素已经有序，只需要经过一轮冒泡就能确定顺序。

        * 最坏 $O(n^2)$：数组内的元素恰好完全逆序，例如想排成 1 2 3 4 5 6 7 而初始是 7 6 5 4 3 2 1。

        * 空间复杂度 $O(1)$，只需要几个变量去交换数组元素、记录最后的交换位置，跟数据规模没有关系。

        * 稳定指排序前后取值相同的元素相对次序不变。

        * 注意事项这块相当于最好情况，需要做一些额外的判断，这是冒泡排序的一个特点。

            ```text
            稳定的排序：取值相同的元素，相对次序不变

               排序前              排序后
             [ 红桃5  黑桃5 ]  ->  [ 红桃5  黑桃5 ]     两个 5 谁也没跑到对方前头

            不稳定的排序：取值相同的元素，次序被打乱

               排序前              排序后
             [ 红桃5  黑桃5 ]  ->  [ 黑桃5  红桃5 ]     取值相同，次序反了
            ```

### 一轮一轮地冒

    * **核心动作**

        * 不断比较相邻的两个元素，如果是逆序的就交换它们的位置。

        * 一轮冒泡的标志是本轮最大值已经排好序，前面的元素还处于未排序区域。

        * 未排序区只剩一个元素时，没人跟它比了，整个排序算法结束。

    * **一轮冒泡的过程**

        ```text
        初始数组:  [ 3  2  1 ]     未排序区 = 全部

        第 1 轮:   比较 3 和 2   ->  逆序，交换
                   比较 3 和 1   ->  逆序，交换
                   结果:    [ 2  3  1 ]     未排序区 = [2, 1]，3 已经就位

        第 2 轮:   比较 2 和 1   ->  逆序，交换
                   结果:    [ 1  2  3 ]     未排序区 = 空，2 也就位了

        第 3 轮:   未排序区只剩一个元素，没人跟它比了
                   -> 整个排序算法结束，数组已有序
        ```

### 优化右边界

    * **右边界变量**

        * 没有优化之前，每次冒泡只能排好一个元素：第一次排好 3，第二次排好 2，最后一次排好 1，右边界每次只减少 1。

        * 优化办法是定义变量 `x`，用来记录最后一次交换的索引位置。

        * `x` 值没有变，意味着后面这些已经是有序的，它记录的就是最后一个无序的右边界。

        * 下一轮冒泡时只需要比较 0 到 x 这个范围内的元素，后面那些不用再比较，冒泡轮数一下子少了很多。

        * 做了这个优化才能真正达到最好情况：已经排好序的数组，一轮冒泡之后 `x` 一直停在 0，下一轮就直接判定不用再排了。

        ```text
        数组: [3, 2, 1, 4, 5]

          i=0:  3 > 2  逆序  交换   ->  x = 0
          i=1:  2 > 1  逆序  交换   ->  x = 1     <- 最后一次交换发生在这儿
          i=2:  1 < 4  有序  不换   ->  x 不变
          i=3:  4 < 5  有序  不换   ->  x 不变

        本轮结果: [2, 1, 3, 4, 5]

          x 记录的是最后一个仍处于无序的右边界
          下一轮只需要比较下标 0 ~ x，也就是 0 ~ 1
          后面那 3 4 5 不需要再比较了
        ```

### 递归版改写成非递归版

    * **递归版结构**

        * 单路递归改成非递归非常容易，其实就是做一个外层循环；多路递归意味着它分叉，改起来就比较复杂，冒泡属于单路。

        ```text
        递归版 bubble(a, j)
           |
           +-- 这一段代码 = 执行一轮冒泡
           |
           +-- 一轮冒泡之后，递归调用 = 意味着要执行下一轮冒泡
           |
           +-- j 代表未排序区的右边界；j == 0 时 return，结束递归
           |
           +-- j 的初始值是 数组.length - 1；下一轮递归时 j 改成 x
        ```

    * **非递归版实现**

        ```java
        public static void sort(int[] a) {
            int j = a.length - 1;          // 未排序区的右边界，初始值定义在循环外
            while (true) {
                int x = 0;                 // 本轮最后一次交换的索引位置
                for (int i = 0; i < j; i++) {
                    if (a[i] > a[i + 1]) {
                        swap(a, i, i + 1);
                        x = i;
                    }
                }
                j = x;                     // 下一轮的右边界直接用 x
                if (j == 0) {
                    break;                 // 未排序区只剩一个元素，排好了
                }
            }
        }
        ```

        * 递归版里"每次递归调用意味着执行下一轮冒泡"，这里就是外层 `while (true)`；轮数事先不知道，反正是若干次。

        * 递归版的 `j` 初值是 `a.length - 1`，这里也把它定义在循环外。

        * 递归版下一轮 `j` 改成 `x`，这里每轮循环结束也把 `j` 更新成 `x`。

        * `j == 0` 就 break，对应递归版的 `return`。

        * 测试数组 `[6, 5, 4, 3, 2, 1]` 跑完变成 `[1, 2, 3, 4, 5, 6]`，对了。

        * IDEA 会提示这里的 `while (true)` 可以优化一下，按 `Alt + Enter` 它就会自动改成一个 `do-while` 循环，最终效果一样。

## 选择排序：不稳定，但交换次数少

    * **复杂度与稳定性**

        | 维度 | 选择排序 |
        | --- | --- |
        | 最好时间复杂度 | $O(n^2)$ |
        | 最坏时间复杂度 | $O(n^2)$ |
        | 平均时间复杂度 | $O(n^2)$ |
        | 空间复杂度 | $O(1)$ |
        | 是否稳定 | 不稳定 |
        | 相对优势 | 交换次数通常少于冒泡 |

        * 最好、最坏、平均时间复杂度都是 $O(n^2)$；最好情况也是 $O(n^2)$，意味着它针对已经排好序的数组并没有额外的优化。

        * 空间复杂度跟数据规模没关系，是 $O(1)$。

        * 不是稳定排序，遇到取值相同的元素，排序后有可能把顺序打乱。

        * 交换次数一般少于冒泡，所以虽然时间复杂度一样，大部分情况下它排序的速度好像比冒泡还要快一些。

        * 这是没有考虑优化的情况，专门针对已经排好的数组优化过的冒泡还是更快。

        * 思想同样还是这种基于比较的思想。

### 每轮选一个最大的

    * **思想与轮次**

        * 每一轮选择，选出一个最大或者最小的元素，把它交换到合适的位置就可以了。

        * 以"每轮选最大"为例，第 1 轮选出最大交换到数组末尾，第 2 轮在剩下的里面再选最大交换到下一个位置，依此类推。

        * 最后就剩一个元素了，不用再选，整个排序结束。

        * 每轮结束未选择区往右收缩一格，右边多一个"已就位"的元素。

        * 当然也可以每轮选一个最小的，思想是类似的。

        ```text
        第 1 轮:  从所有元素里选出最大 -> 交换到数组末尾
        第 2 轮:  在剩下的里面再选最大 -> 交换到下一个位置
        第 3 轮:  下一轮再选择一个最大的 -> 交换到合适的位置
           ...
        第 5 轮:  选择 2 -> 交换到合适位置
        最后:     就剩一个元素了，不用再选，整个排序结束

          每轮结束，未选择区往右收缩一格，右边多一个"已就位"的元素
        ```

    * **轮数与 right 递减**

        * 一共要选择的轮数是元素个数减一：六个元素选择五次，五个元素选择四次，五轮之后剩一个元素就没必要再选。

        * 每轮交换的索引位置初始值是 `a.length - 1`，每轮选择之后这个位置继续减一。

        * `right` 从最右侧开始每次递减，`right > 0` 就停，最后一个元素不用再选，加起来正好循环了 `a.length - 1` 次。

        ```java
        for (int right = a.length - 1; right > 0; right--) {
            // right 就是每轮交换的那个索引位置，也就是区间最右侧的下标
        }
        ```

### 找到 max 之后与 right 交换

    * **内层循环定位最大值**

        * 先假设最右侧这个元素是最大的，用一个 `max` 变量来指向它的索引位置。

        * 它不一定真的是最大的，所以还要把它跟前面 `0 ~ right - 1` 这些元素做比较，有更大的就去更新 `max` 的索引位置。

        * 循环完一遍 `max` 就记录了本轮最大值所在的下标。

        * 所以在循环外要做一件事：交换 `max` 索引和 `right` 索引的位置，把最大的那个换到最右侧。

        ```java
        for (int right = a.length - 1; right > 0; right--) {
            int max = right;              // 先假设 right 处的元素是最大的
            for (int i = 0; i < right; i++) {
                if (a[i] > a[max]) {
                    max = i;              // 找到了更大的，把它的下标记下来
                }
            }
            swap(a, max, right);          // 把最大值的下标与最右侧交换
        }
        ```

        * 准备一个未排序的数组，跑完排序后的结果应该是 `[1, 2, 3, 4, 5, 6]`，选择排序的实现就完成了。

    * **省掉一次没必要的交换**

        * 刚开始最右侧这个元素就已经是最大的情况下，`i` 这边循环完一遍并没有找到一个更大的，那这时候就不用交换。

        * 判断循环结束后 `max` 是否仍然等于 `right`，说明没找到比它更大的，就不用 swap 了。

        ```java
        for (int right = a.length - 1; right > 0; right--) {
            int max = right;
            for (int i = 0; i < right; i++) {
                if (a[i] > a[max]) {
                    max = i;
                }
            }
            if (max != right) {           // 只有真的找到了更大的才交换
                swap(a, max, right);
            }
        }
        ```

        * 这样就省去了一次不必要的交换，是一个微小的优化。
