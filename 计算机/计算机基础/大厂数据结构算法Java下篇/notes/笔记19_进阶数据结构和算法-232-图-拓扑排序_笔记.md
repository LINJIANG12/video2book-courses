# 进阶数据结构和算法-232-图-拓扑排序

## 拓扑排序

* **拓扑排序（Topological Sort）**

    * > **定义**：把一张有向无环图（Directed Acyclic Graph，DAG）的全部顶点，按边的方向排成一个线性序列，使得对任意一条边 $u \to v$，$u$ 都排在 $v$ 前面。

    * 课程之间的依赖关系本质上就是一张有向图，先修课指向后修课。

        ```text
          v1 网页基础 ──┐
                        ├──► v3 JavaWeb ──► v4 Spring框架 ──► v5 微服务框架 ──► v7 实战项目
          v2 Java基础 ──┘                          ▲
          v6 数据库 ───────────────────────────────┘
        ```

    * 上例共七个顶点、六条依赖；课程表看着是一张表，落到代码里就是一个 `List<Vertex>` 装顶点、每个顶点挂一个出边集合的邻接表结构。

    * 顶点只有入度为零时才能排出去；入度为零意味着没有箭头指向它，也就是不需要任何前置知识。

    * > **易错点**：拓扑排序的前提是整张图不能出现环，一旦出现环就没有任何顶点能排出去。

### 入度驱动的核心动作

    * 核心动作只有一个：找一个入度为零的顶点排出去，然后把它的邻居入度减一。

    * 邻居入度减到零，说明它的前置知识全部学完，它就能排了。

    * 入度为零的多个顶点之间没有先后约束，谁排前谁排后都无所谓，但必须落在同一轮里排出去。

    * 每排完一轮就从图里把已排出的顶点移除，剩余图上重新找入度为零的顶点，重复直到顶点排空。

    * 课程依赖图上的完整推演过程：

        | 轮次 | 图上还剩的顶点 | 本轮排出去的顶点 | 排出去之后入度的变化 |
        | :--- | :--- | :--- | :--- |
        | 第一轮 | v1 ~ v7 全部 | v1 网页基础、v2 Java 基础、v6 数据库 | v3 入度 $2 \to 0$ |
        | 第二轮 | v3、v4、v5、v7 | v3 JavaWeb | v4 入度 $2 \to 1$ |
        | 第三轮 | v4、v5、v7 | v4 Spring框架 | v5 入度 $1 \to 0$ |
        | 第四轮 | v5、v7 | v5 微服务框架 | v7 入度 $1 \to 0$ |
        | 第五轮 | v7 | v7 实战项目 | v7 没有出边，结束 |

### 入度统计

    * 顶点类里要额外加一个 `indegree` 属性记录入度，初始值都是零。

    * 统计逻辑：对全图做一层遍历，再对每个顶点的出边集合做一层遍历，每条边指向的那个顶点入度加一。

    * 遍历完所有顶点及其出边集合后，全部顶点的入度就统计完毕。

    * 课程依赖图上统计出的入度分布：

        | 顶点 | 对应课程 | 入度 | 入边来自 |
        | :--- | :--- | :--- | :--- |
        | v1 | 网页基础 | 0 | —— |
        | v2 | Java 基础 | 0 | —— |
        | v3 | JavaWeb | 2 | v1、v2 |
        | v4 | Spring 框架 | 2 | v3、v6 |
        | v5 | 微服务框架 | 1 | v4 |
        | v6 | 数据库 | 0 | —— |
        | v7 | 实战项目 | 1 | v5 |

    * 第一步的统计代码：

        ```java
        // 统计每个顶点的入度
        for (Vertex vertex : graph.getVertices()) {
            for (Edge edge : vertex.getEdgeList()) {
                Vertex to = edge.getTo();          // 这条边指向的顶点
                to.setInDegree(to.getInDegree() + 1);
            }
        }

        // 循环结束顺手打印每个顶点的名字和入度
        for (Vertex vertex : graph.getVertices()) {
            System.out.println(vertex.getName() + " 的入度是：" + vertex.getInDegree());
        }
        ```

### 入队、出队与邻居入度减一

    * 队列用 `LinkedList` 准备，把所有入度为零的顶点用 `offer` 一次性入队。

    * 每次出队的顶点就相当于已经排好序了，随后遍历它的 `edgeList`，把每个相邻顶点的入度减一。

    * 相邻顶点入度被减到零的瞬间，立即把它入队，交给下一轮处理。

    * 课程依赖图上的执行次序：网页基础、Java 基础、数据库同时出队，JavaWeb 入度减到零后入队，Spring 框架随后入队，微服务框架、实战项目依次入队，队列空了循环退出。

    * 第二步与第三步的代码：

        ```java
        // 第二步：把入度为零的顶点全部加入队列
        LinkedList<Vertex> queue = new LinkedList<>();
        for (Vertex vertex : graph.getVertices()) {
            if (vertex.getInDegree() == 0) {
                queue.offer(vertex);
            }
        }

        // 第三步：不断出队，把邻居的入度减一，减到零就入队
        while (!queue.isEmpty()) {
            Vertex current = queue.poll();
            System.out.println(current.getName());          // 出队 = 已排好序

            for (Edge edge : current.getEdgeList()) {       // 遍历它的出边
                Vertex next = edge.getTo();                 // 相邻顶点
                next.setInDegree(next.getInDegree() - 1);    // 相邻顶点入度减一

                if (next.getInDegree() == 0) {              // 减到零了，才能排
                    queue.offer(next);
                }
            }
        }
        ```

    * > **易错点**：⚠️ 出队顺序不唯一。网页基础、Java 基础、数据库这三个入度为零的顶点谁先谁后都行，真正会卡住顺序的，是那些必须「等到某一门课学完才能学」的课程。

## 图里有环时排序卡住

* **成环反例**

    * 在 v5 微服务框架指向 v7 实战项目之外，再补一条 v7 指向 v5 的边，两个顶点之间就构成了环。

        ```text
           v5 微服务框架 ──────► v7 实战项目
                ▲                    │
                └────────────────────┘
                     多出来的这条边
        ```

    * 补边之后 v5 的入度由 1 变为 2，其余顶点的入度不变。

    * 排到 v5 时它只被减了一次，入度仍然是 2，永远减不到零，因此不会入队。

    * v5 排不出去，它后面的 v7 实战项目也就跟着排不出去，整个队列里不会再出现这两个顶点。

    * 道理很直白：微服务框架得等实战项目学完，而实战项目又得等微服务框架学完，两个都在等对方，永远等不到。

### 用结果集大小比对来测环

    * 把出队的顶点名字收进一个 `result` 集合，而不是直接打印。

    * 循环结束后把 `result` 的大小与原始图 `graph.getVertices()` 的顶点数量做一次比较。

    * 两者相等说明每个顶点都从队列里取出来过，没有环；两者不等说明有环。

    * 反例中的实际结果：`result` 里只有五个顶点，而图里有七个顶点，判定为有环；去掉那条成环的边后两者相等，判定为无环。

    * 比对用的代码：

        ```java
        List<String> result = new ArrayList<>();

        while (!queue.isEmpty()) {
            Vertex current = queue.poll();
            result.add(current.getName());          // 不直接打印，收进结果集
            // ... 后面还是照旧减邻居入度、入队
        }

        System.out.println(result.size());                 // 拓扑排序结果的顶点数
        System.out.println(graph.getVertices().size());    // 原始图的顶点数
        ```

    * > **易错点**：⚠️ 不要去判断「被漏掉的顶点是不是超过了一个」之类的阈值。判定就是一次简单的大小比较——结果集里没被排出来的顶点，一定是被环卡住的。

## DFS 版拓扑排序

* **回溯压栈（DFS 版拓扑排序）**

    * 对图中所有未访问过的顶点各做一次深度优先搜索，起点任选。

    * 深度优先搜索沿一条路走到头：网页基础 → JavaWeb → Spring 框架 → 微服务框架 → 实战项目。

    * 走到头往回退时，每退出一层就把当前顶点压入栈，栈是后进先出，后压的顶点在上面。

        ```text
          深入（DFS 一路走到底）：
            网页基础 → JavaWeb → Spring框架 → 微服务框架 → 实战项目    ← 走到头了

          回溯（往回退，每退出一层压一个进栈）：
            实战项目 → 微服务框架 → Spring框架 → JavaWeb → 网页基础  ──► 栈
             压栈       压栈        压栈         压栈       压栈
        ```

    * 尚未遍历的顶点继续各自做一次深度优先搜索：数据库往前遇到已访问过的 Spring 框架，直接把自己压栈；Java 基础遇到已访问过的 JavaWeb，同样直接把自己压栈。

    * 整个栈里元素的顺序就是拓扑排序的结果，课程依赖图上得到的是数据库、Java 基础、网页基础、JavaWeb、Spring 框架、微服务框架、实战项目。

    * DFS 把一个顶点的所有邻居都处理完的那一刻，说明它的前置课程已经全部排完，这时候把它压进栈，它就自然排在所有前置课程后面。

### 三档访问状态

    * 顶点类里加一个 `status` 属性表示访问状态，初始值零表示未访问，二表示已访问，一表示访问中。

    * 不用 `visited` 的原因是布尔值只能表示两种状态，而 DFS 需要区分「没来过」「正在处理」「已经处理完」三档。

    * 顶点类里与图算法相关的属性集合：

        ```java
        public class Vertex {
            private String name;             // 顶点的名字
            private List<Edge> edgeList;     // 该顶点的出边集合（邻接表）
            private int indegree;            // 入度，拓扑排序用
            private int status;              // 0 未访问 / 1 访问中 / 2 已访问，DFS 用
            private int dist;                // 到起点的最短距离，Dijkstra 用
        }
        ```

    * 主流程对图做一层遍历，每个顶点都调用一次 `dfs`；栈声明在循环外，所有顶点共用同一个 `LinkedList<String>` 栈。

    * DFS 版拓扑排序的代码：

        ```java
        public static void topoSortByDfs(Graph graph) {
            LinkedList<String> stack = new LinkedList<>();
            // 写在循环外，所有顶点共用同一个栈
            for (Vertex vertex : graph.getVertices()) {
                dfs(vertex, stack);
            }
            System.out.println(stack);
        }

        private static void dfs(Vertex vertex, LinkedList<String> stack) {
            if (vertex.getStatus() == 2) {
                return;                              // 已经访问过，不用再递归了
            }

            vertex.setStatus(1);                     // 进入递归前，先标记自己"访问中"

            for (Edge edge : vertex.getEdgeList()) { // 遍历相邻顶点
                dfs(edge.getTo(), stack);            // 递归调用，把栈也传下去
            }

            vertex.setStatus(2);                     // 当前顶点彻底处理完了
            stack.push(vertex.getName());            // 往回走的时候才压栈
        }
        ```

    * 压栈必须放在最后：只有等相邻顶点全部处理完、往回走的时候才压栈，否则压进去的顺序会反过来。

### 访问中状态用于环检测

    * 纯拓扑排序流程里只用到了状态二，状态一专门留给环检测。

    * 递归进入一个顶点时先判断它的 `status`：等于二直接 `return`，等于一说明这个顶点自己还没处理完就被别的路径递归回来了。

    * 成环时的递归过程：

        ```text
        处理 v5 微服务框架：先把自己标成 1（访问中）
            │
            ▼
        处理它的邻居 v7 实战项目 → 递归 dfs(v7)
            │
            ▼
        处理 v7 的邻居，里面又有 v5 微服务框架 → 递归 dfs(v5)
            │
            ▼
        dfs(v5) 一进来就发现 status == 1
        说明我自己还没处理完，就又被别人递归回来了  ──►  有环，抛异常
        ```

    * 检测到环就直接抛异常终止，不必继续往下运行；无环时顶点处理完后状态会被改成二，下次进来就不会再走抛异常的分支。

    * 加了环检测的 `dfs`：

        ```java
        private static void dfs(Vertex vertex, LinkedList<String> stack) {
            if (vertex.getStatus() == 1) {
                // 我自己还没处理完，就又被递归回来了 —— 说明有环
                throw new RuntimeException("发现了环，拓扑排序失败！");
            }
            if (vertex.getStatus() == 2) {
                return;
            }
            // ... 下面不变
        }
        ```

    * > **提示**：「访问中」的判断必须放在 `status == 2` 的判断之前。顺序反了的话，一个正在访问中的顶点会被当成「已访问」直接 return，环照样漏过去。

## 最短路径与 Dijkstra

* **Dijkstra 算法**

    * > **定义**：从一个顶点出发，分别求出它到其余所有顶点的最短路径的算法；「单源」指起点只有一个。

    * 算法共五条步骤：所有顶点先设为未访问并组成未访问顶点集合；给每个顶点一个临时距离值，初始顶点为 0，其余为无穷大；循环体里先选临时距离最小的未访问顶点作为当前顶点，再遍历它的邻居更新距离，最后把当前顶点从未访问集合中删除；集合空了算法结束。

    * 以 v1 为起点的示例图：

        ```text
          v1 ──7──► v2 ──15──┐
          │                  │
          │9                 ▼
          │                  v4 ──6──┐
          │                  │       │
          │  v3 ────11──────►│       ├──► v5
          │   │              │       ▲
          │14 │2             │       │9
          │   ▼              │       │
          └──►v6 ─────────────┴───────┘
        ```

    * 手算过程：选中 v1 后把邻居 2 更新为 7、3 更新为 9、6 更新为 14；选中 2 后把 4 更新为 $7 + 15 = 22$；选中 3 后把 4 更新为 $9 + 11 = 20$、把 6 更新为 $9 + 2 = 11$；选中 6 后把 5 更新为 $11 + 9 = 20$；此时 4 和 5 的距离都是 20，任选一个处理，若选 4 则 5 得到 $20 + 6 = 26$，不更新。

    * 算法结束后每个顶点到起点的最短距离：

        | 顶点 | 从 1 出发的最短距离 |
        | :--- | :--- |
        | 1 | 0 |
        | 2 | 7 |
        | 3 | 9 |
        | 4 | 20 |
        | 5 | 20 |
        | 6 | 11 |

    * > **提示**：整个循环里最关键的一句话是「有更短的就更新，没有更短的就保留不变」。Dijkstra 允许一条顶点的距离被改写好几次（3 的邻居 6 就被从 14 改成了 11），这正是它能修正早期错误估计的原因。

### 顶点距离属性与初始化

    * 顶点类里加一个 `dist` 属性表示到起点的距离，创建顶点时默认就是无穷大，只有起点需要改成零。

    * 无穷大取整数的最大值，定义成常量 `INFINITY`。

    * 未处理顶点集合用一个 `ArrayList` 承载，初始内容就是原图全部顶点。

    * 算法结束条件是未处理集合变空，此时所有顶点都已处理完，遍历图把每个顶点的名字和记录的最短距离打印出来。

    * 初始化部分的代码：

        ```java
        private static final int INFINITY = Integer.MAX_VALUE; // 无穷大

        public static void dijkstra(Graph graph, Vertex source) {
            // 第一步：所有顶点都放进"未处理"集合
            List<Vertex> unvisited = new ArrayList<>(graph.getVertices());

            // 第二步：临时距离初始化——创建顶点时默认就是 INFINITY，只需把起点改成 0
            source.setDist(0);
        }
        ```

### 选取当前顶点

    * 第三步抽成独立方法 `findMinDistanceVertex`，接收未处理顶点集合，返回其中临时距离最小的顶点作为当前顶点。

    * 方法内部先假定下标 0 处的元素最小，再从下标 1 循环到 `size - 1`，逐个比较距离，发现更小的就把最小值更新成该元素，循环结束返回最小值。

    * 选取当前顶点的代码：

        ```java
        // 在集合中查找临时距离最小的顶点，并把它返回作为当前顶点
        private static Vertex findMinDistanceVertex(List<Vertex> vertexList) {
            Vertex minVertex = vertexList.get(0);       // 先假定下标 0 处的最小

            for (int i = 1; i < vertexList.size(); i++) {
                Vertex vertex = vertexList.get(i);
                if (vertex.getDist() < minVertex.getDist()) {
                    minVertex = vertex;                 // 找到更小的，就更新最小值
                }
            }
            return minVertex;
        }
        ```

    * > **注意**：这里先假定下标 0 处最小、再与其余元素逐一比较，是最直白的写法；更高效的查找算法存在，但先不考虑效率问题，把功能实现出来。

### 更新邻居距离

    * 第四步抽成独立方法 `updateNeighborDistances`，需要传两个参数：当前顶点（由它拿到邻居集合）与未处理顶点集合。

    * 传集合的原因是：邻居还在集合内表示它还没处理完，才需要更新；邻居不在集合内表示它已经处理完了，不用再动它的距离。

    * 遍历当前顶点的出边拿到邻居后，先用 `contains` 判断它是否还在集合里，在集合里才算新距离。

    * 新距离 = 当前顶点的距离 + 这条边的权值；新距离小于邻居原有距离才更新，否则保持不变。

    * 第五步只要把当前顶点从未处理集合中移除，调用 `remove` 传入当前顶点即可。

    * 主循环在未处理集合非空时不断执行「选最小距离顶点 → 更新邻居距离 → 移除当前顶点」三步，集合被移空表示所有顶点处理完成。

    * 更新邻居距离与主循环的代码：

        ```java
        // 更新当前顶点所有邻居的距离
        private static void updateNeighborDistances(Vertex current, List<Vertex> vertexList) {
            for (Edge edge : current.getEdgeList()) {
                Vertex n = edge.getTo();                // 先拿到邻居的顶点

                // 邻居还在集合里，说明它没处理完，才需要更新
                if (vertexList.contains(n)) {
                    int newDist = current.getDist() + edge.getWeight();  // 当前顶点距离 + 边的权值
                    if (newDist < n.getDist()) {        // 找到更短的距离，就更新
                        n.setDist(newDist);
                    }
                }
            }
        }

            // 第五步：当前顶点处理完了，从未处理集合里移除
            while (!unvisited.isEmpty()) {
                Vertex current = findMinDistanceVertex(unvisited);   // 第三步
                updateNeighborDistances(current, unvisited);         // 第四步
                unvisited.remove(current);                           // 第五步
            }
        }
        ```

    * > **易错点**：⚠️ 第四步里那个 `unvisited.contains(n)` 的判断千万别漏。Dijkstra 的正确性依赖于「只给还没最终确定的顶点更新距离」——已经移除的顶点，它的距离是终值，再去动它就会把答案改错。
