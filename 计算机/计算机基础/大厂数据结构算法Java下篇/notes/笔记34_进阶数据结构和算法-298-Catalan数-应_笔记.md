# 进阶数据结构和算法-298-Catalan数-应

## 数方案个数的一类题先问是不是卡特兰数

* **识别信号：不同的二叉搜索树、不同的括号组合、出栈顺序**
    * > **定义**：这类题问的不是最优化结果，而是满足约束的排列或结构一共有多少种。
    * 看到这一类题先别急着写搜索，先问一句：这是不是第 N 个卡特兰数。
    * 只要输出总数时，直接把求卡特兰数的代码拷过来套进去；方法名不一致就只搬函数体，注释不用带。
    * 搬过来提交即可通过，这类题不需要重新设计算法。

## 不同的二叉搜索树

* **给定 N，问有多少棵结构不同的二叉搜索树（力扣 96）**
    * N 等于 3 时组合数是 5，也就是第 3 个卡特兰数。
    * 本质上就是在求第 N 个卡特兰数，代码沿用求卡特兰数的那一份，不重写方法。

## 栈的出栈顺序一共有多少种

* **问题设定**
    * N 个元素依次进站，进站顺序是一定的：先进站的是 1，接下来是 2，然后是 3，一直到 N。
    * 问将来出站的排列组合有多少种。
    * > **注意**：入站的顺序永远是 1 先、2 后，不存在"2 先入站"这种可能，别搞混。
    * > **提示**：画图时站在框右侧的元素，表示它已经出站了。

### 从最小的几个数数起

* **N 等于 1**：一个元素，进站就得出来，没有其他元素了，一种。
* **N 等于 2**：两种
    * 1 进站之后立刻出来，然后 2 才进站——出站顺序是 **12**。
    * 1 进站之后还没出站，2 就进站了——出站顺序只能是 **21**。
* **N 等于 3**，按「1 是第几个出站的」分类，这个分类角度是整道题的关键
    * **1 第一个出战**：1 走了之后剩下 2 和 3 自由组合，2 也出战顺序是 **123**，2 还没出战 3 又入站顺序是 **132**，两种。
    * **1 第二个出战**：1 进站 → 1 还没出战，2 进站 → 2 出战 → 1 出战 → 3 进站 → 3 出战，顺序是 **213**，一种。
    * **1 最后一个出战**：1、2 都已入站而 3 还没入站时 2 先出站，然后 3 入站、最后 1 出战，顺序是 **231**；或者入站顺序 123、出站顺序 321，两种。
    * 合起来 2 + 1 + 2 = 5，对上卡特兰数的头几项 1、1、5。

### 递推式是怎么长出来的

* **刀口选「1 出战的时刻」**，整条时间线被切成三段

```text
  「1 出战」这一刻 = 一把刀，把时间线切成三段：

    左段：已经出站的 k 个元素      中段：站里只剩 1      右段：还没入站的 n-1-k 个元素
      它们互不干扰，C[k] 种                            它们互不干扰，C[n-1-k] 种
                                  一刀切下去，左段乘右段
```

    * 左段那一截的元素都已经离开站了，它们彼此之间的进出互不干扰。
    * 右段那一截还没进场，进场之后必然排在 1 之后出战。
    * 两截的方案数相乘，再把 1 出战的位置从第一个枚举到最后一个，一累加就是答案。
* **N 等于 4 逐项展开**

| 1 出战的位置 | 已出站的元素个数 | 还没入站的元素个数 | 方案数 |
| --- | --- | --- | --- |
| 第 1 个 | 0 | 3 | $C_0 \times C_3 = 1 \times 5 = 5$ |
| 第 2 个 | 1 | 2 | $C_1 \times C_2 = 1 \times 2 = 2$ |
| 第 3 个 | 2 | 1 | $C_2 \times C_1 = 2 \times 1 = 2$ |
| 第 4 个 | 3 | 0 | $C_3 \times C_0 = 5 \times 1 = 5$ |

    * 总方案数是左右两个相乘，最后再相加，代回 N 等于 4 就是 $C_4 = 5 + 2 + 2 + 5 = 14$。

$$C_n = \sum_{k=0}^{n-1} C_k \times C_{n-1-k}$$

## N 对括号有多少种有效组合

* **问题设定**：给 N 对括号，问能组成多少种有效括号组合。
    * 有效指左括号先出现、右括号再出现；右括号先出现就是无效的。
    * 递推式跟出栈顺序那道题一模一样的形状，都是 $C_n = \sum C_k \times C_{n-1-k}$。

### 从 1 数到 5

* **N 等于 1**：就 `()` 这一种，没有其他可能。
* **N 等于 2**：两种
    * 并列关系：先是一对有效括号，然后是第二对有效括号。
    * 嵌套关系：外层这一对有效括号，内层又是另外一对有效括号。
* **N 等于 3**：分三种情况
    * 一对括号内不包含任何其他括号：跟它平级的还有两对，这两对有 $C_2$ 两种组合，这一对分别跟它们组合得到 2 种。
    * 一对括号内包含了一对括号：三对里一对被包含了，剩下跟它平级的还有一对，平级那对只有一种放法，得到 1 种。
    * 一对括号内包含两对括号：跟它平级的没有了，被包含的两对有 $C_2$ 两种组合，得到 2 种。
    * 总共 2 + 1 + 2 = 5，还是卡特兰数。
* **分析套路**：让某一对有效括号内部不包含其他括号是一种情况；再看一对有效括号内部包含一对，又是一种情况；这样逐一分析下去。

### 递推式：把跨度讲透

* **跨度**：最外层那对括号从左括号到右括号一共罩住了几对，以 $C_4$ 为例切四刀。
    * 跨度为 1：内部包含 0 对，跟它平级的还有 3 对 → $C_0 \times C_3$。
    * 跨度为 2：内部可以包含 1 对，跟它平级的还有 2 对，1 + 2 再加外层这一对正好 4 对 → $C_1 \times C_2$。
    * 跨度为 3：内部包含 2 对，跟它平级的还有 1 对 → $C_2 \times C_1$。
    * 跨度为 4：内部包含 3 对，跟它平级的 0 对 → $C_3 \times C_0$。
    * 两两乘起来最后一累加：$C_4 = 1\times5 + 1\times2 + 2\times1 + 5\times1 = 14$。

### dp 数组要换血

* **这道题要的是全部清单，不只是总数**
    * 前面几道只要把组合总数求出来，这道题要求把所有组合字符串放在一个集合里反馈回来，输入 3 就返回五种括号组合。
    * 直接把求卡特兰数的代码拷过来，运行结果只有一个总数，看不到每种组合具体由哪些括号组成。

| 位置 | 存的东西 |
| --- | --- |
| `dp[0]` | 没东西，记录一个空的字符串 |
| `dp[1]` | 一对括号的唯一组合 |
| `dp[2]` | 平级的 `()()` 与嵌套的 `(())`，集合里两个元素 |
| `dp[3]` | 五种组合 |

    * `dp[3]` 的五种：一对一对一对；一对跟平级的一对里面套一对；一对里面套一对再跟平级的一对；一对里面套两个平级的括号；一对里面套一对、里面又套一对。
    * 把 `int` 数组改成一个放字符串的 `ArrayList` 数组，`dp[0]` 提前放好空串、`dp[1]` 提前放入唯一的那一对括号，`dp[2]`、`dp[3]` 随循环运行不断填满。
    * 原来代码的两层循环可以保持不变，只是要在外层循环里给 `dp[j]` 准备一个初始的空集合。
    * > **注意**：数组是引用类型，刚开始它们的值都是 `null`，必须手动 `new` 出空集合，否则往里 add 会炸。

### K1 和 K2 到底是谁

* **内层循环拆出的两个数字直接决定代码怎么写**
    * 第一个数字表示这对括号里面包含了几个其他括号、跟它平级的有几对；后面这个表示这对括号里包含了几个括号、跟它平级的剩几个。

| 拆分的两个数字 | 里面包含几对 | 跟它平级的有几对 |
| --- | --- | --- |
| 0 和 2 | 0 | 2 |
| 1 和 1 | 1 | 1 |
| 2 和 0 | 2 | 0 |

    * 这两个数字就对应代码里的 `i` 和 `j - 1 - i`，它们实际上就是索引值，按索引可以倒过头去找到 dp 数组中之前生成好的有效括号组合。
    * `dp[i]` 是一个 `ArrayList` 集合，`dp[j-1-i]` 也是一个集合；集合和集合的元素要进行组合，得对他俩再做一个嵌套的循环。
    * `k1` 是被外层一对括号套住的，先写好 `"("`，拼上 `k1`，再来个 `")"`；`k2` 是平级的，只要跟前面这个结果拼在一起就可以。

```java
public List<String> generateParenthesis(int n) {
    List<String>[] dp = new ArrayList[n + 1];

    // dp[0]：没有括号时，唯一合法的"组合"就是空串
    dp[0] = new ArrayList<>();
    dp[0].add("");
    // dp[1]：一对括号只有一种，就是它自己
    dp[1] = new ArrayList<>();
    dp[1].add("()");

    for (int j = 2; j <= n; j++) {
        // 数组是引用类型，得手动 new 出空集合
        dp[j] = new ArrayList<>();
        for (int i = 0; i < j; i++) {
            // k1 是被这对括号套在里面的，k2 是跟它平级的
            for (String k1 : dp[i]) {
                for (String k2 : dp[j - 1 - i]) {
                    dp[j].add("(" + k1 + ")" + k2);
                }
            }
        }
    }
    return dp[n];
}
```

* **j 等于 2 逐项对照**
    * 第一种拆分：`k1` 是 `dp[0]` 里的空字符串，`k2` 是 `dp[1]` 里的那一对圆括号。
    * 第二次拆分：`k1` 变成那一对圆括号，`k2` 变成空串。

```text
  i=0  k1=""    k2="()"   →  "(" + ""    + ")" + "()"  =  ()()    ← 并列
  i=1  k1="()"  k2=""     →  "(" + "()"  + ")" + ""    =  (())    ← 嵌套
```

    * 结果跟手工数出来的完全一致，拼好后加到 `dp[2]` 里。
* **j 等于 3 逐项对照**
    * 第一种拆分是 0 和 2：`k1` 是 `dp[0]` 的空串（就一个元素），`k2` 来自 `dp[2]`，上一轮已算出里面有两个元素。
    * 第二种拆分是 1 和 1：两个集合里各是一对括号。
    * 第三种拆分是 2 和 0：`k1` 拿走 `dp[2]` 的两个元素，`k2` 就是空串。

```text
  i=0  k1=""    k2="()()"   →  "(" + ""    + ")" + "()()"   =  ()()()   第一种
  i=0  k1=""    k2="(())"   →  "(" + ""    + ")" + "(())"   =  ()(())   第二种
  i=1  k1="()"  k2="()"     →  "(" + "()"  + ")" + "()"     =  (())()   第三种
  i=2  k1="()()" k2=""      →  "(" + "()()" + ")" + ""      =  (()())   第四种
  i=2  k1="(())" k2=""      →  "(" + "(())" + ")" + ""      =  ((()))   第五种
```

    * 五种可能都在 `dp[n]` 里，返回结果就是把 `dp[n]` 这个集合返回，打印就不要了。

### 四层 for 的性能代价

* 用动态规划的方法解决有效括号生成，外层有两个 for 循环，内层又套了两个 for 循环，四层 for 一套，性能就下去了。
* 它当然能够通过测试用例，只不过分值不高。

## 打家劫舍：又一个一维 DP

* **问题设定（力扣 198）**
    * 你是一个小偷，计划到一些房间里偷东西，每个房间都有他们各自的价值。
    * 偷的时候**不能相邻偷**，比如偷了 0 号房间就不能偷 1 号房间，只能再偷 2 号房间，相邻会触发警报。
    * 问在不触发警报的情况下，偷这些房间能偷到的最高金额是多少。
    * 它跟零一背包问题是有类似之处的。

```text
  房间编号    0     1     2     3     4
  房间价值    2     7     9     3     1
```

### 跟着五个房间往前走一遍

* **dp 的定义**：一维数组长度跟房间数目保持一致，有五个房间数组长度也是五；每个元素表示偷到第几个房间能得到的最大价值，初始偷盗价值都是零。
* **逐个房间推进**
    * 0 号房间：偷到价值 2，`dp[0] = 2`。
    * 1 号房间：与 0 号互斥，偷 1 号得 7 比偷 0 号得 2 高，`dp[1] = 7`。
    * 2 号房间：0 与 2 不相邻可以一起偷，9 + 2 = 11 高于只偷 1 号的 7，`dp[2] = 11`。
    * 3 号房间：3 加 `dp[1]` 的 7 得 10，比 `dp[2]` 的 11 低，沿用 11，`dp[3] = 11`。
    * 4 号房间：1 加 `dp[2]` 的 11 得 12，比 `dp[3]` 的 11 高，用 12 更新，`dp[4] = 12`。
    * 结论：偷到 4 号房间以后能得到的最大价值是 12。

### 那个被漏掉的 max

* **只写"倒回 i-2 加当前价值"是不完整的**
    * 以 4 号房间为例：偷到 4 就不能看 3，得倒回头去看 `dp[2]` 累积起来的价值，加上 4 号房间本身的钱，$11 + 1 = 12$。
    * 拿 `dp[3]` 检验：套刚才那个式子倒回 `dp[1]`，加上当前的价值 3 得到 $7 + 3 = 10$，这样是错的；偷 0 和 2 才是 11，走 1 和 3 这条路只能偷到 10。
    * 所以要再对比一次：上一次（2 号房间）累积起来的最大价值，跟走 `i-2` 这条线能偷到的价值，二者取一个较大值。

$$\text{dp}[i] = \max\big(\ \text{dp}[i-2] + \text{houses}[i],\ \ \text{dp}[i-1]\ \big)$$

$$\text{dp}[3] = \max(7 + 3,\ 11) = \max(10,\ 11) = 11$$

* > **易错点**：不是非要偷当前这个房间，也可能沿用上一次的最大结果；漏掉这个 `max`，整条递推就退化成贪心了。

### dp0 和 dp1 各自怎么来

* **入参与单房间特例**：方法传进来一个一维数组，索引代表房间编号，元素值代表房间能偷到的价值。
    * 房间只有一个时不需要走下面的逻辑，直接返回这个房间的价值。
* **循环下标必须从 2 开始**
    * > **易错点**：递推式里既有 `i - 2` 又有 `i - 1`，所以 `i` 不能从 0 开始，`dp[0]` 和 `dp[1]` 得提前计算好。
    * `dp[0]` 显然等于 0 号房间的偷盗价值，也就是 `houses[0]`。
    * `dp[1]` 不一定等于 `houses[1]`。例如 0 号房间能偷到的价值是 7、1 号房间只有 2，那就该放弃 1 号、回头只偷 0 号的 7。
    * 所以它是 0 和 1 里面二者找一个更大的，跟主递推式一致，只是在 `i` 等于 1 时没有 `i-2` 这一项，所以单独处理。

$$\text{dp}[1] = \max\big(\text{houses}[0],\ \text{houses}[1]\big)$$

* > **易错点**：⚠️ 直接把 `dp[1]` 取成 `houses[1]` 是错的，必须先跟 `houses[0]` 比一比。

### 把递推式写成代码

```java
public int rob(int[] houses) {
    // 这里很多地方都出现了 length，抽取成一个局部变量
    int len = houses.length;

    // 只有一个房间，偷了这个房间就完事，不用往下走
    if (len == 1) {
        return houses[0];
    }

    int[] dp = new int[len];
    dp[0] = houses[0];
    // 注意：不是直接取 houses[1]，而是要跟 houses[0] 比一比
    dp[1] = Math.max(houses[0], houses[1]);

    for (int i = 2; i < len; i++) {
        // 当前房间的价值从 houses[i] 来
        dp[i] = Math.max(dp[i - 2] + houses[i], dp[i - 1]);
    }

    // 返回整个一维数组的最后一项
    return dp[len - 1];
}
```

* 调 `Math.max` 时当前房间的价值从 `houses[i]` 来；最后返回整个一维数组的最后一项 `dp[houses.length - 1]`。
* 用 `2 7 9 3 1` 这个测试数据，结果就是 12。

## 旅行商问题：先跟最短路径划清界限

* **问题设定**：城市到城市之间都需要一定的花费，比如北京到上海 1000 块、上海到西安 6000 块、西安到武汉 5000 块。
    * 你是一个旅行商人，要到这几个城市去售卖商品，要求不管从哪个城市出发，这几个城市都必须经历一遍，哪条路线花费最少。
    * 花费最少的一条是从北京出发，先到上海，再到武汉，再经过西安，最后回北京，花费是 1 + 4 + 5 + 2 = 1 万 2。

### 四座城市，六条路线

* **起点与约束**：城市之间都是连通的，从哪个城市作为起点出发都可以；就以北京为起点，接下来的选择一共三种，可以先到上海、先到武汉、先到西安。
    * 不能从上海还没逛完其他城市就先回北京；就算提前回去了，也必须让上海把剩下两个城市逛完，最后再回北京。
    * 到上海之后剩给它选择的只有武汉和西安两个城市，各有两种走法；北京到武汉这条线、到西安这条线，分析过程完全类似。

```text
  北京
   ├─ 上海 ─┬─ 武汉 ─┬─ 西安 ─┬─ 回北京
   │        └─ 西安 ─┴─ 武汉 ─┴─ 回北京
   ├─ 武汉 ─┬─ 上海 ─┬─ 西安 ─┬─ 回北京
   │        └─ 西安 ─┴─ 上海 ─┴─ 回北京
   └─ 西安 ─┬─ 上海 ─┬─ 武汉 ─┬─ 回北京
            └─ 武汉 ─┴─ 上海 ─┴─ 回北京
```

* **路线总数**：北京起步有 3 个选择，每个中途落地的城市再各自有 2 个选择，第二个分支走完之后只剩一个城市可去、然后直接回北京，四个城市共 $3 \times 2 = 6$ 种可能路线。

### 与最短路径问题的界限

* **最短路径问题**：说两个城市之间怎么走、距离最短，比如上海直接到西安花费是 6，上海经过武汉到西安花费是 4 + 5，上海经北京再到西安则花费是 3。
    * 最短路径问题**不要求经过每个城市**。
    * 旅行商问题要求所有城市都必须经过，求的是花费最少的路线，两者不能混淆。

### 阶乘级的增长与现实做法

* **路线总数等于城市个数减一的阶乘 $(n-1)!$**
    * 五个城市：$4 \times 3 \times 2 = 24$ 种。
    * 六个城市：$5 \times 4 \times 3 \times 2 = 120$ 种。
* **时间复杂度非常高**，针对旅行商问题一般没有一个特别好的解决办法，只能通过一些近似解去加快运行速度。
    * 四五个城市这样数据量比较少时，可以用动态规划对它做一些优化。
    * 更大的城市数据量只能求近似解，求不出最优解。
