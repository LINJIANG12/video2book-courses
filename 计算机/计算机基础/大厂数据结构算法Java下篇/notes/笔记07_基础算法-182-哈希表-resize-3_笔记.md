# 基础算法-182-哈希表-resize-3

## 链表拆分循环的收尾动作

* **先接链再移尾**

    * 循环处理当前节点 p 时的动作顺序是：先接链，再移尾。
    * 先判断 a 当前指向的元素不为 null，把它的 next 指向当前节点 p，然后才让 a 等于 p。
    * b 链表的做法完全对称：b 指向的元素不为 null 就让 b.next = p，然后 b = p。

    ```java
    // a 当前指向的元素不为 null，就把它的 next 指向当前节点 p
    if (a != null) {
        a.next = p;
    }
    a = p;   // next 改对了，a 才往前走
    ```

    * > **易错点**：这两段代码看着重复，本质只有「先接链、再移尾」这一个动作，交换一下顺序链表就断了。

* **正循环结束后补尾巴置空**

    * 循环结束后两条新链表虽然各自串起来了，但末尾还留着旧链表的影子，这部分必须收尾。
    * 48 这个节点在整个循环过程中压根没被碰过 next，它原本就指向 null，现在仍然指向 null，没有问题。
    * 另一条链表的最后一个元素不一样，它的 next 原来还指着旧链表里的 48，必须改成 null，否则等于把已经拆散的旧链重新串回去。

    ```java
    if (a != null) {
        a.next = null;   // 让 a 当前的最后一个元素指向 null
    }
    if (b != null) {
        b.next = null;   // 同样的操作，b 这边完全对称
    }
    ```

    * > **易错点**：b 不为空这个判断不能省，b 这条链表有可能一个元素都没分到，a 同理；省掉就会把空链表解引用。

* **用两个变量专门记新链表的头**

    * 循环结束时 a 和 b 两个指针停在各自链表的尾巴上，但真正要的是头——链表要塞进新数组的某个索引位置里，塞头有意义，存尾巴没有意义。
    * 因此额外准备 aHead 与 bHead 两个变量，初始均为 null，分别记录拆分之后 a 链表和 b 链表的头指针。
    * 赋值时机在循环内第一次往某条链表添加元素时，判断方式就是该链表的尾指针还等于 null。
    * a 等于 null 说明 a 链表里还没有任何元素，就把当前的 p 记到 aHead；b 等于 null 时同样把 p 记到 bHead。

    ```java
    Node aHead = null;   // a 这个链表的头指针
    Node bHead = null;   // b 这个链表的头指针
    ```

## 拆分后链表在新数组中的索引位置

* **两条新链表各占一段**

    * a 链表保持它原来的索引位置不变。
    * b 链表的索引位置是在原来索引的基础上加上旧数组的长度，也就是旧 table 的 length。
    * 旧数组里索引位置为 0 的链表拆成 a 和 b 后，a 仍在索引 0，b 去 0 + 8 = 8。
    * 旧数组里索引位置为 1 的链表拆成 a 和 b 后，a 仍是索引 1，b 去 1 + 8 = 9。

    ```text
    old index i  ----+------>  new index i            (chain a, index unchanged)
                     |
                     +------>  new index i + L        (chain b, L = old table length)
    ```

    * 读图：旧数组里索引 i 的链表拆开后，a 挂回 i 这个原位，b 挂到 i + L 这一段；L 就是旧数组长度，新数组容量翻倍，索引恰好从 L 开始是新增加的那半段。

    ```java
    table[i] = aHead;                    // a 链表：索引位置不变
    table[i + oldTable.length] = bHead;  // b 链表：原索引 + 旧数组长度
    ```

* **resize 的完整步骤**

    * 先创建一个容量翻倍的新数组。
    * 遍历旧数组，把它的每一条链表拿出来进行拆分。
    * 拆分的具体逻辑是拆成 a 和 b 两条链表，并把它们各自的头指针都记录下来。
    * 拆完以后把头指针放进新数组的相应索引：a 链表索引位置不变，b 链表放在 i 加旧数组长度的位置。

## 三条规律成立的共同前提

* **数组长度必须是 2 的 n 次方**

    * > **定义**：哈希表的数组长度必须是 2 的 n 次方。
    * 按位与代替求模、拆分依据是与旧数组长度按位与是否为零、拆分后一条原地不动一条加旧数组长度，这几条规律全部以此为前提。
    * > **注意**：没有这个前提，这几条规律一条都不成立。

## 按位与代替求模

* **等价式**

    * > **定义**：$$hash \mathbin{\&} (length - 1) \;=\; hash \bmod length \qquad (length = 2^n)$$
    * 两个式子最终运算的结果一样，前提是数组长度必须是 2 的 n 次方。
    * 求模式子好理解，它就代表哈希值除以数组长度后看余数；按位与式子抽象，但它同样是在求余数。

* **十进制里的求余规律**

    * 除以 10 求余数不用看高位，只要看最后一位；除以 100 只要看后两位；除以 1000 只要看后三位。
    * **十进制求余规律**：除以 10、100、1000 这类 10 的 n 次方数字求余数，只需要看被除数的后一位、后两位、后三位，更高的位因为都被整除掉了，不需要考虑。

* **二进制里是完全一样的规律**

    * 二进制下除以 2 的 n 次方，余数就是被除数二进制末尾那 n 位。
    * 以 30 为例：30 的二进制是 11110，2、4、8、16、32 的二进制分别是 10、100、1000、10000、100000。
    * 除以 2 只看后一位是 0，余数 0；除以 4 看后两位是 10，余数 2；除以 8 看后三位是 110，余数 6；除以 16 看后四位是 1110，余数 14。

    ```text
    30        =   11110
    30 % 2    =       0     <- keep the last 1 bit   (mask  1 = 00001)
    30 % 4    =      10     <- keep the last 2 bits  (mask  3 = 00011)
    30 % 8    =     110     <- keep the last 3 bits  (mask  7 = 00111)
    30 % 16   =    1110     <- keep the last 4 bits  (mask 15 = 01111)
    ```

* **用按位与把「后几位」留下来**

    * 任何一个数跟 0 做按位与，结果还是 0，实现清零效果。
    * 任何一个数跟 1 做按位与，都能保留这个数原来的值：1 与 1 还是 1，0 与 1 可以看成保留了原来的 0。
    * 想保留后三位，就找一个前面补零、末尾三位全为 1 的数做掩码：高位与 30 的高位按位与被清零，末尾三个 1 把原来的 110 保留下来。
    * 掩码是前面补零、末尾三位为一的数，按位与之后高位全被清成 0，只留下末尾三位 110。
    * 30 与掩码 7（二进制 00111）做按位与得到 00110，换算成十进制是 6，正好等于 30 % 8。

    ```text
    30        =   11110
    mask 7    =   00111
    AND       =   00110     <- low 3 bits kept, everything above cleared
    ```

* **掩码正好是数组长度减一**

    * 保留后一位的掩码是 1，保留后两位的掩码是 3，保留后三位的是 7，保留后四位的是 15。
    * 这些数正好等于对应数组长度减一：2 - 1 = 1，4 - 1 = 3，8 - 1 = 7，16 - 1 = 15，它们的共同特点是末几位分别都是 1。
    * 数组长度减一的作用就是找出 1、3、7、15 这些掩码，跟原始哈希值按位与以保留后几位，而这个后几位换算成十进制就是最终要找的余数。

| 想保留的位数 | 掩码二进制 | 掩码十进制 | 对应的数组长度 |
| :--- | :--- | :--- | :--- |
| 后 1 位 | 0001 | 1 | 2 |
| 后 2 位 | 0011 | 3 | 4 |
| 后 3 位 | 0111 | 7 | 8 |
| 后 4 位 | 1111 | 15 | 16 |

* **按位与求余的结论**

    * > **注意**：只要数组长度是 2 的 n 次方，`hash & (length - 1)` 就是在求 `hash % length`；因为 `length - 1` 的二进制末尾 n 位全是 1，按位与恰好把哈希值的后 n 位留下来，而那正是余数。

## 拆分链表依据与旧长度的关系

* **后三位与后四位决定索引变不变**

    * 把数字往大小为 8 的数组里放时索引看后三位，后三位就是余数。
    * 后三位相同的数字会被串到同一条链表：0 与 8 的后三位都是 000，串到索引 0；1 与 9 都是 001，串到索引 1；2 与 10 都是 010，串成一条链表。
    * 扩容时容量在 8 的基础上翻倍变成 16，索引重算，此时看后四位。
    * 后三位和后四位取值相同的数字扩容后位置不变，因为后三位看成余数与后四位看成余数相同，说明扩容前后没有变化。

| 数字 | 二进制 | 看后三位（长度 8） | 看后四位（长度 16） | 扩容前索引 | 扩容后索引 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 0 | 0000 | 000 | 0000 | 0 | 0 |
| 1 | 0001 | 001 | 0001 | 1 | 1 |
| 2 | 0010 | 010 | 0010 | 2 | 2 |
| 3 | 0011 | 011 | 0011 | 3 | 3 |
| 4 | 0100 | 100 | 0100 | 4 | 4 |
| 5 | 0101 | 101 | 0101 | 5 | 5 |
| 6 | 0110 | 110 | 0110 | 6 | 6 |
| 7 | 0111 | 111 | 0111 | 7 | 7 |
| 8 | 1000 | 000 | 1000 | 0 | 8 |
| 9 | 1001 | 001 | 1001 | 1 | 9 |
| 10 | 1010 | 010 | 1010 | 2 | 10 |
| 11 | 1011 | 011 | 1011 | 3 | 11 |
| 12 | 1100 | 100 | 1100 | 4 | 12 |
| 13 | 1101 | 101 | 1101 | 5 | 13 |
| 14 | 1110 | 110 | 1110 | 6 | 14 |
| 15 | 1111 | 111 | 1111 | 7 | 15 |

* **拆分依据就是倒数第四位**

    * 读表：0 到 7 这几行倒数第四位都是 0，扩容前后取值相同，索引原封不动；8 到 15 这几行倒数第四位是 1，新索引恰好等于原索引加上 8。
    * 0 到 7 的高位都是 0，倒数第四位为 0，数字本身没变，索引也不会变；8 到 15 的倒数第四位是 1，索引必然变化。
    * 倒数第四位出现 1 的元素拆分时应被分到另一条链表；倒数第四位为 0 的相当于不用动，保持原索引位置不变。

* **旧数组长度为什么正好卡在这一位**

    * 旧数组长度这个 2 的 n 次方，二进制里有且只有一个 1，位置恰好就在要检查的那一位上。
    * 旧长度 8 换算成二进制是 1000，倒数第四位是 1、其余为零；旧长度 16 是 10000，要检查的就变成倒数第五位。
    * 哈希值跟它做按位与，结果就只剩下了这一个比特。

    ```text
    old length 8   = 1000      -> the 4th bit from the right is what we check
    old length 16  = 10000     -> then it becomes the 5th bit from the right

    8 & 0  = 0     8 & 1  = 0     8 & 2  = 0    ...  8 & 7  = 0
    8 & 8  = 8     8 & 9  = 8     8 & 10 = 8    ...  8 & 15 = 8
    ```

    * 第一行结果全为 0，说明这些数字的倒数第四位是 0，扩容后索引不变，拆到同一条链表里去。
    * 第二行结果全为 8，说明这些数字的倒数第四位是 1，扩容后索引要变化，划到另一组。
    * > **注意**：这就是 `(hash & oldLen) == 0` 这个判断式的全部含义。

## 两条新链表索引分配的依据

* **倒数第 n+1 位为 0 的一组原地不动**

    * 扩容之前看后三位得到当时索引，扩容之后看后四位。
    * 倒数第四位为零的元素，扩容前后后三位与后四位取值相同，索引位置不会变。
    * 原来索引是 0 的仍然是 0，原索引是 1 的仍然是 1，原索引是 2 的仍然是 2，全部保持原位。

* **倒数第 n+1 位为 1 的一组加上旧数组长度**

    * 从 8 到 15 这些元素后三位和后四位不一样，索引要加上前面那个 1 对应的十进制值。
    * 8 扩容前看后三位索引是 0，扩容后加上前面的 8，变成 8；9 扩容前看后三位是 1，加上 8 变成 9。
    * 加的这个 8 就是旧数组长度。

* **索引分配结论**

    * > **注意**：倒数第 n+1 位为 0 的元素拆分后保持原索引 i 不变；倒数第 n+1 位为 1 的元素新索引 = 原索引 + $2^n$，而 $2^n$ 正好就是旧数组的长度。

## 哈希算法与哈希码

* **哈希码不该由调用方手动提供**

    * 实现的 get、put 以及 remove 方法都需要提供哈希码这个参数。
    * 哈希码作为参数传入，意味着调用这些方法时要手动提供它。
    * 由调用方提供很难保证哈希码不冲突，最好有一种算法能帮我们生成不冲突或者很少冲突的哈希码。

* **哈希算法的定义**

    * > **定义**：哈希算法是一种将任意长度的数据通过这个算法变成固定长度数据的过程，最终得到的这个结果值称为哈希值。
    * 原始数据的长度可能很大，好几百兆，经过哈希算法后变成固定长度大小的数据，比如变成 16 个字节、128 位。
    * > **定义**：哈希算法就是将任意的对象给它分配一个编号的过程，只不过这个编号是一个有限范围内的数字，比如在 int 这个范围内。

* **常见的哈希算法**

    * MD5、SHA-1、SHA-256、SHA-512、CRC32 等等，此外还有更多的哈希算法。

* **为什么做不到绝对唯一**

    * 哈希值要尽可能分布得比较均匀，最好能唯一，但这是一种理想情况。
    * 最终分配的哈希值是有限范围内的数字，如果将来的对象数量超过了 int 的范围，肯定会有冲突、会有重复。
    * 只能尽量让产生的编号比较唯一、比较均匀，不能完全避免冲突。

## 哈希算法的两个同义词

* **摘要算法**

    * 哈希算法、摘要算法、散列算法这三个词在表达类似的事情。
    * 这些算法计算哈希值时都会考虑原始数据的每一个字节，原始数据只要改动其中任意一个字节，最终得到的哈希值也会有明显的不同。
    * 产生的哈希值能在一定程度上代表原始数据，摘取了原始数据的一些特征要点，因此也称之为摘要算法。

* **散列算法**

    * 哈希算法就是把任意长度的数据变成固定长度数据的过程，比如变成 int 范围内 32 位的过程。
    * 原数据不管多大，最终都要映射到 int 的 32 个格子里，一个格子一个格子地放进去。
    * 这个过程形象地称之为散列——打散了放到这 32 个格子里，最后组成一个数字，因此也叫散列算法。
