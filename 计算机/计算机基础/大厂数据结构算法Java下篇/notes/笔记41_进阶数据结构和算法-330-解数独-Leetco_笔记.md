# 进阶数据结构和算法-330-解数独-Leetco

## 初始化冲突表

* **冲突表三数组（row / col / box）**

    * > **定义**：把棋盘上已填数字造成的行、列、九宫格占用状态固化成三张布尔表，之后每次落笔只是一次查表，不必再回到棋盘重扫。

    * `row[i][x]` 为 `true` 表示第 `i` 行里数字 `x+1` 已被占用；`col[j][x]` 是第 `j` 列；`box[k][x]` 是第 `k` 个九宫格。

    * 类型是 `boolean[][]`，作为参数在递归中一路下传，不是成员变量。

    * 初始化时机：开始填空之前，用原始棋盘 `table` 扫一遍完成。

* **初始化扫描（initConflict）**

    * 双重循环，`i` 扫行 0 到 8，`j` 扫列 0 到 8，取字符 `ch = table[i][j]`。

    * `ch == '.'` 说明该格还没填，没有冲突可记，直接 `continue` 跳过。

    * 只有 `ch` 不是点时才记录，即「初始化冲突状态」。

    ```java
    private void initConflict(char[][] table) {
        for (int i = 0; i < 9; i++) {
            for (int j = 0; j < 9; j++) {
                char ch = table[i][j];
                if (ch == '.') {
                    continue;   // 还是空格，没有冲突可记
                }
                row[i][ch - '1'] = true;
                col[j][ch - '1'] = true;
                box[i / 3 * 3 + j / 3][ch - '1'] = true;
            }
        }
    }
    ```

* **九宫格编号公式**

    * > **定义**：把 9×9 棋盘切成 3×3 个九宫格后，按行优先给出的 0 到 8 编号。

    * 公式：`k = i / 3 * 3 + j / 3`。

    * 验算：单元格 `(i = 0, j = 2)` → `0 / 3 * 3 + 2 / 3 = 0 + 0 = 0`，落在第 0 个九宫格。

    * 九宫格内部同样有九个数字，第二维下标与行列的对应关系一模一样，不用另算。

* **字符与数字的互转**

    * > **定义**：数字从 1 开始、数组索引从 0 开始，两者正好差一个字符 `'1'`。

    * 字符转索引：`ch - '1'`，字符 `'5'` 落到索引 `4`。

    * 索引转字符反向操作：往格子里填 `1` 时用 `(char)(1 + '0')` 变回字符 `'1'`。

    * 口诀是「字符转数字减一，数字转字符加零」，这段代码里来回使用。

    * > **易错点**：差值就是 `'1'` 这一个字符，写成 `- '0'` 会整体偏移一位。

## dfs 填空回溯

* **dfs 方法签名（Depth First Search，DFS）**

    * `private boolean dfs(char[][] table, int i, int j, boolean[][] row, boolean[][] col, boolean[][] box)`。

    * 五个参数：原始棋盘 `table`、行坐标 `i`、列坐标 `j`，加上三张冲突表。

    * 返回值语义：所有空格都填满返回 `true`（找到解）；九个数字全试完仍不成返回 `false`。

    * 首次调用行列都传零，从第 0 行第 0 列开始处理。

* **while 定位下一个空格**

    * 循环条件 `while (i < 9 && j < 9 && table[i][j] != '.')`，字符不是点就说明该格已填，`j++` 继续向右找。

    * 先 `j++` 再判越界：`j >= 9` 说明本行的空格已找完，令 `j = 0`、`i++` 换下一行。

    * `i >= 9` 说明所有行都处理完，相当于已找到解，直接 `return true`。

    * 退出 while 时手上的 `(i, j)` 就是第一个真正的空格，下面交给填空逻辑。

    * > **易错点**：每次自增都得先想越界——如果先判断再自增，走到行末尾会漏掉换行；正确顺序是 `j++` 之后判断 `j >= 9`。

* **落笔门禁与冲突更新**

    * 循环变量 `x` 从 1 到小于等于 9，逐一尝试。

    * `k = i / 3 * 3 + j / 3` 先算出来放在循环外，后面反复用。

    * 落笔前的门禁是查表：`if (row[i][x - 1] || col[j][x - 1] || box[k][x - 1]) continue;`，有冲突就跳过这一轮去试下一个数字。

    * 填入 `table[i][j] = (char) (x + '0')`；`x + '0'` 的结果仍是 int，必须强转 `(char)` 才变成字符。

    * 填完立刻更新三张表：`row[i][x - 1] = true; col[j][x - 1] = true; box[k][x - 1] = true;`

    * > **易错点**：三个下标里只有 `box` 的第一维是算出来的（`i / 3 * 3 + j / 3`），另两维直接用 `i` 和 `j`；三者的第二维全都是 `x - 1`。九宫格「是第几个」要算，九宫格里「是第几个数字」不用算。

* **递归下传与回溯撤销**

    * `if (dfs(table, i, j, row, col, box)) return true;`，`i`、`j` 原样传下去，因为递归入口还会再做一次找空格的检查，调用处不必额外处理。

    * 递归返回 `false` 表示这条路填错了，循环继续试下一个数字。

    * 回溯四步：格子恢复成空格 `table[i][j] = '.'`，三张表的对应格全部撤销 `row[i][x - 1] = false`、`col[j][x - 1] = false`、`box[k][x - 1] = false`。

    * 九个数字全部尝试失败后返回 `false`。

    ```java
    private boolean dfs(char[][] table, int i, int j,
                         boolean[][] row, boolean[][] col, boolean[][] box) {
        while (i < 9 && j < 9 && table[i][j] != '.') {
            j++;
            if (j >= 9) { j = 0; i++; }
        }
        if (i >= 9) {
            return true;   // 没有空格了，找到一个完整的解
        }

        int k = i / 3 * 3 + j / 3;   // 先算出第几个九宫格，后面反复用

        for (int x = 1; x <= 9; x++) {
            if (row[i][x - 1] || col[j][x - 1] || box[k][x - 1]) {
                continue;          // 有冲突，跳过这一轮
            }

            table[i][j] = (char) (x + '0');
            row[i][x - 1] = true;
            col[j][x - 1] = true;
            box[k][x - 1] = true;

            if (dfs(table, i, j, row, col, box)) {
                return true;
            }

            // 回溯：格子恢复空格，三张表这一格全部撤销
            table[i][j] = '.';
            row[i][x - 1] = false;
            col[j][x - 1] = false;
            box[k][x - 1] = false;
        }
        return false;
    }
    ```

* **求得的解**

    * 行行填满、列列不冲突、九宫格也干净，就是一个完整解，由 `i >= 9` 分支返回 `true` 标记。

    ```text
    5 3 4 | 6 7 8 | 9 1 2
    6 7 2 | 1 9 5 | 3 4 8
    1 9 8 | 3 4 2 | 5 6 7
    -----------------------
    8 5 9 | 7 6 1 | 4 2 3
    4 2 6 | 8 5 3 | 7 9 1
    7 1 3 | 9 2 4 | 8 5 6
    -----------------------
    9 6 1 | 5 3 7 | 2 8 4
    2 8 7 | 4 1 9 | 6 3 5
    3 4 5 | 2 8 6 | 1 7 9
    ```

## 两数之和 II 与力扣 1 的差别

* **两数之和 II（力扣 167）**

    * > **定义**：给一个升序数组和一个 `target`，返回数组内两个数字之和等于 `target` 的那两个下标。

    * 例：数组 `2、7、11、15`，`target = 9`，答案是 `2` 和 `7`，返回的是索引值。

    * 硬性约束：所设计的方案必须使用常量级的额外空间，即空间复杂度 $O(1)$。

* **有无序决定用哪种数据结构**

    * 力扣 1 不声明数组有序，用哈希 map：遍历时把数字放进 map，再拿另一个数字 `y` 去查是否凑成 `target`，找到就返回，只要遍历一遍。

    * 力扣 1 最坏情况下 map 里会放 $N - 1$ 个数字，空间复杂度仍是 $O(N)$，不满足 167 的 $O(1)$ 要求。

    * > **结论**：无序就得靠哈希表把「找过没有」变成 $O(1)$；有序则可以靠单调性——和大了缩右端、和小了推左端——用两个下标把空间压到 $O(1)$。

| | 力扣 1（两数之和） | 力扣 167（两数之和 II） |
| --- | :--- | :--- |
| 数组是否有序 | 不一定有序 | 明确升序 |
| 解的数量 | 题目保证只有一组答案 | 只有一组答案 |
| 额外空间限制 | 无 | 必须 $O(1)$ |
| 常用思路 | 哈希表，$O(N)$ | 双指针，$O(1)$ 空间 |

## 双指针收缩

* **双指针收缩规则**

    * 初始化 `i = 0` 指向左侧最小的数字，`j = numbers.length - 1` 指向右侧最大的数字。

    * 循环条件 `i < j`，表示两指针尚未相遇，继续查找。

    * `sum = numbers[i] + numbers[j]`：`sum < target` 令 `i++` 向右找更大的数字让和增大；`sum > target` 令 `j--` 向左找更小的数字让和减小；`sum == target` 则 `break` 退出循环。

    * 走位示例（数组 `2 7 11 15`，`target = 9`）：`2 + 15 = 17 > 9` 令 `j--`；`2 + 11 = 13 > 9` 令 `j--`；`2 + 7 = 9` 命中。

    * 返回 `new int[]{i + 1, j + 1}`。

    * > **易错点**：最后一行最容易忘——代码里的下标从 0 开始，题目要的答案从 1 开始，返回前 `i` 和 `j` 都要加一。测试数据 `[2, 7, 11, 15]`、`target = 9` 时代码里找到的是 `i = 0, j = 1`，应返回 `[1, 2]`。

    ```java
    public int[] twoSum(int[] numbers, int target) {
        int i = 0;
        int j = numbers.length - 1;

        while (i < j) {
            int sum = numbers[i] + numbers[j];
            if (sum < target) {
                i++;            // 和太小，往右找一个更大的
            } else if (sum > target) {
                j--;            // 和太大，往左找一个更小的
            } else {
                break;          // 找到了
            }
        }

        // 题目要求索引从 1 开始，所以 i 和 j 都要加一
        return new int[]{i + 1, j + 1};
    }
    ```

## 三数之和的降维递归

* **三数之和（力扣 15）**

    * > **定义**：从一个数组里挑三个数字使和等于 0，返回所有不重复的组合。

    * 相当于把 `target` 固定成 0。

    * 答案要求去重，例如 `-1、0、1` 组合过之后，第二个 `-1` 不能再与 `0`、`1` 组合。

    * 解法是降维递归加双指针，时间复杂度 $O(N^2)$。

* **与力扣 167、力扣 40 的差别**

    * 与 167 的差别最大：167 明确只有一组答案，找到即可结束；三数之和可能有多个答案，必须全部找出来，并且要考虑去重。

    * 与 40 题「组合总和 II」思路接近但目标不同：40 题只要能凑成 `target` 就算数，比如和为 8 的 `1+1+6`、`1+2+5`、`1+7`、`2+6`，两数、三数都算；三数之和只取恰好三个数且和为 0 的组合。

    * 解法差别：40 题用回溯枚举，时间复杂度 $O(N \cdot 2^N)$；三数之和因为递归次数被限制成只有三层，总时间只有 $O(N^2)$。

| | 三数之和（力扣 15） | 组合总和 II（力扣 40） |
| --- | :--- | :--- |
| 选几个数 | 固定三个 | 不限，两数、三数、四数都算 |
| 和是多少 | 固定为 0 | 题目给的 target |
| 答案是否去重 | 必须去重 | 必须去重 |
| 讲过的思路 | 降维递归 + 双指针 | 回溯枚举 |
| 时间复杂度 | $O(N^2)$ | $O(N \cdot 2^N)$ |

* **降维链条**

    * > **结论**：固定其中一个数字，剩下的两数之和就等于 `0 - numbers[k] = -numbers[k]`，三数之和被降成两数之和，直接套 167 的双指针即可。

    * 例子：数组排序后先固定最小的 `-4`，三数和为 0 意味着剩下两数之和要为 `4`；但剩下最大的两个加起来也只有 3，固定 `-4` 无解；换固定 `-1` 时 target 变成 `1`，`-1 + 0 + 1` 命中。

    * 固定 `-1` 后 `i++`、`j--` 又找到一组，两指针相遇就停；再固定 `0` 时剩余两数至少是 3，凑不出 0 失败；固定 `1` 时剩余数字不够两个，同样不再尝试。

    * 推广到四数之和：先固定一个降成三数之和，递归里再固定一个，剩下的两个继续套两数之和。

    ```text
       三数之和 = 0
            │
            └─ 循环固定一个 numbers[k]（从左往右）
                 │
                 └─ 剩下的两数之和 = 0 - numbers[k] = -numbers[k]
                      │
                      └─ 套 167 的双指针，区间收窄成 [k+1, j]
                           │
                           ├─ 找到 → stack 的固定值 + numbers[i] + numbers[j]
                           │         凑成一组解塞进 result，再 i++、j-- 继续缩小
                           │
                           └─ 本轮没找到 → stack.pop() 回溯，换下一个固定值

       n == 2  →  落到两数之和，直接求解并 return，不再往下递归
       n >  2  →  固定一个数字，n 减一，继续递归
    ```

* **降维递归的参数设计**

    * 签名：`private void dfs(int n, int i, int j, int target, int[] numbers, LinkedList<Integer> stack, List<List<Integer>> result)`。

    * `n` 是剩余待凑的个数，初值 3，每固定一个数就减一，减到 2 时套两数之和并 `return`。

    * `i`、`j` 是剩余数字可用区间的起止索引，`target` 是本轮两数要凑出的和，`numbers` 是原始数组。

    * `stack` 是 `LinkedList<Integer>`，用 `push`、`pop` 暂存每一层已固定的数字；选 `LinkedList` 是因为 `push` 用起来方便。

    * `result` 是 `List<List<Integer>>`，收集所有解，创建在外面再传进去。

    * 循环 `for (int k = i; k < j; k++)` 从左边界 `i` 开始：先 `stack.push(numbers[k])` 固定，再递归，本轮的 `target` 是**本次的 target 减去固定的数字**，区间收窄成 `[k + 1, j]`，个数变成 `n - 1`。

    * 本轮没找到解就 `stack.pop()` 取消固定，换下一个数字。

    * 原始数组必须先 `Arrays.sort` 排序：双指针要求有序，去重也依赖有序。

    ```java
    private void dfs(int n, int i, int j, int target, int[] numbers,
                     LinkedList<Integer> stack, List<List<Integer>> result) {
        // 只剩两个数字了，直接套两数之和
        if (n == 2) {
            twoSum(numbers, i, j, target, stack, result);
            return;
        }

        // 从左往右逐一固定一个数字
        for (int k = i; k < j; k++) {
            // 固定值去重：当前数字和左边那个一样，就没必要再固定一次
            if (k > i && numbers[k] == numbers[k - 1]) {
                continue;
            }

            stack.push(numbers[k]);

            // 固定一个之后：个数 n-1，区间收窄成 [k+1, j]，target 减去固定值
            dfs(n - 1, k + 1, j, target - numbers[k], numbers, stack, result);

            // 本轮没找到解，取消固定，换下一个数字
            stack.pop();
        }
    }
    ```

* **固定值去重**

    * 判定式 `if (k > i && numbers[k] == numbers[k - 1]) continue;`。

    * 当前数字与左边一个相同，说明再固定一次产出的解组合会重复，直接跳过，连 `push` 和递归都不执行。

    * > **易错点**：`k` 与 `i` 都可能从 0 开始，`k - 1` 会越界，所以条件里必须带 `k > i`。第一个数字不需要检查重复，只有从第二个数字起才需要检查。

## 搬过来的双指针

* **相对 167 的两处改动**

    * 第一处改动：`i`、`j` 在 167 里是从 0 到数组长度减一写死的，递归中它们随层变化，所以改成方法的入参。

    * 第二处改动：167 靠返回值把答案交出去，这里是要把结果写进 `result`，不再需要返回值，最后的 `return` 也不需要；因此把 `stack` 与 `result` 两个参数一并搬过来。

    * 签名变成 `private void twoSum(int[] numbers, int i, int j, int target, LinkedList<Integer> stack, List<List<Integer>> result)`。

    * 收缩逻辑不变：循环条件仍是 `i < j`，`sum < target` 令 `i++`，`sum > target` 令 `j--`。

    * 命中解时 `new` 一个 `ArrayList` 作为 `cur`，`cur.addAll(stack)` 把上几层固定的数字带进来，再 `cur.add(numbers[i])` 与 `cur.add(numbers[j])`，最后 `result.add(cur)`。

* **找到解之后不能 break**

    * 167 题目保证只有一组答案，命中即 `break`；三数之和可能有多组解，命中后不能立刻退出。

    * 命中后改成 `i++; j--;` 两边同时缩，继续在更小的区间里找。

    * 例子中固定 `-1` 后先后找到两组三数和为 0 的解，如果沿用 `break` 就只会输出一组。

* **解内去重**

    * 只缩区间还不够：多加入一个 `0` 和一个 `1` 后，程序会输出两组相同的 `-1, 0, 1`。

    * `i` 向右移动时与左边的 `i - 1` 比较，相等就继续 `i++`：`while (i < j && numbers[i] == numbers[i - 1]) i++;`

    * `j` 向左移动时与右边的 `j + 1` 比较，相等就继续 `j--`：`while (i < j && numbers[j] == numbers[j + 1]) j--;`

    * > **易错点**：两段 `while` 的方向相反——`i` 往右走就跟它左边（`i - 1`）比，`j` 往左走就跟它右边（`j + 1`）比。方向搞反，判断的就不是刚走过的那一段，去重完全不生效。

    ```java
    // 把 167 的双指针搬过来：i、j 变成入参，返回值改成往集合里塞
    private void twoSum(int[] numbers, int i, int j, int target,
                        LinkedList<Integer> stack, List<List<Integer>> result) {
        while (i < j) {
            int sum = numbers[i] + numbers[j];
            if (sum == target) {
                List<Integer> cur = new ArrayList<>();
                cur.addAll(stack);        // 上几层固定下来的数字
                cur.add(numbers[i]);
                cur.add(numbers[j]);
                result.add(cur);

                // 167 里这里是 break，但这里不能停，可能还有别的解：
                // 两边同时缩，继续在更小的区间里找
                i++;
                j--;

                // 继续跨过重复值，避免同一组解被收了好几遍
                while (i < j && numbers[i] == numbers[i - 1]) {
                    i++;
                }
                while (i < j && numbers[j] == numbers[j + 1]) {
                    j--;
                }
            } else if (sum < target) {
                i++;                       // 和太小，往右找一个更大的
            } else {
                j--;                       // 和太大，往左找一个更小的
            }
        }
    }
    ```

* **入口调用**

    * `Arrays.sort(numbers)` 是前提：双指针要求有序，去重也靠有序。

    * `List<List<Integer>> result = new ArrayList<>();` 建在外部再传进 `dfs`。

    * 首次调用 `dfs(3, 0, numbers.length - 1, 0, numbers, new LinkedList<>(), result)`：`n = 3` 表示求三数之和，`i` 从最左边开始，`j` 是数组长度减一，`target` 固定为 0。

    * 最后返回 `result`。

    ```java
    public List<List<Integer>> threeSum(int[] numbers) {
        // 排序是前提：双指针要求有序，去重也靠有序
        Arrays.sort(numbers);

        List<List<Integer>> result = new ArrayList<>();
        // n=3 表示求三数之和，target 固定为 0
        dfs(3, 0, numbers.length - 1, 0, numbers, new LinkedList<>(), result);

        return result;
    }
    ```

## 性能实测

* **递归计数与耗时观测**

    * 用一个全局计数器 `public static int count = 0;`，每次递归调用时 `count++`，最后打印 `count` 和整个方法的耗时。

    * 测试数据量取 575 个数字，降维递归加双指针的递归次数为 569 次，耗时 16ms。

    * 递归次数比数据量还少，是因为重复的值在循环里被直接跳过去了，并没有真正递归下去。

* **与力扣 40 的回溯思路对比**

    * 改编点只有一处：用回溯求三数之和时，要检查 `stack.size()` 等于 3 才把这一组加进最终解集合，不是三个的直接排除。

    * 相同数据量 575、相同测试数据下，回溯思路的递归次数达到千万级，耗时 449ms。

| 解法 | 数组数据量 | 递归次数 | 耗时 |
| --- | :--- | :--- | :--- |
| 降维递归 + 双指针 | 575 | 569 次 | 16ms |
| 力扣 40 的回溯思路 | 575 | 千万级 | 449ms |

* **差距来自搜索空间**

    * 两种解法都能得到正确的解，差的不是技巧，而是有没有把搜索空间掐小。

    * 回溯在整个数组上枚举所有组合，代价是 $O(N \cdot 2^N)$。

    * 降维递归每层只固定一个数、剩下交给双指针在 $O(N)$ 里扫完，总代价落到 $O(N^2)$。

    * > **结论**：先想办法排除掉不可能的选择，剩下的空间自然就越缩越小。这条线索从数独那张冲突表开始，到三数之和的降维为止是同一套家什，数据量越大差距越明显。
