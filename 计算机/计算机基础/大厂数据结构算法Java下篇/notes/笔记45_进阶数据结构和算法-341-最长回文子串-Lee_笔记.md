# 进阶数据结构和算法-341-最长回文子串-Lee

## 回文子串与最长回文子串

* **子串（substring）**

    * > **定义**：原字符串里的一段连续字符。

* **回文子串（palindrome substring）**

    * > **定义**：这一段字符正着读、反着读完全一样。

    * 判定方式：把整段词串正着拼一遍与反着拼一遍比对，两串相同即为回文。

    * 实例：`BCCB` 正读反读都是 BCCB；`CBC` 正读反读都是 CBC；`CBABCCBABC` 正读反读一致；`BCDABCD` 反读仍是自身。

* **最长回文子串**

    * 题目要求：给定一个字符串，找出其中长度最长的那个回文子串。

    * 长度相同的多个答案取哪一个都算对，例如交 `ABA` 或交 `BB` 都正确。

    * 边界：某个串里 `BB` 就已经是它自身最长的回文子串。

    * 表面上一个求最长、一个求最短，底下共用同一套肌肉记忆：一个字符一个字符地扫窗口，一个往两边撑，一个往两边收。

## 中心开花

* **中心开花（从中间往两边比）**

    * 机理：把某个字符当作回文子串的中间字符，先比较它左边与右边的字符；两边相等就说明能构成一个更长的回文子串。

    * 条件：左右字符相等则继续扩大范围（左边再取一个、右边再取一个）；一旦左右字符不等就停止查找。

    * 覆盖性：从左到右把每个字符都当一遍中间点，尝试一遍，就能找出最长的那个回文子串。

```text
              ┌───┐
              │ A │  ← 中心字符
              └───┘
         ┌───┐     ┌───┐
         │ B │     │ B │  ← 左右相同，还能再长
         └───┘     └───┘
         └─ B A B ─┘         长度 3
     再往左是 C，对面是 B → 不等，停
```

* **第一遍只把单个字符当中心**

    * 每个中心都先看左边：最左边那个字符左边没东西，能构成回文的只有它自己，长度为 1。

    * 过程中用蓝色标记当前找到的回文长度，用红色标记已记录的最大回文长度。

    * 走查结果如下，最后一个中心为长度 1 超不过前面的 7，直接跳过。

    | 中心字符 | 往两边扩的结果 | 长度 | 当前记录的最大值 |
    | --- | --- | --- | --- |
    | 第一个字符（左边没东西） | 只能是自己 | 1 | 1 |
    | C | 左边 B 与右边不一致 | 1 | 1 |
    | C | 左边右边还是不一样 | 1 | 1 |
    | B | 左右相同，扩一层 | 3 | 3（刷新） |
    | B | 只能停在一 | 1 | 3 |
    | A | 一路扩出去 | 7 | 7（刷新） |
    | 一对 BB | 只能是自己 | 1 | 7 |
    | C | 能到五，但下一步 E 与 F 不等，突破不了 | 5 | 7 |
    | B | 1 | 1 | 7 |
    | A | 1 | 1 | 7 |
    | 后面还有一个字符 | 能到三 | 3 | 7 |

    * 走完一圈得出最长的回文子串长度是 7。

* **第二遍把两个字符也当中心**

    * 疏漏：第一遍只考虑了奇数个字符构成回文子串，忽略了偶数个字符构成的情况。

    * 规则：中心字符有两个时，从这两个字符出发再向两边扩展，扩展出的子串字符个数为偶数。

    * 一开始先试 `B`、`C` 作中心，两者自身就不相等，构不成回文；继续向后试 `C`、`C` 可以，得到长度 4 的回文子串。

    * 后续的 `C`、`B` 与 `B`、`C` 两组都不相等，不能作为中心，偶数长度这一遍的最大值就是 4。

```text
         ┌───┐ ┌───┐
         │ C │ │ C │        ← 这两个字符本身就是中心
         └───┘ └───┘
     ┌───┐           ┌───┐
     │ B │           │ B │
     └───┘           └───┘
     └───────────────┘       ← B C C B，长度 4
```

    * > **易错点**：偶数长度这种情况千万不能忽略。刚才能凑巧找到奇数更长的结果是偶然的，偶数个字符构成的回文子串有可能比奇数的更长。

## extend 方法

* **方法签名与三个参数**

    * `extend(char[] chars, int i, int j)`：第一个参数是原始字符数组，第二个参数 `i`、第三个参数 `j` 代表回文子串的左右边界。

    * 约定：`i` 指向左边界，`j` 指向右边界；中心点是一个字符时两者指向同一位置，中心点是两个字符时 `j` 比 `i` 多一。

* **while 循环与两个边界条件**

    * 机理：每次判断 `i` 和 `j` 指向的字符是否一样，一样就说明构成回文，让 `i` 减一、`j` 加一扩大范围；再次判断，直到两边字符不同即退出。

    * 条件一：`i >= 0`，左边再扩就可能越界，与右侧字符比较将失去意义。

    * > **注意**：`i >= 0` 必须包含等于零。若不含零，当 `i` 等于零、指向的字符与 `j` 指向的字符相等时，这个比较就永远不会执行。

    * 条件二：`j < chars.length`，右侧同样不能越界。

    * 退出场景示例：某轮 `i` 指向 B、`j` 指向 B 相等而进入循环，循环内 `i` 减一变成负一、`j` 加一变成四，下一次判断 `i >= 0` 不成立，循环结束。

* **退出后回退一格**

    * 结论：循环退出时 `i`、`j` 指向的已经不成回文，所以要记录回文状态必须先把 `i` 加一、`j` 减一。

    * 示例中 `i` 从负一回到零、`j` 从四回到三，才是当时回文的真实状态。

    * 长度计算：记录下的 `j - i` 再加一就是回文子串的长度。

    * 记录位置选在循环结束之后，因为放在循环内每扩一次都要判断记录一次，不划算。

* **全局静态边界变量**

    * 用两个静态变量 `left` 与 `right` 记录退出回退后的 `i` 与 `j`。

    * 更新规则：`j - i` 比原来的 `right - left` 更大，说明找到了更长的回文子串，此时才更新 `left` 与 `right`；不大于则不更新。

    * 全部字符处理完一遍后，`left` 与 `right` 就是最长回文子串的左右索引。

    * 测试：把字符串换成 `BCCBC` 的前面一截，`i`、`j` 起始都是 1 与 2，求出 `left` 为 0、`right` 为 3 即正确。

```java
private static int left = 0;
private static int right = 0;

private void extend(char[] chars, int i, int j) {
    while (i >= 0 && j < chars.length && chars[i] == chars[j]) {
        i--;
        j++;
    }
    // 退出时已经不成回文了，退回来一格才是回文区间
    i++;
    j--;
    if (j - i > right - left) {
        left = i;
        right = j;
    }
}
```

## longestPalindrome 方法

* **准备与遍历**

    * 先用 `s.toCharArray()` 拿到原始字符串对应的字符数组，再从数组里取字符，比从字符串里取字符效率更好。

    * 遍历字符数组，把一个字符或两个字符作为中心点交给 `extend`，由中心向两边撑出更长的回文子串。

    * 单字符中心：两个实参都传当前下标 `i`，即 `extend(chars, i, i)`。

    * 双字符中心：左边传 `i`、右边传 `i` 加一，即 `extend(chars, i, i + 1)`。

    * 每次调用都会把更大的回文子串边界记进 `left` 与 `right`，循环结束后用 `new String(chars, left, right - left + 1)` 截出最终结果。

* **两个必须改掉的问题**

    * > **易错点**：为了兼顾双字符中心，外层循环上界必须是 `chars.length - 1`，而不是 `chars.length`，否则 `i + 1` 会超出数组范围。

    * > **易错点**：`left` 与 `right` 做成了静态全局变量，方法每次调用前必须把它们清零，否则会残留上次字符串的结果。

    * > **易错点**：`new String(chars, left, right - left + 1)` 的第三个参数不是右边界，而是要截取的长度，即右边界减左边界再加一。

* **测试用例**

    * 第一个用例结果是 `BAB`；第二个是 `BBBABBB`；第三个是单个字符 `A`，本身即回文；第四个用例里藏着一段明显更长的回文。四个用例全部通过。

```java
public String longestPalindrome(String s) {
    char[] chars = s.toCharArray();
    // 左右边界是静态的，每次调用前先清零，把上次的结果清掉
    left = 0;
    right = 0;

    for (int i = 0; i < chars.length - 1; i++) {
        extend(chars, i, i);     // 单个字符当中心
        extend(chars, i, i + 1); // 两个字符当中心
    }
    return new String(chars, left, right - left + 1);
}
```

## 最小覆盖子串的达标条件

* **最小覆盖子串（minimum window substring）**

    * 题目要求：给原始串 `S` 与目标串 `T`，在 `S` 中找出一个子串，使得该子串中每个出现在 `T` 里的字符，其出现次数都不少于它在 `T` 中的次数；在所有满足条件的子串中返回最短的那个，不存在则返回空字符串。

    * 示例：原始串 `S = ADOBECODEBANC`，目标串 `T = AABC`（A、B、C 各需要一个），答案为 `BANC`，对应下标 9 到 12。

    * 判定条件：范围从左向右看，`BANC` 里 B 出现一次、A 出现一次、C 出现一次，符合条件；`ADOBEC` 同样符合但更长。

## 双指针的交替推进

* **窗口定义**

    * 设两个指针 `i` 与 `j`，初始都指向原始串的第一个字符，窗口范围为 `[i, j)`。

    * 起点状态：初始范围内只有一个 A 出现了一次，B 与 C 尚未出现，条件不满足。

    * `j` 一路右扩，多出 D 之类与目标串对不上号的字符不改变不满足的状态，直到 `j` 扩到 C 的位置才第一次满足条件。

* **交替规则**

    * `i` 不动、`j` 右扩：条件不够就一路扩。

    * 条件全部满足：`i` 右缩让窗口变小，试试能不能更短。

    * 缩到不满足为止：`i` 停住，`j` 再右扩把条件补回来。

    * 直到 `j` 走到串尾结束。

    * 反复过程：先得到 `ADOBEC`，再得到 `DOBECODEBA` 所在的第二个达标窗口，但左边的 D 仍可丢弃说明还不是最短，继续缩 `i`；丢掉 B 之后右边还有一个 B 可顶替，继续缩；一旦丢掉 C 条件立刻不成立，就只能继续扩 `j` 找回一个 C。

    * 终止形态：最后记录的 `BANC` 再缩小就不满足条件，而此时已经到头，它就是最小覆盖子串。

```text
原始串 S = ADOBECODEBANC        目标串 T = AABC（A×1、B×1、C×1）

窗口由 i、j 圈出来：[i, j)
  i 不动、j 右扩   →  条件不够就一路扩
  条件全部满足      →  i 右缩，窗口变小，试试能不能更短
  缩到不满足为止    →  i 停住，j 再右扩把条件补回来
  直到 j 走到串尾   →  结束
```

## 两个计数数组

* **targetCount（需求）**

    * 用途：统计目标串中每种字符各出现了几次。

    * 数值：长度为 128 的整型数组。题目限定字符只可能是大小写英文字母，不可能是中文或其他字符。

    * 做法：把目标串转成 char 数组并遍历，每个字符直接当作数组索引，该索引位置计数加一。

    * 校验：目标串为 `ABC` 时，A、B、C 三个索引位置计数为 1，其余位置为 0；把 B 改成两个字符后，B 位置计数变为 2。

* **sourceCount（库存）**

    * 用途：记录原始串中从 `i` 到 `j` 这个范围内每种字符各出现了几次。

    * 做法：`j` 每向右扩一格，先取出 `chars[j]` 作为索引，`sourceCount` 对应位置加一。

    * 调试：写一个 print 方法只打印数组内不为零的项，即可看到窗口扩大过程中每个字符的累计次数——只有 A 出现一次，加上 D 后是 A 与 D 各一次，如此递推。

```java
char[] target = t.toCharArray();
int[] targetCount = new int[128];
for (char c : target) {
    targetCount[c]++;
}

char[] chars = s.toCharArray();
int[] sourceCount = new int[128];
int i = 0, j = 0;

while (j < chars.length) {
    char right = chars[j];
    sourceCount[right]++;
    j++;
}
```

* **配对关系**

    * > **提示**：`targetCount` 是需求，`sourceCount` 是库存，把两个集合对比就能知道 `[i, j)` 范围内的字符个数什么时候满足了目标条件。

## 达标判定与计数方式

* **条件总数与已通过数**

    * 思路：把目标串拆成若干个条件，例如 `A` 出现次数为一、`B` 出现次数为一、`C` 出现次数为一，共三个条件；窗口只含 A 时满足其中一个，含上 B 时满足两个，含上 C 时满足三个。

    * `passTotal` 为条件总数：遍历 `targetCount` 数组，数出所有不为零的项数。

    * `passed` 为已通过的条件数，初始为零；每次循环中检查 `passed` 是否等于 `passTotal`，相等即表示找到一个解，此时让 `j` 暂停。

    * 价值：用两个计数代替每次把整个窗口扫一遍，把是否达标的判断降成 O(1)。

* **为什么必须写成 ==**

    * 写法：窗口每加入一个字符 `right`，判断 `sourceCount[right] == targetCount[right]`，相等则 `passed` 加一。

    * 解释：初始 `right` 为第一个 A，原始串中 A 出现一次、目标串中 A 也出现一次，二者相等，该条件通过；遇到 D 时原始串中出现一次而目标串中为零，不相等，通过数不增加；再遇到 B 时两侧都出现一次，通过数加到二。

    * > **结论**：判断必须写 `==` 而不是 `>=`。若写成 `>=`，第二个 A 进入窗口时原始串中 A 计数变为二，同样大于等于一，`passed` 会再加一，于是通过数被错记为二——但 A 这条其实只是数量超过，多出来的那个 A 对"覆盖"没有任何贡献，只是一个多余的字符。真正要到 B 的位置才算通过第二条，到 C 才算通过第三条。

```java
int passTotal = 0;   // 我们要满足的目标串中的条件总数
for (int count : targetCount) {
    if (count > 0) {
        passTotal++;
    }
}
int passed = 0;      // 已经通过的条件数

if (sourceCount[right] == targetCount[right]) {
    passed++;
}
```

## 缩小窗口的内层循环

* **循环条件**

    * 进入时机：从调试输出能看到通过数随处理字符依次变化，A 之后是一，D 之后仍是一，到 B 变成二，到 C 变成三；到达 C 这个位置就应该去缩小范围。

    * 判定式：`passed == passTotal`，表示条件仍然全部满足，此时才允许不断把 `i` 加加缩小范围。

    * 额外限制：`i <= j`，`i` 增加过程中不能超过 `j`。

* **每次缩小后的计数维护**

    * 取出 `chars[i]` 记作 `left`，以其为索引把 `sourceCount` 对应位置减一。

    * 条件失效判定：若减完之后 `sourceCount[left] < targetCount[left]`，说明这条条件不再成立，`passed` 减一。

    * 示例：处理到 C 时把它的计数减一变成零，小于目标串中 C 的计数一，该条件作废。

    * 退出机制：`passed` 一旦减少，下一轮判断发现它不等于 `passTotal`，内层 while 循环退出，停止缩小 `i`。

## 最短解的挑选与返回

* **候选解记录**

    * 进入内层 while 循环就意味着找到了一个解，此时把左右边界的差值与上一次的差值比较，挑出差值最小的那一个。

    * 存储方式：自定义一个 `Result` 类型，用它的 `left` 与 `right` 两个属性记录当时的 `i` 与 `j`；循环外先把 `result` 定义为 `null`，表示还没有找到解。

    * 取值分支：`result` 为 `null` 时直接把当前 `i`、`j` 作为当前解；不为 `null` 走 else 分支，在两个解里挑距离更短的。

    * 边界：循环全部走完后 `result` 仍为 `null` 是可能的，代表根本无解。

* **开区间与闭区间的换算**

    * 记录时右边界存的是 `j - 1`，因为 `j` 是开区间的右端，减一才是含首含尾的下标。

    * 因此 `result.right - result.left` 恰好等于 `(j - 1) - i`，与 `j - i` 都是"长度减一"，量纲一致，可以直接比大小。

    * 返回时的截取长度同样是 `result.right - result.left + 1`。

* **返回值两种情况**

    * `result == null`：尝试了所有子串都没有出现能覆盖目标串的情况，返回空字符串。

    * `result != null`：以原始串的字符数组为源，从 `result.left` 开始截取 `result.right - result.left + 1` 个字符返回。

* **候选解长度序列**

    * 整个扫描过程一共记录下来十一个候选解。

    | 轮次 | 依次记录下来的候选窗口 | 长度 |
    | --- | --- | --- |
    | 第一次达标 | `ADOBEC` | 6 |
    | 第二次达标 | `DOBECODEBA` → `OBECODEBA` → `BECODEBA` → `ECODEBA` → `CODEBA` | 10 → 9 → 8 → 7 → 6 |
    | 第三次达标 | `ODEBANC` → `DEBANC` → `EBANC` → `BANC` | 7 → 6 → 5 → 4 |

    * 读图对照：第一次达标时的窗口是 `ADOBEC`，长度 6；最后那个最短窗口是 `BANC`，长度 4。

    * 为什么这题最坏情况并不很慢：第二轮丢 `D`、丢 `O` 一点关系都没有，因为目标串里本来就没有这两个字符；丢第一个 `B` 也没关系，反正右边还有一个 `B`。真正卡住的只有 `C`——一丢就归零，条件立刻不成立。

```text
i=0                       j=5
|                          |
A  D  O  B  E  C  O  D  E  B  A  N  C

i=9                       j=12
|                          |
A  D  O  B  E  C  O  D  E  B  A  N  C
```

* **Result 类型与完整实现**

```java
private static class Result {
    int left;
    int right;
    Result(int left, int right) {
        this.left = left;
        this.right = right;
    }
}

public String minWindow(String s, String t) {
    // 1. 统计目标串里每种字符各需要几个
    int[] targetCount = new int[128];
    for (char c : t.toCharArray()) {
        targetCount[c]++;
    }
    // 条件总数：targetCount 里不为零的个数
    int passTotal = 0;
    for (int count : targetCount) {
        if (count > 0) {
            passTotal++;
        }
    }

    // 2. sourceCount 记录窗口 [i, j) 内每种字符各出现了几个
    char[] chars = s.toCharArray();
    int[] sourceCount = new int[128];
    int passed = 0;
    int i = 0, j = 0;
    Result result = null;   // null 表示还没找到解

    // 3. j 右扩，把条件凑齐
    while (j < chars.length) {
        char right = chars[j];
        sourceCount[right]++;
        // 注意：是 ==，写成 >= 就会把多余字符也当成"条件被满足"
        if (sourceCount[right] == targetCount[right]) {
            passed++;
        }
        j++;

        // 4. 条件全满足，就一路缩小 i，试试能不能更短
        while (passed == passTotal && i <= j) {
            if (result == null || j - i < result.right - result.left) {
                // j 是开区间右端，减 1 才是含首含尾的下标
                result = new Result(i, j - 1);
            }
            char left = chars[i];
            sourceCount[left]--;
            // 计数跌破需求，这条条件就废了
            if (sourceCount[left] < targetCount[left]) {
                passed--;
            }
            i++;
        }
    }

    if (result == null) {
        return "";
    }
    return new String(chars, result.left, result.right - result.left + 1);
}
```

## 两道题对照

| 维度 | 最长回文子串 | 最小覆盖子串 |
| --- | --- | --- |
| 输入 | 一个字符串 | 原始串 `S` 与目标串 `T` |
| 窗口动作 | 从中心向两边撑 | `j` 右扩与 `i` 右缩交替 |
| 状态记录 | 静态全局 `left` / `right` | 自定义 `Result` 类型的两个属性 |
| 终止条件 | 全部中心试完 | `j` 走到串尾，或缩到不满足 |
| 返回 | `new String(chars, left, right - left + 1)` | 无解返回 `""`，否则按 `Result` 边界截取 |

* **LeetCode 5 最长回文子串**

    * 题干：给一个字符串，返回这个字符串中最长的回文子串，子串中所有字符正着读、反着读都一样。

    * 解法一句话概括：从左到右把所有单字符中心和双字符中心都试一遍，用 `extend` 往外撑到撑不动为止，过程中始终用 `left` / `right` 记下最长的那个区间，最后截出来。

    * 三个坑：双字符中心时循环上界是 `chars.length - 1`、静态边界每次调用前要清零、截取的第三个参数是长度而不是右边界。

* **LeetCode 76 最小覆盖子串**

    * 题干：给原始串 `S` 和目标串 `T`，在 `S` 中找一个子串，使该子串中每个出现在 `T` 里的字符出现次数都不少于它在 `T` 中的次数，返回其中最短的一个，不存在返回空字符串。

    * 核心是 `targetCount` 记需求、`sourceCount` 记窗口库存，用 `passTotal`（需求种类数）与 `passed`（已满足条件数）两个计数代替"每次把整个窗口扫一遍"，把达标判断降成 O(1)。

    * 两个方向的动作交替执行：不够就让 `j` 右扩，够了一直满足就让 `i` 右缩，缩到不满足就停手继续扩。
