### 期中考复盘与思维模式

#### 固定型思维与成长型思维

我平时并不热衷那些教人“只要读对一本书、掌握唯一法则就能成功”的畅销自助书，真实生活远比那些简化的口号复杂。但斯坦福心理学家 Carol Dweck 提出的关于思维模式的论述，确实极具启发性。人们在看待自身能力时，往往存在两类截然不同的心态：

```text
+--------------------------------------------------------------------------+
|                            两种核心思维模式对比                            |
+--------------------------------------------------------------------------+
|  【固定型思维 (Fixed Mindset)】       |  【成长型思维 (Growth Mindset)】       |
|  - 认为智力与才能是天生固定的特质     |  - 认为能力与智慧可以通过刻意练习发展 |
|  - 目标是“显得聪明”，极力避免暴露无知 |  - 目标是“持续成长”，把挑战视作进阶阶梯 |
|  - 视“努力”为底子差、软弱的表现       |  - 视“努力”为通往熟练与精通的唯一必经之路 |
|  - 害怕挫折，遭遇难题容易退缩或放弃   |  - 拥抱困难，认为挣扎与犯错是学习的本质 |
+--------------------------------------------------------------------------+
```
上图对比了固定型思维与成长型思维在能力认知、目标设定与面对挫折时的核心分歧。

如果你持有极端的固定型思维，你可能会觉得在高中时必须表现出“我根本没怎么复习，随随便便就考了高分”，以此向外界暗示一切对自己都轻而易举。甚至一旦在大学课堂上承认自己忘记了如何求矩阵的特征值，就会觉得自己的灵魂被烙上了不可磨灭的污点。

相反，成长型思维认为能力是通过努力、良好的指导以及坚持不懈的训练逐步建立起来的。它并不假设人人都是无所不能的天才，但它确信通过投入时间，任何人都可以变强。61B 的内容同样如此。

我小时候也曾是固定型思维的信徒，因为当时数学学得顺手，就自以为自己天赋异禀，一切顺理成章。直到读本科甚至更晚我才明白，那只是因为我对所学的内容充满兴趣，因此心甘情愿投入大量时间去钻研。助教们之所以能站在讲台上清晰流畅地答疑，我和其他讲师之所以看一眼期中考卷就能不用草稿纸直接写出答案，绝非什么神秘的基因优势，仅仅是因为我们把这些题目练了成百上千遍。学习速度或许因人而异，但在 61B 这样的课程中，只要方法得当，你完全有能力学得非常优秀。

#### 掌握学习法与伯克利成绩追踪

教育学家 Benjamin Bloom 在 1980 年代发表过一篇被称为“教育学登月工程”的经典论文，提出了著名的“两西格玛问题（Bloom's 2 Sigma Problem）”。他通过严格的对比实验发现：

```text
成绩分布人数
    ^
    |             常规大班教学 (30:1)         一对一导师辅导 (Mastery Learning)
    |                  ┌───┐                        ┌───┐
    |                 /     \                      /     \
    |                /       \                    /       \
    |               /         \                  /         \
    |             ┌/           \┐              ┌/           \┐
    |           ┌─┘             └─┐          ┌─┘             └─┐
  0 +───────────┴─────────────────┴──────────┴─────────────────┴──────> 成绩百分位
               常规班中位数 (50%)          前 2% 水平 (相差 2 个标准差 σ)
```
上图描绘了 Bloom 两西格玛实验中常规班级授课与一对一掌握学习法在最终成绩分布上的巨大鸿沟。

在传统的一对三十大班教学中，学生的表现呈现常规的正态分布；而在推行“掌握学习法（Mastery Learning，即只有在完全掌握当前模块后才允许推进到下一阶段）”并配备优质一对一指导的环境下，学生的平均成绩竟然跃升到了常规教学班的前 2%（提升了整整两个标准差）。这项研究揭示的核心命题在于：优质的针对性辅导能让绝大多数人达到卓越，教育研究与课程设计的长远目标，正是利用有限的教学资源去无限逼近这种个性化辅导的效果。

在伯克利本地，我也做过真实的数据追踪。多年前我与本科生 Allan（他毕业后去了顶级量化公司 Jane Street）合写过一份内部调研报告，追踪学生从先修课 61A 到 61B 的成绩延续性。当时的数据令人沮丧：在常规教学下，如果一名学生在 61A 中拿了 B 或 C+，他们在 61B 的表现几乎被锁死在对应的区间，极少有人能实现从 B- 到 A- 的跨越。

但转折发生在 2016 年春季。当时由于计算机主修申请设有严格的 3.3 GPA 门槛，面对期末成绩不理想的同学，我提供了允许挂科并于次年重修的选择。结果令人震惊：选择重修并重新扎实投入这门课的学生，第二次修读时的平均成绩足足提升了 2.5 个等级（比如从 C 跃升至 B+ 甚至 A）。这用无可辩驳的数据证明了一件事：你的能力从未被任何一次考试定型，前期的准备与扎实的练习投入完全能重塑学习轨迹。

> **提示**：真正的学习往往伴随着挣扎与阵痛。如果你在写代码或做题时感到轻松写意，那通常说明你只是在重复调用已有的熟练技能；当你感到痛苦、寸步难行时，正是大脑构建全新认知模型的关键时刻。

### 算法效率度量与成本模型

在度过了期中考的低谷后，我们必须把视线投向计算机科学中最核心的能力之一——渐近分析（Asymptotic Analysis）。如果说 61B 有哪项技能的天花板最高、对后续算法设计与复杂系统构建影响最深远，那绝对是这套分析代码运行效率的理论体系。

#### 运行时间函数的困境与增长阶

当我们拿到一段代码片段时，最直观的诉求是想知道：“这段程序运行到底要花多长时间？”

我们很自然地会尝试定义一个函数 $R(N)$，其中 $N$ 代表输入的规模（例如数组的长度、输入的数值大小等），$R(N)$ 代表程序执行所需的实际秒数。但从数学严格性上讲，这个 $R(N)$ 甚至根本不能被称为一个确切的“函数”。

因为如果你在自己的笔记本电脑上运行一段代码，测得耗时 1.2 秒；几秒钟后再次运行，耗时可能变成 1.35 秒；换到机房的服务器上，可能只需要 0.2 秒；在不同架构的 CPU、不同的操作系统调度、甚至 Java 虚拟机的不同即时编译（JIT）状态下，耗时均截然不同。

因此，寻找一个精确描述真实物理耗时的函数不仅是不可能的，而且在工程上也毫无意义。我们真正关心的不是微秒级或毫秒级的绝对数字，而是当输入规模 $N$ 奔向无穷大时，运行时间的**增长阶（Order of Growth）**。

#### 成本模型与代表性操作

为了在纷繁复杂的底层硬件差异之上建立清晰的数学度量，我们采用一种标准的研究方法——**成本模型（Cost Model）**。

其核心思路在于：我们不在乎每一条机器指令的执行时间，而是在算法代码中挑选一个最具有代表性、处于核心执行链路上的关键操作（例如循环最内层的数值比较、数组赋值或加法运算），用 $C(N)$ 来表示该操作随着输入规模 $N$ 变化而发生的总次数。

只要我们选取的代表性操作满足“单次执行耗时恒定（$O(1)$）”，并且该操作的执行次数与其他杂项操作（如循环变量递增、条件判断等）保持常数比例关系，那么只要算出了 $C(N)$ 的增长阶 $f(N)$，整个算法的实际运行时间增长阶就必然被严格限定在 $f(N)$ 的范畴内。

#### 从嵌套循环到几何直观

让我们回顾上一讲结尾处分析过的重复项检查函数 `dup1`：

```java
public static boolean dup1(int[] A) {
    int N = A.length;
    for (int i = 0; i < N; i += 1) {
        for (int j = i + 1; j < N; j += 1) {
            if (A[i] == A[j]) {
                return true;
            }
        }
    }
    return false;
}
```

在这段代码中，最合适充当成本模型的操作显然是内层的相等判断 `A[i] == A[j]`。在最坏情况下（数组中完全没有重复元素），内层比较操作会完整执行：

- 当 $i = 0$ 时，$j$ 从 $1$ 遍历到 $N-1$，执行 $N-1$ 次比较；
- 当 $i = 1$ 时，$j$ 从 $2$ 遍历到 $N-1$，执行 $N-2$ 次比较；
- ……
- 当 $i = N-2$ 时，$j$ 从 $N-1$ 到 $N-1$，执行 $1$ 次比较；
- 当 $i = N-1$ 时，内层循环不执行（$0$ 次）。

将所有比较次数累加，得到精确的总次数函数：

$$C(N) = (N-1) + (N-2) + \dots + 2 + 1 = \sum_{k=1}^{N-1} k = \frac{N(N-1)}{2} = \frac{1}{2}N^2 - \frac{1}{2}N$$

在算术层面上，$\frac{1}{2}N^2 - \frac{1}{2}N$ 是精确的求和结果；但在渐近分析中，随着 $N$ 的急剧膨胀，低阶项 $-\frac{1}{2}N$ 和最高阶常数系数 $\frac{1}{2}$ 都不再改变函数形状的数量级本质，其增长阶等价于 $N^2$。

从几何视角来看，这对应一个底和高均为 $N-1$ 的直角三角形：

```text
j (内层列)
^
|  * * * * * *    (i = 0, 比较 N-1 次)
|  . * * * * *    (i = 1, 比较 N-2 次)
|  . . * * * *    (i = 2, 比较 N-3 次)
|  . . . * * *
|  . . . . * *
|  . . . . . *    (i = N-2, 比较 1 次)
+-------------------> i (外层行)
```
上图将嵌套循环中每一次内层比较映射为一个二维网格点，整体构成了底和高均为 $N-1$ 的三角形区域。

三角形的面积正比于 $\text{底} \times \text{高} \propto N^2$，因此其渐近时间复杂度为 $\Theta(N^2)$。借助几何面积直观化代数求和，是算法分析中极其通用的思考模式。

### 渐近分析实战案例推演

初学者在做渐近分析时最容易犯的错误就是“数循环层数”——看到单层循环就认为是 $N$，看到双重循环就盲猜 $N^2$，看到循环步长翻倍就盲猜 $\log N$。但算法的真实行为远比这种死记硬背的套路微妙得多。

#### 嵌套常数循环的矩形模型

请大家思考下面这个名为 `scan` 的函数，尝试判断其最坏情况运行时间的增长阶：

```java
public static void scan(int N) {
    for (int i = 1; i < N; i += 1) {
        for (int j = i - 1; j <= i + 1; j += 1) {
            int temp = i * j; // 关键计算操作
        }
    }
}
```

乍看之下，这同样是一个外层嵌内层的双重 `for` 循环。许多同学直觉上容易脱口而出“这是 $\Theta(N^2)$”，但我们必须严格依据成本模型来计算。

选取内层的乘法计算 `i * j` 作为成本模型。考察内层循环变量 $j$ 的取值区间：
对于外层循环的任意一个合法 $i$，$j$ 的初始值为 $i - 1$，步长加 1，终止条件为 $j \le i + 1$。
也就是说，$j$ 依次取 $i - 1$、$i$、$i + 1$ 这 3 个确切的值。
- 当 $i = 1$ 时，$j \in \{0, 1, 2\}$，执行 3 次；
- 当 $i = 2$ 时，$j \in \{1, 2, 3\}$，执行 3 次；
- 当 $i = 8$ 时，$j \in \{7, 8, 9\}$，执行 3 次；
- ……
- 直到 $i = N - 1$，依然恒定执行 3 次。

无论外层变量 $i$ 变到多大，内层循环永远只执行固定的 3 次操作！
因此，该算法总的操作次数为：

$$C(N) = 3 \times (N - 1) = 3N - 3$$

```text
j (内层跨度)
^
|  * * *  (宽恒为 3)
|  * * *
|  * * *
|  * * *
|  * * *  ... 沿着 i 轴向前延伸，总长为 N - 1
+-------------------------------------------> i (外层行)
```
上图展示了 `scan` 函数的执行轨迹，它是一个宽恒为 3、长为 $N-1$ 的细长矩形。

细长矩形的面积等于 $3 \times (N-1)$，当 $N$ 趋于无穷大时，其面积显然与 $N$ 严格成正比。

> **易错点**：切莫陷入“双重循环必为平方阶”的思维定势。判断复杂度的唯一依据是核心操作的实际总调用次数，一旦内层循环与全局规模 $N$ 解耦（仅为局部常数），嵌套循环的总耗时同样会退化为纯粹的线性阶 $\Theta(N)$。

#### 指数跳跃与阶梯折线

接下来我们看一个极具迷惑性和启发性的经典案例——`printParty` 函数：

```java
public static void printParty(int N) {
    for (int i = 1; i <= N; i = i * 2) {
        for (int j = 0; j < i; j += 1) {
            System.out.println("hello");
        }
    }
}
```

在这段代码中：
- 外层循环变量 $i$ 从 1 开始，每次迭代通过 `i = i * 2` 呈指数级翻倍增长（即 $i = 1, 2, 4, 8, 16, \dots$），只要满足 $i \le N$ 就继续；
- 内层循环变量 $j$ 从 0 开始，每次递增 1，直到 $j < i$，因此对于当轮的 $i$，内层循环会精确打印 $i$ 次 `"hello"`。

许多同学在考场上看到外层循环是典型的对数步长（跑了约 $\log_2 N$ 次），内层循环上限是变量 $i$，便开始随意拼凑答案，有人猜 $\Theta(\log N)$，有人猜 $\Theta(N \log N)$，甚至有人猜 $\Theta(2^N)$。

遇到不直观的复杂控制流，最踏实的方法就是**手动代入具体数值，逐步追踪并填写表格**：

| 输入规模 $N$ | 外层 $i$ 取到的序列值 | 各轮内层打印次数 | 累计总打印次数 $C(N)$ |
| :--- | :--- | :--- | :--- |
| **$N = 1$** | $1$ | $1$ | **1** |
| **$N = 2$** | $1, 2$ | $1 + 2$ | **3** |
| **$N = 3$** | $1, 2$ (因下次翻倍为 4 超出 $N$) | $1 + 2$ | **3** |
| **$N = 4$** | $1, 2, 4$ | $1 + 2 + 4$ | **7** |
| **$N = 5$** | $1, 2, 4$ (因下次翻倍为 8 超出 $N$) | $1 + 2 + 4$ | **7** |
| **$N = 6$** | $1, 2, 4$ | $1 + 2 + 4$ | **7** |
| **$N = 7$** | $1, 2, 4$ | $1 + 2 + 4$ | **7** |
| **$N = 8$** | $1, 2, 4, 8$ | $1 + 2 + 4 + 8$ | **15** |
| **$N = 16$** | $1, 2, 4, 8, 16$ | $1 + 2 + \dots + 16$ | **31** |

为了确证这个推导在真实机器上的正确性，我现场打开 IntelliJ IDEA 并挂载调试器单步断点执行：当输入 $N = 4$ 时，控制台严格输出了 7 行 `"hello"`；输入 $N = 8$ 时输出了 15 行。

我们观察上面的规律：
每当 $N$ 恰好是 2 的整数次幂时（$N = 2^k$），总打印次数构成了公比为 2 的等比数列求和：

$$C(N) = 1 + 2 + 4 + 8 + \dots + N = 2N - 1$$

而当 $N$ 处于两个 2 的幂之间时（例如 $N \in [4, 7]$），因为外层 $i$ 还不足以迈入下一个翻倍门槛，其总打印次数完全保持不变，恒定等于前一个 2 的幂对应的计算量（即 7 次）。

这导致函数 $C(N)$ 在图像上呈现为一段一段水平平台、并在每个 2 的幂处发生骤升的“阶梯状”或“尖刺状”跳跃：

```text
C(N) (打印次数)
 ^
 |                                                / 严格上界: 2N
31 |                                         *-----/ 
   |                                        /     /
15 |                            *----------/     /
   |                           /                /
 7 |              *-----------/                /
   |             /                            /
 3 |      *-----/                            / 严格下界: 0.5N
 1 |  *--/                                  /
 0 +--+---+-------+-----------+------------+-----> N
   0  1   2       4           8           16
```
上图展示了阶梯跳跃的 $C(N)$ 函数如何被夹在斜率分别为 0.5 与 2 的两条过原点直线之间。

现在面对这个奇怪的非光滑阶梯函数，它的渐近增长阶到底是什么？
答案是：**它依然严格属于 $\Theta(N)$！**

为什么？因为根据大 $\Theta$ 的严密数学定义，我们并不要求函数本身是光滑连续的曲线，我们只要求能找到两个正实数常数 $k_1$ 和 $k_2$ 以及一个阈值 $n_0$，使得对所有 $N \ge n_0$：

$$k_1 \cdot N \le C(N) \le k_2 \cdot N$$

对于任意正整数 $N$，设小于等于 $N$ 的最大 2 的幂为 $2^k$（即 $2^k \le N < 2^{k+1}$）：
- 根据上表可知，此时 $C(N) = 2 \cdot 2^k - 1$；
- 由于 $2^k \le N$，显然有 $C(N) < 2 \cdot 2^k \le 2N$（上界常数取 $k_2 = 2$ 或更宽泛的 $4$ 均成立）；
- 另一方面，由于 $N < 2^{k+1} = 2 \cdot 2^k$，即 $2^k > \frac{1}{2}N$，因此 $C(N) = 2 \cdot 2^k - 1 \ge 2^k > \frac{1}{2}N$（对于 $N \ge 1$，容易验证 $C(N) \ge 0.5N$）。

这就严格证明了 $C(N)$ 在整体上始终被紧紧夹在两条过原点的射线 $0.5N$ 与 $2N$ 之间。一条带有阶梯与尖刺的折线，在长远趋势的宏观尺度下，其本质仍然是一条直线！

#### 动态数组翻倍扩容的内在映射

我为什么要在课堂上大费周章地设计这个怪异的 `printParty` 函数？
这绝非脱离实际的数学文字游戏，它在计算机底层体系与经典数据结构中拥有一个最著名的物理映射——**动态数组的翻倍扩容（Resizing Array / Java 的 `ArrayList`）**。

在实现动态数组时，我们通常在底层分配一个固定长度的物理数组：
- 当数组未满时，向末尾插入新元素只需要常数时间 $O(1)$；
- 当数组被填满时，系统必须开辟一个容量翻倍的新数组，并将老数组中的全部 $N$ 个元素逐一搬迁拷贝到新内存空间中（耗费 $O(N)$ 时间）。

初学者往往会被这单次极为昂贵的 $O(N)$ 扩容开销吓退，担心它会破坏数组的性能。但正是因为扩容规则是**成倍增长**（容量依次为 $2, 4, 8, 16, 32, 64, \dots$），下一次触发扩容搬迁所需要的等待时间也随之成倍拉长！

那些单次耗时为 $N$ 的稀疏重型操作，被以指数级距离拉开。当你把连续插入 $N$ 个元素过程中所消耗的所有数据搬迁成本累加起来时，它的总开销形式与 `printParty` 完全相同：

$$\text{总搬迁开销} = 1 + 2 + 4 + 8 + \dots + 2^k \le 2N - 1$$

将这 $2N - 1$ 次总搬迁均摊到 $N$ 次日常插入操作中，平均每次插入仅分摊不到 2 次搬迁，从而在数学上严谨地保证了动态数组插入操作的均摊常数时间复杂度。

### 渐近分析的数学工具与记号体系

在处理各类复杂代码的渐近分析时，我们不需要沉迷于高深繁琐的微积分计算，在 61B 的整套算法体系中，大家必须熟练掌握的求和公式仅有两个。

#### 两个关键求和公式

这是全课程中唯二要求大家脱口而出的闭合求和公式，只要熟记并掌握它们的结构，考场上面对绝大多数求和形式就能迎刃而解：

```text
公式一：前 Q 个连续奇数之和
1 + 3 + 5 + ... + (2Q - 1) = Q^2

【几何直观证明】
  +---+---+---+
3 | 5 | 5 | 5 |    从左下角单位方块开始，每次环绕一层 L 型走廊：
  +---+---+---+    - 初始中心：1 个方块 (1 = 1^2)
2 | 3 | 3 | 5 |    - 增加第 2 层：加 3 个方块，构成 2x2 方阵 (1 + 3 = 2^2 = 4)
  +---+---+---+    - 增加第 3 层：加 5 个方块，构成 3x3 方阵 (1 + 3 + 5 = 3^2 = 9)
1 | 1 | 3 | 5 |    - 推广至 Q 层：总面积恰好等于边长为 Q 的完整正方形 Q^2
  +---+---+---+
    1   2   3
```
上图通过拼装 L 型环状方块的几何视角，直观说明了奇数累加如何构成连续的完美正方阵。

第二个公式则是等比数列的求和公式：

$$\sum_{i=0}^{Q} 2^i = 1 + 2 + 4 + 8 + \dots + 2^Q = 2^{Q+1} - 1$$

当上限 $Q$ 本身是某个 2 的幂（记作 $N = 2^Q$）时，该式可以简化记作：

$$1 + 2 + 4 + \dots + N = 2N - 1$$

无论推导中遇到多复杂的翻倍或循环折半，把工作量归结并化简到这两个求和范式中，是算法分析最扎实的基础功。

#### 大 Theta、大 O 与大 Omega 的严格定义

在上一周讨论不相交集合（Disjoint Sets / Union-Find）时，讲师在展示效率对比表格中，某些操作标记了神秘的 $\Theta$，某些操作则标记为 $O$。很多同学会感到困惑：它们到底有什么本质区别？

我们可以用基础代数中的比较关系来作生动的类比：

```text
+-------------------------------------------------------------------------------+
|                            三大渐近记号对比速查                                |
+-------------------------------------------------------------------------------+
|  渐近符号     |  代数对应关系  |  几何直观与数学约束                            |
+---------------+----------------+----------------------------------------------+
|  大 Theta (Θ) |  约等于 (=)    |  双向紧确界：被两条同阶常数直线严格上下夹逼    |
|  大 O (O)     |  小于等于 (≤)  |  渐近上界：增长速率不超过该函数的常数倍        |
|  大 Omega (Ω) |  大于等于 (≥)  |  渐近下界：增长速率不低于该函数的常数倍        |
+---------------+----------------+----------------------------------------------+
```

下面我们分别给出它们的严密技术内涵：

**大 Theta ($\Theta$)：紧确双向界**

> **定义**：如果存在正常数 $k_1, k_2$ 以及正整数 $n_0$，使得对所有 $N \ge n_0$，均满足：
> $$k_1 \cdot f(N) \le R(N) \le k_2 \cdot f(N)$$
> 则记作 $R(N) \in \Theta(f(N))$。

大 $\Theta$ 给出了算法执行时间的“精确数量级”。如果一个函数是 $\Theta(N^2)$，它既不可能跑得像 $N$ 那么快，也不可能恶化到 $N^3$ 那么慢。

**大 O ($O$)：渐近上界**

> **定义**：如果存在正常数 $k_2$ 以及正整数 $n_0$，使得对所有 $N \ge n_0$，均满足：
> $$R(N) \le k_2 \cdot f(N)$$
> 则记作 $R(N) \in O(f(N))$。

大 $O$ 只是单向的上界约束。举例来说，如果一个函数的真实增长阶是 $R(N) = N^3 + 3N$：
- 它可以严谨地写为 $R(N) \in \Theta(N^3)$；
- 按照定义，它同样完全符合 $R(N) \in O(N^3)$；
- 甚至把它写成 $R(N) \in O(N^4)$、$R(N) \in O(N^{100})$ 或 $R(N) \in O(2^N)$，在数学逻辑上都是绝对正确无误的声明，因为它的确从未超过这些函数的常数倍放大。

那么在工程实践中，我们为什么经常使用大 $O$ 而不是大 $\Theta$？
让我们回顾不相交集合中快速并查集（Quick Union）的 `connect(p, q)` 操作：
该操作的耗时完全取决于两个节点所在树的高度。
- 如果此前一系列连通操作恰好将树退化为一条长链，树高达到 $N$，那么查找根节点并连接的耗时就是线性时间；
- 但如果输入极为理想，两个节点本身就是根节点或者树的高度只有 1，该操作瞬间就能以 $O(1)$ 常数时间完成。

因为运行时间极度依赖于具体的输入序列和树的动态拓扑结构，我们无法给出一个通用的单一函数用大 $\Theta$ 进行双向锁定。此时采用大 $O$ 记号（写成 $O(N)$），正是为了给出一个能覆盖所有极端情况的坚固上限保证——“无论你的输入有多刁钻，最差最差也绝不可能超过线性级别”。

**大 Omega ($\Omega$)：渐近下界**

> **定义**：如果存在正常数 $k_1$ 以及正整数 $n_0$，使得对所有 $N \ge n_0$，均满足：
> $$R(N) \ge k_1 \cdot f(N)$$
> 则记作 $R(N) \in \Omega(f(N))$。

大 $\Omega$ 是大 $O$ 的完全对偶面。如果 $R(N) = N^3 + 3N$，那么它不仅属于 $\Omega(N^3)$，也属于 $\Omega(N^2)$、$\Omega(N)$ 以及 $\Omega(1)$。

大 $\Omega$ 最强大、最优雅的应用场景，并不在于分析某一段具体写好的代码，而在于在理论计算机科学中**划定特定问题本身固有的计算难度下限**。

例如这样一个经典问题：给定一个完全无序、包含 $N$ 个数字的数组，要求找出其中的中位数。
我们可以断言：寻找无序数组中位数的任何可能算法，其时间复杂度下界必定是 $\Omega(N)$。

无论后世的计算机科学家多么聪明、发明出多么巧妙的数据结构，即便你在超级计算机上运行几百万年，也绝对没有任何人能够设计出一个亚线性时间（如 $O(\log N)$ 或 $O(\sqrt{N})$）的通用找中位数算法。

为什么？论证逻辑朴素而坚不可摧：
因为中位数的值严格取决于集合中所有数字的相对大小分布。只要你的算法漏看了其中的某一个元素，攻击者就能将这个未被查看的位置修改为一个极其巨大的正数或极其微小的负数，从而瞬间彻底改变原本的中位数结果。因此，任何声称正确解决该问题的算法，在最坏情况下都必须至少把这 $N$ 个数据完整审查一遍，这直接在物理上锁死了 $\Omega(N)$ 的理论地板。

类似地，在后续章节中我们将进一步证明，任何**基于比较的排序算法**（如归并排序、快速排序等），其运行时间的理论极限下界必定是 $\Omega(N \log N)$。如果不借助基数排序等非比较策略，绝对没有任何基于两两比较的排序算法能够突破这个数学红线。

#### 嵌套固定步长循环的复杂度判定

【题干】
分析以下代码片段中，乘法操作执行次数的渐近增长阶（大 $\Theta$ 记号）：
```java
for (int i = 1; i < N; i += 1) {
    for (int j = i - 1; j <= i + 1; j += 1) {
        int temp = i * j;
    }
}
```

【解析】
外层循环变量 $i$ 从 1 遍历到 $N - 1$，共执行 $N - 1$ 次。
对于每一个确定的 $i$，内层循环变量 $j$ 严格从 $i - 1$ 遍历至 $i + 1$，仅依次取 $i - 1$、$i$、$i + 1$ 三个值。
因此内层循环的执行次数恒为常数 3，与当前 $i$ 的大小以及全局规模 $N$ 均无关。
总操作次数为 $C(N) = 3(N - 1) = 3N - 3$。
根据大 $\Theta$ 的定义，最高阶为 $N$，常数系数在增长阶中省略。

【答案】
$\Theta(N)$

#### 指数翻倍步长下的打印次数与增长阶推导

【题干】
考察以下方法 `printParty(int N)`，计算当输入参数为 $N$ 时，打印语句的执行总次数 $C(N)$，并给出其整体运行时间的紧确渐近界（大 $\Theta$）：
```java
public static void printParty(int N) {
    for (int i = 1; i <= N; i = i * 2) {
        for (int j = 0; j < i; j += 1) {
            System.out.println("hello");
        }
    }
}
```

【解析】
1. 外层循环变量 $i$ 初始为 1，每次迭代翻倍，其取值为 $1, 2, 4, 8, \dots, 2^{\lfloor \log_2 N \rfloor}$。
2. 对于每个固定的 $i$，内层循环循环 $i$ 次。
3. 当 $N$ 恰好为 2 的整数次幂时，总执行次数为等比数列求和：
   $$C(N) = 1 + 2 + 4 + \dots + N = 2N - 1$$
4. 当 $N$ 介于 $2^k$ 与 $2^{k+1}-1$ 之间时，$C(N)$ 保持为常数台阶，值恒等于 $2 \cdot 2^k - 1$。
5. 虽然函数呈现阶梯状，但对所有 $N \ge 1$，均满足：
   $$0.5 N \le C(N) \le 2 N$$
   根据大 $\Theta$ 严格定义，该函数被夹在斜率分别为 0.5 和 2 的两条过原点直线之间。

【答案】
当 $N$ 为 2 的整数幂时，精确次数为 $2N - 1$；整体运行时间复杂度为 $\Theta(N)$。

#### 未排序数组中位数查找算法的理论下界

【题干】
请简述为什么在无序数组中查找中位数的问题，其计算时间复杂度的渐近下界必定是 $\Omega(N)$？

【解析】
中位数的值由整个数据集合中所有元素的综合排序位置决定。假设存在某种算法执行步数严格少于 $N$ 步（即亚线性复杂度），则必然存在至少一个数组下标处的元素从未被该算法读取或审查。
如果该位置未被检验，外部环境可以随时将其改写为一个极大值或极小值，这种改动足以导致真实的集合中位数发生迁移，从而使该算法输出的答案失效。
因此，任何能保证得出正确中位数的算法，在最坏情况下必须至少将输入中的全部 $N$ 个数据各检查一次，所需操作次数必然满足 $C(N) \ge N$。由大 $\Omega$ 定义可知其下界为 $\Omega(N)$。

【答案】
必须至少检查输入数据中的每一个元素（执行至少 $N$ 次检查），否则未被审查的数据发生极端改变将直接导致结果错误，因此问题固有的理论下界为 $\Omega(N)$。
