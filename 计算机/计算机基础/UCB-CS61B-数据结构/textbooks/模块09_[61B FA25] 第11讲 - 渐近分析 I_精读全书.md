## 渐近分析：算法运行效率的数学刻画
> 对应块：BLK09 | 覆盖分集：P26 | 块标题（分集名）：《[61B FA25] 第11讲 - 渐近分析 I》

今天我们把视线彻底换个方向。

在前十节课里，我们所有的精力几乎都扑在“如何写出漂亮且健壮的代码”上。我们熟悉了调试器（debugger）、掌握了单元测试的编写、摸透了 IntelliJ 的高级用法，还学习了如何利用 Java 的面向对象机制来驾驭程序的复杂度。我们掌握了数据结构的基础，但从这一讲开始，我们的目标发生了一次重大的战略转移：**我们不再只关心代码写得漂不漂亮，而是要全力以赴节省计算机的时间、内存和能源**。

接下来的三讲，我们要沉下心来，为算法和数据结构分析奠定坚实的数学基础。这门课剩下的二十多讲，要么是在这些数学工具的指引下设计更精妙的数据结构，要么是带着这些效率意识重返现实世界的软件工程。

### 有序数组查重：直觉与形式化的鸿沟

为了把问题讲透，我们先看一个非常简单且经典的问题：判断一个**有序数组**中是否存在重复元素。

给定一个已经排好序的数组 $A$，是否存在两个不同的索引 $i$ 和 $j$，使得 $A[i] == A[j]$？

面对这个问题，最容易想到的办法是一种笨拙的穷举策略：把数组里的每一对元素都拿来比一遍。第 0 个和第 1 个相等吗？不相等。第 0 个和第 2 个相等吗？不相等。以此类推，把所有两两组合查个底朝天。

```java
public class DupFinder {
    // 笨拙做法：检查所有可能的配对组合
    public static boolean dup1(int[] A) {
        for (int i = 0; i < A.length; i += 1) {
            for (int j = i + 1; j < A.length; j += 1) {
                if (A[i] == A[j]) {
                    return true;
                }
            }
        }
        return false;
    }

    // 巧妙做法：利用数组有序的先验条件，仅检查相邻元素
    public static boolean dup2(int[] A) {
        for (int i = 0; i < A.length - 1; i += 1) {
            if (A[i] == A[i + 1]) {
                return true;
            }
        }
        return false;
    }
}
```

代码很清楚：`dup1` 嵌套了两个 `for` 循环，而 `dup2` 只有一个循环。

直觉上，你们一定会脱口而出：“`dup2` 显然更好、更快，因为它只循环了一次，做的事情少得多，而且它们返回的结果完全相同！”

但作为计算机科学家，我们不能止步于“感觉上更快”或者“只循环了一次”。说“两个循环不如一个循环快”，这种论据既模糊又经不起推敲。如果一个循环内部干了一万件重型计算，而两个循环内部每次只做一次微小的加法呢？

我们需要一套**简洁、在数学上高度严谨、同时能清晰展示算法优劣**的形式化分析方法。

### 物理时钟与实验计时的现实局限

最直接的比较方法，当然是拿物理时间说话——也就是时钟时间（Wall-clock Time）。

我们可以写一个测试程序，从命令行参数接收一个规模 $N$，在内存中生成一个长为 $N$ 的大数组，然后调用 `dup1` 和 `dup2`。在代码里记录开始时间与结束时间相减，或者在终端直接用 Unix 自带的 `time` 命令（Mac、Linux、Windows 的 WSL，或者 PowerShell），甚至拿手机秒表掐时间。

在课前，我特意在自己的电脑上做了一组对照实验。输入是一个包含 10 万个整数的数组，里面故意不放任何重复项。

实验结果立竿见影：
- `dup1` 耗费了整整好几秒（随着规模加大，算一个数据点我得坐在屏幕前死等十几秒）；
- `dup2` 几乎是瞬时返回，连一毫秒都感觉不到。

如果把不同规模下的耗时绘制成曲线图，`dup1` 的曲线像一根陡峭的抛物线迅速蹿上天花板，而 `dup2` 紧贴着底部平缓前进。

直接跑代码测耗时，确实很直观、操作简单。但如果把它作为评价算法优劣的标准，存在着致命的缺陷：

1. **耗时且不可行**：遇到低效算法或超大规模数据时，测试一次可能要等几分钟、几小时甚至几天。
2. **极度缺乏稳定性与再现性（偶然性过高）**：
   - **硬件平台差异**：在最新的高性能工作站上跑出来的耗时，跟在手机、老旧轻薄本或者闲置树莓派上跑出来的结果完全不同；
   - **运行环境影响**：不同的编译器优化级别、不同版本的 Java 虚拟机即时编译器（JIT）、后台其他进程的 CPU 抢占，都会剧烈扰动时钟读数；
   - **输入数据的严重偏置**：如果传给这两个函数一个“开头两位就是重复元素”的数组（例如 `[1, 1, 2, 3, ...]`），`dup1` 和 `dup2` 都会在执行第一次比对时立刻返回 `true`，耗时同样都是几纳秒。单纯的时钟读数完全掩盖了算法在不同输入形态下的本质区别。

### 操作计数法：从具体数字到符号抽象

既然物理秒表不可靠，第二种思路是：**我们不去测时间，而是去清点代码执行到底发生了多少次具体的操作**。

#### 具体规模下的精确清点

假设我们把数组规模固定为一个具体数字，比如 $N = 10000$。我们把代码里发生的所有微观操作拉出一张清单，逐一盘点它们在最坏情况下（即数组中没有任何重复元素，算法必须硬着头皮查到最后）究竟执行了多少次：

- `int i = 0` 变量初始化：只在循环开始时发生 1 次；
- `int j = i + 1` 内层初始化：外层每轮都要初始化一次，共发生 10000 次（最好情况下如果首位就命中，则只发生 1 次）；
- 小于比较 `<`：外层循环比较 10001 次，内层循环比较的次数累加起来，最坏情况下大约是 50005001 次（约 5000 万次）；
- 自增操作 `i++` 与 `j++`：分别发生约 10000 次和约 5000 万次；
- 相等比较 `A[i] == A[j]`：最坏情况下比较了 $\frac{10000 \times 9999}{2} \approx 49995000$ 次；
- 数组内存访问：每次相等比较需要读取两个元素，访问次数是比较次数的整整两倍，约 1 亿次。

> **结论**：这种操作计数的巨大优势在于**机器无关性**。无论你在超级计算机还是智能手表上运行这段代码，这 5000 万次比较都是雷打不动的客观事实；同时，它也通过“最好”与“最坏”两组数字成功刻画了**输入依赖性**。

但它的代价极其高昂：手算这样一张表格极其琐碎耗时，而且一旦脱离了硬件，光看着“5000 万次操作”，你依然回答不了“在现实中它到底跑 1 秒还是 15 秒”。

#### 符号推导与形态初显

为了摆脱“$N = 10000$”这种随手捏造的数字局限，我们可以更进一步，用数学符号 $N$ 来表示操作次数。

对于 `dup1`，在最坏情况下：
- 内层初始化 `j = i + 1` 的次数介于 $1$ 到 $N$ 之间；
- 小于号比较 `<` 的总次数，本质上来自于代数求和公式 $\frac{(N + 3)(N + 2)}{2}$；
- 相等比较 `A[i] == A[j]` 的次数严格等于 $\frac{N(N - 1)}{2}$。

符号推导让我们看到了**算法的扩展性（Scalability）**。我们不再纠结于具体的运行纳秒数，而是看清了随着规模 $N$ 的增长，操作量究竟呈现怎样的数学“形状”（Shape）。

然而，这种符号统计依然存在局限：
- 极其繁琐，推导过程中极容易被“差一错误”（Off-by-one error）绊倒；
- 忽略了不同微观操作本身的耗时差异。在现代底层架构中，小于比较、自增、内存读取的耗时并不一致；
- 现代硬件拥有分支预测、多级缓存与指令流水线，真实耗时绝对不是微观操作次数的简单加权累加。

顺便提一句，课堂上有的同学问起昨晚湾区的那场小地震（住加州这二十年里它算得上第二强了，有同学住在 14 楼晃得够呛，我自己带娃住 Airbnb 时连床头挂的冲浪板都得提前拆下来以防震落，家里还顺便抓了 4 只老鼠带去野外放生喂了花生草莓）。生活中的突发扰动就像硬件底层的微观抖动一样难以精确预测，但只要抓住主干结构，我们就能稳坐钓鱼台。

### 算法形态的较量：抛物线终究不敌直线

当我们审视操作量与规模 $N$ 的数学关系时，一个关键的事实浮出水面：**不同的算法，其操作量随输入规模增长的“形态”是截然不同的**。

`dup1` 展现出的是一条抛物线（二次方形态），而 `dup2` 展现出的是一条倾斜的直线（线性形态）。

为什么我们如此笃定“直线必然击败抛物线”？

#### 极大规模下的渐进行为

如果你的系统只需要处理几百个数据项，或者你只是在为班级几个朋友搭一个小工具，抛物线算法与直线算法的运行时间可能只差几微秒，用户根本无法感知。

但在真实的工业级场景中——处理包含数十亿粒子的天体物理模拟、服务数亿用户的社交网络图谱、吞吐海量金融交易订单、或者对 4K 视频流进行逐帧重编码——数据规模 $N$ 是极其庞大的。

在这种极端体量下，我们唯一关心的，就是算法在 $N \to \infty$ 时的**渐进行为（Asymptotic Behavior）**。

#### 常数系数遮盖不住阶数的鸿沟

有人可能会提出反驳：“假设有两个算法处理 $N$ 个元素，算法 A 需要执行 $2N^2$ 步操作，而算法 B 需要执行 $500N$ 步操作。算法 B 的常数系数高达 500，难道它总是优于算法 A 吗？”

我们来看这两条曲线的演变：

```text
操作量
  ^
  |                                        / 抛物线：2N^2
  |                                    . -'
  |                                . -'  / 直线：500N
  |                            . -'  . -'
  |                        . -'  . -'
  |                    . -'  . -'
  |                . -'  . -'
  |            . -'. -'  (交叉点 N = 250)
  |        . -'.-'
  |    . -'.-'
  |.-'. -'
  +---------------------------------------------> 规模 N
```

读图说明：在规模较小（$N < 250$）时，直线 $500N$ 确实处于抛物线 $2N^2$ 上方；但一旦跨越交叉点，$N^2$ 的几何级数扩张力便彻底占据主导，将线性函数远远甩在身后。

无论你在直线上乘上多么夸张的常数（哪怕是 50000），只要 $N$ 足够大，抛物线必然在某个临界点之后无可挽回地大幅落后。

| 算法形态 | $N = 100$ | $N = 10,000$ | $N = 1,000,000$ |
| :--- | :--- | :--- | :--- |
| **线性（$N$）** | $< 1$ 毫秒 | 约 1 毫秒 | 约 0.1 秒 |
| **二次方（$N^2$）** | 约 1 毫秒 | 约 2 分钟 | 约 3 小时 |
| **三次阶（$N^3$）** | 约 0.1 秒 | 约 3 个月 | 约 30,000 年 |
| **指数阶（$2^N$）** | 远超宇宙寿命 | 无法想象 | 无法想象 |

当 $N$ 达到几十时，指数级或阶乘级算法（如 $N!$）的可能组合数就已经堪比一副扑克牌的排列总数（$52! \approx 8 \times 10^{67}$），任何现代超级计算机穷尽寿命也算不完。

> **提示**：现实工程中确实存在极罕见的特例。例如朴素矩阵乘法的时间复杂度是 $N^3$，学术界存在渐进复杂度更低的高阶算法（如 Strassen 算法等）。但由于那些算法附带的常数开销过于庞大，往往要等到输入规模超出常规内存极限时才能体现优势。因此在工业界中，有时人们仍会选择常数更小的立方级实现。但在本课程中，我们绝大多数时候坚定地关注**增长形态**。

### 告别繁琐大表：增长阶与四步简化法则

为了证明 `dup1` 是抛物线而 `dup2` 是直线，我们难道每次都要耐着性子列出几十行微观操作，推导出一大堆像 $\frac{(N+3)(N+2)}{2}$ 这样极其繁琐的代数式，然后把其中 99% 的琐碎细节手工划掉吗？

这太笨拙了。

参考 Robert Sedgewick 与 Kevin Wayne 在普林斯顿经典教材《Algorithms 4th Edition》中的分析思想，我们可以将这套繁琐的泥潭升华为一套干脆利落的**四步简化法则**，直接提炼出算法的**增长阶（Order of Growth）**。

#### 简化一：仅聚焦最坏情况（Worst-case Analysis）

在绝大多数场景下，我们抛弃最好情况。为什么？因为最好情况往往是廉价的巧合（比如第一个元素就命中），它无法为系统的可靠性提供任何兜底承诺。

我们往往最关心的是：“万一运气最差，我的程序究竟会慢到什么地步？”

最坏情况为我们提供了一个坚实的性能上限。如果一个算法在最坏情况下的表现都是线性的，那么在日常典型场景下，它无论如何也绝不可能恶化成二次方。

#### 简化二：挑选最具代表性的操作作为成本模型（Cost Model）

我们根本不需要去统计每一个变量的赋值、自增与初始化。

我们只需要在代码中挑选**一个**频繁执行的关键操作，用它的执行频次来代表算法的整体开销。这个被选中的操作，就叫做我们的**成本模型（Cost Model）**。

> **核心原则**：成本模型必须位于最深层循环的内部（系统的性能瓶颈所在），而绝不能挑选外层循环的控制语句。

对于 `dup1`，挑选内层的“相等比较 `==`”作为成本模型是极佳的选择；而如果错误地挑选外层 `int i = 0`，就完全丢失了双重循环的本质。

#### 简化三：忽略低阶项（Ignore Lower Order Terms）

假设一个算法最内层的操作总次数由多项式给出：
$$T(N) = 100N + 2N^3 + 5000$$

从微积分极限的角度来看，当 $N \to \infty$ 时：
$$\lim_{N \to \infty} \frac{100N + 2N^3 + 5000}{2N^3} = 1$$

除了最高次项 $2N^3$ 之外，其余的低阶项 $100N$ 和常数项 $5000$ 在决定增长趋势时完全不值一提。因此，直接把低阶项扔掉。

#### 简化四：忽略常数系数（Ignore Multiplicative Constants）

在最高阶项 $2N^3$ 中，前面的系数 2 同样可以忽略。

既然我们在一开始就已经粗粒度地舍弃了底层硬件的操作耗时差异，那么保留一个“除以 2”或者“乘上 2”的常数系数就毫无严肃的数学意义。$\frac{1}{2}N^2$、$2N^2$ 与 $100N^2$ 都在沿着抛物线的轨道扩张。

> **结论**：通过**锁定最坏情况** $\to$ **选定内层成本模型** $\to$ **舍弃低阶项** $\to$ **抹去常数系数**，我们直接将任何复杂的循环代码降维提炼为其核心的增长阶（例如 $N^2$ 或 $N$）。

### 经典推导实战：高斯求和与直角三角形几何直觉

现在，让我们用这套清爽的法则来重新审视 `dup1` 的增长阶。

我们在内层选定 `A[i] == A[j]` 作为成本模型。最坏情况下（无重复元素），所有的比对都会发生。

当规模为 $N$ 时，我们观察索引变量 $i$ 与 $j$ 的所有可能取值组合：
- 当 $i = 0$ 时，$j$ 取值遍历 $1, 2, 3, \dots, N-1$（共发生 $N-1$ 次比较）；
- 当 $i = 1$ 时，$j$ 取值遍历 $2, 3, \dots, N-1$（共发生 $N-2$ 次比较）；
- 当 $i = 2$ 时，$j$ 取值遍历 $3, \dots, N-1$（共发生 $N-3$ 次比较）；
- $\dots\dots$
- 当 $i = N-2$ 时，$j$ 仅取值 $N-1$（发生 $1$ 次比较）；
- 当 $i = N-1$ 时，内层循环不启动（发生 $0$ 次比较）。

总操作次数 $C$ 即为前 $N-1$ 个自然数的求和：
$$C = 1 + 2 + 3 + \dots + (N - 2) + (N - 1)$$

#### 代数推导：高斯倒序相加技巧

我们可以借用高斯小时候发明的巧妙手法，把式子正着写一遍、倒着写一遍：
$$C = 1 + 2 + \dots + (N - 1)$$
$$C = (N - 1) + (N - 2) + \dots + 1$$

将两式上下对应相加，一共有 $N-1$ 对组合，且每一对的和都严格等于 $N$：
$$2C = \underbrace{N + N + \dots + N}_{N - 1 \text{ 个 } N} = N(N - 1)$$
$$C = \frac{N(N - 1)}{2} = \frac{1}{2}N^2 - \frac{1}{2}N$$

应用我们的简化法则：
1. 舍弃低阶项 $-\frac{1}{2}N$；
2. 抹去常数系数 $\frac{1}{2}$；
最终稳稳锁定增长阶为 **$N^2$**。

#### 几何视角：直角三角形面积法

代数推导虽然精确，但在期末考试或未来的技术考核中，我更希望看到大家建立起一种**几何直觉**。

我们把外层变量 $i$ 和内层变量 $j$ 映射为一个二维平面网格矩阵。以 $N = 6$ 为例：

```text
  j ->  0   1   2   3   4   5
i
0      [·]  *   *   *   *   *    (5 次比较)
1      [·] [·]  *   *   *   *    (4 次比较)
2      [·] [·] [·]  *   *   *    (3 次比较)
3      [·] [·] [·] [·]  *   *    (2 次比较)
4      [·] [·] [·] [·] [·]  *    (1 次比较)
5      [·] [·] [·] [·] [·] [·]   (0 次比较)
```

读图说明：矩阵中的 `*` 代表算法实际发生的比较操作，它们在对角线上方构成了一个直角边长为 $N-1$ 的直角三角形；而 `[·]` 则表示未被执行的组合。

这个几何图景一目了然：
- 整个正方形网格的面积是 $N \times N = N^2$；
- 我们实际执行的操作集合，正好占据了该正方形主对角线上方的半个区域——也就是一个直角三角形；
- 三角形的面积公式是 $\frac{1}{2} \times \text{底} \times \text{高} \approx \frac{1}{2}N^2$。

当正方形随 $N$ 放大时，三角形面积的增长速度与正方形完全保持同步。因此，你连笔都不需要动，光凭几何图形就能瞬间断定：**它的增长阶必然是 $N^2$**！

### 严谨数学刻画：大 $\Theta$ 记号的三明治定义

在工程沟通中，我们可以随口说“它的增长阶是抛物线”或者“它是二次方的”。但在严谨的计算机科学与算法理论中，我们必须使用规范的数学语言：**大 $\Theta$ 记号（Big-Theta Notation）**。

如果一个算法的运行时间函数 $R(N)$ 具有与 $f(N)$ 相同的增长阶，我们记作：
$$R(N) \in \Theta(f(N))$$
（在很多教材或文献中，大家也习惯随手写成等号 $R(N) = \Theta(f(N))$，两者指代同一件事。）

> **易错点**：$\Theta(f(N))$ 在数学本质上是一个**函数的集合（Family of Functions）**。说 $R(N) \in \Theta(N^2)$，意思是 $R(N)$ 属于“所有以二次方速率增长的函数大家族”。

#### 形式化数学定义

> **定义**：对于函数 $R(N)$ 与 $f(N)$，若存在正实数常数 $k_1$、$k_2$ 以及一个阈值 $N_0$，使得对所有 $N \ge N_0$，均满足：
> $$k_1 \cdot f(N) \le R(N) \le k_2 \cdot f(N)$$
> 则称 $R(N) \in \Theta(f(N))$。

这个定义乍看像是一串冰冷的数学公式，但它背后的几何图象非常生动——这就是经典的**三明治夹逼法则（Sandwich Theorem）**。

#### 几何三明治夹逼

考虑一个带有复杂波动的函数：
$$R(N) = 4N^2 + 40\sin(N)$$

因为 $\sin(N)$ 会在 $[-1, 1]$ 之间周期性震荡，导致该函数的曲线在局部呈现出上下微小的波浪状抖动。

但这微小的抖动在大尺度下根本无关大局。我们只需要拉开镜头，在下方放置一条较扁平的抛物线 $3N^2$（取 $k_1 = 3$），在上方放置一条较陡峭的抛物线 $5N^2$（取 $k_2 = 5$）：

```text
耗时 R(N)
    ^
    |                                / 上界：5N^2
    |                            . -'
    |                        . -'   ~ ~ 真实波动曲线 R(N) = 4N^2 + 40sin(N)
    |                    . -'  ~ ~ '
    |                . -' ~ ~ '    / 下界：3N^2
    |            . -'~ ~ '     . -'
    |        . -'~ '       . -'
    |    . -'          . -'
    |.-'           . -'
    +------------------------------------> 规模 N
                 N >= N_0
```

读图说明：当 $N$ 越过阈值 $N_0$ 后，无论局部如何震荡，真实的耗时函数 $R(N)$ 都被牢牢夹在上下两条抛物线之间。它既不会比抛物线增长得更快，也不会比抛物线增长得更慢。从长远来看，它本质上就是一条抛物线！

常见典型函数的增长阶归纳：
- 常数函数（例如 $R(N) = 5$）：增长阶为 $\Theta(1)$；
- 复合多项式（例如 $R(N) = \frac{1}{2}N^2 - \frac{1}{2}N$）：增长阶为 $\Theta(N^2)$；
- 震荡多项式（例如 $R(N) = 4N^2 + 40\sin(N)$）：增长阶为 $\Theta(N^2)$。

至于大 $O$ 记号（只关注上界）与大 $\Omega$ 记号（只关注下界），我们留到周一的课程详细展开。大家今天先把大 $\Theta$ 的严谨夹逼思想吃透，这就足够支撑我们后续所有的复杂度推演了。

### 本讲提到的题目

#### 题目一：`dup2` 最坏情况操作量与访问倍率分析

**题干描述**：
对于有序数组查重算法 `dup2`：
1. 请给出在最坏情况下（数组中无重复元素），循环内判断操作关于规模 $N$ 的增长阶；
2. 为什么在最坏情况下，数组内存访问的次数大约是相邻比较次数的两倍？

**解析依据与答案**：
1. **增长阶判定**：在 `dup2` 中，循环从 $i = 0$ 遍历至 $i = N - 2$，总共进行 $N - 1$ 次相邻元素比较。根据四步简化法则，忽略常数项 $-1$ 与一阶系数，其增长阶严格为线性阶，即 $\Theta(N)$。
2. **两倍访问成因**：在单层循环内部，代码执行的判断语句为 `if (A[i] == A[i + 1])`。为了完成一次相等判断，计算机体系结构必须分别将索引 $i$ 处的元素和索引 $i + 1$ 处的元素从数组内存读取到 CPU 寄存器中。因此，每一次比较必然伴随着两次独立的数组元素读取操作。在执行 $N - 1$ 次比较时，数组访问次数严格等于 $2(N - 1)$ 次，故约为比较次数的两倍。

#### 题目二：高阶多项式函数的增长阶提取

**题干描述**：
假设某算法在最坏情况下的微观操作总耗时可由函数 $R(N) = 100N + 2N^3 + 5000$ 给出，请确定该函数的增长阶，并写出形式化的 $\Theta$ 表达式。

**解析依据与答案**：
根据四步简化法则：
1. **识别主导项**：该函数由一次项 $100N$、三次项 $2N^3$ 与常数项 $5000$ 构成。当规模 $N \to \infty$ 时，高阶项的增速呈压倒性优势，低阶项 $100N$ 与 $5000$ 占比迅速趋近于 0，应当直接忽略；
2. **剥离常数系数**：最高阶项为 $2N^3$，剔除乘性常数系数 2，仅保留其核心数学形态 $N^3$。
因此，该函数的增长阶为三次阶，形式化记作 $R(N) \in \Theta(N^3)$。

#### 题目三：震荡与常数函数的增长阶判定

**题干描述**：
请依据大 $\Theta$ 的形式化定义，判断下列两个函数的增长阶：
1. $f_1(N) = 5$
2. $f_2(N) = 4N^2 + 40\sin(N)$

**解析依据与答案**：
1. **常数函数 $f_1(N) = 5$**：该函数的取值始终为固定常数 5，完全不随输入规模 $N$ 的增长而发生任何形态改变。根据定义，存在常数 $k_1 = 1, k_2 = 10$，使得 $1 \cdot 1 \le 5 \le 10 \cdot 1$ 恒成立。因此其增长阶为常数阶，记作 $f_1(N) \in \Theta(1)$。
2. **震荡函数 $f_2(N) = 4N^2 + 40\sin(N)$**：正弦函数 $\sin(N)$ 的取值严格限制在区间 $[-1, 1]$ 内，故震荡项 $40\sin(N)$ 的取值范围仅为 $[-40, 40]$。当 $N$ 足够大时（例如取 $N_0 = 10$），选取下界系数 $k_1 = 3$ 和上界系数 $k_2 = 5$，不等式 $3N^2 \le 4N^2 + 40\sin(N) \le 5N^2$ 对所有 $N \ge N_0$ 均成立。真实曲线被上下两条抛物线紧密夹逼，其增长阶由最高阶项决定，记作 $f_2(N) \in \Theta(N^2)$。
