## 快速排序进阶：从运行时间谜题到霍尔原地分区的工程奥秘
> 对应块：BLK31 | 覆盖分集：P76 | 块标题（分集名）：《[61B FA25] 第33讲 - 快速排序进阶》

我们在上一讲里已经领教过了各种各样的排序算法。其实看多了你会发现，很多排序算法长得都差不多，它们真正的差异并不在表面的递归框架，而在于底层依托的核心操作究竟是什么。

快速排序（Quicksort）的核心操作，说到底就两个字——**分区（Partitioning）**。

今天我们要彻底把快速排序拆开来看。很多排序算法我只用半节课就带过了，但快速排序必须独占一整讲，因为它肚子里的干货实在太多了。它的运行时间表现充满戏剧性：最好情况下快如闪电，最坏情况下却能直接跌进平方级的泥潭；但更神奇的是，在现实工业界的大规模实测中，它却几乎总是所有通用比较排序里跑得最快的那一个。这究竟是为什么？今天我们就来解开这个谜题，并一步步还原托尼·霍尔（Tony Hoare）当年封爵级的经典原地双指针分区设计。

---

### 分区机制：决定快排命运的核心操作

在扎进复杂的运行时间分析之前，我们先花两分钟把快速排序的底牌重新亮出来。

如果完全按照核心操作来命名，快速排序本该叫“分区排序”（Partition Sort）。它的算法骨架极其纯粹：从数组中挑选一个元素作为**基准（Pivot）**（最朴素的做法就是直接选最左侧的第一个元素），然后通过重新排列数组，把所有比基准小的元素挪到左边，所有比基准大的元素挪到右边。

```text
原始数组:   [ 32, 15, 19, 17, 41, 26,  2 ]
                 |
               以 32 为基准进行分区 (Partition)
                 v
分区结果:   [ 15, 19, 17, 26,  2 ]  32  [ 41 ]
            \___________________/       \____/
                 全部 <= 32             全部 >= 32
```

当这一轮分区结束后，基准元素（比如上面的 32）就已经稳稳地坐落在了它在最终有序数组中应当处于的绝对位置上。

更美妙的事情在于，此时整个排序任务被彻底切分成了两个完全独立的子问题：左边是一堆小于等于 32 的元素，右边是一堆大于等于 32 的元素。32 就像是一道不可逾越的高墙横亘在中央——左侧的数绝不可能跨到右边去，右侧的数也绝不可能溜到左边来。

> **定义**：**分区（Partitioning）** 是将数组重排为两部分的操作，使得基准左侧的所有元素均不大于基准，右侧的所有元素均不小于基准。分区完成后，基准元素即处于其全局最终有序位置，左右两个子数组可分别独立求解。

既然两个子问题互不干扰，我们接下来怎么处理它们都行。你哪怕任性地用归并排序去解左右两边都可以，但我们既然已经有了这么好用的工具，当然是继续递归调用快速排序自身。不断切分下去，直到所有子数组的规模都缩减为 1。而一个大小为 1 的数组天然就是有序的，整个数组便在不知不觉中完成了全排列。

现在关键的问题来了：这个算法到底要跑多久？它的性能究竟受什么支配？答案全系于每次分区后基准最终所处的位置。

### 最好与最坏：天壤之别的运行时间

快速排序的运行时间完全取决于分区切得有多准。我们先来看最好和最坏的两个极端。

#### 完美对半切与 n log n 的最好情况

首先假设我们运气好到了极点：每一次选出的基准元素，在分区完毕后恰好都落在了子数组的正中心，左右两侧剩余的元素数量完全相等。

```text
第 0 层:                 [      N 个元素      ]         -> 分区耗时: N
                             /            \
第 1 层:          [ N/2 个元素 ]        [ N/2 个元素 ]    -> 分区耗时: N/2 + N/2 = N
                    /        \            /        \
第 2 层:        [ N/4 ]    [ N/4 ]    [ N/4 ]    [ N/4 ]  -> 分区耗时: 4 * (N/4) = N
                 ...        ...        ...        ...
第 log2 N 层:   [ 1 ] [ 1 ] [ 1 ] [ 1 ] ... [ 1 ] [ 1 ]   -> 单元素天然有序
```

我们来算一算这种完美状态下的工作量：
1. **每一层的总开销是多少？** 在第 0 层，对长度为 $N$ 的数组进行分区，我们需要线性扫描整个数组，耗时为 $N$。进入第 1 层后，我们面对两个规模为 $N/2$ 的子问题，各自做一次分区分别耗时 $N/2$，合起来依然是 $N/2 + N/2 = N$。再下一层，四个规模为 $N/4$ 的子问题，分区耗时相加还是 $4 \times (N/4) = N$。子问题的规模虽然在不断折半，但子问题的数量却在以成倍的速度递增，两者正好相互抵消。因此，**整棵递归树的每一层，总工作量都死死稳定在 $N$**。
2. **总共有多少层？** 规模从 $N$ 开始，每一轮除以 2，直到变成 1。这显然就是不断除以 2 直到为 1 的次数，也就是 $\log_2 N$。

树高为 $\log_2 N$ 层，每层的代价都是 $N$，总运行时间自然就是：

$$\Theta(N \log N)$$

这与归并排序的分析如出一辙。在这种完美平衡的理想状态下，子问题规模呈指数级迅速收缩，算法效率达到了理论上限。

#### 极端偏斜与已排序数组的平方陷阱

但好运气不可能永远眷顾我们。现在来看看另一个极端：假设我们的运气糟糕透顶，每次挑中的基准，恰好都是当前剩余元素里的最小值。

如果选中的基准已经是最小值，分区后会发生什么？
左侧没有任何比它小的元素，所以左子问题的大小变成了 0；而剩下所有比它大的 $N-1$ 个元素，全部一股脑挤到了右边！

```text
第 0 步 (规模 N):     [ Pivot ] [  剩余 N - 1 个元素全部在右侧  ]   -> 分区工作量: N
                                      /
第 1 步 (规模 N-1):              [ Pivot ] [ 剩余 N - 2 个元素 ]  -> 分区工作量: N - 1
                                                /
第 2 步 (规模 N-2):                        [ Pivot ] [ ... ]   -> 分区工作量: N - 2
                                                         ...
```

本该把问题一分为二的分区操作，此时只削掉了一个孤零零的元素。接下来面对规模为 $N-1$ 的右侧子问题，如果你又倒霉地选到了其中的最小值，问题就再次退化为规模 $N-2$ 的子问题。

把每一层的代价加起来，总工作量为：

$$N + (N - 1) + (N - 2) + \dots + 2 + 1 = \frac{N(N + 1)}{2} = \Theta(N^2)$$

> **易错点**：快速排序并不总是一路疾驰。如果每次切分都极端偏斜，它的递归树就会退化成一个直角三角形。这个三角形的底是 $N$，高也是 $N$，整个面积就是 $\Theta(N^2)$。

那么，什么样的输入会导致这种灾难？答案让人哭笑不得：**已经排好序的数组（或完全逆序的数组）**！

如果你总是固定挑最左侧的元素做基准，面对一个像 `[1, 2, 3, 4, 5, 6]` 这样本就整整齐齐的数组，第一次选 1，剩下 5 个都在右边；第二次在右边选 2，剩下 4 个又全在右边……快速排序最大的怪癖就在于：**面对最简单的有序输入，它反而会彻底卡壳并退化至最耻辱的 $\Theta(N^2)$ 泥沼**。

相比之下，归并排序就不吃这一套——它不管数组长成什么样，每次都机械地从物理正中间一刀切开，因此无论最好还是最坏，始终稳稳维持在 $\Theta(N \log N)$。

这就带来了一个尖锐的质疑：既然最坏情况能烂到 $\Theta(N^2)$，它凭什么被称为“快速”排序？

### 破除平方魔咒：快排为什么在现实中极速狂飙

要严谨证明快速排序的平均复杂度需要用到复杂的概率分布模型与积分推导，我们在此不把大家拖入繁复的数学泥潭。我给你们两个极其直观、颠覆认知的论点，看完你们就会明白：为什么这可怕的 $\Theta(N^2)$ 在实际工程中几乎根本遇不到。

#### 论点一：哪怕每次都极端失衡（10% 划分假说）

我们先来看一个倒霉透顶的假设。

假设你今天运气差到了家，每次拿一个十面骰子掷点，回回都掷出 1——这意味着每一次选择基准进行分区，左右两边都极度不均衡：左边只分到了可怜的 10% 的元素，而右边堆积了整整 90% 的庞大体量。

```text
第 0 层:                          [ 100% N ]                    -> 工作量: N
                                  /        \
第 1 层:                  [ 10% N ]        [ 90% N ]            -> 工作量: 0.1N + 0.9N = N
                          /       \        /       \
第 2 层:              [ 1% N ]  [ 9% N ] [ 9% N ]  [ 81% N ]    -> 工作量: 0.01N + 0.09N + 0.09N + 0.81N = N
```

我们来算一算这棵极度偏瘫的递归树的运行时间：
1. **每一层的总工作量**：第 0 层是原问题的 100%，耗时 $N$；第 1 层是 $10\%$ 和 $90\%$，加起来依然是原数组的全部元素，耗时还是 $N$；第 2 层是 $1\% + 9\% + 9\% + 81\% = 100\%$，工作量依然是 $N$。虽然较小的分支会更早达到大小为 1 的递归基，但在最深分支结束前，每一层的总工作量始终都不超过 $N$。
2. **递归树的最深高度是多少？** 树的最深路径显然沿着每次吃下 90% 数据的最重子问题往下延伸。规模缩减序列为：$N, 0.9N, (0.9)^2 N, \dots, (0.9)^k N = 1$。
   这就相当于在问：$N$ 每次乘以 0.9，乘多少次会缩减到 1？

$$(0.9)^k N = 1 \implies k = \log_{1 / 0.9} N = \log_{10 / 9} N$$

翻开高中数学课本的换底公式：

$$\log_{10 / 9} N = \frac{\ln N}{\ln(10 / 9)} \approx 9.49 \ln N = \Theta(\log N)$$

> **结论**：对数的底数根本不影响渐进复杂度的大局，它仅仅引入了一个常数乘法因子！即使每次切分都恶劣到九一开（10% 对 90%），整棵树的高度依然牢牢处于 $\Theta(\log N)$ 级别。每层工作量是 $N$，总运行时间依然坚挺在 $\Theta(N \log N)$！

这就给我们吃了一颗定心丸：要触发可怕的 $\Theta(N^2)$，算法必须倒霉到每一轮都只削掉常数个元素（如 1 个）；只要每次划分能保留住哪怕固定比例的一小截（哪怕是 99% 对 1%），规模都在呈几何级数快速萎缩，整体就绝不会退化到平方级。

#### 论点二：快排与二叉搜索树排序的惊人同构

第二个论点更加震撼，它揭示了数据结构与算法之间惊人的底层暗合：**快速排序在本质上，就是一棵二叉搜索树（BST）的中序遍历排序！**

大家还记得堆排序（Heapsort）吗？把所有元素塞进一个堆里，再逐个弹出来，顺序就自然排好了。顺着这个思路，我们完全可以发明一种“二叉搜索树排序”（BST Sort）：
拿一个任意的未排序数组，不搞什么复杂的红黑树旋转，也不搞什么平衡因子，就用最原始朴素的插入规则，把数组元素一个接一个插进一棵 BST 里；全部插入完成后，对这棵树做一次中序遍历（左-根-右），输出的结果必然就是有序的。

我们现在来看一个具体的数组：`[5, 3, 2, 1, 7, 8, 4, 6]`。

我们一边执行朴素 BST 插入，一边对照快速排序以 5 为基准的分区过程：

```text
【BST 插入轨迹】                         【快排以 5 为基准的分区】
       5 (根节点)                       基准 = 5
      / \                              比 5 小的进入左侧: [3, 2, 1, 4]
     3   7                             比 5 大的进入右侧: [7, 8, 6]
    / \   \
   2   4   8                           左侧递归以 3 为基准: [2, 1] 3 [4]
  /       /                            右侧递归以 7 为基准: [6] 7 [8]
 1       6
```

我们来仔细核对两者在执行过程中所发生的每一对数字比较：
1. **插入 3**：必须先跟根节点 5 比较（$3 < 5$，往左走）。
   在快排里，以 5 为基准分区时，3 同样必须与 5 比较。
2. **插入 2**：先比 5（$2 < 5$，往左），再比 3（$2 < 3$，往左）。
   在快排里，2 先在以 5 为基准的分区中与 5 比较并落入左侧；随后在左侧子问题中，选 3 为基准，2 再次与 3 比较！
3. **插入 7、8、4、6……**：所有元素在插入 BST 时，因为 5 是整棵树的根，**所有元素都必须无条件先与 5 比一次**；而在快排的第一轮分区里，也恰好是**所有元素都必须无条件与基准 5 比一次**！
4. 随后，所有小于 5 的元素（3, 2, 1, 4）在 BST 中全被导向 5 的左子树，它们在后续插入中会且仅会与左子树中的节点比较；而在快排中，这些小于 5 的元素被划入左子数组，后续递归也只会在它们内部互相比较。大于 5 的元素同理！

> **核心洞察**：对于任意给定的无序数组，**快速排序所执行的元素两两比较集合，与将该数组按相同顺序插入朴素二叉搜索树所执行的比较集合完全绝对一致！** 两者在算法深层逻辑上完全等价。

既然快排与 BST 排序完全同构，那我们在分析 BST 时掌握的全部理论就可以直接无缝平移到快排身上：
- 对随机序列构建 BST，树的平均高度是 $O(\log N)$，每次插入平均耗时 $O(\log N)$，$N$ 次插入的总期望时间就是 $O(N \log N)$。这直接证明了**快速排序在处理随机输入时的期望时间必然是 $\Theta(N \log N)$**！
- BST 什么时候会退化成一条细细长长的单链（Spindly Tree）？输入是有序数组的时候！插入有序数组建树耗时 $\Theta(N^2)$，这刚好精确对应了快排在面对有序数组时退化为 $\Theta(N^2)$ 的最坏情况！

#### 实验实测：百万次比较在隔壁城市的遥远虚空

在真实的计算机硬件上，情况又是怎样的？

我们做过一组严谨的实测实验：生成海量规模为 $N = 1000$ 的随机数组，分别用快速排序对它们进行排序，并精确统计每一个数组完成排序所需的总比较次数。

我们先在心里打个底：
对于 $N = 1000$，如果是理想的 $N \log_2 N$，比较次数大约是多少？
因为 $2^{10} = 1024 \approx 1000$，所以 $\log_2(1000) \approx 10$。

$$N \log_2 N \approx 1000 \times 10 = 10,000 \text{ 次}$$

实验统计出来的柱状分布图展现出了极其震撼的一幕：
- 绝大多数随机数组的实际比较次数，极其紧密地簇拥在 **11,000 到 13,000 次**之间，这与理论的 10,000 次极为贴近；
- 运气稍差一些的数组，耗费了大约 14,000 次比较，这在统计图谱里已经属于极少见的离群点；
- 需要耗费 15,000 次比较的样本，在成千上万次测试中已经寥寥无几。

那么，理论上的最坏情况 $N^2$ 在这张图的什么位置？
$N = 1000$ 时，$N^2 = 1,000,000$（一百万次比较）。

在数据图表上，从 1.2 万到 100 万，坐标轴要向右拉长近百倍！如果把我们展示实验结果的投影屏幕当作尺度基准，100 万那个刻度根本不在教室里，你得走出教学楼、穿过校园，一直走到离我们好几英里外的隔壁城市才能标上那个点！

在随机数组的世界里，撞上百万次比较的概率无限趋近于零。那种几率就像明天出门正好撞上世界末日或者小行星精确砸在头顶一样渺茫。正因如此，即便最坏情况很吓人，快速排序在现实测试中依然是无可争议的速度之王。

> **背景轶事**：
> 托尼·霍尔当年在做机器翻译项目时，曾尝试用快速排序给一句话里的单词排序。但句子通常非常短（比如《戴高帽子的猫》这种儿童绘本），对这类极短输入，快排的递归框架反而不如插入排序轻快。多年后 Josh Hug 还曾就这桩趣事给霍尔发过邮件讨论，霍尔也风趣地回应承认：当时自己还年轻，机器又极其昂贵缓慢，探索过程中难免留下这样的时代印记。

### 驯服最坏情况：四种防御策略的权衡

随机数组的表现虽然无可挑剔，但在工程实践中，我们绝不能把命运完全寄托在概率的慈悲上。因为在真实业务场景中，“已经排好序”或者“局部高度有序”的数据俯拾皆是（比如日志流水、按时间归档的交易单）。一旦给原生快排喂入这种数据，程序就会瞬间陷入瘫痪。

我们该如何彻底拆除这个潜藏的平方级定时炸弹？通常有四种应对思路。

#### 拥抱随机性：洗牌与随机基准

既然快排只在面对随机输入时表现无懈可击，而在特定有序结构上容易被针对，那最直接暴力的破局手段就是：**主动打乱确定性**。

具体实现有两种等价方式：
1. **在排序开始前，对整个数组做一次线性时间的原地随机打乱（Shuffle）**；
2. **在每一次分区时，不再机械死板地挑最左边元素，而是生成一个随机索引作为基准**。

这就像影视剧《叛逆者》（Renegade）里那个骑着喷火摩托、长发飘飘浪迹天涯的主角雷诺·雷恩斯（Reno Raines）一样——拥抱不羁的随机性。虽然从理论纯数学的角度来看，随机打乱依然存在亿万分之一的概率刚好洗出一个纯有序数组，但对工程系统而言，这已经足以彻底摧毁任何固定模式的攻击，把最坏情况的发生几率彻底压制到物理不可能的维度。

#### 寻找更好的基准：近似中位数与对抗性漏洞

第二种思路是从根源上解决失衡：既然我们希望每次都能对半平分，那基准就应当去选这组数据的**中位数（Median）**。

但在未排序的数组里，找中位数绝非易事：

> **易错点**：千万不要以为“取中位数”就是直接读取数组中间索引处的元素 `arr[mid]`！在数组尚未排序前，中间格子里的数值可能是整个数组的最大值，也可能是最小值，它的数值大小分布完全是未知的。

为了避免遍历全数组寻找精确中位数的昂贵开销，工程上普遍采用**近似中位数（Approximate Median）**策略，最典型的就是**三数取中法（Median-of-Three）**：
不看全数组，只抽出固定三个位置的数（例如前三个数，或者首、中、尾三个数），挑出这三者中的中间值作为基准。比如面对 `[7, 2, 3]`，中间值是 3，选 3 做基准就远比直接抓取开头的 7 要明智得多。

但这套看似聪明的确定性方案却隐藏着一个巨大的工程安全漏洞：

> **安全警示**：如果基准的选择完全是**确定性且耗费常数时间**的（没有任何随机噪声加入），黑客就可以利用算法源码中的取样规则，精心构造出专门针对该规则的**对抗性输入（Adversarial Inputs / Killer Inputs）**。早期 Java 的内置排序算法就曾因为采用固定的三数取中策略，被安全研究人员通过特定构造的数据直接干到 $\Theta(N^2)$ 崩溃瘫痪，引发拒绝服务（DoS）漏洞。

至于耗费线性时间去寻找绝对精确的中位数，我们稍后会在性能实测中看到，那更是一条得不偿失的弯路。

#### 动态降级与输入预判

除了上述两种主流招式，学术界和极少数高性能库中还存在另外两种策略：
- **运行时间监控与自省降级（IntroSort 思想）**：在快排递归深入的过程中埋设计数器。一旦发现递归深度超过了某个阈值（比如 $2 \log N$），说明当前数据极度恶劣、快排正在失控退化，算法便立刻止损，原地切换为最坏情况拥有坚实 $\Theta(N \log N)$ 保证的归并排序或堆排序。这种策略在工业界被广泛吸收进 C++ STL 的 `std::sort` 中。
- **预处理分析数组**：在动工前先线性扫一遍数组，检查其是否有序或逆序。如果是，直接走特化通道。但这会为所有普通数据平白增添一道常数开销，实战中极少单独采用。

### 变体工坊：从三遍扫描到霍尔双指针的性能蜕变

快速排序之所以充满魅力，在于它拥有其他排序算法望尘莫及的定制自由度。它不是一个死板的单一方程，而是一个可以自由组合的“变体工坊”。

我们可以把快速排序拆解为三个独立的决策维度：
1. **基准选择策略**：是选最左端、随机挑选、三数取中，还是死磕精确中位数？
2. **分区执行算法**：是用消耗额外内存的三遍扫描法，还是原地指针相向扫描？
3. **防退化保护**：是否在开工前执行预先随机洗牌？

这就像走进一家手工冰淇淋店，你可以根据喜好自由挑选不同风味的基底、果酱和配料。但不同的组合搭配在计算机真实运行起来，性能表现却有着天壤之别。

#### 初代变体的滑铁卢：三遍扫描法的常数劣势

在上一讲的启蒙阶段，为了便于理解，我们曾介绍过一种偷懒的**三遍扫描法（Three-Scan Partitioning）**：
开辟一块与原数组等大的临时辅助空间，第一遍扫描原数组，把所有小于基准的数复制过去；第二遍扫描，把所有等于基准的数复制过去；第三遍扫描，把所有大于基准的数复制过去。

现在我们给快排组装出**变体 A**：
- **基准选择**：最左侧元素；
- **分区算法**：三遍扫描法；
- **防御策略**：排序前先执行一次随机洗牌（规避最坏情况）。

我们把这个变体 A 拿去跟 Java 标准的归并排序同台竞技，对同一个大规模数组进行排序，跑出来的结果令人大跌眼镜：

```text
归并排序 (Merge Sort):   1.3 秒
快排变体 A (三遍扫描法): 3.2 秒
```

号称最快的快速排序，居然被归并排序按在地上摩擦，足足慢了一倍以上！

为什么会这样？虽然三遍扫描在渐进分析上也是 $O(N)$，但它为了完成一次分区，需要对同一块内存反反复复完整扫描三次，而且还要不断在新旧数组间搬运数据。这个巨大的常数开销在成千上万次递归调用中被急剧放大，彻底拖垮了性能。

我们必须抛弃这种低效的做法，寻找一种真正高效的原地分区方案。

#### 霍尔双指针原地分区：爵士的传奇设计

计算机科学家托尼·霍尔之所以能凭借快速排序名垂青史并获封爵士，其最耀眼的精髓就在于他发明的那套鬼斧神工的**双指针相向原地分区法（Hoare In-place Partitioning）**。

这套算法全程只在原数组内部进行元素置换，空间复杂度只有极致的 $\Theta(1)$，而且只需两个指针相向走完一趟数组！

我们来看它的运行机制。
假设我们要分区的数组如下，选定最左侧的 **17** 作为基准：

```text
原始状态:
[  17,   15,   19,   32,    2,   26,   41,   17  ]
   ^                                           ^
   |                                           |
Pivot (基准)                                    G 指针
   L 指针
```

我们派出两位特派员：
- **$L$ 指针（Left）**：从左端起步向右走。$L$ **喜欢小元素**（$\le 17$）。遇到喜欢的它就欢天喜地一步步往前走；一旦撞上不喜欢的**大元素**（$> 17$），它就会心生嫌弃、立刻原地驻足不前。
- **$G$ 指针（Great / Right）**：从右端起步向左走。$G$ **喜欢大元素**（$> 17$）。遇到比 17 大的它就继续往左走；一旦撞上不喜欢的**小元素或等于基准的元素**（$\le 17$），它也同样立刻停下脚步。

只要两人都停在各自讨厌的元素上，他们就会执行一次**元素互换（Swap）**——把 $L$ 讨厌的大元素扔给右边，把 $G$ 讨厌的小元素换回左边！

我们跟随推演流程走一遍完整推演：

**第一阶段：初遇阻碍与首次交换**
1. $L$ 从左向右审视：第一个看到 15，喜欢（$15 \le 17$），继续前进；第二个看到 19，太大了（$19 > 17$），$L$ 停在 19 处。
2. $G$ 从右向左审视：最右端是 17，由于 $G$ 只要严格大于基准的元素，17 它并不喜欢（$17 \le 17$），$G$ 停在 17 处。
3. 此时 $L$ 和 $G$ 双双卡住：

```text
[  17,   15,  [19],   32,    2,   26,   41,  [17] ]
                ^                               ^
                L (卡在 19)                    G (卡在 17)
```

4. 双方执行互换！把 19 和 17 对调：

```text
交换后:
[  17,   15,  [17],   32,    2,   26,   41,  [19] ]
                ^                               ^
                L                               G
```

交换之后，双方心满意足，各自迈步继续向前靠拢。

**第二阶段：再次受阻与二次交换**
1. $L$ 走到 32，太大了（$32 > 17$），再次卡死。
2. $G$ 往左看：41 很大喜欢（走过），26 很大喜欢（走过），退到 2；2 太小了（$2 \le 17$），$G$ 卡在 2。
3. 此时 $L$ 卡在 32，$G$ 卡在 2：

```text
[  17,   15,   17,   [32],  [2],   26,   41,   19  ]
                       ^     ^
                       L     G
```

4. 双方再次执行互换！把 32 和 2 对调：

```text
交换后:
[  17,   15,   17,   [2],  [32],   26,   41,   19  ]
                       ^     ^
                       L     G
```

**第三阶段：指针交叉与扫描终止**
换完之后两人继续往前迈步，结果发生了关键的**指针交叉（Cross）**：
$L$ 向右踏一步跨到了 32 的位置，而 $G$ 向左跨到了 2 的位置。$G$ 跑到了 $L$ 的左侧！
路径一旦交叉，说明全数组的每个角落已经被两位特派员完整巡视了一遍，扫描宣告结束。

```text
交叉状态:
[  17,   15,   17,    2,    32,   26,   41,   19  ]
                      ^      ^
                      G      L
```

> **核心不变量（Invariant）**：
> 请闭上眼睛想象两个人在数组里相向行走：$G$ 走过并退出的右侧区域，必然只留下大元素（要么是他本来就喜欢的大件，要么是刚才从左边换过来的大件）；$L$ 走过并退出的左侧区域，必然只留下小元素。当它们在中间交叉相遇时，$G$ 及其左侧所有项必然都不大于基准，而 $L$ 及其右侧所有项必然都不小于基准。

**第四阶段：终局归位（至关重要的一步）**
此时数组完成分区了吗？**还没有！**
因为我们的基准值 17 还孤零零地呆在最左端的第 0 格里，它本该去往正中间的位置。

现在我们要把基准 17 换到中间，**应该跟 $L$ 换，还是跟 $G$ 换？**

> **易错点**：**基准必须与 $G$ 指针最终所在的位置交换，绝对不能与 $L$ 交换！**
> 看看上面的指针位置：$G$ 目前停在 2 上（属于小数区），而 $L$ 停在 32 上（属于大数区）。如果贸然把开头的 17 和 $L$ 的 32 互换，那么巨大的 32 就会被瞬间甩到全数组的最前头，直接毁掉整个分区！
> 因此，必须将最左侧的 17 与 $G$ 所在的 2 互换。

```text
执行最终归位 (Swap Pivot with G):
[   2,   15,   17,   [17],   32,   26,   41,   19  ]
                       ^
                   基准成功就位
  \______________/           \__________________/
     全部 <= 17                   全部 >= 17
```

看！基准 17 严丝合缝地嵌入了中央，左边清一色小于等于 17，右边清一色大于等于 17。一次优雅的原地分区彻底达成！

#### 变体性能实测与过度设计的惨痛代价

掌握了霍尔分区之后，我们把快排升级为**变体 B**：
- **基准选择**：最左侧元素；
- **分区算法**：**霍尔双指针原地分区**；
- **防御策略**：预先随机洗牌。

我们再次跑一遍实测对决：

```text
快排变体 A (三遍扫描法):       3.2 秒
归并排序 (Merge Sort):         1.3 秒
快排变体 B (霍尔双指针分区):   0.9 秒
```

从 3.2 秒瞬间暴跌到 **0.9 秒**！快速排序一举逆转，干净利落地把归并排序甩在了身后！
这就是霍尔原地分区的威力：在渐进复杂度同为 $O(N)$ 的前提下，它凭借单次相向遍历、就地置换、零额外内存分配的极致低常数，将底层硬件的缓存与流水线性能发挥到了极致。

在这个令人振奋的成果面前，很多初学者常常会产生一种执念：“既然分区越平衡速度越快，那如果我们花费精力去把基准选得绝对完美，性能是不是还能更上一层楼？”

于是有人提出了**变体 C**：
- **基准选择**：利用理论上的线性选择算法，花费 $O(N)$ 代价寻找数组的**绝对精确中位数**；
- **分区算法**：霍尔双指针原地分区；
- **防御策略**：不需要洗牌，因为中位数天然能保证绝对的一分为二。

结果一测，所有人都会大跌眼镜：

```text
快排变体 B (霍尔双指针 + 洗牌): 0.9 秒
快排变体 C (精确中位数基准):    15.0 秒
```

整整耗费了 15 秒！性能非但没有提升，反而直接暴跌了十几倍，沦为全场最慢的蜗牛！

这是计算机科学史上极其生动的一课：**过度追求对称与完美的代价，往往远超不完美本身。**
为了在每一层换取那看似完美的 $50\% / 50\%$ 绝对平衡，你在每个节点上都要耗费极其笨重、复杂的线性开销去苦苦寻找中位数；而与其费尽心机去死磕绝对平衡，还不如彻底放飞自我、潇洒地拥抱随机性——哪怕切出来的子问题是三七开甚至一九开，快排轻快的递归步伐依然能在极低常数的加持下，以疾风般的速度冲过终点线。

### 思考题回顾与延伸

在这一讲的推导中，我们在课堂上留下了两道关键的思考与演算题，它们串联起了本讲的核心机理，现将解析归纳如下：

#### 题目一：极端失衡下的递归树高度推导

> **题干**：若快速排序每一次分区都极不均衡，恰好产生规模为原问题 10% 和 90% 的两个子问题。已知每一层所有子问题的分区总代价之和均为 $N$，试证明该算法的总运行时间依然为 $\Theta(N \log N)$。

**解析**：
算法的总运行时间由“每层工作量 $\times$ 树的最大深度”决定。
每一层的总工作量显然为：

$$0.1N + 0.9N = N$$

树的最大深度取决于数据量缩减最慢的那条路径，即不断保留 90% 数据的长分支：

$$N \to (0.9)N \to (0.9)^2 N \to \dots \to (0.9)^k N = 1$$

解此方程求深度 $k$：

$$(0.9)^k = \frac{1}{N} \implies \left(\frac{10}{9}\right)^k = N \implies k = \log_{10/9} N$$

应用对数换底公式：

$$k = \frac{\ln N}{\ln(10/9)} \approx 9.49 \ln N = \Theta(\log N)$$

因此，整棵树的总工作量为：

$$T(N) \le k \times N = \Theta(N \log N)$$

**结论**：即使划分常态化严重偏斜，只要每一侧保留的比例是固定的常数因子，树高就依然保持对数级别，算法永远不会退化至平方级。

---

#### 题目二：期望比较次数与最坏情况的数量级鸿沟

> **题干**：对于规模为 $N = 1000$ 的随机数组，快速排序期望消耗的比较次数大约是多少？理论最坏情况下的比较次数又是多少？如何从统计学角度理解这种差异？

**解析**：
1. **期望比较次数**：
   快速排序与朴素二叉搜索树等价，对随机输入的期望比较次数约为 $C \approx 2 N \ln N \approx 1.386 N \log_2 N$。
   针对 $N = 1000$：

$$N \log_2 N \approx 1000 \times 9.966 \approx 10,000 \text{ 次}$$

   考虑常数因子后的实测密集分布区间约为 $1.1 \times 10^4 \sim 1.3 \times 10^4$ 次。

2. **最坏情况比较次数**：
   当输入已有序且固定选最左元素时，比较总次数为：

$$\sum_{i=1}^{N-1} i = \frac{N(N - 1)}{2} = \frac{1000 \times 999}{2} \approx 5 \times 10^5 \text{ 至 } 10^6 \text{ 次（约 100 万次操作）}$$

**结论**：期望情况（约 1.2 万次）与理论最坏情况（约 100 万次）之间存在接近两个数量级的物理鸿沟。对于随机输入，所有元素恰好按单调顺序排列以触发最坏情况的概率为 $1 / N!$，在宏观现实世界中属于几乎绝不可能发生的极小概率事件。
