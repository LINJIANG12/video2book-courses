### 两条思路：函数传递与多态

我先从编程中一个有趣的区别谈起——它有点像哲学里的一对概念。把"一段行为"提供给函数，主要有两条路。第一条是函数传递：把函数作为参数递进去，61A、61B 这类课程里很常见。第二条在 Java 里更常见，叫多态：不递函数，而是让"到底执行哪份代码"由对象的类型在运行时决定。当然不止这两种，但这是把行为交给函数的两种主要方式，关键差别在于：多态基于继承，函数传递不基于继承。

> **定义**：多态，简单说就是为不同的底层结构提供相同的接口。

用 Python 看多态。假设有个 Dog 类，构造函数里写 `__init__`。想比较两只狗，直接用大于运算符写 `d1 > d2`。这个大于号就是多态——狗、猫或者列表，都有各自承载大于运算符的魔法函数。"相同的编程接口"指的就是这个大于运算符，"不同的底层形式"可以是狗、列表、土豆——它们各自实现自己的版本。max 函数在运行时拿到 item，它并不确定手里的是 Dog 还是整数，但大于运算符的表现会自动不同：运算符背后触发一次函数调用，指向当前对象所属类的那份实现。

Python 里你们同样见过函数传递。写一个 get_max 函数，额外接收一个键函数——就像给 sorted 传 key 那样。同一个"找最大"，键函数一换，标准就换：不传键函数、直接依赖大于运算符，返回体型最大的狗；传一个"取名字长度"的裸函数——它根本不属于 Dog 类——返回的就是名字最长的狗，这时键函数完全绕开了大于运算符。

所以区别在这里：多态那条路，靠的是继承——也就是大于运算符在每个类里的定义；函数传递那条路，靠的是显式把函数当参数传进去。Python 里两种都常见；Java 里显式传函数就少见了——虽然能写，Java 8 之后配合流（stream）还挺常见，但 Java 8 之前基本全靠多态。为了不让大家为课堂任务额外多学一层 Java，这门课只讲多态这一套。

### 三只狗找最大：Collections.max 的报错

来看三只狗：Greg、Pollusa 和 Clifford，体型分别是 200、5 和 9000，都装在一个列表里，现在试着找出最大的那只。Java 有个内置函数 Collections.max，能处理任意集合——列表算集合。说到这里我得纠正一个讲了十年的错误：映射（Map）不是集合。它并没有继承 Collection 接口，而是独立的数据结构。一年前就有学生指出过这一点——过去我一直跟大家说映射属于集合，是记差了，这个说法我已经更正。

现在试 Collections.max(dogs)，报错。Java 的抱怨翻译过来是：你让我比较这三只狗——可狗是什么？它有名字和体型两个字段，但没说明如何区分两只狗的高下、该比什么。Python 里这样解决：在 Dog 上定义一个类似 `__gt__` 的魔法方法，接收 self 和另一只狗 other，返回体型上的比较结果——现场随手写的语法并不严格，但意思就是这样。Java 里对应的工具是什么？想声明一个类"具备某种能力"，窍门就是定义一个接口，然后声明这个类实现它。

> **定义**：Comparable 是 Java 官方的接口，专供"可比较的事物"；一个类声明 implements Comparable，等于承诺自己具备"可比较"这种能力。

以前我讲课时会从头定义一个没人见过的新接口，叫 AreComparable，但这次直接用真正的那个——Comparable。至于刚才那条报错：要求类型满足 `Comparable<? super T>` 之类的约束、系统找不到符合条件的 T——Java 的类型系统就是这么让人头疼，不是 Java 专家很难读懂这些报错；它想表达的其实就一句：你没告诉 Java 狗能比较，也没提供比较方法。

### Comparable 的本尊：一个方法、一百三十行注释

Comparable 的实际代码长什么样？写它的人是 Josh Bloch——他写出了最好的 Java 书，也维护着这门语言。这个接口的核心契约就一句：比较此对象与指定对象的顺序；若此对象小于、等于或大于指定对象，则分别返回负整数、零或正整数。这个模式咱们见过。整个接口只有一百三十多行注释、仅包含一个函数，但注意它带着类型参数 T——让 T 类型的对象和它自己比较，这就是整个接口。企业级代码里注释多是常态：大家遇到疑问时，都会来这里寻找最终答案。

顺带一提，我在各种地方都能见到 Josh Bloch 的名字，比如快速排序的实现里。第 13 周我会分享一封有趣的邮件：当年我询问快速排序的实现是什么时候改的，收到的回复相当奇怪——到时候让你们猜猜是谁回的。

### 实现 compareTo：按体型比，按差值写

让 Dog 具备可比性，就在类声明顶部写 `implements Comparable<Dog>`，读作"Dog 可以和其他 Dog 比较"。我本可以用猫或其他动物来类比，但我就想拿狗跟狗比。声明一加，立刻报错：你声称能和狗比，却没给出具体方法。走个捷径，让 IDE 自动生成方法体，再把"怎么比"填进去。

首先得确定比较标准——这里按体型比。方法参数不需要 instanceof 类型判断——还记得它吗？比如判断 o 是不是 Dog 的实例。这里不需要：类型参数已写明是 Dog，参数本来就是一只狗，直接比就行。我把对方命名为 utDog，这个名字的来历稍后说。接下来回到契约：比对方小返回负整数，相等返回零，更大返回正整数——写成 -1、0、1 就行。

```java
public class Dog implements Comparable<Dog> {
    // name、size 两个字段及构造器从略
    private int size;

    public int compareTo(Dog utDog) {
        if (this.size < utDog.size) {
            return -1;
        } else if (this.size == utDog.size) {
            return 0;
        }
        return 1;
    }
}
```

先埋一个有趣的小问题：如果 size 声明为 private，compareTo 里还能访问另一只狗的 size 吗？课堂上举手表决了一圈。答案是：照样能用。private 的规则不是"能不能访问其他实例的变量"，而是看代码在哪个文件里：只要在 Dog.java 里，就能访问任何 Dog 对象的所有变量，包括私有的；换到别的文件就不行——关键在于文件级私有。

> **提示**：这是考点——无论 compareTo 声明为私有还是公有，同类实例之间访问私有成员的结论都不变；期中考我不问那些烦人的公有/私有问题。顺带一提：同一个项目目录里能放两个叫 Dog 的文件吗？不行——只要顶部包名相同就不行。

utDog 这个名字的来历：2005 年我去夏威夷大岛划皮划艇——顺带正经推荐那家租赁店，体验非常好；要是你恰好在给同行竞品干活，就当我没说。店主家养了两只狗，我到现在都没搞清哪个名字是人的、哪个名字是狗的，代码里就留下了 utDog。那次旅行的海岸线是一绝：赶上大浪天，海浪涌进喀斯特地貌的细小水道，像一座巨型水上乐园；悬崖边还有洞穴，把皮划艇拴在大概 20 英尺深的礁石上往里钻，能一直走到深入岩壁约一千英尺、天花板塌掉的地方——那是我这辈子干过最酷的事之一。上次再去大约是 2019 年，赶上火山喷发，我们订了离火山最近的住处，地面直冒蒸汽；深夜戴着面具走 45 分钟伐木路去看熔岩，熔岩壳碎裂的声音像玻璃碎裂。跑题有点远——关于大岛有什么问题吗？没有的话，回去写代码。

compareTo 还有另一种更巧妙的写法：不用 if 语句，直接 `return this.size - utDog.size;`。这为什么行得通？乍一看像作弊——什么都没检查，只返回了差值。举个例子：我的体型是 3、你的体型是 100，差值是 -97——负号本身就携带了"我更小"的全部信息；相等时差值为零；反过来就是正数。其实大部分比较函数都这么写。把它写进去，正好可以跑了。

运行前还差一件小事：打印狗之前得给 Dog 补一个 toString，否则打出来就是随便什么奇怪的东西。这块我最近偷懒，直接让大语言模型生成代码——让它写一个 toString 方法，你看这就搞定了。这技术三年前就很酷了，现在的大语言模型做得更棒。跑起来，Collections.max 挑出 9000 号的 Clifford——这正是按体型比较的结论。（顺带认识一下：Clifford 就是绘本里那只大红狗，读过的人都知道，没谁的影响力比它大。另外，以前的课程顺序可不是这样排的，现在这样安排，逻辑上通顺多了。）

到这里值得停一下，给刚才的演示定个名：这是子类型多态——在 Python 里你们可能没怎么接触过。核心思路是先定义一个超类型（比如 Comparable）来规定能力，再由子类型去实现它；Java 运行时会根据实际调用者的类型决定执行哪个函数。这跟你们在 61A 或 88 里写的 Python 不一样，那边有个可以直接重载的大于运算符。

> **定义**：子类型多态——超类型规定能力、子类型实现能力，运行时按调用者的实际类型选择执行哪个函数。

还有个小话题：写 compareTo 时我没加 @Override 注解——为什么？说实话我自己也说不清，咱们一起猜了猜；加上注解时 IDE 还闹了个导入相关的岔子，报错我自己也没看懂。重要的是这个事实：删掉 @Override，方法照样重写，行为没有任何变化。那为什么还要加？它是给程序员看的明确信号，让"我在重写"这个意图显式化，也让编译器帮你把关。保持加着的习惯就好。

### 一道出名的编译题：删掉 compareTo 会挂谁

接下来出个小谜题。期中考我本来出过一道类似的题，助教提醒我"你不是说不想出这种题吗"——说得对，删了。所以这道就当课堂谜题，但它出了名的棘手。

假设有个 DogLauncher，建好一列表狗，然后调 Collections.max(dogs)。Collections 是 Josh Bloch 写的那个类，之前没细讲：里面有个 max 函数，会调用元素上的 compareTo。现在问：如果把 Dog.java 里的 compareTo 删掉，哪些文件编译会报错？提醒一句：编译发生在代码运行之前。祝好运。

答案分布很有意思：50% 选了 Dog，23% 选了 Collections，15% 左右选 DogLauncher 或 Comparable。

先把最反直觉的排除掉：Collections.java 不会挂。Bloch 写 Collections 的时候，你的 Dog 类可能压根不存在——这份代码要编译好、打包、发给用户并且正常运行，它的编译状态不该取决于用户以后写了什么类。很多人卡在这里选了 Collections，理由是"运行时会因为缺 compareTo 崩掉"——但编译发生在那之前：Collections 先被编译、打包，然后才发送，运行时崩溃是另一回事。

接口为什么不依赖实现？现场做个实验。我临时建个新接口，就叫它爆炸相关的东西吧：一个 Explodable 接口，里面有个 explode 方法，接收一个整数——虽不知为何要整数，但就这么定了——再加一个布尔值。然后写个 ExplosionChecker，里面有个静态方法，接收一列"会爆炸的东西"，遍历并对每个元素调用 explode——参数随手给了个 14。

```java
public interface Explodable {
    void explode(int i, boolean b);   // 参数是现场随手定的
}
```

```java
public class ExplosionChecker {
    public static void explosionsValid(List<Explodable> l) {
        for (Explodable x : l) {
            x.explode(14, true);      // 此刻全世界还没有任何类实现 Explodable
        }
    }
}
```

这两段代码完全合法、能编译——尽管此刻还没有任何类实现 Explodable。以后也许有人会来写个炸药类，但现在还没有；所以这份代码能编译，却跑不了：它没有实际功能，得先有人把爆炸功能实现出来。编译的过程只是检查语法和类型是否自洽，把文本转成字节码——一种更规整、更易于运行时执行的格式——并确保一切合理。打个比方：你给孩子写指示——"有人来问要不要饼干，就照这个做"——孩子的能力不如你，所以你把指令写得简单明确、核对好没有错误，孩子照着执行就行。编译器干的就是这件事：替能力不如你的运行时把指令整理好、检查好。

回到谜题。Dog.java 挂——它声明了 implements Comparable<Dog>，等于承诺"我能和别的狗比"，却没提供 compareTo 方法，编译器不答应。DogLauncher.java 不挂，它自己的代码完全合法——不过我留个口子：如果你非要从"整个工程编不过"的角度较真，为了抬杠选 DogLauncher，那也算你说得对。

> **易错点**：编译发生在运行之前。库代码早在你的类存在之前就已编译打包，它的编译不依赖你的实现；缺实现这件事要到运行时才会暴露。

紧接着的变体：如果 Dog 干脆不声明 implements Comparable，但保留 compareTo 方法，会怎样？先想一分钟。答案是：Java 允许这么写——拥有一个 compareTo 方法并不强制要求声明 Comparable，方法就是个普通方法。所以 Dog.java 没问题；Collections.java 还是老样子；这回挂的是 DogLauncher——它把不可比的对象传给了要求可比对象的 max 函数。错误在 DogLauncher，你得修一下它（或者让 Dog 把承诺补上）。

### Comparator：给"另一种顺序"另开一个接口

到目前为止，compareTo 给狗定下了一个自然顺序：对 Dog 来说就是比体型——Pollusa（5）最小，Greg（200）居中，Clifford（9000）最大。但也许并非如此——也许你想按名字排：按字母序的话，Clifford 最小，Greg 居中，Pollusa 最大。

> **定义**：自然顺序——compareTo 方法隐含的排序。Dog 的自然顺序是体型；别的类可以是别的标准。

Python 里的做法你已经会了：函数传递——传入一个键函数，指定按名字排，别用大于运算符。Java 这边依然不把不同的函数当参数传给 Collections.max，而是再次使用子类型多态。这看似是个难题：Comparable 里那个方法的"名额"已经被体型占用了。所以 Java 引入了另一个接口：Comparator。它包含一个 compare 方法，接收两个对象进行比较——像一位外部观察者、一个裁判，判断这两个对象哪个更大。

我在 IDE 里现场写一个 NameComparator，实现 Comparator<Dog>（接口得导入），再实现 compare 方法接收两只狗。第一反应可能是拿名字长度相减：`o1` 名字的长度减 `o2` 名字的长度——但那是按名字长度排，我们想要的是字母序。改用字符串自己的比较：String 自带 compareTo（字符串也是 Comparable 的），直接调它。

```java
public class Dog {
    // ...字段、构造器、compareTo 从略...

    static class NameComparator implements Comparator<Dog> {
        public int compare(Dog o1, Dog o2) {
            return o1.name.compareTo(o2.name);
        }
    }
}
```

用法上有个微妙处。在演示里传入 `new Dog.NameComparator()` 时卡了一下：这个嵌套类得是静态的。原因：用名字比较器时，我不该想着某一只特定的狗；如果类不是静态的，它就得关联到一只具体的狗实例——静态类关联的是 Dog 类本身。换个说法：非静态嵌套类在实例化前，你得先有一个外层实例——等于要先 new 一只狗才能拿到名字比较器，毫无道理。回想当时决定 Node 类要不要 static，问的是同一件事：Node 有没有用到列表实例的变量（比如哨兵节点）？没有，所以 Node 应该是静态的。这有点绕，别太纠结：在 61B 里，什么时候必须加 static 通常很明显，编译器会报错提醒，你加上关键字就行——等你成了专业程序员，或许会再仔细琢磨。

传入名字比较器再运行，打印出"名字最大"的狗：按字母序是 Pollusa。做到了，不错。（要是真按名字长度排，答案会是 Clifford——想要哪种序，取决于比较器怎么写。）想玩点现代 Java 的话，还可以用箭头符号在调用处内联声明一个小函数，效果一样，还是 Pollusa——现在业界更常用 lambda 定义比较器，这节课不讲，想学可以自己总结。

再补一个常见优化。有人觉得每次都要 new 一个比较器有点别扭——可以在 Dog 类里直接提供一个：定义一个全大写的静态变量，比如 NAME_COMPARATOR，类加载时就会自动创建好这个名字比较器，用的时候直接 `Dog.NAME_COMPARATOR`。两种都行；觉得实例化别扭，就提前备好。

最后确认大家都跟上了：比较 "frank" 和 "zika"，compare 返回什么？frank 在字母序上小于 zika，所以返回负数——这就是 compare 的核心逻辑，符号约定和 compareTo 完全一致。

### Comparable 与 Comparator 的分工

该把两个接口的区别说清了。Comparable 说明类有自然顺序——比如这一讲的体型——意思是类的实例可以和同类的其他实例进行比较，规则写在类自己的 compareTo 里。反过来，Comparator 是外部用的：好比找个裁判来比两只狗，可以定义名字、速度等等多种规则。

|              | Comparable                  | Comparator                 |
| :----------- | :-------------------------- | :------------------------- |
| 规则写在哪   | 类自己实现，比较规则在类内部 | 外部实现，像请来的裁判     |
| 方法         | compareTo，与另一个同类对象比 | compare，同时接收两个对象  |
| 能定几种顺序 | 自然顺序，一种               | 名字、速度等，多种         |

既然有了 Comparable，为什么还需要 Comparator？两者功能相似，不多此一举吗？答案是灵活性：只需要一种比较方式，用 Comparable；想要多个可选的排序标准，用 Comparator 更好。一句话记住：想用内置的顺序，就用 Comparable；想用其他外部顺序，就用 Comparator。

最后把视野拉回这场讲座的主线。我们看了多态和函数传递——这只是编程语言课程的概览，更偏编程语言的课会深入类型系统，你会碰到更复杂的情况。但我们已经看到了两种理念的分野：Python 用运算符重载，Java 依赖子类型多态。Python 是动态类型，不必预先声明大于运算符怎么用，运行时判断，不可用就崩；Java 很正式——习惯之后，希望你现在能享受其中，感觉很好。

### 期中考怎么考，以及怎么练

下周就是期中考，几件事说清楚。考试只考写代码，没有"这段代码在干嘛"之类的阅读题——爱做这类题的同学抱歉了。考试专注编程，因为作业全是编程。考试不考根本性的新内容，也不搞巧妙技巧——这通常是我出题的常态：看你是否真正理解了所有内容，以及能否把它们很好地组合起来；你未必总能想到那种绝妙的点子，没关系。

备考路径：务必完成前两个项目并消化讨论作业纸——出题时我参考了这些；接下来做做往年真题，重点练代码题。

最后是纸上写好的一段话，我直接念给你们听：团队的力量大于个人。建议每天挑一两道讨论作业纸上的题目练一练，不要偷看答案；卡住了没关系，花 10 分钟琢磨是很正常的；每天回头看看那些卡壳的题目，说不定就会迸发出新的灵感；找同学聊聊你的解法，或者哪怕只是讨论一下思路。我上过的最难的一门数学课有个规定：一人写白板，旁人看完惊呼"原来还能这么解"——大家感叹太酷了，一个学期下来所有人的水平都提上来了；还有人指出"这一行就能搞定，不用写八行"。大家互相学习、互相纠正，所以请主动分享你的好想法，或者坏想法也行。所谓元认知，就是反思自己的思考过程——这对高质量学习至关重要。只有当你彻底卡住时才去看答案，因为从答案本身学不到什么，真正的深度理解来自元认知。
