# 堆与优先队列

## 平衡二叉搜索树修复与性能全景

### 左倾红黑树插入连环修复

* **左倾红黑树插入修复（LLRB Insertion Repair）**
    * > **定义**：将新键按普通二叉搜索树规则以红链接挂载插入后，自底向上执行的一组局部旋转与变色修复规则序列。
    * 状态对应：左倾红黑树与 2-3 树一一对应，插入红色链接模拟向 2-3 节点加入元素，形成临时的 4-节点。
    * 右倾红链接修复：若节点出现右倾红链接且左链接非红，执行左旋（Left Rotation）。
    * 双连续红链接修复：若节点出现连续两条左倾红链接，对上层父节点执行右旋（Right Rotation）。
    * 临时节点分裂：若节点的左链接与右链接皆为红链接，执行颜色翻转（Color Flip），将中间键提升至上一层。
    * 修复顺序：按照“左旋 $\to$ 右旋 $\to$ 颜色翻转”的三步检测逻辑自底向上回溯，直到所有不变量均被满足。
    * > **注意**：修复操作具备级联效应，单次插入可能引发沿查找路径向上的多次连续旋转与变色。

### 经典树结构性能与选型

* **平衡树实现家族（Balanced Search Trees Family）**
    * > **定义**：通过动态调整维持对数级树高以确保动态集合操作最坏性能界限的树形结构集合。
    * 普通二叉搜索树（BST）：插入与查询时间复杂度依赖输入序列，最坏情况下退化为单向链表，操作退化为 $O(N)$。
    * 2-3 树：通过自底向上节点吸收与分裂机制保持绝对平衡，树高严格为 $O(\log N)$，但多项节点指针实现开销庞大。
    * 左倾红黑树（LLRB）：使用红链接模拟 2-3 树节点，查询与插入时间复杂度严格为 $O(\log N)$，显著简化平衡树工程实现。
    * 工业标准实现：Java 标准库中的 `java.util.TreeMap` 与 `java.util.TreeSet` 底层采用传统红黑树，允许局部红链接右倾以换取更低的旋转调整开销。

## 优先队列抽象数据类型

### 优先队列接口契约

* **优先队列（Priority Queue，PQ）**
    * > **定义**：一种受到严格访问约束的集合抽象数据类型，仅允许存入元素并高效查询或移除当前优先级最高的元素。
    * 核心操作契约：
        * `add(item)`：向优先队列添加一个元素，要求对数级时间复杂度。
        * `getSmallest()`：返回全局优先级最高（键值最小）的元素而不删除，要求常数级时间复杂度。
        * `removeSmallest()`：提取并删除全局优先级最高（键值最小）的元素，要求对数级时间复杂度。
        * `size()`：返回当前队列中的元素总数，要求常数级时间复杂度。
    * 抽象接口交互：
```text
       add(x) ---------> [                 ]
                         [  PriorityQueue  ]
  getSmallest() <------- [  (只暴露最小值)  ]
  removeSmallest() <---- [                 ]
```
    * > **易错点**：优先队列不暴露基于索引的随机访问接口，不支持根据键值定位中间元素。

### 常数空间数据流筛选机制

* **Top-K 数据流筛选算法（Top-K Stream Filter）**
    * > **定义**：利用固定容量优先队列在单遍数据扫描过程中剔除弱项，以常数级内存获取海量流式数据极值前 K 项的算法。
    * 全量排序缺陷：收集全量数据（$N$ 项）并排序需要占用 $O(N)$ 空间复杂度与 $O(N \log N)$ 时间复杂度，内存开销巨大。
    * 最小堆筛选机制：查找海量数据流中最大的 $K$ 个元素时，维护容量上限为 $K+1$ 的最小优先队列。
    * 淘汰规则：新数据进入后若队列大小超过 $K$，立即调用 `removeSmallest()` 剔除局部最弱元素。
    * 资源开销：空间复杂度降至常数级 $O(K)$，时间复杂度为 $O(N \log K)$。
```java
PriorityQueue<Particle> topK = new PriorityQueue<>(k + 1, Comparator.comparingDouble(Particle::energy));
while (detector.hasIncomingParticle()) {
    topK.add(detector.nextParticle());
    if (topK.size() > k) {
        topK.removeSmallest();
    }
}
```

### 底层实现结构性能对比

* **优先队列底层选型权衡（PQ Implementation Trade-offs）**
    * > **定义**：针对优先队列核心访问特征对不同通用数据结构展开的渐进复杂度分析。
    * 无序数组方案：`add` 为 $O(1)$，`getSmallest` 与 `removeSmallest` 必须遍历全数组，时间复杂度为 $O(N)$。
    * 有序数组方案：`getSmallest` 为 $O(1)$，但 `add` 与 `removeSmallest` 涉及大范围元素内存平移，时间复杂度为 $O(N)$。
    * 平衡二叉搜索树方案：各项操作时间复杂度均为 $O(\log N)$，但天然依赖唯一键假定，且基于指针对象存储带来额外的内存开销。
    * 二叉堆方案：`getSmallest` 为 $O(1)$，`add` 与 `removeSmallest` 均为 $O(\log N)$，天然支持重复元素，空间布局扁平。

| 底层实现方案 | `add` 复杂度 | `getSmallest` 复杂度 | `removeSmallest` 复杂度 | 核心瓶颈 / 缺陷 |
| :--- | :--- | :--- | :--- | :--- |
| 无序数组 | $O(1)$ | $O(N)$ | $O(N)$ | 查找与删除最小值需要全量遍历 |
| 有序数组 | $O(N)$ | $O(1)$ | $O(N)$ | 插入与删除需要大范围平移数组元素 |
| 平衡二叉搜索树 | $O(\log N)$ | $O(\log N)$ | $O(\log N)$ | 原生不支持重复元素，指针开销庞大 |
| 二叉最小堆 | $O(\log N)$ | $O(1)$ | $O(\log N)$ | 结构紧凑，天然支持重复项且缓存局部性优异 |

## 二叉最小堆体系结构与核心操作

### 二叉最小堆核心不变量

* **二叉最小堆（Binary Min-Heap）**
    * > **定义**：同时满足完全二叉树结构约束与最小堆偏序约束的特殊二叉树结构。
    * 完全二叉树性质（Completeness）：除最底层外各层节点全满；最底层节点紧密集中在最左侧，中间不允许出现空缺断层。
    * 最小堆性质（Min-Heap Property）：对于树中任意非根节点 $p$，其父节点数值必然小于或等于节点 $p$ 的数值。
    * 结构拓扑形态判定：
```text
       0                         0                         0
     /   \                     /   \                     /   \
    1     5                   1     5                   5     1
   / \   / \                 /     / \                 / \   /
  2   6 8   8               2     8   8               2   6 8
 (有效最小堆)           (无效：非完全树)          (无效：违反最小堆性质)
```
    * 结构约束本质：堆性质属于垂直纵向偏序约束，左子节点与右子节点之间不存在任何横向大小依赖关系。
    * 极值分布：树的全局最小值恒定驻留在二叉堆的根节点位置。

### 上浮调整机制

* **上浮调整（Swim / Bubble Up）**
    * > **定义**：新节点置于树末尾后，通过连续与父节点比较并交换，直至恢复最小堆偏序性质的修复过程。
    * 触发场景：执行元素入堆操作 `add(item)`。
    * 执行逻辑：
        1. 将新元素放置于完全二叉树最底层的最左空位，保证完全二叉树性质不被破坏。
        2. 比较当前节点与其父节点，若当前节点数值严格小于父节点数值，则交换两者位置。
        3. 沿祖先链重复比较与交换，直至当前节点大于或等于父节点，或当前节点已上浮至根节点。
    * 时间复杂度：完全二叉树树高为 $\lfloor \log_2 N \rfloor$，最坏交换次数等于树高，时间复杂度为 $O(\log N)$。

### 下沉调整机制

* **下沉调整（Sink / Bubble Down）**
    * > **定义**：根节点移除后将末尾元素移至堆顶，通过连续与较小子节点比较并交换以重构最小堆的修复过程。
    * 触发场景：执行堆顶弹出操作 `removeSmallest()`。
    * 执行逻辑：
        1. 提取堆顶元素作为返回值；将完全二叉树最末尾的叶子节点移至根节点，恢复完全树结构。
        2. 选取当前节点所有子节点中数值较小者进行对比。
        3. 若当前节点数值大于较小的子节点，则将当前节点与该子节点交换位置。
        4. 重复上述步骤，直至当前节点小于或等于所有子节点，或当前节点下沉为叶子节点。
    * 时间复杂度：最大下潜深度受限于树高，时间复杂度为 $O(\log N)$。
    * > **易错点**：下沉时若错误地与较大子节点交换，将导致原本较小的子节点被置于新父节点下方，破坏局部最小堆性质。

## 堆的底层存储表示与寻址映射

### 树结构的内存表示演进

* **基于引用的树表示法（Reference-Based Tree）**
    * > **定义**：使用显式声明指针字段的独立对象表示树节点的面向对象组织方式。
    * 内存布局缺陷：每个节点存在独立的堆对象开销、对齐填充与指针寻址，内存布局分散且缓存命中率较低。
* **双数组树表示法（Parallel Array Representation）**
    * > **定义**：利用平行的键值数组与父节点索引数组记录树节点与其拓扑关系的扁平化表示法。
    * 拓扑维护：数据数组 `keys[]` 记录节点元素，索引数组 `parents[]` 记录各节点的父节点在数组中的下标。
    * 开销缺陷：需要额外维持一个与节点规模相同的整数数组空间。

### 完全二叉树的单数组数学寻址

* **单数组映射表示法（Single Array Representation）**
    * > **定义**：依据完全二叉树各层紧密排布特征，依靠纯算术推导父子索引对应关系的紧凑线性存储模型。
    * 0 索引体系规则（0-indexed）：根节点位于下标 0。
        * 节点 $k$ 的父节点索引：$\text{parent}(k) = (k - 1) / 2$
        * 节点 $k$ 的左孩子索引：$\text{leftChild}(k) = 2 \times k + 1$
        * 节点 $k$ 的右孩子索引：$\text{rightChild}(k) = 2 \times k + 2$
    * 1 索引体系规则（1-indexed）：跳过下标 0，根节点存储于下标 1。
        * 节点 $k$ 的父节点索引：$\text{parent}(k) = k / 2 = k \gg 1$
        * 节点 $k$ 的左孩子索引：$\text{leftChild}(k) = 2 \times k = k \ll 1$
        * 节点 $k$ 的右孩子索引：$\text{rightChild}(k) = 2 \times k + 1 = (k \ll 1) + 1$
    * 存储映射拓扑：
```text
 数组下标:    0     1     2     3     4     5     6     7
 元素存储:   [ - ] [ A ] [ B ] [ C ] [ D ] [ E ] [ F ] [ G ]
                     \     /
                  parent(k) = k / 2
                  leftChild(k)  = 2 * k
                  rightChild(k) = 2 * k + 1
```
    * 性能优势：物理内存连续分配，消除全部额外指针开销，对 CPU 缓存预取高度友好。

### 泛型抽象与比较机制

* **泛型极性抽象（Generic Comparator Abstraction）**
    * > **定义**：借助比较器解耦堆调整算法与业务对象实体优先级的接口设计模式。
    * 极性翻转规律：最小堆与最大堆在结构调整机制上完全一致，仅需变更比较器符号即可互相转换。
    * 核心调整代码实现：
```java
private void sink(int k) {
    while (2 * k <= size) {
        int j = 2 * k;
        if (j < size && greater(j, j + 1)) {
            j++;
        }
        if (!greater(k, j)) {
            break;
        }
        swap(k, j);
        k = j;
    }
}
```

## 二叉堆典型问题分析

### 最小堆拓扑合法性判别

* **堆合法性判别准则（Heap Validity Verification）**
    * > **定义**：对给定二叉树形态同时进行完全性检查与堆序性检查的判别方法。
    * 完全性破缺场景：节点存在右孩子但缺失左孩子，或某一层尚未排满即在更深层引入子节点，均判定为非法。
    * 偏序破缺场景：存在任何父节点键值大于子节点键值的局部结构，均判定为非法。
    * 重复元素判定：完全二叉树中子节点键值与父节点键值相等满足偏序条件，判定为合法。

### 零索引数组父节点公式推导

* **零索引父节点寻址公式推导（0-Indexed Parent Derivation）**
    * > **定义**：利用整数除法向下取整特性统一奇偶子节点反向定位父节点下标的数学过程。
    * 左孩子反推：设父节点索引为 $p$，其左孩子索引 $k = 2p + 1$，则：
      $$(k - 1) / 2 = (2p + 1 - 1) / 2 = 2p / 2 = p$$
    * 右孩子反推：设父节点索引为 $p$，其右孩子索引 $k = 2p + 2$，则：
      $$(k - 1) / 2 = (2p + 2 - 1) / 2 = (2p + 1) / 2 = p + 0.5$$
    * 整数截断特性：Java 等语言的整数除法执行向下取整，小数部分 $.5$ 被自动丢弃，结果严格收敛为 $p$。
    * > **提示**：公式 $(k - 1) / 2$ 对左孩子与右孩子统一适用，免去了基于下标奇偶性进行条件分支判断的开销。
