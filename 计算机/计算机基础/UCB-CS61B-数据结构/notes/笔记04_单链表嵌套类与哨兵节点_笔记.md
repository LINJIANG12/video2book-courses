# 单链表嵌套类与哨兵节点

## 裸递归链表缺陷与容器封装

### 裸递归数据结构

* **裸递归链表（Naked Recursive List）**
    * > **定义**：由离散节点通过指针直接串联而成、未在外部套用任何容器对象封装的数据结构。
    * 用户引用变量直接绑定首节点地址，底层节点与列表实体概念混淆。
    * 初始化与添加新元素需显式构造底层对象并传入 `null` 或旧引用。
    * 引用关系完全暴露于外部调用方，缺乏对节点连接的隔离保护。
    * > **易错点**：外部变量直接修改裸节点内部的 `next` 引用，将破坏整个底层链表的拓扑连接。

```text
用户变量 L
    |
    v
+--------+------+      +--------+------+
| item:5 | next | ---> | item:10| next | ---> null
+--------+------+      +--------+------+
```

```java
public class IntNode {
    public int item;
    public IntNode next;

    public IntNode(int i, IntNode n) {
        item = i;
        next = n;
    }
}
```

### 容器对象封装

* **单向链表包装容器（Single Linked List，SLList）**
    * > **定义**：充当用户与底层节点之间抽象隔离屏障的面向对象容器类。
    * 内部维护一个指向底层链表首个节点的引用字段。
    * 将底层内存分配、指针传递及 `null` 初始化的处理细节全部封闭在容器内部。
    * 用户变量持有稳定的容器对象，不再随表头节点的变动而重新赋值。

```text
用户变量 L2
    |
    v
+---------------+
|    SLList     |
|  first: ----+ |
+-------------|-+
              |
              v
        +--------+------+
        | item:10| next | ---> null
        +--------+------+
          (IntNode)
```

### 首部操作流转

* **首部插入操作（Head Prepend，addFirst）**
    * > **定义**：在链表最前端插入新元素并将容器头指针指向该新节点的操作。
    * 新建节点的后继指针直接指向旧表头节点，随后更新容器头指针指向新建节点。
    * 操作的时间复杂度为常数阶 $O(1)$，无需移动已有元素。

* **首部查询操作（Head Access，getFirst）**
    * > **定义**：获取链表当前第一个有效数据元素值的访问操作。
    * 解引用头节点的内部数据字段并返回其基础数据类型值。
    * > **易错点**：外部接口应返回节点内部包裹的数据字段，严禁直接返回底层节点引用。

```java
public class SLList {
    public IntNode first;

    public SLList(int x) {
        first = new IntNode(x, null);
    }

    public void addFirst(int x) {
        first = new IntNode(x, first);
    }

    public int getFirst() {
        return first.item;
    }
}
```

## 访问控制与静态嵌套类优化

### 访问权限与信息隐藏

* **私有访问修饰符（Private Access Modifier）**
    * > **定义**：限制类成员仅在当前类作用域内部可见与可操作的访问控制关键字。
    * 阻断外部调用者通过直接点操作符篡改内部节点引用的通道。
    * 防止链表尾部指针被错误回指而产生环形拓扑死循环。
    * > **提示**：私有访问控制是编译器级别的防呆机制，通过底层反射机制依然能够绕过该约束。

```text
+---------------+
|    SLList     |
|  first: ----+ |
+-------------|-+
              |
              v
        +--------+------+        +--------+------+
        | item:10| next | -----> | item:15| next | --+
        +--------+------+        +--------+------+   |
            ^                                        |
            +----------------------------------------+
```

* **信息隐藏（Information Hiding）**
    * > **定义**：隔离外部调用接口与内部私有实现的软件设计原则。
    * 向外部调用者暴露标准稳定的公共方法集合。
    * 保持内部数据字段命名与指针流转拓扑的自主演进能力。

### 嵌套类与内存优化

* **私有嵌套类（Private Nested Class）**
    * > **定义**：完全定义在宿主类内部且访问权限设定为私有的辅助类。
    * 仅在宿主类内部实例化并协同工作，杜绝底层辅助类污染全局命名空间。
    * 嵌套类通常置于类的最顶端，中间放置实例变量与构造函数，最下方放置方法。

* **静态嵌套类（Static Nested Class）**
    * > **定义**：使用 `static` 修饰符声明、不持有外部宿主实例引用的嵌套类。
    * 切断节点与外部容器对象之间的隐式指针依赖。
    * 在 64 位 JVM 中为每个节点节省 8 字节（64 位）的宿主引用开销，内存节省近三分之一。
    * > **易错点**：若省略 `static` 修饰符，嵌套节点在实例化时会被强制塞入一个指向外部容器的隐式引用。

```java
public class SLList {
    private static class IntNode {
        public int item;
        public IntNode next;

        public IntNode(int i, IntNode n) {
            item = i;
            next = n;
        }
    }

    private IntNode first;

    public SLList(int x) {
        first = new IntNode(x, null);
    }
}
```

## 链表长度计算与状态缓存

### 线性遍历与私有递归辅助方法

* **私有递归辅助函数（Private Recursive Helper Method）**
    * > **定义**：在非递归容器类内部定义的接收底层节点作为参数的私有辅助算法函数。
    * 解决外层容器无法直接在自身引用上递归调用的结构性断层。
    * 对外暴露无参公共查询接口，对内递归解引用底层节点链条。

* **尾部追加算法（Tail Append，addLast）**
    * > **定义**：遍历定位链表当前末尾节点并将新建节点挂载于其后继指针的操作。
    * 循环判断当前节点的 `next` 是否为 `null`，非空则指针持续后移。
    * 末尾节点后继指针挂接新建节点，时间复杂度为线性阶 $O(N)$。

```java
private static int size(IntNode p) {
    if (p == null) {
        return 0;
    }
    return 1 + size(p.next);
}

public int size() {
    return size(first);
}
```

### 状态缓存机制

* **大小元数据缓存（Size Metadata Caching）**
    * > **定义**：在容器中持久化维护一个整型实例变量用于实时记录元素总数的优化机制。
    * 空间换时间策略：在每次插入或删除时同步自增或自减该变量。
    * 将元素总数查询操作的时间复杂度由线性阶 $O(N)$ 降至常数阶 $O(1)$。
    * > **提示**：Java 允许成员变量名与无参成员方法名同名并存，字段 `size` 与方法 `size()` 互不冲突。

```java
public class SLList {
    private IntNode first;
    private int size;

    public SLList(int x) {
        first = new IntNode(x, null);
        size = 1;
    }

    public void addFirst(int x) {
        first = new IntNode(x, first);
        size++;
    }

    public void addLast(int x) {
        size++;
        IntNode p = first;
        while (p.next != null) {
            p = p.next;
        }
        p.next = new IntNode(x, null);
    }

    public int size() {
        return size;
    }
}
```

## 哨兵节点拓扑与程序不变量

### 空链表特例危机与边界消除

* **空指针异常边界（Null Pointer Exception Boundary）**
    * > **定义**：空链表中首节点引用为 `null` 导致解引用其成员字段时触发的运行时崩溃。
    * 无参构造生成的空链表在执行尾部追加时直接访问 `p.next` 造成程序崩溃。
    * 采用条件特判 `if (first == null)` 会导致多维或更复杂数据结构中的分支逻辑急剧膨胀。

### 哨兵节点设计模式

* **哨兵节点（Sentinel Node）**
    * > **定义**：常驻于单链表前端且不存储实际有效业务数据的占位哑节点。
    * 链表对象在初始化时即创建哨兵节点，容器引用始终绑定该节点且永不为 `null`。
    * 真实数据节点自哨兵后继 `sentinel.next` 起顺次挂载。
    * 空列表状态下哨兵后继指针直接指向 `null`。
    * 将空列表与非空列表的拓扑行为完全统一，消除插入操作中的条件分支特判。

```text
1. 空列表状态：
+---------------+
|    SLList     |
| sentinel: --+ |
+-------------|-+
              |
              v
        +--------+------+
        | item:47| next | ---> null
        +--------+------+
         (哨兵节点)

2. 存入 10 和 15 后的状态：
+---------------+
|    SLList     |
| sentinel: --+ |
+-------------|-+
              |
              v
        +--------+------+      +--------+------+      +--------+------+
        | item:47| next | ---> | item:10| next | ---> | item:15| next | ---> null
        +--------+------+      +--------+------+      +--------+------+
         (哨兵节点)               (首个真实节点)          (尾部真实节点)
```

```java
public class SLList {
    private static class IntNode {
        public int item;
        public IntNode next;

        public IntNode(int i, IntNode n) {
            item = i;
            next = n;
        }
    }

    private IntNode sentinel;
    private int size;

    public SLList() {
        sentinel = new IntNode(47, null);
        size = 0;
    }

    public SLList(int x) {
        sentinel = new IntNode(47, null);
        sentinel.next = new IntNode(x, null);
        size = 1;
    }

    public void addFirst(int x) {
        sentinel.next = new IntNode(x, sentinel.next);
        size++;
    }

    public int getFirst() {
        return sentinel.next.item;
    }

    public void addLast(int x) {
        size++;
        IntNode p = sentinel;
        while (p.next != null) {
            p = p.next;
        }
        p.next = new IntNode(x, null);
    }

    public int size() {
        return size;
    }
}
```

### 程序不变量理论

* **程序不变量（Program Invariant）**
    * > **定义**：在数据结构完整生命周期及所有公共操作执行前后均恒定保持为真的逻辑断言。
    * 哨兵非空不变量：`sentinel` 引用永远指向一个真实分配的节点对象。
    * 首元定位不变量：首个真实业务元素若存在，必然且唯一挂载在 `sentinel.next`。
    * 规模一致不变量：元数据字段 `size` 的数值始终精准等于真实有效节点的总数量。

### 结构重构演进全景

| 演进阶段 | 改造动作 | 核心工程收益 |
| :--- | :--- | :--- |
| 节点解耦 | 将 `IntList` 更名为 `IntNode` | 明确离散节点定位，剥离面向用户的列表职责 |
| 容器包装 | 引入 `SLList` 封装首指针 | 隐藏底层裸递归与 `null` 初始化细节 |
| 访问私有化 | 将成员变量设为 `private` | 建立安全访问边界，杜绝外部破坏指针拓扑 |
| 静态嵌套 | `IntNode` 作为私有静态嵌套类 | 消除隐式外部类引用指针，节约近三分之一节点内存 |
| 元数据缓存 | 引入 `size` 计数变量 | 空间换时间，长度查询由 $O(N)$ 降至 $O(1)$ |
| 哨兵节点 | 引入常驻虚拟头节点 `sentinel` | 统一空表与非空表拓扑结构，消除空指针条件特例 |

### 线性遍历与常数缓存推导

* **推导场景**：
    * 采用递归遍历实现无缓存 `size()` 方法，处理 1000 个元素耗时 2 秒。
    * 维持软硬件环境不变，计算处理 100 万个元素所需的耗时。
* **复杂度依据**：
    * 递归遍历时间复杂度为线性阶 $O(N)$，执行时间与元素总量呈严格正比例对应。
    * 规模增长倍率：
      $$\frac{1,000,000}{1,000} = 1000$$
    * 线性耗时推导：
      $$2 \text{ s} \times 1000 = 2000 \text{ s} \approx 33.3 \text{ min}$$
* **最终耗时结论**：
    * **2000 秒**（约 33 分 20 秒）。
