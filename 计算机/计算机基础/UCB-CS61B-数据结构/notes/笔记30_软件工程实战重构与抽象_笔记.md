# 软件工程实战重构与抽象

## 瓦片网格几何光栅化与方法设计决策

### 离散几何光栅化推导

* **水平扫描线光栅化（Horizontal Scanline Rendering）**
    * > **定义**：将几何图形沿离散网格的水平行切片，通过连续填充单行离散水平线段拼合目标图形的光栅化策略。
    * 对称分割机理：边长为 $s$ 的正六边形垂直总高度为 $2s$ 网格单元，划分为上下各 $s$ 行对称处理。
    * 上半部几何规律：设行索引 $r \in [0, s-1]$，起始坐标满足 $(x - r, y - r)$，单行线段长度为 $s + 2r$。
    * 下半部几何规律：设行索引 $r \in [0, s-1]$，起始基准为 $(x - s + 1, y - s)$，第 $r$ 行起始坐标为 $(x - s + 1 + r, y - s - r)$，单行线段长度为 $(3s - 2) - 2r$。
    * 几何约束：正六边形水平扫描线的最大宽度恒为 $3s - 2$。

```text
        +---------------+      --- 第 0 行: 宽 s, 起点 (x, y)
       /                 \
      +-------------------+    --- 第 1 行: 宽 s + 2, 起点 (x - 1, y - 1)
     /                     \
    +-----------------------+  --- 第 s - 1 行: 宽 3s - 2 (上半部最大宽度)
    +-----------------------+  --- 下半部第 0 行: 宽 3s - 2 (镜像衔接)
     \                     /
      +-------------------+    --- 下半部第 1 行: 宽 3s - 4
       \                 /
        +---------------+      --- 下半部第 s - 1 行: 宽 s
```

### 状态变更与设计决策

* **原地修改与纯函数权衡（In-place Mutation vs. Pure Function）**
    * > **定义**：在图形绘制与网格更新时，直接就地修改共享画布状态，或是分配并返回全新状态快照的架构决策。
    * 内存开销对比：纯函数在每次绘制时复制尺寸为 $W \times H$ 的二维数组，引发高频垃圾回收；原地修改将时间与空间开销压缩至 $O(1)$ 辅助内存。
    * 状态控制模型：图形缓冲区本质为离散状态机，原地修改具备直接映射物理显存的性能优势。
    * > **易错点**：原地修改会引入方法副作用，若调用链中存在并发访问或缺乏明确调用顺序，会导致画面撕裂或状态脏读。

* **叙事性代码风格（Narrative Code）**
    * > **定义**：显式引入具象业务语义的局部锚点变量，消除多重负号与复合偏移计算的代码表达范式。
    * 认知负荷压缩：将复杂的几何推导展开为基准锚点（如 `firstX`, `firstY`, `firstLength`）与单步线性递推。
    * 维护边界：避免将跨维度坐标偏移与边界扣减硬编码在单行参数列表中。

```java
// 具叙事性的下半部六边形渲染实现
int firstX = this.x - (this.size - 1);
int firstY = this.y - this.size;
int firstLength = 3 * this.size - 2;

for (int rowNum = 0; rowNum < this.size; rowNum++) {
    int startX = firstX + rowNum;
    int startY = firstY - rowNum;
    int length = firstLength - 2 * rowNum;
    drawHorizontalLine(world, startX, startY, length, this.tile);
}
```

### 现场调试与参数验证

* **参数偏移探测法（Parameter Offset Probing）**
    * > **定义**：通过向目标调用接口的人工输入端注入已知常量位移，通过输出坐标变化逆向验证管线连通性的调试技术。
    * 连通性判据：若输入坐标增加固定位移而画面输出同步平移，证明渲染调用管线正常；若画面毫无响应或坐标归零，证明状态丢失发生在上游构造或传递阶段。

* **构造函数自赋值缺陷（Self-Assignment Defect）**
    * > **定义**：构造方法中因遗漏 `this.` 限定符，导致形参与形参自身完成无意义赋值的逻辑错误。
    * 破坏机理：该错误不会触发语法与编译报错，但会导致实例成员变量保留底层类型的默认初始零值。
    * > **易错点**：缺失 `this.` 会使图形坐标静默降解为 $(0, 0)$，导致几何体丢失或被绘制在视口不可见的边缘角落。

## 拓扑蜂窝生成与常量抽象重构

### 空间拓扑与装配计算

* **六边形蜂窝列装配（Hexagonal Column Assembly）**
    * > **定义**：以单列六边形为基础装配单元，依据几何外包尺寸进行周期性错位平移的拓扑拼接算法。
    * 同列垂直步长：同列紧邻的六边形在 Y 轴上的步进距离恒为单个六边形的几何高度，满足 $\Delta Y_{col} = 2s$。
    * 列间水平位移：相邻列在 X 轴上的位移等于正六边形平顶宽度加上单侧水平倾角投影，满足 $\Delta X = 2s - 1$。
    * 列间交错位移：为了实现无缝拓扑咬合，相邻列之间在 Y 轴上必须上下错开半个六边形高度，满足 $\Delta Y = s$。
    * 蜂窝列高分布：卡坦岛式标准对称蜂窝结构的 5 列高度数组满足序列 $[3, 4, 5, 4, 3]$。

```text
       列 0     列 1     列 2     列 3     列 4
      (3个)    (4个)    (5个)    (4个)    (3个)

                         [H]
                [H]               [H]
       [H]               [H]               [H]
                [H]               [H]
       [H]               [H]               [H]
                [H]               [H]
       [H]               [H]               [H]
                [H]               [H]
                         [H]
```

### 坏味道规避与环境表现

* **散弹式修改与常量提取（Shotgun Surgery & Constant Extraction）**
    * > **定义**：系统中某项参数调整迫使多处业务逻辑中的硬编码数值同步发生级联变更的代码坏味道。
    * 重构准则：将分散在初始化、边界检查、绘图循环中的离散整数字面量收拢为私有静态常量。
    * > **易错点**：未统一抽取常量会导致画布边界与逻辑检查范围脱节，直接引发 `ArrayIndexOutOfBoundsException` 运行时数组越界异常。

* **受控色彩抖动（Controlled Color Variance）**
    * > **定义**：在基础材质的固定 RGB 分量上施加有界伪随机微扰，用于消除大面积平铺带来的机械感。
    * 扰动边界控制：为每个地块实例生成独立随机偏移量，严格限定 RGB 扰动区间在特定阈值内，保持地块类型语义可区分。

## 交互循环与持久状态留存机制

### 实时驱动与渲染优化

* **事件驱动游戏主循环（Event-Driven Game Loop）**
    * > **定义**：采用阻塞或非阻塞轮询机制监听输入外设，仅在状态发生实质变更时触发生命周期重绘的控制架构。
    * 重绘约束规则：严格禁止无输入时的盲目全量重绘；必须将画布清空与瓦片渲染动作约束在按键事件触发的分支内。
    * > **注意**：无休眠的全量无条件刷新会导致主线程 CPU 核心占用率飙升，并引发图形双缓冲区的频繁撕裂抖动。

* **瓦片状态恢复模式（Tile State Restoration Pattern）**
    * > **定义**：在实体对象进入目标网格前缓存背景瓦片数据，在实体离开后精确回填原瓦片的无痕穿行机制。
    * 操作阶段：
        1. 动体发生坐标位移前，将暂存的旧瓦片引用写回旧网格单元；
        2. 经过边界与碰撞判定后，更新当前主键坐标；
        3. 提取目标坐标位置的原生瓦片并暂存到缓存指针中；
        4. 将动体瓦片覆盖写入目标网格单元并触发单帧重绘。
    * 留痕缺陷（Footprint Bug）机理：实体在移动时若直接覆写目标瓦片且未暂存底层环境，原地图静态地貌将被永久破坏。

### 架构衰退与测试边界

* **领域模型贫血退化（Domain Model Anemia Degradation）**
    * > **定义**：生成期创建的高层领域实体被立即解构并丢弃，系统退化为无结构二维原始数据矩阵的反模式。
    * 抽象层断裂：二维瓦片数组属于只读或只写的物理渲染画布，并非领域业务模型。
    * 演进代价：若未持久化聚合根对象，后续寻路判定、房间连通性判断以及地貌交互将退化为代价高昂的像素级逆向图形推导。
    * 架构规范：生成阶段产出的结构化实体（六边形、房间、走廊）必须显式存入列表、图或拓扑树中进行全生命周期维护。

* **GUI 渲染与无副作用逻辑解耦（Render-Logic Decoupling）**
    * > **定义**：将确定性的几何拓扑不变量推导，从依赖图形视窗的渲染逻辑中彻底剥离的工程规范。
    * 测试有效性准则：针对图形输出界面编写单元断言性价比极低；单元测试应集中覆盖无副作用的纯计算逻辑（如连通性无环验证、数组跨度公式验证）。

## 系统复杂度哲学与重构准则

### 复杂度根源与分类

* **软件复杂度（Software Complexity）**
    * > **定义**：任何使得软件系统内部结构难以被理解和难以被修改的物理特征集合（John Ousterhout 定义）。
    * 放大效应：系统复杂度具有非线性的累积效应，局部随意打补丁的战术决策将导致后续整体维护边际成本呈指数级上升。

* **系统依赖性（Dependencies）**
    * > **定义**：某处代码的修改强制牵扯其他分散模块同步发生级联变更的隐式拓扑关联。
    * 表现形态：状态变更、底层瓦片复原、物理坐标递增强行交织在深层嵌套的条件判断中，修改任何分支执行次序均会破坏系统不变量。

```text
                     +---------------------------------------+
                     |           系统复杂度的两大根源          |
                     +---------------------------------------+
                                    /         \
                                   /           \
        +----------------------------+       +----------------------------+
        |   依赖性 (Dependencies)     |       |    晦涩性 (Obscurity)      |
        +----------------------------+       +----------------------------+
        | 某处代码的修改必须牵扯      |       | 关键信息在表面上不可见，   |
        | 另一处代码的同步变更；      |       | 充满魔数与不直观命名，     |
        | 执行顺序产生隐式强耦合。    |       | 意图完全被底层细节掩盖。   |
        +----------------------------+       +----------------------------+
```

* **系统晦涩性（Obscurity）**
    * > **定义**：系统核心设计意图被底层散落的魔数与缺乏语义的运算式所遮蔽，使代码无法实现自解释的物理状态。
    * 表现形态：在控制分支中直接内嵌多重坐标偏移加减（如 `[playerX - 1][playerY + 1 - 1]`），掩盖了移动方向与碰撞检测的业务语义。

### 复杂度控制准则

* **战术修补防范原则（Anti-Tactical Patching）**
    * > **定义**：当发现既有设计与新增业务产生冲突时，立刻停下增量补丁编写，重新审视领域模型与数据结构的工程纪律。
    * 止损机制：坚决抵制在不合理的单薄结构上堆砌嵌套 `if` 梯队；通过解耦时序依赖和提取领域语义对象，在根源上阻断复杂度的蔓延。
