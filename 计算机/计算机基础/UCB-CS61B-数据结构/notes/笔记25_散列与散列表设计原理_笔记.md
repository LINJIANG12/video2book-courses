# 散列与散列表设计原理

## 检索范式转换与哈希表基本架构

### 全序比较局限与直接寻址权衡

* **全序比较（Total Order Comparison）**
    * > **定义**：要求数据集合中任意两个元素都存在明确且可传递的大小先后关系的比较模型。
    * 结构依赖：标准二叉搜索树（BST）、2-3 树及左倾红黑树（LLRB）均严格依赖全序关系执行空间分支判定。
    * 理论边界：基于元素比较的平衡树结构增删查操作时间复杂度理论下界为 $\Theta(\log N)$。
    * 应用局限：音频、多媒体文件等无绝对大小顺序的复合数据无法直接适用。
    * > **易错点**：缺乏全序比较能力的对象无法直接作为标准搜索树的键，若未实现比较接口会导致结构瘫痪。

* **直接地址映射（Direct Address Mapping）**
    * > **定义**：为键值域中的每一个可能取值在内存中预先开辟唯一对应存储槽的寻址方式。
    * 时间特性：数据插入、删除与包含判定耗时均为绝对常数时间 $\Theta(1)$。
    * 空间代价：若针对 32 位整型全域进行预分配，需创建 $2^{32} \approx 42.9$ 亿个桶位。
    * > **易错点**：直接寻址在稀疏数据集合下会引发灾难性内存浪费，存在不可调和的时空权衡（Space-Time Tradeoff）。

### 桶阵列与取模规约机制

* **多列表分流（Multiple Lists / Bucketing）**
    * > **定义**：将单一线性表拆分为 $M$ 个独立的子列表，利用映射规则将元素分流存储的数据组织形式。
    * 桶（Bucket/Bin）：底层数组中保存的每一个独立子列表，物理实现通常为链表。
    * 平均链长：在元素分布均匀的前提下，每个桶挂载的元素数量期望为 $N/M$。

* **规约函数（Reduction Function）**
    * > **定义**：将任意范围的整数数据压缩映射至有限区间 $[0, M-1]$ 的数学转换规则。
    * 标准取模规约公式：
      $$\text{Bucket Index} = x \bmod M$$
    * 检索加速比：在理想均匀分布下，取模规约将线性表的遍历规模降低至初始状态的 $1/M$。

```text
数组索引 (桶号)       挂载的链表数据
  [0]        --->  [70] -> null
  [1]        --->  [31] -> [91] -> null
  [2]        --->  [12] -> null
  [3]        --->  null
  [4]        --->  [34] -> null
  [5]        --->  [15] -> [85] -> null
  [6]        --->  [56] -> null
  [7]        --->  null
  [8]        --->  [78] -> null
  [9]        --->  null
```

## 动态扩容机制与均摊性能分析

### 负载因子与几何扩容阈值

* **负载因子（Load Factor，$\lambda$ 或 $L$）**
    * > **定义**：当前集合中元素总数 $N$ 与桶数组总容量 $M$ 的比值。
    * 数学表达式：
      $$L = \frac{N}{M}$$
    * 物理意义：反映哈希表在理想均匀分布状态下各个桶内链表的平均长度。
    * 扩容判定：当负载因子触碰工程设定的上限阈值（如 $L \ge 1.5$）时，系统强制触发数组扩容。

### 重新散列物理迁移与均摊常数时间

* **重新散列（Rehash）**
    * > **定义**：扩容后底层桶数量 $M$ 发生改变，所有既有元素必须基于新模数重新计算槽位并物理迁移的过程。
    * 寻址变更机理：模数由 $M$ 翻倍为 $2M$ 后，元素的存储索引从 $x \bmod M$ 变为 $x \bmod 2M$。
    * 状态重构成本：单次扩容需要线性遍历并搬迁全部 $N$ 个已有元素，耗费 $\Theta(N)$ 时间复杂度。

* **均摊常数时间（Amortized $\Theta(1)$）**
    * > **定义**：通过几何级数递增分配容量，将偶发的高昂扩容成本平摊至每一次基础操作后的时间度量。
    * 长度物理压制：扩容规则确保 $N/M$ 始终处于常数阈值之下，桶内遍历比对操作与总规模 $N$ 无关。
    * > **提示**：固定桶数不扩容会导致哈希表随 $N$ 增大退化为 $\Theta(N)$ 链表，必须配合倍增扩容方可锁定均摊 $\Theta(1)$ 性能。

```text
扩容前 (M = 4, N = 6, L = 1.5):
  [0] ---> [16] -> null
  [1] ---> [13] -> null
  [2] ---> [2]  -> [10] -> null
  [3] ---> [7]  -> [11] -> null

触发扩容 (M 翻倍为 8, 执行 Rehash):
  [0] ---> [16] -> null
  [1] ---> null
  [2] ---> [2]  -> [10] -> null
  [3] ---> [7]  -> [11] -> null
  [4] ---> null
  [5] ---> [13] -> null       <-- 13 从 1 号桶迁移至 5 号桶
  [6] ---> null
  [7] ---> null
扩容后 (M = 8, N = 6, L = 0.75)
```

## 对象整数化与多项式散列编码

### 进制定律与非零编码模型

* **多进制权重展开（Base-B Expansion）**
    * > **定义**：将字符串中各位置字符视作多进制数的高低位，计算其多项式加权和的数值转换方法。
    * 权重展开通式：
      $$\text{val} = \sum_{i=0}^{k-1} c_i \times B^{k-1-i}$$
    * 编码非零规则：小写英文字母映射必须从 1 开始编码（$a=1, b=2, \dots, z=26$），不可从 0 起始。
    * > **易错点**：若设定 $a=0$，则字符序列 `"a"` 与 `"aaa"` 计算得到的高位乘积均为 0，导致前导字符信息彻底丢失并引发伪冲突。

### 秦九韶算法与多项式求值

* **秦九韶算法（Horner's Rule）**
    * > **定义**：将高次多项式转化为嵌套一次因式乘积，在单重循环中逐位累积求值的快速算法。
    * 运算迭代通式：
      $$\text{hash}_i = \text{hash}_{i-1} \times B + c_i$$
    * 字符集基数选取：
        * ASCII 可打印字符集（编号 $33 \sim 126$）：基数通常选用 $B = 126$；
        * Unicode 跨语言扩展字符集：基数需选用更大数值以覆盖表意文字区间。

```java
// 秦九韶算法字符串哈希计算实现
int hash = 0;
for (int i = 0; i < s.length(); i++) {
    hash = hash * 126 + s.charAt(i);
}
```

## 整数溢出与哈希冲突必然性

### 补码溢出与环形回绕特性

* **32 位有符号整数溢出（Integer Overflow）**
    * > **定义**：计算数值超出 32 位有符号二进制补码表示范围时，硬件截断最高进位引发的数值翻转现象。
    * 物理值域边界：$[-2^{31}, 2^{31} - 1]$，即 $[-2147483648, 2147483647]$。
    * 环形回绕（Wrap Around）：在补码体系中，最大正整数继续累加将越过边界跳转至最小负数：
      $$2147483647 + 1 = -2147483648$$
    * 运行表象：多项式连续相乘累加后，长字符串及复杂对象的哈希计算值高概率呈现为负整数。

### 鸽巢原理与哈希码数学本质

* **鸽巢原理（Pigeonhole Principle）**
    * > **定义**：若将 $P$ 只鸽子放入 $H$ 个巢穴且 $P > H$，则至少存在一个巢穴容纳两只或两只以上的鸽子。
    * 映射空间对立：字符串与复合对象的组合空间无限大（$P \to \infty$），而 32 位整型输出空间有限（$H = 2^{32} \approx 4.29 \times 10^9$）。
    * 绝对碰撞性：无论散列函数构造多么复杂，数学上必然存在不同输入对象映射至完全相同的整型数值。

* **哈希码（Hash Code）**
    * > **定义**：将规模无限的对象全集确定性压缩映射至固定大小整型数值空间的函数输出结果。
    * 哈希冲突（Hash Collision）：满足 $x \neq y$ 却存在 $\text{hashCode}(x) = \text{hashCode}(y)$ 的客观状态。

## 冲突解决策略与工程实现规范

### 分离链接法与等价判定语义

* **分离链接法（Separate Chaining）**
    * > **定义**：将所有映射至相同桶索引的键值对串接在同一个单链表中的冲突处理策略。
    * 定位检索双层逻辑：
        1. 基于哈希码与模数定位桶索引（粗粒度分流）；
        2. 遍历桶内链表，调用 `equals` 方法逐一比对键的内容（细粒度精确匹配）。
    * > **注意**：哈希码仅用于缩小检索候选范围，包含判定（`contains`）绝不可仅凭桶内非空做决定，必须以 `equals` 判定为准。

```text
Hash Code & 模运算             桶数组 (Buckets)            链表节点 (equals 逐个比对)
"cat"    -> 2074 % 4 = 2  ==>   [0] -> null
"hug"    -> 3480 % 4 = 0  ==>   [1] -> null
"potato" -> 7812 % 4 = 0  ==>   [2] -> ["cat"] -> null
                                [3] -> null
                                 ^
                                 |  "potato" 与 "hug" 发生哈希冲突，同入 0 号桶:
                                [0] -> ["hug"] -> ["potato"] -> null
```

### 负数哈希码与向下取模修正

* **截断取余与向下取模语义分歧**
    * > **定义**：计算底层对负数商的取整策略差异导致取余与取模在负被除数场景下的不同输出结果。
    * 语言级取余陷阱：Java 的 `%` 运算符执行截断除法取余，负数参与运算保留负号：
      $$-1 \% 4 = -1$$
    * 数组越界隐患：直接利用 `hashCode() % M` 计算桶索引会导致 `ArrayIndexOutOfBoundsException` 异常。

* **向下取模（Floor Modulo）规范**
    * 几何周期语义：负数索引应在模数周期内进行逆向环形循环映射，$-1$ 在模 4 运算下严格等价于 $3$。
    * 标准库工程规范：必须使用 `Math.floorMod` 代替原生 `%` 运算符以保证桶索引非负。

```java
// 正确安全的非负桶索引计算规范
int bucketIndex = Math.floorMod(obj.hashCode(), M);
```

```text
正向索引 (顺时针):   0  -->  1  -->  2  -->  3
逆向循环 (倒数):    -4     -3     -2     -1
对应物理桶号:       [0]    [1]    [2]    [3]
```

## 性能边界评估与树化兜底机制

### 桶分配策略复杂度对比

| 机制类型 | 桶数量 $M$ | 负载因子 $L = N/M$ | 增删查平均耗时 | 极端最坏耗时 | 空间开销评估 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **单固定列表** | $M = 1$ | $N$ | $\Theta(N)$ | $\Theta(N)$ | 无多余引用数组，检索退化为单链表遍历 |
| **固定常数桶** | $M = C$ | 随 $N$ 增大线性飙升 | $\Theta(N/M) = \Theta(N)$ | $\Theta(N)$ | 无法适应动态数据流，最终退化为长链表 |
| **全量预分配** | $M = 2^{32}$ | 趋近于 0 | $\Theta(1)$ | $\Theta(1)$ | 占用海量虚构内存空间，物理工程不可行 |
| **动态翻倍扩容** | 随 $N$ 动态倍增 | 严格受控（$L < 1.5$） | $\Theta(1)$（均摊） | $\Theta(N)$（哈希全冲突） | 空间随需求动态扩展，达到时空平衡 |

### 均匀分布假设与红黑树退化防护

* **均匀分布假设（Uniform Distribution Assumption）**
    * 性能前置条件：哈希表均摊 $\Theta(1)$ 时间复杂度的成立完全建立在哈希值在各桶间均匀散布的假设之上。
    * 恶劣碰撞退化：若哈希函数质量低劣或遭受恶意碰撞攻击，大量键映射至同一桶位，操作耗时将跌落至 $\Theta(N)$。

* **自适应树化兜底机制（Treeification）**
    * 触发阈值：工业级实现（如 Java 8 `HashMap`）设定单桶链表长度超过阈值 8 时触发结构改造。
    * 结构重塑：将超长单链表物理重构为平衡二叉搜索树（红黑树）。
    * 防御收益：将单桶内极端最坏情况下的检索与插入耗时物理下界强制锁定为 $\Theta(\log N)$。

## 典型计算推演与例题分析

### 多项式进制编码计算推导

* **例题**：采用 26 进制编码模型（$a=1, b=2, \dots, z=26$），求字符串 `"cat"` 与 `"bee"` 展开后的十进制整数值。
* **推导过程**：
    * 字符串 `"cat"`：
      $$\text{字符映射}：c = 3, \quad a = 1, \quad t = 20$$
      $$\text{多项式值} = 3 \times 26^2 + 1 \times 26^1 + 20 \times 26^0 = 3 \times 676 + 26 + 20 = 2028 + 26 + 20 = 2074$$
    * 字符串 `"bee"`：
      $$\text{字符映射}：b = 2, \quad e = 5, \quad e = 5$$
      $$\text{多项式值} = 2 \times 26^2 + 5 \times 26^1 + 5 \times 26^0 = 2 \times 676 + 130 + 5 = 1352 + 130 + 5 = 1487$$
* **推演结论**：`"cat"` 对应十进制整数为 **2074**；`"bee"` 对应十进制整数为 **1487**。

### 负数取模桶索引映射计算

* **例题**：已知哈希表包含 $M = 4$ 个桶（合法物理索引为 $0, 1, 2, 3$）。若某数据对象的 `hashCode()` 为 `-1`，计算其理论桶编号，并给出代码规避方案。
* **推导过程**：
    * 数学周期模映射：
      $$-1 \equiv (-1 + 4) \pmod 4 \equiv 3 \pmod 4$$
    * Java 取余算子截断特征：
      $$-1 \% 4 = -1 \quad (\text{产生非法负索引})$$
    * 向下取模函数修正：
      $$\text{Math.floorMod}(-1, 4) = 3 \quad (\text{输出合法非负索引})$$
* **推演结论**：该对象在数学语义上归属于 **3 号桶**；工程实现必须采用 `Math.floorMod(hashCode, 4)` 确保寻址正确。
