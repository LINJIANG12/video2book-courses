# 接口继承与子类型多态

## 抽象接口与类型系统契约

### 语言学层级与接口规约

```text
               +-------------------+
               |   实体 (Entity)    |
               +-------------------+
                         |
                         v
               +-------------------+
               |    列表 (List)     |  <-- 上位词 (Hypernym)
               +-------------------+
                  /               \
                 /                 \
                v                   v
        +---------------+   +---------------+
        |  数组列表      |   |  链表列表      |  <-- 下位词 (Hyponyms)
        |  (AList)      |   |  (SLList)     |
        +---------------+   +---------------+
```

* **上位词与下位词（Hypernym and Hyponym）**
    * > **定义**：语言学中用以描述概念自抽象范畴向具体特化逐级展开的层次分类模型。
    * 上位概念规范公共行为能力，下位概念完整承接并特化落实该行为能力。
    * 面向对象类型体系直接映射此层级结构，以上位接口统合差异化实现。

* **接口契约（Interface Contract）**
    * > **定义**：仅声明方法签名以规定对象能力清单而不包含底层状态与实现逻辑的抽象规约。
    * 接口内部绝不能包含构造函数，严禁执行直接实例化操作。
    * 接口方法签名隐式具备 `public abstract` 属性修饰。
    * > **注意**：接口契约必须剔除底层特化机制，类似动态数组特有的扩容操作绝对不能暴露在通用列表接口中。

```java
public interface List61B<Item> {
    void addFirst(Item x);
    void addLast(Item x);
    Item getFirst();
    Item getLast();
    Item get(int i);
    int size();
    Item removeLast();
    void insert(Item x, int position);
}
```

### 契约实现与多态机制

* **契约实现与多态形参（Contract Implementation and Polymorphic Parameter）**
    * > **定义**：具体类通过声明实现接口以确立子类型身份，使高层算法直接面向抽象接口编程的技术手段。
    * 类通过 `implements` 关键字向编译器担保自身完全满足目标接口规约。
    * 静态方法形参声明为接口类型后，可无差别接收任意满足该接口的子类实例。
    * 代码库借此消除了因数据结构不同而复制多份同名算法的冗余开销。

* **方法重写与方法重载（Method Overriding and Overloading）**
    * > **定义**：重写是子类对父类或接口相同方法签名的精确再实现；重载是同一作用域内方法名相同但参数列表不同的签名分流。
    * 重写要求方法名、参数类型、参数数量及顺序严格一致，且允许返回类型协变。
    * `@Override` 注解驱动编译器启动契约核对检查，确保当前方法准确覆盖超类定义。
    * > **易错点**：方法重写时若发生拼写错误且未标注 `@Override`，编译器会将其静默判定为子类特化的独立方法，导致多态调用失效。

* **静态类型与动态类型（Static Type and Dynamic Type）**
    * > **定义**：静态类型为变量在编译期声明的显式类型；动态类型为堆内存中对象在运行期被实例化出来的真实物理类型。
    * 编译期类型检查严格依据变量的静态类型判定方法调用的合法边界。
    * 运行期虚拟机通过动态方法分派定位堆中对象真实所属类的具体执行逻辑。
    * > **易错点**：若动态类型所拥有的特化方法未在静态类型接口中登记，直接通过该接口引用调用特化方法将触发编译报错。

```text
 编译期视界 (静态类型)                   运行期视界 (动态类型)
+-----------------------+              +-----------------------+
| someList: List61B     |  =======>    | 堆中实体: SLList 实例  |
| 仅暴露 List61B 接口方法 |  (引用指向)  | 具备 SLList 全部字段与方法|
+-----------------------+              +-----------------------+
```

## 实现继承与抽象数据类型选型

### 默认方法与算法复杂度陷阱

* **默认方法（Default Method）**
    * > **定义**：接口使用 `default` 关键字修饰且内建具体方法体的行为复用机制。
    * 允许接口在保持向后兼容性的同时为实现类提供开箱即用的公共算法逻辑。
    * 子类拥有自主选择权，既可直接继承默认行为，亦可通过覆盖重写特化实现。

```java
public interface List61B<Item> {
    // 抽象契约略
    default void print() {
        for (int i = 0; i < size(); i += 1) {
            System.out.print(get(i) + " ");
        }
        System.out.println();
    }
}
```

* **算法复杂度性能悬崖（Performance Cliff in Default Implementation）**
    * > **定义**：高层默认方法机械套用抽象行为在不同底层结构中导致运行时代价呈指数级分化的性能缺陷。
    * 数组结构具备基于物理内存连续分布的常数时间寻址能力，循环执行默认打印算法的时间复杂度维持在线性阶 $O(n)$。
    * 单向链表通过下标单步定位需自头节点起迭代步进，读取索引 $i$ 耗费 $O(i)$ 次指针跳跃。
    * 链表直接沿用默认打印逻辑的时间开销为等差数列累加，总运行时间暴增至二次方阶 $O(n^2)$：
$$\sum_{i=0}^{n-1} i = \frac{n(n-1)}{2} = O(n^2)$$
    * > **注意**：链表子类必须重写覆盖默认方法，利用原生指针单向遍历将耗时强制压回线性阶 $O(n)$。

* **脆弱基类问题（Fragile Base Class Problem）**
    * > **定义**：基类具体实现的深层变动引发派生子类产生不可预期逻辑崩溃的架构强耦合隐患。
    * 接口继承仅规定行为边界，利于解耦；实现继承注入具体代码与状态，诱发强依赖。
    * 系统设计应严守克制，优先采用接口继承组合逻辑，杜绝无限制延展的多层实现继承。

### 抽象数据类型底层存储适配

```text
 栈结构方案对比:
 [单向链表] Head -> [Node 3] -> [Node 2] -> [Node 1] -> null (头插头删，严格 O(1))
 [动态数组] [Node 1 | Node 2 | Node 3 | 空闲位 ] (尾插尾删，均摊 O(1)，偶发扩容)

 百宝袋随机抽取方案对比:
 [动态数组] 基于下标瞬间定位: items[randomIndex] (严格 O(1))
 [单向链表] 自头节点单向步进寻址: p = p.next 重复 k 次 (平均 O(n))
```

* **栈结构选型（Stack Implementation Tradeoff）**
    * > **定义**：遵循后进先出（LIFO）规约且仅在单端进行压栈与弹栈操作的抽象数据类型。
    * 单向链表以头节点作为栈顶，压栈与弹栈仅涉及常数级引用重定向，操作耗时恒定为严格的 $O(1)$。
    * 动态数组以末尾下标作为栈顶，均摊时间复杂度为 $O(1)$，但装满时会触发倍增扩容拷贝开销。
    * 工程实践中单向链表因规避了瞬时扩容抖动而展现出更敏捷平稳的性能。

* **百宝袋选型（Bag Implementation Tradeoff）**
    * > **定义**：支持无序添加、总数统计以及高频执行均匀概率随机抽取元素（`grabRandom`）的抽象数据类型。
    * 动态数组利用随机整数下标进行内存物理偏移计算，定位抽取耗时严格处于常数阶 $O(1)$。
    * 单向链表缺乏直接寻址能力，定位目标位置必须耗费线性步进迭代，单次抽取代价高达 $O(n)$。
    * > **提示**：存在高频随机寻址特征的抽象数据类型在底层物理选型上必须强制绑定动态数组。

## 比较体系与编译期契约裁决

### 自然顺序与对象自度量规范

* **可比较接口（Comparable Interface）**
    * > **定义**：归属于 `java.lang` 核心包，用于赋予宿主实体类内生默认大小度量尺度的参数化接口。
    * 核心规约方法为 `int compareTo(T o)`，其返回值遵从严格的三态判定法则：
```text
 this < o  =====> 返回负整数 (< 0)
 this == o =====> 返回零 (= 0)
 this > o  =====> 返回正整数 (> 0)
```
    * 实体类一旦落地该接口，即确立了其在算法类库（如 `Collections.max`）中的唯一自然顺序。

* **类级私有访问作用域（Class-Level Scoping）**
    * > **定义**：Java 语言访问控制修饰符 `private` 施加于类代码块边界而非物理对象实例的作用域机制。
    * 编写于当前类作用域内的成员方法，拥有直接读取传入同类其他实例所有私有属性的合法权限。
    * 方法实现中直接解引用外部同类实例的私有字段完全符合编译器语法准则。

* **数值比对下溢风险（Arithmetic Underflow Hazard in Comparison）**
    * > **定义**：在重写比较方法时盲目采用数值直接相减替代大小判定引发整型边界翻转的数值错误。
    * 极小负数与极大正数执行减法运算会突破 32 位整型极限，反转为相反符号导致比较逆序。
    * > **注意**：工业生产环境严禁直接相减，必须使用逻辑条件分支判断或调用包装类型静态比对工具。

```java
public class Dog implements Comparable<Dog> {
    private String name;
    private int size;

    @Override
    public int compareTo(Dog uddaDog) {
        return Integer.compare(this.size, uddaDog.size);
    }
}
```

### 独立编译机制与契约缺失判定

* **解耦独立编译模型（Decoupled Separate Compilation）**
    * > **定义**：Java 编译体系中各个源文件以单一类为粒度独立生成对应字节码文件的解耦运行机制。
    * 上层库类或泛型工具方法仅核查形参静态契约的声明完整性，绝不依赖具体实现类的物理存在。
    * 具体业务实现类的代码修改或缺失，绝对无法逆向引发预编译类库自身的编译失败。

* **实现缺失编译归属（Compilation Failure on Missing Implementation）**
    * > **定义**：实体类在类头显式声明接口实现誓约，却未在类体内部给出非抽象方法具体逻辑的语法违规状态。
    * 编译器审查目标类时由于其未兑现非抽象方法的交付义务，当场将编译阻断在实体类自身源码中。
    * 外部调用启动类在此场景下由于被底层类的编译失败所截断，尚未进入深层类型核验阶段。

* **契约声明缺失编译归属（Compilation Failure on Missing Contract）**
    * > **定义**：实体类内部包含了契约所需的方法实现，但类头遗漏了接口继承声明的类型孤立状态。
    * 实体类本身语法完全合法，能够独立平稳编译生成合规的字节码文件。
    * 调用方调用依赖接口契约的方法时，编译器判定实参静态类型缺失必要上位身份，当场于调用方源码处报错。
    * > **易错点**：Java 属于强名义类型系统，即便实体类内部具备同名同参数结构，若无形式誓约亦不被视作合法子类型。

```text
 [变式 A: 类头写 implements, 无方法体]   ===> 编译器拦截在: Dog.java
 [变式 B: 类头无 implements, 有方法体]   ===> 编译器拦截在: DogLauncher.java
```

### 外部裁决器与多维排序

* **比较器接口（Comparator Interface）**
    * > **定义**：归属于 `java.util` 实用包，作为独立于待比较对象之外的第三方裁决策略规范的参数化接口。
    * 核心规约方法为 `int compare(T o1, T o2)`，支持针对同一实体对象灵活定制无限多元的比较维度。
    * 比较器具备完全的无侵入性，无需修改待度量类的既有源码即可实现排序维度的横向扩展。

* **静态嵌套裁决器（Static Nested Comparator）**
    * > **定义**：以内嵌静态类形式寄宿于实体类内部，与实体对象实例完全解绑的高内聚策略实现模式。
    * 非静态内部类隐式绑定至外部类的具体对象，脱离实体实例将无法独立完成实例化构建。
    * 静态嵌套类直接从属于外部类类型本身，支持外部调用方在零实体实例依赖下独立创建裁判对象。
    * > **提示**：工业级标准模式倾向于在宿主类内部定义私有静态比较器，并对外直接暴露静态单例常量。

```java
public class Dog implements Comparable<Dog> {
    public static final Comparator<Dog> NAME_COMPARATOR = new NameComparator();
    private String name;
    private int size;

    private static class NameComparator implements Comparator<Dog> {
        @Override
        public int compare(Dog a, Dog b) {
            return a.name.compareTo(b.name);
        }
    }
}
```

* **两类比较接口特性矩阵（Comparison Dimension Matrix）**

| 对比维度 | `Comparable<T>`（可比较接口） | `Comparator<T>`（比较器接口） |
| :--- | :--- | :--- |
| **所属包路径** | `java.lang.Comparable` | `java.util.Comparator` |
| **角色定位** | 实体内在自度量尺度 | 独立的场外仲裁者策略 |
| **核心抽象方法** | `int compareTo(T o)` | `int compare(T o1, T o2)` |
| **多态策略容量** | 单一唯一，锁定为自然顺序 | 无穷多元，支持任意业务维度横向扩展 |
| **源码侵入性** | 强侵入，必须改动待比较实体类源码 | 零侵入，可完全作为外部类独立扩展编写 |
| **典型调用入口** | `Collections.sort(list)` | `Collections.sort(list, comparator)` |

## 典型习题推演与解析

### 存储结构选型决策题

* **栈与百宝袋选型推演（ADT Storage Selection）**
    * > **提示**：核心考查数据结构对特定行为时间复杂度的微观支撑能力。
    * 题干情境：针对仅支持头部增删的栈（Stack）与高频执行均匀随机抽取的百宝袋（Bag）评估单向链表和动态数组的优劣。
    * 推演逻辑：栈操作高度内聚于顶端，单向链表以头插头删实现常数级指针切换，避免了动态数组因扩容导致的周期性耗时抖动；百宝袋依赖均匀随机抽选，动态数组物理空间连续，根据下标可瞬时实现常数时间寻址，而链表必须历经线性步进迭代。
    * 判定结论：栈结构首选单向链表以获取极小且稳定的常数运行性能；百宝袋结构强制选用动态数组以确立随机访问优势。

### 多态赋值与分派验证题

* **多态赋值与分派推演（Polymorphic Assignment Verification）**
    * > **提示**：核心考查编译期类型边界检查与运行期动态方法分派的协作闭环。
    * 题干情境：分析多态声明执行语句 `List61B<String> lst = new SLList<>(); lst.addFirst("hello");` 的运行表现。
    * 推演逻辑：`SLList` 实现了 `List61B` 接口，在面向对象体系中属于合法子类型，将堆中子类实例赋予超类引用完全符合赋值兼容规则，编译顺利放行；执行第二行时，静态类型 `List61B` 内部已完整收录 `addFirst` 抽象方法契约，调用合法；运行期 JVM 触发动态方法分派，准确命中并执行实际动态类型 `SLList` 对应的实现。
    * 判定结论：代码无语法冲突，编译顺利通过且运行期调用完全平稳正常。

### 契约缺失编译错误归属题

* **契约断裂报错归属推演（Compilation Error Attribution）**
    * > **提示**：核心考查独立编译机制下编译器对方法实现与接口名义契约的具体拦截位置。
    * 题干情境：三个独立文件协同，判定类中存在 `implements` 但缺失方法体（变式 A），以及存在方法体但缺失类头 `implements`（变式 B）时的编译报错归属文件。
    * 推演逻辑：变式 A 中，具体类宣誓了契约却违背交付实现义务，编译器解析当前实体类源码时即可直接判定语法错误，报错定位于具体类文件自身；变式 B 中，实体类内部方法结构自洽，独立编译平稳生成字节码，但在编译调用方源码时，编译器核查到传入实参静态类型未声明必需的接口契约，当场在调用端抛出参数类型不兼容故障。
    * 判定结论：变式 A 编译报错归属于实体类文件；变式 B 实体类独立编译通过，编译报错归属于调用方启动类文件。

### 比较器字典序评估题

* **字典序仲裁推演（Comparator Lexicographical Evaluation）**
    * > **提示**：核心考查外部比较器契约的三态返回值与字符串字符集编码关系。
    * 题干情境：执行小狗名字字典序比较器判定操作 `nc.compare(d1, d2)`，其中 `d1` 命名为 `"Frank"`，`d2` 命名为 `"Zic"`。
    * 推演逻辑：比较器内部直接代理调用字符串对象的 `compareTo` 方法，首字符比对在底层转换为对应 ASCII 码数值运算；大写字符 `'F'` 的底层数值为 70，大写字符 `'Z'` 的底层数值为 90，差值结果小于零，符合字典序在前的数学表达。
    * 判定结论：比较器判定前者小于后者，方法最终返回严格的负整数。
