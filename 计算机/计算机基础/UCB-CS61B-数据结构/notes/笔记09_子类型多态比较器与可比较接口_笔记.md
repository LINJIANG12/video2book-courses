# 子类型多态、比较器与可比较接口

## 函数传递与多态

   * **多态（Polymorphism）**

       * > **定义**：为不同的底层结构提供相同的接口。

       * 把“一段行为”提供给函数有两条主要路径：函数传递——把函数作为参数递进去；多态——不递函数，执行哪份代码由对象的类型在运行时决定。

       * 两者的关键差别：多态基于继承，函数传递不基于继承。

       * Python 的 `d1 > d2` 里的大于号就是多态：狗、猫、列表各自实现承载大于运算符的魔法函数；运算符背后触发一次函数调用，指向当前对象所属类的那份实现——max 在运行时拿到 item 并不确定它是 Dog 还是整数，大于运算符的表现却会自动不同。

       * Python 的函数传递形态：get_max 额外接收一个键函数（就像给 sorted 传 key），键函数一换比较标准就换——传一个“取名字长度”的裸函数（根本不属于 Dog 类）返回的就是名字最长的狗，键函数完全绕开了大于运算符。

       * 使用频率：Python 里两种都常见；Java 里显式传函数少见，Java 8 之后配合流（stream）还挺常见，Java 8 之前基本全靠多态。

   * **子类型多态（Subtype Polymorphism）**

       * > **定义**：超类型规定能力、子类型实现能力，运行时按调用者的实际类型选择执行哪个函数。

       * 核心思路：先定义一个超类型（比如 Comparable）来规定能力，再由子类型去实现它。

       * 与 Python 的分野：Python 用运算符重载、是动态类型——不必预先声明大于运算符怎么用，运行时判断，不可用就崩；Java 依赖子类型多态，很正式。

## Comparable 接口

   * **Comparable**

       * > **定义**：Java 官方的接口，专供“可比较的事物”；一个类声明 implements Comparable，等于承诺自己具备“可比较”这种能力。

       * 核心契约：比较此对象与指定对象的顺序；此对象小于、等于或大于指定对象时，分别返回负整数、零或正整数。

       * 接口本体只包含一个函数，却带着一百三十多行注释，并带类型参数 T——让 T 类型的对象和它自己比较。

       * 接口由 Josh Bloch 编写——他写出了最好的 Java 书，也维护着这门语言；企业级代码里注释多是常态，遇到疑问时注释就是最终答案的出处。

       * 让类“具备某种能力”的通用窍门：定义一个接口，然后声明这个类实现它。

   * **Collections.max 的报错**

       * Collections.max 能处理任意集合——列表算集合；对装着三只狗（Greg 200、Pollusa 5、Clifford 9000）的列表调用会报错：狗有名字和体型两个字段，但没说明如何区分两只狗的高下、该比什么。

       * 报错文本形如要求类型满足 `Comparable<? super T>` 之类的约束，不是 Java 专家很难读懂——它想表达的其实就一句：你没告诉 Java 狗能比较，也没提供比较方法。

       * Python 里的对应解法：在 Dog 上定义一个类似 `__gt__` 的魔法方法，接收 self 和另一只狗 other，返回体型上的比较结果。

       * > **易错点**：⚠️ 映射（Map）不是集合——它并没有继承 Collection 接口，而是独立的数据结构。

## compareTo 的实现

   * **compareTo**

       * 声明方式：在类声明顶部写 `implements Comparable<Dog>`，读作“Dog 可以和其他 Dog 比较”；声明一加却不给出具体方法，立刻报错。

       * 方法参数不需要 instanceof 类型判断（判断 o 是不是 Dog 实例的那种）——类型参数已写明是 Dog，参数本来就是一只狗，直接比就行。

       * 按契约的基本写法：比对方小返回 -1，相等返回 0，更大返回 1。

       * 更巧妙的差值写法：`return this.size - utDog.size;`——如体型 3 对 100，差值 -97，负号本身就携带“我更小”的全部信息；相等时差值为零，反过来就是正数。大部分比较函数都这么写。

       * 打印对象之前要给 Dog 补一个 toString，否则打出来就是随便什么奇怪的东西。

   * **@Override 注解**

       * 删掉 @Override，方法照样重写，行为没有任何变化。

       * 还要加着的理由：它是给程序员看的明确信号，让“我在重写”这个意图显式化，也让编译器帮你把关——保持加着的习惯就好。

   * **private 的文件级规则**

       * > **定义**：private 看的是代码在哪个文件里，而不是“能不能访问其他实例的变量”。

       * 只要代码在 Dog.java 里，就能访问任何 Dog 对象的所有变量，包括私有的；换到别的文件就不行——关键在于文件级私有。

       * 因此 compareTo 里可以直接访问参数 utDog（另一个实例）的私有 size。

       * > **易错点**：⚠️ 无论 compareTo 声明为私有还是公有，同类实例之间访问私有成员的结论都不变。

       * 同一个项目目录里不能放两个叫 Dog 的文件——只要顶部包名相同就不行。

## 编译与运行时的边界

   * **编译（Compile）**

       * > **定义**：编译发生在代码运行之前——过程是检查语法和类型是否自洽，把文本转成字节码（一种更规整、更易于运行时执行的格式），并确保一切合理。

       * 打个比方：给孩子写指示——“有人来问要不要饼干，就照这个做”——把指令写得简单明确、核对好没有错误，让能力不如你的运行时照着执行；编译器干的就是这件事。

   * **接口不依赖实现**

       * 只写接口（如 Explodable，含 explode 方法）与调用它的静态方法（如 ExplosionChecker 遍历列表、对每个元素调用 explode），两段代码完全合法、能编译——尽管此刻还没有任何类实现 Explodable。

       * 这样的代码能编译却跑不了：它没有实际功能，得先有人把功能实现出来。

   * **删掉 compareTo 后谁编译报错**

       * 场景：Dog 声明 `implements Comparable<Dog>`，DogLauncher 建好一列表狗并调用 `Collections.max(dogs)`——Collections 是 Josh Bloch 写的类，里面的 max 会调用元素上的 compareTo；此时删掉 Dog.java 里的 compareTo。

       * Dog.java 挂：声明 implements 等于承诺“我能和别的狗比”，却没提供 compareTo 方法，编译器不答应。

       * Collections.java 不挂：这份库代码要编译好、打包、发给用户并正常运行，它的编译状态不该取决于用户以后写了什么类——写 Collections 时你的 Dog 类可能压根不存在。

       * DogLauncher.java 不挂：它自己的代码完全合法。

       * > **易错点**：⚠️ 编译发生在运行之前——库代码早在你的类存在之前就已编译打包，它的编译不依赖你的实现；缺 compareTo 的崩溃要到运行时才会暴露，“运行时会因缺 compareTo 崩掉”不等于“编译会挂”。

       * 变体：Dog 不声明 implements Comparable 但保留 compareTo 方法——Java 允许这么写，拥有一个 compareTo 方法并不强制要求声明 Comparable，方法就是个普通方法；这回挂的是 DogLauncher——它把不可比的对象传给了要求可比对象的 max；错误在 DogLauncher，修一下它，或者让 Dog 把承诺补上。

## Comparator 接口

   * **自然顺序（Natural Order）**

       * > **定义**：compareTo 方法隐含的排序——Dog 的自然顺序是体型：Pollusa（5）最小、Greg（200）居中、Clifford（9000）最大；别的类可以是别的标准。

       * 想按别的标准排就超出了自然顺序，比如按名字字母序：Clifford 最小、Greg 居中、Pollusa 最大。

   * **Comparator**

       * > **定义**：包含一个 compare 方法、同时接收两个对象进行比较的接口——像一位外部观察者、一个裁判，判断这两个对象哪个更大。

       * 存在理由：Comparable 里那个方法的“名额”已被体型（自然顺序）占用；Java 不把不同的函数当参数传给 Collections.max，而是再次使用子类型多态，为“另一种顺序”另开一个接口。

       * 符号约定与 compareTo 完全一致：比较 “frank” 和 “zika”，frank 在字母序上小于 zika，compare 返回负数。

       * 现代写法：用箭头符号在调用处内联声明一个小函数（lambda），效果一样；业界现在更常用 lambda 定义比较器。

   * **NameComparator 实现要点**

       * 写法：`static class NameComparator implements Comparator<Dog>`（接口要导入），实现 `compare(Dog o1, Dog o2)`，方法体 `return o1.name.compareTo(o2.name);`——String 自带 compareTo（字符串也是 Comparable 的），直接调它。

       * > **易错点**：⚠️ 第一反应“拿名字长度相减”（o1 名字长度减 o2 名字长度）是按名字长度排，不是字母序——想要哪种序取决于比较器怎么写：真按名字长度排，最大的是 Clifford。

       * 嵌套类必须是 static：用名字比较器时不该想着某一只特定的狗；非静态嵌套类在实例化前你得先有一个外层实例——等于要先 new 一只狗才能拿到名字比较器，毫无道理；静态类关联的是 Dog 类本身。

       * 判断要不要 static 的同一问法：Node 类有没有用到列表实例的变量（比如哨兵节点）？没有，所以 Node 应该是静态的。

       * 在 61B 里什么时候必须加 static 通常很明显，编译器会报错提醒，加上关键字就行。

       * 省去每次 new 的优化：在 Dog 类里定义一个全大写的静态变量 NAME_COMPARATOR，类加载时就会自动创建好这个名字比较器，用时直接 `Dog.NAME_COMPARATOR`；两种用法都行，觉得实例化别扭就提前备好。

## Comparable 与 Comparator 的分工

   * **Comparable 的定位**

       * 说明类有自然顺序——类的实例可以和同类的其他实例进行比较，比较规则写在类自己的 compareTo 里。

   * **Comparator 的定位**

       * 外部实现，像请来的裁判——好比找个裁判来比两只狗，可以定义名字、速度等等多种规则。

   * **怎么选**

       * 灵活性是两者并存的理由：只需要一种比较方式，用 Comparable；想要多个可选的排序标准，用 Comparator 更好。

       * 一句话记住：想用内置的顺序，就用 Comparable；想用其他外部顺序，就用 Comparator。

| 维度 | Comparable | Comparator |
| :--- | :--- | :--- |
| 规则写在哪 | 类自己实现，比较规则在类内部 | 外部实现，像请来的裁判 |
| 方法 | compareTo，与另一个同类对象比 | compare，同时接收两个对象 |
| 能定几种顺序 | 自然顺序，一种 | 名字、速度等，多种 |

## 考试范围与备考

   * **期中考边界**

       * 子类型多态与比较器这部分内容不在期中考试范围内，但课后这部分仍要掌握。

       * 渐进分析（大 O、大 Θ 这些记号）期中同样不考，但讨论作业纸上已经出现，先熟悉一下。

   * **考试形式**

       * 只考写代码，没有“这段代码在干嘛”之类的阅读题；考试专注编程，因为作业全是编程。

       * 不考根本性的新内容，也不搞巧妙技巧——看是否真正理解了所有内容、能否把它们很好地组合起来；未必总能想到绝妙的点子，没关系。

       * 备考路径：务必完成前两个项目并消化讨论作业纸（出题参考了这些），再做往年真题、重点练代码题。

   * **练习方法**

       * 团队的力量大于个人：每天挑一两道讨论作业纸上的题目练一练、不偷看答案；卡住了花 10 分钟琢磨很正常，每天回头看看卡壳的题目，找同学聊聊解法或思路。

       * 元认知（Metacognition）就是反思自己的思考过程，对高质量学习至关重要；只有彻底卡住时才去看答案——从答案本身学不到什么，真正的深度理解来自元认知。
