# 引用递归与整数列表

## 内存模型与类型系统

### 基本数据类型

* **基本数据类型（Primitive Types）**
    * > **定义**：Java 虚拟机内部直接通过固定位宽比特序列存储数值的预定义类型。
    * 位宽规格：整数类为 `byte`（8 位）、`short`（16 位）、`int`（32 位）、`long`（64 位）；浮点类为 `float`（32 位）、`double`（64 位）；逻辑与字符类为 `char`（16 位）、`boolean`（底层通常按字长存储）。
    * 存储机制：变量声明时在栈内存中开辟指定位宽的物理空间，变量名与该物理存储空间建立直接映射绑定。
    * > **注意**：基本数据类型的存储单元内部直接容纳数值的二进制位，不存在任何指针间接跳转。

### 引用类型

* **引用类型（Reference Types）**
    * > **定义**：除八种基本数据类型外，仅用于存储堆内存中对象物理起始地址的复合数据类型容器。
    * 存储位宽：所有引用类型变量在栈内存中分配的指针容器固定占用 64 位。
    * 对象实例化机理：`new` 关键字在堆内存中按对象全部字段开辟连续存储空间并初始化，随后返回堆对象的起始内存地址。
    * 空引用机制：引用变量未绑定任何堆对象时填入全 0 比特，在语言层面表现为 `null`。
    * 内存映射结构：
    ```text
    栈内存 (Stack)                           堆内存 (Heap)
    +--------------+ 64-bit 地址 (0x7234)    +-----------------------------+
    | 引用变量 a   | ----------------------> | 堆实例对象 (96+ bits)       |
    +--------------+                         | - 实例变量数据...           |
    ```
    * > **易错点**：引用变量本身的存储位宽与其实例内部包含的字段数量无关，即使对象占用数千位空间，引用变量本身固定占用 64 位。

### 等号黄金法则

* **等号黄金法则（The Golden Rule of Equals）**
    * > **定义**：赋值运算符 `=` 仅执行将右侧变量内存盒中的全部比特位原样复制并覆盖写入左侧变量内存盒的位复制操作。
    * 基本类型表现：直接复制数值比特，赋值完成后两个变量拥有完全独立的物理存储单元，修改互不干涉。
    * 引用类型表现：直接复制 64 位地址比特，使得两个独立引用变量存储相同地址，共同指向堆中同一个对象实体。
    * 间接寻址修改：通过引用变量调用点号运算符（`.`）修改堆对象内部属性，所有持有该对象地址的引用变量均会同步观察到该改变。
    * > **注意**：执行赋值操作时底层绝不创建任何隐式联动通道，本质仅仅是执行一次 64 位比特的位拷贝。

## 参数传递与对象生命周期

### 值传递机制

* **按值传递（Pass-by-Value）**
    * > **定义**：方法调用时将实参变量盒内的全部比特位完整复制并赋值给形参局部变量的调用约定。
    * 栈帧分配过程：调用方法时，虚拟机为形参开辟独立的栈帧局部空间，静默执行等号赋值操作。
    * 基本类型传参表现：形参获得实参数值位拷贝，形参值的改变对调用方实参完全隔离。
    * 引用类型传参表现：形参获得实参的 64 位地址位拷贝，形参与实参指向同一堆对象。
    * 重赋值隔离性：在方法内部对引用形参执行赋值操作（如 `param = null`），仅覆盖形参本地存储的地址位，外部实参的指向维持不变。
    * > **易错点**：修改形参指向对象的内部属性属于通过地址修改堆内存数据；为形参赋新地址仅修改当前局部栈帧，二者底层内存操作截然不同。

### 数组引用与垃圾回收

* **对象迷失与垃圾回收（Garbage Collection, GC）**
    * > **定义**：运行时自动检索并释放已失去所有引用访问路径的堆内存不可达对象的机制。
    * 数组引用本质：Java 中所有数组均属引用类型，数组变量仅在栈上持有指向堆内存连续数组实体的 64 位指针。
    * 孤儿对象判定：当唯一记录某堆对象地址的引用变量被赋予新地址或设为 `null` 时，该堆对象即刻脱离引用链，成为不可达的孤儿对象。
    * 引用断开图解：
    ```text
    +--------+             +-----------------------------+
    | a:null |   (断开)    | int[5] 孤儿对象（无法再被访问）|
    +--------+             +-----------------------------+
    ```
    * > **提示**：失去引用的对象不会立刻被销毁，而是等待后台垃圾回收线程在适当时机统一释放硬件资源。

## 递归整数列表设计与操作

### 递归列表结构与反向构建

* **递归列表结构（Recursive IntList）**
    * > **定义**：由整型数据域和自引用链接域组成的链式递归存储单元。
    * 结构定义规范：
    ```java
    public class IntList {
        public int first;
        public IntList rest;

        public IntList(int f, IntList r) {
            this.first = f;
            this.rest = r;
        }
    }
    ```
    * 递归链接机理：每个节点保存当前整数值（`first`）及指向后继子列表的 64 位地址引用（`rest`），终端节点的 `rest` 存入 `null`。
    * > **注意**：自引用结构并未在自身内部物理嵌套自身，而是通过 64 位地址指针间接链接堆中的同类对象。

* **反向构建模式（Backward Construction）**
    * > **定义**：从链表末端向前逆序分配节点并将新节点挂载为头节点的列表装配技术。
    * 执行顺序约束：Java 严格遵循先计算等号右侧表达式的规则，新节点构造函数在执行时优先捕获旧指针 `L`，随后等号赋值将新节点地址覆写至 `L`。
    * 内存推进步骤：
    ```text
    步骤一：L = new IntList(15, null);
    +--------+      +---------------+
    | L: •   | ---> | 15 |  null    |
    +--------+      +---------------+

    步骤二：L = new IntList(10, L);
    +--------+      +---------------+      +---------------+
    | L: •   | ---> | 10 |    •     | ---> | 15 |  null    |
    +--------+      +---------------+      +---------------+
    ```
    * > **提示**：反向构建避免了正向手动拼接时多重深度寻址的代码冗长问题，确保构造过程中引用链始终不会断裂。

### 列表大小计算算法

* **递归计算列表大小（Recursive Size）**
    * > **定义**：将全局链表长度递归分解为头节点单位长度与后继子链表长度之和的求解策略。
    * 基准条件（Base Case）：`this.rest == null`，表明当前节点为末尾节点，直接返回 1。
    * 递归步进（Recursive Step）：存在后继节点时，返回 `1 + this.rest.size()`。
    * 算法实现：
    ```java
    public int size() {
        if (this.rest == null) {
            return 1;
        }
        return 1 + this.rest.size();
    }
    ```
    * > **定义**：信任递归（Leap of Faith）：只要基准条件成立且每次递归都向基准条件缩小规模，即可直接信任子调用的正确性，无需展开推演调用栈。
    * > **易错点**：若链表末端未正确终止于 `null` 导致形成环状结构，递归调用将引发栈溢出异常（StackOverflowError）。

* **迭代计算列表大小（Iterative Size）**
    * > **定义**：利用游标指针从头至尾沿引用链顺序遍历节点并累加计数的过程式求解算法。
    * 算法实现：
    ```java
    public int iterativeSize() {
        IntList p = this;
        int totalSize = 0;
        while (p != null) {
            totalSize++;
            p = p.rest;
        }
        return totalSize;
    }
    ```
    * 指针推进机理：执行 `p = p.rest;` 不断用后继节点地址覆盖游标指针，直至 `p` 取得 `null` 终止循环。
    * 空间复杂度优势：迭代方式复用固定大小的指针空间，相比递归避免了方法调用栈帧空间的累积开销。

### 递归索引查找算法

* **递归索引查找（Recursive Get）**
    * > **定义**：利用递归逐层递减偏移量实现的零基索引定位算法。
    * 基准条件：`i == 0`，当前节点即为目标，直接返回 `this.first`。
    * 递归步进：向后继节点委派任务，返回 `this.rest.get(i - 1)`。
    * 算法实现：
    ```java
    public int get(int i) {
        if (i == 0) {
            return this.first;
        }
        return this.rest.get(i - 1);
    }
    ```
    * 逻辑推导关系：查找当前节点身后第 $i$ 项，等价于查找后继节点身后第 $i - 1$ 项。
    * > **易错点**：当传入负数索引或超出链表实际长度的索引时，递归在越过末尾节点后会因对 `null` 调用方法而触发空指针异常（NullPointerException）。
