# 图的表示与遍历算法实现

## 图接口规范与职责解耦设计

### 顶点整数抽象与客户端映射

* **顶点整数抽象（Vertex Integer Abstraction）**
    * > **定义**：将图内部节点严格限定为连续非负整数索引 $0$ 至 $V-1$ 的结构约束。
    * 图核心数据结构内部不直接持有泛型对象或业务字符串标识。
    * 业务对象与整数顶点的绑定关系交由外部符号表或数组解耦维护。
    * 顶点编号直接充当数组寻址的物理下标，实现常数级定位开销。
    * > **提示**：业务层通过 `String[] names` 或 `Map<String, Integer>` 转换标识，图内部操作固定为连续整数索引。

```text
[ 业务对象与图顶点的解耦映射 ]

  城市名称 (业务层)         整数索引 (图核心层)          图拓扑关系 (边)
 ┌───────────────┐        ┌─────────────────┐        ┌─────────────┐
 │ 0: "Austin"   │ ──映射──> │  顶点 0         │ ───边───> │  顶点 1     │
 │ 1: "Dallas"   │        │  顶点 1         │          └─────────────┘
 │ 2: "Houston"  │        │  顶点 2         │
 └───────────────┘        └─────────────────┘
```

### 极简图应用程序编程接口

* **极简图接口（Minimalist Graph API）**
    * > **定义**：遵循功能减法设计、仅保留最基本拓扑连接能力的无权图抽象契约。
    * 构造函数 `Graph(int V)` 预分配固定容量，运行期不支持动态扩缩容。
    * 仅开放添加边与邻接迭代等核心基础操作，不支持加权边存储。
    * 查询度数 `degree(v)`、边打印等功能由客户端通过遍历 `adj(v)` 自行组合实现。
    * > **易错点**：无向图调用 `addEdge(v, w)` 时，必须在 `v` 和 `w` 两个顶点的邻接结构中双向记录该边。

```java
public class Graph {
    public Graph(int V);                // 创建包含 V 个顶点、0 条边的图
    public void addEdge(int v, int w);   // 在顶点 v 和 w 之间添加无向边
    public Iterable<Integer> adj(int v); // 返回顶点 v 的相邻顶点集合
    public int V();                      // 返回顶点总数
    public int E();                      // 返回边总数
}
```

```java
public static int degree(Graph G, int v) {
    int degree = 0;
    for (int w : G.adj(v)) {
        degree++;
    }
    return degree;
}
```

### 算法解耦与智者模式

* **智者模式（Wise Man Pattern）**
    * > **定义**：将图的拓扑结构存储与图的检索遍历算法在类定义上完全剥离的面向对象设计模式。
    * 图类仅负责邻接拓扑关系的存储，算法逻辑封装于独立的查询服务类中。
    * 算法类在构造时接收图引用并执行搜索，将遍历结果保存在 `marked[]` 与 `edgeTo[]` 数组中。
    * 客户端向算法对象发起状态查询时，查询过程在 $O(1)$ 时间内直接返回预计算结果。
    * > **注意**：算法对象与图对象交互的唯一通道是调用 `G.adj(v)` 方法。

```text
[ 智者模式 (Paths) 与图结构 (Graph) 的解耦交互 ]

   客户端代码                        智者对象 (Paths)                      图数据结构 (Graph)
  ┌──────────┐                     ┌────────────────┐                  ┌────────────────┐
  │ 调用构造  │ ── new Paths(G, s) ─> │ 构造执行:      │ ── G.adj(v) ────> │ 提供邻接顶点列表 │
  │          │                     │ 执行一次 DFS    │ <── Iterable ─── │                │
  │          │                     │ 填好 marked[]  │                  └────────────────┘
  │          │                     │ 填好 edgeTo[]  │
  │          │                     └────────────────┘
  │ 提问路径  │ ── hasPathTo(v) ───> │ 查 marked[v]   │ 
  │          │ <── 返回 true/false ─ │                │
  │ 获取路径  │ ── pathTo(v) ──────> │ 倒推 edgeTo[]  │
  │          │ <── 返回路径迭代器 ── │ (顺着前驱回溯) │
  └──────────┘                     └────────────────┘
```

## 底层存储结构与双变量复杂度分析

### 邻接矩阵与邻接表存储模型

* **邻接矩阵（Adjacency Matrix）**
    * > **定义**：使用大小为 $V \times V$ 的二维布尔数组记录顶点间连接关系的矩阵表示法。
    * 无向图的邻接矩阵沿主对角线完全对称。
    * 任意两点连通性判定只需一次数组寻址，耗时恒定。
    * 稀疏图场景下存在大量零值冗余，造成内存浪费。
    * > **易错点**：遍历某顶点的所有出边时，邻接矩阵必须完整扫描整行共 $V$ 个元素，无法跳过不存在的边。

* **邻接表（Adjacency Lists）**
    * > **定义**：为每个顶点维护独立列表以顺序记录其实际相邻顶点的存储结构。
    * 内存空间严格受限于有效拓扑边数，避免全零空间的过度分配。
    * 顶点的度数决定了其独立列表的长度，无出边的孤立顶点对应空列表。
    * 遍历顶点的相邻邻居仅需顺序扫描实际存在的边节点。
    * > **提示**：邻接表通常采用泛型列表数组 `List<Integer>[]` 或链表背包数组 `Bag<Integer>[]` 实现。

```text
[ 邻接矩阵与邻接表存储形态对比 (有向图) ]

   有向拓扑图                邻接矩阵二维数组                  邻接表顶点列表数组
     (0) ───> (1)              0   1   2                  索引     邻居列表
      │        │           0 ┌───┬───┬───┐               ┌─────┐  ┌─────────┐
      │        │             │ 0 │ 1 │ 1 │               │ [0] │─>│ 1 ──> 2 │
      ▼        ▼           1 ├───┼───┼───┤               ├─────┤  ├─────────┤
     (2) <─────┘             │ 0 │ 0 │ 1 │               │ [1] │─>│ 2       │
                           2 ├───┼───┼───┤               ├─────┤  ├─────────┤
                             │ 0 │ 0 │ 0 │               │ [2] │─>│ (空)    │
                             └───┴───┴───┘               └─────┘  └─────────┘
```

### 结构性能开销对比

| 算法 / 操作 | 邻接表实现 | 邻接矩阵实现 | 矩阵性能退化根因 |
| :--- | :--- | :--- | :--- |
| **空间开销** | $\Theta(V + E)$ | $\Theta(V^2)$ | 必须开辟完整的 $V \times V$ 二维矩阵空间。 |
| **添加边 `addEdge`** | $\Theta(1)$ | $\Theta(1)$ | 数组寻址赋值与链表头插法耗时恒定。 |
| **查询两点是否相邻** | $O(\text{degree}(v))$ | $\Theta(1)$ | 邻接表需遍历列表，矩阵支持直接寻址。 |
| **遍历全图所有边 `print`** | $\Theta(V + E)$ | $\Theta(V^2)$ | 邻接矩阵必须遍历整个网格中的无效单元格。 |
| **深度优先搜索 (DFS)** | $O(V + E)$ | $\Theta(V^2)$ | 寻找单节点相邻点需顺序扫描对应整行。 |
| **广度优先搜索 (BFS)** | $O(V + E)$ | $\Theta(V^2)$ | 队列各节点扩展时均需对矩阵行执行全扫描。 |

### 双变量渐进时间复杂度推导

* **双变量复杂度模型（Dual-Variable Complexity Model）**
    * > **定义**：利用顶点规模 $V$ 与边密度 $E$ 两个正交独立自由度共同描述图算法资源消耗的渐进分析方法。
    * 边数 $E$ 的取值区间为 $0 \le E \le V(V-1)/2$，稀疏与稠密状态下的规模演变具有独立性。
    * 外层循环遍历全体顶点贡献 $\Theta(V)$ 基础扫描开销。
    * 内层所有邻接列表遍历的累加步数在全图范围内精确等于总出边数 $\Theta(E)$。
    * 全图遍历与搜索的执行时间与两部分开销之和 $\Theta(V + E)$ 严格线性相关。
    * > **易错点**：全图遍历的时间复杂度为 $\Theta(V + E)$ 而非 $\Theta(V \times E)$，内层迭代总量分摊至各顶点后累加总和为 $E$。

```text
[ 图增长的双重维度与复杂度主导区间 ]

    边数 E (连接密度)
      ▲
      │                              稠密极端: E ≈ V²
      │                             (E 占主导，复杂度收敛为 O(V²))
      │                                   ▲
      │                                  ╱
      │                                 ╱
      │       典型稀疏图: E 与 V 处于同一线性量级
      │       (两者共同作用，表现为 O(V + E))
      │          ▲
      │         ╱
      │        ╱
      │  稀疏极端: E 极小甚至为 0
      │  (V 占主导，复杂度收敛为 O(V))
      └────────────────────────────────────────> 顶点数 V (节点规模)
```

## 广度优先搜索与队列不变量

### 先进先出队列推进机制

* **广度优先搜索（Breadth-First Search，BFS）**
    * > **定义**：从起点开始按照图拓扑跳数由近及远逐层辐射访问所有可达顶点的图遍历算法。
    * 算法运行依赖先进先出队列保证顶点访问顺序的层次单调性。
    * 顶点在初次加入队列时即被标记，杜绝节点被重复推入队列。
    * 访问邻居节点时通过前驱指针数组记录生成树的父子对应关系。
    * > **易错点**：标记顶点的操作必须在入队时同步执行，若延迟至出队时标记会导致重复入队并引发性能退化。

```text
[ 广度优先搜索的队列处理机制 ]

      取出当前近距离节点 (队头)                       新发现的较远邻居进入队尾排队
     ┌──────────────────────┐                     ┌────────────────────────┐
<─── │ 出队处理: 标记并记录路径 │                     │ 入队: 距离更远的邻居节点 │ <───
     └──────────────────────┘                     └────────────────────────┘
          ▲                                                    ▲
          │       ┌───────┬───────┬─────────┬─────────┐        │
          └────── │ 队头  │  ...  │   ...   │  队尾   │ ───────┘
                  └───────┴───────┴─────────┴─────────┘
                  距离 = k                 距离 = k + 1
```

### 队列单调距离不变量

* **队列距离单调不变量（Queue Distance Monotonic Invariant）**
    * > **定义**：在广度优先搜索执行期间，队列内部元素的源点距离值保持单调非递减且最大极差不超过 1 的状态约束。
    * 队列内元素的最短距离取值在任意时刻仅包含 $k$ 或同时包含连续的 $k$ 与 $k+1$ 两类。
    * 队头弹出的元素必然处于当前队列的最短距离层 $k$。
    * 距离为 $k$ 的顶点所展开的新未访问邻居距离必定精确等于 $k+1$。
    * 距离为 $k+2$ 的节点唯有在队列中全体距离为 $k$ 的顶点全部出队后方可首次入队。
    * > **提示**：队列不变量在数学上保证了无权图中首次访问节点时所经路径必为最少边数的最短路径。

```text
[ 队列距离不变量的状态转移演进 ]

状态 A: 队列中全是同一距离的节点
       队头 ──> [ k,  k,  k,  k ] <── 队尾

状态 B: 队头处理 k，新入队的邻居距离必定为 (k+1)
       队头 ──> [ k,  k,  k | k+1,  k+1 ] <── 队尾
                └─ 正在处理 ─┘  └── 新入队 ──┘

状态 C: 所有距离为 k 的节点全部出队完毕，队列全变为 (k+1)
       队头 ──> [ k+1,  k+1,  k+1 ] <── 队尾

状态 D: 队头首次处理 (k+1)，新入队的邻居距离首次出现 (k+2)
       队头 ──> [ k+1,  k+1 | k+2 ] <── 队尾
```

### 最短路径重构实现

* **面包屑反向回溯（Breadth-First Path Reconstruction）**
    * > **定义**：基于记录直接前驱节点的整数数组自目标顶点反向追溯至起点的拓扑重构过程。
    * 数组 `edgeTo[w] = v` 记录了广度优先生成树中到达顶点 $w$ 的最短路径最后一步。
    * 回溯过程通过指针更新 `x = edgeTo[x]` 顺序收集路径节点。
    * 收集完成后必须翻转序列以保证起点至终点的正向输出。
    * > **注意**：若目标顶点在 `marked` 数组中未被标记，说明两点间不可达，回溯过程应当直接中止。

```java
public class BreadthFirstPaths {
    private boolean[] marked;
    private int[] edgeTo;
    private final int s;

    public BreadthFirstPaths(Graph G, int s) {
        this.s = s;
        marked = new boolean[G.V()];
        edgeTo = new int[G.V()];
        bfs(G, s);
    }

    private void bfs(Graph G, int s) {
        Queue<Integer> q = new LinkedList<>();
        marked[s] = true;
        q.add(s);

        while (!q.isEmpty()) {
            int v = q.remove();
            for (int w : G.adj(v)) {
                if (!marked[w]) {
                    edgeTo[w] = v;
                    marked[w] = true;
                    q.add(w);
                }
            }
        }
    }

    public boolean hasPathTo(int v) {
        return marked[v];
    }

    public Iterable<Integer> pathTo(int v) {
        if (!hasPathTo(v)) return null;
        List<Integer> path = new ArrayList<>();
        for (int x = v; x != s; x = edgeTo[x]) {
            path.add(x);
        }
        path.add(s);
        Collections.reverse(path);
        return path;
    }
}
```

## 图遍历典型问题解析

### 接口受限图打印实现

* **受限接口边枚举（Constrained Graph Print）**
    * > **定义**：仅利用极简顶点遍历与邻接查询接口重构全图所有连接对的客户端算法。
    * 循环遍历连续整数区间 $[0, V-1]$ 枚举源顶点。
    * 调用 `adj(v)` 获取对应顶点的出边集合。
    * 格式化输出每一对顶点拓扑关系 $v-w$。
    * > **注意**：无向图调用该算法会导致每条边正反两个方向各被打印一次，符合邻接表出边全量遍历语义。

```java
public static void print(Graph G) {
    for (int v = 0; v < G.V(); v++) {
        for (int w : G.adj(v)) {
            System.out.println(v + "-" + w);
        }
    }
}
```

### 邻接表遍历双变量复杂度判定

* **邻接表遍历复杂度评估（Adjacency Lists Traversal Analysis）**
    * > **定义**：基于顶点数组和邻接链表存储特性的双循环累加开销分析。
    * 外层数组循环的迭代次数严格固定为 $V$ 次。
    * 全图所有顶点的入度与出度总和在无向图为 $2E$，在有向图为 $E$。
    * 内层语句的总触发频次与边数 $E$ 呈绝对线性关系。
    * 整体算法渐进时间复杂度收敛于 $\Theta(V + E)$。
    * > **易错点**：不可将时间复杂度泛化为 $\Theta(V^2)$ 或 $\Theta(V \times E)$，稀疏图下 $E \ll V^2$ 且内层遍历总和不随顶点乘积膨胀。
