# 字典树与前缀树

## 拓扑结构与节点设计

### 字符特化与结构演进

* **数据索引字符映射（Data-Indexed Char Map）**
    * > **定义**：以字符在字母表中的偏移量作为数组下标直接寻址的定长映射结构。
    * 键状态标记与查询操作的耗时均为绝对常数时间 $\Theta(1)$。
    * 空间占用完全取决于字符集基数 $R$，与存入元素的实际数量无关。
    * 仅能处理离散的单一字符，无法直接扩展支持任意长度的字符串序列。
* **字典树（Trie / Prefix Tree）**
    * > **定义**：按字符序列沿树深逐层展开、通过路径复用共享公共前缀的检索树。
    * 术语取自检索英文 Retrieval，学术界与工业界通用发音为 `/traɪ/`。
    * 具备相同前缀的字符串在树内部共享完全重合的祖先拓扑路径。
    * 根节点不承载具体字符，仅作为所有字符分支延伸的逻辑入口。
    * 拓扑结构呈现共享前缀的树形展开：
        ```text
                         (root)
                        /      \
                     [s]        [a]
                      |          |
                     [a]        [w]
                   /  |  \       |
                 [d] [m] [p]    [l]
                      |          |
                     [e]        [s]
        ```

### 节点语义与存储精简

* **节点着色标记（Node Coloring / isKey）**
    * > **定义**：在节点内部维护布尔变量以区分前缀过渡路径与完整独立有效键的状态机制。
    * 终止节点（`isKey == true`）标识从根节点下潜至此处的字符序列构成有效键。
    * 过渡节点（`isKey == false`）仅作为更长字符串的前缀骨架，不代表独立存储键。
    * 在映射（Map）实现中，布尔标记可直接替换为关联的值对象引用。
    * > **易错点**：字符串在树中路径连通并不等于该词存在于集合中，判定存在必须核验终止节点的布尔标记。
* **隐式边字符编码（Implicit Edge Character Encoding）**
    * > **定义**：将字符信息完全交由父节点的链接数组索引表达，节点实体本身不存储字符的设计。
    * 节点类内部完全剔除 `char` 实例变量，消除内存冗余。
    * 访问目标子节点的入口唯一对应父节点链接槽位，转移路径已严格锁定字符语义。
    * 节点实体仅需持有终止状态标记及指向后继子节点的映射容器。

### 检索判定状态

* **命中状态（Hit）**
    * > **定义**：待检索序列中的每个字符均成功完成树中跳转且终点节点终止标记为真的状态。
    * 确证目标字符串存在于集合中。
* **中途脱落状态（Fell off the tree）**
    * > **定义**：沿待检索序列下潜遍历时遭遇子节点空引用指针（`null`）的中断状态。
    * 确证集合中不存在任何以此序列为前缀的更长有效键。
* **止于非键节点状态（Ended on white node）**
    * > **定义**：待检索序列完整走通链路但终点节点的终止标记为假的状态。
    * 确证该序列仅为集合中其他有效键的真前缀，其自身并未存入集合。

## 复杂度分析与子节点存储架构

### 时间复杂度分析

* **常数时间检索特性（Key-Count Independent Search）**
    * > **定义**：在以存入键的总数 $N$ 为自变量度量时，检索与插入操作耗时完全独立于 $N$ 的特性。
    * 字典树的插入与查找操作时间复杂度在关于 $N$ 的渐进分析下为严格常数时间 $\Theta(1)$。
    * 指针在树中下潜的最大跳转步数由被检索键自身的字符长度 $L$ 严格锁定。
    * 当引入键长度 $L$ 作为自变量度量时，单次操作的精确时间复杂度为 $\Theta(L)$。
    * > **易错点**：误将平衡树的对数特性 $\Theta(\log N)$ 套用至字典树。字典树单步跳转沿固定边推进，数据集总规模 $N$ 膨胀不会改变特定键的下潜深度。

### 抽象映射层设计

* **子节点映射抽象层（Child Links Abstraction Level）**
    * > **定义**：将节点内部的下行引用抽象为字符至后继节点的键值映射 `Map<Character, Node>`。
    * 解耦高层路径遍历逻辑与底层指针容器的物理排布方式。
    * 允许在空间预算与字符集基数之间灵活切换底层具体实现。

### 存储机制工程权衡

* **定长数据索引数组（Data-Indexed Array）**
    * > **定义**：节点内部为所有潜在字符预分配基数为 $R$ 的固定长度引用指针数组。
    * 寻址速度极快，依赖纯粹的基址加偏移量直接跳转。
    * 最坏情况单步耗时为绝对常数 $\Theta(1)$。
    * 内存浪费严重，稀疏文本树中叶子节点与低分支节点充斥大量空引用占位。
    * 适用于字符集基数 $R$ 较小且分支高度稠密的高并发吞吐场景。
* **哈希表映射（HashTable / HashMap）**
    * > **定义**：节点内部采用哈希容器按需动态管理实际存在的子节点分支。
    * 仅为真实存在的下行分支分配条目，空间利用率极高。
    * 单步寻址平均耗时为常数时间 $\Theta(1)$，最坏情况退化为 $\Theta(R)$。
    * 适用于字符集较大且分支分布稀疏的标准文本词库。
* **平衡二叉搜索树（Balanced BST）**
    * > **定义**：节点内部使用红黑树等平衡二叉树组织后继子节点引用的实现模式。
    * 空间利用紧凑，无冗余空引用，且规避了哈希冲突退化风险。
    * 单步寻址耗时严格受限于对数时间 $O(\log R)$。
    * 预设字符集大小 $R$ 为系统常数，因此在渐进分析意义上 $O(\log R)$ 仍属于常数上界。
    * 适用于内存预算严苛且对延迟抖动高度敏感的系统。

## 前缀特化操作与工业演进

### 前缀检索算法

* **前缀查找（Keys with Prefix）**
    * > **定义**：在数据集中提取出所有以指定序列开头的所有有效键的检索操作。
    * 算法执行分为两阶段：定位前缀末尾对应节点，再对以该节点为根的整棵子树实施全量收集。
    * 哈希表因散列计算彻底破坏了前缀聚集性，执行此操作必须遍历全表，退化为 $\Theta(N)$ 扫描。
    * 字典树将包含相同前缀的键天然聚拢在同一子树内，检索范围严格局限在局部子树。
* **最长前缀匹配（Longest Prefix Match）**
    * > **定义**：在词库中找出能够成为目标输入序列最长前缀的有效键的算法。
    * 从根节点向下一路单向步进，遍历途中每当途经终止标记为真的节点即刷新最优匹配记录。
    * 遭遇空指针脱落或输入序列耗尽时立即终止探测，直接返回记录的最大长度匹配。
    * 相较哈希表频繁切割子串逐次探测的高额开销，字典树仅需一次单向线性下潜。

### 工业级搜索增强

* **自动补全（Autocomplete）**
    * > **定义**：根据用户已输入的击键前缀，即时展现补全候选项的高频交互系统。
    * 依赖字典树的前缀定位机制作为底层核心索引。
* **节点高频词缓存（Top-K Suggestions Cache）**
    * > **定义**：在字典树节点内部预先计算并缓存以该节点为前缀的前 $K$ 个高频推荐词的优化策略。
    * 规避海量并发请求下对深层子树进行全量递归回溯收集造成的延迟恶化。
    * 依托空间换时间，将在线自动补全请求的耗时彻底压制在常数时间响应级。

## 核心实现模型与思维陷阱

### 递归收集与回溯模型

* **子树元素收集机制（Subtree Collection Mechanism）**
    * > **定义**：利用深度优先搜索与路径回溯遍历字典树特定子树中所有有效键的控制流程。
    * 递归终止条件：当前访问节点引用为空时立即中断并返回。
    * 有效状态捕获：检查当前节点的终止标记 `isKey`，为真时将路径拼接结果记录至输出集合。
    * 状态回溯机制：向下递归前向路径构建器追加字符，从子调用返回后必须立即剔除末尾追加的字符。
    * 核心逻辑实现结构：
        ```java
        public List<String> keysWithPrefix(String prefix) {
            List<String> results = new ArrayList<>();
            Node x = get(root, prefix, 0);
            if (x == null) {
                return results;
            }
            collect(x, new StringBuilder(prefix), results);
            return results;
        }

        private void collect(Node x, StringBuilder prefix, List<String> results) {
            if (x == null) {
                return;
            }
            if (x.isKey) {
                results.add(prefix.toString());
            }
            for (char c = 0; c < R; c++) {
                Node nextNode = getChild(x, c);
                if (nextNode != null) {
                    prefix.append(c);
                    collect(nextNode, prefix, results);
                    prefix.deleteCharAt(prefix.length() - 1);
                }
            }
        }
        ```
    * > **注意**：回溯过程中必须保证追加与删除操作对称执行，否则会导致后续分支检索的路径污染。

### 典型复杂度陷阱

* **规模变量归因陷阱（Scale Variable Attribution Trap）**
    * > **定义**：混淆数据集规模 $N$ 与单键长度 $L$ 对操作复杂度影响的直觉误区。
    * 命题模型：对于存有 $N$ 个键的字典树，计算执行一次查询或插入操作关于规模 $N$ 的渐进复杂度。
    * 理论结论：时间复杂度为严格常数时间 $\Theta(1)$。
    * 核心机理：检索下潜路径完全取决于被查找键自身的字符分布，跳转步数受限于其自身长度，与树中存有十条还是百亿条数据完全解耦。
    * > **提示**：若以待操作键本身的字符长度 $L$ 为规模自变量，时间复杂度记为 $\Theta(L)$。
