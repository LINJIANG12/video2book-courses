# 网络层数据平面：路由器结构、IP编址与通用转发

## 网络层服务模型与功能平面

### 网络层核心功能与平面划分

* **网络层（Network Layer）**

    * > **定义**：负责将分组（Packet / IP数据报）从源主机跨越多个物理网络与路由器送达目的主机的通信层次。

    * 发送端接收传输层报文段（TCP报文段或UDP数据报）并封装进IP数据报首部；接收端提取数据载荷并向上解封装交付传输层。

    * 网络层在逻辑上严格划分为负责局部报文处理的数据平面与负责全局路径决策的控制平面。

* **转发（Forwarding）**

    * > **定义**：路由器将分组从物理输入端口移送到合适物理输出端口的局部操作。

    * 归属网络层数据平面，处理时间尺度在纳秒到微秒级别，完全由专用硬件流水线以线速完成。

    * 转发依据仅基于分组首部字段与路由器本地转发表或流表中的表项匹配规则。

* **路由（Routing）**

    * > **定义**：网络层规划分组从源主机到目的主机跨越整个网络端到端完整路径的全局协调机制。

    * 归属网络层控制平面，时间尺度在秒级至分钟级，通常由运行在通用计算核心上的软件进程或远程控制器执行复杂算法完成。

    * 路由协议（如 OSPF、BGP）负责交换全网拓扑与可达性信息，协同计算生成各节点的转发表。

* **转发表（Forwarding Table）**

    * > **定义**：连接控制平面与数据平面的核心接口数据结构，记录目标网络与输出端口的映射关系。

    * 控制平面算法计算出拓扑路径后生成转发表并写入硬件芯片；数据平面据此实施高速查表。

    * 传统转发表项至少包含目的网络号、子网掩码、输出接口与下一跳路由器IP四项核心要素。

### 服务模型与连接机制

* **服务模型（Service Model）**

    * > **定义**：网络层对端到端数据传输特性的抽象承诺与质量保证规范。

    * 单个数据报衡量指标包括可靠交付保证（不损坏、不丢失）与有界时延保证（端到端传输时间不超过预设上限）。

    * 数据报流序列衡量指标包括保序交付（严格按发送顺序接收）、最小带宽保证（恒定吞吐率）与分组时延差（抖动，Jitter，连续分组时延波动差）。

* **尽力而为服务模型（Best-Effort Service Model）**

    * > **定义**：网络层不向端系统提供任何确定性服务质量保证的传输模型。

    * 互联网IP协议默认采用该模型：带宽无保障、丢包不承诺、顺序不保证、时延与抖动无边界，且网络不主动向端系统提供显式拥塞反馈。

    * 核心网通过维持极简无状态与丢弃过载分组换取超大规模的弹性与高吞吐。

* **异步传输模式网络服务模型（ATM Network Service Models）**

    * 恒定比特率（CBR）：承诺端到端固定带宽、零丢包、绝对保序，将时延与抖动约束在极低区间，专用于电话专线仿真。

    * 未指定比特率（UBR）：服务质量指标与IP尽力而为类似，但强制提供底层信元的保序交付。

    * 可用比特率（ABR）：网络节点向源端提供显式拥塞反馈，允许源主机根据网络当前承载能力动态压榨空闲带宽。

* **网络层连接与传输层连接**

    * 状态维护位置与中间网络设备参与度存在本质分界：

    | 对比维度 | 传输层连接（如 TCP） | 网络层连接（如 ATM 虚电路） |
    | :--- | :--- | :--- |
    | **维护节点位置** | 仅存在于源主机与目的主机的操作系统内核中 | 贯穿通信路径上的所有网络核心交换节点与路由器 |
    | **核心设备感知度** | 中间路由器完全无状态，仅独立转发每个数据报 | 每个交换节点在内存中维护完整的虚电路表（VC Table） |
    | **服务定性** | 面向连接（Connection-oriented）服务 | 有连接（Connection-based）服务 |
    | **信令开销** | 仅需端到端三次握手，核心网零开销 | 必须经历端到端显式信令建立、虚电路号分配与逐跳拆除 |

## 路由器体系结构与硬件转发

### 路由器四大核心组件

* **路由处理器（Routing Processor）**

    * > **定义**：运行控制平面软件进程并执行设备管理监控的中央计算系统。

    * 运行分布式路由选择协议实体（OSPF、BGP），计算路由拓扑并维护主路由表。

    * 负责将计算生成的转发表通过内部总线分发至各个输入端口的本地转发芯片中。

* **交换机构（Switch Fabric）**

    * > **定义**：负责将分组从物理输入端口高速移送到物理输出端口的内部专用硬件互连网络。

    * 决定路由器整体转发吞吐能力的物理核心，设计目标吞吐量通常要求达到端口线路速率的数十倍至数百倍。

    * 物理实现演进经历基于内存交换、基于总线交换与基于互联网络交换三代架构。

* **输入端口（Input Port）**

    * > **定义**：承接物理入站信号并执行逐包解封装与查表分流的三级硬件流水线。

    * 物理层线路终端执行光电信号转换，将接收到的模拟波形解码还原为数字比特流。

    * 数据链路层处理模块执行物理帧定界、MAC地址校验与CRC循环冗余校验，校验无误后剥离帧头帧尾提取IP数据报。

    * 网络层查找模块借助本地转发表副本与专用TCAM芯片执行目的地址线速检索，仲裁确定分组的目标输出端口并排队。

* **输出端口（Output Port）**

    * > **定义**：从交换机构接收分组并执行排队调度、成帧与信号调制的出站硬件流水线。

    * 内部配备输出排队缓冲区，应对来自多个输入端口瞬间涌向同一物理链路的流量汇聚。

    * 调度器挑选出队分组，交由链路层加上目标MAC地址与CRC校验和封装成帧，经物理层调制后发射至通信介质。

    * > **注意**：路由器物理接口卡（网卡）在硬件构造上收发一体，逻辑上划分输入端口与输出端口仅用于教学与架构时序解耦。

* **头端阻塞（Head-of-Line Blocking，HOL Blocking）**

    * > **定义**：输入队列头部排队分组因目标输出端口冲突而挂起等待，导致队首后方无输出端口冲突的分组同样被迫停滞的排队现象。

    * 触发条件：多个输入端口的队头分组在同一瞬时争抢转发至同一个输出端口，交换机构仲裁仅允许其中一个输入端口通过。

    * 阻塞机理：未被选中的输入端口队列整体停滞，排在队头之后的后继分组即便目标输出端口当前完全闲置，也无法绕开队首抢先移送。

    * 突发多打一流量持续涌入时，输入队列迅速积压耗尽缓冲，引发输入端缓冲区溢出丢包。

### 交换机构实现架构

* **基于内存交换（Memory-based Switching）**

    * > **定义**：利用通用计算平台的主存（RAM）与中央处理器充当分组中转站的第一代交换架构。

    * 运行机理：输入端口接收分组后触发系统中断，通过系统总线将分组拷贝至主内存；CPU检索软件路由表确定出端口，再通过系统总线将数据拷贝至输出端口缓冲区。

    * 性能极限：每个分组必须强制穿越系统总线两次，整机最大交换吞吐量严格受限于计算机系统总线物理带宽的二分之一。

    * > **易错点**：⚠️ 基于内存的交换架构中，分组出入主存需双向占用系统总线，总线利用率减半导致其无法用于构建高速骨干路由设备。

* **基于总线交换（Bus-based Switching）**

    * > **定义**：输入端口与输出端口直接挂载在单条专用共享内部高速总线上的第二代交换架构。

    * 运行机理：输入端口完成查表后为分组打上内部专属路由标签，将分组直接送上共享总线；所有输出端口监听总线并检验标签，仅匹配标签的输出端口取走分组并剥离标签。

    * 分组仅单次穿越内部总线，彻底摆脱系统主存与通用CPU读写的瓶颈限制，典型吞吐达数十 Gbps。

    * 瓶颈边界：内部总线本质属于广播共享介质，任意瞬时全系统仅允许单一输入端口占用总线发送，总线仲裁限制了超大并发扩展。

* **基于互联网络交换（Interconnection Network Switching）**

    * > **定义**：采用二维网格交叉矩阵或多级交换网络实现多路径并行转发的第三代交换架构。

    * 纵横交换机（Crossbar Switch）由 $N$ 条水平输入线与 $N$ 条垂直输出线构成，形成 $N \times N$ 个可开闭的交叉矩阵开关点。

    * 只要多个输入端口的目标输出端口各不相同，对应交叉点开关即可在空间上同时闭合，实现真正的无阻塞多路全并发转发，整机吞吐达到数百 Gbps 至 Tbps。

    * 信元切片技术（Cell Segmentation）：输入端硬件将变长IP数据报切割为短小且完全等长的固定信元（如 64 字节），信元穿过Crossbar网格耗时恒定，便于统一时钟调度，抵达输出端口后再重组还原为IP数据报。

### 输出端口缓冲、丢弃与调度

* **输出端口缓冲（Output Port Queuing）**

    * > **定义**：用于吸收瞬时汇聚突发流量的输出端口排队存储空间。

    * 触发前提：交换机构转发至某一特定输出端口的瞬时聚合速率超过了该物理链路的线速发送带宽。

    * 缓冲区耗尽时，后续到来的分组将因存储溢出被直接抛弃，成为网络拥塞丢包的微观来源。

* **分组丢弃策略（Drop Policy）**

    * 尾部丢弃（Drop-tail）：队列填满后直接丢弃后续到达的新分组，实现简单但极易在多条TCP连接间引发全局同步（Global Synchronization）。

    * 基于优先级的丢弃（Priority-based Drop）：检测分组首部的优先级标识（如 ToS / DiffServ），缓冲告急时优先踢除已入队的低优先级分组，确保关键业务与控制信令留存。

    * 随机早期检测丢弃（Random Early Drop，RED）：在缓冲区耗尽前依据队列平均长度计算概率曲线，随机提前丢弃少量分组，向端系统发出隐式拥塞预警促使其退避降速。

* **分组调度算法（Packet Scheduling Algorithms）**

    * 先到先服务（FCFS / FIFO）：严格依据分组进入输出队列的时间先后出队发送，不感知业务类型，无服务质量区分。

    * 优先级调度（Priority Queuing，PQ）：将分组按优先级分入多个子队列，只要高优先级队列非空，链路绝对压制低优先级队列；低优先级流量在业务高峰期面临饥饿死锁（Starvation）。

    * 循环轮转调度（Round-Robin，RR）：维护多个类别队列，调度器按固定顺序循环轮流从各队列中依次提取一个分组发送，防止单一队列持续霸占物理链路。

    * 加权公平排队（Weighted Fair Queuing，WFQ）：

        * > **定义**：循环轮转调度的广义加权泛化，为每个类别队列 $i$ 预设固定服务权重 $w_i$（满足 $\sum w_i = 100\%$）。

        * 运行机理：当所有类别队列持续有数据积压时，各队列实际获得的物理链路带宽严格正比于其权重比例：

        $$
        \text{Bandwidth}_i = \text{Link Capacity} \times \frac{w_i}{\sum w}
        $$

        * 边界优势：既杜绝了绝对优先级调度造成的低等级队列饥饿，又为不同业务类别提供了有确定性底线保障的差别化带宽划分。

## 网际协议 IPv4 与分片重组

### IPv4 首部格式与字段语义

* **IPv4 数据报（IPv4 Datagram）**

    * > **定义**：网际协议版本4定义的基本协议数据单元（PDU），由固定首部、可选选项及数据载荷构成。

    * 首部按 32 位（4 字节）为一行进行编排组织，无选项时的固定首部长度恒定为 20 字节。

* **首部核心字段规范**

    * 版本号（Version，4 位）：指示 IP 协议版本，IPv4 该字段二进制固定为 `0100`（十进制 4）。

    * 首部长度（Internet Header Length，IHL，4 位）：

        * > **规则**：以 **4 字节（32 位）** 为基本度量单位，真实字节数等于 $\text{IHL} \times 4$。

        * > **易错点**：⚠️ 固定首部 20 字节对应的最小合法 IHL 数值为 $20 \div 4 = 5$（二进制 `0101`）；取值大于 5 时超出部分表示扩展选项长度。

    * 服务类型（Type of Service，TOS，8 位）：用于标记区分服务优先级，由于缺乏配套跨域阶梯计费与博弈机制，在公网商业运营中长期未获端到端执行。

    * 总长度（Total Length，16 位）：指示包含首部与数据载荷在内的整包字节数，理论上限为 $2^{16}-1 = 65535$ 字节；有效数据载荷长度为 $\text{Total Length} - (\text{IHL} \times 4)$。

    * 生存时间（Time to Live，TTL，8 位）：防止路由环路死循环；分组每经过一台路由器其数值强制减 1，递减至 0 时立即被丢弃并触发 ICMP 超时报告。

    * 上层协议（Protocol，8 位）：解复用标识字段，指示载荷交付的目标协议实体（TCP 为 6，UDP 为 17，ICMP 为 1）。

    * 首部校验和（Header Checksum，16 位）：仅对 IP 首部每 16 位执行二进制反码求和取反计算，不校验数据载荷；检验失败的数据报直接被静默丢弃。

    * 源 IP 地址与目的 IP 地址（Source and Destination IP Address，各 32 位）：记录发信端物理网卡接口与最终宿主网卡接口的全局逻辑编址。

    * 选项（Options，可变长）：支持记录路由等调试指令，为保证硬件线速转发，在骨干网常规数据通信中缺省为空。

### IP 分片与端到端重组机制

* **最大传输单元（Maximum Transmission Unit，MTU）**

    * > **定义**：底层数据链路层数据帧所能封装承载的网络层数据报的最大字节上限（不包含链路层自身帧头与帧尾）。

    * 以太网（Ethernet）典型 MTU 为 1500 字节，FDDI 令牌环网络 MTU 可达 4000 字节。

    * 触发前提：路由器从大 MTU 链路接收数据报，经查表转发需从较小 MTU 链路发出且整包尺寸超标。

* **分片控制三要素**

    * 标识符（Identification，16 位）：源主机分配的唯一编号，同一原始数据报切出的所有分片必须复制并维持完全相同的标识符。

    * 标志位（Flags，3 位）：包含 DF 与 MF 标记。DF（Don't Fragment）置 1 强制禁止分片；MF（More Fragments）置 1 表示后续仍有分片，MF 置 0 表示此片为该组末尾分片。

    * 片偏移量（Fragment Offset，13 位）：指示当前片载荷在原始未切分数据载荷区中的相对起始字节位置。

    * 8 字节对齐规则（8-Byte Alignment Rule）：由于 13 位片偏移需覆盖 65535 字节寻址跨度，设计规定片偏移以 **8 字节** 为计量基准；除最后一片外，其余分片的载荷字节数必须是 8 的整数倍。

* **分片计算与重组准则**

    * 分片独立性：每个切分出来的片均由路由器独立添加包含相同 ID 的完整 20 字节 IP 首部。

    * 计算实例（4000 字节数据报，含 20 首部与 3980 载荷，ID=777，切入 MTU=1500 链路）：

        * 分片 1：总长度 1500 字节，载荷 1480 字节（原区间 0～1479），$\text{MF}=1$，$\text{Offset} = 0 \div 8 = 0$。

        * 分片 2：总长度 1500 字节，载荷 1480 字节（原区间 1480～2959），$\text{MF}=1$，$\text{Offset} = 1480 \div 8 = 185$。

        * 分片 3：总长度 1040 字节，载荷 1020 字节（原区间 2960～3979），$\text{MF}=0$，$\text{Offset} = 2960 \div 8 = 370$。

    * 重组位置约束：分片重组必须且只能由最终目的端主机完成，沿途路由器绝不执行重组（避免占用核心转发内存，且各分片可能沿不同路径抵达）。

    * 重组定时器机制：目标主机接收到某 ID 的首个分片即启动本地定时器；若在超时前集齐所有分片则重组交付，若超时仍有任意一片缺失，目标主机无条件丢弃已收到的该 ID 全部碎片。

### 伴随信令协议 ICMP 与网络诊断工具

* **网际控制报文协议（Internet Control Message Protocol，ICMP）**

    * > **定义**：在主机和路由器之间传递网络层差错报告与运行状态探测的伴随信令协议。

    * ICMP 报文作为载荷封装在 IP 数据报内部进行传输，上层协议字段值为 1。

* **Ping 连通性测试程序**

    * 用于检验目标主机的网络层双向可达性与往返时延（RTT）。

    * 源主机向目标发送 ICMP 回显请求报文（Echo Request，类型 8）；目标主机收到后反转源目地址，回复 ICMP 回显应答报文（Echo Reply，类型 0）。

* **Traceroute 路径探测程序**

    * 用于逐跳探测源主机到目标主机通信链路上的每一跳路由器接口 IP 及跳步延迟。

    * 探测机理：源主机依次向目标发送一组初始 TTL 逐轮递增的分组（TTL 分别置 1, 2, 3...）。

    * 节点超时响应：第 $n$ 跳路由器将 TTL 减为 0 后，依规抛弃该分组并主动回送 ICMP 超时差错报文（Time Exceeded，类型 11）；源端由报文源 IP 提取该跳路由器接口地址并计算 RTT。

## IP 编址体系与无类域间路由

### IP 地址本质与纯子网判据

* **IP 地址（IP Address）**

    * > **定义**：用于全局唯一标识一台网络设备（主机或路由器）与某个物理链路之间的连接边界——即网络接口（Network Interface）的逻辑编号。

    * 路由器承担跨网段转发任务，必须具备至少两个物理接口，因此一台路由器必然拥有至少两个 IP 地址。

    * 多宿主设备（Multi-homed Device）：装配多块网卡或绑定多个接口并配置多个 IP 地址的主机或服务器。

* **纯子网（Pure Subnet）**

    * > **定义**：一组无需网络层路由器介入即可实现一跳直接通信的网络接口集合。

    * 充分必要判据：子网内所有接口的 32 位 IP 地址拥有完全相同的网络前缀；子网内任意两个 IP 接口之间的网络层通信为一跳直接可达（One-hop Reachable）。

    * 内部物理介质通过链路层设备（以太网交换机 Switch 或无线接入点 AP）透明互联，交换机转发不改写 IP 首部，两节点通信在第三层视角仅为一跳。

* **孤岛分析法（Island Method）**

    * 判定规则：将拓扑图中所有主机及路由器的接口连接全部切断，设备主体移走后，留在图纸上的孤立连通网络介质及其所挂接的接口端点构成物理孤岛。

    * 拓扑形态分为局域网（LAN，包含大量主机的广播与多点访问网络）与点到点链路（Point-to-Point Link，长途主干海缆两端直连两台路由器接口的微型双地址孤岛）。

### 分类编址与特殊地址空间

* **分类编址（Classful Addressing）**

    * 早期依据最高比特模式硬性划分网络号与主机号边界，掩码信息内隐于地址本身：

    | 地址类别 | 最高位前缀 | 网络号位数 | 主机号位数 | 全球可用网络数 | 每个网络最大主机数 | 地址首字节范围 | 核心应用定位 |
    | :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
    | **A 类** | `0` | 8 位 | 24 位 | $2^{7}-2 = 126$ 个 | $2^{24}-2 = 16,777,214$ 台 | 1 ～ 126 | 超大型跨国机构与国家级专网 |
    | **B 类** | `10` | 16 位 | 16 位 | $2^{14} = 16,384$ 个 | $2^{16}-2 = 65,534$ 台 | 128 ～ 191 | 大中型企事业单位与高等院校 |
    | **C 类** | `110` | 24 位 | 8 位 | $2^{21} \approx 2,097,152$ 个 | $2^{8}-2 = 254$ 台 | 192 ～ 223 | 小型企业与局部局域网 |
    | **D 类** | `1110` | 不区分 | 不区分 | 不适用（组播地址） | 不适用（组成员） | 224 ～ 239 | 多播/组播传输（Multicast） |
    | **E 类** | `1111` | 不区分 | 不区分 | 不适用（保留地址） | 不适用（科研实验） | 240 ～ 255 | 预留供科学实验与未来测试 |

* **特殊 IP 地址空间**

    * 网络号自身：主机号部分全为 0 的地址（如 `202.38.64.0`），指代该子网实体本身，不分配给单机。

    * 未指定本机地址：32 位全为 0（`0.0.0.0`），用于主机未完成网络参数初始化时的源地址占位。

    * 本地受限广播（Limited Broadcast）：32 位全为 1（`255.255.255.255`），向本物理局域网全员泛洪，公网路由器绝对禁止跨网段转发。

    * 定向广播（Directed Broadcast）：指定网络前缀固定、主机位全为 1（如 `202.38.64.255`），向特定目标子网全员广播。

    * 本地回环测试（Loopback Address）：`127.0.0.0/8`（典型如 `127.0.0.1`），IP 层截获报文并调头原路返回内核，物理网卡不发射信号。

* **私有 IP 地址空间（Private IP Address）**

    * 由 IANA 保留给内网独立编址，公网主干路由器配置严格路由策略直接丢弃阻断：

        * A 类私网：`10.0.0.0/8`（10.0.0.0 ～ 10.255.255.255），容纳约 1677 万个地址。

        * B 类私网：`172.16.0.0/12`（172.16.0.0 ～ 172.31.255.255），涵盖 16 个连续 B 类网络块。

        * C 类私网：`192.168.0.0/16`（192.168.0.0 ～ 192.168.255.255），涵盖 256 个连续 C 类网络块。

### 无类域间路由 CIDR 与最长前缀匹配

* **无类域间路由（Classless Inter-Domain Routing，CIDR）**

    * > **定义**：彻底废除 A、B、C 类硬性分类边界，允许子网前缀落在 32 位任意比特位置的任意变长前缀编址技术。

    * 斜线表示法：`a.b.c.d/x`，其中 `/x` 明确指定高 $x$ 位为网络前缀（Prefix），剩余 $32 - x$ 位为主机号。

    * 子网掩码（Subnet Mask）：32 位二进制数值，网络前缀对应高位全置 `1`，主机位对应低位全置 `0`（如 `/23` 对应掩码 `255.255.254.0`，可用主机数为 $2^{9}-2=510$ 台）。

* **基于按位与运算的查表**

    * 查表代数逻辑：路由器提取数据报首部的 32 位目的地址（DA），逐行与表项子网掩码执行逻辑与运算：

    $$
    \text{Extracted Network Prefix} = \text{DA} \land \text{Subnet Mask}
    $$

    * 提取结果与该表项登记的“目的子网号”进行精确比对，数值一致即告命中。

    * 数据链路层协作：命中表项后，路由器根据下一跳 IP 利用 ARP 解析出其物理 MAC 地址，封装链路层帧并由对应端口线速打出。

* **路由聚集（Route Aggregation）**

    * > **定义**：将具有相同高位前缀的多条连续子网明细路由合并通告为一条超网路由（Supernetting）。

    * 运算实例：将机构划分的 8 个 `/23` 子网（`200.23.16.0/23` 至 `200.23.30.0/23`）向上级骨干网汇聚为单条 `200.23.16.0/20` 路由通告。

    * 核心价值：从源头收敛全球骨干路由表膨胀规模，大幅削减路由更新通告的带宽与计算开销。

* **最长前缀匹配原则（Longest Prefix Match，LPM）**

    * > **规则**：当转发表中存在多个表项能同时与数据报目的 IP 匹配成功时，路由器强制挑选子网掩码中 **1 的位数最多（前缀最长）** 的表项执行转发。

    * > **易错点**：⚠️ 转发表匹配不是先到先得。前缀越长代表子网划分越细致、涵盖地址范围越精确，空洞子网与明细迁移路由借由 LPM 机制获得优先转发仲裁。

    * 默认路由（Default Route）：表项掩码为 `0.0.0.0/0`，当遍历全部特定子网均未命中时兜底生效，将分组交由默认网关（Default Gateway）送往外部网络。

## 网络地址配置与地址转换

### 主机网络参数配置与 DHCP 协议

* **主机上网必备四要素**

    * IP 地址（IP Address）：本机在该子网内部全网唯一的逻辑网络层接口标识。

    * 子网掩码（Subnet Mask）：标定本机所在子网规模，用于比对判断目的端属于本地网段（直接交付）还是外部网段（网关中转）。

    * 默认网关（Default Gateway）：本子网边界出口路由器的内侧接口 IP 地址。

    * 本地域名服务器（Local DNS Server）：提供域名解析服务的网络节点 IP 地址。

* **动态主机配置协议（Dynamic Host Configuration Protocol，DHCP）**

    * > **定义**：提供即插即用（Plug-and-Play）网络参数自动分配与地址动态复用的应用层协议。

    * 承载在 UDP 协议之上，客户端监听端口 68，服务端监听端口 67。

* **DHCP 四步握手交互**

    * 发现阶段（DHCP Discover）：未获 IP 的客户端以 `0.0.0.0:68` 为源地址，向受限广播地址 `255.255.255.255:67` 发送广播探测分组，携带随机事务 ID。

    * 提供阶段（DHCP Offer）：局域网内 DHCP 服务器收到广播后，从可用地址池预留候选 IP，向客户端提供包含 IP、掩码、网关、DNS 与租用期（Lease Time）的 Offer 报文。

    * 请求阶段（DHCP Request）：客户端选择最先收到的 Offer，再次以广播形式发出 Request 分组，公开通告选定的服务器与 IP，并促使其他未被选中的服务器释放预留地址。

    * 确认阶段（DHCP ACK）：被选中的服务器发出 ACK 确认报文，正式批准该 IP 租约生效，客户端配置参数并启动租期倒计时。

    * 租期倒计时过半或即将过期时，客户端需向服务器单播发起续约（Renew）申请；续约失败且租期耗尽后必须释放 IP 并重新发起 Discover。

### 网络地址转换 NAT 与 NAPT

* **网络地址端口转换（Network Address Port Translation，NAPT）**

    * > **定义**：在出口边界路由器处建立私有 IP 及端口与全局公网 IP 及端口之间的动态映射，使整个内网共享少数公网 IP 访问公网的复用技术。

    * 出境重写：内网发出分组通过 NAT 路由器时，路由器将其私有源 IP 替换为路由器的公网 IP，将源端口替换为一个闲置的传输层端口，并在转换表中新增映射条目。

    * 入境还原：外网响应分组到达 NAT 路由器时，路由器根据其外网目标端口检索转换表，将目标 IP 与目标端口改回对应的内网主机私有 IP 与原始端口并送入内网。

    * 传输层端口号共 16 位，单个公网 IP 理论支持高达 65535 个并发连接会话。

* **NAT 工程优势与体系结构缺陷**

    * 工程效益：极大节省公网 IP 租用开销；内网拓扑增减变更对外透明；平滑切换运营商无需修改内网拓扑；外部无法直接主动探测内网主机，提供天然被动安全屏障。

    * > **易错点**：⚠️ NAT 严重违背了分层解耦与端到端设计哲学：
        * 践踏分层原则：第三层网络路由器拆开第四层 TCP/UDP 首部并篡改端口号。
        * 违背端到端原则（End-to-End Principle）：网络核心设备维护易失的连接映射状态；NAT 路由器故障重启将导致全网活跃的长连接全部瞬时崩塌。

* **NAT 穿越技术方案（NAT Traversal）**

    * 外网主动访问内网部署的服务时，NAT 路由查表无初始映射会默认丢弃，业界形成三类穿越方案：

    | 方案类别 | 核心工作机理 | 适用场景与优缺点 |
    | :--- | :--- | :--- |
    | **静态端口映射** | 在 NAT 路由器后台人工硬编码规则：将公网固定端口静态绑定至内网固定 IP 与服务端口 | 配置简单牢固，稳定性高；但必须人工配置后台，不支持动态按需分配 |
    | **UPnP / IGD 协议** | 内网服务启动后通过互联网网关设备（IGD）协议自动向路由器添加、更新和注销映射表项 | 应用程序全自动即插即用；依赖路由器开启支持，应用自主打洞存在安全隐患 |
    | **中继服务器（Relay）** | 内网节点主动向公网中继服务器保持长连接，外部客户端通过中继服务器进行双向中转转发 | 对各类 NAT 具备 100% 穿透兼容性；但大量消耗中继服务器高昂公网带宽，时延显著升高 |

## 下一代网际协议 IPv6

### IPv6 首部架构与核心演进

* **IPv6 协议（Internet Protocol Version 6，IPv6）**

    * > **定义**：采用 128 位地址空间与固化 40 字节基本首部的下一代网际协议。

    * 设计动机：根本性消除 IPv4 地址枯竭危机；废除逐跳重算校验和；取消中间路由器切片以提升主干网转发线速；原生支持流标签 QoS 分级。

    * 版本跳过历史：IPv5 是实验性的流协议（Internet Stream Protocol，ST2），因设计缺陷被废弃，下一代正式版本定名为 IPv6。

* **40 字节固定首部字段规范**

    * 版本号（Version，4 位）：二进制固定为 `0110`（十进制 6）。

    * 流量类别（Traffic Class，8 位）：对应 IPv4 的 TOS 字段，用于标记分组的服务优先级。

    * 流标签（Flow Label，20 位）：将属于同一业务流的分组打上相同标签，路由器对同一流内分组执行一致的路径调度与 QoS 保障。

    * 有效载荷长度（Payload Length，16 位）：指示紧跟在 40 字节基本首部之后的数据字节总数（含扩展首部与传输层数据）。

    * 下一个首部（Next Header，8 位）：解复用字段，指向传输层协议（TCP 为 6，UDP 为 17）或采用 TLV 格式级联的扩展首部（Extension Header）链表。

    * 跳数限制（Hop Limit，8 位）：取代 IPv4 的 TTL，每跳减 1，至 0 丢弃并触发 ICMPv6 报错。

    * 源 IP 地址与目的 IP 地址（Source and Destination Address，各 128 位）：地址空间扩容至 $2^{128} \approx 3.4 \times 10^{38}$ 个，实现全球全网物理接口的直接编址。

* **IPv6 两大减负革新**

    * 彻底废除首部校验和（Checksum）：依赖第二层链路层 CRC 校验与第四层传输层端到端校验和保障正确性；路由器在修改 Hop Limit 时无需重新计算校验和，大幅降低芯片计算时延。

    * 严禁中间路由器分片：中间路由器若遇分组尺寸超过输出链路 MTU，绝对不执行切片，直接抛弃并向源主机回送类型为 `Packet Too Big` 的 ICMPv6 差错报文，报文中明确告知下一跳 MTU；由源主机在发射端主动收缩传输层分段尺寸。

### IPv4 向 IPv6 的平滑过渡

* **演进式平滑过渡策略**

    * 现代互联网覆盖庞大全球终端与异构自治系统，无法通过设定类似 ARPANET 1983年标志日（Flag Day）的停机指令实施全局瞬时切换，必须依赖长期共存平滑过渡。

* **双栈技术（Dual Stack）**

    * > **定义**：在同一个物理网络节点或路由器上同时安装、配置 IPv4 与 IPv6 两套独立的网络层协议栈。

    * 设备具备 IPv4 和 IPv6 两个互不冲突的逻辑地址，能够同时理解并收发两种版本的协议数据报。

* **隧道技术（Tunneling）**

    * > **定义**：将一种协议的数据报作为载荷封装在另一种协议的数据报内部进行透明跨网传输的技术。

    * IPv6 over IPv4 机制：位于 IPv4 海洋两端的双栈边缘路由器，将接收到的 IPv6 完整分组整体塞入 IPv4 数据报的载荷区，IPv4 骨干路由器仅将其作为普通数据报转发；到达目的端边缘路由器后剥离外层 IPv4 头部，将还原出的原生 IPv6 分组投递入目的 IPv6 网络。

    * 随着 IPv6 铺设反超，残存的 IPv4 孤岛反向通过 IPv6 over IPv6 隧道跨域穿行，直至 IPv4 完全退出历史舞台。

## 软件定义网络与通用转发

### SDN 水平集成与三层解耦体系

* **传统垂直集成网络缺陷**

    * 专用中间盒（Middlebox）激增：防火墙、NAT、负载均衡、IDS 均为异构专用硬件，管理配置异构且成本极其高昂。

    * 全网行为固化：控制逻辑分布式固化在全球数百万台路由器中，新增协议或演进功能周期长达数年乃至数十年。

    * 专有软硬件强行绑定：设备商私有硬件平台与私有网络操作系统（NOS）捆绑销售，体系封闭阻碍创新。

    * 流量工程实施困难：传统基于单路径最短路径规则，中继节点查表仅取决于目的 IP，无法实现基于源地址或应用协议的多路径精细化负载均衡。

* **软件定义网络（Software-Defined Networking，SDN）**

    * > **定义**：将控制平面与数据平面完全物理分离，由逻辑集中的远程网络操作系统统一下发流表驱动转发的开放网络架构。

    * 借鉴 PC 产业的水平集成分工：底层由标准化白盒通用分组交换机组成，中间层为逻辑集中、物理分布式集群部署的 SDN 控制器，顶层为开放的网络应用程序。

* **SDN 三层架构与双向接口**

    * 网络应用层（Network Applications）：运行路由计算、防火墙策略、负载均衡、访问控制等业务软件。

    * 北向接口（Northbound Interface）：控制器与上层应用之间的编程接口（如 RESTful API、gRPC），应用层通过其获取网络抽象视图并提交控制逻辑。

    * 网络控制层（SDN Controller / NOS）：维护全局网络拓扑与链路状态，执行统一流表计算与动态策略编译。

    * 南向接口（Southbound Interface）：控制器与底层交换机之间的标准化控制协议（如 OpenFlow）。

        * 下行通道：控制器向交换机下发、修改、删除流表规则。

        * 上行通道：交换机上报端口与链路通断状态，或通过 Packet-In 消息将无法命中既有流表的未知首包上交控制器定夺。

    * 数据平面（Data Plane）：通用分组交换机依据流表规则执行高速线速处理。

    | 架构对比维度 | 传统 IP 分布式网络 | 软件定义网络（SDN） |
    | :--- | :--- | :--- |
    | **体系结构** | 垂直集成（软硬件一体化黑盒绑定） | 水平集成（应用、控制、数据三层物理与逻辑解耦） |
    | **控制形态** | 完全分布式（节点间互通协议，局部运算） | 逻辑上高度集中（控制器全局视图统一决策） |
    | **转发机制** | 传统单字段目的 IP 最长前缀匹配 | 基于多层字段的通用流表 Match-plus-Action |
    | **设备特征** | 路由器、防火墙、NAT 独立物理专机 | 标准化白盒交换机，由下发流表赋予功能角色 |
    | **创新升级** | 需制定新 RFC 并逐台升级固件，周期以年计 | 编写或更新上层网络 App 即可毫秒级动态下发生效 |
    | **流量调度** | 仅依赖静态链路代价（Metric），分流极难 | 支持跨层多维度灵活规划差异化传输路径 |

### 基于流表的通用转发与匹配-动作范式

* **流（Flow）**

    * > **定义**：在特定时间跨度内经过网络观察点的分组序列，序列内所有分组的首部某些字段具有相同的取值或符合预设模式。

* **流表（Flow Table）与匹配-动作范式（Match-Action）**

    * 通用分组交换机废除单纯基于目的 IP 的转发表，代之以支持跨层联合匹配的流表结构。

    * 标准流表项四大核心字段要素：

        * 匹配模式（Pattern）：跨层联合检索入接口、源目 MAC、以太网类型、VLAN ID、源目 IP、协议号、ToS、TCP/UDP 源目端口；未指定字段设为通配符 `*`。

        * 动作集（Actions）：匹配后执行的操作组合，包括出端口转发（Forward）、泛洪（Flood）、直接丢弃阻断（Drop）、重写特定首部字段（Modify-Field，改写 TTL、IP、端口）、上交控制器（Packet-In）。

        * 优先级（Priority）：多条规则同时命中时，无条件遵从优先级数值最高的表项。

        * 计数器（Counters）：实时记录命中该规则的累计分组总数（Packet Count）与累计传输字节总数（Byte Count）。

* **传统网络设备在通用转发中的统一抽象**

    * 抽象为传统路由器：匹配网络层目的 IP 前缀（如 `Dst IP: 10.1.0.0/16`），执行动作 `Forward(Port 1)` 并将 TTL 递减 1。

    * 抽象为二层交换机：网络层与传输层全通配，匹配链路层目的 MAC（如 `Dst MAC: aa:bb:cc...`），执行动作 `Forward(Port 3)`。

    * 抽象为防火墙：匹配特定传输层协议与敏感端口（如 `Protocol: TCP, Dst Port: 22`），执行动作 `Drop`。

    * 抽象为网络地址转换器（NAT）：匹配内网特定主机会话（如 `Src IP: 10.0.0.1, Src Port: 3345`），执行动作 `Modify(Src IP=202.114.0.1, Src Port=50001)` 并向指定端口 `Forward`。

* **细粒度流量工程实践（Traffic Engineering）**

    * 在同一台边界交换机上，为相同目的子网但源自不同内网主机（如 $h_5$ 与 $h_6$）的数据流，下发匹配不同源 IP 的流表规则，分别绑定输出物理接口 3 与 4，实现分流至不同链路。

    * 可将传输层端口纳入匹配模式，使 Web 交互业务（80 / 443 端口）走低时延主路径，备份下载等长流走大带宽备用路径，彻底突破传统网络单路径最短路径规则的约束。
