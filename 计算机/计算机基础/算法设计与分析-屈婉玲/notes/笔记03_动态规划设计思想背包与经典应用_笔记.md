# 动态规划：设计思想、背包与经典应用

## 多阶段决策与优化原则

### 多阶段决策过程

   * **动态规划（Dynamic Programming，DP）**

       * > **定义**：把整个计算过程组织成一个多阶段的决策过程——每一步求解时，把后面阶段的问题看作前面阶段问题的继续，先利用前面问题的结果来做后面问题的决策，从而不必考虑所有可能的结果。

       * 引例（多起点最短路）：$n$ 个起点 $s_1,\dots,s_n$、$m$ 个终点 $t_1,\dots,t_m$，中间夹若干层节点，边带长度，规定不许向回走，求从任一起点到任一终点的所有路里最短的一条；实例的解是 $s_3\to t_4$ 与 $s_5\to t_4$ 两条长度都是 10 的路径。

       * 蛮力困境：层数为 $k$ 的这类网络里，除最上、最下边缘节点外每个节点都有向上、向下两个方向，路径条数接近 $2^k$，工作量不可行。

       * 每个节点标记两样东西：到终点的最短路值——供上一层决策用；本步走向记号 U（向上）/D（向下）——供最后把路径描出来用。

       * 实例算得：$s_1$ 为 15、$s_2$ 为 13、$s_3$ 与 $s_5$ 均为 10；沿标记（如从 $s_3$ 出发的 D、D、D、U）即可描出那条长 10 的路。

       * 决策从最靠近终点的一层往回算，每层最短路都由「一步边长＋下一层节点已算好的最短路」构成：

| 阶段 | 决策对象 | 到终点的最短路怎么构成 |
| :--- | :--- | :--- |
| 第一阶段 | C 层各节点 | 直接取到终点的各条边里最短的 |
| 第二阶段 | B 层各节点 | B 到某 C 的一步边长 ＋ 该 C 的最短路 |
| 第三阶段 | A 层各节点 | A 到某 B 的一步边长 ＋ 该 B 的最短路 |
| 第四阶段 | 起点层各节点 | S 到某 A 的一步边长 ＋ 该 A 的最短路 |

### 子问题的界定

   * **子问题的界定（后边界不动，前边界潜移）**

       * 每一步决策处理一个子问题：后边界始终钉在终点不动，前边界一层一层向起点潜移。

       * 每步决策的内容固定为「一步边长 ＋ 前面子问题的决策结果」——前面的子问题已经算过，结果直接抄过来，计算量由此减下来。

       * > **定义**：动态规划算法的关键，是优化函数值之间存在依赖关系——有了它，不必全部从起点一步步枚举，而是利用前面子问题的结果直接把值拿来。

```text
 阶段一  决策 C 层：                C ─────────→ 终点
 阶段二  决策 B 层：           B ──→ C ─────────→ 终点
 阶段三  决策 A 层：      A ──→ B ──→ C ─────────→ 终点
 阶段四  决策 S 层： S ──→ A ──→ B ──→ C ─────────→ 终点
```

### 优化原则与反例

   * **优化原则（optimization principle），又称最优子结构性质（optimal substructure）**

       * > **定义**：一个最优决策序列的任何子序列本身，一定是相对于子序列的初始状态和结束状态的最优决策序列。

       * 最短路表述：任何最短路径的子路径，相对于它的子问题的起点和终点也是最短的；满足时，做大问题决策可以把这一段的最短路直接拿来用。

       * 适用边界：动态规划算法可用于求解组合优化问题，前提是满足优化原则；不满足就不存在原问题与子问题之间优化函数值的依赖关系，动态规划算法不能工作。

   * **反例：模 10 的最短路**

       * 目标改成「总长度模 10 的余数最小」；仍按多阶段决策从最靠近终点的节点往回算，得到的解是总长模 10 余 1 的那条路径。

       * 真正最优是四条长 5 的边（总长 20，模 10 余 0）：全局最优路径的最后一段并不是该子问题的最优解——该子问题的最优是余 2 的那条短边，全局最优偏偏走了另一条。

       * > **易错点**：出错根源是这个问题破坏了优化原则——问题与子问题的优化函数值之间没有依赖关系，不是决策顺序或实现细节出错；子路径不是子问题的最优解时，「通过子问题的最优来选择全局最优」的推理就是错的。

## 设计要素与矩阵链相乘

### 设计要素

   * **设计要素（动手前五步）**

       * 问题建模：写出优化目标函数的表示形式，以及对解的量的约束条件。

       * 划分子问题：确定子问题怎么划分、边界由哪些参数界定。

       * 写出递推方程：给出原始问题与归约后更小子问题优化函数值之间的依赖关系，是动态规划计算的基础。

       * 判断优化原则：看子问题的解变优后原问题的解是否也变优；优化原则不成立不能用动态规划。

       * 确定初值：最小子问题怎么界定、规模多少、具体值是什么，是计算的基础。

   * **完整要素清单（八条）**

       * 划分子问题、确定边界，把问题转换成多步判断的过程。

       * 定义优化函数，以它的极大或极小作为取舍依据。

       * 确认问题满足优化原则。

       * 列出优化函数的递推方程和边界条件。

       * 自底向上计算：从最小的子问题算起，给定计算顺序。

       * 设计备忘录（memo）：定好表格样式，存子问题的优化函数值与标记——标记有的问题需要设立、有的不需要。

       * 明确标记函数满足的计算公式。

       * 估计复杂度：用递推方程的方法，或者备忘录的方法。

### 矩阵链相乘问题

   * **矩阵链相乘（Matrix-Chain Multiplication）**

       * > **定义**：$n$ 个矩阵 $A_1,\dots,A_n$（$A_i$ 为 $p_{i-1}$ 行 $p_i$ 列）确定乘法次序（加括号方式），使元素相乘的总次数最少；输入是行列向量 $\langle p_0,p_1,\dots,p_n\rangle$（$p_0$ 是第一个矩阵的行数，$p_1$ 是第一个矩阵的列数也是第二个矩阵的行数，依此类推），解是运算顺序＋最少乘法次数。

       * $n$ 个矩阵相乘中间要做 $n-1$ 次乘法。

       * 两个矩阵 $i\times j$ 乘 $j\times k$：结果有 $ik$ 个元素、每元素要 $j$ 次乘法（外加 $j-1$ 次加法），按乘法计基本运算总量为 $i\times j\times k$。

       * 次序敏感实例：$A_1$ 为 $10\times100$、$A_2$ 为 $100\times5$、$A_3$ 为 $5\times50$；$(A_1A_2)A_3$ 要 $10\times100\times5+10\times5\times50=7500$ 次乘法，$A_1(A_2A_3)$ 要 $100\times5\times50+10\times100\times50=75000$ 次，相差十倍——按最少乘法次数的要求，第一种是好结果。

       * 蛮力加括号：$n$ 个矩阵加 $n-1$ 个括号的方法数是卡特兰数（Catalan number）$P(n)=\frac{1}{n+1}\binom{2n}{n}=\frac{(2n)!}{(n+1)!\,n!}$，用斯特林公式（Stirling's formula）化简得 $P(n)\approx\frac{2^{2n}}{n^{3/2}}$——指数函数，$n$ 大时蛮力不可行。

### 递推方程

   * **子问题 $m(i,j)$**

       * 取从 $A_i$ 到 $A_j$ 的连续矩阵链 $A_i..A_j$ 作子问题，由前边界 $i$、后边界 $j$ 界定，输入是原向量中 $\langle p_{i-1},\dots,p_j\rangle$ 那一段；$m(i,j)$ 记这段链最好划分的运算次数。

       * 归约抓「最后一次乘法发生在什么位置」：设发生在 $k$——先算完 $A_i..A_k$ 与 $A_{k+1}..A_j$，再把两个结果矩阵（$p_{i-1}$ 行 $p_k$ 列与 $p_k$ 行 $p_j$ 列）乘起来，合并工作量 $p_{i-1}p_kp_j$，这是把两个子问题的解组合起来的工作量。

$$m(i,j)=\min_{i\le k<j}\{\,m(i,k)+m(k+1,j)+p_{i-1}p_kp_j\,\}$$

   * **划分位置与优化原则**

       * $k$ 的取值从 $i$（划分画在 $A_i$ 后面）到 $j-1$（画在 $A_j$ 前面），每个划分位置都要按公式算一遍、再从中比出最小值。

       * 满足优化原则：$m(i,k)$ 或 $m(k+1,j)$ 变优，$m(i,j)$ 随之变小，可以用动态规划。

### 递归实现的代价

   * **递归骨架**

       * 对每个划分位置 $k$：递归求前、后两段的最优次数，加上合并工作量得到候选总次数；更小则替换 $m(i,j)$ 并同时更新划分位置，$m(i,j)$ 永远保留最少运算次数（递归边界伪码里未写全）。

```text
for k = i to j-1 do                     # k 遍历所有可能的划分位置
    递归求 Ai..Ak   的最优运算次数        # 前一个子问题
    递归求 Ak+1..Aj 的最优运算次数        # 后一个子问题
    合并：两段结果矩阵相乘的工作量         # 最后一次乘法
    if 总次数 < 当前保留的 m(i,j) then     # 这是一个更好的划分
        替换并更新 m(i,j) 与对应的划分位置
```

   * **复杂度仍是指数**

       * 划分位置在 $k$ 时：前段 $k$ 个矩阵工作量 $T(k)$、后段 $n-k$ 个工作量 $T(n-k)$、合并常数工作量 $c$；$n-1$ 种划分都要试，$T(n-k)$ 的求和与 $T(k)$ 的求和是同一公式反序，整理得 $T(n)=\sum_{k=1}^{n-1}\big(T(k)+T(n-k)+c\big)=2\sum_{k=1}^{n-1}T(k)+(n-1)c$。

       * 归纳证明 $T(n)\ge 2^{n-1}$：$n=2$ 成立；代入归纳假设 $T(k)\ge 2^{k-1}$ 后右边成等比级数 $\sum_{k=1}^{n-1}2^{k-1}=2^{n-1}-1$，整理得 $2(2^{n-1}-1)+(n-1)c\ge 2^{n-1}$。

       * 结论：递归实现比蛮力的 $2^{2n}/n^{3/2}$ 阶有下降，但仍指数函数、效率不高。

   * **病根与药方**

       * $n=5$ 实例：不同边界的子问题一共 15 个（规模 1 有五个、规模 2 四个、规模 3 三个、规模 4 两个、规模 5 一个），递归却要计算 81 个子问题；规模 1 的子问题出现次数分别是 8、12、14、12、18。

       * 病根：同一个子问题会在不同递归路径上出现多次，每次出现都重新计算一遍。

       * 药方：空间换时间——把每个子问题首次计算的结果记录下来，后边再碰到直接查记录，每个子问题只算一次；代价是记录中间结果的空间消耗。

## 迭代实现

### 迭代前的三件事

   * **迭代实现的三个先行问题**

       * 迭代从哪里起步、按什么顺序推进：从最小的子问题算起，把计算顺序定死，保证后面用到的值前面已经算好存下。

       * 用什么存储结构保留计算结果：中间每步子问题的结果都要留下，充当备忘录的存储结构要设计时定下来。

       * 解怎么追踪：优化函数的值算出来了，问题的解是什么是另外一件事（最少运算次数是值，括号加在哪里才是解）；要靠标记函数把每一步决策的位置标记下来才能找到解。

### 矩阵链的迭代算法

   * **子问题按链长分拨**

       * 链长 1：$n$ 个子问题 $(i,i)$，初值全 0（一个矩阵没有乘法，不用算）；链长 2：$n-1$ 个；链长 3：$n-2$ 个；……链长 $n-1$：2 个；链长 $n$：1 个，即原始问题。

       * 计算顺序：从链长 1 到 $n$ 逐行推进，每行内子问题从左到右（首位置 $i$ 从小到大）；后面要用到前面的子问题，值直接拿过来。

   * **迭代伪码（两个备忘录）**

       * 维度数组 p 存各矩阵的行列参数；备忘录 m 记所有子问题的最少乘法次数，备忘录 s 记每个子问题取得最小值时的分界位置。

       * 分界位置 $k$ 的动法：先画在 $i$ 后面（前段只有 $A_i$ 一个矩阵）算出第一个结果，再从 $i+1$ 到 $j-1$ 陆续右移遍历所有可能；每换一个分界算一个候选，更小就替换——遍历完保留下来的就是最好结果。

       * 少了 s，最后只知道最少要乘多少次、不知道括号加在哪里。

```text
1   把所有 m[i,i] 置为 0                                   // 链长为 1 的初值
2   for r = 2 to n:                                        // 遍历所有链长
3       for i = 1 to n-r+1:                                // 定下子问题的首位置 i
4           j = i + r - 1                                  // 链长定了，末位置 j 随之而定
5           m[i,j] = m[i,i] + m[i+1,j] + p[i-1]*p[i]*p[j]  // 分界先画在 i 后面试一次
6           s[i,j] = i
7           for k = i+1 to j-1:                            // 分界位置 k 陆续右移
8               t = m[i,k] + m[k+1,j] + p[i-1]*p[k]*p[j]
9               if t < m[i,j]: m[i,j] = t, s[i,j] = k      // 更小就替换，分界一并记下
```

### 填表与追踪算例

   * **算 $m[2,5]$**（$A_2$ 为 $35\times15$、$A_3$ 为 $15\times5$、$A_4$ 为 $5\times10$、$A_5$ 为 $10\times20$）

       * 三个分界候选里 7125 最小，填进 $m[2,5]$，取胜分界（第 3 个矩阵后面）同时记进 $s[2,5]$；调用的 0、2500、2625、1000、4375 全是前面轮次算好存着的现成值——这就是备忘录。

| 分界 $k$ | 前段 | 后段 | 前段值 | 后段值 | 合并工作量 | 合计 |
| :--- | :--- | ---: | ---: | ---: | ---: | ---: |
| $k=2$ | A2 | A3A4A5 | 0 | 2500 | $35\times15\times20=10500$ | 13000 |
| $k=3$ | A2A3 | A4A5 | 2625 | 1000 | $35\times5\times20=3500$ | **7125** |
| $k=4$ | A2A3A4 | A5 | 4375 | 0 | $35\times10\times20=7000$ | 11375 |

   * **顺着标记函数追解**

       * 查 $s[1,5]=3$：最后一次计算切在第 3 个矩阵后面，分成 $(A_1A_2A_3)$ 与 $(A_4A_5)$ 两段；右段只有两个矩阵，怎么乘没有第二种选择，不用再追。

       * 左段还得追：查 $s[1,3]=1$——划分位置在第 1 个矩阵后面，即 $A_2,A_3$ 先算、$A_1$ 再和它们的结果算。

       * 最终加括号 $(A_1(A_2A_3))(A_4A_5)$；按这个顺序乘运算次数是 11875，正是备忘录里存的最少乘法次数——优化函数的值和问题的解对上了。

   * **递归与迭代，各自付出什么**

       * 递归实现的子问题被多次重复计算、计算次数可能指数量级增长，时间耗在这里；迭代每个子问题只算一次、时间复杂度低，省下的时间换来备忘录那一块空间开销——一笔清清楚楚的交换。

| 实现方式 | 时间 | 空间 |
| :--- | :--- | :--- |
| 递归实现 | 时间复杂度高 | 空间比较小 |
| 迭代实现 | 时间复杂度降低 | 空间消耗加多 |

### 复杂度估计

   * **矩阵链迭代算法的 $O(n^3)$**

       * 数循环口径：链长、首位置、切分位置三重循环都是 $O(n)$ 量级，内部操作常数时间。

       * 数备忘录口径：备忘录 $n^2$ 项（子问题对应矩阵链前后边界的所有组合），每项内部划分约 $O(n)$；再加追踪解 $O(n)$，总工作量仍是 $n$ 的立方。

   * **一般估法**

       * 两条路：把备忘录各项的工作量加起来、再与追踪解的工作量相加；或通过递推方程来算。

       * > **提示**：估计一个动态规划算法的复杂度，先数备忘录有多少项、每项要多少工作量，乘起来往往就是总复杂度的主体；追踪解那部分一般追不上它，很多问题的复杂度函数基本上就和备忘录计算的工作量一样。

## 投资问题

### 建模与子问题界定

   * **投资问题**

       * > **定义**：有 $m$ 元钱、$n$ 项投资，把 $x$ 元投到第 $i$ 个项目的回报用效益函数 $f_i(x)$ 表示，求怎么分配这 $m$ 元钱使总效益最大。

       * 解是 $n$ 维向量（各项目分得的钱数）；目标 $\max\sum_{i=1}^{n}f_i(x_i)$，约束 $\sum_{i=1}^{n}x_i=m$、$x_i$ 取非负整数（不妨设各值都是自然数）。

       * 实例：5 万元分给 4 个项目，效益表（钱数单位万元）：

| 投入钱数 $x$ | 项目 1 | 项目 2 | 项目 3 | 项目 4 |
| :---: | :---: | :---: | :---: | :---: |
| 0 | 0  | 0  | 0  | 0  |
| 1 | 11 | 0  | 2  | 20 |
| 2 | 12 | 5  | 10 | 21 |
| 3 | 13 | 10 | 30 | 22 |
| 4 | 14 | 15 | 32 | 23 |
| 5 | 15 | 20 | 40 | 24 |

   * **子问题 $(k,x)$：两种不同类型的参数**

       * $k$ 代表考虑到第几个项目（范围 1 到 $k$），$x$ 界定投资钱数上限（不超过 $x$）；矩阵链的 $i,j$ 是同类型的下标参数，这里两个参数性质不同。

       * 计算顺序：先把 $k$ 定下来（外层从 1 到 $n$），$k$ 给定后再让 $x$ 从小到大（内层从 1 到 $m$）；一个 $k$ 接一个 $k$ 地填，$f(n,m)$ 就是原始问题。

### 递推方程与初值

   * **优化函数 $f_k(x)$**

       * > **定义**：$f_k(x)$ 表示把 $x$ 元钱分给前 $k$ 个项目能取得的最大效益（$k$ 代表项目不超过 $k$ 的范围，$x$ 代表钱数不超过 $x$）。

       * 多步判断思路：已知 $p$ 元（$p\le x$）投给前 $k-1$ 个项目的最大效益 $f_{k-1}(p)$，在此基础上求更大的问题——若给第 $k$ 个项目 $x_k$ 元，它的回报是一项，剩下 $x-x_k$ 元投给前 $k-1$ 个项目的最大回报是另一项。

$$f_k(x)=\max_{0\le x_k\le x}\{\,f_k(x_k)+f_{k-1}(x-x_k)\,\}$$

   * **记号提醒与初值**

       * $x_k$ 最少可投 0 元（不给它钱）、最多投到 $x$ 元，共 $x+1$ 种取值，每种都要代一遍右边的公式、比出其中最大的。

       * > **提示**：这个方程里的 $f$ 一身两职——左边的 $f_k(x)$ 和右边的 $f_{k-1}(x-x_k)$ 是优化函数，备忘录里存着、自己算出来的最大效益；右边的 $f_k(x_k)$ 是第 $k$ 个项目自己的效益函数，查的是原始效益表。同一记号靠位置区分角色，别把查表项当成备忘录项。

       * 初值：$k=1$ 时就是把这些钱分配给第一个项目，直接查原始效益表，不需要计算。

### 填表与解追踪

   * **$k=2$ 的完整推演**

       * $f(2,1)=11$：1 万元给项目 2 得 0、给项目 1 得 11，取 11。

       * $f(2,2)=12$：三种划分里「2 万全给项目 1」得 12 最好，另两种是 5（项目 2 拿 2 万）与 $0+11=11$（各拿 1 万，$f(2,1)$ 直接拿过来用）。

       * $f(2,3)=16$：四种划分里「项目 1 拿 1 万＋项目 2 拿 2 万」$11+5=16$ 最好；继续同法得 $f(2,4)=21$、$f(2,5)=26$。

       * 备忘录里每个优化函数值旁边还记一个标记函数——取得该值时最后一个项目给了多少钱，标记和值记在同一个位置。

   * **顺着标记把分配方案追出来**

       * 备忘录最后一项：5 万元分前 4 个项目最大效益 61，标记是 1——$x_4=1$。

       * 剩 $5-1=4$ 万分前 3 个项目：$x(3,4)$ 的标记是 3——$x_3=3$；剩 $4-3=1$ 万分前 2 个项目：$x(2,1)$ 的标记是 0——$x_2=0$。

```text
x(4,5) 标记 1 → x4 = 1    剩 4 万分给前 3 个项目
x(3,4) 标记 3 → x3 = 3    剩 1 万分给前 2 个项目
x(2,1) 标记 0 → x2 = 0    剩 1 万给第 1 个项目，x1 = 1
```

       * 最终解 $x_1=1,\ x_2=0,\ x_3=3,\ x_4=1$，回报 $11+0+30+20=61$，正是备忘录里存的那一项的值。

### 复杂度

   * **$nm^2$ 量级**

       * 算一项 $f_k(x)$：$x_k$ 有 $x+1$ 种取值要做 $x+1$ 次加法，得到 $x+1$ 个结果还要比出最大、再做 $x$ 次比较。

       * 加法次数 $\sum_{k=2}^{n}\sum_{x=1}^{m}(x+1)=\frac12(n-1)m(m+3)$（等差数列求和）；比较次数 $\sum_{k=2}^{n}\sum_{x=1}^{m}x=\frac12(n-1)m(m+1)$；无论加法还是比较都是 $nm^2$ 量级（$k=1$ 是初值不需要算）。

       * 已是关于 $n$ 和 $m$ 的多项式级别，比蛮力好得多。

       * 备忘录不仅要存表中的项，还用来估计时间复杂度——备忘录的设计因此重要。

## 背包问题

### 建模与子问题界定

   * **背包问题（Knapsack Problem）**

       * > **定义**：$n$ 种物品每种有重量、价值两个参数，在不超过重量限制的前提下装包，使装入物品的总价值最大；不妨设重量都是正整数。

       * 建模：$x_i$ 是第 $i$ 种物品装入的个数，$\max\sum_{i=1}^{n}x_iv_i$，约束 $\sum_{i=1}^{n}x_iw_i\le b$、$x_i$ 为非负整数。

       * 身份：目标函数和约束条件全部是线性函数称线性规划（linear programming）；进一步要求所有 $x_i$ 取非负整数称整数规划（integer programming）。

       * 实例：背包总重量限制 10，四种物品：

| 物品种类 | 价值 | 重量 |
| :---: | :---: | :---: |
| 1 | 1 | 2 |
| 2 | 3 | 3 |
| 3 | 5 | 4 |
| 4 | 9 | 7 |

   * **子问题 $(k,y)$ 与计算顺序**

       * $k$ 界定可选物品范围（只考虑前 $k$ 种），$y$ 界定重量限制；两个参数不是同一种类型（不同于矩阵链的同类型下标）。

       * 顺序：$k$ 从 1 到 $n$ 从小到大界定子问题大小，$k$ 确定后 $y$ 从 1 到 $b$ 从小到大增长；先算 $k=1$ 这一行、再一行一行往下推。

### 递推方程与初值

   * **优化函数 $f_k(y)$**

       * > **定义**：$f_k(y)$ 表示装前 $k$ 种物品、总重量不超过 $y$ 时能取得的最大价值。

       * 方程前一项是不装第 $k$ 种、只用前 $k-1$ 种装；后一项是装下第 $k$ 种得价值 $v_k$，剩余重量 $y-w_k$ 仍由前 $k$ 种填充——下标是 $k$ 不是 $k-1$，反映装完一个还可以继续装第 $k$ 种（装一个、装两个甚至更多的考虑）。

$$f_k(y)=\max\{\,f_{k-1}(y),\;\;v_k+f_k(y-w_k)\,\}$$

   * **初值四条**

       * $f_0(y)=0$：没有考虑任何物品。

       * $f_k(0)=0$：重量限制是零，不可能装入任何物品。

       * $f_1(y)=\lfloor y/w_1\rfloor\cdot v_1$：只装第 1 种物品时，$y$ 除以 $w_1$ 下取整是能装的最大个数，乘单位价值。

       * $y<0$ 时 $f_k(y)=-\infty$：递推里 $y-w_k$ 在 $y$ 小于 $w_k$ 时是负数——负容量意味着这种装法超重、实际不存在，令它等于负无穷，两项比较时这一项自动被抛弃。

### 两种递推写法的取舍

   * **第二种写法（按投资问题的方式）**

       * 装入 $x_k$ 个第 $k$ 种物品产生价值 $x_kv_k$、占据重量 $x_kw_k$，剩下的 $y-x_kw_k$ 交给前 $k-1$ 种填充；$x_k$ 最少 0 个（不装）、最多 $\lfloor y/w_k\rfloor$ 个，全部取值代入取最大：$f_k(y)=\max_{0\le x_k\le\lfloor y/w_k\rfloor}\{\,x_kv_k+f_{k-1}(y-x_kw_k)\,\}$。

   * **工作量对比**

       * 两项取 max 写法算一项是常数：$f_{k-1}(y)$ 按计算顺序已算过可查；$f_k(y-w_k)$ 虽然第一个下标还是 $k$，但 $y$ 值比当前子问题小、也已经算过——查表加一次加法、一次比较。

       * 遍历 $x_k$ 写法算一项可能 $O(b)$：$w_k$ 较小时 $\lfloor y/w_k\rfloor$ 与 $y$ 同量级，须逐个代入——前一种方程计算量小，后一种大。

| 写法 | 算一项的工作量 | 原因 |
| :--- | :---: | :--- |
| 两项取 max | 常数 | 两项都已算过、可以查表 |
| 遍历 $x_k$ 所有取值 | 可能 $O(b)$ | 取值个数可与 $y$ 同量级，须逐个代入 |

### 标记函数与解追踪

   * **标记函数 $i_k(y)$**

       * > **定义**：$i_k(y)$ 反映考虑前 $k$ 种物品、总重不超过 $y$ 时，所装入物品的最大标号。

       * 递推：不装第 $k$ 种效果更好则 $i_k(y)=i_{k-1}(y)$（最大标号至多跟前 $k-1$ 种装的一样）；装第 $k$ 种效果更好则 $i_k(y)=k$。

       * 初值：只考虑第 1 种物品时，$y$ 装不下 1 号物品标记 0，装得下标记 1。

   * **算例：最大价值 12 是怎么装出来的**

       * 按「先 $k$ 后 $y$」把整张表算完，最后一行最后一列 $f_4(10)=12$ 就是能达到的最大价值。

       * 追踪：$i(4,10)=4$——4 号至少装 1 个，扣重 $10-7=3$，继续考虑前 4 种；$i(4,3)=2$——2 号至少装 1 个（标号从 4 直跳到 2，说明 3 号根本没装），扣重 $3-3=0$；$i(4,0)=0$——容量尽，追踪结束。

       * 解：$x_1=0$、$x_2=1$、$x_3=0$、$x_4=1$，总重 $3+7=10$ 不超限，总价值 $3+9=12$。

   * **追踪伪码（三个主要步骤）**

       * 输入是标记函数表，输出各物品装入数量；从表最后一项起步，装一个扣一次重量，标记值变小就换下一种物品，遇 0 收尾。

```text
输入：标记函数表 i(k, y)，物品重量 w1..wn
输出：x1..xn（各物品装入的个数）

1  从最后一项 (n, b) 开始追踪：j ← i(n, b)
   // j 就是最终装入的最大标号物品的标号
2  x_j ← 1；y ← y − w_j            // 该标号物品先装一个，扣掉它的重量
3  查当前位置的标记值：
   - 若仍等于 j：第 j 号物品还可继续装，x_j ← x_j + 1，y ← y − w_j，重复本步
   - 若变成更小的值 t 且 t ≠ 0：t 是下一种被装物品的标号，j ← t，回到第 2 步
   - 若等于 0：容量已尽，追踪结束
```

### 伪多项式时间

   * **伪多项式时间算法（pseudo-polynomial time algorithm）**

       * 两项取 max 的递推每项常数时间；$k$ 有 $n$ 种、$y$ 有 $b$ 种，共 $nb$ 项，总时间 $O(nb)$——表面是关于 $n$、$b$ 的多项式，但并不是真正的多项式时间。

       * > **定义**：表面看起来是 $n$、$b$ 的多项式，但相对真正的输入规模（$n$ 与 $\log b$）并不是多项式的算法，叫伪多项式时间算法。

       * 输入规模由 $b$ 和 $n$ 决定：整数 $b$ 存进计算机用 $\log b$ 位，所以输入规模是 $\log b$ 和 $n$ 两个参数；$n$ 对输入规模是多项式关系，$b$ 不是——$b$ 相当于 $2^{\log b}$，是指数级的。

       * > **易错点**：判断多项式时间看的不是数值多大，而是输入占了多少位；$O(nb)$ 相对 $\log b$ 就是指数级——「看起来是多项式」和「真的是多项式」之间差着一个对数。

### 变形与设计套路

   * **常见变形（处理思路完全一样）**

       * 限制件数：第 $i$ 种物品最多用 $n_i$ 个，每种物品的个数都有上限。

       * 0-1 背包：每种物品最多装一个——不装或者装一个。

       * 多重约束：$m$ 个约束都要满足，典型是物品有重量和体积两个约束——重量不超 $b$、体积也有上限的二维限制下价值最大。

   * **固定的设计四步**

       * 界定子问题：用两个参数界定，优化函数的递推方程、边界条件、初值都由这两个参数决定。

       * 说明计算顺序：参数不是同一类型时，要讲清自底向上计算时哪个参数先取各种值、第一个参数固定后第二个参数怎么取值。

       * 设计备忘录：按子问题的计算顺序设计，存储优化函数值和标记函数值。

       * 设立标记函数并给出追踪解的算法。

## 最长公共子序列

### 问题描述与蛮力算法

   * **子序列与公共子序列**

       * > **定义**：若存在 $X$ 的严格递增下标序列 $i_1<i_2<\cdots<i_k$ 使 $z_1=x_{i_1},\ z_2=x_{i_2},\ \dots,\ z_k=x_{i_k}$，则 $Z$ 是 $X$ 的子序列——挑着选、间隔着选都行、不要求连续，但原来的前后次序不能变；$Z$ 既是 $X$ 的子序列也是 $Y$ 的子序列时称公共子序列，长度即子序列含有的元素个数。

       * 实例：$X$ 有 7 个元素、$Y$ 有 6 个元素，一个最长公共子序列是 BCBA（长度 4，间隔着选）；解不唯一——最长长度相同、选出的子序列可能不一样，只要给出一个即可。

   * **蛮力算法**

       * 不妨设 $m\le n$：依次拿出 $X$ 的每个子序列，检查它在 $Y$ 中是否出现；$X$ 的每个字符选/不选共 $2^m$ 个子序列，每个从头到尾扫一遍 $Y$ 花 $O(n)$，总时间 $n\cdot 2^m$——输入规模的指数量级。

### 递推方程与标记函数

   * **子问题与三种归约**

       * 子问题：$X$ 取前缀 $x_1..x_i$、$Y$ 取前缀 $y_1..y_j$，参数 $i,j$ 是两个不同序列的后边界（原始问题规模由 $m,n$ 两个维度界定）。

       * 归约一：$X$、$Y$ 的最后一个元素相同——把它选入公共子序列，归结到 $X$ 减一、$Y$ 减一的子问题，结果接在子问题最长公共子序列的后面。

       * 归约二：末元素不等时这对末元素不可能被取入，可以不考虑 $X$ 的最后一个元素——归结为 $X$ 前 $m-1$ 个元素与 $Y$ 的公共子序列问题。

       * 归约三：也可以不考虑 $Y$ 的最后一个元素——归结为 $X$ 与 $Y$ 前 $n-1$ 个元素的公共子序列问题。

       * 这些归约满足优化原则和子问题的重叠性，这是能用动态规划的前提。

   * **优化函数 $c[i,j]$**

       * $c[i,j]$ 记 $X$ 取 $x_1..x_i$、$Y$ 取 $y_1..y_j$ 时最长公共子序列的长度（用子问题的两个后边界来记）；初值是有一个序列长度为 0 时 $c=0$。

$$c[i,j]=\begin{cases}c[i-1,j-1]+1, & x_i=y_j\\[4pt]\max\{\,c[i,j-1],\;\;c[i-1,j]\,\}, & x_i\ne y_j\end{cases}$$

   * **标记函数 $b[i,j]$**

       * 记录子问题 $(i,j)$ 是按刚才哪种归约方式得到的，值用三个箭头表示：

| 标记 | 归约去向 | 什么时候取这个标记 |
| :---: | :--- | :--- |
| ↖（斜向） | 归结到 $(i-1,j-1)$ | $x_i=y_j$，末元素选入公共子序列 |
| ←（横向） | 归结到 $(i,j-1)$ | 末元素不等，$Y$ 去掉一个尾元素 |
| ↑（纵向） | 归结到 $(i-1,j)$ | 末元素不等，$X$ 去掉一个尾元素 |

### 追踪伪码与算例

   * **计算与追踪伪码**

       * 计算表时先给边界赋初值（$X$ 或 $Y$ 长度为 0 处 $c$ 为 0、标记置边界值），再按 $i$（$X$ 后边界）、$j$（$Y$ 后边界）双循环逐格计算，相等走斜向、不等在横向纵向两种里取大，标记同步记下。

       * 追踪从原始问题位置 $b[m,n]$ 开始向前；输出子序列是从后向前输出的，先输出的是靠后的字符，斜向标记处输出 $x_i$，横向纵向只移动不取字符。

```text
LCS 长度与标记函数计算：
1  对所有 i：c[i,0] ← 0，b[i,0] 置边界值     // X 的长度为 0
2  对所有 j：c[0,j] ← 0，b[0,j] 置边界值     // Y 的长度为 0
3  for i ← 1 to m:                          // i 是 X 的后边界
4      for j ← 1 to n:                      // j 是 Y 的后边界
5          if x_i = y_j then
6              c[i,j] ← c[i-1,j-1] + 1；  b[i,j] ← ↖
7          else
8              c[i,j] ← max{ c[i,j-1], c[i-1,j] }
9              b[i,j] ← ←（取到 c[i,j-1] 时）或 ↑（取到 c[i-1,j] 时）
```

```text
追踪解 LCS(i, j)：                    // 初始调用 i = m, j = n
1  if i = 0 或 j = 0 then return      // 子问题长度为 0，序列为空，结束
2  if b[i,j] = ↖ then
3      输出 x_i                        // 末项被选入公共子序列
4      LCS(i-1, j-1)                   // 递归调用同样的算法
5  else if b[i,j] = ↑ then
6      LCS(i-1, j)                     // X 减少一
7  else
8      LCS(i, j-1)                     // 横向符号：Y 减少一
```

   * **算例：顺着箭头走出 BCBA**

       * 从表右下角出发：标记 ↑ 向上走 → ↖ 处取 $X$ 第 6 字符 a → 沿斜向移到左上 → ↑ 处只移动不取 → ↖ 处取 $X$ 第 4 字符 b → 斜向移动遇 ← 向左 → ↖ 处取 $X$ 第 3 字符 c → 继续追踪到 $X$ 第 2 位置的字符 b。

       * 选出 $X$ 的第 2、3、4、6 这四个字符，就是 BCBA，问题的解找到。

### 复杂度与解题链

   * **复杂度**

       * 赋初值 $O(m)+O(n)$；优化函数跟标记函数共 $mn$ 个值、每项三种可能选择且每种都是常数时间，计算花 $mn$ 量级。

       * 追踪每步至少缩小 1（缩 $X$、缩 $Y$ 或两个同时缩），至多 $m+n$ 步，工作量 $O(m+n)$。

       * 总时间 $O(mn)$；空间是备忘录 $mn$ 项，$O(mn)$。

   * **解题链**

       * 建模成组合优化问题 → 由 $i,j$ 两个后边界界定（两个不同序列的边界）→ 给出递推方程和初值 → 判定优化原则成立 → 给出算法伪码与追踪解的伪码（标记函数的设定是重要因素）→ 估计时间复杂度与空间复杂度（空间主要是备忘录大小）。

## 图像压缩

### 变位压缩与段头

   * **灰度存储**

       * 每个像素用灰度值表示，灰度值共 256 个（0～255），写成 8 位二进制数；按 8 位一律存储，一幅图占的存储位数是 $8n$——这是基准线。

       * 压缩动机：标记类图像大面积同色（这些地方像点灰度值同一个值）、有些地方灰度值本身很低用不着 8 位（1 位、2 位就存下）；视频是一连串图像，存储更大，更值得找更好的存储方法。

   * **变位压缩**

       * > **定义**：把灰度值序列分成 $m$ 个段，同一段里所有像素用相同的位数存、不同段可以不一样；每段开头附一个段头，记录本段像素个数与每像素位数，供恢复图像时逐段截取。

       * 为什么非有段头不可：存好以后是一串 0/1 序列，恢复时得知道第一段多少像素、每个多少位，才能一段一段按位数截取、恢复灰度值；段头后面跟的才是这段灰度值的二进制表达。

       * 段头固定 11 位：一段的像素个数上界是 256，记 1～256 需 8 位；每像素位数最多是 8，记这八个数需 3 位，$8+3=11$。

       * 第 $t$ 段有 $l_t$ 个像素、每像素占 $b_t$ 位，该段占 $l_t\cdot b_t+11$ 位；$b_t=\lceil\log_2(h_t+1)\rceil$，$h_t$ 是段内最大灰度值——「值加一、取对数、向上取整」正好覆盖 $0\sim h_t$ 共 $h_t+1$ 个取值；灰度最大 255，故 $b_t$ 不超过 8。

       * 整幅图总位数：$\sum_{t=1}^{m}l_tb_t+11m$（各段「位数×像素个数」之和，再加 $m$ 个段头开销）。

### 最优分段问题

   * **优化模型**

       * > **定义**：给定像素的灰度值序列，确定一个最优分段，在「每段像素个数不超过 256」约束条件下使总位数达到最少；最优分段方案就是解。

       * 段数权衡：段分得多，每一段都要付 11 位的额外开销——段里像素节省了位、段头却一段免不了；要的不是「这几种分法里最好」，而是所有可能分法里最好的。

   * **三种分法的账**（12 像素实例：开头 10、12、15，中间站着唯一的 255，后面跟 8 个很小的灰度值）

       * 两个极端都不讨好：段太少，小灰度值被大值拖着多付位；段太多，11 位一个的段头把省下的位又吃了回去。

| 分法 | 段数 | 段头开销 | 像素位数 | 总位数 |
| :--- | :---: | :---: | :---: | :---: |
| 三段：10,12,15 ｜ 255 ｜ 8 个小值 | 3 | 33 | 36 | **69** |
| 全一段 | 1 | 11 | 96 | 107 |
| 每像素一段 | 12 | 132 | 31 | 163 |

### 递推方程与伪码

   * **子问题与归约**

       * 子问题 $s(i)$：前 $i$ 个像素最优分段需要的最少存储位数；前边界不动（永远是 1）、后边界是 $i$，计算顺序从前到后（1 个、2 个……到 $i=n$ 即原始问题）。

       * 归约设想 $s(i)$ 的最优分段里最后一段有 $j$ 个像素：前面 $i-j$ 个像素自成一个子问题（后边界正好 $i-j$，查 $s(i-j)$）；最后一段按「段内最大灰度值加一、取对数、上取整」得每像素位数再乘 $j$；末了补上这一段 11 位段头。

$$s(i)=\min_{1\le j\le\min\{i,\ 256\}}\{\,s(i-j)+j\cdot b(i-j+1,\ i)+11\,\}$$

   * **位数函数、$j$ 的范围与初值**

       * $b(p,q)=\lceil\log_2(1+\max\{p_p,\dots,p_q\})\rceil$ 是第 $p$ 到第 $q$ 个像素这一段每像素要占的位数。

       * $j$ 最小是 1（最后一段只放 1 个像素）；最大受两条限制——段长不能超 256、整个序列不足 256 个像素时最多到 $i$，上限取 $\min\{i,256\}$。

       * 初值：$s(0)=0$（序列为空占 0 位）。

       * > **易错点**：$b(i-j+1,i)$ 只由最后这一段内部的最大灰度值决定，不是全序列的最大值；只有 255 恰好落进最后一段，每像素才按 8 位算——255 待在前面的段里时，最后一段照旧按自己的小位数存。

   * **伪码要点（枚举最后一段的长度）**

       * 常数和初值先立住：256 是段长限度、11 是段头位数、$s(0)=0$。

       * 主循环把后边界 $i$ 从 1 界定到 $n$，对每个 $i$ 做三件事：先做「最后一段只放 1 个像素」的第一个归约（该像素自己占的位数＋$s(i-1)$，归约成 $i-1$ 的子问题）；再把段长逐渐加长——2 个、3 个……到 256 或 $i$ 取小，新像素进入候选段时段内最大像素的位数跟着更新；每换一个段长算出候选「前面子问题的位数＋最后一段的位数」，更小就替换 $s(i)$ 并用新段长替换记录的 $l(i)$——这个标记留给解的追踪用。

       * 11 位段头对每个 $j$ 都一样，枚举时可以不急着加，最后统一补。

### 手算与解追踪

   * **六像素手算**（前五个子问题已算完：$s_1=15$、$s_2=19$、$s_3=23$、$s_4=42$、$s_5=50$，各自的最后一段长度 $l_1\sim l_5$ 也记录在案）

       * 枚举完成，保留下来的最好结果是 $s_6=57$ 位、最后一段只有 2 个像素；表里看得出分水岭——从 3 个像素起 255 进了段，每像素位数从 2 位跳到 8 位，这正是段不能贪长的直观道理。

| :--- | :---: | :---: | :---: |
| 1 | $2\times1+11=13$ | $s_5=50$ | 63 |
| 2 | $2\times2+11=15$ | $s_4=42$ | **57** |

   * **解的追踪**

       * $l(i)$ 存的是「后边界为 $i$ 的最优分段，最后一段的长度」；从后向前追踪：先取从后数第一个段（长度就是 $l(n)$），用总长 $n$ 减掉它更新待追踪长度，接着处理从后数第二个段……一路向前。

       * 追踪工作量 $O(n)$：总长度是 $n$，每做一次长度至少减 1，追踪次数不超过 $n$。

   * **完整流程与经验**

       * 流程：对变位存储问题建模（优化函数、约束「每段像素个数不超过 256」）→ 界定子问题边界（只有一个后边界）→ 列递推方程和初值（求解动态规划算法的关键）→ 伪码 → 标记函数与解的追踪（解要能从表里追回来）→ 时间复杂度。

       * 经验：追踪过程的复杂度通常不如计算过程高，往往计算过程的复杂度就是这个问题的总时间复杂度。

## 最大子段和

### 问题定义

   * **最大子段和（maximum subarray sum）**

       * > **定义**：给定 $n$ 个可以是负数的数 $a_1,\dots,a_n$，取某个连续段的数字之和（$i$ 是前边界最小可到 1，$j$ 是后边界最大可到 $n$）使和最大；如果和是负值就取 0 作为解：$\max\left\{0,\ \max_{1\le i\le j\le n}\sum_{t=i}^{j}a_t\right\}$。

       * 实例：最大的子段是从 11 经过 $-4$ 到 13 的那一段，这段连续数字加起来等于 20。

### 三种算法

   * **蛮力：$O(n^3)$**

       * 前边界 $i$ 从 1 取到 $n$、后边界 $j$ 从 $i$ 取到 $n$，两重循环共 $n^2$ 对边界；每对从 $a_i$ 到 $a_j$ 顺序求和花 $O(n)$；加完与已存的 sum 比，更大则替换 sum 并同时替换前、后边界。

   * **分治：$O(n\log n)$**

       * 从中间划开（划分位置 center 取中点），最优子段只有三种可能的住址：前后边界都在左部（leftsum，递归 1/2 规模子问题）、都在右部（rightsum，递归）、前边界在左部后边界在右部（跨边界，自己算）。

       * 跨边界段必踩 center 与 center+1：从 center 出发向左连续加、逐个比较保留最大，扫到 $a_1$ 得「从 center 向左连续」的最大和 $s_1$；从 center+1 向右扫到最后得 $s_2$；$s_1+s_2$ 就是跨边界的最大和——真正跨边界的段左半截必含 center、右半截必含 center+1，两截各自取最大，拼起来自然最大。

       * 三个值谁大谁是解；$T(n)=2T(n/2)+O(n)$，主定理解得 $O(n\log n)$，比蛮力的 $n^3$ 好很多。

   * **动态规划：$O(n)$**

       * 子问题界定：前边界都是 1、由后边界界定，共 $n$ 个子问题（后边界 1 到 $n$）。

       * 优化函数变通：$c(i)$＝必须包含 $a_i$、从 $a_i$ 向前连续的最大和 $=\max_{1\le k\le i}\sum_{t=k}^{i}a_t$——最长从 $a_1$ 一路加到 $a_i$，最短只含 $a_i$ 自己。

       * 递推 $c(i)=\max\{\,c(i-1)+a_i,\ \ a_i\,\}$：胜负全看 $c(i-1)$ 是负还是正——它是正的前一项显然更大、接着前一段继续加；它是负的前一段只会拖后腿、让 $a_i$ 自己单干。

       * 初值：$c_1=a_1$（$a_1$ 大于零时）；$a_1$ 小于或等于零时取零。

       * 解的得到：$c_1\sim c_n$ 可以一边计算一边比，最终保留的最大值正好是原问题的优化函数值；随时记下刷新最大值时的后边界供追踪。只有这一个循环、循环内全是常数操作，时间 $O(n)$、空间 $O(n)$。

       * > **易错点**：$c(i)$ 是「以 $a_i$ 结尾」的最大和，不是全局答案——算法要求的解前后两个边界都可动，而 $c(i)$ 把 $a_i$ 钉死在段尾；把 $c_1,\dots,c_n$ 全都算出来，从所有 $c$ 里取最大的那个才是要求的优化函数值，它的后边界才是解的后边界。

### 对比与经验

   * **三种算法对比**

       * 同一道题三种算法时间复杂度不在一个档次，动态规划最快。

| 算法 | 时间复杂度 |
| :--- | :---: |
| 蛮力 | $O(n^3)$ |
| 分治 | $O(n\log n)$ |
| 动态规划 | $O(n)$ |

   * **值得留意的设计经验**

       * 子问题界定：界定得简单（只有一个边界）才能保证子问题只有 $n$ 个、每个子问题计算时间是常数，复杂度才能降下来。

       * 优化函数可以和原始问题的优化函数不一样——做一下简单的变通；只要新定义的优化函数和原始问题的优化函数之间存在简单的依赖关系，把新函数全都计算出来之后就能很容易找到原问题的优化函数和它的值，这是本题最鲜明的特点。

       * 计算顺序自底向上、配一张备忘录式的存储表格；解的追踪方法要清楚（本题就是随时记下刷新最大值时的后边界）；复杂度估计比较简单（一个循环、常数操作）。

## 最优二叉检索树

### 概念与平均检索时间

   * **二叉检索树（Binary Search Tree）**

       * > **定义**：把排好序的数组元素 $x_1$ 到 $x_n$（如从小到大的 $n$ 个数）存储在一棵二叉树的节点上，通过与节点比较检索给定的 $x$：在就输出它在数组的哪个位置，不在就输出不在——「不在」正好反映在 $x$ 落到了空隙节点上。

       * 节点两种：圆节点是数据节点（对应数组里的数）；方节点是空隙节点（检索一旦到达就表示 $x$ 不在数组里）。$n$ 个数据节点配 $n+1$ 个空隙，从左到右覆盖「比 $x_1$ 还小（$x_0$ 可看作负无穷）」「$x_1$ 和 $x_2$ 之间」……「比 $x_n$ 还大（$x_{n+1}$ 实际上是正无穷）」。

       * 检索走法：初始 $x$ 与树根比较，小则进入左子树（左儿子当新根递归同样算法）、大则递归进入右子树、等于则停止输出位置；不管怎么走，$x$ 走到叶节点算法必停——输出 $x$ 不在数组里。

       * 检索 3.5 的实例：比树根 4 小进左子树、比 2 大进右子树、比 3 大进入 3 的右节点（树叶）停止——从左数落在第四个空隙，被检索元素处在 3 和 4 之间。

   * **比较次数的尺子**

       * 层数：从根到节点的路径上有几条边层数就是几，根节点的路径长度是 0。

       * 数据节点比较次数＝层数＋1：先和根比一次、到它这里再比一次才知道 $x$ 恰好等于它。

       * 空隙节点比较次数＝层数：只要和它的父节点比过就知道该进入这个空隙，空隙节点本身没有任何比较操作。

       * 记 $d_i$ 为数据节点 $x_i$ 的层数、$g_i$ 为空隙 $i$ 的层数，平均检索次数 $m=\sum_{i=1}^{n}(d_i+1)b_i+\sum_{i=0}^{n}g_ia_i$——「比较次数×概率」对全部节点求和。

   * **概率分布输入与两棵树的账**

       * 输入定型：$b_i$（$i$ 从 1 到 $n$）是 $x$ 是数组第 $i$ 个元素的概率，$a_i$（$i$ 从 0 到 $n$）是落进第 $i$ 个空隙的概率，$n$ 个数据位置加 $n+1$ 个空隙共 $2n+1$ 个概率值；问题的输入就是给定的数组加它的概率分布。

       * 元素出现在数组中的概率都一样时，把树组织成均衡的树是一棵好树；实际中被检索元素服从某种概率分布时均衡树未必好——树的形状得跟着概率走。

       * 六元素实例（$b_1\sim b_6$ 依次 0.1、0.2、0.2、0.1、0.1、0.05，七个空隙分摊剩下的 0.25）：均衡组织的树平均检索一个 $x$ 要 2.51 次比较；1 作根、整棵向一边歪的树要 3.25 次——同样的输入同样的概率分布，仅树的形状不同平均检索时间就差一大截。

       * > **定义**：最优二叉检索树（Optimal Binary Search Tree）——在给定数据集与概率分布下，平均检索时间最少的那棵二叉检索树。

### 子问题与归约

   * **子问题 $S_{i,j}$**

       * > **定义**：子问题由两样东西界定——数据集 $\{x_i,\dots,x_j\}$，加上与之对应的概率分布 $P_{i,j}$（原始分布中与这段数据相关的全部概率：数据节点的概率＋空隙节点的概率）；$i$、$j$ 两个参数划定了子问题的全部边界。

       * 原始问题相当于 $i=1$、$j=n$，即全部 $n$ 个输入数据构成的数据集 $S_{1,n}$；子问题的树是整个问题的解那棵大树里边的一棵子树。

       * 实例：五个字符 a、b、c、d、e，数据概率 0.1、0.3、0.1、0.2、0.1，空隙概率（a 左侧、a–b 间、b–c 间、c–d 间、d–e 间、e 右侧）0.04、0.02、0.02、0.05、0.06、0.01；截取 $S_{2,4}$ 的输入就是数据 {b,c,d} 配概率 0.3、0.1、0.2 及其周边空隙概率。

   * **归约：选定树根，劈出两个子问题**

       * 选第 $k$ 个元素 $x_k$ 作树根：比它小的、排在前面的 $x_i..x_{k-1}$ 归入左子问题 $S_{i,k-1}$，比它大的 $x_{k+1}..x_j$ 归入右子问题 $S_{k+1,j}$，各配自己的概率分布、独立求解。

       * 实例：a～e 里拿 b 当树根，左边实际上只有 a（左子问题 $S_{1,1}$，概率是 a 的概率加它两边空隙），右边是 c、d、e（右子问题 $S_{3,5}$）。

### 递推方程与初值

   * **先备好一个量：子问题的概率之和 $W_{ij}$**

       * > **定义**：$W_{ij}=(a_{i-1}+a_i+\cdots+a_j)+(b_i+b_{i+1}+\cdots+b_j)$——把子问题相关的所有概率（从 $a_{i-1}$ 到 $a_j$ 的空隙加从 $b_i$ 到 $b_j$ 的数据节点）加起来的总和。

       * 实例 $W_{2,4}$：数据节点 0.3、0.1、0.2 全加，空隙节点全加，合计 0.75——反映这个子问题在整个问题中所占有的概率成分。

   * **以 $x_k$ 为根的代价**

       * 记 $m_{ij}$ 为相对于输入 $S_{i,j}$ 和概率分布 $P_{i,j}$ 的最优二叉检索树平均比较次数；以 $x_k$ 为根时，代价是左边子问题的最优比较次数＋右边子问题的最优比较次数＋从 $i$ 到 $j$ 所有概率的总和。

       * $W_{ij}$ 项的来由：$m_{i,k-1}$、$m_{k+1,j}$ 是从子树自己的根向下检索的平均比较次数，一旦用 $x_k$ 合并成一棵更大的树，检索就得从 $x_k$ 出发多走一层——左、右子树里每个数据节点和空隙节点深度都加一，「每人多一次比较」乘以这棵子树占的概率，就是它对工作量的影响。

       * 正式算账：左子树 $m_{i,k-1}$ 添上 $1\times W_{i,k-1}$；右子树 $m_{k+1,j}$ 添上 $1\times W_{k+1,j}$；根是新增节点——第一次比较就命中它的概率是 $b_k$，乘一次比较。把概率部分按定义展开：空隙项拼起来正好是 $a_{i-1}+\cdots+a_j$、数据项拼起来正好是 $b_i+\cdots+b_j$，恰为 $W_{ij}$（与 $k$ 无关）。

$$m_{ij}^{(k)}=m_{i,k-1}+m_{k+1,j}+W_{ij}$$

$$m_{ij}=\min_{i\le k\le j}\{\,m_{i,k-1}+m_{k+1,j}+W_{ij}\,\}$$

   * **初值：边界上的空子树**

       * $m_{i,i-1}=0$ 反映取边上节点作根的两种极端：以最左元素为根（左子树为空）或以最右元素为根（右子树为空），都落在这一形式上。

       * > **易错点**：初值是空树 $m_{i,i-1}=0$，不是单节点；只含一个数据节点的子问题 $S_{i,i}$（如 $m_{1,1}$）不是初值，要由递推方程算出——以它唯一的节点为根时左右都是空树、两项取零，值就是概率之和。

### 实例演算与复杂度

   * **以 b 为根的实例演算（从小到大一层层算）**

       * $m_{1,1}=0.1+0.04+0.02=0.16$：以 a 为根，左子树、右子树都空，值就是概率之和。

       * $m_{3,3}=0.1+0.02+0.05=0.17$、$m_{5,5}=0.1+0.06+0.01=0.17$（c、e 各加两边空隙）；以 d 为根：$m_{3,5}=0.17+0.17+0.54=0.88$（0.54 是 c、d、e 的概率 0.1、0.2、0.1 加周边四项空隙概率）。

       * 合到根上：$m_{1,5}=m_{1,1}+m_{3,5}+W_{1,5}=0.16+0.88+1=2.04$——此时已是原始问题，所有概率加起来恰好等于 1。

       * 验证：按定义直接算（每个数据节点取深度加一、每个空隙节点取深度，工作量乘概率逐节点求和）同样是 2.04，与按递推方程算出的完全一样。

   * **复杂度与流程**

       * 子问题个数：$i,j$ 都在 1 到 $n$ 之中选择，组合是 $n^2$ 量级；每个子问题在 $i,j$ 固定后要对 $k$ 遍历 $i$ 到 $j$ 之间的所有树根候选、$O(n)$ 工作量——算法工作量 $O(n^3)$，多项式时间算法。

       * 空间复杂度正好是备忘录的大小：$n^2$ 格。

       * 标记函数：记下 $S_{i,j}$ 取得最少比较次数时以哪个节点为根（那个 $k$），将来可以追踪出这棵树的结构。

       * 计算顺序：从只有一个数据节点的最小子问题算起，然后连续两个、连续三个挨着的数据节点……所有子问题从小到大迭代。

## RNA 二级结构预测

### 问题描述与配对规则

   * **RNA 二级结构预测（RNA secondary structure prediction）**

       * > **定义**：输入是一级结构——由 A、U、C、G 碱基按实际排列顺序排成的核酸序列，不同字符代表不同碱基；输出是折叠后的二级结构平面图——哪些位置的碱基互相配对，辫和环都画在图上。

       * 背景：RNA 的一级结构是一条长链，实际中不能存在，需折叠成二级结构——链上某些位置的碱基按规则互相匹配、亲合到一起，形成一段段的「辫」；预测出结果之后还可以通过生化的办法检测验证。

   * **四条配对规矩**

       * 配对种类：只能 U 和 A 配对、C 和 G 配对；U 和 C、A 和 G 不能配。

       * 末端不允许出现尖角：$i$ 到 $j$ 配对时中间至少要含三个元素——隔三个元素（$j-i=4$）允许，隔四、五个都可以；只隔一、两个不可以，头上的环不能太小，条件写成 $j-4\ge i$。

       * 每个核苷酸只能参与一个配对：不能一个核苷酸既和这个配又和其他的配。

       * 不允许交叉：平行着配可以——连续的平行配对正好体现在一条辫上；交叉着配不行。

```text
平行配对（允许，连续平行配对构成辫）        交叉配对（不允许）

i             j                         i              j
o-------------o                          \            /
|             |                           \          /
|             |                            \        /
o-------------o                             o------o
i+1          j-1                            k      l
```

       * 结构词汇：连续的一段平行配对是一条辫；辫的头上的那种结构叫发夹环；两条辫之间夹出来的环叫内环。

### 优化模型

   * **从最小自由能到最多配对**

       * 生物学条件：具有最小自由能的结构是稳定的；建立数学模型时简化成——匹配的对数达到最多就认为是稳定结构。

       * 问题定型：给定一条 RNA 链（一级结构），求具有最多匹配对数的二级结构——采取什么样的匹配方法使匹配对数达到最大，那个结构就认为是解。

### 归约与递推方程

   * **子问题与归约**

       * 边界由链的前位置 $i$、后位置 $j$ 决定（$i<j$），这段序列记作 $S_{i,j}$，最大匹配对数记作 $C_{ij}$。

       * 情形一：$j$ 和前面某个位置 $k$ 的碱基配对（满足配对种类）——根据不交叉原则，跨过这条匹配边去配对就不再允许：右边 $k+1$ 到 $j-1$ 只能自己跟自己配，左边 $i$ 到 $k-1$ 也只能自己跟自己配；一个归约动作劈出两个子问题 $S_{i,k-1}$ 与 $S_{k+1,j-1}$。

       * 情形二：$j$ 不参与配对——把这个节点不考虑，整个 $i$ 到 $j$ 的匹配问题看作 $i$ 到 $j-1$ 的匹配问题，归结成长度减一的子问题。

   * **递推方程**

       * $j$ 不参与匹配取子问题的值 $C_{i,j-1}$；$j$ 和第 $k$ 个碱基匹配时，左右两段的最大匹配对数相加、再加上 $j$ 本身这一对匹配的 1：

$$C_{ij}=\max\Big\{\,C_{i,j-1},\ \max_{i\le k\le j-4}\big(C_{i,k-1}+C_{k+1,j-1}+1\big)\Big\}$$

   * **$k$ 的候选与初值**

       * $k$ 要考虑 $j$ 前面所有满足匹配要求的位置：最大到 $j-4$、最小到 $i$，且那个位置的字符和 $j$ 的字符满足 U–A 或 C–G；哪个对数最多取哪个。

       * 初值：$j$ 跟 $i$ 的距离小于四的话它们不能匹配，优化函数值为零：$C_{ij}=0$（$j-i<4$）。

       * > **易错点**：中间隔三个元素意味着 $j-i=4$（$i$ 和 $j$ 之间夹着 $i+1,i+2,i+3$ 三个碱基），所以允许配对的条件是 $j-i\ge4$——容易错写成「$j-i>4$」或「$j-i\ge3$」；递推中 $k$ 的上界 $j-4$ 也由此定。

### 复杂度与标记函数

   * **复杂度**

       * $i$ 和 $j$ 的组合有 $n^2$ 种可能（原始问题长度 $n$），子问题 $n^2$ 个；每个子问题 $j$ 给定后要考察 $k$ 在 $i$ 到 $j-4$ 之间所有可能位置、$O(n)$ 个——整个工作量 $O(n^3)$。

       * 问题满足优化原则；计算顺序按子问题的长度排，从小到大陆续顺序迭代——还是自底向上，从最小的子问题算起。

   * **标记函数**

       * 记下得到最优匹配对数时到底是怎么归约的：$j$ 到底和哪个 $k$ 进行了匹配、还是不参与匹配——把这个最优划分的位置记录下来，将来才能把二级结构画出来。

       * 备忘录记录最优匹配对数的表格。

## 构造问题的流程对照与检查单

   * **两道构造问题的同一张图纸**

       * 界定子问题、找归约、列递推方程和初值、排计算顺序、设标记函数、算复杂度——这套动态规划设计流程在两道构造问题上各走一遍，环节逐项对应见下表。

| 设计环节 | 最优二叉检索树 | RNA 二级结构预测 |
| :--- | :--- | :--- |
| 界定子问题 | 数据区间 $S_{i,j}$ 及其概率分布 $P_{i,j}$ | 碱基区间 $S_{i,j}$ |
| 归约方法 | 选 $x_k$ 作树根，劈成左右两个子问题 | 看 $j$ 与谁配对：配则劈成两段，不配则缩成 $S_{i,j-1}$ |
| 递推方程 | $m_{ij}=\min_k\{m_{i,k-1}+m_{k+1,j}+W_{ij}\}$ | $C_{ij}=\max\{C_{i,j-1},\ \max_k(C_{i,k-1}+C_{k+1,j-1}+1)\}$ |
| 初值 | $m_{i,i-1}=0$（空子树） | $j-i<4$ 时 $C_{ij}=0$（够不着配对） |
| 计算顺序 | 自底向上，子问题从小到大 | 按子问题长度从小到大迭代 |
| 标记函数 | 记下取最优时的树根 $k$，追踪树结构 | 记下 $j$ 的匹配位置（或不匹配），画出结构 |
| 复杂度 | 时间 $O(n^3)$，空间 $O(n^2)$ | 时间 $O(n^3)$ |

   * **动手前的检查单（解任何动态规划问题通用）**

       * 界定子问题：用什么参数来界定子问题的边界。

       * 找归约方法：动态规划利用的是子问题之间的依赖关系——怎么把当前要解的问题归结成更小的子问题。

       * 列递推方程和初值：较大的问题的优化函数值怎样依赖于更小子问题的优化函数值；最小的子问题它的优化函数值是什么。

       * 定计算顺序：子问题按照什么样的顺序、从小到大迭代计算。

       * 设计标记函数：为了求得问题的解是不是需要做标记、标记函数怎么设计。

       * 分析时间复杂度。
