# C 语言基础：编译工具链与控制流

## 编辑环境与命令行界面

### 图形界面与命令行界面

* **图形用户界面（Graphical User Interface，GUI）**
    * > **定义**：以图标、按钮等图形元素呈现、靠点击操作的用户界面。
    * 集成开发环境整体属于 GUI；最左侧的活动栏本质上是一种现代化菜单，可用来打开和关闭各种功能。
* **命令行界面（Command-Line Interface，CLI）**
    * > **定义**：靠输入命令而非点击操作的用户界面。
    * 命令提示符按惯例显示为 `$`，与货币无关，只表示"请在此处输入命令"；有的系统用 `^` 或 `>`，含义一样。
    * GUI 窗口内可以嵌一个终端窗口，窗口底部那个 `$` 就是 CLI。
    * 软件世界基本分成 GUI 和 CLI 两类，一个软件可能同时具备两种界面。
* **Visual Studio Code（VS Code）**
    * 代码写在右上区域的标签页里，一个标签页对应一个代码文件。
    * 文件名的 `.c` 扩展名表示这是 C 语言代码。
    * 语法高亮会在已知语言的代码里自动给不同部分着色，颜色本身不必留意。
    * 左侧文件资源管理器列出逐步创建的文件和文件夹。
    * 减少鼠标和点击、多用键盘打字，一开始会像退步，但多数程序员发现这样效率更高。

### 快捷操作

* 按 `Ctrl+L` 或输入 `clear` 清空终端屏幕，不影响程序功能，只是保持屏幕整洁。
* 输入已存在的文件名的前几个字母再按 `Tab` 键自动补全，前提是该文件确实存在。
* 连按上方向键翻看历史输入过的命令。
* 在编辑器里输入变量名和左方括号后，编辑器会弹出自动补全并把光标定位到该输数字的位置，这是编辑器提供的便利，与 C 语言本身无关。

## 编译与运行链路

### 三条命令

* **`code hello.c`**
    * 在 VS Code 中创建一个名为 `hello.c` 的新文件标签页，随后即可用键盘开始写代码。
    * 文件名只用小写字母且完全不含空格，会比习惯用空格和大写更便于操作。
* **`make hello`**
    * 把源代码编译成机器码。
    * 只写 `hello` 而不重复写 `hello.c`：编译器会自动在当前目录寻找同名的 `.c` 源文件。
    * 编译后没有任何输出通常是好现象；编译时冒出输出信息一般意味着出了问题。
* **`./hello`**
    * 运行刚生成的可执行程序，中间的斜杠表示程序保存在当前文件夹里。
    * 重新修改源代码后必须重新编译，否则运行的还是几分钟前生成的旧机器码。
* 文件名不必叫 `hello`，改成任何名字都可以，但文件名与命令里对应的词必须保持一致。
* `make` 会读取源文件的全部内容，并把它转换为一个程序。
* `hello` 不是一条命令，它是编译出来的程序文件。
* > **注意**：删掉源文件、只留着编译产物没有意义；反过来，只写源代码而从不编译，程序在桌面上不会变成可双击运行的图标。

### 四个步骤

* **预处理**
    * 把头文件的内容直接复制粘贴进你的代码，非常暴力，但省掉了重复写声明的劳动。
* **编译**
    * 把预处理后的代码转换成汇编代码。
* **汇编**
    * 把汇编代码变成实实在在的 0 和 1；产物文件默认叫 `a.out`，`a` 取自 assembler，`out` 是输出。
* **链接**
    * 把你的代码、CS50 库代码、标准输入输出库代码三段二进制拼在一起。
    * 缺 `-lcs50` 这类参数时会出现一串链接报错，因为编译器找不到该去硬盘哪个位置取库文件。
* 完整链路是预处理、编译、汇编、链接；程序员为图省事统称为"编译"。
* > **提示**：知道这几个词的差别，报错时才能读出是哪个环节出了问题。

### 汇编与指令集

* **汇编代码（assembly code）**
    * > **定义**：中央处理器（Central Processing Unit，CPU）能够理解的最低层级指令，CPU 就是英特尔、AMD、苹果这类公司造出来的核心运算部件。
    * 这是 C 和 Python 出现之前程序员写代码的方式：更早是拿打孔卡在大型计算机上直接输入 0 和 1，汇编仍嫌繁琐才有了 C，C 仍嫌繁琐才有了 Python 这样的高级语言。
    * 汇编代码里仍能看到 `main`、`get_string`、`printf` 这些名字，再往下是一串移动、压栈、异或、调用之类的指令。
* > **注意**：生成的汇编代码模式是针对特定 CPU 架构的。同一段 C 代码为 iPhone 编译和为安卓编译，输出的指令集不一样，所以不能把 Mac 的程序拿到 PC 上跑，反过来也不行。
* 分层的价值在于让分工成为可能：不同团队可以分别实现预处理器、编译器、汇编器、链接器，甚至分别写针对不同架构的编译器，而所有人仍然在上层用同一种语言编程。
* 并非所有语言都要编译：JavaScript 的源代码直接从网络服务器发到浏览器，因此任何网站的源代码都能查看。
* > **易错点**：⚠️ 逆向工程不可能完美还原。`for` 和 `while` 在功能上完全等价，选哪个更多是风格问题，最终生成的二进制模式完全相同，凭 0 和 1 根本看不出源代码原本长什么样；逆向所需的时间比正向开发长得多，通常直接重新开发一个反而更省时。

## 命令行文件操作

### 常用命令

* Linux 命令行最常用的一批命令，它们都短得不能再短：
* | 命令 | 作用 |
  | :--- | :--- |
  | `ls` | 列出当前文件夹中的内容 |
  | `mkdir` | 创建一个新文件夹，也就是目录 |
  | `rm` | 删除目录，或删除文件 |
  | `mv` | 移动文件，重命名也用它 |
  | `cp` | 复制文件 |
  | `cd` | 切换目录，也就是进入另一个文件夹 |
  | `code` | 用编辑器打开文件或目录 |
* `rm` 会先向你确认删除原因：
    ```text
    $ rm hello
    remove regular file 'hello'? Y
    ```
* `mv` 的第一个词是源文件，第二个词是目标位置，所以 `mv hello.c hello` 后面要跟两个词。
* > **易错点**：在目标路径末尾加一个斜杠写成 `mv hello.c hello/`，可以明确表示想把文件放进文件夹，而不是把 `hello.c` 重命名为 `hello`；不过目标文件夹已存在时，不加斜杠通常也能被正确识别，系统会自动判断意图。
* `mv` 不必一条专门的 `rename` 命令：对同一目录里的两个文件名使用 `mv` 就直接完成重命名。

### 路径与目录

* `.` 是一个特殊表示法，指当前文件夹；`..` 表示向上移动一级。没有三个点、四个点这种表示法。
* 输入 `cd` 后直接按回车可以回到默认文件夹，也就是主目录；每次登录云端环境都从这里开始。
* 命令提示符会一直显示当前所在的文件夹路径，让你随时知道自己身处哪个目录，不必额外输入命令去问系统。
* `ls` 输出中的文件夹带高亮颜色并在末尾加一个斜杠，与普通文件区分开。
* 文件和文件夹可以存在于不同位置，但不能在同一位置重名，那会产生冲突，在 Mac 或 PC 上同样如此；把一个文件夹放进另一个文件夹里则完全没问题。
* 图形界面里的右键新建、重命名、拖放，在命令行里都有对应命令，效果完全一样。
* 目录形态示例，左边是刚编译完的样子，右边是搬走之后：
    ```text
    ~/pset3/
    └── hello/                 ← 文件夹
        ├── hello.c            ← 源码
        └── hello              ← make 编译出来的可执行程序

                              mv hello.c ../ 之后 ↓

    ~/pset3/
    ├── hello/                 ← 文件夹（空了）
    │   └── hello              ← 可执行程序还在
    └── hello.c                ← 已经搬到上一层
    ```
* `ls` 输出的可执行文件带一个星号标记，表示它是一个可以运行的程序而不只是普通文件；文件资源管理器里看不到这个标记。
* 用星号 `*` 作为所谓的通配符，可以一次性打开文件夹里的所有文件，还能使用更精确的匹配模式。

## 程序骨架与转义序列

### 程序骨架

* **`#include <stdio.h>`**
    * `stdio.h` 是标准输入输出头文件，`printf` 就在这个文件中定义。
    * 这一行的作用是告诉编译器：请从另一个名为 `stdio.h` 的文件中包含 `printf` 的定义。
    * > **易错点**：⚠️ 是 `stdio.h` 而不是 `studio.h`，写成 studio 是网上非常常见的错误。漏掉这一行会报"调用了未声明的库函数 `printf`"，后面跟着一长串晦涩的类型描述，即使代码其他部分完全正确。
* **`int main(void)`**
    * 相当于 Scratch 里"当绿旗被点击"的触发帽：启动程序，本身不产生输出。
* **`printf("hello world\n");`**
    * 相当于 Scratch 里紫色积木中的白色椭圆 say "hello world"：函数本质上是一个动作或动词，在代码中完成一小段工作。
    * `printf` 中的 `f` 代表 format，即格式化打印，它比单纯打印原始文本更强，严格说它做的是"输出"。
    * 用左右括号包裹内容，括号里放要打印的文本。
    * 双引号明确界定内容的起止范围，表明这里不是某个特殊的函数或变量。
    * 结尾加换行符 `\n`，让光标移到下一行。
    * 最后用分号结束语句，就像英语中的句号。
* 函数概念与数学中的函数一致：接收某个输入，通常产生一个输出。
* **副作用（side effect）**
    * > **定义**：由函数调用产生的可见效果，比如显示在屏幕上或从扬声器播放出来。
    * 这通常是短暂发生的事件。
* 向函数传递参数时，有时不只能得到副作用，还能拿到一个有用且可重复使用的**返回值**。

### 转义序列

* **转义序列（escape sequence）**
    * > **定义**：由反斜杠开头的特殊符号组合，能实现一些不同寻常的效果。
    * | 转义序列 | 效果 |
      | :--- | :--- |
      | `\n` | 把光标移动到新的一行 |
      | `\r` | 回车符：把"打印头"移回左侧起始位置，是水平移动而非垂直移动 |
      | `\"` | 输出一个双引号字符本身 |
* `\r` 指的就是老式打字机把打印头移回左侧的过程。
* `\"` 用来解决歧义：双引号内直接连续写引号无法分辨哪个引号对应什么内容，要输出真实的引号字符就得转义。
* 反斜杠本身已有特殊含义，想打印一个反斜杠也需要相应的解决方案。
* 换行符可以脱离任何字符单独输出，本身就是一个可以独立打印的转义序列。
* > **易错点**：不知道 `\n` 的人可能想直接按回车把代码挪到下一行。这违背了大多数编程语言基于行的基本原则——一个完整的逻辑表达应在一行内开始并完成；而且把一句话的一部分硬挪到下一行，看起来也很马虎。

### 占位符与参数

* 写 `printf("hello answer");` 语法上没问题，逻辑上却错了：计算机严格按字面执行，会原样输出 hello answer。
* 解决办法是先输出固定部分再留一个占位符 `%s`，表示写代码时还不知道内容的字符串，运行时被实际内容替换。
* 引号内的逗号只是英语文本的一部分，引号外的逗号才有实际意义，它区分了第一个参数和第二个参数。
* 函数可以接收 2 个、3 个甚至 4 个参数，完全取决于函数设计时预期接收的参数数量。
* 两个参数都是"输入"，区别只在来源：第一个由程序员事先提供，第二个来自用户，因此用变量和占位符来承接。

## 库与文档

### 库与头文件

* **库（library）**
    * > **定义**：他人编写的代码，可以直接在自己的程序中使用。
* **头文件（header file）**
    * 扩展名是 `.h` 而不是 `.c`，包含他人编写的代码。
    * 只有在使用课程提供的函数时，才需要包含课程库的头文件；单纯打印输出并不需要。
* **CS50 库**
    * 提供 `get_string`、`get_int`、`get_char` 等一系列辅助函数，用于获取用户输入。
    * C 语言本身并没有内置这些函数，命名成 `get_string` 就是为了清楚表达功能。
    * 库函数内部也可能调用 `printf` 输出提示信息，查阅文档即可知道，不必自己再调一次。
    * `get_char` 会强制限定你获取的数据类型：如果用户输入了多个字符，函数会要求用户重新输入，反复提示直到配合，因此调用方不必处理这类错误检查。
    * `get_int` 同样会隐式拒绝非法输入并反复重新提示，但"整数"本身范围极广，它不会排除负数这类类型合法却语义上无意义的输入。
    * 库中没有提供 `get_bool`——获取一个真或假的值通常不实用，原本可以设计但决定不这么做。
    * 这种做法本质上是站在前人肩膀上：通过使用写好的函数快速实现实用功能。

### 手册页

* **官方手册页（man pages）**
    * 查找 C 语言信息的标准做法就是查官方手册页，但它们大多写于几十年前、面向资深程序员，不适合初学者。
* **课程整理的手册页**
    * 把所有公开文档资源整合并大幅简化，用接近助教讲解的语言呈现，对不习惯读手册页的人实用得多。
    * 按头文件分类，列出课程中常用的一系列函数，并筛选成更精简的版本。
    * 标准结构自上而下依次是：函数名、概要说明（Synopsis）、它被定义在哪个头文件里、函数原型、描述、示例代码。
    * 取消勾选"较难理解"的选项即可看原始、更晦涩的文档版本。
    * `Standard I/O` 头文件下大约有六七个函数，`printf` 用于在屏幕上输出内容，其他函数还涵盖打开文件、关闭文件等标准输入输出相关功能。
* 人工智能助手同样依赖官方文档这类原始资料，养成主动查文档的习惯和本能。

### get_string 的写法

```c
string answer = get_string("你叫什么名字？ ");
```

    * 函数名就表明它返回一个字符串，提示语用双引号括起来，表明这不是特殊的独立单词。
    * 提示语末尾留一个空格，是把光标从问号旁稍微挪开。
    * 提示语里问号后加一个空格，光标会稍微向右移动，看着舒服一些。
    * 括号后直接用等号接上要存放返回值的变量名，等号左边写变量名。
    * 变量名按惯例用小写字母、不包含空格，与文件名的约定一致。
    * 与 Scratch 的"询问并等待"积木对应，那里的参数"并等待"表示会一直等到用户输入完毕。
    * 这种把输入、赋值、输出缝在一条语句里的琐碎细节，正是从图形化语言过渡到 C 时需要慢慢内化的部分。

## 数据类型与占位符

### 基本类型

* 在 C 里给变量起名字不够，还必须告诉编译器打算存放什么类型的值。
* | 类型 | 装的是什么 | 位数与范围 | 占用字节 |
  | :--- | :--- | :--- | :--- |
  | `bool` | 真 / 假 | 只有两个值 | 1 |
  | `char` | 单个字符 | 不含多个字母或单词 | 1 |
  | `float` | 浮点数（实数） | 32 位，约 40 亿种可能 | 4 |
  | `double` | 双精度浮点数 | 64 位，精度翻倍，仍是有限值 | 8 |
  | `int` | 整数 | 32 位，约正负 20 亿 | 4 |
  | `long` | 长整型 | 64 位，范围大得多，但仍有限 | 8 |
  | `string` | 字符串 | 每字符 1 字节，末尾另加一个终止字节 | 取决于内容 |
* `bool` 占满 1 个字节有点浪费，真或假技术上只需 1 个位，但直接占整字节反而更高效方便，其中 7 个位闲置。
* `int` 32 位时无符号最大约 40 亿；一旦要表示负数，就得在正负范围之间做平衡分配，范围缩到约正负 20 亿。
* `long` 是 `int` 的两倍，含负数时可表示的取值数量大出十几个数量级。
* `char` 专门用来存单个 ASCII 字符，占 1 个字节。
* `string` 占多少完全取决于实际存了什么，存 4 个字符的词和存 5 个字符的词数字不一样。
* > **注意**：无论 32 位还是 64 位，比特数量有限就意味着可表示的数值有上限；实数有无穷多个，所以能在代码中表示的数字数量与实际存在的数字数量之间存在根本性的不匹配。

### 格式说明符

* **占位符（格式说明符）**
    * | 占位符 | 对应类型 |
      | :--- | :--- |
      | `%s` | 字符串 |
      | `%c` | 单个字符 |
      | `%f` | 浮点数，也能用于 `double` |
      | `%i` | 整数 |
      | `%li` | 长整型（`long`） |
* 占位符不止 `%s` 一种，每种可存储的类型都有对应的写法。
* `printf` 以及课程提供的 `getchar`、`get_int`、`get_string` 都留了占位符，可以把值填进提示语一起显示。
* `%f` 后跟一个小数位数字（例如写成 `.50`）可以控制显示多少位有效数字。

## 内存

### 字节画布

* 内存条上的黑色芯片里塞满了用来存放 0 和 1 的空间，可以把内存想象成一张按字节编号的画布；假设芯片是 1GB，就能从 0 编到 10 亿。
* > **注意**：一个 4 字节的值在内存中是连续紧密排列的，不能随意挑几个散落在各处的比特位凑数；`long` 和 `double` 则是 8 个字节排在一起。
* 硬件本质上只是一块拥有大量可用字节的空间，可以从第一个字节寻址到最后一个字节；屏幕上看到的换行只是视觉呈现，计算机本身没有上下左右的空间概念。
* 编译器基本上已经处理好变量在内存中的存放位置，编程时不必自己操心。
    ```text
    address  ->    0        1        2        3        4        5        6        7
                  ┌────────┬────────┬────────┬────────┬────────┬────────┬────────┬────────┐
                  │        │        │        │        │        │        │        │        │
                  └────────┴────────┴────────┴────────┴────────┴────────┴────────┴────────┘

    char  c = 'H' [   'H'   ]
    int   i = 72   [   72    ][        ][        ][        ]
    long  l = 72   [   72    ][        ][        ][        ][        ][        ][        ][        ]
    ```
* 三个 32 位的分数变量 72、73、33 总共占 12 字节，每个值 4 字节。
* 每个变量实际就是由 32 个 0 和 1 组成的二进制序列，三组序列共同构成了那些数字。
* 当变量数量膨胀到 30 个、300 个时，逐个声明独立变量这种粗糙感，往往就是判断设计好坏的标准。

### 数组

* **数组（array）**
    * > **定义**：一块连续的内存，其中的元素一个接一个紧密排列。
    * `int scores[3];` 拆开看是：请创建一个名为 `scores` 的变量，分配能容纳三个整数的空间。
    * 方括号里指定这块内存要存多少个整数，类型和数组名写在前面，这一行会自动分配 12 字节，全部通过 `scores` 这一个名字引用。
    * 只有一个变量，只是通过索引访问它的不同位置，位置 0、1、2。
    * 下标从 0 开始计数，因为计算机领域通常从 0 开始计数。
    * 命名用复数形式更合理。
    * 想调整元素总数，只要改方括号里的数字。
    * 逐个手动赋值或逐个获取是代码重复，本质上和复制粘贴完全相同，应该交给 `for` 循环：
      ```c
      const int N = 3;

      int scores[N];
      for (int i = 0; i < N; i++)
      {
          scores[i] = get_int("Score: ");
      }
      ```
* 数字被硬编码在两个地方（数组大小和循环次数）时要靠人的自觉保证一致，声明成常量后只需在一处修改。
    ```text
    scores  ┌────────┬────────┬────────┬────────┐
            │   72   │        │        │        │   <- scores[0]
            ├────────┼────────┼────────┼────────┤
            │   73   │        │        │        │   <- scores[1]
            ├────────┼────────┼────────┼────────┤
            │   33   │        │        │        │   <- scores[2]
            └────────┴────────┴────────┴────────┘
            4 bytes   4 bytes   4 bytes
    ```

### 字符与字符串

* **字符就是数字**
    * 字符型变量 `'H'`、`'I'`、`'!'` 在内存中很可能连续排列成 72、73、33。
    * 用 `%c` 打印它们得到 `HI!`；把 `%c` 换成 `%i` 并加上空格，就得到 72、73、33 这三个熟悉的老朋友。
    * 这里没有使用显式的类型转换：编译器和 `printf` 足够智能，传入字符类型的值时它们本质上已经知道这会被视为整数，实际上是通过格式说明符隐式转换的。
    * 字符用单引号，字符串用双引号。
* **字符串就是字符数组**
    * `string s = "HI!";` 在内存中的布局与三个 `char` 变量完全一样，只不过这里只有一个变量，指向内存中的 3 个字节。
    * 编译器会自动用一个由 8 个 0 位组成的模式终止双引号里的任何字符串；这个 8 位全 0 的字节叫**空字符（Null Character，NUL）**，专业写法是 `\0`。
    * `\0` 类似于 `\n`，是一种特殊的转义字符，指 8 个 0 位，而不是屏幕上想看到的数字 0；ASCII 表里字符 0 就是 NUL。
    * 长度为 3 的字符串在内存中实际占用 4 个字节，这一切都是双引号自动完成的。
    * `printf` 使用 `%s` 时并不知道该打多少字符，很可能是在内部用一个循环，从第一个字符开始输出、再下一个，直到遇到结尾。
    * 每一个字符串都各自带着一个属于自己的终止字节，编译器会为每一个都补上。
    * > **易错点**：⚠️ 访问 `s[3]` 看到的那个 `0` 正好落在终止字节上，说明 NUL 存在；但这次访问已经越界，程序行为并不可靠。
    ```text
    s = "HI!"  ┌────────┬────────┬────────┬────────┐
               │  72 'H'│ 73 'I'│  33 '!'│    0   │  <- '\0' = NUL
               └────────┴────────┴────────┴────────┘
               s[0]    s[1]    s[2]    s[3]
    ```

## 变量与运算符

### 运算符

* **运算符（operator）**
    * | 运算符 | 怎么读 | 含义 |
      | :--- | :--- | :--- |
      | `=` | 等于 | 赋值：把右边的值复制到左边的变量里 |
      | `==` | 等于 | 相等判断：两边是否相等 |
      | `!=` | bang equals | 不等于 |
      | `<` `<=` | 小于、小于等于 | 左边是否小于／不大于右边 |
      | `>` `>=` | 大于、大于等于 | 左边是否大于／不小于右边 |
      | `\|\|` | 逻辑或 | 两个条件中任意一个为真即可 |
      | `&&` | 逻辑与 | 两个条件都必须为真 |
      | `+` `-` `*` `/` | 加减乘除 | 一个命令完成一次操作 |
      | `%` | 取模 | 求余数 |
* "大于等于"和"小于等于"只需连续按两次对应按键就能输入 `<=` 与 `>=`，不必去翻符号表。
* 设计者为了减少按键次数，把"不等于"定成两个字符的 `!=` 而不是"不等于等于"三个字符。
* > **易错点**：⚠️ 在 Scratch 里一个等号就表示相等判断，因为它是给儿童用的、没有这种混淆；但在 C 和大多数编程语言中，单个 `=` 是赋值，双等号 `==` 才是相等。这是纯粹的历史原因，不是随手定的。
* **逻辑运算符（logical operator）**
    * > **定义**：把一个布尔表达式拆分为两个更小的布尔表达式，并且只需要其中任意一个条件为真即可。
    * `||` 在键盘上的位置因美式、英式或其他布局而异。
    * 判断字符是否同意要用 `||`：同一个变量不可能同时既是小写字母又是大写字母，用 `&&` 会让表达式永远为假、产生程序错误。

### 变量的声明与自增

* 指定变量的类型和名称，实际上是在计算机内存中的某个位置创建了这个变量，指定类型是必要的步骤。
* 如果只是想稍后重新使用并修改一个已经存在的变量，只写变量名即可，再次指定类型显得多余，因为 C 已经知道它的类型。
* 单纯计数用 `int` 就够，那 20 多亿的取值范围完全够用。
    ```c
    int counter = 0;
    counter = counter + 1;
    counter += 1;
    counter++;
    ```
* `counter = counter + 1;` 并不表示相等关系：单个等号表示赋值，含义是把右侧的值复制到左侧变量中，先算出结果再写回 `counter`。
* `+= 1` 与 `++` 效果完全一样，只是省按键，这种写法在 C 中非常普遍。
* > **注意**：没有 `+++` 或者 `++++` 这种更多加号的写法，`counter++` 仅用于把单个变量的值递增一。
* 想一次加 2、加 3 时，`counter = counter + 2` 这种冗长写法反而更清晰；递减同理。
* **常量（constant）**
    * 在类型前加上 `const` 关键字，表示这个值永远不应被改变，后续试图重新赋值编译器会直接拦下。
    * 按惯例和代码风格，常量用全大写字母命名，让别的程序员一眼看出它确实不可更改。
    * 把同一个数字硬编码在多处是糟糕的设计：要么自己会犯低级错误，要么同事根本没意识到你在多个地方硬编码了同一个值。
    * > **提示**：代码里出现两次以上的东西，就该给它一个名字。
* 只打算使用一次的中间变量通常不值得专门创建；不过如果命名后确实更易读（比如叫 `sum` 而不是随手一个字母），可以算净收益。

## 条件分支

### 基本形态

* **条件语句（condition）**
    * > **定义**：程序里的岔路口，让你根据一个布尔表达式的答案决定执行这个、那个还是其他操作。
* **布尔表达式（Boolean expression）**
    * 用小于号得到的结果不是数字，而是一个布尔值：要么是真，要么是假。
    * 布尔变量本身也只能取真或假两个值。
* `if` 加一个空格再跟一对圆括号，圆括号里放布尔表达式，条件为真时执行花括号里的代码。
* > **注意**：`if` 后面这对括号和函数调用毫无关系。`if` 不是函数，而是 C 语言中实现条件语句的关键字，就像 Scratch 里的橙色积木块，是语言本身的功能特性。
* > **提示**：花括号并非总是必需的，只有一行代码时技术上可以省略；但课程里提倡统一的编码风格，缩进对齐 4 个空格，让协作编程的成员写出风格一致的代码，避免每个人的习惯不同而把代码弄得混乱不堪。
* 条件分支里缩进 4 个空格，在逻辑上表明这行代码仅在满足条件时才会执行。
* `if` 加 `else` 就是 if-else 分岔：条件成立走一边，否则走另一边。

### 三问变两问

```c
if (x < y)
{
    printf("X is less than Y\n");
}
else if (x > y)
{
    printf("X is greater than Y\n");
}
else
{
    printf("X is equal to Y\n");
}
```

* 这里用的正是那个已经见过的单个等号，和把 `get_string` 的返回值存进变量时一样。
* 几十年前程序员决定用等号表示赋值，因为视觉上合理，尽管代码的阅读方向是从右到左；发现冲突后，相等判断只能改用两个等号。
* 如果逻辑上只有三种可能性，实际上只需要检查其中两种：前两个判断都不成立，就只剩下相等这一种可能。
* 问第三个问题只是在浪费计算机的时间，进而也浪费了用户的时间。
* > **易错点**：不要把三个判断写成三个互相独立的 `if` 依次排列。三个条件在逻辑上互斥，但这样写无论实际情况如何都会全部检查一遍，第一个条件已经满足后仍然继续问"那么 X 大于 Y 吗""X 等于 Y 吗"。
* 只保留一个 `if` 加一个 `else` 输出"X is not less than Y"也能覆盖剩下两种情况，但输入相同值时输出不够精确。

### 决策树

* 几乎任何代码块都可以转换成流程图，**菱形代表布尔表达式**，也就是条件语句的起点。
* 只有一个 `if` 时，条件为假就意味着没有代码处理那种情况、直接结束；这里并不存在一个叫 "stop" 的关键字。
* `if` 加 `else` 之后流程图上出现了"快捷路径"：第一个问题为真就很快完成，第一个问题为假才再多问一个问题。
    ```text
              开始
                |
           [ x < y ? ]
             /     \
           是        否
            |         |
       "X is less    +-- [ x > y ? ]      ← 只在"否"的分支上继续追问
        than Y"        /         \
            |        是           否
            |         |            |
            |   "X is greater   "X is equal
            |    than Y"         to Y"
            |         |            |
            +---------+------------+
                       |
                      结束
    ```
* 检查完前两个问题后就可以直接输出"X is equal to Y"，因为从逻辑上这必然成立；"X 等于 Y 吗"这个条件不需要检查。
* 这种逻辑流程图正是代码中的缩进和语法结构所要表达的核心意图。
* 循环的条件判断也能画成同样的树：条件为真回到顶部继续执行，为假则结束。

### 字符比较

```c
char c = get_char("Do you agree? ");

if (c == 'Y' || c == 'y')
{
    printf("Agreed.\n");
}
else
{
    printf("Not agreed.\n");
}
```

* 对于只需回答"是"或"否"的情况，获取单个字符就足够了，不需要读取整个字符串。
* > **易错点**：比较字符用的是单引号。单字符用 `char` 类型配单引号；由多个字符组成的文本（单词、句子、段落）用字符串类型配双引号。
* 分开写 `if (c == 'Y')` 和 `if (c == 'y')` 两个分支会有完全一样的输出语句，跟复制粘贴没什么区别；想改提示信息就得改两遍，这种重复本身就是糟糕的设计。
* 把 `if (c == 'y') ... else if (c == 'n')` 里的第二个 `if` 改成 `else` 并默认处理其他情况更高效：不给任何答复就默认最坏的情况，即不同意。
* `get_char` 遇到用户不配合而输入多个字符时会要求重新输入，所以输入 `no` 根本不会生效，测试时看到的现象并非程序逻辑错误。

## 循环

### 三种循环的取舍

* **`while` 循环**
    * > **定义**：条件写在循环体前面，"先问再做"；条件为假就退出，为真就执行循环体并回到条件判断。
* **`do-while` 循环**
    * > **定义**：条件写在循环体后面，"先做再问"；正因为如此，不管条件一开始是否为真，循环体至少会执行一次。
* **`for` 循环**
    * 把初始化变量、检查条件、循环后更新三件事写进一行，语法稍难记，但代码更少，是循环特定次数时更常见的编程惯例。
    * > **提示**：编程中的惯例通常是从 0 开始计数、一直递增到目标值但不包含该值本身，这样屏幕上至少能同时看到循环的起点和终点。
    * | 结构 | 执行顺序 |
      | :--- | :--- |
      | `while` | 判断条件 → 假则退出，真则执行循环体 → 回到判断条件 |
      | `do-while` | 执行循环体 → 判断条件 → 真则回到循环体，假则退出 |
* C 语言中没有 `repeat` 关键字，也没有 Scratch 里那种"永久循环"积木块，但 `while` 完全能满足需求：放一个永远为真的表达式即可，编程惯例是直接写 `while (true)`。
* `while (true)` 加 `break` 跳出来虽然可行，但 C 里有一种循环天生就是给这种情况用的。
* `do-while` 适合"至少做一次"的场景：至少要问用户一个问题，一次都不问程序就没有意义。
* 把条件整体取反写成 `!(N < 0)` 逻辑上完全一样，但读代码的人得多绕一下，宁可多花一行把意图讲明白。
* > **注意**：无论是有意还是无意，一旦出现无限循环，长时间不停输出会让代码空间占用率飙升、CPU 使用率异常，完全失去对环境的控制。解决问题的答案就是按下 `Ctrl+C`。
* 循环固定次数很常见，所以严格来说并不一定非得用 `while`；用 `get_int` 把次数交给用户决定后，条件里的常数换成变量即可。

### for 循环的等价性

```c
int i = 0;
while (i < 3)
{
    printf("meow\n");
    i++;
}

for (int i = 0; i < 3; i++)
{
    printf("meow\n");
}
```

* `for` 的第一个分号之前是初始化变量，接着检查条件；成立就执行花括号内的代码，然后自动执行第二个分号右边的操作。
* 两种做法效果完全一样，只是 `for` 的第一行包含了更多"魔法"，比实际需要写的代码多一些，而这正是更常见的编程惯例。
* 从 3 往下减到 0 或从 0 往上加到 3 都是合法的计数方式，只要布尔表达式与自增方向匹配。
* 从 1 数到 3 也可以把条件写成"小于 4"或"小于或等于 3"，但这样得琢磨"小于 4"到底是什么意思，反而困惑。

### 嵌套循环

* 水平方向和垂直方向都单独处理过，把两者组合进同一个问题还是第一次，打印 3×3 的井号网格就是这种组合。
* 思路顺着老式打字机：打印完一行砖块，回到起始位置，再打印下一行，而 `printf` 一直在做的就是这个逐行输出。
    ```c
    const int n = 3;

    for (int row = 0; row < n; row++)
    {
        for (int column = 0; column < n; column++)
        {
            printf("#");
        }

        printf("\n");
    }
    ```
* 换行那句 `printf("\n")` 放在**内层循环之后、外层循环体之内**：挪进内层循环里，每一列之后都换行，就又变回竖着的一列；放到外层循环外面，三行会挤成一行。
* > **易错点**：换行是整个循环的收尾动作，不该在循环体里反复执行。循环体里少写一个 `\n`，输出形状就从一行变成一列；多写一个 `\n` 就反过来。
* > **提示**：把 `i`、`j` 改名成 `row`、`column` 仅仅是改变变量名称，不会产生任何功能上的影响，但可读性是实打实的收益。
* > **注意**：最好不要让内层循环的变量与外层循环的变量重名以免混淆。`i`、`j`、可能再加 `k` 通常可行，但一旦开始用 `l`、`m`、`o` 这样的名字，很可能说明代码设计本身有问题。
* 嵌套循环在逻辑上实现的正是"行里包含列、列、列、列"这个模型。

### continue 与 break

* **`continue`**
    * > **定义**：回到循环开头，再次执行完全相同的操作。
* **`break`**
    * > **定义**：跳出循环，并继续执行与该循环对应的花括号之后的代码。
* 反复询问直到用户输入正确值的逻辑应该写在循环里，而不是在下面再写一遍同样的判断和同样的输入调用；那样的重复代码没有尽头，你打算给用户多少次机会。
* 只关心"非负就跳出"时，反转逻辑判断写成单个 `break` 即可，同时使用 `continue` 和 `break` 会让代码量变成实际所需的两倍。

```c
int n;

while (true)
{
    n = get_int("N's value? ");

    if (n >= 0)
    {
        break;
    }
}
```

* 更好的做法是自己实现一个只收非负整数的函数，把输入验证和重复提示都封装进去：
    ```c
    int get_n(void)
    {
        int n = get_int("n? ");

        while (n < 0)
        {
            n = get_int("n? ");
        }

        return n;
    }
    ```
    * 签名里的 `int` 表示返回一个整数，而返回值正是这个函数存在的全部意义。
    * 循环体里不直接操作 `n`，只是再问一次，这就是输入验证加重复提示的逻辑。
    * `return n;` 把结果交出去，函数结束。

## 作用域与函数

### 作用域

* **作用域（scope）**
    * > **定义**：由于 C 语言的工作原理，一个变量仅存在于声明它的那一对花括号内。
* 变量只在声明它的花括号之间有效，其他函数根本看不见它。
* 循环内部声明、循环外部使用时，编译器会报 `use of undeclared identifier` 之类的错误：
    ```text
    cat.c:19: error: use of undeclared identifier 'N'
    ```
* > **易错点**：⚠️ 先声明，后赋值。把 `int n = get_int(...)` 写在循环内部却在循环外使用 `n`，编译器就会报"未声明的标识符"。解决办法是把声明单独新起一行移到花括号外部，让作用域覆盖整段代码。
* 单独写 `int n;` 只是创建了这个变量但没有赋值，里面存储的值是未知的；随后再引用变量名给它赋值即可。

### 函数

* **函数签名（function signature）**
    * `void meow(void)`：第一个 `void` 表示不返回任何值，括号里的 `void` 表示不接受任何输入，什么都不收、什么都不返。
    * `void meow(int n)`：自己定义函数、让它接收一个或多个输入时，同样要为这些参数指定类型和名称；括号内不需要分号。
    * `int get_n(void)`：第一个 `int` 表示返回一个整数。
* **函数原型（function prototype）**
    * > **定义**：给编译器的一个提示、一个承诺——后面会有一个叫这个名字的函数，签名如上，末尾以分号结尾。它本身不含任何实现，完全基于信任。
    * C 编译器严格按字面意思、从上往下解析代码，读到第 9 行时函数还不存在就是错误，即便定义就在文件底部它也不肯往下翻。
    * 报错形式是"调用了未声明的函数"，后面跟着一堆相当晦涩的内容。
    * 一般把 `main` 放在文件开头是合乎情理的，但其他函数全堆在顶部会把 `main` 挤得越来越靠下；解决办法是把函数签名单独加上分号复制到上方。
* **注释（comment）**
    * 在 C 里任何以斜杠开头的内容都只给人看、不给计算机看，就像 Scratch 里的便签，是提醒自己、TA 或同事"这几行在干嘛"用的。
* **参数与返回值**
    * 调用时传进去的名字和函数内部接住的名字可以不一样，完全取决于设计选择：你传入的是一个值，函数内部可以给它起一个完全独立的名字。
    * 取一个直接说明用途的名字（如 `times` 而不是到处都用 `n`）更清晰。
    * `meow` 接收参数、没有返回值，只有副作用；`get_n` 不接收参数、有返回值，没有副作用。这是两种完全不同的形状。
* 编程很大程度上是把想法抽象化：解决一次之后就能反复复用、复用、再复用，甚至打包成库让别人也能用。
* 把底层细节抽象出来、最终创建自己的函数，这就是模块化代码。

## 代码质量的三个维度

### 三个维度

* | 维度 | 它在问什么 | 谁能给你打分 |
  | :--- | :--- | :--- |
  | 正确性 | 代码跑出来的行为，是不是预期的行为 | `check50` |
  | 设计 | 有没有白白浪费机器的时间、浪费用户的时间 | 助教当面评估、discussion、`design50` |
  | 风格 | 别人读不读得动：缩进齐不齐、变量名像不像人话 | `style50` |
* 正确性在课程背景下指代码是否按习题集的要求执行；在现实世界中，它意味着完全按照产品经理、CEO 等决策者所确定的软件功能来执行，行为符合预期仅此而已。
* 行为符合预期和设计好不好完全是两件事：有的代码逻辑上百分之百正确，却问了太多不必要的布尔表达式，既浪费计算机的时间也浪费用户的时间。
* 设计更像现实世界中的考量：英语里不仅要把话说对，还要说得漂亮，要提出一个有力、有说服力的论点，而不仅仅是碰巧正确的论点。
* 风格更多关乎代码的美学：排版是否美观、缩进是否整齐，变量命名是否恰当而不是随手写成 `x`、`y`、`z`。
* > **提示**：风格真正影响的是其他人，而不是计算机——但对其他人来说很重要。
* 这种粗糙感往往就是判断设计好坏的标准：到学期末变量数量会越来越多，前辈们早就想出了更好的办法。
* 能优化的代码就应该去优化，代码中反复出现这样的微优化会带来显著的累积效果。

### 打分工具

* **`check50`**
    * 用在每个问题集任务中，运行时指定一个 **slug**（作业题目的唯一标识符），即可快速获得关于正确性的反馈。
    * 它只是提交优质代码的第一道关卡，并不说明实现得好、设计出色或风格优雅。
* **`design50`**
    * 打开程序标签页点一下即可，像 ChatGPT 一样给出改进建议。
    * 不验证代码正确性，只评估设计与质量；这部分更为主观，标准模拟优秀助教可能给出的反馈。
* **`style50`**
    * 左栏显示当前的代码样式，右栏展示应有的规范样式。
    * 确保代码符合课程教学要求，并与官方风格指南保持一致。
    * 在典型企业环境中通常也有一套官方风格指南或工具供所有开发者遵循，这样即使每个人的解决方案各不相同，最终呈现的风格仍能保持统一。
* > **提示**：判断"难以阅读"这个说法听起来合理，但设计往往是主观的，并没有一成不变的硬性规定，有些助教未必认同；代码可读性才是最重要的。

## 数值边界

### 整数溢出

* 系统以 8 位、16 位、32 位或 64 位为单位分配比特，每个数值能用的比特数量是有限的。
* **整数溢出（integer overflow）**
    * > **定义**：试图存储一个过大的数值时发生的溢出。
    * 32 位约能表示 40 亿种可能，带上负数后范围缩到约 20 亿。
    * 最高位是 1 在某种表示方式下意味着"数字本身是负数"，溢出的表现就是回绕：那个 1 最终让数值回到零。
    * 连续翻倍时先看到负数（发生了回绕），再看到 0（确实回到了零），这两种表现同时出现。
* 解决办法是换一个更大的类型：改用占 64 位的 `long`，能给出的范围大得多，但占位符也要跟着换成 `%li`，不能再用 `%i`。
* 即便换成 64 位，位数有限就意味着上限依然存在，只是长整型也能被连续操作撑爆。
* 这不只是玩具问题，在现实世界中确实会发生。
    ```text
    3 个比特（3 个灯泡 / 3 个晶体管）能表示的范围：

        位置    2   1   0
         7      1   1   1
         6      1   1   0
         5      1   0   1
         4      1   0   0
         3      0   1   1
         2      0   1   0
         1      0   0   1
         0      0   0   0

      8  →  需要第 4 个比特。没有它，8 就只能是 0。
    ```

### 截断与浮点精度

* **截断（truncation）**
    * > **定义**：只要使用的还是整数类型，小数点后面的部分都会被直接丢弃。
    * `1 / 3` 显示 0，`2 / 3` 显示 0 而不是 0.66，`3 / 3` 恰好正确，`4 / 3` 显示 1 而不是 1.33。
* 求平均分时 `(72 + 73 + 33) / 3` 得到 59，数学上应该是 59.13，那三分之一的分值被整数除法截掉了。
* **浮点精度问题**
    * 即使把类型改成浮点，`1 / 3` 打印出来也是 `0.333333333333333314829616256247390992939472198486328125` 这样一长串末尾数字，与小学课堂上学到的知识完全相反。
    * 根源是计算机只能用有限数量的比特，而浮点数可能有无限种数值，所以它无法精确表示所有可能的浮点数；我们看到的本质上是近似值。
    * 除了增加比特位数（例如用双精度代替单精度），或至少尝试检测并处理这种情况，没有其他根本性解决方案；在科学计算、金融等对精度要求极高的领域尤其关键。
* 把格式代码从 `%i` 换成 `%f` 之后仍会报"格式说明符要求 double，但传入的参数是 int"，因为 `%f` 显示的是 `double`。
* > **提示**：只要运算中涉及到一个浮点数，整个表达式就会被"提升"为浮点运算，不会停留在整数计算上。因此把分母写成 `3.0` 就能让那三分之一的分值回来，不必把每个数字都转一遍。
* 也可以用类型转换强行指定：把每个操作数写成 `(float) score1`，或把分母写成 `(float) 3`；结果大致相同，也仍会看到一点浮点精度问题。
* 函数里求平均时如果 `return` 语句用的是整数除以整数，又会遭受整数截断；把累加变量改成浮点数或用类型转换把长度也转成浮点数即可解决。

### 现实中的溢出

* 航空业中飞机通常要保持**连续供电 248 天**，这是行业常态：时间就是金钱，航空公司希望飞机尽可能多地在空中飞行，连夜间也不关机。
* 报道称一架波音 787 在持续供电 248 天后出现问题：所有交流电源可能中断，因为多个发电机控制单元同时进入了故障安全模式。
* 根源是发电机控制单元内部的一个软件计数器在持续供电 248 天后发生溢出，当时正在开发软件升级来解决这个安全隐患。
* 短期方案是关机再重启，就像处理手机、电脑等偶尔出问题的电子设备那样：重启时所有变量都重置为默认值，代码从上到下顺序执行，变量重新归零，问题解决。
* 更精确地说，根源很朴素：可能使用了 32 位整数并包含负值，实际可用的只有 31 位用于计数正数，248 天大约对应以十分之一秒为单位的计数上限。
* **Y2K 问题**：几十年来为图方便，计算机一直只用两位数字表示年份而不是四位，1999 年跨入 2000 年时，位数不足的系统很可能把 2000 年误判为 1900 年。
* **2038 问题**：系统通过计算自 1970 年 1 月 1 日以来经过的秒数来记录时间，所有相关计算都基于这个起始日期。
* 《吃豆人》存在一个历史性漏洞：由于缺少一个检查当前关卡的 `if` 条件，玩家最多只能玩到**第 255 关**；超出后屏幕显示乱码，同样是整数溢出，能打到第 256 关反倒成了一种荣誉的象征。
    ```text
    1970-01-01              0  秒
          ...               每经过 1 秒，计数器 +1
          ...
    2038-01-19   2147483647  ← 2^31 - 1，32 位有符号整数的上限
                        ↓ 溢出
                      归零、回绕
                        ↓
            系统把当前时间误认为  1901-12-13
    ```
* > **提示**：248 天和 2038 是同一件事的两副面孔，一个把电源关掉，一个让时钟回到 1901 年；知道这两个日期比死记它们的定义更有用。
