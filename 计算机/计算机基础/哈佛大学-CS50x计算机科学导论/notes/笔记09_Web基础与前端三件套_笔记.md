# Web 基础与前端三件套

## 网络与数据包

### 网络、互联网与 ARPANET

* **网络（network）**

    * > **定义**：计算机之间的互联，无论是有线还是无线。

    * 家庭网络、学校网络、公司网络各自独立存在。

* **互联网（internet）**

    * > **定义**：这些网络再互相连起来所构成的全球性互联，覆盖计算机、服务器、设备以及许许多多别的东西。

    * 世界上几乎任何地方都能找到并路由数据。

* **ARPANET**

    * > **定义**：互联网最初的形式，约始于 1969 年，即高级研究计划局网络。

    * 它是美国国防部的一个项目，目的是把当时数量极其有限的超级计算机连起来。
    * 起因是那些年代超级计算机在地理位置上对许多研究人员根本够不着。
    * 最初只有加州大学洛杉矶分校和另外少数几个节点互相连接。
    * 仅仅大约一年之后，东海岸的哈佛、麻省理工等机构也加进来了。

### 路由器与数据包

* **路由器（router）**

    * > **定义**：一台计算机，负责把数据向上、向下、向左、向右地路由。

    * 路由既发生在地理上，也发生在实际物理连接上。
    * 现实世界里数据可能从这根线出去，也可能从那根线出去，或者从别的线出去。

* **数据包（packet）**

    * > **定义**：信息的载体；它足够小，可以被拆开走不同的路，又带着足够多的地址信息，能被独立地送到终点。

    * 比喻是邮政寄信用的小小白色信封，国内国际都寄。
    * 路由的对象就是数据包：把人想象成路由器时，每个人扮演的正是网络里的一个设备。

* **包交换**

    * 不需要一条预先铺好的专属通路。
    * 只需要一个会转发的中间人网络，剩下的事数据包自己扛。

### 多路径与非最短路由

* **路径的多样性**

    * 一个从发送方到接收方的数据包可能经过任意多个路径节点。
    * 它可以先向上再向左，也可以先向左再向上，甚至可以走之字形、绕来绕去。
    * 无论是有线还是众多无线连接，数据从起点到终点都存在多条可能的路径。

* **不一定走最短路**

    * 数据可能选成本最低的路径。
    * 也可能只是某些人工设置、或者服务器自动配置出来的路由规则的结果。

## IP 协议

### IP 地址与点分十进制

* **IP（Internet Protocol，互联网协议）**

    * > **定义**：其核心作用是为全球每台联网设备分配一个独一无二的地址。

    * 对应现实世界中的实体地址，唯一标识符理论上能让一个信封从全球任何地方准确寄到。
    * IP 协议做的事情就是确保每个人都有唯一的 IP 地址，数据可以通过这个地址发出去或发到这里。
    * 服务器只能靠 IP 协议**寻址**计算机，无法区分收到的包是网页、邮件、聊天还是视频会议片段。

* **点分十进制**

    * IP 地址是一个数字，通常用「某数.某数.某数.某数」的格式表示。
    * 每一段的值都在 0 到 255 之间。
    * 0 到 255 一共 256 种可能，而 $256 = 2^8$，所以每一段是 8 比特。
    * 四段加起来就是 $8 \times 4 = 32$ 比特。

* **服务器（server）与客户端（client）**

    * 服务器是一台**向他人提供信息的计算机**，可以同时处理电子邮件、聊天、视频会议、游戏服务器等多件事。
    * 客户端是通常只服务个人而非很多人的笔记本或台式机。
    * 两者本质上都还是计算机。

### IPv4 与 IPv6

* **IPv4**

    * > **定义**：一个 IPv4 地址是 32 比特，上限是 $2^{32}$，粗略估计为约 40 亿。

    * 这个数字直接限制了全球能接入的设备总数。
    * 一个人至少就有手机和笔记本两台设备，再加上智能家居等物联网设备只会更多。

* **IPv6**

    * > **定义**：使用 128 位的地址空间，大到足以满足可预见未来的所有需求。

    * 全球正逐步从 IPv4 过渡到 IPv6，但这个过渡已经讨论了大概二三十年，到今天还在逐步推进。

### IP 数据报结构

* **IP 数据报（datagram）**

    * > **定义**：一个数据包的**实际结构**，直接来自定义 IP 数据报的技术规范文档。

    * 本质是一个由比特组成的网格：总共表示 32 个比特，索引从第 0 位排到第 31 位。
    * 每一行都代表另外 32 个比特，逐行叠加直到排满 32 位。
    * 归根结底只是一串按特定模式发送的比特流，并且有一份正式的规范文档。

* **源地址与目标地址**

    * 源地址写在信封的**左上角**，即发送方自己的 IP 地址，好让对方知道该回复给谁。
    * 目标地址写在信封中间，即接收方的 IP 地址，信封才能寄到他手上。
    * 数据报里还包含大量其他有用的比特信息。

* **IP 数据报的比特布局**

    ```text
       0    1    2    3    4    5    6    7    9  ...  30   31
     +----+----+----+----+----+----+----+----+ ... +----+----+
     |               这一行是 32 比特                              |  ← 第 0 行
     +----------------------------------------------------------+
     |               同样的 32 比特 × N 行，直到第 31 位          |
     +----------------------------------------------------------+

     +----------------------------------------------------------+
     |  源地址 5.6.7.8        发送方自己的 IP 地址               |
     +----------------------------------------------------------+
     |  目标地址 1.2.3.4      接收方的 IP 地址                   |
     +----------------------------------------------------------+
     |  ……还有大量其他有用的比特信息                             |
     +----------------------------------------------------------+
    ```

## TCP 协议

### 端口号

* **TCP（Transmission Control Protocol，传输控制协议）**

    * > **定义**：让计算机能够唯一地标识**它向外界提供的服务**，即在 IP 地址之外再加一层可区分服务的标识。

    * 有了它，一台计算机才能区分发来的包是电子邮件、聊天消息、视频会议片段还是别的什么。
    * TCP 通过在信封外部做记录管理来确保数据可靠送达。

* **端口号（port number）**

    * > **定义**：同样是数字，附加在 IP 地址之后，用来标识一台机器上对外提供的具体服务。

    * 通常在 0 到 $10^3$ 或几千以内，并且这些数值是**标准化**的。
    * TCP 额外附加了 **16 个比特**来指定端口号，因此实际可以有**数万个**可能的端口号。
    * 端口号只是当年一群人在某个会议室里决定用来标准化流程的任意数字。

* **80 与 443**

    * 用 HTTP 协议请求网页时，信封外部会自动标上**端口 80**。
    * 用 HTTPS（URL 里的 S 代表 secure）时，实际使用的是**端口 443**。
    * 在这些信封外部，除了 IP 地址之外还有端口号、源端口、32 比特序列号等信息。

* **源端口**

    * 写在信封的左上角，接收方靠它回复。

* **信封上的字段**

    ```text
    +--------------------------------------------- 目标地址 1.2.3.4 --+
    |  +---- 目标端口 443（紧跟在 IP 地址之后）                        |
    |  +---- 源端口（发送方写在左上角，接收方靠它回信）                |
    |  +---- 32 比特序列号                                             |
    |  +---- 另外 16 个比特用来指定端口号，所以端口总数数以万计       |
    +---------------------------------------------------------------+
    ```

### 序列号与分片

* **序列号（sequence number）**

    * > **定义**：一个 32 位的值，写在信封的左下角，用于让接收方核对与重组。

    * 在互联网上发消息时数据量通常很大，一次性塞进一个巨大信封会妨碍其他用户同时使用互联网。
    * 接收方能从序列号推断出是否收齐，例如反馈「我缺少第 1、2、3 个包，请重发」。
    * 序列号之外还能实现数据优先级处理等其他功能。

* **分片与重组**

    * 把一个大文件拆成多个分片，分别封装、分别传输。
    * 分片陆续到达目的地时，接收方计算机依据序列号核对并重组。

* **两条协议的分工**

    * IP 让我们能唯一地**标识计算机**。
    * TCP 确保数据**可靠传输**，并允许在同一台设备上**复用多种服务**。

* **分片的信封**

    ```text
       信封 1                  信封 2                  信封 3
      +-------------+        +-------------+        +-------------+
      |  左下角     |        |  左下角     |        |  左下角     |
      |  序列号 1/4 |        |  序列号 2/4 |        |  序列号 3/4 |
      +-------------+        +-------------+        +-------------+

      信封 4
     +--------------+
     |  左下角      |
     |  序列号 4/4  |
     +--------------+
    ```

## DNS 与 DHCP

### 域名解析

* **DNS（Domain Name System，域名系统）**

    * > **定义**：一种把域名翻译成对应 IP 地址的服务器。

    * 每个家庭实际上都拥有一台，即使你可能没意识到——它集成在家用路由器里。
    * 每个校园、每家公司也各有一台，全球有无数台。
    * 设备在刚启动时**根本不知道**对应的 IP 地址，厂商不会在设备里预装几十亿个 IP 地址。

* **域名的价值**

    * 人们访问的是 Google.com、Harvard.edu 这样的**域名**，对人比数字地址好记得多。
    * 从技术上讲这些名称叫**完全限定域名**。

* **查询与标注**

    * 设备向家庭、校园或工作场所的**本地网络**发出查询：「这个域名的 IP 地址是多少？」
    * 拿到答案后，设备实际执行的操作就是把对应的 IP 地址标注在数据包的「信封」外部。

* **DNS 服务器的对照表**

    ```text
       +-------------------------+-------------------------+
       |  域名                   |  IP 地址                |
       +-------------------------+-------------------------+
       |  google.com             |  某个 32 比特数字       |
       |  harvard.edu            |  某个 32 比特数字       |
       |  ...（全世界的域名）    |  ...（对应的地址）      |
       +-------------------------+-------------------------+
    ```

### 域名注册与租赁

* **域名注册商（registrar）**

    * > **定义**：提供域名租赁服务的机构，付一笔钱就获得该域名的使用权。

    * 本质是一种**租赁服务**，按年租也行，一次性租 3 年、5 年也行。
    * 费用可能低至每年 1 美元，也可能高达每年数千美元，取决于域名有没有被别人抢注或被人囤积。
    * 付钱之后还需要在技术层面配置全球某处的 DNS 服务器，让它指向真正为你提供网页的服务器 IP 地址。

### 根服务器与递归缓存

* **根服务器（root server）**

    * > **定义**：全球分布的服务器，掌握着所有 `.com`、`.edu` 等顶级域名的信息。

    * 本地电脑并不知道这些信息，所以通常先问本地网络：在家问集成在路由器里的小盒子，在学校问学校的 DNS 服务器。

* **递归与缓存**

    * 整个设计是**递归**的：本地服务器不知道答案，查询就一路提升到根服务器，拿到结果后把结果**缓存起来**。
    * 答案沿路返回，沿途每一台 DNS 服务器都会记住它。
    * 归根结底它做的事就是一张庞大的域名与 IP 地址对照表，服务器在为我们做查询响应。

* **解析路径**

    ```text
       [你的 Mac / PC / 手机]
              │  「google.com 的 IP 是什么？」
              ▼
       [本地网络里的 DNS]
       家里：集成在家用路由器里的小盒子
       校园：学校的 DNS 服务器
              │  我也不知道 → 继续往上问
              ▼
       [根服务器]  掌握 .com / .edu 等顶级域名的信息
              │
              ▼  答案沿路返回，沿途每一台都把它缓存下来
       google.com  →  1.2.3.4
    ```

### DHCP 自动配置

* **DHCP（Dynamic Host Configuration Protocol，动态主机配置协议）**

    * > **定义**：自动响应设备配置请求的服务，解决「我的 IP 是什么、DNS 和网关在哪」这一组问题。

    * 它并非从一开始就存在；过去必须**手动**配置一切：手动输入电脑的 IP 地址（通常还是别人口头告诉的）、手动输入 DNS 服务器地址、手动输入路由器网关地址。
    * 如今它已普遍部署在家庭网络、校园网和企业网络中。
    * 设备首次启动时会广播一条「Hello world，我的 IP 地址是什么？」式的请求，本地网络中通常就有一台 DHCP 服务器在运行。

* **DHCP 下发的三项配置**

    * 你的 IP 地址是多少。
    * 本地路由器的 IP 地址是什么。
    * DNS 服务器的 IP 地址是多少。

    > **提示**：正因为有了 DHCP，今天只要连上 Wi-Fi 或者插上网线，设备就能自动配置好并开始正常工作。

## URL 结构

### 协议与端口

* **URL 的作用**

    * 帮我们**定位到正确的地方**。
    * 一个典型的 URL 由协议、主机名、顶级域名、路径四部分拼成。

* **协议（scheme）**

    * 通常是 `https`，它通过某种方式实现了安全加密；当然也可能是 `http://`。
    * `https://` 对应 443 端口并加密传输，`http://` 对应 80 端口并明文传输。
    * 浏览器在输入 `http://` 的情况下会自动把你重定向到该网站的安全版本。

* **URL 的组成**

    ```text
       https      www.example.com                     /file.html
       └─ 协议 ─┘  └───── 主机名 ─────┘  └─ 顶级域名 ┘  └── 路径 ──┘
    ```

### 主机名与顶级域名

* **主机名（hostname）**

    * > **定义**：URL 左侧的**具体服务器名称**，许多 URL（但并非全部）包含它。

    * 它不一定非得是字面意义上的一台服务器，`www` 可以指代数十、数百、乃至数千台服务器。
    * 输入一个热门网站域名，实际指向的可能是由**数百甚至数千台服务器组成的集群**。
    * 集群的设计正是为了确保能够处理所有可能访问该网站的用户流量。

* **顶级域名（TLD，Top-Level Domain）**

    * `.com` 代表商业用途，是顶级域名的典型例子。
    * 过去的顶级域名种类非常有限：`.gov`（政府）、`.com`（商业）、`.net`（网络）、`.org`（组织）、`.edu`（教育）。
    * 如今顶级域名的数量已经大幅增加——即使没有上千种，至少也有数百种。
    * 有些如今已经是完整的单词，有些则用两个字符表示它所属的国家。

* **国家代码顶级域名**

    * `.io` **并不是**指输入输出（Input/Output），它实际上是一个双字母的国家代码域名，本质上已被租用为通用顶级域名。
    * `.tv` 原本属于某个国家的域名，但在英语中恰好和 "television" 的缩写撞上了，于是也被广泛用作相关领域的顶级域名。

### 路径与根目录

* **根目录**

    * 访问 `https://www.example.com/` 时，实际上是在请求该网站的**根目录**，也就是默认文件夹。
    * 那个斜杠表示的就是请求获取默认网页。
    * 按惯例这个文件通常被命名为 `index.html`，也可能是 `index.htm` 或别的名字。
    * 服务器默认直接返回根目录的内容，也就是网站的默认页面，免得每次都要手动敲文件名。

* **路径（path）**

    * 域名后面通常跟一个完整的路径，可以包含零个或多个文件夹名，加上零个或一个文件名。

    ```text
       file.html              只指定一个文件
       folder/                只指定一个文件夹
       folder/file.html       文件夹 + 文件
    ```

## HTTP 请求与响应

### 请求与响应信封

* **HTTP（Hypertext Transfer Protocol，超文本传输协议）**

    * > **定义**：一种请求网页、接收网页内容的通信协议，主要对网络通信中数据报文的**内容格式**做了标准化。

    * 它通常使用 80 和 443 端口。
    * 电子邮件有邮件专属的协议，各类互联网服务都有自己的协议标准。

* **请求信封**

    * 信封里装的是 GET、POST 以及一系列其他请求方法的消息。
    * 这本身**并不是代码**：里面没有函数、没有循环、没有变量。
    * 它之所以叫「协议」，是因为多年前人们就把这些消息的格式标准化了。

    ```text
       GET / HTTP/2
       Host: www.harvard.edu
       （可能还有其他一些信息行）
    ```

* **Host 头**

    * 服务器可能在同一台物理服务器上同时处理多个任务、托管好几个域名。
    * 请求必须说明自己实际想访问的是哪一个，所以要指定 `Host`。

* **响应信封**

    * 顺利时服务器用一个装着 HTTP 响应的信封回复。
    * 服务器会注明返回给客户端的**内容类型**，告诉客户端接下来收到的信封里装的是什么。

    ```text
       HTTP/2 200 OK
       Content-Type: text/html
       Date: ...
       （以及其他一些相关信息）
    ```

### 状态码

* **常见状态码**

    | 状态码 | 通俗含义 | 谁的锅 |
    | --- | --- | --- |
    | `200 OK` | 一切正常，页面在这儿 | —— |
    | `300` 段 | 各种「跳转到别处去」 | 服务器的指示 |
    | `301` | 资源**已永久移动**，请去新地址 | 服务器的指示 |
    | `400` 段 | 客户端请求有误 | 你，或者你写的代码 |
    | `404` | 文件未找到 | 路径/地址写错了 |
    | `500` 段 | 服务器那边出问题了 | 服务器不可用，或程序员埋了 bug |
    | `418` | 愚人节玩笑，不是正式规范 | 纯属内部梗 |

* **301 永久重定向**

    * 服务器返回 301 的意思是：这里没有你要找的内容，请前往这个新位置。
    * 相当于在服务器上挂了一个绕行标志，响应行里会给出应该实际访问的目标地址。
    * 实践中它常被用来强制把访问者重定向到 HTTPS 协议，人自己可能都注意不到这个变化。

* **404 未找到**

    * 它成了一个奇怪地广为人知的神秘代码。
    * 最初身份不过是一个深藏在 HTTP 头部信息里、非常底层且晦涩的状态码。
    * 很多（甚至可以说大多数）网站会把这个状态码直接展示出来，所以人们对它很熟悉。

* **500 段与 418**

    * `500` 段意味着服务器那边出了问题，可能是服务器暂时不可用，也可能是程序员埋了 bug 导致崩溃——「内部服务器错误」。
    * `418` 不是正式规范，是多年前一群觉得好玩的人正儿八经写的一份愚人节规范，已成互联网文化的一部分。

* **一个纯玩笑式重定向**

    * 只要查看过去大约 20 年里发给某个域名的 HTTP 头部信息，就能看到某位校友一直在支付域名租金，只为让 301 永久重定向生效，把访问者永远送到另一个网站去。
    * 这类例子还有斯坦福和伯克利等。

### curl 与开发者工具

* **curl（client URL）**

    * > **定义**：一个模拟浏览器行为、通过实际发送信封内容来获取服务器响应的**无头浏览器**。

    * 已安装在 Linux 开发环境里，通常也预装在 Mac 和 PC 上。
    * `-I` 开关只显示响应头部信息，不真正下载页面的任何正文。

    ```bash
    curl -I https://www.harvard.edu
    ```

* **开发者工具的三个标签**

    * **元素（Elements）**：网页一加载完就显示该页面的**所有元素**，包括 HTML 代码。
    * **控制台（Console）**：错误信息会显示在这里，作用类似编辑器里的终端窗口。
    * **网络（Network）**：浏览器正在向服务器发起请求。

* **排查技巧**

    * 勾选「保留日志」并禁用缓存，所有记录就不会被自动清掉，行为完全符合预期。
    * 一次访问热门网站就可能产生数十次 HTTP 请求，相当于来回传递同样多个数据信封。
    * 面对 HTTPS 警告时可以点「继续访问」忽略，之后底部会刷出更多输出。
    * 可以清空全部记录后单独访问某个路径，单独看它自身那一条的请求方法与状态码。

* **在别人的网页上改一个字**

    * HTML 代码是**作为副本**发送到浏览器的，不是在服务器上执行的。
    * 在页面上按住 Control 键点击（或右键）选择「检查」，工具会直接跳转到创建该元素的那一行代码。
    * 在检查器里改字只影响本地副本，点刷新即恢复原样——改动并没有写回服务器。
    * 这使它成为极佳的教学工具：可以对互联网上的**任何网站**这么做，观察别人是怎么构建出同样效果的。

## HTML 文档结构

### 根元素与文档树

* **单根元素**

    * > **定义**：一个 HTML 文档以单个根元素开始，通常就是 `<html>`，而且每个页面只能有一个这样的元素。

    * 根元素里装 `<head>` 和 `<body>`。
    * `<head>` 里通常放一个 `<title>` 标签，标签中间是真正会显示在标签页上的文字。
    * `<body>` 里是用户在页面上看见的正文，占据屏幕大约 95% 的空间，也就是所谓的**视口**。

* **文档树**

    * > **定义**：浏览器从上到下、从左到右读完文件后，在内存里构建出的树形数据结构，并把它存在浏览器的内存（RAM）里。

    * 浏览器**并不是**把文件当成一个扁平的字符串存起来。
    * 它会在内存里动态地分配节点，一个接一个逐步构建出树。
    * 网页里的任何一个标题、每一段文字，在内存里都不是一段文本，而是树上的一个节点——它们有父节点、有兄弟节点、有祖先。
    * 元素可以嵌套元素，浏览器会把这棵树忠实地渲染成眼前的页面。

    ```text
       hello.html
       └── <html>                 ← 唯一的根元素
           ├── <head>
           │   └── <title>
           │       └── "hello title"
           └── <body>
               └── 文本内容
    ```

* **并列的两种形态**

    * 一边是磁盘上一个按字符顺序排列的文件。
    * 另一边是内存里一棵有结构、有层级的树。

### 标签、属性与键值对

* **元素、标签与属性**

    * > **定义**：一个元素包含一个**开始标签**和一个**结束标签**；整门语言只有这两个核心术语。

    * HTML 不是编程语言：没有循环，没有条件语句，变量方面也没有真正的复杂性。
    * 它更像一种实践练习——读文档、摸索着怎么用现有的标签来搭建网站。

* **三段拆解**

    * 以 `<html lang="en">` 为例，`html`（全小写）是**标签名**，同时也是元素名。
    * `lang` 是**属性名**，它用来修改元素的默认行为。
    * `en` 是**属性值**，英语的缩写；大多数人类语言都有对应的缩写表示。

* **键值对写法**

    * 这就是在字典、哈希表等上下文里见过无数次的形式。
    * 键值通过等号分隔，值通常用引号括起来——**双引号或单引号都可以，但要保持一致**。
    * 闭合标签告诉浏览器「我的 HTML 内容到此结束」。

    ```text
       浏览器，接下来是我页面的头部内容。          <head>
       浏览器，页面的头部内容到此结束。            </head>
       浏览器，在头部里面，接下来是标题。          <title>
       标题部分到此结束。                          </title>
       浏览器，现在来的是页面的主体部分。          <body>
       主体部分的内容就到这里。                    </body>
    ```

* **版本声明与注释**

    * 任何用最新版本 HTML（目前恰好是第 5 版，即 **HTML5**）写的网页，开头部分都长这样：

    ```html
    <!DOCTYPE html>
    ```

    * 感叹号语法在大多数情况下只出现在 HTML 注释里，HTML 也有注释。

### 空白、缩进与刷新

* **浏览器忽略空白**

    * 浏览器其实不太在意空白字符，你可以随意添加，它会直接忽略，最终至少在每个文本段落之间保留一个空格。
    * 所以要产生更多段落，必须**明确告诉浏览器**这里放一个段落、那里放一个段落。

* **缩进**

    * 4 个空格缩进是常见做法，虽然并非严格必需。
    * 把某些标签写成一行也完全没问题，因为**浏览器通常会忽略空白字符**。
    * 缩进是为了让人类读起来舒服，不是为了让机器看。

* **刷新**

    * 浏览器读的是下载到本地的那份副本，改完代码一定要刷新才能看到效果。
    * 段落标签的默认上下外边距会让浏览器自动为段落插入空白，看起来更美观。

* ⚠️ **易错点**：改完代码不刷新，你看到的永远是旧版本。检查器里改的样式和 HTML 也一样，刷新即失效——想真正修改只能改源文件。

### 本地托管页面

* **文件与可见范围**

    * HTML 存放在一个文件里，文件名无论叫 `index.html` 还是别的，本质都是文件内部包含的内容。
    * 存在自己的机器上双击浏览器就能加载，但**全世界只有你一个人**能看到。
    * 写在服务器上，才能让全世界的访问者看到相同的内容。

* **http-server**

    * > **定义**：一个通过 HTTP 协议来提供文件服务的命令，会启动自己的网络服务器。

    ```bash
    # 1. 新建一个文件
    touch hello.html

    # 2. 在里面写上那十几行 HTML

    # 3. 起一个 HTTP 服务器，提供当前文件夹的内容
    http-server
    ```

    * 启动后会刷出一大串文本，其中有一个绿色的 **Open Browser** 按钮，点它就能用浏览器打开当前文件夹的内容。
    * 只点文件夹本身，看到的是一个**目录列表**——所有文件的索引。

* **端口选择**

    * 开发环境里的 Web 应用本身已经占用了 **80 端口和 443 端口**，因此我们的代码不能占用这两个端口。
    * `http-server` 默认选的是另一个常见的**开发端口 8080**。
    * 终端里还有一个「端口（Ports）」标签页，会提示「你刚刚在 8080 端口上启动了一个 Web 服务器」。

* ⚠️ **易错点**：**别把 8080 当成某种规定**，它就是人为约定，换任何一个没被占用的端口功能完全一样。真正要紧的是记住端口号是标准化的数字——80 是网页，443 是安全网页。

## HTML 语义标签

### 段落与标题

* **段落标签 `<p>`**

    * > **定义**：代表段落的标签，告诉浏览器「这里放一个段落，那里放一个段落」。

    * 一个元素需要开标签和闭标签各一个，多个段落就把 `<p>` 重复多次。

    ```html
    <p>
        第一段：这里放一个段落。
    </p>
    <p>
        第二段：这个段落到此结束。
    </p>
    ```

* **标题标签 `<h1>` 到 `<h6>`**

    * > **定义**：一共六个标题标签，从最大最粗一直到较小但仍然保持粗体。

    * **所有样式设置都由浏览器自动决定**，你不需要告诉浏览器标题该多大。
    * 它们有顺序、有层级含义，写的时候别把它们当成六种一样的东西随便用。
    * 标题不只是一件视觉上的事，它同时是一句关于「什么更重要」的声明：最重要的内容很可能是那个 H1，其他内容都围绕它展开。

* **常见标题样式**

    * `<h1>1</h1>`、`<h2>2（讨论部分）</h2>`、`<h3>3</h3>` 会渲染成大号粗体文字，很像章节标题、小节标题、子标题。

### 列表

* **无序列表 `<ul>`**

    * > **定义**：生成带项目符号的列表，在它内部声明一系列列表项。

    * `<li>` 是 list item 的缩写，内容可以是任何你想放进列表的东西。
    * 这种项目符号列表在很多网站和在线文档工具里都能见到，底层无非就是 `<ul>` 里嵌套 `<li>`。

    ```html
    <ul>
        <li>foo</li>
        <li>bar</li>
        <li>baz</li>
    </ul>
    ```

* **有序列表 `<ol>`**

    * 把开始标签和结束标签都换成 `<ol>`，列表就显示为 1、2、3。
    * 计算机本身就能快速计数，配合循环效率更高；手动调整序号则要在插入内容后把所有序号重新改一遍。
    * 嵌套的 `<ul>` / `<ol>` 里再放 `<li>`，编号和层级全部由浏览器替你维护，可以直接生成目录结构。

* **占位符惯例**

    * 作为占位符，计算机科学家通常选用像 foo、bar、baz 这样没有实际意义的单词，类似数学家的 X、Y、Z。
    * 写成一团文本时，浏览器只会把它变成一段接一段、中间仅用一个空格分隔的文本——「看起来像不像列表」并不重要。

### 表格

* **基础标签**

    * > **定义**：`<table>` 内用 `<tr>` 表示表格行（table row），行内放 `<td>` 表格数据（table data）。

    ```html
    <table>
        <tr>
            <td>1</td>
            <td>2</td>
            <td>3</td>
        </tr>
        <tr>
            <td>4</td>
            <td>5</td>
            <td>6</td>
        </tr>
    </table>
    ```

* **表头与表体**

    * > **定义**：`<thead>` 定义表头区，`<tbody>` 定义表体区，表头单元格用 `<th>`（table header）而非 `<td>`。

    * 屏幕上看到的加粗表头行，就是浏览器读到了 `<th>` 之后的产物。
    * 这种行和列的布局和手机拨号键盘的界面几乎一模一样，只是 HTML 本身并不会让页面变美。

    ```html
    <table>
        <thead>
            <tr>
                <th>timestamp</th>
                <th>language</th>
                <th>question</th>
            </tr>
        </thead>
        <tbody>
            <!-- 每一行提交进来的数据 -->
        </tbody>
    </table>
    ```

* **与表格工具的对应**

    * 在线表格工具的底层就是同样的行和列标签，点一下工具栏按钮就自动帮你生成了。

### 图片、视频与空元素

* **图片标签 `<img>`**

    * > **定义**：`<img>` 是 image 的缩写，`src` 是 source 的缩写，值就是图片文件名。

    * 可以围绕图片按需添加段落、标题、表格等其它内容。

    ```html
    <img src="bridge.png" alt="哈佛大学">
    ```

* **替代文本 `alt`**

    * > **定义**：alt 表示替代文本（alternative text），为图片加载缓慢、损坏或有视力障碍的用户提供文字描述。

    * 图片正常加载时，细心的用户和屏幕阅读器能读到这段描述。
    * 图片加载缓慢或完全损坏、只显示一个破损图标时，你会看到这段文字而不是一片空白。
    * 它至少会告诉你开发者原本希望你在那里看到什么。

* **空元素（void element / 自闭合元素）**

    * > **定义**：有些元素要么存在要么不存在，用开始标签和结束标签把它包起来在语义上没有意义，因此不需要结束标签。

    * 只要浏览器能明显判断出图像应该放置的位置，就不需要结束标签。
    * 这与其他所有标签（`<html>`、`<head>`、`<body>`）遵循的模式不同，**但这并不是什么错误**。

* **视频标签 `<video>`**

    * > **定义**：`<video>` 内部可以指定多个 `<source>`，以便浏览器按需求选择不同版本、分辨率或画质的视频文件。

    * `<source>` 没有缩写形式，却有一个叫 `src`（source 缩写）的属性。
    * `type` 属性声明内容类型，例如 `video/mp4` 就是它的 MIME 类型。

    ```html
    <video controls muted>
        <source src="video.mp4" type="video/mp4">
    </video>
    ```

* **控件与静音**

    * `controls` 属性启用播放、暂停等控件；不启用就无法启动或停止视频，也看不到控制界面。
    * `muted` 让视频默认静音播放，只有当用户点击时才能真正听到声音。

### 属性的两种写法

* **必须给值的属性**

    * `src="video.mp4"` 告诉浏览器这个文件在哪。
    * `method="get"` 在 HTML 里要写小写，但在 HTTP 请求信封内部会以全大写 `GET` 出现。

* **不给值的属性**

    * `controls` 只要出现即启用，浏览器看到这个词就会明白。

* **两类写法的对照**

    | 属性 | 写法 | 含义 |
    | --- | --- | --- |
    | 源文件 | `src="video.mp4"` | 必须给值：这个文件在哪 |
    | 控件 | `controls` | 不给值：出现即启用 |
    | 请求方法 | `method="get"` | HTML 里写小写，信封里是全大写 `GET` |

* ⚠️ **易错点**：把 `controls` 写成 `controls="true"` 虽然很多情况下也能工作，但规范的做法就是不写值——**布尔属性的存在本身就是全部信息**。

### 超链接

* **超链接标签 `<a>`**

    * > **定义**：HTML 中 "H" 所代表的含义——从一个页面链接到另一个页面的能力。

    * `href` 代表超链接引用（hypertext reference），值设为想链接到的网址。
    * 开始标签和结束标签之间填入的是**希望显示为链接的文字**。
    * 默认渲染成蓝色带下划线；把鼠标悬停上去，浏览器左下角会提示即将跳转的目标网址。

    ```html
    <a href="https://www.harvard.edu/">访问哈佛</a>
    ```

* **严格性与自动生成**

    * HTML 对格式要求很严格：除非你明确告诉它创建链接，否则它不会自动生成链接。
    * 文本写成 `harvard.edu` 或 `www.harvard.edu` 都只会得到一个外观像按钮、却不能点击的字符串。
    * 社交媒体和在线文档里的自动超链接，是开发人员用其他语言写代码检测输入内容中的特定模式后自动转换出来的。

* **钓鱼攻击（phishing）**

    * 因为显示文字和实际地址是两个独立的东西，攻击者可以显示一个链接却指向另一个地址。
    * 页面刷新后显示的内容看不出任何变化，除非用户足够敏锐去注意浏览器底部状态栏那行不起眼的提示，或者点击后被瞬间跳转。
    * 攻击者可以用它伪装成支付平台或各类银行的网址，诱骗用户输入用户名、密码、信用卡信息等敏感数据。
    * 归根结底，这类攻击手法本质上都是基于这些基础的网页构建元素来实现的。

* **语言属性 `lang`**

    * 主要为了 SEO（搜索引擎优化），或者像谷歌翻译这类工具，以便它们知道要翻译的源语言是什么。

* ⚠️ **易错点**：`<a>` 标签里的文字和它的 `href` 是**两个独立的东西**。正因为它们独立才能被用来骗人——所以链接文字绝不能被当成「它要去哪里」的证据。

### 页面分区标签

* **通用分区标签 `<div>`**

    * > **定义**：能在页面上创建一个分区，比段落标签更通用。

    * 它没有实际的功能影响，但语义上更清晰，因为明确表示「我在这里创建了一个分区」。

* **语义化分区标签**

    * > **定义**：`<header>` 定义页面的页眉部分，`<main>` 定义页面的主体内容，`<footer>` 定义页脚部分。

    * 它们的作用不是「长得不一样」，而是**告诉机器这块内容是什么**。
    * 如今的技术术语叫「语义网」：等网站公开、搜索引擎来抓取时，它们会知道页眉内容很重要、主体次之、页脚可能不太关注。
    * 这些标签只是把页面上不同的矩形区域组织起来的另一种思路。

* **默认外边距的差异**

    * 段落标签浏览器默认给了上下外边距，正是这些外边距让几段文字之间有了呼吸感。
    * 分区容器是纯粹的分区容器，默认没有任何外边距，于是它们会贴到了一起。

* ⚠️ **易错点**：把一个标签换成另一个标签时，不要只盯着「我想让它变什么样子」——**你可能同时丢掉了旧标签默认带来的东西**。想要间距，要么继续用 `p`，要么在 CSS 里显式给 `div` 加 `margin`。

* **元素面板的调试技巧**

    * 按住 Ctrl 键点击或右键点击可以再次打开开发者工具。
    * 悬停在元素面板里的某个元素上时，页面上对应的区域会以彩色高亮显示。
    * 点开元素旁的小三角可以展开它的子节点。

### 表单与输入

* **表单标签 `<form>`**

    * > **定义**：一个可以把用户输入送往服务器的表单容器，用 `action` 指定提交目标地址。

    * `method` 指定提交方法；`get` 是默认设置，在 HTML 里写小写，在信封里是全大写。
    * 表单提交后，参数会出现在 URL 的问号后面。

    ```html
    <form action="https://www.google.com/search" method="get">
        <input type="text" name="q" placeholder="query" autocomplete="off" autofocus>
        <input type="submit" value="谷歌搜索">
    </form>
    ```

* **输入标签 `<input>`**

    * > **定义**：表单内部的输入控件，用 `type` 区分用途，用 `name` 指定参数名。

    * `name` 决定提交后 URL 里出现的键名，`value` 决定按钮上显示的文字。
    * `placeholder` 提供灰色占位提示文字，让用户知道该输入什么。
    * `autofocus` 让光标自动落在文本框里，不用再先点击激活它。
    * `type="search"` 比 `type="text"` 多出一个小小的 `X` 按钮，可以一键清空所有内容。
    * 提交类控件还有 `<input type="submit">` 与功能类似的 `<button>` 元素。

* **HTTP 参数**

    * > **定义**：出现在 URL 问号之后的键值对，是向 Web 服务器传递输入的一种方式。

    * 键是 `q`（即 query），等号后面的值是搜索词。

    ```text
    https://www.google.com/search?q=cats&后面一大串
    └────┬─────┘└──────┬───────┘└─┬─┘└──┬──┘└─────┬─────┘
       协议方案          主机名+顶级域名  路径     键      值
                                                  │
                                  问号后面是 HTTP 参数（键值对）
    ```

* **前端与后端**

    * > **定义**：前端是用户直接看到和交互的部分，后端负责为前端提供数据支持。

    * 只实现前端时，提交结果只是把 URL 改成了带参数的形式，并没有真正处理数据。
    * 知道后端接口地址后，只靠前端知识就能搭出同一网站的雏形。

## 校验与安全

### 正则表达式

* **正则表达式（regular expression，regex）**

    * > **定义**：一种描述模式的方法，在验证输入时特别有用。

    * 它不只存在于网络开发领域，在 Python 和许多其他编程语言中同样适用。
    * 多年来人们发明了这套简写符号，通过它可以定义模式并强制实施格式要求。

* **常用符号**

    | 符号 | 含义 |
    | --- | --- |
    | `.` | 任意一个字符（**不代表句号**） |
    | `*` | 出现零次或多次 |
    | `+` | 出现一次或多次 |
    | `?` | 出现零次或一次（可能存在也可能不存在） |
    | `{n}`、`{a,b}` | 出现指定次数，或落在某个次数区间 |
    | `[abc]`、`[a-z]` | 这些字符中的任意一个，或某个范围 |
    | `\d` | 任意一个数字 |
    | `\D` | 任意一个非数字字符 |

* **数据科学中的用途**

    * 验证数据只是它的一面；在实际的网站或文档中寻找数据模式并**提取数据**才是它无可替代的地方。

### pattern 与 type="email"

* **pattern 属性**

    * > **定义**：直接写出一个正则模式，强制输入必须匹配，否则拒绝提交。

    * `.+@.+\.edu` 的读法是：任意字符一次或多次（用户名）、一个 `@`、任意字符一次或多次、字面上的句点、最后是顶级域名。
    * 句点这种特殊字符需要转义时，可以用反斜杠加句号来表示一个实际的句点。

    ```html
    <form>
        <input type="text" name="email" placeholder="email" pattern=".+@.+\.edu">
        <button>注册</button>
    </form>
    ```

* **type="email"**

    * > **定义**：HTML 自带的输入框类型，会自动完成电子邮件格式的匹配验证。

    ```html
    <input type="email" name="email" placeholder="email">
    ```

    * 用上它之后，给出的提示信息比手写 `pattern` 更加明确具体。

* **邮箱校验的边界**

    * 验证电子邮件地址实际上相当复杂，实现的只是一个非常简化的版本。
    * 只验证「用户名 @ 域名 . 顶级域名」这种格式，而像 `main@harvard.edu` 这样的地址实际允许的语法规则复杂得惊人。

### 浏览器端校验不可信

* **本地副本**

    * > **定义**：HTML 代码是从服务器端发送过来、下载到用户设备上的一份副本，用户本地也有一份。

    * 用户可以直接打开开发者工具查看甚至删掉 `pattern` 属性，从而绕过全部校验。
    * 从安全角度来说，浏览器端的这些特性通常都是不可靠的。

    ```text
    你写的：        <input pattern="...">     ← 服务器发来的那份
    用户拿到的：    完全相同的一份本地副本
    用户做的事：    打开开发者工具 → 删掉 pattern 属性 → 绕过全部校验
    ```

* **与 SQL 注入的类比**

    * 两个合作开发网站的人可能想：「我不需要担心转义字符，因为负责 HTML 的人已经用了 `pattern` 属性。」
    * 这种想法很危险，攻击一个网站甚至可以直接在浏览器里删掉网页上的某些功能代码。

* > **结论**：**绝对不能完全信任用户输入的数据。**

### 语法校验工具

* **validator.w3.org**

    * > **定义**：由负责制定 HTML 等语言标准的组织维护的验证网站。

    * 选择「验证直接输入」标签页，把代码复制粘贴进去点检查，就能自动验证标签是否正确闭合。
    * 它还能发现拼写错误、遗漏括号或引号之类的低级错误。
    * 它验证的是语法是否正确，**尽管在屏幕上看起来可能还是一团糟**。

## CSS 样式

### CSS 的角色与术语

* **CSS（Cascading Style Sheets，层叠样式表）**

    * > **定义**：负责网站美学呈现的语言，控制元素的位置、颜色、字体大小等视觉细节。

    * HTML 是网站的**骨架**，负责结构搭建；CSS 像是**皮肤**。
    * 它本身并非编程语言，但随着功能不断丰富，正变得越来越像编程语言。
    * 支持的键值对组合非常丰富，具体技巧最终需要通过查阅参考手册、书籍或在线资源来掌握。

* **声明（declaration）**

    * CSS 里的一个键值对叫一个**声明**。
    * HTML 里键值对叫**属性**（attribute），CSS 里叫**声明**，之所以用不同的词，是因为 **CSS 和 HTML 是由不同的团队各自独立开发的语言**。
    * 属性之间用**分号**隔开；最后一个键值对后严格来说不需要分号，但为保持一致性建议还是加上。

* **语法边界**

    * 标签和属性属于 **HTML 语法**；`style` 里面引号包着的那些才是 **CSS 语法**。
    * 这就像在 Python 代码里嵌入 SQL 语句，只不过方向反过来：这里是 HTML 里嵌 CSS。

* **层叠（cascading）**

    * > **定义**：写在某个元素上的键值对会向下层叠，作用到它内部的每一个标签上。

    * 能生效是因为那些元素是它的子元素——借用树结构的词来说，谁是祖先，谁就替后代兜底。
    * 视觉上可能毫无变化，但代码明显更合理。

    ```html
    <body style="text-align: center;">
        <div>John Harvard</div>
        <div>Welcome to my home page</div>
        <div>(c) 2026</div>
    </body>
    ```

* **内联写法的痛点**

    * 三个 `div` 各写一遍 `text-align: center;` 属于重复劳动。
    * 把所有键值对都堆在某个标签上，属性就被绑死在那儿，一点都谈不上可重用。

### 三种引入方式

* **方式一：写在元素上**

    * 给元素加一个 `style` 属性，里面就是键值对。

    ```html
    <div style="font-size: large; text-align: center;">
        John Harvard
    </div>
    ```

* **方式二：写在页面头部的 `<style>` 标签里**

    * 可以放很多条声明，对整个页面生效。

    ```html
    <style>
        body {
            text-align: center;
        }
        header {
            font-size: large;
        }
    </style>
    ```

* **方式三：单独写进 `.css` 文件再用 `<link>` 关联**

    * 把 `<style>` 标签里的内容整体剪切到 `home.css`，头部的 `<style>` 标签被替换成一行链接代码。

    ```html
    <link href="home.css" rel="stylesheet">
    ```

    * `rel` 用来定义当前文件与被链接文件之间的关系，这里声明的关系是「样式表」。
    * 这个标签不需要闭合，它本身就是一个自闭合标签。
    * 除了字体上的细微差别，视觉上没有任何变化，但设计变得更好了。

* **选择器的骨架**

    ```text
    <style>
      └── 选择器   {  属性: 值;  属性: 值;  }
          ↑              ↑
          │              └── 这些键值对作用到谁身上，由选择器决定
          └── body 匹配到的那一个元素
    ```

* ⚠️ **易错点**：这个 `link` 标签与超链接或可点击文本**毫无关系**，它仅用于关联另一个文件。链接到网页用 `<a>`，链接到样式表用 `<link>`，别搞混。

### 选择器

* **类型选择器**

    * 写法就是标签名本身，例如 `a` 选中页面上**所有**的 `<a>` 标签。
    * 想知道别人网页是怎么做效果的，打开开发者工具的 Elements 面板，这里能直接看到当前所选元素所应用的所有 CSS 样式。

* **类选择器**

    * 写法是在关键词前加一个点，例如 `.centered` 选中所有标了 `class="centered"` 的元素。
    * 自己造一个关键词（比如「居中」这个概念本身并不存在），加上点前缀就是一个 CSS 类。

* **ID 选择器**

    * 写法是 `#Harvard`，选中那一个 ID 为 `Harvard` 的元素。

* **伪类选择器**

    * 在标签名后加上 `:hover` 这样的关键字，浏览器能识别这个语法。
    * 例如 `a:hover` 选中鼠标悬停时的那一刻的那个 `<a>`，可用来只在悬停时显示下划线。

* **属性选择器**

    * 写法是方括号，按属性挑选元素。

* **选择器谱系**

    | 写法 | 名称 | 选中什么 |
    | --- | --- | --- |
    | `a` | 类型选择器 | 页面上**所有**的 `<a>` 标签 |
    | `.centered` | 类选择器 | 所有标了 `class="centered"` 的元素 |
    | `#Harvard` | ID 选择器 | 那一个 ID 为 `Harvard` 的元素 |
    | `a:hover` | 伪类选择器 | 鼠标悬停时的那一刻，那个 `<a>` |
    | `[...]` | 属性选择器 | 按属性挑 |

* ⚠️ **易错点**：想只给**某一个**特定标签写样式，常规做法是给它一个唯一的 ID，并保证页面上没有别的元素用相同的 ID。写规则时写成 `#Harvard`（井号表示这是一个 ID），但在**实际的 HTML 代码里，ID 值前面不需要加井号**——加了反而不合规。

### 类

* **CSS 类（class）**

    * > **定义**：一组键值对，也就是一组属性；可以把同一个类和任何一个 HTML 标签关联起来。

    * 使用时在标签上写 `class` 属性，一个元素可以同时挂多个类。
    * 动机与模块化精神一脉相承：把一组属性打包，拿到网页任何位置重复使用。
    * 它不是函数，但为将来更有趣的功能打下了基础。

    ```css
    .centered {
        text-align: center;
    }

    .large  { font-size: large; }
    .medium { font-size: medium; }
    .small  { font-size: small; }
    ```

    ```html
    <body>
        <header class="large">John Harvard</header>
        <main class="centered medium">Welcome to my home page</main>
        <footer class="small">&#169; 2026</footer>
    </body>
    ```

* **HTML 实体**

    * > **定义**：HTML 里专门用于表示特殊字符的符号组合，**注意结尾的分号**。

    * `&#169;` 会渲染出一个真正的版权符号，而且是用当前页面所使用的字体显示的。

### 外部样式表与框架

* **颜色与文本装饰**

    * > **定义**：`#FF0000` 是十六进制颜色代码，红色分量最高，绿色和蓝色分量均为零。

    * 想要对颜色有如此精细的控制权就靠它。
    * `text-decoration: none;` 去掉下划线，只在悬停时显示下划线效果更好。

    ```css
    a {
        color: #FF0000;
        text-decoration: none;
    }

    a:hover {
        text-decoration: underline;
    }
    ```

* **框架（framework）与库（library）**

    * > **定义**：框架本质上是通过使用**他人编写的库**来实现特定功能的方式，并且按照他们的方式来。

    * 你只需要读他们的文档，然后按具体情况采用他们的函数（代码层面），或者采用他们的 CSS 类。
    * 引入这些类的目的仍然是**代码的可重用性**，而且可以站在巨人的肩膀上。

* **Bootstrap**

    * > **定义**：如今最流行、文档也最简洁完善的一个前端框架，提供了一系列 CSS 类和一套 JavaScript 功能。

    * 因为开源可以直接用在自己代码里，通过 CDN 引入样式文件：

    ```html
    <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/bootstrap/dist/css/bootstrap.min.css">

    <table class="table table-striped">
        <tbody>
            <!-- 每个人都提交的那一行，原封不动 -->
        </tbody>
    </table>
    ```

    * `table table-striped` 中间是空格分隔，表示同时挂上两个类。
    * 白灰相间的条纹让格式好看得多，**仅仅通过修改 CSS 实现，HTML 本身几乎没变**。

* **CDN（内容分发网络）**

    * 链接指向的第三方站点就是专门为他人提供内容服务的服务器。
    * 这类链接通常可以直接从框架的官方文档里复制。

### 元素面板的三个用处

* **学习别人的实现方式**

    * 面板里能直接看到当前所选元素所应用的所有 CSS 样式——颜色 `#FF0000`、文本装饰 `none`。
    * 这些内容一直都在那儿，只是直到现在才被注意到。

* **快速迭代**

    * 把鼠标悬停在属性上，点击或取消点击，就能即时开关某个效果。
    * 临时把颜色改一下，屏幕就变样了——反正刷新就没了。

* **随手试验**

    * 可以临时修改浏览器里的 HTML 或 CSS 来快速试效果，刷新后自动还原。

## JavaScript

### 为什么需要 JavaScript

* **JavaScript 的地位**

    * > **定义**：三种语言里唯一真正意义上的编程语言。

    * 它的语法和功能跟 C、Python 这些语言非常像，学起来不用花多少力气。
    * 开发者会在服务器端写好代码，浏览器把它下载到客户端，最终在用户的机器上运行。
    * 它如今在服务器端也非常流行，并不仅仅是一门基于浏览器的语言。

* **最强大的能力**

    * > **定义**：能在内存中实时修改浏览器里那棵树。

    * 过去：点刷新 → 整页重新下载 → 服务器 → 整棵 DOM 被换掉，页面由成百上千个表格行拼出来。
    * 现在：点刷新 → 事件触发 → JavaScript 取新邮件 → 往**现有** DOM 上再挂一个节点。
    * 可以在初始时一次性下载数据，然后每隔一段时间抓取一些新数据，几乎在任何数据到达时就能拿到更多。

    ```text
    【过去】点刷新 → 整页重新下载 → 服务器 → 整棵 DOM 被换掉
                 <tr><td>…</td></tr> × N

    【现在】点刷新 → 事件触发 → JS 取新邮件 → 往现有 DOM 上再挂一个节点
                 <tr>…</tr> × N   +   <tr>新到的这一封</tr>
    ```

* **DOM（Document Object Model，文档对象模型）**

    * > **定义**：这棵树在浏览器里的名字；通过 JavaScript 可以动态地修改它，实现网页内容的动态更新。

### 语法速览

* **与 Python 的差异**

    * 条件语句是花括号，和 C 语言基本相同，**缩进在 JavaScript 中不影响程序执行**，它只关乎代码风格。
    * 变量用 `let counter = 0;` 声明，不需要指定变量类型。
    * 这更像是礼貌地向浏览器提出请求：请创建一个名为 counter 的变量，默认值设为 0。
    * 分号严格来说并不完全准确，浏览器足够智能，但可以**假设分号始终存在**。

* **语法对照**

    | 想做的事 | Python | JavaScript（≈ C） |
    | --- | --- | --- |
    | 条件 | `if x:` 靠缩进 | `if (x) { … }` 靠花括号 |
    | 循环 3 次 | `for i in range(3):` | `for (let i = 0; i < 3; i++)` |
    | 死循环 | `while True:` | `while (true)` |
    | 加 1 | `counter += 1` | `counter += 1;` 或 `counter++;` |

* **运算符**

    * 加法有「加等于」这个略显冗长的技巧，也有更简洁的「加加」运算符，就像 C 里一样，Python 里可没有这种写法。
    * 循环和 C 几乎一模一样，只是**不需要声明数据类型**。
    * 遍历数组时用的是 `of` 关键字，而不是像 Python 那样用 `in`。

* **引号惯例**

    * JavaScript 社区通常倾向于用单引号而非双引号。
    * 原因只是这样人们需要按 Shift 键输入双引号的次数更少；这是一个惯例，保持一致即可，前提是文本内容里没有真正的撇号。

### 事件与监听

* **事件（event）**

    * > **定义**：用户或其他来源实际执行的操作，可以对它编写监听代码并在发生时执行相应操作。

    * 常见的交互事件包括：更改某些内容、点击某个元素、拖拽对象、松开按键、按下鼠标。
    * 站内任何类似的交互功能都是这样实现的：**通过监听你或其他人实际执行的操作来工作**。

* **真实例子**

    * 在邮箱里点击刷新图标去取新邮件，实际上是一些 JavaScript 代码在跑，它与服务器通信、获取更多邮件并更新页面。
    * 在地图上点击并拖拽去看别的地方，实际上是有代码在监听你的按下与拖拽，好去获取更多地图图块。

* **addEventListener**

    * > **定义**：给任意元素添加一个监听器，告诉它「后续请监听指定事件，并在监听到时执行这段」。

    * 监听器是一个函数或方法，可以应用到任何元素。
    * 传入的**匿名函数**（常说的 Lambda 函数）意味着：当该元素上发生对应事件时，就执行这对花括号之间的代码。

    ```javascript
    document.querySelector('form').addEventListener('submit', function() {
        alert('Hello, ' + document.querySelector('#name').value);
    });
    ```

* **onsubmit 属性**

    * 给表单标签添加的属性，顾名思义：当这个表单提交时就调用指定的函数。

    ```html
    <form onsubmit="greet()">
        <input id="name" placeholder="name" type="text" autocomplete="off" autofocus>
        <button type="submit">Submit</button>
    </form>
    ```

* ⚠️ **易错点**：在表单的事件处理函数里必须加 `return false`。不加的话函数确实会被调用，但浏览器**仍然会尝试把表单提交到服务器**，那会打断自己写的代码执行。加了它，提交表单时唯一发生的事就是执行你定义的函数。

### 引入 JavaScript 的三条路

* **第一条路：写在页面底部**

    * 把 `<script>` 标签放在页面末尾、`</body>` 结束标签之前，确保整个网页内容已经加载完成。
    * 这种做法不需要 `onsubmit` 属性，函数完全从 HTML 里分离出来。

* **第二条路：写在顶部，但等 DOM 就绪**

    * 用 `DOMContentLoaded` 事件把后续代码包起来，位置就可以随意放。

    ```html
    <script>
        addEventListener('DOMContentLoaded', function() {
            // 其余代码
        });
    </script>
    ```

* **第三条路：外链文件**

    * 把代码整个移到独立的 `.js` 文件里，HTML 中只留一行。

    ```html
    <script src="hello.js"></script>
    ```

* **竞态条件（race condition）**

    * 把 `<script>` 放在头部、试图修改网页内容时，网页的实际结构直到下方才定义完成。
    * 代码执行时数据可能还不存在，于是形成竞态条件。
    * 这与 Python 的默认参数问题、C 的原型声明问题本质相似——都是「你用到的东西，可能还没准备好」。
    * 同样的道理，也适用于把 CSS 从 HTML 中分离、把函数从 HTML 中移出来这些做法。

* **三种位置的效果**

    ```text
    <script> 在 head 里 ──▶ DOM 还没建好 ──▶ 竞态条件，代码扑空
    <script> 在 </body> 前 ─▶ DOM 已就绪 ──▶ 安全
    DOMContentLoaded ──────▶ DOM 就绪才执行 ──▶ 安全（位置随意）
    外链 .js 文件 ─────────▶ 由上面任一方式引入 ──▶ 逻辑与结构彻底分离
    ```

### 文档对象与选择器

* **document**

    * > **定义**：一个随浏览器中的 JavaScript 一同提供的**全局变量**，允许编写涉及整个文档（即网页本身）的代码。

* **querySelector**

    * > **定义**：一个函数，允许**使用 CSS 选择器**来选取页面中的特定元素。

    * 之前那些带点号、井号的语法在这里又派上用场。
    * `"#name"` 里的 `#` 仅表示 ID 选择器，只要和 HTML 里设置的唯一标识符一致即可。
    * 这段代码的作用是**定位到树中的那个节点**。

* **点号语法**

    * 在 C 语言里点号用来访问结构体成员，在 Python 里点号用于访问对象的属性。
    * 这里的点号是通过全局变量 `document` 访问文档对象，调用它内部的 `querySelector`，取到目标元素，再深入内部取出它的值。

* **属性读取**

    * `.value` 属性取出这个文本框里的值。
    * `innerHTML` 取出或设置一个元素内部的 HTML 内容。

* **alert**

    * JavaScript 内置的函数，用来弹出一个提示框；字符串之间的拼接用加号。

    ```javascript
    function greet() {
        let name = document.querySelector("#name").value;
        alert("Hello, " + name);
        return false;
    }
    ```

### 模板字符串与实时改树

* **keyup 与实时交互**

    * `keyup` 事件就是键盘按键弹起，就像手指从键盘上抬起。
    * 每按一次 keyup，树上就多长出一块，变化直接发生在网页内部实时进行。

    ```javascript
    addEventListener('DOMContentLoaded', function() {
        let input = document.querySelector('input');

        input.addEventListener('keyup', function() {
            let name = document.querySelector('p');

            if (input.value !== "") {
                name.innerHTML = `Hello, ${input.value}`;
            } else {
                name.innerHTML = 'Hello, whoever you are';
            }
        });
    });
    ```

* **空值的隐式转换**

    * 引号里空着就表示空值；在 JavaScript 里空字符串会被隐式当作假值。
    * 所以 `if (input.value !== "")` 其实可以简写成 `if (input.value)`。

* **模板字符串（template literal）**

    * > **定义**：反引号包裹、可以在一段文本里嵌入表达式结果的写法，本质类似 Python 的 f 字符串。

    * 它看起来有点奇怪——又是美元符号又是花括号，还用了反引号——但在查文档时很可能遇到。
    * 这反映了 JavaScript 社区的一种理念：语言要持续发展演进，就必须确保新版本能够**向后兼容**旧版本的语言特性。
    * 所以他们选择了那些在现有代码中几乎不会出现的字符和语法结构，于是有时候看起来会比预想的更别扭。

* **开发者工具里的实时树**

    * 默认情况下页面里只有一个空的段落标签；输入字母时元素面板里看到的经过缩进排版、语法高亮的结构，就是**内存中那棵树的可视化呈现**。
    * 把内容删掉，结果又回到默认状态。

    ```text
    按下 D      按下 A       按下 V       停止输入
     <p></p>  →  <p>A</p> →  <p>AV</p> →  <p>你好 David</p>
       │           │            │              │
       └───────────┴────────────┴──────────────┴── 每按一次 keyup，树上就多长出一块
    ```

### style 属性与驼峰命名

* **style 属性**

    * > **定义**：在 JavaScript 中，任何元素都可以通过 `style` 属性来设置样式。

    * `body.style.backgroundColor = 'red'` 做的事情，和你在 CSS 里写 `body { background-color: red; }` 是一回事。
    * 监听的是按钮的点击事件，但改变的不是按钮本身的内容，而是**整个页面的样式**。

    ```javascript
    let body = document.querySelector('body');

    document.querySelector('#red').addEventListener('click', function() {
        body.style.backgroundColor = 'red';
    });
    ```

* **驼峰命名法（camelCase）**

    * > **定义**：单词中间用一个突然出现的大写字母把两个词分开。

    * CSS 里连字符是合法的**标识符字符**，但在 JavaScript 里**减号是一个数学运算符**。
    * 那样一来 `background-color` 就变成了 `background` 减去 `color`，显然不对。
    * 于是业界决定用首字母大写来解决——就是原本连字符所在位置的那个字符。

### 定时器与窗口

* **window**

    * > **定义**：一个全局变量，指浏览器窗口本身，不一定是页面的具体内容。

* **setInterval**

    * > **定义**：可以在 `window` 上调用的方法，每隔指定的毫秒数执行一次特定的函数。

    ```javascript
    let body = document.querySelector('body');

    function blink() {
        if (body.style.visibility === 'hidden') {
            body.style.visibility = 'visible';
        } else {
            body.style.visibility = 'hidden';
        }
    }

    setInterval(blink, 500);
    ```

* **visibility 切换**

    * 如果该节点的 CSS `visibility` 属性是 `"hidden"` 就改成 `"visible"`，否则改回 `"hidden"`。
    * 每 500 毫秒翻转一次，效果是闪烁；同时 Elements 面板里的 HTML 和样式面板里的样式都会自动变化。

    ```text
                      每 500 毫秒翻转一次
            ┌────────────────────────────────┐
            ▼                                │
      ┌─────────────┐                 ┌─────────────┐
      │   hidden    │ ──────────────▶ │  visible    │
      │  （看不见） │ ◀────────────── │  （看得见） │
      └─────────────┘                 └─────────────┘
    ```

* ⚠️ **易错点**：你可能会以为 `visible` 的反义词是 `invisible`。**但在 CSS 中，`visible` 的反义词是 `hidden`。** 这种琐碎细节只能死记硬背。

* **已被移除的标签**

    * **HTML 闪烁标签**是 HTML 世界中为数不多的标签之一，实际上**已被弃用、从语言中移除了**——通常人们不会从语言中移除东西，但它实在太糟糕了。
    * 紧随其后的是**滚动标签**：从左到右在屏幕上滚动，像一个丑陋的滚动横幅，类似如今的数字标牌。
    * 如今要重现这种效果只能改用 JavaScript 定时切换。

### 自动完成列表

* **思路**

    * > **定义**：用一份庞大的词表和字符串拼接，动态生成一个 `<ul>` 的内容来充当自动完成提示。

    * 词表可以是一个超过 10 万个单词的数组文件。
    * 监听 `keyup` 事件，输入有值时遍历词表，把以输入内容开头的单词拼成 `<li>` 标签，最后一次性写进列表。

    ```javascript
    let input = document.querySelector('input');

    input.addEventListener('keyup', function() {
        let html = "";

        if (input.value) {
            for (let word of words) {
                if (word.startsWith(input.value)) {
                    html += '<li>' + word + '</li>';
                }
            }
        }

        document.querySelector('ul').innerHTML = html;
    });
    ```

* **关键写法**

    * 遍历数组用 **`of`** 关键字，而不是像 Python 那样用 `in`。
    * `startsWith` 用来判断当前单词是否以用户输入的内容开头。
    * 加等于 `+=` 在这里其实就是**字符串连接**。
    * `<ul>` 元素的内容被设置成那个 `html` 变量的值——这就是自动完成功能通常的实现原理。

* **匹配随输入变窄**

    ```text
    输入 "C"                      输入 "ATS"
    ┌──────────────────────┐     ┌──────────────────────┐
    │ <ul>                │     │ <ul>                │
    │   <li>cat</li>      │     │   <li>ats</li>      │
    │   <li>car</li>      │     │   <li>cats</li>     │
    │   <li>camp</li>     │     │   <li>catski</li>   │
    │   …                 │     │   （只剩 4 个匹配）  │
    │ </ul>               │     │ </ul>               │
    └──────────────────────┘     └──────────────────────┘
          每次 keyup 重建                匹配越来越窄
    ```

* **本质**

    * 如今几乎每个网站都不再手写大段 HTML，而是编写**动态生成 HTML 的代码**。
    * 程序员理解 HTML 的本质：明白无序列表包含 `<li>` 子元素，于是连续创建又一个 `<li>`，动态更新内部 HTML 内容。

### 框架交互与定位

* **Bootstrap 的 JavaScript 功能**

    * > **定义**：框架不只提供可用的 CSS，还提供一整套 JavaScript 功能，让下拉菜单等交互效果容易实现。

    * 复制粘贴的样板代码就能得到带定价功能和禁用菜单项的企业网站界面。
    * 页面里有一个**导航栏**，列出了企业网站常见的主菜单选项。
    * 窗口变得很窄时，界面会自动切换到**移动端显示模式**：它会监听**汉堡菜单**的点击事件，通过这种方式展开菜单选项。
    * 这与主流官网以及众多其他网站的实现方式非常相似。

* **navigator.geolocation**

    * > **定义**：浏览器中名为 `navigator` 的全局对象，包含一个 `geolocation` 属性对象，它有一个 `getCurrentPosition` 方法。

    * 该方法接收一个**匿名函数**作为参数：当系统准备好获取坐标时（因为 GPS 定位可能需要一些时间）就执行这段代码。
    * 返回的位置信息包括纬度和经度。

    ```javascript
    navigator.geolocation.getCurrentPosition(function(position) {
        document.querySelector('#map').innerHTML =
            position.coords.latitude + ', ' + position.coords.longitude;
    });
    ```

* **隐私授权**

    * 出于隐私保护，浏览器会请求授权，必须允许之后才能拿到坐标。
    * 在室内时定位精度有限，系统很可能映射到了建筑拐角处的某个无线接入点，但结果通常已经相当接近。
