# 课程回顾与结业项目

## 课程进度观与结业判定

* **结业判定的基准**

    * > **定义**：重要的不是你相对于同学达到了什么水平，而是你相对于自己的起点取得了多少进步。

    * 这一条会在期末项目和最终成绩评定里被充分考虑。
    * 从教育角度说，真正的关键指标是你从第 0 周到第 10 周之间的进步幅度。
    * 开课时属于“不太适应”那一类的人，从结业这天起已经正式告别这个行列，至少到了中间水平。

* **被扣分不等于落后**

    * 讲师自述：1996 年秋天，他人生中的第一个编程作业连最简单的 “Hello, World” 都没能跑对，注释写得极其详细，甚至特意注明“main 就是 main”，还专门告诉助教自己的文件在哪里结束，结果因没按要求被扣 2 分。
    * 结论是：即使到了作业九还在被扣分，你也正与优秀的人为伍；随着时间推移，一切都会变得更顺、更轻松、更高效。

* > **提示**：这门课比的不是名次，是斜率。

## 问题的本质：算法黑箱

* **输入—算法—输出模型**

    * > **定义**：先有输入（待解决的问题），再得到输出（期望的解），而在这个众所周知的“黑箱”内部，装的就是那些按部就班的算法指令。

    * 解决问题，就是计算机科学的本质。

    ```text
       +---------+      +-----------+      +----------+
       |  input  | ---> | algorithm | ---> |  output  |
       | problem |      |  (black   |      | solution |
       +---------+     |   box)    |      +----------+
                       +-----------+
    ```

* **算法（algorithm）**

    * > **定义**：算法就是为完成某项任务而设计的精确步骤序列。

    * 这个定义与 25 年前第一堂课记下的定义几乎一字不差。
    * 那天记下的两个核心收获是精确性与正确性；这几周未必天天把这两个词挂在嘴上，但一直在贯彻。

* **编程的本质**

    * 编程本身就是把算法翻译成计算机能处理的语言的过程 —— 这正是你在 Scratch、C、Python、SQL 和 Java 里真正做过的事。

## 抽象层级与精确程度

* **口头编程规则**

    * 屏幕上显示一张白底图片，人要用口头编程的方式引导全场观众在纸上画出屏幕上的东西。
    * 只能说话，不能有任何肢体动作；每人进场时拿到一张白纸和一支笔。

* **Jia 的六步立方体指令**

    * 第一步：画两条紧挨着的竖线。
    * 第二步：在这两条竖线的上方、正中间以及下方，各画一个点，总共三个点。
    * 第三步：从左边竖线的顶端出发，画一条线连到最上方那个点；再从右边竖线的顶端出发，也画一条线连到最上方那个点。
    * 第四步：从左上角那个位置画一条线连到中间的点；然后从右边竖线的顶端，画一条线连到中间的点。
    * 第五步：从左边竖线的底端连到最下方的点；从右边竖线的底端也连到最下方的点；最后，把中间点和最下方的点连起来。
    * 第六步：完成。
    * 交上来的结果五花八门：垂直竖线、问号、非常狭窄的一个、还有一个类似的，并非所有部分都进展顺利。

* **画不清楚的两个原因**

    * 一是脑子里已经清清楚楚地想象出了自己要画的东西。
    * 二是这些指令里一个抽象概念都没有用上。
    * 补一句“我们要画一个立方体”其实是对那一堆底层细节做的一次抽象，事情可能立刻简单得多；但“立方体”这个词本身也有歧义（它是否旋转过），所以仍然需要比 Jia 给出的更多信息。

* **坐标描述法**

    * 许多早期绘图程序（包括 Scratch 这样的环境）都默认你拥有一个带 X 轴和 Y 轴的坐标系，可以上下左右移动。
    * 更细的写法：把笔尖放到页面顶端，向西南画一条直线，以相同的距离向南画，再向东南，然后如此反复。
    * 全程都在用角度或方向说话，但在足够多条线落到屏幕上之前，没有人会认出我们在画什么，直到某一刻才看出那一直是个立方体。

    ```text
       "draw a cube"                      <-- abstraction: shortest, but ambiguous
            |
            v
       pen at top -> SW -> S -> SE -> SW -> S -> SE ...
                                            <-- coordinates: exact, but unreadable
    ```

* **取舍的判定**

    * 无论是为了让他人理解我们，还是为了让今天的人工智能理解我们，抑或是介于两者之间的任何情况，所采用的精确程度和抽象层级都直接决定结果。

* **反过来指挥：Presley 的白板**

    * 互动方式完全反过来：观众负责编程，他负责执行；给一支黑色记号笔，站到白板前。
    * 唯一硬性要求是不许抬头、不许回头看，因为答案在屏幕上；其他同学可以随便看，每画完一笔稍微让开一点让大家看清。
    * “画个圆圈”其实是一次很棒的抽象处理，任由它发展会画出一个简笔画小人；“画个火柴人”则给了他一个更有帮助的心理模型。
    * 完整指令从圆圈底部向下画一条线、画出两条对角线作腿、在头部左侧写大写 “H” 并画线连到脸上、调整手臂看起来像在奔跑、最后微调另一只手臂。
    * 结果画出来的是一个正在奔跑、举着 “HIGH” 标语的人物 —— 他其实是在让大家为他鼓掌。
    * 这个环节之所以好，是因为它同时包含了底层细节（线条的方向和长度）和抽象概念；类比到代码，函数上方的注释说明偏抽象，真正实现时写的就更接近针对当前问题的逐步操作指南。

* > **易错点**：黑色马克笔是永久性的，所以很容易一开始就偏离轨道，或者犯个小错误；Presley 能坚持下来相当不容易。

## 十周知识轨迹

* **推进路线**

    ```text
       Scratch          loops / conditions / booleans / variables
           |
           v
       C                memory / arrays / pointers / hash / linked list
           |            runtime analysis
           v
       Python / SQL / Java     beyond arrays and algorithms
           |
           v
       Web + JavaScript  ->  mobile (HTML / CSS)  ->  AI as collaborator
           |
           v
       final project:  the first project you plan all by yourself
    ```

* **视觉化编程入门（Visual Programming with Scratch，VoI）**

    * > **定义**：第一周所处的位置形态，用图形化积木介绍基础的程序设计概念。

    * 目标概念是循环、条件语句、布尔表达式和变量；它们在随后的几周里会以不同的形式、不同的语言反复出现。

* **C 与底层知识**

    * C 是一种极其基础的语言，如今许多其他编程语言都构建在它之上；你可能正在用的那个 Python 解释器，本身就可以用 C 编写。
    * 它对应的是内存、数组、指针、哈希、链表这一组内容，以及运行时间分析。
    * 很多人可能再也不会用到它 —— 讲师自己也只在 CS 50 开课期间每年用上一两个月。

* **不可绕过的知识底盘**

    * 从一种语言引导到另一种语言、从底层到高层、超越数组和算法，内存和数据结构在计算与编程领域几乎无处不在。
    * 用 Python 这样的现代语言时你可能不需要过多操心内存管理，因为优秀的程序员已经在语言本身或你调用的库里替你解决了这些难题。
    * 但你至少可以确信：自己已经理解哈希表的基本概念，知道链表是什么，理解它们之间的权衡取舍，掌握了运行时间的分析方法。
    * 这些正是计算机科学家和软件工程师在实际工作中思考、讨论、在白板上推演的核心内容，也是他们为现实问题设计算法或开发实际产品时的决策依据。

* **现代范式与 Web**

    * 以这些基础知识为跳板，课程探讨了一些非常现代的编程范式，最近还涉及了 Web 编程。
    * 课堂上没有明确讲授移动端编程，但它越来越依赖 HTML 和 CSS；JavaScript 则有人会在期末项目里用到。

* **AI 作为协作者**

    * 课程今天至少有一个目标是为学生指明方向、介绍工具。
    * 完成问题集 9 之后，欢迎并鼓励在期末项目里用上这些工具 —— 你自己的努力和专业知识可以借此被极大地增强。
    * 效果像是身边多了一位初级同事：帮你解决程序错误、指明正确方向、协助实现某个功能。
    * 连正在学 CS 50 Plus 的讲师本人也常低估解决一个问题所需的时间，而这种情况正在开始改变，至少在一定程度上要归功于 AI。

## 期末项目

* **项目定位**

    * > **定义**：期末项目的初衷是成为你自己规划的第一个项目，并由此开启更多项目的序幕。

* **唯一的要求**

## 结业复习题与知识点收束

### 位宽、纪元与时间溢出

* **8 位无符号整数的上界**

    * > **定义**：8 位无符号二进制数（不涉及负数）能表示的最大值是 255。

    * 之所以是 255 而不是 256，是因为我们始终从零开始计数，白白占掉了 256 种可能中的一种。

* **2038 年问题**

    * > **定义**：用 32 位整数记录时间，起点是 1970 年 1 月 1 日这个“纪元”（epoch），到 2038 年的某个特定日期整数溢出。

    * 起因不是恶意输入，而是人类不太擅长未雨绸缪：至今仍习惯用 32 位整数记时间，32 位整数的所有可能组合终将被耗尽。
    * 要避免它必须所有人都把计算机升级到 64 位计数器；所幸绝大多数现代硬件（Mac、PC 和手机）已经是 64 位技术。

### 堆、栈与内存释放

* **`malloc` 的分配区域**

    * 正确答案是**堆（heap）**；“顶部”和“底部”在技术上并没有实际意义，堆通常只是被理解成内存的“上半部分”，这是一种艺术化的呈现方式。
    * 栈（stack）是函数调用时使用的内存区域：每次调用函数都会在栈上获得一个栈帧，局部变量和函数参数就存放在这里。
    * 在 C 语言里，用 `malloc` 分配的内存实际位于堆上。

* **内存泄漏（memory leak）**

    * > **定义**：每次 `malloc` 之后没有 `free`，定义上必然产生内存泄漏。

    * > **易错点**：某些场景下也可能出现段错误或栈溢出，但那不是“不调用 `free`”的直接后果 —— 它们属于相关但不同的问题（用了过多内存，或对内存操作不当）。

### 编译链条与链接

* **编译的四个步骤**

    * 预处理：处理 C 语言里所有以 `#` 开头的指令（`#include`、`#define` 之类）。
    * 编译：把你的代码真正编译成汇编语言。
    * 汇编：由汇编器把代码转换为机器码。
    * 链接：最后一步；现场有 54% 的人答对“解释”不属于编译步骤，也有 29% 的人选了“链接”，同样错。

* **链接的产物**

    * > **易错点**：链接是把你的二进制代码与 CS 50 库、标准输入输出库的二进制代码等合并在一起，最终生成一个像 `hello` 这样的可执行程序。

### 指针的存储与运算符

* **指针存的是什么**

    * 正确答案是**变量的内存地址**（现场约 200 份回答中有 96% 选对）；指针本身只存地址，取值要靠解引用。

* **`&` 与 `*`**

    * `&`（与号）是取址运算符，返回变量的内存地址。
    * `*`（星号）在大多数情况下恰恰相反，是指针解引用运算符，用于访问该地址所指向的内容。
    * C 语言里并不存在“点加星号”这种写法，不过它在概念上相当于星号和点的组合，用于解引用指针并访问结构体内部的成员。

### 运行时间的上界

* **大 O 的含义**

    * > **定义**：大 O 表示运行时间的上界，而不是某一次搜索运气有多好。

    * 线性搜索可能运气好很快就找到，但最坏情况下要一直遍历到列表末尾，所以它的运行时间是 $O(N)$。
    * 它可能是 $\Omega(1)$，但不会写成 $O(1)$ —— 至少在考虑最坏情况时不能这么写。

### 队列与栈

* **队列（queue）**

    * > **定义**：遵循先进先出（FIFO）的数据结构。

    * 就像在餐厅或商店排队，公平地说第一个排队的当然也该第一个被服务。

* **栈（stack）**

    * > **定义**：遵循后进先出（LIFO）的数据结构。

    * 就像食堂里的餐盘，第一个放进去的实际上会是最后一个被取出来的。

### SQL 去重与列约束

* **`DISTINCT`**

    * > **定义**：用于从 `SELECT` 查询返回的结果集中过滤掉重复项的 SQL 命令。

* **`UNIQUE`**

    * 它也是 SQL 里的一个关键字，但用于在数据库模式中定义某一列的值必须唯一（比如电子邮件地址那一列），并不是查询时去重的方法。

### 事务与竞态条件

* **SQL 内置的事务手段**

    * `START TRANSACTION`、`COMMIT`、`ROLLBACK` 三者确实都是 SQL 的特性，即使在问题集 7 或 9 里未必用得上。
    * 它们是讨论牛奶买多这类竞态条件时引出的手段。

* **登记（enroll）**

    * 登记不是一条 SQL 命令，因此它就是“哪一项不属于 SQL 内置的、用于处理竞态条件的功能”的答案。

### HTTP 状态码与重定向

* **418 我是茶壶**

    * 正确答案不是 404、403 或 401，而是“418 我是茶壶”；能记住这个，在计算机科学圈子里就算内行了。
    * > **注意**：它实际上并不是什么实用的技术 —— 多年前的一个愚人节玩笑，一群计算机科学家聚在一起专门制定了一套完整的规范，来定义服务器返回 “418 I'm a teapot” 的具体含义。

* **`safetyschool.org`**

    * 访问这个域名会返回一个 **HTTP 301 重定向头**，指示它实际位于 `yale.edu`，所以答案是耶鲁大学。
    * 原因是耶鲁有一位校友为了这个玩笑，每年支付大约 10 美元，并且已经持续了大约 20 年。

### DNS

* **域名系统（Domain Name System，DNS）**

    * > **定义**：把域名转换成 IP 地址。

    * DNS 是你家庭网络、ISP 网络、校园网络或公司网络中的一台服务器，专门为你解答这类问题。
    * 它与“加密在暗网上发送的数据”无关。

## 本地开发环境

* **`cs50.dev` 是什么**

    * 它其实是对一款名叫 GitHub CodeSpaces 的商业工具的改编版本，而 CodeSpaces 本质上就是**云端版的 VS Code**。
    * VS Code 是微软推出的一款主开源工具，在业界广受欢迎。
    * 尽管这个环境集成了 CS 50 的库、默认关掉了部分菜单选项、并禁用了 AI 功能，它骨子里仍是全世界许多程序员每天真正用来写代码的工具 —— 你一直在学的其实是行业标准。

* **脱离定制环境**

    * 你完全可以继续用 `cs50.dev` 完成期末项目，如果觉得更顺手的话。
    * 也可以在自己的 Mac 或 PC 上安装原版 Visual Studio Code；安装过程本身相当简单，但根据打算用它写什么语言，难免遇到技术支持上的麻烦 —— 比如想用它写 Python，就可能还需要单独下载并安装 Python 环境。
    * 想用最新版本的人得提前知道：有时候就是会出现各种问题导致跑不起来，这时需要去谷歌搜一搜，或者问问 ChatGPT；这种事其实挺常见的。

* **第 0 周为什么不装这些**

    * 好让大家专注于 “Hello, World”、“马里奥”、“现金” 和“信用”这些项目，真正体验计算机科学与编程里有趣的那一部分，而不是被技术支持问题搞得失去学习热情。
    * 现在大家进度各不相同：比较熟练的同学已经能自己处理这类技术问题了，当然也可能一切都会异常顺利。

* **Docker 路线**

    * > **定义**：一项容器化技术，可以在自己的 Mac/PC 甚至云端跑起 CS50 环境，同时仍然能在自己的设备上使用 VS Code。

    * 好处之一是你不必完全依赖某个平台。
    * 你完全可以离线完成所有操作，这在通常情况下非常实用。
    * 有时用上自己电脑的全部性能（而不是只靠浏览器）也会更高效。
    * 程序员通常就是用这种方式干活 —— 用 VS Code 或同类工具。

* **集成开发环境（IDE）与命令行**

    * 目前最流行的可能是三款：Visual Studio Code 本身、Cursor、Windsurf，此外还有数十种其他文本编辑器，它们通常被统称为集成开发环境。
    * 用 Mac 的同学可以在“实用工具”（Utilities）文件夹里找到“终端”（Terminal）；Windows 系统也有类似功能。
    * 它们不一定包含 CS 50 里用到的全部开发工具，但可以照着官方文档把相同的工具装到自己机器上，这样在命令行环境下操作会更得心应手。

## 版本控制与协作

* **Git**

    * > **定义**：通过一个中央云服务器共享你的代码、从而实现多人协作的代码版本控制工具；你能追踪代码的多个版本以及所做的修改。

    * 在 CS 50 里其实是在它之上做了抽象化教学：如果在 `cs50.dev` 上用过时间线功能，你就能回滚到代码的早期版本 —— 课程其实一直在用 Git，只不过一直在替你执行那些命令。
    * 官方文档里有课程团队的 Brian Yu 专门录制的教程，介绍真正的 Git 用法。

* **实时共享（Live Share）**

    * VS Code 的功能：其中一人登录自己的代码空间，点几下按钮把访问权限分享给一起做项目的朋友或伙伴。
    * 之后你们就能像用 Google Docs 那样，在同一个代码空间里实时地编辑代码或不同的文件。
    * 想在期末项目里和伙伴一起做时，这比从零开始学 Git 协作要简单一些。

## 网站部署与学生资源

* **GitHub Pages**

    * 用于托管纯前端网站：只需要 HTML、CSS 和 JavaScript，不需要 Python、Flask 或者任何后端支持。
    * 适合个人作品集网站或单纯发布一些静态内容，一次性写完并部署掉是不错的起点。

* **Netlify**

    * 同样很受欢迎，提供免费的基础账户。

* > **易错点**：一定要说清“Web 应用”和“静态网站”的差别 —— 说“Web 应用”时，指的不只是 HTML、CSS 和 JavaScript，还可能包括 Python、服务端 JavaScript、Ruby 或其他多种语言；这意味着除了前端之外，你可能还需要后端支持，甚至可能还需要数据库。

* **面向学生的免费资源**

    * 亚马逊、微软、谷歌、Cloudflare 都提供面向学生的账户类型：如果你使用 `.edu` 邮箱地址，或者用其他方式证明自己目前的学生身份，通常就可以注册享受折扣甚至免费使用同样的服务。
    * 也就是说，在你学习的过程中是不需要付费的。
    * GitHub 有类似的“学生开发者工具包”。
    * 其他 Web 应用托管平台流行的包括 Heroku、Vercel 以及其他许多服务。

## AI 工具与人类专家

* **AI 在项目中的边界**

    * 在期末项目中再次借助 AI 时，依然欢迎并鼓励你用它来提升自己的生产力。
    * > **易错点**：但不是让它替你完成所有工作；小黄鸭的设计功能相当有限，作为“良师”很称职，可作为构建项目的最佳搭档就不一定了。

* **值得尝试的工具**

    * ChatGPT、Claude、Gemini、GitHub Copilot、OpenAI Codex 这些当下流行的工具。
    * 最容易上手的是 GitHub Copilot：只需按 `cs50.readthedocs.io` 上的文档说明，在你的 CS50 代码空间里启用它 —— 文档会告诉你具体步骤，让你能重新启用 AI 功能（既然期末项目已经允许使用），并把那些默认被禁用的特性全部打开。

* **人类专家**

    * 程序员和技术爱好者多年来常去的地方包括 Reddit、Stack Overflow 和 Server Fault。
    * 讽刺的是，如今所有那些 AI 模型正是基于这些平台积累的问题与答案进行训练的，这也不禁让人担心：如果所有人都只依赖 AI，这些地方未来或许会在某种程度上逐渐失去生存空间。
    * 但当你真正需要有人参与时，它们依然是很好的选择。

* **资讯**

    * 科技领域可以看 TechCrunch，另有 Hacker News；科技与计算机领域的新闻平台还有很多，大概率也有你常用的那几个。
