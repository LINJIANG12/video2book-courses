# Python 编程与数据建模

## 执行模型与性能代价

### 编译型与解释型

* **解释型代码（interpreted code）**

    * > **定义**：写 Python 时运行的代码，由计算机逐行、从左到右"读"你的代码，相当于在两种语言之间做逐句翻译。

    * Python 不只是一种编程语言，它本身就是一个能理解 Python 代码的程序，作用位置与 C 的编译器 clang 对应；写完直接执行解释器，全部编译步骤都免了。

    * 翻译开销就是解释的开销，这是"更高级语言"需要付出的时间代价。

* **字节码（bytecode）**

    * 实际使用的解释器在底层会替你做优化：把代码半透明地编译成一种叫字节码的中间形式，然后直接运行这些字节码。

    * 这比一遍遍重新解释源代码高效得多，社区长期以来一直在对付解释开销。

* **执行链路对照**

    ```text
      C                                Python

      source file                      source file
         |                                 |
         v                                 v
      clang / gcc  (compile)          compiled to bytecode
         |                                 |
         v                                 v
      machine code (0s and 1s)        Python VM executes it
         |                                 |
         v                                 v
      CPU runs it directly            CPU runs the VM
    ```

    * C 侧最终由 CPU 直接执行机器码；Python 侧最终由 CPU 执行的是虚拟机，虚拟机再去执行字节码。

* **用 Python 重写拼写检查器**

    * 约 19 行（其中大半还是空行）就能重写完整个 C 版：声明全局 `words = set()`，再写 `check`、`load`、`size`、`unload` 四个函数。

    * `set()` 创建一个能存大量单词并自动去重的集合，等于自动实现了一遍在 C 里要手写的哈希表；`check` 的函数体只有一行，把单词转成小写再问它是否在集合里。

    * `size()` 直接返回集合长度 `len(words)`；`unload()` 因为根本没有手动分配过任何内存，照样 `return True` 什么都不做。

    * `load` 把文件全部内容读进来、按换行符切分后一次性灌进集合，再假设一切运行正常返回 `True`。

* **速度代价**

    * 同一份大型词典的拼写检查，Python 版总耗时 1.87 秒，C 版为 1.32 秒；两边输出的疑似拼写错误是同一批词。

    * 这 1.32 秒只含 CPU 真正花在处理上的时间，不含把所有东西打印到屏幕那部分额外开销。

    * 结论是用 Python 解决问题确实更容易，代价是代码跑得更慢，只差半秒但占各自窗口里的比例相当可观。

## 样板代码的消失与库的组织方式

### 第一个 Python 程序

* **只有一行的程序**

    ```python
    print("hello world")
    ```

    * 相对 C 版消失的东西：没有 `#include`、没有编译器、没有 `int main(void)`、没有花括号，只剩一对小括号。

    * `printf` 变成 `print`；不需要手动敲 `\n`，写完一行光标已经自动跑到下一行；行末不需要分号。

    * 人们慢慢意识到多数时候更希望自动换行而不是手动控制，于是就把默认行为改成了自动换行。

* **为什么没有 main 函数**

    * 人们几乎总是希望自己正在编辑的那个文件成为程序的主要部分，如果只想写两行代码完成一件事，何必多此一举加上样板代码。

    * 现实中这样写的东西常被叫作脚本：一种轻量级程序，基本上就是从上到下、从左到右顺序执行。

    * 同样的方向也出现在 Java 上——现在不必把代码全塞进一个类里、不必再写 `public static void main` 那种结构。

* **辅助轮：CS50 的 Python 库**

    * 库分两类：语言自带的标准库，和需要自己下载安装的第三方库。

    * 导入写法 `from CS50 import get_string` 语法稍显冗长，但好处是能更精确地指定想从库里导入什么，尤其是不想把整个库都塞进内存的时候。

    * 多个函数可以分开导入 `from cs50 import get_int, get_float, get_string`，也可以直接整库导入再通过稍有不同的语法调用。

    * 这个库和 C 版 CS50 库都像辅助轮，作用只是把"哪些相同、哪些不同"标出来以平滑过渡，应该尽快卸掉。

* **模块与包**

    * > **定义**：模块（module）是可被导入的功能单元；包（package）就是模块的集合。

    * C 里只有头文件，头文件让你能访问库中函数的原型，也就是你想调的那些函数的签名；Python 语境里模块常常就等于库，讨论模块或包其实在聊使用库。

## 字符串输出与格式化

### print 的函数签名

* **print 的原型**

    ```python
    print(*objects, sep=' ', end='\n', file=None, flush=False)
    ```

    * > **定义**：函数签名只告诉你函数名、它接受几个参数、参数是什么类型。

    * `*objects` 这种写法表示零个或多个对象，无论什么类型——数字、字符串、别的都行。

    * `sep` 指定打印参数之间的分隔符，默认值就是一个空格；`end` 指定每次打印完接什么，默认值是 `\n`。

* **获取用户输入**

    * `input` 目前只从键盘取输入并返回一个字符串，功能上与 C 版的 `get_string` 一样，通常就是你获取用户输入的方式。

    * Python 里不需要声明变量类型：返回字符串就存字符串，返回整数就存整数，解释器会根据上下文自己推断。

* **三种拼接写法**

    * 用加号连接：`print("hello, " + answer)`，在字符串语境里 `+` 表示把左右两侧拼接起来，这和 Scratch 里的拼接积木功能一致。

    * 用多个参数：把加号换成逗号、引号里的空格去掉，`print("hello,", answer)`，分隔用的空格由 `sep` 默认值提供。

    * 用 f 字符串：`print(f"hello, {answer}")`，花括号里写变量名表示该变量的值会被替换到那个位置，解释器对它做了插值。

    * > **易错点**：f 字符串必须紧挨着引号写一个大写 `F`。漏掉这个 `F`，你得到的就是一个普通的文本字面量，花括号里的内容会被当成普通字符原样打印。

    * 用花括号不必记住它对应的是哪个变量，而用百分号占位符得记住对应关系，挺烦人的。

* **引号风格**

    * Python 里字符串双引号单引号都能用，不像 C 那样严格区分字符串与字符；关键是保持一致，选一种然后坚持用。

    * 唯一需要交替使用的情形是字符串本身里要包含撇号，比如人名所有格里包着的那一个 `'`，这时双引号串里用单引号或反过来。

    * 官方文档偏向单引号，JavaScript 社区也是；各公司一般都有自己的风格指南明确该用哪种，哪怕只是为了全项目风格统一。

## 变量与数据类型

### 类型推断

* **没有类型声明**

    * `counter = 0` 一行就完成变量创建，类型声明以及更一般的"数据类型"这件事整个消失；一个聪明的解释器完全能根据上下文推断出你放进去的是整数。

    * 类型在底层真实存在，知道一些很有必要，否则会遇到某些难以察觉的错误。

* **类型对照**

    | C | Python |
    | :--- | :--- |
    | `bool` | `bool` |
    | `char` | 没有对应物 |
    | `double`、`float` | `float` |
    | `long` | `int` |
    | `string`（其实是 `char *`，来自 CS50 库） | `str` |

    * C 那一列的 `string` 归功于 CS50 库，它其实是一种字符指针，即某个字符的地址。

    * > **易错点**：这张表里完全没有指针，更不用说字符指针。内存管理强大伴随着一整套可能犯错的模式，Python 这类语言试图移除 C 里那些过于危险的功能——它们可能非常强大，但如果带来的麻烦多于价值就得不偿失。

* **自增写法**

    * 计数器加 1 在 Python 里写 `counter = counter + 1`，缩写 `counter += 1` 在两边都能用。

    * > **易错点**：C 里的 `++` 和 `--` 在 Python 里没有，语法上允许你写它们但它们根本不存在，写了只会报错，所以你会更常看到 `+= 1` 这种写法。

### 类型转换

* **类型名变成函数**

    * > **定义**：C 里做类型转换是 cast，Python 里做的是 convert——数据类型本身变成了一个函数，接收一个参数，就是你想转换的那个字符串。

    * C 里 `get_int` 之所以能拿到整数，也是靠类型转换；但底层其实是整个 `1` 加一个空字符、整个 `2` 加一个空字符，不是字符转整数那种直接的活儿。

* **input 返回字符串引发的陷阱**

    * 把计算器改成纯 `input` 版后，输入 1 和 2 输出的却是 `12`：在字符串语境里 `+` 表示连接，`input` 返回的是用户敲下的按键字符。

    * 解法是把 `int` 直接嵌进表达式 `print(int(x) + int(y))`，属于嵌套函数调用，`input` 的输出被直接当 `int` 的输入。

    * > **易错点**：`input` 拿到的是字符而不是数字。输入 "cat" 或 "dog" 时转换会失败，这需要额外的错误处理。

* **注释**

    * 注释惯例从 `//` 换成 `#`，按一次键就够，敲键次数直接减半。

## 条件与循环

### 条件语句

* **冒号与强制缩进**

    * > **定义**：Python 去掉了条件的括号和代码块花括号，取而代之的是强制要求缩进——用冒号引出后续的缩进块，条件为真时按惯例缩进 4 个空格。

    * 花括号在 C 里条件只有一行时技术上可以省略，但为了风格一致通常还是保留；Python 完全不要求它。

    * 你不能偷懒把代码全部左对齐、想着以后再靠工具自动整理，这种习惯在 Python 里行不通，新手和专业人士都会栽。

    * 括号和花括号能省，省下来的注意力就投给结构本身，代码因此更具可读性。

* **elif**

    * C 的 `else if` 在 Python 里写作 `elif`，这可能是最紧凑的写法。

    * 你当然也可以老老实实写成 `else` 加 `if` 两个词，其他部分完全一样，包括这次同样需要冒号。

### 循环结构

* **while 循环**

    * 几乎从 C 原样搬过来：不用再指定数据类型，分号、括号、花括号都没了，`++` 换成 `+=`，剩下的只有冒号和随后的缩进。

    * 无限循环写成 `while True:`，因为这个布尔表达式按定义恒为真，循环永远不会停止。

    * > **易错点**：C 用小写的 `true` 和 `false`，Python 用首字母大写的 `True` 和 `False`——这个大写的 `T` 确实得写。缩进必须始终保持一致、冒号也必须留着，这两点一旦错位，语法错误或者死循环就来了；中断循环和 C 一样用 `Ctrl + C`。

* **for 循环与 range**

    * Python 的 `for` 不像 C 那样把初始化语句、布尔表达式、更新语句用分号隔开写在一起，你只要用接近自然语言的说法表达，比如"对于列表中的每一个 i"。

    ```python
    for i in [0, 1, 2]:
        print("meow")
    ```

    * 方括号写起来像 C 的数组，但在 Python 里创建的是列表，元素是任意对象；`[0, 1, 2]` 里的三个数没有引号包围，所以是整数。

    * 手写元素的不足是：要执行超过 3 次操作，30 个甚至 300 个数字得一个一个敲进去。

    * > **定义**：`range` 严格说不是一个普通的数据类型，更准确地说它是一个函数，调用它生成一个从零开始的一系列数值，`range(3)` 返回的正是 0、1、2。

    * 它不会一次性返回所有数字，3 个、30 个、300 个还是 300 万个都是逐个返回的，所以迭代次数增加也不会占用更多内存。

    * 跳着数也行：遍历所有奇数、所有偶数、调整递增步长都可以；最标准最常见的方式是一个一个递增。

    * > **提示**：使用 `for` 循环时必须为它指定一个变量，哪怕根本不用；命名为下划线 `_` 是符合 Python 风格的写法，表明"此处声明变量是语法需要，但实际不会用在别处"。

* **缺失的 do-while**

    * > **定义**：`do { } while (c);` 在 Python 里的等价物是 `while True:` 配合一个 `break`，先执行再判断的语义靠"无条件进循环、拿到就跳出来"手动补上。

    ```python
    while True:
        n = int(input("Height: "))
        if n > 0:
            break

    for i in range(n):
        print("#")
    ```

    * C 的 `for` 三段式——初始化、继续条件、每轮之后做什么——在 Python 里被拆成两件事：`range(n)` 说清楚"转几圈"，循环体说清楚"每圈干什么"。

    * > **易错点**：`while n:` 判断的是 `n` 这个对象本身是不是真值，而整数 `2` 恒为真，所以这样的循环永远不会结束。Python 里 `while 2:`、`while 5:` 是合法的，含义就是"永远为真"，整数不会像 C 那样被隐式转换成 0/1 来做真假判断；想写条件就老老实实写 `while n > 0:`。

    * 不推荐的替代写法是把条件写两遍：先无条件进来，再用 `continue` 跳过不合格值、`break` 出去，绕了一圈；套一层 `while True:` 永远比"把条件写两遍"清晰。

* **循环打印图形**

    * `print` 的 `end` 决定"每次打印完之后接什么"，`sep` 决定"多个参数之间用什么隔开"；传 `end=""` 就是什么都不接。

    * 不带任何参数的 `print()` 做的事情就是换行，循环打印并排图形之后要靠它收尾。

    * `print("?" * 4)` 让问号重复四次，和用加号拼接字符串是同一个思路，只是乘法在这里天然表达了"重复"。

    * 二维图形每一行内容完全相同时，用字符串乘法替掉内层循环，代码从 4 行缩到 2 行，而且更好读。

    * > **易错点**：内层循环里不要忘了覆盖 `end`，否则每打印一个字符就换一行，网格会碎成一列；内层循环之后还得补一条 `print()` 才能让每行之间也换行。

    * 把循环变量从 `i`、`j` 改名为 `row` 和 `column`，语义上能让读的人一眼知道自己在做什么。

## 函数、调用顺序与作用域

### 先定义再调用

* **NameError 的来源**

    * > **定义**：Python 用 `def`（define）加函数名和括号定义函数，不指定参数类型也不指定返回类型；即使函数不需要任何输入也不需要 `void` 关键字。

    * Python 虽然在语法上很智能，处理这件事时仍然有些天真：它是从上往下逐行执行的，在定义那一行之前这个名称都还不存在。

    ```text
    line 1   for i in range(3):
    line 2       meow()          <<-- called here
    line 3
    line 4   def meow():         <<-- the name is born here
    line 5       print("meow")

    => NameError: name 'meow' is not defined
    ```

    * C 的老办法是"临时拼凑"：先在文件顶部声明函数原型，再把实现挪到下面；把调用挪到文件末尾程序立刻能跑通，但程序的核心部分会被推到屏幕最底部。

    * C 的原型方案在 Python 里行不通，你不能把第一行代码复制到文件顶部、加个分号，然后指望它能运行。

* **显式调用 main**

    * > **定义**：Python 的做法是把代码放进一个 `main` 函数里，然后在文件末尾调用 `main()`，到那时被调用的函数都已经存在了。

    ```text
    def main():              1. define main first
        meow(3)              2.   it calls meow ...
    def meow(n):             3. define meow right below
        for i in range(n):
            print("meow")
    main()                   4. only now is main() called
    ```

    * `main` 在 Python 中没有任何特殊含义，只是沿用其他编程语言惯例、借用它们主函数的命名方式。

    * Python 不会仅仅因为你创建了一个叫 `main` 的函数就自动调用它；忘了最后那行调用，运行时什么都不会执行。

    * > **注意**：C、Java、C++ 中 `main` 按定义会被自动调用，Python 没有这种特殊的"魔法"，在末尾手动调 `main()` 是常规做法。

    * 常见的模块化写法是加一层条件判断，让那些除了定义函数之外什么都不做的文件可以被导入：

      ```python
      if __name__ == "__main__":
          main()
      ```

    * 函数之间留两行空行是 Pythonic 的编程规范，C 语言里没有这样的惯例。

    * 倒着数当然可以，换一种方式使用 `range` 从一个较大的数值开始递减计数即可；用 `while` 循环也能实现，但一般不建议。

### 作用域与变量创建

* **花括号不管作用域**

    * > **定义**：Python 没有像 C 那样严格框死变量——如果当前作用域里没有更具体的同名变量，就往上找，找到就用。

    * 因此在 `while` 循环体里赋值的变量，可以在循环外的 `for` 里继续使用；从 C 过来第一反应会觉得这不对，但语法上完全没问题。

    * 那个程序大概率比你手写一堆声明加赋值还要短。

* **变量在第一次赋值时被创建**

    * > **定义**：Python 的变量不是"先声明、后赋值"，而是在第一次赋值的那一刻被创建出来，类型也随之确定；没有办法只写一个空的声明让它先存在着。

    * 赋值号左边同时干了三件事：创建变量、给它定类型、给它赋值。

    * > **易错点**：不要在 Python 里找 C 的"先声明一个变量占位"这种写法。变量名单独占一行在 C 里是合法的，在 Python 里是 `NameError`。

## 列表

### 内置数据结构

* **语言自带的结构**

    | Python 类型 | 它替你解决了什么 |
    | :--- | :--- |
    | `range` | 数字范围，内置 |
    | `list` | 数字列表，像数组的升级版，解决了数组的缺点 |
    | `tuple` | 元组，用来表示像 x、y 这样的坐标点 |
    | `dict` | 字典，直接提供键值对，不用自己写哈希表 |
    | `set` | 集合，存唯一值集合，检查元素是否存在非常方便 |

    * C 里主要只能从语言本身拿到数组这一种数据结构，其他结构要么自己实现，要么至少要在课上讨论怎么构建；现在这些连同更多东西全都内置在语言里了。

* **列表是对象**

    * > **定义**：Python 的列表是一个对象，不只是数据，还自带一堆函数——"这个列表多长"和"把这些加起来"这两件最常做的事被做成了内置能力。

    * C 的数组有一个很讨厌的性质：你必须自己记住它有多长，因为运行时它并不知道自己几个元素，所以从课程一开始就要在声明数组的同一行声明一个 `length` 变量，每次塞东西都记得 `length++`。

    * `len` 是 length 的缩写，`sum` 把列表里所有元素相加，`sum(scores) / len(scores)` 就是小学算术里的"全部加起来除以个数"。

    * 变量名用复数 `scores` 比单数 `score` 准确，毕竟里面装的是一堆分数。

* **append 与动态长度**

    ```python
    scores = []

    for i in range(3):
        score = int(input("Score: "))
        scores.append(score)

    average = sum(scores) / len(scores)
    print(f"Average: {average}")
    ```

    * 空列表就是一对空的中括号；`append` 就是"追加"，通过点运算符访问：先是变量名，然后一个点，然后方法名，最后把要追加的值作为参数传进括号里。

    * C 里这一步很啰嗦：要用方括号表示法、要记下标、还得记得自己已经写到第几个了，否则就越界。

    * 先问"你想输几个分数"、用那个数字替掉循环里的 `3`，才真正做到不预先决定列表有多大。

    * > **提示**：`int(input(...))` 是固定套路，用户输入非数字内容时 `int()` 会直接抛异常把程序炸掉；严谨的写法应该包一层 `try` / `except`，再用 `continue` 跳过这一次。

## 字典与数据建模

### 键值对与索引

* **字典就是哈希表**

    ```text
    姓名（键 key）      号码（值 value）
    ----------------------------------------
      "Kelly"        →   "+1-617-495-1000"
      "David"        →   "+1-617-495-1000"
      "John Harvard" →   "+1-949-468-2750"
    ```

    * > **定义**：Python 的字典本质上就是一张哈希表，让你能把某些数据与其他数据关联起来；它就是一组键值对的集合。

    * 用花括号开启一个字典，把一系列键值对写在里面；结构图里的每一行，代码里就是一行。

    * 在 C 里用哈希表这类结构在内存里存储大量数据是一项相当复杂的任务，而字典相当于用 Python 自己的语法手搓了一张哈希表。

* **成员检查与取值**

    * `in` 这个介词在字典上同样理解为成员关系检查，键在字典里返回 `True`，不在返回 `False`。

    * 取值靠方括号表示法 `people[name]`，再套一条 f 字符串就能把号码打印出来。

    * > **易错点**：数组用数字索引，字典用字符串索引。`people["David"]` 里的 `"David"` 是一个键，不是一个位置。

    * 字典的强大不限于 Python，其他语言也一样：你可以像索引数组一样索引字典，只是键从数字变成了字符串。

### 字典的列表

* **一张电子表格**

    * 数据库里的一行数据本质上就是一个字典，一张表就是一个字典的列表——带图形界面的精美表格，底层写的就是这个结构。

    ```text
    ┌────────────────────┬──────────────────────┐
    │ name               │ number               │
    ├────────────────────┼──────────────────────┤
    │ Kelly              │ +1-617-495-1000     │
    │ David              │ +1-617-495-1000     │
    │ John Harvard       │ +1-949-468-2750     │
    └────────────────────┴──────────────────────┘
    ```

    * 每一行代表一条不同的记录、一个不同的数据片段；而表里还缺元数据——现在的模型只有两个属性，还可以加第三列乃至任意数量的其他数据。

    ```python
    people = [
        {"name": "Kelly", "number": "+1-617-495-1000"},
        {"name": "David", "number": "+1-617-495-1000", "email": "malan@harvard.edu"},
        {"name": "John Harvard", "number": "+1-949-468-2750"}
    ]
    ```

    * 外层方括号表示这是一个列表，元素是逗号隔开的字典；此时逗号是在同层的键值对之间做分隔，每个字典的键值对数量可以不同。

    * 好处立刻兑现：想找邮箱地址就把代码里的 `"number"` 改成 `"email"`，想找别的信息改那一处就行。

* **在列表里查找**

    * 这时 `if name in people` 不再成立，因为 `people` 是一个列表，名字藏在每个小字典的 `"name"` 键里面，Python 没法直接比。

    * 必须遍历，但遍历方式只是换了一下：每次迭代里 `person` 被依次赋值为各个字典，检查 `person["name"]` 等不等于要找的姓名。

    ```python
    for person in people:
        if person["name"] == name:
            number = person["number"]
            print(f"Found: {number}")
            break
    ```

    * 这里用到的语法全是之前在小规模示例里见过的，没有新东西，只有嵌套。

    * 严格说先把值起进一个变量只用一次有点多余，f 字符串完全可以直接塞进花括号，但引号嵌套会让它难以阅读。

## 成员检查、线性搜索与异常

### for-else

* **循环的 else 子句**

    * > **定义**：`for` / `while` 循环的 `else` 子句，只有在循环自然跑完时才执行；只要循环过程中执行过 `break`，`else` 就被跳过。

    ```text
    for n in names:
        if n == name:
            print("Found")
            break          ← 命中走这条，else 被跳过
        # 继续往下遍历
    # 循环自然结束（一次 break 都没有）→ 执行 else
    else:
        print("Not found")
    ```

    * 语义上有点奇怪——`else` 怎么会和 `for` 扯上关系——但规则很干净：把整个列表从头到尾走了一遍、一次 `break` 都没调用，说明真的没找到。

    * 这个模式在实践中非常常见：在循环里跟踪某个事件是否发生，发生了走 A，没发生走 B，是循环相关特性里最独特的设计之一。

    * 在 C 里想这么干，要么用一个变量记录"到底找到没有"，要么在函数里提前 `return` 掉。

* **in 运算符**

    * `x in 集合` 是一个真正的语言特性，不是一个语法糖——它把"遍历 + 比较 + 返回布尔值"这一整套固定套路收进了运行时。

    * Python 内部做的仍然是从头到尾遍历整个列表，找到就返回 `True`，走完还没找到就返回 `False`，底层逻辑一点没变。

    * 变的是你不需要手写那个遍历，直接表达你的意思就行，`if name in names` 读起来已经非常接近自然英语。

    * 双等号背后其实也藏着一个循环（`for` 也好 `while` 也好），逐个字符地把两个字符串走一遍才给出那个答案。

### 哨兵值与异常

* **C 的错误反馈方式**

    * > **定义**：在 C 里，返回值是函数向程序员反馈错误情况的唯一途径，通常做法是返回一个特殊值——最常用的是 `NULL`，技术上就是零地址 `0x0` 这个特定哨兵值。

    * 其他函数出问题则要检查返回值是否为 0、-1、1 之类的特定值。

    * > **易错点**：这套办法有个绕不开的别扭。一个本应返回整数的函数可能正数、负数、零都可能合法，你却不得不占用其中一个值来表示"这个值不可用"；指针世界还好办，因为业界约定永远不用 `0x0` 这个实际地址，但技术上它仍然占用了空间。

* **try / except**

    ```python
    try:
        n = int(input("Number: "))
        print("integer")
    except ValueError:
        print("not integer")
    ```

    * 语义很直白：请尝试执行这几行代码，但如果冒出 `ValueError` 这样的错误，就改去执行其他操作，这样就不需要检查任何返回值了。

    * 第 2 行成功则第 3 行成功、异常处理段不触发；第 2 行失败则第 3 行永远不被执行，Python 立即跳转到异常处理器抓下这个错误。

    * 问题的核心是**盲目地**把用户输入转成整数，即使输入根本不是整数；`ValueError` 的含义是 `int()` 无法把输入转换成以 10 为基数的整数。

    * 更早的替代方案是先用 `isnumeric()` 判断再转换——字符串提供 `isnumeric()` 用来判断它看起来是不是一个数字，数字就能断定是整数，否则可能是 "cat"、"dog" 或数字与字母的混合体。

    * 标准异常类型通常采用首字母大写的格式，比如 `ValueError`、`TypeError`；良好实践是预先枚举自己认为可能出错的各种情况，甚至自定义异常。

    * 文档中列出了许多不同的异常类型可供捕获，但 Python 的文档在"记录特定函数会抛出哪些异常"这件事上有所欠缺，实际开发中遇到意料之外的异常就得回头补捕获子句；也有第三方库在这方面说明做得更好。

    * 由此倾向于建议给 Python 版的 `get_int` 和 `get_float` 加更完善的异常处理：功能与 C 版完全一致，输入 "cat"、"dog"、"bird" 这类非数值内容时自动重新提示，直到拿到有效输入。

## C 语言遗留缺陷的修复

### 除法截断

* **整数除法的行为**

    * > **易错点**：在 Python 中，即使你操作的都是整数，当一个整数除以另一个整数、结果在逻辑上应该是一个浮点数值时，你拿到的就是浮点数结果，不需要像 C 里那样费劲地强制转换类型。

    * C 里 1 除以 3 奇怪地显示为 0、4 除以 3 显示为 1，小数部分全部丢失；即使使用浮点数，截断机制仍会直接舍弃所有小数部分。

    * 想要旧版行为它也仍然存在：用两个斜杠 `//` 就是整数除法，而不是现在这种除法。

### 浮点精度

* **精度的上限**

    * 1 除以 3 本应是无限循环小数，但结果显示的是最接近它的有限近似，末尾会出现一些奇怪的数字。

    * 在花括号中的变量名后面加一个冒号、再加一个点号、指定一个格式 `f"{z:.50f}"`，可以像 C 的 `printf` 用 `%f` 那样看到大约 50 位数字。

    * > **易错点**：加到 50 位并不会让结果更正确。内存仍然是有限的，即使明确处理的是浮点数，Python 也只分配了大约 64 位给这些浮点变量，精度只能达到这个程度；看到的是二进制浮点表示法所能表达的、最接近 0.333... 的近似值。

    * Python 生态里有更多第三方库可以自定义浮点数的表示方式，实现 128 位甚至更多位数的更高精度科学计算。

### 整数溢出

* **动态位宽**

    * C 里计数超过 40 亿，或者在有负数表示的情况下超过 20 亿（因为负数会占用正数范围的一部分），数值会莫名其妙地回绕、变成负数，甚至最终变为零。

    * Python 的整数位数会随需要动态调整，这个被语言本身根本性限制掉的问题已经解决，是非常棒的特性。

## 方法与面向对象

### 方法的本质

* **对象内部的函数**

    * > **定义**：当一个函数被内置在某个数据类型内部，并且你通过点运算符 `.` 去调用它（而不是调用某个全局函数再把参数递进去），你用的就是方法（method）——说白了方法就是对象内部的函数。

    * 语言的设计者意识到有些功能天生就黏在它所操作的那个值上：拿到一个字符串必然会想把它转成大写、小写、首字母大写，那干脆把它们直接做进类型里。

    * 这就是面向对象编程（object-oriented programming，OOP）：变量和数据类型不仅有关联的值，还内置了相应的功能。

    * Python 里的字符串本身就是内存中的一个对象，装着用户敲进来的字，还内置了一批当初发明字符串类型的那帮人写的方法。

    * > **提示**：语法其实和 C 非常相似——C 里的 `.` 只能取到结构体内部的数据，Python 允许你走进对象内部，不光能取它的值还能调用它的内置方法。

* **字符串方法与 C 函数的对照**

    | 想做的事 | C 语言里的写法 | Python 里的写法 |
    | :--- | :--- | :--- |
    | 判断两个字符串是否相同 | `strcmp(s, t) == 0`，还要 `#include <string.h>` | `s == t` |
    | 转成小写或大写 | 调 `tolower` / `toupper` 并递参数 | `s.lower()` / `s.upper()` |
    | 复制一份并把首字母大写 | `malloc` + `strcpy` + `toupper(t[0])` + `free` | `t = s.capitalize()` |
    | 把整个字符串变成大写 | 循环逐字符调用 `toupper` | `after = before.upper()` |
    | 装一组值 | 数组 | 列表（底层是可动态伸缩的链表） |
    | 重复 N 次 | `for (i = 0; i < 3; i++)` 写全三段 | `for i in range(3):` |
    | 自定义函数 | 顶部声明原型 + 下面写实现 | `def` 定义，调用写在哪儿都行 |

    * C 那边比的是 `char *`，靠 `strcmp` 逐字符比较、并依赖字符串末尾的空字符 `\0`；Python 版就是一行 `s == t`，连辅助库都不用碰。

    * `capitalize()` 把单词首字母转成大写并返回副本，原串不动；C 那边是标准的面向过程写法，要先分配空间、检查 `malloc` 返回值、逐字符复制、确认长度大于 0，再把 `toupper` 的结果写回去。

    * `for c in before` 会自动把字符串里的每个字符依次交给 `c`，不需要索引、不需要长度、不需要下标运算；既然内置了方法，压根不需要一个字符一个字符地磨。

### 规范化的位置

* **大小写匹配**

    * > **易错点**：Python 是严格按字面值查找的，列表里写的是小写 `y` 和小写 `yes`，输入全大写的 `YES` 就仍然走否定的分支——这是 bug 不是巧合。

    * 把条件一路写成 `s == "y" or s == "yes" or s == "YES"` 也能跑，但扩展性很差；真要覆盖所有大小写组合还要考虑大写锁定键开着或关着的差异，要枚举的东西立刻膨胀起来。

    * 两种修法都对：存进变量后立刻 `s = s.lower()`；或者反过来把输入统一转成大写、列表里写 `["Y", "YES"]`。

    * Python 允许把函数套起来用，`input().lower()` 一步到位；或者在做比较的那一刻才转 `if s.lower() in ["y", "yes"]:`——选哪种取决于你想把"规范化"放在流水线的哪一段。

    * 把所有可能收进一个列表时，`in` 正是用来问"这个值在不在这个列表里"的关键字。

## 命令行参数与文件持久化

### sys 库

* **sys.argv**

    * > **定义**：`sys` 库提供访问命令行参数的功能；由于默认不再有 `main` 函数而失去了的入口，现在都搬到了 `sys` 里。

    * `argv` 本质上就是一个列表——用户在命令行里输入的所有参数组成的列表；既然是列表就可以直接用 `len()` 拿长度，所以不再需要 `argc`。

    ```python
    from sys import argv

    if len(argv) == 2:
        name = argv[1]
        print(f"hello, {name}")
    else:
        print("hello, world")
    ```

    * > **易错点**：解释器本身在 `sys.argv` 里是被忽略的。`sys.argv[0]` 是脚本名本身，第一个用户参数才是 `sys.argv[1]`；C 里 `argc` 会把程序名算进去，迁移时记得把下标和计数都对齐。

    * 也可以写 `import sys` 整库导入，没有必要把库里的每个变量和函数都单独列出来——先给我全部访问权限，稍后我再告诉你具体需要哪些功能。

* **sys.exit**

    * 通过 `sys.argv` 访问参数列表、通过 `sys.exit(n)` 设置退出码，这两个能力把 `int main(void)` 的作用又还给了我们，而且完全不用写 `main`。

    * 判断条件通常写成"长度**不等于** 2"，因为必须由用户提供姓名，不再默认输出 hello world；成功时 `sys.exit(0)`，出错时 `sys.exit(1)`。

### 文件与 CSV

* **open 与追加模式**

    * `open` 对应 C 的 `fopen`；`open(..., "a")` 里的 `"a"` 是追加模式，跟 C 的模式串一个意思。

    * `csv.writer(file)` 是告诉 Python 把这个文件包装成一个可以写入 CSV 的东西，然后交给我；`writer.writerow([name, number])` 是与 writer 对象关联的方法，参数是一个值的列表。

    * Python 自带专门处理 CSV 的库，不需要通过手动加逗号这种临时拼凑的方式来实现自己的 CSV 支持。

* **with 替掉手写的 close**

    * > **易错点**：`with` 的语义确实不太直观——用 `with` 打开文件，出了这个块它就替你关掉。在 Python 里请默认使用 `with`，别再手写 `close()`。

    ```text
    with open("phonebook.csv", "a") as file:   ← 进入块：打开并绑定
        writer = csv.writer(file)
        name = input("Name: ")
        writer.writerow([name, number])
    # 缩进结束 → 无论块内是否抛异常，文件都被自动关闭
    ```

    * 一行代码完成"以追加模式打开文件并绑定到变量"，执行操作，然后一旦缩进结束、无论后面还有没有代码，文件都会自动关闭。

    * C 里得手动 `fclose`，忘记关是常犯的愚蠢错误，这类问题通常不易察觉，除非跑 Valgrind 之类的工具才能检测到，也就是所谓的内存泄漏。

    * 在 Python 里我不需要一开始就打开文件：先把变量值拿到手，写文件那一段可以放到后面，甚至整个文件都可能一个字节都不写。

* **csv.writer 与 csv.DictWriter**

    | | `csv.writer` | `csv.DictWriter` |
    | :--- | :--- | :--- |
    | 额外参数 | 无 | `fieldnames=["name", "number"]` |
    | 每行写什么 | 列表，按列顺序排 | 字典，按键名自己找列 |
    | 隐含前提 | 默认 name 在第 0 列、number 在第 1 列 | 文件里必须先有表头行 |
    | 用户在表格软件里调换列顺序 | 立刻写错列 | 照样正确 |

    * Python 自带的 CSV 模块功能相对基础：它缺少一个能够明确标识每列内容的表头行。

    * `fieldnames` 的值应该是一个列表，包含即将写入的 CSV 文件中预设存在的字段名称；关键变化是每行传的不再是列表而是一个键值对组成的字典，让字典写入器自己判断这些值应该写到哪一列。

    * `csv.writer` 那套相当脆弱，它盲目地假设姓名在前、号码在后；有人用 Excel、Google 表格或任何工具调整了数据顺序，代码就崩了。

    * 表头行直接写在文件开头比在程序里输出表头更好，因为反复运行这个程序时你不希望表头重复出现。

## 第三方库与 pip

### 安装与缺失模块

* **pip**

    * > **定义**：`pip` 是把 Python 包装进你的代码空间的程序，用 `pip install 包名` 就能自动下载并安装公开可用的库，通常装的是最新版本。

    ```bash
    pip install cowsay
    ```

    * Python 自带很多库——即使它们不是第三方库，也需要导入才能使用；不过不用安装，只要一句 `import` 加进你的代码就行。

* **ModuleNotFoundError**

    ```text
    Traceback (most recent call last):
      File ".../cow.py", line 1, in <module>
        import cowsay
    ModuleNotFoundError: No module named 'cowsay'
    ```

    * 这个错误比名称错误和值错误都要直观，它明确告诉你没有名为 `cowsay` 的模块。

    * 顺带一提，把 C 的 `printf` 拼成 `printF` 也会得到一条 `NameError` 回溯，这类随手混入的 C 习惯在迁移时要一并清掉。

### 库的使用实例

* **图像处理**

    ```python
    from PIL import Image, ImageFilter

    before = Image.open("bridge.bmp")
    after = before.filter(ImageFilter.BLUR(10))
    after.save("out.bmp")
    ```

    * 导入 `Image` 和 `ImageFilter` 两个功能模块，模糊只要一行 `filter`，四行代码就实现了 C 里的模糊功能。

    * `ImageFilter.EDGES` 和方框模糊不同，是用来检测图像边缘的，换上去再存一次就能把整幅图像的边缘都勾出来。

* **文本转语音**

    ```python
    import pyttsx3

    engine = pyttsx3.init()
    engine.say("This is CS50 course.")
    engine.runAndWait()
    ```

    * 初始化那一行是必须的，因为文档说明首次使用这个库时需要先做一次初始化。

    * `runAndWait()` 确保整段话完整播报之后程序才结束运行；虽然不像 Scratch 那样用图形化积木呈现，但原理是相似的。

    * > **提示**：这一类云端做不到，因为它是一个基于浏览器的云端开发环境——云端运行时音频无法传输到你本地电脑的扬声器上；在自己的机器上跑 Python，音频就真的能从扬声器里出来。

* **二维码生成**

    ```python
    import qrcode

    image = qrcode.make("https://youtu.be/xvFZjo5PgG0")
    image.save("qr.png")
    ```

    * `qrcode.make` 生成一个包含指定内容的二维码图像，这个函数跟 C 里的 `make` 没有任何关系。

    * `image.save` 把它保存成 PNG（便携式网络图形）文件，与 JPEG、GIF 是同类但特性不太一样。

## 文档与错误回溯

### 官方文档

* **docs.python.org**

    * Python 有一个社区维护的、被公认权威的官方文档，这一点比 C 语言突出得多。

    * 它有点类似 C 里的 man pages，但 man pages 有多个互相矛盾的版本，Python 不一样。

    * 文档里列的是 Python 自带的所有函数而不只是 `print`，往下滚到 `print` 就能看到它的函数签名，只是形式上看起来有点晦涩。

    * 字符串方法、格式化语法、`fieldnames` 这类参数往往都是靠查官方文档才发现的。

* **回溯**

    * > **定义**：这类错误信息通常被称为回溯（traceback），因为系统会沿着代码执行的路径一步步追溯错误源头，把程序在崩溃前尝试过的所有步骤都摊给你看。

    * 如果你调用了一个函数，而这个函数又调用了另一个函数、依此类推，屏幕上会看到所有这些函数调用的记录。

    * 刚接触 Python 时觉得费解的地方在于：名称明明就写在下面，报错却说它未定义——因为在定义那一行之前这个名称确实还不存在。
