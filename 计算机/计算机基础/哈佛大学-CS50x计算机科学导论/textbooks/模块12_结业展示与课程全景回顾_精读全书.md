## 结业这一讲：从一句“画个立方体”到 CS50 展览会
> 对应块：BLK31 | 覆盖分集：P12 | 块标题（分集名）：《结业展示与课程回顾》

### 消防水带之后，我们正式结业

蛋糕已经在教堂耳堂外面等着了，就像第零周结束时那样。过去十多个星期，如果你感觉自己像是被一条传说中的消防水带迎面拍过，被新内容、新技能和新挑战砸得有点喘不过气——请相信，你从来不是一个人在挨这一下。

今天有一件正式的事要宣布：如果你在开课时属于“不太适应”的那一类，从今天起，你已经正式告别这个行列了。你至少已经到了中间水平；如果你本来就在这个区间里，现在你更加游刃有余；如果你一开始就适应得很好，现在你大概已经是这里最得心应手的那批人。

但请记住 CS 50 教学大纲里的那句话：重要的不是你相对于同学达到了什么水平，而是你相对于**自己的起点**取得了多少进步。这一点会在期末项目和最终成绩评定里被充分考虑。而从教育角度说，真正关键的指标是你从第 0 周到第 10 周之间的进步幅度。

我经常在这个阶段讲一件自己的糗事：当年我在 CS 50 的第一个编程作业里表现有多糟糕。1996 年秋天，我连最简单的 “Hello, World” 都没能跑对——那是我人生中的第一个编程作业，下面是当时的实拍照片。这个程序的全部功能就是在屏幕上打印一句 “Hello, World”。我在注释里写得极其详细，甚至特意注明 “main 就是 main”（这完全不是编程规范），还专门告诉助教我的文件在哪里结束（其实根本没必要）。结果因为没按要求来，被扣了 2 分。

所以请放宽心：即使到了作业九你还在被扣分，以我的经历来看——你正与优秀的人为伍。随着时间推移，一切都会变得更顺、更轻松、更高效。

> **提示**：这门课比的不是名次，是斜率。

### 问题的本质：黑箱里装的是算法

不过归根结底，这门课的核心内容其实都浓缩在这一张图里了：

```text
   +---------+      +-----------+      +----------+
   |  input  | ---> | algorithm | ---> |  output  |
   | problem |      |  (black   |      | solution |
   +---------+     |   box)    |      +----------+
                   +-----------+
```

先有输入，也就是待解决的问题；再得到输出，也就是期望的解；而在这个众所周知的“黑箱”内部，装的就是那些按部就班的算法指令。**解决问题，就是计算机科学的本质。**

为了说明“算法”这个词到底指什么，我翻出了大约 25 年前我在 CS 50 第一节课上的笔记——直到今天，我那糟糕的字迹还留着这么一句：

> **定义**：算法（algorithm）就是为完成某项任务而设计的精确步骤序列。

这和我们今天的定义几乎一字不差。那天我记下的核心收获是两件事：**精确性与正确性**。这几周我们未必天天把这两个词挂在嘴上，但一直在贯彻它们。

> **结论**：编程本身就是把算法翻译成计算机能处理的语言的过程——这正是你们在 Scratch、C、Python、SQL 和 Java 里真正做过的事。

### “你画我猜”：把一个立方体讲成步骤

最后一堂课不讲新东西，我们来做个小练习，检验一下大家对这些内容的掌握——来玩一局 CS 50 版的“你画我猜”。

#### Jia 的六步指令

第一位自告奋勇的志愿者上台了——她先做了自我介绍：“大家好，我叫 Jia，我是一名大一新生。”

规则很简单：屏幕上会显示一张白底图片，而 Jia 需要**用口头编程**的方式，引导全场观众在纸上画出屏幕上的东西。只能说话，不能有任何肢体动作。大家进来时应该都拿到了一张白纸和一支笔——没有的话，从朋友那儿借一支，或者从活页夹里翻出来，都行。

于是观众听到了这样六步指令：

- **第一步**：画两条紧挨着的竖线。
- **第二步**：在这两条竖线的上方、正中间以及下方，各画一个点，总共三个点。
- **第三步**：从左边竖线的顶端出发，画一条线连到最上方那个点；再从右边竖线的顶端出发，也画一条线连到最上方那个点。
- **第四步**：从左上角那个位置画一条线连到中间的点；然后从右边竖线的顶端，画一条线连到中间的点。
- **第五步**：从左边竖线的底端连到最下方的点；从右边竖线的底端也连到最下方的点；最后，把中间点和最下方的点连起来。
- **第六步**：完成。

结果交上来一看——五花八门。“垂直竖线，问号。”“这个非常狭窄的一个。”“这里还有一个类似的。”并非所有部分都进展顺利。

为什么会这样？我敢说有两条原因。一是因为你们脑子里已经清清楚楚地想象出了自己要画的东西；二是因为在这些指令里，**我们一个抽象概念都没有用上**。

我敢说，如果 Jia 一开始就补上一句“好的，各位，我们要画一个**立方体**”——这其实是对那一堆底层细节做的一次抽象——那对我们所有人来说，事情可能都会简单得多。但“立方体”这个词本身也有歧义：它是否像这样旋转过？所以比起“立方体”，我们仍然需要比 Jia 给出的更多信息。

那还有没有更严谨的办法？有。许多早期的绘图程序，包括 Scratch 这样的环境，都默认你拥有一个带 X 轴和 Y 轴的坐标系，可以上下左右移动。于是我们换一种更细的方式描述：

```text
   "draw a cube"                      <-- abstraction: shortest, but ambiguous
        |
        v
   pen at top -> SW -> S -> SE -> SW -> S -> SE ...
                                        <-- coordinates: exact, but unreadable
```

把笔尖放到页面顶端，向西南画一条直线，以相同的距离向南画，再向东南，然后如此反复。我们全程都在用角度或方向说话——但在足够多条线落到屏幕上之前，没有人会认出我们在画什么，直到某一刻，看啊，我们一直在画一个立方体。

> **结论**：无论是为了让他人理解我们，还是为了让今天的人工智能理解我们，抑或是介于两者之间的任何情况，我们所采用的**精确程度**和**抽象层级**都直接决定结果。

#### 反过来指挥：Presley 的白板

我们换个完全相反的互动方式：再请一位志愿者上台，**观众**负责编程，**他**负责执行。

这位同学叫 Presley，也是一名大一新生，住在 Stton 宿舍。我们给他准备了黑色记号笔，请他站到白板前。唯一的硬性要求是：**不许抬头、不许回头看**，因为答案就在屏幕上；但其他同学可以随便看。每画完一笔，请稍微让开一点，让大家看清你画了什么。

于是全场开始大声喊指令：“画个圆圈。”“别画太大。”“哦，我喜欢这个。”——第一条其实是一次很棒的抽象处理，如果任由它发展下去，你最后会画出一个简笔画小人。但我们还是决定用手势把指示做得更精确一点，免得 Presley 不知所措。于是有了这样一串：

- 从圆圈底部向下画一条线；
- 从你刚画的那条线，画出两条对角线；
- 把原始的那条垂直线延长到与圆形大致相同的高度；
- 从那条线的底部画出两条对角线，当作腿——这一步“很好地运用了细节与抽象手法”；
- 在头部左侧写上一个大写的 “H”，字母下方再画一条短线；“不要对话框，只写 high”；
- 从 “high” 画一条线连到脸上，中间留一点空隙；
- 调整手臂，让它们看起来像是在奔跑；
- 从左臂画一条垂直线，一直画到底部；
- 最后再微调一下另一只手臂。

结果 Presley 画出来的是什么？是一个正在奔跑、举着 “HIGH” 标语的人物——他其实是在让我们为他鼓掌。

> **易错点**：黑色马克笔是永久性的，所以很容易一开始就偏离轨道，或者犯个小错误；Presley 能坚持下来相当不容易。

我觉得这个环节之所以好，是因为它同时包含了**底层细节**（线条的方向和长度）和**抽象概念**。当有人喊出“画个火柴人”时，那确实给了他一个更有帮助的心理模型。这有点像函数上方那段注释说明，但当我们真正深入去实现这个函数时，写的就更接近于针对当前这个问题的逐步操作指南了。

### 这十周：从 Scratch 一路走到 AI

回顾过去几周，这大致就是我们走过的学习轨迹：

```text
   Scratch          loops / conditions / booleans / variables
       |
       v
   C                memory / arrays / pointers / hash / linked list
       |            runtime analysis
       v
   Python / SQL / Java     beyond arrays and algorithms
       |
       v
   Web + JavaScript  ->  mobile (HTML / CSS)  ->  AI as a collaborator
       |
       v
   final project:  the first project you plan all by yourself
```

我们从零开始学 Scratch——确切地说是在第一周，它的定位是**视觉化编程入门（VoI）**，目标是向大家介绍那些基础的程序设计概念：循环、条件语句、布尔表达式和变量。这些概念非常重要，在随后的几周里，它们会以不同的形式、不同的语言反复出现。

之后我们转向了更传统的 C。你们很多人可能再也不会用到它了——坦白说，就连我自己也只在 CS 50 开课期间每年用上一两个月。但它的意义在于，C 是一种极其基础的语言，如今许多其他编程语言都构建在它之上。举个例子：你们可能正在用的那个 Python 解释器，本身就可以用 C 编写。

从一种语言引导到另一种语言，从底层到高层，超越数组和算法——所有这些内容，包括内存和数据结构，在计算与编程领域里几乎无处不在。用 Python 这样的现代语言时，你可能不需要过多操心内存管理问题，因为优秀的程序员们已经在语言本身或你调用的库里替你把这些难题解决了。但你至少可以确信：自己已经理解了哈希表的基本概念，知道链表是什么，理解它们之间的权衡取舍，掌握了运行时间的分析方法——这些正是计算机科学家和软件工程师在实际工作中思考、讨论、在白板上推演的核心内容。当他们为现实问题设计算法或开发实际产品时，这些基础知识就是决策的依据。

再往后，我们以这些基础知识为跳板，探讨了一些非常现代的编程范式，最近还涉及了 Web 编程。虽然课堂上没有明确讲授，但移动端编程其实也越来越依赖 HTML 和 CSS；还有 JavaScript——你们中的一些人也许会在期末项目里用到它。

至于人工智能：如今你无论如何都无法避免使用、接触或借助它。今天至少有一个目标是**为你们指明方向、介绍工具**。既然你们已经完成了问题集 9，我们非常欢迎并鼓励在期末项目里用上这些工具。这样一来，你们不仅能比几年前的前辈们完成更多工作，还能取得更大的成功——因为你自己的努力和专业知识，现在可以通过这些工具被极大地增强。

我也正在学 CS 50，或者说 CS 50 Plus。即使是我，也常常低估解决一个问题所需的时间。而这种情况正在开始改变，至少在一定程度上要归功于 AI：你身边就像多了一位初级同事，可以帮你解决程序错误、指明正确方向，甚至协助实现某个功能。

### 期末项目：第一次自己掌舵

既然已经走到课程尾声，我想让你们看看从这里出发能走向何方。期末项目的初衷，就是希望它能成为**你自己规划的第一个项目**，并由此开启更多项目的序幕。

到目前为止的每一个习题集，都是我和团队编写的，你们一直按照我们的指示一步步完成。期末项目则彻底卸下了这些“辅助轮”。我们欢迎、也鼓励你借鉴代码——想做网页项目的话，可以参考问题集 9，甚至更早的问题集；但如果想做的东西和以往习题集更相似，最终的目标是让它真正成为**你自己的作品**。甚至，你可以从一个完全空白的窗口和一个闪烁的光标开始，构建属于自己的东西。

正如你在项目说明里看到的，你需要为自己设定几个目标：一个无论如何都要实现的基础目标，一个更具挑战性的进阶目标，以及一个理想目标——尽管从 25 年前到今天，真实软件项目里真正实现理想目标的情况依然罕见。对于期末项目，我们唯一的要求是：**请构建一个你真正感兴趣的项目，解决一个实际问题**，无论是服务于校园还是服务于更广的世界。正如我们在项目说明中所写的那样：改变世界，努力实现一些有意义的目标。

也请大胆一点：尝试在这最后几周里创造出超越课程本身价值的作品。如果愿意，明年一月乃至更久以后，你还可以继续完善它。

### 通宵、展览和一件 T 恤

那么，有哪些支持机制已经就位？你又该如何着手推进？

先说 CS 50 的一项悠久传统：史诗级的通宵活动——**CS 50 黑客松**。大约晚上 7 点，我们会提供一些披萨；晚上还有冰淇淋；如果你能坚持到午夜活动接近尾声时还保持清醒，我们会安排一整批 CS 50 专属接驳车，驱车前往 24 小时营业的 “国际煎饼屋”（International House of Pancakes，IHOP），和大家一起享用早餐。

光是这一个晚上，我们就全靠它了。

那黑客松本身到底是干什么的？深夜时分，这个绝佳机会究竟能让你深入探索什么？我和教学团队都会在场，但我们的**主要目的不是直接回答你所有的问题**，而是帮助你学会自己解决问题：我们会引导你找到相关的资源，比如必要的网站和文档，这样最终你就能靠自己的力量解决眼前的问题，不再依赖我们之前提供的那些辅助轮。

最终的目标，是为了学期末的展览——也就是所谓的 **CS 50 展览会（CS50 Fair）**做好准备。届时，你将有机会在手机或笔记本电脑上，向来自教职员工、学生、工作人员以及全校访客的过往行人展示你的期末项目。现场会有一些表情符号气球在等着你，还设有一个照相 booth，愿意的话可以留下这一刻的记录。这次展览会的核心目标，其实就是向过往的参观者展示你的项目，让你自己为过去几个月里独自完成的成果感到欣喜。

而在活动结束时，你将领到一件专属的 CS 50 纪念 T 恤——希望你能自豪地把它穿出去：你已经成功完成了 CS 50。

### 猜谜游戏：两队六个人

在进入最后一个游戏之前，先来看看大家到底掌握了多少知识。几周前我们做过一次测试，大家表现很棒；这次我们想从你们过去几周准备的复习题里挑一些，再挑战一下。

规则是这样的：请 6 位同学上台，分成两队，每队 3 人。每一轮，从屏幕上的一个 CS 50 相关术语开始，队里一人**用肢体语言表演**（不能说话，否则就失去意义了），另外两人喊出答案。60 秒限时，猜出就换下一个词，看你们总共能拿多少分。Kelly 自告奋勇做计分。词库可以随意跳过，直到用完为止——但尽量别把我们的题全用完。

几位同学当场报了队名和自我介绍：A 队这边是 Leah（大二，住 Houghty 宿舍）、Stephen（大二）、Charlotte（大二，现在人在加拿大）；另一队是 Jenny Pan（住 Leverett 学院）、Noah、以及一位从加拿大来的同学。

于是就有了这样一些让人抓狂的时刻：有人一上来就“调用递归”，被队员喊中；有人比划出“鸭子”，被夸“这鸭子不错”；有人比划“二进制”“10 个比特”，绝对被认出来；也有人在队友喊“无序数组”之后，怎么比都不像。轮到 A 队时，5 分成了待超越的分数。第二轮里，“运行时间”只挣到 3 分，而最后那个词——先是没人猜中，直到有人喊出“一次合并通话”，全场才反应过来：那说的是 merge sort（归并排序）。

确实相当困难。感谢所有上台的志愿者，也感谢 Kelly。

临别赠礼是给每个人的：属于你自己的**超级马里奥主题 Pez 糖果盒**。我也很高兴我们最终解决了提问环节里话筒传递的问题。

### 工具箱：走出 cs50.dev

#### 装上真正的 VS Code

到目前为止，我们一直是通过网址 `cs50.dev`、用 Visual Studio Code 来上 CS 50 的。回想一下，这其实是对一款名叫 GitHub CodeSpaces 的商业工具的改编版本——它本质上就是**云端版的 VS Code**，而 VS Code 是微软推出的一款主开源工具，在业界广受欢迎。

也就是说，尽管在这个环境里我们集成了 CS50 的库、默认关掉了部分菜单选项、并禁用了 AI 功能，但它骨子里仍然是全世界许多程序员每天真正用来写代码的工具。你们一直在学的，其实都是行业标准。

现在，如果你愿意——当然你也可以继续用 `cs50.dev` 完成期末项目，如果觉得更顺手的话——可以脱离 CS50 的定制环境，在自己的 Mac 或 PC 上安装原版 Visual Studio Code。安装过程本身相当简单，但根据你打算用它写什么语言，难免会遇到一些技术支持上的麻烦：比如你想用它写 Python，就可能还需要单独下载并安装 Python 环境。如果你想用最新版本，也得提前知道有时候就是会出现各种问题导致跑不起来，这时你就需要去谷歌搜一搜，或者问问 ChatGPT——这完全正常，这种事其实挺常见的。

这也正是为什么我们在第 0 周不碰这些内容：好让我们专注于 “Hello, World”、“马里奥”、“现金” 和 “信用” 这些项目，让大家真正体验计算机科学与编程里有趣的那一部分，而不是被技术支持问题搞得失去学习热情。现在大家的进度各不相同：比较熟练的同学已经能自己处理这类技术问题了——当然，也说不定一切都会异常顺利。

官方文档里还有一条稳妥的路：借助 **Docker** 这项容器化技术，在你自己的 Mac/PC 甚至云端跑起 CS50 环境，同时仍然能在自己的设备上使用 VS Code。这样做的好处之一是你不必完全依赖某个平台；你完全可以离线完成所有操作，这在通常情况下非常实用；有时用上自己电脑的全部性能（而不是只靠浏览器）也会更高效。程序员通常就是用这种方式干活——用 VS Code 或同类工具。市面上还有很多别的选择，目前最流行的可能是这三款：Visual Studio Code 本身、一款叫 Cursor 的工具，以及叫 Windsurf 的那一款，此外还有数十种其他文本编辑器，它们通常被统称为**集成开发环境（IDE）**。

至于命令行工具：用 Mac 的同学可以在“实用工具”（Utilities）文件夹里找到一个叫“终端”（Terminal）的程序；Windows 系统也有类似的功能。它们不一定包含你在 CS 50 里用到的全部开发工具，但你可以照着官方文档把相同的工具装到自己机器上，这样在命令行环境下操作也会更加得心应手。（用 Linux 的同学大概早就对这些熟悉了。）

#### Git、协作与部署

再说 **Git**。在 CS 50 里，我们其实是在它之上做了抽象化教学；而在今天，它已经基本成为与他人协作的实际标准工具：通过一个中央云服务器来共享你的代码，从而实现多人协作的代码版本控制，你能追踪代码的多个版本以及所做的修改。如果你有兴趣，CS 50 官方文档里有我们团队的 Brian Yu 专门录制的教程，介绍真正的 Git 用法。因为我们此前一直用自动化的方式，把这个工具抽象封装了一层——如果你在 `cs50.dev` 上用过时间线功能，你就能回滚到代码的早期版本；我们其实一直在用 Git，只不过**一直在替你执行那些命令**。

如果在期末项目里想和伙伴一起做，你可以用 Git；不过我也可以建议你试试 VS Code 的**实时共享（Live Share）**功能：其中一人登录自己的代码空间，点几下按钮就能把访问权限分享给一起做项目的朋友或伙伴，然后你们就能像用 Google Docs 那样，在同一个代码空间里实时地编辑代码或不同的文件。这比从零开始学 Git 协作要简单一些。

如果你想在期末项目里部署网站，甚至课程结束后继续维护（如果它是个静态网站的话），有两个热门选择，主要是因为它们都提供免费方案。其一是 **GitHub Pages**，用它托管纯前端网站——只需要 HTML、CSS 和 JavaScript，不需要 Python、Flask 或者任何后端支持；其二是 **Netlify**，也很受欢迎，提供免费的基础账户。个人作品集网站也好，单纯发布一些静态内容也好，一次性写完并部署掉，都是不错的起点。

当然不止这些。亚马逊、微软、谷歌、Cloudflare 都提供面向学生的账户类型：如果你使用 `.edu` 邮箱地址，或者用其他方式证明自己目前的学生身份，通常就可以注册享受折扣甚至免费使用同样的服务。也就是说，在你学习的过程中，你是不需要付费的。GitHub 也有类似的“学生开发者工具包”，另外还有一些 Web 应用托管平台，流行的包括 Heroku、Vercel 以及其他许多服务。

> **易错点**：这里要说清楚“Web 应用”和“静态网站”的差别——说“Web 应用”时，指的不只是 HTML、CSS 和 JavaScript，还可能包括 Python、服务端 JavaScript、Ruby 或其他多种语言；这意味着除了前端之外，你可能还需要后端支持，甚至可能还需要数据库。

#### AI，以及真正的人类

在期末项目中再次借助 AI 时，我们依然欢迎并鼓励你用它来提升自己的生产力——但**不是让它替你完成所有工作**。小黄鸭的局限也在这里：它的设计功能相当有限，作为“良师”很称职，可作为构建项目的最佳搭档就不一定了。真正值得你尝试探索的，是 ChatGPT、Claude、Gemini、GitHub Copilot、OpenAI Codex 这些当下流行的工具。

其中最容易上手的——如果你还不熟悉 ChatGPT 这类工具的话——可能就是 **GitHub Copilot**。仅仅因为你可以按照我们在 `cs50.readthedocs.io` 上的文档说明，在你的 CS50 代码空间里启用它：文档会告诉你具体步骤，让你能重新启用 AI 功能（既然期末项目已经允许使用），并把那些默认被禁用的特性全部打开。

当然，还有**人类专家**。程序员和技术爱好者多年来常去的地方包括 Reddit、Stack Overflow 和 Server Fault。讽刺的是，如今所有那些 AI 模型正是基于这些平台积累的问题与答案进行训练的——这也不禁让人担心：如果我们都只依赖 AI，这些地方未来或许会在某种程度上逐渐失去生存空间。但当你真正需要有人参与时，它们依然是很好的选择。

资讯方面也有 plenty 的地方：科技领域可以看 TechCrunch，另有 Hacker News；科技与计算机领域的新闻平台还有很多，你大概也有自己常用的那几个。

最后是**继续往下走的路**——虽然可能带点个人偏好——你也可以考虑 CS 50 Plus。这门本科生课程在过去十多年里已经积累了丰富的开放课件资源：更深入的 Python 课程、SQL 进阶、名为 R 的语言、网络安全、游戏开发等等。所有这些课程都可以在 `edX.org/cs50` 找到，你无需付费或注册即可访问，全部内容完全免费开放。寒假期间，如果你想为期末项目、为职业发展、或者单纯为春季学期做准备，来这里深挖某个主题就好。

### 十五道题：你们自己出的考卷

蛋糕之前还有最后一个小游戏，是所有人都可以参与的趣味问答。屏幕上这些题目，全部来自你们自己——我们最近征集的复习题目，你们提交什么我们就问什么。

**第一题：8 位无符号二进制数能表示的最大数值是多少？** 256、128、255，还是 1？

最热门的答案是 255，而且只要再点一次确认键就能证明它确实是正确答案。那么为什么是 255 而不是 256？因为我们**始终从零开始计数**——这白白占掉了 256 种可能中的一种。所以 8 位无符号二进制（不涉及负数）能表示的最大值确实是 255。

**第二题：2038 年问题的核心是什么？** 是整数溢出、恶意输入、SQL 注入，还是内存泄漏？

揭晓排名第一的答案：有 **92%** 的人选了“整数溢出”，正确。原因是，我们至今仍习惯用 32 位整数记录时间，这个时间起点叫作“纪元”（epoch），也就是 1970 年 1 月 1 日。遗憾的是，人类不太擅长未雨绸缪，32 位整数的所有可能组合终将被耗尽，到 2038 年的某个特定日期就会溢出——除非所有人都把计算机升级到 64 位计数器。所幸如今绝大多数现代硬件（你的 Mac、PC 和手机）已经是 64 位技术了，所以希望这最终不会成为真正的问题。不过，当那个多年前的谷歌日历提醒真的响起时，希望你还能想起我们这门课。

**第三题：以下哪一项不属于编译的步骤？** 链接、预处理、汇编，还是解释？

这道题有点挑战性。最受欢迎的答案：有 **54%** 的人选了“解释”，正确。而有 29% 的人选了“链接”，也错。回想一下我们讲过的编译过程：编译本身只是多个步骤中的一环——先有预处理步骤，负责处理 C 语言里所有以 `#` 开头的指令（`#include`、`#define` 之类）；然后是汇编阶段，把你的代码真正编译成汇编语言；再由汇编器把代码转换为机器码；最后才是链接阶段。

> **易错点**：链接这一步，是把你的二进制代码与 CS 50 库的二进制代码、标准输入输出库的二进制代码等合并在一起，最终生成一个像 `hello` 这样的可执行程序。

**第四题：指针存储的是什么？** 是变量的名称、值的内存地址、值的大小，还是变量的值？

在收到的约 200 份回答中，有 **96%** 的参与者选了正确答案：**变量的内存地址**。

**第五题：线性搜索的运行时间复杂度是多少？** $O(1)$、$O(N)$、$O(N^2)$，还是 $O(N \log N)$？

搜索这类操作有时或许会运气好，但大 O 表示的是运行时间的**上界**——你可能要一直遍历到列表末尾，所以线性搜索的运行时间显然是大 O 的：$O(N)$。它可能是 $\Omega(1)$，但不会是 $O(1)$，至少在我们考虑最坏情况时是这样。

**第六题：哪种数据结构遵循“先进先出”？** 队列、链表、栈，还是哈希表？

先进先出（FIFO）就是**队列**，正如你所期望的那样：如果你在餐厅或商店排队，公平地说，第一个排队的当然也该第一个被服务。与之相反的是**栈**，它遵循 LIFO（后进先出）——就像食堂里的餐盘，第一个放进去的，实际上会是最后一个被取出来的。

**第七题：哪个运算符可以返回变量的内存地址？** 是星号、美元符号、与符号，还是连字符加大于号？

最热门且正确的答案是**与符号 `&`**，这就是取址运算符。而星号 `*` 在大多数情况下恰恰相反：它是**指针解引用运算符**，用于访问该地址所指向的内容。至于“点加星号”那种写法，C 语言里并不存在，不过它在概念上相当于星号和点的组合，用于解引用指针并访问结构体内部的成员。

**第八题：用于从结果集中移除重复行的 SQL 命令是什么？**

`DISTINCT` 是正确的。结果集就是你执行 `SELECT` 查询后返回的答案，而想过滤掉重复项，就应该这么写。`UNIQUE` 虽然也是 SQL 里的一个关键字，但它用于在数据库模式中定义某一列的值必须唯一（比如电子邮件地址那一列），并不是查询时去重的方法。

**第九题：HTTP 状态码 418 代表什么？** 404 未找到、418 我是茶壶、403 禁止访问，还是 401 未授权？

正确答案是“我是茶壶”。如果你以后能记住这个，在计算机科学圈子里就算内行了——虽然它实际上并不是什么实用的技术：这是多年前的一个愚人节玩笑，一群计算机科学家聚在一起，专门制定了一套完整的规范，来定义服务器返回 “418 I'm a teapot” 的具体含义。

**第十题：`malloc` 从哪里动态分配内存？** 堆、栈、全局变量，还是汇编？

**堆（heap）** 正确。“顶部”和“底部”在技术上并没有实际意义，堆通常只是被理解成内存的“上半部分”，这是一种艺术化的呈现方式。**栈（stack）** 则是函数调用时使用的内存区域：每次调用函数，都会在栈上获得一个所谓的“栈帧”，局部变量和函数参数就存放在这里。在 C 语言里，用 `malloc` 分配的内存实际位于堆上。

**第十一题：在 C 语言中，用 `malloc` 分配内存却忘记调用 `free`，可能导致什么问题？** 内存泄漏、段错误、栈溢出，还是以上所有情况？

最常见的答案是**内存泄漏**，正确。你可以想象，在某些场景下也可能出现段错误或栈溢出，但那并不是“不调用 `free`”的直接后果——它们属于相关但不同的问题（比如用了过多内存，或者对内存操作不当）。严格来说，就“每次 `malloc` 之后没有 `free`”这件事而言，**内存泄漏就是定义上必然发生的结果**。

**第十二题：这个域名 `safetyschool.org` 指向哪个网页？** 哈佛大学、普林斯顿大学、耶鲁大学，还是哥伦比亚大学？

回想一下，这个问题是在我们讨论 HTTP 重定向的背景下提出的。访问 `safetyschool.org` 会返回一个 **HTTP 301 重定向头**，指示它实际位于 `yale.edu`。为什么？因为耶鲁有一位校友为了这个玩笑，每年支付大约 10 美元，并且已经持续了大约 20 年。

**第十三题：DNS 的作用是什么？** 是加密在暗网上发送的数据，还是把域名转换成 IP 地址？

大约在第 200 份回答处，才出现正确答案：**把域名转换成 IP 地址**。DNS 即域名系统；它是你家庭网络、ISP 网络、校园网络或公司网络中的一台服务器，专门为你解答这类问题。

**第十四题：以下哪一项不是 SQL 内置的、用于处理竞态条件的功能？** 开始事务、提交、回滚，还是登记？

正确答案是**登记（enroll）**。虽然 `START TRANSACTION`、`COMMIT`、`ROLLBACK` 这三个确实都是 SQL 的特性（即使你在问题集 7 或 9 里未必用得上），但 `enroll` 并不是一条 SQL 命令。还记得吗？我们讨论这个问题，正是讲到牛奶买多、也就是竞态条件的时候。

**第十五题，也是最后一题，请尽快回答：Mayland 教授在每节 CS 50 课程开始时都会说什么？**

是“欢迎来到哈佛大学计算机科学课程”？还是“大家好，准备好编程了吗”？还是“好的，这里是 CS 50”？

事实上所有这些问题都出自你们自己，而我确信有 **98%** 的同学都选中了它——

“好的，这里是 CS 50。”
