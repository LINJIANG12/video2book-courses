## 编译：把高级语言翻译成机器能懂的样子
> 对应块：BLK01 | 覆盖分集：P01-P07 | 块标题（分集名）：《1-1什么是编译》

计算机程序设计语言分成三个层次：机器语言、汇编语言、高级语言。层次越高，人写起来越省力，机器就越不能直接执行；人写得越舒服，离机器越远。这中间的落差由谁来填，就是这门课要讲的事情。

### 从机器语言到高级语言

#### 机器语言

机器语言是可以被计算机直接理解的语言。计算机只能直接理解 0 和 1 两个数字，所以用机器语言编写的程序，都是由 1 和 0 构成的序列。

看一条真实的机器指令：

```text
C706 0000 0002
```

这里用的是十六进制的书写形式。`C706` 是这条指令的操作码，表示一次移入（传送）操作；`0000` 和 `0002` 是两个操作数。整条指令的意思是：把数值 2 存放到地址 0000。

从这一个例子就能看出机器语言的表达习惯离人有多远。人类习惯用十进制，机器用的是二进制，书写时常用十六进制；程序员还得记住各个操作码代表什么操作——`C706` 到底是传送、加法还是跳转，全凭记忆。这几条加起来，使得用机器语言编写和阅读程序都十分困难，而且经常容易写错。

> **提示**：机器语言的本体始终是 0 和 1 的序列，写成十六进制只是为了让人看得短一点、抄得省事一点，不改变它是二进制机器码这一事实。

#### 汇编语言

机器语言难写，很快出现了汇编语言。汇编语言引入了助记符，把冰冷的操作码换成有含义的英文缩写。

例如一条汇编指令里的 `MOV` 就是一个助记符，它来自英文单词 move，表示移入的意思。假设我们用一个符号名来代表地址 0000，那么这条带 `MOV` 的指令与前面那条 `C706 0000 0002` 完成的是等价的功能——同样是把数值 2 存放到地址 0000。

因为引入了助记符，汇编语言比机器语言直观得多，这是一次实实在在的进步。但它的局限也很硬：

- 汇编语言依赖于特定的机器，换一台机器，指令系统就可能不一样；
- 程序员需要熟悉目标机的特性，哪些寄存器能用、寻址方式怎么算，都得门儿清，这对非计算机专业人员来说使用上很受限制；
- 编写效率比较低，即使是一个比较简单的数学表达式，也需要好几条指令才能写完。

#### 高级语言

后来又出现了高级语言。高级语言以一种类似于数学定义或自然语言的简洁形式来编写程序。例如一条高级语言的语句，就能完成前面那两条指令等价的功能。

高级语言的好处正好补上了汇编语言的短板：

- 它更加接近于人类的表达习惯；
- 它不依赖于特定的机器，同一段程序不必为每种机器重写一遍；
- 编写效率比较高，不管多么长的数学表达式，用一条语句就可以简洁地表达。

### 编译就是一次翻译

高级语言和汇编语言的程序，最终都要翻译成由 0 和 1 构成的机器代码，才可以在计算机上执行。区别只在于翻译的起点不同：

- 把汇编语言翻译成机器语言的过程，称为**汇编**；
- 把高级语言翻译成汇编语言、或者直接翻译成机器语言的过程，称为**编译**。

> **定义**：编译的本质是一个翻译的过程，它特指将高级语言翻译成汇编语言和机器语言的过程。被翻译的那一方（高级语言）称为源语言，翻译得到的那一方（汇编语言或机器语言）称为目标语言。

这门课学的就是编译器的构成原理和相关技术，也就是搞清楚一件事：编译器是如何将高级语言自动翻译成汇编语言和机器语言的。注意“自动”这两个字——人拿着手册一条条手写翻译不算本事，编译器要做的，是拿到一段从没见过的高级语言程序，自己分析、自己变换、自己产出目标代码。

### 编译器在语言处理系统中的位置

为了建立可执行的目标程序，光有编译器是不够的，还需要几个配套程序。它们串起来是这样一条流水线：

```text
 源程序（可能分散在多个文件中）
    │
    ▼
 预处理器        聚合多个文件中的源程序；把宏这样的缩写语句展开成原始语句
    │
    ▼
 编译器          高级语言程序 → 汇编语言程序
    │
    ▼
 汇编器          汇编语言程序 → 可重定位的机器代码
    │
    ▼
 可重定位目标代码 ──┐
 其他目标代码 ──────┼──▶ 链接器 ──▶ 可执行代码 ──▶ 加载器 ──▶ 内存中运行
 库文件 ────────────┘
```

读图说明：源程序从上方进来，一路被预处理、编译、汇编、链接、加载，每一环只负责一种形态的转换，最后才变成内存里可以执行的指令。

**预处理器**要解决两件事。一是源程序可能被分割成模块，存放在不同的文件里，预处理器负责把存储在不同文件中的源程序聚合在一起；二是它负责把被称为宏的缩写语句转换为原始语句，也就是把写起来省事的简写还原成编译器真正能处理的完整代码。

**汇编器**把汇编语言程序翻译成机器代码。它生成的机器代码有一个重要性质：可重定位。所谓可重定位，是指汇编器生成的机器代码在内存中存放的起始位置不是固定的，代码中的所有地址都是相对于这个起始位置的相对地址。起始位置加上相对地址，得到的才是在内存中的绝对地址。

正因为地址是相对的，才需要**加载器**：它负责修改可重定位地址，并且将修改后的指令和数据加载到内存中适当的位置。

**链接器**管的是另一类问题。大型程序经常被分割成多个部分分别编译，因此可重定位的机器代码可能要与其他可重定位的目标程序以及库文件进行链接，生成可执行代码，这一工作由链接器完成。链接器还负责解决外部内存地址问题：一个文件中的代码可能会引用另一个文件中的数据对象或过程，这些数据对象和过程的地址相对于当前这个文件来说就是外部地址，必须由链接器在拼装时统一解决。

> **易错点**：可重定位不等于地址随机。代码里写的全是相对地址，绝对地址要等加载时用“起始位置 + 相对地址”现算，所以同一份目标代码可以装到内存的不同位置去。

### 从人工翻译看编译系统的结构

编译的本质是一个翻译过程。编译器的输入是一个高级语言程序，比如说一个 C 语言程序；输出是汇编语言程序或者机器语言程序。那么机器是如何把输入的 C 语言程序自动翻译成汇编语言程序的呢？这个问题不必凭空想设计，先看人是怎么干这活的。

比如要把这样一个英文句子翻译成汉语：

> In the room, he broke a window with a hammer.

这里英语是源语言，汉语是目标语言。翻译的过程大体可以分为两步：先从源语言也就是英语的层面，分析这个句子表达的含义，也就是句子的语义；再根据这个语义，用目标语言也就是汉语的方式说一遍，翻译就完成了。通过分析源语言来获得句子语义的这个过程，称为**语义分析**。

#### 抓住谓语动词

语义分析从划分句子成分入手。第一步是抓住句子的核心谓语动词——谓语动词知道了，句子的一半意思就知道了。这个句子里很容易找到核心谓语动词是 break，表示“打”的意思。

提到“打”这个动作，自然就会追问：是谁施加了打这个动作？谁是被打的对象？用什么打的？为什么打？打的结果如何？这些问题都可以通过分析 break 的上下文来获得。

由于这里 break 采用的是主动语态，它的主语 he 就是动作的施事者，宾语 window 就是动作的受事者。反过来，如果 break 采用的是被动语态 be broken，那么它的主语就变成动作的受事者了——语态一变，同一个位置上的名词扮演的语义角色就翻了。`with a hammer` 是补语，表示动作使用的工具；`in the room` 是状语，表示动作发生的地点。

这样一来，就能分析出 break 前后的这些名词性成分与核心谓语动词 break 之间的语义关系。把这些关系画成一张图：

```text
break（打）  ← 中心结点：句子所描述的动作
├── he       — agent     施事者
├── window   — object    受事者
├── hammer   — tool      工具
└── room     — location  地点
```

读图说明：最上面是表示“打”这个动作的根结点，它向下连着四个实体结点，每条边上的标注就是该实体与核心谓语动词之间的语义关系——he 是施事者 agent，window 是受事者 object，hammer 是工具 tool，room 是地点 location。

照着这张图的意思，再用汉语的方式说一遍，就是“在房间里，他用锤子砸了一扇窗户”，翻译完成。

#### 中间表示为什么重要

上面那张图是一种中间表示，它独立于具体的语言。英语可以用这张图表示，汉语也可以用这张图表示，日语、法语、德语、意大利语等等都可以用它表示。有了它，不管目标语言换成什么，翻译都能进行下去。

> **结论**：中间表示之所以重要，是因为它起到了桥梁的作用。源语言先被压成与语言无关的语义结构，再由这个结构生成任意一种目标语言；否则每两种语言之间都要单独修一条翻译通道。

这也解释了编译器为什么值得拆成前后两半：分析源语言的那一半只管把程序变成中间表示，生成目标代码的那一半只管拿中间表示去生成目标代码，两边通过中间表示解耦。

#### 从短语到词性

要想进行语义分析，首先要划分句子成分。那么是根据什么划分句子成分的呢？主语和宾语通常由名词短语构成，状语和补语通常由介词短语构成——所以划分句子成分的关键，是识别出句子中的各类短语，这一过程称为**语法分析**，也叫句法分析。

那么又是根据什么识别句子中的各类短语？靠词性。一个冠词加上一个名词可以构成一个名词短语，一个代词本身也可以构成一个名词短语。所以要识别各类短语，关键是要确定句子中各个单词的词性，或者叫词类，这一过程称为**词法分析**。

把这三层串起来，就得到一个句子的分析过程：先做词法分析，在词法分析的基础上做语法分析，然后做语义分析。具体来说是四步：

1. 通过词法分析确定句子中各个单词的词性或者说词类；
2. 进行语法分析，识别句子中的各类短语，从而获得句子的结构；
3. 进行语义分析，根据句子的结构分析出各个短语在句子中充当什么成分，从而确定各个名词性成分与核心谓语动词之间的语义关系；
4. 最后给出中间表示形式。

### 编译阶段与前后端

编译器在工作的时候也经过这样几个步骤，我们称之为阶段：词法分析、语法分析、语义分析、中间代码生成、目标代码生成。在中间代码和目标代码生成之后，通常还有一个代码优化的步骤。

这几个阶段按职责分成两半：

- 前面几个阶段统称为**分析部分**，也叫编译器的前端。它对源语言进行分析并生成中间表示，因此这个部分只与源语言相关。
- 后面的几个阶段统称为**综合部分**，也叫编译器的后端。它在中间表示的基础之上生成目标代码，因此它只与目标语言相关。
- 中间表示独立于具体的语言，起到桥梁的作用。

```text
 源程序
    │
    ▼
 前端（分析部分，只与源语言相关）
 词法分析 → 语法分析 → 语义分析 → 中间代码生成
    │
    ▼
 中间表示（独立于具体语言，起桥梁作用）
    │
    ▼
 后端（综合部分，只与目标语言相关）
 目标代码生成 → 代码优化
    │
    ▼
 目标程序
```

读图说明：上半截是前端，只认源语言，产出的是语言无关的中间表示；下半截是后端，只认目标语言，拿中间表示去生成目标代码。要支持一门新的源语言，改前端即可；要支持一种新的目标机器，改后端即可。

> **注意**：这里所说的阶段是编译器的逻辑组织方式，不是实现时的物理分块。在实现过程中，多个阶段可能会被组合在一起。

比如语义分析的结果通常直接表示成中间代码的形式，因此这两个阶段通常是放在一起实现的。另外，也可以在语法分析分析句子结构的同时，结合语义规则直接进行语义分析，这一技术称为**语法制导翻译**。在语法制导翻译的情况下，语法分析、语义分析、中间代码生成三个阶段可以放在一起实现。这就是编译器的大体结构。

### 词法分析：字符流变 token

词法分析是编译的第一个阶段。词法分析器的任务是：从左向右、逐行扫描源程序的字符，识别出各个单词，确定单词的类型，并将识别出的单词转换成统一的机内表示，也就是词法单元 token 的形式。

token 是一个二元组，由**种别码**和**属性值**两部分构成。种别码表示单词的种别。自然语言句子中的每一个单词都有一个词性，或者叫词类；程序设计语言中的单词同样要分类，大体上分为五类。

| 单词类别 | 例子 | 集合性质 | 种别码分配 | 属性值 |
| :--- | :--- | :--- | :--- | :--- |
| 关键字 | `program`、`if`、`else`、`then` | 事先可以确定 | 一词一码 | 空 |
| 标识符 | 程序员声明的数据对象名、过程名 | 开放集合，无法枚举 | 多词一码，全部共用一个种别码 | 标识符的具体字面值 |
| 常量 | 整型、浮点型、字符型、布尔型常量 | 开放集合，但按类型划分 | 一型一码 | 该常量具体的值 |
| 运算符 | 算术、关系、逻辑运算符 | 事先可以确定 | 一词一码，或一类一码 | 一类一码时存放具体运算符 |
| 界线符 | 分号、左右括号、等号、左右花括号 | 事先可以确定 | 一词一码 | 空 |

这张表背后是一条统一的取舍：能事先枚举的，靠种别码区分；枚举不了的，靠属性值区分。

**关键字**：给定一个程序设计语言，它的关键字集合是事先可以确定的，因此为每一个关键字分配一个种别码，也就是一词一码。

**标识符**：它是程序员为程序中声明的数据对象或过程起的名字。标识符是一个开放的集合，事先不可能枚举所有的标识符，因此把所有标识符统一作为一类单词，给它们分配同一个种别码，也就是多词一码。为了区分不同的标识符，就用 token 的第二个分量属性值来存放各个标识符具体的字面值。

**常量**：包括整型常量、浮点型常量、字符型常量、布尔型常量等等。常量与标识符类似，也是开放集合，事先不能枚举。但是不同类型的常量构成方式不同，因此为每种类型的常量分配一个种别码，也就是一型一码；为了区分同一类型下的不同常量，同样用属性值存放每一个常量具体的值。

**运算符和界线符**：与关键字类似，它们也是事先可以确定的，因此可以为每一个运算符和每一个界线符分配一个种别码，也就是一词一码。当然，也可以为每一类运算符分配一个种别码，这时为了区分同一类型下的不同运算符，仍然是用属性值存放具体的运算符。

> **提示**：种别码本身是一个整数，只是为了直观起见，实现和讲解时常采用宏定义的形式。区分单词靠的是种别码，区分同类单词中的哪一个靠的是属性值——两个分量各管一件事，这就是 token 设计成二元组的原因。

按照这套分配原则，看一个词法分析结果的例子。种别码用宏名表示：`WHILE` 表示关键字 while，`SLP` 表示左圆括号，`SRP` 表示右圆括号，`IDN` 表示标识符 identifier，`NE` 表示不等号 not equal，`CONST` 表示常量，`LP` 表示左花括号，`RP` 表示右花括号，`INC` 表示加加，`SEMI` 表示分号。扫描一段含 while、标识符、常量和自增运算的程序片段，得到的 token 序列里各个单词的形态如下：

| 单词 | 种别码 | 属性值 | 为什么这样填 |
| :--- | :--- | :--- | :--- |
| `while` | `WHILE` | 空 | 关键字是一词一码，靠种别码就能与其他单词区分开 |
| `(` | `SLP` | 空 | 界线符，一词一码 |
| `value` | `IDN` | `value` | 标识符多词一码，靠属性值区分是哪一个 |
| `!=` | `NE` | 空 | 运算符，一词一码 |
| `100` | `CONST` | `100` | 常量，属性值就是它本身的值 |
| `)` | `SRP` | 空 | 界线符，一词一码 |
| `{` | `LP` | 空 | 界线符，一词一码 |
| `++` | `INC` | 空 | 运算符，一词一码 |
| `;` | `SEMI` | 空 | 界线符，一词一码 |
| `number` | `IDN` | `number` | 与 `value` 同属标识符，种别码相同、属性值不同 |
| `}` | `RP` | 空 | 界线符，一词一码 |

一个 token 对应一个单词。可以看到，凡是能靠种别码唯一确定的单词，第二个分量都是空的；只有标识符和常量这两类开放集合，才需要用属性值把“同一个种别码底下的不同个体”区分出来。

词法分析器如何将输入的字符序列自动地转换成 token 序列，是第三章词法分析要解决的问题。

### 语法分析：从 token 序列到分析树

语法分析是编译的第二个阶段。它的主要任务是从词法分析器输出的 token 序列中识别出各类短语，并构造语法分析树（parse tree）。语法分析树描述了句子的语法结构。

#### 赋值语句的分析树

假如输入了一个赋值语句：

```c
position = initial + rate * 60;
```

经过词法分析，得到一个 token 序列，其中 `position`、`initial` 和 `rate` 都是标识符，`60` 是一个常数。由这个 token 序列构造出的分析树是：

```text
赋值语句
├── id(position)
├── =
├── 表达式
│   ├── 表达式
│   │   └── id(initial)
│   ├── +
│   └── 表达式
│       ├── 表达式
│       │   └── id(rate)
│       ├── *
│       └── 表达式
│           └── 60
└── ;
```

读图说明：树的叶子是词法分析给出的一个个单词，往上每一层归约都对应一条语法规则——标识符或常数本身构成一个表达式，表达式加上或乘上另一个表达式构成一个更大的表达式，最后标识符接上赋值号、表达式和分号，构成一条赋值语句。

从这棵树能直接看出三条规则的作用：

- 一个标识符或者一个常数本身可以构成一个表达式；
- 一个表达式加上另一个表达式，或者乘上另一个表达式，可以构成一个更大的表达式；
- 一个标识符连接上一个赋值号，再连接上一个表达式和一个分号，可以构成一条赋值语句。

树的形状同时把优先级也说清楚了：`rate * 60` 先合成一个表达式，再与 `initial` 相加，乘在加的下层，所以先算。

#### 声明语句的文法与分析树

再看变量声明语句。先看它的文法，文法由一系列规则构成：

$$D \to T\ IDS\ ;$$

$$T \to \text{int} \mid \text{real} \mid \text{char} \mid \text{bool}$$

$$IDS \to id$$

$$IDS \to IDS\ ,\ id$$

这里的 $D$ 是英文单词 declaration 的首字母，表示声明语句；$T$ 是英文单词 type 的首字母，表示类型；$IDS$ 是 identifier sequence 的缩写，表示标识符序列。

第一条规则说明：一个声明语句 $D$ 是由一个类型 $T$ 连接上一个标识符序列 $IDS$ 和一个分号构成的。$T$ 可以是 `int`，也可以是 `real`，或者 `char` 和 `bool`——竖线表示的是“或”关系。第三条规则说明：一个标识符 id 本身可以构成一个标识符序列 $IDS$。第四条规则说明：一个 $IDS$ 连接上一个逗号和一个标识符 id，可以构成一个更大的标识符序列 $IDS$。这是典型的递归写法，一条规则就能把任意长度的标识符序列描述完。

根据这个文法，如果输入这样一个声明语句：

```c
int a, b, c;
```

它的分析树是：

```text
D
├── T
│   └── int
├── IDS
│   ├── IDS
│   │   ├── IDS
│   │   │   └── id(a)
│   │   ├── ,
│   │   └── id(b)
│   ├── ,
│   └── id(c)
└── ;
```

读图说明：最里面一个 id(a) 自成一个 $IDS$；它接上逗号和 id(b) 长成更大的 $IDS$；再接上逗号和 id(c) 长成最终的 $IDS$；最后由类型 `int`、这个 $IDS$ 和一个分号拼成声明语句 $D$。整棵树的生长过程，就是把文法规则从下往上用了一遍。

语法分析器如何根据语法规则为输入的句子构造分析树，是第四章语法分析要解决的问题。

### 语义分析：属性与检查

语义分析是编译的第三个阶段。高级语言程序中的语句大体分为两类：一类是声明语句，一类是可执行语句。声明语句会声明一些数据对象或过程，并且为它们分别起个名字，就是标识符。对于声明语句来说，语义分析的主要任务就是收集标识符的属性信息。

#### 标识符的属性

标识符有哪些属性？

- **种属**：一个标识符对应的是一个简单变量，还是一个复合变量（比如说数组、记录等等），还是一个过程。
- **类型**：标识符对应的变量或过程是整型的还是实型的，还是字符型、布尔型、指针型等等。
- **存储位置和长度**：程序中声明的数据对象和过程，都要在内存中为它分配一块存储空间，因此存储位置和所占用的空间大小（也就是长度），成为标识符很重要的两个属性。
- **值和作用域**：变量的值，以及标识符起作用的范围。
- **参数和返回值**：对于过程的名字来说，它的属性还包括参数和返回值信息。

存储位置是怎么排出来的，看一个分配相对地址的例子。假设一个实型变量占用 8 个字节，一个整型变量占用 4 个字节：

| 标识符 | 类型 | 相对地址 | 占用空间 | 地址怎么来的 |
| :--- | :--- | :--- | :--- | :--- |
| $x$ | 实型数组，8 个元素 | 0 | 64 字节 | 第一个声明，从 0 开始；$8 \times 8 = 64$ |
| $i$ | 整型 | 64 | 4 字节 | 紧接在 $x$ 占用的 64 字节之后 |
| $j$ | 整型 | 68 | 4 字节 | $64 + 4 = 68$ |

读表说明：地址不是随便给的，而是按声明顺序一块一块往后摞，前一个对象占多少字节，后一个对象的相对地址就从哪里开始。数组要按“元素个数 × 单个元素长度”整体预留，所以 $x$ 一下占掉 64 个字节。

#### 符号表与字符串表

语义分析阶段收集的这些标识符属性信息，都会存放在一个称为**符号表**的数据结构中。每一个标识符都对应符号表中的一条记录，记录的每一个字段对应标识符的一个属性，比如类型（type）、种属（kind）、值（value）、地址（address）等等。

符号表通常带有一个**字符串表**，用来存放程序中用到的标识符和字符常数。这样一来，name 字段就被分割成两个部分：一部分用来存放标识符在字符串表中的起始位置，另一部分用来存放标识符的长度。

```text
符号表中的一条记录
    name    ──▶ （在字符串表中的起始位置，标识符长度）
    type
    kind
    value
    address

字符串表（名字集中存放，按出现顺序追加）
    偏移 0   simple   长度 6
    偏移 6   symbol   长度 6
    偏移 12  table    长度 5
```

读图说明：符号表里不再直接放名字本身，只放一个指向字符串表的二元组；真正的字符都躺在字符串表里。比如 `simple` 长度 6，`symbol` 长度 6，`table` 长度 5，起始偏移由前面名字的长度逐个累加得到。

这里有个问题值得停下来想一想：既然 name 字段就是存名字的，为什么还要在符号表之外单独设一张字符串表，把名字绕一圈存到别处去？

#### 语义检查

语义分析的另一个任务是语义检查。编译器在这一步要抓出那些语法上没毛病、意思上说不通的错误。常见的语义错误包括：

- 变量或过程未经声明就使用；
- 变量或过程名重复声明；
- 运算分量类型不匹配，比如说将一个数组的名字和一个过程的名字相加，是没有意义的；
- 操作符与操作数之间的类型不匹配，比如说数组的下标通常是整数，如果把一个浮点数作为数组的下标，编译器将报告错误；
- 对非数组变量使用数组访问操作符；
- 对非过程名使用过程调用操作符；
- 过程调用的参数类型或数目不匹配；
- 函数返回类型有错误。

发现运算分量类型不一致的时候，可能要进行自动的类型转换。比如说一个二元算术运算符可以作用于一对整数，也可以作用于一对浮点数，但是如果将它作用于一个整数再加一个浮点数，那么就要将其中的整数自动类型转换为浮点数，这次运算才能按浮点算下去。

### 中间代码生成：三地址码

源程序的中间表示可以有多种形式，比如说三地址码和语法结构树。语法结构树简称语法树。

> **易错点**：语法结构树（syntax tree）与我们前面讲的语法分析树（parse tree）不是一回事。前者是中间表示的一种形式，后者是语法分析阶段的产物；语法树的一个变体是无环有向图，那要到第八章才展开。

三地址码由类似于汇编语言的指令序列组成，每个指令最多有三个操作数，因此叫三地址码。

#### 三地址指令

常用的三地址指令包括赋值指令、复制指令、跳转指令等等，每一类里的操作符是区分指令种类的关键。

| 指令形式 | 含义 |
| :--- | :--- |
| `x = y op z` | 二元运算：`op` 是二元运算符，`y`、`z` 是两个运算分量的地址，`x` 是运算结果的存放地址 |
| `x = op y` | 一元运算：`op` 是一元运算符，只有 `x` 和 `y` 两个操作数 |
| `x = y` | 复制指令：把 `y` 的值复制给 `x` |
| `if x rel_op y goto n` | 条件跳转：若 `x` 和 `y` 满足关系 `rel_op`，就跳转到地址 `n` 对应的指令 |
| `goto n` | 无条件跳转：直接跳转到地址 `n` 对应的指令 |
| `param x` | 参数传递：将 `x` 设置为参数 |
| `call p, n` | 过程调用：`p` 是过程的名字，`n` 是过程的参数个数 |
| `return x` | 过程返回：跳转到地址 `x` 对应的指令 |
| `x = y[i]` | 数组引用：`y` 是数组的名字，表示数组的基地址，`i` 是数组元素的偏移地址 |
| `x[i] = y` | 数组赋值：把一个变量的值赋给一个数组元素 |

为了让地址写起来方便，可以用源程序中的名字也就是标识符，来作为三地址指令中的地址。因为每个标识符对应的地址都存放在符号表中，通过这些名字就可以找到它们的地址。另外，常量或者是编译器生成的临时变量，也可以作为三地址指令的地址。

> **易错点**：`x = y[i]` 里的 `i` 是数组元素的偏移地址，不是数组的下标。下标要经过元素长度的换算才能变成偏移，三地址码里用的已经是换算后的偏移量。

#### 四元式

将三地址指令表示成数据结构，有以下几种方式：四元式、三元式和间接三元式。以四元式为例，它由四个分量构成，第一个分量对应于三地址指令中的操作符，后面三个分量对应于指令中的三个操作数。

| 三地址指令 | 操作符 | 分量二 | 分量三 | 分量四 |
| :--- | :--- | :--- | :--- | :--- |
| `x = y op z` | `op` | `y` | `z` | `x` |
| `x = op y` | `op` | `y` | 空 | `x` |
| `x = y` | `=` | `y` | 空 | `x` |
| `if x rel_op y goto n` | `rel_op` | `x` | `y` | `n` |
| `goto n` | `goto` | 空 | 空 | `n` |
| `param x` | `param` | `x` | 空 | 空 |
| `call p, n` | `call` | `p` | `n` | 空 |
| `return x` | `return` | `x` | 空 | 空 |
| `x = y[i]` | `=[]` | `y` | `i` | `x` |
| `x[i] = y` | `[]=` | `y` | `x` | `i` |

读表说明：二元运算的第二个和第三个分量对应两个源操作数，第四个分量对应目标操作数；一元运算和复制只有两个操作数，所以有一个分量留空；条件跳转的第二个和第三个分量是待比较的两个量，第四个分量是目标跳转地址。

几个细节值得单独点出来。一元运算对应的赋值语句只有一个源操作数 $y$，用第二个分量表示，第三个分量为空。复制指令的操作符是等号，这条指令也只有两个操作数。无条件跳转只有一个操作数，就是目标地址。数组引用指令的操作符写成 `=[]`，表示等号的右边是一个数组元素，第二个和第三个分量分别表示等号右边数组的基地址和偏移地址，第四个分量表示等号左边的变量。数组赋值指令的操作符写成 `[]=`，表示等号的左边是一个数组元素，第二个分量表示等号右边的变量，第三个和第四个分量分别表示等号左边数组的基地址和偏移地址。

三地址指令的四元式表示，与前面讲的自然语言的中间表示有相似之处。给定一个动作“打”，它涉及施事者、受事者、工具、地点等语义角色；在三地址指令中，操作符就相当于句子的核心谓语动词，操作数就相当于各个语义角色，只不过这里每个操作符涉及到的操作数最多有三个。

> **结论**：除了复制指令以外，每一条指令都只有一个操作符，也就是说只能完成一个动作。因此一个三地址指令序列唯一确定了一个运算完成的顺序——这是它作为中间表示好用的根本原因。

#### 一段控制流的翻译

看一个中间代码生成的例子。输入的程序片段里，一个 while 语句中嵌入了一个 if-else 语句，if 语句里又嵌入了一个 while 语句。编译之后得到的中间代码编号从 100 取到 112，每条指令后面的注释说明它的去向：

```text
100  if a < b goto 102        ; a < b 成立转 102，否则顺序执行 101
101  goto 112                 ; 跳出整个 while 语句
102  if c < 5 goto 104        ; c < 5 成立转 104，否则顺序执行 103
103  goto 110                 ; 转去 else 分支
104  if x > y goto 106        ; x > y 成立转 106，否则顺序执行 105
105  goto 100                 ; 内层 while 结束，回到外层条件
106  t1 = x + 1               ; 计算 x + 1，存入临时变量 t1
107  z = t1                   ; 把 t1 的值赋给 z，完成 z = x + 1
108  goto 104                 ; 回到内层 while 的条件
110  x = y                    ; else 分支：把 y 的值赋给 x
111  goto 100                 ; 回到外层 while 的条件
112  ...                      ; while 语句之后的指令
```

读图说明：跳转指令的 j 取自英文单词 jump；凡带 `goto` 的指令都在改变控制流，没有跳转的指令按编号顺序往下走，这就是三地址码“顺序唯一确定”的表现。

把这段代码走一遍，控制流就清楚了。

先判断 $a$ 是否小于 $b$。如果 $a < b$，就跳转到 102 号指令，进一步判断 $c$ 是否小于 5；如果 $a$ 不小于 $b$，就继续执行 101 号指令，无条件跳转到 112 号指令，也就是跳出整个 while 循环语句。

当 $c < 5$ 的时候，跳转到 104 号指令，进一步判断 $x$ 是否大于 $y$；如果 $c$ 不小于 5，就继续执行 103 号指令，无条件跳转到 110 号指令——也就是说当 $c$ 不小于 5 的时候，要执行 else 分支的赋值指令，而 110 号指令就是将 $y$ 的值赋给 $x$。执行完这条指令以后，跳转到 100 号指令，也就是回到 while 语句的起始处，重新判断 $a$ 是否小于 $b$。

当 $x > y$ 的时候，执行 106 号指令。这条指令将 $x$ 的值加上 1 赋给 `t1`，然后进一步将这个值赋给 $z$，也就是完成了 $z = x + 1$。执行完这条语句以后，跳转到 104 号指令，重新判断 $x$ 是否大于 $y$。

如果 $x$ 不大于 $y$，那么就继续执行 105 号指令，无条件跳转到 100 号指令，也就是回到 while 语句的起始处。事实上，如果 $x$ 不大于 $y$，那么内层 while 语句就执行完毕，控制权要交回外层循环。

编译器如何根据分析树自动生成中间代码，是第六章要讲的内容。

### 目标代码生成与代码优化

目标代码生成以源程序的中间表示形式作为输入，并把它映射到目标语言。这一步有一个很重要的任务：为程序中使用的变量合理地分配寄存器。寄存器数量有限、访问最快，哪个变量放寄存器、哪个只能留在内存，直接决定生成代码跑得快不快。

代码优化则是为改进代码所进行的等价的程序变换，使其运行得更快一些，占用的空间更少一些，或者二者兼顾。“等价”是前提：变换前后的程序必须做同一件事，只是做得更省。

代码优化分为两类：

| 类别 | 优化发生在哪一层 | 关注点 |
| :--- | :--- | :--- |
| 机器无关优化 | 中间代码层面 | 与具体机器无关的等价变换 |
| 机器相关优化 | 目标代码层面 | 利用具体机器的特性做变换 |

优化的内容包括很多方面。比如自动识别代码中的重复运算或冗余运算，并将其删除；再比如把代价较高的运算替换为等价的代价较低的运算。详细内容在第八章和第九章展开。

### 语言与文法的基本概念

编译器要对高级程序设计语言进行词法、语法等分析。要想让计算机能够自动地分析语言，就要把相关的语言学知识，也就是文法，提供给计算机。那么在计算机中是如何表示语言及其文法的？这是第二章要回答的问题，先从几个基本概念开始。

#### 字母表与它的运算

第一个概念是**字母表**，用符号 $\Sigma$ 表示。一个字母表 $\Sigma$ 是一个有穷符号集合。符号的典型例子包括字母、数字、标点符号等等。例如，由 0 和 1 两个数字构成的集合是一个二进制字母表；ASCII 字符集和 Unicode 字符集也都是字母表。

既然字母表是一个集合，就可以在字母表上进行集合运算。

**字母表的乘积**：假设 $\Sigma_1$ 和 $\Sigma_2$ 是两个字母表，它们的乘积是一个集合，集合中的每个元素由两个符号构成，第一个符号来自 $\Sigma_1$，第二个符号来自 $\Sigma_2$。例如：

$$\{0, 1\} \times \{a, b\} = \{0a,\ 0b,\ 1a,\ 1b\}$$

**字母表的幂**：字母表 $\Sigma$ 的 $n$ 次幂是 $n$ 个 $\Sigma$ 相乘。例如二进制字母表的三次幂等于三个二进制字母表相乘，最后得到的集合中的元素都是长度为 3 的 01 字符串。可见，字母表的 $n$ 次幂实际上就是长度为 $n$ 的符号串构成的集合。

这里 $n$ 可以等于 0，也就是说 $\Sigma$ 的 0 次幂表示长度为 0 的符号串构成的集合。长度为 0 的符号串就是没有符号的符号串，称为**空串**，用一个特殊的符号 $\epsilon$ 表示。

**正闭包**：字母表 $\Sigma$ 的正闭包是 $\Sigma$ 的各个正数次幂的并集：

$$\Sigma^{+} = \Sigma^{1} \cup \Sigma^{2} \cup \Sigma^{3} \cup \cdots$$

例如 $\{a, b, c, d\}$ 这个字母表，它的正闭包就是由该字母表上长度为 1 的字符串集合，并上长度为 2 的字符串集合，再并上长度为 3 的字符串集合，以此类推。由此可见，字母表的正闭包实际上就是长度为正数的符号串构成的集合。

**克林闭包**：字母表 $\Sigma$ 的克林闭包是在正闭包的基础之上，再并上一个 $\Sigma$ 的 0 次幂，也就是在正闭包的基础上再添加一个空串：

$$\Sigma^{*} = \Sigma^{0} \cup \Sigma^{+}$$

由此可见，字母表的克林闭包实际上就是任意符号串构成的集合，这个符号串的长度可以为 0。

假设 $\Sigma$ 是一个字母表，那么 $\Sigma$ 的克林闭包中的每一个元素都称为 $\Sigma$ 上的一个**串**。由此可见，串就是字母表中符号的一个有穷序列。

#### 串与串上的运算

字符串 $s$ 的长度是指字符串 $s$ 中符号的个数，通常在 $s$ 的前后各加一条竖线来表示长度。例如字符串 $aab$，它的长度就是 3，写成 $|aab| = 3$。长度为 0 的字符串称为空串，用符号 $\epsilon$ 表示。

**连接**：如果 $x$ 和 $y$ 是两个串，$x$ 和 $y$ 的连接是指把 $y$ 附加到 $x$ 后面而形成的串，记为 $xy$。例如 $x = \text{dog}$，$y = \text{house}$，那么 $xy = \text{doghouse}$。空串是连接运算的单位元：对于任意一个串 $s$，在它的前面或者后面连接上一个空串，得到的还是 $s$。

**前缀与后缀**：假设 $x$、$y$、$z$ 是三个字符串，如果 $x = yz$，那么 $y$ 就是 $x$ 的前缀，$z$ 就是 $x$ 的后缀。

**串的幂**：如果把串上的连接运算看作是串的乘法运算，那么可以定义串的幂运算。串 $s$ 的 $n$ 次幂等于将 $n$ 个 $s$ 进行连接。例如 $s = ba$：

| 幂次 | 结果 |
| :--- | :--- |
| $s^{1}$ | $ba$ |
| $s^{2}$ | $baba$ |
| $s^{3}$ | $bababa$ |

值得注意的是，$s$ 的 0 次幂表示将 0 个 $s$ 连接起来，这实际上就是空串，所以 $s^{0} = \epsilon$。这条规定和字母表的 0 次幂是同一个道理：幂次为 0，留下的就只有空串。

### 本讲提到的题目

**题目**：符号表中为什么要设计字符串表这样一种数据结构，而不是将标识符直接存放到 name 字段中？

**解析**：回到符号表的结构看。符号表的每一条记录都要装 type、kind、value、address 这些字段，编译器查表时希望记录是定长的——知道第几条记录，就能用“表基址 + 序号 × 记录长度”一步算出它的位置。可是标识符的长度从一两个字符到几十个字符都有，如果名字直接塞进 name 字段，记录长度就跟着名字长短浮动，定长寻址立刻失效：按序号定位要逐条累加长度，插入和删除一条记录还要把后面所有记录整体搬动。

把名字挪进字符串表之后，符号表的 name 字段只剩下“起始位置 + 长度”两个整数，记录重新变成定长，寻址、插入、删除都退化成常数时间的下标运算；字符串表那边只做追加，已有的字符不用搬动。这样一拆，变长的部分被隔离在一张只增不改的表里，定长的部分留在符号表里承担检索。

**答案**：核心是用“定长记录 + 变长字符串分离”换取符号表的定长结构——name 字段只存起始位置和长度，标识符本身集中放在字符串表中。这样记录长度固定，便于按序号快速定位与增删；字符串表只追加不搬动，相同的名字或字符常数还能共用同一段字符，不必重复存储。

## 把语言的规则说清楚：从文法到正则表达式
> 对应块：BLK02 | 覆盖分集：P08-P13 | 块标题（分集名）：《2-2文法定义》

什么是文法？这个问题不适合从背定义开始——背下"四元组"三个字，跟会用它是两回事。我们先把问题摆到一个具体的句子上：给你一个从没见过的词串，你怎么判断它算不算某一门语言里合法的一句话？

接下来要讲的内容，都是围绕这个判断展开的：先把"规则"写成可以一步步算的式子，再让规则自己长出句子，最后把规则压到最紧凑的写法。

### 从一个英文句子出发

先看一个简化版本的、用来描述英语句子构成规则的文法：

```text
句子     → 名词短语 动词短语
名词短语 → 形容词 名词短语 | 名词
动词短语 → 动词 名词短语
形容词   → little
名词     → boy | apple
动词     → eat
```

逐条读下来：一个句子，由一个名词短语加一个动词短语构成；一个名词短语，可以由一个形容词加一个名词短语构成，也可以只由一个名词构成；一个动词短语，由动词加一个名词短语构成；形容词可以是 little，名词可以是 boy 或者 apple，动词可以是 eat。

从这个例子可以提取出文法的组成要素。出现在里面的符号明显分成两类：用尖括号括起来的那部分，是语法成分；没有括起来的那部分，是语言的基本符号。

分界线画在哪里，取决于这个文法描述的对象。这个文法描述的是句子的构成规则，句子的基本符号就是单词；如果换一个文法去描述单词的构成规则，那个文法的基本符号就变成字母了。

> **结论**：描述哪一级构造，基本符号就落在哪一级——描述句子时是单词，描述单词时是字母。这也是后面区分"终结符"的落脚点。

### 文法是一个四元组

根据这个例子，可以给出文法的形式化定义。文法用大写字母 $G$ 表示，把 $G$ 定义成一个四元组：

$$G = (V_T,\ V_N,\ P,\ S)$$

四个分量逐个说清楚。

#### 终结符与非终结符

$V_T$ 是终结符集合，$T$ 取自 terminal symbol。终结符就是文法所定义的语言的基本符号。刚才那个例子里，文法描述的是句子的组成规则，句子的基本符号是单词，于是这些单词构成了该文法的终结符集。终结符有时候也称为 token。

$V_N$ 是非终结符集合。非终结符用来表示语法成分，就是刚才那些用尖括号括起来的符号。它们之所以"非终结"，是因为还可以从它们进一步推导出其他的语法成分。非终结符有时也称为语法变量。

> **注意**：终结符集合与非终结符集合是不相交的，$V_T \cap V_N = \emptyset$。两者统称文法符号，所以 $V_T \cup V_N$ 表示的就是文法符号集。

#### 产生式：头与体

$P$ 是产生式的集合。产生式描述的是把终结符和非终结符组合成串的方法；说得直白一点，产生式就是用来产生串的式子。

产生式的一般形式是：

$$\alpha \to \beta$$

读作"$\alpha$ 定义为 $\beta$"。

从这里能看出，$\alpha$ 和 $\beta$ 表示的都是文法符号串。这个结论值得停一下，把中间那一步补上：$V_T$ 是终结符集合，它是一个字母表；$V_N$ 是非终结符集合，它也是一个字母表；两个字母表的并集仍然是一个字母表；而字母表的闭包，表示的是这个字母表上的符号串构成的集合。所以 $\alpha$、$\beta$ 都落在这个闭包里，都是文法符号串。

对 $\alpha$ 有一个硬性要求：至少要包含一个非终结符。$\alpha$ 称为产生式的头，也叫左部；$\beta$ 称为产生式的体，也叫右部。

刚才那个英文文法里，每一条规则都是一个产生式。

#### 开始符号

$S$ 是文法的开始符号。它是一个特殊的非终结符，表示该文法中最大的语法成分。

英文文法描述的是句子的构成规则，句子就是这个文法里最大的语法成分，所以句子是它的开始符号。

#### 一个算术表达式的例子

换一个更贴近程序设计语言的例子——简化版本的算术表达式文法：

```text
E → E + E
E → E * E
E → (E)
E → id
```

- 终结符集合是 $\{\mathbf{id}, +, *, (, )\}$：id 就是标识符，再加上加号、乘号、左括号、右括号。这些都是最终会出现在句子里的单词，所以它们构成这个文法的终结符集。
- 非终结符集合只有一个元素 $E$，$E$ 表示表达式（expression）。
- 产生式集合就是上面那四条。
- 开始符号是 $E$：表达式是这个文法最大的语法成分，而且这个文法里也没有别的非终结符。

这里约定：在不引起歧义的前提下，可以只写文法的产生式。上面四条一列，这个文法就说清楚了。

#### 候选式与符号约定

一组左部相同的产生式可以合并。对

$$\alpha \to \beta_1,\quad \alpha \to \beta_2,\quad \dots,\quad \alpha \to \beta_n$$

可以简记为

$$\alpha \to \beta_1 \mid \beta_2 \mid \dots \mid \beta_n$$

读作"$\alpha$ 定义为 $\beta_1$，或者 $\beta_2$，……，或者 $\beta_n$"。$\beta_1$ 到 $\beta_n$ 称为 $\alpha$ 的候选式。

于是那四条 $E$ 产生式可以简写成 $E \to E+E \mid E*E \mid (E) \mid \mathbf{id}$。

为了避免每次都声明哪些符号是终结符、哪些是非终结符，我们对符号的使用做一些约定：

| 符号 | 约定含义 |
| :--- | :--- |
| 字母表中排在前面的小写字母（$a$、$b$、$c$） | 终结符 |
| 运算符、标点符号、数字 | 终结符 |
| 粗体字符串（$\mathbf{id}$、$\mathbf{if}$） | 终结符 |
| 字母表中排在前面的大写字母（$A$、$B$、$C$） | 非终结符 |
| $S$ | 开始符号，一种特殊的非终结符 |
| 小写斜体名字（$expr$、$stmt$） | 非终结符，分别表示表达式与语句 |
| 代表程序构造的大写字母（$E$、$T$、$F$） | 非终结符：expression、term、factor |
| 字母表中排在后面的大写字母（$X$、$Y$、$Z$） | 文法符号，既可以是终结符，也可以是非终结符 |
| 字母表中排在后面的小写字母（$u$、$v$、$w$、$x$、$y$、$z$） | 终结符号串，包括空串 |
| 小写希腊字母（$\alpha$、$\beta$、$\gamma$） | 文法符号串，包括空串 |

两处要补一句：排在后面的小写字母表示的是终结符号串，既然是"串"，就有可能为空，所以包含空串；小写希腊字母表示文法符号串，同样是串，同样包含空串。

另外还有一条兜底约定：除非特别说明，第一个产生式的左部就是文法的开始符号。

把上面这些约定归成一句话就是：排在前面的小写字母是终结符，排在前面的大写字母是非终结符；排在后面的大写字母是文法符号；排在后面的小写字母是终结符号串；小写希腊字母是文法符号串。

### 推导与归约

现在回到开头那个判断问题：假设来了一个单词串 little boy eats apple，我们怎么判定它是不是满足前面那个英文文法的句子？

为了回答这个问题，先介绍两个概念：推导和归约。

#### 用产生式的右部替换左部

给定文法 $G$，如果存在一个产生式 $\alpha \to \beta$，就可以把符号串 $\gamma\alpha\delta$ 中的 $\alpha$ 替换为 $\beta$，也就是把 $\gamma\alpha\delta$ 重写为 $\gamma\beta\delta$，记作

$$\gamma\alpha\delta \Rightarrow \gamma\beta\delta$$

此时称文法符号串 $\gamma\alpha\delta$ 直接推导出 $\gamma\beta\delta$。

> **定义**：直接推导，就是用产生式的右部替换产生式的左部。

如果 $\alpha_0$ 能够直接推导出 $\alpha_1$，$\alpha_1$ 又能直接推导出 $\alpha_2$，以此类推，一直到 $\alpha_{n-1}$ 能够直接推导出 $\alpha_n$，那么记作

$$\alpha_0 \Rightarrow \alpha_1 \Rightarrow \alpha_2 \Rightarrow \dots \Rightarrow \alpha_n$$

称 $\alpha_0$ 经过 $n$ 步推导出 $\alpha_n$，简记为 $\alpha_0 \Rightarrow^{n} \alpha_n$。

两个边界要说清：$n = 1$ 时经过一步推导，就是直接推导；$n = 0$ 时经过零步推导，等于没有推导，所以 $\alpha$ 经过零步推导得到的还是 $\alpha$。

对应到前面讲过的闭包：直接推导的正闭包表示经过正数步推导，也就是至少一步，记作 $\Rightarrow^{+}$；直接推导的克林闭包表示经过若干步推导，可以是零步，记作 $\Rightarrow^{*}$。

#### 拿 little boy eats apple 推一遍

从文法的开始符号"句子"出发，实际推一遍：

```text
句子
⇒ 名词短语 动词短语
⇒ 形容词 名词短语 动词短语
⇒ little 名词短语 动词短语
⇒ little 名词 动词短语
⇒ little boy 动词短语
⇒ little boy 动词 名词短语
⇒ little boy eats 名词短语
⇒ little boy eats 名词
⇒ little boy eats apple
```

读图说明：每一行都是根据一条产生式，把它的右部替换进当前句型里的某个非终结符之后得到的符号串。

第一步，根据"句子 → 名词短语 动词短语"，把产生式的左部"句子"替换为右部"名词短语"加上一个"动词短语"。第二步，根据"名词短语 → 形容词 名词短语"，把"名词短语"替换成一个"形容词"加上一个"名词短语"。第三步，根据"形容词 → little"，把"形容词"替换成单词 little。

照这个方式继续：把"名词短语"替换成"名词"，把"名词"替换成 boy；把"动词短语"替换成一个"动词"加上一个"名词短语"，把这个"动词"替换成 eats；最后再把剩下的"名词短语"替换成"名词"，把"名词"替换成 apple。

这里要说明一点：我们忽略英文单词的形态变化，也就是说，把 eat 和 eats 看作是同一个词。

这个自顶向下的过程就是一个推导的过程——从文法的开始符号出发，最后推出了这样一个词串。

#### 归约是倒着走

与推导相反，那个自底向上的过程称为归约。

推导的每一步，是用产生式的右部替换产生式的左部；归约的每一步正好相反，是用产生式的左部替换产生式的右部。

```text
apple  → 名词  → 名词短语
eats   → 动词
动词 名词短语 → 动词短语
boy    → 名词  → 名词短语
little → 形容词
形容词 名词短语 → 名词短语
名词短语 动词短语 → 句子
```

照着走一遍：先根据"名词 → apple"把 apple 替换成左部"名词"，再根据"名词短语 → 名词"把这个"名词"替换成左部"名词短语"；把 eats 替换成"动词"；把"动词 名词短语"替换成"动词短语"；把 boy 替换成"名词"，再把这个"名词"替换成"名词短语"；把 little 替换成"形容词"；把"形容词 名词短语"替换成"名词短语"；最后，把"名词短语 动词短语"替换成文法的开始符号"句子"。

> **结论**：归约是推导的逆过程。

#### 一个词串凭什么算句子

有了推导和归约，开头那个问题就有答案了，而且答案有两条途径。

一条是从生成的角度讲：如果从文法的开始符号可以推导出这个词串，那么这个词串就是该语言的一个句子。

另一条是从识别的角度讲：如果从这个词串可以归约出文法的开始符号，那么这个词串就是该语言的一个句子。

> **结论**：无论走哪一条途径，每一步都必须"根据规则"来——推导和归约的每一步，都要对得上文法里的某一条产生式。

### 句型、句子与语言

#### 句型与句子

先看句型。如果从文法的开始符号 $S$ 出发，经过若干步可以推导出一个文法符号串 $\alpha$，那么 $\alpha$ 就称为这个文法的一个句型。

由于 $\alpha$ 是一个文法符号串，所以一个句型里既可以包含终结符，也可以包含非终结符，还可能是空串。

再看句子。如果 $\alpha$ 中的每一个符号都是终结符，也就是说，从开始符号 $S$ 经过若干步可以推导出一个终结符号串 $w$，那么这个终结符号串 $w$ 就是该文法的一个句子。

> **结论**：句子是一个特殊的句型——不包含任何非终结符的那种句型。

回到刚才那个推导：推导过程中每一步得到的符号串都是一个句型，但只有最后一个句型可以称为句子，因为只有它里面没有非终结符。

#### 语言是句子的集合

由文法 $G$ 的开始符号 $S$ 推导出的所有句子构成的集合，称为文法 $G$ 生成的语言，记为 $L(G)$，$L$ 取自 language：

$$L(G) = \{\, w \in V_T^{*} \mid S \Rightarrow^{+} w \,\}$$

回到那个算术表达式文法：它生成的语言里包含多少个句子？回答是无穷多个。

> **结论**：文法解决了无穷语言的有穷表示问题——一个有限的四元组，把无穷多个句子一次说清楚了。

#### 标识符：从文法推出来的语言

看一个具体例子。下面这个文法，生成的语言是什么？

```text
D → 0 | 1 | 2 | … | 9
L → a | b | c | … | z
T → L | D | T L | T D
S → L | L T
```

先看 $D$ 的产生式：$D$ 定义为 0 或 1 或 2，一直到 9，所以 $D$ 表示的是数字（digit）。再看 $L$：$L$ 定义为 a 或 b 或 c，一直到 z，所以 $L$ 表示的是字母（letter）。

那么 $T$ 表示什么？$T$ 定义为 $L$ 或者 $D$，可见 $T$ 可以用来表示一个字母或者一个数字；而它的后两个候选式是 $T \to TL$ 和 $T \to TD$，也就是说，还可以把 $T$ 替换成 $TL$ 或者 $TD$。

关键在于，串首那个 $T$ 是"还能继续长"的位置：

```text
T ⇒ T L ⇒ T D L ⇒ T D D L ⇒ … ⇒ D D D L
```

读图说明：每一步都只动最左边那个 $T$，把它换成 $TL$ 或 $TD$，所以最左边始终留着一个可替换的位置，直到最后一步把它换成 $D$ 为止。

不妨假设第一步把 $T$ 替换成了 $TL$；对于串首这个非终结符 $T$，继续替换成 $TL$ 或者 $TD$，假设这一步替换成了 $TD$；接下来对串首的 $T$ 再替换，假设又换成了 $TD$。这个替换的过程可以一直进行下去，直到最后一步把串首的 $T$ 替换成 $D$——这样得到的，实际上就是一个字母数字串。

最后看文法的开始符号 $S$ 能推出什么。$S$ 定义为 $L$ 或者 $LT$：$S$ 可以表示一个字母，或者一个字母后面加上一个字母数字串。概括起来，$S$ 推出的是字母打头的字母数字串。

> **结论**：这正是标识符的构成方法，所以这个文法生成的语言，实际上就是标识符。

#### 语言上的运算

按定义，语言是一个集合，那么我们自然就可以在语言上进行若干集合运算：并运算、连接运算（也就是乘积运算）、幂运算，还有闭包运算。

这里有一个容易含糊的点：语言 $L$ 的零次幂，是由空串构成的集合，即 $L^0 = \{\varepsilon\}$。

看一个例子。$L$ 是字母的集合，我们把它看作一种语言；$D$ 是数字的集合，也把它看作一种语言。

- $L \cup D$ 得到的，是由字母和数字构成的语言；
- $(L \cup D)^{*}$ 表示的是由字母数字串构成的集合；
- $L(L \cup D)^{*}$ 表示的，是由字母打头的字母数字串构成的集合。

最后这个集合，实际上也是标识符的构成方法，因此它表示的也是标识符。

同一个语言——标识符——到这里已经见过两种写法了：一套产生式，一个集合表达式。后面还会见到第三种，也是更紧凑的一种。

### 乔姆斯基的四级分类

根据对文法中产生式的不同要求，乔姆斯基把文法分成了四种类型，分别是 0 型文法、1 型文法、2 型文法和 3 型文法，合称乔姆斯基文法分类体系。

这一套分类的划分依据只有一条：产生式被限制到什么程度。限制一层层加上去，语言也一类比一类窄。

#### 无限制文法

0 型文法就是我们前面定义的那种文法。它对产生式几乎没有限制，只要求产生式左部 $\alpha$ 中至少包含一个非终结符。

所以 0 型文法也称为无限制文法，或者短语结构文法。由 0 型文法生成的语言，称为 0 型语言。

#### 上下文有关文法

1 型文法也称为上下文有关文法。它在 0 型文法的基础上进一步要求：产生式左部 $\alpha$ 中符号的个数，不能多于右部 $\beta$ 中符号的个数。

$$\lvert\alpha\rvert \le \lvert\beta\rvert$$

这类文法之所以叫上下文有关文法，是因为在这类文法中，产生式的一般形式为

$$\alpha_1 A \alpha_2 \to \alpha_1 \beta \alpha_2$$

也就是说，非终结符 $A$ 只有在它的上下文分别是 $\alpha_1$ 和 $\alpha_2$ 的时候，才可以替换为 $\beta$——替换得看着左右邻居的脸色，所以它是上下文有关的。

由这个定义可以直接看出：上下文有关文法中不包含空产生式。所谓空产生式，就是产生式右部 $\beta$ 是空串的产生式。假设上下文有关文法里允许空产生式，那么 $\lvert\beta\rvert = 0$；而左部 $\alpha$ 至少要包含一个非终结符，所以 $\lvert\alpha\rvert \ge 1$。左部长度大于等于 1、右部长度等于 0，这与 $\lvert\alpha\rvert \le \lvert\beta\rvert$ 直接矛盾。

由上下文有关文法生成的语言，叫做上下文有关语言。

> **易错点**：长度不等号的方向不要记反。是左部不长于右部，右部至少要跟左部一样长；方向一旦反过来，空产生式就成了合法产生式，整个层级的结论都会跟着变。

#### 上下文无关文法

2 型文法也称为上下文无关文法，简称 CFG。上下文无关文法要求每一个产生式的左部 $\alpha$ 必须是一个非终结符，也就是产生式的一般形式为

$$A \to \beta$$

这里的大写字母 $A$ 表示非终结符，这是前面就约定好的。

这条要求的意思很直接：把 $A$ 替换成 $\beta$，不需要考虑它的上下文，因此它称为上下文无关文法。

前面那个生成标识符的文法，每一条产生式的左部都是单个非终结符，所以它就是一个上下文无关文法。由上下文无关文法生成的语言，称为上下文无关语言。

#### 正规文法

3 型文法也叫正规文法，简称 RG。它分为两种：右线性文法和左线性文法。

右线性文法在 2 型文法的基础上，进一步对产生式的右部作出限制：每一条产生式的右部，要么是一个终结符号串 $w$，要么是在终结符号串 $w$ 的右边添一个非终结符 $B$。

$$A \to w \qquad \text{或} \qquad A \to wB$$

相应的，左线性文法要求产生式的右部要么是一个终结符号串 $w$，要么是在终结符号串 $w$ 的左边添一个非终结符：

$$A \to w \qquad \text{或} \qquad A \to Bw$$

把这两种情况概括起来：在正规文法中，产生式的右部最多只有一个非终结符，而且所有产生式里这个非终结符都要待在同一侧。

看一个右线性文法的例子：

```text
S → 字母 | 字母 T
T → 字母 | 数字 | 字母 T | 数字 T
```

这里的"字母""数字"是终结符的占位说法——具体展开时，用 a、b、c、d 代表全部字母，用数字代表全部数字。

先验一下它是不是右线性文法：每一条产生式的左部都是一个非终结符，所以它首先满足上下文无关文法也就是 2 型文法的要求；再看各产生式的右部，要么是一个终结符号串，要么是在终结符号串的右边增加一个非终结符，所以它是右线性文法。

那么这个右线性文法生成的是什么语言？根据 $T$ 的产生式，$T$ 可以表示一个字母，也可以表示一个数字；而 $T$ 又可以定义成"一个字母或者一个数字后面加上一个 $T$"，后面这个 $T$ 还能继续替换成一个字母或数字加 $T$。这个替换过程可以一直循环下去，因此 $T$ 生成的实际上是一个字母数字串。

再看文法的开始符号：$S$ 定义为一个字母，或者一个字母加上一个字母数字串。概括起来，就是字母打头的字母数字串——这实际上还是标识符的构造方法。所以这个文法生成的语言也是标识符，它跟我们前面介绍的那个生成标识符的上下文无关文法是等价的。

事实上，还可以写出与这个右线性文法等价的左线性文法，这就留作练习了。

由正规文法生成的语言称为正规语言。不仅标识符可以用正规文法来描述，程序设计语言中的大多数单词都可以用正规文法来描述——这一点会在第三章词法分析里详细展开。

#### 逐级包含

四种文法之间的关系，直接从各自的限制条件就能读出来：

| 类型 | 别称 | 对产生式的限制 | 生成的语言 |
| :--- | :--- | :--- | :--- |
| 0 型 | 无限制文法、短语结构文法 | 左部 $\alpha$ 中至少包含一个非终结符 | 0 型语言 |
| 1 型 | 上下文有关文法（CSG） | $\lvert\alpha\rvert \le \lvert\beta\rvert$，一般形如 $\alpha_1 A \alpha_2 \to \alpha_1\beta\alpha_2$ | 上下文有关语言 |
| 2 型 | 上下文无关文法（CFG） | 左部必须是单个非终结符，$A \to \beta$ | 上下文无关语言 |
| 3 型 | 正规文法（RG） | 右线性 $A \to w \mid wB$；左线性 $A \to w \mid Bw$ | 正规语言 |

这张表里的限制是一层压一层加上去的：0 型只要求左部含有非终结符；1 型再加一条长度关系；2 型把左部收窄成单个非终结符；3 型再限制右部的形状。

由此得到一个结论：如果不考虑空产生式的因素，各种类型的文法集合之间是一个逐级包含的关系。

```text
0 型文法（无限制文法 / 短语结构文法）
└── 1 型文法（上下文有关文法，CSG）
    └── 2 型文法（上下文无关文法，CFG）
        └── 3 型文法（正规文法，RG）
```

读图说明：越往里，限制越强，能装进来的文法就越少。

于是：如果一个文法是 2 型文法，那么它一定是 1 型文法，但反过来不成立；一个 3 型文法肯定是 2 型文法，进而也肯定是 1 型文法，反过来同样不成立。

> **注意**：这个逐级包含的结论，前提是"不考虑空产生式"。前面已经论证过 1 型文法不含空产生式，而写文法时又常常用到空产生式，所以严格来说，含空产生式的文法不在这个逐级包含关系的讨论范围之内。

### 分析树

前面讲过，正规文法可以用来描述程序设计语言中的大多数单词，但它的生成能力有限，几乎描述不了程序设计语言中的句子构造。而上下文无关文法可以描述大部分程序设计语言中的语法构造，也是被研究得最多的一种文法。所以这一节专门讲上下文无关文法的分析树。

第一章里已经对分析树有了一点了解——分析树是用来描述句子结构的。这里给出分析树的正式定义。

#### 分析树的定义

这一节用的例子是一个带负号的算术表达式文法，要用到的产生式是 $E \to E+E$、$E \to -E$、$E \to (E)$ 和 $E \to id$，开始符号是 $E$。

- 根结点对应文法的开始符号。在例子中，根结点就对应文法的开始符号 $E$。
- 每一个内部结点表示对一个产生式的应用：该结点的标号是产生式的左部 $A$，该结点的子结点的标号从左到右构成了产生式的右部 $\beta$。
- 叶结点的标号既可以是非终结符，也可以是终结符。
- 从左到右排列叶结点得到的符号串，称为这棵树的产出，或者边缘。

对照例子看：根结点是一个内部结点，它表示的是对"$E \to -E$"这条产生式的一次应用，所以根结点的标号是这条产生式的左部，而它的子结点的标号从左到右构成了这条产生式的右部——负号和 $E$。再往下，那个结点是对"$E \to (E)$"的应用，最下面那个结点是对"$E \to E+E$"的应用。

#### 边缘与推导

分析树是推导的图形化表示。给定一个推导

$$S \Rightarrow \alpha_1 \Rightarrow \alpha_2 \Rightarrow \dots \Rightarrow \alpha_n$$

对推导过程中的每一个句型 $\alpha_i$，都可以构造出一棵边缘为 $\alpha_i$ 的分析树。

换句话说：推导走一步，树往下长一层；树每长一层之后的边缘，恰好就是那一刻的句型。

#### 长出一棵分析树

现在把推导和树放在一起，一步一步走。

从文法的开始符号 $E$ 开始推导。初始的时候，分析树中只有一个结点，也就是根结点，它对应文法的开始符号 $E$。

第一步，根据"$E \to -E$"把文法的开始符号替换成 $-E$。分析树这一边，就是对根结点应用这条产生式，为它生成两个子结点，这两个子结点分别对应右部中的两个符号：负号和 $E$。这个时候，分析树的边缘 $-E$ 就对应着当前的句型 $-E$。

第二步，根据"$E \to (E)$"把这个句型中的符号 $E$ 替换为"括号 $E$"。分析树这一边，就是对那个 $E$ 结点应用这条产生式，为它添加三个子结点，分别对应右部中的三个符号。这个时候生成的分析树，它的边缘是负号、左括号、$E$、右括号，正好对应着当前的句型。

这个过程可以一直进行下去：里面那个 $E$ 用"$E \to E+E$"换成 $E+E$，两个 $E$ 再用"$E \to id$"换成 id。

```text
E
└─ E → -E
   ├─ -
   └─ E
      └─ E → (E)
         ├─ (
         ├─ E
         │  └─ E → E + E
         │     ├─ E → id
         │     ├─ +
         │     └─ E → id
         └─ )
```

读图说明：缩进表示父子关系，箭头右侧是作用在这一个结点上的产生式；最底下一排的 id 都是叶结点，从左到右把叶结点读出来，就是 $-(id+id)$。

最后推出句子 $-(id+id)$ 的时候，生成的分析树，它的边缘对应的正好也是这个句子。

#### 短语与直接短语

给定一个句型，它的分析树中每一棵子树的边缘，都称为该句型的一个短语。

比如句型 $-(E+E)$ 的分析树：整棵树的根对应的子树，边缘是 $-(E+E)$，所以它构成该句型的一个短语；以括号里面那个 $E$ 为根结点的子树，边缘是 $(E+E)$，也是该句型的一个短语；再往里，以最里面那个 $E$ 为根结点的子树，边缘是 $E+E$，仍然是该句型的一个短语。

> **定义**：如果一棵子树只有父子两代结点，也就是说这棵子树的高度为 2，那么这棵子树的边缘称为该句型的一个直接短语。

在这个例子里，只有以最里面那个 $E$ 为根结点的子树高度是 2，所以它的边缘 $E+E$ 就是这个句型的直接短语。

#### 产生式的右部不一定是直接短语

从定义可以直接推出一半结论：直接短语是高度为 2 的子树的边缘，而这样一棵子树正好对应一次产生式的应用，所以直接短语一定是某个产生式的右部。

反过来不成立。看这个例子：一个文法里，"高人""人民""民生""生活""活水""水平"都是名词，也就是同一条产生式的右部。现在输入一个句子："提高人民生活水平"。

在它对应的分析树里，"人民""生活""水平"分别是以这三个名词作为根结点的子树的边缘，而且这三棵子树的高度都是 2：

```text
名词     名词     名词
 │        │        │
人民     生活     水平
```

读图说明：三个名词结点各自只挂一个子结点，子树高度为 2，所以它们的边缘"人民""生活""水平"都是这个句子的直接短语。

而"高人""民生""活水"虽然也是那条产生式的右部，但在这棵分析树里，它们不是任何一棵高度为 2 的子树的边缘，所以它们不是这个句子的直接短语。

它们有可能是别的句子的直接短语。比如"活水"，在句子"唯有源头活水来"里就是一个直接短语；但在"提高人民生活水平"里，它不是。

> **易错点**：直接短语一定是某个产生式的右部，但产生式的右部不一定是当前句型的直接短语。判断时要回到这一棵分析树上看，不能只看文法里有没有这条产生式。

#### 二义性

> **定义**：如果一个文法可以为某个句子生成多棵分析树，则称这个文法是二义性的。

看一个例子。这是一个用来描述条件语句的文法：

```text
S → if E then S
S → if E then S else S
S → other
```

前两个候选式表示的是条件语句：条件语句分两种，一种带 else，一种不带 else。第三个候选式 other 表示除条件语句以外的其他语句，比如赋值语句、循环语句、过程调用语句等等。

现在有了一个句型：

```text
if E1 then if E2 then S1 else S2
```

为它构造分析树，可以构造出两棵：

```text
第一棵                                第二棵
if E1 then                            if E1 then
    if E2 then S1 else S2                if E2 then S1
                                      else S2
```

读图说明：第一棵把 `if E2 then S1 else S2` 整体当作内层语句，else 归里面那个 if；第二棵只把 `if E2 then S1` 当作内层语句，else 归外面那个 if。

同一个文法、同一个句子，却能构造出两棵分析树，所以这个文法是二义性文法。

大多数编译器都希望文法不是二义性的，因为遇到歧义的时候，计算机无法进行确定的操作。

要消除歧义，就得改造文法。但改造文法需要付出代价，比如要引入新的非终结符或者空产生式。在某些情况下，也可以通过引入一些消歧规则来消除二义性。

回到这个例子：产生歧义的根源，是句子里有两个 if 却只有一个 else，这个 else 既可以跟第一个 if 匹配，也可以跟第二个 if 匹配。大多数程序设计语言都规定：每个 else 和最近的、尚未匹配的 if 匹配。按这条规则，else 就跟第二个 if 匹配——于是删掉第二棵分析树，只保留第一棵。

最后一个问题：怎么判定一个上下文无关文法是不是二义性的？

> **结论**：对于任意一个上下文无关文法，不存在一个算法来判定它是否是无二义性的。但是我们能给出一组充分条件，满足这组条件的文法一定是无二义性的。

充分条件的含义要分清：满足了这组条件，它肯定是无二义性的；但是不满足这组条件，也未必就是有二义性的。

### 正则表达式

进入第三章，词法分析。

第二章里曾经讲到，程序设计语言的大多数单词都可以用正规文法来描述。这一章要介绍一种用来描述正规语言的更紧凑的表示方法——正规表达式。

#### 从集合写法到紧凑写法

前面反复用到的一条事实是：语言是一个集合，因此可以在语言上进行多种集合运算，比如并运算、乘积运算（也就是连接运算），还有闭包运算。

看一个语言。这个语言中的每一个句子是这样构成的：句首是字母 $a$，接下来连接一个任意长度的 $ab$ 串，再接下来连接一个空串，这个时候表示句子已经结束了；除此之外，还可以连接一个点号或者下划线，接下来连接一个长度大于等于 1 的 $ab$ 串。

这个语言用集合记号写出来，又是花括号又是并运算，写起来比较复杂。换成正规表达式，是这样：

$$a(ab)^{*}\left(\varepsilon \mid (. \mid \_)(ab)^{+}\right)$$

对着念一遍就明白了：$a$ 是句首那个字母；$(ab)^{*}$ 是任意长度的 $ab$ 串；$\varepsilon$ 那一支表示句子到此结束；另一支先接一个点号或下划线，再接一个长度至少为 1 的 $ab$ 串——$(ab)^{+}$ 正好就是"一个以上"。

从这个例子可以看出正规表达式的构造方式：它可以由较小的正规表达式，按照特定的规则递归地构建。每个正规表达式 $r$ 定义或者表示一个语言，记为 $L(r)$；这个语言也是根据 $r$ 的子表达式所表示的语言递归定义的。

#### 递归定义与优先级

既然正规表达式是按照一定规则递归构建的，定义也就顺着这个递归给出。

- 空串 $\varepsilon$ 是一个正规表达式，它表示的语言只包含空串：$L(\varepsilon) = \{\varepsilon\}$。
- 字母表 $\Sigma$ 上的任何一个符号 $a$ 都是一个正规表达式，它表示的语言只包含它自己：$L(a) = \{a\}$。
- 假设 $r$ 和 $s$ 是两个正规表达式，它们表示的语言分别是 $L(r)$ 和 $L(s)$，那么 $r \mid s$ 也是一个正规表达式，它表示的语言是两者的并集：$L(r \mid s) = L(r) \cup L(s)$。
- $r$ 和 $s$ 连接，$rs$ 也是一个正规表达式，它表示的语言是 $L(r)$ 连接上 $L(s)$：$L(rs) = L(r)L(s)$。
- $r$ 的克林闭包 $r^{*}$ 也是一个正规表达式，它表示的语言就是 $L(r)$ 的克林闭包：$L(r^{*}) = (L(r))^{*}$。
- 括号 $(r)$ 也是一个正规表达式，它表示的语言就是 $L(r)$。

这几种运算的优先级，由高到低依次是：克林闭包、连接、或运算。

拿一个只有两个符号的字母表 $\Sigma = \{a, b\}$ 走一遍：

- $a$ 是正规表达式，$b$ 也是正规表达式；
- 因此 $a \mid b$ 还是正规表达式，它表示符号 $a$ 或符号 $b$；
- $(a \mid b)(a \mid b)$ 也是正规表达式，它表示这个串由两个符号构成，第一个符号是 $a$ 或者 $b$，第二个符号也是 $a$ 或者 $b$，所以它表示的串包括 $aa$、$ab$、$ba$、$bb$；
- $a^{*}$ 表示把任意个 $a$ 连接起来；
- $(a \mid b)^{*}$ 表示任意长度的 $ab$ 串；
- $a \mid a^{*}b$ 表示 $a$，或者是若干个 $a$ 后面连接一个 $b$。

#### 描述 C 语言的无符号整数

十进制整数：

$$(1 \mid 2 \mid \dots \mid 9)(0 \mid 1 \mid \dots \mid 9)^{*} \;\mid\; 0$$

它表示：第一个符号是 1 至 9 中的一个数字，接下来连接若干个 0 至 9 中的数字；除此之外，还可以就是单独的符号 0。

八进制整数：

$$0\,(1 \mid 2 \mid \dots \mid 7)(0 \mid 1 \mid \dots \mid 7)^{*}$$

第一个符号是数字 0，第二个符号是 1 至 7 中的一个数字，接下来连接若干个 0 至 7 中的数字。

十六进制整数：

$$0\,x\,(1 \mid 2 \mid \dots \mid 9 \mid a \mid b \mid \dots \mid f)(0 \mid 1 \mid \dots \mid 9 \mid a \mid b \mid \dots \mid f)^{*}$$

第一个符号是 0，第二个符号是 $x$，第三个符号是 1 至 9 或者 a 至 f 中的一个符号，接下来连接若干个 0 至 9 或者 a 至 f 中的符号。

注意十进制那一支末尾的那个 $0$：它表示单独的 0 本身也是一个合法的十进制无符号整数。

> **定义**：可以用正规表达式定义的语言，叫做正规语言，或者正规集合。

#### 代数定律与等价性

正规表达式遵循一些代数定律：

- 或运算满足交换律和结合律：$r \mid s = s \mid r$，$(r \mid s) \mid t = r \mid (s \mid t)$；
- 连接运算满足结合律：$(rs)t = r(st)$；
- 连接运算对或运算满足分配律：$r(s \mid t) = rs \mid rt$，$(s \mid t)r = sr \mid tr$；
- 空串是连接的单位元：$\varepsilon r = r\varepsilon = r$——在一个正规表达式的前面或者后面加上一个空串，表示的还是这个正规表达式；
- 闭包中一定包含空串：$\varepsilon \in L(r^{*})$；
- 克林闭包运算具有幂等性：$(r^{*})^{*} = r^{*}$。

还有一条更根本的结论：

> **结论**：正规文法与正规表达式是等价的。对任何一个正规文法 $G$，都存在定义同一语言的正规表达式 $r$；反过来，对任何正规表达式 $r$，也都存在生成同一语言的正规文法 $G$。

### 正则定义

#### 给正则表达式起名字

写复杂的正规表达式时，同一个子表达式要反复写，读起来也费劲。为了方便，可以给某些正规表达式命名，然后像使用字母表中的符号一样，用这些名字来构造正规表达式。

具体来说，正则定义是这样一个定义序列：

```text
d1 → r1
d2 → r2
…
dn → rn
```

每一个 $r_i$ 都是一个正规表达式，每一个 $d_i$ 都是给对应正规表达式 $r_i$ 起的名字。

对名字有两条硬性要求：每一个 $d_i$ 都是一个新符号，它们都不在字母表 $\Sigma$ 中，而且互不相同；每一个 $r_i$ 只能使用字母表中的符号，或者已经定义好的前 $i-1$ 个名字 $d_1, d_2, \dots, d_{i-1}$。

"只能用前面已经定义的"这一条是关键：它保证了每个名字在被使用之前已经有定义，整个定义序列不会绕成一个圈。

#### C 语言标识符的正则定义

```text
digit   → 0 | 1 | 2 | … | 9
letter_ → 字母 | 下划线
id      → letter_ ( letter_ | digit )*
```

第一个正规表达式表示 0 至 9 中的一个数字，给它起个名字叫 digit，表示"数字"。

第二个正规表达式表示一个字母或者下划线，给它起个名字叫 letter_。

第三个正规表达式，用前面起好的这两个名字来构造：首先是一个 letter_，接下来连接一个由 letter_ 或者 digit 构成的串。这个表达式表示的就是字母打头的字母数字串，正是标识符的构造方法，所以给它起个名字叫 id，表示标识符。

#### 无符号数的正则定义

```text
digit        → 0 | 1 | 2 | … | 9
digits       → digit digit*
可选小数部分 → . digits | ε
可选指数部分 → E + digits | E - digits | E digits | ε
number       → digits 可选小数部分 可选指数部分
```

逐条看。

digit 还是表示一个数字。digit 连接上一个 digit 的克林闭包，表示的是一个长度大于等于 1 的数字串，给它起个名字叫 digits。

"可选小数部分"是一个点号后面连接上一个长度大于等于 1 的数字串，表示的是小数部分；这个正规表达式还可以取空串，所以叫"可选的小数部分"。

"可选指数部分"表示大写字母 E 后面连接一个正号，或者一个负号，或者直接连接上一个长度大于等于 1 的数字串，表示的是指数部分；这个正规表达式也可以取空串，所以叫"可选的指数部分"。

number 由三部分构成：第一部分是一个长度大于等于 1 的数字串，接下来连接可选的小数部分，再接下来连接可选的指数部分。

两个可选部分各取空串还是非空，组合起来正好覆盖四类数：

| 小数部分 | 指数部分 | 表示的数 | 例子 |
| :--- | :--- | :--- | :--- |
| 空串 | 空串 | 整数 | $2$ |
| 非空 | 空串 | 小数 | $2.15$ |
| 非空 | 非空 | 指数形式的浮点数 | $2.15E+3$，即 $2.15 \times 10^{3}$；$2.15E-3$，即 $2.15 \times 10^{-3}$ |
| 空串 | 非空 | 整数的若干次幂 | $2E-3$，即 $2 \times 10^{-3}$ |

指数为正数的时候，这个正号是可以省略的，比如 $2.15E3$ 表示的就是 $2.15 \times 10^{3}$。

> **提示**：这里的 `E` 是字母表里一个普通符号，用作指数标记，跟前面那个表示表达式的非终结符 $E$ 不是一回事，同名不同身份。

由此可见，number 这个正则定义表示的就是整型或者浮点型的无符号数。

### 本讲提到的题目

#### 写出无符号整数和浮点数的文法

**题目**：写出无符号整数和浮点数的文法。

**解析**：正文里的"无符号数的正则定义"已经把这件事拆成了三块——数字串、可选的小数部分、可选的指数部分。把每个名字换成一个非终结符，把"连接"换成产生式首尾相接，就得到文法。

**答案**（一种可行的写法）：

```text
S → N | N . N | N E T | N . N E T
N → D | N D
T → + N | - N | N
D → 0 | 1 | … | 9
```

$N$ 生成至少一位的数字串；$S$ 的四条候选式分别对应整数、小数、带指数的整数、带指数的小数；这里的 $E$ 是终结符，就是指数标记那个字符；$T$ 是 $E$ 后面那一段，允许带正号、带负号，也允许不带符号。四条产生式的左部都是单个非终结符，所以这是一套上下文无关文法。如果要求写成正规文法，就得把"数字串—小数部分—指数部分"这三段的连接拆成一串右线性产生式，篇幅会长不少，但思路与前面右线性标识符文法相同。

#### 写出生成标识符的左线性文法

**题目**：写出与前面那个右线性标识符文法等价的、用来生成标识符的左线性文法。

**解析**：左线性要求非终结符出现在终结符号串的左边，也就是 $A \to w$ 或 $A \to Bw$ 的形状。所以右线性里"终结符在前、非终结符在后"的写法，要整体调一个个儿。

**答案**（一种可行的写法）：

```text
S → a | b | … | z
S → S a | S b | … | S z
S → S 0 | S 1 | … | S 9
```

第一组产生式给出一个单独的字母，这是标识符的第一个字符；后两组产生式表示"一个标识符后面再接一个字母或数字，仍然是标识符"。从单个字母出发，反复接字母或数字，得到的就是字母打头的字母数字串。

> **提示**：左线性、右线性说的是产生式右部里非终结符站的位置，不是串往哪个方向生长。$S \to Sa$ 里非终结符 $S$ 站在终结符 $a$ 的左边，所以它是左线性。

用 $L$、$D$ 两个非终结符可以把这套文法写得更短（$S \to L \mid SL \mid SD$，$L \to a \mid \dots \mid z$，$D \to 0 \mid \dots \mid 9$），但严格按"右部最多一个非终结符"的要求，$S \to SL$ 里出现了两个非终结符，得展开成上面那种逐个符号的形式才算标准写法。

## 有穷自动机：从一部电梯到词法分析器
> 对应块：BLK03 | 覆盖分集：P14-P18 | 块标题（分集名）：《3-3有求自动机》

### 1948 年，两位神经物理学家

有穷自动机这个名字听着像是为编译器准备的，其实它出生在别的领域。1948 年，两位神经物理学家首先提出了它，用来对一类处理系统建立数学模型。

这类系统有几个共同点：它有一系列离散的输入输出信息，内部状态数目有穷。而这里的"状态"不是随便贴的标签，它概括的是**过去输入信息处理的状况**。系统不需要把历史全部记下来，只要知道当前处在哪个状态、当前面临什么输入，就能决定后续行为；每处理完一个输入，内部状态也随之改变。

电梯控制装置是个典型例子。

- 输入：顾客的乘梯需求，也就是他要到达的层号；
- 状态：电梯当前所处的层数，加上它的运行方向——上行还是下行。

电梯并不需要记住先前全部服务要求。它只要知道当前状态，再加上"还有哪些服务请求没有被满足"，就能决定下一步是继续上行、下行，还是停下来开门。所有按过的键，都被压缩进了这两样东西里。

> **提示**：这就是"有穷"两个字的实际含义——不是输入有穷，而是**记住过去的能力有穷**。输入可以任意长，机器只保留一个有穷的状态，用状态代表它"记得"的那部分历史。

词法分析器要干的正是这件事。源程序可以几十万字符，但扫描到某一处时，需要记住的东西只有"当前这个单词读到了哪一段"。这也是有穷自动机能成为词法分析理论基础的原因。

### 机器上只有三样东西

FA 的模型由三部分构成：输入带、读头、有穷控制器。

```text
  +----+----+----+----+----+----+
  | a  | b  | b  | a  | a  | b  | ...   <- 输入带：存放输入符号串
  +----+----+----+----+----+----+
                 ^
                 |                      <- 读头：从左向右逐个读取，不能修改
        +--------+--------+
        |  finite control |             <- 有穷控制器：有穷个状态
        +-----------------+
```

输入带用来存放输入符号串。读头从左向右逐个读取输入符号，它有三个限制：**不能修改**带上的符号，**不能往返移动**，也就是说只能从左往右，不能从右往左。

有穷控制器里有有穷个状态。它根据当前的状态和当前的输入符号，来控制转入下一个状态。

> **提示**：读头不能改写、不能回退，这不是图省事，而是词法分析的真实约束——源程序是只读的，扫描器顺着往下走，走过的字符不会回头去改。真需要"回头看"的时候，靠的是另设的输入指针回退，而不是让读头倒着走。

于是整台机器的"记忆"只有一处：控制器里那个状态。它能记住多少，完全由状态数决定。

### 转换图：怎么把自动机画出来

有穷自动机可以用一种叫**转换图**的有向图表示。图里每个节点表示 FA 的一个状态；除节点之外，还有一批带标记的有向边。

状态分两类。一类是**初始状态**：只有一个，由一条 `start` 箭头指向。另一类是**终止状态**，也叫接收状态：可以有多个，用双圈表示。

边的画法是一条约定：如果对输入符号 $a$，存在一个从状态 $p$ 到状态 $q$ 的转换，就在 $p$ 和 $q$ 之间画一条有向边，标上符号 $a$。比如在状态 0 和状态 1 之间标上 $a$，就表示"在状态 0 遇到符号 $a$，可以进入下一个状态——状态 1"。

```text
   start
     |
     v
   ( 0 ) --a--> ( 1 )        ( 2 )        (( 3 ))

   ( )     单圈：普通状态
   (( ))   双圈：终止（接收）状态，可以有多个
   start   箭头指向的那个，是唯一的初始状态
```

读图的路数是固定的：先顺着 `start` 箭头找到起点，再找双圈看哪些地方算"走通了"，中间那些带标记的边就是每一步可走的路。图里只画了对理解有用的部分，一台自动机究竟有哪些边，以它自己的定义为准。

### 什么叫"接收"一个串

> **定义**：给定一个输入串 $x$，如果存在一个对应于串 $x$ 的、从初始状态到某个终止状态的转换序列，则称串 $x$ 被这个 FA **接收**。

定义里用的是"**存在**"两个字。同一个状态遇到同一个符号，可能有好几条路可走，只要有一条能一路走到终止状态，这个串就算被接收，并不要求所有路都走通。

拿一台四状态的自动机试一遍，看它能不能接收串 $abbaabb$。它的边是这样：状态 0 遇到 $a$ 或 $b$ 都可以留在状态 0，同时状态 0 遇到 $a$ 还可以转到状态 1；状态 1 遇到 $b$ 转到状态 2；状态 2 遇到 $b$ 转到状态 3；状态 3 是终止状态。

| 步 | 读入 | 已读前缀 | 状态 | 说明 |
| :--: | :--: | :--- | :--: | :--- |
| 0 | — | $\varepsilon$ | 0 | 起始 |
| 1 | a | a | 0 | 留在 0 |
| 2 | b | ab | 0 | 留在 0 |
| 3 | b | abb | 0 | 留在 0 |
| 4 | a | abba | 0 | 留在 0 |
| 5 | a | abbaa | 1 | 这一次不留，转到 1 |
| 6 | b | abbaab | 2 | |
| 7 | b | abbaabb | 3 | 终止状态，接收 |

第 5 步是整条路径的关键：同样是状态 0 遇到 $a$，第 1 步选择留在 0，第 5 步选择转到 1。前面读到的 `abba` 里没有能利用的后缀，留在 0 就够了；而从第 5 步开始，最后三个符号恰好凑成 `abb`，这时候转到 1、再顺着 $1 \to 2 \to 3$ 走上去，就落到了终止状态。可见这个自动机可以接收 $abbaabb$。

> **提示**：这张表里每一步的"选择"不是随手挑的，它对应的正是定义里那句"存在一个转换序列"——要找的是**一条**走得通的路径，而不是唯一的一条路径。这一点在讲 NFA 的时候会变成主角。

一个有穷自动机 $M$ 接收的所有串构成的集合，称为这个 FA **定义**或**接收**的语言，记作 $L(M)$，这里的 $M$ 表示 machine。

上面这台自动机接收的语言，是**所有以 $abb$ 结尾的 $ab$ 串**构成的集合。看它后半段的结构就明白：状态 1、2、3 记的分别是"刚刚读到的后缀以 $a$ 结尾""以 $ab$ 结尾""以 $abb$ 结尾"。走到状态 3，就意味着这个串的最后三个符号正好是 $abb$。

### 最长子串匹配原则

> **定义（最长子串匹配原则）**：当输入串的多个前缀与一个或多个模式匹配时，总是选择**最长**的那个前缀进行匹配。

看一个具体的例子。有台自动机里，状态 1 是终态，它表示匹配上了单词小于号 `<`；状态 2 也是终态，它表示匹配上了单词小于等于号 `<=`。现在输入串是一个小于号紧跟一个等于号，那么它的两个前缀——`<` 和 `<=`——分别与这两个模式都匹配上了。这时候按最长子串匹配原则，选的是更长的那个前缀，也就是 `<=`。

输入 `++` 也一样：`+` 和 `++` 这两个前缀都能匹配上各自对应的单词，最后还是取 `++`。

由此得到一条运行时的行为准则：**在到达某个终态之后，只要输入带上还有符号，有穷自动机就继续前进，以便寻找尽可能长的匹配。**

> **提示**：这条原则解释了扫描器一个看似"多此一举"的动作——读到一个终态不能马上收工，得继续往下读，直到读不下去为止，然后再回到上一步记下的那个终态位置，把那里当作单词的结尾。后面讲错误恢复时，找"已扫描字符串中最后一个对应终态的字符"，用的就是这个位置。

### DFA：一个五元组和一张转换表

有穷自动机分两类：确定的有穷自动机，简称 DFA；非确定的有穷自动机，简称 NFA。先把确定的这一类说清楚。

DFA 被定义为一个五元组：

- $S$：有穷状态集合；
- $\Sigma$：输入字母表，也就是输入符号的集合，这里约定**空串不是字母表中的元素**；
- $\delta$：把 $S$ 和 $\Sigma$ 的笛卡尔乘积映射到 $S$ 的转换函数，也就是说，对状态集合中的任何一个状态 $s$ 以及字母表中的任何一个字母 $a$，$\delta(s,a)$ 表示从状态 $s$ 出发、沿着标记为 $a$ 的边所能到达的状态，即状态 $s$ 对应输入符号 $a$ 的后继状态；
- $s_0$：初始状态，或者叫开始状态；
- $F$：终止状态或接收状态的集合。

关键在于 $\delta$ 的值域：$\delta(s,a)$ 是一个**状态**，不是一个集合。给定状态和符号，去处唯一。

看一个 DFA 的例子。它的状态集合 $S$ 里有四个状态：0、1、2、3；字母表里有两个元素：$a$ 和 $b$。$\delta$ 函数可以用一张表写出来：

| 状态 | a | b |
| :--: | :--: | :--: |
| 0 | 1 | 0 |
| 1 | 1 | 2 |
| 2 | 1 | 3 |
| 3 | 1 | 0 |

逐条念一遍：状态 0 遇到 $a$ 进入状态 1，遇到 $b$ 还是状态 0；状态 1 遇到 $a$ 保持在状态 1，遇到 $b$ 进入状态 2；状态 2 遇到 $a$ 回到状态 1，遇到 $b$ 进入状态 3；状态 3 是终态，遇到 $a$ 进入状态 1，遇到 $b$ 进入状态 0。接收状态集合 $F=\{3\}$。

这张表也叫**转换表**。一台有穷自动机既可以用转换图表示，也可以用转换表表示，**两者功能等价**：图是给人看形状的，表是给机器查的。

> **提示**："确定"两个字有两层意思叠在一起：表里每一个格子最多只有一个状态，所以给定状态和输入，去处唯一；读头只能从左向右一个符号一个符号地读，所以读入顺序也唯一。两条合起来，整条运行路径是唯一确定的，不需要猜、不需要回溯。

### NFA：同一个输入，可能去好几个状态

非确定的有穷自动机简称 NFA，它跟 DFA 的唯一区别是：从状态 $s$ 出发，沿着标记为 $a$ 的边所能到达的状态可能有多个，并不是唯一确定的，所以叫非确定的。因此这里的 $\delta(s,a)$ 表示的是从状态 $s$ 出发、沿着标记为 $a$ 的边所能到达的**状态集合**。

看一个 NFA 的例子：

| 状态 | a | b |
| :--: | :--: | :--: |
| 0 | {0,1} | {0} |
| 1 | $\varnothing$ | {2} |
| 2 | $\varnothing$ | {3} |
| 3 | $\varnothing$ | $\varnothing$ |

从初始状态 0 出发，遇到符号 $a$ 时进入的状态集合是 $\{0,1\}$，两个元素；遇到符号 $b$ 时集合里只有 $\{0\}$。状态 1 遇到 $b$ 进入 $\{2\}$，状态 2 遇到 $b$ 进入 $\{3\}$。

如果转换函数没有给出对应于某个"状态—输入"对的信息，就把空集 $\varnothing$ 填进相应的表项。表里的 $\varnothing$ 是一句明确的声明：这个状态不允许遇到这个符号，遇到就是出错。

DFA 和 NFA 具有**等价性**：对于任何一个 NFA $N$，存在识别同一语言的 DFA $D$；相应地，对于任何一个 DFA $D$，也存在识别同一语言的 NFA $N$。

后一个方向几乎是白送的——DFA 的每条边只指向一个状态，而 NFA 允许指向一个集合，单元素集合也是集合，所以 DFA 本身就是 NFA 的一个特例。真正有分量的是前一个方向：任意一个 NFA 都能改写成一台等价的 DFA，这件事下一节就给例子，具体算法放到子集构造法那一节。

### 等价的两台机器，两种脾气

拿上一节那台 NFA 来改造成 DFA。它认的语言也是"以 $abb$ 结尾的 $ab$ 串"。

构造出来的 DFA 有四个状态，含义各不相同：状态 0 表示当前串还没有出现可用的后缀，状态 1 表示当前串以 $a$ 结尾，状态 2 表示当前串以 $ab$ 结尾，状态 3 表示当前串以 $abb$ 结尾。状态 3 是终止状态。

```text
              a               b               b
  start --> (0) --a--> (1) --b--> (2) --b--> ((3))

  自环与回退边：
  (0) --b--> (0)        (1) --a--> (1)
  (2) --a--> (1)        (3) --a--> (1)        (3) --b--> (0)
```

先说主干：初态 0 无论来多少个 $b$ 都停在 0，直到某一刻来了 $a$，才进入状态 1；状态 1 无论后面再来多少个 $a$ 都停在 1，因为它始终表示"当前串以 $a$ 结尾"；状态 1 遇到 $b$ 进入状态 2，表示"当前串以 $ab$ 结尾"；状态 2 遇到 $b$ 进入状态 3，表示"当前串以 $abb$ 结尾"。

再说那些回退边，它们才是"断言被否定"的地方。状态 2 遇到 $a$，原来"以 $ab$ 结尾"的条件被破坏，但新来的这个 $a$ 本身是有用的，于是退回状态 1，改口说"当前串以 $a$ 结尾"。状态 3 也是同样的道理：它已经是终态，可只要输入带上还有符号就得继续走——遇到 $a$ 回到状态 1（`abba` 的后缀是 $a$），遇到 $b$ 退回状态 0（`abbb` 的结尾连一个可用的 $a$ 都凑不出来，什么都不用记了）。如果输入带此时没有新符号，状态 3 就作为结尾，表示这个 DFA 成功接收了一个以 $abb$ 结尾的符号串。

两台机器认的是同一个语言，所以说它们**等价**。这个语言还可以用一个正则表达式写出来：

$$(a|b)^*abb$$

也就是说，若干个 $a$ 或 $b$ 随便排，最后跟一个 $abb$。

从这里能看出两层等价关系。第一层：正则表达式与有穷自动机等价——给定一个正则表达式，可以构造出跟它等价的有穷自动机；给定一个有穷自动机，也可以构造出跟它等价的正则表达式。第二层：前面讲过正则文法与正则表达式也等价。所以三者之间是相互等价的：给定了正则文法，可以构造跟它等价的有穷自动机；给定一个有穷自动机，也可以构造跟它等价的正则文法。

代价是两边的脾气完全不同。

- **NFA 更直观**。从上面那台 NFA 上，一眼就能看出它认的是"以 $abb$ 结尾的 $ab$ 串"；换成那台 DFA，得顺着四条状态的含义一条条分析，才能得出同样的结论。
- **DFA 更容易实现**。它的每一步都只有一个去处，查表、转移，不需要处理"同时处在多个状态"这种麻烦事。

> **提示**：这就是后面整套流程的动机来源——让人去写直观的 NFA，让机器去跑确定的 DFA，中间用算法把前者变成后者。既要好写，又要好跑，两头都不肯将就。

### 空边：不读符号也能走

NFA 的有向边上，除了标记字母表里的字母，还可以标记空串。这样的 NFA 叫**带有空边的 NFA**。从定义上看，它的输入符号中是包含空串的。

这和 DFA 那条"空串不是字母表中的元素"的约定并不矛盾：$\Sigma$ 里仍然没有空串，空边是边上的标记，不是读进来的符号——它不消耗输入。

看一个带空边的 NFA 例子。状态 A 和状态 B 之间有一条标记为空串的有向边，它表示在状态 A 不需要遇到任何符号，就可以直接进入状态 B。但状态 A 和状态 B 不是一回事：一旦进入了状态 B，就不再接收符号 0；而在状态 A 的时候是可以接收符号 0 的。同样，状态 B 和状态 C 之间也有一条空边，表示在状态 B 不需要遇到任何符号就能直接进入状态 C；但一旦进入状态 C，就不再接收符号 1，只能接收符号 2。

```text
  start --> (A) --ε--> (B) --ε--> ((C))

  (A) 只接收 0：(A) --0--> (A)
  (B) 只接收 1：(B) --1--> (B)
  (C) 只接收 2：(C) --2--> (C)
```

这个带空边的 NFA 接收的语言，可以用正则表达式写成

$$0^*1^*2^*$$

也就是由若干个 0 连接上若干个 1，再连接上若干个 2。

带空边和不带空边的 NFA 同样具有等价性：给定一个带空边的 NFA，可以构造一个与它等价的不带空边的 NFA；反过来，一个不带空边的 NFA 也可以构造出等价的带空边的 NFA——把已有的边看成普通边，再补上几条空边就是了。

等价的不带空边版本长这样：

```text
  start --> ((A)) --1--> ((B)) --2--> ((C))

  (A) --0--> (A)        (B) --1--> (B)        (C) --2--> (C)
```

其中状态 A 表示当前的串由若干个 0 连接而成，状态 B 表示当前的串由若干个 0 连接上若干个 1 构成，状态 C 表示由若干个 0 连接上若干个 1、再连接上若干个 2 构成。

有意思的是，这里 A、B、C 三个都是终态。为什么可以这样标？因为在状态 A 的时候，可以认为 1 和 2 的个数都是 0；在状态 B 的时候，可以认为 2 的个数是 0。既然允许"若干个"是零个，那么停在 A 或 B 也是合法的结尾。于是这台自动机接收的语言仍然是 $0^*1^*2^*$。

> **提示**：空边改变的只是"走的路径"，不改变"读了多少符号"。所以判断一个串能不能被接收时，空边可以随便走、连着走、走任意多条，全都不算消耗输入。这一点在子集构造法里会具体兑现成一个叫空闭包的东西。

### 让 DFA 跑起来

形式定义再漂亮，最后落到机器上就是十几行代码。DFA 的算法实现是这样的：

- 输入：以文件结束符 `EOF` 结尾的字符串 $x$；此外还有 DFA 的开始状态 $s_0$、接收状态集合 $F$、转换函数 `move`。
- 输出：如果这个 DFA 接收符号串 $x$，回答 `"yes"`，否则回答 `"no"`。

```text
s = s0;
c = nextChar();
while (c != EOF) {
    s = move(s, c);
    c = nextChar();
}
if (s in F) return "yes";
else return "no";
```

逐段看。先把 DFA 的初始状态 $s_0$ 赋给变量 $s$，$s$ 表示当前状态。接着调用 `nextChar` 返回输入串 $x$ 的下一个符号，赋给 $c$，$c$ 表示当前的输入符号。

只要 $c$ 不等于文件结束符 `EOF`，就循环做两件事：调用 `move` 函数，`move(s, c)` 表示从状态 $s$ 出发、沿着标记为 $c$ 的边所能到达的状态，把这个状态赋给当前状态 $s$；然后再取输入串的下一个符号。

这个循环实际上就是依次从每一个状态、根据当前的输入符号转移到下一个状态，直到遇到文件结束符为止。遇到文件结束符时，看当前状态在不在终止状态集合 $F$ 里：在，就表示这个 DFA 成功接收了输入串，返回 `"yes"`；不在，返回 `"no"`。

> **提示**：注意这里全程只用了两个变量 $s$ 和 $c$。状态数再多也是常数，与输入串长度无关，所以空间是 $O(1)$、时间是 $O(n)$。这就是"有穷"二字在实现层面的全部红利——它不记忆历史，只维护一个当下。

这个算法回答的是"整个串能不能被接收"。而真正的词法分析器要干的活更细：它得把一串字符切成一个个单词，每切出一个就报一次 token。这就需要在 DFA 外面再套一层最长子串匹配的循环，那是后面识别各类单词时要处理的事。

### 为什么不直接造 DFA

正则表达式采用的是一种符号序列的形式，它可以很直观地描述单词的构成。但在构造分析器的时候，真正实现或模拟的是 DFA。于是问题就来了：怎么从正则表达式走到 DFA？

直接从正则表达式构造 DFA 是比较困难的。给定一个不算复杂的正则表达式，硬要一步到位画出那台 DFA，几乎无从下手。所以通常的做法是绕一下：先把正则表达式转换成等价的 NFA——因为 NFA 相对 DFA 更直观，从正则表达式构造 NFA 比较简单；再从 NFA 构造等价的 DFA。

$$\text{正则表达式} \;\longrightarrow\; \text{NFA} \;\longrightarrow\; \text{DFA}$$

这条路线的好处是每一步都很机械：第一步是照着正则表达式的语法结构往上套规则，第二步是照着状态集合做穷举。两步都不需要灵感。

### 五条规则，把正则表达式搭成 NFA

既然正则表达式是归纳定义的，那么"正则表达式到 NFA"的构造也照着它的定义归纳着来：每个基本情形给一台小机器，每个组合情形给一种拼装方式。

**空串**是一个正则表达式，它对应的 NFA 是这样一台机器：一个初始状态，一个终止状态，两者之间有一条标记为空串的有向边。它表示在初始状态的时候，不需要遇到任何符号就可以直接进入终止状态——也就是说，它接受一个空串。

**字母表中的每一个符号**也是一个正则表达式，它对应的 NFA 就是在初始状态 $q_0$ 到终止状态 $q_f$ 之间的有向边上，标记输入符号 $a$。

如果 $r_1$ 和 $r_2$ 都是正则表达式，那么 $r_1$ 连接上 $r_2$ 也是一个正则表达式，它对应的 NFA 就是把 $r_1$ 和 $r_2$ 对应的 NFA **串联**起来，首尾相连。

$r_1$ 或 $r_2$ 也是一个正则表达式，它对应的 NFA 就是把两台 NFA **并联**起来。

一个正则表达式的克林闭包还是正则表达式。$r_1$ 的克林闭包表示把若干个 $r_1$ 连接起来，所以它的 NFA 是一个**循环**的形式，在这条可以循环的边上标记子表达式 $r_1$。

```text
  ① 空串 ε：
      start --> (q0) --ε--> ((qf))

  ② 单符号 a：
      start --> (q0) --a--> ((qf))

  ③ 连接 r1 r2：
      start --> (q0) --[r1]--> (qm) --[r2]--> ((qf))

  ④ 或 r1|r2：
      start --> (q0) --[r1]--> ((qf))
                (q0) --[r2]--> ((qf))          （两条边并联，起点终点相同）

  ⑤ 闭包 r1*：
      start --> (q0) --ε--> (q1) --ε--> ((qf))

      (q1) --[r1]--> (q1)                      （循环边，绕 r1 一圈回到自己）
```

这五条就是全部家当。任何正则表达式，不管套了多少层括号、叠了多少个星号，都是这五种形状拼出来的，所以照着它的语法树自底向上搭，一定能搭出一台 NFA。

拿一个具体表达式走一遍，把它变成等价的 NFA：

$$(a|b)^*abb$$

第一步，设一个初始状态、一个终止状态，在两者之间引一条边，边上标记待转换的正则表达式。这时整台机器就是"一条边扛下所有"。

```text
  start --> (q0) --(a|b)*abb--> ((qf))
```

第二步，把这个正则表达式分解成四个子表达式连接的形式：$(a|b)^*$、$a$、$b$、$b$。于是 NFA 也分解成四部分串联。

```text
  start --> (q0) --(a|b)*--> (p1) --a--> (p2) --b--> (p3) --b--> ((qf))
```

后三个部分已经不能再分解了，就是三条普通边。第一部分还可以继续分：它是一个子表达式的克林闭包，转换成等价的 NFA 就是循环形式，循环边上标记子表达式 $a|b$。

```text
  start --> (q0) --ε--> (L) --ε--> (p1) --a--> (p2) --b--> (p3) --b--> ((qf))

  (L) --a|b--> (L)                            （循环边）
```

第三步，循环边上的 $a|b$ 还能再往下分：它是两个子表达式做或运算，对应的自动机是两条边并联，一条标 $a$、一条标 $b$，起点和终点都是 $L$。

到这里，给定一个正则表达式，就构造出了跟它等价的 NFA。整个过程没有任何需要动脑的判断，只有"看到什么结构就套哪条规则"。

### 子集构造法

NFA 到 DFA 的转换有一套现成的算法。它的思路非常朴素：NFA 的麻烦在于"同一个输入可能去好几个状态"，那就干脆把这好几个状态打成一个包，让这个包成为 DFA 的一个状态。于是有了这条贯穿全节的结论——

> **结论**：与 NFA 等价的 DFA 中的每一个状态，都是一个由 NFA 中的状态构成的集合，也就是 NFA 状态集合的一个子集。

正因为如此，这个方法叫**子集构造法**。

#### 先看没有空边的那个 NFA

NFA 是这样的：从初始状态 A 遇到输入符号 $a$，既可以进入状态 A，也可以进入状态 B；在状态 B 遇到 $b$，既可以进入状态 B，又可以进入状态 C；在状态 C 遇到 $c$，既可以进入状态 C，又可以进入状态 D。

| 状态 | a | b | c |
| :--: | :--: | :--: | :--: |
| A | {A,B} | $\varnothing$ | $\varnothing$ |
| B | $\varnothing$ | {B,C} | $\varnothing$ |
| C | $\varnothing$ | $\varnothing$ | {C,D} |
| D | $\varnothing$ | $\varnothing$ | $\varnothing$ |

现在构造跟它等价的 DFA。NFA 中的初始状态 A，在 DFA 中还是初始状态。

初始状态 A 遇到输入符号 $a$ 时，既可以进入 A 也可以进入 B。虽然不能确定它到底进哪个，但可以确定它**肯定进二者之一**，于是构造一个新状态，它是由 A 和 B 构成的集合 $\{A,B\}$。A 遇到 $a$ 时，肯定进入这个状态。

$\{A,B\}$ 遇到 $a$ 时又到哪儿去？这个状态由 A 和 B 组成，所以它遇到 $a$ 进入的状态，就是 A 和 B 分别遇到 $a$ 时进入的状态的**并集**。查表：A 遇 $a$ 得 $\{A,B\}$，B 遇 $a$ 得 $\varnothing$，并起来还是 $\{A,B\}$。所以这个状态遇到 $a$ 时还进入它自己。

$\{A,B\}$ 遇到 $b$ 呢？A 遇 $b$ 得 $\varnothing$，B 遇 $b$ 得 $\{B,C\}$，并起来是 $\{B,C\}$，于是又构造一个新状态 $\{B,C\}$。而 $\{B,C\}$ 遇 $b$：B 得 $\{B,C\}$、C 得 $\varnothing$，还是 $\{B,C\}$，自环。

$\{B,C\}$ 遇 $c$：B 得 $\varnothing$、C 得 $\{C,D\}$，并起来是 $\{C,D\}$，又是一个新状态。其中的 D 在 NFA 中是终态，表示在这个状态可以成功接收一个符号串，所以把这个集合状态也标记为终态。$\{C,D\}$ 遇 $c$ 仍是 $\{C,D\}$，自环。

其余组合都落到空集上，图上就没有边可画——那是一条死路。

| DFA 状态 | a | b | c |
| :--: | :--: | :--: | :--: |
| A | AB | — | — |
| AB | AB | BC | — |
| BC | — | BC | CD |
| CD（终态） | — | — | CD |

```text
              a              b              c
  start --> (A) --a--> (AB) --b--> (BC) --c--> ((CD))

  自环：(AB) --a--> (AB)      (BC) --b--> (BC)      (CD) --c--> (CD)
```

验证一下这两台是否等价。上面那台 NFA 识别的是由若干个 $a$ 连接上若干个 $b$、再连接上若干个 $c$ 构成的串，这里的"若干"至少是一个。看 DFA 的转换图：从 A 出发必须先读一个 $a$ 才能到 AB，从 AB 必须先读一个 $b$ 才能到 BC，从 BC 必须先读一个 $c$ 才能到 CD，而到不了 CD 就不算接收。所以它识别的也是 $a^+b^+c^+$，若干同样至少为一个。

#### 再看带空边的那个 NFA

这回的 NFA 带空边：A 遇 0 自环，A 有一条空边到 B，B 遇 1 自环，B 有一条空边到 C，C 遇 2 自环。

先算它各状态遇到各符号能到哪儿。这一步的关键是：空边不消耗输入，所以进了某个状态之后，可以顺着空边继续往前溜达。

- A 遇 0：先到 A，进了 A 就能沿空边到 B，进了 B 又能沿空边到 C，所以是 $\{A,B,C\}$；
- A 遇 1：A 自己不吃 1，但 A 沿空边到 B 之后就能吃 1，于是相当于 A 也能吃 1，进 B，再沿空边到 C，得 $\{B,C\}$；
- A 遇 2：A 沿空边走到 C 之后就能吃 2，进 C，得 $\{C\}$；
- B 遇 1：进 B，再沿空边到 C，得 $\{B,C\}$；
- B 遇 2：B 沿空边到 C 吃 2，得 $\{C\}$；
- C 遇 2：得 $\{C\}$。

| 状态 | 0 | 1 | 2 |
| :--: | :--: | :--: | :--: |
| A | {A,B,C} | {B,C} | {C} |
| B | $\varnothing$ | {B,C} | {C} |
| C | $\varnothing$ | $\varnothing$ | {C} |

> **提示**：A 能吃 1、能吃 2，靠的不是它自己有对应的边，而是"沿空边走到 B、走到 C 之后，用别人的边"。空边在这里起的作用，是把后面状态的可接收符号**前移**到了前面状态。

现在构造等价的 DFA。NFA 中的初态 A，在 DFA 中也是初态。由于在 A 不需要遇到任何符号就能直接进入 B，B 相当于也是一个初始状态；进了 B 不需要遇到任何符号就能直接进入 C，C 也相当于是初始状态。于是把 A、B、C 组合起来，构成 DFA 的初始状态 $\{A,B,C\}$。

这个初始状态里的 C 在 NFA 中是终止状态，所以整个初始状态也被标记为终态——也就是说，这台 DFA 可以接收空串。事实上那台 NFA 也确实可以接收空串。

- $\{A,B,C\}$ 遇 0：三个状态遇 0 的并集是 $\{A,B,C\} \cup \varnothing \cup \varnothing$，还是 $\{A,B,C\}$，自环。
- $\{A,B,C\}$ 遇 1：并集是 $\{B,C\} \cup \{B,C\} \cup \varnothing = \{B,C\}$，新状态 $\{B,C\}$。它含终态 C，所以也标终态。
- $\{A,B,C\}$ 遇 2：并集是 $\{C\} \cup \{C\} \cup \{C\} = \{C\}$，新增一个节点 C。
- $\{B,C\}$ 遇 1：$\{B,C\} \cup \varnothing = \{B,C\}$，自环。
- $\{B,C\}$ 遇 2：$\{C\} \cup \{C\} = \{C\}$，转到 C。
- $\{C\}$ 遇 2：还是 C，自环。

| DFA 状态 | 0 | 1 | 2 |
| :--: | :--: | :--: | :--: |
| ABC（终态） | ABC | BC | C |
| BC（终态） | — | BC | C |
| C（终态） | — | — | C |

```text
                   1              2
  start --> (ABC) ----> (BC) ------> ((C))

  自环：(ABC) --0--> (ABC)      (BC) --1--> (BC)      (C) --2--> (C)
  另有：(ABC) --2--> (C)        （跳过 1，1 的个数为 0）
```

再验证一次。NFA 可以接收若干个 0 连接着若干个 1、再连接着若干个 2，这里的"若干"可以是 0 个，正则表达式就是 $0^*1^*2^*$。看 DFA：在初始状态可以接收若干个 0；如果若干个 0 之后再遇到 1，就进入 BC，继续接收若干个 1；如果在 BC 之后又遇到 2，就进入 C，继续接收若干个 2。当然也可以在 ABC 接收了若干个 0 之后直接遇到 2 进入 C，这时候 1 的个数就是 0。两边功能一致，都是 $0^*1^*2^*$，"若干"都可以是 0 个。

> **提示**：初态是终态这件事不是巧合，它就是"这个语言允许空串"的直接体现。判断一台 DFA 认不认空串，看一眼它的初态是不是双圈就够了。

子集构造法的完整算法、以及其中空闭包函数的计算方法，课后对着上面这两个例子读一遍就通了：一个是纯集合的并，一个多了一步"顺着空边把能到的状态都收进来"。

### 识别标识符与无符号数

有了子集构造法这套工具，就可以真的给一门语言的各类单词造 DFA 了。从最简单的两类开始：标识符和无符号数。

先看标识符。标识符的正则表达式由两个子表达式构成：第一部分识别一个字母或者下划线，第二部分识别若干个由字母、下划线或数字组成的串。两部分是连接关系，所以它的 DFA 也就由两部分串联起来。

```text
                     字母 / 下划线 / 数字
                   +---------------------+
                   |                     |
                   v                     |
  start --> (0) --字母 / 下划线--> ((1))
```

注意这里根本不需要跑子集构造法：这台 NFA 本身就是一个 DFA。状态 0 遇字母或下划线只有一条边指向 1，状态 1 遇字母、下划线、数字也只有一条边回到自己，每个"状态—符号"对的去处都是唯一的。

> **提示**：有些正则表达式画出来的图天然就是确定的——每个状态对每个符号最多只有一条出边，标识符这台就是。所以别一看到正则表达式就先想着转换，先看看它是不是已经是一台 DFA。

#### 无符号数的三段结构

无符号数的正则表达式由三部分构成：

$$\text{digit}^+ \;(\,\text{'.'}\;\text{digit}^+\,)? \;(\,E\,(\,\text{'+'} \mid \text{'-'}\,)?\;\text{digit}^+\,)?$$

第一部分是长度大于等于 1 的数字串，第二部分是可选的小数部分，第三部分是可选、可带正负号的指数部分。

第一部分对应的 NFA 很直接：一个状态读数字自环，读满一个就能进下一段。

第二部分按正则表达式是两个子表达式做或运算得到的，所以对应的 NFA 是两部分并联：上面一支是"小数点后面连接长度大于等于 1 的数字串"，下面一支是空串——也就是从状态 1 直接空边跳到状态 3，表示"小数点和小数部分整个不要"。

第三部分同样是或运算，也是两部分并联：一支是字母 $E$ 后面接一个正号、一个负号或者一个空串，再接长度大于等于 1 的数字串；另一支是空串，也就是从状态 3 直接空边跳到状态 6，表示"指数部分整个不要"。

把这些拼起来，就得到这台带空边的 NFA：

```text
  start --> (0) --d--> (1) --'.'--> (2) --d--> (3) --E--> (4) --ε--> (5) --d--> ((6))

  自环：(1) --d--> (1)      (3) --d--> (3)      (6) --d--> (6)
  空边：(1) --ε--> (3)      （小数部分取空）
        (3) --ε--> (6)      （指数部分取空）
        (4) --ε--> (5)      （正负号取空）
  符号：(4) --'+'--> (5)    (4) --'-'--> (5)
```

读图：整数部分至少一位数字；读完整数后，要么接着读小数点和小数位，要么沿空边跳过整个小数部分；读完小数位后，要么接着读 $E$ 和指数，要么沿空边跳过整个指数部分。终态落在 6 号状态上——整数、小数、带指数的数，三种结尾最后都能沿空边汇到它。

#### 子集构造走一遍

这台 NFA 里有空边，得转成 DFA。

NFA 的初始状态也是 DFA 的初始状态 0。状态 0 遇到数字 $d$ 时，先进入状态 1，而只要进了状态 1 就能沿空边进入状态 3、再沿空边进入状态 6。所以初态 0 遇 $d$ 进入的是 $\{1,3,6\}$，构造出这个新状态。

$\{1,3,6\}$ 遇 $d$ 到哪儿？1 遇 $d$ 进 1，进了 1 就带上 3 和 6；3 遇 $d$ 进 3，带上 6；6 遇 $d$ 还是 6。三种情况并起来仍是 $\{1,3,6\}$，自环。

$\{1,3,6\}$ 还能遇什么？状态 1 可以遇小数点，进状态 2；状态 3 和 6 都不接受小数点，所以遇小数点进入状态 2。

还有 $E$。状态 3 遇 $E$ 进状态 4，进了 4 就能沿空边进 5；状态 1 和 6 都不接受 $E$，所以遇 $E$ 进入 $\{4,5\}$。

再没有别的符号了。接着看状态 2：遇 $d$ 进状态 3，进了 3 就带上 6，所以进入 $\{3,6\}$；它不再接受别的输入符号。

$\{3,6\}$ 遇 $d$：3 进 3 带上 6，6 进 6，并起来仍是 $\{3,6\}$，自环。$\{3,6\}$ 遇 $E$ 进入 $\{4,5\}$，因为 3 吃 $E$、6 不吃。它也不再接受别的符号。

$\{4,5\}$ 遇正号或负号进入状态 5；遇 $d$ 时，4 沿空边到 5 再吃 $d$ 进 6，5 吃 $d$ 也进 6，所以进入 $\{6\}$。状态 5 遇 $d$ 进 6，$\{6\}$ 遇 $d$ 还是 6。

| DFA 状态 | d | . | E | + | - |
| :--: | :--: | :--: | :--: | :--: | :--: |
| 0 | {1,3,6} | — | — | — | — |
| 136（终态） | 136 | 2 | 45 | — | — |
| 2 | 36 | — | — | — | — |
| 36（终态） | 36 | — | 45 | — | — |
| 45 | 6 | — | — | 5 | 5 |
| 5 | 6 | — | — | — | — |
| 6（终态） | 6 | — | — | — | — |

检验一下它认不认无符号数。从初态读到一位数字就进入 $\{1,3,6\}$，这个状态可以继续收若干个数字。如果此后没有别的符号，就成功接收一个整数——它停在终态。

如果后面来了小数点，进入状态 2，接下来必须收小数位：收到数字进入 $\{3,6\}$，继续收若干个数字。如果此后没有别的输入符号，成功接收一个小数。

如果此后遇到 $E$，说明这个数带指数部分，进入 $\{4,5\}$：先决定要不要正负号，再收至少一位数字，落到状态 6（终态）。注意从 $\{1,3,6\}$ 也可以直接遇 $E$ 走指数——整数部分直接接指数，小数部分为 0 个，这条路是通的。

> **提示**：$\{1,3,6\}$ 是 DFA 的**一个**状态，不是三个状态。子集构造法里最容易犯的错，就是把集合里的元素当成并列的几条路——它们已经被打包成一个整体了，下一步的去处是这个集合里所有元素去处的并集。

### 各进制整数与注释

#### 三种进制的整数合成一台

十进制、八进制、十六进制的无符号整数，各自都能画出一台 DFA：十进制是 $1\sim9$ 开头接任意多个 $0\sim9$；八进制是 $0$ 开头接任意多个 $0\sim7$；十六进制是 $0x$ 开头接 $0\sim f$。

真正的源程序里这三种数混在一起出现，所以要把三台合成一台统一的、可以识别各进制无符号整数的 DFA。

```text
   start --> (0) --1~9--> (1) --0~9 自环--> 十进制整数，token：DEC
                |
                |0
                v
             {2,3,5} --1~7--> (4) --0~7 自环--> 八进制整数，token：OCT
                |
                |x
                v
              (6) --十六进制数字--> (7) --0~f 自环--> 十六进制整数
```

从初始状态遇到 $1\sim9$ 中的一个数字，进入状态 1，它可以继续接收若干个 $0\sim9$ 的数字构成的数字串，最终识别出十进制整数。识别完之后把这个单词表示成 token：种别码是 `DEC`，表示十进制数，后面跟它的属性值。

初始状态遇到输入符号 0 时，既可以进入状态 2，也可以进入状态 3，还可以进入状态 5——因为一个以 0 开头的串，既可能是十进制的 0，也可能是八进制数，还可能是十六进制数，此刻还看不出是哪种。于是构造一个新状态，由状态 2、3、5 构成的集合 $\{2,3,5\}$。

如果在这个状态之后输入串就没有别的符号了，那就把这个 0 识别成一个十进制整数 0，token 的种别码是 `DEC`，值是 0。

在 $\{2,3,5\}$ 里继续遇到 $1\sim7$ 中的数字，进入状态 4。状态 4 可以继续接收若干个 $0\sim7$ 的数字，最终识别出一个八进制数，种别码是 `OCT`，后面跟属性值。

在 $\{2,3,5\}$ 里继续遇到 $x$，进入状态 6；状态 6 遇到一位十六进制数字进入状态 7，状态 7 继续接收若干个 $0\sim f$ 之间的数字，最终识别出一个十六进制数。

> **提示**：三种进制共用了一个"0 开头"的前缀，所以它们的候选状态被并成了一个集合状态。这也是 NFA 转 DFA 时最典型的形态——不是有三个状态可选，而是"当前可能处在三种解释之下"。

#### 注释：等一个星号，再等一个斜杠

注释 `/* ... */` 的识别过程，是一段很能说明"状态记住的是什么"的 DFA。

在初始状态遇到斜杠，进入状态 1，表示当前的串以斜杠结尾。接下来如果遇到星号，进入状态 2，表示当前串以一个斜杠加上一个星结束——注释开始了。

在状态 2，如果遇到星号以外的任何一个符号，都保持在状态 2。这个时候表示的是注释的内容，一直在状态 2 里收注释内容，直到某一刻遇到星号，进入状态 3，说明注释结尾的那个星号已经出现了。

在状态 3，如果还遇到星号，就一直保持在状态 3，也就是当前串仍然以星号结尾。在状态 3 如果遇到斜杠，进入状态 4，这时就成功接收了一个注释。

在状态 3 如果遇到星号或斜杠之外的任何一个符号，就破坏了"当前串以星号结尾"这个条件，需要退回状态 2，重新等星号。

```text
  start --> (0) -/-> (1) -*-> (2) -*-> (3) -/-> ((4))

  (2) 遇 * 以外的符号：留在 (2)，继续收注释内容
  (3) 遇 *：留在 (3)，继续等斜杠
  (3) 遇 * 和 / 以外的符号：退回 (2)，重新等星号
```

状态 2 和状态 3 的区别只有一件事：末尾有没有一个星号。注释内容里出现的斜杠、字母、括号，全都在状态 2 里被一格一格吞掉；只有在状态 3 遇到斜杠，才算是真正收尾。

> **提示**：从状态 3 退回状态 2 的那条边，不是"出错重来"，而是"把这个符号当作注释内容收下"。这一点和后面错误处理里的"回退"性质完全不同，别看混了。

### 一台 DFA 认出所有单词

把前面这些识别不同单词的 DFA 整合起来，就得到一台统一的、识别各类单词的 DFA。

```text
                       字母 / 下划线
   start --> (0) -----------------------> 标识符分支 --> token：IDN
               |
               | 数字
               +-----------------------> 无符号数分支 --> token：DEC / OCT / ...
               |
               | 其它字符
               +-----------------------> 运算符、界符分支 --> token：运算符 / 界符
```

在初始状态，输入串的第一个符号如果是字母或下划线，就进入识别标识符的分支；识别完把标识符表示成 token，种别码是 `IDN`，后面跟属性值。如果第一个符号是数字，就进入识别数的分支。如果第一个符号是其它字符，就进入识别运算符和界符的分支。

这台 DFA 从初始状态开始，从左至右逐个扫描输入串上的每一个字符；每当识别出一个单词，就把它表示成 token 的形式，然后退回到初始状态，继续识别下一个单词。

还有一类非常重要的单词没有提到：关键字。关键字是由字母组成的串，所以完全可以用识别标识符的 DFA 来识别。具体做法是：每当识别出一个标识符，就查一下关键字表；如果这个字符串在关键字表里，就把它识别成关键字；如果不在，才当作普通标识符。

> **提示**：关键字不另造 DFA，是为了让"长得一样的东西走同一条路"。`if`、`while` 和一个普通变量名在字符层面没有任何区别，区别只在最后一步查表。一台 DFA 覆盖两类单词，代价只是多一次表查找。

### 词法错误与恐慌模式

词法分析器不只是识别源程序中的单词，它还要负责检测源程序中可能存在的一些词法错误。因为无论程序员多么努力，程序中都会难免有错误。

词法阶段可以检测到的错误主要有两类：

- **单词拼写错误**，比如写错的十六进制数、写错的指数形式浮点数——它们的字符长得像那么回事，但走不到任何终态；
- **非法字符**，也就是字母表里根本不该出现的字符。

检测的办法很直接：如果当前的状态与当前的输入符号，在转换表对应项中的信息为空——也就是说当前状态不可以遇到当前输入符号——那就报错，调用错误处理程序。

错误处理程序的动作，是**按最长子串匹配原则往前找退路**：在已扫描的字符串里，找最后一个对应于某个终态的字符。

如果找到了这样一个字符，说明前面已经成功识别了一个单词。这时就把该字符以及它前面的字符识别成一个单词，然后把输入指针退回到该字符之后，扫描器重新回到初始状态，继续识别下一个单词。

如果没找到对应于任何终态的字符，那就是真的出错了：从串首到出错点，一个合法单词都没能切出来。这个时候必须以一定的方式进行处理，使编译器能够继续运行下去——也就是从错误状态尽快恢复过来，以便检测源程序中更多的错误。

这种错误处理的方式叫**错误恢复**。最简单的错误恢复策略是**恐慌模式**：从剩余的输入中不断地删除字符，直到词法分析器能够在剩余输入的开头发现一个正确的字符为止。

> **提示**：为什么"最后一个终态字符"能当断点？因为最长子串匹配保证了扫到那个位置为止，前面那一段已经是一个完整合法的单词，后面那些字符本来就不属于它。断在那里，既没有丢掉已识别的单词，也没有把错误字符吞进 token 里。

到这里，从一台电梯开始的有穷自动机，走完了它作为词法分析理论基础的一整条路：先用状态记住"读到哪儿了"，再用转换图把状态和符号的关系画出来，用 DFA 和 NFA 区分"确定"与"非确定"，用子集构造法把好写的换成好跑的，最后落到一台能逐字符切出 token、还能从错误里爬起来的扫描器上。
