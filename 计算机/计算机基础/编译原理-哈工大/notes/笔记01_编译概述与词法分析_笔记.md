# 编译概述与词法分析

## 语言的层次与翻译

### 三个层次

* **机器语言（machine language）**

    * > **定义**：计算机能够直接理解的语言，程序由 0 和 1 构成的序列组成。

    * 一条机器指令 `C706 0000 0002`：`C706` 是操作码，表示移入（传送）；`0000`、`0002` 是两个操作数；整条指令表示把数值 2 存放到地址 0000。

    * 书写时常用十六进制，只是为了缩短、便于抄写；机器语言的本体始终是二进制机器码。

    * 编写与阅读困难：人类习惯十进制而机器用二进制，程序员还须记住各操作码代表哪种操作，容易写错。

* **汇编语言（assembly language）**

    * > **定义**：用助记符代替操作码的语言；助记符是有含义的英文缩写，如 `MOV` 取自 move，表示移入。

    * 一条带 `MOV` 的指令与 `C706 0000 0002` 完成等价功能：同样把数值 2 存放到地址 0000。

    * 依赖特定机器：换一台机器，指令系统可能不同。

    * 要求程序员熟悉目标机特性，如哪些寄存器可用、寻址方式如何计算，非计算机专业人员使用受限。

    * 编写效率低：一个比较简单的数学表达式也要好几条指令才能写完。

* **高级语言（high-level language）**

    * > **定义**：以类似数学定义或自然语言的简洁形式编写程序的语言。

    * 接近人类表达习惯；不依赖特定机器，同一段程序不必为每种机器重写；编写效率高，再长的数学表达式也可用一条语句表达。

    * 一条高级语言语句即可完成前面两条指令等价的功能。

### 汇编与编译

* **汇编（assembly）**

    * > **定义**：把汇编语言翻译成机器语言的过程。

* **编译（compilation）**

    * > **定义**：把高级语言翻译成汇编语言、或者直接翻译成机器语言的过程。

    * **源语言（source language）**：被翻译的一方，即高级语言。

    * **目标语言（target language）**：翻译得到的一方，即汇编语言或机器语言。

    * 编译器要自动完成分析、变换与目标代码产出：拿到一段从未见过的高级语言程序，自己分析、自己变换、自己产出目标代码。

### 语言处理系统

* 从源程序到可执行代码的完整流水线：

    ```text
     源程序（可能分散在多个文件中）
        │
        ▼
     预处理器    聚合多文件中的源程序；把宏展开成原始语句
        │
        ▼
     编译器      高级语言程序 → 汇编语言程序
        │
        ▼
     汇编器      汇编语言程序 → 可重定位的机器代码
        │
        ▼
     可重定位目标代码 ──┐
     其他目标代码 ──────┼──▶ 链接器 ──▶ 可执行代码 ──▶ 加载器 ──▶ 内存中运行
     库文件 ────────────┘
    ```

* **预处理器（preprocessor）**

    * 把存储在不同文件中的源程序聚合在一起。

    * 把被称为宏的缩写语句转换为原始语句。

* **编译器（compiler）**

    * 把高级语言程序翻译成汇编语言程序。

* **汇编器（assembler）**

    * 把汇编语言程序翻译成机器代码，产物是**可重定位**的机器代码。

* **可重定位（relocatable）**

    * > **定义**：机器代码在内存中存放的起始位置不是固定的，代码中的所有地址都是相对于该起始位置的相对地址。

    * 绝对地址 = 起始位置 + 相对地址。

* **链接器（linker）**

    * 把可重定位的机器代码与其他可重定位的目标程序、库文件链接，生成可执行代码。

    * 解决外部内存地址问题：一个文件中的代码可能引用另一个文件中的数据对象或过程，这些地址相对于当前文件就是外部地址，须在拼装时统一解决。

* **加载器（loader）**

    * 修改可重定位地址，并把修改后的指令和数据加载到内存中适当的位置。

* > **易错点**：可重定位不等于地址随机。代码里写的全是相对地址，绝对地址要等加载时用「起始位置 + 相对地址」现算，所以同一份目标代码可以装到内存的不同位置。

## 编译系统的结构

### 从人工翻译看分析步骤

* **语义分析（semantic analysis）**

    * > **定义**：通过分析源语言来获得句子语义的过程。

    * 翻译分两步：先从源语言层面分析句子表达的语义，再按目标语言的方式把该语义说一遍。

    * 例句 `In the room, he broke a window with a hammer.` 中，英语是源语言，汉语是目标语言。

    * 语义分析从划分句子成分入手，第一步抓核心谓语动词：`break`（打）。

    * 主动语态下主语 `he` 是施事者（agent），宾语 `window` 是受事者（object）；换成被动语态 `be broken`，同一位置的主语就变成受事者。

    * `with a hammer` 是补语，表示工具（tool）；`in the room` 是状语，表示地点（location）。

* 语义关系图：

    ```text
    break（打）  ← 中心结点：句子所描述的动作
    ├── he       — agent     施事者
    ├── window   — object    受事者
    ├── hammer   — tool      工具
    └── room     — location  地点
    ```

* **中间表示（intermediate representation）**

    * > **定义**：独立于具体语言的语义结构；源语言先被压成它，再由它生成任意一种目标语言。

    * 英语、汉语、日语、法语、德语等都能用它表示，换目标语言不影响翻译流程。

    * 作用是桥梁：否则每两种语言之间都要单独修一条翻译通道。

    * 编译器据此拆成前后两半：分析源语言的一半产出中间表示，生成目标代码的一半消费中间表示，两边通过中间表示解耦。

* **语法分析（syntax analysis）**

    * > **定义**：识别句子中的各类短语，从而划分句子成分的过程，也称句法分析。

    * 主语和宾语通常由名词短语构成，状语和补语通常由介词短语构成。

* **词法分析（lexical analysis）**

    * > **定义**：确定句子中各个单词的词性（词类）的过程。

    * 一个冠词加一个名词可以构成名词短语，一个代词本身也可以构成名词短语；识别各类短语的前提是确定各单词的词性。

* 句子的分析顺序：词法分析 → 语法分析 → 语义分析 → 给出中间表示。

### 阶段划分与前后端

* 编译的阶段依次为：词法分析、语法分析、语义分析、中间代码生成、目标代码生成；中间代码和目标代码生成之后通常还有代码优化。

* 阶段与前后端的对应：

    ```text
     源程序
        │
        ▼
     前端（分析部分，只与源语言相关）
     词法分析 → 语法分析 → 语义分析 → 中间代码生成
        │
        ▼
     中间表示（独立于具体语言，起桥梁作用）
        │
        ▼
     后端（综合部分，只与目标语言相关）
     目标代码生成 → 代码优化
        │
        ▼
     目标程序
    ```

* **前端（front end）**

    * > **定义**：分析部分，对源语言进行分析并生成中间表示，因此只与源语言相关。

* **后端（back end）**

    * > **定义**：综合部分，在中间表示的基础上生成目标代码，因此只与目标语言相关。

* 中间表示独立于具体语言：支持一门新的源语言只改前端，支持一种新的目标机器只改后端。

* > **注意**：阶段是编译器的逻辑组织方式，不是实现时的物理分块；实现过程中多个阶段可能被组合在一起。

* **语法制导翻译（syntax-directed translation）**

    * 在语法分析句子结构的同时，结合语义规则直接进行语义分析。

    * 采用它时，语法分析、语义分析、中间代码生成三个阶段可以放在一起实现。

* 语义分析的结果通常直接表示成中间代码的形式，因此这两个阶段通常放在一起实现。

## 词法分析

### 任务与 token

* **词法分析（lexical analysis）**

    * > **定义**：编译的第一个阶段，从左向右、逐行扫描源程序的字符，识别出各个单词、确定单词的类型，并将识别出的单词转换成统一的机内表示。

* **词法单元（token）**

    * > **定义**：单词的机内表示，是一个二元组（种别码，属性值）。

    * 种别码表示单词的种别，本身是一个整数，实现和讲解时常采用宏定义的形式。

    * 两个分量各管一件事：种别码区分单词，属性值区分同一类单词中的哪一个。

### 五类单词与种别码分配

* 程序设计语言的单词大体分为五类，种别码的分配遵循同一条取舍：能事先枚举的靠种别码区分，枚举不了的靠属性值区分。

| 单词类别 | 例子 | 集合性质 | 种别码分配 | 属性值 |
| :--- | :--- | :--- | :--- | :--- |
| 关键字 | `program`、`if`、`else`、`then` | 事先可以确定 | 一词一码 | 空 |
| 标识符 | 程序员声明的数据对象名、过程名 | 开放集合，无法枚举 | 多词一码，全部共用一个种别码 | 标识符的具体字面值 |
| 常量 | 整型、浮点型、字符型、布尔型常量 | 开放集合，但按类型划分 | 一型一码 | 该常量具体的值 |
| 运算符 | 算术、关系、逻辑运算符 | 事先可以确定 | 一词一码，或一类一码 | 一类一码时存放具体运算符 |
| 界线符 | 分号、左右括号、等号、左右花括号 | 事先可以确定 | 一词一码 | 空 |

* **关键字（keyword）**

    * 给定一门程序设计语言，其关键字集合事先可以确定，因此为每个关键字分配一个种别码。

    * 关键字靠种别码即可与其他单词区分，属性值为空。

* **标识符（identifier）**

    * 程序员为程序中声明的数据对象或过程起的名字，是开放集合，事先不可能枚举。

    * 所有标识符统一作为一类单词，共用一个种别码；用属性值存放各个标识符具体的字面值。

* **常量（constant）**

    * 包括整型常量、浮点常量、字符常量、布尔常量等，也是开放集合。

    * 不同类型的常量构成方式不同，因此一型一码；同一类型下的不同常量靠属性值区分。

* **运算符（operator）与界线符（delimiter）**

    * 两者都事先可以确定，可以为每一个分配一个种别码，即一词一码。

    * 运算符也可以按类分配种别码，此时用属性值存放具体的运算符。

### 单词到 token 的映射

* 一段含 while、标识符、常量和自增运算的程序片段，其单词与 token 的对应关系如下（种别码用宏名表示）：

| 单词 | 种别码 | 属性值 | 依据 |
| :--- | :--- | :--- | :--- |
| `while` | `WHILE` | 空 | 关键字，一词一码 |
| `(` | `SLP` | 空 | 界线符，一词一码 |
| `value` | `IDN` | `value` | 标识符，多词一码 |
| `!=` | `NE` | 空 | 运算符，一词一码 |
| `100` | `CONST` | `100` | 常量，属性值即其值 |
| `)` | `SRP` | 空 | 界线符，一词一码 |
| `{` | `LP` | 空 | 界线符，一词一码 |
| `++` | `INC` | 空 | 运算符，一词一码 |
| `;` | `SEMI` | 空 | 界线符，一词一码 |
| `number` | `IDN` | `number` | 标识符，种别码同 `value`、属性值不同 |
| `}` | `RP` | 空 | 界线符，一词一码 |

* 一个 token 对应一个单词；凡是能靠种别码唯一确定的单词，第二个分量都是空的。

* 只有标识符和常量这两类开放集合，才需要用属性值把「同一个种别码底下的不同个体」区分出来。

## 语法分析

### 任务与分析树

* **语法分析（syntax analysis）**

    * > **定义**：编译的第二个阶段，从词法分析器输出的 token 序列中识别出各类短语，并构造语法分析树。

* **语法分析树（parse tree）**

    * > **定义**：描述句子语法结构的树；叶子是词法分析给出的一个个单词，往上每一层归约都对应一条语法规则。

    * 树的形状同时把优先级说清楚：处于下层的运算先算。

### 赋值语句的分析树

* 输入 `position = initial + rate * 60;`，其中 `position`、`initial`、`rate` 是标识符，`60` 是常数。

* 由 token 序列构造出的分析树：

    ```text
    赋值语句
    ├── id(position)
    ├── =
    ├── 表达式
    │   ├── 表达式
    │   │   └── id(initial)
    │   ├── +
    │   └── 表达式
    │       ├── 表达式
    │       │   └── id(rate)
    │       ├── *
    │       └── 表达式
    │           └── 60
    └── ;
    ```

* 从树能直接读出三条规则：一个标识符或一个常数本身构成一个表达式；一个表达式加上或乘上另一个表达式构成更大的表达式；一个标识符接赋值号、再接一个表达式和分号，构成一条赋值语句。

* `rate * 60` 先合成一个表达式，再与 `initial` 相加；乘在加的下层，所以先算。

### 声明语句的文法与分析树

* 变量声明语句的文法：

    ```text
    D → T IDS ;
    T → int | real | char | bool
    IDS → id
    IDS → IDS , id
    ```

* $D$ 取自 declaration，表示声明语句；$T$ 取自 type，表示类型；$IDS$ 是 identifier sequence 的缩写，表示标识符序列。

* 第一条规则：声明语句由类型、标识符序列和一个分号构成；$T$ 的竖线表示「或」关系。

* 第三条规则：一个标识符本身构成标识符序列；第四条规则：一个标识符序列接逗号和标识符构成更大的标识符序列——典型的递归写法，一条规则描述任意长度。

* 对输入 `int a, b, c;`：

    ```text
    D
    ├── T
    │   └── int
    ├── IDS
    │   ├── IDS
    │   │   ├── IDS
    │   │   │   └── id(a)
    │   │   ├── ,
    │   │   └── id(b)
    │   ├── ,
    │   └── id(c)
    └── ;
    ```

* 树自下而上生长：`id(a)` 自成一个 $IDS$，接逗号和 `id(b)` 长成更大的 $IDS$，再接逗号和 `id(c)` 长成最终 $IDS$，最后由 `int`、$IDS$、分号拼成 $D$。

## 语义分析

### 标识符的属性

* 语义分析是编译的第三个阶段；高级语言语句分声明语句与可执行语句，声明语句的语义分析主要任务是收集标识符的属性信息。

* **种属**：标识符对应的是简单变量、复合变量（数组、记录等）还是过程。

* **类型**：整型、实型、字符型、布尔型、指针型等。

* **存储位置和长度**：数据对象和过程都要在内存中分配存储空间，存储位置与占用空间大小是两个重要属性。

* **值和作用域**：变量的值，以及标识符起作用的范围。

* **参数和返回值**：过程名的属性还包括参数与返回值信息。

* 相对地址按声明顺序逐块往后摞，前一个对象占多少字节，后一个就从哪里开始：

| 标识符 | 类型 | 相对地址 | 占用空间 | 地址由来 |
| :--- | :--- | :--- | :--- | :--- |
| $x$ | 实型数组，8 个元素 | 0 | 64 字节 | 第一个声明从 0 开始；$8 \times 8 = 64$ |
| $i$ | 整型 | 64 | 4 字节 | 紧接在 $x$ 占用的 64 字节之后 |
| $j$ | 整型 | 68 | 4 字节 | $64 + 4 = 68$ |

* 数组按「元素个数 × 单个元素长度」整体预留，所以 $x$ 一次占掉 64 个字节。

### 符号表与字符串表

* **符号表（symbol table）**

    * > **定义**：存放标识符属性信息的数据结构，每个标识符对应一条记录，字段包括 type、kind、value、address 等。

* **字符串表（string table）**

    * > **定义**：集中存放程序中用到的标识符和字符常数的表，按出现顺序追加。

    * 符号表的 name 字段被拆成两部分：标识符在字符串表中的起始位置，以及标识符的长度。

* 结构示意：

    ```text
    符号表中的一条记录
        name    ──▶ （在字符串表中的起始位置，标识符长度）
        type
        kind
        value
        address

    字符串表（名字集中存放，按出现顺序追加）
        偏移 0   simple   长度 6
        偏移 6   symbol   长度 6
        偏移 12  table    长度 5
    ```

* 单独设字符串表的理由：

    * 符号表记录希望定长，查表时可用「表基址 + 序号 × 记录长度」一步算出第几条记录的位置。

    * 标识符长度从一两个字符到几十个字符不等，名字直接塞进 name 字段会让记录长度浮动，定长寻址失效；按序号定位要逐条累加，插入删除还要整体搬动后续记录。

    * 拆开后 name 字段只剩两个整数，记录重新定长，寻址、插入、删除都退化成常数时间的下标运算。

    * 字符串表只做追加，已有字符不用搬动；相同的名字或字符常数还能共用同一段字符，不必重复存储。

### 语义检查

* **语义检查（semantic checking）**

    * > **定义**：抓出那些语法上没毛病、意思上说不通的错误。

* 常见的语义错误：

    * 变量或过程未经声明就使用；

    * 变量或过程名重复声明；

    * 运算分量类型不匹配，例如把一个数组的名字和一个过程的名字相加；

    * 操作符与操作数之间的类型不匹配，例如把浮点数作为数组下标；

    * 对非数组变量使用数组访问操作符；

    * 对非过程名使用过程调用操作符；

    * 过程调用的参数类型或数目不匹配；

    * 函数返回类型有错误。

* 自动类型转换：二元算术运算符作用于一个整数和一个浮点数时，把其中的整数自动转换为浮点数，运算才能按浮点算下去。

## 中间代码生成

### 中间表示与三地址码

* 中间表示可以有多种形式，例如三地址码和语法结构树（简称语法树）。

* > **易错点**：语法结构树（syntax tree）与语法分析树（parse tree）不是一回事：前者是中间表示的一种形式，后者是语法分析阶段的产物；语法树的一个变体是无环有向图。

* **三地址码（three-address code）**

    * > **定义**：由类似于汇编语言的指令序列组成，每条指令最多有三个操作数。

    * 地址可以直接用源程序中的标识符：每个标识符的地址存放在符号表中，通过名字即可找到。

    * 常量或编译器生成的临时变量，也可以作为三地址指令的地址。

### 三地址指令

| 指令形式 | 含义 |
| :--- | :--- |
| `x = y op z` | 二元运算：`op` 是二元运算符，`y`、`z` 是两个运算分量的地址，`x` 存放结果 |
| `x = op y` | 一元运算：`op` 是一元运算符，只有 `x`、`y` 两个操作数 |
| `x = y` | 复制指令：把 `y` 的值复制给 `x` |
| `if x rel_op y goto n` | 条件跳转：`x` 与 `y` 满足关系 `rel_op` 时转到地址 `n` |
| `goto n` | 无条件跳转：直接转到地址 `n` |
| `param x` | 参数传递：将 `x` 设置为参数 |
| `call p, n` | 过程调用：`p` 是过程名，`n` 是参数个数 |
| `return x` | 过程返回：转到地址 `x` |
| `x = y[i]` | 数组引用：`y` 是数组名（基地址），`i` 是数组元素的偏移地址 |
| `x[i] = y` | 数组赋值：把变量的值赋给一个数组元素 |

* > **易错点**：`x = y[i]` 里的 `i` 是数组元素的偏移地址，不是数组下标；下标要经过元素长度换算才变成偏移，三地址码里用的已经是换算后的偏移量。

* 除复制指令外，每条指令只有一个操作符，只能完成一个动作，因此三地址指令序列唯一确定了运算完成的顺序。

### 四元式

* **四元式（quadruple）**

    * > **定义**：三地址指令的一种数据结构表示，四个分量依次对应操作符与三个操作数。

    * 其他表示方式还有三元式和间接三元式。

| 三地址指令 | 操作符 | 分量二 | 分量三 | 分量四 |
| :--- | :--- | :--- | :--- | :--- |
| `x = y op z` | `op` | `y` | `z` | `x` |
| `x = op y` | `op` | `y` | 空 | `x` |
| `x = y` | `=` | `y` | 空 | `x` |
| `if x rel_op y goto n` | `rel_op` | `x` | `y` | `n` |
| `goto n` | `goto` | 空 | 空 | `n` |
| `param x` | `param` | `x` | 空 | 空 |
| `call p, n` | `call` | `p` | `n` | 空 |
| `return x` | `return` | `x` | 空 | 空 |
| `x = y[i]` | `=[]` | `y` | `i` | `x` |
| `x[i] = y` | `[]=` | `y` | `x` | `i` |

* 二元运算的第二、第三分量是两个源操作数，第四分量是目标操作数；一元运算与复制只有两个操作数，一个分量留空。

* `goto` 只有一个操作数，即目标地址；数组引用的操作符写成 `=[]`，表示等号右边是数组元素，第二、第三分量是基地址与偏移地址。

* 数组赋值的操作符写成 `[]=`，表示等号左边是数组元素；第二分量是等号右边的变量，第三、第四分量是基地址与偏移地址。

* 与自然语言的中间表示相似：操作符相当于核心谓语动词，操作数相当于各个语义角色，只是操作数最多三个。

### 控制流翻译

* 一个 while 语句内嵌 if-else、if 内再嵌 while 的程序片段，翻译出的三地址指令序列：

    ```text
    100  if a < b goto 102        ; a < b 成立转 102，否则顺序执行 101
    101  goto 112                 ; 跳出整个 while 语句
    102  if c < 5 goto 104        ; c < 5 成立转 104，否则顺序执行 103
    103  goto 110                 ; 转去 else 分支
    104  if x > y goto 106        ; x > y 成立转 106，否则顺序执行 105
    105  goto 100                 ; 内层 while 结束，回到外层条件
    106  t1 = x + 1               ; 计算 x + 1，存入临时变量 t1
    107  z = t1                   ; 把 t1 的值赋给 z，完成 z = x + 1
    108  goto 104                 ; 回到内层 while 的条件
    110  x = y                    ; else 分支：把 y 的值赋给 x
    111  goto 100                 ; 回到外层 while 的条件
    112  ...                      ; while 语句之后的指令
    ```

* 控制流走查：$a < b$ 成立转 102，不成立走 101 转 112 跳出；$c < 5$ 成立转 104，不成立走 103 转 110 执行 else 赋值，再转 100 回外层条件。

* $x > y$ 成立执行 106 计算 $x+1$、107 赋给 $z$，再转 104 重新判断；不成立走 105 转 100，内层 while 结束。

* 跳转指令的 j 取自 jump；凡带 `goto` 的指令都在改变控制流，没有跳转的指令按编号顺序往下走。

## 目标代码生成与代码优化

* **目标代码生成（target code generation）**

    * 以源程序的中间表示作为输入，把它映射到目标语言。

    * 重要任务是为程序中使用的变量合理分配寄存器：寄存器数量有限、访问最快，哪个变量进寄存器、哪个留在内存，直接决定代码跑得快不快。

* **代码优化（code optimization）**

    * > **定义**：为改进代码所进行的等价的程序变换，使程序运行得更快、占用空间更少，或者二者兼顾。

    * 「等价」是前提：变换前后的程序必须做同一件事，只是做得更省。

| 优化类别 | 优化发生的层次 | 关注点 |
| :--- | :--- | :--- |
| 机器无关优化 | 中间代码层面 | 与具体机器无关的等价变换 |
| 机器相关优化 | 目标代码层面 | 利用具体机器的特性做变换 |

* 优化的内容包括：自动识别代码中的重复运算或冗余运算并删除；把代价较高的运算替换为等价的代价较低的运算。

## 字母表与串

### 字母表及其运算

* **字母表（alphabet）**

    * > **定义**：一个有穷符号集合，用 $\Sigma$ 表示。

    * 符号的典型例子包括字母、数字、标点符号；二进制字母表 $\{0,1\}$、ASCII 字符集、Unicode 字符集都是字母表。

* **字母表的乘积**

    * $\Sigma_1 \times \Sigma_2$ 的元素由两个符号构成，第一个符号来自 $\Sigma_1$，第二个来自 $\Sigma_2$。

    * 例：$\{0,1\} \times \{a,b\} = \{0a,\ 0b,\ 1a,\ 1b\}$。

* **字母表的幂**

    * $\Sigma^{n}$ 是 $n$ 个 $\Sigma$ 相乘，得到的元素都是长度为 $n$ 的符号串。

    * $\Sigma^{0}$ 表示长度为 0 的符号串构成的集合，即 $\{\varepsilon\}$。

* **空串（empty string）**

    * > **定义**：长度为 0、没有符号的符号串，用 $\varepsilon$ 表示。

* **正闭包（positive closure）**

    * $\Sigma^{+} = \Sigma^{1} \cup \Sigma^{2} \cup \Sigma^{3} \cup \cdots$，即长度为正数的符号串构成的集合。

* **克林闭包（Kleene closure）**

    * $\Sigma^{*} = \Sigma^{0} \cup \Sigma^{+}$，即任意符号串构成的集合，长度可以为 0。

* **串（string）**

    * > **定义**：字母表 $\Sigma$ 的克林闭包中的每一个元素，即字母表中符号的一个有穷序列。

### 串上的运算

* 串 $s$ 的长度是其中符号的个数，记作 $|s|$，如 $|aab| = 3$；长度为 0 的串是空串 $\varepsilon$。

* **连接（concatenation）**：把 $y$ 附加到 $x$ 后面形成串 $xy$；如 $x = \text{dog}$、$y = \text{house}$，则 $xy = \text{doghouse}$。

* 空串是连接运算的单位元：对任意串 $s$，$s\varepsilon = \varepsilon s = s$。

* **前缀（prefix）与后缀（suffix）**：若 $x = yz$，则 $y$ 是 $x$ 的前缀，$z$ 是 $x$ 的后缀。

* **串的幂**：$s^{n}$ 是 $n$ 个 $s$ 连接；$s^{0} = \varepsilon$，即 0 个 $s$ 连接起来是空串。

| 幂次 | $s = ba$ 时的结果 |
| :--- | :--- |
| $s^{1}$ | $ba$ |
| $s^{2}$ | $baba$ |
| $s^{3}$ | $bababa$ |

## 文法的形式定义

### 四元组与两类符号

* **文法（grammar）**

    * > **定义**：描述语言构成规则的形式系统，定义为一个四元组 $G = (V_T,\ V_N,\ P,\ S)$。

* **终结符集合 $V_T$**

    * $T$ 取自 terminal symbol；终结符是文法所定义的语言的基本符号。

    * 描述句子构成规则时，基本符号是单词，这些单词就构成终结符集；终结符有时也称为 token。

* **非终结符集合 $V_N$**

    * 非终结符用来表示语法成分，还可以从它进一步推导出其他语法成分，所以称「非终结」。

    * 非终结符有时也称为语法变量。

* > **注意**：终结符集合与非终结符集合不相交，$V_T \cap V_N = \emptyset$；两者统称文法符号，$V_T \cup V_N$ 是文法符号集。

### 产生式与开始符号

* **产生式（production）**

    * > **定义**：描述把终结符和非终结符组合成串的方法的式子，一般形式为 $\alpha \to \beta$，读作「$\alpha$ 定义为 $\beta$」。

    * $\alpha$ 是产生式的头，也叫左部；$\beta$ 是产生式的体，也叫右部。

    * 左部 $\alpha$ 至少要包含一个非终结符，这是对产生式的唯一硬性要求。

    * $\alpha$、$\beta$ 都是文法符号串：$V_T$、$V_N$ 都是字母表，并集仍是字母表，字母表的闭包给出其上的符号串。

* **开始符号（start symbol）**

    * > **定义**：一个特殊的非终结符，表示该文法中最大的语法成分。

* 算术表达式例子：$E \to E+E \mid E*E \mid (E) \mid \mathbf{id}$；$V_T = \{\mathbf{id}, +, *, (, )\}$，$V_N = \{E\}$，开始符号是 $E$。

* 约定：在不引起歧义的前提下，可以只写文法的产生式。

### 候选式与符号约定

* **候选式（alternative）**

    * > **定义**：左部相同的多条产生式合并后，右部的各个选择 $\beta_1, \beta_2, \dots, \beta_n$。

    * 合并写法：$\alpha \to \beta_1 \mid \beta_2 \mid \dots \mid \beta_n$，读作「$\alpha$ 定义为 $\beta_1$，或者 $\beta_2$，……，或者 $\beta_n$」。

* 符号的使用约定：

| 符号形式 | 约定含义 |
| :--- | :--- |
| 字母表中排在前面的小写字母（$a$、$b$、$c$） | 终结符 |
| 运算符、标点符号、数字 | 终结符 |
| 粗体字符串（$\mathbf{id}$、$\mathbf{if}$） | 终结符 |
| 字母表中排在前面的大写字母（$A$、$B$、$C$） | 非终结符 |
| $S$ | 开始符号，一种特殊的非终结符 |
| 小写斜体名字（$expr$、$stmt$） | 非终结符，分别表示表达式与语句 |
| 代表程序构造的大写字母（$E$、$T$、$F$） | 非终结符：expression、term、factor |
| 字母表中排在后面的大写字母（$X$、$Y$、$Z$） | 文法符号，既可以是终结符，也可以是非终结符 |
| 字母表中排在后面的小写字母（$u$、$v$、$w$、$x$、$y$、$z$） | 终结符号串，包括空串 |
| 小写希腊字母（$\alpha$、$\beta$、$\gamma$） | 文法符号串，包括空串 |

* 排在后面的小写字母表示终结符号串，小写希腊字母表示文法符号串；两者都是「串」，都包含空串。

* 兜底约定：除非特别说明，第一个产生式的左部就是文法的开始符号。

## 推导、归约与语言

### 直接推导与多步推导

* **直接推导（direct derivation）**

    * > **定义**：用产生式的右部替换产生式的左部。

    * 若有产生式 $\alpha \to \beta$，则可把符号串 $\gamma\alpha\delta$ 重写为 $\gamma\beta\delta$，记作 $\gamma\alpha\delta \Rightarrow \gamma\beta\delta$。

* **$n$ 步推导**

    * 若 $\alpha_0 \Rightarrow \alpha_1 \Rightarrow \cdots \Rightarrow \alpha_n$，称 $\alpha_0$ 经过 $n$ 步推导出 $\alpha_n$，记作 $\alpha_0 \Rightarrow^{n} \alpha_n$。

    * $n = 1$ 时就是直接推导；$n = 0$ 时等于没有推导，$\alpha$ 经过零步推导得到的还是 $\alpha$。

    * $\Rightarrow^{+}$ 表示经过正数步推导（至少一步）；$\Rightarrow^{*}$ 表示经过若干步推导（可以是零步）。

* 从开始符号「句子」推出 `little boy eats apple`：

    ```text
    句子
    ⇒ 名词短语 动词短语
    ⇒ 形容词 名词短语 动词短语
    ⇒ little 名词短语 动词短语
    ⇒ little 名词 动词短语
    ⇒ little boy 动词短语
    ⇒ little boy 动词 名词短语
    ⇒ little boy eats 名词短语
    ⇒ little boy eats 名词
    ⇒ little boy eats apple
    ```

* 每一步都是根据一条产生式，把右部替换进当前句型中的某个非终结符；推导时忽略英文单词的形态变化，`eat` 与 `eats` 视为同一个词。

### 归约

* **归约（reduction）**

    * > **定义**：用产生式的左部替换产生式的右部，是推导的逆过程。

* 归约示例：`apple → 名词 → 名词短语`；`eats → 动词`；`动词 名词短语 → 动词短语`；`boy → 名词 → 名词短语`；`little → 形容词`；`形容词 名词短语 → 名词短语`；`名词短语 动词短语 → 句子`。

* 判定一个词串是否句子的两条途径：

    * 从生成角度：从开始符号可以推导出该词串，它就是该语言的一个句子。

    * 从识别角度：从该词串可以归约出开始符号，它就是该语言的一个句子。

* 无论走哪条途径，每一步都必须对得上文法里的某一条产生式。

### 句型、句子与语言

* **句型（sentential form）**

    * > **定义**：从开始符号 $S$ 出发，经过若干步可以推导出的文法符号串 $\alpha$。

    * 句型里既可以包含终结符，也可以包含非终结符，还可能是空串。

* **句子（sentence）**

    * > **定义**：从开始符号 $S$ 经过若干步推导出的终结符号串 $w$。

    * 句子是特殊的句型——不包含任何非终结符的那种句型；推导过程中每一步得到的都是句型，只有最后一个才是句子。

* **语言（language）**

    * 文法 $G$ 生成的语言是它所有句子构成的集合，记作 $L(G) = \{\, w \in V_T^{*} \mid S \Rightarrow^{+} w \,\}$，$L$ 取自 language。

    * 文法解决无穷语言的有穷表示问题：一个有限的四元组，把无穷多个句子一次说清楚。

* 标识符文法及其语言：

    ```text
    D → 0 | 1 | 2 | … | 9
    L → a | b | c | … | z
    T → L | D | T L | T D
    S → L | L T
    ```

    * $D$ 表示数字（digit），$L$ 表示字母（letter）。

    * $T$ 可表示一个字母或一个数字，又可由 $TL$、$TD$ 继续生长；串首的 $T$ 始终是「还能继续长」的位置，最终长成字母数字串。

    * $S$ 推出一个字母，或一个字母后接一个字母数字串，即字母打头的字母数字串——这正是标识符的构成方法。

* 语言上的运算：并、连接（乘积）、幂、闭包。

    * $L^{0} = \{\varepsilon\}$，即语言 $L$ 的零次幂是由空串构成的集合。

    * 字母集合 $L$ 与数字集合 $D$：$L \cup D$ 是字母和数字构成的语言；$(L \cup D)^{*}$ 是字母数字串的集合；$L(L \cup D)^{*}$ 是字母打头的字母数字串的集合，也是标识符。

* 标识符到这里已有两种写法：一套产生式，一个集合表达式；后面还有更紧凑的第三种。

## 乔姆斯基文法分类

### 四种类型

* **0 型文法（type-0 grammar）**

    * 也称无限制文法或短语结构文法；对产生式几乎没有限制，只要求左部至少包含一个非终结符。

    * 由 0 型文法生成的语言称为 0 型语言。

* **1 型文法（type-1 grammar，上下文有关文法 CSG）**

    * 在 0 型基础上要求 $|\alpha| \le |\beta|$，即左部符号个数不能多于右部。

    * 一般形式为 $\alpha_1 A \alpha_2 \to \alpha_1 \beta \alpha_2$：非终结符 $A$ 只有在上下文分别为 $\alpha_1$、$\alpha_2$ 时才能替换为 $\beta$，所以称上下文有关。

    * 由定义可直接推出不含空产生式：若 $\beta = \varepsilon$，则 $|\beta| = 0$；而左部至少含一个非终结符，$|\alpha| \ge 1$，与 $|\alpha| \le |\beta|$ 矛盾。

    * > **易错点**：不等号方向是左部不长于右部，右部至少要跟左部一样长；方向记反，空产生式就成了合法产生式，整个层级的结论都会跟着变。

* **2 型文法（type-2 grammar，上下文无关文法 CFG）**

    * 每条产生式的左部必须是单个非终结符，一般形式 $A \to \beta$。

    * 把 $A$ 替换成 $\beta$ 不需要考虑上下文，所以称上下文无关；生成的语言称上下文无关语言。

    * 生成标识符的文法每条产生式左部都是单个非终结符，所以它是上下文无关文法。

* **3 型文法（type-3 grammar，正规文法 RG）**

    * 右线性文法：$A \to w$，或 $A \to wB$；左线性文法：$A \to w$，或 $A \to Bw$，其中 $w$ 是终结符号串。

    * 概括：产生式右部最多只有一个非终结符，而且所有产生式中这个非终结符都要待在同一侧。

    * 生成的语言称为正规语言；程序设计语言中的大多数单词都可以用正规文法描述。

* 右线性文法示例：

    ```text
    S → 字母 | 字母 T
    T → 字母 | 数字 | 字母 T | 数字 T
    ```

    * 每条产生式左部都是单个非终结符，满足 2 型要求；右部要么是终结符号串，要么在终结符号串右边添一个非终结符，所以是右线性。

    * $T$ 生成字母数字串，$S$ 生成字母打头的字母数字串，即标识符；它与前面生成标识符的上下文无关文法等价。

### 逐级包含

| 类型 | 别称 | 对产生式的限制 | 生成的语言 |
| :--- | :--- | :--- | :--- |
| 0 型 | 无限制文法、短语结构文法 | 左部 $\alpha$ 中至少包含一个非终结符 | 0 型语言 |
| 1 型 | 上下文有关文法（CSG） | $|\alpha| \le |\beta|$，一般形如 $\alpha_1 A \alpha_2 \to \alpha_1\beta\alpha_2$ | 上下文有关语言 |
| 2 型 | 上下文无关文法（CFG） | 左部必须是单个非终结符，$A \to \beta$ | 上下文无关语言 |
| 3 型 | 正规文法（RG） | 右线性 $A \to w$ 或 $A \to wB$；左线性 $A \to w$ 或 $A \to Bw$ | 正规语言 |

* 限制是一层压一层加上去的：0 型只要求左部含非终结符；1 型再加长度关系；2 型把左部收窄成单个非终结符；3 型再限制右部形状。

* 不考虑空产生式时，四类文法的集合是逐级包含关系：

    ```text
    0 型文法（无限制文法 / 短语结构文法）
    └── 1 型文法（上下文有关文法，CSG）
        └── 2 型文法（上下文无关文法，CFG）
            └── 3 型文法（正规文法，RG）
    ```

* 2 型文法一定是 1 型文法，但反过来不成立；3 型文法一定是 2 型文法，进而也是 1 型文法，反过来同样不成立。

* > **注意**：逐级包含的前提是「不考虑空产生式」；1 型文法不含空产生式，而写文法时又常用空产生式，所以含空产生式的文法不在这个关系的讨论范围之内。

## 分析树与二义性

### 分析树的定义

* **分析树（parse tree）** 的正式定义：

    * 根结点对应文法的开始符号。

    * 每一个内部结点表示对一个产生式的应用：结点标号是产生式的左部 $A$，子结点标号从左到右构成产生式的右部 $\beta$。

    * 叶结点的标号既可以是非终结符，也可以是终结符。

    * 从左到右排列叶结点得到的符号串，称为这棵树的产出，或称边缘。

* 分析树是推导的图形化表示：推导走一步，树往下长一层；树每长一层之后的边缘，恰好就是那一刻的句型。

* 以 $E \to E+E$、$E \to -E$、$E \to (E)$、$E \to id$ 推导 $-(id+id)$：

    ```text
    E
    └─ E → -E
       ├─ -
       └─ E
          └─ E → (E)
             ├─ (
             ├─ E
             │  └─ E → E + E
             │     ├─ E → id
             │     ├─ +
             │     └─ E → id
             └─ )
    ```

### 短语与直接短语

* **短语（phrase）**

    * > **定义**：给定一个句型，其分析树中每一棵子树的边缘，都是该句型的一个短语。

    * 例：句型 $-(E+E)$ 中，整棵树的边缘 $-(E+E)$、括号内子树的边缘 $(E+E)$、最内层子树的边缘 $E+E$ 都是短语。

* **直接短语（direct phrase）**

    * > **定义**：子树只有父子两代结点（高度为 2）时，这棵子树的边缘称为该句型的一个直接短语。

    * 上例中只有以最里面那个 $E$ 为根的子树高度为 2，所以 $E+E$ 是直接短语。

* 直接短语一定是某个产生式的右部：高度为 2 的子树正好对应一次产生式的应用。

* 反过来不成立：产生式的右部不一定是当前句型的直接短语。设「高人」「人民」「民生」「生活」「活水」「水平」都由同一条产生式生成，在「提高人民生活水平」中，只有「人民」「生活」「水平」是高度为 2 的子树的边缘，所以是直接短语；「高人」「民生」「活水」不是。

* 「活水」在「唯有源头活水来」中是直接短语，在当前句中不是——同一个串在不同分析树里地位不同。

* > **易错点**：判断直接短语要回到这一棵分析树上看，不能只看文法里有没有这条产生式。

### 二义性

* **二义性文法（ambiguous grammar）**

    * > **定义**：如果一个文法可以为某个句子生成多棵分析树，则称该文法是二义性的。

* 条件语句文法：

    ```text
    S → if E then S
    S → if E then S else S
    S → other
    ```

    * `other` 表示除条件语句以外的其他语句，如赋值语句、循环语句、过程调用语句。

* 句型 `if E1 then if E2 then S1 else S2` 可以构造出两棵分析树：

    ```text
    第一棵                                第二棵
    if E1 then                            if E1 then
        if E2 then S1 else S2                if E2 then S1
                                          else S2
    ```

    * 第一棵把 `if E2 then S1 else S2` 整体当作内层语句，else 归里面那个 if。

    * 第二棵只把 `if E2 then S1` 当作内层语句，else 归外面那个 if。

* 消除歧义要改造文法，代价是可能引入新的非终结符或空产生式；也可以引入消歧规则。

* 该例的歧义根源是句子里有两个 if 却只有一个 else；大多数语言规定每个 else 与最近的、尚未匹配的 if 匹配，按此规则只保留第一棵树。

* **判定**：对任意一个上下文无关文法，不存在一个算法来判定它是否无二义性；但可以给出一组充分条件，满足条件的文法一定无二义性。

* 充分条件的含义要分清：满足则一定无二义；不满足也未必有二义。

## 正规表达式

### 递归定义与优先级

* **正规表达式（regular expression）**

    * > **定义**：由较小的正规表达式按特定规则递归构建的表达式，每个正规表达式 $r$ 定义或表示一个语言 $L(r)$。

    * 空串 $\varepsilon$ 是正规表达式，$L(\varepsilon) = \{\varepsilon\}$。

    * 字母表 $\Sigma$ 上的任何一个符号 $a$ 是正规表达式，$L(a) = \{a\}$。

    * 若 $r$、$s$ 是正规表达式，则 $r \mid s$ 是正规表达式，$L(r \mid s) = L(r) \cup L(s)$。

    * 若 $r$、$s$ 是正规表达式，则 $rs$ 是正规表达式，$L(rs) = L(r)L(s)$。

    * 若 $r$ 是正规表达式，则 $r^{*}$ 是正规表达式，$L(r^{*}) = (L(r))^{*}$。

    * 若 $r$ 是正规表达式，则 $(r)$ 是正规表达式，$L((r)) = L(r)$。

* 运算优先级由高到低：克林闭包、连接、或运算。

* 在 $\Sigma = \{a,b\}$ 上的例子：$a \mid b$ 表示 $a$ 或 $b$；$(a \mid b)(a \mid b)$ 表示 $aa$、$ab$、$ba$、$bb$；$a^{*}$ 表示任意个 $a$ 连接；$(a \mid b)^{*}$ 表示任意长度的 $ab$ 串；$a \mid a^{*}b$ 表示 $a$，或若干个 $a$ 后接一个 $b$。

* 一个更复杂的例子：$a(ab)^{*}(\varepsilon \mid (. \mid \_)(ab)^{+})$ 表示句首为 $a$，接任意长度的 $ab$ 串，然后或者结束，或者接一个点号或下划线再接至少一个 $ab$ 串。

### 描述 C 语言的无符号整数

* 十进制：$(1 \mid 2 \mid \dots \mid 9)(0 \mid 1 \mid \dots \mid 9)^{*} \mid 0$；首位是 1 至 9，后接若干 0 至 9，末尾单独的 $0$ 表示 0 本身也合法。

* 八进制：$0(1 \mid 2 \mid \dots \mid 7)(0 \mid 1 \mid \dots \mid 7)^{*}$；首位是 0，第二位是 1 至 7，后接若干 0 至 7。

* 十六进制：$0x(1 \mid \dots \mid 9 \mid a \mid \dots \mid f)(0 \mid \dots \mid 9 \mid a \mid \dots \mid f)^{*}$；依次是 0、x、一位十六进制数字、若干十六进制数字。

* **正规语言（regular language）**

    * > **定义**：可以用正规表达式定义的语言，也叫正规集合。

### 代数定律与等价性

* 或运算满足交换律与结合律：$r \mid s = s \mid r$，$(r \mid s) \mid t = r \mid (s \mid t)$。

* 连接运算满足结合律：$(rs)t = r(st)$。

* 连接对或满足分配律：$r(s \mid t) = rs \mid rt$，$(s \mid t)r = sr \mid tr$。

* 空串是连接的单位元：$\varepsilon r = r\varepsilon = r$。

* 闭包中一定包含空串：$\varepsilon \in L(r^{*})$；克林闭包具有幂等性：$(r^{*})^{*} = r^{*}$。

* **正规文法与正规表达式等价**：对任何一个正规文法 $G$，都存在定义同一语言的正规表达式 $r$；对任何一个正规表达式 $r$，也都存在生成同一语言的正规文法 $G$。

## 正则定义

### 定义序列与约束

* **正则定义（regular definition）**

    * > **定义**：给正规表达式命名的定义序列 $d_1 \to r_1,\ d_2 \to r_2,\ \dots,\ d_n \to r_n$，每个 $r_i$ 是正规表达式，每个 $d_i$ 是给它起的名字。

* 对名字的两条硬性要求：

    * 每个 $d_i$ 都是新符号，不在字母表 $\Sigma$ 中，而且互不相同。

    * 每个 $r_i$ 只能使用字母表中的符号，或者已经定义好的前 $i-1$ 个名字 $d_1, \dots, d_{i-1}$。

* 「只能用前面已经定义的」保证每个名字在使用前已有定义，整个定义序列不会绕成一个圈。

### C 语言标识符与无符号数

* C 语言标识符的正则定义：

    ```text
    digit   → 0 | 1 | 2 | … | 9
    letter_ → 字母 | 下划线
    id      → letter_ ( letter_ | digit )*
    ```

    * `digit` 表示一个数字；`letter_` 表示一个字母或下划线；`id` 由 `letter_` 接一个由 `letter_` 或 `digit` 构成的串，即字母打头的字母数字串。

* 无符号数的正则定义：

    ```text
    digit        → 0 | 1 | 2 | … | 9
    digits       → digit digit*
    可选小数部分 → . digits | ε
    可选指数部分 → E + digits | E - digits | E digits | ε
    number       → digits 可选小数部分 可选指数部分
    ```

    * `digits` 是长度大于等于 1 的数字串；可选小数部分是点号接 `digits` 或空串；可选指数部分是 `E` 接正号、负号或直接接 `digits`，或取空串。

| 小数部分 | 指数部分 | 表示的数 | 例子 |
| :--- | :--- | :--- | :--- |
| 空串 | 空串 | 整数 | $2$ |
| 非空 | 空串 | 小数 | $2.15$ |
| 非空 | 非空 | 指数形式的浮点数 | $2.15E+3$ 即 $2.15 \times 10^{3}$；$2.15E-3$ 即 $2.15 \times 10^{-3}$ |
| 空串 | 非空 | 整数的若干次幂 | $2E-3$ 即 $2 \times 10^{-3}$ |

* 指数为正数时正号可以省略：$2.15E3$ 表示 $2.15 \times 10^{3}$。

* > **提示**：这里的 `E` 是字母表里一个普通符号，用作指数标记，与表示表达式的非终结符 $E$ 同名不同身份。

## 有穷自动机

### 模型与状态

* **有穷自动机（finite automaton，FA）**

    * > **定义**：1948 年由两位神经物理学家提出的数学模型，用来描述一类具有离散输入输出信息、内部状态数目有穷的处理系统。

    * 状态概括的是过去输入信息处理的状况；系统不必记录全部历史，只要知道当前状态和当前输入，就能决定后续行为，每处理完一个输入状态随之改变。

    * 三个组成部分：输入带（存放输入符号串）、读头（从左向右逐个读取输入符号）、有穷控制器（有穷个状态，根据当前状态与当前输入决定转入下一个状态）。

    * 读头的三条限制：不能修改带上的符号、不能往返移动，只能从左往右。

    * 「有穷」指记住过去的能力有穷：输入可以任意长，机器只保留一个有穷状态。

* 电梯控制装置：输入是顾客要到达的层号，状态是电梯当前所处层数加上运行方向；不必记住先前全部服务要求，只要当前状态加未满足的请求，就能决定继续上行、下行还是停下开门。

* 词法分析器同理：源程序可以几十万字符，但扫描到某一处时，需要记住的只有「当前这个单词读到了哪一段」。

### 转换图

* **转换图（transition diagram）**

    * > **定义**：用有向图表示有穷自动机；每个结点表示一个状态，带标记的有向边表示转换。

    * 若对输入符号 $a$ 存在从状态 $p$ 到状态 $q$ 的转换，就画一条从 $p$ 指向 $q$ 的边并标上 $a$。

* 初始状态只有一个，由一条 `start` 箭头指向；终止状态（接收状态）可以有多个，用双圈表示。

    ```text
       start
         |
         v
       ( 0 ) --a--> ( 1 )        ( 2 )        (( 3 ))

       ( )     单圈：普通状态
       (( ))   双圈：终止（接收）状态，可以有多个
       start   箭头指向的那个，是唯一的初始状态
    ```

* 读图路数固定：先顺 `start` 箭头找起点，再找双圈看哪些地方算走通，中间带标记的边就是每一步可走的路。

### 接收与最长子串匹配

* **接收（accept）**

    * > **定义**：给定输入串 $x$，如果存在一个对应于 $x$ 的、从初始状态到某个终止状态的转换序列，则称串 $x$ 被这个有穷自动机接收。

    * 定义用的是「存在」：同一状态遇同一符号可能有好几条路，只要有一条能一路走到终止状态，这个串就算被接收，不要求所有路都走通。

* 一台四状态自动机（状态 0 遇 $a$、$b$ 都留在 0，遇 $a$ 还可转到 1；1 遇 $b$ 到 2；2 遇 $b$ 到 3；3 是终态）接收 `abbaabb` 的过程：

| 步 | 读入 | 已读前缀 | 状态 | 说明 |
| :--: | :--: | :--- | :--: | :--- |
| 0 | — | $\varepsilon$ | 0 | 起始 |
| 1 | a | a | 0 | 留在 0 |
| 2 | b | ab | 0 | 留在 0 |
| 3 | b | abb | 0 | 留在 0 |
| 4 | a | abba | 0 | 留在 0 |
| 5 | a | abbaa | 1 | 这一次不留，转到 1 |
| 6 | b | abbaab | 2 | 走 $1 \to 2$ |
| 7 | b | abbaabb | 3 | 终止状态，接收 |

* 第 5 步是关键：状态 0 遇 $a$ 可以选择留在 0 或转到 1；前面读到的 `abba` 没有可利用的后缀就留在 0，从第 5 步起最后三个符号恰好凑成 `abb`，转到 1 再走 $1 \to 2 \to 3$ 就落到终止状态。

* 一个有穷自动机 $M$ 接收的所有串构成的集合，称为它定义或接收的语言，记作 $L(M)$；上例的语言是所有以 $abb$ 结尾的 $ab$ 串。

* 状态 1、2、3 记的分别是「刚刚读到的后缀以 $a$ 结尾」「以 $ab$ 结尾」「以 $abb$ 结尾」。

* **最长子串匹配原则**

    * > **定义**：当输入串的多个前缀与一个或多个模式匹配时，总是选择最长的那个前缀进行匹配。

    * 输入 `<` 紧跟 `=` 时，`<` 与 `<=` 两个前缀都匹配，取 `<=`；输入 `++` 时 `+` 与 `++` 都匹配，取 `++`。

    * 运行时准则：到达某个终态之后，只要输入带上还有符号，有穷自动机就继续前进，以便寻找尽可能长的匹配。

    * 这解释了扫描器读到终态不马上收工、继续读到读不下去、再回到上一个终态位置把那里当单词结尾的行为。

## DFA 与 NFA

### 确定的有穷自动机

* **确定的有穷自动机（deterministic finite automaton，DFA）**

    * > **定义**：五元组 $(S, \Sigma, \delta, s_0, F)$。

    * $S$：有穷状态集合。

    * $\Sigma$：输入字母表，约定空串不是字母表中的元素。

    * $\delta$：转换函数 $S \times \Sigma \to S$；$\delta(s,a)$ 表示从状态 $s$ 出发沿标记为 $a$ 的边所能到达的状态。

    * $s_0$：初始状态（开始状态）；$F$：终止状态（接收状态）的集合。

    * 关键在于 $\delta$ 的值域：$\delta(s,a)$ 是一个状态，不是一个集合；给定状态和符号，去处唯一。

* **转换表（transition table）**

    * > **定义**：以状态为行、输入符号为列的表格，逐格给出 $\delta(s,a)$。

    * 转换图与转换表功能等价：图是给人看形状的，表是给机器查的。

* 一个四状态 DFA 的转换表（接收状态集合 $F = \{3\}$）：

| 状态 | a | b |
| :--: | :--: | :--: |
| 0 | 1 | 0 |
| 1 | 1 | 2 |
| 2 | 1 | 3 |
| 3 | 1 | 0 |

* 「确定」的两层含义：表里每个格子最多只有一个状态，去处唯一；读头只能从左向右逐符号读，读入顺序也唯一。两条合起来，整条运行路径唯一确定，不需猜、不需回溯。

### 非确定的有穷自动机

* **非确定的有穷自动机（nondeterministic finite automaton，NFA）**

    * > **定义**：与 DFA 的唯一区别是 $\delta(s,a)$ 表示从状态 $s$ 出发沿标记为 $a$ 的边所能到达的状态集合，可能有多个。

    * 转换函数没有给出某个「状态—输入」对的信息时，表项填空集 $\varnothing$，表示该状态不允许遇到该符号，遇到即出错。

* 一个 NFA 的转换表：

| 状态 | a | b |
| :--: | :--: | :--: |
| 0 | {0,1} | {0} |
| 1 | $\varnothing$ | {2} |
| 2 | $\varnothing$ | {3} |
| 3 | $\varnothing$ | $\varnothing$ |

* **等价性**：对任何一个 NFA $N$，存在识别同一语言的 DFA $D$；对任何一个 DFA $D$，也存在识别同一语言的 NFA $N$。

    * DFA 本身就是 NFA 的特例：NFA 允许指向集合，单元素集合也是集合。

    * 有分量的是 NFA → DFA：任意一个 NFA 都能改写成等价的 DFA，算法是子集构造法。

### 等价机器的两种脾气

* 把「以 $abb$ 结尾」的 NFA 改造成 DFA，四个状态的含义：0 表示当前串还没有可用后缀，1 表示以 $a$ 结尾，2 表示以 $ab$ 结尾，3 表示以 $abb$ 结尾，3 是终态。

    ```text
                  a               b               b
      start --> (0) --a--> (1) --b--> (2) --b--> ((3))

      自环与回退边：
      (0) --b--> (0)        (1) --a--> (1)
      (2) --a--> (1)        (3) --a--> (1)        (3) --b--> (0)
    ```

* 回退边是「断言被否定」的地方：状态 2 遇 $a$，原条件「以 $ab$ 结尾」被破坏，但新来的 $a$ 有用，退回状态 1 改口说「以 $a$ 结尾」。

* 状态 3 已是终态，只要输入带上还有符号就得继续走：遇 $a$ 回状态 1（`abba` 的后缀是 $a$），遇 $b$ 退回状态 0（`abbb` 连可用的 $a$ 都凑不出）；若无新符号，状态 3 作为结尾表示成功接收。

* 该语言的正规表达式是 $(a|b)^{*}abb$。

* 三层等价：正规表达式与有穷自动机等价；正规文法与正规表达式等价；因此正规文法与有穷自动机也等价。

* 两种机器的脾气：NFA 更直观，一眼能看出认的是「以 $abb$ 结尾的 $ab$ 串」；DFA 更容易实现，每一步只有一个去处，查表转移，不必处理「同时处在多个状态」。

* 整套流程的动机：让人去写直观的 NFA，让机器去跑确定的 DFA，中间用算法把前者变成后者。

### 带空边的 NFA

* **带有空边的 NFA（NFA with ε-transitions）**

    * > **定义**：有向边上除了标记字母表中的字母，还可以标记空串的 NFA；从定义上看，它的输入符号中包含空串。

    * 这与 DFA「空串不是字母表中的元素」不矛盾：$\Sigma$ 里仍然没有空串，空边是边上的标记，不是读进来的符号，它不消耗输入。

* 例：A 有一条空边到 B，B 有一条空边到 C；A 收 0 自环，B 收 1 自环，C 收 2 自环。

    ```text
      start --> (A) --ε--> (B) --ε--> ((C))

      (A) 只接收 0：(A) --0--> (A)
      (B) 只接收 1：(B) --1--> (B)
      (C) 只接收 2：(C) --2--> (C)
    ```

    * 该自动机接收的语言是 $0^{*}1^{*}2^{*}$。

* 等价的不带空边版本：A 遇 1 到 B，B 遇 2 到 C，三个状态各自对相应数字自环；A、B、C 三个都是终态，因为在 A 时可以认为 1 和 2 的个数都是 0，在 B 时可以认为 2 的个数是 0。

* 带空边与不带空边的 NFA 等价：给定带空边的 NFA 可构造等价的不带空边 NFA；反过来把已有边看成普通边、再补几条空边即可。

* > **提示**：空边改变的只是走的路径，不改变读了多少符号；判断一个串能否被接收时，空边可以随便走、连着走、走任意多条，都不算消耗输入。

### DFA 的实现

* 算法：输入为以 `EOF` 结尾的字符串 $x$、开始状态 $s_0$、接收状态集合 $F$、转换函数 `move`；输出 `"yes"` 或 `"no"`。

    ```text
    s = s0;
    c = nextChar();
    while (c != EOF) {
        s = move(s, c);
        c = nextChar();
    }
    if (s in F) return "yes";
    else return "no";
    ```

* 全程只用 $s$ 和 $c$ 两个变量，状态数是常数、与输入串长度无关：空间 $O(1)$、时间 $O(n)$。

* 这个算法回答「整个串能不能被接收」；词法分析器要在此之外再套一层最长子串匹配的循环，每切出一个单词就报一次 token。

## 正规表达式到 NFA

### 转换路线

* 正则表达式 → NFA → DFA：直接从正规表达式构造 DFA 比较困难，所以先转成等价的 NFA，再从 NFA 构造 DFA。

* 先转 NFA 的理由：NFA 相对 DFA 更直观，从正规表达式构造 NFA 比较简单。

* 两步都很机械：第一步照着正规表达式的语法结构往上套规则，第二步照着状态集合做穷举，都不需要灵感。

### 五条基本规则

* 空串 $\varepsilon$：一个初始状态、一个终止状态，两者之间一条标记为空串的有向边。

* 字母表中的符号 $a$：初始状态 $q_0$ 到终止状态 $q_f$ 的边上标记 $a$。

* 连接 $r_1 r_2$：把两台 NFA 串联起来，首尾相连。

* 或 $r_1 \mid r_2$：把两台 NFA 并联起来。

* 闭包 $r_1^{*}$：循环形式，在可以循环的边上标记子表达式 $r_1$。

    ```text
      ① 空串 ε：
          start --> (q0) --ε--> ((qf))

      ② 单符号 a：
          start --> (q0) --a--> ((qf))

      ③ 连接 r1 r2：
          start --> (q0) --[r1]--> (qm) --[r2]--> ((qf))

      ④ 或 r1|r2：
          start --> (q0) --[r1]--> ((qf))
                    (q0) --[r2]--> ((qf))          （两条边并联，起点终点相同）

      ⑤ 闭包 r1*：
          start --> (q0) --ε--> (q1) --ε--> ((qf))

          (q1) --[r1]--> (q1)                      （循环边，绕 r1 一圈回到自己）
    ```

* 任何正规表达式，不管套多少层括号、叠多少个星号，都是这五种形状拼出来的；照着语法树自底向上搭，一定能搭出一台 NFA。

### 构造示例

* 对 $(a|b)^{*}abb$，第一步设初始状态与终止状态，两者之间引一条边，边上标记整个正规表达式。

    ```text
      start --> (q0) --(a|b)*abb--> ((qf))
    ```

* 第二步把它分解成四个子表达式连接：$(a|b)^{*}$、$a$、$b$、$b$，NFA 也分解成四部分串联。

    ```text
      start --> (q0) --(a|b)*--> (p1) --a--> (p2) --b--> (p3) --b--> ((qf))
    ```

* 第三部分之后都是普通边；第一部分是克林闭包，转换成循环形式，循环边上标记子表达式 $a|b$。

    ```text
      start --> (q0) --ε--> (L) --ε--> (p1) --a--> (p2) --b--> (p3) --b--> ((qf))

      (L) --a|b--> (L)                            （循环边）
    ```

* 最后把循环边上的 $a|b$ 拆成两条并联的边，一条标 $a$、一条标 $b$，起点和终点都是 $L$。

## 子集构造法

### 原理

* **子集构造法（subset construction）**

    * > **定义**：把 NFA 中「同一个输入可能到达的好几个状态」打成一个包，让这个包成为 DFA 的一个状态，从而把 NFA 转换成等价的 DFA。

* 与 NFA 等价的 DFA 中的每一个状态，都是 NFA 状态集合的一个子集，方法因此得名。

* 转移规则：集合状态遇到某个符号的去处，是集合内各状态遇到该符号去处的并集。

### 无空边的 NFA

* 待转换的 NFA（状态 A 遇 $a$ 可到 A 或 B，B 遇 $b$ 可到 B 或 C，C 遇 $c$ 可到 C 或 D，D 无出边）：

| 状态 | a | b | c |
| :--: | :--: | :--: | :--: |
| A | {A,B} | $\varnothing$ | $\varnothing$ |
| B | $\varnothing$ | {B,C} | $\varnothing$ |
| C | $\varnothing$ | $\varnothing$ | {C,D} |
| D | $\varnothing$ | $\varnothing$ | $\varnothing$ |

* 构造过程：NFA 的初态 A 仍是 DFA 的初态；A 遇 $a$ 进 $\{A,B\}$，$\{A,B\}$ 遇 $a$ 得 $\{A,B\}$（自环）、遇 $b$ 得 $\{B,C\}$；$\{B,C\}$ 遇 $b$ 自环、遇 $c$ 得 $\{C,D\}$；$\{C,D\}$ 含 NFA 终态 D，标为终态，遇 $c$ 自环。

| DFA 状态 | a | b | c |
| :--: | :--: | :--: | :--: |
| A | AB | — | — |
| AB | AB | BC | — |
| BC | — | BC | CD |
| CD（终态） | — | — | CD |

* 对应的转换图：

    ```text
                  a              b              c
      start --> (A) --a--> (AB) --b--> (BC) --c--> ((CD))

      自环：(AB) --a--> (AB)      (BC) --b--> (BC)      (CD) --c--> (CD)
    ```

* 验证：NFA 识别 $a$、$b$、$c$ 各至少一个的串；DFA 从 A 必须先读 $a$ 到 AB，从 AB 必须先读 $b$ 到 BC，从 BC 必须先读 $c$ 到 CD，到不了 CD 不算接收，所以识别的也是 $a^{+}b^{+}c^{+}$。

### 带空边的 NFA

* **空闭包（ε-closure）**

    * > **定义**：从某个状态出发，沿着空边可以到达的所有状态的集合；空边不消耗输入，所以进入一个状态后可以顺着空边继续往前走。

    * 计算各状态遇各符号的去处时，先把能沿空边到达的状态都收进来，再用这些状态自己的边。

* 待转换的 NFA：A 遇 0 自环、有空边到 B；B 遇 1 自环、有空边到 C；C 遇 2 自环。

| 状态 | 0 | 1 | 2 |
| :--: | :--: | :--: | :--: |
| A | {A,B,C} | {B,C} | {C} |
| B | $\varnothing$ | {B,C} | {C} |
| C | $\varnothing$ | $\varnothing$ | {C} |

    * A 能吃 1、能吃 2，靠的不是自己有对应的边，而是沿空边走到 B、走到 C 之后用别人的边；空边把后面状态的可接收符号前移到了前面状态。

* 构造 DFA：A 可沿空边到 B、再到 C，所以初态是 $\{A,B,C\}$；其中 C 是 NFA 终态，故初态也是终态，表示可以接收空串。

| DFA 状态 | 0 | 1 | 2 |
| :--: | :--: | :--: | :--: |
| ABC（终态） | ABC | BC | C |
| BC（终态） | — | BC | C |
| C（终态） | — | — | C |

* 对应的转换图：

    ```text
                       1              2
      start --> (ABC) ----> (BC) ------> ((C))

      自环：(ABC) --0--> (ABC)      (BC) --1--> (BC)      (C) --2--> (C)
      另有：(ABC) --2--> (C)        （跳过 1，1 的个数为 0）
    ```

* 验证：初始状态收若干 0，遇 1 进 BC 收若干 1，遇 2 进 C 收若干 2；也可以在 ABC 收完 0 后直接遇 2 进 C，此时 1 的个数为 0。两边都是 $0^{*}1^{*}2^{*}$。

* 初态是终态不是巧合，它就是「这个语言允许空串」的直接体现；判断一台 DFA 认不认空串，看初态是不是双圈。

* > **易错点**：$\{1,3,6\}$ 是 DFA 的一个状态，不是三个并列的状态；下一步的去处是这个集合里所有元素去处的并集，不能把它们当成几条独立的路。

## 词法分析器的 DFA 构造

### 标识符

* 标识符的正规表达式由两部分串联：识别一个字母或下划线，再识别若干个字母、下划线或数字。

    ```text
                         字母 / 下划线 / 数字
                       +---------------------+
                       |                     |
                       v                     |
      start --> (0) --字母 / 下划线--> ((1))
    ```

* 这台 NFA 本身就是一个 DFA：状态 0 遇字母或下划线只有一条边指向 1，状态 1 遇字母、下划线、数字也只有一条边回到自己。

* > **提示**：有些正规表达式画出来的图天然就是确定的——每个状态对每个符号最多只有一条出边；先看它是否已经是 DFA，别一看到正规表达式就想着转换。

### 无符号数

* 正规表达式：$\text{digit}^{+} \;(\,'.'\;\text{digit}^{+}\,)? \;(\,E\,(\,'+'\mid'-'\,)?\;\text{digit}^{+}\,)?$，三部分分别是至少一位数字、可选小数部分、可选且可带正负号的指数部分。

* 拼接出的带空边 NFA：

    ```text
      start --> (0) --d--> (1) --'.'--> (2) --d--> (3) --E--> (4) --ε--> (5) --d--> ((6))

      自环：(1) --d--> (1)      (3) --d--> (3)      (6) --d--> (6)
      空边：(1) --ε--> (3)      （小数部分取空）
            (3) --ε--> (6)      （指数部分取空）
            (4) --ε--> (5)      （正负号取空）
      符号：(4) --'+'--> (5)    (4) --'-'--> (5)
    ```

* 子集构造走查：初态 0 遇 $d$ 进 1，进 1 后可沿空边到 3、再到 6，所以进入 $\{1,3,6\}$。

    * $\{1,3,6\}$ 遇 $d$ 仍得 $\{1,3,6\}$（自环）；遇 `.` 由状态 1 进 2；遇 $E$ 由状态 3 进 4，再沿空边进 5，得 $\{4,5\}$。

    * 状态 2 遇 $d$ 进 3、带上 6，得 $\{3,6\}$；$\{3,6\}$ 遇 $d$ 自环，遇 $E$ 得 $\{4,5\}$。

    * $\{4,5\}$ 遇正号或负号进入状态 5；遇 $d$ 时 4 沿空边到 5 再吃 $d$、5 吃 $d$，都进 6，得 $\{6\}$；5 遇 $d$ 进 6，6 遇 $d$ 自环。

| DFA 状态 | d | . | E | + | - |
| :--: | :--: | :--: | :--: | :--: | :--: |
| 0 | {1,3,6} | — | — | — | — |
| 136（终态） | 136 | 2 | 45 | — | — |
| 2 | 36 | — | — | — | — |
| 36（终态） | 36 | — | 45 | — | — |
| 45 | 6 | — | — | 5 | 5 |
| 5 | 6 | — | — | — | — |
| 6（终态） | 6 | — | — | — | — |

* 检验：读到一位数字进 $\{1,3,6\}$，继续收若干数字，无后续符号就成功接收整数；遇小数点进状态 2，必须收小数位后到 $\{3,6\}$，可成功接收小数；遇 $E$ 进 $\{4,5\}$，决定正负号后收至少一位数字落到状态 6，成功接收带指数的数。

* 从 $\{1,3,6\}$ 也可以直接遇 $E$ 走指数，整数部分直接接指数、小数部分为 0 个，这条路是通的。

### 各进制整数

* 十进制、八进制、十六进制的无符号整数各自都能画出一台 DFA；源程序里三种数混在一起，要合成一台统一的 DFA。

    ```text
       start --> (0) --1~9--> (1) --0~9 自环--> 十进制整数，token：DEC
                    |
                    |0
                    v
                 {2,3,5} --1~7--> (4) --0~7 自环--> 八进制整数，token：OCT
                    |
                    |x
                    v
                  (6) --十六进制数字--> (7) --0~f 自环--> 十六进制整数
    ```

* 初态遇 $1\sim9$ 进状态 1，继续收若干 $0\sim9$，识别出十进制整数，token 种别码为 `DEC` 并带属性值。

* 初态遇 0 时可能进状态 2、3、5，于是构造集合状态 $\{2,3,5\}$：以 0 开头的串既可能是十进制 0、八进制数，也可能是十六进制数，此刻还看不出是哪种。

* 若 0 之后没有别的符号，就识别为十进制整数 0，种别码 `DEC`，值是 0。

* $\{2,3,5\}$ 遇 $1\sim7$ 进状态 4，继续收若干 $0\sim7$，识别出八进制数，种别码 `OCT`。

* $\{2,3,5\}$ 遇 $x$ 进状态 6，状态 6 遇一位十六进制数字进状态 7，继续收若干 $0\sim f$，识别出十六进制数。

* > **提示**：三种进制共用「0 开头」前缀，候选状态被并成一个集合状态；这不是三个状态可选，而是「当前可能处在三种解释之下」。

### 注释

* 注释 `/* ... */` 的识别状态：初态遇 `/` 进状态 1（当前串以斜杠结尾）；遇 `*` 进状态 2（注释开始）；状态 2 遇 `*` 以外的任何符号都留在 2（收注释内容）；遇 `*` 进状态 3（结尾星号已出现）；状态 3 遇 `/` 进状态 4，成功接收一个注释。

    ```text
      start --> (0) -/-> (1) -*-> (2) -*-> (3) -/-> ((4))

      (2) 遇 * 以外的符号：留在 (2)，继续收注释内容
      (3) 遇 *：留在 (3)，继续等斜杠
      (3) 遇 * 和 / 以外的符号：退回 (2)，重新等星号
    ```

* 状态 2 与状态 3 的区别只有一件事：末尾有没有一个星号；注释内容里的斜杠、字母、括号全在状态 2 里被一格一格吞掉，只有在状态 3 遇斜杠才算真正收尾。

* > **提示**：从状态 3 退回状态 2 不是「出错重来」，而是把这个符号当作注释内容收下；这与错误处理里的回退性质完全不同。

### 统一 DFA 与关键字

* 把识别不同单词的 DFA 整合起来，得到一台统一的 DFA：

    ```text
                           字母 / 下划线
       start --> (0) -----------------------> 标识符分支 --> token：IDN
                   |
                   | 数字
                   +-----------------------> 无符号数分支 --> token：DEC / OCT / ...
                   |
                   | 其它字符
                   +----------------------- 运算符、界符分支 --> token：运算符 / 界符
    ```

* 从初态开始从左至右逐个扫描字符；每识别出一个单词就表示成 token，然后退回初始状态，继续识别下一个单词。

* **关键字**由字母组成，完全可以用识别标识符的 DFA 识别：每识别出一个标识符就查关键字表，在表里就识别成关键字，不在才当普通标识符。

* > **提示**：关键字不另造 DFA，是为了让长得一样的东西走同一条路；`if`、`while` 和普通变量名在字符层面没有区别，区别只在最后一步查表，代价只是多一次表查找。

## 词法错误处理

* 词法阶段可以检测到的错误主要有两类：

    * 单词拼写错误，比如写错的十六进制数、写错的指数形式浮点数——字符长得像那么回事，但走不到任何终态。

    * 非法字符，也就是字母表里根本不该出现的字符。

* 检测办法：如果当前状态与当前输入符号在转换表对应项中的信息为空，即当前状态不可以遇到当前输入符号，就报错并调用错误处理程序。

* **错误恢复（error recovery）**

    * > **定义**：以一定方式处理错误，使编译器能够继续运行下去，从错误状态尽快恢复，以便检测源程序中更多的错误。

* 处理动作是按最长子串匹配原则往前找退路：在已扫描的字符串里，找最后一个对应于某个终态的字符。

    * 找到了：把该字符以及它前面的字符识别成一个单词，输入指针退回到该字符之后，扫描器回到初始状态，继续识别下一个单词。

    * 没找到：从串首到出错点一个合法单词都没能切出来，必须以一定方式处理。

* **恐慌模式（panic mode）**

    * > **定义**：最简单的错误恢复策略，从剩余的输入中不断删除字符，直到词法分析器能够在剩余输入的开头发现一个正确的字符为止。

* > **提示**：最后一个终态字符能当断点，是因为最长子串匹配保证了扫到那个位置为止，前面那一段已经是一个完整合法的单词；断在那里既没有丢掉已识别的单词，也没有把错误字符吞进 token。
