# 语法分析：自底向上

## LR 分析法的基本思想

* **LR 分析法（LR parsing）**

    * > **定义**：从左到右扫描输入串，按最右推导的逆序做归约，用状态记录句柄识别的进展，在栈顶认出句柄后完成归约的自底向上分析方法。

    * 名称中 L 为 Left，表示对输入从左到右扫描；R 为 Right，表示反向构造出一个最右推导序列；归约序列倒过来看就是一个最右推导。

    * LR 文法是能构造出相应移入-归约语法分析器的最大文法类，是一个上界；某一种具体的表构造方法只能覆盖其中一部分。

    * 能力递进：LR(0) 处理不了算术表达式的文法，SLR 用 FOLLOW 集补上一部分，SLR 仍有补不动的冲突，再往上才是 LR(1)。

    * 向前查看 $k$ 个符号的分析器记作 $LR(k)$ 分析器；多数描述程序设计语言的上下文无关文法最多向前看一个符号就够，有实践意义的是 $k=0$ 与 $k=1$。

    * 约定括号中的 $k$ 省略时表示 $k=1$，说「LR 分析器」默认已向前看一个符号。

* **句柄的逐步识别**

    * 句柄随输入符号逐个进栈而逐步形成：先看到一个 $b$ 不能确定，归约出一个 $B$ 仍只是「可能」，整串符号齐了才敢断言栈顶就是句柄。

    * 以 $S \to bBB$ 为例，右部三个符号对应四个识别阶段：

    ```text
    S -> . b B B     还没见到 b，期待终结符 b        （移进状态）
    S -> b . B B     b 已进栈，等待归约出第一个 B    （待约状态）
    S -> b B . B     第一个 B 到位，等待第二个 B     （待约状态）
    S -> b B B .     三个符号齐了，可以归约成 S      （归约状态）
    ```

    * 圆点左边是已经拿到手的符号，圆点右边是还欠着的符号；圆点位置就是句柄识别的进度条。

    * 移进状态欠一个终结符，待约状态欠一个非终结符，归约状态什么都不欠，因此可以动手归约。

## LR 分析器的结构与分析表

* **LR 自动机（LR automaton）**

    * LR 分析器也叫 LR 自动机，与移入-归约分析器结构大体相同：输入带、读头、带分析表的主控程序、符号栈。

    * 唯一区别是多出一个与符号栈平行的状态栈；两个栈深度始终一致，符号进栈则状态进栈，符号出栈则对应状态一起出栈。

    ```text
                  +---------------------------+
       输入串 --> |  输入缓冲区  b a b $      | --> 读头逐个读入
                  +---------------------------+
                              |
                              v
                  +---------------------------+       +---------------------+
                  |         主控程序          | <---> |       分析表        |
                  |      查 ACTION / GOTO     |       |   ACTION |  GOTO    |
                  +---------------------------+       +---------------------+
                        |            ^
              移进/弹栈 |            | 查表结果
                        v            |
                  +-----------+  +-----------+
                  |  符号栈   |  |  状态栈   |
                  |   $ b B   |  |   0 2 5   |
                  +-----------+  +-----------+
    ```

* **动作表（ACTION）**

    * 每行对应一个状态，每列对应文法的一个终结符及结束符 `$`，表项是一个语法分析动作。

    * 移进动作记作 $S_n$，$S$ 为 shift，把当前输入符号移进分析栈并进入状态 $n$，即把状态 $n$ 压入状态栈。

    * 归约动作记作 $r_n$，$r$ 为 reduce，用第 $n$ 个产生式进行归约。

    * 接收动作记作 `acc`，是 accept 的缩写，表示成功接收。

    * > **易错点**：$S_n$ 中的 $n$ 是状态号，$r_n$ 中的 $n$ 是产生式编号；两个 $n$ 写法相同、含义完全不同，查表时别串。

* **转移表（GOTO）**

    * 每列对应文法的一个非终结符，表项表示在某个状态遇到某个非终结符之后进入的后继状态。

    * 移进项只出现在终结符列，因为只有终结符才谈得上移进；GOTO 项只出现在非终结符列，因为只有归约出非终结符才需要转向。

## 分析表的驱动

### 走查实例

* **文法与分析表**

    * 增广文法为 $S' \to S,\ S \to BB,\ B \to aB,\ B \to b$；去掉增广产生式后三条产生式依次编号为 1、2、3。

    * 分析表共 0 到 6 号七个状态，ACTION 的列为 $a$、$b$、`$`，GOTO 的列为 $S$、$B$。

    | 状态 | `a` | `b` | `$` | `S` | `B` |
    | :--- | :--- | :--- | :--- | :--- | :--- |
    | 0 | $S_3$ | $S_4$ | | 1 | 2 |
    | 1 | | | acc | | |
    | 2 | $S_3$ | $S_4$ | | | 5 |
    | 3 | $S_3$ | $S_4$ | | | 6 |
    | 4 | $r_3$ | $r_3$ | $r_3$ | | |
    | 5 | $r_1$ | $r_1$ | $r_1$ | | |
    | 6 | $r_2$ | $r_2$ | $r_2$ | | |

    * 移进项只出现在终结符列；归约状态 4、5、6 那三行的 ACTION 部分整行都是同一个归约动作，这正是冲突的病根。

* **走查过程**

    * 初始：输入缓冲区为 `bab$`，状态栈为 `0`，符号栈为 `$`。

    | 步 | 状态栈 | 符号栈 | 剩余输入 | 查表与动作 |
    | :--- | :--- | :--- | :--- | :--- |
    | 1 | `0` | `$` | `bab$` | `ACTION[0,b] = S4`：b 进栈，转 4 |
    | 2 | `0 4` | `$ b` | `ab$` | `ACTION[4,a] = r3`：按 $B \to b$ 归约，b 出栈、B 进栈；`GOTO[0,B] = 2` |
    | 3 | `0 2` | `$ B` | `ab$` | `ACTION[2,a] = S3`：a 进栈，转 3 |
    | 4 | `0 2 3` | `$ B a` | `b$` | `ACTION[3,b] = S4`：b 进栈，转 4 |
    | 5 | `0 2 3 4` | `$ B a b` | `$` | `ACTION[4,$] = r3`：按 $B \to b$ 归约，b 出栈、B 进栈；`GOTO[3,B] = 6` |
    | 6 | `0 2 3 6` | `$ B a B` | `$` | `ACTION[6,$] = r2`：按 $B \to aB$ 归约，aB 出栈、B 进栈；`GOTO[2,B] = 5` |
    | 7 | `0 2 5` | `$ B B` | `$` | `ACTION[5,$] = r1`：按 $S \to BB$ 归约，BB 出栈、S 进栈；`GOTO[0,S] = 1` |
    | 8 | `0 1` | `$ S` | `$` | `ACTION[1,$] = acc`：接收 |

    * 第 2 步中 4 号状态遇 $a$ 走归约而不是移进：$a$ 还在输入缓冲区里等着，分析器先回头处理栈顶的 $b$，说明当前输入符号只用来查表，归约本身不消耗它。

    * 第 5 步归约 $B \to b$ 时同时弹出符号栈顶的 $b$ 与状态栈顶的 4，露出 3 号状态后再查 `GOTO[3,B]` 得 6。

    * 第 7 步产生式右部 $BB$ 有两个符号，符号栈弹两个、状态栈也弹两个，露出 0 号状态；归约出 $S$ 后查 `GOTO[0,S]` 得 1。

    * > **提示**：归约动作的输入符号不变；每次归约完先看新的栈顶状态，用 GOTO 转移，再拿原来那个输入符号继续查 ACTION。

### 格局变换

* **格局（configuration）**

    * 任意时刻的格局为 $(s_0 X_1 s_1 X_2 s_2 \cdots X_m s_m,\ a_i a_{i+1}\cdots a_n\$)$，左边栈中符号与状态交替、栈底 $s_0$、栈顶 $s_m$，右边为剩余输入，当前输入符号是 $a_i$。

    * 含义：输入串前 $i-1$ 个符号已经进栈分析过，从 $a_i$ 起尚未处理。

* **移进与归约的格局变换**

    * 移进：若 $\text{ACTION}[s_m,a_i]=s_x$，则

    $$(s_0\cdots s_m,\ a_i a_{i+1}\cdots a_n\$) \Rightarrow (s_0\cdots s_m a_i s_x,\ a_{i+1}\cdots a_n\$)$$

    * 移进的效果是符号栈多一个 $a_i$、状态栈多一个 $s_x$、输入指针右移一格。

    * 归约：若 $\text{ACTION}[s_m,a_i]=r_x$，第 $x$ 个产生式为 $A \to \beta$、右部长度为 $k$，则两栈各弹出 $k$ 项露出 $s_{m-k}$，压入 $A$，再查 $\text{GOTO}[s_{m-k},A]=y$ 压入 $y$。

    $$(s_0\cdots s_{m-k}\cdots s_m,\ a_i a_{i+1}\cdots) \Rightarrow (s_0\cdots s_{m-k} A y,\ a_i a_{i+1}\cdots)$$

    * 归约时输入串一个符号都没动，这是归约与移进最本质的区别：归约是把已经进栈的一串符号折叠成一个非终结符，只改变栈，不改变输入位置。

    * $\text{ACTION}[s_m,a_i]=\text{acc}$ 表示分析成功，$=\text{error}$ 表示出现语法错误。

    * > **注意**：弹出 $k$ 个符号的同时必须弹出 $k$ 个状态；只弹符号不弹状态会使栈顶状态与栈中符号对不上号，后续 GOTO 全错。

### 主控程序

* **输入与输出**

    * 输入为输入串 $w$ 与描述 ACTION、GOTO 的 LR 分析表；输出为 $w$ 的归约步骤或错误提示。

    * 初始化：状态栈置 $[s_0]$、符号栈置 `[$]`、输入缓冲区置 `w$`、当前输入符号取第一个符号。

* **循环分支**

    * 取栈顶状态 $s$ 查 $\text{ACTION}[s,a]$：shift 分支压符号与状态并读下一个符号；reduce 分支按产生式弹栈、查 GOTO 压状态、输出所用产生式；acc 分支成功退出；error 分支调用错误恢复例程。

    * 主控程序只有几条分支，LR 分析的难点不在驱动而在分析表的构造；不同 LR 分析法的区别都在「归约时允许看多少上下文」。

## LR(0) 项目与增广文法

* **LR(0) 项目（LR(0) item）**

    * > **定义**：右部某个位置标有圆点的产生式，称为相应文法的一个 LR(0) 项目，一般形式为 $A \to \alpha_1 \cdot \alpha_2$。

    * 右部有 $k$ 个符号的产生式对应 $k+1$ 个项目；空产生式只有一个项目 $A \to \cdot$，因为圆点最左即最右。

    * 圆点后是终结符的项目为移进项目，看到这个终结符就把它移进来。

    * 圆点后是非终结符的项目为待约项目，得先把这个非终结符归约出来。

    * 圆点在右部末尾的项目为归约项目，右部已经齐了，可以用这条产生式归约。

    * > **提示**：项目不是产生式的一部分，而是「产生式加一个进度标记」；同一条产生式的不同项目描述同一条规则在不同识别阶段的样子。

* **增广文法（augmented grammar）**

    * > **定义**：设 $G$ 是以 $S$ 为开始符号的文法，在 $G$ 中加入新的开始符号 $S'$ 和产生式 $S' \to S$ 所得到的文法 $G'$ 称为 $G$ 的增广文法。

    * 增广前后描述同一个语言、两者等价，$S' \to S$ 只是套在门口的一层壳，不改变任何句子的归属。

    * 目的是让开始符号只出现在一个产生式的左部，从而保证分析器只有一个接收状态。

    * 开始符号若出现在多个产生式左部，就可能在好几处归约出开始符号，接收状态不唯一，分析器不知道该在哪儿停。

* **初始项目与接收项目**

    * $S' \to \cdot S$ 是初始项目：初始时刻期待识别出文法开始符号 $S$。

    * $S' \to S \cdot$ 是接收项目：开始符号已经归约出来，可以接收；它是唯一「可以收工」的项目，只可能出现在一个项目集里。

    * 其余圆点落在右部末尾的项目统称归约项目。

## 项目集闭包与 LR(0) 自动机

* **等价项目**

    * 项目中圆点后面是非终结符时存在等价项目：等待这个非终结符，等价于等待它所有产生式的开头。

    * 圆点后面是终结符的项目没有这层展开，等价类只有它自己。

    * 以增广文法 $S' \to S,\ S \to vI{:}T,\ I \to I{,}i,\ I \to i,\ T \to r$ 为例，把每条产生式的项目都写出来共十五个；闭包的作用就是把这些项目并成少数状态。

    * 例：$S \to v\cdot I{:}T$、$I \to \cdot I{,}i$、$I \to \cdot i$ 三个项目等价，下一步都盯着 $I$ 的首符。

* **项目集闭包（item set closure）**

    * > **定义**：把所有等价的项目组成一个项目集合 $I$，该集合称为项目集闭包；每个项目集闭包对应自动机的一个状态。

    * 闭包把「下一步盯同一个符号」的项目并进同一个状态，避免项目数直接变成状态数导致自动机与表膨胀；闭包里的项目共享同一个进度。

    * CLOSURE 算法：$J \leftarrow I$；对 $J$ 中每个 $A \to \alpha \cdot B\beta$ 与每条 $B \to \gamma$，若 $B \to \cdot\gamma$ 不在 $J$ 中则加入；重复到没有新项目加入。

    * 数学形式是求最小不动点：

    $$\text{CLOSURE}(I) = I \cup \{\, B \to \cdot\gamma \mid A \to \alpha \cdot B\beta \in \text{CLOSURE}(I),\ B \to \gamma \in P \,\}$$

    * 「重复到没有新项加入」不能省：新加入的项目圆点后可能又是非终结符，需要一层层展开。

* **GOTO 函数**

    * > **定义**：$\text{GOTO}(I,X)$ 返回项目集 $I$ 对文法符号 $X$ 的后继项目集闭包。

    * 算法：$J$ 置空；对 $I$ 中每个圆点后为 $X$ 的项目 $A \to \alpha \cdot X\beta$，把 $A \to \alpha X \cdot \beta$ 加入 $J$；返回 $\text{CLOSURE}(J)$。

    * 最后一步必须求闭包：圆点右移后可能又出现非终结符，不重新求闭包拿到的不是完整状态。

* **规范 LR(0) 项目集族（canonical LR(0) collection）**

    * 从 $C=\{\text{CLOSURE}(\{S' \to \cdot S\})\}$ 出发；对 $C$ 中每个项目集 $I$ 与每个文法符号 $X$，若 $\text{GOTO}(I,X)$ 非空且不在 $C$ 中则加入；重复到不再产生新项目集。

    * 以 $S' \to S,\ S \to BB,\ B \to aB,\ B \to b$ 为例，逐个项目集为：

    ```text
    I0 { S' -> . S,  S -> . B B,  B -> . a B,  B -> . b }
    I1 { S' -> S . }                                  接收
    I2 { S -> B . B,  B -> . a B,  B -> . b }
    I3 { B -> a . B,  B -> . a B,  B -> . b }
    I4 { B -> b . }                                   归约
    I5 { S -> B B . }                                 归约
    I6 { B -> a B . }                                 归约
    ```

    * 转移关系：$I_0$ 遇 $S,B,a,b$ 分别进 $I_1,I_2,I_3,I_4$；$I_2$ 遇 $B$ 进 $I_5$、遇 $a,b$ 进 $I_3,I_4$；$I_3$ 遇 $B$ 进 $I_6$、遇 $a$ 回到自己、遇 $b$ 进 $I_4$。

    * $I_1$ 是接收状态，$I_4$、$I_5$、$I_6$ 是归约状态且都没有出边。

    * $I_3$ 遇 $a$ 的自环，是 $B \to a\cdot B$ 还想再套一层 $aB$ 的表现，也就是右递归结构在自动机上的形态。

* **LR(0) 自动机五元组**

    * $M=(C,\ V_N \cup V_T,\ \text{GOTO},\ I_0,\ \{I_{acc}\})$。

    * 状态集为规范 LR(0) 项目集族 $C$，符号表为 $V_N \cup V_T$，转换函数为 GOTO。

    * 初始状态 $I_0=\text{CLOSURE}(\{S' \to \cdot S\})$，终止状态集合只有一个元素 $\text{CLOSURE}(\{S' \to S \cdot\})$。

    * 终止状态集合能写成单元素集合，前提是接收项目唯一，这正是需要增广的原因。

## LR(0) 分析表的构造与冲突

* **填表规则**

    * 先构造增广文法的规范 LR(0) 项目集族 $C$，令第 $i$ 个项目集对应状态 $i$。

    * 移进：状态 $i$ 含 $A \to \alpha \cdot a\beta$，且 $i$ 对 $a$ 的后继状态为 $j$，则 $\text{ACTION}[i,a]=sj$。

    * 归约：状态 $i$ 含 $A \to \alpha \cdot$ 且 $A \ne S'$，则对每一个终结符及 `$` 都填 $\text{ACTION}[i,a]=rj$，$j$ 是产生式 $A \to \alpha$ 的编号。

    * 接收：状态 $i$ 含 $S' \to S \cdot$，则 $\text{ACTION}[i,\$]=\text{acc}$。

    * 三条规则未定义的条目一律留空。

    * > **注意**：归约规则中的「每一个终结符及 `$`」是关键——LR(0) 归约时不看任何输入符号，归约项目一旦落进某状态，该状态对所有输入都归约，表上就是整行 $rj$；这条规则的霸道正是冲突的来源。

* **移进-归约冲突**

    * 算术表达式文法的 LR(0) 自动机状态 2 同时含归约项目 $E \to T \cdot$ 与圆点后为 $*$ 的移进项目。

    * 输入符号为 $*$ 时，归约项目要求把栈顶 $T$ 归约成 $E$，移进项目要求把 $*$ 移进并转入状态 7，一个格子填不进两个动作。

    * 状态 9 存在同样的冲突。

* **归约-归约冲突**

    * 某文法的 LR(0) 自动机第二个状态含两个空产生式归约项目，一个要把栈顶空串归约成 $B$，一个要归约成 $T$，两者圆点都在末尾、都不受输入符号限制。

    * 遇输入时无法决定归约成 $B$ 还是 $T$，这就是归约-归约冲突。

    * 该状态还夹着一个移进项目，它与两个归约项目各自冲突，属于移进-归约与归约-归约混合的状态。

* **LR(0) 文法**

    * > **定义**：如果 LR(0) 分析表中没有语法分析动作冲突，该文法称为 LR(0) 文法。

    * 上下文无关文法不总是 LR(0) 文法；算术表达式这种常见结构 LR(0) 就处理不了。

    * 消解冲突有两条路子：给归约加条件、别让它见谁都归约（SLR 用 FOLLOW 集）；让项目自己带上上下文信息、把「什么情况下才允许归约」记进项目（LR(1) 用展望符）。

## SLR(1) 分析法

* **基本思想**

    * LR(0) 构造项目时向前查看了 0 个符号，没有考虑文法符号的上下文环境，只知道「右部已经凑齐」，不知道「凑齐」与「该归约」之间还差一个条件：归约出的非终结符后面接的东西得说得通。

    * 该条件可用 FOLLOW 集表达：若把栈顶 $T$ 归约成 $E$ 后 $E$ 后面紧跟着 $*$，而 $* \notin \mathrm{FOLLOW}(E)$，说明硬归约出的 $E$ 在此处根本不该出现，$T$ 不是句柄。

    * FOLLOW 集能告诉我们哪些情况下不应该归约，这就是 SLR 分析法的基本思想。

    * 只需向前查看一个符号就能确定是否归约、如何归约，故称 SLR(1) 分析法；按 $k=1$ 省略 1 的约定也叫 SLR 分析法，S 表示 simple。

    * > **提示**：SLR 的闸门加在归约一侧——移进照旧，归约要先验票，票就是 FOLLOW 集；移进项目本身没有加任何限制。

* **冲突可解的充分条件**

    * 项目集 $I$ 含 $m$ 个移进项目 $A_1 \to \alpha_1 \cdot a_1\beta_1,\ \dots,\ A_m \to \alpha_m \cdot a_m\beta_m$ 与 $n$ 个归约项目 $B_1 \to \gamma_1 \cdot,\ \dots,\ B_n \to \gamma_n \cdot$。

    * 若 $n$ 个 $\mathrm{FOLLOW}(B_i)$ 两两互不相交，且它们与 $\{a_1,\dots,a_m\}$ 也互不相交，则冲突可解。

    * 下一个输入符号 $a$ 属于 $\{a_1,\dots,a_m\}$ 时移进；属于某个 $\mathrm{FOLLOW}(B_i)$ 时用 $B_i \to \gamma_i$ 归约；两者都不是则报错。

    * 因为 $n+1$ 个集合两两不交，$a$ 最多落进其中一个集合，最多触发一个动作，动作唯一，冲突消失。

* **SLR 表与 LR(0) 表的差别**

    | 比较项 | LR(0) 分析表 | SLR 分析表 |
    | :--- | :--- | :--- |
    | 归约状态遇输入符号 | 任何符号都归约，整行 $rj$ | 只有落在 FOLLOW 集里的符号才归约 |
    | 归约依据 | 只看栈顶是否凑齐产生式右部 | 凑齐右部，且输入符号在左部非终结符的 FOLLOW 集里 |
    | 冲突状态 | 无法区分，直接冲突 | 乘号不在 FOLLOW 集，冲突消解 |

    * 构造算法与 LR(0) 几乎相同，唯一不同在归约项目：LR(0) 对任何输入符号都填归约，SLR 只对 FOLLOW 集中的符号填归约。

    * 算术表达式文法的状态 2 遇乘号时，因 $* \notin \mathrm{FOLLOW}(E)$ 不能归约，只能移进；状态 9 同理。

    * 归约-归约冲突的例子：$B$ 的 FOLLOW 集只有 $d$，$T$ 的 FOLLOW 集为 $\{\$,\,b\}$；状态 2 遇 $d$ 用第 4 个产生式归约成 $B$，遇 $b$ 或 `$` 用第 2 个产生式归约成 $T$，遇 $a$ 移进，三组符号各归各的。

* **SLR 文法**

    * > **定义**：如果给定文法的 SLR 分析表中不存在有冲突的动作，该文法称为 SLR 文法。

* **FOLLOW 集救不了的冲突**

    * $b \in \mathrm{FOLLOW}(A)$ 只是把 $\alpha$ 归约成 $A$ 的必要条件，不是充分条件：在 FOLLOW 集里推不出这一次就该归约。

    * 同一非终结符在不同位置出现时，后继符集合不同：$L \to *R$ 里的 $R$ 后接等号，$S \to L=R$ 里的 $R$ 后只能接 `$`，两个位置的后继符集分别是 $\{=\}$ 与 $\{\$\}$，都只是 $\mathrm{FOLLOW}(R)=\{=,\$\}$ 的真子集。

    * 赋值语句文法的 SLR 自动机状态 2 含圆点后为等号的移进项目与归约项目 $R \to L \cdot$，而等号既在移进集合里，又落在 $\mathrm{FOLLOW}(R)$ 里。

    * 遇等号时一个项目要求移进、另一个要求归约，移进-归约冲突照样出现。

    * 根源是 FOLLOW 集为全局信息：它统计该非终结符在整个文法里所有可能的后继符号，把不属于当前归约位置的符号也算了进来，条件放得太宽，闸门关不严。

    * 从 LR(0) 到 SLR 再到 LR(1)，一路加的都是同一件东西：给归约多带一点上下文信息，让「该不该归约」这个判断越来越准。

## LR(1) 分析法

* **LR(1) 项（LR(1) item）**

    * > **定义**：形如 $[A \to \alpha \cdot \beta,\ a]$ 的项称为 LR(1) 项，$A \to \alpha\beta$ 是产生式，$a$ 是终结符（`$` 也算特殊终结符），称为这个项的展望符。

    * 名字里的 1 指第二个分量的长度为 1；理论上可向前看 $k$ 个符号、第二个分量为长度 $k$ 的串，多数程序设计语言 $k=1$ 足够。

    * 展望符只在归约项目 $[A \to \alpha \cdot,\ a]$ 上起作用：只有下一个输入符号正好等于 $a$，才允许用 $A \to \alpha$ 归约。

    * 移进项目与待约项目的展望符闲着：移进与否看圆点后那个符号，闭包是否展开看圆点后是否非终结符，都轮不到后继符说话。

    * 某项目上挂的展望符集合总是 $\mathrm{FOLLOW}(A)$ 的子集，通常还是真子集。

* **展望符的传递**

    * 对 $[A \to \alpha \cdot B\beta,\ a]$ 与产生式 $B \to \gamma$，等价项目是 $[B \to \cdot\gamma,\ b]$，其中 $b \in \mathrm{FIRST}(\beta a)$。

    * $\beta$ 推不出空串时，$b$ 来自 $\mathrm{FIRST}(\beta)$，称自生的后继符。

    * $\beta$ 可以空掉时，$a$ 直接落到 $B$ 后面，$b=a$，称继承的后继符。

    * > **提示**：自生与继承可以同时出现；若 $\beta$ 既可空、首符集又非空，闭包中两样都要收进去。

* **LR(1) 自动机与表的构造**

    * 三处改动：CLOSURE 中等价项目的展望符取 $\mathrm{FIRST}(\beta a)$ 中每个符号；GOTO 先把圆点右移一位、展望符原样带着，再对新项目集求闭包；规范项集族从 $[S' \to \cdot S,\ \$]$ 出发反复迭代到不再产生新项目集。

    * 分析表构造与 LR(0)、SLR 的唯一不同仍在归约项目：状态 $i$ 含 $[A \to \alpha \cdot,\ a]$ 时，只在 $a$ 这一列填归约。

    * $I_0$ 从 $[S' \to \cdot S,\ \$]$ 起手，$S'$ 后面只能跟 `$`；展开 $S$ 得 $[S \to \cdot L=R,\ \$]$ 与 $[S \to \cdot R,\ \$]$，再展开 $L$ 得 `[L → ·*R, =]`、`[L → ·id, =]`，展开 $R$ 又得 `[R → ·L, $]` 及另一组 `[L → ·*R, $]`、`[L → ·id, $]`。

    * $I_0$ 中 `[L → ·*R]` 出现两次，一次展望符是等号、一次是 `$`；LR(0) 里它们是同一个项目，LR(1) 里成了两条不同的项，这是后续状态分裂的种子。

    * 两处自环：$I_4$ 遇 `*` 回到 $I_4$、$I_{11}$ 遇 `*` 回到 $I_{11}$；$I_{10}$ 同时是 $I_6$ 和 $I_{11}$ 在 $L$ 上的后继。

    * 状态 2 含 $S \to L \cdot =R$ 与 $R \to L \cdot$：遇等号移进进入状态 6，遇 `$` 才归约成 $R$；SLR 中「遇等号是移还是归」的冲突在这里不存在，归约开关从整个 $\mathrm{FOLLOW}(R)$ 收窄为单个 `$`。

    * 五个归约动作：r1 归约 $S \to L=R$、r2 归约 $S \to R$、r3 归约 $L \to *R$、r4 归约 $L \to id$、r5 归约 $R \to L$。

    * 状态 10、12、13 的归约只在 `$` 上有效，遇等号一律报错：从 $I_0$ 走到这三个状态的路径必跨过一条标等号的边，而该文法中 $L$、$R$ 自己都推不出等号、句子里等号最多出现一次，进入这些状态时等号已经用掉，再读到等号句子一定已错。

    * 状态 2 强行归约的后果：$R \to L$ 出栈露出状态 0，$\text{GOTO}(0,R)=3$；$S \to R$ 出栈露出状态 0，$\text{GOTO}(0,S)=1$；状态 1 只接受 `$`，此刻输入是等号，仍旧出错，错误只是晚几步暴露。

* **LR(1) 文法**

    * > **定义**：若按上述办法构造出的 LR(1) 分析表中没有语法分析动作冲突，该文法称为 LR(1) 文法。

    * 代价是状态数：同一文法的 SLR 自动机 10 个状态，LR(1) 为 14 个；像 C 这样的语言，LR(0) 分析表通常几百个状态，换成 LR(1) 就是几千个。

## 同心项目集与 LALR(1) 分析法

* **同心项目集（sets with the same core）**

    * > **定义**：如果两个 LR(1) 项目集除展望符以外完全相同，就称它们是同心的；第一分量的集合相同即为同心，这个第一分量的集合本身是一个 LR(0) 项目集，所以「心」指 LR(0) 项目集。

    * $I_8$ 的项目是 `R→L·, {=, $}`，$I_{10}$ 是 `R→L·, $`，第一分量一模一样，只差展望符。

    * 该自动机有四对同心集：$I_8$ 与 $I_{10}$、$I_4$ 与 $I_{11}$、$I_5$ 与 $I_{12}$、$I_7$ 与 $I_{13}$。

    * LR(1) 比 SLR 多的四个状态，正是这四对没有合并的结果。

* **LALR 的合并**

    * > **定义**：寻找具有相同核的 LR(1) 项目集，把它们合并成一个项目集，再按合并后的项目集族构造分析表，这就是 LALR 分析法的基本思想；合并后展望符取各家的并集。若分析表没有动作冲突，该文法称为 LALR 文法。

    * $I_8$ 与 $I_{10}$ 归约的是同一条产生式 $R \to L$，不是把 $L$ 归约成别的非终结符，合并后动作不冲突；其余三对同理。

    * $I_8+I_{10}$ 合成 $I_8$、$I_4+I_{11}$ 合成 $I_4$、$I_5+I_{12}$ 合成 $I_5$、$I_7+I_{13}$ 合成 $I_7$，合并后的展望符都变成 `{=, $}`。

    * 边跟着重定向：指向 $I_{10}$、$I_{11}$、$I_{12}$、$I_{13}$ 的边分别改指 $I_8$、$I_4$、$I_5$、$I_7$；四个状态整块删除，自动机回到 10 个状态。

    * 表上变化都在「进哪个状态」：状态 6 遇 `*` 原来进 11、现在进 4，遇 `id` 原来进 12、现在进 5，遇 $L$ 进 8；状态 11 原来那一行整块消失。

* **合并可能造出归约-归约冲突**

    * 两个状态的核都是 `A→c·` 与 `B→c·`，展望符正好错开：$I_6$ 遇 `d` 归约 $A \to c$、遇 `e` 归约 $B \to c$，$I_9$ 遇 `d` 归约 $B \to c$、遇 `e` 归约 $A \to c$。

    * 合并后展望符并成 `{d, e}`，两个状态都挂上 `A→c·` 与 `B→c·`：遇 `d` 归约成 $A$ 与归约成 $B$ 都合法，遇 `e` 也一样，形成归约-归约冲突。

    * 合并同心集只会造出归约-归约冲突，不会造出移进-归约冲突：合并只动各对应项的展望符集合，而展望符只在归约时起作用，移进动作根本不看它。

* **合并的代价：错误发现推迟**

    * 文法 $S \to AcA$、$A \to aA \mid d$，$A$ 生成若干个 $a$ 后接一个 $d$，句子形如 $a^*d\,c\,a^*d$，中间必定有一个 $c$。

    * 自动机结构左右对称：$c$ 之前一半识别前一个 $a^*d$、展望符为 $c$，$c$ 之后一半识别后一个 $a^*d$、展望符为 `$`；两半中间的 $I_4$ 与 $I_9$、$I_6$ 与 $I_{10}$ 同心且动作不冲突。

    * 输入 `d $` 缺少中间的 $c$：合并前 $I_4$ 只在 $c$ 上有条目，遇 `$` 当场报错。

    * 合并后 $I_4$ 的展望符为 `{c, $}`，遇 `$` 也归约成 $A$，$d$ 与状态 4 出栈露出状态 0，$\text{GOTO}(0,A)$ 进 $I_2$，直到 $I_2$ 遇 `$` 无条目才报错，晚了两步。

    * 推迟的是归约而不是移进：LALR 可能多做几次多余的归约，但绝不会把错误的符号移进栈，错误一定在下一个输入符号被移进之前暴露。

* **LALR 的定位**

    * 形式上与 LR(1) 自动机一样使用 LR(1) 项目、展望符照挂。

    * 大小上与 LR(0) 自动机相当：同心集的心就是 LR(0) 项目集，合并后状态数与 LR(0) 一个量级，而 LR(0) 与 SLR 的自动机大小本来就相同。

    * 分析能力夹在 SLR 与 LR(1) 之间：合并会延迟一部分错误的发现，所以比 LR(1) 弱；对信息的划分比 SLR 细、延迟发现的错误比 SLR 少，所以比 SLR 强。

    * 合并后的展望符集合仍然是 FOLLOW 集的子集。

    | 分析技术 | 归约判据 | 状态规模 | 分析能力 |
    | :--- | :--- | :--- | :--- |
    | LR(0) | 任何输入符号都归约 | 基准 | 最弱 |
    | SLR | $\mathrm{FOLLOW}(A)$ | 与 LR(0) 相同 | 强于 LR(0) |
    | LALR | 合并后的展望符集合 | 与 LR(0) 相当 | 介于 SLR 与 LR(1) 之间 |
    | LR(1) | 单个展望符 $a$ | 数倍于 LR(0) | 最强 |

## 二义性文法的 LR 分析

* **二义性文法与 LR 的关系**

    * 任何一个二义性文法都不是 LR 的：拿它构造 LR 分析表，一定会在某个状态撞上动作冲突，这是二义性带来的必然结果。

    * 这不等于二义性文法不能用：某些二义性文法特征很好，比等价的非二义性文法更简短、更自然。

    * 实际做法是文法照二义性写，冲突留到构造分析表时用额外信息裁掉。

* **算术表达式：用优先级与结合性裁决**

    * 二义性写法为 $E \to E+E \mid E*E \mid (E) \mid \mathrm{id}$，四条产生式；消除二义性要引入新非终结符分出优先级与结合性层次，产生式变多，LR 状态数也跟着变多。

    * 冲突出在两个状态：一个代表栈顶已是 $E+E$，一个代表栈顶已是 $E \times E$；遇加号或乘号时归约与移进都成立，是移进-归约冲突。

    * 栈顶为 $E+E$：来乘号则乘法优先级高于加法，应先把乘法算出来，移进乘号；来加号则加法左结合，应先算栈里这个加法，归约。

    * 栈顶为 $E \times E$：乘法优先级最高，来加号则加法优先级低、先算栈里的乘法；来乘号则同优先级下乘法左结合、仍先算栈里的乘法，一律归约。

    * 两个冲突靠优先级加结合性两条语言层面的约定裁干净，得到的 SLR 分析表可以直接使用。

* **悬空 else：就近匹配**

    * 把 `if expression then` 记作 $i$、`else` 记作 $e$、其它产生式记作 $a$，文法写作 $S \to iSeS \mid iS \mid a$。

    * LR(0) 自动机中有一个状态同时装着两种可能：`iS` 已经可以归约，后面还允许再接 `eS`；遇 $e$ 时既可归约也可移进，冲突就在这里。

    * 消解办法是就近匹配：遇 $e$ 就移进，让这个 `else` 与前面离它最近的那个 `if` 配对。

    * > **注意**：二义性文法必须严格控制使用；冲突裁错一次，分析器识别的语言就会与预期不符。

## 语法错误的检测与恢复

* **错误检测**

    * LR 分析器查分析表，查到报错条目，就说明检测到一个语法错误。

    * 恢复的常用路子有两条：恐慌模式与短语层次。

* **恐慌模式（panic mode）**

    * 从栈顶向下扫描，直到找到某个状态 $S_i$ 对某个非终结符 $A$ 有后继状态，即 $\mathrm{goto}(S_i,A)$ 存在，认为从 $A$ 推导出的串里含着错误。

    * 丢弃零个或多个输入符号，直到遇到一个可能合法地跟在 $A$ 后面的符号 $a$，即 $a \in \mathrm{FOLLOW}(A)$。

    * 把 $\mathrm{goto}(S_i,A)=S_{i+1}$ 压进栈。

    * 此时下一个输入符号 $a$ 能合法跟在 $A$ 后面，正常分析可以接着做。

    ```text
    [栈]    …  S_i  S_j  …  栈顶
      ↓  弹栈，直到 S_i 有 goto(S_i, A)
    [输入]  …  b  a  …
      ↓  丢弃 b 等符号，直到 a ∈ FOLLOW(A)
    [恢复]  压入 goto(S_i, A) = S_{i+1}
      ↓  下一个符号 a 可以合法跟在 A 之后
    [继续]  正常分析
    ```

* **短语层次恢复**

    * 逐个检查 LR 分析表中的报错条目，结合语言的实际用法，判断哪种程序员错误最可能触发该条目，为它写一段专门的恢复过程。

    * 不是通用的机械流程，需针对具体文法手工设计；针对性强，诊断信息能直接说到点子上。

* **算术表达式分析器的四个错误例程**

    | 状态 | 在读什么 | 读到的符号 | 动作 | 诊断信息 |
    | :--- | :--- | :--- | :--- | :--- |
    | $I_0$ 及同类的 $I_2$、$I_4$、$I_5$ | 运算分量的首符 | `+`、`*`、`$` | error 1：压入状态 3 | 缺少运算分量 |
    | 同上 | | `)` | error 2：丢弃 `)` | 不匹配的右括号 |
    | $I_1$ | `$` 或运算符 | `(`、`id` | error 3：压入状态 4 | 缺少运算符 |
    | $I_1$ | | `)` | error 2：丢弃 `)` | 不匹配的右括号 |
    | $I_6$（栈顶 `( E`） | `)` 或运算符 | `(`、`id` | error 3：压入状态 4 | 缺少运算符 |
    | $I_6$ | | `$` | error 4：压入状态 9 | 缺少右括号 |
    | $I_3$、$I_7$、$I_8$、$I_9$ | 含归约项目 | 非法符号 | 先归约 | 延迟发现 |

    * error 1 压入状态 3，正是 $I_0$ 读入 `id` 之后进入的后继状态，等于替程序员补上一个运算分量。

    * error 2 把右括号从输入里删掉，继续分析。

    * error 3 压入状态 4，即状态 1 读入加号之后进入的后继状态，等于补上一个运算符，补进去的运算符按加号算。

    * error 4 压入状态 9，即状态 6 读入右括号之后进入的后继状态，等于补上一个右括号。

    * 含归约项目的状态遇非法符号不报错、先执行归约：归约不会把非法符号移进栈，所以错误一定在任何一个移进动作之前被发现。

    * 带上例程后，LR(0) 分析表所有空白格不再一律是「报错」，而是填上相应错误处理例程的指针，一次编译能把程序员的错尽量多地报出来。
