[听音转录 · P50 6-8布尔表达式的回填]
> 来源：**听音转录**——非平台字幕，由讲师原声转录

同学们好，下面我们来学习布尔表达式的回填。

在为布尔表达式和控制流语句生成中间代码的时候，关键的问题是确定跳转指令的目标标号。在生成跳转指令的时候，目标标号还不能确定，那么在我们前面介绍的翻译方案中，解决这一问题的方法就是将存放标号的地址作为继承属性传递到跳转指令生成的地方。但是这样做需要再进行一趟处理，将标号同具体的地址绑定起来。

在这一部分，我们将介绍一种称为回填的技术。它把一个由跳转指令组成的列表以综合属性的形式进行传递。具体来说，生成一个跳转指令时，暂时不指定该跳转指令的目标标号。这样的指令都被放入由跳转指令组成的列表中。同一个列表中的所有跳转指令具有相同的目标标号，等到能够确定正确的目标标号时，才去填充这些指令的目标标号。

我们首先来介绍布尔表达式的回填。因此，我们为非终结符 $B$ 设置两个综合属性，一个是 $B\text{.truelist}$，一个是 $B\text{.falselist}$。$B\text{.truelist}$ 指向一个包含跳转指令的列表，这些指令最终获得的目标标号就是当 $B$ 为真时控制流应该转向的指令的标号。类似地，$B\text{.falselist}$ 指向一个包含跳转指令的列表，这些指令最终获得的目标标号是当 $B$ 为假时控制流应该转向的指令的标号。

为了处理跳转指令的列表，我们构造三个函数：
第一个函数是 makelist 函数，它的参数 $i$ 是一个跳转指令的标号。这个函数创建一个只包含标号 $i$ 的列表，函数返回指向新创建的列表的指针。
merge 函数，它的两个参数 $p_1$、$p_2$ 是指向两个列表的指针。这个函数将 $p_1$ 和 $p_2$ 指向的列表进行合并，返回指向合并后的列表的指针。
第三个函数是 backpatch 函数，也就是回填函数。它的第一个参数 $p$ 是一个列表的指针，第二个参数 $i$ 是一个目标标号。这个函数将 $i$ 作为目标标号插入到 $p$ 所指列表中的各指令中。

那么我们先来看一下布尔表达式的回填。首先来看当 $B$ 定义为一个关系表达式的时候，这个布尔表达式将被翻译成两条跳转指令。第一条跳转指令是：如果 $E_1$ 与 $E_2$ 满足这个关系，那么跳转到一个目标标号，这个时候这个目标标号并不填写。第二条指令是一个无条件跳转指令，跳转的目标标号也不填写。

因为这两个跳转指令的目标标号等待回填，因此我们要把它们放到相应的列表中。第一条跳转指令，它的目标标号是 $B$ 的真出口，因此我们把它放到 $B\text{.truelist}$ 中。这里调用 makelist 函数生成一个只包含 nextcode 的列表，并把这个列表的指针赋给 $B\text{.truelist}$。这里 nextcode 是即将生成的下一条指令的标号，在这里也就是这条指令的标号。那么第二条跳转指令，它的目标标号是 $B$ 的假出口，因此需要把这条跳转指令放到 $B\text{.falselist}$ 中。因此我们调用 makelist 函数生成一个只包含 $\text{nextcode} + 1$ 这样一个标号的列表，这里 $\text{nextcode} + 1$ 这个标号就是这条指令的标号。这样的话，我们就将这两条指令分别放入 $B\text{.truelist}$ 中和 $B\text{.falselist}$ 中。

我们来看下一个产生式，当 $B$ 定义为 true 的时候，这个时候可以确定布尔表达式的值为真，生成一条跳转到 $B$ 的真出口的指令。由于这个真出口的标号目前不能确定，所以有待回填，我们把它放入到 $B\text{.truelist}$ 中。

对于产生式 $B$ 定义为 false，可以确定这个布尔表达式的值为 false，这个时候生成一条跳转到 $B$ 的假出口的跳转指令。但是这个假出口的标号目前还不能确定，因此把这条跳转指令放入到 $B\text{.falselist}$ 中。

对于产生式 $B$ 定义为括号 $B_1$，对 $B$ 的翻译与对它的子表达式 $B_1$ 的翻译是相同的，因此 $B$ 的属性值等于 $B_1$ 的属性值。

对于产生式 $B$ 定义为 $\text{not } B_1$，那么 $B$ 的值与 $B_1$ 的值正好相反，因此将两个非终结符的属性进行对调。

下面我们来看产生式 $B$ 定义为 $B_1 \text{ or } B_2$。我们先来看一下翻译方案的示意图。我们说 $B_1\text{.truelist}$ 中的这些指令都要跳转到 $B_1$ 的真出口。当 $B_1$ 为真的时候，整个表达式的值就是真的，因此 $B_1$ 的真出口就是 $B$ 的真出口。要跳转到 $B_1$ 的真出口，就是要跳转到 $B$ 的真出口，因此 $B_1\text{.truelist}$ 中的这些指令都要放入到 $B\text{.truelist}$ 中。同理，$B_2\text{.truelist}$ 中的这些指令都要跳转到 $B_2$ 的真出口。当 $B_2$ 为真的时候，整个表达式的值也为真，因此 $B_2$ 的真出口就是 $B$ 的真出口。要跳转到 $B_2$ 的真出口，就是要跳转到 $B$ 的真出口，因此 $B_2\text{.truelist}$ 中的指令都应该放入到 $B\text{.truelist}$ 中。

我们再来看 $B_1\text{.falselist}$ 中的指令，它们都是要跳转到 $B_1$ 的假出口。当 $B_1$ 的值为假的时候，我们要进一步判断 $B_2$ 的值，因此 $B_1$ 的假出口就是 $B_2$ 的第一条指令。因此，$B_1\text{.falselist}$ 中的这些指令都要跳转到 $B_2$ 的第一条指令。

$B_2\text{.falselist}$ 中的指令都要跳转到 $B_2$ 的假出口。当 $B_2$ 的值也是假的时候，那么整个布尔表达式的值也是假的，因此 $B_2$ 的假出口就是 $B$ 的假出口。要跳转到 $B_2$ 的假出口，就是要跳转到 $B$ 的假出口，因此 $B_2\text{.falselist}$ 中的所有的指令都要放入到 $B\text{.falselist}$ 中。

根据这个示意图我们可以看出，在分析 $B_2$ 之前，我们需要用 $B_2$ 的第一条指令的标号来回填 $B_1\text{.falselist}$ 中的各条指令。当然，我们也可以记录下 $B_2$ 的第一条指令的标号，然后再规约的时候完成这个回填的动作。为了记下 $B_2$ 的第一条指令的标号，我们在非终结符 $B_2$ 之前插入一个标记非终结符 $M$。与 $M$ 关联的语义动作，它的任务就是记录下 $B_2$ 的第一条指令的标号。我们给 $M$ 设置一个综合属性 code，也就是说 $M\text{.code} = \text{nextcode}$，也就是说 $M\text{.code}$ 等于下一条指令的标号。因为我们把 $M$ 放在了 $B_2$ 之前，因此 $M\text{.code}$ 记录的就是 $B_2$ 的第一条指令的标号。

接下来，根据这个翻译方案的示意图，我们要用 $M\text{.code}$ 来回填 $B_1\text{.falselist}$ 中的各条指令，因此我们先调用 backpatch 函数，用 $M\text{.code}$ 来回填 $B_1$ 的 falselist 中的各条指令。接下来这个语义动作还要计算 $B$ 的两个综合属性 $B\text{.truelist}$ 和 $B\text{.falselist}$。根据这个示意图可以看出，$B\text{.truelist}$ 是由 $B_1\text{.truelist}$ 和 $B_2\text{.truelist}$ 合并而成的，因此我们调用 merge 函数将 $B_1\text{.truelist}$ 和 $B_2\text{.truelist}$ 进行合并，将合并后的列表指针赋给 $B\text{.truelist}$。根据这个翻译方案示意图可以看出，$B\text{.falselist}$ 就等于 $B_2\text{.falselist}$。

好，下面我们来看 $B$ 定义为 $B_1 \text{ and } B_2$。我们来画出它的翻译方案示意图。$B_1\text{.truelist}$ 中的所有的指令，它跳转的目标标号是 $B_1$ 的真出口。当 $B_1$ 的值为真的时候，我们要进一步判断 $B_2$ 的值，因此 $B_1$ 的真出口是 $B_2$ 的第一条指令。

$B_1\text{.falselist}$ 中的所有指令，它们都要跳转到 $B_1$ 的假出口。当 $B_1$ 的值为假的时候，整个表达式 $B$ 的值就为假，因此 $B_1$ 的假出口就是 $B$ 的假出口。要跳转到 $B_1$ 的假出口，就是要跳转到 $B$ 的假出口，因此 $B_1\text{.falselist}$ 中的指令都要放入到 $B\text{.falselist}$ 中。

根据这个示意图我们可以看出，在分析 $B_2$ 之前，需要用 $B_2$ 的第一条指令来回填 $B_1\text{.truelist}$ 中的各条指令，因此我们需要记录下 $B_2$ 的第一条指令的标号。这样我们就在产生式中 $B_2$ 之前插入一个标记非终结符 $M$，用来记录下 $B_2$ 的第一条指令的标号，$M\text{.code}$ 就等于 $B_2$ 的第一条指令的标号。接下来我们来编写语义动作：用 $M\text{.code}$，也就是 $B_2$ 的第一条指令的标号，来回填 $B_1\text{.truelist}$ 中的各条指令。接下来我们要计算 $B$ 的两个综合属性。由这个示意图可以看出，$B\text{.truelist}$ 等于 $B_2\text{.truelist}$；$B\text{.falselist}$ 是将 $B_1$ 和 $B_2$ 的 falselist 进行合并，因此我们调用 merge 函数将 $B_1\text{.falselist}$ 和 $B_2\text{.falselist}$ 合并，合并后的列表指针赋给 $B\text{.falselist}$。

现在，我们可以将栈顶的 $B \text{ or } B$ 规约为非终结符 $B$，对应于这个产生式。那么执行与它关联的语义动作：用 $M\text{.code}$，也就是 102，来回填 $B_1\text{.falselist}$。$B_1\text{.falselist}$ 是 101，因此 101 这条指令它的目标标号就是 102。

接下来我们来计算 $B$ 的两个综合属性。$B\text{.truelist}$ 等于它的两个子节点的 truelist 合并，也就是 100 和 104。$B\text{.falselist} = B_2\text{.falselist}$，也就是 103、105。

这样我们可以看出，这是整个 $B$ 对应的三地址码。那么在这其中有四条指令是等待回填的。那么在 $B\text{.truelist}$ 中有两条指令，100 和 104。当 $B$ 的真出口确定以后，我们将用 $B$ 的真出口的标号来回填这两条指令。那么在 $B\text{.falselist}$ 中是两条指令，103 和 105。当 $B$ 的假出口确定以后，用 $B$ 的假出口的标号来回填这两条指令。

[听音转录 · P51 6-9控制流语句的回填]
> 来源：**听音转录**——非平台字幕，由讲师原声转录

同学们好，下面我们来学习控制流语句的回填。

这是我们前面给出的控制流语句的文法。这里我们为非终结符 $S$ 设置综合属性 $S.nextlist$。它指向一个包含跳转指令的列表，这些指令最终获得的目标标号就是按照运行顺序紧跟在 $S$ 代码之后的指令的标号。

我们先来看第一个产生式：
$$S \to \text{if } B \text{ then } S_1$$

我们先来画翻译方案的示意图。$B.truelist$ 中的所有的指令要跳转到 $B$ 的真出口，也就是 $S_1$ 的第一条指令。$B$ 的 $falselist$ 中的所有指令要跳转到 $B$ 的假出口。当 $B$ 为假的时候，我们要跳出 if 语句，去执行 $S$ 之后的第一条指令，因此 $B.falselist$ 中的所有的指令都应该放入 $S.nextlist$ 中。

对于 $S_1$ 来说，$S_1.nextlist$ 中的所有指令都要跳转到 $S_1$ 之后的第一条指令。当 $S_1$ 执行完毕之后，整个 $S$ 语句就执行完毕，接下来要执行 $S$ 之后的第一条指令，因此 $S_1.nextlist$ 中的所有的指令要放入 $S.nextlist$ 中。

根据这个示意图，那么在分析 $S_1$ 之前，我们要用 $S_1$ 的第一条指令的标号来回填 $B.truelist$ 中的各条指令。因此我们需要记录下 $S_1$ 的第一条指令的标号，为此我们在 $S_1$ 之前设置标记非终结符 $M$，$M.code$ 就等于 $S_1$ 的第一条指令的标号。接下来我们来编写这个产生式的语义动作。首先用 $M.code$ 来回填 $B.truelist$ 中的各条指令。接下来我们来计算 $S$ 的综合属性 $S.nextlist$。根据示意图可以看出，$S.nextlist$ 是由 $B.falselist$ 和 $S_1.nextlist$ 合并而成，因此我们调用 merge 函数合并这两个列表。

下面我们来看产生式：
$$S \to \text{if } B \text{ then } S_1 \text{ else } S_2$$

我们先来画翻译方案的示意图。$B.truelist$ 中的各条指令都要跳转到 $B$ 的真出口，也就是 $S_1$ 的第一条指令。$B.falselist$ 中的所有指令都要跳转到 $B$ 的假出口，也就是 $S_2$ 的第一条指令。

$S_1.nextlist$ 中的所有指令要跳转到 $S_1$ 之后的第一条指令。那么 $S_1$ 执行完以后，我们就要跳出 $S$ 语句，去执行 $S$ 语句之后的第一条指令，因此 $S_1.nextlist$ 中的所有指令要放入 $S.nextlist$ 中。

对于 $S_2$，$S_2.nextlist$ 中的所有指令要跳转到 $S_2$ 之后的第一条指令。因为 $S_2$ 执行完以后，整个 $S$ 语句就结束了，接下来要执行 $S$ 之后的第一条指令，因此 $S_2.nextlist$ 中的所有指令也要放入 $S.nextlist$ 中。

另外，在 $S_1$ 执行完毕之后，我们要显式地生成一条跳转指令，跳转到 $S$ 之后的第一条指令，因此这条指令也要放入 $S$ 的 $nextlist$ 中。

根据这个示意图，我们要用 $S_1$ 的第一条指令来回填 $B.truelist$，要用 $S_2$ 的第一条指令来回填 $B.falselist$，因此我们需要记录下 $S_1$ 和 $S_2$ 的第一条指令的标号。这样我们就要在 $S_1$ 和 $S_2$ 之前分别设置一个标记非终结符 $M$。

另外，在 $S_1$ 之后我们要生成跳转指令，因此我们在 $S_1$ 之后设置一个标记非终结符 $N$，用来生成这条跳转指令。由于这条指令的目标标号需要等待回填，因此我们调用 makelist 函数构造一个只包含这条跳转指令的列表，并把列表的指针赋给 $N$ 的 $nextlist$ 属性。接下来我们根据这个示意图来编写这个产生式的语义动作。

首先我们用 $M_1.code$ 来回填 $B$ 的 $truelist$。然后用 $M_2.code$ 回填 $B$ 的 $falselist$。接下来我们来计算产生式左部非终结符 $S$ 的综合属性 $S.nextlist$。根据示意图可以看出，$S.nextlist$ 是由 $S_1.nextlist$ 和 $N.nextlist$ 还有 $S_2.nextlist$ 三部分合并而成。因此我们首先调用 merge 函数将 $S_1.nextlist$ 和 $N.nextlist$ 进行合并，将合并后的列表同 $S_2.nextlist$ 进行合并，将合并后的列表指针赋给 $S.nextlist$。

下面我们来看 while 语句对应的产生式。我们先来画翻译方案示意图。

$B.truelist$ 中的所有指令都要跳转到 $B$ 的真出口，也就是 $S_1$ 的第一条指令。$B.falselist$ 中的所有指令都要跳转到 $B$ 的假出口。当 $B$ 为假的时候，我们要跳出这个 while 语句，去执行 $S$ 之后的第一条指令，因此 $B.falselist$ 中的所有指令要放入到 $S.nextlist$ 中。

$S_1.nextlist$ 中的所有指令要跳转的目标标号是 while 语句的第一条指令。因此我们要在非终结符 $B$ 之前设置标记非终结符 $M_1$，来记录下 $B$ 的第一条指令的标号。在 $S_1$ 的代码之后，我们要显式地生成一条跳转指令，跳转到 while 语句的第一条指令。

根据这个翻译方案示意图可以看出，我们需要用 $B$ 的第一条指令的标号来回填 $S_1.nextlist$ 中的指令，用 $S_1$ 的第一条指令的标号来回填 $B.truelist$ 中的指令。因此我们在 $B$ 和 $S_1$ 之前设置标记非终结符 $M_1$ 和 $M_2$，用来记录 $B$ 和 $S_1$ 的第一条指令的标号。接下来我们来根据翻译方案的示意图编写语义动作。

首先用 $M_1.code$ 来回填 $S_1$ 的 $nextlist$ 中的指令。接下来用 $M_2.code$ 来回填 $B.truelist$ 中的各条指令。然后我们来计算 $S$ 的综合属性 $nextlist$。$S.nextlist$ 就等于 $B.falselist$。另外根据翻译方案的示意图，在 $S_1$ 之后我们要生成一条跳转到 $M_1.code$ 的跳转指令，因此生成跳转指令 `goto M1.code`。

下面我们来看产生式：
$$S \to S_1 S_2$$

我们来画一下翻译方案的示意图。$S_1.nextlist$ 中的所有指令要跳转到 $S_1$ 之后的第一条指令。因为 $S_1$ 执行完以后，我们要去执行 $S_2$，所以 $S_1.nextlist$ 中的所有的指令都要跳转到 $S_2$ 的第一条指令。

$S_2.nextlist$ 中的所有指令都要跳转到 $S_2$ 之后的第一条指令。当 $S_2$ 执行完以后，整个 $S$ 就执行完了，因此将执行 $S$ 之后的第一条指令，所以 $S_2.nextlist$ 中的所有的指令都要放入 $S.nextlist$ 中。因为我们要用 $S_2$ 的第一条指令去回填 $S_1$ 的 $nextlist$，因此我们在 $S_2$ 之前设置标记非终结符 $M$ 来记录 $S_2$ 的第一条指令的标号。

它对应的语义动作：用 $M.code$ 来回填 $S_1.nextlist$ 中的各条指令，然后 $S.nextlist = S_2.nextlist$。

对于赋值语句，因为赋值语句中不包含跳转指令，所以 $S.nextlist$ 等于空。

下面我们来看一个例子。假如我们要翻译这样一个控制流语句：这是一个 while 语句中嵌套着一个 if 语句，if 语句中又嵌套了一个 while 语句。

这是这个输入的控制流语句对应的注释分析树。接下来我们来看这棵注释分析树是如何自底向上构造起来的。

我们从左向右扫描输入串。当读入 while 以后，那么将对应着对这个产生式的应用。那么读入 while 以后，暂顶归约出一个 $M_1$，$M_1.code$ 用来记录下一条指令的标号。我们假设下一条指令的标号从 100 开始，这样 $M_1.code$ 就等于 100。

接下来我们将读入的 $a < b$ 归约为非终结符 $B$。那么我们来执行与 $B$ 相关的语义动作。与 $B$ 相关的语义动作首先是将下一条指令的标号放入 $B$ 的 $truelist$ 中，因此 $B$ 的 $truelist = 100$。那么将再下一条指令的标号放到 $B$ 的 $falselist$ 中，这样 $B.falselist$ 中存放的就是标号 101。接下来我们生成两条跳转指令：第 100 号指令是 `if a < b goto _`，第 101 号指令是 `goto _`。

接下来我们读入关键字 do，然后栈顶归约出标记非终结符 $M_2$。$M_2.code$ 等于下一条指令的标号，也就是 102。

接下来我们读入下一个输入符号 if。这个 if 语句对应着对这个产生式的应用。接下来我们将读入的 $c < 5$ 归约为布尔表达式 $B$。根据 $B$ 关联的语义动作，$B$ 的 $truelist$ 中存放的是下一条指令的标号，也就是 102；$B$ 的 $falselist$ 中存放的是再下一条指令的标号，也就是 103。接下来我们生成两条跳转指令：第 102 号指令是 `if c < 5 goto _`，第 103 号指令是 `goto _`。

接下来我们读入输入符号 then，然后栈顶归约出标记非终结符 $M_1$。$M_1.code$ 等于下一条指令的标号，也就是 104。

接下来我们读入输入符号 while，那么将对应着对这一个产生式的应用。读入输入符号 while 以后，栈顶归约出标记非终结符 $M_1$。$M_1.code$ 等于下一条指令的标号，也就是 104。

接下来我们将读入的 $x > y$ 归约为标记非终结符 $B$。根据与 $B$ 关联的语义动作，$B$ 的 $truelist$ 中存放的是下一条指令的标号，也就是 104；$B$ 的 $falselist$ 中存放的是再下一条指令的标号，也就是 105。接下来我们生成两条三地址指令：第 104 号指令是 `if x > y goto _`，第 105 号指令是 `goto _`。

接下来我们读入输入符号 do 之后，栈顶归约出标志非终结符 $M_2$。$M_2.code$ 等于下一条指令的标号，也就是 106。

接下来我们读入输入符号 $z = x + 1$，并且将 $x + 1$ 归约为一个算术表达式 $E$。接下来我们生成一个新的临时变量 $t_1$ 用来存放表达式 $E$ 的值，$E$ 的 address 就等于 $t_1$。接下来我们生成一条三地址指令 $t_1 = x + 1$。然后我们将 $z = E$ 归约为赋值语句 $S$。生成的代码是 $z = t_1$。我们说赋值语句中没有跳转指令，因此 $S$ 的 $nextlist$ 等于空。

这样我们就可以将栈顶的 $\text{while } M_1 B \text{ do } M_2 S$ 归约为非终结符 $S$，执行这段语义动作。首先用 $M_1.code$，也就是 104，来回填 $S_1.nextlist$ 中，也就是它中的跳转指令。因为 $S.nextlist$ 是空，所以实际上不用采取任何回填动作。接下来我们用 $M_2.code$，也就是 106，来回填 $B$ 的 $truelist$ 中的指令，也就是 104。因此 104 中的目标标号就是 106。接下来 $S$ 的 $nextlist$ 等于 $B$ 的 $falselist$，也就是 105。然后生成一条跳转指令 `goto M1.code`，也就是 `goto 104`。

在归约出 $M_1$ 之后的这个 $S_1$ 之后，栈顶将归约出标记非终结符 $N$。与 $N$ 关联的这个语义动作：首先调用 makelist 函数创建一个只包含下一条指令标号，也就是 109 的列表，把它赋给 $N.nextlist$，然后生成一条跳转指令 `goto _`。

在读入 else 以后，栈顶将归约出标记非终结符 $M_2$。$M_2.code$ 用来记录下一条指令的标号，也就是 110。

接下来将读入的 $x = y$ 归约成一条赋值语句，生成三地址指令 $x = y$。因为赋值语句中不包含跳转指令，因此 $S$ 的 $nextlist$ 等于空。

这样我们就可以将栈顶的 $\text{if } B \text{ then } M_1 S_1 N \text{ else } M_2 S_2$ 归约为非终结符 $S$。归约的时候执行这样一段语义动作：首先用 $M_1.code$，也就是 104，来回填 $B$ 的 $truelist$ 中的指令，也就是 102。因此 102 的目标标号就是 104。接下来用 $M_2.code$，也就是 110，来回填 $B$ 的 $falselist$ 中的指令，也就是 103。因此 103 号指令它的目标标号将是 110。接下来，父节点的 $nextlist$ 属性等于它的三个子节点 $S_1$ 的 $nextlist$、还有 $N$ 的 $nextlist$、还有 $S_2$ 的 $nextlist$ 进行合并。合并后 $S_1.nextlist$ 等于 105 和 109。

这个时候我们将栈顶的 $\text{while } M_1 B \text{ do } M_2 S_1$ 归约为非终结符 $S$，执行这样一段语义动作：首先用 $M_1.code$，也就是 100，来回填子节点的 $nextlist$ 中的指令，也就是 105 和 109 号指令，它们的目标地址将是 100。接下来用 $M_2.code$，也就是 102，来回填 $B$ 的 $truelist$ 中的指令，也就是 100 号指令，它的目标标号将是 102。接下来，父节点的 $nextlist$ 等于 $B$ 的 $falselist$，也就是 101。最后生成一条跳转指令 `goto M1.code`，也就是 `goto 100`。

这样我们就生成了这个控制流语句的三地址码。

我们可以看出，这个语句的 $nextlist$ 中存放的是第 101 号指令，那么当 $S$ 的下一条指令的标号确定以后，就回填到这条指令。

我们把这些三地址指令在这里重写一下，然后并且列出它们的形式：四元式形式。

同学们好，下面我们来学习 switch 语句的翻译。

很多语言中都使用 switch 语句，或者说是 case 语句。我们先来看一下 switch 语句的语法。在 switch 语句中，有一个待求值的选择表达式 $E$，它有 $n-1$ 个可能的取值，是 $n-1$ 个常量。当选择表达式的值与其中的某一个常量匹配的时候，就执行与这个常量对应的代码段 $S_i$。如果选择表达式的值与所有的常量都不匹配的话，那么我们就执行缺省的代码段 $S_n$。

根据 switch 语句的含义，我们先来绘制 switch 语句的代码结构图。我们说 switch 语句的代码是由 $E$ 的代码和各个 $S$ 的代码构成的。在生成 $E$ 的代码之后，我们需要生成一条三地址指令：$t = E.\text{address}$，也就是说将表达式 $E$ 的值存放到临时变量 $t$ 中。

在读入 $\text{case } V_1$ 以后，我们生成一条条件跳转指令，也就是说：如果 $t \neq V_1$，goto $L_1$。$L_1$ 是 $\text{case } V_2$ 之后的第一条指令。那么，读入 $\text{case } V_2$ 以后，我们也要生成一条条件跳转指令，也就是 if $t \neq V_2$ goto $L_2$。那么 $L_2$ 就是对应于 $\text{case } V_3$ 之后的第一条指令。以此类推。最后，在读入 $\text{case } V_{n-1}$ 之后，我们要生成一条条件跳转指令：if $t \neq V_{n-1}$ goto $L_{n-1}$。这里 $L_{n-1}$ 是 $S_n.\text{code}$ 中的第一条指令的标号。

在生成每个 $S$ 的代码之后，我们要生成一条跳转指令 goto next，这里 next 是 $S_n$ 的代码之后的第一条指令的标号，也就是整个 switch 语句之后的第一条指令的标号。

那么，根据这个代码结构图，我们可以编写 switch 语句的翻译方案。

在非终结符 $E$ 之后，我们嵌入语义动作：调用 newtemp 函数生成一个临时变量 $t$，然后生成三地址指令 $t = E.\text{address}$，将表达式 $E$ 的值赋给临时变量 $t$。

在符号 $\text{case } V_1:$ 之后，我们嵌入语义动作：生成一个新的标号 $L_1$，并且生成条件跳转指令 if $t \neq V_1$ goto $L_1$。

在 $S_1$ 之后嵌入语义动作：生成一个新的标号 next，然后生成指令 goto next。

在符号 $\text{case } V_2:$ 之后嵌入语义动作：这个时候我们调用 label 函数，将下一条指令的标号赋给 $L_1$；然后我们生成一个新的标号 $L_2$，并生成三地址指令 if $t \neq V_2$ goto $L_2$。

那么在 $S_2$ 之后生成跳转指令 goto next。以此类推。

直到在 default 之后，我们调用 label 函数，将下一条指令的标号赋给 $L_{n-1}$。那么在 $S_n$ 之后，我们要调用 label 函数，将下一条指令的标号赋给 next。

在这个翻译方案中，每一个条件跳转指令，它的四元式的第四个分量都不是目标标号，而是存放目标标号的地址，因此我们需要再进行一趟处理，将标号和地址绑定起来。

那么，在这个翻译方案中，各个分支测试指令是与各个 $S$ 的代码混合在一起的。事实上，当分支个数较多的时候，我们可以将这些分支测试指令集中在一起，这样便于在代码生成阶段生成高效的分支测试代码。

这样，我们可以给出第二种翻译方案的代码结构图。在这里，我们将各个分支测试指令集中在一起，放在所有 $S$ 的代码之后。这样，在指令 $t = E.\text{address}$ 之后，我们需要添加一条跳转指令 goto test。这里 test 是分支测试代码的第一条指令的标号。另外，在每个 $S$ 的代码之后，我们要生成一条跳转指令 goto next，这里 next 是分支测试代码之后的第一条指令的标号。

在代码生成阶段，根据分支的个数以及这些值是否在一个较小的范围内，这种条件跳转指令序列可以被翻译成最高效的 $n$ 路分支。

根据这个代码结构图，我们可以来编写 switch 语句的翻译方案。

在非终结符 $E$ 之后，我们嵌入语义动作：生成一个新的临时变量 $t$，并生成三地址指令 $t = \text{address}$，然后生成一个新的标号 test，并且生成跳转指令 goto test。

在符号 $\text{case } V_1:$ 之后，我们要嵌入语义动作：这个时候调用 newlabel 函数建立一个新的标号 $L_1$，并且将 $S_1.\text{code}$ 中的第一条指令的标号赋给 $L_1$；然后我们在 $V_1$ 和 $L_1$ 之间建立映射，并把它放到映射表中。

在 $S_1$ 之后我们嵌入语义动作：生成一个新的标号 next，然后生成跳转指令 goto next。

同理，在符号 $\text{case } V_2:$ 之后，我们建立一个新的标号 $L_2$，并且将 $S_2.\text{code}$ 中的第一条指令的标号赋给 $L_2$，然后在 $V_2$ 和 $L_2$ 之间建立映射，并把它放入到映射表中。

在 $S_2$ 之后生成跳转指令 goto next。以此类推。

一直到 default 之后，我们嵌入语义动作：生成一个新的标号 $L_n$，并且将 $S_n.\text{code}$ 中的第一条指令的标号赋给 $L_n$。在 $S_n$ 之后，我们生成跳转指令 goto next。

接下来，我们调用 label 函数，将下一条指令的标号赋给 test。接下来，我们从映射表中读取 $n-1$ 个映射，然后生成相应的条件跳转指令序列：if $t = V_1$ goto $L_1$，if $t = V_2$ goto $L_2$，以此类推，一直到 if $t = V_{n-1}$ goto $L_{n-1}$。接下来，我们生成跳转指令 goto $L_n$。

在生成这些跳转指令的时候，标号已经与它们的地址进行了绑定，因此我们可以将目标标号直接填入到跳转指令中。最后，我们调用 label 函数，将下一条指令的标号赋给 next。

为了便于代码生成器检测到这些分支测试代码，那么我们引入一种新的指令——case 指令。这里 $\text{case } t, V_1, L_1$ 表示 if $t = V_1$ goto $L_1$。因此，这个 case 指令它同这个条件跳转指令，它们的含义是相同的。但是 case 指令它更容易被代码生成器探测到，从而对这些指令进行特殊地处理。
