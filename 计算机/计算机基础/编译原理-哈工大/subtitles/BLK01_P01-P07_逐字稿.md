[听音转录 · P02 1-2编译系统的结构]
> 来源：**听音转录**——非平台字幕，由讲师原声转录

同学们好，下面我们来介绍编译系统的结构。

我们前面讲过，编译的本质是一个翻译的过程。编译器的输入是一个高级语言程序，比如说一个 C 语言程序。编译器的输出是汇编语言程序或者机器语言程序。那么机器是如何将输入的 C 语言程序自动地翻译成汇编语言程序的呢？这里我们可以借鉴人工翻译的过程。

比如说我们要将这样一个英文句子：In the room, he broke a window with a hammer. 翻译成汉语。在这里英语就是源语言，汉语就是目标语言。那么我们是如何进行翻译的呢？我们说翻译的过程大体可以分为两步。

首先，从源语言也就是英语层面，我们先要分析这个句子表达的含义，也就是句子的语义。接下来根据这个语义，我们再用目标语言也就是汉语的方式说一遍，就完成了翻译的过程。那么通过分析源语言来获得句子语义的这一过程称为语义分析。

那么我们是如何进行语义分析的呢？我们说通常是从划分句子成分入手。首先抓住句子的核心谓语动词，因为谓语动词知道了，句子的一半意思就知道了。这里我们很容易找到这个句子的核心谓语动词是 break，表示“打”的意思。提到“打”这个动作，我们就想知道是谁施加了打这个动作？谁是被打的对象？用什么打的？为什么打？打的结果如何等等。这些都可以通过分析 break 的上下文来获得。

由于这里 break 采用的是主动语态，因此它的主语 he 就是动作的施事者，宾语 window 就是动作的受事者。反过来，如果 break 采用的是被动语态 be broken，那么它的主语就是动作的受事者。with a hammer 是补语，表示动作使用的工具。in the room 是状语，表示动作发生的地点。

这样我们就可以分析出 break 前后的这些名词性成分和核心谓语动词 break 之间的语义关系。我们可以用一个图来表示。

在这个图中，图中央的这个结点表示句子描述了“打”这样一个动作。周围的四个结点对应着句子中的四个实体，分别是 he、window、hammer 和 room。从中间的这个结点到周围的四个结点分别引出了四条边，边上的信息表示这些实体和核心谓语动词之间的语义关系。其中 he 是动作的施事者，agent；window 是动作的受事者，object；hammer 是动作采用的工具，tool；room 是动作发生的地点，location。根据这个图的意思，我们再用汉语的方式说一遍，也就是“在房间里，他用锤子砸了一扇窗户”，就完成了翻译的过程。

那么这个图它是一种中间表示，它独立于具体的语言。也就是说英语可以用这个图来表示，汉语也可以用这个图来表示，日语、法语、德语、意大利语等等都可以用它来表示。有了这个图，不管目标语言是什么，我们都可以进行翻译。所以说中间表示很重要，它起到了一个桥梁的作用。

根据以上的分析，我们知道要想进行语义分析，首先要划分句子成分。那么我们是根据什么划分句子成分的呢？我们都知道主语和宾语通常是由名词短语构成的，状语和补语通常是由介词短语构成的。因此要想划分句子成分，关键是识别出句子中的各类短语，这一过程称为语法分析，也叫句法分析。

那么我们又是根据什么来识别句子中的各类短语呢？我们说是通过词性。比如说一个冠词加上一个名词可以构成一个名词短语，一个代词本身也可以构成一个名词短语。因此要想识别句子中的各类短语，关键是要确定句子中各个单词的词性或者叫词类，这一过程称为是词法分析。

综上所述，我们可以得到一个句子的分析过程，也就是说首先进行词法分析，在词法分析的基础上进行语法分析，然后进行语义分析。

具体来说也就是，首先通过词法分析确定句子中各个单词的词性或者说词类；接下来进行语法分析，识别句子中的各类短语，从而获得句子的结构；接下来进行语义分析，根据句子的结构分析出各个短语在句子中充当什么成分，从而确定各个名词性成分和核心谓语动词之间的语义关系；最后给出中间表示形式。

那么事实上编译器在工作的时候也是经过这样几个步骤，我们称之为阶段。分别是词法分析、语法分析、语义分析、中间代码生成、目标代码生成。在中间代码和目标代码生成之后，通常还有一个代码优化的步骤。

其中前面几个阶段统称为分析部分，也叫编译器的前端。它对源语言进行分析并生成中间表示，因此这个部分只与源语言相关。后面的几个阶段统称为综合部分，也叫编译器的后端。它在中间表示的基础之上生成目标代码，因此它只与目标语言相关。中间表示独立于具体的语言，起到一个桥梁的作用。

值得注意的是，我们这里所说的阶段是编译器的逻辑组织方式。在实现过程中，多个阶段可能会被组合在一起。比如说语义分析的结果通常直接表示成中间代码的形式，因此这两个阶段通常是放在一起实现的。

另外，可以在语法分析分析句子结构的同时结合语义规则直接进行语义分析，这一技术称为语法制导翻译。在这种情况下，语法分析、语义分析和中间代码生成三个阶段可以放在一起实现。

这就是编译器的大体结构。好，这一部分我们就介绍到这里。

同学们好，下面我们来简单介绍一下词法分析。

词法分析是编译的第一个阶段。词法分析器的任务是：从左向右，逐行扫描源程序的字符，识别出各个单词，确定单词的类型，并将识别出的单词转换成统一的机内表示，也就是词法单元 token 的形式。

token 是一个二元组，它由种别码和属性值两部分构成。其中，种别码表示单词的种别。提到单词的种别，我们说自然语言句子中的每一个单词都有一个词性，或者叫词类。那么，程序设计语言中的单词多分为哪些类型呢？

我们说，大体上分为五类。

第一类是关键字，例如 program、if、else、then 等等。给定一个程序设计语言，那么它的关键字集合是事先可以确定的，因此我们为每一个关键字分配一个种别码，也就是一词一码。

第二类单词是标识符，它是程序员为程序中声明的数据对象或过程起的名字。由于标识符是一个开放的集合，也就是说我们事先不能枚举所有的标识符，因此我们将所有的标识符统一作为一类单词，并给它们分配同一个种别码，也就是多词一码。为了区分不同的标识符，我们用 token 的第二个分量属性值来存放不同标识符具体的字面值。

第三类单词是常量，包括整型常量、浮点型常量、字符型常量、布尔型常量等等。常量与标识符类似，它也是一个开放的集合，也就是说我们事先不能枚举所有的常量。但是，不同类型的常量它们的构成方式是不同的，因此我们为每种类型的常量分配一个种别码，也就是一型一码。为了区分同一类型下的不同常量，我们也是用 token 的第二个分量属性值来存放每一个常量具体的值。

第四类单词是运算符，包括算术运算符、关系运算符和逻辑运算符。

第五类单词是界线符，比如说分号、左括号、右括号、等号、左花括号、右花括号等等。

运算符和界线符与关键字类似，它们也是事先可以确定的，因此我们可以为每一个运算符和每一个界线符分配一个种别码，也就是一词一码。当然，我们也可以为每一类运算符分配一个种别码，那么为了区分同一类型下的不同运算符，我们也是用 token 的第二个分量属性值来存放具体的运算符。

根据以上的种别码分配原则，我们来看一个词法分析结果的例子。假如说我们输入这样一个程序片段，那么这就是词法分析后得到的 token 序列，每一个 token 对应着一个单词。

那么种别码本身应该是一个整数，这里为了直观起见，我们采用的是宏定义的形式。比如说我们用大写的 WHILE 来表示关键字 while；用 SLP 表示左括号；用 SRP 表示右括号；用 IDN 表示标识符 identifier；用 NE 表示不等号 not equal；用 CONST 表示常量；用 LP 表示左花括号，RP 表示右花括号；INC 表示加加；SEMI 表示分号。

我们先来看第一个单词 while。while 是一个关键字，它是一词一码，因此通过它的种别码可以将其同其他的单词区分开，因此它的第二个分量是空的。同样的道理，左括号、不等号、右括号、左花括号、加加、分号和右花括号，它们都是一词一码的单词，因此它们的第二个分量都是空的。这里 value 和 number 是两个标识符，因此它们的种别码都是 IDN，表示标识符；它们的第二个分量属性值分别来存放它们各自的字面值，用来对它们进行区分。100 是一个常量，它的第二个分量属性值就是 100 本身。

[听音转录 · P04 1-4语法分析概述]

同学们好，下面我们来简单介绍一下语法分析。

语法分析是编译的第二个阶段。语法分析的主要任务是从词法分析器输出的 token 序列中，识别出各类短语，并构造语法分析树。语法分析树描述了句子的语法结构。

我们先来看一个例子，赋值语句的分析树。假如我们输入了一个赋值语句：
```c
position = initial + rate * 60;
```
那么，经过词法分析，我们得到一个 token 序列。其中，`position`、`initial` 和 `rate` 都是标识符，`60` 是一个常数。这就是它对应的分析树。

我们可以看出，一个标识符或者一个常数本身可以构成一个表达式；一个表达式加上另一个表达式，或者乘上另一个表达式，可以构成一个更大的表达式；一个标识符连接上一个赋值号，再连接上一个表达式和一个分号，可以构成一条赋值语句。

我们再来看一个变量声明语句的分析树的例子。首先来看变量声明语句的文法。文法是由一系列规则构成的。这里的 $D$ 是英文单词 declaration 的首字母，表示声明语句；$T$ 是英文单词 type 的首字母，表示类型；$IDS$ 是 identifier sequence 的缩写，表示标识符序列。

从第一条规则我们可以看出，一个声明语句 $D$ 是由一个类型 $T$ 连接上一个标识符序列 $IDS$ 和一个分号构成的。这里的 $T$ 可以是 `int`，也可以是 `real`，或者 `char` 和 `bool`。这里的竖线表示的是“或”关系。根据第三条规则可以看出，一个标识符 id 本身可以构成一个标识符序列 $IDS$。那么，一个 $IDS$ 连接上一个逗号和一个标识符 id，可以构成一个更大的标识符序列 $IDS$。

根据这个文法，假如说我们输入了这样一个声明语句：
```c
int a, b, c;
```
那么，这就是它的分析树。

从这个分析树我们可以看出，一个标识符 id 本身可以构成一个标识符序列 $IDS$；一个 $IDS$ 连接上一个逗号和一个 id 以后，可以构成一个更大的 $IDS$；一个类型 $T$ 连接上一个标识符序列 $IDS$ 和一个分号，可以构成一个声明语句。

[听音转录 · P05 1-5语义分析概述]
> 来源：**听音转录**——非平台字幕，由讲师原声转录

同学们好，下面我们来简单介绍一下语义分析。

语义分析是编译的第三个阶段。我们先来看一下语义分析的主要任务。

我们说，高级语言程序中的语句大体分为两类：一类是声明语句，一类是可执行语句。在声明语句中，会声明一些数据对象或过程，并且为它们分别起个名字，就是标识符。那么对于声明语句来说，语义分析的主要任务就是收集标识符的属性信息。

那么标识符都有哪些属性呢？

首先是种属，也就是说一个标识符对应的是一个简单变量还是一个复合变量（比如说数组、记录等等），还是一个过程。

第二个属性就是类型，也就是说标识符对应的变量或过程是整型的还是实型的，还是字符型、布尔型、指针型等等。

另外两个属性是存储位置和长度。我们说，程序中声明的数据对象和过程，我们都要在内存中为它分配一块存储空间，这样存储位置和所占用的空间的大小（也就是长度），就成为标识符很重要的两个属性。

比如说输入这样一个程序片段，其中声明了一些数据对象。首先声明了一个实型数组 $x$，因此 $x$ 的相对地址就是 0。我们假设一个实型变量占用 8 个字节，那么这个数组包含 8 个元素，因此它就占用了 64 个字节。所以接下来声明的变量 $i$，它的相对地址就是 64。我们再假设一个整型变量占用 4 个字节，那么接下来声明的变量 $j$，它的相对地址就是 $64 + 4 = 68$，以此类推。

另外，变量的值和过程的作用域也是两个重要的属性。对于过程的名字来说，它的属性还包括参数和返回值信息。

语义分析阶段收集的这些标识符的属性信息，我们都会存放在一个称为符号表的数据结构中。每一个标识符都对应着符号表中的一条记录，记录的每一个字段对应着标识符的一个属性，比如说类型（type）、种属（kind）、值（value）、地址（address）等等。

符号表通常带有一个字符串表，用来存放程序中用到的标识符和字符常数。这样的话，name 字段就被分割成两个部分：其中一部分用来存放标识符在字符串表中的起始位置，另一部分用来存放标识符的长度。比如说第一个标识符 simple，它的长度是 6 个字符；第二个标识符 symbol，它的长度也是 6 个字符；第三个标识符 table，它的长度是 5 个字符。

同学们课下可以思考一下，符号表中为什么要设计字符串表这样一种数据结构，而不是将标识符直接存放到 name 字段中？

语义分析的另一个任务就是语义检查。常见的语义错误包括：变量或过程未经声明就使用；变量或过程名重复声明；运算分量类型不匹配，比如说将一个数组的名字和一个过程的名字相加是没有意义的。当发现运算分量类型不一致的时候，可能要进行自动的类型转换，比如说一个二元算术运算符可以作用于一对整数，也可以作用于一对浮点数，但是如果将它作用于一个整数再加一个浮点数，那么就要将其中的整数自动类型转换为浮点数。

语义错误还包括操作符与操作数之间的类型不匹配，比如说数组的下标通常是整数，如果把一个浮点数作为数组的下标，那么编译器将报告错误。另外，对非数组变量使用数组访问操作符、对非过程名使用过程调用操作符、过程调用的参数类型或数目不匹配、函数返回类型有错误等等，都是常见的语义错误。

三地址码由类似于汇编语言的指令序列组成，每个指令最多有三个操作数，因此叫三地址码。

我们来看一些常用的三地址指令，包括赋值指令、复制指令、跳转指令等等。这里红色的部分表示指令的操作符。

我们先来看第一条赋值指令：$x = y \text{ op } z$。这里 op 是一个二元运算符，y 和 z 是两个运算分量的地址，x 是运算结果的存放地址。为了方便起见，我们可以用源程序中的名字，也就是标识符，来作为三地址指令中的地址。因为每个标识符对应的地址都存放在符号表中，因此通过这些名字就可以找到它们的地址。另外，常量或者是编译器生成的临时变量，也可以作为三地址指令的地址。

我们来看第二条赋值语句：$x = \text{op } y$。这里的 op 是一个一元运算符。因此这条指令只有两个操作数，x 和 y。

复制指令，它的形式是 $x = y$。这条指令也只有两个操作数。

这是条件跳转指令：`if x rel_op y goto n`。这条指令表示如果 x 和 y 满足关系 rel_op，那么就跳转到地址 n 对应的指令。

无条件跳转指令的形式是 `goto n`，就是直接跳转到地址 n 对应的指令。

这是参数传递指令：`param x`，将 x 设置为参数。

过程调用指令：`call p, n`。这里 p 是过程的名字，n 是过程的参数的个数。

过程返回指令：`return x`，也就是说跳转到地址 x 对应的指令。

这是数组引用指令：$x = y[i]$。这里 y 是数组的名字，表示数组的基地址，i 是数组元素的偏移地址。这条指令表示将一个数组元素的值赋给一个变量。这里我们需要注意，i 是数组元素的偏移地址，而不是数组的下标。

数组赋值指令：$x[i] = y$。这条指令表示将一个变量的值赋给一个数组元素。

第三条是与地址、指针操作相关的指令。

四元式由四个分量构成，其中第一个分量对应于三地址指令中的操作符，后面三个分量对应于指令中的三个操作数。这就是前面列出的这些三地址指令对应的四元式形式。其中第一条指令，它的操作符是 op，这里的第二个和第三个分量对应着指令中的两个源操作数，第四个分量对应着指令中的目标操作数。

第二条指令，它是一个一元运算对应的赋值语句。因此它只有一个源操作数 y，我们用第二个分量来表示，第三个分量为空。

复制指令，它的操作符是等号，这条指令也只有两个操作数。

条件跳转指令，它的操作符是 rel_op，第二个和第三个分量对应着 x 和 y，第四个分量对应着目标跳转地址。

这是无条件跳转指令，它只有一个操作数。

第三条是与过程调用和返回相关的指令的四元式表示。

这是数组引用指令，它的操作符是 `=[]`。这个符号表示等号的右边是一个数组元素。我们用第二个和第三个分量来表示等号右边的数组的基地址和数组元素的偏移地址，用第四个分量来表示等号左面的变量。

[听音转录 · P07 2-1词法语法分析基本概念]

同学们好，今天我们来学习第二章，语言及其文法。

我们都知道，编译器要对高级程序设计语言进行词法、语法等分析，那么要想让计算机能够自动地分析语言，就要把相关的语言学知识，也就是文法，提供给计算机。那么在计算机中是如何表示语言及其文法的呢？这就是我们这章要介绍的内容。

首先我们来看基本概念。

第一个概念是字母表，我们用符号 $\Sigma$ 来表示。一个字母表 $\Sigma$ 是一个有穷符号集合。符号的典型例子包括字母、数字、标点符号等等。例如，由 0 和 1 两个数字构成的集合是一个二进制字母表。另外，ASCII 字符集还有 Unicode 字符集都是字母表。

既然字母表是一个集合，那么我们就可以在字母表上进行一些集合运算。首先我们来看字母表的乘积。假设 $\Sigma_1$ 和 $\Sigma_2$ 是两个字母表，那么它们的乘积是一个集合，集合中的每个元素由两个符号构成，第一个符号来自于字母表 $\Sigma_1$，第二个符号来自于字母表 $\Sigma_2$。例如，字母表 $\{0, 1\}$ 和字母表 $\{a, b\}$ 相乘，得到的结果是一个集合，集合中的元素分别是 $0a$、$0b$、$1a$ 和 $1b$。

接下来我们来看字母表上的幂运算。字母表 $\Sigma$ 的 $n$ 次幂是 $n$ 个 $\Sigma$ 相乘。例如，二进制字母表它的三次幂等于三个二进制字母表相乘，那么最后得到的集合中的元素都是长度为 3 的 01 字符串。可见，字母表的 $n$ 次幂实际上就是长度为 $n$ 的符号串构成的集合。那么这里 $n$ 可以等于 0，也就是说 $\Sigma$ 的 0 次幂表示长度为 0 的符号串构成的集合。那么长度为 0 的符号串其实就是没有符号的符号串，我们把它叫做空串。我们这里用一个特殊的符号 $\epsilon$ 来表示空串。

下面我们来看字母表的正闭包运算。字母表 $\Sigma$ 的正闭包是 $\Sigma$ 的各个正数次幂的并集。例如，$\{a, b, c, d\}$ 这个字母表，它的正闭包就是由字母表上长度为 1 的字符串集合，并上长度为 2 的字符串集合，再并上长度为 3 的字符串集合，以此类推。由此可见，字母表的正闭包实际上就是长度为正数的符号串构成的集合。

下面我们来看字母表的克林闭包。字母表 $\Sigma$ 的克林闭包是在字母表 $\Sigma$ 的正闭包的基础之上，再并上一个 $\Sigma$ 的 0 次幂，也就是说，在正闭包的基础之上再添加一个空串。由此可见，字母表的克林闭包实际上就是任意符号串构成的集合，那么这个符号串的长度可以为 0。

假设 $\Sigma$ 是一个字母表，那么 $\Sigma$ 的克林闭包中的每一个元素都称为是 $\Sigma$ 上的一个串。由此可见，串就是字母表中符号的一个有穷序列。

字符串 $s$ 的长度就是指字符串 $s$ 中符号的个数，通常我们在 $s$ 的前后各加一条竖线用来表示 $s$ 的长度。例如字符串 $aab$，它的长度就是 3。那么长度为 0 的字符串称为是空串，我们前面讲过，用符号 $\epsilon$ 表示。

下面我们来看串上的运算。首先我们来看连接运算。如果 $x$ 和 $y$ 是两个串，那么 $x$ 和 $y$ 的连接是指把 $y$ 附加到 $x$ 后面而形成的串，记为 $xy$。例如，如果 $x = \text{dog}$，$y = \text{house}$，那么 $xy$ 就等于 $\text{doghouse}$。空串是连接运算的单位元，也就是说对于任意一个串 $s$，在它的前面或者后面连接上一个空串，得到的还是 $s$。

假设 $x, y, z$ 是三个字符串，如果 $x = yz$，那么 $y$ 就是 $x$ 的前缀，$z$ 就是 $x$ 的后缀。

如果把串上的连接运算看作是串的乘法运算的话，那么我们可以定义串的幂运算。串 $s$ 的 $n$ 次幂等于将 $n$ 个 $s$ 进行连接。例如，如果 $s = ba$，那么 $s$ 的 1 次幂就等于 $ba$，$s$ 的 2 次幂就等于 $baba$，$s$ 的 3 次幂就等于 $bababa$，以此类推。这里值得注意的是，$s$ 的 0 次幂是表示将 0 个 $s$ 连接起来，这实际上就是空串，所以 $s$ 的 0 次幂等于空串。
