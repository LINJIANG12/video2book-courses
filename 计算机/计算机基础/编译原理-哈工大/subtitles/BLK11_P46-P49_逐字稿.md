同学们好，下面我们来学习数组引用的翻译。

我们对前面给出的赋值语句的基本文法进行扩展，这里我们引入新的非终结符 $L$。$L$ 可以生成一个标识符连接上一个数组下标表达式的序列，因此 $L$ 表示的是一个数组元素。根据第二个产生式我们可以看出，一个数组元素本身就是一个表达式。根据第一个产生式可以看出，我们可以为数组元素赋值。

将数组引用翻译成三地址码时，要解决的主要问题就是确定数组元素的存放地址，也就是数组元素的寻址。

我们先来看一下一维数组元素的寻址。假设每个数组元素的宽度是 $w$，那么数组元素 $A[i]$ 的相对地址就是 $base + i \times w$。这里 $base$ 是数组的基地址，$i \times w$ 是偏移地址。

我们再来看二维数组。假设一行的宽度是 $w_1$，同一行中每个数组元素的宽度是 $w_2$。那么数组元素 $A[i_1][i_2]$ 的相对地址就是 $base + i_1 \times w_1 + i_2 \times w_2$。这里 $i_1 \times w_1 + i_2 \times w_2$ 是偏移地址。

那么对于 $k$ 维数组，数组元素 $A[i_1][i_2]\dots[i_k]$ 的相对地址就是 $base + i_1 \times w_1 + i_2 \times w_2 + \dots + i_k \times w_k$。这里 $w_1$ 是 $A[i_1]$ 的宽度，$A[i_1]$ 是一个 $k-1$ 维数组。$w_2$ 是 $A[i_1][i_2]$ 的宽度，$A[i_1][i_2]$ 是一个 $k-2$ 维数组。那么 $w_k$ 就是 $A[i_1][i_2]\dots[i_k]$ 的宽度，$A[i_1][i_2]\dots[i_k]$ 是数组的基本元素。那么这一部分就是这个数组元素的偏移地址。

我们来看一个例子。假设标识符 $A$，它是一个 $3 \times 5 \times 8$ 的三维整型数组。我们假设一个整型变量占用 4 个字节，那么数组元素 $A[i_1][i_2][i_3]$ 它的地址就是 $base + i_1 \times 160$。160 是数组 $A[i_1]$ 的宽度。$A[i_1]$ 它是一个二维数组，是一个 $5 \times 8$ 的二维整型数组，因此它的宽度就是 $5 \times 8$ 再乘上 4，$5 \times 8 = 40$ 再乘上 4 等于 160。这里 32 是数组 $A[i_1][i_2]$ 的宽度。数组 $A[i_1][i_2]$ 是一个一维数组，也就是一个由 8 个整型变量构成的数组，那么它的宽度就是 $4 \times 8 = 32$。那么这个 4 呢，就是数组元素 $A[i_1][i_2][i_3]$ 的宽度。$A[i_1][i_2][i_3]$ 是一个整型变量，它的宽度就是 4。

好了，下面我们来看带有数组引用的赋值语句翻译的一个例子。假设 $A$ 是一个包含 $n$ 个整型变量的数组。现在我们要翻译源程序的片段 $c = A[i]$。那么根据前面的地址计算公式，我们可以算出来 $A[i]$ 的地址是 $base + i \times 4$。它对应的三地址码就是这样三条三地址码：首先，我们计算 $i \times 4$ 的值，$i \times 4$ 是偏移地址，我们把这个偏移地址存放在 $t_1$ 中。接下来，我们用基地址加上偏移地址得到这个数组元素的实际地址。那么这里我们用数组的名字 $A$ 来表示数组的基地址，那么数组的基地址加上数组的偏移地址得到的是数组的实际地址 $t_2$。我们将 $t_2$ 中的元素取出来赋给变量 $c$。

再来看一个二维数组的例子。假如说 $A$ 是一个 $3 \times 5$ 的二维整型数组，那么我们来翻译源程序片段 $c = A[i_1][i_2]$。数组元素 $A[i_1][i_2]$ 它的地址是 $base + i_1 \times 20 + i_2 \times 4$。那么在生成它的三地址码的时候，首先我们来计算这一部分偏移地址 $i_1 \times 20$，我们把它存放到 $t_1$ 中。接下来我们来计算这一部分偏移地址 $i_2 \times 4$，把它存放在临时变量 $t_2$ 中。接下来我们将这两部分相加存放到临时变量 $t_3$ 中，$t_3$ 中存放的就是这个数组元素的偏移地址。接下来我将这个偏移地址与数组的基地址相加，得到数组元素的实际地址 $t_4$，然后将 $t_4$ 中的元素取出来赋给变量 $c$。

下面我们来看一下数组引用的 SDT。在数组引用的翻译方案的设计过程中，关键的问题是如何将这个地址计算公式同数组引用的文法关联起来。

我们来看这个例子。假如说 $A$ 是一个 $3 \times 5 \times 8$ 的三维整型数组，现在我们要翻译语句片段 $A[i_1][i_2][i_3]$。前面对于简单赋值语句的翻译采用的是自底向上的翻译方法，因此这里我们还可以延续这个自底向上的翻译过程。我们从左向右扫描输入的符号串。当读入 $A[i_1]$ 以后，我们可以将它归约为非终结符 $L$。$L$ 表示的是数组元素 $A[i_1]$。这个时候我们通过查询符号表可以获得 $A$ 的类型表达式和它的基地址，这样 $base$ 的值就可以确定了。现在 $i_1$ 的值也可以确定。我们接下来要计算 $w_1$。$w_1$ 是数组元素 $A[i_1]$ 的宽度。要想求这个宽度需要知道 $A[i_1]$ 的类型表达式。我们说 $A[i_1]$ 是 $A$ 的一个元素，现在 $A$ 的类型表达式通过查询符号表已经获得了，那么我们根据 $A$ 的类型表达式就可以得到它的元素也就是 $A[i_1]$ 的类型表达式。这样的话，我们为 $L$ 设置一个综合属性 type，用 type 来表示 $L$ 生成的数组元素的类型，那么这个时候 $L$ 的 type 值就是 array 5 array 8 int。有了这个类型表达式我们就可以计算出它的宽度 $w_1$，也就是等于 $5 \times 8 = 40$，$40$ 再乘上 4 是 160。这样的话，我们就可以计算这一部分偏移地址。为此我们为 $L$ 再设置一个综合属性 offset。offset 只是一个临时变量，将该临时变量用于累加公式中的 $i_j \times w_j$ 这一项，从而计算数组引用的偏移量。那么这个时候，这个累积的偏移地址是 $i_1 \times 160$。

接下来我们继续向右扫描。当读入 $i_2$ 以后，我们可以连同前面这个 $L$ 一起归约出一个新的 $L$。这个时候我们来计算 $L$ 的 type 属性。$L$ 表示的是数组元素 $A[i_1][i_2]$，那么 $A[i_1][i_2]$ 是 $A[i_1]$ 的一个元素，因此我们可以通过子节点的这个 type 属性中的元素的类型表达式来获得 $A[i_1][i_2]$ 的类型表达式，也就是 array 8 int。那么有了这个类型表达式，我们可以计算出来宽度 $w_2$，也就是等于 $4 \times 8 = 32$。这个时候我们来计算 $L$ 的 offset 属性，也就是累积的这个偏移地址，也就是说用子节点的 offset 值再加上新计算出的这个 $i_2 \times 32$。

接下来我们继续向右扫描。当读入 $i_3$ 以后，连同前面这个 $L$ 归约出一个新的 $L$。$L$ 的 type 属性是由子节点的 type 属性中的元素的类型表达式提供，也就是 int。那么它的宽度 $w_3$ 就是 4。这个时候我们来计算它的 offset 属性。offset 属性就是在子节点的 offset 属性的基础上再追加上新计算的这个 $i_3 \times 4$。

这样我们就完成了这个数组元素的偏移地址的计算。接下来我们需要加上它的基地址。为此我们为 $L$ 再设置一个 array 属性。array 是数组名在符号表的入口地址，我们将 array 属性沿着由若干个 $L$ 组成的链向上传递到数组元素所在的节点。这样这个数组元素的基地址和偏移地址都具备了，我们就可以计算它的实际地址。

根据以上的分析，我们来看数组元素的 SDT。我们还是通过这个例子来理解这个 SDT。那么这个数组元素它的地址的计算公式在这里。这个翻译方案中所有的语义动作都在产生式的末尾，因此我们还是可以采用自底向上的方式进行翻译。

这是输入的这个符号串对应的分析树。当我们将这三个标识符归约为表达式 $E$ 的时候，$E$ 的 address 属性分别是 $i_1, i_2, i_3$。也就是说这三个表达式的值存放在变量 $i_1, i_2$ 还有 $i_3$ 中。

接下来我们从左向右扫描。当读入 $A[i_1]$ 的时候，我们可以归约出非终结符 $L$。这个时候我们执行这样一段语义动作：首先调用 lookup 函数查询符号表，返回标识符 id 也就是 $A$ 在符号表中的入口地址，把它赋给 $L.array$。这里我们可以用名字来表示地址，因此 $L.array$ 就等于 $A$。

接下来我们来算 $L$ 的 type 属性。因为 $A[i_1]$ 是 $A$ 的一个元素，因此我们将 $L.array$ 也就是 $A$ 的类型表达式 type 中的元素 element 的类型表达式赋给 type 属性。这样 $L$ 的 type 属性就等于 `array(5, array(8, int))`。

接下来我们来计算 $L$ 的 offset 属性。我们调用 newtemp 函数生成一个新的临时变量，并把函数返回的临时变量的地址赋给 $L$ 的 offset 属性。我们假设新生成的这个变量名字叫 $t_1$，那么 $L$ 的 offset 属性就等于 $t_1$。

接下来我们生成一条三地址指令。这里 $L.offset = t_1$，$E.addr = i_1$。$L.type$ 的 width 通过这个类型表达式可以算出来 $5 \times 8 = 40$，$40$ 再乘上 4 等于 160。这样生成的三地址指令就是 `t1 = i1 * 160`。那么这里 $t_1$ 就是对这一部分偏移地址的计算。

接下来我们继续向右扫描。当读入 $i_2$ 以后，我们连同前面的这个 $L$ 归约出一个新的 $L$。这个时候我们执行这个产生式关联的语义代码：首先计算 array 属性。可以看出，array 属性是由子节点传递给父节点。接下来计算 type 属性。type 属性是由子节点的 type 属性中的元素 element 的类型表达式提供的，因此 `type = array(8, int)`。接下来我们需要生成一个新的临时变量用来计算这一部分偏移地址。假设新生成的变量名叫 $t_2$，那么 $t$ 就等于 $t_2$。接下来我们生成一条三地址指令，这里 $t = t_2$，$E.addr = i_2$。$L.type$ 的 width 根据这个类型表达式等于 $4 \times 8 = 32$。这样生成的三地址指令就是 `t2 = i2 * 32`。

接下来我们来计算 $L$ 的 offset 属性。为此我们调用 newtemp 函数生成一个新的临时变量，把函数返回的临时变量的地址赋给 $L.offset$。我们假设新生成的这个临时变量名叫 $t_3$，那么 $L$ 的 offset 就等于 $t_3$。接下来我们生成这样一条三地址指令：$L.offset = t_3$，$L_1.offset = t_1$，这个 $t$ 是刚才生成的临时变量 $t_2$。因此生成的三地址指令是 `t3 = t1 + t2`。这个 $t_3$ 存放在存放大就是这一部分累积的偏移地址。

接下来我们继续向右扫描。当读入标识符 $i_3$ 以后，连同前面的这个 $L$ 归约出一个新的 $L$。依然执行这个产生式关联的语义动作：首先计算 $L$ 的 array 属性，array 属性是由子节点传递给父节点。接下来计算 type 属性，type 属性是由子节点的 type 属性中的元素的类型表达式提供的。接下来我们需要生成一个新的临时变量用来计算这一部分偏移地址。假设新生成的临时变量它的名字叫 $t_4$，那么 $t$ 就等于 $t_4$。接下来我们生成三地址指令：$t = t_4$，$E.addr = i_3$。$L.type$ 的 width 等于 4，因此就是 `t4 = i3 * 4`。

接下来我们来计算 $L$ 的 offset 属性。调用 newtemp 函数生成一个新的临时变量，把函数返回的临时变量的地址赋给 $L.offset$。假设新生成的临时变量名字叫 $t_5$，那么 offset 的属性值就是 $t_5$。接下来生成三地址指令：$L.offset = t_5$，$L_1.offset = t_3$。这个 $t$ 现在是 $t_4$，也就是说 `t5 = t3 + t4`。

这样我们就完成了数组元素的偏移地址的计算。接下来我们将 $L$ 归约为表达式 $E$。根据这个产生式对应的语义动作：首先计算 $E$ 的 address 属性，调用 newtemp 函数生成一个新的临时变量，把函数返回的临时变量的地址赋给 $E.addr$。假设新生成的临时变量名字叫 $t_6$，那么 $E.addr$ 就等于 $t_6$。接下来生成三地址指令：$E.addr = t_6$，$L.array = A$，$L.offset = t_5$。因此对应的三地址指令就是 `t6 = A[t5]`。

这样我们就完成了这样一个输入片段的翻译。我们来看一下，这段代码，这段三地址码就是用来计算这个数组元素的地址。首先用 $i_1 \times 160$ 得到这一部分偏移地址，把它存放在 $t_1$ 中。接下来用 $i_2 \times 32$ 计算这一部分偏移地址，把它存放在 $t_2$ 中。然后将这两部分加在一起的偏移地址存放在临时变量 $t_3$ 中。接下来计算这一部分偏移地址存放在 $t_4$ 中，然后将前两部分的累积的偏移地址 $t_3$ 加上 $t_4$ 等于总的偏移地址。将总的偏移地址加上数组的基地址，得到了数组元素的地址 $t_6$。

根据这个产生式对应的语义动作，也就是说，当给一个数组元素赋值的时候，那么生成的三地址指令就是 `L.array[L.offset] = E.addr`。

同学们好，下面我们来学习控制流语句及其SDT。

我们说程序设计语言的控制流程一般分为三种，分别是顺序结构、分支结构和循环结构。分支结构比如说 if 语句、case 语句；循环结构比如说 while 语句、for 语句、repeat 语句等等。这里我们给出控制流语句的基本文法。

这里 $S$ 用于生成一个可执行语句的序列。那么一个可执行语句既可以是一个赋值语句，也可以是一个分支语句（这里分支语句我们以 if 语句为例），还可以是一个循环语句（这里循环语句我们以 while 语句为例）。那么可执行语句序列可以构成一个程序 $P$。

下面我们来看一下控制流语句的代码结构。这里我们以 if-then-else 语句为例。这个 if 语句 $S$，它的代码是由三部分构成，分别是布尔表达式 $B$ 的代码，加上 $S_1$ 的代码，加上 $S_2$ 的代码。我们说布尔表达式 $B$ 被翻译成由跳转指令构成的跳转代码，那么这些跳转代码根据布尔表达式的值来选择下一个执行点。当 $B$ 的值为 true 的时候，那么执行 $S_1$ 的第一条指令；当 $B$ 的值为 false 的时候，执行 $S_2$ 的第一条指令。当 $S_1$ 执行完以后，我们需要跳转到 $S$ 之后的下一条指令，因此我们需要生成一条跳转指令 `goto S.next`。

`S.next` 表示的是一个地址，这个地址中存放了紧跟在 $S$ 代码之后的下一条指令的标号。那么紧跟在 $S$ 代码之后的下一条指令，我们也称为是 $S$ 的后继指令。也就是说我们用指令的标号来标示一条三地址指令，这里指令的标号实际上就是一个序号。我们把 next 作为 $S$ 的继承属性。既然 $S$ 有继承属性 next，那么 $S_1$ 和 $S_2$ 就都有 next 属性。$S_1$ 和 $S_2$ 执行完以后，都将执行 $S$ 之后的第一条指令，也就是 `S.next` 指向的指令。因此 $S_1$、$S_2$ 还有 $S$，它们的 next 属性指向的是同一个指令。

我们说在布尔表达式 $B$ 的代码中包含一些跳转指令，这些跳转指令根据 $B$ 的值来选择下一个执行点，因此我们要为 $B$ 设置两个出口，分别表示当 $B$ 的值为真的时候跳转到的目标指令，和当 $B$ 的值为假的时候跳转到的目标指令。这样我们要为 $B$ 也设置两个继承属性：`B.true` 和 `B.false`。它们都是地址，地址中分别存放了当 $B$ 的值为真实或者假时，控制流转向的指令的标号。

那么定义好了文法符号的属性，接下来我们来编写控制流语句的SDT。

对于第一个产生式 $P \to S$：首先，因为 $S$ 具有继承属性 next，因此在 $S$ 出现之前的语义动作中，我们要计算 $S$ 的 next 属性。我们这里调用 newlabel 函数。newlabel 函数生成一个用于存放标号的临时变量 $L$，返回变量的地址。我们将函数返回的变量地址赋给 `S.next`。这个变量中将存放 $S$ 执行完以后的下一条指令的标号。当 $S$ 分析完毕以后，也就是说 $S$ 的代码都生成完以后，那么我们就可以确定 $S$ 之后的下一条指令的标号，因此这个时候我们调用 label 函数。label 函数将下一条三地址指令的标号赋给 $L$，在这里就是 `S.next`。也就是说这个时候我们将下一条指令的标号赋给 `S.next`。由此可见，在 $S$ 之前的这个语义动作只是确定了 $S$ 的后继指令标号的存放地址，但是这个标号的具体值要等 $S$ 分析完毕之后的这个语义动作中填入。这就相当于在旅店为客人先预定一个房间，等客人到达以后再入住。那么这里 `S.next` 就相当于一个房间号，那么在 $S$ 出现之前，这个房间号是可以预先确定的。

在生成的三地址码中，$L_1$ 到 $L_5$ 是用来存放标号的变量的地址，那么我们需要再进行一趟处理，将标号同对应的地址绑定起来。这里我们用蓝色数字标出这些地址中存放的标号，分别是：$L_3$（$L_3 = 3$）、$L_1$（$L_1 = 11$）、$L_4$（$L_4 = 5$）、$L_5$（$L_5 = 8$）、$L_2$（$L_2 = 1$）。

下面我们来检验一下生成的三地址码是否正确。首先，如果 $a < b$，那么这个布尔表达式的值就为真值，因此我们就进入 while 循环，然后我们就跳转到第三条指令来判断 $c$ 是否小于 $d$。如果 $c < d$，那么就应该跳转到这条语句去执行 $x = y + z$。因此，如果 $c < d$ 就跳转到 5 号指令去执行 $x = y + z$。执行完以后，执行完 $x = y + z$ 以后，我们需要回到 while 语句的第一条语句，来重新判断 $a$ 是否小于 $b$。
