同学们好，下面我们来学习归纳变量的删除。

对于在强度削弱算法中引入的复制语句 $j = t$，如果在归纳变量 $j$ 的所有引用点都可以进行复制传播的话，并且 $j$ 在循环的出口处不活跃，那么就可以删除复制语句 $j = t$。

我们来看一个例子。在前面的强度削弱的过程中，基本块 B2 中引入了一条复制语句 $t_2 = s_2$。我们可以看出，$t_2$ 有唯一的引用点，就是 $t_3 = A[t_2]$ 中的这个 $t_2$。我们可以看出，这里的 $t_2$ 可以被 $s_2$ 代替，因此这条复制语句就可以被删除掉。

我们来看一下，这里的 $t_2$ 被 $s_2$ 代替了，复制语句 $t_2 = s_2$ 被删除。

同样的道理，在基本块 B3 中引入的复制语句 $t_4 = s_4$，其中 $t_4$ 唯一的引用点，$t_5 = A[t_4]$ 中的 $t_4$，也可以被 $s_4$ 代替，因此这条复制语句也可以被删除。在这里，我们用 $s_4$ 来代替 $t_4$，并且将复制语句 $t_4 = s_4$ 删除。

在强度削弱后，有些归纳变量的作用只是用于测试。如果可以用对其他归纳变量的测试来代替对这种归纳变量的测试，那么就可以删除这种归纳变量。

具体来说，对于仅用于测试的基本归纳变量 $i$，我们取 $i$ 族的某个归纳变量 $j$。这里我们尽量使得 $c$ 和 $d$ 简单，也就是说 $c = 1$ 或者 $d = 0$ 的情况。我们把每个对 $i$ 的测试替换成对 $j$ 的测试。

这里分为两种情况：

第一种情况，在条件跳转指令中，关系表达式中的两个运算分量，其中的一个 $i$ 是基本归纳变量，另一个 $x$ 不是归纳变量。那么，我们假设 $j = c \times i + d$，那么 $i$ 与 $x$ 满足这种关系，就相当于 $j$ 与 $c \times x + d$ 满足这种关系。这里我们假设 $c$ 是大于 0 的。因此，这条跳转指令就可以被替换成这条跳转指令。

第二种情况，在条件跳转指令中，关系表达式的两个运算分量 $i_1$ 和 $i_2$ 都是基本归纳变量。在这种情况下，如果我们能够分别找到 $i_1$ 族和 $i_2$ 族的两个归纳变量 $j_1$ 和 $j_2$，并且使得这两个归纳变量对应的三元组中的 $c$ 和 $d$ 都是相同的。在这种情况下，$i_1$ 和 $i_2$ 满足这种关系，就等价于 $j_1$ 和 $j_2$ 满足这种关系。这里我们还是在假设 $c > 0$ 的情况。这个时候，我们就可以将这条跳转指令替换成这条跳转指令。

如果找不到这样两个归纳变量 $j_1$ 和 $j_2$，那么测试的替换可能是没有价值的，因为我们还要引入乘法或加减运算。如果这些跳转指令可以被替换的话，那么基本归纳变量 $i$ 将不再被引用，可以删除和它们相关的指令。

我们再回到前面的例子。在经过强度削弱以后，基本归纳变量 $i$ 和 $j$ 的唯一用途就是在基本块 B4 中用于测试循环是否结束。那么这个时候，我们可以找到 $i$ 族和 $j$ 族的两个归纳变量 $s_2$ 和 $s_4$。$s_2$ 的三元组是 $(i, 4, 0)$，$s_4$ 的三元组是 $(j, 4, 0)$，也就是说，这两个归纳变量它们的三元组中的 $c$ 和 $d$ 恰好是相同的。这个时候，$i \ge j$ 我们就可以替换成 $s_2 \ge s_4$。

这个时候，基本归纳变量 $i$ 和 $j$ 在流图中将不再被引用，因此可以将这两条指令删除掉。这样，我们就又删除掉了两个归纳变量。

[听音转录 · P79 9-4寄存器的选择]
> 来源：**听音转录**——非平台字幕，由讲师原声转录

同学们好，下面我们来学习寄存器的选择。我们在前面曾经讲过，有效地利用寄存器对于代码生成是非常重要的。

事实上，在为每个形如 $x = y \text{ op } z$ 的三地址指令生成目标代码的时候，我们要执行以下的操作：首先，调用一个称为 getReg 的函数来为指令中的 $x, y, z$ 分别选择一个寄存器，把这些寄存器分别称为 $R_x, R_y$ 和 $R_z$。接下来，对于所选择的寄存器 $R_y$，如果 $R_y$ 中当前存放的不是 $y$，那么需要生成一条加载指令 LD $R_y, y'$，这里 $y'$ 是存放 $y$ 的内存地址之一。类似地，对于所选择的寄存器 $R_z$，如果 $R_z$ 中当前存放的不是 $z$，那么也要生成相应的加载指令。最后我们生成目标指令 OP $R_x, R_y, R_z$。

在代码生成过程中，我们需要一定的数据结构来说明哪些变量的值当前存放在哪些寄存器中。另外我们还需要知道，一个变量的内存地址中存放的值是否是该变量的正确值。因为该变量的最新值可能刚在寄存器中计算出来，还没有保存回它的内存地址中。为此，我们需要定义两种数据结构，分别是寄存器描述符和地址描述符。

其中，寄存器描述符用来记录每个寄存器当前存放的是哪些变量的值；而地址描述符用来记录运行时每个名字的当前值存放在哪个或哪些位置。这些位置可能是寄存器、栈单元、内存地址，或者是它们的某个集合。这些信息可以存放在该变量名对应的符号表条目中。

另外，在基本块的结尾处，我们可能需要一些收尾处理。也就是说，对于一个在基本块的出口处可能活跃的变量 $x$，如果它的最新值还存放在某个寄存器中，而没有保存回它的内存地址中，那么我们就需要生成相应的保存指令，将该变量的值保存回它的内存位置。

下面我们来看一下如何管理寄存器和地址描述符。当代码生成算法生成加载、保存和其他指令的时候，它必须同时更新寄存器和地址描述符。

对于加载指令 LD $R, x$，这条指令是将变量 $x$ 的值加载到寄存器 $R$ 中。因此，我们首先要修改 $R$ 的寄存器描述符，使它只包含 $x$；同时，我们还要修改 $x$ 的地址描述符，把 $R$ 作为新的位置加入到 $x$ 的地址集合中。由于 $R$ 中此时存放了 $x$ 的值，因此我们要从任何不同于 $x$ 的地址描述符中删除 $R$。

对于运算指令 OP $R_x, R_y, R_z$，这条指令更新了变量 $x$ 的值，并把它存放在寄存器 $R_x$ 中。因此，我们首先要修改 $R_x$ 的寄存器描述符，使它只包含 $x$。由于 $x$ 的新的值已经存放在了 $R_x$ 中，因此我们要从所有不同于 $R_x$ 的寄存器描述符中删除 $x$。这条指令更新了 $x$ 的值，因此我们要修改 $x$ 的地址描述符，使它只包含位置 $R_x$。由于此时寄存器 $R_x$ 用来存放变量 $x$ 的值，因此我们要从任何不同于 $x$ 的地址描述符中删除 $R_x$。

接下来我们来看保存指令。这条指令将 $x$ 的值保存到它的内存地址中，因此我们需要修改 $x$ 的地址描述符，使它包含自己的内存位置。

值得注意的是，对于形如 $x = y$ 的复制语句，我们假设 getReg 函数总是为 $x$ 和 $y$ 选择同一个寄存器。因此，如果需要生成加载指令 LD $R_y, y'$，那么在生成加载指令并像处理所有加载指令那样处理完各个描述符之后，我们还要增加两个额外的操作。这里因为 getReg 函数为 $x$ 和 $y$ 选择了同一个寄存器，因此寄存器 $R_y$ 中也存放了 $x$ 的值，所以我们要修改 $R_y$ 的寄存器描述符，使它也包含 $x$。那么这条语句更新了 $x$ 的值，把它存放在了寄存器 $R_y$ 中，因此我们要修改 $x$ 的地址描述符，使它只包含 $R_y$。

下面我们来看一个例子。假如说我们要为由以下几条三地址指令构成的基本块生成目标代码。这里我们假设 $t, u, v$ 是该基本块的局部临时变量，而变量 $a, b, c, d$ 在基本块的出口处活跃。这里我们需要给出各个寄存器的描述符和各个变量的地址描述符。初始的时候，各个寄存器中不存放任何值，而变量 $a, b, c, d$ 的值存放在它们各自的内存地址中。

首先，我们为第一条三地址指令生成三条目标指令，也就是分别将变量 $a$ 和 $b$ 的值加载到寄存器 R1 和 R2 中，然后将 R1 中的 $a$ 值减去 $b$，并将得到的运算结果，也就是 $t$ 的值，存放在寄存器 R2 中。这里我们使用 R2 来存放 $t$ 的值，是因为原先存放在 R2 中的 $b$ 的值在基本块中将不再被使用。对于第一条指令，将变量 $a$ 的值加载到了寄存器 R1 中，因此我们先修改 R1 的寄存器描述符，使它只包含 $a$。同时，我们要修改 $a$ 的地址描述符，增加位置 R1。对于第二条指令，将变量 $b$ 的值加载到寄存器 R2 中，因此我们先修改 R2 的寄存器描述符，使它只包含 $b$。同时，修改 $b$ 的地址描述符，增加位置 R2。第三条指令更新了变量 $t$ 的值，把它存放在了 R2 中，因此我们要修改 R2 的寄存器描述符，使它只包含 $t$。同时，修改 $t$ 的地址描述符，使它只包含位置 R2。这个时候，寄存器 R2 用来存放变量 $t$ 的值，因此我们需要从任何不同于 $t$ 的地址描述符中删除 R2，因此这个 R2 将被删除。

对于第二条三地址指令，它对应以下两条目标指令：我们说 $a$ 的值已经存放在寄存器 R1 中，那么我们为 $c$ 选择了寄存器 R3，把 $c$ 加载到了寄存器 R3 中。因此，我们先修改 R3 的寄存器描述符，使它只包含 $c$。同时，我们修改 $c$ 的地址描述符，增加位置 R3。那么第二条指令更新了变量 $u$ 的值，将它存放在了寄存器 R1 中。因此，我们修改 R1 的寄存器描述符，使它只包含 $u$。同时，修改 $u$ 的地址描述符，使它只包含位置 R1。这个时候寄存器 R1 用来存放变量 $u$ 的值，因此我们要从任何不同于 $u$ 的地址描述符中删除 R1，因此这个 R1 将被删除。

对于第三条三地址指令，$t$ 的值已经在寄存器 R2 中，$u$ 的值在寄存器 R1 中。因此，我们将这两个值相加，得到变量 $v$ 的值，将它存放在寄存器 R3 中。那么这个时候修改 R3 的寄存器描述符，使它只包含 $v$；同时修改 $v$ 的地址描述符，使它只包含地址 R3。这个时候寄存器 R3 用来存放变量 $v$ 的值，因此我们从任何不同于 $v$ 的地址描述符中删除 R3，因此这个 R3 将被删除。

下一条语句是复制语句。这里我们为 $d$ 选择了寄存器 R2，将 $d$ 的值加载到寄存器 R2 中。因此，我们修改 R2 的寄存器描述符，使它只包含 $d$。同时，我们修改 $d$ 的地址描述符，增加位置 R2。这个时候，寄存器 R2 用来存放变量 $d$ 的值，因此我们要从所有不同于 $d$ 的地址描述符中删除 R2，也就是把这个 R2 删除。对于这个复制语句，我们说 getReg 函数为 $a$ 和 $d$ 选择了同一个寄存器，因此 $a$ 的值也存放在寄存器 R2 中。因此我们修改 R2 的寄存器描述符，使它也包含 $a$。由于这条语句更新了 $a$ 的值，把它存放在了 R2 中，因此我们要修改 $a$ 的地址描述符，使它只包含 R2。

对于最后一条指令，$v$ 的值已经在寄存器 R3 中了，$u$ 的值已经在寄存器 R1 中了，因此将这两个值相加得到 $d$ 的值，把它放在 R1 中。因此我们修改 R1 的寄存器描述符，使它只包含 $d$。由于 $d$ 的最新值已经存放在了寄存器 R1 中，因此我们从所有不同于 R1 的寄存器描述符中删除 $d$。这条语句更新了 $d$ 的值，把它存放在了 R1 中，因此我们修改 $d$ 的地址描述符，使它只包含 R1。这个时候由于寄存器 R1 中存放了变量 $d$ 的值，因此我们要从所有不同于 $d$ 的地址描述符中删除 R1，也就是将这个 R1 删除。

这样，这五条三地址语句都处理完了。这个时候我们发现，变量 $a$ 和 $d$ 的值还存放在寄存器 R2 和 R1 中，而没有存放到它们各自的内存地址中。因为 $a, b, c, d$ 在基本块的出口处是活跃的，因此我们要增加一个收尾工作，也就是说将 $a$ 和 $d$ 的值保存回它们的内存位置，因此生成两条保存指令。生成完这两条保存指令以后，要修改 $a$ 和 $d$ 的地址描述符，使它们包含 $a$ 和 $d$ 的内存地址。

同学们好，下面我们来学习寄存器选择函数 getreg 的设计。

我们说 getreg 函数首先要为 $y$ 和 $z$ 分别选择一个寄存器，这两次选择面对的问题是相同的。这里我们将集中考虑为变量 $y$ 选择寄存器 $R_y$ 的方法。

方法如下：首先我们先来判断变量 $y$ 是否已经在某个寄存器 $R$ 中了。如果是的话，我们就可以选择这个寄存器，从而省略掉一个加载的操作。如果不是的话，那么我们继续判断是否还有空的寄存器 $R$，如果有的话，我们就选这个寄存器 $R$。否则的话，无论如何我们要选择一个可行的寄存器 $R$。那么对于这个选择出来的寄存器，我们可能需要生成必要的保存指令，将寄存器中已有的值保存到它的内存地址中。

因此我们要为每个候选的寄存器 $R$ 计算一个费用，这个费用对应着需要生成的保存指令的个数，我们将选择费用最低的寄存器。

下面我们来看如何计算一个寄存器 $R$ 的费用。

对于一个寄存器 $R$，首先初始的时候，我们将它的费用值设置为 0。我们令 $n$ 等于寄存器 $R$ 中存放的变量 $v$ 的个数。接下来，我们依次考虑寄存器 $R$ 中存放的各个变量 $v_i$。

初始的时候我们令 $i = 1$。然后我们来判断变量 $v_i$ 是否还保存在寄存器 $R$ 之外的某处。如果是的话，那么我们就可以省略掉一条保存指令。

否则的话，我们进一步判断 $v_i$ 是否是这个指令要计算的变量 $x$。如果是的话，说明 $v_i$ 也就是 $x$ 的值马上就要被更新了。这个时候我们进一步判断 $x$ 是否是该指令的运算分量之一，也就是这里的 $z$。如果不是的话，说明 $x$ 在更新之前将不再被使用，因此我们不需要将它保存。

如果以上情况不满足的话，我们就要进一步判断 $v_i$ 在此后是否还使用。如果不再使用，那么就不需要保存这个变量的值。否则的话，我们就需要生成一条保存指令，因此它的费用就要加 1。

接下来我们来判断 $i$ 是否等于 $n$。如果不等于 $n$，我们就令 $i$ 的值加 1，接下来去分析下一个变量。如果 $i = n$ 的话，说明寄存器 $R$ 中的所有变量都已经分析完毕。这个时候我们输出总的费用值，就得到了这个寄存器 $R$ 的费用。

接下来，getreg 函数还要为 $x$ 选择寄存器 $R_x$。$R_x$ 的选择方法与 $R_y$ 类似，区别之处在于因为 $x$ 的一个新值正在被计算，因此只存放了 $x$ 的值的寄存器对于 $R_x$ 来说总是可接受的，即使 $x$ 就是 $y$ 或 $z$ 之一。

另外，如果 $y$ 在指令 $I$ 之后不再使用，而且 $R_y$ 中仅仅保存了 $y$ 的值，那么 $R_y$ 同时也可以用作 $R_x$。对 $z$ 和 $R_z$ 也有类似的选择。

最后值得注意的是，当 $I$ 是复制指令 $x = y$ 的时候，那么我们按照上述方法选择好 $R_y$ 之后，可以直接令 $R_x = R_y$。

同学们好，下面我们来学习窥孔优化。

所谓窥孔，是程序上的一个小的滑动窗口。窥孔优化，就是在优化的时候，检查目标指令的一个滑动窗口，也就是窥孔，并且只要有可能，就在窥孔内用更快或更短的指令来替换窗口中的指令序列。事实上，某些窥孔优化技术也适用于中间代码的优化。

这一节我们将介绍几个具有窥孔优化特点的程序变换的例子，分别是冗余指令的删除、控制流优化、代数优化和机器特有指令的使用。

我们首先来看冗余指令的删除。

首先，我们可以删除一些冗余的加载和保存指令。在前面给出的这个例子中，会生成形如这样的代码序列，也就是加载了一个刚刚存放到内存中的值。那么这个时候第四条指令就是一个冗余的加载指令，我们可以将它删除。值得注意的是，如果第四条指令之前有一个标号，也就是说某条指令可能会跳转到第四条指令，那么我们就不能保证第三条指令总是在第四条指令之前执行，这个时候就不能删除第四条指令。

另外的一种冗余指令是不可达代码。比如说，一个紧跟在无条件跳转指令之后的不带标号的指令，就是不可达代码，可以将其删除。例如，为了调试的目的，在某些大型程序中可能会包含这样的代码序列：

```c
if debug == 1 goto L1
```

去打印调试信息，然后再执行 L2 开始的指令。这个代码序列可以等价变换成这样的代码序列，也就是：

```c
if debug != 1 goto L2
```

直接去执行 L2 开始的指令。如果在程序开始的时候，我们将 debug 设置为 0，那么通过复制传播，第一条指令就可以等价变换成：

```c
if 0 != 1 goto L2
```

那么第一条指令中的条件表达式的值总是 true，因此它就相当于是一条无条件跳转指令。这样，在这个无条件跳转指令之后的不带标号的指令就变成了不可达代码，可以将它们删除。

下面我们来看控制流的优化。

如果在代码中出现了跳转到跳转指令的指令，那么在某些条件下，可以使用一个跳转指令来代替。例如，对于这样的代码序列：

```c
if a < b goto L1
...
L1: goto L2
```

L1 又是直接跳转到 L2 的无条件跳转指令，那么这个代码序列可以等价变换成：

```c
if a < b goto L2
```

这个时候如果没有其他指令跳转到标号为 L1 的指令，并且标号为 L1 的指令之前是一条无条件跳转指令的话，那么这条指令是可以删除的。

接下来我们来看代数优化。所谓代数优化，就是利用代数规则来进行优化。例如，我们可以利用代数恒等式来消除窥孔中类似于 $x = x + 0$ 或 $x = x \times 1$ 的运算指令。

另外我们也可以进行强度削弱，也就是用运算代价低的指令来代替运算代价高的指令。例如，对于乘数或者除数是 2 的幂的定点数乘法或除法，我们用移位运算来实现，代价会比较低。另外，除数为常量的浮点数除法，可以通过乘数为该常量倒数的乘法来求近似的值。

除此之外，我们可以充分利用目标系统的某些高效的特殊指令来提高代码的效率，比如说我们用 inc 指令来代替加 1 操作。
