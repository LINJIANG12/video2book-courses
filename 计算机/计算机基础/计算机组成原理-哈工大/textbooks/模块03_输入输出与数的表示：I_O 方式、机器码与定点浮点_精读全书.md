## 输入输出系统概述：从分散连接到 I/O 处理器
> 对应块：BLK16 | 覆盖分集：P52-P54 | 块标题（分集名）：《5.1 概述 5.1-a1》

从今天开始，我们进入第五章——输入输出系统。这是计算机组成原理硬件部分的最后一块。这一章我们要介绍六方面的内容：先简要介绍输入输出系统的概况，也就是本节 5.1；接着会简要介绍计算机系统的外部设备；5.3 介绍 I/O 接口的功能，以及为了完成这些功能 I/O 接口应该具有什么样的结构；5.4、5.5、5.6 介绍 I/O 设备与主机信息传送的三种主要控制方式。这里要提醒一句：这三种控制方式并不全面，在介绍的过程当中，我们还会对另外两种控制方式做简要的介绍。

### 为什么输入输出系统值得单独一章

输入输出系统是计算机系统当中种类最多、功能最多、结构最复杂、构成也最多样的一套系统。有一个数字大家可以体会一下：在现代计算机系统当中，外部设备的总成本可以占到计算机总成本的 80% 以上。可以说，没有这些丰富多彩的外部设备，就没有现代计算机在各个领域的大规模应用。

这个局面不是一天形成的。早期的计算机任务比较少，它所面临的核心任务就是计算，全球计算机的数量也非常少，外部设备的种类就更少。随着计算机的发展，比如到了 60 年代，计算机开始被应用到文本处理当中，就产生了字符发生器和字符型的显示器。计算机再往前发展，在多媒体、嵌入式计算等领域被大规模应用——比如把嵌入式计算机系统装载到自动设备当中、装载到武器装备当中，去控制设备或者武器，让这些设备能够自主地进行工作。到现代，计算机的应用就更加广泛了：互联网，甚至产生了"网络就是计算机"这样的概念；还有物联网、云计算、物理信息系统，以及最近最流行的一个词——互联网+。所有这些应用，背后都离不开丰富多彩的外部设备。

### I/O 系统的发展：I/O 操作一步步从 CPU 中分离出来

#### 分散连接与程序查询

早期的计算机数量少、应用少、外部设备也非常少，外部设备和主机之间采用**分散连接**的方式：每一个设备都有专门的控制线路，这些控制电路甚至和 CPU 的控制电路设计在一起，集中耦合。这个时候增加和删除外部设备都非常难。但由于当时外部设备的数量比较少、计算机的数量也非常少，这种设计还是值得的。

这个时期，外部设备和主机之间的信息传送主要采用**程序查询方式**。在这种方式当中，CPU 的工作和 I/O 的工作是串行进行的：I/O 进行数据输入输出的时候，CPU 必须运行相应的程序，或者处在等待状态。

#### 接口与 DMA 控制器的出现

随着计算机的发展，外部设备越来越多，分散连接的方式已经不适应外部设备的发展、计算机技术的发展以及计算机应用领域的扩展。这种情况下就出现了 I/O 接口，出现了 DMA 控制器——由 I/O 接口和 DMA 控制器与主机、CPU 相互配合，完成数据的输入和输出操作。

连接方式也发生了变化：采用**总线**进行连接。I/O 设备通过接口连接在总线上，一个总线可以连接多个设备，总线的另一端和主机相连。传输控制方式随之改变，要求 CPU 和 I/O 之间能够并行工作，于是出现了另外两种信息交换的控制方式——**中断方式**和 **DMA 方式**（5.5 和 5.6 中会详细介绍）。

#### 通道与 I/O 处理机

在中断和 DMA 这两种方式当中，信息传输过程当中或者信息传输完成之后，CPU 仍要参与部分信息传输的处理工作。为了使 CPU 的工作和 I/O 的工作能够进一步并行起来，又出现了具有通道结构的 I/O 系统。**通道**可以看作是一种简单的处理器，或者是一个小型的、功能更强的 DMA 控制器：它能够执行通道程序，有自己的指令系统，通过执行通道程序，可以控制连接在通道上的 I/O 设备和主机之间直接进行信息传输。

比通道方式更进一步的，是 **I/O 处理器**。I/O 处理器可以是专用的处理器；在大型计算机当中，可以使用现代的微处理器直接作为 I/O 处理器来控制 I/O 设备的工作；也有一些大型计算机直接采用和主机当中完全相同的处理器来充当 I/O 处理器。这个时候的 I/O 处理机功能非常强大，甚至在没有 I/O 设备工作的时候，I/O 处理机可以作为主机的处理器完成相应的计算任务。

> **结论**：从这一段发展概况当中，大家要看到一个事实——随着 I/O 系统的发展，数据的输入输出操作逐渐地从 CPU 当中分离了出来。这一条主线贯穿整章。

### I/O 系统的组成：软件与硬件

I/O 系统的组成分为软件和硬件两大部分。

#### I/O 指令

软件我们先看第一块：CPU 指令集当中的 I/O 指令。程序员把这些 I/O 指令编写到应用程序当中，CPU 执行这些指令，控制外部设备，使外部设备和 CPU、主机之间能够协调地进行工作。

I/O 指令的格式分两部分。第一部分是**操作码**。实际上 I/O 指令的操作码相当于 I/O 指令的一个标志——它表示这条指令是 I/O 指令，指出了要对 I/O 设备做什么样的操作，比如说对 I/O 设备进行查询、进行输入、进行输出，以及进行其他的控制。第二部分是**设备码**，给出的是 I/O 设备的编码，也就是 I/O 设备的地址，或者是 I/O 设备当中某一个寄存器的地址——这些寄存器我们把它叫做 I/O 的端口。

#### 通道指令与广义 I/O 指令

软件的第二块是通道指令。前面说过，通道是一种小型的 DMA 处理器，能够实现 I/O 设备和主机之间直接进行信息传送；通道有自己的控制器，有的通道还有自己的存储器，能够执行由通道指令组成的通道程序——通道指令就是通道自身的指令。

通常情况下，编程人员并不会直接写通道指令。为了调用外部设备，应用程序当中需要增加**广义 I/O 指令**，它要指出：参加数据传输的 I/O 设备、数据传输在存储器中的首地址、传输数据的长度，以及传输的方向——是向 I/O 设备传输数据，还是向存储器传输数据。操作系统根据广义 I/O 指令给出的参数和要求的操作，编写一个由通道指令组成的通道程序，把通道程序放在内存或者通道自己内存的指定位置，然后启动通道进行工作。通道拿到通道程序的首地址以后，就可以执行通道程序，控制 I/O 设备完成相应的输入输出工作。

所以通道指令的参数要指出：要传输的成块数据（数组）的首地址；当然通道也可以传输单个字节，那就要指出这个字节在内存当中的哪一个地址，或者要把这个字节传输到内存当中的哪一个地址；如果是一组数据，还要指出传输的字数、传输的方向、设备地址等等。这些参数都要由通道指令指出，所以通道指令一般会比较长——比如 IBM 370 的通道指令长度是 64 位。

通道的下边还可以带若干个**子通道**，子通道可以并行地工作；每个子通道下面可以连接多个设备控制器；每个设备控制器还可以连接多个设备。

#### 硬件组成

I/O 系统的硬件包括 I/O 设备本身，以及输入输出的接口设备——I/O 设备通过接口连接在总线上，和主机完成信息交换。如果采用通道方式，那么设备连接的是设备控制器，设备控制器连接子通道，子通道连接通道。这就是 I/O 系统硬件的简单组成。

### I/O 设备与主机的联系方式

这一节解决的是"主机和 I/O 设备如何进行联系"的问题。I/O 设备是有地址的，主机要和 I/O 设备之间进行联系，必须要给出 I/O 设备的地址。

#### 统一编址与单独编址

对 I/O 设备进行编址有两种方式。

第一种方式称为**统一编址**：把 I/O 设备的地址看成是内存地址的一部分。比如说内存地址一共是 1 兆，那么我们把这一兆地址当中的低地址部分或者高地址部分的 64K 拿出来，这部分地址就作为 I/O 设备或者端口的地址。如果输入输出指令或者访存指令的地址码部分落到了 I/O 地址部分，那么这一次的读写操作实际上是针对 I/O 设备进行的。在这种情况下，CPU 可以直接利用取数指令或存数指令对 I/O 设备进行访问和控制，**不需要单独的 I/O 指令**——只要取数、存数指令的地址码落到了 I/O 地址部分，这条指令就是对 I/O 设备进行操作的。因此采用统一编址的计算机系统，它的指令集会相对简单。什么情况下适合统一编址呢？如果内存系统的编址空间比较大，就可以拿出一部分地址空间作为 I/O 设备使用——比如说内存地址采用的是 64 位，寻址空间非常大。

第二种方式是**不统一编址**，也叫做**单独编址**：在内存地址空间之外专门设置一个地址空间。比如内存的地址空间是 20 位，寻址范围是 1 兆；对外部设备进行编址的时候，它的地址空间是从 16 个 0 到 16 个 1，也就是 64K。为了区分一条指令到底是对内存进行操作还是对 I/O 设备进行操作，在单独编址的计算机当中，输入输出就不能再借用原有的取数或存储指令了，**必须用专用的 I/O 指令**来对 I/O 设备进行控制和操作。

| 对比项 | 统一编址 | 单独编址 |
| :--- | :--- | :--- |
| I/O 地址来源 | 内存地址空间的一部分 | 内存之外专门设置的地址空间 |
| 使用什么指令 | 取数/存数等访存指令即可 | 必须设置专用的 I/O 指令 |
| 指令系统 | 相对简单 | 指令集要额外增加 I/O 指令 |
| 适用前提 | 内存编址空间足够大（如 64 位） | 内存编址空间有限（如 20 位 1 兆）时另设 64K I/O 空间 |

#### 设备选择电路

编完了地址以后要进行**选址**。选址通过一个设备选择电路来识别某一个设备是否被选中，这个电路相当容易：只要把 CPU 给出的地址和设备当中保存的自己的地址进行比较，如果两者相同，这个设备就被选中了。设备被选中之后，就可以开始进行数据传输。

#### 数据传送方式：串行与并行

数据传送方式在第三章当中实际上已经介绍过了。第一种方式是**串行传送**：数据一位一位地进行传输，传输速度比较慢，但适合进行远程传输。第二种方式是**并行传送**：同时有多位数据在数据线上进行传输，因此数据线有多条，通常情况下数据线的条数是 8 的倍数。

#### 联络方式：立即响应、异步与同步

联络方式说的是外部设备接收或者发送数据时的响应情况，一共三种。

**立即响应方式**。对一些结构简单的设备，状态数量也比较少，接收到数据或者输入数据的话，可以直接进行显示。比如我们的一些 LED 灯，接收到数据之后，直接就可以用亮或者不亮的方式来表示它接收到的数据的值。

**异步工作方式**。一般来说采用应答信号。异步既可以并行传输，也可以串行传输。CPU 和接口之间一般都是并行传输，所以这里讲的应答信号，主要是 I/O 接口和 I/O 设备之间采用的。并行传输时，I/O 接口和 I/O 设备之间要有多条数据线组成类似总线结构的数据线来完成数据的并行输入输出，双方之间还要采用应答信号。比如说 I/O 设备要接收数据：I/O 端口把数据准备好以后，通过一个信号告诉 I/O 设备"端口当中的数据已经准备好了"，I/O 设备对端口当中的数据进行读取，并且给出应答信号。反过来看输入：I/O 设备把数据通过 I/O 接口输入到 CPU 当中（主机当中），I/O 接口当中的数据缓冲器一旦空了，它就会向 I/O 设备发送信号，告诉 I/O 设备可以向 I/O 接口当中发送数据；I/O 设备向 I/O 接口发送数据，并且给出应答信号。

异步也可以通过**串行**的方式进行联络。串行数据的格式是：前面是命令字，中间是数据字，后面也是命令字。以串行异步传送一个数据字为例，要使这种工作方式能够正确进行，传输时首先要有**起始位**——9.09ms 的一个低电平；低电平结束之后是若干位数据位（我们这里是八位数据位）；传输结束以后给出两位高电平的**终止位**，用 $2 \times 9.09\,\text{ms}$ 表示这次传输（数据）结束。

```text
 ┌──────┬────────────────────────┬──────────┬──────────┐
 │起始位 │      数据位（8 位）     │  终止位   │  终止位   │
 │ 低电平│      D0 D1 … D7        │  高电平   │  高电平   │
 └──────┴────────────────────────┴──────────┴──────────┘
   9.09ms                            2 × 9.09ms（传输结束）
```

读图：先落一个 9.09ms 的低电平作为起始位，接着传 8 位数据位，最后用两个高电平的终止位收尾，一次串行异步传输结束。

**同步工作方式**。设备和主机之间如果要同步工作，必须有一个**定宽定距的时标**，通过这个时标控制在某一个时间点必须开始某一项工作、在某个时间点某一项工作必须结束。

### I/O 设备与主机的连接方式：辐射式与总线

连接方式其实在介绍 I/O 设备发展的时候就已经介绍过了，这里归纳成两种。

第一种方式教材上把它叫**辐射式连接**，实际上就是分散连接：主机和 I/O 设备分散式的连接，增加一个 I/O 设备，主机当中就需要增加一套控制电路来对它进行控制。在早期，由于外部设备数量比较少，采用这种方式也是合适的；但随着计算机的发展，外部设备越来越多，如果每一台设备都配一套控制线路、配一套信号线，会造成对主机系统增加或者删除设备都非常麻烦。另外，为一台主机系统设计的设备，要拿到另外一台机器上去使用，可移植性也非常弱。一句话：辐射式连接既不便于增删设备，也不便于设备的移植。

第二种方式就是采用**总线**进行连接：外部设备通过接口和主机进行连接。接口在这里承担几件事——向外部设备传送主机的控制命令；向主机传送外部设备的状态信息；完成数据缓存，外部设备的输入数据可以先缓存在接口当中，完成数据的格式转换等操作之后，再输入到主机；反过来，主机当中的数据也可以在接口当中缓存，经过格式变化等处理之后传输给外部设备。这种方式特别便于增删设备，因为接口一般会采用标准的方式——工业标准、国际标准或者国家标准——只要外部设备接入接口或主机时采用标准接口的方式，就很容易实现外部设备和主机的连接，也很容易实现外部设备的可移植性。

```text
                ┌── I/O 接口 ── I/O 设备
 主机 ── 总线 ──┼── I/O 接口 ── I/O 设备
                └── I/O 接口 ── I/O 设备
```

读图：设备都挂在标准接口后面、接口再挂上总线，增删设备只动接口这一层，主机一侧完全不用改。

### 信息传送的控制方式之一：程序查询

I/O 设备和主机信息传送的控制方式有五种，我们先介绍前三种里最早的一种——**程序查询方式**。在这种方式当中，CPU 和外设是采用串行方式进行工作的。

以数据输入为例。如果我们要从某一个外部设备上读一批数据进入计算机的内存，看看是怎么做的：首先 CPU 在程序当中要执行一条读操作的指令，向 I/O 设备发出读命令；发出读命令以后，CPU 开始读取 I/O 的状态——实际上是 I/O 接口当中状态触发器（状态标志）的值，看数据是否已经准备好。如果数据没有准备好，程序里有一条跳转指令，CPU 会不断地反复去读这个状态标志（查询的同时还要检查状态是否出错，出错则进入出错处理）；只有当状态标志显示数据已经准备好了，CPU 才可以从接口当中读出一个数据——这个数据可以是一个字节，也可以是一个字——先放到 CPU 的某一个寄存器当中，再把这个寄存器当中保存的数据写入到内存的指定位置。下一步判断这次传输是否结束：如果没有结束，CPU 还会通过程序向 I/O 设备发出读指令，接着又是查询状态、等待数据准备好……如此循环往复。

把核心过程抽出来看：外部设备的工作速度一般都比较慢，CPU 的工作速度很快。外部设备接收到 CPU 的指令以后开始数据准备，经过一段较长的时间数据才能准备好；准备好以后，数据被送入 I/O 接口当中的数据缓冲寄存器，然后把工作状态标志置为"设备准备好"（数据准备好）。CPU 只有查到了这个数据准备好的标志之后，才能开始进行数据传输：通过接口把数据先读入到 CPU 的某一个寄存器，再从寄存器转存入某一个内存单元。而在数据准备的整个过程当中，CPU 一直处于原地踏步的状态——没有去执行其他指令，没有去做其他的工作，CPU 的效率会非常低。

程序查询方式还有一个结构上的特点：内存和 I/O 之间要想进行数据交换，必须通过 CPU——先把数据送入 CPU 当中，然后才能通过 CPU 把数据送入指定的目标，这个目标可能是外部设备，也可能是内存的某一个存储单元。所以内存、CPU、I/O 三者之间的连接关系，可以看作是 **CPU 一手托两家**：

```text
        ┌──────────┐
        │   内 存   │
        └────┬─────┘
             │
        ┌────┴─────┐
        │   CPU    │  ← 一手托两家：任何信息交换都必须经过 CPU
        └────┬─────┘
             │
        ┌────┴─────┐
        │ I/O 接口 │
        └────┬─────┘
             │
        ┌────┴─────┐
        │ I/O 设备 │
        └──────────┘
```

读图：一边连着内存、一边连着 I/O 接口，外部设备慢、CPU 快，在原地踏步等待的过程当中消耗了 CPU 大量的时间，效率自然非常低。

> **易错点**：程序查询方式中 CPU 和 I/O 的工作是彻底串行的——I/O 工作的时候，CPU 在踏步；CPU 工作的时候，I/O 早已准备好了。这一点在后面的对比中要反复用到。

### 信息传送的控制方式之二：程序中断

程序中断方式是对程序查询方式的一个改进，它让 CPU 被一定程度地从数据的输入输出工作当中解放出来。怎么解放的？关键在于把 I/O 设备的工作分成两个阶段：第一个阶段是**数据准备阶段**，也就是 I/O 设备进行自身的准备、状态准备；第二个阶段才是**与主机交换信息**。在程序查询方式当中，这两个阶段 CPU 都要工作、都要参与；而程序中断方式对它进行了改进——在 I/O 设备或者 I/O 端口进行自身准备的时候，CPU 不进行查询；只有当外部设备和内存（主机）之间开始进行信息交换的时候，CPU 才暂停现行程序、把现行程序打断，然后为输入和输出进行服务。所以这种方式叫做中断方式，后面我们会详细介绍中断的定义。

看一下中断方式的过程。CPU 执行主程序，在执行过程当中碰到了一个 I/O 指令，执行这条指令，启动 I/O 设备进行数据准备（可能是数据输入，也可能是数据输出）。发出启动设备的指令以后，CPU 继续执行原来的程序。外部设备接收到启动命令以后开始进行状态准备；当外部设备准备好接收或者输入数据以后，它就会向 CPU 提出一个**中断请求**，让 CPU 停止对当前程序的执行，转而和 I/O 设备进行数据交换。假设 CPU 在执行第 $k$ 条指令的过程当中收到了外部设备发来的中断请求信号：CPU 在执行完第 $k$ 条指令以后，把这个程序断点和相关的程序现场进行保存，然后跳转到中断服务程序，通过执行这个中断服务程序来完成数据的输入输出操作。中断服务程序执行完这一次的输入输出操作之后，CPU 又转回到原来的程序——原来是在第 $k$ 条指令执行结束之后开始处理中断的，所以转回的时候恢复相关寄存器的内容，然后从 $k+1$ 条指令开始继续执行原来的程序。

```text
CPU    : 执行主程序 → 执行I/O指令(启动设备) → 继续执行主程序 → 第k条指令执行完
                                                      ↓ 保存断点/现场
         中断服务程序(完成I/O) → 恢复现场 → 从第k+1条继续执行主程序
                                   ↑
I/O设备 :      收到启动命令 → 设备自身准备(数据准备) → 准备就绪 → 发出中断请求 ┘
               |←———————————— CPU 与 I/O 并行 ————————————→|
```

读图：设备自身准备的整个阶段 CPU 都在执行主程序，没有踏步等待；只有真正要进行数据传输了，才由外部设备主动发起中断请求，请 CPU 协助完成数据的输入输出操作。

对比程序查询方式就清楚了：在设备自身准备阶段，程序查询里的 CPU 是踏步等待的，而中断方式里 CPU 依然在执行主程序；在数据输入输出的过程中、真正要进行数据传输的时候，CPU 才暂停现行程序，转而进行输入输出操作。所以中断方式实现了 **CPU 和 I/O 的部分并行**，CPU 被一定程度地解放出来——数据准备期 CPU 不需要参与，数据传输过程 CPU 才需要参与。

但是要注意，这种情况下对 CPU 的解放其实并不是非常彻底。因为传输过程当中仍然需要 CPU 的参与；而且要保证程序被中断以后、返回时能够正确地执行，中断的时候要保护现场、保存程序断点，程序返回的时候要恢复现场、恢复程序断点——这些都要靠指令来完成，是需要一定时间的。如果外部设备和内存（主机）之间进行信息传输的数据量非常小，比如说只传输一个字节，可能需要十几条甚至几十条指令来完成现场的保护或者恢复工作，依然要消耗 CPU 较大的时间。

程序中断方式的完整流程是：依然由 CPU 向 I/O 发出读指令（我们以读作为例子）；CPU 发出这个 I/O 读指令之后，CPU 的工作和 I/O 的工作开始并行进行——CPU 继续执行原来的程序，I/O 设备开始进行设备的准备工作，一直到准备就绪；之后由 I/O 设备向 CPU 发出中断请求，CPU 读取 I/O 的状态，确定到底是哪一个设备发出了中断请求，然后检查状态是否出错，如果出错就进行出错处理；如果没有出错，CPU 从 I/O 接口当中读一个字送到 CPU，再把这个字写入到内存当中；下一步进一步判断这个输入输出工作是否已经完成——如果已经完成，就做结束处理；如果没有完成，CPU 向 I/O 发出读下一个字的操作，如此循环，直到完成、结束。

### 信息传送的控制方式之三：DMA

第三种方式是 **DMA 方式**。这种方式把 CPU 进一步地从数据输入输出这个工作当中解放出来：外部设备和内存之间可以建立直接的连接，由 DMA 控制器（DMA 接口）直接控制外部设备和内存之间进行数据交换。它和前两种方式的差别在哪里？程序查询和程序中断当中，内存和 I/O 之间的数据交换都必须经过 CPU 这一双"手"；DMA 把这个通道直接打通了，不再事事劳驾 CPU。DMA 方式的详细内容，我们在后面专门展开。

## I/O 系统精读：DMA 方式、外部设备与 I/O 接口
> 对应块：BLK17 | 覆盖分集：P55-P57 | 块标题（分集名）：《5.1 概述 5.1-b2》

前面我们已经把程序查询方式和程序中断方式讲完了。这一篇从第三种 I/O 控制方式——DMA 方式讲起，然后把 I/O 系统的两大块基础内容补齐：外部设备有哪些、I/O 接口为什么存在又由什么构成。这三块合在一起，正好把"主机和外设之间到底怎么打交道"这个问题搭出一个完整的骨架。

### DMA 方式：让 CPU 彻底退出数据传送

#### 为什么中断方式还不够

先回顾一下中断方式下数据是怎么走的。不管是程序查询还是中断，内存、CPU、I/O 设备三者之间的连接关系都没变——CPU 始终在中间，内存和外设在两边。中断方式下要想把一个数据输入到内存，依然是先把数据读入 CPU，再由 CPU 写入内存；输出也一样。也就是说，**即使在中断方式当中，真正的数据传输过程依然需要 CPU 来做**，需要 CPU 通过执行程序的方式完成数据对主机的输入和输出。中断只是把 CPU 从"等待数据准备"里解放出来了，数据搬运这一步它还得亲自动手。

DMA 方式则可以进一步把 CPU 从数据输入输出这个工作中解放出来。它在内存和 I/O 设备之间建立了一条**直接通路**：内存通过 DMA 控制器可以直接和 I/O 设备进行数据交换，整个过程不需要 CPU 参与，也不需要中断现行程序的执行。

#### 周期窃取：一个存取周期的交易

DMA 控制器要控制内存和外设之间交换信息，就一定要使用总线——包括地址线、数据线、控制线。这些总线如果被 DMA 拿去用了，CPU 就得把总线的控制权让出来。让出多长时间？**就是一个存取周期**。

在这个存取周期当中，如果 DMA 需要完成 I/O 和内存之间的数据交换，那么这个存取周期就交给 DMA 使用，总线的控制权也一并交给它。这一个周期结束之后，总线的控制权、对内存的使用权又归还给 CPU，I/O 设备继续准备下一个数据，CPU 继续执行现行程序。这种用一个存取周期来"借用"总线的做法，就叫**周期挪用，或者叫周期窃取**。

#### DMA 工作时 CPU 在干什么

有一个问题值得想清楚：在 DMA 占用总线的那个存取周期里，CPU 难道就干等着吗？

不是的。在这个周期里 CPU 虽然不能使用系统总线、不能访问内存、不能进行访存操作，但它还是可以继续执行指令的。关键在于：现代处理器并不是每执行一条指令才去内存取一条指令——**指令是要预取的**。在指令执行之前，可能若干条指令已经被预取到 CPU 的指令缓冲当中了。只要这些指令不需要访存（或者在这个存取周期中不需要访存），CPU 就可以利用指令缓存中的指令和数据缓存中的数据，继续执行主程序里的指令。

所以在这个存取周期里，CPU 的操作和 DMA 控制器（或者说外部设备）的操作是可以**并行**的。整个工作过程可以画成这样：

```text
CPU       ：执行主程序 → 发出启动I/O指令 → 继续执行主程序 →（让出一个存取周期）→ 继续执行主程序
                                             ↑                     ↓
I/O设备/DMA：                准备数据 ………… → 发出DMA请求，占用总线
                                              ↑
内存        ←←←←←←←←←←←←←←←←← 在这一个存取周期内完成I/O与内存之间的数据交换
```

图上能看出来：CPU 只在数据交换的那一个存取周期里"靠边站"，之前之后都在跑自己的主程序；数据准备阶段则完全由外设在 DMA 控制器控制下自行完成。

#### 三种控制方式的 CPU 效率对比

程序查询、程序中断、DMA 三种方式放到同一张图上看，CPU 被解放的程度是一级一级递进的：

| 控制方式 | 数据准备阶段 | 数据传送阶段 | CPU 的处境 |
| :--- | :--- | :--- | :--- |
| 程序查询 | CPU 踏步查询 I/O 接口状态 | CPU 执行程序完成传送 | 大部分时间都在查询等待，效率最低 |
| 程序中断 | CPU 与外设**并行**工作 | CPU 执行中断服务程序完成传送 | 准备阶段解放了，传送时仍要 CPU |
| DMA | CPU 与外设**并行**工作 | DMA 控制器占用总线，直接在内存与外设间传送 | 只让出一个存取周期，可与 DMA 并行 |

程序查询方式里，CPU 执行到一条 I/O 指令、启动 I/O 之后，就开始对设备状态或 I/O 接口的状态进行查询，一直查询到数据准备好并完成数据传输，之后才能继续执行原来的程序——这当中大部分时间 CPU 都在等待外部设备做设备准备或自身准备。

程序中断方式里，CPU 发出启动 I/O 指令后就去执行原来的程序，外部设备开始数据准备；一旦 I/O 准备完成，就通过 I/O 接口向 CPU 发出中断请求。CPU 如果可以响应，在某一条指令执行周期结束的时候响应中断，转去执行中断服务程序——这个中断服务程序要完成的正是数据的输入输出操作。执行完再回到被中断的主程序。所以**在数据准备阶段，CPU 和外设是并行工作的**，CPU 在这个阶段被解放了出来。

DMA 方式则更进一步：外部设备数据准备结束后，会窃取一个存储周期（或者几个存储周期），在这个或这些存储周期中，外部设备和内存在 DMA 控制器的控制之下完成一个字（或几个字）的信息交换。与中断方式相比，**数据传送过程中不需要保存现场、不需要恢复现场、不需要执行中断服务程序、不需要用软件来完成数据输入输出的控制**——CPU 的效率被提得更高。

> **提示**：程序查询、程序中断、DMA 之外，还有通道方式和 I/O 处理机方式。这两种方式本课程不展开，建议去看计算机系统结构的教材——国内的计算机系统结构教材一般都有介绍。可以看到的规律是：随着 I/O 技术的发展，I/O 系统的自制能力越来越强。

### 外部设备：一个分类就够了

外部设备这一节只做简要介绍。虽然教材上篇幅非常大，但 I/O 设备种类实在太多，涉及物理、机械和计算机多个领域——要想把 I/O 设备讲清楚，绝不是计算机组成原理这一门课能解决的。所以这里的核心其实就一件事：**给外部设备做一个分类**。分类要给出标准，不同的分类标准会给出不同的分类。

I/O 设备（也就是外部设备）通过接口电路和主机进行连接。外部设备本身包括两大部分：一个是**设备控制器**，另一个就是外部设备的机电部分。主机通过 I/O 接口向设备控制器传输控制命令，控制外部设备进行相关操作；同样，主机通过 I/O 接口读取外部设备的状态——比如是忙还是已经准备好，等等。接口电路的功能和结构我们在后面专门讲。

按用途划分，I/O 设备可以分成三大类：

- **人机交互设备**：包括输入设备和输出设备。这类设备做的是"翻译"工作——把人能识别的信息转换成计算机能识别的信息输入到计算机里，或者把计算机里的二进制信息转换成人能识别的文字、图像、声音输出出来。键盘、鼠标、打印机、显示器都是。
- **计算机的信息存储设备**：磁盘、磁带、光盘这类设备，在存储器一章里它们是存储系统的一部分，同时它们也是计算机系统的外部设备。各种类型的文档、影视资料都可以保存在磁盘、光盘和磁带上。它们同样需要通过 I/O 接口和主机联系。
- **机机通信设备**：比如调制解调器、网卡，用于计算机和计算机之间、或者计算机和某种大型/小型设备之间进行信息交换。

#### 输入设备：键盘是怎么"认字"的

输入设备的任务是把人能识别的信息送进计算机。以键盘为例：要判断是否有键按下，然后根据哪个键被按下，把和这个键相对应的二进制编码输入到计算机中。

常用的键盘是**编码键盘**，其结构和工作原理并不复杂（教材 169 页图 5.15 给出了完整结构）：

```text
  计数器 ──→ 行译码 ─┐
       │             ├──→ 扫描键矩阵（若干键排成矩阵）
       └─→ 列译码 ─┘              │
                                  ↓ 扫描到某键按下
                        计数停止，计数值作为 ROM 地址
                                  │
                                  ↓
                     ROM（保存每个键对应的 ASCII 码）
                                  │
                                  ↓ 中断方式读入
                                 CPU
```

读法：把若干个键排列成矩阵，用一个计数器经过行译码、列译码之后对键盘进行扫描，确定到底是哪一个键被按下了。一旦扫描到某个键按下，**计数器的计数就会停止**；同时可以把计数器的输出作为 ROM 的输入地址，而 ROM 当中保存着键盘上每个键对应的 ASCII 码，CPU 把这个 ASCII 码读进来——这个读入是**通过中断方式**进行的。CPU 的读入操作经过一段时间延迟后，可以用来清除中断标记，并再次启动计数器，让计数器重新对键盘进行扫描，为下一个字符的输入做准备。

鼠标也是大家非常常用的输入设备，分机械式和光电式两种，教材上对两种都有介绍。触摸屏原来应用比较少，现在几乎每个人用的手机都是触摸屏，其工作原理可以通过教材或网络做一个简单了解。

#### 输出设备：显示器与打印机

最常用的输出设备是显示器，图形、图像、字符都通过它显示。显示器实际上有三种类型：

- **字符显示器**：早期的显示器只能支持字符显示，显示器里有字符发生器，把 ASCII 码转换成相应的字符点阵在屏幕上显示出来；
- **图形显示器**：显示的是**矢量图形**——就是用人工方式或程序在计算机上画出来的、由点线面构成的图形；
- **图像显示器**：现在大家见到的几乎都是这种，绝大多数显示器都支持图像显示，照片、视频都可以在显示器上显示。

打印机按是否使用打击方式可分为两种。一种是**击打式**，也就是针式打印机，15 到 20 年前非常流行，它把字符点阵通过色带和纸打印出来；这种打印机又分逐字打印和逐行打印两种，按打印纸的宽度还可分成窄行和宽行。它并没有消失——目前各种类型的票据打印机用的就是它，比如坐出租车时打出来的出租车发票，那台打印机就是击打式的针式打印机。另一种是**非击打式**，包括激光打印机和喷墨打印机两种类型。

#### 模数转换、终端与汉字处理

还有几类设备值得知道。**A/D 和 D/A 转换**：A 是模拟信号，D 是数字信号。计算机内部使用的都是数字信号，如果计算机要对外部设备进行控制、或者把信号进行远程传输，就需要 D/A 设备，把计算机控制的数字信号转换成模拟信号传输给设备进行控制，或者进行远程传输；在接收端再利用 A/D 把模拟信号转成数字信号接收。反过来，外部设备的状态信息、或外部设备对主机的输入，可能是模拟信号方式，要输入到计算机当中就必须转换成计算机能识别的数字信号，这就要用 A/D 设备。

**终端**：一般来说由显示器和键盘构成，但终端上带的不仅仅是一个显示器和键盘，还有一些控制机构、缓存等等，类似于我们现在常说的瘦客户机。它能够完成显示控制、存储、键盘管理以及通信控制。终端一般不能单独使用，要通过连接线和远程的主机连接之后才能工作。

**汉字处理（以及其他语言文字处理）**：英文之外的汉字输入要有输入码，在计算机内部进行存储、处理要有内码，要进行显示、输出则要有字模码。这些内容在早期的微型计算机组成原理（或微机组成技术）课程和教材上都有讲授，需要的话可以查相关资料。

#### 多媒体技术

"多媒体"这个词实际上是从英文 multimedia 直接翻译过来的，所谓多媒体就是**多种媒体技术和手段相结合进行综合应用**，给人以更多的视听或动作上的感受。应用非常多：比如虚拟现实——飞行员在飞一个新的机型之前，要用飞行模拟器进行训练；再比如玩游戏，像体感游戏机，把人对游戏的控制和反应通过手柄或者仿真的输入器输入到系统当中——把手柄安在羽毛球拍上、网球拍上、乒乓球拍上，或者安在枪上来玩游戏。

多媒体的关键技术包括数据的压缩与解压缩、编码技术、专用芯片、语音识别、图像识别、图片识别等等。多媒体技术是计算机领域目前非常热的研究点之一，这里只做简单介绍。

### I/O 接口：为什么要加一层

#### "接口"这个词有多宽

接口这个词的含义非常广泛：可以用在软件模块和软件模块之间，可以用在硬件模块和硬件模块之间，也可以用在软件和硬件之间。有一本非常有名的计算机组成原理教材就叫《计算机组织与设计：硬软件接口技术》——所谓硬件和软件之间的接口，实际上就是计算机硬软件的交界面，也就是计算机系统结构。这一节要讲的范围窄得多：**主机和 I/O 设备之间的接口**。

#### 为什么要用接口

在第三章已经讲过，我们采用总线的方式来完成外部设备和主机之间的连接。但总线不能直接把设备挂上来就完事，主机和设备之间需要接口，原因有六个：

- **实现设备的选择**：外部设备要有地址，主机通过地址来确认这次数据传输和哪个设备进行，所以接口首先要实现设备选择，确认哪个设备参与本次输入输出操作；
- **实现数据缓冲**：外部设备类型多样、工作速度差异非常大——硬盘速度比较快，键盘可能很长时间才能输入一个字节的数据，要通过接口实现数据缓冲，达到速度匹配的目的；
- **实现数据格式转换**：接口和主机之间采用并行传输，一次传输一个字节或一个字；外部设备和接口之间可能采用串行传输，一位一位地传数据，要在接口中完成组装或拆解，做格式转换；
- **实现电平转换**：主机和 I/O 设备工作的电平不一致，要通过 I/O 接口完成电平的转换，使主机和 I/O 设备能够协调地工作；
- **传送控制命令**：CPU 把控制命令传输到接口当中，由这个命令来控制外部设备进行工作；
- **反映状态标志**：接口当中要有一些状态标志，标明外部设备是忙还是闲、是否已经准备好、有没有中断请求。

### 接口的功能与组成

#### 从总线看接口的四条线

刚才介绍的六点就是接口的功能，这些功能决定了接口硬件电路的结构。看一个通过总线方式连接的 I/O 接口电路：主机通过 I/O 总线和接口连接，总线可以分成四种类型。

```text
        主机侧                      I/O 接口                    设备侧
     ───────────              ┌──────────────────────┐
      设备选择线 ─────────────→  设备选择电路（比较器）  │
      数据线     ←═══════════→  数据缓冲寄存器 DBR     │←═══════════→ 外部设备
      命令线     ─────────────→  命令寄存器 → 命令译码器│──命令──────→
      状态线     ←─────────────  状态标记（触发器组）    │←─状态───────
                               └──────────────────────┘
```

- **设备选择线**：这条线上传输的是参与本次信息交换的设备的设备码或端口号，实际上就是设备的地址（或端口地址）。地址传给 I/O 接口，在接口当中进行匹配，看是否是这个接口上连接的某个设备要参与这次数据传输。它是**单向**的。
- **数据线**：完成数据的输入和输出，它的条数和接口的类型有关系，是**双向**的。
- **命令线**：来自主机的命令通过命令线输入到 I/O 接口当中，经过缓冲和译码之后，可以控制设备做相应的输入或输出操作。
- **状态线**：也是**单向**的，从 I/O 接口送到 I/O 总线、进而送到主机，由主机了解外部设备的工作状态——是忙、是准备好、还是出错，都通过状态线传输。

> **提示**：六项功能里的并串转换和电平转换，在教材给出的接口功能图中没有画出来——是为了让电路更简单明了。实际上应该是有的，大家可以在给出的几个功能的基础上，对接口的功能和组成做进一步完善。

#### 假设接口只做四件事：四大模块怎么来

假设我们要设计的接口有四个功能：一是**选址**功能，确认某一个设备是否就是给定的、要参与本次数据传输的设备；二是**传送命令**的功能，接收来自主机的命令并对命令进行锁存；三是核心的**传送数据**功能；四是**反映设备状态**的功能。功能定了，组成就跟着定了：

- 选址功能由**设备选择电路**完成——从逻辑实现上说，就是一个**比较器**；
- 传送命令的功能由**命令寄存器**（把命令锁存）加上**命令译码器**以及节拍发生器完成，发出控制信号，控制接口和外部设备完成相应的功能；
- 传送数据的功能由**数据缓冲寄存器（DBR）**完成——这个寄存器稍加改进，就可以变成并串转换或串并转换的电路；
- 反映状态的功能用**状态标记**实现——利用一系列的触发器。

#### 状态标记：四个触发器各管一件事

状态触发器要反映设备的哪些状态？

- **完成触发器 D**：标记设备是否准备好。$D=1$ 表示准备工作已经完成，$D=0$ 表示准备工作尚未完成；
- **工作触发器 B**：标记外部设备是否忙。$B=1$ 表示外部设备忙，$B=0$ 表示外部设备已经完成工作、是闲的；
- **中断请求触发器**：中断方式下，设备准备好以后主动向主机提出中断请求，所以接口当中要有中断请求触发器；
- **屏蔽触发器**：接口可能有中断请求，但是否允许它向主机提出，要看这次设备中断请求的重要性。屏蔽触发器等于 1 时，表示尽管设备已经完成了工作，依然不能向主机（或 CPU）发出中断请求——因为当前主机所处理的工作，它的重要性比这次输入输出操作要大。

#### I/O 接口的基本组成框图

把前面的功能和分析合起来，I/O 接口的基本组成可以分成五大模块：**设备选择电路**（确定是否是某一个设备要参与给定的输入输出操作）、**命令寄存器和命令译码器**（确认本次操作是输入、输出还是其他类型的操作）、**数据缓冲寄存器 DBR**、**状态标记**（由一系列触发器完成）——再加上一个**控制逻辑电路**，让这四大部分的主要电路能够协调地、按时序地工作。

一端连 CPU、一端连外部设备的最基本 I/O 接口就是这样：

```text
                ┌───────────────────────────────────────────┐
   CPU 侧       │               I/O 接口                     │      设备侧
  ─────────────→  设备选择电路（比较器）                       │
   地址线（设备地址）   ↑        命令寄存器 ──→ 命令译码器      │── 命令 ──→ 外部设备
  ─────────────→          数据缓冲寄存器 DBR                  │←═ 数据 ═⇒
   命令线               状态标记：完成D / 工作B /              │←─ 状态 ───
  ─────────────→        中断请求 / 屏蔽 触发器                │
   数据线（双向、并行）  控制逻辑与时序电路                     │
  ←─────────────                                            │
   状态线                                                    │
                └───────────────────────────────────────────┘
```

读法：CPU 和接口之间一般是**并行、双向**的数据传输；地址线给出外部设备的地址，供设备选择电路使用；命令线送来的操作命令放入命令寄存器中锁存，进而译码，并在时序电路的控制下给出各个操作以及操作之间的时间关系；状态线把 I/O 接口和外部设备的状态传输给 CPU。接口右侧，外部设备通过数据线、命令和状态与接口连接：数据线传输要交换的数据；命令来自命令译码器和时序逻辑，控制外部设备做相应的工作；状态是外部设备的状态，输入进来对状态标记进行置位或复位。这个基本框图还可以进一步复杂化——这一步留给大家自己来做。

### 接口的类型

给接口分类，给出一个标准，就有一个分类方法。

- **按数据传送方式**：这个"猜都能猜出来"——分并行接口和串行接口。比如 8255 芯片就是并行接口芯片，8251 芯片就是串行接口芯片。
- **按功能选择的灵活性**：分**可编程接口**和**不可编程接口**。可编程接口的功能和工作方式可以通过编程的方式设置，比如英特尔的 8255；不可编程接口不能通过软件方式设置功能和工作方式，但可以通过硬联的方式来改变，典型的芯片是英特尔的 8212。
- **按通用性**：把多种类型接口当中通用的电路做到一个芯片里，就形成了**通用接口**，比如前面提到的 8255、8251；**专用接口**则只能用于主机和某一种类型的设备连接，像英特尔的 8279、8275 都是专用接口。
- **按数据传送的控制方式**：前面详细介绍了三种数据传送的控制方式，其中程序查询方式不需要接口进行控制，剩下两种——**中断方式有中断的接口，DMA 方式有 DMA 的接口**。

## 程序查询方式与中断接口的硬件雏形
> 对应块：BLK18 | 覆盖分集：P58-P60 | 块标题（分集名）：《5.4 程序查询方式》

这一讲我们解决两件事：一是程序查询方式的流程，二是程序查询方式的接口电路。也就是说，要依托上一节介绍的 I/O 接口电路基本组成，以及程序查询方式对接口电路提出的功能要求，真正把程序查询方式的接口电路设计出来。讲完查询方式，我们顺势进入程序中断方式的前半段——中断的概念、中断怎么产生，以及中断接口电路里新添的那几样硬件。

### 一个设备的查询流程

先看最简单的情形：传输过程中只有一个设备参与内存和 I/O 之间的数据交换。

CPU 在执行程序的过程中，会执行到一条输入输出指令，由这条 I/O 指令发出启动设备的命令。设备接到命令后就开始做数据准备，准备好以后再把数据传给 CPU。关键在 CPU 这一侧：发出启动命令之后，CPU 并不会去干别的，而是开始检查状态标记——I/O 接口里的数据是否准备好、设备是否已做好输入输出的准备。

```text
            ┌────────────────────────┐
            │  CPU 执行到 I/O 指令，   │
            │  发出启动设备的命令      │
            └───────────┬────────────┘
                        ▼
            设备开始准备数据
                        ▼
            ┌────────────────────────┐
   ┌───────▶│  CPU 检查状态标记：      │
   │        │  数据是否准备就绪？      │
   │        └───────────┬────────────┘
   │   未就绪            │ 已就绪
   └──（CPU 踏步等待）    ▼
            ┌────────────────────────┐
            │      进行数据交换       │
            └────────────────────────┘
```

图里那条回环就是程序查询方式的全部精髓：如果没准备就绪，CPU 就处于一种**踏步状态**，通过循环的方式反复检查状态标记，直到设备准备好为止，才开始交换数据。

这个过程靠三条指令就能撑起来：检查状态标记用的是一条**测试指令**；流程图里那个"是否准备就绪"的菱形判断框，用的是**转移指令或者分支指令**；真正交换数据这一步，用**数据传送指令**、**输入输出指令**或者**访存指令**来完成。

### 多个设备：按优先级排队查询

如果有多个设备都要通过程序查询方式和内存交换数据，怎么办？那就得把参与传输的这些设备按**优先级**——也就是轻重缓急——排一个序：优先级越高的设备，被查询到的时间就越早。

CPU 先检查优先级最高的设备一的状态标记：就绪了，就处理设备一和内存之间的信息交换；没就绪，就去检查次优先级的设备二，按优先级的先后顺序逐步向后检查，依次完成各设备的数据输入输出。查询的顺序就是优先级的顺序，这一点和后面中断方式里的排队思想是一脉相承的。

### 查询程序怎么写：从保存现场到判断结束

上面是流程的骨架，真正落到程序员头上，要写一段程序来实现这个查询过程，嵌入到应用程序里，由这段程序完成数据的输入输出。这段程序的完整流程是这样的：

```text
保存寄存器内容
      │
      ▼
设置计数值（决定本次传输的数据量）
      │
      ▼
设置存储缓冲区的首地址
      │
      ▼
启动外设
      │
      ▼
查询状态标记，未就绪则踏步等待
      │
      ▼
传送一个字
      │
      ▼
修改内存地址（+1 / −1）、修改计数值（+1 / −1）
      │
      ▼
判断这批数据是否传完 ──否──▶ 再次启动外设，回到查询
      │是
      ▼
   结束 I/O 传输
```

逐段过一遍。第一步要**保存寄存器的内容**：程序查询要完成内存和外设之间的数据输入输出，需要借助 CPU 当中的某一个寄存器对数据进行暂存。如果这个寄存器当前的数据是有用的，就得先把它保存起来——可以写入某个内存单元，可以压入堆栈，也可以挪到 CPU 里其他闲置的寄存器中。

接着**设置计数器的值**，目的是控制这次传输的数据量——这次内存和 I/O 之间到底传多大量的数据。计数值的设置有两种方式：

- 一种是：要传 $n$ 个字，就把计数器设成 $n$，每完成一个字的传输计数器减 1，减到 0 为止，数据传输结束；
- 另一种是：把计数器设成一个**负数**，并且这个负数用补码表示（补码我们到第六章再讲），每传一个字计数器加 1，直到计数器溢出、值变成 0，数据传输才结束。

> **易错点**：两种设置方式对应两种修改方向——设成正数 $n$ 就往下减，设成补码负数就往上加。修改计数值时用加 1 还是减 1，完全取决于你当初是怎么设置计数值的。

计数值设完，还得**设置存储缓冲区的地址**：要完成内存和 I/O 之间的传输，得知道内存中这一块数据的起始地址。保存数据也好、读取数据也好，都从这个缓冲区的首地址开始。

这几样初值都设好，就可以**启动外部设备**，让它去做数据准备和传输准备。启动之后，因为是程序查询方式，CPU 就开始查询 I/O 接口或者设备的状态，看是否准备好；没准备好，CPU 就以原地踏步的方式反复查询，一直到状态标志表明数据已经准备好了，这个查询操作才会停止，开始传输一个字。

一个字传完，前面设置的那些初始值要修改：**内存地址**加 1 或减 1，为输入输出下一个数据做准备；**计数器**的值也要加 1 或减 1（理由见上面那个易错点）。然后判断这批数据是不是传完了——没传完，CPU 再一次启动外设，循环这个过程；传完了，就结束这次 I/O 传输。

### 程序查询方式的接口电路：以输入为例

有了流程，再结合上一节介绍的 I/O 接口电路基本组成，我们就可以分析出程序查询方式的接口电路长什么样。下面以**数据的输入**为例——所谓输入，就是把外部设备的数据输入到主机、输入到内存的某个存储单元当中。

```text
 地址线 ──▶ 设备选择电路 ──SEL──┐
 启动命令 ─────────────────────┤
                               ▼
                    置位 / 复位两个状态标记
                    D（完成）← 0     B（工作）← 1
                               │ B 启动设备
                               ▼
        设备准备数据 ──输入数据线──▶ DBR（数据缓存）
                               │ 设备工作结束信号（经设备状态线）
                               ▼
                    D ← 1（就绪）    B ← 0（不忙）
                               │
   CPU 一直查询 D，D=1 ──▶ CPU 经数据线把数据读入
```

从头走一遍。CPU 通过**地址线**给出外部设备的地址，设备选择电路拿自己的设备地址（端口号）和地址线上的地址作比较：相同，说明这次启动的就是连在这个接口上的设备，选择信号 **SEL** 有效。只有 SEL 这个信号有效，这个 I/O 接口电路才会工作——它实际上是整个接口电路的选择信号。SEL 有效、启动命令也有效，接口就开始工作。

在启动命令和 SEL 都有效的前提下，接口对两个状态标记进行**置位或复位**。此刻 CPU 刚发出读命令，设备还没开始工作，所以标记 $D$ 应该是 0，表示数据还没有准备好；标记 $B$ 被置为 1，表示设备开始工作、处于忙的状态。

$B$ 这个标记会去**启动设备**。设备接到 $B$ 的标记信号和启动命令后开始工作，把数据准备好，数据通过输入数据线保存到 **DBR**（数据缓存寄存器）里。这时候设备的工作结束，设备通过**设备状态线**向接口电路送入一个"设备工作结束"信号。这个信号会修改接口里的两个标记：$D$ 被置为 1，表示数据已经准备好了；同时 $B$ 被清为 0，表示设备已经工作完成、不忙了。

而在这整个过程中——一直到 $D$ 变成 1 之前——CPU 都在原地踏步地查询，查的就是这个 $D$：只要 $D$ 不等于 1，就一直查下去。$D$ 等于 1 了，说明数据已经放进了 DBR，CPU 可以传输了，就通过数据线把这个数据读入，这一次输入的工作到此结束。

这个接口电路的结构非常简单。真正做设计的时候，接口电路要比这复杂得多：比如要对 CPU 传来的命令进行**锁存**、对命令进行**译码**，在时序电路的控制下按顺序产生一系列控制信号，控制接口和 I/O 设备做相应的工作。

至于输出的流程，大家可以自己试一下：以输出为例，推一推输出在这个接口上的工作流程是什么。把 $D$、$B$ 两个标记在输出方向上的置位、复位顺序想清楚，这道电路你就真正吃透了。

### 中断到底是什么

接下来进入程序中断方式。这一部分要解决五个问题：中断的概念、I/O 中断怎么产生、程序中断方式的接口电路、I/O 中断的处理流程、中断服务程序的流程。前两个问题在这里展开。

首先回答：什么是中断？

**中断**是指 CPU 在执行程序的过程中，如果发生了意外事件或者特殊事件，CPU 要中断当前程序的执行，转而去处理这个特殊事件或异常事件——处理的方式是执行一段**中断服务程序**；处理结束之后，返回到被中断程序的**程序断点**，继续执行原来的程序。这一来一回的整个过程，就叫中断。

中断的种类非常多，方式也很多。我们通过一张时序图来理解这个概念：

```text
 CPU：… k 条指令 ─┤保存断点、保存现场├─▶ 中断服务程序① ─┤返回断点├─▶ k+1 条指令 ─▶ … q 条指令
                        ▲                                                      │
                        │ 中断请求                                              │ 中断请求
 外设：                  └──────────────                                        ▼
                                                              中断服务程序② ─▶ 返回 q+1 条指令
```

CPU 执行主程序，假设执行到第 $k$ 条指令时，某个外部设备要向内存输入数据，它就会通过**中断请求线**向 CPU 发出中断请求。CPU 在第 $k$ 条指令执行结束的时候，会去查询有没有中断请求、能不能响应；可以响应的话，CPU 就中断现行程序的执行。当然中断的过程是比较复杂的：要把**程序断点**保存起来——中断服务之后总得知道从哪儿接着执行；还要**保存中断现场**——有些寄存器的值，中断服务程序里可能要用，它们的当前值就得先存起来。

这些做完之后执行中断服务程序；执行结束，根据保存的断点，程序的控制流回到第 $k+1$ 条指令，接着往下执行。执行到第 $q$ 条指令时，外部设备又发出了中断请求，处理过程和第 $k$ 条指令那次是相似的——CPU 还要去执行中断服务程序。注意，中断服务程序①和中断服务程序②可能是不同的，也可能是相同的；服务程序执行结束后，返回第 $q+1$ 条指令继续向下执行。

### 打印机是如何产生中断的

中断是**中断源**产生的。所谓中断源，就是主机的外部和内部、CPU 的外部和内部，凡是能够引发 CPU 发生中断的因素，都叫中断源。下面拿打印机看一看 I/O 中断具体是怎么产生的。

一边是 CPU，一边是打印机。CPU 执行主程序，主程序里假如有打印命令，CPU 就通过打印命令启动打印机；打印机开始做打印前的准备，而 CPU **继续执行原来的程序**。打印机准备好以后可以接收数据、可以打印了，就向 CPU 发出一个中断请求；CPU 响应这个请求，执行一个中断服务程序，向打印机传输数据。传送和接收结束以后，CPU 中断返回，继续执行原来的程序，打印机则执行打印操作。

打印完以后，打印机的缓冲区空了，还可以继续接收新的数据，它就会再一次向 CPU 发出中断请求；CPU 响应，CPU 和打印机之间再次进行数据交换，交换结束，CPU 继续原来的程序，打印机继续打印——就是这样一个往复的过程。

从这个过程里能看出中断方式最有价值的一点：**打印机的工作和 CPU 的工作是并行的**。数据准备阶段，打印机做状态准备，CPU 还在执行原来的程序；准备好了，发中断请求，CPU 响应、传送数据、中断返回，之后一个继续算它的程序，一个继续打它的东西。对比一下程序查询方式里 CPU 原地踏步干等设备的画面，谁在浪费 CPU 的时间，一目了然。

### 程序中断方式的接口电路要多四样东西

上一节介绍 I/O 接口电路基本结构的时候，我们说它有五部分：选址、数据缓冲、状态标记、命令缓冲和译码。如果采用程序中断方式，光有这些还不够，还需要增加几样电路。

第一样是**中断请求标志**，由外部设备对它进行设置，表示"有中断请求了"。第二样是**中断屏蔽触发器**：中断请求标志能否变成真正的中断请求信号发给 CPU，还要看它是否会被屏蔽掉。为什么要屏蔽？因为有的时候，计算机正在执行的程序或者正在执行的中断服务程序，它的重要性要比这个设备提出的中断请求更高，那么这个中断请求就该被屏蔽掉，不让它发向 CPU。

第三样是**排队器**。同一个时刻向 CPU 发出中断请求的可能有多个设备，这些设备的优先级是不一样的——比如高速设备，它的优先级要高一点，因为如果不及时响应，高速设备里保存的数据就可能丢失。排队器的任务，就是在所有提出中断请求的设备中确定出优先级最高的那一个，经过排队器之后，只有优先级最高的那个设备提出的中断可以被响应。

第四样，响应中断之后要去执行中断服务程序，CPU 必须知道**中断服务程序的入口地址**——它在内存当中的起始地址。这要靠**中断向量地址形成部件**来形成。

把这几样加上 5.3 节的接口基本结构，就得到了程序中断方式接口电路的基本组成。下面把其中几样关键的硬件逐一讲清楚。

### 两个触发器：INTR 与 MASK

每个采用程序中断方式传输的设备，接口当中都要配置**中断请求触发器 INTR** 和**中断屏蔽触发器 MASK**——它们是两个标记。

- **INTR**：输出端 $Q$ 为 1，表示有中断请求，并且通过中断请求线把这个请求送给 CPU，通知 CPU 外部设备有一个中断请求；为 0 表示没有请求。
- **MASK**：$Q$ 端输出为 1，表示这个中断会被屏蔽掉；为 0 表示开放，中断不会被屏蔽。

那什么时候才会真正产生中断请求？条件有三个，缺一不可：

> **结论**：数据已经准备好（完成触发器 $D$ 为 1，设备已把数据放入 DBR）、中断未被屏蔽（MASK 的 $Q$ 端为 0，$\overline{Q}$ 端为 1）——当 $D$ 触发器的 $Q$ 端和 MASK 触发器的 $\overline{Q}$ 端均为 1 时，INTR 被置为 1，表示有中断请求。

还有最后一环：在**指令执行周期结束之前**，CPU 会发出**中断查询信号**。在这个查询信号的控制下，INTR 的 $D$ 端输入被送入输出端，中断请求信号才真正产生、沿中断请求线送向 CPU。也就是说，CPU 对中断请求的察觉，是以一条指令执行完为节拍来进行的——这也呼应了前面"执行到第 $k$ 条指令结束才查询中断请求"的时序图。

### 链式排队器：硬件怎么排优先级

多个设备同时发出请求时，要用**中断排队器**把优先级最高的中断请求筛出来。排队有两种实现方式：一种是**软件**方式，实际上就是用查询的办法排中断的优先级——在一个表格当中规定好优先级，排队的过程就是从高优先级到低优先级的一个查询过程，这部分内容在第八章讲；另一种是**硬件**方式，硬件实现又有两种做法：可以把排队电路**集中放在 CPU 内部**，也可以把排队电路**分散放在每一个接口当中**，各接口里和排队相关的电路连接在一起，组成一个链——这就是**菊花链方式**，或者叫链式排队器。我们这里介绍后一种。

给出的链式排队器里，每个接口当中就是**一个非门、一个与非门**，各级接口的排队电路相互连接在一起，构成一条链。记号约定：$\overline{INTR}_i$ 上带一横表示相应中断请求信号的非，我们取它的非端作为输入。优先级从图的左侧向右侧递减——在我们给出的四个（推广到 $n$ 个）中断源当中，1 号、2 号、3 号、4 号……的优先级是按降序排列的。

```text
（优先级：1 ＞ 2 ＞ 3 ＞ … ＞ n，自左向右递减）

      接口1             接口2             接口3
  ┌──────────┐     ┌──────────┐     ┌──────────┐
  │ 非门+与非门 │     │ 非门+与非门 │     │ 非门+与非门 │   ……
  └──────────┘     └──────────┘     └──────────┘
   ▲    │INTp1'      ▲    │INTp2'      ▲
   └────┴────────────┘    └────────────┘
   （前一级的 INTp' 送入下一级，串成一条链）
```

它的行为逻辑分几种情况来看。

**所有中断源都没有请求**时，每个 $\overline{INTR}_i$ 的值都是 1，每一个 $INTp_i'$ 的输出都是 1——链上畅通无阻。

**设备 1 有中断请求**：$\overline{INTR}_1$ 就等于 0，$INTp_1'$ 保持高电平（等于 1），而排在它后面的 $INTp_2'$、$INTp_3'$、一直到 $INTp_n'$ 都会被清成低电平——请求信号一进链，就把后面所有级别"封死"了。

**设备 2 有请求、设备 1 没有**：$\overline{INTR}_1$ 是低电平对应 $INTR_1$ 无请求、$INTR_2$ 为高电平；这时 $INTp_1'$ 和 $INTp_2'$ 为高电平，而 $INTp_3'$ 到 $INTp_n'$ 均为低电平，并且这个值会一直向下传递。

看出规律了吗？链式排队器的输出序列是**若干个 1 后面跟着若干个 0**，最后那个 1 所在的位置，就是所有提出中断请求的中断源当中、优先级最高的那一个。凭肉眼扫一眼序列当然容易判断，但排队要靠硬件电路实现，不能靠"看"。

> **提示**：怎么用电路把"最后那个 1"筛选出来？大家也可以先想一想自己的办法。教材上给出的办法是：把 $INTR_i$ 和 $INTp_i'$ 做与非操作——若两者均为高电平，与非门输出低电平，再经过一个非门，得到 $INTp_i$。经过这样的电路之后，$INTp_1$ 到 $INTp_n$ 这 $n$ 个输出当中**只有一个值为 1**，这个 1 就标出了所有请求源中优先级最高的那一个。

排队的问题到此解决。

### 中断向量地址形成部件

设备如何提出中断请求、多个设备同时请求如何筛出优先级最高的——前面都讲清楚了。确定了响应哪个中断源之后，下一步最重要的任务，就是**找到中断服务程序的入口地址**。

寻找入口地址同样有两种方法：一种是通过**软件查表**的方式查到中断服务程序的入口地址，这个在第八章介绍；这里主要介绍硬件方法——**硬件向量法**：由硬件产生**向量地址**，再由向量地址找到中断服务程序的入口地址。

#### 先分清四个概念

用硬件向量法之前，有几个容易搅在一起的概念必须区分好。

| 概念 | 含义 |
| :--- | :--- |
| 中断号 | 中断的编号。比如 8086 当中支持 256 个中断，被编号成 0～255 |
| 中断向量 | 可以理解成中断服务程序的入口地址；在 x86 系列当中，是段地址和偏移量组成的一个向量；有时也指程序状态字 |
| 入口地址 | 中断服务程序在内存当中的起始地址，实际上可以由中断向量来生成 |
| 向量地址 | 中断向量所保存的内存单元的地址 |

中断向量这个概念要多说两句。在 x86 里，它可以理解成由中断服务程序的段地址和偏移量组成的一个向量。有的时候，中断向量也指**程序状态字**：CPU 发生中断的时候，一些非体系结构寄存器、或者表示程序状态的寄存器，指令是无法读取的，那么在计算机内部就把它们集成了一个字，这个字就叫程序状态字。所以所谓中断向量，实际上就是与中断服务程序相关的入口信息——既包括段地址（或者偏移量），也包括执行中断服务程序时需要的一些状态信息。

向量地址则是"地址的地址"：中断服务程序的入口地址保存在某个内存单元里，这个内存单元的地址就是向量地址；或者，我们可以在那个单元里放一条**跳转指令**，通过这条跳转指令跳转到中断服务程序——这时向量地址就是这条跳转指令在内存中保存的地址。

#### 向量地址怎么形成、怎么送到 CPU

形成向量地址的部件就叫**中断向量地址形成部件**。它的输入就是前面讲的链式排队器（或者其他类型的中断优先级排队器）的输出——这里有一条一定要记住的特征：**输入当中只有一位是高电平，其他各位都是低电平**。有多少个中断源、对应多少个中断服务程序，就有多少位输入；它的输出对应的就是向量地址。

```text
 排队器输出                中断向量地址形成部件
 INTp1～INTpn          （本质上是一个设备编码器）
 ┌─────────────┐        ┌──────────────┐
 │ 0 1 0 0 0 … │ ─────▶ │ 编出对应的     │ ──▶ 向量地址 010010
 └─────────────┘        │ 向量地址      │
                        └──────────────┘
```

比如排队器的输出是 1 后面跟若干个 0，把它作为向量地址形成部件的输入，部件输出的就是一个向量地址——我们给出的例子里输出是 010010，它就指出了中断服务程序入口地址（或者那条跳转指令）在内存单元中保存的地址是多少。同样，如果输入是 0、1 后面跟若干个 0，输出就是 00010011——这是给出的一个假设，具体输出值由排队器的输出得到，也取决于你设计的计算机把各中断服务程序的入口地址安排在内存的什么位置。

从电路属性上看：输入只有唯一的一个 1、其余都是 0，输出是一串 0/1 编码——这实际上就是一个**设备编码器**。编码器的具体结构可以看教材第 199 页图 5.42（例 5.2 的电路图），那里给出了一个非常巧妙的设备编码器：排队器的输出 $INTp_i$ 既作为一组**三态门**的输入端，又作为这组三态门的**控制端**。由于排队器的输出只有一个 1，图里虽然有多组三态门，但**只有一组是有效的**——也就是被选中的那组三态门导通，把它的输入送到输出，通过数据线传送到 CPU 当中。

> **结论**：向量地址是通过**系统总线的数据线**送入 CPU 的。

#### 从向量地址到入口地址

向量地址形成以后，就可以找到中断服务程序的入口地址了。看一个模仿内存结构的例子：如果形成的向量地址是 **12h**，它表示中断服务程序的入口地址（或者那条跳转指令）保存在内存单元 12h 当中；到这个地址去看，里面存的是一条跳转指令，通过跳转指令就可以跳转到中断服务程序——比如 200 这个地址对应的就是打印机的服务程序。这样，中断向量地址形成部件加上内存里的跳转指令，就把"响应哪个中断"落实成了"执行哪段程序"。

### 接口电路全貌：和基本组成对上号

最后把中断请求标记、排队器、中断向量地址形成部件这三样合起来，对照 5.3 节介绍的接口电路五大组成部分，看程序中断方式接口电路的整体面貌。

接口电路的基本组成是按功能设计的：要有**设备选择电路**，要有**命令寄存器和命令译码器**，要有**数据缓冲电路**，还要有接口或设备的**状态标记**，中间是控制整个接口协调工作的**控制逻辑**。对应过来：

- **设备选择电路**的输出是本接口的选择信号，只有这个输出有效，这个接口才会开始工作；
- **命令缓冲器（命令寄存器）和命令译码器**负责通过命令译码，确认本次操作对接口和相应设备到底做什么；
- **状态标记** $D$ 和 $B$ 两个触发器，在程序查询方式当中已经介绍过了；
- 和程序查询方式相比，**新增加了两个触发器**：INTR 表示中断请求标记——如果中断源有中断请求，INTR 的值可能就会被置为 1；是不是真的被置为 1，和中断屏蔽触发器 MASK 有关：如果这个中断没有被屏蔽，并且设备工作已经完成（$D$ 为 1），那么在中断查询信号的控制之下，INTR 的输出就会变成 1；
- 还有一个**排队器**，我们采用的是链式排队——排队电路分布在 I/O 接口当中，通过线路连接在一起：来自高一级排队器的信号进入第一级排队器，它的输出再送往下一级；
- 排队器之上就是**设备编码器**——也就是刚才那个硬件结构的中断向量地址形成部件，它的输出通过**数据总线**被送入到 CPU 当中，产生中断服务程序的入口地址，或者入口地址所保存的那个存储单元的地址，或者那条跳转指令所保存的那个存储单元的地址。

到这儿，程序查询方式的流程与接口电路、程序中断方式的概念、中断请求的产生与屏蔽、链式排队和向量地址的形成就都交代清楚了。中断响应之后 CPU 具体怎么处理、中断服务程序怎么组织，是这一部分接下来的内容。

> **承前启后**：上一节讲完「程序查询方式与中断接口的硬件雏形」，下一节接着讲「程序中断的响应、服务流程与 DMA 方式的引入」。

## 程序中断的响应、服务流程与 DMA 方式的引入
> 对应块：BLK19 | 覆盖分集：P61-P64 | 块标题（分集名）：《5.5 程序中断方式5.5-c1》

### CPU 什么时候才能响应中断

外设提出中断请求是随机的——只要它准备好了，接口就可能向 CPU 发出请求。但 CPU 不能随时被打断，所以要先回答两个问题：**什么条件下**允许响应，**什么时刻**去响应。

条件落在 CPU 内部的一个触发器上——**中断允许触发器 EINT**。学过 8086 的同学应该都记得，8086 的状态寄存器里有一个 IF 标志，它就是"是否允许发生中断"这一位的具体实现：允许中断时 EINT 为 1，不允许时为 0。对它的操作有三条路：

- 用指令系统里的**开中断指令**把 EINT 置 1；
- 用**关中断指令**把 EINT 置 0；
- 也可以由**硬件自动复位**，把中断关掉。

> **结论**：EINT = 1 是 CPU 响应外设中断请求的必要条件，开与关都可以由指令或硬件控制。

时间上，在大量的机器设计、或者说一般的机器设计中，都定在**每条指令执行阶段结束的时候**：CPU 发出查询信号，把每个接口中有中断请求的那些接口的中断请求触发器置 1。随后就可以想象我们前面讲过的那条电路——中断请求触发器的值送入排队电路，再送入设备编码器进行编码。记住这条时间规则：中断的检查点是指令边界，指令执行到一半是不理睬中断的。

### 跟着一次输入操作走一遍中断接口

以输入为例——所谓输入，都是以主机为中心，由外设把数据通过 I/O 中断接口电路送进主机。下面把整条链路串起来。

CPU 在执行主程序的过程中，会执行到一条输入指令，这条指令要求指定的外设把数据输入主机。过程如下：

```text
CPU 执行主程序 → 遇到输入指令 → 数据线上给出设备地址
        ↓
设备地址送入接口 → 设备选择电路与接口地址比对 → 相同则选中
        ↓
SEL 信号有效（接口和设备被选中，接口电路才开始工作）
        ↓
CPU 送来启动命令 / 控制命令 → 在接口中译码
        ↓
命令与 SEL 同时有效 → 触发器 B、触发器 D 被设置
        ↓
B = 1（设备忙，已启动）  D = 0（数据尚未准备好）→ 设备开始工作
        ↓
设备工作结束 → 数据送入数据缓冲寄存器 DBR
        ↓
D = 1（数据就绪，CPU 随时可取）  B = 0（设备空闲）
        ↓
若未屏蔽：MASK 触发器的非端为 1，与 D = 1 一道经与非门、再经非门送到 INTR 输入端
        ↓
CPU 指令执行阶段结束 → 发中断查询信号 → INTR 置 1，同时启动排队器
        ↓
排队器输出中只有一个 1（其余全为 0）→ CPU 发出中断响应信号
        ↓
形成向量地址 → 经数据线送入 PC
        ↓
PC 用该地址取出中断服务程序入口地址（或那条跳转指令）
        ↓
执行中断服务程序，把数据取走
```

读这段图要抓住三个关键点。第一，**SEL 信号是接口和相应设备被选中的标志**，只有它有效，接口电路才会开始工作。第二，设置 B 和 D 这两个触发器必须**命令与 SEL 同时有效**，缺一不可。第三，请求能否送达 CPU，取决于 D 为 1（数据就绪）且接口**没有被屏蔽**——MASK 触发器的非端输出为 1，表示允许这个接口提出中断请求；两个 1 经与非门再经非门，就把请求送到了中断请求触发器 INTR 的输入端，等 CPU 在指令结束时发来的查询信号把它置 1。

### 中断服务程序的四步流程

中断服务程序的流程一共分四部分。

**第一步，保护现场**。它包含两项工作。第一项是保护**程序断点**，而断点又有两部分内容：一部分是中断返回后要执行的那条指令的地址，也就是当前 PC 里保存的值；另一部分是程序执行状态——那些不能由指令直接读写的状态，它们同样是断点的一部分，也要保护。这部分工作由硬件自动完成，教材上管它叫**中断隐指令**。要注意，中断隐指令本身并不是一条指令，它是硬件自动执行的一系列操作，第九章会有更详细的介绍。第二项是保护**通用寄存器（体系结构寄存器）的内容**：如果中断服务程序里要用到这些寄存器，就必须把原值保存起来，因为中断返回后主程序还要用它们继续工作。这些寄存器一般是在中断服务程序中用**进栈指令**保存的。

**第二步，中断服务**。不同设备的中断请求，服务的内容是不一样的——到底做什么操作、怎么操作，与外部设备直接相关。因此不同功能的设备，编写的中断服务程序也各不相同。

**第三步，恢复现场**。这里说的恢复现场主要指体系结构寄存器的内容。前面用进栈指令保护的，恢复时用**出栈指令**即可。但保护的方式并不限于进栈：你可以把它们保存在内存的指定单元，那样恢复时就要用一系列取数指令把内容取回来；如果机器内部有大量寄存器，还可以把它们转存到另一些寄存器里。判据只有一条——只要中断服务之后返回来还能把这些寄存器的值恢复回去，怎么存都行。

**第四步，中断返回**。用**中断返回指令**回到原来被中断程序的断点处。

> **易错点**：断点 ≠ 只有 PC。PC 里的指令地址和那些指令读不到的程序状态都算断点，前者连同程序状态由硬件（中断隐指令）保护，后者里的寄存器内容才由服务程序里的进栈指令保护。

### 单重中断与多重中断

什么是**单重中断**？CPU 在执行中断服务程序的过程中，如果来了新的中断请求，那么不管它的优先级有多高，都不能打断现行的中断服务程序。相应地，**多重中断**（也叫中断嵌套）则允许优先级更高的中断源打断现行的中断服务程序——CPU 当前执行的就是一个中断服务程序，更高优先级的请求一来，它还要再一次被中断，CPU 转去处理更紧急的事务。

从指令周期的角度看，两种方式在进入服务程序之前做的事是一样的：取指令、执行指令，执行结束后查询有无中断请求；没有就继续取指、执行，循环往复；有则响应，进入**中断周期**。中断周期主要做三件事：

1. 保护断点；
2. 形成中断服务程序的入口地址；
3. 关中断。

把一条指令的解释过程分成取指令、形成操作数地址、取操作数、执行几个阶段的话，中断周期就排在执行之后，是其中的一个阶段：

```text
取指令 → 形成操作数地址 → 取操作数 → 执行 → 中断周期
                                            │
                                            ├─ 保护断点
                                            ├─ 形成中断服务程序入口地址
                                            └─ 关中断
```

这三件事由硬件按照一定的时序完成，这就是中断隐指令——它虽然不是一条指令，但要完成一系列有先后顺序的操作。中断周期结束，入口地址已经给出，下面就进入中断服务程序的执行。

两种方式的**真正区别**出现在服务程序内部。单重中断的服务程序是这样走的：先保护现场（把服务程序要用的寄存器压入堆栈），然后设备服务，再恢复现场（一串出栈指令），**最后才开中断**，接着中断返回。也就是说，从保护现场到恢复现场的整个过程中，中断允许触发器 EINT 一直为 0——即便期间来了优先级更高的请求，CPU 也不响应。多重中断为了能在服务过程中响应更高级的请求，把**开中断的位置提前了**：保护现场之后马上开中断，于是设备服务期间是允许响应更高优先级请求的。

```text
单重中断服务程序流程            多重中断服务程序流程
      保护现场                       保护现场
        │                             │
        │                           开中断 ←—— 位置提前，服务期间可被更高级请求打断
        ↓                             ↓
      设备服务                       设备服务
        ↓                             ↓
      恢复现场                       恢复现场
        ↓                             ↓
      开中断                         中断返回
        ↓
      中断返回
```

从这两列流程的对比就能看出：为了支持多重中断（嵌套），我们对服务程序流程做的改动其实只有一处——开中断的时机。改动虽小，含义却大：单重中断把整个服务过程当成"原子"操作，多重中断则把真正不可分割的部分收缩到保护现场和恢复现场这两小段。

### 主程序与中断服务程序抢占 CPU 的全景

前面介绍过的那张示意图，在这里做进一步强化。CPU 执行主程序，执行到一条输入输出指令，就用这条指令去启动外设；外设收到启动命令，并通过设备选址电路知道本接口、本设备被选中，于是开始做准备工作。CPU 发出启动命令之后，在主程序中接着执行下一条指令——注意，这期间 CPU 依然在连续执行主程序。

外设准备好之后向 CPU 发出中断请求。能发请求有两个前提：CPU 的 EINT 为 1（允许中断），且接口中 MASK 标记的输出为 0（即其非端为 1，表示允许该接口提请求）。于是在某条指令执行阶段结束时，CPU 查询并响应，去执行中断服务程序完成数据传送；传送结束返回被中断的主程序，继续执行，直到设备下一次准备好数据，再一次打断主程序。

> **结论**：宏观上 CPU 与 I/O 已经并行工作了——设备做数据准备或状态准备时，CPU 仍在执行主程序，这是中断方式相比程序查询方式最主要的差别。但微观上，CPU 仍要中断现行程序的执行，为 I/O 设备服务：响应请求、执行中断服务程序的那段时间，主程序的执行是断开的。这一"宏观并行、微观串行"的定性，是大家要特别关注的。

### DMA 的数据通路：把 CPU 从传送中解放出来

接下来进入 5.6 节，DMA 方式。DMA 是个缩写，指**直接存储器访问**。这一部分讲四个主要内容，先从 DMA 方式的特点讲起——第一个小问题就是 DMA 与程序中断两种方式的数据通路。

回顾 5.1 节概述里讲过的结论：程序中断方式和程序查询方式，即使做的是内存和外设之间的信息交换，这个信息也**首先要经过 CPU 作为缓冲**，再由 CPU 完成转存。也就是说，I/O 设备的数据要进主存，或者主存的数据要输出给 I/O 设备，都必须经过 CPU 中的某一个寄存器——在我们的模型机里给定的就是 ACC；换成其他结构的机器，也要用 CPU 中的某个寄存器作数据传输的中介。以输出操作为例：主存中的数据先送入 CPU 的某个寄存器，再通过输出通路送入中断接口，由接口送给 I/O 设备完成输出。

采用程序中断方式，外设做数据准备或状态准备时确实不需要 CPU 参与，CPU 和外设可以并行工作；但一旦状态或数据准备好、真正开始输入输出了，CPU 就必须中断正在执行的程序，去执行中断服务程序，由它来完成数据的进出。**真正传数据的时候，还是要 CPU 的参与**——这会降低 CPU 的效率，因为 CPU 是计算机中非常珍贵的资源。

DMA 方式则进一步把 CPU 从数据传送这个过程中解放出来：采用 DMA 接口后，外设和内存之间的数据交换可以通过 DMA 接口**直接传送**，不需要 CPU 作为中间媒介转送。这就是两者数据通路上的本质差异。

```text
程序查询 / 程序中断方式的数据通路：
    主存 ◄────► CPU 中的寄存器（模型机为 ACC） ◄────► 中断接口 ◄────► I/O 设备
                 ▲
                 └── 真正传数据时必须由 CPU 执行中断服务程序

DMA 方式的数据通路：
    主存 ◄──────────────► DMA 接口 ◄──────────────► I/O 设备
                （不经 CPU，直接成块传送）
```

### DMA 与主存交换数据的三种方式

#### 停止 CPU 访存

第一种方式是**直接停止 CPU 对主存的访问**：只要外设要和内存交换数据，从这块数据的第一个字开始，CPU 就放弃总线的控制权、放弃对内存的访问，把两者交给 DMA 接口。这是控制上最简单的一种方式，适合大量数据的传输。

但它有问题。传输过程中，如果 CPU 内部的指令缓冲器里还有指令，CPU 可以继续工作、继续执行指令，只要执行过程不访问存储器就行；没有指令可执行时，CPU 保持当前状态。问题在于**这种方式不能充分发挥 CPU 对主存的利用率**：即使是一整块数据的传输，数据也是一个字一个字地在主存与外设之间走的，传输的间隔可能比较大，甚至会超过一个存取周期。也就是说，在传输间隔这段时间里，DMA 接口并没有直接使用内存，却依然占着内存的访问权，CPU 无法利用这段时间访存。

```text
主存工作时间：  |— CPU 控制并使用 —|——————————— DMA 请求并占用 ———————————|— CPU 控制 —|
                                     ↑
                        这一长段时间里 DMA 并未真正使用内存
                        （传输间隔）—— 主存利用率没有被充分发挥
```

#### 周期挪用（周期窃取）

第二种方式解决了上面的问题，叫**周期挪用**，也叫**周期窃取**。注意，这里说的"周期"指的是**存取周期**（访存周期）：DMA 接口准备好数据传输时，通过申请建立总线的使用权，占用一个或几个存取周期完成传输；在传输间隔或数据准备阶段，DMA 接口放弃内存的使用权和总线的占用——"窃取"的就是这一小段。

DMA 访问主存时有三种可能：

| 时刻 CPU 的状态 | 处理办法 |
| :--- | :--- |
| CPU 不访存 | 存储器使用权与总线使用权直接分配给 DMA |
| CPU 正在访存，处在某个存取周期的中间阶段 | DMA 不能抢占，必须等这个周期结束 |
| CPU 与 DMA 同时请求访存 | DMA 优先，CPU 让出总线控制权和内存访问权 |

同时请求时为什么 DMA 优先？因为 DMA 上连接的都是**高速设备**，如果不及时响应，可能造成数据丢失。

```text
主存工作时间：  | CPU | DMA |  CPU  | CPU | DMA |
                      ↑             ↑
                窃取一个存取周期   再窃取若干周期
                （每个空档 DMA 窃取一个或几个存取周期完成传输）
```

这种方式的好处是：数据准备过程中 CPU 可以利用间隙完成访存操作，使**存储器和总线的利用率更高**。这一点其实非常重要——在现代计算机结构中，最影响机器效率和机器速度的就是主存储器。大家可能听说过一个词，没听说过的话希望到网上查一下：**存储墙（memory wall）**。去看看这个词的产生背景，以及目前有哪些方式在解决存储墙的问题，对我们理解"主存利用率为什么金贵"很有帮助。

#### 交替访问

第三种方式是让 DMA 和 CPU **交替访问内存**。这种方法把 CPU 的工作周期分成 C1 和 C2 两部分：C1 这段时间专供 DMA 访存，C2 专供 CPU 访存。由于在固定的时间点上，存储器和 I/O 总线的使用权是固定的，DMA 就**不需要提出申请、建立对总线的控制权**，传输速度会比较快，控制也简单。

```text
主存工作时间：  |——工作周期——|——工作周期——|——工作周期——|
                  C1  |  C2    C1  |  C2    C1  |  C2
                 DMA    CPU    DMA    CPU    DMA    CPU
              （前一段 DMA 控制并使用主存，后一段 CPU 控制并使用主存）
```

整个过程不需要申请、建立和归还总线使用权，由时序直接确定总线和内存使用权的归属。不过要说明：这种方式**实用性并不是非常强**。

### DMA 接口的功能与组成

接口的组成是由接口的功能确定的——先想清楚 DMA 接口在传输过程中要干哪些事，结构自然就出来了。想象一遍用 DMA 接口传数据的过程，可以归纳出五项功能：

1. **申请总线与内存**：要进行数据传送，DMA 接口要向 CPU 提出总线和内存的占用请求；
2. **接管控制权并控制传输**：CPU 允许之后，要处理控制权的转交，转交完要能真正控制、管理总线和内存，并控制数据的传输；
3. **确定传输方向**：数据是从内存写到外设，还是从外设读入内存，方向必须知道；
4. **定位与计数**：传输成块数据时，要知道内存首地址、数据块长度、设备地址；且每传输完一个字，都要修改内存地址、修改传输数据长度——改长度主要是为了判定数据块传送是否结束；
5. **报告完成**：传输结束后给出操作完成的信号，使 CPU 能做进一步处理。

对应这五项功能，来看 DMA 接口的组成。先给个大框图：DMA 既要和主存打交道，又要和 CPU 打交道，这里假设采用单总线结构，主存、CPU、DMA 接口都挂在总线上。

```text
            ┌────────────────────────── DMA 接口 ──────────────────────────┐
            │                                                              │
  CPU ══数据线══► 预置初值：AR（内存首址）、WC（字数）、DAR（设备地址）          │
            │                                                              │
  主存 ◄────┼── 地址线（AR 送出访存地址）                    ┌────────────┐  │
            │  ┌────┐ ┌────┐ ┌────┐ ┌─────┐              │  DMA 控制   │  │
            │  │ AR │ │ WC │ │ BR │ │ DAR │ │·控制逻辑·│◄─┤    逻辑     │  │
            │  └────┘ └────┘ └────┘ └─────┘              └────────────┘  │
            │              ▲                                    ▲          │
  外设 ◄────┼──────────────┴── BR 直连外设 ──── DREQ（设备请求）/应答 ──────┼──►
            │                                                              │
            │  ┌──────────┐                                                │
            │  │ 中断机构   │◄── WC = 0 时置位中断请求触发器                  │
            │  └──────────┘──── 传输完成后向 CPU 发中断请求                   │
            └──────────────────────────────────────────────────────────────┘
```

逐个部件看它们为什么非在不可。

**地址寄存器 AR**：CPU 要先告诉 DMA 接口从内存的哪个地址开始传输（或输入的数据从内存哪个地址开始存放），所以需要一个地址寄存器。AR 通过**地址线**把要访问的内存地址送给主存——从这里就能看到，DMA 接口接管了总线、接管了主存。

**字计数器 WC**：要知道传输的数据量，就需要一个计数器。这里有个提醒——WC **不能把它理解成厕所，它是字数计数**（word counter）。设每次传输的数据单位和编址单位相同、数据从首地址开始存取，并采用补码方式：WC 里保存的是 $-N$（$N$ 为要传输的数据数量），每传输一个数据，WC 加 1；加到 0 就表示传完了。AR 同理是每完成一个字的输入或输出就加 1（从低地址向高地址推进）。

**数据缓冲寄存器 BR**：外设输入的数据或主存输出的数据，都要暂存在接口的这个缓冲寄存器里，外部设备与 BR 直接相连。

**设备地址寄存器 DAR**：它有两个作用。一是供设备选择电路使用，判断这次访问的设备是不是本接口当前连接的、归这个 DMA 接口管理的设备；二是像访问硬盘这类设备时，DAR 里还可以保存**柱面号、磁道号、扇区号**，供数据传输过程中确认数据地址。

这几组初值——AR 的内存首址、WC 的数据数量、DAR 的设备地址——都是 CPU 通过**数据线**预置进去的；数据的输入输出当然也走数据线。

**DMA 控制逻辑**：输入输出过程需要它来控制。它控制接口内部协调工作，控制在给定时序发出给定信号——比如向 CPU 发出 DMA 请求，向主存发出读写控制命令。联络信号有两对：外设要做 DMA 传输，就向 DMA 控制逻辑发请求信号 **DREQ**（设备请求），DMA 控制器对设备给出应答信号；DMA 要占用总线、接管主存控制权，就通过总线向 CPU 发出总线使用请求，CPU 发出应答信号，由 DMA 控制器接收。

**中断机构**：可能有人会奇怪——DMA 不是为了摆脱中断吗，怎么接口里还有一个中断机构？它的用途是**数据传输完成之后的后续处理**：当 WC 计到 0、表示传输结束时，它向中断机构发信号，把中断机构里的中断请求触发器置 1；当一条指令执行结束之后，由中断机构向 CPU 发出中断请求，由 CPU 做传输后的处理。

> **提示**：DMA 接口的组成和它的功能一一对应——要申请总线所以有 DMA 控制逻辑和请求应答信号，要定位和计数所以有 AR、WC、DAR，要暂存所以有 BR，要做传输后处理所以有中断机构。这一点大家要记住。

## DMA方式的工作过程与机器数表示的开篇
> 对应块：BLK20 | 覆盖分集：P65-P68 | 块标题（分集名）：《5.6 DMA方式5.6-b1》

DMA 的一次传送过程，实际上可以分为三部分：首先是**预处理**，然后进行**数据传送**，数据传送结束之后做**后处理**。这三段各自干了什么、DMA 接口内部那些寄存器在一字一字传送时是怎么轮转的、它和程序中断方式到底差别在哪——这一讲我们把它彻底讲透。讲完 DMA 的收尾，我们就进入课程的新篇章：计算机当中数的表示与运算，从无符号数、机器数与真值讲到原码表示法。

### DMA传送的三段流程

#### 预处理：开工前的四项设置

可以想象，所谓预处理，就是在数据进行传输之前我们要做的一些相应设置。具体做法是通过几条输入输出指令，设置如下信息：

- **传输方向**：到底是输入还是输出，是从内存到 I/O，还是 I/O 到内存；
- **设备地址**：要和哪一个设备进行数据传输；
- **主存地址**：主存的哪一个地址要和设备进行交换；
- **数据量**：传输的数据量有多大。

这些工作做完，再启动设备。设备开始准备数据（或者进行状态准备）之后，才能开始真正的传输。

> **定义**：预处理 = CPU 用输入输出指令完成的方向、设备地址、主存起始地址、数据量四项设置，并启动设备。

#### 数据传送：一个字一个字地“抢”总线

预处理完成后，CPU 继续执行主程序当中输入输出指令后面的那些指令；至于数据真正的输入输出操作，由 DMA 接口来完成，DMA 接口控制完成**一批**数据的传送。也就是说，在整个传送过程当中，CPU 除了执行完那条输入输出指令、对 I/O 接口当中的寄存器进行设置之外，CPU 的工作和外部设备、接口的工作是**完全并行**的。数据传输完了以后，才能做后续的处理。

我们用图形的方式把数据传送的过程展示出来。每传一个字，都要回答同一个问题：能不能占用总线和内存的使用权？

```text
        ┌──────────────────────────────────────────────┐
        │      不允许传送：继续查询（CPU 正在占用         │
        │      总线或主存，DMA 接口就只能等）             │
        ▼                                              │
 是否允许传送？──允许──→ 主存地址送入总线（由 AR 寄存器给出）
                                                       │
        ┌──────────────────────────────────────────────┘
        ▼
 DMA 控制逻辑控制进行一个字的传输
        │
        ▼
 修改主存地址（为下一次传输做准备），同时修改字计数器 WC
        │
        ▼
 字计数器溢出（一块数据传完）？──否──→ 回到“是否允许传送”
        │ 是
        ▼
 向 CPU 申请程序中断，进入后处理
```

读这张图有几个关键点。**为什么主存地址要由 AR（主存地址寄存器）来送？** 因为只有这个寄存器知道，要交换的信息需要保存或者存储到主存的哪个地址当中。

**字计数器 WC 里装的是什么？** 它实际记录的是剩余要传输的数据量是多少个字。用这个计数器，我们就可以判断数据块的传输是否结束。如果我们采用**补码方式**来表示剩余数据的数量，那么每传一个字计数器加一，加到溢出（计满归零），就意味着数据块传输结束——这就是后面讲补码表示时大家能体会到的技巧。

传输结束时，它会向 CPU 申请一个程序中断。那这正是下一节要说的后处理。

#### 后处理：中断服务程序的三件事

前面已经提了好几次“后处理”，后处理到底做哪些工作？执行中断服务程序，做 DMA 结束的处理操作，具体包括：

- **数据的校验**：数据输入到主存，对不对，要做校验的工作；
- **判断是否继续使用 DMA 进行数据传输**；
- **检查传输过程是否正确**，要执行一个诊断程序。

从接口的图上我们看到，执行完数据输入或者输出以后，WC 的值发生了溢出、里面的值是零了，就提出中断请求。这些后处理的操作，就是 CPU 在响应了 DMA 接口的中断请求以后，执行中断服务程序来完成的。做完之后 CPU 中断返回，继续执行主程序。

### 以输入为例：DMA接口如何走完一字

前面我们给出了 DMA 接口的基本组成框图，下面以数据的**输入**为例，看 DMA 接口在数据输入过程中是如何工作的。

首先要明确：输入输出是以主机、以 CPU 作为出发点的。所以**输入就是指数据从外部设备送入到主存储器**。整个一步一字的接力过程是这样的：

```text
① 设备把数据送入数据缓冲寄存器 BR（保存要输入的数据）
② 设备 ──设备请求信号──→ DMA 控制逻辑（“数据已经准备好了”）
③ DMA 控制逻辑 ──通过总线向 CPU 提出占用总线和主存的请求──→ CPU
④ CPU 在允许的情况下给出应答，放弃对总线和主存的占用，
   总线和主存的控制权交由 DMA 接口控制
⑤ AR 把主存地址送上地址总线（不管读还是写，都要有这个地址）
⑥ DMA 控制器 ──应答信号──→ 设备（“已经开始进行数据传输”）
⑦ DMA 控制器发出对内存的读写控制命令，
   BR 中的数据通过数据线送到数据总线上
⑧ 每传输一个数据：AR 加一、字计数器加一，然后判断是否传输完
        ├─ 没结束：回到①（设备同样再把数据放入 BR，DMA 重新发出占用请求）
        └─ 结束：WC 值发生溢出
⑨ WC 的溢出信号送给中断机构的中断请求触发器，把它置位、参加中断排队，
   后面就是中断接口当中那一系列动作：CPU 接到中断请求，执行中断服务程序做后处理
```

这里注意职责的分界：数据和控制信号由 DMA 控制器以及 BR 发出——对内存的读写控制命令是 DMA 控制器发出的，数据是 BR 经数据总线送出的。

### 输出过程：方向反过来，骨架不变

输出就是把 BR 当中的数据送到设备当中去。骨架和输入完全一样，只是触发条件和数据流向反了过来：

1. 一次输出完成之后，**BR 已经空了**，设备通知 DMA 控制器：BR 已经空了，可以用于接收下一个数据了；
2. DMA 控制器向 CPU 发出总线和主存的控制权请求，CPU 在允许的情况下给出应答信号，内存和总线的控制权都交给 DMA 控制逻辑（或者说交给了 DMA 接口）；
3. 要进行数据输出，还要给出要访问的内存单元的地址——还是通过 AR 给出来；
4. 同时 DMA 对设备给出应答，告诉设备已经开始了新的传输；
5. 通过这些控制信号以及给出的地址信号，**主存当中的数据就会被再次写入到数据缓冲寄存器 BR 当中**；
6. 同时修改主存地址寄存器和字计数器，修改完字计数器以后判断传输是否结束。输出还没有结束的话，就循环刚才这个过程，要再一次向 CPU 提出总线和主存的占用请求；
7. 如果数据传输完成了，用 WC 的溢出信号告诉中断控制机构，把中断机构里边的**中断请求触发器**之一置位，由中断机构向 CPU 发出中断请求信号进行后处理。

### DMA接口与系统的连接方式

一台机器上可以有多个 DMA 接口，这多个 DMA 接口都要连接到总线上。那么怎么连接？这个方式大家应该比较熟悉，因为我们在讲总线那部分的时候，是有类似的结构——它就是总线仲裁思想的翻版。有两种方式。

#### 公共请求线：串行链接的翻版

大家一看这个结构就会觉得非常熟悉，就是总线进行仲裁的时候采用的**串行链接**方法：各个 DMA 接口通过地址线、数据线和主存进行连接，同时**所有的 DMA 接口共享一条请求线**，这条请求线是送给 CPU 的。

进行 DMA 响应的时候，各个 DMA 接口也是有优先级排序的：CPU 通过一条查询线，一个一个接口地进行查询，**越靠近 CPU 的 DMA 接口，它的优先级就越高**。

这种方式的优缺点，大家可以模拟总线仲裁里串行链接方式的优缺点来进行分析——逻辑完全一样。

#### 独立请求：排队搬进CPU里

第二种方法就是**独立的 DMA 请求**，类似于总线仲裁当中的独立请求方式。每一个 DMA 接口依然要和地址线、数据线进行连接——因为 DMA 接口要控制数据的传输过程，要通过地址线、读写命令线、数据线和内存之间直接进行数据交换。

和公共请求线方式不同的是：**每一个接口都有独立的 DMA 请求信号，每一个接口都有独立的 DMA 响应信号**，而排队的工作是在 CPU 内部完成的。

它的优缺点，大家也可以模仿第三章当中独立请求方式来进行分析。同时我们还可以模拟第三章当中给出的方法，给出第三种 CPU 和系统进行连接的方式。

### DMA方式与程序中断方式的比较

DMA 和程序中断这两条路，我们从五个角度做一个对比：

| 比较项 | 程序中断方式 | DMA方式 |
| :--- | :--- | :--- |
| 数据传送 | 由程序来传（中断服务程序），需要 CPU 的参与 | 直接由硬件进行控制，不需要 CPU 的参与 |
| 响应时间 | 在指令执行周期结束的时候，进行中断查询、响应中断 | 外部设备和主存直接交换数据，在**存取周期结束**时响应 |
| 处理异常 | 程序执行过程中发生异常，可以用中断方式处理 | DMA 方式不行 |
| 中断请求的作用 | 通过执行中断服务程序来**完成数据的传输** | 用于**后处理**：检查数据是否有错、还需不需要 DMA 传输、传输过程是否有错 |
| 优先级 | 比较低 | 更高 |

其中优先级这一条值得展开说一下为什么：DMA 方式是内存和外设之间直接进行数据交换，通常情况下连接的设备都是高速设备，所以在 I/O 和内存进行数据传输这件事上，DMA 方式的优先级更高，中断方式的优先级会比较低。

> **易错点**：两种方式都会发出中断请求，但目的和作用完全不一样——中断方式靠中断请求“干活”（传数据），DMA 方式靠中断请求“收尾”（后处理）。

### DMA接口的类型：选择型与多路型

DMA 接口主要有两种类型：选择型和多路型。区别的核心在于“物理上接几个设备、逻辑上能同时服务几个设备”。

#### 选择型：物理多挂、逻辑独占

**选择型**接口从物理上说连接了多个设备，但是在数据准备和数据传送的整个过程当中，在逻辑上这个接口只能连接一个设备。

看结构就明白了：选择型接口的这套寄存器及控制电路**只有一套**。某一个设备要使用这个接口进行数据传输，CPU 通过运行一条输入输出指令，对这些寄存器的值——字计数器、主存地址寄存器、设备地址寄存器等等——进行设置；设置成了某一个设备要和主存之间进行数据交换所需要的那些值之后，**其他的设备就无法再提出 DMA 请求、无法和主存之间进行数据交换了**。

所以从物理上讲有多个设备进行连接，但是从 CPU 运行那条输入输出指令、到准备数据、数据准备好、传输、一直到传输结束，这个过程中只能有一个设备使用这个接口。这就是选择型的含义。

#### 多路型：准备并行、传输串行

**多路型**接口在物理上连接多个设备，在逻辑上也可以连接多个设备；但真正进行数据传输的时候，也只能有一个设备和内存之间进行数据传输。差别在于：**数据准备阶段，可以有多个设备同时进行数据准备**。

下面以**通道**为例来介绍。我们前面讲过，通道是一种小型的 DMA 处理器，实际上也是一种 DMA 接口。一个通道下面包含了若干个**子通道**，每一个子通道都配有自己的一套主存地址寄存器、设备地址寄存器和字计数器：

```text
                ┌──────────────  通道（小型 DMA 处理器）──────────────┐
                │                                                    │
        ┌── 子通道 1：主存地址寄存器 + 设备地址寄存器 + 字计数器 ──→ 设备…
        │
  CPU ──┼── 子通道 2：主存地址寄存器 + 设备地址寄存器 + 字计数器 ──→ 设备…
        │
        └── 子通道 3：主存地址寄存器 + 设备地址寄存器 + 字计数器 ──→ 设备…

  数据准备：多个设备经各自子通道并行进行
  数据传送：串行执行——一次只有一个设备和内存之间传输
```

工作过程是这样的：设备进行数据传输时，CPU 执行到了输入输出指令、要控制某一个设备进行输入输出，它就对**相应子通道**当中的寄存器进行设置；设置完以后就继续执行自己的程序。碰到了下一条输入输出指令，如果两个设备使用的是**不同的子通道**，那么它会对其他子通道当中的主存地址寄存器、字计数器、设备地址等等再次进行设置。外部设备在之后的时间里就可以进行数据准备——这个数据准备是**多个外部设备并行进行**的。外部设备准备好了，通过子通道向通道提出数据传输请求；这个时候不同设备的数据传输，就是**串行执行**的。

#### 多路型工作实例：磁盘、磁带与打印机

我们用一个具体的时序例子看多路型接口如何响应多个设备。假设一个多路型接口连接了三个设备：

| 设备 | 提出请求的间隔 | 说明 |
| :--- | :--- | :--- |
| 磁盘 | 每 30 µs 一次 | 30 µs 包含了数据的传送时间和数据的准备时间 |
| 磁带 | 每 45 µs 一次 | 比磁盘慢一点 |
| 打印机 | 每 150 µs 一次 | 更慢，其余时间在进行数据准备，准备好了才能提出请求 |

并且假设真正用于数据传送的时间是 **5 µs**——也就是 DMA 接口当中的数据送入到主存、或者主存当中的数据送入到 DMA 接口，这个事情只需要 5 µs。

```text
 请求/响应时序（示意，时间自左向右）：

  打印机  请求(最早) ···································· （每隔 150 µs 再请求）
  磁盘    ····· 请求  请求  请求  请求  请求 · 请求 ···   （每隔 30 µs）
  磁带    ····· 请求   请求   请求   请求 ·  请求 ···    （每隔 45 µs）
          ─────┬───┬────┬────┬────┬────┬───┬────┬────→
  响应：    打印机  磁盘  磁带  磁盘  磁带  磁盘  磁盘  磁带
            (5µs) (5µs) (5µs) (5µs) (5µs) (5µs) (5µs) (5µs)
                          ↑
              磁盘与磁带同时提出请求时：响应磁盘
```

怎么读这段时序：由于打印机是最早提出请求的，那么首先响应打印机的请求，把 5 µs 的时间给打印机进行数据传输。这个数据传输结束以后，时间向后延续，磁盘和磁带**同时**发出了传输请求、都要使用总线和 DMA 接口同总线内存进行数据交换——响应谁？谁的优先级高。**速度越高的设备，它的优先级就越高**，所以在这儿我们要响应磁盘的操作，用 5 µs 完成数据传输。

注意这里有一个前提：因为是多路型的，数据在请求之前就已经被放入到 DMA 接口当中的数据缓冲器里面了，所以这 5 µs 就是纯粹用于接口当中的数据和主存当中的数据进行传输。响应完磁盘，接着响应磁带的请求——下一个 5 µs。然后时间再向后延续：磁盘的输入请求，5 µs；磁带的输入请求，5 µs；再往后又是磁盘的输入请求……到最后两条竖线的位置，又是磁盘和磁带同时提出了请求，还是响应磁盘的请求（磁盘速度更高），然后再响应磁带。

从这个例子可以看到一个重要结论：**尽管一个多路型的通道连接了多个设备，但实际上还有很多时间这个通道是处于空闲状态的，还可以连接更多的设备。**

> **提示**：选择型的通道、多路型的通道，大家如果觉得不好理解，建议去看一下体系结构教材当中有关通道处理机的表述。

#### 数据表示与第六章的内容组织

首先必须了解什么叫做**数据表示**。

> **定义**：数据表示是指在计算机当中能够被硬件直接识别和处理的数据类型。所谓能够被硬件直接识别和处理，是指在计算机系统的指令集当中为这些数据提供相应的指令，必须用硬件来实现这些运算。

在接下来的讲解过程中，我们将分析数据的**笔算方法**，并且对笔算方法进行改进；在此基础上，借助笔算方法，研究这些算法在计算机当中用硬件如何实现，给出相应的硬件组成。

第六章一共分了五节：首先介绍计算机系统当中的无符号数和有符号数；在介绍的基础上，看无符号数和有符号数在计算机当中是如何表示的、如何存储的；然后介绍定点运算和浮点运算，利用存储在计算机当中的数据完成算术操作和逻辑运算；在此基础上，根据运算方法，设计算术逻辑运算单元。

第一节“无符号数和有符号数”要讲两个主要内容：首先是无符号数，然后是有符号数。有符号数的第一部分内容是**机器数和真值**——一个实际给定的数值存储到计算机当中，如何存储、如何表示，这个表示的方法就是机器数。机器数的表示方法按顺序有四种：**原码表示法**、**补码表示法**（在分析原码表示法存在的问题之后给出）、**反码表示**和**移码表示**。对这四种机器数表示方法，我们主要介绍：用数学方式给出定义、逐个分析每一种表示方法的特点并举例；机器数和真值之间如何转换、不同类型的机器数相互之间如何转换；以及机器数的表示范围和字长之间的关系。

### 无符号数：只有数值部分

无符号数就是没有正负号的这些数据。大家学过 C 语言，在 C 语言当中已经使用过无符号数了；在我们这门课里，看的是它在计算机当中怎么表示、怎么存储。

实际上无符号数的表示和存储非常简单：它只有数值部分，用计算机当中的寄存器或者存储器，按照规定的长度把它保存进去就可以了。如果这个无符号数保存在寄存器当中，那么**寄存器的长度就直接给出了无符号数的表示范围**：

| 寄存器位数 | 表示范围（二进制） | 表示范围（十进制） |
| :--- | :--- | :--- |
| 8 位 | 8 个 0 ～ 8 个 1 | 0 ～ 255 |
| 16 位 | 16 个 0 ～ 16 个 1 | 0 ～ 65535 |

所以无符号数非常简单。麻烦的是带符号的数。

### 机器数与真值：符号也要数值化

有符号数是指有正负号的这些数。它们在计算机当中怎么表示？实际上也很简单：一个数由两部分组成——**符号**和**数值**，我们只要把这两部分都保存到计算机当中（保存到存储器或者寄存器当中），任务就完成了。

先把两个名词钉死：

> **定义**：保存在计算机当中的数，叫做**机器数**；平时用的数据的真实的值——带有正负号的那个数，叫做**真值**。

真值是带符号的，符号是正号或者负号。而在计算机当中，这个符号要把它**数值化**——用数字来表示数的符号。为什么可以用数字表示符号？因为计算机当中的存储元件存储信息的时候，可以存储低电平或者高电平，我们把它形象地称为 0 或者 1，那么就可以用 0 和 1 这两种状态来代表数的符号。

除了符号，还有一个容易被忽略的问题：**小数点**。这一点大家要记住——

> **注意**：在计算机当中没有专门的硬件用于表示小数点，计算机当中的小数点都是以**约定的方式**给出的。

#### 小数形式：小数点约定在符号位后面

以正数 $+0.1011$ 为例。把它保存到计算机当中，要保存三部分内容：这个数的符号、小数点的位置、数值位是什么。假设我们约定用 0 表示正号，那么机器数的形式就是：第一位 0 是符号位，后面的 1011 直接存放在寄存器或者存储器当中表示数值；小数点在设计计算机的时候就可以约定它的位置——就在符号位的后面。

负数 $-0.1011$ 同理：1 是符号位，表示当前这个数据是一个负数；小数点的位置以约定的方式给出，没有任何硬件来表示；后面放的是数值位。

所以从存储单元或者寄存器当中，我们看到的数据依然是一串 0、1 代码；在这串代码当中，某一位（我们约定放在最高位、寄存器的最左端）表示了数据的符号位，符号位的后面就是小数点的约定位置。在编程的过程当中，要遵守这个约定。

#### 整数形式：小数点约定在数值位最后

比如真值 $+1100$，保存到计算机当中同样需要解决三个问题：符号、数值的保存、小数点。机器数的形式是：0 是符号位（正数），1100 是数值，小数点的位置**约定在数值位的最后**。如果是 $-1100$，同样是 1 作符号位、1100 作数值部分，小数点在数值部分的最后，以约定的方式给出——一定要记住，没有任何硬件用于标识小数点的位置。

这样一来，把符号数值化之后，定点计算机——也就是小数点位置固定的这些计算机——可以分成两类：

| 类型 | 小数点约定的位置 |
| :--- | :--- |
| 小数定点机 | 符号位的后面 |
| 整数定点机 | 数值位的最后 |

### 原码表示法：带符号的绝对值

实际上，把符号数字化（数值化）本身，就已经给出了一种机器数的表示方式——我们把这种表示方式称为**原码表示法**。下面看它的定义。

#### 整数原码的定义

这个定义我们以数学的方式给出，区分整数和小数。先看整数。设真值为 $x$，数值部分的位数为 $n$：

$$[x]_{原} = \begin{cases} 0,\,x, & 0 \le x < 2^n \\[4pt] 2^n - x, & -2^n < x \le 0 \end{cases}$$

逐条解读：

- $x$ 大于等于零时，原码的形式就是“$0,\ x$”——逗号前那个 0 表示符号位，说明这是一个正数或者大于等于零的数；逗号后的 $x$ 是真实的数值部分。**逗号的作用就是把符号位和数值部分隔开**，小数点则在约定的位置（数值位的最后）。
- $x$ 是负数时，符号位变成 1。$2^n - x$ 怎么理解？$x$ 是负值，减 $x$ 相当于加上 $x$ 的绝对值，而数值部分是 $n$ 位，数据位最高位的位权就是 $2^n$——所以这一支实际上就相当于**给这个数据的绝对值加上了 $2^n$**，加出来的进位正好落在符号位上，把符号位置成 1。

#### 两个例子

**例一**：$x = +1110$。根据定义，在符号位的位置写一个 0，然后是逗号（表示这个数据是一个整数），数值部分直接把真值的数值部分照抄，小数点在约定的位置——数值位的最后：

$$[+1110]_{原} = 0,\,1110$$

**例二**：$x = -1110$。假设在计算机当中存储这个整数，数值部分是 4 位，即 $n = 4$。按照定义，这是一个小于零的值，用 $2^n - x$ 来求它的原码：

$$[-1110]_{原} = 2^4 - (-1110) = 2^4 + 1110 = 1,\,1110$$

还是用逗号把符号位和数值部分进行了分离。

#### 定义里的不等号与零的原码

定义中几个不等号的选择是有讲究的，这也是容易忽略的细节：

- 上界为什么是严格的 $x < 2^n$？因为数值部分如果是 $n$ 位的话，即使数值部分全都是 1，它能表示的最大整数值也只是 $2^n - 1$，所以这里用的是大于号。
- 负数一侧为什么是 $-2^n < x$？因为它所能表示的最小值，只能到“1，后面数值位全 1”所对应的 $-2^n + 1$，所以表示范围是从 $-2^n$ 的右侧一直到 0。
- 零有两个分支都覆盖：$x = 0$ 时，$x \ge 0$ 和 $x \le 0$ 两个分支都适用，用这两种办法计算出来的 $[x]_{原}$ **可能会不同**。这是原码的一个固有特点，后面讲补码的时候还会再回到这个话题。

从例子和定义可以看出原码的本质：如果真值是正数，符号位用 0 表示；是负号，符号位用 1 表示——因此原码表示法实际上是**带符号的绝对值**表示：我们保存的是数据的绝对值，只是在符号位部分用数值化的 0 和 1 来标记正负。

> **结论**：原码 = 符号位（0 正 1 负，数值化的符号）+ 绝对值的数值部分；逗号只是书写时把符号与数值隔开的记号，小数点的位置完全靠约定，没有任何硬件。

## 原码的小数表示与补码：从拨时钟到模运算
> 对应块：BLK21 | 覆盖分集：P69-P71 | 块标题（分集名）：《6.1无符号数和有符号数6.1-a3》

上一段我们处理的是整数的原码，这一段先看**小数**的原码表示，然后顺着原码在加减法上的麻烦，一步步推出补码——从生活里最熟悉的时钟讲起，把"减法变加法"这件事彻底讲清楚。

### 小数的原码：小数点前那位当符号

小数就是 $0.x_1x_2\cdots x_n$ 这种形式。如果 $x$ 是一个小数，并且它的值在 0 和 1 之间（**包括零，不包括一**），那么它的原码定义是：

- **正数**：原码就是真值本身去掉符号，小数点前面那一位用 0 来代表它是正数；
- **负数**：把小数点前面那一位作为符号位，用 1 表示，数值位照抄。写成公式就是 $[x]_原 = 1 - x$（因为 $x$ 是负值，$1-x$ 实际上就是 $1 + |x|$）。

举例来说，$x = +0.1101$，它的原码直接就是 0.1101。注意这里的两个 0 意义不一样：小数点前面这个 0 是**真正的数据**，表示小数点前第一位的值是零；写在 $[x]_原$ 前面的那个 0 表示的是**这个数的符号**——它是一个正数。小数点在约定的位置以约定的方式给出，符号位和数值位之间用小数点隔开。

再看负数的例子：$x = -0.1101$，按定义 $[x]_原 = 1 - x = 1 + 0.1101 = 1.1101$，还是用小数点把符号位和数值位隔开。

> **提示**：回想整数那边——整数是用**逗号**把符号位和数值部分分开的。但这个逗号和小数点真的存进计算机了吗？没有。无论整数的逗号还是小数的小数点，在计算机里都是**不需要存储的**，它们仅仅是为人的阅读方便加上去的。

第三个例子：$x = +0.1000000$（1 后面六个零），它的原码就是它本身 0.1000000。虽然原码就是数值本身，但要记住：原码中符号位位置上的 0，和真值当中小数点前面那一位的 0，意义是不一样的。若 $x = -0.1000000$，就用公式 $1 - x$ 计算，很容易得出原码是 1.1000000。

把这几类例子放在一起，规律其实非常简单：

- **整数**：加一个符号位，正数加 0、负数加 1，后面跟一个逗号，数值部分照抄，就是原码；
- **小数**：小数点前面那一位用于表示符号，正数用 0、负数用 1，小数点后面的数值部分照写。

但在这个过程当中一定要记住：**原码是保存在计算机当中的数据**。既然存进计算机，不管放的是寄存器还是存储单元，位数都是有限的。所以题目让你求某一个真值的原码时，**一定要告诉你机器数的长度是多少，并且这个长度包含了一位符号位**，这样我们才能做变换。

### 从原码找回真值

已知原码求真值，同样非常好求。

**例 6.1**：已知 $[x]_原 = 1.0011$（小数，定点小数机），求 $x$。符号位是 1，说明它是负数。按定义，$x = 1 - [x]_原 = 1 - 1.0011$，得 $x = -0.0011$。其实还有一种更容易的解法：原码的符号位换成负号，数值位照抄，直接就是 $-0.0011$。

**例 6.2**：已知 $[x]_原 = 1{,}1100$（整数），求 $x$。符号位是 1，是负数。数值部分长度是 4，所以 $x = 2^4 - [x]_原$，算出真值是 $-1100$。实际上根据原码变换的原理，机器数符号位直接变成负号、数值位照抄，同样得到 $-1100$。

**例 6.3**：已知 $[x]_原 = 0.1101$，求 $x$。这个例子就更简单了：小数点前面的 0 表示这是一个正数，它的值就是 $+0.1101$。

**例 6.4**：$x = 0$，求 $[x]_原$。根据原码的定义，$x \ge 0$ 和 $x \le 0$ 时原码是不一样的——也就是说**零的原码有两种形式**，而且整数、小数各有表现。设 $x$ 是小数、数值部分长度是 4 位：

- 正零：$[+0]_原 = 0.0000$；
- 负零：按定义 $[x]_原 = 1 - x$，得 $[-0]_原 = 1.0000$。

整数同理，数值部分 4 位：$[+0]_原 = 0{,}0000$，$[-0]_原 = 1{,}0000$。从这里可以看出来：**正零和负零的原码并不相等**。这一点先放在这儿，后面讲到补码时会有一个有趣的对比。

### 原码的麻烦：加减法要做两种运算

原码的特点非常简单、非常直观，变换起来也容易：符号位位置上正号换成 0、负号换成 1，整数后面跟逗号、小数后面跟小数点。但是在**运算**的时候，例如加减法运算，用原码就会出现问题。

我们看两个数做加法时，运算器实际要做什么操作：

| 数一 | 数二 | 实际操作 | 结果 |
| :--: | :--: | :-- | :-- |
| 正 | 正 | 加法 | 正数 |
| 正 | 负 | 减法 | 可正可负，看两者绝对值谁更大 |
| 负 | 正 | 减法 | 可正可负 |
| 负 | 负 | 加法 | 负数 |

同样是"加法"这个过程，如果用原码表示，运算器可能做加法、也可能做减法，结果符号还要额外判断——这对运算器来说是比较麻烦的。

于是就提出一个问题：**能不能对加法和减法进行归一化，只用加法就能完成加法或者减法的运算？** 进一步分析，这个问题实质上是：在减法运算的过程中，我们能不能找到一个**与负数等价的正数**，用这个正数去替代参加运算的那个负数，把减法操作转换成加法操作？如果可以，那么不管加法还是减法，在运算器当中就统一成加法运算了。下面要讲的补码表示法，解决的正是这个问题。

### 时钟给我们的启发：负数可以用正数代替

补码这个概念，我们从生活当中的一个例子开始讲——时钟。假如现在是六点，我们要把时钟调整到三点，有两种方法：

```text
从 6 点调到 3 点：
  方法一：逆时针拨 3 格（逆时针视为减法）  6 - 3 = 3
  方法二：顺时针拨 9 格（顺时针视为加法）  6 + 9 = 15
          时钟以 12 为模，到 12 归零重新计数
          15 - 12 = 3  -->  效果相同
```

时钟有一个特点：**它是以 12 为模的**。显示的时间到 12 实际上就归零了，又从一开始计数，所以多出来的那个 12 会被减掉。由此可见，像时钟这样的有模的、能记录数据的设备上，我们**可以用正 9 来代替 −3，把减法变成加法操作**。这时我们就称正 9 是 −3 以 12 为模的**补数**：减 3 和加 9 会得到同样的效果，记作 −3 与 +9 在模 12 的情况下等价。

同理，想从六点拨到两点：逆时针拨 4 格，或者顺时针拨 8 格，效果相同——减 4 操作可以用加 8 操作替代；−5 和正 7 在模 12 的情况下，减 5 和加 7 效果也完全相同。

由此我们得到几条结论：

> **结论**：一个**负数加上模**，就得到这个负数的补数。比如 −3 加上 12 就是它的补数。但记住——**谈补数一定要先指定模是多少**，否则补数无从谈起；补数本身是一个正数。

> **结论**：互为补数的一个正数和一个负数，**它们绝对值的和就是模**。比如 −3 和 +9、−4 和 +8，绝对值的和都是 12。

> **结论**：**正数的补数就是它自己**。

### 把时钟换成寄存器：模就是字长

计算机当中的数据存储设备和时钟实际上是相似的。举一个简单的例子：设存放数据的寄存器是**四位**的，那么它计数的时候就是**模 16** 的——一旦做加法加到大于等于 16，进位部分将被自动丢掉，这点和时钟非常相似，只不过时钟以 12 为模，四位计数器以 16 为模。

比如要把 1011 变成 0：

```text
4 位寄存器（模 16）：
  减法：1011 - 1011 = 0 0000
  加法：1011 + 0101 = 1 0000   最高位进位自然丢掉 --> 0 0000
```

从这个例子可以看出：减掉 1011 这个减法操作，完全可以用加上 0101 这个加法操作来替换。在模 16 的情况下，**−1011 做减法的效果和 +0101 完全相同，−1011 模 16 的补数就是 +0101**（16 − 11 = 5，即 0101；两者绝对值之和正好是 16）。

同样的道理：

- 数据是 −011、寄存器是三位的，模就是 8，减 011 的操作可以换成加 101 的操作（8 − 3 = 5）；
- 数据是 −0.1001 的小数，符号位一位加上后面的数值位，什么时候会把最高位的进位扔掉呢？当加法的结果达到 2 的时候。也就是说小数是**模 2** 的，−0.1001 的补数就用 $2 - 0.1001$ 来计算（负数和它的补数绝对值相加等于模），得到 1.0111。

那么问题来了：0101 既可以看作正数 0101（正数的补数是它自己），又是 −1011 的补数——**这个 0101 到底是一个正数，还是那个负数的补数？** 为了对它们进行区别，我们引入符号位：

- 正数 0101 的补数，写成 0,0101——符号位添 0，逗号隔开符号位和数值位；
- 负数 −1011 的补数，写成 1,0101——符号位添 1。

怎么实现在符号位上"正数添 0、负数添 1"呢？其实非常简单。求补数时我们给这个数加上了 $2^4$（模 16），现在要想在符号位的位置给负数添一个 1，注意这一位的位权正是 $2^4$，所以还要再加一个 $2^4$——两个 $2^4$ 就是 $2^{4+1} = 2^5$，我们就用 $2^5$ 作为模来计算补数：

- 负数：$2^5 - 1011 = 1{,}0101$，和我们前面的结果一致；
- 正数：$2^5 + 0101 = 10{,}0101$，符号位只有一位，最高位那个 1 会被丢掉，结果还是 0,0101。

这样，补码就用一位符号位来表示这个数是正还是负了：整数用逗号把符号位和数值部分隔开。

### 补码的定义：整数与小数

根据上面的分析，我们可以正式给出补码的定义。

**整数**的补码：

$$
[x]_补 =
\begin{cases}
0,\,x, & 0 \le x < 2^n \\[4pt]
2^{n+1} + x, & -2^n \le x < 0
\end{cases}
$$

其中 $n$ 是**数值位的位数，不包括符号位**——这点大家要记住。正数时补码就是符号位填 0、逗号、后面直接写真值的数值部分；负数时用 $2^{n+1} + x$ 计算。注意负数这一段是**带等号的**：采用补码形式，最小可以表示到 $-2^n$——这比原码多表示了一个数，为什么能这样写，在后面的分析当中大家能够看到。另外，$x = 0$ 时，不管是正零还是负零、不管整数形式还是小数形式，**补码都是相同的**——和原码的两种零对比着记。

看几个例子。设计算机存储数据字长 5 位，1 位符号位、4 位数值位：$x = +1010$，正数的补码就是它本身，符号位填 0，得 $[x]_补 = 0{,}1010$。再设字长 8 位、1 位符号位、7 位数值位：$x = -1011000$，按定义 $[x]_补 = 2^8 + x$，用二进制算就是 1 后面八个零减去 1011000，非常好算，结果是 $[x]_补 = 1{,}0101000$。这里注意：**模是 $2^{n+1}$，$n$ 是数值位的位数**。

**小数**的补码：

$$
[x]_补 =
\begin{cases}
x, & 0 \le x < 1 \\[4pt]
2 + x, & -1 \le x < 0
\end{cases}
$$

还是借助真值中小数点前面那个 0 的位置来表示符号。真值为正时补码就是真值本身；真值为负时补码是模 2 的，用 $2 + x$ 计算。

这里有一个要点：真值小数点后面的有效数字，你想写多长就可以写多长，只要那张纸能写下；但在计算机当中，$x$ 的补码是**机器数**，机器数是有位数约定的。假如真值数值部分有 8 位，而机器数的数值部分只能表示 6 位，那么真值最后两位就会被扔掉或者做舍入处理——这时补码的值和真值并不严格相同。**一定要记住，我们的数据是要存放在计算机当中的，受到计算机硬件资源（或体系结构定义的数据长度）的限制。**

举例：$x = +0.1110$，设小数定点数存储字长 5 位，1 位符号位、4 位数值位，小数点约定放在符号位后面，则 $[x]_补 = 0.1110$。若 $x$ 是负数，如 $x = -0.1100000$，设字长 8 位（符号位 1 位、数值位 7 位），它是 $[-1, 0)$ 区间的数，直接用公式 $[x]_补 = 2 + x$，算得 $[x]_补 = 1.0100000$，符号位是 1，表示负数。

还要记住一点：**小数的补码是模 2 的**。当然你也可以模别的数：模 4 的话小数点前面是两位，模 8 是三位，模 16 是四位。后面讲溢出的时候，我们会引入模 4 补码，到时看它有什么作用。

### 快捷方式：符号位不变，数值位取反加一

由真值计算负数的补码，实际上要做一次减法：整数是 $2^{n+1}$ 减去整数的绝对值，小数是 2 减去小数的绝对值，求起来略显麻烦。实际上求补码有**快捷方式**，我们用一个例子来说明。

设 $x = -1010$，数值部分 $n = 4$，模是 $2^5 = 32$。按整数补码的定义：

$$
[x]_补 = 2^5 - 1010
$$

$2^5$ 就是 1 后面五个零。我们真正做减法的时候是怎么做的呢？把 100000 拆成"11111 再加 1"：先用 11111 去减 1010。由于都是二进制数，逐位相减时 1 减去对应位的值，等于把该位取反——原来该位是 0，1 减 0 得 1；原来该位是 1，1 减 1 得 0。所以 11111 减 1010 就得到 10101，然后再加上拆出来的那个 1，得到 10110，即 $[x]_补 = 1{,}0110$。

现在把 $x$ 的原码摆在一起看：$[x]_原 = 1{,}1010$，$[x]_补 = 1{,}0110$。符号位的位置都是 1，数值位每一位都相反，补码还多加了末位的 1。由此可以总结出：

> **结论**：当真值为负时，从原码求补码——**保持符号位不变，数值位每位取反，末位加 1**。前提是它的真值必须是负值；否则正数的原码和补码形式完全一样，符号位都是 0，不需要变。

这个例子可以推广：把 $x$ 改为任意的 $x = -x_1x_2\cdots x_n$（数值部分 $n$ 位，模 $2^{n+1}$），用同样的方法可以推出，对任何一个真值为负的数，这个规则都成立。这就是求补码的快捷方式，**希望大家掌握**——它比利用公式直接计算一个负数的补码要快得多。

如果从真值开始直接求补码也可以：真值和原码只是符号的表示有差别——真值用正负号表示负数，原码用符号位等于 1 表示负数，数值部分是相同的。所以从真值求负数的补码，直接把符号位写成 1，然后对数值部分每位取反、末位加 1。当然前提是它是负数，并且转换过程中**一定要考虑计算机规定的数据字长是多少**。

### 从补码变回真值

**例 6.5**：已知 $[x]_补$ 的符号位是 0（形如 $0.xxxx$ 的小数），求 $x$。符号位为 0 说明 $x$ 是正数，正数的补码和真值相同，直接把符号位的 0 换成正号写出来就可以了——因为真值是用正负号表示数据符号的。

**例 6.6**：已知 $[x]_补 = 1.0001$，求 $x$。可以用定义来求：$[x]_补 = 2 + x$，推出 $x = [x]_补 - 2$，直接计算即可。其实还有一个方式：由补码变回原码。用上一段总结的转换规则——符号位保持不变、数值位每位取反、末位加 1——从补码转换出原码 $[x]_原 = 1.1111$，再把符号位的 1 改成负号，就得到真值 $x = -0.1111$。

**例 6.7**：已知 $[x]_补 = 1{,}1110$，这是整数定点计算机当中保存的一个数据，$n = 4$。符号位是 1，说明是负数。按定义，模是 $2^{4+1} = 2^5$，用 $[x]_补$ 减去模就得到 $x = -0010$。同样也可以先用规则由补码变原码：符号位依然是 1，数值位 1110 每位取反得 0001、末位加 1 得 0010，所以 $[x]_原 = 1{,}0010$；已知原码求真值非常容易，$x = -0010$。

所以这条规则大家要记住：**当真值为负的时候**——这个前提不能忘——把补码除符号位之外的数值位每一位取反、末位加 1，就得到原码。如果真值是正数，原码补码形式完全相同，不需要任何变化。

### 本讲提到的题目

讲完"补码变原码"的规则后，课上留了一个证明任务：请证明这条规则对任意负小数成立。

**题目**：设真值 $x = -0.x_1x_2\cdots x_n$（数值部分 $n$ 位），证明：由补码到原码的变换规则"符号位不变，数值位每位取反，末位加 1"是成立的。

**解析**（依据正文中的补码定义与"取反"的推导思路）：由小数补码定义，$[x]_补 = 2 + x$，于是 $|x| = -x = 2 - [x]_补$。设 $[x]_补 = 1.y_1y_2\cdots y_n$，把模 2 拆成 $1.\underbrace{11\cdots1}_{n} + 0.\underbrace{00\cdots0}_{n-1}1$。前一项减去数值部分时，$1 - y_i$ 恰好是 $y_i$ 取反（与正文中 11111 减数的逐位分析相同），得 $0.\bar{y}_1\bar{y}_2\cdots\bar{y}_n$；再补上拆出来的 $0.00\cdots1$，即末位加 1。所以 $[x]_原 = 1.(\bar{y}_1\bar{y}_2\cdots\bar{y}_n\ \text{末位加}\ 1)$——符号位不变、数值位每位取反、末位加 1，规则成立。

## 补码、反码与移码：机器数表示的进阶细节
> 对应块：BLK22 | 覆盖分集：P72-P74 | 块标题（分集名）：《6.1无符号数和有符号数6.1-b3》

上一节我们建立了补码、反码的定义，这一节先从一道例题入手：**求下列真值的补码**。把真值列出来，$\pm 70$，先把它们变成二进制，再一步步求出原码和补码。这道题做完，我们会顺手提炼出一条负数补码的快速转换规律；然后转到反码的表示法，做三种机器数的小结，再看同一串二进制代码在不同解读下真值差多少；最后讲一种新的机器数——移码，它就是为了"一眼比大小"而生的。

### 从真值到补码：例题与快速规律

先解决 $\pm 70$ 的二进制转化。规则化的方法非常容易：一次一次地除以 2，看余数，把余数从最低位排到最高位，就得到二进制。不过我一般用 $64+4+2$ 来算，直接把二进制写出来——70 就是 `1000110`，一个一、三个零，再加上 4 和 2 对应的 `110`。

接下来求机器数。假设 $x = \pm 70$，机器字长 8 位，其中一位是符号位，小数点在数值位的后面——这是一台整数定点机。

对 $x = +70$ 这种大于零的数，原码就是 `0,1000110`：注意整数这里是用**逗号**把符号位和数值部分隔开的。正数的数值部分和真值完全相同，补码也是同样的一个值。

对 $x = -70$，符号位是 1，数值部分照着真值抄下来，得到原码 `1,1000110`。再从原码转补码：符号位保持不变，每位取反、末位加一——`1,1000110` 变成 `0,0111010`。

看投影上的这个值，实际转换时根本不用老老实实"取反再加一"，有个规律：

> **规律**：负数的补码，从最低位往高位看，**最后一个 1 以及它右边的所有位照抄**，其余各位（含符号位）**全部取反**。

写成一般形式：若真值是 $-0.x_1x_2\cdots x_k1\underbrace{00\cdots0}$（最后一个 1 后面跟若干个 0），那么它的补码就是

$$[x]_\text{补} = 1.\bar{x}_1\bar{x}_2\cdots\bar{x}_k1\underbrace{00\cdots0}$$

符号位用 1 表示，$x_1$ 到 $x_k$ 每位取反，末尾那个 1 和后面的 0 照写。回头看 $-70$ 的例子：`1,1000110` 里最低位的 1 和它右边的 `0` 保持不变（`10`），前面的每位取反（第一个 1 变 0、三个 0 变一、一个 1 变 0），直接写下来就是 `0,0111010`。这种方法成立，大家可以自己去证明一下。

再举第三个小数的例子。$x = 0.1110$，假设这是台小数定点机，机器字长 5 位：一位符号位，四位数值位。大于零，所以原码 `0.1110`，补码也是这个形式。换成负数 $-0.1110$：原码把符号位改成 1，得 `1.1110`；补码符号位保持不变还是 1，小数点后面的两个 1 变成 0，后面那个 1 照写下来——`1.0010`，这就是 $x$ 的补码。

然后看零。$x = +0$，补码是零，原码也是零。$x = -0$ 呢？补码还是零：按小数补码的定义 $[x]_\text{补} = 2 + x$，2 加上 $-0.0000$ 得到 `10.0000`，符号位只有一位，前面那个 1 要丢掉，所以 $-0$ 的补码还是 `0.0000`。但原码就不一样了：符号位是负值，原码是 `1.0000`。

> **结论**：正零和负零的补码形式相同，原码形式不同。整数也一样——按补码定义可以推出，正零和负零的补码同样是相同的，大家也可以去证明一下。

还有个特殊值：$-1$ 的补码。用定义推：$2 + (-1) = 1$，用二进制表示就是 `1.0000`。从这里能看出，$-1$ **是有补码的**，它的补码就是 `1.0000`；但是它**没有原码形式**——原码表示不了它。

最后强调一件事，一定要记住：补码方式最大的好处是**可以把减法转换成加法**。不要因为经过这一系列细节的讲解，就把补码这个本质的能力给忘掉了。

### 反码表示法

补码的做法是：负数符号位为 1，后面的数值位在原码数值位的基础上每位取反、末位加一。那么反码表示呢，就是**末位加一这个"一"不加了**——比补码还少一步。

先看整数的定义。若 $0 \le x < 2^n$（正数），反码就是

$$[x]_\text{反} = 0,\ x$$

用逗号把符号位和数值部分隔开，这个 $x$ 就是真值。但一定要记住：反码也是一种机器数表示形式，要受到计算机当中对字长规定的限制、受到存储资源的限制。如果说真值的数值部分是六位，而机器字长规定整数表示只有四位，那么后两位就要扔掉，这一点要比较清楚。

若 $x < 0$（负数），补码用的是模 $2^{n+1}$，即 $[x]_\text{补} = 2^{n+1} + x$。现在末位那个加一不加了，实际上就相当于把模减了一，所以

$$[x]_\text{反} = (2^{n+1} - 1) + x \quad (\bmod\ 2^{n+1}-1)$$

这里 $x$ 是真值，$n$ 是数值部分的位数——即计算机系统中规定的整数表示时数值部分的位数。

小数对应地：若 $0 \le x < 1$，$[x]_\text{反} = x$；负数时，补码是模 2，小数末位加一加的是 $2^{-n}$，现在不加了，所以模要从 2 里减掉 $2^{-n}$：

$$[x]_\text{反} = (2 - 2^{-n}) + x \quad (\bmod\ 2-2^{-n})$$

这里 $n$ 是小数的位数。反码和补码的区别就是最后这一位：补码要加的那个"一"，现在不加了，所以从模当中把 $2^{-n}$ 减掉。

举个例子。$x = +1101$，机器字长 5 位、一位符号位四位数值位，大于零的值只需加一个符号位：`0,1101` 就是 $x$ 的反码。$x = -1101$ 时，符号位是 1，数值部分按定义计算：$(2^5 - 1) - 1101$，也就是 $1111 - 1101$，实际上就是对 `1101` 每一位做取反，得到 `0010`，所以 $[x]_\text{反} = 1,0010$。

小数例子。$x = +0.1101$，大于零，反码就是它本身，用 `0` 表示正号——注意这两个零是有区别的，前面讲过了——写成 `0.1101`，用小数点把符号位和数值位隔开。$x = -0.1010$ 是负数，用公式变换：$2 - 2^{-4} = 1.1111$（二进制形式），减去 `0.1010`，符号位部分是 1，数值部分 $1111 - 1010$ 实际上就是 `1010` 每一位取反，得 `0101`，所以 $[x]_\text{反} = 1.0101$。这一步其实就是前面说的快速变换：补码我们知道怎么快速变换，反码就是比补码后面少加了一个一，比补码还要快。

再看几个已知反码求真值的例子。$[x]_\text{反} = 0,1110$，前面这个零说明是正数，机器字长 5 位、符号位占一位，那么 $x = +1110$，非常简单。$[x]_\text{反} = 1,1110$，符号位是 1 说明是负值，负数每位取反就可以，所以 $x = -0001$——当然也可以按定义计算，结果肯定还是这个值。

然后求零的反码。假设是小数：正零的反码就是它本身，`0.0000`，小数点前面的零是符号位；负零呢，符号位用 1，后面的值每一位取反，得 `1.1111`。整数同样如此：正零是 `0,0000`，负零是 `1,1111`。从这个例子能看出，**正零和负零的反码是不一样的**——和原码一样，零在反码里也有两种形式。

### 三种机器数的小结

原码、补码、反码都讲完了，对这三种机器数做一个小结。

第一，最高位都是符号位。整数书写时用逗号把符号位和数值位隔开，小数用小数点隔开——注意这只是**书写的时候**，并不是说数据存进计算机后里面真的弄一个逗号。计算机里是没有这个逗号的，书写时加逗号或小数点只是为了分清符号位和数值位。

第二，对正数来说，存储时原码、反码和补码**完全相同**：符号位都是零，数值部分就是真值的数值部分——当然还要考虑机器字长的限制。

第三，对负数来说，三种形式的机器数符号位都是 1，但数值部分不同：原码的数值部分和真值相同；把原码的每个数值位取反、末位加一，得到补码；只取反、不加一，就得到反码。

结合零的表示可以再补一句：正零和负零的机器数形式相同只有补码；原码和反码都是不一样的。

### 八位字长下的表示范围对比

下面看一个例子。假设机器字长是八位，其中一位是符号位，同一串二进制代码——从全 0 到全 1——当它代表无符号数、原码、补码和反码的时候，对应的真值范围是不一样的。同一个二进制数存放在计算机里，用不同形式的机器数去解读，它代表的真正的值并不一样。

| 二进制代码 | 无符号数 | 原码 | 补码 | 反码 |
| :---: | :---: | :---: | :---: | :---: |
| `0000 0000` | 0 | +0 | 0 | +0 |
| `0000 0001` | 1 | +1 | +1 | +1 |
| `0111 1111` | 127 | +127 | +127 | +127 |
| `1000 0000` | 128 | −0 | **−128** | −127 |
| `1000 0001` | 129 | −1 | −127 | −126 |
| `1111 1110` | 254 | −126 | −2 | −1 |
| `1111 1111` | 255 | −127 | −1 | −0 |

逐列看。无符号数：从八个 0 到八个 1，表示 0 到 255。原码：符号位 0 是正数，直接是真值，从正 0 到正 127；符号位 1 表示负号，从 −0 开始一直到 −127。补码：前半部分同样表示 0 到 127；符号位 1 表示负数，哪个值表示 −1 呢？最下面的 `1111 1111`——负数每位取反、末位加一，实际值是 1，所以它是 −1，往上依次是 −2、−3、−4，到 `1000 0001` 是 −127。那 `1000 0000` 是多少？大家去计算一下：它是负数，每位取反、末位加一，正好是 **−128**，这是补码比原码多表示的那个数。反码：0 到 127 没问题；符号位 1 加七个 0，即 `1000 0000`，取反后是七个 1，表示 −127，往下 `1000 0001` 是 −126、−125，一直到 `1111 1111` 是 −0。

> **易错点**：补码的表示范围是 $-2^n \sim 2^n - 1$（$n$ 为数值位数），负方向比原码、反码多一个数，因为补码把 −0 那个编码让给了 $-2^n$。

### 已知 [y]补 求 [−y]补

下面这个规律**非常有用**，大家一定要记住，后面讲运算的时候会用到它：已知 $y$ 的补码，如何求 $-y$ 的补码？

先设 $y$ 是小数，$[y]_\text{补} = y_0.y_1y_2\cdots y_n$，其中每一位都是 0 或者 1。

第一种情况，$y$ 是正数，即 $y_0 = 0$。$[y]_\text{补} = 0.y_1y_2\cdots y_n$，由于符号位是 0 说明 $y$ 是正数，所以 $y$ 本身就是 $0.y_1y_2\cdots y_n$。那么 $-y$ 就是 $-0.y_1y_2\cdots y_n$，它的补码按定义求：符号位变成 1，每一个 $y_i$ 都取反，末尾再加一个 $2^{-n}$。对照两种形式：符号位相反，所有的数值位都相反，并且末位要加一，才能从 $[y]_\text{补}$ 得到 $[-y]_\text{补}$。也就是说，**$y$ 为正时：$[y]_\text{补}$ 连同符号位在内，每位取反、末位加一，就得到 $[-y]_\text{补}$**。

第二种情况，$y$ 小于零，$[y]_\text{补} = 1.y_1y_2\cdots y_n$，1 是符号位，表示负值。由 $[y]_\text{补}$ 先求出 $[y]_\text{原}$——符号位不变，每位取反末位加一——进而得到 $y$ 的值：$-(0.y_1y_2\cdots y_n + 2^{-n})$。那么 $-y$ 就是一个正数，值为 $0.y_1y_2\cdots y_n + 2^{-n}$；正数的补码就是它本身，所以 $[-y]_\text{补} = 0.y_1y_2\cdots y_n + 2^{-n}$。还是对照一下：符号位一个 1 一个 0，不一样，然后每位都取了反，末位加上一——同样得到 $[-y]_\text{补}$。

所以两种情况的结论一致：

> **结论**：不论 $y$ 正负，$[-y]_\text{补}$ 都等于把 $[y]_\text{补}$ **连同符号位在内**，每位取反、末位加一。这和"负数原码转补码"只在数值位上操作不同——这里连符号位也要一起翻。

### 移码：为比较大小而生

前面讲了原码、补码、反码三种机器数，尤其是补码，后面讲计算机的运算方法时会大量用到。那为什么还要讲移码呢？因为在计算机内部的数据表示当中，用补码很难直接判断它对应真值的大小。

举几个例子。给出四个十进制数，两两相互对应：$+21$ 和 $-21$，$+31$ 和 $-31$。21 用 $16+4+1$ 转成二进制是 `10101`；31 用 $32-1$ 转成二进制是 `11111`。假设机器字长六位，一位符号位五位数值位，小数点约定在数值位最低位的后面。

用补码表示：$+21$ 符号位 0，`0,10101`；$-21$ 符号位 1，数值部分每位取反末位加一得 `01011`，即 `1,01011`。$-31$ 同样：符号位 1，数值部分变成四个零一个一，即 `1,00001`。现在只看补码的二进制值：`1,01011` 要比 `0,10101` 大，按这个判断 −21 大于 +21——实际上这是错的。同样还能判断出 −31 大于 +31，也是错的。**补码的编码大小和真值的大小没有直接对应关系**，这就是它的短板。

问题的根源在于补码的定义：$[x]_\text{补} = x + 2^{n+1}$（$x < 0$ 时）。如果改成对正数负数都加 $2^n$，情况就不一样了。比如正 `10101` 加上 $2^5$ 变成 `1,10101`；负 `10101` 加上 $2^5$ 变成 `0,01011`。正 31 加 $2^5$ 变成 `1,11111`，−31 加 $2^5$ 变成 `0,00001`。这样一看，+21 比 −21 大，这是对的；+31 比 −31 大，也都是对的。这种表示方式就叫做**移码**。

#### 移码的定义

若计算机字长是 $n+1$ 位（数值部分 $n$ 位），则

$$[x]_\text{移} = 2^n + x$$

不管正数还是负数，不做任何区别，把真值统一加上 $2^n$，就变成了移码。可以在数轴上看这种表示方式：

```text
真值轴:   -2^n ──────────────── 0 ──────────────── 2^n - 1
            │                  │                   │
            └───── 整个数轴统一加上偏移量 2^n，向右平移 ─────┘
                          ↓
移码轴:          0 ───────────────── 2^n ───────────── 2^(n+1) - 1
```

图上从真值到移码：不管是正数还是负数都加上了 $2^n$，相当于给整个数轴上的真值统一加了一个偏移量，整体向右移了 $2^n$——这大概也就是为什么把这种机器数表示形式称为"移"码。

举个例子，$x = 10100$，$[x]_\text{移} = 2^5 + 10100$，实际上就是在符号位那个位置加上一个 1，得到 `1,10100`——注意这里**符号位是 1 表示正数**。若 $x = -10100$，同样加上 $2^5$，得 `0,01100`，符号位是 0 表示移码当中的负数。和补码恰好相反，务必留心。

关于移码的定义，有两点要注意。第一，不管是正数还是负数，都是加上 $2^n$，这是与补码定义最大的差别。第二，从定义看，移码**只有整数形式的定义，没有小数形式的定义**。为什么？这和移码在计算机数据表示当中的作用有关：移码的大小很好判断，所以通常用来表示**浮点数阶码**，而阶码都是整数，所以移码的定义当中也就只给出了整数形式。

#### 移码和补码的关系

下面把移码和补码做个比较，总结出规律性的东西。设 $x = +1100100$，字长八位、一位符号位。移码很好算：$2^7$ 加上真值，就是在符号位部分加一个 1，得 `1,1100100`；它的补码符号位是 0，得 `0,1100100`。也就是说 $x > 0$ 时，移码和补码**符号位不一样，数值位完全相同**。

换 $x = -1100100$，$n = 7$：移码是 $2^7 - 1100100$，算出来是 `0,0011100`，表示移码当中的负数；补码是 $x + 2^8$，得 `1,0011100`。对照一下：数值部分完全相同，符号位正好相反。

> **结论**：同一个真值的移码和补码只相差一个符号位，数值位部分完全相同。所以把补码变成移码、或移码变成补码非常方便——从逻辑实现上说，只需要在符号位上加一个非门取反即可。

再看一张真值、补码、移码的对照表。设数值部分五位、符号位一位：

| 真值 | 补码 | 移码 |
| :---: | :---: | :---: |
| −100000（−32） | `1,00000` | `0,00000` |
| −11111（−31） | `1,00001` | `0,00001` |
| −00001（−1） | `1,11111` | `0,11111` |
| −0 | `0,00000` | `1,00000` |
| +0 | `0,00000` | `1,00000` |
| +00001（+1） | `0,00001` | `1,00001` |
| +11111（+31） | `0,11111` | `1,11111` |

补码这一列的运算非常好算：$n = 5$，负数加上 $2^{n+1} = 2^6$，正数和正负 0 与真值完全相同，只是前面加一个符号位。移码这一列根据"与补码只差符号位"的规律很容易写出来。表里还可以再算一列这个二进制代码当作无符号数时的十进制整数值——注意那不是移码对应的真值，只是这串代码本身按无符号数解读时的值，两者不要混。看关键的两处：正零和负零，补码有唯一的表示形式，移码也有相对应的唯一表示形式（都是 `1,00000`）；最小的负数 −100000（即 −32），移码表示值是**全零**——加上 $2^5$ 之后，把负的最小值移到了零这个位置。而最大的正数 +31 加上 $2^5$ 之后变成六个一。

#### 移码的特点

最后归纳移码的特点。设字长六位、数值部分五位。

其一，$x = 0$ 时：正零的移码是 $2^5 + 0$，即 `1,00000`；负零是 $2^5 - 0$，结果完全相同。所以**正零和负零的移码是相同的**，零在移码中有唯一的表示。

其二，$n = 5$ 时能够表示的最小真值是 $-2^5$，就是表里给出的 1 后面五个零。它用移码表示时要加上 $2^5$：$-2^5 + 2^5 = 0$。可见**最小的真值经过加 $2^n$ 以后，移码恰好是全零**；而最大的真值 $2^n - 1$ 加 $2^n$ 后，移码是全一。移码的全零到全一，正好对应真值从小到大单调排列。

其三，移码的用途：刚才已经说了，它用来表示**浮点数的阶码**。正因为它把真值平移成了单调递增的无符号编码，这种表示方法非常容易判断浮点数阶码的大小——这就是移码存在的全部理由。

## 数的定点表示和浮点表示（上）
> 对应块：BLK23 | 覆盖分集：P75-P77 | 块标题（分集名）：《6.2 数的定点表示和浮点表示（上）6.2-a》

今天我们进入 6.2 节——数的定点表示和浮点表示。这一节主要有四方面内容：第一，数的定点表示，看看定点数在计算机当中是如何存储的；第二大部分是数的浮点表示，这部分是我们这一节的**重点**——先介绍浮点数的表示形式，并根据表示形式一起分析浮点数的表示范围；接着讲浮点数的规格化形式，以及为什么我们要对浮点数进行规格化——规格化以后才能把它存储到计算机当中；介绍了这些内容以后，我会举一些例子帮助大家理解知识点；最后给大家介绍 IEEE 754 标准。

### 定点表示：小数点是约定出来的

所谓定点表示，是指**小数点按约定的方式给出**——在计算机当中，没有专门的硬件来表示小数点。小数点的位置是由计算机体系结构设计人员在设计体系结构的过程当中约定的，硬件实现和软件实现都要遵守这个约定。软件编程人员要根据这个约定，在程序当中调整数值的大小，以适应约定。

> **定义**：定点数 = 小数点位置固定且由约定给出、不占硬件的数。

根据小数点约定位置的不同，主要有两种形式。

第一种，小数点的位置约定在**数符的后面**。这个位置一旦约定下来，就意味着计算机当中存放、处理的定点数**都是小数**。如果是补码形式的话，它能够表示的唯一一个整数就是 $-1$。

第二种，小数点的位置约定在**数值部分的最后**。这样约定之后，计算机当中的定点数就都是整数。

于是，按照一台定点计算机约定的小数点位置，我们可以把定点计算机分成两类：一类是**小数定点机**——小数点放在数符的后面、数值的前面；另一类是**整数定点机**——小数点放在数值部分的后面。

### 定点数的表示范围：三种机器码各算一遍

前面我们已经讲过，一个有符号数存放到计算机当中，要转换成机器数的表示形式，一共介绍了四种。这里我们分析**原码、补码和反码**在小数定点机和整数定点机当中的表示范围。设机器字长为 $n+1$ 位：1 位数符，$n$ 位数值。

**小数定点机**。用原码表示，能表示的正数最大值，是数符部分等于 0、尾数 $s_1$ 到 $s_n$ 全为 1 的那个数：

$$+(1-2^{-n})$$

负数这一段，绝对值最大的那个负数（也就是能表示的最小负数），是数符为 1、数值部分也全为 1：

$$-(1-2^{-n})$$

所以原码的表示范围就在 $-(1-2^{-n})$ 到 $+(1-2^{-n})$ 之间。

用补码形式呢？正数最大值依然是数符为 0、数值部分全 1，还是 $1-2^{-n}$；但负数部分能表示的最小值是数符为 1、数值部分**全 0**，这个值就是 $-1$。所以补码的区间是从 $-1$ 到 $+(1-2^{-n})$——注意负方向的边界和原码不一样。

反码表示的范围和原码是相同的，大家可以自己去分析一下。

**整数定点机**。原码表示的正数最大值，依然是数符为 0、数值部分全 1，但现在的位权变了，这个值是 $2^n-1$；负数部分的最小值是数符为 1、数值部分全 1，即 $-(2^n-1)$。补码形式正数最大值和原码相同，负数的最小值却可以表示到 $-2^n$——这种情况下数符是 1，数值部分每一位 $s_i$ 都等于 0。反码同样和原码范围相同。

| 机器码 | 小数定点机 | 整数定点机 |
| :--- | :--- | :--- |
| 原码 | $-(1-2^{-n}) \sim +(1-2^{-n})$ | $-(2^n-1) \sim +(2^n-1)$ |
| 补码 | $-1 \sim +(1-2^{-n})$ | $-2^n \sim +(2^n-1)$ |
| 反码 | 与原码相同 | 与原码相同 |

> **易错点**：补码在负方向上比原码"多挤进去"一个数——小数是 $-1$，整数是 $-2^n$，靠的正是数值部分全 0、数符为 1 这个编码。

这里大家要注意一个问题：计算机当中表示的数是**离散的**。比如数符加数值一共 $n+1$ 位，它能表示的小数最多只有 $2^{n+1}$ 个；而在这个数据区间里，连续的实数有无数个。在计算机当中，我们就是用这 $2^{n+1}$ 个数，去表示这个范围之内的所有的数。这一点记住，后面分析浮点数时还会再回到它。

### 为什么非要引入浮点表示

进入浮点表示之前，我们先问几个问题，大家一起思考一下：

- 为什么在计算机当中要引入浮点表示？浮点表示的格式是什么？比如尾数的符号怎么表示、尾数的长度取多少，阶码的符号怎么表示、阶码的长度取多少，用哪种机器数形式来表示尾数和阶码，尾数和阶码的基值是不是必须相同——基值的大小对浮点数表示到底有哪些影响，比如对可表示浮点数的个数、表示范围、最大的浮点数、最小的浮点数各有什么影响？
- 为什么要引入规格化？怎么进行规格化？
- 目前浮点数表示格式的标准是什么？

先回答第一个问题：为什么最早只有定点表示的机器后来要引入浮点。最早的计算机受硬件技术限制，只有定点表示方式——小数定点机和整数定点机两种。但我们在科学计算过程当中，经常会用到浮点数。在定点机当中要用浮点数，需要**程序员自己去调整小数点的位置、自己对计算结果进行校正**，这给程序员造成了很大的负担。

第二个问题是数的表示范围非常小。比如小数定点机，它能表示的值一定是小于等于 1 的；如果我们想表示两个大小相差非常大的数据，就需要很长的机器字长。这里我给出一个例子，这个例子比较极端：太阳的质量是 $0.2\times10^{34}$ 克，一个电子的质量是 $0.9\times10^{-27}$ 克。如果在某一个科学计算问题当中，太阳的质量和电子的质量同时出现、都要在计算机当中存储，两者的差距达到 $10^{61}$ 这个量级。我们可以简单算一下：要用二进制数表示这么大差距，需要 **203 位**的二进制数。即使有了这 203 位的存储单元——它既能保存太阳的质量也能保存电子的质量——大家可以想象一下，保存电子质量的时候，那个存储单元大部分的值都是零，尤其是高位部分，大量空间就被浪费掉了。而如果这道题当中涉及的大部分都是和电子质量差不多大小的数据、太阳的质量只出现一次，那我们进行数据存储时会浪费大量的存储空间。

第三个问题就是数据存储单元的利用率会很低。基于这些原因，我们引入了浮点数据表示。

### 浮点数的形式：N = S × r 的 j 次方

浮点数据表示的形式是：

$$N = S \times r^{\,j}$$

大家在高中阶段应该学过科学计数法，这是同一个思路。$S$ 我们称为**尾数**，$j$ 是**阶码**，$r$ 是**尾数的基值**。在计算机当中，尾数的绝对值是小于等于 1 的（是小数），阶码是整数——这和十进制科学计数法的规定类似，科学计数法里规定 $S$ 的值应该小于 10。

尾数的基值其实有多种取法：可以取 $r=2$，这样尾数当中每一位二进制数就表示尾数的一位；也可以取 4，这时尾数当中的**两位**二进制数表示一位四进制的位数；取 8，就是三位二进制表示一位八进制数；取 16，就是四位二进制表示一位十六进制数。

我们以 $r=2$ 为例看一个具体数据：

$$N = 11.0101_{(2)}$$

用浮点数的形式，它可以有好几种写法。把小数点的位置固定，对数据部分右移两位，尾数就变成了 $0.110101$，数据本身的大小变成了原来的 $\tfrac14$，所以阶码要相应调整成二进制的 $10$（也就是十进制的 2），保持真值不变。同样，尾数再右移一位，数据变为原来的 $\tfrac12$，阶码就变成二进制 $11$；还可以把数据左移两位，数据扩大为原来的四倍，那么阶码就变成二进制 $-10$，也就是十进制的 $-2$；另外还可以把数据右移四位，同时阶码变成二进制 $100$。不管怎么移，只要阶码跟着调整，这个数据的大小就保持不变。

但要注意：在计算机当中，**尾数是采用小数定点形式来表示的**，它的值必须小于等于 1，所以只有尾数部分是纯小数的那几种写法才能存进机器；而其中比较特殊的是这一种——数值的**最高位是非零**的，对二进制数来说这一位直接就是 1。这种表示形式，我们就称为**规格化的数**。

### 浮点数在机器里怎么存

经过上面的分析我们知道：$S$ 是尾数，用小数表示，可正可负，所以它要有数符，尾数的符号就直接表示了这个浮点数的符号；阶码是一个整数，也是可正可负的。那么这样一个浮点数在计算机当中如何存储呢？浮点数存储同样要以机器数的形式进行。如果设计计算机的时候就已约定了尾数的基值——取二进制、四进制还是八进制——那么存储时基值本身不用存，我们只需要把浮点数的**尾数部分和阶码部分（包括数符和阶符）**，用前面讲过的机器数表示形式，按设计规定的位数存起来：尾数取多少位、数符是一位还是两位、阶码取多少位，照着约定放即可。

存放格式长这样：

```text
┌──────┬────────────────┬──────┬─────────────────┐
│ 阶符 │  j1  j2 …  jm  │ 数符 │  S1  S2 …  Sn   │
└──────┴────────────────┴──────┴─────────────────┘
   ↑          ↑              ↑          ↑
  阶码符号   阶码(整数)      尾数符号   尾数(n位小数)
             小数点在数值部分最后        小数点紧跟在数符后面
```

读这张图的关键一句话：**阶码和尾数共同决定了这个浮点数小数点所在的实际位置**。$n$ 是尾数的位数，$m$ 是阶码的位数；阶码本身是定点整数，尾数本身是定点小数。

### 浮点数的表示范围

依据刚刚给出的格式，我们来分析浮点数的表示范围。假设现在**不考虑规格化**，无论尾数还是阶码都用**原码**形式表示，尾数的数值部分是 $n$ 位、阶码的数值部分是 $m$ 位。在数轴上，我们要找四个点：最小的负数、最大的负数、最小的正数、最大的正数。

**最小的负数**，也就是绝对值最大的那个负数：它的尾数绝对值应该是最大的——原码下就是数符为 1、数值部分全 1，即 $-(1-2^{-n})$；同时要让阶码最大——阶符为正、$m$ 位数值部分全 1，即 $+(2^m-1)$。合起来：

$$-(1-2^{-n})\times 2^{\,2^{m}-1}$$

**最大的负数**，是绝对值最小、贴近于零的那个：尾数绝对值最小——数符依然为 1，数值部分前面 $n-1$ 位都是 0、最后一位是 1，这个值是 $-2^{-n}$；阶码则要取绝对值最大的负数——阶符为 1、$m$ 位数值全 1，即 $-(2^m-1)$：

$$-2^{-n}\times 2^{-(2^{m}-1)}$$

**最小的正数**：尾数最小取 $+2^{-n}$，阶码同样取绝对值最大的负数 $-(2^m-1)$；**最大的正数**：尾数全 1、符号位为 0，阶码符号为 0、数值部分全 1，即 $+(1-2^{-n})\times 2^{\,2^{m}-1}$。

把具体参数带进去感受一下规模。若 $m=4$、$n=10$，这种格式数据总长一共 16 位：1 位阶符、1 位数符、4 位阶码、10 位尾数数值部分。它能表示的二进制数的个数是 $2^{16}$ 个——也就是说，机器用这有限个数据，去表示最小负数和最大正数之间的所有的数。$2^{16}$ 个数据的个数是有限的，而且每一个数据相互之间都是离散的，所以我们始终是在**用有限的数据表示无限多的实数**。

如果表示的范围超出了计算机能够表示的范围，就有**上溢**和**下溢**：上溢是阶码大于最大的阶码了，计算机系统会按计算出错进行处理；下溢是阶码小于最小的阶码、落在靠近零的位置，计算机处理时把它按**机器零**处理。

### 规格化：为了保住精度

接下来看浮点数的规格化形式。我们**为什么要对浮点数进行规格化**？这件事一定要搞清楚。规格化的作用，就是尽可能保证数据的精度。如果不进行规格化，尾数的小数点后面可能会有若干个零；如果我们用原码表示，这些零就是真正的零。放到计算机当中，尾数的长度是有限的，超出给定长度的那部分尾数的值就要被扔掉，会严重影响数据的精度。为了尽可能保证精度，我们要让尾数的**有效位数尽可能多**，所以采用规格化的形式。

那么什么叫规格化形式？$r=2$ 的时候，尾数（小数点后）的**最高位就应该是 1**——注意这个 1 是指它的**真值**是 1。如果尾数采用四进制，两位二进制数表示一位四进制数，规格化就要求尾数的最高的两位不能都等于零；$r=8$，最高三位不能全为零；同样可以推导出，基值是 16 时最高的四位不能同时为零。从这里可以看出：**尾数的基值不同，浮点数规格化的形式也是不一样的**。

> **定义**：$r=2$ 时规格化要求尾数最高数值位（真值）为 1；一般地，$r=2^k$ 时要求尾数最高 $k$ 位不全为 0。

怎么对浮点数进行规格化？实际上就是通过把尾数的数据进行左移或者右移，使它满足上面的形式——$r=2$ 时让尾数最高位等于 1，$r=4$ 时让最高的两位不等于零——同时**调整阶码，保证数据的真值不发生变化**。

以 $r=2$ 为例，规格化有两种方式。一种进行数据的**左移**，把左边出现的多余的零移掉，这叫**左规**：尾数向左移一位，数据增大为原来的两倍，为了使数据的值不发生变化，阶码部分就要减 1。另一种是**右规**：数据向右移动、小数点的位置不变，每右移一位，数据值变成了原来的 $\tfrac12$，为了保证数据值不变，阶码就要加 1。

基值不是 2 时，移位要以基值的进制为单位：$r=4$ 时，尾数中的两位二进制数才是一位四进制数，所以每移一次要移动**两位**二进制位——左规尾数左移两位、阶码减 1，右规尾数右移两位、阶码加 1；$r=8$ 时左规尾数左移三位、阶码减 1，右规尾数右移三位、阶码加 1。通过移位和阶码的调整，保证这个浮点数的真实值不发生变化。

### 基值 r 越大越好吗

尾数的基值既可以取 2，也可以取 4、取 8，那么基值对浮点数的表示有什么影响呢？这里先给出两条结论，大家要**自己动笔分析一下**，证明一下这些结论的正确性：

- $r$ 值越大，所能表示的浮点数的**范围**就越大，能表示的浮点数的**个数**也越多；
- $r$ 值越大，所能表示的**精度**就会越低。

范围和个数与精度是一对交换，鱼和熊掌的账要会算。试着用前面推表示范围的同一套方法，把 $r$ 换成 4、8 代进去走一遍，结论自然就出来了。

最后用一组参数把规格化后的范围完整算一遍，作为这一部分的收尾。取 $m=4$、$n=10$、尾数的基值为 2，并且要求尾数规格化：

| 端点 | 尾数（原码） | 阶码（原码） | 值 |
| :--- | :--- | :--- | :--- |
| 最大正数 | $0.111\cdots1$ | $0,\,1111$ | $(1-2^{-10})\times 2^{15}$ |
| 最小正数 | $0.100\cdots0$ | $1,\,1111$ | $\tfrac12\times 2^{-15}=2^{-16}$ |
| 最大负数 | $-0.100\cdots0$ | $1,\,1111$ | $-\tfrac12\times 2^{-15}=-2^{-16}$ |
| 最小负数 | $-0.111\cdots1$ | $0,\,1111$ | $-(1-2^{-10})\times 2^{15}$ |

读一下这张表的思路：规格化要求尾数最高数值位是 1，所以正尾数最小只能取到 $0.100\cdots0$（即 $\tfrac12$），最大取到 $0.111\cdots1$（即 $1-2^{-10}$）；要绝对值最大就把阶码取到正的最大 $+15$，要绝对值最小、贴近零就把阶码取到绝对值最大的负数 $-15$。对照前面不规格化时的四个端点可以发现：规格化之后，最小正数和最大负数都被"抬"离了零——因为尾数再也不能是那些前面带一串 0 的非规格化小数了，这正是规格化保精度的直接体现。

### 本讲提到的题目

课上我们做了这样一个练习，把它完整还原在下面。

**题目**：假设机器数的字长是 24 位，要求能表示十进制数 $\pm 30000$，并且要**保证最大精度**，请设计一种浮点数的表示格式——阶码取几位、尾数取几位？

**解析**：先看范围由谁决定。$2^{14}=16384$，$2^{15}=32768$，超过了 3 万，所以阶码部分的取值范围必须能覆盖到 15，我们才能表示 32768、也就是满足 $\pm 30000$ 的要求。阶码数值部分取 4 位时，范围可以达到 $\pm 15$，最大能到 $2^{15}-1=32767$，能够满足用户的要求；取 5 位当然更能满足（范围还要再乘 2），但那就白占了位数。再看精度由谁决定——**尾数的长度**。题目要求保证数的最大精度，就必须让尾数尽可能的**长**，所以要缩短阶码的位数，取能满足范围要求的最短值。于是：数符占 1 位、阶符占 1 位、阶码部分给 4 位，一共拿出 6 位；字长 24 位，剩下的都是尾数部分，尾数长度是 18 位。

**答案**：阶码 4 位（外加 1 位阶符），尾数 18 位（外加 1 位数符）；即 24 位按"1 位数符 + 1 位阶符 + 4 位阶码 + 18 位尾数"分配。

这道题把本讲的两条主线拧在了一起：**范围靠阶码，精度靠尾数**——遇到"设计格式"类的问题，先按表示范围卡出阶码的下限，再把剩下的位数全部让给尾数。

### 例题：把 19/128 写成定点数和浮点数

题目要求：把 $+\dfrac{19}{128}$ 写成二进制数的定点数和浮点数，也就是写出它在定点机和浮点机当中的机器数表示形式。条件是：数值部分取 10 位（其中数符 1 位），浮点数的阶码取 5 位（其中含 1 位阶符），尾数要求规格化。这个题其实很好写，我们一步步来。

先把 19 变成二进制。19 用 $16+2+1$ 一凑就出来了，所以 $19 = (10011)_2$。

再除以 128。$128 = 2^7$，每除以 2 相当于小数点左移一位（数据相对小数点右移一位），所以一共要移 7 位，小数点后面还剩下 7 位数值：

$$\frac{19}{128} = (0.0010011)_2$$

**定点表示**：题目要求数值部分 10 位，现在只有 7 位，缺的 3 位补零补齐（正数的高位补零不改变大小）。所以定点数形式是 `0.0010011000`。因为它是正数，存放在机器当中不管是原码、反码还是补码，机器数形式都是相同的。

**浮点表示**：要求尾数规格化。把上面这个定点小数相对小数点左移两位，数据扩大了四倍，所以阶码要 compensating 地取 $-2$，也就是二进制的 $-10$。尾数就是左移后的规格化形式 `0.1001100000`（数符 1 位 + 数值 10 位，共 11 位）。

这里有个要点：尽管从总体上看这个数是正数，但在浮点表示当中，**阶码部分和尾数部分要分别进行表示**。这个数的阶码是负的，所以阶码部分的原码、反码、补码形式就不一样了；而尾数大于零，无论用原码、反码还是补码表示，尾数这部分都是相同的。

| 机器数形式 | 阶码（5 位，含 1 位阶符） | 尾数（数符 + 10 位数值） |
| :---: | :---: | :---: |
| 原码 | `1,0010` | `0.1001100000` |
| 补码 | `1,1110` | `0.1001100000` |
| 反码 | `1,1101` | `0.1001100000` |

阶码的三种形式怎么来的：真值 $-2$ 的原码数值部分是 `0010`；求补码，`0010` 每位取反、末位加一，得 `1110`，所以补码阶码是 `1,1110`；求反码，在原码数值部分基础上每位取反，得 `1,1101`。

> **易错点**：浮点数整体的正负只由数符决定，但阶码和尾数是两段独立的机器数，各变各的。正数的浮点表示里，负阶码照样要按负数求补码、反码。

### 例题：把 -58 写全各种机器数形式

再看一个例子，要求把 $-58$ 表示成二进制数的定点数和浮点数，写出定点机中的三种机器数，以及浮点机中"阶码、尾数各取什么码"的几种组合形式，其他要求和上面一样。

先把 $-58$ 变成二进制。这个变法非常简单，可以用规范的方法除 2 取余，用余数来构成二进制数；不过通常情况下，我更喜欢把 58 按 2 的幂拆开：$58 = 32 + 16 + 8 + 2$，直接写出 $(111010)_2$。

**定点表示**：这是个负数，数值部分要求 10 位，现在已有 6 位，要加进 4 个零。在哪加？不能改变数据的大小，所以只能在前面加——补齐后数值部分是 `0000111010`。三种机器数很容易写出：

| 机器数形式 | 定点机表示 |
| :---: | :---: |
| 原码 | `1,0000111010` |
| 反码 | `1,1111000101` |
| 补码 | `1,1111000110` |

**浮点表示**：首先要确定数据小数点所在的位置。$-58$ 是整数，小数点在末尾；要把它变成规格化的浮点形式，小数点要挪到 `0.111010` 这里——相当于数据相对小数点右移了 6 位（小数点位置不动，数据移），数据变成了原来的 $2^6$ 分之一。为了保持数值大小不变，要再乘以 $2^6$：

$$-58 = -0.1110100000 \times 2^{110_2}$$

阶码真值是 $+6$，大于零，所以它的原码、反码、补码、移码数值部分都是 `0110`，只是符号位或编码规则带来差别；尾数小于零，三种码就要分别求了。四种组合形式如下：

| 阶码形式 | 尾数形式 | 阶码 | 尾数 |
| :---: | :---: | :---: | :---: |
| 原码 | 原码 | `0,0110` | `1.1110100000` |
| 补码 | 补码 | `0,0110` | `1.0001100000` |
| 反码 | 反码 | `0,0110` | `1.0001011111` |
| 移码 | 补码 | `1,0110` | `1.0001100000` |

几个容易踩坑的地方，大家一定要注意：

- 阶码数值部分是 4 位，这个不要忘掉，要补齐成 4 位、符号位放 0。
- 用补码或反码表示时，**阶码是大于零的，形式不变**。不要上来就把阶码的数值部分也给它取反了，这是不行的。反码形式下只有尾数和原码相比是每位取反。
- 阶码用移码表示时，移码和补码的区别就在符号位，数值位部分完全相同——把补码 `0,0110` 的符号位改成一，就是移码 `1,0110`；尾数仍用补码，形式完全相同。

### 机器零：什么样的数当成零

接下来看一个特例：机器零怎么处理。什么样的数是机器零？怎么进行表示？

判定条件有两条：

> **定义**：浮点数只要满足下列两条之一，就按机器零处理——
> ① 尾数为零，不管阶码是什么值；
> ② 阶码等于或小于它能表示的最小值，不管尾数是多少。

第一条的依据是规格化要求：如果这个数是非零的，规格化之后尾数小数点后面第一位数值部分的真值就应该是 1；现在尾数全为零，说明它不可能是非零数，那就不管阶码是什么值，都按机器零处理。第二条是下溢情形：阶码已经小到表示不了了，这个数再大也大不到哪去，当成零。

举个具体例子。还是用我们前面用过的那个假设：$m=4$、$n=4$，阶码和尾数都用补码表示。

- 第一种形式：尾数的值为零，不管阶码是多少，这个数都当成机器零处理。
- 第二种形式：阶码等于了能表示的最小值。$m=4$ 时，补码阶码的最小值是 $-16$（即 $-10000_2$），不管尾数是什么，这个值都当成零处理。

如果阶码改用移码表示、尾数仍用补码呢？我们知道移码是在真值上加 $2^n$，那么阶码真值 $-16$ 的移码恰好是**全零**。所以判断规则可以统一成一句话：只要阶码是全零，或者尾数是全零，这个数就是机器零。

> **结论**：这样判断的好处是，判零只需要判"全零"，非常有利于用硬件电路来实现对零的判别。

### IEEE 754 标准的浮点数格式

最后讲解一下 IEEE 754 标准，我们只讲浮点数这部分。它的格式是这样的：

```text
┌──────┬────────────────────┬───────────────────────────────┐
│ 数符 │    阶码（含阶符）    │   尾数 M（规格化，最高位 1 隐含） │
└──────┴────────────────────┴───────────────────────────────┘
                  ↑
     这条边界就是小数点的位置：
     它既是尾数的小数点，也是阶码的小数点
```

最前面这一位表示数的符号，也就是尾数的符号；中间的字段表示阶码，阶码当中包括了阶符；最后是尾数。要求尾数必须用规格化的方式表示。

规格化带来一个重要推论：假设尾数的基值是 2，那么规格化尾数的第一位数值，它的真值一定要是 1。既然第一位一定是 1，那这一位就可以**隐含掉**，不在数据当中进行表示，计算的过程当中把它补齐就可以了。这样做的一个好处是：实际上增加了尾数的位数，增大了尾数能够表示的精度。

754 标准当中对实数有三种规定：

| 类型 | 总位数 | 数符 | 阶码 | 尾数 |
| :---: | :---: | :---: | :---: | :---: |
| 短实数 | 32 位 | 1 位 | 8 位 | 23 位 |
| 长实数 | 64 位 | 1 位 | 11 位 | 52 位 |
| 临时实数 | 80 位 | 1 位 | 15 位 | 64 位 |

可以看到，阶码位数越多，能表示的数据范围越大；尾数位数越多，表示的精度就越高。大家可以自己按照短实数的阶码和尾数位数，分析一下短实数的表示范围是多少——这是个很好的练手题。

### 习题 6.16：机器字长 16 位能表示多大的数

现在介绍一下习题 6.16。这个题问的人比较多，我们集中解答一下。

题目要求：假设机器字长是 16 位，写出下列各种情况下它能表示的数的范围——也就是最小的数是多少、最大的数是多少；机器数采用一位符号位，答案用十进制数表示。

一位符号位、总长度 16 位，对一般的数来讲就是一个 $1+15$ 的形式。大家会发现，下面每一问其实都是在数轴上摆这 16 个位置——零占几个位置、剩下的数往哪边排。这个问题想清楚了，每一问都是水到渠成。

#### 无符号整数：16 位全是数值

这个比较简单。无符号数没有符号位，16 位全部都是数据，每一位都可以是 0 或者 1。所以最小的数一定是全零——16 个零代表十进制的 0；最大的数就是全一——16 个 1，即 $2^{16}-1$。推广开来说，n 个 1 就是 $2^n-1$。

无符号整数没有正负之分，表示范围一定是从 0 开始到 $2^{16}-1$。这个题是一定要掌握的，因为它涉及定点表示中无符号数表示范围这个基本功。

#### 原码定点小数：关于原点对称

定点小数是什么样子的？第一位是符号位，符号位和最高数值位之间有一个隐含的小数点。写出这个 16 位（1 位符号 + 15 位数值）的定点小数的范围，正的负的都有，我们按照真值在数轴上来写，这样最简单。

```text
 -(1-2^-15)           -0      0           +(1-2^-15)
 ────┼────────────────┼──────┼───────────────┼────►
     └──── 负小数区 ───┘      └─── 正小数区 ──┘
          原码的零有两个：+0 和 -0
```

正数一侧：从 0 开始，当 15 位数值全是 1 时达到正数的最大，即 $0.111\cdots1$（15 个 1）。15 个 1 怎么求值？它实际上就是 1 减去 $0.000\cdots01$——14 个零、最后一个 1，也就是 $2^{-15}$：

$$0.\underbrace{11\cdots1}_{15} = 1 - 2^{-15}$$

所以正小数的范围是从 0 到 $1-2^{-15}$。而原码有一个非常好记的特性：**不管是正数还是负数、整数还是小数，它的表示范围都是基于零对称的**。所以负数一侧一定是从 0 到 $-(1-2^{-15})$。两段连起来，原码定点小数的表示范围就是：

$$-\left(1-2^{-15}\right) \sim +\left(1-2^{-15}\right)$$

数轴上还要注意一个细节：原码的零有两个，一个是 $+0.0\cdots0$，一个是 $-0.0\cdots0$。

#### 补码定点小数：两个零合成一个之后

在数轴上对比一下原码和补码，区别立刻就出来了：原码的零有两个，而补码把正零和负零合成了一个，只保留一个零，它占用了正零的位置。

补码作为正数来讲，和原码的表示范围是一样的，最大的正小数仍然是 $0.111\cdots1$（15 个 1），即 $1-2^{-15}$，这应该没有问题。问题就来了：负数一侧怎么办？

```text
 -1                    0                  +(1-2^-15)
 ────┼─────────────────┼─────────────────────┼────►
     ←← 向左多出一个编码位置
     两个零合成一个，省下的位置让负数区向左扩展
```

原来原码在负数区有 $-0$ 这个编码，现在两个零合成一个了，负数这一侧就少了一个编码位置。16 位编码总共就是 $2^{16}$ 个，总数不能变——所以负数区间必须再向左扩展一个小数单位，让能表示的数的个数保持 $2^{16}$ 个不变。这个小数单位是多少？15 位小数，最小的小数单位就是 $0.000\cdots01$（14 个零、最后一个是 1），即 $2^{-15}$。

在原码负数最大 $-(1-2^{-15})$ 的基础上再往左减一个 $2^{-15}$，结果很有意思：

$$-\left(1-2^{-15}\right) - 2^{-15} = -1$$

> **结论**：补码定点小数的表示范围是 $-1 \sim +\left(1-2^{-15}\right)$。补码这个地方很难理解——为什么负数能表示到 $-1$？就是因为它在数轴上整体向左挪了一个小数单位。记住这一条就行。

对比一下：正数部分补码和原码一样，负数部分比原码向左多了一个单位；原码是对称的，补码不对称。

#### 定点整数：从原码推到补码

补码定点整数和定点小数是类似的，但还得从原码讲起，所以先看原码整数的表示范围。

原码整数也有两个零：$+0$ 和 $-0$。$+0$ 是正数区域的最小值；正数的最大值，除符号位外还有 15 位，数位全 1 就是最大的正数：$0111\cdots1$，即 $2^{15}-1$。15 个 1 为什么等于 $2^{15}-1$？它是一个 1 后面跟 15 个 0（即 $2^{15}$）减去最后一位的 1，大家可以在纸上减一下试试，结果必然是 15 个 1。左侧从 $-0$ 开始，到负的 15 个 1，即 $-(2^{15}-1)$。两部分对称，所以原码定点整数的范围是：

$$-\left(2^{15}-1\right) \sim +\left(2^{15}-1\right)$$

再看补码整数，和小数那边一模一样的逻辑：两个零合成一个零了，这是最重要的一点。从零开始到最大的正数 $2^{15}-1$ 没有问题；关键在负数一侧——原来左侧有 $2^{15}$ 个编码位置（含 $-0$），现在 $-0$ 没有了，但左侧仍需要 $2^{15}$ 个数，所以最小的负数要再向左移动一个单位。

整数的移动单位就是 1（小数的移动单位取决于有多少位小数，整数就是 1）。$-(2^{15}-1)$ 再减 1：

$$-\left(2^{15}-1\right)-1 = -2^{15}$$

也就是一个 1 后面跟 15 个 0 的形式——注意，这个数是一个**原码所不能够表示**的数，但补码把它补进来了。

> **结论**：补码定点整数的表示范围是 $-2^{15} \sim +\left(2^{15}-1\right)$。和原码相比，正数的最大值一样，负数一侧向左多挪了一格。

#### 原码浮点数的表示范围（非规格化）

重点来了。其实问得最多的还是第六问和第七问，因为大家对浮点数的格式掌握得不太太好，我们重点来说一下。

第六问的格式：阶码 6 位，含 1 位阶符，也就是 1 位阶符后面 5 位数值；尾数 10 位，含 1 位数符，也就是 1 位数符后面 9 位小数。要求写出正数和负数各自的表示范围，可以分开写，也可以写到一起。

先说一句实在话：这个题目本身不太严谨，因为它没有说阶码用什么形式、尾数用什么形式。所以我们给它规定一下：假设阶码是原码、尾数也是原码，而且是一个非规格化的数——这一点很重要。

浮点数的值是"尾数乘以 2 的阶码次方"：$N = S \times 2^E$。其中尾数 $S$ 一定是个小数，用原码**小数**的表示范围；阶码 $E$ 一定是整数，用原码**整数**的表示范围，它不可能出现小数。$1+5$ 形式的原码整数阶码，范围是 $-31 \sim +31$；$1+9$ 形式的原码小数尾数，范围是 $\pm\left(1-2^{-9}\right)$。

还有一个细节：零是机器零，浮点数的表示范围里并不包含零，所以要从"最小的正浮点数"开始写。尾数取最小的正数，是 $0.000000001$（8 个零最后一个是 1），即 $2^{-9}$；阶码也取最小，是 $-31$。两者相乘，得到最小的正数：

$$2^{-9} \times 2^{-31}$$

尾数取最大 $0.111111111$（9 个 1），即 $1-2^{-9}$；阶码取最大 $+31$，得到最大的正数：

$$\left(1-2^{-9}\right) \times 2^{31}$$

负数这一侧怎么解决？负数也到不了零。绝对值最小的负数，尾数取 $-2^{-9}$，阶码取 $-31$（和正数那边对称取法）；绝对值最大的负数，尾数取 $-(1-2^{-9})$，阶码取 $+31$。写出来就是：

$$-\left(1-2^{-9}\right) \times 2^{31} \sim -2^{-9} \times 2^{-31}$$

大家看一下：正数和负数是对称的。所以非规格化原码浮点数这种题，你记住正数范围，负数直接取相反数就可以了。答案写成这种"因式连乘"的形式就可以，不用乘出来，这就是十进制的表示形式。

#### 补码规格化浮点数：难点全在负数尾数

第七问和第六问的区别在于：阶码、尾数均采用补码，并且是规格化的数。还是得从数轴上看，我总是在画数轴。

**先定阶码。** 全部采用补码的话，$1+5$ 形式的阶码范围就变了：从负的"一个 1 后面五个 0"（$-100000_2 = -32$）到正的"五个 1"（$01111_2 = +31$）。补码比原码能多表示一个最小的数，向左多挪了一个单位，所以阶码范围是 $-32 \sim +31$。注意这个范围，一会儿要用到它。

**再定正数范围。** 规格化是什么样子？不管是正数还是负数，尾数真值的最高数值位一定是 1，后面各位任意。正数尾数最小是 $0.100000000$（1 后面 8 个 0），即 $2^{-1}$；阶码取最小 $-32$，得到最小的正数：

$$2^{-1} \times 2^{-32}$$

正数尾数最大是 $0.111111111$，即 $1-2^{-9}$；阶码取最大 $+31$，得到最大的正数：

$$\left(1-2^{-9}\right) \times 2^{31}$$

和原码相比，正数部分的尾数没有任何变化。

**负数就有点变化了。** 原码的时候，负尾数能够取到 $-0.1000\cdots0$，也就是 $-\dfrac{1}{2}$。但是我们通过讲了两个特例之后发现：$-\dfrac{1}{2}$ 的补码不是规格化的！$-\dfrac{1}{2}$ 的补码应该是 $1.1000\cdots0$——符号位和最高数值位都是 1，而补码规格化的负数要求形如 $1.0\times\cdots\times$。所以说这个位置不行了，$-\dfrac{1}{2}$ 要被排除掉。

$-\dfrac{1}{2}$ 被排除了，就意味着负尾数的整个区间要向左移动一个单位，这样才能保持负数区编码个数不变。这个单位是 $2^{-9}$。逐个看两端：

- 绝对值最小的负尾数：原来是 $-\dfrac{1}{2}$，再向左减一个单位 $2^{-9}$，变成
$$-\left(\frac{1}{2} + 2^{-9}\right) = -0.100000001_2$$
（0.1 后面 7 个零、最后一个是 1）。阶码取最小 $-32$，得到绝对值最小的负数：$-\left(2^{-1}+2^{-9}\right) \times 2^{-32}$。
- 绝对值最大的负尾数：原来是 $-0.111111111$（9 个 1），即 $-(1-2^{-9})$，再向左加一个 $-2^{-9}$，结果就是 $-1$。阶码取最大 $+31$，得到最小的负数：$-1 \times 2^{31} = -2^{31}$。

所以补码规格化浮点数的完整范围是：

$$\begin{cases}
\text{正数：} \; 2^{-1}\times 2^{-32} \;\sim\; \left(1-2^{-9}\right)\times 2^{31} \\[4pt]
\text{负数：} \; -2^{31} \;\sim\; -\left(2^{-1}+2^{-9}\right)\times 2^{-32}
\end{cases}$$

大家要注意的是：正数部分的尾数和原码相比没有变化，而负数部分的尾数变化是最大的——原来我们认为 $-1$ 是补码里一个普普通通的负整数，结果现在它成了规格化尾数。这道题比较难理解的就在这里。

### 解题心法：一切都在数轴上

最后把这类题的方法归拢一下。这一组小问，实际上考察的都是数轴的表示形式：机器字长定死为 16 位，不管是定点数还是浮点数，编码的总个数就是 $2^{16}$ 个——表示范围的问题，本质上是这 $2^{16}$ 个编码在数轴上怎么摆：零占几个位置、省下来的位置让哪一侧扩展、扩展的单位是 1 还是 $2^{-15}$ 还是 $2^{-9}$。把这个分配思路想通了，每一问都是同一个套路。

对付浮点数格式的考察，一定要知道规格化到底是什么样子的——规格化的数一定是什么样子，尤其是补码规格化里 $-\dfrac{1}{2}$ 不合格、$-1$ 反而合格这个反直觉的点。另外，像第六问这种题目，考试当中一般会给出阶码、尾码具体采用什么码的标准，按给定的那一种做就可以了。书后面给出了这组题的详细答案，大家课下的时候对照着在书上把数轴画一遍，画完这一遍，定点与浮点的表示范围就真正拿下了。
