# 总线：结构演进与控制机制

## 结构演进：从单总线到多总线

   * **单总线结构**

       * > **定义**：把 CPU、主存、所有 I/O 设备全部挂接在一条公共总线上的最原始结构。

       * 缺陷：所有设备挤占同一条总线，谁要传数据都得排队，总线成为整个系统的瓶颈。

   * **双总线结构**

       * > **定义**：把存储总线与 I/O 总线分离，中间用通道衔接的多总线结构。

       * 存储总线连接 CPU 与主存；I/O 总线连接各类 I/O 设备；通道把两条总线连接起来，实现 I/O 设备与主存、I/O 设备与 CPU 之间的通信。

       * 这种构型既可以以 CPU 为中心，也可以以存储器为中心，还存在其他画法，图中给出的是一种典型结构。

   * **通道（Channel）**

       * > **定义**：专门用于输入输出操作的简单处理器。

       * 通道一般有自己的控制器和指令系统，能执行简单指令、执行通道程序。

       * 通道程序通常由操作系统编写，而不是由人工编写。

```text
        ┌──────────────────────────────┐
        │           存储总线            │
        └────┬─────────────────────┬───┘
          ┌──┴──┐               ┌──┴──┐
          │ CPU │               │ 主存 │
          └──┬──┘               └─────┘
          ┌──┴──┐
          │ 通道 │
          └──┬──┘
        ┌────┴─────────────────────────┐
        │           I/O 总线            │
        └──┬───────┬───────────┬───────┘
        ┌──┴──┐ ┌──┴──┐     ┌──┴──┐
        │设备1│ │设备2│ ... │设备n│
        └─────┘ └─────┘     └─────┘
```

## 三总线与四总线结构

   * **DMA 三总线结构**

       * DMA（Direct Memory Access，直接存储器访问）：外部设备直接访问系统内存、不需要绕道。

       * 三条总线：主存总线（连接 CPU 与主存）、DMA 总线（连接各高速外设的 I/O 接口）、I/O 总线。高速外设可以有多个，它们的 I/O 接口都接在 DMA 总线上。

       * 高速设备与主存交换信息走 DMA 总线，不经过 I/O 总线、不通过 CPU；低速设备与主存交换信息仍走 I/O 总线。该结构以 CPU 为中心。

   * **带 Cache 的局部总线三总线结构**

       * 动因：CPU 与主存交换信息量最大，但 CPU 性能约每年提高 52%（1985—2002），内存存储延迟约每 10 年才降为原来的一半，内存速度是瓶颈。

       * 对策：在 CPU 与内存之间增加小容量、高速度的 Cache，CPU 运行所需的指令和数据主要从 Cache 获取。

       * 分层：局部总线连接 CPU、Cache 与局部 I/O 控制器（可挂高速局部设备）；系统总线连接主存；系统总线经扩展总线接口接一条扩展总线，各类设备均可挂接。

       * 价值与遗留问题：解决了 I/O 设备的扩展问题；但多种类型、多种速度的设备混在同一条扩展总线上，快设备被慢设备拖住，影响外设工作速度。

   * **四总线结构**

       * > **定义**：用桥电路把高速设备与低速设备分类组织的结构，解决扩展总线快慢混挂的问题。

       * 局部总线连接 CPU 与 Cache（或桥）；系统总线连接主存、Cache 和桥，CPU 与主存经系统总线、局部总线交换数据。

       * 关键变化：桥电路扩展出一条高速总线承接高速设备；低速设备经扩展总线接口接扩展总线。

       * 特点：高速设备用高速总线、低速设备用低速总线分类组织，数据传输速率可以更高。

```text
   ┌─────┐ ┌───────┐
   │ CPU │ │ Cache │
   └──┬──┘ └──┬────┘
      └───────┼──────┬──────┐
              │   局部总线   │
      ┌───────┴──┐  ┌────┴───┐
      │   主存    │  │   桥   │
      └──────────┘  └────┬───┘
              │    ┌─────┴──────────────┐
              │    │       高速总线       │── 高速设备 …
              │    └────────────────────┘
              │
        扩展总线接口
              │
      ┌───────┴──────────┐
      │      扩展总线      │── 低速设备 …
      └──────────────────┘
```

## 真实机器的总线结构

   * **传统微型计算机总线**

       * 系统总线连接 CPU 与存储器（这一段速度较快），再经标准总线控制器扩展出 I/O 总线挂接各类设备。

       * 本质是把系统总线和 I/O 总线分离。

   * **VESA 总线结构**

       * 系统总线连接 CPU 与主存储器；从系统总线扩展出 VESA 总线这条高速总线，挂接高速图形设备；再经标准总线控制器扩展出低速总线挂接低速设备。

       * 同样是高速设备与低速设备分类组织。

   * **PCI 总线结构**

       * 系统总线连接 CPU 与存储器；经 PCI 桥扩展出高速 PCI 总线，连接多媒体、高速网络、高速图形等高速设备；再经标准总线控制器扩展出 ISA / EISA 总线连接低速设备。

   * **PCI 总线的扩展**

       * 当 PCI 总线上要接的设备较多、总线驱动能力不够时，通过 PCI 桥进行扩展：CPU 与存储器之间是存储器总线，下面接桥电路，桥电路下再挂 PCI 总线 1、PCI 桥、PCI 总线 2……可以继续扩展。

       * 桥电路同时实现了总线驱动能力的提高与总线的扩展。

## 总线判优控制的基本概念

   * **主设备（主模块）**

       * > **定义**：对总线具有控制权的设备，可以提出总线占用申请，占用总线后能控制与另一台设备之间的通信过程。

   * **从设备（从模块）**

       * > **定义**：不能控制总线、不能提出占用请求，只能响应主设备发来的总线命令的设备。

       * 有些设备既可以作主设备也可以作从设备；有些总线有多个主设备，有些总线只允许一个主设备。

   * **判优控制的两种实现方式**

       * > **定义**：总线同一时刻只能有一对设备使用，多个设备同时申请时必须由裁决机制决定谁占用总线，这就是总线判优控制。

       * 集中式：把判优逻辑做在一个部件上（如放在 CPU 当中），下分链式查询、计数器定时查询、独立请求三种。

       * 分布式：判优逻辑分布到各个设备或各个设备的端口上。

## 链式查询方式

   * **结构**

       * 集中式控制，总线控制部件集中；除数据总线、地址总线外，还有三条关键信号线：

       * BR（总线请求）：所有设备共用一条线发出总线占用请求。

       * BS（总线忙）：某设备占用总线后置该线，告知总线控制部件或其他部件总线忙。

       * BG（总线授权）：总线控制部件沿这条线逐个向下查询，是「链式」名称的由来。

```text
     ┌──────────────┐
     │  总线控制部件  │
     └─┬────┬────┬──┘
       │BR  │BS  │BG        BG 逐个向下查询
       │    │    └───────────────────────┐
     ┌─┴────┴────┴─┬────────┬─────────┬──┴──────┬──
     │ 数据线/地址线 │ I/O接口0 │ I/O接口1 │ ... I/O接口n
     └─────────────┴────────┴─────────┴─────────┘
```

   * **工作过程**

       * 有请求的接口通过 BR 向总线控制部件提出占用请求；控制部件在可以让出总线控制权时沿 BG 逐个向下查询，授权信号传到第一个提出请求的接口即停，该接口获得使用权并置 BS 总线忙。

   * **特征与优缺点**

       * 优先级由 BG 的查询顺序（即设备连接方式）事先确定；排得靠后的低优先级设备的请求可能一直得不到应答。

       * 对电路故障敏感：BG 传送路径上任一接口电路故障，其后所有设备都无法再获得总线使用权。

       * 优点：结构特别简单，判优线只有三条；增删设备容易；优先级算法简单；可靠性设计易实现（如把 BS 或 BG 各换成两条线冗余）。

       * 缺点：查询要一直向下进行，速度慢。一般用在微型计算机或简单嵌入式系统。

## 计数器定时查询方式

   * **结构**

       * 与链式查询同为集中式，保留 BR、BS 与数据线、地址线；区别是多一条**设备地址**线，线上的地址由总线控制部件内的计数器给出，用于查找某一设备是否发出了占用请求——这是该方式名称的来源。

```text
     ┌─────────────────────┐
     │     总线控制部件      │
     │   ┌─────────┐       │
     │   │  计数器  ├─ 设备地址线（宽度与设备数有关）
     │   └─────────┘       │
     └─┬─────────┬─────────┘
       │BR       │BS
     ┌─┴─────────┴─┬────────┬─────────┬─────────┐
     │ 数据线/地址线 │ I/O接口0 │ I/O接口1 │ ... I/O接口n
     └─────────────┴────────┴─────────┴─────────┘
```

   * **工作过程**

       * 主设备经 BR 提出占用请求；控制部件在可响应时启动计数器，计数值经设备地址线输出，从某个接口开始逐个查询：被查询接口无请求则计数器加 1 查下一个，有请求则该接口应答、置 BS 被选中。

   * **优先级非常灵活**

       * 计数器每次从 0 开始：查询按接口 0 到接口 n 的固定次序，即事先确定的固定优先级。

       * 计数器从上一次停止的计数值开始：优先级变为循环优先级，谁也不总是老大。

       * 计数器初值由软件设定为 $k$：接口 $k$ 的优先级变为最高。

       * 还可经软件对总线控制部件进行设置，更灵活地改变优先级顺序。

   * **线数**

       * 抛开各方式共有的数据线、地址线，与链式查询相比少一条 BG、多一条设备地址线；设备地址线须能给 $n$ 个设备编码，至少 $\lceil \log_2 n \rceil$ 条，再加 BR、BS 各一条，共 $\lceil \log_2 n \rceil + 2$ 条。

## 独立请求方式

   * **结构**

       * 每个 I/O 接口各有两条独立信号线：自己的 BRi 专门发本设备的总线占用请求，自己的 BGi 接收应答。

       * 总线控制部件内部有一个**排队器**，优先级排队由集中电路完成。

```text
              ┌───────────────────┐
              │    总线控制部件     │
              │  ┌─────────────┐  │
              │  │   排队器     │  │
              │  └─────────────┘  │
              └─┬───┬───┬───┬────┘
                │BR0│BG0│BR1│BG1│ ... BRn│BGn
     ┌──────────┴───┴───┴───┴────────────────┐
     │            数据线 / 地址线               │
     └────┬────────────┬─────────────┬───────┘
       I/O接口0      I/O接口1       ... I/O接口n
```

   * **工作过程与特征**

       * 多个接口同时经各自的 BR 把请求送入总线控制部件，经优先级排队后对某一设备的请求应答，被应答的设备占用总线使用权。

       * 速度快：不像前两种方式按顺序查找，确定哪个设备占用总线的速度更快。

       * 优先级灵活，取决于排队器的设置：可按预定优先级事先排队、可自适应（工作中重要的设备给高优先级）、可计数器循环设置、还可几种方法混合。

       * 代价是线数多：$n$ 个设备可能需要 $2n$ 条线解决判优。

   * **三种集中式判优方式对比**

| 方式 | 判优信号线（不含数据/地址线） | 找请求者的方式 | 优先级 |
| :--- | :--- | :--- | :--- |
| 链式查询 | BR、BS、BG 共 3 条 | BG 逐个向下链式查询，慢 | 连接顺序事先固定，靠后者可能饿死 |
| 计数器定时查询 | 设备地址 $\lceil \log_2 n \rceil$ 条 + BR、BS，共 $\lceil \log_2 n \rceil+2$ 条 | 计数器逐个查询 | 固定/循环/软件设初值，灵活 |
| 独立请求 | 每设备 BRi、BGi 两条，$n$ 台约 $2n$ 条 | 排队器直接裁决，最快 | 预定/自适应/循环/混合，最灵活 |

## 总线传输周期

   * > **定义**：总线传输周期指主设备和从设备之间完成一次完整且可靠的通信所需的时间。

   * **四个阶段**

       * 申请分配：主设备获得总线使用权，由总线判优逻辑（总线仲裁）解决。

       * 寻址：主设备发出地址和命令，通过地址找到从设备、通过命令控制从设备完成相应操作。

       * 数据传输：从设备已准备好数据就发送数据；已准备好接收就进行数据接收。

       * 结束：主模块撤销相关信息，从模块也撤销相关信息。

## 同步通信

   * > **定义**：用统一的、定宽定距的时标控制数据传送过程，每个操作、每个信号都在固定时间点上给出的通信方式。

   * **同步数据输入时序（总线周期由 4 个时钟周期构成）**

```text
时钟：  |──T1──|──T2──|──T3──|──T4──|

T1 上升沿     ：主设备（CPU）给出地址信号
T2 上升沿     ：给出读命令
T3 上升沿之前 ：从设备必须给出数据信号
T4 上升沿     ：数据信号和读命令撤销
T4 周期结束   ：地址信号撤销
```

   * **同步数据输出时序**

```text
时钟：  |──T1──|──T2──|──T3──|──T4──|

T1 上升沿     ：给出地址信号
T1 下降沿     ：给出数据
T2 上升沿     ：给出写命令
T3 上升沿     ：写入操作进行
T4 上升沿     ：主设备撤销数据、撤销写命令
T4 周期结束   ：撤销地址信息，完成输出操作
```

   * **特点与适用条件**

       * 两个要点：必须由定宽定距的时钟控制整个传输过程；在给定时间点上完成相应操作。

       * 所有从模块用同一时标、在同一时标中完成规定操作，主从模块强制同步；因此必须选速度最慢的模块作为统一时标来设计，快的设备也被最慢的拖住。

       * 通常应用在总线长度比较短、各模块存取时间比较一致的情况下。

## 异步通信

   * > **定义**：没有统一时标，由主设备发请求、从设备给应答的握手方式完成通信联络的通信方式。

       * 主设备发起总线通信，从设备受主设备控制；相比同步通信要增加两条线：请求线（主设备发请求）与应答线（从设备作应答）。

   * **不互锁方式**

       * 主设备发出请求后，不管是否收到应答，经一定延迟即撤销请求；从设备发出应答后，也不管主设备是否收到，过一段时间即撤销应答。

       * 如同扔飞盘：扔出去就算、喊一嗓子就算，双方都不确认，可靠性有问题。

   * **半互锁方式**

       * 对不互锁的改进：主设备**收到应答后才撤销请求**，收不到则请求一直保持；但从设备发出应答后不管对方是否收到，延迟一段时间仍撤销应答。

       * > **易错点** ⚠️：半互锁的主设备请求可能因一直收不到应答而**长期保持高电平**、迟迟撤不掉，这是它遗留的隐患。
   * **全互锁方式**

       * 主设备收到应答后才撤销请求；从设备**看到请求撤销后才撤销应答**，两头完全咬合。

       * 可完成可靠的数据传输；传输中发现数据出错时，半互锁、全互锁方式都可请求从设备重新发送或重新接收数据。

   * **三种握手方式对比**

| 方式 | 主设备何时撤销请求 | 从设备何时撤销应答 | 可靠性 |
| :-- | :-- | :-- | :-- |
| 不互锁 | 不等应答，延迟后即撤 | 不管主设备，延迟后即撤 | 不可靠 |
| 半互锁 | 收到应答才撤（收不到则保持） | 发出应答后延迟即撤 | 请求信号可能一直保持高电平 |
| 全互锁 | 收到应答才撤 | 看到请求撤销才撤 | 可靠，出错可请求重发 |

## 半同步通信

   * > **定义**：同步通信与异步通信的结合——用定宽定距的时钟统一调度（同步特征），再加一条由从设备控制的 wait 等待线（异步特征）。

       * 同步特征：通信全过程由定宽定距的时钟管理，发送方用时钟前沿发送信号，接收方用时钟后沿判断、识别。

       * 异步特征：允许不同速度的设备协调工作；wait 信号由从设备给出，从设备没准备好就拉住这条线让主模块等。

   * **读操作时序（总线周期安排为 4 个时钟周期）**

```text
 T1            T2            (Tw...)        T3            T4
 |             |             |              |             |
 主模块发地址   主模块发读命令  检测wait:      从模块给数据   从模块撤销数据
                             低电平则插入                 主模块撤销命令
                             等待周期Tw
```

       * T1 发地址，T2 上升沿发读命令；正常时从模块在 T3 上升沿之前把数据放到数据总线上，T4 从模块撤数据、主模块撤命令。

       * 从模块来不及准备时，在 T3 到来之前把 wait 拉成低电平；主模块在每个时钟周期到来之前检测 wait：低电平则不进入 T3、插入一个等待周期 $T_w$ 再检，仍低再插一个 $T_w$，直到 wait 变高电平才进入 T3 取数据。

       * > **易错点** ⚠️：wait 是**低电平有效**——检测到低电平是「没准备好、要等待」，变成高电平才表示可以进入 T3 取数，方向不要记反。

   * **价值**

       * 允许不同速度的存储设备之间进行信息交换：时钟骨架保证通信规整，wait 线给慢设备「等等我」的权利。

## 三种通信方式的共同缺陷与分离式通信

   * **共同缺陷：中间有一段总线在空转**

       * 同步、异步、半同步的一个传输周期都可分三步：主模块发地址和命令（占用总线）→ 从模块准备数据（**不占用总线**，总线空闲）→ 从模块向主模块发送数据（占用总线）。

       * 总线是系统瓶颈，从模块准备数据期间总线闲着，空闲就是浪费。

   * **分离式通信**

       * > **定义**：把一个总线传输周期拆成两个子周期，准备数据期间真正让出总线使用权，以充分挖掘总线每一瞬间潜力的通信方式。

       * 第一个子周期：主设备发地址、发命令并占用总线；发送完即断开与总线的连接，放弃总线使用权。

       * 第二个子周期：从设备准备好后**再次申请占用总线**——此刻它发起占用请求，身份已从从模块**变成主模块**，由它把信息放到总线上完成数据传输。

   * **算得出的例子：从硬盘读数据**

       * 第一步定位：磁头沿盘面径向移动到指定磁道，一般需要**几十个毫秒**。

       * 第二步找扇区：磁头停在磁道上，盘片转动等指定扇区转到磁头下；以 5000 转/分的磁盘计，平均等半转 $t_{avg} = \frac{1}{2} \times \frac{60}{5000}\,\text{s} \approx 6\,\text{ms}$。

       * 第三步读数据：数据传输率 33MB/s，一个扇区约 512B，读完一个扇区只需 $512\,\text{B} \div 33\,\text{MB/s}$，量级为**十几微秒**。

       * 若用半同步方式，从发出磁盘读命令到读完，绝大部分时间总线都在干等机械动作；换成分离式，通道发完定位命令即与总线断开，磁盘控制器完成定位后**变成主设备**再申请总线继续找扇区、传数据，机械动作期间总线为别的设备干活。

   * **四个特点**

       * 各个模块都有权申请占用总线，都可以从从模块变成主模块。

       * 采用同步通信方式：从模块准备好数据后，后续通信用定宽定距的时钟完成发地址、发数据、发写信号等。

       * 各模块准备数据的时候不占用总线。

       * 总线被占用时一定在进行数据传输或传输控制命令，没有一个时钟周期在干等，充分利用了总线带宽。

       * > **提示**：分离式通信的本质是「谁要发信息谁当主模块」，总线只在真正传信息的那一刻被占用。
