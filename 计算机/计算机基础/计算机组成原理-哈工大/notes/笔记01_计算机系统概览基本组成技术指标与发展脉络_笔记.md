# 计算机系统概览：基本组成、技术指标与发展脉络

## 课程定位与计算机系统抽象

* **计算机组成（Computer Organization）**

    * > **定义**：计算机硬件系统的逻辑实现——用数字电路知识、门电路、触发器等数字电子元器件实现硬件系统，不是物理实现。

    * 课程讲授数字电子计算机硬件系统逻辑实现的**一般原理**，不依托任何具体机型；好处是设计时不受具体机型制约，代价是学完可能感觉"空"，需靠含具体机型的教材落地。

    * 课程内容四块：基本部件的结构和组织方式、基本运算的操作原理、基本部件和基本单元的设计思想、把部件链接成协调运行整体的系统级组织。

    * 课程组织采用**自顶向下、层层细化**：先给整个硬件系统盖帽，逐渐细化到底层部件的逻辑实现。

* **计算机系统结构（Computer Architecture，体系结构）**

    * > **定义**：程序员所看到的计算机系统的属性、概念性结构和功能特性——这里的程序员指**机器语言程序员**，即编写能在硬件上正确执行的程序所必须了解的属性。

    * 体系结构规定的内容包括：指令集、寄存器文件的组织、内存的编址单位、数据表示（指令集能对哪些类型的数据操作）。

    * 体系结构采用"分析加评测"方式回答"该不该这样设计"：如 Cache 选两路/四路/八路组相联、一条指令是否引入指令集，都要分析评测后决定。

    * 计算机组成回答"具体怎么实现"：体系结构规定有没有乘法指令、操作数类型和长度，组成设计者研究如何用逻辑实现这条乘法指令。

* **软硬件分界与层次结构**

    * > **定义**：计算机系统从顶层抽象分为**硬件**（看得见摸得着的实体，如主机、外设）和**软件**（具有各类特殊功能的信息，存储在计算机中，驱动硬件按指令有序工作）。

    * 软件分两类：**系统软件**管理软硬件资源、提供人机交互界面，包括操作系统、语言处理程序（汇编/编译/解释程序）、服务性程序（数学库、数据库管理系统、网络软件、诊断调试工具等）；**应用软件**面向特定任务编制，调用系统软件提供的接口。

    * 从程序员视角，计算机分五层：M0 微程序机器（硬件直接执行微指令）、M1 实际机器（用微指令解释机器指令）、M2 操作系统机器（用机器语言解释操作系统）、M3 汇编语言机器（汇编程序翻译成机器语言程序）、M4 高级语言机器（编译程序翻译成汇编语言程序）。

    * 一个微程序对应一条机器指令；高级语言程序逐层向下翻译，才能完成一条指令乃至一个程序的执行。

    * M2 之上（M2/M3/M4）由软件实现，M1 及以下由硬件实现，虚线即**软硬件交界面**；这条线完成计算机系统的功能分配。

    * > **易错点**：⚠️ 一个功能用硬件还是软件实现在逻辑上等价，但代价不同：硬件实现底层复杂、造价高、设计周期长；软件实现需要指令集中多条指令组合，软件庞大、运行速度慢。

* **抽象（Abstraction）**

    * > **定义**：隐藏系统中不重要的细节，以便把其他方面的细节或结构表达得更清楚；是处理系统复杂性的核心方法。

    * 从物理构成角度，计算机系统可抽象成九层：物理抽象层（用量子机制和麦克斯韦方程描述电子移动）→ 电子元件层（device 层，用管脚电流电压特征描述）→ 模拟电路层（连续电压，构建放大器、滤波器）→ 数字电路层（构建与门、非门）→ 更高层；计算机组成主要研究**逻辑层**，与微体系结构层一起实现数据通路（datapath）和控制。

* **三个 Y（驾驭系统复杂性的设计方法）**

    * **层次化（Hierarchy）**：把系统划分成模块、子模块，递归细化，把大问题变成小问题。

    * **模块化（Modularity）**：每个模块要有明确定义的功能和**接口**，子模块才能组装成更大的模块和系统。

    * **规则性（Regularity）**：让模块接口和功能定义满足工业/国际标准，使模块可复用；典型例子是标准化内存条，任何厂家的内存都能插进接口符合标准的机器，同时细化了产业分工。

* **计算机的多态性**

    * 计算机形态跨度极大：纽扣大小的传感器（温湿度、地磁传感器）→ 信息家电（PDA 等个人数字助理）→ 笔记本/台式机 → Server → mainframe 大主机结构服务器（面向大型企业事务处理）→ HPC。

    * **HPC（High Performance Computer，高性能计算机）**：如天河二号有 312 万个处理器核心，LINPACK 实测 33 PF（每秒 3.3 亿亿次浮点），理论峰值 54 PF；泰坦 200 个机柜、18688 个计算节点，异构结构（AMD 皓龙 16 核 CPU + 开普勒 GPU），实测 20 PF。HPC 也可戏读为高功耗、高价格的计算机。

    * 物联网 = 把传感器嵌入电网、桥梁等设备感知状态，信息传到后台判断健康状态；加上反馈控制能力（前端感知、后端处理并反馈动作）即 **CPS（信息物理系统）**。

## 冯·诺依曼体系结构

* **存储程序（Stored Program）思想**

    * > **定义**：指令和数据以同等地位、都用二进制、不加区分地存放在存储器中，机器按地址访问取出执行；凡按此原理设计的机器都称冯·诺依曼计算机。

    * 由美籍匈牙利科学家冯·诺依曼提出并运用到计算机设计中，他因此被称为"现代计算机之父"。

    * 1945 年冯·诺依曼参与发表**存储程序通用电子计算机方案 EDVAC**（E 电子、V 变量、A 自动化、C 计算机），确定新计算机由五大部分组成并描述其职能与相互关系，是计算机史上划时代的文献；第一台冯·诺依曼结构机器是 **1949 年的 EDVAC**。

    * 缘起：1944 年冯·诺依曼在火车站偶遇弹道实验室军方负责人戈尔斯坦，被 ENIAC 研制计划吸引后加入研制小组。

* **冯·诺依曼计算机的六个特点**

    * 由**运算器、控制器、存储器、输入设备、输出设备**五大部件组成。

    * 指令和数据以**同等地位**存于存储器，访问**按地址**进行。

    * 指令和数据都用**二进制**表示。

    * 指令由**操作码**和**地址码**构成：操作码指明做什么，地址码指明操作数所在地址（内存或寄存器）。

    * **存储程序**：程序预先存放在存储器中。

    * **以运算器为中心**。

    * 六点的核心就是存储程序；对每个特点都可追问：五大部件能否合并（算盘上五个部件在人和算盘上重新分配）、指令数据能否分开存（现代指令 Cache 与数据 Cache 分开且**按内容查找**）、为何是二进制、操作码还能编码寻址方式与数据类型长度（IBM 360 同一加法按基值长度分八种）、能否不以运算器为中心。

* **五大部件的职能**

    | 部件 | 功能 |
    | :--- | :--- |
    | 运算器 | 完成算术运算和逻辑运算（核心） |
    | 存储器 | 存放数据和程序 |
    | 控制器 | 指挥控制程序运行，完成指令执行及指令间先后顺序控制 |
    | 输入设备 | 把人能识别的信息转化成机器能识别的形式，经运算器存入存储器 |
    | 输出设备 | 把处理结果转化成人熟悉的形式 |

* **结构演进：从以运算器为中心到以存储器为中心**

    * 以运算器为中心的问题：数据输入输出必须经过运算器，运算器成为系统**瓶颈**；且框图杂乱、无层次化特征。

    * 改进一：改为**以存储器为中心**，输入输出设备与存储器之间直接交换信息，运算器只负责运算。

    * 改进二：整理成层次化结构——ALU 与 CU 合成 **CPU**；主存与 CPU 构成**主机**；输入设备、输出设备加辅助存储器构成 **I/O 设备**；主机加 I/O 设备构成完整的计算机系统硬件。

* **可计算性与上机前的准备**

    * 用计算机解决问题先问"能不能算"：**可计算性理论**研究计算的可行性——若存在算法对定义域 D 中任意 $x$ 都能算出 $f(x)$，则函数可计算；著名的不可计算问题是**图灵机停机问题**。

    * 编程序之前先**建立数学模型**（如正弦交流电的实时电压模型），再**确定计算方法**（如 $\sin x$ 用级数展开、$\sqrt{x}$ 用迭代公式，迭代到相邻两次结果之差满足精度要求为止），最后才编程。

    * 程序是运算所需的全部步骤，由指令构成，每条指令对应一个步骤。

## 存储器的组成与访问

* **存储体的三级结构**

    * > **定义**：存储体由若干**存储单元**构成，存储单元由多个**存储元件**构成；类比为一栋大楼（存储体）、房间（存储单元）、床位（存储元件，有人/无人对应 1/0）。

    * **存储字**：存储单元里存放的一串二进制代码的组合；**存储字长**：存储单元中二进制代码的位数。

    * 存储单元**按地址寻址**：给出地址即可把指令或数据从存储体中取出。

* **MAR 与 MDR**

    * **MAR（Memory Address Register，存储器地址寄存器）**：保存要访问的存储单元地址；位数由**存储单元个数**决定，$n$ 位二进制能区分 $2^n$ 个地址。

    * **MDR（Memory Data Register，存储器数据寄存器）**：保存要送入 CPU 或刚从存储体取出的数据；位数与存储单元长度相同，反映**存储字长**。

    * 例：MAR 4 位 → 16 个存储单元；MDR 8 位 → 存储字长 8 位。

    * MAR 和 MDR 是**接口寄存器**，CPU 与存储体打交道都要经过它们。

    * > **提示**：MAR 管"多少个"单元，MDR 管"每个多大"——一个由存储单元个数决定，一个由存储字长决定。

## 运算器的结构与四则运算

* **运算器的基本组成**

    * > **定义**：运算器核心是**算逻运算单元 ALU**，通常是组合电路——输入撤销输出随之撤销，故必须在输入端加寄存器保存参与运算的数据。

    * 三个寄存器：**ACC（Accumulator，累加器）** 与 **X（数据寄存器）** 是 ALU 的两个输入寄存器，结果送回 ACC；**MQ（乘商寄存器）** 不参与加减法，只在乘除法时出场——名字即"乘"与"商"的缩写。

    * MQ 存在的原因：乘法结果长度是操作数的**两倍**，需要额外寄存器保存。

    * 该结构是**累加器型模型机**的结构；若设计通用寄存器型计算机，寄存器数量与结构会相应变化。

* **四则运算的寄存器分配**

    | 运算 | ACC | X | MQ | 结果去向 |
    | :---: | :--- | :--- | :--- | :--- |
    | 加法 | 被加数（初态） | 加数 | 不用 | 和 → ACC |
    | 减法 | 被减数（初态） | 减数 | 不用 | 差 → ACC |
    | 乘法 | 被乘数（初态），清零后存乘积高位 | 被乘数（中途转入） | 乘数、乘积低位 | 高位在 ACC、低位在 MQ |
    | 除法 | 被除数（初态）、余数 | 除数 | 商 | 商 → MQ，余数 → ACC |

    * 乘法用**加法和移位**实现：乘数每一位是 0 或 1，斜式每一行要么是被乘数要么是 0，用 ACC 逐行累加（不能像笔算那样同时相加）。

    * 除法用**减法和移位**实现：与除数做差，够减商 1、不够减商 0。

* **单地址指令的执行步骤**

    * 模型机指令只有一个地址码，另一个操作数**隐含在 ACC** 中；执行前须先用取数指令把被加数/被减数/被乘数/被除数送入 ACC。

    * 加法：`(M) → X`，`(ACC) + (X) → ACC`；减法对应 `(M) → X`，`(ACC) − (X) → ACC`。记号 $[M]$ 表示地址为 M 的内存单元的**内容**——地址与地址里的内容是两回事。

    * 乘法四步：`(M) → MQ`（乘数）、`(ACC) → X`（被乘数）、`0 → ACC`（清零）、`(X) × (MQ) → ACC//MQ`（高位进 ACC、低位进 MQ，结构图上两寄存器间的双斜线即拼接关系）。第 1 步与第 2 步可互换甚至同时进行；第 3 步须在第 2 步之后；操作先后顺序由控制器控制。

    * 除法两步：`(M) → X`，`(ACC) ÷ (X)` 后商进 MQ、余数留在 ACC。

    * > **易错点**：⚠️ 两个 8 位数相乘结果最多 16 位（如 $80 \times 80 = 6400$），8 位寄存器存不下；乘法结果位数超出寄存器长度是设计运算器时必须处理的问题。

## 控制器与指令执行流程

* **控制器的三件套**

    * > **定义**：控制器的功能是**解释**一条指令——从取指、分析、取操作数到执行、保存结果的全过程都由它控制，并保证指令按序执行；用"解释"一词避免与运算器的"操作"混淆。

    * **PC（Program Counter，程序计数器）**：保存**当前要执行的指令的地址**；因指令要连续执行，PC 必须有计数功能（PC + 1 → PC），为下一次取指做准备；"加 1"实际加几与机器结构有关。

    * **IR（Instruction Register，指令寄存器）**：存放**当前要执行的指令本身**，控制单元从 IR 中取出操作码进行分析；操作码部分记作 OP，地址码部分记作 AD。

    * **CU（Control Unit，控制单元）**：控制器的**核心**，各种控制信号都从 CU 发出，控制操作的先后顺序。

* **一条指令的三个阶段**

    * **取指令**：PC 把指令地址送 MAR、MAR 送存储体，存储体取出指令送 MDR，MDR 送 IR。取指结束后即可做 PC + 1——因为分析、执行阶段不再用到 PC 的旧值。

    * **分析指令**：把 IR 中的操作码（OP）送给 CU 译码，CU 发出控制信号。

    * **执行指令**：由 CU 控制相应部件完成操作。

    * 取数指令执行：IR 的地址码（AD）送 MAR → 存储体取出数据送 MDR → MDR 送 ACC。存数指令方向相反：AD 送 MAR，ACC 内容送 MDR，MDR 数据写入存储体；**任何指令的取指阶段操作都相同**。

* **程序的完整执行过程**

    * 启动三步：通过输入设备把程序和数据存入内存；把程序**首地址**送入 PC；启动机器。

    * 程序执行 = 逐条执行指令的组合；每条指令走"取指 → 分析 → 执行"三步；最后一条存数指令结束后打印，再停机。

## 模型机程序设计实例

* **从算式到程序：指令条数由算法决定**

    * 任务：计算 $ax^2 + bx + c$，机器为累加器型（一个操作数在 ACC，另一个来自主存），假设 $a$、$b$、$c$、$x$ 已在内存。

    * 按原始形式算需 **8 条指令**：取 $x$ → 乘 $x$ 得 $x^2$ → 乘 $a$ 得 $ax^2$ → 存数转存 → 取 $b$ → 乘 $x$ 得 $bx$ → 加 $ax^2$ → 加 $c$。

    * 先变形 $ax^2 + bx + c = (ax + b) \cdot x + c$，按右式算只需 **5 条指令**：取 $x$ → 乘 $a$ → 加 $b$ → 乘 $x$ → 加 $c$。

    | 对比项 | 原始形式 | 变形形式 |
    | :--- | :--- | :--- |
    | 指令条数 | 8 条 | 5 条 |
    | 执行速度 | 慢 | 快 |
    | 存储空间 | 更大 | 更小 |

    * > **提示**：这是**算法**层面的改进——同一台机器上指令条数多的程序更慢且更占存储空间，写程序前先在算法上动脑子。

* **指令格式与编码**

    * 假设指令 **16 位**：6 位操作码 + 10 位地址码；如取数指令操作码 `000001`，地址码 `0000001000`（十进制 8）表示取 8 号单元的数据进 ACC。

    * 单操作数指令中 ACC 是默认的，不必在指令中指出；六条指令（取数、存数、加法、乘法、打印、停机）操作码分别编码，地址码写操作数的实际物理地址。

* **存储程序思想的落地**

    * 程序清单进内存：0~7 号单元存指令（操作码 + 地址码），8~11 号单元存 $x$、$a$、$b$、$c$，结果存 12 号单元——指令和数据在存储器眼里没有任何区别，同等地位、都是二进制。

    * 只有以**存储程序**方式把指令和数据保存进存储器，系统才能执行这些指令。

## 计算机硬件的技术指标

* **机器字长**

    * > **定义**：CPU 一次能够处理的数据的位数。

    * > **易错点**：⚠️ 两个 8 位数相加得 8 位结果，机器字长是 **8 位不是 24 位**——只看"一次处理"的数据宽度，不把操作数和结果加起来数。

    * 通常机器字长与 CPU 寄存器位数相等（模型机中即 ACC、X、MQ 的长度）；模型机还假设存储字长也等于寄存器长度——**这只是模型机假设**，现实计算机并非都如此。

    * 机器字长越长性能越好：64 位数相加，8 位字长要做八次分段加法，64 位字长一次完成。

* **运算速度指标**

    * **主频与核数**：主频越高、核数越多机器**可能**越快，但主频和核数**不是机器速度的直接指标**——还要看完成一条指令需要多少时钟周期。

    * **吉布森法（Gibson mix）**：按每条指令出现的频率 $f_i$ 计算指令执行时间的**加权平均**。$f_i$ 两种算法：在程序清单上直接统计得**静态使用频率**；真实执行程序统计得**动态使用频率**（更准确）。简单把所有指令执行时间求平均是错的——执行很慢但出现频率极低的指令对整机性能影响不大。

    * **CPI（Cycles Per Instruction）**：执行一条指令平均需要多少个**时钟周期**，按静态或动态使用频率加权平均；越少越好，理想是一条指令一个周期。

    * **IPC**：一个时钟周期能完成多少条指令，与 CPI 相反；为衡量超标量计算机（每周期完成多条指令）而设。

    * **MIPS（Million Instructions Per Second）**：每秒执行多少**百万条**指令；但"MIPS 越大越快"有问题——还要看每条指令完成了多少运算、指令复杂程度如何。

    * **FLOPS（Floating-point Operations Per Second）**：每秒完成的**浮点运算**次数，可加 M/G/T/P 前缀；从"执行指令"回到"完成运算"的角度，比 CPI、MIPS 更科学。

    * 最直接的方法：把最常用的程序装到待选机器上实测运行性能——这是**最合适**的选机方法。

* **存储容量的表示**

    * 存储容量用**存放二进制信息的总位数**衡量；主存容量两种写法。

    * 方法一：**存储单元个数 × 存储字长**。由 MAR、MDR 位数直接得出：MAR 10 位 → $2^{10}$ = 1K 个单元，MDR 8 位 → 容量 **1K × 8 位**；MAR 16 位、MDR 32 位 → **64K × 32 位**。1K 个单元也意味着编址需要 10 位，即 MAR 的长度。

    * 方法二：**字节数**。小写 b 是位（bit），大写 B 是字节（Byte），$1\ \text{B} = 2^3 = 8$ 位；$2^{13}$ b = 1 KB；$2^{21}$ b = 256 KB；G 是 $2^{30}$。

    * > **易错点**：⚠️ b 和 B 差 8 倍，$2^{13}$ 个**小 b** 才等于 1 个 K 的**大 B**，换算时先把位换成字节再套 K、M、G。

## 电子计算机的诞生与发展史

* **ENIAC**

    * 由宾夕法尼亚大学摩尔小组（四位科学家和工程师，含戈尔斯坦和 24 岁的埃克特）研制，**1946 年**出现；教材称其为第一台计算机，但"哪台是第一台"本就有争议——它对后续发展的深远影响是确定的（冯·诺依曼结构正是从它的研究过程中产生的，虽然那些思想没用在它身上）。

    * 主要指标：采用**十进制**运算；约 **18000 个电子管**（不同文献记 17000/18000/18800 不等）、1500 个继电器；功耗 **150 千瓦**（相当于 1500 个 100 瓦灯泡）；重 **30 吨**、占 **1500 平方英尺**；速度**每秒 5000 次加法**——比当时最快的机器快 1000 倍、手工计算的 20 万倍；总花费 **48 万美金**；军方用于计算**弹道表**；编程靠**手工扳动开关和插拔电缆**；1955 年退役。

    * 两个致命缺点：**没有存储器**；**用布线接板控制**，运行很小的程序也要搭接几天——编程工作抵消了计算速度。改进方向正是冯·诺依曼结构要解决的两个核心问题：存起来、用程序控制。

* **发展的驱动力与分代**

    * 驱动力是**需求**：弹道实验室每天要出六张火力表，每条弹道是一组难精确求解的非线性方程组，200 名计算员加班加点算一张火力表约需两个月——战争年代时间决定胜负。

    * 另一驱动力是**技术**：电子管 → 晶体管 → 集成电路，**电子技术的发展是直接动力**；当电子技术处在发展平台期时，**体系结构技术**顶上——电子技术与体系结构技术对计算机发展的贡献基本**五五分成**。

    * 计算机分代以**硬件技术的发展**为标志：第一代电子管（1946—1957，约每秒 4 万次）→ 第二代晶体管 → 第三代中小规模集成电路 → 第四代大规模集成电路 → 第五代超大规模集成电路（1978 年至今）。

* **IAS：典型的冯·诺依曼结构机器**

    * 1946 年开始设计、1952 年投入运行；名称来自**普林斯顿大学先进技术研究院**（Institute for Advanced Studies），资金部分来自普林斯顿大学、军方机构和美国政府。

    * 整体分四块（I/O 合在一起，再分即五大部分）；数据输入输出都要**经过 ALU**——典型的以运算器为中心的冯·诺依曼结构。

* **IBM System/360：系列机的起点**

    * 大主机结构，1961 年开始研制、1964 年研制成功；"360"意为 360 度全方位服务科学界、商业界、工业界；投入 **50 亿美金**，被《幸福》杂志称为"IBM 五十亿美元的大赌博"——赌成功了。

    * 突出特点是**系列产品**而非单台机器：大中小型 360 具有相同的指令系统、相同的数据表示，可运行相同程序、配置相同外设、互相互联。

    * 贡献一：研发中阿姆达尔、布鲁克斯提出了**计算机系统结构**概念，定义了软硬件交界面——软硬件人员可依同一规定**同时设计**，缩短研制周期。

    * 贡献二：催生系列机与兼容机——按同一软硬件交界面可设计内部组成不同（内部总线 8/16/32/64 位均可）但指令集相同的机器。**一个厂家**内生产的相同体系结构的一组机器叫**系列机**；**不同厂家**生产的相同体系结构的机器叫**兼容机**。

* **微处理器与摩尔定律**

    * **微处理器**：用一片大规模集成电路组成的处理器，集成运算器和控制器（相对概念）；**微型计算机**：使用微处理器和集成度相当高的大规模集成电路构成的、面向个人用户的体积小、重量轻、价格低的计算机。

    * 基础芯片：**1971 年 Intel 4004**（4 位）是第一块微处理器芯片；存储芯片 1970 年出现，当时只能存放 256 位；微处理器位数走过 4 → 8 → 16 → 32 → 64 位。

    * Intel 芯片晶体管数：8086 2.9 万 → 80286（3 年后）13.4 万 → 80386（1985）27.5 万 → 80486（约 4 年后）120 万，大体每代约 4 倍；用对数坐标（纵轴每格十倍）对年限作图呈**指数发展**。

    * **摩尔定律**：由 Intel 创始人之一戈登·摩尔 1965 年在《电子学》杂志 35 周年约稿**《让集成电路填满更多的元件》**中发现——新一代芯片的晶体管数是前一代的两倍，每代芯片在前一代出现后 18~24 个月推出。表述为：芯片集成晶体管数**每 18 个月翻一番、每 3 年变为原来的 4 倍**；价格不变时性能相应提高一倍；每一美元能买到的计算性能每 18 个月提高一倍。

## 软件的发展与计算机的应用展望

* **编程语言的演进**

    * **机器语言**：面向机器的二进制代码，难记忆；每台新机器一套新指令集，软件换机器就要重写。

    * **汇编语言**：仍面向机器，但助记符号比 0、1 代码易记；与机器指令基本一一对应。

    * **高级语言**：面向问题、与底层指令集关系不大，程序员不需了解指令系统，编程效率大幅提高。代表：FORTRAN（科学/工程计算）、Pascal（结构化程序设计）、C++（面向对象）、Java（跨平台、适应网络环境）。

* **软件发展的三个特点**

    * **开发周期长**：现代软件几千万行代码量级——4000 万行、人均年产 1 万行即需 4000 人年。

    * **制作成本昂贵**：软件主要靠人编写，人年工资即是成本。

    * **质量检测的特殊性**：软件测试难以走通到底——遍历输入域不现实；代码覆盖（每行都执行过）也不能保证无错；分支覆盖、路径覆盖因多层循环的**组合爆炸**几乎不可能全部检测。

    * 需求分析与软件测试两头约占软件价格的一半；软件开发效率低（硬件有大量辅助工具，软件仍主要靠人写代码），由 bug 引发的火箭爆炸、银行/电商网站瘫痪等实例很多。

* **计算机的应用谱系**

    * **科学计算**：电子计算机产生的动因；天体建模、核爆炸模拟、气候/天气预报、流体/海洋/大气质量建模等，用 HPC。

    * **数据处理**：银行、电信、民航、税务等数据密集型任务，单笔运算量不大但并发量大；用 mainframe 大主机（如 IBM 360、IBM z10）。

    * **工业控制与实时控制**：自动化靠计算机控制设备实现，如无人驾驶系统。

    * **网络技术**：电子商务（京东、淘宝）、网络教育（慕课）、敏捷制造（对快速变化的市场需求做出快速响应）。

    * **虚拟现实（VR，亦称灵境技术/人工环境）**：计算机模拟虚拟世界，听觉视觉触觉身临其境；典型应用是飞行训练的地面模拟系统。

    * **办公自动化与信息管理系统**、**CAD/CAM/CIMS**：CIMS 是计算机集成制造系统，把产品设计过程中孤立的自动化子系统有机联合，适合**多品种、小批量**生产。

    * **多媒体技术**与**人工智能**：AI 是未来会改变世界的技术。

* **计算机的展望**

    * **类人脑超级智能**：自动驾驶、IBM Watson、谷歌大脑、百度大脑等方向；要求机器有大的存储容量、很高的运算速度和模式匹配速度。

    * **芯片集成度的天花板**：受三方面限制——物理极限（晶体管再小也比一个原子大）、成本（制造设备越来越昂贵，制造成本几何级数上升）、功耗与缺陷（功耗散热增加、线延迟增大、制作缺陷增多）。

    * **替代硅芯片的三个方向**：**光计算机**（光最方便做数据传输，折射/反射镜可让光在空中交叉，避免印刷总线不能直接交叉的限制）、**DNA 计算机**（控制 DNA 分子间的生化反应完成计算）、**量子计算机**（利用原子的量子特征完成计算，量子密码是当前热门）。

## 总线基础

* **为什么用总线**

    * **分散连接**的问题：$n$ 个设备两两相连需约 $n(n-1)/2$ 组通信线路；接口占用大量空间；扩展困难——新增一个 I/O 设备要新增 $n$ 束线。

    * > **定义**：总线（bus）是一组信息的**公共传输线**，各个设备都连到总线上，需要传输信息的一对设备利用这条总线传输。

    * 总线的代价：**任何一个时刻只能有一对部件使用总线**，其他部件须等其释放——总线成为系统瓶颈。

* **串行与并行传输**

    * **串行**：信息一位一位地放上线、一位一位接收，一根数据线。

    * **并行**：多位同时上线、同时接收，需要多条数据线；但距离长时平行线间产生干扰、信号变形，故**并行通常用于短距离**（机箱内部），**串行支持较长距离**。

    * 串行一次 1 位、并行一次 8 位看似并行快得多，但高速信号实际用哪种需查资料另行考证。

* **总线结构的演变**

    * **单总线结构**：CPU、主存、I/O 接口全挂一条系统总线；任一时刻只能一对部件使用——I/O 与主存传输时主存与 CPU 无法传输，**CPU 执行程序的过程会停止**；总线长了传输延迟大、发生总线征用。

    * **面向 CPU 的双总线结构**：从 CPU 延伸出 M 总线（存储总线，专用服务繁忙的 CPU—主存交换）和 I/O 总线；但主存与外设之间**没有直接通路**，须以 CPU 为媒介，外设与主存传输时 CPU 仍被打断。

    * **以存储器为中心的双总线结构**：从主存发出存储总线（连 CPU）和系统总线（连 CPU 与 I/O）；进步在于主存与外设可经系统总线直接交换；但目前技术下两条总线通常**不能同时工作**（双口 RAM 向两端口送数据也是分时的）。

* **总线的分类**

    * 按位置分三类：**片内总线**（芯片内部各部件间连接）、**系统总线**（计算机各部件之间的信息传输）、**通信总线**（计算机之间、计算机与其他系统/设备之间通信，串行或并行）。

    * 系统总线按传输信号分三类：

        * **数据总线**：传数据信号，**双向**；宽度与机器字长、存储字长相关但通常**小于等于**它们——64 位机上数据总线可只做 8 位，传一个 64 位数要 8 次。

        * **地址总线**：**单向**，由 CPU（或主设备）发出；条数与存储地址、I/O 地址单元个数相关；模型机中地址总线宽度与 MAR 宽度一致。

        * **控制总线**：有出有入——出的如存储器读写控制、总线使用权许可、中断确认（CPU 发出）；入的如中断请求、总线请求（I/O 接口送给 CPU）。

* **总线的特性与性能指标**

    * 总线的物理载体是印刷电路板上的布线，微机中即**主板**（模板），板上留接口插槽供 CPU 插板、存储器插板、I/O 插板接入。

    * 四个特性：**机械特性**（尺寸、形状、管脚数、排线次序）、**电气特性**（传输方向与有效电平范围）、**功能特性**（每根线传什么信号——地址/数据/控制/状态反馈）、**时间特性**（信号间的时序关系、持续时间）。

    * 性能指标：

        * **总线宽度**：数据线的根数（4/8/16/32 条），根数越多同时传输的位数越多。

        * **标准传输率**：每秒传输的**最大字节数**，两个关键词——"最大"（满负荷）、单位是字节。

        * **时钟同步/不同步**：传输方式同步还是不同步；不用"异步"一词，因为"不同步"包括多种类型。

        * **总线复用**：地址线与数据线共用，如 8086 的 20 根地址线中 16 条兼作数据线（先给地址并锁存，再传数据）；目的是**减少芯片管脚数**、减小封装体积。

        * **信号线数**：地址线、数据线、控制线线数的总和。

        * **总线控制方式**与**负载能力**（总线上可挂多少个 I/O 设备）。

* **总线标准**

    * 总线标准给出一个**标准界面**：不同专业化企业（专产内存、CPU、I/O 设备）按同一约定生产即可互连成完整系统；标准从低速向高速、强扩展能力演进，老标准逐步淘汰。

    * ISA 带宽可算：时钟 8 MHz（每秒 8M 次）× 每次传 16 位即 2 B = **16 MB/s**；EISA 数据线加宽到 32 位、时钟仍 8 MHz，带宽翻倍为 32 MB/s，且与 ISA 兼容。

    | 标准 | 数据线 | 时钟 | 带宽 | 特点 |
    | :--- | :---: | :---: | :---: | :--- |
    | ISA | 16 位 | 8 MHz | 16 MB/s | 工业标准体系结构，已逐步淘汰 |
    | EISA | 32 位 | 8 MHz | 32 MB/s | 对 ISA 的扩展，ISA 卡可插到 EISA 总线 |
    | VESA | — | — | — | 视频电子标准协会（1989 年成立的非盈利国际组织）针对 PC 高速活动图像而生；很多信号直接来自 CPU，驱动能力较差 |
    | PCI | — | — | — | 外设部件互联标准，当前用得最多；独立于处理器，用中间缓冲器把 CPU 子系统与外设分开，外设可随意添加而不拖累系统性能 |
    | AGP | — | — | 最高 533 MB/s | Intel 1996 年 7 月推出，点对点局部总线，连接控制芯片与显卡，由 PCI 发展而来 |
    | RS-232 | — | — | — | 常用串行通讯总线标准，R 即"推荐"（Recommended） |
    | USB | — | — | — | 通用串行总线（Universal Serial Bus） |
