# 输入输出系统：概述、程序查询与中断方式

## I/O 系统的发展主线：I/O 操作逐步从 CPU 中分离

* **输入输出系统（Input/Output System，I/O 系统）**

    * > **定义**：由 I/O 软件与 I/O 硬件组成的、完成主机与外部设备之间信息交换的系统，是计算机系统中种类最多、功能最多、结构最复杂、构成最多样的一套系统。

    * 现代计算机中外部设备的总成本可占到整机总成本的 80% 以上。
    * 外设的丰富程度是随应用推动的：60 年代计算机用于文本处理产生了字符发生器与字符显示器；多媒体、嵌入式应用把计算机装进自动设备与武器装备；再往后互联网、物联网、云计算、物理信息系统等应用都依赖丰富多彩的外部设备。
    * 本章脉络：5.1 概况、5.2 外部设备、5.3 I/O 接口的功能与结构、5.4–5.6 设备与主机信息传送的控制方式（三种主要控制方式之外还会简要介绍另外两种）。

* **分散连接（辐射式连接）**

    * > **定义**：早期计算机中每个外部设备都有专门控制线路、甚至与 CPU 控制电路设计在一起集中耦合的连接方式。

    * 触发条件：早期计算机数量少、应用少、外设也少，为每台设备配一套控制线路是值得的。
    * 边界：增删设备困难；为一台主机设计的设备拿到另一台机器上可移植性弱。既不便于增删设备，也不便于设备移植。
    * 该时期信息传送主要采用**程序查询方式**：CPU 的工作和 I/O 的工作串行进行，I/O 做输入输出时 CPU 必须运行相应程序或处于等待状态。

* **接口 + 总线连接与 DMA 控制器**

    * 外设增多后分散连接不再适应，出现 I/O 接口与 DMA 控制器，连接方式改为总线：I/O 设备通过接口挂在总线上，一条总线可连接多个设备，另一端连主机。
    * 传输控制随之要求 CPU 与 I/O 并行工作，出现**中断方式**和 **DMA 方式**两种信息交换控制方式。

* **通道（Channel）**

    * > **定义**：一种简单的处理器，可视为小型化、功能更强的 DMA 控制器，能执行由通道指令组成的通道程序，控制所连 I/O 设备与主机直接进行信息传输。

    * 通道有自己的指令系统与控制器，有的通道还有自己的存储器；操作系统按广义 I/O 指令的参数编写通道程序放入内存（或通道自己的内存），启动通道后通道凭通道程序首地址执行，完成 I/O。
    * 通道可带若干**子通道**，子通道可并行工作；每个子通道下接多个设备控制器，每个设备控制器又可连接多个设备。

* **I/O 处理机（I/O Processor）**

    * 比通道更进一步：可以是专用处理器；大型机中可用现代微处理器直接充当，也有大型机直接采用与主机完全相同的处理器充当。
    * 功能强大到没有 I/O 设备工作时，I/O 处理机可作为主机的处理器完成计算任务。

* **演进主线**

    * 程序查询（CPU 与 I/O 串行）→ 接口 + 中断/DMA（CPU 与 I/O 并行）→ 通道 → I/O 处理机。
    * 结论性规律：随着 I/O 系统的发展，数据的输入输出操作逐渐从 CPU 中分离出来，I/O 系统的自治能力越来越强。

## I/O 系统的组成：软件与硬件

* **I/O 指令**

    * CPU 指令集中控制外部设备的指令，由程序员编入应用程序，CPU 执行后使外设与主机协调工作。
    * 格式分两部分：**操作码**是 I/O 指令的标志，指出对 I/O 设备做什么操作（查询、输入、输出及其他控制）；**设备码**给出 I/O 设备的编码（设备地址），或设备内某个寄存器的地址——这些寄存器称为 **I/O 端口**。

* **通道指令（Channel Instruction）**

    * > **定义**：通道自身的指令，组成通道程序，指出传输成块数据（数组）的首地址（或单个字节的内存地址）、传输的字数、传输方向、设备地址等参数。

    * 通道指令一般较长，例如 IBM 370 的通道指令长度是 64 位。
    * 编程人员通常不直接写通道指令：应用程序中增加**广义 I/O 指令**，指出参加传输的 I/O 设备、数据在存储器中的首地址、传输数据的长度与传输方向；操作系统据其参数编写通道程序并启动通道。

* **I/O 硬件组成**

    * 包括 I/O 设备本身与输入输出接口设备：设备通过接口连到总线上与主机交换信息。
    * 采用通道方式时的层级：设备 → 设备控制器 → 子通道 → 通道。

## I/O 设备与主机的联系方式

* **统一编址**

    * > **定义**：把 I/O 设备（端口）的地址看成内存地址的一部分的编址方式。

    * 例：内存地址共 1 兆，拿出其中低地址部分或高地址部分的 64K 作为 I/O 设备或端口的地址；访存指令的地址码落到 I/O 地址部分，这次读写就是针对 I/O 设备的。
    * 条件与优点：CPU 可直接用取数/存数指令访问和控制 I/O 设备，**不需要单独的 I/O 指令**，指令系统相对简单。
    * 适用前提：内存编址空间足够大，例如采用 64 位地址、寻址空间非常大时可以拿出一部分作 I/O 地址。

* **单独编址（不统一编址）**

    * > **定义**：在内存地址空间之外专门设置一个 I/O 地址空间的编址方式。

    * 例：内存地址空间 20 位、寻址 1 兆；外设单独编址从 16 个 0 到 16 个 1，共 64K。
    * 边界：输入输出不能再借用取数/存数指令，**必须用专用的 I/O 指令**区分操作对象是内存还是 I/O 设备；指令集要额外增加 I/O 指令。

* **设备选择电路**

    * > **定义**：识别某设备是否被选中的电路，实现上就是把 CPU 给出的地址与设备中保存的自身地址进行比较，两者相同则该设备被选中。

    * 设备被选中之后即可开始数据传输。

* **数据传送方式**

    * **串行传送**：数据一位一位传输，速度较慢，适合远程传输。
    * **并行传送**：多位数据同时在多条数据线上传输，数据线条数通常为 8 的倍数。

* **联络方式**

    * **立即响应**：结构简单、状态数量少的设备收到数据或输入数据可直接响应，如 LED 灯接收到数据后直接以亮或不亮表示接收到的值。
    * **异步工作**：采用**应答信号**；既可并行也可串行传输。CPU 与接口之间一般是并行传输，应答信号主要用在 I/O 接口与 I/O 设备之间：输出时端口把数据准备好后发信号告知设备、设备读取并给应答；输入时接口中数据缓冲器一旦空了就发信号允许设备发送、设备发送数据并给应答。
    * 串行异步的数据格式：前面是命令字、中间是数据字、后面也是命令字；传输一个数据字时先有**起始位**（9.09ms 低电平），接着若干位数据位（如 8 位），最后两位高电平**终止位**（$2 \times 9.09\,\text{ms}$）表示传输结束。
    * **同步工作**：设备和主机之间必须有一个**定宽定距的时标**，控制在某个时间点必须开始某项工作、某个时间点某项工作必须结束。

## I/O 设备与主机的连接方式

* **辐射式连接的问题**

    * 每增加一个 I/O 设备，主机就要增加一套控制电路与信号线；设备越多越麻烦，且可移植性弱。
    * 适用边界：仅在早期外设数量很少时合适。

* **总线连接与接口的职责**

    * 外部设备通过接口连到总线上，接口承担：向外部设备传送主机的控制命令；向主机传送外部设备的状态信息；数据缓存（外设输入数据先缓存在接口中、完成格式转换后再输入主机，反向同理）以及数据格式转换等处理。
    * 接口一般采用工业标准、国际标准或国家标准，只要设备与主机采用标准接口连接，就便于增删设备、便于设备移植。

* **总线连接的拓扑**

    * ```text

         主机 ── 总线 ──┼── I/O 接口 ── I/O 设备
                    └── I/O 接口 ── I/O 设备

## 信息传送的控制方式总览

* **五种控制方式**

    * 本课程展开的三种：程序查询方式、程序中断方式、DMA 方式；另有通道方式与 I/O 处理机方式仅简要提及。
    * 三方式的 CPU 处境递进：

| 控制方式 | 数据准备阶段 | 数据传送阶段 | CPU 的处境 |
| :--- | :--- | :--- | :--- |
| 程序查询 | CPU 踏步查询 I/O 接口状态 | CPU 执行程序完成传送 | 大部分时间在查询等待，效率最低 |
| 程序中断 | CPU 与外设并行工作 | CPU 执行中断服务程序完成传送 | 准备阶段解放了，传送时仍要 CPU |
| DMA | CPU 与外设并行工作 | DMA 控制器占用总线，直接在内存与外设间传送 | 只让出一个存取周期，可与 DMA 并行 |

* **程序查询方式的核心特征**

    * CPU 执行读指令发出读命令后，反复读取 I/O 接口中状态标志（同时检查状态是否出错、出错则进入出错处理）；只有标志显示数据准备好，才从接口读出一个字节或一个字到 CPU 的某个寄存器，再写入内存指定位置；判断传输是否结束，未结束则再次发读指令循环。
    * 数据准备的整个过程中 CPU 一直原地踏步，效率非常低。
    * 结构特点：内存与 I/O 之间的数据交换必须经过 CPU——数据先送入 CPU，再由 CPU 转存到目标，即 **CPU 一手托两家**。

* **程序中断方式的核心特征**

    * 改进点：把 I/O 设备的工作分成**数据准备阶段**与**与主机交换信息阶段**；设备自身准备时 CPU 不查询、继续执行主程序，只有开始信息交换时 CPU 才暂停现行程序转去服务。
    * 流程：CPU 执行主程序 → 执行 I/O 指令启动设备 → 继续执行主程序 → 设备准备就绪发**中断请求** → CPU 在第 $k$ 条指令执行完后保存断点与现场 → 执行中断服务程序完成数据输入输出 → 恢复现场 → 从第 $k+1$ 条指令继续。
    * 实现了 CPU 与 I/O 的**部分并行**；但解放不彻底：真正传输仍需 CPU，且保护/恢复现场与断点要靠指令完成——传一个字节可能要十几甚至几十条指令做现场保护恢复，消耗 CPU 较大时间。

* **DMA 方式的核心特征**

    * 外部设备与内存之间建立直接连接，由 DMA 控制器（DMA 接口）直接控制两者交换数据，不再事事劳驾 CPU。
    * DMA 占用总线的时间就是**一个存取周期**：该周期内总线控制权与内存使用权交给 DMA，周期结束归还 CPU、外设继续准备下一个数据——这就是**周期挪用（周期窃取）**。
    * 占用总线的那个存取周期里 CPU 并不干等：依靠**指令预取**（若干指令已预取到指令缓冲），只要不访存，CPU 可继续执行主程序，CPU 操作与 DMA 操作并行。
    * 与中断方式相比：数据传送过程不需要保存现场、恢复现场、执行中断服务程序，不需要用软件完成数据输入输出的控制，CPU 效率更高。

## 外部设备的分类与典型设备

* **外部设备的两大部分**

    * 外部设备包括**设备控制器**与外部设备的机电部分；主机通过 I/O 接口向设备控制器传输控制命令，并通过接口读取设备状态（忙、准备好等）。

* **按用途的三大分类**

    * **人机交互设备**：完成"翻译"——把人能识别的信息转换成计算机能识别的信息输入，或把计算机的二进制信息转换成人能识别的文字、图像、声音输出；键盘、鼠标、打印机、显示器属此类。
    * **计算机的信息存储设备**：磁盘、磁带、光盘，既是存储系统的一部分又是外部设备，通过 I/O 接口与主机联系。
    * **机机通信设备**：如调制解调器、网卡，用于计算机之间或计算机与大型/小型设备之间的信息交换。

* **编码键盘（Encoded Keyboard）**

    * > **定义**：常用键盘的一种，把按键排成矩阵，用计数器经行译码、列译码对键盘扫描确定哪个键被按下，计数器输出作为 ROM 地址，ROM 中保存每个键对应的 ASCII 码。

    * 扫描到某键按下时**计数器停止计数**；CPU 通过**中断方式**读入 ASCII 码；读入操作经过一段时间延迟后清除中断标记，并再次启动计数器重新扫描，为下一个字符输入做准备。
    * 鼠标分机械式和光电式两种。

* **显示器**

    * **字符显示器**：早期形态，内含字符发生器，把 ASCII 码转换成字符点阵显示。
    * **图形显示器**：显示**矢量图形**——人工方式或程序画出的、由点线面构成的图形。
    * **图像显示器**：现在绝大多数显示器属此类，照片、视频都可显示。

* **打印机**

    * **击打式**（针式打印机）：把字符点阵通过色带和纸打印出来；分逐字打印与逐行打印，按纸宽分窄行与宽行；并未消失，票据打印机（如出租车发票打印机）就是它。
    * **非击打式**：激光打印机和喷墨打印机两种。

* **A/D 与 D/A 转换**

    * 计算机内部都是数字信号：要控制外部设备或远程传输信号，用 D/A 把数字信号转成模拟信号；接收端用 A/D 把模拟信号转回数字信号。
    * 外部设备的状态信息或对主机的输入若为模拟信号，输入计算机必须经 A/D 转换。

* **终端**

    * 一般由显示器和键盘构成，还带控制机构、缓存等，类似瘦客户机；能完成显示控制、存储、键盘管理及通信控制。
    * 一般不能单独使用，要通过连接线与远程主机连接后才能工作。

* **汉字处理与多媒体**

    * 汉字处理需要三种码：输入用**输入码**，内部存储处理用**内码**，显示输出用**字模码**。
    * **多媒体（Multimedia）**：多种媒体技术和手段相结合进行综合应用，给人更多视听或动作上的感受；关键技术包括数据压缩与解压缩、编码技术、专用芯片、语音识别、图像识别、图片识别等。

## I/O 接口的功能与组成

* **I/O 接口（I/O Interface）**

    * > **定义**：主机和 I/O 设备之间的交界面电路，负责在总线与外部设备之间完成设备选择、数据缓冲、格式与电平转换、命令传送和状态反映。

    * "接口"一词本可用于软件模块间、硬件模块间、软硬件之间（软硬件交界面即计算机系统结构）；此处范围仅指主机与 I/O 设备之间的接口。

* **接口存在的六个原因**

    * 实现设备的选择：主机通过地址确认本次传输和哪个设备进行。
    * 实现数据缓冲：外设类型多样、速度差异大（硬盘快、键盘可能很长时间才输入一个字节），靠缓冲达到速度匹配。
    * 实现数据格式转换：接口与主机间并行传输（一次一个字节或一个字），外设与接口间可能串行传输，要在接口中完成组装或拆解。
    * 实现电平转换：主机与 I/O 设备工作电平不一致，需接口转换使两者协调工作。
    * 传送控制命令：CPU 把控制命令传到接口，由命令控制外部设备工作。
    * 反映状态标志：接口中要有状态标志，标明外设忙闲、是否准备好、有无中断请求。

* **接口的四类总线信号线**

    * **设备选择线**：单向，传输参与本次信息交换的设备码或端口号（设备地址），送入接口中匹配。
    * **数据线**：双向，条数与接口类型有关。
    * **命令线**：来自主机的命令输入接口，经缓冲和译码后控制设备做相应输入输出操作。
    * **状态线**：单向，从接口送到主机，主机借此了解外设忙、准备好还是出错。

* **接口的五大组成模块**

    * **设备选择电路**：逻辑实现就是一个**比较器**，输出本接口的选择信号，只有该信号有效接口才工作。
    * **命令寄存器与命令译码器**：接收并锁存主机命令，译码后配合节拍发生器发出控制信号。
    * **数据缓冲寄存器（Data Buffer Register，DBR）**：完成数据传送的核心；稍加改进即可变成并串转换或串并转换电路。
    * **状态标记**：用一系列触发器实现。
    * **控制逻辑电路**：让前四部分协调地、按时序地工作。

* **状态标记的四个触发器**

    * **完成触发器 D**：$D=1$ 表示准备工作已完成，$D=0$ 表示尚未完成。
    * **工作触发器 B**：$B=1$ 表示外部设备忙，$B=0$ 表示设备已完成工作、是闲的。
    * **中断请求触发器**：中断方式下设备准备好后主动向主机提请求，接口中要有一位标记。
    * **屏蔽触发器**：为 1 时表示尽管设备已完成工作，也不能向主机（CPU）发出中断请求——因为当前主机处理的工作重要性比这次输入输出操作更高。

* **接口的类型划分**

    * 按数据传送方式：**并行接口**与**串行接口**（如 8255 是并行接口芯片，8251 是串行接口芯片）。
    * 按功能选择的灵活性：**可编程接口**（功能和工作方式可编程设置，如 8255）与**不可编程接口**（不能软件设置，但可通过硬联方式改变，典型如 8212）。
    * 按通用性：**通用接口**（把多种类型接口中通用的电路做到一个芯片，如 8255、8251）与**专用接口**（只能用于主机和某一种类型设备连接，如 8279、8275）。
    * 按数据传送的控制方式：程序查询方式不需要接口进行控制，中断方式有中断接口，DMA 方式有 DMA 接口。

## 程序查询方式的流程

* **单设备查询流程**

    * CPU 执行到 I/O 指令，发出启动设备的命令；设备开始准备数据；CPU 检查状态标记看数据是否就绪，未就绪则处于**踏步状态**，循环反复检查，直到设备准备好才开始数据交换。
    * 撑起这个流程只需三条指令：检查状态标记用**测试指令**；判断是否就绪的分支用**转移指令或分支指令**；交换数据用**数据传送指令**、**输入输出指令**或**访存指令**。

* **多设备的查询顺序**

    * 多个设备都通过程序查询方式与内存交换数据时，把设备按**优先级**（轻重缓急）排序：优先级越高的设备被查询到的时间越早。
    * CPU 先查最高优先级设备的状态标记，就绪则处理它与内存的信息交换，未就绪则依次向后检查次优先级设备——查询顺序就是优先级顺序。

* **查询程序的完整步骤**

    * **保存寄存器内容**：查询方式需借 CPU 某寄存器暂存数据，若该寄存器当前数据有用要先保存——可写入内存单元、压入堆栈或挪到其他闲置寄存器。
    * **设置计数值**（控制本次传输数据量），两种方式：要传 $n$ 个字就把计数器设成 $n$，每传一个字减 1，减到 0 结束；或把计数器设成**补码表示的负数**，每传一个字加 1，加到溢出变 0 才结束。
    * **设置存储缓冲区首地址**：保存或读取数据都从这个内存起始地址开始。
    * **启动外设**，让其做数据准备和传输准备。
    * **查询状态标记**，未就绪则踏步等待，就绪后**传送一个字**。
    * **修改初值**：内存地址加 1 或减 1，计数值加 1 或减 1。
    * **判断这批数据是否传完**：未传完则再一次启动外设循环；传完则结束 I/O 传输。

    * > **易错点**：计数值设成正数 $n$ 就往下减，设成补码负数就往上加——修改计数值用加 1 还是减 1，完全取决于当初的设置方式。

## 程序查询方式的接口电路（以输入为例）

* **接口电路的信号连接**

    * 地址线接入设备选择电路，比较相同则选择信号 **SEL** 有效——SEL 是整个接口电路工作的前提。
    * 启动命令与 SEL 同时有效时，接口对状态标记置位/复位：此刻数据未准备好，$D \leftarrow 0$；设备开始工作，$B \leftarrow 1$。

* **数据就绪的过程**

    * $B$ 标记去**启动设备**；设备把数据准备好，经输入数据线保存到 DBR。
    * 设备工作结束，通过设备状态线向接口送"设备工作结束"信号，把 $D$ 置 1（数据就绪）、$B$ 清 0（设备不忙）。

* **CPU 侧的等待与取数**

    * 从启动到 $D$ 变 1 之前，CPU 一直原地踏步查询的就是 $D$；$D=1$ 说明数据已放入 DBR，CPU 经数据线读入，本次输入结束。
    * 真实设计中接口还要对 CPU 命令**锁存**、**译码**，在时序电路控制下按顺序产生一系列控制信号。

## 中断的基本概念

* **中断（Interrupt）**

    * > **定义**：CPU 执行程序过程中发生意外事件或特殊事件时，中断当前程序的执行，转去执行一段中断服务程序处理该事件，处理结束后返回被中断程序的程序断点继续执行原程序的全过程。

    * CPU 在第 $k$ 条指令执行结束时查询并响应中断请求：保存程序断点与中断现场，执行中断服务程序；结束后恢复寄存器内容，从第 $k+1$ 条指令继续执行。
    * 不同时刻、不同设备的中断请求可对应不同（也可相同）的中断服务程序。

* **中断源（Interrupt Source）**

    * > **定义**：主机的外部和内部、CPU 的外部和内部，凡是能够引发 CPU 发生中断的因素。

* **打印机中断的产生过程**

    * CPU 执行主程序中的打印命令启动打印机 → 打印机做打印前准备，**CPU 继续执行原程序** → 打印机准备好可接收数据后向 CPU 发中断请求 → CPU 响应并执行中断服务程序传输数据 → 传送结束 CPU 中断返回继续原程序，打印机执行打印 → 打印缓冲区空了可再接收数据时，打印机再次发中断请求，如此往复。
    * 由此体现中断方式最有价值的一点：**打印机的工作和 CPU 的工作是并行的**。

* **宏观并行、微观串行**

    * 宏观上：设备做数据准备或状态准备时 CPU 仍在执行主程序，CPU 与 I/O 已并行工作——这是中断方式相比程序查询方式最主要的差别。
    * 微观上：CPU 仍要中断现行程序为 I/O 服务，响应请求、执行中断服务程序的那段时间主程序执行是断开的。

## 中断请求的产生与屏蔽

* **中断请求触发器 INTR**

    * 每个采用程序中断方式传输的设备接口中都配置；$Q$ 端为 1 表示有中断请求，沿中断请求线送给 CPU；为 0 表示没有请求。

* **中断屏蔽触发器 MASK**

    * $Q$ 端为 1 表示该中断会被屏蔽掉，为 0（$\overline{Q}$ 为 1）表示开放。
    * 屏蔽的原因：有时计算机正在执行的程序或中断服务程序的重要性比该设备的中断请求更高，此时请求应被屏蔽，不让它发向 CPU。

* **中断请求置 1 的条件**

    * 条件一：数据已经准备好——完成触发器 $D$ 为 1，设备已把数据放入 DBR。
    * 条件二：中断未被屏蔽——MASK 的 $\overline{Q}$ 端为 1。
    * 条件三：CPU 在**指令执行周期结束之前**发出**中断查询信号**，在此信号控制下 INTR 的 $D$ 端输入才送入输出端，请求信号真正产生并沿中断请求线送向 CPU。
    * 三个条件缺一不可；CPU 对中断请求的察觉以一条指令执行完为节拍。

    * > **易错点**：$D$ 为 1 且未屏蔽只是准备好了请求，真正置 1 还要等 CPU 的中断查询信号——请求的"产生"与"被 CPU 察觉"是两个时刻。

## 中断优先级排队

* **中断排队器（Interrupt Arbiter）**

    * > **定义**：在同一时刻多个设备发出中断请求时，从中确定出优先级最高的那一个的电路或机制；经过排队器后只有优先级最高的设备的中断可以被响应。

    * 高速设备优先级要高：不及时响应可能导致高速设备中保存的数据丢失。
    * 排队有两种实现：**软件方式**即查询法排优先级（在表格中规定优先级，从高到低逐个查询）；**硬件方式**又分排队电路集中放在 CPU 内部、分散放在每个接口中两种。

* **链式排队器（菊花链方式）**

    * 每个接口中只有**一个非门、一个与非门**，各级接口的排队电路相互连接构成一条链；优先级自左向右递减（1 ＞ 2 ＞ 3 ＞ … ＞ n）。
    * 记号：$\overline{INTR}_i$ 表示中断请求信号的非，取非端作输入。
    * 行为逻辑：
        * 所有中断源都无请求：每个 $\overline{INTR}_i$ 为 1，每个 $INTp_i'$ 输出都是 1，链上畅通。
        * 设备 1 有请求：$\overline{INTR}_1 = 0$，$INTp_1'$ 保持 1，其后的 $INTp_2'$ 到 $INTp_n'$ 全被清成 0——请求一进链就把后面所有级别封死。
        * 设备 2 有请求、设备 1 无：$INTp_1'$、$INTp_2'$ 为 1，$INTp_3'$ 到 $INTp_n'$ 为 0 并一直向下传递。
    * 输出序列规律：**若干个 1 后面跟着若干个 0**，最后那个 1 的位置就是所有请求源中优先级最高的那一个。
    * 把"最后那个 1"筛选成单路信号的电路：把 $INTR_i$ 与 $INTp_i'$ 做与非操作（两者均为高电平时输出低电平），再经一个非门得到 $INTp_i$；如此 $INTp_1$ 到 $INTp_n$ 中**只有一个值为 1**，它标出优先级最高的请求源。

## 中断向量地址的形成

* **硬件向量法**

    * > **定义**：由硬件产生向量地址、再由向量地址找到中断服务程序入口地址的方法；寻找入口地址的另一种方法是软件查表。

    * 形成向量地址的部件是**中断向量地址形成部件**：输入是排队器的输出——特征是**输入中只有一位为高电平、其余各位都是低电平**；有多少个中断源（中断服务程序）就有多少位输入；输出对应向量地址。
    * 电路属性：输入只有唯一一个 1、输出是一串 0/1 编码——本质上就是一个**设备编码器**。实现上排队器输出 $INTp_i$ 既作为一组**三态门**的输入端又作为其控制端；因只有一个 1，多组三态门中**只有一组有效导通**，把对应编码送上数据线。
    * 向量地址通过**系统总线的数据线**送入 CPU。

* **四个易混概念**

| 概念 | 含义 |
| :--- | :--- |
| 中断号 | 中断的编号，如 8086 支持 256 个中断，编号 0～255 |
| 中断向量 | 可理解为中断服务程序的入口信息；x86 中由段地址和偏移量组成，有时也指程序状态字 |
| 入口地址 | 中断服务程序在内存中的起始地址，可由中断向量生成 |
| 向量地址 | 中断向量所保存的内存单元的地址（"地址的地址"） |

* **中断向量与程序状态字**

    * CPU 发生中断时，一些非体系结构寄存器、或表示程序状态的寄存器无法由指令读取，计算机内部把它们集成一个字，这个字叫**程序状态字**。
    * 中断向量实际是与中断服务程序相关的入口信息：既包括段地址（或偏移量），也包括执行服务程序所需的状态信息。

* **从向量地址到服务程序**

    * 向量地址指向的内存单元里可以存**中断服务程序的入口地址**，也可以存一条**跳转指令**，通过跳转指令跳到服务程序——此时向量地址就是那条跳转指令在内存中的保存地址。
    * 例：向量地址为 12h，表示入口地址（或跳转指令）保存在内存单元 12h 中，其中跳转指令指向的 200 号单元对应打印机的服务程序。

## CPU 响应中断的条件与时刻

* **中断允许触发器 EINT**

    * CPU 内部控制是否允许响应中断的触发器；8086 状态寄存器中的 IF 标志就是它的具体实现：允许中断 EINT 为 1，不允许为 0。
    * 置 1 与清 0 的三条路：**开中断指令**置 1；**关中断指令**置 0；**硬件自动复位**关中断。

    * > **定义**：EINT = 1 是 CPU 响应外设中断请求的必要条件。

* **响应时刻**

    * 一般机器设计中都定在**每条指令执行阶段结束的时候**：CPU 发出查询信号，把有中断请求的接口的中断请求触发器置 1；随后请求值送入排队电路、再送入设备编码器编码。
    * 中断的检查点是**指令边界**，指令执行到一半不理睬中断。

## 中断接口的完整输入链路

* **从启动到取数的全流程**

    * CPU 执行主程序遇输入指令，在数据线上给出设备地址。
    * 设备地址送入接口，设备选择电路与接口地址比对，相同则选中，**SEL 有效**——接口和设备被选中后接口电路才开始工作。
    * CPU 送来的启动/控制命令在接口中译码；**命令与 SEL 同时有效**（缺一不可）才设置触发器 B、D：$B=1$（设备忙、已启动）、$D=0$（数据未准备好），设备开始工作。
    * 设备工作结束，数据送入 DBR：$D=1$（数据就绪，CPU 随时可取）、$B=0$（设备空闲）。
    * 若未屏蔽（MASK 的非端为 1），它与 $D=1$ 一道经与非门、再经非门送到 INTR 输入端。
    * CPU 指令执行阶段结束发中断查询信号，INTR 置 1 并同时启动排队器；排队器输出中只有一个 1，CPU 发出中断响应信号。
    * 形成向量地址，经**数据线**送入 PC；PC 用该地址取出中断服务程序入口地址（或那条跳转指令）；执行中断服务程序把数据取走。

## 中断服务程序的流程

* **保护现场**

    * 包含两项：一是保护**程序断点**——既包括中断返回后要执行的那条指令地址（当前 PC 的值），也包括程序执行状态（不能由指令直接读写的状态，如程序状态字）；这部分由**硬件自动完成**，教材称**中断隐指令**——它并不是一条指令，而是硬件自动执行的一系列操作。
    * 二是保护**通用寄存器（体系结构寄存器）**的内容：中断服务程序里要用到这些寄存器就必须先存原值，因为中断返回后主程序还要用；一般在服务程序中用**进栈指令**保存。

    * > **易错点**：断点 ≠ 只有 PC。PC 里的指令地址和指令读不到的程序状态都算断点，前者连同程序状态由硬件（中断隐指令）保护，服务程序里要用的寄存器内容才由进栈指令保护。

* **中断服务**

    * 不同设备的中断请求服务内容不一样——做什么操作、怎么操作与外部设备直接相关；不同功能的设备编写的服务程序各不相同。

* **恢复现场**

    * 主要指恢复体系结构寄存器的内容：用进栈指令保护的用**出栈指令**恢复；存在内存指定单元的用一系列取数指令取回；机器内有大量寄存器时也可转存到另一些寄存器。
    * 判据只有一条：中断服务之后返回来还能把这些寄存器的值恢复回去，怎么存都行。

* **中断返回**

    * 用**中断返回指令**回到原来被中断程序的断点处。

## 单重中断与多重中断

* **单重中断（Single Interrupt）**

    * > **定义**：CPU 执行中断服务程序的过程中，来了新的中断请求时，不管其优先级多高都不能打断现行中断服务程序的中断方式。

    * 服务程序流程：保护现场（服务程序要用的寄存器压栈）→ 设备服务 → 恢复现场（出栈）→ **最后才开中断** → 中断返回。
    * 从保护现场到恢复现场的整个过程中 EINT 一直为 0，期间来了优先级更高的请求 CPU 也不响应。

* **多重中断（中断嵌套，Interrupt Nesting）**

    * > **定义**：允许优先级更高的中断源打断现行中断服务程序的中断方式。

    * 与单重中断的唯一流程差异：**开中断的位置提前**——保护现场之后马上开中断，设备服务期间允许响应更高优先级请求。
    * 含义：单重中断把整个服务过程当"原子"操作；多重中断把真正不可分割的部分收缩到保护现场和恢复现场这两小段。

* **中断周期**

    * 从指令周期角度看，两种方式进入服务程序前做的事一样：取指令、执行指令，执行结束后查询有无中断请求，有则响应进入**中断周期**。
    * 中断周期排在指令解释过程的执行阶段之后，主要做三件事：**保护断点**；**形成中断服务程序的入口地址**；**关中断**。
    * 这三件事由硬件按一定时序完成，即中断隐指令；中断周期结束、入口地址给出后进入中断服务程序的执行。

## DMA 方式的数据通路与访存方式

* **DMA（Direct Memory Access，直接存储器访问）**

    * > **定义**：在内存与 I/O 设备之间建立直接通路、由 DMA 接口直接控制两者交换数据而不需要 CPU 作为中间媒介的传送控制方式，也不需要中断现行程序的执行。

    * 数据通路差异：程序查询/程序中断方式下，主存与 I/O 之间的信息必须先经过 CPU 中的某个寄存器（模型机为 ACC）作缓冲再转存；DMA 方式下主存直接与 DMA 接口相连，直接成块传送。
    * 即使在中断方式中，真正的数据传输过程仍需要 CPU 执行程序来完成——中断只把 CPU 从"等待数据准备"里解放出来，搬运数据这步仍要亲自动手。

* **停止 CPU 访存**

    * > **定义**：外设要与内存交换数据时，从这块数据的第一个字开始 CPU 就放弃总线控制权和对内存的访问、把两者交给 DMA 接口的方式。

    * 控制上最简单，适合大量数据的传输。
    * 缺陷：数据是一个字一个字在主存与外设间走的，传输间隔可能超过一个存取周期——间隔期间 DMA 并未真正使用内存却依然占着访问权，CPU 无法利用这段时间访存，**不能充分发挥 CPU 对主存的利用率**。

* **周期挪用（周期窃取，Cycle Stealing）**

    * > **定义**：DMA 接口准备好数据传输时，通过申请建立总线使用权，占用一个或几个**存取周期**完成传输；传输间隔或数据准备阶段放弃内存使用权和总线占用的方式。

    * DMA 访问主存的三种可能：

| 时刻 CPU 的状态 | 处理办法 |
| :--- | :--- |
| CPU 不访存 | 存储器使用权与总线使用权直接分配给 DMA |
| CPU 正在访存，处在某个存取周期的中间阶段 | DMA 不能抢占，必须等这个周期结束 |
| CPU 与 DMA 同时请求访存 | DMA 优先，CPU 让出总线控制权和内存访问权 |

    * 同时请求时 DMA 优先的原因：DMA 上连接的都是**高速设备**，不及时响应可能造成数据丢失。
    * 好处：数据准备过程中 CPU 可利用间隙完成访存，**存储器和总线的利用率更高**——现代计算机中最影响机器效率和速度的就是主存储器（存储墙，memory wall 问题）。

* **交替访问**

    * > **定义**：把 CPU 的工作周期分成 C1、C2 两部分，C1 专供 DMA 访存、C2 专供 CPU 访存的方式。

    * 使用权在固定时间点上固定，DMA **不需要提出申请、建立总线控制权**，传输速度较快、控制简单。
    * 边界：这种方式**实用性并不是非常强**。

## DMA 接口的功能与组成

* **DMA 接口的五项功能**

    * **申请总线与内存**：数据传送前向 CPU 提出总线和内存的占用请求。
    * **接管控制权并控制传输**：CPU 允许后处理控制权转交，转交完真正控制、管理总线和内存并控制数据传输。
    * **确定传输方向**：数据是从内存写到外设还是从外设读入内存。
    * **定位与计数**：传成块数据时要知道内存首地址、数据块长度、设备地址；每传完一个字修改内存地址和数据长度——改长度是为判定数据块传送是否结束。
    * **报告完成**：传输结束后给出操作完成信号，使 CPU 能做进一步处理。

* **地址寄存器 AR**

    * CPU 预置内存首址（输出数据从内存哪个地址取、输入数据从内存哪个地址存）；AR 通过**地址线**把访存地址送给主存——DMA 接口接管了总线、接管了主存。每完成一个字的输入输出 AR 加 1（从低地址向高地址推进）。

* **字计数器 WC**

    * > **定义**：记录传输数据量（字数，word counter）的计数器。

    * 设数据单位与编址单位相同、数据从首地址开始存取并采用补码方式：WC 保存 $-N$（$N$ 为要传输的数据数量），每传输一个数据加 1，加到 0 表示传完。

* **数据缓冲寄存器 BR**

    * 外设输入的数据或主存输出的数据都暂存在这里，外部设备与 BR 直接相连。

* **设备地址寄存器 DAR**

    * 作用一：供设备选择电路使用，判断本次访问的设备是否是本接口当前连接、归此 DMA 接口管理的设备。
    * 作用二：访问硬盘这类设备时，DAR 里还可保存**柱面号、磁道号、扇区号**，供传输过程中确认数据地址。
    * AR、WC、DAR 的初值都由 CPU 通过**数据线**预置；数据的输入输出也走数据线。

* **DMA 控制逻辑**

    * 控制接口内部协调工作，按给定时序发出给定信号——如向 CPU 发 DMA 请求、向主存发读写控制命令。
    * 联络信号两对：外设向 DMA 控制逻辑发请求信号 **DREQ**（设备请求），DMA 控制器对设备给应答信号；DMA 要占用总线、接管主存控制权时通过总线向 CPU 发总线使用请求，CPU 给出应答信号由 DMA 控制器接收。

* **中断机构**

    * DMA 接口里仍有中断机构，用途是**数据传输完成之后的后续处理**：WC 计到 0 表示传输结束时，向中断机构发信号把中断请求触发器置 1；一条指令执行结束后由中断机构向 CPU 发中断请求，由 CPU 做传输后的处理。

    * > **提示**：DMA 接口的组成和功能一一对应——要申请总线所以有 DMA 控制逻辑与请求/应答信号，要定位计数所以有 AR、WC、DAR，要暂存所以有 BR，要做传输后处理所以有中断机构。
