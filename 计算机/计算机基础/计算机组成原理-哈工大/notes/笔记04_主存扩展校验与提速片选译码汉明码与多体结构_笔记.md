# 主存扩展、校验与提速：片选译码、汉明码与多体结构

## 存储器容量扩展与片选设计

### 扩展连线的四步法

* **扩展四步法（含画图共五步）**

    * > **定义**：CPU 与存储芯片连接题的固定解题流程——① 写出对应的二进制地址码；② 根据地址范围确定芯片的种类和数量；③ 分配地址线（哪些作芯片地址输入、哪些作片选信号）；④ 确定片选逻辑；⑤ 画出连接图。

* **地址范围规律**

    * > **定义**：容量为 $2^n$ 个单元的存储区域，其地址范围是低 $n$ 位地址从全 0 连续变到全 1，高位保持不变。

    * $n$ 位二进制地址每一位有 0、1 两种取值，各位之间相乘共构成 $2^n$ 个存储单元；反之要实现 $2^n$ 个单元的区域，就要占用 $n$ 位地址。

    * 相邻区域的起始地址 = 前一区域末地址加一；连续等大的区域靠高位逐段累加来切分。

* **地址线按位相连**

    * CPU 地址线与芯片地址线相连时必须高位接高位、低位接低位，按高低位顺序依次相连。

* **MREQ 必须参与片选**

    * $\overline{\text{MREQ}}$ 是访存控制信号、低电平有效——只有它有效时 CPU 访问的才是内存，所以它必须包含在片选输入信号当中。

* **地址线不能遗漏**

    * > **易错点**：对任何一个芯片来说，CPU 的地址线要么输入到这个芯片当中，要么一定要出现在片选的输入端，一根地址线都不能有遗漏。

    * 片选信号里的地址信号加上芯片输入的地址信号，合在一起必须等于全部地址信号。

* **ROM 与 RAM 接线差异**

    * ROM 只读、不能写：编程引端接地使其处于工作状态（而非编程状态），数据单向、只能输出。

    * RAM 数据双向，既可输入也可输出，需接读写命令信号。

* **扩展实例：4K ROM 加 8K RAM**

    * 16 根地址线寻址 64K：最小 4K 为系统程序区（地址 0000H～0FFFH，A0～A11 从全 0 变全 1），用一片 4K×8 ROM；相邻 8K 为用户程序区（1000H 起连续 8K），可用两片 4K×8 RAM——两片各自有片选信号，不是位扩展或字扩展拼成的一组。

    * 地址线在 A11 与 A12 之间划开：A0～A11 送每个芯片，A12、A13、A14 作 74138 的 C、B、A 输入；A15 与 $\overline{\text{MREQ}}$ 参与控制端。

    * 若改用一片 8K×8 RAM：A0～A12 直接作芯片地址输入（在 A12 与 A13 之间划开），高位 A13～A15 连同 $\overline{\text{MREQ}}$ 进片选逻辑，由译码器一路输出直接选中。

### 74138 译码器与片选逻辑

* **74138（三八译码器）**

    * > **定义**：三个编码输入端 C（高位）、B、A（低位）对应 000～111 八种输入组合，每种组合下输出端 $\overline{Y_0} \sim \overline{Y_7}$ 中恰有一个输出有效电平，输出低电平有效。

    * 使能条件：$G_1\,\overline{G_{2A}}\,\overline{G_{2B}} = 100$，即 $G_1$ 接高电平、$\overline{G_{2A}}$ 与 $\overline{G_{2B}}$ 接低电平。

    * 用途：CPU 用不到的闲置高位地址线正好组合起来接 $CBA$ 端，产生唯一的片选信号；片选 $\overline{CS}$ 低电平有效，恰好与 $\overline{Y_i}$ 低有效匹配。

* **选译码输入端的原则**

    * 三个译码输入端必须保证其取值在各个地址区域中各不相同，才能唯一地决定芯片的选择；恒为 0 的地址线区分不出区域，不能当译码输入。

* **闲置引脚的处理**

    * CPU 没用到的引脚（如恒 0 的高位地址线、$\overline{\text{MREQ}}$）一定要参与 74138 的控制端；控制端有缺口时用外接 $V_{CC}$ 高电平或接地补齐，具体接法可有多个方案，原则只有一个。

* **片选逻辑的灵活性与铁律**

    * 题目不指定必须用译码器时，可用学过的数字逻辑自行画片选逻辑，不必拘泥于 74138。

    * 无论怎么画，铁律不变：地址线不能遗漏、$\overline{\text{MREQ}}$ 必须参与片选。

* **选芯片要为连线服务**

    * 同样拼出 4K×8 的 ROM 区，两片 2K×8 与两片 4K×4 片数相同：2K×8 只占用 $A_0 \sim A_{10}$，$A_{11}$ 没被 ROM 用到、必须额外参与 ROM 的片选，连线麻烦；两片 4K×4 串联（位扩展）后与 RAM 统一占用 $A_0 \sim A_{11}$，连线最简。

* **2K×8 方案的片选合成**

    * 两片 2K×8 ROM 各自独立并联时，$\overline{Y_0}$ 有效且 $A_{11}=0$ 才选 ROM1（$A_{11}$ 与 $\overline{Y_0}$ 同进或门，两个 0 出 0）；$A_{11}$ 经非门取反后与 $\overline{Y_0}$ 同进或门选 ROM2。

    * 或门"有 1 出 1，全 0 出 0"，低电平有效信号靠"全 0 出 0"产生。

### 模块板结构存储器

* **模块板结构**

    * > **定义**：存储器系统分三层组织——整个系统由若干块模块板组成，每块板由若干 RAM 芯片组成，芯片内部还有自己的单元编址。

* **最大主存空间**

    * > **定义**：最大主存空间 = $2^{\text{地址码位数}} \times$ 存储字长。

    * 字长 8 位、地址码 18 位的机器：$2^{18} \times 8$ 位 = 256K×8 位 = 256K 字节——同一容量的三种写法要会换算；没有特殊说明时机器字长 = 存储字长 = 指令字长。

* **分层容量拆算**

    * 板数 = 总容量 ÷ 每板容量（如 256K×8 ÷ 32K×8 = 8 块）；每板片数 = 板容量 ÷ 单片容量（32K×8 ÷ 4K×4 = 16 片）。

    * 总片数两种算法互相验算：板数 × 每板片数，或总容量 ÷ 单片容量。

* **主存地址格式三段切分**

    * "CPU 如何选择模块板"的本质是主存地址格式设计：18 位地址从高到低拆成模块号（选板）、组号（选板内芯片组）、片内地址（选组内单元）三段。

```text
| 模块号 3 位 |  组号 3 位  | 片内地址 12 位 |
  选第几块板    选板内第几组   选组内第几个单元
```

    * 模块号位数由模块板个数决定（8 块板 → 3 位）；片内地址位数由单片容量决定（4K = $2^{12}$ → 12 位）；剩余一段用减法核对。

    * > **易错点**：板内 16 片 4K×4 芯片不是每片单独占一个编号——机器一次要访问 8 位数据，一片只能出 4 位，必须两片并成一组 4K×8 一起被选中，这就是位扩展。"片号"实际选的是"组"，位数按组数（8 组 → 3 位）取，直接给 16 片分 4 位是错的。

### 连接题的故障分析

* **片选恒有效的三情形**

    * 现象：不论往哪片 RAM 写入数据，某片（以 A000H 为起始地址的那片）总有与之相同的数据——该片片选 $\overline{CS}$ 恒为低电平、总处于被选中状态。

    * 在芯片与译码器本身完好的前提下，三种可能：$\overline{CS}$ 与 $\text{R}/\overline{\text{W}}$ 错连或短路（写操作时 $\text{R}/\overline{\text{W}}$ 为低电平）；$\overline{CS}$ 与 $\overline{\text{MREQ}}$ 错连（同为低电平有效）；$\overline{CS}$ 直接接地。

    * 排查思路：从现象 → 哪个信号出问题 → 该信号怎么会恒有效，倒着推回去。

* **高位地址线断线的后果**

    * 地址线 $A_{13}$ 与 CPU 断线并搭到高电平上：译码器 A 端恒为 1，$CBA$ 只剩 001、011、101、111 四种取值，只能访问 $A_{13}=1$ 的那一半地址空间对应的芯片。

    * $A_{13}=0$ 的另一半地址空间对应的芯片永远不可能被访问——一根参与译码的高位地址线断了，整个存储器凭空丢一半。

## 存储器校验与汉明码

### 校验的必要性与检错纠错原理

* **为什么要校验**

    * 内存是电子设备：动态 RAM 信息保存在电容中、静态 RAM 保存在双稳态触发器中，复杂电磁环境或空间带电粒子打击可能造成电容充放电、触发器翻转，信息出错。

    * 存储器里保存的是程序代码和数据，不校验则轻则程序失效、重则灾难性后果；从星载机、弹载机、舰载机、车载计算机到台式机、笔记本、手机，保存的信息都采用校验技术。

* **代码集**

    * > **定义**：代码指合法代码的集合——计算机中保存或传输的代码里哪些是合法的；不在这个集合中出现的代码即可确认出错。

* **五个代码集的检错纠错实验**

| 合法代码集 | 检错能力 | 纠错能力 |
| :--- | :--- | :--- |
| 000～111 全体 | 无 | 无 |
| 偶校验四码（000/011/101/110） | 检一位错 | 不能定位、无法纠 |
| 三倍冗余（000/111） | 检一位错 | 纠一位错 |
| 四倍冗余（0000/1111） | 检两位错 | 纠一位错 |
| 五倍冗余（00000/11111） | 检两位错 | 纠两位错（检不出三位错） |

    * 一位错的概率最大（甚至超过 90%），错位数越多的错误出现概率越小——纠错按概率就近归属合法代码：收到 110 时直接纠成 111，而不认为 000 发生了两位错。

* **编码最小距离**

    * > **定义**：编码最小距离 $L$ 指合法代码集中任意两组合法代码之间二进制位数差异的最小值，即把一个合法代码变成集合中另一个所需改变的最少二进制位数。

    * $L$ 越大检错纠错能力越强，数量关系为 $L - 1 = D + C$，其中 $D$ 是可检测错误的位数、$C$ 是可纠正错误的位数，通常 $D \geq C$。

    * 汉明码就是具有一位纠错能力的编码，其最小距离为 3。

### 汉明码的编码

* **汉明码（Hamming Code）**

    * > **定义**：以奇偶校验为基础的分组校验编码，采用非划分式分组——组和组之间有交叉，有些位属于多个组、有些位只属于一个组。

    * 普通奇偶校验加上一位校验位后只能发现有一位翻转、不知道哪位错；划分式分组（组间无重叠、各组数据位合起来就是原数据）只能缩小出错范围；汉明码靠交叉分组把出错位置精确指出来。

* **交叉分组结构**

    * 各校验位 $c_i$ 按"位置的二进制编码"分组：$c_1$ 管右起第一位为 1 的位置（1、3、5、7……），$c_2$ 管右起第二位为 1 的（2、3、6、7……），$c_4$ 管右起第三位为 1 的（4、5、6、7……），$c_8$ 管右起第四位为 1 的，依此可排到 $c_{16}$、$c_{32}$、$c_{64}$。

    * 分组表的三条性质：每一组都有一个独占位置（正是该校验位所在位置）；任何两组有一个为它们共有、其他组没有的位置（位置编码中那两位为 1、其余为 0）；任何三组亦然——纠错全靠这三条性质。

* **汉明码三要素**

    * 检测位位数：信息位 $n$ 位、检测位 $k$ 位时需满足 $2^k \geq n + k + 1$——$k$ 位检测结果要能区分 $n+k$ 位中哪一位错以及"无错"，共 $n+k+1$ 种状态。

    * 检测位位置：第 $i$ 组（$i$ 从 1 数起）的校验位放在 $2^{i-1}$ 位置，即 1、2、4、8……（组号从 0 数起即 $2^i$）——校验位只校验本组，不会与其他组共有该位置。

    * 检测位取值：无特殊说明一律按偶校验，让所在小组中 1 的个数为偶数。

* **编码示例**

    * 0101 按偶校验：$n=4$，由 $2^k \geq n+k+1$ 得 $k=3$；位置 1、2、4 放校验位，3、5、6、7 放信息位；三组分别凑偶得 $c_1=0$、$c_2=1$、$c_4=0$，汉明编码 0100101。

    * 0011 按偶校验：同样分三组，得 $c_1=1$、$c_2=0$、$c_4=0$，汉明编码 1000011。

    * 校验位取值可用"搬家法"或异或法——两者是一回事：异或结果为 0 说明该组 1 的个数已是偶数，为 1 说明是奇数。

### 汉明码的纠错

* **纠错协议与 P 值**

    * 收发双方要有协议：数据按汉明码、偶校验方式编码；接收方按数据位数判断分组数，对每组做按位加（异或）得一个 $P_i$，$P$ 的个数与检测位个数相等。

    * 偶校验下组内无错则 $P_i = 0$；把各组结果按组序排成二进制数，其十进制值就是出错位号，全 0 表示没有出错——校验结果要么指出某一个位置出错、要么指出没有错。

* **纠错示例**

    * 收到 0100111：$P_1=0$、$P_2=1$、$P_4=1$，$110_2 = 6$——错在第二、三组共有的位置 6（位置 7 虽也是二、三组公共位置，但它还属第一组，若 7 错则 $P_1$ 应为 1）；把第六位改过来，取位置 3、5、6、7 四位得原信息 0101。

    * 收到 0101101：只有第三组 $P=1$，错在第三组独占的位置 4——该位置正是校验位，可以不去纠，因为对接收方有用的不是校验位，校验位最终要去掉。

* **奇校验配置**

    * 分组方式、校验位位置完全相同，只是校验位添入后要使每组中 1 的个数为奇数个；其纠错过程与偶校验配置的差别可按同一思路推导。

## 提高访存速度

### 存储墙与三条路线

* **存储墙（memory wall）**

    * > **定义**：CPU 速度提升远快于存储器造成的性能鸿沟，是影响计算机性能的主要因素之一。

    * 数据：1985 到 2002 年，因采用 RISC 技术，CPU 速度约每年提升 52%（指数式）；而内存大约每经过 10 年，访问延迟才降为原来的一半。

    * CPU 执行程序需要的指令、数据、运行结果都要经过内存，存储器慢则 CPU 得不到指令和数据、只能空等。

* **三条提速路线**

    * 采用更高速的器件（速度更快、带宽更大、延迟更小）；采用 Cache 层次结构（小容量高速缓存放在 CPU 与主存之间）；调整主存结构（单体多字、多体并行、高性能芯片）。

### 单体多字结构

* **单体多字**

    * > **定义**：把存储器的存储字长加宽，使一次访存取出多个机器字的结构。例：CPU 字长 16 位、存储字长 64 位，一次访问取出四个机器字，可增加存储器带宽。

    * 取出的多个字先放数据寄存器，下次使用时直接从寄存器取走。

    * 问题一：写 16 位单字长数据时，另外 48 位也会被写入给定存储单元、造成错误修改；要支持单字长写入需存储器内部用硬件专门实现，存储器会变复杂。

    * 问题二：取出的四个字若不含所需信息（如第一条指令就是跳转范围很大的跳转指令），其余全部浪费。

    * 根子在于：一个存储单元中的多个机器字以整体方式存取。

### 多体并行系统

* **多体并行**

    * > **定义**：由多个独立存储体构成的并行存储系统，每个体都有自己的控制电路（自己的 MAR、MDR、地址译码器、读写控制），具备并行工作的基础；按编址方式分高位交叉与低位交叉两种。

* **高位交叉编址**

    * > **定义**：地址按体顺序编制——编完一个存储体的全部单元再编下一个体，地址高位是体号、低位是体内地址。

    * 程序按序存储，指令顺序执行时只有一个体被 CPU 不停访问、其余体全部空闲——并行基础用不上。

    * 用高位选体、低位寻址本质上就是存储器容量扩展（字扩展）：适合扩容，不适合提高带宽。

* **低位交叉编址**

    * > **定义**：地址横向轮流编制——相邻地址分属相邻的体，地址低位是体号、高位是体内地址；体号编在地址最低位上正是"低位交叉"名字的由来。

    * 程序按序存储使连续指令分布在连续的体中；CPU 在一个存取周期开始时给出地址，被访体把内部地址与读写命令锁存后自己完成操作，同一存取周期内 CPU 还可轮流向其余体发出访问——即分离式通讯。

    * 流水访问：把存取周期 $T$ 分成四段、每段恰为一个总线传输周期 $\tau$，各体错开 $\tau$ 依次启动，需满足 $T = 4\tau$。

    * 连续读 $k$ 个字所需时间为 $T + (k-1)\tau$——第一个字耗时 $T$，之后每过一个 $\tau$ 完成一个读取操作。

    * 体号判定：地址对体数取余，余数即体号（八体中 RAM1 范围内所有地址对 8 取余恒为 1）。

    * > **结论**：低位交叉在不改变存取周期的前提下增加存储器带宽；高位交叉用于容量扩展，低位交叉用于带宽与访问速度的提高。

```text
         ├────────── 一个存取周期 T = 4τ ──────────┤
M0: 启动 ········································· 完成，数据送 CPU
M1:      启动 ···································· 完成
M2:           启动 ······························· 完成
M3:                启动 ·························· 完成
         τ            τ            τ            τ
```

* **八体低位交叉存储器设计**

    * 64K 字节分八体、低位交叉编址：每体 64KB ÷ 8 = 8KB，即八片 8K×8 位 RAM；芯片引脚有 $\overline{OE}$ 允许读（低有效，接 CPU 的 $\overline{RD}$）、$\overline{CS}$ 片选、$\overline{WE}$ 允许写（接 $\overline{WR}$）。

    * 地址格式：低 3 位 $A_2A_1A_0$ 是体号（固定为体的编号 000～111），高 13 位 $A_3 \sim A_{15}$ 是体内地址（从全 0 变全 1）——编址变化从 $A_3$ 开始而不是 $A_0$，与常规扩展题不同。

    * 连线：CPU 的 $A_3$ 接每片芯片的地址引脚 $A_0$、$A_{15}$ 接芯片 $A_{12}$，必须高位接高位、低位接低位——不能按编号同名相连。

    * 片选：$A_2A_1A_0$ 接 74138 的 C、B、A（C 为高位），$\overline{Y_0} \sim \overline{Y_7}$ 依次作 RAM0～RAM7 的片选；访存信号 $M/\overline{IO}$ 高电平访存，可直接接 $G_1$、$\overline{G_{2A}}\overline{G_{2B}}$ 接地，或经非门取反接 $\overline{G_{2A}}\overline{G_{2B}}$、$G_1$ 外接 +5V。

    * 各片地址范围：RAM0 为 0000H～FFF8H、RAM1 为 0001H～FFF9H……RAM7 为 0007H～FFFFH，首末地址逐体加一，各个体的地址范围不连续。

    * 控制信号形态：$M/\overline{IO}$ 高电平访存、低电平访问 I/O；$\overline{WR}$ 写命令与 $\overline{RD}$ 读命令各自独立、低电平有效，不共用一根信号线。

* **八片 8K×8 顺序扩展的地址范围**

    * 八片 8K×8 RAM 按高位 $A_{15}A_{14}A_{13}$ 译码选片（占满 $CBA$ 全部八种组合），低 13 位 $A_0 \sim A_{12}$ 作片内地址，16 位地址空间恰好用满：

| 芯片 | 高三位 | 起始地址 | 终止地址 |
| :--- | :--- | :--- | :--- |
| RAM0 | 000 | 0000H | 1FFFH |
| RAM1 | 001 | 2000H | 3FFFH |
| RAM2 | 010 | 4000H | 5FFFH |
| RAM3 | 011 | 6000H | 7FFFH |
| RAM4 | 100 | 8000H | 9FFFH |
| RAM5 | 101 | A000H | BFFFH |
| RAM6 | 110 | C000H | DFFFH |
| RAM7 | 111 | E000H | FFFFH |

### 高性能存储芯片

* **SDRAM（同步动态 RAM，Synchronous DRAM）**

    * 之前的动态 RAM 芯片采用异步方式通讯，读写时序中没有同步时钟信号；SDRAM 要求 CPU 与存储器在给定的时间点开始或完成给定操作，存储器速度与 CPU 保持一致、CPU 不需等待——前提是芯片本身速度足够快。

* **RDRAM**

    * Rambus 公司开发的 RAM，主要解决存储器的带宽问题。

* **CDRAM（带 Cache 的 DRAM）**

    * > **定义**：片内集成 Cache 的 DRAM 芯片，用一行缓存加速后续访问。

    * 存储阵列标称 $2048 \times 512 \times 4$：实际 2048 行 × 2048 列，列分成 4 组、每组 512 列；行地址 11 位寻址 2048 行，列地址 9 位译码出 512 个列选信号，每个列选信号选中分属 4 组的 4 列。

    * 片上 Cache 容量 $512 \times 4$，正好缓存住一行的数据。

    * 工作方式：把本次访问的行地址与上一次比较——相同则该行已在 Cache 中，用列选信号直接读 Cache；不同则把新的一行写入 Cache 备用。

    * 特别适合突发式读取：读第一个数据要从存储阵列读、速度较慢；后续数据已缓冲到 Cache，读取非常快。

## 寻址范围与主存地址格式

* **寻址范围**

    * > **定义**：寻址范围指可以访问到的字数或字节数——按字编址问能访问的字数，按字节编址问能访问的字节数。

* **按字节编址**

    * 存储容量 64K 字节的机器按字节编址可找到 64K 个字节，地址从 0 连续编到 $2^{16}-1$，即 0～65535。

* **按字编址**

    * 存储字长 32 位即 4 个字节，寻址范围 = 64K 字节 ÷ 4 = 16K 个字；14 位字号恰好覆盖 $0 \sim 2^{14}-1$。

* **字地址与字节地址的分配**

    * 以高位字节地址为字地址时：每个字占 4 个字节，字地址取该字最高（最左）字节的编号——0、4、8……65532，所有字地址都是 4 的整数倍，说明字地址与字长有关。

    * 末行字地址可倒推：最后一个字节是 65535，往前推到高位字节就是 65532。

* **主存地址格式**

    * 主存地址必须最小化到字节这一最小寻址单位：高位是字号（指出第几个字），位数由字数决定——16K = $2^{14}$ → 14 位；低位是字内地址（指出字内哪个字节），位数由一个字的字节数决定——4 字节 → 2 位；合计 16 位。

```text
|      字号（14 位）       | 字内地址（2 位） |
|  寻址 16K = 2^14 个字   |   4 选 1 个字节  |
```

    * 字内字节编号：高位字节 00、第二字节 01、第三字节 10、第四字节 11。

    * > **易错点**：寻址范围只与"总容量 ÷ 最小寻址单位"有关——按字节编址是 64K，按字编址是 64K 字节 ÷ 4 字节 = 16K；而主存地址位数按字节这一最小寻址单位设计，字号的位数由字数决定、字内地址的位数由一个字含几个字节决定，两件事分开算。

## 高速缓冲存储器

### Cache 的定位与局部性原理

* **高速缓冲存储器（Cache）**

    * > **定义**：位于 CPU 和主存之间的小容量高速存储器，用静态 RAM 做成，容量小、速度高（主存则容量大、速度低），用来缓解 CPU 空等问题。

* **程序访问的局部性原理**

    * > **定义**：程序执行过程中指令和数据使用呈现的规律，是 Cache 能充分发挥作用的前提，分时间与空间两方面。

    * 时间局部性：当前正在使用的指令和数据，在不久的将来还会被使用到——应放进 Cache，再用时直接从 Cache 取。

    * 空间局部性：当前正在使用某个指令或数据，不久的将来相邻的指令和数据就可能被用到——调块时要连同相邻信息一起放入。

    * 空间局部性直接指出 Cache 与主存的数据交换单位是**一块**，块中既包括正在使用的、也包括相邻的指令和数据；块的大小通过实验确定。

### 块、标记与命中

* **按块组织**

    * 主存和 Cache 都分成大小相等的块：主存 $M$ 块、Cache $C$ 块，$C$ 远小于 $M$，主存中只能有部分块被缓存到 Cache。

    * 主存地址分成主存块号与块内地址两部分，块内地址的位数决定块的大小（块含 16 字节、编址单位为字节 → 块内地址 4 位）；Cache 地址同样分缓存块号与块内地址。

* **块内地址无需变换**

    * 主存块与 Cache 块大小相同、块间整块传送、块内字节顺序不变，所以主存地址的块内地址部分与 Cache 地址的块内地址部分值完全相同、不需任何转化。

    * Cache 不需要一套独立形成的地址：块内地址部分直接共用，缓存块号由地址映射与变换机构查出。

* **标记（tag）**

    * > **定义**：Cache 块上记录主存块号的存储区域，标识主存块与 Cache 块之间的对应关系。

    * 主存块调入 Cache 时把该主存块号写入标记；CPU 访问时拿地址中的主存块号与各 Cache 块的标记比较，与某一标记相等且该块有效，即可从 Cache 直接获取。

* **命中与不命中**

    * 命中：要访问的块已调入 Cache，能直接在 Cache 中取到数据或指令；不命中：块未调入，必须到主存中获取。

### 命中率与访问效率

* **命中率**

    * $$h = \frac{n_1}{n_1 + n_2}$$

    * $n_1$ 为在 Cache 中访问到数据或指令的次数，$n_2$ 为未访问到、到主存中才找到的次数。

* **影响命中率的因素**

    * Cache 容量：越大命中率可能越高——极端情况 Cache 与内存一样大时，除第一次访问外全命中。

    * 块长：太小没充分利用局部性（没执行几条指令块内信息就用光，还要再取下一块）；太大则 Cache 能容纳的块数变少，且大块中可能只有部分信息对 CPU 有用、其余白占空间。一般取 4～8 个字。

    * 块的大小与一个存取周期内能从内存调出的信息长度有关：Cray-1 内存 16 体交叉、每体存一个字，块长 16 个存储字；IBM 370 四体交叉、存储字 64 位，块长 4 字即 256 位。

* **访问效率**

    * $$e = \frac{t_c}{h \cdot t_c + (1-h) \cdot t_m} \times 100\%$$

    * $t_c$ 为 Cache 访问时间、$t_m$ 为主存访问时间；分母是平均访问时间——命中概率乘 Cache 时间加不命中概率乘主存时间。

    * 该公式成立的前提是访问 Cache 和访问主存**并行**进行（不命中时 Cache 与主存同时被访问）；若改为串行——先查 Cache、不命中再访主存——平均访问时间变为 $t_c + (1-h)t_m$，效率变为 $e = \dfrac{t_c}{t_c + (1-h)\,t_m} \times 100\%$，同样命中率下效率更低。

    * 边界：$h=0$ 时效率最小为 $\dfrac{t_c}{t_m}$；$h=1$（次次命中）时效率最大为 1。

### Cache 的基本结构

* **三大部件**

    * Cache 存储体：信息以块为单位保存在其中。

    * 地址映射与变换机构：**映射**给出规则——主存的一个块可以放到 Cache 的哪一个或哪些块中；**变换**把主存块号转换成相应的 Cache 块号（或把主存地址转换成 Cache 地址）。

    * 替换机构：允许装入的位置已满而新块又要调入时，调用替换算法决定哪一个块退出（写回主存或直接作废），把新块写入让出的位置。

* **直接通路**

    * 主存和 Cache 之间有一条直接通路，完成主存与 Cache 之间的整块信息传送。

    * 有些计算机为进一步提速：发现不命中时先把所需数据直接送 CPU，同时该块在 Cache 与主存之间传送，两件事同时做。

* **读操作流程**

    * CPU 发出访存地址 → 映射变换机构判断是否命中：命中则从 Cache 直接取出信息送 CPU。

    * 不命中则两条路都要走：访问主存取出信息送 CPU；同时判断该内存块允许放入的 Cache 块是否已满（与映射方法有关，不一定整个 Cache 满）——未满直接调入，已满启用替换算法腾出位置后调入。

### 写策略

* **一致性问题**

    * Cache 是主存中某些块的缓存，读操作不修改任何信息、主存与 Cache 天然一致；写操作只写 Cache 不写主存就会造成两者不一致——写策略要解决的核心就是一致性。

* **写直达（write through）**

    * > **定义**：写操作时把操作数同时写入 Cache 和主存的写法，写的时间就是写主存的时间。

    * 时刻保持 Cache 与主存一致，块从 Cache 退出时不需要再写回主存。

    * 缺点：CPU 对同一内存单元反复写时（如累加求和程序反复更新同一单元的和），造成 Cache 与主存之间频繁的信息交换。

* **写回法（write back）**

    * > **定义**：写操作只写 Cache、主存内容暂不更新，允许一段时间内两者不一致，直到该 Cache 块退出 Cache 时才写回主存。

    * 缺点：多处理器系统中同一主存块在各处理器的 Cache 中都有副本，写回时机不同导致副本之间的一致性问题——这是并行计算机系统结构要研究的问题。

| 对比项 | 写直达（write through） | 写回法（write back） |
| :--- | :--- | :--- |
| 写入时机 | 同时写 Cache 和主存 | 只写 Cache，块退出时才写回主存 |
| 一致性 | 时刻保持一致 | 允许一段时间内不一致 |
| 块退出时 | 不需要再写回主存 | 需要把块写回主存 |
| 缺点 | 同一单元反复写时频繁交换信息 | 副本一致性难保证（多处理器场景） |

### Cache 的改进

* **分级 Cache**

    * 离 CPU 近的 Cache 直接做在 CPU 当中（片内 Cache，内部可再分两级），主板上、CPU 外面再做更大容量的 Cache。

    * 现代多核处理器每个核有自己的 Cache、多个核还有共用 Cache，很多处理器至少有三级 Cache。

* **统一缓存与分立缓存**

    * 冯·诺依曼结构把指令和数据以同等方式保存，对应**统一缓存**——指令和数据放在同一个 Cache 中。

    * 现代机器常把指令 Cache 与数据 Cache **分开**（分立缓存），以避免流水过程中造成资源冲突，如 MIPS 计算机。

    * 实例：Pentium 指令 8K Cache + 数据 8K Cache；PowerPC 620 为 32K 指令 Cache + 32K 数据 Cache。
