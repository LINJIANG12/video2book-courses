# DMA 方式：从接口雏形到工作全流程

## DMA 传送的三段流程

### 预处理

* **预处理（Preprocessing）**

    * > **定义**：数据传输开始前，CPU 通过几条输入输出指令完成的参数设置，设置完毕后启动设备，设备开始准备数据（或做状态准备）之后才能开始真正的传输。

    * 设置的四项信息：**传输方向**（输入还是输出，是内存到 I/O 还是 I/O 到内存）、**设备地址**（和哪一个设备传输）、**主存地址**（主存哪个地址与设备交换）、**数据量**（传输的数据量有多大）。

### 数据传送

* **数据传送（Data Transfer）**

    * > **定义**：预处理完成后，由 DMA 接口控制完成**一批**数据的传送，真正的输入输出操作不经 CPU。

    * 预处理结束后 CPU 继续执行主程序中输入输出指令后面的指令，整个传送过程中 CPU 的工作与外部设备、接口的工作**完全并行**。

    * 每传一个字都要回答同一个问题：**能否占用总线和主存的使用权**——不允许传送（CPU 正在占用）就继续查询等待，允许则进行一字传输。

    * 允许传送后，**主存地址由 AR（主存地址寄存器）送上总线**：只有这个寄存器知道要交换的信息需要保存或存储到主存的哪个地址。

    * 一字传完后同时**修改主存地址（为下一次传输做准备）和字计数器 WC**，再判断数据块是否传完；未传完回到"是否允许传送"的判断。

* **字计数器（Word Counter，WC）**

    * > **定义**：记录剩余要传输的数据量是多少个字的寄存器，用它判断数据块的传输是否结束。

    * 若用**补码方式**表示剩余数据量，则每传一个字计数器加一，加到溢出（计满归零）即意味着数据块传输结束。

    * 一块数据传完（WC 溢出）后，向 CPU 申请程序中断，进入后处理。

### 后处理

* **后处理（Post-processing）**

    * > **定义**：数据传送结束后，CPU 响应 DMA 接口的中断请求、执行中断服务程序所做的 DMA 结束处理操作。

    * 三件事：**数据校验**（数据输入到主存对不对）；**判断是否继续使用 DMA 进行数据传输**；**检查传输过程是否正确**（执行一个诊断程序）。

    * 触发路径：输入/输出执行完后 WC 的值溢出（值为零）→ 提出中断请求 → CPU 响应并执行中断服务程序完成这些操作 → 中断返回，继续执行主程序。

## 一次输入的逐字接力

* **输入（Input）**

    * > **定义**：输入输出以主机、以 CPU 为出发点，输入即数据从外部设备送入主存储器。

    * 职责分界：**对内存的读写控制命令由 DMA 控制器发出**，**数据由 BR（数据缓冲寄存器）经数据总线送出**。

```text
① 设备把数据送入数据缓冲寄存器 BR（保存要输入的数据）
② 设备 ──设备请求信号──→ DMA 控制逻辑（"数据已经准备好了"）
③ DMA 控制逻辑 ──经总线向 CPU 提出占用总线和主存的请求──→ CPU
④ CPU 在允许的情况下给出应答，放弃对总线和主存的占用，
   总线和主存的控制权交由 DMA 接口控制
⑤ AR 把主存地址送上地址总线（不管读还是写，都要有这个地址）
⑥ DMA 控制器 ──应答信号──→ 设备（"已经开始进行数据传输"）
⑦ DMA 控制器发出对内存的读写控制命令，
   BR 中的数据通过数据线送到数据总线上
⑧ 每传输一个数据：AR 加一、字计数器加一，然后判断是否传输完
        ├─ 没结束：回到①（设备再把数据放入 BR，DMA 重新发出占用请求）
        └─ 结束：WC 值发生溢出
⑨ WC 的溢出信号送给中断机构的中断请求触发器，把它置位、参加中断排队，
   CPU 接到中断请求，执行中断服务程序做后处理
```

## 输出过程的反向骨架

* **输出（Output）**

    * > **定义**：把 BR 当中的数据送到设备中去，骨架与输入完全一样，只是触发条件和数据流向反了过来。

    * 触发条件不同：一次输出完成后 **BR 已经空了**，由设备通知 DMA 控制器"BR 已空、可以接收下一个数据"，而不是由设备送数据进来。

    * 后续骨架：DMA 控制器向 CPU 发出总线和主存的控制权请求 → CPU 允许时给出应答、控制权交给 DMA 控制逻辑 → 通过 **AR 给出要访问的内存单元地址** → DMA 对设备给出应答（已开始新的传输）→ 主存当中的数据被写入 BR。

    * 同时修改主存地址寄存器和字计数器；输出未结束就循环上述过程，每轮都要再一次向 CPU 提出总线和主存的占用请求。

    * 传输完成时用 WC 的溢出信号把中断机构里的**中断请求触发器**之一置位，由中断机构向 CPU 发出中断请求信号进行后处理。

## DMA 接口与系统的连接

一台机器上可以有多个 DMA 接口，都要连接到总线上，连接方式是总线仲裁思想的翻版。

### 公共请求线方式

* **公共请求线连接**

    * > **定义**：所有 DMA 接口共享一条送给 CPU 的请求线，结构对应总线仲裁中的**串行链接**方法。

    * 各 DMA 接口通过地址线、数据线和主存进行连接；响应时 CPU 通过一条查询线一个一个接口地查询，**越靠近 CPU 的 DMA 接口优先级越高**。

    * 优缺点与总线仲裁里串行链接方式的优缺点逻辑完全一样，可按同样思路分析。

### 独立请求方式

* **独立 DMA 请求**

    * > **定义**：每一个 DMA 接口都有独立的 DMA 请求信号和独立的 DMA 响应信号，对应总线仲裁中的**独立请求**方式。

    * 排队的工作在 **CPU 内部**完成；每个接口仍要与地址线、读写命令线、数据线连接，以便和内存直接进行数据交换。

    * 优缺点模仿独立请求方式来分析；还可以模拟同样的思路给出第三种 CPU 和系统的连接方式。

## DMA 方式与程序中断方式的比较

| 比较项 | 程序中断方式 | DMA 方式 |
| :--- | :--- | :--- |
| 数据传送 | 由程序来传（中断服务程序），需要 CPU 的参与 | 直接由硬件进行控制，不需要 CPU 的参与 |
| 响应时间 | 在**指令执行周期结束**时进行中断查询、响应中断 | 外设与主存直接交换数据，在**存取周期结束**时响应 |
| 处理异常 | 程序执行过程中发生异常，可以用中断方式处理 | DMA 方式不行 |
| 中断请求的作用 | 通过执行中断服务程序来**完成数据的传输** | 用于**后处理**：检查数据是否有错、还需不需要 DMA 传输、传输过程是否有错 |
| 优先级 | 比较低 | 更高 |

* **优先级差异的原因**

    * DMA 方式是内存和外设之间直接进行数据交换，通常连接的设备都是**高速设备**，所以在 I/O 和内存进行数据传输这件事上 DMA 的优先级更高、中断方式更低。

> **易错点** ⚠️：两种方式都会发出中断请求，但目的和作用完全不一样——中断方式靠中断请求"干活"（传数据），DMA 方式靠中断请求"收尾"（后处理）。

## DMA 接口的类型

区别的核心在于"物理上接几个设备、逻辑上能同时服务几个设备"。

### 选择型接口

* **选择型（Selector Type）**

    * > **定义**：物理上连接多个设备，但在数据准备和数据传送的整个过程中，逻辑上只能连接一个设备的 DMA 接口。

    * 结构上寄存器及控制电路**只有一套**：CPU 运行一条输入输出指令，把字计数器、主存地址寄存器、设备地址寄存器等设置成某一设备与主存交换数据所需的值之后，**其他设备就无法再提出 DMA 请求、无法和主存交换数据**。

### 多路型接口

* **多路型（Multiplexor Type）**

    * > **定义**：物理上、逻辑上都可以连接多个设备，但真正进行数据传输时仍只能有一个设备和内存传输的 DMA 接口。

    * 与选择型的差别：**数据准备阶段可以有多个设备同时进行数据准备**，数据传送阶段串行。

* **通道（Channel）**

    * > **定义**：一种小型的 DMA 处理器，实际上也是一种 DMA 接口，可作为多路型的实例。

    * 一个通道下包含若干**子通道**，每个子通道都配有自己的一套**主存地址寄存器、设备地址寄存器和字计数器**。

    * 工作过程：CPU 执行输入输出指令时对**相应子通道**的寄存器进行设置后继续执行自己的程序；碰到下一条输入输出指令，若两个设备用**不同的子通道**，就对另一子通道的寄存器再次设置——之后多个外部设备**并行进行数据准备**；设备准备好后经子通道向通道提出数据传输请求，不同设备的传输**串行执行**。

### 多路型响应时序实例

* **时序参数**

    * 假设一个多路型接口连接三个设备，真正用于数据传送的时间为 **5 µs**（接口中的数据送入主存、或主存中的数据送入接口）：

| 设备 | 提出请求的间隔 | 说明 |
| :--- | :--- | :--- |
| 磁盘 | 每 30 µs 一次 | 30 µs 包含数据的传送时间和准备时间 |
| 磁带 | 每 45 µs 一次 | 比磁盘慢一点 |
| 打印机 | 每 150 µs 一次 | 更慢，其余时间在进行数据准备，准备好了才能提出请求 |

* **响应规则与结论**

    * 打印机最早提出请求，首先响应打印机、给 5 µs 做数据传输；其后磁盘和磁带**同时**发出请求时，**速度越高的设备优先级越高**，故响应磁盘。

    * 因为是多路型，数据在请求之前已经放入 DMA 接口的数据缓冲器，所以每个 5 µs 都是纯粹用于接口与主存之间的数据传输。

    * 结论：尽管一个多路型通道连接了多个设备，实际上仍有很多时间处于空闲状态，**还可以连接更多的设备**。

> **提示**：选择型、多路型的通道若不好理解，可参考体系结构教材中有关通道处理机的表述。

## 数的表示开篇：课程定位与数据表示

### 课程与教材定位

* **CPU 的构成**

    * CPU 的核心一部分是 **ALU（算术逻辑运算单元）**，另一核心是**控制单元**，还需要一系列寄存器的支持以及 CPU 内部的互联（把各组成部分连接成整体）。

    * 本部分课程主要讲解 ALU 及其逻辑实现，内容分三块：计算机中数据的表示、数的计算方法、根据表示和计算方法设计运算器。

* **教材**

    * 主教材：唐朔飞《计算机组成原理》第二版（高等教育出版社，"十二五"普通高等教育规划教材，曾获全国普通高等学校优秀教材二等奖）。

    * 参考教材一：Patterson 和 Hennessy 合著的经典教材，国内外很多大学用作计算机组成原理教材；参考教材二：Harris《数字设计和计算机体系结构》——书名是体系结构，实际讲计算机组成，以 MIPS 处理器为实例讲解处理器的逻辑实现。

### 数据表示与章节组织

* **数据表示（Data Representation）**

    * > **定义**：在计算机当中能够被硬件直接识别和处理的数据类型；"能被硬件直接识别和处理"指指令集中为这些数据提供了相应指令，必须用硬件来实现这些运算。

    * 讲解路径：先分析数据的**笔算方法**并对笔算方法进行改进，再借助笔算方法研究算法在计算机中如何用硬件实现、给出相应的硬件组成。

* **第六章的内容组织**

    * 五节结构：先介绍无符号数和有符号数 → 看它们在计算机中如何表示、如何存储 → 介绍定点运算和浮点运算 → 根据运算方法设计算术逻辑运算单元。

    * 有符号数部分先讲**机器数和真值**，机器数表示方法按顺序有四种：**原码表示法、补码表示法**（在分析原码存在的问题之后给出）**、反码表示、移码表示**。

    * 四种表示方法的讲法统一为：用数学方式给出定义、逐个分析特点并举例；机器数和真值之间、不同类型机器数之间如何转换；表示范围和字长之间的关系。

### 无符号数

* **无符号数（Unsigned Number）**

    * > **定义**：没有正负号的数，只有数值部分，用寄存器或存储器按规定的长度保存即可。

    * 若保存在寄存器中，**寄存器的位数直接给出表示范围**：

| 寄存器位数 | 表示范围（二进制） | 表示范围（十进制） |
| :--- | :--- | :--- |
| 8 位 | 8 个 0 ～ 8 个 1 | 0 ～ 255 |
| 16 位 | 16 个 0 ～ 16 个 1 | 0 ～ 65535 |

### 机器数与真值

* **机器数（Machine Number）与真值（True Value）**

    * > **定义**：保存在计算机当中的数叫**机器数**；平时用的带正负号的数据的真实值叫**真值**。

    * 有符号数由**符号**和**数值**两部分组成，两部分都要保存进计算机；符号要**数值化**——用 0 和 1 两种状态代表数的符号（存储元件可存低电平或高电平，形象地称为 0 或 1）。

* **小数点的约定**

    * > **注意**：计算机当中没有专门的硬件表示小数点，小数点都是以**约定的方式**给出的。

    * 定点计算机（小数点位置固定）按约定位置分两类：

| 类型 | 小数点约定的位置 |
| :--- | :--- |
| 小数定点机 | 符号位的后面 |
| 整数定点机 | 数值位的最后 |

    * 小数形式（如 $+0.1011$）：机器数最高位是符号位（约定 0 为正、1 为负），符号位后面就是小数点的约定位置，其余位存数值。

    * 整数形式（如 $+1100$）：0 作符号位、1100 作数值部分，小数点约定在数值位的最后，同样没有任何硬件标识。

### 原码表示法

* **原码表示法（Sign-Magnitude）**

    * > **定义**：把符号数字化本身给出的一种机器数表示——本质是**带符号的绝对值**：保存数据的绝对值，只在符号位用数值化的 0（正）、1（负）标记正负。

    * 逗号只是书写时把符号位和数值部分隔开的记号，小数点的位置完全靠约定，没有任何硬件。

#### 整数原码的定义

设真值为 $x$，数值部分的位数为 $n$：

$$[x]_{原} = \begin{cases} 0,\,x, & 0 \le x < 2^n \\[4pt] 2^n - x, & -2^n < x \le 0 \end{cases}$$

* **定义解读**

    * $x \ge 0$ 时原码就是"$0,\ x$"：逗号前的 0 是符号位，逗号后是真实数值部分；$x < 0$ 时符号位变 1。

    * 负数一侧 $2^n - x$ 的理解：$x$ 是负值，减 $x$ 相当于加上 $x$ 的绝对值，数值部分 $n$ 位、最高位位权是 $2^n$，所以这一支相当于**给绝对值加上 $2^n$**，进位正好落在符号位上、把符号位置成 1。

* **两个例子**

    * $x = +1110$：符号位写 0，数值照抄真值——$[+1110]_{原} = 0,\,1110$。

    * $x = -1110$（数值部分 4 位，$n = 4$）：$[-1110]_{原} = 2^4 - (-1110) = 2^4 + 1110 = 1,\,1110$。

#### 不等号与零的原码

* **上界为什么是严格的 $x < 2^n$**

    * 数值部分是 $n$ 位时，即使全为 1，能表示的最大整数值也只是 $2^n - 1$，所以用严格小于。

* **负数一侧为什么是 $-2^n < x$**

    * 所能表示的最小值只能到"1，后面数值位全 1"对应的 $-2^n + 1$，所以表示范围是从 $-2^n$ 的右侧一直到 0。

> **易错点** ⚠️：$x = 0$ 时两个分支都适用，用两种办法算出的 $[x]_{原}$ **可能会不同**——这是原码的固有特点，到补码表示时还会回到这个话题。
