# CPU 结构与指令流水线

## CPU 寄存器的分类

* **寄存器分类的总体说明**

    * > **定义**：不同 CPU、不同指令集结构对寄存器的设置要求不同，教材给出的是各种类型计算机中通用的抽象分类，且各分类方法之间并不完全正交（不完备、有交叉）。

    * 一种分法看寄存器**对用户是否可见**；另一种分法分出**控制与状态寄存器**。用户不可见寄存器实际上非常多，例如流水线计算机中流水段之间的流水段寄存器全部用户不可见。

* **用户可见寄存器**

    * **通用寄存器**：可存放操作数，如 8086 的 AX、BX；有些机器还让通用寄存器支撑某种寻址方式，充当寻址方式的专用寄存器。

    * **数据寄存器**：保存数据、操作数，要满足多种类型操作数的需求——现代通用机中既有保存整数的寄存器，又有保存浮点数的寄存器；有些机器把两个寄存器拼接存放双倍长数据，如乘法操作时把 ACC 与 MQ 拼接保存乘积。

    * **地址寄存器**：保存地址，如 8086 的段寄存器、堆栈指针等。

    * **条件码寄存器**：保存条件码，作为**分支的依据**——根据前面指令执行结果是正负、是否溢出、是否有进位、是否为零等，判断要不要跳转。

* **控制寄存器**

    * > **定义**：用于控制 CPU 操作的寄存器，理解它们最好的办法是看一遍从内存取一条指令的过程：PC 把指令地址送给 MAR，MAR 送地址给主存、CU 同时发读命令，读出的指令放入 MDR，再送入 IR——PC、MAR、MDR、IR 四者皆为控制寄存器。

    * > **易错点** ⚠️：控制寄存器 ≠ 用户不可见。「用户可见」指用户编程时可利用或读到其值——MAR、MDR、IR 用户不可见，**PC 是用户可见的**。

* **状态寄存器与 PSW**

    * **状态寄存器**：反映指令执行结果的情况或计算机软硬件的状态，可存放条件码，如 8086 的状态寄存器。

    * **PSW（Program Status Word，程序状态字寄存器）**：P 指 Program、S 指 Status、W 指 Word，用于存放程序状态字。

    * 程序状态字的由来：中断或子程序调用要保存程序运行现场和断点（含软件与硬件信息），其中部分状态无法逐个用指令读取——若为每个状态都设一条指令，指令集会非常庞大——于是设计者把与软硬件状态相关的寄存器**集合成一个大寄存器**。

    * > **提示**：程序状态字长度较长，有些可达几千位；正因它是整体，可用**交换程序状态字**的方式完成程序现场切换，使中断中保存与恢复断点、现场的工作变容易。

* **控制单元与中断系统**

    * **CU（Control Unit，控制单元）**：产生全部指令执行所需的**操作命令的序列**——不仅产生命令，还要保证命令之间的先后顺序。

    * CU 设计方法两种：组合逻辑设计（硬联方式），全硬件实现、速度快，精简指令集计算机的控制器通常用硬连线逻辑；微程序设计方式，采用存储逻辑实现、设计较简单，适用于复杂功能指令。

    * 中断系统在专门章节讲解；ALU 的运算功能在运算方法部分已详细介绍。

## 指令周期

* **指令周期（Instruction Cycle）**

    * > **定义**：从取出一条指令开始到这条指令执行结束所需的全部时间，即解释一条指令所需的全部时间。

    * 完成一条指令：先把指令从内存单元取出放入 IR，再分析操作码与寻址方式（合称**取指周期**）；然后执行指令、完成全部运算并写回结果（**执行周期**）。

    * > **提示**：「分成取指与执行两段」只是教材给出的一个例子——不同 CPU、不同指令集、不同设计方法可以把指令解释分成不同阶段，要具体分析。

* **不同指令的指令周期长短**

    * 有的指令只含取指周期、不含执行周期：如空操作指令 NOP，系统不需做任何操作。

    * 取指与执行两段长度相同：如 `ADD memory`（从内存取操作数与 ACC 相加、结果存 ACC），取指访存一次、执行也访存一次，时间基本相同，因为这段时间里占比重最大的是**访问存储器**。

    * 取指与执行长度不同：如乘法指令，执行阶段运算复杂、所需时钟周期数多，执行周期比取指周期长。

    * 具有间接寻址的指令周期：间接寻址在找操作数地址的过程中也要访存，若把「取操作数地址」塞进执行周期，执行周期要两次访存、被拉得很长——所以在指令周期中**专门加一个间接周期**，使解释过程分为取指、间接、执行三阶段，各访存一次。

    * 具有中断周期的指令周期：机器支持中断时，执行周期结束要确认有无中断请求；有则响应中断，在中断周期中完成保存断点、形成中断服务程序入口地址、硬件关中断。一条复杂又带中断的指令，完整指令周期含取指、间接、执行、中断四个阶段。

* **指令周期的流程**

    ```text
              ┌──────────┐
      ┌──────>│  取指周期 │<───────────────────────┐
      │       └────┬─────┘                        │
      │            ▼                              │
      │     采用间接寻址？──否───────────┐          │
      │            │是                 │          │
      │            ▼                   │          │
      │       ┌──────────┐             │          │
      │       │  间接周期 │────────────>│          │
      │       └──────────┘             ▼          │
      │                        ┌──────────┐       │
      │                        │  执行周期 │       │
      │                        └────┬─────┘       │
      │                             ▼             │
      │                      有中断请求？──否──────┤
      │                             │是           │
      │                             ▼             │
      │                       ┌──────────┐        │
      │  保护断点·形成入口地址·│  中断周期 │────────┘
      │  关中断               └──────────┘
      └── 下一条指令的取指
    ```

    * > **提示**：这张图**不是程序流程图**，它只是一个指令周期的流程——仅完成一条指令，执行完接着取下一条指令。

* **CPU 工作周期的标志**

    * > **定义**：控制器为分辨当前处于指令周期哪个阶段而设的标记——即便对同一部件（内存）操作，不同阶段的操作也不同。

    * CPU 对内存的访问有四种性质：

    | 阶段 | 访存性质 | 读回/写入的内容 | 数据的去向 |
    | :-- | :-- | :-- | :-- |
    | 取指周期 | 读 | 指令 | 送入 IR |
    | 间接周期 | 读 | 地址（操作数所在单元的地址） | 送入 IR 的地址码部分（或 MDR 的地址码部分） |
    | 执行周期 | 读 | 操作数 | 送入 CPU 中的寄存器，为数据操作做准备 |
    | 中断周期 | 写 | 程序断点 | 写入内存指定单元 |

    * 实现方式：用 **D 触发器**分别对取指、间接、执行、中断四个周期进行标识，确认当前指令的执行阶段。

## 指令周期的数据流

* **取指周期的数据流**

    * 用到的部件：PC（给出要取指令的内存地址）、MAR（保存访存地址）、MDR（保存数据）、IR（保存取回的指令）、CU（控制全部操作）。

    ```text
   PC ──→ MAR ──→ 地址总线 ──→ 存储器
   CU ──→ 读命令 ──→ 控制总线 ──→ 存储器（执行读操作）
   存储器 ──→ 数据总线 ──→ MDR ──→ IR
   CU 控制：PC + 1 ──→ PC
    ```

    * 流程：PC 把地址送 MAR，MAR 经地址总线送存储器；CU 的读命令经控制总线送存储器；存储器读出内容经数据总线入 MDR，再由 MDR 送入 IR。

    * 取指尚未结束：还要**为取下一条指令做准备**——无跳转时下一条指令地址为当前 PC 值加一，由 CU 控制 `(PC)+1 → PC`。

* **间接周期的数据流**

    * 前提：当前指令采用间接寻址——操作数的地址保存在指令地址码所指向的内存单元里。指令此刻在 IR（MDR 中也有）。

    ```text
   MDR（地址码部分）──→ MAR ──→ 地址总线 ──→ 存储器
   CU ──→ 读命令 ──→ 控制总线 ──→ 存储器
   存储器 ──→ 数据总线 ──→ MDR（地址码部分 = 操作数的地址）
    ```

    * > **提示**：此时读回来的「数据」实际上是一个**地址**——操作数所在内存单元的地址；送入 MDR 后，MDR 的地址码部分才真正保存了操作数的地址。

* **执行周期的数据流**

    * 不同指令在执行周期中的操作差异非常大，需按具体指令逐一分析。

* **中断周期的数据流**

    * 用到的硬件：PC、MAR、CU、MDR；要做的三件事：**保存断点、形成中断服务程序入口地址、硬件关中断**。

    ```text
   ① 保存断点：
      CU ──→ 断点保存地址 ──→ MAR ──→ 地址总线 ──→ 存储器
      CU ──→ 写命令 ──→ 控制总线 ──→ 存储器
      PC ──→ MDR ──→ 数据总线 ──→ 存储器（指定单元）

   ② 形成入口地址：
      CU ──→ 中断服务程序入口地址 ──→ PC
    ```

    * 保存断点是**写操作**：CU 确定断点保存地址送 MAR，发写命令；断点就是中断后要执行的下一条指令地址，保存在 PC 中，故 PC 值送 MDR 再写入指定单元。

    * 入口地址由 CU 给出并直接写入 PC——PC 指出下一条要执行的指令，此后程序就从服务程序开始执行。

## 流水线的性能指标

* **吞吐率（Throughput）**

    * > **定义**：单位时间内指令流水线所完成的指令条数（一般流水线即单位时间内输出的结果数量）。

    * **最大吞吐率**：流水线满负荷、无资源冲突、无数据相关、无转移指令时能达到的最大吞吐率。设流水线分 $m$ 段、每段时间均为 $\Delta t$，则每过一个 $\Delta t$ 输出一个结果：

    $$T_{max} = \frac{1}{\Delta t}$$

    * **实际吞吐率**：连续处理 $n$ 条指令，第一条走完 $m$ 段需 $m\Delta t$，之后每 $\Delta t$ 流出一条、还需 $(n-1)\Delta t$，总时间 $T = (m+n-1)\Delta t$：

    $$T_p = \frac{n}{(m+n-1)\Delta t}$$

    * 最直接的计算方法：衡量某段时间 $T$ 内到底输出了多少条指令（多少个结果）。

* **加速比（Speedup）**

    * > **定义**：采用流水线技术与不采用流水线技术两种方法**速度的比值**；该概念很广，可用于任意「采用某技术 vs 不采用」的对比，不限于流水线。

    * 不采用流水：每条指令需 $m\Delta t$，$n$ 条共 $nm\Delta t$；采用流水：$(m+n-1)\Delta t$。

    $$S = \frac{nm\Delta t}{(m+n-1)\Delta t} = \frac{nm}{m+n-1}$$

    * > **提示**：流水线不理想时的通则——加速比就是**两个时间的比值**：不采用流水线技术的时间 ÷ 采用流水线技术的时间。

* **效率（Efficiency）**

    * > **定义**：流水线中**硬件的利用率**。

    * 利用率到不了 100% 的原因：存在**建立时间**（第一条指令从进入到结果输出）与**排空时间**（最后一条指令进入到输出）——第一条指令刚进流水线时只有 $S_1$ 工作，$S_2..S_4$ 空闲；相关或流水线冲突造成的停顿也让各功能段难以一直工作。

    ```text
  流水段
   S4 │                    /  /  /  ███
   S3 │               /  /  /  ███ ███
   S2 │          /  /  /  ███ ███ ███
   S1 │  ███ ███ ███ ███ ███ ███ ███
      └───────────────────────────────→ 时间
       ├建立时间├    稳定满负荷    ├排空┤
      ███ = 该流水段有指令在工作
    ```

    * 计算：效率 = 时空图中处于工作状态的面积 ÷ 时间与空间两条轴构成的总面积。单个流水段的利用率 = 该段使用的时间 ÷ 该段被加电的总时间。

## 指令流水的原理

* **流水线技术的定位**

    * 流水线是现代处理器中**最常用、最有效**的提高指令解释速度的技术，从嵌入式处理器到高性能处理器都在使用。

    * 提速老办法回顾：提高访存速度（高速芯片、Cache、多体并行交叉访问）；提高 I/O 与主机传送速度（程序控制→中断→DMA→通道→I/O 处理机，以及多种总线方式）；提高运算速度（高速芯片、改进算法、快速进位链）。提高处理机能力的另一条路：**改进体系结构，开发系统的并行性**。

* **并行性：并发与同时**

    * **并发（Concurrency）**：两个或多个事件在**同一时间段**内发生——如分时系统中多道程序在各自小时间片上轮流使用资源，并非同一时刻真正同时执行。

    * **同时（Simultaneity）**：两个或以上事件在**同一时刻**发生，执行时间相互重叠。

    * > **定义**：并发是同一时间段内、在小时间片上轮流发生；同时是同一时刻真正并行发生、执行时间相互重叠。**流水线方式就是同时方式的一种**。

    * **并行性的等级**：程序级、过程级（粗粒度，通常由软件如操作系统实现）；指令级并行（ILP，Instruction Level Parallelism）——两条或多条指令同一时刻都处于被解释或被执行状态；指令内部操作、微操作之间并行（细粒度，由硬件实现）。流水线正是硬件实现的细粒度并行。

* **从串行执行到二级流水**

    * 串行执行：一条指令解释完才开始下一条——取指阶段只用取指部件、执行阶段只用执行部件，**总有一个部件空闲**，控制器利用率非常低。

    * **二级流水**：把取指部件与执行部件独立设计后让它们同时干活——执行第 1 条时取指部件去取第 2 条，对不同指令来说取指与执行在时间上**重叠**。

    * 理想情况下每 $T/2$ 完成一条指令，指令周期减半，解释速度提高一倍。但并非所有流水线都是理想流水线，指令之间也有相关性，流水线很难一直满负荷。

* **二级流水提速打折扣的两个原因**

    * **原因一：有些指令执行时间太长。** 取指假设指令格式统一、长度一致、取指时间相同，但复杂指令执行时间远长于取指。解决办法：在取指与执行部件之间**加缓冲区**，缓存取回的指令，执行部件空闲时到缓冲区取指令——解耦两个速度不匹配的部件。

    * **原因二：条件转移指令。** 无条件转移在译码阶段就知道是转移指令及目标地址，对流水线效率影响较小；**条件转移必须等执行阶段结束、有了结果，才知道转移条件是否成立、才能确定下一条指令的真正地址**，之前流水线只能等待或猜测，时间损失大。程序中转移指令很常见——一般 3～5 条指令中就有一条转移指令。解决方式很多，如**分支预测**（最简单的是猜测法）。

* **六级流水线的时间账**

    * 六个功能段：**取指令、指令译码、形成操作数的地址、取操作数、执行、写回**（写回指把结果写到给定寄存器或内存单元）；单独设「形成操作数地址」一段，是因为指令可能采用多种寻址方式，要先算出地址才能取数。

    * 9 条指令、每段一个时间单位：串行需 $9 \times 6 = 54$ 个时间单位；流水线只用 **14** 个时间单位（前提是无冲突、无转移指令）。

## 影响流水线性能的三类相关

* **结构相关（资源冲突）**

    * > **定义**：流水线中功能部件发生冲突——两条或以上指令征用同一个功能部件。

    * 典型场景：取指、取操作数、写回都要访存——第 4 时间段指令 1 取操作数与指令 4 取指同时访存；第 6 时间段指令 1 写回、指令 3 取操作数、指令 6 取指三方冲突。对寄存器（一读一写同周期）、运算器的争用同样构成结构相关。

    * 解决办法：**停顿**（把后到的取指往后推，教材称**加入气泡**）；**指令存储器与数据存储器分开**（现代计算机分开指令 Cache 与数据 Cache 即为此，也称**哈佛结构**）；**指令预取**（访存快时利用空闲时间把多条指令取入 CPU 内的**指令缓冲队列**，减少访存冲突）。

* **数据相关（读写次序被打乱）**

    * > **定义**：不同指令重叠操作、流水线有多个读段写段时，可能**改变操作数的读写次序**而产生的相关。共三种。

    * **先写后读相关（写后读）**：对某存储单元或寄存器必须先写后读程序才正确——如减法结果存 R1，加法指令要用 R1 做操作数，必须等减法把结果写入 R1 后再读。

    * **先读后写相关（读后写）**：对同一存储器件（内存或寄存器）必须先读后写——如存储指令把 R2 存入内存单元 M，紧接着加法指令更新 R2，次序反了存入 M 的就是加法结果而非原 R2。

    * **写后写相关**：对同一存储器件多次写入时必须保证程序规定的写入时间顺序——如两条指令都写 R3，最终 R3 应是程序顺序靠后那条的值。

    * 解决办法一：**后推法**（推后读/推后写）——后条指令等前条写完再读，正确但浪费时间。

    * 解决办法二：**旁路技术**（相关专用通路，有的教材叫**前向通道**）——要写入 R1 的值在第一条指令运算器输出端就已生成，结果一旦在输出端生成就直接送入第二条指令的运算器输入端，不必等写入 R1，更省时间。

* **控制相关（转移指令的代价）**

    * > **定义**：由**转移指令**引发的相关。

    * 过程：条件转移指令在译码阶段不知是否真转移，后续指令照样逐个进入流水线；直到它**执行阶段结束**才知条件是否成立——若真转移，中间已进入流水线的指令在正常串行执行中本不该被执行，**执行结果要作废**，从转移目标重新取指、分析、执行，这些被作废的指令就是**转移造成的损失**。

    * | 相关类型 | 由什么引发 | 典型场景 | 解决办法 |
      | :--- | :--- | :--- | :--- |
      | 结构相关 | 功能部件（资源）冲突 | 同一周期多条指令同时访存；争用寄存器、运算器 | 停顿（加气泡）；指令/数据存储器分开（哈佛结构）；指令预取 |
      | 数据相关 | 重叠操作改变了读写次序 | 先写后读、先读后写、写后写 | 后推法；旁路技术（相关专用通路／前向通道） |
      | 控制相关 | 转移指令 | 条件转移要等执行结束才知去向，已入流水线的指令作废 | 分支预测（如猜测法）等 |

## 流水线的结构与分段

* **指令流水线的一般结构**

    * 六段结构每段一个时钟周期：取指（取指部件）→ 译码（确认指令要做什么）→ 地址形成（地址形成部件，因寻址方式多样）→ 取操作数 → 执行 → 写回。

    * 分多少段、每段做哪些操作，对不同结构的机器、不同的 CPU **是不一样的**。

    * 若流水线**不出现断流**（无资源冲突、无数据冲突、无控制冲突）且指令条数足够、能连续输入，则**一个时钟周期出一个结果**——六段流水相当于指令解释速度提高六倍。

    * **流水段之间一定要加锁存器**：保存前段操作结果，同时为下一段提供操作数据和操作信号——这是流水线能逐段推进的物质基础。

* **各段时间要尽量相等**

    * > **注意**：为使流水线提速有效，**每一段操作时间要尽可能相等**。若各段时间不等而每段占一个时钟周期，时钟周期就得按最长的功能段设置——一条短板决定整条流水线的节奏，降低整体速度。分段做功能分配时要考虑各段执行时间尽量相等。

* **运算流水线**

    * > **定义**：复杂的运算过程也可用流水线方式实现，以提高运算器速度。

    * 典型例子：浮点加减法需求阶差、对阶、尾数求和、规格化，比定点加法时间长得多，可用三段流水线：

    ```text
  对阶部件          尾数求和部件        规格化部件
 ┌────────┐       ┌────────┐        ┌────────┐
 │  对阶   │──────→│ 尾数求和 │───────→│  规格化  │──→ 结果
 └────────┘       └────────┘        └────────┘
        ↑ 锁存器          ↑ 锁存器
    ```

    * 分成三段后，与不分段相比最大速度提高三倍。

## 流水线的多发技术

* **超标量技术（Superscalar）**

    * > **定义**：每个时钟周期之内，有多条**独立的**指令**同时**进入不同的流水线去执行。

    * 要求配置多条流水线、多个功能部件——如三条流水线每周期进三条独立指令，最高加速比可达三倍。

    * 通常**不调整指令的执行顺序**：由编译程序在编译阶段用优化技术把可并行的独立指令挑选、搭配好，靠**静态的、编译阶段的调度**挖掘并行性。

* **超流水线技术（Superpipeline）**

    * > **定义**：把一个时钟周期（一个流水段）进一步细分（如分成三份），在一个时钟周期之内让三条指令**分阶段（非同时）**进入流水线，一个功能部件被使用三次。

    * 流水线结构不变（仍是取指、译码、执行、写回），只是每个时钟周期均分成三份，每个时间点开始时都可进入一条新指令。

    * 与「把流水线细分」（如四段细分成 12 段）的区别在**锁存器**：超流水段间**依然有锁存器**，但一个流水段内部等分出的三份之间**没有锁存器**；细分流水线则每小段之间都有。

    * > **定义**：超流水的一个关键技术——**不同指令处在同一个流水段当中时，相互之间的信号不能叠加**：段间靠锁存器隔离，段内靠时钟细分错开。

    * MIPS 处理器即采用超流水技术；同样一般不调整指令执行顺序，由编译程序静态优化。例中提速三倍，即**最大吞吐率达原来流水线的三倍**。

* **超长指令字技术（VLIW，Very Long Instruction Word）**

    * > **定义**：由编译程序找出指令间的并行性，把多条可并行、无相关的指令组合成一条**长至几百字节**的指令字，内含**多个操作码字段、多个操作数字段**，取出后译码、由多个并行功能部件分别执行。

    * 两个关键前提：编译程序找并行性的依据是计算机中**执行部件的数量和种类**；被组合的**指令之间不能有相关性**。

    * 优点：**减少取指令的时间**——一次取出的是十几条甚至几十条指令（打包成一条）。应用于数字信号处理、多媒体信号处理等领域。

    ```text
   内存 ──→ 取指部件 ──→ 译码／控制单元 ──┬→ 取数部件
   （取出一条几百字节                      ├→ 存数部件
     的超长指令字，                        ├→ 定点运算部件
     含多个操作码字段）                    ├→ 浮点加减部件
                                          └→ 浮点乘除部件
    ```

    * 特点：用**多个处理部件**来做——单一取指部件取指令，控制单元译码后控制多个功能部件同时执行各自的操作。

## 中断系统概述

* **中断源的类型**

    | 中断源类型 | 典型例子 |
    | :--- | :--- |
    | 人为设置的中断 | 程序中编入访管指令，访问管理程序（操作系统中的程序）实现程序功能 |
    | 程序性事故 | 运算溢出、操作码不能识别、非法的除法 |
    | 硬件故障 | 存储器故障、硬盘坏道、电源掉电 |
    | I/O 设备 | 设备做输入输出要使用中断 |
    | 外部事件 | 如用键盘上的中断键人为中断程序执行 |

    * > **提示**：中断系统不是 I/O 的附属品，而是 CPU 处理「计划外事件」的统一机制——程序调试、各种异常事件的处理都靠它。

* **中断系统要解决的七个问题**

    * 各中断源如何向 CPU 提出中断请求（各源独立提出）。

    * 多个中断源同时提出请求怎么办。

    * CPU 在什么条件下、什么时间、以什么方式响应中断。

    * 断点如何保存、现场如何保存。

    * 中断服务程序的入口地址怎么寻找、怎么形成并送给 PC。

    * 如何恢复现场、如何返回。

    * 处理中断的过程中又出现新中断怎么办。

    * 实现总原则：**软件加硬件**结合；不同计算机对软硬件功能的划分不同，划分依据三方面折中——**中断系统的速度、设计的复杂性、设计的灵活性**。

## 中断请求与判优

* **中断请求触发器与中断请求标志寄存器**

    * > **定义**：给每一个中断源设置一个触发器，标记该中断源是否提出了中断请求；多个中断源对应多个触发器，逻辑上组成**中断请求标志寄存器**——每一位标识一个中断源，如第一位表示电源掉电、后面依次为是否过热、存储器读写校验是否出错等。

    * 触发器的两种摆放：**分散结构**——放在各中断源自己的接口电路中；**集中结构**——集中在 CPU 的中断系统内。

* **中断判优**

    * > **定义**：多个中断源同时请求时，按中断事件产生的严重程度或重要性把中断源**分级**（中断源的优先级），用**中断判优逻辑**确定当前所有请求中优先级最高者予以响应。

    * 判优有硬件与软件两种实现；现代计算机大多数 CPU 的判优由硬件实现。

* **硬件排队器**

    * 两种摆放：**分散**在各中断源接口电路中（链式排队器——每个中断源一个非门一个与非门，串联成判优电路）；**集中**在 CPU 内部或 CPU 之外的专门判优机构中。

    * 集中排队器的关键特征：**输出中只有一位是 1、其余各位都是 0**——每个中断源输出为 1 的条件是**比它优先级高的中断源都没有请求**；高优先级源有请求时用控制线把低优先级源的输出清零。

    * 设计顺序：先划分中断源优先级，再设计排队器排队，最终响应优先级最高的请求。

* **软件查询判优**

    * > **定义**：用程序查询的方式实现判优——把「谁优先」翻译成「先查谁」。

    * 流程：先判断优先级最高的中断源有无请求，有则转入其中断服务程序入口地址执行；没有再判断次优先级源，依次向下。

## 中断服务程序入口地址的形成

* **硬件向量法**

    * > **定义**：用硬件直接形成**中断向量地址**——排队器的输出（仅一根线为 1）作为**向量地址形成部件**的输入，指出当前优先级最高的中断源，据此确定应执行哪个中断服务程序，形成的向量地址送入 PC。

    * **两层地址关系（务必分清）**：中断服务程序的入口地址有两种给出办法——

        * 向量地址对应的存储单元里**存一条跳转指令**，跳转指令中包含服务程序入口地址，直接跳转过去；

        * 向量地址对应的内存指定位置**存的就是服务程序本身的入口地址**，取回送入 PC 执行。

    * 特点：硬件向量法**速度快**，但设计的**灵活性比较低**。

* **软件查询法**

    * > **定义**：通过执行一个**中断识别程序**查找服务程序入口地址。

    * 机制：识别程序开头是一条**跳过下一条指令**的指令，查询 1 号中断源的**完成触发器 D**——D=1（已准备好、提出了请求）则执行下面那条转移指令转入其服务程序；D=0 则跳过转移指令，继续查询下一个源，依次检测到最后一个。

    * > **易错点** ⚠️：软件查询法的「查询次序」本身就是优先级——想改变中断服务的优先级，只要调整查询次序即可；这正是软件方法更灵活之处，也是它比硬件向量法慢的原因。

## 中断响应的条件与时间

* **响应条件：允许中断触发器 EINT**

    * > **定义**：CPU 中设**允许中断触发器 EINT**，标识 CPU 是否允许响应中断请求——**EINT 置 1 时才允许响应**。

    * 背景概念：**单重中断**——CPU 在响应某中断源、执行其中断服务程序期间，即使有新中断源请求也不能响应。

* **响应时间：指令执行阶段结束之后**

    * 一般机器只有在**指令的执行阶段结束以后**才响应中断请求。

    * 响应时机固定在指令边界上的道理：断点保存的正是「下一条要执行的指令的地址」；若允许在指令执行中途响应，「当前执行到哪」没有唯一的指令边界，断点与现场都难以完整保存和恢复。

    * 例外：某些指令非常复杂、执行时间很长，为及时处理异常事件，也允许在指令执行过程中响应中断。

    * 响应时刻的动作：指令执行阶段结束时 CPU 发出**查询信号**，送到每个中断源的中断请求触发器，驱动触发器输出端置 1，把中断请求信号送入排队电路。

## 中断隐指令

* **中断隐指令**

    * > **定义**：响应中断时由**硬件自动完成**的三个操作——保存断点、寻找中断服务程序入口地址、关中断；它**不在指令系统中**，没有对应的操作码，不由任何一条具体指令驱动，但响应中断时必须进行。

    * **保存断点**的两种方法：保存到内存某个特定存储单元；或把断点**进栈**，返回时再出栈。

    * **寻找入口地址**的两种方法：硬件向量法——把中断向量地址送 PC（该单元内含入口地址或跳转指令）；软件方法——把中断识别程序入口地址 M 送 PC，执行识别程序找到入口地址。

    * **关中断**：把 EINT 置 0。目的：单重中断机器中防止服务程序执行期间被新中断源打断；多重中断机器中也是为使保存断点、保存现场的过程安全完成——不允许低优先级请求打断正在执行的高优先级服务。

* **响应中断的控制电路**

    * 两个 RS 触发器：**中断标记**触发器（表示 CPU 正在执行某一中断）、**中断允许**触发器 EINT（表示当前是否允许响应新请求）。

    * 触发条件：EINT=1 **且**排队器输出有请求（有请求时排队器恰有一根线为 1，用或门汇总）——两者皆 1 时经 S 端把中断标记置 1；中断标记一置 1，EINT 即被置 0（关中断）；同时排队结果送向量地址形成部件，向量地址送 PC，为执行服务程序做好准备。

## 现场的保护与恢复

* **保护现场的两部分内容（完成者不同，务必分清）**

    * **保存断点**：由**中断隐指令**（硬件）自动完成。

    * **CPU 中寄存器的内容**：执行服务程序要用到这些寄存器，而主程序返回后还要用，故也要保存——这部分由**中断服务程序**（软件）完成。

    * > **结论**：编写中断服务程序时，用到的寄存器在使用之前要先把内容保存起来。

* **恢复现场**

    * 由中断服务程序完成：保护现场时用 `PUSH` 指令把寄存器内容压入堆栈；恢复时按**相反的次序**用 `POP` 出栈。寄存器内容也可保存在内存某地址中，不一定要走堆栈。

* **中断服务程序的骨架**

    ```text
中断服务程序：
    ① 保护现场：PUSH 相关寄存器（内容存入堆栈）
    ② 执行中断服务主体（设备服务部分）
    ③ 恢复现场：按 PUSH 相反的次序 POP 寄存器
    ④ 中断返回：IRET
    ```

## 多重中断

* **多重中断（中断嵌套）**

    * > **定义**：CPU 在执行中断服务程序的过程中，若有新中断源提出请求、且其优先级**比正在处理的服务程序更高**，则进行响应。

    * 嵌套过程：主程序被打断进入服务程序(1)，服务程序(1)被打断进入服务程序(2)，再进服务程序(3)——发生三次中断、产生三个断点；执行完逐层返回，原则是**中断谁，返回谁**。

* **实现多重中断的两个条件**

    * **EINT 要提前打开**：中断服务程序要在适当位置**提前开中断**（把 EINT 置 1），才能响应新请求。

    * **只有优先级更高的中断源才能打断**：优先级低的无权中断优先级高的——否则谁都能插队，优先级形同虚设。

    * 运行轨迹示例（优先级 A > B > C > D）：主程序中 B、C 同时请求，响应 B；B 执行完**返回主程序**（它中断的是主程序）；此时 C 请求标记还在，主程序再次被打断去执行 C；C 执行中 D 请求但因优先级低于 C 不被响应；C 结束返回主程序，再响应 D；D 执行中 A 请求、优先级更高，D 被打断转去执行 A；A 结束**返回 D**，D 结束返回主程序。

## 中断屏蔽字

* **中断屏蔽触发器（MASK）**

    * > **定义**：每个中断源对应一个 MASK 触发器，用**中断屏蔽字**来设置，控制该中断源的请求能否提出、能否进入排队器排队。

    * 在设备接口一侧：D 是完成触发器（设备完成工作、要提请求）。MASK 的 Q 端输出为 0 表示**没有屏蔽**（Q 非端为 1）——在 D=1 且 MASK 的 Q 非端也为 1 的条件下，CPU 查询信号才能使中断请求触发器 INTR 输出为 1；MASK 置 1 则请求被屏蔽——无论 D 为何值，INTR 输出都是 0，不能向 CPU 发出请求。

    * 与排队器结合：屏蔽字的**长度与中断源的个数相等**，每一位对应一个 MASKᵢ——MASKᵢ=1 时对应源被屏蔽，请求无法提出、其排队输出被钳为 0，不能被排队器选中；MASKᵢ=0 表示开放，允许请求进入排队器参加排队。

    * 每个中断源都有自己的屏蔽字，表示**该源的服务程序执行期间**允许哪些源的请求进排队器——如运行 1 号源服务程序时其屏蔽字全一，则 1～16 号任何源的请求都进不了排队器，CPU 不响应、不服务。

    * > **提示**：硬件排队器定下的优先级是设计时固定的，而屏蔽字让运行中的每个服务程序都能自己决定「我执行期间放行谁」——这正是中断系统软硬件折中里「灵活性」的落点；此外也可人为设屏蔽字挡掉不希望打扰的某个中断源。

* **响应优先级与处理优先级**

    * > **结论**：**中断响应优先级**由硬件排队器确定，出厂即固定，不可改变；**中断处理优先级**可以通过重新设置中断屏蔽字来改变。

    * 原理：设置屏蔽字可以让优先级高的中断请求**不能进入中断排队器排队**、更不能被响应，从而提高某个中断的处理优先级。

* **用屏蔽字重排处理次序（A、B、C、D，响应优先级 A > B > C > D 固定）**

    * 原屏蔽字规则：每个源屏蔽**自身及优先级更高的源**（1 屏蔽、0 开放，位序按 A、B、C、D）：

    | 中断源 | 原屏蔽字 | 屏蔽的对象 |
    | :---: | :---: | :---: |
    | A | 1111 | A、B、C、D |
    | B | 0111 | B、C、D |
    | C | 0011 | C、D |
    | D | 0001 | D |

    * 主程序不屏蔽任何中断，屏蔽字为全零。

    * 把处理优先级改成 **A > D > C > B** 后的新屏蔽字（屏蔽自身、开放处理优先级更高的源）：

    | 中断源 | 新屏蔽字 | 执行该服务程序时开放的中断 |
    | :---: | :---: | :---: |
    | A | 1111（全一） | 无 |
    | D | 0111 | A |
    | C | 0110 | A、D |
    | B | 1100 | A、D、C |

    * 改变前的运行轨迹（处理优先级 = 响应优先级）：A、B、C、D 同时请求 → 响应 A，A 屏蔽字全一、无人能打断，执行完返回主程序 → 依次 B、C、D 一层层排下来，谁也打不断谁。

    * 改变后的运行轨迹：同时请求仍先响应 A（响应优先级最高），A 执行完返回主程序；随后 B 的响应优先级最高、响应 B——但 B 的新屏蔽字开放 C、D，于是 C 的请求进排队器、响应 C；C 的屏蔽字 0110 不屏蔽 D，D 打断 C；D 结束**返回 C**，C 结束返回 B，B 返回主程序——嵌套返回路径是进入路径的逆序。同一响应优先级，只换几个屏蔽字，处理次序完全不同。

* **屏蔽字在服务程序中的设置时机**

    * 多重中断服务程序的完整流程：

    ```text
保护现场（push 指令保存服务程序要用到的寄存器）
   ↓
设置中断屏蔽字        ← 必须在开中断之前完成
   ↓
开中断（提前开中断，目的就是能实现多重中断）
   ↓
中断服务（真正干活的主体）
   ↓
关中断               ← 恢复现场的过程不能被打断
   ↓
恢复现场、恢复中断屏蔽字
   ↓
开中断
   ↓
中断返回
    ```

    * 位置要点：**设置屏蔽字在保护现场之后、开中断之前**；关中断之后先恢复现场、再恢复屏蔽字（让恢复过程不被打断），恢复完再开中断、进行中断返回。

## 多重中断的断点保护

* **固定地址保存断点的缺陷**

    * 两种断点保护办法：**断点进栈**（中断隐指令由硬件直接完成）；**保存到特定地址**（如「0 地址」——引号里的零不一定是物理地址零，可以是任意给定地址），同样由中断隐指令完成。后者的中断周期操作：0 → MAR，发写命令，PC → MDR，(MDR) → M(MAR)。

    * > **易错点** ⚠️：单一中断下「断点存固定地址」没有任何问题；坑只在**多重中断**里出现——固定地址只有一个格子，后到的断点保存会**冲掉前面断点的内容**。如三次嵌套产生 $K+1$、$L+1$、$M+1$ 三个断点全存 0 地址，至少两个断点丢失。

* **转存断点的完整程序**

    * 约定断点保存在 0 地址单元，服务程序框架：

    | 地址 | 内容 |
    | :---: | :--- |
    | 0 | （程序断点保存处） |
    | 5 | 跳转指令，跳转到 SERVE |
    | …… | SAVE ← ACC（保存现场） |
    | …… | ACC ← M[0]（取数：断点进 ACC） |
    | …… | RETURN ← ACC（存数：断点转存） |
    | …… | 开中断，执行中断服务程序 |
    | …… | ACC ← SAVE（恢复现场） |
    | …… | JMP (RETURN)（间接跳转，返回断点） |

    * 地址 5 即**向量地址**：由中断向量地址形成部件形成后送 PC，程序转入服务程序（SERVE 为入口地址）。

    * 先保存现场：服务程序要用 ACC，先把 ACC 内容存入 SAVE 单元。

    * 关键的**转存**动作：取数指令把 0 地址单元的内容（即断点）取入 ACC，存数指令把断点值存入 RETURN 单元——通过转存，断点在多重中断嵌套中不再被后到断点覆盖。

    * 转存做完才**开中断**执行服务主体；执行完先恢复现场（SAVE 内容送回 ACC）。

    * 返回用**间接跳转指令** `JMP (RETURN)`：不是跳到 RETURN，而是跳到 RETURN 单元中**保存的那个地址**——即断点、下一条要执行的指令的地址。

    * > **提示**：转存与「屏蔽字必须在开中断之前设置」是同一件事的两面——凡是不能被打断的准备动作（保护现场、转存断点、设置屏蔽字），都必须赶在开中断之前做完；一开中断，别的请求随时可能进来。返回之前还要恢复中断屏蔽字。

## 微操作命令分析

* **微操作命令**

    * > **定义**：指令解释过程中由控制单元发出的命令；这些命令完成的动作与整条指令要完成的功能相比小得多，故称微操作命令。

    * 完成一条指令分四个工作周期：**取指周期**（把指令从给定内存单元取出）、**间址周期**（间接寻址时把操作数的地址从内存取出、放入指令的地址码部分）、**执行周期**（完成对操作数的读取和操作）、**中断周期**（若有请求则响应：保存断点、形成入口地址、硬件关中断）。

    * 分析的前提假设：**指令定长**，长度与机器字长、存储字长相等，一次访存即可取出指令或操作数地址。

* **取指周期的微操作**

    * ```text
PC → MAR → 地址总线 → 存储器
1 → 读命令
存储器 → 数据总线 → MDR → IR
OP(IR) → CU（译码）
(PC) + 1 → PC
      ```

    * 五件事：PC 的指令地址经 MAR、地址总线送存储器；CU 发读命令；读出内容经数据总线入 MDR 再入 IR；取指周期内完成**译码**——IR 的操作码部分送 CU 译码（此结构中取指不需要 ALU）；PC 加一再存回 PC，为取下一条指令做准备。

* **间址周期的微操作**

    * 四步：IR（或 MDR）中的**形式地址**（地址码部分）送 MAR；CU 发读命令；存储器在指定单元取出**操作数的地址**，经数据总线送 MDR；该地址再送 IR 的地址码部分——此后 IR 中指令的地址码部分就是操作数的物理地址（操作数所在存储单元的地址），间址结束。

* **执行周期的微操作（三类指令）**

    * **非访存类指令**：

        * CLA（清零）：把零送给 ACC，一条微操作命令完成整条指令。

        * COM（取反）：ACC 内容按位取反，一条控制命令即可。

        * 算术右移：各位右移一位，同时最高位 $ACC_0$（符号位）写回 $ACC_0$（空位用原符号位填充），两个操作同时进行。

        * 循环左移：各位左移一位，同时 $ACC_0$ 移到最末位 $ACC_n$，两个操作同时进行。

        * STP（停机）：把零送到停机标志 G。

    * **访存类指令**（寄存器内容记法：寄存器名外加括号，如 (ACC)、(MDR)）：

        * ADD X（加法，ACC 中已有被加数）：Ad(IR) → MAR、发读命令；M(MAR) → MDR；(ACC) + (MDR) → ACC。

        * STA X（存数，写操作）：Ad(IR) → MAR；CU 发**写命令**；(ACC) → MDR；(MDR) → M(MAR)。

        * LDA X（取数）：Ad(IR) → MAR、发读命令；M(MAR) → MDR；(MDR) → ACC。

    * **转移指令**：

        * JMP X（无条件转移）：IR 的地址码部分送 PC 即完成。

        * BAN X（负则转，条件转移的一例）：判断 ACC 最高位 $ACC_0$——$ACC_0=1$（上次结果为负）则 Ad(IR) → PC，跳转成功；$ACC_0=0$ 则 PC 不变，顺序执行下一条。

        * > **注意**：取指阶段已完成 PC 加一，**执行阶段不需要再把 PC 加一**——下一条顺序指令的地址已在 PC 中。

* **三类指令的指令周期对比**

    | 指令类型 | 指令周期组成 |
    | :--- | :--- |
    | 非访存类 | 无间接寻址、不需访存：取指周期 + 执行周期 |
    | 访存类（直接寻址） | 地址码直接给出操作数地址：取指周期 + 执行周期 |
    | 访存类（间接寻址） | 取指周期 + 间址周期 + 执行周期 |
    | 转移类（直接） | 取指周期 + 执行周期 |
    | 转移类（间接寻址） | 取指周期 + 间址周期 + 执行周期 |

* **中断周期的微操作**

    * 所有指令的中断周期都做**相同的工作**——三件事：保存断点、形成入口地址、硬件关中断。

    * **保存断点方式一（存入给定地址，如 0 地址）**：

    ```text
0 → MAR          （目标地址送 MAR）
1 → 写命令        （对存储器进行写操作）
PC → MDR         （断点在 PC 当中，先送 MDR）
(MDR) → M(MAR)   （完成写入，断点保存完毕）
    ```

    * **保存断点方式二（断点进栈）**：堆栈也是内存的一部分，断点写入栈顶——先 (SP)−1 → SP 且 → MAR（减一形成新栈顶地址），1 → 写命令，PC → MDR，(MDR) → M(MAR)。

    * **形成入口地址**：硬件向量法——把向量地址保存到 PC；软件查询法——把中断识别程序入口地址 M 送 PC，由 CPU 执行识别程序给出服务程序入口地址。

    * **硬件关中断**：把 0 送到中断允许触发器 EINT。
```
