## 从归并的非递归写法，到用链表实现队列
> 对应块：BLK23 | 覆盖分集：P91-P93 | 块标题（分集名）：《基础数据结构-059-数组-e01-合并有序数组》

上一节我们用递归把归并写完了，思路是：数组分成左右两段，各自排好序，然后递归地把它们并回去。递归好写、好想，调用栈帮我们把"先并左边、再并右边"这件事自动记下来了。

不过递归有它的代价——每一次递归调用都要压栈、弹栈，栈空间跟着递归深度往上走，栈里还得多存一份中间下标。我们今天把这件事翻过来做一遍：**不递归，用一个循环把两个有序区间并起来**。写完之后你会发现，它比递归版还少一个参数。

再往后，我们正式开一种新的数据结构：队列，并且用链表把它落地实现出来。

### 不用递归，一样能把两个有序区间并起来

#### 三个指针先各就各位

先把图摆出来。第一个数组 `a1` 已经被分成了两个各自有序的区间：`[1, 5, 6]` 和 `[2, 4, 10, 11]`，我们要把它们并进结果数组 `a2`。

```text
         区间一 (i .. mid)      区间二 (j .. right)
 a1:  [ 1 ] [ 5 ] [ 6 ]  |  [ 2 ] [ 4 ] [ 10 ] [ 11 ]
       ^i          ^mid       ^j                ^right

 a2:  [ _ ] [ _ ] [ _ ] [ _ ] [ _ ] [ _ ] [ _ ]
       ^k
```

三个指针的分工非常清楚：

| 指针 | 含义 | 谁在动 |
| --- | --- | --- |
| `i` | 区间一当前待比较的位置 | 区间一的元素被取走时才动 |
| `j` | 区间二当前待比较的位置 | 区间二的元素被取走时才动 |
| `k` | 结果数组 `a2` 下一个空位的下标 | 每写入一个元素就动 |

`mid` 是区间一的右边界，`right` 是整个 `a1` 的右边界，这两个是**固定不动**的，它们的作用就是随时告诉我们"走到头了没有"。

整个循环体只有一句话：比较 `a1[i]` 和 `a1[j]`，**小的那个写进 `a2[k]`，然后被写走的那个指针和 `k` 各往后挪一位**。

我们把整个过程走一遍，你会看到"挪指针"这件事是有节奏的：

- `1` 对 `2`，`1` 小，`1` 进 `a2`，`i++`，`k++`；
- `2` 对 `5`，`2` 小，`2` 进 `a2`，`j++`，`k++`；
- `5` 对 `4`，这次轮到区间二赢了，`4` 进 `a2`，`j++`，`k++`；
- `5` 对 `10`，`5` 进 `a2`，`i++`，`k++`；
- `6` 对 `10`，`6` 进 `a2`，`i++`，`k++`。

注意每一步只会有一个指针往前挪——因为只会有一个元素被写走。这是归并最核心的不变式。

#### 循环什么时候停，尾巴谁来收

走到最后一步，`i` 加一之后越过了 `mid`。这时候区间一已经被掏空了，`a1[j]` 和 `a1[j+1]` 也就是 `10` 和 `11` 还乖乖躺在那儿没人要。

> **结论**：循环退出只可能是因为 `i > mid` 或者 `j > right`——**两个区间至少有一个被搬空了**。而搬空的那个，它的剩余部分没有得比、也没人跟它争，可以整段直接搬进 `a2`。

这就是为什么循环后面一定要补一刀，而且是**对称的两刀**：

- `i > mid`（区间一空了）：把 `a1` 从 `j` 开始的剩余部分复制到 `a2`，个数是 `right - j + 1`；
- `j > right`（区间二空了）：把 `a1` 从 `i` 开始的剩余部分复制到 `a2`，个数是 `mid - i + 1`。

两段代码结构一模一样，差别只在起点和长度。

> **易错点**：循环里只处理"两个区间都还有货"的情况。这一步做完，**至少有一个区间是空的**，剩下的元素必须由循环后的补偿逻辑收尾。少了这一步，结果数组就会少一截，而且只在"两个区间长度不一样"时才暴露——最容易漏测的情况。

#### 代码：比递归版少一个参数

方法二我们叫它非递归版本。跟之前那个递归版本比，**它少了一个参数**——递归版把 `k`（也就是 `a2` 的写入下标）当成了方法参数，一路往下传；非递归版本里 `k` 从头到尾只服务于这一次合并，所以我们把它收成方法内的局部变量，初值给 `0` 就行。

```java
public static void merge(int[] a1, int mid, int right, int[] a2) {
    // k 只服务于这一次合并，收成局部变量，不必再往下传
    int k = 0;

    int i = 0;         // 区间一 [0 .. mid] 的当前位置
    int j = mid + 1;   // 区间二 [mid+1 .. right] 的当前位置

    // 两个区间都还有元素时，不断把较小的那个搬进 a2
    while (i <= mid && j <= right) {
        if (a1[i] < a1[j]) {
            a2[k] = a1[i];
            i++;
        } else {
            a2[k] = a1[j];
            j++;
        }
        // k++ 从 if/else 里提到外层，两个分支都要做，写一次就够了
        k++;
    }

    // 收尾：至少有一个区间被搬空了，把它的剩余部分整段复制过去
    if (i > mid) {
        // 区间一空了，区间二还有剩
        System.arraycopy(a1, j, a2, k, right - j + 1);
    } else {
        // 区间二空了，区间一还有剩
        System.arraycopy(a1, i, a2, k, mid - i + 1);
    }
}
```

逐段拆一下核心逻辑：

- **`while (i <= mid && j <= right)`**。这里必须用 `<=`，因为下标 `mid` 和 `right` 本身都是**有效元素**，不是"下一个空位"。写成 `<` 会漏掉每个区间的最后一个元素。
- **`if` / `else` 里各写一次 `k++`**。这是最容易写成重复代码的地方——两个分支都要让 `k` 挪位。那就别写两遍，把它提到 `if/else` 结构外面，`k++` 就只出现一次，代码立刻干净不少。这种"两个分支都要做的公共动作"往上一层抽，是很划算的习惯。
- **`System.arraycopy(src, srcPos, dest, destPos, length)`**。这里用系统批量复制而不是手写 `for` 循环，一是意图更清楚，二是数组本来就是连续内存，让底层一次搬完比逐个赋值快。

测的时候把递归版的调用注释掉，换成方法二的调用，跑一遍，得到的合并结果和递归版完全一致。

> **提示**：把两个版本摆在一起对一对，你会发现**主要思路完全一样**，只是形式上代码出现的位置有区别——递归版把"取较小值"这件事交给调用栈去循环，非递归版把它交给一个 `while` 去循环。理解了这一点，归并的两种写法就再也不会混了。

### 队列：排队买商品的那条队伍

接下来我们再学一种数据结构，队列。

队列跟现实生活里非常像：排队买商品、排队做核酸，都是从队尾进来，从队头出去，一动不动地往前挪。计算机里的队列也是**以顺序的方式维护一组数据**，只不过规矩被固定下来了：

> **定义**：向队列的一端添加数据（**尾部 tail**），从队列的另一端移除数据（**头部 head**）。

这一条固定的两端限制，就是队列和链表的全部差别：

```text
链表                          队列
+------------------------+    +------------------------+
| 可以在任意位置插入、删除  |    |  只能在尾部插入          |
+------------------------+    |  只能在头部移除          |
                                +------------------------+
```

链表想在哪儿插就在哪儿插，想删哪儿就删哪儿；队列不行。想从中间插队？插队是要被所有人瞪的。

### 自己定义一个精简的队列接口

接下来看怎么用代码实现队列。

因为我后面可能会提供**多种队列的实现**——有基于链表的、有基于数组的——所以先把接口定义出来，不同实现都往它上面靠。

那这里为什么不用 JDK 自带的 `java.util.Queue`？你看它继承的是 `Collection` 这一个大接口，方法密密麻麻一大片，全实现一遍太累了，**违背了接口的单一职责原则**。所以我自己写一个简化的：

```java
public interface Queue<E> {

    // 向队列尾部插入一个元素，成功返回 true，失败（队列满）返回 false
    boolean offer(E e);

    // 从队列头部取出元素并移除；队列为空返回 null
    E poll();

    // 只获取队列头部的元素，不移除；队列为空返回 null
    E peek();

    // 判断队列是否为空，空返回 true
    boolean isEmpty();
}
```

四个方法的名字都是现成的行业用语，讲清楚它们：

| 方法 | 动作 | 队列为空时 |
| --- | --- | --- |
| `offer` | 提供元素，插到**尾部** | — |
| `poll` | 拉取头部元素并**移除** | 返回 `null` |
| `peek` | 只**看一眼**头部元素，不移除 | 返回 `null` |
| `isEmpty` | 判断是否为空 | 返回 `true` |

`offer` 和 `poll` 是一对：一个进一个出，分守两头。`peek` 和 `poll` 的区别只有"移不移除"这一件事——`peek` 相当于队伍里探头看一眼下一个是谁，`poll` 相当于真的把人叫出来办完事让他走。

### 用链表实现队列：单向环形带哨兵

先看链表版本。原理上非常简单：把之前写过的链表代码拿过来，挑一个改改就行。为了换个心情，我这里用一段**之前没写过的**链表来实现——**单向、环形、带哨兵**。

这三个定语每一个都要认得：

- **单向**：节点里只有 `next` 指针，没有 `prev` 指针。省掉一个指针，也省掉一份同步维护的麻烦。
- **环形**：链表末尾的节点不再指向 `null`，而是回过头来指向头，首尾相连成环。
- **带哨兵**：有一个专门的头节点**不出现在数据里**。它的作用就一个——**简化空链表时的添加和删除**。没有哨兵的话，"链表为空"和"链表只有一个元素"是两种完全不同的处理分支；有了哨兵，这两种情况被拉平成了同一种。

#### 从图上倒推：这个类该有哪些属性

属性不要凭感觉加，**看图倒推**。看这张空队列的图：

```text
      head ═►[哨兵]◄═ tail
                 ⇕  next 指回自己
                 ⇒ head == tail ⇒ 队列为空
```

至少得有两个指针：一个 `head` 指向头节点，一个 `tail` 指向尾节点。初始状态下它们俩指向**同一个哨兵节点**。

哨兵节点的值是无所谓的，我们给个 `null`。还有一个绕不开的问题：环形链表要求 `tail.next` 指回头，可现在 `tail` 和 `head` 是同一个对象，等价于"哨兵的 next 指向哨兵自己"。这跟之前讲双向环形链表时是一模一样的场景。

> **易错点**：这一句 `tail.next = head` **没法在字段声明处写**。因为写它的时候，头节点对象可能根本还没被创建出来。必须放到对象创建完成之后的地方去执行。

所以属性和初始化长这样：

```java
public class LinkedListQueue<E> implements Queue<E>, Iterable<E> {

    // 头节点指针，始终指向哨兵
    private final Node<E> head;
    // 尾节点指针，初始与 head 指向同一个哨兵
    private final Node<E> tail;

    private int size;      // 当前节点数
    private int capacity;  // 队列容量上限

    // 哨兵与环的接线：无参构造和有参构造都要用，抽成初始化语句块
    {
        this.head = new Node<>(null);
        this.tail = this.head;
        this.tail.next = this.head;
    }
    ...
}
```

再说两处设计。

**第一，`Iterable<E>` 不是必须的**，加上纯粹是为了将来迭代和测试方便。

**第二，节点类要用泛型。** 这里引出泛型的两个好处：

1. 可以用 `null` 了。之前我们节点里的值一直是 `int`，用 `int` 就没法表示"没有值"这种特殊情况——**"不存在"是需要被表达出来的**，队列为空时 `poll` 和 `peek` 都要返回 `null` 来表示"没东西可拿"，没有泛型这条路走不通；
2. 泛型能代表更多类型。不光是整数了，小数类型可以，自定义的 `student` 类型也可以。

```java
private static class Node<E> {
    // 单向链表，所以只要一个 next
    private Node<E> next;
    // 这一回 value 可以是任意类型了
    private E value;

    public Node(E value) {
        this.value = value;
    }
}
```

#### offer：改动三个指针

`offer` 是往队列尾部插一个值。就跟现实中排队一样，**只能从队尾排进来**——你总不能从队伍中间插，或者从队头插进去，那叫插队。

插入的过程中，**一共只改动三个指针**。看图：

```text
  插入前（空队列）              插入后（队列里只有一个 1）

  head ═►[哨兵]◄═ tail          head ═►[哨兵] ──► [1] ◄═ tail
         ⇕ self                        ▲              │
         next 指自己                   └──────────────┘
```

1. **旧尾巴的 `next` 指向新节点**。原来队列是空的，旧尾巴就是哨兵本身，所以这一步就是"哨兵的 `next` 指向新节点"；
2. **新节点的 `next` 指向头**。新节点成了新尾巴，环形链表要求尾巴回到头。注意这里：**如果链表不是环形的，尾巴的 `next` 指向 `null` 就行了**；正因为是环形，才必须回头；
3. **`tail` 指向新节点**。新节点正式成为队尾。

思路清晰，代码就直写：

```java
@Override
public boolean offer(E e) {
    if (isFull()) {
        return false;
    }
    Node<E> node = new Node<>(e);
    node.next = this.head;   // ② 新尾巴的 next 回到头
    this.tail.next = node;   // ① 旧尾巴的 next 指向新节点
    this.tail = node;        // ③ tail 前移
    size++;
    return true;
}
```

返回值的意思是：插入成功返回 `true`，插入失败返回 `false`。现在先返回 `true`，`false` 的情况要等我们考虑了容量之后才会出现，现在还没有。

测试很简单：建一个队列对象，调五次 `offer`，把 `1 2 3 4 5` 依次塞进去。因为是从尾部插入的，队列里元素的顺序跟插入顺序一致，跑一遍全通过。

> **结论**：从这段代码能明显感觉到，**队列比链表好实现**。链表可以在任意位置插入删除，什么都要考虑；队列被死死限制在头尾两个口上，复杂的情况全都被挡在外面了。

#### 迭代器：从 `head.next` 开始走

`iterator` 很简单，`new` 一个迭代器对象，里面声明一个指针 `p`，**泛型自然也要加上**。

指针从哪儿开始迭代？**从 `head.next` 开始**。因为哨兵本身不参与迭代，它不是数据。然后每次循环：先把指针所在节点的值记下来返回，再让指针向后走一步（`p = p.next`）。

那什么时候走到头？环形链表没有 `null` 可判断，所以判断条件是：**当 `p` 又指向哨兵的时候，说明走完一圈了**。

```java
@Override
public Iterator<E> iterator() {
    return new Iterator<E>() {
        // 从哨兵的下一个开始，哨兵不参与迭代
        private Node<E> p = head.next;

        @Override
        public boolean hasNext() {
            return p != head;   // 又回到哨兵就走完一圈了
        }

        @Override
        public E next() {
            E value = p.value;
            p = p.next;
            return value;
        }
    };
}
```

#### `isEmpty` 与 `peek`

`isEmpty` 问的是"这个队列空不空"。不用额外记状态，**看 `head` 和 `tail` 两个指针就行**：

- 空的时候，`head` 和 `tail` 都指向哨兵，两者相等；
- 加入了 `1`、又加入了 `2` 之后，`head` 指向头节点、`tail` 指向尾节点，两者不相等。

所以什么时候这两个指针**不相等**，就表示队列非空。

```java
@Override
public boolean isEmpty() {
    return head == tail;
}
```

`peek` 是只取头部值、不移除。比如队列里有个 `1`，我 `peek` 一下拿到 `1`，但 `1` 读完还留在队列里。

先考虑空的情况：如果队列只有哨兵、没有别的节点，就返回 `null`，表示没有值可取。非空的话，`head` 是哨兵，那 `head.next` 就是第一个节点，直接返回它的 `value` 就行。代码极简：

```java
@Override
public E peek() {
    if (isEmpty()) {
        return null;
    }
    return head.next.value;
}
```

> **提示**：这里 `isEmpty()` 判空之后才去取 `head.next.value`，顺序不能反。空的队列里 `head.next` 是哨兵自己，哨兵的 `value` 恰好也是 `null`，虽然结果"碰巧"是对的，但那是巧合，不是逻辑。**判空这一步是显式的契约，不要指望它自己碰对。**

测试这边：空队列 `peek` 应该返回 `null`；加一个节点 `1` 之后返回 `1`；再加一个节点 `2`，返回的**还是 `1`**——因为 `2` 在后面，队头没动。三条都跑通。

#### `poll`：删掉的节点如果正好是尾巴

`poll` 要求取出第一个节点的值，**并且把这个节点从队列里删掉**。

删 `1` 怎么删？就是让哨兵的 `next` 直接指向 `2`，把 `1` 跳过去——`1` 就被"跳过去"了，也就意味着它被删掉了。

```text
  poll 之前                poll 之后

  [哨兵] ──► [1] ──► [2]   [哨兵] ──────────► [2]
     ▲                                ▲
     └──────── head                   └─ head.next 直接跳到 2
```

代码写出来：

```java
@Override
public E poll() {
    if (isEmpty()) {
        return null;
    }
    // 第一个节点就是哨兵的 next
    Node<E> first = head.next;
    head.next = first.next;   // 把 first 跳过去
    if (first == tail) {
        tail = head;          // 特殊情况：删的正好是尾节点
    }
    size--;
    return first.value;
}
```

**`if (first == tail)` 这一句是这段代码里唯一的难点，也是最不能省的一句。**

我们拿"队列里只剩一个节点"的情况试一试：假设队列里就剩 `1`，那 `head.next` 就是 `1`，而 `1` 的 `next` 指向谁？因为环形，它指向哨兵。于是 `head.next = first.next` 执行完之后，哨兵的 `next` 又指回了哨兵自己——队列确实空了，这没问题。

可是 `tail` 呢？`1` 已经被删了，`tail` 却还指着那个已经不存在的 `1`！这指针就悬空了，`isEmpty()` 也会误判。**只有当被删节点恰好是尾节点时**——也就是队列只剩一个元素的时候——我们必须把 `tail` 重新拉回哨兵。

而多于一个的时候，删掉头节点，`tail` 指向的尾节点根本没动，不用管它。

> **易错点**：判断条件是"**被删除的节点 `first` 等于 `tail`**"，而不是"队列里只剩一个元素"。写成后者你还得额外维护一个计数，很麻烦；写成前者只多一个判断，而且语义上更准确——**尾节点被删了，尾指针就得重置**。

测试用例是提前准备好的：往队列里加 `1 2 3 4 5`，第一次 `poll` 移除队头的 `1`，断言返回 `1`；第二次返回 `2`，第三次 `3`，第四次 `4`，第五次 `5`。**第六次再调用时队列里已经没有元素了，断言它返回 `null`。** 跑一遍，单元测试全通过。

### 给队列加上容量：满了就得返回 false

到这儿这个队列就算讲完了。但真拿去做队列，还差一个现实里绕不开的东西：**容量**。

队列不是可以无限往里塞数据的，它总得有个上限。假设最大容量是 `10`，那前十个元素用 `offer` 都能正确加进去；**加第 11 个的时候，它就该返回 `false` 了**——表示队列满了，加不进去了。

所以接口上再加一个方法，判断队列是不是满了：

```java
// 检查队列是否已满，满返回 true
boolean isFull();
```

#### `size` 与 `capacity` 两个新属性

问题是，光靠现有的 `head` 和 `tail` **判断不出满没满**。所以得加两个属性：

| 属性 | 含义 | 变化 |
| --- | --- | --- |
| `size` | 当前节点数 | `offer` 时 `++`，`poll` 时 `--` |
| `capacity` | 队列容量上限 | 固定不变 |

两个都应该是 `private` 的。

`size` 是变化的：调 `offer` 加了个节点，`size` 加一；调 `poll` 删了个节点，`size` 减一。

`capacity` 可以在创建队列的时候由使用者自己指定，所以要加一个有参构造；如果使用者不指定，就默认容量为 `Integer.MAX_VALUE`，**表示容量不受限制**，尽可能往里放；指定了的话，就以指定的为准。

```java
public LinkedListQueue() {
    // 不指定容量 ⇒ 无上限
    this(Integer.MAX_VALUE);
}

public LinkedListQueue(int capacity) {
    this.capacity = capacity;
}
```

> **提示**：`tail.next = head` 这一行在有参构造里也得写一遍，两个构造方法里有重复代码。在 Java 里遇到这种情况，可以把它抽到**实例初始化语句块**（一对大括号）里，所有构造方法共用的那段"公共代码"放进去，代码立刻清爽很多。

```java
{
    this.head = new Node<>(null);
    this.tail = this.head;
    this.tail.next = this.head;
}
```

> **易错点**：用初始化语句块的前提是——被赋值的字段**不能在构造方法体里再赋一次值**。Java 的执行顺序是"字段初始化 → 初始化语句块 → 构造方法体"，语句块执行的时候构造方法体还没跑，所以 `head`、`tail` 必须在这两个阶段完成赋值，构造方法体只留给 `capacity` 这类按参数决定的字段。否则 `this.tail` 在语句块里还是个 `null`。

#### `offer` 加装前的满员检查

现在 `offer` 要改的地方很清楚了。刚才不考虑容量时，你可以不断建新节点往里塞；现在考虑了容量，就**必须在添加之前做一次检查**：

如果 `size == capacity`（比如容量上限设成 `10`，`size` 已经涨到 `10` 了），你还能再加新节点吗？加不进去了。这就相当于队列满了，**直接 `return false`，让添加失败**。

而且这个判断我们刚才已经专门写了一个方法了——`isFull`。所以别在 `offer` 里手写 `size == capacity`，直接换成 `isFull()` 的调用：

```java
@Override
public boolean isFull() {
    return size == capacity;
}

@Override
public boolean offer(E e) {
    // 满了直接失败，后面的添加操作终止
    if (isFull()) {
        return false;
    }
    Node<E> node = new Node<>(e);
    node.next = this.head;
    this.tail.next = node;
    this.tail = node;
    size++;
    return true;
}
```

容量这一块一共做了这么几件事，稍微捋一下：**加了两个属性 `size` 和 `capacity` 表示当前节点数和队列容量；两者相等时就表示队列已满、已满就不该再添加；`size` 今后在新增元素和删除元素的时候都要同步更新。**

测试用例用的是一个容量为 `3` 的有参构造。加 `1 2 3` 没问题；再 `offer(4)`、`offer(5)` 就加不进去了——`isFull()` 已经拦下来了，`offer` 返回 `false`，`4` 和 `5` 根本没被真正加入队列。所以最终队列里的元素期望值仍然是 `1 2 3`。跑一遍，通过。

到这儿，用链表实现的这个队列就彻底讲完了。

## 环形数组实现队列：从下标绕回到整数溢出
> 对应块：BLK24 | 覆盖分集：P94-P98 | 块标题（分集名）：《基础数据结构-062-队列-环形数组实现-方法1》

前面我们用链表把队列实现了一遍。今晚换一条路——用数组。

但一上手你就发现别扭：普通数组的尾巴是死的，出队一次就得把后面所有元素往前搬一格，$O(n)$，白瞎了数组本身的好。

所以这一讲的主角是**环形数组**：一个大小固定、首尾相连的数组。它看起来是个环，物理上还是个老老实实的线性数组，我们只是用程序控制，让它的索引走到末尾之后又回到零。

这一讲分两条线走完。前半段把方法一从头敲一遍——头尾指针本身就存着索引；后半段换一种思路，让指针只管一直加、用的时候再取模，顺手挖出一个普通测试用例死活测不出来的整数溢出坑。

### 环形数组到底是个什么东西

说白了就一句话：**大小固定、首尾相连的数组**。

```text
        索引:   0    1    2    3    4
              ┌────┬────┬────┬────┬────┐
              │    │    │    │    │    │
              └────┴────┴────┴────┴────┘
                ↑                    │
                └────────────────────┘
                  走完 4，下一步又回到 0
```

读图就知道：索引的有效范围还是 `0 1 2 3 4`，只不过走完 4 之后下一个不是 5，而是绕回 0。所谓的"环"，完全是程序在控制，不是内存布局变了。

> **定义**：环形数组 = 物理上仍然是普通的线性数组，只是让索引在使用时可以循环回绕，从而在逻辑上构成一个环。

名字里带个"环"，好处是实打实的。既然索引会自动绕回来，**越界这个问题就不存在了**——走到末尾它自己就回到零，你根本不用写那句"如果超过长度就归零"的判断。

另外一条隐形优势：它毕竟还是数组。我们以前讲数组的时候说过，它能充分利用**局部性原理**、吃到 CPU 缓存的红利，访问速度比链表快得多。环形数组把这个优点完整保留了下来。

> **结论**：环形数组特别适合实现**有界队列**，以后还会遇到的 ring buffer，也都是这个套路。

### 换掉普通数组，省掉的那次 $O(n)$

先做个对比。用普通数组实现队列，无非两个操作：**从尾部入队**，**从头部出队**。

入队还好。数组里已经有 `a b c d`，我往尾部添一个 `e`，随便找个空位放进去，时间复杂度是大 $O(1)$，完全可以接受。

出队就难看了。假设把 `a` 移走：

```text
移动前:  [ a ][ b ][ c ][ d ]
           ↑
           head 必须在索引 0

移动后:  [   ][ b ][ c ][ d ]
             ← b 顶上
                 ← c 也得挪
                     ← d 也得挪
```

`b` 要当新的头，就得占掉原来 `a` 的位置；`b` 之后的所有元素，也都得跟着往前平移一格。一共 $n$ 个元素全动，时间复杂度直接飙到 $O(n)$。

**为什么这么别扭？因为普通数组的头和尾是固定的——必须是索引 0 才能当头。**

环形数组就自由多了。同样把 `a` 移走，其他元素一个都不用动，只要让头指针往前指一格，让索引 1 上的 `b` 成为新的头：

```text
出队后:  [   ][ b ][ c ][ d ]
             ↑
             head 挪一格，元素原地不动 → O(1)
```

环形数组里**任意一个索引位置都能当头，也能当尾**，起点和终点都不再被钉死在零上。数据一个字节都不用搬。

> **易错点**：普通数组出队慢，根子不在"数组"这个结构上，而在"头尾固定"这个约定上。是约定僵住了，不是数组慢。

### 要点一：下标是怎么绕回来的

动手写之前先解决两个要点，第一个就是**怎么算环形数组的下标**。

假设环形数组长度是 5，有效索引只有 `0 1 2 3 4`。现在当前位置是 3，我要往前走两步，落点应该在哪儿？

画一下就很清楚：3 往前走两步，没有 5 了，绕回来变成 **0**。

那这个 0 是怎么算出来的？先按普通的方式加：$3 + 2 = 5$；再拿这个 5 去除以数组长度 5，看余数——余数是 **0**，这就是正确的索引位置。

换个步数验证一下。往前走三步：$3 + 3 = 6$，$6 \div 5$ 的余数是 **1**。对上了。

于是公式就出来了：

$$(\text{当前位置} + \text{前进步数}) \bmod \text{数组长度}$$

> **结论**：环形数组任意一步的落点，等于"当前位置加步数"再对数组长度取模。

公式本身简单得不像话，但**你得知道它是怎么来的**，不然代码里写一个 `+ 1` 都心里没底。老规矩，先把这句记住，后面每一处求模都用它。

### 要点二：空和满，怎么判

第二个要点是判空和判满。实现队列至少要两个指针，我用蓝色箭头表示头指针 `head`，红色箭头表示尾指针 `tail`。

刚一开始，两个箭头都指向索引 0。此时 `0 1 2 3 4` 一个元素都没存，整个队列是空的。

#### 判空：两个指针重合在一格

**入队**是往 `tail` 指向的位置塞一个新元素，然后 `tail` 往前挪一格。比如塞了个 `a`：`arr[tail] = a`，写完 `a` 之后 `a` 就从指针位置"擦掉"了，`tail` 落到索引 1。这时队列里有东西了，大小是 1，容量还是 5。

**出队**是把 `head` 指向的元素移除，然后 `head` 往前挪一步。比如把 `a` 拿掉、不要了，蓝色箭头落到索引 1，`b` 成为新的头。

这一来一回，判空的条件就出来了：**头尾指针指向同一个位置，队列就是空的**。

> **结论**：`head == tail` ⟺ 队列为空。反过来只要两者不指向同一格，队列就非空。

#### 判满：那最后一个位置别放东西

顺着往下想判满。往队列里连着加 `a、b、c、d`，`tail` 一路挪到索引 4 之后会绕回索引 0。这时候还能不能再加一个 `e`？

有同学说：能啊，不是还空着索引 0 这一格吗。加吧。

问题就出在这儿。加完 `e`，`tail` 继续前进，落到索引 1——**跟 `head` 重合了**。

可我们前面刚定下判空的条件：头尾指向同一格就是空。现在队列里明明装着 `a b c d e` 五个元素，一点都不空，却被判成了空。**两个条件撞车了，这就是矛盾。**

所以最好不要这么干。**最后一个位置我们空着，不存元素，专门留给 `tail` 指针用。** 也就是说，长度为 5 的数组，队列里实际只能装 4 个元素。

判满的条件随之而来：

$$(\text{tail} + 1) \bmod \text{数组长度} == \text{head}$$

也就是**尾指针再往前走一步，如果落点跟头指针重合，就说明满了**。

```text
长度 5，只装 4 个，索引 1 这一格永远空着给 tail

  [ a ][   ][ b ][ c ][ d ]
    ↑              ↑
    T              H

  tail 停在索引 1 时：(tail + 1) % 5 == 2 ≠ head，还没满
  tail 停在索引 2 时：(tail + 1) % 5 == 3 ≠ head，还没满
  ...
  tail 停在索引 0 时：(tail + 1) % 5 == 1 == head → 满
```

这里有个细节要抠清楚：为了通用，**`tail + 1` 之后还得再对数组长度取模**。我们这个例子里长度是 5，就得模 5。不模的话，`tail` 在索引 4 时算出 5，5 压根不是合法索引。

> **提示**：后面还会介绍更多判空判满的办法，空指针法只是比较常用的一种，先把它彻底搞明白。

### 方法一：head 与 tail 本身就存着索引

要点理清了，写代码就非常容易。我准备了一个 `ArrayQueue1`，实现我们之前的 `Queue` 接口，把它改成环形数组的实现。

#### 字段和构造方法

先把数组定义好，用泛型，是一个 `E` 类型的数组，我们叫它 `arr`。然后是头指针和尾指针——注意，这两个指针将来就是数组里的索引位置，所以用 `int` 存就够了。

两个指针的初始值都是 0。头指针叫 `head`，尾指针叫 `tail`。

再写一个带参构造，因为**你得通过它告诉队列的容量**。参数传一个 `capacity`。

这里就要把前面那个"留一格给 `tail`"的结论用上了：既然环形数组必须专门留一个位置存 `tail` 指针，它不能存数据，那么实际的数组大小应该是**你期望的容量加一**。我期望存 4 个数据，实际数组大小就该是 5。

```java
@SuppressWarnings("unchecked")
public ArrayQueue1(int capacity) {
    // 环形数组要专门留一个位置给 tail 指针，所以实际大小是期望容量 + 1
    arr = (E[]) new Object[capacity + 1];
}
```

创建出来的是 `Object` 数组，这里要做一次类型转换；不想让它报警告，就加上 `@SuppressWarnings` 这个注解。

#### isEmpty 与 isFull

先实现这两个最简单的，也是接口里定义的 `isEmpty` 和 `isFull`。

判空特别好写：刚才说过头尾指针取值相等就是空。

```java
public boolean isEmpty() {
    return head == tail;
}
```

判满的结论前面也给出了：尾指针再前进一步，取模后的索引位置等于 `head`，就表示队列已经满了。

```java
public boolean isFull() {
    return (tail + 1) % arr.length == head;
}
```

#### offer：先判满，再写 tail

`offer` 是向队列尾部新增元素。新增之前当然要先判断一下——如果队列已经满了，那就不用新增了，用我们刚写的 `isFull` 判断，满就 `return false` 表示新增失败。

没满就走下面的逻辑：往队列尾部加入新元素。怎么找到队列尾部？是不是有那个 `tail` 指针？直接通过 `tail` 这个索引找到队列的尾部位置，把新值赋给它就行了。

然后尾指针要前进一步。这里有个小陷阱：直接写 `tail = tail + 1` 行不行？**不行**。万一 `tail` 恰好是 4，加一不能加到 5 去，你得变成零。

所以记着那个公式，**加一之后再对数组长度取模**，这样才能保证索引始终在有效范围内，不至于超过它的有效范围。

```java
public boolean offer(E e) {
    if (isFull()) {
        return false;
    }
    arr[tail] = e;
    tail = (tail + 1) % arr.length;   // 关键：加一之后要模回长度
    return true;
}
```

#### poll 与 peek：一个动指针，一个不动

`poll` 是从队列头部移除元素。同样先判断，队列已经空了的话返回 `null`，表示没有可移除的。

不空的话，就根据头指针的位置拿元素：`arr[head]` 就是要返回的值。返回之前头指针也得往前挪一步——比如刚才那个 `a` 被移走了，头指针就该指向索引 1，让 `b` 成为新的头。跟 `offer` 一样，为了避免越过有效索引范围，要取模。

```java
public E poll() {
    if (isEmpty()) {
        return null;
    }
    E value = arr[head];
    head = (head + 1) % arr.length;
    return value;
}
```

`peek` 跟 `poll` 非常像，也是先判断，为空就返回 `null`。区别在于：它不用让 `head` 指针移除，它只是**去获取**头部的元素，不动指针。所以它更简单，直接 `return arr[head]` 就可以了。

```java
public E peek() {
    if (isEmpty()) {
        return null;
    }
    return arr[head];   // 不动 head
}
```

#### iterator：遍历也是一圈一圈的

还差一个迭代器方法。这个我们都写过很多遍了：创建一个迭代器对象，设置一个指针，还是叫 `p`。

`p` 的初始值应该是从 `head` 这块开始。什么时候结束？**当 `p` 跟 `tail` 相等的时候**，表示没有元素了，退出循环。所以循环条件就是 `p != tail`，每次循环通过 `p` 拿到数组元素的值并返回。

那 `p` 每次也要往前进。加一就完了吗？没有，`p` 加一有可能从 4 加到 5 去了，所以也得给它做一个求模运算，括号括起来，对数组长度取模，算出来的这个索引值作为 `p` 下一次的值。

```java
@Override
public Iterator<E> iterator() {
    return new Iterator<E>() {
        int p = head;              // 起点是 head

        @Override
        public boolean hasNext() {
            return p != tail;      // 追上 tail 就没元素了
        }

        @Override
        public E next() {
            E value = arr[p];
            p = (p + 1) % arr.length;   // p 同样要模
            return value;
        }
    };
}
```

到这里 `offer`、`poll`、`peek` 三个方法全部完成。测试用例我不细看了——基本是把之前链表实现那个测试用例拿过来改改，把实现类名从 `LinkedListQueue` 换成这里的 `ArrayQueue1`，其余照旧，节省时间跑一遍。添加、移除、`peek` 等等都测到了，都通过。

基于环形数组实现的队列，方法一就完成了。

### 头尾指针只管一直加，用的时候再算

上一集我们介绍过两种判空判满的办法：一种是只用 `head` 和 `tail` 两个变量，靠它们判断空还是满；第二种是引入一个新的辅助变量 `size`，用 `size` 判断队列的空和满。

这两种办法，其实在我看来都不是最好的做法。下面再来看一种。

先回到方法一。它的 `head` 和 `tail` 代表什么呢？它俩代表的就是我们的头和尾，**并且它存储的就是真正计算后的那个索引值**——`head` 里存的是头指针计算后的索引，`tail` 里存的是尾部计算后的索引。每次为了防止越界，我们都跟数组长度做了求模运算，求模之后的结果存到 `head` 和 `tail` 里。

那我们能不能转换一下思路？**让 `head` 和 `tail` 不要存储这个计算结果**，它们就只是一个不断递增的指针值。有新元素入队就让 `tail` 加一，有旧元素出队就让 `head` 加一，它就不断递增。

但是最终我们用到索引值的时候，这个计算的结果**不用 `head` 和 `tail` 来保存，随用随计算**，什么时候用到什么时候去算。

#### 容量三，走一遍

新做法下，假设数组容量是 3，里面最多存三个元素，创建出来自然就有索引 0、1、2。`head` 初始是零，`tail` 初始也是零。

我开始往里存元素：

```text
第 1 次: tail = 0 → 存 a 到索引 0 → tail 自增成 1
第 2 次: tail = 1 → 存 b 到索引 1 → tail 自增成 2
第 3 次: tail = 2 → 存 c 到索引 2 → tail 自增成 3
第 4 次: tail = 3 → 3 不能直接当索引用（有效索引只有 0/1/2）
                  → 3 % 3 = 0 → 存 d 到索引 0
```

看到了吗：`tail` 一开始正好对应着我们要存储的索引位置，但自增到 3 之后就超出了有效范围。而这也不难办——**把 3 拿去对数组长度求模，余数是零**，下次再存就知道该往索引 0 存新元素了，比如存个 `d`。

所以 `tail` 就是一个不断自增的整数，每次把它的结果跟数组长度求模，求得的余数作为索引。

`head` 的处理是类似的，它也是一个不断递增的整数，这里先不展开分析。

> **易错点**：新实现和旧实现的唯一区别就是——旧实现里 `head`、`tail` 本身**存的就是索引**；新实现里它们**只是不断递增的整数**，必须先计算才能得到索引。搞混这一点，后面所有代码都会写歪。

#### 各个方法怎么改

有了思路，代码就简单了。`head` 和 `tail` 初始值都是零，数组在构造方法里初始化。

这里有个明显的好处：**数组的长度就是我们的容量，不需要像之前那样给 `tail` 预留一个空位了，不需要加一。** 另外，因为这个数组以后不可能再被重新赋值，所以它可以看作一个常量，用 `final` 修饰一下。

先看 `offer`，大家可以对比之前的代码做参照。同样先判断队列是不是已经满了，满了就 `return false`。没满的话，根据尾指针找到它**正确的**索引位置——那不就是 `tail` 对数组长度取模吗，公式就列在上面了。找到索引，把值赋成 `value`。添加完之后，尾指针往前走一步，也就是 `tail++`，最后 `return true`。

```java
public boolean offer(E e) {
    if (isFull()) {
        return false;
    }
    arr[tail % arr.length] = e;   // tail 不是索引，用的时候现算
    tail++;
    return true;
}
```

新旧实现的改动就在这儿，一句话说清：**新的实现里 `tail` 本身不是索引，要根据它算出索引再往那个位置赋值，然后 `tail` 加加；旧的实现里 `tail` 本身就是索引，能直接找到位置，但加完元素之后要把它**下一次**的索引（`tail + 1` 再模数组长度）算出来存回 `tail` 里。**

`poll` 是从队列头部移除元素。先判断队列是不是空的，空的话没什么可以出的，只能返回 `null`。不空的话，先根据 `head` 找到它的索引位置，方法跟上面一样，也是 `head % arr.length`。把这个索引位的值返回就行了。返回之后 `head` 要往后走一步，把当前这个元素跳过去，所以是 `head++`。

```java
public E poll() {
    if (isEmpty()) {
        return null;
    }
    E value = arr[head % arr.length];
    head++;
    return value;
}
```

`peek` 跟它差不多，也是获取头部元素但不移除。所以代码其实就差了 `head++` 那一行，我们直接复制过来一份，把 `head++` 去掉就行了——只是获取元素，不让 `head` 指针往后走。复制过来的那两行也可以合成一行。

判空还是老样子，`head == tail` 就是为空，两个指针重合了，队列中自然没有元素。

判满跟以前**不一样**了：

$$(\text{tail} - \text{head}) == \text{数组长度}$$

`tail` 是尾巴，`head` 是头，**尾巴减掉头，不就是从头到尾它的一个距离吗**。当这个距离等于数组长度时，意味着什么？意味着满了。这个距离其实就是你从头到尾放的元素个数，元素个数等于数组长度，那可不就是表示队列满了。

```java
public boolean isFull() {
    return tail - head == arr.length;   // 尾巴减头，就是从头到尾的距离
}
```

#### 迭代器也要先换算

`iterator` 定一个指针 `p`，起点是 `head`，每次往前走一步。注意这里的 `p` **它不直接对应索引**，也得换算成索引——每次要根据 `p` 对数组长度取模，才能算出它的索引位置。

把这个索引位置的值拿到，每次遍历的时候返回它。指针每次要自增，`p++`。什么时候是个头？当 `p` 等于 `tail` 的时候，应该结束循环；`p != tail` 就不断循环。

至此，用新思路改写的代码完成了，测试用例还是把之前那个改改，跑一遍，看着都过了。

### 不容易测出来的坑：整数溢出

有同学问：这块代码写得还有没有问题？**还真就存在一个问题，而且不容易测出来。**

问题还是出在 `head` 和 `tail` 上。它俩是两个整数值，我们的算法里都是让它俩不断自增、不断自增——**我们并没有去考虑它自增超过正整数最大值会怎么样。**

#### 先把 bug 复现出来

我其实又准备了一个测试用例，刚才被我注释掉了，现在把它打开。

```java
@Test
void testOverflow() {
    // 为了让这个测试用例能跑通，先把 head / tail 前面的 private 去掉
    ArrayQueue3<Integer> queue = new ArrayQueue3<>(10);
    queue.head = 2147483640;

    for (int i = 0; i < 10; i++) {
        queue.offer(i);
        System.out.println("tail = " + queue.tail
                + ", 算出来的索引 = "
                + Integer.toUnsignedLong(queue.tail) % queue.arr.length);
    }
}
```

`head` 的值被顶到了 `2147483640`。**`int` 正整数的最大值是多少？是 `2147483647`。注意看，它是不是差一点就会超过这个范围了。**

然后我创建了一个容量为 10 的队列，循环十次，用 `offer` 往里面添加元素。按理讲，这十个数应该都能加进去——从 0 到 9，队列容量也是十，都能加进去。但实际跑一遍，**报错了**。

错误信息说：他要访问索引 `-8` 的时候出错了。有 `-8` 这个索引吗？没有啊，所以他肯定报错。

#### 为什么前八次都没事

我们把每次调用 `offer` 之前 `tail` 的值，和它算出来的索引值都打印出来看。

```text
第 1~8 次：tail = 2147483640 … 2147483647
            索引 = tail % 10 → 0 … 7            全部合法

第 9 次：  tail = 2147483647 + 1 = 2147483648
            int 装不下 → 由正变成负，溢出成 -2147483648
            -2147483648 % 10 = -8              ← 数组里根本没有 -8 这一格
```

大家看，前八次都没问题。刚开始 `tail` 是 `2147483640`，然后 `2147483641`，当然它们算出来的索引都是 0、1、2 这些合法值。

一直到**第九次**的时候，`2147483647` 再加一，已经超过了正整数的最大值了，变成一个负数。负数再去求索引，算出来的索引也是个负数了，于是就出现了刚才那个错误。

所以我们得把这个边界条件考虑进去。**为什么这个问题不容易复现？因为你用普通的测试用例，它的 `head` 和 `tail` 自增不到那么大的数，因此暴露不出来问题。必须把它们的取值设得比较大，才能把这个bug 挖出来。**

#### C 语言的解法，和 Java 的绕法

问题的原因我们知道了，怎么解决？

先看一个"很爽"的解法。咱们都听过 C 语言吧，C 语言里有一种数据类型叫 `unsigned int`，无符号的 `int` 整数。什么叫无符号？就是这个数字存储的时候不考虑符号位了，**它只能代表零和正数**，存储范围是从 0 一直到 $2^{32} - 1$。

那如果我们把 `head` 和 `tail` 的数据类型改成这种无符号的 `int`，当它自增到最大值了再次增会怎么样？**它就又回过头来从零开始。** 所以它再怎么自增，最终它的数字永远是一个零和正数，你最后去求个模，计算出来的索引总是一个合法的，没问题。

如果是用 C 语言，解决这个问题很简单，把 `head` 和 `tail` 改成无符号 `int` 就完了。

但很遗憾，我们现在用的是 Java。**Java 语言有这种无符号的整数吗？没有。** 那怎么办呢？我们采用一种迂回的办法。

Java 里有一个 `Integer` 包装类，包装类里有一个叫 `toUnsignedLong` 的方法。它是干什么的呢？把我们原本超过了 Java 中 `int` 最大正整数之后、溢出变成负数的那个数，**重新转换成一个更大的 `long`**——`long` 是不是能表示 `int` 不能表示的值？是的。所以我们可以用它来解决。

```java
arr[(int) (Integer.toUnsignedLong(tail) % arr.length)] = value;
```

这里有两个细节，我都踩过：

第一，**求余数之前先转成 `long`**。本来到第八次、第九次它都会变成负数、超过范围，但我把超过范围的数转换成这个长整型，它相当于又能表示这个超大数字了；用长整型再去计算余数，就不会出现负数的问题了。

第二，Java 中数组的索引**只能是 `int`，不能是 `long`**，所以最后还得转回 `int`。不转回来它照样报错。

所以所有涉及余数计算的地方，都照这个样子改一遍——先转 `long`，求余，最后转 `int`。`head` 那一处用同样的方法包起来，迭代器遍历的时候也需要转一下。

改完之后回到刚才那个测试用例，把注释打开、把临时代码去掉再跑一遍，**不报错了**。最后再打印一下队列里的元素值：因为我们每次是把 `i` 加进去、从零加到了九，所以最后打印出来 `0~9` 就对了。这些数字被正确地加入了队列，这就是我们解决这个问题的办法。

> **易错点**：这是环形数组指针实现的经典暗坑。只要指针是"一直自增、用时取模"的写法，就必须配套溢出处理，否则跑上亿次操作后必然崩。**测试用例越普通，越测不出来。**

## 环形队列的位运算优化与二叉树层序遍历
> 对应块：BLK25 | 覆盖分集：P99-P101 | 块标题（分集名）：《基础数据结构-067-队列-环形数组实现-方法3》

### 求模的二进制规律

在介绍解决方法之前，我们先从二进制的角度，把求模运算的一个规律看一遍——这个规律一旦看懂，环形队列后面那一堆 `% array.length` 就能全部拆掉。

先说结论。

> **结论**：当除数是 2 的 n 次方的时候，余数就是被除数二进制形式的**后 n 位**。

前提必须钉死：除数只能是 2、4、8、16……这一串 2 的幂。除数一旦不是这个，规律立刻不成立。

我们随便拿个数验证。被除数选 100，除数选 8（$2^3$），100 ÷ 8 的商是 12，余数是 4——12 乘 8 是 96，96 加 4 正好凑回 100，结果没问题。

再把两侧的二进制摆在一起看。商 12 的二进制是 1100，能不能在被除数里找到它？就在最前面四位，1100 严丝合缝。余数 4 的二进制是 100，也能在被除数里找到，就在最后三位。

```text
100 = 1100100b
      ---- ----
      1100  100
       12    4
```

这个规律我提前先告诉大家，就是当我们的除数是二的 n 次方的时候，那我们直接从这个被除数里，就能找出它的商和余数了。

我们再多走几个例子，验证一下。把被除数换成 111，除数还是 8。算出来商是 13，余数是 7，对不对？被除数 111 的二进制是 1101111，前面的 1101 正好是 13，末三位 111 正好是 7。规律照样成立。

那到底后面几位从几位开始算？我们刚才除的是 8，$2^3$，所以取后三位。那如果除个 16 呢？16 也是二的 n 次方，再算一次：111 ÷ 16，余数变成 15，15 对应的正是被除数的后四位。

> **结论**：如果除数是 $2^n$，那么被除数的后 $n$ 位就是我们要的余数，也就是模。

#### 换个视角：除以二的幂就是右移

当然，我们也可以从另一个角度来理解。还是以 111 ÷ 8 为例。111 除以 2 是不是就相当于右移一位？把最右边这个 1 移没了，这就是除以 2。除以 4 就相当于右移两位，除以 8 就相当于右移三位，这个没问题吧。

我们现在让它右移三位。右移之后剩下的 1101 就是商，被移走的那三位 111 就是余数——这就相当于除不尽的部分。所以"后 n 位是余数"和"除以 $2^n$ 等于右移 n 位"，本来就是同一件事的两面。

不过大家一定要记着，前提是除数必须是二的 n 次方。如果除数不是 $2^n$，那这个规律是不成立的。

#### 用一个掩码把后 n 位抠出来

那么接下来的问题就具体了：除以 8 我知道找后三位，除以 16 我知道找后四位，可是我怎么去求任意一个数二进制形式的最后几位呢？

我们来看一个例子。比如我想求 110 ÷ 8 的余数，最终结果是 6。我们就盯着这个目标去看：我要把它的后三位保留，前面都变成零。要达到这个目的，我们可以找一个特殊的数——它的前五位是零，目的是跟原始这个数的前五位做一个按位与，因为零跟任意数做按位与，结果就是零，相当于把前五位清零了；然后这个特殊数的后三位都是一，一跟原始的数字做按位与，就能把原始的数字保留下来。

```text
x    = 110  ->  1 1 0 1 1 1 0
mask  =   7  ->  0 0 0 0 0 1 1 1
result      ->  0 0 0 0 0 1 1 0   = 6
```

一跟一按位与是一，一跟零按位与是零，后三位就被原样保留了下来。这个特殊的数前五零后三个一，它其实就是个 7。

那 7 跟我们的除数之间有啥关系呢？8 减 1 正好是 7。再看一个，这回要保留后四位，也就是相当于除以 16 求余数，1110 算出来余数是 14。跟 15 做一次按位与就行——15 后面是四个一、前面是四个零，前四位清零、后四位保留，结果就是 14。

所以这个规律很简单：我们要保留任意一个数字二进制的最后几位，怎么办？你就看看我要保留最后几位，如果是四位，那就是二的四次方减一，跟它按位与就行了，$2^4 - 1$ 不就是 16 - 1 = 15 吗。要保留最后三位，就是二的三次方减一，就是 7，跟 7 按位与就可以了。

```text
divisor   8 = 1000b     mask  8 - 1  = 0111     = 7
divisor  16 = 10000b    mask 16 - 1  = 01111    = 15
divisor  32 = 100000b   mask 32 - 1  = 011111   = 31

x & 7    保留 x 的后 3 位  ->  x % 8
x & 15   保留 x 的后 4 位  ->  x % 16
x & 31   保留 x 的后 5 位  ->  x % 32
```

把我们刚才这个按位与运算的规律做一个小结：如果我们的除数是二的 n 次方，那就可以应用下面这个规律——求余数的时候就不用除法这个运算去求了，只要找到被除数的后 n 位就能得到余数；怎么得到后 n 位呢？把被除数跟二的 n 次方减一做一个按位与，就能得到我们要的余数。

### 把规律搬进环形队列

好，套到我们当前这个例子中怎么做呢？被除数是谁？被除数是不是就是我们的 tail、head 这些指针？除数是谁？除数是不是就是数组的长度？所以只要能保证数组的长度是二的 n 次方，我们就可以应用这个规律，替换掉原来的求模运算。

```text
          +-----+-----+-----+-----+-----+-----+-----+
idx  ->   | e0  | e1  | e2  | e3  | e4  | e5  | e6 |
          +-----+-----+-----+-----+-----+-----+-----+
            ^head                         ^tail
```

比如说我已经保证了，你的数组长度肯定就是二的 n 次方，那么怎么做呢？就把它跟数组长度减一，做一个按位与就 OK 了。

```java
// 原来的求模
int index = tail % array.length;

// 改成按位与
int index = tail & (array.length - 1);
```

注意这里不用加括号，因为减法运算优先级高，它是先做完减法再做前面的按位与。如果你不放心，你用一个括号改变一下它的优先级也行。

#### 三处求模，全部换成按位与

改动完这一处，下面代码就是类似的。求 head 指针那个地方，原来除以数组长度求余数的那一坨就不要了，直接改成 `head & (array.length - 1)`；还有一个地方我记得，就是我们遍历的时候，这个 p 这个指针，它同样的也是除以数组长度，做一个按位与就 OK 了。

这样的改动可以说是一举两得。

第一得，我们的按位与运算是要比求模运算性能要更高的。因为求模运算本质上是除法呀，这种位运算它的性能肯定要比你除法的性能要高。

第二得更妙，就是我们不用考虑那个符号位的问题了。因为按位与它总是找到我们这个被除数的后几位，跟你最前面那个符号位有半毛钱的关系？没有，没有啊。所以我们也不用去考虑当 tail 自增变成负数时，它的那个符号位的问题了。

#### tail 溢出成负数，判断满队列还准不准

这里我再插一句，也是你们有可能问的一个问题。我们在之前实现 size 字段方法的时候，是用了 `size = tail - head`，得到从尾到头元素的个数吗？看看元素个数如果等于数组长度，表示这个队列已经满了，这是我们之前写的逻辑。那这段逻辑会不会也存在类似的漏洞呢？

比如说我们的 tail 已经自增超过了正整数的最大值了，变成负数了。那一个负数减去 head——假设 head 还是正数——那负数减正数会不会也得到一个负数，造成这个判断失败呢？

其实这一块儿大家不用担心，我们来试验一下。比如 head 是一个很大的数了，1247483640；tail 已经是正整数的最大值了，为了大家看得清楚，我就直接把它换成那个最大的正整数值，还是那个 47 亿。那接下来呢我让它再向前走几步，再加等于一个、走五步吧，这肯定是超过它的范围了，他肯定会由正变负。我们先打印出来看一下，打印的结果 tail 已经变成负数了。

那这么一个负数减掉这个 head，它能保证正确性吗？我们试一下就知道了。先预料一下，tail 它是向前走的五步，是不是相当于 47 亿 + 5，你先把它当正数看，应该走到 52 了；52 再回过头来减 40，是不是应该计算出来是 12？也就是当前这个元素个数是 12。我们看它能不能计算出那个 12——可以吧。

所以这个大家不用担心啊。虽然 tail 它超过了范围，但是它只要跟原来的数，它的运算结果没有超过范围就行。它减过之后的这个差值没有超过正整数的范围，那我们的结果就是正确的。

但是你想想 `tail - head` 差得能够超过正整数的最大值，也就是 2147483647 吗？超不过，为啥呀？咱们 Java 中数组的最大长度也是这个值。你说从数组的尾部一个指针减掉数组头部这个指针，它能超过数组长度吧？肯定超不过啊。

> **易错点**：`size = tail - head` 能一直算对，依据是**差值不溢出**，而不是 tail 自己不溢出。指针本身溢不溢出、溢成什么值，和这个判断准不准，是两码事。

### 容量凑不齐二的幂怎么办

我们刚才能够进行这样的改动，前提就是除数——也就是数组长度——必须是二的 n 次方。那如果我们类的使用者传过来这个 capacity 不是二的 n 次方怎么办呢？这里有两种策略。

#### 策略一：校验，不对就抛异常

第一种策略就是我检查出来它不是二的 n 次方，那我可以抛一个异常，告诉他你传的这个参数不对，请你传过来一个二的 n 次方作为这个队列的容量。

那怎么判断一个数是不是二的 n 次方？大家可以看一个结论：**只要把这个数跟它减一，做一个按位与，结果是零，它就是二的 n 次方；不是零，就判断出来它不是二的幂。**

我们举几个例子。先挑一个二的 n 次方，8 的二进制是 1000，它减一是 7，是三个 1，它俩做按位与，结果是不是零？结果肯定是零，因为它的零跟 1 正好是错开的。再挑一个 16，16 跟它的减一 15 做按位与，结果是不是零？也是的，你看它的零和一也都是正好错开的，最后按位与的结果仍然是零。凡是这种二的 n 次方，跟它的减一做按位与，它肯定结果是零。

再挑一个反例，比如 14，14 跟减一 13，它俩按位与能是零吗？显然不是，你看它的零跟 1 它不是正好错开的，所以结果是个非零的数。

所以第一种办法很简单，我们就把这个 capacity 和 capacity 减一按位与判断一下，如果它不等于零，那就抛一个异常。

```java
// 必须加括号：先做按位与，再跟零比较
if ((capacity & (capacity - 1)) != 0) {
    throw new IllegalArgumentException("capacity 必须是二的幂，也就是二的 n 次方");
}
```

> **易错点**：写成 `capacity & (capacity - 1) != 0` 是错的。`!=` 的优先级高于 `&`，先去算 `capacity - 1 != 0`，再拿这个布尔值跟 capacity 做按位与，判断的就完全不是我们想要的那个东西了。必须用括号把按位与框住，让它先算完。

> **定义**：一个正整数 x 是二的幂，当且仅当 `x & (x - 1) == 0`。原因很简单：二的幂在二进制里是一个 `1` 后面跟一串 `0`，减一之后正好变成一串 `1`，0 和 1 首尾互补、按位与自然是零。

#### 策略二：向上取整到最近的二的幂

第二种策略就是你本来这个数不是二的 n 次方，但我可以把它改成一个比较接近的二的 n 次方。

举个例子，比如说你传过来的是个 13，13 并不是二的 n 次方，那我就找一个与它最接近、比它大的一个数——找到 16，我就以这个 16 作为我这个数组容量。那如果你传过来是个什么 22 呢，找到它最接近的比它大的二的幂，是 32。总之你不是二的 n 次方，我想办法给你改成一个。

这个"最近且大于"的数怎么找？我们拿 30 举例，做一个分析。二的四次方等于 16，那这个 16 是我们要找的数吗？不是啊，因为 16 比 30 小，我们要找一个比它大的，所以我们尝试它的下一个，也就是二的五次方 32。这个 32 就是我们要找的数，因为它比 30 大，而且也是离它最近的一个二的幂。

那我们怎么根据 30 得到这个 32？你看，30 是介于 16 和 32 之间的，所以将来如果去求二的几次幂，它肯定是二的 4 点某次幂。等于我们这里的 30，其实这个 4 点几后面的小数部分我并不关心，我只要能知道它前面这个整数部分，那它的整数部分加一，是不是就是我们要找的那个二的五次方？这样 32 就能得到。

问题就转换成了：我要求到底是二的几次方等于 30，这不就是求以二为底 30 的对数吗？

```text
30 = 2^4.xxx
     |  |
     |  +-- 小数部分，我不关心
     +----- 整数部分 4，+1 得到 5，再求 2^5 = 32
```

**方法一：借助对数。** Java 里要求以二为底的对数还是比较麻烦的，因为 Java 里面它要求的都是什么以十为底的对数，或者是以那个自然数为底的对数，它没有以 2 为底的。那这个怎么办呢？我们可以做一个转换——要求以二为底某个数的对数，实际上可以把它转换成：先把这个数以十为底数的对数求出来，求出来之后呢，再除以一个以十为底、二的对数就行了。

```java
int n = (int) (Math.log(capacity) / Math.log(2)) + 1;
```

`Math.log(capacity) / Math.log(2)` 算出来是 4 点几，找到以后我们只想保留整数部分、小数部分不要，那么就可以做一个 `int` 的强制类型转换，这就相当于把小数部分舍弃掉了。舍弃之后我们是不是还得加个一？加个一，这就得到了一个数字 n，将来我们要求二的 n 次方就可以了。

30 代进去，打印出来 n 是 5，正是我们要的二的五次方。那怎么根据这个 n 再算出二的五次方呢？很简单，我们用位运算就可以了，只需要把一给它左移 n 位，也就是一左移五位，那就能得到二的五次方。

```java
int newCapacity = 1 << n;
```

为什么？因为一的二进制就是 `1`，左移一位，左边……右侧用零补齐，这个是不是就是二？二就是代表二的二次方……二的**一**次方。然后左移两位就变成 100，这就是二的二次方是那个 4；左移三位，右侧补三个零，这个就是二的三次方是那个 8；以此类推，左移四位是二的四次方，左移五位就是二的五次方 32。

当然这个代码里有一个小漏洞。什么漏洞呢？就如果他传过来这个数原本就是二的 n 次方，比如说它传过来的就是 32，那你按我们刚才这个逻辑去算一下，算一下发现是不是被变成 64 了？哎，他就找了下一个数字了。其实这种情况下，我们是不是应该保留原来的 32 就行了，因为它传过来的本来就是二的幂，那我们就不用再去找下一个了。

这种情况怎么办呢？非常简单，我们只要把原始这个数给它先减一，再求对数——先减一，再求对数，那么这回又能保证它的正确了。这个减一怎么来的，大家也要知道。

```java
int n = (int) (Math.log(capacity - 1) / Math.log(2)) + 1;
int newCapacity = 1 << n;
```

**方法二：位运算补位。** 另一种方法主要是利用了一些位运算，达到了离它最近二的幂的一个效果，大家可以把它看成一种二进制的计算技巧。结论直接看就行：先让 c 在它原来的基数上减一，减完一以后，把这个 c 做一个右移移位的运算；右移之后，把它跟原来的 c 做一个逻辑或运算。接下来，把这个移位加逻辑或的代码复制四份——当然这个位运算就变成了右移 2 位、右移 4 位、右移 8 位和右移 16 位。

```java
int c = capacity;
c -= 1;
c |= c >>> 1;
c |= c >>> 2;
c |= c >>> 4;
c |= c >>> 8;
c |= c >>> 16;
c += 1;
```

这个代码写出来是不是很漂亮？看起来很对称，很有规律。最后呢，我们把 c 在它原来的基数上加等于一就行了。最后这个 c 就是我们要求的那个结果。

我把这里的原始的 c 改成了 30，正确的结果是不是应该是 32？之前方法一的代码先注释掉了。打印出来是 32。那如果这个原始的数字，它原本就是二的 n 次方呢？它也能保证正确性，是不是也是正确的？

所以我们把刚才这段代码复制一份，放在我们的构造器里。构造里策略一的代码就不要了，策略一跟策略二是二选一的啊，所以把策略一的代码注释掉。我为了少改一点，就把这里的 capacity 改成 c 就完了。

这样做完之后，即使它原来传过来的这个数不是二的 n 次方，经过了我们这一系列运算之后呢，就可以把它改成一个二的 n 次方的数，根据二的 n 次方数创建出来这个数组，它才能跟我们接下来计算索引的代码，才能够保证它的正确性。

### 二叉树层序遍历

这节课呢我们来看一道跟队列相关的练习题目，叫做**二叉树的层序遍历**。有同学说二叉树之前好像没接触过，没关系啊，这个非常简单，我一讲你就明白了。

所谓二叉树，顾名思义，它就是说树中的每个节点最多有两个分叉。你看我这个图里画的：节点 1 它有两个分叉，分别是他的左孩子 2、右孩子 3；节点 2 呢，它的左孩子是 4，右孩子是 5。它最多有两个分叉。

当然呢，你也可以没有分叉，像我们这里的 4，它已经是最顶头的节点了，它没有孩子了，那它就是没有分叉啊。也可以只有一个分叉，比如说节点 2，我把它的 4 这个左孩子去掉，它只有右边这个分叉，这也是允许的；或者呢我把它右边这个分叉去掉，只保留它左边这个分叉，也是可以的。就二叉树呢它没有什么特别严格的限制，就是说只要你的这个孩子数不超过两个，都可以称之为二叉树。

#### 先把节点定下来

那我们用程序怎么表示这个二叉树中的节点呢？很简单，就是我们可以设计一个 `TreeNode` 的类，它有三个属性：分别是节点的值，就是我们看到的 1、2、3、4，这个节点的值；还有呢他的左孩子是谁、他的右孩子是谁。这三个属性就能表示二叉树中一个节点了。

```java
class TreeNode {
    private final int value;
    private TreeNode left;
    private TreeNode right;

    public TreeNode(int value) {
        this.value = value;
    }

    public TreeNode(int value, TreeNode left, TreeNode right) {
        this.value = value;
        this.left = left;
        this.right = right;
    }

    @Override
    public String toString() {
        return String.valueOf(value);
    }
}
```

下面的都只是作为初始化，给它进行赋值的：可以给它的 value 赋一个值，根据 value 进行一个创建节点对象；也可以同时根据 value 以及左右孩子来创建一个节点对象。

注意把 `toString` 重写一下，后面直接打印节点，打印出来的就是它的值，我们就不用每次再去取 `value` 了。

#### 层序遍历就是一层一层地过

那再回到题目要求。题目呢是说我要对二叉树进行一个程序遍历。什么叫遍历呢？就是我要把树中的每个节点都过一遍，这叫遍历。那层序遍历呢？就是说他过的顺序是一层一层来的。

```text
              1
            /   \
           2     3
          / \   / \
         4   5 6   7

第一层: 1
第二层: 2, 3
第三层: 4, 5, 6, 7
```

也就是我将来遍历的时候，先找到它最顶层的这个节点 1；接下来呢第二层也就是第二层的两个节点，分别是 2 和 3；第三层这也有四个节点，那就是 4、5、6、7。也就是我将来遍历这个二叉树的顺序，就是按一层一层这个顺序来的，我们这个例子中，将来遍历出来应该是 1、2、3、4、5、6、7 这样一个顺序啊，这就叫层序遍历。

#### 用队列一层一层地推

好，题目要求我们清楚了，那接下来我们看看解题思路。对于这个二叉树来讲，已知的是它第一层的这个节点啊，我们也有个称呼，把它叫 root，根节点。那第一层是已知的，那下面几层呢都得间接地获得啊，不是一下子就能拿到。

那我们可以先设一个空的队列，我们把它第一层这个根节点先加入到队列里面。然后呢，我们在处理完第一层的节点以后，会把它下一层的节点给它再次加入队列，然后我们不断重复这个过程，就能达到一个程序遍历的效果。

我们把这个过程描述一下。比如说他已经把根节点加入队列了，那每次呢从队列里获取一个元素，就把刚才这个 1 这个节点给弹出了。获取到之后呢，我们就可以把它打印出来。接下来看一下他有没有左右的孩子，有，对吧？左孩子 2 有，那就把它也加入到队列；右孩子 3 是不是也有啊？哎，把 3 也加入到队列。好，这第一层的数据已经遍历完成了。

接下来队列里面是不是存储了，已经把第二层的数据都存进去了。好，接下来我们去遍历第二层的数据。那第二层数据呢，同样我们先取出来队列头部的这个元素，把它弹出来，当然你也可以把它去打印一下。打印完了之后呢，我们还要处理它下一层的数据，所以就看这个 2 有没有左右孩子，结果是不是也都有啊，所以接下来我们把 2 的孩子 4 以及 5 也加入到队列。

这样 2 处理完了，重复这个过程，我们再从队列头部弹出下一个元素 3。好看一下 3，打印出来 3，然后再看一下 3 有没有左右孩子，结果 3 也有左右孩子 6 和 7，那么再把 6 和 7 也加入到队列。那其实到这儿呢，我们发现第三层的数据也被加入到队列里了，我们逐一处理就行了。

```text
round   poll & print   offer (next level)     queue left
  1         1              2, 3            [2, 3]
  2         2              4, 5            [3, 4, 5]
  3         3              6, 7            [4, 5, 6, 7]
  4         4                --            [5, 6, 7]
  5         5                --            [6, 7]
  6         6                --            [7]
  7         7                --            []
```

然后再从队列头拿到这个 4，打印，当然 4 呢没有左右孩子了，那就不用往队列里加入了。好，继续处理，从队列头移除这个 5，5 呢同样没有左右孩子了，那不用有新的节点加入到队列；然后拿下一个 6，打印；然后拿下一个 7，打印。直到队列空了，说明所有的节点都处理过了，那么这时候就可以停止循环，我们的遍历也结束了。

#### 代码实现

好，那接下来我们来看一下代码的实现。这里呢我已经事先准备好了一棵树啊，这个树就是用来表示我们刚才这个二叉树的。你看它的根节点是 1，1 呢它有左孩子 2、右孩子 3；那 2 这个节点呢又有自己的左右孩子，分别是 4 和 5；3 呢也有它的左右孩子，分别是 6 和 7。就跟我们刚才这个树是一模一样的。

首先呢我们准备一个队列。队列的话，你用 JDK 自带的也可以，或者用我们之前给的实现也可以。那我们用一个我们自己的实现吧，就用这个叫 LinkedList 的队列，基于链表的这个队列实现。

那为什么不选那个基于数组的队列实现呢？因为链表这个它没有容量限制。你看它有两个构造，如果我们调的是这个无参的构造，那实际上这时候它的 capacity 呢是整数的最大值，是不是就相当于没有容量限制。为什么选没有容量限制呢？是因为我这个树中的节点个数是不确定的，我设置大了浪费内存对吧，设置小了，它将来不够用啊，所以我们就干脆选择这种没有容量限制的实现，比较方便一些。

那队列里面的元素类型呢？是不是就是我们这个树中的节点呀，还是这个 TreeNode 的。好，起个变量名 q，然后调它无参构造，把它创建出来。

那刚开始这个队列里面，我们是不是先把这个根节点放进去啊？这个是已知的，我们先把它放进去，用它的 `offer` 方法放入根节点，也就是这里的 root。

```java
LinkedListQueue<TreeNode> q = new LinkedListQueue<>();   // 无参构造：capacity = 整数最大值
q.offer(root);                                            // 根节点先入队

while (!q.isEmpty()) {                                    // 队列非空就还有下层节点没处理
    TreeNode n = q.poll();                                // 从队头取出本轮要处理的节点
    System.out.println(n);                                // 重写了 toString，直接打出值

    if (n.left != null) {                                 // 左孩子不为空才入队
        q.offer(n.left);
    }
    if (n.right != null) {                                // 右孩子同理
        q.offer(n.right);
    }
}
```

那下面呢我们就要写一个循环来处理了。那刚才我们也看到了，循环条件呢，就是当队列里只要有元素，就表示还有它的下层的未处理的节点，我们要不断地循环；当什么时候这个队列空了，表示所有的节点都处理完了，那么退出去了。所以这个循环条件呢就是判断一下，如果队列非空，我就不断循环了。

那每次循环的时候呢，我们就从队列的头部获取一个元素，让它的 `poll` 方法从队列头获取这个元素，我们交个 n 吧，它是本轮要处理的一个节点。那这个节点呢要处理起来其实很简单，我们现在就做一个打印吧，就把它打印一下。因为我这个节点呢重写了它的 `toString` 方法，它就会把这个节点的值打印出来。

打印完了之后呢，我们应该把这个节点它的下一层的、也就是左右孩子节点再加入到队列。比如说我取出来的是 1 对吧，那你应该把 1 它的下层 2 和 3 这两个左右孩子加入到队列，以便下轮的处理。因此呢我们就来判断一下：如果这个 n 它有左孩子、它的左孩子不为空，那我们就把左孩子加入到队列里，再调用那个 `offer` 方法加入他的左孩子。那如果为空呢，我们就不用加了对吧；如果他连孩子都没有，是 null 的话，那没必要处理了啊。所以我们先判断一下不为空加入左孩子，然后再判断一下，如果右孩子不为空，我就复制了一下改一下，如果不为空，那么把这个右孩子也加入队列。

好，这样重复这个过程，什么时候队列空了啊，表示所有的这个节点都处理完成了，我们就可以退出循环了。我们来看一下它的执行效果吧——核心代码就这么点啊，其实还是比较简单的，就是按我们刚才的这个程序进行了一个遍历。1234567，就是按程序对它实现了一个遍历。

### 本讲提到的题目

**题目：二叉树的层序遍历。** 给定一棵二叉树，请按层序输出它的所有节点值。

**解析**：层序遍历要求"一层一层"地访问节点，而"先进先出"的队列正好能保证这一点——先入队的节点先出队，于是上一层还没处理完，下一层的节点就已经在队里排好了位置。入队时坚持先左后右，下一层出队时自然就是从左到右的次序，这正是层序的定义。用数组队列也能做，但树的节点个数事先不确定，链表队列没有容量限制，更省心。

**答案**：

1. 建立一个队列，把根节点入队；
2. 只要队列非空，就从队头 `poll` 出一个节点，打印它的值；
3. 若该节点左孩子不为空，左孩子入队；若右孩子不为空，右孩子入队；
4. 队列为空时说明整棵树已经处理完毕，结束循环。

完整代码见上文"代码实现"一节。对着 1、2、3、4、5、6、7 这棵树，输出结果就是 `1 2 3 4 5 6 7`。

## 逆波兰表达式求值与中缀转后缀
> 对应块：BLK27 | 覆盖分集：P106-P108 | 块标题（分集名）：《基础数据结构-072-栈-e02-后缀表达式求值》

这节课我们再来看一道例题，题目叫**逆波兰表达式求值**。

这种逆波兰表达式其实也叫**后缀表达式**，说白了就是把那个运算符写在后面。举个例子，平时我们要算 1+2 怎么写？是不是 `1+2`，运算符写在两个数字的中间——这种我们称为**中缀表达式**，也就是运算符在两个数字之间。那么后缀表达式要做同样的 1+2 怎么写呢？一二，加号写在后面，`12+`，这种就叫后缀表达式。

好理解吧？不要被它的名字架住了，其实很好理解。

而且这个逆波兰表达式你交给计算机去用，非常方便，因为它有这样几个特点。

```text
中缀表达式              后缀表达式
   1 + 2       --->       1 2 +
   ^   ^                      ^  ^
   |   |                      |  |  |
   |   +-- 运算符夹在        |  |  +-- 运算符被推到最右
   |       两个数中间        |  +----- 后弹出来的那个数(右操作数)
   +---------- 左操作数      +-------- 先弹出来的那个数(左操作数)

人读: 先 1, 再 2, 最后做 +
机器读: 从左到右扫, 遇到运算符就把栈顶两个取出来算
```

> **结论**：逆波兰表达式第一，它都是从左向右进行计算；第二，它不用去考虑运算符的优先级，不用包含括号。换句话说，只要你得到的是一个逆波兰表达式，它相当于把那个优先级已经弄好了——左边的优先级肯定高，先运算，然后右边的优先级以后再运算。

### 力扣上的两道例题

我们来看一下力扣上的几个例子。

比如说有这样一个后缀表达式 `["2","1","+","3","*"]`，它是怎么算的呢？它是有个 2 和 1，然后有个加号，啥意思啊？就是 2 加 1，这是将来要做加法的两个数字，一个是加数，一个是被加数，他俩做一个加法运算。把相加的结果 3，再跟后面这个 3 再做一个乘法运算，结果是 9。理解了吧？这是一个例子。

下一个例子稍微费点脑筋：`["4","13","5","/","+"]`。刚开始是 4、13、5，这些是不是都是数字啊？但是要做操作的应该先是谁做操作？应该是 13 和 5 做操作，因为我们加减乘除都是**双元运算**——啥叫双元运算符呢？就是它需要两个数字才能做，加减乘除的运算。那 4 跟 13 他俩为啥不先做运算呢？因为它右侧不是运算符啊，所以他得先放一放，先别着急。先把 13 和 5 做一个除法运算，你看它俩是不是正好从左向右，找到了第一个运算符，那第一个运算符就找它左边的两个数字做一个除法。13÷5，整数除法是 2，小数直接舍掉。然后再把这个 2 跟他前面这个数字 4 再做一个加法运算，最后得到了 6。

> **易错点**：13÷5 在这道题里是**整数除法**，结果是 2，不是 2.6。小数部分直接舍弃，不用做任何四舍五入的处理。

题目也说了，将来数字呢都是整数，加减乘除都视为整数运算。此外呢，数字跟运算符的个数它会给定正确，它不会说你要做个加法，它前面只给你一个数字，那不行，它都给你给证据；而且呢也不会有除零的情况发生。

> **结论**：总之你就不用担心他给定的这个表达式的正确性，你只需要根据这个表达式，去计算出它最终的一个结果——这就是我们这个题目的需求。

### 遇数字入栈，遇运算符出栈

解题思路其实很简单，咱们就以上面这两个例子说明。

从左向右去遍历，遇到数字就放入栈；如果遇到了运算符，就从栈中取出它前两个元素进行计算，计算的结果呢再压入栈。

先看第一个例子。它是个字符串数组，从左向右遍历。遍历到第一个了，是数字，数字怎么办呢？就压入栈，把这个 2 压入栈。那如果继续往右边，发现又是数字，那就把它再压入栈。没问题吧？那什么时候遇到运算符了呢？那我们就开始计算了——要从栈里把这个 1 弹出来，把 2 弹出来，然后做一个加法运算。

注意啊，加出来的结果它可能还要继续跟其他的数做运算，所以我们应该把加的结果 3 再存入栈，把它俩加的结果再存进去。然后重复刚才的过程：遇到数字压入栈，把第二个 3 压入栈。接下来遇到什么了？遇到这个运算符了，遇到运算符就从栈里面把这两个 3 都给它弹出来，弹出来之后呢，三三得九，做完乘法了，九呢放到栈里面。那如果后续再没有了，没有其他的数字以及运算符了——第一个例子结束。

```text
token:      2        1        +        3        *
            |        |        |        |        |
            v        v        v        v        v
stack:   [ 2 ] -> [ 2 1 ] -> [ 3 ] -> [ 3 3 ] -> [ 9 ]
            push     push     pop,pop   push     pop,pop
                               push(2+1)           push(3*3)

遍历结束, 栈里只剩 9, 它就是答案
```

再看第二个例子。这回从左向右遍历，第一个是个 4，那就把 4 加入栈；然后第二个是 13，那就把 13 压入栈。只要是数字就加入栈，那是 5 还是继续把它压入栈。没问题吧？好，接下来遇到了一个运算符了——5 弹出来，13 弹出来，然后你做那个 13÷5 的操作，做完这个操作呢，13÷5=2，结果还是要压入栈的，因为他可能这个结果要做后续的运算。把他俩的结果再压入栈。

好，继续遍历，碰到一个运算符了。这时候把 2 和 4 都弹出栈，做一个加法运算，二和四相加的结果六存入栈。

最终如果没有其他的运算符和这个数字了，那我们这个栈里肯定就剩了一个元素，这个元素就是我们最重要的结果。

> **结论**：所以总结一下——我们从左向右去遍历，遇到数字就加入栈；遇到运算符就从栈里取出两个元素进行计算，计算的结果要记着保存到栈里；最终所有都遍历完了，栈里剩下的那个就是我们最终要的结果。

### 落到 Java 代码里

有了思路我们来实现一下方法。这个方法的定义呢，参数是一个字符串数组，里面存的就是这些个数字或者是运算符，当然都是以字符串形式存在的——所以将来我们要运算的话，我们得把这个字符串转成数字。那最终运算的结果呢是一个 int 整数，作为方法的返回值。

首先呢我们得创建一个栈。因为力扣这道题目的它对数组的长度啊没有做限制，所以这个数组的长度是变化的。因此我们就不用我们自己写那个栈的实现了。我们之前写过一个基于数组的，还写过一个基于链表的实现，我们写的那两个栈呢，它的长度都是固定的，我不好去估算到底多大的栈才够用。所以我们用一个 Java 自带的栈的实现，`LinkedList`。

> **提示**：注意它表面看起来好像是个链表是吧，但实际上它也实现了栈的相关方法，`push`、`pop`、`peek` 都有，就够用了。

我先把它创建出来。将来我这个栈里存的想是存这个数字，所以我给它写我们的类型，选择这个引用包装类型 `Integer`。它这个好处啊，就是占的容量可以动态变化，如果你将来不够用了，它会……这个容量它没有限制，没有限制。

创建了之后呢，我们就开始去遍历这个字符串数组，对吧？遍历出来的这个字符串，我先做一个判断啊——如果是运算符，做相应的操作；那如果是数字，做相应的操作。我这里就用一个 `switch` 吧，对我们的这个字符串做一个匹配。

```java
public int evalRPN(String[] tokens) {
    // 数组长度不受限制, 栈的长度会变化, 所以用 LinkedList 充当栈
    // 它表面是链表, 但也实现了栈的相关方法(push/pop/peek)
    LinkedList<Integer> stack = new LinkedList<>();

    for (String token : tokens) {
        switch (token) {
            case "+" -> {
                int b = stack.pop();
                int a = stack.pop();
                stack.push(a + b);
            }
            case "-" -> {
                int b = stack.pop();
                int a = stack.pop();
                stack.push(a - b);
            }
            case "*" -> {
                int b = stack.pop();
                int a = stack.pop();
                stack.push(a * b);
            }
            case "/" -> {
                int b = stack.pop();
                int a = stack.pop();
                stack.push(a / b);
            }
            default -> {
                // 加减乘除都没匹配上, 能走到这里的都是数字
                stack.push(Integer.parseInt(token));
            }
        }
    }

    // 遍历结束, 栈里剩下的那一个就是结果
    return stack.pop();
}
```

四个运算符分支几乎是复制粘贴的，真正的差别只在那个符号。那 default 里面肯定都是数字，没问题吧？如果能走到这，它表示的都是数字。我们先来看数字——简单数字呢我只要把它压入栈就行了。当然我们这个 token 目前是字符串，我们把它转成数字，`Integer.parseInt(token)` 这样就可以把一个字符串转成它对应的数字。转换好了之后呢，我们压入栈。

> **易错点**：注意我压入栈的顺序跟你弹出栈的顺序正好是反的。比如说我从左向右，这里这个 4 压入进去了，然后再加入一个 13 压入进去了，那弹出来的时候是谁先弹出来？是不是 13 先弹出来。所以呢我如果是 `a + b` 的话，那我弹出的时候就先弹出的应该是 `b`，没问题吧？

这两个数字有了，那是不是把它们做一个加法运算就行了？`a + b`，然后运算的结果是不是还要压入栈？以便下次运算，所以我们调用 `stack.push`，把我们的 `a + b` 的结果再压入栈。

好，剩下的就差不多了。减法那就是把 `b` 跟 `a` 都弹出栈，然后 `a - b`——**注意这个顺序就很重要了**。因为加法 `a` 和 `b` 谁在前谁在后没关系，但是减法、除法啊都跟它的顺序有关。`b` 是先弹出来的，所以它是右边这个操作数；这个 `a` 是后弹出来的，所以它是左边这个操作数。这是减法的，乘法的改一下符号就行了，最后除法到。

> **结论**：遇到的运算符就弹出两个数字做计算，计算的结果重新压入栈，然后依次遍历。什么时候这个遍历结束了，说明所有的操作都完成了，那就是结果。也就是等我们这个 `for` 循环结束了，结束之后我们再 `pop`，把栈里剩下的那个取出来，就是最终的结果。

对这个 `switch` 的新语法稍提一句啊：这种新语法呢是用了一个减号加一个箭头，这种方式好处就是你不用写那个 `break`。就是 Java 里你如果少写 `break`，它不是会有相应的问题嘛，对吧？但是用了新语法之后，那个 `break` 你就不用去操心了。

好，最后我们测试一下。这里呢我是用了力扣的两个测试用例。第一个测试用例呢，它的计算结果应该是个 22，它比较复杂，比较长一些，但是正确结果应该是 22。第二个测试用例我们口算一下啊——这是不是 2+1 得 3，3 再乘以 3 是不是 9？第二个应该是 9。好跑一遍：没问题吧，第一个是 22，第二个是 9，这个测试用例也就通过了。

### 你写的每一行中缀，编译器早就在替你翻译了

那有同学就会说到，这个后缀表达式求值到底在哪会用到呢？我们平时自己写源代码，不都是写的中缀表达式吗？

比如说我们来看这个例子，我写了个方法，我要计算 `a` 和 `b` 这两个变量的值。大家来看是不是 `a + b`，把加号写在中间，这叫中缀表达式。我们并没有写过这种后缀表达式，那这个后缀表达式用在哪呢？

其实我们写的源代码，它最终要变成二进制代码啊。比如说 Java 中的这个类，它会编译成二进制的 `class`，变成 class 以后，其实呢它就把我们写的中缀表达式就转换成了后缀表达式。

> **结论**：我们的 Java 编译器，它会帮我们把这个高级语言的中缀表达式，转换成更底层的后缀表达式，这样计算机用起来才更方便。

怎么证明呢？给大家演示一下。我先让原来的这个代码跑一遍，这里我给个 10 和 20，待会儿好看。跑一遍是为了生成它的字节码文件，生成了 class 文件以后，我们就可以打开控制台，然后去反编译我们刚才这个类的 class。

```bash
javap -c -v E03
```

反编译的命令是 `javap` 加两个参数 `-c -v`，然后后面跟上这个类名。稍等啊，这个反编译的过程稍微慢一些。

好了，我们待会呢主要看它的 `test` 方法被反编译成了什么样子。往上找一找，大家看这是不是我们的 `test` 方法呀，我们带着大家读一下。

首先呢给同学们说一下，它在编译成字节码以后，它就不是用 `a`、`b`、`c` 代表这个变量了，它是用一个符号零。就是说这个位置 0 索引的变量对应着 `a`，位置 1 的变量对应着 `b`，位置 2 的变量对应着 `c`。所以大家要跟 `a`、`b`、`c` 对应起来。

我们来看啊，这里跟操作变量的主要的命令啊，有两个。一个是带这种 `store` 的，这就是向变量存储值。比如说刚才这里准备了一个常数 10，然后调用了 `istore 0`，就是把 10 这个数存到了 0 号变量，也就是 `a` 这个变量，对应着这行代码。那接下来呢又准备了一个数 20，把它存到 1 号变量里，也就是对应着这行代码，对上了吧。

还有一个命令呢，就是读取变量值的，是 `load` 的命令。你看 `iload 0`、`iload 1`，其实就是去读 `a` 和 `b`，分别读 `a` 和 `b` 它俩的值。

那接下来我们把重点集中在这三行代码上，这三行代码其实就对应着一个后缀表达式：

```text
iload 0     |  读 a 的值
iload 1     |  读 b 的值
iadd        |  再拿这两个数做加法

注意: 加号不是先算的, 它是在两个数都读完之后才做的
```

你看我们要做 `a + b`，是不是他先得读 `a` 的值？也就是 `iload 0`，就是读取了 `a` 的值。然后 `iload 1` 就是读到了 `b` 的值。注意那个加是不是还没做呢？它是在读完了之后，在他俩这个数之后做这个加法，就是这个 `iadd`。这是一个典型的后缀表达式。

啊，也可以看几个更复杂一点的例子。我们看一个带优先级的，比如说我再加一个变量，这个叫 `d` 啊，再来一个 `c`。然后呢我们先自己来分析下，这里这个中缀转成后缀应该长什么样。那大家来看，`a` 他刚开始不能跟 `b` 做加法啊，因为这个乘法的优先级比较高。所以呢，他得先把 `b` 和 `c` 这两个数都放到那个栈里，先做乘法，`b` 和 `c` 是不是先乘啊，乘法的结果当然他也跟我们之前那个后缀表达式计算是类似的，把它的结果再放入栈。这个栈的结果，跟栈前面这个 `a` 他俩再做一个什么加法啊。所以将来它的后缀表达式应该长这个样子。我们验证一下。

```text
a + b * c

iload 0     |  a
iload 1     |  b
iload 2     |  c
imul        |  先把 b 和 c 乘出来
iadd        |  再跟 a 加
```

好，编译完了之后呢我们再反编译——这个反编译总是比较慢。找那个 `test` 方法：零就是 `a` 嘛，一是 `b`，二是 `c`。你看接下来这几行代码就比较关键了啊，就对应着我们这里的后缀表达式，零和一是不是对应着这里的 `a`、`b`，二就对应着 `c`。接下来 `imul` 是什么呢？就是那个乘法运算，对应着我们这个运算符；刚才说过了 `iadd` 对应着加法运算。是不是就把我们自己写的这种中缀转成了 JDK 能识别的后缀。

当然如果你用括号改变了它的优先级，咱们再来看一下，那改变优先级了会变成什么？就是 `a`、`b` 先加，先加完了结果再存入栈，栈呢再跟 `c` 做对应的乘法，应该变成这个样子。

```text
(a + b) * c

iload 0     |  a
iload 1     |  b
iadd        |  a 和 b 先加, 结果留着
iload 2     |  c
imul        |  再跟 c 乘
```

所以呢我们说这个后缀表达式还是很重要的。

### 中缀转后缀：把运算符推到后面去

那接下来一道例题啊，我们讲讲怎么把这个中缀表达式转成它对应的后缀表达式，当然是用程序来做啊。

先来看一个最简单的例子 `a + b`。我们是不是要把他这个中间的运算符想办法放到最后啊？那怎么做呢？可以这样——从左向右分析它的每个字符。那如果遇到的不是运算符字符，那我们就直接把它放到一个新字符串里。遇到了这个中间的运算符了呢，那我就可以先把运算符暂存到栈上，因为运算符它得放到最后，所以我得先把它暂存一下。接下来呢再看下一个字符，下一个字符 `b` 它不是运算符，那就直接放到新字符串里。最后呢没有其他字符了，再把栈上的这个运算符拿出来，放到我们的这个字符串的最后——这样就把 `a + b` 变成了 `a b +`，没问题吧？

那我们再看一个例子，这个例子呢是 `a + b - c`。同样我们按照刚才的这个思路来走一遍。

那 `a` 不是运算符，直接把它放到新字符串。`+` 是运算符，是不是要放到栈里来——把加号放到栈里。好，接下来 `b` 啊，不是运算符，放到新字符串。

好注意下面不一样了，下面呢我们要处理一个减号。那减号大家去想，他将来跟这个加号谁先运算啊？这种平级的运算符，是不是应该是由左向右运算啊？加法和减法他俩是平级的，平级的话那肯定是从左向右来运算。所以呢你别着急，先把减号放到这里啊——我们得让加法先做呀。

所以呢我们这时候得把栈中的这个加号先给它弹出来，弹出来以后呢，先让它做加法，是不是拼到我们这个字符串。最后相当于先做 `a + b`，然后呢我们再把这个减号放到这里。没问题吧？下面就类似了，然后发现下一个字符不是运算符，把它放到新字符串，最后没有其他字符了，再从这里把这个减号拿出来放到最后。这就表示我将来先做 `a + b`，`a + b` 的结果再跟 `c` 做运算，跟 `c` 做一个减法运算。

> **结论**：所以从刚才呢我们看出来了：如果像这种平级的怎么办？如果我发现这个放第二个运算符，前面有跟他平级的运算符，那我得把前面这个运算符先给它弹出栈，让它先运算。因为这个时候左边的、也就是这个加号，它的优先级更高吗，那先让它运算。运算完了，我这个减号再入栈。

好，咱们继续。那比如说下面这个例子 `a * b + c`，同样的道理：`a` 不是运算符，直接拼到新字符串；乘号呢，给它暂存到栈里；`b` 不是运算符，直接拼好；接下来处理这个加号，那这个加号跟这个乘号应该是先运算，是不是？乘号应该先运算，那肯定怎么做？肯定就是把乘号给它弹出栈，让他先做乘法，做完乘法以后，那我这个加号是不是才能入栈。加号再入栈；接下来不是运算符的直接拼到新字符串；最后没有其他字符了，把我们栈中剩下的这个加号给它出栈，让他最后做加法。

其实我们这第三个例子跟前面第二个例子是类似的——就是说你如果在处理到运算符的时候，发现前面的有跟他同级或者是比他高的这个运算符，是不是都应该让前面的这个先出栈，先运算，然后我后面这个运算符呢再入栈。这是第三种情况。

最后再看第四个例子啊，第四个例子跟前面稍有一些不一样了。`a` 不是运算符直接拼串，加号先入栈；接下来 `b` 不是运算符拼串；该处理这个乘号了。那这回这个乘号跟前面栈里存在加号，谁应该先运算？是不是乘法的优先级要高啊，所以乘号得先运算。既然他要先运算，你这时候能把加号出栈吗？不应该吧。如果这个时候你加号出栈，是不是他先算的就是 `a + b` 了。所以怎么办？我们让乘号先入站，让乘号先入栈，然后继续向后。`c` 呢不是运算符，拼串。现在没有其他字符了，先出栈的是谁？哎，这回先出栈的是乘号。既然他先出站了，最终就意味着是不是先算的是 `b * c` 这个乘法。最后呢出栈的是这个加号，这意思是说 `b * c` 的结果跟 `a` 做一个加法。这样是不是就保证了这回的乘法先运算、加法后运算。

> **结论**：所以它跟我们前面这几个例子不一样的地方就是——如果你处理到某个运算符，发现它的优先级更高，那你不应该把前面的运算符出栈，而是把优先级更高的这个运算符让它入栈。

```text
读入:   a      +       b      *       c
        |      |       |       |       |
        v      v       v       v       v
sb:    "a"     |     "ab"    |      "abc"
        |    push(+)  push(*)
        |    stack=[+] stack=[+, *]
        |                 |
        |                 +-- '*' 优先级更高, 直接入栈, 压着 '+' 不动
        |
遍历结束: 依次 pop -> sb.append('*') -> sb.append('+')
结果:    "abc*+"
```

当然呢我们可以在刚才这个基础上，我们再稍微扩展一下，比如说它后面还有其他的运算。刚开始我们分析到，比如说再来个减 `d`。刚开始我们分析到——拼串了是吧，加号入栈了，`b` 拼串了，乘号优先级更高，是不是入栈了对吧？好，`c` 直接拼串。好，接下来处理减号了。

你看这回这个减号该怎么做？是不是他遇到的栈里的优先级比他高了？优先级比他高的，能先处理减号吗？不行吧。所以我们遇到了优先级更低的一个运算符，那你得去把我们这个栈里的这些个运算符是不是先处理好啊。先把乘号给他出站，先让他做前面的乘法，乘法做完了以后，这个乘号就没了，已经出站了。那这个加法和减号谁先做？是不是加法应该先做，因为加法在左边嘛，减号在右边啊。先做加号，所以只要遇到平级的、比他高的都要出站。好让他再做加法，做完加法了，这个时候我们的减号是不是才能入站啊，好再让这个减号入站。

所以这个规律是不是又跟我们前面第二个例子、第三个例子是类似的啊。最后 `d` 它直接拼串，最后没有其他字符了，减号出站，最后再做减法。

### 把规律写成三条文字

好最后这个括号的我们暂不分析，我们先把前面这些代码实现了，括号呢我们单独来一下。

把我们刚才的规律写成文字的话，那就得到了这么三点。

**第一点**：如果我们遇到的是这种非运算符，直接拼串就完了。

**第二点**：那如果遇到的是加减乘除这些运算符呢，那就分成了两种情况。一种呢就是遇到的这个运算符，它的优先级比栈顶的运算符优先级要高，那这时候我就入栈啊——就好比我的当前运算符是这个乘号啊，它比栈顶的那个加号优先级要高，这种情况下乘号是不是就入栈。这是第一种情况。第二种情况呢，就是说它的优先级比栈顶的要低，或者是等于，那这种情况下我们需要把栈里那些大于等于它优先级的这些运算符都要出站，出站之后拼串，然后我们现在这个运算符啊，它再入栈。这是遇到运算符的情况。

**第三点**：就是当所有的字符都遍历完成之后呢，栈里剩余的运算符依次出栈，拼接到字符串的尾部就可以了。

```text
读到字符 c
  |
  |-- 不是运算符 ----------------------------> 直接拼串(数字/变量原样输出)
  |
  `-- 是运算符
        |
        |-- 栈为空 --------------------------> c 直接入栈(没人跟它比)
        |
        `-- 栈不为空, 比较 priority(c) 与 priority(栈顶)
              |
              |-- priority(c) > 栈顶优先级 ------> c 直接入栈
              |                                     它比栈顶优先, 得排在栈顶后面算
              |
              `-- priority(c) <= 栈顶优先级
                    |
                    `-- while 栈非空 且 栈顶优先级 >= priority(c)
                          |-- 成立: 出栈 -> 拼串, 继续循环(可能连弹多个)
                          `-- 不成立: 跳出, c 入栈

遍历全部字符之后: 栈里剩下的运算符依次出栈, 拼到字符串尾部
```

把上面的话压成一张表，就三种对照关系：

| 遇到运算符 `c`，栈顶是 `t` | 谁该先算 | 动作 |
| --- | --- | --- |
| `c` 优先级比 `t` 高 | `c` 先算 | `t` 不出栈，`c` 直接入栈压着它 |
| `c` 与 `t` 平级 | 左边的 `t` 先算 | `t` 出栈拼串，`c` 再入栈 |
| `c` 优先级比 `t` 低 | `t` 先算 | 弹掉所有优先级 ≥ `c` 的拼串，`c` 入栈 |

### 把规律翻译成代码

接下来呢我们先做一些准备工作，因为呢待会我要知道每个运算符它的一个优先级啊，所以我先提供一个方法。那这个方法呢就是去返回这个运算符它的优先级。

比如说我可以做一个简单的设定：加减优先级是 1，可以吧？那乘除呢优先级高一些，我就让它返回一个 2。当然呢你可以扩展啊，以后我们如果有了更多的运算符，那么你可以针对这个规则进行扩展。

那这个方法呢它返回的是个整数，代表它的优先级，方法名呢我们就叫 `priority` 吧，就是优先级的意思，方法的参数就是这个运算符，是一个 `char`。这里呢我们就可以用一个 switch 表达式来实现啊，就对这个 `c` 也就是运算符做一个匹配。如果匹配到它是一个乘号或者是除号，在这种情况下我们返回一个 2；我匹配到的是一个加号或者减号，那就返回一个 1；那其他情况呢，我们暂时认为它是一个非法的运算符，我们就抛一个异常吧。

```java
private int priority(char c) {
    return switch (c) {
        case '*', '/' -> 2;
        case '+', '-' -> 1;
        default -> throw new RuntimeException("不合法的运算符：" + c);
    };
}
```

主方法呢是下面这个中缀转后缀，参数接收的是中缀表达式，返回的呢是后缀表达式。那我们先写点这个基础代码。

我们先准备好一个栈啊，先准备好一个 `LinkedList`。这个栈叫 `stack`，里面存的什么呢？因为将来主要放的都是运算符，所以我们用一个 `character` 啊。再准备一个后缀表达式，后缀表达式我们用一个 `StringBuilder` 去做字符串的拼接啊，因为拼接的字符串多的话，用这个 `StringBuilder` 拼接更好一些。

好创建一个 `StringBuilder`，它的长度呢就跟原来这个表达式长度一样吧——其实会比原来短，为啥呢？因为原来的表达式将来可能会有些括号，你中缀转后缀了以后，后缀表达式里括号都去掉了。好，最终呢我们把这个 `StringBuilder` 转换成字符串返回就可以了。

```java
public String infixToPostfix(String infix) {
    // 栈里将来主要放运算符
    LinkedList<Character> stack = new LinkedList<>();
    // 拼串用 StringBuilder; 容量给到原表达式长度, 实际还会更短(括号会被丢掉)
    StringBuilder sb = new StringBuilder(infix.length());

    for (int i = 0; i < infix.length(); i++) {
        char c = infix.charAt(i);
        switch (c) {
            case '+', '-', '*', '/' -> {
                if (stack.isEmpty()) {
                    // 栈空的时候没人可比, 直接入栈
                    stack.push(c);
                } else if (priority(c) > priority(stack.peek())) {
                    // 当前运算符优先级更高, 直接入栈
                    stack.push(c);
                } else {
                    // 栈顶优先级大于或等于当前运算符, 都要出栈, 可能连弹多个
                    while (!stack.isEmpty() && priority(stack.peek()) >= priority(c)) {
                        sb.append(stack.pop());
                    }
                    stack.push(c);
                }
            }
            // 加减乘除都没匹配上, 剩下的 default 就是非运算符, 直接拼串
            default -> sb.append(c);
        }
    }

    // 遍历完成, 栈里剩余的运算符依次出栈, 拼接到尾部
    while (!stack.isEmpty()) {
        sb.append(stack.pop());
    }

    return sb.toString();
}
```

核心的逻辑我们一段一段对着看。先看这个非运算符啊——非运算符呢我们直接把这个字符拼到目标的字符串里是不是就行了？直接 `sb.append(c)`。拼谁呢？拼这个字符 `c`，它里面可能就是一些数字啊或者变量啊，总之不是这些运算符。这是第一种情况。

那第二种情况，那遇到了这些加减乘除的运算符，那我们是不是要把它跟栈顶元素比较？哎当然有一点我这儿没写啊，就是如果这个栈里都没有运算符，栈是空的，空的话我是不是直接把这些运算符入栈就可以了。所以我们先把这种情况处理一下：如果 `stack.isEmpty()` 就是空的，那直接就把我们这个 `c` 啊，当前这个运算符，加减乘除，给它压入栈里就可以了。

好那如果栈不是空的，我们是不是才做刚才这两个比较？分两种情况：第一个就是我当前的优先级比栈顶的这个优先级要高，这种情况下呢那我就把它入栈，入栈的话那就是 `stack.push` 这个 `c`。这个运算符。这个简单啊。

然后 `else` 呢？我们要把栈里面那些个优先级比如当前这个运算符优先级高的，或者是等于它的啊，都要出站，都要出站。因为要出站多个，所以我们写一个 `while` 循环，就不断地去出站啊。判断一下，如果 `stack.peek()`——先不要出站，先拿到栈顶的元素，看一下它的优先级。如果这个优先级比我们当前的这个运算符的优先级要高的话，那怎么办呢？或者等于，它都要出站。都要出站，那我们就调用那个叫 `stack.pop`，`pop` 才是出站啊。

如果要出站，出站之后这个运算符要拼到哪去呢？还是拼到我们的字符串上，直接就把它拼到我们字符串的尾部就可以了，`append` 做一个拼接。当然了我们不断循环，如果这个栈空了，是不是就不用循环了？所以多加一个条件，就是判断一下，如果这个栈不为空的时候，我们才不断循环。取个反——不为空，并且呢这里的这个运算符的优先级大于等于我当前运算符优先级的话，那么就不断循环，先把栈里这些腾空。

然后呢等循环结束了，是不是我当前的运算符再给它入站呀，那就调用 `stack.push` 来把我们的 `c` 入站。好，这就把第二点我们都实现完了。

最后一点呢，就是遍历完成了，栈里剩余的运算符也要依次出站啊。就等我们整个这个循环都结束了，我们再把整个栈再腾空。腾空的话就是判断下如果这个栈不为空，就不断地给它弹空，`pop` 弹空，弹空出来。这个运算符是不是也要拼到这个 `StringBuilder` 上，所以我们还要做一个 `append` 拼接啊。这就写完了。

> **结论**：那测试一下吧。但是这个代码啊大家一定要先分析了，然后再写代码啊。不然的话你自己像没头苍蝇一样，没有总结去写代码，那很容易很难把这个逻辑写正确。

好测试一下，呃我先把这两个带括号的先去掉，我们看看测试前面这几个。

好咱们检查一下看对不对。第一个 `a + b` 变成了 `a b +`，没问题吧？第二个 `a + b - c`，其实我们前面都分析过，最后变成了 `a b + c -`，没问题吧？第三个呢是一个 `a + b * c`，最后变成了 `a b c 乘加`。第四个我看一下啊，是 `a * b - c`——当然这里其实是加 `c` 啊，其实大家能看出来是不是，最后应该变成 `a b 乘 c 减` 对吧。没问题吧？

## 括号怎么出栈，以及栈和队列的互相模拟
> 对应块：BLK28 | 覆盖分集：P109-P112 | 块标题（分集名）：《基础数据结构-072-栈-e03-中缀表达式转后》

我们接着中缀表达式转后缀往下走。前面几个例子都比较干净，全是加减乘除一路平推，没有括号。这一节把括号补上——括号一进来，整个算法就多了一条必须单独处理的规则，而这条规则里头还藏着一个特别容易搞错的地方。

先从最简单的开始：`(a+b)*c`。

### 左括号的优先级，我们故意把它设成 0

一上来是左括号。我们可以把它看成一个运算符，先入栈。栈里现在是 `[ ( ]`。

然后 `a`，不是运算符，直接拼串。接着是加号——这一步得想一下：是把之前的括号出栈，还是让加号跟着入栈？

显然这个左括号留着还有用，将来肯定要跟右括号做一些相应的处理，所以我们不能把左括号出栈，应该把加号暂时先给它入栈。

那凭什么加号就能直接入栈？回头看我们前面那条规则：新运算符入栈的条件，是当前运算符的优先级比栈顶运算符的优先级要高。加号跟左括号一比，加号竟然入栈了——按我们这个规则反推，说明加号的优先级比左括号要高。

> **易错点**：这里大家的认知跟我们平常的认知是反的。我们天然认为括号的优先级更高，但为了让算法能套进原来那条"比栈顶优先级高才入栈"的规则里、**不改动以前的代码**，我们必须让左括号的优先级比加号更低。记住这条就够了。

所以规矩定死：前面乘除的优先级是 2，加减是 1，左括号就设成 **0**。比谁都低。

### 右括号：弹到左括号为止

接着看 `(a+b)*c` 的后半段。`b` 直接拼串，然后来的是右括号。

右括号意味着什么？意味着括号里面所有的运算都应该马上做。所以遇到右括号，从栈顶一路弹到左括号为止，弹出来的运算符都拼到结果串尾部：

```text
入栈序列:  (  +  *        ( * 入栈后还没来得及出栈)
拼接结果:  a  b  →  ab+c*

遇到 ')':
  栈顶是 '+'  ≠ '('  →  pop，拼接  →  ab+c+
  栈顶是 '('  = '('  →  跳出循环
  最后再 pop 一次，把左括号弹掉 —— 但它不用拼接，直接抛弃
  接着 '*' 才入栈，'c' 拼串
没有更多字符了 → 把 '*' 出站，拼到尾部

最终: ab+c*
```

整个意思就是先做了 `a+b`，结果再跟 `c` 做乘法。

再练两个找找感觉。第二个例子 `(a+b*c)-d*e`：左括号入栈，`a` 拼串，加号优先级比左括号高，入栈，`b` 拼串，乘号优先级又比加号高，也入栈（栈是动态的，肯定够用，还可以动态变），`c` 拼串。接下来是减号。

减号走的是我们前面说过的那条逻辑：把栈里比减号优先级高的、或者跟它相等的都出栈。乘号比减号高，先出栈直接拼串；加号跟减号优先级一样，也要提前做，所以加号也出栈。剩下一个左括号——左括号优先级比减号低，只有大于等于它的才出栈，所以左括号留着不用动。等全部弹完，减号入栈，`d` 拼串；后面没东西了，减号才出站，左括号这时候也没用了，跟着出站。

所以括号里面的次序是先 `b*c`，再跟 `a` 做加法，加完之后跟 `d` 做减法。后面碰到乘号入栈、`e` 拼串，最后把乘号放在最后面，也就是前面这一堆的运算结果跟 `e` 做乘法。结果是 `abc*+d-e*`。

第三个例子 `a*(b+c)`：`a` 直接拼串，乘号入栈。左括号的优先级比乘号低，不过没关系，遇到左括号我们算一个特殊处理，只要是左括号一律直接入栈。`b` 拼串，加号优先级比左括号高，入栈，`c` 拼串。现在遇到右括号，把栈里直到左括号为止的所有运算符都出栈，加号出站拼过来，左括号也没用了，出站。

注意这里右括号只弹到左括号为止，最初那个乘号要留着不动。这就意味着 `b` 和 `c` 先做加法，最后没东西了，再把乘号出站，也就是 `(b+c)` 的结果跟前面的 `a` 做乘法。结果是 `abc+*`。

### 把这两条规则补进代码

落到代码上，其实就是在匹配运算符的那个分支里再加两个 `case`。我提前就把左括号的优先级改了，加一条：如果匹配到的是左括号，把优先级设置成零——别待会忘了。

左括号很简单，直接入栈就行，`push` 到栈里。右括号要把栈里直到左括号为止的所有运算符出站，所以写一个 `while` 循环：检查栈顶元素，看它是不是不等于左括号，不等于左括号这些都应该出站，怎么出站？`stack.pop()`。pop 出来的结果要拼接到 `StringBuilder` 的尾部。

循环的结束条件是什么？是遇到左括号，遇到就退出循环。退出循环之后，那个左括号留着有用吗？没用了，所以我们还得再做一次 `pop`，这次 pop 的目的就是把左括号弹掉。但左括号跟前面这几个处理不一样，它不用做拼接，所以只做一个弹出就行了。

```java
case '(':
    priority = 0;                        // 左括号优先级压到最低
    stack.push(operator);
    break;

case ')':
    while (!stack.isEmpty() && stack.peek() != '(') {
        postfix.append(stack.pop());     // 运算符出栈并拼接
    }
    stack.pop();                          // 把左括号弹掉，不拼接
    break;
```

> **提示**：这个非空判断加的时候要说明一下——代码老报这个警告也不太好啊，警告就是说这个 stack 如果是空的可能会产生空指针。我前面加一个非空判断把它挡掉。其实这种条件不会出现，因为我们要遇到的右括号，它前面肯定会给它 push 一个左括号。我们假定这个表达式都是正确的，不可能给你一个括号都不配对的表达式。所以这个情况其实不会出现，不过为了避免它出现警告，我还是把它加上了。

测试用例我就用刚才分析的这几个情况跑一遍：第一个 `(a+b)*c` 得到 `ab+c*`；第二个 `(a+b*c)-d*e` 得到 `abc*+d-e*`；最后一个 `a*(b+c)` 得到 `abc+*`。都对。这关于中缀表达式转后缀就讲完了。

### 双栈模拟队列

再来看一道题目，需求很简单：请你使用两个栈来模拟一个队列。

队列咱们知道，一头进一头出。但是栈呢，它只能操作一头，只能对栈顶进行操作。所以我们至少得需要两个栈，才能去模拟这个队列。

思路就是我画的这张图：我创建两个栈 `s1` 跟 `s2`，用 `s2` 的栈顶来模拟队列的尾巴，用 `s1` 的栈顶去模拟队列的头部。

#### 队尾就交给 s2 的栈顶

队列尾有哪些操作？其实主要的操作不就是一个添加元素嘛。那我们能不能用 `s2` 来模拟向队列尾部添加？可以。`push` 方法本意是往 `s2` 的栈顶添加一个 `a`，那添加的这个 `a` 是不是就好像是加到了我们的队列尾巴。

那如果再加一个呢？比如再 push 一个 `b`，`b` 应该放在 `a` 的上面，所以 `a` 应该向底部靠，`b` 放在 `a` 的上面，是不是就好像是 `b` 加到了队列的尾部。所以没问题，我们要模拟往队列尾部添加元素的操作，直接去调用 `s2` 的 `push` 方法就可以实现了。

#### 队头：先把 s2 倒进 s1

队列头部主要的操作是从头部移除元素。比如我们模拟往队列里面加的元素是 `a`、`b`，要从队列头移除，是不是应该移除 `a`。

但是 `a` 能直接移除吗？不行。你看我们的 `s2`，`a` 是在栈的底部，栈只能操作顶部，它不能直接操作 `a`。那怎么办？就要借助 `s1` 了。`s1` 现在还是空着的，这个时候操作它也没东西可操作。

那思路是怎样的呢？我就是把 `s2` 里面这个 `a`、`b` 给他倒腾到 `s1` 这边来。

```text
加入 a、b 之后
  s2: [ a | b ]    ← 栈顶是 b，b 就是队尾；a 被压在栈底
  s1: [   空   ]

要移除队头 a，可 a 卡在 s2 栈底，栈只动栈顶，动不了 —— 借 s1

  s2: [ a | b ]   pop b   →  push 进 s1  →  s1: [ b ]
  s2: [ a     ]   pop a   →  push 进 s1  →  s1: [ a | b ]
                     ↓
  s2: [   空   ]
  s1: [ a | b ]    ← 栈顶 a 就是队头

从顶至底看：s2 里是 b a，倒进 s1 后变成 a b，顺序正好颠倒
```

所以这里的思路就是把 `s2` 所有的元素都弹出来，先放到 `s1` 里。这样就能操作栈顶了，操作栈顶就相当于把刚才队列头部的这个 `a` 进行一个移除。这时候我们只需要调用 `s1` 的 `pop` 就可以了。

那如果下一次我已经把 `a` 移除了，我要移除下一个元素，需不需要到 `s2` 这边找？可以先不找。也就是说，将来 `s1` 只要不为空，我们就可以直接从 `s1` 这边去移除元素，代表模拟队列头部的移除操作。直到什么时候 `s1` 空了，我们再到 `s2` 这边去找，重复刚才这两步操作就行了。

```java
Stack<Integer> s1 = new Stack<>(100);   // 模拟队列头
Stack<Integer> s2 = new Stack<>(100);   // 模拟队列尾

// 队尾添加
public void push(Integer value) {
    s2.push(value);
}

// 队头移除
public Integer pop() {
    if (s1.isEmpty()) {                 // s1 空了才去 s2 倒腾
        while (!s2.isEmpty()) {
            s1.push(s2.pop());
        }
    }
    return s1.pop();                    // s1 非空就直接取栈顶
}
```

#### peek 和 empty

`peek` 方法非常简单，逻辑几乎跟 `pop` 一样，只是说到了最后他不是把元素移除，只是获取队列头的元素。所以就把整个代码复制一份，只把最后这行改成只获取不移除，调 `peek` 获取栈顶的元素，也就是获取队列头的元素。

`empty` 就是检查这个队列是不是空的。怎么检查？我们是用两个栈模拟一个队列，所以两个栈如果都是空的，整个队列才是空的。`return s1.isEmpty() && s2.isEmpty();` 就表示整个队列是空的。

这里我的栈的实现都选择了我们自定义的实现，它不是自动扩容的，容量一旦在构造方法里给定了就不能变了。题目里说了最多调用 100 次 `push`、`pop`、`peek` 或者 `empty`，所以我这两个栈的大小也设成了 100，肯定能满足需求。

提交一下，执行通过了，测试也就过了。最后说一下，这道题目在实际开发中并没有太大的意义，它主要是让你熟悉队列和栈的各自特点——队列只能操作两端，一端添加一端移除；栈只能操作一端的添加移除。

### 单队列模拟栈

下一道题跟上一道需求反过来了：上一题是用两个栈模拟队列，这道题是用队列来模拟栈。题目还有一个进阶需求，问你是不是可以只用一个队列来实现栈。我们直接就写这个进阶需求。

这道题跟上一道类似，在实际开发中也没有太大的意义，只是帮我们熟悉队列和栈这两种数据结构的各自特点。

#### push：新元素要转到队头

先看添加操作。队列给你了，就是这个 `q`，我们先用 `q` 来做一个添加的操作。队列的添加方法是 `offer`，作用是向队列的尾部添加一个元素。

先加一个 `a`，`a` 就加到了队列的尾部，那这个 `a` 也相当于被加入到了栈的顶部，跟栈的行为目前是一样的。

接下来再加一个 `b`。`b` 被加到哪了呢？`offer` 方法总是向尾部添加，所以 `b` 肯定是加在了 `a` 的后面。但是这就不对了——我们希望它最终表现出来的是一个栈的行为，新加入的 `b` 你看现在是不是偏向于栈底的位置了，按理来讲我们期望 `b` 应该到栈顶这个位置。所以现在跟我们期望的不符。

那怎么办呢？也简单。我们希望 `b` 在栈顶，那是不是就得把 `b` 前面所有东西给它移走？但是移走了你又不能说不要，我们得把 `a` 移走之后给他再回过头来加到队列的尾部，这不就相当于 `a` 跑到了 `b` 的后面吗，`b` 现在是栈顶元素了。

所以我们的 `offer` 方法，将来加完元素之后，你得把队列前面的其他元素再给它从队列头移除，重新加入到队列里，这样才能模拟出栈这个特性。

再加一个 `c`，`c` 跑到了 `a` 的后面，跟栈的行为是不一样的，那我要让 `c` 变成栈顶怎么办？你得把前面的 `a` 和 `b` 都给它移走，它才能变到栈顶。把 `b` 先移走，从队列头移到队列尾，队列头尾是可以操作的；然后再把它前面的 `a` 也移走，也是从队列头移到队列尾。这样 `c` 就变到了栈顶。

这里有个小地方你要记牢：**每次循环的次数是 size 而不是 size-1**。因为 size 是先加一、再循环的，这跟代码逻辑配合起来刚好把前面的元素全部轮转一遍。

```text
栈的视角：栈顶 → 栈底
队列的视角：队头 → 队尾

push(a)                     [ a ]
push(b)  offer → [a b]      轮转 1 次  →  [ b a ]
push(c)  offer → [b a c]    轮转 2 次  →  [ c b a ]
                            栈顶=c，栈顶到栈底 c b a —— 与 a b c 正好逆序 ✓

再 push(d)：offer → [ c b a d ]，轮转 3 次
  [ b a d c ] → [ a d c b ] → [ d c b a ]
  栈顶 = d  ✓
```

> **易错点**：不要写 `size--`，而是 `size++`，然后循环 `size - 1` 次——因为新加的元素已经 offer 到队尾了，它自己不用再轮转。写反了就变成老元素转到新元素后面，那就不是栈了。

#### pop、top、empty 和 size 的维护

`pop` 方法非常简单，只要把 `size` 减一，从队列头移除元素，`return queue.poll()` 就可以了。`top` 是获取栈顶元素，size 不用变，调用 `peek` 获取队列的头部元素。`empty` 更简单，一个队列对应一个栈，队列为空那就是栈为空，直接 `return queue.isEmpty()`。

```java
ArrayQueue<Integer> queue = new ArrayQueue<>(100);
private int size = 0;                   // 原队列没有 size，类内自己记一个

public void push(int value) {
    queue.offer(value);                 // 先加到队列尾部
    size++;
    for (int i = 0; i < size - 1; i++) { // 再把前面的元素全部搬到队尾
        queue.offer(queue.poll());
    }
}

public int pop() {
    size--;
    return queue.poll();
}

public int top() {
    return queue.peek();                // size 不变
}

public boolean empty() {
    return queue.isEmpty();
}
```

> **提示**：题目里已经明确说了，调用 `pop` 和 `top` 的时候它保证栈不为空，所以我在代码实现里就不用写空检查了。为啥能省？因为我的队列实现里如果遇到队列为空会返回一个 `null` 值，这个 `null` 返回回来之后方法签名又是基本类型 `int`，`null` 不能转成基本类型 `int`，会出现空指针异常。现在不用做这个 `null` 判断了，代码才能简化成这个样子。

队列我选了之前自己实现的那个 `ArrayQueue`，容量也设成 100，因为题目需求说将来它的 `push`、`pop` 这些方法最多调 100 次。提交一下，都通过了。

### 双端队列：限制更少的那个

接下来正式开讲双端队列。它跟我们之前学的队列以及栈，区别在哪呢？我们先做一个简单的对比。

队列的定义是在队列的一端做删除，这一端称为队列头；另一端做添加，这一端称为队列尾。正因为它在一端添加、一端删除，所以它有一个特点 First In First Out，简称 FIFO，就是先进入队列的肯定先出来。因为它做了限制，尾部只能添加，将来头部才能取出，所以先进的一定先出来。

栈我们学过，它只能在一端做添加和删除，另一端不能做，能做操作的这一端我们称之为栈顶。正因为有这样的定义，它有后进先出的特点，Last In First Out，简称 LIFO，后放进去的先出来。因为大家操作的都是栈顶，你后面往栈顶放进去的东西，肯定先从栈顶拿出来。

今天要讲的双端队列，其实它的限制就少了：它在队列的两端都可以做删除，也都可以做添加，只是说队列的中间你不能随便操作。

| 结构 | 能操作的一端 | 不能操作的一端 | 特点 | 口头缩写 |
| --- | --- | --- | --- | --- |
| 队列 | 头删、尾加 | 中间不能动 | 先进入的先出来 | FIFO |
| 栈 | 栈顶加、栈顶删 | 另一端不能动 | 后进来的先出来 | LIFO |
| 双端队列 | 头尾都能加、都能删 | 中间不能动 | 限制更少 | — |

至于后面这几个也是跟队列相关的——优先级队列、延时队列，包括并发非阻塞队列、并发阻塞队列，这些今天暂时不设计，我们就先不做了解了。

#### Deque 接口里那八个方法

先看接口定义，顺便解释一下 `Deque` 这个名字的由来。队列的单词是 `q`，那 `Deque` 中的 `d` 就是 double 的意思，第二个 `e` 是 end 的意思，最后 `que` 是队列的意思，合在一起就是双端队列。

双端队列的特点是既可以对头做添加和删除，也可以对尾做添加和删除，所以它的添加删除方法其实一共就有四个，还有两个不删除只获取的方法，以及判空判满的方法。我们大概过一下，我就不写注释了，也比较简单：

| 方法 | 作用 |
| --- | --- |
| `offerFirst` | 向队列的头部添加元素 |
| `offerLast` | 向队列的尾部添加元素 |
| `pollFirst` | 从队列的头部删除元素 |
| `pollLast` | 从队列的尾部删除元素 |
| `peekFirst` | 获取头部元素，不删除 |
| `peekLast` | 获取尾部元素，不删除 |
| `isEmpty` / `isFull` | 判空、判满 |

一共这么八个方法，这就是我们的双端队列接口定义。

#### 为什么是双向环形链表

我们先用双向环形链表来实现双端队列。首先两个名词不要弄混了：双向和双端，它俩是指同一个概念吗？不是。

双向是什么？双向是链表的节点，它既有 `previous` 指针，也有 `next` 指针，这种我们称之为叫双向链表；只有 `next` 指针的，那叫单向链表。

双端是指什么？双端是指我们这种队列，它的两端都可以做添加、都可以做删除，这种称之为双端队列。这是这两个概念，先不要混淆了。

那这里我为什么要用双向链表来实现双端队列呢？你看之前我们实现队列的时候，是不是只用了单向链表，节点只有一个 `next` 指针？为啥它只需要一个单向链表就够了？因为队列是要删除它的头，但是尾部不需要做删除，尾部只做添加。而在链表里删一个节点，你得知道他上一个节点是谁。那删除这个队列头的话，他知不知道上一个节点呢？知道，因为实现的时候使用了哨兵，哨兵就是你第一个节点的上一个节点，所以相当于它的上一个节点是已知的，删除头不需要做额外的操作。

但是如果我要操作双端队列，是不是要删除尾啊？那删除尾你知道尾巴的上一个节点是谁吗？如果你用这种单向链表，是不是就不知道它的上一个节点是啥，你只知道尾巴自己，但尾巴的上一个你还得去查找一下，这个性能就低了。因此我们要实现双端队列的话，为了方便尾部的删除操作，我们得使用双向链表，也就是通过它的 `previous` 指针知道尾巴的上一个节点是谁。

那又为什么使用环形链表呢？环形链表我们前面讲过，它可以用一个哨兵，这个哨兵既充当头又充当尾，这样就可以节省一个哨兵，操作起来也是非常的方便。所以我们要用双向环形链表来实现双端队列。

#### 哨兵 sn 与迭代器

`Node` 类我已经定义好了，分别有两个指针 `previous` 指针和 `next` 指针，中间还有一个 `value` 值，构造方法都提供好了。给外层的队列类提供必要的属性：首先得有个容量 `capacity`，这个容量我们可以用构造方法做初始化；此外还应该有一个 `size`，代表队列中的元素个数；当然了我们刚才提到，要实现环形链表，我们得提供一个哨兵，哨兵的类型是 `Node`，名字我还是叫 `sn`。

刚开始它的 `previous`、`next` 还有 `value` 都是 `null`，那我们要对这个哨兵做一个初始化，它要既作为头也作为尾。大家来看，如果我把哨兵作为尾的话，尾的 `next` 是不是要指向头？所以一开始它的 `next` 应该指向头，头也是哨兵 `sn`，那头的 `previous` 应该指向尾，所以把它作为头的话，它的 `previous` 应该指向尾。`value` 刚开始也是这个 `sn` 啊，这样我们的哨兵就初始化好了。

```java
private static class Node {
    private Node previous;
    private Node next;
    private Integer value;

    public Node(Node previous, Node next, Integer value) {
        this.previous = previous;
        this.next = next;
        this.value = value;
    }
}

private final Node sn;               // 哨兵：既是头也是尾

public Deque(int capacity) {
    this.capacity = capacity;
    this.size = 0;
    sn = new Node(null, null, null);
    sn.next = sn;                    // 尾的 next 指向头
    sn.previous = sn;                // 头的 previous 指向尾
    sn.value = sn;
}
```

这回我们先实现 `iterator`，它比较简单。有一个 `iterator` 对象，然后设置一个 `pointer` 指针叫 `p`，这个 `p` 要从我们链表中第一个元素开始遍历。第一个元素怎么找到呢？`sn` 是头，头的 `next` 是不是就找到了我们第一个元素啊，这是我们遍历的起点。

那什么时候结束呢？就是我这个 `p` 指针它再次遇到 `sn` 哨兵的时候，就表示结束了。所以当 `p` 不等于哨兵的时候，就表示它还没有结束，没有结束那么他就不断地遍历。那每次遍历的话，先把 `p` 的 `value` 值拿到，先暂存一下，然后 `p` 向后走一步，`p = p.next`，然后返回这个 `value` 值。这是我们的迭代器已经写好了，接下来我们再去实现其他的一些方法。

```java
@Override
public Iterator<Integer> iterator() {
    return new Iterator<Integer>() {
        private Node p = sn.next;     // 从第一个元素开始

        @Override
        public boolean hasNext() {
            return p != sn;           // 再次遇到哨兵就结束
        }

        @Override
        public Integer next() {
            Integer value = p.value;  // 先取值
            p = p.next;               // 再后移
            return value;
        }
    };
}
```

## 双端队列的两副骨架：链表版补全与循环数组版实现
> 对应块：BLK29 | 覆盖分集：P113-P116 | 块标题（分集名）：《基础数据结构-074-双端队列-链表实现-2》

双端队列这个名字本身就带着一点贪心：队头要能插，队尾也要能插；队头要能删，队尾也要能删；两头还都得能探头看一眼。我们已经用双向链表把它的骨架搭起来了，方法名也都定好了，剩下的活儿就是把这些名字一个个填上具体动作。

听起来琐碎，但每一行代码该写在哪、该改哪根指针，都被哨兵节点死死钉住了。把这一块补完，链表版的双端队列就算彻底完工。

### 链表版：把剩下的方法补齐

#### 判空判满：有 size 就够了

先看最没意思的两个方法。我们这个实现里提供了 `size` 属性，所以判空判满简单得不像话：

```java
public boolean isEmpty() {
    return size == 0;
}

public boolean isFull() {
    return size == capacity;
}
```

`size` 等于零，队列就是空的；`size` 一直涨，涨到等于 `capacity`，队列就是满的。不用再去数节点，不用去看 `head` 和 `tail` 撞没撞在一起。

> **结论**：链表版判空判满完全由 `size` 说了算，这是有 `size` 的最大好处。
> **注意**：满了以后 `offerFirst` / `offerLast` 直接 `return false`，不是抛异常。

至于剩下的方法，我们就从上往下依次实现就完了。

#### 向两端添加：四个指针的手术

双向链表添加节点，你必须知道新节点的上一个和下一个。我们把上一个叫 `a`，下一个叫 `b`，被添加的节点叫 `added`——它就是夹在中间的那一个。

头插的时候：新节点要当头，它的上一个是谁？是哨兵。所以 `a` 就是哨兵，`b` 就是哨兵的 `next`。

```text
插入前:      a  <──>  b

             a.next 要改成 added
             b.prev 要改成 added
             added.prev = a
             added.next = b

插入后:      a  <──>  added  <──>  b
             ↑            ↑            ↑
          a.next     added 双指针     b.prev

读图：四根指针一次到位，a.prev 和 b.next 原样不动。
```

前面讲双向链表的时候说过，一共有四个指针需要改变，这里正好对上一根不少：两个指针还没创建出来的新节点身上，两个指针在老邻居身上。全部改完，最后别忘了 `size` 加一，`return true` 表示成功。

```java
public boolean offerFirst(E e) {
    if (isFull()) {
        return false;
    }
    Node<E> a = sentinel;
    Node<E> b = sentinel.next;
    Node<E> added = new Node<>(e);
    added.prev = a;
    added.next = b;
    a.next = added;
    b.prev = added;
    size++;
    return true;
}
```

尾插跟它差不多。开头那个判满的代码一模一样，直接粘过来；要添加的节点也得找到它的前一个和后一个，还是叫 `a` 和 `b`。这回我们要添加的是最后一个——最后一个它后面有东西吗？有啊，也是哨兵。所以这回 `b` 是哨兵，`a` 是哨兵的 `previous`。

```java
public boolean offerLast(E e) {
    if (isFull()) {
        return false;
    }
    Node<E> a = sentinel.previous;
    Node<E> b = sentinel;
    Node<E> added = new Node<>(e);
    added.prev = a;
    added.next = b;
    a.next = added;
    b.prev = added;
    size++;
    return true;
}
```

看清楚了吗？两个方法只差两行：`a` 和 `b` 分别是谁。中间的插入代码、`size++`、最后 `return true`，一字不差。所以写第二个方法的时候根本不用重写，复制一下改两行就完事。

#### 从两端移除：让 a 和 b 互相指过去

`pollFirst` 是移除队列的第一个元素。思路也是先找到被移除元素它的上一个节点 `a`，以及下一个节点 `b`，然后把中间这个 `remove` 摘掉。

先判空：队列已经空了，那没啥可移除的，直接 `return null`。

不空的话，这回要找到的是三个节点。被移除的是第一个元素，它的上一个是哨兵，所以 `a` 是哨兵，`remove` 是哨兵的 `next`，`b` 是 `remove.next`。

怎么把中间这个 `remove` 移掉？相当于让它跳过去：

```text
移除前:   a  <──>  remove  <──>  b

移除后:   a  <──────────────>  b
          a.next = b
          b.prev = a

读图：两边互相指过去，谁也不再指向 remove，它就被彻底摘出去了。
          remove 自己的 prev / next 用不着清，反正没人能走到它。
```

最后 `size` 减一，然后 `return remove.value`。

```java
public E pollFirst() {
    if (isEmpty()) {
        return null;
    }
    Node<E> a = sentinel;
    Node<E> remove = sentinel.next;
    Node<E> b = remove.next;
    a.next = b;
    b.prev = a;
    size--;
    return remove.value;
}
```

删最后一个元素跟它差不多，判空的代码直接粘过来。找 `a`、找 `remove`、找 `b`，这回我问 `b` 是谁——我们这回要移除最后一个，`b` 是哨兵；哨兵的前一个就是 `remove`，`remove` 的前一个才是 `a`。

```java
public E pollLast() {
    if (isEmpty()) {
        return null;
    }
    Node<E> b = sentinel;
    Node<E> remove = sentinel.previous;
    Node<E> a = remove.prev;
    a.next = b;
    b.prev = a;
    size--;
    return remove.value;
}
```

同样是让 `a.next` 指向 `b`、`b.prev` 指向 `a`，把中间的 `remove` 跳过去，`size` 减一，返回 `remove.value`。到这里 `pollLast` 也写完了。

#### peek：看一眼，但别动

`peekFirst` 是获取队列中第一个元素，**但不移除**。逻辑还是先判空，空了就 `return null`。不空的话，这回特别简单：哨兵的 `next` 就是队列中第一个元素，它的 `value` 就是我们要的元素值，直接 `return` 就可以了。

因为不移除，所以 `size` 也不用修改。

```java
public E peekFirst() {
    if (isEmpty()) {
        return null;
    }
    return sentinel.next.value;
}

public E peekLast() {
    if (isEmpty()) {
        return null;
    }
    return sentinel.previous.value;
}
```

`peekLast` 跟它差不多：从尾巴往前找，找到尾巴的上一个——尾巴也是哨兵，所以 `sentinel.previous` 就是最后一个元素，它的 `value` 就是要返回的值。

#### 跑一遍测试用例

省时间，测试用例我已经提前准备好了。

第一个用例：容量设成 5。先用 `offerFirst` 往队列头部加 `1`、`2`、`3`。刚加 `1` 的时候队列就是 `1`；再加 `2`，`2` 加在头部就放在 `1` 前面；再加 `3`，`3` 在 `2` 前面。所以头部这一段是 `321`。接着调两次 `offerLast` 往尾部加 `4` 和 `5`，尾部这段就是 `45`。合起来 `32145`。

现在再加第六个元素——队列满了，容量才 5，加不进去，所以应该 `return false`。

最终队列中元素的顺序是不是 `32145`？是。

第二个用例专测那些 `poll` 方法。先用 `offerLast` 加 `1`、`2`、`3`、`4`、`5`，因为全是尾部添加，顺序跟加的顺序保持一致，就是 `12345`。接下来一路拆：

| 次序 | 调用 | 返回值 | 剩余队列（头 → 尾） |
| :--- | :--- | :--- | :--- |
| 1 | `pollFirst` | 1 | `2345` |
| 2 | `pollFirst` | 2 | `345` |
| 3 | `pollLast` | 5 | `34` |
| 4 | `pollLast` | 4 | `3` |
| 5 | `pollLast` | 3 | 空 |

队列空了之后你再调任何 `poll`，返回的都应该是 `null`。最后再验一下 `isEmpty`，应该是 `true`。两个用例都跑通了。

至此为止，基于链表实现的双端队列就完成了。

### 循环数组版：元素一动不动，动的是指针

那我们换一副骨架。这一节课来实现基于循环数组的双端队列。

先说思路。我们的实现里需要两个指针：`head` 头指针和 `tail` 尾指针。刚开始这两个指针都指向数组下标零。假设我的数组长度是 4，它的有效索引就是 `0 1 2 3`。

#### 两个指针与一个空位

双端队列既然两头都能操作，那添加就有两个方向：向尾部添加是 `offerLast`，向头部添加是 `offerFirst`。

先看 `offerLast`。要向队列尾部添加一个元素 `a`，怎么办？往 `tail` 指针指向的索引位置把 `a` 加进去，加进去之后 `tail` 指针再加一。再调一次 `offerLast` 加一个 `b`，还是往 `tail` 指向的位置存进去，然后 `tail` 再加一。这就是 `offerLast`：**先添加元素，然后 `tail` 再加一**。

那 `offerFirst` 呢？有同学问了，要加到头部，那是不是得把 `a`、`b` 整体往后移一位，然后 `c` 放在最前面？不用。我们这是循环数组——**数组内的元素不要动，我们动的是指针**。所以大家别想着动元素。

那就把 `head` 指针减一，把 `c` 放进 `head` 指向的位置。

```text
初始状态（offerLast 加了 a、b 之后）
下标:     0        1        2        3
         [ 空 ]  [  a  ]  [  b  ]  [ 空 ]
          tail                             head

调用 offerFirst(c)：head 先减一 → -1，再把 -1 换算成 3

下标:     0        1        2        3
         [ 空 ]  [  a  ]  [  b  ]  [  c  ]
          tail                             head

读图：从 head 读到 tail，顺序就是  c  a  b
```

有同学说这个头指针是零啊，它减一变成 `-1` 了。没关系，你只要让它做一次索引的换算，不要让它出现无效的索引不就行了吗？减一之后把 `-1` 换算成 3，头指针就指向索引 3 了。

注意细节上它跟 `offerLast` 有个区别：`offerLast` 是**先添加元素，`tail` 再加一**；而 `offerFirst` 是**`head` 先减一，然后再添加元素**。这样读的时候才是从头到尾读，`c a b`。当然，我刚才说的这个加减，加完减完之后都要换算成合法的有效索引位置。

#### 判空判满：为什么必须浪费一个位置

那我们怎么判断这个队列是空还是满？

其实当 `head == tail`，也就是这两个指针指向的位置相同时，我们就可以认为队列是空的。而当它们之间的距离——从 `head` 一直到 `tail`，从头到尾的距离——等于数组长度减一的时候，我们就可以认为队列是满了。

看上面那张图，从 `head` 开始数 `c a b`，它们之间的距离是 3，是不是等于我们数组长度 4 减 1？所以现在这种状态表示队列已经满了。

有同学说，这不是浪费了一个位置吗？你看 `tail` 指针指向的这个位置还没存元素呢。那能不能把这个位置存一个元素，比如存一个 `d`，然后 `tail` 再加一？这样行不行？**这样就不行了。** 大家看，`head` 跟 `tail` 他俩是不是又指向同一个位置了？那相当于跟判空的条件一模一样了，你就区分不出来它到底是空还是满。

> **结论**：只用 `head` 和 `tail` 两个指针，就必须浪费一个位置来区分空和满。
> **提示**：当然，你如果另外再用一个 `size` 变量来判断空满，就可以避免这一点。我们现在不用 `size`，就用这两个指针，那必须浪费。所以将来 `tail` 停下来的这个位置，是不存储元素的。

#### 减：pollFirst 与 pollLast，顺序依然相反

删除元素调的是 `pollFirst`（从头部删）和 `pollLast`（从尾部删）。

`pollFirst` 该怎么办？是不是让 `head` 加一？是的——不过加一之后的结果要转换成有效索引，不然 `head` 直接加一能变成 4，4 是无效索引，所以得把加一换算成 0。

那这里有个关键问题：`pollFirst` 是应该**先让 `head` 加一**，还是**先取 `head` 指向的值，再让 `head` 加一**？显然我们是要移除，你是不是先得把这个值拿到呀？所以它是**先获取要移除的值，然后 `head` 再加一**。先把 `c` 拿到手，然后 `head` 加一，加一本身变成 4，换算成有效索引之后就是 0 了。

`pollLast` 呢？它应该是让 `tail` 减一。这回又是先取值还是先动指针？显然 `tail` 指向的这个位置压根不存储值，所以我们得先让它减一，减一之后再获取这个值，把它移除掉。

也就是说 `pollLast` 是**先 `tail` 减一，然后再获取要移除的值**。

四个方法的顺序摆在一起看，几乎是一张对照表：

| 方法 | 顺序 | 原因 |
| :--- | :--- | :--- |
| `offerLast` | 先放元素，`tail` 加一 | `tail` 停下的位置本来就不存元素 |
| `offerFirst` | `head` 先减一，再放元素 | 保证从头读到尾就是正确的顺序 |
| `pollFirst` | 先取值，`head` 加一 | 值要交给调用者，得先拿到 |
| `pollLast` | `tail` 先减一，再取值 | `tail` 指的位置压根没元素 |

#### increment 与 decrement：换算的活儿交给它

那具体代码怎么写？先来看两个工具方法，叫 `increment` 和 `decrement`。它们的作用就是：让我们做完加一、减一之后，索引值恢复成一个有效的索引——万一加减之后越界了，我得把它恢复成合法索引。

之前介绍用循环数组实现队列的时候，我们说过可以用求模运算来达到这个效果。现在这两个方法的实现思路稍微有些差别，我是借鉴了 JDK 中双端队列的实现——JDK 里的双端队列叫 `ArrayDeque`，我是借鉴了它的思路，我们来看下人家是怎么做的。

`increment` 的思路很简单：一旦加一之后发现越界了，那我就把它恢复成零。

```java
private int increment(int i, int capacity) {
    if (i + 1 < capacity) {
        return i + 1;
    }
    return 0;
}
```

举个例子。刚开始 `head` 和 `tail` 都指向索引 2。我调一个 `offerLast` 向尾部添加元素 `a`，那就是往 `tail` 指向的位置加 `a`，然后 `tail` 再加一。这时候 `2 + 1 = 3`，并没有超过有效索引范围，所以它会走到那个"直接加一"的分支。

那如果我再次调用 `offerLast` 呢？继续往 `tail` 指向的位置把 `b` 存进数组，然后 `tail` 再加一。这回加一是不是就超过数组长度了？`3 + 1 = 4`，大于等于数组长度 4。那怎么办？既然是循环数组，那我就把它恢复成零，让它循环开头，不就得了吗？

可以看到它这里并没有用求模运算，而是自己写了两个分支，达到类似的效果。

`decrement` 就差不多了：在减一操作之后，如果越界了，我要把它恢复成正常的正确索引值。

```java
private int decrement(int i, int capacity) {
    if (i - 1 >= 0) {
        return i - 1;
    }
    return capacity - 1;
}
```

还是举例。`head` 和 `tail` 刚开始指向索引 1，现在我要用 `offerFirst` 向队列头部添加元素——它是先让 `head` 减一，然后再加元素。减一之后 `0`，注意看，减一之后是不是仍然大于等于零？大于等于零就意味着这个索引是有效的，那直接走下面那个分支，直接减一就行了。

那如果我再次调用 `offerFirst`？这回再减一是不是变成 `-1` 了？`-1` 小于零怎么办？我们要把它恢复成正确的索引值——让它等于数组长度减一，也就是 `4 - 1 = 3`，又构成了一个循环。

### 动手实现循环数组版

#### 属性与构造方法：数组要多开一格

先给实现类添加必要的属性。首先有个数组属性，类型就是队列中的元素类型，也就是这里的 `E`；另外还需要两个指针，`head` 头指针和 `tail` 尾指针。`head` 和 `tail` 不用赋初值，因为不赋初值默认值就是零。

数组在构造方法里初始化。容量通过参数 `capacity` 传过来。我们前面说过，`tail` 停下来的位置不会存储元素，会浪费一个位置，所以我们实际数组长度应该是给定的容量**加一**。

```java
private E[] array;
private int head;
private int tail;

@SuppressWarnings("unchecked")
public ArrayDequeImpl(int capacity) {
    array = (E[]) new Object[capacity + 1];
}
```

这里有个必要的类型转换，记得加上这个警告；不想让它出现，也可以加一个注解抑制掉。最后把抽象方法先给它生成好，这样准备工作就做好了。

#### isEmpty 与 isFull：距离有两种算法

`isEmpty` 很简单，前面分析过：`head` 等于 `tail` 就表示队列是空的。

`isFull` 稍微复杂一点，在我们刚才分析的基础上，其实又可以分成两种情况。

第一种情况：假设数组长度是 4，那队列放几个元素算满呀？我们这种实现里 `tail` 指针会浪费一个索引位置，所以将来放三个元素就算放满了。我们先用 `offerLast` 加三个元素 `a`、`b`、`c`，`tail` 一路加一。这时候 `tail` 是大于 `head` 的，那直接一减就能知道距离。

```text
状态一：tail > head    数组长度 4，容量 3
下标:   0       1       2       3
       [ a ]   [ b ]   [ c ]   [ 空 ]
       head                      tail

       距离 = 3 - 0 = 3 = 4 - 1   →  满
```

第二种情况：初始状态跟刚才类似，只不过这回我调 `offerFirst` 向队列头部加三个元素，把队列先放满。要往头部放，得先让 `head` 减一，然后再往 `head` 的位置添加元素。

`head` 现在是零，减一算出来正确的索引位置是三，往索引三加第一个元素 `a`；接下来 `head` 再减一，到索引二加入 `b`；再减一，索引一加入 `c`。现在队列也满了。

但是现在我们不能用刚才的办法直接 `tail` 减 `head` 了，因为这个时候 `tail` 是零，`head` 是一，跟刚才的条件不相符，现在是 `head > tail`。

那怎么办？我们这是个环，是个环形数组。你看从 `head` 的索引出发，往右数 `c`、`b`、`a`，一直到 `tail`，距离是三；但是如果你倒着数，从 `tail` 直接逆时针往回找 `head`，那它的距离应该是一。

```text
状态二：tail < head    同样放满
下标:   0       1       2       3
       [ 空 ]  [ c ]   [ b ]   [ a ]
       tail    head

       正着从 head 数到 tail，绕一圈 = 3
       倒着从 tail 数到 head        = 1
       head - tail = 1              →  满
```

整个数组长度是 4，我放满了三个，是不是还剩一个？所以当 `tail` 小于 `head` 的时候，我们让 `head` 减去 `tail`，结果是一，就表示这个队列放满了。

写成代码也比较简单：

```java
public boolean isEmpty() {
    return head == tail;
}

public boolean isFull() {
    if (tail > head) {
        return tail - head == array.length - 1;
    } else if (tail < head) {
        return head - tail == 1;
    } else {
        return false;
    }
}
```

那个 `else` 就表示它既不是 `tail > head`，也不是 `tail < head`，是不是它俩相等了？相等的情况下表示队列是空嘛，所以 `isFull` 这里应该返回 `false`。

> **易错点**：`tail < head` 那一支里为什么是 `head - tail == 1`，而不是等于数组长度减一？因为满的时候只放了 `N - 1` 个元素，环上正好还剩一个空位，`head` 和 `tail` 只隔一格。

#### offer 与 poll：满打满算就这几行

接下来实现这些方法就非常简单了，因为前面都分析过。大家注意一点：我们在计算索引值，比如让它加一或者减一的时候，都要用刚才那两个方法——`increment` 做加法，`decrement` 做减法，因为它俩能保证我们加减完的结果仍然在一个合法范围。

`offerFirst` 先判断队列满了没，满了直接 `return false`。不满的话，`offerFirst` 是先让 `head` 减一，然后在这个 `head` 的位置添加元素。调用 `decrement` 方法让 `head` 减一，第二个参数是数组长度，因为数组长度在方法内会用到；减完的结果用它更新 `head` 的值。减完之后，在 `head` 这个索引位置添加元素，也就是通过 `array[head]` 找到索引位置，然后赋值给我们的参数，最后 `return true`。

`offerLast` 跟它差不多，也是先判断满没满，满了就 `return false`。但注意它的顺序不太一样：它是先往 `tail` 指针的位置添加完这个元素之后，`tail` 再加一。

```java
public boolean offerFirst(E e) {
    if (isFull()) {
        return false;
    }
    head = decrement(head, array.length);
    array[head] = e;
    return true;
}

public boolean offerLast(E e) {
    if (isFull()) {
        return false;
    }
    array[tail] = e;
    tail = increment(tail, array.length);
    return true;
}
```

两个 `poll` 方法也是先判断队列是不是空的，空了返回 `null`。不空的话，前面已经分析过顺序了：

```java
public E pollFirst() {
    if (isEmpty()) {
        return null;
    }
    E e = array[head];
    head = increment(head, array.length);
    return e;
}

public E pollLast() {
    if (isEmpty()) {
        return null;
    }
    tail = decrement(tail, array.length);
    return array[tail];
}
```

#### 数组实现必须考虑内存释放

刚才实现的两个 `poll` 方法还有一件事情没有考虑，就是内存释放问题。实际上只要是用数组实现的一些数据结构，都应该在删除元素时考虑内存释放。

**这是我前面的疏忽**——之前用数组实现的队列、用数组实现的栈，以及今天这个数组实现的双端队列，都应该思考一下是不是要在删除元素时考虑内存释放。为什么？我们一起来分析一下。

如果存储的是**基本数据类型**，那是不需要考虑内存释放的。比如我用数组实现了一个双端队列，存的是基本类型 `int`，这里的 `100`、`200` 都是 `int` 整数。我要把 `head` 指针指向的 `100` 删掉，怎么做？是不是让 `head` 指针加一就行了？把这个 `100` 跳过去以后访问不到它了，就意味着它被删了。

有同学说，这种情况我们不需要把 `100` 清个零什么的吗？不需要。为什么呢？你想啊，`100` 占几个字节？是不是四个字节。删除之前 `100` 占了四个字节，删除之后就算你把它清零了，那 `0` 占几个字节？是不是也占四个字节。所以你清不清零，它对内存的占用是一样的。因此本着多一事不如少一事的原则，我们不做任何处理，只要让 `head` 加一就行了。

但是反过来，如果是**引用类型**，我们就要多做一些事情，让内存及时释放。

```text
数组格子（数组自身占的内存）            堆上的对象（数组之外额外的空间）
 [r1]   [r2]   [r3]      ──引用──►     ( e1 )   ( e2 )
   └──────┴──────┘

读图：数组格子里放的是引用（地址），通过它跟堆上的对象连起来。

head 加一之后 ── 只是说「将来访问不到 r1 了」
              ── 但 r1 还躺在格子里，仍然引用着 e1
              ── GC 一看还有引用，e1 的内存永远收不掉

只有把这一格置为 null，才没人引用 e1，它才能在 GC 时被回收
```

对象占用的内存是在垃圾回收时才能得到回收的，只要有人引用它，它就释放不掉。现在 `head` 指针光加一够吗？不够——加一之后只是说将来我访问不到 `r1` 了，但 `r1` 是个引用，它引用地址引用的这个对象，它的内存会释放吗？不会。因为有 `r1` 引用着 `e1` 呢。所以我们应该把数组该索引位置的值置为 `null`。

从我们之前实现队列开始，我们就把实现都加上了泛型，为了更通用。加上泛型是不是意味着，将来这些数据结构里存储的都是引用类型？包括我们之前实现的栈呀、队列呀、双端队列呀，都加了泛型，所以我们都得考虑它的内存释放问题。

那这个代码怎么写呢？在 `pollFirst` 里，我们拿到 `head` 指针这个要删除的值、把它存到临时变量以后，为了以后没人再引用这个被删除的 `e` 对象，我们可以把 `head` 指针所在位置的这个数组值更新成 `null`。将来数组的这个索引位置就不会引用我们的 `e` 这个对象了，这样就能帮助我们做一次垃圾回收。我们写个注释：这行代码是帮助我们进行垃圾回收操作的。

类似的，在执行 `pollLast` 的时候，我们获取到了 `tail` 指针指向索引位置的值、也把它抽取成一个临时变量之后，同样把这一格置为 `null`。

```java
public E pollFirst() {
    if (isEmpty()) {
        return null;
    }
    E e = array[head];
    array[head] = null;                     // 帮助 e 的内存被垃圾回收
    head = increment(head, array.length);
    return e;
}

public E pollLast() {
    if (isEmpty()) {
        return null;
    }
    tail = decrement(tail, array.length);
    E e = array[tail];
    array[tail] = null;                     // 帮助 e 的内存被垃圾回收
    return e;
}
```

如果没有这两行呢？将来就算别处没有人引用 `e` 这个对象了，数组还是引用着它呀，`e` 的内存就得不到释放。

之前的一些实现我都改了，包括以前队列的实现、栈的实现，做删除操作的时候都做了类似的内存释放处理，这个大家可以翻看之前的代码，我就在这就不提了。

#### peek：只读不改，索引照样得先算

最后把两个 `peek` 方法也顺手实现一下，这个比较简单。先判断队列，如果是空的返回 `null`。`peekFirst` 是获取 `head` 指针位置的值，`return array[head]` 就行了。

`peekLast` 也是先判空返回 `null`，但它取的是队列尾部的值。注意 `tail` 指针我们说过它不指向元素，它的位置不存储元素，所以它要减一，才指向最后一个元素。那我们这块要怎么写？

写成 `array[tail - 1]` 行吗？不行。我们说过万一这时候 `tail` 正好是零，减一就变成 `-1` 了，不在有效索引范围里。所以我们应该调那个 `decrement` 方法，它能保证减一之后仍然是一个有效的索引。

```java
public E peekFirst() {
    if (isEmpty()) {
        return null;
    }
    return array[head];
}

public E peekLast() {
    if (isEmpty()) {
        return null;
    }
    return array[decrement(tail, array.length)];
}
```

#### 迭代器：从 head 一直走到 tail

最后来实现一下迭代器，这个比较简单，我们写过很多次了。先创建一个迭代器对象，然后设置一个指针 `pointer`。这个 `pointer` 的初始值应该是什么？是不是应该是 `head`——从 `head` 开始遍历。

那到什么时候结束呢？到它等于 `tail` 的时候就结束。什么时候这个 `pointer` 指向了 `tail`，就表示没元素了，这时候应该结束循环。所以当 `pointer` 不等于 `tail` 时，就不断地循环。

每次循环的时候，我们先获取 `pointer` 指向的这个值，也就是 `array[pointer]`，把它复制给一个临时变量，我们需要返回这个当前的值；然后让这个 `pointer` 加一。

那能不能直接写成 `pointer++`？不行，因为加一有可能让这个数组跳出它的有效索引范围。那怎么办？调那个 `increment` 方法加一。所以我们的 `pointer` 应该等于 `increment(pointer, array.length)`。

```java
public Iterator<E> iterator() {
    return new Iterator<E>() {
        private int pointer = head;

        @Override
        public boolean hasNext() {
            return pointer != tail;
        }

        @Override
        public E next() {
            E value = array[pointer];
            pointer = increment(pointer, array.length);
            return value;
        }
    };
}
```

#### 测试用例：三个来回全部跑通

迭代器写好之后就可以测试了。

第一个用例主要测两个 `offer` 方法，队列容量设置为 3。先 `offerFirst` 加一个 `1`，加在队列的头部；再调一个 `offerFirst` 加 `2`，`2` 就加到 `1` 的前面了；第三步调一个 `offerLast`，往队列的尾部加了一个 `3`。这三个方法运行完，队列中间的元素顺序应该是 `2 1 3`。那如果我再加第四个元素呢？加不进去了，因为我们设置的容量是 3，加第四个元素它应该返回 `false`，这时候队列满了。最终队列中的元素顺序是 `213`。

## Z 字层序与优先级队列：一次顺序改造，两种数组取舍
> 对应块：BLK30 | 覆盖分集：P117-P119 | 块标题（分集名）：《基础数据结构-078-双端队列-e01-二叉树Z》

### Z 字形到底是什么形状

先把这道题的形状说清楚，别急着写代码。

之前我们做过一道二叉树层序遍历的题。啥叫层序遍历呢？一层一层地来：第一层就一个根节点，第二层由左向右，第三层还是由左向右，就是 `2 3`、然后 `4 5 6 7`，这么一层一层捋下去，这就叫层序遍历。

那 Z 字形层序遍历是什么？第一层还是由左向右，第二层就反过来了，**由右向左**，输出成 `3 2`——注意，是 `3 2` 不是 `2 3`。第三层再由左向右，`4 5 6 7`。要是有第四层呢？第四层又有两个孩子 `8` 和 `9`，第四层又由右向左，输出成 `9 8`。

来来回回就是：**由左向右、由右向左、再由左向右、再由右向左**，走的就是一个 Z 字。

```text
树的层次（从左到右）        Z 字形输出
第一层：  1                 →   1
第二层：  2  3              →   3  2
第三层：  4  5  6  7        →   4  5  6  7
第四层：      8  9          →   9  8

整串输出：1 | 3 2 | 4 5 6 7 | 9 8
```

### 老骨架：层序遍历里的队列和 level

要解这道题，**在层序遍历的基础上稍作修改就能达到效果**，不用另起炉灶。所以我们先把当初那套骨架调出来回忆一遍。

层序遍历提供一个方法，根节点从参数传进来。前面先做一个特殊条件判断：根节点为空，说明二叉树里没有数据，这时候返回一个空集合就可以了；根节点不为空，说明树里有数据，就往下走。

往下走的这套操作，核心就一个队列，用来暂存下一层的节点。而整个算法的骨架是这样的：

```text
外层 while：只要队列非空，就说明还有层没处理
    └─ 内层 for：把「当前这一层」的节点全部从队列里取出来 → 塞进 level
           └─ 顺手把取出来的这些节点的孩子 offer 进队列 → 留给下一层用
```

内层循环是关键，**它就是用来区分二叉树中每一层的数据的**。每循环一次，就把当前层的数据从队列中取出来，放进一个叫 `level` 的集合里——这个 `level` 就是专门用来保存每一层的结果的。最终外层返回的那个大集合里，其实就套着一个个小的 `level`。

跑一遍当初的效果：树是三层，第一层是 `1`，第二层是 `2 3`，第三层是 `4 5 6 7`。结果打出来，第一层 `level` 里是 `1`，第二层是 `2 3`，第三层是 `4 5 6 7`。这就是正常的层序遍历。

### 只改一处：偶数层改从队头插入

现在的问题是：`level` 保存的每一层结果，顺序全是「从左到右」。而我们只需要在**偶数层把顺序倒过来**。

那怎么倒？大家想一想 `level` 里用的是哪个添加方法。原代码调的是往集合**尾部**添加元素的那个方法：第一次循环加了 `2`，再往尾部加入 `3`，三就加在了二的后面，于是顺序就是 `2 3`。

那反过来，如果我事先知道这一层是偶数层，添加的时候**改成往集合的头部添加**呢？先往头部加 `2`，再往头部加 `3`——三是不是就跑到二的前面了？这样是不是就实现了偶数层逆序的效果？

所以整个思路就一句话：**只要能区分出当前处在哪一层，然后调用不同的添加方法就可以了**。奇数层往尾部加，偶数层往头部加。

这里就该我们刚学过的双端队列出场了。为什么不能用原来的 `ArrayList`？因为它底层是普通数组，往尾部添加效率还可以，但一遇到偶数层要往头部添加，效率就不高了。双端队列的底层实现既可以基于链表，也可以基于环形数组，**不管往头部加还是往尾部加，效率都很高**。用我们之前写过的任何一个双端队列实现都行，另外 JDK 自己也有 `ArrayDeque`，还有 `LinkedList`——`LinkedList` 本身就是一个双端队列。这里我们就用基于链表实现的 `LinkedList`。

> **易错点**：因为要用双端队列特有的方法（往头部插），所以 `level` 那里就不能再声明成普通的接口类型了，直接写成 `LinkedList`。

怎么区分奇偶层？设一个布尔变量 `isOdd`，代表「当前是不是奇数层」。一开始它是 `true`，因为我们认为第一层是 `1`，从奇数层开始。如果是奇数层，还是往尾部添加，调用 `offerLast`；不是奇数层、就是偶数层的话，调用 `offerFirst` 把节点的值加到头部。

每次内层循环循环完一遍，就到了下一层，把这个奇偶标志取反就行：`isOdd = !isOdd`。原来是奇数层，取反变偶数层；原来是偶数层，取反变奇数层。

```java
public List<List<Integer>> zigzagLevelOrder(TreeNode root) {
    if (root == null) {
        return Collections.emptyList();       // 根为空，二叉树里没数据，返回空集合
    }

    List<LinkedList<Integer>> result = new ArrayList<>();
    // 队列用来暂存下一层的节点
    Queue<TreeNode> queue = new LinkedList<>();
    queue.offer(root);

    boolean isOdd = true;                     // 第一层是奇数层，由左向右

    while (!queue.isEmpty()) {
        // 双端队列：奇数层往尾部加，偶数层往头部加
        LinkedList<Integer> level = new LinkedList<>();
        int levelSize = queue.size();         // 先固定住当前层的节点个数

        for (int i = 0; i < levelSize; i++) {
            TreeNode node = queue.poll();     // 取出一个属于当前层的节点

            if (isOdd) {
                level.offerLast(node.val);    // 奇数层：由左向右
            } else {
                level.offerFirst(node.val);   // 偶数层：由右向左
            }

            if (node.left != null) queue.offer(node.left);
            if (node.right != null) queue.offer(node.right);
        }

        result.add(level);
        isOdd = !isOdd;                       // 下一层，奇偶翻转
    }

    return result;
}
```

跑一下：第一层还是 `1`，第二层是 `3 2`，第三层是 `4 5 6 7`。顺序对了，偶数层就是倒过来了。这道 Z 字层序遍历就这么实现完了。

> **结论**：Z 字形层序遍历 = 层序遍历 + 一个奇偶标志 + 偶数层改从队头插入。

### 优先级队列：出队不再按先后

接下来我们换一种队列，优先级队列。它跟之前学的普通队列做个比较：普通队列的特点是**一端进、另一端出**——从队列的尾部进入，然后从队列的头部出来。优先级队列也是一端进、一端出，那它们的区别在哪呢？

普通队列有个特点叫 **FIFO**，First In First Out，先进先出。优先级队列呢？它**不一定按进入队列的顺序出来**，而是按队列中元素的一个优先级来出——优先级高的先出来，优先级低的后面出来，是**按优先级出队**。

来看个例子，这是我提前写好的一个测试用例。队列里放了一些元素，每个元素是一个 `Entry`，可以理解为一系列任务——任务一、任务二等等，每个任务都有自己的 `priority` 优先级。

入队顺序是任务 `1 2 3 4 5`。但由于优先级不同，出队的时候就不一样了：第一次出队的是优先级最高的 `5`，也就是任务四；第二次出队的是优先级 `4` 的任务，也就是任务一；以此类推。**入队的顺序跟出队的顺序完全不一样了。**

所以两种队列的差别，一句话讲清楚：

| 队列 | 出队依据 | 典型场景 |
| --- | --- | --- |
| 普通队列 FIFO | 谁先进来谁先出去 | 排队买票，先来后到 |
| 优先级队列 | 谁优先级高谁先出去 | 任务调度，紧急任务先处理 |

优先级队列常见有三种实现。这一块我们先把前两种、基于数组的实现讲完，第三种要用到一个新的底层数据结构，放到后面再讲。

### 无序数组：入队简单，出队靠扫

先看第一种：**基于无序数组**的实现。

准备一个数组，紫色部分是数组的索引，蓝色部分是数组中的元素，元素里的数字就代表它的优先级。这里先做个约定：**数字越大，优先级越高**，数字小的优先级就低。

那么入队的时候怎么做？特别简单——**往数组的尾部把新元素加进来就可以了**。假设新元素的优先级是 `3`，执行一次 `offer`，它就加到了尾部。注意：新加入元素的优先级跟原来的元素并没有任何顺序上的关系，只要加到尾部就行。

#### 出队要先找出最大值的下标

出队就没这么简单了。出队是执行 `poll`，但我们**不能随便挑一个给他出队**，应该挑优先级最高的那个出队，也就是那个 `10`。

怎么找？大家也能想到，**遍历一遍数组，找出优先级最高的那个**。这个过程我们用两个指针来走：

- `max`：代表当前最大值所在的下标，最开始假设零索引这个元素就是最大的，初始值 `0`；
- `i`：从一开始，每次循环向后加一。

每次把 `i` 指向的元素跟 `max` 指向的元素比较，如果 `i` 的元素比 `max` 的大，就把 `max` 更新成 `i`。

代到数组 `[4, 2, 1, 5, 10, 7, 3]` 上走一遍：`2` 比 `4` 小，`max` 不用动；`1` 比 `4` 小，也不用动；接下来 `5` 比 `4` 大，把 `max` 更新成索引 `3`；重复这个逻辑，`10` 比 `5` 更大，把 `max` 更新成索引 `4`；最后 `7` 和 `3` 都没有这个 `10` 大。所以直到遍历到数组结尾，我们找到了最大的索引值，就是索引 `4`。

找到了怎么出队？很简单，**把这个元素从数组中删掉就行了**。就是找到最大值时把它删掉，后面的 `7` 和 `3` 都向低下移一格。

所以第一种实现就是这样：入队没啥可做的，把新元素加到数组末尾；出队的时候遍历一遍数组，找到优先级最高的元素，然后把它从数组删除。

> **结论**：这个出队操作，相当于进行了一轮**选择排序**。

#### 中间删一个元素就是移位

`remove(int index)` 就是从数组中间删一个元素，这个我们在讲动态数组时介绍过，这里权当复习。

思路是：如果你删的是最后一个元素，其实只要让 `size` 减一就行了，让它访问不到范围之外的这个被删除元素就 OK 了。如果删的不是最后一个元素，比如删的是索引 `4`，我就应该把它后续的元素向前挪一位——`5` 处的这个 `7` 要向前挪，保证数组元素的连续性。

怎么判断你删的是不是最后一个元素？当 `index` **小于 `size - 1`** 时，说明它不是最后一个元素，这时候才需要移动；如果它等于 `size - 1` 了，就不需要移动。但两种情况最终都要让 `size` 减一。

移动的代码用 `System.arraycopy` 最简单：第一个参数是原数组 `array`；移动的起始位置是删除索引加一，比如例子中是从 `5` 往 `4` 移动；目的数组还是 `array`，目的索引起始位置就是被删除的位置 `index`；最后一个参数表示移动的元素个数，是 `size - 1 - index`。为什么？看这个例子最后的索引位置是 `6`，`6` 减去被删除的索引 `4`，正好就是 `2`——两个元素要移。

#### 代码实现

先把类的骨架定下来。它实现了我们自己的 `Queue` 接口，因为优先级队列也具备队列的一些方法——`offer`、`poll`、`peek`，还有判空判满的方法都应该有。

这里跟以前**不一样**的地方在于：队列中的元素，也就是这个泛型 `E`，它**不能是任意类型**的。不是所有的 Object 类都有「优先级」这么一个特性，所以我们应该让放进优先级队列中的元素必须实现一个接口，我给它起名叫 `Priority`（当然这个 `Priority` 是我自己定义的）。它的作用就是返回这个元素的优先级，是一个整数，**整数越大表示优先级越高**——这就是前面约定好的。

所以数组的类型也应该是 `Priority` 而不是 `E`。另外还需要一个代表数组中元素个数的变量 `size`。构造方法给数组一个初始容量 `capacity`，它决定了队列的大小。索引不用环形那套了，直接从 `0` 到 `size - 1` 就行。

判空判满最简单：`size` 等于零表示队列为空，`size` 等于数组长度表示放满了。

```java
public class PriorityQueue1<E extends Priority> implements Queue<E> {

    private Priority[] array;   // 元素必须实现 Priority 接口
    private int size;

    public PriorityQueue1(int capacity) {
        this.array = new Priority[capacity];
    }

    public boolean isEmpty() {
        return size == 0;
    }

    public boolean isFull() {
        return size == array.length;
    }

    // 入队：只往尾部塞，满了就直接失败
    @Override
    public boolean offer(E e) {
        if (isFull()) {
            return false;
        }
        array[size++] = e;
        return true;
    }

    // 返回优先级最高的元素的下标——poll 和 peek 都要用
    private int selectMax() {
        int max = 0;                    // 先假设零索引优先级最大
        for (int i = 1; i < size; i++) {
            // 每个元素都实现了 Priority，都能调 getPriority()
            if (array[i].getPriority() > array[max].getPriority()) {
                max = i;                // 比当前最大值大，就更新下标
            }
        }
        return max;
    }

    @Override
    public E peek() {
        if (isEmpty()) {
            return null;
        }
        int max = selectMax();
        return (E) array[max];          // 接口限定返回 E，要强转
    }

    @Override
    public E poll() {
        if (isEmpty()) {
            return null;
        }
        int max = selectMax();
        E e = (E) array[max];           // 必须先记录，再删除
        remove(max);
        return e;
    }

    // 从数组中间删一个元素，本质是移位
    private void remove(int index) {
        if (index < size - 1) {
            System.arraycopy(array, index + 1, array, index, size - 1 - index);
        }
        size--;
    }
}
```

> **易错点**：`poll` 里千万别写成先 `remove` 再 `return array[max]`。你把 `max` 位置删掉之后，上面的元素就顶上来取代了原来的位置，这时候返回的**根本不是你要的那个优先级最高的元素**，而是它上面那个元素。所以一定要先用一个临时变量 `e` 记录下来，删完再返回。

测试用例基本没怎么改，只是让 `Entry` 实现了 `Priority` 接口。它的 `value` 其实主要就是一个文字描述——你是任务一、任务二，代表一个加入队列的信息；真正决定优先级的是后面这个 `priority`。加入的顺序是任务 `1 2 3 4 5`，优先级随便给了一组值。出队的话，第一个出来的肯定是优先级最高的 `5`，也就是任务四；第二个出来优先级 `4` 的任务一，以此类推。跑一遍，全部测试通过。

### 有序数组：出队简单，入队靠插

第二种实现：**基于有序数组**。

数组索引还是 `0 1 2 3 4`，但注意看，现在元素是**排好序的**，分别是 `1 4 5 8 10`。**优先级越大的元素排在数组的尾部。**

这样做的好处立刻就体现出来了：将来出队变得非常简单——出队的目的就是把优先级最大的元素删掉，而它就在数组尾部，**找到尾部元素删掉就 OK 了**。

```text
无序数组：[4, 2, 1, 5, 10, 7, 3]      10 不知道在哪儿，得扫
有序数组：[1, 4, 5, 8, 10]            最大值固定在尾部，直接拿
```

#### 尾部就是答案

`peek` 返回队列中优先级最高的元素。你看我们现在都排好序了，优先级最高的是谁？是不是就是队列尾部这个元素。所以我们只要找到队列尾部元素返回就行了：

```java
@Override
public E peek() {
    if (isEmpty()) {
        return null;
    }
    return (E) array[size - 1];
}
```

`poll` 呢？不光是要找到尾部这个优先级最高的元素，还要把它删掉。先赋值给一个临时变量，最终返回它。怎么删？`size` 减一就访问不到刚才那个尾部元素了。

**但是光这样做够吗？** 其实我们忽略了一个问题：前面讲过，数组中存储的是**引用类型**，你光 `size` 减一了，数组还引用着刚才的这个对象呀——刚才那个 `10` 号对象还被引用着呢。所以最好应该断开数组跟这个对象之间的联系：在 `size` 处减一之后，把 `size` 处的这个引用**置为 `null`**。这样有助于垃圾回收，将来 GC 的时候才能把那个优先级为 `10` 的对象占用内存给释放掉。

这两行可以合二为一：先减 `size`，再把 `size` 处的引用置为 `null`，写成左减减就等价了。

```java
@Override
public E poll() {
    if (isEmpty()) {
        return null;
    }
    E e = (E) array[--size];   // 先减一，再断开引用
    array[size] = null;         // 有助于垃圾回收
    return e;
}
```

> **易错点**：这个 `null` 赋值别省。上一节的实现里我们只做了 `--size`，没有把那个引用地址释放掉，这里顺手补上。

#### 入队是在跑一次插入排序

反过来，入队就要复杂一些。假设我有一个新元素，优先级是 `3`，我要把它入队，是不是得**把它按顺序排列好**，不是说加在尾部就行了。

来看一下过程。既然要入队，第一步得先把这个数组的 `size` 加一——数组元素数量加一，加一之后相当于在末尾腾出了一个坑。然后设置一个指针 `i`，从后往前，把要入队的元素优先级跟 `i` 指向的元素优先级做对比：

- `10` 比 `3` 大，应该排在数组更靠尾部的位置，所以 `10` 向后移动一位；
- `i` 再找下一个元素，`8` 比 `3` 也大，`8` 也要向后移动一位；
- 再往下 `5` 比 `3` 大，`5` 向后移；`4` 比 `3` 大，`4` 也向后移；
- 最后比较这个 `1`，`1` 比 `3` 小了，那就不用移动了。

那 `3` 是不是就应该插入到索引 `1` 这个位置？这样就完成了一次入队操作。

> **结论**：这个入队操作，就是我们之前做过练习里的**一次插入排序**。

因为这段插入的代码有一定的通用性，我们单独写一个 `insert` 方法来完成它。它不需要有返回值，作用是把我们的元素插到数组中正确的位置。

指针 `i` 的初始值应该是 `size - 1`，然后不断减小，一直到 `0`。判断条件是两个：`i` 大于等于零，**并且** `i` 处的优先级比我们要入队的元素 `e` 的优先级还要大——满足就说明 `i` 指向的元素要往上移，移到 `i + 1` 的位置去。然后每次 `i` 要减减。

退出循环之后，就把 `i + 1` 的位置加入我们的元素 `e` 就可以了。

边界条件也没问题：假如我们要插的元素最小，比如插一个 `0`，它比这里的 `1` 还要小。那 `i` 会一直减到 `-1`，小于零了也没有关系，表示循环退出。此时 `i + 1` 正好是 `0`，把 `0` 加到这个位置就 OK 了。所以这段代码对边界条件也是没有问题的。

```java
@Override
public boolean offer(E e) {
    if (isFull()) {
        return false;
    }
    size++;                  // 先腾一个坑，元素个数加一
    insert(e);               // 从 size - 1 往前找位置
    return true;
}

private void insert(E e) {
    int i = size - 1;
    for (; i >= 0 && array[i].getPriority() > e.getPriority(); i--) {
        array[i + 1] = array[i];    // 比我大的，整体向后挪一位
    }
    array[i + 1] = e;               // i 退到 -1 时，正好落在下标 0
}
```

> **提示**：`offer` 里是**先 `size++` 再 `insert`**，顺序别搞反。`insert` 的扫描起点是 `size - 1`，只有先把坑位算进去，它才知道要从后往前挪到哪儿；插完之后元素个数自然就加上了。

跟上一个实现相比，很多代码都是一样的——声明队列元素类型必须实现 `Priority` 接口、`array` 属性、`size` 属性、判空判满方法，这些都一模一样，直接拷贝过来用。不一样的主要就是 `offer`、`poll`、`peek` 这三个方法。

测试用例基本没改，只是把测试类换成了我们新的这个实现类，加入的对象优先级有高有低。入队不管你优先级是高是低，出队肯定是按优先级出队的：优先级最高的 `5`（任务四）第一个出来，接着是优先级 `4` 的任务一，然后是任务二、任务三，优先级最低的任务五最后出来。跑一下，也都通过了。

### 复杂度：两种实现正好反过来

我们来把账算清楚。

**基于无序数组**的实现：入队就是往数组尾部加一个元素，时间复杂度是 $O(1)$。出队 `poll` 以及包括 `peek`，时间复杂度是 $O(n)$——因为你要找 `max`，得把 $n$ 个元素做一个比较，找出一个最大值。

**基于有序数组**的实现正好反过来：`poll` 和 `peek` 总是在取这个数组尾部的元素，时间复杂度是 $O(1)$；而 `offer` 因为要执行一个插入操作，最糟糕的情况下要给数组中每个元素比较一次，时间复杂度是 $O(n)$。

```text
无序数组                          有序数组
offer → 尾部直接塞，O(1)          offer → 跑一次插入排序，O(n)
poll  → 扫全表找最大值，O(n)       poll  → 永远取尾部，O(1)
```

| 实现 | 入队 offer | 出队 poll / 查看 peek |
| --- | --- | --- |
| 无序数组 | $O(1)$ | $O(n)$ |
| 有序数组 | $O(n)$ | $O(1)$ |

一个把复杂度压在入队上，一个压在出队上。**这两种做法都不是最好的**——所以第三种实现要登场了，不过它得用到一个新的底层数据结构，我们下一块再讲。

### 本讲提到的题目

**二叉树的 Z 字形层序遍历**

**题干**：给定一棵二叉树，返回它所有节点按层次遍历的顺序，其中奇数层由左向右、偶数层由右向左交替进行，即 Z 字形（蛇形）顺序。

比如这棵树：

```text
        1
      /   \
     2     3
    / \   / \
   4   5 6   7
      / \
     8   9
```

输出就是：第一层 `1`；第二层 `3 2`；第三层 `4 5 6 7`；第四层 `9 8`，即 `1 | 3 2 | 4 5 6 7 | 9 8`。

**解析**：这题不需要新算法，在层序遍历的基础上改一处即可。层序遍历用队列暂存下一层节点、用内层循环区分层数、用一个集合 `level` 保存每层结果；把 `level` 换成双端队列后，奇数层用 `offerLast` 从尾部加，偶数层用 `offerFirst` 从头部加，加一个布尔标志 `isOdd` 在每层结束后取反即可。正文「只改一处：偶数层改从队头插入」一节给出了完整实现与推导。

**答案**：见正文中的 `zigzagLevelOrder` 实现，输出 `1 | 3 2 | 4 5 6 7 | 9 8`。
