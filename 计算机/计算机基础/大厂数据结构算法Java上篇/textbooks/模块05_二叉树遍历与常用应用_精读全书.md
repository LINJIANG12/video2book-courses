## 分层遍历怎么数出层，栈怎么搭起来
> 对应块：BLK26 | 覆盖分集：P102-P105 | 块标题（分集名）：《基础数据结构-069-队列-e01-二叉树层序遍》

先接着把层序遍历收个尾。

前面的写法已经把树完整走了一遍：根节点先进队列，每出一个就把它的左右孩子塞回队列，队列空了树也就走完了。跑一下，控制台上确实把 7 个节点的值都打出来了——可全挤在同一行，一、二、三、四、五、六、七排成一条长龙。

> **易错点**：能跑通不等于对。层序遍历名字里那个"层"字，到现在还没体现出来。

### 先让输出分出层来

要的分层效果，说白了就一句话：第一层的内容输出完就换行，第二层输出完再换行，第三层接着换。

那代码上怎么搞？外层循环保持不动，**在里面再套一个内层循环**：内层循环跑一次，输出一个换行符。就这样——第一层一个节点换一次行，第二层两个节点换一次行，第三层四个节点再来一次。分层效果立刻就出来了。

问题紧接着就来了：内层循环到底该跑几次？

答案很直白：**就跑当前这一层节点的个数**。第一层 1 个就循环 1 次，第二层 2 个就循环 2 次，第三层 4 个就循环 4 次。

于是问题转化成了：我怎么知道每一层到底有几个节点？

这个好办——自己数。

看第一层，只有根，它有两个孩子，那下一层就是 2 个节点。第二层是 2 和 3，它俩一共有 4 个孩子，那第三层就是 4 个节点。规律就是这么朴素：把当前层每个节点的孩子数加起来，就是下一层的节点数。

> **定义**：下一层节点数 = 当前层所有节点的孩子总数。

这里必须补一句：**这个数没有规律可循，得自己算**。二叉树里一个节点可能有两个孩子，也可能只有一个，还可能一个都没有，你事先不知道它是哪一种，所以别指望能从上一层的个数乘 2 推出来——那是满二叉树才有的性质。

那就开始写代码。引入两个变量：

- `c1`：当前这一层的节点数。它的初值是**已知的**，因为一开始我们只往队列里塞了一个根节点，第一层就是 1 个，所以 `c1 = 1`；
- `c2`：下一层的节点数。初值先给 0，代表还不知道。

内层循环写成 `i < c1`，循环体里干原来那几件事：出队一个节点、打印它的值（顺带把它的左右孩子塞回队列）。每塞一个孩子，就 `c2++`——左孩子加一，右孩子也加一。这样内层循环跑完，`c2` 里就攒好了下一层的节点数。最后把 `c1` 更新成 `c2`，交接给下一轮外层循环。

```java
public void levelOrder(Node root) {
    Queue<Node> queue = new LinkedListQueue<>();
    queue.add(root);

    int c1 = 1;                 // 当前层的节点数，一上来是已知的：第一层只有根
    while (!queue.isEmpty()) {
        int c2 = 0;             // 下一层的节点数，先归零，等着重新统计

        for (int i = 0; i < c1; i++) {
            Node node = queue.poll();
            print(node.value + " ");   // print 不换行，节点之间用空格隔开

            if (node.left != null) {
                queue.add(node.left);
                c2++;
            }
            if (node.right != null) {
                queue.add(node.right);
                c2++;
            }
        }

        println();               // 这一层输出完了，换行
        c1 = c2;                 // 下一层的节点数交接给 c1
    }
}
```

这里有三个地方要留意。

第一，输出那里我特意改成了 `print` 而不是 `println`，节点后面补一个空格。不换行 + 空格，等这一层全打印完了再统一来一个换行，层次感才是连贯的；要是每个节点各换一行，那又回到挤不挤的问题上去了。

第二，**内层循环的次数不能写死**。`c1` 每轮都在变，第一层是 1，第二层是 2，第三层可能是 4 也可能是 3，所以条件只能是 `i < c1`。

第三，`c2` 是"边循环边累加"的，它必须在每个外层循环开始时重新归零——它是"下一层"的计数，上一轮的值对这一轮没用。

跑一遍你就明白了：第一次 `c1` 是 1，内层循环跑一次，输出一个换行；第二次统计出下层是 2 个节点，就循环两次，再一个换行；第三轮又是 4……以此类推，分层效果就这么出来了。

> **提示**：这里用的是我们自己写的那个队列类。搬到力扣上时要连队列代码一起粘过去，麻烦的话就把接口定义去掉简化一下，或者干脆换成 JDK 的 `LinkedList`——Java 里的 `LinkedList` 本身就是一个双端队列，拿来做这道题完全够用。

### 力扣要的不是打印，是收集

控制台打印只是演示。真到力扣那道题上，要求不是"把节点打印出来"，而是**把这些节点收集起来**。

收集的形式是两层嵌套的集合：外面一个大集合，里面每一层再套一个小集合。

```text
大集合 result = [
    [ 1 ],        ← 第一层
    [ 2, 3 ],     ← 第二层
    [ 4, 5, 6, 7 ]← 第三层
]
```

也就是说，外层 list 装着所有层，每一层自己是一个小 list，代表这一层的节点值。第一层的 1 放进第一个小集合，第二层的 2 和 3 放进第二个，第三层的 4、5、6、7 放进第三个，最后这三个小集合统一塞进外层大集合，返回的就是这个结构。

好在我们刚才的代码几乎可以照抄，关键就是三处改动：

1. 创建一个大集合 `result`，方法最后 `return result`；
2. **在"换行"的那个位置创建内层小集合**——因为换行就意味着一层结束了，正好是新一层开始。集合的元素类型是 `Integer`，我们就叫它 `level`；
3. 把原来"打印这个节点"的地方，换成"把这个节点的值 `add` 到 `level` 里"。注意只存 `value`，不要把整个节点塞进去。内层循环跑完，说明这一层收集齐了，再把 `level` 加进外层的 `result`。

另外还有一种特殊情况必须处理：题目完全可能给你传一个 `null` 进来。`root == null` 说明里面根本没有任何节点数据，直接返回一个空的 `result` 就行，不用往下走。

```java
public List<List<Integer>> levelOrder(TreeNode root) {
    List<List<Integer>> result = new ArrayList<>();
    if (root == null) {
        return result;                  // 空树，返回空的二维列表
    }

    Queue<TreeNode> queue = new LinkedListQueue<>();
    queue.add(root);

    int c1 = 1;
    while (!queue.isEmpty()) {
        List<Integer> level = new ArrayList<>();   // 当前层的数据
        int c2 = 0;

        for (int i = 0; i < c1; i++) {
            TreeNode node = queue.poll();
            level.add(node.value);                  // 只收 value，不收节点

            if (node.left != null) {
                queue.add(node.left);
                c2++;
            }
            if (node.right != null) {
                queue.add(node.right);
                c2++;
            }
        }

        result.add(level);              // 这一层齐了，塞进大集合
        c1 = c2;
    }

    return result;
}
```

改动就这么多，核心那套 `c1` / `c2` 的计数逻辑一行没动。

### 栈：只能在一端动手的线性结构

下面我们换一种数据结构——栈。

到目前为止学的数组、链表、队列，全都是线性结构：元素从头到尾连成一条线。栈也是线性的，但它的限制比队列还狠。

| 结构 | 能在哪儿做添加 / 删除 |
| --- | --- |
| 数组、链表 | 线的任意位置都行：两端、中间，想动哪儿动哪儿 |
| 队列 | 只能两端：一端添加（队尾），一端删除（队头） |
| 栈 | **只能一端**：添加和删除都发生在同一个端 |

栈能做操作的那一头叫**栈顶**（top），另一端不能动的叫**栈底**（bottom），中间也不能动。

打个比方最好懂：栈就是我们生活中那一摞厚厚的书。往这摞书里加书，只能从最上面加；要拿书，也是从最上面拿。如果你偏偏想要最底下那一本怎么办？只能把上面的书一本一本全搬走，才够得着。

栈的规矩就这么多：进出只能同进同出，中间没得插。

### 接口里的五个方法

跟前面一样，先给栈定个接口，再给这个接口配常见实现。这个接口里定了五个方法：

| 方法 | 干什么 | 失败 / 空时返回 |
| --- | --- | --- |
| `push(value)` | 向栈顶添加元素，也叫"压入" | 栈满了返回 `false` |
| `pop()` | 从栈顶弹出元素（移除并取出） | 栈空了返回 `null` |
| `peek()` | 拿到栈顶元素的值，**不移除** | 栈空了返回 `null` |
| `isEmpty()` | 判断栈是不是空的 | 返回 `boolean` |
| `isFull()` | 判断栈是不是已经装满了 | 返回 `boolean` |

`push` 和 `pop` 是一对，都在操作栈顶，中间和栈底都是碰都不碰的。`peek` 和 `pop` 长得像，区别就一个：**拿不拿走**。`isEmpty`、`isFull` 看名字就知道了。

栈接口下面给了两个实现：**基于链表的**，和**基于数组的**。一个一个来。

### 链表版栈：哨兵节点加一个头指针

先看链表版。准备一个单向链表，配一个哨兵节点来实现栈。因为是单向的，节点类很简单，就两个东西：一个 `value`，一个 `next` 指针。

```java
public class Node<E> {
    private E value;
    private Node<E> next;

    public Node(E value, Node<E> next) {
        this.value = value;
        this.next = next;
    }
}
```

然后是三个属性：

- `capacity`：容量。栈得有个容量上限，用构造方法初始化；
- `size`：栈中元素的个数。刚开始是 0，你不断往栈顶压元素，它就跟着涨，而且不能超过 `capacity`；
- `head`：头指针。它一开始就指向一个哨兵节点。

哨兵节点是个什么东西？就是一个值无所谓、只起"起跑线"作用的节点。刚建好的时候里面没元素，所以让哨兵的 `next` 指向 `null`。

```java
private int capacity;
private int size;
private Node<E> head;

public LinkedListStack(int capacity) {
    this.capacity = capacity;
    this.size = 0;
    this.head = new Node<>(null, null);   // 哨兵节点，它没有后继
}
```

这里有个问题值得停下来想一秒：链表版**队列**我们用了 `head` 和 `tail` 两个指针，栈为什么一个就够了？

因为队列要操作两端——`head` 那端移除，`tail` 那端添加——两个指针才方便。而栈只操作一端，全程只在**栈顶**做添加和移除，那就在 `head` 这部分搞定，完全用不着再来一个尾指针。

#### 空和满怎么判断

判断空，其实有好几种写法。一开始 `head.next` 指向的是不是 `null`？是的话说明没有下一个节点了，那就是空栈。所以判断 `head.next == null` 是可以的。

也可以用我们准备的 `size`：`size == 0` 就是空。这里我们用 `size`，好维护。

判断满更简单：只要 `size` 不断增长，什么时候 `size == capacity` 了，就是装满了。

```java
public boolean isEmpty() {
    return size == 0;          // 也可以写成 head.next == null
}

public boolean isFull() {
    return size == capacity;
}
```

#### push：往前插一节车厢

`push` 是往栈顶添加元素。假设现在栈里已经有个元素 1，结构是 `哨兵 → 1 → null`，现在要压一个 2 进去——插在哪儿？插在 1 的前面，也就是 `head` 的后面，让 2 成为新的第一个节点。

```text
  压入前                      压入 2 之后
   head                       head
    |                          |
    v                          v
  [哨兵] --> [1] --> null   [哨兵] --> [2] --> [1] --> null
  栈顶: 1                     栈顶: 2
```

写法上分几步：先判断栈满没有，满了就 `return false`；没满就创建一个新节点，它的 `value` 来自参数，它的 `next` 指向原来的第一个节点（也就是 `head.next`）；然后让 `head.next` 指向这个新节点，新节点就正式成为第一个节点、也就是栈顶了；最后 `size++`，返回 `true`。

```java
public boolean push(E value) {
    if (isFull()) {
        return false;                  // 满了，压不进去
    }
    Node<E> node = new Node<>(value, head.next);   // 新节点指向原来的第一个节点
    head.next = node;                              // head 转而指向新节点
    size++;
    return true;
}
```

#### pop：从栈顶摘掉第一节

`pop` 是从栈顶移除元素。假设现在栈顶是 2，我要把 2 移走——让哨兵的 `next` 直接指向 2 的下一个节点（1），相当于把 2 跳过去了。

先判空，空了没什么可移除的，返回 `null`。不空的话，先把第一个节点找出来，起个名字叫 `first`，然后让 `head.next` 指向 `first.next`，它就被跳过去了。最后返回 `first.value`，注意 `size--`。

```java
public E pop() {
    if (isEmpty()) {
        return null;                   // 空栈，没什么可移除的
    }
    Node<E> first = head.next;
    head.next = first.next;            // 把 first 跳过去
    size--;
    return first.value;
}
```

#### peek：看一眼但不动

`peek` 是拿栈顶元素的值，但**不移除**。那就照着 `pop` 复制一份改改：空栈还是返回 `null`；因为不移除，所以不需要 `head.next = first.next` 这一行；因为不移除，`size--` 也不要了。

改完发现还能再简洁一点：这里的 `first` 本来就等于 `head.next`，那两行完全可以合成一行，上面那个临时变量都不用留。

```java
public E peek() {
    if (isEmpty()) {
        return null;
    }
    return head.next.value;            // 拿栈顶，但不移除
}
```

#### iterator 和两个测试用例

最后把 `iterator` 补上。创建一个迭代器对象，里面建个指针 `p`，初始值是 `head.next`——因为遍历要从第一个元素开始。什么时候算遍历结束？我们整个链表就是以 `null` 收尾的，所以 `p != null` 就继续。每次遍历先把 `p` 的 `value` 存进临时变量，然后让 `p` 向后走一步（`p = p.next`），返回临时变量。

```java
public Iterator<E> iterator() {
    return new Iterator<E>() {
        private Node<E> p = head.next;      // 从第一个元素开始

        @Override
        public boolean hasNext() {
            return p != null;               // null 是整条链表的结尾
        }

        @Override
        public E next() {
            E value = p.value;
            p = p.next;
            return value;
        }
    };
}
```

测试用例很简单。建一个容量为 3 的栈，依次 `push` 1、2、3：刚开始压进去的 1 在栈底，后来压的 2 跑到栈顶，最后压的 3 又在最上面——所以从栈顶到栈底的顺序是 **3、2、1**。再压第 4 个元素，因为超过容量了，返回 `false`，表示压入失败。

第二个用例同样是容量 3、压进 1、2、3，这回专门测 `pop`：第一次 `pop` 出来的是栈顶元素 3，第二次是 2，最后一次是 1。再 `pop` 一次——栈已经空了，应该返回 `null`。跑一遍，全对。

### 数组版栈：把栈顶安排在右边

接下来是数组实现。同样实现栈接口，抽象方法先生成，然后加属性。

属性有两个：

- 一个底层数组 `Object[]`，元素类型是泛型 `E`，长度按构造方法传进来的 `capacity` 在构造时创建。创建 `Object` 数组需要一次必要的类型转换，顺便把警告也去掉；
- 一个指针 `top`，它代表栈顶的位置。

思路是这样的：假设容量是 4，有效索引就是 0、1、2、3。**我们把数组的左边视为栈底，右边视为栈顶**——越靠右，越靠近栈顶。

```text
索引:  0    1    2    3
       +----+----+----+----+
       | a  | b  | c  | d  |
       +----+----+----+----+
       栈底            栈顶

top = 4   ← 已经走到数组末尾之外，此时 top == stack.length，栈满了
```

这个方向和链表版正好是倒过来的。为什么这么设计？因为数组往右边操作性能更高——往数组尾部添加元素、删除元素，性能都更好。既然顶部固定在右边，那把右边留作顶部就顺理成章了。

> **注意**：这是数组版栈最容易搞错的地方，一定要记住——`top` 加一之后，指向的是栈顶元素的**后一个位置**，不是栈顶元素本身。所以真正的栈顶是 `stack[top - 1]`。

#### 空和满的判据

`top` 一开始在 0，等于 0 就是空。`top` 不断自增，加满了以后它的值会等于数组长度，所以 `top == stack.length` 就是满。

对比一下两种实现的判据，还是挺有意思的：

| 判据 | 链表实现 | 数组实现 |
| --- | --- | --- |
| 空 | `size == 0` | `top == 0` |
| 满 | `size == capacity` | `top == stack.length` |

#### push：用后置自增合并两行

`push` 的逻辑我们都写过好几遍了：先判满，满了 `return false`；没满就往栈顶这个索引位置塞进新元素，然后 `top` 往前走一步，最后 `return true`。

这里可以合并成一行：`stack[top++] = value`。

```java
public boolean push(E value) {
    if (isFull()) {
        return false;
    }
    stack[top++] = value;      // 后置 ++：先按 top 找到位置赋值，再自增
    return true;
}
```

为什么可以这么写？因为**后置 `++` 是先做求索引的运算，然后再加一**。它先拿 `top` 原来的值（比如 0）找到数组里那个位置，给它赋好值，然后 `top` 自己才加一。比数组实现简单多了。

#### pop：栈顶是 `top - 1`，不是 `top`

`pop` 要找到栈顶元素并移除。先判空，空了返回 `null`。不空的话，怎么找栈顶？

有人会想，我直接写 `array[top]` 行不行？**注意，不行**。因为每次添加完元素以后 `top` 都加加了，加加之后它指向的位置**不是**栈顶元素，而是栈顶元素后一个位置。所以要 `top` 减一才是栈顶元素。

```java
public E pop() {
    if (isEmpty()) {
        return null;                   // 空栈，没什么可移除的
    }
    return stack[--top];        // 前置 --：先自减，再按自减后的结果取索引
}
```

还有一件事：要不要把这个元素真正"删掉"？有同学说把 `b` 清零就行。**不用，不用**。我们只要让 `top` 指针减一就够了。减一以后，以后还会读到 `b` 吗？不会了。以后你再读栈顶元素，读到的是这次自减之后的结果，也就是 `a` 了。`b` 就相当于被跳过去了。不用真的把 `b` 清掉，只是让我们读不到这个被删掉的值而已。

还有个细节要小心：这里用的是**前置**自减 `--top`，不能写成后置。因为我们得先让 `top` 减一，减完之后这个结果才是栈顶元素的位置，然后才能按它去取值。前置自减正好满足这个顺序要求——先做自减，再根据自减后的结果当索引去找栈顶元素。

#### peek：去掉自减，两行又并成一行

`peek` 和 `pop` 差不多，拿栈顶元素的值但不删除。既然不删除，那就没有 `--top` 这一说了。把 `pop` 的代码复制一份，去掉减减，减减去掉之后这两行又能合成一行。

```java
public E peek() {
    if (isEmpty()) {
        return null;
    }
    return stack[top - 1];
}
```

三种写法放一起对比一下，这个后置 `++`、前置 `--` 的区别就再也不会搞混了：

| 场景 | 写法 | 原因 |
| --- | --- | --- |
| `push` | `stack[top++] = value` | 后置 `++`：先按旧的 `top` 定位，再自增 |
| `pop` | `return stack[--top]` | 前置 `--`：先自减拿到栈顶位置，再取值 |
| `peek` | `return stack[top - 1]` | 不改 `top`，只能老老实实减一 |

#### iterator：从右往左走

数组版的迭代器要注意方向。链表版是从栈顶开始遍历，栈顶在链表最前面；而数组版的栈顶在**右边**，所以得把数组从后往前倒着遍历。

指针 `p` 的初始值给 `top`。什么时候算遍历到头了？`p` 每次遍历都要减一，减到 0 就表示没有元素了，所以条件是 `p > 0`。

跟前面一样，`p` 刚开始是 `top`，它减一才是栈顶，所以取的值是 `array[p - 1]`。而且因为 `p` 自己每次也要减一，这两行同样可以合成一行：直接 `--p` 就行，后面那个减一不要了。

```java
public Iterator<E> iterator() {
    return new Iterator<E>() {
        private int p = top;            // 初始给 top，从右往左遍历

        @Override
        public boolean hasNext() {
            return p > 0;               // 减到 0，说明没有元素了
        }

        @Override
        @SuppressWarnings("unchecked")
        public E next() {
            return (E) stack[--p];      // 先自减拿到栈顶位置，再取值
        }
    };
}
```

测试用例不用新写，把链表版那套改一改就行：把 `LinkedListStack` 改成 `ArrayStack`，`pop` 改成 `peek` 之类，跑一遍看结果就行。数组版的实现到此就完成了。

### 有效的括号：把期望的右括号先压进栈

下面看一道跟栈直接相关的练习题——力扣上的《有效的括号》。

题目是这样的：给定一个字符串，字符串里只可能包含三种括号，分别是小括号 `()`、大括号 `{}`、中括号 `[]`，让你判断这个字符串中的括号是否有效。

什么叫有效？题目给了几个例子。第一个例子，小括号的左边先出现、右边后出现，成对，所以有效。第二个例子，小括号、中括号、大括号各出现一对，也有效。第三个例子就无效了——小括号只出现了左边，中括号只出现了右边。

不过我觉得题目这几个例子举得不够全面，我们再看几个无效的：先是右小括号、后是左小括号，这种无效；括号成对了但**嵌套方式不对**也无效；个数不对（比如小括号少了右边）无效；只输出了半个括号当然也无效。

> **提示**：嵌套关系这条最容易漏。像 `([)]` 这样——小括号确实成了一对，中括号也确实成了一对，但你要么让小括号把中括号整个包起来，要么让中括号把小括号整个包起来，不能像这样交叉着裹。所以"括号都成对"不等于"有效"。

#### 解题思路

我们**从左向右**扫这个字符串，每看到一个字符就做判断。

碰到**左括号**怎么办？跟它配对的是哪个右括号，我先把那个"期望的右括号"存起来——放进栈里。因为我预期将来会来一个右小括号把它配掉，那就先把这份期望压在栈里。

看具体过程。第一个字符是左小括号 `(`，跟它配对的是右小括号 `)`，所以把 `)` 压进栈。第二个字符还是左括号，是个左中括号 `[`，跟它配对的是右中括号 `]`，所以把 `]` 压进栈。注意，**每次操作的都是栈顶**。以此类推，这就是碰到左括号时的逻辑。

碰到**右括号**呢？拿它跟栈顶元素比较。**相等**，说明这对括号有效；**不相等**，说明无效。

接着上面的例子：第三个字符是右小括号 `)`,拿它跟当前栈顶元素比一下——现在的栈顶是 `]`……那如果这里来的是右小括号，它跟栈顶的 `]` 就不等，那就不是有效括号了。而如果来的是右中括号 `]` 跟栈顶的 `]` 相等，说明它跟前面那个左中括号成了一对。

对上了之后该做什么？既然这一对括号已经有效了，栈顶这个"期望的右括号"就没用了，直接把它弹出来。弹出来是为了让栈里下一个元素继续跟右边这个字符匹配。

比如第四个字符是右小括号，拿它跟新的栈顶比：如果相等，说明它跟更前面那个左括号成了一对。

> **结论**：遇左括号就把"配对的右括号"压栈；遇右括号就跟栈顶比，相等就弹出、不等就立即判定无效。

#### 代码实现

栈就用我们自己写的那个数组版，元素类型用 `Character`（字符的包装类）。栈的大小就选字符串的长度——虽然最多肯定也放不了这么多，但如果都是成对出现的，它最多放的就是这个字符串的一半。

然后从左向右遍历，用 `for` 循环从 0 到字符串长度减一，每轮取出当前字符，简称为 `c`。按照刚才的逻辑分支：如果是左小括号，就把配对的右小括号 `push` 进栈；左中括号、右中括号类似；左大括号就把右大括号 `push` 进去。

前三个条件都不成立，说明这个字符肯定是右括号了。这时候先做一个判断：**判断栈是不是非空**。非空的话，取出当前字符 `c`，通过 `stack.peek()` 拿到栈顶元素，判断它俩是不是相等。相等说明成对了，把栈顶元素 `pop` 弹出，比较下一组；不相等直接 `return false`，也不用继续循环了。

循环结束之后怎么判断所有括号是不是都配上了？看栈：栈空了，说明所有括号都配上对了；不是空的，说明还有没配上的。

道理就在这儿——每成功匹配一对，栈顶就被弹掉一个。如果全程都能配得上，循环结束时栈肯定被弹空了。反过来，如果栈里还剩了一个，说明这边还有一个括号没有找到与之配对的，比如最开始那个左小括号，一直没等到它的右小括号。

所以最后返回 `stack.isEmpty()` 就行：栈空返回 `true`（全部有效），非空返回 `false`（还有没对上的）。

```java
public boolean isValid(String s) {
    Stack<Character> stack = new ArrayStack<>(s.length());

    for (int i = 0; i < s.length(); i++) {
        char c = s.charAt(i);

        if (c == '(') {
            stack.push(')');            // 把"期望的右括号"压进去
        } else if (c == '[') {
            stack.push(']');
        } else if (c == '{') {
            stack.push('}');
        } else {
            // 前三个条件都不成立，必定是右括号
            if (!stack.isEmpty() && c == stack.peek()) {
                stack.pop();            // 成对了，弹掉，继续匹配下一组
            } else {
                return false;
            }
        }
    }

    return stack.isEmpty();             // 栈空了说明全部配上对了
}
```

#### 跑测试用例时炸出来的空指针

测试用例我准备了一堆，前几个是有效括号，后几个是无效括号。有效的那几个跑一下，都返回了 `true`，没问题。无效的分开来测。

前几个无效例子在循环中间就被拦下来了。第一个：遇到左括号先压进去一个右括号，遍历到第二个字符的时候，发现这俩右括号不等，说明它跟栈顶元素不匹配，直接就 `return false` 了。下一个例子是往栈里放了两个对应的右括号，配对的时候发现第三个字符跟栈顶的那个对不上，同样在循环中间就返回了 `false`。

还有一个例子稍微绕一点：先压了一个右括号，又压了一个右括号，接下来跟栈顶能对上，就把它弹出了；然后因为没有更多字符了，循环结束了。这时候栈不是空的，还剩一个没配上对的括号，所以返回 `false`。最后那个跟它类似，也是循环结束后发现栈不空，返回 `false`。

跑完这四个都返回了 `false`，没问题。

好，还有两个测试用例，打开注释跑一下——**报错了**，一个空指针异常。

为什么会出现这个异常？我们来分析一下。这最后两个测试用例跟前面那几个不同的地方在于：**它的第一个字符是一个右括号**。前面那些测试用例的第一个字符都是左括号，所以一直没踩到坑。

为什么右括号开头就会报错呢？分享它的执行过程：假设第一个字符是右括号，走那几个 `if` 的时候，前面判断的全是"是不是左括号"，条件都不成立，所以直接来到了 `else`。没问题吧？但进入 `else` 这块的时候，**栈还是空的**！既然栈是空的，`peek()` 返回的就是个 `null`。这个 `null` 又要跟前面一个基本类型的 `char` 做比较——Java 会尝试把 `null` 转成基本类型的 `char`，转换不了，就抛空指针异常了。

所以我们在这儿应该多加一个判断：**只有当栈不为空的时候，才能做后续的 `peek` 操作**。不为空，取出来的才不是 `null`，才能做比较。

```java
} else {
    if (!stack.isEmpty() && c == stack.peek()) {
        stack.pop();
    } else {
        return false;              // 栈是空的，第一个字符就是右括号，必定无效
    }
}
```

改动完再测，最后两个也过了。这两种都是无效括号。

而且从道理上讲，第一个字符就是右括号，它必定是无效的，所以直接在这里返回 `false` 就行。

> **结论**：代码不是一次就能写正确的。你得设计不同的测试用例，才能反映出代码里可能存在的问题。这次的坑就是"没考虑第一个字符是右括号的情况"——而这个坑，恰恰只有当测试用例的**开头**变了才暴露得出来。

## 二叉树深度优先遍历：前序、中序、后序的规则与两种实现
> 对应块：BLK38 | 覆盖分集：P147-P150 | 块标题（分集名）：《基础数据结构-102-二叉树-深度优先遍历》

### 三种遍历，一个共同点

二叉树的深度优先遍历还可以进一步分成三种，分别是 preorder 前序遍历、inorder 中序遍历和 postorder 后序遍历。

这三种遍历方式有各自的一些规则，但除了规则不同之外，它们还有一个共同特点：**在遍历的过程中都要深入到叶子节点**，也就是深入到离根节点更远的那些叶子节点。

规则不同，走法不同，可它们最终都要扎到最深的地方去把叶子看一遍——记住这个共同点，后面理解非递归写法的时候特别有用。

### 先把例子摆好：一棵用数组表示的树

我们拿一棵很小的树当例子，因为它刚好能撑起前中后序三种顺序，又不至于让人看晕。

这棵树是用一个数组来表示的，改完数组点一下保存，动画就会按新的数据把这棵树重新画出来。

```text
        1
       / \
      2   3
     /   / \
    4   5   6
```

对着这棵树：

- 节点 `1` 的两个孩子是 `2` 和 `3`；
- 节点 `2` 的两个孩子是 `4` 和 null；
- 节点 `3` 的两个孩子是 `5` 和 `6`。

这里的 **null 表示没有孩子**。比如节点 `2` 的右孩子我不想让他有，那就给个 null 值表示没有孩子。如果你还想改别的，比如把节点 `3` 的左孩子 `5` 换成 null，改完保存，`3` 的左孩子就没了；反过来，也可以给节点 `4` 新加两个孩子，中间的值用逗号分隔就可以了，顺着往后加。

图里每个节点有两种颜色，一种现在看到的灰色，表示这个节点在遍历的时候还没有被访问过；如果是绿色的，就表示这个节点已经被访问过了。后面我们演示前中后序的规则，就靠这两种颜色来看它到底是走到了、还是走到了但还没打印。

### 前序遍历：根、左子树、右子树

前序遍历的规则是：**你访问每个节点时，都是先访问这个节点的值，然后访问这个节点的左子树，最后访问这个节点的右子树。**

什么叫左右子树？其实就是它左边的所有后代和右边的所有后代。拿节点 `1` 来讲，它的左子树是 `2` 和 `4`——因为它们是整棵树的一部分，所以我们把它称之为子树；`1` 的右子树就是 `3`、`5`、`6` 这几个。那如果拿节点 `2` 来讲，它的左子树就是 `4`，右子树没有，是空。

那对于上面这棵树，前序遍历最终的结果就是：

```text
1 2 4 3 5 6
```

这个 `1 2 4 3 5 6` 说的是值的顺序，也就是访问到一个节点就把它的值打印出来，最后打印出来的这个顺序。

为什么是这样的顺序？我们一步一步走一遍：

一开始还是从根节点开始——对于一棵树来讲根节点是一致的，其他节点都是在遍历的过程中逐渐访问到的。先访问根节点的值，把 `1` 打印出来。接下来访问哪个节点？看规则，要访问根节点的左子树，也就是 `2`。

进入 `2` 这个节点，它同样按照刚才的规则走：先打印 `2`，再访问 `2` 的左子树 `4`。`4` 这边也是打印它的值，而 `4` 的左右子树都没有了，所以它的左子树算是访问完了，右子树也算是访问完了。

到这里打印的顺序是 `1 2 4`。

注意接下来我们要往回走了。`4` 完了，相当于 `2` 的左子树完成了；`2` 的右子树是 null，所以也算完成了。至此 `2` 和 `4` 作为 `1` 的左子树就完成了，`1` 的左半边 OK，接下来改走 `1` 的右半边。

访问 `1` 的右子树 `3`，先打印 `3` 的值；然后访问 `3` 的左子树 `5`，`5` 没有左右子树，整个 `5` 就算完成了；再访问 `3` 的右子树 `6`，`6` 的左右子树也完成了。

这样对于 `1` 来讲，它的右子树 `3 5 6` 都完成了，最后 `1` 也完整结束了。所以整个前序遍历打印出来的值顺序就是 `1 2 4 3 5 6`。

### 中序遍历：左子树、根、右子树

中序遍历的规则是：**在访问每个节点时，先访问这个节点的左子树，然后访问这个节点的值，最后访问这个节点的右子树。**

同样是这棵树，中序遍历打印出来的值顺序应该是：

```text
4 2 1 5 3 6
```

注意这里的差别——中序遍历虽然一开始拿到的也是根节点，但它**不能直接打印根节点的值**。因为规则是先访问完根节点的左子树，才能打印根节点的值，所以它别着急打印，得先去找根节点的左子树 `2`。

那拿到 `2` 以后，是不是可以直接打印呢？也不是。你得先访问 `2` 的左子树，也就是 `4`。那 `4` 能直接打印值吧？类似的，也不能，你得访问 `4` 的左子树——当然 `4` 没有左子树，那它这个就算是左子树完成了。它的左子树完了，就可以打印节点 `4` 的值了；完了之后是它的右子树，`4` 也没有右子树，右子树也算完成。

至此 `4` 完成了，意味着上一个节点 `2` 的左子树遍历完成，那就可以打印 `2` 的值了，顺序是 `4 2`。`2` 没有右子树，所以 `2` 这个节点整个算 OK 了，它作为 `1` 的左子树完成了。

`1` 的左子树完成之后，就可以打印 `1` 的值了，现在顺序是 `4 2 1`。

接下来访问 `1` 的右子树。这里我考大家一下：`1` 的右子树这边应该先打印谁？是先打印这个 `3` 呢，还是先打印 `5` 啊？

> **提示**：先打印 `5`。虽然他是先进入了 `3` 这个节点，但是 `3` 的左子树没有完成之前，是不能打印 `3` 的值的；因此他得先找到 `3` 的左子树。

`3` 的左子树里面同样是先走 `5`，而 `5` 的左子树是 null，所以直接就算遍历完成，然后 `5` 的左子树 OK 了，就打印 `5` 的值，然后是 `5` 的右子树。`5` 完成后，`3` 的左子树才算完成——所以是先 `5`，然后才回到 `3`。

`3` 的左子树 OK 了，那就可以打印 `3` 的值。接下来访问 `3` 的右子树，这边比较简单，也是左、值、右这样一个顺序把它遍历完成。整个 `3 5 6` 作为 `1` 的右子树遍历完成，中序遍历也就完整结束了。

### 后序遍历：左子树、右子树、根

后序遍历的规则是：**先访问左子树，然后访问这个节点的右子树，最后才是访问这个节点的值。**

还是从根节点开始，但进入根节点之后能直接打印值吗？不行。他得先访问完它的左右子树，最后才能打印他的值。所以先找根节点的左子树 `2`。

进入 `2` 这个节点，`2` 的左右子树没有访问完之前，也是不能打印 `2` 这个值的。所以在进入 `2` 的左子树 `4`；`4` 这边它没有左右子树，可以访问完成，打印 `4` 这个节点的值。所以最先打印出来的是 `4`。

`4` 完成了，它作为 `2` 的左子树就 OK 了；`2` 的右子树没东西；`2` 的左右子树都完成之后，最后打印 `2` 这个节点的值。那 `2` 和 `4` 完成了，相当于 `1` 这边的左子树完成了。这时候能马上打印 `1` 吗？

不能。我们得访问 `1` 的右子树，因为它是左、右、值这样一个顺序。

接下来访问 `1` 的右子树，这边跟前面很类似：先进入 `3`，但 `3` 能直接打印吗？还不行，他得先把 `3` 的左右子树都访问完成了，才能打印 `3`。接下来进入 `3` 的左子树 `5`，`5` 没有左右子树，就 OK 了，打印完左右之后打印值，也就是打印 `5`。`3` 的左子树 OK，接下来 `3` 的右子树，右边也是左、值、右这样一个顺序，把 `6` 打印出来。

这就相当于 `3` 的右子树完成了。`3` 的左右子树都完成了，是不是就可以打印 `3` 了？打印 `3`。然后 `3 5 6` 作为 `1` 的右子树都遍历完成，`1` 的左右子树才完成，最后打印的是 `1` 的值。

所以整个后序遍历的顺序是：

```text
4 2 5 6 3 1
```

### 三条规则并排对照

到这里我们把这三种遍历做一个简单的比较。

| 遍历方式 | 访问每个节点时的顺序 | 这棵树跑出来的结果 |
| :--- | :--- | :--- |
| 前序 preorder | 节点值 → 左子树 → 右子树 | 1 2 4 3 5 6 |
| 中序 inorder | 左子树 → 节点值 → 右子树 | 4 2 1 5 3 6 |
| 后序 postorder | 左子树 → 右子树 → 节点值 | 4 2 5 6 3 1 |

> **结论**：这三条一定要把它作为重点，要记住——给你一棵树，应该在自己的脑海里就能知道它的前序遍历是什么样的顺序，中序遍历是什么样的顺序，后序遍历是什么样的顺序。总之要把它熟练掌握。

### 递归实现：一个方法就够了

这三种遍历其实都有两种做法，一种是用递归方式求解，一种是用非递归方式求解，我们都要分别讲一讲。先看递归，递归的比较简单。

**递归为什么简单？** 因为我们这个例子中，每个节点它的遍历规则是一样的。以前序遍历为例，它的规则都是先值、再左子树、再右子树：`1` 节点得遵守这个规则，`3` 节点也得遵守，`5` 节点也得遵守。既然所有节点遵守的规则都一样，意味着什么？意味着将来它调用的方法是不是同一个呀——方法是同一个。那在方法的执行过程中，如果他遇到了其他节点，他只要**递归调用自身**这个方法就可以了。

所以这道题目你用递归求解，是最直接也最好理解的。

#### 把这棵树构造出来

树就用了我们之前写好的那个节点类里面的三个属性：一个是 `value` 值，还有左孩子，还有右孩子。构造方法里，它会把左右孩子作为参数，值也会作为中间的一个参数。

我们就构造一个跟刚才这个例题一模一样的树：

```java
// 构造方法：第一个参数左孩子，第二个参数值，第三个参数右孩子
Node(int value) {
    this.value = value;
}

Node(Node left, int value, Node right) {
    this.left = left;
    this.value = value;
    this.right = right;
}
```

4、5、6 没有左右孩子了，那就调了它一个参数的构造，这时候相当于它的左右孩子都没有赋值。整棵树这么写出来就是：

```java
Node root = new Node(
        new Node(new Node(4), 2, null),          // 2：左孩子 4，右孩子 null
        1,
        new Node(new Node(5), 3, new Node(6))    // 3：左孩子 5，右孩子 6
);
```

#### 前序遍历：打印放在最前面

方法我们拿到了，参数就是传过来一个节点。拿到节点以后，就把刚才的规则转换成代码呗。

```java
void preorder(Node node) {
    // 递归操作得有一个结束条件
    if (node == null) {
        return;
    }

    // 先访问节点的值
    System.out.print(node.value + " ");

    // 再访问左子树
    preorder(node.left);

    // 最后访问右子树
    preorder(node.right);
}
```

几个地方要拆开看：

- 我不想把它换行，就不用 `println` 了。为了待会跟其他的值有所分隔，我加一个空格（加个缩进也一样）；
- 访问左子树的时候，我问 `2` 这个节点：你访问的规则跟刚才 `1` 节点一不一样？一样的，所以调用的方法仍然是我们这个 `preorder` 方法，只不过这回传过去的节点变成了当前节点的左孩子 `node.left`；
- 右子树也是以相同的 `preorder` 逻辑去处理，只不过处理的节点是当前节点的右子树。

> **易错点**：别忘了我们这个递归操作得有一个结束条件。比如我的右孩子传过去就是 null 了，那下次递归的时候如果发现是 null，是不是应该结束递归？所以我们判断一下，如果传过来的节点已经是 null 了，就可以结束递归，直接 `return`。

这样前序遍历代码就写完了，是不是很简洁——先值、再左子树、再右子树，左右子树就是对应着两次递归调用。

测试一下，把根节点作为第一个参数传进去：

```text
1 2 4 3 5 6
```

跟我们刚才的分析结果一样，前序遍历代码就写完了。

#### 中序遍历：打印放在中间

中序遍历的规则是左、值、右。

```java
void inorder(Node node) {
    if (node == null) {
        return;
    }

    // 先访问左子树：别着急打印当前节点的值
    inorder(node.left);

    // 左子树访问完了，再打印当前节点的值
    System.out.print(node.value + " ");

    // 最后以相同的逻辑访问右子树
    inorder(node.right);
}
```

拿到一个节点，先别急着打印它的值，你先调用一个相同的 `inorder` 逻辑去访问当前节点的左子树；等左子树访问完了，回过头来再去打印当前节点的值；当前节点值完成了，最后再以相同的 `inorder` 逻辑去处理当前节点的右子树。同样别忘了递归的终止条件，如果当前节点已经是 null 了，那没必要继续递归，返回就可以了。

跑一下：

```text
4 2 1 5 3 6
```

跟我们刚才的分析结果也是一样的。你会发现，前序遍历、中序遍历、后序遍历，只是把这个顺序稍微调整一下就 OK 了。

#### 后序遍历：打印放在最后面

后序遍历太容易了，我们就把刚才的代码直接拷过来稍微改改：后序遍历是先左子树、再右子树，最后再访问节点值。

```java
void postorder(Node node) {
    if (node == null) {
        return;
    }

    postorder(node.left);
    postorder(node.right);

    // 左右子树都完成了，最后处理这个值
    System.out.print(node.value + " ");
}
```

测试一下：

```text
4 2 5 6 3 1
```

至此为止，我们用递归方法实现的二叉树的前中后序遍历就讲完了。

### 非递归的突破口：三条路其实是同一条

前面是用递归来实现的。这节课我们要采用非递归的方式，实现相同的遍历效果，非递归的代码要比递归难很多。那咱们先不着急去写代码，先来找一找这三种遍历它们的一个**共同规律**。

有同学会说这三种遍历好像没啥规律啊，它们打印值的顺序也不一样：前序是 `1 2 4 3 5 6`，中序是 `4 2 1 5 3 6`，后序是 `4 2 5 6 3 1`，打印值的顺序没啥规律。

虽然他们打印值的顺序是有先有后，**但是他走的路径其实是一样的**。我们这三种遍历在树的节点中走的路径都是一样的。

```text
都得从根节点出发，先走左边：
   1 → 2 → 4 →（4 左边没路了）→ 回 2 →（2 右边没路）→ 回 1
左边这棵子树走完了，再走右边：
   1 → 3 → 5 →（5 左边没路了）→ 回 3 → 3 → 6 →（6 左边没路了）→ 回 3
最后从 3 回 1，这就算走完一圈了
```

所以大家来看，虽然他们将来打印值的顺序不一样，但是我在遍历整棵树的过程中，他走的路径是一样的。我们就从这一点出发去看一下我们如何使用非递归的方式来实现这三种遍历：不考虑它的值的顺序，让它按照这三种的顺序、三种的规则打印不就行了吗，反正路径都一样。

#### 第一版代码：沿着左边一路向下

那我们先不着急去按照什么前序中序后序这些顺序打印我们的节点值，我们先想办法写段代码，这段代码就是让我们能够沿着这个树的这些节点走上这么一圈。

因为在走的这个过程中，当前的节点我们得有一个指针，比如说就叫 `current`，它的初始值应该是根节点，反正是从根开始。然后让它不断向前走，`current` 会不断变化，它代表的是当前节点。

我们刚开始能想到的就是：让他沿着左边这条路向前走。所以我们写一个 `while` 循环，如果这个 `current` 不为空，那就向前走：

```java
Node current = root;
while (current != null) {
    System.out.print(current.value + " ");
    current = current.left;   // 沿着左边一路向前
}
```

来先看一下它的效果：

```text
1 2 4
```

好像这个树没走完对吧。不着急，我们先来看一下它当前工作的顺序：刚开始是根节点，所以它打印出来了 `1`；接下来 `current` 被更新成了它的左孩子 `2`，所以第二轮循环它打印出了 `2`；这次循环结束的时候又把 `current` 更新成 `2` 的左孩子也就是 `4`，所以第三轮循环它就打印了 `4`。因为 `4` 没有左孩子了，`current` 被更新成了 null，第四次循环的时候发现这个条件不成立就退出了。所以他只走了 `1 2 4` 这三个节点。

那问题来了：我们怎么让它把这个树走全了呢？

#### 节点不认得回家的路，得上栈

这里有一个很关键的步骤：**我得沿着 `4` 向回走了**。因为我们来的时候是 `1 2 4`，向回走你才能找到它后续的右边这些东西，对不对？

那向回走就有一个新的问题了：我们得让他**记住来时的路**。因为我们这个节点类现在是这样设计的——每个节点只有自己的左右孩子，他不知道自己的父亲是谁。比如说我们已经循环到 `4` 了，那你要向回走是不是得知道 `2` 呀？但是 `4` 它并没有一个属性说它的父节点是谁，因此呢他找不到他父亲，也就是找不到他来时的路。

那怎么办呢？用哪种数据结构来记录来时的路啊——用栈比较合适。

我们去的时候，每经过一个节点，我就把这个节点记录到栈里：先经过的是 `1`，那我在循环结束前把 `1` 存入到栈里，然后继续向左走；走到 `2` 了，那我把 `2` 将来也要记录到这里；走到 `4` 了，最后把 `4` 也记录到这里。那什么时候 `4` 它的左边路不通了？没有左孩子了，说明走到头了，是不是该回走了？向回走的时候，大家看来的时候 `1 2 4` 这个顺序，回的时候这个每个元素弹出来就可以了——这样就记录了他回来时的路。现在应该从 `4` 向后返回，然后呢下一个返回的是 `2`，最后返回到 `1`，没问题吧。

> **提示**：这里的栈大家用我们自定义的也行，或者用 JDK 的也可以——你就选择 `LinkedList`，它也可以作为栈，调用它的 `push` 方法或者 `pop` 方法就可以了。我们自己也写过一个叫 `LinkedListStack` 的、基于链表的栈实现，实现了 `push` 和 `pop` 方法，两个实现选一个就可以。

#### 区分"去"和"回"

那我们每次循环的时候，除了打印这个值以外，我就把当前这个节点给它加到刚才的 `stack` 这个栈里，来把他压入栈。压入栈其实就是为了记住回来的路。

那现在又有新的问题了：我们把这些数据记下来了，那什么时候我们弹栈呢？是不是刚才我说了，当这个 `current` 是 null 的时候，也就是左边这条路走到头了，说明该往回走了。所以这个条件呢我们应该把它区分开：

- 如果 `current` 不等于 null，这表示左边的路还没走完，没走完我们就要走刚才这个"去"的逻辑；
- 如果是 else，就说明我这个 `current` 已经等于 null 了，左边这条路走到头了，走到头该回了。那我这个时候就去弹栈，把栈顶的元素弹出来，打印它，也就是 `pop.value`。

这就把关的代码和回的代码区分开了。

> **易错点**：不过这样呢它又有新的问题。你看我们这个 `while` 循环，它总是在判断 `current != null`，如果 `current == null` 它走到头了，是不是它这个外层的 `while` 循环都不会进入了？那怎么办呢？

所以我们这个外层的循环也得稍微改一下，再给它加一个条件：**如果栈里面有元素，是不是表示它记录了来时的路，这个时候你应该退出循环吗？不应该**，说明他还没往回走呢。因此呢我们这个 `while` 循环的条件是，当我们的 `current` 不等于 null，**还要有一个条件就是当这个 `stack` 不为空**——`stack` 里有东西，说明他还没来得及往回走，这时候你不应该结束循环，对不对啊。所以我们加上一个 `stack` 不为空的条件，这两个条件同时满足，那么它就可以进入我们这个循环了。

#### 回完之后，拐向右子树

走一遍：去的时候 `1 2 4`，左边这条路走完了，我们继续来看右边。

那你看我们怎么拿到右边这个起点呢？很简单，你看我们回的最后这个节点，是不是就是一个 `1` 节点？那一节点也就是我们这里的 `pop` 变量，它 `.right` 是不是就拿到这个 `3` 了？拿到 `3` 了，这就是他右边路的起点。那我们可以把这个 `pop.right` 赋值给 `current`，赋值给 `current` 呢，是不是 `current` 就不等于 null 了，那下次循环的时候，他是不是就可以沿着右边路的起点也就是 `3` 继续向前走啊。

把整套代码连起来，就是这样：

```java
void dfs(Node root) {
    LinkedList<Node> stack = new LinkedList<>();
    Node current = root;

    while (current != null || !stack.isEmpty()) {
        if (current != null) {
            // 去
            System.out.print(current.value + " ");
            stack.push(current);
            current = current.left;
        } else {
            // 回
            Node node = stack.pop();
            System.out.print(node.value + " ");
            current = node.right;
        }
    }
}
```

运行出来的完整结果是这样的：

```text
current = 1     去：打印 1，1 压栈，current = 1.left       栈=[1]
current = 2     去：打印 2，2 压栈，current = 2.left       栈=[1,2]
current = 4     去：打印 4，4 压栈，current = null         栈=[1,2,4]
current = null  回：弹出 4，打印 4，current = 4.right      栈=[1,2]
current = null  回：弹出 2，打印 2，current = 2.right      栈=[1]
current = null  回：弹出 1，打印 1，current = 1.right = 3  栈=[]
current = 3     去：打印 3，3 压栈，current = 3.left       栈=[3]
current = 5     去：打印 5，5 压栈，current = null         栈=[3,5]
current = null  回：弹出 5，打印 5，current = 5.right      栈=[3]
current = null  回：弹出 3，打印 3，current = 3.right = 6  栈=[]
current = 6     去：打印 6，6 压栈，current = null         栈=[6]
current = null  回：弹出 6，打印 6，current = 6.right      栈=[]
current = null  回到 3 再回到 1 没走成：此时 current 是 null，栈也空了
               两个条件都不成立，退出循环
```

最后这个 `6 → 3 → 1` 为什么没走？因为这时候 `current` 是 null 而栈呢在 `6` 弹出以后也变空了，所以这两个条件相当于都不成立了，就退出循环了。不过呢也无所谓了，最后从 `6` 回 `3`、从 `3` 回 `1`，这个已经不太重要了。

所以我们看到，刚才这段代码就能够实现绕树一圈：**`1 2 4 4 2 1 3 5 3 6`**。这一段代码大家把它重点理解，理解之后呢，待会我们来看一下它能同时解决两个问题——前序遍历和中序遍历。

### 同一段代码，两种遍历

有同学会说，你这段代码写好了就能同时处理两种遍历啊，前序中序——是的啊。不过现在这个打印效果可能不太清楚，因为颜色都是一样的。那我用一个在控制台上输出彩色的这么一个方法，大家可以调用它。我们把刚才的 `print` 换成这个方法，它需要一个参数，参数就是决定打印的颜色，`31` 是红色，然后 `34` 是蓝色。

```java
void printColor(Object o, int color) {
    System.out.print("\033[" + color + "m" + o + " ");
}
```

现在"去"用红色表示，"回"的时候用蓝色表示，我们来看一下效果。

#### 打印放在"去"上：前序

前序遍历的规则是值、左、右，所以它处理到当前节点了，它就可以立马去打印它的节点值了。红色区打印顺序是：

```text
1 2 4 3 5 6
```

是不是前序遍历 `1 2 4 3 5 6`？是的吧。

#### 打印放在"回"上：中序

中序遍历的规则是左、值、右。肯定不能是在去的时候就打印值吧？去的时候你打印了值，那就不符合左、值、右的顺序了。你得把所有的左子树都处理完了，再打印值。因此呢这个打印的代码，我们把它放在回来的时候再打印，就顺理成章了——因为回来的时候意味着它的左子树都完成了呀，完成了，那不就是左、值，然后再处理一个右吗。

蓝色区打印顺序是：

```text
4 2 1 5 3 6
```

没错，就是中序遍历。

> **结论**：所以我们这个代码它可以处理我们的前序，也可以处理中序。当然了，你可以稍微改一下：把这个"回"注释掉，那这段代码你拿过去就是一个前序遍历的代码；那你把"回"这块注释取消、把"去"这个代码注释掉，那这段代码你拿过去就是中序遍历的代码。

#### 前序的执行流程

当前节点从根节点开始。前序的规则是值、左、右，所以它处理到当前节点了，就可以立马打印它的节点值——对应着那句 `print`。只打印完了之后呢，我们需要把它压入到栈里，把当前节点压入栈，这是为了将来记住回来的路。

按照值、左、右这个顺序，接下来要处理它的左孩子，所以找到我们当前节点的左孩子，将来把左孩子作为下一轮循环的当前节点，也就是我们看到的这个 `2`。`2` 这个节点的处理规则都是一样的，也是值、左、右：先打印值，绿色已经把它值打印了；打印完了，把当前节点 `2` 压入到栈，然后继续处理他的左孩子，也就是 `4`。当前节点变成了 `4`，也是打印它的值，并且把 `4` 压入到栈。

再处理 `4` 的左孩子的过程中，发现它的左孩子已经是 null 了，也就是这条路走到头了，左边这条路走到头了。所以他这回循环的时候这个 `if` 条件是不成立的，就会进入 `else`，进入 `else` 就意味着该往回走了。

在往回走的过程中，他其实就是要做**弹栈和处理右孩子**。接下来往回走，他就会把 `4` 从栈顶给它弹走。弹走之后呢，要检查一下他有没有右孩子——当然现在这个右孩子是 null，是 null 的话那他就继续向上走、继续往回走就可以了；如果有右孩子的话，他会把右孩子作为当前节点，按照类似的规则来处理好。我们这里 `4` 没有右孩子，那它就直接向回走，继续弹栈，把那个 `2` 弹走。弹走之后看一下 `2` 有没有右孩子，当然也没有，那就继续往回走。

把 `1` 弹走以后，`1` 又有右孩子了，所以呢把 `1` 的右孩子作为 `current` 节点，`current` 再次进入循环，也就是准备处理这个 `3`。`3` 同样还是按照值、左、右顺序，先打印 `3` 的值并且把 `3` 入栈，入了以后按值、左、右处理它的左孩子，也就是 `5`。当前节点变成了 `5`，同样打印 `5` 的值，然后按值、左、右处理它的左孩子——它没有左孩子，左孩子为空，那我们就可以进入 `else` 了，进入 `else` 往回走弹栈。把 `5` 弹栈之后，看一下我的右孩子需不需要处理，结果不需要处理，那就继续往回走，再把 `3` 弹栈。看一下 `3` 弹栈之后有没有右孩子要处理？当然 `3` 有右孩子，所以把 `3` 的右孩子作为 `current`，进入下一轮循环。

下一轮循环里面，把当前节点 `6` 进行值、左、右的处理好：打印它的值，然后处理左孩子、处理右孩子，它俩的左右孩子都是空，所以就处理完成了。所以整个这个顺序就是 `1 2 4 3 5 6` 这样一个顺序。

#### 中序的执行流程

中序遍历的规则是左、值、右，这个大家都很清楚了。

刚开始我们让它沿着规划好的路线，先把所有的左子树都过一遍。现在左边这条路上走到头了，这个时候大家看 `current` 是不是等于 null 了？等于 null 了，它就会进入 `else` 往回走。往回走的过程中，先弹出 `4`——弹出 `4` 我就可以打印了对吧，因为左边都走完了嘛，左、值、右，那么就可以打印 `4` 的值了。那么 `4` 这边没有右孩子，所以右孩子算是处理完成，继续弹出 `2`，弹出 `2` 之后打印 `2`。`2` 呢这边也处理它的右孩子，当然他 `2` 的右孩子也是 null，跳过去了。

接下来再弹出一、打印 `1` 的值，处理 `1` 的右孩子。那 `1` 的右孩子是 `3`，同样 `3` 这边不能立刻打印啊，他得先沿着左边这个路走到头，走到头没有左孩子了，回来的时候再打印。所以他先走到 `5` 这边，确实没有左孩子了，那当然 `3` 和 `5` 都被压入到栈了。回来的时候弹出 `5`，这时候就可以打印 `5` 的值了；好，`5` 它的右孩子处理一下，没有；继续弹出啊，这回弹出 `3`、把 `3` 的值打印，`3` 有右孩子，所以把 `3` 的右孩子这边做类似的处理就完了。

这就是我们的中序遍历。

## 二叉树遍历：后序的判断技巧、一套统一模板与两道递归应用题
> 对应块：BLK39 | 覆盖分集：P151-P154 | 块标题（分集名）：《基础数据结构-106-二叉树-前中后遍历-非递归》

前序和中序的非递归写法刚讲完，你会发现两段代码几乎一模一样：沿着左链一路压栈，走到头再回头弹栈打印，唯一的差别只是打印的那一行放在哪里。后序还是这套骨架，可它偏偏在"往回走"的那一刻多出来好几层判断。

多出来的判断到底在判断什么？这一讲就从这个差额开始。

例子还是这一棵，为了讲清楚后序，给节点 2 补上了一个右孩子：

```text
          1
        /   \
       2     3
      / \   / \
     4   7 5   6

前序（根左右）：1 2 4 7 3 5 6
中序（左根右）：4 2 7 1 5 3 6
后序（左右根）：4 7 2 5 6 3 1
```

### 后序遍历：回来的时候不能急着弹栈

后序的"去"那一段跟前序、中序一模一样，一行都不用改：`current` 沿着左孩子一路往下走，走的过程把经过的每个节点都压进栈里，走到头为止。有区别的只有回来的时候。

先看中序。从 4 回到 2，2 会被弹出，同时把 2 打印出来。这时候有同学会问：2 不是还有右孩子 7 吗？将来从 7 回来的时候，难道就用不到 2 了吗？

用不到。因为中序的规则是"左—根—右"，2 打印完，接下来就该去遍历它的右子树 7 了。等 7 那边处理完回来的时候，根本不需要经过 2——栈里此时只剩一个 1，直接从 7 跳到 1 就行了。所以中序这套代码在回来的时候是**直接把栈顶弹走**，一个节点只用一次。

后序就不一样了。后序的规则是"左—右—根"，2 必须等左子树和右子树都处理完了才能打印。现在从 4 回到 2，左子树是处理完了，但右子树 7 还没有处理完——所以这时候 2 绝对不能弹，你得给我留在栈里留着。等 7 那边走完回来，才能把 2 弹出来、打印 2。

> **结论**：不是所有情况下都需要回来时立刻弹栈。有时候得让这个节点在栈里多留一会儿，等它的右子树处理完了再弹。

### 怎么判断右子树已经处理完了

那具体怎么写？我们每次处理栈顶元素时，并不是一上来就把它弹出去，先要做一次检查：左右子树都完成了，才可以弹出。

先拿栈顶元素，用 `stack.peek()`，把它叫作 `pick`。左边不用判断——能走到 `else` 分支，就意味着左子树肯定处理完了，因为"去"的时候已经把左子树都走完了。真正要判断的是右子树。

右子树处理完了，一共两种情况。

**第一种：右子树本来就不存在。** 像节点 4，它的右孩子是 `null`。`null` 需要处理吗？不需要，`null` 就意味着右子树不用处理，等价于已经处理完了。所以 `if (pick.right == null)`，直接把它弹出、打印出来——左右子树此刻都已完成，留着它没用了。

**第二种：右子树不为空，但已经被处理完了。** 像节点 2，它的右孩子是 7。这个就要靠一个技巧了——**记录最近一次弹出的元素**。

看两个场景就明白了。四弹栈的时候，我们用一个临时变量把它记下来。现在从 4 回到 2，栈顶是 2，2 该弹吗？显然不该——刚从它的左孩子回来，右孩子那边还没走呢，2 先留着。那如果是上一次弹的是 7，从 7 往回走呢？这次就该弹了：因为 7 是 2 的右孩子，能从 7 往回走，就说明右孩子已经处理完了。

所以判断方法很直接：**看栈顶元素的 `right` 是否等于上一次弹出的那个元素**。相等，说明右子树处理完了，可以弹栈打印了。

那"最近一次弹出的元素"这个值从哪里来？`stack.pop()` 的返回值就是它。但要注意，弹栈只发生在"真正要弹"的地方，我们需要在**下一次循环**里拿它跟栈顶的 `right` 做对比，所以这个变量不能是循环内部的局部变量，必须定义在循环外面，初始值给 `null`。

于是判断条件就是一个"或者"：要么右子树是 `null`，要么右子树虽然不为 `null` 但已经处理完了（等于上次弹出的那个元素）。

```java
public List<Integer> postorderTraversal(TreeNode root) {
    List<Integer> result = new ArrayList<>();
    if (root == null) return result;
    LinkedList<TreeNode> stack = new LinkedList<>();
    TreeNode current = root;
    TreeNode pop = null;                 // 最近一次弹栈的节点，必须定义在循环外
    while (current != null || !stack.isEmpty()) {
        while (current != null) {        // 去：一路压栈，这段跟前序中序完全一样
            stack.push(current);
            current = current.left;
        }
        TreeNode pick = stack.peek();
        if (pick.right == null || pick.right == pop) {
            stack.pop();                 // 右子树无需处理 or 已处理完成
            result.add(pick.value);
            pop = pick;
        } else {
            current = pick.right;        // 右子树还没处理，让它进入下一轮
        }
    }
    return result;
}
```

注意 `else` 那一支：不是把 2 弹走，而是让 `current = pick.right`，把右子树作为当前节点送进下一轮处理。2 留在栈里等着。

完整走一遍：

```text
压栈：current 沿左链走   1 → 2 → 4        栈（底→顶）：[1, 2, 4]

peek = 4，4.right == null      → 弹栈并打印 4，pop = 4
peek = 2，2.right = 7 ≠ pop(4) → 2 留在栈里，转去处理右子树 7
peek = 7，7.right == null      → 弹栈并打印 7，pop = 7
peek = 2，2.right = 7 == pop(7) → 弹栈并打印 2
```

读图说明：每个节点要么因为"没有右孩子"被弹出，要么因为"上一次弹出的正好是我的右孩子"被弹出，两个条件缺一不可。

一路走下来打印结果是 `4 7 2 5 6 3 1`，也就是 4725631，跟后序的期望顺序对得上。

> **易错点**：`pop` 这个变量一定要定义在循环外面。放在循环内，下一次循环就取不到上一次弹出的值了，整个判断就失效。

到这里三种非递归遍历就齐了。前序和中序比较简单，是一个模式；后序只在判断条件上做了调整，但还是希望把它记住——非递归这种方式比较难考，各位多留意一些。

### 把三种非递归遍历合成一套模板

有同学就想了：能不能把这三份代码结合起来，写一个统一的模板，同时处理三种遍历？

答案当然是可以。好处很直接：将来你只需要记一套代码模板，不用记三份。

我们**基于后序的代码**来改。为什么选它？因为后序走的路是最全的，它其实是绕着所有的节点走了一圈；而前序和中序会提前把栈顶元素弹走，再回来的时候也是提前弹走，所以它们其实少走了几步路。

先把所有打印代码暂时去掉，剩下这段代码就是一份完整的"绕树一周"。然后再做一个等价的调整：原来那个 `if` 有两个条件，现在把它拆成 `if / else if / else`，把第二个条件单独拎出来做一支。代码逻辑一点没变，只是多了一行重复的代码——但正是这一拆，后面才能在两处放不同的打印。

#### 先把这段代码读懂

拆开之后每行是什么意思，一一对上：

- 内层 `while`：`current = current.left`，接下来要处理它的左子树；
- `else if` 分支里：`current = pick.right`，接下来要处理这个节点的右子树；
- 第一个 `if` 条件 `pick.right == null`：它没有右孩子，右子树无需处理；
- 第二个 `else if` 条件 `pick.right == pop`：右子树已经处理完成了（刚才讲后序时重点说过，它是从右子树那边处理完往回走的）；
- 最后的 `else`：待处理这个右子树。

#### 三种遍历各自在什么时候打印

理解了含义，就来看前中后各自该把打印放在哪里。

前序是"根—左—右"，先打印值再处理左右子树，所以打印必须放在**处理左子树之前**，打印 `current.value`。

后序是"左—右—根"，右子树处理完了往回走的时候，这个节点已经从栈里弹出来了，弹出来之后打印它的值。这是一处。还有一处——`pick.right == null` 那一支：它同样意味着左右子树都处理完成了，也该按后序的规则打印。所以后序有两处打印，打印的都是刚弹出的 `pick.value`。

中序是"左—根—右"，左子树处理完之后、右子树处理之前打印。这一处打印的是 `pick.value`，因为此时节点还在栈里没弹出去。另一处就是 `pick.right == null` 那一支：虽然右子树是空的，但这个值的打印不能少，得先打印完再去（那个不存在的）右子树。所以中序也是两处。

整理成一张表：

| 遍历 | 顺序 | 打印位置 | 打印的值 | 几处 |
| --- | --- | --- | --- | --- |
| 前序 | 根 左右 | 处理左子树之前 | `current.value` | 1 处 |
| 中序 | 左 根 右 | 处理右子树之前，以及 `pick.right == null` 分支 | `pick.value` | 2 处 |
| 后序 | 左 右 根 | 弹栈之后，以及 `pick.right == null` 分支 | `pick.value` | 2 处 |

对照表格就明白了：正是因为 `pick.right == null` 这一支和中序、后序各自的打印位置在**执行时间上不一致**，刚才才必须把原来的 `if` 拆成两支。

完整模板长这样，打印用不同颜色标出来（红 31 是前序、蓝 34 是后序、绿 36 是中序）：

```java
public void traversal(TreeNode root) {
    if (root == null) return;
    LinkedList<TreeNode> stack = new LinkedList<>();
    TreeNode current = root;
    TreeNode pop = null;
    while (current != null || !stack.isEmpty()) {
        while (current != null) {
            // 前序：在处理左右子树之前打印当前节点的值
            print(current.value, 31);
            stack.push(current);
            current = current.left;
        }
        TreeNode pick = stack.peek();
        if (pick.right == null) {
            stack.pop();
            pop = pick;
            print(pick.value, 34);   // 后序：无右子树，左右都已完成
            print(pick.value, 36);   // 中序：无右子树，打印完才轮到右子树
        } else if (pick.right == pop) {
            stack.pop();
            pop = pick;
            print(pick.value, 34);   // 后序：右子树已处理完成，往回走到当前节点
        } else {
            print(pick.value, 36);   // 中序：处理右子树之前，节点还留在栈里
            current = pick.right;
        }
    }
}
```

输出比较长，正好用颜色分开看：红色的前序是 `1 2 4 7 3 5 6`，绿色的中序是 `4 2 7 1 5 3 6`，蓝色的后序是 `4 7 2 5 6 3 1`，三路全部对上。一套代码，统一了前中后三种遍历。

### 力扣三道遍历题：把打印改成收集到 List

回到力扣，三道题一口气讲不完，分别是 144 题二叉树的前序遍历、94 题二叉树的中序遍历、145 题二叉树的后序遍历。

这三道题都没有规定说你必须用递归或者非递归来解，但它给了个建议：递归算法太简单了，问你能不能用迭代算法来完成。这个咱们都讲过。

实操一遍：就把上面这套通用模板复制过去，改三处。

第一处，**栈的实现换成 `LinkedList`**，这样就不用自己定义一个栈类了，可以少往 IDE 里粘贴一个类。

第二处，**把所有打印都删掉**。因为题目不是要你把结果打到控制台上，而是让你把这些值收集到一个 `List` 集合当中。所以先创建一个集合叫 `result`，然后把原来打印值的地方改成 `result.add(...)`。

第三处，整个循环结束、遍历完成的时候，`result` 里就已经保存了对应的全部值，直接 `return result` 就行了。

前序只有一个添加点，直接在 `current.value` 那里加：

```java
public List<Integer> preorderTraversal(TreeNode root) {
    List<Integer> result = new LinkedList<>();
    if (root == null) return result;
    LinkedList<TreeNode> stack = new LinkedList<>();
    TreeNode current = root;
    TreeNode pop = null;
    while (current != null || !stack.isEmpty()) {
        while (current != null) {
            result.add(current.value);   // 前序唯一的添加点
            stack.push(current);
            current = current.left;
        }
        TreeNode pick = stack.peek();
        if (pick.right == null || pick.right == pop) {
            stack.pop();
            pop = pick;
        } else {
            current = pick.right;
        }
    }
    return result;
}
```

中序和后序就不用再演示了，套路完全一样，只是添加元素的位置要换到刚才讲的那两处：

- 中序：没有右子树的那个分支里，把栈顶元素值加进去；以及处理右子树之前，把栈顶元素值加进去。
- 后序：没有右子树时，在它弹栈之后把 `pick.value` 加进去；以及右子树处理完成之后，把 `pick.value` 加进去。

三道题都复制过去提交，通过。

### 对称二叉树：比的不是左和左，是外侧和内侧

来看一道题目，对称二叉树。题意一看就明白：检查一棵二叉树是不是左右对称的。

```text
        1
      /   \
     2     2
    / \   / \
   3   4 4   3
```

根节点不用检查，从根节点的左右孩子开始对比：看看他俩的值是不是一样。相等，就表示至少从这两个节点开始是 ok 的、对称的，然后接着往下走。

往下走的时候，这里特别容易搞错：**不是左跟左比、右跟右比**。是这么比的：

```text
第 1 层：左 2      与  右 2
第 2 层：左 2 的左 3 与  右 2 的右 3   ← 外侧配对
         左 2 的右 4 与  右 2 的左 4   ← 内侧配对
```

下面一层完全类似，两个"三"之间也是外侧比外侧、内侧比内侧。这样一层层递归下去，最终就能判断出这棵树是不是对称的。当然，检查过程中一旦发现两边不一样（比如这边是个 6，那边不是 6），就立刻结束递归，告诉它这是一棵不对称的二叉树。

代码怎么写？首先要一个**独立的递归函数** `check`：因为题目给的函数只有一个参数，而待会儿我们要去检查两个参数，所以原来的函数就不拿来做递归了，重新写一个。新函数还是返回布尔值，`true` 表示对称，`false` 表示不对称，接受当前节点的左右两个孩子，从 `root.left` 和 `root.right` 传进去。

`check(left, right)` 有三种基本情况。

**第一种：左右两个孩子都是 `null`。** 说明对称，不用继续递归了，直接 `return true`。

**第二种：一边空一边不空。** 左边不空右边空，肯定不对称；左边空右边不空，同样不对称，`return false`。

**第三种：左右都不为空。** 先比较值：如果值不等，那它一定不对称，返回 `false`。

> **易错点**：值相等的时候**不能**直接 `return true`。有同学会写成 `return left.value == right.value;`，说"它俩值相等了，说明是对称的呀"——不对。即使两个 2 的值相等了，你也不敢保证他们的孩子对称；左边这个 2 要是有个孩子是 3，你在没有比较它下沉孩子的情况下，根本不能确定它俩是对称的。值相等只能说明"它俩的值不排除对称"，最后还得接着递归向下继续对比。

递归怎么往下走？外侧的一对：`check(left.left, right.right)`；内侧的一对：`check(left.right, right.left)`。这两个条件必须同时成立才算对称，把它们逻辑与的结果作为最终结果返回就可以了。

顺便说一个简化。第二个 `if` 条件里的两个"不等于 `null`"，其实是多余的。因为有了第一个 `if` 的检查，能执行到下面的代码，就意味着 `left` 和 `right` 肯定不能同时为 `null`（同时为 `null` 第一个 `if` 就成立、直接返回了）。既然我假定 `right == null`，那 `left` 肯定不为 `null`，多写这一句就是多余；同理假定 `left == null` 时，`right != null` 也是多余。所以两个条件都可以去掉。

> **易错点**：能这么简化的前提是**前面必须有那个"两者同时为 `null`"的 `if`**。没有第一个 `if`，你不能这么写。

代码：

```java
public boolean isSymmetric(TreeNode root) {
    if (root == null) return true;
    return check(root.left, root.right);
}

private boolean check(TreeNode left, TreeNode right) {
    // 情况一：两边都为空，对称
    if (left == null && right == null) return true;
    // 情况二：一边空一边不空，不对称（两个"!= null"是多余的）
    if (left == null || right == null) return false;
    // 情况三：值不等，一定不对称
    if (left.value != right.value) return false;
    // 值相等不能直接返回 true，还得递归比外侧和内侧
    return check(left.left, right.right) && check(left.right, right.left);
}
```

简单测一下，写两个用例：第一个是对称的——1 有两个孩子 2，左边这个 2 的两个孩子是 3 和 4，右边这个 2 的两个孩子是 4 和 3，应该返回 `true`；第二个是不对称的例子。两个用例都通过了。

### 二叉树最大深度：教材深度和力扣深度差 1

来看力扣 104 题，二叉树的最大深度。

先把深度定义说清楚。教材里关于深度的定义是：从这个树的根节点出发，找到离根最远的那个节点，然后数一下从根到这个离根最远节点的总的边数，也就是图中画的线段数目，就是它的深度。

```text
第一棵                第二棵                 第三棵

    1                     1                      1
   / \                   /  \                    /
  2   3                 2    3                  2

离根最远：2 或 3        离根最远：4            只有根节点
教材深度： 1            教材深度： 2            教材深度： 0
力扣深度： 2            力扣深度： 3            力扣深度： 1
```

第一棵树离根最远的是 2 和 3，距离都一样，随便找一个，从 1 到 2 有一条边，深度是 1。第二棵树离根最远的是 4，从根到 4 两条边，深度是 2。第三棵树没有其他左右孩子，深度是 0。

但是要注意一点：**我们最终要解的是力扣题目，力扣题目里的深度定义，要在教材的深度定义上多加一个 1**。也就是上面这张表最下面两行的差别：力扣里第一棵是 2、第二棵是 3、第三棵是 1。

后面的题目解答一律以力扣为准，因为最终我们更多是在力扣上做这些题。但教材中的定义也得知道。

#### 递归思路

第一种思路，也是比较简单的思路：递归求解。

以中间那棵树为例，我想求根节点 1 的深度。怎么办？我不知道，没关系——我先找到它左子树的深度，然后找到它右子树的深度，两个深度里挑一个最大的，再加上根节点自身这一层的 1，就得到本节点的深度了。

那右子树的深度怎么求？思路一样，递归求解。看 3 这个节点：求它左子树的深度、求它右子树的深度，这两个深度挑一个更大的再加一，就是 3 这个节点的深度。

那到什么时候可以直接求解、不用再递归了呢？到叶子节点。比如 4，左右子树都是 `null`，深度可以看成 0；两个 0 里挑一个大的还是 0，再加上它自己这一层 1，叶子节点的深度就是 1。遇到叶子节点就可以直接求解了。

代码就顺理成章：

```java
public int maxDepth(TreeNode root) {
    if (root == null) return 0;                                  // null 的深度是 0
    if (root.left == null && root.right == null) return 1;       // 叶子节点深度是 1
    int d1 = maxDepth(root.left);                                // 左子树深度
    int d2 = maxDepth(root.right);                               // 右子树深度
    return Math.max(d1, d2) + 1;                                 // +1 是把本层算上
}
```

`Math.max` 就是两个数字挑一个大的返回，别忘了求完子树的最大值之后还要 `+1`，这个 `+1` 是为了把本一层的深度加上。

测试用例已经写好了，正好对应图上画的这几棵：第一棵，一个节点 1，左孩子 2 右孩子 3，深度应该是 2；第二棵，左孩子 2，右孩子 3，而 3 又有一个右孩子 4，深度期望值是 3；第三棵只有一个根节点，它也算是没有左右孩子的叶子节点，深度是 1。运行一下，三个用例全部通过。

（提醒一下：在方法上直接运行只会跑一个用例，要把鼠标点到类上、右键 Run 整个类，三个用例才会一起跑。）

#### 叶子节点那个 if 其实可以去掉

最后说一个细节。代码里的第二个 `if`——判断叶子节点这一步，其实是可以去掉的。

为什么？看一个传进来的参数正好是叶子节点的情况，比如 4。它的左右孩子都是空，所以我去求左孩子深度，得到的是 0；再求右孩子的深度，结果也是 0。两个 0 里挑一个最大的，还是 0；最后加上一，正好就是这个叶子节点的深度 1。

所以就算把这个 `if` 去掉，刚才的代码仍然能对叶子节点求出正确结果。不加这个判断也可以。

#### 它本质上就是后序遍历

最后再往上抽一层。我们刚才这种思路求解二叉树最大深度，本质上是什么？

它本质上就是**后序遍历的递归应用**。为什么是后序？因为你看，我先要求左子树的深度，然后再求右子树的深度，这跟后序遍历"左—右—根"的顺序是吻合的。其实就是在遍历后序的过程中得知了左右子树的深度，然后回到当前节点，再做一些计算。

思路就是我们之前学过的二叉树后序遍历，这是这道题第一种解题思路。

### 非递归后序遍历：顺手量出栈的最大高度

第二种解题思路是用非递归的方式做后序遍历，而且是在遍历的过程中就把最大深度算出来。

我们先回忆一下，用非递归的方式做后序遍历，是不是要借助一个栈？没错，每经过一个节点就把它压入栈里。

来看这张图。这棵树长这样：

```text
            1
          /   \
         2     3
        / \     \
       4   5     6
          /
         7
```

从 1 开始一路向左走：经过 1，把 1 压栈；经过 2，把 2 压栈；正好走到 4，把 4 压栈——注意是"正好"，1 和 2 都没有左孩子以外的路，只有 4 有左孩子，而 4 没有左孩子，所以 4 直接把它的左指针置空，走到这里就走完了。

```text
沿左子树一路向前，每经过一个节点就压栈

        1                    2                    4
       / \                  / \                   /
      2   3     push      4   5     push       (null)
     / \     \  ──────►  / \     \  ──────►    走到底了
    4   5     6          5   6                   开始回退，看 right

   栈：[1]              栈：[1,2]              栈：[1,2,4]
```

走到头了，接下来就该往回走了。往回走的过程中，元素再从栈里一个一个弹出来。

这时候我们就可以插一句话进来了：我问，从 1 走到 4 走完了，是不是就代表这棵树从 1 到 4 的一个深度？是从 1 到 4 深度是三吧。

**当然，这可能不是最后的结果。** 为什么？你看我们接下来如果是从 1 一路走到 7 呢，那条路径是 1 → 2 → 5 → 7，这时候栈里压入的是 1、2、5、7，四个元素，深度就是 4 了。

所以规律就出来了：**后序遍历过程中，栈里元素个数的最大值，就是这棵树的最大深度**。因为栈里装的永远是"当前正在走、还没走完回溯"的那条根到当前节点的路径，路径有多长，栈就有多深。

```text
另一条路径走到更深处时，栈会更高

        1 → 2 → 5 → 7      栈：[1,2,5,7]      深度 4
```

> **结论**：记录这个栈的元素个数，每次它有了更大的值，就把这个更大的值记录下来。等到所有节点都遍历过一遍以后，这个栈曾经的最大值就是整棵树的最大深度。

### 把后序遍历的代码改造成求最大深度

这个代码我们以前写过，今天复习一遍。先定一个 `current`，代表当前节点，初始值是 `root`，从 root 开始向前走；还需要一个临时变量 `pop`，它对应的是最近一次弹栈的元素，初始值是 `null`；再就是一个 `stack`，用 `LinkedList` 来实现。

然后是一个 while 循环，条件是 `current` 不等于 null **或者**栈不为空，两个条件满足一个就得继续循环。

在每次循环里，我们要让它沿着左子树先向前走。所以当 `current` 不为空时，压栈，然后把 `current` 更新成 `current.left`。什么时候 `current` 等于 null 呢？也就是进入了 `else`，说明左边走到头了，那我们才在 `else` 里考虑是不是要往回走。

`else` 这块有个关键：**要等左右子树都处理完成了，栈顶的元素才能弹栈**。因为我是后序遍历嘛，比如这里的 2，要等它的左右子树都处理完成了才能弹栈。

怎么判断左右子树都处理完了？先 `peek` 拿到栈顶元素（只看不弹），看它两种情况：如果它的右子树是 `null`，那没啥可说的了，没有右子树肯定可以弹栈了；或者，当它的右子树正好是上一次弹栈的元素 `pop` 时，我们也认为它的右子树处理完了。就好比现在图里的栈顶元素是 2，最近一次弹栈元素是 5，那你看 2 的 right 是不是等于 5？2 的 right 等于最近一次弹栈元素，说明 5 这边都弹栈了，说明 2 的右子树处理完成了，那 2 能弹栈吗？可以。

于是把当前这个栈顶元素 pop 弹栈，弹栈的结果我们是不是要记录到 `pop` 变量里。

如果它的右子树不满足这两个条件，表示右子树还没处理完，我们就要让它沿着右子树向前进，也就是让 `current` 等于栈顶元素的右子树，进入下一轮处理。

```java
public List<Integer> postorderTraversal(TreeNode root) {
    List<Integer> result = new ArrayList<>();
    Deque<TreeNode> stack = new LinkedList<>();

    TreeNode current = root;
    TreeNode pop = null;           // 最近一次弹栈的元素

    while (current != null || !stack.isEmpty()) {
        if (current != null) {
            stack.push(current);   // 沿左子树一路向前走
            current = current.left;
        } else {
            TreeNode top = stack.peek();   // 只看不弹
            if (top.right == null || top.right == pop) {
                pop = stack.pop();          // 左右子树都处理完了，才能弹栈
                result.add(pop.val);
            } else {
                current = top.right;       // 右子树还没处理完，转过去
            }
        }
    }
    return result;
}
```

现在把这个后序遍历的代码跟题目结合起来。刚才我们已经分析过了，在后序遍历的过程中，如果我能记录下这个栈的最大高度，它就是我要求的整个树的最大深度。所以先定一个变量 `max`，代表栈的最大高度，刚开始当然是 0。

**什么时候去更新它呢？很简单，只有一个地方——你往这个栈里加元素的时候**，它的高度才会变化。所以我们等它 push 以后高度发生了变化，判断一下就行：先拿到它的 `size()`，这个 size 就是栈中元素个数，也就是它的高度；如果这个 size 大于我们的 `max`，就更新。

比如说刚开始是 0，那我走到 4 压栈的时候，它的元素个数是 3 了，那 3 比 0 大，是不是应该把最大高度更新成 3？这时 max 就等于 3。等我遍历到 7 的时候，栈里放了四个元素，这时候 size 是 4，比刚才记录的三更大，那我应该把 max 更新成 4。这样 max 就始终被记录为一个最大值。

等所有循环结束以后，返回的这个 max 就是我们栈曾经的最大高度，也是我们树的最大深度。

```java
public int maxDepth2(TreeNode root) {
    Deque<TreeNode> stack = new LinkedList<>();
    TreeNode current = root;
    TreeNode pop = null;
    int max = 0;

    while (current != null || !stack.isEmpty()) {
        if (current != null) {
            stack.push(current);
            max = Math.max(max, stack.size());   // 唯一需要更新 max 的地方
            current = current.left;
        } else {
            TreeNode top = stack.peek();
            if (top.right == null || top.right == pop) {
                pop = stack.pop();
            } else {
                current = top.right;
            }
        }
    }
    return max;
}
```

> **提示**：测试用例跟刚才差不多，只不过换成新写的这个类，三个用例跑下来都通过了。不过我要实话实说——第二种解法跟前面那种递归解法相比，你实际放到力扣上去跑，这个效率并不高。但是它也给你提供了一种解题思路。

### 层序遍历：队列的 size 就是分层的刀

求二叉树深度的第三种办法是使用层序遍历。这种做法很容易理解：你看这棵树有一层、两层、三层、四层，那它的层数不就是最大深度吗？所以我们用层序遍历把二叉树过一遍，我只要知道它有几层，最大深度就是几。

这个思想很容易理解，一眼就看出来了。

队列我们以前做练习的时候用过一道习题，当时已经做过一遍了，忘了的同学也没关系，我们再把这个代码稍微回顾一下。先选择一个队列的实现，之前练习时用的是我们自己自定义的接口和实现，今天我们稍微换一下，换成 JDK 给我们提供的队列接口 `Queue`，将来里面放的还是 `TreeNode` 这个类型；那实现类呢，就选择 `LinkedList` 就可以。

从这里我们也可以看到，`LinkedList` 的用途很多：它既可以作为双向链表，也可以作为队列，还可以作为栈——身兼数职。

层序遍历的逻辑大概是这样的：首先把根节点加到队列里，调用它的 `offer` 方法，把它加到队列的尾部；接下来写一个循环，不断地从队列的头部取出元素。比如一开始加的是根节点，那我就把根节点从队列头部取出来，取出来以后把它的下一层子节点加到队列——比如把 2 和 3 加到队列；等到下次循环的时候，再从队列头部把 2 取出来，取下来以后再把 2 的下一层加到队列。这样不断地循环，它就会把每一层的元素按从左到右的顺序依次加到队列了。

那什么时候结束呢？等我的队列为空了，表示所有的节点都处理过了，这时候退出循环。

```text
入队 root，然后不断「出队 → 把孩子入队」

   ┌──────────┐                    ┌──────────┐
   │ 1 │      │  出队 1，入队 2、3 │ 2 │ 3    │   ← 这一层是第 2 层
   └──────────┘  ──────────────►  └──────────┘
                                           │ 出队 2、3，入队 4、5、6
                                           ▼
                                    ┌────────────┐
                                    │ 4 │ 5 │ 6  │  ← 第 3 层
                                    └────────────┘
                                           │ 出队 4、5、6，入队 7
                                           ▼
                                     ┌─────┐
                                     │  7  │            ← 第 4 层
                                     └─────┘
```

把循环写出来：判断一下队列不为空的时候就不断循环，每次循环从队列的头部调用它的 `poll` 方法取出元素。取出来以后，要把它的下一层这些节点加到队列；加之前判断一下，如果这个节点是空的，那就没必要加了，不为空才加。

```java
public void levelOrder(TreeNode root) {
    Queue<TreeNode> q = new LinkedList<>();
    q.offer(root);

    while (!q.isEmpty()) {
        TreeNode node = q.poll();
        System.out.print(node.val + " ");
        if (node.left != null) {
            q.offer(node.left);
        }
        if (node.right != null) {
            q.offer(node.right);
        }
    }
}
```

整个遍历代码非常简单。等我这个循环不断循环，什么时候队列空了，相当于所有节点都处理完了，包括它的下一层也都处理完了，这时候就可以退出循环。

#### 输出里没有层的分界线，怎么办

我们先简单地实现了一个层序遍历，但刚才的输出结果里，并没有把层与层之间的分界线给它体现出来——第一层是 1，第二层是 2、3，第三层是 4、5、6，第四层是 7，全都连在一块儿了。

既然我不知道层的分界，那是不是最终我们并没有计算出这个层数，也就是最大深度啊？所以我们得把层与层之间给它区分开。

前面讲那个习题的时候，我讲过这么一种做法：先定一个临时变量 `c1`，它用来记录每层有几个元素，当然初始值是 1，因为刚开始第一层有一个元素。

接下来在里面写个小循环，在 while 里写个小循环，这个小循环就循环 `c1` 次。比如一开始循环一次，循环一次以后我输出一个换行，就表示第一层结束了。之后我更新 `c1` 的值——接下来要循环第二层了，我就把 `c1` 更新成 2，因为第二层有两个元素，这个小循环循环两次，输出一个换行，就把第二层的结束位置判断出来了。当然接下来 `c1` 被更新成 3，就是第三层我循环三次，最后它被更新成 1，第四层我循环一次。通过 `c1` 来判断我每一层的分界线。

> **易错点**：注意是"输出换行"表示这一层结束了，所以它其实发生在循环的末尾——换句话说，**层数是在循环结束之后才知道的**，这一点和后面最小深度要踩的坑正好相反。

那 `c1` 的这些值我们怎么统计出来呢？就是我怎么知道每一层有几个元素呢？很简单：我们在处理这一层元素的时候，把它的孩子的个数加起来，是不是就是它下层的元素个数啊。

所以我们再定一个临时变量 `c2`，刚开始它是 0，把所有这一层的孩子的个数累加到这个 `c2` 上，最终 `c2` 就是下一层元素的个数，也就是下次循环 `c1` 的值。

```java
public void levelOrderWithDivider(TreeNode root) {
    Queue<TreeNode> q = new LinkedList<>();
    q.offer(root);

    int c1 = 1;                       // 本层元素个数
    while (!q.isEmpty()) {
        int c2 = 0;                   // 下一层元素个数
        for (int i = 0; i < c1; i++) {
            TreeNode node = q.poll();
            System.out.print(node.val + " ");
            if (node.left != null)  { q.offer(node.left);  c2++; }
            if (node.right != null) { q.offer(node.right); c2++; }
        }
        c1 = c2;
        System.out.println();         // 一层的分界线
    }
}
```

改完之后跑一下，结果对了：第一层、第二层、第三层、第四层，清清楚楚。这是当时我们的一种实现方式。

#### 用 queue.size() 把 c1、c2 一起干掉

不过呢，今天我们选择的是 JDK 的队列实现，那我们可以让这个过程更加简单一些。

你看我们刚才是用 `c1` 去记录每一层有几个元素对吧？那其实不用这个 `c1` 也行——你看我们的队列中有一个方法叫 `size()`，它就是获取队列中有几个元素嘛。这个方法用它可以达到跟刚才 `c1` 完全等价的效果。

为什么？我们来分析一下。第一次循环的时候，这个队列中是不是有一个元素？就表示第一层只有一个元素嘛。接下来我们看这个小循环，小循环里是不是就把元素 1 出队了？一已经出队了，二和三就被加入到队列了。那我问，这时候队列有几个元素？也就是当我们这一次循环结束的时候，队列中是不是有两个元素——二和三没问题吧？那这是不是就是我们接下来第二层的元素个数？它下次循环的时候就循环两次不就得了吗。

那再来看，当它循环这两次处理二和三的时候，它是不是内层就会把二和三的孩子们加到队列？二和三被取走了，但是二和三的孩子们被加到队列了，那这时候队列的元素个数是几？是 4、5、6 没问题吧？所以等到下次再进入下层的循环的时候，队列中的元素个数就是三个。这三个元素如果处理完了，他们的孩子是不是被加入到队列了？当然这三个元素就从队列移走了，他们的孩子被加进去了，那这时候队列的元素个数就是一。

```text
q.size() 的取值序列：   1  →  2  →  3  →  1
c1   的取值序列：       1  →  2  →  3  →  1     完全一致
```

所以我们用队列的 `size()` 就可以取代原来的 `c1` 和 `c2`，代码就可以这么改：`c1` 这些都不要了，`c2` 也不要了。然后找到每次小循环刚开始的时候，就可以先拿到这个 size 的值，然后我这里循环 size 次就行了。

> **提示**：`for (int i = 0; i < q.size(); i++)` 这种写法当然也能跑，但我不建议这样写。因为你循环了十次，就相当于在循环内调了十次 `size()` 方法；而写在循环外侧，就相当于你只调了一次方法，每次循环的时候只是用你方法的返回值，并没有再去调九次方法——这样会好一些。

```java
public void levelOrderWithSize(TreeNode root) {
    Queue<TreeNode> q = new LinkedList<>();
    q.offer(root);

    while (!q.isEmpty()) {
        int size = q.size();          // 进入本层时，队列里正好是本层的全部节点
        for (int i = 0; i < size; i++) {
            TreeNode node = q.poll();
            System.out.print(node.val + " ");
            if (node.left != null)  q.offer(node.left);
            if (node.right != null) q.offer(node.right);
        }
        System.out.println();
    }
}
```

有同学会问："老师你之前为啥不用这个 size？这看起来简单是吧？"这里是有原因的。因为当时我那个实现好像有点问题——也不是说有问题，就是我当时我们自己的队列实现，我并没有给它加那个 size 字段。所以你想用那个 size 也行，但是就得改我这个实现，我得把代码实现稍微做一些调整。当时也是为了麻烦，所以我们没有 size，用了 `c1`、`c2` 那两个变量来实现了相同的效果。这是原因，也给大家解释一下。

#### 回到题目本身：加一个 depth

现在知道了怎么把层次分清，这道题就很简单了。我们加一个变量，这个变量用来统计深度，刚开始深度是 0。每次这个小循环结束的时候，也就是每次换行的时候，是不是我就知道这个深度应该加一了？所以在这里来一个深度加一。最后等这个外层的大循环结束，这个 depth 里面的值就是我们这棵树的深度，直接返回就可以了。

当然这些打印代码可以不要，因为它并不去计算我们的结果，只是为了我们调试过程看得清晰些。

```java
public int maxDepth3(TreeNode root) {
    if (root == null) {
        return 0;                     // 力扣可能传进来一棵空树
    }

    Queue<TreeNode> q = new LinkedList<>();
    q.offer(root);

    int depth = 0;
    while (!q.isEmpty()) {
        int size = q.size();
        for (int i = 0; i < size; i++) {
            TreeNode node = q.poll();
            if (node.left != null)  q.offer(node.left);
            if (node.right != null) q.offer(node.right);
        }
        depth++;                       // 处理完一层，深度加一
    }
    return depth;
}
```

测试跑一遍，测试用例都通过了。不过呢我们最后还是有一个地方没有考虑：力扣里可能会把这个 root 传过来是个 `null`，`null` 就表示它是个空的树，这个空的树它的深度应该是 0。如果你不加那个空的判断，它会有一个测试用例通不过。我们判断一下，如果 root 等于 null 表示深度是 0，我就不用走下面逻辑了，直接 return 0 就可以了。这也算是一个特殊的条件处理。

至此为止，我们求二叉树最大深度的三种方法就讲完了。

| 解法 | 深度从哪里来 | 讲师评价 |
| --- | --- | --- |
| 递归后序遍历 | 递推式 `max(left, right) + 1` | 效率是最高的 |
| 非递归后序遍历 | 栈的元素个数，取过程中的最大值 | 提供了一种新思路，性能稍逊一筹 |
| 层序遍历 | 队列 `size()` 逐层推进的轮数 | 一眼就能看出来的思路，性能稍逊一筹 |

> **结论**：真正写进生产代码、放到力扣上去跑，还是第一种递归后序最高效。后面这两种的价值在于——它们把"非递归遍历二叉树"这件事彻底打通了。

### 最小深度：对称写法只差一个判断

这节课我们再来解一道题目，叫做求二叉树的最小深度。

前面其实我们做过一道题叫求二叉树的最大深度，有同学说："好像这两道题差不多呀。"对吧？那我们对照着以前求最大深度那个代码，先来写这个最小深度的代码。

当然我们也是先判断一下，如果这个节点已经是 null 了，那这时候深度是 0，return 一个 0，这是递归的终止条件。然后接下来我们就递归来求一下它的左子树有多深、右子树有多深，两个里面取个小的，加上一，就是我这一层数的深度。就跟刚才的代码是对称的，因此呢我们就有先求左子树的深度 `node.left`，然后呢也是求它右子树的深度 `node.right`。两个深度有了，回这两个深度里挑一个小的，然后 return 求两个数的最小值，但我还得加上这一层它自身的深度，所以再加一。

```java
public int minDepth(TreeNode root) {
    if (root == null) {
        return 0;
    }
    int d1 = minDepth(root.left);
    int d2 = minDepth(root.right);
    return Math.min(d1, d2) + 1;    // 有同学就写出了这样的代码
}
```

有同学呢就写出了这样的代码，那这个代码对不对呢？我们来测试一下。这里我已经写好了几个测试用例，一共四个，我们都运行一遍。

可以看到它的前三个测试用例都通过了。那第四个为什么没通过呢？

第四个用例我描述了这样一棵树：根节点是 1，它的左子节点是 2，右子节点没有，就这么一棵树。

```text
        1
       /
      2
```

我问这棵树它的深度是几呀？深度是 2。但是我们运行这个测试用例时，求出来的深度是多少呢？就按我刚才这样去写，它求出来深度是 1。期望值是 2，但求出来是 1。

我们分析一下它的执行过程。这棵树的根节点是 1，首先把根节点从参数传过来，传过来以后呢，这个条件不成立，然后它就求根节点左子树的深度，左子树深度求出来应该是 1 吧。那再求根节点右子树的深度，这时候求出来是几？它没有右子树，求出来是 0。

**注意，求出来是 0 啊。** 那运行下面代码，下面代码里 0 和 1 里面挑一个最小值，是不是最小值又是 0？再加上本层的深度，0 + 1 = 1。所以呢就得出了我们根节点它的深度是一，这就不对了，深度正确的话应该是 2。

那问题出在哪了呢？问题就出在：如果它有一个子树是 `null` 的时候，其实是**不应该把它计算在内**的。这种情况下，我们认为不为 `null` 的那条树才是它的深度，为 `null` 的那个我们其实不应该把它作为深度的比较。

因此呢，它比我们那个求最大深度稍微要多一点代码。我们应该在左右子树这个深度返回以后，做一个判断：如果刚才的右子树，它的深度是 0，那这种情况下我们其实是应该以左子树的深度为准，就不要去两个里面再找最小值了，0 我们就不应该让它去参与这个最小值的计算。如果 `d2` 是 0，那这个时候呢，我们应该返回 `d1 + 1` 就可以了，就是返回它左子树深度加一，加上我本层的这个深度。那如果 `d1` 是 0 的话，也就是左子树这边为空了、右子树有东西对吧？那这种情况下应该返回 `d2 + 1`。

这是我们这两个条件的含义：第一个是当右子树为空时，它的深度计算出来是 0，这个时候我们就以左子树为准，就返回左子树深度加一；下面就是差不多的了，当左子树为 null 的时候，那我们应该返回右子树的深度加一。

**只有左右两个子树都不为 null 的时候，我们才需要找这两个深度的最小值，再加一。** 这是它跟我们之前求最大深度不一样的地方。

```java
public int minDepth(TreeNode root) {
    if (root == null) {
        return 0;                     // 递归的终止条件
    }

    int d1 = minDepth(root.left);     // 左子树的深度
    int d2 = minDepth(root.right);    // 右子树的深度

    if (d1 == 0) {
        return d2 + 1;                // 左子树为空，以右子树为准
    }
    if (d2 == 0) {
        return d1 + 1;                // 右子树为空，以左子树为准
    }
    return Math.min(d1, d2) + 1;      // 两边都有，取较小的那个
}
```

> **易错点**：最大值问题里 `null` 分支返回 0 完全没有影响，因为 0 永远不参与"取大"；可最小值问题里，0 是所有非负数里最小的那个，它一旦被算进去，结果必然塌成 1。**求最大深度可以无条件取 max，求最小深度必须先把 null 摘出去。** 这就是为什么最小深度比最大深度要多两个 if。

这是第一种解法，用后序遍历、递归的方式求解的。

### 最小深度的层序解法：遇到的第一个叶子说了算

刚才我们是使用后序遍历来实现了求二叉树的最小深度，那其实呢还有一种性能更高的做法，就是使用层序遍历来求二叉树的最小深度。

用层序遍历求最大深度的规律好找啊，就是一共有几层，二叉树的最大深度就是几。但怎么用层序遍历去找它的最小深度呢？这里大家不容易看出来。不过我们先给出结论：

> **结论**：如果你用层序遍历的话，那么你遇到的第一个叶子节点，它所在的那一层就是最小深度。

举个例子。就以现在这棵树为例，你看叶子节点都有哪些？是不是这里的 4，还有这里的 7，还有这里的 6。当然这个 6 跟 4 他们都是叶子节点啊，他们在同一层，太好区分了。那我把 6 换一下，把 6 去掉：

```text
去掉 6 之后，叶子节点变成了 4、3、7

        1
      /   \
     2     3
    / \
   4   5
      /
     7

   第 2 层： 3   ← 第一个遇到的叶子 → 最小深度 = 2
   第 3 层： 4
   第 4 层： 7
```

这回再来看我们这个结论，是不是就能领悟一些了？它遇到的第一个叶子节点所在的层就是最小深度。像这个离得最远的叶子节点 7，它肯定不是最小深度。那你看我们最近的是谁？是 3，它所在的这一层就是第二层，最小深度是 2。4 呢也不行，因为你层序遍历的话，它是后遇到的。

好，这是我们的结论。大家先知道了，那结论有了，写代码就非常简单了。

层序遍历的代码我们就不重头写了，就把之前求最大深度的那个层序遍历代码直接拿过来稍微改改就行了。这些打印就不要了。我们刚才给大家这个结论：将来你层序遍历的过程中，只要判断出这个节点是叶子节点，找到的第一个叶子节点，那它所在的层就是我们的最小深度。

所以我们从队列里拿出来一个节点以后，就先判断一下他是不是叶子节点，是叶子节点的话，就相当于找到了，我们就不用继续层序遍历了。那怎么判断一个节点是不是叶子节点？就是当他的左右孩子都是 null 的时候，像这里的 4、7、3，左右孩子都是 null，这是叶子节点的一个特征。

因此呢代码就是拿到这个节点以后，看一下他的左孩子如果等于 null，并且它的右孩子也等于 null，就表示找到叶子节点了。那既然找到叶子节点了，还需要继续循环吗？不需要了，我们直接返回就可以了。返回什么呢？就返回我们这个 depth，它是用来统计你是在第几层的。

```java
public int minDepth2(TreeNode root) {
    if (root == null) {
        return 0;
    }

    Queue<TreeNode> q = new LinkedList<>();
    q.offer(root);

    int depth = 0;
    while (!q.isEmpty()) {
        depth++;                      // 自增要放到本层循环的前面
        int size = q.size();
        for (int i = 0; i < size; i++) {
            TreeNode node = q.poll();

            if (node.left == null && node.right == null) {
                return depth;         // 遇到的第一个叶子节点，它所在层就是最小深度
            }

            if (node.left != null)  q.offer(node.left);
            if (node.right != null) q.offer(node.right);
        }
    }
    return depth;
}
```

> **易错点**：注意这个 `depth++` 的位置。我之前写求最大深度那个版本时，`depth++` 是放在小循环**结束之后**的，因为那时候层数是数出来的；这里必须把它放到小循环的**前面**。为什么？你看刚开始 depth 是 0 嘛，然后我遍历第一层，遍历的时候 depth 加一之后才变成 1。如果我们这时候第一层就是叶子节点了，这就是它的最小深度，直接 return 就对了。如果你把这个加加放在后面，他还没来得及加成一，就直接返回了，那就是初始值 0 了，就不对了。

为什么说它比我们之前那个后序遍历效率高一些呢？因为他只要找到叶子节点，后续就少了好多的遍历。比如说他找到第一个叶子节点 3 了，那后续这些 4 啊、7 啊这些节点就不用继续层序遍历了，直接返回，这个方法的调用也结束了。因此呢效率要比我们前面那种后序方式效率要高。

最后我们也是做一个简单的单元测试，这几个测试用例都通过了。你把这个代码直接放到力扣上也是没有问题的。

### 翻转二叉树：沿着那根轴翻过去

接下来我们再来看一道题目，叫做翻转二叉树。什么意思呢？我们看一下这个动画就明白了。

比如说刚开始这个树长这样（节点的编号是按层序从 1 开始排的）：

```text
        1
      /   \
     2     3
    / \
   4   5
      / \
     7   8
```

那么看一下它的翻转效果，就是把它的两个左右孩子做一个交换。比如说 1 的两个左右孩子 2、3，他俩交换一下——注意看 2 是不是交换到右边来了，3 交换到左边来了。当然 2 呢如果还有他的更多的孩子，都会跟着先交换过去。

这个 2 跟 3 是不是交换了？那接下来呢，3 他没有孩子就跳过了。2 这边呢，2 的两个孩子 4、5 是不是也应该交换一下来反转嘛，就整个反转一下。好，4 和 5 交换了一下。那 4 没有孩子就无所谓了，那 5 的两个孩子 7 和 8 呢，是不是也要交换一下？

最终的效果就是变成这个样子。我们可以截张图，跟它翻转之前我们做一个对比：

```text
       翻转前                            翻转后

          1                                 1
        /   \                             /   \
       2     3        ────►             3     2
      / \                               / \
     4   5                             5   4
        / \                           / \
       7   8                         8   7
```

大家看是不是就相当于做了一个沿我们的 y 轴做了一个 180 度的翻转呀。

下面来看一下这个代码的实现，这个还是比较简单的。你想啊，我翻转操作是不是就是把当前节点这两个左右孩子做一个调换呀——原来的左孩子变成右孩子，原来的右孩子变成左孩子，是不是这就 OK 了。那至于剩下这些节点怎么办呢？做一样的处理对吧。比如说这个 2，他的左右孩子是不是处理方式跟 1 的左右孩子一样呀？也是把他俩的位置做一个调换。

既然处理逻辑都一样，那这道题显然用递归解是最为合适的好。

那我们就写一个递归函数，就处理某一个节点，作为参数传进来，那我就处理这个节点它的左右孩子的翻转动作。那怎么翻转呀？很简单，我们先把它的左孩子存到一个临时变量 `t` 里面，然后把它的左孩子位置就空出来了，赋值为它的右孩子；然后再赋一个新的值，就是刚才临时变量 `t` 的值，是不是就相当于左右做了一个交换。

但这个树还没有整个翻转完成对吧？所以我们要对它的左孩子递归地做类似的操作，他的右孩子呢也要递归地做类似操作。比如说这个 2 他的左右孩子，也要做一个翻转。因此呢我们这个代码就可以继续递归，调用 `fn(node.left)`，就是对当前节点的左孩子做递归；然后呢对当前节点的右孩子做递归。

那什么时候是个头啊？只要你遇到传过来的节点对象是个 `null`——比如说 3 的左孩子是个 null，这个 null 传过来了，那还需要去翻转吗？不需要了啊。什么时候这个节点对象是 null，我们就结束递归就可以了。

```java
public TreeNode invert(TreeNode root) {
    fn(root);
    return root;              // root 本身不会变，翻转的是它的左右孩子
}

private void fn(TreeNode node) {
    if (node == null) {
        return;               // 遇到 null 就停止递归
    }

    TreeNode t = node.left;   // 左孩子先存到临时变量
    node.left = node.right;   // 左孩子位置让给右孩子
    node.right = t;           // 右孩子位置再填回临时变量

    fn(node.left);
    fn(node.right);
}
```

翻转的起点就是从 root 进行翻转。但是大家想啊，翻转之后这个 root 本身它不会变是吧？它都是在交换它的左右孩子，root 本身它不会变。那这道题目也说你将来翻转完了，再把这个 root 返回就可以了，所以我们最终返回这个 root 就 OK 了。

这道题目我们直接到力扣上测试一下，把刚才这个方法的代码拷贝过去，他原来那个就不要了，直接粘过来，提交一下——是不是测试通过了。这就是我们这个翻转二叉树，它就实现完成了。

> **提示**：整个翻转只有一个动作——交换指针。临时变量 `t` 是必需的，因为一旦先写了 `node.left = node.right`，原来的左孩子就再也找不回来了。

## 把字符串和遍历结果还原成二叉树
> 对应块：BLK41 | 覆盖分集：P159-P162 | 块标题（分集名）：《基础数据结构-114-二叉树-e08-根据后缀表》

这一段我们啃四个东西，但它们其实是一家人：**给我们的只有一串字符或者一串遍历结果，能不能把原来那棵树原样还原回来**。

先来一道不算力扣、但相当经典的题：给一个后缀表达式，让你构造出它对应的表达式树。接着两道是力扣上非常眼熟的老朋友——前序加中序还原、中序加后序还原。最后我们正式进一个新结构：二叉搜索树。

### 一棵还没长出来的表达式树

先回忆一下概念。中缀表达式、后缀表达式，后缀表达式也叫逆波兰表达式（Reverse Polish Notation）。之前做栈的那几道习题里我们见过两道相关的：一道是给一个后缀表达式算出最终结果，另一道是把熟悉的中缀表达式转成后缀表达式。今天这道不一样——后缀表达式本身可以用一棵二叉树来表示。

为什么值得这么表示？因为将来你存一个后缀表达式，它并不是就存成那么一串字符串的，计算机里往往把它转成这种树状结构来存，这样对计算机非常方便。

我们来看例子。`2 1 - 3 *` 这个后缀表达式，你写成中缀更眼熟：`(2-1)*3`，先拿 2 和 1 做减法，再把结果跟 3 做乘法。它对应的树是这样的：

```text
          *
        /   \
       -     3
      / \
     2   1
```

看图之前先把规则说清楚：**叶子节点都是操作数，非叶子节点都是运算符**。`-` 的左孩子是左操作数 2，右孩子是右操作数 1；`(2-1)` 的结果再跟 3 做乘法，所以 `*` 的左孩子是 `-`，右孩子是 3。最后 `(2-1)*3 = 1*3 = 3`。

所以题目就是：给你后缀表达式，把它转成这样的表达式树。解法跟之前求后缀表达式那道题非常像，**也要用栈**。

> **前提**：你给的后缀表达式是合法的，并且里面全是双元运算符，也就是每个运算符都接收两个操作数，不支持别的东西。没有这个前提，下面那套走法就无从谈起。

#### 扫一遍字符串，栈就是我们的"爹"

思路是从左往右遍历这个表达式。

遍历到的字符如果是数字，就先入栈。比如遇到的第一个字符是 `2`，就把 2 入栈；第二个字符是 `1`，就把 1 入栈。

> **为什么数字要先入栈？** 因为我们最终要建立的是节点之间的父子关系，而后缀表达式里**运算符一定靠右**——你看上面那张图，`-`、`*` 都是靠右被扫到的。父节点还没出现之前，这两个孩子节点你总得先有个地方暂存着，那就先放栈里。

一旦扫到运算符，就到了"建立父子关系"的时刻。哪个是左、哪个是右，这里是最容易搞错的一步：

1. **先出栈的是右孩子**。栈里是 `2` 后进、`1` 先出，所以 `1` 是 `-` 的右孩子，剩下那个 `2` 是左孩子。两个都弹完之后，这个 `-` 子树就建好了，把 `-` 自己再入栈。
2. 为什么运算符自己也要入栈？因为它还没完事，它得跟后面的操作数或者运算符**再去找一个爹**。比如接着扫到 `3`，把 3 入栈；再扫到 `*`，又是运算符，`-` 出栈、`3` 出栈组成 `-`、`*` 的两个孩子，最后把 `*` 入栈。

走一遍完整的过程，栈的变化一目了然：

| 扫到 | 动作 | 栈（从栈底到栈顶） |
| --- | --- | --- |
| `2` | 建一个数字节点入栈 | `2` |
| `1` | 建一个数字节点入栈 | `2` → `1` |
| `-` | 连弹两个建父子，`-` 入栈 | `-` |
| `3` | 建一个数字节点入栈 | `-` → `3` |
| `*` | 连弹两个建父子，`*` 入栈 | `*` |

扫完之后表达式就结束了，**栈里最后剩下的那个节点，就是整棵树的根**。至此，后缀表达式建树的操作就完成了。

#### 拿后序遍历反向验收

代码写完了，怎么验证构造出来的树是对的？有个特别简单的办法，而且特别漂亮。

先看一个规律：**对这棵表达式树做一次后序遍历（左右根），得到的结果应该就是原来的后缀表达式**。

对着图走一遍你就明白了。先一路深入到最左侧，打印 `2`；然后回到 `-` 的右孩子，打印 `1`；然后打印 `-`。这正好是 `*` 的左子树打完了。接着走右子树，`3` 是叶子，直接打印；最后打印根 `*`。

写出来就是：`2 1 - 3 *`。跟一开始那个后缀表达式一模一样。

> **结论**：如果后序遍历的结果跟你最开始给的后缀表达式一致，说明这棵树构造正确；不一致，就是有问题。
>
> 顺带一说，这也是后序遍历一个非常重要的应用——**二叉树的后序遍历可以很容易地得到一个后缀表达式**。

我的测试代码就是这么干的：先准备一批后缀表达式当测试用例（用的都是之前做过的那些逆波兰表达式），调方法拿到根节点，对根节点做一次 postOrder，把遍历到的每个节点值加进一个 resultList，最后拿这个 resultList 跟最开始的逆波兰表达式做对比。跑出来全部测试通过。

#### 落到代码里

有几个实现细节要交代清楚。

**第一，输入是字符串数组**，甭管数字还是运算符，统统用字符串表示，因为它们在遍历时长得一模一样。

**第二，节点的值要换成字符串。** 我们最早用的那个 `TreeNode`，里面的值是 `int` 类型的。现在表达式里数字和运算符混着存，我把这个值的类型改成 `String`。

**第三，栈用什么？** 为了让代码更好写，我用 `LinkedList` 作为栈的实现，它本来就是双端队列，`push`/`pop`/`peek` 现成。栈里放的元素统一是 `TreeNode`。

**第四，用 `switch` 分两种情况**：命中 `+`、`-`、`*`、`/` 就是运算符，走一套处理；剩下的交给 `default`，那就是数字，直接压栈。

```java
public class ExpressionTree {

    /**
     * 根据后缀表达式构建表达式树（表达式树的中序 = 中缀表达式，后序 = 后缀表达式）
     */
    public static TreeNode<String> build(String[] postfix) {
        // 用 LinkedList 作为栈的实现，栈里放的都是 TreeNode
        LinkedList<TreeNode<String>> stack = new LinkedList<>();

        for (String t : postfix) {
            switch (t) {
                case "+":
                case "-":
                case "*":
                case "/":
                    // 运算符：弹两个元素作为它的孩子节点
                    // 注意！先弹出来的是右孩子，后弹出来的才是左孩子
                    TreeNode<String> right = stack.pop();
                    TreeNode<String> left = stack.pop();
                    // 当前遍历到的 t 就是它们俩的父节点，也就是这棵子树的根
                    TreeNode<String> parent = new TreeNode<>(t);
                    parent.left = left;
                    parent.right = right;
                    // 它自己可能还要跟别的节点去建立父子关系，所以继续入栈
                    stack.push(parent);
                    break;
                default:
                    // 不是运算符，那剩下的就是数字，直接压栈
                    stack.push(new TreeNode<>(t));
                    break;
            }
        }

        // 循环结束，栈里剩下的那个节点就是整棵树的根节点
        return stack.peek();
    }
}
```

再补一个调用它、然后反向验收的测试骨架，注意后序遍历那个方法我们前面写过，直接拿来用就行，不用重复贴：

```java
@Test
void buildFromPostfix() {
    String[][] cases = {
        {"2", "1", "-", "3", "*"},
        // ...其余用例取自之前做过的逆波兰表达式
    };

    for (String[] postfix : cases) {
        TreeNode<String> root = ExpressionTree.build(postfix);
        List<String> resultList = new ArrayList<>();
        postOrder(root, resultList);          // 左右根，把每个节点值塞进结果集
        Assertions.assertEquals(Arrays.asList(postfix), resultList);
    }
}
```

> **易错点**：代码里就三处容易写反——先 `pop` 出来的是 **right**，后 `pop` 的是 **left**；父节点 `parent` 要**重新入栈**；数字分支里是**直接压栈**，不建父子关系。这三处一错，树的形状就整个歪掉，而后序遍历那个检验会第一时间把它揪出来。

### 前序加中序：把遍历结果还原回树

接下来上力扣的题。给你一个二叉树的**前序遍历**结果，也给你同一个二叉树的**中序遍历**结果，最后让你根据这两个结果把这棵二叉树还原出来。

比如前序是 `1 2 4 3 6 7`，中序是 `4 2 1 6 3 7`。还原出来应该是这样：

```text
              1
            /   \
           2     3
          /     / \
         4     6   7
```

凭什么能还原？靠的是前序和中序**各自的遍历特点**。

**前序是根左右**，所以它第一个打印出来的值，肯定是根节点的值。就拿这个例子，`preorder[0] = 1`，根就是 1，这非常好判断。

但光有前序，你不知道后面这些值哪些属于左子树、哪些属于右子树。没有别的条件的话，我完全可以编出一棵左子树是 `2 4 3`、右子树是 `6 7` 的树来，谁能说它不对？

**中序是左根右**，所以在它打印根节点值之前打出来的那些，一定是左子树的部分；打印根之后打出来的那些，一定是右子树。对着中序 `4 2 1 6 3 7` 一看：根是 `1`，它前面的 `4 2` 就是左子树，后面的 `6 3 7` 就是右子树。

可是注意，这里拆出来的 `4 2` 是**中序**的顺序，前序那边拆出来的左子树是 `2 4`，右子树是 `3 6 7`。光给前序的这两段顺序，还是确定不了 `4` 和 `2` 里谁是根、`3`、`6`、`7` 里谁是根。所以还得同时借助中序的结果继续往下区分。

这时候你就会发现——**这活儿是个子问题**。就盯着 `2 4`（前序）和 `4 2`（中序）这两组打印值看，处理方式跟刚才那个大问题是完全一样的：`2` 和 `4` 里谁是根？当然是 `2`，因为前序先打印根。那 `4` 是左还是右？没关系，去中序里一看，左边就是 `4`，所以 `4` 是左孩子；`2` 的右边没东西了，右子树为空。

下面这组同理。前序 `3 6 7` 定出根是 `3`，`6` 和 `7` 暂时定不出来；看中序 `6 3 7`，找到 `3` 的位置，它左边 `6` 是左子树，右边 `7` 是右子树。子问题一旦某一步没法再切分了，递归就停。

所以解题思路就是：**用递归，根据两组遍历结果先定根，再定左边有哪些、右边有哪些，一直切分到没法再切为止。**

#### 切数组的刀法：含头不含尾

写代码时，逻辑就三条：从中序里找根的位置 → 按位置把两边切出来 → 递归。

先说找根位置：写个循环从 0 遍历到 `inorder.length`，判断 `inorder[i]` 是不是等于刚才拿到的根节点的值。某一轮相等了，`i` 就是根在**中序**里的位置。在中序数组里，从 `0` 到 `i-1` 是左子树，从 `i+1` 到 `length-1` 是右子树。

切数组用的是 `Arrays.copyOfRange`，它后面有两个参数 `from` 和 `to`。**这里要特别注意：`from` 会被复制进去，`to` 不会被复制，实际上复制到的是 `to - 1`，也就是含头不含尾。** 所以传参的时候要自己加一减一：

```java
// 中序切分：左边 [0, i)，右边 (i, length]
int[] inLeft = Arrays.copyOfRange(inorder, 0, i);
int[] inRight = Arrays.copyOfRange(inorder, i + 1, inorder.length);
```

前序那边同样要切。根不用管它，我们要找 `2 4`，所以索引从 **1** 开始拷；拷几个元素呢？`4 2` 和 `2 4` 都代表左子树，长度肯定一样，`inLeft` 是从 0 拷到 `i`（不含），那 `preLeft` 就是从 1 拷到 `i+1`：

```java
int[] preLeft = Arrays.copyOfRange(preorder, 1, i + 1);
// preRight 则是 i+1 一路到数组末尾
int[] preRight = Arrays.copyOfRange(preorder, i + 1, preorder.length);
```

这里我为了大家看得清楚，先不考虑效率，每次切分都老老实实 `copyOfRange` 出一个新数组。回头再算这笔效率账。

#### 谁跟谁一组递归

左右子树都拆好了，万事俱备，只欠递归。

- **前序的左子树 + 中序的左子树**，也就是 `2 4` 和 `4 2`，它俩一组递归。
- **前序的右子树 + 中序的右子树**，也就是 `3 6 7` 和 `6 3 7`，它俩一组递归。

每次方法调用都能拿到一个根节点，把它返回上去。`2 4` / `4 2` 这组返回回来的是 `2`；`3 6 7` / `6 3 7` 这组返回回来的是 `3`。它们俩就是当前节点 `root` 的左孩子和右孩子。

> **易错点**：找到根节点位置之后，循环要立刻 `break`。`i` 已经拿到了，后面再往后遍历 `6 3 7` 那些元素纯属浪费，别忘了加这个 `break` 条件。

递归什么时候停？当 `preorder` 和 `inorder` 的长度等于零的时候，就可以结束递归 `return` 了——这时候没有子树了。

这个条件其实只写一个就行：传进来的 `preorder` 和 `inorder` 长度肯定是一样的，那一个是零了，另一个肯定也是零。

```java
public static TreeNode<Integer> buildTree(int[] preorder, int[] inorder) {
    // 递归终止条件：没有节点了
    if (preorder.length == 0 || inorder.length == 0) {
        return null;
    }

    // 前序第 0 个元素就是根节点的值，据此创建根节点
    int rootValue = preorder[0];
    TreeNode<Integer> root = new TreeNode<>(rootValue);

    // 在中序结果里定位根节点的位置，定位到了立刻 break
    int i = 0;
    for (; i < inorder.length; i++) {
        if (inorder[i] == rootValue) {
            break;
        }
    }

    // 中序切分：[0, i) 是左子树，(i, length] 是右子树
    int[] inLeft = Arrays.copyOfRange(inorder, 0, i);
    int[] inRight = Arrays.copyOfRange(inorder, i + 1, inorder.length);

    // 前序切分：根不在里面，左子树从 1 开始，长度与 inLeft 对齐
    int[] preLeft = Arrays.copyOfRange(preorder, 1, i + 1);
    int[] preRight = Arrays.copyOfRange(preorder, i + 1, preorder.length);

    root.left = buildTree(preLeft, inLeft);
    root.right = buildTree(preRight, inRight);
    return root;
}
```

### 中序加后序：只换了根的位置

下一道题跟上一道几乎是一家人：给你**中序**和**后序**的遍历结果，还原一棵二叉树。

解题思路也几乎一样，就差一个地方——**定位根节点的位置变了**。

后序是**左右根**，它得先把左右子树都打印完成，最后才打印根。所以根节点是**后序数组的最后一个元素**。就拿同一棵树来说，中序还是 `4 2 1 6 3 7`，后序是 `4 2 6 7 3 1`，最后一个 `1` 就是根。

> **提示**：这道题还有个前提——**所有节点的值都不会重复**。要是重复了就有麻烦了，比如这个结构里有两个 `1`，我拿着根节点的值去中序里找，到底是第一个 `1` 还是第二个 `1` 是根，就判断不出来了。题目已经给你保证了不重复，所以大家也不用担心比较出错。

定位到根之后，照旧回到中序里找它的位置。找到 `1`，它左边的 `4 2` 就是左子树，右边的 `6 3 7` 就是右子树。光有中序这一份还是不够的，得结合后序一起判断。

看后序结构：`4 2` 这一段切出来对应左子树，`6 7 3` 这一段切出来对应右子树。切完之后又是两个子问题——左子树那组继续递归去求它的根和下层左右子树，右子树那组同理。老规矩，递归求解。

区别就只这一点：**后序定位根，取的是数组最后一个元素。**

切数组时后序有个坑，非常容易写错：

- `postLeft` 是左子树，还是**从 0 到 `i`**（`i` 不含）。
- `postRight` 是右子树，**这个 `i` 要算进右子树里**，所以从 `i` 开始；末尾那个根元素不要，到 `length - 1` 为止（`copyOfRange` 的 `to` 不含）。

为什么右子树要包含 `i` 这个位置？因为在中序里，`i` 是**根**的位置；在后序里，根跑到了最末尾，同一个下标位置上装的已经是右子树的最后一个元素了。这两个数组的下标是一一对应的，只是根被搬到了后面。

```java
public static TreeNode<Integer> buildTree(int[] inorder, int[] postorder) {
    if (inorder.length == 0 || postorder.length == 0) {
        return null;
    }

    // 区别就在这：后序的最后一个元素才是根节点
    int rootValue = postorder[postorder.length - 1];
    TreeNode<Integer> root = new TreeNode<>(rootValue);

    // 到中序里定位根的位置，找到就 break
    int i = 0;
    for (; i < inorder.length; i++) {
        if (inorder[i] == rootValue) {
            break;
        }
    }

    // 中序切分：跟上一题一模一样
    int[] inLeft = Arrays.copyOfRange(inorder, 0, i);
    int[] inRight = Arrays.copyOfRange(inorder, i + 1, inorder.length);

    // 后序切分：左边 [0, i)，右边包含 i，末尾的根不要
    int[] postLeft = Arrays.copyOfRange(postorder, 0, i);
    int[] postRight = Arrays.copyOfRange(postorder, i, postorder.length - 1);

    // 中序的左 + 后序的左一组，右边一组
    root.left = buildTree(inLeft, postLeft);
    root.right = buildTree(inRight, postRight);
    return root;
}
```

> **易错点**：`inorder` 和 `postorder` 长度一样，所以拷贝范围用谁的 `length` 都一样，写哪个都行。但 `postRight` 的起点是 `i` 而不是 `i + 1`，终点是 `length - 1` 而不是 `length`——这两处必须比中序那两行多退一格、少进一格。

上一道题我没测，这道题测一下：把中序、后序丢进去建树，提交。结果测试是通过了，但效率明显不理想，执行花了 **6ms，只击败了 13.9% 的用户**。差在哪？

### 这两道还原题的效率账

 效率差主要体现在这么两点。

**第一，每次进入递归都要到中序结果里线性地找一遍根节点的位置。** 每层都找一遍，每层都是线性时间，一叠加就上来了。能不能把所有节点（每个子树的根）的位置一次性记录下来，加速这个查找？可以，最方便的数据结构是 `HashMap`。但我们到现在还没讲 HashMap，所以这个优化暂时先放一放。

**第二，每次切分左右子树我都 `copyOfRange` 创建了新数组。** 这块也可以优化：改成往下传**索引位置（下标边界）**，在原始数组的范围里查找，不创建新数组，这样就把创建数组和拷贝的开销全省了。

把这两处都做了之后，整个程序性能能到 **99% 左右，超过 99% 的提交者**。

这两个优化这道题我就不做了——HashMap 咱们暂时还没学。等讲完哈希表，我们再回过头来把它优化掉。

### 二叉搜索树：为了让查找不必从头挨个比较

前面学过的那些基础数据结构，数组、链表、队列，在里面查找一个元素，效率高不高？都不高，都是线性时间 $O(n)$。

如果需求是快速查找，那就得引入新的算法或者新的数据结构。这里有同学会想到，我们最早接触的那个算法——**二分查找法**，它能不能提高查询效率？可以，它的查询效率可以达到对数时间 $O(\log n)$，听起来不错。

> **但是它有前提**：二分查找是针对一个**已排序的数组**做的。而话说回来，你对一个数组里的元素做排序，这个成本还是比较高的。先排个序再去查找，好像有些得不偿失。

有没有一种折中的办法？换一种数据结构，不采用数组了，而是采用我们马上要介绍的**二叉搜索树**。用它既能让查询效率比较高，而且往这个结构里加入新元素的时候，它本身就已经是排好序的结构了，不用你再额外去排序。这就是我们要介绍二叉搜索树的原因。

#### 它的两条硬规矩

这棵树也叫**二叉排序树**。要成为二叉搜索树，必须符合两个特征。

**第一个特征**：树节点上要增加一个 `key` 这样的属性。以前讲二叉树的时候说过，节点的基本属性有 `value`、有左孩子和右孩子；除此之外，我们给二叉搜索树的节点再加一个 `key`。这个 `key` 用来比较这些节点谁大谁小。而且还有一个很重要的条件——**`key` 不能重复，在整棵树里它的取值是唯一的**。

**第二个特征**：对于树中的任意一个节点，它的 `key` 取值比它左子树的 `key` 都要大，比它右子树的 `key` 值要小。

```text
                4
              /   \
            2      7
           / \    / \
          1   3  5   8
                 /
                6
```

对着图验证一遍：节点 `4`，它左子树 `key` 取值是 1、2、3，都比 4 小；右子树的 `5 6 7 8` 都比 4 大。再看 `2`，左边 1 比它小，右边 3 比它大；`7` 左边 5、6 比它小，右边 8 比它大；`6` 左边 5 比它小。**树中所有节点都符合这个规则。**

那这里留个问题考考你：假设我想给 `6` 再加一个右孩子，这个右孩子将来它的取值应该是多少？

它必须比谁大？比 6 大。但它得比谁小？**得比 7 小**——因为 6 的右孩子，同时也属于 7 的左子树啊。所以我加一个 `6.5`，它就可以作为 6 的右孩子，你看 `6`、`5`、`6.5` 他们都是 7 的左子树，都要比 7 小。这就是二叉搜索树的两个特点，大家先理解一下。

#### 查找有多快

我们来找 `8`，看看这棵树中到底有没有。

**不需要跟每个节点都比较一次**。从根节点开始，先拿 `4` 跟待查找的 8 比较，发现 8 比 4 大，那接下来该去哪找？到 4 的右边去找。因为按二叉搜索树的定义，它右边这些值都比 4 大，左边这些值比 4 小——既然 4 都比 8 小，那左边的 1、2、3 肯定也比 8 小，左边这些完全不用比较了。

**这是不是自然而然就是一个二分查找？**

继续向右走，找到 `7`，7 跟 8 比发现 8 还是大，所以继续到 7 的右边找。7 左边那些 5 和 6 是不是也都不用比较了——又少了一半比较的次数。

沿着 7 继续向右走，当前节点的值跟待查找的值相等，就表示找到了。

一共比较了几次？一次、两次、三次。整棵树中的元素个数是 8 个，我只比较了 3 次。

> **结论**：查找的性能还是比较高的，**基本上跟树高相关**。包括以后要讲的插入、删除，也都是跟树高相关。如果这棵树长得还不错的，左右比较平衡，那它的时间复杂度可以达到对数级——一次少一半，一次少一半——就是 $O(\log n)$。

#### 什么时候会慢成一条直线

当然也有特殊情况。

```text
    5
   /
  4
 /
3
/
2
/
1
```

这也是一棵二叉搜索树，它也符合定义：5 的左边 4 都比它小，4 的左边 3 都比它小，3 的左边 2 都比它小，2 的左边 1 都比它小。但它长得有点丑——左右高度相差比较大，也就是它**不平衡**。

这种情况下查找性能就没那么高了。比如你要查找 `1`，得比较 `1 2 3 4 5` 五次才能找到，时间复杂度又回到线性时间 $O(n)$ 了。

所以二叉搜索树的**平均时间复杂度是对数时间，但最坏情况会退化成 $O(n)$**。后面我们会专门讲怎么把这个"最坏情况"给治住。

对二叉搜索树我们先建立这个初步认识，接下来就去设计它的数据结构，编写它的增删改查代码。

#### 根据后缀表达式建表达式树

**题干**：给定一个合法的后缀表达式（运算符均为双元运算符），把它还原成对应的表达式二叉树。例如 `2 1 - 3 *`。

**答案**：`root = *`；`*` 的左孩子是 `-`，右孩子是 `3`；`-` 的左孩子是 `2`，右孩子是 `1`。

**解析**：见「一棵还没长出来的表达式树」一节。核心是从左往右扫，数字入栈，运算符连弹两个（先弹的是右孩子）建立父子关系，再把自己入栈；扫完后栈顶即根。

            /   \

**解析**：见「前序加中序：把遍历结果还原回树」一节。前序定根、中序定左右，切成子问题后递归。
