# 栈与双端队列：表达式求值与互相模拟

## 中缀表达式与后缀表达式

### 两种记法

* **中缀表达式（Infix Notation）**

    * > **定义**：运算符写在两个数字之间的表达式形式，`1+2` 就是最典型的中缀表达式。

* **后缀表达式（Postfix Notation，又称逆波兰表达式，Reverse Polish Notation，RPN）**

    * > **定义**：把运算符推到最右端、写在操作数之后的表达式形式，`1+2` 写成 `12+`。

    * 运算符一律被推到最右，先弹出来的那个数是左操作数，后弹出来的那个数是右操作数。

    * 计算时只需从左向右扫一遍，遇到运算符就把栈顶两个数取出来算。

    * 不用考虑运算符优先级，也不用包含括号——拿到一个后缀表达式时优先级已经定好了，左边的优先级肯定更高，先运算，右边的以后再运算。

    * > **结论**：只要得到的是一个逆波兰表达式，就可以直接按栈算到底，不需要回查任何优先级规则。

    ```text
    中缀表达式              后缀表达式
       1 + 2       --->       1 2 +
       ^   ^                      ^  ^
       |   |                      |  |  |
       |   +-- 运算符夹在        |  |  +-- 运算符被推到最右
       |       两个数中间        |  +----- 后弹出来的那个数(右操作数)
       +---------- 左操作数      +-------- 先弹出来的那个数(左操作数)

    人读: 先 1, 再 2, 最后做 +
    机器读: 从左到右扫, 遇到运算符就把栈顶两个取出来算
    ```

### 编译器已经把中缀翻成后缀

* Java 源码编译成 `class` 字节码之后，中缀表达式已经被转换成更底层的后缀形式，转换工作由编译器完成。

* 字节码里不再用 `a`、`b`、`c` 命名变量，而是用槽位索引：索引 0 对应 `a`，索引 1 对应 `b`，索引 2 对应 `c`。

* 存取变量靠两个指令：`istore` 系列向变量存值，`iload` 系列读取变量值；`iadd` 对应加法运算，`imul` 对应乘法运算。

* 做 `a + b` 时对应三条指令：先 `iload 0` 读 `a` 的值，再 `iload 1` 读 `b` 的值，最后 `iadd` 才做加——加号不是先算的，它在两个数都读完之后才做。

    ```text
    a + b * c                (a + b) * c

    iload 0     |  a         iload 0     |  a
    iload 1     |  b         iload 1     |  b
    iload 2     |  c         iadd        |  a 和 b 先加, 结果留着
    imul        |  先把 b*c  iload 2     |  c
    iadd        |  再跟 a 加 imul        |  再跟 c 乘
    ```

* 查看字节码的命令是 `javap -c -v`，后面跟上类名。

## 后缀表达式求值

### 求值规则与推演

* **遇数字入栈，遇运算符出栈**

    * > **定义**：从左向右遍历 token，遇数字压栈，遇运算符从栈中取出两个元素计算，计算结果重新压栈，遍历结束后栈里剩下的那个元素就是答案。

    * 计算结果必须重新入栈，因为它可能还要和后续的数继续运算。

    * 从左向右遇到的第一个运算符，一定与它左边紧邻的两个数做运算。

    ```text
    token:      2        1        +        3        *
                |        |        |        |        |
                v        v        v        v        v
    stack:   [ 2 ] -> [ 2 1 ] -> [ 3 ] -> [ 3 3 ] -> [ 9 ]
              push     push     pop,pop   push     pop,pop
                                 push(2+1)           push(3*3)

    遍历结束, 栈里只剩 9, 它就是答案
    ```

* **两个典型算例**

    * `["2","1","+","3","*"]`：2 和 1 相加得 3 压回栈，第二个 3 压栈后两个 3 相乘得 9，结果 9，等价于 `(2+1)*3`。

    * `["4","13","5","/","+"]`：4 与 13 不能先算，因为 4 的右侧不是运算符；直到从左向右遇到第一个运算符 `/`，才对 13 和 5 做除法得 2（整数除法），再与 4 相加得 6。

* **题目给定的边界**

    * 加减乘除都视为整数运算，中间过程按整数处理，小数部分直接舍弃，不做四舍五入。

    * 数组长度不受限制。

    * 题目保证数字与运算符的个数是配对的，不会出现只给一个操作数就跟着运算符的情况，也保证不会出现除零。

    * > **易错点**：$13 \div 5$ 在这道题里是整数除法，结果是 2 而不是 2.6，小数部分直接舍弃即可。

    * 力扣自带的两个测试用例结果分别是 22 和 9。

### 弹栈顺序与左右操作数

* 压栈顺序与弹出顺序正好相反：先弹出的 `b` 是右操作数，后弹出的 `a` 是左操作数。

* 加法与乘法中 `a`、`b` 谁在前谁在后无所谓，减法与除法严格依赖该顺序，因此代码里一律写成 `a - b`、`a / b`。

* 方法签名是 `int evalRPN(String[] tokens)`，参数是存着数字或运算符的字符串数组，返回值是最终结果这个 `int` 整数。

### Java 实现要点

* 数组长度不受限制、栈的长度会变化，因此不用之前写的定长栈，直接用 `LinkedList` 充当栈。

* 栈的元素类型选引用包装类型 `Integer`，好处是容量可以动态变化、没有上限。

* > **提示**：`LinkedList` 表面看起来是链表，但它也实现了栈的相关方法，`push`、`pop`、`peek` 都有，够用了。

* 四个运算符分支几乎是复制粘贴，真正的差别只在符号；`default` 分支能走到就说明一定是数字，用 `Integer.parseInt(token)` 转换后压栈。

* `switch` 的新语法用减号加箭头，好处是不用写 `break`。

* 整个 `for` 循环结束后再 `pop` 一次，把栈里剩下的那个取出来就是最终结果。

    ```java
    public int evalRPN(String[] tokens) {
        // 数组长度不受限制, 栈的长度会变化, 所以用 LinkedList 充当栈
        LinkedList<Integer> stack = new LinkedList<>();

        for (String token : tokens) {
            switch (token) {
                case "+" -> { int b = stack.pop(); int a = stack.pop(); stack.push(a + b); }
                case "-" -> { int b = stack.pop(); int a = stack.pop(); stack.push(a - b); }
                case "*" -> { int b = stack.pop(); int a = stack.pop(); stack.push(a * b); }
                case "/" -> { int b = stack.pop(); int a = stack.pop(); stack.push(a / b); }
                default  -> stack.push(Integer.parseInt(token));
            }
        }
        return stack.pop();
    }
    ```

## 中缀表达式转后缀表达式

### 三条规则

* **规则一：遇到非运算符字符**

    * 数字、变量这类非运算符字符直接拼到结果字符串里，不进栈也不比较优先级。

* **规则二：遇到加减乘除运算符**

    * 栈为空时没人可比，当前运算符直接入栈。

    * 当前运算符优先级比栈顶高时，直接入栈，压着栈顶不动。

    * 当前运算符优先级比栈顶低或与栈顶平级时，把栈中优先级大于等于它的运算符全部出栈拼串（可能连弹多个），循环结束后当前运算符再入栈。

* **规则三：全部字符遍历完成之后**

    * 栈里剩余的运算符依次出栈，拼接到字符串尾部即可。

    ```text
    读到字符 c
      |
      |-- 不是运算符 ----------------------------> 直接拼串(数字/变量原样输出)
      |
      `-- 是运算符
            |
            |-- 栈为空 --------------------------> c 直接入栈(没人跟它比)
            |
            `-- 栈不为空, 比较 priority(c) 与 priority(栈顶)
                  |
                  |-- priority(c) > 栈顶优先级 ------> c 直接入栈
                  |                                     它比栈顶优先, 得排在栈顶后面算
                  |
                  `-- priority(c) <= 栈顶优先级
                        |
                        `-- while 栈非空 且 栈顶优先级 >= priority(c)
                              |-- 成立: 出栈 -> 拼串, 继续循环(可能连弹多个)
                              `-- 不成立: 跳出, c 入栈

    遍历全部字符之后: 栈里剩下的运算符依次出栈, 拼到字符串尾部
    ```

* > **提示**：写这类代码前一定先在纸上把规律走通，没有归纳就动手，逻辑很容易写错。

### 优先级与对照关系

* **优先级设定**

    | 运算符 | 优先级 |
    | :--- | :--- |
    | `*`、`/` | 2 |
    | `+`、`-` | 1 |
    | `(` | 0 |

    * `priority(char)` 用 `switch` 表达式实现：匹配到乘号或除号返回 2，匹配到加号或减号返回 1，其他情况视为非法运算符并抛异常；以后有更多运算符可以在这条规则上扩展。

* **比较结果的三种对照**

    | 遇到运算符 `c`，栈顶是 `t` | 谁该先算 | 动作 |
    | :--- | :--- | :--- |
    | `c` 优先级比 `t` 高 | `c` 先算 | `t` 不出栈，`c` 直接入栈压着它 |
    | `c` 与 `t` 平级 | 左边的 `t` 先算 | `t` 出栈拼串，`c` 再入栈 |
    | `c` 优先级比 `t` 低 | `t` 先算 | 弹掉所有优先级 ≥ `c` 的拼串，`c` 入栈 |

* **平级与更高的处理**

    * 加减、乘除各自平级，平级一律由左向右运算；遇到第二个平级运算符时，先把前一个弹栈拼串让它先运算，当前运算符再入栈。

    * `a + b - c`：加号先出栈拼串，减号再入栈，结束时减号出栈，得到 `ab+c-`，语义是先做 `a+b` 再与 `c` 相减。

    * `a + b * c`：加号先入栈，遇到优先级更高的乘号时不弹加号，乘号直接压在上面；遍历结束后依次出栈得到 `abc*+`。

    * `a + b * c - d`：遇到减号时，乘号和加号都比它高或与它平级，都要先出栈让它们先运算，减号最后才入栈，结束时再出栈。

    ```text
    读入:   a      +       b      *       c
            |      |       |       |       |
            v      v       v       v       v
    sb:    "a"     |     "ab"    |      "abc"
            |    push(+)  push(*)
            |    stack=[+] stack=[+, *]
            |                 |
            |                 +-- '*' 优先级更高, 直接入栈, 压着 '+' 不动
            |
    遍历结束: 依次 pop -> sb.append('*') -> sb.append('+')
    结果:    "abc*+"
    ```

### 括号出栈规则

* **左括号的优先级故意设成 0**

    * 左括号可以看成一个运算符，识别到它就把它压进栈里，作为一条特殊处理。

    * > **易错点**：直觉上括号的优先级最高，但为了让左括号能套进「比栈顶优先级高才入栈」这条已有规则里、不改动原来的代码，必须让左括号的优先级比加号还低。记住这一条就够了。

    * 有了优先级 0 这条设定之后，`a` 拼串、左括号入栈、`+` 因为优先级高于栈顶的左括号而入栈、`b` 拼串，整套规则不必分叉。

* **右括号：弹到左括号为止**

    * 右括号意味着括号里面所有的运算都应该马上做，所以从栈顶一路弹到左括号为止，弹出来的运算符都拼到结果串尾部。

    * 循环退出之后还要再 `pop` 一次，把左括号弹掉；这次弹出的左括号不做拼接，直接丢弃。

    * 右括号只弹到左括号为止，括号外面更早入栈的运算符一律留着不动。

    * > **提示**：`while` 循环要加上 `!stack.isEmpty()` 判断，是为了挡掉可能产生空指针的警告；实际上只要遇到右括号，前面必然已经压过一个左括号，这个情况不会出现。

    ```text
    入栈序列:  (  +  *        ( * 入栈后还没来得及出栈)
    拼接结果:  a  b  →  ab+c*

    遇到 ')':
      栈顶是 '+'  ≠ '('  →  pop，拼接  →  ab+c+
      栈顶是 '('  = '('  →  跳出循环
      最后再 pop 一次，把左括号弹掉 —— 但它不用拼接，直接抛弃
      接着 '*' 才入栈，'c' 拼串
    没有更多字符了 → 把 '*' 出站，拼到尾部

    最终: ab+c*
    ```

* **括号样例走查**

    * `(a+b)*c`：左括号入栈、`a` 拼串、加号因优先级高于左括号入栈、`b` 拼串，右括号弹出加号拼串并丢弃左括号，`*` 入栈、`c` 拼串，结束时 `*` 出栈，得 `ab+c*`。

    * `(a+b*c)-d*e`：左括号、`a`、加号、`b`、乘号、`c` 之后遇到减号，乘号比减号高先出栈、加号与减号平级也要提前出栈，左括号优先级比减号低留着不动；减号入栈、`d` 拼串，最后减号与左括号一起出栈；再往后乘号入栈、`e` 拼串，结束时乘号出栈，得 `abc*+d-e*`。

    * `a*(b+c)`：左括号优先级虽低于乘号，但遇到左括号一律直接入栈；右括号只把加号弹出并丢弃左括号，最初那个乘号留着不动，结束时乘号才出栈，得 `abc+*`。

* **不带括号的对照结果**

    | 中缀 | 后缀 |
    | :--- | :--- |
    | `a + b` | `ab+` |
    | `a + b - c` | `ab+c-` |
    | `a + b * c` | `abc*+` |

### 实现骨架

* 栈用 `LinkedList<Character>`，因为将来主要放的是运算符。

* 结果串用 `StringBuilder` 拼接，初始容量取原表达式长度；实际结果会更短，因为转换后括号都被丢掉了。

    ```java
    public String infixToPostfix(String infix) {
        LinkedList<Character> stack = new LinkedList<>();
        StringBuilder sb = new StringBuilder(infix.length());

        for (int i = 0; i < infix.length(); i++) {
            char c = infix.charAt(i);
            switch (c) {
                case '+', '-', '*', '/' -> {
                    if (stack.isEmpty()) {
                        stack.push(c);            // 栈空, 没人可比, 直接入栈
                    } else if (priority(c) > priority(stack.peek())) {
                        stack.push(c);            // 当前运算符更高, 直接入栈
                    } else {
                        while (!stack.isEmpty() && priority(stack.peek()) >= priority(c)) {
                            sb.append(stack.pop());
                        }
                        stack.push(c);
                    }
                }
                default -> sb.append(c);           // 非运算符, 直接拼串
            }
        }

        while (!stack.isEmpty()) {
            sb.append(stack.pop());
        }

        return sb.toString();
    }
    ```

## 双栈模拟队列

* **为什么要两个栈**

    * 队列一端进一头出，栈只能操作一头、只能动栈顶，所以至少要两个栈才能模拟一个队列。

    * `s2` 的栈顶模拟队列尾，`s1` 的栈顶模拟队列头。

* **队尾交给 s2**

    * 往队列尾部添加元素直接调 `s2.push`：新元素压到 `s2` 的栈顶，就等价于加到了队列尾巴上。

    * 先加 `a` 再加 `b` 时，`b` 放在 `a` 上面、``a` 向底部靠，形态上就是 `b` 排在队列尾部。

* **队头先把 s2 倒进 s1**

    * 要移除队头 `a` 时它卡在 `s2` 栈底，栈动不了它，得先把 `s2` 的元素全弹出来推进 `s1`，顺序正好颠倒过来，之后取 `s1` 栈顶就是队头。

    ```text
    加入 a、b 之后
      s2: [ a | b ]    ← 栈顶是 b，b 就是队尾；a 被压在栈底
      s1: [   空   ]

    要移除队头 a，可 a 卡在 s2 栈底，栈只动栈顶，动不了 —— 借 s1

      s2: [ a | b ]   pop b   →  push 进 s1  →  s1: [ b ]
      s2: [ a     ]   pop a   →  push 进 s1  →  s1: [ a | b ]
                         ↓
      s2: [   空   ]
      s1: [ a | b ]    ← 栈顶 a 就是队头

    从顶至底看：s2 里是 b a，倒进 s1 后变成 a b，顺序正好颠倒
    ```

* **只倒一次就够**

    * 只要 `s1` 不为空就直接从 `s1` 移除，不必每次都回 `s2` 找；等 `s1` 空了再去 `s2` 倒腾一遍。

* **peek 与 empty**

    * `peek` 的逻辑与 `pop` 几乎一样，只把最后一行从 `pop` 改成 `peek`，即只获取不移除队头元素。

    * `empty` 要两个栈都空才算整个队列为空：`return s1.isEmpty() && s2.isEmpty();`。

* **实现选择**

    * 两个栈都选自定义实现，不自动扩容，容量一旦在构造方法里给定就不能再变。

    * 题目限定最多调用 100 次 `push`、`pop`、`peek` 或 `empty`，所以两个栈的大小都设成 100，肯定够用。

    * > **结论**：这类互相模拟的题目在实际开发中没有太大意义，主要是用来熟悉队列与栈各自的操作特点——队列一端添加一端移除，栈只能操作一端。

    ```java
    Stack<Integer> s1 = new Stack<>(100);   // 模拟队列头
    Stack<Integer> s2 = new Stack<>(100);   // 模拟队列尾

    public void push(Integer value) {
        s2.push(value);
    }

    public Integer pop() {
        if (s1.isEmpty()) {
            while (!s2.isEmpty()) {
                s1.push(s2.pop());
            }
        }
        return s1.pop();
    }
    ```

## 单队列模拟栈

* **push 的做法**

    * 队列的 `offer` 总是从尾部添加，先加的 `a` 恰好在栈顶，但后加的 `b` 就跑到栈底去了，跟期望的栈行为不符。

    * 办法是把新元素前面的所有元素从队头搬到队尾，新元素就转到了队头、也就是栈顶。

    ```text
    栈的视角：栈顶 → 栈底
    队列的视角：队头 → 队尾

    push(a)                     [ a ]
    push(b)  offer → [a b]      轮转 1 次  →  [ b a ]
    push(c)  offer → [b a c]    轮转 2 次  →  [ c b a ]
                                栈顶=c，栈顶到栈底 c b a —— 与 a b c 正好逆序 ✓

    再 push(d)：offer → [ c b a d ]，轮转 3 次
      [ b a d c ] → [ a d c b ] → [ d c b a ]
      栈顶 = d  ✓
    ```

* **size 的维护是这题的关键**

    * > **易错点**：循环次数是 `size - 1` 而不是 `size`；`size` 先自增再循环，轮转的正是新元素之前的那批元素，新元素自己已经 `offer` 到队尾了不用再转。

    * 写反了就变成老元素排到新元素后面，那就不是栈了。

* **pop、top、empty**

    * `pop` 把 `size` 减一并返回 `queue.poll()`；`top` 调 `queue.peek()`，`size` 不变；`empty` 直接 `return queue.isEmpty()`，一个队列对应一个栈。

    * > **提示**：题目保证调用 `pop` 和 `top` 时栈不为空，所以可以省掉空检查——队列为空时会返回一个 `null`，而 `null` 无法转成基本类型 `int`，本来就会抛空指针异常。

    * 队列用之前实现的 `ArrayQueue`，容量同样设成 100，因为题目限定这些方法最多调用 100 次。

    ```java
    ArrayQueue<Integer> queue = new ArrayQueue<>(100);
    private int size = 0;

    public void push(int value) {
        queue.offer(value);
        size++;
        for (int i = 0; i < size - 1; i++) {
            queue.offer(queue.poll());
        }
    }

    public int pop()        { size--; return queue.poll(); }
    public int top()        { return queue.peek(); }
    public boolean empty()  { return queue.isEmpty(); }
    ```

## 双端队列

* **双端队列（Double Ended Queue，Deque）**

    * > **定义**：在队列的两端都能做添加、都能做删除的队列，只是队列的中间不能随便操作。

    * `Deque` 里的 `d` 是 double 的意思，第二个 `e` 是 end 的意思，`que` 是队列，合起来就是双端队列。

* **三种结构的对照**

    | 结构 | 能操作的一端 | 不能操作的一端 | 特点 | 口头缩写 |
    | :--- | :--- | :--- | :--- | :--- |
    | 队列 | 头删、尾加 | 中间不能动 | 先进入的先出来 | FIFO |
    | 栈 | 栈顶加、栈顶删 | 另一端不能动 | 后进来的先出来 | LIFO |
    | 双端队列 | 头尾都能加、都能删 | 中间不能动 | 限制更少 | — |

    * 队列的 FIFO（First In First Out）来自「尾部只能添加，将来头部才能取出」这条限制；栈的 LIFO（Last In First Out）来自「添加和删除都发生在栈顶」。

* **接口里的八个方法**

    | 方法 | 作用 |
    | :--- | :--- |
    | `offerFirst` | 向队列的头部添加元素 |
    | `offerLast` | 向队列的尾部添加元素 |
    | `pollFirst` | 从队列的头部删除元素 |
    | `pollLast` | 从队列的尾部删除元素 |
    | `peekFirst` | 获取头部元素，不删除 |
    | `peekLast` | 获取尾部元素，不删除 |
    | `isEmpty` / `isFull` | 判空、判满 |

    * 优先级队列、延时队列、并发非阻塞队列、并发阻塞队列都属于队列家族，但不属于这次实现的范围。

### 双向环形链表实现

* **为什么选双向环形链表**

    * 「双向」与「双端」不是同一个概念：双向说的是链表节点既有 `previous` 指针又有 `next` 指针，只有 `next` 的叫单向链表；双端说的是队列两端都能增删。

    * 之前的队列只用单向链表就够，是因为它删头时有哨兵兜底，头节点的 `previous` 是已知的，不需要额外操作。

    * 双端队列还要删尾，单向链表只知道尾巴自己、不知道它的上一个是谁，还得去查找，性能就低了；用双向链表可以通过 `previous` 指针直接拿到尾的上一个节点。

    * 用环形是为了让一个哨兵既充当头又充当尾，省掉一个哨兵，操作更方便。

* **哨兵 sn 的初始化**

    * 队列类要提供 `capacity`（构造方法初始化）、`size`（元素个数）和哨兵 `sn`。

    * 初始化时 `sn.next` 指向头、`sn.previous` 指向尾，而 `sn` 自己既是头也是尾，所以两者都指向 `sn`，`sn.value` 也赋成 `sn`。

    ```java
    private static class Node {
        private Node previous;
        private Node next;
        private Integer value;

        public Node(Node previous, Node next, Integer value) {
            this.previous = previous;
            this.next = next;
            this.value = value;
        }
    }

    private final Node sn;          // 哨兵：既是头也是尾

    public Deque(int capacity) {
        this.capacity = capacity;
        this.size = 0;
        sn = new Node(null, null, null);
        sn.next = sn;                // 尾的 next 指向头
        sn.previous = sn;            // 头的 previous 指向尾
        sn.value = sn;
    }
    ```

* **四个节点的统一命名**

    * 双向链表插入一个节点要改四根指针：新节点 `added` 身上两根（`prev`、`next`），老邻居 `a`、`b` 身上各一根，`a.prev` 和 `b.next` 原样不动。

    ```text
    插入前:      a  <──>  b

                 a.next 要改成 added
                 b.prev 要改成 added
                 added.prev = a
                 added.next = b

    插入后:      a  <──>  added  <──>  b
                 ↑            ↑            ↑
              a.next     added 双指针     b.prev
    ```

    * 头插时 `a` 是哨兵、`b` 是 `sentinel.next`；尾插时 `a` 是 `sentinel.previous`、`b` 是哨兵。

    * 两个 `offer` 方法只差 `a`、`b` 分别是谁这两行，中间的插入代码、`size++`、`return true` 一字不差，第二个方法复制一下改两行就完事。

    * 移除时让 `a` 和 `b` 互相指过去：`a.next = b`、`b.prev = a`，谁也不再指向 `remove`，它就被彻底摘出去了；`remove` 自己的 `prev`、`next` 不用清，反正没人能走到它。

    ```text
    移除前:   a  <──>  remove  <──>  b

    移除后:   a  <──────────────>  b
              a.next = b
              b.prev = a

    读图：两边互相指过去，谁也不再指向 remove，它就被彻底摘出去了。
          remove 自己的 prev / next 用不着清，反正没人能走到它。
    ```

    * 头删时 `a` 是哨兵、`remove` 是 `sentinel.next`、`b` 是 `remove.next`；尾删时 `b` 是哨兵、`remove` 是 `sentinel.previous`、`a` 是 `remove.prev`。

* **判空判满与 peek**

    * > **结论**：链表版的判空判满完全由 `size` 说了算——`size` 等于零队列就是空的，等于 `capacity` 就是满的，不用数节点，也不用去看 `head` 和 `tail` 有没有撞在一起。

    * > **注意**：满了以后 `offerFirst` / `offerLast` 直接 `return false`，不是抛异常。

    * `peekFirst` 直接返回 `sentinel.next.value`，`peekLast` 返回 `sentinel.previous.value`；都先判空返回 `null`，因为不移除所以 `size` 不用修改。

    * 迭代器从 `sn.next` 起步，`hasNext` 判断 `p != sn`，`next` 先取 `p.value` 再让 `p = p.next`。

    ```java
    public boolean isEmpty() {
        return size == 0;
    }

    public boolean isFull() {
        return size == capacity;
    }

    public E peekFirst() {
        if (isEmpty()) {
            return null;
        }
        return sentinel.next.value;
    }

    public E peekLast() {
        if (isEmpty()) {
            return null;
        }
        return sentinel.previous.value;
    }
    ```

* **链表版测试用例**

    * 容量 5：`offerFirst` 依次加 `1`、`2`、`3` 得到头部段 `321`，再 `offerLast` 两次加 `4`、`5`，整体是 `32145`；再加第六个元素时队列已满，返回 `false`。

    * 全部用 `offerLast` 加 `1`~`5`，因为都是尾部添加所以顺序保持为 `12345`，随后连续摘取：

    | 次序 | 调用 | 返回值 | 剩余队列（头 → 尾） |
    | :--- | :--- | :--- | :--- |
    | 1 | `pollFirst` | 1 | `2345` |
    | 2 | `pollFirst` | 2 | `345` |
    | 3 | `pollLast` | 5 | `34` |
    | 4 | `pollLast` | 4 | `3` |
    | 5 | `pollLast` | 3 | 空 |

    * 队列空了之后再调任何 `poll` 返回的都应该是 `null`，此时 `isEmpty` 返回 `true`。

### 循环数组实现

* **元素一动不动，动的是指针**

    * 两个指针 `head` 和 `tail`，刚开始都指向数组下标零。

    * `offerLast` 先把元素放进 `tail` 指向的索引，再让 `tail` 加一；`offerFirst` 先让 `head` 减一，再把元素放进 `head` 指向的索引。

    * 向头部添加不需要把 `a`、`b` 整体后移，因为循环数组里元素不动，只动指针。

    * `head` 减一得到 `-1` 也没关系，做一次索引换算把它变成 `3` 即可，不出现无效索引就行。

    * > **结论**：加减完之后都必须换算成合法有效索引。

    ```text
    初始状态（offerLast 加了 a、b 之后）
    下标:     0        1        2        3
             [ 空 ]  [  a  ]  [  b  ]  [ 空 ]
              tail                             head

    调用 offerFirst(c)：head 先减一 → -1，再把 -1 换算成 3

    下标:     0        1        2        3
             [ 空 ]  [  a  ]  [  b  ]  [  c  ]
              tail                             head

    读图：从 head 读到 tail，顺序就是  c  a  b
    ```

* **空与满靠浪费一格区分**

    * `head == tail` 表示队列为空。

    * 从 `head` 一直到 `tail` 的距离等于数组长度减一，表示队列已满。

    * > **结论**：只用 `head` 和 `tail` 两个指针，就必须浪费一个位置来区分空和满——如果让 `tail` 停下的位置也存元素，两个指针会重新指向同一位置，跟判空条件一模一样就区分不出来了。

    * 如果另外用一个 `size` 变量来判断空满就可以避开这一点；这个实现不用 `size`，所以 `tail` 停下来的那个位置不存储元素，实际数组长度要给到「给定容量加一」。

    ```java
    private E[] array;
    private int head;
    private int tail;

    @SuppressWarnings("unchecked")
    public ArrayDequeImpl(int capacity) {
        array = (E[]) new Object[capacity + 1];   // 尾部浪费一格, 长度取容量 + 1
    }
    ```

* **四种操作的先后顺序**

    | 方法 | 顺序 | 原因 |
    | :--- | :--- | :--- |
    | `offerLast` | 先放元素，`tail` 加一 | `tail` 停下的位置本来就不存元素 |
    | `offerFirst` | `head` 先减一，再放元素 | 保证从头读到尾就是正确的顺序 |
    | `pollFirst` | 先取值，`head` 加一 | 值要交给调用者，得先拿到 |
    | `pollLast` | `tail` 先减一，再取值 | `tail` 指的位置压根没元素 |

    * `head` 加一之后可能等于数组长度成为无效索引，`tail` 减一之后可能变成 `-1`，两者都要靠工具方法换算回来。

* **increment 与 decrement**

    * `increment(i, capacity)`：`i + 1 < capacity` 就返回 `i + 1`，越界则恢复为 `0`。

    * `decrement(i, capacity)`：`i - 1 >= 0` 就返回 `i - 1`，越界则恢复为 `capacity - 1`。

    * 这里没有用求模运算，而是自己写两个分支达到同样效果，这套思路借鉴自 JDK 的 `ArrayDeque`。

    ```java
    private int increment(int i, int capacity) {
        if (i + 1 < capacity) {
            return i + 1;
        }
        return 0;
    }

    private int decrement(int i, int capacity) {
        if (i - 1 >= 0) {
            return i - 1;
        }
        return capacity - 1;
    }
    ```

    * 所有加减索引的地方都要经过这两个方法：迭代器的指针不能直接写 `pointer++`，`peekLast` 也不能直接写 `array[tail - 1]`，因为 `tail` 为零时减一会得到 `-1`。

* **判满的两种距离算法**

    * `tail > head` 时，队列满的条件是 `tail - head == array.length - 1`，这时正着一减就知道距离。

    * `tail < head` 时正着数要绕一圈，改用 `head - tail`，满的条件是 `head - tail == 1`。

    * `head == tail` 说明队列是空的，`isFull` 返回 `false`。

    ```text
    状态一：tail > head    数组长度 4，容量 3
    下标:   0       1       2       3
           [ a ]   [ b ]   [ c ]   [ 空 ]
           head                      tail

           距离 = 3 - 0 = 3 = 4 - 1   →  满

    状态二：tail < head    同样放满
    下标:   0       1       2       3
           [ 空 ]   [ c ]   [ b ]   [ a ]
           tail    head

           正着从 head 数到 tail，绕一圈 = 3
           倒着从 tail 数到 head        = 1
           head - tail = 1              →  满
    ```

    * > **易错点**：`tail < head` 那一支为什么是 `head - tail == 1` 而不是数组长度减一？因为满的时候只放了 $N - 1$ 个元素，环上正好还剩一个空位，`head` 和 `tail` 只隔一格。

    ```java
    public boolean isEmpty() {
        return head == tail;
    }

    public boolean isFull() {
        if (tail > head) {
            return tail - head == array.length - 1;
        } else if (tail < head) {
            return head - tail == 1;
        } else {
            return false;
        }
    }
    ```

* **数组实现必须考虑内存释放**

    * 存基本数据类型时不需要处理：`100` 占四个字节，清零后的 `0` 也占四个字节，指针移开后访问不到那个格子就等于删掉了，本着多一事不如少一事的原则不做任何处理。

    * 存引用类型时必须把该格置 `null`：`head` 加一只说明「将来访问不到 `r1` 了」，`r1` 还躺在格子里引用着堆上的对象，GC 一看还有引用就永远收不掉。

    * 对象占用的内存是在垃圾回收时才回收的，只要有人引用它就释放不掉；栈、队列、双端队列都加了泛型，存的都是引用类型，所以删除元素时都要做这一下。

    ```text
    数组格子（数组自身占的内存）            堆上的对象（数组之外额外的空间）
     [r1]   [r2]   [r3]      ──引用──►     ( e1 )   ( e2 )
       └──────┴──────┘

    读图：数组格子里放的是引用（地址），通过它跟堆上的对象连起来。

    head 加一之后 ── 只是说「将来访问不到 r1 了」
                  ── 但 r1 还躺在格子里，仍然引用着 e1
                  ── GC 一看还有引用，e1 的内存永远收不掉

    只有把这一格置为 null，才没人引用 e1，它才能在 GC 时被回收
    ```

    * `pollFirst` 先把 `array[head]` 存到临时变量，再把该格置 `null`，最后推进 `head`；`pollLast` 先把 `tail` 减一，再取出该格的值并置 `null`。

    ```java
    public E pollFirst() {
        if (isEmpty()) {
            return null;
        }
        E e = array[head];
        array[head] = null;                     // 帮助 e 的内存被垃圾回收
        head = increment(head, array.length);
        return e;
    }

    public E pollLast() {
        if (isEmpty()) {
            return null;
        }
        tail = decrement(tail, array.length);
        E e = array[tail];
        array[tail] = null;                     // 帮助 e 的内存被垃圾回收
        return e;
    }
    ```

* **peek 与迭代器**

    * `peekFirst` 返回 `array[head]`；`peekLast` 返回 `array[decrement(tail, array.length)]`，因为 `tail` 本身不指向元素必须先退一格，而退格要交给 `decrement` 才不会出现 `-1`。

    * 迭代器的 `pointer` 从 `head` 起步，`hasNext` 判断 `pointer != tail`，`next` 先取 `array[pointer]` 再让 `pointer = increment(pointer, array.length)`。

    ```java
    public E peekFirst() {
        if (isEmpty()) {
            return null;
        }
        return array[head];
    }

    public E peekLast() {
        if (isEmpty()) {
            return null;
        }
        return array[decrement(tail, array.length)];
    }

    public Iterator<E> iterator() {
        return new Iterator<E>() {
            private int pointer = head;

            @Override
            public boolean hasNext() {
                return pointer != tail;
            }

            @Override
            public E next() {
                E value = array[pointer];
                pointer = increment(pointer, array.length);
                return value;
            }
        };
    }
    ```

* **数组版测试用例**

    * 容量 3：`offerFirst` 加 `1`，再 `offerFirst` 加 `2`，再 `offerLast` 加 `3`，结果是 `213`；再加第四个元素返回 `false`。

    * 容量 7：`offerLast` 加 `1 2 3` 得到 `123`，再 `offerFirst` 加 `4 5 6 7` 得到 `7654123`，此时已满，随后连续摘取：

    | 次序 | 调用 | 返回值 | 剩余队列（头 → 尾） |
    | :--- | :--- | :--- | :--- |
    | 起始 | — | — | `7654123` |
    | 1 | `pollFirst` | 7 | `654123` |
    | 2 | `pollFirst` | 6 | `54123` |
    | 3 | `pollLast` | 3 | `5412` |
    | 4 | `pollLast` | 2 | `541` |
    | 5 | `pollFirst` | 1 | `54` |
    | 6 | `pollLast` | 4 | `5` |
    | 7 | `pollFirst` | 5 | 空 |
    | 8 | `pollFirst` | `null` | 空（`isEmpty()` 返回 `true`） |

    * `peek` 用例：`offerFirst(1)`、`offerLast(2)`、`offerFirst(3)`、`offerLast(4)` 得到 `3 1 2 4`，`peekFirst` 返回 `3`，`peekLast` 返回 `4`。

## Z 字形层序遍历

* **Z 字形（Zigzag，蛇形）**

    * > **定义**：奇数层由左向右、偶数层由右向左交替进行的层序遍历。

    * 第一层是 `1`，第二层输出 `3 2` 而不是 `2 3`，第三层回到 `4 5 6 7`，第四层再反成 `9 8`，走的就是一个 Z 字。

    ```text
    树的层次（从左到右）        Z 字形输出
    第一层：  1                 →   1
    第二层：  2  3              →   3  2
    第三层：  4  5  6  7        →   4  5  6  7
    第四层：      8  9          →   9  8

    整串输出：1 | 3 2 | 4 5 6 7 | 9 8
    ```

* **沿用层序遍历的骨架**

    * 层序遍历的核心是一个队列暂存下一层的节点，外层 `while` 只要队列非空就说明还有层没处理，内层 `for` 把当前这一层的节点全部取出来塞进 `level`。

    * 内层循环就是用来区分二叉树中每一层数据的，每循环一次就把当前层数据放进一个叫 `level` 的集合，最终大集合里套着一一个个小 `level`。

    * 根节点为空说明树里没有数据，返回空集合即可。

* **只改一处：偶数层改从队头插入**

    * > **结论**：Z 字形层序遍历 = 层序遍历 + 一个奇偶标志 + 偶数层改从队头插入。

    * 原来的 `level` 用的是往集合尾部添加的方法，改成往头部添加就能把偶数层倒过来：先往头部加 `2`，再往头部加 `3`，`3` 就跑到了 `2` 的前面。

    * 布尔标志 `isOdd` 表示「当前是不是奇数层」，初始为 `true`（第一层是奇数层）：奇数层调 `offerLast`，偶数层调 `offerFirst`；每层结束后 `isOdd = !isOdd` 取反。

    * 不用 `ArrayList` 是因为它底层是普通数组，往尾部添加效率尚可，一遇偶数层要往头部添加效率就不高；双端队列不管往头加还是往尾加效率都高，写过的任一实现都行，JDK 的 `ArrayDeque` 也可以，而 `LinkedList` 本身就是双端队列。

    * > **易错点**：因为要用双端队列特有的往头部插的方法，`level` 就不能声明成普通的接口类型，要直接写成 `LinkedList`。

    * 内层 `for` 之前要先用 `int levelSize = queue.size();` 把当前层的节点个数固定下来。

    ```java
    public List<List<Integer>> zigzagLevelOrder(TreeNode root) {
        if (root == null) {
            return Collections.emptyList();
        }

        List<LinkedList<Integer>> result = new ArrayList<>();
        Queue<TreeNode> queue = new LinkedList<>();
        queue.offer(root);

        boolean isOdd = true;                     // 第一层是奇数层, 由左向右

        while (!queue.isEmpty()) {
            LinkedList<Integer> level = new LinkedList<>();
            int levelSize = queue.size();         // 先固定住当前层的节点个数

            for (int i = 0; i < levelSize; i++) {
                TreeNode node = queue.poll();
                if (isOdd) {
                    level.offerLast(node.val);
                } else {
                    level.offerFirst(node.val);
                }
                if (node.left != null) queue.offer(node.left);
                if (node.right != null) queue.offer(node.right);
            }

            result.add(level);
            isOdd = !isOdd;
        }

        return result;
    }
    ```

## 优先级队列

* **优先级队列**

    * > **定义**：同样是一端进一端出，但出队不再按进入的先后，而是按元素优先级出队，优先级高的先出来。

    | 队列 | 出队依据 | 典型场景 |
    | :--- | :--- | :--- |
    | 普通队列 FIFO | 谁先进来谁先出去 | 排队买票，先来后到 |
    | 优先级队列 | 谁优先级高谁先出去 | 任务调度，紧急任务先处理 |

    * 入队顺序跟出队顺序完全不一样：按任务 `1 2 3 4 5` 入队后，最先出队的是优先级 `5` 的任务四，其次是优先级 `4` 的任务一。

    * 常见有三种实现，基于数组的两种先讲完，第三种要用到一个新的底层数据结构。

* **元素类型必须实现 Priority 接口**

    * 队列元素不能是任意类型：不是所有对象都有「优先级」这个属性，所以放进优先级队列的元素必须实现自定义的 `Priority` 接口。

    * `Priority` 的作用是返回该元素的优先级，是一个整数，整数越大表示优先级越高。

    * 因此数组的类型声明成 `Priority` 而不是泛型 `E`，`peek` 与 `poll` 返回时要把结果强转成 `E`。

    * 判空判满：`size` 为零表示空，`size` 等于数组长度表示满；索引直接用 `0` 到 `size - 1`，不做环形那一套。

* **无序数组实现**

    * 入队就是往数组尾部追加，新加入元素的优先级跟原有元素之间没有任何顺序关系要维护。

    * 出队不能随便挑，得挑优先级最高的：遍历数组，`max` 记录当前最大值所在下标并假设初始为 `0`，`i` 从 `1` 开始每次循环向后加一，只要 `i` 指向的元素更大就把 `max` 更新成 `i`。

    * 在 `[4, 2, 1, 5, 10, 7, 3]` 上走一遍：`2`、`1` 都比 `4` 小不动 `max`，遇到 `5` 把 `max` 更新成索引 `3`，遇到 `10` 再更新成索引 `4`，最后的 `7` 和 `3` 都不够大，最大值的下标是 `4`。

    * 找到之后从数组里把这个元素删掉即可，后面的 `7` 和 `3` 都向低下移一格。

    * > **结论**：这轮出队查找相当于进行了一次选择排序。

    * `remove(int index)`：只有 `index < size - 1` 时才需要把后面的元素整体前移一格，保证数组元素的连续性；两种情况最终都要 `size--`。

    * 移位用 `System.arraycopy(array, index + 1, array, index, size - 1 - index)`，四个参数分别是原数组、起始位置、目的数组、目的起始位置、元素个数 `size - 1 - index`。

    * > **易错点**：`poll` 里千万别写成先 `remove` 再 `return array[max]`，删完之后上面的元素会顶上来取代那个位置，返回的根本不是优先级最高的那个元素；一定要先用临时变量 `e` 记录下来，删完再返回。

    ```java
    private int selectMax() {
        int max = 0;                    // 先假设零索引优先级最大
        for (int i = 1; i < size; i++) {
            if (array[i].getPriority() > array[max].getPriority()) {
                max = i;                // 比当前最大值大, 就更新下标
            }
        }
        return max;
    }

    private void remove(int index) {
        if (index < size - 1) {
            System.arraycopy(array, index + 1, array, index, size - 1 - index);
        }
        size--;
    }

    @Override
    public E poll() {
        if (isEmpty()) {
            return null;
        }
        int max = selectMax();
        E e = (E) array[max];           // 必须先记录, 再删除
        remove(max);
        return e;
    }
    ```

* **有序数组实现**

    * 数组元素保持有序，优先级越大的元素排在数组尾部。

    ```text
    无序数组：[4, 2, 1, 5, 10, 7, 3]      10 不知道在哪儿，得扫
    有序数组：[1, 4, 5, 8, 10]            最大值固定在尾部，直接拿
    ```

    * `peek` 就是取尾部这个优先级最高的元素，`return (E) array[size - 1];`；`poll` 先把尾部元素赋给临时变量，`size` 减一后就访问不到了。

    * 但光 `size` 减一不够，数组里存的 `10` 号对象还被引用着，应该在减一之后把 `size` 处的引用置为 `null`，将来 GC 才能把它占用的内存释放掉。

    * 两行可以合二为一：先减 `size`，再把 `size` 处的引用置 `null`，写成左减减就等价。

    * 入队要跑一次插入排序：先 `size++` 在末尾腾出一个坑，指针 `i` 从 `size - 1` 往 `0` 走，只要 `i >= 0` 且 `array[i]` 的优先级比待插入元素大，就把 `array[i]` 往后挪一位；循环退出后把待插入元素放到 `i + 1`。

    * 插优先级 `3` 时的移动过程：`10` 比 `3` 大后移一位，`8` 后移一位，`5` 后移一位，`4` 后移一位，比较到 `1` 时 `1` 比 `3` 小不再移动，于是 `3` 插入索引 `1`。

    * 边界情形：要插的元素比队列里所有元素都小时，`i` 会一路退到 `-1`，此时 `i + 1` 正好是 `0`，落在下标 0，这段代码对边界条件也没有问题。

    * > **提示**：`offer` 里是先 `size++` 再 `insert`，顺序不能反；`insert` 的扫描起点是 `size - 1`，只有先把坑位算进去它才知道要从后往前挪到哪儿，插完之后元素个数自然就加上了。

    ```java
    @Override
    public boolean offer(E e) {
        if (isFull()) {
            return false;
        }
        size++;                  // 先腾一个坑, 元素个数加一
        insert(e);               // 从 size - 1 往前找位置
        return true;
    }

    private void insert(E e) {
        int i = size - 1;
        for (; i >= 0 && array[i].getPriority() > e.getPriority(); i--) {
            array[i + 1] = array[i];    // 比我大的, 整体向后挪一位
        }
        array[i + 1] = e;               // i 退到 -1 时, 正好落在下标 0
    }

    @Override
    public E poll() {
        if (isEmpty()) {
            return null;
        }
        E e = (E) array[--size];   // 先减一, 再断开引用
        array[size] = null;         // 有助于垃圾回收
        return e;
    }
    ```

    * 两种实现的 `array` 属性、`size` 属性、判空判满方法、元素必须实现 `Priority` 接口这一约束完全一样，直接拷贝即可，不一样的只有 `offer`、`poll`、`peek` 三个方法。

* **两种实现的复杂度正好相反**

    | 实现 | 入队 offer | 出队 poll / 查看 peek |
    | :--- | :--- | :--- |
    | 无序数组 | $O(1)$ | $O(n)$ |
    | 有序数组 | $O(n)$ | $O(1)$ |

    * 无序数组出队要把 $n$ 个元素比较一遍才能找出最大值，复杂度压在出队上。

    * 有序数组的 `poll` 与 `peek` 总在取数组尾部元素是 $O(1)$，`offer` 最糟糕情况下要给每个元素比较一次，复杂度压在入队上。

    * > **结论**：这两种做法都不是最好的，一个把复杂度压在入队上，一个压在出队上，第三种实现要换一个底层数据结构。
