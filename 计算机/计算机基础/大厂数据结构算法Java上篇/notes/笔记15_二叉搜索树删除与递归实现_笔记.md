# 二叉搜索树：删除与递归实现

## 删除的四种形态

删除比查找和插入复杂，原因是被删除节点的孩子个数不确定；按孩子个数可以归成四种形态，前两种最简单、最后一种最复杂。

| 形态 | 被删除节点的孩子 | 处理思路 | 难度 |
| :--- | :--- | :--- | :--- |
| 情况一 | 没有左孩子 | 把右孩子托孤给父节点 | 简单 |
| 情况二 | 没有右孩子 | 把左孩子托孤给父节点 | 简单 |
| 情况三 | 左右都没有（叶子节点） | 被情况一、二涵盖 | 不用写额外代码 |
| 情况四 | 左右孩子都有 | 让后继节点顶替上去 | 最复杂 |

    * **叶子节点不需要单独写代码**

        * > **定义**：情况三（左右孩子都为空的叶子节点）已经被情况一和情况二完全覆盖。

        * 走情况一逻辑时右孩子是 `null`，把 `null` 托孤给父节点等价于让父节点的对应指针置空，结果正确。

        * 走情况二逻辑时左孩子是 `null`，把 `null` 托孤给父节点得到的是同一个结果。

        * > **结论**：写代码只考虑情况一、情况二、情况四；情况四放在最后的 `else` 里，前面的「等于 null」判断全部去掉，能走到 `else` 就说明左右孩子都有。

    * **单孩子节点的替换**

        * 被删除节点只有一个孩子时没有选择余地：唯一的孩子直接顶上去，占据被删除节点原来的位置。

        * 顶上去的节点带着自己原有的后代一起过来，后代的指针不需要改动。

        * 删除 3 的右孩子 4（4 无左孩子、右孩子是 7）：7 成为 3 的右孩子，7 的后代 9 跟着过来。

        * 删除 6 的右孩子 4（4 有左孩子 2、无右孩子）：2 成为 6 的右孩子，2 的后代 1、3 跟着过来。

    * **自测用例的走向**

        * 用例树形：`4` 的右孩子是 `7`，`7` 的左孩子是 `6`，`6` 的左孩子是 `5`，待删除节点是 `7`。

        * `7` 有左孩子无右孩子，命中情况二，走 `else if` 分支，把左孩子 `6` 顶上去。

        * `7` 原本是 `4` 的右孩子，所以 `6` 也作为右孩子顶上去，`5` 作为 `6` 的左孩子一起移动。

        * 删除后应与上述预期树形完全一致即视为通过；情况一与情况二完全对称，此处只演示情况二的测试用例。

## 托孤方法 shift

    * **托孤（shift）**

        * > **定义**：把 `child` 顶上去，占据 `deleted` 原来的位置。

        * 方法有三个参数：被删除节点的父亲 `parent`、被删除节点 `deleted`、被顶上去的节点 `child`。

        * `child` 的命名刻意用「被顶上去的节点」而不是「被删除节点的孩子」，因为在情况四里传进去的可能是被删除节点的孙子或重孙子。

        * `parent == null` 说明被删除节点就是根节点，此时令 `root = child`，让 `child` 成为新的根。

        * `parent != null` 时先判断 `parent.left == deleted`：成立则接左孩子，否则接右孩子；第二个判断可以省略，直接写成 `else`。

        * 这个方法有通用性，情况四里先后要用它两次。

        * > **结论**：托孤必须挂在同一侧——被删除节点原本是左孩子，接上去的也只能是左孩子，否则二叉搜索树的定义当场被破坏。放错侧会让本该更大的值出现在左侧或本该更小的值出现在右侧。

## 非递归删除的骨架

    * **delete(int k) 的契约**

        * > **定义**：参数是待删除节点的 `k`，返回值是被删除节点的 `value` 值。

        * 第一步从根开始找待删除节点，同时记下它的父节点。

        * 第二步判断是否真的找到，`p == null` 表示没找到，直接返回 `null`，后续删除也就无从谈起。

        * 第三步按四种形态执行删除，第四步返回被删除节点的 `value`。

    * **查找时顺带记录父节点**

        * `parent` 在循环外层定义，初始为 `null`。

        * 每次向左或向右走之前，先把当前 `p` 存进 `parent`；下次循环若命中待删除节点，`parent` 就是它的父亲。

        * > **易错点**：命中之后绝不能再写 `parent = p`。那样 `break` 之后 `parent` 与 `p` 指向同一个节点，取值完全一样，父子关系直接失效 ⚠️。代码里 `parent = p` 必须放在比较分支之前、`break` 之后不再赋值。

```java
public Node delete(int k) {
    // 第一步：从根开始找待删除节点，同时记下它的父节点
    Node p = root;
    Node parent = null;
    while (p != null) {
        if (p.value == k) {
            break;
        }
        // 要向左/向右走了，走之前先把当前节点记成 parent
        parent = p;
        if (p.value > k) {
            p = p.left;
        } else {
            p = p.right;
        }
    }

    // 第二步：判断一下这个节点是不是真的找到了
    if (p == null) {
        return null;
    }

    // 第三步：找到了，执行删除操作（下面分四种情况）
    // 第四步：返回被删除节点的 value 值
}
```

    * **情况一与情况二只是两次托孤**

        * 第一个参数传被删除节点的父节点 `parent`，第二个参数传被删除节点 `p`，第三个参数传要顶上去的那个孩子。

        * 情况一：`p.left == null` 时把 `p.right` 顶上去；情况二：`p.right == null` 时把 `p.left` 顶上去。

        * 两种情况合起来已经把叶子节点也处理掉了，不必再补分支。

        * 非递归版本代码量不大，性能比递归版本更好。

```java
    if (p.left == null) {
        // 情况一：删除节点没有左孩子，把右孩子托孤顶上去
        shift(parent, p, p.right);
    } else if (p.right == null) {
        // 情况二：没有右孩子，但是有左孩子，把左孩子顶上去
        shift(parent, p, p.left);
    }
```

## 后继顶替的情况四

    * **情况四的三个步骤**

        * > **定义**：被删除节点左右孩子都有时，先找到后继节点，再判断要不要先清理后继的后事，最后用后继取代被删除节点。

        * 第一步找后继；第二步若后继与被删除节点不相邻，先让后继把后事处理干净；第三步后继顶替被删除节点。

        * 之前的「托孤」策略在这里用不上，因为有两个孩子可选，必须显式选一个。

        * 整个过程里 `shift` 会被调用两次：一次用来清理后继的后事，一次用来让后继顶替被删除节点。

### 找后继节点

    * **后继的通用定义**

        * > **定义**：后继节点（successor）就是比被删除节点大的那些节点中最小的那个。

        * 通用的找法有两条：节点有右子树时，后继是右子树中的最小值；没有右子树时，到祖先里找自左向右的那个祖先。

        * 情况四里不需要第二条：能进入情况四就证明被删除节点既有左子树又有右子树，后继一定在右子树里，只需一路向左走到头。

        * 之前写过的完整找后继代码并不是每段都能用上，这里只用到前半部分。

    * **沿左链一路走到底**

        * 后继变量 `s` 的起点是被删除节点的右孩子 `p.right`。

        * 用 `sParent` 记录 `s` 的父亲，初始值就是被删除节点 `p`，每次循环都更新成上一轮的 `s`。

        * 循环条件是 `s.left != null`，为真就把 `s` 换成 `s.left`；循环结束时 `s` 就是后继，`sParent` 是它的父亲。

        * 示例：`4` 的右孩子是 `8`，`8` 的左孩子是 `7`，`7` 的左孩子是 `5`。`s` 依次取 `8`、`7`、`5`，`sParent` 依次取 `4`、`8`、`7`，`5` 的 `left` 为空，走到底。

```java
    // 找后继节点：p 的右子树里的最小值
    Node s = p.right;
    Node sParent = p;          // s 的父亲，初始值就是被删除节点 p
    while (s.left != null) {
        sParent = s;
        s = s.left;
    }
```

### 相邻判定与清理后事

    * **用后继的父亲判定相邻**

        * 后继是从被删除节点的右子树开始找的，所以一开始 `s` 的父亲就是被删除节点 `p`。

        * 循环结束后若 `sParent` 仍然是 `p`，说明后继恰好是被删除节点的右孩子，两者相邻，让它直接顶上去即可。

        * 若 `sParent` 不再是 `p`（例如变成了 `7`），说明后继藏在右子树更深处，两者不相邻，必须先清理后事。

    * **不相邻时的清理动作**

        * 把后继 `s` 当成待删除节点，复用 `shift` 把它从原位置摘掉，让它的右孩子顶上去。

        * 调用形式是 `shift(sParent, s, s.right)`：父亲传 `sParent`，被删节点传 `s`，顶上去的传 `s.right`。

        * 这一步做完，后继才腾出手来接管被删除节点的位置。

        * > **结论**：不相邻时必须「先删后接」，顺序是死的——先把后继的后事处理干净，再让后继顶上去。

```java
    // sParent != p，说明后继跟被删除节点不相邻
    if (sParent != p) {
        // 不相邻：先把后继的后事处理干净
        // 把后继从它原来的位置摘掉，让它的右孩子顶上去
        shift(sParent, s, s.right);
    }
```

### 后继不可能有左孩子

    * **只有右孩子可托**

        * > **定义**：后继是右子树里的最小值，因此它不可能有左孩子——左孩子一定比它更小，那就不是最小值了。

        * 代码能执行到这一段就说明后继必然只有右孩子，可以放心把右孩子传上去。

        * 不存在「让后继的左孩子顶上去」这种可能，所以传给 `sParent` 的只能是 `s.right`。

        * 后继没有左孩子，恰好是它的左指针在接管被删除节点左子树时可以直接覆盖的原因。

    * **它决定了接指针的方式**

        * 相邻时后继的右指针原本就指向被删除节点的右子树，可以原样带上来，不必改。

        * 不相邻时后继的右孩子已经被清理掉交给 `sParent`，右指针必须重新指向被删除节点的右孩子。

        * 左指针两种情况都要改，一律指向被删除节点的左孩子。

### 顶替与指针改接

    * **顶替动作还是托孤**

        * `shift` 只改 `parent` 的两个指针之一，不会动顶上去的那个节点的左右指针，所以顶替之后还要手工接一遍。

        * 调用 `shift(parent, p, s)`：父亲是被删除节点的父节点，被删的是 `p`，顶上去的是后继 `s`。

        * 之后 `s.left = p.left`，让后继的左指针接住被删除节点的左子树。

        * 相邻时 `s.right` 不用动——它原本的右指针直接跟着带上来就是被删除节点的右子树。

        * 不相邻时 `s.right` 必须改成 `p.right`：原来后继的右孩子已经被清理掉、交给 `sParent` 了，这里要重新指向被删除节点的右孩子。

```java
    // 步骤三：后继顶替掉被删除节点
    shift(parent, p, s);

    // 然后把后继节点自己的左右指针接好
    s.left = p.left;
    s.right = p.right;
```

    * **不相邻的完整流程**

        * 找后继得到 `s = 5`、`sParent = 7`；清理后事 `shift(7, 5, 6)`，`6` 顶上 `5` 的位置。

        * 顶替 `shift(parent, 4, 5)`，再接指针 `s.left = 2`、`s.right = 8`，后继 `5` 接管 `4` 的位置。

```text
  找后继：8 --left--> 7 --left--> 5，得到 s = 5, sParent = 7

  清理后事：shift(7, 5, 6)

          4                  4
         / \                / \
        2   8              2   8
           / \                / \
          7   9              7   9
         /                  /
        5                  6        <- 6 顶上 5 的位置

  顶替：shift(parent, 4, 5)，再接指针 s.left = 2、s.right = 8

          4                  5        <- 后继 5 顶替了 4
         / \                / \
        2   8              2   8
           / \                / \
          7   9              7   9
         /                  /
        5                  6
         \
          6
```

## 为什么必须让后继顶替

    * **不能让右子树里的 6 顶上去**

        * 被删除节点是 `4`，两个孩子是 `2` 和 `8`，候选的后继是 `5`。

        * 二叉搜索树要求节点左边的值都更小、右边的值都更大。

        * 把 `6` 放上去后，它的右边会出现 `5`、`7`、`8`、`9`，其中 `5` 比 `6` 小却出现在它右侧，直接破坏二叉搜索树的特性。

        * 后继顶上去不会破坏特性，因为它本来就是右子树里最该待在这个位置的节点。

    * **换用前任也可以**

        * 从被删除节点的左子树里找一个前任节点来替换，思路是成立的。

        * 但代码要做相应调整：找最大值还是找最小值的方向要换，左右指针的执行顺序也要跟着改。

        * 代码总量与用后继时一样，但找最大值还是找最小值、左右指针执行的顺序都要跟着改；这里只给出后继方案，前任方案留作题外延伸。

## 递归版删除的返回值语义

    * **返回值就是删剩下的孩子**

        * > **定义**：递归版 `delete` 的返回值是删除后剩下的那些孩子节点；找到了就返回删剩下的孩子，没找到就返回 `null`。

        * 递归删除的关键点是把被删除节点从整棵树中断开，断开的方式就是把它的孩子返回上去。

        * 删除 6 时若它只有一个孩子 7，就返回 7；返回过程中上一层把 6 的父亲的 `right` 指向这个新的 7，6 就被从中间断开了。

        * 父子关系由上一层递归调用建立：`node.left = delete(node.left, key)` 或 `node.right = delete(node.right, key)`，接住返回值。

    * **入口与内部方法要分开**

        * 对外暴露的 `delete` 只是一层壳，起点传根节点。

        * 内部递归方法的第一个参数是本次递归的删除起点，随递归不断变化（可能是根，也可能是下一层的左孩子或右孩子）。

        * 起点为 `null` 表示找到头了、没找到，直接返回 `null`，无需继续定位。

```java
// 对外暴露的删除入口
public Node delete(int key) {
    return delete(root, key);        // 起点就是根节点
}

// 内部递归方法：node 是本次递归的删除起点
private Node delete(Node node, int key) {
    if (node == null) {
        return null;                 // 既然都没找到，那剩下的也是 null
    }

    if (key < node.value) {
        node.left = delete(node.left, key);
    } else if (key > node.value) {
        node.right = delete(node.right, key);
    }

    return node;
}
```

    * **找到之后仍是那四种形态**

        * 能走到比较结果相等的分支，说明当前 `node` 就是被删除节点。

        * 情况一：`node.left == null` 时返回 `node.right`；情况二：`node.right == null` 时返回 `node.left`。

        * 情况四：在右子树里找后继顶上去，顶上去后要把后继的左孩子改成被删除节点的左孩子，最后返回后继。

        * 父子关系不需要在这一层操心，上一次递归调用已经用返回值帮它建立好了。

        * 这段初版代码只处理了「后继与被删除节点相邻」的情况。

```java
    if (node == null) {
        return null;
    }

    if (key < node.value) {
        node.left = delete(node.left, key);
    } else if (key > node.value) {
        node.right = delete(node.right, key);
    } else {
        // 找到了，按四种情况处理
        if (node.left == null) {
            return node.right;       // 情况一：只有右孩子
        } else if (node.right == null) {
            return node.left;        // 情况二：只有左孩子
        } else {
            Node s = node.right;     // 情况四：右子树里的最小值作为后继
            while (s.left != null) {
                s = s.left;
            }
            s.left = node.left;      // 后继接住被删除节点的左子树
            return s;
        }
    }

    return node;
```

## 递归版的不相邻修正

    * **初版漏掉的分支**

        * 初版只做了 `s.left = node.left` 就把 `s` 返回，而 `s` 原本还有一个右孩子 6。

        * 直接返回的结果是整棵树只剩 `5`、`2`、`6`，被删除节点原来的右孩子 `8`、`7`、`9` 整条链全部丢失。

        * 根因是没有处理「后继与被删除节点不相邻」这一类，后继的右孩子还挂在被删除节点的右子树里没摘掉。

    * **在右子树里再递归一次**

        * 把被删除节点的右子树当成新起点，再递归删除一次后继本身。

        * 起点传 `node.right`，待删的键传后继的 `s.key`，相当于在「以右孩子为根的子树」里删掉后继，返回的就是那棵以右孩子为根的子树。

        * 返回值接到 `s.right` 上，后继的后事才算处理干净。

```java
    // 先删：把后继的后事处理干净
    Node rest = delete(node.right, s.key, new ArrayList<Object>());
    // 再接
    s.left = node.left;
    s.right = rest;
    return s;
```

    * **先删后接，顺序不能颠倒**

        * > **易错点**⚠️：这两行只有一种合法顺序——先 `delete` 再赋 `left`。反过来写，等于在待删节点上凭空挂出一个新孩子，删除逻辑立刻失真。

        * 如果先给后继的 `left` 赋成被删除节点的左孩子，那么接下来在右子树里删后继时，后继就变成了两个孩子，干扰了删除动作。

        * 正确做法是在后继只有一个孩子的情况下先删掉它，删完之后再把它的左孩子改成被删除节点的左孩子。

    * **顶层必须重新赋值给 root**

        * 调完递归方法后还要做一次赋值，把返回结果重新给 `root`。

        * 删除根节点时返回的就是后继节点，不接住它，根就停留在已经被删掉的旧节点上。

        * 这一步不能省，它和递归层里 `node.left = delete(...)` 是同一件事，只是发生在最外层。

```text
   初始                错误做法：直接返回 s        正确做法：先在 8 子树里删 5

        4                       5                           5

    /     / \                     ← 8、7、9 没了            / \
   1     7   9                                              7   9
        /                                                      /
       5                                                     6

         6
```

## 递归 delete 的完整通用实现

    * **一个返回值不能代表两种含义**

        * 对外的 `delete` 要求返回被删除节点的 `value`，内部递归方法返回的是「删剩下的」，两种语义必须分开。

        * 解法是再加一个参数 `ArrayList<Object> result`（值的类型是 `Object`，所以容器泛型也是 `Object`），专门用来往外送被删除节点的值。

        * 执行到「找到了」这一步时，把当前 `node` 的 `value` 加进 `result`；整个递归过程必须传同一个集合。

        * 删除后继节点时需要另一个集合，不能复用 `result`，因为后继的值不是要返回的那个值，直接新建一个用不上就丢。

        * 递归结束后 `result` 为空表示没找到，返回 `null`；找到了则 `result` 里只有一个结果，取零号位返回。

    * **三个参数各司其职**

        * > **提示**：第一个参数是遍历起点，所以内层递归才能传 `node.right`；第二个参数是这一层要找的键，所以内层传的是 `s.key`；第三个参数是唯一用来往外送被删值的通道。返回值和结果容器，一件事只干一样。

    * **完整代码**

```java
// 对外暴露的方法：起点是根，返回被删除节点的 value
public V delete(K k) {
    ArrayList<Object> result = new ArrayList<Object>();
    this.root = delete(this.root, k, result);
    if (result.isEmpty()) {
        return null;                       // 没找到
    }
    return (V) result.get(0);              // 找到了，只有一个
}

// 递归方法：返回的是"删剩下的"，起点 + k + 回传被删值的容器
private BSTNode<K, V> delete(BSTNode<K, V> node, K k, ArrayList<Object> result) {
    if (node == null) {
        return null;
    }
    if (k.compareTo(node.key) < 0) {
        node.left = delete(node.left, k, result);
    } else if (k.compareTo(node.key) > 0) {
        node.right = delete(node.right, k, result);
    } else {
        // 找到了，把被删除节点的 value 记进 result
        result.add(node.value);

        // 情况一：没有左孩子，右孩子直接顶上去
        if (node.left == null) {
            return node.right;
        }
        // 情况二：没有右孩子，左孩子直接顶上去
        if (node.right == null) {
            return node.left;
        }

        // 情况三：左右孩子都在，找后继顶上去
        BSTNode<K, V> s = node.right;                 // 起点 = 当前节点的右子树
        while (s.left != null) {
            s = s.left;                                // 顺着左链找到后继
        }
        // 先删：把后继的后事处理干净，这里用的是全新的集合，用不上就丢
        BSTNode<K, V> rest = delete(node.right, s.key, new ArrayList<Object>());
        // 再接：顺序反了就会给待删节点造出一个新孩子
        s.left = node.left;
        s.right = rest;                                // rest 就是那棵以右孩子为根的子树
        return s;
    }
    return node;
}
```

    * **两个版本的取舍与测试**

        * 递归版代码更简洁，思路一眼可见；非递归版稍复杂，但性能更好。

        * 沿用针对非递归版写过的那套测试用例，递归版要跑通四组：删除叶子节点 `1`、`3`、`5`、`8`；只有一个孩子的情况；有两个孩子且后继与被删除节点不相邻；有两个孩子且相邻。

        * 这四组都通过，说明递归实现把四种形态全部跑通了。

## 范围查询

范围查询只需要在中序遍历上加条件：二叉搜索树的中序遍历天然是升序结果，遍历过程中天然能判断大于、小于、大于等于、小于等于，有选择地把节点值收进结果集合即可。

| 方法 | 传参 | 收集哪些节点 | 能否提前结束 |
| :--- | :--- | :--- | :--- |
| `less` | `k` | 值 `< k` 的所有节点 | 能，遇到第一个不小于 `k` 的就停 |
| `greater` | `k` | 值 `> k` 的所有节点 | 中序不能，改反向中序才能 |
| `between` | `k1`、`k2` | `k1 ≤ 值 ≤ k2` 的所有节点 | 能，遇到第一个 `> k2` 的就停 |

    * **三个方法的契约**

        * `less`：给一个 `k`，把所有比 `k` 小的节点值装进一个集合返回。

        * `greater`：给一个 `k`，把所有比 `k` 大的节点值装进一个集合返回。

        * `between`：给 `k1`、`k2`，找大于等于 `k1` 且小于等于 `k2` 的所有节点值。

        * > **易错点**：`between` 是**含边界**的 ⚠️。找 3 到 5 之间时 `3`、`4`、`5` 三个都要，`1`、`2` 不要，`6`、`7` 不要，期望值是 `[3, 4, 5]` 而不是 `[4]`。

        * 「小于等于」「大于等于」这两个变体属于自行扩展的部分。

    * **实现方式：用迭代而不是递归**

        * 栈用 `LinkedList` 来充当，指针 `p` 起点是根节点。

        * 循环条件是 `p != null` **或** 栈不为空：`p != null` 表示还没向左走到头，该向前进；`p == null` 表示走到头了，该向回走，而向回走时栈不会空。两个条件是「或」的关系，任一满足就说明遍历没结束。

        * 向前进：`stack.push(p)` 记录路径，然后 `p = p.left`。

        * 向回走：`stack.pop()` 弹栈，处理当前值，再 `p = pop.right` 沿右指针继续，形成「左、值、右」。

        * 后序遍历不能直接弹栈，得先判断右子树遍历完没有；当前是中序，可以直接弹。

        * 这段架子写好后，`greater` 与 `between` 直接复制两份即可，不必重头写。

```text
        ┌────────────────────────────────────────────┐
        │  循环条件： p != null  或  栈不为空          │
        └────────────────────────────────────────────┘
                    │              │
         p != null  │              │  p == null
        （向前进）   │              │（向回走）
                    ▼              ▼
          push(p); p = p.left   s = stack.pop()
          记录路径，压栈              │
                                    ▼
                          处理值：跟传入的 k 比较
                                    │
                                    ▼
                              p = s.right
                          （右指针继续向前进）
```

    * **less 与 between 的提前结束**

        * `less` 在中序骨架里判断：弹出的值小于 `k` 就收进 `result`，否则立刻 `break`。

        * 中序是升序，一旦当前值已经不小于 `k`，后面所有值只会更大，继续走纯属浪费，这个 `break` 就是 `less` 能提前结束的全部秘密。

        * `between` 要同时判断大于等于 `k1` 且小于等于 `k2`，两个条件都满足才收进集合。

        * `between` 的退出条件是弹出的值已经大于 `k2`；遍历到 6 而 `k2` 是 5 时就可以退出。

        * `greater` 用中序实现时**不能提前结束**，必须遍历完整棵树，只能不断加入，不能加 `break`。

    * **greater 改用反向中序**

        * > **定义**：反向中序遍历（右、值、左）在二叉搜索树上产出的是**降序**结果。

        * 降序下只要碰到第一个小于等于 `k` 的值就可以退出，后面的值只会更小。

        * 深度优先遍历有前序、中序、后序三种（左或右在前、值在中、左右或右左的差别），与之对应也有反向前序、反向中序、反向后序三种，区别就是把左右顺序颠倒。

        * 反向中序与中序的代码是对称的：入栈方向由左换成右，弹栈后处理值、处理完继续走的子树由右换成左。

        * 示例树上的入栈顺序：中序是 `4 → 2 → 1`，反向中序是 `4 → 8 → 9`。

| 遍历方向 | 二叉搜索树上的输出 | 能不能提前停 | 适合谁 |
| :--- | :--- | :--- | :--- |
| 中序（左 → 右） | 升序 | 只有 `less`、`between` 能 | 找小的、找中间的 |
| 反向中序（右 → 左） | 降序 | `greater` 能 | 找大的 |

    * **三个方法的测试期望值**

        * 测试树的值是 1 到 7，`less` 传入 `k` 等于 6，期望结果是 `1`、`2`、`3`、`4`、`5`。

        * `greater` 传入 `k` 等于 6，比 6 大的只有 7，期望结果是 `7`。

        * `between` 查 3 到 5 之间，因为含边界，期望结果是 `3`、`4`、`5`。

        * 用 `assertTrue(...equals(...))` 比较两个集合是否相等，而不是打印结果。

```java
public List<V> greater(K k) {
    BSTNode<K, V> p = this.root;
    LinkedList<BSTNode<K, V>> stack = new LinkedList<BSTNode<K, V>>();
    List<V> result = new ArrayList<V>();

    while (p != null || !stack.isEmpty()) {
        if (p != null) {                         // 向前进：压栈 + 右移
            stack.push(p);
            p = p.right;                         // ← 与 less 的唯一区别
        } else {                                 // 向回走：弹栈，处理值，左移
            BSTNode<K, V> pop = stack.pop();
            if (pop.value.compareTo(k) > 0) {
                result.add(pop.value);
            } else {
                break;                            // 降序走到头了，后面只会更小
            }
            p = pop.left;                         // ← 与 less 的唯一区别
        }
    }
    return result;
}
```

## 力扣三题对照

    * **节点定义的差异**

        * 例题里的 `BTNode` 有三个属性：`val`、`left`、`right`。

        * 泛型的 `BSTNode` 有四个属性：`key`、`value`、`left`、`right`，键唯一不重复、值可以是任意类型。

        * 力扣的 `TreeNode` 只有一个数值属性 `val`，既当键又当值，键值没有分开。

        * 做题时允许适当简化：需要比较大小或比较待删除的键时，直接拿 `val` 与 `key` 比即可。

### 删除二叉搜索树中的节点

    * **与例题的三点对应**

        * `root` 是删除的起点，`key` 是待删除的键。

        * 第一个 `if`（`key < root.val`）和第二个 `if`（`key > root.val`）表示还没找到，按大小关系继续往左或往右递归。

        * 返回值代表「删剩下的」节点，它与当前节点（也就是被删除节点的父亲）之间的父子关系，就是由这两行赋值建立的。

    * **三种处理的写法**

        * 情况一：只有右孩子（或左右都没有），返回 `root.right`，等价于把当前节点断开。

        * 情况二：只有左孩子，返回 `root.left`，父子关系同样由上一层赋值建立。

        * 情况三：两个孩子都有，先在右孩子为起点、顺着左链找到后继，再递归调用一次把后继从原位置摘掉，让后继接走被删节点的左子树，最后返回后继作为新的返回。

```java
class Solution {
    public TreeNode deleteNode(TreeNode root, int key) {
        if (root == null) {                      // 递归边界：没得找了
            return null;
        }
        if (key < root.val) {                   // 没找到，继续往左递归找
            root.left = deleteNode(root.left, key);
        } else if (key > root.val) {            // 没找到，继续往右递归找
            root.right = deleteNode(root.right, key);
        } else {
            // 到这儿说明 root.val == key，就是被删除节点
            if (root.left == null) {             // 情况一：只有右孩子（或左右都没有）
                return root.right;
            }
            if (root.right == null) {            // 情况二：只有左孩子
                return root.left;
            }
            // 情况三：两个孩子都有
            TreeNode s = root.right;             // 先在后继候选区里找后继
            while (s.left != null) {
                s = s.left;
            }
            s.left = deleteNode(root.left, s.val);   // 后继接走被删节点的左子树
            return s;                                // 后继顶上来，当新的返回
        }
        return root;
    }
}
```

### 新增节点

    * **题目前提砍掉了更新分支**

        * 课堂例题的 `put` 分两种情况：`k` 已存在就更新值，`k` 不存在才新增。

        * 力扣这道题做了简化，只考虑新增，因为题目前提保证传进来的 `value` 与树中已有节点的值一定不同。

        * 因此不可能走到「相等」那个分支，也就不需要写更新逻辑。

    * **递归版的查找与落子**

        * > **定义**：思路就是不断比较、不断往左或往右往下钻，直到遇到一个 `node == null` 的空位，在那里创建新节点。

        * `value` 小于当前节点的值就递归到 `node.left`；大于就递归到 `node.right`。

        * 找到空位时直接 `return new BSTNode<>(key, value)`，靠返回值把新节点交给上一层。

        * 上一层用 `node.left = put(node.left, key, value)` 或 `node.right = ...` 接住返回值，父子关系就在这一步建立。

        * 方法末尾必须有 `return node`，否则后两个分支缺少返回值、语法不通过。

    * **递归写法的代价**

        * 查找路径上的所有节点都会被重新赋值一次，比如把 `2` 返回上去后上一层会执行 `5.left = 2`。

        * 但 `2` 与 `5` 本来就是父子关系，这次赋值是多余的。

        * 非递归实现没有这个问题；递归写法因为返回值必须往下传，多出来的复制动作只能接受。

```java
private BSTNode<K, V> put(BSTNode<K, V> node, K key, V value) {
    if (node == null) {                        // 找到空位了，落子
        return new BSTNode<K, V>(key, value);
    }
    if (key.compareTo(node.key) < 0) {
        // 往左走，并把新节点接到当前节点的左孩子上
        node.left = put(node.left, key, value);
    } else {
        // 往右走，并把新节点接到当前节点的右孩子上
        node.right = put(node.right, key, value);
    }
    return node;                               // 语法上必须有个返回值
}

public BSTNode<K, V> put(K key, V value) {
    BSTNode<K, V> node = this.root;
    node = put(node, key, value);              // 顶层接一次
    if (node != null) {
        this.root = node;
    }
    return this.root;
}
```

### 搜索目标节点

    * **只查找、不改树形**

        * 给定 `target`，小于当前节点值就递归向左找，大于就递归向右找，相等就返回当前节点。

        * 每一层只做一次比较就决定往哪边递归，命中即返回，不需要像删除那样回接指针。

        * 这道题与课堂例题的 `get` 方法是同一件事。

    * **终止条件**

        * 一路走到空节点还不相等，说明树里没有它，返回 `null`。

        * 节点本身为空时同样直接返回 `null`，它同时充当递归边界和未命中的返回值。

```java
class Solution {
    public TreeNode searchBST(TreeNode root, int target) {
        if (root == null) return null;
        if (root.val == target) return root;
        if (target < root.val) {
            return searchBST(root.left, target);
        } else {
            return searchBST(root.right, target);
        }
    }
}
```
