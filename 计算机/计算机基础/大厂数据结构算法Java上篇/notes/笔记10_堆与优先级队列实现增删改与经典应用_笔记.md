# 堆与优先级队列：实现、增删改与经典应用

## 堆的存储地基

* **完全二叉树（Complete Binary Tree）**

    * > **定义**：除了最后一层以外每一层都得填满，而且填充的顺序要由左向右。

    * 堆就是一棵完全二叉树，只是不真的建树，而是用数组按层序把这棵树压平了。

    * 大顶堆的成立条件只有一条：父子之间处处满足「父 ≥ 子」。

    * 末尾追加不可跳格：左边没填满就不能去填右边，所以新元素只能加到数组末尾，不能跳着加到更靠后的索引。

    ```text
              7                    [0] = 7
            /   \
           6     5                 [1] = 6    [2] = 5
          / \   / \
         3   2 1   4               [3] = 3  [4] = 2  [5] = 1  [6] = 4
    ```

* **索引公式**

    * $left = 2 \times parent + 1$，$right = 2 \times parent + 2$。

    * $parent = \left\lfloor \frac{child - 1}{2} \right\rfloor$，Java 的整数除法本身就是向下取整，不用再调 `floor`。

    * `right` 直接用 `left + 1` 求出更划算：一次加法比一次乘法效率高。

* **上浮与下潜**

    * 上浮（`up`）只沿父链比，下潜（`down`）只沿子链比；每往下一层，能比较的元素就少一半，所以比较次数是对数级的。

    * 这两个动作是堆所有增删改接口的地基，其余方法都是它们的组合。

## 用大顶堆实现优先级队列

### 选型理由

* **大顶堆（Max Heap）选型理由**

    * > **定义**：大顶堆是根节点为当前最大元素的完全二叉树，用数组存储时根就是索引 `0`。

    * 理由一：队首要出队的元素是优先级最高者，它就摆在索引 `0`，**不用找**，位置是已知的。

    * 理由二：把根从数组里删掉的代价是对数级的。

### 入队 offer 的占坑与上浮

* **`offer`：占住末尾的坑，再一路往上顶**

    * 先判满，满了直接 `return false`。

    * 入队前末尾位置就是 `size`，所以 `child` 的初值等于 `size`；操作全部完成后 `size` 再自增。

    * > **易错点**：新元素**先别往坑里塞**。正确做法是只移动父亲、自己最后再落位；否则父亲下沉的那一步会把刚放进去的元素覆盖掉。

    * 循环条件：只要新元素优先级高于父元素，就把父元素的值挪到 `child`；随后 `child = parent` 上移，`parent` 按公式重算。

    * 终止条件有两个：新元素优先级小于等于父元素，或者 `child` 已经等于 `0`（浮到堆顶）。

    ```java
    // offer：向堆中添加一个元素
    public boolean offer(E e) {
        if (isFull()) {
            return false;
        }

        // 记录新元素将要落位的坑位，先不真正填入
        int child = size;
        size++;

        // Java 整数除法直接向下取整，不用再调 floor
        int parent = (child - 1) / 2;

        // 一路上浮：父亲比新元素小，就把父亲压下去
        while (child > 0 && priority(e) > priority(queue[parent])) {
            queue[child] = queue[parent];   // 父元素向下移动
            child = parent;                  // 坑位上移，接着跟上一层父亲比
            parent = (child - 1) / 2;
        }

        queue[child] = e;
        return true;
    }
    ```

    * 走一遍插入 `4`：先跟父亲 `3` 比，`3` 被换下去；再跟 `19` 比，`19` 更大，停，`4` 落在索引 `4`。

    * 走一遍插入 `200`：依次把 `4`、`19`、`100` 压下去，`200` 停在索引 `0`，因为没有更上一层的父亲了。

    ```text
    插入 4 之后：                 再插入一个更大的 200：

            100 (0)                    200 (0)
           /      \                    /      \
       19 (1)    36 (2)            19 (1)    36 (2)
        /  \     /   \              /  \      /   \
      ? (3) 4 (4) ? ?            ? (3) 100 (4) ?   ?
                 /                             /
              3 (9)                          4 (9)
    ```

### 出队 poll 的交换与下潜

* **`poll`：先和末尾换一下，再从堆顶一路下潜**

    * 第一步：把堆顶元素和最后一个元素交换，让数组尾部那个被换下来的元素承担被移除的角色。

    * 交换的目的是效率：数组尾部移除只要 `size` 减一，是 $O(1)$；直接从中间删要把后面元素整体往前挪，是 $O(n)$。

    * 第二步：刚换上来的尾部元素不满足大顶堆，从索引 `0` 开始下潜。

    * 下潜的每一步只跟两个孩子里**较大的那个**交换，重复直到它比两个孩子都大或者没有孩子为止。

    ```text
    第一步：堆顶与末尾交换             第二步：7 一路下潜

              7 (0)                            36 (0)
            /       \                         /       \
       19 (1)      36 (2)                 19 (1)       7 (2)
                              -->      /    \       /     \
                            ? (5)  ? (6)     ? (3)  ? (4)  25 (5) ? (6)
                                                                       |
                                                                   25 没有孩子，停
    ```

* **`down` 只认「较大者索引变了没有」**

    * `max` 初值先**假设**是 `parent`，再依次拿左孩子、右孩子跟它比，谁更大就把 `max` 更新成谁。

    * 只要 `max != parent` 就说明 `max` 被更新过，把二者交换并对 `max` 递归下潜；若两个孩子都不比父亲大，`max` 保持不变，递归自然终止。

    * > **易错点**：算出来的左右孩子不一定存在。`left` / `right` 超出有效索引范围时必须跳过比较，所以两个 `if` 都要带上 `left < size`、`right < size` 的前置条件。

    ```java
    // down：从 parent 开始，把父元素一路往下潜
    private void down(int parent) {
        int left = parent * 2 + 1;
        int right = left + 1;          // 用加法代替乘法，效率更高

        // 先假设父元素最大
        int max = parent;

        if (left < size && priority(queue[left]) > priority(queue[max])) {
            max = left;
        }
        if (right < size && priority(queue[right]) > priority(queue[max])) {
            max = right;
        }

        if (max != parent) {
            swap(parent, max);
            down(max);                // 换上来的那个位置，接着往下潜
        }
    }

    // poll：移除优先级最高的元素
    public E poll() {
        if (isEmpty()) {
            return null;
        }

        // 与末尾交换，让优先级最高的元素挪到数组尾部
        swap(0, size - 1);
        size--;

        E e = queue[size];    // 暂存出队的元素
        queue[size] = null;   // 置为 null 有助于垃圾回收

        down(0);              // 从堆顶重新下潜，恢复大顶堆
        return e;
    }

    // swap：交换数组中两个索引位置的值
    private void swap(int i, int j) {
        E t = queue[i];
        queue[i] = queue[j];
        queue[j] = t;
    }
    ```

### peek 与出队顺序

* **`peek` 只看堆顶**

    * 空队列返回 `null`；否则直接返回索引 `0` 的元素。

* **入队顺序任意，出队顺序一定从高到低**

    * 无论以什么顺序 `offer`，`poll` 出来的必然是优先级最高的先出，然后依次递减——这是大顶堆给优先级队列的保证。

### 三种实现的效率账

* **三种实现的效率账**

    | 实现方式 | 入队 offer | 出队 poll |
    | :--- | :--- | :--- |
    | 无序数组 | —— | $O(n)$：比较 n 个元素，挑出优先级最大的 |
    | 有序数组 | $O(n)$：插入排序，最坏比较 n 次 | —— |
    | 大顶堆 | $O(\log n)$：只沿父链一路比 | $O(\log n)$：只沿子链一路下潜 |

    * 无序数组短板在出队，有序数组短板在入队，堆把两个短板同时补齐。

    ```text
    入队只比一条父链：              出队只走一条子链：

              (0)                          (0)
               |                            |
              (3)                     (1)          (2)
               |                     /   \        /   \
              (7)                  (3)   (4)    (5)   (6)
               |
             (15)

    每往下一层，能比较的元素就少一半，
    所以比较次数是对数级的。
    ```

## 小顶堆：拿大顶堆改三处

* **小顶堆（Min Heap）**

    * > **定义**：根节点为当前最小元素的完全二叉树，数组存储时索引 `0` 就是全场最小值。

    * `offer`：大顶堆是新元素优先级**高于**父元素才上浮，小顶堆改成新元素**低于**父元素才上浮。

    * `down`：第一步（堆顶与末尾交换、`size` 减一）完全不变，第二步把「跟较大的孩子交换」改成「跟较小的孩子交换」，条件从大于改成小于。

    * 变量名 `max` 改成 `min`，先把 `min` 假设成 `parent`，再用两个孩子去刷新。

    ```java
    // offer 的上浮逻辑：只把"比父元素高"改成"比父元素小"
    int child = size;
    heap[child] = x;                       // 先放到队尾（数组下标）
    while (child > 0) {
        int parent = (child - 1) / 2;
        if (heap[parent].value > x.value) { // 原为：优先级高于父元素才交换
            swap(parent, child);            // 小元素上浮
            child = parent;
        } else {
            break;                          // 相等也停，所以后来者不会顶掉先来者
        }
    }
    size++;

    // down 的下潜逻辑：变量名从"max"改成"min"，比较条件从大于改成小于
    int min = parent;                                                  // 先假设父元素最小
    if (leftChild < size && heap[leftChild].value < heap[min].value) { // 与左孩子比
        min = leftChild;
    }
    if (rightChild < size && heap[rightChild].value < heap[min].value) { // 再与右孩子比
        min = rightChild;
    }
    if (min != parent) {                                               // 找的不是自己才换
        swap(parent, min);
        down(min);                                                      // 换完继续往下潜
    }
    ```

    * 上浮条件是**严格小于**才交换，相等即停，所以先入堆的相同元素不会被后来者顶掉，输出是稳定的。

## 用小顶堆合并多条有序链表

### 多路归并的堆算法

* **多路归并（力扣 23 题）**

    * 一句话思路：让每条链表各派一个「当前代表」参加比赛，让堆挑出最小的那个，挑完谁出局，它那条链表再派下一个上来。

    * 固定动作六步：给每条链表设一个指针指向头节点 → 把各链表头节点 `offer` 进小顶堆 → 取堆顶（必是当前所有代表里最小的）→ 挂到结果链表尾部 → 出局元素的指针后移一步、把下一节点 `offer` 回堆 → 堆空为止。

    * 堆为空就意味着所有链表都走完了，此时结果链表建成。

    ```text
      链表一: 1 -> 4 -> 5 -> null        p1
      链表二: 1 -> 3 -> 4 -> null        p2
      链表三: 2 -> 6 -> null             p3

                   offer(p1)  offer(p2)  offer(p3)
                         \        |        /
                          v       v       v
                        [ 小 顶 堆 ]  堆顶始终是最小的
                         ^       ^       ^
                         |       |       |
          pop 堆顶 -------+-------+-------+-------> 依次接到结果链表尾部

     结果链表(哨兵 s):  s -> ...（每 pop 一个，尾指针 t 往后挪一格）
    ```

    * 三条链表 `1 -> 4 -> 5`、`1 -> 3 -> 4`、`2 -> 6` 的逐轮推演：

    | 这一轮 | 出堆前堆里的元素 | 取出的最小值 | 结果链表 |
    | :--- | :--- | :--- | :--- |
    | 初始 | 1, 1, 2 | 1（链表一的） | 1 |
    | 补入 p1 的下一个 4 | 1, 2, 4 | 1（链表二的） | 1, 1 |
    | 补入 p2 的下一个 3 | 2, 4, 3 | 2（链表三的） | 1, 1, 2 |
    | 补入 p3 的下一个 6 | 4, 3, 6 | 3（链表二的） | 1, 1, 2, 3 |
    | 补入 p2 的下一个 4 | 4, 4, 6 | 4（链表一的） | 1, 1, 2, 3, 4 |
    | 补入 p1 的下一个 5 | 4, 6, 5 | 4（链表二的） | 1, 1, 2, 3, 4, 4 |
    | p2 已到头，不再补入 | 6, 5 | 5（链表一的） | 1, 1, 2, 3, 4, 4, 5 |
    | p1 已到头，不再补入 | 6 | 6（链表三的） | 1, 1, 2, 3, 4, 4, 5, 6 |

    * > **提示**：堆里出现两个 `4`、两个 `5` 时，出来的是**先入堆的那个**，因为上浮的条件是严格小于才交换，相等不换，先来的先走。

    * > **提示**：堆里的元素个数不是恒定的 3。两条链表走完后堆里只剩两个，最后只剩一条时就是直接拿走；堆空的那一刻就是全部处理完的那一刻。

### 合并代码的要点

* **合并代码的几个要点**

    * 堆的初始容量定为链表数组的长度——有几条链表，堆里最多就放几个元素。

    * 空链表没必要入堆，入堆前先判 `head != null`。

    * 循环条件是「堆不为空」而不是「还有链表没走完」：两者等价，但用堆来判最省事。

    * 尾指针 `t` 一开始指向哨兵 `s`；先 `t.next = min`，再 `t = min`，保证 `t` 始终指向结果链表的最后一个元素。

    * > **易错点**：⚠️「被移除元素的下一个再入堆」这一步绝对不能漏，否则各条链表就没有代表继续在堆里挑最小；`min.next` 已是 `null` 的不要 `offer`；最后返回 `s.next`，别把哨兵返回出去。

    ```java
    class Solution {

        public ListNode mergeKLists(ListNode[] lists) {
            // 几条链表，堆里最多几个元素
            MinHeap heap = new MinHeap(lists.length);

            // 把各链表的头节点先加入到小顶堆
            for (ListNode head : lists) {
                if (head != null) {   // 空链表没必要入堆，所以先判一下
                    heap.offer(head);
                }
            }

            ListNode s = new ListNode(-1, null);  // 哨兵节点，值给什么都无所谓，next 先给 null
            ListNode t = s;                        // 尾指针，一开始指向哨兵

            // 堆不为空就一直转：堆空了说明所有链表都走完了
            while (!heap.isEmpty()) {
                ListNode min = heap.pop();         // 摘下当前最小的
                t.next = min;                      // 接到新链表尾部
                t = min;                           // 尾指针跟着后移

                if (min.next != null) {            // 被移除元素的下一个再入堆，这一步不能漏
                    heap.offer(min.next);
                }
            }

            return s.next;                        // 哨兵自己不用返回
        }
    }
    ```

### 堆容量上界

* **为什么不全塞进堆**

    * 把每条链表的所有元素一次性塞进堆再逐个出堆，顺序同样保证升序。

    * 代价是空间：例子中八个元素全塞进去，堆容量至少得设成 `8`；而只放「当前代表」的话容量只要链表条数 `3`。

    * > **结论**：堆的价值在于能用有限空间做「找最小值」这件事——堆里的元素个数上界是链表条数，不是元素总数。

    * > **注意**：这种做法的执行效率不如分而治之的两两归并，它的价值是好理解：把「每次从多个候选里挑最小的」交给堆去做，省掉手写归并递归。

## 队列漏掉的两个窟窿

### 使用者分两种角色

* **使用者是生产者与消费者两种角色**

    * 生产者是一段主要调用 `offer` 往队列里提供元素的代码，消费者是另一段主要调用 `poll` 从队列里获取元素的代码。

    * 生产者的执行者可能是一个线程，消费者可能是**另一个**线程；也可能是多个线程同时充当生产者、多个线程同时充当消费者，共享同一个队列。

    * 单纯基于数组的队列实现没有考虑过多线程环境，存在线程安全问题。

### 拿不到就不放弃的需求

* **「拿不到就不放弃」的需求**

    * 队列为空时原实现直接返回 `null`，队列满时 `offer` 返回 `false`，都表示「立刻失败」。

    * 可需求常常是「我一定要拿到一个元素」「我就是要硬塞进去」，现有手段只能写循环不断重试。

    * > **结论**：问题的根子是同一个——`null` 和 `false` 这种立刻失败的返回值，撑不起「我一定要等到你行」的需求；而且重试次数不确定，白白让 CPU 空转。

## 锁：交错、临界区与可打断等待

### 指令交错如何破坏队列

* **指令交错（Instruction Interleaving）**

    * 多线程下 `offer` 里那两行（一句赋值、一句自增）执行次序可能被打断：线程 `t1` 执行完赋值还没自增，执行权切到 `t2`，`t2` 两行跑完，再切回 `t1` 执行自增。

    * 结果 `t2` 的元素被放到了 `tail` 仍为 `0` 的下标上，把 `e1` 覆盖掉了；`tail` 最终自增到 `2`，**位置是对的，内容是错的**。

    ```text
    时刻    T1 做的事                        T2 做的事              队列[0]   tail
     ──    ─────────────────────────       ──────────────        ────────   ─────
      0     初始                               初始                  null       0
      1     queue[0] = "e1"                    ─                     e1         0
      2     切走，tail++ 还没执行              ─                     e1         0
      3     ─                                 queue[0] = "e2"      e2         0   ← e1 被覆盖
      4     ─                                 tail++               e2         1
      5     tail++                            ─                     e2         2   ← T2 的代码已跑完
    ```

    * 复现办法：在 `offer` 方法的第一行加断点，断点类型选 `Thread`，以 debug 模式启动后在不同线程之间来回切换单步执行。

    * > **易错点**：⚠️交错不止一种——可能 `t1` 两行先全跑完再跑 `t2`，也可能 `t2` 先赋值、`t1` 跑完两行、最后回头执行 `t2` 的自增。次序有多种，结果就不止一种：可能完全正确，也可能 `e2` 覆盖 `e1`，也可能 `e1` 覆盖 `e2`，宏观上呈现混乱。

### 两种锁与固定套路

* **两种锁的选择**

    | 选择 | 是什么 | 特点 |
    | :--- | :--- | :--- |
    | `synchronized` | 一个关键字 | 在关键字这一级别上提供的锁实现，功能相对较少 |
    | `ReentrantLock` | 一个类（工具类） | reentrant 是「重新进入」、lock 是「锁」，翻译过来就是可重入锁；功能更为丰富 |

* **`ReentrantLock` 的固定三步套路**

    * 先创建锁对象。锁对象可能被跨方法、被类的其他成员方法使用，所以要向上提取为类的成员变量。

    * 在要保护的代码**之前**调 `lock()` 加锁，写完要保护的代码，在其**之后**调 `unlock()` 解锁；两者之间的多行代码不会在多线程下交错执行。

    * 加锁和解锁必须成对出现且一定被执行到，靠 `try-finally` 保证：`lock()` 写在 `try` 块**外面**，`try` 里写受保护的代码，`finally` 里写解锁。

    ```java
    private final ReentrantLock lock = new ReentrantLock();

    public void offer(String e) {
        lock.lock();          // 加锁写在 try 外面
        try {
            queue[tail] = e;  // 需要保护的两行代码
            tail++;
        } finally {
            lock.unlock();    // 一定被执行
        }
    }
    ```

    * > **定义**：同一时刻如果有多个线程都来加锁，只有一个线程能够成功，其他线程都会加锁失败。

    * 加锁后 `t1` 先拿到锁进入临界区，`t2` 停在 `lock()` 这一行进入 `wait` 阻塞状态；等 `t1` 解锁唤醒它后它才继续，因为此时 `tail` 已指向下一个下标，不会再发生覆盖。

    ```text
    加锁后（临界区互斥）：

      T1                          T2
      -------------------------   -------------------------
      lock()  成功 ↓              lock()  阻塞在 wait
      queue[0] = "e1"
      tail++        tail=1
      unlock()  ──── 唤醒 ────►   从 lock() 处继续往下
                                 queue[1] = "e2"
                                 tail++        tail=2
    ```

    * 两个线程的效果相当于串行，交错问题被消除。

### 可打断的等待

* **`lock()` 与 `lockInterruptibly()`**

    * > **定义**：线程在获取锁时陷入阻塞，就必须等到当前锁的持有者解锁时才能被唤醒、恢复运行。

    * 如果 `t1` 迟迟不解锁，`t2` 不想再等下去，就必须换方法——用 `lock()` 加的锁只能一直等到解锁，换成锁对象的 `lockInterruptibly()` 就能在阻塞状态被提前打断。

    * 提前唤醒不代表拿到了锁：只要持有者还没解锁，它照样拿不到锁；它只是被打断并抛异常，意思是「我不想继续获取这把锁了，我不想等下去了」。

    * 该方法会抛检查异常，调用处要处理异常，测试代码也得加 `try-catch`。

    | 方法 | 阻塞时能不能被打断 | 打断之后 |
    | :--- | :--- | :--- |
    | `lock()` | 不能，只能一直等下去，除非持有者解锁 | —— |
    | `lockInterruptibly()` | 能，在阻塞状态随时可以打断 | 抛出异常，放弃获取这把锁 |

## 大顶堆的完整增删改

### 读接口与空堆判断

* **`peek` 的实现**

    * 取堆顶对应的就是索引 `0`，直接 `return array[0]` 即可。

    * 堆大小为零时取索引 `0` 会报错，所以要加判断——比如没有元素时抛一个异常，或者用包装类让它返回 `null`。

* **空堆判断的欠缺**

    * 无参 `poll` 和带参 `remove` 都没有考虑堆为空的情况，这种情况下应该对异常做一些处理。

### 删与改的共同骨架

* **删与改共用一副骨架**

    * 从数组中间直接删元素效率不高，要把后面整体前挪，是 $O(n)$；所以统一策略都是**先跟最后一个元素交换**，再让 `size` 减一。

    * 交换上来的那个元素不受控，可能破坏堆特性，解法都是让它做一次**下潜**。

    | 方法 | 交换的是哪两个位置 | 下潜从哪开始 |
    | :--- | :--- | :--- |
    | `poll()` | `0` 与 `size - 1` | 索引 `0` |
    | `remove(index)` | `index` 与 `size - 1` | 索引 `index` |
    | `replace(element)` | 不交换，直接把参数写进 `array[0]` | 索引 `0` |

    * > **结论**：删和改的本质都是一件事——把一个不受控的元素塞进堆里，然后让它下潜；区别只在于这个元素落在哪儿。

    * `poll` 的三步：记录 `top = array[0]` 作为返回值 → 交换 `0` 与 `size - 1` → `size--` 后 `down(0)`。

    ```java
    public E poll() {
        E top = array[0];        // 先把堆顶记录下来，最终返回的就是它
        exchange(0, size - 1);   // 0 与 size-1 处的元素交换
        size--;                  // 相当于把尾部那个元素删掉了
        down(0);                 // 刚换上来的元素做下潜
        return top;
    }

    public E remove(int index) {
        E removed = array[index];  // 记录被删除的元素，最终要返回它
        exchange(index, size - 1); // index 与 size-1 处的元素交换
        size--;                    // 删除完成
        down(index);               // 下潜从 index 开始，而不是从 0
        return removed;
    }

    public void replace(E element) {
        array[0] = element;   // 参数直接赋值给数组的索引 0
        down(0);              // 可能破坏了堆的特性，从索引 0 下潜恢复
    }
    ```

    * `size` 只是个整数，删掉之后不必把数组该位置重置为 `null` 去「帮助垃圾回收」。

### 入队 offer 与上浮 up

* **`offer` 与 `up`：往堆的尾部塞一个元素**

    * `offer` 负责判满与 `size++`，上浮全部交给 `up`；底层数组不做扩容，大小一开始就固定。

    * `up` 需要一个参数，因为每轮上浮都要拿这个新元素跟父元素比较。

    * `up` 里 `child` 的初值是**尚未自增的那个 `size`**，这就是新元素最终该待的位置。

    * > **易错点**：`up` 的最后一行 `array[child] = element` 最容易漏。循环里只是把父元素一路挤下去，新元素本身始终没落过地，退出循环时必须补上这一行，否则堆里多一个坑。

    ```java
    public boolean offer(E element) {
        if (size == array.length) {   // 底层数组没有考虑扩容，大小一开始就固定了
            return false;             // 满了就 return false，表示添加失败
        }
        up(element);                   // 没满才执行上浮
        size++;
        return true;                   // 上浮成功，size 加一，添加成功
    }

    private void up(E element) {
        int child = size;                  // 新元素当前所在的位置
        while (child > 0) {                // child == 0 就说明浮到堆顶了，停止上浮
            int parent = (child - 1) / 2;  // 父元素指针，每轮按公式重算
            if (element.compareTo(array[parent]) <= 0) {
                break;                     // 没有父元素大或者跟它相等，就不用再上浮了
            }
            array[child] = array[parent];  // 父元素往下走一格
            child = parent;                // child 挪到刚才 parent 的位置，继续向上
        }
        array[child] = element;            // 最后别忘了：新元素要落在 child 这个位置
    }
    ```

    * 走一遍：堆为 `[0]=7 [1]=5 [2]=6 [3]=4`，加入 `8` 时 `child = 7`，`parent = (7-1)/2 = 3`；依次与 `4`、`5`、`7` 比较全部更大，三轮后停在堆顶索引 `0`。

### 三个必须掌握的方法

* **三个必须掌握的方法**

    * > **结论**：堆里最要紧的三个方法是上浮 `up`、下潜 `down`，以及堆化 `heapify`。

    * `heapify` 写在堆的构造方法里：把无序数组传进去，构造方法内部调用它完成建堆。

## 堆排序

### 排序步骤与循环体

* **步骤**

    * 第一步：对未排序的数组使用 `heapify` 建立一个大顶堆。

    * 第二步：反复把堆顶元素与当前堆底元素交换，`size` 减一让堆缩小一个，再对换上来的元素做下潜。

    * 循环到堆里只剩一个元素为止。

    * 未排序数组 `2 3 1 7 6 4 5` 经 `heapify` 得到 `7 6 5 3 2 1 4`；随后每轮把当前最大值排到堆外已排好序的位置上。

    ```text
    初始:    2  3  1  7  6  4  5

    第 0 步 heapify
             7  6  5  3  2  1  4

    第 1 轮：7 与堆底 4 交换，size 7 -> 6，4 下潜
             7  6  5  3  2  1  4
             ^            ^
             堆外        7 已经排好序（最大）
             堆内:  6 3 5 4 2 1

    第 2 轮：6 与当前堆底交换，size 6 -> 5，下潜
             ^              6 排好序
             堆内:  5 3 1 4 2

    第 3 轮：5 与当前堆底交换，size 5 -> 4，下潜   -> 5 排好序
    第 4 轮：4 排好序
    第 5 轮：3 排好序
    第 6 轮：2 排好序

    堆里剩一个元素时，退出循环

    最终:    1  2  3  4  5  6  7
    ```

    * **循环体与 `poll` 几乎一模一样**

    * 堆顶跟堆底交换、`size` 减一、然后下潜。

    * 被换到堆外的那一轮最大值就落在已排好序的位置上，再也不会被动到。

    ```java
    public void sort(int[] array) {
        MaxHeap heap = new MaxHeap(array);   // 构造方法里已经调用 heapify 完成建堆

        while (heap.size > 1) {             // 一直循环到堆里剩一个元素为止
            heap.exchange(0, heap.size - 1); // 堆顶元素与堆底交换，把最大值排好序
            heap.size--;                    // 堆缩小一，排好的位置不再参与
            heap.down(0);                   // 换上来的元素破坏了堆特性，下潜恢复
        }
    }
    ```

## 求第 k 大元素

### 数组中的第 k 大元素

* **堆的选择：用小顶堆而不是大顶堆**

    * 容量为 `k` 的小顶堆里留着「到目前为止最大的 `k` 个元素」，而这 `k` 个里最小的那个正是堆顶，它就是整个数据里的第 `k` 大。

    * 算法分两段：先把前 `k` 个元素直接入堆；剩下的元素逐个与堆顶判断，比堆顶小就跳过，比堆顶大就 `replace` 换掉堆顶。

    ```java
    class Solution {
        public int findKthLargest(int[] numbers, int k) {
            MinHeap heap = new MinHeap(k);        // 堆里最多放 k 个元素，容量就设成 k

            // 第一步：先把前 k 个元素放进去
            for (int i = 0; i < k; i++) {
                heap.offer(numbers[i]);
            }

            // 第二步：剩下的元素逐个判断
            for (int i = k; i < numbers.length; i++) {
                if (numbers[i] > heap.peek()) {   // 比堆顶小就什么都不做
                    heap.replace(numbers[i]);     // 比堆顶大就替换掉堆顶
                }
            }

            // 循环结束，堆里留的就是到目前为止前 k 大的元素，堆顶即第 k 大
            return heap.peek();
        }
    }
    ```

    * `findKthLargest` 用 `numbers = [3, 2, 1, 5, 6, 4]`、`k = 2` 返回 `5`；用 `numbers = [3, 2, 3, 1, 2, 4, 5, 5, 6]`、`k = 4` 返回 `4`。

    * 小顶堆代码直接拷贝大顶堆改三处：构造方法改名 `MinHeap`；上浮和下潜里的比较条件把「大于」改成「小于」（下潜里有两处）；把 `max` 重构成表示最小值的变量名。

    * > **结论**：这个解法性能不是最好的，时间复杂度为 $O(n)$ 的快速选择算法才是干这件事的正解。

### 数据流中的第 k 大元素

* **数据流第 k 大：数组解与流解的分野**

    * 数组意味着数据一开始就固定死了、以后不再变化；数据流意味着将来还会有新数据被收集上来，数据是变化的。

    * 求**数据流**中的第 `k` 大，堆就是最好的选择，其他算法反而不好使——这是堆的一个典型应用场景。

    * 题目要求实现构造方法与 `add` 两个方法：构造时告知要求的 `k` 位和初始数组，`add` 会被不断调用、参数模拟新收集到的数据、返回值是当前第 `k` 大。

    * 初始数组 `4 5 8 2`、要求第三大时，只保留最大的三个 `4 5 8`；随后依次 `add(3)`、`add(5)`、`add(10)`、`add(9)`、`add(4)`，返回值依次是 `4 5 5 8 8`。

    * 堆里的演变：`3` 比堆顶 `4` 小被忽略、返回 `4`；`5` 替换掉堆顶 `4`，堆变成 `5 5 8`，返回 `5`；`10` 替换堆顶，堆变成 `5 8 10`，返回 `5`；`9` 替换堆顶，堆变成 `8 9 10`，返回 `8`；`4` 比堆顶小被跳过，仍返回 `8`。

    * 相比数组版多出的一个坑是**堆没满**：初始数组可能不足 `k` 个甚至为空，此时 `peek` 根本取不到元素，所以要先用 `isFull()` 判断，没满就先 `offer` 让它凑够 `k` 个。

    ```java
    public boolean isFull() {
        return size == array.length;
    }

    public class KthLargest {
        private MinHeap heap;               // 小顶堆作为成员变量

        public KthLargest(int k, int[] numbers) {
            heap = new MinHeap(k);          // 容量就是 k
            for (int num : numbers) {
                add(num);                   // 初始数组遍历一遍，走同一套逻辑
            }
        }

        public int add(int val) {
            if (!heap.isFull()) {
                heap.offer(val);            // 还没满，先让它凑够 k 个
            } else if (val > heap.peek()) {
                heap.replace(val);          // 满了，才拿新值和堆顶比，比它大才替换
            }
            return heap.peek();             // 堆顶就是第 k 大
        }
    }
    ```

    * > **注意**：⚠️堆没满就返回堆顶元素其实名不副实——只有一个元素时谈不上「第三大」，两个元素时返回的也只是第二大。但测试用例里存在初始数组为空的场景，不这么写就跑不过，只能这样处理。

## 用两个堆求数据流中位数

### 中位数与数据流的特点

* **中位数**

    * > **定义**：中位数 = 奇数个时正中间的那个数；偶数个时正中间两个数的算术平均值。

    * 奇数个例如 `2 3 4` 取 `3`；偶数个例如 `1 2 3 4` 取 `(2+3)/2 = 2.5`。

    * 数据流不是一串排好序就再也不动的静态数据，它意味着新数据源源不断地涌现出来。

    * 「全收集起来排序」形式上行得通，但每来一个新数据就要重排一次，性能非常低。

### 两半各留一个极值

* **两半各自留一个极值**

    * 把所有数据分成两部分：一部分装较小的数据约占一半，另一部分装较大的数据。

    * > **结论**：较小一半的最大值 + 较大一半的最小值 = 中位数。

    * 不用排序：前两个元素有没有顺序、剩余数字是不是有序都不关心，只要把小的那些里最大的挑出来、大的那些里最小的挑出来就行。

    * 找最大值用大顶堆，找最小值用小顶堆，两个堆顶相对着站，中间就是中位数。

    ```text
          大顶堆 left                    小顶堆 right
          （较小的一半）                  （较大的一半）

                3   ◄───── 中位数 ─────►   7
              /   \                       /   \
             1     2                     8     9
    ```

### 平衡规则与绕一圈的添加

* **平衡不是天然的，得靠规则盯着**

    * 两个堆的元素个数应该相等；不相等时最多也不能超过一个——左边四个右边三个可以，左边三个右边四个也可以。

    * 左边多一个时，元素多的那个堆的堆顶自己就是中位数。

    * 平衡规则只有两条：两堆个数一样时新来的元素让**左边**加一；两堆个数不一样时（说明右边少一个）让**右边**加一。交替下去个数差始终不超过一。

* **先放错边，再倒腾回来**

    * 直接把新元素放进要加一的那一边可能破坏性质：两边一样多要加 `10` 给左边，`10` 显然不是中位数。

    * 绕一圈的做法：要让左边加一，就先把新元素加到**右边**，再从右边取走**最小**的那个加到**左边**；要让右边加一，就先把新元素加到**左边**，再把左边**最大**的那个倒到**右边**。

    * 走一遍：两边一样多时来了 `10`，先加到右边，弹出右边最小的 `7`，剩下 `8 9 10`，把 `7` 加到左边——左边四个右边三个，且 `7` 作为右边最小的它到了左边必然也是左边最大的，性质天然就对。

    * > **提示**：记住这「绕一圈」就够了——不能随便加，也不能直接加，要哪边加一就先加另一边、再把极值倒回来。

### 取中位数的两条规则

* **取中位数两条规则**

    * 左右两堆个数一致：各取堆顶求平均。

    * 左边多一个：直接取左边的堆顶，它就是中位数。

    ```java
    public double findMedian() {
        if (left.size() == right.size()) {
            // 还得除以 2.0，不是除以 2
            return (left.peek() + right.peek()) / 2.0;
        }
        // 左边多一个，左边堆顶就是中位数
        return left.peek();
    }
    ```

    * > **易错点**：返回的是小数，必须除以 `2.0`；写成除以 `2` 走整数除法会把小数部分直接舍去。

    * 走一遍：加入 `1 2 3 7 8 9` 六个数，两边各三个，左边 `1 2 3`、右边 `7 8 9`，中位数是 $(3 + 7)/2 = 5$；再加入 `10`，左侧变为 `1 2 3 7`、右侧为 `8 9 10`，中位数是 $7$；再加入 `4`，先把 `4` 加到左边、把左边最大的 `7` 倒到右边，最后左边 `1 2 3 4`、右边 `7 8 9 10`，中位数是 $(4 + 7)/2 = 5.5$。

## 自定义堆：一个开关管住大小顶堆

### 一个开关管住大小顶堆

* **用布尔变量 `max` 合并 `MaxHeap` 与 `MinHeap`**

    * > **定义**：`Heap` 类里的布尔字段 `max` 为真表示创建大顶堆，为假表示创建小顶堆，构造方法只负责把它存进成员变量。

    * 大顶堆与小顶堆的全部差别就在上浮、下潜两个方法的比较条件上，所以只要根据 `max` 选合适的比较条件就能区分。

    ```text
       max == true（大顶堆）        max == false（小顶堆）
       ─────────────────────       ──────────────────────
       up:  新增 > 父  → 上浮        up:  新增 < 父  → 上浮
       down: 左孩子 > 父 → 选左     down: 左孩子 < 父 → 选左
             右孩子 > 父 → 选右           右孩子 < 父 → 选右
    ```

    * `down` 里要改两处：左孩子跟父亲比较、右孩子跟父亲比较。大顶堆是左孩子大于父元素时把它选为更大者，小顶堆则是左孩子小于父元素时把最小值更新成左孩子。

    * 除这几行之外其他代码一行都不用改。

### 容量不够就扩容

* **容量会不够，所以堆得能长大**

    * 中位数题最多会调用 $5 \times 10^4$ 次添加与查找，5 万个数据两个堆一边一半各要放 25000 个，固定容量的堆根本跑不过。

    * > **结论**：堆只需要考虑一个扩容入口，就是 `offer` 添加元素的地方，其他地方都不需要考虑。

    * 堆的底层是数组，容纳不下新元素时扩容即可；不给堆设上限，容量不够就扩，不存在放满放不满。

    ```java
    public boolean offer(T value) {
        if (size == data.length) {
            // 目前这个堆已经放满了，应该进行扩容
            grow();
        }
        // 容量没满，再执行上浮和 size++ 的操作
        up(size, value);
        size++;
        return true;
    }

    private void grow() {
        // 新容量 = 旧容量 * 1.5 = size + (size >> 1)
        int newCapacity = size + (size >> 1);
        Object[] newData = new Object[newCapacity];
        System.arraycopy(data, 0, newData, 0, size);  // 旧数据不能丢
        data = newData;                                 // 新数组取代旧数组
    }
    ```

    * > **易错点**：`(size >> 1)` 的括号一定要加。加法运算优先级比移位高一些，不加括号算出来的结果就不对。

    * 扩容实测：初始容量 5 的堆循环放十个元素，前五个填满；放第六个触发扩容到 `7`，放完第七个又填满、再扩到 `10`，接着放下第八、第九、第十个。

## `PriorityQueue` 与比较器

### 用 PriorityQueue 替换自定义堆

* **用 `PriorityQueue` 替换自定义 `Heap`**

    * `PriorityQueue` 功能与堆类似，支持泛型也支持扩容，直接用即可。

    * 小顶堆直接 `new` 出来的默认就是小顶堆，元素小的会放到堆顶、也就是队列头部。

    * 大顶堆要在构造方法里多传一个 lambda 表达式。

    ```java
    private PriorityQueue<Integer> left;   // 泛型是堆中元素的类型
    private PriorityQueue<Integer> right;

    // 小顶堆：直接 new，默认创建出来它其实是个小顶堆，
    // 小的元素会放到堆顶，或者说放在队列的头部
    right = new PriorityQueue<>();

    // 大顶堆：构造方法里多加一个 lambda 表达式
    left = new PriorityQueue<>((t1, t2) -> t2.compareTo(t1));
    ```

    * 算法逻辑完全照搬：两边一样多就把新数加到右边再把右边最小的挪到左边，否则把新数加到左边再把左边最大的挪到右边。

    ```java
    public void addNum(int num) {
        if (left.size() == right.size()) {
            // 左边要加一：先加右边，再把右边最小的挪到左边
            right.offer(num);
            left.offer(right.poll());
        } else {
            // 右边要加一：先加左边，再把左边最大的挪到右边
            left.offer(num);
            right.offer(left.poll());
        }
    }
    ```

    * 与自定义 `Heap` 版本只有两处差别：`size` 不再是字段而是 `size()` 方法；取堆顶用 `peek()` 而不是 `top()`。

    * 查找中位数处的空指针黄色警告可以忽略：题目保证调用查找前至少有一个元素；只判条件不成立的分支——两边各一个元素时 `peek` 也不可能为空。

### 比较器怎么决定堆顶

* **比较器（`Comparator`）**

    * 比较器本质上就是个对象，可以调用它的 `compare` 方法得知 `a` 和 `b` 谁大谁小。

    * 小顶堆与大顶堆的比较器正好相反：

    | 堆类型 | 比较器 | `compare(a, b)` 返回 -1 | 返回 0 | 返回 1 |
    | :--- | :--- | :--- | :--- | :--- |
    | 小顶堆 | `(t1, t2) -> t1.compareTo(t2)` | a 小于 b | a 等于 b | a 大于 b |
    | 大顶堆 | `(t1, t2) -> t2.compareTo(t1)` | b 小于 a | b 等于 a | b 大于 a |

    * 内部只看上浮那一步：小顶堆里父元素 `a` 为 `10`、新增 `b` 为 `5`，`cp.compare(a, b) > 0` 表示父元素大于新增元素，新增更小所以该上浮。

    * 换成大顶堆后其他代码都不用变，把新增改成 `20`、`a` 仍是 `10`，`compare(a, b)` 同样大于零——因为换了比较器，它在 `b` 大于 `a` 时返回结果大于零。

    ```java
    // 注意：比较器对象的类型是 Comparator，这里起名叫 cp
    Comparator<Integer> cp = (t1, t2) -> t1.compareTo(t2);

    // 上浮的判断
    if (cp.compare(a, b) > 0) {
        // 表示父元素 a 大于新增元素 b，新增元素更小，所以它应该上浮
    }
    ```

    * > **结论**：把构造方法的比较器一改，`PriorityQueue` 自然从小顶堆的判断逻辑变成大顶堆的判断逻辑——这就是大小顶堆实现的全部差别。

## 完全二叉树与二叉树存储

### 节点角色与完全二叉树

* **二叉树的节点角色**

    * 二叉树中每个节点最多只有两个孩子；只有一个孩子也行，没有孩子也行。

    * > **定义**：没有孩子的节点叫做**叶子节点**；树的起始节点叫做**根节点**。

* **完全二叉树的判定**

    * 除了最后一层每一层填满、且由左向右依次填充，缺一不可。

    ```text
              1                 1
            /   \             /   \
           2     3           2     3
          /               /   \   /  \
         4               4     5 6   7

        普通二叉树            不算完全二叉树
                             最后一层跳过了 2 的右孩子，
                             直接去填 3 的左孩子了
    ```

    * 右侧那棵树填了 `2` 的左孩子之后本该填 `2` 的右孩子，却跳过去直接填 `3` 的左孩子，违反由左向右依次填满，所以只是普通二叉树。

### 两种存储方式

* **两种存储方式**

    * 树节点表示：节点类里有一个 `value` 表示节点的值，还有左孩子和右孩子字段，它们的类型也是这个树节点类型。

    * 数组表示：按层序把树压平，索引 `0` 是根，`0` 的左右孩子是 `1` 和 `2`，`1` 的左右孩子是 `3` 和 `4`，`2` 的左右孩子是 `5` 和 `6`；没有的左右孩子用 `null` 表示。

    ```text
       索引:   0     1     2     3     4     5     6
       节点:   1     2     3     4     5     6    null

       层 1:  [ 1 ]
       层 2:  [ 2   3 ]
       层 3:  [ 4   5   6  null ]
    ```

    * 两种方式都可以，实际过程中按需要选择。

### 遍历的两种走法

* **遍历的两种走法**

    * > **定义**：二叉树遍历分成**广度优先遍历**与**深度优先遍历**两类，前者尽可能访问距离根节点最近的节点。

    * 广度优先遍历即层序遍历，一层一层由左向右访问，例如 `1 → 2 → 3 → 4 → 5 → 6 → 7 → 8`。

    * 层序遍历针对的是树节点表示的二叉树；若二叉树用数组实现，直接从索引 `0` 依次向后遍历数组，顺序天然就是层序遍历，不需要队列。
