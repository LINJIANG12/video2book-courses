# 二叉搜索树：合法性判定、前序还原与最近公共祖先

## 合法性判定

### 合法二叉搜索树的定义

* **二叉搜索树（BST, Binary Search Tree）**

    * > **定义**：任意节点左边**所有**值严格小于它、右边**所有**值严格大于它。

    * 判定对象是"左边所有"，不是"左边那个"；祖先与后代之间的大小关系同样要成立。
    * 值相等也不合法，判据必须是严格小于与严格大于，不能放宽。
    * 合法例：根 4、左 2 右 6，2 的孩子是 1 和 3，中序为 1、2、3、4、6。
    * 非法例一：根 5、左 4 右 6，4 的孩子是 3 和 7；6 本身没问题，但 3 落在 5 的右侧却比 5 小。
    * 非法例二：树中出现了两个值相等的节点。

### 中序遍历是唯一判据

* **中序遍历（inorder traversal）**

    * > **定义**：左子树 → 根节点 → 右子树。

    * 合法二叉搜索树的中序遍历结果必然是严格升序；反过来，中序不是严格升序则树一定非法。
    * 判定动作：中序过程中记住上一个访问到的值 `previous`，每访问一个新节点与它比较，出现 `previous >= 当前值` 立刻判非法。
    * 上面那棵根 5 的树中序是 4、5、3、6、7，5 大于 3，升序在此断裂，当场判非法。
    * 判据里的等号也算非法，所以 `previous` 的初值必须严格小于任何可能的节点值。

### 非递归中序加 previous

* **非递归解法（显式栈中序）**

    * 循环条件有两个：`p != null` 表示还在沿左边向前走，`stack` 非空表示正在向回走。
    * 向前走时压栈并令 `p = p.left`；向回走时弹栈，弹出的节点就是当前待处理节点，处理完令 `p = p.right`。
    * 判据写在"处理值"的位置：`previous >= p.val` 直接 `return false`，后续遍历根本不必再跑。
    * 整个 `while` 跑完一遍没抓到非法点，说明整棵树合法，最后 `return true`。

    ```java
    public boolean isValidBST(TreeNode root) {
        Deque<TreeNode> stack = new LinkedList<>();
        TreeNode p = root;
        long previous = Long.MIN_VALUE;   // 记录上一个访问到的节点值
        while (p != null || !stack.isEmpty()) {
            if (p != null) {              // 沿着左边一路向前走
                stack.push(p);
                p = p.left;
            } else {                       // 左边到头了，开始往回走
                p = stack.pop();
                // 向回走：弹出哪个节点，就处理哪个节点的值
                if (previous >= p.val) {
                    return false;          // 上一个值 >= 当前值，不合法，没必要继续了
                }
                previous = p.val;
                p = p.right;               // 弹出来的这个节点，右边还有路就向右走
            }
        }
        return true;                       // 整个 while 跑完都没找到非法点，那就是合法
    }
    ```

    * > **易错点**：初值不能取 `0`——题目不限定节点值范围，若最左节点的值是 -1，一上来第一次比较就错。
    * > **易错点**：初值也不能取 `Integer.MIN_VALUE`——单节点取值为 `-2147483648` 的用例会挂，`previous` 与节点值相等，按 `>=` 判成非法。
    * 正确初值是 `Long.MIN_VALUE`：节点值类型为 `int`，用 long 的边界当负无穷才不会出现相等，改动只有一行。
    * 力扣上执行耗时 1ms。

### 递归中序加 previous

* **递归解法（成员变量共享 previous）**

    * `previous` 声明为类的成员变量，无论递归嵌套多深都用同一个。
    * 递归骨架三步：先递归处理左子树，再比对当前节点值，最后递归处理右子树。
    * 节点为 `null` 时没有可比较的对象，直接 `return true`。
    * 左子树的返回值和右子树的返回值都要用上，最终 `return a && b`；当前节点自身是否合法已在前面的 `return false` 里判掉。

    ```java
    private long previous = Long.MIN_VALUE;

    public boolean isValidBST(TreeNode root) {
        return doValue(root);
    }

    private boolean doValue(TreeNode node) {
        if (node == null) {
            return true;                 // 空节点没什么可比的，直接合法
        }
        if (previous >= node.val) {
            return false;                // 保证严格升序，>= 都算不合法
        }
        previous = node.val;             // 合法就更新 previous，继续往下递归

        boolean a = doValue(node.left);  // 左子树也要合法
        boolean b = doValue(node.right); // 右子树也要合法
        return a && b;
    }
    ```

    * 力扣上执行耗时 0ms，比非递归那版还快。

### 剪枝与 previous 的作用域

* **剪枝（pruning）**

    * 递归本身构成一棵调用树，把其中一些枝杈提前剪掉、让它尽早返回，就结束了一些不必要的递归。
    * 触发场景：根 4、左 2 右 6，2 的右孩子是 4，6 的左孩子是 3、右孩子是 7。这棵树非法，4 的右子树里跑出了比它小的 3。
    * 未剪枝的写法里，3 比对失败返回 `false`，但 6 拿到这个返回值后没有立刻检查，仍会继续判断 6 的值、再判断 6 的右子树 7。
    * 最终结果仍是 `false` 没有错，但 6 和 7 的比较纯属浪费；加了剪枝后处理到 3 就直接返回，6 和 7 不再被访问。
    * 力扣上执行耗时剪枝前后都是 0ms，没有明显提升。

    ```java
    private boolean doValue(TreeNode node) {
        if (node == null) return true;
        if (previous >= node.val) return false;
        previous = node.val;

        boolean a = doValue(node.left);
        if (!a) return false;             // 剪枝：左边一失败，整棵子树没必要再看
        return doValue(node.right);       // 下面就只需要判断 b 了
    }
    ```

* **previous 做成方法参数的陷阱**

    * 把 `previous` 声明成方法参数、每层递归都带上，部分测试用例能过、另一部分过不了，错误极难发现。
    * 反例树：根 3、右孩子 4、4 的左孩子 5。树非法，因为 5 应比 4 小；中序是 3、5、4，但代码返回 `true`。
    * 原因：处理 5 时确实把 `previous` 改成了 5，可那是 5 那次调用的局部变量；回头处理 4 时，4 手里的 `previous` 仍是调用时传进来的 3，`3 >= 4` 不成立，于是漏判。
    * 本质是方法参数属于局部变量，每个方法运行时这份变量对外私有，方法内的修改不会影响其他方法。

    ```java
    public boolean isValidBST(TreeNode root) {
        AtomicLong previous = new AtomicLong(Long.MIN_VALUE);
        return doValue(root, previous);
    }

    private boolean doValue(TreeNode node, AtomicLong previous) {
        if (node == null) return true;
        if (previous.get() >= node.val) return false;      // 调用 get 拿到对象里存的值
        previous.set(node.val);                            // 调用 set 修改，有 get 就有 set

        boolean a = doValue(node.left, previous);
        if (!a) return false;
        return doValue(node.right, previous);
    }
    ```

    * 修法一：换回成员变量，因为全局变量在一个方法内改了会影响另一个方法。
    * 修法二：把参数换成同一个对象，全层传递同一个引用，对它里面的值做修改就能被其他方法看到。
    * > **易错点**：不能直接用 `Long` 代替 `AtomicLong`——`Long`、`Integer`、`Character` 等包装类型不可变，里面的值改不了；必须用 `AtomicLong` 这种能用 `set` 修改的可变对象。
    * 换成对象传参后，上面那棵反例树被正确判为 `false`。

    | 解法 | previous 怎么记 | 特点 |
    | :--- | :--- | :--- |
    | 非递归中序 | 循环外一个局部变量 | 骨架简单，但初值必须用 `Long.MIN_VALUE` |
    | 递归 + 全局变量 | 类成员变量，所有层共用 | 好用，但它是带状态的 |
    | 递归 + 对象传参 | `AtomicLong`，全层共用一个对象 | 传参干净，本质等价于全局变量 |

### 只比父子不够

* **父子比较法的局限**

    * 常见思路是判"父亲比左孩子大、比右孩子小"，每条父子边都成立就认为合法。
    * 反例：根 4、左 2 右 6，6 的孩子是 3 和 7。4 比 2 大、比 6 小，6 比 3 大、比 7 小，按此逻辑全部通过。
    * 实际非法：3 落在 4 的右子树里却比 4 小。
    * 局限根源是只考虑了父节点与子节点之间的大小关系，没有把祖先节点与后代节点之间的关系算进来。

### 上下限把祖先约束传下来

* **上下限递归（min/max 区间法）**

    * 每个节点带一对上下限，节点值必须大于下限且小于上限，祖先的约束沿递归一路传下去。
    * 根节点 4 的区间是 $(-\infty, +\infty)$；2 的下限是负无穷、上限收紧为 4；6 的下限收紧为 4、上限先给正无穷。
    * 3 的下限是 4、上限是 6，落在 $(4,6)$ 之外所以不合法；同一个位置换成 5 就合法，因为 $4 < 5 < 6$。
    * 越界判据用 `node.val <= min || node.val >= max`，与中序的 `>=` 判据保持一致。

    | 节点 | 下限 min | 上限 max | 结论 |
    | :--- | :--- | :--- | :--- |
    | 4（根） | $-\infty$ | $+\infty$ | 合法 |
    | 2 | $-\infty$ | 4 | 合法 |
    | 1 | $-\infty$ | 2 | 合法 |
    | 6 | 4 | $+\infty$ | 合法 |
    | 3 | 4 | 6 | 3 落不进 $(4,6)$，不合法 |
    | 5（若存在） | 4 | 6 | 5 比 4 大、比 6 小，合法 |
    | 7 | 6 | $+\infty$ | 合法 |

    * 递归方向：左孩子下限不变、上限收紧为 `node.val`；右孩子下限收紧为 `node.val`、上限不变。
    * 左右孩子的校验必须同时成立，最终返回两者的逻辑与关系即可。
    * Java 没有整数负无穷，用 `Long.MIN_VALUE` 和 `Long.MAX_VALUE` 充当两端边界。
    * 力扣上执行耗时 0ms。

    ```java
    public boolean isValidBST(TreeNode root) {
        return isValid4(root, Long.MIN_VALUE, Long.MAX_VALUE);
    }

    // min：下限，max：上限，节点值必须大于 min 且小于 max
    private boolean isValid4(TreeNode node, long min, long max) {
        if (node == null) {
            return true;                        // 空节点直接认为合法
        }
        if (node.val <= min || node.val >= max) {
            return false;                       // 越界，不合法
        }
        // 左孩子：下限不变，上限收紧为当前节点值
        // 右孩子：下限收紧为当前节点值，上限不变
        return isValid4(node.left, min, node.val) && isValid4(node.right, node.val, max);
    }
    ```

## 二叉搜索树的范围和

### 中序遍历求和

* **范围和（range sum）**

    * 给一棵二叉搜索树和一个范围，求落在范围之内所有节点值的和，范围是闭区间 $[low, high]$。
    * 中序展开的升序序列为 1、3、5、6、7、10、13、15、18，遍历时值落在范围内就累加，不在就跳过。
    * 算例一：范围 $[7, 15]$ 命中 7、10、15，和为 32。
    * 算例二：范围 $[6, 10]$ 命中 6、7、10，和为 23。

    ```java
    public int rangeSumBST(TreeNode root, int low, int high) {
        Deque<TreeNode> stack = new LinkedList<>();
        TreeNode p = root;
        int sum = 0;                     // 求和肯定得定义在循环外
        while (p != null || !stack.isEmpty()) {
            if (p != null) {
                stack.push(p);
                p = p.left;
            } else {
                p = stack.pop();
                if (p.val >= low && p.val <= high) {
                    sum += p.val;
                }
                p = p.right;
            }
        }
        return sum;
    }
    ```

    * 力扣上执行耗时约 4ms，并不是最优解。
    * 用前序或后序也能算对，因为每个节点都会过一遍；选中序只是为了遍历到上限时能提前结束。
    * 加一行 `if (p.val > high) break;` 就能少循环几次，但仍达不到最优。

    ```java
    } else {
        p = stack.pop();
        if (p.val > high) break;          // 升序遍历，一旦超过上限，后面全是废的
        sum += p.val;                     // 能走到这行，一定在 [low, high] 内吗？不一定！
        p = p.right;
    }
    ```

    * > **易错点**：`break` 之后 `< low` 的判断千万不能省——中序从最小值开始，1、3、5、6 这些小于下限的节点照样会被遍历到，它们只是不参与累加而已。
    * 慢的根源是筛选不彻底：比上限 `high` 大的能提前结束，比 `low` 小的却必须从最小值一路走过去。

### 上下限剪枝递归

* **上下限剪枝求和**

    * 改从根节点直接向下递归，递归过程中对越界的整条枝干做剪枝筛选。
    * `node.val < low` 时它自己和整棵左子树都出局，只递归右子树。
    * `node.val > high` 时它自己和整棵右子树都出局，只递归左子树。
    * 节点落在范围内时，返回 `node.val` 加上左子树累加结果与右子树累加结果。
    * 力扣上执行耗时 0ms，范围 $[7, 15]$ 的结果仍是 32。

    ```java
    public int rangeSumBST(TreeNode root, int low, int high) {
        return rangeSum(root, low, high);
    }

    private int rangeSum(TreeNode node, int low, int high) {
        if (node == null) return 0;                          // 空节点，累加结果就是 0
        if (node.val < low) {
            return rangeSum(node.right, low, high);          // 自己和整棵左子树都出局
        }
        if (node.val > high) {
            return rangeSum(node.left, low, high);           // 自己和整棵右子树都出局
        }
        // 在范围内：自己 + 左子树结果 + 右子树结果
        return node.val
             + rangeSum(node.left, low, high)
             + rangeSum(node.right, low, high);
    }
    ```

    * 四条分支的走向：

    ```text
                              node
                                │
             ┌──────────────────┼───────────────────┐
             │                  │                   │
           node == null      node.val < low     node.val > high
             │                  │                   │
           返回 0          只递归右子树        只递归左子树
                                │
                                ▼
                  low ≤ node.val ≤ high
                                │
                                ▼
              node.val + 左子树累加 + 右子树累加
    ```

    * 逐节点判合法性的常见测试用例：层次 `4 2 6 1 3` 合法；层次 `4 2 6 3 7` 非法，3 挂在了 2 的左边却比 2 大。

## 前序还原二叉搜索树

### 题目前提与结论

* **前序遍历（preorder traversal）**

    * > **定义**：根 → 左 → 右；序列里第一个元素一定是根，后面接着是一整棵左子树的前序，再接着一整棵右子树的前序。

    * 题目给出二叉搜索树的前序遍历结果 `[8, 5, 1, 7, 10, 12]`，要求还原原树。
    * 前提一：`preorder` 数组长度 $\ge 1$，不会是空数组，索引 0 一定是个真节点，可以放心拿它当根。
    * 前提二：数组里没有重复值，插入时只有"小于往左""大于往右"两种情况，"等于"这一支不必写。
    * > **结论**：前序序列加上二叉搜索树的插入规则，就能唯一确定原树。

* **还原结果**

    * 依次是：8 直接当根；5 比 8 小成为 8 的左孩子；1 比 8 和 5 都小落到 5 的左边；7 比 5 大成为 5 的右孩子。
    * 10 比 8 大成为 8 的右孩子；12 比 8 和 10 都大落到 10 的右边。
    * 走完一遍前序仍是 `[8, 5, 1, 7, 10, 12]`，与输入一致，说明还原正确。

    ```text
                       8
                     /   \
                    5     10
                   / \      \
                  1   7      12
    ```

### 顺序插入

* **顺序插入法**

    * 思路最直觉：插入规则是固定的，干脆从左到右把这串数挨个往一棵空树里插一遍。
    * 主方法只有几行：索引 0 建根，然后从索引 1 开始循环，每次把一个值交给插入方法。
    * 力扣上执行 0ms，击败了 100% 的用户。

    ```java
    public TreeNode bstFromPreorder(int[] preorder) {
        TreeNode root = new TreeNode(preorder[0]);
        for (int i = 1; i < preorder.length; i++) {
            int val = preorder[i];
            insert(root, val);
        }
        return root;
    }
    ```

    * > **易错点**：循环必须从索引 `1` 开始，不能从 `0`；索引 0 已经拿去建根节点，再插一遍就把根的值改坏了。
    * 插入方法名从 `put` 改成 `insert` 时，返回值类型要跟着改成 `TreeNode`，新节点必须作为返回值传出去。
    * 主方法里最外层 `return node` 传回的值用不上没关系，它本来就是给递归内部的父子关系用的。

    ```java
    public TreeNode insert(TreeNode node, int val) {
        if (node == null) {
            // 找到空位了，把新节点建出来返回
            return new TreeNode(val);
        }
        if (val < node.val) {
            // 比当前节点小，往左子树递归去找空位
            node.left = insert(node.left, val);
        } else {
            // 比当前节点大，往右子树递归去找空位
            node.right = insert(node.right, val);
        }
        return node;
    }
    ```

    * 时间复杂度：一次插入是 $O(\log n)$，树里有多少个元素就循环多少次，总共 $O(n \log n)$，并非最优。
    * `else` 这一支在这里就够，不必单独判"等于"，无重复值这条前提省掉了一个分支。

### 上限法

* **上限法（给每个节点配一把上限尺）**

    * 同样从左到右遍历每个值，但它不插入，而是给每个值配一对上限，用尺子判断它该挂到哪儿。
    * 节点一创建出来就配两个数：左孩子上限与右孩子上限；想当它的左孩子不能超过左限，想当右孩子不能超过右限。
    * 8 没有限制直接创建，配上左限 8、右限 $+\infty$；5 的左限是 5、右限是 8；1 的左限是 1、右限是 5。

    ```text
                            8   [左限 8, 右限 ∞]
                          /   \
                  [左限 5, 右限 8] 的 5    10
                        /   \
              [左限 1, 右限 5] 的 1    7
    ```

    * 5 的右限是 8 而不是 $+\infty$：递归走到 5 时传下来的 `max` 已经是 8 的左孩子上限，5 的右孩子既要大于 5 又得小于 8。
    * 关键差别在于不立刻创建节点，而是先拿尺子量一下；量不过就把当前节点的左右孩子都给 `null`、算它完整，再回到上一层补父子关系。
    * 处理值 `7` 时先试 1 的左孩子（超过左限 1，不行）与右孩子（1 的右限是 5，7 大于 5，不行），两次失败后 1 才算完整。
    * 值本身仍停在 `7` 上，回上一层再试：7 没超过 5 的右限 8，可以创建；下一个值 `10` 试 7 的左右都超限，7 完整后才与 5 建立父子关系。
    * 然后 5 整块完成，再与 8 建立关系；`10` 试过 7 之后改试 8 的右孩子，`12` 试过 10 的左孩子失败后成为 10 的右孩子，整棵树完成。

* **上限法的实现**

    * 用一个全局下标 `i` 从 0 开始取当前要处理的值，节点创建好之后才让 `i` 加加，自增到数组长度时递归退出。
    * 左孩子的上限是当前值 `value`，右孩子的上限沿用传下来的 `max`；最外层第一次调用设成正无穷。
    * 时间复杂度 $O(n)$，比顺序插入的 $O(n \log n)$ 更优秀，代价是每个值只被取用一次。

    ```java
    private int i = 0;

    public TreeNode bstFromPreorder(int[] preorder) {
        return insert(preorder, Integer.MAX_VALUE);
    }

    public TreeNode insert(int[] preorder, int max) {
        // 递归的出口：数组已经取完
        if (i == preorder.length) {
            return null;
        }

        int value = preorder[i];

        // 超过上限，坐不上这个位置，返回 null 作为上一层节点的孩子
        if (value > max) {
            return null;
        }

        TreeNode node = new TreeNode(value);
        i++;
        node.left = insert(preorder, value);
        node.right = insert(preorder, max);
        return node;
    }
    ```

    * > **注意**：这道题的取值不会超过正整数的最大值，放心传 `Integer.MAX_VALUE` 就行，不用再考虑溢出。
    * > **易错点**：`i++` 的位置要注意，必须放在两次递归调用**之前**，不能挪到后面——要拿下一个值去试位置，得先让下标前进到下一个位置。

### 分治法

* **分治法（partition）**

    * 前序序列的第一个元素是根，比它小的那段是左子树，比它大的那段是右子树。
    * 左右子树在序列里必然是连续的，因为前序是"根 → 左 → 右"，根值之后先连着一段左子树、再连着一段右子树。
    * 一次划分只能分开一层，所以对左子树递归套用同样的算法继续拆分，直到区间为空。

    ```text
    区间 [8,5,1,7,10,12]    根 = 8    index = 3
    ├─ 左区间 [5,1,7]         根 = 5    index = 2
    │  ├─ 左区间 [1]           根 = 1    index = 3（越界 → 左子树为空）
    │  └─ 右区间 [7]           根 = 7
    └─ 右区间 [10,12]         根 = 10   index = 5
       └─ 右区间 [12]          根 = 12
    ```

    * 区域规模随划分逐渐缩小：6 个元素可能变成 3 个、2 个、1 个，直到区域内没有元素。
    * `index` 是这一轮找到的分界线位置，也就是右子树的起点，`index - 1` 是左子树的终点；左区间为空时 `index` 会一路越过区域末尾。
    * 参数三个：数组 `preorder`、区间起点 `start`、区间终点 `end`，起始时是 0 到数组长度减一。
    * 结束条件是 `start > end`，即范围内没有元素了，返回 `null`。
    * 根直接取 `preorder[start]`；分界线从 `start + 1` 起向右扫，遇到第一个大于根的元素就停。
    * 每次返回该区间的根节点即可：左区间返回的 5 挂成 8 的左孩子，右区间返回的 10 挂成 8 的右孩子。

    ```java
    public TreeNode bstFromPreorder(int[] preorder) {
        return partition(preorder, 0, preorder.length - 1);
    }

    public TreeNode partition(int[] preorder, int start, int end) {
        // 区间内没有元素了
        if (start > end) {
            return null;
        }

        // 区间起点的元素就是根
        int rootVal = preorder[start];
        TreeNode root = new TreeNode(rootVal);

        // 从根的下一个位置开始，找第一个大于根的元素作为分界线
        int index = start + 1;
        while (index <= end && preorder[index] < rootVal) {
            index++;
        }

        // 左子树区间：start + 1 到 index - 1
        root.left = partition(preorder, start + 1, index - 1);
        // 右子树区间：index 到 end
        root.right = partition(preorder, index, end);

        return root;
    }
    ```

    * 时间复杂度与顺序插入同档，都是 $O(n \log n)$，比上限法稍逊一筹。
    * 原因：每个区间都要线性扫一遍找分界线，单次划分的开销与区间长度成正比，树越偏斜代价越大。
    * 三种解法的取舍：顺序插入最好想最好写；上限法最绕，绕到必须亲手走一遍"某个值为什么当不了一的孩子"才真正明白；分治法最贴合二叉搜索树的定义本身。

    | 解法 | 核心动作 | 单个值要付出的代价 | 时间复杂度 |
    | :--- | :--- | :--- | :--- |
    | 顺序插入 | 每个值从根一路走到空位插进去 | 一次插入 $O(\log n)$ | $O(n \log n)$ |
    | 上限法 | 配左右上限，值先试位置、站得住再建节点 | 一次，取用即止 | $O(n)$ |
    | 分治法 | 找分界线，把区间切成左右两半再递归 | 随所在区间长度变化 | $O(n \log n)$（与方法一同档） |

## 最近公共祖先

### 题意与规律

* **最近公共祖先（lowest common ancestor, LCA）**

    * 给一棵二叉搜索树和树中的两个节点 p、q，求离它俩最近的一个公共祖先。
    * 前提一：这两个节点确定存在于树中，不用考虑找不到的情况。
    * 前提二：祖先也算它自己，这一句很容易被漏掉。
    * > **结论**：公共祖先往往不止一个，题目要的是深度最大的那一个，难度全部集中在"最近"两个字上。

* **判定规律**

    * > **结论**：当待查找的节点 p 和 q 处在某个节点的两侧时，这个节点就是它俩最近的公共祖先。

    * "两侧"包含"其中一个正好等于当前节点"这种情形。
    * 例树：根 6，左 2 右 8，2 的右孩子是 4，4 的右孩子是 5。
    * 问 2 和 8：2 的祖先链是 2、6，8 的祖先链是 8、6，交集只剩 6，答案就是 6。
    * 问 4 和 5：4 的祖先是 4、2、6，5 的祖先是 5、4、2、6，2、4、6 都是公共祖先，最近的是 4。
    * 套规律走 4 和 5：6 处两者都小于它，不满足；2 处两者都大于它，也不满足；4 处四自己等于它、五大于它，算"在两侧"，命中 4。

### 沿比较链下行

* **循环实现**

    * 把 `root` 复制给临时变量 `a` 代表当前节点，循环条件写成"同一侧"。
    * `p.val < a.val && q.val < a.val` 表示两者都在 `a` 的左侧，`p.val > a.val && q.val > a.val` 表示两者都在右侧。
    * 只要还在同一侧就继续往下走，一旦分居两侧或其中一个等于 `a`，退出循环时的 `a` 就是答案。
    * 往哪边走只看 `p` 就够：既然能进循环就说明两者同侧，p 在哪一侧，q 一定跟着在哪一侧。
    * 两组算例：p、q 为 2 和 8 打印出 6；为 4 和 5 打印出 4。

    ```java
    public TreeNode lowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q) {
        TreeNode a = root;
        while ((p.val < a.val && q.val < a.val) || (p.val > a.val && q.val > a.val)) {
            if (p.val < a.val) {
                a = a.left;
            } else {
                a = a.right;
            }
        }
        return a;
    }
    ```

    * > **易错点**：不要一上来就去遍历整棵树、求两条根到节点的路径再找交点；一条比较链就能走下来，没必要把简单题做复杂。

## 不平衡与旋转

### 不平衡的代价与旋转

* **树失衡后的退化**

    * 二叉搜索树长得不平衡时查询效率会受影响：查 1 也要从根开始一路向左、再向左转，四个元素比较了四次才找到。
    * 正常二叉搜索树能做到 $O(\log n)$，一旦出现这种不平衡，最坏情况下就退化成 $O(n)$。

    ```text
        4
       /
      3
     /
    2
   /
  1
    ```

* **旋转（rotation）**

    * 解决办法叫旋转，上面这棵树右旋一下，也就是顺时针转一下：

    ```text
          3
         / \
        2   4
       /
      1
    ```

    * 原来的根 4 向右旋下去，原来的 3 向右旋上来当新根。
    * 再查 1 就轻松多了：先跟 3 比，比 3 大的那些元素根本不用比较，查询效率就恢复了。
    * > **结论**：旋转并不会破坏二叉搜索树的性质——旋完之后依然是"左边的都比根小、根右边的都比根大"，因为旋转只改变父子关系，不改变谁比谁大。

### 高度差与平衡因子

* **高度与高度差**

    * 高度按约定：叶子节点高度是 1，往上一层加一；空节点（`null`）的高度约定为 0。
    * 判断依据是高度差：某个节点的左右孩子高度差超过 1，就认为这棵树不平衡，才需要用旋转去修正。
    * 例：上面那棵失衡的树，根的左孩子高度是 3、右孩子是 `null` 记作 0，高度差 $3 - 0 = 3$，明显超过 1，该旋。
    * 例：根节点高度是 3，左右孩子一个高 2、一个高 1，高度差是 1，就不需要旋转，仍认为是平衡的。
    * > **结论**：只有当某个节点的左右孩子高度差**超过 1** 时才旋转；不超过 1 一律不动，硬旋没有本质提升。

* **平衡因子（balance factor, bf）**

    * > **定义**：一个节点的左子树高度减去它的右子树高度，所得结果就是它的平衡因子。

    * 方法名 `balanceFactor`，取前两个字母简称 bf，返回整数，参数是节点对象。
    * 读懂返回值比背公式重要，看到数就该立刻浮现出这棵树的样子。

    ```text
                    6
                  /   \
                 2     8
                  \
                   4
                    \
                     5
    ```

    | 平衡因子取值 | 含义 | 是否平衡 |
    | :--- | :--- | :--- |
    | 0 | 左右子树等高 | 平衡 |
    | 1 | 左子树比右子树高一层 | 平衡 |
    | -1 | 左子树比右子树矮一层 | 平衡 |
    | $> 1$ | 左边太高 | 不平衡，需要旋转 |
    | $< -1$ | 右边太高 | 不平衡，需要旋转 |

    * 树上节点 4 的左右子树高 1、高 1，$1 - 1 = 0$，零表示左右等高，肯定平衡。
    * 节点 2 的左子树高 1、右子树高 2，$1 - 2 = -1$，高度差没超过 1，同样平衡。
    * 左子树高 3、右子树高 1 得 $2$，表示左边高；镜像情形 $1 - 3 = -2$，表示右边高。
    * 这个反应速度后面写旋转代码时会直接用到。

### 破坏平衡的时机

* **新增与删除**

    * 导致二叉树失去平衡的情况只有新增和删除两种。
    * 新增的例子：原本根的左孩子高度是 1、右孩子是 `null` 高 0，高度差没超 1；往左加一个 3 之后，原左孩子高度从 1 变成 2，根的高度跟着变成 3。
    * 这时从根来看，左子树高 2、右子树高 0，$2 - 0$ 已经超过 1，平衡被打破，得靠旋转修回来。
    * 删除同理：删掉右侧的 8 之后，根的高度变成 3，左孩子高度变成 2，右孩子归 0，左右高度差又超过 1。
    * 修改操作不会破坏平衡：找到某个节点把它的值改掉不会导致不平衡，只有新增和删除会。

### AVL 树

* **自平衡二叉搜索树（AVL 树）**

    * > **定义**：二叉搜索树在插入和删除时都可能导致节点失衡，如果在插入和删除时通过旋转让它**始终保持平衡**，这种二叉搜索树就叫自平衡的二叉搜索树。

    * 自平衡二叉搜索树有很多种实现，最著名的一种叫 AVL 树。
    * 名字来源：发明者有两个人，一个人的名字里有 A 和 V，另一个作者的名字里有 L，拼成 AVL。

* **节点类与高度维护**

    * 节点用静态内部类 `AvlNode` 定义，`key` 用来比较大小，另有 `value` 以及 `left`、`right` 两个孩子引用。
    * 比普通二叉搜索树节点多存一个 `height`，类型为 `int`；节点刚创建出来时高度就是 1。
    * 三个构造方法分别对应只传 `key`、传 `key` 和 `value`、四个参数全传，不管哪个高度都不需要你传、默认就是 1。

    ```java
    private static class AvlNode {
        public int key;
        public int value;
        public AvlNode left;
        public AvlNode right;
        public int height;

        public AvlNode(int key) {
            this.key = key;
            this.height = 1;
        }

        public AvlNode(int key, int value) {
            this.key = key;
            this.value = value;
            this.height = 1;
        }

        public AvlNode(int key, int value, AvlNode left, AvlNode right) {
            this.key = key;
            this.value = value;
            this.left = left;
            this.right = right;
            this.height = 1;
        }
    }
    ```

    * 高度已经做成属性还要单独写求高度的方法，是因为传进来的节点对象有可能是 `null`，不能让一个 null 去点 `height`。
    * 这个方法把 null 的情况顺手处理好：node 已是 null 就返回 0，否则通过 `height` 属性拿高度。
    * > **易错点**：求任何节点的高度都走这个方法，不要图省事直接点属性，空指针就是这么来的。

    ```java
    private int height(AvlNode node) {
        return node != null ? node.height : 0;
    }
    ```

    * 节点高度是"左右子树高度的最大值再加 1"，这个公式与求二叉树最大深度时是同一个。

    $$h(node) = \max\left(h(node.left),\ h(node.right)\right) + 1$$

    ```java
    private void updateHeight(AvlNode node) {
        node.height = Math.max(height(node.left), height(node.right)) + 1;
    }
    ```

    * 顺着插入走一遍：先插 9，树里就一个节点，保持创建时的高度 1；插 7 成为 9 的左孩子，7 自身仍为 1，9 更新成 2。
    * 再插右孩子 10，9 的高度反而不变、仍是 2，因为左右子树高度都是 1，取最大值 1 再加一还是 2。
    * 再插 5 成为 7 的左孩子，5 的高度是 1，7 更新成 2，9 更新成 3。
    * 需要调用更新方法的三种时机是新增、删除以及旋转之后。
    * 平衡因子同样必须调 `height` 方法求左右高度，因为左右子树都有可能为 `null`。

    ```java
    private int balanceFactor(AvlNode node) {
        return height(node.left) - height(node.right);
    }
    ```

### 四种失衡情况与旋转方案

* **失衡类型的命名规则**

    * 四种情况叫左左、左右、右右、右左，命名规则是：第一个字描述失衡节点自己哪边高，第二个字描述它的左孩子或右孩子哪边高。
    * 左左：失衡节点自己左边更高，它的左孩子也是左边更高或者等高，两者同向偏左。
    * 右右：与左左完全对称，失衡节点和它的右孩子都是右边高，同向偏右。
    * 左右：失衡节点左边高，但它的左孩子是右边高、左边反而更低，两者反向。
    * 右左：与左右对称，失衡节点右边高，但它的右孩子左边高。
    * 判断时叶子节点不用看；例树中节点 2 左高 1 右高 0 没超、节点 3 左高 2 右高 1 也没超，只有失衡节点本身超标。

    | 失衡类型 | 失衡节点 | 它的左/右孩子 | 特征 |
    | :--- | :--- | :--- | :--- |
    | 左左 | 左边高 | 左孩子左边高或等高 | 失衡点与左孩子同向偏左 |
    | 左右 | 左边高 | 左孩子右边高 | 失衡点与左孩子反向 |
    | 右右 | 右边高 | 右孩子右边高或等高 | 失衡点与右孩子同向偏右 |
    | 右左 | 右边高 | 右孩子左边高 | 失衡点与右孩子反向 |

* **旋转方案**

    * 只分"左边高"和"右边高"两种，既定不出旋转方向也定不出旋转次数，所以必须拆成四种。
    * 反例：失衡节点是 6、左高 3 右高 1，照样做一次右旋后左边高度变成 1、右边变成 3，失衡不但没解决反而更极端。
    * 左左：对整个左左子树做一次右旋就恢复平衡，参与旋转的是 5 向右旋下去、3 代替它原来的位置成为新根。
    * 旋转里有个"换爹"操作：3 上去、5 下来后 5 成了 3 的右孩子，而 4 原本已经是 3 的右孩子，所以 4 必须变成 5 的左孩子。
    * 右右：与左左对称，一次左旋就能恢复平衡。
    * 左右：先让左子树向左旋，4 这个节点换上来后变成左左的情况，再对整个失衡节点向右旋一次。
    * 右左：先让右子树向右旋，4 上来 6 下去，再让整个失衡节点 2 向左旋，同样恢复平衡。

    | 失衡类型 | 恢复方式 |
    | :--- | :--- |
    | 左左 | 一次右旋 |
    | 右右 | 一次左旋 |
    | 左右 | 左子树先左旋，失衡节点再右旋 |
    | 右左 | 右子树先右旋，失衡节点再左旋 |

    * 结论直接给：左左一次右旋就够，右右一次左旋就够，中间的左右和右左都得两次旋转。
