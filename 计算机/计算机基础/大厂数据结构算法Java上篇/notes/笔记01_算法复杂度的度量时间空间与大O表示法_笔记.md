# 算法复杂度的度量：时间、空间与大 O 表示法

## 事前统计法与执行次数推算

### 二分查找的循环次数

* **循环次数 $L$**

    * > **定义**：二分查找每轮把待查范围对半砍掉，循环次数为 $L = \lfloor \log_2 n \rfloor + 1$，其中 $n$ 是元素个数、$L$ 是循环次数。

    * 以二为底的对数说白了就是把这个数反复除以二，看除几次能除到 1。

        ```text
         n = 4      4 -> 2 -> 1                   2 次
         n = 8      8 -> 4 -> 2 -> 1              3 次
         n = 16    16 -> 8 -> 4 -> 2 -> 1         4 次
         n = 32    32 -> 16 -> 8 -> 4 -> 2 -> 1   5 次
        ```

    * 5、6、7 这种数除不尽，对数不是整数：7 除一次得 3.5，除两次得 1.75，对数落在 2 和 3 之间，向下取整得 2，加一还是 3。

    * 元素个数从 4 涨到 32，循环次数只从 2 涨到 5，$n$ 每翻一倍 $L$ 只多 1。

### 循环体内外的逐行执行次数

* **逐行计数**

    * > **定义**：把与循环相关的语句拆开逐条统计执行次数，条件语句要数到每一次判断，包括最后一次不成立的判断。

    * 目标在右半边，所以第一个 `if` 一定不成立；第一个不成立就会接着去比第二个 `else if`；`mid++` 与赋值各执行一次；最后的 `else` 只往右边找，永远进不去。

        ```text
         [while 循环内]
           循环条件  i < j                 ->  L + 1 次   (最后一次不成立才退出)
           计算中间索引 mid                ->  L 次
           if:  target 与中间值比较         ->  L 次
           else if:  中间值是否小于目标     ->  L 次
               mid++ 与赋值                 ->  2L 次
           else                            ->  0 次       (只往右边找，永远进不去)
           ----------------------------------------------------
           循环体内小计                     ->  5L 次

         [循环外的零散语句]
           循环初始化、判断、步进等         ->  1 + 1 + 2 = 4 次
        ```

    * 循环条件 `i < j` 跑的是 $L+1$ 次而不是 $L$ 次，因为最后一次比较不成立循环才退出，这最后一次比较同样要算数。

* **求和成执行函数**

    * 循环体内合计 $L + L + L + L + 2L = 5L$ 次。

    * 循环外零散语句合计 $1 + 1 + 2 = 4$ 次。

    * 两部分相加得到二分查找的总执行行数 $f(n) = 5(\lfloor \log_2 n \rfloor + 1) + 4$。

### 把两个查找算法放到同一杆秤上

* **单位时间假设**

    * > **定义**：假设每行语句执行的时间都一样，用单位时间 $t$ 表示，那么总执行行数乘以 $t$ 就是总时间。

* **两个算法在同一规模下的数值**

    * 线性查找那边早算过，函数式是 $f(n) = 3n + 3$；二分查找是 $f(n) = 5(\lfloor \log_2 n \rfloor + 1) + 4$。

    * $n = 4$ 时：线性查找 $3 \times 4 + 3 = 15$，即 $15t$；二分查找 $\lfloor \log_2 4 \rfloor + 1 = 3$，$5 \times 3 + 4 = 19$，即 $19t$。

    * $n = 1024$ 时：线性查找 $3 \times 1024 + 3 = 3075$，即 $3075t$；二分查找 $\lfloor \log_2 1024 \rfloor = 10$，$5 \times (10 + 1) + 4 = 59$，即 $59t$。

    * > **易错点** ⚠️：看到 15 比 19 小就下结论说线性查找更快是错的，当时只有 4 个元素，数据量太小，优点还没显出来。

* **事前统计法**

    * > **定义**：先推算语句执行次数、再拿执行次数比大小的办法叫事前统计法。

    * 判算法好坏不能光看数据量小的情况，要看数据规模持续增大的时候它是不是还能表现得优秀。

### 用曲线验证增长趋势

* **把式子变成可画的形式**

    * 横轴 $x$ 代表数据规模也就是数组内元素的个数，纵轴 $y$ 代表算法执行的代码行数或者说总时间。

    * 画图工具只认 $x$ 不认 $n$，办法有两种：把所有 $n$ 替换成 $x$；或者让 $n$ 的取值来自于 $x$，把 $x$ 的每个值赋值给 $n$，将来这里的 $n$ 就等价于 $x$。

    * 让 $n$ 的取值来自于 $x$ 时，那条 $n = x$ 的线可以点前面的小图标隐藏掉，剩下的红线就是 $f(n)$。

    * 线性查找粘 $3x + 3$ 出来一条红线，$x = 2$ 时 $y = 9$、$x = 4$ 时 $y = 15$，与手算结果完全对得上。

    * 一个网页里能画多张图，鼠标点一下就能开第二张，方便两条线摆在一起对比。

* **缩小纵轴后的读数**

    * 数据量到 120 左右时二分查找大约 $39t$，而这个规模下线性查找那条红线已经看不在哪儿了。

    * 数据规模上万、点到 14000 时二分查找总时间是 $74t$，还是很小的数，红色线都不知道跑哪儿去了。

    * 二分查找的曲线几乎不产生多大变化，线性查找的时间成本却一下子飙升，这就是变化趋势。

## 时间复杂度

### 定义与高低判读

* **时间复杂度**

    * > **定义**：时间复杂度是用来衡量一个算法的执行时间随着数据规模的增大而增长的一个时间成本。

    * 它就是前面通过事前分析得到的结果，在计算机科学里有一个专门的术语。

* **高低判读规则**

    * 数据规模不断增大而算法的执行时间并没有明显增长，说明这个算法的时间复杂度低，是相对比较优秀的算法。

    * 数据量越来越大而算法的执行时间增长得非常快，说明时间复杂度高，相对而言也是不那么好的算法。

### 分析前提

* **环境无关性**

    * > **注意**：分析时间复杂度的过程中，要把硬件、软件环境统统剔除掉，只针对算法本身来考虑它在执行时间上到底好不好。

    * 硬件环境因素包括 CPU 主频、内存的存取速度等。

    * 软件环境因素包括 Java 语言的编译器是不是对你的代码做了优化，优化之后它跑的速度可能就快了。

    * > **易错点** ⚠️：时间复杂度的分析过程是不依赖于环境因素的，不能拿跑得快的环境给算法加分。

## 从 f(n) 到 g(n)

### 化简的目标

* **执行函数 $f(n)$**

    * > **定义**：算法要处理的数据规模是 $n$，代码总的执行函数记作 $f(n)$，它代表数据规模变化时总执行时间的变化趋势。

    * 线性查找的 $f(n) = 3n + 3$、二分查找的 $f(n) = 5(\lfloor \log_2 n \rfloor + 1) + 4$ 都能当作 $f(n)$ 用。

* **化简函数 $g(n)$**

    * > **定义**：用一个更简单的函数来代表数据规模与时间成本之间的变化关系，这就是对 $f(n)$ 进行化解得到 $g(n)$。

    * 原始式子相对来讲都挺复杂，不容易一眼看过去判断时间复杂度的高低，即一眼看过去抓不住主要矛盾。

    * > **注意**：更简单的这个函数，它的**变化趋势**要跟 $f(n)$ 相近，注意是相近，不是相等。

    * 找到一个与原本 $f(n)$ 变化趋势相近的函数、用它来代表时间复杂度，这种表示法就是大 O 表示法。

### 渐近上界、下界与紧界

* **记号约定**

    * $c$、$c_1$、$c_2$ 都是常数，$n$ 代表数据规模并对应横轴。

    * $f(n)$ 是实际执行的代码行数与 $n$ 的一个函数，代表执行时间与数据规模之间的变化趋势。

    * $g(n)$ 是化简后的函数，它的趋势与 $f(n)$ 一致，也是 $n$ 的函数。

* **三种界的几何形状**

    * 渐近上界：$g(n)$ 乘上常数 $c$ 之后，从某个点 $n_0$ 开始所有值都比 $f(n)$ 的值大。

    * 渐近下界：在某个点以后，$c$ 乘以 $g(n)$ 的值总是小于 $f(n)$。

    * 渐近紧界：$g(n)$ 乘 $c_1$ 在 $f(n)$ 的下面、乘 $c_2$ 在 $f(n)$ 的上面，把 $f(n)$ 包围在中间，一个在它上面一个在它下面。

        ```text
                 c2·g(n)  ────────────────────────  总在上方
                ╱         ╲
              f(n)         ╲                      被夹在中间
            ╱       ╲       ╱
                 c1·g(n)  ────────────────────────  总在下方
             └──────────────────────────────────→  n
        ```

* **三界对照**

    | 概念 | 符号 | 几何关系 | 代表的含义 |
    | :--- | :--- | :--- | :--- |
    | 渐近上界 | $O(g(n))$ | $c \cdot g(n)$ 总在 $f(n)$ 上方 | 算法执行的最差情况 |
    | 渐近下界 | $\Omega(g(n))$ | $c \cdot g(n)$ 总在 $f(n)$ 下方 | 算法执行的最佳情况 |
    | 渐近紧界 | $\Theta(g(n))$ | $c_1 \cdot g(n)$ 在下、$c_2 \cdot g(n)$ 在上 | 最差与最佳都能代表 |

* **名称来源**

    * 渐近上界、渐近下界、渐近紧界这几个名字都是按单词的直接翻译来的。

### 大 O 代表的含义

* **大 O 表示法**

    * > **定义**：大 O 表示法就是渐近上界的写法，括号里面写上 $g(n)$，形式为 $O(g(n))$。

* **为什么等于最差情况**

    * 横轴代表数据规模，纵轴代表算法实际执行的代码行数，$y$ 轴的值越大说明实际执行的代码行数越多，相对来讲就更糟糕。

    * 从某个点 $n_0$ 开始 $f(n)$ 总在 $g(n)$ 的下方，意味着 $f(n)$ 执行得再糟糕也不能比 $g(n)$ 更差，$g(n)$ 是一种更差的情况。

    * 所以渐近上界说的是算法的一种最糟糕情况：你再差，不能比这个上界函数表示的更差。

## f(n) 化简成 g(n) 的实操

### 线性查找化简为 O(n)

* **取最高次项并凑出上界**

    * 对多项式办法很直接：找到它的最高次项，把最高次项作为 $g(n)$，$3n + 3$ 的最高次项就是 $n$。

    * 先令 $g(n) = n$，画出来发现绿线在红线 $3n + 3$ 下面，与要成为上界的方向反了。

    * $g(n)$ 前面还有个系数 $c$ 这个常量系数，给它乘个值比如乘个 4，就变成在某个点之后所有绿线的取值都比红线大。

    * 分界点大概是 $n_0 = 3$：从 $n = 3$ 开始所有绿线取值都比红色线大，所以这个绿线函数就是原本 $f(n)$ 的一个上界。

* **写出结果**

    * 大 O 表示法不体现那个系数 $c$，会把系数直接去掉，光剩下 $g(n)$。

    * 只要能找到一个 $g(n)$、保证它是 $f(n)$ 的渐近上界，就可以用大 O 括号把 $g(n)$ 写进去，本例 $g(n)$ 就是 $n$，记作 $O(n)$。

### 二分查找化简为 O(log₂ n)

* **先展成多项式**

    * 把 5 跟括号里这些乘进去、括号不要了，就变成 $5$ 乘以那一堆，再加上 $5 \times 1$ 和括号里面的 4，相当于整个加了个 9，即 $f(n) = 5 \log_2 n + 9$。

    * 化成多项式后按口诀处理：常数 9 这种肯定是最低项直接去掉，前面这一项里的系数和 floor 函数也都可以去掉。

    * 去掉之后剩下的就是以二为底的 $n$ 的对数，即 $g(n) = \log_2 n$，画出来这条紫线就是 $g(n)$。

* **验证上界并写出结果**

    * 紫线同样还在红线下面，还不能作为渐近上界，可以再乘系数：先乘 3 不够、还在下面，乘个 10 这回跑到所有红色线段的上方，成为 $f(n)$ 的一个渐近上界。

    * 二分查找用大 O 表示法写就是 $O(\log_2 n)$。

    * > **提示**：在 markdown 里写数学公式，先写两个 dollar，然后在两个 dollar 里面写大 O 括号和以二为底的 $n$ 的对数就可以了。

### 化简口诀

| 口诀 | 例子 | 为什么可以 |
| :--- | :--- | :--- |
| 相乘的常量可以省略 | $f(n) = 100 n^2 \Rightarrow g(n) = n^2$ | $g(n)$ 总可以再乘一个常数 $c$，只要这个 $c$ 比你原来的 100 大一些，它增长就一定比原来 $f(n)$ 快，也就保证了 $g(n)$ 肯定在 $f(n)$ 上面，所以这个常数是多少并不重要 |
| 多项式的低次项可以省略 | $n^2 + n \Rightarrow n^2$；$n^3 + n^2 \Rightarrow n^3$ | $n$ 再怎么变化，也没有 $n^2$ 变化得快；$n^2$ 也追不上 $n^3$ 增长的快 |
| 对数的底数不重要 | $\log_2 n$ 与 $\log_{10} n$ 等价 | $\log_2 n = \dfrac{\log_{10} n}{\log_{10} 2}$，而 $\log_{10} 2$ 就是一个常数，属于第一条那种情况 |
| 对数的常数次幂可以省略 | $\log^2 n$、$\log^3 n$ 前面的 2 和 3 | 道理一样，那个系数可以直接去掉 |

* **记牢优先级**

    * 前两条是要记牢的，后面两条没那么重要，心里有数就行。

    * 四条口诀可套用到任意 $f(n)$ 上：相乘的常量、多项式低次项、对数的底数、对数的常数次幂，能省则省。

## 常见大 O 记号

### 七种常见大 O 的排序

| 大 O 表示 | 称呼 | 曲线形态 |
| :--- | :--- | :--- |
| $O(1)$ | 常量时间 | 一条黑色横线，跟 $n$ 再也没关系了 |
| $O(\log n)$ | 对数时间 | 绿色，稍微有点弧度，几乎紧贴着 x 轴 |
| $O(n)$ | 线性时间 | 蓝色直线，时间跟数据规模成正比 |
| $O(n \log n)$ | —— | 橙色，跟线性时间是同一档；归并排序就是这一档 |
| $O(n^2)$ | 平方时间 | 红色，幅度变化很大，非常靠上；类似的还有立方时间等等 |
| $O(2^n)$ | 指数时间 | 黑色，会在某一点之后超过前面的平方时间 |
| $O(n!)$ | $n$ 的阶乘 | 图上画不出来——画图软件放上去那条线就不对了，变化太大 |

* **低三档的读法**

    * 表格按时间复杂度从低到高排序，复杂度低的算法更好、高的更不好。

    * $O(1)$ 跟数据规模已经没有关系，数据规模再怎么增长算法执行的执行时间都是一个常数，这是最优的一种时间复杂度。

    * $O(\log n)$ 叫对数时间，因为对数的底数没有关系，以二为底还是以十为底都一样，它也是非常优秀的一档。

    * $O(n)$ 叫线性时间，意味着算法时间跟数据规模正好是成正比的，线性查找就是这一档。

* **高四档的读法**

    * $O(n \log n)$ 跟刚才的线性时间其实是一档的，归并排序落在这一档。

    * $O(n^2)$ 叫平方时间，类似的还有立方时间等等。

    * $O(2^n)$ 叫指数时间，它在之后某一点会超过平方时间，所以指数时间比平方时间还要更高一些。

    * $O(n!)$ 是 $n$ 的阶乘，画图软件真放不上去、变化太大，它应该是时间复杂度最高的。

### 档次评价

* **优秀档**

    * 常量时间 $O(1)$ 和对数时间 $O(\log n)$ 这两档都算非常优秀的算法了。

* **第二档**

    * 线性时间 $O(n)$ 和 $O(n \log n)$ 也算一档，属于第二段。

* **较差档**

    * 平方时间 $O(n^2)$、指数时间 $O(2^n)$ 和 $n$ 的阶乘 $O(n!)$ 都属于比较差的算法。

## Ω 与 Θ

### 渐近下界

* **渐近下界 $\Omega(g(n))$**

    * > **定义**：存在一个 $g(n)$ 函数，在某一个点之后它的值总是在 $f(n)$ 的下方，记作 $\Omega(g(n))$，欧米伽。

    * 它代表算法执行的最佳情况、最优情况——它能代表的时间，不能比它再好了。

### 渐近紧界

* **渐近紧界 $\Theta(g(n))$**

    * > **定义**：从某个 $n$ 开始，$g(n)$ 乘 $c_2$ 就在 $f(n)$ 的上面、乘 $c_1$ 就在 $f(n)$ 的下面，把 $f(n)$ 夹在中间，记作 $\Theta(g(n))$。

    * 它既能做上界也能做下界，既能代表算法的最差情况也能代表算法执行的最佳情况，两种情况都能代表，这就叫紧界。

    * 有了大 O 渐近上界的认识之后，再看这两个概念就非常好理解了。

### 三种记法的使用倾向

* **记法清单**

    * 学到的三种时间复杂度表示法分别是渐近上界的大 O、欧米伽 $\Omega$ 和渐近紧界 $\Theta$。

* **选用倾向**

    * 一般考试或者面试人家问的都是大 O，实际当中大家的认识上也是大 O 用得更多。

    * 实际上 $\Theta$ 更好一些，因为它既能代表算法执行的最差情况，也能代表最佳情况。

    * 写文章仍以大家习惯的大 O 为主，只是有些时候会提到 $\Theta$，出现 $\Theta$ 不必觉得奇怪。

## 空间复杂度

### 定义与统计口径

* **空间复杂度**

    * > **定义**：空间复杂度衡量一个算法随着数据规模的增大而占用的额外空间成本，它同样用大 O 表示法来表示。

    * 衡量算法好坏的第二个因素就是空间复杂度，从字面意思理解是衡量这个算法在空间占用上的好坏。

* **统计口径**

    * > **注意**：只统计**额外**空间成本，原始数据占用的空间不算在内，要看数据量越来越大了是不是要占用一些额外的空间。

    * 以二分查找为例，输入的参数其实都算原始数据，所以在"数组"和"要查找的目标"之外再看还有哪些空间上的占用。

### 二分查找的额外空间

* **局部变量的空间账**

    * 计入额外空间的是 i 指针、j 指针和循环内的 mid 中间索引：

        ```text
          额外空间  =  i 指针               4 字节
                    +  j 指针               4 字节
                    +  循环内的 mid 中间索引  4 字节
                    ---------------------------------
                      合计                  12 字节
        ```

    * 循环不会每次都产生新的 mid：在大多数语言里它这种占内存的方式会预先估算出方法内这些局部变量会占用多少空间，循环内的 mid 实际上会重用这块空间，不会循环一次就多占用一个 mid 的 4 个字节。

* **占用与数据规模无关**

    * 这部分占用也不会随着数据规模增大而增大，数组内元素变成 1 万、10 万、100 万，i、j、mid 占用的内存都不变。

    * 因此二分查找的空间复杂度是 $O(1)$，额外占用的只是一个常量的空间，就是那么 12 个字节，它不会再多占用，也不会随着 $n$ 的变化而变化。

| 时间复杂度 | 最坏情况 | $O(\log n)$ | 用大 O 表示法只考虑了上界，常数系数与多项式的低阶项都可以省略 |
| 时间复杂度 | 最好情况 | $O(1)$ | 要查找的元素正好在数组的中间索引位置，只需循环一次、比较一次，哪怕数组内有一万个元素 |
| 时间复杂度 | 平均情况 | $O(\log n)$ | 推导过程比较复杂，属于数学上的事，知道一下就可以 |
| 空间复杂度 | 额外占用 | $O(1)$ | 只额外占用常数个指针 i、j、mid |

* **平均情况的性质**

    * 平均情况与最坏情况同为 $O(\log n)$，这一档的推导过程比较复杂，属于数学上的事，只作结论而不作推导。

* **记号选择的例外**

    * > **易错点** ⚠️：二分查找不能用 $\Theta$ 紧界表示。紧界要求最坏情况、最好情况有一个共同的函数、同一个 $g(n)$，而二分查找最坏情况是 $\log n$、最好情况是常数 1，这俩不是同一个函数。
