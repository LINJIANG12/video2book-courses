# 链表算法实战：反转、删除、合并与判环

## 反转单向链表

### 头摘法：把旧链表的头搬到新链表头上

    * **头摘法**

        * > **定义**：不新建任何节点对象，把旧链表的头节点逐个摘下来，接到新链表的头部，最终得到倒序链表。

        * 三个指针各司其职：o1 是旧链表当前的头，n1 是新链表当前的头，o2 是临时变量。

        * o2 记下的不是"旧链表剩下的部分"，而是"下一次循环里 o1 该站的位置"，第 ④ 步靠它把 o1 送回原位。

        * 每轮四步的固定顺序：`o2 = o1.next` → `o1.next = n1` → `n1 = o1` → `o1 = o2`。

        * 第 ② 步让 o1 从旧链表这边"脱队"，第 ③ 步才让 n1 真正指到新搬来的节点，二者相邻且不可调换。

        * > **易错点**：少了 `n1 = o1`，n1 永远停在旧头上，结果就不是反转而是乱接。

        * 循环条件是 `o1 != null`，因为搬的就是 o1 本身，o1 为 null 即表示旧链表已搬空。

        * 返回值是 `n1`（新链表的头），不是 o1。

        * 边界：代码按"一个节点以上"写。链表为空、或只有一个节点（`o1.next == null`）时直接 `return o1`。

        * 走查：`1→2→3→4→5` 进去，`5→4→3→2→1` 出来。每搬一次 o1 往后挪一格、n1 往里塞一格，结果自然是倒序。

```java
// o1 传进来就是旧链表的头节点，只需要补一个 n1
ListNode n1 = new ListNode();      // 新链表的头，里面还没有任何节点

while (o1 != null) {               // o1 不为 null 就还有节点可搬
    ListNode o2 = o1.next;         // 先记下旧链表的第二个节点
    o1.next = n1;                   // 让 o1 接到新链表头上
    n1 = o1;                        // n1 前进到新链表的头
    o1 = o2;                        // o1 回到旧链表第一个位置
}

return n1;                          // 题目要的是新链表的头节点
```

```text
初始状态：

    o1 ──▶ [1] ──▶ [2] ──▶ [3] ──▶ [4] ──▶ [5] ──▶ null
    n1 ──▶ （空的，新链表只有个头）

搬走 1 之后：

    n1 ──▶ [1] ──▶ null
    o1 ──▶ [2] ──▶ [3] ──▶ [4] ──▶ [5] ──▶ null     （o2 原是 2）

搬走 2、3、4、5 之后：

    n1 ──▶ [5] ──▶ [4] ──▶ [3] ──▶ [2] ──▶ [1] ──▶ null
    o1 ──▶ null                                     ← 退出循环
```

### 五种解法的取舍

| 方法 | 做法 | 评价 |
| :--- | :--- | :--- |
| 方法一 | 从旧链表依次取节点，按值 `new` 出新节点加进新链表 | 最简单，但每次都创建新节点对象，内存上更浪费 |
| 方法二 | 旧链表头部移除 + 新链表头部添加 | 好理解，能复用节点对象，真正写代码一般都用这种，更面向对象 |
| 方法三 | 递归 | 单链表没有 prev 指针，找上一个节点不方便；递归把倒序天然记住了，回来时交换相邻节点即可，代码量少 |
| 方法四 | 一个链表模拟出两个链表，每次从旧链表**第二个**节点移走 | 指针一多就不好理解；能看懂 o1、n1、o2 三个指针的含义，其实也不难 |
| 方法五 | 同方法二，但不封装成方法，直接面向过程 | 跟方法二思路一模一样，代码量更少 |

    * 力扣官方给出的是方法五和递归（方法三）这两种解法，可以自己做个简单对比。

    * 判断回文时用到的 `reverse` 是方法五的收敛版，初始 `n1 = null`（新链表一开始还没有元素），循环体与上面一致。

## 哨兵与双指针站位

### 哨兵节点

    * **哨兵节点（dummy / sentinel）**

        * > **定义**：人为塞在头节点之前的工具节点，它自己的值不参与任何比较，只为保证待删节点永远有一个前驱。

        * 构造两行：`s = new ListNode(-1); s.next = head;` 值给 -1 即可，`s` 站在整个链表的头。

        * 效果：删第一个节点和删中间节点变成同一套代码，不用再开小灶。

        * > **易错点**：哨兵是自己加的工具节点，不是题目要的东西，返回时给 `s.next` 而不能把 s 交出去。

        * 更大的用处：只要头节点也可能是被删的那个，前驱就永远存在，删头节点一个分支都不用写。

        * 有序去重"一个不留"的迭代版里哨兵同样不是多余的——链表一上来就连着好几个重复值时，重复段前面压根没有节点可改 `next`。

### 在 while 条件里先赋值再判断

    * **先赋值再判断**

        * > **定义**：把 p2 的取值写进 `while` 的条件表达式，让它每一轮循环开头重新站位，而不是进循环前写死一次。

        * 适用前提：这个指针的位置从来就不是固定的，而是取决于另一个指针此刻站在哪儿。

        * 典型写法：`while ((p2 = p1.next) != null)`、`while ((p2 = p1.next) != null && (p3 = p2.next) != null)`。

        * 配套骨架：两个分支里只动 p1，p2、p3 交给循环条件刷新。

        * > **提示**：分支对称、尾部动作相同的形状是链表题里非常常见的骨架，看到就知道重复行该往哪儿合并。

### 等价写法的收敛

    * 按值删除的迭代版里，`p2 = p2.next` 可以写成 `p2 = p1.next`：删除分支中 p2 的旧 next 与 p1 的新 next 都是被删节点的后继。

    * else 分支的 `p1 = p1.next; p2 = p2.next;` 可以写成 `p1 = p1.next; p2 = p1.next;`：p1 刚前进过，它的新 next 就是原来 p2 的位置。

    * 改完后给 p2 赋值的地方从三处收敛到两处（一处初始化、两处分支），再把"每次 p2 都要平移"这行提到 if/else 外面，IDEA 会在 if 上画下划波浪线提示抽取公共部分。

    * 最后还能再合一处：循环末尾那句赋值与循环前的初始化本质相同——都是"进入循环前先把 p2 摆好"，统一放到循环开始处即可。

    * > **提示**：看到别人写的代码跟自己不一样，先别急着说谁错，去找这种等价关系：表面不同，效果完全一样。

## 删除类问题

### 按值删除节点

    * **迭代版：哨兵 + p1/p2 同步平移**

        * > **注意**：删一个节点靠的是它的上一个节点把 next 指过去，而单链表没有 prev 指针，所以设 p1 指待删节点的上一个、p2 指待删节点本身，两个指针同步后移、p1 永远慢一格。

        * 初始化：p1 指向哨兵 s，p2 指向 `s.next`。

        * 循环体只做一件事：拿 p2 的值跟目标值比；`p2 == null` 表示走完一遍，没有要删的了。

        * 命中时 `p1.next = p2.next` 把 p2 跳过去，然后 p2 继续往后找；不命中时两个指针各后移一位。

        * > **易错点**：命中删除之后 p1 留在原地不动，p2 还得往前走。两个指针写成一起平移，一旦删掉一个就等于跳过一个。

        * 返回 `s.next`。示例 `7→7→7→7` 删 7 删到最后哨兵后面没人了，返回的就是 null，正好对应空链表。

        * 示例 `1→2→6→3→6` 删 6，两个 6 都摘掉，剩 `1→2→3`。

    * **递归版：返回删干净后的链头**

        * > **定义**：返回值不是"删掉了几个节点"的数字，而是"从当前节点起、已经干净的那条链表的第一个节点"。

        * 到底（`p == null`）：直接返回 null。

        * `p.value == value`：这个节点不要了，但后面的节点不能丢，返回"从下一节点开始的那段递归结果"，等于把自己跳过去。

        * `p.value != value`：自己留下，但 next 必须更新成子递归的删干净结果，再把自己和它一起返回。

        * > **易错点**：不相等分支里的 `p.next` 更新千万别漏。原封不动返回 p，等于从这一层往下一个节点都没处理，前面几层的删除全白干。

        * 对比：迭代要两个指针加一个哨兵，递归几行收工。

```java
public ListNode deleteNode(ListNode p, int value) {
    if (p == null) {
        return null;
    }
    if (p.value == value) {
        return deleteNode(p.next, value);
    }
    p.next = deleteNode(p.next, value);
    return p;
}
```

### 删除倒数第 N 个节点

    * **题目约定**

        * n 从 1 开始计数，题目保证 $1 \le n \le \text{size}$，不会给 0、-1 或超出长度的值，非法输入不用考虑。

        * 示例：`1→2→3→4→5` 删 n=2 得 `1→2→3→5`；链表只有 `1`、n=1 删空；`1→2` 删 n=1 得 `1`。

        * 两道做法的共同点：从头到尾只往后走，没有任何指针回头去数链表有多长。

    * **递归法：返回一个"倒数位置"**

        * > **定义**：递归函数返回的不是节点而是一个整数，告诉你当前这个节点倒着数是倒数第几个。

        * 终点 null 返回 0（倒着数它算第零个），其余情况当前节点的倒数位置等于下一节点的倒数位置加一：

$$位置(p) = 位置(p.next) + 1$$

        * 命中条件是"下一节点的倒数位置等于 n"，此时执行 `p.next = p.next.next`：当前节点不再指向它，改指向它的下一个，等于跳过去。

        * 读法：若当前 p 是 3、要删的是 p.next（4），那 4 的下一个是 5，也就是 `p.next.next`。

        * 这个函数返回 int，不能套"自带方法"那套，得另写一个名字叫 `recursion` 的函数，参数两个：节点与要查的倒数第几个。

        * > **易错点**：只从 head 递归会漏删第一个节点——每个节点都在处理它的下一个，而第一个节点没有上一层调用，没人能在它上面做删除。解法是加哨兵 s 指向 head，直接拿哨兵去递归，由哨兵替它删。

        * 带哨兵后链上节点数比原来多 1，首节点也落在覆盖范围内，返回 `s.next`。

```java
public ListNode removeNthFromEnd(ListNode head, int n) {
    ListNode s = new ListNode(-1);
    s.next = head;
    recursion(s, n);
    return s.next;
}

private int recursion(ListNode p, int n) {
    if (p == null) {
        return 0;
    }
    int nth = recursion(p.next, n);
    if (nth == n) {
        p.next = p.next.next;
    }
    return nth + 1;
}
```

    * **快慢指针法**

        * 起点是一条带哨兵的链表，`p1`、`p2` 初始位置都压在哨兵上。

        * 第一段：p2 先甩开 `n + 1` 步。之所以是 n+1 而不是 n，因为真正要动手改指针的是被删节点的**前一个**，p2 必须在末尾多领先一格。

        * 第二段：两个指针齐步后移，每次各走一步，直到 `p2 == null`；此时 p1 自动停在倒数第三个——两指针之间那几格距离从头到尾没变过。

        * 收尾一句：`p1.next = p1.next.next`，让 p1 跨过它的后继。

        * 删头节点一个分支都不用写：删倒数第五个时 p2 先甩六步就直接到 null，第二段循环一次都进不去，p1 停在哨兵上，`sNode.next = sNode.next.next` 执行即完成。

        * > **易错点**：甩步循环条件是 `i < n + 1`，少写一个 `+1`，p1 就会停在被删节点自己身上而不是它的前一个。

        * 同样默认输入合法：n 得落在链表长度内，否则 p2 甩着甩着就甩到 `null.next` 上去了。

```java
public ListNode deleteNthFromEnd(ListNode head, int n) {
    ListNode sNode = new ListNode(-1);
    sNode.next = head;

    ListNode p1 = sNode;
    ListNode p2 = sNode;

    // 第一段：p2 先甩开 n + 1 步
    for (int i = 0; i < n + 1; i++) {
        p2 = p2.next;
    }

    // 第二段：齐步后移，保持距离，直到 p2 走到 null
    while (p2 != null) {
        p1 = p1.next;
        p2 = p2.next;
    }

    p1.next = p1.next.next;
    return sNode.next;
}
```

```text
  dummy -> 1 -> 2 -> 3 -> 4 -> 5 -> null
    ^      ^
    p1     p2

  p2 先甩开 n+1 = 3 步:

  dummy -> 1 -> 2 -> 3 -> 4 -> 5 -> null
    ^                ^
    p1               p2

  齐步后移两轮:

  dummy -> 1 -> 2 -> 3 -> 4 -> 5 -> null
                     ^              ^
                    p1             p2

  p2 走到 null，p1 停在倒数第三个，执行 p1.next = p1.next.next:

  dummy -> 1 -> 2 -> 3 -> 5 -> null
```

### 有序链表去重

    * **前提**

        * 两道题的前提都是链表已**升序排列**；一道重复的只留一个，另一道重复的一个不留，别到时候串了。

    * **重复的只留一个**

        * 迭代版：设两个相邻指针，p1 指第一个元素、p2 指第二个元素，每次比较两者 `value`。

        * 相等则删掉 p2 指向的节点且 **p1 原地不动**；不等则两个指针各后移一位。

        * > **易错点**：删掉 p2 之后 p1 绝对不能跟着走。被删的只是一串重复里的最后一个，p1 得留在原地盯着**同一个值**继续比，否则碰上 `1 1 1` 只能删掉一个。

        * 兜底：`head == null` 或 `head.next == null` 时谈不上重复，直接返回 head，节点数小于二不走这套分析。

        * 递归版返回"从当前节点起、完成去重后的那一条链表"：当前节点与 next 值重复就丢掉自己、从下一节点接着递归；不重复则保留自己并把 next 更新成"从下一节点开始去重后的结果"。

        * 递归出口同样是空链返回空、只剩一个节点（`p.next == null`）返回节点自身。

        * > **易错点**：`p.next = deleteDuplicates(p.next)` 这一句不能省。删节点的动作是靠返回值把链表重新缝起来完成的。

    * **重复的一个不留**

        * 递归版：`p.val == p.next.val` 时，另起一个 x 从 `p.next` 起步一路跳过所有与 p 同值的节点，找到第一个不一样的节点，以它为准继续递归；不重复则保留自己并接去重后的子链表。

        * > **易错点**：跳过重复段的 `while` 必须带 `x != null` 条件。整条链表全是同一个值时（如 `1→1→1`），x 会一路走到 null 才停，少了这个判断指针就跑到 `null.next` 上去了。

        * 迭代版用三个指针：p1 是将要被删节点的前一个、p2 是当前正在判定的节点、p3 是 p2 的下一个；初始 p1 指哨兵、p2 指第一个节点、p3 指第二个节点。

        * p2 与 p3 相等时，p3 一直后移到值不同的节点上，然后 `p1.next = p3`，把 p2 开头的那一整段重复一次性摘下；不等时只挪 p1，p2、p3 下一轮重新赋值时自然跟上。

        * > **注意**：`p1.next = p3` 这一行就是整个算法的全部——它不是删一个节点，而是把一整段重复从链上摘下来，一行到位，不管这段里到底有几个。

        * > **易错点**：内层 while 的循环体在推进写法下是空的，这是**故意**的，p3 的推进写在循环条件里；别以为是漏了代码就往里塞一条推进语句，那样一轮会跳两格。

| | 重复的只留一个 | 重复的一个不留 |
| :--- | :--- | :--- |
| 输入 | `1→1→2→2→3→3` | `1→1→1→2→3` |
| 输出 | `1→2→3` | `2→3` |
| 遇到当前节点与 next 相等 | 摘掉 next，当前节点留下 | 当前节点连同它那一整段一起摘掉 |
| 示例 | `1→2→3→3→4→4→5` → `1→2→5` | 同上例中三重复了删掉、四重复了也删掉 → `1→2→5` |

## 合并类问题

### 合并两个有序链表

    * **迭代：谁小谁进新链表**

        * 新链表初始就是一个哨兵 `s`，另声明尾指针 `p` 指向 s；原来的两条链表叫 p1、p2。

        * 每轮比一次，谁小就接到新链表尾部，然后那个小的指针后移一位、`p` 也后移一位。

        * 循环条件是 `p1 != null && p2 != null`，不管哪条到头了都该结束。

        * > **注意**：退出后不用再一个一个比较。每轮挑走的就是当前全局最小，剩下的元素只会更大，整段照搬即可。

        * 尾部两个 `if (p1 != null) p.next = p1;` 与 `if (p2 != null) p.next = p2;` 是对称的，两条都空时合并结果也是空。

        * `p = p.next` 在两个分支里一模一样，重复代码没有价值，提到 if/else 外面。

    * **递归：返回小的，把它的 next 接上内层结果**

        * 终止条件：其中一个为 null 就直接返回另一个原样交出去。

        * 两点规矩：一是每次递归返回更小的那个节点，并把它的剩余部分跟另一条链表继续递归比较；二是在交出这个节点之前，先把它的 `next` 更新成内层递归的返回值。

        * 走查 `1→3→8→9` 与 `2→4`：依次返回 1、2、3、4；最后一次 p2 已空，直接返回 8，而 8 的 next 自动就带着 9。

        * 再往上一层一层接起来：8、9 应作为 4 的 next，4 在真正返回之前要先把 next 指向内层结果，依此类推链表就重新链好了。

        * > **易错点**：`p1.next = merge(...)` 和 `return p1` 的顺序不能颠倒——先把 next 接对，再把 p1 交出去当链头。反过来写，返回的就是一条断掉的链表。

```java
public ListNode mergeTwoLists(ListNode p1, ListNode p2) {
    ListNode s = new ListNode(-1);   // 新链表的哨兵
    ListNode p = s;                  // p 一直指向新链表的尾

    while (p1 != null && p2 != null) {
        if (p1.val < p2.val) {
            p.next = p1;
            p1 = p1.next;
        } else {
            p.next = p2;
            p2 = p2.next;
        }
        p = p.next;                  // 分支对称、尾部动作相同
    }

    if (p1 != null) {
        p.next = p1;
    }
    if (p2 != null) {
        p.next = p2;
    }

    return s.next;
}

public ListNode merge(ListNode p1, ListNode p2) {
    if (p1 == null) {
        return p2;
    }
    if (p2 == null) {
        return p1;
    }
    if (p1.val < p2.val) {
        p1.next = merge(p1.next, p2);
        return p1;
    } else {
        p2.next = merge(p1, p2.next);
        return p2;
    }
}
```

### 合并多个升序链表

    * **题目形态**

        * 输入是若干条升序链表统一放进的一个数组，输出是合并后的一条同样升序的链表。

        * 示例 `[1,4,5]`、`[1,3,4]`、`[2,6]` 合成 `1 1 2 3 4 4 5 6`。官方难度定的是困难，实际只要会合并两个，合并多个并不更难。

        * 合并两个的实现直接从前面的题拷过来即可，递归或非递归都行；实测**非递归实现效率更高一些**。

    * **必须新写一个带边界的递归函数**

        * > **注意**：不能直接拿题目给的那个方法去做递归——它只带一个参数，没有左右边界，而这里要记录左右边界，必须另写一个 `split`。

        * `split(lists, i, j)` 返回 `lists[i..j]` 这一段合并后的链表，接收原始数组与左右边界。

        * 结束条件是**左右边界重合**（`i == j`），此时区间里只有一条链表，直接 `return lists[i]`（返回 `lists[j]` 也一样，反正此时两者相等）。

        * > **易错点**：结束条件不是 `i > j`，而是 `i == j`；写错就会漏掉最后一条链表的合并。

        * 中间点 `m = (i + j) / 2`，第一次递归管 `i..m`，第二次管 `m + 1..j`。

        * 入口处数组为空时直接返回 null，最终合并结果就是一条空链表。

        * 例：数组长度 5 时 `i = 0`、`j = 4`，`m = (0 + 4) / 2 = 2`，区间被分成 `0~2`（三条链表）与 `3~4`（两条链表）两段。

        * 两边各自返回 left 与 right，最后丢给 `mergeTwoLists` 一行收口。

| 合并步骤 | 两个区间 | 结果 |
| :--- | :--- | :--- |
| 左半第一刀 | `[1,3]` + `[4,8]` | `[1,3,4,8]` |
| 左半第二刀 | `[1,3,4,8]` + `[2,5]` | `[1,2,3,4,5,8]` |
| 右半 | `[2,6]` + `[3,7]` | `[2,3,6,7]` |
| 收口 | `[1,2,3,4,5,8]` + `[2,3,6,7]` | `[1,2,2,3,3,4,5,6,7,8]` |

```java
public ListNode mergeKLists(ListNode[] lists) {
    if (lists.length == 0) {
        return null;
    }
    return split(lists, 0, lists.length - 1);
}

private ListNode split(ListNode[] lists, int i, int j) {
    if (i == j) {
        return lists[i];
    }
    int m = (i + j) / 2;
    ListNode left = split(lists, i, m);
    ListNode right = split(lists, m + 1, j);
    return mergeTwoLists(left, right);
}
```

### 分而治之与减而治之

    * **分而治之（divide and conquer）**

        * **分**：原始问题被切成多个子问题，且每个子问题的规模比原来小；合并多个升序链表的例子里规模恰好减少一半，因为 m 取的是中间点。

        * **治**：一直切分到问题能被解决为止。本例切到 `i..j` 里只剩一条链表时直接返回它，让它去跟别的结果合并。

        * **和**：各子问题各自返回结果后，把它们合并在一起——本例中第一个子问题返回 left、第二个返回 right。

        * 凡是多路递归都或多或少体现分治思想，最早的多路递归斐波那契也是拆成两个子问题、求解后合并结果。

    * **减而治之（decrease and conquer）**

        * 可以看成是分而治之的一种特例，相当于**单路递归**：不拆成两个以上子问题，只是规模比原来小。

        * 它只有一个「减」，没有「分」，自然也没有「和」。

        * 著名例子是**递归实现的二分查找**：每次把区间砍掉一半，砍到只剩一个元素直接返回。

| | 分而治之 | 减而治之 |
| :--- | :--- | :--- |
| 拆几个子问题 | 两个或更多 | 只剩一个（不拆） |
| 子问题规模 | 比原来小（常为一半） | 比原来小 |
| 有「和」这一步吗 | 有，要合并各子问题结果 | 没有 |
| 典型例子 | 合并多个升序链表、斐波那契 | 二分查找 |

## 快慢指针

### 查找链表的中间节点

    * **中间的定义**

        * 奇数个节点取正中间那个：`1 2 3 4 5` 取 `3`。

        * 偶数个节点两个都算，但取**靠右**的那个：`3` 和 `4` 中以 `4` 为中间节点。

    * **一走一步与一走两步**

        * 慢指针 `p1` 一次走一步，快指针 `p2` 一次走两步，两个都从 head 出发。

        * 奇数 5 个：初始 p1@1 p2@1 → 第 1 轮 p1@2 p2@3 → 第 2 轮 p1@3 p2@5，此时 `p2.next` 是 null，到头退出，p1 指向 3。

        * 偶数 6 个：第 3 轮时 p1@4、p2 本身是 null，到头退出，p1 指向 4。

        * 退出条件有两种：只要 `p2` 的 next 是 null，或者 `p2` 本身是 null，都算走到头——所以条件要写两个判断。

        * > **易错点**：循环条件里 `p2 != null` 一定要写在 `p2.next != null` 前面。`&&` 是短路运算符，会先执行前面的条件判断；`p2` 已经等于 null 时后半部分不执行，才不会出空指针。

        * `p2 = p2.next.next` 也可以写成 `p2 = p2.next` 写两遍，效果一样。

        * 这道题用快慢指针最好理解，效率也最高。

```java
public ListNode middleNode(ListNode head) {
    ListNode p1 = head;   // 慢指针
    ListNode p2 = head;   // 快指针

    // p2 != null 必须写在前面
    while (p2 != null && p2.next != null) {
        p1 = p1.next;
        p2 = p2.next.next;
    }

    return p1;
}
```

### 判断回文链表

    * **题意与难度**

        * > **定义**：正着读、反着读效果一样的链表就是回文；`1→2→2→1`（1221）与 `1→2→3→2→1`（12321）是回文，`1→2` 不是。

        * 题目要求 $O(n)$ 时间复杂度、$O(1)$ 空间复杂度。

        * 力扣把它定成简单，但实际应该定中等：要真达到这个目标解起来比较麻烦，因为它综合了找中间点与反转链表等多种解法。

    * **基础解法：三步走完**

        * 步骤一：找到这个链表的中间点；步骤二：把中间节点之后的半个链表反转；步骤三：把反转后的这半个链表跟原始链表逐元素比较，全部相同就是回文。

        * 走查偶数 `1→2→2→1`：中间点（靠右）= 2 → 后半段 `2→1` 反转成 `1→2` → 逐对比较 1 vs 1、2 vs 2 全同 → true。

        * 走查奇数 `1→2→3→2→1`：中间点 = 3 → 后半段 `3→2→1` 反转成 `1→2→3` → 三对全同 → true。

        * 反例 `1→2→3`：后半段反转过来跟前半段一比就发现不一样，立即返回 false。

        * 半截链表都遍历完还没发现不同，才能证明是回文。奇偶唯一的区别是奇数时中间节点算前半截的尾巴，反转时从中间节点的下一个开始算。

        * > **提示**：比较循环的条件只看 `newHead` 就够了，因为它比较短（只有半条链表），更长的原始链表不用额外做非空判断。

    * **优化解法：把前两个循环合成一个**

        * 分段成本：找中间点那一段要一直遍历到快指针走到链表末尾；反转那一段的循环次数其实是链表的一半；比较那段没法优化了。

        * 所以要动的是前两段——把「找中间点」和「反转」放进同一个循环；转向在于这一回反转的是**前半个链表**而不是后半个。

        * 以 `1221` 为例，快慢指针一趟跑完，慢指针停在中间节点 2 上、快指针走到结尾；顺手把慢指针**前面那部分**反转掉，等找到中间点时前半段已经变成新链表 `n1`。

        * 拿哪一段反转不影响判回文——把反转后的新链表跟从慢指针开始的后半段逐一比较即可。

        * 步骤缩成两个：步骤一在一个循环里既找中间点又反转前半个链表；步骤二把反转后的前半个链表跟从中间点开始的后半个链表逐一比较。

        * 等价关系：反转时用来记录旧链表"老二"的临时变量 `o2` 完全可以由慢指针 `p1` 来当——`p1` 与 `o1` 每轮同步前进，一开始都指向 head。

        * 优化前后对比：优化前执行耗时 4ms，只击败 80% 多的用户，测试用例全过却拿不到高分。

    * **奇数个节点为什么判错**

        * `1221` 偶数用例改完返回 true，但 `12321` 返回了 false：反转后的 `n1` 是 `2→1`，从慢指针开始的后半段是 `3→2→1`，第一个 2 跟 3 一比就不一样。

        * 原因：奇数个节点时退出快慢指针循环的那一刻，**慢指针恰好停在那个独一无二的中间节点上**，而反转的是慢指针之前那一段，中间节点本身没被摘进 `n1`，拿长度差一截的左右两段去比自然比不整齐。

        * 偶数个节点不会有这个问题，因为退出循环前最后一次迭代已经把慢指针所在的那个节点摘进 `n1` 了，两边正好等长。

        * 修法：判断出是奇数个节点就让 `p1` 从它的后一个节点开始比，即先 `p1 = p1.next` 再跟 `n1` 比。

        * 奇偶的判据有规律：退出快慢指针循环时，若是奇数个节点，快指针 `p2` 肯定不为 null（它自己的 next 是 null 但它本身不是）；偶数个节点时 `p2` 就是 null。

        * 去掉打印后再提交耗时 2ms，击败 100% 的用户；中途出现的 5ms 版本是因为代码里多了两行打印。

        * > **注意**：优化的核心是把「找中间点」和「反转前半个链表」合进同一个循环，三个 while 缩成两个；循环总遍历量仍与链表长度成正比（$O(n)$），全程只用几个指针变量，额外空间 $O(1)$。

```java
while (n1 != null) {
    if (n1.val != p1.val) {
        return false;          // 只要有一处不等，就不是回文
    }
    n1 = n1.next;
    p1 = p1.next;
}
return true;
```

## 判环：龟兔赛跑算法

### 无环与有环的形状

```text
【无环】
n1 -> n2 -> n3 -> n4 -> n5 -> null
 ^
 |
起点（head）


【有环】
n1 -> n2 -> n3 -> n4 -> n5
               ^        |
               +--------+
            环入口 = n4
```

    * 差别只在一个地方：尾节点的 next 是 null，还是指回了链条中间某一个节点。

    * > **定义**：有环链表的特点是——链表中任意节点的 next 都不为空，所有的 next 值都由它指向链表中真实存在的另一个节点。

    * 之所以要算法，是因为代码只有一个 head，它必须一步一步走下去才知道，没有整条链路的形状。

### 龟兔赛跑第一阶段：判环

    * **算法描述**

        * > **定义**：弗洛伊德龟兔赛跑算法（Floyd's cycle-finding algorithm）——如果链表存在环，那么在环上以不同速度前进的两个指针，必定会在某个时刻相遇。

        * 第一阶段：龟一次走一步，兔子一次走两步。兔子若能走到终点说明不存在环；兔子能追上龟说明存在环。

        * > **注意**：两个速度不同的指针在一条没有环的链子上永远追不上——兔子每走两步龟就走一步，两者间距只会越来越大；差距随步数累积，但链路有限、没有回头路，兔子一定先撞到 null 上。

        * 有环时的走位：龟走一步兔子走两步，这样不断往下，兔子追上龟就表示链表中确实存在环。

    * **代码要点**

        * 兔子 `h` 一次走两步，龟 `t` 一次走一步，每轮走完后判 `h == t`。

        * 循环条件写两个判断：`h != null && h.next != null`。

        * > **易错点**：只写 `h != null` 不够。兔子一次要走两步，如果它的 next 已经是 null，`h = h.next.next` 就会出现空指针，所以条件里要再加 `h.next != null`。

        * 相遇判定用 Java 的 `==` 而不是值比较，因为这里比的是"是不是同一个对象"而不是"值是否相等"。

        * 循环结束（兔子走到终点）还没相遇，说明没有环，返回 false。

        * 测试：十二个节点的链 `n1..n12`，`n12.next = n8` 形成环时返回 true；去掉这一句让 `n12.next = null` 时返回 false。

### 两条结论与第二阶段的原理

    * **两个量**

        * 设起点到环入口的距离为 $a$，绕环一圈的长度为 $b$；例中 $a = 7$、$b = 5$，`n12` 的 next 指回 `n8`，于是 `n8 → n9 → … → n12 → n8` 闭合成环。

    * **结论一：a 加上绕环整数圈都能命中环入口**

        * 从链表起点出发，走 $a$ 加上绕环 $n$ 圈都能找到环入口：

$$a + n\cdot b$$

        * 绕环一整圈回到原地，在环入口绕几圈都还站在环入口，所以 $a$ 加上 $b$ 的整数倍都落在环入口上。

        * 这个结论听上去平常，但它是整个证明的支点。

    * **结论二：龟第一次相遇时恰好绕环 n 圈**

        * 兔子必须先走完直线距离 $a$，只有在绕圈过程中才可能追上龟，之后又绕 $n$ 圈再加多出来的 $k$ 步（例中绕了两圈，再走一、二、三步才追上）。

        * 龟的距离类似：走完 $a$、绕环 $n$ 圈（例中还没绕满一圈，本质是零圈）、再加同一个 $k$。

        * 兔子每次走两步、龟走一步，所以两者距离成二倍关系，相减后 $a$ 与 $k$ 都被消掉，只剩绕环 $n$ 圈：

$$\text{兔} = 2\cdot\text{龟} \quad\Longrightarrow\quad \text{兔} - \text{龟} = \text{龟}$$

        * 例中环长为 5，第一次相遇时龟正好走了 10 步，就是绕环两圈。

    * **两条结论怎么合起来**

        * 龟在相遇点已走了 $n\cdot b$ 步，若在此基础上再走 $a$ 步就落到环入口，因为 $n\cdot b + a = a + n\cdot b$，与"从起点出发走 $a + n\cdot b$"完全相等。

        * 但 $a$ 对我们来说是未知的，不知道该再走几步；让兔子帮忙——龟回到起点，兔子留在原位充当原来的龟。

        * 对留在相遇点的"假龟"来说，走 $a$ 步能到环入口；对从起点出发的龟来说，走 $a$ 步同样到环入口。两者同步推进，必然在入口再次相遇。

        * > **注意**：第二阶段的"魔法"就是把一个未知长度 $a$ 的问题，转化成两个都能独立推进的进程。

### 第二阶段的代码与首尾相接的坑

    * **算法描述**

        * 从龟兔第一次相遇开始，让龟回到起点、兔子保持原位不变，然后两者每次各走一步，再次相遇的地点就是环的入口。

    * **找环入口的写法**

        * 第一阶段的代码要原样搬过来，因为第二阶段依赖第一次相遇的位置；这个版本在没找到环时返回 null 而不是 false。

        * `t = head` 就是龟回到起点，兔子指针的值不用动；内层 `while (t != h)` 里两个各走一步，退出时 `t == h`，返回 t 或 h 都行。

        * > **提示**：因为无环时返回的是 null，就不要再点它的 value 了，不然又是一个空指针。

    * **首尾相接的环会把算法骗过去**

        * 环首尾相接时尾节点指向头节点，整个链表就是一个大环，环入口应该是 n1，此时 $a = 0$。

        * 按算法描述，第一阶段相遇后让龟回到起点——这时龟就在起点、兔子也在起点，两者已经相遇；可代码不管三七二十一先各走一步，立刻相遇后就判定出节点二是环入口。

        * > **易错点**：正确答案是节点一。代码的执行顺序比算法描述多走了一步，数学推导没错，错在没把"回到起点"这个动作本身当成一次相遇判定。

        * 修法很简单：先不要让它俩前进一步，`t = head` 之后先判一次 `if (t == h) return t;`，只有没重合才进 while 循环。改完所有测试用例都能通过。

        * 龟兔赛跑只是检测环的一种算法，此外还有别的算法。

```java
public boolean hasCycle(ListNode head) {
    ListNode h = head;   // 兔子：一次走两步
    ListNode t = head;   // 龟：  一次走一步

    while (h != null && h.next != null) {
        t = t.next;
        h = h.next.next;

        if (h == t) {          // 指向同一个节点对象，说明相遇了
            return true;
        }
    }
    return false;              // 兔子走到了终点，全程没相遇
}

public ListNode detectCycle(ListNode head) {
    ListNode h = head;
    ListNode t = head;

    while (h != null && h.next != null) {
        t = t.next;
        h = h.next.next;
        if (h != t) {
            continue;
        }

        t = head;                       // 龟回到起点，兔子原地不动

        // 关键：先判一次。龟回到起点时可能已经和兔子重合了
        if (t == h) {
            return t;
        }

        while (t != h) {                 // 每次各走一步
            t = t.next;
            h = h.next;
        }
        return t;
    }
    return null;
}
```

## 合并两个有序数组

### 题目形态的改造

    * 力扣 88 题原题给的是两个**不同**数组 `[1,2,3,0,0,0]` 与 `[2,5,6]`，把全部元素塞回 nums1（那三个 0 是预留空位），结果 `[1,2,2,3,5,6]`。

    * 改后的版本是**同一个数组内的两个有序区间**：`[1,5,6]` 与 `[2,4,10,11]` 合并成 `[1,2,4,5,6,10,11]`，元素个数不变，结果仍存回原数组。

    * 改它的理由：两个区间**起点终点已知**，跟后面要讲的归并排序联系更紧密，而原题跟归并排序没有直接联系。

### 递归函数的七个参数

| 参数 | 含义 | 本例取值 |
| :--- | :--- | :--- |
| `a1` | 原始数组 | `{1, 5, 6, 2, 4, 10, 11}` |
| `i` / `iN` | 第一个有序区间的**起点**与**终点** | `i = 0`、`iN = 2`（对应 `1,5,6`） |
| `j` / `jN` | 第二个有序区间的**起点**与**终点** | `j = 3`、`jN = 6`（对应 `2,4,10,11`） |
| `a2` | 保存合并结果的数组 | 与 `a1` 等长，`a1` 有多少元素它就有多少 |
| `k` | `a2` 当前的写入索引 | 从 `0` 开始 |

    * 思路：比较两个区间起点 `a1[i]` 与 `a1[j]`，谁更小就把小的**复制**到结果数组 `a2`，每放一个 `k` 前进一格。

    * > **提示**：注意是**复制**不是移动。复制之后那个 `1` 其实还在 `a1` 里，只不过 `i` 这个位置变了。

### 每一轮只做一件事

| 轮次 | `a1[i]` | `a1[j]` | 取出的值 | 动作 | `a2` 现状 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | 1 | 2 | 1 | `i` 更小，`i++` | `[1]` |
| 2 | 5 | 2 | 2 | `j` 更小，`j++` | `[1,2]` |
| 3 | 5 | 4 | 4 | `j` 更小，`j++` | `[1,2,4]` |
| 4 | 5 | 10 | 5 | `i` 更小，`i++` | `[1,2,4,5]` |
| 5 | 6 | 10 | 6 | `i` 更小，`i++` | `[1,2,4,5,6]` |
| 6 | `i` 越界 | 10 | 10、11 | 整段复制，**return** | `[1,2,4,5,6,10,11]` |

    * 某个区间被取空时，剩下的元素必然更大，把另一个区间剩余的部分直接复制到 `a2` 即可，不用再比较。

    * 区间走空的判据就是索引越过终点：`i` 已经移动到索引 3 而 `iN` 是 2，就说明第一个区间内没元素了；`j` 越过 `jN` 同理。

    * 结束条件：剩余元素复制完就不再递归调用 merge。

    * > **易错点**：整段复制之后直接 `return`，内部再不用调用 merge——照着示意图继续递归是错的。

    * 这两个分支完全对称，会写一个剩下一个照着写就行。

### arraycopy 的五个参数与回写

| 参数 | 含义 | 复制第二个区间剩余元素时的取值 |
| :--- | :--- | :--- |
| 1 | 原始数组是谁 | `a1` |
| 2 | 在源数组的起始索引 | `j` |
| 3 | 目的数组是谁 | `a2` |
| 4 | 在目的数组的起始索引 | `k` |
| 5 | 复制的元素个数 | `jN - j + 1` |

    * > **提示**：元素个数要**加一**。`jN` 指向 `11`（索引 6）、`j` 最后指向 `10`（索引 5），$6 - 5 = 1$，加上一才是这个区间内的元素个数。

    * 想把结果更新回原数组，再来一次 `System.arraycopy(a2, 0, a1, 0, a2.length)` 即可，`a1` 的值就变成 `1 2 4 5 6 10 11`。

    * 调用示例：`merge(a1, 0, 2, 3, 6, a2, 0)`，其中 `a2 = new int[a1.length]` 与原数组等长。

```java
public static void merge(int[] a1, int i, int iN, int j, int jN, int[] a2, int k) {
    // 第一个区间被取空了，第二个区间剩下的整段搬过去
    if (i > iN) {
        System.arraycopy(a1, j, a2, k, jN - j + 1);
        return;                       // 已经结束了，剩下的递归代码不用执行
    }

    // 第二个区间被取空了，对称的情况
    if (j > jN) {
        System.arraycopy(a1, i, a2, k, iN - i + 1);
        return;
    }

    // 谁小取谁：取完谁前进一格，结果数组的写入位置也前进一格
    if (a1[i] < a1[j]) {
        a2[k] = a1[i];
        i++;
        k++;
    } else {
        a2[k] = a1[j];
        j++;
        k++;
    }

    merge(a1, i, iN, j, jN, a2, k);
}
```
