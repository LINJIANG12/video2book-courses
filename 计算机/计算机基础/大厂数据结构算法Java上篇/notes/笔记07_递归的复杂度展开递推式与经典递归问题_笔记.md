# 递归的复杂度：展开递推式与经典递归问题

## 快速排序最坏情况的展开法

* **最坏情况下的快速排序递推式**

    * > **定义**：分区没分好时虽然仍拆成两个子问题，但一个子问题分了 $n-1$ 个数、另一个只分了一个数，形成极端不平衡。

    * $$T(n) = T(n-1) + c + n$$

    * $T(n-1)$：剩下那个大的子问题，含 $n-1$ 个数。

    * $c$：$T(1)$，递归到头时的常数。

    * $n$：分区操作所占用的时间。

    * > **提示**：每一层末尾的 `c + n` 都要保留，别一上手就当成低阶项扔掉。展开法最后能冒出 $n^2$，靠的就是这些看起来可以扔的小项一层层累加。

* **展开过程**

    * 每展开一层，前面的 $T$ 减一号，尾部就多攒一个 $c$ 和一个递减的 $n$，一直到 $T(1)$ 才停下来。

    ```text
    T(n) = T(n-1) + c + n
          = T(n-2) + c + c + n + (n-1)
          = T(n-3) + c + c + c + n + (n-1) + (n-2)
          = ...
          = T(1) + c×(n-1) + [ n + (n-1) + (n-2) + ... + 3 + 2 ]
    ```

    * $c$ 的个数可以直接数出来：最开始一个，展开到 $T(n-1)$ 又一个，到 $T(n-2)$ 是两个，到 $T(n-3)$ 是三个。

    * 把最后写成 $T(n-(n-1))$ 而不是 $T(1)$，就是为了让规律看得更清楚：减到 $n-(n-1)$ 时 $c$ 的个数正好是 $n-1$ 个。

    * 除 $c$ 外的 $n$、$(n-1)$、$(n-2)$ 又是一个从 2 开始的等差数列，$2+3+4$ 一直加到 $n$。

* **化简**

    * 三部分合并后：$$T(n) = cn + \frac{1}{2}n^2 + \frac{1}{2}n - 1$$

    * 化简时去掉一次项、去掉常数项、再去掉常数系数 $\frac{1}{2}$，最后剩下 $n^2$。

    * > **结论**：快速排序一旦落到分区没分好的极端情况，时间复杂度达到 $O(n^2)$，与冒泡排序相同。这里分析的是最差情况。

## 在线递推求解器

* **在线递推求解器（online recurrence solver）**

    * > **定义**：把递推式和终止条件输进去，由工具直接算出闭式解的在线计算器。

    * 用法：递推式加上终止条件两个式子，中间用逗号隔开，粘贴时选粘贴输入的那个选项，回车即开始计算。

    * 它最有价值的用法不是替你算，而是替你**检查**：自己推导错了可以拿它跑一遍对答案。

* **三个递推式的求解结果**

    | 递推式 | 终止条件 | 求解结果 | 时间复杂度 |
    | :--- | :--- | :--- | :--- |
    | $T(n)=T(n-1)+c$ | $T(1)=c$ | $cn$ | $O(n)$ |
    | $T(n)=T(n-1)+n$ | $T(1)=c$ | $c+\frac{1}{2}n^2+\frac{1}{2}n-1$ | $O(n^2)$ |
    | $T(n)=T(n-1)+n+c$ | $T(1)=c$ | $cn+\frac{1}{2}n^2+\frac{1}{2}n-1$ | $O(n^2)$ |

    * 三行的求解结果与手算推导完全一致，包括末项的 $-1$。

## 递归之外的那部分开销

* **只看递归次数的口算结论**

    * 斐波那契的 $1.618^n$ 结论只盯着 $T(n-1)$ 和 $T(n-2)$ 两路递归的次数，忽略了递归以外的其他计算。

    * 主定理的角度看，整个算法占用的时间是分成「递归部分」和「递归以外的部分」的，之前只算了递归部分。

    * 被忽略的恰恰是一次加法运算：数字小的时候可以当成常数级时间，数字越来越大时就不行了——两个特别大的数字相加，加法本身占用的时间也得算进去。

    * 把大数相加考虑进去后，时间复杂度不再是 $1.618^n$，而是比它更大的一个数。

    * > **易错点**：凡是递归里带有**大整数运算**（加、乘、比较）的算法，用「只看递归次数」的口算结论时要留个心眼。判断某项运算是不是 $O(1)$，取决于它的参数规模会不会随 $n$ 一起长。

## 汉诺塔的移动规律

* **汉诺塔（Tower of Hanoi）**

    * > **定义**：把按大小摞好的一摞圆盘从一根柱子整体搬到另一根柱子的经典递归问题。

    * 传说背景：大梵天创建世界时做了三根金刚石柱，其中一根从下往上按大小顺序摞着 64 片黄金圆盘，大的在下面、小的在上面，另外两根起初是空的；大梵天命令婆罗门把这些圆盘重新摆到另一根柱子上。

    * 两条规定：一次只能移动一个圆盘；小圆盘上不能放大圆盘。

    * 题目要求：用程序代码模拟圆盘的移动过程，并估算时间复杂度。

* **柱子与圆盘的命名约定**

    * 三根柱子起名 `a`、`b`、`c`；每个圆盘用数字表示大小，1 号最小。

    * 目标是把这摞圆盘从 `a` 移到 `c`。

* **从少到多找规律**

    * 一个圆盘：直接从 `a` 移到 `c`，是最小问题，可直接求解。

    * 两个圆盘：先把 1 号移到 `b`，2 号腾出手从 `a` 移到 `c`，再把 1 号从 `b` 移到 `c`。

    * 三个圆盘：先把 1、2 从 `a` 移到 `b`，3 号腾出来从 `a` 移到 `c`，再把 1、2 从 `b` 移到 `c`。

    * 四个圆盘：前三个先从 `a` 移到 `b`，4 号从 `a` 移到 `c`，再把前三个从 `b` 移到 `c`。

* **三步通用骨架**

    ```text
    第 1 步：A --(借助 C)--> B     前 n-1 个盘子先让路
    第 2 步：A -------------> C   第 n 个盘子直接过去
    第 3 步：B --(借助 A)--> C   前 n-1 个盘子归位
    ```

    * 为了把 $n$ 个盘子从 `a` 移到 `c`，必须先把前 $n-1$ 个从 `a` 移到 `b`，第 $n$ 个才能从 `a` 移到 `c`，最后再把前 $n-1$ 个从 `b` 移到 `c`。

    * 解第 $n$ 个盘子的移动过程依赖前面 $n-1$ 个的移动过程，所以用递归求解比较合适。

## 用 LinkedList 表示柱子

* **柱子与圆盘的内存表示**

    * 用 `LinkedList` 代表一根柱子，三个集合分别对应 `a`、`b`、`c`。

    * 集合里的元素代表圆盘，元素类型选整数，数字小的代表小圆盘，数字大的代表大圆盘。

    * 约定：大的圆盘放下面、小的圆盘放上面，所以用集合的靠前位置代表柱底、靠后代表柱顶。

    ```text
            A              B              C
          ┌───┐          ┌───┐          ┌───┐
          │ 3 │          │   │          │   │
          ├───┤          │   │          │   │
          │ 2 │          │   │          │   │
          ├───┤          │   │          │   │
          │ 1 │          │   │          │   │
          └───┘          └───┘          └───┘
       集合下标 0 1 2                  集合为空
       （底部在左，顶部在右）
    ```

* **`init` 方法：初始化一根柱子**

    * 接受参数 `n` 代表这根柱子上要加的圆盘个数。

    * 往集合尾部添加即往柱顶添加，所以先添加最大的 `n`，再让 `i` 一直减到 1，共 $n$ 个圆盘。

    * `init(3, a)` 之后打印 `a` 的结果是 `3 2 1`；`b` 和 `c` 为空表示柱子上还没有加圆盘。

* **移动一个圆盘**

    * 从柱顶移走再用 `addLast` 加到目标柱顶，两步就完成了「把一个圆盘从一根柱子移到另一根柱子」。

    ```java
    int disk = a.removeLast();  // 先把元素从顶端移走，返回的就是被移除的那个元素
    b.addLast(disk);            // 再把它加到 b 的顶端
    ```

* **`print` 方法的抽取**

    * 打印这块因为要用到很多次，所以在 IDE 里用 `refactor → extract method` 抽成一个叫 `print` 的方法。

    * 抽取后就有了「如何移动圆盘」和「如何打印柱子状态」两个方法。

## `move` 方法的递归结构

* **`move` 方法的四个参数**

    * 参数 `n` 代表圆盘个数。

    * 另外三个参数分别代表三根柱子，类型都是 `LinkedList`：`a` 原始柱子、`b` 中间借助的柱子、`c` 最终目标的柱子。

* **中间那一步可以直接求解**

    * 它只移动一个圆盘，而移动一个圆盘可直接求解：从 `a` 先 `removeLast()` 移走，再 `c.addLast()` 加到目标去。

* **两处递归调用的参数顺序**

    * 第一步递归 `move(n - 1, a, c, b)`：这回目标不一样了，要把 $n-1$ 个盘子从 `a` 借助 `c` 移到目标 `b`，所以参数顺序要调整。

    * 第三步递归 `move(n - 1, b, a, c)`：$b$ 得借助 `a` 才能移到 `c`。

* **结束条件与打印时机**

    * `n` 等于 0 表示没有盘子可移，加一个 `if` 判断直接 `return`。

    * 每次真正执行完中间这步之后盘子状态变了，就把状态打印出来。

* **完整实现**

    ```java
    import java.util.LinkedList;

    public class HanoiDemo {

        /** 初始化：把 1..n 号圆盘按从大到小摞到 a 柱的底部 */
        public static void init(int n, LinkedList<Integer> a) {
            for (int i = n; i >= 1; i--) {
                a.addLast(i);
            }
        }

        /** 打印三根柱子的当前状态 */
        public static void print(LinkedList<Integer> a,
                                 LinkedList<Integer> b,
                                 LinkedList<Integer> c) {
            System.out.println("A:" + a + "  B:" + b + "  C:" + c);
        }

        /** 把 n 个圆盘从 a 柱借助 b 柱移到 c 柱 */
        public static void move(int n,
                                LinkedList<Integer> a,
                                LinkedList<Integer> b,
                                LinkedList<Integer> c) {
            if (n == 0) {                 // 没有盘子了，结束递归
                return;
            }
            move(n - 1, a, c, b);         // ① 前 n-1 个从 a 借助 c 移到 b
            c.addLast(a.removeLast());    // ② 第 n 个圆盘从 a 移到 c
            print(a, b, c);               // 状态变了，打印出来
            move(n - 1, b, a, c);         // ③ 前 n-1 个从 b 借助 a 移到 c
        }

        public static void main(String[] args) {
            LinkedList<Integer> a = new LinkedList<>();
            LinkedList<Integer> b = new LinkedList<>();
            LinkedList<Integer> c = new LinkedList<>();

            init(3, a);
            print(a, b, c);
            move(3, a, b, c);
        }
    }
    ```

* **三阶汉诺塔的实际移动序列**

    * 初始全部在 `a` 柱；1 号盘子移到 `c`；2 号盘子移到 `b`；1 号盘子从 `c` 移到 `b`；3 号盘子移到最终目标 `c`；1 号盘子移到 `a`；2 号盘子移到目标 `c`；1 号盘子移到 `c`。

* **三盘与四盘的共同点**

    * 都要先把 $n-1$ 个从 `a` 移到 `b`，才能把第 $n$ 个从 `a` 移到 `c`，最后再把 $n-1$ 个从 `b` 移到 `c`，大步骤都能拆成这三个。

    * > **易错点**：三根柱子的参数顺序是这套代码里最容易写错的地方。① 是 `a → b` 借助 `c`，写成 `move(n-1, a, c, b)`；③ 是 `b → c` 借助 `a`，写成 `move(n-1, b, a, c)`。写反了不会编译报错，只会给你一个不合法的移动序列。

## 汉诺塔的递推式与规模

* **汉诺塔的递推式**

    * 每次递归把原问题拆成两个子问题，所以子问题个数是 2；数据规模只比原来减少 1。

    * $$T(n) = 2T(n-1) + c$$

    * 剩下中间那个移动操作可以看成常数。

* **求解路径**

    * 主定理解不了这种 $n-1$ 的递推式。

    * 两种选择：一种是用数学推导把它展开求出 $T(n)$；另一种是用在线递推求解器，并额外指明当 $n$ 等于 1 时运行时间也是常量。

    * 两者结果一致：$T(n) = c(2^n - 1)$。

    * 去掉后面那一项和前面乘的系数 $c$，复杂度就是 $O(2^n)$。

* **64 片黄金圆盘为什么等一辈子**

    * 把 `n` 改成 64 一运行，程序好像一直在移动、一直没有结束，等一辈子也结束不了。

    * $n = 64$ 就相当于 $2^{64}$：实测移一次的时间是 6500 纳秒，但要在这个基础上再乘以 $2^{64}$。

    * 算出来是一生无法接受的事件。

## 杨辉三角的规律与坐标化

* **杨辉三角（Pascal's triangle）**

    * > **定义**：每行首尾都是 1、其余位置等于正上方两个数之和的三角形数阵，用来求解高次开方运算。

    * 它实际来自比杨辉更早的数学家贾宪，杨辉在自己的书里引用了这张图形，所以叫杨辉三角，西方叫帕斯卡三角。

    * 规律有两个：三角形的两条边上的数字都是 1；剩下的数字正好是它正上方两个数字之和。

    * 题目要求：用编程的方法生成这样一个三角形并把它打印出来。

    ```text
            1
           1 1
          1 2 1
         1 3 3 1
        1 4 6 4 1
       1 5 10 10 5 1
    ```

    * 比如 2 的正上方是两个 1，加起来是 2；5 的正上方是 1 和 4，加起来正好是 5。

    * 杨辉三角还有其他规律，这里不做展开。

* **斜过来看：正上方变左上与右下**

    * 正着看不好分析，斜过来看好分析：把每一行称之为 $i$、每一列称之为 $j$。

    * 第 $i$ 行第 $j$ 列的元素来自上一行的**前一列** $(i-1, j-1)$ 加上上一行的**同列** $(i-1, j)$。

    $$\text{element}(i, j) = \text{element}(i-1, j-1) + \text{element}(i-1, j)$$

    * 两种可直接求解的特殊情况：当 $j = 0$（第零列）时取值唯一是 1；当 $i = j$（这条斜边）时取值也是 1。

    * 除了这两种情况，剩下的元素都符合上面的推导。

* **`element(i, j)`：把推导直接写成递归**

    * 方法名 `element`，参数 `i` 和 `j` 分别代表行与列，返回值是这一列的值，类型 `int`。

    ```java
    private static int element(int i, int j) {
        if (j == 0 || i == j) {              // 第零列 或 斜边：取值唯一为 1
            return 1;
        }
        // 上一行的前一列 + 上一行的同列
        return element(i - 1, j - 1) + element(i - 1, j);
    }
    ```

    * 验证：行与列都从零开始，`element(4, 2)` 对应 `1 2 3 4 5` 这一行的第三个数字，结果是 6。

## 打印杨辉三角的排版

* **`print(n)` 的两层循环**

    * `print` 不需要返回值，参数 `n` 代表这个三角形的高度。

    * 需要两层循环：外层 `i` 代表行，从 0 到 $n-1$（`i < n`）；内层 `j` 代表列，从 0 循环到 `j <= i`。

    * 因为要打印到一行去，内层用 `printf` 而不是 `println`；等内层循环完了才算一行结束，这时再打印一个换行符。

    ```java
    private static void print(int n) {
        for (int i = 0; i < n; i++) {           // 外层：每行
            for (int j = 0; j <= i; j++) {       // 内层：每列
                System.out.printf("%-4d", element(i, j));
            }
            System.out.println();                // 内层循环完了，才算一行结束
        }
    }
    ```

* **用 `printf` 的格式串对齐**

    * 刚写完的版本数字紧挨着打印，不太好看。

    * `%4d`：`d` 代表格式化数字，`4` 代表宽度占四位，不足用空格补齐。

    * `%-4d`：减号表示左对齐，每个数字左对齐占 4 位后三角形就正过来了。

    ```text
            1
           1   1
          1   2   1
         1   3   3   1
        1   4   6   4   1
       1   5   10  10  5   1
    ```

* **每行前面补空格的正过来规律**

    * 最下面一行不用加空格；它上面一行加 2 个空格，再往上一行加 4 个，依次到最上面一行加 8 个。

    * 这个规律跟高度有关，也跟行号有关。

    | 行号 `i` | 空格数（高度 `n = 5`） |
    | :---: | :---: |
    | 0 | 8 |
    | 1 | 6 |
    | 2 | 4 |
    | 3 | 2 |
    | 4 | 0 |

    * 公式是 `(n - 1 - i) × 2`；验一个：`i = 0`、`n = 5` 时 `5 - 1 - 0 = 4`，乘 2 得 8。

    * 之所以乘 2，是因为数字占了四位、每个数字最多占四位；宽度若是 6，这里就变成乘 3。

* **`printSpace(n, i)` 方法**

    * 专门写一个方法打印空格，参数接收 `n` 和 `i` 两个，因为空格数跟它们俩都有关。

    * 算出空格数 `number = (n - 1 - i) × 2`，循环这么多次打印空格，打印空格不加换行。

    ```java
    private static void printSpace(int n, int i) {
        int number = (n - 1 - i) * 2;      // 数字占 4 位，所以乘 2
        for (int k = 0; k < number; k++) {
            System.out.print(" ");
        }
    }

    private static void print(int n) {
        for (int i = 0; i < n; i++) {
            printSpace(n, i);              // 每行之前先打空格
            for (int j = 0; j <= i; j++) {
                System.out.printf("%-4d", element(i, j));
            }
            System.out.println();
        }
    }
    ```

## 杨辉三角的二维数组记忆化

* **重复计算的来源**

    * 求 `element(i, j)` 和求 `element(i, j+1)` 都要用到 `element(i-1, j)`，它被算了两遍。

    ```text
            (i, j)                (i, j+1)
           /      \              /        \
    (i-1, j-1)  (i-1, j) == (i-1, j)   (i-1, j+1)
                      ^^^^^^^^
                        算了两遍
    ```

    * 递归实现是多路递归——一个问题被分成两个子问题，时间复杂度可以达到指数级，相当高。

    * 解法是**记忆法（memoization）**缓存：如果某次计算已经做过了就记下来，下次遇到相同计算不重复做。

* **缓存容器的选型与形状**

    * 斐波那契那次优化用的是一维数组；杨辉三角分成了行与列，跟二维数组更像，所以第一时间想到二维数组。

    * 行数就是 $n$，因为 `n` 代表三角形的高度。

    * 列的数目是变化的：第 0 行 1 列、第 1 行 2 列、第 2 行 3 列，以此类推，第 `i` 行的列数是 `i + 1`。

    * 所以初始写成 `int[][] values = new int[n][]`，再在每行循环里为第 `i` 行 `new int[i + 1]`。

    * 这个二维数组要作为参数传进递归函数，所有递归调用的地方都把它传进去。

* **命中判定与写入**

    * 二维数组刚建好时全是 0，出现 1、2、3、4、6 这些值就说明该项已经算过。

    * 所以判定条件是：当第 `i` 行第 `j` 列的取值大于 0 时说明已经计算过，直接返回该结果，不再走下面的计算逻辑。

    * 写入分两种情况：直接返回 1 的两条边把 1 存进去；其余位置把上一行两列之和存进去，最后返回这个二维数组里的值。

    ```java
    private static int element1(int i, int j, int[][] values) {
        if (values[i][j] != 0) {      // 已经算过了，直接返回缓存的结果
            return values[i][j];
        }
        if (j == 0 || i == j) {
            values[i][j] = 1;         // 两条边，取值唯一
        } else {
            // 上一行的前一列 + 上一行的同列
            values[i][j] = element1(i - 1, j - 1, values)
                         + element1(i - 1, j, values);
        }
        return values[i][j];
    }

    private static void print1(int n) {
        int[][] values = new int[n][];        // 行数 = 高度 n
        for (int i = 0; i < n; i++) {
            values[i] = new int[i + 1];        // 第 i 行有 i+1 列
            printSpace(n, i);
            for (int j = 0; j <= i; j++) {
                System.out.printf("%-4d", element1(i, j, values));
            }
            System.out.println();
        }
    }
    ```

    * 改动前后打印效果一样，但时间复杂度提升很大。

    | 版本 | 时间复杂度 |
    | :--- | :--- |
    | 直接递归 `element(i, j)` | 指数级，即 $O(2^n)$ 量级 |
    | 二维数组记忆化 `element1(i, j, values)` | $O(n^2)$ |

    * > **结论**：记忆化的收益不改变算法能算出什么结果，只改变它算出这个结果要算多少次。同一个「多路递归 + 子问题重叠」的骨架，能不能降一个量级，取决于有没有把算过的项记下来。

## 杨辉三角的一维数组空间复用

* **二维数组的代价与优化动机**

    * 引入二维数组换来时间复杂度下降，代价是引入了额外的空间成本。

    * 关键观察：二维数组里存了那么多信息，可实际上大部分用完就废了——一行打印完、根据它生成了下一行之后，这行留着就没用了。

    * 所以可以简化成一个一维数组，每次生成新数据时只是覆盖原有的旧数据，实现空间上的重用。

* **从右往左覆盖：1331 变成 14641**

    * 一维数组的好处是还没计算出来的元素初值都是 `0`。

    * 目标是根据某一行生成它的下一行，但**不能新建数组**，还是用同一个数组。

    ```text
    算之前:   1   3   3   1   0
    算之后:   1   4   6   4   1
    ```

    * 多出来的那一项的值来自**当前值加上上一个值**。

    | 下标 | 怎么来的 | 新值 | 覆盖掉原来那个 |
    | :--- | :--- | :--- | :--- |
    | 4 | `0 + 1` | 1 | 1（多出来的那一项） |
    | 3 | `1 + 3` | 4 | 1 |
    | 2 | `3 + 3` | 6 | 3 |
    | 1 | `3 + 1` | 4 | 3 |
    | 0 | 恒为 1 | 1 | 不用动 |

    * 每一步都是「当前项加上上一项」，再把算出来的新值盖到旧位置上；最后那一项不用动，因为它的值永远是 1。

    * > **易错点**：必须**从右向左**扫。反过来从左往右的话，在拿 `row[j]` 算 `row[j + 1]` 之前 `row[j]` 已经被上一轮改掉了，用的就不是上一行的数据。

* **`createRow` 方法与循环边界**

    * 方法不需要返回值，用 `void` 即可；参数两个：一维数组 `row` 记录上次的结果，行号 `n` 表示你是第 0 行还是第 1 行。

    * 第 0 行是杨辉三角的对顶行，不用根据上一行求解，结果已知：`n` 等于 0 时 `row[0] = 1` 然后直接 `return`。

    * 其他行从右向左把相邻两列加起来，新值就是上次这一列的值加上前一列的值。

    * 起点是 `n`：以第 4 行为例，它最右侧的列恰好也是 4（行号依次是 0、1、2、3、4），所以起点就是 `n`。

    * 终点是 `j > 0`：第 0 列的值始终固定为 1，没必要求，算到 `j = 1` 时停止。

    ```java
    public static void createRow(int[] row, int n) {
        // 第 0 行：对顶行，结果已知
        if (n == 0) {
            row[0] = 1;
            return;
        }

        // 从右向左：相邻两列相加，新值直接覆盖旧值
        for (int j = n; j > 0; j--) {
            row[j] = row[j] + row[j - 1];
        }
    }
    ```

* **`print2` 方法的改造**

    * 一维数组长度设成 `n` 就够用了；每次循环调用 `createRow` 生成这一行数据并存进 `row`，然后循环 `row` 打印每一列的值。

    ```java
    public static void print2(int n) {
        int[] row = new int[n];
        for (int i = 0; i < n; i++) {
            createRow(row, i);
            for (int j = 0; j <= i; j++) {
                System.out.print(row[j] + " ");
            }
            System.out.println();
        }
    }
    ```

    * 改造后打印效果与二维数组版本一致。

    * 一维数组让方法内的实现反而更简单了，都不用去递归调用——因为直接根据上一行的结果就能算出当前行的结果。

    * 但不要因为代码里没有递归就说它不是多路递归题：只是在循环内多次调用 `createRow`，`createRow` 自身并不调用自身，所以递归的地位其实没有了。

    * 一维数组这种优化有另一个称呼，可以叫**动态规划（dynamic programming）的优化方式**，可以把这个例子看成动态规划一个比较简单的应用场景。

    * 另外杨辉三角还可以通过每一行的前一项计算出下一项，不借助上一行就得到这一行的数据，这跟它的另一个特性有关、涉及一些数学公式，这里不做展开。

## 反转链表

* **反转链表（reverse linked list）**

    * > **定义**：给定一个单链表的头节点，把它反转并返回反转后的链表头节点。

    * 题目给的进阶说明：可以用**迭代或者是递归**的方式完成反转。

    ```text
    链表  1 → 2 → 3 → 4 → 5   反转之后变成 5 → 4 → 3 → 2 → 1
    链表  1 → 2                反转之后变成 2 → 1
    空链表                     反转之后返回一个空
    ```

* **节点表示与题目形式**

    * 节点类里有 `val`（节点的值）和 `next`（下一个节点的指针）；因为是单链表，所以没有 `previous` 指针。

    * 力扣这些链表题目里都没有链表外层那个集合类，按理说应该有一个包含多个节点的集合，但它只给了节点类，所以写题时形式会和之前的例题不一样。

    * 调试用的 `toString` 把链表每个节点都打印出来。

    ```java
    class ListNode {
        int val;
        ListNode next;

        public ListNode(int val) {
            this.val = val;
        }

        @Override
        public String toString() {
            StringBuilder sb = new StringBuilder();
            ListNode p = this;
            while (p != null) {
                sb.append(p.val).append(" ");
                p = p.next;
            }
            return sb.toString();
        }
    }
    ```

    * 测试用 `o1` 到 `o5` 代表各节点并连好，`o5` 的 `next` 是 `null`；先打印旧链表 `1 2 3 4 5`，调 `reverseList` 后应打印 `5 4 3 2 1`。

### 另起一条链，一律插到头部

* **做法**

    * 构造一条新链表，从旧链表依次拿到每个节点，用旧节点的值创建新节点，再把新节点加到新链表的头部，完成后新链表就是倒序的。

    * 新链表刚开始是 `null`；拿到 1 插头部，再拿 2 插头部变成 `2 → 1`，拿 3 变 `3 → 2 → 1`，以此类推直到 5。

    * 这是最直接也最简单的方法。

    ```java
    public static ListNode reverseList1(ListNode head) {
        ListNode newHead = null;   // n1：新链表的头节点
        ListNode p = head;          // 旧链表的遍历指针，从头部开始

        while (p != null) {
            ListNode node = new ListNode(p.val);  // 用旧节点的值造一个新节点
            node.next = newHead;                  // 新节点插到新链表头部
            newHead = node;                       // 更新新链表的头
            p = p.next;                           // 旧指针往下挪
        }

        return newHead;
    }
    ```

* **循环退出条件**

    * 每次循环结束让 `p` 等于 `p.next`，当 `p.next` 是 `null` 被赋给 `p` 时，下次循环就等于 `null`，表示没有节点了，退出循环。

* **代价**

    * 代价在 `new ListNode(p.val)` 这一行——每个旧节点都造了个新副本，相当于把原链表重新复制了一份，算法前后总共有十个节点。

### 从旧链头部摘下来搬过去

* **与复制法的差别**

    * 思想同样是构造新链表，但不同之处是要从旧链表的头部移除节点，移走了就等于旧链表这个节点不要了。

    * 移到哪去呢？移到新链表的头部，不断从旧链表头部移走、移到新链表头部，新链表就是倒序的，旧链表也没了。

    * 好处是过程中没有创建新节点，节点还是原来那几个，算法前后节点个数还是五个。

    * 代价是要额外提供一个容器类，用它记录新链表的头节点以及相关方法。

* **容器类 `List` 的两个方法**

    * 成员变量 `head` 记录链表头节点，外加一个构造函数给它赋初值。

    * `addFirst` 不需要考虑链表为空的情况：`head` 是 `null` 也没关系，`first` 的 `next` 会指向 `null`，然后 `head` 被更新成 `first`。

    * `removeFirst` 返回值是**它被移除的那个节点**：先拿到 `first`，若不为 `null` 就把第二节点复制给 `head` 作为新头，并把 `first.next` 置空断尾；`head` 为空时直接返回 `null`，不走 `next` 逻辑，避免空指针。

    ```java
    class List {
        ListNode head;

        List(ListNode head) {
            this.head = head;
        }

        // 往头部添加节点
        void addFirst(ListNode first) {
            first.next = head;   // 待添加节点的 next 指向原来的 head
            head = first;        // head 更新成新节点
        }

        // 移除头部节点，返回被移除的那个节点
        ListNode removeFirst() {
            ListNode first = head;
            if (first != null) {
                head = first.next;   // 第二个节点成为新的头节点
                first.next = null;   // 被移除的节点先断开
            }
            return first;
        }
    }
    ```

* **搬家的循环**

    * `list1` 根据旧 `head` 构造，`list2` 是新链表、头节点先为 `null`；不断从 `list1` 移除头节点并加给 `list2`。

    * 被移除的节点等于 `null` 表示都移没了，循环条件写成 `(first = list1.removeFirst()) != null`。

    ```java
    public static ListNode reverseList2(ListNode head) {
        List list1 = new List(head);   // 旧链表
        List list2 = new List(null);   // 新链表，头节点先为 null

        ListNode first;
        while ((first = list1.removeFirst()) != null) {
            list2.addFirst(first);
        }

        return list2.head;
    }
    ```

    * 最后返回 `list2` 的头节点，因为题目要的就是反转之后的头节点。

### 递归回溯时互换相邻两节点

* **第一步：先递归找到最后一个节点**

    * 之所以要找最后一个节点，是因为找到后就能把它作为反转后的首节点。

    * 递归调用时每次都去找它的下一个节点；当节点的 `next` 指向 `null` 时它就是最后一个节点，返回 `p` 即可。

    * 返回结果会一层层往上返，用变量 `last` 记录并最终返回。

    * 空链表传进来就是 `null` 时直接返回 `null`，这时最后一个节点就是 `null`，不再往下递归。

    ```java
    // 只负责找最后一个节点
    private static ListNode findLast(ListNode p) {
        if (p == null) return p;       // 空链表，直接返回
        if (p.next == null) return p;  // 到头了，它就是最后一个节点

        ListNode last = findLast(p.next);
        return last;                   // 一层层把结果往上带
    }
    ```

    ```text
    reverseList(p = 1)
      └─ reverseList(p = 2)
          └─ reverseList(p = 3)
              └─ reverseList(p = 4)
                  └─ reverseList(p = 5)   ← p.next == null，返回
              ← 回到 p = 4
          ← 回到 p = 3
      ← 回到 p = 2
    ← 回到 p = 1
    ```

* **第二步：在每次递归调用结束时把相邻两节点反过来**

    * `p` 等于 4 这次调用里，四就是 `p`，五就是 `p.next`；让五指向四就是让 `p.next` 的 `next` 指向 `p`，写成 `p.next.next = p`。

    * 依次类推：`p` 等于 3 时让 4 指向 3，`p` 等于 2 时让 3 指向 2，最后让 2 指向 1。

* **死循环是怎么来的，又怎么断尾**

    * 在 `p` 等于 4 这次调用里，执行 `p.next.next = p` 后 5 指向了 4，但当前节点 4 仍然指向 5（它要等下一次调用才指向 3），于是 4 → 5 → 4 构成了环。

    * 极端情况是链表只有 4 和 5 两个节点：调用结束后没有任何节点指向 `null`，直接成死循环。

    * 解决办法是让当前节点 `p` 指向 `null` 断尾，变成 `5 → 4 → null`；每一层返回前都做一次 `p.next = null`。

    ```java
    public static ListNode reverseList3(ListNode p) {
        if (p == null) return p;         // 空链表
        if (p.next == null) return p;    // 只有一个节点，它就是最后一个

        ListNode last = reverseList3(p.next);  // 往下递归，拿最后一个节点

        p.next.next = p;   // 后一个节点指回当前节点
        p.next = null;     // 当前节点断尾，否则 4→5→4 成了环

        return last;       // 一层层把最后一个节点传上去
    }
    ```

* **两段逻辑要分开看**

    * 返回值那一路是为了把最后一个节点层层传上去、作为新链表的头节点。

    * 中间加的 `p.next.next = p` 和 `p.next = null` 两行是把相邻节点逆序，同时断尾。

### 三个指针在同一条链上剪切

* **思路：把第二个节点搬到最前面**

    * 设两个指针 `o1` 和 `n1`，刚开始都指向链表头部；`o1` 代表 old 即原来的第一个节点，`n1` 代表 new 即新链表的头。

    * 把这一条链表当成两条链表看：`old` 是原来正确的 `1 2 3 4 5`，`new` 要变成 `3 2 1` 这样逆序的链表。

    * 算法是每次找到 `o1` 的下一个节点，也就是旧链表第二个节点，从整个列表中断开它，再作为头节点插到整个链表的头部；`o1` 全程不变，始终指向原来那个 1。

    ```text
    初始:  o1 = 1,  o2 = 2,  n1 = 1
            1 → 2 → 3 → 4 → 5

    第 1 轮：把 2 剪切到头部
            新链表 2 → 1        旧链表 1 → 3 → 4 → 5      o2 重新指向 3
    第 2 轮：把 3 剪切到头部
            新链表 3 → 2 → 1    旧链表 1 → 4 → 5          o2 重新指向 4
    第 3 轮：把 4 剪切到头部
            新链表 4 → 3 → 2 → 1  旧链表 1 → 5            o2 重新指向 5
    第 4 轮：把 5 剪切到头部
            新链表 5 → 4 → 3 → 2 → 1   旧链表只剩 1
    ```

    * 循环结束条件：`o1` 的下一个节点，也就是旧链表中第二个节点为 `null` 时退出。

* **三个指针的分工**

    * `o1` 是旧的头，`n1` 是新链表的头，两者初始都指向链表最开始的那个节点。

    * `o2` 是旧链表中第二个节点，排名老二的那个节点，初始值是 `o1.next`。

    * 设好指针后重复做一件事：把排名老二的这个节点从链表中剪切掉，放到新链表的头部。

* **每轮重复的四步**

    * **断开**：让 `o1` 指向 `o2` 的下一个节点，`o2` 就从中间断开了。

    * **接到新链表头部**：让 `o2` 的 `next` 指向新链表的头 `n1`。

    * **更新新头**：把 `o2` 的值赋值给 `n1`，此时 `n1` 和 `o2` 共同指向新链表的头部。

    * **`o2` 回到自己的位置**：它代表旧链表中第二个节点，前几步做完它的活就结束了，取值应为 `o1.next`。

    ```java
    public static ListNode reverseList4(ListNode head) {
        // 1) 设置三个指针：旧头、旧老二、新头
        ListNode o1 = head;
        ListNode o2 = o1.next;   // 旧链表中第二个节点
        ListNode n1 = o1;        // 新链表的头

        // o2 是旧链表的第二个节点，它等于 null 说明处理完了
        while (o2 != null) {
            o1.next = o2.next;   // 2) 把 o2 从链表中断开
            o2.next = n1;        // 3) o2 接上新链表的头
            n1 = o2;             // 4) 让 o2 成为新头
            o2 = o1.next;        // 5) o2 回到它在旧链表里的位置
        }

        return n1;
    }
    ```

* **两个边界条件**

    * 边界情况有两种：链表为空里没有节点；链表中只有一个元素。

    * 一个元素不需要颠倒，直接返回这个节点本身即可，这两种情况都直接返回头节点。

    ```java
    if (o1 == null || o1.next == null) {
        return head;   // 空链表 / 只有一个节点
    }
    ```

### 四种解法的对照

* **解法特征对比**

    | 解法 | 在哪儿动手 | 额外节点成本 | 关键难点 |
    | :--- | :--- | :--- | :--- |
    | 方法一 | 复制新节点，一律插新链头部 | 翻倍（原 5 个变 10 个） | 头插法把新头一路顶走 |
    | 方法二 | 从旧链头部摘下来搬过去 | 无 | 需要 `removeFirst` / `addFirst` 这对容器方法 |
    | 方法三 | 递归回溯时互换相邻两节点 | 无 | 必须断尾，否则成环 |
    | 方法四 | 三个指针剪切旧链第二个节点 | 无 | `o2` 每轮都要回到它在旧链里的位置 |

* **本质与共同边界**

    * 反转的本质只有一句话——**把链表的指向关系一条条翻过来，同时让新头一直跟着走**；四种解法其实就是四种「在哪儿翻」的位置。

    * 四种方法共同的边界是同一个：**空链表、只有一个节点时直接返回头节点本身**，根本不用进循环。

    * 反过来记也一样——凡是写成「先访问 `x` 再判空」的地方，都要先问一句这里会不会是 `null`。
