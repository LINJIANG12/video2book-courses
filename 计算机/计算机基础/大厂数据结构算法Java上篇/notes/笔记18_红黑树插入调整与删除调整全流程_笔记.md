# 红黑树：插入调整与删除调整全流程

## 两条调整路线与失衡判据

* **插入与删除的分工**

    * > **定义**：`put` 负责新增或者更新，`remove` 负责删除；两者都先按二叉搜索树（BST，Binary Search Tree）的常规逻辑走，再补一次红黑树特有的平衡修复。

    * `put` 与普通 BST 插入的唯一差别，是新增结束后调用一次 `fixRedRed` 修复红红相邻。

    * `remove` 摘节点本身仍是常规做法，靠李代桃僵技巧把复杂情形降级，摘完节点才处理平衡。

* **两类失衡**

    * > **定义**：红红不平衡指两个相邻节点都是红色，破坏性质三；它细分四种情况，由 `fixRedRed` 处理。

    * 黑黑不平衡指整条路径上少了一个黑色，细分六种情况，由 `fixDoubleBlack` 处理。

    * 让红黑树恢复平衡的手段只有两种：变色与旋转。

    * > **结论**：删黑色节点要考虑平衡，删红色节点不需要考虑平衡；删除调整的全部复杂度都来自「删的是黑」这一件事。

* **本流程引用到的性质编号**

    * 性质三：任意两个相邻节点不能同时是红色。

    * 性质四：根节点必须是黑色。

    * 规则五：从根到任意叶子的路径上黑色节点数目必须相同，即黑高相等。

    * > **提示**：长文未说明性质一与性质二的具体内容。

## 结构调整中的三种称呼

* **叔叔 `uncle`**

    * > **定义**：父节点的对称位置上的那个节点，也就是爷爷的另一个孩子；由 `uncle(x)` 取出。

    * 叔叔是红还是黑，直接决定这次修复走「变色」还是「旋转」。

* **兄弟 `sibling`**

    * > **定义**：与被调整节点同父的另一个节点，由 `x.sibling()` 取出；兄弟是黑色时，还要看它的两个孩子的颜色。

* **祖父 `grandParent`**

    * > **定义**：`parent.parent`，即父节点的父节点。

* **`nil` 的颜色约定**

    * > **定义**：`nil`（空节点）一律按黑色看待，所以 `isBlack(null)` 为真。

    * 判断「是不是黑色」时必须把 `nil` 一起算进去，否则会漏掉整类情况。

* **后继节点**

    * > **定义**：有两个孩子的节点被删除时顶替它的节点，从它的右子树出发一路向左走到头得到，即右子树中最左边的节点。

## 插入端：顺着 k 找空位

* **`put` 的整体骨架**

    * > **定义**：从 `root` 出发一路比较键值找空位，找到就新建节点并建立父子关系；遇到相同的 k 就地更新值并立刻返回。

    * 循环内 `parent` 每轮更新成当前节点；树为空时循环一次都不走，`parent` 保持 `null`，此时新节点直接当根。

    * 非空树里 `k < parent.k` 时挂为左孩子，否则挂为右孩子；随后调用 `fixRedRed(inserted)`。

* **与普通 BST 插入的第一个差别：父子关系变双向**

    * 节点对象多出一个 `parent` 属性，插入时不仅要设置 `parent.left` / `parent.right`，还要回填 `inserted.parent`。

    * > **易错点**：插入的是根节点时可以省略赋 `parent`，因为根的父亲本就该是 `null`，与字段初始值一致；所以 `parent` 字段要声明为默认 `null`。

* **与普通 BST 插入的第二个差别：新节点默认红色**

    * 新建节点的 `color` 初始为红色。

    * 若新增节点与父节点同为红色，就触发性质三被破坏，需要交给 `fixRedRed` 调整；被调整的对象就是新增节点本身，记作 `x`。

    ```java
    public void put(int k, int v) {
        Node p = root;
        Node parent = null;

        while (p != null) {
            if (k < p.k) {
                parent = p;
                p = p.left;
            } else if (k > p.k) {
                parent = p;
                p = p.right;
            } else {
                p.v = v;              // 键相同，做更新，不再往下走
                return;
            }
        }

        Node inserted = new Node(k, v);   // 颜色默认红色

        if (parent == null) {
            root = inserted;
        } else if (k < parent.k) {
            parent.left = inserted;
            inserted.parent = parent;     // 双向父子关系
        } else {
            parent.right = inserted;
            inserted.parent = parent;
        }

        fixRedRed(inserted);
    }
    ```

## 插入端：能收工的两个情况

* **插入的就是根节点**

    * > **定义**：新增节点 `x` 就是 `root` 时，把 `x` 的颜色染黑即可收工。

    * 依据是新节点初始为红色，而根节点必须是黑色，违反的是性质四。

* **父节点是黑色**

    * > **定义**：`isBlack(x.parent)` 成立时直接返回，不做任何调整。

    * 依据有三条：根节点仍为黑色满足性质四；没有新增红红相邻；新增的是红色节点不参与黑高计数，各路径黑高不变，规则五不受影响。

* **合起来的判定**

    * > **结论**：只要插入节点是根，或者它的父亲是黑的，调整就可以直接收工。

    ```java
    private void fixRedRed(Node x) {
        if (x == root) {
            x.color = Color.BLACK;
            return;
        }
        if (isBlack(x.parent)) {
            return;
        }

        Node parent = x.parent;
        Node uncle = uncle(x);
        Node grandParent = parent.parent;
        // 后面按叔叔的颜色分流
    }
    ```

## 插入端：叔叔是红色，只需变色

* **触发条件与规则**

    * > **定义**：插入节点与父节点同为红色触发红红相邻，且叔叔也是红色时，只靠变色即可恢复平衡。

    * 规则是：父亲染黑、叔叔染黑、祖父染红，然后对祖父递归调用 `fixRedRed`。

    * > **结论**：遇到叔叔为红，就把父亲和叔叔变黑、祖父变红。

* **为什么三步都不可省**

    * 只把父亲染黑：红红相邻虽消除，但父这条路径多出一个黑、叔这条路径没有，`3` 子树左右黑高不等，规则五被破坏。

    * 加上叔叔染黑：`3` 子树重新左右平衡，但父亲与叔叔都变黑后，这两条路径相对其他路径多出一个黑，还得减掉一个。

    * 2 与 4 刚由红变黑，变回红会抵消前面的染色，唯一可行的选择是把祖父 3 染红，使各路径黑高保持不变。

    ```text
            变色前                    变色后

            5 (R)                  5 (R)
            │                      │
       ┌────┴────┐            ┌───┴────┐
     3 (B)     13           3 (R)     13 (?)
     ┌─┴─┐                     │
    2(R) 4(R)              2 (B) 4 (B)
     │
    1 (R)  ← 本次插入        1 (R)
    ```

* **祖父染红之后为什么要递归**

    * 祖父染红可能与上方节点再次红红相邻，此时把祖父当作「刚插入的节点」继续判断；若祖父的叔叔仍为红，重复同一套变色，如此一路向上。

    * 递归推进到根时，根节点必须染黑；因为根之上没有更多节点，性质四不容妥协。

    * > **结论**：整个 `fixRedRed` 里真正需要递归的只有这一支，因为只有它把祖父染红之后，红红相邻才可能往上一层传染。

* **代码**

    ```java
    if (isRed(uncle)) {
        parent.color = Color.BLACK;
        uncle.color = Color.BLACK;
        grandParent.color = Color.RED;
        fixRedRed(grandParent);   // 由祖父递归调用后续代码
        return;
    }
    ```

    * > **提示**：编译器可能提示 `uncle` 这行有空指针风险，不会发生——`nil` 按黑色看待，走不到这个分支，能进入分支就说明叔叔非空。

## 插入端：叔叔是黑色，得靠旋转

* **触发条件与四种形态**

    * > **定义**：插入节点与父节点同为红色，但叔叔是黑色（叔叔为 `nil` 也算命中），这是最复杂的一支；它按父与新节点的左右位置分成四种不平衡，与 AVL 树里的四种形态同名同法。

| 不平衡形态 | 判断特征 | 解决办法 |
| --- | :--- | :--- |
| 左左 LL | 父亲是左孩子，且插入节点是左孩子 | 一次右旋 |
| 左右 LR | 父亲是左孩子，插入节点是右孩子 | 先对父亲左旋，再对祖父右旋 |
| 右左 RL | 父亲是右孩子，插入节点是左孩子 | 先对父亲右旋，再对祖父左旋 |
| 右右 RR | 父亲是右孩子，插入节点是右孩子 | 一次左旋 |

* **为什么变色救不回来**

    * 把父亲染黑会让父这条路径多一个黑；改让祖父染红补偿，则祖父转向叔那条路径时又少一个黑——无论怎么染，两条路径的黑高无法同时对齐。

    * 叔这条路径少黑色，唯一的解法是旋转把黑色转过去，以祖父为旋转轴：祖父下沉，父亲上升。

* **左左的处理**

    * > **结论**：左左不平衡的三板斧是父亲变黑、祖父变红、对祖父做一次右旋。

    * 旋转上去的父亲是黑色，不会再触发红红相邻，所以这一支做完即平衡，不需要额外递归。

    ```text
                5 (B)                      3 (B)
               /       \                  /       \
           3 (R)     nil 视作黑       2 (R)        5 (R)
           /                                          \
       2 (R)  ← 本次插入                          nil 视作黑
    ```

* **左右的处理**

    * > **定义**：父在左、插在右属于左右不平衡，先围绕父左旋把它掰成左左，再走左左那一套。

    * 左旋之后顶上来成为新父亲的是插入节点本身，所以变色对象随之换人：把插入节点染黑、祖父染红，再对祖父右旋；祖父仍染红。

    * > **易错点**：左右这种情形里染色的对象换了，要把 `x` 染黑而不是原来的 `parent`——这是它与左左唯一的差别。

* **右左与右右的处理**

    * 右左：先对 `parent` 右旋归约成右右，随后把插入节点 `x` 染黑、祖父染红，再对祖父左旋。

    * 右右：父亲染黑、祖父染红，再对祖父左旋。

    ```java
    if (isLeftChild(parent) && isLeftChild(x)) {
        // 左左：父亲变黑、祖父变红、祖父右旋
        parent.color = Color.BLACK;
        grandParent.color = Color.RED;
        rightRotate(grandParent);
    } else if (isLeftChild(parent)) {
        // 左右：父左旋；插入节点变黑、祖父变红、祖父右旋
        leftRotate(parent);
        x.color = Color.BLACK;
        grandParent.color = Color.RED;
        rightRotate(grandParent);
    } else if (isLeftChild(x)) {
        // 右左：父右旋；插入节点变黑、祖父变红、祖父左旋
        rightRotate(parent);
        x.color = Color.BLACK;
        grandParent.color = Color.RED;
        leftRotate(grandParent);
    } else {
        // 右右：父亲变黑、祖父变红、祖父左旋
        parent.color = Color.BLACK;
        grandParent.color = Color.RED;
        leftRotate(grandParent);
    }
    ```

    * 条件可去掉两处冗余判断：走到第二个分支时插入节点必然是右孩子，走到第三个分支时父亲必然是右孩子。

    * > **提示**：保留多余条件与去掉后的写法效果等价，去掉只是让读代码的人不必反推「走到这里说明什么」。

* **整体判定顺序**

    ```text
                        插入节点 x 是根节点吗？
                         是 ────────► 染黑，return
                         否
                          │
                    父亲是黑色吗？
                     是 ────────► 什么都不做，return
                     否
                      │
                叔叔是红色吗？（红红相邻已确定）
              是 ─────┴───── 否
              ▼                ▼
         case 3 变色        case 4 父亲是左孩子吗？
         父变黑 + 叔变黑       是 ────────┴───── 否
         + 祖变红            ▼               ▼
         递归调 fixRedRed  x 是左孩子吗？   x 是左孩子吗？
         （祖父为红再修）    是 ───┴─── 否   是 ───┴─── 否
                            ▼      ▼        ▼      ▼
                           左左    左右     右左     右右
                         祖右旋  父左旋+  父右旋+  祖左旋
                                祖右旋  祖左旋
    ```

    * > **结论**：能收工的两种情况先收工，只有叔叔是黑色这一支才动用旋转，而只有叔叔是红色那一支才递归。

## 删除端：两个备件方法

* **`find`：按 key 定位待删节点**

    * > **定义**：从 `root` 出发，比当前小往左、比当前大往右、相等返回当前节点；一路走到 `null` 还没命中说明树里没有这个 key，返回 `null`，主流程直接返回。

* **`findReplaced`：定位删剩下的节点**

    * > **定义**：入参是 `find` 得到的 `deleted`，返回将来要顶到 `deleted` 位置上的那个节点，分三种情况。

    * 没有孩子（叶子）：返回 `null`。

    * 只有一个孩子：左空返回右孩子，右空返回左孩子。

    * 有两个孩子：返回后继节点，即从右子树出发一路向左走到头。

    * > **提示**：前两个分支不必写「恰好只有一个孩子」——能走到那里说明已排除没有孩子的情况，此时至少有一个孩子，两个分支各测一个方向就走不到「都有孩子」那一步。

    ```java
    private Node findReplaced(Node deleted) {
        if (deleted.left == null && deleted.right == null) {
            return null;
        }
        if (deleted.left == null) {
            return deleted.right;
        }
        if (deleted.right == null) {
            return deleted.left;
        }
        Node s = deleted.right;   // 后继：右子树最左边的节点
        while (s.left != null) {
            s = s.left;
        }
        return s;
    }
    ```

## 删除端：李代桃僵把两孩子降级

* **`doRemove` 的三分支骨架**

    * > **定义**：`doRemove` 先 `Node replaced = findReplaced(deleted)`，再按 `replaced == null`、`只有一个孩子`、`有两个孩子` 三个分支处理。

    * 有两个孩子的分支自己不去摘节点，只负责把自己降级；因为后继一定落在「没有孩子」或「只有一个孩子」两档里，真正干活的永远只有前两个分支。

    * 递归形式的入口：`remove(k)` 先 `find`，为 `null` 直接返回，否则交给 `doRemove(deleted)`。

* **交换的是键值，不是节点引用**

    * > **定义**：删两孩子节点时并不删掉它本身，而是把 `deleted` 与后继 `replaced` 的 `k` 和 `value` 整体互换，然后递归去删 `replaced`。

    * 交换之后两个对象的 `left`、`right` 与颜色一点不变，变的只有 `k` 与 `value`；于是 `replaced` 站到了原位置并挂着原有的孩子，而原位置的对象装着后继的键值。

    * 效果是待删对象从「有两个孩子」退化成「没有孩子」或「只有一个孩子」，直接落进前两个分支，永远走不到两孩子分支。

    * > **易错点**：交换的是 `k` 与 `value`，不是节点引用。写成 `Node t = deleted; deleted = replaced; replaced = t;` 等于把两个对象的位置对调，父子指针全断。

    ```java
    Node t = deleted;
    deleted.k = replaced.k;
    replaced.k = t.k;

    Object v = deleted.value;
    deleted.value = replaced.value;
    replaced.value = v;

    doRemove(replaced);   // 现在要删的是 replaced，不是 deleted
    ```

## 删除端：根节点与非根节点的摘除

* **被删的是根节点**

    * 根节点没有孩子：孤零零一个根，直接 `root = null`，整棵树清空。

    * 根节点有两个孩子：不需要单独处理，李代桃僵已把它转成「有一个孩子」或「没有孩子」。

    * 根节点只有一个孩子：这个孩子不可能是黑色，否则黑高立刻不平衡，而删除前是平衡的，所以孩子必为红色。

    * 对这个必红的孩子仍用李代桃僵：把孩子的键和值复制到根节点上，再把孩子置为 `null`；实际被删的是孩子，根节点活着、颜色仍是黑色，平衡性一点不用调。

    * > **提示**：置空时不用管它是左孩子还是右孩子，把根节点的 `left` 与 `right` 都置为 `null` 即可，反正它就这一个孩子。

* **被删的不是根节点**

    * 没有孩子：找到它的父亲，判断它是父亲的左孩子还是右孩子，把对应那一侧置 `null`。

    * 只有一个孩子：让孩子顶掉被删节点的位置，`deleted` 是左孩子则 `parent.left = replaced`，否则 `parent.right = replaced`。

    * > **易错点**：孩子顶上去之后，它自己的 `parent` 也必须跟着改成 `parent`，`replaced.parent = parent;` 这一句不能少。

    * > **提示**：父子关系是双向的，这些置空操作本质是帮 GC——被删节点的 `left`、`right`、`parent` 全部置空后不再引用任何对象，回收时才不会被引用链挂住。

## 删除端：删黑必失衡，删红不用管

* **判据**

    * > **结论**：只要删的是黑节点就必须考虑平衡调整，删红节点不需要。

    * 删黑节点意味着从根到它这条路径上的黑色数目少了一个，规则五被破坏；补救思路是让另一条路径也少一个黑来对齐。

    * 删红节点不参与黑高计数，不需要变色也不需要旋转，其他节点全部保持原样。

* **中间位置的红节点为什么不用单独考虑**

    * 红节点如果有孩子，只能有两个黑孩子：不能有红孩子（否则红红相邻），也不能只有一个黑孩子（那样黑高不平衡）。

    * 所以红节点要么没孩子，要么有两个黑孩子；后者走李代桃僵去交换后继，真正被删掉的已经不是那个红节点，而是它的后继——一个黑节点。

    * 因此中间红节点的删除总会转成李代桃僵，只需要处理叶子位置红色节点的删除，而它不影响平衡。

## 删除端：删黑剩红，一行染色

* **条件与处理**

    * > **定义**：要删的是黑节点、删剩下的是红节点时，属于最简单的一种情形。

    * 处理只有一句：把 `replaced` 的 `color` 改成 `BLACK`，恰好在缺黑的那条路径上补上一个黑。

* **代码中的两处分支**

    ```java
    // 没有孩子的情况
    if (deleted.isBlack()) {
        fixDoubleBlack(deleted);   // 黑色叶子要走复杂调整
    }
    // 否则是红色叶子，删就删了，什么都不用做

    // 只有一个孩子的情况
    if (deleted.isBlack() && replaced.isBlack()) {
        fixDoubleBlack(replaced);
    } else {
        replaced.color = BLACK;    // 删的是黑、剩的是红
    }
    ```

    * > **提示**：在 `deleted.isBlack()` 处报空指针警告属于误判，能执行到那个分支说明 `deleted` 一定非空。

## 删除端：双黑

* **双黑是欠了一个黑，不是多了一个黑**

    * > **定义**：双黑指「删除节点与剩余节点都是黑色」造成的、整条路径上因少了一个黑色而触发的不平衡；`fixDoubleBlack` 修的正是这笔欠账。

    * 删黑剩红时红节点一变色就补上了，所以那种情形并不算少黑。

    * 删黑剩黑时，剩下的节点本来就是黑的，不能让它变红——否则问题原样保留还多欠一个，整条路径实打实少了一个黑，这才叫双黑。

    * > **易错点**：双黑与删黑剩红只差一个字，名字挨得很近：前者剩下的动不了，后者剩下的能染色补上，千万别记混。

## 删除端：两个调用点与相反的顺序

* `fixDoubleBlack` 只有两个调用点，但调用顺序与传入参数都不同，且顺序相反。

| 场景 | 顺序 | 传给 `fixDoubleBlack` 的参数 |
| --- | :--- | :--- |
| 没有孩子 | 先调整平衡，再把节点摘掉 | `deleted` |
| 有一个孩子 | 先真正删除（`replaced` 顶上），再调整平衡 | `replaced` |

* **两种顺序的展开**

    ```text
       没有孩子                          有一个孩子

      fixDoubleBlack(deleted)           replaced 顶上来
                ↓                              ↓
         再把 deleted 摘掉            fixDoubleBlack(replaced)
    ```

    * 没有孩子时结构还没动，所以拿 `deleted` 去调；有一个孩子时结构已经变了，`deleted` 不在树里，能代表「欠了一个黑」的位置是顶上来的 `replaced`。

    * > **易错点**：这两个调用点的先后顺序一定要分清，顺序颠倒会拿错节点去补黑。

## 删除端：兄弟是红的过渡情形

* **条件与性质**

    * > **定义**：被调整节点触发双黑且兄弟是红色时进入这一支；兄弟为黑则还要看两个侄子的颜色，分出后两种情况。

    * 红兄弟的两个侄子一定是黑孩子：红不能有红孩子，而一个黑孩子又会破坏黑高。

    * case 3 不能直接恢复平衡，它必须先把自己转成后两种情况之一，再继续往下调。

* **旋转 + 换色两步**

    * > **定义**：被调整节点是左孩子就对父左旋，是右孩子就对父右旋，两者完全对称；一次旋转后新兄弟变成原来那个黑侄子，正好落在后两种情况的入口。

    * 换色规则是父节点取兄弟的颜色、原兄弟染黑；旋转前父黑兄红且平衡，旋转后让两者互换颜色，整棵子树的黑高不变，临时重新平衡。

    * 调完这两步后新兄弟已是黑色，递归再走一次即可命中后两种情况。

    ```text
           旋转前                      旋转 + 换色之后

              6                             8 (B)
             / \                           /   \
            4   8                         6 (R)  …
               /          ──────▶       /  \
              7                         4    7 (B)
                                        ↑ 待删
    ```

* **代码与终止条件**

    * > **定义**：`fixDoubleBlack` 的参数 `x` 是被调整节点，可能是删除节点，也可能是删剩下的节点；`x == root` 说明已调整到整棵树顶部，黑高本就要求各路径相等，直接返回。

    ```java
    private void fixDoubleBlack(Node x) {
        if (x == root) {
            return;
        }

        Node parent = x.parent;
        Node sibling = x.sibling();

        if (sibling.isRed()) {
            if (x.isLeftChild()) {
                leftRotate(parent);
            } else {
                rightRotate(parent);
            }
            parent.color = sibling.color;   // 父亲与原兄弟换色
            sibling.color = BLACK;
            fixDoubleBlack(x);              // 必须再递归一次
            return;
        }
        // 后面按侄子的颜色继续分流
    }
    ```

    * > **提示**：`parent.color = sibling.color;` 字面就是父与兄换色；由于已判定兄弟为红、而红红相邻不允许，旋转前父亲必定是黑色，写死成红色也等价，但取兄弟的颜色语义更直白。

    * > **易错点**：末尾的 `fixDoubleBlack(x)` 不能省。旋转换色只是过渡完成，还欠着一个黑没还，不递归走一次双黑就会留在树里。

## 删除端：兄弟与两个侄子全黑

* **条件**

    * > **定义**：被调整节点触发双黑、兄弟是黑色、且兄弟的两个孩子也都是黑色时命中这一支；兄弟的两个孩子都是 `nil` 也照样命中。

    * > **提示**：判断颜色一定要把 `nil` 算成黑色，这是红黑树里最容易漏掉的一条。

* **调整规则**

    * 第一步兄弟变红，目的是让待删节点那条路径与兄弟那条路径的黑高同时减一，从而在子树内部对齐。

    * 随后看父亲：父亲是红就染黑，缺失的黑色就地补齐，当场收工；父亲是黑则无从补偿，把父亲当成新的被调整节点，让它再次触发双黑并向上递归。

    * > **结论**：父亲是红时兄弟变红、父亲变黑两步搞定，绝不能多转一步。

* **三个层次的例子**

    * 兄弟与侄子全黑、父亲是黑：兄弟变红后子树两侧同步减一，直接收工，无需任何旋转。

    * 兄弟与侄子全黑、父亲是红：兄弟变红后 `{待删, 父, 兄弟}` 这两条路径比别的少一个黑，把红色父亲染黑就地补齐。

    * 全黑多层树、父亲也是黑：没有空闲的红色可拿来补，以父亲为新的被调整节点继续触发双黑；每层都是「兄弟变红 → 父亲仍是黑 → 再以父亲为被调整节点」，一路递归到根，中间撞上红色父亲即刻收工。

    ```text
    删 1 → 双黑
       └ 兄弟 3 黑、两个侄黑 ⇒ 兄弟变红
            └ 1、3 两条路径各少一个黑，父亲 2 已是黑，没法补齐
                 └ 以「2」为被调整节点 ⇒ 再次触发双黑
                      └ 2 的兄弟 6 黑、两个侄黑 ⇒ 6 变红
                           └ 2、6 两条路径仍各少一个黑，父亲 4 已是黑
                                └ 再以「4」为被调整节点 ⇒ 双黑
                                     └ 4 的兄弟 12 黑、两个侄黑 ⇒ 12 变红
                                          └ 整棵树恢复平衡，1 可以安全落地
    ```

* **代码里的空指针分支**

    ```java
    if (sibling == null) {
        balance(parent);          // 没人可调，让父节点作为被调整节点向上递归
    } else if (isBlack(sibling.left) && isBlack(sibling.right)) {
        sibling.color = RED;      // 兄弟变红，兄弟那条路径也少一个黑
        if (isRed(parent)) {
            parent.color = BLACK; // 父红转黑就地补齐，收工
        } else {
            balance(parent);      // 父也是黑的，把债往上还
        }
    } else {
        // 侄子里有红的，一律落到下一支
    }
    ```

    * 「兄弟是黑色」是隐含了兄弟可能为 `null` 的，所以访问 `sibling.left` 之前必须先判 `sibling` 非空；万一真是 `nil`，走让父节点递归那条路。

    * 两个侄子都黑是这一支的唯一条件，条件不成立就意味着侄子里有红的，因此后面的 `else` 可以一把兜住下一支，不必另写判断。

    * > **易错点**：不要因为调试时「好像一直没走到过」`sibling == null` 分支就把它删掉，没测出来不等于它不存在，防御性代码的价值就在这里。

## 删除端：兄弟黑而侄子里有红

* **条件与变色失效的原因**

    * > **定义**：被调整节点触发双黑、兄弟是黑色、且兄弟至少有一个孩子是红色时命中这一支；两个侄子都是红也算命中。

    * 按前一支的思路走不通：兄弟染红之后，兄弟本就有红孩子，于是出现红红相邻、违反性质三。

    * > **结论**：变色解决不了的问题就用旋转解决，红红相邻正是两支的分水岭。

* **四种不平衡与旋转轴**

    * 这一支按「兄弟在左还是在右」乘「红侄子在兄弟的左还是右」拆成左左、左右、右右、右左四种，规则与插入端的四种形态同名。

    * > **结论**：左右先围绕兄弟左旋把自己掰成左左，再围绕父节点右旋；右左先围绕兄弟右旋再围绕父节点左旋；右左与右右对称，各做两次旋转。

* **左左的染色规则**

    * 围绕父节点右旋，随后染三处：旋上来的父节点变黑，补齐待删节点那条路径缺的黑；原兄弟继承父节点原来的颜色；红色左侄子变黑，补上本属于兄弟的那个黑色。

    * > **结论**：左左这套操作不管父亲是什么颜色都成立——父亲本来就黑时前两步等于空操作，红侄子照样要染黑；旋转把对颜色的依赖转嫁到节点身份上，而不依赖父亲当下的颜色。

    ```java
    // 左左：兄弟是左孩子，且兄弟的左孩子是红色
    if (sibling.isLeft() && isRed(sibling.left)) {
        sibling.left.color = BLACK;    // ① 红侄子变黑，补齐缺失的黑色
        sibling.color = parent.color;  // ② 兄弟继承父节点原来的颜色
        parent.color = BLACK;          // ③ 父节点变黑
        rightRotate(parent);           // ④ 围绕父节点右旋
    }
    ```

    * > **易错点**：染色顺序不能反，绝对不能先动父节点，因为第二步要写 `sibling.color = parent.color`，父节点先变黑就再也取不到它原来的颜色。口诀是先侄子、再兄弟、最后父亲。

* **左右的归约与染色时机**

    * 左右先围绕兄弟左旋把红侄子从右侄子变成左侄子，形状归约成左左，再围绕父节点右旋即可。

    * 染色从根上想：待删节点这条路径少一个黑，所以旋上来的父节点要变黑；将要取代父节点位置的那个节点继承父节点原来的颜色；旋转前的兄弟本来就是黑的，旋转后颜色不变。

    ```java
    // 左右：兄弟是左孩子，但红色的是兄弟的右孩子
    else if (sibling.isLeft() && isRed(sibling.right)) {
        sibling.right.color = parent.color;   // 变色必须写在左旋之前
        leftRotate(sibling);                  // 先把自己掰成左左
        rightRotate(parent);                  // 再按左左处理
    }
    ```

    * > **易错点**：左右这一支的顺序坑方向与左左相反，变色必须写在左旋之前；左旋做完 `sibling.right` 已经变成 `nil`，事后再取 `sibling.right.color` 就是标准的空指针。

    * 四个分支最后一步都是把 `parent` 染黑，这一行可以提到所有分支的外层统一执行。

* **两个红侄子怎么办**

    * 两个侄子都是红时，代码会先命中左左分支（条件写在最前面的 `if`）。

    * > **结论**：强行改走左右分支也成立——两种处理都能得到一棵平衡的红黑树，只是形状不同。

    * 若想让这个例子落到左右分支，把左右那段 `else if` 提到左左之前即可。

    * > **提示**：在网页示例上改动代码后要刷新页面才生效，这一步特别容易让人干等。

## 删除端：六种情况全景

| 情形 | 触发条件 | 处理手法 |
| --- | :--- | :--- |
| case 0 | 删除节点有两个孩子 | 李代桃僵：找后继节点交换键值，退化成一个孩子或没有孩子，把问题简化掉 |
| case 1 | 删的是根节点 | 没有剩余就直接置 `nil`、`root` 指向 `nil`；有剩余就用剩余的键值替换根节点的值，再把剩下的那个孩子置成 `nil` |
| case 2 | 删的是黑，剩下的是红 | 把剩下的这个红染黑，正好补足缺的那个黑 |
| case 3 | 双黑，兄弟是红色 | 过渡情况：通过一次旋转转化成 case 4 或 case 5 之一 |
| case 4 | 双黑，兄弟是黑、两个侄子也是黑 | 纯变色：兄弟变红；父亲红则父亲变黑收工，父亲黑则把父亲当被调整节点递归 |
| case 5 | 双黑，兄弟是黑、至少一个侄子红 | 变色加旋转：细分为左左、左右、右右、右左四种不平衡 |

* **全景的规律**

    * > **结论**：前两种是简化问题，case 3 是搭桥过河，case 4 与 case 5 才是真正干活的。

    * 两支的判定条件互斥——侄子全黑走 case 4，有红侄子走 case 5，一个 `if / else` 就分完。

    * 旋转只在 case 5 里登场，且只有四种固定姿势；旋转在前几支里由插入端承担。

## 删除端：组合例子

* **先过渡再落地**

    * 删一个兄弟为红的节点会先走 case 3：被删节点是左孩子就围绕父节点左旋，旋转后把父与旧兄弟的颜色互换，树暂时恢复平衡并 `return`。

    * 接着落到的分支由新兄弟决定：新兄弟已是黑色、两个侄子也为黑色（含 `nil`）就是 case 4，兄弟变红后待删节点与它这条路径各少一个黑，父亲是红色就染黑补齐，节点可以安全删除。

* **向上递归撞上旋转**

    * 删一个兄弟黑、侄黑、父亲也黑的节点：case 4 让兄弟变红后两条路径各少一个黑，父亲无红可补，于是以父亲为被调整节点递归。

    * 父亲那一侧兄弟是黑的但带一个红侄子，落到 case 5；兄弟在左、红侄子在右，属左右不平衡，先围绕兄弟左旋再围绕父节点右旋，欠账一次性还清，根节点最终必为黑色。

* **先李代桃僵再进 case 4**

    * 有两个孩子且父亲是红的：交换键值后待删对象变成红节点，真正删的是交换后落在叶子位置的黑节点；命中 case 4，兄弟变红使两条路径各少一个黑，父亲染黑补齐后安全删除。

    * 有两个孩子且父亲也是黑的：交换后同样是 case 4，兄弟变红后整棵树少一个黑，父亲一侧再次触发双黑，父亲的兄弟也是黑、侄黑，又是一次 case 4，把父亲的兄弟染红后整棵树平衡，再删掉该节点。

    * 有两个孩子且祖先链上很快撞上红父亲：交换后命中 case 4，兄弟变红后父亲恰好是红，染黑就地补齐，节点安全删除。

## 全流程收束

* **两条路线的触发点**

    * 插入端四种情况的判定顺序是：是根就染黑、父黑就收工、叔红走变色递归、叔黑走四种形态的旋转。

    * 删除端六种情况的判定顺序是：两孩子先降级、根节点单独摘、摘完按删黑与否分流、删黑缺黑再按兄弟颜色分三支。

    * > **结论**：两条路线的复杂度来源不同——插入端的复杂度集中在「叔黑要旋转」，删除端的复杂度集中在「删黑要还账」。

* **真正需要递归的三处**

    * 插入端只有叔红那一支递归，因为只有它把祖父染红后才可能把红红相邻往上一层传染。

    * 删除端有两处递归：叔红那一支旋转换色后必须再走一次，兄弟与侄全黑且父亲也是黑时把父亲当作新的被调整节点。

* **可背的调整口诀**

    * > **结论**：补一个黑只有两种手段——变色与旋转；旋转的姿势只有四种；判断颜色时 `nil` 一律算黑。
