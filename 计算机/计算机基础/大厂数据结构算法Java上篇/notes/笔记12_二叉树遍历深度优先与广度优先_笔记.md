# 二叉树遍历：深度优先与广度优先

## 深度优先遍历的共同点

* **深度优先遍历的前序、中序、后序**

    * > **定义**：二叉树的深度优先遍历可进一步分成前序、中序、后序三种，规则各不相同。
    * 三者唯一的共同特点：遍历过程中都要深入到叶子节点，也就是深入到离根节点更远的那些叶子节点。
    * 这条共同点是非递归写法的理解关键。

* **子树**

    * > **定义**：某节点的子树就是它左边的所有后代（称左子树）和右边的所有后代（称右子树）。
    * 例：根节点 `1` 的左子树是 `2` 和 `4`，右子树是 `3`、`5`、`6`。
    * 例：改看节点 `2`，它的左子树是 `4`，右子树没有，是空。

* **左右子树的访问方向**

    * 三个访问位（当前节点值、左子树、右子树）的先后次序，就是前序、中序、后序的唯一区别。
    * 三种遍历无论规则怎么排，最终都要扎到最深的地方把叶子看一遍。

---

## 三条访问规则

* **前序遍历（preorder）**

    * > **定义**：访问每个节点时，先访问该节点的值，然后访问该节点的左子树，最后访问该节点的右子树。
    * 值 → 左子树 → 右子树；进入一个节点后即可立刻打印它的值。
    * 打印出的正是值的顺序：访问到一个节点就把它的值打印出来。

* **中序遍历（inorder）**

    * > **定义**：访问每个节点时，先访问该节点的左子树，然后访问该节点的值，最后访问该节点的右子树。
    * 左子树 → 值 → 右子树；拿到节点后不能马上打印它的值。
    * 以根 `1` 的右子树为例，先打印的是 `5` 而不是 `3`：虽然先进入了 `3`，但 `3` 的左子树没走完就不能打印 `3` 的值。

* **后序遍历（postorder）**

    * > **定义**：先访问该节点的左子树，再访问该节点的右子树，最后才访问该节点的值。
    * 左子树 → 右子树 → 值；进入节点后左右子树都访问完之前不能打印它的值。
    * 最先打印出来的是最左侧叶子的值；根节点的值一定最后打印。

* **规则的记忆要求**

    * > **结论**：给一棵树，应该能立刻在脑中说出它的前序、中序、后序各是什么顺序，要练到熟练。
    * 三种遍历的差别只是把同三行代码的顺序调整一下。

## 示例树与遍历结果

### 第一棵示例树

```text
        1
       / \
      2   3
     /   / \
    4   5   6
```

* **节点关系**

    * 节点 `1` 的两个孩子是 `2` 和 `3`。
    * 节点 `2` 的两个孩子是 `4` 和 null。
    * 节点 `3` 的两个孩子是 `5` 和 `6`。
    * null 表示没有孩子。

* **三种遍历的输出**

    | 遍历方式 | 访问每个节点时的顺序 | 这棵树跑出来的结果 |
    | :--- | :--- | :--- |
    | 前序 preorder | 节点值 → 左子树 → 右子树 | 1 2 4 3 5 6 |
    | 中序 inorder | 左子树 → 节点值 → 右子树 | 4 2 1 5 3 6 |
    | 后序 postorder | 左子树 → 右子树 → 节点值 | 4 2 5 6 3 1 |

### 第二棵示例树

给节点 `2` 补上右孩子 `7`，用来讲清后序。

```text
          1
        /   \
       2     3
      / \   / \
     4   7 5   6
```

* **遍历序列**

    | 遍历 | 顺序 | 结果 |
    | :--- | :--- | :--- |
    | 前序 | 根左右 | 1 2 4 7 3 5 6 |
    | 中序 | 左根右 | 4 2 7 1 5 3 6 |
    | 后序 | 左右根 | 4 7 2 5 6 3 1 |

* **节点的两种状态色**

    * 灰色：该节点在遍历过程中还没有被访问过。
    * 绿色：该节点已经被访问过了。
    * 靠这两种颜色可以区分「已经走到」和「走到了但还没打印」。

## 递归实现

* **递归为什么直接可用**

    * > **定义**：每个节点遵守的遍历规则完全相同，将来调用的就是同一个方法；遇到其他节点时只要递归调用自身这个方法。
    * 所以左右子树就是对应着两次对同一个方法的递归调用。
    * 递归必须带结束条件：传进来的节点为 null 时直接 `return`。
    * > **易错点**：⚠️ 别漏掉递归的结束条件——右孩子传过去就是 null，下次递归发现是 null 就应该结束。
    * 想让输出与其他值分隔，就用 `print` 后面补一个空格，不用 `println`。

* **节点的构造**

    * 三参数构造方法的参数顺序是：第一个左孩子，第二个值，第三个右孩子。
    * 叶子节点调单参数构造，左右孩子都不赋值。
    * 单参数构造把 `value` 赋上；双参数构造再加 `left` 和 `right`。

```java
// 构造方法：第一个参数左孩子，第二个参数值，第三个参数右孩子
Node(int value) {
    this.value = value;
}

Node(Node left, int value, Node right) {
    this.left = left;
    this.value = value;
    this.right = right;
}

// 构造第一棵示例树
Node root = new Node(
        new Node(new Node(4), 2, null),          // 2：左孩子 4，右孩子 null
        1,
        new Node(new Node(5), 3, new Node(6))    // 3：左孩子 5，右孩子 6
);
```

### 打印放在不同位置

* **前序：打印放在最前面**

    * 先打印当前节点的值，再递归左子树，最后递归右子树。
    * 输出 `1 2 4 3 5 6`。

* **中序：打印放在中间**

    * 拿到节点先别急着打印值，先递归左子树；左子树访问完了再打印当前节点的值；最后递归右子树。
    * 输出 `4 2 1 5 3 6`。

* **后序：打印放在最后面**

    * 先递归左子树，再递归右子树，最后打印当前节点的值。
    * 输出 `4 2 5 6 3 1`。

```java
void preorder(Node node) {
    if (node == null) {
        return;
    }
    System.out.print(node.value + " ");   // 先访问节点的值
    preorder(node.left);                  // 再访问左子树
    preorder(node.right);                 // 最后访问右子树
}

void inorder(Node node) {
    if (node == null) {
        return;
    }
    inorder(node.left);                   // 先访问左子树：别着急打印当前节点的值
    System.out.print(node.value + " ");   // 左子树访问完了，再打印当前节点的值
    inorder(node.right);                  // 最后以相同的逻辑访问右子树
}

void postorder(Node node) {
    if (node == null) {
        return;
    }
    postorder(node.left);
    postorder(node.right);
    System.out.print(node.value + " ");   // 左右子树都完成了，最后处理这个值
}
```

## 非递归的突破口

* **三种遍历走的是同一条路径**

    * 打印值的顺序各不相同（前序 `1 2 4 3 5 6`、中序 `4 2 1 5 3 6`、后序 `4 2 5 6 3 1`），但它们在树中行走的路径其实一样。
    * 既然路径相同，非递归时就不必去管值的顺序，让它按各自的规则打印即可。

```text
都得从根节点出发，先走左边：
   1 → 2 → 4 →（4 左边没路了）→ 回 2 →（2 右边没路）→ 回 1
左边这棵子树走完了，再走右边：
   1 → 3 → 5 →（5 左边没路了）→ 回 3 → 3 → 6 →（6 左边没路了）→ 回 3
最后从 3 回 1，这就算走完一圈了
```

* **第一版代码：只沿着左边一路向下**

    * 用指针 `current` 表示当前节点，初值是根节点，让它不断向前走。
    * 效果只输出 `1 2 4`：`1` 打印后 `current` 变左孩子 `2`，再变 `2` 的左孩子 `4`，`4` 没有左孩子时 `current` 变成 null，循环退出。
    * 树没走全：还得能沿着 `4` 向回走，才能找到它后续右边的东西。

* **节点不认得回家的路，得上栈**

    * > **易错点**：节点类只有自己的左右孩子，没有父节点属性，所以在 `4` 这里根本找不到父亲 `2`，也就找不到来时的路。
    * 用栈记录来时的路：每经过一个节点就把它压栈；回来时按来时顺序 `1 2 4` 依次弹栈即可。
    * 栈可以用自己写的 `LinkedListStack`，也可以用 JDK 的 `LinkedList`，调用它的 `push` 和 `pop` 方法。

* **区分「去」和「回」**

    * `current != null`：左边这条路还没走完，走「去」的逻辑——打印值、压栈、`current = current.left`。
    * `else`：左边走到头了，该往回走——弹栈一个节点、打印它、`current` 换成它的右孩子。
    * 回到的最后一个节点就是右子树的起点：`node.right` 拿到的 `3` 就是右边路的起点。

```java
void dfs(Node root) {
    LinkedList<Node> stack = new LinkedList<>();
    Node current = root;

    while (current != null || !stack.isEmpty()) {
        if (current != null) {
            // 去
            System.out.print(current.value + " ");
            stack.push(current);
            current = current.left;
        } else {
            // 回
            Node node = stack.pop();
            System.out.print(node.value + " ");
            current = node.right;
        }
    }
}
```

* **外层循环的条件**

    * > **易错点**：⚠️ 循环条件只写 `current != null` 是错的——`current` 一旦为 null，外层 `while` 根本不进入，就来不及往回走。
    * 必须加上「栈不为空」这一条：`stack` 里还有东西说明来时的路还没回退完，此时不能结束循环。
    * 两个条件同时成立才进入循环，写成 `current != null || !stack.isEmpty()`。

* **完整走查**

    * 这段代码走出的打印序列是 `1 2 4 4 2 1 3 5 3 6`——去的时候打一遍，回的时候再打一遍。

```text
current = 1     去：打印 1，1 压栈，current = 1.left       栈=[1]
current = 2     去：打印 2，2 压栈，current = 2.left       栈=[1,2]
current = 4     去：打印 4，4 压栈，current = null         栈=[1,2,4]
current = null  回：弹出 4，打印 4，current = 4.right      栈=[1,2]
current = null  回：弹出 2，打印 2，current = 2.right      栈=[1]
current = null  回：弹出 1，打印 1，current = 1.right = 3  栈=[]
current = 3     去：打印 3，3 压栈，current = 3.left       栈=[3]
current = 5     去：打印 5，5 压栈，current = null         栈=[3,5]
current = null  回：弹出 5，打印 5，current = 5.right      栈=[3]
current = null  回：弹出 3，打印 3，current = 3.right = 6  栈=[]
current = 6     去：打印 6，6 压栈，current = null         栈=[6]
current = null  回：弹出 6，打印 6，current = 6.right      栈=[]
current = null  回到 3 再回到 1 没走成：此时 current 是 null，栈也空了
               两个条件都不成立，退出循环
```

* **最后的 `6 → 3 → 1` 为什么没走**

    * 此时 `current` 是 null，而 `6` 弹出以后栈也空了，两个条件都不成立，就退出循环。
    * 最后从 `6` 回 `3`、从 `3` 回 `1` 不再重要，遍历已经完整。

## 同一段代码实现前序与中序

* **打印放在「去」上得到前序**

    * 前序规则是值、左、右，处理到当前节点就可以立马打印它的值。
    * 红色区打印顺序：`1 2 4 3 5 6`。

* **打印放在「回」上得到中序**

    * 中序规则是左、值、右，去的时候不能打印值，得等所有左子树处理完再打印。
    * 回来的时候意味着它的左子树已经完成了，正好是「左、值」再处理一个右。
    * 蓝色区打印顺序：`4 2 1 5 3 6`。

* **切换方式**

    * 把「回」这段注释掉，这段代码就是前序遍历代码。
    * 把「去」注释掉、「回」取消注释，这段代码就是中序遍历代码。

* **用颜色区分打印时机**

    * 把 `print` 换成一个带颜色参数的方法，参数里的颜色码 `31` 是红色、`34` 是蓝色。

```java
void printColor(Object o, int color) {
    System.out.print("\033[" + color + "m" + o + " ");
}
```

### 前序的执行流程

* **一路向下**

    * 当前节点从根开始；前序是值、左、右，处理到当前节点就立马打印值。
    * 打印完把当前节点压栈记住回来的路，再把它的左孩子作为下一轮的当前节点；`2`、`4` 都照同一规则处理。

* **到达尽头转回退**

    * 处理 `4` 的左孩子时发现是 null，左边这条路走到头，`if` 不成立进入 `else`。
    * 往回走要做的是弹栈并处理右孩子：弹出 `4` 后检查它有没有右孩子；为 null 就继续向上回退弹 `2`，`2` 也没有右孩子，再弹 `1`。

* **转向右子树**

    * 弹出 `1` 后发现它有右孩子，把右孩子作为 `current`，`current` 再次进入循环处理 `3`。
    * `3` 打印并入栈后按值、左、右处理左孩子 `5`；`5` 没有左孩子，进入 `else` 弹栈，`5` 无右孩子继续回退弹 `3`；`3` 有右孩子，把 `6` 作为 `current` 进入下一轮。
    * 整条顺序为 `1 2 4 3 5 6`。

### 中序的执行流程

* **先把所有左子树过一遍**

    * 沿规划好的路线一直向左，左边走到头时 `current` 等于 null，进入 `else` 往回走。
    * 先弹出 `4`：左边都走完了，可以打印 `4` 的值；`4` 没有右孩子，右子树算完成，继续弹出 `2` 并打印 `2`；`2` 的右孩子也是 null，跳过。

* **回到根再向右**

    * 弹出 `1` 并打印其值，处理 `1` 的右孩子 `3`。
    * `3` 不能立刻打印，得先沿左路走到头：先走到 `5`，`3` 和 `5` 都被压入栈。
    * 回来时弹出 `5` 即可打印；`5` 无右孩子处理一下就跳过，继续弹出 `3` 并打印 `3`。
    * `3` 有右孩子，把右孩子做类似处理就完成。

## 后序遍历的弹栈时机

* **「去」的那一段完全相同**

    * `current` 沿左孩子一路往下走，走的过程中把经过的每个节点压进栈，走到头为止，这一行都不用改。
    * 有区别的只有回来的时候。

* **为什么中序可以立刻弹栈**

    * 中序从 `4` 回到 `2` 时，`2` 被弹出并打印，接下来就该去遍历它的右子树 `7`。
    * 等 `7` 处理完回来时根本不需要经过 `2`——栈里此时只剩 `1`，直接从 `7` 跳到 `1` 就行。
    * 所以中序回来时是直接把栈顶弹走，一个节点只用一次。

* **为什么后序不能立刻弹栈**

    * 后序规则是「左—右—根」，`2` 必须等左子树和右子树都处理完才能打印。
    * 从 `4` 回到 `2` 时左子树已完成、右子树 `7` 还没处理，所以 `2` 绝对不能弹，必须留在栈里等着。
    * 等 `7` 那边走完回来，才能把 `2` 弹出来并打印。

* **结论**

    * > **结论**：不是所有情况下都需要回来时立刻弹栈；有时候得让这个节点在栈里多留一会儿，等它的右子树处理完了再弹。

### 判定右子树是否已处理完

* **先 `peek` 再决定弹不弹**

    * 每次处理栈顶元素时不是一上来就弹出去，先拿 `stack.peek()` 得到 `pick`，左右子树都完成了才可以弹。
    * 左边不用判断：能走到 `else` 分支就意味着左子树肯定处理完了，因为「去」的时候已经把左子树都走完了。

* **右子树已完成的第一种情况**

    * 右子树本来就不存在，像节点 `4` 的右孩子是 `null`。
    * `null` 意味着右子树不用处理，等价于已经处理完了，所以 `pick.right == null` 时直接弹出并打印。

* **右子树已完成的第二种情况**

    * 右子树不为空但已经被处理完，像节点 `2` 的右孩子是 `7`，要靠记录最近一次弹出的元素来判断。
    * 判断方法：看栈顶元素的 `right` 是否等于上一次弹出的那个元素；相等说明右子树处理完了，可以弹栈打印。
    * 能从 `7` 往回走就说明右孩子已经处理完；从 `4` 回到 `2` 时上次弹的是 `4` 而 `2.right` 是 `7`，两者不等，`2` 先留着。

* **`pop` 变量的作用域**

    * 「最近一次弹出的元素」就是 `stack.pop()` 的返回值。
    * 弹栈只发生在真正要弹的地方，需要在**下一次**循环里拿它跟栈顶的 `right` 比较，所以这个变量必须定义在循环外面，初值给 `null`。
    * > **易错点**：⚠️ `pop` 定义在循环内，下次循环就取不到上一次弹出的值，整个判断直接失效。
    * 判定条件是一个「或者」：右子树是 `null`，或者右子树虽不为 `null` 但已处理完（等于上次弹出的元素）。
    * `else` 那一支不是把 `2` 弹走，而是让 `current = pick.right`，把右子树作为当前节点送进下一轮，`2` 留在栈里等着。

```java
public List<Integer> postorderTraversal(TreeNode root) {
    List<Integer> result = new ArrayList<>();
    if (root == null) return result;
    LinkedList<TreeNode> stack = new LinkedList<>();
    TreeNode current = root;
    TreeNode pop = null;                 // 最近一次弹栈的节点，必须定义在循环外
    while (current != null || !stack.isEmpty()) {
        while (current != null) {        // 去：一路压栈，这段跟前序中序完全一样
            stack.push(current);
            current = current.left;
        }
        TreeNode pick = stack.peek();
        if (pick.right == null || pick.right == pop) {
            stack.pop();                 // 右子树无需处理 or 已处理完成
            result.add(pick.value);
            pop = pick;
        } else {
            current = pick.right;        // 右子树还没处理，让它进入下一轮
        }
    }
    return result;
}
```

* **判定走查**

```text
压栈：current 沿左链走   1 → 2 → 4        栈（底→顶）：[1, 2, 4]

peek = 4，4.right == null      → 弹栈并打印 4，pop = 4
peek = 2，2.right = 7 ≠ pop(4) → 2 留在栈里，转去处理右子树 7
peek = 7，7.right == null      → 弹栈并打印 7，pop = 7
peek = 2，2.right = 7 == pop(7) → 弹栈并打印 2
```

* **每个节点被弹出的两条理由**

    * 要么因为「没有右孩子」被弹出，要么因为「上一次弹出的正好是我的右孩子」被弹出，两个条件缺一不可。
    * 一路打印结果是 `4 7 2 5 6 3 1`，与后序的期望顺序对得上。

## 统一模板

* **为什么基于后序的代码改**

    * 后序走的路是最全的，它其实是绕着所有节点走了一圈。
    * 前序和中序会提前把栈顶元素弹走，再回来的时候也是提前弹走，所以它们其实少走了几步路。
    * 好处是将来只需要记一套代码模板，不用记三份。

* **改造的两步**

    * 先把所有打印代码暂时去掉，剩下的一段就是完整的「绕树一周」。
    * 再做一个等价调整：原来的 `if` 有两个条件，现在拆成 `if / else if / else`，把第二个条件单独拎出来做一支。
    * 逻辑一点没变，只是多了一行重复代码，但正是这一拆后面才能在两处放不同的打印。

* **拆开后每行的含义**

    * 内层 `while` 里 `current = current.left`：接下来要处理它的左子树。
    * `else if` 分支里 `current = pick.right`：接下来要处理这个节点的右子树。
    * 第一个 `if` 的条件 `pick.right == null`：它没有右孩子，右子树无需处理。
    * 第二个 `else if` 的条件 `pick.right == pop`：右子树已经处理完成，是从右子树那边处理完往回走的。
    * 最后的 `else`：待处理这个右子树。

### 三种遍历的打印位置

* **前序**

    * 顺序是根—左—右，先打印值再处理左右子树，所以打印必须放在处理左子树之前，打印 `current.value`。
    * 只有 1 处打印。

* **中序**

    * 顺序是左—根—右，左子树处理完之后、右子树处理之前打印，打印 `pick.value`，因为此时节点还在栈里没弹出去。
    * 另一处是 `pick.right == null` 那一支：虽然右子树是空的，但这个值的打印不能少，得先打印完再去那个不存在的右子树。
    * 共 2 处打印。

* **后序**

    * 顺序是左—右—根，右子树处理完往回走时这个节点已从栈里弹出，弹出之后打印它的值。
    * 另一处是 `pick.right == null` 那一支：它同样意味着左右子树都处理完成了。
    * 共 2 处打印，打印的都是刚弹出的 `pick.value`。

* **打印位置对照**

    | 遍历 | 顺序 | 打印位置 | 打印的值 | 几处 |
    | :--- | :--- | :--- | :--- | :--- |
    | 前序 | 根 左右 | 处理左子树之前 | `current.value` | 1 处 |
    | 中序 | 左 根 右 | 处理右子树之前，以及 `pick.right == null` 分支 | `pick.value` | 2 处 |
    | 后序 | 左 右 根 | 弹栈之后，以及 `pick.right == null` 分支 | `pick.value` | 2 处 |

* **为什么必须拆成两支**

    * 正是因为 `pick.right == null` 这一支和中序、后序各自的打印位置在**执行时间上不一致**，刚才才必须把原来的 `if` 拆成两支。

```java
public void traversal(TreeNode root) {
    if (root == null) return;
    LinkedList<TreeNode> stack = new LinkedList<>();
    TreeNode current = root;
    TreeNode pop = null;
    while (current != null || !stack.isEmpty()) {
        while (current != null) {
            // 前序：在处理左右子树之前打印当前节点的值
            print(current.value, 31);
            stack.push(current);
            current = current.left;
        }
        TreeNode pick = stack.peek();
        if (pick.right == null) {
            stack.pop();
            pop = pick;
            print(pick.value, 34);   // 后序：无右子树，左右都已完成
            print(pick.value, 36);   // 中序：无右子树，打印完才轮到右子树
        } else if (pick.right == pop) {
            stack.pop();
            pop = pick;
            print(pick.value, 34);   // 后序：右子树已处理完成，往回走到当前节点
        } else {
            print(pick.value, 36);   // 中序：处理右子树之前，节点还留在栈里
            current = pick.right;
        }
    }
}
```

* **颜色约定**

    * 红色 `31` 是前序、蓝色 `34` 是后序、绿色 `36` 是中序。
    * 输出上红色的前序是 `1 2 4 7 3 5 6`，绿色的中序是 `4 2 7 1 5 3 6`，蓝色的后序是 `4 7 2 5 6 3 1`，三路全部对上。

## 力扣三道遍历题

* **题目**

    * 三道题分别是二叉树的前序遍历、中序遍历、后序遍历，要求返回二叉树的遍历序列。
    * 题目没有强制用递归或非递归，但建议用迭代算法完成——理由是递归太简单了。

* **改造成收集的三处**

    * 第一处：栈的实现换成 `LinkedList`，不用自己定义栈类，少往编辑器里粘贴一个类。
    * 第二处：把所有打印都删掉，先创建集合 `result`，把原来打印值的地方改成 `result.add(...)`。
    * 第三处：整个循环结束、遍历完成时 `result` 里已保存全部值，直接 `return result`。

* **三种遍历的添加点**

    * 前序只有一个添加点，直接在 `current.value` 那里加。
    * 中序有两处：没有右子树的那个分支里把栈顶元素值加进去；以及处理右子树之前把栈顶元素值加进去。
    * 后序有两处：没有右子树时在它弹栈之后把 `pick.value` 加进去；以及右子树处理完成之后把 `pick.value` 加进去。

```java
public List<Integer> preorderTraversal(TreeNode root) {
    List<Integer> result = new LinkedList<>();
    if (root == null) return result;
    LinkedList<TreeNode> stack = new LinkedList<>();
    TreeNode current = root;
    TreeNode pop = null;
    while (current != null || !stack.isEmpty()) {
        while (current != null) {
            result.add(current.value);   // 前序唯一的添加点
            stack.push(current);
            current = current.left;
        }
        TreeNode pick = stack.peek();
        if (pick.right == null || pick.right == pop) {
            stack.pop();
            pop = pick;
        } else {
            current = pick.right;
        }
    }
    return result;
}
```

## 对称二叉树

### 比的是外侧和内侧

* **配对规则**

    * 根节点不用检查，从根节点的左右孩子开始对比，先看它俩的值是不是一样。
    * 值相等表示至少从这两个节点开始是对称的，然后接着往下走。
    * 往下走时**不是左跟左比、右跟右比**，而是外侧配对、内侧配对。

```text
        1
      /   \
     2     2
    / \   / \
   3   4 4   3
```

```text
第 1 层：左 2      与  右 2
第 2 层：左 2 的左 3 与  右 2 的右 3   ← 外侧配对
         左 2 的右 4 与  右 2 的左 4   ← 内侧配对
```

* **逐层递归**

    * 下面一层完全类似，两个「3」之间也是外侧比外侧、内侧比内侧，这样一层层递归下去就能判断是否对称。
    * 检查过程中一旦发现两边不一样（比如这边是 `6` 那边不是 `6`），立刻结束递归，返回这是不对称的二叉树。

### check 的三种基本情况

* **为什么要独立的递归函数**

    * 题目给的函数只有一个参数，而检查需要两个参数，所以原来的函数不拿来做递归，重新写一个 `check`。
    * `check` 返回布尔值，`true` 表示对称，从 `root.left` 和 `root.right` 传进去。

* **两种空节点情况**

    * 左右两个孩子都是 `null`：说明对称，不用继续递归，直接返回 `true`。
    * 一边空一边不空：左边不空右边空肯定不对称，左边空右边不空同样不对称，返回 `false`。

* **都不为空时**

    * 先比较值，值不等一定不对称，返回 `false`。
    * 值相等时不能直接返回 `true`——两个 `2` 的值相等，并不敢保证它们的孩子对称。
    * 值相等只能说明「不排除对称」，最后还得接着递归向下继续对比。
    * 递归怎么走：外侧一对是 `check(left.left, right.right)`，内侧一对是 `check(left.right, right.left)`，两者逻辑与的结果就是最终结果。

* **两个可以省掉的判断**

    * 第二个 `if` 条件里的两个「不等于 `null`」是多余的：能执行到它就意味着 `left` 和 `right` 不会同时为 `null`。
    * 既然假定 `right == null` 那 `left` 肯定不为 `null`，多写的判断就是多余；假定 `left == null` 时 `right != null` 同理。
    * > **易错点**：这个简化能成立的前提是**前面必须有那个「两者同时为 `null`」的 `if`**，没有第一个 `if` 就不能这么写。

```java
public boolean isSymmetric(TreeNode root) {
    if (root == null) return true;
    return check(root.left, root.right);
}

private boolean check(TreeNode left, TreeNode right) {
    // 情况一：两边都为空，对称
    if (left == null && right == null) return true;
    // 情况二：一边空一边不空，不对称（两个 "!= null" 是多余的）
    if (left == null || right == null) return false;
    // 情况三：值不等，一定不对称
    if (left.value != right.value) return false;
    // 值相等不能直接返回 true，还得递归比外侧和内侧
    return check(left.left, right.right) && check(left.right, right.left);
}
```

## 二叉树的最大深度

### 教材深度与力扣深度差 1

* **两种定义**

    * 教材定义：从树的根节点出发，找到离根最远的那个节点，数一下从根到这个最远节点的总边数（图中线段数目），就是它的深度。
    * 力扣定义：在教材定义上多加 1；后面的题目解答一律以力扣为准。
    * 只有一个根节点的树，教材深度是 0，力扣深度是 1。

```text
第一棵                第二棵                 第三棵

    1                     1                      1
   / \                   /  \                    /
  2   3                 2    3                  2

离根最远：2 或 3        离根最远：4            只有根节点
教材深度： 1            教材深度： 2            教材深度： 0
力扣深度： 2            力扣深度： 3            力扣深度： 1
```

* **三组期望值**

    * 根 `1`，左孩子 `2`、右孩子 `3`：深度是 `2`。
    * 根 `1`，左孩子 `2`、右孩子 `3`，而 `3` 又有一个右孩子 `4`：深度是 `3`。
    * 只有一个根节点，它也算没有左右孩子的叶子节点：深度是 `1`。

### 递归求深度

* **递推式**

    * 本节点深度 = max(左子树深度, 右子树深度) + 1，那个 `+ 1` 是把本层算上。
    * 叶子节点可以直接求解：左右子树都是 `null`，深度看成 0，两个 0 挑一个大的还是 0，再加自身这一层 1，深度就是 1。
    * `Math.max` 就是两个数字挑一个大的返回；别忘了求完子树最大值之后还要 `+ 1`。
    * 叶子节点那个 `if` 其实可以去掉：传进来的正好是叶子 `4` 时，求左孩子深度得 0、求右孩子深度也是 0，挑大还是 0，加一正好是 1。

* **本质**

    * 这种思路本质上就是**后序遍历的递归应用**：先求左子树深度、再求右子树深度，与后序「左—右—根」的顺序吻合。
    * 其实就是在遍历后序的过程中得知了左右子树的深度，然后回到当前节点再做计算。

```java
public int maxDepth(TreeNode root) {
    if (root == null) return 0;                                  // null 的深度是 0
    if (root.left == null && root.right == null) return 1;       // 叶子节点深度是 1
    int d1 = maxDepth(root.left);                                // 左子树深度
    int d2 = maxDepth(root.right);                               // 右子树深度
    return Math.max(d1, d2) + 1;                                 // +1 是把本层算上
}
```

## 层序遍历

* **队列版的基本走法**

    * 根节点先进队列，每出一个节点就把它的左右孩子塞回队列，队列空了树也就走完了。
    * 只这么写虽然能把 7 个节点的值全打出来，但全挤在同一行，名字里那个「层」字还没体现出来。

* **分层的做法**

    * 外层循环保持不动，在里面再套一个内层循环；内层循环跑一次就输出一个换行符。
    * 第一层一个节点换一次行，第二层两个节点换一次行，第三层四个节点再来一次，分层效果立刻出来。
    * 内层循环到底该跑几次？就跑**当前这一层节点的个数**：第一层 1 次，第二层 2 次，第三层 4 次。

* **怎么知道每层有几个节点**

    * > **定义**：下一层节点数 = 当前层所有节点的孩子总数。
    * 第一层只有根，它有两个孩子，所以下一层是 2 个；第二层是 `2` 和 `3`，一共有 4 个孩子，所以第三层是 4 个节点。
    * > **易错点**：⚠️ 这个数没有规律可循，得自己算——一个节点可能有两个孩子、只有一个、还是一个都没有，事先不知道是哪种，别指望由上一层乘 2 推出来，那是满二叉树才有的性质。

### 计数变量 c1 与 c2

* **两个变量的分工**

    * `c1`：当前这一层的节点数，初值是已知的 `1`——一开始只往队列里塞了一个根节点，第一层就是 1 个。
    * `c2`：下一层的节点数，初值给 `0`，代表还不知道。

* **累加与交接**

    * 内层循环写成 `i < c1`，循环体里出队一个节点、打印它的值，顺带把它的左右孩子塞回队列。
    * 每塞一个孩子就 `c2++`——左孩子加一，右孩子也加一；内层循环跑完 `c2` 里就攒好了下一层的节点数。
    * 最后把 `c1` 更新成 `c2`，交接给下一轮外层循环。

* **三个要留意的地方**

    * 输出那里用 `print` 而不是 `println`，节点后面补一个空格；等这一层全打印完再统一换行，层次感才连贯。
    * 内层循环的次数不能写死：`c1` 每轮都在变，条件只能是 `i < c1`。
    * `c2` 是边循环边累加的，它必须在每个外层循环开始时重新归零——它是「下一层」的计数，上一轮的值对这一轮没用。

```java
public void levelOrder(Node root) {
    Queue<Node> queue = new LinkedListQueue<>();
    queue.add(root);

    int c1 = 1;                 // 当前层的节点数，一上来是已知的：第一层只有根
    while (!queue.isEmpty()) {
        int c2 = 0;             // 下一层的节点数，先归零，等着重新统计

        for (int i = 0; i < c1; i++) {
            Node node = queue.poll();
            print(node.value + " ");   // print 不换行，节点之间用空格隔开

            if (node.left != null) {
                queue.add(node.left);
                c2++;
            }
            if (node.right != null) {
                queue.add(node.right);
                c2++;
            }
        }

        println();               // 这一层输出完了，换行
        c1 = c2;                 // 下一层的节点数交接给 c1
    }
}
```

* **队列实现的选择**

    * 上面用的是自己写的队列类；搬到力扣上时可以把队列代码一起粘过去，麻烦的话就去掉接口定义简化一下。
    * 也可干脆换成 JDK 的 `LinkedList`——Java 的 `LinkedList` 本身就是一个双端队列，拿来做这道题完全够用。

### 改成收集而不是打印

* **目标结构**

    * 控制台打印只是演示，力扣那道题要的不是「把节点打印出来」，而是把这些节点收集起来。
    * 收集形式是两层嵌套集合：外面一个大集合 `result`，里面每一层再套一个小集合 `level`，元素类型是 `Integer`。

```text
大集合 result = [
    [ 1 ],             ← 第一层
    [ 2, 3 ],          ← 第二层
    [ 4, 5, 6, 7 ]     ← 第三层
]
```

* **三处改动**

    * 创建一个大集合 `result`，方法最后 `return result`。
    * 在「换行」的那个位置创建内层小集合——因为换行意味着一层结束了，正好是新一层开始。
    * 把原来「打印这个节点」的地方换成「把这个节点的值 `add` 到 `level` 里」；注意只存 `value`，不要把整个节点塞进去。内层循环跑完说明这一层收集齐了，再把 `level` 加进外层 `result`。
    * 核心那套 `c1` / `c2` 的计数逻辑一行没动。

* **空树特判**

    * 题目完全可能传一个 `null` 进来，`root == null` 说明里面根本没有任何节点数据，直接返回一个空的 `result` 就行，不用往下走。

```java
public List<List<Integer>> levelOrder(TreeNode root) {
    List<List<Integer>> result = new ArrayList<>();
    if (root == null) {
        return result;                  // 空树，返回空的二维列表
    }

    Queue<TreeNode> queue = new LinkedListQueue<>();
    queue.add(root);

    int c1 = 1;
    while (!queue.isEmpty()) {
        List<Integer> level = new ArrayList<>();   // 当前层的数据
        int c2 = 0;

        for (int i = 0; i < c1; i++) {
            TreeNode node = queue.poll();
            level.add(node.value);                  // 只收 value，不收节点

            if (node.left != null) {
                queue.add(node.left);
                c2++;
            }
            if (node.right != null) {
                queue.add(node.right);
                c2++;
            }
        }

        result.add(level);              // 这一层齐了，塞进大集合
        c1 = c2;
    }

    return result;
}
```

## 栈

* **栈的定义**

    * > **定义**：栈（stack）是一种线性结构，添加和删除都发生在同一个端。
    * 能做操作的那一头叫栈顶（top），另一端叫栈底（bottom），中间也不能动。
    * 生活类比是一摞厚的书：加书只能从最上面加，拿书也只能从最上面拿；想要最底下那一本只能把上面的全搬走。
    * 进出只能同进同出，中间没得插。

* **三种线性结构的操作位置**

    | 结构 | 能在哪儿做添加 / 删除 |
    | :--- | :--- |
    | 数组、链表 | 线的任意位置都行：两端、中间，想动哪儿动哪儿 |
    | 队列 | 只能两端：一端添加（队尾），一端删除（队头） |
    | 栈 | **只能一端**：添加和删除都发生在同一个端 |

* **接口里的五个方法**

    | 方法 | 干什么 | 失败 / 空时返回 |
    | :--- | :--- | :--- |
    | `push(value)` | 向栈顶添加元素，也叫「压入」 | 栈满了返回 `false` |
    | `pop()` | 从栈顶弹出元素（移除并取出） | 栈空了返回 `null` |
    | `peek()` | 拿到栈顶元素的值，**不移除** | 栈空了返回 `null` |
    | `isEmpty()` | 判断栈是不是空的 | 返回 `boolean` |
    | `isFull()` | 判断栈是不是已经装满了 | 返回 `boolean` |

    * `push` 和 `pop` 是一对，都在操作栈顶，中间和栈底碰都不碰。
    * `peek` 和 `pop` 长得像，区别就一个：拿不拿走。

### 链表版栈

* **节点类与三个属性**

    * 单向链表节点很简单：一个 `value` 和一个 `next` 指针。
    * `capacity`：容量，栈得有上限，用构造方法初始化。
    * `size`：栈中元素的个数，初值 0，不断往栈顶压元素就跟着涨，且不能超过 `capacity`。
    * `head`：头指针，最开始指向一个哨兵节点；刚建好时里面没元素，所以哨兵的 `next` 指向 `null`。

* **哨兵节点**

    * > **定义**：哨兵节点是一个值无所谓、只起「起跑线」作用的节点。
    * 作用是让头指针有东西可指，不必在空栈和首个节点之间做特判。

* **为什么一个头指针就够**

    * 链表版队列用了 `head` 和 `tail` 两个指针，栈只要一个就够。
    * 因为队列要操作两端（`head` 端移除、`tail` 端添加），两个指针才方便；栈只操作一端，全程只在栈顶做添加和移除。

* **空和满怎么判断**

    * 判断空可以看 `head.next` 是不是 `null`；也可以用 `size == 0`，这里用 `size` 更好维护。
    * 判断满更简单：`size` 不断增长，`size == capacity` 时就是装满了。

* **push：往前插一节车厢**

```text
  压入前                      压入 2 之后
   head                       head
    |                          |
    v                          v
  [哨兵] --> [1] --> null   [哨兵] --> [2] --> [1] --> null
  栈顶: 1                     栈顶: 2
```

    * 先判断栈满没有，满了就 `return false`。
    * 没满就创建新节点：`value` 来自参数，`next` 指向原来的第一个节点也就是 `head.next`。
    * 然后让 `head.next` 指向这个新节点，它就正式成为第一个节点、也就是栈顶；最后 `size++` 返回 `true`。

* **pop：从栈顶摘掉第一节**

    * 先判空，空了返回 `null`。
    * 不空的话先把第一个节点找出来记作 `first`，让 `head.next` 指向 `first.next`，相当于把 `first` 跳过去了；最后返回 `first.value`，注意 `size--`。

* **peek：看一眼但不动**

    * 照着 `pop` 复制一份改改：空栈还是返回 `null`；因为不移除，所以不需要 `head.next = first.next` 这一行，`size--` 也不要。
    * 还能再简洁一点：`first` 本来就等于 `head.next`，那两行完全可以合成一行，临时变量都不用留。

* **iterator 与测试用例**

    * 迭代器的指针 `p` 初值是 `head.next`，因为遍历要从第一个元素开始；整条链表以 `null` 收尾，所以 `p != null` 就继续。
    * 每次遍历先把 `p` 的 `value` 存进临时变量，再让 `p` 向后走一步 `p = p.next`，返回临时变量。
    * 容量为 3 的栈依次压入 1、2、3：1 在栈底，2 跑到栈顶，3 又在最上面，所以从栈顶到栈底是 `3、2、1`。
    * 再压第 4 个元素超过容量，返回 `false` 表示压入失败。
    * 测 `pop`：依次弹出的应该是 `3`、`2`、`1`，再弹一次栈已空返回 `null`。

```java
public class Node<E> {
    private E value;
    private Node<E> next;

    public Node(E value, Node<E> next) {
        this.value = value;
        this.next = next;
    }
}

private int capacity;
private int size;
private Node<E> head;

public LinkedListStack(int capacity) {
    this.capacity = capacity;
    this.size = 0;
    this.head = new Node<>(null, null);   // 哨兵节点，它没有后继
}

public boolean isEmpty() {
    return size == 0;          // 也可以写成 head.next == null
}

public boolean isFull() {
    return size == capacity;
}

public boolean push(E value) {
    if (isFull()) {
        return false;                  // 满了，压不进去
    }
    Node<E> node = new Node<>(value, head.next);   // 新节点指向原来的第一个节点
    head.next = node;                              // head 转而指向新节点
    size++;
    return true;
}

public E pop() {
    if (isEmpty()) {
        return null;                   // 空栈，没什么可移除的
    }
    Node<E> first = head.next;
    head.next = first.next;            // 把 first 跳过去
    size--;
    return first.value;
}

public E peek() {
    if (isEmpty()) {
        return null;
    }
    return head.next.value;            // 拿栈顶，但不移除
}

public Iterator<E> iterator() {
    return new Iterator<E>() {
        private Node<E> p = head.next;      // 从第一个元素开始

        @Override
        public boolean hasNext() {
            return p != null;               // null 是整条链表的结尾
        }

        @Override
        public E next() {
            E value = p.value;
            p = p.next;
            return value;
        }
    };
}
```

### 数组版栈

* **把栈顶安排在右边**

    * 属性有两个：底层数组 `Object[]`（元素类型是泛型 `E`，长度按构造方法传入的 `capacity` 在构造时创建，创建 `Object` 数组需要一次必要的类型转换）和指针 `top`。
    * 假设容量是 4，有效索引是 0、1、2、3，把数组的**左边视为栈底、右边视为栈顶**，越靠右越靠近栈顶。
    * 这个方向和链表版正好倒过来，因为数组往右边操作性能更高——往数组尾部添加、删除元素性能都更好。

```text
索引:  0    1    2    3
       +----+----+----+----+
       | a  | b  | c  | d  |
       +----+----+----+----+
       栈底            栈顶

top = 4   ← 已经走到数组末尾之外，此时 top == stack.length，栈满了
```

* **top 指向的不是栈顶元素**

    * > **注意**：这是数组版栈最容易搞错的地方——`top` 加一之后，指向的是栈顶元素的**后一个位置**，不是栈顶元素本身，真正的栈顶是 `stack[top - 1]`。
    * 所以 `pop` 里直接写 `array[top]` 是不行的，必须先减一才是栈顶元素。
    * 空和满的判据：初值 0，`top == 0` 就是空；`top` 不断自增，加满以后它的值等于数组长度，`top == stack.length` 就是满。

* **两种实现的判据对比**

    | 判据 | 链表实现 | 数组实现 |
    | :--- | :--- | :--- |
    | 空 | `size == 0` | `top == 0` |
    | 满 | `size == capacity` | `top == stack.length` |

* **push、pop、peek 的写法**

    * `push`：先判满，满了返回 `false`；没满就往栈顶索引位置塞进新元素，然后 `top` 往前走一步；合并成一行是 `stack[top++] = value`。
    * 能这么写是因为后置 `++` 是先做求索引的运算再加一：先拿 `top` 原来的值找到位置赋值，`top` 自己才加一。
    * `pop`：先判空返回 `null`；不空返回 `stack[--top]`，用**前置**自减，因为得先让 `top` 减一，减完的结果才是栈顶元素的位置。
    * `peek`：判空后返回 `stack[top - 1]`，不改 `top`，只能老老实实减一。
    * 弹出时**不用真的把被删元素清零**——只要让 `top` 减一，以后再读栈顶读到的是自减后的结果，被删的值就读不到了。
    * 数组版的迭代器要从右往左遍历：指针 `p` 初值给 `top`，`hasNext` 条件是 `p > 0`（减到 0 表示没有元素），`next` 返回 `(E) stack[--p]`。

    | 场景 | 写法 | 原因 |
    | :--- | :--- | :--- |
    | `push` | `stack[top++] = value` | 后置 `++`：先按旧的 `top` 定位，再自增 |
    | `pop` | `return stack[--top]` | 前置 `--`：先自减拿到栈顶位置，再取值 |
    | `peek` | `return stack[top - 1]` | 不改 `top`，只能老老实实减一 |

```java
public boolean push(E value) {
    if (isFull()) {
        return false;
    }
    stack[top++] = value;      // 后置 ++：先按 top 找到位置赋值，再自增
    return true;
}

public E pop() {
    if (isEmpty()) {
        return null;                   // 空栈，没什么可移除的
    }
    return stack[--top];        // 前置 --：先自减，再按自减后的结果取索引
}

public E peek() {
    if (isEmpty()) {
        return null;
    }
    return stack[top - 1];
}

public Iterator<E> iterator() {
    return new Iterator<E>() {
        private int p = top;            // 初始给 top，从右往左遍历

        @Override
        public boolean hasNext() {
            return p > 0;               // 减到 0，说明没有元素了
        }

        @Override
        @SuppressWarnings("unchecked")
        public E next() {
            return (E) stack[--p];      // 先自减拿到栈顶位置，再取值
        }
    };
}
```

## 有效的括号

* **题目与有效条件**

    * 给定一个只可能包含小括号 `()`、大括号 `{}`、中括号 `[]` 的字符串，判断括号是否有效。
    * 有效要求：每种括号都成对，且嵌套关系正确。
    * `()`、`{[]}` 这类成对出现的有效；`([)]` 这种虽然各自成对、但嵌套交叉的无效。

* **栈里存的是期望**

    * > **结论**：遇左括号就把「配对的右括号」压栈；遇右括号就跟栈顶比，相等就弹出、不等就立即判定无效。
    * 关键在于存进去的是**期望**，不是已经出现过的东西：看到左小括号 `(` 就先把 `)` 压进去，看到左中括号 `[` 就先把 `]` 压进去，每次操作的都是栈顶。
    * 遇到右括号时拿它跟栈顶元素比较，相等说明这对括号有效，配对之后栈顶这个「期望的右括号」就没用了，直接弹出来让栈里下一个元素继续跟右边这个字符匹配。

* **嵌套关系这条最容易漏**

    * 像 `([)]` 这样，小括号确实成了一对、中括号也确实成了一对，但不能让它们交叉着裹：要么小括号把中括号整个包起来，要么中括号把小括号整个包起来。
    * 所以「括号都成对」不等于「有效」。

* **实现细节**

    * 栈用自己写的数组版，元素类型用 `Character`；栈的大小选字符串的长度——虽然最多肯定放不了这么多，但成对出现时它最多放字符串长度的一半。
    * 用 `for` 循环从 0 到字符串长度减一，每轮取出当前字符：前三个条件都不成立，说明这个字符肯定是右括号。
    * 循环结束后判断所有括号是否都配上：栈空说明全部配对，不是空的说明还有没配上的，直接返回 `stack.isEmpty()`。
    * 道理是每成功匹配一对，栈顶就被弹掉一个；如果全程都能配上，循环结束时栈肯定被弹空。

```java
public boolean isValid(String s) {
    Stack<Character> stack = new ArrayStack<>(s.length());

    for (int i = 0; i < s.length(); i++) {
        char c = s.charAt(i);

        if (c == '(') {
            stack.push(')');            // 把"期望的右括号"压进去
        } else if (c == '[') {
            stack.push(']');
        } else if (c == '{') {
            stack.push('}');
        } else {
            // 前三个条件都不成立，必定是右括号
            if (!stack.isEmpty() && c == stack.peek()) {
                stack.pop();            // 成对了，弹掉，继续匹配下一组
            } else {
                return false;
            }
        }
    }

    return stack.isEmpty();             // 栈空了说明全部配上对了
}
```

### 测试用例炸出来的空指针

* **表现**

    * 前几个无效例子都在循环中间被拦下来返回 `false`：第二个字符跟栈顶元素不匹配直接返回；有两个测试用例先压两个右括号、第三个字符跟栈顶对不上，循环中间返回 `false`。
    * 还有两个例子是循环结束后发现栈不空，返回 `false`。
    * 但最后两个测试用例一打开就报空指针异常。

* **原因**

    * 最后两个用例的不同之处在于**第一个字符是一个右括号**，前面那些用例第一个字符都是左括号，所以一直没踩到坑。
    * 第一个字符是右括号时，前面的 `if` 条件都不成立直接进 `else`，但此时栈还是空的。
    * 栈为空时 `peek()` 返回 `null`，这个 `null` 又要跟基本类型的 `char` 做比较，Java 会尝试把 `null` 转成基本类型的 `char`，转换不了就抛空指针异常。

* **修法**

    * 只有当栈不为空的时候才能做后续的 `peek` 操作，不为空取出来的才不是 `null`，才能做比较。
    * 从道理上讲，第一个字符就是右括号必定无效，直接在这里返回 `false` 就行。

```java
} else {
    if (!stack.isEmpty() && c == stack.peek()) {
        stack.pop();
    } else {
        return false;              // 栈是空的，第一个字符就是右括号，必定无效
    }
}
```

* **结论**

    * > **结论**：代码不是一次就能写正确的，得设计不同的测试用例才能反映出代码里可能存在的问题。
    * 这次的坑就是「没考虑第一个字符是右括号的情况」——而这个坑恰恰只有当测试用例的**开头**变了才暴露得出来。

## 两条路线的关系

* **深度优先靠栈，广度优先靠队列**

    * 深度优先的三种次序靠一个显式的栈记住「来时的路」，节点只有左右孩子属性、认不得父亲，所以必须由栈代劳。
    * 广度优先的层序遍历靠队列按先进先出的顺序自然分层，用 `c1` / `c2` 两个计数变量把每一层切成一段。

* **分层的两种理解**

    * 深度优先的「层」体现在访问顺序上——三种次序都要扎到最深的叶子，看的是路径。
    * 广度优先的「层」体现在数据结构上——一层一个内层集合，层数等于大集合的规模。

* **同一棵树的四组序列**

    | 遍历 | 第一棵示例树 | 第二棵示例树（`2` 补右孩子 `7`） |
    | :--- | :--- | :--- |
    | 前序 | 1 2 4 3 5 6 | 1 2 4 7 3 5 6 |
    | 中序 | 4 2 1 5 3 6 | 4 2 7 1 5 3 6 |
    | 后序 | 4 2 5 6 3 1 | 4 7 2 5 6 3 1 |
    | 层序 | [1] / [2, 3] / [4, 5, 6] | 长文未说明 |
