# 二叉搜索树：查找、插入与最值

## 节点与树的设计

* **BSTNode（二叉搜索树节点，binary search tree 的缩写）**

    * > **定义**：构成二叉搜索树的节点，做成静态内部类 `BSTNode`。

    * 属性一共四个：

        | 属性 | 类型 | 作用 |
        | :--- | :--- | :--- |
        | `k` | `int` | 关键字，决定往左还是往右 |
        | `value` | `Object` | 节点携带的值，任意类型 |
        | `left` | `BSTNode` | 左孩子 |
        | `right` | `BSTNode` | 右孩子 |

    * `k` 选 `int` 的理由：k 与 k 之间必须能进行大小比较，`int` 做大小比较最简单；要扩展可以让它实现 `Comparable` 之类的接口。
    * `value` 定成 `Object` 的理由：值可以是任意东西，学生对象、字符串都行。
    * `left` 与 `right` 的类型就是 `BSTNode` 自己，左孩子叫 `left`、右孩子叫 `right`。
    * 构造方法备齐三个：按 k 创建节点、按 k 与 value 创建节点、按 k、value 再加左右孩子创建节点。

    ```java
    public static class BSTNode {
        int k;
        Object value;
        BSTNode left;
        BSTNode right;

        public BSTNode(int k) {
            this.k = k;
        }

        public BSTNode(int k, Object value) {
            this.k = k;
            this.value = value;
        }

        public BSTNode(int k, Object value, BSTNode left, BSTNode right) {
            this.k = k;
            this.value = value;
            this.left = left;
            this.right = right;
        }
    }
    ```

* **键值对与 map 的类比**

    * > **定义**：二叉搜索树做的事与 Java 的 map 集合很像——根据一个键，快速找到对应的值。

    * 节点上只挂一个 k 不够：光凭一个 key 没法把值捞出来，所以必须再挂一个 value。
    * 这个类比从设计节点那一刻起就一直成立，后面代码越写越像 map；`put` 也与 `map.put` 相像，但并不是要去实现一个 HashMap，而是要让一棵二叉搜索树把键值对放到该在的位置。

* **BSTTree（树类）**

    * > **定义**：外层的二叉搜索树类，属性只有一个 `root`，类型为 `BSTNode`，表示根节点。

    * 预先规划好的方法：

        | 方法 | 作用 |
        | :--- | :--- |
        | `get` | 根据 key 找到该节点所关联的值 |
        | `min` | 获得树中最小的 k，以及它关联的值 |
        | `max` | 获得最大的关键字，以及它关联的值 |
        | `put` | 把键值对存到树里，也就是添加 |
        | 前驱 | 找到比它小的所有值里最大的那个，也就是离它最近的 |
        | 后继 | 找到比它大的所有值里离它最近的那个 |
        | `delete` | 根据关键字删除节点 |

* **前驱与后继的含义**

    * 前驱：比它小的那些 key 中最大的那个，即离它最近、比它小的那个。
    * 后继：比它大的那些 key 中离它最近的那个。
    * 例：四的前驱是三，七的前驱是六，七的后继就是八。

* **delete 的删除边界**

    * > **注意**：`delete` 只是删除一个节点，不是把它后代节点都跟着删掉。

    * 删六时只是把六删掉，不会连着五一起删；五将来会挂到别的位置上去，把这棵树接起来。

## get 查找

### 三种走向

* 从根节点开始，把根节点的 k 与待查找的 k 做比较，只有三种走向：

    * 待查找的 k 小一些，就从根节点向左找。
    * 待查找的 k 大一些，就从根节点向右找。
    * 两个 k 值相等，就是已经找到了。

* 「相等就等于找到了」成立，是因为二叉搜索树里 k 的值是唯一的，唯一就不存在「这个 key 藏在别的分支上」的可能。
* 不管下一步向左还是向右，下一个节点的判断逻辑与根节点完全一样；每个节点的处理逻辑都相同，所以可以利用递归来求解。

### 递归版

* `doGet(BSTNode node, int key)` 是专门做递归的内部方法，返回 `Object` 表示将来返回的是这个 value，两个参数分别是当前节点与待查找的 key。

    ```java
    private Object doGet(BSTNode node, int key) {
        if (node == null) {
            return null;
        }
        if (key < node.k) {
            return doGet(node.left, key);
        } else if (key > node.k) {
            return doGet(node.right, key);
        } else {
            return node.value;
        }
    }
    ```

* 递归结束条件：node 已经到 null，它再向左找就是 null；null 表示没找到，应结束递归并返回 null。
* 「向左找」就是递归调用 `doGet`，这回传进去的 node 是 `node.left`；要比较的 key 始终不变。
* node 的 k 小于待查找的 k，说明待查找的 key 更大，就调用 `doGet(node.right)` 从右孩子继续。
* 既不小于也不大于就是相等，最终只想返回它的值，所以直接 `return node.value`。
* 公开方法只是一层包装，起点是 root：

    ```java
    public Object get(int key) {
        return doGet(root, key);
    }
    ```

* > **注意**：分成 `get` 与 `doGet` 两个方法，是让 `get` 对外隐藏 `BSTNode` 这个内部数据结构——使用者只要知道有这么个 k 就行，不需要知道他手里拿到的值到底是从哪个节点上翻出来的；`doGet` 是类内部自己用的、不暴露给外界，这是「公开的接口」与「内部的实现」之间那道墙。

### 测试树与断言

* 用来测试的树只有 4、2、6、1、3、5、7 七个节点：

    ```text
                4
              /   \
             2     6
            / \   / \
           1   3 5   7
    ```

* 一和三是叶子节点，父节点是二，二的左孩子是一、右孩子是三。
* 五和七也是叶子节点，父节点是六，六的左孩子是五、右孩子是七。
* 根节点是四，左孩子是二，右孩子是六；二只有一和三两个孩子。
* 键是唯一的，就是这里看到的 1 到 7 这七个键；值是一批人名，比如张无忌、周青书等。
* 断言：k 等于 1 应当返回张无忌，k 等于 2 应当返回周芷若，都测了一遍。
* 再测一个不存在的八：树里只有 1 到 7，找不到最终走 `node == null` 这个条件，返回 null 表示没有找到；期望值与实际运行结果一致，`get` 初步测试通过。

### 非递归版

* 把刚才的 `get` 注释掉，用同样名字和同样参数重写一个非递归版本，测试用例不用改。

    ```java
    public Object get(int key) {
        BSTNode node = root;
        while (node != null) {
            if (key < node.k) {
                // 向左走：下次循环从当前节点的左孩子开始
                node = node.left;
            } else if (key > node.k) {
                // 向右走：下次循环从当前节点的右孩子开始
                node = node.right;
            } else {
                // 找到了，直接返回，不需要再进循环
                return node.value;
            }
        }
        // 循环结束还没找到，说明整棵树里没有这个 key
        return null;
    }
    ```

* 先准备一个 `BSTNode` 变量，初始值为 root，因为总是从根节点开始比较。
* 循环条件是 `node != null`：只要当前节点不为空，就不断重复「小了向左、大了向右、相等即命中」的判断。
* k 小于 node 的 key，下一次循环 node 就变成左孩子；k 更大，node 就变成右孩子，每圈向左或向右推进一站。
* 命中后不需要再进循环，直接 return。
* 循环自然结束说明这个 key 在整棵树里没有，返回 null。

### 伪递归

* > **定义**：伪递归指一个函数的最后一步，也就是 `return` 的时候，调用的是函数自身、结果原封不动往上抛的写法。

* `return doGet(node.left, key)` 是典型伪递归，连结果都不加工直接抛上去。
* 遇到伪递归就该想一下是否改成非递归实现，性能会更好。
* 动机：Java 毕竟不支持尾递归的自动优化，这件事不妨交给程序员自己做。
* 凡是以前用递归实现的、属于伪递归的代码，转换成非递归代码非常容易。
* 尾递归里 `doMin` 也算比较简单的一种：判断逻辑不多，转换的参照范式就是它的递归版与非递归版这一对。

### 泛型化与 Comparable 上限

* > **定义**：泛型上限语法指在泛型声明中用 `extends` 关键字后面跟上界类型，用来限定该泛型实参必须是什么的子类型。

* 第一个想到的扩展手段是泛型：给外层 tree 类和内层节点类都加泛型声明，凡是出现 k 的地方都从 `int` 改成泛型 K。

    ```java
    public class BSTTree<K extends Comparable<K>> {

        public static class BSTNode<K> {
            K k;
            Object value;
            BSTNode<K> left;
            BSTNode<K> right;
            // 构造方法略
        }
    }
    ```

* 因为节点类用了泛型，声明左右孩子时也得补上泛型定义，写成 `BSTNode<K> left`、`BSTNode<K> right`，否则黄色的警告会一直杵在那里。
* 改完泛型还不能工作：随便给一个泛型 T，它不一定能参与大小比较，而 k 的前提就是必须能比较大小。
* Java 中要让任意一个类型具备能比较大小的能力，得让它实现 `Comparable` 接口。
* 加上 `K extends Comparable<K>` 之后，K 就有了上限——它必须是 `Comparable` 接口的子类型，不再是任意类型，k 才能进行大小比较。
* String 已经实现了 `Comparable` 接口，所以字符串可以作为 k 参与比较。

### 用 compareTo 改写查找判断

* > **提示**：`compareTo` 的方向千万别搞反——是「待查找的 key 去跟节点上的 key 比」，即 `k.compareTo(p.k)`；返回负数说明 k 小，该往左走。这一条极容易写反，记住这一条就够了。

* 泛型 K 既然是 `Comparable` 的子类型，就能直接用 `Comparable` 这个父类型里定义的 `compareTo`，它与另一个同样实现了 `Comparable` 的对象做大小比较。
* 仍然用非递归实现：指针 p 初值为 root，只要 p 不为空就不断循环。

    | 返回值 | 含义 | 查找方向 |
    | :--- | :--- | :--- |
    | 负数 | 待查找的 k 小于 `p.k` | 向左走，`p = p.left` |
    | `0` | 两者相等 | 找到了，返回 `p.value` |
    | 正数 | 待查找的 k 大于 `p.k` | 向右走，`p = p.right` |

    ```java
    public Object get(K k) {
        BSTNode<K> p = root;
        while (p != null) {
            int result = k.compareTo(p.k);
            if (result < 0) {
                // k 小于 p.k，向左走
                p = p.left;
            } else if (result > 0) {
                // k 大于 p.k，向右走
                p = p.right;
            } else {
                // 二者相等，找到了
                return p.value;
            }
        }
        return null;
    }
    ```

* 先把 `compareTo` 的返回值暂存在变量 `result` 里，再根据这个变量判断走向。
* 测试时节点类型带上泛型声明，k 取 a、b、c、d 这些字符串；a 仍对应张无忌、b 仍对应周芷若，测试通过。

### 还能再往前走的两步

* k 改成泛型后有可能传进来 null，最好对 key 做一个非空判断，否则去调用任何方法都会出空指针。
* value 也可以做成泛型：用大写 V 代表值的类型，凡是出现值的地方都改成 V；声明两个泛型后，声明变量时都得带上两个泛型类型参数，`return` 的 value 也就成了 V。
* 走到这一步回头一看，代码已经分成键和值两部分，与 Java 中的 map 集合非常像；泛型字母若想贴合「键 k」的第一个字母，可把 T 改成 K。
* 后面所有例子仍采用 `int` 作为 k 的类型，实现起来更简单；扩展性改造留给读者。

## min 与 max

### 判定标准

* > **定义**：`min` 负责查找最小关键字并返回它对应的值，`max` 负责查找最大关键字并返回它对应的值。

* `min` 的走法：从根节点开始不断向左找，一直走到头，走到头的那个节点就是最小关键字所在节点。
* 判定「向左走到头」的唯一标准是当前节点还有没有左孩子：有左孩子就是没走到头，没有就是走到头了。
* 例：四向左走到二，二再向左走到一，一没有左孩子，说明到一就到头了，一是最小关键字，返回它的值即可。
* `max` 与之完全对称：从根节点开始不断向右走，走到头时最右端的节点就是最大关键字所在节点，判定标准是当前节点还有没有右孩子。

### min 的递归版

* `doMin(BSTNode node)` 是独立的、专供递归的方法，参数就是当前节点对象。

    ```java
    private Object doMin(BSTNode node) {
        if (node == null) {
            return null;
        }
        // 已经走到头了，当前节点就是最小的那个
        if (node.left == null) {
            return node.value;
        }
        // left 不为空，说明没走到头，继续向左走
        return doMin(node.left);
    }

    public Object min() {
        return doMin(root);
    }
    ```

* `node.left == null` 表示向左已经没有路了，这时节点自己就算最小的，直接返回它的 value。
* `node.left` 不为空说明没走到头，继续向左走就是递归调用当前节点的左孩子；传进来是四就先看四的左孩子二，再看二，依次往下。
* 特殊情况：整棵树一开始就是 null、一个节点都没有时，根本没有什么最小节点可找，那些判断都没有必要，直接 `return null` 表示没有找到。
* 测试：这棵树里最小的关键字是 1，调用后返回的是张无忌，断言通过。

### min 的非递归版

    ```java
    public Object min() {
        if (root == null) {
            return null;
        }
        BSTNode p = root;
        while (p.left != null) {
            // 还有左孩子，说明向左还没走到头
            p = p.left;
        }
        // 走到头了，此时的 p 就是最左边那个节点
        return p.value;
    }
    ```

* 先判空：`root == null` 时没必要继续找最小关键字，直接返回 null。
* 指针 p 起点是 root，循环条件为 `p.left != null`；left 不为空说明没走到头，下一次循环让 p 等于 p.left，向左走一步。
* 退出循环时 p 就是最左边的节点，也就是最小关键字节点，返回 p.value；同一批测试用例照样通过。

### max

    ```java
    public Object max() {
        if (root == null) {
            return null;
        }
        BSTNode p = root;
        while (p.right != null) {
            // 还有右孩子，说明向右还没走到头
            p = p.right;
        }
        // 最右端的节点，就是最大关键字节点
        return p.value;
    }
    ```

* 树是空的直接返回；否则指针 p 从根节点出发不断向右走。
* 判定向右走到头的标准是当前节点的右孩子等于 null；right 不等于 null 就说明没走到头，让 p 等于 p.right 继续循环。
* 走到头后 p 就是最右端的节点，直接返回 p.value。
* 测试：这棵树最右侧是 7，对应值阴丽，调用 max 返回阴丽，断言通过。

## put 插入

### 两种情形

* > **定义**：`put(k, v)` 把一个键值对放进二叉搜索树，让它正确落到该在的位置上，整个方法只分两种情况。

    * k 在整棵树里已经有了：不新增，只做一个更新，用新传进来的值把这个节点里旧的 value 覆盖掉，位置不动。
    * k 在整棵树里根本不存在：把 key 和 value 封装成一个节点对象，挂到这棵树里。

* 两种情形都得先根据 k 到树里找一遍，看对应的节点在不在；因为要对 k 做查找，查找代码不重写，直接把 get 里那段查找逻辑拿过来用。
* 实现上采用非递归方式，因为非递归更简单。

### 两个出口

* 查找成功的出口只有一个：走到与 k 相等的那个节点。
* 查找失败的出口也只有一个：指针被推成 null。
* put 只要在这两个出口上分别接上「更新」和「新增」，剩下的活儿就是找对父节点。
* 从 get 复制来的代码要去掉那两处 return：原来走 `else` 的位置相当于找到了（能走到 else 说明既不小于也不大于，即相等），在这里做更新并 return；原来 while 循环结束的位置表示所有节点都比过一遍仍没找到，在这里做新增。

### 纸上推演

* 示例树贯穿整个插入过程，节点上只标 key，值对理解算法不重要就不画了：

    ```text
                    4
                  /   \
                 2     6
                / \   / \
               1   3 5   7
                          \
                           8
    ```

* put 一个已存在的 1：与根 4 比 1 < 4 向左，与 2 比 1 < 2 向左，与 1 比相等，命中后更新该节点的 value 并 return。

    ```text
      1 与 根 4 比   ->  1 < 4   ->  向左
      1 与   2 比   ->  1 < 2   ->  向左
      1 与   1 比   ->  相等    ->  命中，更新该节点的 value，return
    ```

* put 一个不存在的 9：与 4 比 9 > 4 向右，与 7 比 9 > 7 向右，与 8 比 9 > 8 想向右但 8 右边已空；因为 8 已是叶子节点、向右前进不了，走到头时 parent 停在 8，查找失败，于是把新节点 9 挂成 8 的右孩子。

    ```text
      9 与 4 比   ->  9 > 4   ->  向右
      9 与 7 比   ->  9 > 7   ->  向右
      9 与 8 比   ->  9 > 8   ->  想向右，但 8 右边已空
                              ->  查找失败，parent 停在 8
                              ->  新节点 9 挂成 8 的右孩子
    ```

### parent 比 node 慢一拍

* > **定义**：`parent` 是新节点将要挂上去的那个父节点引用，它比 `node` 慢一拍。

* 现有代码里没有一行是跟父亲相关的，办法是：循环里每转一圈，先把上一站记下来（`parent = node`），再按 k 的大小让 node 向左或向右推进。
* node 之所以能当父节点的信息来源，是因为它的值一路从根节点被更新成沿途的每一个节点；只要在它被推成 null 之前把引用留下来，就等于记下了新节点的父节点。

    ```text
      查找 9 的过程中，parent 与 node 各自停在哪：

      初始        parent = null      node = 4
      第 1 圈     parent = 4         node = 7     （9>4，向右）
      第 2 圈     parent = 7         node = 8     （9>7，向右）
      第 3 圈     parent = 8         node = null  （9>8，向右；8 没右孩子）
      退出循环    parent = 8   <--  新节点 9 的父亲
                  node   = null <--  查找失败信号
    ```

* ⚠️ **易错点**：`parent = node` 一定写在 if 判断之前。这样最后一次循环才会先把 8 记进 parent、再把 node 推成 null；如果写在判断之后，parent 就会晚一拍，最后只能记住 7，9 就会被挂错地方。

### 出循环后的三条新增分支

* 有了父节点和新节点，建立父子关系还差一步：新节点是父节点的左孩子还是右孩子——循环内的判断出了循环就失效了，得重新拿新节点的 k 与父节点的 k 比一次。
* 新节点比父节点的 k 小，就作为 parent 的左孩子；比父节点的 k 大，就作为 parent 的右孩子。

    | 条件 | 新增动作 |
    | :--- | :--- |
    | `parent == null` | 整棵树是空的，新节点直接当根 |
    | `k < parent.key` | 新节点作 parent 的左孩子 |
    | 其余情况 | 新节点作 parent 的右孩子 |

* 不可能再出现相等：相等的那条路径已经在循环里 return 走了，走的是更新逻辑，所以最后这个条件可以简化成一个 `else`。
* 空树这一支来自 parent 的初始值——树是空的话根本没有进 while 循环，循环结束时 parent 仍是 null，此时新节点没有父节点，就作为整棵树的根。
* 完整骨架：

    ```java
    public Node put(int k, Object v) {
        Node parent = null;          // 新节点要挂的那个父节点
        Node node = this.root;       // 当前考察的节点

        // 查找骨架：从 get 直接搬过来，两处 return 已砍掉
        while (node != null) {
            parent = node;           // 每转一圈，先把上一站记下来
            if (k < node.key) {
                node = node.left;
            } else if (k > node.key) {
                node = node.right;
            } else {
                // 出口一：k 已存在，只更新，不新增，也不必再向下走
                node.value = v;
                return;
            }
        }

        // 出口二：k 不存在，走到这里说明查找失败
        Node newNode = new Node(k, v);      // 键值来自我们这里的 key、value

        if (parent == null) {
            this.root = newNode;
        } else if (k < parent.key) {
            parent.left = newNode;
        } else {
            parent.right = newNode;
        }
    }
    ```

* 更新那一行就够：既然能执行到那儿，说明已经拿到了目标节点对象，把它的 value 属性换成新传进来的值即可。
* 这一版实现里节点类叫 `Node`、关键字字段叫 `key`，与前面 `BSTNode` / `k` 的命名不同，但承担的角色一样。

### 手工对拍测试

* 先依次 put 4、2、6、1、3、5、7、8 长出一棵树，再手工搭一棵一模一样的树作为期望值，用 `equals` 对拍。
* 比较过程只比较 k 值、不比较 value，结构一模一样就返回真，所以断言用 `assertTrue`。
* 更新场景：树建好后再 put 一个 1，1 已经存在，于是原对象被换成新值；再 get 一次，返回的应是更新后的值。

    @Test
    public void shouldInsertInOrderThenUpdateExistingKey() {

## 前任与后继

### 中序遍历的直觉与它的性能代价

* > **定义**：对二叉搜索树做中序遍历，得到的结果就是升序的结果；中序遍历的规则是「左、根、右」。

* 直觉做法：先把树里所有 k 排个序，本例排好就是 1 2 3 4 5 6 7 8；要找 4 的前任后继，它的前一个肯定是 3、后一个肯定是 5。

    ```text
      1..8 这棵树上的中序（左 -> 根 -> 右）：

      先一路压到最左 1，打印 1
      回 2，打印 2           ->  2 的左子树（1）已完成
      下到 3，打印 3
      回 4，打印 4           ->  4 的左子树（1 2 3）已完成
      下到 5，打印 5
      回 6，打印 6           ->  6 的左子树（5）已完成
      回 7，打印 7           ->  7 的左子树（5 6）已完成
      下到 8，打印 8

      输出：1 2 3 4 5 6 7 8   ——  升序
    ```

* 根节点的值不能一上来就打印：左子树还没遍历完，根的值得先放着；1 处理好了意味着 2 的左子树处理完成，才能打印 2，再处理 2 的右子树打印 3；同理 3 处理完，1 2 3 作为 4 的左子树完成，才能打印 4。
* > **注意**：实际实现前任后继并不会采用中序遍历，因为它的性能并不高。

* 笨办法要设两个指针：一个指向要找的节点，另一个在它前面、指向它之前的一个节点，两者同步向前推进。

    ```text
      找 8 的前任，最笨的实现要挂两个指针一起往前走：

      指针 A（要找的节点）  :  1  2  3  4  5  6  7  8
      指针 B（它前面一个）  :  1  2  3  4  5  6  7
                              ^                 ^  ^
                              A                 B  A

      A 走到 8 时 B 才停在 7  ->  8 的前任是 7
      可 8 恰好是最末尾，前面 1..7 全白走了一遍才换来这一个答案
    ```

* 后一个指针指到 8 时，前一个指针正好停在它的前任 7；但最坏情况下得把整棵树中序遍历一遍才知道前任是谁。

### 前任的两条规律

* 找前任有两条规律，按目标节点有没有左子树分。

    * 规律一：有左子树时，前任节点就是左子树的最大值。
    * 规律二：没有左子树时，从它的祖先节点里找「从左边来的、且离它最近的那个」。

* 规律一的验证：4 的左子树是 1、2、3，都比 4 小，在其中挑最大值 3，就是 4 的前任。
* 属于规律一的节点在这棵树里有：2（左子树只有 1，前任是 1）、4（左子树最大 3 是前任）、6（左子树只有 5，前任是 5）、7（左子树是 5、6，其中最大 6 是前任）。
* 规律二里「祖先」指父节点、爷爷节点、太爷爷节点等；条件是这个祖先必须从当前节点的左边来，并且是最近的。
* 规律二的验证：5 的祖先是 6、7、4，其中 6 是爹、7 是爷爷、4 是太爷爷；6 和 7 都是从右边来的、比 5 大，肯定不是前任，只有 4 从左边来，所以 5 的前任是 4。
* 继续验证：3 没有左子树，祖先里有 2 和 4，两者都从左边来但 2 更近，3 的前任是 2；8 的祖先 7 和 4 都从左边来，7 更近，8 的前任是 7，4 因为更远不算数。
* 反例：1 的祖先 2 和 4 都是从右边来的，没有一个从左边而来的祖先，所以 1 没有前任。

### predecessor 的实现

* 求某个 k 的前任，前提是得先找到这个节点本身；节点在树里都没有，就无所谓什么前任。
* 先写一遍查找，指针 p 初值为 root：k 更小就 `p = p.left`，k 更大就 `p = p.right`，两个 k 相等表示找到了。
* 找到后不能直接 return 方法，因为接下来还有逻辑；退出循环后 p 指向的就是找到的那个节点，对它套用规律一和规律二即可。
* 循环结束但 p 等于 null，表示节点没找到，它的前任也相当于不存在，直接返回 null。

    ```java
    public Object predecessor(int k) {
        Node ancestorFromLeft = null;   // 从左而来的最近祖先，初始为 null
        Node p = this.root;

        while (p != null) {
            if (k < p.key) {
                p = p.left;             // 向左走：当前祖先在右边，不记账
            } else if (k > p.key) {
                ancestorFromLeft = p;   // 向右走：祖先在左边，记一笔
                p = p.right;
            } else {
                break;                  // 找到了，但不能直接返回，后面还有活
            }
        }

        if (p == null) {
            return null;                // 连节点都没找到，前任自然也不存在
        }

        if (p.left != null) {
            return max(p.left).value;   // 规律一：左子树的最大值
        }

        // 规律二：没有左子树，取从左而来的最近祖先；没有就返回 null
        return ancestorFromLeft != null ? ancestorFromLeft.value : null;
    }
    ```

* 祖先不用单独去回溯父指针找：找 5 的过程中必然经历过 4、7、6 这些节点，它们就是 5 的祖先——查找路径上的每一步都在经历它的祖先。
* 「这个祖先是从左而来」翻译成代码就是「这一步是向右走的」：4 到 7 是向右走，说明 4 在左边；7 到 6、6 到 5 都是向左走，属于从右而来，不记账。
* `ancestorFromLeft` 初始为 null（可能根本没有这样的祖先），只在 `else if` 这个向右走的分支里赋值，在 `p = p.left` 分支里不赋值；命中节点后不再改动它。
* 循环结束后若它不为 null，它就是前任节点，用三元运算符返回它的值；等于 null 则说明没有从左而来的祖先，也就是没有前任，返回 null。

    ```text
      找 5 的查找路线，以及每一步在"记账"：

       4  --向右-->  7  --向左-->  6  --向左-->  5
       ^              ^
       |              七、6 都是从右边来的，不记账
       四从左边来  ->  ancestorFromLeft = 4

      命中 5 之后不再改动这个变量
      ->  它停在 4  ->  4 就是 5 的前任
    ```

* 推演找 1：从根 4 到 1 全程都走「k < 当前节点」的第一个 if，从没进过第二个 else if，所以 `ancestorFromLeft` 始终是 null，1 没有前任。

    ```text
      找 1：4 --向左--> 2 --向左--> 1
            每一步都走"k < 当前节点"的分支，第二条分支从未进入
            ancestorFromLeft 保持 null  ->  1 没有前任

      找 8：4 --向右--> 7 --向右--> 8
            每一步都走"k > 当前节点"的分支，依次记账 4 -> 7
            命中 8 后不再改动  ->  停在 7  ->  8 的前任是 7
    ```

* 推演找 8：第一次进入循环就走 else if 向右走，把变量更新成 4；继续向右走经过 7，再把变量更新成 7；命中 8 后变量停在 7，返回 7 的值。

### max 的通用化重载

* 规律一需要「找一棵子树的最大值」，而不是「找整棵树的最大值」——以 1、2、3 这棵子树为例，它的最大值就是以 2 为起点不断向右走到底得到的 3。
* 通用办法是让 max 接收任意一个节点类型作为参数：把原来「以根节点为起点」换成「以任意节点为起点」，就找的是这棵子树的最大值。

    ```java
    // 原版：只能找整棵树的最大值
    public Node max() {
        Node node = this.root;
        while (node.right != null) {
            node = node.right;
        }
        return node;
    }

    // 通用版：换成任意节点作为起点
    public Node max(Node node) {
        while (node.right != null) {
            node = node.right;
        }
        return node;
    }

    // 原版可以直接委托给通用版
    public Node max() {
        return max(this.root);
    }
    ```

* 找左子树的最大值时，`p.left` 就是这棵子树的起点，直接 `return max(p.left).value` 即可。

### 后任与前任的镜像

* 后任（后继节点）的两条规则与前任完全对称。

    * 规则一：有右子树时，后继节点就是右子树中的最小值——右子树里的节点都比它大，挑最小的才是离它最近的。
    * 规则二：没有右子树时，到祖先里找「从右而来的、且离它最近的那个」。

* 规则一的例子：5 有右子树，右子树里只有 6，所以 6 是 5 的后任；2 的右子树最小值 3 是 2 的后继；3 的右子树是 4，最小值 4 是 3 的后继；7 的后继是 8。

    ```text
      有右子树：取右子树最小值
          5 -> 6        （5 的右子树里只有 6）
          2 -> 3        （右子树 {3}）
          3 -> 4        （右子树 {4}）
          7 -> 8        （右子树 {8}）

      没有右子树：找从右而来的最近祖先
          1 -> 2        （祖先 2、4 都从右而来，最近的是 2）
          8 -> 无       （祖先 7、4 全是从左而来，一个都没有）
    ```

* 规则二的例子：1 没有右子树，祖先 2 和 4 都从右而来，离 1 最近的是 2，所以 2 是 1 的后继；8 也没有右子树，但祖先 7 和 4 全是从左而来，一个从右而来的都没有，所以 8 没有后继。

### successor 的实现

* 代码与 predecessor 完全对称，直接拷贝过来改：变量名换成 `ancestorFromRight`；既然是从右而来，把赋值语句挪到向左走的那个分支里。
* 还需要补一个通用的 `min`：把原来「从根节点找最小值」的逻辑照搬，参数换成任意一个节点类型，原来的 root 都用 node 代替。

    ```java
    public Object successor(int k) {
        Node ancestorFromRight = null;  // 从右而来的最近祖先，初始为 null
        Node p = this.root;

        while (p != null) {
            if (k < p.key) {
                ancestorFromRight = p;  // 向左走：祖先在右边，记一笔
                p = p.left;
            } else if (k > p.key) {
                p = p.right;            // 向右走：当前祖先在左边，不记账
            } else {
                break;
            }
        }

        if (p == null) {
            return null;
        }

        if (p.right != null) {
            return min(p.right).value;  // 规律一：右子树的最小值
        }

        // 规律二：没有右子树，取从右而来的最近祖先；没有就返回 null
        return ancestorFromRight != null ? ancestorFromRight.value : null;
    }

    // 通用版 min：任意节点作为起点，找这棵子树的最小值
    public Node min(Node node) {
        while (node.left != null) {
            node = node.left;
        }
        return node;
    }
    ```

### 两类情形汇总

* 前任与后继的判定规则互为镜像，各覆盖四种情形：

    | 情况 | 前任 | 后继 |
    | :--- | :--- | :--- |
    | 有左/右子树 | 左子树的最大值 `max(p.left)` | 右子树的最小值 `min(p.right)` |
    | 没有左/右子树 | 路径上从左而来的最近祖先（最后一步向右走的那一站） | 路径上从右而来的最近祖先（最后一步向左走的那一站） |
    | 找不到该节点 | `null` | `null` |
    | 对应祖先也不存在 | `null`（本树中 1 没有前任） | `null`（本树中 8 没有后继） |

* 以 1..8 这棵树为例：1 的前任为 null、8 的前任为 7、5 的前任为 4；1 的后继为 2、5 的后继为 6、8 的后继为 null。
