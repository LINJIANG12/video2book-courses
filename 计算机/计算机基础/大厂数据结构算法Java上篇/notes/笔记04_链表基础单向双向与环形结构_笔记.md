# 链表基础：单向、双向与环形结构

## 链表的遍历

### 遍历的起点与终点

* **遍历指针（pointer）**
    * > **定义**：一个类型为 `Node`、初值为 `head` 的变量，借 `next` 指针逐个访问链表节点。
    * 起点必须是 `head`，它间接指向链表的第一个节点。
    * 循环条件是 `pointer != null`；指针指向 `null` 表示所有节点都处理过，退出循环。
    * 每轮末尾执行 `pointer = pointer.next`，把指针挪到下一个节点。
    * 指针变量名可用 `pointer`，也可简写成 `p`。

    ```text
    head ──▶ [1] ──next──▶ [2] ──next──▶ [3] ──next──▶ [4] ──next──▶ null
              ▲
              │
              └─ 第 1 轮：p 停在这里
    ```

* **逐轮推进**
    * 第 1 至 4 轮指针依次停在 node(1)、node(2)、node(3)、node(4)，循环条件均为真，轮末动作都是 `p = p.next`。
    * 第 5 轮指针指向 `null`，循环条件为假，不处理任何值，直接退出循环。

    ```text
    轮次   p 指向      循环条件 p != null    本轮处理的值   轮末动作
     1     node(1)     true                 1             p = p.next
     2     node(2)     true                 2             p = p.next
     3     node(3)     true                 3             p = p.next
     4     node(4)     true                 4             p = p.next
     5     null        false                ——            退出循环
    ```

* > **提示**：后面所有遍历写法——`while` 版、`for` 版、迭代器版——都是这张表的不同翻译。

### while 版与 for 版

* **loop（while 版）**
    * 方法名不用 `forEach`，避免与接口中已有的 `forEach` 冲突，改叫 `loop`。
    * 对链表节点要执行的操作不要写死在循环里，应通过 `consumer` 参数从外界传进来。
    * `consumer` 接收一个参数、没有返回值，参数就是当前节点的 `pointer.value`；具体怎么做由调用方决定。

    ```java
    public void loop(Consumer<Integer> consumer) {
        Node pointer = head;

        while (pointer != null) {
            consumer.accept(pointer.value);
            pointer = pointer.next;
        }
    }
    ```

* **loop2（for 版）**
    * `for` 循环三部分与链表遍历一一对应：第一部分赋初值，第二部分是循环条件，第三部分改变循环变量。
    * 循环体内执行的仍是 `consumer` 对当前节点的操作。

    | `for` 循环的三部分 | 作用 | 在链表遍历里对应什么 |
    | :--- | :--- | :--- |
    | 第一部分 | 给循环内的临时变量赋一个初始值，它只会执行一次 | `Node pointer = head` |
    | 第二部分 | 循环条件，为真就不断循环，为假就退出循环 | `pointer != null` |
    | 第三部分 | 改变循环变量，在每次循环结束时把它改成下一个值 | `pointer = pointer.next` |

    ```java
    public void loop2(Consumer<Integer> consumer) {
        for (Node pointer = head; pointer != null; pointer = pointer.next) {
            consumer.accept(pointer.value);
        }
    }
    ```

* > **提示**：`while` 版与 `for` 版都要掌握，可以优先选自己熟悉的一种，但另一种也要能读懂——面试和阅读别人代码时两种都会撞上。

### 迭代器与增强 for

* **`Iterable` 接口**
    * 链表类实现 `Iterable<Integer>`，泛型是 `int` 值对应的包装类型 `Integer`。
    * 接口的抽象方法 `iterator()` 要求返回一个 `Iterator` 迭代器对象。
    * `hasNext` 询问是否还有下一个元素；`next` 返回当前元素的值并让指针指向下一个元素。

* **匿名内部类实现**
    * `pointer` 作为迭代器的属性，类型为 `Node`，初值为 `head`。
    * `hasNext` 直接 `return pointer != null`。
    * `next` 先用临时变量 `v` 取 `pointer.value`，再执行 `pointer = pointer.next`，最后返回 `v`。
    * 增强 `for` 的底层就是调用 `hasNext` 与 `next`。

    ```java
    public class SingleLinkedList implements Iterable<Integer> {

        @Override
        public Iterator<Integer> iterator() {
            return new Iterator<Integer>() {

                Node pointer = head;

                @Override
                public boolean hasNext() {
                    return pointer != null;
                }

                @Override
                public Integer next() {
                    Integer v = pointer.value;
                    pointer = pointer.next;
                    return v;
                }
            };
        }
    }
    ```

* **输出必然是倒序**
    * `addFirst` 是头插，元素逆着加进去；`loop` 顺着链表走，输出自然是倒着的。
    * 越往后加的元素位于链表的越前面，四是最后加的，所以最先被打印。
    * 依次头插 `1 2 3 4` 后遍历，结果是 `4 3 2 1`，输出 `4321` 说明遍历本身没写错。

    ```java
    @Test
    void loopTest() {
        SingleLinkedList list = new SingleLinkedList();
        list.addFirst(1);
        list.addFirst(2);
        list.addFirst(3);
        list.addFirst(4);

        for (Integer value : list) {
            System.out.println(value);      // 4 3 2 1
        }
    }
    ```

### 内部类能否加 static

* **判定经验**
    * > **定义**：当一个类使用了外部类的一个成员变量时，它就不能加 `static`。
    * `Node` 的 `value` 与 `next` 都是它自身的，与外部类任何成员变量没有联系，所以可以加 `static`。
    * `NodeIterator` 的字段初值是外部类的 `head`，相当于跟外部类的实例相关，所以不能加 `static`。
    * 推荐做法是能加就加，实在必须用到外部成员变量时才去掉。

    ```java
    public class SingleLinkedList implements Iterable<Integer> {

        static class Node {          // 能加 static：value 和 next 都是它自己的
            int value;
            Node next;
            Node(int value) { this.value = value; }
        }

        class NodeIterator {        // 不能加 static：它用了外部类的 head
            Node pointer = head;
            // ...
        }
    }
    ```

* **匿名内部类的来历**
    * `new Iterator<Integer>() { ... }` 这种没有名字的内部类称为匿名内部类。
    * 在 IDE 里对这段代码右键 `Refactor` → `Convert anonymous to inner class`，可以把它转成带名字的内部类，直观看出 `static` 的差异。

## 单向链表的增删查

### 尾部添加：findLast 与 addLast

* **头插与尾插的难度差**
    * 头部添加只需两步：新建节点让其 `next` 指向原第一个节点，再让 `head` 指向新节点。
    * 头插涉及的两个对象都是已知的，不用额外查找。
    * 尾部添加卡在"最后一个是谁"——它不是已知的，只能从 `head` 一路走过去。

    ```text
    addFirst：只动两个已知的东西
        新建 node(5) ──next──▶ 原第一个节点 ──▶ ...
        建好之后，再让 head 指过来
        head 知道第一个是谁，原第一个节点就在那儿，都不用查

    addLast：卡在"最后一个是谁"
        head ──▶ 第一个 ──▶ 第二个 ──▶ ... ──▶ 最后一个 ──▶ null
        head 知道第一个，之后的节点都得依次查找
    ```

* **findLast**
    * > **定义**：返回链表中最后一个节点的 `Node` 对象；只供内部查找使用，标识符为 `private`，不把 `Node` 暴露给外界。
    * 判据：节点的 `next` 指向 `null`，它就是最后一个节点，其他节点的 `next` 都有东西。
    * 实现：指针初值 `head`，只要 `pointer.next != null` 就不断后移，循环结束时 `pointer` 即最后一个节点。
    * 空链表必须提前返回 `null`，否则 `head` 为 `null` 时访问 `null.next` 会空指针。
    * 改写成 `while (pointer.next != null) { pointer = pointer.next; }` 效果完全一样。

    ```java
    private Node findLast() {
        Node pointer = head;

        if (pointer == null) {
            return null;   // 空链表：根本没有最后一个节点
        }

        for (; pointer.next != null; pointer = pointer.next) {
            // 循环体什么都不做，只为了把指针一路推到最后一个节点
        }

        return pointer;    // 循环结束时，pointer 指向的就是最后一个节点
    }
    ```

* **addLast**
    * 先 `findLast` 拿到 `last`；`last` 为 `null` 说明是空链表，此时添加第一个节点与添加最后一个节点逻辑相同，转调 `addFirst` 后立刻返回。
    * 非空时新建节点，`node.next = null` 使它成为新尾巴，再让 `last.next = node` 让原尾巴有了后继。
    * 连续四次 `addLast` 加 `1 2 3 4` 会同时覆盖空链表与非空链表两条分支，可用 `expected.equals(list)` 断言验证。

    ```java
    public void addLast(int value) {
        Node last = findLast();

        if (last == null) {
            // 空链表：添加第一个节点跟添加最后一个节点，逻辑其实是一样的
            addFirst(value);
            return;
        }

        Node node = new Node(value);
        node.next = null;         // 它成了新的尾巴
        last.next = node;         // 原来那个尾巴 now 有后继了
    }
    ```

### 按索引取值：索引只能算，不能存

* **索引的来源**
    * 链表节点只存 `value` 与 `next`，并不记录索引。
    * 索引必须在遍历过程中逐步算出：第一个节点是 0，再往后依次 1、2、3。
    * 给节点加一个索引字段不可行——删掉中间节点后，其后所有节点的索引都要跟着改，维护成本过高。

    ```text
    删除索引 2 的节点之前：
      head ──▶ [1] ──▶ [2] ──▶ [3] ──▶ [4] ──▶ null
       索引     0       1       2       3

    删除索引 2 的节点之后：
      head ──▶ [1] ──▶ [2] ──▶ [4] ──▶ null
       索引     0       1      （原本是 3，现在得改成 2）
    ```

* **for 循环的语法限制**
    * `for` 循环第一部分只能声明同一种类型的变量，`Node pointer` 与 `int i` 类型不同，必须分开写。
    * 第三部分支持用逗号隔开的多条表达式，可以同时写 `pointer = pointer.next, i++`。
    * `int i` 初值为 `0`，每轮末尾 `i++`，与 `pointer` 同步后移。

    ```java
    // ✘ 语法错误：第一部分里 Node 和 int 不是同一种类型
    for (Node pointer = head, int i = 0; pointer != null; ...)

    // ✔ 第三部分支持多条表达式：指针后移，并且 i 加加
    for (Node pointer = head; pointer != null; pointer = pointer.next, i++) {
        System.out.println(pointer.value + " " + i);
    }
    ```

### findNode 与 get

* **findNode**
    * > **定义**：`private Node findNode(int index)`，返回索引 `index` 对应的节点；找不到返回 `null`。
    * 从 `head` 起遍历，用 `i` 记索引，`i == index` 时返回当前指针指向的节点。
    * 遍历完仍未命中说明超出了正常索引范围，返回 `null` 表示没找到，例如四个元素去查索引 10。

    ```java
    private Node findNode(int index) {
        Node pointer = head;

        for (int i = 0; pointer != null; pointer = pointer.next, i++) {
            if (i == index) {
                return pointer;      // 找到了，返回当前指针指向的节点
            }
        }

        return null;                 // 遍历完还没找到：索引越界
    }
    ```

* **get**
    * 对外方法 `public int get(int index)` 关心的是节点的值而不是节点对象，所以返回 `int`。
    * 内部调用 `findNode(index)`，`node == null` 表示没找到，抛 `IllegalArgumentException`。
    * 异常信息用 `String.format` 构造：`%d` 是数字占位符，`%n` 是换行，把具体的 `index` 填进去告诉调用方是哪个索引不合法。
    * 不用 `-1` 作失败返回值，因为列表中的值本身可能存负数。

    ```java
    public int get(int index) {
        Node node = findNode(index);

        if (node == null) {
            throw new IllegalArgumentException(String.format(
                    "index %d 不合法%n请检查你传入的 index 值", index));
        }

        return node.value;
    }
    ```

### 已实现的方法清单

* **清单**
    * 遍历提供三种写法：自己写的 `while` 循环、自己写的 `for` 循环、`iterator` 迭代器。

    | 方法 | 作用 |
    | :--- | :--- |
    | `addFirst` | 向链表的头部添加元素 |
    | `addLast` | 向链表的最后一个位置添加元素 |
    | `get` | 获取某个索引位置的元素 |
    | `findNode` | 根据索引找到节点，未找到返回 `null` |
    | `findLast` | 找到最后一个节点，空链表返回 `null` |

* **抽取查找方法的目的**
    * 找最后节点、按索引找节点都抽成独立方法，好处是这些查找逻辑以后在其他地方还能重用。

## 按索引插入与删除

### insert：先找上一个节点

* **插入的两步**
    * 往索引 `index` 插入时，要先找到上一个节点 `previous`，也就是 `index - 1` 位置的节点。
    * 单向链表只能往后指，接入新节点唯一的下手处就是前一个节点的 `next`。
    * 第一步 `node.next = previous.next`，让新节点接上原后继；第二步 `previous.next = node`。
    * 两步的顺序不能反：先动了 `previous.next`，原来那个后继就再也拿不到了。

    ```text
    插入前，index = 2：
        head ──▶ [1] ──▶ [2] ──▶ [3] ──▶ [4] ──▶ null
         idx0     idx1     idx2     idx3
                   ▲ previous，新节点要插在 idx2 前面

    插入后，index = 2：
        head ──▶ [1] ──▶ [2] ──▶ [N] ──▶ [3] ──▶ [4] ──▶ null
         idx0     idx1     idx2     idx3     idx4
    ```

* **实现**
    * `insert(int index, int value)` 无返回值，先判 `index == 0` 走 `addFirst` 并立即 `return`。
    * `previous` 直接复用 `findNode(index - 1)`，拿到后判空，为空则抛异常。
    * 新建节点的 `next` 要与 `previous.next` 指向同一个对象，所以写 `node.next = previous.next`。

    ```java
    public void insert(int index, int value) {
        // 索引为零时，走头部插入，后面这套逻辑一概不用跑
        if (index == 0) {
            addFirst(value);
            return;
        }

        // 关键的第一步：找到索引位置的上一个节点
        Node previous = findNode(index - 1);
        if (previous == null) {
            throw illegalIndex(index);
        }

        // 第二步：创建新节点，并让它接上原来的后继
        Node node = new Node(value);
        node.next = previous.next;

        // 第三步：把上一个节点接到新节点上
        previous.next = node;
    }
    ```

* > **提示**：链表插入的难点从来不是那两行赋值，而是"能不能找到该往哪儿插"；找到 `previous` 之后，插入本身是免费的。

### 插入的合法索引范围

* **边界取值**
    * 插入的合法索引是 `0` 到 `size`；`size` 那个位置正好落在链表末尾之外，看起来还没有元素，但仍是合法的追加位置。
    * 索引 `4` 时 `4 - 1 = 3` 能取到 `previous`，后面的逻辑照常执行，等价于追加。

    | 操作 | 结果 | 说明 |
    | :--- | :--- | :--- |
    | `insert(2, 5)` | `1 2 5 3 4` | 最典型的中间插入 |
    | `insert(4, 5)` | `1 2 3 4 5` | 插到末尾，等价于追加 |
    | `insert(10, 5)` | 抛异常 | 索引越界，previous 找不到 |
    | `insert(0, 5)` | `5 1 2 3 4` | 特例，走 `addFirst` |

* > **易错点**：`index == 0` 的判断必须写在 `findNode(index - 1)` 之前。写在后面等于没写——`findNode(-1)` 返回 `null`，代码会先一步抛异常，永远走不到 `addFirst`。

### removeFirst 与 remove

* **removeFirst**
    * 删除第一个节点只需让 `head` 指向原来的第二个节点，链表里就剩 `2 3 4` 了。
    * 被摘掉的节点与列表失去联系，从 `head` 出发再也够不到它。

    ```text
    删除前：head ──▶ [1] ──▶ [2] ──▶ [3] ──▶ [4] ──▶ null
    摘掉 head 与 [1] 的连接之后：
            head ──▶ [2] ──▶ [3] ──▶ [4] ──▶ null
    [1] 被挪到了画外 —— 从 head 出发已经再也够不到它
    ```

* **被摘节点的内存**
    * Java 的规则是：只要一个对象将来没有任何人引用它，垃圾回收时就可以把它占用的内存回收掉。
    * 被删除节点没有任何指针指向它，GC 时内存就能释放，不必额外处理。
    * 换成 C 这类不自动管理内存的语言，则必须由自己把被删除节点的内存手动释放。

* **remove**
    * 与 `insert` 同一套路：`previous` 靠 `findNode(index - 1)` 拿，`removed` 就是 `previous.next`。
    * 核心动作是 `previous.next = removed.next`，让前驱越过被删节点直接接上后继。
    * 被摘下来的 `removed` 同样不用管，GC 会收走。

    ```java
    public void remove(int index) {
        // 索引为零交给 removeFirst
        if (index == 0) {
            removeFirst();
            return;
        }

        Node previous = findNode(index - 1);
        if (previous == null) {
            throw illegalIndex(index);
        }

        // 被删除的节点在删除前就是 previous.next
        Node removed = previous.next;
        if (removed == null) {
            throw illegalIndex(index);
        }

        previous.next = removed.next;
    }
    ```

### 三种必查情况与越界异常

* **index 等于零**
    * `0 - 1 = -1`，`findNode` 在这里是废的，`previous` 必然为 `null`。
    * 但索引零是能删的，所以提前拦下来直接走 `removeFirst`，下面所有逻辑一概不执行。

* **index 大于零但 previous 没找到**
    * 说明索引越界，抛异常。

* **previous 找到了但 removed 是 `null`**
    * 链表 `1 2 3 4` 的有效索引是 `0` 到 `3`，删索引 `4` 时 `4 - 1 = 3` 能取到 `previous`，但索引 `4` 的节点根本不存在，`previous.next` 是 `null`。
    * 这一刻必须报错，绝不能让删除继续往下走，否则下一步 `previous.next = removed.next` 就是空指针。

    | 操作 | 结果 | 说明 |
    | :--- | :--- | :--- |
    | `remove(2)` | `1 2 4` | 正常删除中间的 `3` |
    | `remove(0)` | `2 3 4` | 特例，内部转调 `removeFirst` |
    | `remove(5)` | 抛异常 | 越界，previous 找不到 |
    | `remove(4)` | 抛异常 | previous 找得到，但节点本身不存在 |

* **illegalIndex**
    * 一长串异常对象写在代码里很别扭，用 `Extract Method` 把它抽成 `illegalIndex` 方法，语义是"返回一个不合法的索引异常"。
    * 抽完之后 `insert` 与 `remove` 里都只剩一句 `throw illegalIndex(index)`。
    * 这个异常与 `get` 找不到时抛的是同一个，直接复用。

## 哨兵节点：让链表永不为空

### 哨兵的动机

* **麻烦在哪**
    * 代码里很多地方都要处理"链表为空"与"链表非空"两种情况，`addLast` 尤其要为两种情况写两套完全不同的逻辑。
    * `insert` 与 `remove` 都依赖 `findNode` 找上一个节点，但索引为零时上一个是 `-1`，`findNode(-1)` 必然返回 `null`，只能靠特判兜。

* **哨兵节点**
    * > **定义**：一个不存业务数据的特殊节点；即使链表里没有自己的节点，它也一定存在。
    * `head` 从指向 `null` 改为指向哨兵；哨兵的 `value` 取什么无所谓（示例用 `666`），真正重要的是它的 `next`。
    * 判断链表时不再需要做"空链表"判断——链表里肯定有一个节点，这个节点就是哨兵。
    * 找上一个节点这个动作也跟着简化，省下来的代码很可观。

    ```text
    没有哨兵：
        head = null          <-- 空链表，只能靠 head == null 判空

    有哨兵：
        head ──▶ [sentinel:666] ──▶ null
                  |
                  +-- value 无所谓，它不存数据；真正重要的是它的 next
    ```

    ```java
    private Node head = new Node(666);   // 666 只是占位，哨兵不存业务数据
    // 哨兵的 next 初始就是 null
    ```

### 加哨兵后的连锁改动

* **addLast 与 findLast**
    * 加了哨兵之后 `findLast` 返回的不再可能是 `null`：没有其他节点时，最后一个节点就是哨兵。
    * `addLast` 里的 `if (last == null)` 失去意义，整个判断可以去掉。
    * `findLast` 里的 `head == null` 同样永远不会成立，`head` 总是指向哨兵，可以直接删掉。

    ```java
    public void addLast(int value) {
        Node last = findLast();     // 最差也会返回哨兵，不会是 null
        Node node = new Node(value);
        last.next = node;
    }

    private Node findLast() {
        Node p = head;              // p 一开始就是哨兵
        while (p.next != null) {
            p = p.next;
        }
        return p;                   // 空链表时返回的就是哨兵
    }
    ```

* **遍历起点必须改**
    * 改完立刻翻车：`addLast` 加好 `1 2 3 4` 后，断言期望第一个元素是 `1`，实际遍历出来的是 `666`。
    * 原因是遍历代码没改，`head` 现在就是哨兵，等于从哨兵开始遍历了。
    * 起点必须改成 `head.next`——哨兵的 `next` 才是真正的第一个元素，哨兵自身的 `666` 不该被遍历。

    ```text
    head ──────────▶ [sentinel:666] ──▶ [1] ──▶ [2] ──▶ null
                        |
    head.next ───────────┘

    遍历起点必须落在这一格，而不是 sentinel 自己
    ```

* **findNode 起点同步后移**
    * `findNode` 同样只需把起点从 `head` 改成 `head.next`，其他逻辑不动。
    * 这一改动会连带生效：`get`、`insert`、`remove` 都调用了 `findNode`。
    * 这一轮改动落在三点：`addLast` 去掉判空、`findLast` 与 `findNode` 起点后移一格、所有遍历从 `head.next` 起步。

* > **易错点**：加哨兵后 `get` 里的判空不能省。`findNode` 返回 `null` 已经不是"链表为空"，它专指"索引越界"——有了哨兵，空链表也返回哨兵而不是 `null`，那个判断的语义变了，不能简化掉。

### 特判的删除：addFirst 与 removeFirst

* **insert 特判被哨兵救回**
    * 索引 0 的前面什么都没有，没有 `previous`，所以无哨兵时必须特判。
    * 有哨兵时，索引 0 的上一个节点就是哨兵，而哨兵的 `next` 正好指向索引 0 的元素。
    * 插入那两行逻辑一个字都不用改，只是 `previous` 的取值范围变宽了。

    ```text
    没有哨兵时：
        head ──▶ [1] ──▶ [2] ──▶ [3] ──▶ null
         索引0     索引1     索引2
        往索引 0 插入 → 找不到 previous → 必须特判

    有哨兵时：
        head（哨兵）──▶ [1] ──▶ [2] ──▶ [3] ──▶ null
         索引0     索引1     索引2
        往索引 0 插入 → previous 就是 head → 特判消失
    ```

* **findNode 的起点要改成 -1**
    * 哨兵的索引天然就是 `-1`（`0 - 1`），它不是凭空多出来、不参与索引体系的节点。
    * `findNode` 原来从 0 开始、起点是 `head.next`，完全没考虑哨兵，于是往索引 0 插入时会抛 `index 0 不合法`。
    * 把起点改成 `head`、索引从 `-1` 开始，第一个 `-1` 就正好对上哨兵，返回的就是哨兵。

    | 场景 | 操作 | 期望结果 | 说明 |
    | :--- | :--- | :--- | :--- |
    | 头部插入 | 往索引 0 插入 5 | `5 1 2 3 4` | `previous` 是哨兵 |
    | 中间插入 | 往索引 2 插入 5 | `1 5 2 3 4` | 常规路径 |
    | 尾部插入 | 往索引 4 插入 5 | `1 2 3 4 5` | 插到末尾 |
    | 非法索引 | 往索引 5 插入 | 抛异常 | 4 个元素最大索引是 4 |

* **addFirst 改为 insert(0, value)**
    * `addFirst(value)` 就是 `insert` 往索引 0 位置加入元素，是它的特例，不再重写一遍。
    * 空链表头插同样不用特殊处理，走 `insert(0, ...)` 即可，结果是列表中只有一个该元素。

* **removeFirst 改为 remove(0)**
    * 加哨兵后 `remove` 在索引 0 也能正常工作（`findNode` 返回的就是哨兵），头部删除的特判可以删掉。
    * `removeFirst` 就是 `remove(0)`，内部直接转调即可。

* **remove 的两种非法**
    * 一种是上一个节点找不到（删索引 5），一种是被删除节点找不到（删索引 4），两种都要抛异常。

    | 场景 | 操作 | 说明 |
    | :--- | :--- | :--- |
    | 中间删除 | 删除索引 2 | 常规路径，`previous` 是索引 1 |
    | 头部删除 | 删除索引 0 | `previous` 是哨兵，验证特判确实可以删掉了 |
    | 非法（一） | 删除索引 5 | 导致上一个节点找不到，应抛异常 |
    | 非法（二） | 删除索引 4 | 导致被删除节点找不到，应抛异常 |

* > **提示**：凡是能表达成"某个通用方法的一个特例"的操作，都不要重写一遍——`addFirst` 与 `removeFirst` 分别就是 `insert(0, value)` 与 `remove(0)`。

## 双向链表

### 节点类与两个哨兵

* **节点类**
    * 双向链表（Doubly Linked List）的节点有两个指针：`previous` 指向上一个节点，`next` 指向下一个节点。
    * 字段顺序刻意把 `previous` 放上面、`next` 放下面，中间夹 `value`，为的是将来复制方便。
    * 有参构造一次同时指定 `previous`、值与 `next`。

    ```text
    单向链表的节点:        双向链表的节点:
       +-----------+         +-----------+
       |    next   |         | previous  |
       +-----------+         +-----------+
       |   value   |         |   value   |
       +-----------+         +-----------+
                             |    next   |
                             +-----------+
    ```

    ```java
    public class Node {
        // 上一个节点指针
        Node previous;
        // 节点值
        int value;
        // 下一个节点指针
        Node next;

        public Node(Node previous, int value, Node next) {
            this.previous = previous;
            this.value = value;
            this.next = next;
        }
    }
    ```

* **两个哨兵互相指着**
    * 链表类里放两个哨兵成员变量：`head` 在头，`tail` 在尾。
    * 链表刚创建时两个哨兵就有值了，头哨兵用 `666`，尾哨兵用 `888` 稍作区分。
    * `head.next = tail` 且 `tail.previous = head`，空表时尾哨兵的 `previous` 指向的正是头哨兵。

    ```java
    head = new Node(null, 666, null);   // 头哨兵：previous 不需要指向东西，值无所谓给 666，next 先给 null
    tail = new Node(null, 888, null);   // 尾哨兵：跟它差不多，值随便给一个 888 稍微区分一下
    head.next = tail;                   // 让头的 next 指向尾
    tail.previous = head;               // 让尾的 previous 指向头
    ```

### findNode：起点 -1，终点尾哨兵

* **遍历条件变了**
    * 存储数据的节点索引从 `0` 开始；把头哨兵算上的话，头哨兵对应索引 `-1`。
    * 有时需要把头哨兵本身找出来，所以索引从 `-1` 开始循环，指针初值为 `head`。
    * 循环条件不再是 `pointer != null`，而是 `pointer != tail`——尾哨兵本身不存数据，它代表整条链表的结束。
    * 出了有效范围仍没命中就返回 `null`，说明 `index` 不合法。

    ```java
    private Node findNode(int index) {
        Node pointer = head;          // 起点是头哨兵，对应索引 -1
        int i = -1;                   // 索引从 -1 开始
        while (pointer != tail) {     // 尾哨兵就是链表结束标志
            if (i == index) {
                return pointer;
            }
            pointer = pointer.next;
            i++;
        }
        return null;                  // 出了有效范围，说明 index 不合法
    }
    ```

* **两个哨兵的分工**
    * 头哨兵索引 `-1`，尾哨兵是循环的终止条件，二者都不计入业务元素的索引区间。
    * `findNode` 会被 `insert`、`remove`、`addFirst`、`removeFirst` 共同复用。

### insert：一次改四个指针

* **四步赋值**
    * 第一步 `previous = findNode(index - 1)` 找到上一个节点。
    * 第二步 `next = previous.next`，有了 `previous` 就直接得到下一个节点。
    * 第三步 `new Node(previous, value, next)` 建新节点，它的 `previous` 与 `next` 一次到位。
    * 第四步补上 `previous.next = inserted` 与 `next.previous = inserted`；整个过程一共有四个指针需要改变。

    ```java
    // 先找到新节点的上一个节点，也就是 index - 1 位置的节点
    Node previous = findNode(index - 1);
    // 找到了 previous 之后，previous 这个时候它的 next 就是它的下一节点
    Node next = previous.next;

    // 创建新节点：previous 指针、值来自方法参数、next 指针
    Node inserted = new Node(previous, value, next);

    // 剩下两个指针
    previous.next = inserted;
    next.previous = inserted;
    ```

* **两个边界都能工作**
    * 往索引 3（链表 `1 2 3` 的末尾）插入时，上一个节点是索引 2 的 `2`，下一个节点因为有尾哨兵而一定找得到且非空。
    * 往索引 0 插入时，上一个节点就是头哨兵，下一个是原来的索引 0 元素，同样正常。
    * `index` 不合法时 `previous` 为 `null`，直接抛非法的参数异常，这个异常跟单向链表里写的同一个，直接复用。
    * 正因为索引 0 也能正常工作，`addFirst` 内部直接调用 `insert(0, value)` 即可，不用重写。

* > **提示**：在有效的索引范围内，找到的这个 `next` 肯定非空，不用担心它是个 `null` 再去调用方法触发空指针。

### remove：两种非法情况

* **三个节点与两行改写**
    * 先 `previous = findNode(index - 1)`，再 `removed = previous.next`，再 `next = removed.next`，三个节点就齐了。
    * 改写只有两行：`previous.next = next` 与 `next.previous = previous`。
    * 两个指针都不再指向 `removed`，它就没有任何人引用了，相当于从列表中断开。

    ```java
    Node previous = findNode(index - 1);   // 上一个
    Node removed  = previous.next;         // 被删除的
    Node next     = removed.next;          // 下一个

    previous.next = next;
    next.previous = previous;
    ```

* **两种非法**
    * 第一种：`previous` 为 `null`。`findNode` 的有效范围是从 `-1` 一直到最后一个节点，出了这个范围返回 `null`，此时抛 `IllegalArgumentException`。
    * 第二种：`removed` 是尾哨兵。如果 `previous` 恰好找到的是最后一个元素，那被删除节点就是尾哨兵，哨兵不能被删，同样抛异常。
    * 索引 0 由同一套逻辑处理，所以 `removeFirst` 直接改成 `remove(0)` 即可。

### 双向链表的优势：尾节点已知

* **单向链表的短板**
    * 单向链表不记录最后一个节点是谁，必须从头一个一个找，直到某个节点的 `next` 等于 `null`。
    * 现在还要维护 `next` 和 `previous` 两个指针，双向链表在普通操作上并不比单向链表省事。

* **尾节点已知带来的好处**
    * 尾哨兵的 `previous` 直接指向最后一个节点，尾节点是已知的，不用从头查找。
    * 正因如此，`addLast` 与 `removeLast` 成为双向链表操作最快、也最特色的两个方法。

* **addLast**
    * `last = tail.previous` 直接拿到最后一个节点，这回不用从头找。
    * 新节点 `added` 的 `previous` 指向 `last`、值来自参数、`next` 指向 `tail`。
    * 再补两行：`last.next = added` 与 `tail.previous = added`。

    ```java
    // 直接通过尾哨兵拿到最后一个节点，这回不用从头找
    Node last = tail.previous;

    // 新节点：previous 指向 last，值来自参数，next 指向 tail
    Node added = new Node(last, value, tail);

    // 剩下两个指针
    last.next = added;
    tail.previous = added;
    ```

* **removeLast**
    * `removed = tail.previous` 是被删除的最后一个节点，上一个节点就是 `removed.previous`。
    * 让上一个节点的 `next` 指向尾哨兵，再让尾哨兵的 `previous` 指回上一个节点。
    * 最后一个节点谁都不指向它了，相当于被删除。

    ```text
    removeLast（当前是 1 2 3）

        previous(2)     removed(3)     尾哨兵
             |              |              |
             v              v              v
        +---------+    +---------+    +---------+
        |    2    | -> |    3    | -> |  tail   |
        +---------+    +---------+    +---------+
             ^                              ^
             |                              |
    previous.next = tail        tail.previous = previous

    现在最后一个节点谁都不指向他了，就相当于从列表中被删除了
    ```

    * > **易错点**：如果通过 `tail.previous` 取到的被删除节点就是头哨兵，说明链表已经删空了，不能再删，必须抛出异常告诉他删除索引不正确。

### 迭代器

* **起点与终点**
    * 遍历起始位置是 `head.next`，头哨兵本身不需要遍历。
    * `hasNext` 返回 `pointer != tail`，走到尾哨兵就表示遍历应该结束了。
    * `next` 先把当前值记录下来，再让 `pointer` 前移，最后返回该值。

    ```java
    public boolean hasNext() {
        return pointer != tail;     // 走到尾哨兵就停
    }

    public int next() {
        int value = pointer.value;  // 先记下当前值
        pointer = pointer.next;     // 再前移
        return value;
    }
    ```

* > **注意**：实际写代码应当写一个测一个；把所有方法都写完再去统一测试，容易攒出一堆问题。

## 双向环形链表

### 环形结构与自环哨兵

* **环形链表**
    * 非环形链表以 `null` 结尾，指针指向 `null` 就表示遍历结束。
    * 环形链表让最后一个节点不指向 `null`，而是回头再指向头，首尾相连形成一个环。
    * 遍历时必须先用指针 `head` 记下头的位置；某个节点的 `next` 等于 `head` 就表示走过一圈、该退出循环。

    ```text
    非环形链表：
      head ──▶ [节点1] ──next──▶ [节点2] ──next──▶ [节点3] ──next──▶ null

    环形链表（最后一个节点的 next 回头指向头）：
          ┌──────────────────────────────────┐
          │                                  │
          ▼                                  │
        [节点1] ──next──▶ [节点2] ──next──▶ [节点3]
          ▲
          │  head 指针记录的节点
    ```

    * > **注意**：图上分开画的两个"节点1"其实是同一个节点对象，只是为了画图方便才拆开；真实结构里节点三的 `next` 直接指回节点一。

* **哨兵身兼首尾两职**
    * 只有 `next` 指针的是单向环形链表，既有 `next` 又有 `previous` 的是双向环形链表。
    * 带哨兵的双向环形链表里，哨兵既作为头也作为尾：不加哨兵的 `null` 结尾换成哨兵自己。
    * 作为头时：`sentinel.next` 指向第一个节点，第一个节点的 `previous` 指向哨兵。
    * 作为尾时：最后一个节点的 `next` 指向哨兵，哨兵的 `previous` 指向最后一个节点。
    * 两个身份落在同一对指针上，所以无论链表是空、只有一个还是有十个，`addFirst` 与 `addLast` 的写法能对称起来。

    ```text
    空链表：哨兵自环
              ┌───────────────────────────┐
              │                           │
              ▼                           │
             sentinel.previous ──┐   sentinel.next ──┐
              ▲                 │      ▲            │
              └─────────────────┘      └────────────┘

    有两个节点时：
        sentinel ──next──▶ [节点1] ──next──▶ [节点2] ──next──▶ sentinel
            ▲                                                     │
            └──────────────────── previous ───────────────────────┘
    ```

### 哨兵的初始化

* **自环的初始状态**
    * 链表刚创建、没有其他节点时，哨兵自己指向自己：`next` 指向自己，`previous` 也指向自己。
    * 节点类仍是 `previous`、`value`、`next` 三个属性加一个有参构造，用静态内部类 `static class Node`。

    ```java
    public class LinkedList implements Iterable<Integer> {

        // 节点类：值 + 前驱 + 后继，还是那三个属性
        static class Node {
            int value;
            Node previous;
            Node next;

            public Node() {
            }

            public Node(Node previous, int value, Node next) {
                this.previous = previous;
                this.value = value;
                this.next = next;
            }
        }

        // 哨兵对象：在链表构造之前就已经创建好了
        private final Node sentinel = new Node();

        public LinkedList() {
            // 这两行必须等到哨兵对象创建完成之后才能写
            sentinel.previous = sentinel;   // 指回自己
            sentinel.next = sentinel;       // 指回自己
        }
    }
    ```

* > **易错点**：`sentinel.previous = sentinel;` 一定要写在构造方法里，不能写在字段声明那一行上。字段声明执行的那一刻 `sentinel` 这个对象自己还没有被创建出来，连"指回自己"的那个"自己"都还不存在。

### addFirst 与 addLast

* **头插 addFirst**
    * 前驱 `a` 是固定的，就是哨兵；后继 `b` 是 `sentinel.next`，也就是原链表的第一个节点。
    * 新节点 `previous` 指 `a`、值来自参数、`next` 指 `b`，再补 `a.next = node` 与 `b.previous = node`。
    * 双向链表每次插入都必须考虑四个指针，少一个就接不上。

    ```java
    // 头插：把新节点作为整个链表的第一个节点
    public void addFirst(int value) {
        Node a = sentinel;                   // 前驱 a：固定的，就是哨兵
        Node b = sentinel.next;              // 后继 b：原来链表的第一个节点
        Node node = new Node(a, value, b);   // 新节点：previous 指 a，next 指 b

        a.next = node;                       // 前驱的后继 → 新节点
        b.previous = node;                   // 后继的前驱 → 新节点
    }
    ```

* **空链表也能正确工作**
    * 只有哨兵时，`a` 是哨兵，而 `b = sentinel.next` 仍然指向哨兵，所以 `a` 和 `b` 都代表 `sentinel`。
    * 这时哨兵既是头也是尾，新节点 `previous` 指向头、`next` 指向尾，正好成为第一个节点。
    * 后面两行让头的 `next` 与尾的 `previous` 都指向新节点，四个指针一个没漏，代码不需要任何改动。

* **尾插 addLast**
    * 后继 `b` 就是哨兵，哨兵永远可以作为尾巴；前驱 `a = b.previous`，也就是原链表的最后一个节点。
    * 之后的三行赋值与头插完全一致。

    ```java
    // 尾插：把新节点追加到链表的最后
    public void addLast(int value) {
        Node b = sentinel;                   // 后继 b：哨兵永远是尾巴
        Node a = b.previous;                 // 前驱 a：原链表的最后一个节点
        Node node = new Node(a, value, b);

        a.next = node;                       // 前驱的后继 → 新节点
        b.previous = node;                   // 后继的前驱 → 新节点
    }
    ```

* **顺序验证**
    * 空链表依次头插 `1 2 3 4 5`，结果为 `5 4 3 2 1`。
    * 空链表依次尾插 `1 2 3 4 5`，结果为 `1 2 3 4 5`。

### removeFirst 与 removeLast

* **删除的统一套路**
    * 删除是插入的镜像：插入把 `a`、`b` 都改指向新节点，删除把 `a`、`b` 都改指向对方，中间那个节点就被跳过了。
    * 具体就是 `a.next = b` 与 `b.previous = a` 两行。

* **removeFirst**
    * 待删除节点 `remove = sentinel.next`，就是哨兵后面的第一个节点。
    * 前驱 `a` 是哨兵，后继 `b = remove.next`。
    * 必须判 `remove == sentinel`：这说明链表为空，哨兵不能删，抛异常。

    ```java
    // 删除第一个节点
    public void removeFirst() {
        Node remove = sentinel.next;         // 第一个节点：哨兵的 next
        if (remove == sentinel) {
            throw new RuntimeException("非法：链表为空，哨兵不能删");
        }
        Node a = sentinel;                   // 前驱
        Node b = remove.next;                // 后继

        a.next = b;                          // 前驱和后继互相跳过 remove
        b.previous = a;
    }
    ```

* **removeLast**
    * 待删除节点 `remove = sentinel.previous`，就是哨兵前面的最后一个节点。
    * 前驱 `a = remove.previous`，后继 `b` 是哨兵。
    * 判空与 `removeFirst` 完全相同，可直接照搬那段判断。

    ```java
    // 删除最后一个节点
    public void removeLast() {
        Node remove = sentinel.previous;      // 最后一个节点：哨兵的 previous
        if (remove == sentinel) {
            throw new RuntimeException("非法：链表为空，哨兵不能删");
        }
        Node a = remove.previous;             // 前驱
        Node b = sentinel;                    // 后继：哨兵永远是尾巴

        a.next = b;
        b.previous = a;
    }
    ```

* **删空的两种表现**
    * `1 2 3 4 5` 连续删头节点：`2 3 4 5` → `3 4 5` → `4 5` → `5` → 空 → 抛异常。
    * `1 2 3 4 5` 连续删尾节点：`1 2 3 4` → `1 2 3` → `1 2` → `1` → 空 → 抛异常。
    * 最后一次之所以抛异常，是因为这时链表中就剩一个哨兵，再删就把哨兵自己杀了。

### 按值删除与 findByValue

* **findByValue**
    * > **定义**：返回第一个 `value` 等于给定值的节点；转完一圈仍没找到返回 `null`。
    * 哨兵不参与比较，指针从 `sentinel.next` 开始。
    * 循环条件是 `p != sentinel`，又回到哨兵就说明转完一圈了。
    * 每个节点用 `p.value` 与目标值比较，相等就返回该节点。

    ```java
    // 按值查找节点：找到返回该节点，转完一圈还没找到返回 null
    public Node findByValue(int value) {
        Node p = sentinel.next;               // 哨兵不参与比较，从它的 next 开始
        while (p != sentinel) {               // 又回到哨兵，说明转完一圈了
            if (p.value == value) {
                return p;
            }
            p = p.next;
        }
        return null;
    }

    // 按值删除节点
    public void remove(int value) {
        Node remove = findByValue(value);
        if (remove == null) {
            // 没找到，那肯定就不用删了；抛个异常或者直接返回都行
            return;
        }
        Node a = remove.previous;             // 前驱
        Node b = remove.next;                 // 后继

        a.next = b;                           // 把 remove 从中间跳过
        b.previous = a;
    }
    ```

* > **提示**：`findByValue` 的循环条件是 `p != sentinel`，所以它永远不可能返回哨兵，这正是按值删除不必再单独判断"删的是不是哨兵"的原因；而 `removeFirst` 与 `removeLast` 是直接把 `sentinel.next` 与 `sentinel.previous` 当作删除目标，空表时这两个取到的就是哨兵自己，所以那两个方法必须自己加判空抛异常。

* **按值删除的流程**
    * 从哨兵的后一个节点开始遍历，逐个比较目标值，找到后再取它的 `previous` 与 `next` 作为 `a`、`b`。
    * 让 `a.next = b`、`b.previous = a`，中间那个 `remove` 就被跳过去了。
    * `1 2 3 4 5` 依次删 `1、2、3……`，结果为 `2 3 4 5` → `3 4 5` → ……

### 迭代器：回到哨兵即结束

* **遍历起点**
    * 链表类实现 `Iterable`，用匿名内部类写 `iterator()`，遍历指针 `p` 作为该内部类的一个属性。
    * `p` 的初始值是 `sentinel.next`，哨兵本身不用遍历。

* **终止条件与取下一个**
    * `hasNext` 返回 `p != sentinel`；回到哨兵就表示转满一圈、没有下一个了。
    * `next` 先把 `p.value` 记录下来，再让 `p = p.next`，最后返回该值。

    ```java
    @Override
    public Iterator<Integer> iterator() {
        return new Iterator<Integer>() {
            // 遍历指针：从哨兵出发，哨兵本身不参与遍历
            private Node p = sentinel.next;

            @Override
            public boolean hasNext() {
                // 回到哨兵 = 转满一圈 = 没有下一个了
                return p != sentinel;
            }

            @Override
            public int next() {
                int value = p.value;   // 先把当前节点的值记录下来
                p = p.next;            // 指针再向后走一位
                return value;
            }
        };
    }
    ```

## 递归遍历

### 递归函数

* **入口与递归体**
    * 入口 `loop()` 只负责指明从哪个节点开始定位，把 `head` 传给递归函数。
    * 递归函数 `recursion(Node current)` 表示"针对某一个节点要执行的操作"——处理第一个节点和处理第二个节点的操作是一样的。
    * 打印完当前节点后，把 `current.next` 交给 `recursion` 自己继续处理，就形成了自己调用自己。
    * 递归必须有终点：`current == null` 时直接 `return`，因为链表中的节点个数是有限的。

    ```java
    // 入口：指明从哪个节点开始定位
    public void loop() {
        recursion(head);
    }

    // 递归函数：处理当前节点，然后把下一个节点交给"自己"
    private void recursion(Node current) {
        if (current == null) {       // 没有节点了，递归到此为止
            return;
        }
        System.out.println(current.value);
        recursion(current.next);
    }
    ```

* **适用范围**
    * 递归遍历在带哨兵的单向链表、带哨兵的双向链表里都是同构的：当前节点的"下一个"照旧交给同一个函数。
    * `while` 版与 `for` 版遍历只是语法不同、本质没有区别，递归遍历则是链表的另一种重要遍历方式。

### before 与 after

* **放在递归调用之前**
    * 输出顺序与链表顺序一致，是正序。

* **放在递归调用之后**
    * 输出顺序与链表顺序恰好相反，是逆序：先从链头一路走到链尾，再回头从链尾往链头输出。

* **成因**
    * 递归是"下去一趟再上来一趟"，走的是来回两趟路；而 `Iterator` 是一次给出一个值，两者机制不同。

* **抽成 Consumer**
    * 把这两行操作抽成两个 `Consumer`（`beforeConsumer` 与 `afterConsumer`）传进来，递归方法也相应加两个参数，IDEA 可以直接生成缺失的参数。
    * 这样操作就不再写死在方法里，由调用方把要做的事通过 `Consumer` 传进来。
    * 这种前、后两段分离的形态与 Spring 的 AOP 前置通知、后置通知很接近。

    ```java
    public void loop(Consumer<Integer> beforeConsumer, Consumer<Integer> afterConsumer) {
        recursion(head, beforeConsumer, afterConsumer);
    }

    private void recursion(Node current,
                           Consumer<Integer> beforeConsumer,
                           Consumer<Integer> afterConsumer) {
        if (current == null) {
            return;
        }
        beforeConsumer.accept(current.value);                  // 递归调用之前执行
        recursion(current.next, beforeConsumer, afterConsumer);
        afterConsumer.accept(current.value);                   // 递归调用之后执行
    }
    ```

### 递归的定义

* **递归（recursion）**
    * > **定义**：一种解决问题的方法，同一个问题也可以用非递归方式解决；递归的解决方案取决于同一类问题的更小实例。
    * 同一类问题：函数在内部调用了自己；若内部调用的是别的函数，解决的就不是同一类问题，那就不叫递归。
    * 每次递归调用处理的数据规模都比上次缩减——链表中从当前节点起变成从当前节点的下一个节点起，规模少了一个节点。
    * 缩减到最后一定无需再递归：节点等于 `null` 表示没有其他节点了，直接 `return`。

* **为什么取决于子集**
    * 外层函数调用内层函数，内层函数不结束，外层函数就不能结束——必须等内层调用结束、返回了，外层代码才能继续向下执行。
    * 所以必须先等子集处理完成，外层函数的调用才能完成：递归必须先把子问题处理了，才能处理外层的主问题。

* > **提示**：递归调用处理的数据，一般都是上一次调用的数据上的子集。

### 递归的执行过程

* **伪代码展开**
    * 假设链表是 `1 → 2 → 3 → null`，用递归前后各打印一次的递归函数走一遍。
    * 每进入一层先判断 `node == null`，不成立就把这个 if 删掉不看，直接打印并递归调用下一层。
    * 只有最内层 `f4(null)` 的判断成立并执行 `return`，它后面的代码都不再执行。

    ```text
    f1(节点1)                    ← 第一次进入，参数是节点 1
        node 不为 null，不进入 return 分支
        打印 node.value  →  1
        递归调用 f2(节点1.next)   ← 节点一的 next 是节点二
            node 不为 null，不进入 return 分支
            打印 node.value  →  2
            递归调用 f3(节点2.next)   ← 节点二的 next 是节点三
                node 不为 null，不进入 return 分支
                打印 node.value  →  3
                递归调用 f4(节点3.next)   ← 节点三的 next 是 null
                    node == null 成立，执行 return
                    递归终点：只有这一层执行 return，后面的代码都不执行
    ```

* **下钻与回退**
    * 下钻阶段依次打印 `1 2 3`，这是正序。
    * 栈底 `return` 之后逐层唤醒，每层回到自己的递归调用之后继续向下执行，又打印 `3 2 1`，这是逆序。
    * 调用栈是栈底 `f1 → f2 → f3 → f4`（栈顶），栈顶最先返回、栈底最后返回，两段拼起来输出 `1 2 3 3 2 1`。

    ```text
       下钻阶段（发调用）              回退阶段（return 之后才继续）
       ───────────────────────────────────────────────────────────▶

       f1(节点1)  打印 1  ──┐
       f2(节点2)  打印 2  ──┤  一路往下钻
       f3(节点3)  打印 3  ──┤
       f4(null)   return   ──┘  栈底返回  ──▶  f3 打印 3
                                                 f2 打印 2
                                                    f1 打印 1

       调用栈：  栈底 f1 → f2 → f3 → f4（栈顶）
                 栈顶最先返回，栈底最后返回

       输出：  1  2  3  3  2  1
    ```

* > **注意**：上面这段是伪代码，不考虑代码语法上的正确性，只看它的执行过程。
