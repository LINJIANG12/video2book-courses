# 二叉树：深度、翻转与遍历结果还原

## 二叉树的最大深度

### 递归解法

* **最大深度（max depth）**

    * > **定义**：二叉树的最大深度是从根节点到最远叶子节点的最长路径上的节点个数。

    * 递推式是 `max(左子树深度, 右子树深度) + 1`，节点为 `null` 时返回 0 作为递归终止条件。

    * 三种解法里效率最高，真正写进生产代码、提交力扣时优先选它。

* **三种解法对照**

    | 解法 | 深度从哪里来 | 讲师评价 |
    | --- | --- | --- |
    | 递归后序遍历 | 递推式 `max(left, right) + 1` | 效率是最高的 |
    | 非递归后序遍历 | 栈的元素个数，取过程中的最大值 | 提供了一种新思路，性能稍逊一筹 |
    | 层序遍历 | 队列 `size()` 逐层推进的轮数 | 一眼就能看出来的思路，性能稍逊一筹 |

    * 后两种解法的价值在于把「非递归遍历二叉树」这件事彻底打通。

### 非递归后序遍历解法

* **栈的最大高度即树的最大深度**

    * > **定义**：后序遍历过程中，栈里元素个数的最大值，就是这棵树的最大深度。

    * 栈里装的永远是「当前正在走、还没走完回溯」的那条根到当前节点的路径，路径有多长，栈就有多深。

    * 示例树里路径 1→2→4 走完时栈是 `[1,2,4]`，深度 3；换一条路径 1→2→5→7 时栈是 `[1,2,5,7]`，深度 4。

    ```text
                1
              /   \
             2     3
            / \     \
           4   5     6
              /
             7
    ```

    * 更新时机只有一处：往栈里 `push` 元素之后，用 `Math.max(max, stack.size())` 刷新 `max`。

* **后序遍历的三个控制变量**

    * `current` 是当前节点，初值 `root`；`pop` 记录最近一次弹栈的元素，初值 `null`；`stack` 用 `LinkedList` 实现。

    * 循环条件是 `current != null` **或** 栈不为空，任一满足就继续。

    * `current` 不为空时只做一件事：压栈并令 `current = current.left`，沿左子树一路向前；`current` 为空进入 `else` 时才考虑是否往回走。

    * > **易错点**：栈顶元素必须等左右子树都处理完成才能弹栈。判定条件是 `top.right == null` 或 `top.right == pop`（栈顶的右孩子正好等于最近一次弹出的元素，说明右子树已走完）；两个条件都不满足才转向 `current = top.right`。

    ```java
    public int maxDepth2(TreeNode root) {
        Deque<TreeNode> stack = new LinkedList<>();
        TreeNode current = root;
        TreeNode pop = null;              // 最近一次弹栈的元素
        int max = 0;

        while (current != null || !stack.isEmpty()) {
            if (current != null) {
                stack.push(current);
                max = Math.max(max, stack.size());   // 唯一需要更新 max 的地方
                current = current.left;
            } else {
                TreeNode top = stack.peek();         // 只看不弹
                if (top.right == null || top.right == pop) {
                    pop = stack.pop();               // 左右子树都处理完了才能弹栈
                } else {
                    current = top.right;             // 右子树还没处理完，转过去
                }
            }
        }
        return max;
    }
    ```

    * > **提示**：这份代码测试用例全部通过，但放到力扣上与递归解法相比效率并不高，它的价值在于提供了一种新思路。

### 层序遍历解法

* **层序遍历的骨架**

    * `Queue<TreeNode> q = new LinkedList<>()`，`offer` 入队、`poll` 出队。

    * `LinkedList` 一身兼三职：双向链表、队列、栈。

    * 先把根节点 `offer` 进队列，`while (!q.isEmpty())` 不断出队并把它的左右孩子入队；队列空了表示所有节点连同其下一层都已处理完。

* **分层与深度**

    * 朴素层序遍历的输出把各层连在一起、没有分界线，等于没算出层数。

    * 手工分层的写法用两个变量：`c1` 记本层元素个数（初值 1），`c2` 在处理本层时累加孩子个数，下一轮令 `c1 = c2`。

    * 队列的 `size()` 能把 `c1`、`c2` 一起干掉：进入本层时队列里正好是本层的全部节点，两者取值序列完全一致（1 → 2 → 3 → 1）。

    * > **易错点**：不要写 `for (int i = 0; i < q.size(); i++)`，那样循环十次就调十次 `size()`；应先把 `size` 取到循环外侧，只调一次方法。

    ```java
    public int maxDepth3(TreeNode root) {
        if (root == null) {
            return 0;                     // 力扣可能传进来一棵空树
        }

        Queue<TreeNode> q = new LinkedList<>();
        q.offer(root);
        int depth = 0;

        while (!q.isEmpty()) {
            int size = q.size();          // 进入本层时，队列里正好是本层的全部节点
            for (int i = 0; i < size; i++) {
                TreeNode node = q.poll();
                if (node.left != null)  q.offer(node.left);
                if (node.right != null) q.offer(node.right);
            }
            depth++;                       // 处理完一层，深度加一
        }
        return depth;
    }
    ```

    * > **易错点**：求最大深度时 `depth++` 放在小循环结束之后，因为层数是数出来的，循环结束之后才知道；这一点跟最小深度踩的坑正好相反。

    * `root == null` 必须单独判断返回 0，空树深度为 0，漏掉这个判断会挂掉一个测试用例。

## 二叉树的最小深度

* **最小深度（min depth）**

    * > **定义**：最小深度是从根节点到最近叶子节点的路径长度。

    * 终止条件与最大深度相同：节点为 `null` 时返回 0。

* **对称写法只差一个判断**

    * 直觉写法 `Math.min(minDepth(root.left), minDepth(root.right)) + 1` 是错的，前三个测试用例能过、第四条挂掉。

    * 反例是「一条腿」的树：根节点 1、左子节点 2、无右子节点，深度应为 2，直觉写法却算出 1。

    ```text
            1
           /
          2
    ```

    * 执行过程：右子树深度返回 0，0 和 1 取最小值得 0，再加本层得 1。

    * > **易错点**：`null` 分支返回的 0 在取最大时毫无影响，因为 0 永远不参与「取大」；但在取最小值时 0 是所有非负数里最小的那个，一旦算进去结果必然塌成 1。求最大深度可以无条件取 max，求最小深度必须先把 `null` 摘出去。

    * 正确写法在两个深度返回后先做判断：`d1 == 0` 返回 `d2 + 1`（左子树为空，以右子树为准），`d2 == 0` 返回 `d1 + 1`（右子树为空，以左子树为准），只有左右都不为 `null` 时才 `Math.min(d1, d2) + 1`。

    ```java
    public int minDepth(TreeNode root) {
        if (root == null) {
            return 0;                     // 递归的终止条件
        }

        int d1 = minDepth(root.left);     // 左子树的深度
        int d2 = minDepth(root.right);    // 右子树的深度

        if (d1 == 0) return d2 + 1;       // 左子树为空，以右子树为准
        if (d2 == 0) return d1 + 1;       // 右子树为空，以左子树为准
        return Math.min(d1, d2) + 1;      // 两边都有，取较小的那个
    }
    ```

* **层序解法：遇到的第一个叶子说了算**

    * > **定义**：用层序遍历求最小深度时，遇到的第一个叶子节点，它所在的那一层就是最小深度。

    * 叶子节点的判定是 `node.left == null && node.right == null`，两个指针都为 `null`。

    * 把示例树里最深的 6 去掉之后，叶子变成 4、3、7；层序第一个碰到的是第 2 层的 3，所以最小深度是 2，离根最远的 7 不可能是答案。

    ```text
                1
              /   \
             2     3
            / \
           4   5
              /
             7

          第 2 层： 3      ← 第一个遇到的叶子 → 最小深度 = 2
          第 3 层： 4
          第 4 层： 7
    ```

    * 找到第一个叶子后直接 return，后续节点不必再层序遍历，方法调用就此结束，因此比递归后序解法效率更高。

    * > **易错点**：`depth++` 必须放在小循环的**前面**。若第一层就是叶子节点，放在后面会来不及加一就返回初始值 0。

    ```java
    public int minDepth2(TreeNode root) {
        if (root == null) {
            return 0;
        }

        Queue<TreeNode> q = new LinkedList<>();
        q.offer(root);
        int depth = 0;

        while (!q.isEmpty()) {
            depth++;                      // 自增要放到本层循环的前面
            int size = q.size();
            for (int i = 0; i < size; i++) {
                TreeNode node = q.poll();

                if (node.left == null && node.right == null) {
                    return depth;         // 遇到的第一个叶子节点，它所在层就是最小深度
                }

                if (node.left != null)  q.offer(node.left);
                if (node.right != null) q.offer(node.right);
            }
        }
        return depth;
    }
    ```

## 翻转二叉树

* **翻转二叉树（invert tree）**

    * > **定义**：把一棵二叉树沿 y 轴做 180 度镜像，等价于每个节点的左右孩子互相交换。

    ```text
           翻转前                            翻转后

              1                                 1
            /   \                             /   \
           2     3        ────►             3     2
          / \                               / \
         4   5                             5   4
            / \                           / \
           7   8                         8   7
    ```

    * 翻转起点是 `root`，但 `root` 本身不变——所有动作都发生在它的左右孩子上，所以翻转完直接返回 `root`。

    * 每个节点交换完还要对左右孩子递归做同样的处理：2 的孩子要翻、5 的孩子也要翻，只翻根节点那一层是不够的。

    * 遇到传进来的节点是 `null` 就结束递归。

    * > **提示**：整个翻转只有一个动作——交换指针。临时变量 `t` 是必需的，一旦先写了 `node.left = node.right`，原来的左孩子就再也找不回来了。

    ```java
    public TreeNode invert(TreeNode root) {
        fn(root);
        return root;              // root 本身不会变，翻转的是它的左右孩子
    }

    private void fn(TreeNode node) {
        if (node == null) {
            return;               // 遇到 null 就停止递归
        }

        TreeNode t = node.left;   // 左孩子先存到临时变量
        node.left = node.right;   // 左孩子位置让给右孩子
        node.right = t;           // 右孩子位置再填回临时变量

        fn(node.left);
        fn(node.right);
    }
    ```

## 表达式树与后缀表达式建树

### 表达式树的形状与前提

* **表达式树（expression tree）**

    * > **定义**：叶子节点都是操作数、非叶子节点都是运算符的二叉树。

    * 表达式树的中序遍历等于中缀表达式，后序遍历等于后缀表达式。

    * 后缀表达式也叫逆波兰表达式（Reverse Polish Notation，RPN）；存一个后缀表达式时，计算机里往往把它转成这种树状结构来存，比存成一串字符串方便。

    * 示例：后缀表达式 `2 1 - 3 *` 写成中缀是 `(2-1)*3`，先拿 2 和 1 做减法，再把结果跟 3 做乘法，最终 `(2-1)*3 = 1*3 = 3`。

    ```text
                *
              /   \
             -     3
            / \
           2   1
    ```

    * `-` 的左孩子是左操作数 2、右孩子是右操作数 1；`(2-1)` 的结果再跟 3 相乘，所以 `*` 的左孩子是 `-`、右孩子是 3。

* **建树的前提**

    * > **前提**：给的后缀表达式必须是合法的，且里面全是双元运算符——每个运算符都接收两个操作数，不支持别的东西；没有这个前提，那套栈走法就无从谈起。

### 用栈建树与反向验收

* **扫描过程**

    * 从左往右遍历表达式，遇到数字就建一个节点入栈。

    * 数字先入栈是因为后缀表达式里运算符一定靠右被扫到，父节点还没出现之前，这两个孩子节点总得先有个地方暂存。

    * 扫到运算符就连弹两个：先弹的是右孩子，后弹的是左孩子，两个组成该运算符的子树，运算符自己再入栈，因为它还没完事，得跟后面的操作数或运算符再去找一个爹。

    * 扫完之后栈里剩下的那个节点，就是整棵树的根。

    | 扫到 | 动作 | 栈（从栈底到栈顶） |
    | --- | --- | --- |
    | `2` | 建一个数字节点入栈 | `2` |
    | `1` | 建一个数字节点入栈 | `2` → `1` |
    | `-` | 连弹两个建父子，`-` 入栈 | `-` |
    | `3` | 建一个数字节点入栈 | `-` → `3` |
    | `*` | 连弹两个建父子，`*` 入栈 | `*` |

* **后序遍历反向验收**

    * > **结论**：对这棵表达式树做一次后序遍历（左右根），得到的结果应该就是原来的后缀表达式；一致说明构造正确，不一致说明有问题。

    * 对着图走一遍：深入最左侧打印 `2`，回到 `-` 的右孩子打印 `1`，然后打印 `-`，正好是 `*` 的左子树打完；接着走右子树，`3` 是叶子直接打印，最后打印根 `*`，写出 `2 1 - 3 *`，与初始表达式一模一样。

    * 这也是后序遍历一个非常重要的应用——二叉树的后序遍历可以很容易地得到一个后缀表达式。

    * 验收写法是：拿一批后缀表达式当用例，调方法拿到根节点，对根节点做一次 postOrder，把遍历到的每个节点值塞进结果集，最后与最初的逆波兰表达式逐项比对。

* **实现要点**

    * 输入是字符串数组，数字与运算符一律用字符串表示，因为它们遍历时长得一模一样。

    * 节点的值要改成 `String` 类型，才能让数字和运算符混着存在同一个 `TreeNode` 里。

    * 栈用 `LinkedList` 实现（它本来就是双端队列，`push`/`pop`/`peek` 现成），栈里放的元素统一是 `TreeNode`。

    * 用 `switch` 分两种情况：`+`、`-`、`*`、`/` 命中就是运算符走一套处理，剩下的交给 `default`，那就是数字，直接压栈。

    * > **易错点**：三处最容易写反——先 `pop` 出来的是 **right**，后 `pop` 的是 **left**；父节点 `parent` 要重新入栈；数字分支里是直接压栈，不建父子关系。三处一错，树的形状就整个歪掉，而后序遍历那个检验会第一时间把它揪出来。

    ```java
    public static TreeNode<String> build(String[] postfix) {
        LinkedList<TreeNode<String>> stack = new LinkedList<>();

        for (String t : postfix) {
            switch (t) {
                case "+": case "-": case "*": case "/":
                    TreeNode<String> right = stack.pop();   // 先弹的是右孩子
                    TreeNode<String> left = stack.pop();    // 后弹的是左孩子
                    TreeNode<String> parent = new TreeNode<>(t);
                    parent.left = left;
                    parent.right = right;
                    stack.push(parent);                      // 还要找爹，重新入栈
                    break;
                default:
                    stack.push(new TreeNode<>(t));          // 数字直接压栈
                    break;
            }
        }

        return stack.peek();                                // 栈里剩下的就是根
    }
    ```

## 由遍历结果还原二叉树

### 前序加中序

* **可还原的依据**

    * > **定义**：前序遍历是根左右，第一个打印出来的值 `preorder[0]` 肯定就是根节点的值。

    * 中序遍历是左根右，打印根之前打出来的那些一定是左子树部分，打印根之后的那些一定是右子树。

    * 光有前序不够，不知道后面这些值哪些属于左子树、哪些属于右子树——完全可以编出一棵左子树是 `2 4 3`、右子树是 `6 7` 的树来，谁能说它不对。

    * 前序拆出来的左段是 `2 4`、右段是 `3 6 7`，中序拆出来的左段是 `4 2`、右段是 `6 3 7`；只看前序那两段定不出 `4` 和 `2` 里谁是根，得同时借中序继续区分。

    * 盯住 `2 4` 与 `4 2` 这两组值看，处理方式跟大问题完全一样：`2` 是根（因为前序先打印根），`4` 在中序里位于 `2` 左边所以是左孩子，`2` 的右边没东西，右子树为空。这就是个子问题，切到没法再切分时递归停。

* **示例与切数组的刀法**

    * 前序 `1 2 4 3 6 7`、中序 `4 2 1 6 3 7`，还原结果是根 1，左孩子 2，右孩子 3；2 的左孩子是 4；3 的左孩子是 6、右孩子是 7。

    ```text
                    1
                  /   \
                 2     3
                /     / \
               4     6   7
    ```

    * 逻辑三条：中序里找根的位置 → 按位置把两边切出来 → 递归；前序的左子树配中序的左子树一组递归，右子树配右子树一组递归，每次调用返回一个根节点挂到当前节点上。

    * > **注意**：`Arrays.copyOfRange` 的 `from` 会被复制进去、`to` 不会被复制，实际复制到的是 `to - 1`，即含头不含尾，传参时要自己加一减一。

    * 中序按根位置 `i` 切：左边是 `[0, i)`，右边是 `(i, length]`。

    * 前序切分要把根排除掉，左子树从索引 **1** 开始拷；`4 2` 和 `2 4` 代表同一棵子树、长度一样，`inLeft` 从 0 拷到 `i`（不含），`preLeft` 就从 1 拷到 `i + 1`，`preRight` 从 `i + 1` 一路到数组末尾。

    * 递归终止条件是 `preorder.length == 0 || inorder.length == 0`；两个数组长度必然相同，那一个是零另一个肯定也是零，只判一个就够。

    * > **易错点**：在中序里定位到根的位置后，循环要立刻 `break`，`i` 已经拿到，再往后遍历 `6 3 7` 那些元素纯属浪费。

    ```java
    public static TreeNode<Integer> buildTree(int[] preorder, int[] inorder) {
        // 递归终止条件：没有节点了
        if (preorder.length == 0 || inorder.length == 0) {
            return null;
        }

        int rootValue = preorder[0];
        TreeNode<Integer> root = new TreeNode<>(rootValue);

        int i = 0;
        for (; i < inorder.length; i++) {
            if (inorder[i] == rootValue) break;      // 定位到了立刻 break
        }

        // 中序切分：[0, i) 是左子树，(i, length] 是右子树
        int[] inLeft  = Arrays.copyOfRange(inorder, 0, i);
        int[] inRight = Arrays.copyOfRange(inorder, i + 1, inorder.length);

        // 前序切分：根不在里面，左子树从 1 开始，长度与 inLeft 对齐
        int[] preLeft  = Arrays.copyOfRange(preorder, 1, i + 1);
        int[] preRight = Arrays.copyOfRange(preorder, i + 1, preorder.length);

        root.left = buildTree(preLeft, inLeft);
        root.right = buildTree(preRight, inRight);
        return root;
    }
    ```

### 中序加后序

* **只换了根的位置**

    * > **定义**：后序遍历是左右根，要把左右子树都打印完成才打印根，所以根节点是后序数组的最后一个元素。

    * 同一棵树：中序仍是 `4 2 1 6 3 7`，后序是 `4 2 6 7 3 1`，末尾的 `1` 就是根；中序里 `1` 左边的 `4 2` 是左子树，右边的 `6 3 7` 是右子树。

    * 只靠中序这一份还是不够的，得结合后序一起判断：后序切出来的 `4 2` 对应左子树，`6 7 3` 对应右子树，切完又是两个子问题递归求解。

    * > **前提**：所有节点的值都不会重复。重复了就麻烦了，比如结构里有两个 `1`，拿着根节点的值去中序里找，根本判断不出是第一个 `1` 还是第二个 `1` 是根；题目已经保证不重复，不用担心比较出错。

    * 与前序加中序那题的唯一区别就是：**后序定位根取的是数组最后一个元素**。

* **切数组的坑**

    * 中序切分跟上一题一模一样：左边 `[0, i)`，右边 `(i, length]`。

    * 后序切分：`postLeft` 是左子树，从 0 到 `i`（`i` 不含）；`postRight` 是右子树，起点是 **`i`**，末尾那个根元素不要，到 `length - 1` 为止。

    * 右子树要包含下标 `i`，是因为在中序里 `i` 是根的位置；在后序里根跑到了最末尾，同一个下标位置上装的已经是右子树的最后一个元素了。这两个数组的下标一一对应，只是根被搬到了后面。

    * > **易错点**：`inorder` 和 `postorder` 长度一样，拷贝范围用谁的 `length` 都一样、写哪个都行；但 `postRight` 的起点是 `i` 而不是 `i + 1`，终点是 `length - 1` 而不是 `length`，这两处必须比中序那两行多退一格、少进一格。

    ```java
    public static TreeNode<Integer> buildTree(int[] inorder, int[] postorder) {
        if (inorder.length == 0 || postorder.length == 0) {
            return null;
        }

        // 区别就在这：后序的最后一个元素才是根节点
        int rootValue = postorder[postorder.length - 1];
        TreeNode<Integer> root = new TreeNode<>(rootValue);

        int i = 0;
        for (; i < inorder.length; i++) {
            if (inorder[i] == rootValue) break;
        }

        int[] inLeft    = Arrays.copyOfRange(inorder, 0, i);
        int[] inRight   = Arrays.copyOfRange(inorder, i + 1, inorder.length);
        int[] postLeft  = Arrays.copyOfRange(postorder, 0, i);
        int[] postRight = Arrays.copyOfRange(postorder, i, postorder.length - 1);

        root.left = buildTree(inLeft, postLeft);
        root.right = buildTree(inRight, postRight);
        return root;
    }
    ```

### 效率账与优化方向

* **两处开销**

    * 每次进入递归都要到中序结果里线性地找一遍根的位置，每层都线性扫，叠加起来开销就上来了。

    * 每次切分左右子树都用 `copyOfRange` 创建了新数组，创建与拷贝的开销全浪费在这上面。

    * 未优化的中序加后序版本执行耗时 6ms，只击败了 13.9% 的用户，效率明显不理想。

* **两条优化路径**

    * 把所有节点（每个子树的根）在中序里的位置一次性记录下来以加速查找，最方便的数据结构是 `HashMap`。

    * 改成往下传索引位置（下标边界），在原始数组的范围里查找，不创建新数组，把创建数组和拷贝的开销全省掉。

    * 两处都做之后，整个程序性能能到 99% 左右，超过 99% 的提交者；`HashMap` 属于后续内容，这两处优化先搁置。

## 二叉搜索树

### 引入理由与两条硬规矩

* **为什么要引入它**

    * 数组、链表、队列里查找一个元素都是线性时间 $O(n)$。

    * 二分查找的查询效率可以达到对数时间 $O(\log n)$，但前提是针对一个**已排序的数组**，而给数组元素排序的成本本来就比较高，先排个序再去查找有些得不偿失。

    * 二叉搜索树是折中办法：换一种数据结构，既让查询效率比较高，新元素加进来时结构本身就已经是排好序的，不用再额外排序。

* **两条硬规矩**

    * > **定义**：二叉搜索树（binary search tree，BST）也叫二叉排序树，第一个特征是节点在 `value`、左孩子、右孩子之外再加一个 `key` 属性，`key` 用来比较节点谁大谁小，且 `key` 在整棵树里取值唯一、不能重复。

    * 第二个特征是对于树中的任意一个节点，它的 `key` 比它左子树所有节点的 `key` 都大，比它右子树所有节点的 `key` 都小。

    ```text
                        4
                      /   \
                    2      7
                   / \    / \
                  1   3  5   8
                         /
                        6
    ```

    * 逐节点验证：4 的左子树是 1、2、3 都比它小，右子树的 5、6、7、8 都比它大；2 的左边 1 比它小、右边 3 比它大；7 的左边 5、6 比它小、右边 8 比它大；6 的左边 5 比它小。

    * 约束会向上传递：给 6 加右孩子时，它既要大于 6，又必须小于 7——因为 6 的右孩子同时也属于 7 的左子树，所以 `6.5` 合法；`6`、`6.5` 都得比 7 小。

### 查找性能与最坏情况

* **查找过程**

    * 找 8 时不需要跟每个节点都比较一次：从根 4 开始比，发现 8 比 4 大就去右边找，因为右边这些值都比 4 大、左边 1、2、3 肯定也比 8 小，左边完全不用比较。

    * 继续向右走到 7，比完 8 还是大就继续到 7 的右边，7 左边那些 5 和 6 又都不用比较了，又少了一半比较次数；沿 7 向右走，当前节点值与待查值相等即命中。

    * 一共比较三次：4、7、命中；整棵树有 8 个元素。

    * > **结论**：查找性能基本上跟树高相关，以后讲的插入、删除也都是跟树高相关；树长得平衡时时间复杂度可以达到对数级，就是 $O(\log n)$。

    * 这形态上自然而然就是一个二分查找。

* **退化成一条直线**

    ```text
            5
           /
          4
         /
        3
       /
      2
     /
    1
    ```

    * 这也是一棵二叉搜索树，也符合定义：5 的左边 4 比它小，4 的左边 3 比它小，依此类推；但左右高度相差比较大，它不平衡。

    * 这种情况查找性能就没那么高，查 1 得比较 1、2、3、4、5 五次才能找到，时间复杂度又回到线性时间 $O(n)$。

    * 二叉搜索树的平均时间复杂度是对数时间，最坏情况会退化成 $O(n)$。
