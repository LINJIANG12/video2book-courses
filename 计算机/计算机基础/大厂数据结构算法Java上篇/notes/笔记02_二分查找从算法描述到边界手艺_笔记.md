# 二分查找：从算法描述到边界手艺

## 问题定义与前提

   * **二分查找（binary search）**

       * > **定义**：在一个内含 $N$ 个元素的升序数组中查找目标值，找到返回它的索引位置，找不到返回 `-1`。

       * 输入对应方法的参数：待查找的升序数组 `a` 与目标值 `target`。

       * 输出对应方法的返回值：命中返回索引，未命中返回 `-1`。

       * > **易错点**：找不到返回 `-1` 是为了把成功与失败区分开——成功返回的位置必然大于等于 0，返回一个负数才表示没有成功。

       * 同一个算法可以对应一个或多个方法，基础版实现命名为 `binarySearchBasic`。

   * **升序且允许重复**

       * > **定义**：数组元素保证 $a[0] \le a[1] \le a[2] \le \cdots \le a[N-1]$，由小到大排列，称之为升序排列。

       * 前提条件写的是「小于等于」而不是「小于」，所以数组内允许两个元素相等、允许出现重复元素。

       * 重复元素二分查找也能处理，但需要专门的版本才能稳定返回最左或最右的那一个。

       * `target` 每次查找都可以更换，同一个数组可以分别去查不同的值，把命中与未命中两种结果都走一遍。

   * **六步流程**

       * 设置两个指针 `i`、`j`。

       * 判断范围内是否还有元素。

       * 取中间值。

       * 目标小于中间值：走左半区。

       * 目标大于中间值：走右半区。

       * 目标等于中间值：找到，直接返回。

## 双指针与搜索范围

   * **`i` 与 `j` 的初始化**

       * `i` 一开始指向索引 0，`j` 一开始指向索引 $N-1$。

       * 两个指针像两只手一样从数组两头往中间夹，把当前还可能有答案的那一段夹在中间；左边是 `i`，右边是 `j`。

       * 初始范围涵盖整个数组，随着算法推进 `i` 向右移、`j` 向左移，范围越来越小。

```text
      +----+----+----+----+----+----+----+----+
下标  |  0 |  1 |  2 |  3 |  4 |  5 |  6 |  7 |
      +----+----+----+----+----+----+----+----+
      | A0 | A1 | A2 | 30 | A4 | A5 | A6 | A7 |
      +----+----+----+----+----+----+----+----+
         ^                                  ^
         i                              j = N - 1
```

   * **终止条件 `i <= j`**

       * > **定义**：`i` 大于 `j` 表示这个范围内没东西了，查找结束返回 `-1`；`i` 小于等于 `j` 表示范围内还有东西，就得继续往下找。

       * 缩小范围的过程中若找到元素则算法结束，没找到则范围继续缩小。

   * **最后的机会不能丢**

       * > **易错点**：`i` 与 `j` 相等时不能提前收工。范围里还剩一个元素没比较过，直接返回 `-1` 就等于把这个元素漏掉了。

       * 这一轮仍然要走取中间值和比较三步，因为这个时候还有最后一次查找机会，还不确定当前元素是不是要找的结果。

   * **`while (i <= j)` 与 `while (i < j)`**

       * 把条件改成 `i < j` 后，查找下标 0 的元素 `7` 会在第 3 轮直接退出并返回 `-1`。

       * 根源是少做了一次比较：前面每轮参与比较的都是 `i` 与 `j` 中间的那个 `m`，但最后一次还得比较 `i`、`j` 指向的元素，它有可能正是要找的目标。

```text
错误版本 while (i < j)，查找数组中下标为 0 的元素 7：
  轮 1:  i = 0, j = 7, m = 3 -> a[3] = 30 ;  7 < 30  ->  j = M - 1 = 2
  轮 2:  i = 0, j = 2, m = 1 -> a[1] = 13 ;  7 < 13  ->  j = M - 1 = 0
  轮 3:  i = 0, j = 0 ;  i < j 不成立  ->  直接退出  ->  return -1
                                    ^
                        a[0] = 7 从来没有参与过比较！

正确版本 while (i <= j)，查找数组中下标为 0 的元素 7：
  轮 1:  i = 0, j = 7, m = 3 -> a[3] = 30 ;  7 < 30  ->  j = M - 1 = 2
  轮 2:  i = 0, j = 2, m = 1 -> a[1] = 13 ;  7 < 13  ->  j = M - 1 = 0
  轮 3:  i = 0, j = 0 ;  i <= j 成立  ->  继续进入循环
         m = (0 + 0) / 2 = 0，与 i、j 指向同一个元素
         a[0] = 7 == 7  ->  这回才真正找到目标, 返回 0
```

       * 加了等于就表示 `i`、`j` 指向的元素也会参与比较；不加等于只有 `m` 参与，就会产生这个疏漏。

       * > **注意**：这个等号加与不加跟 `j` 的取值方式有关，改进版本里 `j` 的初值不同，循环条件也跟着变。

## 三个例子走通流程

   * **查 14：一次左移就命中**

       * 第一轮没找到，但得到了「目标在左半区」的结论，带着这个结论把范围缩到左边，第二轮命中。

| 轮次 | i | j | 中间下标 m | 中间值 | 与 target 比较 | 边界变化 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 第 1 轮 | 0 | 7 | (0+7)/2 = 3.5 → 3 | 30 | 30 > 14 | 走目标小于中间值：j = M - 1 = 2 |
| 第 2 轮 | 0 | 2 | (0+2)/2 = 1 | 14 | 14 == 14 | 找到了，返回下标 1 |

   * **查 38：一次右移就命中**

       * 第二轮的取整要注意：$4 + 7 = 11$，除以二是 5.5，同样要向下取整成 5，中间值正好是 38。

```text
查 38：
  轮 1:  i = 0, j = 7, m = 3 -> a[3] = 30 ;  38 > 30  ->  i = M + 1 = 4
  轮 2:  i = 4, j = 7, m = (4 + 7) / 2 = 5.5 -> 5 -> 中间值正好是 38
         38 == 38  ->  找到, 退出循环, 返回 5
```

   * **查 25：范围被压空**

       * 第 3 轮 `i == j` 仍然走了取中间值与比较：$m = (2+2)/2 = 2$，中间值 `22` 仍比 `25` 小，于是 `i = M + 1 = 3`，`i > j` 终于满足。

| 轮次 | i | j | 中间下标 m | 中间值 | 与 target 比较 | 边界变化 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 第 1 轮 | 0 | 7 | 3 | 30 | 30 > 25 | j = M - 1 = 2 |
| 第 2 轮 | 0 | 2 | 1 | 14 | 14 < 25 | i = M + 1 = 2 |
| 第 3 轮 | 2 | 2 | 2 | 22 | 22 < 25 | i = M + 1 = 3，此时 i > j |
| 结束 | 3 | 2 | — | — | 范围内没东西了 | 返回 -1 |

## 中间下标的取法

   * **`m = (i + j) / 2`**

       * > **定义**：中间索引 `m` 就是 `i` 与 `j` 相加起来除以二。

       * 需要向下取整：$0 + 7$ 除以二是 3.5，3.5 不能作为索引，向下取整得 3。

       * Java 中两个 `int` 相除会自动舍弃小数部分，所以基础版不必额外调用取整函数。

       * 换到别的语言要自己处理取整：JavaScript 里两数相除不会自动取整，得再调 `Math.floor` 把 3.5 变成 3。

   * **除法会算出负数**

       * 构造 `i = 0`、`j = Integer.MAX_VALUE - 1 = 2147483646`：第一次 $m = 1073741823$ 正常，约等于整数最大值的一半。

       * 目标在中间值右侧时 `i = m + 1 = 1073741824`，此时 $i + j = 3221225470$，已经超过 Java 最大正整数 2147483647，再除以二就得到负数。

       * > **定义**：一个二进制数其实有两种表现形式——一种把最高位看成符号位，另一种把最高位当成普通数字。同样的比特位，两种看法算出来的数值完全不同。

       * Java 里没有无符号整数，一律把最高位读成符号位。

       * 八位小例子：`11111111` 全当普通数字是 255，最高位当符号位则表示 -1。

       * > **易错点**：这个现象不要笼统地叫「溢出」。$i + j$ 的 3221225470 其实并没有超出 32 位的表示范围，它超出了 **int 有符号正数的上限**；严格讲这是同一串比特位被按两种规则解读。

```text
i + j 在 32 位下的比特位：
    1011 1111 1111 1111 1111 1111 1111 1110
    ↑最高位

最高位不当符号位：  3221225470    （看起来是正数的结果）
最高位当符号位：    -1073741826   （Java 看到的是这个）
```

   * **无符号右移 `>>>`**

       * > **定义**：把二进制的所有 0 和 1 一起向右平移指定位数，左边空出来的高位用 0 补齐。

       * 偶数时结果就是除以二；奇数时是除以二向下取整，所以右移一位可以直接看成「除以二取整」。

       * 除法**不会去动那个符号位**，负数除以二还是负数，前面已经变负的结果根本救不回来；右移不一样，符号位本身被一起挪走了。

```text
8       = 00001000
8 >>> 1 = 00000100 = 4        高位补 0

16      = 00010000
16 >>> 1 = 00001000 = 8

7       = 00000111
7 >>> 1 = 00000011 = 3        = 7 / 2 = 3.5 向下取整

    1011 1111 1111 1111 1111 1111 1111 1110   3221225470   （i + j，负数）
>>> 1
    0101 1111 1111 1111 1111 1111 1111 1111   1610612735   （约 16 亿，正数）
```

       * > **易错点**：这里必须是 `>>>`，不能写成 `>>`。整套道理讲的就是「符号位要被移走」，而 `>>` 是带符号右移，会把符号位一路带下来，负数移完还是负数。

       * `>>>` 天然就是向下取整的，`(0 + 7) >>> 1` 直接得 3，不用额外包一层取整函数。

       * 这一行在 Java 里、哪怕在 JavaScript 里都可以当整数运算用，多语言通用，不用为每种语言各写一份。

       * > **结论**：为了避免中间索引算成负数，一定要把除法改成无符号右移。

   * **`i + ((j - i) >> 1)` 写法**

       * 代码里常写成 `int m = i + ((j - i) >> 1);`，右移一位代表除以二。

       * 题目给数组长度 1 到 1 万这样的范围时，用除法算中点也没问题，不用移位也行；写成移位只是为了代码稍微通用一些。

## 三种比较结果

   * **三个分支的走向**

       * `a[m] > target`：`j = m - 1`，只在左半区继续找。

       * `a[m] < target`：`i = m + 1`，只在右半区继续找。

       * `a[m] == target`：直接 `return m`，找到后不需要再循环下去做比较。

```text
                      a[M] = 30
                         |
          +--------------+--------------+
          |                             |
     target = 14                  target = 38
   target < a[M]                 target > a[M]
          |                             |
          v                             v
  i 不变, j = M - 1            i = M + 1, j 不变
          |                             |
          v                             v
  只在左半区继续找                 只在右半区继续找

  第三种情况:  target == a[M]  ->  找到了, 直接 return M
```

   * **方向为什么成立**

       * 根子都在「升序」这两个字上：中间值 30 已经大于 14，它右侧的元素只会更大，所以 30 及其右侧所有元素下一轮都不用参与比较。

       * 反过来 38 大于 30，说明要找的 38 肯定在 30 的右侧，30 及其左侧所有元素下一轮就没必要参与了。

       * > **结论**：一轮就把范围缩小约一半，查找过程与数组元素总数无关。

## 基础版实现与测试

   * **`binarySearchBasic`**

       * > **定义**：基础版二分查找的方法实现，三分支、左闭右闭、找不到返回 `-1`。

       * `int i = 0;` 与 `int j = a.length - 1;` 就是设指针，$N$ 就是数组的元素个数，也就是 `a.length`，所以右边界等于 `a.length` 减一。

       * `while (i <= j)` 就是「看范围内还有没有东西」。

       * `int m = (i + j) / 2;` 是取中间下标，Java 的整数除法自动舍弃小数部分。

       * 三个 `if` 分支正好对应流程里的三个比较结果。

```java
public class BinarySearch {

    /**
     * 二分查找基础版
     */
    public static int binarySearchBasic(int[] a, int target) {
        int i = 0;               // 左边界，初始指向索引 0
        int j = a.length - 1;    // 右边界，初始指向索引 N-1

        while (i <= j) {         // 范围内还有元素，才值得再比较一次
            int m = (i + j) / 2; // Java 中 int 除法自动取整，舍弃小数部分

            if (a[m] > target) {
                j = m - 1;       // 目标在中间值左侧，右边界向左收缩
            } else if (a[m] < target) {
                i = m + 1;       // 目标在中间值右侧，左边界向右收缩
            } else {
                return m;        // 相等，找到，直接返回索引位置
            }
        }

        return -1;               // i > j，范围内没东西了，没有找到
    }
}
```

   * **分支次序：为什么全写小于号**

       * 数组是升序排列的，写成小于号，方向跟数组升序的顺序一致：看到 `i <= j` 第一反应就是 `i` 在左侧、更小，`j` 在右侧、更大。

       * 把代码顺序换一下写成 `j >= i`，逻辑一模一样但读起来特别别扭，跟数组升序的顺序正好反过来。

       * 「中间值跟目标值比较」那处同理：一眼就能看出目标更小、在左边，目标更大、在右边。

       * > **结论**：升序数组就用小于，降序数组自然就该反过来用大于。

   * **测试用例的写法**

       * > **定义**：`assertEquals(预期值, 方法实际返回值)` 把预期值跟实际结果做相等比较，一致则断言通过。

       * 找到的情况：把数组里每个元素都验证一遍，预期值就是它自己的下标。

       * 找不到的情况挑三个点：比所有元素都小的 `0`、夹在 13 和 21 中间的 `15`、比所有元素都大的 `60`，预期值都是 `-1`。

       * > **提示**：判断循环条件该写 `i <= j` 还是别的，改完把已写好的测试用例再跑一遍，让失败的断言替你验证，比空推快得多。

## 改动版：`j` 只当边界

   * **`binarySearchAlternative` 的三处改动**

       * > **定义**：与基础版逻辑等价的另一种写法，把区间改成左闭右开，核心是「`j` 只当边界」。

       * 改动一：`j` 初值从 `a.length - 1` 变成 `a.length`。

       * 改动二：循环条件从 `i <= j` 变成 `i < j`。

       * 改动三：目标在左边时 `j` 从 `m - 1` 变成 `m`，而 `i = m + 1` 不变。

       * 正确性仍用老办法验证：把基础版的测试复制一份，只改调用的方法名，找到与找不到的几种情况全部通过。

```java
public static int binarySearchAlternative(int[] a, int target) {
    int i = 0;
    int j = a.length;                   // 改动一：去掉 -1
    while (i < j) {                     // 改动二：去掉等号
        int m = (i + j) >>> 1;
        if (a[m] == target) {
            return m;
        }
        if (target < a[m]) {
            j = m;                      // 改动三：去掉 -1
        } else {
            i = m + 1;                  // 这个不变
        }
    }
    return -1;
}
```

   * **`i` 与 `j` 的身份对照**

       * 基础版是**左闭右闭的边界**：`i`、`j` 不光代表搜索的边界，它们指向的元素最终也有可能参与比较运算。

       * 改动版是**左闭右开的（开）边界**：`i` 的含义没有改变，它指向的元素仍然有可能是查找目标；`j` 却只是作为一个边界，它指向的一定不是查找目标。

       * 改动版里 `j` 的初值取 `a.length`，指向的是一个**并不存在的元素**。

```text
基础版（左闭右闭）
  下标    0    1    2    3    4    5    6    7
  元素    4    ?    ?   13   22    ?    ?   25
         ↑                        ↑
         i                        j   ← j 指向的元素可能就是答案 25

改动版（左闭右开）
  下标    0    1    2    3    4    5    6    7    8
  元素    4    ?    ?   13   22    ?    ?   25    ✗
         ↑                        ↑
         i                        j   ← j 一定不是答案，它越界了
```

   * **为什么 `j` 只能是 `m`**

       * > **结论**：改动版里 `j` 的含义是「只作为一个边界，它指向的元素肯定不会参与比较」，所以缩小边界时才能让它等于 `m` 而不是 `m - 1`。

       * 原因是这个 `m` 在当轮比较时已经比较过了，既然决定了要向左找，`m` 指向的元素肯定不等于目标，下次不参与比较。

       * > **易错点**：若写成 `j = m - 1`，下一轮 `j` 就会指向那个恰好等于目标、但已被跳过的元素，结果跟目标恰巧错过，把答案漏掉。

       * 例：查找 13，`i = 0`、`j = 8`，$m = (0+8)/2$ 取整得 4，中间值 22；目标更小所以 `j = m = 4`；下一轮 $m = (0+4)/2 = 2$，目标更大所以 `i = m + 1 = 3`；此时 `i < j` 仍成立，再算 $m = (4+3)/2$ 取整得 3，中间值等于目标，找到。

   * **`while` 里为什么不能加等号**

       * 因为 `j` 指向的元素本来就不应该让它继续参与比较了；加上等号会允许最后一步 `i` 等于 `j`，让它们指向的元素一起参与比较，与前面的假设直接矛盾。

       * > **易错点**：只要加上这个等号条件，在查找一个数组内没有的元素时就会陷入死循环。

       * 第三轮 `i == j` 时算出的 `m` 与 `i`、`j` 指向同一个元素，它已经比过且不相等；又因为目标比中间值小进入「在左边」分支，`j = m` 让 `j` 原地不动，状态与上一行完全相同，于是刚才那段逻辑原封不动地再走一遍。

```text
查找数组中不存在的 30：

i=0 j=8 -> m=4, a[4]=35 > 30  ->  j = m = 4
i=0 j=4 -> m=2, a[2]=19 < 30  ->  i = m + 1 = 3
i=3 j=4 -> m=3, a[3]=27 < 30  ->  i = m + 1 = 4     （m 恰好等于 i，比较合法）
i=4 j=4 -> i == j，若允许进循环：m=4, a[4]=35 > 30  ->  j = m = 4   ← j 原地不动
i=4 j=4 -> …… 状态与上一行完全相同，死循环
```

   * **两个版本并排对照**

       * 这两种版本都得掌握：改动版的写法会继续用在二分查找的更多用途里，包括 left most、right most。

| 对照项 | 基础版 | 改动版 |
| :--- | :--- | :--- |
| `i` 初值 | `0` | `0` |
| `j` 初值 | `a.length - 1` | `a.length` |
| `i` 指向的元素 | 可能是答案 | 可能是答案 |
| `j` 指向的元素 | 可能是答案 | 一定不是答案 |
| 循环条件 | `i <= j` | `i < j` |
| 目标在中间值左侧 | `j = m - 1` | `j = m` |
| 目标在中间值右侧 | `i = m + 1` | `i = m + 1` |
| 边界语义 | 左闭右闭 | 左闭右开 |
| 找不到时返回 | `-1` | `-1` |

## 复杂度：凭什么说二分比线性快

   * **线性查找（linear search）**

       * > **定义**：从下标 0 循环到数组长度减一，逐个与目标比较，相等就返回这个索引，都循环完一遍还没找到就返回 `-1`。

       * 代码行数比二分查找少，理解起来也更简单。

       * 对数组里的元素**没有升序的要求**。

   * **事后统计法**

       * > **定义**：让两个算法的代码各跑一遍，看看你快还是我慢，是最为直接的做法。

       * 缺点一：**比较依赖于测试数据**，只有数据量规模比较大时才看得出差别，而准备测试数据通常要花费很多精力。

       * 缺点二：**比较依赖于硬件环境**，跑得快可能只是因为你的机器好，并不是因为算法好。

   * **事前分析法与它的两条前提**

       * > **定义**：不实际执行算法，而是通过分析的手段去预估算法的执行时间。

       * 前提一：**只分析算法最差的执行情况**，最好与平均情况先不考虑；为公平起见，分析二分查找时也取最坏情况。

       * 前提二：**假设每行语句执行的时间是一样的**，否则还得考虑赋值、自增、比较之间的差异，事情就被搞复杂了。

   * **线性查找的最坏情况**

       * 最差执行情况就是找不到的时候，所有循环都跑完，最后又执行了一个 `return -1`，执行的代码行数肯定最多。

       * 判断条件是 $n + 1$ 次，因为前 $n$ 次遍历下标 0 到 $n-1$，最后一次 `i == n` 才发现已越过数组，但那次比较还是得有。

       * `return i` 是 0 次，因为每次比较都不成立，根本进不了 `if` 里头；最后的 `return -1` 一定执行一次。

| 语句 | 最坏情况下的执行次数 |
| :--- | :--- |
| `for` 里给临时变量 `i` 赋值 | 1 |
| `for` 里判断是否循环结束 | $n + 1$ |
| `for` 里 `i++` 自增 | $n$ |
| `if (a[i] == target)` 比较 | $n$ |
| `if` 里的 `return i` | 0 |
| 最后的 `return -1` | 1 |

$$
1 + (n + 1) + n + n + 0 + 1 = 3n + 3
$$

       * 它跟数组元素个数直接相关：1000 个元素要执行 3003 次，1 万个要执行 30003 次。

   * **二分查找的 `while` 循环次数**

       * 「没找到」也要分两种情况，找一个在左侧没找到和找右侧没找到，语句总次数是不一样的，而且**右侧没找到更差一些**，所以以右侧没找到为准。

       * 数循环次数的办法很直接：每次进入循环一定会求中间索引 `m`，数 `m` 出现了几次就相当于进入了几次循环。

       * 元素个数为 4、找右侧没有的 100 时 `m` 出现 3 次；元素个数改成 8、同样找 100 时 `m` 出现 4 次。

| 元素个数 $n$ | while 循环次数 |
| :--- | :--- |
| 4 ~ 7 | 3 |
| 8 ~ 15 | 4 |
| 16 ~ 31 | 5 |
| 32 ~ 63 | 6 |

       * > **结论**：区间的长度每翻一倍，循环次数才多一次——从 4 到 8 翻倍加 1，从 8 到 16 翻倍又加 1。

## 平衡版

   * **比较次数的不平衡**

       * > **定义**：基础版循环体 `if / else if` 每轮的比较次数不同，往左走成本低、每轮只比一次，往右走成本高、每轮要比两次。

       * 目标在最左边时每轮 `target < a[mid]` 成立，`if` 一旦成立就不再进 `else if`，$L$ 轮合计 $L$ 次比较。

       * 目标在最右边时每轮 `target > a[mid]`，`if` 永远不成立、每次都掉进 `else if`，每轮 2 次，$L$ 轮合计 $2L$ 次比较。

       * 既然有便宜的一半和贵的一半，那就总有改进空间，平衡版要做的就是把这两半拉平。

   * **左闭右开区间 $[i, j)$**

       * 待查找区间是 $a[i \dots j-1]$；`a[i]` 有可能就是要找的目标，`a[j]` 一定不是，它压根就是一个边界，只是「待查区间的右端点之外那一格」。

       * 循环条件不再是 `i <= j` 而是 `j - i > 1`，`j - i` 就是当前范围内待查找的元素个数；一旦只剩一个元素就退出循环。

       * 跑到最后一步会发现 `a[j]` 已经不在范围内了，这恰恰说明区间里只剩 `a[i]` 这一个元素。

   * **循环只负责收缩**

       * > **定义**：平衡版不在循环内找出目标元素，循环的唯一职责就是把边界缩小；范围内只剩 `i` 指向的那一个元素时退出循环，然后才在**循环外面**比较 `a[i]` 跟目标是否相同。

       * 「找到」这个动作被从循环里搬了出来。既然比较搬到循环外，循环里就只需要「这一轮往哪边收缩」这一个判断。

   * **`else` 分支必须是 `i = m`**

       * 去掉 `else if` 后只剩一个 `if` 和一个 `else`，所以循环内每轮只可能做一次比较——左边一次、右边也是一次，平衡了。

       * `if` 分支跟从前一样：目标小于中间值就把右边界 `j` 收缩到 `m`。

       * > **易错点**：进了 `else` 意味着目标**要么等于中间值、要么大于中间值**，目标有可能正好在 `m` 上，所以 `i` 不能再写成 `m + 1`，必须写成 `m`。

       * 例：目标 22、中间索引 `m` 指向的恰好就是 22，若还按老习惯写 `i = m + 1`，`i` 一路就跑到 30 去了，把 22 整个错过。

       * 这一条赋值是平衡版与前面所有版本最不一样的地方：**中间值本身必须被包含在内**。

   * **代价：最好情况不再是 $O(1)$**

       * 优点必须在**数据量非常大的时候**才能体现，数量小的话这点差异并不明显。

       * 基础版里待查找元素恰在数组正中央时第一轮就比中，中间元素跟目标相等直接退出，只需要一轮，时间复杂度是 $O(1)$。

       * 改动之后这个最好情况没有了，因为不存在「第一轮就命中直接返回」的情形，最好与最坏情况全都是 $O(\log n)$。

       * 上下界可以用同一个函数描述时，表达式写成 $\Theta(\log n)$。

       * > **易错点**：平衡版换来的不是「整体更快」而是「比较次数更均匀」，它牺牲了 $O(1)$ 的最好情况换来每轮恒定 1 次比较；不要再拿「命中中间值一次就返回」去描述这一版。

```java
public static int bsearch(int[] a, int target) {
    int i = 0;
    int j = a.length;          // 左闭右开：a[j] 越界，不可能是目标
    while (j - i > 1) {        // j - i 就是范围内待查找的元素个数
        int m = (i + j) / 2;
        if (target < a[m]) {
            j = m;            // 目标在左侧，右边界收缩到 m
        } else {
            i = m;            // 目标 >= a[m]，必须停在 m，不能是 m + 1
        }
    }
    // 循环只负责收缩边界，最后一次比较挪到循环外面做
    return a[i] == target ? i : -1;
}
```

   * **用 `[10, 20, 22, 30]` 找 22 走一遍**

       * $j - i = 4 > 1$，$mid = 2$，`a[2] = 22`，`22 < 22` 不成立走 `else`，`i = 2`。

       * $j - i = 2 > 1$，$mid = 3$，`a[3] = 30`，`22 < 30` 成立，`j = 3`。

       * $j - i = 1$ 退出循环，在循环外比较 `a[2] = 22` 与目标，相等，返回 2。

## `Arrays.binarySearch` 与插入点

   * **`java.util.Arrays.binarySearch`**

       * > **定义**：Java 的二分查找实现在 `java.util` 包下的 `Arrays` 类里，有一大堆以 `binarySearch` 命名的方法，区别只在于处理的数据类型不一样，实现彼此类似。

       * 第二个参数的命名习惯是 `key`（自己写惯用 `target`），内部再调另一个叫 `binarySearch0` 的方法，并多传了两个参数：0 与数组长度。

       * `low` 是左边界、含义等同自己写的 `i`；`high` 是右边界、含义等同自己写的 `j`，取值分别是那个 0 和数组长度减 1。

       * 两个指针都可能指向要查找的目标，所以循环条件必然是 `low <= high`，必须带上等于，保证最后 `low == high` 时指向的元素也还能参与一次比较。

       * 中间索引用**无符号右移**代替除法以避免出现负数。

   * **判断顺序：先右、再左、后相等**

       * 自己的习惯是先看目标是不是在左边、再看是不是在右边；它先看目标是不是在中间值的右边。

       * 既然是三分支，这一版**向左找成本更高**：`if` 比一次不成立、`else if` 再比一次；而向右找只需 `if` 那一次比较。

       * > **提示**：它这里要是先用小于号就更好了，小于号跟阅读习惯一致，也跟它「先右」的思路更搭。

   * **找不到时返回的不是 `-1`**

       * 循环走完没找到，它返回的是左边界加一再取负号 `-(low + 1)`。

       * > **定义**：**插入点（insertion point）** 指一个新值按顺序插入后仍能保证升序的那个位置，也就是第一个满足「左边所有元素 ≤ 目标、右边所有元素 ≥ 目标」的索引。

       * 对基础版二分查找算法，循环退出时 `i` 停在的位置就是插入点，用 `i` 这一个变量表示就够了。

       * 验证：数组 `[2, 5, 8]`，找比所有元素都小的 `0`，跑完 `i` 指向索引 0；找 `20`，`i` 指向 4；找 `40`，`i` 先做 `7 + 1 = 8` 的动作后退出循环，指向 8，而 40 应插在索引 8。

       * `low` 的含义跟 `i` 相同，所以 **`low` 就是插入点**；方法返回 0 和正数表示「找到了」，必须返回负数才表示「没找到」，所以把 `low` 取负数返回。

   * **换算与「为什么非要减掉那个 1」**

       * 文档 `returns` 段落写的是「负的 `-(insertion point) - 1`」；换算时把 1 移到等式左边，相当于「返回结果 + 1」等于负的插入点，再把负号去掉。

| 查找的 key | 在数组中 | 返回值 | 真实插入点索引 |
| :--- | :--- | :--- | :--- |
| 4 | 否 | `-2` | 1 |
| 1 | 否 | `-1` | 0 |
| 9 | 否 | `-4` | 3 |
| 5 | 是 | `1` | —— |

       * 查 4 得 `-2`：`-2 + 1 = -1` 去掉负号得 1，4 将来插进 `[2, 5, 8]` 的索引位置是 1，它应该插到 2 和 5 之间。

       * 查 1 得 `-1`：`-1 + 1 = 0`，1 最小只能插在最前面。

       * 查 9 得 `-4`：`-4 + 1 = -3` 去掉负号得 3，9 比所有元素都大，插到 8 的后面。

       * > **易错点**：必须减 1 的唯一理由是整数里正零和负零其实是同一个值，`0 == -0` 永远为真；插入点若为 0 而直接返回 `-0`，就与「命中索引 0」根本区分不开。

   * **顺着插入点把元素插进去**

       * > **注意**：Java 的数组不会自动扩容，得新建一个长度是旧数组加一的新数组，然后分三步搬。

       * 真正的插入点索引等于返回值加 1；`-2 + 1` 之后可能还是负数，所以还要求绝对值，Java 里用 `Math.abs`。

       * 第一步 `System.arraycopy(a, 0, b, 0, insertIndex)` 把插入点之前的元素拷到新数组，拷完是 `[2, 0, 0]`。

       * 第二步 `b[insertIndex] = target` 把目标落到插入点，新数组变成 `[2, 4, 0]`。

       * 第三步把旧数组插入点之后的元素拷到新数组：源起点是 `insertIndex`，目标起点是 **插入点加一**（那一格已被 target 占了），长度是 `a.length - insertIndex`。

```java
int r = Arrays.binarySearch(a, target);
if (r < 0) {                            // 没找到，r 是负数
    int insertIndex = Math.abs(r + 1);  // 真正的插入点索引
    int[] b = new int[a.length + 1];    // Java 的数组不会自动扩容，得新建

    System.arraycopy(a, 0, b, 0, insertIndex);              // ① 插入点之前
    b[insertIndex] = target;                                // ② 目标落到插入点
    System.arraycopy(a, insertIndex, b, insertIndex + 1,    // ③ 插入点之后
                     a.length - insertIndex);

    System.out.println(Arrays.toString(b));
}
```

```text
old a:    [ 2   5   8 ]
            ↑
            insertIndex = 1

step 1:   [ 2   0   0 ]        ← System.arraycopy(a, 0, b, 0, insertIndex)
step 2:   [ 2   4   0 ]        ← b[insertIndex] = target
step 3:   [ 2   4   5   8 ]    ← System.arraycopy(a, insertIndex, b, insertIndex + 1, ...)
```

## 重复元素与候选位置写法

   * **基础版返回的是「第一个碰到的」**

       * > **定义**：基础版遇到重复元素时返回的是它第一个遇到的那个，并不保证是最左侧的。

       * `[1, 2, 3, 4, 4, 5, 6, 7]` 查重复元素 4 返回 3，那只是碰巧——中间索引第一次就落在 3 上，而 3 恰好就是最左侧的 4。

       * 改成 `[1, 2, 4, 4, 4, 5, 6, 7]`（三个 4）再跑，仍返回 3，而真正的最左侧是索引 2。

   * **候选位置思路**

       * > **结论**：相等时记一个候选者，然后不停止，继续往左走；循环走完，候选者就是答案。

       * 相等的中间点不一定就是最终结果，因为左边可能还有更靠左的重复值；但它可以作为一个候选位置先记录下来。

       * 记录候选位置并不意味着算法结束，还要在左侧继续找，也就是继续把 `j` 缩到 `m - 1`。

       * 下一轮中间点若不等就扩大 `i`；又遇到相等的中间点就更新候选位置；直到 `i > j` 退出循环。

```text
index:   0  1  2  3  4  5  6  7
value:   1  2  4  4  4  5  6  7

轮次   搜索区间          mid   a[mid]   这一轮做什么
  1     i=0 .. j=7        3      4     相等：candidate = 3，j = m - 1 = 2
  2     i=0 .. j=2        1      2     不等：i = m + 1 = 2
  3     i=2 .. j=2        2      4     相等：candidate = 2，j = m - 1 = 1
  4     i=2 > j=1，循环结束 -> 返回 candidate = 2
```

   * **leftmost 实现**

       * 改动主要在 `else` 分支：指针初始化、`while` 条件、`mid` 的计算、两个不相等的分支跟基础版一字不差。

       * 定义变量 `candidate` 专门记录候选位置，初值 `-1` 表示还没有任何候选者。

       * 相等时不再立刻返回，而是 `candidate = m` 记下来，然后 `j = m - 1` 继续向左找；循环结束后返回 `candidate`，一次都没匹配上就返回初始值 `-1`。

```java
int candidate = -1;          // -1 表示还没有任何候选者

while (i <= j) {
    int m = (i + j) / 2;
    if (target < a[m]) {
        j = m - 1;
    } else if (target > a[m]) {
        i = m + 1;
    } else {
        candidate = m;       // 先记下来，不急着返回
        j = m - 1;           // 还要继续往左找
    }
}

return candidate;            // 一次都没相等，就是初始值 -1
```

       * 测试用例：查 1 得 0，查 2 得 1，查重复元素 4 得 2，查 5 得 5，查 6 得 6，查 7 得 7；查 0、3、8 全部返回 `-1`。

   * **rightmost：只换一个方向的边界**

       * 与 leftmost 完全对称：同样用 `candidate` 记录候选位置，同样每次中间值跟目标相等时记录并更新候选。

       * > **结论**：唯一的区别是方向——leftmost 发现相等后向左找、把 `j` 缩小；rightmost 发现相等后向右找、把 `i` 扩大到 `m + 1`。

```java
} else {
    candidate = m;       // 同样先记录
    i = m + 1;           // rightmost：向左找改成向右找，缩小 j 改成扩大 i
}
```

       * 都找不到时候选者同样返回 `-1`；数组里三个重复的 4，最右侧的 4 应为索引 4。

## 把 `-1` 换掉

   * **leftmost 原来返回 `-1` 的问题**

       * leftMost 查找与目标相等的**最靠左**索引，rightMost 查找**最靠右**索引，找不到时两个方法都返回 `-1`。

       * 找不到的情况它们给回来的东西一模一样，而一个只能告诉你「没有」的返回值能承载的信息量太瘦了。

   * **`leftMost2`：返回 `i`**

       * > **定义**：删除 `candidate`、统一返回 `i`，`i` 的含义是**大于等于 target 的最靠左的那个索引位置**。

       * `candidate` 在循环里一次都没被用上，直接删掉，代码就短了一截。

       * `target < a[m]` 与 `target == a[m]` 执行的语句完全一样（都是 `j = m - 1`），所以合成 `if (target <= a[m])`，原来的 `else` 省了，`else if` 顺势降级成 `else`。

```java
// leftMost 2：返回“大于等于 target 的最靠左索引”
public static int leftMost2(int[] a, int target) {
    int i = 0;
    int j = a.length - 1;

    while (i <= j) {
        int m = i + ((j - i) >> 1);
        if (target <= a[m]) {
            j = m - 1;          // 小于等于中间值，都往左
        } else {
            i = m + 1;          // 大于中间值，往右
        }
    }
    return i;
}
```

       * 实测验证比空推靠谱：查存在的 `4`，`i` 指向与目标相等的、最靠左的那个索引；查不存在的 `3`，`i` 指向 4，是比目标大的元素里最靠左的；查不存在的 `5`，`i` 指向 7。

       * > **易错点**：`i` 是在循环里一路向右累加出来的；若数组里所有元素都比 target 小，它会一路加到 `a.length` 这个越界位置，所以返回值不能无脑当索引用，边界得自己判一下。

   * **`rightMost2`：返回 `i - 1`**

       * > **定义**：分支合并方向反过来，合成 `if (target < a[m]) { j = m - 1 } else { i = m + 1 }`，返回的 `i - 1` 代表**小于等于 target 的最靠右的那个索引位置**。

       * 查存在的 `4`，`i - 1` 落在索引 5，正是最右侧的那个 4；查不存在的 `5`，`i - 1` 落在索引 5，那个元素是 4，是比目标小的元素里最靠右的。

```java
// rightMost 2：返回“小于等于 target 的最靠右索引”
public static int rightMost(int[] a, int target) {
    int i = 0;
    int j = a.length - 1;

    while (i <= j) {
        int m = i + ((j - i) >> 1);
        if (target < a[m]) {
            j = m - 1;
        } else {
            i = m + 1;          // 大于等于中间值，都往右
        }
    }
    return i - 1;
}
```

       * > **结论**：一个 `>=` 配「最靠左」，一个 `<=` 配「最靠右」，这两个方法合起来就正好卡住了一个区间左右两端的所有边界。

## 由边界返回值派生的应用

   * **尺子图**

       * 下面所有例子都拿这段升序数组当尺子量：三个 4 挤在中间，靠左是 1、2，靠右是 7。

```text
下标: 0   1   2   3   4   5   6  ...
元素: 1   2   4   4   4   7  ...
```

   * **四个名词**

       * > **定义**：**排名** 指 target 在数组里排第几，比 target 小的元素有几个，它自身就是第几；图里 5 比它小的有 1、2、4、4、4 共五个，所以排名第六。

       * > **定义**：**前任** 指所有比 target 小的元素里最靠右的那个；图里 5 的前任是 4，取靠左的那个就不叫前任了。

       * > **定义**：**后任** 指所有比 target 大的元素里最靠左的那个；图里 5 的后任就是它右边第一个 7。

       * > **定义**：**最近邻居** 把前任和后任放在一起，看谁离 target 更近，答案就是谁。

   * **四个公式**

       * > **结论**：求排名 = `leftMost(target) + 1`，因为索引从 0 开始而排名从 1 开始。

       * 图里比 4 小的有 1 和 2，4 排第三；查不存在的 5 时返回大于等于 5 的最靠左索引即第一个 7 的位置 5，加 1 等于 6，5 确实排第六。

       * > **结论**：求前任 = `leftMost(target) - 1`；查 4 时是 2 - 1 = 1 即 `a[1] = 2`，查 5 时是 5 - 1 = 4 即那个 4。

       * > **结论**：求后任 = `rightMost(target) + 1`；查 4 时最右侧的 4 索引 4 加 1 得 7，查 5 时小于等于 5 的最靠右就是最后这个 4，加 1 得 7。

       * > **结论**：往前看用 leftMost，往后看用 rightMost。

   * **范围查询的四种基本区间**

       * > **定义**：**范围查询** 是给出一个目标值，找出数组内所有小于、大于、小于等于、大于等于目标的元素。

       * 诀窍是不用去遍历，只要把条件翻译成一段**索引区间**，那一段里全是答案，区间外一个都不是。

       * 以目标 4 为例，小于 4 的元素在图中只有 1 和 2，也就是从下标 0 到最左侧那个 4 的前一位；大于等于 4 则要把几个 4 本身也算进去。

| 查询条件 | 索引区间 |
| :--- | :--- |
| `x < target` | `[0, leftMost(target) - 1]` |
| `x <= target` | `[0, rightMost(target)]` |
| `x > target` | `[rightMost(target) + 1, ∞)` |
| `x >= target` | `[leftMost(target), ∞)` |

       * > **结论**：「小于」收左端、「小于等于」收右端；「大于」动左端、「大于等于」动右端。

       * 前两条是从下标 0 一直扫到边界，所以边界只能由 leftMost 或 rightMost 提供；后两条是拿边界当起点往右一扫到无穷，起点也只由这两个方法给。

   * **组合区间**

       * > **结论**：$target_1 \le x \le target_2$ 用 $[\text{leftMost}(target_1),\ \text{rightMost}(target_2)]$，从 4 的 leftMost 开始一直到 7 的 rightMost 为止。

       * > **结论**：$target_1 < x < target_2$ 用 $[\text{rightMost}(target_1) + 1,\ \text{leftMost}(target_2) - 1]$，左边往右找、右边往左找把两个等号都摘掉。

```java
// 4 <= x <= 7
int from = leftMost2(a, 4);
int to   = rightMost(a, 7);
// 区间 [from, to]

// 4 < x < 7
int from = rightMost(a, 4) + 1;
int to   = leftMost2(a, 7) - 1;
```

## 三种写法的收束

   * **题目条件**

       * 这道题（力扣 704）给定一个包含 $n$ 个元素的**升序**有序整型数组与目标值 `target`，存在返回下标，不存在返回 `-1`。

       * 题目提示：数组中元素不重复，不用考虑找最左边还是最右边的那个，找到就算对。

       * 题目提示：$n$ 的取值范围是 1 到 1 万，不大，累加不会超过 `int` 能表示的最大整数范围，所以用除法算中点都没问题，不用移位也行。

       * > **提示**：提交时方法名、类名最好不要动，但参数名可以随便改；讲课时对着图写代码，自己写时在草稿纸上画个草图就能代替动画。

   * **三种写法的差异**

       * 基础版和改动版的循环都是三分支的 `if / else if / else`，三个分支最多会比较两次；平衡版的目标就是把这个三分支改成两分支。

| 写法 | 区间 | `j` 初值 | 循环条件 | 分支数 | 命中返回 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 基础版 | 前闭后闭 `[0, a.length - 1]` | `a.length - 1` | `i <= j` | 三分支 | `else` 里直接 `return m` |
| 改动版 | 前闭后开 `[0, a.length)` | `a.length` | `i < j` | 两分支 | 循环外三元 `a[i] == target ? i : -1` |
| 平衡版 | 前闭后开 `[0, a.length)` | `a.length` | `i + 1 < j`（等价 `j - i > 1`） | 一对 `if / else` | 循环外三元 `a[i] == target ? i : -1` |

   * **基础版的等号不能去**

       * > **易错点**：等号绝对不能去掉。循环内每次比较的刚开始全是 `m`，如果 `i == j` 时不再去找 `m`，它俩指向的元素恰恰可能就是要查找的目标，而前面每轮比的都是中值、`i` 与 `j` 指向的值一直没有机会参与比较——**这就是最后的机会**。

       * 走进循环后算出的 `m` 才能代表 `a[i]` 跟 `a[j]` 参与比较；等号漏了就意味着可能漏掉某一次比较。

   * **改动版与平衡版共用的要点**

       * 两者在范围的选取上一样，都是前闭后开的区间，`j` 指向的是一个不参与比较的位置；`i` 初始值是 0，`j` 初始值是 `a.length`。

       * `j` 重新赋值时都用 `m` 而不是 `m - 1`：`m` 已经比过了，放到 `m - 1` 会把那个还没比较过的值漏掉。

       * 平衡版 `else` 分支用 `i = m`：扩到 `m + 1`，若恰好 `a[m]` 就等于目标，这个相等的元素反而被漏掉了。

       * 平衡版的退出条件是 `i + 1 == j`，此时 `i` 指向最后一个元素；继续循环写成 `i + 1 < j`，等价写法是 `j - i > 1`。

## 搜索插入位置

   * **题目要求**

       * 给定一个排序的升序数组和目标值，能找到就返回索引，找不到就返回它**按顺序插入后仍能保证升序**的那个位置。

       * > **定义**：**插入位置** = 使数组仍升序的第一个空位，也就是第一个满足「左边所有元素 ≤ 目标、右边所有元素 ≥ 目标」的索引。

       * 这是二分查找里唯一一个「找不到反而不返回 `-1`」的形态；找到的情况跟熟悉的结论完全一致，不一样的是找不到时。

   * **取值范围**

       * 数组 `[1, 3, 5, 6]`，找 `2` 应插在索引 1 得到 `[1][2][3][5][6]`；找 `7` 比所有元素都大，只能挂到队尾，索引正好等于数组长度。

```text
index:   0     1     2     3
array:  [1]   [3]   [5]   [6]

target = 2  ->  不在数组内，应插在 index 1，结果 [1][2][3][5][6]
target = 7  ->  不在数组内，应插在 index 4，结果 [1][3][5][6][7]
```

       * > **易错点**：插入位置的取值范围是闭区间 $[0, n]$，它可以是 $n$，这跟查找下标的上界 $n-1$ 不一样，是个很容易写错的点。

   * **题目条件里的「没有重复元素」**

       * 题目要求 $O(\log n)$；数组长度在 1 到 $10^4$ 之间，$n$ 不会太大，用除法取中点完全可以，不必上移位。

       * 题目特别强调数组是**没有重复元素的升序数组**。

       * > **结论**：left most 写法在乎的不是「没有重复」而是「找最靠左」，有重复也行、没重复也可以，所以题目给不给这条约束代码都能过——这就是边界写法比基础写法更值钱的地方。

   * **思路一：改 `Arrays` 的返回值**

       * `Arrays.binarySearch` 找不到时返回负的插入点再减一，那这道题就**别带符号了、也别做那个减一了，直接把插入点还回去**。

```java
int i = Arrays.binarySearch(nums, target);
return i < 0 ? -i : i;
```

       * 底层版本循环退出时 `i` 停在的就是插入点，这正是 `-(i + 1)` 的由来。

       * 解题时把数组参数和目标值参数改个名、中间分支一个字不动，只把返回值换成 `return i`，可随手通过；但它毕竟依赖了标准库的约定。

   * **思路二：left most**

       * > **定义**：left most 版本返回的是大于等于 target、并且最靠左的那个索引，这跟插入位置是同一个东西，所以直接 `return i` 就完事。

       * 三分支里 `target < nums[m]` 与 `target == nums[m]` 动作完全一样，都是 `j = m - 1`，因此合成 `target <= nums[m]`，剩下的 `else if` 顺势改成 `else`。

```java
int i = 0, j = nums.length - 1;
while (i <= j) {
    int m = (i + j) / 2;
    if (target <= nums[m]) {
        j = m - 1;
    } else {
        i = m + 1;
    }
}
return i;
```

       * > **易错点**：相等时最容易写错。数组里有重复元素时，二分中途撞上相等的那个值往往是**中间偏右**的那一个，直接返回就错了；比如要找 4，`[1, 2, 4, 4, 4, 7, 8]` 里可能先撞上索引 4，它不是最靠左的 4。

       * 验证：`[1, 2, 4, 4, 4, 7, 8]` 找 3 返回 2（第一个 ≥ 3 的位置），找 5 返回 5（第一个 ≥ 5 的位置），两例返回后都仍是升序。

       * > **结论**：这道题推荐用 left most 写，它有重复元素时同样给出正确的插入位置，适应性比思路一强得多。

## 搜索开始结束位置

   * **题目要求**

       * > **定义**：**非递减顺序** 指升序排列但允许相等元素连排；开始位置就是最靠左的那个，结束位置就是最靠右的那个。

       * `[5, 7, 7, 8, 8, 10]` 找 `8` 得到开始位置 3、结束位置 4，返回 `[3, 4]`。

       * 找不到时开始位置和结束位置**都返回 `-1`**；题目同样要求 $O(\log n)$。

   * **`left`：候选值写法**

       * > **定义**：目标值是否存在由 `searchRange` 统一判断，`left` 只负责最左侧命中下标、找不到给 `-1`。

       * 与上一题那个「始终返回插入点」的 left most 有一处关键差别：上一题里相等时直接丢弃即可，这一题里相等时得先把下标记下来，再继续往左逼。

       * `candidate` 声明在**循环外面**，初值 `-1` 表示还没有候选；一旦 `nums[m] == target` 就记下这个命中，但它只是候选，不能就此收工，接着 `j = m - 1` 继续缩小范围往左找。

       * > **结论**：循环结束时有两个出口——目标存在则最后一次记下的 `candidate` 就是最靠左的索引，压根没找到则 `candidate` 从头到尾都是 `-1`；一个变量同时表达了「找到」和「没找到」两种状态，这就是设初值 `-1` 的妙处。

```java
private int left(int[] nums, int target) {
    int i = 0, j = nums.length - 1;
    int candidate = -1;
    while (i <= j) {
        int m = (i + j) / 2;
        if (target < nums[m]) {
            j = m - 1;
        } else if (target > nums[m]) {
            i = m + 1;
        } else {
            candidate = m;
            j = m - 1;
        }
    }
    return candidate;
}
```

   * **`right`：跟 `left` 只差一行**

       * > **结论**：`right` 与 `left` 唯一的区别在相等那一支——不确定当前候选是不是最靠右的，所以要**继续往右找**，`i = m + 1`。

       * 两个方法只差一个赋值：一个是 `j = m - 1`，一个是 `i = m + 1`，就这一行方向整个反过来。

       * > **提示**：`left` 和 `right` 完全可以合成一个方法，加一个布尔参数表示往左还是往右——往左就在相等时压 `j`，往右就多一个判断压 `i`。

   * **`searchRange`：把两次查找拼成一个答案**

       * > **结论**：顺序有讲究，**先跑 `left`**；它一旦返回 `-1` 就说明目标值压根不在数组里，`right` 再跑一遍纯属浪费，直接按题目要求丢回 `{-1, -1}`。

       * 只有确认存在了，才有必要去求最右边界；数组下标 0 放开始位置，下标 1 放结束位置。

```java
public int[] searchRange(int[] nums, int target) {
    int start = left(nums, target);
    if (start == -1) {
        return new int[]{-1, -1};
    }
    int end = right(nums, target);
    return new int[]{start, end};
}
```

## 数组：连续存储带来的直接寻址

   * **数组（array）的定义与补充**

       * > **定义**：数组是由一组元素组成的数据结构，说白了就是把多个元素放一块儿统一管理；元素可以是值，也可以是变量。

       * 补充一：元素的类型必须一致，不能一部分是 `int`、另一部分是 `double`，那样就没法用数组管。

       * 补充二：每个元素都有一个索引（或者叫键，key）来标识；index 与 key 纯粹是翻译差异，本质是给每个元素一个唯一标识。

       * 真正值钱的不是定义而是特点：数组中的元素是**连续存储**的，多个元素紧挨着、一个接一个。

   * **地址公式**

       * > **定义**：数组数据的起始地址叫基地址（base address），元素下标记 $i$，每个元素占用的字节数记 `size`，则 $\text{address}(i) = \text{base address} + i \times \text{size}$。

       * `int` 数组每个元素 4 字节，已知索引 0 的地址是 $b$，则索引 1 是 $b + 4$、索引 2 是 $b + 8$、索引 3 是 $b + 12$、索引 4 是 $b + 16$。

       * `int` 数组 `size = 4`；换成 `double` 数组 `size` 就变成 8，因为 `double` 占 8 字节。

       * > **易错点**：`size` 是**每个元素**的字节数而不是元素个数；`i` 是**索引**而不是「第几个」——第 3 个元素的索引是 2，这一步错了后面全错。

       * 例：元素 `1 2 3 4 5` 的 `byte` 数组、基地址 `0x...4c8`，元素 3 的索引是 2、`size = 1`，十六进制里 `a` 表示十所以 $8 + 2 + 1 = 10$。

$$
\text{address}(2) = \texttt{0x4c8} + 2 \times 1 = \texttt{0x4ca}
$$

   * **Java 里一个 `int` 数组的内存账本**

       * Java 里数组本质上是一个**对象**，所以也分**对象头**和**数据**两大部分。

       * `mark word` 8 字节，记录对象的哈希码、GC 分代年龄、加锁时的锁信息。

       * 类指针 4 字节，表示「你这个对象是什么类型」，一个 `int[]` 的类指针可以简单理解成指向 `int[]` 的 `.class`。

       * 数组长度 4 字节，值得占 4 个字节是因为它是 32 位、能表示到 $2^{32}$ 这个量级，这直接决定了数组的最大容量。

       * 对象头合起来 $8 + 4 + 4 = 16$ 字节；数据部分每个 `int` 元素 4 字节且紧挨着存；最后还要补**对齐字节**，因为 Java 里对象大小必须是 8 字节的整数倍。

```text
+----------------------------+  offset
|  mark word            8 B  |   0
+----------------------------+   8
|  class pointer        4 B  |   8
|  length               4 B  |  12
+----------------------------+  16   <- 对象头 16 字节
|  a[0] = 1             4 B  |  16
|  a[1] = 2             4 B  |  20
|  a[2] = 3             4 B  |  24
|  a[3] = 4             4 B  |  28
|  a[4] = 5             4 B  |  32
+----------------------------+  36   <- 数据 5 x 4 = 20 字节
|  padding              4 B  |  36   <- 补齐到 8 的整数倍
+----------------------------+  40   总计 40 字节
```

   * **随机访问为什么是常数**

       * > **定义**：**随机访问** 指按索引查元素；叫随机是因为知道了索引就等于知道了地址。

       * 把索引代进地址公式一步算出位置，跟数组里有多少个元素、数据规模多大一点关系都没有；一个一万个元素或一个亿个元素，公式一算就出来了。

       * > **结论**：数组随机访问的时间复杂度是常数 $O(1)$。

       * 这里讨论的是**大小固定的数组**，它压根就不能删除元素、也不能添加元素，创建时大小就固定死了。

## 动态数组

   * **静态数组与动态数组**

       * > **定义**：Java 自带的数组不能插入、不能删除、大小在创建时就固定死了，这种叫**静态数组**；能插入或删除元素、且大小可以按实际需要发生变化的叫**动态数组**。

       * > **提示**：Java 里最熟悉的动态数组是 `ArrayList`，不过现在是在学数据结构，所以自己动手实现一个。

   * **`size`：逻辑大小**

       * > **定义**：`size` 叫**逻辑大小**，代表动态数组里**有效的元素个数**。

       * 刚创建时它是 0，表示还没管理任何元素；此时图上明明画着一堆格子，但它们全是无效的、不能使用。

       * 添加元素 `size` 增大，删除元素 `size` 缩小；添加 `1 2 3 4 5` 五个元素之后 `size` 变成 5，后面几个灰色的无效、访问不得。

       * 删除索引 2 的元素 `3` 时，要**保证数组元素的连续性**，所以 4 和 5 必须往前移一格，4 去顶替原来 3 的位置，最后 `size` 减一。

       * > **结论**：`size` 就是数组内有效元素个数的唯一裁判，有 `size` 在手，那些「物理上存在但逻辑上无效」的格子就永远访问不到。

   * **容量与扩容**

       * 容量是动态数组将来可以放的元素个数，示例里是 8；加 `6 7 8 9` 都没问题，加到第 10 个元素的时候放不下了。

       * > **定义**：**扩容** 说穿了就是造一个更大的数组出来，把旧数组的元素复制过去，让新数组顶替旧数组，最后把刚才放不下的那个元素写进新数组。

       * > **结论**：要实现的清单是插入元素、删除元素、扩容；前两个操作都要顺带管理逻辑大小 `size`，第三个是在预设容量不够时扩大容量。

```text
[1][2][3][4][5][6][7][8]       容量 8 装满了，第 10 个放不下
        |
        | 1. 创建一个容量更大的新数组
        v
[1][2][3][4][5][6][7][8][ ][ ][ ]...
        |
        | 2. 把旧数组里的元素复制到新数组
        v
[1][2][3][4][5][6][7][8][ ][ ][ ]
        |
        | 3. 用新数组顶替旧数组，再把 10 写进去
        v
[1][2][3][4][5][6][7][8][10]
```

   * **三个属性与初值**

       * 底层静态数组：名字虽然叫动态数组，底层为了存储元素内容还是需要一个静态数组；第一个属性先简单点，就搞一个 `int` 数组，只存数字。

       * `size`：逻辑大小，控制数组内有效元素的个数，初值 0，表示还没有有效元素。

       * `capacity`：容量，初值给 8；底层静态数组给一个同等容量的空数组。

       * 创建出空数组之后这些元素都被初始化成了 0，值是什么无所谓——只要 `size` 在控制，就访问不到这些无效元素。

   * **`addLast`：往最后一格写**

       * > **定义**：新增的元素作为**最后一个**加进动态数组，最后的位置就是 `size`。

       * `size = 0` 时最后的索引是 0，把新元素加到索引 0；再加第二个时 `size = 1`，就加到索引 1。

```java
public void addLast(int element) {
    array[size] = element;
    size++;
}
```

   * **`add(index, element)`：先把后队整体后移**

       * 往数组内**某一个索引位置**插入新值，原来该索引之后的所有元素向后移一位；例如 `1 2 3 4 5` 在索引 2 插入 6，最终是 `1 2 6 3 4 5`。

       * 用 `System.arraycopy` 把从 `index` 开始的所有元素右移一格，拷完索引 2 空出来，写入 `element`，最后 `size++`。

       * 参数一源数组就是我们这个 `array`；参数二从哪开始拷贝，从 `index` 开始；参数三拷到哪去，还在同一个数组内所以还是 `array`；参数四目标起始位置是 `index + 1`；参数五拷几个，`size` 是 5、`index` 是 2 所以 $5 - 2 = 3$。

```text
size = 5, array = [1][2][3][4][5], index = 2, element = 6

System.arraycopy(array, index, array, index + 1, size - index);
                    |        |         |              |
                 源数组    源起始位   目标数组      目标起始位  拷贝个数
                              2                   3         5 - 2 = 3

  before:  [1][2][3][4][5]
                    ~~~ 这三个（3 4 5）整体后移一格 ~~~
  after:   [1][2][ ][3][4][5]
                   ^ 索引 2 空出来了
  final:   [1][2][6][3][4][5]      size = 6
```

       * > **易错点**：`arraycopy` 的源区间和目标区间**是重叠的**（源从 `index` 起、目标从 `index + 1` 起），但它按元素个数一次性搬运、底层处理得对，不会边搬边覆盖；写成逐个倒序赋值当然也对，只是又慢又啰嗦。

       * > **提示**：`System.arraycopy` 能实现数组间或者数组内元素的拷贝复制，插入、扩容都靠它搬数据。

   * **`index` 到底能取多大**

       * 小于 0：压根不在数组里，不行。

       * 等于 `size`：可以，这种情况跟 `addLast` 是一回事，把它作为最后一个元素加进去。

       * 大于 `size`：不行，新加的元素跟前面有效的元素**断开了**，中间不能断，必须保证新加的元素跟原来的元素都连在一起。

       * > **结论**：`add` 真正能覆盖的合法区间是 $[0, size-1]$，再加上「等于 `size`」这个尾插特例。

   * **合并：`addLast` 就是 `add(size, …)`**

       * 既然两个方法有重叠，就给 `add` 多加一个 `else if`，判断 `index == size` 时执行 `addLast` 的逻辑。

       * 把代码搬过来会发现：既然进了这个分支 `index` 必然等于 `size`，里面写的 `array[index]` 可以直接用 `array[size]`，而这跟 `if` 分支里那两行一模一样；既然一模一样就没必要关在 `if` 里面，干脆抽出来放到 `if` 外面。

       * `else if` 跟着没了，现在的 `add` 同时处理范围内插入与尾插两种情况，反正都要写元素、都要 `size++`，统一放外面执行。

```java
public void add(int index, int element) {
    if (index >= 0 && index < size) {
        System.arraycopy(array, index, array, index + 1, size - index);
    }
    array[index] = element;
    size++;
}

public void addLast(int element) {
    add(size, element);
}
```

       * > **提示**：合并之后方法进来第一件事最好还是做一次 `index` 的合法性判断，小于 0 或大于 `size` 就直接报错，别让它往下执行。
