# 内部排序算法体系与复杂度下界

## 简单排序与相邻交换瓶颈

### 冒泡排序

* **冒泡排序（Bubble Sort）**

    * **定义**：通过自顶向下或自底向上依次比对相邻两元素，逆序则立即调换，每趟扫描将未排序区间的最大值（或最小值）沉底落位的相邻交换排序算法。

    * 机理：从待排区间起始位置开始，逐对比较相邻元素 $A[i]$ 与 $A[i+1]$；若 $A[i] > A[i+1]$ 则执行元素值交换，否则保持不动继续后移；第 $k$ 趟处理前 $N-k+1$ 个元素，使得当前未排序区间最大元落入目标终点。

    * 提前终止判定：引入整型标记变量 `flag`，每趟扫描前置 0；内层循环若触发任何一次交换则置 1；一趟结束若 `flag` 仍为 0，表明全序列所有相邻元素均满足 $A[i] \le A[i+1]$，算法立即退出。

    * 数值：最好时间复杂度为 $O(N)$（初始序列完全升序，首趟比对即触发 `flag == 0` 退出）；最坏时间复杂度为 $O(N^2)$（初始序列完全逆序，必须走满完整的 $N-1$ 趟且每步均发生交换）；平均时间复杂度为 $O(N^2)$；额外辅助空间复杂度为 $O(1)$。

    * 边界：单向链表适用性极高，算法全程仅需单向顺序扫描并操作相邻节点，不依赖数组随机访问与逆向寻址能力。

    * 规则：满足稳定性要求，仅在 $A[i] > A[i+1]$ 时触发对调，键值相同的元素绝不交换，相对先后次序保持不变。

    * 运行常数对比：两两交换需要借助中间变量执行三次赋值操作，内层循环指令开销较大，实测运行耗时通常明显高于插入排序。

### 插入排序

* **插入排序（Insertion Sort）**

    * **定义**：将待排序列划分为前部已排序区间与后部未排序区间，依次摸入未排序区间的首个元素并逆向比对已排序序列，单步后移较大手牌腾出空位以完成落位的排序算法。

    * 机理：外层游标 $P$ 从下标 1 递增至 $N-1$；临时变量 `Tmp = A[P]` 暂存待插入项并留出逻辑空位；内层游标从 $P-1$ 开始向左比对，凡满足 $A[i-1] > \text{Tmp}$ 的已有元素均向后复制一位（`A[i] = A[i-1]`），直至遭遇不大于 `Tmp` 的元素或抵达数组左边界，随后执行 `A[i] = Tmp` 一次性就位。

    * 数值：最好时间复杂度为 $O(N)$（初始序列升序，新元素与手牌最右端比对一次即停止）；最坏时间复杂度为 $O(N^2)$（完全逆序，总后移次数严格为 $\sum_{P=1}^{N-1} P = \frac{N(N-1)}{2}$）；平均时间复杂度为 $O(N^2)$；额外空间复杂度为 $O(1)$。

    * 精确复杂度模型：$T(N, I) = O(N + I)$，其中 $N$ 为线性扫描基准开销，$I$ 为输入序列包含的逆序对总数；当待排序列基本有序（$I = O(N)$）时，算法实际运行性能接近线性阶。

    * 规则：满足稳定性要求，逆向扫描比对条件采用严格大于（`A[i-1] > Tmp`），遇相等元素立即停止后移并将新牌置于相同元素之后。

    * 常数优势：内层循环仅需单次向后复制赋值，无需中间变量执行三次置换赋值，相较冒泡排序常数项显著精简。

### 逆序对与相邻交换复杂度下界

* **逆序对（Inversion）**

    * **定义**：对于待排序列中任意一对下标满足 $i < j$ 但对应元素满足 $A[i] > A[j]$ 的二元组 $(A[i], A[j])$。

    * 相邻交换单步定理：任意一次相邻元素的直接交换操作，至多且只能恰好消除 1 个逆序对。

    * 证明机理：对于包含相邻元素对 $(A[i], A[i+1])$ 的序列，若 $A[i] > A[i+1]$，对调两者后该逆序对被消除；对于任意处于该对外部的元素 $A[k]$（无论 $k < i$ 还是 $k > i+1$），交换前后 $A[k]$ 与 $A[i]$ 及 $A[i+1]$ 的相对先后位置与大小关系均未发生改变，外部逆序对状态保持守恒。

    ```text
    考虑序列中的三个相邻元素: [ ... A[i], A[i+1] ... ]
    情况一: A[i] > A[i+1]，构成一个逆序对。
    交换两者后变为:           [ ... A[i+1], A[i] ... ]
    结论: 外部元素相对次序与大小完全不变，单次相邻交换最多且只能消除 1 个逆序对。
    ```

    * 相邻交换总步数下界：若输入序列初始存在 $I$ 个逆序对，任何仅依靠交换相邻两元素的排序算法，使序列达到完全有序（逆序对总数归零）所必须执行的最少交换次数严格等于 $I$。

    * 随机排列平均逆序对数：$N$ 个互异元素的序列共有 $\binom{N}{2} = \frac{N(N-1)}{2}$ 对相对位置关系；对于任意排列 $L$ 及其反序排列 $L_R$，在 $L$ 中为正序的对在 $L_R$ 中必定为逆序对，故两排列逆序对数之和为 $\frac{N(N-1)}{2}$；全部随机排列中平均逆序对数为 $I_{avg} = \frac{N(N-1)}{4} = O(N^2)$。

    * 相邻交换平均复杂度定理：任何仅依靠相邻元素交换来实现的排序算法，其平均时间复杂度下界为 $\Omega(N^2)$。

    * 复杂度破局方向：要突破平方时间阶门槛，必须打破相邻交换限制，允许相隔较远距离的元素进行跨越式跳跃交换，使单次交换波及中间元素并批量消除多个逆序对。

## 希尔排序与增量序列

### 希尔排序间隔机制

* **希尔排序（Shell Sort）**

    * **定义**：利用给定的递减正整数序列作为步长间隔，依次对相隔步长的子序列执行插入排序，逐步建立多层局部有序并最终以步长 1 收尾的跨距离跳跃排序算法。

    * 增量序列结构：递减正整数序列满足 $D_M > D_{M-1} > \dots > D_1 = 1$；算法共执行 $M$ 趟排序，每趟选取增量 $D_k$ 进行“$D_k$-间隔排序”（$D_k$-sorting）。

    * 间隔排序保持性定理：一个已达到 $D_k$-间隔有序的序列，在经过后续更小增量 $D_{k-1}$ 的间隔排序之后，仍然严格保持原有的 $D_k$-间隔有序性，前序整理成果不会被后序操作破坏。

    * 算法实现：外层循环推进增量递减；内层以 $D$ 为步长执行插入排序，游标从 $P = D$ 扫描至 $N-1$，暂存 `Tmp = A[P]` 后，将左侧相隔 $D$ 且大于 `Tmp` 的元素逐级向后移动 $D$ 个位置。

    * 稳定性：不稳定，远距离跨步长跳跃交换会打乱键值相同的元素在数组中的原有先后相对次序。

    * 空间复杂度：严格原地工作，额外辅助空间复杂度为 $O(1)$。

### 原始增量的退化与互质增量优化

* **希尔原始增量（Shell's Increment）**

    * **定义**：以数组长度的一半为初值，各趟之间采用连续整除折半递推的增量选取方案：$D_M = \lfloor N/2 \rfloor, D_k = \lfloor D_{k+1}/2 \rfloor, \dots, D_1 = 1$。

    * 数值：使用原始增量序列的希尔排序在最坏情况下的时间复杂度为 $\Theta(N^2)$。

    * ⚠️ **易错点**：原始折半增量各元素之间互不质因子独立（如 8 是 4 的倍数、4 是 2 的倍数），导致所有子序列相互隔离；在偶数位置为小数、奇数位置为大数的病态数据下，前序所有远距离排序均为空跑，所有逆序对被全量堆积至 $D_1 = 1$ 的最后一趟，退化为纯相邻插入排序。

* **互质增量序列（Coprime Increments）**

    * **定义**：增量序列中相邻或相关元素互质的增量设计，旨在使各趟排序覆盖的元素网格充分交叠交叉比对。

    * Hibbard 增量公式与性能：定义为 $D_k = 2^k - 1$（取值如 $1, 3, 7, 15, \dots$）；最坏时间复杂度为 $\Theta(N^{3/2})$，猜想平均时间复杂度为 $O(N^{5/4})$。

    * Sedgewick 增量公式与性能：定义为交叉取值公式 $9 \times 4^i - 9 \times 2^i + 1$ 或 $4^i - 3 \times 2^i + 1$（取值如 $1, 5, 19, 41, 109, \dots$）；最坏时间复杂度为 $O(N^{4/3})$，猜想平均时间复杂度为 $O(N^{7/6})$。

    * 工程表现：处理规模在数万（$10^4 \sim 10^5$ 级别）范围内的数据集时，采用 Sedgewick 增量的希尔排序实测运行速度通常超越诸多平均复杂度为 $O(N \log N)$ 的复杂算法。

## 堆排序与原地选择机制

### 选择排序瓶颈与堆优化

* **简单选择排序（Selection Sort）**

    * **定义**：每趟在未排序区间中线性扫描定位最小（或最大）元，将其与未排序区间首元素进行远距离交换的排序算法。

    * 交换与比较开销：外层循环固定迭代 $N-1$ 次，元素物理交换次数为严格的 $O(N)$；但定位最值的 `ScanForMin` 线性扫描开销无可避免，总比较次数在最好、最坏及平均情况下均钉死在 $\Theta(N^2)$。

    * 稳定性：不稳定，远距离跨区间交换会越过相同大小的元素并改变其相对次序。

    * 瓶颈突破方向：利用优先队列数据结构（二叉堆）替代线性扫描，将获取最值的单步代价从 $O(N)$ 压降至 $O(\log N)$。

### 最大堆原地排序与零基索引

* **堆排序（Heap Sort）**

    * **定义**：利用最大堆数据结构在原物理数组上组织数据，通过反复将堆顶最大元交换至当前堆底并执行下滤调整，在无外部辅助空间前提下实现升序排列的原地排序算法。

    * 升序对应堆类型规则：从小到大升序排序必须使用**最大堆**；若使用最小堆则弹出最小值必须存入外部数组，无法达成 $O(1)$ 原地空间指标。

    * 原地收缩机理：首先对输入数组建立最大堆；随后循环将堆顶最大元素 $A[0]$ 与当前堆尾元素 $A[i]$ 对调，并将堆有效规模减 1（锁定末尾已排定最大元）；接着对下标 0 处的新堆顶执行下滤恢复最大堆；循环 $N-1$ 轮后全序列完全有序。

    ```text
    建立好的最大堆:       [ 最大元 D | 堆内其他元素 ... | 堆尾元素 A ]
    步骤 1: 交换堆顶与堆尾 -> [ 元素 A   | 堆内其他元素 ... | 最大元 D (落位) ]
    步骤 2: 堆规模减 1    -> [ 元素 A   | 堆内其他元素 ... ] | 锁定: [ D ]
    步骤 3: 堆顶下滤恢复  -> [ 次大元 C | 堆内其他元素 ... ] | 锁定: [ D ]
    结论: 堆有效区间向左收缩，有序序列向左延伸，共享同一物理数组。
    ```

    * 零基索引平移关系：
        * 节点 $i$ 的左孩子下标为 $2i + 1$；
        * 节点 $i$ 的右孩子下标为 $2i + 2$；
        * 节点 $i$ 的父节点下标为 $(i - 1) / 2$；
        * 最后一个非叶子节点下标为 $\lfloor N/2 \rfloor - 1$。

    * 数值：建堆耗时为线性阶 $O(N)$；执行 $N-1$ 次交换与下滤耗时 $O(N \log N)$；堆排序在最好、最坏以及平均情况下时间复杂度均为 $O(N \log N)$；额外辅助空间复杂度严格为 $O(1)$。

    * 平均比较次数：处理 $N$ 个互异元素的随机排列时，平均比较次数约为 $2N \log N - O(N \log \log N)$。

    * 稳定性：不稳定，建堆下滤与堆顶堆尾交换过程中均会打乱同值元素的相对位置。

    * 硬件缓存劣势：父子节点下标跨度较大，指针跳跃式内存访问破坏了现代 CPU 缓存（Cache）局部性原则，实际 CPU 运行时间常数偏大，通常逊于快速排序与精选增量的希尔排序。

## 归并排序与分治策略

### 有序子列归并与递归实现

* **归并操作（Merge）**

    * **定义**：利用三个游标指针并行比对两个物理相邻且内部各自有序的子序列，将较小元依次录入目标缓冲数组，并将剩余段全量倾倒合并为单一完整有序序列的线性操作。

    * 逆向倒回技巧：归并比对过程中左边界游标 `L` 被连续递增修改，而右边界终点 `RightEnd` 自始至终保持不变；因此在将临时数组 `TmpA` 的归并结果倒回原数组 `A` 时，采取以 `RightEnd` 为基准逆向倒数 `NumElements` 次的写入方式，避免下标越界与初始起点丢失。

    * 递归分治模型（MSort）：
        * 分（Divide）：计算中点 $\text{Center} = \lfloor (L + \text{RightEnd}) / 2 \rfloor$；
        * 治（Conquer）：递归调用对左半段 $[L, \text{Center}]$ 及右半段 $[\text{Center} + 1, \text{RightEnd}]$ 独立排序；
        * 合（Combine）：调用 `Merge` 将左右两段合并；
        * 递归终止条件为 $L == \text{RightEnd}$（单元素天然有序）。

    * 复杂度与性质：递推式为 $T(N) = 2T(N/2) + O(N)$；在最好、最坏及平均情况下时间复杂度均稳定为 $O(N \log N)$；双指针比对时使用小于等于判断（`A[L] <= A[R]`）使得同值元素优先输出左子列项，算法满足严格**稳定**性。

    * ⚠️ **易错点**：辅助数组 `TmpA` 严禁在 `Merge` 函数内部随用随开（局部频繁 `malloc` 与 `free`），否则在整个递归树上将触发 $N-1$ 次堆内存分配与释放，引发巨大系统开销与内存碎片；必须在最外层包装接口 `Merge_Sort` 处一次性动态申请大小为 $N$ 的连续空间，将指针传入递归体系全程复用，任务结束时统一释放。

### 非递归迭代归并与双缓冲机制

* **非递归归并排序（Iterative Merge Sort）**

    * **定义**：摒弃自顶向下的递归函数调用栈，从步长为 1 的单元素有序段起步，自底向上成对倍增合并子序列直至全数组有序的迭代归并算法。

    * 双缓冲交替机制：外层分配一个与原数组等长的辅助空间 `TmpA`，原数组 `A` 与 `TmpA` 互为输入源与输出目标交替倒腾，将额外空间复杂度严格控制在 $O(N)$，杜绝每层开辟新数组导致的 $O(N \log N)$ 空间膨胀。

    * 一趟归并（Merge_pass）尾部边界处理规则：
        * 成对完整子列推进条件：循环控制边界为 $i \le N - 2 \cdot \text{length}$，步长每次递增 $2 \cdot \text{length}$；
        * 尾部余两段情形：若跳出后满足 $i + \text{length} < N$，说明剩余两个子序列（后一段长度不足 `length`），调用归并函数将两段合并至 $N-1$；
        * 尾部余一段情形：若跳出后满足 $i + \text{length} \ge N$，说明仅剩单个孤立子列，通过单循环直接将其原样拷贝至目标数组。

    ```text
    情形一 (i + length < N):
    [...已处理完整成对...] | [ 长度为 length ] [ 长度不足 length ] (归并最后两段)
                           ^                 ^                 ^
                           i             i+length            N-1

    情形二 (i + length >= N):
    [...已处理完整成对...] | [ 仅剩一段，长度不足或等于 length ]    (直接复制到 TmpA)
                           ^                                 ^
                           i                                N-1
    ```

    * 双步打包调用技巧：外层 `while (length < N)` 循环内成对调用两次 `Merge_pass`；首步将数据由 `A` 归并至 `TmpA` 且 `length *= 2`，次步紧接着由 `TmpA` 归并回 `A` 且 `length *= 2`；该设计在代数上硬性保证循环退出时最终有序数据必然稳稳驻留在原数组 `A` 中，省去判定输出落点的额外分支。

    * 适用边界：由于存在 $O(N)$ 辅助空间开销及内存间频繁数据搬运，在内存容量充裕的通用内排序中较少作为首选；在海量数据无法一次性装入内存的外排序（External Sorting）体系中为核心基础架构。

## 快速排序与基准划分策略

### 主元选取与三数中值法

* **快速排序（Quick Sort）**

    * **定义**：基于分治思想，通过选取基准主元将待排序列划分为左小右大两个独立子集，并在单趟处理中将主元一次性锁定到全局最终正确位置的递归排序算法。

    * 最优递推条件：每次划分的主元均恰好位于当前序列正中央，将问题平分为等规的两半，递推式为 $T(N) = 2T(N/2) + O(N)$，时间复杂度达到最优的 $O(N \log N)$。

    * ⚠️ **易错点**：固定选取首元素 `A[0]` 作为主元是极度脆弱的策略；当输入序列初始完全有序或逆序时，单趟划分耗费 $O(N)$ 却只能切出包含 0 个与 $N-1$ 个元素的极度偏斜子集，递归树退化为单支链，运行时间恶化为最坏的 $O(N^2)$。

    * 随机选取开销：调用系统随机数发生器 `rand()` 会引入较大的时间与指令消耗，不适合高频内层排序。

* **三数中值法（Median-of-Three）**

    * **定义**：提取待排区间左端 `Left`、中央 `Center` 和右端 `Right` 三处元素，经三次条件置换使其局部有序，并取居中元素作为主元的枢轴选取方案。

    * 三步排序规则：
        * 若 $A[\text{Left}] > A[\text{Center}]$，交换两者；
        * 若 $A[\text{Left}] > A[\text{Right}]$，交换两者，确保三者最小值锁定于 `Left`；
        * 若 $A[\text{Center}] > A[\text{Right}]$，交换两者，确保三者最大值锁定于 `Right`，中位数锁定于 `Center`。

    * 藏主元操作：将居中主元与倒数第二个元素交换（`Swap(&A[Center], &A[Right - 1])`）；由于 `Left` 处的最小值天然属于合规左子集，`Right` 处的最大值天然属于合规右子集，双指针扫描的有效区间被收敛精简为 $[Left + 1, Right - 2]$。

### 双指针子集划分与相等元素处理

* **双指针子集划分（Partitioning）**

    * **定义**：利用对向游标指针向中央交替推进，将错放至左右子集的异位元素对进行置换，并在相遇后将主元换回相交分界点的就地分割过程。

    * 对向推进机制：指针 $i$ 从左向右扫描，遇到不小于主元的元素立即停步；指针 $j$ 从右向左扫描，遇到不大于主元的元素立即停步；若 $i < j$ 则交换 $A[i]$ 与 $A[j]$ 并继续推进；若 $i \ge j$ 则循环终止，最后执行 `Swap(&A[i], &A[Right - 1])` 将主元准确落入其全局绝对位置。

    * 单次归位特性：主元一旦经历一趟子集划分并落位，该位置即为其最终有序输出时的固定槽位，后续所有递归治理步骤中永不再参与移动。

    * ⚠️ **易错点**：面对待排序列所有元素完全相等的极端用例，双指针扫描遭遇与主元相等的元素必须**停步并执行交换**。停步交换虽然会触发若干次冗余置换，但能迫使双指针以均等速度收缩并在序列正中相遇，将区间均等切半以守住 $\log N$ 递归深度与 $O(N \log N)$ 理论底线；若视而不见直接跳过，左指针将无阻碍直冲右端点，直接堕入最坏的 $O(N^2)$ 退化。

### 截断阈值与混合排序

* **截断阈值（Cutoff）**

    * **定义**：快速排序中设定的子序列临界长度阈值；当递归子区间跨度小于该阈值时，程序主动放弃快排递归，转而直接调用简单插入排序处理局部区间的混合算法策略。

    * 机制依据：快速排序高度依赖函数运行时调用栈，涉及繁杂的断点保护、参数压栈出栈等环境常数开销；当子序列规模缩减至数十至上百微型区间时，递归常数损耗压倒分治算法优势，此时直接插入排序实际执行耗时更为轻巧高效。

    * 数值：工程阈值 `Cutoff` 通常预设在 100 左右（或由具体硬件平台基准测试调优确定）。

    * 复杂度与特性：快速排序平均时间复杂度为 $O(N \log N)$，最坏为 $O(N^2)$；函数调用栈在平均情况下消耗 $O(\log N)$ 辅助空间，最坏情况下消耗 $O(N)$；算法为**不稳定**排序；综合实测运行时间常数在所有内部排序算法中最小，为实际工程首选。

## 表排序与物理重排

### 表排序与间接排序机制

* **表排序（Table Sort）**

    * **定义**：针对庞大体积实体数据项，物理实体在内存中保持静止，仅建立并操作下标或指针数组进行比较与逻辑重排的间接排序（Indirect Sorting）技术。

    * 机制：初始化长度为 $N$ 的指针向量 $\text{Table}[i] = i$；排序全程所有元素比对均通过 $A[\text{Table}[i]]$ 进行间接读取，所有位置调换仅在 `Table` 数组内部置换整数下标，庞大结构体或多媒体实体在内存中物理位置始终不变。

    * 零开销输出条件：若应用场景仅要求按升序输出数据序列（如打印日志、网络序列化推流），直接遍历 `Table` 依次访问物理数据即可，实体物理移动开销严格为 0。

### 置换独立环与物理重排

* **置换独立环（Disjoint Cycles）**

    * **定义**：有限集合中任意一个元素下标置换映射，在代数上必然可以唯一分解为若干个互不相交、首尾闭合的独立轮换置换结构。

    ```text
    环 1 (四元环):
    [ 0 ] ---> Table[0] = 3 ---> Table[3] = 1 ---> Table[1] = 5 ---> Table[5] = 0 (闭合回归)

    环 2 (一元自环):
    [ 2 ] ---> Table[2] = 2 (原本就在正确位置，无需移动)

    环 3 (三元环):
    [ 4 ] ---> Table[4] = 7 ---> Table[7] = 6 ---> Table[6] = 4 (闭合回归)
    ```

    * 空托盘接力物理重排机理：
        * 外层扫描遍历下标 $i$：若 $\text{Table}[i] == i$ 则表明属于一元自环，该位置已自然有序，跳过；
        * 若 $\text{Table}[i] \neq i$，开启新环：暂存起点实体 `Tmp = A[i]`，腾出空位 $p = i$；
        * 循环索取填补：查表得 $\text{next} = \text{Table}[p]$，将后继实体复制至当前空位（`A[p] = A[next]`），并将已归位表项就地打上自环标记（`Table[p] = p`），指针前移 $p = \text{next}$；
        * 环路闭合就位：当追溯到目标位置满足自环（回到起点）时，将暂存的 `Tmp` 注入最终空位，并完成该独立环的标记重置。

    * 数值与复杂度界限：
        * 最好情况：原始数据物理已有序，全部分解为一元自环，实体物理搬运次数严格为 0；
        * 最坏情况：整个置换被粉碎为 $N/2$ 个二元环；处理每个二元环需执行 3 次实体赋值（提取起点、目标平移、写回暂存）；全表物理搬动次数上限为 $\frac{N}{2} \times 3 = 1.5N$ 次；
        * 耗时分析：设单个庞大结构体物理拷贝耗时为常数 $m$，物理重排在最坏情况下时间复杂度为 $O(m \cdot N)$，严格保持在线性阶。

## 桶排序与基数排序

### 桶排序机制与性能边界

* **桶排序（Bucket Sort）**

    * **定义**：为待排关键字的每一个可能取值独立设立一个链表容器（桶），通过一次线性扫描将数据直接映射入桶，再按桶固有序号顺次收集输出的非比较排序算法。

    * 机理：声明包含 $M$ 个桶头指针的数组 `Count` 并置空；遍历 $N$ 个数据项，以关键字为下标直接索引对应的桶头，利用单链表头插法入桶（耗时 $O(N)$）；分配完成后按下标 $0$ 至 $M-1$ 顺序扫描各桶，依链表依次串联输出（耗时 $O(M + N)$）。

    * 数值模型：$T(N, M) = O(M + N)$。

    * 适用条件与边界：当键值可能取值范围 $M$ 远小于数据总规模 $N$（即 $M \ll N$）时，项 $M$ 在渐进分析中可被忽略，算法呈现严格线性时间复杂度 $O(N)$。

    * 退化缺陷：若取值范围 $M \gg N$（如 10 个数据取值在 $0 \sim 999$ 之间，$M=1000 \approx N^3$），算法开销被顺序扫描大量空桶所支配，导致运行效率急剧退化。

### 基数排序与多关键字策略

* **基数排序（Radix Sort）**

    * **定义**：将待排数据按进位基数 $B$ 解构为多位并列码元，固定设立 $B$ 个桶，通过多轮交替的数位分派与收集串联实现整体有序的进阶桶排序算法。

    * 派系分类：
        * 次位优先（Least Significant Digit first, LSD）：从数位的最次位（个位）起始向高位推进，最后在主位（最高位）完成排序；
        * 主位优先（Most Significant Digit first, MSD）：从数位的主位（最高位）起始分流至各子桶，各桶内部再递归处理次高位。

    * LSD 运作机理与稳定性关联：各趟按当前位取值入桶，入桶过程严格遵循先进先出（FIFO）排队原则以维系算法稳定性；一趟收集后数据在低位维度已有序；在后续高位分配中，高位相同的元素其低位先后顺序得以被完好继承。

    * 数值模型：设数据规模为 $N$，数制基数为 $B$，数位总趟数为 $P = \lceil \log_B(\text{Key}_{\max} + 1) \rceil$；每趟分配耗时 $O(N)$，收集串联耗时 $O(B)$；全流程执行 $P$ 趟，总时间复杂度为 $O(P(N + B))$；额外空间复杂度为 $O(N + B)$。

* **多关键字排序（Sorting on Multiple Keys）**

    * **定义**：待排对象由多个主次层级清晰的分量关键字复合构成的排序模型。

    * 扑克牌整理策略对比（主关键字为 4 种花色，次关键字为 13 种面值）：
        * MSD 策略：先按 4 种花色建立大桶进行物理分流，随后在各桶内部必须单独调用其他传统排序算法整理面值，最后合并；
        * LSD 策略：先为主关键字的次位（13 种面值）建 13 个桶并依次收集，随后直接为主位（4 种花色）建 4 个桶分装并收集；在第二趟入花色桶过程中完全无需执行桶内面值比对，自然呈现完全有序。

    * 策略边界取舍：LSD 适合规整固定位长的数字或扑克牌排序；在处理超长且长度参差不齐的字符串集合时，MSD 可借由前缀字符迅速将数据切分进极小子集并提前终止非交叠分支，具备针对性剪枝优势。

## 内部排序算法综合权衡

### 基于比较排序的复杂度理论下界

* **比较排序复杂度下界定理**

    * **定理**：任何完全依赖于两两比对元素关键字相对大小来进行决策的内部排序算法，在最坏情况下的时间复杂度渐进下界必然为 $\Omega(N \log N)$。

    * 理论边界：冒泡排序、直接插入排序、简单选择排序、希尔排序、堆排序、归并排序与快速排序均受制于比较下界；要突破该下界跑出真正的线性阶 $O(N)$，必须放弃单纯两两比对，转而利用键值内在分布规律与数位空间映射。

### 常见内部排序算法全景对比

* **核心算法性能与特征汇总**

    | 排序算法 | 平均时间复杂度 | 最坏时间复杂度 | 额外空间复杂度 | 稳定性 | 算法特征与适用场景 |
    | :--- | :--- | :--- | :--- | :--- | :--- |
    | **冒泡排序** (Bubble Sort) | $O(N^2)$ | $O(N^2)$ | $O(1)$ | 稳定 | 相邻元素两两比对交换；对单向链表友好；效率低下 |
    | **直接插入排序** (Insertion Sort) | $O(N^2)$ | $O(N^2)$ | $O(1)$ | 稳定 | 逐个插入有序前缀；基本有序或小规模数组性能优异 |
    | **简单选择排序** (Selection Sort) | $O(N^2)$ | $O(N^2)$ | $O(1)$ | 不稳定 | 跨区间寻找最值并跳跃交换；交换开销小但比较死锁 |
    | **希尔排序** (Shell Sort) | $O(N^d) \ (1 < d < 2)$ | $O(N^2)$ | $O(1)$ | 不稳定 | 突破平方下界先驱；效率取决于增量互质程度；数万数据下强悍 |
    | **堆排序** (Heap Sort) | $O(N \log N)$ | $O(N \log N)$ | $O(1)$ | 不稳定 | 原地排序理论上下界稳定；父子节点跳跃访问破坏缓存局部性 |
    | **归并排序** (Merge Sort) | $O(N \log N)$ | $O(N \log N)$ | $O(N)$ | 稳定 | 严格稳定；辅助空间开销大且内存搬移多；外排序绝对主力 |
    | **快速排序** (Quick Sort) | $O(N \log N)$ | $O(N^2)$ | $O(\log N)$ | 不稳定 | 递归栈空间耗费；内层循环紧凑且缓存局部性好；工程综合最快 |
    | **基数排序** (Radix Sort) | $O(P(N + B))$ | $O(P(N + B))$ | $O(N + B)$ | 稳定 | 空间换时间突破比较下界；依赖先进先出队列与键值数位长度 |

* **工程权衡核心技术洞察**

    * 稳定性内在分水岭：仅发生相邻元素比对挪动的算法（冒泡、直接插入）天然保持稳定性；凡包含跨越式跳跃交换的算法（简单选择、希尔、堆、快速）必然破坏稳定性；归并排序取等号靠左保证稳定性；基数排序依赖队列式先进先出保证稳定性。

    * 空间代价梯度：冒泡、直接插入、简单选择、希尔与堆排序为严格的原地排序（$O(1)$ 空间）；快速排序递归栈在平均状态下消耗 $O(\log N)$ 空间；归并排序必须开辟与输入等长的 $O(N)$ 辅助缓冲区；基数排序需要额外维护包含 $B$ 个指针头与数据链表节点的辅助容器。

    * 理论渐进与物理架构差异：堆排序虽然拥有理论上完美的 $O(N \log N)$ 渐进上下界且空间为 $O(1)$，但由于数组下标按倍数跳转访问，显著破坏 CPU 缓存行（Cache line）命中率；快速排序依靠紧凑的双指针局部线性扫描，硬件缓存预取命中率极高，实际运行常数在所有通用内部排序中最小。

## 散列查找与冲突处理

### 散列查找哲学与散列表模型

* **散列法（Hashing）**

    * **定义**：直接依据记录的关键字，通过确定的映射函数直接计算出对应的存储内存物理地址（或数组下标），从而跳过关键字两两比对过程实现记录直接访问的查找技术。

    * 哲学演进：传统查找手段（顺序查找 $O(N)$、二分查找动态维护开销大、AVL 树在字符串关键字上逐字比较昂贵）均受困于“两两比对”；散列查找跳过比对，以确定函数直接完成“空间寻址”，将平均查找时间压缩至常数阶 $O(1)$。

    * 核心支柱：
        * 构造高效均匀的散列函数；
        * 制定完备稳健的冲突解决策略。

    * 术语定义：
        * **散列表（Hash Table）**：用于存放记录的连续物理存储空间（一维数组）；
        * **冲突 / 碰撞（Collision）**：不同的关键字经过散列函数计算后得出了完全相同的存储地址；
        * **同义词（Synonyms）**：映射到同一散列地址的多个不同关键字彼此互称同义词。

    * **装填因子（Loading Factor）**

        * **定义**：散列表中已装入的元素总数与散列表物理空间容量的比值，记作 $\alpha = \frac{\text{表中填入的元素总数}}{\text{散列表的空间容量}}$。

        * 边界：$\alpha$ 较小时空槽位较多，冲突概率低但空间冗余浪费；$\alpha$ 过大时空间利用率高，但同义词冲突概率呈指数级攀升。

    * ⚠️ **易错点**：固定拓展单槽位容量（如采用 $M \times 2$ 的二维数组）无法根治冲突；当同义词数量超过预留列上限时仍会发生槽位溢出，必须依赖全局冲突应对体系。

    * 查找与删除边界：在仅有插入操作的散列表中，若按散列地址探查遇到空槽位，可直接断定目标关键字不存在；若系统允许物理删除，直接将槽位置空会阻断后续冲突链的连续探查，必须引入逻辑删除标记（懒惰删除）。

### 散列函数构造策略

* **数字关键字构造法**

    * **定义**：针对整型、电话号码、身份证等数值型关键字设计的地址映射计算法则。

    * 直接定址法：取关键字的线性函数值 $H(key) = a \cdot key + b$；无冲突且计算极微，适用于关键字连续且先验分布明确的场景；数据离散时会引发大面积内存空置。

    * 除留余数法：计算公式 $H(key) = key \bmod p$；参数选取规则为 $p \le \text{TableSize}$ 且 $p$ 优选素数（质数），有效避开因数据周期性公约数产生的大面积同义词堆积。

    * 数字分析法：对关键字各数位样本进行方差统计，剔除分布僵化位，仅抽取样本集合中变动波动剧烈、随机度高的数位组合为地址（如手机号后 4 位、身份证号中行政代码与出生日期的高离散尾数）。

    * 折叠法：将长数字切分成位数相等的若干短段（末段不足补零），将各短段数字重叠相加并舍弃最高进位，使长关键字的每一段均能间接渗透到最终地址中。

    * 平方取中法：将大整数自乘平方，借助乘法进位的全量扩散效应，截取平方计算结果正中央若干位作为散列地址，保证原数每一位均对结果产生影响。

* **字符串关键字多项式散列法**

    * **定义**：将变长字符串视为特定进制下的多项式展开，并利用位运算与秦九韶算法进行高效地址压缩的方法。

    * 朴素累加缺陷：简单将各字符 ASCII 码相加（$\sum str[i] \bmod \text{TableSize}$）对字符排列顺序彻底脱敏（如 `stop` 与 `post` 必撞），且 10 字符累加值域被锁死在 $[0, 1270]$ 狭窄区间，冲突率极高。

    * 多项式移位哈希（32 进制与霍纳法则）：将字符串视为基数 32 的多项式展开；选择 32 的依据在于 $32 = 2^5$，乘以 32 在 CPU 底层可被直接映射为单周期位运算左移 5 位（`h << 5`）；结合霍纳法则（Horner's Rule）递推实现如下：

    ```c
    Index Hash(const char *Key, int TableSize)
    {
        unsigned int h = 0;
        while (*Key != '\0') {
            h = (h << 5) + *Key++;
        }
        return h % TableSize;
    }
    ```

### 开放定址法冲突探测机制

* **开放定址法（Open Addressing）**

    * **定义**：发生冲突时不向外扩展外挂链表，而是依据固定的增量序列在散列表物理数组内部继续寻觅下一个可用空槽位的闭散列冲突处理机制。

    * 数学通式：第 $i$ 次冲突探测地址定义为 $H_i(key) = (H(key) + d_i) \bmod \text{TableSize}$，其中 $d_i$ 为探测增量序列。

* **线性探测法（Linear Probing）**

    * 增量模型：$d_i = i \ (i = 1, 2, \dots, \text{TableSize}-1)$。

    * 规则：发生碰撞后依次向右探查相邻槽位，遇末端则取余回绕至数组首部。

    * ⚠️ **易错点**：线性探测极易引发**一次聚集（Primary Clustering）**；不同散列地址的元素一旦被挤占到相邻格子即会连成连续占用块，后续新元素落入该区域任意位置均被迫沿着整个块一路探测到底，导致冲突发生率如滚雪球般失控恶化。

* **二次探测法（平方探测法，Quadratic Probing）**

    * 增量模型：$d_i = \pm i^2 \ (i = 1, 2, \dots)$，展开为 $+1^2, -1^2, +2^2, -2^2, +3^2, -3^2, \dots$。

    * 规则：发生碰撞后以原点为基准正负交替双向跳跃，所有计算越界偏移经取余操作收敛回合法区间；通过非线性跳跃离散化分布，打散连续占据块，根除一次聚集现象。

* **双散列法（Double Hashing）**

    * 增量模型：$d_i = i \times H_2(key)$；探测公式为 $H_i(key) = (H_1(key) + i \times H_2(key)) \bmod \text{TableSize}$。

    * 规则：$H_1(key)$ 决定起始探测地址，$H_2(key)$ 依据关键字本身动态计算单步跳跃跨度；使得即使在 $H_1$ 处发生碰撞的同义词，由于其步长不同而在后续探测轨迹上迅速分道扬镳。

    * 约束条件：$H_2(key)$ 的输出绝对不能为 0，且 $H_2(key)$ 的取值应与 `TableSize` 互质，以保证能够遍历全表可用槽位。
