# 图论高级算法：最短路、最小生成树与拓扑排序

## 最短路径算法

### Dijkstra 算法的松弛全流程

* **单源最短路径与算法定位**

    * > **定义**：从图中指定的一个固定源点出发，到达其余所有顶点的最短路径问题。前提条件是图中所有边的权重必须为非负数。

    * 算法基本思路与无权单源最短路一致，但松弛时必须带权累加。

* **初始化与外循环**

    * 初始化 `dist`（距离数组）为正无穷、`path`（路径数组）为 $-1$。
    * 选定编号为 1 的顶点作为原点，原点到它自己的距离初始化为 0。
    * 与原点直接相邻的两个顶点，其到原点的最短距离就是这两条边的权重：`dist[v2] = 2`、`path[v2] = 1`；`dist[v4] = 1`、`path[v4] = 1`。

* **外循环（`while`）的每一步**

    * 选出 $v$：从未收录顶点中挑当前 `dist` 最小者（直接扫描或用最小堆均可），把 `collected[v]` 标记为 `true`。
    * 松弛：遍历 $v$ 的每个邻接点 $w$。若 $w$ 未被收录且 $dist[v] + \text{weight}(v, w) < dist[w]$，则更新 `dist[w]` 并把 `path[w]` 改为 $v$。

* **样例走查（源点 $v_1$，图含 $v_1 \dots v_7$）**

    * 收录 $v_4$：$v_4$ 的邻接点有 $v_3,v_5,v_6,v_7$。
        * $v_3$ 距离为 $\infty$，而 $1 + 2 = 3 < \infty$ → `dist[v3]=3`、`path[v3]=4`；
        * $v_5$：`dist[v5]=3`、`path[v5]=4`；
        * $v_6$：`dist[v6]=1+8=9`、`path[v6]=4`；
        * $v_7$：`dist[v7]=1+4=5`、`path[v7]=4`。
    * 收录 $v_2$：邻接点 $v_4$（`collected` 为 true，跳过）、$v_5$。$2 + 10 = 12$ 远大于 3，不等式不成立，$v_5$ 保持原路径不变。
    * 收录 $v_3$（此时 $v_3$ 与 $v_5$ 距离并列最小，从编号小的开始选）：$v_1$ 已访问；$v_6$ 当前距离 9（来自 $v_4$），从 $v_3$ 走是 $3 + 5 = 8 < 9$ → `dist[v6]=8`、`path[v6]=3`。
    * 收录 $v_5$：唯一邻接点 $v_7$，$3 + 6 = 9 > 5$，不等式不成立，不做处理。
    * 收录 $v_7$：唯一邻接点 $v_6$，$5 + 1 = 6 < 8$ → `dist[v6]=6`、`path[v6]=7`。
    * 收录 $v_6$：没有邻接点，循环很快结束。此时不存在未收录顶点，跳出 `while`。

* **并列极值与路径回溯**

    * 并列极值处理：若候选未收录顶点中出现多个并列最小 `dist` 值，任意挑一个收录都能得到全局最优解。
    * 路径回溯：自终点出发沿 `path` 连续读取前驱标号，直到遇到负数（原点）。本例从 `path[6]` 找到 7、从 `path[7]` 找到 4、从 `path[4]` 找到 1，检查 `path[1]` 得到 $-1$ → 最短路径为 $v_1 \to v_4 \to v_7 \to v_6$。
    * 本例最关键的看点是 $v_6$ 这个顶点被更新了两次（$9 \to 8 \to 6$），它完整展示了算法如何一层一层把最短距离刷出来。

### 全源最短路与 Floyd 算法

* **两种策略的复杂度分野**

    * 朴素做法：把单源最短路算法对每个顶点各调用一次。
        * 稀疏图：单源最短路做到 $O(V \log V)$，调用 $V$ 次后是 $V^2 \log V$，效果仍然比较好。
        * 稠密图：在 $V^2 + E$ 的基础上再乘一个 $V$，变成 $V^3 + EV$，对稠密图就显得多余。
    * Floyd 算法：时间复杂度是**真正的** $O(V^3)$，没有后面那条尾巴，所以在稠密图上效果更好。

* **矩阵状态的定义与递推**

    * > **定义**：$D^k[i][j]$ 表示从顶点 $i$ 到顶点 $j$、**只允许经过编号小于等于 $k$ 的顶点**作为中间过渡节点时的最短路径长度。

    * 顶点编号若从 0 编到 $V-1$，则当 $k = V-1$ 时该矩阵就是真正的最短距离矩阵。路径是一步一步生成的：从只考虑 0 号顶点开始，逐步递推到 $V-1$。
    * 初值问题：$k$ 从 0 开始记，则前一步记作 $D^{-1}$。
        * 主对角元全为 0（零阶矩阵）；
        * $i$ 与 $j$ 之间有边则 $D[i][j]$ 为该边权重；
        * **两顶点之间无直接边时必须初始化为正无穷**——只有这样后面才能被慢慢变小，随便给值不行。
    * 递推原理：新收进来的顶点 $k$ 要么根本不在 $i$ 到 $j$ 的最短路径上（保持原样），要么一定在路径上；后一种情况下 $i$ 到 $j$ 的路径必然由 $i$ 到 $k$ 与 $k$ 到 $j$ 两段最短路径拼成，而这两段的中间都不含 $k$，所以在 $D^{k-1}$ 阶段就已经算好了。

        $$D^k[i][j] = \min\left( D^{k-1}[i][j], \; D^{k-1}[i][k] + D^{k-1}[k][j] \right)$$

    * 三重 `for` 循环嵌套即得 $O(V^3)$；候选过渡节点 $k$ 必须在**最外层**。

* **路径矩阵与递归打印**

    * 若还要求输出 $i$ 到 $j$ 之间的具体路径，需另配一个二维数组 `path[i][j]`，初始化为 $-1$（表示当前 $i$ 到 $j$ 之间没有路径）。
    * 当 `path` 在第 $k$ 步被更新时，意味着 $i$ 到 $j$ 一定经过 $k$，于是把 $k$ 记入 `path[i][j]`。
    * 打印路径是一个简单递归：先递归打印 $i$ 到 $k$ 的路径，再输出 `path[i][j]` 的值 $k$，最后递归打印 $k$ 到 $j$ 的路径。

### 哈利·波特的考试：极值建模的样板

* **题目背景（P95 题意理解）**

    * > **场景**：在霍格沃茨的魔咒期末考试中，考官要求考生把手中的一种动物变身为考场指定的另一种动物，每次施展变身魔咒都要念咒语，咒语长度即变身代价。哈利事先知晓所有可能考到的动物种类，以及任意两种动物之间互相变身所需的咒语长度，希望挑一只「最容易变身」的动物带进考场。

    * 咒语示例：把猫变成老鼠要念「哈哈」，把老鼠变成鱼要念「呵呵」，把猫直接变成鱼则念「啦啦啦」；衡量路径长短以**字符串长度**为标准。
        * 走「哈哈」再「呵呵」共 8 个字符；
        * 直接念「啦啦啦」只有 6 个字符，所以后者才是捷径。
    * 咒语可以反向施展（把老鼠变回猫念「啊啊」），所以整个图是**无向图**；每种动物是图里的一个顶点，每条无向边上有权重，权重就是该咒语的字符串长度，因此是一个**网图**。
    * 初步分析：带猫去时最难变的是鱼（6 字符），带鱼去时最难变的是猫（6 字符），带老鼠去时无论变鱼还是变猫都只需 4 字符 → 显然带老鼠去最合算。

* **样例数据与图规模**

    * 样例第一行给出两个数字：第一个是动物个数（图的顶点数），后面的 11 表示边的个数；接下来每一行给出一条边。
    * 这张网图比前面那个复杂得多，很难一眼看出该带哪只动物去。

* **求解步骤**

    * 第一步：先找出任意两个动物之间的最短路径——显然要用刚讲完的 Floyd 算法最合适。
    * 第二步：得到最短距离矩阵 $D$，$D[i][j]$ 记录从顶点 $i$ 到顶点 $j$ 的最短距离。矩阵里的数值来自不同路径的组合，例如第三行第五列的 120 表示从 $v_3$ 到 $v_5$ 的最短距离是 120（该处两条候选路径分别是 $70 + 50$ 与 $80 + 60$，取小者）。
    * 第三步：逐一检查每一行里最大的那个数字。行的最大值代表「带这个动物去时最难变的是哪个动物」——第 1 行最大是 81（变成第 5 个动物最麻烦），第 2 行最大是 80（第 5 个动物最麻烦），第 3 行也指向第 5 个，第 4、5、6 行的最大值则都指向第 3 个。
    * 第四步：从圈出来的这六个行最大值中找最小值。答案是 4 号动物，它最难变的咒语长度是 70，是所有动物里最容易的。

* **抽象总结（本题的通用范式）**

    * > **结论**：给一个无向网图，用 Floyd 算法算出任意两点之间的最短路径；然后对每一个顶点扫描它到其他所有顶点最短路径中的最大值，把这个最大值记下来；最后在所有顶点里找这些最大值中最小的那一个。

* **程序框架规划（`FindAnimal`）**

    * 在写 `main` 之前先做规划，这道题可简单分成两步：
        1. `BuildGraph`：把输入读进来并构建出图；
        2. `FindAnimal`：对这个图做分析——求任意两点最短路、找最短距离里的最大值、再找最大值里的最小值。
    * 图的表示选型：主要调用的算法模块是 Floyd，矩阵形式表示更方便，所以生成的是 `MGraph`（用邻接矩阵表示的图）。

        ```c
        int main(void) {
            MGraph Graph = CreateGraph(Nv);
            BuildGraph(&Graph);
            FindAnimal(&Graph);
            return 0;
        }
        ```

* **现成模块的引用与裁剪**

    * `MGraph` 定义：唯一需要删掉的是顶点存储的数据——本问题里每个顶点代表一只动物，又不存动物名字，所以顶点数据的两行可以删掉；边的定义（两个端点 + 权重）无需改动。
    * `CreateGraph`：原始代码无需任何改动，只做「有 $N_v$ 个顶点、没有边的空图」的初始化；唯一要注意的是这里**默认顶点编号从 0 开始**。
    * `InsertEdge`：可直接引用无需改动；因为是无向图，读进来的权重要**同时赋给矩阵里的两个元素**。
    * `BuildGraph`：读顶点个数建空图 → 读边个数，边数不为 0 就创建新边结点读入数据并插入 → 顶点数据部分整体删掉（辅助变量 `VertexV` 那一行也不必要）。
    * 编号对齐：图默认顶点编号从 0 开始，而输入里动物编号从 1 开始，所以插入边前要**把读进来的编号全部减 1**——读进 1 变 0、读进 2 变 1，边 $(1, 2)$ 存进图里就是 $(0, 1)$。

* **Floyd 模块的裁剪与两个必查细节**

    * 本题不需要记录路径，所以所有与 `path` 相关的语句全部删掉。
    * 负值圈判定分支也可以删掉：原算法检测 `D[i][i] < 0` 判断是否存在负值圈（`i` 到 `i` 的最短距离是负数，即对应一个负值圈），一旦存在就 `return false`；本题保证输入所有距离都是正的，永远返回 `true`，这个布尔值没有意义，把返回类型由 `bool` 改成 `void` 即可。

* **`FindAnimal` 的实现要点（`FindMin` 与 `FindMaxDist`）**

    * 第一件事就是调用现成的 Floyd 算法，把图里任意两点之间的最短距离矩阵 $D$ 算出来。
    * `FindMin` 做的是「求最小距离」这一层：先把 `MinDist` 初始化成一个很大很大的数（即无穷大），然后扫描每一个动物 $i$（$i$ 从 0 到 `Graph->Nv`），调用 `FindMaxDist` 找到第 $i$ 只动物的最大距离赋给 `MaxDist`；若这个距离比当前的 `MinDist` 更小，就更新 `MinDist` 并记录这只动物的编号。
    * > **易错点**：⚠️ 记录编号时写的是 $i+1$ 而不是 $i$。题目里输入的动物从 1 开始编号，而图里的顶点从 0 开始编号，这一步的偏移极易写错。
    * 不连通情况的处理：当 `FindMaxDist` 返回无穷大时，说明从这只动物出发到某些动物根本没有路径，带它去必然失败，直接输出 `0` 就返回。
    * `FindMaxDist` 本身极简单——找最大值先把 `MaxDist` 初始化成一个很小的数（比如 0），然后扫描第 $i$ 行的每个 $D[i][j]$，发现更大就更新。
    * > **易错点**：⚠️ 行内求最大值时必须加 `j != i` 的判断把对角元跳过去。因为邻接矩阵初始化时所有顶点间的距离都是正无穷，对角元 $D[i][i]$ 也就永远是正无穷；不排除它的话一读到对角元就必然大于 `MaxDist`，函数永远返回无穷大，直接出错。

## 最小生成树算法

### 最小生成树的三重内涵与约束

* **生成树（Spanning Tree）**

    * > **定义**：包含图中全部 $|V|$ 个顶点，且仅包含 $|V|-1$ 条边的一个无回路连通子图。

    * 「树」的三条性质：一定连通、一定没有回路、$V$ 个顶点恰好有 $V-1$ 条边（不能多也不能少）。
    * 「生成」的含义：图里所有顶点都一定要在这棵树里，且这棵树的全部 $V-1$ 条边都在原始的图中。
    * 生成树不唯一：含 4 个顶点的完全图有好几种生成树做法，只要满足 4 个顶点、3 条边、无回路即可。向生成树里任加一条多余的边都必定构成回路。

* **最小生成树（Minimum Spanning Tree，MST）**

    * > **定义**：在所有生成树中，边的权重和达到最小的那一棵。

    * 名字里包含三个概念：是树、是生成树、还是最小的生成树。
    * 存在性充要条件：最小生成树如果存在，图一定是连通的；反过来，图连通就一定能找到一棵最小生成树。两者等价。

* **贪心策略与三条硬约束**

    * > **定义**：贪心就是一步一步解决问题，每一步都要最好的、只要眼前最好的。

    * 不同问题里「好」有不同定义；在最小生成树里「好」就是**权重最小的边**。
    * 但不能简单地把所有边按权重排序后一路收到 $|V|-1$ 条为止——必须同时满足三条约束：
        1. 只能用原图里存在的边，原图没有的边不能用；
        2. 必须正好用掉 $V-1$ 条边，不能多也不能少；
        3. 生成的是一棵树，每条边收进来时都不能在现有树里构成回路。

### Prim 算法：让小树慢慢长大

* **算法机理**

    * > **定义**：从一个根节点开始，让一棵小树慢慢长大的贪心算法。

    * 逐步演示（7 个顶点的图）：
        * 随便选一个点作根节点，比如 $v_1$，先把 $v_1$ 收进树里；
        * 找最小的边——但不是随便找，必须是跟这棵树有关系的、往外能长出去的最小边。$v_1$ 直接相连的三条边里挑最小的一条收进来，它的另一个端点 $v_4$ 就一起被收录，树长大到两个顶点；
        * 继续以 $v_1$、$v_4$ 为基础往外长：此时有两条权重为 2 的边可选，另有一条权重为 1 的边——但这条 1 跟这棵树挨不上，不能收；在两条 2 中选一条（假定选上面那条），$v_2$ 被收录；
        * 下一条比较小的边权重是 3，收进来会构成回路，不行；权重 4 也不行（另一个回路）；再往下权重 4 的这条可以，收进来后 $v_7$ 进来；
        * 好消息是 $v_7$ 终于跟 $v_1$ 拉上了关系，于是在此收进的边让 $v_6$ 也进来了；
        * 最后收进来的是 $v_5$，通过权重 6 的那条边。至此 7 个顶点全部收进树，正好 6 条边，形成最小生成树。

* **与 Dijkstra 的同构机制**

    * 两者框架几乎一样：都是每次从未收录顶点中挑一个收进来，然后检查它的每个邻接点是否受到影响。
    * **距离定义的本质差异**：Dijkstra 的 `dist[v]` 记录固定源点到 $v$ 的**累计路径总长度**；Prim 的 `dist[v]` 记录顶点 $v$ 到**当前这棵生成树的最小直接连边权重**。
    * **松弛判定的本质差异**：
        * Dijkstra：`dist[v] + weight(v, w) < dist[w]`（要累加历史路径）
        * Prim：`weight(v, w) < dist[w]`（只比对单边权重，不累加）

* **实现要点**

    * `dist` 初始化：与根节点 $s$ 有直接边相连的顶点，初始距离就是这条边的权重；与 $s$ 之间没有直接边的，一律定义为**正无穷**（这一点与 Dijkstra 类似）。
    * 不必真去构建树节点：对每个顶点存它的 `parent`（父结点编号）即可，这与并查集里的概念差不多。根节点的 `parent` 设为 $-1$；当发现某个顶点的 `parent` 是 $-1$ 就知道它一定是根结点。
    * 收录判定：把 $v$ 收进最小生成树就意味着它到这棵树的距离变成了 0，所以只要把 `dist[v]` 设成 0 就代表已被收录。
    * 松弛：新收录 $v$ 后检查它的每个邻接点 $w$——若 `dist[w] != 0`（说明 $w$ 尚未被收录）且 $v$ 到 $w$ 之间有直接边、这条边的权重小于原有的 `dist[w]`，就更新 `dist[w]`，并让 $v$ 成为 $w$ 的 `parent`。
    * 跳出条件与不连通判定：`while` 循环在「找不到这样的 $v$」时 `break` 跳出。跳出后有两种可能：
        * 所有顶点都已收进树 → 皆大欢喜，程序正常结束；
        * 所有未收录顶点的 `dist` 全都是无穷大 → 剩下的顶点到这棵树之间都没有边，说明**整个图不连通**。
    * 因此跳出后要数一下收进来的顶点数：正好 $V$ 个就顺利结束，不到 $V$ 个就说明「生成树不存在」——换言之，「存在最小生成树」与「图连通」是等价的。

* **时间复杂度与适用边界**

    * 用简单粗暴的顺序扫描方法，$T(n) = O(V^2)$，与边数 $E$ 无关。
    * 稠密图用这种简单方法就够用，算法比较容易实现；对稀疏图则另有更好的方法（见 Kruskal）。

### Kruskal 算法：把森林合并成一棵树

* **算法机理**

    * > **定义**：把森林合并成一棵树的贪心算法，思想比 Prim 更好理解。

    * 核心图景：初始状态下**每一个顶点都是一棵树**，然后通过不断把边收进来，把两棵树并成一棵树，最终把全部 7 个节点并成一棵。
    * 逐步演示：先把权重 1 的两条边直接收进来；再收两条权重 2 的边，此时已有四条边；权重 3 的边收进来会构成回路，不要；权重 4 的边也构成回路，不要；另一条权重 4 的边可以收；权重 5 的边会构成一条回路，不能要；权重 6 的边可以收。数下来 1、2、3、4、5、6 共六条边，至此必然生成最小生成树。

* **伪代码的收集对象是边**

    * > **区别**：Kruskal 的最小生成树集合里收集的不是顶点而是边，一开始是空集。

    * 循环流程：每次从边集里选一条权重最小的边，把它从边集里删掉；检查这条边加入最小生成树后是否构成回路——不构成就加进生成树，构成的则生成树不要它、边集里也已删除，彻底无视这条边，再看下一条权重最小的边。
    * 循环继续的条件有两个且必须同时满足：生成树里收的边数不到 $V-1$；且原图里还有边。

* **最小堆加速选边**

    * 最坏情况下边会收满 $V-1$ 条，`while` 执行 $V-1$ 次，但整体复杂度还取决于「怎样快速取出一条权重最小的边」。
    * 把所有边按权重放进**最小堆**（建堆 $O(E)$），每轮用 $O(\log E)$ 弹出一条最小边。
    * > **易错点**：⚠️ 简单粗暴地把所有边都搜集一遍、或一开始把所有边完整排个序都不合算——为后续根本用不到的大权值边付出无效开销。

* **并查集判环机制**

    * 难点是「怎样知道这条边是否在最小生成树里构成回路」，解法正是并查集。
    * 一开始认为每个顶点都是独立的树，也就相当于并查集里每个顶点是一个独立集合；把一条边收进去就是把两棵树并成一棵、把两个集合并成一个集合。
    * 判定规则：放入新边 $(v, w)$ 前先检查 $v$ 属于哪个集合、$w$ 属于哪个集合。
        * 分属不同的树 → 加这条边肯定不构成回路，收进生成树并合并集合；
        * 已经在同一棵树里 → 加进去必然构成回路，丢弃。

* **终止判定与复杂度**

    * 跳出循环时：若生成树里正好有 $V-1$ 条边，宣布找到了最小生成树。
    * 坏消息情形：不到 $V-1$ 条边就跳出来了，说明原图里的边已经都被删光了——即**生成树不存在**，等价地说就是原图不连通。
    * 用最小堆 + 并查集实现，$T(n) = E \log E$。当图非常稀疏（$E$ 与 $V$ 同一数量级）时，基本就是 $V \log V$，比 Prim 的 $V^2$ 稍快一点。

### Prim 与 Kruskal 的特性对比

* **推进主体与支撑结构**

    * > **定义**：两类经典最小生成树算法在收录维度、基础支撑工具与状态维护上的技术异构。

    * Prim 围绕**顶点**展开，通过逐步吞并相邻外部顶点向外扩张单棵树；Kruskal 围绕**边**展开，通过由小到大贪心收录合法边把分散的森林整合成树。
    * Prim 以顶点距离数组 `dist[]` 和父结点数组 `parent[]` 为核心；Kruskal 以边权最小堆和顶点并查集为核心底座。
    * Prim 的防环机制是「只向未收录的外部顶点跨越，绝不接入树内闭合边」；Kruskal 靠并查集根节点查询校验（$\text{Find}(v) == \text{Find}(w)$ 则成环）。

* **时空复杂度与选型**

    * 稠密图（边数接近 $V^2$）首选基于数组扫描的 Prim（$O(V^2)$）；稀疏图（边数与 $V$ 同数量级）首选堆 + 并查集的 Kruskal（$E \log E$，稀疏时约 $V \log V$）。

    | 评估维度 | Prim 算法 | Kruskal 算法 |
    | :--- | :--- | :--- |
    | 推进核心 | 围绕「顶点」向外扩张单棵树 | 围绕「边」贪心选取合并森林 |
    | 支撑数据结构 | `dist[]`、`parent[]` | 边权最小堆、顶点并查集 |
    | 回路防范机制 | 仅向未收录外部顶点跨越，不接入树内闭合边 | 并查集根节点校验 |
    | 松弛判定条件 | $\text{weight}(v, w) < dist[w]$（无累计路径） | 无松弛，直接检验边端点集合连通性 |
    | 时间复杂度 | $O(V^2)$（基础实现，与 $E$ 无关） | $E \log E$（稀疏图约 $V \log V$） |
    | 最优适用拓扑 | 稠密图及完全图 | 稀疏图（$E$ 与 $V$ 同数量级） |
    | 不连通判定标志 | 跳出后累计收录顶点数不到 $V$ | 边集已空但累计收录边数不足 $V-1$ |

## 活动时序与工程调度网络

### AOV 网络与拓扑排序

* **从排课表到 AOV 网络**

    * 场景：某计算机专业列出 15 门课程的课程号、名称与**预修课程**。要学计算机网络得先学操作系统（课程 10），要学操作系统得先学算法（课程 7）和计算机组成，要学组成得先学逻辑，要学算法得先学数据结构，要学数据结构得先会写程序并最好知道一点离散数学概念。
    * 真实专业有好几十门课，课程数量大增后靠人工排先后顺序就相当复杂，得写程序解决——而这一章讲的正是图。
    * > **定义**：AOV 网络（Activity On Vertex）——在这个有向图里，所有真实的活动都表现在**顶点**上，顶点之间的有向边表示两个活动之间的先后顺序。

    * 画图步骤：
        * 先找出没有预修课程的课程（1、2、3、4 门），先把这四个顶点画出来；
        * 数据结构课程 3 的预修是课程 1 和 2，所以 $c_3$ 的前驱结点有两个；
        * 课程 4 之后可以学微积分二（课程 5）；课程 6 需要课程 5；课程 7 需要课程 3；课程 9 需要课程 8；操作系统需要课程 7 和 9，二者共同推出课程 10；课程 11 同样需要课程 7 和 9；课程 12 需要课程 7；课程 13 需要课程 2；课程 14 需要课程 10；课程 15 需要课程 6——依赖关系图完成。

* **拓扑序与拓扑排序**

    * > **定义**：在这个 AOV 图里，如果从 $v$ 到 $w$ 有一条有效的路径，那么 $v$ 在输出时一定排在 $w$ 之前；满足这个条件的顶点序列称为一个**拓扑序**，获得拓扑序的过程称为**拓扑排序**。

    * 换句话说：如果要学习 $w$ 之前必须先学习 $v$，那么输出时 $v$ 一定要在 $w$ 之前。
    * 存在性充要条件：AOV 网络能排出合理拓扑序，则它一定是有向无环图（DAG）。
    * 死锁成环机理：若图中存在环，就意味着 $v$ 这个活动自己成了自己的前驱结点——它在自己开始之前就必须已经结束，这是不可能的事，所以有环就不可能得到合理的拓扑序。

* **朴素拓扑排序与它的 $O(V^2)$ 开销**

    * 外层循环 $V$ 步，每一步在还没被输出的顶点中找一个**入度为零**的 $v$，把它输出（记录输出序号），然后把 $v$ 从原图里「抹掉」。
    * 「抹掉」不是真删结点，而是把 $v$ 的每个邻接点的入度减 1——也就是把从 $v$ 到 $w$ 的这条边减掉，$w$ 少了一条额外的边。
    * 若每一步都正常，外循环执行 $V$ 步后自然把所有顶点输出完毕。
    * 环路判定：若外循环还没结束就已经找不到入度为零且未输出的顶点，说明还剩好几个顶点没输出、且每个顶点入度都不为零，图里必定有回路，直接 `break`。
    * 简单粗暴的做法是每次把所有点都扫描一遍找那个「未输出且入度为零」的顶点，这一步就是 $O(V)$，整体复杂度变成 $O(V^2)$——非常不聪明。

* **队列优化拓扑排序**

    * > **思路**：每当任何一个顶点的入度变为零时，不要把它留在原处，而是把它挪到一个特殊容器里（数组、链表、堆栈、队列都行），下次要找入度为零的顶点时直接到容器里取，不必重扫全图——这一步的时间复杂度顿时变成常数级。

    * 全流程：
        1. 先检查图中每个顶点有没有入度为零的，统统放进容器；
        2. 只要容器非空就取出一个顶点（必然入度为零），直接输出；
        3. 输出后把它从图里抹掉——把它的每个邻接点入度减 1，减的同时检查是否减到了 0，减到 0 就放进容器，否则什么都不做；
        4. 继续取下一个顶点。
    * 环路判定：跳出 `while` 时如果并非所有顶点都已输出（还有顶点留在图里），就说明图里一定存在回路。用一个计数器在每次输出时 `cnt++`，跳出后比对 `cnt` 与顶点个数，不相等则途中必有回路。
    * 复杂度：每个顶点入队一次、每条边被扫描一次，整体降为 $O(V + E)$。稀疏图时这约等于 $O(V)$，稠密图时是 $V^2$ 数量级。
    * 附带能力：这个算法还可以用来检测一个图是不是有向无环图。

### AOE 网络与关键路径

* **AOE 网络（Activity on Edge）**

    * > **定义**：另一类网络——每一条**边**代表一道工序或一个活动，顶点表示「活动到达这个顶点就结束了」。这类网络一般用于安排庞大项目：项目分成很多道工序，工序之间有先后依赖关系。

    * 绘图约定：边的上面写这道工序的**持续时间**（完成它一共需要多少天），边的下面写**机动时间**。
    * 顶点分三块：上面写顶点编号 $v_j$；中间写这个顶点所有任务**最早的完成时间** `Earliest`；下面写这些项目**最晚需要完成的时间** `Latest`。
    * > **虚边解耦规则**：某道工序若不仅要等前两个工序结束、还得等第三个工序结束（三者等齐才能往下走），不能简单把两个顶点合并——因为第一个工序的开工跟后两个是否完工毫无关系，它只要等自己的前驱即可。解法是画一条持续时间（权重）为 **0** 的**虚边**，这样既表明三道工序必须等齐，又不影响只关心单个前驱的那道工序。

* **最早完成时间：前向顺推取最大**

    * 从第 0 天开始沿拓扑序顺推：某工序要 6 天 → 该顶点 `Earliest` 就是第 6 天；另一条要 4 天 → 第 4 天；再往下一个要 1 天 → 第 5 天；再下一个要 2 天 → 第 7 天。
    * 遇到汇聚结点（需等齐三条支路）：三条路径分别给出 7 天、5 天、7 天，**必须取最大的那个**，因为要求三道工序全部完工才能往下走。
    * 递推公式：初始化 `Earliest[0] = 0`；若 $\langle i, j \rangle$ 是一条边，则前驱的 `Earliest` 加上该边权重就是下一个顶点的 `Earliest`；当有三条边同时指向它时取所有边中最大的那个。
        $$Earliest[j] = \max_{\langle i, j \rangle \in E} \left\{ Earliest[i] + Weight\langle i, j \rangle \right\}$$
    * 顺推到最后一个结束顶点即得整个工期。样例中：$7+9 = 16$、$7+7 = 14$、$7+4 = 11$ 取 14；另一边过来是 18，另一边过来也正好是 18 → 最后一个顶点的 `Earliest` 是 18，整个工期 18 天以内结束。

* **最晚完成时间：后向逆推取最小**

    * 作为项目负责人，既想知道哪几个组一天都不能耽误，也想知道哪几个组中间可以拎出去干别的事情（有机动时间）。
    * 从「保证整个工期 18 天结束」这个约束出发，从结束的顶点往回推：该组要 2 天完工，若要在第 18 天结束，最晚必须第 16 天开始 → `Latest = 16`；另一组同样是 18 天倒推，最晚第 14 天开始。
    * 多选择时必须取最小：某顶点前面那条路径倒推是「第 10 天开工就可以」，但另一条路径倒推「必须第 7 天完工」（因为还有一道工序在等着，它要第 7 天开工否则整体延误）→ 这个顶点也是第 7 天要完工，同样不可延迟。
    * > **结论**：当有多种倒推选择时，**必须选那个最小的**。

    * 逆推公式：最后一个顶点的 `Latest` 等于它的 `Earliest`；然后倒着往回推，若 $\langle i, j \rangle$ 是一条边，则用后继的 `Latest` 减去该边的持续时间；多选择时取 minimum。
        $$Latest[i] = \min_{\langle i, j \rangle \in E} \left\{ Latest[j] - Weight\langle i, j \rangle \right\}$$

    * 续推示例：$7-2 = 5$、$7-1 = 6$；回到顶点 0 时有三种选择 $6-6$、$6-4$、$5-5$ 都得 0，取最小仍是 0。

* **机动时间的定量公式**

    * 机动时间就是「哪些组是可以不用可头赶工的」：某道工序第 0 天就能启动、最晚第 6 天完工即可，而它只需要 4 天 → 机动时间 2 天（老板当然不会真的放假，这两天可以把他们调去干别的事情）。
    * 计算公式：若 $\langle i, j \rangle$ 是一条边，用终点的 `Latest` 减去起点的 `Earliest`，再减去这道工序要花的时间。
        $$Slack\langle i, j \rangle = Latest[j] - Earliest[i] - Weight\langle i, j \rangle$$
    * 样例中另外两道工序也各有 2 天和 13 天的机动时间。有了这张图，项目经理就可以据此调配人力。

* **关键路径（Critical Path）**

    * > **定义**：机动时间严格等于 0 的那些活动所组成的、从头走到尾的路径。

    * 工程刚性特征：这些组一天都不能耽误，只要耽误一天整个工期都得往后顺延——关键路径指的就是绝对不允许延误的这些活动（这些边）组成的路径。
    * 多关键路径：关键路径不止一条。把所有机动时间为 0 的任务从头走到尾所组成的路径，都叫关键路径。
    * 算法实现：测算**项目总工期**的程序只需把拓扑排序的程序稍微改一改——在出队削减入度时动态递推更新 `Earliest` 数组即可（课后习题）。
    * 完整的 `Latest` 与 `Slack` 推算程序写起来略烦，课程中留作课后练习。

### AOV 网络与 AOE 网络模型对比

* **网络语义与属性分配**

    * > **定义**：两类活动网络在顶点与边的语义分配机制上的本质对照。

    * AOV 中顶点承载活动本身、边仅表示先后约束；AOE 中顶点仅作为阶段完成的里程碑、边承载活动工期与机动时间。
    * AOV 拓扑图直接连线无需虚边概念；AOE 在非对称依赖场景下必须引入耗时为 0 的虚边来解耦。

* **计算目标与复杂度**

    * AOV 侧重可行执行序列的排定与死锁检测（顶点入度归零驱动入队，无极值比对）；AOE 侧重总工期估算、瓶颈工序定位与人力调度（顺推汇聚取最大、逆推分叉取最小）。
    * 两者时间复杂度同为 $O(V + E)$。

    | 比较维度 | AOV 网络（Activity on Vertex） | AOE 网络（Activity on Edge） |
    | :--- | :--- | :--- |
    | 顶点语义 | 指代具体的业务活动或工序 | 指代事件里程碑（入边全完工、出边可开工） |
    | 有向边语义 | 指代活动间的拓扑先后依赖约束 | 指代具体业务活动及工序持续时间 |
    | 边权物理内涵 | 无权（或权重无物理耗时含义） | 活动施工需耗费的物理时间 |
    | 虚边引入需求 | 拓扑图直接连线，无虚边概念 | 引入权值为 0 的虚边解耦非对称依赖 |
    | 核心计算目标 | 拓扑排序、拓扑合法序列生成、回路检测 | 最短总工期测算、工序机动时间分配、关键路径识别 |
    | 极值决策准则 | 顶点入度归零驱动入队，无极值比对 | 前向顺推汇聚取最大值、后向逆推分叉取最小值 |
    | 算法时间复杂度 | $O(V + E)$（队列优化） | $O(V + E)$（拓扑顺推与逆推） |

## Dijkstra 的两个常见变形

### 多权重的旅游规划问题

* **问题设定**

    * 城市是图里的节点、公路是边，问题一眼就是单源最短路径；但麻烦在于每条边**不止一种权重**。
    * 第一种权重是人人想要的**距离**；第二种权重是**收费**。题目要求首先以距离为标准找最短路，当这样的路径不止一条时，再在并列者中挑费用最小的那条。

* **样例推演**

    * 若只想找最便宜的路径，从 0 直接走到 3 只需花 10 块钱——但这条路太远了（距离是 4，说不定翻了一个山头），没人愿意走，所以这条路不能用。
    * 最短距离的路径有两条：`0→1→3` 和 `0→2→3`，距离都是 3（分别是 $1+2$ 和 $2+1$）。距离并列时才去比较收费：一条收费 40，另一条收费 50 → 输出收费 40 的那条。

* **算法改造**

    * 解决思路仍然基于 Dijkstra。区别只在于：经典 Dijkstra 里「距离相等时什么都不做」，而本题距离相等时**还必须按收费再做一次更新**。
    * 为第二个权重另建一个数组 `cost`，`cost[w]` 存的就是从源点 $s$ 走到 $w$ 当前这条路径上所有费用的和。路径被更新时费用也必须更新：`cost[w] = cost[v] + E.cost`。
    * 核心改造是在原算法后加一条 `else if` 分支：当发现另外一条**等长**的最短路径、且这条新路径上的费用比原来更小时，也要更新——先更新费用，同时别忘了更新 `path`。

### 等长路径计数与最少边数遴选

* **等长最短路径的条数统计**

    * > **思路**：加一个计数数组 `count`，`count[v]` 记录从源点到 $v$ 的最短路径一共有多少条。初始化时**源点的 `count` 设为 1**。

    * 发现更短路时的更新规则：从 $v$ 到 $w$ 只有一条边，所以从 $s$ 到 $v$ 曾有多少条最短路，从 $s$ 到 $w$ 就也会有多少条——把数字**继承**过来即可，`count[w] = count[v]`。
    * > **易错点**：⚠️ 发现**等长**路径时绝不能写 `count[w]++`。新等长路径虽然 $v \to w$ 只有一条边，但从 $s$ 到 $v$ 这边的最短路可不一定只有一条，$v$ 带给 $w$ 的是**一堆**等长最短路，必须全量合并：`count[w] = count[w] + count[v]`。

* **边数最少的最短路径**

    * > **结论**：这个问题与旅游规划问题本质等价——把每条边的费用全部定义为 1，就等价于求边数最少的路径。

    * 与旅游规划的差别仅在于**费用数组的初值**。此处仍叫 `count`，但它是数边数的计数器。
    * > **易错点**：⚠️ 此时源点的 `count` **必须初始化为 0 而不是 1**——从 $s$ 到 $s$ 自己是没有边的。错误初始化为 1 会让全图所有顶点的边数统计集体虚增。
    * 后续处理与前面讨论过的完全一致：找到更短路时 `count[w] = count[v] + 1`（这个 1 可理解为一条边的特殊权重 1，边有其他权重时就替换成其他权重）；找到等长路径时同样是 `count[w] = count[w] + count[v]` 加该边的新权重。

## 排序算法基础规范

### 接口规范与运行假设

* **统一函数签名**

    * > **定义**：各种排序算法的函数头有一个统一规范的格式 `void X_Sort(ElementType A[], int N);`，其中 `X` 是排序算法名称，`A[]` 是待排元素数组，`N` 是待排元素总个数。

    * `ElementType` 可以是任意类型，只要能比较大小。为简单起见默认讨论整数排序（字符串甚至任何数据结构都能排，只要能比大小），并默认按从小到大排。

* **三条默认假设**

    * 输入的 $N$ 一定是一个合法的正整数。
    * 只讨论**基于比较的排序**：无论是整数、字符串还是别的 `ElementType`，都假设小于、等于、大于这三个符号有定义，且这是排序算法中最重要的一件事。
    * 只讨论**内部排序**：待排数据规模完全在可用物理内存容量之内，全部一次性加载进内存、算法全量在高速内存中闭环完成（区别于受内存容量制约、依赖磁盘 I/O 与多路归并的外部排序）。

### 稳定性与多样性准则

* **算法稳定性（Algorithm Stability）**

    * > **定义**：任意两个相等的数据，排序前后的相对位置不发生改变。

    * 举例：排序学生名单时有两个同名的「小明一」和「小明二」，排序前小明一在小明二前面；排序完成后这两个名字会排在一起，若小明一仍排在小明二前面，则这种排序算法是**稳定的**，否则是**不稳定的**。

* **算法多样性准则**

    * > **结论**：每一种算法都有它必须存在的理由——**没有任何一个算法在任何情况下都是最快最好的**。

    * 每种算法都是在「你的数据具有某种特征时它可能是最好的」，数据特征一换，原来好的算法就不好了，另一种反而可能最好。
    * 这也正是为什么一种算法能被写进教科书——它一定有它存在的非常重要的理由。
