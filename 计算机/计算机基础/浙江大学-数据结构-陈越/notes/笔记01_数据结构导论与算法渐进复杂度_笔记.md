# 数据结构导论与算法渐进复杂度

## 数据结构的三组开场案例

### 图书摆放：组织方式直接决定操作效率

* **问题抽象**

    * > **定义**：给定一批图书与若干书架，决定「怎么摆」。等价于给定一堆数据与一块存储空间，决定「怎么存」。

    * 摆放方案只与两个操作挂钩：新书怎么插入、某本指定的书怎么找到。
    * > **结论**：解决问题方法的效率与数据的组织方式直接相关。

* **随便放（无序组织）**

    * 插入：哪有空放哪，新书直接贴在最后，一步到位，常数级开销。
    * 查找：只能从头到尾把每一本书过一遍才敢下结论，书城规模一大就是灾难。

* **按书名拼音字母顺序放（全局有序组织）**

    * 查找：二分查找。先取中点书比对，范围每轮折半，很快收敛到一本书。
    * 插入：新书若为 A 开头（阿 Q 正传），几乎所有书都要往后错位一格，代价极高。

* **先分类再在类内按字母序放（分级分类组织）**

    * 查找：先定位类别，再在类这个小范围内二分，检索规模大幅压缩。
    * 插入：同样先定类、再二分定位插入位，仍需局部挪位，但远少于全局有序。
    * 空间分配难题：各类藏书量本就不同，统一预分书架——给多了空置浪费，给少了不断要加柜子。
    * 分类粒度难题：分得粗则单类工作量依旧大，分得细则类别数量爆炸（3 万个类目时「这本书属于哪一类」本身又成了难题）。

* **逻辑结构的三个形态（由图书案例自然导出）**

    * 线性结构：一本书前面只有一本书、后面只有一本书（除首尾），一对一关系。
    * 树形结构：给每一类一个编号，一个类目编号下对应很多本书，一对多关系。
    * 图形结构：一本书对应很多人、一个人又对应很多本书，多对多关系网。

### PrintN：递归代码简洁但空间代价恐怖

* **同一个问题的两种实现**

    * 循环实现：`for` 循环打印 $1 \sim N$。
    * 递归实现：$N \neq 0$ 时递归调用自身传入 $N-1$，返回后打印当前的 $N$。
    * 递归版本连临时变量都不用，代码行数与循环版相同，看上去更简洁。

* **实测反差**

    * $N=10$ 与 $N=100$（万）两者都正常。
    * $N=10^5$ 时循环版慢慢打完 10 万个数，屏幕显示不全但最终正确结束。
    * $N=10^5$ 时递归版直接罢工，一个数字都没打出来就非正常中断（爆栈）。

* > **结论**：解决问题方法的效率与空间的利用效率直接相关。计算机实在特别不愿意跑递归程序。

### 多项式求值：巧妙程度直接拉开数量级

* **两个函数**

    * 笨办法 $f_1$：直接翻译标准定义式 $P(x) = \sum_{i=0}^{n} a_i x^i$，先令 $p = a_0$，再循环累加 $a_i x^i$。
    * 巧办法 $f_2$：秦九韶算法，巧妙利用结合律每轮提取一次公因子，程序从里往外算，$p$ 从 $a_n$ 起，每轮用 $x$ 乘已算出的 $p$ 再加上 $a_{i-1}$。

* **乘法次数的精确计数**

    * $f_1$：`for` 循环里的 `power(x, i)` 用简单累乘算 $x^i$ 需要 $i-1$ 次乘法，再乘系数共 $i$ 次；总乘法次数 $\sum_{i=1}^{n} i = \frac{1}{2}n^2 + \frac{1}{2}n$，即 $T_1(n) = c_1 n^2 + c_2 n$。
    * $f_2$：每轮循环只有 1 次乘法、共 $n$ 轮，总乘法次数恰为 $n$，即 $T_2(n) = c_3 n$。
    * 加减法耗时远低于乘除法，分析时直接忽略不计。

* **硬件计时与循环放大法（Clock Ticks）**

    * `clock()` 返回从程序开始运行到该函数被调用时刻所耗的时钟打点数，返回类型为 `clock_t`；配套常数 `CLK_TCK`（clock tick 的缩写）给出该机器每秒的时钟打点数，不同机器取值可能不同。
    * 计时模板必须 `#include <time.h>`；`start`、`stop` 均为 `clock_t`，`duration` 为 `double`（单位秒）。
    * 测试范围纪律：读输入、预处理等准备工作全部写在第一次 `clock()` 之前；输出 `duration` 等后继处理写在第二次 `clock()` 之后，核心只有四行：

        ```c
        start = clock();
        /* 被测函数调用写在这里 */
        stop  = clock();
        duration = (stop - start) / (double)CLK_TCK;
        ```

    * 首测失败现象：$f_1$、$f_2$ 的 tick 全为 0，原因是两函数跑得太快、运行时间不到一个 tick，`clock()` 根本捕捉不到差别。
    * 循环放大解法：定义 `MaxK` 为最大重复调用次数（本例取 $10^7$），把单次调用换成 `for` 循环重复 `MaxK` 次，再把总时间除以 `MaxK` 折算单次耗时：

        ```c
        start = clock();
        for (k = 0; k < MaxK; k++) MyFunction(...);
        stop  = clock();
        duration = (stop - start) / (double)CLK_TCK / MaxK;
        ```

    * 放大后的实测：两组数据具体数值因机器而异，但相对大小稳定差约一个数量级。

## 数据结构的定义、逻辑结构与抽象数据类型

### 数据结构的两面：组织方式与操作集

* **数据结构（Data Structure）**

    * > **定义**：数据对象在计算机中的组织方式。数据对象不是孤立的，它一定与一系列加在它上面的操作相关联；实现这些操作所用的方法叫做算法。

* **逻辑结构（Logical Structure）**

    * 线性结构：元素一对一关联，除首尾外每元素有唯一前驱与唯一后继。
    * 树形结构：元素一对多的层级分支，父结点向下辐射多个子结点。
    * 图形结构：元素多对多的网状关联。

* **物理存储结构（Storage Structure）**

    * > **定义**：上述逻辑结构在机器内存里到底怎么放——是连续放还是东一个西一个隔开放，即用数组存还是用链表存。

### 抽象数据类型（Abstract Data Type，ADT）

* **数据类型的两个要素**

    * 数据对象集：说的是什么东西。
    * 与数据对象集相关联的操作集：说的是对这些东西做什么。
    * 二者必须紧密结合——不能只讲怎么摆放图书而不讲对图书做什么操作。
    * 在 C 语言中这两件事是分开处理的；在 C++、Java 等面向对象语言里由**类**把数据对象集与操作集封装在一起。

* **抽象的三重不关心**

    * > **定义**：抽象就是不具体——描述数据类型的方法不依赖于具体实现。

    * 与存放数据的机器无关、与数据的物理存储结构无关、与实现操作的算法和编程语言无关。
    * 总体原则：只描述数据对象集和相关操作集是什么，不关心它是怎么做到的。

* **矩阵 ADT 实例**

    * 数据对象集：$n \times m$ 个矩阵元素，每个元素描述为三元组 $\langle a, i, j \rangle$——$a$ 是元素的值，$i$、$j$ 是它所在的行号与列号。
    * 操作集：`Create`（建立 $m \times n$ 空矩阵）、`GetMaxRow`（返回总行数）、`GetMaxCol`（返回总列数）、`GetEntry`（按行号列号返回该位置元素的值）、`Add`（行列一致时返回和，否则返回错误标志）、`Multiply`（行列匹配时返回积，否则返回错误标志）。
    * 抽象点一（元素类型的抽象）：$a$ 究竟是 `float`、`double` 还是 `int` 一概不关心，元素值统一用自定的 `ElementType`；实现时只需在文件头 `#define` 一次。类型变更不必逐处替换——盲目 replace 会把本来真的是 `int` 的地方也换成 `double` 从而出错。
    * 抽象点二（存储方式的抽象）：矩阵到底用二维数组、一维数组还是十字链表存，ADT 定义里一概不管。
    * 抽象点三（算法与语言的抽象）：描述 `Add` 时只说「可加则返回和」，不说先按行加还是先按列加，也不说用什么语言实现。

## 算法定义与好坏衡量

### 算法的五个要素

* **算法（Algorithm）**

    * > **定义**：一个有限的指令集，接受零个或多个输入，至少产生一个输出，并在有限步骤之后终止。

    * 有穷性：算法中不允许存在无限循环的概念。程序可以一直跑（如操作系统不关机就一直跑），算法不可以。
    * 确定性：每条指令必须有充分明确的目标，不可以有歧义。
    * 可行性：目标不可以太远大，必须落在计算机能处理的范围之内。
    * 抽象性：描述手段不依赖于任何一种计算机语言与具体实现方式。

* **选择排序的伪代码抽象**

    * 算法机理：从尚未排好序的子序列中每次挑一个最小元素，贴到已排好序子序列的最后面，重复直至得到升序序列。
    * 第一版伪码看着像 C 函数，但中间两个最核心的步骤（找最小元、换到有序部分最后位置）用自然语言描述，因此不是 C 函数。

        ```text
        void SelectionSort(ElementType List[], int N) {
            for (i = 0; i < N - 1; i++) {
                从 List[i] 到 List[N-1] 中找一个最小元
                记录它的位置到 min_pos
                把 List[min_pos] 与 List[i] 交换
            }
        }
        ```

    * 区间划分：`List[0..i-1]` 是已排好序部分，`List[i..N-1]` 是未排序部分，扫描范围正是 `List[i]` 到 `List[N-1]`。
    * 更清晰版本把两处自然语言抽成具名函数：

        ```c
        void SelectionSort(ElementType List[], int N) {
            int i, min_pos;
            for (i = 0; i < N - 1; i++) {
                min_pos = ScanForMin(List, i, N - 1);
                Swap(List[i], List[min_pos]);
            }
        }
        ```

    * 抽象点：写得像数组的 `List` 未必必须是数组，传链表整个算法依然正确；写得像函数的 `Swap` 也未必必须用函数实现，可以是宏，都是具体实现细节，描述算法时不关心。

### 空间复杂度与时间复杂度

* **空间复杂度 $S(n)$**

    * > **定义**：算法写成的程序在执行时占用存储单元的长度。

* **时间复杂度 $T(n)$**

    * > **定义**：算法写成的程序在执行时耗费时间的长度。

* **为何写成 $n$ 的函数**

    * 两个指标都直接与待处理数据的规模相关。打印 10 个整数瞬间出结果，打印 10 万个就得等一会儿——这个 10 或 10 万就是数据规模 $n$。
    * 空间复杂度太大，程序可能直接爆掉、非正常中断；时间复杂度太大，可能等到世界末日也等不到结果。

* **递归与循环的空间账（$N = 10^5$ 实证）**

    * 递归机制：每次调用函数之前，系统必须把当前函数的所有现有状态存到内存某处；执行完返回时再恢复这些状态接着执行下一句。
    * 递归链 `PrintN(100000) → PrintN(99999) → … → PrintN(1) → PrintN(0)`，返回前每一层的现场都还在系统内存里堆着，因此占用空间与原始 $n$ 成正比，$S(n) = c \cdot n$。
    * 当 $n$ 非常大时，程序可用的有限空间被用爆，非正常退出。
    * 循环版本只有一个临时变量与一个 `for` 循环，不涉及任何函数调用，占用空间始终是常量，$S(n) = c = O(1)$，$n$ 再大也没问题。

## 渐进表示法与复杂度阶梯

### 大 O、大 Omega、大 Theta

* **渐进上界记号（大 $O$）**

    * > **定义**：若存在常数 $c$ 与 $n_0$，使得当 $n \ge n_0$ 时 $f(n)$ 总是 $T(n)$ 的某种上界，记作 $T(n) = O(f(n))$；对空间复杂度同理。

* **渐进下界记号（大 $\Omega$）**

    * > **定义**：$g(n)$ 是 $T(n)$ 的某种下界，记作 $T(n) = \Omega(g(n))$。

* **渐进等价记号（大 $\Theta$）**

    * > **定义**：大 $O$ 与大 $\Omega$ 同时成立，即函数既是上界也是下界，二者基本等价。

* **粗略分析原则**

    * 完全没有必要一步一步去数某个操作做了多少次；有必要的只是关心：随着数据规模增大，复杂度增长的性质会怎样。
    * 比较两个算法时，只要知道第一个在大 $n$ 时由 $n^2$ 主导、第二个由 $n$ 主导，就知道 $n$ 充分大时第一个必然更慢。

* **上下界的非唯一性**

    * 一个函数的界有无穷多个。复杂度是 $n$ 的常数倍时，可以写成 $O(n)$、$O(n^2)$、$O(n^3)$……下界同理。
    * 太大的上界与太小的下界对分析效率毫无帮助。
    * 书写约定：写大 $O$ 时取**能找到的最小上界**；写大 $\Omega$ 时取**能力范围内找到的最大下界**。

### 函数增长阶梯与数值对照

* **增长偏序**

    * $1 < \log n < n < n \log n < n^2 < n^3 < 2^n < n!$
    * $\log n$ 长得最慢，$n$ 稍差一点，$n \log n$ 居于 $n$ 与 $n^2$ 之间；$n^3$ 还不是最可怕的，$2^n$ 与 $n!$ 才是。
    * 底数无关紧要：不管以 $2$、$10$ 还是 $e$ 为底，$\log$ 函数之间只差一个常数倍，而常数因子会被大 $O$ 吸收，所以教科书里统一简写为 $\log n$。

* **不同规模下的函数数值表**

    | 函数类型 | 记号 | $n=1$ | $n=2$ | $n=4$ | $n=8$ | $n=16$ | $n=32$ |
    | :--- | :--- | :---: | :---: | :---: | :---: | :---: | :---: |
    | 常数阶 | $1$ | 1 | 1 | 1 | 1 | 1 | 1 |
    | 对数阶 | $\log n$ | 0 | 1 | 2 | 3 | 4 | 5 |
    | 线性阶 | $n$ | 1 | 2 | 4 | 8 | 16 | 32 |
    | 线性对数阶 | $n \log n$ | 0 | 2 | 8 | 24 | 64 | 160 |
    | 平方阶 | $n^2$ | 1 | 4 | 16 | 64 | 256 | 1024 |
    | 立方阶 | $n^3$ | 1 | 8 | 64 | 512 | 4096 | 32768 |
    | 指数阶 | $2^n$ | 2 | 4 | 16 | 256 | 65536 | 4294967296 |
    | 阶乘阶 | $n!$ | 1 | 2 | 24 | 40320 | $2.09\times10^{13}$ | $2.63\times10^{35}$ |

* **每秒执行 $10^6$ 行指令的计算机耗时表与其中的印刷错误**

    * 假设一台每秒执行 $10^6$ 行指令的计算机，$n$ 从 $10^1$ 增长到 $10^6$，观察各复杂度函数的实际耗时。
    * $2^n$ 一栏在 $n = 100$ 时就已经不要想跑出结果了。
    * > **易错点**：⚠️ 这张表上存在一处印刷错误——标着 $\log n$ 的那一列，运行时间居然比 $n$ 还慢，这绝不可能。$\log n$ 应比 $n$ 快得多；这一列比 $n$ 慢、比 $n^2$ 快，介于两者之间，因此**只可能是 $n \log n$**。

* **工程本能：见到 $O(n^2)$ 就想压成 $O(n \log n)$**

    * 每次看到算法复杂度是 $n^2$，专业程序员的下意识反应就是「能不能降成 $n \log n$」。
    * $n = 10^6$ 时，$n^2 = 10^{12}$ 与 $n \log n \approx 2 \times 10^7$ 相差 5 万倍，效率提升非常明显。

### 复杂度分析的四个小窍门

* **加法规则（顺序拼接）**

    * 两段算法拼在一起，总时间是两段的和，上界取两个上界中较大的那个：$T_1(n) + T_2(n) = \max(O(f_1), O(f_2))$。

* **乘法规则（嵌套执行）**

    * 两个算法嵌套起来、复杂度相乘时，上界就是上界的乘积：$T_1(n) \times T_2(n) = O(f_1 \times f_2)$。

* **多项式主部规则**

    * 若 $T(n)$ 是关于 $n$ 的 $k$ 阶多项式，真正起作用的只有最高那一项，其余全部可以忽略。

* **结构体规则**

    * `for` 循环：复杂度 = 循环总轮数 $\times$ 循环体内代码的复杂度。
    * `if-else` 分支：要算三段代码的复杂度——`if` 条件判断本身、then 分支、else 分支，取三者中最大的那个。

## 最大子列和：四个算法的效率演进

### 问题定义与暴力枚举

* **最大子列和（Maximum Subsequence Sum）**

    * > **定义**：给定 $n$ 个整数序列 $\{A_0, A_1, \dots, A_{n-1}\}$，求从 $A_i$ 到 $A_j$ 连续一段子列和 $\sum_{k=i}^{j} A_k$ 的最大值；若最大值是负数则返回 0 作为结束。

* **算法一：暴力枚举（$O(N^3)$）**

    * 思路：把所有连续子列和全算出来，再从中找最大的一个。$i$ 是子列左端、$j$ 是右端（$j \ge i$），内层 $k$ 从 $i$ 累加到 $j$ 得到 `ThisSum`，与 `MaxSum` 比大小后更新。

        ```c
        int MaxSubsequenceSum1(int A[], int N) {
            int ThisSum, MaxSum = 0;
            int i, j, k;
            for (i = 0; i < N; i++) {
                for (j = i; j < N; j++) {
                    ThisSum = 0;
                    for (k = i; k <= j; k++) ThisSum += A[k];
                    if (ThisSum > MaxSum) MaxSum = ThisSum;
                }
            }
            return MaxSum;
        }
        ```

    * 复杂度判定：三层嵌套 `for` 看似直接是 $N^3$，但只有第一层是 $0 \to N$，后两层分别是 $i \to N$ 与 $i \to j$；用中学的证明技巧仍可证出总运算量是 $N^3$ 乘以一个常数，$T(N) = O(N^3)$。
    * 不聪明在哪：算下一个 $j$ 时完全没必要从头再累加一遍，$k$ 循环纯属多余。

### 记忆累加与分治递归

* **算法二：记忆累加（$O(N^2)$）**

    * 思路：固定 $i$ 后推进 $j$，`ThisSum` 从 0 起，每次只在当前部分和的基础上加一个 $A_j$。

        ```c
        int MaxSubsequenceSum2(int A[], int N) {
            int ThisSum, MaxSum = 0;
            int i, j;
            for (i = 0; i < N; i++) {
                ThisSum = 0;
                for (j = i; j < N; j++) {
                    ThisSum += A[j];
                    if (ThisSum > MaxSum) MaxSum = ThisSum;
                }
            }
            return MaxSum;
        }
        ```

    * 两重循环嵌套，$T(N) = O(N^2)$。$N = 10^5$ 时与算法一相差 10 万倍，是很大进步，但仍不是最好的。

* **算法三：分而治之（$O(N \log N)$）**

    * > **定义**：把大而复杂的问题切成小块分头解决，最后把结果合并起来。

    * 「分」：数组从中间一分为二，递归求左边的最大子列和、右边的最大子列和。
    * 「治」：还必须补上第三种情形——**跨越切分中线的最大子列和**。三个结果取最大才是最终答案。
    * 跨界和的求法：从中间切分线开始，先向左扫描（每元素扫一次）再向右扫描（每元素扫一次），两侧各得最大边界和后相加，耗时严格为 $O(N)$。

    * 逐层推演示例（8 个数字）：左半区递归返回 6，右半区递归返回 8，顶层跨越中线的最大子列和为 11，比较 $\{6, 8, 11\}$ 返回 11。

    * **递推方程与展开**：

        $$T(N) = 2\,T(N/2) + cN, \quad T(1) = O(1)$$

        * 把 $N$ 换成 $N/2$ 代入再展开一步：$T(N) = 2\left(2\,T(N/4) + c\frac{N}{2}\right) + cN = 4\,T(N/4) + 2cN$。
        * 每展开一层就多出一个 $cN$，展开 $k$ 步后：$T(N) = 2^k T\left(N/2^k\right) + kcN$。
        * 终止条件：$N/2^k = 1$，即 $2^k = N$，所以 $k = \log_2 N$。
        * 代回得两项：一项是 $O(1)$ 级的 $T(1)$，一项是 $O(N \log N)$ 级的 $kcN$；按加法取大，整体为 $O(N \log N)$。

### 在线处理与四算法实测

* **算法四：在线处理（$O(N)$）**

    * > **定义**：单次从左到右扫描，每读入一个元素即时累加结算，当前部分和一旦转负就立刻归零重置的流式算法。

        ```text
        ThisSum = 0;  MaxSum = 0;
        for (i = 0; i < N; i++) {
            ThisSum += A[i];
            if (ThisSum > MaxSum)      MaxSum = ThisSum;
            else if (ThisSum < 0)      ThisSum = 0;
        }
        return MaxSum;
        ```

    * 只有一个 `for` 循环，循环体内的 `if-else` 都是常数数量级，$T(N) = O(N)$。
    * 理论下界：无论如何总得把每一个元素看一遍，读输入本身就需要 $O(N)$，所以 $O(N)$ 已达该类问题的数学下界。
    * 代价：正确性不明显，理解这个程序的工作方式略有困难；先看例子。

    * 逐元素走查（8 个数：$-1, 3, -2, 4, -6, 1, 6, -1$）：

        | 读入 | `ThisSum` 变化 | 状态判定 | `MaxSum` |
        | :---: | :--- | :--- | :--- |
        | 初始 | $0$ | — | $0$ |
        | $-1$ | $-1 \to 0$ | 负数，丢弃并归零 | $0$（不变） |
        | $3$ | $3$ | 正数，维持 | $3$（更新） |
        | $-2$ | $1$ | 正数，仍有增益潜力 | $3$（不变） |
        | $4$ | $5$ | 正数，维持 | $5$（更新） |
        | $-6$ | $-1 \to 0$ | 负数，拖垮后续，丢弃归零 | $5$（不变） |
        | $1$ | $1$ | 正数，重新累加 | $5$（不变） |
        | $6$ | $7$ | 正数，大幅攀升 | $7$（更新） |
        | $-1$ | $6$ | 正数，维持 | $7$（不变） |

    * **负和丢弃的合法性**：题目要求的是**连续**子列和，当前和一旦为负，后面无论再加什么数都只会更小，不可能变大；还不如从头加起，所以直接抛弃归零。
    * **「在线」的严格内涵**：每输入一个数据就实时完成阶段性处理；输入流在任何时刻 $k$ 意外截断，算法都能立刻返回针对前 $k$ 个数据的正确当前解。走查中读到前 4 个数（$-1,3,-2,4$）时若突然停住，返回 5 就是对的。
    * **副作用**：算法效率这么高一般是有代价的——正确性不是特别明显，别人要理解它到底怎么工作略微有点困难。

* **四算法运行性能实测对照表**

    * 同一台机器上跑，$n$ 从 $10^1$ 到 $10^5$；表中不含输入输出开销。

## 线性表与顺序存储结构

### 一元多项式的三种表示法

* **建模出发点**

    * 一元多项式 $P(x) = \sum_{i=0}^{n} a_i x^i$ 的基本运算有两式相加、相乘、相减等，问题在于「怎么用程序设计语言表示这样的多项式并实现相应操作」。
    * 提取关键信息：多项式的阶数（含最高指数）；以及每一项的两个关键属性——**系数**与**指数**。

* **表示法一：顺序存储直接表示（数组下标隐式映射指数）**

    * 用数组 $A$ 表示多项式，$A[i]$ 就是 $a_i x^i$ 中项的系数，下标 $i$ 即对应指数。
    * 例：$4x^5 - 3x^2 + 1$ 用 6 个分量表示，分量为 0 的那项的值是 1，代表指数为 0 的项的系数；下标为 1 的分量值是 0，代表 $x$ 一次方系数为 0。
    * 优点：表述简单，有关运算（尤其是相加）也容易实现——两个数组对应分量相加即可。
    * 致命缺陷：面对 $x + 3x^{2000}$ 这种稀疏多项式，至少要用 2001 个分量，其中只有两项非零，造成**空间的巨大浪费**；做加法时循环从 0 做到 2000，实际上大量计算是在加无效的零。

* **表示法二：顺序存储结构数组表示（只存非零项）**

    * 思路：既然所有系数为零的非零项全都要表示进来干什么，能不能只表示非零项？
    * 每个非零项有两个信息（系数、指数），所以把多项式看成一个由「系数 + 指数」二元组组成的有序集合，用**结构数组**存放，每个分量不再是单个系数而是一个结构。
    * 运算要点：按指数大小有序存储（例中把指数大的排在前面、小的排在后面），相加时从头开始比较，指数高的先输出，指数相等则对应系数相加。
    * 例：$P_1$ 三项、$P_2$ 四项，比较第一项时 $x^{19}$ 比 $x^{12}$ 大则先输出 $x^{19}$；接着比较 $x^{12}$ 与 $x^8$，先出 $x^{12}$；再遇两边的 $x^8$，系数 15 与 $-4$ 相加得 11 输出；当某一方走完后，把剩下那一方的剩余项直接拷过来即可。
    * 结论：既省空间（$x + 3x^{2000}$ 只要两个分量），运算效率也不算差。

* **表示法三：链表存储非零项**

    * 同理也不一定非用数组不可，可以用链表：每个节点包含指数、系数，外加一个指针域把各节点串起来，仍按指数递降或递增有序排列。

        ```c
        typedef struct PolyNode *Polynomial;
        struct PolyNode {
            int coef;
            int expon;
            Polynomial next;
        };
        ```

    * 相加逻辑与结构数组完全相同：分别指向两表的头，比较指数大小，大的输出，相等则系数相加。

* **三种表示法的启示**

    * > **结论**：同一个问题可以有不同表示方法；数据结构里最常见的就两种——用数组存或用链表存。
    * 不仅仅是多项式，许多更有共性的问题都归结为同一个模型：**管理一个有序的线性序列**——这就是线性表。

### 线性表的定义与抽象数据类型

* **线性表（Linear List）**

    * > **定义**：由同类元素所构成的一个有序序列的线性结构。

    * 相关术语：表中的元素个数称为线性表的长度；无元素时称为**空表**；起始位置的元素称为**表头**，最后一个位置的元素称为**表尾**。

* **线性表 ADT 规格**

    * 数据对象集：由 $n$ 个元素组成的有序序列。类型名叫 `List`，具体的线性表叫 $L$，表内元素 $x$ 的类型叫 `ElementType`（可以是整型、实型、也可以是结构体），另用整数表示某元素在表中的位置。
    * 主要操作集：
        * `MakeEmpty()`：建立一个空线性表。
        * `FindKth(k, L)`：在表中找到位序为 $k$ 的元素。
        * `Find(x, L)`：告诉一个元素 $x$，找它在这个表中第一次出现的位置。
        * `Insert(x, k, L)`：在线性表 $L$ 的第 $k$ 个位置之前插入新元素 $x$。
        * `Delete(k, L)`：删除线性表中位序为 $k$ 的元素。
        * `Length(L)`：返回线性表 $L$ 的长度 $n$。

### 顺序存储结构与四个基本操作

* **结构定义与物理含义**

    * 两个必须知道的东西：数组是什么（数组可以放不同长度的线性表，它是连续存放的），以及最后一个元素在哪里——所以要有一个指针 `Last` 来指示线性表中最后一个元素所在的位置。

        ```c
        #define MAXSIZE 1000
        typedef int ElementType;

        typedef struct LNode *List;
        struct LNode {
            ElementType Data[MAXSIZE];
            int Last;
        };
        ```

    * > **易错点**：⚠️ `Last` 是最后一个元素的物理**下标**（下标从 0 开始）。`Last = 0` 表示表里有一个元素；表长为 $\text{Last} + 1$；空表必须初始化为 `Last = -1`。
    * 存取特性：访问下标 $i$ 的元素直接 `L->Data[i]`，取表长直接 `L->Last + 1`，都是 $O(1)$ 常数时间。

* **操作一：初始化 `MakeEmpty`**

    * 用 `malloc` 申请结构体，把结构的 `Last` 设为 $-1$（因为下标从 0 开始，$-1$ 表示一个元素都没有），再把结构指针返回。

        ```c
        List MakeEmpty(void) {
            List L = (List)malloc(sizeof(struct LNode));
            L->Last = -1;
            return L;
        }
        ```

* **操作二：按值查找 `Find`**

    * 循环变量 $i$ 从 0 开始逐个后移，比较 `Data[i]` 是否等于 $X$，一直到 `Last` 为止；循环退出有两种可能：`Data[i] != X` 条件被破坏（找到了）或 $i < \text{Last}$ 条件被破坏（$i$ 超过 `Last`，没找到）。
    * $i > \text{Last}$ 时返回 $-1$（没找着），否则 $i$ 就是相应位置。

        ```c
        int Find(ElementType X, List PtrL) {
            int i = 0;
            while (i <= PtrL->Last && PtrL->Data[i] != X) i++;
            if (i > PtrL->Last) return -1;
            else return i;
        }
        ```

    * 性能：运气好第一个就中，运气不好最后一个才中，平均比较次数为 $\frac{n+1}{2}$。

* **操作三：插入 `Insert`（必须从后往前挪）**

    * 目标：在逻辑第 $i$ 个位置（$i$ 从 1 到 $n+1$，即插在表头到表尾之后）插入 $X$。因为数组下标从 0 开始，实际要放到**下标 $i-1$** 的位置。
    * 数组是连续存放的，必须先把 $i-1$ 之后的元素全部往后挪一位，腾出 $i-1$ 这个位置再放。
    * 边界校验：表满的判别条件是 `Last == MAXSIZE - 1`（最后一个元素正好是数组最后一个元素）；插入位序必须落在 $1$ 与 $\text{Last}+2$ 之间。
    * 挪动方向：**从后向前**。若从前往后挪，第一步把下标 $i-1$ 复制给 $i$ 时就会冲刷掉位置 $i$ 的原数据，后续单元全被首个元素重复污染。

        ```c
        void Insert(ElementType X, int i, List PtrL) {
            int j;
            if (PtrL->Last == MAXSIZE - 1) return;          /* 表满 */
            if (i < 1 || i > PtrL->Last + 2) return;        /* 位置非法 */
            for (j = PtrL->Last; j >= i - 1; j--) {         /* 从后往前挪 */
                PtrL->Data[j + 1] = PtrL->Data[j];
            }
            PtrL->Data[i - 1] = X;
            PtrL->Last++;
        }
        ```

    * 性能：平均移动次数为 $\frac{1}{2} n$，$T = O(n)$。

* **操作四：删除 `Delete`（必须从前往后挪）**

    * 目标：删除逻辑第 $i$ 个位置的元素（$i$ 从 1 到 $n$），对应下标 $i-1$。位置空出来后必须把它之后的元素全部往前挪。
    * 边界校验：删除位序必须落在 $1$ 与 $\text{Last}+1$ 之间。
    * 挪动方向：**从前向后**。控制变量 $j$ 从 $i$ 递增到 `Last`，执行 `Data[j-1] = Data[j]`。

        ```c
        void Delete(int i, List PtrL) {
            int j;
            if (i < 1 || i > PtrL->Last + 1) return;         /* 位置非法 */
            for (j = i; j <= PtrL->Last; j++) {             /* 从前往后挪 */
                PtrL->Data[j - 1] = PtrL->Data[j];
            }
            PtrL->Last--;
        }
        ```

    * > **易错点**：⚠️ 插入与删除的循环顺序**恰好相反**——插入从 `Last` 递减到 $i-1$，删除从 $i$ 递增到 `Last`。写反任何一个都会覆盖掉尚未搬运的原始数据。
    * 性能：平均移动次数为 $\frac{1}{2}(n-1)$，$T = O(n)$。
