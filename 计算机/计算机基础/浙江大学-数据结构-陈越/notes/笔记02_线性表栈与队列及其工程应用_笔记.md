# 线性表、栈与队列及其工程应用

## 线性表链式存储与基本操作

### 链式存储的动机与结点结构

* **链式存储（Linked Storage）**

    * > **定义**：把逻辑上相邻的两个元素用链连接起来，而不要求它们在物理上相邻。

    * 数组存储时相邻元素不仅逻辑相邻、物理也相邻，插入删除都要把后面大量元素整体前挪或后挪。
    * 链式存储里只要轻易改链即可，不需要对很多元素做挪动。
    * 代价：数组里查第 $i$ 个元素是 $A[i-1]$、求长度靠 `Last` 都很容易；链表里光知道头指针，既不知道第 $i$ 个元素在哪、也不知道链表有多长，这两件事都变复杂了。

* **单向链表（Singly Linked List）结点结构**

    * 每个结点是一个结构，至少含两个分量：代表该结点所对应数据的数据域，以及代表下一个结点位置的指针域 `Next`。

        ```c
        typedef int ElementType;
        typedef struct LNode *List;
        struct LNode {
            ElementType Data;
            List Next;
        };
        ```

    * 逻辑与物理映射拓扑如下：

        ```text
        PtrL
          │
          ▼
        ┌──────┬──────┐    ┌──────┬──────┐    ┌──────┬──────┐
        │ Data │ Next ├───►│ Data │ Next ├───►│ Data │ NULL │
        └──────┴──────┘    └──────┴──────┘    └──────┴──────┘
        ```

* **表长统计（`Length`）**

    * 临时指针 `p = PtrL`、计数器 `j = 0`，以 `p != NULL` 为推进条件，逐结点执行 `p = p->Next` 并 `j++`；到最后一个结点时它的 `Next` 是 `NULL`，循环退出，此时 `j` 即表长。

        ```c
        int Length(List PtrL) {
            List p = PtrL;
            int j = 0;
            while (p != NULL) {
                p = p->Next;
                j++;
            }
            return j;
        }
        ```

    * 时间复杂度等于表长，$T(n) = O(n)$。

### 链表查找机制

* **按序号查找（`FindKth`）**

    * > **定义**：临时指针 `p` 从表头起、计数器 $i = 1$，循环维持两个条件 `p != NULL && i < K`；退出时若 $i == K$ 返回 `p`，若 $p == NULL$（$K$ 超长或 $K \le 0$）返回 `NULL`。

        ```c
        List FindKth(int K, List PtrL) {
            List p = PtrL;
            int i = 1;
            while (p != NULL && i < K) {
                p = p->Next;
                i++;
            }
            if (i == K) return p;
            else return NULL;
        }
        ```

    * 必须一个个往后找，平均扫描 $\frac{n}{2}$ 个结点，$T(n) = O(n)$。
    * 循环退出的两种可能恰好对应「找到了」（$i = K$）与「没找到」（$p = \text{NULL}$）两种结果。

* **按值查找（`Find`）**

    * 循环以 `p != NULL && p->Data != X` 维持推进，命中时因条件不满足退出并返回结点地址；遍历全表未命中时 `p` 最终为 `NULL`。

        ```c
        List Find(ElementType X, List PtrL) {
            List p = PtrL;
            while (p != NULL && p->Data != X) {
                p = p->Next;
            }
            return p;
        }
        ```

    * 平均查找长度 $\frac{n+1}{2}$，$T(n) = O(n)$。

### 链表结点插入机制

* **中间及尾部插入**

    * > **定义**：在链表第 $i$ 个位置插入新结点 $X$，使原第 $i$ 个结点后移变为第 $i+1$ 个结点。

    * 指针重组两步：先用 `malloc` 分配新结点并置值；用 `s->Next = p->Next` 让新结点接入原后继；再用 `p->Next = s` 让前驱结点接向新结点。
    * 前驱结点即第 $i-1$ 个结点，用 `FindKth(i - 1, PtrL)` 取得。

        ```text
                p (第 i-1 个结点)       原本的第 i 个结点
              ┌──────┬──────┐          ┌──────┬──────┐
              │ Data │ Next ├───┐      │ Data │ Next │
              └──────┴──────┘   │      └──────┴──────┘
                                │             ▲
                          (②)   │             │ (①)
                                ▼             │
                              ┌──────┬──────┐ │
                              │  X   │ Next ├─┘
                              └──────┴──────┘
                                    s
        ```

    * > **易错点**：⚠️ 指针修改次序绝对不能颠倒。若先执行 `p->Next = s;`，原后继结点地址瞬间丢失；随后 `s->Next = p->Next;` 会让新结点的 `Next` 指向自身形成自环，后半段链表全部脱节。

* **表头插入与完整实现**

    * $i = 1$ 时不存在第 0 个前驱结点，直接让新结点的 `Next` 指向原表头 `PtrL`，并返回新结点地址作为新链表头。
    * 外部调用规范：主调函数必须显式接收返回值刷新入口，标准写法为 `PtrL = Insert(X, i, PtrL);`。

        ```c
        List Insert(ElementType X, int i, List PtrL) {
            List p, s;
            if (i == 1) {
                s = (List)malloc(sizeof(struct LNode));
                s->Data = X;
                s->Next = PtrL;
                return s;
            }
            p = FindKth(i - 1, PtrL);
            if (p == NULL) return NULL;
            s = (List)malloc(sizeof(struct LNode));
            s->Data = X;
            s->Next = p->Next;
            p->Next = s;
            return PtrL;
        }
        ```

### 链表结点删除机制

* **结点摘除与内存释放**

    * > **定义**：将第 $i$ 个位置的结点从逻辑链条中脱钩，并把其占用的动态堆内存显式归还操作系统。

    * 稳健执行四步：定位第 $i-1$ 个前驱 `p`；用临时指针 `s` 记录待删结点（`s = p->Next`）；修改前驱指针绕过待删结点（`p->Next = s->Next`）；`free(s)` 彻底回收，杜绝内存泄漏。

        ```text
                p (第 i-1 个结点)         s (待删除结点)          第 i+1 个结点
              ┌──────┬──────┐          ┌──────┬──────┐          ┌──────┬──────┐
              │ Data │ Next ├───┐      │ Data │ Next ├────►     │ Data │ Next │
              └──────┴──────┘   │      └──────┴──────┘          └──────┴──────┘
                                │                                      ▲
                                └──────────────────────────────────────┘
        ```

* **表头删除与非法边界**

    * 空表删除直接返回 `NULL`；$i = 1$ 时令 `s = PtrL`，更新 `PtrL = PtrL->Next` 后 `free(s)`；其余情形先由 `FindKth(i - 1, PtrL)` 定位前驱，若 `p == NULL` 或 `p->Next == NULL` 直接返回 `NULL`。

        ```c
        List Delete(int i, List PtrL) {
            List p, s;
            if (i == 1) {
                if (PtrL == NULL) return NULL;
                s = PtrL;
                PtrL = PtrL->Next;
                free(s);
                return PtrL;
            }
            p = FindKth(i - 1, PtrL);
            if (p == NULL || p->Next == NULL) return NULL;
            s = p->Next;
            p->Next = s->Next;
            free(s);
            return PtrL;
        }
        ```

## 广义表与多重链表

### 广义表定义与联合体实现

* **广义表（Generalized List，GList）**

    * > **定义**：线性表的一种推广结构，表中元素不仅可以是不可再分的原子，还可以是另一个广义表（子表）。

    * 多元多项式模型：把二元多项式 $P(x, y) = (9y^2 + 4)x^{12} + (15y^3 - y)x^8 + 3x^2$ 视为关于 $x$ 的一元多项式，各项系数域由数值常数转变为指向变量 $y$ 的独立一元多项式子表指针。

        ```text
        主链表 (变量 x):
        ┌───┬───┬───┐    ┌───┬───┬───┐    ┌───┬───┬───┐
        │ 12│ • │ • ├───►│ 8 │ • │ • ├───►│ 2 │ 3 │NULL│
        └───┴─│─┴───┘    └───┴─│─┴───┘    └───┴───┴───┘
              │                │
              ▼                ▼
          子链表 (变量 y)   子链表 (变量 y)
          9y^2 + 4         15y^3 - y
        ```

* **标记与联合体机制**

    * > **定义**：用整型标记域区分单元素原子与子表指针两种异构数据形态的工程范式。

    * `Tag == 0` 读原子数据域 `URegion.Data`；`Tag == 1` 读子表指针 `URegion.SubList` 递归寻址；`Next` 指向同层下一个结点。

        ```c
        typedef struct GNode *GList;
        struct GNode {
            int Tag; /* 0 代表单元素，1 代表子表指针 */
            union {
                ElementType Data;
                GList SubList;
            } URegion;
            GList Next;
        };
        ```

### 多重链表与稀疏矩阵十字链表

* **多重链表（Multilist）**

    * > **定义**：链表中的结点同时隶属于两个或两个以上相互交织的逻辑链表的链式存储结构。

    * > **易错点**：⚠️ 结点有多个指针不等于多重链表。双向链表的 `Prior` 与 `Next` 串联的是同一张线性表的相反遍历方向，仍属单一链表；多重链表的本质特征是结点必须同时隶属于两个或两个以上相互交织的独立逻辑链表。

* **稀疏矩阵十字链表（Cross List）**

    * > **定义**：存放绝大多数元素为零的巨型稀疏矩阵，每个非零项结点由水平行链表与垂直列链表双向穿插而成的循环网状结构。

    * 三类结点：普通项结点含 `Row`、`Col`、`Value`，通过 `Right` 构成水平行循环链表、通过 `Down` 构成垂直列循环链表；表头结点是各行各列循环链表的起始入口；全局总头结点位于左上角，三元组分别记录总行数、总列数与非零项总个数。

        ```text
                       Col 0        Col 1
                         │            │
                         ▼            ▼
                     ┌───────┐    ┌───────┐
        Row 0 ────►  │(0,0,1)├───►│(0,1,2)├───► (循环回行头)
                     └───────┘    └───────┘
                         │            │
                         ▼            ▼
                     ┌───────┐
        Row 1 ────►  │(1,0,3)├───► (循环回行头)
                     └───────┘
                         │            │
                         ▼            ▼
                     (循环回列头)  (循环回列头)
        ```

## 堆栈原理与存储结构

### 堆栈抽象数据类型与出栈合法性

* **堆栈（Stack）**

    * > **定义**：一种受操作位置约束的线性表，插入和删除限定且仅限定在表的一端（栈顶）进行，遵循后入先出（LIFO）规则。

    * 核心操作集：`CreateStack(MaxSize)`、`IsFull(S)`、`Push(S, item)`、`IsEmpty(S)`、`Pop(S)`。

* **出栈合法性判定**

    * > **结论**：对任意出栈元素，在它之后出栈且在它之前已经压入的所有元素，必须以逆序形式弹出。

    * 输入序列 `a, b, c` 时输出序列 `c, a, b` 绝对无法生成——`c` 首先出栈说明 `a`、`b` 均在栈内且 `b` 在栈顶，下一出栈项必定是 `b`。
    * 卡特兰数公式：输入长度为 $n$ 的互异序列，合法出栈排列总数为
        $$C_n = \frac{1}{n+1}\binom{2n}{n}$$
    * 数值实例：$n = 4$ 时全排列 $4! = 24$，合法出栈序列 $C_4 = \frac{1}{5}\binom{8}{4} = 14$ 种，非法序列共 10 种。

### 堆栈顺序存储与对撞双栈

* **顺序栈（Sequential Stack）**

    * 整型变量 `Top` 代表当前栈顶元素在数组中的下标：栈空 `Top = -1`；压入首个元素置于 `Data[0]`、`Top = 0`；栈满条件 `Top == MaxSize - 1`。

        ```c
        void Push(Stack PtrS, ElementType item) {
            if (PtrS->Top == MaxSize - 1) return;
            PtrS->Data[++(PtrS->Top)] = item;
        }

        ElementType Pop(Stack PtrS) {
            if (PtrS->Top == -1) return -1;
            return PtrS->Data[(PtrS->Top)--];
        }
        ```

* **对撞双栈（Dual Stack）**

    * > **定义**：两个堆栈复用同一个连续一维数组，分别从两端向中间相对增长的动态空间复用设计。

    * 栈 1 栈底设在下标 0，栈顶 `Top1` 向右递增，空栈初值 `Top1 = -1`；栈 2 栈底设在下标 `MaxSize - 1`，栈顶 `Top2` 向左递减，空栈初值 `Top2 = MaxSize`。

        ```text
               Top1 ──►                         ◄── Top2
        ┌──────┬──────┬──────┬──────┬──────┬──────┬──────┬──────┐
        │  S1  │  S1  │  S1  │ 闲置 │ 闲置 │  S2  │  S2  │  S2  │
        └──────┴──────┴──────┴──────┴──────┴──────┴──────┴──────┘
          0      1      2                    MaxSize-2 MaxSize-1
        ```

    * > **易错点**：⚠️ 栈满条件绝非 `Top1 + Top2 == MaxSize`。两者是数组两端的绝对物理下标，直接相加没有几何意义；两栈顶相遇紧挨的唯一判定是 `Top2 - Top1 == 1`。

        ```c
        void PushDual(DualStack PtrS, ElementType item, int tag) {
            if (PtrS->Top2 - PtrS->Top1 == 1) return;
            if (tag == 1) PtrS->Data[++(PtrS->Top1)] = item;
            else if (tag == 2) PtrS->Data[--(PtrS->Top2)] = item;
        }

        ElementType PopDual(DualStack PtrS, int tag) {
            if (tag == 1) {
                if (PtrS->Top1 == -1) return -1;
                return PtrS->Data[(PtrS->Top1)--];
            } else if (tag == 2) {
                if (PtrS->Top2 == MaxSize) return -1;
                return PtrS->Data[(PtrS->Top2)++];
            }
            return -1;
        }
        ```

### 堆栈链式存储与栈顶定位

* **链栈栈顶选型权衡**

    * > **结论**：单向链表必须把**表头**作为栈顶。

    * 链尾方案失效机理：若把单向链表表尾作为栈顶，出栈时必须删除尾结点并把栈顶指针回退到其前驱；单向指针无法逆寻，得从表头重新遍历 $n$ 个结点找前驱，单次出栈退化为 $O(n)$。
    * 表头方案：入栈直接头插，出栈直接删除首个有效结点并后移头指针，入栈出栈均为 $O(1)$。

* **带头结点链栈实现**

    * 链栈结点按需动态申请，只要可用物理内存未耗尽，逻辑上永不栈满；栈空条件是头结点的后继指针为空，即 `S->Next == NULL`。

        ```c
        void Push(Stack S, ElementType item) {
            Stack TmpCell = (Stack)malloc(sizeof(struct SNode));
            TmpCell->Data = item;
            TmpCell->Next = S->Next;
            S->Next = TmpCell;
        }

        ElementType Pop(Stack S) {
            if (S->Next == NULL) return -1;
            Stack FirstCell = S->Next;
            S->Next = FirstCell->Next;
            ElementType TopElem = FirstCell->Data;
            free(FirstCell);
            return TopElem;
        }
        ```

## 堆栈的核心算法应用

### 后缀表达式求值机制

* **后缀表达式（Postfix Expression / RPN）**

    * > **定义**：算术运算符严格位于参与计算的操作数之后的表达式书写形式。

    * 核心优越性：运算符出现的物理次序即其实际执行计算的次序，彻底消除优先级差异与括号嵌套的解析负担。

* **后缀求值状态机推进**

    * > **定义**：利用单个操作数栈对后缀表达式进行单向扫描求值的算法流程。

    * 状态转移规则：从左向右逐项读取，遇到操作数压栈；遇到运算符连续弹出两个操作数（先弹为右操作数、后弹为左操作数），完成运算后结果压回栈顶；扫描终结时栈底保留的唯一数值即全式结果。单遍扫描 $T(n) = O(n)$。

### 中缀表达式转后缀表达式算法

* **中缀转后缀调度机理**

    * > **定义**：利用运算符栈把中缀表达式在线转换为后缀表达式的调度算法。

    * 运算数恒等性：转换过程中所有运算数的相对物理出现顺序保持不变，直接接入输出流。
    * 运算符入栈与弹出规则：当前运算符优先级高于栈顶则压栈；低于或等于栈顶则弹出栈顶运算符并输出，重复比较直至当前优先级大于栈顶，再把当前运算符压栈；平级严格遵循「左优先」出栈。

* **括号优先级动态切换规则**

    * > **定义**：左右括号在栈外与栈内处于不同生命周期时采用的动态优先级切换协议。

    * 左括号 `(` 在栈外具有最高优先级，任何普通运算符都无法阻挡其进栈；一旦进入栈内，左括号优先级立即降为最低，充当括号内表达式计算的隔离底座；遇到右括号 `)` 时不断弹出栈顶运算符输出，直到遇到左括号，弹出并丢弃左括号，括号符号不进入最终输出流。

        ```text
        输入项    操作动作与优先级比较判定          运算符栈 (栈底 -> 栈顶)    当前输出序列
        --------------------------------------------------------------------------------------
        a         运算数，直接输出                  [ ]                       a
        *         栈空，乘号压栈                    [*]                       a
        (         栈外优先级最高，压栈              [*, (]                    a
        b         运算数，直接输出                  [*, (]                    a b
        +         栈内(优先级最低，加号优先级高，入 [*, (, +]                 a b
        c         运算数，直接输出                  [*, (, +]                 a b c
        )         括号结束，弹栈直到左括号，丢弃(   [*]                       a b c +
        /         同级左优先，弹出*输出，/压栈      [/]                       a b c + *
        d         运算数，直接输出                  [/]                       a b c + * d
        (结束)    表达式读完，排空栈内残留运算符    [ ]                       a b c + * d /
        ```

### 系统调用栈与回溯应用

* **系统调用栈（Call Stack）**

    * > **定义**：操作系统或程序运行时环境用于管理嵌套函数调用与递归调用的受限栈内存空间。

    * 现场保存与倒序恢复：函数层层嵌套调用时，系统将调用点返回地址、局部变量与寄存器状态顺序压栈；子函数执行完毕返回时按后进先出逆序弹出恢复现场，使程序无缝回到先前断点。

* **路径试探与回溯（Backtracking）**

    * > **定义**：在探索求解空间时把每一步试探路径压入堆栈，一旦遭遇死胡同就弹出栈顶状态退回最近决策点的机制。

    * 图的深度优先搜索（DFS）在实现上正是借助于堆栈，只是表现形式常常写成递归。

## 队列原理与两种存储实现

### 队列抽象数据类型与假溢出

* **队列（Queue）**

    * > **定义**：只允许在表的一端（队尾，Rear）插入、在另一端（队头，Front）删除的操作受限线性表，遵循先进先出（FIFO）规则。

    * 生活映射：排队时加入队伍必须站队尾，接受服务从队头开始。
    * 与堆栈的分野：堆栈插入删除只能在一端进行；队列则一端插入（入队）一端删除（出队），因此表现出「先来先服务」。
    * 核心操作集：`CreateQueue(MaxSize)`、`IsFull(Q)`、`AddQ(Q, item)`、`IsEmpty(Q)`、`DeleteQ(Q)`。

* **顺序存储与假溢出（False Overflow）**

    * > **定义**：用一维数组实现顺序队列时，由于两端指针持续向高下标单向移动，导致队尾指针触达数组边界而前端已闲置大片空间的虚假满队现象。

    * 与堆栈结构差异对比：堆栈是一数组加一个 `Top`（只在一端增删，一个变量就够）；队列在两头发射，所以要用 `front` 与 `rear` 两个下标变量，结构体共三个分量——数组 `data` 以及 `front`、`rear` 两个数组下标。
    * 下标约定：空队初始 `front = rear = -1`；入队执行 `rear++` 并写入；出队执行 `front++` 并取出。`front` 指向队头元素的前一个位置，`rear` 指向队尾的实际元素。
    * 连续入队三个元素再删除一个时，`front` 仍保持 $-1$ 不动，因为删除只是让它指向了下一个元素的前一个位置。
    * 假溢出现象：队列排到数组最后一位时 `rear` 已无路可走，但前端其实还空着大片空间——后面排不了，那就排到前面去，由此引出循环队列。

### 循环队列空满判定与化解方案

* **循环队列空满矛盾**

    * > **定义**：数组首尾相连成环后，单纯依靠 `front == rear` 无法区分队列全空与全满的数学歧义。

    * 矛盾数理本质：大小为 $n$ 的数组，`front` 与 `rear` 的下标距离差值只有 $n$ 种（$0, 1, \dots, n-1$），而队列装载元素个数从 0 到 $n$ 共 $n+1$ 种状态；用 $n$ 种距离标识 $n+1$ 种状态在数学上必然冲突——就像用一个比特去区分三种情况，做不到。
    * 触发时刻：6 个分量的数组已放 5 个元素时，再放第 6 个会让 `rear + 1 == front`，`front == rear` 成立；按此组织法该判空，此刻却真的满了。

* **增加额外标记法**

    * 计数器变量法：引入 `size` 记录当前队列元素个数，`size == 0` 为空、`size == n` 为满；插入 `size++`、删除 `size--`。
    * 状态标记位法：引入 `tag`（0/1），插入时置 `tag = 1`、删除时置 `tag = 0`；`front == rear` 时看 `tag` 就知道最后一次操作是插入还是删除，从而分辨是满还是空。

* **空间舍弃判定法（课程采用）**

    * > **定义**：在容量为 $n$ 的环形数组中人为限定最多只容纳 $n-1$ 个元素，把客观状态数压缩为 $n$ 种以消除歧义的工程方案。

    * 队空判定：`front == rear`
    * 队满判定：`(rear + 1) % MAXSIZE == front`

        ```text
                   [0]                     [0]
                /       \               /       \
             [5]         [1]         [5]         [1]  <-- front
              |   (空)    |           |   (满)    |
             [4]         [2]         [4]         [2]
                \       /               \       /
                  [3]                     [3]
               front=rear=0            rear=5, (5+1)%6 == front
        ```

### 循环队列操作与模运算实现

* **模运算指针推进**

    * > **定义**：利用整数求模 `% MAXSIZE` 实现下标到达数组末端后平滑折返归零的环形推进算法。

    * 边界推进公式：下标 $k$ 向后前进一步的物理下标为 $(k + 1) \pmod{\text{MAXSIZE}}$。例：`(5 + 1) % 6 == 0`。

* **循环队列基础操作实现**

    * 入队：先判满（`(rear + 1) % MAXSIZE == front` 则拒绝写入），否则 `rear` 加一并求余后写入 `Data[rear]`。
    * 出队：先判空（`front == rear` 则拒绝删除），否则 `front` 加一并求余，此时 `front` 指向的正好是队头元素所在位置，直接 `return Data[front]`。

        ```c
        void AddQ(Queue PtrQ, ElementType item) {
            if ((PtrQ->rear + 1) % MAXSIZE == PtrQ->front) {
                return; /* 队满拒绝写入 */
            }
            PtrQ->rear = (PtrQ->rear + 1) % MAXSIZE;
            PtrQ->Data[PtrQ->rear] = item;
        }

        ElementType DeleteQ(Queue PtrQ) {
            if (PtrQ->front == PtrQ->rear) {
                return ERROR; /* 队空拒绝删除 */
            }
            PtrQ->front = (PtrQ->front + 1) % MAXSIZE;
            return PtrQ->Data[PtrQ->front];
        }
        ```

### 链式存储实现队列

* **front / rear 的挂载位置抉择**

    * > **结论**：单向链表实现队列时，`front` 必须挂在链表**头**，`rear` 挂在链表**尾**。

    * `front` 承担删除操作、`rear` 承担插入操作。
    * 链表头位置做插入或删除都很方便：删除很快能找到下一个，插入也因为知道当前位置而方便；链表末尾做插入没问题，**做删除有问题**——单向链表删掉之后不知道前一个在哪里。
    * 如果把 `front` 放在链表尾，后面就炸了；倒过来让 `front` 在头、`rear` 在尾则正好。

* **数据结构定义**

    * 链表结点含两个域：数据域 `data` 与把结点串起来的指针域 `next`。
    * 代表队列的结构体只有两个指针 `front` 与 `rear`，分别指向链表的头和尾；这两个结构合起来构成链式队列的完整定义。

        ```c
        typedef struct QNode *Queue;
        struct QNode {
            ElementType Data;
            struct QNode *Next;
        };
        typedef struct {
            Queue Front, Rear;
        } LinkQueue;
        ```

        ```text
        PtrQ ──► ┌──────────────┐
                  │ Front ──────┼──► [队头结点] ──► ... ──► [队尾结点] ◄─┐
                  │ Rear  ──────┼────────────────────────────────────────┘
                  └──────────────┘
        ```

* **出队 `DeleteQ` 的执行序列**

    * 第一步判空：当 `front` 不指向任何东西（等于 `NULL`）时队列为空。
    * 非空时先让 `front` 找到队列头的第一个元素（记作 `frontCell`）。
    * 关键一步：把 `front` 指针的值改成 `front->Next`。
    * 判别队列是不是只有一个元素：当 `front == rear` 时说明队列只有一个元素且它已被删除，`front` 与 `rear` 都要置为 `NULL`；若队列不止一个元素，摘掉头结点后 `rear` 仍然指向最后一个元素不动，只需改 `front`。
    * 把第一个结点的元素值先用赋值语句保存到一个变量，再 `free` 掉这个结点，最后 `return` 该变量的值。

        ```c
        Status DeQueue(LinkQueue *Q, ElementType *e) {
            QNode *FrontCell;
            if (Q->Front == NULL) return ERROR;      /* 队空 */
            FrontCell = Q->Front;
            *e = FrontCell->Data;                    /* 先保存元素值 */
            Q->Front = FrontCell->Next;              /* front 前移 */
            if (Q->Front == NULL) Q->Rear = NULL;    /* 仅剩一个元素时 rear 也要置空 */
            free(FrontCell);
            return OK;
        }
        ```

    * > **易错点**：⚠️ 只改 `front` 而不判 `front == rear` 的情形，会在删掉最后一个元素后留下一个指向已 `free` 内存的野 `rear` 指针。
    * 入队操作反过来即可：判空后在 `rear` 后挂新结点，并更新 `rear`。

## 一元多项式运算工程实现

### 多项式数据结构与程序主框架

* **多项式单链表结构**

    * > **定义**：按指数严格降序链接非零单项式的数据结构，每一结点封装系数、指数与后继指针。

        ```c
        typedef struct PolyNode *Polynomial;
        struct PolyNode {
            int coef;          /* 系数 */
            int expon;         /* 指数 */
            Polynomial link;   /* 后继结点指针 */
        };
        ```

* **程序控制主架构**

    * > **定义**：自顶向下协调多项式输入解析、乘法求解、加法归并与格式化输出的主干调度流程。整体框架就是 `main` 函数：先读入第一个多项式，再读入第二个，然后做乘法运算并输出结果，接着做加法运算并输出结果。

        ```c
        int main() {
            Polynomial p1, p2, pp, ps;
            p1 = ReadPoly();
            p2 = ReadPoly();
            pp = Mult(p1, p2);
            PrintPoly(pp);
            ps = Add(p1, p2);
            PrintPoly(ps);
            return 0;
        }
        ```

* **存储结构选型对比**

    * > **定义**：在多项式非零项序列管理中，静态数组、动态数组与单向链表三种存储方案的工程特性评估。

    | 存储结构 | 空间灵活性 | 编程复杂度 | 适用场景与特征 |
    | :--- | :--- | :--- | :--- |
    | **静态数组** | 空间静态固化，项数少时浪费严重，项数超限引发溢出 | 极低，下标访问直观，调试排错简易 | 项数上限预先精确已知的简单计算 |
    | **动态数组** | 按已知项数通过动态内存按需分配，杜绝存储浪费 | 低，兼具数组连续访问与空间按需分配优势 | 输入起始即明确给出总项数的批量运算 |
    | **单向链表** | 动态扩容极强，节点随用随申请，无预分配限制 | 较高，需额外存储指针域，指针重组与释放要求严格 | 项数动态剧烈增减、频繁归并插入的通用计算 |

### 尾插法构建、二级指针与哑节点技巧

* **二级指针参数传递**

    * > **定义**：在追加结点函数中传递尾指针变量自身的物理内存地址，以便在被调函数作用域内就地更新主调函数尾指针的编程机制。

    * > **易错点**：⚠️ 尾指针必须以二级指针 `Polynomial *pRear` 形式传入。C 语言函数参数是单向值传递，若传一级指针，函数内执行 `*pRear = P` 只能修改形参副本，主调作用域的尾指针无法同步推进，后续插入节点会覆盖前序节点。

        ```c
        void Attach(int c, int e, Polynomial *pRear) {
            Polynomial P = (Polynomial)malloc(sizeof(struct PolyNode));
            P->coef = c;
            P->expon = e;
            P->link = NULL;
            (*pRear)->link = P;     /* 新结点接在原尾结点之后 */
            *pRear = P;             /* 尾指针向前推进至新结点 */
        }
        ```

* **临时哑节点技术**

    * > **定义**：构建链表前先分配一个临时空结点作为起始占位锚点，统一首结点与后续结点的插入逻辑，并在构建结束时释放该占位结点。

        ```text
        初始阶段 (申请临时哑节点):
        P, rear ----> [ 临时哑节点 (空) ] -> NULL

        读入项循环追加后:
        P ----------> [ 临时哑节点 ] -> [ 3, 4 ] -> [ -5, 2 ] -> [ 6, 1 ] -> NULL
                                                                  ^
                                                                 rear
        释放哑节点:
                       t 指向并释放
                      [ 临时哑节点 ]
                            |
        P -----------------> [ 3, 4 ] -> [ -5, 2 ] -> [ 6, 1 ] -> NULL (真实链表头)
        ```

* **多项式读入解析（`ReadPoly`）**

    * > **定义**：解析标准输入中的项数 $N$ 及后续成对的系数与指数，构造严格降序的多项式单链表。

        ```c
        Polynomial ReadPoly() {
            Polynomial P, rear, t;
            int c, e, n;
            scanf("%d", &n);
            P = (Polynomial)malloc(sizeof(struct PolyNode));
            P->link = NULL;
            rear = P;
            while (n--) {
                scanf("%d %d", &c, &e);
                Attach(c, e, &rear);
            }
            t = P;
            P = P->link;
            free(t);
            return P;
        }
        ```

### 多项式相加的双指针归并

* **加法的基本思想**

    * > **定义**：两个指数相同的项把对应系数相加，否则直接把该项拷贝过来；整个过程从头开始比较，看哪个指数高就输出哪一项。

    * 逐项推演示例（$P_1$ 三项、$P_2$ 四项，指数高者在前）：$x^5$ 只有这一项直接拷贝；$x^4$ 两项系数相加得 6；$x^3$ 两项系数相加得 0，结果里就不体现；$x^2$ 直接拷贝；$x^1$ 两项系数相加得 3；$x^0$ 是 $-1$ 直接拷贝。

* **算法流程与双指针推进**

    * 用 $P_1$、$P_2$ 分别指向两个多项式的第一个结点（也就是最高项）开始循环：
        * 指数相等 → 系数相加，结果不为 0 就作为一个新的项放进结果多项式；
        * $P_1$ 这一项指数大 → 把 $P_1$ 这项拷贝过去，$P_1$ 后移；
        * $P_2$ 这一项指数大 → 把 $P_2$ 这项拷贝过去，$P_2$ 后移。
    * 当其中一个多项式已全部挪完，把剩下那个多项式剩余的项全部接到结果多项式后面。

* **结果表的构造与 `attach` 的角色**

    * 结果多项式的头必须记住，因为最终要 `return` 的是这个单链表的第一个结点；同时还要知道尾在哪，因为要不断往后面加新项——所以用 `front` 与 `rear` 两个整型变量分别指向结果多项式的头和尾。
    * 为方便操作，构造一个**临时空结点**作为结果多项式的表头，一开始 `front` 与 `rear` 都指向它，程序返回前再把这个空结点释放掉。
    * `compare` 函数极其简单：比较两个参数值大小，第一个大返回 1，第二个大返回 $-1$，相等返回 0。
    * 拷贝动作交给 `attach`：前两个参数分别代表要拷贝这一项的系数和指数，第三个参数是尾指针，把这个以系数和指数构成的新项接到 `rear` 的后面。

### 多项式相乘的逐项插入实现

* **两条架构路线**

    * > **定义**：计算两多项式交叉相乘并合并同类项的两大工程实现路径。

    * 路线一（转化为多次累加）：把 $P_1$ 各项分别乘以 $P_2$ 得到多组单项乘积链表，反复调用 `Add` 累加合并；逻辑清晰但产生大量中间结点的动态申请与释放开销。
    * 路线二（逐项就地定位插入）：直接维护单张结果链表，外层循环遍历 $P_1$、内层循环遍历 $P_2$，新项即时定位插入至已序结果链表。

* **逐项插入有序链表算法**

    * > **定义**：用基准多项式打底、后续项通过游标寻位进行同类项就地合并或跨接插入的相乘实现。

    * 执行步骤：
        1. 空输入守卫：`if (!p1 || !p2) return NULL;`
        2. 基准链表构建：用 $P_1$ 首项与 $P_2$ 全部项相乘，构造初始严格降序结果链表；
        3. 双重循环定位：$t_1$ 从第二项起外层循环、$t_2$ 遍历 $P_2$，计算 $c = t_1\text{->coef} \times t_2\text{->coef}$、$e = t_1\text{->expon} + t_2\text{->expon}$；
        4. 前驱游标滑动：游标 `rear` 从哑结点起，以 `rear->link && rear->link->expon > e` 为条件定位应插前驱；
        5. 同类项与插入判定：若 `rear->link->expon == e` 则系数就地累加，和为零时从链表删除并释放该结点；否则动态分配新结点插入到 `rear` 与 `rear->link` 之间；
        6. 释放哑结点并返回首结点。

        ```c
        Polynomial Mult(Polynomial p1, Polynomial p2) {
            Polynomial P, rear, t1, t2, t;
            int c, e;
            if (!p1 || !p2) return NULL;
            t1 = p1; t2 = p2;
            P = (Polynomial)malloc(sizeof(struct PolyNode));
            P->link = NULL;
            rear = P;
            while (t2) {
                Attach(t1->coef * t2->coef, t1->expon + t2->expon, &rear);
                t2 = t2->link;
            }
            t1 = t1->link;
            while (t1) {
                t2 = p2; rear = P;
                while (t2) {
                    c = t1->coef * t2->coef;
                    e = t1->expon + t2->expon;
                    while (rear->link && rear->link->expon > e) rear = rear->link;
                    if (rear->link && rear->link->expon == e) {
                        if (rear->link->coef + c) {
                            rear->link->coef += c;
                        } else {
                            t = rear->link;
                            rear->link = t->link;
                            free(t);
                        }
                    } else {
                        t = (Polynomial)malloc(sizeof(struct PolyNode));
                        t->coef = c; t->expon = e;
                        t->link = rear->link;
                        rear->link = t;
                        rear = rear->link;
                    }
                    t2 = t2->link;
                }
                t1 = t1->link;
            }
            t = P; P = P->link; free(t);
            return P;
        }
        ```

### 格式化输出与逆向空格处理

* **逆向前导空格输出法**

    * > **定义**：通过初值为 0 的标志变量记录首项状态，把「尾部不留空格」转化为「首项不打空格、后续项前导补空格」的格式化控制技术。

    * 边界条件：多项式链表为空时直接输出 `0 0\n`；非空遍历时第一项只翻转 `flag = 1`，后续各项在输出数值前先打印一个分隔空格，彻底消解尾部冗余空格。

        ```c
        void PrintPoly(Polynomial P) {
            int flag = 0;
            if (!P) {
                printf("0 0\n");
                return;
            }
            while (P) {
                if (!flag) flag = 1;
                else printf(" ");
                printf("%d %d", P->coef, P->expon);
                P = P->link;
            }
            printf("\n");
        }
        ```

## 查找机制演进与树结构引出

### 静态查找与动态查找

* **静态查找（Static Search）**

    * > **定义**：在数据记录集合固定不变的前提下，仅进行根据关键字检索目标元素的数据操作。

    * 典型场景：查阅纸质字典、查阅物理常数表、查询系统内置静态路由表。无需考虑运行中新增或移除记录的维护成本。

* **动态查找（Dynamic Search）**

    * > **定义**：在检索查找的同时，集合内部记录频繁发生插入与删除变动的数据操作形态。

    * 典型场景：数据库表管理、电商平台商品库、操作系统进程控制块调度。要求底层存储不仅提供高效检索，还必须以相近效率支撑插入与删除。

    | 查找类别 | 集合状态特征 | 允许操作集合 | 典型应用场景 |
    | :--- | :--- | :--- | :--- |
    | **静态查找（Static Search）** | 集合固定不变，无增删操作 | 仅执行检索查询 | 查阅纸质字典、物理常数表、系统静态路由表 |
    | **动态查找（Dynamic Search）** | 集合动态变化，增删频繁 | 检索、插入、删除交替穿插 | 数据库记录管理、电商平台商品库、操作系统进程控制块 |

### 顺序查找与哨兵机制

* **顺序查找（Sequential Search）**

    * > **定义**：在线性数据集合中从一端开始逐项比对关键字与目标值的线性查找方法。

    * 性能指标：最好情况比较 1 次，最坏情况比较 $n+1$ 次，平均成功查找长度 $\frac{n+1}{2} \approx \frac{n}{2}$，$T(n) = O(n)$。

* **哨兵优化技巧（Sentinel Technique）**

    * > **定义**：在数组下标 0 处临时埋放待查关键字 $K$，使查找循环无需在每次迭代中校验下标越界的极度精炼优化手法。

    * 推进机理：有效数据存放于下标 $1 \sim n$，查找从尾端 $n$ 递减推进。有效区间命中则提前返回 $i > 0$；全区间无匹配时循环在 $i = 0$ 处撞上自身哨兵必然退出并返回 0。

        ```text
        数组存储结构:
        下标:    [ 0 ]   [ 1 ]   [ 2 ]   ...   [ n-1 ]   [ n ]
        数据:    [ 哨兵K ] [ a1 ]  [ a2 ]  ...   [ an-1 ]  [ an ]
                   ^                                       |
                   |                  <---- 从后往前扫描 ---|
            若无匹配项，最终停在此处
        ```

        ```c
        int SequentialSearch(StaticTable Tbl, int K) {
            int i;
            Tbl->Element[0] = K; /* 0 号单元设置哨兵 */
            for (i = Tbl->Length; Tbl->Element[i] != K; i--)
                ;
            return i; /* 返回 0 说明查找失败，> 0 为对应下标 */
        }
        ```

### 二分查找算法与先决条件

* **二分查找折半排障模型**

    * > **定义**：基于全域单调性，通过在中点进行连通性测试将待查搜索空间单次削减一半的折半决策模型。

    * 现实案例映射：架空电话线 150 公里沿线竖立 100 万根电线杆，顺序逐杆爬测平均需测试 50 万次；在中点电线杆测试双向连通性即可立即排除 50 万根杆，仅需 $\log_2(1000000) \approx 20$ 次测试即可精准定位故障点。

* **二分查找先决条件与实现**

    * > **定义**：在支持常数级随机访问且按关键字严格有序的数组中实施折半区间的查找算法。

    * 苛刻先决条件：必须采用顺序存储结构（数组）以支持 $O(1)$ 定位中点下标；数组元素必须按关键字递增或递降严格有序。
    * 循环与边界越界机理：左右游标维持 `left <= right`，计算中点 `mid = (left + right) / 2` 并比对；未查到时区间收缩，最终发生 `left > right` 边界错位并返回 0。

        ```c
        int BinarySearch(StaticTable Tbl, int K) {
            int left = 1, right = Tbl->Length, mid;
            while (left <= right) {
                mid = (left + right) / 2;
                if (K < Tbl->Element[mid]) right = mid - 1;
                else if (K > Tbl->Element[mid]) left = mid + 1;
                else return mid;
            }
            return 0;
        }
        ```

### 二分查找判定树与平均查找长度

* **判定树模型（Decision Tree Model）**

    * > **定义**：将二分查找在有序数组中的所有比较路径与分支决策抽象映射为二叉拓扑的分析工具。

    * 比较次数与层数映射定理：查找特定节点所需的比较次数，严格等于该节点在判定树中所处的层次（根节点处于第 1 层）。

        ```text
                                 [ 6 ]                   <--- 第 1 层 (比较 1 次)
                                /     \
                          [ 3 ]         [ 9 ]             <--- 第 2 层 (比较 2 次)
                         /     \       /     \
                      [ 1 ]   [ 4 ]  [ 7 ]   [ 10 ]       <--- 第 3 层 (比较 3 次)
                         \       \      \       \
                        [ 2 ]   [ 5 ]  [ 8 ]   [ 11 ]     <--- 第 4 层 (比较 4 次)
        ```

* **判定树高度与平均查找长度**

    * > **定义**：衡量二分查找在最坏与平均情况下比较次数的数学量化指标。

    * 树高与最坏比较次数：包含 $n$ 个结点的有序数组判定树高度为
        $$h = \lfloor \log_2 n \rfloor + 1$$

    * 平均查找长度（ASL）实例推导：对 $n = 11$ 的有序表（等概率查找），第 1 层 1 个结点（比较 1 次）、第 2 层 2 个结点（比较 2 次）、第 3 层 4 个结点（比较 3 次）、第 4 层 4 个结点（比较 4 次）：
        $$\text{ASL} = \frac{1 \times 1 + 2 \times 2 + 4 \times 3 + 4 \times 4}{11} = \frac{33}{11} = 3$$

* **二分查找的动态局限与二叉搜索树萌芽**

    * > **定义**：顺序存储在二分查找下的静态高效性与动态增删高昂开销之间的结构性矛盾。

    * 结构性缺陷：二分查找把查找时间降到 $O(\log n)$，但插入删除时因数组连续物理约束必须整体平移后继元素，单次增删代价高达 $O(n)$。
    * 演进动机：直接用指针把数据组织成真树结构（二叉搜索树），兼具链表动态插删灵活性与判定树的对数级检索效率，使查、增、删均能在 $O(\log n)$ 内完成。

### 树的递归定义与最小连通性

* **树的递归定义**

    * > **定义**：树是 $n$（$n \ge 0$）个结点的有限集合。$n = 0$ 时为空树；非空树有且仅有一个特定的根结点，其余结点被划分为 $m$（$m > 0$）个互不相交的有限集，各集合本身又是根的子树。

        ```text
        标准多叉树:                        非树形态 1 (子树相交):          非树形态 2 (多父环路):
               [ A ]                             [ A ]                           [ A ]
             /   |   \                          /     \                         /     \
          [ B ] [ C ] [ D ]                  [ B ]   [ C ]                   [ B ]   [ C ]
           / \         |                        \     /                         \     /
        [ E ] [ F ]  [ G ]                       [ D ]                           [ D ]
                                          (B、C 子树在 D 相交)            (D 同时认 B、C 为父)
        ```

* **树的拓扑性质与最小连通图**

    * > **定义**：树在图论层面上作为保持所有结点无回路连通的最经济连接拓扑结构。

    * 边数与结点数恒等式：含 $n$ 个结点的树，边数严格恒等于 $n-1$ 条；除根结点外每个结点向上有且仅有一条边连其父结点。
    * 最小连通性：随机移除树中任意一条边，整棵树必然分裂为两个互不连通的子图；在树中任意两结点间添加一条边，树内必定立刻闭合产生回路。

### 树的拓扑术语体系

* **节点分叉与度**

    * 结点的度为其拥有的子树数目（直接引出的分支边数）；树的度为全树所有结点度的最大值。
    * 度为 0 的结点称为叶结点（终端结点），度大于 0 的结点称为分支结点（非终端结点）。

* **节点亲缘关系**

    * 某结点的直接上层结点为其父结点；某结点直接下引子树的根结点为其子结点；拥有同一父结点的所有同层结点互为兄弟结点。

* **路径与层次度量**

    * 路径长度：由严格父子连线构成的结点序列所经过的边数（等于路径包含的结点数减 1）。
    * 层次（Level）：根结点规定为第 1 层，其子结点为第 2 层，逐层递增。
    * 树的高度 / 深度（Height / Depth）：全树所有结点层次的最大值。

    | 术语名称 | 英文对应 | 结构定义与度量规范 |
    | :--- | :--- | :--- |
    | **节点的度** | Degree of Node | 该节点拥有的子树数目（直接引出的分支边数） |
    | **树的度** | Degree of Tree | 树中所有节点度的最大值（分叉最多的节点的度） |
    | **叶节点** | Leaf Node | 度为 0 的终端节点，下方无挂接子树 |
    | **分支节点** | Branch Node | 度大于 0 的非终端节点 |
    | **父节点** | Parent | 某节点的直接上层唯一前驱节点 |
    | **子节点** | Child | 某节点直接下引的子树的根节点 |
    | **兄弟节点** | Sibling | 拥有相同父节点的同层节点 |
    | **路径** | Path | 具有严格父子关系的节点序列 $n_1, n_2, \dots, n_k$ |
    | **路径长度** | Path Length | 路径经过的边数（等于路径包含的节点总数减 1） |
    | **祖先节点** | Ancestor | 从根节点至该节点路径上的所有上层前驱节点 |
    | **子孙节点** | Descendant | 以某节点为根的子树中包含的所有下层后继节点 |
    | **节点的层次** | Level | 规定根节点为第 1 层，其子节点为第 2 层，逐层递增 |
    | **树的高度/深度** | Height / Depth | 全树所有节点层次的最大值 |
