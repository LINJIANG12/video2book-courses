## 损失函数：从多分类交叉熵到二分类交叉熵
> 对应块：BLK20 | 覆盖分集：P48-P49 | 块标题（分集名）：《Day04-07.损失函数_多分类交叉熵损失介绍》

### 模型搭好了，接下来要回答"它好不好"

到这一步，神经网络这个模型已经搭出来了：特征进来，先做一次加权求和（就是那个 $\Sigma$），再过一下激活函数，最后得到一个结果。这个结果在整件事里扮演的角色叫**预测值**。

预测值要和 target value 比一比。target value 就是我们以前说的目标值，专业一点的叫法是**标签**。预测值和标签之间的 difference——说白了两字，差异。这个差异，就是所谓的**误差**。

```text
特征 ──► 加权求和 (Wx + b) ──► 激活函数 ──► 模型输出 = 预测值
                                              │
                                              │  比较 difference
                                              ▼
                                        真实值 / 标签
                                              │
                                              ▼
                                             误差
```

读图：一次前向传播走到头，模型交出来的只是一组预测值；这组数字本身没有好坏，只有把它和标签摆在一起对比，差出来的那一截才能被度量。损失函数就是把这个差换算成一个能比较、能优化的数。

> **定义**：损失函数用来衡量模型的拟合情况，也就是衡量模型的好与坏；衡量的方式，是比较网络输出（预测值）和真实值（标签）之间的差异。

记住一句话就够：损失函数是用来衡量模型拟合情况好与坏的。它没那么玄，本质上就是一个打分器——分数越低，说明拟合得越好。

### 它有一堆名字，说的却是同一件事

损失函数在不同的文献里叫法不一样，常见的有四个：

| 英文名 | 中文叫法 |
| :--- | :--- |
| loss | 损失函数 |
| cost | 代价函数 |
| objective | 目标函数 |
| error | 误差函数 |

有人顺口还会叫"成本函数"。为什么同一个东西能有这么多名字？

原因其实很朴素：机器学习和深度学习不是由一家公司、一个机构搞出来的，而是好多家、好多机构各做各的，中间没有谁站出来统一定过命名。于是 A 公司管它叫损失函数，B 公司管它叫代价函数，名字就这么岔开了。

这种事跟生活里的称呼一模一样。我在公司，同事会用带"夯"字的那个叫法喊我；可一回到家，家里人只会叫我的小名，他们甚至不知道"夯"这个字跟我有什么关系。再比如我跟同学说过，以后课程里会经常出现"汤圆"这两个字——不是因为我爱吃汤圆，是因为我儿子小名叫汤圆；同学还打趣说这名字起得不对，应该叫小航才对。同一个词、同一个功能，换个环境，意思和叫法就都变了。

> **结论**：叫损失也好，代价也好，目标也好，误差也好，本质是同一件东西。看到这几个词，不要以为是四个不同的概念。

### 损失函数的家谱：分类归分类，回归归回归

按任务类型分，常用的损失函数就这几支：分类问题里有二分类交叉熵和多分类交叉熵，回归问题里有 MAE、MSE 和 Smooth L1。

| 任务类型 | 损失函数 | 常用简称 | 说明 |
| :--- | :--- | :--- | :--- |
| 分类 | 多分类交叉熵损失 | `CrossEntropyLoss` | 多分类任务的主力，公式内含 softmax |
| 分类 | 二分类交叉熵损失 | `BCELoss` | 只分两类，配合 sigmoid 使用 |
| 回归 | 平均绝对误差 | MAE | Mean Absolute Error |
| 回归 | 均方误差 | MSE | Mean Squared Error，注意这是"均方误差"，不是"平均平方" |
| 回归 | Smooth L1 | Smooth L1 | 结合 MAE 与 MSE 两者特点做的升级优化 |

MSE 的名字容易读错，它是 mean squared error，落在中文里叫均方误差。至于 Smooth L1，它是把前两者的特点揉在一起做的改进版；真到该用的时候，用 Smooth L1 会更好一点。RMS 那一族先不铺开，眼下把这五种的区别和各自的特点弄清楚就够。

先把多分类交叉熵讲透——它的思路理顺了，二分类那个自然就通了。

### 多分类交叉熵：先给结论，再拆推导

我习惯先把结论摆出来，再讲为什么。结论就一句：

> **结论**：多分类交叉熵损失，等于 softmax 函数加上一个损失计算。也就是说，它内部默认就包含了 softmax 这个动作。

这句话的用处非常实际：**如果用多分类交叉熵，输出层就不用再写 softmax 了。** 之前搭网络的时候，`forward` 的最后一步还专门写了一个 softmax 把结果映射成概率；现在知道了，只要后面接的是多分类交叉熵，那一步可以不写，代码直接写到 `fc` 的输出就行。为什么能这么省？因为下一步就是模型训练，训练里要算损失，而 softmax 这个动作交给损失函数替你做掉了。

再往细里看公式。多分类的交叉熵长这样：

$$Loss = -\sum_{i} y_i \log\big(S(F(x_i))\big)$$

| 符号 | 含义 |
| :--- | :--- |
| $x_i$ | 第 $i$ 个样本，$i$ 从 1 数到 $n$，一共 $n$ 个样本 |
| $F(x)$ | 加权求和，也就是样本属于各个类别的预测分数，写成 $Y = WX + B$ 那个形式 |
| $S(\cdot)$ | 激活函数，把预测分数映射成概率 |
| $\log$ | 求对数 |
| $y_i$ | 样本属于某个类别的真实概率，只取 0 或 1 |
| $\sum$ 与负号 | 先累加、再整体取负，保证损失是个正数 |

按顺序读下来就是一条流水线：

```text
样本 x ──► F(x) 加权求和（预测分数）
       ──► S(·) 激活（softmax 映射成概率）
       ──► log(·) 取对数
       ──► × y   乘上该类别的真实概率（0 或 1）
       ──► Σ     所有类别累加
       ──► 取负
       ══► 一个样本的损失
```

读图：四个动词——加权求和、激活、求对数、乘真实概率，然后累加、取负。每个样本都走一遍这条流水线，$n$ 个样本就得到 $n$ 个这样的结果，最后再合起来（代码里默认取平均）。这里 $S$ 那一步算出来的，确切说不是"激活后的分数"，而是**映射之后的概率**。

顺着这条链记符号最简单：$X$ 是样本，$F(X)$ 是加权求和，$S$ 包住 $F(X)$ 得到概率，$\log$ 是对数，$Y$ 是真实概率。至于 $Y$ 为什么只有 0 和 1 两种可能——因为它是"真实"概率。你就想一个最直白的问题：你是男的吗？真实情况要么是，概率 100%；要么不是，概率 0%。不存在"你的真实概率有 70% 是男的"这种情况，真实的东西不带模糊。

### 代入一组数，看它到底在惩罚什么

公式摊开了还是抽象，代一组数进去。

输入一个值，经过 network（也就是神经网络那一串处理），输出的分数是 0.12 这样的加权求和结果。但光有加权求和没有意义——我还得知道"它属于 A 类、B 类、C 类的概率分别是多少"。于是拿这组分数过一遍 softmax，得到 0.1、0.7、0.2 三个概率，加起来正好是 1。这三个数就把原来那个 0.12 覆盖掉了：分数是中间产物，概率才是最终答案。

假设标签是 `010`，也就是真实类别是第二个。代进公式：

$$Loss = -\big(0 \times \log 0.1 \;+\; 1 \times \log 0.7 \;+\; 0 \times \log 0.2\big)$$

三个括号项里，乘 0 的两个直接没了，真正生效的只有 $\log 0.7$ 这一项，整体再取负：

$$Loss = -\log 0.7$$

这就是那句听着有点绕的话的由来：**最小化正确类别所对应的预测概率的对数的负值。**

拆开看就顺了。$y$ 只有 0 和 1，凡是取 0 的类别，乘出来都是 0，被彻底忽略；剩下那个 1，落在真实类别上，所以"能留下来参与计算的"必然是正确类别那一项。于是损失函数其实压根不关心你给错误类别分了多少概率，它只盯着一件事：**你把正确类别的概率给到了多大**。

> **提示**：$-\log p$ 在 $p$ 越接近 1 时越小。所以"最小化 $-\log p$"和"把正确类别的预测概率往 1 推"是同一件事，只不过前者能算出一个可以求导、可以优化的数值。这也解释了为什么这个损失值越小越好。

概率论的说法再念一遍：我们做的是最小化正确类别所对应的预测概率的对数的负值。这个值算出来，就充当这批样本的损失。

### 落到代码：多分类交叉熵的四个动作

导包两个：`torch` 和 `torch.nn`（习惯简写成 `nn`）。函数里固定四步——设置真实值、设置预测值、创建损失函数、计算损失。

```python
import torch
import torch.nn as nn


def dm01():
    # 1 设置真实值：one-hot 写法，1 落在哪一位就是哪一类
    y_true = torch.tensor([[0, 1, 0], [1, 0, 0]], dtype=torch.float)
    # 真实值也可以直接给类别索引，与上面的 one-hot 完全等价
    # y_true = torch.tensor([1, 0])

    # 2 设置预测值：每个样本一组分数，并开启自动微分
    y_pred = torch.tensor([[0.1, 0.8, 0.1], [0.7, 0.2, 0.1]],
                          dtype=torch.float, requires_grad=True)

    # 3 创建多分类交叉熵损失函数
    criterion = nn.CrossEntropyLoss()

    # 4 计算损失
    loss = criterion(y_pred, y_true)
    print(loss)


if __name__ == '__main__':
    dm01()
```

第一步，真实值。`010` 里的 1 落在第二位，按从 0 开始的索引数，它就是 1 号类；`100` 的 1 落在第一位，就是 0 号类。所以这里的两行分别代表两个样本，标签是 1 号类和 0 号类。真实值也支持"不写 one-hot、直接写类别索引"的写法，两种都对。注意 `dtype` 必须指定成 `torch.float`——**小数才能算**，整型张量进不了这套运算。

第二步，预测值。这里是个二维的嵌套列表：外层两个元素对应两个样本，内层每个列表是一个样本在三个类别上的分数。`requires_grad=True` 不能漏——这个值后面要参与自动微分，靠求导去更新权重；不打开它，梯度就传不回去。

第三步，创建损失函数。`nn.CrossEntropyLoss()` 就是多分类交叉熵。它底层要的东西少得可怜：一个预测、一个真实，剩下的 softmax、log 全在内部完成。也就是说，公式里那个 $S(\cdot)$ 和 $\log$ 你都不用在外面再写一遍。

顺手提一个容易被忽略的参数：点进 `CrossEntropyLoss` 的源码看，它的 `reduction` 默认值是 `'mean'`，所以它算出来的是**平均损失**，不是你所有样本损失的简单堆叠。

第四步，把预测和真实扔进去，打印。跑出来是 `1.0283`。

这个数值值得多说一句。它不等于把 0.8、0.7 直接代进 $-\log$ 再取平均的结果，因为进去的那两组数会被当成 **softmax 之前的分数**，先重新映射成概率，再取对数、再对两个样本求平均。这正是"公式里包含 softmax"落在实处的样子：我交出去的只是分数，映射成概率这一步由损失函数替我做了。所以写模型时那个 softmax 是真的可以不写。

> **提示**：既然是手动模拟，预测值不必凑成和为 1。你写 `0.7、0.2、0.3` 加起来 1.2 也照样能跑，底层会自己处理。真实训练时这些数来自网络的输出，自然不会出现这种"拍脑袋"的和，但做演示时不必纠结。同理，真实值写 `[1, 0]` 还是 `[1, 1]`、`[1, 2]` 也都随你——只要和你自己写的 one-hot 对得上就行。

小结成一句接口：给我一个真实值、一个预测值，剩下的交给多分类交叉熵，它就能替你把损失算出来。这三个数的具体大小不用纠结，`1.0283` 只是个演示结果，这个值越小越好。

### 二分类交叉熵：公式里没有 sigmoid，所以得自己写

处理二分类任务时，我们不再用 softmax，改用 sigmoid。

先看一个细节，这个细节决定了代码怎么写：二分类交叉熵的公式里，哪里出现了 sigmoid？翻一遍——没有。多分类的公式里有 softmax，所以那一步可以省；二分类的公式里没有 sigmoid，那就意味着将来做二分类时，这个激活函数**必须手动写**。这是两者最要紧的一条区别。

公式本身是：

$$L = -\big[y \log \hat{y} + (1-y)\log(1-\hat{y})\big]$$

$y$ 是样本属于某一类别的真实概率，取值只有 0 和 1；$\hat{y}$ 是样本属于该类别的预测概率。

这两个取值分别把公式砍掉一半：

| 真实标签 | 公式里发生什么 | 剩下什么 |
| :--- | :--- | :--- |
| $y = 0$ | 左边 $0 \times \log \hat{y}$ 归零 | $-\log(1-\hat{y})$ |
| $y = 1$ | 右边 $(1-1)\log(1-\hat{y})$ 归零 | $-\log \hat{y}$ |

$y=0$ 意味着完全不属于 A 类，那就只看"它不是 A 类"这件事算得准不准；$y=1$ 意味着 100% 属于这个类别，$1-1=0$，右边整块消失，只看 $-\log \hat{y}$。所以那两张看起来分开画的曲线，本质上是同一个公式的两个分支：一个是 $\log \hat{y}$，另一个是 $\log(1-\hat{y})$，具体走哪支，由真实标签是 1 还是 0 决定。

这个式子看着眼熟吧——逻辑回归就是这么推出来的。二分类交叉熵和它在形式上是同一套东西。

在 PyTorch 里，二分类交叉熵对应 `nn.BCELoss()`，BCE 就是 Binary Cross Entropy。实际工程里，二分类的场景用得相对少一些，所以这两个细节记住即可：公式不含 sigmoid，用时自己补。

### 落到代码：二分类交叉熵与转 numpy 的坑

代码结构照旧四步，只是换成 `BCELoss`，真实值和预测值的形状也变了。

```python
import torch
import torch.nn as nn


def dm01():
    # 1 设置真实值：三个样本，0 是一类，1 是另一类
    y_true = torch.tensor([0, 1, 0], dtype=torch.float)

    # 2 设置预测值：每个样本属于正类的概率（即 sigmoid 的输出）
    y_pred = torch.tensor([0.69, 0.54, 0.26],
                          dtype=torch.float, requires_grad=True)

    # 3 创建二分类交叉熵损失函数
    criterion = nn.BCELoss()

    # 4 计算损失
    loss = criterion(y_pred, y_true)
    print(loss)
```

第一步，真实值是一维的 `[0, 1, 0]`。它代表三个样本，分别是 0 类、1 类、0 类——也就是 A 类、B 类、A 类这么三组判断。

第二步，预测值也是三个数，每个数是一个样本属于正类的概率，也就是 sigmoid 的输出。这里要特别注意和多分类的区别：多分类的预测是**一个样本一整组**分数，所以要嵌套的中括号包成二维；二分类是一个样本**一个**概率，`[0.69, 0.54, 0.26]` 就是三组独立判断——第一个样本是 0 还是 1，第二个是 0 还是 1，第三个是 0 还是 1。形状上的这点差别，根源就在任务本身。

第三步，`nn.BCELoss()`。顺手点进源码看一眼，`reduction` 默认还是 `'mean'`。所以不只是交叉熵，很多损失函数底层算的都是平均损失、也就是均值。

第四步，把真实和预测丢进去，打印出来是 `0.6962`，也就是大约 0.69。这个数怎么来的，正好可以核对一遍：三个样本里两个标签是 0、一个标签是 1，所以三项分别是 $-\log(1-0.69)$、$-\log 0.54$、$-\log(1-0.26)$，即 1.171、0.616、0.301，加起来 2.088，再除以 3，得 0.6962。平均损失这个 `reduction='mean'` 是实打实在起作用的。

> **注意**：这里的 `y_pred` 开了 `requires_grad=True`，算出来的 `loss` 就带着计算图。想把它转成 numpy，不能直接 `loss.numpy()`，得先断开梯度：`loss.detach().numpy()`。转完打印类型是 `numpy.ndarray`；如果你只打印值不打印类型，屏幕上看到的还是个 `tensor`，容易误判。后面把损失拿出来画图或者打印统计量时，这一步别忘。

最后把两者的分工钉在一起看：

| 对比项 | 多分类 | 二分类 |
| :--- | :--- | :--- |
| 输出层激活函数 | softmax | sigmoid |
| 损失函数 | `nn.CrossEntropyLoss()` | `nn.BCELoss()` |
| 公式里是否含激活 | 含 softmax | 不含 sigmoid |
| 代码里还要不要手写激活 | 可以不写 | 必须写 |
| 预测值形状 | 每个样本一组分数 | 每个样本一个概率 |
| 底层默认归约 | `reduction='mean'` | `reduction='mean'` |

`BCELoss` 用于二分类，`CrossEntropyLoss` 用于多分类；一个省掉 softmax，一个补上 sigmoid。这两条记牢，写模型的时候就不会在 `forward` 的最后一步犹豫要不要加激活了。至于损失函数本身，它永远只做一件事：拿一个真实值、一个预测值，还你一个越小越好的数。

## 回归任务的三种损失函数，和一次梯度下降复盘
> 对应块：BLK21 | 覆盖分集：P50-P53 | 块标题（分集名）：《Day04-09.损失函数_MAE损失函数介绍》

### 开场：回归这一块，只学一种就够

回归任务的损失函数，我先把结论放这儿：很负责任地讲，最后只学一种，**smooth l1 就够了**。

不过前头那两个还是得看一遍。MAE 和 MSE 不是白讲的——smooth l1 就是从这两个的毛病上拼出来的。不知道它们各自在哪儿别扭，就看不出 smooth l1 那两段拼接的意义，也不知道自己为什么要在代码里换掉 `L1Loss`。

先说命名这件事。回归的第一个损失叫 MAE，A 是 absolute，中文叫**平均绝对误差**：真实值减预测值取绝对值，全部加起来，再除以样本总数。这东西以前统计学里就学过，不新鲜。它在 PyTorch 里叫 `L1Loss`。

顺着这个规律猜，MSE 该叫 `L2Loss` 吧？

恭喜你，猜错了，它叫 `MSELoss`。原因很简单——MSE 比 MAE 用得多，名字就这么定下来了。所以你写代码的时候手一滑敲个 `L2`，编辑器里根本不会有提示，压根没有这个东西。就跟老婆饼里没有老婆、鱼香肉丝里没有鱼是一样的。

| 损失函数 | 中文名 | 别名 | PyTorch 里的写法 |
| :--- | :--- | :--- | :--- |
| MAE | 平均绝对误差 | L1 loss | `nn.L1Loss()` |
| MSE | 均方误差 | L2 loss（但没有 `L2Loss` 这个 API） | `nn.MSELoss()` |
| Smooth L1 | 平滑 L1 | — | `nn.SmoothL1Loss()` |

> **易错点**：`L2 loss` 只是 MSE 的习惯叫法，不是代码里的类名。PyTorch 里没有 `nn.L2Loss()`，写 MSE 只能写 `nn.MSELoss()`。

### MAE：误差的绝对值先求和，再平均

公式没什么花头：

$$MAE = \frac{1}{n}\sum_{i=1}^{n}\left|y_i - \hat{y}_i\right|$$

真实值减预测值，取绝对值，全部加起来，再除以样本数。真实减预测还是预测减真实都无所谓，反正外面套了绝对值。

MAE 有个容易被忽略的性质：它是照着 L1 正则化那套思路走的，**能让权重降到 0**。假设手上有 50 列特征，其中 30 列的权重被压成 0，那最终参与计算的特征列就从 50 列掉到 20 列，数据一下就变稀疏了。也正因为能惩罚较大的值，它常常被当成正则项塞进别的 loss 里，起一个约束作用——也就是说，它一般不单独上场，而是充当别的损失函数的子项，用来调参。

它最大的问题出在零点。你可以自己问一句：零点可导吗？

不可导。L1 的图像就是一条直线，一步到位，有点像以前学的正规方程法，套公式直接出结果；可真走到零点这个位置，导数算不出来，梯度下降就没法往下算。万一零点恰好就是最小值呢？那就有可能直接跳过去。

我想要的其实是另一种样子：在这个区间里给我一段有弧度的线，像梯度下降那样在这儿一点一点逼近、逼近，最后贴到正确值上——这样才对。所以 smooth l1 才叫"平滑的 L1"：L1 在两头挺好，直线下降快、效率高，就中间这一段不好；中间这一段不好怎么办？拿 L2 补上。

### 一个脚本，跑通 MAE

导包两行，`nn` 是 neural network，神经网络：

```python
import torch
import torch.nn as nn
```

别的东西今天不一定学会，这两行应该已经很熟了。既然要在一个案例里把三种损失都演示完，就把它们拆成三个函数，再写一个调用跑起来。

```python
import torch
import torch.nn as nn


def dm01():
    # 1. 定义变量：记录真实值
    y_true = torch.tensor([2.0, 2.0, 2.0], dtype=torch.float32)

    # 2. 定义变量：记录预测值
    y_pred = torch.tensor([1.0, 1.0, 1.9], requires_grad=True)

    # 3. 创建 MAE 损失函数对象
    criterion = nn.L1Loss()

    # 4. 计算损失
    loss = criterion(y_pred, y_true)

    # 5. 打印损失
    print("mae loss:", loss)


dm01()
```

几处细节得说清楚：

- 真实值给了三个 `2.0`，**三个值就是三个样本**，一会儿预测出来的也只是三个样本，别把它当成一个批次里的什么特殊结构。
- `dtype=torch.float32` 是指定类型，写 `float` 也行，别让它变成默认之外的类型就好。
- 预测值 `[1.0, 1.0, 1.9]` 跟讲义保持一致就行，别太离谱。中间这个改成 `2.3` 也无所谓，正负都有也没关系，反正是自己编的预测结果。
- `requires_grad=True` 是这里最核心的一个属性。预测值必须挂上自动微分，因为它一会儿要结合损失函数求导，求导的目的是更新参数——不能求导，这条链就断了。

损失怎么来的？两个数相减：`2.0 - 1.0 = 1.0`，`2.0 - 1.0 = 1.0`，`2.0 - 1.9 = 0.1`，加起来 `2.1`，三个样本再除以 `3`，结果就是 `0.7`。

真跑出来，打印的是一串带尾巴的小数，大概 `0.6999999……` 这个样子，不是干干净净的 `0.7`。为什么？因为它是个 float。

> **提示**：所有编程语言，不管 Python 还是 Java，只要涉及小数，用的都是近似的思想，没有绝对相等。你说相等，那也只是精确到小数点后第 8 位、第 16 位，精确到第 100 位、第 1000 位是做不到的。所以有同学跑出来的末位跟我不一样，跟版本或环境有关，属于正常现象；但如果你照着这组数据跑出个 `3`，那绝对不可能——出现那种数只能说明代码写错了。

另外有个容易让人犯嘀咕的地方：之前做多分类的时候，无论怎么映射，所有类别的概率加起来应该为 1，可刚才手动写数据的时候并不为 1，这样行不行？行。因为数据是自己手动给的，想给谁就给谁，只不过结果准或不准而已。真实训练里那个"和为 1"的约束，是 softmax 之后才成立的。

到这里你会发现，所谓"算损失"就一句话：搞一个真实值、搞一个预测值，把损失对象一造，往里一调，结果就出来了。想知道它底层怎么算，把这组数代进去手算一遍就明白了。

### MSE：平方把异常值放大，也把梯度撑爆

MSE 也叫 L2 loss，还有一个名字叫欧式距离。

面试里有一道机器学习常问的题：用距离的时候，为什么曼哈顿距离用得少、欧式距离用得多？背答案会说维度限制之类。我告诉你，最简单的理由就是**它有个平方**。平方意味着什么？意味着能把异常值放大。

举个例子：一个值是 100，一个值是 1。用绝对值，你只能看到 99；用平方，你看到的是 99 的平方，接近 1 万。值一下就变得更离散了。反过来讲，模型也就更容易受这些异常值的影响——正向说是让异常值暴露出来，反向说就是被它带偏。

公式跟 MAE 只差一个平方：

$$MSE = \frac{1}{n}\sum_{i=1}^{n}\left(y_i - \hat{y}_i\right)^2$$

真实值减预测值，平方，求和，除以样本数。还是那组数据：三个差值分别是 1、1、0.1，平方之后 `1 + 1 + 0.01 = 2.01`，除以 `3`，约等于 `0.67`。

代码不用重写，把 `dm01` 整个复制一份，改名 `dm02`，把上一个函数调用注释掉，只换损失函数这一行：

```python
def dm02():
    y_true = torch.tensor([2.0, 2.0, 2.0], dtype=torch.float32)
    y_pred = torch.tensor([1.0, 1.0, 1.9], requires_grad=True)

    criterion = nn.MSELoss()

    loss = criterion(y_pred, y_true)
    print("mse loss:", loss)
```

注意别手滑写成 `nn.L2Loss()`，没有这个东西。后面两个演示的代码跟这里一模一样，改的只是这一行 API。

MSE 还有一层用法：**它也常常作为正则项**。正则项是干什么的？就是拿来调和参数的，它不单独用，而是充当别的公式里的惩罚系数，用来解决那些公式的过拟合问题。

这地方有个天天被问的问题：GBDT 和 XGBoost 有什么区别？其实简单说，XGBoost 不就是在 GBDT 的基础上加了一个 $\Omega$ 正则化项吗？加它的目的就是防止过拟合，最后一路推下去推到一个打分函数，效果就出来了。同一个道理，MSE 也经常以这种身份出现，结合别的式子一起用。

MSE 的毛病跟 MAE 正好相反。MAE 是零点不可导，MSE 是**预测值和目标值相差很大时梯度容易爆炸**。

回忆一下权重更新公式：

$$W_{new} = W_{old} - \eta \frac{\partial L}{\partial W}$$

梯度要是个 1 万，学习率哪怕只有 `0.01`，乘出来也是 100。上来就把 W 减掉 100，这个值得跑到哪儿去了？这就叫梯度爆炸。

举个极端例子：真实值是 100，模型给你预测成 1。这模型得人工智障成什么样才能干出这种事，但只是举例。此时差值 99，用 MAE 你看到的就是 99；用 MSE 呢？平方一下，瞬间从 99 干到接近 1 万。要是真实值是 1 万，预测成 1，平方之后就是无限放大。

说到人工智障，插一句题外话。你有没有问过一些模型"9.9 和 9.10 谁大"？这题其实没有 9.10 的概念，9.9 大。但两年多前，通义系列——就是阿里那个通义千问——你问它这个，它就告诉你 9.10 大。那段时间大家都在玩，我也去问了一下，历史记录现在还留着。现在它就不会这么答了，会给你讲"数学上 9.9 比 9.11 大"，还会补充一句"如果 9.11 是版本号，那 9.11 被认为更高"。这一层发散挺好。你要是问 DeepSeek，开深度思考它会给你完整的推理过程，用 V3 就直接给结论，各家模型的侧重点不一样。

还有个更离谱的。Chatbox 里能调模型的严谨与想象，我手一滑把想象拉满，问它"模仿近几十年的红利，给个快速赚到第一桶金的建议"，它让我去火星上开发房地产。思路确实是对的，可前提是我得先上去再说。

所以 MSE 的优点和缺点其实是同一件事：它更容易关注异常值，异常值过大时就容易梯度爆炸。这也解释了为什么实际开发里，回归很少直接拿 MSE 顶上去。

### Smooth L1：中间带平方，两头走直线

smooth l1 还不如直接叫它"平滑的 L1"。前面已经知道 MAE 也就是 L1 的弊端：零点不可导，因此会错过最小值。那就在形状上动刀子，做成一个分段函数——当 $x$ 的绝对值小于 1 时，换成 $0.5x^2$；其他情况下，用绝对值减去 0.5。

$$L = \begin{cases} 0.5x^2, & |x| < 1 \\ |x| - 0.5, & \text{其他} \end{cases}$$

这里的 $x$ 就是预测值和目标值的差。把它画出来，是这么三段：

```text
            x < -1              -1 <= x <= 1              x > 1
    --------------------+-------------------------+--------------------
      |x| - 0.5         |        0.5 * x^2        |       |x| - 0.5
      斜率恒为 -1        |   越靠近 0，梯度越小     |       斜率恒为 +1
         （L1）          |          （L2）         |          （L1）
```

读这张图只需要看一件事：中间那一段是抛物线，两侧是两条斜率固定的直线，三者在 $x=\pm 1$ 处正好接上，接点处函数值和导数都连续。

为什么中间要用 $0.5x^2$？因为无论 $x$ 是正还是负，平方以后都是正数，原来在零点那个尖角就被换成了一段平滑的弧线。为什么要减 0.5？为了让 $x=\pm 1$ 的地方两头对得上：$0.5 \times 1^2 = 0.5$，$|1| - 0.5$ 也等于 0.5，不会跳空。

这么一来它的本质就清楚了：**中间这段有平方，是 L2；外侧这段没有平方，是 L1**。所以 smooth l1 可以说是 L1 和 L2 的综合，或者更准确地说，是在 L1 的基础上加了一个平滑系数。它同时解决了两件事：

- 用中间那段 L2 解决 L1 零点不平滑、不可导、可能错过最小值的问题；
- 用外侧那段 L1 解决 L2 遇到离群点时梯度容易爆炸的问题——外面是直线，没有平方，差多大梯度就是多大，不会翻着倍往上涨。

代码还是复制，改成 `dm03`，只换损失函数：

```python
def dm03():
    y_true = torch.tensor([2.0, 2.0, 2.0], dtype=torch.float32)
    y_pred = torch.tensor([1.0, 1.0, 1.9], requires_grad=True)

    criterion = nn.SmoothL1Loss()

    loss = criterion(y_pred, y_true)
    print("smooth l1 loss:", loss)
```

同一组数据、同一个预测值，三种损失跑出来的数是这样的：

| 损失函数 | 同一组数据下的结果 |
| :--- | :--- |
| MAE（L1） | 0.7 |
| MSE（L2） | 0.67 |
| Smooth L1 | 0.335 |

两个差值都是 1，正好卡在分段点上，按外侧那条走，各算 `1 - 0.5 = 0.5`；差值 0.1 落在中间，算 `0.5 × 0.01 = 0.005`。三个加起来 `1.005`，除以 3，就是 `0.335`。所以损失从 0.7 掉到了 0.33 上下，MAE 报出来的损失是最高的。

> **提示**：这三个数摆在一起只是为了让你直观看到同一组预测值在不同定义下差多少，它们并不是同一把尺子，不能拿去做"谁更准"的排名。

顺带把实战里的选择定下来：回归优先用 smooth l1；多分类优先用 cross entropy，也就是交叉熵；二分类用 BCE。你可能会以为以后定义损失函数时用得最多的是 smooth l1，其实不是——用得最多的是交叉熵，真正要动手写的也就交叉熵和 BCE 这两个。别看这俩名字眼熟，多分类的交叉熵**自带 softmax 激活**，训练模型的时候那一层激活就不用再写一遍了。

机器学习的 MAE、MSE 各有各的问题，smooth l1 是在它们身上一代一代迭代出来的东西。没有哪个是白出现的。

### 梯度下降回顾：一条公式，三个毛病

网络优化方法是干什么的？说白了，就是针对权重更新公式做调整。所以整章都围着这一条式子转。

#### 权重更新公式

$$W_{new} = W_{old} - \eta \frac{\partial L}{\partial W}$$

梯度下降是一种寻找损失函数最小化的方法。除了它，还有一条思路叫正规方程法，但正规方程法有个弊端：矩阵必须有逆，没有逆就算不下去。

从数学角度看，梯度的方向是函数增长最快的方向，那么反方向就是下降最快的方向——所以是"减去"学习率乘梯度，而不是加上。

念这条公式之前先把符号认了：$\eta$ 读 eta，就是"一塔"，是学习率；$\partial$ 读 partial 或者 round，也有人按"偏德尔塔"来念，意思都是偏导；$\Delta$ 才是德尔塔；$\prod$ 是连乘，不是"门"。这几个符号在论文和讲义里到处都是，念错了不丢人，但听着别扭。

#### 学习率为什么要动

学习率太小，下降就会太慢，训练的时间成本直接上去；学习率太大，下降就会太快，容易震荡，有可能跳过最优解，甚至进入无限的循环里。

以前学的时候，公式里只有梯度是能变的：W 减去固定的学习率乘上梯度，靠梯度的变化让结果动起来。可学习率要是一开始就写死，其实不好——我想让它前期大一点，降得快一些；等后期离得差不多了，再让它降下来，慢慢往最小值上贴。所以得从学习率这个角度入手做调整，也就有了后面三种策略：等间隔调整、指定间隔调整、指数间隔调整。

#### 三个绕不过去的问题

传统的梯度下降有三个绕不过去的问题：

- 平缓区域下降慢。梯度接近 0 的地方，一步挪不了多少。
- 鞍点。一个方向上像谷底，另一个方向上却是坡顶，站在那儿感觉是平地，其实不是最小值。
- 局部最小值。掉进一个小坑里就出不来了，后面明明还有更深的坑。

光靠 $W_{new} = W_{old} - \eta \frac{\partial L}{\partial W}$ 这一条，这三个问题都解决不了，所以得换方法。接下来会讲四个梯度下降优化方法：动量法、AdaGrad、RMSProp、Adam；再加上三种学习率优化策略，一共七种。

这里还得提前交代一个知识点：**反向传播**。它本身属于"了解"级别的知识点，可从开篇讲到现在，天天都在提反向传播，所以我会按"掌握"的级别来讲；但讲完你最终做到"了解"就可以了。

### epoch、batch、iteration：三个词和两个手算

这三个词超级简单，但必须张嘴就能答：

| 概念 | 含义 |
| :--- | :--- |
| epoch | 模型训练的轮数，训练集完整过一遍算一轮 |
| batch size | 每批次的样本数量，也就是每次反向传播更新权重用多少条数据 |
| iteration | 迭代次数，用一个 batch 做一次参数更新算一次，一批一迭代 |

所以你手里有多少批，就有多少个 iteration。就相当于咱班有多少个组，就有多少个组长——一组一个组长。

一个 epoch 内部是这样跑的：

```text
一个 epoch：把训练集完整过一遍
├── batch 1  ──> 反向传播、更新一次参数 ──> iteration 1
├── batch 2  ──> 反向传播、更新一次参数 ──> iteration 2
├── ...
└── batch 7  ──> 反向传播、更新一次参数 ──> iteration 7
```

图里那个 7 是下面第一个例子的批次数：一个 epoch 里切出几批，就有几次参数更新。

第一个例子：训练 100 轮，总共 100 条数据，每批 16 条。

`100 ÷ 16 = 6` 余 `4`，也就是 6 批各 16 条，最后剩 4 条单独成一批，所以每轮 7 批。100 轮乘 7，一共 700 批，也就是 700 个 iteration。

第二个例子：5 万个样本，每批 256 条。

`50000 ÷ 256 = 195.3` 左右，四舍五入是 196。也就是说训练集里一共有 196 个 batch，一个 epoch 就有 196 个 iteration。每轮要用 5 万张，训练 10 轮就是 50 万张样本，iteration 是 `196 × 10 = 1960` 个。

批次数怎么算才不啰嗦？按最直白的算法，得先拿总数除以每批条数，看看有没有小数，有小数还得加一，很麻烦。这里有个分页公式，是我师傅传给我的，我又传给你们：

$$\text{批次数} = \left\lfloor \frac{N + B - 1}{B} \right\rfloor$$

翻译成人话：总条数加上每批条数减一，再对每批条数做整除。Python 里两个左斜线 `//` 就是整除，直接写：

```python
batch_num = (N + B - 1) // B
```

套一下 5 万和 256：`(50000 + 256 - 1) // 256`，结果就是 196。能整除的时候它也照样成立，`(N + B - 1) // B` 就等于 `N // B`，不用再分两种情况写。

### 四种梯度下降，区别只在一个 batch

深度学习里梯度下降的几种方法，根本区别就在 **batch size 不同**。

| 方法 | 每个 batch 用多少样本 | 特点 |
| :--- | :--- | :--- |
| 全梯度下降 BGD | 整个训练集的 N 条 | 一批就是全部，全部训完才更新一次 |
| 随机梯度下降 SGD | 1 条 | 每次只拿一条，更新最频繁 |
| 小批量梯度下降 Mini-batch | B 条，且 $1 < B < N$ | 取 1 条退化成 SGD，取全部退化成 BGD |
| 随机平均梯度下降 | 1 条，但与历史梯度求均值 | 初期效果不好，后期越来越准 |

全梯度下降是把 N 条当成一批，一批训练完了再走一步；随机梯度下降是每次只选一条；小批量是取其中 B 条，B 大于 1 并且小于 N——一共 100 条，你至少得选两条，选一条就成随机梯度下降了，把所有的都选上又变回全梯度下降。

还有一个随机平均梯度下降：第一次先选一个值算梯度；第二次算完梯度以后，拿第二个梯度和第一个梯度求均值作为结果；第三次再和上次的均值求均值。它的弊端是初期可能不准，但到后期效果会越来越准。

小批量的批次数，未整除时是 $N \div B + 1$，整除时就是 $N \div B$。别分两种情况写了，把上面那个分页公式丢过来，`(N + B - 1) // B` 一个式子就够。

这一块收个尾。梯度下降算法的思想，是寻找损失函数的最小值，它属于一种网络优化；网络训练里的三个概念，epoch 是训练的轮数，batch size 是每批的数据条数，iteration 是迭代次数也就是批次的数量——一批一个迭代。明天再被问到，就答这三句。

接下来就是优化方法那一坨：动量法、AdaGrad、RMSProp、Adam 四个优化器，配上等间隔、指定间隔、指数间隔三种学习率策略，再往后才是反向传播。

## 反向传播：把一次前向计算倒着拆回来
> 对应块：BLK22 | 覆盖分集：P54 | 块标题（分集名）：《Day04-13.反向传播(了解)》

### 先有正向传播，才谈得上反向

接下来要讲的是 BP 算法，back propagation，中文叫反向传播。

但你要真想听懂反向传播，得先知道另一个词——正向传播。数据从输入层进去，到隐藏层一，到隐藏层二，再到输出层，出输出结果，这整个动作叫正向传播，也叫前向传播。方向就一个字：从左往右。

现在问题来了。每一层都有自己的 $W$：这一层有 $w_1$、$w_2$、$w_3$，那一层也有自己的 $W$，再往后还有自己的 $W$。将来更新参数的时候，先更新谁？先更新最后一层的，还是先更新最前面那一层的？

先更新最后一层，再逐层往前传递。这个反着方向走的动作，就叫反向传播。

> **定义**：前向传播是数据输入到神经网络后逐层向前传，一直算到输出层；反向传播（BP，back propagation）是利用损失 error 值，从后往前，结合梯度下降逐层求导，依次完成参数更新。

梯度下降就是那个老公式：

$$W_{新} = W_{旧} - \eta \cdot \text{梯度}$$

$\eta$ 是学习率。这里先把形式记住，等下要往里代。

为什么非得"逐层"？因为拿到损失以后，你想直接算第一层的参数——算不了。损失式子里压根没有第一层那些权重，只有最后一层的输出。所以你只能先算最后一层，再往前传，一节一节剥。

### 参数有几组，为什么越往前越难更

先把这张图上的参数数清楚。一共 26 个。

怎么数出来的？不用一个个人肉点，按组数。靠近输入的那一组，每个节点要接 3 个输入、再加 1 个偏置，也就是每个节点 4 个参数，这样的节点有 3 个，三四一十二，12 个；中间那一组同样是每个节点 4 个参数，节点 2 个，二四得八，8 个；靠近输出的那一组，每个节点只有 2 个输入加 1 个偏置，3 个参数，节点 2 个，三二得六，6 个。12 + 8 + 6 = 26。

更新的时候顺序反过来：先把最后那 6 个更新掉，再更新中间那 8 个，最后才轮到最前面那 12 个。

为什么越往前越难更？因为越往前，路越多。

算靠近输出的那个权重，从总损失倒推回去基本只有一条链：损失 → 输出层的输出 → 输出层的加权和 → 这个权重，别无岔路。可你要是去算一个靠近输入的参数，情况就变了：这一个输入，上一层的每一个神经元都跟它连着，倒推的时候，每一条连接都是一条路。

```text
 靠近输出：损失 ──► 输出层输出 ──► 输出层加权和 ──► 这个权重
                   一条链，没有岔路

 靠近输入：损失 ──┬──► 输出节点 O1 这条路 ──┐
                  └──► 输出节点 O2 这条路 ──┴──► 隐藏层 ──► 这个权重
                   每往前一层，岔路就多一组
```

> **提示**：路多不只是"更麻烦"，还意味着"要相加"。同一个隐藏层权重，从上面那个输出节点传回来一份梯度，从下面那个输出节点也传回来一份，两份都得算进去。这才是隐藏层比输出层难更的根本原因——不是公式变复杂了，是路径变多了。

### 链式法则：把导数一路约下去

反向传播靠的是链式法则。

举个例子。要求 $Y$ 对 $X$ 的导数，但 $Y$ 和 $X$ 之间隔着 $A$ 和 $B$：

$$\frac{\partial Y}{\partial X} = \frac{\partial Y}{\partial A} \cdot \frac{\partial A}{\partial B} \cdot \frac{\partial B}{\partial X}$$

写成分数看就很直观：前一项的分母 $A$ 和后一项的分子 $A$ 约掉，$B$ 和 $B$ 约掉，剩下的正好是 $\partial Y / \partial X$。

> **提示**：约分只是帮助记忆的直观写法，真正保证成立的是链式法则本身——复合函数对自变量的导数，等于沿途每一段导数连乘。

这个"一段一段往回乘"的动作，就叫梯度传播。反向传播做的事，就是利用链式法则，沿着网络把梯度从后往前一段段传下去，对各个节点的权重做更新。

### 前向算一遍：每个节点只做两件事

换成一张能手算的小图：两个输入 $I_1$、$I_2$，两个隐藏节点 $H_1$、$H_2$，两个输出节点 $O_1$、$O_2$。

不管盯的是哪个节点，它们干的活都是同样的两件。

> **定义**：每个神经元先对上一层的输出做加权求和（外加偏置），得到 $net$；再把 $net$ 送进激活函数，得到 $out$。前向传播就是把这两步沿着层一遍遍重复。

加权求和里那个偏置，实际是当成一个"输入恒为 1"的权重加进去的，所以式子里总能看见一个 $\times 1$。

#### 隐藏层的加权求和与激活

先算 $H_1$ 的加权求和：

$$net_{h1} = w_1 I_1 + w_2 I_2 + b_1 \times 1 = 0.15 \times 0.05 + 0.20 \times 0.10 + 0.35 \times 1 = 0.3775$$

再把 0.3775 送进激活函数。这一层用的是 sigmoid：

$$\sigma(x) = \frac{1}{1 + e^{-x}}$$

式子里负号后面那个 $x$，就是刚才算出来的加权求和结果：

$$out_{h1} = \frac{1}{1 + e^{-0.3775}} \approx 0.5933$$

$H_2$ 是同一套流程：用 $w_3$、$w_4$ 和同一个偏置 $b_1$ 做加权求和，再套 sigmoid，得到 $out_{h2} \approx 0.5969$。

#### 输出层的激活与损失

输出层要注意一件事：它的输入不再是原始特征，而是隐藏层算出来的 $out$。

$$net_{o1} = w_5 \cdot out_{h1} + w_6 \cdot out_{h2} + b_2 \times 1$$

套 sigmoid，得到 $out_{o1} \approx 0.7514$。$O_2$ 换成 $w_7$、$w_8$，同样加上 $b_2$，激活后 $out_{o2} \approx 0.7729$。

四个节点的结果摆到一起：

| 节点 | 加权求和 $net$ | 激活输出 $out$ |
| :-- | :-- | --: |
| $H_1$ | $0.15 \times 0.05 + 0.20 \times 0.10 + 0.35 = 0.3775$ | 0.5933 |
| $H_2$ | $w_3 \times 0.05 + w_4 \times 0.10 + 0.35$ | 0.5969 |
| $O_1$ | $w_5 \times 0.5933 + w_6 \times 0.5969 + b_2$ | 0.7514 |
| $O_2$ | $w_7 \times 0.5933 + w_8 \times 0.5969 + b_2$ | 0.7729 |

激活输出就是预测值。有了预测值，就能算损失了。

这里用的是平方损失，两个输出各占一半：

$$E_{total} = \frac{1}{2}(t_1 - out_{o1})^2 + \frac{1}{2}(t_2 - out_{o2})^2$$

真实值 $t_1 = 0.01$，$t_2 = 0.99$。

两个平方加起来再除以 2，和各自先除以 2 再加起来是一回事。分开算更省事：

- 左边：$(0.7514 - 0.01)^2 \approx 0.5496$，除以 2 得 0.2748
- 右边：$(0.99 - 0.7729)^2 \approx 0.0471$，除以 2 得 0.0236
- 合计：$0.2748 + 0.0236 = 0.2984$

> **易错点**：0.2984 是总损失，不是某一个输出的误差。等下反向传播对 $out_{o1}$ 求导时，只有左边那一半跟它有关，右边那一半是常数，导数为 0，直接扔掉。把两项一起求导，是这里最容易犯的错。

到这儿，前向传播结束。算到这里，跟反向传播一点关系都没有，全是正向的活。

### 反向推一遍：以 W5 为例

要更新 $w_5$，就得求总损失对 $w_5$ 的导数 $\partial E_{total} / \partial w_5$。

能不能一步求出来？不能。因为损失式子里根本没有 $w_5$ 这个符号：损失里出现的是 $out_{o1}$，$out_{o1}$ 是 $net_{o1}$ 激活出来的，$net_{o1}$ 里才有 $w_5$。所以得一节一节剥：

$$\frac{\partial E_{total}}{\partial w_5} = \frac{\partial E_{total}}{\partial out_{o1}} \cdot \frac{\partial out_{o1}}{\partial net_{o1}} \cdot \frac{\partial net_{o1}}{\partial w_5}$$

```text
 E_total   总损失
    │
    │ ① 损失对预测值求导
    ▼
 out_o1    输出层激活后的预测值
    │
    │ ② 预测值对加权和求导
    ▼
 net_o1    输出层的加权求和
    │
    │ ③ 加权和对权重求导
    ▼
   w5      要更新的那个权重
```

三段从上往下乘一遍，就是 $w_5$ 的梯度。

#### 损失对预测值求导

总损失里只有第一项含 $out_{o1}$，第二项当常数处理，导数为 0。对第一项求导要分内外两层：外层是平方，$1/2$ 和外层求导下来的那个 2 相乘正好抵消，剩下 $(t_1 - out_{o1})$；内层 $(t_1 - out_{o1})$ 对 $out_{o1}$ 求导是 $-1$。合起来：

$$\frac{\partial E_{total}}{\partial out_{o1}} = -(t_1 - out_{o1}) = out_{o1} - t_1 = 0.7514 - 0.01 = 0.7414$$

#### 预测值对加权和求导

$out_{o1}$ 是 $net_{o1}$ 过 sigmoid 得到的，所以这一段就是 sigmoid 的导数。这个式子前面算过，结论可以直接用：

$$\sigma'(x) = \sigma(x)\bigl(1 - \sigma(x)\bigr)$$

$$\frac{\partial out_{o1}}{\partial net_{o1}} = out_{o1}(1 - out_{o1}) = 0.7514 \times (1 - 0.7514) = 0.7514 \times 0.2486 = 0.1868$$

为什么能直接把 $out_{o1}$ 代进公式？因为 $out_{o1}$ 本身就是 sigmoid 作用在 $net_{o1}$ 上的结果，公式里的 $f(x)$ 就是 $out_{o1}$，不必再把 $net_{o1}$ 反解回去。

#### 加权和对权重求导

$$net_{o1} = w_5 \cdot out_{h1} + w_6 \cdot out_{h2} + b_2$$

对 $w_5$ 求导，后面两项都是常数，导数为 0；$w_5$ 这一项求导，剩下的就是它自己的系数：

$$\frac{\partial net_{o1}}{\partial w_5} = out_{h1} = 0.5933$$

这一段最省事——不用算什么，把正向算出来的 $out_{h1}$ 搬过来就行。

#### 三段连乘才叫梯度

$$0.7414 \times 0.1868 \times 0.5933 \approx 0.0822$$

> **结论**：这个连乘的结果就是对 $w_5$ 的梯度。梯度不是其中某一个偏导，而是整条链上所有偏导乘起来。

拿到梯度，参数更新就是一代的事。$w_5$ 的初值是 0.40，学习率取 0.5（这是自己定的超参数）：

$$w_5^{新} = 0.40 - 0.5 \times 0.0822 = 0.3589$$

到这一步，$w_5$ 才算更新完。注意，只更新了一个参数。

### 再往前推：W6 和 W1 怎么走

$w_6$ 最好办。三段链路原封不动，只有第三段换个对象：对 $w_6$ 求导，剩下的是 $out_{h2}$。所以它的梯度就是那前两段的乘积再乘上 $out_{h2}$。

$w_1$ 的路就长了，得一路穿到隐藏层：

```text
 E_total ──► out_o1 ──► net_o1 ──► out_h1 ──► net_h1 ──► w1
  总损失      预测值    输出层加权和   隐藏层输出   隐藏层加权和   第一层权重
```

顺着 $w_5$ 那条线找到 $out_{h1}$，再由 $out_{h1}$ 找到 $net_{h1}$，最后由 $net_{h1}$ 找到 $w_1$。每往前一层，链上就多两段。

而且 $w_1$ 不止这一条路。从下面那个输出节点 $O_2$ 一样能走回来：损失 → $out_{o2}$ → $net_{o2}$ → $out_{h1}$ → $net_{h1}$ → $w_1$。

> **易错点**：两条路都通，而且两条都要算。$w_1$ 这种隐藏层权重被两个输出节点共用，它的梯度是两条路径传回来的贡献之和；只挑一条路算，等于把另一份梯度丢了。

这就是前面那句"越往前路越多"落地的地方：网络越深，同一个权重被复用的次数越多，反传时要走全的路径也越多。难的不是公式，是路径得一条条走完再累加。

### 一轮更新之后：拿新权重再算一遍

$w_1$ 到 $w_4$、$w_5$ 到 $w_8$ 全部更新完，这一堆权重就都是新值了。

然后拿同一批特征——特征本身不变——配上刚更新的权重和偏置，再前向算一遍，又能拿到一个新的损失；有了新损失，再反向传一遍，再更新一轮。

这就是平时说的"训练多少多少轮"。

> **结论**：一轮训练 = 一次前向（算出损失）+ 一次反向（算出梯度、更新全部参数）。所谓训练 N 轮，就是把这一整套动作重复 N 遍，每轮特征不变，变的是权重。

### 一句话分清前向与反向

前向传播：拿着特征，从输入层经隐藏层到输出层，从左往右，把结果算出来。

反向传播：拿着损失，从右往左，结合梯度下降那个公式

$$W_{新} = W_{旧} - \eta \cdot \text{梯度}$$

依次代入，把每一个参数更新掉。方向刚好相反，起点刚好相反，干的事刚好相反——一个负责算，一个负责改。

顺带说一句，这一节在讲义上标的是"了解"两个字。按"了解"的分量，半小时讲完就够了。但既然要按"掌握"来，那就得做到一件事——把 $w_5$ 那条三段链从头到尾自己写一遍、自己代一遍数，能独立走通，才算掌握。
