## 从词到向量：词嵌入层与循环网络层的第一关
> 对应块：BLK39 | 覆盖分集：P100-P102 | 块标题（分集名）：《Day07-09.词嵌入层_解释》

### 从“cat 后面跟谁”说起

我想分析一件事：cat 这个词的后边，应该是哪个词？

我不知道。你也不知道。为什么不知道？因为不同的字放在不同的环境里，语义是不一样的。

我常拿两句话考人。第一句：小明吃饭去呀，我去我不去。你告诉我，到底是去还是不去？第二句：小明骑车一把把把把住了。这里边连着四个“把”，每一个的身份都不一样——有的是量词，有的是动词，有的是名词“车把”，最后又回到动词。

> **提示**：同一串字符，在不同的上下文里承担的词性、语义都不同。机器如果只看到字符串，它连“这是几个意思”都分不出来，更别说算。

所以第一步不是建模，是换一种表示：把这个字转化成数值。转化成数值以后，我才能去分析这一组值和那一组值之间，到底有什么样的关系。

承载这件事的东西，就叫词表——确切地说，叫词向量表。

### 词向量表：左边是词，右边是数

词向量表长这样：左边一列是词，右边一片是数。左边告诉我这里边现在有多少个词——比如 100 个。你问我怎么知道是 100？举例而已，往下拉拉拉拉，一共 100 个。一会儿做歌词那个案例，去重以后是 5703 个词。

右边是每个词对应的词向量。我现在希望你把每个词转换成 128 维。128 是什么意思？就是用 128 个数值来表示这个词。这就是词向量的维度。

```text
        维度1    维度2    维度3    维度4    …
  cat    1.20     0.10     ...      ...
  meat   ...      ...      ...      ...
  on     ...      ...      ...      ...
  …      ...      ...      ...      ...
```

图里只有 4 列，所以这里的维度是 4；如果写成 128，那就是 128 列。行数是词的个数。按这个套路组合起来就是 100×128——100 个词，每个词 128 列。

单独看一个小例子：3×4。3 个词，每个词用 4 个数值表示。

有一点要提前讲清楚：每次生成的数值都不一样。这次是 1.2、0.1 这么一组，你下次再执行，它又变了。所以它的底层肯定是有公式在帮我们做这件事。你不用去管这个数值具体生成成什么，你只需要知道：生成的时候会按词在语料里出现的先后顺序来安排——你这个词的后边是那个词，那这个词和它的关联性就是最大的。将来假设我看到了 cat 这个词，下一个单词我大概率会给你生成跟它关系最近的那个。

> **结论**：词向量表把“语义上的远近”变成“数值上的关系”。初始的数值是随机的，这层关系要靠训练一点点长出来。

### 初始化：随机，或者借别人的

第一个动作，初始化词向量。

两条路：随机初始化；或者加载预训练的词向量，拿现成的来初始化。后者就是 word to vector——怎么把单词转成向量，这是一个稍微绕一点的地方，讲到 NLP 的时候会再展开。这里先拿来用，后面我会跟你聊这个东西。

我再说一遍：讲 RNN 的目的是给 NLP 做一个铺垫，并不是说 RNN 半天就讲完了。不可能。后边 NLP 大概还要讲好几天。

### 光有向量不够，还得有本字典

第二个动作，输入索引。

每个词在词汇表里有唯一的索引。什么叫词汇表？

你要把 100 个词往这一丢，然后让每个词生成词向量，能不能做？能做。但有问题：一共多少个词不知道；cat 在你这里边是第几个词不知道；on 是第几个不知道；有没有 where 这个词，我也不知道。所以还得有一张词汇表。

词汇表就是一个字典。怎么设？看你自个儿想怎么设置。比如拿索引当键：0 对应 cat，1 对应 meat，2 对应 on，再往下点点点点。这就是词汇表。

然后听好这句话：标准的词向量，不是拿词来转的，是拿索引来转的。把 0 那个词转成它，1 那个词转成它，2 那个词转成它。

一会儿这样的索引得有多少个？歌词案例一共 5703 个词，索引就到 5702。为什么到 5702？因为一共 5703 个词，从 0 开始数。

训练就是通过这样一条条索引，去学词与词之间的联系和关系。

### 一次映射，把索引换成向量

词嵌入层把这些单词的索引，映射为词向量。

这句话为什么非做不可？你让我分析词与词的关系，我分析不了汉字，做不了；单词也做不了。不同的单词在不同语境里的意思也不一样。

table 这个词，学过 SQL 的都知道它是表格。但 table 的本意还有一个：桌子。on the table，是放到桌子上；create table，你总不能说“创建个桌子”吧，那是建表。同样的单词，放在不同的语义里，意思完全不一样。

所以接下来要做的事就两步：先构建词表，构建完词表以后，拿它的索引来生成对应的词向量。这事由嵌入层干。

然后，把这些词向量作为输入。换言之，你的 RNN 分析的不是词表，也不是词，是词向量。

假设现在来一个“我爱你”，“我爱你”的后边是什么？不知道。但是我预测出来，这个位置应该是一个索引，比如 66。那我就去词汇表里，找 66 对应的那个词是谁，把它显示到这。这就是 AIGC 的样子：预测下一个词的索引，再去词汇表里把它找回来。

也就是说，整个处理是基于词向量做的，根据上下文生成下一个序列的输出。什么叫上下文？就是上一时刻的隐藏状态，加当前时刻的输入。

再说一遍：RNN 的输入，要的不是词汇表，也不是词，而是词向量。词向量有两种给法：一种是词直接对应它的向量，一种是词的索引对应向量。我们用后者。

这一关过了，下午的课你就真听懂接近一半，至少三分之一。剩下的就看循环网络你能不能听懂——能听懂它，你就学会了，剩下的都是案例。

### 新来的第四个 API

词嵌入层在 PyTorch 里叫 `nn.Embedding`。

词嵌入层对应的英文就是 embedding，所以 API 顺理成章叫 `nn.Embedding`。

顺便考你一下，还记得那几个 API 吗？全连接层叫 `Linear`；卷积层叫 `Conv2d`；池化层里用得最多的是最大池化，叫 `MaxPool2d`。就这几个，这几天天天写。今天又添一个：`Embedding`。

它要两个参数：

| 参数位置 | 含义 | 示例 | 歌词案例 |
| :--- | :--- | :--- | :--- |
| 第一个参数 | 词的数量，确切说是词表大小 | 10 | 5703 |
| 第二个参数 | 词向量的维度 | 4 | 128 |

先拿 10 和 4 举例。10 代表十个词；4 代表把每个词转化成四维的数值。

一会儿做案例——AI 杰伦歌词生成——左边这个数不用想，肯定是 5703；后边这个写 128，就是每个词生成 128 个数值。本质上来讲是一样的，只是规模不同。

> **定义**：`nn.Embedding` 是一张按行取值的词向量表。索引进去，对应的那一行向量出来；表里的数值在初始化时是随机的，之后跟着训练走。

### 先把语料切成词

玩 API 的第一步：先将语料分词。

语料就是这句：

> 北京冬奥的进度条已经过半，不少外国运动员在完成自己的比赛后踏上归途。

这就算语料了？还没完，后边还有个句号。

你帮我切一下词。你会怎么切？真有人上来“北”一刀、“京”一刀——正常人不会这么切吧。应该是“北京”“冬奥”这么切。

插一句题外话：有个地名把东南西北四个字占齐了，你知道是哪吗？北京西站南广场东——北京西站的南广场的东边，东南西北齐了。郭德纲和于谦的相声里好像讲过这一段。我没跟你开玩笑，真有这么个地名。

接着切：的、进度条、已经、过半；逗号；不少、外国、运动员、在、完成、自己、的、比赛、后、踏上、归途；句号。

这里藏着一个选择：那些重复出现的“的”，是只保留一个，还是照着原顺序都留下来？两种方案都可以做，一会儿两种都能走。

再往下就是个现实问题：如果让我们自己写一个切词的库，你会发现要训练好久。这个需求早就有人帮我们做完了——结巴分词器，`jieba`。

名字这里有个小讲究：不要说“G8 分词器”，这个词就叫 jieba，一般念拼音，中文写作结巴分词器。结巴怎么说话？断断续续。你去西餐厅吃饭，点了一瓶年份酒，服务员问你开不开，你一紧张“开开开开”全给开了，然后补一句“开玩笑是吧”——那不过分了吗。

装一下就行：`pip install jieba`。它有三种切词方式，NLP 课里专门有一节讲这三种方式的区别，还会讲 word to vector。这里先用第一种 `jieba.lcut`，它是专门切中文的。

### 五步把一句话变成一堆向量

把刚才那几步连起来，代码是这样的：

```python
import torch
from torch import nn
import jieba


def dm01():
    # 第一步：定义一句话
    text = "北京冬奥的进度条已经过半，不少外国运动员在完成自己的比赛后踏上归途。"

    # 第二步：使用 jieba 分词
    words = jieba.lcut(text)
    print(words)

    # 第三步：创建词嵌入层，第一个参数是词表大小，第二个是词向量维度
    embedding = nn.Embedding(len(words), 4)

    # 第四步：拿到每个词的下标索引
    indices = [i for i, word in enumerate(words)]

    # 第五步：把词索引转成词向量（要的是张量，所以先转 tensor）
    vectors = embedding(torch.tensor(indices))

    for i, word in enumerate(words):
        print(word, "\t\t", vectors[i])


if __name__ == '__main__':
    dm01()
```

建表前还有一步 `unique words` 去重，先把重复的词剔除再建表；这里为了看清楚“一个词一行”，直接把分词结果丢进去，所以重复出现的“的”会各占一行。

#### 分词结果长什么样

运行之后先出一堆日志，别慌，那不是报错。往下看有 `successfully`，成功的意思，上边都是日志。

分词结果：北京、冬奥、的、进度条、已经、过半、逗号、不少、外国、运动员、在、完成、自己、的、比赛、后、踏上、归途、句号——18 个词。

你看它切得跟人切的一模一样。搞 jieba 这个库的团队确实厉害。

但也不是万能。我拿“我去我不去”试了一下，“不去”被切成了两个——应该是两个还是一个？应该是一个词。这种就切得不太好。再拿“小明骑车一把把把把住了”试，这个反而切得不错：一把、把、把、把住，“把”的几种身份基本分开了。可以点个赞。

> **提示**：分词器的好坏直接决定词表的质量。词表错了，后面的索引、词向量、预测全都跟着错，所以这一环不能想当然。

#### 用 enumerate 拿索引

建层的时候，第一个参数我写了 `len(words)`。为什么不直接写 18？我确实刚看过，是 18 个词。但万一这句话改了呢？所以用列表长度，句子多长它都能自适应。

第二个参数我写了 4。8 维、10 维、256 维、128 维都无所谓，咱先小一点，四维，别那么大。

现在说说索引怎么拿。`for word in words` 打印出来的是每个词，但这个词的索引是多少，我不知道。最直白的写法是在循环外面写个 `i = 0`，循环里打印 `i` 和 `word`，然后 `i += 1`。能不能拿到索引？能，0 到 17 一路下来。

但这么写不够高效，也太 low 了。将来出去找工作，要二三十 K 的岗位，人家让你写代码，你写成小学生那样，说不过去。

Python 里没有 `i++`，那是 Java 的东西，别记错，自增写 `i += 1`。

换个写法，有个函数叫 `enumerate`：把 `words` 扔进去，前边就会给你一个 `i`、一个 `word`。效果同上，一样是 0 到 17。它做的事就是返回列表中每个值以及它的索引。

#### 索引进，向量出

这里要再确认一遍：要转成词向量的是谁？是索引，不是词。

这一步有个正式名字：word to vector。这个 `to` 就是“到”、转换的意思，vector 就是向量。连起来读，词到向量。

`embedding` 要的是张量，所以把索引包成 `torch.tensor(...)` 再扔进去。

打印的时候我在词和向量之间塞了两个 `\t`，让它缩进对齐。有的对齐了，有的没对齐——中文字符宽度不一样，这很正常，但比挤在一起好看多了。

看结果：北京这个词，转成了几个数值？1、2、3、4，四个。

再执行一次，你猜跟上次一样吗？不一样。刚才北京还是 0.05、0.55 那个量级，现在变成了 -0.1076。不用管它。关系是不变的：北京后边大概率是冬奥，逗号后边大概是进度条。

到这里，把词索引转成词向量这一波，就讲完了。

### 顺序为什么必须建模

“我爱你”这串文本是有顺序的。“我爱你”和“你爱我”，表达的意思完全不一样。顺序一颠倒，意思就变了。

为了表示出数据的序列关系，就需要用循环神经网络来建模。

> **定义**：RNN，全称 Recurrent Neural Network，循环神经网络，主要处理序列数据。所谓序列数据，就是后边的数据对前边的数据有依赖。

哪些是序列数据？天气预测、股市分析、文本分析、文本生成，这一堆全都是。

它由三层组成。第一层词嵌入层，把每个词生成对应维度的词向量。第二层循环网络层，根据词向量算下一个词：你传一个词进来，我算下一个词大概率是谁；你生成下一个词，我再算再下一个词大概率是谁。第三层输出层，把结果输出。

第二层干的那件事，其实就是 AIGC 的活。

### 三个神经元，还是一个

“我爱你”，我想预测“我爱你”的下一个词是什么。

你觉得后边应该是什么？有人接“你爱我”——那是蜜雪冰城的梗。我觉得后边应该是个逗号。

那我爱你后边到底是啥？第一次把“我”传进去，要基于最开始的上一次隐藏状态来算。问题来了：上次的隐藏状态是什么？

不知道。因为这是第一个字。

这就像《乡村爱情故事》拍第一部的时候，它的“上部”是什么状态？不知道。但拍第二部的时候，第一部结束的剧情是什么，我们是知道的，第二部肯定围绕它开始。又像《哪吒》：拍第一部的时候，饺子导演也不知道这个电影能那么火；到第二部《哪吒之魔童闹海》火成那样，他就有更多资金去玩第三部了。

回到正题。一开始的上次隐藏状态不知道，那就初始化一个全零的，先假设它有。于是：“我”在这里充当本次的输入，结合这个初始状态，就有了 H1——本次的隐藏状态。有了 H1，就有了“我”后边的那个字，记作 I。这个 I 就是预测出来的字：我的后边有一个 I。

这是一次，结束了。

下一次怎么办？把 I 当输入，结合上一次的隐藏状态，得到本次的隐藏状态以及输出。再下一次，把“你”弄进来，结合上次的隐藏状态，算本次的隐藏状态和本次的预测。那个 Y3，就是一会儿要放到“我爱你”后边那个位置的词。

现在问题来了：这里边一共有几个神经元？

三个。因为我爱你这句话切完是三个词，所以要做三回。

但是换个句子呢？“今天天气很好，非常适合出去玩”，或者“北京冬奥会圆满落幕，不少外国运动员已经踏上了回家的旅途”。就拿刚才那 18 个词的那句话来讲，神经元是不是得来十几个？如果丢一段诗、丢一个文本过来，神经元要更多。

所以神经元的数量到底是多少个？做不了，不知道。

这时候老外想了个办法：还是同一个神经元。第一次是它，第二次还是它，第三次还是它。同一个神经元，把词不断重复地、循环地往里边传。所以它叫循环神经网络。

本来是三个，现在变成一个：先传“我”，再传 I，再传“你”。

```text
  按词数铺神经元（数量随句子长度爆炸）
  x1="我" ──▶ [神经元] ──▶ y1
  x2="爱" ──▶ [神经元] ──▶ y2
  x3="你" ──▶ [神经元] ──▶ y3

  同一个神经元循环使用（数量恒为一个）
  x1="我" ──▶ [同一神经元] ──▶ h1 ──▶ y1="爱"
  x2="爱" ──▶ [同一神经元] ──▶ h2 ──▶ y2="你"
  x3="你" ──▶ [同一神经元] ──▶ h3 ──▶ y3="，"
```

读图：上面那排看着整齐，但句子一长就得跟着加神经元，加多少个事先算不出来；下面那排始终只有一个神经元，词一个一个喂进去，状态一步一步往下传。这就是“循环”两个字的来历。

### 记忆、上下文，和那个一直走的小球

这就叫记忆功能、上下文理解——连接不同的时间步，结合上下文的语义来分析。

顺着这个思路还能扯远一点。哪吒第三部里会不会出现孙悟空？大概率会——金箍棒都已经出来了。再往前倒：金箍棒原本还有个名字叫定海神针，是大禹治水时量水的那根尺子；大禹三过家门而不入，妻子等他等到化成了望夫石；孙悟空又是从石头缝里蹦出来的。石头、大禹、定海神针，一条线居然串下来了，说起来还是自己本家的武器。这叫野史，野史之所以叫野史，就是因为它野，有待考证。可你看它像不像刚才那件事——手里攥着一串已经发生的上下文，去推下一个最可能出现的东西？

看着是三个神经元，本质是一个。它每次都结合上一次的隐藏状态，加上本次的输入，得到本次的隐藏状态和本次的输出。

然后把那个 I 和这次的隐藏状态放进来，再预测下一个，再预测下一个。那个小球一直在走、一直在走——一个神经元在做这件事。

举个完整的例子。基于“我”预测出“你”：先把我传进来，结合上次的隐藏状态算本次的输出；本次输出是 I，把 I 放回来当本次的输入，再结合上次的隐藏状态推本次的隐藏状态，基于它推后边的“你”。

想预测“你”的后边，就把“你”拉过来往后推。想推“我爱你，”的下一个，就把 Y3 扔过来，结合 H3 推 H4，基于 H4 推 Y4。

这里边几个神经元？一个。

最后得到的是预测概率。注意：这里边显示的“不是你”，而是词库里每个词的概率全拿到了。一会儿运算量大就大在这——5703 个词，每次往下预测，都要把 5703 个词的概率算一遍。

选哪个？选概率最高的那个。

所以再问你一个问题：歌词生成有 5703 个词，起手那个词写“星星”、写“分手”，都可以，因为这 5703 个词里有这俩。但我能不能写个“AI”，让你基于 AI 看下一个是谁？

不能。你往里边一放，它就报错——去词表里找 AI，根本没有这个词。所以它不允许。

### 两个加权求和，中间夹一次激活

先看隐藏状态怎么来：

$$h_t = \tanh\left(W_{ih}x_t + b_{ih} + W_{hh}h_{t-1} + b_{hh}\right)$$

最外层的 $\tanh$ 是激活函数。$W_{ih}$ 是输入数据的权重，$b_{ih}$ 是输入数据的偏置，$x_t$ 是当前时刻的输入——所以 $W_{ih}x_t + b_{ih}$ 是这一路输入的加权求和。

上一次的隐藏状态是不是也该有一份？有。$W_{hh}$ 是输入隐藏状态的权重，$b_{hh}$ 是输入隐藏状态的偏置，$h_{t-1}$ 是上一次的隐藏状态，$W_{hh}h_{t-1} + b_{hh}$ 是另一路加权求和。

两路加起来，整体过一遍 $\tanh$，得到的值就是当前时刻的隐藏状态。

> **提示**：这里的 $\tanh$ 不是随手选的。在我接触的众多深度学习算法里，它是唯一一个底层默认用 $\tanh$ 的；剩下的那些底层一般选 ReLU。它比较老，从最初一路传到现代，所以底层就默认成了 $\tanh$。

拿到 $h_t$ 还没完，再做一次加权求和：

$$y_t = W_{hy}h_t + b_y$$

$y_t$ 就是当前时刻的输出。整件事说穿了就是两次加权求和：第一次，上一次的隐藏状态加当前时刻的输入，得到当前时刻的隐藏状态；拿着它做第二次加权求和，得到 $y_t$。

### 输出的是整个词表的概率

$y_t$ 是词汇表映射输出的一个向量。这个向量经过全连接层，输出得到最终的预测结果 $\hat{y}_t$。

$\hat{y}_t$ 里每个元素，代表当前时刻生成词汇表中每个词的得分。换言之，如果词表一共 5703 个词，那 $\hat{y}_t$ 就是这 5703 个词各自的得分。词汇表里有多少个词，$\hat{y}_t$ 里就有多少个元素值。

最终选什么？5703 个词里边，哪个概率最大选哪个。

每生成一个词，就再来预测下一次哪个词概率最大，再下一次哪个词概率最大，然后拼接、拼接、拼接，得到最终结果。这就是 AIGC。

说到这插一句。以前那是“人工智能”，也是“人工智障”。问它 9.11 和 9.9 谁大？显然是 9.9 大。它可能给你来个 9.11 大。说明它在做这种预测的时候，算法有问题。

```text
  h(t) ──▶ 全连接层 ──▶ ŷ(t)
                          │
                          ├── 词1   的得分
                          ├── 词2   的得分
                          ├── …
                          └── 词5703 的得分
                          │
                          ▼
                   取最大得分对应的词
```

读图：$h_t$ 经过一次线性变换，摊成和词表一样长的一排数；这一排数里最大的那个位置，就是这一步要生成的词。

### 把一次前向传播摊开

工作机制其实就三步：接收输入、更新隐藏状态、输出计算。

“接收输入”说的是两个东西：一个是隐藏状态，一个是输入元素。“更新隐藏状态”说的是 $h_1$。“输出计算”说的是把 $h_1$ 变成 $y_1$ 的那个动作。

```text
  h(t-1)  ──┐
            ├──▶ 加权求和 ──▶ tanh ──▶ h(t) ──▶ 加权求和 ──▶ y(t)
  x(t)    ──┘
```

读图：左边两路进来，一路是上一次的隐藏状态，一路是当前输入；两路合到一处做加权求和，过激活函数得到新的隐藏状态；新的隐藏状态再做一次加权求和，就是这一步的输出。

$h_0$ 是上一次的隐藏状态，结合当前输入得到 $h_1$，$h_1$ 是当前时刻的隐藏状态，基于 $h_1$ 算出 $y_1$。下一次把 $y_1$ 当输入，把当前的隐藏状态当作“上一次的隐藏状态”，算 $h_2$，再往下预测。

推进到后面就是：$h_1$ 预测 $y_1$，$h_2$ 预测 $y_2$，$h_3$ 预测 $y_3$，$h_4$ 预测 $y_4$，一路接下去。

### 文本生成：M 后面为什么跟出 A

现在落个地。假设初始词是 M。

M 扔进去，它是谁？它就是 $x_t$。上次的隐藏状态呢？我这里没有，就初始化一个全零的，假设有。于是有 $h_0$、有 M，就能算 $h_1$。

有 $h_1$，就能预测 $y_1$，也就是输出层的结果 $o_1$。$o_1$ 预测出来是 A——原来 M 的后边是 A。第一次结束。

A 的后边是什么？不知道。怎么办？把 A 代入输入，把刚才的 $h_1$ 当作现在的隐藏状态，基于 $h_1$ 和 A 算出 $h_2$，$h_2$ 再算 $o_2$。$o_2$ 去所有词里边，把每个词的概率都算一遍，选概率最大的那个拉过来，是 C。

下次把 C 放进来当输入，$h_2$ 当上一次的隐藏状态，基于 $h_2$ 和 C 算 $h_3$，基于 $h_3$ 算 $o_3$。C 的后边原来是 H。再把 H 拿来，$h_3$ 扔过来算 $h_4$……

重复、重复、重复，直到生成完整的词或者句子。

```text
  初始词 M
     │
     ▼
  h0(全零) + M ──▶ h1 ──▶ o1 ──▶ 取最大 ──▶ A
                                              │
      ┌───────────────────────────────────────┘
      ▼
  h1 + A ──▶ h2 ──▶ o2 ──▶ 取最大 ──▶ C
                                        │
      ┌─────────────────────────────────┘
      ▼
  h2 + C ──▶ h3 ──▶ o3 ──▶ 取最大 ──▶ H
                                        │
                                        ▼
                              继续，直到满 50 个词
```

读图：每往右走一格，就是一次完整的前向传播；上一格的输出变成下一格的输入，上一格的隐藏状态变成下一格的“上一次隐藏状态”。攒够长度就停——比如给个星星，再给 50 个词，那就是生成 50 个词结束。

有人会问：为什么是 A、C、H？你管我，我在这瞎写的。但正式写代码的时候，它确实会去所有词里边算每个词的概率，帮你挑最大的那个。

### 循环网络层对外是什么形态

循环网络层的作用，一句话：基于上一次的隐藏状态，加上本次的输入，得到本次的隐藏状态；基于本次的隐藏状态，得到本次的输出。

说出来是这样，但一会儿写代码你会发现，它没有箭头，是一个逗号——你给我俩，我直接给你俩。可刚才推公式的时候明明看到底层还有一步，这就是抽象封装的差别：公式讲的是内部怎么算，接口讲的是外面怎么调用。

公式还是那两个：

$$h_t = \tanh\left(W_{ih}x_t + b_{ih} + W_{hh}h_{t-1} + b_{hh}\right)$$

这一步对应“上次的隐藏状态加权求和 + 本次输入加权求和”。

$$y_t = W_{hy}h_t + b_y$$

有了 $h_t$ 以后，拿它做加权求和，得到的就是本次输出；换到词表的尺度上说，就是词汇表中所有词的概率，选概率最大的那个词作为最终预测结果。

5703 个词，每算一次都要把这 5703 个词的概率全算一遍，然后找最大的那个过来。

### 三层各司其职

| 层 | 作用 |
| :--- | :--- |
| 词嵌入层 | 把词，或者词的索引，转换为词向量的表示 |
| 循环网络层 | 逐步处理词向量，生成每个时间步的隐藏状态 |
| 输出层（全连接层） | 通过线性变换，把隐藏状态映射为词汇表中词的概率分布 |

“每个时间步的隐藏状态”这句话，展开就是：基于 $h_0$ 和本次输入得到 $h_1$，基于 $h_1$ 和本次输入得到 $h_2$，再得 $h_3$、$h_4$、$h_5$、$h_6$；$h_1$ 预测 $y_1$，$h_2$ 预测 $y_2$，$h_3$ 预测 $y_3$，$h_4$ 预测 $y_4$。

输出层通常给出的是词汇表中词的概率分布——你输出的其实是一排概率，告诉外面“到底是哪个词”。

```text
  文本
   │
   ▼
  [词嵌入层]   词 / 索引 ──▶ 词向量
   │
   ▼
  [循环网络层] 逐时间步：h(t-1) + x(t) ──▶ h(t)
   │
   ▼
  [输出层]     h(t) ──▶ 词表中每个词的概率分布
   │
   ▼
  概率最大的词
```

读图：从一句话进去，到下一个词出来，中间就是这三层在接力。词嵌入层负责把词变成数，循环网络层负责让数带上时间，输出层负责把时间还原成词。

## nn.RNN 循环网络层：参数、形状与一次前向
> 对应块：BLK40 | 覆盖分集：P103 | 块标题（分集名）：《Day07-12.RNN层(循环网络层)_API》

这次要拆的是 `nn.RNN`，也就是循环网络层。先打个预防针：真正落到代码上就那么几行，难的全在参数上；更让人头大的是，这一层要的四个张量，维度顺序一个和一个都不一样，光看形状说明就能把人看懵。

所以先拿一句大白话把它的行为定住：RNN 就像你的大脑在看电影的过程中记住剧情。同一部片子，有人能注意到身份令牌上画的是只鹰，有人连主角干了什么都说不清——记住多少，取决于你花了多少精力、有多大的“脑容量”去记。后面的参数、形状、返回值，都可以往这个画面上套。

### 三个参数：词向量维度、隐藏维度、层数

`nn.RNN` 最要紧的是三个参数。

`input_size` 是输入数据的维度，说白了就是词向量的维度——把一个词转成多少个数字。`hidden_size` 是隐藏层的维度，也就是隐藏状态向量有多长。`num_layers` 是隐藏层的层数，这个 RNN 有几层在处理；它默认就是 1，一般情况下一层也够用。

| 参数 | 含义 | 演示取值 |
| :--- | :--- | :--- |
| `input_size` | 输入数据的维度，也就是词向量的维度 | 128 |
| `hidden_size` | 隐藏状态向量的维度 | 256 |
| `num_layers` | 隐藏层的层数，默认 1 | 1 |

第一步，创建循环网络层，一行代码就够：

```python
import torch
import torch.nn as nn

rnn = nn.RNN(input_size=128, hidden_size=256, num_layers=1)
```

点进源码还能看到两个默认值：`num_layers` 默认确实是 1；旁边有个 `nonlinearity` 参数，默认用的激活函数是 `tanh`。这两个先记住——层数默认一层，激活默认 `tanh`。

### 一次前向：进去两个，出来两个

参数认完，先别急着往下写。得先弄清楚这一层每次被调用时吃什么、吐什么。

把 `x` 扔进去，再把 `h_0` 扔进去。`x` 是本次的输入，`h_0` 是上一时刻的隐藏状态。经过 RNN 处理，返回 `h_1`，也就是当前时刻的隐藏状态；除了 `h_1`，还会返回一个 `y_1`，就是 output。

```text
   x   ──┐
         ├──►  nn.RNN  ──┬──►  output
   h_0 ──┘               └──►  h_1
```

左边两路喂进去，右边两路拿回来；上面那一路是输出，下面那一路是当前时刻的隐藏状态。

这正是那张经典的 RNN 单元图：基于上一次的隐藏状态和本次的输入，得到本次的隐藏状态和本次的输出。整个层不管展开多长，每一步做的都是这一件事。

### 四个张量，四套形状

接下来是最容易看懵的地方。四个张量的形状说明摆在一起：

| 张量 | 形状 | 三个维度依次表示 | 演示取值 |
| :--- | :--- | :--- | :--- |
| `x` | `(seq_len, batch, input_size)` | 句子长度、批大小、词向量维度 | `(5, 32, 128)` |
| `h_0` | `(num_layers, batch, hidden_size)` | 隐藏层层数、批大小、隐藏状态维度 | `(1, 32, 256)` |
| `output` | `(seq_len, batch, hidden_size)` | 句子长度、批大小、输出向量维度 | `(5, 32, 256)` |
| `h_n` | `(num_layers, batch, hidden_size)` | 隐藏层层数、批大小、隐藏状态维度 | `(1, 32, 256)` |

你看这玩意是不是有点奇葩：每个东西要的维度顺序都不一样。要都一样，这 API 就好记了；偏偏 `x` 以句子长度打头，`h_0` 以层数打头，`output` 又绕回句子长度。光看这张表，确实容易懵。

懵归懵，规律还是有的：凡是隐藏状态（`h_0`、`h_n`），第一个维度都是层数，后面跟着批大小和隐藏维度；凡是跟序列打交道的（`x`、`output`），第一个维度都是句子长度，后面跟着批大小和那一时刻的向量维度。

> **提示**：形状说明里的 `h_n` 和代码里拿到的那个“当前时刻的隐藏状态”是同一个东西。`h_n` 是站在整条序列的角度起的名字，指的是最后一个时间步的隐藏状态；下面按当前时刻叫它 `h_1`。

### 每帧的细节与脑子的容量

形状是死的，含义得换成大白话。

先说 `input_size=128`：它把这一个词转成 128 个数字。前面画示意图时用的是 4 维，这里给到 128 维。你可以把它想成电影里每一帧画面有 128 个细节——颜色、动作、表情之类。RNN 每次看到的就是这 128 个细节。RNN 是谁？RNN 就是你的大脑。每读一个词，大脑接收到的就是这个词的 128 个细节。

再说 `hidden_size=256`，也就是隐藏状态向量的维度。这个数越大，说明上一时刻的隐藏状态记录的信息越多。用看电影打比方：上一部片子给你的剧透越多，你是不是越方便猜下一部的剧情？

拿《哪吒2》来说。最后一个画面是什么？金箍棒出来了。如果金箍棒出来之后，画面再切到一座山、山上有猴子，那下一部里悟空大概率就要登场了。你能猜到这一步，是因为脑子里存着“金箍棒—悟空”这条线索。`hidden_size` 干的就是这个：它决定你能存下多少条这样的线索。

注意，256 不是“脑子的大小”，是“脑容量”——当前时刻你愿意花多少精力去记。同一部《哪吒2》，有人看完能跟你聊半天细节，有人只记得打斗很燃，差别就在这儿。你记住多少，还要看当时大脑里活跃的神经元有多少个；`hidden_size` 就是给这份“活跃度”定了个长度。

具体到 RNN 里，这 256 维可以拿来记角色关系，也可以拿来记情节提要。比如《哪吒2》里有四大龙王，敖丙他爹叫敖光，他是哪个海的龙王？北海还是东海？再超纲一点：他身上那件万鳞甲，真有一万片鳞？“万鳞”只是说很多，不是精确的一万。敖丙的姑姑又是哪个海的龙王？这些都属于“角色关系”这一类信息。

《哪吒2》里这种细节特别多。玉虚宫发给门人的身份令牌，上面画的是只鹰——就是美国国旗上那只鹰；前期人人都想要令牌，到后面令牌被弄碎了。乾元顶刚进玉虚宫的时候特别像“五什么楼”——我可没说破。顶封口那个小窗口上还有个图标，是一个 dollar，一个 S 加两竖线。还有大家追着要的玉液琼浆，后来发现是哪吒在里面撒的尿。仙丹也是，申公豹那么努力攒了一大堆，给弟弟申小豹吃，结果在别人眼里那玩意跟糖豆一样多。

顺着申公豹这条线还能多说一句：太乙接到的任务是让灵珠转世，做成了就能位列十二金仙；申公豹累死累活，最后争取到的机会跟太乙完全不是一个量级。他那句“人心中的成见是一座大山”，配着这个处境看，确实有点给角色洗白的意思，跟《封神榜》里的申公豹已经很不一样了。

这些细节，看的时候留意到了就是存进去了，没留意就是没有。`hidden_size` 说的就是这件事：你拿多大的向量、花多大的精力去记。值越大，能存储的剧情记忆就越多。

这种“记没记住”的差别随时能验证。杰森·斯坦森的电影，《机械师》《速度与激情》，还有一部《以暴制暴》。《速度与激情》这个系列我也一直在追，拍到最终章（上），据说后面还有中和下，再有一两部就收尾，之后就不拍了；国内好像一直还没上，我还在等。我问你，《速度与激情》第六部是哪一部？第六部是核潜艇那一部——我没记错的话。我一说“核潜艇”，你脑子里那个画面是不是就回来了？另一部我一直在追的是《乡村爱情》。再比如《西游记》，我说一句“师父”，哪一集都有；换个说法——一个圈能套各种兵器——你马上就知道是太上老君的金刚琢、青牛精那一关。

很多东西你其实都见过，只是一时想不起来，给个提示就出来了。隐藏状态存的就是这一类东西：存得越多，越容易被提示唤醒。

> **易错点**：128 和 256 别搞混。128 是每次输入的长度——每看一个词，进来的就是 128 个数字；256 是能记住多少——这个数越大，记住的东西越多。一个管“看进来多少”，一个管“存下来多少”。

### 一层看剧情，两层做深加工

`num_layers` 是大白话最好解释的一个：你的大脑只有一层来处理它，就是 1；如果是 2，说明有两层大脑接力理解剧情——第一层先处理，第二层再深加工。

说白了，就是在这里解读几次：解读一次，还是深度解析？深度解析就像前面聊的那些野史，够野。比如“斜月三星洞”，菩提老祖的道场——斜月加三星，一弯月配三个点，拼起来是个“心”字，说的其实就是心。再比如一个筋斗十万八千里，这个数字背后也有讲究；金箍棒重一万三千五百斤，据说跟人一天呼吸的次数有点关系。这些其实都是道教里的一套数值。往深了解读，越看越有意思；浅一点看，就只看到“搬救兵、搬救兵、搬救兵”。

再往野了扯，大禹和猴子有没有关系？好像也能扯上。

回到参数上：`num_layers` 就是“这个 RNN 有几层在处理”。默认 1 层，一般也取 1 层。层数一变，`h_0` 第一个维度就得跟着变——造 `h_0` 的时候会看到。

### 造出输入：三十二个人同时看五帧

第二步，造出本次的输入 `x`。它要随机生成，长度必须和 `input_size` 对齐：

```python
x = torch.randn(size=(5, 32, 128))
```

三个数按顺序念：5 是 `seq_len`，也就是每个句子的长度、一个句子有多少个词；32 是 `batch`，也就是句子的数量、一批里有几个句子；128 是词向量的维度，必须和创建层时写的 `input_size` 一致。

换到电影画面上：这相当于一部电影总共 5 帧画面，同时有 32 个人在看。咱们班要是有 32 个人一起看《哪吒2》，看完我来问细节，你信不信，有些细节有人留意到了，有人完全没印象？32 个人看的是同样的 5 帧，每个人记住的内容却不一样——`batch` 这一维装的就是 32 个各自独立的样本。

所以整个输入可以读成一句话：32 个人，每人看 5 帧新画面，每帧有 128 个细节。

### 上一时刻的记忆：h_0 的三个数

有了 `x`，第三步是补上上一时刻的隐藏状态 `h_0`：

```python
h_0 = torch.randn(size=(1, 32, 256))
```

还是随机生成。三个数逐个看。

第一个 1 对应 `num_layers`，隐藏层的层数，也就是 RNN 的层数。一层大脑来记这个事，不过度解读，只看剧情。这个数必须和创建层时写的 `num_layers` 一致。

第二个 32 是批大小，和 `x` 里的 32 是同一批人。

第三个 256 是隐藏状态向量维度，和 `hidden_size` 一致。

连着 `x` 一起读：32 个人，每个人脑子里都有一幅画，画的是他们对上一部电影记住了多少；现在再给他们看新的 5 帧，每帧 128 个细节，看这 32 个人能记住多少。

`h_0` 是 `(1, 32, 256)`，`x` 是 `(5, 32, 128)`。前者是“看新片之前脑子里的存量”，后者是“这一次要看的新内容”。

### 调用一次，拿回两个结果

第四步是落地：把 `x` 和 `h_0` 一起丢给 RNN，拿回当前时刻的输出和当前时刻的隐藏状态。

```python
output, h_1 = rnn(x, h_0)

print(output.shape)
print(h_1.shape)
```

`output` 打印出来是 `(5, 32, 256)`，`h_1` 是 `(1, 32, 256)`。

`output` 是每个时间步的输出，包含了所有时间步的隐藏状态，所以第一维回到句子长度 5：5 帧画面、32 个人、每帧 256 维——每看一帧，大脑记住的剧情都存了一份。

`h_1` 是最后一个时间步的隐藏状态，只关注最后一帧，所以第一维是层数 1：看完最后一帧，脑子里最新的那份剧情记忆。

《哪吒2》最后一个画面，是在陈塘关外，哪吒和敖丙相视而立，夕阳照过来，两个人的身影被拉得很长，然后结束。`h_1` 就是看完这个画面之后，你脑子里剩下的那份记忆。

把时间展开，`output` 和 `h_1` 的关系就清楚了：

```text
   x_1 ──► [ RNN ] ──► y_1
              │
              ▼
   x_2 ──► [ RNN ] ──► y_2
              │
              ▼
   x_3 ──► [ RNN ] ──► y_3
              │
              ▼
   x_4 ──► [ RNN ] ──► y_4
              │
              ▼
   x_5 ──► [ RNN ] ──► y_5
```

每一行是一个时间步：吃进这一刻的输入，吐出这一刻的输出 `y`，再把这一刻的隐藏状态顺着向下的箭头交给下一刻。五个 `y` 收起来就是 `output`，最后一行吐出的隐藏状态就是 `h_1`。

> **结论**：`x` 和 `output` 的第一维都是句子长度，`h_0` 和 `h_1` 的第一维都是层数；隐藏状态永远是 `(num_layers, batch, hidden_size)`，输入和输出永远是 `(seq_len, batch, 向量维度)`。

最后把这四样东西对回那张经典图：`x` 是本次输入，`h_0` 是上一时刻的隐藏状态，`output` 是当前时刻的输出，`h_1` 是当前时刻的隐藏状态。单步图里画的 `y_1` 只是其中一个时刻，`output` 把 5 个时刻的 `y` 都存了下来。进去两个，出来两个，中间这一下就是循环网络层干的全部事情。

四步连起来，完整跑一遍是这样的：

```python
import torch
import torch.nn as nn

# 1. 创建循环网络层：词向量 128 维，隐藏状态 256 维，一层
rnn = nn.RNN(input_size=128, hidden_size=256, num_layers=1)

# 2. 本次输入：(seq_len, batch, input_size)
x = torch.randn(size=(5, 32, 128))

# 3. 上一时刻的隐藏状态：(num_layers, batch, hidden_size)
h_0 = torch.randn(size=(1, 32, 256))

# 4. 调用：拿回所有时间步的输出，以及最后一个时间步的隐藏状态
output, h_1 = rnn(x, h_0)
print(output.shape)   # torch.Size([5, 32, 256])
print(h_1.shape)      # torch.Size([1, 32, 256])
```

代码就这么几行，真正要花时间的是每次看到形状都能换算回那个画面：几帧、几个人、每帧多少细节、脑子里存下多少。把这几问答顺了，`(5, 32, 128)` 和 `(1, 32, 256)` 就不会再记反。

## 周杰伦歌词生成器：词表与滑动窗口数据集
> 对应块：BLK41 | 覆盖分集：P104-P105 | 块标题（分集名）：《Day07-13.RNN_AI歌词生成器案例_构》

接下来我们要做一个 RNN 的文本生成案例——AIGC，用 AI 来生成周杰伦的歌词。

这个案例的定位得先摆清楚：它的目的是让你对 RNN 先有一个简单的印象，不是一口气把 RNN 讲透。接下来的十二天里，至少有一半时间都在和 RNN、和这种序列相关的数据打交道，明天开始讲的内容一路往下，全是序列相关的东西。所以这里只是开个头，先快速过一遍，有个印象；后面往深里讲、详细讲，学起来反而轻松。你要是现在就担心"讲太快跟不上"，把心放回肚子里，后面有大把时间慢慢磨。

### 先看清整个案例的骨架

这个程序最终要干的事，说穿了就一句话：拿杰伦的歌词训一个模型，然后给一个起始词、给一个长度，让它顺着往下生成歌词。

整个案例比以往多一步，拆开是五步：

1. 获取数据，分词，构建词表；
2. 数据预处理，构建数据集；
3. 搭建 RNN 神经网络；
4. 模型训练；
5. 模型预测。

五步各自落成一块代码，最后再补一个 main 入口，也就是第六步"测试"，先写个 `pass` 占位，用到的时候再说。

第一步的活儿最杂：读文件、切词、去重、建词表、把整篇歌词换成索引。第一个函数 `build_vocab` 是整个案例里最绕的一个，后面反而会简单很多。有人看到这儿可能想：这玩意儿就这么简单？嘿，想多了——这一页的代码量不小。

数据在发下来的资料里，文件名是「杰伦 lyrics」，拖到项目的 `data` 目录下，别贴错位置。这个文件一共 5819 行，你不信就拉到末尾自己数。不过要提前说一句：按词算，数量只会比 5819 多，不会少——一行歌词里有空格，切词会把它切成好几个词。

导包这一堆前面都见过，不再逐个解释：

```python
import torch
import jieba
from torch.utils.data import DataLoader, Dataset
from torch import nn, optim
import time
```

`torch` 负责计算，`jieba` 负责切词，`DataLoader` 是数据加载器，`nn` 里是各种层，`optim` 是优化器，`time` 用来计时。不想手敲，就把前面文本生成案例里的 import 整块复制过来。

整个案例的数据流是这样：

```text
data/杰伦lyrics（5819 行）
        │  逐行读 + jieba 分词
        ▼
all_words（列表套列表：一行一个子列表）
        │  去重
        ▼
unique_words（5703 个词）
        │  enumerate 建映射
        ▼
word_to_index（词 → 索引）
        │  每行换成索引，行尾补空格索引 40
        ▼
corpus_index（一整条编号长龙）
        │  五个一窗，输出整体右移一位
        ▼
(X, Y) 成对样本 → DataLoader → RNN
```

读图：前半段是"把人话压成编号"，后半段是"把编号喂给网络"，词表就是中间的关口——模型不认识"想要"这两个字，只认识数字。编号还只是中间产物，真正进网络之前，每个编号还要映射成词向量，然后才拿去做训练。

### 把 5819 行歌词压成一张词表

函数叫 `build_vocab`，从头到尾七个动作。

#### 两个列表先摆好

```python
unique_words = []   # 去重后所有的词
all_words = []      # 每行文本的分词结果
```

`unique_words` 最后要回答"一共有多少种词"；`all_words` 要按行留住每一句的分词结果。两个都得有——一个用来建词表，一个用来把整篇歌词按原顺序换成索引。

#### 逐行读、逐行切

```python
for line in open('./data/杰伦lyrics', 'r', encoding='utf-8'):
    words = jieba.lcut(line)
    all_words.append(words)
    for word in words:
        if word not in unique_words:
            unique_words.append(word)
```

逐行读文件还是前面学过的字节流那套：`open(路径, 'r', encoding='utf-8')`，`r` 表示读，`encoding` 指定码表。

切词用 `jieba.lcut(line)`。这里我故意没做 `strip`，先打印一行看看切完什么样，打印出来是 `['想要', '有', '直升机
']` 这个样子——换行符直接粘在了最后一个词上。这一眼很关键：它说明"一行"这个概念，在切完词之后就没有独立标记了。打印只是确认，看完就删。

每行切完的结果 `append` 进 `all_words`，这个列表就成了列表套列表：

```text
all_words = [
    ['想要', '有', '直升机\n'],    ← 第一句歌词切完
    [...],                         ← 第二句歌词切完
    [...],                         ← 第三句歌词切完
]
```

内层是一句话的词，外层是所有的句子。这个结构后面要用两次：一次去重，一次转索引。

#### 去重，剩 5703 个词

去重就是一句判断：不在 `unique_words` 里，才加进去。

```python
word_count = len(unique_words)   # 5703
```

5703 是"多少种词"，不是"一共多少个词"。同一个词出现一百次，在这里只算一个。这个区别现在看着小，等会儿写 Dataset 的时候会咬人一口。

#### 词作键，索引作值

```python
word_to_index = {word: i for i, word in enumerate(unique_words)}
```

`enumerate` 从头到尾给词表编号，`i` 是索引，`word` 是词。谁做键？词做键，索引做值。反过来写成 `{i: word}` 也成立，那就是"拿索引查词"，可后面我们干的是"拿到一个词、查它的编号"，所以键必须是词。

打印出来，编号从 0 一直到 5702。为什么是 5702 收尾？因为从 0 开始数，5703 个词，最后一个自然是 5702——看着像少一个，其实一个没少。字典最末一项是「冠军要大卖」。

#### 给每句话补一个结束标记

最后一步，把整篇歌词换成索引。先准备一条空的长列表：

```python
corpus_index = []
```

然后逐行处理：

```python
for words in all_words:
    temp = []
    for word in words:
        temp.append(word_to_index[word])
    temp.append(word_to_index[' '])
    corpus_index.extend(temp)
```

拆开看：

- `temp` 装"这一行的索引"，每行开头清空；
- 内层循环把一行里的每个词换成编号，靠的就是刚才那张词表；
- 行尾再补一个 `word_to_index[' ']`，也就是空格这个词的编号，它在词表里是 40；
- `extend` 把 `temp` 摊平着接进 `corpus_index`。

`extend` 和 `append` 的差别必须分清：

```text
append:  corpus_index = [[0, 1, 2, 40], [3, 4, 5, 40]]   列表套列表
extend:  corpus_index = [0, 1, 2, 40, 3, 4, 5, 40]        摊平成一条长龙
```

我要的是下面那条长龙。用 `append`，你得到的是一堆句子，句子里才是编号；用 `extend`，整篇歌词才连成一条连续的序列——RNN 要的正是这种连续。

> **易错点**：`append` 把整个列表当一个元素塞进去，`extend` 把列表里的元素逐个接上去。前者套一层，后者摊平。

行尾这个 40 是我特意补的"句号"。一开始这一步空着没写，直接 `extend`，打印出来一看：整条长龙全是数字，一句歌词和下一句粘在一起，你根本找不到"这句话到哪儿结束"。再往下想更荒唐——一句歌词连着几百个编号，谁能一口气唱完？中间怎么换气？肺活量得多大？

所以每行末尾补一个 40，看到 40 就知道一句话讲完了。

> **提示**：40 不是行号也不是长度，它是"空格"这个词在词表里的索引。每行结尾补的就是它。

最后把四样东西一起返回：

```python
return unique_words, word_to_index, word_count, corpus_index
```

去重后的词列表、词表、去重后的词数、全文的索引长龙——建词表这件事的四份产物，其中 `corpus_index` 是下一步的原料。

合起来看一遍：

```python
def build_vocab():
    # 1. 定义变量：去重后的词、每行的分词结果
    unique_words = []
    all_words = []

    # 2. 遍历数据集，获取每行文本
    for line in open('./data/杰伦lyrics', 'r', encoding='utf-8'):
        # 2.1 对每行歌词分词
        words = jieba.lcut(line)
        # 2.2 分词结果记到 all_words（列表套列表）
        all_words.append(words)
        # 2.3 去重后加到 unique_words
        for word in words:
            if word not in unique_words:
                unique_words.append(word)

    # 3. 统计去重后词的数量
    word_count = len(unique_words)
    print(word_count)

    # 4. 构建词表：词作键，索引作值
    word_to_index = {word: i for i, word in enumerate(unique_words)}

    # 5. 歌词文本用词表索引表示
    corpus_index = []

    # 6. 遍历每一行的分词结果
    for words in all_words:
        # 6.1 记录本行的词索引
        temp = []
        # 6.2 取每个词对应的索引
        for word in words:
            temp.append(word_to_index[word])
        # 6.3 行尾补空格索引，作为一句的结束标记
        temp.append(word_to_index[' '])
        # 6.4 extend 摊平进 corpus_index
        corpus_index.extend(temp)

    # 7. 返回四份产物
    return unique_words, word_to_index, word_count, corpus_index
```

到这儿，第一个函数写完了。它在数据流图上干的，就是把左边那半段全部走通。

### 词表有了，数据集为什么还不能直接用

训练需要一个数据加载器，标准套路前面用过很多次：

数据 → 张量 → `TensorDataset` → `DataLoader`。

- 把索引长龙转成 `tensor`；
- 用 `TensorDataset` 包成数据集对象；
- 交给 `DataLoader` 分批。

前两步都不难，卡在中间这一步：这次的数据集不能这么封。

`TensorDataset` 的前提是"你手里是一堆独立样本，第 i 条就是第 i 条"。可 RNN 训练要的不是这个。它学的是"给定前面的词，下一个词是什么"，所以样本必须成对：

```text
给 0  → 要它预测 1
给 1  → 要它预测 2
给 2  → 要它预测 3
```

读图：每一组样本都是"当前词 + 下一个词"，模型学的就是这个先后关系。

一个词一个词地喂，能训，但太慢——每步只挪一个词。于是改成一次给五个：连续五个编号作为一个样本，让模型一次预测接下来的五个。

这样一来，样本就不是从数据里"随便切"出来的，而是要在一条长序列上按固定步长滑出来。窗口多大、从哪儿开始、什么时候停，`TensorDataset` 全管不了。这个数据集只能自己写：定义一个类，继承 `Dataset`。

> **结论**：`build_vocab` 解决"词怎么变成编号"，自定义 `Dataset` 解决"编号怎么变成成对的训练样本"。两件事分属两层，别混。

### 红框与蓝框：把长龙切成输入和答案

画两个框。红框是输入，蓝框是输出，蓝框永远比红框往右错一位。

```text
编号长龙:  0   1   2   3   40  0   4   ...
红框输入: [0   1   2   3   40]
蓝框输出:     [1   2   3   40  0]
```

读图：红框里的五个词是模型看得到的上下文，蓝框里的五个词是它要预测的答案；蓝框的每一位都对着红框的下一位，问的就是"每个词后面跟着谁"。这里用一组简化编号来示意，40 是空格这个词的索引，别纠结某个数字具体对应哪个词。

两个框一起右移一位，再取下一组，一直滑到长龙末尾：

```text
第 1 次: X = [0, 1, 2, 3, 40]   Y = [1, 2, 3, 40, 0]
第 2 次: X = [1, 2, 3, 40, 0]   Y = [2, 3, 40, 0, 4]
```

看这两行：每右移一位，红框丢掉最左边一个词、右边补进一个新词；蓝框跟着做同样的动作，起点永远比红框晚一位。

滑到末尾有个坑：红框不能取到最后一个元素。假设最后五个词就摆在这儿，红框停住，蓝框再往后挪一位就没词了。所以红框的最后一个元素最多落在倒数第二个位置上；蓝框可以取到最后一个元素，因为它的最后一位正好是红框最后一位的下一个。

> **提示**：红框、蓝框长度一样，都是五个，差别只在起点——蓝框比红框晚一位。红框的终点必须给蓝框留出一位，否则蓝框就伸出序列外了。

### 自己写一个 Dataset

自定义数据集就是继承 `torch.utils.data.Dataset`，然后实现三个方法。这三个都是"魔法方法"，不用你手动调，Python 到点会自动调：

- 创建对象时，自动调 `__init__`；
- 对它用 `len()` 时，自动调 `__len__`；
- 对它用 `对象[索引]` 时，自动调 `__getitem__`。

三件事写对，`DataLoader` 就能像用内置数据集一样用它。

#### 初始化：把四件事算清楚

```python
def __init__(self, corpus_index, number_chars):
    # 1.1 文档数据中词的索引（整条长龙）
    self.corpus_index = corpus_index
    # 1.2 每个句子（窗口）要几个词
    self.number_chars = number_chars
    # 1.3 文档数据中词的数量——不去重
    self.word_count = len(self.corpus_index)
    # 1.4 句子（窗口）的数量
    self.num_samples = self.word_count // self.number_chars
```

传进来两样：整条索引长龙，和每个窗口要几个词。

1.3 这一行得停一下。`word_count` 是全文一共有多少个词，不去重。为什么不能去重？索引长龙里的 0 代表"想要"，而"想要"在整份歌词里出现了很多次，每次都是 0。你按去重的 5703 去算窗口，数量就全错了。这里要的是长度，不是种类。

> **提示**：`build_vocab` 里的 `word_count` 是 5703，指"有多少种词"；Dataset 里的 `word_count` 是 `len(corpus_index)`，指"全文一共多少个词"。名字一样，含义完全不同，别串。

1.4 用整除 `//`：有多少个完整的五，就有多少个样本；末尾不够五个的词凑不成完整窗口，舍掉。假设全文 100 个词、窗口 5，那就是 20 个样本。

#### 长度：回答"有多少个样本"

```python
def __len__(self):
    return self.num_samples
```

`len(dataset)` 会走到这里，只回答一个问题：有多少个样本。数量在初始化时就算好了，不用每次现数。

#### 取样本：越界修正与两段切片

```python
def __getitem__(self, index):
    # 3.1 修正起始索引，保证落在合法范围内
    start = min(max(index, 0), self.word_count - self.number_chars - 1)
    # 3.2 结束索引
    end = start + self.number_chars
    # 3.3 输入值：start 到 end 这一段
    X = self.corpus_index[start:end]
    # 3.4 输出值：整体右移一位
    Y = self.corpus_index[start + 1:end + 1]
    # 3.5 以张量形式返回
    return torch.tensor(X), torch.tensor(Y)
```

`dataset[0]` 会走到这里，`index` 的意思是"这个窗口从哪儿开始"。

先修正起始位置。外面套 `min`，里面套 `max`，跟 ReLU 的 `max(0, x)` 一个思路：

- 下界 `max(index, 0)`：传负数进来一律压成 0。Python 里写 `-1` 确实能取到最后一个元素，可正索引和负索引混着用，"我们就没得玩了"，所以这里干脆不允许负数。
- 上界 `word_count - number_chars - 1`：太大也不行。假设全文 100 个词、窗口 5，`start` 最多只能到 94。为什么不是 95？因为 `start = 95` 时，输入取 95 到 99，输出就要取 96 到 100——100 已经越界了。减掉的这个 1，就是给蓝框留的最后一位。`start = 94` 时，输入 94 到 98、输出 95 到 99，正好把最后一个词吃进来。

> **易错点**：上界里的 `- 1` 不是随手写的。少减这个 1，最后一个窗口的输出切片就会越界。

然后是两段切片：

| 变量 | 切片写法 | `start = 0` 时拿到的索引 |
| :--- | :--- | :--- |
| `X`（输入） | `corpus_index[start:end]` | 0、1、2、3、4 |
| `Y`（目标） | `corpus_index[start+1:end+1]` | 1、2、3、4、5 |

`end` 就是窗口末尾。切片包左不包右，所以 `start = 0`、`end = 5` 拿到的正好是 0 到 4 这五个，不多不少——这就是为什么 `end` 直接加五就行，不用再减一。`Y` 的起点是 `start + 1`、终点是 `end + 1`，整体右移一位，长度和 `X` 一样。

最后用 `torch.tensor` 把两个列表包成张量返回。列表只是 Python 里的东西，包成张量，`DataLoader` 取出来的 batch 才能直接进模型。

这段代码，每一行你都认识；写到一块，第一次看确实容易晕。不是语法难，是"窗口在长龙上怎么挪"这件事得先在脑子里跑一遍。

## 搭建 AI 歌词生成器的神经网络
> 对应块：BLK42 | 覆盖分集：P106 | 块标题（分集名）：《Day07-15.RNN_AI歌词生成器案例_搭》

数据那一段收拾完，这个案例的动作就换成了构建网络。这一步得先打个预防针：它是整个案例里最容易绕进去的地方，因为一路上要时刻盯着数据格式怎么变。

### 三层处理，绕在维度上

先把要干的事拆开：词嵌入层、循环网络层、全连接层，三层依次处理，最后得到结果。搭网络的顺序也是这个顺序——先建词嵌入，再建循环网络，再建输出，最后在 `forward` 里做各种维度转换。

层本身没什么难度，几行代码的事。真正让人卡住的是中间那一堆形状：输入维度从 `sequence × batch` 出发，词向量一转，变成 `sequence_len × batch × 128` 这样的三维，一层一层往下倒。所以这里的重点不在「怎么写层」，而在「每一层的输入输出长什么样」。

后边其实就没啥了。模型搭完，再往下就是训练那些常规动作。

还有一点铺垫要记住：上一段数据处理已经统计出，语料里不重复的词一共 5703 个。这个数下面会反复出现——三层里有两层要用它。

### 把三层先搭出来

网络的类叫 `TextGenerator`，继承 `nn.Module`。第一个动作是初始化：`def __init__(self, unique_word_count)`。开头固定套路，`super().__init__()` 把父类的成员初始化掉，括号里什么都不用写。然后才是我们自己的三层。

#### 词嵌入层：5703 个词，每个 128 维

`unique_word_count` 是去重后的词的数量，也就是那 5703。爱钻牛角尖的同学会追问一句：既然它是去重词数，上一步统计完返回的时候为什么不直接叫 `unique_word_count`？这个随你——想统一就把上一步的命名一起改了，不改也不影响，只要自己清楚这个数指的是去重之后的词数就行。

`nn.Embedding` 收两个参数。第一个是语料中词的数量，5703：这 5703 个词，每个词都要转成对应的词向量。第二个是词向量的维度，回答的是「这个词要表示成几维」。转成 4 维行不行？行；5 维、6 维、更长都行。课程里给的是 128，不是 64。这个维度越大，词向量相对越精准，但计算量也跟着变大，是精度和开销之间的折中。

于是这一行就是 `self.ebd = nn.Embedding(unique_word_count, 128)`。

#### 循环网络层：128 进、256 藏、一层

循环网络层相对简单一点。三个参数：第一个是输入的维度，也就是词向量维度 128——RNN 收到的输入就是词向量，所以这个数必须和嵌入层的第二个参数一致；第二个是隐藏层维度 256，它管的是「记录多少信息」，值越大记住的越多；第三个是网络层数，我们写 1。

层数写 1 是什么效果？一层就只记最后一项信息。写 2 的话会再叠一层，记住最后两次、做一次深加工。这里一般给 1。

代码就是 `self.rnn = nn.RNN(128, 256, 1)`，和之前做小测试时的那套参数完全一样。

> **提示**：这里的「网络层数」指纵向堆叠的 RNN 层数，不是句子的长度，也不是时间步数。后面 `forward` 里出现的 `seq_len` 才是和时间有关的那一维。

#### 输出层：词表多大，输出就多宽

第三个是输出层，也是全连接层。两个参数：第一个是特征向量维度，必须和隐藏层维度一致，256；第二个是词表中词的个数，也就是 `unique_word_count`，5703。

输出为什么是 5703？因为我们要知道词表中每个词的概率，然后挑概率最大的那个当预测结果。前面那些值处理完，吐出来一个 5703 维的向量：这一维是「有」的概率，那一维是「直升机」的概率，别的位置还有别的词的概率……一整套看下来，谁的概率最大，谁就是下一个词。所以输出的宽度只能是词表大小。

写成 `self.out = nn.Linear(256, unique_word_count)`。

三层说完，初始化方法整体就是这样：

```python
def __init__(self, unique_word_count):
    super().__init__()
    # 词嵌入：5703 个词，每个词一个 128 维向量
    self.ebd = nn.Embedding(unique_word_count, 128)
    # 循环网络：输入 128 维，隐藏层 256 维，1 层
    self.rnn = nn.RNN(128, 256, 1)
    # 输出层：256 维特征映射到词表大小
    self.out = nn.Linear(256, unique_word_count)
```

### 前向传播：形状一路换着走

第二个动作是前向传播：`def forward(self, input, hidden)`。`input` 是输入的数据，也就是以前一直写的那个 X；`hidden` 是上一时刻的隐藏状态。这一趟数据从进来走到出去，形状要连着换几次，是最需要盯住的地方。

```text
input                (batch, seq_len)
   |
   |  Embedding(5703, 128)
   v
embed                (batch, seq_len, 128)
   |
   |  transpose(0, 1)
   v
embed                (seq_len, batch, 128)
   |
   |  RNN(128, 256, 1)   +  hidden (1, batch, 256)
   v
output               (seq_len, batch, 256)
   |
   |  reshape(-1, 256)
   v
output               (seq_len * batch, 256)
   |
   |  Linear(256, 5703)
   v
output               (seq_len * batch, 5703)
```

看这张图：最后一维从「词下标」变成 128，前两维对调了一次，接着 RNN 把最后一维从 128 变成 256，然后把三维压成二维，最后 256 变成 5703。整条链上变的是形状，数值一路往下传。

#### 先过嵌入层：词下标变词向量

`embed = self.ebd(input)`。这一步把每个词的下标换成它对应的 128 维词向量，形状从 `(batch, seq_len)` 变成 `(batch, seq_len, 128)`——句子还是那些句子，只是每个词的位置上换成了一个向量。

#### 交换维度，再交给 RNN

接下来这一步最容易漏：`embed = embed.transpose(0, 1)`。

为什么非换不可？`nn.RNN` 默认要的输入是 `(seq_len, batch, input_size)`：第一维是每个句子的词数，第二维是这一批有多少条句子。嵌入层给的却是 `(batch, seq_len, 128)`，两边正好反着。不换位直接喂进去，维度就对不上，后面全乱。

换的道理也很直白：隐藏状态的形状是 `(num_layers, batch, hidden_size)`，batch 在第二维；RNN 的输入也要把 batch 放在第二维，两边才能对齐。所以要把句子长度挪到最前面，把 batch 挪到第二位。

> **易错点**：`seq_len` 和 batch 别在嘴里说反。`seq_len` 是每个句子的词数，也就是句子长度；batch 是这一批句子的条数。进 RNN 时长度在前、条数在后，这跟嵌入层刚出来时正好相反。

换完是 `(seq_len, batch, 128)`，送进去：`output, hidden = self.rnn(embed, hidden)`。RNN 返回两样东西——`output` 是每个时间步的输出，形状 `(seq_len, batch, 256)`；`hidden` 是这一轮跑完的隐藏状态，形状 `(1, batch, 256)`，留给下一轮用。

#### 压成二维，全连接才吃得下

`self.out` 是 `nn.Linear`，它只能处理二维数据，而 `output` 现在是三维的。办法是把前面两维乘到一起去：`output.reshape(-1, output.shape[-1])`。

`reshape` 是重构形状的函数。第一个参数写 `-1`，意思是这一维交给 PyTorch 自动计算；第二个参数 `output.shape[-1]` 取最后一维，也就是 256。于是 `(seq_len, batch, 256)` 变成 `(seq_len × batch, 256)`：行数是「句子长度 × 批大小」，列数是 256。

为什么是「乘起来」？拿小例子体会一下：一共三个词，每个词 4 维，那一次送进去的就是 3 × 4 = 12 个数。现在是一批句子、每个句子若干个词、每个词 256 维，同样把前面几维摊平，让全连接一行一行地吃。

这一行也可以换个写法先转置一下，不过直接 `reshape` 一步到位，那一步就省了。

压平之后过输出层：`output = self.out(...)`，形状变成 `(seq_len × batch, 5703)`。每个位置一行，一行 5703 个数，就是这个位置上对词表每个词的打分。

#### 返回预测结果与隐藏状态

`return output, hidden`。`output` 是输出层的结果，也就是预测结果——每个位置对每个词的打分，取最大的那个就是预测出的下一个词；`hidden` 是隐藏状态，下一轮迭代接着用。

前向传播整体写出来：

```python
def forward(self, input, hidden):
    # 1. 词嵌入：词下标到 128 维词向量，(batch, seq_len, 128)
    embed = self.ebd(input)
    # 2. 前两维对调，换成 RNN 要的 (seq_len, batch, 128)
    embed = embed.transpose(0, 1)
    # 3. 过 RNN，拿每个时间步的输出和新的隐藏状态
    output, hidden = self.rnn(embed, hidden)
    # 4. 全连接只吃二维，压平成 (seq_len * batch, 256)
    output = self.out(output.reshape(-1, output.shape[-1]))
    # 5. 返回预测结果与隐藏状态
    return output, hidden
```

> **提示**：这块确实绕。真看不明白就每执行一步打印一次维度——嵌入层处理完打一次，`output` 打一次，`hidden` 打一次，形状对上号，中间那几步就通了。

也别在维度上死磕太久。RNN 这个案例的目的，是对文本这块做一个简单的入门；后面 NLP 还有 12 天要讲这一堆操作，光 RNN 的各种变形预计就要两天半到三天，大概落在 NLP 的第三到第六天。

### 隐藏状态：第一次进来得自己造一个

三个方法里还差一个。以往的网络就 `__init__` 加 `forward` 两个方法，这次多一样东西：第一次处理的时候，上一时刻的隐藏状态根本不存在，得先造一个出来。

所以定义一个初始化隐藏状态的方法：`def init_hidden(self, bs)`。`bs` 就是 batch size，也就是这一批有多少条句子（比如 32）。它要三个维度：网络层数、batch、隐藏层向量维度——层数是 1，batch 是 `bs`，隐藏层向量维度是 256。

256 哪来的？就是前面 `nn.RNN` 的第二个参数，自己写的那个；层数 1 也是自己写的。这个维度越大，记住的信息越多，和搭 RNN 时说的是同一件事。

返回全零张量：

```python
def init_hidden(self, bs):
    return torch.zeros(1, bs, 256)
```

为什么非得单独写个方法？`forward` 是前向传播，框架会自动调用它；`init_hidden` 不会，得手动调。

爱钻牛角尖的还会追两句。第一句：以前怎么没写过这个函数？因为以前不需要上一时刻的隐藏状态，没有历史要接。第二句：非得写成函数吗，不写行不行？行。将来训练的前一刻，把这几行代码拉过来直接用，照样能充当初始隐藏状态；只是代码结构上不合理——初始化就该待在搭建这一步里。所以还是定义成方法，拿模型对象直接调用。

### 搭完先验一眼：建对象、看参数、试打印

模型搭完，先建个对象看看：`model = TextGenerator(word_count)`，把前面统计出来的去重词数 5703 传进去。这次测试不看效果，模型还没训练，只看结构建对没有。

```python
model = TextGenerator(word_count)   # word_count = 5703

for name, param in model.named_parameters():
    print(name, param.shape)
```

`named_parameters()` 把模型里所有参数连名字一起给出来，`param.shape` 是参数的形状。打印出来大致是这么一串：

| 参数名 | 形状 | 对应的东西 |
| :--- | :--- | :--- |
| `ebd.weight` | `(5703, 128)` | 词嵌入表：5703 个词，每个 128 维 |
| `rnn.weight_ih_l0` | `(256, 128)` | 输入到隐藏层的权重 |
| `rnn.weight_hh_l0` | `(256, 256)` | 隐藏层到隐藏层的权重 |
| `rnn.bias_ih_l0` | `(256,)` | 输入那一路的偏置 |

还有个细节：要是在 `forward` 里加一句 `print` 打印 `embed.shape`，会发现根本打不出来。原因很简单——`forward` 是前向传播，只有模型真正被调用、训练跑起来的时候才执行，光建一个对象不会进这个函数。想看维度，就在里面写好打印语句，等模型跑起来自然就出来了。

模型搭到这儿就完整了。重点其实就一句：那几个参数别传错。层本身三行代码，传错一个数，模型照样能建出来，但结构已经不是你要的那个了。真正值得多花时间的是 `forward` 里那几次形状转换。

## 让 RNN 学会写歌词：模型训练与逐词生成
> 对应块：BLK43 | 覆盖分集：P107-P108 | 块标题（分集名）：《Day07-16.RNN_AI歌词生成器案例_模》

模型搭完了，权重还是一堆随机初始化出来的数。这时候你把"星星"喂进去，它回给你的 5703 个分数跟"星星"没有半点关系，纯属噪声——因为还没训练过。

所以下一步只有一件事：训练。而训练这件事拆开看，是一条相当固定的流水线：迭代数据、送进网络、算损失、反向传播、更新参数、保存模型。这套流程前面已经走过好几遍，骨架一模一样，这里不用重新发明，照着填就行。

不过在下第一行代码之前，有个问题得先答上来：这个任务算二分类，还是多分类？

> **结论**：多分类。

理由很直接。输出的不是"是/否"两个打分，而是 5703 个词各自的概率——词表里每一个词，都要预测一次"它接在这个位置的概率有多大"，最后挑最大的那个。类别数就是词表大小。既然是多分类，损失函数自然又落到那个老熟人身上：多分类交叉熵 `CrossEntropyLoss`。

优化器也没新东西，SGD、Adam 都行，这里用 Adam。

```text
encoded_text
    |
    v
LyricsDataset   -->  (x, y)    x: (5, 32)   y: (5, 32)
    |
    v
DataLoader      -->  batch_size=5, shuffle=True
    |
    v
TextGenerator(x, hidden)
    |
    v
output  (32, 5, 5703)
    |
    v
CrossEntropyLoss( reshape(output), transpose + reshape(y) )
    |
    v
loss -> backward -> step -> save
```

这张图从上到下就是一条流水线：歌词编号交给数据集切片，DataLoader 把样本凑成批，模型吐出 5703 维的打分，最后由交叉熵把打分的形状和标签的形状对齐，算出一个损失。整篇的难点基本都压在那条对齐线上。

### 训练函数里重新铺开的准备工作

先把 `main` 收拾干净。按讲义的设定，`train` 不带参数——原先散在 `main` 里的一句话一件事，现在全部收进函数内部重新做一遍。于是 `main` 里只剩一行：

```python
if __name__ == '__main__':
    train()
```

看着清爽，但代价是：这个函数里必须把前面所有准备工作重新走一遍，一件都不能少。闲话少说，直接开写。

#### 词典、数据集与模型

第一件事，构建词典：

```python
unique_word_count = build_word_count()
```

这个函数会把歌词文本读出来、清洗、切词、去重、编号，得到一个"词 → 索引"的字典。这里特意改了个名字：不叫 `word_count`，叫 `unique_word_count`。

为什么要加这个前缀？因为 `word_count` 到后面会有歧义——它到底是"每个词出现了多少次"，还是"去重之后的词表"？我们要的是后者，5703 个互不相同的词。加个 `unique` 把话说清楚，后面看代码的人（包括几天后的自己）不会误会。

> **易错点**：5703 不是随手写的常数，它是去重后的词表长度。模型最后要输出多少个类别，就必须和它严格相等，差一个都会在损失函数那里对不上。

第二件事，获取数据集：

```python
lyrics_dataset = LyricsDataset(encoded_text)
```

`encoded_text` 是整段歌词的张量形式——把文本里每一个词换成它在词表里的编号，整首歌就变成一串整数。`LyricsDataset` 架在这串编号上，按索引切滑动窗口：给一个 `index`，它返回一对 `x, y`，`x` 是连续的若干词，`y` 是整体往后挪一位的同样长度。

第三件事，初始化模型：

```python
model = TextGenerator(len(unique_word_count))
```

注意这里传的是词表大小，不是词表本身。模型拿它做什么？做最后一层全连接的输出维度——最终要给 5703 个词每个都打一个分，这一层的输出就必须正好是 5703 列。多一列少一列，后面交叉熵立刻报错。

#### DataLoader 的三个参数

```python
lyrics_dataloader = DataLoader(dataset=lyrics_dataset,
                               batch_size=5,
                               shuffle=True)
```

这三个参数是固定套路，但每个都得说清楚：

| 参数 | 传什么 | 含义 |
| :--- | :--- | :--- |
| `dataset` | `lyrics_dataset` | 数据集对象，负责按索引吐出 `x, y` |
| `batch_size` | `5` | 每批取几个样本，也就是每批 5 个句子 |
| `shuffle` | `True` | 每轮开始前随机打乱顺序 |

`batch_size` 是 5，数据集里的 `number_chars` 是 32，两个数一乘就是这一批数据的形状：5 个句子，每个句子 32 个词。所以一批 `x` 是 `(5, 32)`。

`number_chars` 到底指什么，不用背。按住 Ctrl 点进 `LyricsDataset` 的定义，看它的注释，写得很清楚：每个句子里词的个数。

为什么偏偏是 5 和 32？说实话没有硬性规定。但前期这两个值都别太大：数一大，能切出来的句子就少，迭代次数跟着少，模型练不透，效果反而不行。稳妥的做法是从小往大试，先让模型简单一点，跑通了再往上加，慢慢找到一个合适的。

要聊经验之谈，就一条：选 2 的幂，8、16、32、64。工程上大家习惯这么取。

> **提示**：忘了参数含义时别猜，点进源码看。`DataLoader` 的 `batch_size`、`LyricsDataset` 的 `number_chars`，注释都写在那儿，比凭记忆靠谱。

#### 损失函数与优化器

第五件、第六件，都是老代码：

```python
criterion = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(model.parameters(), lr=0.01)
```

`criterion` 就是"准则"，别拼错。

Adam 后面不用再传 `betas`，因为源码里的默认值就是 `(0.9, 0.999)`，点进去能看到。这两个数一个管梯度的一阶矩，一个管梯度平方的二阶矩——说白了一个决定往哪个方向走、走多快，一个决定步子该放多大。Adam 是同时从"梯度方向"和"学习率尺度"两个角度做自适应，这也是它比裸 SGD 省心的地方。

`model.parameters()` 不能漏。优化器得知道它该更新谁。

### 轮、批次与单步

结构上就三层，一层套一层。把整段训练代码的骨架先摆出来，再往里填肉：

```text
for epoch in range(epochs)              <- 第几轮
    start / iterator_num / total_loss   <- 每轮开头重置
    for x, y in lyrics_dataloader       <- 本轮的第几批
        hidden = model.init_hidden(5)
        output, hidden = model(x, hidden)
        y = y.transpose(0, 1).reshape(-1)
        loss = criterion(...)
        zero_grad / backward / step
        total_loss += loss.item()
        iterator_num += 1
    print(本轮信息)                      <- 每轮一次
save(model.state_dict())                <- 全部结束一次
```

读这张图的诀窍只有一个：看缩进。谁在谁里面，决定了它执行几次。

`epochs = 10`。轮数当然越多越好，但先来十轮看看效果，十轮差不多能看出个大概。

```python
epochs = 10

for epoch in range(epochs):
```

顺手提一句：如果循环变量在循环体里根本用不到，可以写成 `for _ in range(epochs):`。下划线是 Python 的约定，意思是"这个值我不关心"。这里后面要用 `epoch + 1` 打印轮数，所以保留名字。

#### 每轮开头要备好的三个变量

```python
    start = time.time()
    iterator_num = 0
    total_loss = 0.0
```

三个变量，三种用途：本轮开始时间、本轮已经跑过多少批、本轮累计的损失。

位置很关键——它们写在 `for epoch` 的**里面**，所以每一轮进来都会重新赋值。`epoch` 取 0 到 9，分别对应第 1 轮到第 10 轮，打印时加一才是人看的轮数。

`iterator_num` 直译是"迭代次数"，但更准确的说法是**这一轮训练了多少个批次**。实际开发里大家习惯都叫迭代次数，本质上是一回事。

> **提示**：这三个变量写在哪一层，决定了它们的生命周期。写在 `for epoch` 里面，每轮清零，算出来的是"本轮平均"；提到外面，全程累加，算出来的是"至今平均"。这两种口径的差别，后面讲 loss 震荡时还要专门用一次。

#### 一个批次的前向与反向

内层循环，逐行看：

```python
    for x, y in lyrics_dataloader:
        hidden = model.init_hidden(5)
        output, hidden = model(x, hidden)
        y = y.transpose(0, 1).reshape(-1)
        loss = criterion(output.reshape(-1, len(unique_word_count)), y)
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        total_loss += loss.item()
        iterator_num += 1
```

**先造记忆。** `hidden = model.init_hidden(5)`：每批数据进来，都得先给它一个初始的隐藏状态。为什么？因为网络里没有任何地方替你保存"上一批的记忆"——这一批是独立的 5 个句子，跟上一批没有先后关系，所以它们的起点必须是全零。

如果把这件事写死在训练代码里，大概是这个样子：

```python
hidden = torch.zeros(1, 5, 256)
```

第一个 1 是 RNN 的层数，中间的 5 是批大小，最后的 256 是记忆维度。能跑，但太死了：批大小一改这里要跟着改，记忆维度一改这里又要跟着改，而且这两个数跟数据、跟模型都没有任何关联，纯粹是抄过来的。所以更早的时候在模型里单独封装了一个 `init_hidden`，现在只需要告诉它这批有几个样本：

```python
hidden = model.init_hidden(5)
```

这个 `5` 就是 `batch_size`。记忆维度 256 由模型自己知道，不用在外面重复一遍。

> **提示**：这就是封装的意义——不只是少写几个字，而是把"谁知道什么"分清楚了。批大小属于训练数据，记忆维度属于模型结构，各管各的，思路才不会断。

**再前向。** `output, hidden = model(x, hidden)`：把输入和上一步的记忆一起送进去，拿回两样东西。`output` 是这一步每个位置对 5703 个词的打分，`hidden` 是更新后的记忆。注意这里是重新赋值 `hidden`，记忆就这么一步步往前传。

**然后对形状。** `y = y.transpose(0, 1).reshape(-1)` —— 这一行是整个训练代码里最容易写错的地方，得把形状摊开讲。

数据集给出来的 `y` 是 `(batch, seq_len)`，5 行 32 列，先批次后句子长度。而模型输出的 `output` 是 `(seq_len, batch, vocab_size)`，32 行 5 列，先句子长度后批次。两边的头一个维度刚好是反的。

```text
y        (batch=5, seq=32)
         |
         |  transpose(0, 1)
         v
         (seq=32, batch=5)
         |
         |  reshape(-1)
         v
         (160,)            <- 160 个位置的真实词编号

output   (seq=32, batch=5, vocab=5703)
         |
         |  reshape(-1, 5703)
         v
         (160, 5703)       <- 每个位置对 5703 个词的打分
```

交叉熵要的形式是"一行一个位置，每行 5703 个词的打分"，所以两边都要把前两维摊平成 160。第 $i$ 行的打分和第 $i$ 个真实编号，必须说的是同一个位置。

> **易错点**：`transpose` 这一步漏掉，代码照样能跑，损失照样能算出来，**不会报任何错**——因为 160 个数字的个数没变。但标签和位置全部错位了：模型学到的是"第 3 个句子的第 1 个词"配上"第 1 个句子的第 3 个词"，训出来的东西是乱的。形状对得上不等于语义对得上，这类错误最难查。

记一句话就够：**谁的批次在前，谁就要被换到后面去**。`y` 是批次在前，所以要转；`output` 天生批次在后，不用动。

**算损失。** `loss = criterion(...)` 一口气把 160 个位置的损失平均成一个数。

**最后三行固定动作。**

```python
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

清零梯度、反向传播求梯度、按梯度更新参数。`zero_grad()` 不能省——不清零的话，这一批算出来的梯度会累加到上一批残留的梯度上，等于把两批的更新方向混在一起，更新就乱了。

`total_loss += loss.item()`：累加本轮的损失。用 `.item()` 取成普通浮点数，不要直接把张量加进去，那样会把整条计算图一起留在内存里。

`iterator_num += 1`：批次数加一，等会儿求平均要用。

### 打印与保存：两个结束的分界

每轮结束打印一次：

```python
    print(f'第{epoch + 1}轮, 耗时{time.time() - start:.2f}s, '
          f'平均损失{total_loss / iterator_num:.4f}')
```

三项信息：第几轮（`epoch + 1`）、本轮耗时（`time.time() - start`，保留两位小数，后面跟个 `s`）、本轮平均损失（总损失除以批次数，保留四位）。

这一行的位置很有讲究。把上面那个内层 `for` 折叠起来，你会发现它跟内层 `for` 是**平级**的——它在外层 `for` 的里面、内层 `for` 的外面。所以它每轮执行一次，不是每批执行一次。

> **提示**：判断一段代码属于哪一层，不用靠猜。把上一层折叠掉，看它跟谁对齐就行。这个动作在长函数里特别有用，比数缩进快得多。

十轮全部跑完，保存模型：

```python
torch.save(model.state_dict(), './model/text_generator.pth')
```

它在最外层 `for` 的外面，所以整个训练结束才执行一次。

`state_dict()` 保存的是参数字典，**不含网络结构**。这一点很关键：它意味着测试的时候不能"打开文件就得到一个模型"，必须先用代码把同样的结构 new 出来，再把参数灌进去。文件名倒是随意，叫 `text_model.pth` 也行，叫 `text_generator.pth` 也行，这里选后者，跟类名对得上，好认。

### 报错栈怎么读

代码写完，右键运行。第一条报错长这样：

```text
AttributeError: module 'torch' has no attribute 'zero'
```

`torch` 里没有 `zero` 这个属性。

先说不要怎么做：看到报错就慌，或者干脆从第一行开始一行行往下检查到第 242 行。整个案例写下来两百四十来行，靠眼睛扫一遍，扫完也不知道错在哪，纯属浪费。

正确做法是顺着调用栈往回走。控制台里的异常信息，第一行点一下，它跳到最初发起调用的地方；再点第二行，跳到下一层；再点，就到真正出错的那一行；再点，就进 `torch` 自己的源码了。这条报错的路径是：

```text
train()
  |
  +--> hidden = model.init_hidden(5)
         |
         +--> torch.zero(...)      <-- 就是这里，少了 s
                |
                +--> torch 源码
```

看到 `torch.zero` 和 `torch.zeros` 的差别，问题就明白了：少写了一个 `s`。

> **提示**：报错栈本身就是一张调用关系地图。它告诉你"谁调了谁、最后死在哪"，顺着走比通读代码快一个数量级。而且问题只要能看明白，就已经解决一半——剩下的只是改那个字母。

改完再跑，一轮大概六秒，十轮一分钟左右。这个速度可以接受：句子虽然有九千多条，但批次数并不算多。

### loss 为什么在震荡

训练跑起来，把每轮的 loss 排开看，它不是一路往下掉，中间会往上弹一下。

第一反应通常是"哪里又写错了"。先别急，看看这个数是怎么算出来的：

```python
total_loss / iterator_num
```

这两个变量都定义在 `for epoch` 的**里面**，每轮开头被重置成 0。所以这个商只反映**本轮**的情况——第一轮的平均损失、第二轮的平均损失，各自独立。而 `shuffle=True` 又把每轮的批次顺序打乱了，每轮见到的组合本来就不一样，上下浮动是正常的。

想让它看起来平滑，最简单的办法是把这三个变量提到 `for epoch` 的外面：

```python
start = time.time()
iterator_num = 0
total_loss = 0.0

for epoch in range(epochs):
    ...
```

这样一来它们不再清零：`total_loss` 从头到尾一直累加，`iterator_num` 也一直累加，相除得到的是"训练至今所有轮、所有批次的平均损失"。这个数只会越来越平稳地往下走。

| 变量位置 | 生命周期 | 反映什么 | 曲线形态 |
| :--- | :--- | :--- | :--- |
| `for epoch` 内 | 每轮清零 | 本轮平均损失 | 上下震荡 |
| `for epoch` 外 | 全程累加 | 至今平均损失 | 平滑下降 |

> **结论**：震荡不是 bug，是口径问题。先确认自己算的是哪种平均，再判断"该不该降"。

真正影响收敛的是另外两个旋钮，下一节连着生成效果一起说。

### 预测：词到索引，再回到词

模型训练完，参数存进了 `text_generator.pth`。接下来要验证它到底学了什么：给一个起始词，让它一个词一个词往下接。

这里有个前提必须先想清楚——**模型不认识字，它只认识编号**。所以整条链路绕不开三步：

```text
"星星"
   |
   |  word_to_index["星星"]        <- 第一步：词找编号
   v
  89
   |
   |  model(torch.tensor([[89]]), hidden)
   v
output  (1, 1, 5703)
   |
   |  argmax                     <- 第二步：在 5703 个打分里取最大的位置
   v
  40
   |
   |  unique_words[40]            <- 第三步：编号找回词
   v
"的"
   |
   +---- 把 40 当成下一步的输入，回到最上面
```

第一步查词表拿编号，第二步送进模型预测下一个编号，第三步拿编号回词表取字。三步滚一轮，生成一个词；再滚一轮，再生成一个词。

#### evaluate 的准备动作

```python
def evaluate(start_word, sentence_length):
```

两个参数：从哪个词开始、要生成多长。调用的时候就一行：

```python
evaluate('星星', 50)
```

函数开头先把四件事备齐：

```python
    unique_word_count = build_word_count()
    unique_words = list(unique_word_count.keys())

    model = TextGenerator(len(unique_words))
    model.load_state_dict(torch.load('./model/text_generator.pth'))

    hidden = model.init_hidden(1)
```

词典要重新构建一遍——编号必须和训练时完全一致，否则第 89 号在训练时是"星星"，测试时变成了别的词，整个模型就白训了。

模型要先 new 再 load：`state_dict` 只有参数、没有结构；结构必须由代码重新声明，形状对得上，参数才有地方放。`init_hidden(1)` 里的 1 是批大小——一次只生成一句话，所以是 1。

#### 起始词必须先过词表

```python
    word_index = word_to_index[start_word]
```

这一行决定了起始词的身份：它必须是词表里已有的词。

如果你输入"憨哥""AI""夯"这类词，字典里查不到，直接抛 `KeyError`。这不是 bug，是设计使然：模型输出的是**词表内 5703 个词的概率分布**，它压根没有"词表外"这个概念，也没有哪一行能代表一个不存在的词。想让它以"AI"为题写歌，得先让"AI"进词表，那又是另一件事了。

反过来，一个字的起始词完全没问题，只要它在 5703 里面。

#### 逐词生成的循环

```python
    generate_sentence = [word_index]

    for i in range(sentence_length):
        output, hidden = model(torch.tensor([[word_index]]), hidden)
        word_index = torch.argmax(output).item()
        generate_sentence.append(word_index)
```

列表的第一个元素直接放起始词的编号，所以最后打印出来的第一句天然就是起始词开头，正好扣题。

循环体三行，逐个说。

`torch.tensor([[word_index]])`：模型要的输入是二维的 `(seq_len, batch)`。现在只有一个词、一个样本，所以是 `(1, 1)`——两层方括号，一个都不能少。少一层就变成一维，RNN 会把它当成"一个批次里有若干词"，行为完全不同。

`output, hidden = model(...)`：这里把 `hidden` 又传进去、又接回来，记忆在循环里一路传递。这一点跟训练时正好相反：

| 场景 | hidden 怎么处理 | 为什么 |
| :--- | :--- | :--- |
| 训练 | 每批重置为全零 | 一批是独立样本，与上一批没有先后关系 |
| 生成 | 一路往下传，不重置 | 一句话是连续过程，后面的词要用到前面的记忆 |

`torch.argmax(output).item()`：`output` 是这一步对 5703 个词的打分，`argmax` 返回分数最大的位置——也就是概率最大的那个词的编号。输出形状是 `(1, 1, 5703)`，前两维都是 1，所以展平后的下标正好等于词表下标。`.item()` 把张量取成 Python 整数，才能拿去查列表。

> **提示**：预测时不需要 softmax。训练用的交叉熵内部已经带了 log_softmax，所以模型最后一层直接吐原始打分。而 softmax 是单调的，取最大值和取 softmax 之后的最大值是同一个位置——只要"谁最大"，直接 `argmax` 就够。

每生成一个词，都要重新算一遍 5703 个打分。生成 50 个词，就是 50 次前向，一次都不能省。

#### 把索引还原成词

现在 `generate_sentence` 里躺着的是一串编号，比如 `103、33、21、66、55`。直接打印出来就是"念数字"——像有些演员不背台词，镜头前对着嘴型念一二三四五。得把它翻译回汉字：

```python
    for index in generate_sentence:
        print(unique_words[index], end='')
```

为什么用 `unique_words[index]` 而不是 `word_to_index`？因为那个字典的键是词、值是编号，它只能"给词找编号"，不能反着来——**字典没有按值找键这个动作**。而 `unique_words` 是按编号排好序的列表，第 89 个元素就是编号 89 对应的词，`unique_words[89]` 直接取。

`end=''` 表示打印完不加任何东西，不换行也不补空格。这样词与词才能首尾相接，把模型学到的标点和断句原样还原出来。要是每打一个就换一行，读起来是一列竖排的字，什么也看不出来。

### 复读机与调参

第一次跑，以"星星"开头，十轮训练、学习率 0.01，输出是这样的：

```text
星星的溪边河口默默的在等我 相思寄红豆 相思寄红豆无能为力
在人海中漂泊 心伤透 无尽无天涯尽头 满脸风霜落寞
近乡情怯的我 相思寄红豆无能为力
```

还挺押韵。但注意看，"相思寄红豆无能为力"重复出现了——这就是复读机的苗头。

换个起始词"分手"，问题更明显：

```text
分手的话就像语言暴力 我已无能为力 再提起 决定中断
首席娘子 她人在江南等我 所以你才要跟他分手
```

前半句还在题上，后半句已经跑到"娘子"去了，而且来回打转。到底是智能还是智障，就看这一下。

原因有两条，都是实打实的。

第一条，**每次喂给模型的句子太长了**。`number_chars` 给的是 32，一个样本就是 32 个词。句子越长，能切出来的句子越少，迭代次数跟着少，模型练得不够。把 32 改小，批次数立刻翻上去。

第二条，也是最关键的，**学习率太大**。`lr=0.01` 就是 $10^{-2}$，对 Adam 来说这是相当激进的步长——它的常用量级在 $10^{-3}$。步子太大，参数在最优点附近来回横跳，细的东西学不进去。

第三处顺带一起改：**轮数太少**。十轮只是"看一眼效果"的量级，真要有样子，得 50、100，甚至 1000 轮。

所以调参就三个地方：

```python
optimizer = torch.optim.Adam(model.parameters(), lr=0.001)   # 0.01 -> 0.001
epochs = 50                                                  # 10 -> 50
number_chars = 5                                             # 32 -> 5，可选
```

改完再跑：50 轮，一轮五秒，大概五分钟。以"分手"开头，结果是：

```text
分手的话就像语言暴力 我已无能为力 再提起 决定中断手机
然后在这里不限日期 然后将过去慢慢温习 让我爱上你
那场悲剧是你完美演出的一场戏
```

这就有点像歌词了——有断句、有转折、有收尾。再换回"星星"：

```text
一颗两颗三颗四颗连成线 背着背对背默默许下心愿
看远方的星是否听得见 手牵手
```

比十轮那次明显好，甚至有点像周董的味道。

> **注意**：仔细对比会发现，50 轮输出的**开头几句和十轮那次一模一样**。这不是巧合——起始词相同、解码方式又是每次取最大（贪心），只要模型对开头已经很有把握，前几个词必然复现。差异只会出现在模型"拿不准"的位置。所以看效果不能只读第一句，要往后读。

还想更好？那就把轮数堆到几千。代价是实打实的：50 轮五分钟，几千轮就是几个小时。训练这件事的"贵"，就贵在这儿。

最后演示一个必然会踩的坑：把起始词换成 `AI`，或者干脆来一个"夯"字，右键运行，立刻报错。因为 5703 个词里没有它们——词表里全是歌词中出现过的字词，一个没出现过的词，查表那一步就断了。

### 这套流程的形状

回头看，整个案例拢共四步：

1. 构建词汇表——把歌词里所有不重复的词捞出来，编号；
2. 构建数据对象——滑动窗口，每次挪一位，一批一批地吐 `x, y`；
3. 编写网络模型——最难的一步，难在各种维度转换：嵌入层多少维、RNN 多少维、输出多少列；
4. 训练与测试——套路和前几个案例一致，没有太多新东西。

真正让人卡住的永远是第三步。那些"这个参数干什么的""这个形状为什么反了"一旦想通，剩下的就是填空题。

这个案例也不是凭空编的。它是从一个真实项目里剥出来的，真实开发中这种活至少要两个月；后面还有大概十二天，会把其中每一步掰开揉碎，讲清楚为什么这么做。

日常用起来的姿势很简单：`train()` 跑一次，把这一行注释掉，以后每次只改起始词跑 `evaluate`。不然每换一个词就重训一遍，白等。

至于这个模型能走多远——它写出来的词，再找一个模型谱曲，一首歌就有了。要是运气好，朗朗上口，说不定真能改变点什么。广东有位歌手，据说当年在淘宝上花几百块买下一首歌，后来那首歌带给他的利润到了"一个小目标"。几百块在座谁都拿得出来，一个小目标就不一定了。

代码两百四十来行，一个能写词的模型，就这样跑起来了。
