## 把线性回归真正跑起来：训练、损失曲线与拟合线
> 对应块：BLK13 | 覆盖分集：P33-P34 | 块标题（分集名）：《Day03-04.PyTorch模拟线性回归_模》

前面那一小段代码只做了一件事——把 100 个样本点造出来，让 $x$ 和 $y$ 躺在手里。到了模型训练，代码量一下子多起来：数据集、数据集对象、数据加载器、模型、损失函数、优化器，一层套一层，最后再套一个两重循环。乍一看很杂，实际上它是以后会反复用到的一套固定骨架，值得在一开始就把形状记住。

### 训练代码的整体骨架

刚造完数据的时候，我们手里只有两个张量。要让它们真正喂进模型，中间还得经过封装：先把 $x$、$y$ 打包成数据集对象，再由数据集对象生成数据加载器，数据加载器才是训练循环真正伸手去取数据的地方。

整条链路是这样串起来的：

```text
原始数据 (x, y)
    │
    ▼
TensorDataset  →  数据集对象
    │
    ▼
DataLoader     →  按 batch_size 切批，shuffle 决定要不要打乱
    │
    ▼
训练循环（重复 100 轮）：取一批 → 预测 → 算损失 → 清零 → 反向传播 → 更新参数
    │
    ▼
loss_list（每轮一个平均损失）
    │
    ├──► 损失曲线
    └──► 散点图 + 拟合线
```

读这张图只要抓住一条：数据从左边进来，先被"切"（切批），再被"用"（训练），最后被"看"（画图）。切、用、看，就是整个过程。

链条里有两个名字从此固定下来，最好现在就直接背掉：`criterion` 是损失函数对象，`optimizer` 是优化器对象。以后不管是全连接网络、卷积网络还是循环网络，这两个变量名基本不会变，见到就该知道它是什么。

优化器这里先用 SGD，也就是我们之前学过的随机梯度下降。注意"先用"两个字——等到讲 ANN 的时候，这里会换，后面还有动量法、AdaGrad、RMSprop、Adam 一大串等着。那些都是对"怎么更新参数"这件事的不同做法，现在不必展开，用最朴素的 SGD 把流程跑通就够了。

学习率写的是 `lr=1e-2`。这是科学计数法，$1\times10^{-2}$，也就是 $0.01$。写成 `1e-3`、`1e-4` 同样是这个意思，分别是 $0.001$ 和 $0.0001$。看到 `e` 不要以为是自然常数，它就是"乘以 10 的几次方"。

### 轮、批与样本：先把数量账算清

代码里有一行 `epochs = 100`。这 100 指的是**训练 100 轮**。

这里有个说法上的讲究：最好不要张口就说"迭代 100 次"。为什么？因为一轮内部并不是只走一次——每一轮都要分批走好几趟。说"迭代 100 次"，会让人误以为参数只更新了 100 回，实际上远不止。

账很好算。我们一共造了 100 条样本，每批取 16 条：

```text
第 1 批   16 条
第 2 批   16 条
第 3 批   16 条
第 4 批   16 条
第 5 批   16 条
第 6 批   16 条
第 7 批    4 条
```

六个 16 是 96，最后剩下 4 条，凑成第 7 批。所以一轮是 7 批。

再往上一层：一轮 7 批，跑 100 轮，总共就是 $100 \times 7 = 700$ 个批次。每一个批次都会做一次完整的"预测—算损失—反向传播—更新参数"，也就是说参数被更新了 700 次，不是 100 次。

换个角度看更直观：100 条数据被翻来覆去用了 100 轮，相当于模型一共看过 $100 \times 100 = 10000$ 条样本。数据集没变大，是重复利用把它"撑"到了这个量级。

层级关系摆在一起是这样：

```text
100 轮（epoch）
└── 每轮 7 批（batch）
    └── 每批 16 条样本（最后一批 4 条）
        └── 预测 → 算损失 → 清零 → 反向传播 → 更新
```

正因为每轮只往 `loss_list` 里塞一个数，100 轮跑完，这个列表里就正好有 100 个值。一会儿把它画出来，会看到一条折线：前面掉得飞快，后面慢慢变缓。不可能是直线，也不可能是先慢后快——损失在训练初期下降最猛，这是后面画图时要重点看的现象。

另外两个变量是为"算平均"准备的：`total_loss` 记损失的总和，`total_samples` 记已经训练过的批次数，两者一除就是平均损失。

为什么要除？拿班里的例子说最清楚。假设班里现在有张三、李四两个人，想求平均年龄，把两人年龄一加除以 2 就完了。又来一个王五，把王五的年龄也加进去，除以 3；再来一个赵六，加进去，除以 4。人越来越多，分子在涨，分母也在涨，除出来的才是当下的平均值。

损失是同一个道理。每训练完一批，就把这批的损失累加进 `total_loss`，同时把计数加一；累加到最后再一除，得到的才是平均水平。分子分母同步增长，平均值才不会被"训练得越多、总和越大"这件事带偏。

循环里还有一个写法要认一下：`for _ in range(...)`。那个下划线不是特殊语法，它就是个变量名，和 `i` 一样，只是用来占位。它的潜台词是"这个值我后面不会用到"。如果你看不惯，写成 `for i in ...` 完全等价，一模一样，没有任何区别。

### 数据集、加载器、模型、损失与优化器

这五步是固定套路，顺序也别乱：

| 步骤 | 代码对象 | 关键参数 |
| :--- | :--- | :--- |
| 数据集 | `TensorDataset(x, y)` | 特征张量与标签张量 |
| 数据加载器 | `DataLoader(dataset, batch_size=16, shuffle=True)` | 数据集对象、批次大小、是否打乱 |
| 模型 | `nn.Linear(1, 1)` | 输入特征维度、输出维度 |
| 损失函数 | `nn.MSELoss()` | 默认按均值归约 |
| 优化器 | `optim.SGD(model.parameters(), lr=1e-2)` | 待优化参数、学习率 |

背下这张表，以后写任何一个网络的训练脚本，前五步都是照着填。等 ANN 讲完接 CNN、RNN，这套动作还是原样，一个字都不用改。

#### 数据集对象与数据加载器

第一步，把张量封装成数据集对象：

```python
dataset = TensorDataset(x, y)
```

第二步，用这个数据集对象去构造数据加载器：

```python
dataloader = DataLoader(dataset, batch_size=16, shuffle=True)
```

三个参数各管一件事：第一个是数据集对象，第二个是每批多少条，第三个是每轮要不要把数据打乱。

`batch_size=16` 不是规定死的，是自己挑的。改成 8 行不行？行。改成 1 行不行？也行，但每批只有一条，那就等于没分批，分批这件事本身就失去意义了。选 16 只是让"一轮分七批"这个账好算、也好看。

`shuffle=True` 值得多问一句：如果**不**打乱会怎样？

不打乱的话，每轮切出来的批次永远是同样的组合——前 16 条一批、接着 16 条一批，一百轮下来一模一样。模型每轮看到的都是同一副牌，顺序都不带变的，那这个"多轮训练"就没什么价值了。所以训练集要打乱。

打乱之后，每轮每批的成员都不同：第一轮第一批可能是 1、3、5、7 号样本，第二轮第一批可能就变成 2、4、6、8 号。数据组合一变，模型见到的情形就多，学出来的结果自然更准一些。

测试集则不打乱。道理很直白：测试集是用来做预测的，一条一条喂进去算输出，顺序对结果没有任何影响，打乱纯属多余动作。所以惯例就是训练集打乱、测试集不打乱。

#### 线性模型与那个叫 model 的变量

第三步，创建模型：

```python
model = nn.Linear(1, 1)
```

两个参数：第一个是输入的特征维度，第二个是输出的维度。这里 $x$ 是一个特征，$y$ 是一个标签，所以两边都是 1。

如果换成三个特征、一个标签，第一个参数就写 3。举个具体场景：要预测一个人的健康状况，得知道身高、体重、年龄，这三样就是三个特征，健康状况是那一个标签，模型就写成 `nn.Linear(3, 1)`。特征有几个，第一个参数就填几，这是硬对应关系。

这里还有个命名习惯要掰过来。在机器学习那部分，我们给线性回归的模型起名一直叫 `estimator`。到了深度学习，请改口叫 `model`。

不改行不行？技术上当然行，它就是个变量名。但很多代码、很多底层接口的参数名就叫 `model`，你一路用 `estimator`，读别人的代码、对别人的接口时就要在脑子里做一次翻译。与其这样，不如现在就统一，以后所有模型都叫 `model`。它和你以前的 `estimator` 是同一个东西，只是名字换了。

#### 平方损失与随机梯度下降

第四步，损失函数：

```python
criterion = nn.MSELoss()
```

`criterion` 是"标准、准则"的意思，在这里就是衡量预测离真实值有多远的尺子。这里用 MSE，平方损失。

第五步，优化器：

```python
optimizer = optim.SGD(model.parameters(), lr=1e-2)
```

第一个参数 `model.parameters()` 是模型里待调整的参数，也就是 $w$ 和 $b$；第二个是学习率。优化器拿到这两样，才知道"要动谁"和"每次动多大"。

到这一步，五个对象全部就位：数据有了、切批的方式有了、模型有了、尺子有了、更新规则也有了。剩下的就是让它们转起来。

### 训练过程：一轮里到底发生了什么

从第六步开始，写法和前面五步不一样了，要打起精神。前面都是"创建对象"，一句话一个；这里是把对象用起来，要写循环，还要决定每个循环里做哪几件事。

#### 定义变量与按轮循环

先把四个变量摆出来：

```python
epochs = 100
loss_list = []
total_loss = 0.0
total_samples = 0
```

四个变量各司其职：`epochs` 是训练轮数；`loss_list` 用来装每轮的平均损失，跑完就有 100 个值；`total_loss` 是这一轮里损失的累加；`total_samples` 是这一轮里已经训练过的批次数。

`total_loss` 特意写成 `0.0` 而不是 `0`，这是个细节：它一会儿要拿去做除法，用小数打底，除出来的结果才带小数位，不会在整数上被截断。

外层的轮循环：

```python
for epoch in range(epochs):
```

`range(100)` 给出的是 0 到 99，所以 `epoch` 的取值是 0、1、2……一直到 99，取不到 100。这一点在打印的时候要用到——想显示"第几轮"，得写 `epoch + 1`，不然第一轮会印成第 0 轮。

#### 从加载器取一批，先做预测

轮循环里面，紧接着是批循环：

```python
for train_x, train_y in dataloader:
    y_pred = model(train_x)
```

`dataloader` 是个可迭代对象，每一次迭代吐出一批数据，正好解包成 `train_x` 和 `train_y` 两部分。因为前面设了 `batch_size=16`，这里每次拿到的是 16 条特征和对应的 16 个标签；一轮迭代 7 次，7 次之后就跳出内层循环，说明这一轮训练完了，外层接着进下一轮。

这里有一点值得单独拎出来：有些参考代码会在这个位置写 `train_x.type(torch.float32)`，把数据转成 32 位浮点。这一行我不写。不是省事，是因为造数据集的时候已经转过一次了——上面转过的，下面就不必再转。反过来，如果前面的数据还是整型或者双精度，这里就必须补上这一行，否则模型拿到类型不对的输入会直接报错。**转换只做一次，做在数据源头**，这是省掉重复动作的正确位置。

数据进来，第一件事是预测：

```python
y_pred = model(train_x)
```

现在的处境是：特征 $x$ 有，真实标签 $y$ 也有，唯独缺模型的输出。把 `train_x` 丢进模型，模型拿当前的 $w$ 和 $b$ 算一遍，吐出来的就是预测值。这一步在以前叫 `y_pred`，现在还是叫 `y_pred`，命名不用改。

#### 算损失之前先把形状对齐

有了预测，就可以算损失：

```python
loss = criterion(y_pred, train_y.reshape(-1, 1))
```

`criterion` 要两个输入：预测值和真实值。预测值直接给 `y_pred`，真实值却得先 `reshape` 一下，这里不能省。

原因在形状上。预测时喂进去的 `train_x` 是"多行一列"，一批 16 条就是 16 行 1 列，模型吐出来的 `y_pred` 自然也是 16 行 1 列。可 `train_y` 是从最初那个一维的 $y$ 里切出来的，它是一条 16 个值的平铺序列，没有"列"的概念。一个 16 行 1 列，一个 16 个排成一行，两者对不上。

`.reshape(-1, 1)` 就是把后者掰成前者：`-1` 交给 PyTorch 自动算——能排多少行就排多少行；后面的 `1` 明确指定只有一列。一批 16 条，结果就是 16 行 1 列。

掰完之后两边形状一致，一个位置对一个位置，减法才有意义。整个数据集上也是同一个道理：原来 $y$ 是 1 行 100 列，转完变成 100 行 1 列，跟 100 行 1 列的 $x$ 一一对应。

> **提示**：如果不做这个 `reshape`，PyTorch 会把形状为 `(16,)` 的 `train_y` 当成 `(1, 16)` 去广播，与 `(16, 1)` 的预测值相减会得到一个 `16 × 16` 的矩阵——每个预测值都跟所有真实值比了一遍。损失照样能算出一个数，但这个数毫无意义。形状对不上时，先怀疑广播，再怀疑公式。

#### 累加总损失与批次数

损失算出来了，接下来两行是"记账"：

```python
total_loss += loss.item()
total_samples += 1
```

`loss` 是个张量，哪怕里面只有一个数，它也是张量。`.item()` 就是把这个单元素张量里的数值取出来，变成普通的 Python 浮点数，这样才能往 `total_loss` 上累加。

`total_samples += 1` 加的是"一批"，不是"一条"。一批 16 条样本，这里也只加 1。为什么可以这样？因为在训练循环里，数据从来不是一条一条进来的，`train_x` 一次就是 16 条。既然进来的是批，计数就该按批记。

那为什么除出来的还是平均损失？因为这里的 `loss` 本身已经是**这一批的平均损失**了。

这不是猜的，是 `nn.MSELoss` 底层定的。它的 `reduction` 参数默认取 `mean`，也就是"求平均"；SGD 拿到这 16 条样本，把 16 个损失加起来除以 16，才交给你这个 `loss`。所以 `loss.item()` 拿到的是批均值，`total_samples` 记的是批数，两者一除，得到的就是"批均值的平均"。

拿班里的例子再走一遍：把全班分成 7 个组，先要第一组 16 个人的平均年龄，再要第二组 16 个人的平均年龄，一组一组要下来，拿到 7 个组均值，把它们加起来除以 7，就近似是全班平均年龄。这里的第一组、第二组就是第一批、第二批，组均值就是 `loss.item()`，7 就是 `total_samples`。

> **提示**：最后一批只有 4 条样本，7 个批均值等权相加再除以 7，与"按样本数加权"的严格平均会差一点点。这个偏差很小，写训练脚本时通常不管它；知道它是近似就够了。

还有一处容易被人追问：这两个累加变量要不要每轮清零？写在轮循环外面，它们会一轮一轮往上加，除出来的是"从开始到现在所有批次"的平均；写在轮循环开头清零，除出来的才是这一轮自己的平均。两种写法画出来的曲线形状一致，前者更平滑一些。想严格得到"每轮的平均损失"，就在每轮开头把 `total_loss` 和 `total_samples` 归零。

#### 梯度清零、反向传播、参数更新

损失有了，重头戏在这三行：

```python
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

顺序不能乱，一步都不能少。

`optimizer.zero_grad()` 是梯度清零。为什么必须清？因为 PyTorch 的梯度是**累加**的：如果不清，这一批算出来的梯度会叠在上一批的梯度上，越叠越大，参数更新就完全跑偏了。至于"要不要先判断一下梯度是不是零"，不用，底层已经替你做掉了这个判断。

`loss.backward()` 是反向传播，从损失出发往回走，把每个参数的梯度算出来。此时梯度只是算好了、存着，参数本身还没动。

`optimizer.step()` 才是真正的更新：优化器按照刚算出的梯度和学习率，把 $w$ 和 $b$ 往前挪一小步。

> **提示**：`backward()` 要求起点是标量。这里 `loss` 本来就是单个数值，可以直接调；如果你自己写的损失最后是个向量，专业写法要先 `loss.sum()` 把它压成一个标量再反向传播，否则会报"grad can be implicitly created only for scalar outputs"。

#### 收尾：记录本轮平均损失

内层批循环结束，意味着一轮训练完毕。这时把这一轮的平均损失记下来：

```python
loss_list.append(total_loss / total_samples)
print(f"第 {epoch + 1} 轮，平均损失：{total_loss / total_samples}")
```

`total_loss` 里累加的是各批的均值，`total_samples` 记的是批数，两者一除就得到平均损失。把它塞进 `loss_list`，等 100 轮跑完，这个列表里就有 100 个数——正好是后面画损失曲线要用的全部数据。

打印时用 `epoch + 1`，因为 `epoch` 从 0 开始；用 f-string 把轮数和平均损失拼进一句话，训练过程中就能看到损失一路往下掉。

### 打印结果，和真实参数对一对

第七步不再是训练动作，而是把训练结果摊开来看。

先把 100 轮的平均损失打出来：

```python
print(f"100 轮的平均损失分别为：{loss_list}")
```

那 100 个数值就来自 `loss_list`——每轮末尾 append 一个，100 轮就是 100 个。跑起来会看到类似这样的开头：第一轮 957，第二轮 834，第三轮 748；到后面变成 13 几、12 几、11 几。数字一路往下，说明训练确实在起作用。

再把模型学到的参数打出来：

```python
print(f"权重：{model.weight}")
print(f"偏置：{model.bias}")
```

我们造数据时用的真实参数是 $w = 27.478$、$b = 14.5$。训练 100 轮之后得到的 `model.weight` 和 `model.bias`，跟这两个数已经非常接近，差距小得有点出乎意料。

差距为什么这么小？因为跑了 100 轮。要是跑 1000 轮，这个差距会更小。训练就是这么一件"反复磨"的事：轮数越多，参数越往真实值上贴。当然，代价是时间。

到这里，线性回归从数据到参数整条链路已经跑通了。但光看两个数字还不够直观——模型到底行不行，得画出来看。

### 损失曲线：为什么前面陡、后面平

第一张图画损失：

```python
plt.plot(range(epochs), loss_list)
plt.title("损失值曲线变化图")
plt.grid()
plt.show()
```

横轴是轮次，用 `range(epochs)` 生成 0 到 99 共 100 个点；纵轴是每轮的平均损失，直接给 `loss_list`。这两个东西长度都是 100，正好配对。

`title` 给图起个名字，`grid` 加上网格线方便读数，`show` 把图弹出来。

跑一下，看到的是一条下降的曲线：大概前 40 轮掉得很快，之后越来越平，最后几乎贴着横轴缓慢下滑。

为什么会是这个形状？因为训练前期梯度大，参数离正确值远，每一步迈出去都能带来明显的损失下降；越接近最优点，梯度越小，同样的学习率迈出的步子带来的改进就越有限。所以曲线必然是"先陡后缓"，不可能是匀速直线。

这条曲线的形状本身就在提示一件事：学习率不该从头到尾一个值。前期梯度大，学习率可以给大一点，让迭代次数少一些；后期梯度小了，学习率该跟着变小，否则容易在最优点附近来回晃。这叫学习率动态调整。现在做不到，因为 `lr=1e-2` 是写死的；等到第四天会专门讲怎么让学习率随训练进程变化。

### 散点图与两条直线

光有损失曲线还不够。损失降了，只说明模型在拟合训练数据，可它拟合得对不对、偏了多少，图上才看得出来。所以第二张图要把样本点和模型画出的直线放在一起。

#### 先看样本点落在哪

```python
plt.scatter(x, y)
plt.show()
```

`scatter` 画散点，把最初那 100 个样本的 $x$ 和 $y$ 丢进去，100 个点就铺在坐标平面上了。

这里有个容易忽略的细节：`plt.show()` 加不加，结果完全不同。

如果中间不写 `show`，那么前面画的损失曲线和这里画的散点会被画进**同一张图**——因为 matplotlib 默认往当前坐标轴上叠加，损失曲线的纵轴是损失值，散点的纵轴是 $y$，两套量纲糊在一起，什么都看不清。

如果在中间写了 `show`，损失曲线先弹出来显示完，再画散点就是新的一张图。所以跑完会看到两张独立的图：第一张是损失值变化，第二张是样本点分布。

#### 用训练出的参数算预测值

点有了，接下来该画拟合线。思路很直接：模型学到的是一组 $w$ 和 $b$，拿这组参数对每个 $x$ 算一遍 $wx+b$，得到的就是模型认为的 $y$；把 $(x, y_{\text{预测}})$ 连起来，就是拟合线。

```python
y_pred = torch.tensor([v * model.weight + model.bias for v in x])
```

`x` 是那 100 个样本点的特征，`for v in x` 把里面的值一个一个取出来，`v` 依次是第 1 个、第 2 个、第 3 个……每个 `v` 乘上训练出来的权重、加上训练出来的偏置，就得到一个预测值。外面套一层 `torch.tensor`，把这些散装的数重新收成张量，好跟 `x` 一起送进画图函数。

写成公式就是熟悉的 $y = wx + b$。唯一的变化是这里的 $w$、$b$ 不是我们造数据时设定的真值，而是模型自己学出来的。

#### 用真实参数算真实值

光有预测线，看不出偏了多少，还得有一条"标准答案"的线：

```python
y_true = torch.tensor([v * coef + bias for v in x])
```

结构完全一样，只是把训练出来的参数换成造数据时的原始参数：`coef` 是当初设定的权重 $27.478$，`bias` 是当初设定的偏置 $14.5$。

有人可能会问：$y$ 本来就在手里，直接拿 `y` 当真实值不行吗？行，但这里要的不是"数据里的标签"，而是"按真实公式算出来的一条直线"。只有把公式代进去，两条线才是同一套横坐标下的两条直线，才能一眼看出模型偏离了多少。直接撒 100 个点，是看不出这条线该往哪偏的。

#### 两条线合到一张图上

```python
plt.plot(x, y_pred, color="red", label="预测值")
plt.plot(x, y_true, color="green", label="真实值")
plt.legend()
plt.grid()
plt.show()
```

两条线的横坐标都是同一个 `x`，所以必然落在同一张图里。红色是模型预测，绿色是真实值——绿色换成蓝色也一样，只要两种颜色分得开。

`legend` 把 `label` 里写的名字显示成图例，`grid` 加网格，最后 `show` 展示。

画出来会看到什么？红色和绿色几乎贴在一起，但并不是完全重合，中间还能看出一丝缝隙。这个结果已经相当好了——100 轮训练能把两条线逼到这个程度，说明模型确实学到了东西。要是把轮数加到 500，两条线会继续往一起靠。

回到工作实际：如果去公司写代码，模型能调到这个程度，已经算挺 OK 了。

### 从 100 轮到 500 轮：最后是算力的事

100 轮已经让两条线几乎重合，500 轮只会更近。再往上加，收益会越来越小，但时间成本是实打实往上涨的。

这就绕回那句老话：人工智能等于数据加算法加算力。

数据决定模型的上限——数据本身没有规律、或者特征不够，模型再调也上不去；算法是我们刚才写的那一整套，模型结构、损失函数、优化器、训练流程，都属于算法；而算法要跑多少轮、每轮多少批、总共算多少次，最后拼的就是算力。同样一份代码，跑 100 轮和跑 500 轮，差别不在思路上，在机器上。

所以到后期，很多事情的瓶颈已经不是"会不会写"，而是"算不算得动"。这句话现在听着抽象，等模型大到一定程度，就会变得非常具体。

这套线性回归的代码，要不要背下来？不需要。

它存在的意义只回答一个问题：PyTorch 能不能做线性的事？能。从造数据、封装、切批、建模、算损失、反向传播到画图，整条链路都跑通了，说明这套工具链是通的。

但再往下想一步：我们平时用 PyTorch，做得更多的是线性回归这种事，还是分类这种事？显然是分类。而分类靠一条直线是分不开的，得有非线性的能力——于是就有了神经元，有了激活函数。这就是接下来要讲的内容。

### 先说几句题外话：深度学习是个黑盒

神经网络属于深度学习。机器学习也好，深度学习也罢，都是实现 AI 的一种途径或者说方式，这一点先厘清。但两者的脾气不一样。

机器学习，你越往深里学越会发现：只要数学好，公式都能推导出来。深度学习不是这样，它的可解释性要差一些。

举个例子，分层。假设六层比五层效果好，为什么？不一定——我自己跑出来五层比六层好，也是常有的事。可“六层就是比五层好”这种情况确实存在；至于原因，我们可能不知道。因为它在内部自动提取特征，那个“为什么”是试验出来的。

这也是它被叫作黑盒的原因。世界上确实有很少一部分人在研究怎么把深度学习的可解释性提上去，看能不能用数学、用公式解释得更好一点，但这部分人比较少；也可能现在已经有一定研究了，只是还没发表出来。所以公认的说法是：玩深度学习，可解释性会差一些。

说到底就一句话：深度学习在做的时候，核心就在于搭建神经元。

这一章学完，要做到五件事：知道什么是人工神经网络；知道常见的激活函数；了解常见的参数初始化方法；能够完成神经网络模型的搭建；知道网络模型参数的计算方法。

### 人工神经网络和它的生物原型

先把名字理清。人工神经网络，英文 `artificial neural network`，简称 `ANN`。里面的 `NN` 是 `neural network`——neural 是神经，network 是网络，合起来就是“神经网络”这四个字。以后说 NN，说的就是神经网络。

人工神经网络简称神经网络，它是一种模仿生物神经网络结构和功能的一种计算模型。人脑就可以看作一个生物神经网络，由众多神经元组成；那些一个一个的小圈，就可以当作神经元。

信号在生物神经元里怎么走？顺序是：树突接收输入信号，交给细胞核，细胞核处理之后通过轴突往下传，最后由轴突末梢输出。

```text
                  树突
            （接收输入信号）
              \    |    /
               \   |   /
             ┌──────────┐
             │  细胞核  │  ← 信号在这里累积
             └──────────┘
                   │
                   │ 轴突
                   ▼
              轴突末梢
            （输出信号）
```

读图的方向就是信号的流向：输入从树突进，经过细胞核，再从轴突末梢出去。

这里有个容易被忽略的细节：树突收到一个数据，不是转手就交给轴突。它先把信号给到细胞核，细胞核在这里等——你不断地往树突上送，它不断地接收、不断地往细胞核里攒；攒到一定的量，才交给轴突。轴突可以理解成大脑，由它做处理；处理完，把结果给轴突末梢，这才是输出。

### 攒够电位才发信号

当电信号通过树突进入细胞核，它不会来一个往后传一个，而是逐渐聚集电荷；当达到一定电位之后，细胞才被激活，轴突这时才发出电信号。说白了，不是来一个处理一个，是攒一批处理一下。

这个“阈值”不是凭空想出来的。早先有科学家拿小猫做过实验：给它看不同的图片、视频，或者放声音，看它受到外界刺激以后，神经信号到底是什么样的波动、什么样的阈值。放舒缓的音乐是一种反应，放恐怖的音乐、放老虎的叫声又是一种反应——受了惊吓、受了刺激，轴突的反应是不一样的。

这事放到人身上也看得见。人平静的时候，轴突的反应是平稳的，没有上头；可到了答辩那天，唱唱歌、玩一会儿，氛围一到，平时很内向的人也有点上头，讲解的时候状态都不一样。跟自己喝酒是一个道理：一个人闷头喝，二两就倒了；氛围到了，可能能干两斤——这当然夸张了，但超常发挥是有的。

再举个更日常的例子。有个成语叫火中取栗，没听过也没关系，换个场景：围炉烤火，手里一个核桃掉进火里了，你会不会下意识伸手去拿？成年人多半不会，掉里边就掉里边了，手不伸。小孩不一样，他对火没有什么感知，看见掉进去就伸手，一伸手就烫了手。

烫这一下发生了什么？火的温度传给体表，传给细胞核；细胞核收到信息，知道火把他的手烫疼了；大脑适应并记住这种信号。以后再见着火，同样的动作他就不做了。

同一条链路：不同的输入信号，经树突往下传给细胞核，细胞核来处理。神经网络一会儿要做的，跟这个过程非常像。

### 一个神经元，其实就是逻辑回归

神经网络的结构，和我们之前学过的逻辑回归一模一样。

回忆一下逻辑回归怎么玩：输入（输入层，也可以就理解为输入数据）交给线性模型，得到一个预测值；预测值再交给 `sigmoid`——这个叫激活函数——最后得到一个 0 到 1 之间的值，也就是概率。

神经网络就是把这条链路换了个说法：前面的不叫输入数据了，叫输入层；输入层的数据交给线性模型，去跑预测值；线性模型也好、`sigmoid` 也好，这一堆统统叫隐藏层；最后把结果做输出，叫输出层。

```text
输入层            隐藏层                        输出层
  │        ┌───────────────────────┐            │
  └───────►│ 线性模型 → 激活函数   │───────────►│
           └───────────────────────┘
```

有人会问：每层会不会只有一个人？不会。如果每层只有一个人，一层处理完交给下一层，那就又回到之前单模型的形态了。我们学过集成学习——多个弱学习器组合成一个强学习器；每一层都可以当作一个集成学习来看。

所以输入层的数据进来，后面是隐藏层一、隐藏层二、隐藏层三，每一层里都有多个小方块，每个小方块就叫神经元。一层可以有多个神经元，前一层的结果交给下一层，一层一层往下走，最后到输出层。这个流程，和当初讲逻辑回归时是一模一样的。

### 拆开一个神经元：加权求和与激活

先把图上的几个单词对上号：`input` 是输入层，`output` 是输出层，`activation function` 是激活函数，`artificial neuron` 是人工神经元。

输入层要竖着看，不是横着看。竖着排下来的 X1、X2、X3 一直到 Xn，这些叫特征。注意，这是一条样本的特征，不是多条样本。

什么场景？比如我要基于你的身高、体重、学历、专业、考试成绩、工作经验、性别，来预测你的就业薪资。左边这一堆是特征，右边的薪资是标签，它们属于同一个学生的同一条记录。把这条横着的信息竖过来，一个特征对应一个格子塞进输入层——所以输入层这里不是多条样本，就是一条。

> **结论**：样本有几个特征，输入层就有几个神经元，而且一一对应。如果还有第二条数据，就接着往这里传。

每个特征的重要性不一样，所以每个特征前面都要配一个权重：$w_1x_1$、$w_2x_2$……一直加到 $w_nx_n$，最后加上偏置 $b$。用求和号写就是

$$
\sum_{i=1}^{n} w_i x_i + b
$$

这不就是以前讲过的线性公式吗？$y = w^T x + b$，写简单点就是 $wx + b$，或者 $kx + b$，以前写代码就是这么写的。这个求和号做的事情，四个字：加权求和——把这条样本的各个特征，按照各自的权重整合到一起，算出一个预测值。

> **结论**：加权求和这一步是线性的。

光有线性不够，做分类要的是非线性结构。所以把加权求和的整体结果——注意是整体，那一整块原封不动地搬过去——扔进激活函数 $f$，由它做一个映射，输出一个非线性结果。映射到哪儿？拿 `sigmoid` 来说，就是映射到 0 到 1 之间，变成一个概率。

所以一个神经元就两段：左边加权求和，右边激活函数把结果映射成概率。这就是神经网络里神经元最简单的解释。

把这套流程再顺着生物神经元的说法讲一遍：不同来源的输入，都有各自的权重，先做加权计算，也就是 $wx + b$；算完输入到神经元（细胞）里再计算；最后通过激活函数输出。输出的这个值，就是可以拿来用的概率。

### 层与层之间的两条规矩

网络要立起来，靠两条规矩。

第一条：相邻层神经元相互连接。左边那层和右边那层叫相邻层，相邻层之间的神经元是连着的。

第二条：同层神经元之间相互隔离。同一层里，这个神经元想拿那个神经元的数据——拿不到。它只能往前一层拿。

所以数据流只有一个方向：上一层的输出，就是下一层的输入；上层所有神经元的输出结果，全部当作下一层每个神经元的输入数据。

每个神经元都要从前一层的每一个神经元上取数，这种结构叫全连接——`fully connected`。也有不是全连的，先有个印象。

```text
   前一层                     后一层
     ● ────────────────────── ●
     ● ────────────────────── ●
     ● ────────────────────── ●

   后层每个神经元都连到前层全部神经元；
   同层神经元之间没有横向连线。
```

一层为什么要放多个神经元？把一个层想成五个人。同一件事交给不同的人做，结果不一样；同一本书五个人来读，理解也不一样。

这五个人之间数据不共享——同层不连接，他们各自跑到前一层，把所有的特征数据都拉过来，各自做分析、各自出结果。一个人处理完直接给答案，要么 A 要么 B，效率不 OK；万一结果有偏差怎么办？多个人一起看，就是三个臭皮匠顶个诸葛亮。

还有一点容易看错：第二层是新的神经元，和第一层不是同一批。它要拿第一层的数据，但它不是第一层那几个人。层与层之间只有数据传递的关系，没有身份继承的关系。

输出层也一样，依旧和前一层的每个神经元建立连接、读取信息、做最后的分析。做二分类就简单了：一个神经元从里面筛“男”，另一个从里面筛“女”，最后就完成了男女二分类。

### 层数和每层神经元数量怎么定

隐藏层越多，理论上效率越低——这里说的效率是执行时长——但结果相对越精准，因为算得越多。每层的神经元越多，结果相对也越精准。

那是不是层越多越好、每层神经元越多越好？总有个上限，总有个设置。

经验规律是：前层的神经元可以多一些，后层的神经元可以少一些，也就是由多到少。当然不绝对。到了卷积那一块你会看到相反的情况：一层比一层多，多到一个极值，后面又一层比一层少。但正常实际开发做设定的时候，一般后层会比前层少一些。

连接不是白连的。相邻神经元相互连接之后，每条连接都要分配一个强度，这个强度就是权重系数 $w_1$、$w_2$。隐藏层在做的事，说到底就是拿特征做加权求和，把结果交给激活函数，由激活函数去预测概率到底是正还是反。

> **提示**：隐藏层不是只做加权求和。加权求和得到的是线性结果，要分类就得靠激活函数把它映射成非线性输出，所以每个隐藏层后面都要跟一个激活函数。

### 四个激活函数，以及怎么挑

加权求和好理解，不就是 $y = kx + b$ 吗。激活函数是干什么的？先把四个名字记下来：`sigmoid`、`tanh`、`ReLU`、`softmax`。

发音上有点分歧，先说清楚，省得以后听别人讲对不上号。`tanh` 有人念 /tæn/，也有人把后面的 h 念出来，念 /tæntʃ/。`ReLU` 有人念“re-loo”，也有人念“ray-lu”，跟 Linux 到底念“里纳克斯”还是“林尼克斯”一样，两种都有人用。自己去搜一下，一搜就出来了。

#### 先按任务类型挑

`softmax` 用在多分类。之前做多分类的时候，专门设过一个 `softmax` 参数，应该有印象；它就是把输出变成各个类别上的概率。所以输出层是多分类，首选 `softmax`。

输出层是二分类，首选 `sigmoid`。

隐藏层里，`ReLU` 用得最多，而且它不是只有一个，下面还分很多变体。隐藏层越往前，越可以考虑 `tanh`。`sigmoid` 呢？说得直接一点，它没有太大用，不到必要的时候一般不选它。

所以挑的顺序是：多分类用 `softmax`，二分类优先 `sigmoid`，隐藏层优先 `ReLU`，再往前靠 `tanh`。

#### 再按梯度大小挑

为什么 `ReLU` 用得最多、`tanh` 排在 `sigmoid` 前面？看梯度。

更新权重的公式是

$$
w_1 = w_0 - \eta \cdot \frac{\partial L}{\partial w}
$$

损失函数对权重的导数就是梯度，每一步用旧权重减去学习率乘梯度。

> **结论**：梯度越大，一次减掉的值越大，参数变化越快，达到同样的效果需要的迭代次数越少；梯度越小，步子越小，迭代次数越多。

三个函数的导数量级：`sigmoid` 求导之后最大是 0.25；`tanh` 求导之后最大近似 1；`ReLU` 在输入大于等于 0 的区间，导数恒为 1——注意它不是“近似 1”，是实打实的 1。

所以从迭代速度看，`ReLU` 最快，`tanh` 次之（近似 1），`sigmoid` 最慢（0.25）。这也印证了前面的顺序：隐藏层优先 `ReLU`，`sigmoid` 不到必要不选。

| 激活函数 | 常见位置 | 导数（梯度） | 选择倾向 |
| :--- | :--- | :--- | :--- |
| `sigmoid` | 二分类输出层 | 最大 0.25 | 不到必要不选 |
| `tanh` | 隐藏层，越靠前越优先 | 最大近似 1 | 次于 `ReLU` |
| `ReLU` | 隐藏层 | 正区间恒为 1 | 用得最多，变体多 |
| `softmax` | 多分类输出层 | 未展开 | 多分类首选 |

四个激活函数、各自该待的位置、梯度量级，拼在一起就是这一讲的结论。至于每个函数自己的思路、公式和曲线长什么样，是接下来要展开的事；先把这张表记住——遇到激活函数，先看任务类型，再看梯度。

## 神经网络的文字定义与 Sigmoid 激活函数
> 对应块：BLK15 | 覆盖分集：P36-P38 | 块标题（分集名）：《Day03-07.神经网络_文字介绍》

神经网络那张图，我们已经从头到尾过了一遍：圆圈是神经元，箭头是连接，一层一层往后推。图好懂，可它落不进代码里——真坐下来写一行，脑子里转的不是图，是几条干巴巴的结论：这一层跟上一层怎么连、一批数据该长成什么形状、一个神经元里到底存着几个数。这几条不钉死，后面写多少行都是照着图描，描歪了自己还不知道。所以先把文字这块补齐，再往深里走一步：激活函数到底补上了什么，Sigmoid 又为什么只能站在浅层。

### 从图解回到文字：三层结构与三条硬性特点

图上那套东西收起来，先摆正三个名词：输入层、隐藏层、输出层。名字好认，真正要抠的是下面三条特点，一条比一条容易被想歪。

**同一层的神经元之间没有连接。** 注意"同一层"这三个字——说的是这一层内部的多个神经元彼此不连，不是层与层之间不连。你把同一层的圆圈横着看过去，它们之间一根线都没有。

**第 N 层的每一个神经元，都和第 N-1 层的所有神经元相连。** 这条讲的是层与层之间：下一层里的每一个，都要接上一层的一整排。所谓"全连接"，全就全在这里——不是"有连接"，是"一个不漏地连"。

**全连接接收的样本数据都是二维的。** 这条最像废话，也最容易在代码里踩坑，值得单独摊开。

拿形状为 `(16, 3)` 的数据说：16 行 3 列。一行是一个样本，三列是这个样本的三个特征 $x_1$、$x_2$、$x_3$；它们分别配上 $w_1$、$w_2$、$w_3$，再加一个偏置 $b$，就是一次完整的加权求和——一个神经元吃一行，干的就是这件事。

那 16 行一起塞进去行不行？行，这才是正常用法。一次传 N 行就是一批数据，网络对这一批逐个算加权求和，再算损失、算均值，一轮下来就是一次批量更新。

但这个二维是硬门槛。你写个 `(2, 16, 3)`，也就是两个 16 行 3 列的矩阵叠成一个三维的东西，它接不住——三维的它处理不了。真碰上这种形状，只能把前两维拆开：先拿第一个 16 条当一批送进去，再拿第二个 16 条当第二批送进去。数据一点没错，错的是外面多套了一层壳。

> **易错点**：网络认的是"样本数 × 特征数"这张二维表，不是"批数 × 样本数 × 特征数"的三维块。批次是你在外面一批一批喂的，不是一次性塞进三维结构里让它自己拆。

再往下是结构上的咬合：第 N-1 层的输出，就是第 N 层的输入。这话听着像同义反复，落到数字上很具体——这一层输出 5 个数，下一层的输入维度就是 5；下一层再输出 5 个，再下一层的输入还是 5。上一层的出口，直接怼在下一层的入口上。

```text
(16, 3)  -->  (16, 5)  -->  (16, 5)
```

> 读图说明：一路往后走，行数（样本数）始终不变，变的是列数（特征数）；上一层的列数，就是下一层的输入维度。

每条连接上都有一个权重值，每个神经元另外还有自己的偏置 $b$。所谓"每个神经元都有自己的 W 和 B"，说的就是这些散落在连接和节点里的参数——它们才是训练时要动的东西。

顺便说个题外话：讲"每个神经元都得有自己的一份权重"的时候，我一激动差点把课上不该说的字带出来，只好用"阿西"顶上。"阿西"是个感叹词，是个好姑娘。

### 每个神经元在算四个量

前面把话说顺了口：每个神经元干两件事，先加权求和，再套激活函数。这话不算错，但只说了一半——说全了是四件。

为什么是四件？因为神经元不只在正向传播时工作。正向走过去，它要留下两个值；反向走回来，这两个值各自还要留下一个梯度。两个值、两个梯度，凑成四件。

```text
前向：x --> 加权求和 z --> 激活 a --> 损失
反向：损失 --> a 的梯度 --> z 的梯度 --> 更新 W、b
```

> 读图说明：同一条链，走过去算两个值，走回来算这两个值各自的梯度——四件事就是这两去两回。

具体是这四个：

1. 前向传播的加权求和，得到内部状态值；
2. 前向传播的激活函数，得到激活值；
3. 反向传播的激活值梯度；
4. 反向传播的内部状态值梯度。

前向那两个是往后传的：$z$ 是这一层对输入的线性汇总，$a$ 是加了非线性之后真正交给下一层的东西。反向那两个是往回算的：它们一路传回去，最终落到 $W$ 和 $b$ 的更新上。所以别把神经元记成"两个值"，要记成"一对值加一对梯度"，一一对应，缺一不可。

> **定义**：内部状态值就是加权求和的结果 $z = Wx + b$，$W$ 是权重矩阵，$x$ 是输入，$b$ 是偏置；激活值是把 $z$ 送进激活函数之后得到的 $a = f(z)$，作用是在这个位置上增加一个非线性因素。

一个神经元拆到底，就是这两步：加权求和、激活。没有第三个零件。

### 一句话把神经网络说清楚

那神经网络是什么？由神经元组成的网络，就叫神经网络。哪有那么复杂，想啥呢。

完整一点：神经网络是一种模仿生物神经网络的结构和功能的计算模型；它由神经元构成，而神经元由加权求和和激活函数构成。两层"构成"套在一起，就是它的全部定义。

结构上它固定分三段：

- **输入层**：对接特征。你有几个特征，它就开几个口；
- **隐藏层**：输入和输出之间的所有层都叫隐藏层，几层都行；
- **输出层**：把结果输出去。

三段的名字是死的，中间那段的数量是活的。后面说到"几层"，数的都是隐藏层——输入层和输出层不算。

### 激活函数只干一件事：注入非线性

激活函数的作用，一句话说完：给你的神经元注入非线性因素，这样神经元才能做分类问题。

为什么非要非线性？把所有激活函数都摘掉，剩下的动作只有加权求和：一层加权求和，把结果交给下一层再加权求和，再下一层还是加权求和。一路下来，这本质上就是一个大的线性回归模型，跑不出线性关系的圈。

把这条定义摊开说：激活函数用于对每层的输出数据进行变换，进而为整个网络注入非线性因素；因此神经网络可以拟合各种曲线。没有引入非线性因素的网络，等价于用了一个线性模型；通过给网络增加激活函数引入非线性，模型就可以逼近任意函数，提升它对复杂问题的拟合能力。

说白了还是那一句：激活函数是给网络注入非线性因素的。没有它，你的模型就是一个大线性模型。

你可能会说：你说是就是？我不信，你得有例子。行，那就把一个小网络摊开，一层一层代进去算。

### 两层网络展开后，还是一个线性式

摆一个最小的网络：两个输入 $x_1$、$x_2$，两个隐藏神经元 $c_1$、$c_2$，一个输出 $out$。全连接，故意一个激活函数都不加，就看它最后变成什么。

隐藏层两个神经元各算各的加权求和：

$$c_1 = w_{11}x_1 + w_{12}x_2 + b_1$$

$$c_2 = w_{21}x_1 + w_{22}x_2 + b_2$$

输出层再拿 $c_1$、$c_2$ 做一次加权求和：

$$out = v_1 c_1 + v_2 c_2 + b_3$$

到这里还是三个分开的式子。下一步是关键：把 $c_1$、$c_2$ 整个代进 $out$ 里。

$$out = v_1(w_{11}x_1 + w_{12}x_2 + b_1) + v_2(w_{21}x_1 + w_{22}x_2 + b_2) + b_3$$

展开，再按 $x_1$、$x_2$ 和常数项归拢——也就是把公因式提出来。含 $x_1$ 的是 $v_1w_{11}x_1$ 和 $v_2w_{21}x_1$，提出 $x_1$；含 $x_2$ 的同理；剩下的全是常数：

$$out = (v_1w_{11} + v_2w_{21})x_1 + (v_1w_{12} + v_2w_{22})x_2 + (v_1b_1 + v_2b_2 + b_3)$$

括号里那一坨，$v$、$w$、$b$ 都是训练时要定的参数，乘完加完就是一个确定的数。给它起个名：

$$K_1 = v_1w_{11} + v_2w_{21}, \quad K_2 = v_1w_{12} + v_2w_{22}, \quad C = v_1b_1 + v_2b_2 + b_3$$

整个式子就缩成了：

$$out = K_1 x_1 + K_2 x_2 + C$$

眼熟吗？这就是 $w_1x_1 + w_2x_2 + b$，换了身衣服而已，一个标准的线性公式。

回头看看这一路：哪一步出现过激活函数？一步都没有。

> **结论**：没有激活函数的时候，神经网络本质上就是一个大的线性模型。中间那两个隐藏神经元看着多了一层，实际只是把系数换了个算法，表达能力一点没多——层数只改变系数怎么算，不改变模型的形状。

### Sigmoid：把任意输入压进 0 到 1

第一个要拆的激活函数是 Sigmoid，最经典的那个。公式：

$$f(x) = \frac{1}{1 + e^{-x}}$$

式子里只有一个变量 $x$，它就是前面反复出现的加权求和。整个 Sigmoid 干的事，就是把这个加权求和的结果压进一个固定区间里。

先看它随 $x$ 怎么走。$x$ 越大，$-x$ 越小，$e^{-x}$ 跟着越小；分母 $1 + e^{-x}$ 越小，一个固定的 1 除以一个越小的正数，商就越大。所以 $x$ 越大，$f(x)$ 越大，整条曲线单调递增。

再看两头。$x$ 往正无穷走，$e^{-x}$ 趋近 0，分母趋近 1，$f(x)$ 趋近 1；$x$ 往负无穷走，$e^{-x}$ 涨到无穷大，分母无穷大，$f(x)$ 趋近 0。

所以它的值域是 $(0, 1)$：再大的输入也压不到 1 以上，再小的输入也压不到 0 以下，两头都只是无限逼近。

```text
   f(x)
    1 |                   ________
      |               ___/
  0.5 |           ___/
      |       ___/
    0 |______/
      +--------------------------
                  x
```

> 读图说明：左端贴着 0，右端贴着 1，中间在 $x=0$ 附近穿过 0.5，形状是一条关于点 $(0, 0.5)$ 对称的 S 曲线。

有效区间不在整条实轴上。-6 到 6 之间它才有明显变化；-3 到 3 之间变化最陡、效果最明显；出了 ±6，曲线基本贴死在 0 和 1 上。

贴死有个副作用：信息被压没了。输入 100 和输入 1 万，激活值都在 1 附近，差不出多少；求导以后更是都无限逼近 0，你根本看不出这两个数有什么区别。异常的大值就这样被抹平，模型容易忽略掉这种异常关系。

> **提示**：Sigmoid 的"饱和"不是故障，是它的形状决定的。输入绝对值一旦大过 6 左右，输出就进了平台区，增量信息基本丢失。

### 对 Sigmoid 求导：0.25 这个上限

接下来对它求导。除法求导的规则前面用过，这里直接用结果：

$$f'(x) = f(x)\bigl(1 - f(x)\bigr)$$

这个式子有个好处：算导数不用重新碰 $e^{-x}$，拿函数值自己就能算出来。

现在问一个更具体的问题：这个导数最大能到多少？也就是这条曲线最陡的地方有多陡。

令 $A = f(x)$，导数式就变成 $A(1 - A)$，展开是 $A - A^2$。这是关于 $A$ 的二次函数，开口向下，求极值：

$$\frac{d}{dA}\left(A - A^2\right) = 1 - 2A = 0 \quad \Longrightarrow \quad A = 0.5$$

把 $A = 0.5$ 代回去：$0.5 \times (1 - 0.5) = 0.5 \times 0.5 = 0.25$。

所以 Sigmoid 的导数最大就是 0.25，取到它的位置是 $f(x) = 0.5$，也就是 $x = 0$。整条导数曲线是一口钟：中间顶到 0.25，两边往 0 掉。

```text
   f'(x)
 0.25 |            /\
      |          /    \
      |        /        \
      |      /            \
    0 |____/________________\___
      +--------------------------
                  x
```

> 读图说明：导数在 $x=0$ 处顶到 0.25 的上限，往两边迅速衰减，$|x|$ 超过 6 之后基本贴在 0 上。

导数范围是 $(0, 0.25]$。记这个数不是为了考试，是为了下一节算一笔账。

### 五层之内梯度就消失了

导数小，为什么是件大事？看权重更新公式：

$$w_{\text{新}} = w_{\text{旧}} - \eta \cdot \frac{\partial L}{\partial w}$$

$\eta$ 是学习率，$\frac{\partial L}{\partial w}$ 是损失函数对这个权重的导数，也就是梯度。

梯度一旦约等于 0，后面那一项就没了：$w_{\text{新}} = w_{\text{旧}} - \eta \times 0 = w_{\text{旧}}$。学习率设多大都没用，乘 0 还是 0，权重一步都不动。

而 Sigmoid 的梯度，偏偏就爱往 0 跑。梯度是损失对权重的导数，按链式法则一层一层乘出来，每经过一层都要乘上那一层激活函数的导数。Sigmoid 那一项一旦贴近 0，整条乘积就被压到 0 附近。单层还好，多层一叠就出事，就按最理想的 0.25 算：

$$0.25 \times 0.25 = 0.0625 \qquad (\text{两层})$$

$$0.0625 \times 0.0625 = 0.00390625 \qquad (\text{四层})$$

$$0.00390625 \times 0.25 = 0.0009765625 \qquad (\text{五层})$$

五层乘下来，$0.00098$ 左右，也就是万分之九点八，往下就按"万分之九"这个量级去感受。

万分之九是什么概念？可以理解成：给你九块钱，让你活一万天。人这一辈子也就三万多天，按四万天算——一万天花九块，那这辈子赚够三十六块就衣食无忧了。不开玩笑嘛，三十六块钱，现在去搬会儿砖也就有了。

回到更新公式。原来的权重是 10，学习率 0.01，梯度 0.0009，减掉的是 $0.01 \times 0.0009 = 0.000009$。10 减这么一点，还是 10；下一次从 9.999999 变成 9.999998，再下一次再少一丁点。对损失来说，这跟没动有什么区别？

这就是梯度消失。不是梯度算错了，是它一层层乘下来，小到已经推不动参数。

> **结论**：Sigmoid 的网络大概五层之内就会碰上梯度消失，超过五层基本训不动。所以它一般只用于浅层网络，不超过五层。

> **提示**：这里说的五层，是按隐藏层数的——两个隐藏层就是两层。另外，每层的激活函数可以各用各的，这一层 Sigmoid、下一层 ReLU 都没问题；只是为了研究 Sigmoid，才让整条链都用它。

### 不以零为中心，所以只在输出层用

除了梯度消失，Sigmoid 还有一个特点：它不是以零为中心的。

输出全落在 $(0, 1)$ 里，中心在 0.5，不是 0。以 0.5 为界，往上那些输出偏正，往下那些偏负；整条曲线关于点 $(0, 0.5)$ 对称，不是关于原点。也就是说，后一层拿到的输入永远是一堆正数，不会正负相间。这也是它在实践中用得很少的一个原因。

但它有一个位置几乎不可替代：输出层。二分类要的就是一个 0 到 1 之间的概率，Sigmoid 正好干这个。多分类呢？用 Softmax。

> **结论**：二分类的输出层用 Sigmoid，多分类的输出层用 Softmax。这是它俩的应用场景。

### 隐藏层怎么选：从 ReLU 往下排

输出层定死了，中间的隐藏层呢？优先级是这样：

1. ReLU；
2. LeakyReLU；
3. PReLU 或 RReLU；
4. tanh；
5. Sigmoid。

ReLU 优先；搞不定，上 LeakyReLU；还搞不定，PReLU 或者 RReLU；再往下 tanh；最后才轮到 Sigmoid。

有人会问：万一前面几个都搞不定，就 Sigmoid 能搞定呢？一般来讲不存在这事。真到那一步，问题多半不在激活函数上。

这几个激活函数的公式和图像，后面一个一个讲。先把 Sigmoid 的账收一下——这一节要记住的就四个数：

| 记忆点 | 数值 |
| :--- | :--- |
| 输出映射区间 | 0 ~ 1 |
| 中心点 | 0.5，大于 0.5 偏正，小于 0.5 偏负 |
| 有效区间 | -6 ~ 6，其中 -3 ~ 3 效果明显 |
| 导数范围 | 0 ~ 0.25 |

公式、图像、导数、该待的位置，齐了。接下来就该把它写进代码里。

## 激活函数的下半场：Tanh、ReLU、Softmax 与选型规则
> 对应块：BLK16 | 覆盖分集：P39-P41 | 块标题（分集名）：《Day03-10.Tanh激活函数介绍》

### 先把 Sigmoid 的账对一遍

Sigmoid 讲完，别急着翻页。它那几条结论是这一讲的参照系，我重新摆一遍，你们对着回忆：

- 输入大致落在 $-6$ 到 $6$ 之间才有反应，变化真正明显的是 $-3$ 到 $3$；
- 它把任意实数压到 $0$ 到 $1$；
- 求导之后，导数值落在 $0$ 到 $0.25$。

最后这条最要命。$0.25$ 是 Sigmoid 能给出的最大斜率，也就是说它在最陡的地方，梯度也只有四分之一。反向传播一层层乘下去，几层之后就小得没法看了。

还有一个更隐蔽的问题：值域是 $0$ 到 $1$，全是正数。一个负得很厉害的加权和输进去，出来是 $0.00$ 几，仍然是正的。正负这件事在输出端被抹平了，网络只知道"有多大"，不知道"朝哪边"。所谓 Sigmoid 没有考虑负样本，说的就是这个意思。

Tanh 就是冲着这个缺口来的。

### Tanh 的公式与它的上下界

$$\tanh(x) = \frac{e^{x} - e^{-x}}{e^{x} + e^{-x}} = \frac{1 - e^{-2x}}{1 + e^{-2x}}$$

两种写法等价，后一种推极限更顺手，因为指数只剩一项，符号也干净。

式子里的 $x$ 还是老熟人——上一层加权求和的结果。它可正可负、可大可小，所以真正要问的是：$x$ 往两端跑的时候，这个式子会停在哪里。

先让 $x$ 越来越大。$e^{-2x}$ 会迅速往 $0$ 掉，分子变成 $1-0=1$，分母也是 $1+0=1$，一比一，得 $1$。$x$ 越大，输出越贴近 $1$。

再让 $x$ 越来越小，也就是负得越来越狠。这时候 $e^{-2x}$ 反过来暴涨，前面那个 $1$ 跟它比只是零头，可以直接不看：分子剩下 $-e^{-2x}$，分母剩下 $e^{-2x}$，约掉，得 $-1$。

两头一夹，值域就定死了：$-1$ 到 $1$。

> **结论**：Tanh 把任意实数映射到 $(-1, 1)$，以 $0$ 为中心，输入为正输出为正，输入为负输出为负。负样本第一次在激活函数的输出里有了位置。

对称中心这个细节值得单独拎出来。Sigmoid 的对称中心在 $0.5$，输出绕着 $0.5$ 上下分布；Tanh 的中心在 $0$，正负各占一半。零中心的输出对下一层更友好，这一点后面还会用到。

从曲线上看，它并不是全区间都灵敏。大概 $-3$ 到 $3$ 之间还有明显反应，再往外就贴住 $\pm 1$；真正变化快的是 $-1$ 到 $1$ 这一段。超过 $\pm 3$ 之后，曲线几乎是平的。

### 导数为什么落在 0 到 1

说它的导数在 $0$ 到 $1$ 之间，不能红口白牙一碰就完事，得把证据摆出来。

$$\frac{d}{dx}\tanh(x) = 1 - \tanh^{2}(x)$$

推导过程记不住没关系，结论要记牢：Tanh 的导数等于 $1$ 减去它自己的平方。

要找这个式子的最大值，把 $\tanh x$ 记成 $A$，式子就成了 $1 - A^{2}$。对 $A$ 求导得 $-2A$，令它等于 $0$，只有 $A=0$ 一个解，也就是 $\tanh x = 0$。代回去：$1 - 0^{2} = 1$。

所以导数最大能到 $1$，出现在 $x=0$ 那一点。而 $A^{2}$ 永远非负，$1-A^{2}$ 就不会超过 $1$；只要 $x$ 有限，它又大于 $0$。导数的范围就是 $(0, 1]$，习惯上写成 $0$ 到 $1$。

> **易错点**：别把"导数最大是 1"理解成"导数恒等于 1"。它只在原点取到 $1$，往两边迅速往下掉，$|x|>3$ 之后基本就是 $0$ 了。

这个"两侧趋零"也正是 Tanh 的软肋：两头都平，梯度就没了，深层网络照样会梯度消失。它比 Sigmoid 强，但没有跳出这个坑。

### 它比 Sigmoid 快，但比较要取极值

把两家的导数上限摆在一起：Sigmoid 是 $0.25$，Tanh 是 $1$。

参数更新的公式还是那条：

$$w \leftarrow w - \eta \cdot \frac{\partial L}{\partial w}$$

梯度是乘在学习率后面的那一项。它是 $1$，这一步就迈得大；它是 $0.25$，同样的学习率下只迈四分之一步。步子大，走到终点需要的步数就少——收敛更快、迭代次数更少，Tanh 相对 Sigmoid 的优势全部来自这里。

不理解就换个场景：楼下一万颗鸡蛋要搬到教室，一次搬两个和一次搬十个，哪个跑的次数少？当然是一次十个。梯度就是你"一次能搬几个"。

> **结论**：在各自的最佳状态下，Tanh 的梯度上限是 Sigmoid 的四倍，收敛更快，迭代次数更少。

但这个比较有个前提必须说清楚：要拿各自的极值比，不能随手挑一个点。

举个反例。假如某个任务里，Tanh 的梯度长期稳定在 $0.1$，而 Sigmoid 稳定在 $0.25$，谁的效率高？这时候反而是 Sigmoid。所以"Tanh 一定比 Sigmoid 快"是句错话，正确说法是"Tanh 的梯度上限更高"。比较激活函数要看导数曲线的高点，而不是随便取一个横坐标。

### 接进脚本，并把结论落成文字

原理讲完，落到代码上反而没什么工作量：函数图和导数图，前面画 Sigmoid 的脚本改两处就能用。

| 位置 | 原来 | 改成 |
| :--- | :--- | :--- |
| 类名 | `Sigmoid` | `Tanh` |
| 调用 | `sigmoid(...)` | `tanh(...)` |

大小写要分清：类名按 Python 的规矩首字母大写，写成 `Tanh`；真正调用的时候用小写 `tanh`，那是库里的函数名。两处都得改，只改一处跑不起来。

运行之后画出来的两张图——左边函数、右边导数——应该和前面推出来的结论完全一致：左边值域是 $-1$ 到 $1$，右边值域是 $0$ 到 $1$。

顺手把这一段的分析写成文字，以后复习看一张表就够了。

| 项目 | Sigmoid | Tanh |
| :--- | :--- | :--- |
| 值域 | 0~1 | -1~1 |
| 对称中心 | 0.5 | 0 |
| 有效区间 | -6~6（-3~3 明显） | -3~3（-1~1 明显） |
| 导数范围 | 0~0.25 | 0~1 |
| 收敛速度 | 慢 | 快 |
| 主要用途 | 浅层、输出层 | 隐藏层（浅层） |

Tanh 用在隐藏层，而且只建议用在浅层——不超过五层的网络。再深，两侧导数趋零的问题会一层层累积，照样训不动。至于输出层，Tanh 不接手，那还是 Sigmoid 的活。

### ReLU：一个 max 就完事

ReLU 的公式简单到没什么可讲的：

$$\mathrm{ReLU}(x) = \max(0, x)$$

一句话翻译：负数一律变 $0$，正数原样保留。图像是左边贴着横轴的一条线，右边是 $y=x$ 这条斜线，中间在原点拐个弯。

这就带来一个立场问题：它只认正样本，更加重视正信号，负信号直接忽略。负的加权和进来，输出是 $0$，这部分信息全丢。默认情况下 ReLU 就是这么干的。

> **提示**：ReLU 默认只保留正半轴，负半轴一律压成 $0$；如果确实需要保留负区间的信息，要用它的几个变体，后面再说。

导数更简单：负区间是常数 $0$，导数为 $0$；正区间是 $y=x$，导数为 $1$。所以 ReLU 的导数只有两个取值——$0$ 或 $1$，不存在 $0.5$、$0.7$、$0.8$ 这种中间值。

> **提示**：$x=0$ 这个拐点上导数不存在，工程实现里统一按 $0$ 处理。它只影响一个点，对训练没有实际影响。

为什么它永远是 $1$？正区间里 $\max$ 取到的就是 $x$ 本身，斜率天然是 $1$；负区间取到的是常数 $0$，斜率天然是 $0$。它压根走不到"介于 $0$ 和 $1$ 之间"那种状态。

拿它跟 Tanh 比，差距就在这儿：Tanh 的导数上限是 $1$，但实际训练中大量点落在 $0.2$、$0.3$、$0.4$ 上；ReLU 在正区间是实打实的 $1$，一步是一步。所以 ReLU 的收敛速度比 Tanh 还快，这也是它现在用得最多的原因。

还有一层是计算量。Sigmoid 每算一次都要 $1/(1+e^{-x})$，指数、除法都得上；ReLU 只做一次比较。两边根本不是一个量级的运算，训练效率的差距就这么来的。

### 梯度不衰减的另一面：神经元死亡

ReLU 最漂亮的地方，是它在正区间没有饱和。$x$ 再大，斜率还是 $1$，梯度不衰减。

这件事在深层网络里是救命的。Sigmoid 的梯度上限 $0.25$，五层传下来是 $0.25^{5}$，小到可以忽略；ReLU 的 $1$ 无论乘多少次方还是 $1$，十层、一百层都不变形。梯度消失在这里被按住了。

但同一个设计，翻过来就是它的死穴。

训练往前推进，权重在变，输入分布也在变，总会有一部分输入落进负半轴。落进去的神经元梯度是 $0$；梯度是 $0$，代进更新公式 $w \leftarrow w - \eta \cdot 0$，权重原地不动，而且永远不动。

权重不更新，这个神经元的输出就固定成 $0$，之后无论喂什么都是 $0$。它等于从网络里被摘掉了。这个现象有专门的名字：神经元死亡，英文叫 dead ReLU。

> **结论**：ReLU 用"负区间梯度为零"换来了稀疏和高效，代价是一旦神经元长期落在负区间，就再也活不过来。

稀疏这件事本身还有好处。一部分神经元输出为 $0$，等于在做特征筛选：本来 $20$ 列特征参与，筛着筛着只剩 $7$ 列。特征少了，模型跟着变简单，参数之间的相互依存关系也被削弱，过拟合的压力就小一些。

所以 ReLU 相对 Sigmoid 的优势可以归成三条：计算量小很多；正区间梯度不衰减，撑得起深层网络；输出稀疏，顺带缓解过拟合。

### 给负样本留一条缝的变体

ReLU 唯一的硬伤是负区间直接归零，那就在负区间留一条小缝。

$$\mathrm{LeakyReLU}(x) = \begin{cases} x, & x > 0 \\ 0.01x, & x \le 0 \end{cases}$$

负的时候不再给 $0$，而是给 $0.01x$——把原来的值缩小一百倍。它无限接近 $0$，但没有变成 $0$，梯度也就不是 $0$，神经元不会被判死刑。

这个 $0.01$ 很像正则化里的那套思路。ReLU 像 L1：不听话的权重直接砍成 $0$，不要了。Leaky ReLU 像 L2：给一个系数，把值压得很小很小，但值还在。一个是删除，一个是削弱。

$0.01$ 是 ReLU 的作者定的，不是我们必须遵守的常数。它和学习率的常用区间（$0.01$ 到 $0.001$）是同一个量级，按这个量级给系数，效率通常比较合适。

想自己定这个系数，就用 PReLU：负区间的斜率当成参数，你给多少就是多少，$0.0001$ 也行，$0.02$ 也行。想让它每次随机取，就用 RReLU。

那问题来了：既然 Leaky ReLU、PReLU、RReLU 干的是同一件事，为什么名字要起这么多？

因为深度学习不是一家公司做的。多家机构、多个团队各做各的，各自给自己的方法起名，凑到一起就成了一词多义。损失函数就是现成的例子：loss、cost function、代价函数、成本函数，说的是同一个东西，只是叫法不同。

这就像你从小到大换过好几个外号，小学一个、初中一个、高中一个，你也不会专门跑去告诉同桌"我以前叫这个"。

实际用的时候不用纠结：要么 ReLU（不考虑负样本），要么 Leaky ReLU（默认 $0.01$），要自己指定斜率就用 PReLU。

### Softmax：Sigmoid 在多分类上的推广

Softmax 处理的是多分类。它不是横空出世的新东西——把它理解成 Sigmoid 在多分类上的推广，最省事。

拿 if-else 打比方。Sigmoid 就是二选一的 if-else：是，或者不是。三选一、四选一、五选一，if-else 当然也能写，但得一层层嵌套。Softmax 干的事就是把这个嵌套摊平，一次给出每个类别的概率。

比如要判断一个样本属于 A、B、C、D 四类中的哪一类，它给出的结果可能是这样：

| 类别 | A | B | C | D |
| :--- | :--- | :--- | :--- | :--- |
| 概率 | 0.1 | 0.3 | 0.5 | 0.1 |

四个概率加起来正好是 $1$。这就是 Softmax 的核心约束——所有类别的概率必须凑成 $1$，这也是"概率"这个说法能成立的前提。

分给谁？分给概率最大的那个。$0.5$ 最大，这个样本就判给 C 类。

再举个特别生活的例子。路上看一个人，打扮偏中性，一张嘴把性别说错很尴尬。那就估概率：$0.7$ 是男生、$0.3$ 是女生，按男生称呼；反过来 $0.6$ 是女生、$0.4$ 是男生，就按女士称呼。真要是五五开，谁也说不准，那就只能猜。男、女、萨瓦迪卡，三类也一样，分别算概率，取最大的那个。

放到网络结构里，它长这样：

```text
[ input ] --> [ hidden layer ] --> z1  z2  ...  z10
                                        |
                                        v
                                softmax normalize
                                        |
                                        v
                          p1 + p2 + ... + p10 = 1
                                        |
                                        v
                           argmax(pi) -> predicted class
```

图里输出端摆了 $10$ 个数，对应 $10$ 个类别。每个类别分到一个概率，十个加起来是 $1$；其中最大的那一项占了约 $0.74$，剩下九个全加一起才 $0.26$。那这个样本就判给 $0.74$ 对应的那一类，没有悬念。

### 指数归一化是怎么算的

$$\mathrm{softmax}(z_i) = \frac{e^{z_i}}{\sum_{j=1}^{n} e^{z_j}}$$

$z_i$ 是第 $i$ 个类别拿到的线性输出，也就是上一层加权求和的结果。分子是它自己的指数，分母是全部类别指数的和。

拿五个数举例，$z_1=1$、$z_2=2$、$z_3=3$、$z_4=4$、$z_5=5$。第一个类别的概率是 $e^{1}$ 除以 $e^{1}+e^{2}+e^{3}+e^{4}+e^{5}$；第二个是 $e^{2}$ 除以同一个分母；一直到第五个。分母对每个类别都一样，变的只有分子。

指数在这里干了两件事：一是把任意实数变成正数，概率不可能为负；二是它单调递增，原来大的 $z$，归一化之后概率仍然最大，排序不会被弄乱。再让分母做一次归一，这组数就天然满足"非负且和为 $1$"。

> **结论**：Softmax 把输出层的线性结果映射到 $0$ 到 $1$，并保证同一组类别的概率加起来等于 $1$，最后取最大的那个作为预测类别。

### dim 决定沿哪个方向凑成 1

这部分代码只有三行，没什么含金量：定义一个张量装分类数据，调 softmax 时指定 `dim`，打印出来看结果。真正容易错的是那个 `dim`。

一维张量只有一个方向，`dim=0` 就是沿这唯一的轴归一，几个数加起来是 $1$。

二维就有两个方向了。`dim` 的含义是"把哪一个维度压掉"：

| 写法 | 压掉哪个维度 | 归一结果 |
| :--- | :--- | :--- |
| `dim=0` | 第 0 维（行索引） | 每一列的元素相加为 1 |
| `dim=1` | 第 1 维（列索引） | 每一行的元素相加为 1 |

> **提示**：`dim` 不是"第几行"或"第几列"，而是"沿哪个维度求和"。判断方法很简单：写完 `dim=k`，看第 $k$ 个下标在结果里消失了，剩下的下标就是结果保留的方向。

验证也不麻烦。打印出来的那组概率，直接相加看是不是 $1$；想手算，把打印出来的数字整串复制，粘贴进系统计算器，它会把带加号的算式直接算出来，不用一个一个点。

拿一组数试一下就明白：把其中一个 $0.7$ 改成 $0.6$，总和立刻少 $0.1$，差一点都不行。

### 落地的选型规则

回到最开始那个问题：激活函数到底干什么用？一句话——给神经元加上非线性，这样它才有能力把不同类别分开。

记住这一句，剩下的就是位置问题：这个激活函数放在哪一层。

输入层不用选。它接的是你的原始特征，不承担激活的职责，选什么没有意义。

隐藏层优先 ReLU。它是目前最常用的，正区间梯度恒为 $1$，收敛最快，计算最省。ReLU 不行——比如负样本里也带着重要信息——就退到 Leaky ReLU，默认 $0.01$；嫌 $0.01$ 不合适，用 PReLU 自己定，或者 RReLU 随机取。再不行，Tanh。再不行，Sigmoid。

Tanh 排在 Sigmoid 前面，理由上面算过：梯度上限 $1$ 对 $0.25$，而且以 $0$ 为中心，比 Sigmoid 的 $0.5$ 中心更好用。

如果 Tanh 和 Sigmoid 都救不回来，别在激活函数上继续纠结——换思路。这就像从学校回老家：飞机、轮船、汽车、自行车都不选，还能步行；步行都走不了，那就是回不去，不能花钱找人把你背回去。

输出层按任务类型定。二分类用 Sigmoid，输出一个 $0$ 到 $1$ 的概率；多分类用 Softmax，输出一组和为 $1$ 的概率，取最大。

回归问题用 Identity，$f(x)=x$，什么都不做。这个了解就行——用神经网络做纯回归的场景很少，绝大多数是分类。

| 位置 | 选择 | 说明 |
| :--- | :--- | :--- |
| 隐藏层 | ReLU → Leaky ReLU → PReLU / RReLU → Tanh → Sigmoid | 从左往右依次尝试，全都不行就换思路 |
| 输出层（二分类） | Sigmoid | 输出 0~1 的单个概率 |
| 输出层（多分类） | Softmax | 输出一组和为 1 的概率 |
| 输出层（回归） | Identity | $f(x)=x$，很少用 |
| 输入层 | 不选 | 与输入特征有关，不承担激活职责 |

> **结论**：隐藏层按 ReLU → Leaky ReLU → PReLU / RReLU → Tanh → Sigmoid 的顺序试；输出层按任务类型定：二分类 Sigmoid、多分类 Softmax、回归 Identity。

记不住就把这张表截个图。以后再遇到"这个网络该用什么激活函数"，先看层的位置，再看任务类型，两步就能定下来。

### 本讲提到的题目

最后留了一道面试题：**常见的激活函数及其特点**。还特意点了一句——别问"激活函数的作用"，那题太送分，要问就问特点。

题干：请说出常见的激活函数，并说明各自的特点与适用场景。

解析按讲的顺序过一遍：

- Sigmoid：映射到 $0$~$1$，导数 $0$~$0.25$；梯度消失明显，适合浅层，多用于二分类输出层。
- Tanh：映射到 $-1$~$1$，以 $0$ 为中心，导数 $0$~$1$；收敛比 Sigmoid 快，用于隐藏层且限于浅层。
- ReLU：$\max(0, x)$，只考虑正样本；导数非 $0$ 即 $1$，计算量小、收敛最快、缓解梯度消失，用于隐藏层尤其深层，缺点是神经元死亡。
- Softmax：多分类，把多个输出变成和为 $1$ 的概率，取最大者为结果，用于多分类输出层。

如果再追问一句"那怎么选"，就按隐藏层和输出层两条线答，答案就是上面那张优先级表。

## 参数初始化：打破对称性与七种方案
> 对应块：BLK17 | 覆盖分集：P42-P43 | 块标题（分集名）：《Day04-01.参数初始化_介绍》

### 初始化到底在防什么

搭一个神经网络，有个绕不过去的动作：每一层、每一个神经元身上都挂着自己的 W 和 B，也就是权重和偏置，这些值一开始总得给一个，不能空着。这个"一开始给什么值"，就是参数初始化。

那初始化到底有什么用？它同时管着三件事：会不会一上来就梯度消失或者梯度爆炸、收敛得快不快、以及网络到底能不能学到不同的东西。

#### 的五次方，与 10 的五次方

先问你一个问题。如果一开始权重设得非常小，比如 0.01，而且五层每层都是 0.01，那么数据往前传的时候每过一层就乘一次 0.01，五层下来就是 $0.01^5$，也就是 $10^{-10}$ 这个量级。梯度同样是一层层乘下去的，乘到最后变得非常非常小——这就是梯度消失。

反过来，如果一开始权重是 10，每层都是 10，$10^5$ 就是 100000，乘出来的数非常大，梯度一路被放大——这就是梯度爆炸。

```text
x --[x0.01]--> h1 --[x0.01]--> h2 --[x0.01]--> h3 --[x0.01]--> h4 --[x0.01]--> y   => 0.01^5 = 1e-10
x --[x10]----> h1 --[x10]----> h2 --[x10]----> h3 --[x10]----> h4 --[x10]----> y   => 10^5    = 100000
```

两条链路的层数完全一样，唯一差别是每层乘的那个系数：小于 1 的系数连乘会指数级衰减，大于 1 的系数连乘会指数级膨胀。

> **结论**：参数初始化的第一个作用，是防止梯度消失和梯度爆炸。

梯度消失、梯度震荡、梯度爆炸这三种病具体长什么样，后面会用代码专门演示一遍，这里先把这条因果关系记住就够了。

#### 梯度大一点，收敛快一点

第二个作用是提高模型的收敛速度。理由就摆在参数更新的那条公式上：

$$W_{\text{new}} = W - \eta \cdot g$$

其中 $\eta$ 是学习率，$g$ 是梯度。学习率固定不变的时候，梯度 $g$ 越大，一次更新迈出的步子就越大，模型收敛得就越快。

这也顺带解释了为什么我们优先用 ReLU：ReLU 求导之后，值不是 1 就是 0，只要这一层没被截断，梯度就原样往下传；而 tanh 的导数最大值也才到 1，绝大多数位置还要更小。梯度传得更"足"，收敛自然更快。

#### 打破对称性

第三个作用最需要讲明白：权重的初始化必须打破对称性，否则网络的学习能力会受到限制。

先看一个具体的层。假设这一层的 5 个神经元，都接同一组输入：

```text
输入  x1  x2  x3      （同一组特征，五个神经元共用）

神经元 1   W = (w1, w2, w3)   B = b
神经元 2   W = (w1, w2, w3)   B = b
神经元 3   W = (w1, w2, w3)   B = b
神经元 4   W = (w1, w2, w3)   B = b
神经元 5   W = (w1, w2, w3)   B = b
                              |
                              v
               五个输出完全相同 —— 同一批数据算了五遍
```

每个神经元都有自己的 W1、W2、W3 和一个 B，这样才能和三个特征一一对上。问题在于：一旦这五组 W 和 B 全都一模一样，那么输入一样、权重一样、偏置一样，算出来的结果必然一样。

结果一样意味着什么？意味着这五个神经元做的事情完全重合，等于拿同一批数据算了五回。往后传，传下去的是五份一样的数；做预测，五个神经元给出的答案还是同一个。摆五个和摆一个没有区别，这一层就白搭了。更麻烦的是，初始化一样，它们后续收到的梯度也一模一样，每次更新迈出的步子相同，训练多少轮都还是同一条心。

所以初始化的时候必须保证这五个神经元的权重和偏置各不相同，让它们各自去抓不同的特征信息，这样网络内部原有的对称性才算被打破。哪怕这一层生成的全是 1、下一层全是 2、再下一层全是 3，只要同一层内部的值互相不同，结合相同的输入也能学出不同的东西来。

> **结论**：参数初始化有三个目的——防止梯度消失或梯度爆炸、提高收敛速度、打破对称性。前两个是"值的量级"问题，第三个是"值要彼此不同"的问题，而在七种方案里真正区分优劣的，正是第三条。

### 七种方案与九个 API

这些初始化方案在 PyTorch 里全都归在 `torch.nn.init` 下面。`nn` 是 neural network，神经网络；`init` 是 initialization，初始化——合起来就是"神经网络的初始化"，所以每个函数都长成 `nn.init.xxx_`。

函数名基本就是把方案名直接搬过来：均匀分布 `uniform`、正态分布 `normal`、全零 `zeros`、全一 `ones`、固定值 `constant`、凯明 `kaiming`、泽维尔 `xavier`，末尾那个下划线是 PyTorch 的原地操作约定——直接改写传进去的那个张量本身，而不是另外返回一份新的。凯明和泽维尔各自都有正态、均匀两个版本，于是七种方案落成了九个函数。这几个单词背下来，这一块就算学会大半了。

| 方案 | API | 取值 |
| :--- | :--- | :--- |
| 均匀分布 | `nn.init.uniform_` | 默认 $U(0,1)$，可改为 $[-\frac{1}{\sqrt{D}},\ \frac{1}{\sqrt{D}}]$ |
| 正态分布 | `nn.init.normal_` | $N(0,1)$，均值和标准差可调 |
| 全零 | `nn.init.zeros_` | 全部为 0 |
| 全一 | `nn.init.ones_` | 全部为 1 |
| 固定值 | `nn.init.constant_` | 全部为指定值 |
| 凯明 · 正态 | `nn.init.kaiming_normal_` | $N(0,\text{std})$，$\text{std}=\sqrt{2/n_{in}}$ |
| 凯明 · 均匀 | `nn.init.kaiming_uniform_` | $[-\text{limit},\ \text{limit}]$，$\text{limit}=\sqrt{6/n_{in}}$ |
| 泽维尔 · 正态 | `nn.init.xavier_normal_` | $N(0,\text{std})$，$\text{std}=\sqrt{2/(n_{in}+n_{out})}$ |
| 泽维尔 · 均匀 | `nn.init.xavier_uniform_` | $[-\text{limit},\ \text{limit}]$，$\text{limit}=\sqrt{6/(n_{in}+n_{out})}$ |

#### 均匀分布与正态分布

均匀分布是最朴素的一种：权重在这个区间里均匀随机地取，默认区间是 0~1。嫌默认区间不合适，可以自己指定，常用的是 $[-\frac{1}{\sqrt{D}},\ \frac{1}{\sqrt{D}}]$。

这里的 $D$ 是"输入数量"，具体讲是**当前层的上一层**有几个神经元。为什么是上一层而不是当前层？因为当前层是做输出的，只有它的上一层才是给它喂输入的。

举个例子：一个 3 个神经元的层后面接一个 5 个神经元的层，后者的输入就是 3；再往后接的那一层，输入就是 5。每一层的 $D$ 都取自己上一层的大小，不是全网络共用一个数。

正态分布的取法则是均值为 0、标准差为 1 的高斯分布，函数名 `normal_`。它和均匀分布在使用上几乎是一回事——都是随机取值，只是随机的方式从"平着铺开"变成了"中间密、两边稀"。

#### 全零、全一、固定值

剩下三种最简单：`zeros_` 全零、`ones_` 全一、`constant_` 固定值。固定值的英文是 constant，不是 for，念对拼对就行。

这五种里面哪个用得最多？答案是全零。原因很实在：有些时候我们压根不考虑偏置，就把偏置项全部设成零，权重再换别的方案去初始化。所以"全零"最常见的角色不是给权重用的，而是给偏置用的。

那权重怎么设？七种方案讲到这里才五种，真正必须要会的是后两种。

#### 凯明初始化：专为 ReLU 设计

凯明初始化还有个名字叫"何初始化"，因为提出它的作者姓何——何凯明。

这个人确实很厉害。1984 年出生在广州，2003 年从广州市执信中学毕业，是当年广东省高考的满分状元，师从汤晓鸥，如今是人工智能科学家。顺便说一句，他长得有点像小马哥——马化腾；乍一看还跟最近那位乒乓球冠军有点像，可见高手都是相似的。

凯明初始化分两个版本：`kaiming_normal_` 和 `kaiming_uniform_`。记法就是"在均匀、正态的单词前面加上 kaiming_"，一目了然。

取值范围是这么定的：

$$\text{std} = \sqrt{\frac{2}{n_{in}}}, \qquad \text{limit} = \sqrt{\frac{6}{n_{in}}}$$

正态版从均值为 0、标准差为 std 的分布里抽样；均匀版从 $[-\text{limit},\ \text{limit}]$ 里取。两个式子的差别只在分子：一个是 2，一个是 6。

**为什么是 2 和 6？** 这个不好推，是人家试验出来的。

要把这件事说透，得先承认一个现实：神经网络中间到底做了哪些事，我们其实不知道，所以它被称为黑盒子。世界上有一小批人正在尝试用公式、用数学把它解释清楚，也许已经有人做出了成果，只是还没发表。而做神经网络方向，发论文相对来讲是比较简单的——注意，是"相对"——典型的套路是这样：你觉得现在深度学习的某个环节、某个参数或者某个公式不 OK，于是做大量训练，发现针对某几个参数做优化之后，模型的拟合效果确实好了很多，那你就可以拿着这批数据去发论文了。凯明就是这么来的。

所以将来我们做的事就是直接调 API，但底层必须清楚：正态是从 0 到 std 之间抽样，均匀是从 -limit 到 limit 之间取，std 和 limit 各自怎么算。

> **易错点**：$n_{in}$ 是"当前层接收到的输入个数"，也就是上一层有多少个神经元，而不是字面意义上的"输入层有几个神经元"。输入层和输入维度是两码事——只有最左边那一层，两个说法才碰巧重合。以 3 → 5 → 5 → 2 这个结构为例：第一个隐层的输入是 3，第二个隐层是 5，输出层也是 5；用凯明时，每一层各拿自己的这个数去算，不能拿输入层的 3 一以贯之。

什么时候用凯明？记住一条：只要用 ReLU，就优先用凯明。因为凯明就是专门针对 ReLU 及其变体做的一种设计——它考虑到了 ReLU 激活函数的特性，按输入维度把值的范围缩放好，所以能让梯度保持稳定。至于用正态版还是均匀版，都可以。

#### 泽维尔初始化：把输出也算进来

这个单词念泽维尔，Xavier，音标 /ˈzeɪviər/——不是"希维尔"。

之前中午有同学提问，一路"希维尔""希维尔"地念，我都没反应过来这是谁。这个单词你去查一下发音就明白了。念错了出去别说是我教的，就说自学成才。

API 更好记：把凯明那行的 `kaiming` 换成 `xavier`，其他一模一样。

真正的区别在范围上。凯明只看输入，泽维尔除了输入还要看输出：

$$\text{std} = \sqrt{\frac{2}{n_{in} + n_{out}}}, \qquad \text{limit} = \sqrt{\frac{6}{n_{in} + n_{out}}}$$

$n_{in}$ 是当前层接收的、上一层的神经元数量，$n_{out}$ 是当前层输出的、要传给下一层的数量。说白了就是"这一层进几个、出几个，两个数加起来"。

按 3 → 5 → 5 → 2 的结构算一遍：3 进 5 出的那一层，加起来是 8；5 进 5 出的那一层是 10；5 进 2 出的那一层是 7。每层算每层自己的，别串。

适用场景上，泽维尔适合 sigmoid、tanh 这类激活函数，能解决梯度消失；但对 ReLU 这种函数表现就不好了。

于是问题自然就来了：凯明会不会正是因为泽维尔对 ReLU 支持不够友好，才专门针对这个问题做出的改进？很可能。单看公式，不过就是把输出那一项从分母里拿掉、系数再调一调；但真要把这个改动验证成"更好"，需要大量实验。这就是站在前人的肩膀上看世界——而能想到这一步、并且把它验证出来，本身就已经说明实力了。

### 七种方案摆在一起比

把七种方案按"能不能打破对称性"分成两堆，优劣会立刻变得很清楚。

| 方案 | 能否打破对称性 | 优点 | 缺点 | 适用场景 |
| :--- | :--- | :--- | :--- | :--- |
| 均匀分布（随机） | 能 | 每个神经元拿到的值都不同，天然破除对称性 | 取值范围不当会引出梯度问题 | 浅层网络、结构简单的模型 |
| 正态分布 | 能 | 同上，随机性同样能破对称 | 取值范围不当会引出梯度问题 | 浅层网络、结构简单的模型 |
| 全零 | 不能 | 操作简单 | 不能打破对称性 | 几乎不使用；只用于偏置 |
| 全一 | 不能 | 操作简单 | 不能打破对称性，还会让激活值在网内一路放大，造成梯度爆炸 | 测试时临时固定用 |
| 固定值 | 不能 | 操作简单 | 不能打破对称性 | 调试、测试时固定用 |
| 凯明 | 能 | 专为 ReLU 及其变体设计，考虑到了 ReLU 激活函数的特性，能对输入维度做缩放、保持梯度稳定 | 对非 ReLU 激活效果一般 | ReLU 及变体；深层网络（十层以上） |
| 泽维尔 | 能 | 能解决 sigmoid、tanh 的梯度消失 | 对 ReLU 这类函数表现不佳 | sigmoid、tanh；深层网络 |

先说三个"一个值"的方案：全零、全一、固定值。它们的优点是同一个——实现简单，反正整层都是同一个值，不用考虑什么分布、什么区间；缺点是同一个——打破不了对称性。全一还多一条毛病：每层都乘 1 再累加，激活值在网络中会指数增长，最后造成梯度爆炸。

顺手问一句：初始化时把权重全设成 1，能不能打破对称性？不能，大家全是一个值，谁也不比谁特殊。全零也一样，每个神经元还是由同一套 W1、W2、W3 加一个 B 组成，你的这些值和我的这些值一模一样，对称性在这里就破不了；特征一样，算出来的结果自然也一样。这也是为什么全零几乎不使用，只在偏置上留个位置。

能打破对称性的是另外四个：随机（均匀分布）、正态分布、凯明、泽维尔。随机之所以能破对称，是因为一旦随机，你我的 W 就不一样，算出来的结果也不一样了；但它的问题在于取值范围——范围选不当，照样会引出梯度问题。这恰好解释了凯明和泽维尔存在的意义：它们不是"更随机"，而是把随机的范围按输入维度（泽维尔还要加上输出维度）算好了。

### 代码落地：三行五列到底是谁的参数

公式看完了，接下来把它们一行行敲出来。新建一个 `day04` 的工程，文件叫 `01_参数初始化_介绍`，七个方案各写一个函数，从 `DM01` 排到 `DM07`。

#### 先建一个层，才有地方放参数

第一件事是导包：

```python
import torch.nn as nn
```

`nn` 指的就是 neural network，神经网络。

然后是建层。为什么不直接初始化一个张量，非要先建一层？因为初始化这个东西是挂在某一层的权重上的——没有层，就没有 W 和 B 可初始化。再往深一层想：每个神经元的标准动作是先做加权求和、再过激活函数，而"选哪种初始化"本来就是和激活函数配套决定的（凯明配 ReLU、泽维尔配 sigmoid/tanh）。所以你得先有一个神经元、先有一层，才谈得上给它配方案。

输入层不用管：它只负责拿着特征往里对接，本身没有激活函数，也不参与这里的讨论。建隐藏层或者输出层都行。

```python
import torch.nn as nn


def DM01():
    # 1. 创建一个线性层（全连接层）：输入维度 5，输出维度 3
    linear = nn.Linear(5, 3)

    # 2. 对权重 W 做均匀分布初始化（默认 0~1）
    nn.init.uniform_(linear.weight)

    # 3. 对偏置 B 做同样的初始化
    nn.init.uniform_(linear.bias)

    # 4. 打印生成结果
    print(linear.weight)
```

`nn.Linear(5, 3)` 的两个位置参数分别是 `in_features` 和 `out_features`。写的时候注意，别把它抄成 `in_features: 5`——那个冒号是类型注解的写法，写成冒号会直接报错；要写就写等号 `in_features=5`。这两个参数本来由程序自动接收，正常也不需要手写。

5 和 3 只是随手定的。每层有多少个神经元、总共几层，都是我们自己定的，没有什么硬性规定；三层为什么不如两层、七个神经元为什么不如五个，这些全是测出来的。

#### 加不加 .data 的区别

`print(linear.weight)` 打出来的不只是数值，后面还挂着一句 `requires_grad=True`，意思是这块张量要自动计算梯度，也就是自动微分。

加上 `.data` 就只打印数值本身，干净得多：

```python
print(linear.weight.data)
print(linear.bias.data)
```

比形式更值得注意的，是每次运行的结果都不一样：这一轮是 0.22、0.91，下一轮变成 0.49、0.9，再跑一次又成了 0.7、0.04。这正是随机初始化该有的样子——每次都会重新抽一遍。

要在两个方案之间比数值差异，盯着几行数字是看不出名堂的；把这些值画成折线图，分布上的区别一眼就出来了。

#### 第一行是第一个神经元的权重

生成出来的东西是一个 3 行 5 列的矩阵。为什么是 3 行 5 列，而不是 5 行 3 列？这就得回到全连接层的定义：上一层的每个神经元，都要和下一层的每个神经元建立连接。

```text
             x1     x2     x3     x4     x5    |   b
          +------------------------------------+--------+
输出 1    | w11    w12    w13    w14    w15    |  b1    |  ->  y1
输出 2    | w21    w22    w23    w24    w25    |  b2    |  ->  y2
输出 3    | w31    w32    w33    w34    w35    |  b3    |  ->  y3
          +------------------------------------+--------+
```

读这张图有个关键：横行是"神经元"，竖列是"输入"。第 1 行就是第 1 个神经元针对 5 个输入的 5 个权重——它要和这 5 个输入分别相乘再求和，最后加上自己那一个偏置 b1，才是这个神经元的输出。

5 个输入、3 个神经元，于是排成 3 行 5 列。偏置也不是一列数据，而是每行末尾的一个数，一共 3 个。对应到实际打印的值：第一行开头那个数是 0.1336，这一行配的偏置是 0.9245；第二行的偏置是 0.4689；第三行是 0.7284。

> **提示**：看权重矩阵要看行，不要看列。一行对应一个神经元的一整套参数，这正是"每个神经元都有自己的 W 和 B"在代码里的样子。

#### 定值三种：连注释一起改

`DM02` 是固定值：

```python
def DM02():
    linear = nn.Linear(5, 3)
    # 固定值初始化：权重和偏置都设为 3
    nn.init.constant_(linear.weight, 3)
    nn.init.constant_(linear.bias, 3)
    print(linear.weight.data)
```

结果是一整片 3：权重的三行全是 3，三个偏置也全是 3。这时候三个神经元的权重一样、偏置一样、吃到的输入也一样，输出必然一样——对称性一点没破。三个神经元算出来是同一个值，那这一层摆三个和摆一个有什么区别？没有区别。

`DM03` 是全零：

```python
def DM03():
    linear = nn.Linear(5, 3)
    # 全零初始化
    nn.init.zeros_(linear.weight)
    print(linear.weight.data)
```

全零就是把 `constant_` 后面那个值去掉，换成 `zeros_`。偏置的写法一模一样，只是把 `.weight` 换成 `.bias`，这里不重复写——以后真正用得最多的，其实就是 `nn.init.zeros_(linear.bias)` 这一行。

从这一行往后，偏置就不再单写了：`weight` 和 `bias` 的初始化套路完全一致，写两遍没有意义。

`DM04` 是全一：把 `zeros_` 换成 `ones_`，出来就是 3 行 5 列全 1 的矩阵。

改函数名的时候有个必须提的坑：这些代码都是从上一个函数复制来的，函数名改了、里面的注释没跟上，就会出现"代码是全零、注释写着固定值"这种事。注释不能瞎写，得和代码死死对齐。

#### 随机剩下的：只换一个后缀

`DM05` 是正态分布：

```python
def DM05():
    linear = nn.Linear(5, 3)
    # 正态分布初始化：均值 0、标准差 1
    nn.init.normal_(linear.weight)
    print(linear.weight.data)
```

默认就是均值 0、标准差 1。不满意默认值的话，按住 Ctrl 点进函数签名，能看到 `mean` 和 `std` 两个参数，改它们就行。

`DM06` 是凯明：

```python
def DM06():
    linear = nn.Linear(5, 3)
    # 凯明初始化：正态版
    nn.init.kaiming_normal_(linear.weight)
    # 凯明初始化：均匀版
    nn.init.kaiming_uniform_(linear.weight)
    print(linear.weight.data)
```

`DM07` 是泽维尔：把 `kaiming` 换成 `xavier`，其余一个字都不用动。

```python
def DM07():
    linear = nn.Linear(5, 3)
    # 泽维尔初始化：正态版
    nn.init.xavier_normal_(linear.weight)
    # 泽维尔初始化：均匀版
    nn.init.xavier_uniform_(linear.weight)
    print(linear.weight.data)
```

七个方案我只单独写了一个函数，后面全是复制粘贴改一个单词——因为 API 的形态本来就一模一样。凯明的正态版和均匀版生成出来的数值差别还挺明显，但那是分布形状的差别，不是高下之分。

观察结果时别纠结"哪种看着更顺眼"，真正的判断标准只有一条：第一行和第二行的数是不是不一样，也就是第一个神经元和第二个神经元的权重是不是不同。不同，对称性就破了，这一层才有意义。

### 到底该用哪个

四条判断，对号入座就行：

| 情形 | 选择 |
| :--- | :--- |
| 激活函数是 ReLU 及其变体 | 凯明（正态版、均匀版都行） |
| 激活函数是 sigmoid、tanh 等非 ReLU | 泽维尔 |
| 浅层网络（两层、三层，五层以内） | 随机初始化，或者正态分布 |
| 深层网络（十层以上） | 凯明或泽维尔 |

ReLU 优先凯明，因为 ReLU 用得最多，凯明又是为它量身定做的；非 ReLU 就交给泽维尔。浅层的两层、三层、五层以内，用随机初始化或者正态分布完全够，不一定非得请出凯明和泽维尔——这两个方案本来就是为深层准备的，浅层硬用当然也能跑，只是没必要。而一旦到了深层，就必须在凯明和泽维尔之间选，不能再随手随个机就完事。

七种方案听下来多，实际要掌握的就三种：

- 凯明，排第一，因为 ReLU 用得最多；
- 泽维尔，除了 ReLU 之外的基本都归它；
- 全零，专门给偏置用。

一句话收口：权重要么凯明、要么泽维尔，偏置全零。

还有三问，是这一块最该条件反射答出来的。

参数初始化的目的是什么？防止梯度消失或梯度爆炸、提高收敛速度、打破对称性。

七种方案分别是谁？按能不能打破对称性分两堆：破不了的三个是全零、全一、固定值；能破的四个是随机（均匀分布）、正态分布、凯明、泽维尔。

到底怎么选？ReLU 用凯明，非 ReLU 用泽维尔，浅层随机，深层凯明或泽维尔。这三问答得出来，参数初始化就算过关了。

## 从结构图到代码：神经网络的搭建与参数计算
> 对应块：BLK18 | 覆盖分集：P44-P45 | 块标题（分集名）：《Day04-03.神经网络_搭建流程介绍》

前面讲深度学习，我们一直在嘴上说“搭个神经网络”——几个隐藏层、每个隐藏层放几个神经元、输入几个输出几个。说得再热闹，那也停在表达层面。这一节把它落到地上：手里既然已经有一张神经网络的结构图，就照着这张图把代码重构出来。

PyTorch 里定义一个深度神经网络，说白了就四个字——层堆叠。玩过积木没有？搭网络跟搭积木是一回事：一层一层往上摞，一会儿摞个长方形，一会儿摞个正方形，一会儿摞个椭圆，摞完就成型了。

### 搭网络跟搭积木是一回事

那这个“搭”，落在代码的哪个位置？

先把 `nn` 是谁说清楚：`nn` 就是 Neural Network，神经网络。所以要搭自己的网络类，第一件事就是搞一个类，继承 `nn.Module`。继承完，重写两个方法就够了。

第一个是 `__init__`，初始化方法。你搭层就在这里面搭：几个隐藏层、几个输出层、每个隐藏层几个神经元、几个输入几个输出，全写在这儿；层搭完之后顺手把参数初始化一下，也在这儿。

第二个是 `forward`，前向传播。从输入层出发，过隐藏层一、隐藏层二，一直到输出层，从左往右走一遍，这就是前向传播。反向传播是从输出层逐层往回更新，方向正相反，那是另一码事——这里用不上，后面会专门做。

关于初始化还有句实话要说：这一版我把初始化写给你看，可往后真写代码，只把层搭好就行，初始化我都不写。为什么？因为底层默认就帮你做了。像后面用到 CNN、RNN，初始化其实早就替你做过了。所以初始化先知道有这么个动作，别把它当成必写项。

`forward` 这个名字还有讲究。带双下划线的方法叫什么？魔法方法。魔法方法的特性是不用你手动调，特定场合下自动调用。`forward` 没有那对下划线，不是魔法方法，但**它的用法跟魔法方法一模一样**——将来你把模型实例化出来，底层会自动调用它。你看不到谁在代码里手写一句“来，forward 一下”，没这回事，把它写好放着就行。

> **易错点**：正因为底层是按名字来找你的，`forward` 这个名字不能改。换了名字，别人就找不到你了。固定写法，一个字别动。

> **定义**：`forward` 里干的事，就是把 `__init__` 中定好的那些层依次取出来，往里面传数据，一节一节走完前向传播。

所以整件事总结下来就三句话：搞个类继承它，重写两个方法，完事。

### 先看懂这张图：四个层，还有那个“+1”

动手之前先把图看明白。这张图不是随手编的例子——它是一套考试卷里那道大题的原题。真考的时候神经元数量可能会变，但思路一模一样。

```text
┌─────────┐      ┌─────────┐      ┌─────────┐      ┌─────────┐
│ 输入层  │      │ 隐藏层1 │      │ 隐藏层2 │      │ 输出层  │
├─────────┤      ├─────────┤      ├─────────┤      ├─────────┤
│ x1      │      │ o       │      │ o       │      │ o       │
│ x2      │ ───▶ │ o       │ ───▶ │ o       │ ───▶ │ o       │
│ x3      │      │ o       │      │         │      │         │
│ +1 bias │      │ +1 bias │      │ +1 bias │      │         │
└─────────┘      └─────────┘      └─────────┘      └─────────┘
```

四个方框从左往右依次是输入层、隐藏层 1、隐藏层 2、输出层，箭头方向就是数据流动的方向；数一数框里画了几个节点，就知道每层有几个神经元。

图上有三处 `+1`，这里最容易想歪。看到它就以为“多一个神经元”——不对。这个 1 是 bias，偏置。一个神经元要出结果，是拿上一层传过来的若干输入各自乘权重做加权求和，再**加上自己的偏置**。所以那个 1 不是数据层面多出来的一维特征。

> **易错点**：`+1` 是偏置不是神经元，算 `nn.Linear` 的第一个参数时不能把它算进去——偏置是本层自己加权时加上去的，不是上一层传下来的输入。

这一点我是拿点名来验的。先问一位同学：隐藏层 1 的输入、输出各是几，`nn.Linear(?, ?)` 里那两个数该怎么填？他答“3、3”。第一个 3 什么意思？——上一层不是 4 个吗，还带个 +1 的。加 1 是 bias，真正传下来参与加权的是 3 个。第二个 3 呢？这层自己有 3 个神经元，所以输出是 3。我本来赌你们会答错，答错就把接下来要写的代码手抄一遍——咱这代码六七十行呢——结果这位同学硬是没往坑里跳。

> **提示**：这一层也有自己的 `+1`，但那个偏置只服务本层；轮到下一层数输入维度时，数的仍然是本层的神经元个数 3，不是 3+1。

照这个规矩把三层排下来：

| 层 | 输入维度 | 输出维度 | 代码写法 |
| :--- | :--- | :--- | :--- |
| 隐藏层 1 | 3 | 3 | `nn.Linear(3, 3)` |
| 隐藏层 2 | 3 | 2 | `nn.Linear(3, 2)` |
| 输出层 | 2 | 2 | `nn.Linear(2, 2)` |

输入层压根不用搭。你喂进来的特征有几个，它自动就是几维——这件事不用你管，代码里也不会出现“输入层”这一行。

### 规定死的搭配：Xavier 配 Sigmoid，Kaiming 配 ReLU

三层维度排完，神经元这一块就算构思完了。可每个神经元还差最后一个动作，而且是两个活：左边加权求和，右边过激活函数。我在图上左边写个加号代表加权求和，右边写个 S 代表 Sigmoid——当然不一定非用 Sigmoid，写个 R 用 ReLU 其实更合适。

于是问题来了：隐藏层 1、隐藏层 2、输出层，一共需要几个激活函数？三个。有人会追问，那输入层为什么不需要？输入层跟你的特征数有关，它不做激活，不用设置。

骨架齐了，接下来就是几条规定死的动作：每一层用什么方式初始化权重，配什么激活函数。

先看第一个隐藏层。硬性规定用谁？Xavier。哪种 Xavier？标准化的 Xavier（Xavier normal）。这个“标准化”指的是正态分布，不是均匀分布——名字里写着 normal，别写成 uniform。

激活函数规定用 Sigmoid。于是隐藏层 1 是 Xavier 加 Sigmoid 的组合。

这里就有人要跟我抬杠了：不对吧，不是说了 Sigmoid 更适合输出层的二分类吗？现在这是隐藏层 1，里面就 3 个神经元，又不是二分类，能用 Sigmoid 吗？

> **结论**：能用，只是效果好与不好的问题。激活函数不是“只能用在某一层”的专利，选它取决于你想让这一层输出什么形态，不取决于这层是不是最后一层。

如果是真实开发、让我自己选，你猜我选什么？我会选 ReLU，想都不想，一定选 ReLU；初始化加 Kaiming，ReLU 配 Kaiming。但现在人家有硬性规定，那就按人家的来。这个大家会写就行，不用纠结。

再往下，第二个隐藏层规定用什么？Kaiming 正态，配 ReLU。到输出层，假如是多分类，那不用想了，多分类一定是 Softmax。

| 层 | 权重初始化 | 激活函数 |
| :--- | :--- | :--- |
| 隐藏层 1 | Xavier 标准化（正态分布） | Sigmoid |
| 隐藏层 2 | Kaiming 正态 | ReLU |
| 输出层 | 未作规定 | Softmax（多分类） |

三层的搭配定完，这张图就彻底构思完毕了。接下来的问题只剩一个：该写代码了。

不过在动键盘之前，先把“搭建”这件事在整个深度学习流程里的位置摆正，不然写代码容易糊。

### 搭建流程只有正向，反向在训练那一步

神经网络搭建流程，一共三步：

1. 定义一个类，继承 `nn.Module`；
2. 在 `__init__` 方法中搭建神经网络；
3. 在 `forward` 方法中完成前向传播。

就这三步。有人马上要问：那反向传播呢？反向传播后面会专门做，这个地方不需要。

为什么不需要？因为放到深度学习做一个案例的全局里看，一共是四步：

```text
深度学习案例：  准备数据  →  搭建神经网络  →  模型训练  →  模型测试
机器学习案例：  准备数据  →  数据预处理  →  特征工程  →  模型训练  →  模型测试  →  评估
```

上面这条是深度学习的四步，下面这条是机器学习的六步，对比着看就明白深度学习少在哪儿了。

机器学习里，数据准备好还得自己做预处理、自己做特征工程，前前后后六步。到了深度学习，你只要准备好数据，把数据丢进神经网络，剩下那些手工活由网络自己去做。所以四步里第二步就是搭建神经网络——它顶掉了机器学习的预处理和特征工程。

而反向传播属于哪一步？属于第三步模型训练。搭建神经网络是第二步，训练是第三步，两件事分属不同步骤。所以在这一步里，只有正向，没有反向。这个界限一定要分清。

> **提示**：写这些代码的目的很直接——今天要做的是个深度学习 ANN，做手机价格预测。到时候你会发现，我写代码就是严格按这四步来组织的：先准备数据，再搭网络，再训练，最后测试。

顺便说一句，这张图我希望你能背下来。不是背后面那些参数，是背两条东西：神经网络搭建流程，以及深度学习案例的四个步骤。这两条是骨架，具体数字考场上会变，骨架不会变。

### 先把参数算清楚：整个模型一共 26 个

代码一写，参数就跟着来了。那先把账算明白：这张图里，参数一共有多少个？

盯住隐藏层 1 里的一个神经元看。它有几个参数？有人张嘴答五个，正确的答案是四个——三个 $w$ 加一个 $b$。上一层传下来 3 个输入，每个输入配一个权重，再配上自己的一个偏置，4 个。

按这个口径逐层数：

| 层 | 神经元个数 | 每个神经元的参数 | 本层合计 |
| :--- | :--- | :--- | :--- |
| 隐藏层 1 | 3 | 3 个 $w$ + 1 个 $b$ = 4 | 12 |
| 隐藏层 2 | 2 | 3 个 $w$ + 1 个 $b$ = 4 | 8 |
| 输出层 | 2 | 2 个 $w$ + 1 个 $b$ = 3 | 6 |

隐藏层 2 每个神经元为什么是 4 个？它的上一层有 3 个神经元，所以 3 个权重，再加一个偏置。输出层每个神经元为什么是 3 个？它的上一层只有 2 个神经元，2 个权重加一个偏置。

加起来：$12 + 8 + 6 = 26$。整个模型的参数总量就是 26 个。

不过光我说 26 个不算数。你心里肯定还有一句“我不信，你让我看看呗”。想亲眼验证，就得请 `torchsummary` 出场——它会把每一层的输出形状和参数数量打出来，加总跟你手算的对一对。

### 落笔：类骨架与 __init__

新建一个工程，名字叫“神经网络搭建”。包导进来，然后正式动手。

第一步，创建类、继承 `nn.Module`：

```python
import torch
import torch.nn as nn


class ModelDemo(nn.Module):
    def __init__(self):
        # TODO 1.1 初始化父类成员
        super().__init__()
```

类名叫 `ModelDemo` 或者 `MyModel` 都行，关键是括号里那个 `nn.Module`。这里插一句我以前提醒过的话：深度学习这部分会用到面向对象的知识，之前让大家复习，用处就在这儿。

`TODO` 是个好东西。注释里写上 `TODO`，它就会被高亮，一眼能看到这一节还没做完。注意 `TODO` 前面的井号不能省，省了就报错——它本质上是注释里的一个关键词。

#### 先初始化父类

`__init__` 进来第一件事，是固定套路：初始化父类成员。

```python
super().__init__()
```

你继承的是 `nn.Module`，那就要先把父类该做的初始化做完，再搭自己的层。这一行是固定写法，没有商量余地。

#### 三层怎么摆

接下来搭网络。只搭隐藏层和输出层，输入层不用搭——喂进来几个特征，它自动接住。

```python
        # TODO 1.2 搭建神经网络：隐藏层 + 输出层
        self.linear1 = nn.Linear(3, 3)
        self.linear2 = nn.Linear(3, 2)
        self.out = nn.Linear(2, 2)
```

变量名有点讲究。全连接层在实战里就两个词：要么 FC（fully connected），要么 linear。我个人喜欢 `linear`，因为类名就叫 `nn.Linear`，创建一个线性层，名字对得上。

所以我先写 `self.linear1`。这里顺手记一个习惯：正常我会写 `hidden1`，一看就知道是隐藏层的意思；但既然用的是 `nn.Linear`，就顺着叫 `linear1`、`linear2`。

到输出层，本来该叫 `linear3`，我偏不叫——把它换成 `out` 或者 `output`。名字是给自己看的，第三层是输出层，就叫输出，读代码的人一眼能认出来。

#### 参数初始化：这一版写，往后可以不写

层搭好了，参数还是随机的，所以要初始化。这一步对应的就是前面那张表里的规定。

隐藏层 1 用 Xavier 正态：

```python
        # TODO 1.3 参数初始化
        nn.init.xavier_normal_(self.linear1.weight)
```

`nn.init` 是 PyTorch 的初始化模块，点 `xavier`，后面跟 `normal` 还是 `uniform`？规定是 normal，所以是 `xavier_normal_`。对谁初始化？对 `self.linear1` 这个层，具体是它的 `weight`。

那 bias 要不要初始化？规定里没提。我的习惯是把 bias 全置 0：

```python
        nn.init.zeros_(self.linear1.bias)
```

隐藏层 2 同理，规定是 Kaiming 正态，配的也是同样的两行：

```python
        nn.init.kaiming_normal_(self.linear2.weight)
        nn.init.zeros_(self.linear2.bias)
```

到此参数初始化写完。但我要提前说清楚：以后写代码就写到搭层这一步为止，初始化这个活不用做——底层默认会初始化，CNN、RNN 那些层也一样。这一版写出来，是为了让你知道这个位置本来该干什么，以及规定的初始化方式长什么样。

### forward：名字不能改，写法有两版

第二个方法，前向传播。

```python
    def forward(self, x):
```

格式是固定的：方法名就叫 `forward`，参数是一个 `x`。

前面说过，这个函数会在你创建模型的时候被自动调用。既然是被底层按名字找上来的，那这个名字能不能随手改？不能。改成别的，别人就找不到你了。固定写法，一个字别动。

传进来的 `x` 是谁？就是输入层那份数据。注意 `x` 不是一个数，是一个矩阵——一批样本一起喂进来，它是一整块数据。

#### 分解版：先加权求和，再激活

第一层隐藏层的计算，拆开写就是两步。

先做左边的加权求和，把数据送进第一个线性层：

```python
        x = self.linear1(x)
```

再做右边的激活。规定用 Sigmoid，那就是 `torch.sigmoid`，小写：

```python
        x = torch.sigmoid(x)
```

两步合起来看：第一层神经元处理完了。

这里可能有人没跟上：左边那个 `x` 和右边那个 `x` 是同一个东西吗？你把它们想象成 $x_1$、$x_2$ 就明白了。最开始的 $x$ 是传进来的一整批特征，不止一个；$x_1$ 是加权求和之后的结果；$x_2$ 是再激活之后的结果。真要一层一层往下推，到第三层就该出现 $x_3$、$x_4$、$x_5$、$x_6$ 了。

可这么写太乱，谁记得住哪个 $x$ 是哪一步的。所以实战里清一色全写 `x`：进去是 `x`，出来换个新值还是叫 `x`，一路覆盖到底。反正下一步只认最新的那个。

#### 合并版：实际开发清一色这么写

既然加权求和之后紧跟着就是激活，那两行能不能并成一行？能：

```python
        x = torch.sigmoid(self.linear1(x))
```

原来第二行的 `x` 就是第一行的结果，直接把它替换成 `self.linear1(x)` 塞进 `torch.sigmoid` 的括号里，一行顶两行。合并版怎么来的？就这么合出来的。

第二层隐藏层，同样的套路。这一层规定用 ReLU，那就换成 `torch.relu`：

```python
        x = torch.relu(self.linear2(x))
```

第三层是输出层。多分类的输出，激活用 Softmax：

```python
        x = torch.softmax(self.out(x), dim=-1)
```

你敲到 `torch.` 这一步，编辑器后面呼啦啦给你列一串函数，Softmax 就在里面；这跟你在第一层写激活函数时它给你推荐 ReLU 是一回事。

最后把结果返回：

```python
        return x
```

#### dim=-1 是按行算

`dim=-1` 这个参数值得单独说一句，很多人抄代码的时候根本不看它。

`-1` 代表最后一个维度。对二维数据来说，`dim=1` 和 `dim=-1` 是一回事，写哪个都行。

“按最后一个维度算”是什么意思？假设一次喂进来 5 行 3 列的数据——每一行就是一条样本。处理的时候，它是拿一行过来，对这一行做转置，把这一行里的各个列当成特征去算；算完这一行，再处理下一行。

所以 `dim=-1` 的实际含义是：**按行计算，一条样本一条样本地算**。Softmax 把一条样本在各个类别上的分数归一化，跨行去归一是没有意义的——不同样本之间凭什么互相挤占概率。

### 写到这儿就算搭完了

三层计算走完、`return x` 一返回，网络就搭完了。

这个返回的 $x$，对应的是前两天那张讲前向传播、反向传播与自动微分的图里的 $z$。也就是说，我们这一步只负责把输入一路推到 $z$，后面的损失、梯度、参数更新都不在这一节的范围里。

整份代码合起来看：

```python
import torch
import torch.nn as nn


class ModelDemo(nn.Module):
    def __init__(self):
        # TODO 1.1 初始化父类成员
        super().__init__()

        # TODO 1.2 搭建神经网络：隐藏层 + 输出层
        self.linear1 = nn.Linear(3, 3)
        self.linear2 = nn.Linear(3, 2)
        self.out = nn.Linear(2, 2)

        # TODO 1.3 参数初始化
        nn.init.xavier_normal_(self.linear1.weight)
        nn.init.zeros_(self.linear1.bias)
        nn.init.kaiming_normal_(self.linear2.weight)
        nn.init.zeros_(self.linear2.bias)

    def forward(self, x):
        # TODO 2.1 第一层隐藏层：加权求和 + 激活
        x = torch.sigmoid(self.linear1(x))
        # TODO 2.2 第二层隐藏层
        x = torch.relu(self.linear2(x))
        # TODO 2.3 输出层
        x = torch.softmax(self.out(x), dim=-1)
        # TODO 2.4 返回预测值
        return x
```

再明确一句：有一套卷，大题就是给你一张这样的图，下面列几条要求，让你写这段代码。写到这儿就够了，一模一样地写到这儿，15 分。核心就两块——`__init__` 里把层搭出来，`forward` 里把前向传播串起来。

## 把模型跑起来：建对象、喂数据、数清 26 个参数
> 对应块：BLK19 | 覆盖分集：P46-P47 | 块标题（分集名）：《Day04-05.神经网络_模型训练》

网络搭完，架子立在那儿，下一步是让它真跑一次。这是我们做这件事的第二个动作：模型训练。

严格讲，这一步还不配叫训练——模型一次都没更新过，这一轮只是拿随机数据做一次测试。真实的训练代码比这复杂得多，要算损失、要反向传播、要一轮轮迭代。但入门就得先把这条最细的线走通：建对象、喂数据、看输出、数参数。这四件事走通了，后面往上加什么都只是往这条线上挂。

```text
to do 1  搭建网络：类 + __init__ + forward
to do 2  模型训练 / 测试：def train()
           ├─ 创建模型对象
           ├─ 创建数据集样本
           └─ 调用模型，拿到输出
to do 3  测试入口：调用 train()
```

读图：第一个动作负责把网络搭出来，第二个动作负责让它跑一次，第三个动作只是个入口，里面就一句 `train()`。

### 把 train 函数放在类的外面

第二个动作写成一个函数 `def train()`。位置有讲究：它跟 `class` 平级，顶格写，不要缩进到类里头去。

初学者十有八九会把它写成类的方法。脑子里一想“这是模型的训练”，手就往类里面伸，缩进四个空格，变成 `my_model.train()`。错在语义上：这个函数是**用**模型的，不是模型的**一部分**。搭网络那几段才是模型自己的血肉，训练是从外面发起的一个动作。

当然，你不封装、直接把这几行写到 `main` 里也能跑，但独立成一个 `train()` 更清楚，`main` 里就留一句 `train()`。

### 先建一个模型对象

```python
my_model = ModelDemo()
print(my_model)
```

`ModelDemo` 就是刚才搭网络时写的那个类。实例化出一个对象，起名 `my_model`。打印它，屏幕上会出来这么一串：

```text
ModelDemo(
  (linear1): Linear(in_features=3, out_features=3, bias=True)
  (linear2): Linear(in_features=3, out_features=2, bias=True)
  (linear3): Linear(in_features=2, out_features=2, bias=True)
)
```

看到这一串别慌，也别以为是框架替你生成的——层名 `linear1`、`linear2`、`linear3` 是你自己起的，`in_features`、`out_features` 里的数字是你自己填的，`bias=True` 也是你自己写的。它只是把你写进 `__init__` 的那几条 `Linear` 原样列了一遍，顺手把结构画给你看。

到这一步，模型对象有了，但它是“生的”：参数还是初始化时那一版，一条数据都没见过。

### 再随机造一批数据

```python
data = torch.randn(size=(5, 3))
print(data)
print(data.shape)
print(data.requires_grad)
```

要玩数据，先 `import torch`。`randn` 生成的是标准正态分布的随机数，`size=(5, 3)` 就是五行三列——五条样本，每条三个特征。

这里有个小瑕疵：随机数没设种子，每跑一次出来的数都不一样。不管它，我们现在只看数据格式，不看具体值。

`data.shape` 打出来是 `torch.Size([5, 3])`。它本质上是个元组，你不用纠结它长什么样，把里面的数字念对就行：五行三列。

`data.requires_grad` 打出来是 `False`。这个属性管的是“要不要参与自动微分”，刚生成出来的时候默认是 `False`，也就是先不挂梯度。

### 把数据喂进模型

```python
output = my_model(data)
print(output)
print(output.shape)
print(output.requires_grad)
```

模型对象后面挂一对括号，把 `data` 塞进去，这就是调用模型。返回值存进 `output`，叫 `output_value` 也一样，随你。

好奇心先走一步：输出会是什么形状？答案是五行两列。

推一遍就明白了：传进去五行三列，第一层 `Linear(3, 3)` 三进三出，出来还是五行三列；第二层 `Linear(3, 2)` 三进两出，变成五行两列；第三层 `Linear(2, 2)` 两进两出，仍是五行两列。行数从进门到出门一直不动，变的是列数。

```text
data (5 × 3)
   │
   ▼
Linear(3 → 3) ──► (5 × 3) ──► 参数 3 × (3 + 1) = 12
   │
   ▼
Linear(3 → 2) ──► (5 × 2) ──► 参数 2 × (3 + 1) = 8
   │
   ▼
Linear(2 → 2) ──► (5 × 2) ──► 参数 2 × (2 + 1) = 6
   │
   ▼
softmax ──► 两个输出相加为 1
```

读图：列数被每一层的第一个参数（输入特征数）卡住，从 3 到 3、再到 2、再到 2；行数代表样本条数，全程不变；三层参数量加起来 26，这个数一会儿要拿工具核一遍。

再看那两个数。输出第一行是 0.53、0.46 这样的两个值，它们加起来是 1。为什么？因为模型最后接的是 softmax。昨天讲激活函数时说过，softmax 适用于多分类，输出的是各个类别的概率，所有类别的概率相加必然等于 1。屏幕上只有两位小数，截断之后看着像 0.99，底下真实值加起来是整 1。

### 输出为什么自带梯度

`data.requires_grad` 是 `False`，`output.requires_grad` 却变成了 `True`。我没手动设过任何东西，这是谁给的？

答案在 `forward` 里。你把数据往模型对象后面一挂，PyTorch 底层就转手去调 `forward`，前向传播算出来的就是预测值——从头到尾我们没写过一行 `my_model.forward(data)`，全是底层自动调用的。数据进了 `forward`，一路乘 W、加 B，而这些 W、B 都是需要更新的参数，PyTorch 就把这条计算链记了下来，把结果标成“需要梯度”。为什么要标？因为下一步反向传播要拿这些值往回求导、改参数。你现在看到的 `True`，是给反向传播留的接口。

> **提示**：`requires_grad` 只表示这个张量参不参与求导，跟数值对不对没有关系。输入数据自己是 `False`，经过一层带参数的运算，输出就成了 `True`，这是自动微分在记录计算图。

### 用 torchsummary 核一遍参数量

前面那些参数是纸上算的，现在请个工具来验。

```python
from torchsummary import summary

summary(my_model, input_size=(5, 3))
```

`torchsummary` 是第三方包，得先装上：`pip install torchsummary`。

它吃两个参数：

- 第一个是模型对象 `my_model`；
- 第二个是输入数据的维度 `(5, 3)`，就是你用 `randn` 造出来的那个形状，不是单个样本的那三个特征。

跑出来会出一张表，你只盯三列：层名、输出形状、参数量。

| 层 | 输出形状 | 参数量 |
| :--- | :--- | :--- |
| Linear-1 | [-1, 3] | 12 |
| Linear-2 | [-1, 2] | 8 |
| Linear-3 | [-1, 2] | 6 |
| 合计 | — | 26 |

表尾还有两行最关键：`Total params` 是 26，`Trainable params` 也是 26。这两个以后可能不一样——比如总共 200 个参数，实际只训练 150 个（冻住一部分不动）。入门阶段遇不到，你有多少就训多少。

12、8、6 怎么来的，这是整块里最该亲手数一遍的地方。

第一层：3 个神经元，每个都要接上一层的 3 个输入，就是 3 条权重 W，再加自己 1 个偏置 B，一个神经元 4 个参数；3 个神经元乘 4，12 个。

第二层：2 个神经元，每个接上层那 3 个神经元，同样 3 条 W 加 1 个 B，也是 4；2 乘 4，8 个。

第三层：2 个神经元，每个只接上层 2 个神经元，2 条 W 加 1 个 B，是 3；2 乘 3，6 个。

12 加 8 加 6，正好 26。

算的时候每个神经元名下反复冒出来的 4、4、3，不是神经元个数，是“上层神经元数 + 1”。第一层和第二层上层都是 3 个，所以各是 4；第三层上层是 2 个，所以是 3。这个 4 就是这么来的，那个 3 也是这么来的。

> **易错点**：输入数据和网络权重是两回事。5×3 里的 3 是样本的特征数，是喂进来的数据；W1、W2、W3 是连接上的权重，是要训练的参数。数参数量的时候别把输入特征也数进去，特征不是参数。

表下面那几行——forward/backward pass size、params size、estimated total size——现在用不到，先不看。它们说的是前向反向各占多大资源，等项目大了再说。

### 输出形状前面那个 -1

表里输出形状写的是 `[-1, 3]`、`[-1, 2]`、`[-1, 2]`。那个 -1 不是负一，是“这一维我不定，你按实际输入自己算”。

它占的是批次维。这次传了 5 行，它就是 5；下次传 6 行，它就是 6；传 10 行、500 行都行。既然随时会变，就没法写死，只能用 -1 占位，让框架自动推断。这就是所谓“批次不确定、自动计算”。

能动的只有行，列动不了。第一层写的是 `Linear(3, 3)`，第一个 3 是输入特征数，意思很硬：到我这儿的数据，特征数必须是 3。你造一个六行五列塞进去，直接报错。想收五列也行，把层定义里的第一个 3 改成 5，网络结构跟着变，权重数量也跟着变。

一句话记住：行是样本数，随便改；列是特征数，网络一旦定死就不能改。

### 把 26 个参数逐个认一遍

summary 只给数量，不给具体值。想看见这 26 个家伙长什么样，得用 `named_parameters()`：

```python
for name, param in my_model.named_parameters():
    print(name, param, end="\n\n")
```

这个 API 把每一层的名字和参数成对吐出来，`end="

"` 是每组打完之后空一行，不然一坨挤在一起没法看。

名字一出来你就认识了：`linear1.weight`、`linear1.bias`、`linear2.weight`……

值全是 0。别怀疑，初始化的时候就是全置 0 的——你上一节亲手写的初始化代码，这会儿显形了。

对号入座：

- `linear1.weight` 是个 3×3 的矩阵。一行对应这一层的一个神经元，行里那三个数是这个神经元连到上层三个输入的三条权重。画到图上，就是三条线竖着汇进同一个神经元。
- `linear1.bias` 三个数，一个神经元配一个。
- 第二行是第二个神经元的，第三行是第三个，依次往下。
- `linear2.weight` 是 2×3：2 个神经元，每个接 3 个输入；`linear2.bias` 两个。
- `linear3.weight` 是 2×2，每个接上层 2 个输入；`linear3.bias` 两个。

挨个数一遍：3×3 得 9，加 3 个偏置是 12；2×3 得 6，加 2 个偏置是 8；2×2 得 4，加 2 个偏置是 6。合起来 26，跟 summary 报的数一模一样。

> **提示**：权重矩阵的形状是“本层神经元数 × 上层神经元数”。看行数就知道这层有几个神经元，看列数就知道它接了多少个输入，不用翻代码。

### 前向出结果，反向改参数

参数全摆出来之后，“训练”这件事一句话就能说清：

- 前向传播：拿这 26 个参数把输入算成预测值，这是第一版结果；
- 算损失：看预测跟真实答案差多少；
- 反向传播：回来把这 26 个参数全都改一遍；
- 再前向、再算损失、再反向……

就这么转圈。每转一轮，26 个参数就往真实规律靠近一点，模型的拟合效果就好一点。转到损失降不下去，模型就算训出来了。

我们刚才只跑了前向：26 个参数一个都没动，所以这一轮只是测试，不是训练。等损失函数和优化方法接上，这个循环才真正转起来。

### 搭网络到底几步

把前面的动作收拢一下，搭一个神经网络就三步：

- 定义一个类，继承 `nn.Module`；
- 在 `__init__` 里做两件事：第一行 `super().__init__()` 把父类成员初始化，这是固定动作，一步都不能省；然后把自家的层搭起来；
- 写 `forward`，定义前向传播怎么算。

硬要强调的话，中间还藏着一步：参数初始化。把 W、B 置成初始值，放在搭完层之后，`__init__` 里解决。刚才打印出来全是 0，就是它干的。

顺序上也要清楚：创建对象的时候先走 `__init__`，完成父类初始化、搭网络、初始化参数；等数据喂进去，再走 `forward` 做预测。两个方法都是 PyTorch 在调，你只负责把它们写对。

### 网络参数量怎么算

记一个公式：

$$\text{本层参数量} = \text{本层神经元数量} \times (\text{上层神经元数量} + 1)$$

那个 +1 是偏置，每个神经元都配一个 B，别忘了它。

拿它把 26 验一遍：第一层 3 × (3 + 1) = 12；第二层 2 × (3 + 1) = 8；第三层 2 × (2 + 1) = 6。加起来 26，跟 summary 报的一分不差。

> **注意**：这个公式只对全连接层成立。全连接层的定义就是“本层每个神经元和上层所有神经元都连”，所以才是乘法。后面学 CNN（卷积神经网络）和 RNN，参数量算法都不一样——卷积核是共享的，不能拿这套乘。现在这个是最简单的情形，先把它吃透。

要是跟别人讲这个 26，顺序得反过来：先报结构，再算数。上来就说“上一层有 3 个，3 加 1 是 4，所以这层 12 个”，听的人不知道你在说哪张网，当场就懵。正确的说法是——输入 3 个特征，两个隐藏层分别 3 个和 2 个神经元，输出层 2 个神经元，架构是 3-3-2-2；然后一层一层算 12、8、6，合计 26。对方脑子里先有图，数字才落得下去。面试也是这个道理，先把网络结构交代清楚，再谈参数量。

### 神经网络的优缺点

#### 优点：精度高，还能逼近任意非线性

精度高，性能优于其他机器学习方法，某些领域已经超过人。凭什么超过人？举个例子：还是 3 个特征进来，我把隐藏层写成 512 个神经元，网络就会基于这 3 个特征抽出 512 组信息，生成 512 组权重和偏置。人来抽？人来根本不知道该抽谁。就像接亲时伴娘让新郎快速说出新娘的十个优点，新郎支支吾吾说两三个就卡住了；让你说一百个，更得琢磨半天。特征怎么组合、怎么加权，交给算法自己找，这块人确实比不了。

第二，可以近似任意非线性函数。因为激活函数把非线性加进来了，所以任何分类它都能做，二分类、多分类都行。

第三，学界业界都热，框架和库一大堆，说白了就是有一堆现成的 API 可以直接用。

#### 缺点：黑箱、费算力、怕小数据

第一是黑箱。W 和 B 我都给你打印出来了，可你解释不了：为什么是这个 W、这个 B？这个 W 到下一个 W 中间经历了什么？我写 3 是这个结果，写 5 是那个结果，为什么？三个隐藏层比两个效果好，好在哪？没有公式能验证，只能不断调参、看结果。跟 K-means 比一比就明显了：K 怎么定是有办法的，SSE 加肘部法，肘窝那个拐点就是 K；神经网络没有这种抓手。也没有“训练集测试集 7:3 或 8:2”“学习率 0.01 到 0.0001”那种能背下来的规律。几层、每层几个神经元，全得试。

那实际做项目怎么办？先搭一个简单的，两三层，每层少来几个神经元，然后慢慢加、慢慢测。有一条经验可以分享：神经元个数从前层往后层应该逐渐递减，第一层最多，第二层其次，越往后越少。经验之谈，不是定理，但大方向错不了。

第二是训练时间长，需要大量算力；网络结构复杂，超参要调——几层、每层几个，都是变量。

第三，小数据集上表现不好，容易过拟合。模型太复杂，一条数据也能被它提出一堆“脏”规律。还是那只天鹅：给你的数据全是白的，模型就提取出“天鹅都是白的”，突然来一只黑的，它认不出来了。解决过拟合最直观的办法是正则化，这是后面的内容。

收个尾：优点精度高、应用场景广；缺点黑箱、不适用于小数据集。这两句别背，能用自己的话讲出来，才算真懂了。
