# CNN图像分类案例

## 网络结构与形状推演

### 输入张量的真实维度

   * **输入张量（Input Tensor）**

       * > **定义**：送入网络的一批图像，形状为 `[N, C, H, W]`，依次是批大小、通道数、高、宽。

       * 架构图最左侧标注的 `[1, 32, 32]` 只表示“一张图就是一个样本”，其中的 1 不参与任何后续计算；真实输入是 `[3, 32, 32]`。

       * 彩色图像固定为三个通道，通道数 3 是卷积核深度与卷积层参数量的计算依据。

       * 图中红色卷积核只卷灰色特征堆里的一个切片，是在演示单个切片上的加权求和；底层执行时三个通道一起卷，三份结果叠加相加。

   * **隐藏层（Hidden Layer）与输出层（Output Layer）**

       * 输入层不需要搭建，手写的部分从第一个隐藏层一直到输出层。

       * 中间的卷积层与池化层统称隐藏层；最后一块本质上是全连接，但分层上归输出层。

### 卷积核与通道的对应

   * **卷积核数量（Number of Filters）**

       * 一个卷积核产出一张特征图，所以卷积核数量 = 输出通道数 = 该卷积层的“神经元个数”。

       * 第一层写成 3→6，意思是 3 个输入通道进、6 个卷积核出，输出 6 个通道。

### 尺寸计算公式

   * 输出特征图的边长由输入边长、卷积核边长、填充圈数、步长共同决定：

$$N_{out} = \left\lfloor \frac{W - F + 2P}{S} \right\rfloor + 1$$

   * $W$ 是输入边长，$F$ 是卷积核边长，$P$ 是填充圈数，$S$ 是步长，除法向下取整。

   * 第一次卷积：输入 32×32、卷积核 3×3、填充 0、步长 1，$N_{out} = (32 - 3 + 0) / 1 + 1 = 30$，所以 32 进、30 出。

   * 计算某一层的尺寸时，$W$ 取它上一层的输出尺寸，不是原始输入尺寸；第二个卷积层用 15，不是 32。

   * 第二个卷积层：$(15 - 3 + 0) / 1 + 1 = 13$；第二个池化层：$(13 - 2) / 2 + 1 = 6$。

   * 整套架构只有两条规律：凡是卷积，核 3×3、步长 1、填充 0；凡是池化，窗口 2×2、步长 2。代入公式即可逐层推完。

   * > **易错点**：除法是向下取整，不是四舍五入；$11/2$ 先把小数部分砍掉变成 5 再加 1 得 6，不是把 5.5 凑成 6 再加 1。

### 池化步长的反推

   * **池化步长（Pooling Stride）**

       * 架构图只标了窗口 2×2，没有标步长；步长由“30 列缩成 15 列”这一要求反推出来。

       * 用 4×4 小图试算：2×2 窗口、步长 1 时窗口重叠着挪，4 列能挪出 3 个位置；步长 2 时窗口互不重叠，4 列只容得下 2 个窗口。

       * 2×2 窗口配步长 2 是“列数缩一半”的唯一不重叠选择，所以池化步长取 2；公式验证 $(30 - 2) / 2 + 1 = 15$。

### 逐层形状链条

| 层 | 配置 | 输出形状 |
| :--- | :--- | :--- |
| conv1 | 3×3，3→6，步长 1，填充 0 | `[N, 6, 30, 30]` |
| pool1 | 2×2，步长 2 | `[N, 6, 15, 15]` |
| conv2 | 3×3，6→16，步长 1，填充 0 | `[N, 16, 13, 13]` |
| pool2 | 2×2，步长 2 | `[N, 16, 6, 6]` |
| reshape | 摊平 | `[N, 576]` |
| fc1 | `Linear(576, 120)` | `[N, 120]` |
| fc2 | `Linear(120, 84)` | `[N, 84]` |
| output | `Linear(84, 10)` | `[N, 10]` |

   * 通道数、分辨率、特征数各占形状中的一个位置，只有最后的 10 从头到尾不变，因为它是分类数。

   * 每经过一次卷积或池化只改变形状，不改变样本数；样本数 N 始终停留在第一维，由批次决定。

### 特征图摊平

   * **摊平（Flatten）**

       * > **定义**：把四维特征图 `[N, C, H, W]` 压成二维 `[N, C×H×W]`，让只能吃二维数据的全连接层接得住。

       * $16 \times 6 \times 6 = 576$，576 是一张图的特征向量长度，由前面的卷积池化决定，不是随手写的超参。

       * `nn.Linear` 的第一个参数只能写死 576：建层时还没有数据，但已知数据一定会被摊成 576 列；前面通道数或尺寸一改，这里必须重算。

       * 摊平没有参数、没有可学习内容，不算单独一层，直接与 `fc1` 合写成 576 进、120 出。

## 网络搭建代码

### 层类型与 API 映射

| 结构 | API | 关键参数 |
| :--- | :--- | :--- |
| 卷积层 | `nn.Conv2d` | 输入通道、输出通道（卷积核数量）、卷积核大小、步长、填充 |
| 池化层 | `nn.MaxPool2d` / `nn.AvgPool2d` | 窗口大小、步长、填充 |
| 全连接层 | `nn.Linear` | 输入维度、输出维度 |

   * 池化里最大池化 `nn.MaxPool2d` 用得最多，平均池化 `nn.AvgPool2d` 用得少。

   * 把这三类 API 一层一层往里填，网络就搭出来了，没有第四类结构。

### 层定义与超参来源

```python
class ImageModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.conv1 = nn.Conv2d(3, 6, kernel_size=3, stride=1, padding=0)
        self.pool1 = nn.MaxPool2d(2)
        self.conv2 = nn.Conv2d(6, 16, kernel_size=3, stride=1, padding=0)
        self.pool2 = nn.MaxPool2d(2)
        self.fc1 = nn.Linear(576, 120)
        self.fc2 = nn.Linear(120, 84)
        self.output = nn.Linear(84, 10)
```

   * `conv1` 的五个参数全部来自架构图读数：输入 3（三通道）、输出 6（六个卷积核）、卷积核 3×3、步长 1、填充 0。

   * `conv2` 的输入通道必须是 6，它接的是上一层的输出通道；“输入通道 = 上一层输出通道”是硬约束，写错当场报维度错。

   * `nn.MaxPool2d(2)` 只写一个 2 就够：窗口 2×2，池化步长默认等于窗口大小，填充默认 0。

   * 120 与 84 是自选超参，取决于数据集与算力；最后一层必须写 10，输出维度与类别数必须一致。

   * 最后一层命名为 `output` 而不是 `fc3`，因为它在分层上充当输出层。

### 前向传播的组成单元

   * **卷积块（Convolution Block）**

       * > **定义**：卷积、激活、池化三步串联组成的基本单元。

       * 卷积本质是加权求和，结果仍是线性的，所以接激活函数把它掰弯；最后池化降维。

       * 拆开写是 `X = self.conv1(X)`、`X = torch.relu(X)`、`X = self.pool1(X)`；合并成 `self.pool1(torch.relu(self.conv1(X)))` 效果完全相同，嵌套调用从里往外执行。

   * **前向传播（Forward Propagation）**

       * `X.reshape(X.size(0), -1)` 的第一个参数是行数，取当前 batch 的样本数；第二个参数 -1 让框架按“总元素数 ÷ 行数”自动算出 576 列。

       * 输出层直接返回 10 个原始得分，不接 softmax：`CrossEntropyLoss` 的公式内部已经包含 softmax 与损失计算，再写一遍等于算两次。

```python
def forward(self, X):
    X = self.pool1(torch.relu(self.conv1(X)))
    X = self.pool2(torch.relu(self.conv2(X)))
    X = X.reshape(X.size(0), -1)
    X = torch.relu(self.fc1(X))
    X = torch.relu(self.fc2(X))
    return self.output(X)
```

   * > **提示**：`nn.CrossEntropyLoss` = softmax + 负对数似然，模型最后一层输出不要再接 softmax，接了就重复了。

### 结构与形状自检

   * **summary 工具**

       * `summary(model, input_size=(3, 32, 32), batch_size=8)` 逐层打印输出形状与本层参数量，最后给总数。

       * 传入 `batch_size=8` 不会生效，打印出的形状仍是 `[2, 576]`，改成 1 也一样：类里没有 `batch_size` 这个量，工具自己补了一个占位批次维。

       * 真实 batch 只在训练循环里出现：外层走轮数、内层走批次，一批几条数据，这个维度就是几。

       * 在 `forward` 里 `print(X.shape)` 此时也不准，因为没有真实数据流进来；接上训练循环后才能看到 `8 × 576`。

       * 不管行数是几，列永远是 576。

## 参数量核算

### 卷积层参数

   * **卷积层参数量**

       * 公式：$\text{输入通道数} \times \text{卷积核尺寸}^{2} \times \text{卷积核数量} + \text{卷积核数量}$。

       * 前两项相乘是全部权重 $W$ 的个数，最后加的一项是偏置，每个卷积核配一个 $b$。

       * 第一层：$6 \times (3 \times 3 \times 3) + 6 = 162 + 6 = 168$。

       * 第二层：$16 \times (6 \times 3 \times 3) + 16 = 864 + 16 = 880$。

       * 卷积核尺寸要展开成 9 再乘，不是乘 3；输入通道要按真实的 3 算，不能按图上标的 1 算。

       * 卷积核数量本身是超参，改成 10 个、100 个公式照样成立，偏置跟着变成 10 份、100 份。

       * 这条公式本质还是 $Y = WX + B$：卷积核是权重的容器，靠窗口共享权重，不像全连接那样每个输入配每个输出。

### 全连接层参数

   * **全连接层参数量**

       * 公式：$(\text{上一层神经元数量} + 1) \times \text{当前层神经元数量}$。

       * 加的那个 1 是偏置 $b$：上一层每个输出都要连到本层每个神经元，最后每个神经元再配一个偏置。

       * 第一层：$(576 + 1) \times 120 = 69{,}240$。

       * 第二层：$(120 + 1) \times 84 = 10{,}164$。

       * 输出层：$(84 + 1) \times 10 = 850$。

       * 576 是列、是每行的特征数，位置就是“上一层神经元数量”；有 576 个特征就需要 576 个权重来配它。

### 池化层与总量对账

   * **池化层的参数**

       * 池化层没有参数：窗口只挑最大值或取平均，没有可学习权重，也不改变通道数，只把分辨率降下来，参数量为 0。

| 层 | 类型与规格 | 参数计算 | 参数量 |
| :--- | :--- | :--- | ---: |
| conv1 | `Conv2d(3 → 6, 3×3)` | $6 \times 3 \times 3 \times 3 + 6$ | 168 |
| pool1 | `MaxPool2d(2×2, 步长 2)` | 无参数 | 0 |
| conv2 | `Conv2d(6 → 16, 3×3)` | $16 \times 6 \times 3 \times 3 + 16$ | 880 |
| pool2 | `MaxPool2d(2×2, 步长 2)` | 无参数 | 0 |
| fc1 | `Linear(576 → 120)` | $(576+1) \times 120$ | 69,240 |
| fc2 | `Linear(120 → 84)` | $(120+1) \times 84$ | 10,164 |
| output | `Linear(84 → 10)` | $(84+1) \times 10$ | 850 |
| 合计 | | | 81,302 |

   * 168 + 880 + 69,240 + 10,164 + 850 = 81,302，与 `summary` 打出的总数一致，说明每一层的规格都没写错。

   * 值得记的是全连接那条“上一层加一乘本层”，卷积层参数量的推导背下来意义不大。

## 训练骨架与准备对象

### 建模流程

   * **建模四步**

       * 准备数据集 → 搭建神经网络 → 模型训练 → 模型测试，四步走完就得到一个能出结果的模型。

       * 这是后续所有模型的公共骨架：CNN 这么走，RNN 也这么走，区别只在第二步搭的网络不同。

       * 到 RNN 时流程会多一步构建词表：文本不能直接喂进网络，得先把词转成词向量。

### 训练与测试的函数分工

   * **train 与 evaluate**

       * `train` 只收训练数据集，`evaluate` 只收测试数据集；模型在各自函数内部创建，不从外面传。

       * `DataLoader` 写在 `for` 循环外面：整个训练只构建一次加载器，然后反复迭代它；写进循环里就是每轮重新造一个，白费功夫。

       * `main` 只剩三步：取 `train_dataset` 与 `test_dataset`、`train(train_dataset)`、`evaluate(test_dataset)`。

       * 函数不能命名为 `test`：以 test 开头的函数会被 pytest 当作测试用例收集，右键跑脚本时容易平白无故被干扰；`evaluate` 的词义也更准确。

### 训练前的对象准备

   * **数据加载器（DataLoader）**

       * `DataLoader(train_dataset, batch_size=8, shuffle=True)`。

       * `batch_size=8` 与前面看到的 `(8, 576)` 对应；改成 10，形状立刻变成 `(10, 576)`，576 是每张图固定的特征数。

       * `shuffle=True` 让每轮训练打乱顺序；不打乱时每轮喂进去的批次顺序一模一样，模型会带上顺序偏好。

   * **损失函数与优化器**

       * `criterion = nn.CrossEntropyLoss()`，多分类交叉熵，对应十分类任务。

       * `optimizer = optim.Adam(model.parameters(), lr=1e-3)`：`model.parameters()` 把模型里所有待训练的 W 和 B 交给优化器，`lr=1e-3` 就是 0.001。

       * 学习率可以写成 `1e-4`（0.0001），但学习率一小，同样效果需要更多轮，成本又上去。

       * 优化器不逐个试 `optim.SGD`，直接用 `Adam`，原因是训练成本太高。

       * `epochs = 10`：每轮约 30 秒，十轮约 5 分钟；写到 100 轮就是约 50 分钟，时间账不允许。

### 模式切换

   * **训练态与评估态**

       * 每批动作的第一句是 `model.train()`，测试侧对称写 `model.eval()`。

       * 训练态与测试态下 Dropout 行为不同：训练时随机失活一部分神经元，测试时要关掉。

       * 本案例没有使用 Dropout，切与不切结果完全一样，但这一步必须保留成习惯，否则以后加了 Dropout 会想不起来。

       * > **易错点**：`model.train()` 切的是“模式”，不是训练动作；它不会算损失，也不会更新参数，只告诉网络当前是训练态。

## 单批训练动作与统计

### 固定动作链

   * **单批训练（Training Step）**

       * 顺序固定为：切训练模式 → 前向 → 算损失 → 梯度清零 → 反向传播 → 更新参数 → 统计。

```text
model.train()                 切换训练模式
      ↓
y_pred = model(x)             前向，拿到每个类别的得分
      ↓
loss = criterion(y_pred, y)   计算损失
      ↓
optimizer.zero_grad()         梯度清零
      ↓
loss.backward()               反向传播，求梯度
      ↓
optimizer.step()              按梯度更新 W 和 B
      ↓
统计正确个数、总损失、总样本数
```

       * `model(x)` 吐出形状为 `(批大小, 类别数)` 的得分矩阵。

       * `criterion(y_pred, y)` 的参数顺序是先预测、后真实，不能反。

       * 三个优化动作顺序固定：先 `zero_grad()` 清零上一批梯度，再 `backward()` 求梯度，最后 `step()` 更新参数；不清零梯度会一批批累加、越滚越大。

       * > **易错点**：`zero_grad()` 必须写在 `backward()` 之前；顺序颠倒，这一批的梯度会叠在上一批的残留上。

### argmax 取类别

   * **argmax**

       * `torch.argmax(y_pred, dim=1)` 返回最大值所在的索引，不是最大值本身。

       * `dim=1` 沿第二个维度、也就是最后一维，在每一行内部横向比较；结果是一维张量，长度等于批大小，每个值落在 0 到 9。

       * 8 条样本进模型得到 8×10 的得分矩阵，一行十个数字是一张图在十个类别上的得分，取最大值的下标就是预测类别。

       * 得分是科学计数法：`8.9e-01` 是 0.89，`1.0e+00` 是 1.0，`2.3e-02` 是 0.023；`9e-02`（0.09）比 `1e-01`（0.1）小，不能只比小数点前的数字。

       * `(torch.argmax(y_pred, dim=1) == y)` 得到一串 True/False，`.sum()` 数出 True 的个数，就是这一批预测对了多少条。

       * > **提示**：最后一层没接 softmax，这张表严格说是每个类别的得分；argmax 只比大小、不看绝对值，直接取最大下标与先 softmax 再取下标结果完全一样。

### 三笔账

   * **批次统计（Batch Statistics）**

       * 正确个数：`total_correct += (torch.argmax(y_pred, dim=1) == y).sum()`。

       * 总损失：`total_loss += loss.item() * len(y)`；`loss.item()` 取出 Python 浮点数，`CrossEntropyLoss` 对一个批次默认求平均，必须乘本批样本数才能还原成这批的总损失。

       * 总样本数：`total_samples += len(y)`，不能写 `+= 1`；`+= 1` 数的是跑了几批，与分子的样本损失和对不上，且正确率还要拿它当分母。

       * 统一累加总损失的原因：每批条数可能不一样，最后一批常常不满；若把各批平均值相加再除以批数，大小批权重相同会失真，累加“批平均 × 批大小”再除以总样本数才是按样本加权。

   * **每轮变量**

       * `total_loss = 0.0`、`total_samples = 0`、`total_correct = 0`、`start = time.time()` 必须写在 `epoch` 循环内部，每轮开头重新赋值，这一轮才只记这一轮的账。

### 每轮输出与调试开关

   * **轮次输出**

       * 打印语句与内层 `for` 平级，不能缩进到循环体里；能执行到这一行，说明本轮所有批次都跑完了。

       * 轮数用 `epoch + 1`：`range` 从 0 开始，给人看的轮数从 1 开始。

       * 平均损失用 `total_loss / total_samples`，格式 `:.5f`；训练后期损失很小，留两位小数看不出变化。

       * 正确率用 `total_correct / total_samples`，格式 `:.2f`；耗时用 `time.time() - start`。

   * **调试开关**

       * 两个 `break`：一个在内层 `for` 末尾让每轮只跑一批，一个在打印之后让整个训练只跑一轮。

       * 两个都打开等于只喂八条数据就结束，正确率必然很低；实际训练必须注释掉，自己调试整条链路是否跑通时才可以打开。

## 模型保存与测试

### 参数字典的保存

   * **state_dict**

       * `torch.save(model.state_dict(), './model/image_model.pth')` 写在所有轮次跑完之后、函数末尾，训练全部结束才存一次。

       * `state_dict()` 存的是各层 W 和 B 的参数字典，不是模型对象本身；测试时必须先建一个结构相同的模型当壳，再把参数字典灌进去。

       * `./model` 目录必须先建出来，否则保存直接报错。

### 测试流程

   * **evaluate**

       * 动手前先把 `main` 里的 `train(...)` 注释掉，否则一运行模型又从头训一遍。

       * 测试加载器用 `shuffle=False`：测试集不需要打乱，打乱反而对不上账。

       * 先 `ImageModel()` 再 `load_state_dict(torch.load(...))`：两个函数里的模型结构必须完全一致，否则键对不上，加载直接失败。

       * `.pth` 是 pickle 格式，即 Python 专有的对象序列化存盘形式。

       * 测试不算损失，只算对错，所以整个函数里没有 `criterion`。

       * `model.eval()` 与训练里的 `model.train()` 对称；`eval` 是 `evaluate` 的前三个字母，一个是被调用的方法，一个是函数名。

   * **前向与统计**

       * `out = model(x)` 后接 `torch.argmax(out, dim=1)` 取类别，再累加正确数与样本数。

       * 打印正确率：`total_correct / total_samples`，保留两位小数。

### 训练与测试的差异

| 环节 | train | evaluate |
| :--- | :--- | :--- |
| 数据加载器 | `shuffle=True`，每轮打乱 | `shuffle=False`，顺序无所谓 |
| 模型 | 新建，参数随机初始化 | 新建后用 `load_state_dict` 装入训练好的参数 |
| 模式 | `model.train()` | `model.eval()` |
| 损失函数 | 需要，反向传播靠它 | 不需要 |
| 反向传播与参数更新 | 三步固定动作 | 没有 |
| 循环结构 | 外层 epoch、内层 batch | 只有 batch |

   * 测试相当于把训练里的“算损失、清零、反向、更新”整段删掉，换成“加载参数、切 eval、只做前向、只做统计”。

   * 两者共用的动作是建模型、取数据、前向、argmax 统计，分岔只在要不要算损失与反向更新。

### softmax 的取舍

   * 网络最后一层没接 softmax，`out` 是原始得分；训练时由 `CrossEntropyLoss` 在内部完成 softmax。

   * 测试时损失函数对象不存在，必须自己取类别；softmax 是单调的，得分越大的类概率也越大，直接取最大下标与先 softmax 再取最大下标结果一致。

   * > **提示**：测试不要补 softmax；补了也不影响 argmax 结果，只是多算一遍。真要看概率再补，只要类别 argmax 就够。

## 效果评估与调优

### 基线结果

   * 十轮训练后测试准确率 0.61；第一轮 0.39，很快到 0.5；跑到二十轮时训练集约七成、测试仍为 0.61。

   * 训练集准确率明显高于测试集，说明模型把训练集背下来了，产生了过拟合。

   * 案例代码里自带优化后的结果：测试集准确率从 0.557 提到 0.93。

### 调优方向

| 方向 | 案例里的取值 | 可以怎么改 |
| :--- | :--- | :--- |
| 增加卷积核输出通道数 | 第一层 6、第二层 16 | 例如把 6 换成 60 |
| 增加全连接层参数量 | 576、120 | 576 之后接 1000、800、600、500、300、100，一层层去测 |
| 调整学习率 | $1\times10^{-3}$ | 降到 $1\times10^{-4}$ |
| 调整优化方法 | Adam | 换成 AdaGrad |
| 调整激活函数 | ReLU | 换成 Tanh、Sigmoid |

   * 通道数就是卷积核数量，也就是神经元数量；两层卷积的通道数都偏小，往上加即可。

   * 全连接层决定模型能组合出多少种判断，参数堆得越多容量越大。

   * Adam 已经很均衡，可调空间不大；换成 AdaGrad 是走另一条思路，从学习率角度入手，不靠梯度调整。

   * 这些改动没有玄机，都是“往里边加”，代价一律是时间。

### 过拟合与正则化

   * **过拟合（Overfitting）**

       * > **定义**：训练的时候 OK、测试的时候不 OK；模型把训练集背下来了，换一批没见过的数据就露馅。

       * 判断依据很直接：训练集准确率远远高于测试集，就说明产生了过拟合。

       * 案例针对过拟合做三件事：学习率从 $1\times10^{-3}$ 改成 $1\times10^{-4}$、增加模型参数量、增加正则化。

   * **Dropout（随机失活）**

       * 案例代码里已经加了 Dropout，用随机失活缓解过拟合，丢弃概率写 $P=0.5$。

       * 数据量大时失活概率可以大一些，数据量小时要小一些，一般 $P$ 取 0.2 到 0.5。

       * 没有被随机失活的神经元按 $\frac{1}{1-P}$ 的比例缩放，把丢掉的那部分补回来。

       * 全连接层神经元数量直接加到 2048；网络越大、参数越多，训练成本与周期越高，但最终效果通常更好。

### 成本约束

   * 一轮训练约 30 秒：十轮 5 分钟，一百轮约 50 分钟；加层、加通道还会让每轮本身变慢。

   * 轮数翻十倍，等待时间就翻十倍；学习率调小后同样效果需要更多轮，成本又叠加一层。

   * 数据、算法、算力三者缺一不可：算法早写完了，为了验证行不行仍要花大量时间反复测试，算力这一关卡人。

   * 想省时间就把训练放到空闲时段跑，人走开、回来再看结果，不要坐在屏幕前干等。

### 实现路径

   * 合上代码写不出来是正常现象，代码量摆在那里；办法不是硬背代码，而是先记住流程，再一层层往下细化。

   * 先照这套基线跑通、跑对，再谈改；手上有一份能正确运行的基线，改起来才知道自己在改什么。

   * 架构可以改：加卷积层、改步长都可以，层数具体定几个要看数据集复杂度和算力，两者权衡。

   * 层数再怎么堆，思路都是同一套：先按图数层，再逐层套公式算尺寸，最后按公式把参数对一遍账。

```text
读图 → 数层 → 套公式算尺寸 → 搭层 → 写 forward → 算参数与 summary 对账
```

```text
取数据集
   ↓
创建数据加载器（只建一次，放在循环外）
   ↓
创建模型 → 创建损失函数 → 创建优化器
   ↓
遍历 epochs（外层）
   ├─ 每轮开头清账：总损失、总样本数、正确数、开始时间
   ├─ 遍历 data_loader（内层）：
   │     切 train → 前向 → 算损失 → 清零 → 反向 → 更新 → 统计三笔账
   └─ 一轮结束：打印 loss、acc、耗时
   ↓
训练全部结束：torch.save 保存 state_dict
   ↓
evaluate：建模型 → load 参数 → 切 eval → 前向 → argmax → 统计正确率
```

## 序列数据与循环神经网络

### 序列数据的判定

   * **序列数据（Sequence Data）**

       * > **定义**：后面的数据跟前边的数据有关系，就是序列数据。

       * “我爱你”三个字顺序一调，变成“爱你我”或“你爱我”，主动被动立刻反过来，说明文本前后有依赖。

       * RNN 不只处理文本：预测股票时明天的行情与今天关联，预测天气时明天的天气与今天关联，传感器、语音也都算序列数据。

       * RNN 能处理和记住前面时间步的信息，特别适用于时间序列或有时序依赖的任务。

### RNN 的分层与应用

   * **RNN 三层结构**

       * 词嵌入层 → 循环网络层 → 全连接层；词嵌入层与循环网络层理解透，文本生成案例就能做。

       * 最绕的是循环网络层：它怎么计算、API 怎么调用，需要按“两进两出”理解。

   * **应用范围**

       * 自然语言处理：文本生成、语言建模、机器翻译、情感分析。

       * 时间序列预测：股市、气象、传感器；语音先转成频谱图，变成一堆数值再做识别。

       * 音乐生成：学习音乐的时序模式生成新乐曲，词和谱都算。

### 词嵌入与词表构建

   * **词向量（Word Vector）**

       * > **定义**：用数值表示一个词的状态。

       * 词向量是一组小数，四维就是四个数，128 维就是 128 个数；实际开发不用四维，直接上 128 维，一个词生成 128 个数值。

       * 这些数值是随机初始化还是训练得到，属于词嵌入层内部的事；要抓住的是它的功能——给我一个词，我转换成向量。

   * **构建词表（Vocabulary Construction）**

       * 先用结巴分词器切词，“我爱你”切成“我”“爱”“你”，切出来的这些词构成词库。

       * 5819 行歌词切词、去重后得到 5703 个词的语料库，即 5703 个 128 维词向量。

       * 网络只认数值、不认文字，所以词嵌入这一步绕不过去；先有词、再有词向量，顺序不能反。

       * 构建词表是 RNN 流程比 CNN 多出的一步。

   * **自然语言处理（Natural Language Processing，NLP）**

       * > **定义**：用计算机算法理解自然语言。

       * 流程：文本预处理 → 词嵌入层 → 隐藏层处理。

       * 输出单元能做的任务：情感分析（判断好评还是差评）、文本分类、实体提取、翻译、主题分析。

### 循环单元的计算

   * **循环单元（Recurrent Unit）**

       * 四个量：$h_{t-1}$ 上一时刻的隐藏状态、$x_t$ 当前时刻的输入、$h_t$ 当前时刻的隐藏状态、$y_t$ 当前时刻的输出。

       * 计算分两步：先由上一隐藏状态与当前输入算出当前隐藏状态，再由当前隐藏状态算出当前输出。

$$h_t = \sigma(W h_{t-1} + V x_t + b)$$

$$y_t = \sigma(U h_t + b')$$

   * $W$ 作用于 $h_{t-1}$，$V$ 作用于 $x_t$，$U$ 作用于 $h_t$，$b$ 与 $b'$ 是偏置项，$\sigma$ 是激活函数。

   * 里面是加权求和、外面过激活函数，本质仍是以前学的神经元。

   * 循环网络层对外两进两出：输入上一时刻隐藏状态与当前时刻输入，返回当前时刻隐藏状态与当前时刻输出。

   * 第一次输入时没有上一时刻的隐藏状态，做全零初始化。

   * > **易错点**：$\sigma$ 是激活函数，大写 $\Sigma$ 是求和符号，$\partial$ 是偏导符号，三者不要混。

### 单句推演与循环的含义

   * **单句推演**

       * 第一步输入“我”，上一隐藏状态全零，基于这个“空”和“我”算出 $h_1$，再由 $h_1$ 推出下一个词是“爱”的概率并取最大。

       * 第二步把上一步推出的“爱”当作当前输入、$h_1$ 当作上一隐藏状态，算出 $h_2$，推出下一个词是“你”的概率。

       * 第三步把“你”放到输入位，结合上一隐藏状态，推它后面可能是哪个词；一个词一个词往前挪，每次都带着上一次的状态。

```text
时刻 1：输入 "我" + h0 = 0  → [ 单元 ] → h1 → 预测下一个词 "爱"
时刻 2：输入 "爱" + h1      → [ 单元 ] → h2 → 预测下一个词 "你"
时刻 3：输入 "你" + h2      → [ 单元 ] → h3 → 预测下一个词
```

   * **循环的含义**

       * 文本长度不一样，切词后词的个数也不一样，神经元个数无法写死：写三个套不上长句，写五个套不上短句。

       * 解决办法是让同一个神经元反复调用：输入一个词，结合上次状态预测下一个词；把预测出的词当作下一次输入，再结合上次隐藏状态继续推。

       * 循环的是这个单元被反复调用，不是数据绕回网络。

       * 一句话概括 RNN：不断处理输入，利用之前累积的“记忆”处理新输入，适合文本这类有先后顺序的数据。

       * 隐藏状态可以类比追剧进度：追到后面几部时，人物关系与之前剧情都在脑子里，这份“剧情推进到哪了”就是一路攒下来的隐藏状态；第一次输入没有前情，所以全零。
