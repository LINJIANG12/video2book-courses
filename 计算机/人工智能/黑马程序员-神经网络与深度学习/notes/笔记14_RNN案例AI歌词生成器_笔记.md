# RNN案例：AI歌词生成器

## 案例骨架与数据流

* **AI 歌词生成器（Lyrics Generator，AIGC）**

    * > **定义**：用周杰伦歌词训练一个字符级 RNN，给定起始词与生成长度，逐词续写出歌词文本。

    * 案例定位是建立对 RNN 的初步印象，不作为 RNN 的完整展开；后续还有大量序列建模内容。

    * 输入由起始词与生成长度两项构成，输出是以起始词开头的歌词序列。

* **六步程序骨架**

    * 获取数据、分词、构建词表。

    * 数据预处理，构建滑动窗口数据集。

    * 搭建 RNN 神经网络。

    * 模型训练。

    * 模型预测。

    * 另设 main 入口作为第六步测试，初版先写 `pass` 占位。

* **语料规格**

    * 歌词文本共 5819 行，放在项目 `data` 目录下。

    * 按词统计的数量多于 5819 行：一行歌词含空格，分词会把它切成多个词。

    * 去重后共 5703 个词，索引范围 0～5702。

* **依赖分工**

    * `torch` 负责张量计算，`jieba` 负责中文分词。

    * `DataLoader` 负责分批，`Dataset` 是自定义数据集的基类。

    * `nn` 提供网络层，`optim` 提供优化器，`time` 用于计时。

* **数据流**

    ```text
    data/杰伦lyrics（5819 行）
            │  逐行读 + jieba 分词
            ▼
    all_words（列表套列表：一行一个子列表）
            │  去重
            ▼
    unique_words（5703 个词）
            │  enumerate 建映射
            ▼
    word_to_index（词 → 索引）
            │  每行换成索引，行尾补空格索引 40
            ▼
    corpus_index（一整条编号长龙）
            │  五个一窗，输出整体右移一位
            ▼
    (X, Y) 成对样本 → DataLoader → RNN
    ```

    * 前半段把文本压成编号，后半段把编号喂给网络；词表是中间的关口，模型只认识数字。

    * 编号仍是中间产物，进入网络前每个编号还要映射成词向量。

## 词表构建

### 分词与去重

* **build_vocab**

    * > **定义**：把整份歌词转成「去重词列表、词到索引映射、去重词数、全文索引序列」四份产物。

    * 读取用 `open(..., 'r', encoding='utf-8')`：`r` 表示读，`encoding` 指定码表。

    * 分词用 `jieba.lcut(line)`，返回该行的词列表。

* **两个容器**

    * `unique_words` 存去重后的词，回答「一共有多少种词」。

    * `all_words` 按行存每句分词结果，用来按原顺序把歌词换成索引。

    * `all_words` 是列表套列表：内层是一句话的词，外层是所有句子。

* **分词细节**

    * 不调用 `strip` 时换行符会粘在行末词上，例如 `'直升机\n'`。

    * 这个现象说明「一行」在切词之后没有独立标记。

    * 打印只为确认切词结果，确认后即删除。

* **去重规则**

    * 判断 `word not in unique_words` 才 `append`。

    * `word_count = len(unique_words)` 得 5703，统计的是「多少种词」而非「一共多少个词」。

    * 同一个词出现一百次只算一个。

### 索引化与句尾标记

* **word_to_index**

    * `{word: i for i, word in enumerate(unique_words)}`：词作键、索引作值。

    * 反向写成 `{i: word}` 是「拿索引查词」，与「拿词查编号」的需求相反，键必须是词。

    * 编号从 0 到 5702；5703 个词从 0 起数，末位自然是 5702。

* **全文索引化**

    * 逐行新建 `temp` 装本行索引，内层循环 `temp.append(word_to_index[word])`。

    * 行尾执行 `temp.append(word_to_index[' '])`，空格在词表中索引为 40，作为一句的结束标记。

    * `corpus_index.extend(temp)` 把本行摊平接入整条序列。

    * 返回四样：`unique_words`、`word_to_index`、`word_count`、`corpus_index`；最后一项是下一步的原料。

* **append 与 extend**

    | 方法 | 结果 | 形态 |
    | :--- | :--- | :--- |
    | `append` | `[[0, 1, 2, 40], [3, 4, 5, 40]]` | 列表套列表，整行当一个元素 |
    | `extend` | `[0, 1, 2, 40, 3, 4, 5, 40]` | 摊平成一条连续长龙 |

    * RNN 要连续序列，必须用 `extend`；用 `append` 得到的是一堆句子，句子里才是编号。

    * > **易错点**：`append` 把整个列表当一个元素塞进去，`extend` 把列表里的元素逐个接上去。

    * > **提示**：40 不是行号也不是长度，而是「空格」这个词在词表里的索引。

* **两个 word_count**

    * 词表口径 `5703`：去重后的词种类数。

    * 序列口径 `len(corpus_index)`：全文词的总个数，不去重。

    * > **易错点**：两个同名字段含义完全不同，按去重值算窗口数会全错。

## 滑动窗口数据集

### 自定义数据集的动因

* **TensorDataset 的局限**

    * 前提是「第 i 条就是第 i 条」的独立样本。

    * RNN 学的是「给定前面的词，下一个词是什么」，样本必须成对：给 0 预测 1、给 1 预测 2。

    * 窗口大小、起点、终止位置 `TensorDataset` 都管不了，只能自定义继承 `Dataset` 的类。

* **窗口化的动机**

    * 一个词一个词地喂能训，但每步只挪一个词，速度太慢。

    * 改为连续五个编号作输入，让模型一次预测接下来的五个。

    * 样本要在一条长序列上按固定步长滑出，不能从数据里随便切。

### 窗口切分规则

* **红框与蓝框**

    ```text
    编号长龙:  0   1   2   3   40  0   4   ...
    红框输入: [0   1   2   3   40]
    蓝框输出:     [1   2   3   40  0]
    ```

    * 红框是模型看得到的上下文，蓝框是要预测的答案。

    * 蓝框整体比红框右移一位，每一位对着红框的下一位。

    * 两个框长度相同，差别只在起点；红框的终点必须给蓝框留出一位。

* **滑动过程**

    ```text
    第 1 次: X = [0, 1, 2, 3, 40]   Y = [1, 2, 3, 40, 0]
    第 2 次: X = [1, 2, 3, 40, 0]   Y = [2, 3, 40, 0, 4]
    ```

    * 每右移一位，红框丢掉最左一个词、右边补进一个新词，蓝框同步。

    * 红框不能取到最后一个元素，最多落在倒数第二个位置；蓝框可以取到最后一个元素。

### Dataset 实现

* **三个魔法方法**

    * 创建对象自动调 `__init__`，`len()` 自动调 `__len__`，`对象[索引]` 自动调 `__getitem__`。

    * 三者写对，`DataLoader` 就能像内置数据集一样使用它。

* **初始化**

    * 入参为整条索引长龙和每个窗口的词数 `number_chars`。

    * `self.word_count = len(self.corpus_index)` 统计全文词数，不去重。

    * `self.num_samples = self.word_count // self.number_chars`，整除，末尾不足一个窗口的词舍掉。

    * 例：全文 100 词、窗口 5，得到 20 个样本。

* **长度**

    * `__len__` 只回答「有多少个样本」。

    * 数量在初始化时已经算好，不用每次现数。

* **取样本**

    * `start = min(max(index, 0), self.word_count - self.number_chars - 1)` 修正起始索引。

    * 下界 `max(index, 0)` 把负数压成 0，避免正索引与负索引混用。

    * 上界 `word_count - number_chars - 1`：全文 100 词、窗口 5 时 `start` 最多到 94。

    * `start = 95` 时输出要取 96～100，100 已越界；减掉的 1 就是给蓝框留的最后一位。

    * `end = start + number_chars`，`X = corpus_index[start:end]`，`Y = corpus_index[start+1:end+1]`。

    * 切片包左不包右，`start=0、end=5` 正好取到 0～4 五个元素，所以 `end` 直接加五即可。

    * 返回 `torch.tensor(X), torch.tensor(Y)`，转成张量后 `DataLoader` 组出的 batch 才能直接进模型。

    * > **易错点**：上界的 `- 1` 不能省，少减这个 1 最后一个窗口的输出切片就会越界。

* **样本实况**

    | 变量 | 切片写法 | `start = 0` 时拿到的索引 |
    | :--- | :--- | :--- |
    | `X`（输入） | `corpus_index[start:end]` | 0、1、2、3、4 |
    | `Y`（目标） | `corpus_index[start+1:end+1]` | 1、2、3、4、5 |

    * `LyricsDataset(corpus_index, 5)` 的 `len` 为 9827。

    * 5819 行歌词切词后每行不止一个词，再按五词一窗切分，样本数必然多于行数。

    * `dataset[0]` 得 `X=[0, 1, 2, 3, 40]`、`Y=[1, 2, 3, 40, 0]`。

    * `dataset[1]` 得 `X=[1, 2, 3, 40, 0]`、`Y=[2, 3, 40, 0, 4]`。

    * `index` 是窗口在长龙上的起始位置，不是样本序号；相邻样本共享四个词。

## 网络结构

### 三层定义

* **TextGenerator**

    * 继承 `nn.Module`，`__init__(self, unique_word_count)` 内先执行 `super().__init__()`。

    * 三层顺序为词嵌入层、循环网络层、输出全连接层，`forward` 负责维度转换。

    * 去重词数 5703 被两层用到：嵌入层的词表规模与输出层的类别数。

* **词嵌入层**

    * `self.ebd = nn.Embedding(unique_word_count, 128)`：5703 个词，每个词 128 维向量。

    * 第二个参数是词向量维度，4、5、6 维也能跑。

    * 维度越大词向量相对越精准，计算量同步变大，128 是精度与开销的折中。

* **循环网络层**

    * `self.rnn = nn.RNN(128, 256, 1)`：输入维度 128、隐藏层维度 256、层数 1。

    * 输入维度必须与嵌入层输出维度一致，RNN 收到的输入就是词向量。

    * 隐藏层维度决定记录多少信息，越大记得越多。

    * 层数 1 只记最后一项信息；层数 2 再叠一层、做一次深加工；一般给 1。

    * > **易错点**：层数是纵向堆叠的 RNN 层数，不是句子长度也不是时间步数；时间维是 `forward` 里的 `seq_len`。

* **输出层**

    * `self.out = nn.Linear(256, unique_word_count)`：256 维特征映射到词表大小。

    * 输出宽度必须等于词表大小，因为要给出每个词的概率打分，再取最大者作预测。

    * 第一个参数必须与隐藏层维度一致。

### 隐藏状态与参数核对

* **init_hidden**

    * `return torch.zeros(1, bs, 256)`：三位分别是层数、批大小、隐藏层维度。

    * `256` 来自 `nn.RNN` 第二个参数，`1` 是层数，两者都要与网络定义一致。

    * `forward` 由框架自动调用，`init_hidden` 不会自动调用，必须手动调。

    * 不封装成方法也能在训练前直接写 `torch.zeros`，但初始化逻辑应归到搭建阶段，结构上更合理。

* **参数核对**

    | 参数名 | 形状 | 对应部件 |
    | :--- | :--- | :--- |
    | `ebd.weight` | `(5703, 128)` | 词嵌入表 |
    | `rnn.weight_ih_l0` | `(256, 128)` | 输入到隐藏层的权重 |
    | `rnn.weight_hh_l0` | `(256, 256)` | 隐藏层到隐藏层的权重 |
    | `rnn.bias_ih_l0` | `(256,)` | 输入那一路的偏置 |
    | `rnn.bias_hh_l0` | `(256,)` | 隐藏那一路的偏置 |
    | `out.weight` | `(5703, 256)` | 特征映射到词表打分 |
    | `out.bias` | `(5703,)` | 每个词一个偏置 |

    * 用 `model.named_parameters()` 遍历 `name, param` 打印 `param.shape` 即可核对。

    * 形状全对上说明三层参数没传错；传错一个数模型照样能建出来，但结构已不是要的那个。

    * `forward` 里的 `print` 在建对象时不执行，只有模型被调用、训练跑起来才执行。

## 前向传播

### 形状链

* **一次前向的形状变化**

    ```text
    input                (batch, seq_len)
       |
       |  Embedding(5703, 128)
       v
    embed                (batch, seq_len, 128)
       |
       |  transpose(0, 1)
       v
    embed                (seq_len, batch, 128)
       |
       |  RNN(128, 256, 1)   +  hidden (1, batch, 256)
       v
    output               (seq_len, batch, 256)
       |
       |  reshape(-1, 256)
       v
    output               (seq_len * batch, 256)
       |
       |  Linear(256, 5703)
       v
    output               (seq_len * batch, 5703)
    ```

    * 最后一维从词下标变 128，前两维对调一次，128 变 256，三维压二维，256 变 5703。

* **嵌入**

    * `embed = self.ebd(input)`：`(batch, seq_len)` → `(batch, seq_len, 128)`。

    * 句子还是那些句子，只是每个词的位置换成一个向量。

### 维度交换与展平

* **transpose**

    * `embed = embed.transpose(0, 1)`：`(batch, seq_len, 128)` → `(seq_len, batch, 128)`。

    * `nn.RNN` 默认输入是 `(seq_len, batch, input_size)`，隐藏状态是 `(num_layers, batch, hidden_size)`，batch 固定在第二维。

    * 不换位直接喂进去维度对不上，后面全乱。

    * > **易错点**：`seq_len` 是每个句子的词数，batch 是这一批句子的条数；进 RNN 时长度在前、条数在后，与嵌入层刚出来的顺序相反。

* **RNN 输出**

    * `output, hidden = self.rnn(embed, hidden)`。

    * `output` 是每个时间步的输出，形状 `(seq_len, batch, 256)`。

    * `hidden` 是这一轮跑完的隐藏状态，形状 `(1, batch, 256)`，留给下一轮。

* **展平与输出层**

    * `nn.Linear` 只能处理二维数据，三维的 `output` 必须先摊平。

    * `output.reshape(-1, output.shape[-1])`：`-1` 交给 PyTorch 自动计算，`output.shape[-1]` 取 256。

    * `(seq_len, batch, 256)` → `(seq_len × batch, 256)`，行数是「句子长度 × 批大小」，列数是 256。

    * 过 `self.out` 后为 `(seq_len × batch, 5703)`，每个位置一行 5703 个打分。

    * 返回 `output, hidden`：`output` 是每个位置对每个词的打分，`hidden` 供下一轮迭代。

## 训练流程

### 任务判定与准备工作

* **多分类判定**

    * 输出不是「是/否」两个打分，而是词表 5703 个词各自的概率，属多分类。

    * 损失函数用多分类交叉熵 `nn.CrossEntropyLoss()`。

* **优化器**

    * `torch.optim.Adam(model.parameters(), lr=0.01)`，`model.parameters()` 不能漏。

    * `betas` 默认 `(0.9, 0.999)` 是源码默认值，不用再传。

    * 一阶矩决定往哪个方向走、走多快，二阶矩决定步子放多大。

* **准备工作**

    * `train` 不带参数，`main` 内只写 `train()`，所有准备在函数内部重做一遍。

    * `unique_word_count = build_word_count()` 得到词到索引的字典，命名加 `unique` 前缀强调是去重词表。

    * `lyrics_dataset` 由整段歌词的索引序列构建，窗口词数由 `number_chars` 指定。

    * `model = TextGenerator(len(unique_word_count))` 传词表大小，不能传词表本身。

    * 5703 必须与模型输出类别数严格相等，差一个交叉熵就对不上。

* **DataLoader 参数**

    | 参数 | 值 | 含义 |
    | :--- | :--- | :--- |
    | `dataset` | `lyrics_dataset` | 按索引吐出 `x, y` 的数据集对象 |
    | `batch_size` | `5` | 每批取 5 个样本，即 5 个句子 |
    | `shuffle` | `True` | 每轮开始前随机打乱顺序 |

    * 一批 `x` 形状为 `(5, 32)`：`batch_size` 5 乘 `number_chars` 32。

    * `number_chars` 是每个句子里词的个数，定义在 `LyricsDataset` 的注释里。

    * 两个值前期都别取太大：能切出的句子变少，迭代次数变少，模型练不透。

    * 经验取法是从小往大试，优先 2 的幂：8、16、32、64。

### 单批训练

* **循环骨架**

    ```text
    for epoch in range(epochs)              <- 第几轮
        start / iterator_num / total_loss   <- 每轮开头重置
        for x, y in lyrics_dataloader       <- 本轮的第几批
            hidden = model.init_hidden(5)
            output, hidden = model(x, hidden)
            y = y.transpose(0, 1).reshape(-1)
            loss = criterion(...)
            zero_grad / backward / step
            total_loss += loss.item()
            iterator_num += 1
        print(本轮信息)                      <- 每轮一次
    save(model.state_dict())                <- 全部结束一次
    ```

    * 缩进层级决定谁在谁里面、执行几次。

    * 每轮开头重置 `start = time.time()`、`iterator_num = 0`、`total_loss = 0.0`。

    * `epochs = 10`，轮数越多越好，十轮先看个大概。

    * 循环变量在循环体内不使用时可写 `for _ in range(epochs)`；这里要打印 `epoch + 1`，保留变量名。

* **隐藏状态**

    * `hidden = model.init_hidden(5)`：每批重置为全零。

    * 一批是独立的 5 个句子，与上一批没有先后关系，起点必须是全零。

    * 写死 `torch.zeros(1, 5, 256)` 也能跑，但批大小和记忆维度一改就要跟着改，所以封装进模型。

    * 封装把归属分清：批大小属于训练数据，记忆维度属于模型结构。

* **前向与标签对齐**

    * `output, hidden = model(x, hidden)`：`output` 是每个位置对 5703 个词的打分，`hidden` 是更新后的记忆。

    * `y = y.transpose(0, 1).reshape(-1)`：`(batch=5, seq=32)` → `(32, 5)` → `(160,)`。

    * `output` 原生为 `(seq=32, batch=5, vocab=5703)`，`reshape(-1, 5703)` 后为 `(160, 5703)`。

    * 交叉熵要「一行一个位置、每行 5703 个打分」；两边前两维都摊成 160，第 $i$ 行打分与第 $i$ 个真实编号必须指同一位置。

    * 口诀：谁的批次在前，谁就要被换到后面去；`y` 批次在前所以要转，`output` 天生批次在后不用动。

    * > **易错点**：漏掉 `transpose` 不报错、损失照样算得出来，因为 160 个数字个数没变；但标签与位置全部错位，模型学到的是错配关系，形状对得上不等于语义对得上。

* **三行固定动作**

    * `optimizer.zero_grad()` 清零梯度，不清零会把上一批残留梯度累加进来。

    * `loss.backward()` 反向传播求梯度，`optimizer.step()` 按梯度更新参数。

    * `total_loss += loss.item()` 取普通浮点数累加，避免把整条计算图留在内存里。

    * `iterator_num += 1` 记批次数，供求本轮平均。

### 收尾与报错定位

* **打印**

    * 每轮结束打印 `f'第{epoch + 1}轮, 耗时{time.time() - start:.2f}s, 平均损失{total_loss / iterator_num:.4f}'`。

    * 该语句与内层 `for` 平级、在外层 `for` 里面，所以每轮执行一次而非每批一次。

    * 判断代码层级可把上一层折叠掉，看它跟谁对齐。

* **保存**

    * 十轮跑完执行 `torch.save(model.state_dict(), './model/text_generator.pth')`，在两层循环之外，只执行一次。

    * `state_dict()` 只存参数字典，不含网络结构。

    * 测试时必须先用代码重建同样结构，再把参数灌进去。

* **报错定位**

    * 典型报错 `AttributeError: module 'torch' has no attribute 'zero'`，原因是 `torch.zeros` 少写一个 `s`。

    * 调用栈路径：`train()` → `hidden = model.init_hidden(5)` → `torch.zero(...)`。

    * 顺着调用栈逐层点进控制台异常信息定位真正出错的行，不要从第一行通读两百多行代码。

## 训练效果与调参

### 损失震荡

* **损失口径**

    * 每轮打印 `total_loss / iterator_num`，两个变量都在 `for epoch` 内、每轮清零，只反映本轮情况。

    * `shuffle=True` 每轮打乱批次顺序，每轮见到的组合不同，浮动正常。

    * > **提示**：震荡不是 bug，是统计口径问题；先确认算的是哪种平均，再判断该不该降。

* **变量位置与曲线**

    | 变量位置 | 生命周期 | 反映什么 | 曲线形态 |
    | :--- | :--- | :--- | :--- |
    | `for epoch` 内 | 每轮清零 | 本轮平均损失 | 上下震荡 |
    | `for epoch` 外 | 全程累加 | 至今平均损失 | 平滑下降 |

    * 把三个变量提到 `for epoch` 外可得到全程平均，曲线越来越平稳地下降。

    * 判断曲线形态前先看变量写在哪一层，写在里面算本轮平均、写在外面算至今平均。

### 复读机与调参

* **复读机表现**

    * 十轮、`lr=0.01` 时，「相思寄红豆无能为力」重复出现。

    * 换起始词「分手」后，后半句跑到「娘子」并来回打转。

* **三条成因**

    * 每次喂给模型的句子太长：`number_chars=32`，一个样本 32 个词，能切出的句子少、迭代次数少、训练不足。

    * 学习率太大：`lr=0.01` 即 $10^{-2}$，对 Adam 是偏激进的步长，常用量级为 $10^{-3}$；步长过大会在最优点附近横跳，细节学不进去。

    * 轮数太少：十轮只是看效果的量级，真要有样子需要 50、100 甚至上千轮。

* **三处调整**

    | 参数 | 原值 | 调整后 | 作用 |
    | :--- | :--- | :--- | :--- |
    | 学习率 | `0.01` | `0.001` | 减小步长，避开最优点附近震荡 |
    | 轮数 | `10` | `50` | 增加训练量 |
    | `number_chars` | `32` | `5`（可选） | 缩短窗口，增加可切样本与迭代次数 |

    * 十轮时一轮约六秒，总共一分钟左右；五十轮时一轮约五秒，总共约五分钟。

    * 调参后「分手」开头的输出有断句、有转折、有收尾，明显更像歌词。

* **贪心解码的表现**

    * 生成时每一步取打分最大的词，起始词相同则前几个词必然复现。

    * 十轮与五十轮的开头几句可能一模一样，差异只出现在模型拿不准的位置。

    * 看效果不能只读第一句，要往后读。

    * 继续堆到几千轮还能提升，50 轮五分钟，几千轮就是几个小时。

## 歌词生成

### 生成循环

* **三步链路**

    ```text
    "星星"
       |
       |  word_to_index["星星"]        <- 第一步：词找编号
       v
      89
       |
       |  model(torch.tensor([[89]]), hidden)
       v
    output  (1, 1, 5703)
       |
       |  argmax                     <- 第二步：在 5703 个打分里取最大的位置
       v
      40
       |
       |  unique_words[40]            <- 第三步：编号找回词
       v
    "的"
       |
       +---- 把 40 当成下一步的输入，回到最上面
    ```

    * 词找编号、编号进模型取最大、编号回词表取词，三步滚一轮生成一个词。

    * 生成 50 个词就是 50 次前向，一次都不能省。

* **evaluate 准备**

    * 定义 `def evaluate(start_word, sentence_length)`，调用如 `evaluate('星星', 50)`。

    * 词典必须重新构建，编号要与训练时完全一致；第 89 号换了词，模型等于白训。

    * `unique_words = list(unique_word_count.keys())` 把词表字典的键按索引顺序取成列表。

    * `model = TextGenerator(len(unique_words))` 先建结构，再 `model.load_state_dict(torch.load('./model/text_generator.pth'))` 灌参数。

    * `hidden = model.init_hidden(1)`，批大小为 1，一次只生成一句话。

* **逐词循环**

    * `word_index = word_to_index[start_word]` 取起始词编号。

    * `generate_sentence = [word_index]` 先放起始词，保证输出以它开头。

    * `output, hidden = model(torch.tensor([[word_index]]), hidden)` 前向一次。

    * 输入必须是二维 `(seq_len, batch)` 即 `(1, 1)`，两层方括号缺一不可；少一层会退化成一维，RNN 按「一个批次里有若干词」解释。

    * `word_index = torch.argmax(output).item()` 取打分最大的位置；`output` 形状 `(1, 1, 5703)`，前两维为 1，展平下标等于词表下标。

    * `generate_sentence.append(word_index)` 记下并作为下一轮输入。

### 状态传递与还原

* **训练与生成的状态差异**

    | 场景 | `hidden` 处理 | 原因 |
    | :--- | :--- | :--- |
    | 训练 | 每批重置为全零 | 一批是独立样本，与上一批无先后关系 |
    | 生成 | 一路传递不重置 | 一句话是连续过程，后面的词要用前面的记忆 |

    * 生成时 `hidden` 既传入又接回，记忆在循环里连续传递。

* **无需 softmax**

    * 训练用的交叉熵内部已含 `log_softmax`，模型最后一层直接输出原始打分。

    * softmax 是单调变换，取最大值与取 softmax 后的最大值是同一个位置。

    * 只要「谁最大」，直接 `argmax` 就够。

* **索引还原**

    * `for index in generate_sentence: print(unique_words[index], end='')`。

    * 用 `unique_words[index]` 而不是 `word_to_index`：后者键是词、值是编号，只能由词查号。

    * 字典没有「按值找键」的动作，按编号取词必须用按索引排好序的列表。

    * `end=''` 让词与词首尾相接，不换行不补空格，模型的标点与断句才能原样还原。

* **词表外输入**

    * 输入「憨哥」「AI」「夯」这类词表外的词，查表时抛 `KeyError`。

    * 模型输出的是词表内 5703 个词的概率分布，没有「词表外」概念。

    * 一个字的起始词可用，只要它在 5703 个词之内。

    * 要让新词可作起始词，必须让它进入词表，那是另一件事。

* **使用方式**

    * `train()` 跑一次后注释掉，以后只改起始词跑 `evaluate`，避免每换一个词就重训。

    * 整个案例归结为四步：构建词汇表、构建数据对象、编写网络模型、训练与测试。

    * 真正卡住人的是编写网络模型，难点集中在维度转换；参数与形状想通后其余是填空题。
