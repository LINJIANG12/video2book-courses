# 学习率策略与正则化

## 学习率衰减策略

### 等间隔衰减

* **等间隔衰减**

    * > **定义**：每隔一个固定轮数就把当前学习率乘一次衰减系数 $\gamma$，间隔数由人给定。

    * 用法举例：训练 50 轮调一次学习率，再训练 50 轮再调一次。

    * 间隔填 10，每十轮调整一次，节奏还算可以；间隔一旦填到 50，调整次数太少，学习率在很长时间里纹丝不动。

    * 等间隔与指定间隔共用同一个调整式 $LR_{new} = LR \times \gamma$，换掉的只是 API，训练循环、优化器、日志都不用动。

    * 局限：只会按同一个间隔、同一个比例一路均匀地乘下去，前期和后期在时间轴上没有任何区别，做不到「前期降得快、后期降得慢」。

    * 行为边界：「什么时候降」被间隔数锁死，衰减时刻不能自己指定。

    * 收益与代价：直观、易于调试、适用于大批量数据；学习率变化幅度较大，可能一步跳过最优解。

    * 适用：大型数据集、较简单的任务。

    * 与之对应的调度器类名长文未给出，只给了 `MultiStepLR` 与 `ExponentialLR` 两个接口。

### 指定间隔衰减

* **指定间隔衰减（MultiStepLR）**

    * > **定义**：把要做衰减的轮次逐项写进 `milestones` 名单，训练到名单里的轮数就衰减一次，其余轮数不动。

    * 比分间隔多出来的参数只有 `milestones`；名单按从小到大排，写几项就衰减几次。

    * 定参方式：台阶位置给 `milestones`，每级乘的倍数给 `gamma`。台阶落在 50、125、160 轮，学习率 0.1、0.05、0.025、0.0125 依次减半，于是 `gamma = 0.5`。

    * 名单可以排得不规整，写成 10、20、50、90、125、145，想在哪一轮降就在哪一轮降。

    * 轮数的来源：为什么第 20 轮要降、第 22 轮和第 23 轮不降，没有公式能推，来自实际工作中大量跑代码、反复测试得出的经验结论；50、125、160 本质上是照着目标曲线随手写的一组值，真到项目里得自己试。

    * 收益与代价：易于调试、训练过程稳定；名单不合理时衰减过快，优化提前停滞。

    * 适用：对训练平稳性要求较高的任务。

    * > **易错点**：凭感觉把名单写成 50、100、150，与目标曲线的台阶对不上；指定间隔所谓「不稳定」不是策略本身带来的，而是名单填错造成的。

```text
lr
0.100 |#########
      |         |
0.050 |         |#########
      |         |         |
0.025 |         |         |#########
      |         |         |         |
0.0125|         |         |         |#########
      +---------+---------+---------+-----> epoch
      0         50        125       160
```

```python
milestones = [50, 125, 160]  # 在这些轮数上各衰减一次
scheduler = optim.lr_scheduler.MultiStepLR(
    optimizer,
    milestones=milestones,
    gamma=0.5,
)
```

### 指数衰减

* **指数衰减（ExponentialLR）**

    * > **定义**：把轮数搬进指数位，学习率按 $LR_{new} = LR \times \gamma^{epoch}$ 逐轮衰减。

    * 幂的作用：初始学习率 0.1、$\gamma = 0.5$ 时，第一轮是 $0.1 \times 0.5^1$，第二轮是 $0.1 \times 0.5^2$，往后是三次方、四次方、五次方；幂每加一，学习率就更小一圈。

    * 关键约束：$\gamma$ 在指数位上，绝不能像等间隔、指定间隔那样取 0.5；取 0.1 时 $0.1^2=0.01$、$0.1^3=0.001$、$0.1^4=0.0001$，几步就掉到 $0.000001$，模型还没学到东西就停摆。

    * 取值：一般取 0.9 几，比如 0.95，量级上与动量法、Adam 里的 $\beta$ 差不多。

    * 曲线形状：前期衰减快、中期慢下来、后期更慢，比较符合梯度下降的规律，三种手动策略里相对用得多。

    * 收益与代价：平滑、考虑历史更新、收敛稳定性较强；超参调节较复杂、需要更多资源。

    * 适用：高精度、需要避免过快收敛的任务。

    * 实现复杂度在三者中最高：每次都要额外算一步，把当前 epoch 代进指数位。

```python
scheduler = optim.lr_scheduler.ExponentialLR(optimizer, gamma=0.95)
```

### 三种策略的取舍

| 策略 | 衰减方式 | 实现难度 | 优点 | 缺点 | 适用场景 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 等间隔 | 固定步长 | 最低 | 直观、易于调试、适用于大批量数据 | 学习率变化幅度较大，可能跳过最优解 | 大型数据集、较简单的任务 |
| 指定间隔 | 指定步长 | 中等 | 易于调试、训练过程稳定 | 名单不合理时衰减过快，优化提前停滞 | 对训练平稳性要求较高的任务 |
| 指数 | 平滑衰减 | 较高 | 平滑、考虑历史更新、收敛稳定性较强 | 超参调节较复杂、需要更多资源 | 高精度、需要避免过快收敛的任务 |

* **实现难度差异的来源**

    * 等间隔最简单，扔一个 10、一个 20 进去就不用管，到点它自己转。

    * 指定间隔稍微难一点，得算清楚为什么这一轮要换、其他轮不换。

    * 指数最麻烦，每次都要把当前 epoch 代进指数位多算一步。

* **实际使用频率**

    * 这三种方式将来实际开发里用得都不多，用得最多的是 Adam（让公式自动调学习率），其次是 SGD 和动量法。

    * 学它们的用处：别人代码里写了 `MultiStepLR`、`ExponentialLR` 得看得懂；万一要求「必须在第多少轮调学习率」，手里得有这几种工具。

## 正则化与过拟合

### 三种拟合状态

| 状态 | 训练集表现 | 测试集表现 | 主要原因 | 处理方向 |
| :--- | :--- | :--- | :--- | :--- |
| 欠拟合 | 差 | 差 | 模型过于简单 | 增加模型复杂度、增加数据量、增加特征数 |
| 正好拟合 | 好 | 好 | 容量与任务匹配 | 保持 |
| 过拟合 | 好 | 差 | 模型过于复杂、学到无关特征 | 正则化 |

* **过拟合（overfitting）**

    * > **定义**：训练集表现很好、测试集表现很差，根子在模型过于复杂，学到了与任务无关的「脏」特征。

    * 典型例子：训练识别天鹅的模型，喂一万张全是白天鹅的图片，模型很可能学出「天鹅都是白的」这条规则，飞来一只黑天鹅就认不出来——它学到的不是天鹅的本质特征，而是训练集里碰巧一直成立的颜色。

    * 与数据量的关系：样本少，模型见到的偶然多，更容易把偶然当规律；拿 KNN 的 K 值类比，K 越小模型越复杂越容易过拟合，K 越大模型越简单越容易欠拟合。

* **欠拟合（underfitting）**

    * > **定义**：训练集与测试集表现都差，根子在模型过于简单。

    * 对策：让模型复杂一点、增加数据集、增加特征数。

* **正好拟合**

    * 训练集也 OK、测试集也不错，容量与任务匹配，这是想要的状态，保持即可。

### 正则化的三条路线

| 方式 | 对权重做什么 | 达到的效果 |
| :--- | :--- | :--- |
| L1 正则化 | 权重可以被压到 0 | 某些特征被彻底摘掉，相当于做了一次降维 |
| L2 正则化 | 权重无限接近 0，但不会等于 0 | 把权重整体压小 |
| 随机失活（dropout） | 每次、每批次训练时随机让一部分神经元「死亡」 | 防止某些特征对结果的影响过大 |

* **正则化（regularization）**

    * > **定义**：很多机器学习算法用来减少测试误差的一类策略的统称；在深度学习里，它的目标是避免或压低过拟合。

    * 深度学习的表示能力很强，强到经常把训练集背下来，所以过拟合在深度学习里是常态，必须用不同的策略去压。

    * 主流三类：范数惩罚（L1 范数、L2 范数）、随机失活（dropout）、特殊网络层（如 BN 批量归一化）。

    * > **易错点**：正则化只能降低、缓解过拟合，不能说「防止」——它解决不了过拟合。

* **L1 与 L2 的差别**

    * L1 能把权重真的变成 0，一部分权重直接消失，权重矩阵变稀疏，效果上相当于降维。

    * L2 只能让权重无限趋近 0，永远留着一点点尾巴，权重整体被压小但结构不动。

* **BN 与前三者的关系**

    * 前三者动的是权重和神经元的存活，BN 动的是数据本身的分布，不是同一个路数。

## 随机失活

### 机理

* **随机失活（dropout）**

    * > **定义**：训练过程中让神经元以超参 $P$ 的概率停止工作、激活被重置为零，没被清零的那部分按 $1/(1-P)$ 的比例缩放。

    * 针对的场景：神经网络里参数很多，但数据量不足；参数多、数据少，模型就会去背训练集的细节。

    * 子网络：某一层只有五个神经元，第一批活 1、4、5，第二批活 1、3、5，第三批活 2、4、5，每批死掉的都不一样，留下的神经元组成一个更小的子网络。

    * 底层逻辑：本来五个神经元只能凑一次完整的训练，现在按不同的失活组合，可以凑出 1-4-5、1-3-5、2-4-5、3-4-5 这样一组一组的子网络，每一批只更新当前这个子网络的参数——数据一个数都没改，可训练的组合数量被放大了。

    * 等价描述：训练过程就是对完整神经网络的一些子集做训练，每次基于输入数据只更新子网络的参数。

    * 防过拟合的方式：网络不能依赖某几个特别强势的特征，这次靠它、下次它可能被关掉，只能学着用更分散、更冗余的证据去做判断。

    * 生活类比：五个人算平均年龄，五个人一起算只能算一次；随机挑两个、三个、四个分别算，就能得出好几组不同的平均年龄，人还是那五个人，可用的组合多了。

    * 思路类比：有点像集成学习里的加权操作——预测对的把权重降下来、预测错的把权重升上去，靠多次不同组合的结果互相纠偏。

```text
neurons: 1 2 3 4 5
batch 1: 1 . . 4 5
batch 2: 1 . 3 . 5
batch 3: . 2 . 4 5
```

### 超参 P 与插入位置

* **失活概率（$P$）**

    * > **定义**：每个神经元被清零的概率，是 dropout 的超参。

    * 常用范围 0.2 到 0.5；写 0.9 等于每个神经元都有 90% 的概率停工，网络会稀疏得没法看。

    * 按数据量：数据量非常大可以往 0.5 靠，比如 0.4；数据量本身就少就取小一点，0.2、0.3 就够了——本来就缺数据，再大规模失活，模型更学不到东西。

    * 按网络规模：模型较小、或者任务本身比较复杂的，丢弃率 0.3 甚至更小；网络非常深、比较大的，可以设到 0.5 或 0.6，压过拟合的效果更明显。

    * 模型复杂度与失活率同向：模型复杂就把 $P$ 调大（0.5、0.6），模型简单就小一点（0.2）；反过来干会让结果没人干活——一百人按 0.5、0.6 失活还剩一些，班里只有两个人就没人了。

    * 插入位置：实际应用里一般加在激活函数之后。

    * > **易错点**：模型本来就简单却把 $P$ 设得很大，本来就缺数据还大规模失活，等于把仅有的信息再丢掉一层。

### 缩放与训练测试差异

| 阶段 | 失活 | 缩放 |
| :--- | :--- | :--- |
| 训练 | 按概率 `p` 随机清零 | 活下来的乘 $\frac{1}{1-p}$ |
| 测试 | 不失活，所有神经元都参与 | 不缩放 |

* **缩放补偿**

    * > **定义**：训练时把存活神经元的输出乘 $1/(1-P)$，把被清零造成的输出量级缺口补回来。

    * 数值：$P=0.5$ 时 $1/(1-0.5)=2$，即把存活神经元的输出放大两倍；原本 2.3 的数，失活后原样保留的会变成 4.6。

    * 为什么必须做：一层输出有一半位置变成 0，整体量级明显缩水；就这么送进下一层，训练阶段的输入尺度和测试阶段差一大截，后面的权重是照着缩小后的尺度学的，一测试就偏。

    * 补偿的尺度：从期望上看，这一层的输出总和与「一个都不失活」时保持一致。

    * 只在训练阶段做：测试时压根没有「被清零」这回事，输出量级天然完整，测试端因此可以是一个普通的恒等操作。

* **模式开关**

    * `model.eval()` 把模型设成测试模式，`model.train()` 设成训练模式；生不生效取决于模型当前处于什么模式。

    * 测试必须让所有神经元都上场：测试要拿全部数据一起算，不能只挑几条数据、几个神经元，否则结果就有偏差。

    * 训练时随机失活的目的，是造出不同的子网络；测试时用完整网络给出稳定结果。

    * > **易错点**：方向记反——失活只属于训练阶段，测试阶段既不删神经元也不缩放。

### 代码实现

* **`nn.Dropout`**

    * > **定义**：`torch.nn` 把随机失活做成的一个网络层，构造参数是失活概率 `p`。

    * 调用方式：`dropout = nn.Dropout(p=0.5)`，把上一层的激活输出传进去，得到失活后的结果。

    * 完整数据链：`t1`（1 行 4 列、取值 0~10 的浮点输入特征）→ `nn.Linear(4, 5)` 加权求和得 `l1`（有正有负）→ `torch.relu` 得 `output`（负值全部变 0）→ dropout 得 `d1`（活下来的 ×2）。

    * 形状不必较真：`nn.Linear(4, 5)` 的两个参数是输入特征维度和输出特征维度，写 4 和 4 也可以，这一层开几个神经元没有硬性规定。

    * 顺序不能反：先加权求和、再过激活、最后对激活值失活；直接对 `l1` 做失活等于跳过激活函数，这一层就白搭了一个非线性。

    * `p` 还影响可读性：`p=0.4` 时缩放是 $1/0.6$，不好算也不好讲；回到 `p=0.5` 时 $\frac{1}{0.5}=2$，活下来的值正好放大两倍，现象一眼就能看出来。

    * 极端情况：某一轮剩下的值全被清掉不算错，50% 的概率本来就允许这种运气，多跑两次就正常。

    * 复现：`torch.randint` 每跑一次都是新的一组随机数，想复现就在造数据之前固定 `torch.manual_seed(种子值)`。

    * ReLU 的确定性：`l1` 里小于 0 的一律压成 0、大于 0 的原样放行，即 $\mathrm{ReLU}(x) = \max(0, x)$，跟随机性一点关系都没有。

    * > **易错点**：ReLU 把负数归零和随机失活把神经元清零是两件完全不相干的事。看见输出里出现 0 就以为「随机失活生效了」，是这里最容易犯的误读——ReLU 只要值为负每次都归零，随机失活按概率随机挑、挑中谁每轮都不一样，而且必须在训练模式下才发生。

```python
dropout = nn.Dropout(p=0.5)
d1 = dropout(output)
```

| 变量 | 身份 |
| :--- | :--- |
| `t1` | 输入特征 |
| `l1` | 加权求和结果 |
| `output` | 激活函数处理结果 |
| `d1` | 随机失活处理结果 |

## 批量归一化

### 命名与定位

* **批量归一化（batch normalization，BN）**

    * > **定义**：对每一批数据先做标准化（拉到均值 0、标准差 1），再用一组可学习参数做缩放与平移（重构），借此缓解过拟合、让训练更稳更快。

    * 定位：属于正则化的一种，作用也是缓解模型的过拟合；与 L1/L2、dropout 不同路数——前两者动权重、dropout 动神经元存活，BN 动数据本身的分布。

    * 命名来由：底层先做的是标准化，更应景的名字应该是「批量标准化」。标准化本身就是针对归一化做的一次优化和调整。

    * 归一化的弊端：归一化把值映射到 0 到 1 之间，太容易被这一列的最大值和最小值影响，一整列里只要出现一个极端值，缩放的比例就被带偏；标准化改成参考这一列的均值和方差。

    * 叫法：标准化在某些地方也被直接叫成归一化，所以 `batch normalization` 译成批量归一化不能说错，只是叫法松了一点；记住底层动作是标准化，名字就不用纠结。

    * 「批量」的含义：不是拿整个数据集算一套均值方差，而是数据分成一批一批、每一批各自算自己的均值方差、各自标准化，批与批之间互不干扰，这也是名字里 batch 的来历。

    * 出处：2015 年谷歌提出。

### 标准化与重构

$$ y = \gamma \cdot \frac{x - \mu_B}{\sqrt{\sigma_B^2 + \varepsilon}} + \beta $$

| 符号 | 含义 |
| :--- | :--- |
| $x$ | 这一批数据的输入 |
| $\mu_B$ | 这一批数据的均值 |
| $\sigma_B^2$ | 这一批数据的方差 |
| $\sqrt{\sigma_B^2 + \varepsilon}$ | 标准差，标准差等于方差开平方根 |
| $\varepsilon$ | 小常数，取 $10^{-5}$，防止分母变成 0 |
| $\gamma$ | 缩放系数，可学习 |
| $\beta$ | 平移量，可学习 |

* **两段结构**

    * 标准化段 $\dfrac{x-\mu_B}{\sqrt{\sigma_B^2+\varepsilon}}$：先减均值、再除标准差，输出被拉成均值为 0、标准差为 1 的分布。

    * 重构段 $\gamma \cdot (\cdot) + \beta$：先乘 $\gamma$ 缩放、再加 $\beta$ 平移。

    * 还是 $Wx+B$ 的形状：缩放就是以前的权重 $W$，平移就是以前的偏置 $B$，只不过这次作用在标准化之后的数据上；看公式不要被希腊字母唬住，拆成「标准化一坨 + 一次线性变换」就通了。

    * 顺序是死的：先标准化稳住分布，再缩放平移挽回表达力，两步缺一不可。

    * $\gamma$ 在部分材料里写作 $\lambda$，认出是同一个东西即可。

* **$\varepsilon$ 与可学习参数**

    * $\varepsilon$ 的唯一职责是别让分母等于 0：一批数据如果全部相同，方差就是 0，开完根号还是 0，直接除就炸了；加上 $10^{-5}$，分母最小也是 $10^{-5}$，计算能继续。

    * $10^{-5}$ 这个量级说明 $\varepsilon$ 只是「防零」不是「调节」，小到几乎不影响正常的除法结果，不要指望通过改它来调模型效果。

    * $\gamma$、$\beta$ 不是人工设定的超参数，而是和权重一样跟着训练、通过反向传播更新的可学习参数；代码里只决定「要不要用它」，不决定它等于几。

    * 若 $\gamma$ 恒等于 1、$\beta$ 恒等于 0，BN 就只是死板地做标准化，什么信息都找不回来；正因为它们可学习，BN 才既能享受标准化的稳定，又能保留必要的表达能力。

    * 手设数值不行：给缩放设 0.3、给平移设 5 这种做法不成立，这两个数由训练过程学出来，把 API 写上、底层替你做掉。

### 内部协方差偏移

* **内部协方差偏移（internal covariate shift）**

    * > **定义**：神经网络搭好以后，前一层参数的改变对后续所有层都有影响——前面一抖，后面全跟着抖。

    * 程度：批次之间的数据分布差异越大，「抖」得越厉害，这个内部协方差就越不稳定。

    * Sigmoid 的有效区间：Sigmoid 只有在 $-6$ 到 $6$ 这个范围内还有点像样的效果，真正好用的是 $-3$ 到 $3$；超出这个区间曲线压得极平，梯度几乎贴着 0，参数很难再动。

    * 不标准化的后果：数据的量级随任务变，可能整体偏在几十、上百的位置，压根落不进 $-3$ 到 $3$；数据不在有效区间里，权重更新的步子只能迈得又小又别扭，收敛自然慢。

    * 标准化的收益：主要部分集中到 0 附近一个很窄的区间（比如 0 到 1 这个量级），分布更均匀，正好落在 Sigmoid 的敏感段，梯度有劲、收敛快，最终效果也更好。

    * 更根本的一层收益：压住层与层之间的分布漂移——每层输出都被拉回同一个窄区间，后面所有层看到的输入始终是同一个量级，管的是整条链路的稳定性。

* **乡村小道与高速公路**

    * 没有 BN 的路：没有限速，想怎么开就怎么开；老司机跑到 130、150，新手怕得只敢龟速，调「限速系数」得同时照顾最慢和最快两头。

    * 落到训练上：一万条数据每批 100 条分成 100 批，第一批全是 3、第二批 100、第三批 5、第四批 130，权重 $W$ 必须横跨整条数轴来回折返，折线陡峭，像坐过山车，拟合情况变得很差，每一批都在纠偏，等于一直在原地打转。

    * 有 BN 的路：最低限速和最高限速都标出来，所有车的速度被压进同一个区间，管理起来就轻松了。

    * 落到数据上：3、100、5、130 被分别压成 0.2、0.9、0.3、0.8 这样的小数，$W$ 只需要在这个很窄的范围里做微调，内部协方差立刻稳定下来。

    * 副作用：标准化在抹平差异的同时丢掉了很多信息——3 千米每小时和 130 千米每小时原本是很有区别的两件事，压成 0.2 和 0.8 之后，「极慢」和「极快」的味道就淡了。

    * 所以才有重构：拿 $\gamma$ 去乘 0.2、再加上 $\beta$，通过调整这两个可学习参数，把丢掉的信息找补一部分回来。

    * 综合作用：减少内部协变量偏移，让权重调整更接近一条平缓的线而不是折角极大的折线，从而加速训练、让过程更稳定，并顺带起到正则化的作用——数据分布稳定了，模型就不容易去死记某一批数据的偶然特征。

```text
没有 BN：  3 km/h ── 100 km/h ── 5 km/h ── 130 km/h ── 6 km/h
             W 必须横跨整条数轴来回折返，折线陡峭

有 BN：    0.2 ── 0.9 ── 0.3 ── 0.8 ── 0.25
             W 只在窄区间内微调，折线平缓
```

### 接口与形状

| 接口 | 处理对象 |
| :--- | :--- |
| `BatchNorm1d` | 一维特征，比如文本 |
| `BatchNorm2d` | 二维图像 |
| `BatchNorm3d` | 三维数据，比如医学影像 |

* **`nn.BatchNorm2d` 的构造参数**

    * `num_features`：输入特征数，跟通道数有关，几通道就是几。

    * `eps`：`1e-5`，加在分母上的小常数（噪声值），防止分母变成 0。

    * `momentum`：动量，用于计算统计量的移动平均。

    * `affine`：`True` 时用可学习的 $\gamma$、$\beta$ 做缩放平移；`False` 就只输出标准化结果、不做重构。

* **形状约束**

    * `BatchNorm2d` 要的输入是 4D 的 `(N, C, H, W)`——批大小、通道数、高、宽；喂一份 2D 数据进去，这一层会直接报错。

    * `BatchNorm1d` 收 `(N, C)`；`num_features` 必须等于上一层的输出维度或图像的通道数，对不上就报错。

    * 一维表格数据要先过线性层：`(2, 2)` 的输入经 `nn.Linear(2, 4)` 变成 4 个特征，再用 `BatchNorm1d(num_features=4)` 接上。

    * 二维图像本身就是多维的，可以直接交给 `BatchNorm2d`，所以图像那条路上不必中间再加线性层。

    * 三维版本吃带上深度维度的张量（`NCDHW` 这一套），具体细节长文未展开；三维以上用不上。

    * > **易错点**：数据和层对不上形状是这一节最容易踩的坑——`BatchNorm2d` 收 `(N, C, H, W)`、`BatchNorm1d` 收 `(N, C)`，`num_features` 又必须与上一层输出维度或通道数一致。

```python
input_2d = torch.randn(size=(1, 2, 3, 4))
bn2d = nn.BatchNorm2d(num_features=2, eps=1e-5, momentum=1, affine=True)
output_2d = bn2d(input_2d)

input_1d = torch.randn(size=(2, 2))
linear = nn.Linear(2, 4)
l1 = linear(input_1d)
bn1d = nn.BatchNorm1d(num_features=4)
output_1d = bn1d(l1)
```

* **结果观察**

    * 处理后所有值都被压进一个很小的区间；想知道某个值为什么是那个数，只能拿中间值按公式算一遍——神经网络只能通过数值去模拟数据与数据之间的关系，不会把中间过程翻译成人话。

    * 一维例子的对比：处理前能看到 0.3、1.0、0.4、0.8 这种参差，处理后基本落在 $-1$ 到 $1$ 附近，整个区间的差距明显变小、更均匀。

    * 二维例子的形状：`size=(1, 2, 3, 4)` 是 1 张图、2 个通道、每个通道 3 行 4 列像素；正常该写 3 个通道（RGB），这里写 2 只是取 R 和 G。

### 适用领域

* **计算机视觉（CV）**

    * BN 在计算机视觉领域用得最多，理由长在数据身上：图像处理的基本单位是像素点，像素点的取值范围是 0 到 255。

    * 这个跨度意味着批次之间的分布差别会非常大——这一批数据整批接近 0，那一批整批是 5，下一批整批 200，再来一批又全是 10；权重面对这种输入只能来回坐过山车。

    * 处理顺序：先归一化或标准化把像素压到一定区间，再做缩放和平移，情况会好很多。

    * 接口对号入座：一维特征（如文本）用 `BatchNorm1d`，二维图像用 `BatchNorm2d`（后面卷积网络里的常客），三维数据（如医学影像）用 `BatchNorm3d`。

## 分类任务的数据准备

### 问题定性

* **价格区间分类**

    * 数据是 20 列特征加 1 列标签共 21 列，2000 条样本；特征是电池一次性可用的总容量、是否支持蓝牙等。

    * 标签不是连续价格，而是把价格映射成四个区间——比如 1500 以下、1500 到 3000、3000 到 5000、5000 往上，用 0、1、2、3 表示。

    * > **定义**：要预测的是离散的类别——四个价格区间之一，所以本质上是分类问题，不是回归问题；这一条定下来，后面的损失函数和输出层维度就跟着定了。

    * 与机器学习的差别：机器学习要人工决定 20 列特征全用还是只用几列、选 XGBoost 还是 GBDT，绕一圈又回到人工挑特征；深度学习把特征直接喂给网络，省掉挑特征与挑模型的活。

    * 输出标签数是 4，损失函数用 `CrossEntropyLoss`（多分类交叉熵），它内部本身就自带 softmax，所以前向传播里 softmax 那一步可以省略不写。

* **流程骨架**

    * ANN 与 CNN 都是四步：准备数据集 → 搭建神经网络 → 模型训练 → 模型测试。

    * RNN 处理文本要多一步：构建语料库（词表）→ 准备数据集 → 搭建神经网络 → 模型训练 → 模型测试，共五步。

    * 搭网络仍是三步老动作：定义一个类继承 `nn.Module`、重写 `__init__`、重写 `forward` 做前向传播。

### 数据管道

* **读取与切片**

    * 数据集就是一个 CSV 文件，`pd.read_csv` 一句加载；不要直接 `print(data)`（两千行太长），用 `data.head()` 看前五行。

    * 看形状：`data.shape` 是 `(2000, 21)`，2000 行是 2000 条样本，21 列是 20 个特征加 1 列标签。

    * 切片：`X, Y = data.iloc[:, :-1], data.iloc[:, -1]`；`:-1` 包左不包右，最后一列不要、前面全要（前 20 列），`-1` 只要最后一列。

    * 形状对照：`X.shape` 是 `(2000, 20)`，`Y.shape` 是 `(2000,)`——那个 1 默认不显示，但它确实就是 2000 条标签。

* **类型转换**

    * 特征列要转浮点：`X = X.astype(np.float32)`，因为后面要做自动微分，那是对小数做操作的。

    * 标签列不动：`Y` 本身就是 0、1、2、3 这样的整数类别编号，不参与求导，保持整型正好。

    * > **易错点**：把标签也转成浮点，反而会在算交叉熵时报错。

* **切分与封装**

    * 切分：`train_test_split(X, Y, test_size=0.2, random_state=3, stratify=Y)`；`test_size=0.2` 是八比二，2000 条分成 1600 条训练、400 条测试。

    * `random_state` 是随机种子，把每次切分的结果固定住。

    * `stratify=Y` 是分层抽样：抽取时参考 `Y` 里各类别的比例，保证训练集里四个价格区间都有，不会出现某个区间一条都没抽到的情况；这个参数容易忘。

    * 两层封装：先用 `torch.tensor(x_train.values)` 把 numpy 数组变成张量，再用 `TensorDataset` 把特征张量与标签张量打包成一个数据集对象。

    * 两种转张量方式：`torch.tensor(...)` 拷一份内存，`torch.from_numpy(...)` 与原数组共用一块内存，本质一样，用哪个都行。

    * `DataLoader` 不在这里包：数据集对象上没有直接取数据的接口，要包成 `DataLoader` 才能一批一批取；训练集在训练函数里包、测试集在测试函数里包，两边代码各自对齐。

    * 返回四个值：`train_dataset`、`test_dataset`、`x_train.shape[1]`（20，输入特征数，决定输入层神经元数）、`len(np.unique(Y))`（4，输出标签数，决定输出层神经元数）。
