# PyTorch张量创建与类型操作

## 张量的本质与维度

   * **张量（Tensor）**

       * > **定义**：元素同属一种数据类型的多维矩阵，以类的形式封装，是 PyTorch 的核心数据抽象。

       * 两条底线：同一张量内所有元素类型统一；元素值必须是数值。人工神经网络、卷积神经网络、循环神经网络底层处理数据用的都是它。

       * 与 NumPy 的 ndarray 形态相近，多出来的能力是 GPU 加速与自动微分。构造时指定 `device='cuda'` 即在 GPU 上运行，不指定则在 CPU 上运行。

       * 数值运算、矩阵操作都以方法形式封装在张量类里；自动微分即求导，是后续参数更新所依赖的机制。

   * **维度（dimension）**

       * 0 维是标量，只有一个值；1 维是向量，是一条线；2 维是矩阵，是一张行列表；3 维是若干同形矩阵叠起来的一叠表；4 维是若干三维张量再往上摞成的一垛砖，更高维按同样方式逐层叠加。

       * 形状 $3 \times 4 \times 5$ 读作三个 4 行 5 列：第一个维度是张量个数，后两个是每个张量的行数与列数。

       * 一张 $32 \times 32$ 的彩色图片记为 $3 \times 32 \times 32$，即三个 32 行 32 列的矩阵，每个矩阵对应一个颜色通道。

   * **通道顺序（HWC 与 CHW）**

       * 存图时按 HWC 排列，形状 `(32, 32, 3)`，高、宽在前，通道在最后。

       * 模型处理时按 CHW 排列，形状 `(3, 32, 32)`，通道在最前；两者装的是同一张图，靠交换维度把最后一位挪到最前。

## 张量创建的三种入口

   * **`torch.tensor`（小写）**

       * > **定义**：以现成数据为输入创建张量，输入可以是标量、列表或 NumPy 数组。

       * 可用 `dtype=` 同时指定元素类型：`torch.tensor(data, dtype=torch.float)`。

       * 只收一个位置参数，第一个位置是数据、第二个位置是类型；`torch.tensor(2, 3)` 会报 `TypeError: tensor() takes 1 positional argument but 2 were given`。

       * 使用频率最高，把 ndarray 或列表封装成张量走的就是它。

   * **`torch.Tensor`（大写）**

       * 以形状为输入，`torch.Tensor(2, 3)` 直接得到两行三列张量，元素是随机浮点数。

       * 不接受 `dtype` 参数，元素类型由数据本身决定，在这个位置写 `dtype` 会报错。

       * 按形状直接创建这个能力在实际开发中几乎碰不到。

   * **`torch.IntTensor` 等带类型名的构造器**

       * 名字里写死了元素类型，同时支持按形状创建，`torch.IntTensor(10)`、`torch.IntTensor(2, 3)` 都能跑。

       * 类型不匹配时先尝试自动转换，转换不了才报错：整数数据喂给 `FloatTensor` 会得到带小数点的浮点张量。

   * **入口选择**

       * > **易错点**：`torch.tensor` 与 `torch.Tensor` 是两个不同入口，一个吃数据、一个吃形状，大小写不是命名风格问题，写错会直接报参数数量错误或拿到一堆随机数。

       * 功能上大写覆盖小写还多一条按形状创建，但日常真正要做的是把数据封装成张量，所以小写用得更多。

| 写法 | 输入 | 可指定 `dtype` | 可只给形状 |
| :--- | :--- | :---: | :---: |
| `torch.tensor(...)` | 数据（标量、列表、ndarray） | 能 | 不能 |
| `torch.Tensor(...)` | 形状 | 不能 | 能 |

## 默认数据类型与位宽

   * **元素类型（dtype）**

       * 张量内元素的数据类型，用 `t.dtype` 查看，例如 `torch.int64`、`torch.float32`。

       * 与 `type(t)` 区分：后者返回 `torch.Tensor`，说的是容器本身是什么。

   * **默认浮点类型**

       * `float32` 是张量的默认数据类型，默认值不重复显示，所以有的输出带类型名、有的不带。

       * 32 指位数（bit），1 字节等于 8 比特位：`float32` 占 4 字节，`float16` 占 2 字节，`float64` 占 8 字节；字节越多，可表示的数值范围越大。

       * 默认选 32 位是为省空间，且深度学习里的运算以小数为主，32 位精度够用，64 位纯属浪费。

   * **`uint8` 的符号性**

       * `uint8` 的 u 是 unsigned，无符号，范围 0~255，没有负数。

       * 有符号的 8 位整数范围是 -128~127，两者不要混记。

   * **最常用的两种**

       * 浮点认 `float32`，整数认 `int64`：以整数数据创建张量时默认得到的就是 `int64`。

| 类型 | 简写 | 占用 | 说明 |
| :--- | :--- | :---: | :--- |
| `torch.float32` | `torch.float` | 4 字节 | 张量默认的浮点类型 |
| `torch.float64` | `torch.double` | 8 字节 | 64 位浮点 |
| `torch.float16` | `torch.half` | 2 字节 | 占用为 32 位的一半 |
| `torch.int64` | — | 8 字节 | 整数数据创建时默认得到它 |
| `torch.uint8` | — | 1 字节 | 无符号 8 位，范围 0~255 |

## 全零、全一与指定值张量

### 六个构造函数

   * **`ones` / `zeros` / `full`**

       * 直接按形状创建：`torch.ones(2, 3)` 得两行三列全 1，`torch.zeros(2, 3)` 得两行三列全 0。

       * `full` 多一个填充值参数，写法是 `torch.full(size=(2, 3), fill_value=255)`。

   * **`_like` 后缀**

       * `ones_like` / `zeros_like` / `full_like` 不接收行列数，只照入参张量的形状生成同形张量。

       * 入参必须是张量，直接传列表会报错，须先用 `torch.tensor(...)` 包一层。

       * > **易错点**：`ones_like` / `zeros_like` / `full_like` 的入参是张量，不是列表。

| 函数 | 作用 |
| :--- | :--- |
| `torch.ones(size)` | 创建全 1 张量 |
| `torch.ones_like(t)` | 照 `t` 的形状创建全 1 张量 |
| `torch.zeros(size)` | 创建全 0 张量 |
| `torch.zeros_like(t)` | 照 `t` 的形状创建全 0 张量 |
| `torch.full(size, fill_value)` | 用指定值填充 |
| `torch.full_like(t, fill_value)` | 照 `t` 的形状用指定值填充 |

### 填充值传参与 255 的来历

   * **形状必须打包**

       * `full` 的第二个参数位置是填充值，不是第二个维度；要两行三列得把形状打包成一个整体，写 `size=(2, 3)` 或直接传 `(2, 3)` 元组。

       * `full_like` 同理，先照模板张量的形状，再补上要填的值。

   * **255 的含义**

       * 255 是单通道颜色上限：RGB 红绿蓝三原色每通道取值 0~255，越接近 0 越黑，越接近 255 越白，三通道全 0 是黑、全 255 是白。

       * 图像按通道分二值图、灰度图、索引图与三通道的 RGB 真彩图；画全黑图或全白图时用的就是 `fill_value=255`。

   * **只有 zeros 是高频**

       * 线性公式 $y = wx + b$ 中 $b$ 是偏置（bias），即使考虑线性关系时把偏置忽略掉，参数初始化里仍要保留它，最省事的做法是用 `zeros` 把偏置项全设为 0。

       * `ones` 不必强记，`full` 除了造全黑全白图之外基本不再出现。

## 线性张量

### arange

   * **参数与边界**

       * 三个参数是 `start`、`end`、`step`，包左不包右：`torch.arange(0, 10, 2)` 得到 `tensor([0, 2, 4, 6, 8])`，终点 10 不在结果里。

       * 起点算进去、终点不算，是范围类函数的常见规矩，但具体结果以实际打印为准，不能只凭惯例下结论。

   * **起止组合**

       * 从 1 开始、每次加 2、到 11 之前为止写作 `torch.arange(1, 11, 2)`。

       * `type(torch.arange(0, 10, 2))` 返回 `torch.Tensor`，拿到的就是张量。

### linspace

   * **参数含义**

       * 三个参数是起点、终点、元素个数，首尾都含：`torch.linspace(1, 10, 5)` 得到 `tensor([1.0000, 3.2500, 5.5000, 7.7500, 10.0000])`。

       * 步长由首尾差除以间隔数反推：$(10-1)/(5-1)=2.25$；个数改成 4 时 `torch.linspace(1, 10, 4)` 得到 `1., 4., 7., 10.`，步长 3。

   * **与 arange 的差别**

       * > **易错点**：`linspace` 的第三个参数是元素个数，不是步长；它与 `arange` 的第三个参数位置相同、含义完全不同。

       * 参数含义不用猜：按住 Ctrl 加鼠标左键点函数名跳进源码，前三个参数写得很清楚。

## 随机张量与随机种子

### 两个种子函数

   * **`torch.initial_seed`**

       * 不传参，默认取当前系统时间戳作随机种子，时间一直在变，所以每次生成的值都在变。

       * 实际开发基本不用，知道它按时间戳走即可。

   * **`torch.manual_seed`**

       * 把种子钉死，`torch.manual_seed(3)` 之后同一段代码反复运行，输出逐位一致，结果可复现。

       * 种子对设置之后的所有随机调用都生效，不是只管最近一次；一个文件里写在导包下面设一次即可，不必每个函数再设。

### 三类随机张量

   * **`torch.rand`**

       * 参数是 `size`，`torch.rand(2, 3)` 得两行三列浮点张量，值在 0 到 1 之间均匀分布。

       * 不设种子时每次运行结果都不同，设了 `manual_seed` 才会固定。

   * **`torch.randn`**

       * n 表示 normal，造的是正态分布张量，均值 0、标准差 1。

       * 与 `rand` 的区别只在分布形状：`rand` 的值平铺在 0 到 1 之间，`randn` 的值可正可负、大部分挤在 0 附近、越往两边越稀。

   * **`torch.randint`**

       * `torch.randint(0, 10, size=(2, 3))`，前两个参数是区间两端，`size` 管形状，返回整数张量。

       * 换 `size=(3, 5)` 就是三行五列，每行五个数、共三行。

### 掌握优先级

   * 必须掌握 `arange`、`linspace`、`manual_seed`、`randint` 四个；`rand` 与 `randn` 的参数形式跟 `randint` 是同一套，用到时类比即可。

   * 判断一个 API 要不要背，标准是它有没有被别的 API 替代，而不是它常不常见。

| 函数 | 造出来的结果 | 是否必背 |
| :--- | :--- | :--- |
| `torch.arange` | 指定范围、指定步长的线性张量，包左不包右 | 要 |
| `torch.linspace` | 指定首尾、指定个数的等差张量，首尾都含 | 要 |
| `torch.initial_seed` | 以当前时间戳为种子，不传参 | 不用，知道即可 |
| `torch.manual_seed` | 把随机种子固定下来 | 要 |
| `torch.rand` | 0 到 1 之间均匀分布的浮点张量 | 会用即可 |
| `torch.randn` | 均值 0、标准差 1 的正态分布张量 | 会用即可 |
| `torch.randint` | 指定范围的整数张量 | 要 |

## 元素类型的查看与转换

### 查看与创建时指定

   * **`dtype` 与 `type()`**

       * `t1.dtype` 返回 `torch.int64`，看的是张量里元素的类型。

       * `type(t1)` 返回 `torch.Tensor`，看的是张量这个容器本身的类型；一个说里面装的是什么数，一个说容器是什么。

   * **创建时指定**

       * `torch.tensor([1, 2, 3, 4, 5], dtype=torch.float16)` 的元素类型就是 `torch.float16`，写 `torch.float` 即 32 位。

       * 创建张量时直接把类型给出去，是以后用得最多的一种写法，ANN、CNN 这类模型用的全是 `float32`。

### type() 统一转换

   * **写法**

       * `t1.type(torch.int16)` 把元素类型转成 `int16`，括号里换成 `torch.int32`、`torch.double` 都可以。

       * 推荐掌握这一条：一行完成，参数只有目标类型名，不必记六个方法名。

   * **搭配链式**

       * 转换可以接在别的调用后面，如 `torch.from_numpy(n1).type(torch.float32)`，不必先落一个中间变量。

### 同名方法族

   * **对应关系**

       * `half()` 转 `float16`、`float()` 转 `float32`、`double()` 转 `float64`、`short()` 转 `int16`、`int()` 转 `int32`、`long()` 转 `int64`。

       * > **易错点**：方法名把位宽省掉了，`float` 就是 `float32`、`int` 就是 `int32`、`long` 就是 `int64`，不要自己往里补数字。

       * 这一族与 Java 的基本类型高度对应，学过 Java 一眼能认，只是多出 `half` 这种操作。

| 方法 | 目标类型 | 位宽与占用 |
| :--- | :--- | :--- |
| `half()` | `torch.float16` | 16 位浮点，2 字节 |
| `float()` | `torch.float32` | 32 位浮点，默认小数类型 |
| `double()` | `torch.float64` | 64 位浮点 |
| `short()` | `torch.int16` | 16 位整数 |
| `int()` | `torch.int32` | 32 位整数 |
| `long()` | `torch.int64` | 64 位整数，默认整数类型 |

## 张量与 NumPy 互转

### 共享内存与深浅拷贝

   * 浅拷贝拷贝得少，只把第一层拷出来，后续层共享；深拷贝每一层都拷走，相当于独立剥离出一份新数据。这套区分主要针对可变类型。

   * 放到张量转换上，判断标准只有一条：新对象与原对象是否指向同一块内存。共享内存等价于浅拷贝，不共享等价于深拷贝。

### 张量转 NumPy

   * **`numpy()` 共享内存**

       * `n1 = t1.numpy()` 得到 ndarray，与原张量共享同一份数据；改 `n1` 的某个元素，`t1` 同步变化。

       * `numpy()` 不接收参数，不能靠传参顺便拷一份。

   * **`copy()` 断开共享**

       * `t1.numpy().copy()` 得到独立数组，改动新数组不影响原张量。

   * **验证方式**

       * > **易错点**：两边打印结果长得一样不能证明共享内存，它们本来就装着同一批数字；必须改动一头的元素，再看另一头是否跟着变。

       * 验证时改 NumPy 数组那一头更直观，源头一变，张量跟不跟一眼可见。

### NumPy 转张量

   * **`torch.from_numpy`**

       * `torch.from_numpy(n1)` 共享内存，改原数组张量跟着变。

       * 参数表里只有 `ndarray`，没有 `dtype`，元素类型沿用数组本身的类型（整数数组得到 `int32`）；要换类型只能在转换后接 `.type(torch.float32)`。

   * **`torch.tensor`**

       * `torch.tensor(n2)` 默认不共享内存，改原数组张量不动。

       * 日常用得最多的写法，创建张量一直用它。

### 链式编程

   * **链式编程（chaining）**

       * > **定义**：函数返回值是一个对象时，可以继续用点把下一个函数接在后面，一路点下去。

       * 判断标准只看有没有用点连返回值：`t1.numpy().copy()` 是链式编程，`torch.tensor(np.array([11, 22, 33]))` 只是把一个函数塞进另一个函数的参数，属嵌套调用。

### 内存中的地址关系

   * 栈里只放变量名与它拿到的地址，真正的数据在堆区；`numpy()` 没有造新数据，只是把同一个地址再抄一份交给新变量，两边因此指向同一块空间。

   * `.copy()` 顺着原地址找到数据，复制一份放到新位置并给出新地址，两个变量从此互不干扰。

```text
numpy() / from_numpy()：共享同一地址

    t1 ──┐
         ├──► 0X01 [1, 2, 3, 4, 5]
    n1 ──┘

numpy().copy()：各自独立

    t1 ──────► 0X01 [1, 2, 3, 4, 5]
    n1 ──────► 0X02 [1, 2, 3, 4, 5]
```

## 标量张量与 item 取值

   * **标量张量（scalar tensor）**

       * > **定义**：只有一个值的张量。

       * `torch.tensor(10)` 与 `torch.tensor([100])` 都是标量张量，中括号里只有一个元素也算。

   * **`item()`**

       * `t1.item()` 把张量里的值取出来，返回 Python 原生数值（整数张量得 `int`），类型不再是 `Tensor`。

       * 浮点标量取出后尾部会拖一长串小数，原因是计算机里小数本来近似存储、浮点张量精度更低，属正常现象。

       * > **易错点**：`item()` 只对单元素张量成立，`torch.tensor([100, 200]).item()` 直接报错。

   * **可容纳的元素**

       * 布尔值可以建、可以取，参与运算时 `True` 按 1、`False` 按 0 处理。

       * 字符串不行，`torch.tensor('张三')` 抛 `TypeError`；张量里归根到底只能装数值。

   * **工程写法与命名**

       * 带自动微分标记的张量不能直接转 NumPy，标准写法是先复制再转：`t1.detach().numpy()`。

       * 接收 `item()` 结果的变量不要命名 `value`，Python 里很多对象自带 `value` 属性，容易冲突。

       * 反向传播阶段取出损失值用的就是 `item()`。

## 张量的基本运算

### in place 约定

   * 带下划线后缀的方法 `add_`、`sub_`、`multiply_`、`divide_` 修改原张量；不带下划线的返回新张量，原数据不动。

   * 这套约定与 pandas 的 `in place=True` 是同一语义，PyTorch 用一条下划线把它标在函数名上。

### 逐元素运算

   * 设 `t1 = torch.tensor([1, 2, 3])`：`sub(1)` 得 `0, 1, 2`；`multiply(2)` 得 `2, 4, 6`；`divide(2)` 得 `0.5, 1.0, 1.5`；`neg()` 得 `-1, -2, -3`；`t1 // 2` 得 `0, 1, 1`。

   * `neg()` 是唯一不需要参数的，自己翻号即可。

   * `/` 除法产生小数，`1 / 2` 得 `0.5`；`//` 是整除，`1 // 2` 得 `0`，两者不是一回事。

   * 张量与单个数值运算时，该数值与张量中的每一个元素依次计算一遍。

### 符号写法

   * 基本运算都有符号版本，符号更灵活：`t1 + 10` 不改原数据，`t1 += 10` 改原数据，效果与 `add`、`add_` 一致。

   * 同时保留函数与符号两套写法，是为了满足不同的使用习惯，两者没有功能差异。

| 运算 | 函数写法 | 符号写法 | 是否改原数据 |
| :--- | :--- | :--- | :--- |
| 加法 | `t1.add(10)` | `t1 + 10` | 否 |
| 加法（原地） | `t1.add_(10)` | `t1 += 10` | 是 |
| 减法 | `t1.sub(1)` | `t1 - 1` | 否 |
