### 怎么学强化学习：先摆正心态

在正式开始之前，我想先多说几句关于如何学习强化学习的建议，这对想入门的同学比较有用。

首先要明确学习目标。强化学习不外乎两个方面：第一个是**原理**部分，第二个是**实践和编程**部分。这门课是关于原理部分的——想学实践编程的，有很多其它非常好的课程和资料。那原理重不重要？从我的角度来说是非常非常重要的。它能让你非常清晰地理解：你在用的这个算法，它的原理是什么、它在做什么样的事情、有什么优势、有什么劣势、如果我想创新应该从哪方面入手。这些都是非常重要的基础。

学原理也要根据自己的实际情况和兴趣合理制定计划：有人要把所有原理系统地过一遍、非常透彻地理解，这是一种；也有人有些地方已经比较熟、有些地方特别感兴趣，那就针对性地学。明确目标之后，就要给自己的目标配上合适的学习时间。

> **提示**：学习和研究当中很多时候的焦虑，就来自于我们没有给自己的目标分配合适的时间。

比如读一篇论文，按理应该花一周、五天，但你只给它安排了一天，必须一天之内学会——等到一天快结束的时候，你会发现连 introduction 部分还没搞定，于是非常非常焦虑。相反，如果给的时间比较充裕，心态非常平和、稳扎稳打，也许两三天这篇论文就搞定了。所以一定要配上合适的时间。

那为什么我要劝大家放弃"一个小时入门、一上午精通"这种速成的想法？因为强化学习的原理有两个特点：

- **数学性比较强**。你直观地去讲这个算法在干什么，其实理解是不深刻的，换个角度再讲可能就讲不明白了；但理解了背后的数学、这个公式在干什么事情之后，你会发现对这个算法 360 度无死角，都可以非常好地解释清楚、理解清楚。
- **系统性比较强**。它是一环扣一环的，后面的章节内容一定以前面章节的内容为基础。如果上来直接学 Q-learning、学 policy gradient，连基本的概念定义都没了解清楚，只能说了解了一个大概，遇到很多问题会云里雾里，或者很容易就被问倒了。

那究竟要花多少时间？其实也不用很久很久，我想强调的只是把心态放平。以这门课为例，线上全部内容 11 个小时左右，按 10 个小时算（大家也可以有针对性地选择，不必全部学一遍）。我建议学到一半有不懂的地方就停下来理解清楚，不要带着问题继续往前走，这样效率更高。如果采用这种方式，时间算翻倍：10 小时变 20 小时；如果学习过程当中还需要补其它相关基础知识打基础，时间再翻倍，从 20 小时变到 40 小时。

40 个小时算多还是少？这里有性价比的问题。如果这 40 个小时效率比较高、基础也比较好，学完之后你对强化学习原理的理解就已经达到比较深刻的程度了；再配上一些实践、再花一些时间，之后你就可以去阅读论文而且不会有太大障碍。要达到这个效果，付出这个时间还是非常值得的。再往现实里算一算：花两个星期（不算周末），一共 10 天，每天 4 个小时——上午 2 小时、下午 2 小时——你还有时间做其它事情。总的来说，花一些时间扎扎实实往前走，看似是最笨的方法，实际上是一劳永逸、最高效的方法。

#### 基本概念：一切的起点

第一章讲基本概念：状态、action、reward、return、episode、policy，都是强化学习当中非常非常基础的概念。我们会首先通过一个 grid-world example——网格世界的例子，就是一个机器人在里面找到目标区域——来介绍，这个例子非常直观，整个课程当中会非常广泛地使用。之后我会把所有这些概念放到 Markov decision process（MDP）的框架下更正式地介绍。第一章的内容会在强化学习当中非常广泛地使用。

#### 贝尔曼公式：用 state value 评价策略

第二章有两个非常关键的点：一个概念、一个工具。搞明白了这个概念和这个工具以及它们之间的关系，这一章就非常清晰了。

概念是 **state value（状态值）**：从一个状态出发，沿着一个策略所得到的奖励回报的平均值。状态值越高，说明对应的策略越好；状态值越低，说明沿着这个策略得到的奖励比较少、策略不好。我们为什么要关注状态值？就是因为它能够评价一个策略好还是不好。

工具是**贝尔曼公式**。用一句话描述：它描述了所有状态的 状态值 之间的关系，这个关系实际上是一个等式、一个方程。通过求解这个方程，我就能求出来一个给定策略的状态值，因此就能评价这个策略到底好还是不好。

> **定义**：求解贝尔曼公式、进而得到一个策略所对应的状态值，这个过程叫**策略评价**（policy evaluation）。

策略评价在强化学习当中是非常基础的一个概念：我评价了一个策略得到它的值，然后基于它的值改进策略，这样循环下去，最后就能得到最优的策略。这个思想非常非常重要。

#### 贝尔曼最优公式：直指最优策略

从名字就能感受到，贝尔曼最优公式（Bellman optimality equation）实际上是贝尔曼公式的一个特殊情况。每一个贝尔曼公式都对应了一个策略；贝尔曼最优公式作为一个特殊的贝尔曼公式，也对应了一个策略——什么策略？**最优策略**。我们为什么要研究它？就是因为它和最优策略有关系，要不然我们也不研究它。

这就涉及到一个非常基础的问题：**强化学习的终极目标是什么**？上过我课的同学，当你听到这个问题的时候，一定要非常快速地反应到：强化学习的终极目标就是**求解最优策略**。

学这一章要把握两点。第一个关键点还是概念：最优策略和最优的 state value。最优策略的定义是：沿着这个策略能得到最大的状态值，沿着其它所有策略得到的状态值都没它大。第二个关键点是工具：贝尔曼最优公式。它写出来的形式非常简洁（矩阵向量形式），但第一次接触的同学需要花一些时间去学习、去理解——不过你会觉得物超所值，因为它带来的理解非常深刻、非常全面。

分析这个式子，我们用到了**不动点原理**，它告诉我们这个式子两个方面的性质：

- 一方面是非常基础的问题：最优策略、最优 state value 到底存在不存在？实际上是存在的——如果存在都不存在，我干嘛要研究它？它存在，但最优策略不一定是唯一的，而**最优的状态值是唯一的**；最优策略可能是确定性的（deterministic），也可能是随机性的（stochastic），但**一定存在确定性的最优策略**。
- 另一方面，它给出了一个算法来求解这个贝尔曼最优公式。把公式求解出来，自然就得到了最优策略和最优 state value，强化学习的目标也就达到了。

#### 值迭代与策略迭代：第一批求解算法

第四章 value iteration 和 policy iteration 是"算法和方法"板块的第一个。学完它，我们就知道了第一批能够求解最优策略的算法是什么。具体学了 3 个算法：

| 算法 | 关系 |
| :--- | :--- |
| 值迭代（value iteration） | 贝尔曼最优公式对应的那套求解算法，在这里被拆开细致研究 |
| 策略迭代（policy iteration） | 下一章蒙特卡洛方法当中有非常重要的应用 |
| 截断策略迭代（truncated policy iteration） | 前两个的统一化表达；值迭代和策略迭代是它的两个极端情况 |

这三个算法有一个共同特点：它们是**迭代式**的算法，并且每一个迭代步骤当中有两个子步骤——**policy update** 和 **value update**。意思是：当前时刻我有一个策略，策略不太好，没关系，先估计一下这个策略的值（做一下策略评价），得到值之后就根据这个值来改进策略；改进完得到新策略，再估计它的值，然后再改进策略……这两个步骤不断迭代，最后就能找到最优的策略。

> **结论**：这种"值和策略不断交替迭代"的思想，不仅在第 4 章，后面**所有**的强化学习算法都是这么做的，只不过具体形式、算法形式可能不同而已。

另外要注意，这一章介绍的算法是**需要模型**的。什么是模型，可以到基本概念那一章去看。如果没有模型该怎么办？那就来到第五章。

#### 蒙特卡洛方法：第一次甩掉模型

第五章的蒙特卡洛（Monte Carlo）方法，是整个强化学习当中**最简单的、也是第一个不需要模型就能找到最优策略**的方法。从第四章跳到第五章有一个鸿沟（gap）：我第一次要面对"没有模型"这个情况，没模型该怎么办？有时候大家会比较懵。实际上要明确两点：

- **第一点，你没有模型，你要学习什么？** 实际上要学习随机变量的期望值（expectation）。为什么？因为前面提到的 state value、action value 等等，它们全都是随机变量的期望值。
- **第二点，你没有模型，你有什么？** 我们有随机的采样。对 $X$ 的采样 $x_i$ 我有很多个，取平均值 $\bar{x}$，它就可以作为 $\mathbb{E}[X]$ 的一个很好的近似。

所以：没模型你要有数据，没有数据要有模型，什么都没有就什么都学不了——就是这么简单。把这样一个很简单的思想结合到强化学习当中，就得到了第一个不需要模型的强化学习算法。具体介绍了三个算法，难度依次增加：**MC Basic、MC Exploring Starts、MC ε-greedy**。

第一个 MC Basic 非常非常简单，它实际上就是第四章的 policy iteration——把里面依赖于模型的那部分拿掉，换成依赖于数据的放进去，就得到了 MC Basic。但这个算法实际当中不能用，因为效率非常低。不能用为什么要讲？就是希望大家把复杂的东西和最核心的东西剥离开来，看到最核心的东西其实非常非常简单；之所以后面两个算法有很多复杂的东西进来，是为了提高效率、更好地利用数据。

到这里大家可能有感觉了：强化学习真的是一环扣一环。要学蒙特卡洛，得先学会 policy iteration；要学 policy iteration，得先知道 value iteration；要学 value iteration，得先知道 Bellman optimality equation……从中间任何一个地方开始学，前面的基础没打好，就会有似懂非懂、理解不深的情况出现。

#### 随机近似：增量式思想的铺垫

从第五章到第七章时序差分方法之间，有一个比较大的鸿沟：第五章的算法都是 **non-incremental**（非增量）的，而第七章变成了 **incremental**（增量）的。如果不熟悉的话，第一次看到这些算法会比较懵：为什么这个算法会设计成这个样子？这些算法究竟在解决什么问题？所以我们按下暂停键，先用第六章随机近似（stochastic approximation）打好基础。

这一章介绍的第一个问题是**均值估计（mean estimation）**——估计一个随机变量的期望，正好用来说明什么是 non-incremental、什么是 incremental：

```text
non-incremental（批量式）:
  1万个采样 x1 x2 ... x10000  --等全部采齐-->  一次性求平均 -> 近似 E[X]

incremental（增量式）:
  初始估计(不准,没关系) -> 来一个采样就更新一次估计 -> 来一个更新一次 -> 越来越准
```

读图说明：上面一条路要等所有样本收集齐才能用，下面一条路进来一个就用一个。

增量式的好处很明显：如果有 1 万个样本，不需要等很久很久全部收集齐了再用，可以进来一个就用一个——在等样本收集的过程当中就已经有一些信息可用了，虽然可能不太准确，但起码有信息可以用。

具体来说这一章介绍了三个算法。第一个是 **Robins-Monro 算法**（简称 RM 算法），它求解的是一个非常简单的问题：函数 $g(w)=0$，$w$ 取什么值的时候方程成立？它非常有意思的一点是：不需要知道 $g(w)$ 长什么样子、它的表达式、它的梯度导数，全都不需要知道，就可以把解求出来。第二个是**随机梯度下降（stochastic gradient descent，SGD）**，它不仅用在强化学习当中，在很多其它机器学习领域都有非常广泛的应用；我们对它做了比较多的分析，并且指出 SGD 实际上是一种特殊的 RM 算法。之后我们还比较了 SGD、batch gradient descent 和 mini-batch gradient descent。总的来说，第六章就是打基础：增量式算法的思想，以及 SGD 这个算法和它的思想，在后边都会有非常广泛的应用。

#### 时序差分学习

有了第六章的基础，第七章时序差分（Temporal-Difference，TD）方法就容易学了。它是强化学习当中非常经典的方法，具体介绍了这么几种。

第一个，我们花了比较大的篇幅介绍**用 TD 方法学习 state value**，这能比较好地揭示 TD 方法的思想。学 state value 这件事，前面几章其实都在做：有的地方用蒙特卡洛方法来学 state value，有的地方用模型来计算 state value，这里用时序差分方法来计算 state value——都是在做类似的事情，但用的方法不一样。

第二个，这个算法可以进一步推广到 **Sarsa**，也就是用 TD 的思想来学习 action value。得到了 action value，可以以此为据去更新策略，得到新策略再计算它的 action value，这样不断循环，就能够不断改进策略，直到最后找到最优策略。

第三个是大名鼎鼎的 **Q-learning**。它比较特殊：直接计算 optimal action value，所以它是一个 **off-policy** 的算法。这里就涉及到 on-policy 和 off-policy 这两个非常重要的概念：

| | 生成数据的策略 | 被改进的目标策略 | 判定 |
| :--- | :--- | :--- | :--- |
| on-policy | behavior policy | target policy | 两者相同 |
| off-policy | behavior policy（可以是别的策略） | target policy | 两者可以不同 |

读表说明：强化学习当中有两个策略——**behavior policy** 用来生成经验数据，**target policy** 是我们不断改进、希望它收敛到最优策略的目标策略；两个相同就是 on-policy，可以不同就是 off-policy。

off-policy 的好处是什么？就是我可以用之前的、别的策略所生成的数据为我所用，拿过来进行学习，然后得到最优策略。

在这一章最后，我们给了一个统一化的视角：介绍的这些算法，表达式都非常类似，它们求解的数学问题也都是非常类似的。

#### 值函数近似：神经网络登场

从第七章到第八章 value function approximation，又存在一个比较大的跳跃：前面全都是**基于表格形式**的。比如状态值 $v_\pi(s)$，$s$ 是一个状态，每一个状态对应一个状态值，这些状态值存在一个表格或者向量当中，想去访问或者修改都非常容易。但现在遇到的问题是：如果状态非常多，或者状态是连续的，表格形式的效率就比较低下，或者就不再适用了。

所以这时候要用**函数的形式**去代替表格：用 $\hat{v}(s,w)$——$v$ 仍然是值，hat 代表近似，$w$ 是这个函数对应的参数——希望这个函数和真实的 $v_\pi(s)$ 越接近越好。

具体来说，第一个算法就是用值函数近似的思想来做 state value estimation。前面每一章都有不同的算法来做这件事，这是一个非常重要的问题。在这里它是怎么做的？实际上非常简单，分三步：

```text
第一步：明确一个目标函数 J(w)
第二步：求这个目标函数的梯度
第三步：用梯度上升 / 梯度下降对目标函数进行优化
```

读图说明：值函数近似的整个套路就是"定目标、求梯度、做优化"三步走。

具体在这里，目标函数 $J(w)$ 是真实的 state value $v_\pi(s)$ 和函数值 $\hat{v}$ 之间差的一个平均值，我希望找到一个最优的 $w$，使得这个函数能够很好地近似真实的 $v_\pi(s)$。这个思想也可以和 Sarsa、Q-learning 相结合：都可以来估计 action value，得到 action value 之后，再和 policy improvement 相结合，不断地迭代，就可以找到最优策略。这里还有非常重要的一点：我们介绍了 deep Q-learning（DQN），里面的很多技术——比如用两个网络、经验回放等等——也有详细介绍。

总的来说，第八章开启了一个新的篇章：我们引入了函数，而神经网络是函数非常好的一个表达方式。所以第八章，神经网络首次进到了强化学习当中。

#### 策略梯度：从改值到直接改策略

从第八章到第九章，又有一个跳跃：从第八章往前全都是 **value-based** 方法，第九章和第十章开始变成 **policy-based** 方法。它们的区别是什么？举一个简单的例子：第八章当中有一个目标函数 $J(w)$，$w$ 是值函数的参数，我要更新值函数的参数，使得这个值函数能够很好地近似一个策略所对应的值，在这个基础之上再更新策略——先估值、再改策略。而 policy gradient 不太一样：它有一个目标函数 $J(\theta)$，$\theta$ 是**策略**的参数——这里我们也把策略从表格形式变成了函数的形式——所以我是**直接去优化 $\theta$，也就是直接改变策略**，慢慢地就得到最优策略。这就是它们之间比较直观的区别。

第九章主要介绍 policy gradient。它的基本思路非常简单，和我们刚才提到的一样，还是那三步：找目标函数、求目标函数的梯度、用梯度上升或下降去优化目标函数。这个思想是非常广泛使用的。具体来说这里的目标函数有两个，感兴趣可以去看细节；其中第二个目标函数所对应的梯度就叫 **policy gradient**——非常著名的 policy gradient 定理就是直接给出它的梯度是什么。求这个梯度的过程相对来说比较复杂，但对绝大多数同学来说，比较熟悉这个表达式也就足够了。第三步有了梯度就做**梯度上升**，因为这时候我们要最大化目标函数。这一章会介绍一个非常经典的 policy gradient 方法：**REINFORCE**。

#### Actor-Critic：两条路线的合流

从第九章到第十章 actor-critic，实际上还是有一个小的跳跃，但这个跳跃已经很小了：actor-critic 是把 policy-based 方法和 value-based 方法相结合——更准确来说，就是把第九章 policy gradient 和第八章当中的内容结合在一起。更准确地说，actor-critic 的方法就是第九章 policy gradient 的方法。那它为什么叫这个名字？实际上就是为了突出这里边 value 所起到的作用：**actor** 对应的就是 policy update；**critic** 就是评论——我评论一个策略好还是不好，实际上就是求它的值，所以对应的就是 value。

如何理解 actor-critic 这种架构？有很多直观的解释，我最喜欢的是用数学式子来解释。你不需要知道式子里每个符号具体是什么，只需要知道：这个式子是在更新 $\theta$——$t$ 时刻的 $\theta$ 变成了 $t+1$ 时刻的 $\theta$，而 $\theta$ 是策略的参数，所以通过这个式子，策略就会逐渐变好，这个式子对应的就是 actor。然后在更新的时候我需要什么？需要 $q$，$q$ 就是值。所以我要更新策略，需要先求出这个值；得到了值可以更新策略，更新完了策略再得到值——这里边也存在着策略和值交互的关系。

具体介绍了这么几种方法：

- **QAC**：最简单的 actor-critic 算法，实际上就是刚才那个式子。
- **A2C**（advantage actor-critic，因为有两个 a）：引入了一个 baseline 来减小估计的方差。
- **off-policy 化**：actor-critic 本质上还是 policy gradient，而 policy gradient 自然是一种 on-policy 的算法。能不能把它变成 off-policy？实际上可以，用一种叫 **importance sampling**（重要性采样）的方法。而且重要性采样不仅仅局限于 actor-critic——前面所有的 on-policy 方法，都可以用重要性采样转成 off-policy 的方法。
- **deterministic actor-critic**：前面介绍的这些都要求策略是随机的，也就是在每个状态有概率选择到所有的 action；我们也可以用确定性的策略，这时候介绍的就是确定性 actor-critic。

这样我们就非常快地介绍完了强化学习原理当中涉及到的关键名词、概念、算法。我相信大家还是有很多没有理解清楚的，没有关系——只要你能大概明白它的脉络，并且接下来根据自己的实际情况制定相应的学习计划，这一讲就达到了它的目的。

### 网格世界：全课程通用的例子

下面进入第一次正式的课：强化学习的基本概念。这些基本概念将在后续课程当中被广泛地使用，所以非常重要。这次课基本上包括两部分：第一部分，通过例子的方法介绍一些概念；第二部分，把这些概念以一种更加正式的方式介绍出来，并且是在 Markov decision process（MDP）框架下。

本课程包括本节课会广泛使用的一个例子，就是 **grid-world example**——网格世界，有一个机器人在里面走。这里边的每一个小网格有不同的类型：

- **accessible**（可进入的）：用白色表示，就是可以进去的；
- **forbidden**（禁区）：用黄色表示；
- **target area**（目标区域）：我们希望机器人能进到这个区域当中。

此外，网格世界是有边界的。机器人可以在相邻的块之间移动，**不能在斜的方向移动**。

为什么要考虑这样一个例子？因为它非常容易理解、非常直观，之后大家会发现，用它来介绍很多概念的时候会非常清晰。

强化学习在这个例子当中的任务是什么？就是机器人要找到一个比较好的路径（a good path）到达目标。这里边有一些问题，比如：怎么样去定义一个路径究竟是好还是坏？这其实是一个非常核心的问题，之后我们会详细定义什么是最优的策略、最优的路径等等。但直观上来说，其实可以先回答：

> **直观判断**：一条好路径应该——尽可能地避免 forbidden area、不要进去；不要有没有意义的拐弯（本来要进 target area，却先走到别处又回去、绕来绕去，这种应该避免）；不要试图超越边界（要往上走或往左走却撞墙，这种也应该避免）。

### 状态与状态空间

用这个例子，我们来介绍整门课程当中的第一个概念：**state（状态）**。

> **定义**：state 描述的是 agent 相对于环境的状况（status）。在 grid-world example 当中，state 指的就是**位置（location）**。

这里有 $s_1, s_2, s_3$ 一直到 $s_9$ 这么多个位置，我们就用这些字母来表示这些状态。要注意，$s_1$ 这些字母实际上是一个**索引**，它真正对应的状态，在这里是二维平面上的位置——$x$ 方向的位置和 $y$ 方向的位置。如果是更复杂的问题，可能除了位置之外还要对应速度；如果是机器人的话，还要对应加速度等等其他类型的状态信息。

如果我们把所有的状态放到一起，就得到了**状态空间（state space）**。"空间"这个词，大家第一次听说的时候可能会感觉很害怕——什么线性空间之类的。实际上不用这么害怕，这里的"空间"其实就是一个**集合（set）**。

> **定义**：状态空间就是把所有的状态 $s_i$ 放到一起得到的集合，记作花体 $\mathcal{S}=\{s_i\}$。

两边花括号代表的就是一个集合。有时候我们会在后面给出 $i$ 的取值范围；有时候不给的话，大家从上下文也可以直接得到 $i$ 的范围。

### 动作与动作空间

下一个概念：**action（动作）**，非常重要的、非常基本的一个概念。action 是什么？就是在每一个状态，实际上有一系列可采取的行动。在这个例子里一共有 5 个行动 $a_1$ 到 $a_5$：

| 动作 | 含义 |
| :--- | :--- |
| $a_1$ | 向上走 |
| $a_2$ | 向右走 |
| $a_3$ | 向下走 |
| $a_4$ | 向左走 |
| $a_5$ | 原地不动（用圆圈表示） |

这张表之后我们会频繁地用到，希望大家能够放到脑子里记一下。把所有这些 action 放到一起，就得到了 **action space（动作空间）**，用花体 $\mathcal{A}$ 表示——和前面一样，它实际上也是一个集合。

值得指出的是，action space 是**和状态依赖的**：不同的状态，它的 action space 是不一样的。这就是为什么我们要写成 $\mathcal{A}(s_i)$——这表示 $\mathcal{A}$ 实际上是 $s_i$ 的一个函数。

### 状态转移

下一个概念：**state transition（状态转移）**。它的意思是：当我采取一个 action 的时候，agent 可以从一个 state 移动到另一个 state，这样的过程就被称为状态转移。举两个例子：

- 我在 $s_1$，采取 $a_2$（往右走），下一个状态就跳到 $s_2$；
- 我在 $s_1$，采取 $a_1$（往上走），下一个状态还是 $s_1$。这是怎么回事？$s_1$ 在边上，往上走会撞到边界——如果边界是一堵墙的话，会被撞回来，还是回到 $s_1$，不会出去。

> **定义**：state transition 实际上定义了 agent 和环境的一种交互行为。

#### 撞墙、禁区与交互规则的自由度

能不能用其他方式来定义这种交互行为？首先，因为这只是一个仿真、一个游戏，实际上可以**任意定义**。比如刚才往上走撞墙会被弹回来，也可以定义成被弹到左边（下一个状态是 $s_4$），甚至被弹到下面（下一个状态是 $s_7$）——因为是游戏，想怎么定义就怎么定义。但实际当中并不是这个样子：机器人就在那里，它要往那边移动一点，不可能想跑到哪个状态就跑到哪个状态。所以实际当中我们不能任意定义，但在游戏当中其实是可以的。

再关注一下 forbidden area。比如我在 $s_5$，采取 $a_2$ 往右走，下一个状态是什么？其实有两种情况：

- **第一种**：forbidden area 虽然是禁区，但仍然**可以进去**，只不过进去会被惩罚。那 $s_5$ take $a_2$，下一个状态就是 $s_6$，也就是它进去了。
- **第二种**：forbidden area 物理上就**无法进入**，比如周围装上了墙，怎么都进不去。那 $s_5$ take $a_2$，就会被弹回来，又回到 $s_5$。

在我们课程当中，考虑的是**第一种情况**：forbidden area 虽然叫 forbidden，但是可以进去，只不过会得到惩罚。这种情况相比第二种，实际上更加一般化、也更加难——为什么？因为如果把一些状态排除掉的话，状态空间就变小了，做搜索的时候会更容易。而且，允许进入 forbidden area 还会出现比较有意思的现象：虽然进去会得到惩罚，但也许穿过 forbidden area 反而是到 target area 的最近路径，所以有可能 agent 会冒险进到 forbidden area、再从那里到 target area——这会带来一些比较有意思的行为，之后我们会介绍。

#### 从表格到条件概率

State transition 可以用**表格（tabular）**的形式表现出来：表格的每一行对应一个状态，每一列对应一个 action。比如在 $s_1$ take $a_1$（往上走），会被弹回来，下一个状态就是 $s_1$。任何一个状态、任何一个 action 在表里都有定义。但表格的形式虽然直观，实际当中用起来是比较受限的——因为它**只能表示 deterministic（确定性）的情况**。比如在 $s_1$ take $a_1$，我有可能跑到 $s_1$，也可能被弹回到 $s_4$，甚至可能被弹回到 $s_7$——一个动作对应多个可能状态，这时候表格就无法表达了。

更一般的方法是用 **state transition probability（状态转移概率）**，这是我们第一次把 probability 引进来。它的直观是什么？比如"我在 $s_1$、take $a_2$（往右走）、下一个状态是 $s_2$"，这是一个语言的叙述；它的数学表达，就用**条件概率（conditional probability）**——这也是我们第一次提到条件概率。如果大家对这个不熟悉，可以看我那本书的附录，里面有针对条件概率和其他概率论的初步介绍；没学过也没有关系，因为它非常直观：**如果我现在在 $s_1$、并且 take $a_2$，那么我下一个时刻跳到 $s_2$ 的概率是多少？**

$$p(s_2 \mid s_1, a_2) = 1$$

同样的，在 $s_1$ take $a_2$，下一个时刻跳到其它任意一个状态 $s_i$（$i \neq 2$）的概率：

$$p(s_i \mid s_1, a_2) = 0, \quad i \neq 2$$

这就是用条件概率来描述 state transition。当然这仍然是一个确定性的例子，但条件概率能够描述**随机性**的情况。比如有风：机器人本来在 $s_1$ 往右走会到 $s_2$，但因为风的原因，它可能以 50% 的概率跑到 $s_2$、以 50% 的概率跑到 $s_5$：

$$p(s_2 \mid s_1, a_2) = 0.5, \qquad p(s_5 \mid s_1, a_2) = 0.5$$

所以概率的形式是更加一般化的，随机的 state transition 也可以用它描述。

### 策略：强化学习独有的概念

下面介绍一个非常重要的概念：**policy（策略）**。这是强化学习当中独有的一个概念。

> **定义**：policy 告诉 agent——我如果在一个状态，应该 take 哪一个 action。

直观上，policy 用箭头来表示：9 个状态，每一个状态都对应一个箭头（那个圆圈代表待在原地不动）。基于这个策略，实际上可以得到一些 path，或者叫 **trajectory（轨迹）**——这个之后会详细介绍，这里先通过直观展示。比如我从某个格子出发：策略（绿色箭头）告诉我应该往右走，根据刚才的状态转移，下一个时刻我就被跳到右边那个状态；到了那里，策略告诉我向下走，我就跳到下面的状态；依次类推——策略让我往下走我就跳下去，策略让我往那边走我就过去，最后策略让我待在原地不动。所以从不同格子出发，按照"策略 + 状态转移"走，就会得到不同的 path，这是比较直观的。

#### 从箭头到条件概率

刚才的策略是用箭头表示的，实际当中稍微复杂一点的情况都没法用这么直观的形式表示，所以要用一种能描述复杂情况、一般化情况的方法——**数学的表达方式**，仍然是用条件概率。我们举一个例子，针对 $s_1$ 的策略 $\pi$：这里边的 $\pi$ 一般情况下指圆周率，但在强化学习当中，$\pi$ 就**统一指策略**。$\pi$ 是一个条件概率，它指定了任何一个状态下、任何一个 action 的概率是多少：

$$\pi(a_1 \mid s_1) = 0, \qquad \pi(a_2 \mid s_1) = 1, \qquad \pi(a \mid s_1) = 0 \ \text{（其它所有 action）}$$

针对一个状态，它所有 action 的概率之和应该加起来等于 1。这只是一个状态的策略；还有 $s_2$ 一直到 $s_9$——**对每一个状态，我们都要有它的策略**。

#### 随机性策略与编程实现

刚才的情况是确定性的：在 $s_1$ 我一定会 take $a_2$。实际上也存在**不确定性的（stochastic）policy**。比如从某个格子出发，策略有 0.5 的概率往右走、另外 0.5 的概率往下走。那么同样从那里出发，我有可能得到这样一条轨迹，也有可能得到那样一条轨迹——策略是不确定的。用条件概率来表示也非常简单：

$$\pi(a_2 \mid s_1) = 0.5, \qquad \pi(a_3 \mid s_1) = 0.5, \qquad \text{其它 action 的概率全为 } 0$$

它俩相加之和等于 1；其它 action 的概率有时候我们就省略掉了，但大家要知道，**每一个 action 其实都有概率，只不过它是 0 而已**。

策略也可以用**表格**的形式表达出来：每一行对应一个状态，每一列对应一个 action。随便看一个格子，比如 $s_5$ 采取往下走这个 action 的概率是 1——对 $s_5$ 来说它是确定性策略；而 $s_1$ 有 0.5 的概率是 $a_2$、0.5 的概率是 $a_3$——对 $s_1$ 来说它是随机性的（stochastic）策略。这种表格是非常 general 的，确定性和随机性的情况它都能够描述。实际上我们**编程的时候就是这么做的**：用一个数组或者一个矩阵来表示这样一个策略。

最后提一下实际当中怎么**执行**一个策略。比如某个状态有 0.5 的概率是 $a_2$、0.5 的概率是 $a_3$，编程时怎么实现？其实也很简单：

```text
从 0 到 1 做一次均匀分布的随机采样（很多软件都有这个功能），得到一个数 x：
  x 落在 0 ~ 0.5   -> 采取 action a2
  x 落在 0.5 ~ 1   -> 采取 action a3
```

读图说明：按概率大小划分 [0,1] 区间，采样值落在哪一段就执行哪一段对应的动作，动作被执行的频率自然就等于它的概率。

## 从 Reward 到 State Value：给策略打分的数学工具
> 对应块：BLK02 | 覆盖分集：P03-P05 | 块标题（分集名）：《第1课-基本概念（Part2-Reward,re》

上一讲我们把状态、动作、状态转移这些积木搭好了，这一讲接着搭剩下的几块：reward、trajectory、return、episode，最后把它们全部装进一个正式的框架——Markov decision process（MDP）。装完之后，我会用几个例子回答一个更根本的问题：为什么 return 这么重要？怎么计算它？顺着这个问题走下去，我们就会碰到这一阶段真正的两个主角——state value 和贝尔曼公式。

### Reward：一个数背后的引导艺术

Reward 是强化学习当中非常有独特性的一个概念。首先它是一个数——一个实数、一个标量。在 agent 采取了一个动作之后，它会得到这样一个数。这个数是有含义的：

- 如果这个数是**正数**，代表我们对这样的行为是**鼓励**的；
- 如果这个数是**负数**，代表我们不希望这样的行为发生，实际上是对行为的一个**惩罚**。

这里有两个问题值得停下来想清楚。

第一个问题：如果不给 reward，或者说把它设为 0，代表什么？这个回答起来相对来说会比较复杂，不过总的来说就是没有 punishment——而在一定程度上，没有惩罚就是鼓励。

第二个问题：能不能反过来，用正数代表 punishment、用负数代表鼓励？实际上是可以的，这是一种数学上的技巧，本质上来说得到的东西是一样的。你想，如果正数代表鼓励，agent 希望得到越来越多的正数；如果正数代表惩罚，agent 自然要去 minimize 这个惩罚，让惩罚越来越少。两种写法，优化方向等价。

在 grid-world 例子当中，我们的 reward 是这样设计的：

- agent 想要逃出四周的边界，每次有这样的动作，就给它 $r_{\text{bound}} = -1$；
- agent 要进到 forbidden area 里去，有这样的倾向时，给它 $r_{\text{forbid}} = -1$；
- agent 进到了 target area，到达了目标，给它鼓励，$r_{\text{target}} = +1$；
- 其它所有行动得到的 reward 都是 0，比如从这走到那、在原地保持不动等等。

理解 reward 有一个很好的角度：它可以被理解成是一个 **human-machine interface**——我们和机器进行交互的一种手段。因为 reward 设计相对直观，我们就可以通过它引导 agent，告诉它应该怎么样做、不应该怎么样做。在上面这个例子里，通过设计这样的 reward，agent 就不会跑出边界、不会进 forbidden area，而是尽量地进到 target area。**我们通过设计 reward 来实现我们的目标。**

### 用表格和条件概率表示 Reward

Reward 可以用 **tabular representation** 来表示：表格的每一行对应一个状态，每一列对应一个 action。比如在状态 $s_1$ 采取 action $a_1$，我得到的一个 reward 就是 $r_{\text{bound}}$。这个表格很直观，但它的应用比较有限——为什么？因为它只能表示 **deterministic（确定性）** 的情况：在一个状态采取一个行动，我**一定**会得到一个确定的 reward。如果实际上 reward 的大小是不确定的，表格的形式就不再适用了。

这时候要用更一般化的方法——还是老朋友，条件概率。比如在状态 $s_1$ 选择了 action $a_1$（往上走），直观上它的 reward 是 $-1$。写成数学就是：

$$p(r = -1 \mid s_1, a_1) = 1, \qquad p(r \neq -1 \mid s_1, a_1) = 0$$

你看，这其实也是确定性的：得到 $-1$ 的概率是 1，得不到 $-1$ 的概率是 0。确定性只是随机性的一个特例。

那真正随机的 reward 长什么样？举个生活中的例子：比如我们学习得非常努力，那么我一定会得到 reward——努力学习这个 action 是值得鼓励的，一定会有一个正的 reward。但是我能得到多少，可能由很多因素决定，有一定的随机性。也就是说，**一定会得到正 reward，但具体值不确定**，这时条件概率描述的就是这种分布。

### Trajectory 与 Return：给策略打分的起点

下一个概念叫 **trajectory**。它其实刚才已经隐约出现了——它是一个 **state-action-reward 链**。具体来说，考虑这样一条轨迹：

```text
s1 --a2,r=0--> s2 --a3,r=0--> s3 --...--> s9(target, r=+1)
```

从初始状态 $s_1$ 出发，take action $a_2$，得到 reward 0，跳到 $s_2$；再接着 take action $a_3$，得到 reward 0；这样持续下去，最后到达目标。这样一个链就被称为一个 trajectory，里面包含了三个部分：状态、action、reward。

然后是一个非常重要的概念——**return**，我希望大家能够注意起来。Return 是针对一个 trajectory 而言的：**把沿着这条轨迹所得到的所有 reward 加起来**。上面这条轨迹是 0、0、0……到达目标之后是 1，加起来 return 就是 1。

如果策略不同，从同一起点出发会得到不同的轨迹。比如另一个策略往下走、再往下、再往右，这条轨迹上依次得到 0、$-1$、0、$+1$，加起来 return 就是 0。

其实我可以先给大家透露一些 return 的作用。刚才分析了这两条轨迹——究竟哪条好？或者哪个 policy 好？直观上来说，第一个比较好，因为它没进 forbidden area；第二个进了，应该避免。但这是直观，**数学上怎么刻画"第一个比第二个好"？** 比较 return 就行了：第一个 return 是 $+1$，第二个是 $0$，第一个策略能得到更多的 reward，所以第一个好。这就是数学和直观的对接——我们在数学上描述策略好坏，就要通过 return 这个概念。Return 可以用来**评估一个策略是好还是坏**，只有能评估，我们才知道当前策略不好时，下一个策略会不会更好，才能不断地改进策略。

### Discounted Return：让无穷长的轨迹收敛

Return 仍然是 return，但它叫 discounted。究竟是怎么回事呢？先看一个例子。

之前的轨迹到达 target 之后，其实策略还在持续地运行：每次见到这个 target 都会得到 $+1$、$+1$、$+1$……agent 一直采取 $a_5$ 原地不动，还是在 $s_9$。所以这条 trajectory 是**无限长**的。把 return 加起来的话，前面还是 0，到达目标之后每次都 $+1$，一直加下去就是无穷——return 沿着这条无穷长的轨迹**发散掉了**。

怎么解决？引入 **discount rate**，用 $\gamma$ 表示，它是 0 到 1 之间的一个数。discount rate 和 return 相结合，就得到了 discounted return：

$$G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \gamma^3 R_{t+4} + \cdots$$

数字还是刚才那些数字，只是每个 reward 前面都加上了折扣：$\gamma$、$\gamma^2$、$\gamma^3$……可以算一下：前面的项不用考虑，把 $\gamma^3$ 提出来，后面是一个 $1 + \gamma + \gamma^2 + \cdots$ 的无穷数列。学过高等数学的话，这是个比较基础的知识：**当 $\gamma < 1$ 时，这个无穷数列的和等于 $\frac{1}{1-\gamma}$**。所以最后的 discounted return 就变成了一个有限的值。

通过引入 discounted return 我们得到了什么？两件事：

- **第一，把发散的求和变成有限值**，无穷长的轨迹也能算 return 了；
- **第二，它能平衡更远未来的 reward 和更近未来的 reward**。当 $\gamma$ 趋向于 0 时，因为后面的次方数非常高，$\gamma^3$、$\gamma^4$、$\gamma^5$ 会很快衰减掉，最后的值主要依赖于最开始所得到的 reward；相反，如果 $\gamma$ 趋向于 1，未来的 reward 衰减得比较慢，积累起来的就会比较大。

之后我们会看到，通过控制 $\gamma$，我们能够控制 agent 学到的策略。简单来说：**减小 $\gamma$ 会让它变得更加近视**，更注重最近的 reward；**$\gamma$ 比较大，它会变得更加远视**，更注重长远的 reward。

### Episode：有限步的试验与持续不断的任务

Episode 是强化学习中一个很重要的概念。Episode 会伴随一个 **terminal state**——这个我们刚才没明讲，但已经隐式地包含在里面了：从起点出发，沿着轨迹走到目标的时候就停了，trajectory 最后停掉了。这样的一个 trajectory 我们称为一个 episode，或者叫一个 **trial**，就是"试"的意思。

- 一个 episode 通常都是**有限步**的，这样的任务被称为 **episodic tasks**；
- 有些任务**没有 terminal state**，意味着 agent 和环境的交互会永远持续下去，这样的任务称为 **continuing tasks**。

什么样的任务是 continuing 的？其实在现实世界当中，找不到永远持续下去的任务——当然，时间比较长的话，我们会近似地把这样的任务说成是 continuing tasks。

回到 grid-world：到达目标区域之后，究竟是停在那不动，还是像计算 discounted return 时那样，继续执行策略、一直停到 $s_9$ 那边？实际上有一种**统一的方法**来描述 episodic 和 continuing tasks——在本课程当中我们并不区别这两种，因为我们把 episodic task 转换成了 continuing task。转换有两种方法：

- **第一种**：把 target state 认为是一个特殊的 **absorbing state**（吸收态）。设置状态转移概率的时候，只要当前状态就是 target，不论采取什么 action 都会再回到这个状态；或者修改 action space，让这个状态下的 action 只剩下"留在原地"。当然还要再补一条：之后所得到的所有 reward 全都是 0。
- **第二种**：把 target state 当作一个**普通的状态**，它也有策略——策略好的话它就会一直留在那，能一直收集正的 reward；策略不好的话它还可能跳出来。

在我们这个课程当中，使用的是第二种。第二种相对来说更具一般化：目标不区别对待，被当成一个一般的状态去学习，相对来说会耗费更多的搜索，但是更加一般化。

### 把概念装进 MDP 的框架

到此为止，我们把强化学习中比较重要的概念都通过例子的方法介绍了一遍。下面把这些概念放到 **Markov decision process**（MDP）当中——这是一个框架，我们用相对正式的方式把这些概念重新介绍一遍。

MDP 有几个要素。**第一个要素是集合（sets）**：

- 状态集合，就是之前提到的 state space；
- 动作集合，action space；
- reward 集合——从 $s$ 出发 take action $a$，得到的 reward 一定是来源于一个集合。

**第二个要素是概率分布（probability distribution）**：

- **state transition probability**：当前在 $s$，采取一个行动，跳到 $s'$ 的概率是多少；
- **reward probability**：当前在 $s$，take action $a$，得到 $r$ 的概率是多少。

**第三个要素是 policy**：在状态 $s$ 有一个策略，这个策略会告诉你采取 action $a$ 的概率究竟是多少。

最后，MDP 一个比较独特的性质，就是 **Markov 性质**，也叫 **memoryless property**（无记忆性）。这个性质是什么意思？其实就是**和历史无关**。通过这个式子会看得比较清晰：

$$p(S_{t+1} \mid S_t, A_{t+1}) = p(S_{t+1} \mid S_0, A_1, S_1, \ldots, S_t, A_{t+1})$$

我最开始的状态是 $S_0$，采取 action，慢慢走到 $S_t$，在 $S_t$ 采取 action $A_{t+1}$，这时候跳到下一个状态 $S_{t+1}$ 的概率，等于我完全不考虑这些历史——不管之前在什么地方，反正现在我在 $S_t$、take action $A_{t+1}$、跑到 $S_{t+1}$——两个概率一模一样。也就是说，之前的历史是完全没有关系的。类似地，在 $S_t$ take action $A_t$ 得到的 reward，也和之前的历史没有关系。

很有意思的一点：如果将来有人问起来什么是 Markov decision process，你就可以回答——**Markov decision process 就是 Markov decision process**。这好像是废话，但实际上我想说的是：用这 3 个关键词就可以描述它——

- **Markov** 对应 Markov property，也就是 memoryless property；
- **decision** 对应 policy，因为 decision 就是决定，决定就是策略；
- **process** 就是我从什么状态跳到什么状态、采取什么 action 等等，这些由 sets 和 probability distribution 来描述。

这 3 个关键词很好地概括了 MDP。

回到 grid-world example。这样的例子可以用图来概括：每一个圆对应一个状态，这些边对应采取 action 时会转移到什么样的下一个状态。比如在这有 0.5 的概率向右走，从 $s_1$ 意味着有 0.5 的概率跑到 $s_2$。

```text
        0.5
  (s1) -----> (s2)        圆 = 状态
   |                       边 = 采取 action 后的转移
   | 0.5                   边上的数字 = 转移概率
   v
  (s3)
```

注意，这个图描述的是 **Markov process（马尔科夫过程）**，而我们刚才讲的是 Markov decision process。它俩的关系其实很简单：**如果我的 decision——也就是 policy——确定了，那么这个 policy 就和整个系统融为一体，MDP 自然就变成了一个马尔科夫过程。**

到这里，本节课的第一部分就结束了：我们通过 grid-world example 包括最后的 MDP，介绍了状态、动作、状态转移、reward、trajectory、episode、return、discounted return 这些关键概念，它们在后面的课里马上就会用到。

### 为什么 Return 重要：三个策略的对比

从这次课开始我们介绍贝尔曼公式。这次课要抓住两个东西：一个核心概念是 **state value**，一个 fundamental tool（很重要的工具）是**贝尔曼公式**。路线是：先用例子说明为什么要研究 state value 和贝尔曼公式，然后正式定义 state value，接着推导贝尔曼公式、写出它的 matrix-vector form、讲怎么从贝尔曼公式求解 state value，最后从 state value 过渡到 action value。

第一个例子想说明的是：**为什么 return 是重要的**。Return 上次课介绍过了，复习一下：当有一条轨迹，沿着它我会得到很多的 rewards，把这些 reward 求和——当然要加上 discount rate——得到的就是 discounted return。

大家看这 3 个例子，它们的环境是一模一样的：这是目标、这是 forbidden area、白色的是 accessible area。不同的是三个策略在 $s_1$ 处的选择：

- 策略 1 在 $s_1$ 向下走；
- 策略 2 在 $s_1$ 向右走；
- 策略 3 有 50% 的概率向右、50% 的概率向下。

在其它状态，它们的策略都相同。要回答的问题是：从 $s_1$ 出发，哪一个策略最好、哪一个最差？直观上来说，第一个最好，第二个最差，第三个不好也不差——因为第一个不会进 forbidden area，第二个会进去，第三个有一定概率进去。**非常重要的就是：能不能用数学来描述这种直观？** 答案是可以的，我们的数学工具就是 return。

下面分别计算这 3 个策略从 $s_1$ 出发的 return。

**策略 1**：从 $s_1$ 走到 $s_3$ 得到 0，从 $s_3$ 到 $s_4$（目标）得到 1，之后一直待在 $s_4$，每次都是 1。把 $\gamma$ 提出来，后面是一个数列，整理后得到：

$$\text{return}_1 = \frac{\gamma}{1-\gamma}$$

**策略 2**：沿着它的轨迹走，首先会得到一个 $-1$（进到了 forbidden area），然后进到 target area，一直得到 $+1$、$+1$……后面加起来是 $\frac{\gamma}{1-\gamma}$，前面是 $-1$：

$$\text{return}_2 = -1 + \frac{\gamma}{1-\gamma}$$

**策略 3**：这个策略是 stochastic 的，一半概率向右、一半概率向下。向右走那条轨迹的 return 就是刚才策略 2 算出的 $-1 + \frac{\gamma}{1-\gamma}$；向下走那条轨迹的 return 就是策略 1 算出的 $\frac{\gamma}{1-\gamma}$。两边分别乘上概率（类似于权重）再相加：

$$\text{return}_3 = 0.5\left(-1 + \frac{\gamma}{1-\gamma}\right) + 0.5 \cdot \frac{\gamma}{1-\gamma} = -0.5 + \frac{\gamma}{1-\gamma}$$

严格来说，$\text{return}_3$ 已经不再是 return 的基本概念了——return 的基本概念是针对**一个**轨迹定义的，而现在我们有两个轨迹，实际在做的是**求平均值**。求平均值可以理解为求 **expectation**，所以 $\text{return}_3$ 严格上来说，就是我们接下来要介绍的 state value。这里先不用纠结，就认为它是从 $s_1$ 出发所得到的一个平均的 return。

现在把三个 return 摆在一起比较：

| 策略 | return | 直观判断 |
| :--- | :--- | :--- |
| 策略 1（向下） | $\dfrac{\gamma}{1-\gamma}$ | 最好，不进 forbidden area |
| 策略 3（各 50%） | $-0.5 + \dfrac{\gamma}{1-\gamma}$ | 居中，有一定概率进去 |
| 策略 2（向右） | $-1 + \dfrac{\gamma}{1-\gamma}$ | 最差，必然进去 |

非常明显：return 1 最大，return 2 最小（因为它带 $-1$），return 3 居中（$-0.5$）。**数学上的不等式和我们的直观是一致的**——我们就建立起了数学和直觉的关系，而这个关系的关键纽带就是 return。所以 return 非常重要，它能用来评估策略。

### Bootstrapping：从自己出发迭代出答案

Return 这么重要，怎么计算它？大家可能会说，刚才不是算过了吗？为什么还要讲？因为刚才用的是 return 最本质的定义，实际上我们有**更好的方法**。

考虑这样一个例子：有 4 个状态 $s_1, s_2, s_3, s_4$，策略已经给出来了（就是那些箭头），对应的 reward 是 $r_1, r_2, r_3, r_4$——不用管具体的值，我们就用字母表示。问题是怎么计算分别从不同状态出发所得到的 return。

首先引入符号：用 $v_i$ 表示从 $s_i$ 出发的 return。先看 $s_1$：沿着轨迹它会跳到这边、跳到这边、再按策略跳、再跳，之后还会继续无穷地走下去。这条轨迹对应的 return 是：

$$v_1 = r_1 + \gamma r_2 + \gamma^2 r_3 + \gamma^3 r_4 + \cdots$$

这是一个非常简单的定义。其它的 $v_2$ 也一样：$r_2 + \gamma r_3 + \gamma^2 r_4 + \cdots$，照定义都能写出来。

下面介绍第二种方法——这种方法很简单也很有意思。回到 $v_1$：它等于 $r_1$ 加上后面一堆 reward，我把 $\gamma$ 提出来，得到

$$v_1 = r_1 + \gamma \underbrace{(r_2 + \gamma r_3 + \gamma^2 r_4 + \cdots)}_{=\ v_2}$$

括号里面这个是什么？回头一看，$r_2 + \gamma r_3 + \gamma^2 r_4 + \cdots$ 就等于 $v_2$！所以：

$$v_1 = r_1 + \gamma v_2$$

这个数学已经非常清晰了。它的直观是什么意思？我从 $s_1$ 出发跳到 $s_2$，这个过程中首先得到 $r_1$；后面的路还很长，没有关系——我知道我跳到了 $s_2$，从这出发我得到的 return 一定是 $v_2$。类似地：

$$v_2 = r_2 + \gamma v_3, \qquad v_3 = r_3 + \gamma v_4, \qquad v_4 = r_4 + \gamma v_1$$

这组式子告诉我们：**从不同状态出发得到的 return，依赖于从其它状态出发所得到的 return。** 这个 idea 在强化学习当中就被称为 **Bootstrapping**，是很重要的一个概念。

Bootstrapping 从历史发展的角度来说有不同的定义。从最字面的意义看，bootstrap 指的是我们穿鞋的时候，鞋帮上有一个带子，拉那个带子可以帮我们更好地把鞋穿上去。但后来引申出一个具有讽刺意义的意思：想象一下，我们双手拉着鞋后面的两个带子使劲往上拉，能不能把自己拉起来、让两只脚腾空？显然不行——所以它讽刺的是那些异想天开的做法。现代的意思就是引申出来的：**我从自己出发，然后不断地迭代，得到我要的结果。** 这就是一个很好的例子：我要得到 $v_1, v_2, v_3, v_4$，我可以从我自己出发，最后得到我自己。

大家可能会问：这怎么可能呢？我要求解的就是 $v$，可我还要事先知道 $v$，这好像陷入了不可能解决的问题。直观上不可能，但看数学就会觉得非常简单。

首先把这组式子写成矩阵和向量的形式：左边写成向量 $(v_1, v_2, v_3, v_4)^{\mathsf T}$；右边第一项是 $r$，整理成一个向量；第二项是 $\gamma$ 乘以 $(v_2, v_3, v_4, v_1)^{\mathsf T}$——**注意这个顺序不是 $v_1, v_2, v_3, v_4$**，所以我们要整理一下，把这个顺序恢复，恢复之后它就变成了一个矩阵作用在 $v$ 上：

$$v = r + \gamma P v$$

这个式子非常简单。$v$ 是未知量；$r$ 是 immediate reward，我知道；$\gamma$ 我知道；$P$ 矩阵我也知道——它对应的实际上是策略再加上 state transition 的这些东西，之后我们会详细介绍。学过线性代数的应该都能求解：把右边移到左边，

$$(I - \gamma P)v = r$$

再把矩阵求逆、乘到右边，就解出了 $v$：

$$v = (I - \gamma P)^{-1} r$$

这个例子说明了什么？它告诉了我们一个公式——**这个公式实际上就是贝尔曼公式**。当然，这是针对非常简单的、特别是 deterministic 的情况，后面我们会更正式地介绍一般化的贝尔曼公式。

虽然简单，这个例子告诉了我们非常重要的一个 idea：**一个状态的 value 实际上依赖于其它状态的 value**——这就是 bootstrapping。另外，**matrix-vector form 非常有用**：只看某一个公式是不行的，但把所有公式组合到一起得到 matrix-vector form，就很容易求出来、理解怎么求解 state value。

当然，我们现在还没有正式定义 state value，这些只是例子。我们再做一个例子加深理解——就是最开始考虑的那个 grid-world 例子：能不能写出来在这个策略下不同 return 之间的关系，也就是写出贝尔曼公式？实际上非常容易。从 $s_1$ 出发，直接跳到 $s_3$：首先得到一个 0 的 reward，然后跳到了 $v_3$，$v_3$ 究竟是什么我不用管，反正从那出发一定得到的就是 $v_3$：

$$v_1 = 0 + \gamma v_3$$

类似地，从 $s_2$ 跳到目标 $s_4$，首先得到一个 1，再加上从 $s_4$ 出发一定得到的 $v_4$。这样得到一组线性方程，非常简单，可以用手求解，也可以用程序求解，这里就不再展开细节了。

### State value 的正式定义

现在正式介绍 state value。先引入一些符号。看这个最简单的单步过程：

```text
        At            Rt+1
  St ------->  ...... ------> St+1
 (当前状态)   (采取动作/获得奖励)  (下一状态)
```

$S_t$ 指的是当前的状态，在当前状态下采取的动作是 $A_t$，得到的下一个 reward 是 $R_{t+1}$，跳到的下一个状态是 $S_{t+1}$。这里 $t$ 指当前的时刻，$t+1$ 指下一个时刻。

值得指出的是，有时候我们也会把 $R_{t+1}$ 写成 $R_t$——也就是在 $S_t$ 采取 $A_t$ 得到的 reward 记作 $R_t$。当然一般来说我们都写成 $R_{t+1}$，从数学上来说它们没有本质区别，只是一个习惯。

注意：这里所有的 $S$、$A$、$R$ **全是大写**，那就代表它们是 **random variable（随机变量）**——我们可以对它们做一系列操作，比如常见的 expectation。另外，这个过程中的所有跳跃都是由概率分布决定的：

- 在 $S_t$ 采取什么动作，由 **policy** 决定；
- 在 $S_t$ take $A_t$ 得到什么 reward，由 **reward probability** 决定；
- 在 $S_t$ 采取 $A_t$ 跳到哪个状态，由 **state transition probability** 决定。

单步过程可以推广到多步：从 $S_t$ 出发，take $A_t$，跳到下一个状态，得到 reward，这样持续下去，就得到了一个 **multi-step trajectory**。对这条轨迹当然可以求 discounted return，用大写的 $G_t$ 表示，它是对这些 immediate reward 的相加，并考虑 discount rate $\gamma$：

$$G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \cdots$$

因为 $R_{t+1}$、$R_{t+2}$ 等等全都是 random variable，所以 $G_t$ 也是一个随机变量。

有了这些准备，就可以正式定义 state value 了。实际上它非常简单：$G_t$ 是一条 trajectory 的 discounted return，**state value 就是 $G_t$ 的 expectation（期望值）**——或者叫 expected value、mean、average，它们都代表同一个意思，就是平均值：

$$v_\pi(s) = \mathbb{E}\left[G_t \mid S_t = s\right]$$

注意这是一个 **conditional expectation**：当前的状态要取一个具体的值 $s$。State value 的全称叫 **state-value function**，简称 state value，记作 $v_\pi(s)$。

这里有几点点要说明：

- **它是 $s$ 的函数**：从不同的 $s$ 出发，得到的轨迹不同，显然 discounted return 不同，求平均也不同。
- **它也是策略的函数**：本来可以写成 $v(s, \pi)$，把 $\pi$ 当作一个变量放进括号里；但为了简单起见，我们写成 $v_\pi(s)$，把 $\pi$ 放到下标。显然，不同的策略得到不同的轨迹，不同的轨迹得到不同的 return，进而得到不同的 state value。
- **"value" 不仅仅是一个数值**，它也代表一种**价值**：当一个状态的 state value 比较大时，代表这个状态是比较有价值的——因为从这个状态出发，会得到更多的 return。

最后回答一个问题：**return 和 state value 有什么区别？** 在刚才的 motivating example 里我们反复提到 return，现在定义的是 state value，它们的区别和联系其实非常简单：

> **定义**：Return 是针对**单个 trajectory** 求的；state value 是对**多个 trajectory** 得到的 return 再求平均值。

如果从一个状态出发可能得到多条轨迹，return 和 state value 显然有区别；但如果一切都是确定性的、只能得到一条 trajectory，那从该状态出发得到的 return 和它的 state value 就是一样的。

回头看那 3 个例子，它们分别对应 3 个策略 $\pi_1, \pi_2, \pi_3$。现在计算在三个不同策略下同一个状态 $s_1$ 的 state value——这个计算非常简单：

- $\pi_1$ 下从 $s_1$ 出发只有唯一一条轨迹，这条轨迹的 return 就是它的 state value；
- $\pi_2$ 下同样只有一条轨迹，state value 就是沿这条轨迹的 return；
- $\pi_3$ 稍微麻烦一点，它有两条轨迹，state value 是这两条轨迹 return 的平均值——把概率乘到前面去，这实际上就是 expectation 的求法。

结果显然：$v_{\pi_1}$ 最大，$v_{\pi_2}$ 最小，$v_{\pi_3}$ 居中——所以第一个策略最好，第二个策略最差。State value 一登场，"评估策略"这件事就有了正式的数学载体。而要真正算出它、用好它，靠的就是下一节的主角：贝尔曼公式。

## 贝尔曼公式详解：从逐项推导到矩阵求解，再到贝尔曼最优公式
> 对应块：BLK03 | 覆盖分集：P06-P10 | 块标题（分集名）：《第2课-贝尔曼公式（贝尔曼公式的详细推导）》

上一节我们已经定义了 state value，并且通过例子说明了它非常重要。那接下来一个很自然的问题就是：**怎么把它计算出来？** 主要的工具就是这个贝尔曼公式。贝尔曼公式用一句话来描述就是：**它描述了不同状态的 state value 之间的关系。**

先提醒一句：这部分看上去会有一些数学，但实际上并没有那么难，所以希望大家能稍微耐心一点。而且我们刚刚通过 motivating example 已经建立起了一些直观概念——这些直观能帮助我们更好地理解接下来的数学。

### 从一条 trajectory 开始：把 return 拆成两半

考虑一条 trajectory：我从状态 $s$ 出发，take 一个 action，然后一直走下去。这条 trajectory 可以计算它的 discounted return $G_t$——这个我们已经看过了。

这里面新的东西是什么？就是把 $G_t$ 分成两部分：把 $\gamma$ 提取出来，括号里边这一部分实际上就是 $G_{t+1}$。所以：

$$G_t = R_{t+1} + \gamma\, G_{t+1}$$

```text
G_t = R_{t+1} + γ·G_{t+1}
      └───┬──┘   └───┬───┘
     immediate       future
      reward         reward
```

也就是说，$t$ 时刻我能得到的 return，等于**立即能拿到的 immediate reward**，再加上**从下一时刻出发我能得到的 return**（乘上 discount rate）。

现在把这个式子两边取期望。期望对加号是可以拆开的，于是右边就变成了两个 expectation：

$$v_\pi(s) = \mathbb{E}[R_{t+1} \mid S_t = s] + \gamma\, \mathbb{E}[G_{t+1} \mid S_t = s]$$

下面要做的，就是分别分析这两个 expectation，把它们的形式算出来——这样我们就得到了贝尔曼公式。

### 两个期望，各个击破

#### 第一项：immediate reward 的均值

当前时刻我在状态 $s$，立即拿到的 reward 是 $R_{t+1}$。它的 mean 是什么？我们把计算流程过一遍：

在状态 $s$，我其实有多个 action 可以去 take。我 take action $a$ 的概率就是策略 $\pi(a \mid s)$；当我 take 了 action $a$ 之后，我得到 reward $r$ 的概率是 $p(r \mid s, a)$，而 $r$ 本身的值就是这个 $r$。按期望的定义，把这些概率乘上取值、全加起来，就是答案：

$$\mathbb{E}[R_{t+1} \mid S_t = s] = \sum_{a} \pi(a \mid s) \sum_{r} p(r \mid s, a)\, r$$

第一项究竟是什么？它非常简单——**就是我能得到的 immediate reward 的一个均值**。

#### 第二项：future reward 的均值

第二项是从当前状态 $s$ 出发，下一个时刻之后的 return 的 mean。这个是有点意思的，我们来看一下它等于什么。

我从当前 $s$ 出发，其实有多个选择，可以跳到不同的 $s'$：我跳到某个 $s'$ 的概率是 $p(s' \mid s, a)$，跳过去之后、从 $s'$ 出发所能得到的 return 的均值，就是针对 $s'$ 的那个量。把这些按概率加权、一相加，就是这个 expectation。

这里中间有一个小步骤值得停下来讲：式子里本来有一项是"在已知当前状态是 $s$ 的条件下"的 expectation，但它可以去掉——**因为我已经知道下一个状态是 $s'$ 了，其实就不用关心我之前究竟处在什么状态了**。所以条件在 $s$ 上的条件期望，就等于条件在 $s'$ 上的条件期望。

> **提示**：这个性质实际上就是 Markov 性质，也就是 memoryless（无记忆）的性质。

从 $s'$ 再出发，计算之后所能得到的 return 的平均值——这就是一个 state value，只不过是针对 $s'$ 的 state value，也就是 $v_\pi(s')$。

还剩一件事没算：从 $s$ 到 $s'$ 的概率 $p_\pi(s, s')$ 是什么？从 $s$ 出发我有多种选择（不同的 action），我选择某个 action 的概率是 $\pi(a \mid s)$，选了这个 action 后跳到 $s'$ 的概率是 $p(s' \mid s, a)$。把所有 action 上的概率加起来：

$$p_\pi(s, s') = \sum_{a} \pi(a \mid s)\, p(s' \mid s, a)$$

所以第二项最终就是：

$$\mathbb{E}[G_{t+1} \mid S_t = s] = \sum_{s'} p_\pi(s, s')\, v_\pi(s')$$

这里边其实我们用到了概率论当中的很多小技巧。如果对概率论还不太熟悉，可以去看一下我们那本书附录里的介绍。

### 贝尔曼公式登场：它到底在说什么

把两个 expectation 分别代回去，就得到了贝尔曼公式：

$$v_\pi(s) = \sum_{a} \pi(a \mid s) \Big[ \sum_{r} p(r \mid s, a)\, r + \gamma \sum_{s'} p(s' \mid s, a)\, v_\pi(s') \Big]$$

也可以把第一项提取成一个记号、第二项里的概率提取成 $p_\pi(s, s')$，写成更简洁的：

$$v_\pi(s) = r_\pi(s) + \gamma \sum_{s'} p_\pi(s, s')\, v_\pi(s')$$

大家**不要被这个公式所吓到**，其实它非常简单，之后我们还会通过例子再看一遍。这里有几个重要的点需要说明：

- **这就是"传说当中的贝尔曼公式"**。它在干什么？它描述了不同状态的 state value 之间的关系——左边是 $s$ 的 state value，右边是 $s'$ 的 state value，它们的关系就通过这个式子表达出来。
- 式子包含两项：第一项是 immediate reward 的一个 mean，第二项是 future reward 的一个 term。
- **非常非常重要的一点：这不是一个式子。** 这个式子对状态空间当中**所有**状态都成立。如果我们有 $n$ 个状态，就会有 $n$ 个这样的式子；通过这 $n$ 个式子联立，我们才能把 state value 求解出来。通常书上都只写这样一个式子，所以**千万不要以为贝尔曼公式就只有这一个式子**。
- 右边出现了其它的 state value，而它正是我们要算的东西——怎么算？这其实就是 **bootstrapping**（自举）：直观上说，我要计算的 $v_\pi(s)$ 依赖其它状态的 $v_\pi(s')$，单看好像没法算；但我们实际有一组这样的式子，把式子联立起来就能解出来。

> **易错点**：贝尔曼公式是"一组"方程，不是一个方程。单个式子里 $v_\pi(s)$ 依赖 $v_\pi(s')$，看似死循环；真正的求解靠的是把 $n$ 个状态对应的 $n$ 个式子联立。

还有一个问题：这个式子依赖哪些概率？

- $\pi(a \mid s)$ 是什么？它就是 **policy**。所以贝尔曼公式是**依赖策略的**——不同的策略会得到不同的 state value。给定一个策略，列出贝尔曼公式、解出 state value，用 state value 去评价这个策略好还是不好——这个过程就叫 **policy evaluation**（策略评估）。
- 另外两个概率 $p(r \mid s, a)$ 和 $p(s' \mid s, a)$，它们是 **dynamic model**（也叫 environment model）。这里分两种情况：本节和下节我们都**假设知道这个 model**，并给出相应的算法；如果不知道 model，其实也能求出 state value——但那就是 model-free reinforcement learning 的算法了，我们未来会重点介绍。

### 用例子把公式"焐热"：手写贝尔曼公式

贝尔曼公式看起来是非常唬人的，实际上它非常简单。我们用例子来更深入地了解一下。

**第一个例子**：有一个策略 $\pi$（用绿色箭头表示），在每个状态只往一个方向走。我们来把这个问题当中所有的贝尔曼公式全部写出来。

先看 $s_1$。建立贝尔曼公式，要做的就是把这个式子里边的每个量都确定下来它应该是什么：

- 在 $s_1$，我 take action $a_3$ 的概率是 $1$，take 其它 action 的概率是 $0$。所以对 $a$ 求和只剩下一项，求和号直接去掉了。
- 我从 $s_1$ 出发 take $a_3$，得到 $r = 0$ 的概率是 $1$，得到 $r \neq 0$ 的概率是 $0$——所以我**一定**会得到 $r = 0$。
- 我从 $s_1$ 出发 take $a_3$，跳到 $s_3$ 的概率是 $1$，跳到别处的概率是 $0$——所以我**一定**跳到 $s_3$。

于是 $s_1$ 的贝尔曼公式就变成了：

$$v_\pi(s_1) = 0 + \gamma\, v_\pi(s_3)$$

有的同学可能已经发现了：在之前的 motivating example 当中，其实已经有类似的结果了。实际上我们完全可以不看这个复杂的公式，**直观地看图就能写出来**：$v_\pi(s_1)$，我从 $s_1$ 出发，先得到一个 immediate reward $0$，加上 $\gamma$，然后跳到了 $s_3$，所以是 $\gamma v_\pi(s_3)$。和刚才从复杂式子推出来的一模一样——虽然这个式子是从公式推导得到的，但它从直观上非常容易理解。

$s_2, s_3, s_4$ 也可以类似地写出来，这样就得到了一个方程组（具体怎么写，大家可以自己练习一下）。解这个线性方程组，再把 $\gamma = 0.9$ 代进去（当然也可以代任何你喜欢的数值），就得到：

| 状态 | $s_1$ | $s_2$ | $s_3$ | $s_4$ |
| :--- | :---: | :---: | :---: | :---: |
| state value | $9$ | $10$ | $10$ | $10$ |

这个结果其实挺有意思。state value 代表一个状态的**价值**：价值高，说明这个状态值得我们往那个方向去走。为什么 $s_2, s_3, s_4$ 的价值高？因为它们离 target area 都比较近；而 $s_1$ 离 target area 比较远。

算出 state value 之后，下一步要干什么？**就可以去改进这个策略了**——慢慢就能得到最优的策略，这个我们后面再说。

**第二个例子**：比刚才复杂一点——$s_1$ 有两个方向可以走。当然可以用一般化的贝尔曼公式去推，但针对这么简单的例子，我们完全可以手写出来：

$$v_\pi(s_1) = 0.5\,(-1 + \gamma v_\pi(s_2)) + 0.5\,(0 + \gamma v_\pi(s_3))$$

往右的概率是 $0.5$，往右会得到一个 $-1$，然后乘 $\gamma$ 跳到 $v_\pi(s_2)$；往下的概率也是 $0.5$，immediate reward 是 $0$，跳到 $v_\pi(s_3)$。两项相加，就是 $s_1$ 对应的贝尔曼公式。$s_2, s_3, s_4$ 也可以类似写出，解方程组、代入 $\gamma$ 的数值，得到：

| 状态 | $s_1$ | $s_2$ | $s_3$ | $s_4$ |
| :--- | :---: | :---: | :---: | :---: |
| state value | $8.9$ | $10$ | $10$ | $10$ |

注意：$s_2, s_3, s_4$ 和刚才一样都是 $10$，但这个策略下 $s_1$ 的 state value 是 $8.9$，比刚才的 $9$ 要小——**所以这个策略没有刚才那个策略好**。你看，光靠比较 state value，我们就能比出两个策略的优劣。

### 矩阵-向量形式：把 n 个式子装进一个式子

有了贝尔曼公式，接下来要考虑的就是怎么求解它。单看一个公式：左边一个 state value，右边还有一个 state value，单凭这一个式子求出 state value 是不可能的。但我们注意到，这个 elementwise form 对**所有状态**都成立——$n$ 个状态就有 $n$ 个方程。把所有方程放在一起，就能整理成一个 matrix-vector form。这个形式对求解和理解问题非常有帮助。

先把贝尔曼公式做一步演化：把 immediate reward 那一项合并成 $r_\pi(s)$（代表从当前状态出发所能得到的 immediate reward 的平均值），把概率合并成 $p_\pi(s, s')$。要写成矩阵形式，还得给状态标上号——只用 $s$ 表示分不清是谁——从 $s_1$ 一直到 $s_n$。于是对第 $i$ 个状态：

$$v_\pi(s_i) = r_\pi(s_i) + \gamma \sum_{j=1}^{n} p_\pi(s_i, s_j)\, v_\pi(s_j)$$

把它变成 matrix-vector form 就非常简单了：

$$v_\pi = r_\pi + \gamma P_\pi v_\pi$$

- $v_\pi$ 是一个向量：$(v_\pi(s_1), \dots, v_\pi(s_n))^\top$；
- $r_\pi$ 同样是一个向量，每个分量是各状态的 immediate reward 均值；
- $P_\pi$ 是矩阵，元素 $[P_\pi]_{ij}$ 表示**从 $s_i$ 跳到 $s_j$ 的概率**。$P_\pi$ 也被称为 **state transition probability matrix**（状态转移概率矩阵）。

我们拿例子来看 $P_\pi$ 究竟长什么样。还是刚才那两个例子，$n = 4$：

- 第一个例子（单向策略）：$r_\pi$ 的第一个分量是"从 $s_1$ 出发 immediate reward 的 average"，这是确定性的，所以是 $0$；$s_2, s_3, s_4$ 出发的 immediate reward 全都是 $1$。$P_\pi$ 的第一行：第一个元素是从 $s_1$ 跳到 $s_1$ 的概率，是 $0$；第二个元素从 $s_1$ 到 $s_2$，也是 $0$；第三个元素从 $s_1$ 到 $s_3$，显然是 $1$；第四个从 $s_1$ 到 $s_4$，还是 $0$。其它行以此类推。
- 第二个例子（两方向策略）：$r_\pi$ 的第一个元素是"以 $0.5$ 的概率往右走得到 $-1$，加上以 $0.5$ 的概率往下走得到 $0$"，即 $0.5 \times (-1) + 0.5 \times 0$；$P_\pi$ 的第一行则是 $s_1$ 到 $s_2$ 为 $0.5$、$s_1$ 到 $s_3$ 为 $0.5$，其余为 $0$。和刚才不同——现在 $s_1$ 是有可能跳到 $s_2$ 去的。

### 怎么求解：解析解与迭代解

先回答一个非常关键的问题：**为什么要求解 state value？** 给定一个 policy，列出它的贝尔曼公式，再求解得到 state value——这个过程叫做 **policy evaluation**。

> **定义**：给定策略 $\pi$，通过列出并求解贝尔曼公式得到 $v_\pi$，用以评价该策略的好坏，这一过程称为 policy evaluation（策略评估）。它是强化学习当中非常关键的一个问题、非常基础的一个工具——因为只有能评价一个策略到底好不好，才能进一步改进它，最后找到最优策略。

方法有两种。

**第一种是 closed-form solution**（解析解）。把矩阵形式的 $v_\pi = r_\pi + \gamma P_\pi v_\pi$ 移项，把左边剩下的矩阵求逆、乘到右边，就得到：

$$v_\pi = (I - \gamma P_\pi)^{-1} r_\pi$$

这个解析表达式非常地优美。但是，**在实际当中我们并不会使用它**——因为这里要求一个逆，而当状态空间比较大的时候，矩阵维数也会很大，求逆的计算量也会很大。

**第二种是 iterative solution**（迭代解）：

$$v_{k+1} = r_\pi + \gamma P_\pi v_k$$

大家比较一下：这个式子和贝尔曼公式非常像，中间的项一模一样，只不过 $v_\pi$ 变成了 $v_k$ 和 $v_{k+1}$。怎么用？最开始的第 $0$ 步，我可以**随便猜一个** $v_0$，比如全都是 $0$；把 $v_0$ 代到右边，左边就算出 $v_1$（右边那些量都是事先知道的）；再把 $v_1$ 代到右边得到 $v_2$，再得到 $v_3$……这样一直下去，就得到一个序列 $v_0, v_1, v_2, \dots, v_k$。实际上可以证明：**当 $k$ 趋向于无穷时，$v_k$ 收敛到真实的 $v_\pi$**。

为什么会收敛？基本想法是定义 $v_k$ 到 $v_\pi$ 之间的误差 $\delta_k$，最后能证明 $\delta_k$ 趋向于 $0$。证明书上有，大家自己去看一下。

### 用 state value 评价策略：几个直观的例子

有了求解方法，我们就能真正地"评价"策略了。考虑这样一个设置：agent 试图跳过边界会得到 $-1$，进到 forbidden area 会得到 $-1$，到 target area 会得到 $+1$；$\gamma = 0.9$。

先看两个**看起来比较好**的策略。好在哪里？直观上看，它们不会试图跳出边界、不会撞墙、不会进 forbidden area——比如从某个格子出发，沿着策略走，最后顺利进到 target area 里去。用解析解或者迭代解都可以算出它们的 state value：**全部为正数**。还有一个很有意思的现象：靠近 target area 的那些状态，state value 都比较大；离 target area 越远，state value 就越小。

再看另一个策略：和上面几乎一模一样，只不过在两个格子里——上面那个策略往下走、这个策略往右走——但最后算出来的 state value **完全相同**。也就是说，在这两个格子里，往下走和往右走其实效果是一样的：**不同的策略是能够得到相同的 state value 的**。

然后是两个**看起来比较差**的策略。第一个：无论在哪个格子都向右走——这显然不合理，算出来的 state value 也**全是负数**。所以很明显，通过 state value 就能判断出这个策略不好。第二个是随机生成的一个策略，在很多状态它会撞墙或者进 forbidden area，显然也不好——算出来的 state value 和我们的直觉是一致的。

> **结论**：计算 state value，就能定量地评价一个策略究竟好还是不好。这就是 policy evaluation 的力量。

### 从 state value 到 action value

本节的主要内容——state value 和描述它的 Bellman equation——到这里就介绍完了。下面我们从 state value 转向 **action value**。虽然 action value 是在这节课的最后讲的，但**绝不意味着它不重要**；恰恰相反，它实际上是非常重要的。把它放到最后，是因为要先了解 state value，之后再去介绍 action value 就会相对容易很多。

**两者的区别和联系**：state value 指的是 agent 从**一个状态**出发所得到的 average return；action value 指的是 agent 从**一个状态出发、并且选择了一个 action 之后**所得到的 average return。

**为什么要关注 action value？** 因为我们一直讨论的"策略"，说的就是"在一个状态我要选择什么样的 action"。那面对一些 action，我应该选哪些呢？实际上就要根据 action value 来做判断：action value 大的，意味着选那个 action 能得到更多的 reward，我就会去选那个。

action value 的定义：

$$q_\pi(s, a) \triangleq \mathbb{E}\left[ G_t \mid S_t = s,\ A_t = a \right]$$

> **定义**：$q_\pi(s, a)$ 表示从当前状态 $s$ 出发、take action $a$ 之后所得到的 return 的 average（期望），称为 action value。它是一个 state-action pair 的函数——既依赖从哪个状态出发，又依赖从这个状态的哪个 action 出发；同时它也依赖策略 $\pi$，不同的策略当然会得到不同的 action value。

**它和 state value 在数学上有什么联系？** 从 state value 的定义出发：我从 $s$ 出发有多个 $a$，选每个 $a$ 的概率是 $\pi(a \mid s)$，选了这个 $a$ 之后得到的 average return 是一个量——这是期望的一个基本性质，于是：

$$v_\pi(s) = \sum_{a} \pi(a \mid s)\, q_\pi(s, a)$$

也就是说，**一个状态的 state value，等于它选不同 action 得到的 action value 的加权平均**，权重就是这个策略。

再拿这个式子和之前推导的贝尔曼公式对比：贝尔曼公式右边那一长串复杂表达式，前面一部分和上式相同，后面那部分正是 $q_\pi$。于是我们得到了 action value 的表达式：

$$q_\pi(s, a) = \sum_{r} p(r \mid s, a)\, r + \gamma \sum_{s'} p(s' \mid s, a)\, v_\pi(s')$$

> **结论**：这两个式子实际上是一个硬币的两面——第二个式子告诉我们，如果知道了一个状态所有的 action value，求平均就得到这个状态的 state value；第四个式子告诉我们，如果知道了所有状态的 state value，就能求出所有的 action value。

**一个容易出错的例子**。有一个策略（绿色箭头）：在 $s_1$ 要往右走。我们先求"在 $s_1$ 并且 take action $a_2$（往右）"的 action value。这个例子比较简单，可以直接写出来：第一部分是 immediate reward 的均值，因为现在是确定性的，它一定是 $-1$；future reward 部分因为它会跳到 $s_2$，所以是 $\gamma v_\pi(s_2)$：

$$q_\pi(s_1, a_2) = -1 + \gamma\, v_\pi(s_2)$$

下面有个**初学者非常容易出错**的地方：在 $s_1$ 除了 $a_2$ 之外，其实还有 $a_1, a_3, a_4, a_5$ 这些 action，那么它们的 action value 是什么？很多初学者会认为它们是 $0$——理由是"策略告诉我应该往右走，其它的 action 我们就不管了"。**这实际上是不对的。** 虽然现在这个策略告诉我们往右走，但实际上这个策略可能是不好的；未来我们恰恰希望能看一看，在这个状态**其它的 action 究竟好还是不好**——如果其它 action 的 action value 很大，也许下一时刻我们就会选择那个 action。这实际上就是一种策略改进的思想，未来会详细介绍。

比如 $a_3$：虽然策略没告诉我要走 $a_3$，但我仍然可以衡量一下，"如果在 $s_1$ take $a_3$"会得到什么——先得到 immediate reward $0$，然后跳到 $s_3$，所以 $q_\pi(s_1, a_3) = 0 + \gamma v_\pi(s_3)$。其它的 action value 也都可以这样算出来。

> **易错点**：action value 的定义里，action 是"被强制指定"的，和策略选不选它无关。策略没选的 action，它的 action value 照样存在、照样可以计算——而且未来选 action 靠的正是比较所有 action 的 action value，挑最大的那个。

**怎么计算 action value？** 两种方法：第一种，先求解贝尔曼公式得到 state value，再按上面的表达式从 state value 算出 action value；第二种，可以**不经过 state value、直接计算 action value**——比如通过数据的方式，这时候也许就不再依赖模型了。可以依赖模型，也可以不依赖模型，这正是我们未来会介绍的一些算法。

### 第2课收个尾

本节课有两个关键性的概念：**state value** 和 **action value**。先介绍了 state value，了解它之后再介绍 action value 就非常容易理解。

- state value 满足贝尔曼公式；贝尔曼公式刻画了 state value 之间的关系，也给了我们一个工具——通过求解贝尔曼公式求出 state value。
- 它有 elementwise form（对每个状态都有一个式子）和一个非常简洁的 matrix-vector form：$v_\pi = r_\pi + \gamma P_\pi v_\pi$。
- 求解有两种办法：closed-form solution 和 iterative solution。
- 贝尔曼公式后面那一长串，其实就是 action value。

下节课我们将会介绍一个非常重要的公式——**贝尔曼最优公式**。

### 下半场开场：最优策略与贝尔曼最优公式

这次课我们将会介绍最优策略以及贝尔曼最优公式。贝尔曼最优公式是贝尔曼公式的一个**特殊情况**，但我们将会看到，它是非常重要的一个式子。

学习的时候希望大家重点关注**两个概念和一个工具**：两个概念是 optimal state value 和 optimal policy，一个工具就是贝尔曼最优公式。要知道，**强化学习的目的就是寻找最优策略**——所以这节课讲的最优策略的定义、以及怎么寻找最优策略，是非常重要的。

课程大纲看起来内容比较多，但实际上每一部分都比较短，大家可以合理规划自己的时间：先介绍一个 motivating example，然后给出 optimal policy 和 optimal state value 的定义；之后的大部分篇幅都在介绍贝尔曼最优公式——这个式子长什么样、怎么求解、它的解是什么样、满足什么性质；有了贝尔曼最优公式，我们就能求解出 optimal policy；最后再分析一下 optimal policy 有哪些性质。

### Motivating example：怎么把一个不太好的策略改好

先看一个我们看过很多次的例子。有一个策略 $\pi$（绿色箭头表示），我们做两件事：第一件，求解贝尔曼公式得到 state value，进而得到 action value；在那个基础上，再介绍一个很有意思的现象。

**第一步是复习**：对每一个状态都可以写出贝尔曼公式。比如 $v_\pi(s_1)$——从 $s_1$ 出发往右走，会得到一个 $-1$ 的 immediate reward，然后乘 $\gamma$，因为跳到了 $s_2$，所以后面是 $v_\pi(s_2)$：

$$v_\pi(s_1) = -1 + \gamma\, v_\pi(s_2)$$

其它的式子也可以类似得到。这一组式子是线性方程组，有很多方法可以求解；把 $\gamma = 0.9$ 代进去，就得到各状态的 state value（具体过程大家可以自己算一下）。

**第二步求 action value**。以 $s_1$ 为例，它一共有 5 个 action，每一个 action 都有一个 action value。比如 $a_3$（往下走）：先得到一个 $0$ 的 immediate reward，然后是 $\gamma$ 乘上跳到的 $s_3$ 的 state value——把 $\gamma$ 和 $v_\pi(s_3) = 10$ 这些具体数值代进去，就得到 $9$。其它的 action 类似地都能算出来。我把 $a_3$ 写成蓝色，就是因为可以看到：**$a_3$ 对应的 action value 是最大的**。

准备工作做完，就可以提出一个很有意思的问题了。当前这个策略实际上**不太好的**——为什么？因为在 $s_1$ 它要往右走，这要进入 forbidden area。那我们**怎么样去改进这个策略**，得到一个更好的策略呢？

**答案就依赖于 action value。**

先看当前策略（current policy）能写成什么形式：在 $s_1$，当 $a = a_2$（往右走）时概率是 $1$，当 $a \neq a_2$ 时概率是 $0$——非常简单。在这个策略下，我们刚刚已经把所有的 action value 都算出来了，并且发现 $a_3$ 对应的 action value 最大。那我们能不能选 $a_3$ 作为一个新的策略？具体来说，新的策略就是：当 $a = a^*$ 时概率为 $1$，当 $a \neq a^*$ 时概率为 $0$——也就是说这个新策略**一定会选 $a^*$**。这个 $a^*$ 就是对应 action value 最大的那个 action，在这个例子里就是 $a_3$。

于是：现在的策略是往右走，新策略 $\pi_{\text{new}}$ 是往下走。大家看到了，往右走不太好，往下走真的是比较好的一个策略——**因为它正好绕开了 forbidden area**。

**为什么选 action value 最大的那个 action，就能得到比较好的策略呢？** 从直观上来说，action value 本身就代表了 action 的价值：如果我选一个 action 它的 action value 很大，就意味着之后我能得到很多的 reward，相应的策略自然比较好。这从直观上很容易理解。

**但数学上其实并不是那么容易理解的。** 为什么？因为这个例子太简单了——$s_2, s_4, s_3$ 的策略都已经是最优的了，所以在这种情况下我在 $s_1$ 选 action value 最大的 action，刚好就能是往下走。但如果不是这种情况呢？比如在 $s_2$ 的时候往上走、$s_4$ 的时候往下走、$s_3$ 的时候往左走——也就是**其它状态的策略都不是最优的**——那我在 $s_1$ 选 action value 最大的，是否仍然能得到最优的 action？这里面就有一些不确定性在里边。

不过我现在可以告诉大家：**只要我们一遍一遍地去做，不断地迭代，最后一定会得到一个最优的策略**——先对每一个状态都选 action value 最大的那个 action，选完一次得到一个新策略，再迭代得到一个新策略，最后那个策略就会趋向最优策略。这时候这个过程已经**超出了我们直观理解的范围**，我们有必要依靠数学来进行更严格、更透彻的分析。这个数学工具，实际上就是贝尔曼最优公式。

### 什么才叫"最优策略"：正式定义

上节课介绍 state value 的时候反复强调过：state value 之所以重要，是因为它能衡量一个策略究竟好还是不好。下面我们把这种说法正式地定义出来。

先定义"更好"：如果有两个策略 $\pi_1$ 和 $\pi_2$，它们在每一个状态都有自己的 state value；如果**对于所有的状态 $s$**，$\pi_1$ 得到的 state value 都大于等于 $\pi_2$ 得到的 state value，我们就说 $\pi_1$ 比 $\pi_2$ 要好。进一步定义"最优"：如果一个策略 $\pi^*$，对**任意**的一个状态、相比**任意**的其它一个策略 $\pi$，它所得到的 state value 都要大，我们就说 $\pi^*$ 是最优的。

> **定义**：若对任意状态 $s$ 都有 $v_{\pi^*}(s) \geq v_{\pi}(s)$（$\pi$ 为任意其它策略），则称 $\pi^*$ 为最优策略（optimal policy）；对应的 $v_{\pi^*}$ 称为最优 state value（optimal state value）。

这些定义其实并不麻烦，比较麻烦的是定义出来之后，我们要回答一系列的问题：

- 这个最优的策略**是否存在**？因为它看上去非常理想——比其它所有策略都好，并且在所有状态上都能打败其它策略。会不会实际上只存在"在某些状态上能打败别人、在另一些状态上没法打败"这样的策略？
- 这个策略**是否唯一**？会不会有很多个策略都是最优的？
- 最优策略是 **stochastic 还是 deterministic**？我们有时候喜欢确定性的——在某一个状态确定性地告诉我应该采取什么 action。那最优策略究竟是确定性的还是非确定性的？
- 最优策略**怎么样去得到**？

为了回答这些问题，我们需要研究贝尔曼最优公式。把贝尔曼最优公式研究透了，上面这些问题**全都能回答掉**。

### 贝尔曼最优公式：形式上长什么样

按照我们的介绍方法，先把贝尔曼最优公式直接给出来，之后再详细分析它的性质。

大家首先看这样一个式子——它看着非常眼熟，实际上就是贝尔曼公式（当其中的策略 $\pi$ 给定的时候）。但我们做一个小小的改动：在 $\pi$ 前面加上了 $\max_\pi$：

$$v(s) = \max_{\pi} \; \big[ r_\pi + \gamma P_\pi v \big]$$

elementwise 的形式，也就是在原来的贝尔曼公式外面套一个 $\max_\pi$：

$$v(s) = \max_{\pi} \sum_{a} \pi(a \mid s) \Big[ \sum_{r} p(r \mid s, a)\, r + \gamma \sum_{s'} p(s' \mid s, a)\, v(s') \Big]$$

加了 $\max_\pi$ 之后，$\pi$ 就**不再是给定的了**——因为这里边**嵌套了一个优化问题**：我需要先解决这个优化问题、求解出最优的 $\pi$，然后再把 $\pi$ 代到式子里边去。这个就是贝尔曼最优公式。右边那个比较复杂的长串，我们可以简洁地写成 $q(s, a)$。

**已知什么、求什么？** 已知的是那些概率——它们对应系统的模型，还有 reward、$\gamma$；要求解的是 $v$。那 $\pi$ 究竟是已知的还是未知的？对于一个贝尔曼公式来说，$\pi$ 一定是给定的；但贝尔曼最优公式里 $\pi$ 没有给定，**我们必须要去求解这个 $\pi$**。

matrix-vector form 也一样，从 elementwise 到 matrix-vector 的过程和之前贝尔曼公式那节讲得一样，这里就不再重复了——唯一的区别就是前面多了一个 $\max_\pi$。这个 $\max_\pi$ 是对一个向量取的，它实际上可以拿到式子里边去逐元素操作。

> **提示**：贝尔曼最优公式非常 tricky，也非常 elegant（优美）。说它优美，是因为它的形式非常简洁，却能同时刻画最优策略和最优 state value；说它 tricky，一方面是它右边镶嵌了一个最优化问题，另一方面是求解和理解其中那些问题都不那么直观。

我相信大家现在有很多问题萦绕在脑海里：怎么求解？这个公式是否存在解？解是否唯一？我们为什么要研究它？它和最优策略、最优 state value 有什么样的关系？不用着急，这些问题我们后面会一个一个地解答。

### 右边那个 max 怎么处理：两个小例子

现在详细分析这个表达式里**可能让人迷惑的部分**——出现在右边的那个求最大化的优化问题。对初学者来说确实容易迷惑：在这个式子当中，未知量有 $v$（虽然它是一个向量，但我们也把它当成一个未知量）；除此之外我们还要求解一个 $\pi$——对任意一个状态，都要求出最优的 $\pi$。相当于**一个式子要求两个未知量**，这怎么求解呢？

实际上非常简单。我举一个例子，大家就会明白。

**第一个例子**。考虑两个变量 $x$ 和 $a$，它们满足这样一个式子（它是模拟贝尔曼最优公式的结构得到的——右边也存在一个对 $a$ 求最优的问题）：

$$x = \max_{a} \left\{ 2x - 1 - a^2 \right\}$$

求解分两步：

1. **先把等号右边对 $a$ 的最优值求出来。** 这是非常明显的：因为这里是 $-a^2$，负的 $a^2$ 一定是非正的，所以当 $a = 0$ 的时候它达到最大，最优值就是 $2x - 1$；如果 $a \neq 0$，值一定会更小。
2. **再把达到最优值的 $a$ 代回去。** 右边变成了 $2x - 1$，左边是 $x$，于是 $x = 2x - 1$，非常容易解出 $x = 1$。

通过这两个步骤，我们就解出 $a = 0$、$x = 1$，这就是这公式的解。**这个思路就可以放到求解贝尔曼最优公式当中**：右边的那些项（模型、reward、$\gamma$）都是已知的；$v$ 那一项之后会先给它一个初始值，给了初始值它也就给定了——把它缩写成 $q(s, a)$，此时 $q(s, a)$ 是已知的。于是受刚才例子的启发，我们要做的就是**把 $\pi(s, a)$ 确定下来**，也就是解决"在给定一组 $q$ 值的情况下，权重怎么取才能让目标最大"的问题。

**第二个例子**。先考虑简单的情况：假如我有 3 个 $q$ 值——$q_1, q_2, q_3$，要解决的问题是求解三个系数（权重）$c_1, c_2, c_3$，使得目标函数 $c_1 q_1 + c_2 q_2 + c_3 q_3$ 达到最大。约束是它们的和等于 $1$，并且每一个都大于等于 $0$。为什么要有这个约束？因为**这些系数对应的就是概率 $\pi$**——概率天然满足这些性质。

那最优值是什么呢？我们不妨假设 $q_1, q_2, q_3$ 里存在一个最大值，假设它是 $q_3$（当然也可以假设是 $q_1$ 或者 $q_2$，完全没问题）。最优解就是：$c_3 = 1$，$c_1 = c_2 = 0$。

给两个解释。一个是**直观的解释**：$c_3$ 代表 $q_3$ 的权重，因为 $q_3$ 是最大的，我们希望把所有的权重全部押到 $q_3$ 上面去，自然 $c_3$ 应该等于 $1$，这时候总和最大。另一个是**数学上的解释**，我们来看这样一个式子——因为 $c_1 + c_2 + c_3 = 1$，所以：

$$q_3 = (c_1 + c_2 + c_3)\, q_3 = c_1 q_3 + c_2 q_3 + c_3 q_3 \;\geq\; c_1 q_1 + c_2 q_2 + c_3 q_3$$

中间那步是因为 $q_3$ 是最大的，它大于等于 $q_1$ 和 $q_2$，所以每一项 $q_3$ 换成 $q_1$ 或 $q_2$ 只会变小或不变。于是最左边的 $q_3$ 大于等于最右边那个加权和——**不论 $c_1, c_2, c_3$ 取什么样的值**，$q_3$ 都是大于等于它们的；而等号取到，显然对应的就是 $c_3 = 1$ 的情况。

把这样的思路用到求解贝尔曼最优公式当中，结论就出来了：

> **结论**：当右边的 $q$ 值确定之后，$\max_\pi$ 那一项的最优值就等于**最大的那个 $q$ 值**；取到这个最优值的 $\pi$ 是：对 $a^*$（对应最大 $q$ 值的那个 action）概率为 $1$，对其它 action 概率为 $0$。

到这里，我们就比较清晰地展示了嵌套在贝尔曼最优公式里、可能让人感到迷惑的右边这个最优项应该怎么样处理了。有了这个钥匙，贝尔曼最优公式的求解、它解的存在性与唯一性，就能一层一层地打开了。贪心的直觉——"每个状态都选 action value 最大的 action"——也就从"看起来合理"变成了"数学上严格成立"的第一步。后面的分析，我们接着往下走。

## 贝尔曼最优公式的求解、最优策略的性质与两个迭代算法
> 对应块：BLK04 | 覆盖分集：P11-P14 | 块标题（分集名）：《第3课-贝尔曼最优公式（公式求解以及最优性）》

上一讲我们把贝尔曼最优公式里最难缠的那个 $\max_\pi$ 处理掉了。这一讲我们先把这个公式彻底求解出来——为此要请出一位非常强大的帮手：收缩映射定理（contraction mapping theorem）；然后立刻用这个工具去研究最优策略本身，看看它有哪些有意思、甚至反直觉的性质。再往后，这个求解算法会正式得名"值迭代"（value iteration），并引出它的兄弟"策略迭代"（policy iteration）——这是整个课程里第一次正式介绍强化学习算法。

### 把 max 消掉：贝尔曼最优公式就是 v=f(v)

先回顾我们是怎么处理右边那个 $\max_\pi$ 的。要求解 $\max_\pi$ 的方法是：先固定 $v$，我就可以求出来一个 $\pi$。至于这个 $\pi$ 长什么样子、最后得到的最优值是什么，其实我们不用太关心——反正我们知道，结果一定是 $v$ 的函数。于是把它写成一个函数 $f(v)$，贝尔曼最优公式就化成了：

$$v = f(v)$$

这是多么简单的一个式子啊。这里的 $f(v)$ 实际上是一个向量，向量中对应每个状态 $s$ 的元素就是贝尔曼最优公式逐状态的那个表达式。

下面就来求解这个式子。但在求解之前，要先介绍收缩映射定理。

### 不动点与收缩映射

**不动点（fixed point）**：如果在集合 $X$ 上有一个点 $x$，有一个映射（或者说函数，两者是一回事）$f$，满足

$$f(x^*) = x^*$$

那 $x^*$ 就被称为一个不动点。直观解释很清晰：我这边有一个点 $x$，经过 $f$ 一映射，又映射到了我自己——这个点就不再动了，所以叫不动点。

**收缩映射（contraction mapping）**：如果一个函数满足

$$\|f(x_1) - f(x_2)\| \le \gamma \|x_1 - x_2\|$$

其中 $\gamma < 1$，它就叫收缩映射。这个不等式说的是：取任意两个点，它们函数值之间的距离，小于这两个点本来的距离，还要再乘一个小于 1 的因子。一维情况下一画就明白：$x_1$ 映射到 $f(x_1)$，$x_2$ 映射到 $f(x_2)$，两个像之间的距离比原来更近了——这就是"收缩"（contractive）这个名字的由来。

看两个例子。第一个，$x = f(x)$，取 $f(x) = 0.5x$，$x$ 是标量。很容易验证 $0 = 0.5 \times 0$，所以 $x=0$ 是一个不动点。那它是不是收缩映射？答案是肯定的，可以算一下：随便取 $x_1, x_2$，

$$\|0.5x_1 - 0.5x_2\| = 0.5\|x_1 - x_2\| \le \gamma\|x_1 - x_2\|$$

把 0.5 提出来，这个 $\gamma$ 比如说取 0.6、0.7 都行，只要小于 1 就满足定义。所以 $0.5x$ 是一个收缩映射。

第二个例子把它推广到向量情形：$x$ 是向量、$A$ 是矩阵，考虑 $f(x) = Ax$。当 $A$ 的矩阵范数（matrix norm）小于 1 时，同样可以得到 0 是它的不动点，并且 $Ax$ 也是一个收缩映射。

### 收缩映射定理：存在、唯一、可迭代求解

有了这两个概念，就可以引出收缩映射定理了。这是一个非常强大的定理——除了这门课，其他很多领域里只要你要求解一个形如 $x = f(x)$ 的式子，都会用到它。

如果 $f$ 是一个收缩映射，那么 $x = f(x)$ 有三个重要结论：

- **存在性（existence）**：我根本不关心 $f$ 的表达式究竟是什么，它只要是一个收缩映射，就一定存在一个不动点 $x^*$ 满足 $f(x^*) = x^*$；
- **唯一性（unique）**：这个不动点是唯一存在的；
- **可求解性**：定理还给出了怎么求这个不动点——一个迭代算法

$$x_{k+1} = f(x_k)$$

从 $x_0$ 出发算出 $x_1$，把 $x_1$ 代回去算出 $x_2$，这样下去，当 $k$ 趋向于无穷大时 $x_k$ 会收敛到不动点 $x^*$。当然实际当中我们根本不需要 $k$ 趋向无穷，跑一些步骤就可以得到比较满意的结果。而且收敛速度（convergence rate）非常快，是**指数收敛**的。

用刚才的例子验证一下。$x = 0.5x$ 的不动点是 0，现在我们知道它还是唯一的；虽然这个例子简单到一眼就能看出答案，但用迭代算法同样能收敛过去：$x_0 = 10$，则 $x_1 = 5$，$x_2 = 2.5$，趋势明显，最后趋向 0。向量情形 $Ax$ 也有类似的结果。

定理本身的证明这里就不讲了，书当中有非常详细的证明，感兴趣可以去看。

### 用收缩映射定理求解贝尔曼最优公式

现在回到贝尔曼最优公式。$v = f(v)$ 正是收缩映射定理要解决的那一类问题。要应用定理，首先要证明其中的 $f(v)$ 是一个收缩映射。实际上可以证明：

$$\|f(v_1) - f(v_2)\| \le \gamma \|v_1 - v_2\|$$

这里的 $\gamma$ 就是折扣率（discount rate），它是小于 1 的——之前定 $\gamma < 1$ 的伏笔在这里兑现了。至于这个结论为什么成立，这里不再详细介绍，书中有完整的论证。

知道了 $f$ 是收缩映射，贝尔曼最优公式就可以立刻用收缩映射定理求解，得到三个结论：

1. 贝尔曼最优公式一定存在一个解，记作 $v^*$；
2. 这个解 $v^*$ 是唯一存在的；
3. 这个解可以通过迭代算法 $v_{k+1} = f(v_k)$ 求解出来，$v_k$ 最后会收敛到 $v^*$。

### 最优性：v* 是最大的 state value，π* 是贪婪的确定性策略

接下来分析这个解的最优性。假设 $v^*$ 是贝尔曼最优公式的解（可以用刚才的算法求出来），$\pi^*$ 是对 $v^*$ 的最优策略——也就是把 $v^*$ 固定住之后求解出来的那个 $\pi$。这样，公式里的 $\max_\pi$ 就可以去掉，改成 $\pi^*$：

$$v^* = r_{\pi^*} + \gamma P_{\pi^*} v^*$$

这个式子是什么？它实际上就是一个**贝尔曼公式**。大家知道，贝尔曼公式一定是对应一个策略的，而这就是对应 $\pi^*$ 的贝尔曼公式。那么自然地，这里的 $v^*$ 就是 $v_{\pi^*}$，也就是 $\pi^*$ 所对应的 state value。

> **结论**：贝尔曼最优公式是一个特殊的贝尔曼公式，只不过它对应的策略比较特殊，是一个最优的策略。希望大家能够记住这一条。

当然，这个策略究竟是不是最优的、$v^*$ 是不是最大的 state value，需要一个结论来支撑：**对于任何其它策略所得到的 state value，都没有 $v^*$ 大**；相应地，$\pi^*$ 就是最优的策略，因为它对应的 $v_{\pi^*} = v^*$ 达到了最大。这个结论的证明同样放在书里。

那 $\pi^*$ 长什么样子呢？其实并不陌生了：在状态 $s$，$\pi^*$ 会选择 $a^*$——也就是该状态下 action value 最大的那个 action，给它概率 1，其它 action 概率全为 0。所以这个策略首先是**确定性的**（deterministic），同时又是**贪婪的**（greedy）——所谓 greedy 就是它不管其它的，我就选最大的那个。

到这里，贝尔曼最优公式的全部内容就介绍完了。总结几条要记住的：它有两个表达式，一个是逐元素形式（elementwise form），一个是矩阵—向量形式（matrix-vector form）；它的解一定存在且唯一——再强调一点，**最优的 state value 是唯一的，但对应这个最优 state value 的最优策略不一定是唯一的**；求解靠的是那个迭代算法；而解出的 state value 和 policy 都是最优的——这正是我们为什么要研究贝尔曼最优公式。

贝尔曼最优公式给我们提供了一个非常强大的工具：求解最优策略、求解最优 state value。下面立刻用这个工具来分析最优策略，看它有哪些有意思的性质。

### 什么决定了最优策略？

先回答一个问题：什么样的因素决定了最优的策略？如果大家不了解贝尔曼最优公式，这个问题其实挺难回答；但了解了它，你会发现这是个非常简单的问题。

看贝尔曼最优公式的结构：我们要做的是从中求出那些黑色的变量——最优策略和最优 state value；而已知的是那些红色的量——概率 $p$（代表系统的模型）、$r$（代表我们设计的 reward）、以及折扣率 $\gamma$。求解贝尔曼最优公式，就是在已知红色量的条件下把黑色量求出来。

> **结论**：最优策略和最优 state value 由三样东西决定——reward 怎么设计（$r$）、折扣率怎么选（$\gamma$）、以及系统的模型是什么样。

系统模型一般是很难改变的，所以我们不考虑它；下面就看改变 $r$ 或者改变 $\gamma$ 时，最优策略会发生什么。

### γ 由大到小：策略从抄近道到极度短视

实验场地是网格世界，目标区域是我们希望到达的地方。reward 设计：跑出边界 $-1$，进 forbidden area $-1$，到 target $+1$，$\gamma = 0.9$。用之前介绍的算法求解贝尔曼最优公式，得到最优策略和对应的最优 state value。

观察这个最优策略，发现一个有意思的现象：我们之前说 forbidden area 希望能绕开，但实际上最优策略反而不绕——从起点出发它会往右走进 forbidden area，然后穿过去到 target。为什么？因为它发现：这样穿过去虽然暂时得到一个负数（惩罚），但从长远来看，所得到的 return 比绕一大圈还要大。

下面从这个基准出发改参数。唯一改的是 $\gamma$：从 0.9 降到 0.5。最优策略立刻变了——不再往右穿 forbidden area，而是往左走绕一个大圈过去。为什么？因为它衡量后发现，绕大圈得到的 return 比穿过去得到的要大，它才会这样选择。原因在于 $\gamma$ 的含义：$\gamma$ 比较大时 agent 比较**远视**，比较重视未来的 reward；$\gamma$ 比较小时它变得**近视**，return 的大小主要由近期的 reward 决定——因为 $\gamma$ 小，未来的 reward 打折打得非常厉害。

继续把 $\gamma$ 降到 0，最优策略又变了，变得 extremely short-sighted——非常地近视，只关注 immediate reward。回想一下 return 的定义：

$$G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \cdots$$

$\gamma = 0$ 意味着后边全是 0：不论未来的 return 是多少，经过折扣之后全都是 0，所以 return 就等于 immediate reward，那它自然选择 immediate reward 最大的 action。举两个具体格子：有一个格子，往上走会撞墙或进 forbidden area，得到负奖励；原地不动或往左走得到 0——它显然在"原地不动"和"往左"里选（程序里是随机选一个，这里刚好选了原地不动）。但紧挨 target 的那个格子还是会进去，因为往 target 走是一个正数，而原地不动是 $-1$ 的惩罚，它自然选往 target 走。

> **结论**：$\gamma = 0$ 时整个策略会变得非常短视、非常不好，从很多状态出发根本到达不了 target area。

### 惩罚加重：另一种让策略绕开的办法

再看一个例子。所有参数和第一个基准完全一样，只有一点不同：forbidden area 的奖励从 $-1$ 改成 $-10$——进到 forbidden area 会得到额外更重的惩罚。这时候策略就变成了绕着 forbidden area 过去，注意这里 $\gamma$ 仍是 0.9。而且当 $\gamma$ 从 0.9 变到 0.5 时，它同样可以避开 forbidden area。

把这几组实验放到一起看：

| 改动的量 | 改动内容 | 最优策略的行为 |
| :--- | :--- | :--- |
| $\gamma$ | $0.9 \to 0.5$ | 从穿过 forbidden area 改为绕大圈避开 |
| $\gamma$ | 降到 $0$ | 极度短视，很多状态到不了目标 |
| $r$ | forbidden 由 $-1$ 加重到 $-10$ | 即便 $\gamma = 0.9$ 也绕开 forbidden area |

也就是说，"让 agent 避开 forbidden area"这个目的，既可以靠调 $\gamma$ 实现，也可以靠加重惩罚实现——$r$ 和 $\gamma$ 是两个都能拧的旋钮。

### reward 整体乘 a 加 b：最优策略不变

还有一个非常重要的情况：如果每一个 $r$ 都乘上一个因子 $a$ 再加上一个偏置 $b$，变成 $ar + b$，整个系统的最优策略会发生改变吗？

考虑一个具体例子。我们常用的设置是 $r_{boundary} = r_{forbidden} = -1$、$r_{target} = +1$。现在给所有的 $r$ 全都加上 1：$r_{forbidden}$ 和 $r_{boundary}$ 变成 0，$r_{target}$ 变成 2，$r_{otherstep}$ 变成 1。为什么会有 otherstep？因为这里隐含了另外一个奖励 $r_{otherstep} = 0$——从一个白色格子走到另一个白色格子，是没有任何奖惩的；但加偏置量的时候，这个隐含的 0 也要同样加上 1。

做了这样的变换之后，最后的策略**实际上不会改变**。为什么？因为最重要的不在于 reward 的绝对值（absolute value），而在于它们相互之间的相对值（relative value）。

这个结果可以用定理的形式更严谨地表示出来。原来的贝尔曼最优公式解是 $v^*$；现在把每个 reward 改成 $ar + b$，对应的贝尔曼最优公式变成 $v' = \max_\pi (r_\pi' + \gamma P_\pi v')$——因为只改变了 $r$，所以 $r_\pi'$ 和原来的 $r_\pi$ 不一样。可以证明，新公式的解和 $v^*$ 有这样的关系：

$$v' = a\,v^* + b$$

选最优策略时实际看的是 action value：知道 state value 就能求出每一个 action value；同样由 $v'$ 求出的 action value 和之前的也呈现同样的关系——原来的 action value 乘 $a$ 加偏置 $b$。而我在选择最优策略时，不看 action value 的绝对值，只看相对值：比如原来的 action value 是 1、2、1、1、1（假设有 5 个 action），我肯定选第 2 个；如果现在变成 100、200、100……我还是选 200 那个，因为我是选最大的，不在意绝对值是多少。所以最优策略不变。定理的详细证明可以在书中找到。

### 为什么不会绕远路：γ 就是隐形的每步惩罚

再来看一个例子，这个例子很有意思，可能会让大家脑筋拐不过来弯。左边是一个非常简单的 4 格子问题，通过求解贝尔曼最优公式得到了最优策略和对应的 optimal state value；右边的策略区别只在于某个状态是往左走而不是往下走——这显然不是最优策略，它对应的 state value 也明显要小。

我的问题是：为什么它不能这样拐一个弯，去做所谓的 meaningful detour？detour 本来就是绕路的意思。因为我在设计 $r$ 的时候，从一个白色格子进到另一个白色格子，$r$ 是 0——没有惩罚，那它就可以从这走到这、甚至再走回来再过去，都可以。为什么这样绕路就不是最优的呢？

答案很简单。如果你直接跳过去，会得到 $+1$，之后待在那一直得到 $+1$，也就是 $1, \gamma\cdot 1, \gamma^2\cdot 1, \ldots$；而绕路的话，先得到 0、又是 0，然后才得到 1——和刚才相比多了一个 $\gamma^2$ 的折扣因子在前面，所以 state value 就变小了。

这里想说的是：很多人在设计 reward 的时候会觉得，每走一步应该给一个惩罚（比如 $r = -1$），代表一种能量消耗，这样它就不会绕远路、会走最短路径；如果 $r = 0$，它好像就会绕远路。但实际上是不是这样呢？通过刚才的分析发现并不是——因为除了 $r$ 之外，我们还有 $\gamma$：绕的路越长，到达目标拿到奖励就越晚，对应 $\gamma$ 的次方就越小、打折打得越厉害，所以它自然会找最短的路径过去。

> **提示**：不需要用"每步负奖励"去阻止绕路，折扣因子 $\gamma$ 本身就惩罚了绕路——晚到一步，未来的正奖励就多乘一个小于 1 的因子。

### 值迭代：给迭代算法一个正式的名字

这一讲进入第 4 课。先交代一下课程地图：上节课介绍了贝尔曼最优公式，这节课来到整个课程当中第一次正式介绍的强化学习算法，而且是 model-based 算法；下节课将介绍整个课程第一个 model-free 的算法。这三章内容关系非常密切：今天介绍的 value iteration 其实上节课已经出现过，今天会以更正式的方式介绍；另一个算法 policy iteration 则是下节课 Monte Carlo learning 的基础。这次课的主要内容分三部分：value iteration、policy iteration、truncated policy iteration——之后会发现，前两者是第三个的两个极端情况。

先看 value iteration。上节课介绍了贝尔曼最优公式的 matrix-vector form，怎么样求解它？我们给出了收缩映射定理：只要用这个迭代算法，就能求解出最优的策略和最优的 state value：

$$v_{k+1} = \max_\pi \left( r_\pi + \gamma P_\pi v_k \right)$$

右边是 $v_k$，左边是 $v_{k+1}$。这个算法实际上有名字，它就叫**值迭代**（value iteration）。至于这个算法为什么设计成这个样子、为什么能找到最优策略，上节课都已经回答过了，这里不再重复。

仔细看这个算法，它实际上包含两部分。第一部分：给定 $v_k$，求解嵌套在式子当中的那个优化问题，解出 $\pi$——这一步叫 **policy update**，它处理的是右边的优化问题，得到 $\pi_{k+1}$；第二部分：把求出的 $\pi_{k+1}$ 代回式子，根据 $v_k$ 求出 $v_{k+1}$——这一步叫 **value update**。

> **易错点**：$v_k$ 究竟是不是一个 state value？猛地感觉它好像在贝尔曼公式的位置上，应该是 state value。但大家仔细看：如果左边是 $v_k$，右边也是 $v_k$，那它确实是一个贝尔曼公式，$v_k$ 就是 state value；可是左边并不是 $v_k$。所以 $v_k$ 不是 state value——它就是一个向量、一个值，叫它什么值都可以。这也是"值迭代"这个名字的由来。

### 值迭代的逐元素形式与编程流程

matrix-vector form 经常用来做理论分析；想看怎么实现的时候，要看它的 elementwise form。

先看 policy update。对每一个状态 $s$，都可以写出对应的式子：右边的 $v_k$ 和前面的量都是已知的，把 $v_k$ 代进去就可以得到 $q_k(s, a)$——每个状态-动作对的 action value。怎么求解这时候的最优策略？上节课已经详细介绍了：最优策略会选取对应 $q_k$ 最大的那个 action（记作 $a_k^*$），其它所有 action 的概率都是 0。所以这是一个确定性策略，并且是 greedy policy——它只寻求最大的 q-value。

再看 value update。把刚才求出的 $\pi_{k+1}$ 代进去：对应 $q_k$ 最大的那个 action 概率是 1、其它全是 0，所以最后的结果非常简单：

$$v_{k+1}(s) = \max_a q_k(s, a)$$

$v_{k+1}$ 就是 $q_k$ 里面最大的那个数。

整个流程可以用字符画串起来：

```text
        v_k  (从 v_0 或 v_1 开始，任意初值)
         |
         | 对每个状态 s，代入 v_k 算出所有 action 的 q_k(s,a)
         v
        q_k  ──> 找出哪个 q_k 最大 ──> 对应的 action
         |                                |
         |                                v
         |                     policy update: 得到 greedy 策略 π_{k+1}
         v
   value update: v_{k+1}(s) = 最大的那个 q_k(s, a)
         |
         v
        v_{k+1}  ──> 回到顶部，进入下一轮迭代
```

读图说明：一轮迭代就是"由 $v_k$ 算 $q_k$，由 $q_k$ 同时得到新策略和新值"，然后循环。

写成伪代码就是：先有一个初值 $v_k$；当 $v_k$ 还没收敛时——收敛的判据是 $v_k - v_{k-1}$ 小到一个很小的数（比如 0.001），我们就认为 $v_k$ 已经收敛了——就做下面的事情：假设现在是第 $k$ 次迭代，遍历所有的状态 $s$，对每一个状态遍历它所有的 action，计算出每个 $(s,a)$ 对应的 $q_k$；算出 $q_k$ 之后立刻就非常简单了——看哪个 action 对应最大的 $q_k$：policy update 就选这个 action，value update 就取这个最大的 $q_k$ 作为 $v_{k+1}$。

### 值迭代实例：两步迭代找到最优策略

用一个网格世界的例子看看这个算法怎么工作：场地里有 forbidden area 和 target area，要对这个问题求出最优策略。迭代过程中每次会得到一个策略 $\pi_{k+1}$，把它画在网格上观察。

用这个算法做策略搜索，需要具备什么能力？当你给我 $v$ 的时候，我要能够求出 $q$——也就是要能从 $v$ 计算得到 $q$-table。编程的时候不一定非得真的存这么一个表格，但这个计算能力必须有。

第一步，$k=0$：选取 $v_0$，值可以任意选取，简单起见全部取 0。把 $v_0$ 代入得到 q-table：一边是每个状态，一边是每个 action 对应的 $q$。有了这个表格，policy update 立刻能做：比如对 $s_1$，看哪些 $q$ 最大——有两个并列最大，对应的 action 是 $a_3$ 和 $a_5$，那我可以随便选一个，这里选 $a_5$；其它状态类似，看哪个 $q_k$ 最大就选哪个。然后 value update：这些最大的 $q_k$ 就作为新的 $v_1$，供下一步使用。

把这一轮的策略画出来：$s_2$、$s_3$ 和 $s_4$ 实际上都已经达到了最优，但在 $s_1$ 还没达到最优——它原地不动，而最优是要往下走。不用着急，再迭代一步。

$k=1$：把 $v_1$ 的值重新代回 q-table，得到一个新的 q-table；针对每一个状态看哪个 $q_k$ 最大：$s_1$ 对应的最大值是 $a_3$，新的策略选 $a_3$；其它状态依次得到新的策略和新的值。把新策略画出来，一眼看上去就知道这已经是最优策略了——也就是说，只用两个步骤就找到了最优策略，尽管最开始只是随便猜了一个数。当然这个例子非常简单，问题复杂的话需要更多迭代步骤。可以继续往下迭代，什么时候停呢？就是当 $v_k - v_{k-1}$ 是一个很小的数的时候——这意味着再往下怎么努力都没办法再改变了，这时候就可以停止。

### 策略迭代：评估与改进的循环

接下来介绍 policy iteration。讲法是：先给出算法是什么，再详细分析它的性质，最后把算法拆开看怎么编程实现。

算法是这样的：最开始有一个初始策略 $\pi_0$，可能是任意给定的策略，也许是不好的策略——没关系，之后会不断迭代，找到一个好的策略。每次迭代分两个步骤：

- **policy evaluation（策略评估，简称 PE）**：给定一个策略，求解它对应的贝尔曼公式，得到所对应的 state value。已知 $\pi_k$（最开始是 $\pi_0$），求解出 $v_{\pi_k}$，这就是去评估这个策略；
- **policy improvement（策略改进）**：求出 $v_{\pi_k}$ 之后，求解一个优化问题，得到新的策略 $\pi_{k+1}$。$\pi_{k+1}$ 会比 $\pi_k$ 更好，所以叫 policy improvement——至于为什么会更好，之后会介绍。

整个过程可以这样表示：

```text
π_0 (随便猜的策略，可能不好)
 │
 │  policy evaluation:  解贝尔曼公式，得 v_{π0}
 v
v_{π0}
 │
 │  policy improvement:  解 max 优化，得 π_1（比 π_0 好）
 v
π_1 ──> v_{π1} ──> π_2 ──> v_{π2} ──> …… 不断交替，直到收敛
```

读图说明：策略迭代就是"评估当前策略、再据此改进策略"两个步骤交替进行的大循环。

### 四个关键问题

具体实现稍微往后放一放，先回答四个比较关键的问题。

#### 策略评估怎么求 state value

这个在介绍贝尔曼公式的时候已经非常详细地介绍过了：假设 $\pi_k$ 给定，可以写出它的贝尔曼公式，然后求解 state value。有两种方法：第一种是**闭式解**（closed-form solution），这里不详细展开，不熟悉的话可以回看之前的课程；第二种才常用——因为闭式解涉及矩阵求逆，我们不太会用，经常用的是**迭代解**（iterative solution）：对 $v_{\pi_k}$ 先有一个猜测，然后不断迭代，慢慢得到 $v_{\pi_k}$。

这里想指出一点：policy evaluation 是 policy iteration 这个大算法里的一步，而这一步又依赖一个迭代算法——相当于有一个大的迭代算法，里边一步当中嵌套着一个小的迭代算法。

#### 为什么新策略一定更好

$\pi_{k+1}$ 是在 $v_{\pi_k}$ 给定时求解那个 max 式子得到的。可以证明：

$$v_{\pi_{k+1}} \ge v_{\pi_k}$$

所以 $\pi_{k+1}$ 一定不比 $\pi_k$ 差，这就是它叫 policy improvement 的原因。这里我简单地作为一个结果放上来，详细的证明可以在书中找到。

#### 为什么最终能收敛到最优

首先直观上：因为每一步都有 policy improvement，所以 $v_{\pi_0}$ 可能不好，但 $v_{\pi_1}$ 会好一点，$v_{\pi_2}$ 更好，慢慢地 $v_{\pi_k}$ 肯定比之前好；而最好的当然是 $v^*$——贝尔曼最优公式的解，最优的 state value。所以直观上它确实越来越好，能找到最优策略。

但数学上来说会稍微复杂一点：虽然知道 $v_{\pi_k}$ 越来越好，但它究竟能不能好到最优的那个值，还需要证明。这里直接放一个结果：当 $k$ 趋于无穷时，$v_{\pi_k}$ 一定会收敛到最优的 optimal state value，并且策略也会收敛到一个最优策略。证明同样在书里。

#### 与值迭代是什么关系

有两个要点。第一，回答上一个问题（收敛性）时，证明 policy iteration 收敛实际上用到了 value iteration 收敛的结果——它是基于之前 value iteration 的结果建立起来的。第二，policy iteration 和 value iteration 实际上是两个极端，是一个更一般的算法——truncated policy iteration——的两个极端，稍后会看到。

### 策略迭代的逐元素实现与伪代码

要实现就要研究 elementwise form。

第一步 policy evaluation：它的 matrix-vector form 就是迭代求解一个贝尔公式的算法，elementwise form 是：

$$v_{\pi_k}^{(j+1)} = r_{\pi_k} + \gamma P_{\pi_k} v_{\pi_k}^{(j)}$$

上标 $(j)$ 代表第 $j$ 个内层迭代估计出来的 $v_{\pi_k}$ 的值。初始值可以给一个 $v_{\pi_k}^{(0)}$，这些量和 $\pi_k$ 都是已知的，通过这个式子求出左边，再把左边代到右边，循环直到收敛——我就认为找到了 $v_{\pi_k}$，这一步完成。

第二步 policy improvement：上一步找到了 $v_{\pi_k}$，这一步要更新得到 $\pi_{k+1}$，方法是求解那个 max。elementwise form 里，$v_{\pi_k}$ 已知，括号里实际上就是 $q_{\pi_k}$，可以求解出来。有好几个 $q_{\pi_k}$，应该选什么样的策略？这在 value iteration 当中已经知道了：新的最优策略就是选 $a_k^*$——对应最大的 $q_{\pi_k}$ 的那个 action。

整个流程用伪代码展示：在每一个 iteration（比如第 $k$ 个），有两步。

1. **policy evaluation**：目标是求解 $v_{\pi_k}$。给它一个初始猜测（任意值），代入上面的迭代算法，直到 $v_{\pi_k}^{(j)}$ 收敛，就得到了 $v_{\pi_k}$。
2. **policy improvement**：遍历所有的状态，对每一个状态再遍历它的每一个 action；用刚才求出的 $v_{\pi_k}$ 求出 $q_{\pi_k}$；接下来很简单——新的策略就是选 $q_{\pi_k}$ 里对应最大的那个 action。得到 $\pi_{k+1}$ 之后回到第一步，下面要计算 $v_{\pi_{k+1}}$，这样不断地迭代循环下去。

### 策略迭代实例：一个迭代就够的小例子

看一个非常简单的例子来体会算法怎么工作：问题里只有两个网格，右边是 target area。最优策略显示应该是：在左边的格子里往右走，在 target 格子里静止不动。我们的初始策略不合适——都是往左走，看看它怎么收敛到 optimal policy。

问题的设置：每个格子有 3 个动作——$a_l$ 往左、$a_0$ 保持不动、$a_r$ 往右。

第 0 个 iteration（$k=0$），第一步 policy evaluation：要求解 $v_{\pi_0}$，实际上就是求解贝尔曼公式。因为它非常简单，可以直接求解出来；当问题比较复杂时，就用迭代的算法来求解——这里问题简单，直接跳过求解过程。得到了 $v_{\pi_0}$ 之后，第二步之前还要计算 $q_{\pi_0}$：$q_{\pi_k}$ 和 $v_{\pi_k}$ 有固定关系——给出 $v_{\pi_k}$ 一定能求出 $q_{\pi_k}$。把 $v_{\pi_0}$ 的具体值代到表格里，就得到 $q_{\pi_0}$ 的具体数值。然后 policy improvement：新的策略很简单，看 $q_{\pi_0}$ 哪个最大——$s_1$ 那一行最大的对应 $a_r$，所以在 $s_1$ 选 $a_r$；$s_2$ 那一行最大的对应 $a_0$，在 $s_2$ 选 $a_0$。

把这个新策略画出来就可以发现，它已经是最优了：$s_1$ 往右走，$s_2$ 保持不动。这个问题非常简单，所以一个 iteration 就得到了最优策略；比较复杂的话会需要多个 iteration。

### 大例子里的有趣现象：离目标近的策略先变好

再看一个更复杂的例子，通过它能发现很有意思的东西。基本设置已给出：对一个 $5\times5$ 的网格求最优策略。图上画的是：从最开始的随便一个策略 $\pi_0$ 出发，计算 $v_{\pi_0}$，policy improvement 得到 $\pi_1$，再 policy evaluation 得到 $v_{\pi_1}$……这样一直下去，直到 $\pi_{10}$ 和 $v_{\pi_{10}}$。可以看到中间过程的策略都是不好的，有的状态的策略乱七八糟；到最后 $\pi_{10}$ 时已经得到了最优策略——从任何一点出发都能到达目标区域。比如从某个点出发不会穿过 forbidden area 到达目标区域，这是因为这里的设置 $r_{forbidden} = -10$，进入 forbidden area 有比较大的惩罚，所以它会避开。

这个过程当中有一个非常有意思的现象，大家注意一下：$\pi_0$ 是不好的策略，每个状态都保持原地不动；$\pi_1$ 时很多状态的策略也还是不好，但这几个状态的策略——包括 target area——已经变好了；从 $\pi_1$ 到 $\pi_2$，又有一个状态的策略变好了；从 $\pi_2$ 到 $\pi_3$，又变好一个——原来它是向上的（不好的），现在变成向左、能够到达目标区域了；再往下慢慢地这个也变好了，$\pi_5$ 时这些也变好了；直到 $\pi_9$ 时，比较近的这些状态的策略都已经变好，只有比较远的状态还没变好。

这个现象就是：**接近目标的状态，它的策略会先变好；远离目标的状态，策略会后变好。**

直观上为什么会这样？数学上我们已经很清楚了（收敛性证明保证了最终收敛到最优），直观的解释是：我在某一个状态选择 greedy action——也就是对应最大 action value 的那个 action——的时候，严重依赖于**其它状态**的策略。如果其它状态的策略是不好的、乱七八糟的，那我虽然选了一个最大的 action value，但那个可能也是没有意义的；但如果其它状态有能够到达目标区域的策略，那么很显然，我走到那个状态也能达到目标区域、能得到正的 reward，所以我这时候的 greedy action 就是最优的策略。

> **结论**：当这个状态周围没有状态能到达目标区域时，它也不会到达目标区域；当周围有状态能够到达目标区域时，它新的策略也能到达目标区域。最优性就是这样从目标附近一圈一圈向外扩散的。

### 两个算法放在一起看

最后把这一讲的两个算法并排对照一下，方便抓住各自的骨架：

| 对比项 | 值迭代（value iteration） | 策略迭代（policy iteration） |
| :--- | :--- | :--- |
| 每轮的两步 | policy update + value update | policy evaluation + policy improvement |
| 是否完整解贝尔曼公式 | 否，每轮只做一步值更新 | 是，内层迭代把 $v_{\pi_k}$ 解到收敛 |
| $v_k$ 的身份 | 不是 state value，只是任意值 | $v_{\pi_k}$ 是当前策略真实的 state value |
| 收敛依据 | 收缩映射定理（指数收敛） | 证明中用到了值迭代的收敛结果 |
| 两者关系 | 同为 truncated policy iteration 的两个极端 | 同为 truncated policy iteration 的两个极端 |

读表说明：两个算法都由" greedy 选最大 q 值的 action"这一点驱动策略更新，区别在于每轮对值的处理深度——这正对应它们作为 truncated policy iteration 两个极端的含义。

## 从截断策略迭代到蒙特卡洛：把模型从强化学习里拿掉
> 对应块：BLK05 | 覆盖分集：P15-P19 | 块标题（分集名）：《第4课-值迭代与策略迭代（截断策略迭代算法）》

刚刚我们介绍了 policy iteration 和 value iteration 这两个算法，下面来介绍第三个算法——truncated policy iteration（截断策略迭代）。在开始之前我想强调：这第三个算法其实并不是一个特别不同的算法，恰恰相反，它是 value iteration 和 policy iteration 这两个算法的**一般化推广**。等你明白它之后就会恍然大悟：原来 value iteration 和 policy iteration 只是它的两个特殊情况。所以在介绍它的过程中，我会反复地把前两个算法拿出来比较——这一部分实际上是非常重要的。

而这一讲的后半段，我们将迈出整个课程里关键的一步：从 model-based 走向 model-free。上节课的 policy iteration 正是这一次课的基础，我们把它里面依赖模型的部分替换掉，就得到了基于蒙特卡洛的强化学习算法。

### 两个算法，各走各的路

先把之前学的两个算法摆出来。policy iteration 从一个初始策略 $\pi_0$ 出发——这个策略可能是非常不好的、任意猜测的策略。在第 $k$ 个 iteration 中，它包含两个步骤：

- **policy evaluation**：手里有策略 $\pi_k$，通过求解贝尔曼方程求出 $v_{\pi_k}$；
- **policy improvement**：刚才不是求出 $v_{\pi_k}$ 了吗？再求解一个优化式子，得到一个新策略 $\pi_{k+1}$，然后不断迭代下去。

value iteration 有一个最开始的区别：它不是从策略出发，而是从一个值 $v_0$ 出发——这个 $v_0$ 可以是任意值，通过算法最后能够收敛到 $v^*$，也就是 optimal state value。在第 $k$ 个 iteration 中它也包含两个部分：

- **policy update**：已经知道 $v_k$，求解一个优化式子，得到新策略 $\pi_{k+1}$；
- **value update**：刚才知道了 $\pi_{k+1}$（于是知道了相关的量），再加上手里的 $v_k$，一步就能求出 $v_{k+1}$，然后不断迭代。

到这里其实有些同学已经发现了：这两个算法非常类似。为了比较它们，我们把形式上下对齐——第二行是 value iteration，它从 $u_0$ 出发，最开始没有所谓初始的策略；为了比较，我们强行把它和 policy iteration 对齐着看：一个新策略、一个新值，一个新策略、一个新值。这两列的推进结构几乎一模一样。

```text
policy iteration:   π0 ──policy evaluation──> v_π0 ──policy improvement──> π1 ──> v_π1 ──> π2 ──> v_π2 ──> ...
value iteration:    u0 ──policy update──────>  π1  ──value  update──────> v1  ──>  π2  ──> v2  ──> ...

（value iteration 没有初始策略，为了对齐比较，强行让 v0 = v_π0）
```

读法：上下两行是同一套"策略—值"交替结构，区别藏在每一步求值的方式里。

### 关键差异：无穷步与一步

那它们的区别究竟是什么？这个是非常关键的，也是引出 truncated policy iteration 的核心。我们一步步对着比：

| 步骤 | policy iteration 在做什么 | value iteration 在做什么 |
| :--- | :--- | :--- |
| 对策略的操作 | 给定初始策略 $\pi_0$ | 还没开始——它没有初始策略，只有初始的值 |
| 对值的操作 | 由 $\pi_0$ 求解贝尔曼方程，得 $v_{\pi_0}$ | 给定初始值 $v_0$；为让两算法可比，强行令 $v_0 = v_{\pi_0}$ |
| 对策略的操作 | 由 $v_{\pi_0}$ 求解优化，得 $\pi_1$ | 由 $v_0$ 求解同一个优化，同样得 $\pi_1$（因为 $v_0 = v_{\pi_0}$） |
| 对值的操作 | 由 $\pi_1$ 求解贝尔曼方程，得 $v_{\pi_1}$ | 有了 $\pi_1$ 加上 $v_0$，**一步**就求出 $v_1$，立刻投入下一步 |

前几步两个算法每一步都是相同的。到第四步的时候就出现了不同：policy iteration 要老老实实求解贝尔曼方程得到 $v_{\pi_1}$；value iteration 只走一步就得到 $v_1$，而且 $v_1$ 马上用到下一步当中。从这一步起，$v_1$ 和 $v_{\pi_1}$ 就不再相同了，再往下走，所得到的策略和值也全都不同了。

所以关键是：$v_{\pi_1}$ 和 $v_1$ 有什么不同？我们把求解贝尔曼方程那个内嵌的迭代算法详细展开写：

$$v_{\pi_1}^{(0)} \;\to\; v_{\pi_1}^{(1)} \;\to\; v_{\pi_1}^{(2)} \;\to\; \cdots \;\to\; v_{\pi_1}^{(j)} \;\to\; \cdots \;\to\; v_{\pi_1}^{(\infty)} = v_{\pi_1}$$

右上角带括号的上标代表第几次估计：$(0)$ 是第 0 次估计，可以从任意初始值出发；代进去得到 $(1)$，再代进去得到 $(2)$，一直到计算无穷多次，$v_{\pi_1}^{(\infty)}$ 就是真正的 $v_{\pi_1}$（$\infty+1$ 还是无穷，所以迭代式在极限处成立）。这是一个典型的求解贝尔曼方程的迭代算法，没什么太新的东西。

新的东西在这个初始值上。为了比较两个算法，我让求解贝尔曼方程的初始值等于 $v_0$——$v_0$ 正是 value iteration 出发的那个值。那么：

```text
初始 v_π1^(0) = v0
  └─ 迭代 1 步  ──>  v_π1^(1)  = v1   （这就是 value iteration 得到的值，马上用于下一步 policy update）
  └─ 迭代 j 步  ──>  v_π1^(j)        （一个"中间步"：当作新值 v1π，直接放进下一步算策略）
  └─ 迭代 ∞ 步  ──>  v_π1^(∞) = v_π1 （policy iteration 要的精确值）

        j = 1            某个有限 j              j = ∞
   value iteration ── 截断策略迭代 ── policy iteration
```

读法：同一条迭代链，value iteration 在 $j=1$ 处截取，policy iteration 走到 $j=\infty$，中间任何有限的 $j$ 都是截断策略迭代。

一句话说清：在这一步，**value iteration 实际上只计算了一步，而 policy iteration 需要计算无穷多步**才能得到 $v_{\pi_1}$。那我们自然能想象：是否有一个中间步，比如我只计算 $j$ 次，把 $v_{\pi_1}^{(j)}$ 当作一个新的量，直接放到下一步计算策略当中？这样一个思路、这样一个算法，就叫 truncated policy iteration。为什么叫 truncated（截断）？因为从 $j$ 到无穷的那些步全部没有了、全部截断了。

> **结论**：truncated policy iteration 是更一般化的形式——$j=1$ 时它变成 value iteration，$j=\infty$ 时它变成 policy iteration。

这里我还想强调一个点：**policy iteration 这个算法只在理论上存在**，在实际当中是不可能存在的——它需要计算无穷多步，实际当中怎么可能计算无穷多步呢？我们经常做的是判断 $v_{\pi_1}^{(j)}$ 和 $v_{\pi_1}^{(j-1)}$ 之间的误差是不是已经足够小，足够小就停止迭代。但即便那样，它计算的仍然是有限步。所以在实际当中，我们真正想执行 policy iteration 时，它也一定是迭代的、一定是截断的 policy iteration。这就是这个算法重要的原因。

### 截断之后，还收敛吗

truncated policy iteration 的伪代码和 policy iteration 的伪代码是一模一样的，唯一的区别在一处：原来判断 state value 是否收敛，现在改成判断是否执行够了指定的次数。可以事先设定一个参数，等于 1、等于 2、还是 100、1000 都可以；小于这个数就执行，大于这个数就停。停下来的 $v_k^{(j+1)}$ 就作为新的 $v_k$，放进下一个步骤去计算策略。至于截断参数 $j_{\text{truncate}}$ 怎么选，之后我们会通过一个例子来告诉大家。

这里有一个明显的问题：我没有计算无穷多步，所以算出来的 $v_k$ 实际上并不是 $v_{\pi_k}$。这种截断会不会带来问题？比如会不会让整个算法不再收敛？这个问题完整回答起来比较复杂，这里只给一个简单的结果，从直观上给大家一些解释：

> **结论**：在求解贝尔曼方程的迭代算法中，如果初始值取一个比较特殊的值——$v_{\pi_{k-1}}$，那么可以证明 $v_{\pi_k}^{(j+1)}$ 一定比 $v_{\pi_k}^{(j)}$ 要大。

也就是说，你计算一次它也会增大，计算 $j$ 次也会增大，计算无穷多次它也会增大。而计算无穷多次付出的代价非常大，所以我们不做——用有限步就够了。关于这个结果的证明，大家可以到我的书里去看。

这个结果可以用一张图很好地展示出来。图的横轴是 $k$，也就是外面这个 iteration 的 index；纵轴是值——为了简单起见，这里的 state value 只有一维。红线代表 optimal state value $v^*$；紫线是 $v_k$，代表 value iteration，从某个点出发的值不断收敛到 $v^*$；$v_{\pi_k}$ 是 policy iteration 得到的，从相同的值出发也逐渐收敛到 $v^*$。黑色的线就是 truncated policy iteration：它每一步只做有限次迭代，是能做一些改进的，所以它比 $v_k$ 要好，但比 $v_{\pi_k}$ 要稍微差一点——正好夹在 policy iteration 和 value iteration 两者中间。

```text
值 ↑
v* │──────────────────────────── 红线：optimal state value
   │        ＿＿＿＿－－－－ v_{πk}（policy iteration，紫线）
   │     ＿＿------          （黑线：truncated，始终夹在两者中间）
   │  ＿-                     v_k（value iteration，紫线）
   │ ● 起点相同
   └──────────────────────────────────> k
```

读法：三条线从同一起点出发，上面那条收敛最快、下面那条每步改进最少，黑线在中间；既然蓝紫两条线都收敛，不难想象黑色的线也是收敛的。

### 换一个问题：没有模型，怎么估计量

下面进入第 5 次课：基于蒙特卡洛（Monte Carlo）的强化学习方法。上节课介绍的 value iteration 和 policy iteration 是 model-based 的方法；这次课我们介绍整个课程中**第一次出现的 model-free 方法**。

开始之前说明两点。第一点：上节课的 policy iteration 实际上是这次课的基础——待会大家就会看到，我们是把 policy iteration 当中基于模型的部分替换掉，换成不需要模型的部分，就得到了今天的算法。第二点是命名问题：在我们这门课当中，我们把 value iteration 和 policy iteration 也统称为 model-based reinforcement learning；但更准确地说，它们应该称为 dynamic programming（动态规划）的方法。而 model-based reinforcement learning（简称 MBRL）最近一些年又逐渐兴起，研究的是用数据估计出一个模型，再基于这个模型来做强化学习——这和我们的做法不是一回事，只是课程里沿用了这个宽泛的叫法。

这次课的大纲是：先通过一个 motivating example 介绍 Monte Carlo estimation 的基本思想，之后介绍三个基于蒙特卡洛的强化学习算法——MC Basic、MC Exploring Starts、MC ε-Greedy（MC 是蒙特卡洛的首字母缩写）。这里我想强调：**这三个算法是环环相扣的，前面一个是后面一个的基础**。MC Basic 是最最简单的基于蒙特卡洛的强化学习算法，它简单到在实际当中是没法用的——效率各方面都比较差；但它对于揭示"怎么样把模型给去掉、不基于模型实现强化学习"这个核心 idea，是非常非常关键的。后面两个算法都是它复杂化的产物：比如让数据的使用效率更高、去除 exploring starts 这样的 assumption。

### 抛硬币：蒙特卡洛估计的基本思想

从 model-based 过渡到 model-free，最让人难以理解的就是：**在没有模型的情况下，怎么去估计一些量？**这里有一个重要的方法，就是 Monte Carlo estimation。我通过一个抛硬币的例子来说明。

手上有一个硬币，抛到空中落下来，要么正面朝上要么反面朝上。把结果设为随机变量 $X$：正面朝上 $X=+1$，反面朝上 $X=-1$。要求解的问题是：$X$ 的平均数、$X$ 的 expectation 是什么？

有两种方法。第一种是 model-based 的：$X$ 的概率分布我们是知道的——正面 0.5、反面 0.5，那么 expectation 直接按定义计算：

$$E[X] = 0.5 \times (+1) + 0.5 \times (-1) = 0$$

这个方法非常简单，但问题是：这么精确的概率分布（模型），我们可能是无法知道的——这正是这次课所面临的问题。

那能不能在没有模型的情况下也去估计？答案非常简单，基本思想就是：**投掷硬币很多次，把所有采样求平均**。做了 $N$ 次实验，结果分别是 $x_1, x_2, \ldots, x_N$，先相加再除以 $N$，得到平均值 $\bar{x}$，就用它来近似 $E[X]$：

$$\bar{x} = \frac{1}{N}\sum_{j=1}^{N} x_j \;\approx\; E[X]$$

有的同学可能会问：用平均数来近似 $E[X]$，精确吗？$N$ 比较小的时候这种近似是不精确的，但随着 $N$ 逐渐增大，近似会越来越精确。比如投硬币任务做了 200 次，真实的 expectation 是 0：最开始的两次投的都是负，用它们做平均结果是负数，和真实值相差比较大；但用越来越多的数据做平均，平均数会越来越收敛到真实的 expectation。这种直观解释有很好的数学支撑，那就是 **Law of Large Numbers（大数定理）**。设 $x_1,\ldots,x_N$ 是 $N$ 个 iid（independent and identically distributed）的 sample，可以证明两个结论：

$$E[\bar{x}] = E[X], \qquad \mathrm{Var}[\bar{x}] = \frac{1}{N}\,\mathrm{Var}[X] \;\xrightarrow{N\to\infty}\; 0$$

$\bar{x}$ 本身也是随机变量，它的 expectation 等于真实的 expectation——所以 $\bar{x}$ 是**无偏估计**；而它的方差是 $X$ 方差的 $N$ 分之一，当 $N$ 趋向无穷时方差趋向 0，$\bar{x}$ 就趋向一个常数，这个常数正是 expectation。基本的证明可以到书里去看。

> **定义**：凡是需要做大量采样和实验、然后用实验结果来进行近似的方法，都可以称为蒙特卡洛估计的方法。

为什么这门课需要考虑 Monte Carlo estimation？因为我们没有模型，而它恰恰不用模型。那为什么要考虑 mean estimation？因为 state value 和 action value 的定义**本来就是 expectation**——这个到后边马上就会用到。

### 把 policy iteration 里的模型抠掉：MC Basic

要理解第一个算法，核心问题就一个：**怎么把 policy iteration 变成 model-free 的？**policy iteration 依赖模型，但实际上我们可以把它依赖模型的那一部分替换掉，换成 model-free 的模块，这样就得到了 model-free 的强化学习算法。这是最最本质的 idea，希望大家抓住。

policy iteration 每轮包含 policy evaluation 和 policy improvement 两步。policy evaluation 求出 $v_{\pi_k}$；然后做改进——求解一个最优化问题得到 $\pi_{k+1}$，而且这个优化可以针对每一个 $s$ 展开，后面那一长串就是 $q_{\pi_k}(s,a)$，也就是 action value。求解的方式我们已经知道了：选择最大的那个 $q_{\pi_k}$ 就行。

所以这里非常核心的量就是 $q_{\pi_k}$。计算它有**两种方法**：

- 第一种**依赖模型**：就是 value iteration 用的那套——第一步得到 $v_{\pi_k}$，第二步利用已知的模型求出 $q_{\pi_k}$；
- 第二种**不依赖模型**：回到 action value 最原始的定义——从 $s$ 出发 take action $a$，得到一个 return；这个 return 是随机变量，求它的期望：

$$q_{\pi_k}(s,a) = E\big[\,G_t \mid S_0 = s,\; A_0 = a\,\big]$$

model-free 的强化学习和基于蒙特卡洛的方法，核心思想就是：**用定义式的 expectation（这是一个 mean estimation 问题），替代依赖模型的计算式**。而 mean estimation 怎么解，刚才抛硬币已经讲过了——采样、求平均。具体做法：

- 从任意一个 $(s,a)$ 组合出发，根据当前策略生成一个 episode；
- 计算这个 episode 的 discounted return，记作 $g(s,a)$——注意 $G_t$ 是随机变量，$g(s,a)$ 是它的一次采样；
- 有很多这样的采样，就求平均来估计 $q_{\pi_k}(s,a)$：

$$q_{\pi_k}(s,a) \approx \frac{1}{N}\sum_{i=1}^{N} g_i(s,a)$$

> **提示**：没有模型的时候得有数据，没有数据的时候得有模型——反正你总得有一个。没有模型时我们就依赖数据。数据在统计或概率里叫 sample，在强化学习里有一个特殊的名字：**experience（经验）**。

到这里算法已经清晰了，它的名字叫 **MC Basic**。整个流程：从初始策略出发（可能是不好的，慢慢改进），第 $k$ 个 iteration 包含两步——

1. **policy evaluation**：对**所有** $(s,a)$ 求 $q_{\pi_k}(s,a)$。方法就是从每个 $(s,a)$ 出发得到很多 episode，对 episode 的 return 求平均；
2. **policy improvement**：用上一步得到的 $q_{\pi_k}$，求解优化问题，选 action value 最大的那个 action 作为新策略。

它和 policy iteration 实际上是一样的：第二步一模一样，唯一的区别在第一步——policy iteration 先求 state value 再转成 action value；MC Basic 直接通过数据得到 $q_{\pi_k}$。伪代码的结构也和 policy evaluation 类似：每个 iteration 遍历每一个状态 $s$，再遍历 $s$ 对应的每一个 action $a$，从 $(s,a)$ 出发采样很多 episode，计算 average return 作为 $q_{\pi_k}(s,a)$；下一步改进时选 action value 最大的 action 作为新策略。

在讲例子之前，我要先强调几点：

- **MC Basic 是 policy iteration 的一个变形**：把基于模型的模块拿掉，换成不需要模型的模块。所以你要明白基于蒙特卡洛的算法，首先应该明白基于模型的 policy iteration——否则上来就学这个，你可能会有很多问题，比如"我为什么要选 action 最大的作为策略"等等。
- **MC Basic 有用但不实用**：它能非常清晰地揭示"怎么把 model-based 变成 model-free"这个过程，但它的 efficiency 比较低。之后会介绍两个算法逐渐提高它的效率。另外，"MC Basic"这个名字大家在其它地方是看不到的，这是我特意起的名字。这也是我的一个想法：学习的时候，应该把**最最核心的想法**和那些让它看起来更复杂的东西剥离开来——把 policy iteration 中基于模型的部分替换掉，这就是最核心的想法；至于怎么更高效地利用数据、怎么更高效地更新、怎么去掉实际中难以实现的假设，这些会让算法看起来非常复杂（当然也更实用），但首先明白最核心的 idea 是非常重要的。
- **为什么直接估计 action value，而不先估 state value 再转？**很显然：如果先估计 state value，之后还要再转一遍，而"从 state value 转到 action value"这一步又依赖模型，肯定不行。所以直接把 action value 估计出来。
- **收敛性仍然有保证**：policy iteration 是收敛的，MC Basic 和它一模一样、只不过估计 action value 的方法有差别，所以收敛性仍能保证。未来随着算法越来越复杂，这种收敛性会逐渐消失、或者说分析会越来越复杂。

### 算例：一个迭代就找到最优策略

下面通过例子进一步学习 MC Basic。看这样一个例子：有一个初始策略 $\pi_0$，在其它状态这个策略都还不错，只是在 $s_1$ 和 $s_3$ 这两个状态不太好。我们从 $\pi_0$ 出发，用 MC Basic 找到最优策略。

MC Basic 的 policy evaluation 要求出对**任意** $s$ 和**任意** $a$ 的 $q_{\pi_k}(s,a)$。这个例子有 9 个 state、每个 state 对应 5 个 action，一共 $9 \times 5 = 45$ 个 state-action pair，所以要求 45 个 $q_{\pi_k}$。假设从每个 $(s,a)$ 出发采 $n$ 条轨迹求平均，那总共要 $45 \times n$ 条轨迹。找到 $q_{\pi_k}$ 之后第二步做 policy improvement：在每个状态选出对应最大 action value 的 action。因为时间关系，45 个不可能全算，我们就找 5 个——针对 $s_1$ 的 5 个 action 看看具体怎么做。

先做 policy evaluation。从 $(s_1,a_1)$ 出发要采 $n$ 条轨迹求平均，**但是**这个问题很简单：policy 是 deterministic 的，环境也是 deterministic 的——这意味着从 $s_1, a_1$ 出发不管采样多少次，得到的轨迹都是相同的，所以只要采一次就可以。如果是更复杂的情况——policy 是 stochastic 的，或者 policy deterministic 但环境 stochastic——那么采样不同次会得到不同轨迹，这时需要采样多次求平均。我们这里采一次，从 $s_1$ 往上走、回来、再往上走、再回来，得到轨迹：

```text
s1 ──a1──> s1 ──a1──> s1 ──a1──> ...
（s1, a1, s1, a1, s1, a1, ...）
```

读法：往上走又被弹回原地，来回循环；这条轨迹的 discounted return 就记作 $q_{\pi_0}(s_1,a_1)$。

$(s_1,a_2)$ 到 $(s_1,a_5)$ 的求法都是类似的。求出来之后做 policy improvement：比较这些 action value 哪个最大——实际上 $a_2$ 和 $a_3$ 是最大的（$a_2$ 往右、$a_3$ 往下，直观上看也是比较好的 action）。它俩的 action value 相等，所以可以任选 $a_2$ 或 $a_3$ 作为新策略，而这个新策略**已经是实现最优了**——也就是说一个 iteration 就找到了最优策略。原因也简单：这个例子本身简单，而且除了 $s_1$ 之外周围的 state 的 policy 已经达到最优了，所以它很轻松就能找到最优策略。

如果是线下，我会停下来让大家做个 5 分钟左右的练习，比如用 MC Basic 找 $s_3$ 的最优策略；线上学习的话，大家根据自己的情况来。我只想提醒一句：有时候你自己动手写一写，比你只是去看，会理解得更深刻。

### episode 长度：探索的半径

第二个例子不再是展示怎么用 MC Basic 解决问题，而是用它得到最优策略之后，去分析最优策略有什么有意思的性质。这里重点关注 **episode 的长度**。

用 MC Basic 需要数据——从任何状态和 action 出发，有很多 episode，计算 episode 的 return。这个 episode 的长度理论上越长越好，最好是无穷长，这样算出的 return 最精确。但现实中 episode 不可能无穷长，特别在我们的 grid-world 例子当中**没有终止条件**：如果不人为设置 episode 长度，它会一直持续下去。那 episode 长度设为多少才合适？这是一个很有意思的问题，大家往下看。

先看 episode length = 1 的结果：这个估计显然是不好的。length 等于 1 意味着：从 $s$ 出发 take action $a$，跳到新状态得到 reward——到这我就停止了，后面的全都不做，直接拿这个 reward 当作 episode 的 return，显然不准确。此时只有**紧挨着目标**的那些状态 value 是正数、策略是正确的；其它所有状态的 value 全是 0、策略也都不好。value 是 0 意味着它们根本就没到达目标——到达目标就会得到正数。

> **比喻**：想象我们在沙漠当中，身边有一片水源。我从原地向四面八方探索，但探索半径只有 1 公里。水源离我 5 公里，那我不管怎么探索，肯定探测不到水源，所以从这出发的策略一定是不对的；反过来，如果水源离我很近，1 公里的半径刚好能探索到它，我就知道该往哪个方向走。

所以 **episode length 直观上可以理解为探索半径的长度**。增加长度会发生什么？非常有意思：

- **length = 2**：除了刚才对的那几个状态，又多了两个状态策略变成对的——因为从它们出发正好两步到达目标，value 也是正数。但注意：有一个状态策略看起来是对的，**实际上是随机产生的**——它向上的、向左的、原地不动的 action value 都是 0，只是刚好随机选了其中一个。它的 value 是 0，意味着根本没到达目标——到达目标需要 3 步才行。
- **length = 3**：那个状态的 value 变成正数，策略就是正确的策略了。
- 继续增加：离目标更远的状态也慢慢到达目标、策略慢慢变成最优。到 **length = 14**：从某个角落出发要数整整 14 步才能到达目标，value 是正数了；但旁边还有一个状态往上走仍是随机选择——它的 value 是 0，说明没到达目标，要么原地不动、要么往上，刚好选了往上。
- **length = 15**：它就可以到达目标了——证据就是这个状态的 value 已经是正数。
- **length = 30 或 100**：策略基本上不怎么变化了，唯一变化的是 optimal state value 的估计值还在不断变化。length 很大（比如 100 或接近无穷）时，估计的 optimal state value 和真值就基本一样了。

> **结论**：episode length 比较短时，只有离目标比较近的状态才能在这么短的步骤内找到目标、找到正确的策略；随着 length 逐渐增大，离目标越来越远的状态也能慢慢到达目标、找到最优策略。总而言之，episode length 必须足够长，让**所有状态都有机会到达目标**；同时它也不需要无限长，足够充分地长就可以了。例子中走几十步几百步是给大家直观解释，实际当中遇到具体问题还要具体分析。

### 让数据别浪费：visit 与即时更新

MC Basic 探索完了，接下来介绍它的推广——MC Exploring Starts，让算法变得更高效。MC Basic 的好处是帮助我们理解怎么用蒙特卡洛实现 model-free 的强化学习，坏处是考虑得比较少、效率低。我们完全可以在两个方向上把它推广：**更高效地利用数据**、**更高效地更新策略**。

#### 数据利用：一个 episode 能喂多少个 (s,a)

先引入一个简单的概念叫 **visit（访问）**：episode 当中每出现一次某个 state-action pair，就称为对这个 pair 有了一次 visit。MC Basic 用的策略叫 **initial-visit**：对一个 episode，只考虑最开头那个 $(s_1,a_2)$，用整个 episode 的 return 来估计 $q_\pi(s_1,a_2)$。它的问题是没有充分利用 episode——里面还有很多数据被浪费了。为什么？看这条 episode：

```text
原 episode:  (s1,a2) ──> (s2,a4) ──> (s1,a2) ──> (s2,a3) ──> (s5,a1) ──> ...
                 │          │           │           │          │
截出片段:   从(s1,a2)起  从(s2,a4)起  从(s1,a2)起  从(s2,a3)起  从(s5,a1)起
            估计q(s1,a2) 估计q(s2,a4) 再估q(s1,a2) 估计q(s2,a3) 估计q(s5,a1)
```

读法：这条 episode 除了开头的 $(s_1,a_2)$，还访问了 $(s_2,a_4)$、又一次 $(s_1,a_2)$、$(s_2,a_3)$、$(s_5,a_1)$。从 $(s_2,a_4)$ 开始，不考虑前面、只考虑后面，完全可以把它当作一个**新的 episode**，用来估计 $(s_2,a_4)$ 的 action value——为什么不呢？显然是可以的。类似地，每个被访问的 pair 都能截出自己的一段，数据就利用得非常充分了。

这里还有两种略有区别的方法：**first-visit** 和 **every-visit**。例子里第一次访问了 $(s_1,a_2)$，第三次又访问了它。every-visit 是不管那么多，只要访问到一次，它后面的部分就可以用来估计 $q(s_1,a_2)$——第一次用，第三次再用一次；first-visit 则只用第一次出现，第二次出现时不再用它后面的部分来估计。

#### 更新时机：不等齐，来一个用一个

另一个方向是更高效地**更新策略**。MC Basic 的做法是把从一个 state-action pair 出发的所有 episode 全部收集齐，做 average return 来估计 action value——问题是必须等所有 episode 全都到手，等的过程自然浪费时间。另一种方法：得到**一个** episode，就用它的 return 立刻估计 action value，不要停、不要等，下一个就直接开始改进策略。一个 episode 改进一次，效率就提升了。

有同学可能会问：本来要用很多个 episode，现在只用一个来估计 action value，显然不准，这到底行不行？实际上这种思想我们在上节课讲 truncated policy iteration 的时候已经介绍过了：policy evaluation 本来要解贝尔曼方程、需要无穷多步迭代，当时我们只做有限步迭代，得到的 state value 肯定不精确，但没有关系，算法仍然行之有效。同样的思想用在这里：一个 episode 估计 action value 显然不精确，但没有关系。

> **定义**：这一类方法有一个名字，叫 **generalized policy iteration（GPI）**。GPI 不是一个具体的算法，而是一大类算法，或者说是一种思想、一种架构：在 policy evaluation 和 policy improvement 之间不断地切换，而且 policy evaluation 不需要非常精确地把 action value 或 state value 估计出来。上节课介绍的算法和这节课介绍的算法，实际上都能落到这个 GPI 框架当中。

#### MC Exploring Starts 算法本身

有了上面的思考，就可以得到新算法 **MC Exploring Starts** 了。什么是 Exploring Starts 稍后详细讲；先说它就是 MC Basic 的推广——让计算效率更高。伪代码简要过一下：先是生成一个 episode，这没什么好说的；下面做 policy evaluation 和 policy improvement，详细细节我推荐大家自己去看，这里只说一点。

假如得到了这样一个 episode：$(s_1,a_1) \to (s_2,a_2) \to (s_3,a_3) \to (s_4,a_4) \to \cdots$。正常的做法是从头遍历：第一个访问的是 $(s_1,a_1)$，把它后面所有的 reward 加起来得到 return，作为 $(s_1,a_1)$ 的 action value 估计值；然后碰到 $(s_2,a_2)$，再把后面所有的 reward 加起来……但大家在看这个算法的时候会发现，**它是从后边开始做的**。为什么？实际上是为了提高计算效率。举个例子：假设后面部分的 return $g$ 已经算出来了，那么计算 $(s_3,a_3)$ 时就不用再把后面所有 reward 全加一遍——设从 $(s_3,a_3)$ 出发得到的 immediate reward 是 $r$，那么

$$g \;\leftarrow\; r + \gamma g$$

这个新的 $g$ 就是从 $(s_3,a_3)$ 出发的 return，又可以用来计算 $(s_2,a_2)$ 的 return——同样是 $r + \gamma g$，这里的 $r$ 是从 $(s_2,a_2)$ 出发得到的 reward。这样通过**倒推**的方式，就能比较高效地把整条 episode 上所有 pair 的 return 都算出来。所以大家在看很多算法时会觉得"为什么会有这么复杂的东西？"——其实都是这种小技巧，用来提高计算效率。

#### 为什么需要 exploring starts

为什么需要 exploring starts 这个条件？它为什么是必要的？紧紧抓住这两个单词的含义就可以。

- **exploring** 指的是：从**每一个** $(s,a)$ 出发都要有 episode。只有这样，才能用后面生成的 reward 来估计 return，进而估计 action value。如果恰恰有一个 state-action 没被访问到，我就可能把那个 action 漏掉了——但那个 action 恰恰又可能是最优的。所以为了得到最优策略，要确保每一个 $(s,a)$ 都能被访问到，这就是 exploring 的含义。
- **starts** 指的是：要访问每一个 $(s,a)$、从它后面生成数据，其实有两种办法。第一种是从 $(s,a)$ **开始**一个 episode——这就是 start；第二种是从其它 $(s,a)$ 开始，但 episode 能**经过**当前的 $(s,a)$，那后面的数据也可以用来估计当前 pair 的 return——这叫 visit。两种情况其实都可以，但目前的 visit 没办法确保，因为它依赖于策略、依赖于环境：我怎么确保从其它的 $(s,a)$ 出发一定能经过剩下所有这些 $(s,a)$ 呢？没办法确保。所以我只能用比较笨的方法：确保从每一个 $(s,a)$ **开始**都一定有一个 episode。

不过，exploring starts 虽然重要且必要，**在实际当中却难以实现**。比如网格世界里有一个实际的机器人，它要从不同的 $(s,a)$ 出发，我就必须把它搬运过去、设置好程序等等，会比较麻烦——理论和实际之间存在一个 gap。那能不能把 exploring starts 这个条件去掉，或者转化成其它的形式实现？答案是可以的，我们需要用到 **soft policies**——这就引出了第四部分，MC without exploring starts，我们会介绍一个叫 MC ε-Greedy 的算法。
