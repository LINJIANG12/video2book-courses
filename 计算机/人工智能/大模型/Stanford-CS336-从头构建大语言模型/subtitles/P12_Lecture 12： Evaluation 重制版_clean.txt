好，那去年出了個升級版，稍微難一點。大家看這個，這些。所以這就是軌跡。ARC-AGI-1 出來的時候，你們知道的那個 thing，我覺得這其實就是零分，基本上模型什麼都沒做出來。這就跟 GPT-3 一樣，預訓練模型根本沒帶來任何提升，對吧？而這完全在出題方的預料之中。預訓練模型只是比如說去學互聯網上有哪些事實，或者學一些語言規律，但這些其實都沒什麼直接的幫助。至少對這些 ARC-AGI 任務來說是這樣。

然後到了 2024 年，發生了一件事。準確說在這個時候，OpenAI 發布了他們的 o1 和 o3 模型，隨後局面就開始迅速打開了。比你想的突然。而現在這就是我們的 ARC-AGI-1 基本上算是解決了。而且到了 2025 年左右，ARC-AGI-2 出來之後，它也是這樣。雖然還沒完全解決，但你看它正一步步走向那一步，最終被徹底解決，被解決。所以真正被解鎖的其實就是推理能力。

就這點，現在大家可能會想，對這些任務來說，預訓練裡那些知識真的有必要嗎？當然要是沒有預訓練，就不會有今天推理模型的這種爆發。可以說它依然重要，但在 ARC-AGI 發展的很長一段時期裡，這種重要性並不明顯。就在上個月，ARC-AGI-3 發布了。大家可以看到這種熟悉的模式。ARC 的開發者一看，心想哎呀該出新的基準測試了，於是現在的測試變成了一個交互式環境。你可以上網玩這個遊戲，同樣這裡沒有語言，你只是試圖通過觀察模式來找出規律。挺有意思的，不過現在的得分非常低。明年我上這門課時，肯定得更新這張幻燈片。咱們走著瞧吧。

覺得 ARC-AGI 這條發展線挺有意思的，值得琢磨。一字上目標是將推理與知識解耦，這真的很難。但你知道，我覺得這大概是目前最好的嘗試了。目前還不太清楚是不是真能把這些東西完全解耦。當然了，要是大家真在意這個 benchmark，我覺得他們多半是能做到的。我覺得基本上什麼都能拿來做 benchmark，所以你完全可以設計出這類問題。

這些還是來自某種先驗，而且我也說不準是不是真存在所謂純粹的推理。這也只限於人類能做的推理。它的明確目標就是在合理時間內讓人百分之百能做出來，所以這其實沒法延伸到超人類的推理上。比如拿到國際數學奧賽 IMO 金牌，或者攻克數學上那些尚未解決的難題，這些可以說仍然非常有用、很重要。但很明顯這暴露了當前模型的一些短板，所以如果你把目標理解成基本上能解決所有任務，那確實還有不少工作要做。

——ARC-AGI-3 遊戲看起來挺圖形化的，那麼這裡面是涉及某種多模態前端，還是說它只是一種文本表示？

對，問題在於這看起來非常圖形化，很有畫面感。那輸入給 language model 到底是什麼呢？我不太確定具體的分辨率，我猜是 64×64 的。所以你既可以直接提供這張圖，也可以用 ASCII art 或者某種文本形式來表示。不管用哪種方式，這裡都有一種空間屬性是模型必須去推理的。Thank you. 這真的不算英語或者自然語言吧？謝謝。

好，那咱們換個話題，聊聊另一類跟安全性有關的基準測試。所以關於安全和 language model 的討論已經有一陣子了。你再想想其他領域，比如汽車，這裡安全指的是什麼就很清楚了。汽車有安全評級，這涉及到把車撞向牆壁，測試安全氣囊的效果，看它保護的怎麼樣，保護車裡的假人。這是經過幾十年遊說，才一點點搞清楚車輛安全到底指什麼的結果。

那這對 AI 又意味著什麼呢？說實話這裡沒有現成的好答案，但我可以舉些例子，說說大家都是怎麼想的。比如有個叫 HarmBench 的基準測試，主要就是用那些有害的內容去 prompt 模型，期望模型基本上會拒絕回答。這就是一種類型的安全，我覺得。大家一提到安全，最核心的想法可能是我想要防止那些不懷好意的人利用 language model 幹壞事。但事實證明這並非唯一關鍵的因素。所以有一項叫 AIR-Bench 的研究，它試圖通過審視歐盟、中國以及美國的公司政策從整體角度來考量安全性，並建立了一套涵蓋所有不同潛在風險點的分類體系，接著利用這套體系構建一組特定的提示詞並進行評估，以此類推。

不過安全性方面有個問題是越獄，這屬於一個獨立的子問題。也就是說 language model 通常被訓練去拒絕有害指令。但正如大家所知，只要方法得當就能繞過這一限制。因此早期有一些研究採用自動方法來優化提示詞以繞過。使用 GCG，它本質上是一種逐坐標優化算法。而且值得注意的是，在開源模型上進行優化，使我們能夠將這些效果遷移到其他模型。我希望這些攻擊現在不管用了，但在那會兒咱們確實能生成一堆 basically 胡言亂語的東西，然後一步步規劃怎麼毀滅人類，而 OpenAI 的模型居然就照做了。當然你可能會說這算不算一個毀滅人類的有害計劃，但這至少說明當時的模型並沒有拒絕。正常情況下它應該拒絕才對。

好，這就帶出了一個更大的問題：到底什麼是安全性？讓這事兒變的棘手的是，安全性的很多方面都高度依賴具體情境，畢竟它牽扯到政治、法律還有社會規範。這在不同的國家各不相同。所以談到安全性，你就得先搞清楚風險到底有哪些。風險實際上也非常多樣，可能需要分別給予不同的關注。

所以幻覺是個風險，尤其是在醫療、法律或者金融這類場景下。不過這其實也跟能力掛鉤。打個比方，要是你把模型做得更准，那它就跟少出現幻覺有關。阿諛奉承是個問題，教唆犯罪是個問題，但這可能跟能力是反著來的。不平等或者因為能力提升而丟掉批判性思維，這也算個風險。如果你想一想 language model 對這個世界產生的社會影響，再想想所謂安全就是確保 AI 能造福於人，這其實是個挺複雜的話題。我時間有限，沒法展開細說。

最後 language model 還有個雙重用途的問題。網絡安全 agent 既可以用來入侵系統，也可以做滲透測試讓系統更安全。所以討論它們到底是安……風險還是真正有意，這其實是個雙刃劍。

好，咱們接下來，咱們聊聊更宏觀的一些考量。關於評估，我覺得評估裡很重要的一點就是現實性，或者說生態效度。評估能在多大程度上反映真實世界的使用？比如考試就跟真實場景差得挺遠的。像 Chatbot Arena，數據都來自真實用戶，但咱們可能會想這種用戶分布或者使用場景的分布到底對不對呢？我後面會提到幾個 benchmark，他們試圖去衡量生態效度，尤其是在用例層面，至少不是針對單個 query 這個層面。

好，所以 OpenAI 做了一個叫 GDP-Eval 的 benchmark。然後他們挑了美國 GDP 排名前九的行業，涵蓋 44 種不同職業，找了一批專業人士來創建任務。這些專業人士大概有 14 年的經驗。你能看到裡面有護士、禮賓接待、房產中介、影視剪輯師等等。他們創建了一堆任務。

這是醫學領域的另一個例子。在此之前，很多醫學 benchmark 都是基於標準化考試的。其實對咱們人類也一樣，你得考這些標準化考試從醫學院畢業，然後才能上手做手術。其實流程更長，你不會直接給病人做手術。所以重點在於對於 language model，你也不能只是讓它通過醫學考試就直接部署。所以這是一個項目，你知道的。這 121 個任務由 29 位臨床醫生提供，目的是模擬臨床醫生真正會向 language model 提出的問題。這和那種多項選擇題式的考試完全不一樣。

這裡還有另一個項目，它用的是真實數據。那麼咱們想想誰手裡真正掌握著人們行為的數據，是模型開發者嗎？所以這個項目挺有意思，因為它用 language models 本身來分析真實數據。所以尤其是出於隱私考慮，你沒法直接去查看那些人的數據，但你可以讓 language models 去查看數據並分析總結出一般規律。所以 language models 就能告訴你人們都有哪些類型，以及大家一般用 Claude 來做什麼。

有時候真實性和隱私會相互衝突，因為理想情況下你其實希望能拿到真實查詢流裡的樣本。這對評估能了解一個模型的運行效果並深入理解錯誤究竟出在哪兒是非常有價值的。但這又會觸及隱私方面的考量。

好，那麼還有一個要考慮的點，也就是另一種效度，那就是總的來說，我們怎麼知道這些評估在科學上是有效的呢？這一點其實很早就被提出來了，叫訓練任務重疊或者說數據污染。所以在機器學習入門課裡你會學到不要在自己的測試集上訓練。希望如此。在基礎模型出現之前，這其實是相當……明白吧？以前用 ImageNet、SQuAD 這些數據集做基準測試時都有明確的訓練集和測試集，大家玩的都是同一套規則。你在訓練集上訓練，在測試集上測試，事情很簡單。

但現在我們面對的是那些在網絡上訓練出來的模型，而且遠不止於此，還有你根本不知道數據裡到底有什麼。所以我覺得這讓評估變得很不一樣。那咱們能怎麼辦呢？首先你可以試著推斷一下模型是不是真的見過這些測試數據。這個想法挺巧妙的，這是 Task 團隊提出的。他們利用了一個事實：基準測試裡問題出現的順序本應是隨機的，但如果模型偏好某種與基準測試一致的特定順序，那很可能它只是在那個基準上訓練過。

另一種辦法是你可以鼓勵大家主動報告。就，你知道，就是實際訓練集和測試集有重疊。所以這其實是個規範問題對吧？我覺得吧，可能在機器學習裡不太常見，但在統計學裡大家都會報告置信區間。得出一個估計值，但我總想知道這個估計值靠不靠譜，這就是標準做法。所以這篇立場論文的想法是，你們這些模型提供商如果打算聲稱拿到了某個 GPQA 分數，那就應該給出依據，證明你沒拿測試集去訓練。

所以還有個路子就是乾脆放棄。就是說好吧，所有這些評估咱們就假設大家都拿它們去訓練過了，先假設最壞的情況。所以呢，我們網站上有個功能就是你可以隨時定義全新的評估。所以這裡有一堆點子，比如 LiveCodeBench、Untreatable Eval，他們主要就是去抓取新網頁、歸檔論文或者 GitHub 上的內容，然後定義那些超出截止日期的評估，也就是超出 language model 截止日期的那些。所以這看起來挺靠譜，效果也不錯。但有一點要記住，時間戳也不一定靠譜。因為比如我可能會發布一個帶代碼倉庫，你懂的，舉個例子，我可能往 GitHub 上放點東西，但它其實是從別的某個倉庫衍生來的。那我怎麼知道那東西是不是真的全新的呢？謝謝。

第四條路是用私有評估。像那些公司、模型開發者就是這麼幹的，對吧？所以如果你是 Google 或者 OpenAI，你有自己的內部代碼庫，你可以認為它不在互聯網上，而且你顯然不會拿這些數據來訓練，所以你可以拿它來做評估，這通常是相當可靠的。而如果你不是一家公司，你可以用你個人寫的東西。我讀研的時候有一堆被拒的論文從來沒放到網上，所以我可以用那些。而這類評估我覺得對 perplexity 評估非常有利，因為做 perplexity 你只需要一個好的數據集就能評估對數概率。謝謝。

我要提的另一個顧慮是數據集質量。還記得吧？我之前展示過 SWE-bench Verified 的排行榜。這是因為 SWE-bench 有一堆問題，有些任務的單元測試不夠嚴謹，還有其他一些毛病後來都被修正了。就，你知道其實還有很多別的 benchmark，比如 ARC、MMLU，這些 benchmark 都經歷過這個過程。大家做了更仔細的核查，然後發現等等，等等，這道題其實有點不對，它本身是不是哪裡出了問題。謝謝。好，比如這個例子，文本裡沒給曲線，所以你沒法回答這個問題。謝謝。你看這嬰兒穿襪子了嗎？謝謝。

還有一篇論文指出 agentic benchmarks 問題很多，這可以說更難評估，因為它不只是看問題和選項那麼簡單，而是一整個環境。答案你可以看一看，但它是一整個環境。而且有些情況是這樣的，你知道寫代碼時有能跑通或跑不通的 test cases，當然很好，但咱們都知道 test cases 可能不全，所以你可能過了所有測試，代碼卻還是沒法用。TAU-bench 基準測試裡還有另一種情況，如果 agent 直接輸出空響應，得分能到 30% 左右。這即是基準測試裡有些瑣碎的問題，咱們得小心避開這些坑。我要提一下 DAWSON 這個工具，它用 language model 來檢查 agent 的運行軌跡，從而發現問題。所以這算是對我們這種重度量化的基準測試方法的一種定性回應吧。

我總建議大家，不管是你自己搞基準測試還是跑模型，一定要看看輸出結果，試著審核一下，確保你測的真是你想測的東西，你在認真測的東西。謝謝。

好，那麼你知道咱們接下來也許會要聊得更有哲學意味一些。評估到底是為了什麼？好，我剛才聊了各種評估類型，其實根本不存在一種能通吃所有情況的評估方法。我覺得你在考慮評估的時候得把目的想清楚。我覺得這點經常沒說清楚。打個比方，你可能是個用戶或者公司正在糾結要不要買，你是要為某個具體場景選 A 還是選 B？或者你是做研究的，憑直覺覺得智能是怎麼回事，想找個法子測一測？或者你是出於商業或政策上的考慮，想搞清楚它到底有什麼好處和壞處？或者你是搞模型開發的，想聽聽反饋，好把模型改得更好？所以不同的目標會讓你就選不同的基準測試，或者把幾種評估方法混著用。

最後還有件事得說清楚，我前面稍微提過，就是咱們到底在評估什麼。基礎模型出來之前，大家評估的是方法，因為咱們有訓練集和測試集，唯一變的就是算法本身。而今天咱們主要評的是模型和系統，這裡面什麼因素都可能變。其實也有例外，比如 nanoGPT 速度競賽，這是一種刻意設計的評估方式，主要用來衡量算法性能，尤其是模型訓練的速度有多快。不過大多數 language model 評估其實都是針對最終成品的，這很有用，畢竟這才是真正要上線供用戶實際使用的東西。但我覺得關鍵就在於你得始終非常明確地去界定，也就是明確你的目標，好吧。所以不存在唯一的標準評估，關鍵在於你選擇去測量什麼。

我們聊了不少不同的 benchmark，從困惑度開始，包括基於考試的、聊天場景、智能體交互還有推理和安全方面的。這些 benchmark 在難度、真實感和有效性上各不相同，而且往往需要權衡取捨。很難同時做到既高度真實、極具挑戰性，又具備生態效度，同時還完全避免訓練數據和測試數據的污染。你通常得在這些因素之間做個取捨，具體取決於你的目標，你得決定自己願意在哪一方面讓步。
