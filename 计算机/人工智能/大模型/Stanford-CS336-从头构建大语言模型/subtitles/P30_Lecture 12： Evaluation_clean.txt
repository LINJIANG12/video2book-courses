那今天我们要讲的是评估。到目前为止，这门课里训练一个 language model 需要做的，我们都已经做过了。我们定义了架构、优化器，还有主训练循环。我们讲了怎么用 kernel parallelism 让训练跑得更快，然后还看了 scaling laws。我们还稍微看了一点怎么让 inference 也快起来。所以现在唯一还没讲的，就是用来训练的数据。我们下周会专门花时间讲这个。数据会塑造模型的行为。如果你用代码来训练，那你的模型多半就会擅长处理代码。如果你只用 DNA 序列来训练它，估计连英语都不会说。不过在讲数据之前，我们得先说清楚，我们希望模型具备什么样的行为，而这正是评估要讨论的主题。

所以，评估其实就在问一个很简单的问题：咱们训练好的这个模型，到底有多好？那到底什么叫好呢？乍一看，评估好像就是个挺机械的流程，你定好一些 prompt，发给模型，拿到回复，然后算算准确率。那为啥我们要花整整一节课来讲评估？其实，评估是个很深奥的话题，而且特别关键，因为正是评估在塑造 AI 的发展。评估就像是指路明灯，不管是做开源模型还是闭源模型的开发者，大家都盯着它看。它就像是衡量我们进步的一个尺子。所以，你认真琢磨怎么评估，其实就是在无形中决定你的模型将来能做成什么样。

那评估难在哪呢？通常一开始你脑子里只有一个比较抽象的想法：我到底想让模型干啥？比如，我可能希望我的模型在对话或推理方面表现出色。好的，这些都是抽象概念，而评估的过程其实就是把这些抽象概念转化为具体指标，这通常要依靠一些具体的 prompt 或环境来实现。所以，这就是我们要面对的核心挑战。接下来我们会看到很多例子，展示这种从抽象概念到具体指标的转化过程是怎么发生的。

那么让我们回到“什么样的模型才算好”这个问题上。表面上看，如果一个模型在基准测试上表现不错，那它可能就算是个好模型。这里有一个网站叫 Artificial Analysis，它现在基本上成了衡量模型所谓智能水平的一个标准。所以如果你打开 artificialanalysis.ai，就能看到从 GPT-4o 往下排列的各种模型排名。其实在这之后还有很多模型啊，总之，这是一个衡量标准。它包含了许多不同的数据集，其中一些我们后面会讲到。

又或者，如果一个模型在基准测试中表现优异，同时运行成本低，那它就算好模型，毕竟成本是个重要考量。图，这张图展示了之前的 Intelligence Index 以及运行该模型所需的费用。这是基于 inference cost 运行特定模型的情况。你可以看到，正如预期的那样，这两者确实存在相关性。运行花费越高，Intelligence Index 通常也越高，但两者并非完全对应。

又或者，如果人们只是单纯更喜欢某个模型，那它就算好模型。稍后我们会深入探讨，这就是 LMSYS，前身为 Chatbot Arena 所持的观点。我们可以根据人们是否喜欢某个模型，来对模型进行排名。

又或者，如果人们选择使用某个模型并为此付费，那它就算好模型。所以 OpenRouter 就是这样一种服务，让你能通过一个统一的端点来调用多种不同的模型。这样一来，他们就收集了大量关于大家都在用哪些模型的统计数据。他们还把这些数据公开了，看看通过 OpenRouter 用的最多的那些模型，是挺有意思的。当然，这并不能代表所有模型的使用情况，但它能让你大致了解 OpenRouter 上的用户都在用什么。所以，这更像是一种经济学视角：我不知道什么才算好，但如果有人愿意为它付费，那它一定不错。

好，咱们接着往下说。这些答案未必都对，我也不确定到底有没有标准答案，我只是想让你换个角度思考一下究竟什么才算好。那咱们现在就开始，来看看评估 language model 有哪些不同的具体的方法。要开始的话，没有比回到 language model 的核心思想更合适了。简单来说，它就是在 token 序列上的一个分布，P(x)。从这个角度来看，评估分布有一个很自然的方法，比如困惑度、似然或者对数损失。这些概念其实都挺相关的，基本上就是说，我拿个测试数据集 D，看看我的 language model 给它分配了多少概率质量，然后我做了归一化和除法，这样数值就更容易理解了。但核心问题就是，我的概率 language model 到底给这个数据集分配了多少概率质量？好的，这挺自然的。实际上我们在训练时最小化的就是训练集上的困惑度。

好的，那最直观的做法就是在测试集上测困惑度，这也是过去很多年里语言建模研究里大家传统上都在做的事。在整个 2010 年代，你随便拿篇语言建模的论文来看，做的基本都是这件事情。那时候常用的数据集有 Penn Treebank 和 WikiText-103，还有个 10 亿词规模的基准，它的数据是从别处采集来的。机器翻译的元数据，这全都属于经典范式，也就是做分布内评估。你用数据集的训练部分来训练模型，再用测试部分来评估效果。大家确实进步挺大，不过主要就看困惑度降低了多少。比如 2016 年有篇很有名的论文，它证明了把 CNN 和 LSTM 用到这个 10 亿词基准上，困惑度能大幅降低。记住，那时候人们还在聊 n-gram 模型，可能还有那种混合模型。这是第一个决定性的结果，证明纯神经网络这条路显然才是正确方向。那时候挺简单的，你在训练集上训练，在测试集上看困惑度。

2019 年 OpenAI 推出 GPT-2 的时候，他们用了个叫 WebText 的数据集，就是从 Reddit 上链接过来的 40GB 网页文本。不过他们的评估方式其实不太一样，他们在别人都在用的标准数据集上做了零样本评估。这属于分布外评估，这是他们论文里的一张表，展示了他们训练不同模型的效果，最大的那个模型有 15 亿参数。他们取得了相当明显的提升，特别是在那些小数据集上。举个例子，PTB 是个很小的数据集，跟 SOTA 比起来，它的困惑度是 35%。现在，如果你手头有足够多的分布内数据，效果其实还不如那些最先进的方法。不过话说回来，这个模型压根没在 10 亿词规模的数据集上训练过，能做到这样已经挺厉害了。也许有点数据重叠吧，我也说不准，毕竟我不确定他们有没有认真做过训练集和测试集的去重。

So，这也开启了一种看待 language model 的新范式：不再只盯着分布内的设定，而是我们想要在大数据集上训练，然后在标准基准上评估。这在今天我觉得早就成了标配，但在当时还被看作挺新鲜的做法。谢谢。

那，既然咱们聊到困惑度，我还想提一点：你需要的其实就是困惑度。这话说得别太当真，不过我觉得这确实是推动许多 language model 研究的一种思维模式。基本逻辑是这样的：假设存在一个真实分布，我们叫它 t，而你正在训练模型 p。那么你能获得的最嘉困惑度是多少？最佳困惑度就是那个真实分布的熵，只有当 p 与 t 完全一致时，才能达到这个值。所以，通过最小化困惑度，你本质上是在不断压低困惑度，而唯一的极小值点就出现在你真正得到真实分布的时候。一旦掌握了真实分布，你就通关了。你只需对万事万物建模，就能解决所有问题，比如根据问题生成解法或者根据提问给出答案。所以，只要不断压低困惑度，我们最终就能实现通用人工智能，这就是这个论点。

说实话，这听起来可能有点不切实际，但在我看来，这确实是推动许多人不断扩展 language model 的核心动力，尤其是在那样一个时期里。效果提升没那么显著，在 GPT-3 出现之前，大家其实并不确定语言模型能带来这么大的影响。当时大家坚信，只要把困惑度降下来，好事自然会发生。

所以，当然，困惑度可能并不是全部。换种说法，困惑度提供的信息可能超出了你的实际需求。打个比方，如果句子是“斯坦福大学成立于 1885 年”，困惑度会对所有 token 的预测结果都进行惩罚。具体来说，它会去计算在已知其他词的情况下，1885 出现的概率。这个 token 其实挺有用的，它本质上就是一个问答示例，只是伪装成了句子补全的形式，所以它能捕捉到关于世界的知识。不过，像句首词或者像 founded 这种词，我觉得就没那么有意思了。但 perplexity 可不管这些，只要你的输出偏离了真实分布，它就会按每一个 bit 的偏差向你计费。
