第一篇是 MiniCPM，我想这是 2024 年的，是一个高性能的 small language model。还有 DeepSeek，大家现在都很熟悉了，我不用再解释为什么要讲 DeepSeek，这很好。不过我们还是先从 MiniCPM 讲起。我挺喜欢这篇论文的，尤其是它刚发表的时候，当时感觉非常新颖，很有前沿感。即便到了 2026 年，我觉得 MiniCPM 团队做的很多工作对我们依然很有启发。这不过后面讲到新论文时会细说。不过我感觉现在大家似乎已经默认了一些经典的 scaling 操作，比如怎么设学习率、怎么做 Chinchilla 优化，这些基本都成了标配。我觉得这类东西现在大家都觉得是理所应当的了，就像大家默认你肯定知道该怎么操作一样。所以现在论文里很少再提这些了。正因如此，回过头来聊聊这些早期的论文其实挺有意义的。

MiniCPM 是中国 open-source 社区里一群来自业界、学界还有合作伙伴的朋友一起搞出来的项目，目的是做一个高性能、参数规模中等的 language model。当时它刚出来的时候，在 1B 到 2B 参数这个档位里基本上算是顶尖水平了。虽然现在 Gemma 和其他 2B 或 3B 的模型性能更强，但 MiniCPM 依然是训练良好、具备竞争力的模型，至少放在 2024 年的标准来看是这样。

那这些模型怎么训练呢？正如我之前提到的，咱们得把一些 scaling 参数调对。我今天想重点强调的一点是，初始化这事儿特别重要。初始化之所以重要，是因为它能让某些超参数不那么依赖模型规模。

那么我想先从这篇 MiniCPM 论文里提到的第一个技术聊起，它是一类特殊的初始化方法叫做 muP。那么 muP 的核心思想就是，无论模型规模如何放大或缩小，我都希望最优学习率保持不变。我在两三次课之前简单提过这个概念，希望大家还有点印象。但这是我们今天要讨论的第一个真正的具体实现。

它具体长什么样呢？MiniCPM 这篇论文列出了一系列操作：他们会缩放嵌入 embedding 的输出，按层数的平方根来缩放残差连接，对所有矩阵形状的张量则依据 fan-in / fan-out 比率来缩放它们的初始化，他们还会调整张量的学习率，大家请注意这一点。这一点之所以显得特别，是因为如果你平时不习惯按参数设置学习率，会觉得有点奇怪。另外他们还会对 language model 的 head 做缩放。咱们后面会聊为什么要这么做，以及这些缩放比例是怎么推导出来的。

简单说，你只需要把初始化和学习率的设定稍微改一改，希望能让训练过程更稳一点。当然我们这儿训练的是个小模型，但还是想搞一套像样的缩放策略。做这个研究的一个目的，就是不想靠训练几百个模型去暴力穷举，从而得到那个 1.5B 的模型。咱们希望第一次就把超参数调准，所以会先训练一堆小得多的模型，然后搭一个缩放阶梯，一路扩展到目标大小，大概五倍左右。所以他们阶梯上最大的那个模型和最后真正发布的那个模型之间差了大概五倍。他们的目标是想把那些大家普遍认为很敏感的参数定下来，比如最佳批量大小、学习率，还有咱们在 Chinchilla 里提过的 token 与模型规模的比率。

他们其实也想复现一下 Chinchilla 的分析。这事儿现在对我们来说没那么重要了，对你们估计也一样，哪怕你们正在做训练。不过我还是得聊聊这个，因为他们做这件事的方式里有个关键点，我觉得特别有价值，也很实用。

好，就像我刚才说的，搞这种叫 muP 的奇怪初始化，或者说非标准初始化，主要目的就是想让最优学习率保持稳定，是吗？至少在 MiniCPM 这个例子里答案是肯定的。事实上他们的实验结果非常干净、漂亮，他们在各种模型上扫了学习率，所以每条线就是一个模型的大小。最小损失基本就在 10 的 -2 次方那儿。我猜对于最小的那个模型，最小值稍微偏了一点，但即便如此也挺接近最小值的。所以这是 muP 方法的一个很好的成功案例。接下来我们会聊聊其他几个用了 muP 的模型和论文。这不是唯一的方法，但确实是一种有效的方法。如果你能做到类似这样的效果，基本上就不用再去调学习率了。

不过当然，哪怕你有个漂亮的参数化方案，把学习率锁定在某个最优值上，你的最优 batch size 也还是不会保持不变。所以你看，batch size 其实是随着数据集规模和模型规模变化而变化的。在他们的案例里，他们跑了一批这样的模型训练，你在这些图上看到的一列点就代表一次训练。他们把 batch size 固定，然后增加处理的 token 数量，我猜是从下往上递增的。

然后他们问：好，我们做了这么多次训练，那把这些二次曲线拟合到每一条线，也就是这些等损失等高线上最优的 batch size 是多少？结果他们发现最优 batch size 大致是随着处理的 token 数量按比例变化的。他们在不同规模的模型上都试了一遍。考虑到我们在 Kaplan 论文里看到的临界 batch size 那些漂亮的缩放规律，这个结果你应该不会觉得意外。不过最优的 batch size 相对于目标 loss 来说确实呈现出一种幂律结构。所以你看，这就很像 Kaplan 那套分析逻辑：如果你的 loss 更低，也就是在图的左边，那 batch size 就得更大，对吧？这就是临界 batch size 的缩放规律。所以既然你已经通过 scaling laws 反推出了一个特定的 loss 目标，那你基本上就能定下那个最优或者说临界 batch size 了，这样能帮你找到最佳的权衡点，对吧？这里有个很清晰很干净的规律，有了它，你就能非常轻松精确地把 batch size 定下来了。

谢谢。好，那咱们刚才说的这两点，batch size 和学习率的缩放，后面还会反复提到。可以说它们是做 scaling laws 时最重要也最敏感的两个参数。

不过我最后还想讲讲 MiniCPM 论文里我觉得很关键的一点。所以大家还记得吧，要做 Chinchilla 的话，咱们得训练好多个不同的模型。咱们举个例子，这次要做的是 IsoFLOPs 实验。也就是说我把浮点运算量预算固定下来，然后去调整 token 数量和模型大小之间的取舍。具体怎么做呢？我会增加训练数据的量，也就是增加训练的序列数量。不过随着序列数量增加，大家要记住，每个序列得到的学习率调度是不同的。你们用的都是余弦学习率，但它们的曲线长得不一样。你得在训练前就清楚最终的总预算，才能定出余弦调度。

这就带来了一个挺让人头疼的问题，你不得不反复重新训练模型。比如你想训练一个 800 万序列的模型，你不能接着 400 万训练模型的末尾继续训，你必须从头开始，因为学习率调度从根本上就不同，这真的很让人头疼。从某种意义上说，这么做的成本相当于二次方增长，因为你

每次都得从头开始重新跑训练。呃这太浪费了，我想很多人也是这么觉得的。我觉得MiniCPM论文里有个很不错的方案，现在一般叫它预热稳定衰减学习率，这是个挺通用的叫法。它的形状大体上是个大梯形。首先是一个预热阶段。呃预热阶段通常按固定的步数来定义，而不是按训练总量的比例来定，也就是跟你的训练总时长无关。接下来会有相当长的一段时间，把学习率保持恒定，这就是稳定阶段。然后在最后，学习率会比较快的衰减到零，这就是衰减阶段。一般来说，衰减阶段大约占整个训练总量的10%到20%。

所以在训练的绝大部分时间里，学习率都保持稳定，然后在最后阶段迅速衰减到最大学习率的10%左右。这就是典型的预热、稳定、衰减学习率策略。

好，那我们为什么要这么做呢？这么做的意义何在？我们之所以用WSD，是因为现在只要稳定阶段一结束，我们就能随时重启训练。所以，如果我想复用之前的训练，并继续跑下去，我只需要把训练回滚到上一个稳定的检查点就行。接着，我就接着稳定阶段的学习率继续往下跑，然后再把模型重新衰减到零。

所以，这让我们能很方便地做数据规模实验，基本上不用每次都重新跑一遍。你每次都得重新衰减，但这可能只占总成本的10%左右。反复做衰减可比反复重跑预训练划算多了。这是一个很常见的技巧，很多地方都在用。我给大家看个性能对比吧。

以前有很多这种形式的图。我想最近是谁做的来着？也许是Martin Jaggi他们，我记得是在ETH，他们对WSD的性能做过深入的研究。不过我觉得很多论文都展示了类似的情况。你会有一个调得很好的余弦学习曲线，这是这条橙线，然后还有各种WSD曲线。WSD曲线看起来总有点怪怪的，因为在进入衰减阶段之前，你的表现看起来差远了，直到进入衰减阶段，你突然又把之前落下的全都追了回来。收益都追回来了，然后你的表现大致能赶上，甚至有时超过余弦学习率的表现。

凭经验来说，要是你去问那些训练模型的人，很多人会说，余弦调度在很多情况下稍微好一点，但WSD在不少其他场景下其实也差不多好。它就像一个非常通用的默认学习率。如果你只是想接着跑之前的实验，通常不需要重新跑。不过，如果你以前没试过学习率衰减，看到它带来的影响有多大，真的挺震撼的。学习率衰减这一步，对于搞定训练最后那个退火阶段真的特别关键。

好，这就是之前的对比。好了，既然咱们有了WSD风格的学习率，Chinchilla风格的分析其实就很简单了。你主要要做的就是跑一次长周期的训练，然后把检查点回退，反复做衰减。这样你就能在数据维度上扫一遍，同时也在模型维度上扫一遍。你可以做 non-embedding FLOPs 分析，或者任何你想做的其他分析。MiniCPM的作者不知为啥选了方法一和方法三来复现。我觉得这两个在Chinchilla方法里最不可靠，但他们出来的 scaling 曲线确实挺好看的。

你看，MiniCPM那个Chinchilla方法一得到的下包络线挺漂亮的，基本都成线性。是挺好的。然后是方法三，在计算量和非嵌入参数的权衡上，大部分时候他们得到的scaling曲线都很平滑。看起来大多数情况下，他们得到的拟合结果都挺符合Chinchilla规律的。有一点我得提一下，就是他们得到的指数差别挺大的。就他们整体的联合拟合而言，跟Chinchilla比的话，论文里说这意味着他们应该用比Chinchilla多得多的文本来训练。说实话，我不太确定这算不算是真的成立，还是说他们的Chinchilla拟合结果跟原始Chinchilla论文比有点奇怪。

我先停一下，看看大家有没有关于MiniCPM的问题。我觉得主要有两点值得记住。第一，用muP是个挺有用的技巧，能帮你稳定学习率随规模变化时的表现。第二点要记住的是WSD学习率，这也就是个很常见的技巧。这种学习率你们都得知道，这是基础内容。

好，不错。那咱们接着看DeepSeek。这是DeepSeek早期的一篇原始论文，那时候他们还没开始聊MoE这些很酷的东西。哪怕看DeepSeek的第一篇论文，也能看出这帮人做事非常认真，就拿DeepSeek LLM来说。我觉得即便到现在，这也是开源世界里scaling分析做得最漂亮的研究之一。我觉得他们做实验的品味特别好。所以哪怕R1这些还没出来，大家就都看出来，这帮人是要成大事的。

好，所以DeepSeek用的scaling策略跟MiniCPM那几个不太一样。他们主要是想优化超参数。他们不搞那个muP，也不搞这种挺有意思的scaling调整。相反，他们打算直接拟合一条scaling laws，用来估算最优的batch size和learning rate。咱们都知道learning rate和batch size其实得跟着规模变，但如果它们的规律是可预测的，就跟scaling laws那样，那咱们心里就有底了。我们其实不用太担心，他们主要是在不同规模下做广泛的网格搜索，好找出最优解。这就是他们正在做的一类事情。他们会便利learning rate、便利batch size，然后看看处理一定数量token时的终端损失是多少。

他们会先固定计算量，然后变动这两个参数，而且他们会针对几个不同的规模都这么做。接着，他们主要会去识别最低损失，也就是图里颜色最浅的那个点。他们会在对应位置标个小星号，然后针对各个规模都这么做。所以如果你在足够多的不同规模上都这么做，你就会得到像这样的图表。

这张图的意思是，好吧，我要在某个范围内变动我的非嵌入训练FLOPs。你能看到这儿这些灰点对吧？当我变动这个参数时，我的最优batch size也会跟着变。记住，最优batch size是从这些大型网格中找出来的，也就是找到那个损失最小的点，对吧？我会得到一条看起来像直线的东西。最优批次大小应该随非嵌入计算量（non-embedding FLOPs）缩放。同样地，对于最优学习率，我会在非嵌入计算量范围内得到一堆灰点。接着我可以用一条线去拟合这些数据，以此估算出最优学习率大概该是什么样。

好，以上就是 \mu P 的推导。刚才我讲了不少细节，所以我想聊聊这背后的核心要点到底是什么。核心要点在于，\mu P 这个论点本身非常有趣。这不仅是因为里面有实际有用的东西，更是因为推导出这个算法的过程本身就很有趣。因为这里用到的数学方法很不一样，它的思路是，好吧，咱们要取一个缩放极限。针对我的网络，我先断言它具备某种不变性，接着做一些额外假设，然后去推导这类超参数需要满足什么约束。这些约束本质上给你的超参数也划定了一些 scaling limits。我觉得这是一个通用的原则，用来推导不同的算法或超参数的 scaling，这大概跟你们在 CS 或 ML 训练中习惯的做法很不一样。

好，以上就是 \mu P 的推导。我想用几个实证例子来收尾 \mu P 这部分。有个独立研究者发了篇挺有意思的论文，基本上是用各种不同的方式对 \mu P 做了压力测试。你可以把 \mu P 看做是一种调整超参数的流程。参数，所以取决于你怎么做，比如 Adam 的学习率就是网络不同组件的函数。所以你会涉及到嵌入参数、注意力参数、输入输出的 MLP 或者 softmax 线性层。这些情况在 \mu P 下会有不同的缩放表现，同时也有一些遵循非 \mu P 规则的缩放方式。有意思的是，那篇论文复现了不同规模下训练的 language model 的不少 \mu P 结果，不出所料，它得出的主要结论和 MiniCPM 的研究一致：只要 \mu P 设置正确，且仅进行缩放，比如在这里，用一种非常受控的方式，你就能得到和基线 \mu P 一样的学习率最优性不变性，或者看看那种追踪注意力投影偏差的 \mu P 变体，这两种情况都都能很好地迁移。

但你可能会问，现实中其实有很多 \mu P 没涵盖的情况。比如技术上讲，SwiGLU 就不在 \mu P 范围内，初始化或 RMSNorm 的变动也不行，要是你大幅改动优化器，那也会破坏规则。所以你可能会问，这些理论不予许的因素里，哪些真正破坏了 \mu P 呢？其实大部分时候，这些都能和 \mu P 兼容，但有些情况不行，比如在 RMSNorm 中学习增益项。事实证明这会让 \mu P 失效。虽然很多时候去掉它们并不会影响效果，所以这倒不算个坏主意，但 \mu P 确实会因此出问题。另外，如果你用一些更冷门的优化器，比如 Lion，它基本上依赖梯度的符号，\mu P 似乎也会失效。符号梯度在理念上和 \mu P 挺像的，所以 \mu P 可能还会在其他一些有趣的地方失效。最后，最让人担心的是，如果你做较大的解耦权重衰减，\mu P 最终会严重失效。所以这可能是它唯一没通过的压力测试。

好了，为了收尾这最后一节，你最终可能会问，\mu P 到底有没有用？如果你真心想让学习率稳定下来，它其实挺管用的。有很多这类实验都显示，当你增加宽度时，最优学习率会随规模发生巨大但可预测的偏移，而用了 \mu P 之后就不会这样。所以，它是工具箱里的众多工具之一，用来控制那些随规模变化而漂移的超参数。我觉得这是个很有意思、有待探索的研究方向，还没到该下定论的程度，也没说这就是唯一正确的做法，不过 \mu P 风格的初始化方案很有前景。另外，光是去拟合 scaling laws 也很有前途。
