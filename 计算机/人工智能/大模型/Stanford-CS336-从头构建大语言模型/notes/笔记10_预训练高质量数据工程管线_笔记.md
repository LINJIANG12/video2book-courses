# 预训练高质量数据工程管线

## 语料生命周期与网络准入边界

### 数据工程生命周期

* **大语言模型训练三阶段管线（Three-stage Training Pipeline）**

    * > **定义**：将大语言模型从零构建至面向用户交互对齐所经历的数据形态分层注入全流程，包含预训练、中训练与后训练三个递进阶段。

    * **预训练阶段（Pre-training）**：面向底层通用世界模型构建，输入万亿至数十万亿 Token 规模的原始海量语料（全球网络抓取、开源代码、学术论文、数字化图书），建立联合概率分布、语法结构与常识表征。

    * **中训练阶段（Mid-training）**：在基础通识之上接入高质量语料进行能力专项退火与激活，输入精选数学推导、长文档与高质量合成数据，核心目标是扩展注意力窗口（如从 4K/8K 延展至 32K/128K）并强化数理与逻辑推理。

    * **后训练阶段（Post-training）**：面向特定人机交互与下游任务对齐，输入多轮对话日志（Transcripts）、指令遵循数据集、思维链（CoT）轨迹与强化学习（RL）环境反馈，消除幻觉与有害输出，确立行为规范与安全边界。

    * **演进趋势**：模型训练范式已从单纯追求原始语料规模的粗放式堆砌，转向依赖更小规模、极致清洗提纯的高质量数据精炼。

* **基座模型与对话模型（Base Model vs. Instruct Model）**

    * > **定义**：基座模型指完成预训练与中训练阶段、具备续写能力的原始权重；对话模型指在基座检查点之上经过指令微调（SFT）和偏好对齐（RLHF/DPO）后的最终交付形态。

    * **工业现状与边界模糊**：现代工业管线常将三个阶段拆解细分为四至五个递进混合阶段；部分前沿商业开源模型（如 Qwen-2.5-72B）仅对外发布最终 Instruct 权重而隐藏中间 Base 检查点。

    * **完全开源基准标杆**：开源项目 OLMo（Open Language Model）将预训练、中训练各阶段数据配比、过滤代码、超参数及全部中间 Checkpoint 全盘公开，为全流程可复现研究提供基准。

### 网络爬取现实与技术壁垒

* **全球公开网络准入漏斗（Web Accessibility Funnel）**

    * > **定义**：描述物理互联网全部数据经由技术渲染、访问控制、行业契约及法律条款层层阻断后，最终收缩为极小比例合规训练语料的漏斗模型。

    ```text
    +-------------------------------------------------------------------------------+
    |                       全球网络可获取数据的层层收缩模型                        |
    +-------------------------------------------------------------------------------+
    |  [ 物理世界互联网全部数据空间 ]                                               |
    |  ├── 动态渲染/交互表单/深网 (Deep Web, 静态 URL 无法触达)                      |
    |  └── [ 静态可寻址网络空间 ]                                                   |
    |      ├── 身份认证/付费墙/围墙花园 (Facebook, X, LinkedIn, NYT, 私有数据库)     |
    |      └── [ 公开可访问服务器 ]                                                 |
    |          ├── 网络安全防御阻断 (Cloudflare, WAF, 人机验证 CAPTCHA, IP 封禁)    |
    |          └── [ 爬虫可连通服务器 ]                                             |
    |              ├── 爬取协议拦截 (robots.txt 封禁名单, Disallow: /)              |
    |              └── [ 协议允许抓取空间 ]                                         |
    |                  ├── 法律条款限制 (服务条款 ToS 禁止 AI 训练, 严格版权保护)   |
    |                  └── [ 最终合法可用预训练语料 (仅占极小比例) ]                |
    +-------------------------------------------------------------------------------+
    ```

    * **动态单页应用与深网（SPA & Deep Web）**：前端依赖 JavaScript 动态渲染、表单交互或无公开静态 URL 的内容（如 Discord 聊天流）无法通过简单图遍历与 `curl` 抓取。

    * **围墙花园（Walled Gardens）**：高价值平台（如 Facebook、X、LinkedIn、付费新闻）部署身份认证与付费墙；平台内部数据对母公司闭环专有，对外部第三方爬虫彻底封闭。

    * **安全防御机制**：内容分发网络（CDN）部署 Web 应用防火墙（WAF）、速率限制、IP 频控及动态人机验证（CAPTCHA），直接拦截自动化无头浏览器。

* **网络协议自律与服务条款红线（Robots Exclusion & Terms of Service）**

    * > **定义**：规范网络爬虫行为准入范围的行业技术协议与网站服务法定访问契约。

    * **协议性质与主流拦截（robots.txt）**：属于行业自律契约而非强制法；主流网站已针对 AI 专用爬虫（如 `OAI-SearchBot`、`ChatGPT-User`、`ClaudeBot`、`PerplexityBot`、`CohereBot`）配置显式 `Disallow` 规则。

    * **服务条款合规约束（Terms of Service, ToS）**：用户访问网站与服务器交互形成的法定契约；绝大多数主流站点在 ToS 中显式加入“严禁使用自动化工具抓取本站内容用于机器学习或大模型训练”条款，商业化未经授权抓取构成违约风险。

    * **准入限制剧烈恶化趋势**：《危机中的同意》（*Consent in Crisis*）量化研究证实，以 2023 年生成式 AI 爆发为拐点，全球主流数据源中实施完全爬取封禁（`robots.txt` 封锁）的站点比例激增近 40 倍，且绝大多数站点在 ToS 中补充了 AI 训练禁令。

* **爬取过载冲击与影子图书馆（Server Overload & Shadow Libraries）**

    * > **定义**：大规模高并发抓取对物理基础设施造成的服务瘫痪风险，以及离线托管受版权保护数字资源的未授权盗版网络。

    * **基础设施冲击**：高频并发抓取导致目标服务器带宽、CPU 与连接池枯竭，引发正常服务雪崩并大幅推高目标站点的云服务账单（如 24 小时内发起超百万次请求瘫痪开源文档站点）。

    * **影子图书馆争议（LibGen, Anna's Archive）**：突破出版付费墙、通过离岸避风港服务器非法汇集数千万册版权书籍与学术专著；司法管辖区定性为大规模数字盗版窝点，曾作为 Books3 语料混入早期开源数据集，埋下重大版权诉讼隐患。

## 知识产权法理与模型训练合规

### 现代版权法基础原则

* **思想与表达二分法（Idea-Expression Dichotomy）**

    * > **定义**：版权法核心法理准则，规定法律仅保护固定在有形媒介中的独创性表达形式，绝对不保护表达背后的抽象思想、客观事实、运作流程或数学算法本身。

    * **事实与算法排除**：快速排序算法的数学原理属于公有思想不可被独占垄断，但某位程序员针对该算法编写的具体代码实现受版权排他保护；电话黄页等纯客观事实的简单汇编不具备独创性，不受版权法保护。

    * **确权门槛与存续期限**：现代版权法（如美国 1976 年版权法）确立作品固定在有形媒介（如博客随笔写入存储）即自动获得版权保护，无需官方登记；保护期长达作者终身加 70 年（或发表后 75 年以上），期满后方坠入公有领域（Public Domain）。

    * > **易错点**：⚠️ 版权侵权不限于文本字面的逐字抄袭（Verbatim Memorization）。虚构作品中的独创世界观设定、丰满的人物角色形象（如商业作品中直接盗用虚构角色），即便生成文本与训练样本无重合 n-gram，同样构成衍生侵权。

### 合法使用与合理使用原则

* **模型训练合法利用路径（Licensing vs. Fair Use）**

    * > **定义**：大模型使用受版权保护作品的两大法定途径：获得合法合同授权，或依据成文法抗辩合理使用豁免。

    * **知识共享协议（Creative Commons, CC）**：自愿开源授权体系，允许创作者在保留署名（如 CC BY-SA）的前提下向公众免费分发，维基百科与开放教育资源均基于此。

    * **商业采购许可**：科技公司直接与数据平台（如 Reddit、Stack Overflow、新闻出版集团）签署商业采购协议，锁定合法预训练权。

* **合理使用四要素判定框架（Fair Use Doctrine, 4-Factor Test）**

    * > **定义**：美国《版权法》第 107 条设立的司法裁决标准，通过综合权衡四个法定维度判断未经授权使用作品是否免于侵权责任。

    | 法定要素维度 | 偏向判定为侵权（Infringing） | 偏向判定为合理使用（Fair Use） |
    | :--- | :--- | :--- |
    | **1. 使用目的与性质** | 纯商业盈利目的、原样复读与被动分发 | 非营利性学术科研、高度转换性使用（Transformative Use） |
    | **2. 原作品的性质** | 极具原创性与创造力的虚构艺术作品（小说、诗歌） | 客观记录、事实性技术文献与历史报道 |
    | **3. 使用分量与实质性** | 完整复制全文、抽取作品独创精髓（Heart of the Work） | 仅截取非核心片段、极小比例引用 |
    | **4. 对原作品市场的影响** | 构成直接市场替代品（Market Substitute），削弱原作者经济收益 | 开辟不重叠的全新衍生市场、不构成经济替代 |

    * **转换性使用核心判例（Authors Guild v. Google）**：法院判定谷歌图书扫描并建立搜索索引属于转换性合理使用，因其提供片段视图（Snippet View）创造了全新检索工具，未对图书原生态销售市场构成替代。

    * **司法裁决新分水岭（Anthropic 著作权侵权案）**：司法界初步确认“将受保护作品用于算法特征提取与模型数学训练的过程本身构成转换性合理使用”；但明确判定**合理使用不能洗白前端非法数据获取手段**。Anthropic 因直接从影子图书馆批量下载盗版电子书用于训练，最终达成 15 亿美元和解（折合每本受害图书约 3000 美元）。

    * **输出记忆化动摇抗辩（《纽约时报》诉 OpenAI 案）**：原告利用特定 Prompt 诱导模型近乎 100% 逐字复现独家深度调查报道，直接破坏了第一要素（原样复制）与第四要素（构成直接市场替代），危及合理使用抗辩。

### 纯合规预训练探索与法律陷阱

* **纯合规语料库（Common Corpus / Common Pile）**

    * > **定义**：对任何潜在法律争议零容忍、完全建立在公有领域和纯宽松授权数据之上的纯净预训练数据集（规模约 8 TB）。

    * **数据构成**：收录 The Stack v2 宽松协议代码、政府公开发布的非保密文书与公报纪要、CC 授权预印本与讲义、古登堡计划公有领域文学。

    * **性能天花板代差**：仅使用 8 TB 绝对合规语料训练的模型性能达到基本可用（胜过初代 LLaMA 或早期旧模型），但在通用智能基准上与在数十万亿全网数据中淘洗提炼出的顶级商业开源模型存在显著代差。

* **开源数据三大法律陷阱（Legal Pitfalls of Open Data）**

    * > **定义**：开源社区中表面具备宽松协议、深层潜藏版权侵权风险的数据污染现象。

    * **许可清洗（License Laundering）**：普通网民将受版权保护的作品抹去原作者信息，恶意打上 CC-BY 或 MIT 标签并上传至公开仓库，该标签在司法层面不具备合法豁免效力。

    * **集合许可与单体许可脱节（Collection vs. Single Document Licensing）**：数据集分发者为其整理的打包数据集声明了宽松开源许可证（如 MIT/Apache-2.0），但这仅代表其对整理脚本的授权，集合内部包含的成千上万篇独立作品未经原始版权方授权。

    * **合成数据洗白悖论（Synthetic Data Laundering）**：使用具备商用开源权重的模型合成数据时，若上游生成模型本身基于未授权全网语料与盗版图书预训练，其合成输出在法理上仍属于未经授权语料的层层包装洗白，且受商业 ToS 竞争性限制约束。

## 核心基石数据源与正文提取

### 核心垂直语料库

* **全球网络快照归档（Common Crawl, CC）**

    * > **定义**：自 2007 年稳定运营的非营利性公共网络镜像基础设施，每月定期发起全球网络巡回抓取并公开转储。

    * **体量与周期**：每月抓取 20 亿至 50 亿个网页，历年累计抓取网页超 3000 亿个；单次未压缩数据转储（Dump）纯文本规模约 370 TB（商业搜索引擎 Google 内部索引在 100 PB 以上）。

* **多语言权威百科（Wikipedia）**

    * > **定义**：基于严格社群协作与同行评审机制建立的多语言知识库，全球大模型通识常识的核心基石。

    * **准入机制与数据规范**：包含超 6700 万篇词条；执行“禁止原创研究（No Original Research）”与“第三方文献权威引注”铁律；官方提供定期打包的 XML/Tar 导出快照（Tarball Dumps），严禁针对在线 Web 页面暴力并发抓取。

    * **快照时间差投毒漏洞（Snapshot Poisoning）**：维基百科官方导出全量快照日程固定；攻击者可在导出流水线触发前数分钟向特定词条注入恶意后门或偏见脏数据，快照打包脚本会将恶意篡改固化进归档文件；即便社区机器人在数十分钟后撤销篡改，全球下载当期快照训练模型的机构已受到永久毒化。

* **代码资产与全生命周期元数据（GitHub Ecosystem）**

    * > **定义**：包含源代码、工程提交历史与开发者协同事件的综合软件工程语料库，大模型通用逻辑推理能力的核心支柱。

    * **代码仓库文件镜像（Repository Blobs）**：托管超 4.2 亿个仓库（公开仓库超 2800 万个），包含海量因 Fork 和拷贝导致的近重复代码；通过扫描工具（ScanCode）严格剥离 GPL 等强传染性开源协议，仅保留 MIT、Apache-2.0、BSD 等宽松许可文件。

    * **协作事件流元数据（GH Archive & Software Heritage）**：GH Archive 每小时发布快照，冻结 Issue 讨论、PR 审查流与开发者行级批注；Software Heritage 建立全球开源软件通用的扁平化哈希内容寻址库。

* **学术论文预印本库（arXiv）**

    * > **定义**：涵盖物理、数学、计算机与定量生物学等前沿领域的开放科学预印本仓储（收录超 300 万篇高水平论文）。

    * **源码红利与解析优势**：支持官方批量通道打包下载原始 LaTeX 源码；相比于多栏排版、公式易发生错位 OCR 崩坏的扁平 PDF，LaTeX 源码完整保留了数学证明环境（`\begin{proof}`）、交叉引用与层级公式推导。

### 原始多模态载体转换

* **网络归档格式（WARC vs. WET）**

    * > **定义**：Common Crawl 官方发布的两类标准网络归档文件格式。

    * **WARC（Web ARChive）**：记录爬虫与服务器交互的每一个原始字节，包含完整 HTTP 请求头、响应状态码、元数据与未解析原生 HTML 代码，体量庞大但信息无损。

    * **WET（WARC Encapsulated Text）**：Common Crawl 官方预先用内置算法剥离 HTML 标签后导出的纯文本提取文件。

    * > **易错点**：⚠️ 绝不要直接使用 Common Crawl 官方发布的 WET 文件作为预训练语料。官方 WET 提取管线过于粗暴，丢失了段落层级、列表结构与表格排版语义，并残留大量页眉页脚与广告垃圾；DataComp-LM 消融实验证实，从原始 WARC 自行解析出的语料在下游评测中表现全面碾压官方 WET。

* **HTML 正文解析与结构线性化（DOM Linearization & Extractors）**

    * > **定义**：将树状层级 DOM 结构投影为模型可接受的一维连续 Token 序列，并剔除页眉、页脚、侧边栏及广告等噪声的正文抽取工程。

    * **有损投影本质**：内嵌多媒体图片通常丢弃或降级为 `alt` 标签；合并单元格（`rowspan`/`colspan`）与多层嵌套复杂表格无法无损展平，线性化转换必须在破坏排版结构与引入冗余标记之间妥协。

    | 抽取方案 | 核心技术路径 | 吞吐速度与资源开销 | 语义抽取质量 | 工业落地局限 |
    | :--- | :--- | :--- | :--- | :--- |
    | **Resiliparse** | 基于 C++ 底层的高性能 DOM 树解析与文本块密度判定 | 极高（单核数千网页/秒，CPU 占用极低） | 优秀；对主流博客、新闻正文切分干净 | 面对极端非规范前端排版时仍有误删长段落现象 |
    | **Trafilatura** | Python 规则引擎结合正文与标签密度启发式算法 | 中等（单核数十至数百网页/秒） | 较好；兼顾学术与通用长文本提取 | 全网十万亿 Token 规模处理时吞吐瓶颈明显 |
    | **轻量视觉/模型驱动** | 基于版面分析模型或小分类器进行视觉可见边界判定 | 较低（需专用 GPU/TPU 推理算力支持） | 极高；精准剔除不可见广告与浮层噪声 | 计算成本极昂贵，难以对全网原始语料全量铺开 |

* **PDF 文档解析与视觉多模态处理（PDF Extraction & FinePDFs）**

    * > **定义**：针对公网分散的 PDF 电子文档执行格式识别、文本流提取与 OCR 视觉重建的清洗管线。

    * **原生 PDF 与扫描件双轨挑战**：纯数字原生 PDF 缺乏原生语义标签，多栏排版论文极易出现跨栏串读；扫描件与影印件本质为位图图像，必须调用视觉语言模型（VLM）进行高算力消耗的光学字符识别（OCR）。

    * **高信息密度回报**：PDF 制作与公开发布具备较高的人工整理排版成本（学术论文、企业财报、行业白皮书、法律卷宗），其平均信息密度与逻辑严整度显著优于普通 HTML 页面，高昂的解析算力投入具备极高转化收益。

### 规则与启发式基石阶段

* **早期长文档探索集（BERT BookCorpus & GPT-2 WebText）**

    * > **定义**：确立自回归与双向语言模型长程上下文连续建模范式的早期探索数据集。

    * **BookCorpus（2018）**：从独立自出版平台 Smashwords 抓取 1.1 万本免费小说，与英文维基百科拼装训练 BERT，首次确立全篇连续文档输入；后因明确违反平台 ToS 被迫下架。

    * **WebText（2019）**：OpenAI 借助 Reddit 社区人工审美注意力机制，仅抓取获赞数 $\text{Karma} \ge 3$ 的帖子所包含的出站超链接，提炼出包含 800 万个网页、总计 40 GB 纯文本的高信噪比语料，验证了人工偏好外部过滤的有效性。

* **C4 启发式规则体系（Colossal Clean Crawled Corpus）**

    * > **定义**：Google 为训练 T5 模型基于 Common Crawl 12 个历史转储构建的 1560 亿 Token（约 800 GB）纯净语料，启发式规则清洗的极限代表。

    * **七大硬性清洗规则**：
        1. 丢弃未以合法终结标点符号（句号、感叹号、问号、反引号）结尾的行；
        2. 丢弃全篇句子数量少于 3 句的页面；
        3. 丢弃单行词数少于 5 个单词的短行；
        4. 命中详尽脏话与恶俗词汇黑名单的页面整页剔除；
        5. 剔除包含“Terms of Service”、“Cookie Notice”等通用模板占位符的行；
        6. 使用 `langdetect` 强制保留英文置信度高于 0.99 的文档；
        7. **剔除任何出现花括号 `{` 的行**。

    * > **易错点**：⚠️ C4 为了清洗残留的 JavaScript 脚本代码而粗暴剔除所有包含花括号 `{` 的文本行，导致 C4 语料库将互联网上的真实编程代码完全误杀剔除，使早期基于 C4 训练的模型完全丧失代码编程能力。

* **人工规则透明体系（DeepMind Gopher MassiveWeb）**

    * > **定义**：DeepMind 耗费算力构建的 10.5 TB 预训练语料，坚持全流程纯手工启发式规则，拒绝模型黑盒过滤。

    * **核心理念与设计**：认为基于机器学习的小分类器会向语料强加不可控的归纳偏置、抹杀小众专业知识；通过对符号与单词比例、无意义停用词频次设定严苛阈值，并对连续重复字符与 n-gram 施加指数级惩罚，确立工业级规则清洗工艺标杆。

### 多元混合与模型过滤演进

* **GPT-3 多源加权语料集（GPT-3 Dataset）**

    * > **定义**：OpenAI 构建的 500 GB（4000 亿 Token，最终训练截断为 3000 亿 Token）预训练语料，确立多数据源加权采样与分类器判别机制。

    | 子数据集名称 | 原始 Token 规模 | 训练时采样权重 | 训练等效 Epoch 数 |
    | :--- | :--- | :--- | :--- |
    | **Filtered Common Crawl** | 4100 亿 Token | 60% | 0.44 |
    | **WebText2** | 190 亿 Token | 22% | 3.47 |
    | **Books1** | 120 亿 Token | 8% | 2.00 |
    | **Books2** | 550 亿 Token | 8% | 0.44 |
    | **Wikipedia** | 30 亿 Token | 3% | 3.00 |

    * **分类器与去重机制**：以 WebText 为正样本、原始 Common Crawl 为负样本训练二元逻辑回归分类器；配合 MinHash LSH 算法执行跨数据源激进模糊去重。

* **跨领域异构语料集（EleutherAI The Pile）**

    * > **定义**：开源研究组织构建的包含 22 个专门领域子集、解压体量达 825 GB 的多元开源综合语料库。

    * **多元领域构成**：涵盖 PubMed 生物医学文献、arXiv 论文、FreeLaw 诉讼判例、USPTO 专利、Stack Exchange、PhilPapers 哲学论文、Hacker News 以及安然公司（Enron）破产解密内部邮件。

    * **Books3 侵权隐患**：除古登堡公有图书外，打包收录了源自影子图书馆 Bibliotik 的 20 万本受版权保护当代图书（Books3），后续引发全行业版权诉讼，被开源复刻版（如 RedPajama-V2）紧急剔除。

* **开源配方与纯网页主义（LLaMA-1, RefinedWeb & FineWeb）**

    * > **定义**：Meta 开源 1.4 万亿 Token 详尽清洗配方，以及后续验证纯网络语料亦可支撑顶级模型的代表性探索。

    * **LLaMA-1 创新分类策略**：Common Crawl 占比 67%；在训练质量分类器时放弃传统的“拟合维基百科词条文风”，转为**判别网页是否被维基百科作为外部参考文献所引用**，兼顾事实权威度与自然叙事文风。

    * **RefinedWeb（Falcon, 5T Token）**：主张纯网页至上（Web-only），使用 Trafilatura 精准抽取正文并结合严密的 MinHash LSH 模糊去重，证明无需人工构造的专业数据集亦可超越混合语料基线。

    * **FineWeb（Hugging Face, 15T Token）**：重跑 Common Crawl 自 2013 至 2024 年共 96 个历史转储，采用透明启发式规则与 PII 敏感信息脱敏，提炼出 15 万亿 Token 超大规模纯网页黄金基准。

* **模型驱动过滤黄金标准（DataComp-LM, DCLM）**

    * > **定义**：由多机构联合推出的标准化预训练数据评估基准，确立轻量判别模型过滤登顶工业黄金标准。

    * **极致保留率**：从 240 万亿原始 Token 的 DCLM-Pool 中，经规则预筛、MinHash 去重，再由 fastText 分类器评分截断，最终**仅保留得分最高的 1.4% 顶级语料（3.8 万亿 Token，DCLM-Baseline）**，淘汰 98.6% 劣质语料。

    * **正负样本精巧构建**：正样本采用 GPT-4 合成的高阶指令集 OpenHermes-2.5 与 Reddit 深度通俗科普问答 ELI5；负样本从 RefinedWeb 通用网页中随机采样。

* **教育价值打分与合成重写（NVIDIA Nemotron-4）**

    * > **定义**：针对 DCLM 保留率过低（3.8T 难以支撑 15T-36T 预算）导致的库容枯竭痛点，引入双分类器级联与大规模合成数据重写的预训练语料方案（交付 6 万亿 Token）。

    * **教育价值分类器蒸馏**：利用前沿 LLM 对抓取网页的“教育价值（深度概念解析、逻辑严整度）”打分，将打分标签蒸馏至 fastText 极速分类器全量推断。

    * **低质重写与多任务合成**：包含真实事实但文风粗糙破碎的低质网页，调用大模型重新表述为客观规范的“维基百科体”；对顶级高质文本调用大模型自动合成成套深度问答（QA 对）与提取推理链。

## 语料质量与毒性分类过滤

### 分类过滤数学框架与模型选型

* **目标驱动分类过滤通用数学框架（Target-driven Quality Filtering Framework）**

    * > **定义**：给定小规模黄金目标集 $T$（如精选维基百科、教科书）与海量原始未过滤候选集 $R$（如 Common Crawl），通过估计生成概率或判别概率，从 $R$ 中筛选出与 $T$ 分布最相似的高质量子集 $R^*$ 的过滤机制。

    ```text
    +-------------------------------------------------------------------------------+
    |                          通用模型化数据质量过滤框架                           |
    +-------------------------------------------------------------------------------+
    |  原始未过滤语料池 R (10 万亿 Token) ─────────┐                                |
    |                                              ├──> [ 训练轻量判别/生成分类器 ] |
    |  黄金目标数据集 T (小规模精选维基/教科书) ───┘                                |
    |                                              │                                |
    |                                              ▼                                |
    |                                 全量单遍扫描 R 计算评分                       |
    |                                              │                                |
    |                                              ▼                                |
    |                                 超过阈值 tau 保留，其余丢弃                   |
    |                                              │                                |
    |                                              ▼                                |
    |                                 最终高质量训练子集 (占 R 的 1%~5%)            |
    +-------------------------------------------------------------------------------+
    ```

    * **工程约束**：分类算法必须具备强泛化能力（超越目标集的具体词汇表层），且推断速度必须满足在 CPU 集群上对数十万亿 Token 级别原始文档进行单遍极速全量扫描。

* **生成式困惑度模型过滤（Perplexity Filtering, PPL）**

    * > **定义**：直接在目标集 $T$ 上估计语言模型概率分布，用其为候选文档计算交叉熵困惑度，保留困惑度低于设定阈值的文本（以 KenLM 5-gram 为核心实现）。

    * **数学形式化公式**：
        $$\text{PPL}(d) = \exp \left( -\frac{1}{N} \sum_{i=1}^N \log P(w_i \mid w_{i-n+1}, \dots, w_{i-1}) \right)$$

    * **判别机理**：困惑度越低，说明候选文档的字词搭配规律与高质量目标集越吻合；困惑度过高则表明文本充斥错别字、乱码、机翻垃圾或无序词串，予以剔除。

* **判别式轻量线性分类器（fastText Classifier）**

    * > **定义**：将目标集 $T$ 作为正样本、从原始候选集 $R \setminus T$ 中随机无偏采样等量文档作为负样本，训练基于词袋与字符级 n-gram 的高吞吐快速线性分类模型。

    * **运行机制**：推断输出文档属于高质量类别的连续预测概率分数 $S(d) \in [0, 1]$；工程人员依据算力预算设定切分截断阈值 $\tau$ 或实施拒绝采样。

* **语言识别与毒性安全过滤（LID & Toxicity Filtering）**

    * > **定义**：在质量过滤前置管线中执行的多语种归类与恶意有害内容剔除机制。

    * **语言识别（fastText LID）**：覆盖 176 种语言，在维基百科与多语种平行对齐语料上训练；对拼写特征明显的单语言识别精度极高，在语码转换（Code-switching）和方言口语场景存在边界模糊，但已属于高度成熟的非瓶颈模块。

    * **毒性过滤（Toxicity Filtering）**：引入 Jigsaw Toxic Comments 等标注集训练轻量二分类器，识别仇恨言论、侮辱性词汇与暴力内容，设定硬性安全阈值在预训练前置环节直接拦截。

### 任务专项过滤与计算预算权衡

* **领域级联过滤范式（OpenWebMath Pipeline）**

    * > **定义**：针对特定专业推理能力构建的高浓度专项语料提炼流水线（提炼出 150 亿 Token 纯净数学语料）。

    * **三阶段级联架构**：
        1. **规则初筛**：正则表达式极速扫描，检查并保留包含 LaTeX 数学语法标记（如 `\frac`、`\sum`、`\begin{equation}`）的页面；
        2. **生成式困惑度过滤**：在 Proof-Pile 精选数学证明集上微调训练 KenLM 五元语法模型，剔除困惑度超出阈值的杂乱页面；
        3. **判别式风格分类**：训练专用 fastText 分类器，精准鉴别客观规范的学术论文与逻辑推导行文语体。

    * **核心结论**：在 15B 高浓度数学语料上训练出的模型，其数学推理表现远超在未经清洗、体积大整整 20 倍（300B Token）的通用原始语料上训练的模型；验证了“质量是对目标任务能力的精准对齐”。

* **教科书级价值蒸馏（Textbooks Are All You Need, Phi-1）**

    * > **定义**：微软提出的一种利用超强教师模型小规模打分蒸馏至轻量分类器、全网筛选高教育价值代码的分层过滤策略。

    * **分层实施流水线**：
        1. 设计“教育价值（Educational Value）”提示词，要求代码逻辑清晰、注释详尽、自成体系；
        2. 调用昂贵的 GPT-4 对 10 万条 Python 代码样本进行细粒度质量打分；
        3. 以 GPT-4 的打分为黄金伪标签，训练随机森林（Random Forest）或 fastText 轻量分类模型；
        4. 将轻量模型部署至全量公开代码库执行低成本单遍推断过滤，仅以较小的训练步数和模型参数规模达成代码基准评测极佳水准。

* **训练计算预算与质量阈值权衡（Compute Budget vs. Quality Threshold Trade-off）**

    * > **定义**：最优数据过滤阈值与预定训练总 Token 规模及算力预算强绑定的动态权衡规律（由 Michael Ryan 受控消融实验揭示）。

    ```text
    训练损失
    (Loss) ^
           |  \
           |   \  (短周期: DCLM 精品数据极速下降)
           |    \
           |     *---* Resiliparse 基础数据 (第一轮单遍遍历，平稳下行)
           |      \   \
           |       \   \
           | DCLM   *---*---* (重复多轮 Epoch: 出现过拟合，Loss 趋平)
           | 严选集  \       \
           |          *       *---*---* (Resiliparse 持续消耗未见新 Token，
           |                             最终长线泛化损失反超 DCLM)
           +------------------------------------------------------------>
                                                        总训练步数 (Steps)
    ```

    * **短周期训练（短跑模式）**：当 GPU 计算预算有限、只能训练较少 Token 时，必须将质量阈值设至极高，确保模型在有限步数内只接触最纯净的黄金语料，追求最高单位步数收敛速率。

    * **长周期海量规模（马拉松模式）**：当拥有数万亿至数十万亿 Token 充足计算预算时，全网极高质数据总量有限；若阈值卡得过紧，精品池被迅速耗尽，模型被迫陷入多轮次（Multi-epoch）重复训练，遭遇边际收益锐减与记忆化过拟合；此时必须放宽阈值，容纳更多略显平庸但具备多样性且未曾见过的独占 Token，其最终泛化表现全面超越多轮重训的高质量集。

## 海量语料去重与局部敏感哈希

### 语料重复类型与去重驱动

* **文本重复形态与审计案例（Exact vs. Near Duplication）**

    * > **定义**：互联网语料库中普遍存在的完全一致或骨架高度雷同的多源文本冗余。

    * **完全重复（Exact Duplication）**：文本字符逐字完全一致；典型来源包括镜像站点（Mirror Sites）、爬虫死循环或重定向重复抓取、GitHub 仓库 Fork（99% 以上代码文件未作修改）。

    * **近似重复（Near Duplication）**：文本主干高度雷同，仅局部实体或格式存在微小差异；典型来源包括全网散布的开源许可证协议文本（MIT/Apache）、网站统一隐私免责声明、模板化广告（仅替换地名“加拿大”为“美国”）、文本排版仅多出一个逗号。

    * **C4 数据集极端重复审计**：Google C4 数据集经事后审计发现，某款防毒面具的产品营销文案在整个语料库中一字不差地重复出现了整整 **61,000 次**。

    * **去重核心驱动力**：
        1. **杜绝算力虚耗**：在重复内容上反复计算前向与反向传播，不提供任何信息量增量；
        2. **抑制记忆化与隐私版权泄露**：高频重复使得模型将特定文本序列与标点死记硬背在权重中，极易在推理时被诱导复现受版权保护的原文或个人敏感数据（PII）；
        3. **基准去污染（Decontamination）**：利用去重相似度比对，严格剔除预训练语料库中渗漏的下游评估测试题（MMLU、GSM8K、HumanEval）。

    * > **易错点**：⚠️ 去重粒度直接决定长文本语义完整性。T5 团队在清洗 C4 时采用“连续三句跨度（3-sentence span）”精确去重，发现全局重复即从原文生硬剔除，导致大量文档正文内部产生突兀的语义断层，严重破坏语言模型的长程逻辑连贯性建模；现代工业界主流体系全面转向文档级（Document-level）的近似去重与整篇剔除。

### 集合相似度与最小哈希

* **杰卡德相似度（Jaccard Similarity）**

    * > **定义**：将文档切分为词项集合或连续 $k$-shingle 字符块集合，通过交集与并集基数比值度量两篇文档近似程度的数学指标。

    * **数学定义公式**：
        $$J(A, B) = \frac{|A \cap B|}{|A \cup B|}$$
        取值范围为 $[0, 1]$；若 $A = \{1, 2, 3, 4\}$ 且 $B = \{1, 2, 3, 5\}$，则 $J(A, B) = \frac{3}{5} = 0.6$。

* **最小哈希算法（MinHash）**

    * > **定义**：一种在线性时间内无偏估计两集合 Jaccard 相似度的随机哈希降维算法，使两集合在同一随机哈希函数下的碰撞概率严格等于其 Jaccard 相似度。

    * **数学定理与碰撞证明**：
        $$\mathbb{P}[h_{\min}(A) = h_{\min}(B)] = J(A, B)$$
        将文档表示为全域特征布尔矩阵的一列，一个哈希函数等价于对全域元素行进行一次完全随机的全局置换 $\pi$。扫描各行时，双方取值均为 0 的行对相似度无贡献直接忽略；首次遇到“集合 $A$ 或集合 $B$ 至少有一方为 1”的行，必然落在并集 $A \cup B$ 之中。在该首行中两集合哈希值相等的条件是该元素同时属于集合 $A$ 与 $B$（即落在交集 $A \cap B$）。由于置换均匀随机，任一属于并集的元素率先出现的概率均等，碰撞概率精确等于 $\frac{|A \cap B|}{|A \cup B|}$。

    * **签名向量构建**：预先选取 $K$ 个相互独立的随机哈希函数（如 $K = 100$），为每篇文档生成长度为 $K$ 的整数签名向量；比对签名相等的维度比例，即可在毫秒级单遍估计任意文档对的 Jaccard 相似度，摆脱 $O(N^2)$ 全局字符比对。

### 局部敏感哈希与分带相变机制

* **局部敏感哈希分带技术（LSH Banding Technique）**

    * > **定义**：将 MinHash 签名向量均匀切分为多个频带（Bands），结合带内严格与逻辑（AND）和带间宽容或逻辑（OR），将平缓的线性碰撞概率锐化为相变 S 型曲线的高维索引技术。

    ```text
    文档 MinHash 签名向量 (共 n = b * r 个哈希值)
    [ h_1, h_2, ..., h_r ]  --->  Band 1  ---> [ Hash Bucket 桶 1 ] (带内需全等: AND)
    [ h_{r+1}, ..., h_{2r} ] --->  Band 2  ---> [ Hash Bucket 桶 2 ] (带内需全等: AND)
      ...                           ...
    [ h_{(b-1)r+1}, ..., h_n ] ->  Band b  ---> [ Hash Bucket 桶 b ] (带内需全等: AND)
                                    │
                                    └──> 只要任意一个 Band 命中同桶即为候选对 (带间: OR)
    ```

    * **分带碰撞概率公式推导**：
        设两文档实际 Jaccard 相似度为 $s$，签名总维数 $n = b \times r$（切分为 $b$ 个带，每个带包含 $r$ 个哈希函数）：
        1. 单个带内所有 $r$ 个哈希值完全匹配的概率为 $s^r$；
        2. 单个带发生失配的概率为 $1 - s^r$；
        3. 全部 $b$ 个带均未匹配的概率为 $(1 - s^r)^b$；
        4. 至少在一个带发生碰撞并成为候选对的总概率：
           $$P_{\text{candidate}} = 1 - (1 - s^r)^b$$

    * **标准数值演算步骤**：
        假定相似度 $s = 0.8$，系统配置 $b = 5$ 个带，每带 $r = 10$ 个哈希函数（总哈希数 $n = 50$）：
        - 单带匹配概率：$0.8^{10} \approx 0.107374$；
        - 单带失配概率：$1 - 0.107374 = 0.892626$；
        - 全带全部失配概率：$(0.892626)^5 \approx 0.56581$；
        - 最终命中候选对的概率：$P = 1 - 0.56581 = 0.43419 \quad (\approx 43.4\%)$。

* **相变 S 曲线与临界拐点（Phase Transition S-curve & Critical Threshold）**

    * > **定义**：分带概率函数呈现出的类阶跃激活曲线，在临界相似度阈值两侧产生强烈的概率相变，实现高相似度极速收敛捕获、低相似度断崖过滤。

    ```text
    命中概率 P
      1.0 ^                                       *---*---*
          |                                     *
          |                                   /
          |                                 /
          |                               /
      0.5 |                             *  <-- 跃迁中心点 P ≈ 0.632
          |                            /
          |                           /
          |                         /
      0.0 *---*---*----------------*
          +-------------------------------------------------->
          0.0                    阈值 s*                  1.0  相似度 s
    ```

    * **相变拐点解析公式**：
        相变曲线拐点 $s^*$ 出现在单带失配概率等于 $1/b$ 的临界位置，数学近似为：
        $$s^* \approx \left(\frac{1}{b}\right)^{1/r}$$

    * **拐点特征常数**：在临界相似度 $s^*$ 处，命中概率渐近逼近固定数学常数：
        $$P(s^*) = 1 - \left(1 - \frac{1}{b}\right)^b \approx 1 - \frac{1}{e} \approx 0.632$$

    * **参数调节物理规律**：
        - 增大行数 $r$：带内匹配条件更严苛，$s^r$ 急剧衰减，曲线整体向右偏移且坡度更陡，极致压制低相似度假阳性；
        - 增大带数 $b$：提供更多匹配通道，曲线整体向左偏移，降低准入门槛，大幅提升召回率。

## 多源数据混合与轮次控制

### 数据配比瓶颈与轮次过拟合

* **多源静态混合启发式（Static Mixing Heuristics）**

    * > **定义**：面对通用网络、代码、论文、百科等多源语料池，在批次生成时分配采样权重的传统工程策略。

    * **经验直觉微调（Vibes-based Tuning）**：完全依据研究人员对评测表现的主观直觉动态增减某个源的采样比例，缺乏数学可解释性与鲁棒性。

    * **均匀采样与按体积比例采样的双重缺陷**：均匀采样无视各源质量差距，容易引发小源过拟合；按 Token 体积比例采样（Proportional Mixing）则导致体量庞大（如 10T）但信噪比偏低的网络爬虫源瞬间吞没仅有百亿 Token 的高价值教科书与数学源，严重稀释模型的专业逻辑能力。

    * **跨领域不可通约性**：高质量 Python 算法代码与高水平哲学论文承载不同认知维度的先验知识，无法在单一标量标尺上比较绝对质量，必须维系知识广度的多样性配比。

* **多轮训练过拟合灾难（Multi-epoch Overfitting Trap）**

    * > **定义**：静态混合比例忽略了数据源物理库容限制，导致小型高价值子集在全周期训练中被动经历过多轮次而引发的模型性能坍塌。

    * **典型数值推演推导**：
        - 低质量通用网络源库容：$10\text{T}$（10 万亿）Token；
        - 高价值精选教科书源库容：$10\text{B}$（100 亿）Token；
        - 预训练总吞吐预算：$1\text{T}$（1 万亿）Token；
        - 设定 $1:1$ 静态平均配比（两源各承担 $500\text{B}$ Token 吞吐）：
          $$\text{Epoch}_{\text{low}} = \frac{500\text{B}}{10\text{T}} = 0.05 \quad (\text{低质源仅被消耗了 } 5\% \text{ 的数据})$$
          $$\text{Epoch}_{\text{high}} = \frac{500\text{B}}{10\text{B}} = 50 \quad (\text{高质源全量数据被模型反复死记硬背了整整 } 50 \text{ 个轮次！})$$

    * **灾难性后果**：在同一个高价值小语料上重复超过几个轮次会导致严重的表征僵化与过拟合，验证集损失剧烈震荡发散，预训练彻底崩盘。

    * **批次生成规范**：在工程落地中，多源混合不是在单个 Token 粒度频繁交错拼接，而是以完整长序列（Sequence-level）为单位从采样源抽取并装入 Batch，保证语流连贯并稳定梯度方差。

* **轮次上限约束采样（UniMax Sampling）**

    * > **定义**：在多语言或多源异构模型训练中，为避免低资源语种与小样本高质源过度复用而设立的最大轮次硬上限约束机制。

    * **数学约束方程**：
        $$p_i \cdot N_{\text{train}} \le E_{\max} \cdot |D_i|$$
        其中 $p_i$ 为第 $i$ 个数据源的采样概率，$N_{\text{train}}$ 为总训练 Token 预算，$E_{\max}$ 为法定最大允许轮次上限（如严格限制 $\le 20$ Epoch），$|D_i|$ 为该源独占 Token 库容。

    * **动态重分配流**：当某小型高价值数据源在训练中期提前耗尽 $E_{\max}$ 允许轮次后，管线自动切断对该源的采样，将其权重归零，释放出的采样配额动态重平衡至尚未达到轮次上限的语料池。

### 回归优化配比与跨规模迁移

* **基于回归的数据混合优化（Regression-based Data Mixing, RegMix / DoReMi）**

    * > **定义**：通过在低成本小型代理模型上大范围采样混合权重并测量验证损失，拟合出响应曲面并求解理论最优解，再直接外推至大模型全量预训练的配比优化方法。

    ```text
    +-------------------------------------------------------------------------------+
    | Step 1: 在单纯形空间利用狄利克雷分布采样多种数据配比候选 w = (w_1, ..., w_k) |
    +---------------------------------------+---------------------------------------+
                                            │
                                            ▼
    +-------------------------------------------------------------------------------+
    | Step 2: 训练一组轻量级代理模型 (如 30M - 300M 参数量)，评估下游任务 Loss     |
    +---------------------------------------+---------------------------------------+
                                            │
                                            ▼
    +-------------------------------------------------------------------------------+
    | Step 3: 拟合对数线性回归或决策树模型: Loss = f(w_1, w_2, ..., w_k)             |
    +---------------------------------------+---------------------------------------+
                                            │
                                            ▼
    +-------------------------------------------------------------------------------+
    | Step 4: 约束优化求解理论最优配比 w* = argmin f(w)，外推至生产级大模型训练    |
    +-------------------------------------------------------------------------------+
    ```

    * **先验分布采样**：混合权重向量 $\vec{w}$ 位于概率单纯形（Simplex，$\sum w_i = 1$），从狄利克雷分布（Dirichlet Distribution）或指数分布中采样候选混合方案。

    * **代理模型与拟合曲面**：采用 30M 至 300M 参数量的轻量代理模型在小 Token 预算下快速训练；采用对数线性模型（Log-linear Model）或梯度提升决策树（GBDT）拟合配比到验证损失的映射函数。

    * **约束求解极值**：利用拉格朗日乘子法或序列二次规划（SQP），求解在满足 $\sum w_i = 1$ 且 $w_i \ge 0$ 约束下的全局最小损失最优权重 $\boldsymbol{w}^*$。

    * > **易错点**：⚠️ 优化目标的设定决定了模型的综合智力走向。若代理模型评估集过度偏向代码与数学基准，回归优化器会将几乎全部权重倾斜给代码和数学语料，最终导致全量训练出的基座模型日常对话和通用文学表达能力严重退化；必须确保评估集具备高度无偏的多样性。

* **模拟轮次对齐与网格聚类（Simulated Epoching & Domain Clustering）**

    * > **定义**：解决小参数代理模型向千亿参数大模型跨规模迁移配比时产生的尺度依赖与极值失真问题的校准机制。

    * **极值外推失真与尺度依赖风险**：数值优化在单纯形极端边界处（如某源权重趋近 1）采样稀疏，导致回归外推误差急剧放大；小模型由于训练总步数少，小数据源（如维基百科）天然跑不满 1 轮，小模型会强烈倾向于给予维基百科极高权重；一旦搬到大模型，维基百科因库容耗尽强行空转数十轮引发过拟合。

    * **模拟轮次对齐机制（Simulated Epoching）**：在训练小型代理模型时，对高价值小数据源按照大模型的缩放比例进行**主动等比例下采样（Downsampling）**（如人工压缩可用池至 1%），强行让小模型在探索阶段就经历与大模型完全相同的数据匮乏与重复惩罚，确保拟合出的最优配比在大尺度训练中平滑生效。

    * **二维聚类网格（Domain Clustering Grid）**：针对全网抓取的海量粗糙爬虫数据（Common Crawl），先利用无监督聚类对文本进行细分主题划分，结合质量打分映射到“主题领域 $\times$ 质量层级”的二维矩阵网格中，将每个网格单元抽象为独立子数据源纳入回归优化。

    * > **定义**：将 GitHub 动态协作中非线性的有向无环图（DAG，包含多轮 Diff、行级批注、代码审查讨论）投影为自回归模型可吸收的一维结构化序列。

    * **XML 语义标签封装**：设计 `<issue>`、`<pr>`、`<diff>`、`<review_comment>` 等专用结构化标记封装事件流：
        ```text
        <pr_event type="review_comment" commit="a1b2c3d">
          <file_context path="src/core/engine.py">
            ... 变更行上下文代码片段 ...
          </file_context>
          <diff>
            - old_faulty_logic()
            + new_optimized_logic()
          </diff>
          <comment author="lead_reviewer">此处存在潜在的内存泄漏风险，建议改用显式上下文管理器释放资源。</comment>
        </pr_event>
        ```

    * **上下文权衡设计**：单个变更行缺失上下文会导致语义断裂，填入全量文件会造成严重上下文冗余；管线在变更行前后各截取固定局部窗口（如 $\pm 3$ 行）、函数级作用域与全文件前置包裹之间实施折衷平衡。

### 任务驱动长链推理合成

* **长思维链推理轨迹合成（CoT Synthesis, OpenThoughts）**

    * > **定义**：在后训练阶段摆脱昂贵人工标注，以精选真实问题为种子、由高能力教师模型高并发采样生成复杂长程思维链（CoT）轨迹的数据范式（产出 120 万条高质推理样本）。

    * **核心流水线步骤**：
        1. **种子池提纯**：从 Stack Exchange、NuminaMath、Codeforces 等竞技与问答平台精选出 7.5 万道核心高质种子问题；
        2. **多路径生成（Best-of-N）**：每道问题独立并行采样 16 组不同的长程推理轨迹（$75{,}000 \times 16 \approx 1{,}200{,}000$ 样本），覆盖多样化解题切角；
        3. **格式与去重过滤**：剔除逻辑死循环与排版损坏样本。

    * **核心反直觉实验结论**：
        - **精选优于盲目堆砌**：盲目整合所有粗糙公开题库会拉低综合推理水准，精选少数高信噪比核心种子收益最高；
        - **模型绝对跑分不等于教学能力**：基准评测跑分更高的模型不一定是最佳教师；实测中参数量更小但推理步骤详尽平缓的 Qwen-32B（QwQ-32B），其合成出的思考轨迹在微调转化率与学生模型接受度上显著超越 DeepSeek-R1；
        - **结果答案硬过滤收益微弱**：长程推理中仅凭最终答案对错进行二元硬过滤收效甚微，思维链中间推导步骤的严密性与自我反思修正过程才是关键。

### 软件工程智能体与环境解耦

* **重型沙箱执行环境流水线（SWE-smith）**

    * > **定义**：在隔离容器中为 GitHub 真实代码仓库还原编译构建环境，通过主动注入 Bug 生成单元测试并收集执行反馈的软件工程智能体数据构建范式。

    * **工程瓶颈（依赖地狱，Dependency Hell）**：尝试检出开源项目历史 PR 提交时，过时的依赖源失效、底层系统库不兼容导致 Docker 镜像构建频繁崩溃，维护成本极高，年产出规模受限于数万条（约 5 万条）量级。

* **执行环境解耦推演（SWE-zero & SWE-rebench）**

    * > **定义**：利用大模型内生代码语义先验，完全剥离实时 Docker 终端运行反馈、在纯静态上下文中高并发推演软件工程解决轨迹的突破性范式。

    | 合成技术范式 | 任务与问题来源 | 运行环境依赖度 | 数据规模吞吐能力 | 核心优势与工程代价 |
    | :--- | :--- | :--- | :--- | :--- |
    | **SWE-smith** | 人工规则向真实代码仓库主动注入 Bug | 极高；必须依赖真实 Docker 环境与单元测试执行 | 较小（约 5 万条样本） | 轨迹具备真机闭环验证保障；但受困于历史依赖冲突与极高的构建失败率 |
    | **SWE-zero** | 真实 GitHub PR 历史合并记录 | 零依赖；完全解耦真实终端执行环境 | 极大（生成 30 万条真实轨迹） | 彻底摆脱容器依赖地狱，支持超高并发推演；缺乏对极隐蔽动态运行 Bug 的纠错能力 |
    | **SWE-rebench** | 全网大规模并发抓取真实 PR | 混合；弹性沙箱尽力构建运行验证 | 极高（扩展至 1200 万条轨迹） | 兼顾全网工程多样性与局部真机验证；对自动化弹性构建流水线容错要求极高 |

    * **环境解耦对照实测**：基准评估中，允许终端实时执行反馈的智能体得分约 80 分；完全禁止执行反馈、依赖纯静态推演的智能体得分高达近 70 分；证明顶级代码模型具备极强的代码先验推演能力。

    * **混合微调工业实践**：SWE-zero 以零环境依赖高并发合成 30 万条无执行真实轨迹，仅搭配极小规模（约 1.3 万条）真实沙箱验证的黄金轨迹混合微调，即达到工业级卓越表现；SWE-rebench 进一步将该模式扩展至 1200 万条规模高地。
