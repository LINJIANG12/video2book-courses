在咱们讲完消息对象字段的说明以后，咱们接着来看 1.6 实战。这里的话咱们主要是讲两个练习，一个是对话历史的优化，第二个是多轮对话聊天机器人该如何去实现。

我们在刚开始讲消息的时候就提到过模型，说它是没有记忆的。如果我们希望模型能够记住之前你问过哪些消息、哪些信息，那我们是不是要维护一个消息的列表？在每一次跟大模型交互的时候把列表塞给大模型，大模型就记得之前的你都问过什么问题了，这就保持了它有一个记忆的状态。

有了这样一种思路以后，咱们再回过来看一下咱们这一节的内容。首先第一个问题就是如何去维护历史对话的管理。

大家看，我们刚开始的时候最简单，只有一个系统消息和一个 HumanMessage，然后我们把它塞给大模型开始进行交互。第二轮的时候，我们必须把上一轮的回复，AIMessage，和我们这一轮的 HumanMessage 重新放进去，这是一对。放进去以后 AI 又有一个回复。再下一轮的话，再把上一轮 AI 的回复再加上这一轮的 HumanMessage 再加进去。每一次都应该加一对，首先你得加一下上一轮的回复，再加上我们这一轮新的问题，得是这样的一个思路，每次加一对，这个大家要小心一点。

下面我就举了几个例子。看第一个例子，我们 invoke 了“我叫张三”，下次的话没有传历史，直接又问“我叫什么”，显然大模型是记不住的，根本就没有维护这样一个列表。

接着来看举例二，确实是有了一个列表，但是你看靠不靠谱：我们这里有一个用户的问题，然后直接交互了；接下来我们这里又生成了一个新的消息列表，那是不是跟前面又没有任何关系了？所以这块也没有记忆的概念，这个也不对。

再下面知道去做 append，添加到我们现有的列表当中，加进去了，然后做了交互。但是你在下一个过程当中又去添加了一个新的用户问题，是不是忘了把上一个回复的 response 它的 content 加到 conversation 列表里了？所以这个也是一个错误的。

正确的做法，大家看看我们这里边列的。这是我们一个 conversation 列表，先是用户的一个问题，把它加到 conversation 里面以后，跟大模型有个交互。交互的结果，交互的结果是一个 AIMessage，所以我们添加的时候以字典的方式或者 JSON 格式也行，role: assistant，content 就是我们回复结果里面的 content 字段，这就是我们对应的回复的字符串，添加进来了以后，接着你再去提问的时候，我们再去添加一个 HumanMessage 就可以了。注意，是这样的一个思路。每一轮我们都不能丢了这一步和这一步。每增加一轮，得把你这个 response 2 替换 response 1 添加进来，然后再去传你第三个问题。得是这样的一个思路。

这个不难理解，咱们就过掉了。接着来看对话历史的优化。

我们会发现，随着我们跟模型对话越来越长，首先我们会去消耗大量的 token 和成本。这个怎么理解呢？我们 model 在进行交互的时候，传进来的是消息的列表，大模型需要花 token，咱们需要花钱，输入多少 token、输出多少 token 都需要有一定的标准。你传入的信息越多，对应的 token 就越多，花费肯定就越多，所以这是一个成本的问题。

另外的话你会发现，当对话历史特别多的时候，用户有的时候也记不住他之前到底问过什么了，或者大概率也不会问以前的事情了，我们就有必要做个优化。

还有一个点，有钱不差钱，传进去过多的 token，第一个，浪费大模型的响应时间，信息太多它需要处理；第二个，如果你传进来的信息不够精准，后续问的问题都跟最近的情况相关，那么多余传的这些其实也不利于大模型做一个响应，响应的结果可能也会受上面无聊信息的一些影响。总而言之，结论就是我们有必要对对话历史做一个优化。以后的的话我们专门还会去讲上下文和记忆的问题，这里咱们只是先简单地做一个这样的优化。

这个优化的思路也非常直接，我们只保留最近 $n$ 轮的对话。这里边我们首先明确的是要保留 system 这个消息，你不能说一共是好多轮了，然后我们只保留最近的，把最初的 SystemMessage 给扔掉了，基础的角色都没有了，这是不合适的。所以 SystemMessage 我们要保留，然后通过最近用户的跟 AI 的交互，HumanMessage、AIMessage 一对一对的，我们只保留最近的，更早的我们就丢弃了，就是这样个思路。

咱们下面的重心就是来编写这样一个函数。首先里面包含了咱们对应的消息的列表，还有 max_pairs。这个你也可以设个默认值，比如默认我们就给它是保留最近的三轮记录。在这里边我们是不是就开来具体处理了？保留最近的 $n$ 轮对话。

这里的参数 `max_pairs` 是保留对话的轮数，每轮等于一个 user 消息再加上一个 assistant。

我们要去分离系统的消息和对话消息：

```python
def trim_messages(messages, max_pairs=3):
    """
    保留最近的 n 轮对话
    :param max_pairs: 保留对话的轮数，每轮 = 1 user + 1 assistant
    """
    # 分离系统消息和对话消息
    system_messages = [m for m in messages if m.get("role") == "system"]
    conversation_messages = [m for m in messages if m.get("role") != "system"]
```

这里是一个列表推导式，如果 `m.get("role") == "system"`，我们就把它取出来放到这里边。然后再去获取 `conversation_messages`，同样是一个列表推导式，只需要把上面拿过来，这个位置改成 `!=` 就可以了。

分离完以后，接下来我们下面要做的是不是只保留最近的消息对？意味着我们从这里边要取一个切片：

```python
    # 只保留最近的消息对
    recent_messages = conversation_messages[-(max_pairs * 2):]
```

基于前面的 `conversation_messages` 去取切片。这里大家注意一下该怎么去写呢？是不是就跟我们这个参数相关了。这里是一个“对”，那就意味着首先这个“对”的话我们得让它去乘一个 2，这就涉及到了一共是多少个了。按照 Python 的写法，我们这样处理一下就可以了：`-(max_pairs * 2):`。

在这个基础之上，我们接着去返回系统消息和最近的消息对。直接去 return 一下，把这两个直接做一个连接就可以了：

```python
    return system_messages + recent_messages
```
