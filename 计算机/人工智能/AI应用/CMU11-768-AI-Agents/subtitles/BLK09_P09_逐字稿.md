今天我们要从监督微调过度到策略梯度方法，这是强化学习里最基础但也最优雅的形式之一。我们贯穿全课的例子是这个叫 number search 的任务，基本上就是训练一个 agent，根据太高了还是太低了的反馈来猜一个数。这个任务很简单，容易理解，也容易想出一个合理的策略。

设定是这样的：环境里有一个数，agent 不知道这个数，它是 1 到 16 的整数。agent 有 4 次机会猜这个数。每次猜完，如果猜对了，环境会说正确，否则环境会说应该猜高一点或应该猜低一点。然后就这样继续下去，agent 可以再猜一次，总共最多猜 4 次。只要任何一次猜对了，任务就结束，它得到奖励 1；但如果 4 次都猜完还没猜对，奖励就是 0。

我们接下来要过一遍的很多轨迹，都来自一个隐藏数字是 11 的例子。agent 会试着猜出它。这里有 4 次可能的尝试：第一次，agent 猜 8，得到反馈应该猜高一点；然后猜 12，得到反馈应该猜低一点；再猜 10，高一点；最后猜 11，最后一次猜对了。另一种尝试可能从一个更小的数开始。

那么，这里的最优策略是什么？最好的起始数是多少？中间值，对吧？像 20 个问题游戏，要把搜索空间对半拆，对吧，最好先猜 8。不过，你们有多少人玩过 Wordle？就是纽约时报的那个猜词游戏，挺好玩的，它跟这个有点类似，也有一个最优的首次猜测，能从信息论的角度缩小搜索空间。这里的概念类似，你可以从一个次优的第一次猜测 4 开始，但只要把反馈考虑进去，先猜高一点，再高一点，再低一点，如此不断调整下去，最终也能猜对。

但也可能出错，对吧？我们可以从一个很糟糕的 16 开始，除非碰巧猜对，否则反馈会是低一点，这种情况下我们可能就超时了，4 次之内没猜出来。类似的，还有一个很糟糕的策略，从 1 开始，然后 2、3、4，最后超时，任务失败。大家都清楚这个设定了吗？

那我们继续。我们还要给轨迹定义奖励。奖励就是一个标量值，告诉你这条轨迹是好是坏。在 agent 场景里，这可能对应于，比如你写的代码在 SWE-bench 上是否通过了全部单元测试。通过全部测试就得奖励 1，没全通过就得奖励 0。当然也可以有不是 0 或 1 的值，也就是非二值奖励，比如通过测试的比例。不过现在人们训练的很多领域，也就是所谓的 RLVR，用可验证奖励做强化学习，奖励都是 0 或 1。但我们今天讲的方法更通用，也适用于标量奖励。

简单回顾一下 SFT 是怎么工作的。在监督微调里，你有一个任务的示范，然后训练 agent 去复制这个示范。做法是最大化示范内容的概率、动作的概率，把一条轨迹拆成这些步骤，给 agent 一个 prompt，一次猜测，环境反馈高一点，再一次猜测，更多环境反馈，以此类推。

我们的任务是给定这些示范动作，记作 $a^*$，我们要最大化 agent 在此前全部历史条件下给这些动作分配的概率。所以这就是监督微调损失，最大化整个序列概率的对数，也就是各个动作概率对数之和，对吧？我们要模仿的目标动作有很多来源。这些示范可能来自亲自演示任务的人，也可能来自我们想模仿、蒸馏的更强模型。而今天，它们还可以来自 agent 自己生成的轨迹。我们想在模型中强化这些轨迹。这部分应该是大家之前学过的内容，包括之前的 LLM 训练课程和上周的 SFT 讲座。

不过 SFT 存在一些问题，强化学习正是要解决这些问题。我们主要关注其中三个。

第一个可以称为任务失配。监督微调最大化的是每个时间点上被示范动作的概率，但我们真正关心的是最大化 agent 成功完成任务的概率。这两者很接近，但并不完全一样。原因有几个，第一个原因是成功完成任务的方式不止一种，对吧？比如第一次猜 8 是最好的选择，但只要你能利用好反馈，从 4 开始猜也是合理的。在第一步反馈之后，同样有多种合理的动作可选。而示范不管是来自人还是别的模型，只展示了一种解法，但我们希望 agent 也能用上其他解法。第二个问题是有些动作比另一些差，但在 SFT 看来它们都一样。比如收到应该猜高一点的反馈后，如果我们输出一个小于 8 的数，那就非常糟糕，对吧？但 SFT 不会区分那些没被示范过的动作。所以无论 agent 把最高概率给了一个更差的备选动作，还是给了一个更好的、只是没被示范的动作，损失都是一样的。这就是 SFT 损失与我们真正想优化的目标之间的失配问题。我们真正想要的是最大化期望奖励，也就是任务成功的概率。

第二个问题是数据失配。我们希望从次优数据中学习。即便假设我们的示范就是完成任务的最佳方式，如果我们还能拿到一些没那么好甚至失败的示范，它们也能给模型提供有用的信号。比如说，我们知道这是一条坏轨迹，比如它超时了，我们不会想直接对它做 SFT，不会想最大化那些动作的概率，但我们可能希望有一种学习方法能让模型不再走出这样的轨迹。强化学习就是做到这一点的一种方式。

第三个问题叫曝光偏差。在 SFT 中，你训练模型根据一段固定的过去动作序列来预测下一个动作，对吧？而这段固定的动作序列来自某个地方。但到了评估时，之前的动作是由模型自己生成的。对吧？因为你得逐个产生动作，用的就是过去的动作，这就是与环境交互的自回归过程了。如果 agent 产生的动作跟它训练时见过的历史分布差得很远，它给出的响应可能就没校准好，因为他从没见过那样的数据。比如说，我们只在下一个整数总是符合反馈的示范上训练，反馈说更高就猜更高，那么生成时如果模型犯了错，采样到一个更小的数，它可能就完全乱了，因为训练时它只见过这些最优策略，没见过这种情况。这样讲清楚了吗？

理解强化学习的一种方式是，它让模型自己生成训练数据，并学会从自己的错误中恢复，这样在生成时它就能应对自己的错误。模型自己生成训练数据这个特性，就叫在策略。这通常是件好事，因为它让模型准备好应对自己的错误，而且得到的监督信号和模型当前能预测的东西很匹配。但它在效率上可能有取舍。在 Graham 的讲座里，我们会讲很多放宽这些假设、更偏向离策略的方法。

好，这就是监督微调在 agent 乃至一般序列预测上的三个问题。有什么问题吗？

强化学习的大致思路是不再用一条固定的轨迹来学习、通过最大化动作的概率去模仿它，而是让 agent 或模型自己生成动作，然后评估这些动作在轨迹中的奖励，接着调整 agent 的参数，让高奖励的轨迹更可能出现，低奖励的轨迹更少出现。形式上讲，稍后我们会看到具体公式，我们要训练 agent 去最大化它的期望奖励，也就是在 agent 和环境共同作用下的概率期望。

简单示意一下：假设我们有数字搜索这样的任务，环境里的隐藏目标是猜出数字 11。我们让 agent 生成多条轨迹，就是每一步从 agent 采样出可能的动作，跟平时在环境里评估 agent 的方式一样。对每条轨迹，我们通过在环境中执行这些动作得到一个奖励，然后把这个奖励作为强化学习方法的反馈，它会调整 agent 的参数，让这些高奖励的轨迹更可能出现。

这就能解决我们前面提出的 SFT 的三个问题。任务失配解决了，因为我们现在直接训练 agent 去最大化期望奖励。具体怎么做我还没讲，这节课前半部分会重点讲这个，我们会写出期望奖励的形式，对它求导，然后直接优化。它还能解决数据失配，因为后面会看到，尤其是课程中后段，agent 将能从所有轨迹中学习，这样它能从这些坏轨迹里得到信号，以后就会避免采取那些导致这类轨迹的动作。它还能帮助解决曝光偏差，因为现在训练用的轨迹是由 agent 自己生成的，这就是在策略的。如果它犯了错，发现错误导致奖励很差，就会因此受到惩罚，以后学会避免。所以它算是在为应对自己的错误做准备。大概三四年前，人们对语言模型有很多不满，比如有重复倾向，会卡在循环里出不来。后来人们开始把强化学习作为最后的后训练步骤，模型能从自己的错误中恢复，这些问题就大多解决了。

接下来我们讲怎么把与环境的交互表示成轨迹，这样就能建立我们要优化的目标函数。这部分不会花太多时间，因为就是课程前半部分内容的回顾。我们有一个 agent，它会被表示成一个策略，记作 $\pi_\theta$。$\theta$ 是驱动这个 agent 的语言模型的参数。agent 生成动作的方式是从语言模型里采样，再把采样结果放到它运行的那个框架里执行，这样就产生了动作。然后你在环境里执行这些动作，环境会返回观测和奖励。我们要看的很多设定只在任务结束时给奖励，比如真正执行测试用例的时候。但我们讲的内容几乎都同样适用于有中间奖励的设定。

也就是你每采取一个动作，都能得到一些关于这个动作价值的奖励。

举几个例子，看看这个通用框架怎么用在文本生成上。任务实例可以是你想生成补全的那个prompt。观测可以是目前已有的token。动作就是下一个token。奖励可以是judge模型给的分数，比如你在做基于人类反馈的强化学习的时候。

对于web agents，就像一两周前讲的那种设定，任务实例可以是任务本身加上网站。这里要注意，环境的状态，也就是决定环境的一切，和agent能观测到的东西是两回事。可能有一些隐藏状态，比如背后数据库的上下文。但agent只能观测到它当前所在的页面。它可以执行点击、输入、滚动这些动作，还可能拿到中间奖励，比如任务描述里的子任务它已经完成了多少个。

至于数字搜索，我们见过的任务实例就是agent要猜的那个数，而且这个数对agent是隐藏的。数字搜索里一开始每个任务对agent都一样，观测是该猜高一点、该猜低一点或正确。动作是下一次猜测。猜对了奖励是一，超时了就是零。

好，我们的目标就是最大化期望奖励。那这是什么意思呢？我们要做的，是从agent那里采样，也就是让agent在环境中生成轨迹。通常的做法是从语言模型里采样动作，然后把这些动作喂给agent的框架去执行，对吧？所以可以把它写成：从这个由语言模型本身参数化的分布中采样一条轨迹。对每条采样得到的轨迹——这是个很复杂的分布，取决于agent、语言模型和环境——我们会得到一条轨迹，然后评估它的奖励。这会给出一个数值。而我们要最大化拿到高奖励的机会，也就是最大化这个期望。我们把这个目标记作 $J(\theta)$，因为它是语言模型参数的函数。

在我们这个非常简单的设定里，就用这个数字搜索。假设语言模型实际能产出的轨迹只有四条，说明它学到了一个非常尖锐的策略。假设它给第一条轨迹的概率是0.3，第二条是0.2，第三条和第四条各是0.25。一般来说蓝色代表成功，奖励为一；红色代表失败，奖励为零。所以如果agent只能产出这四条轨迹，期望奖励就是0.5。也就是把这些轨迹的奖励按agent策略下的概率加权求和。

训练的目标就是优化这个量。我们要调整参数 $\theta$ 来最大化这个期望奖励。你可以把当前这个agent看做比较差，因为它有相当高的概率（0.5）产出奖励为零的轨迹。我们想把这部分概率挪走。理想情况下把所有概率都挪到奖励为一的轨迹上，也就是把概率质量从红色挪到蓝色。这显然是简化了，因为实际上agent能产出的可能轨迹不是无限多，但也是组合爆炸级别的数量。不过我们这里只是把可视化稍微简化了一下。

有一种做法是对SFT做一个很简单的改动，而且动机很充分，它叫专家迭代。专家迭代的一种特定形式叫强化自训练，简称ReST。ReST的思路是：我们直接从当前策略生成数据，也就是从当前的语言模型参数生成；然后挑出成功的轨迹，把它们当做微调数据，用它们来更新模型。这就是“强化”这个词的由来，它会强化agent已经在产生的正确行为。

它有两个步骤，会不断迭代。ReST-EM这个名字我想是取自期望最大化，因为它看起来非常像EM算法。你们有些人可能在机器学习课上见过。思路是交替进行这两步：第一步，从当前策略采样轨迹，得到它们的奖励；第二步，对这些收集来的轨迹做大量SFT，让模型把它们的概率变得很高。然后重复。你会从当前策略得到更多轨迹，并把这些把这些轨迹加进已有的好轨迹集合里，然后用所有这些来训练模型。这样你就有了一个不断增长的数据集，让模型迭代地越来越擅长生成这些轨迹。

这大致是个高层描述。具体机制是：先生成一批轨迹，评估每条的奖励，然后用一个阈值来筛选。如果奖励是二值的，这一步很简单，是二值的话就保留奖励为一的轨迹，丢掉奖励为零的。然后把所有任务实例中保留下来的轨迹合并起来，作为下一轮迭代的训练集。SFT的目标就是SFT目标，最大化这些被保留轨迹中动作的概率，也就是二值奖励下奖励为一的那些轨迹。

从示意图上看，这其实和我们接下来要讲的强化学习方法相当像。严格来说它不算强化学习，但确实和强化学习有很多相似之处。因为你是在用模型生成数据，再根据轨迹的奖励来决定怎么在这些数据上更新。后面我们会看到强化学习怎么用更细粒度的方式做到这一点，不过这是一个非常简单又相当有效的起点方法。它复用了监督微调的全部机制，而且很适合二值化的奖励。

对。你问的是自训练，它和自蒸馏的区别只在于：你是用奖励来做筛选的。自蒸馏也可以指在模型生成的全部轨迹上做训练。它叫自训练是因为看起来很像自训练，说它是强化的，是因为你用了奖励，等于在强化那些好的轨迹。

对，我有个更基础的问题，你怎么保证轨迹里确实有奖励的正本？比如最糟糕的情况，采样出来全是一堆失败的轨迹呢？

没错，这是个好问题。就是你怎么保证有些轨迹能拿到好奖励？如果你的模型根本产生不出有好奖励的轨迹，那强化学习和这个方法可能都不太适用。有几个办法：一个是准备一些好轨迹的示范，用它们来训练模型。比如RE论文和很多推理模型都会有一个所谓的冷启动阶段，先在推理轨迹上训练模型，然后再开始做强化学习，这样能让强化学习或类似方法更容易产生高奖励的轨迹。还可以用课程学习，先挑那些有足够轨迹能产生奖励的题目来训练，等模型变强了再去攻克更难的题。还可以用中间奖励，如果你了解这个问题，知道先探索代码仓库有用，就可以为此给模型奖励，希望它学会之后就能解锁解决整个任务。但这是强化学习算法必须应对的一个大问题。刚才说的就是几种解法。

好。那我们现在正式进入策略梯度方法。

我们要最大化这个量，也就是 $J(\theta)$，奖励的期望。我们不能直接用反向传播来做这件事，原因有两个：第一个原因是，动作是从我们的策略里采样出来的；第二个原因是，接下来要在黑盒环境里执行这些动作，而这个环境几乎总是不客观的。这就让我们没法做反向传播，没法像机器学习课上那样直接用链式法则去求出奖励对参数的导数。另外动作是离散的，而且是采样出来的，采样动作对参数的导数几乎处处为零，因为参数改变的是概率，但在到达某个阶跃点之前并不会改变采样出的动作。环境通常也不可微。

这个问题的一般解法其实是一个相当经典的方法叫REINFORCE，是Williams在1992年提出的。它会用期望奖励的这个定义，再加上一些基本的代数技巧，从而算出它的一个估计值，用模型采样出的样本，加上我们之前看过的反向传播流程来求偏导数，也就是对参数 $\theta$ 的导数。下一张幻灯片会演示具体怎么做。

这就是我们要优化的目标，它是对来自环境和策略的轨迹取期望，也就是这些轨迹奖励的期望。如果你还记得期望是什么，它就是对这些东西，也就是这些轨迹求和。对里面的这一项，也就是奖励加权，权重就是那条轨迹的概率。这是在

一个非常大的空间上求和，比如语言模型所有可能的轨迹。我们几乎不可能精确算出它，但如果我们想算，结果就是这个样子。

对它求梯度，也就是对参数 $\theta$ 求偏导，我们可以把这个求导移到求和号里面。而这个奖励项只依赖于轨迹，所以一旦知道轨迹就知道奖励是多少，它不再依赖于参数。参数负责生成轨迹，而奖励只是轨迹的函数，所以这个奖励项会乘上这个概率的偏导数。

但这一步还是很难，因为这是对可能数量极其庞大的轨迹求和。所以我们要用一个代数技巧，叫做得分比值技巧，就是乘上再除以 $P_\theta$ 这一项。我们在这里写上它，分母里也有它，两者相消，所以这个和那个是一样的。然后我们就能用这个技巧，也就是 $\log P$ 对 $\theta$ 的偏导数，直接用链式法则，它就等于 $P$ 的偏导数除以 $P$。把这个恒等式用在这里，就得到这一项，这有点神奇。因为我们现在有了这个，也就是对轨迹的期望乘上奖励项，再乘上这一项。

而这一项其实就是我们在 SFT 里做的同一个计算。在 SFT 里，我们同样在对一堆 token 的 $\log$ 概率求关于语言模型参数的偏导数。

那么我们可以通过采样轨迹来估计这个量，然后计算这里的这一项，这样我们就得到了这个期望奖励梯度的估计。有什么问题吗？这个方法非常通用，对语言模型和环境都不做任何假设。

对，我想问的是轨迹是状态和动作的序列，但大语言模型生成的动作本身也是序列，有没有标准的方式来处理这个问题？

对，我们过几页幻灯片就会拆开讲。不过这是个好问题。

我们把那一项抄过来，然后把它拆成各个组成部分。这些轨迹的采样方式，就是让语言模型加上它上面的 agent 去和环境交互，这和你平时运行这个 agent 用的流程是一样的。这样就得到一条轨迹。

我们这里应该是对轨迹求平均，因为我们可以从这个分布里抽取若干样本再取平均来估计期望，也就是期望里面的这个量。所以如果我们对从这个分布抽出的许多轨迹求平均，也就是对这个量求平均，就能得到这个梯度的估计。

那里面这些项是什么呢？因为这是一条轨迹，我们把它拆成一步步来看，它就是对各个时间步求和，每一项是那个特定动作贡献的梯度。过几页我们会讲怎么算。

所以这里有三个组成部分：轨迹，我们通过采样得到；任务层面的评估，来自环境；还有这个梯度。它的计算方式和监督微调里求梯度的方式相同，但关键在于这里的动作是采样出来的，来自 agent 本身，而不是由某个标准答案演示出来的。

好，那我们怎么得到轨迹的 $\log$ 概率呢？这部分我讲快一点，要记住的关键是一条轨迹的概率既取决于语言模型加 agent 给出的概率，也取决于你从环境得到那些特定观测和奖励的概率。但关键在于这个概率完全不依赖于语言模型的参数，所以如果我们对轨迹的 $\log$ 概率求关于参数的导数，这整个项就直接消失了，因为它相对于参数是个常数，所以我们可以直接忽略它。而这个梯度，轨迹的梯度，就是轨迹内各个动作的梯度之和。这一步主要是为了严谨做的记账。

不过有一点很重要，agent 产生的这些动作可能对应你语言模型里的多个 token，对吧？比如你要做一个复杂的工具调用，它就会拆成多个 token。当然，这些 token 的 $\log$ 概率直接加起来，就是整个动作的 $\log$ 概率。还有，当有了这个轨迹的梯度，对一条轨迹的梯度，你只要乘上奖励，它是一个标量值，来自环境，就得到这条采样轨迹对期望的贡献。

那在实际例子上跑起来是什么样子的呢？你会有一条从 agent 采样出来的轨迹，这些蓝色的 token 就是模型实际生成的，所有灰色 token 要么是 prompt 一部分，要么来自环境，要么是脚手架加的，而这些才是真正由语言模型生成出来的，也正是会对策略梯度的损失产生贡献的部分。

我们拿到所有这些生成的 token，取它们的 $\log$ 概率，也就是那个生成的动作是从语言模型的分布里采样出来的，在那个时刻的各个 token 上的分布。然后我们把这些 token 的对数概率全部乘以这条轨迹对应的奖励，这样清楚吗？

然后如果对它求梯度，梯度会传进去作用到这里的对数概率上。所以你的梯度就是奖励乘以梯度。我第一次看到在相当复杂的任务上实现 REINFORCE 的代码时，那是在用强化学习优化对话模型，出自一篇叫 Deal or No Deal 的论文，实现竟这么简单，真让人惊讶。基本上就是做一次 SFT 的梯度计算，然后把梯度乘以奖励，或者把损失乘以奖励再求梯度，但它确实有效，数学上也成立。这里我们会用一个掩码，也就是把一部分内容遮掉，只选出你自己生成的那些 token，然后把它们全部乘以这条轨迹的奖励。这就是 REINFORCE 策略梯度的实现。

训练循环就是采样一些任务实例，评估它们的奖励，用刚才那页讲的公式算出损失，然后再做更新，也就是对这一批样本里的所有实例做一次更新。之后讲 GRPO 的时候，我们会说怎么给一个任务实例 $i$ 生成多条可能的轨迹，然后全部用在更新里。但如果只是标准的 REINFORCE，每个例子只用一条轨迹，然后据此计算更新。所以 batch size 就是任务实例数。但到了 GRPO，每个任务实例还会有多个采样。关于这部分有问题吗？

好，简单说一下，在二值奖励下，这看起来很像我们讲过的 REST 的流程。两者都只是用奖励去缩放动作的对数概率。区别在于 REINFORCE 是完全在线的，采样出这些轨迹，然后直接在它们上面更新；而 REST 是先攒出一个很大的数据集，然后在上面训练，可能对所有实例跑一个甚至多个 epoch。但背后的直觉基本一样。不过这也有很多问题，所以很少有人直接开箱就跑标准的 REINFORCE 策略梯度。

我认为接下来这些方法最强的动机在于由奖励驱动的更新其实应该是相对的。我们来看这两条不同的轨迹：这条是成功的，按我们讲过的更新规则，奖励为 1，所有动作都会被上调权重；这条是失败的，第一次猜的就很糟，最后超时了。只用基础 REINFORCE 或 REST 的话，这个例子完全不会产生更新，对吧？因为更新要乘以奖励，而奖励是 0。但我们其实想学会别这么做，对吧？

接下来这一部分的思路是平移奖励，让梯度的估计依然正确，同时能从各种尺度的奖励中学到东西，或者说平移。换个角度看，你做的更新应该取决于策略在这个例子上预期表现有多好。比方说这是个简单例子，模型 95% 的时候都能拿到奖励 1。如果剩下 5% 的时候你犯了个很蠢的错，拿到奖励 0，就应该大力惩罚这些罕见但代价高的错误。接下来要讲的基线和优势函数就是干这个的，把奖励和策略在这个例子上预期拿到的奖励做比较。

数学上是这样，我们定义一个优势函数，它以到某个时间步为止的历史和一个动作为自变量，意思是假设你采取这个特定动作，然后剩下的轨迹都从语言模型里采样，这会告诉你结果；再把它和直接从语言模型采样，包括这个动作，然后继续走下去的情况对比。这就能告诉你，考虑到语言模型之后会采取的所有动作，这个特定动作相对于整体价值来说有多好。

举个具体例子可能有帮助。假设猜数游戏进行到一半，猜 8，反馈是要更高；猜 12，反馈是要更低。那我们就知道数字在 8 和 12 之间，所以只可能是 9、10 或 11。我们并不确切知道这个价值函数是什么，它取决于我们的策略。但可以想想大概是 $\frac{2}{3}$ 到 1 之间，对吧？如果策略总是做到最好，那从这个局面出发你总能赢；但如果策略在合法选项里比较随机，那可能更接近 $\frac{2}{3}$。

我们可以想想各个猜测相对于这个基线的优势函数。比如猜 11 就不太好，因为它在这个范围的一端，万一 11 不对，那就不太好了，就还剩两个候选数和一次机会，所以它的优势应该很低；而猜 10 就不错，因为就算猜错，还剩一次机会，往高或往低都行。

很多强化学习算法就是从估计这些优势和价值的各种不同方法推导出来的，也就是这个动作的 $Q$ 值和相应的价值。接下来我们会讲其中几种方法。但一个关键想法是，如果我们不知道 $Q^\pi$ 或 $V^\pi$，我们可以估计它们。我们可以通过实际行动估计这个特定动作的期望奖励，也可以估计这个价值，也就是我们预期表现有多好，用的就是我们所说的基线函数。接下来几页幻灯片会给出一些基线函数的例子。

基线其实就是一种重新缩放奖励的方法。这是 REINFORCE 对期望回报的估计量，它用奖励来缩放对数概率，也就是用奖励去重新缩放这个对数概率的梯度。而基于优势函数的方法，一般就是从奖励里减去一个基线。这两种方法数值上并不等价，但都是估计策略梯度的有效方法。下一页幻灯片会证明这也是对同一个量的有效无偏的估计量。而定义不同的基线就会得到不同的强化学习算法。

接下来会有一个例子说明为什么减去基线是有好处的。在那个例子里基线就是一个常数。基线也可以是你目前见过的所有例子的奖励的滑动平均；它还可以是一个训练出来的神经网络模型，Actor-Critic 方法和 PPO 就是这样，我们下一讲可能会讲到 PPO。但这需要一个独立于策略之外的模型，成本可能很高。在本讲的最后一部分，我们不会用单独的模型，而是直接从策略本身采样来估计策略下的期望奖励。这就是 GRPO 算法。

好，关于这个有什么问题吗？接下来几页幻灯片还会进一步说明为什么要用基线。

这里简单说一下基线和偏差的问题。这两个项都是对底层期望……

奖励的估计，而估计是可能有偏差的。估计有偏差和方差，偏差是说估计的均值可能偏离真值多少，方差是说抽出来的估计值有多分散。

你可能会担心估计量有偏差。有一个引理表明，减去一个只依赖于到目前为止历史的基线——我们这里定义的所有基线都是这样——不会使梯度产生偏差。

看法是这样的：这是我们的优势函数，也就是基于基线的期望回报估计。我们可以把它的期望分解成这几项，只用结合律，把这一项放到这里，这就是偏导数的定义，也就是 $J$ 的梯度，减去这里基线 $b$ 乘以这一项的期望。

如果这一项的期望是 0，那它就等于前面这个。要看出这一点，只需取这一项，把期望像这样展开：它是对从这个策略采样的动作取期望，然后把基线项提出来。基线只依赖于到目前为止的历史，不依赖别的，于是剩下的就是对动作求概率之和。

我们可以用同样的对数导数技巧把它改写成这样，然后这一项就变成 1，于是就是基线项乘以 1 的偏导数，结果是 0。

这说明你可以减去一个只依赖于到那时为止的动作和观测历史的基线，而不会使策略梯度的估计产生偏差。

接下来看一个例子，说明基线如何真正降低梯度估计中的噪声。这一点非常重要，因为强化学习中大量的工作就是在降低梯度估计的方差，让学习稳定，能扛住从策略和环境采样带来的各种波动。

为了说明这一点，我们看一个非常简单的例子，只有两个动作。没有多个时间步，只有一次决策在两个动作里选，你要么猜 A，要么猜 B。

我们用一个只有单个参数的极简策略，就是 $\theta$。对 $\theta$ 应用 sigmoid 函数就得到一个概率化的策略。sigmoid 是一个压缩函数，把负无穷到正无穷的实数映射到 0 和 1 之间。我们把这个值当做选 A 的概率。假设当前策略的 $\theta$ 是 -1.1，最后给出很方便的概率：0.25 的概率猜 A，它的奖励是 1；0.75 的概率猜 B，它的奖励是 0。这是个好策略还是坏策略？想想概率和奖励是怎么对应的。

这是坏策略，因为它把更高的概率给了没有奖励的选项。所以我们希望用策略梯度来更新参数 $\theta$。$\theta$ 该往哪个方向更新呢？

对，我们希望它变得更正。因为 $\theta$ 越大，我们在这条曲线上就走得越靠上，猜 A 的概率就越高，而 A 正是奖励更高的那个选项。

那我们先不用基线来算梯度，看看策略梯度能不能给出正确方向。我们可以算出期望，也可以算出从每个可采样动作得到的策略梯度估计值。那如果我们采样到猜 A，梯度估计是多少？这个值等于奖励乘上偏导数，而利用 sigmoid 函数的性质，这里的偏导数是 0.75。所以梯度就是两者的乘积等于 0.75。

同样，如果采样到的不是 A 而是 B 呢？因为奖励是 0，得到的梯度估计就是 0。这有点像我们之前看到的那些轨迹奖励为 0 时得不到任何梯度。这里也一样，采样到奖励为 0 的动作就得不到任何梯度。

但如果按策略梯度的严格定义，也就是对所有动作取期望——这个设定里只有两个动作，我们可以精确算出来——只要把每个梯度乘上采样到该动作的概率就行。具体数字后面几页会看到，大概是 0.18。

所以真正的策略梯度，也就是对所有动作的期望，是 0.18。但我们只能得到噪声很大的估计，有 25% 的概率会踩到 0.75，远高于 0.18；然后 75% 的概率会得到 0 作为估计值。而我们真正想要的是两个采样估计都更接近真值 0.18。

基线就能做到这一点。相比之前，改动只是从奖励里减去一个基线，其他计算都一样。结果就是如果采样到猜 A，梯度估计变成 0.375；如果采样到 B，梯度估计就是 -0.125。乘上各动作概率后的期望仍然是 0.18 左右，和之前一样，但每个单独的样本都更接近真值了，因为基线确实降低了样本的方差。后面还有一页会可视化这一点。

关键在于期望没有变，它只是让估计量的方差变小了。这是好事，因为你要在真实数据上做这些估计做更新，你可不想让梯度没必要的把你晃来晃去。

来看看可视化。如果基线是 0，梯度估计是这样的，它们的期望值是 0.18。当我们拖动基线，可以看到梯度估计逐渐收敛到期望的真值。不管怎样，我们做的更新都会让模型更正确。更新会让 $\theta$ 变得更正，从而提高猜 A 的概率，把更多概率放到奖励为 1 的那个选项上。只不过估计的方差更低时，这个过程会更快。

用剩下的最后一点时间我们来讲一个简化版的 GRPO，也就是组相对策略优化（Group Relative Policy Optimization）。如果我没记错的话，它是一种得到优势函数、估计基线的方法，用的是模型自身的 rollout。这个方法其实是很近期才提出的，它出自 DeepSeek 的一篇论文。那篇工作在训练推理模型时非常注重效率。

过去很多把强化学习用于语言模型的工作，都需要一个单独的模型来预测基线。预测基线来降低方差非常重要，但做起来很难，大家用的都是单独的模型。但 DeepSeek 非常看重效率，想用不多的算力训练模型，而单独的模型很吃算力。于是他们提出这个方法，去掉单独的模型，直接用模型自身的多样本来估计期望值，也就是策略下的期望奖励。这个思路相当优雅。

具体做法是对同一个实例从模型采样多次，然后取每次的奖励。然后我们对奖励做中心化，取这一组里所有这些采样的奖励均值。得到一个均值，我们基本上就拿它当基线。这很合理，因为一个好的基线就是你期望的策略下的奖励，而估计它的好办法就是把策略跑多次取奖励再求均值。这样我们就得到了中心化的奖励。

在原始的 GRPO 论文里，他们还做了标准化，也就是不仅平移，还重新缩放。他们算出这组轨迹奖励的标准差，然后除以这个标准差得到优势函数。不过实际上除以标准差这一步似乎并不是必要的。很多自称 GRPO 的实现其实都去掉了除以标准差的步骤，这样更贴近优势函数本身。后面几页会讲到一篇叫 Dr. GRPO 的论文，意为 Done Right GRPO，它更详细地讨论了这样做的动机。实际上很多 GRPO 的实现并不除以标准差，只减去均值。

GRPO 的更新非常简单，和我们之前定义的策略梯度很像。你有一个任务实例，也就是一个要解决的强化学习问题，你要从它生成多个 rollout，也就是把同一个问题解多次，每次重置环境，通过从你的 agent 采样来得到完整轨迹。至于组大小取多少，我记得 Apoorva 在他的课上会给一些建议，不过一般取 8 左右。你会算这些 rollout 奖励的均值，并由此得到优势函数的估计。后面会用一页幻灯片展示两种优势估计方法。这样就得到一个实例的一组 rollout 和优势函数。

如果 GPU 装得下更多样本，你还可以对其他实例取同样大小的组。而且组均值只在每个例子内部计算。这一点很重要，因为价值函数应该只是对具体例子上奖励的估计，所以我们的优势函数只应该看这个例子内部的奖励。而每条轨迹的优势函数是用那个公式对它的奖励做缩放得到的：先减去均值，可能再除以实例内奖励的标准差。

好，时间还够，Dr. GRPO 对 GRPO 做了两处修改，你们在作业里也要做这两处。这些修改总体上是有帮助的，因为它们能够帮助避免 GRPO 里的一些偏差。第一处修改我们刚才已经提过了，它不除以标准差，只减去组内奖励的均值。这么做的动机是，如果除以标准差，优势函数就不再感知问题的难度了，因为你等于把各种难度范围都重新缩放成了同一标准，这其实可能是有害的。GRPO 还除以了生成的 token 数，这会让模型偏向又长又错的答案。所以 Dr. GRPO 只除以一个常数，即可生成的最大 token 数。

好，之前有个问题，如果所有奖励都是 0 怎么办？那就糟了。因为如果所有轨迹都失败，说明对当前策略来说任务可能太难了，就算有基线，你也得不到任何信号。如果所有轨迹都成功，也有问题，因为对当前策略来说任务太简单了。就是说如果是二值奖励，1 是我们能拿到的最好结果，那这也不好。一般来硕，只要样本之间没有区分度就不好，因为这样 GRPO 估计出的优势函数就给不出任何信号。

那如果每条采样轨迹都失败，我们能做什么？可以换不同的任务实例，也可以在 prompt 里注入一些知识，引导模型产出更可能正确的解法，还可以加入示范。有一些离策略强化学习的方法，会把正确的示范放进组里，或者更简单，先在这些正确示范上微调模型，再跑强化学习；或者用更有信息量的奖励，鼓励模型在生成完整轨迹之前就做出正确的中部决策，这叫奖励塑形。比如给模型找到正确文件的奖励就是一个例子。

好，快速对比一下目前讲过的方法。每种方法都让 agents 在环境里执行动作，然后我们用 agents 产生的这些动作来计算损失。这些方法看起来都像某种自训练，区别只在于如何给生成的动作重新加权。ReST-EM 假设奖励是 0 或 1 的二值奖励，只筛出正确的轨迹，然后对他们做 SFT。REINFORCE 用轨迹的奖励来重新加权损失，也就是重新加权梯度，我们花了很多时间证明这是正确的。而 GRPO 用的是优势函数，奖励会做平移，还可能按模型对同一实例采样的其他轨迹的奖励来重新缩放。

这些方法都有助于解决本讲座开头提出的三个问题。任务不匹配现在应该解决了，因为我们直接最大化奖励，直接最大化期望奖励；数据不匹配方面，只要基线用的合适，现在就能从零奖励轨迹中学习了；另外，这些方法在策略特性也有助于应对曝光偏差，因为模型在训练时相当于自己在开车，所以它应该学会从自己的错误中恢复过来。但这也有代价，你得真的在环境里去尝试各种方案，这可能开销很大，还会给梯度引入一些噪声。我们也讲过一些让这个过程更稳健的方法。但从下周开始的后面两讲，我们还会介绍其他方法。好，今天就到这里。
