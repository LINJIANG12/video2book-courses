抱歉，我重新說，其實不是這個。好了，應該沒問題了。對，CUA 就是計算機使用 agent，它和你已經見過的 agent 有點不同，因為它的輸入其實是大多數應用裡的圖形用戶界面。它可以是網頁瀏覽 agent，可以是操作你桌面電腦的 agent，也可以是操作手機這類移動設備的東西。

廣義上這些都是計算機使用 agent，通過和人類相同的圖形界面來操作。它們以截圖作為輸入，執行的動作也和人類是同一類：點擊、滾動、滑動、點按等等。關鍵區別在於它們和人類在完全相同的空間裡操作，這讓建模和評估方面出現了很多有意思的問題和挑戰。

大體上，CUA 按下面的方式運作。你有一個用戶任務提供給模型，你還有環境觀測，通常是一張截圖，就是你電腦屏幕或手機上當前顯示的內容。它也可以是其他基於文本的表示，但大體上大多數前沿 CUA 都用截圖表示。這基本上就是用戶自己做這個任務時會看到的東西。這兩個輸入都進入模型，模型通常會產生一段推理軌跡，也就是思維鏈，然後產生它想執行的下一個動作。這個動作可以是在環境裡允許的任何動作，比如點擊、滾動、打字等等。我們接著處理這個動作，在你環境的基礎設施裡執行它。如果是點擊，就真的在電腦上執行，執行後會得到新的觀測。

舉個具體的例子，任務可能是幫我買一個藍色馬克杯。你可能有一個初始的環境觀測，比如來自瀏覽器，這些會輸入到計算機使用 agent 模型裡。模型可能產生這樣的推理：我看到屏幕中央有個藍色馬克杯，我要點它，然後它會生成一個格式化的待執行動作。這裡它想對環境做一次左鍵點擊，我們在環境裡執行這個動作，也就是真的在環境裡點某個位置，然後得到執行動作之後的新觀測。比如這裡你會得到一張新截圖，這是 agent 已經點擊了那個藍色馬克杯，新觀測會顯示它的詳情。模型接著接收這個新觀測，基於更新後的觀測產生新的待執行動作。它可能會說配送信息在下面，我要往下滾動去找，然後生成這個滾動動作。我們再次在基礎設施裡執行，你又得到新觀測，就這樣重複，直到模型認為任務完成。根據任務複雜度，這個過程可能疊代很多很多次。

好，你從一個觀測開始，模型執行一個動作，你得到新觀測，如此重複直到結束。通常你會得到某種獎勵，來自環境、人類用戶或某個評審，告訴你模型做得成不成功。通常這個獎勵就是 0 或 1 的二值獎勵，但有時也可以是某些情況下的部分獎勵。大體上計算機使用 agent 就是這麼工作的，就是這樣一個觀察、推理、行動的循環，不斷重複，直到模型用完預算或者它認為任務已經完成。

今天看起來很簡單，模型也確實很強，後面幾頁幻燈片會看到。但情況並非一直如此，我們不妨做個快速調查。大家覺得計算機使用 agent 最早何時出現？有人覺得是 2020 年之前嗎？好，有幾位舉手。也就是 2020 到 2024 年間我們開始構建 CUA？好。那誰覺得是 2024 年之後？答案其實是第一篇 CUA 論文 2017 年就發表了。按 AI 的標準，這已經相當古老了，對吧？那是 OpenAI 的論文，有個 World of Bits 項目，他們構建了一個非常簡化的玩具環境。可以看到基本都是合成數據，環境非常簡化，看起來有點像手機上的界面，但極其簡化，完全不真實。這篇論文做的是，其實是做了大量 RL 訓練，這和現在的 LLM-RL 不太一樣，更接近我們過去為遊戲 agent 做的 RL。我覺得這個項目超前於時代，當時的模型完全做不了這種任務，連簡化的 Mini World of Bits 都做得很差。

這大概就是第一篇 CUA 論文。2022 年隨著語言模型興起，關注度開始上升。後來有篇叫 WebShop 的論文，也做了簡化的購物環境。如演示所示，它比 Mini World of Bits 真實得多，就是在模擬的亞馬遜網站點擊。雖然有點假，但比 Mini World of Bits 好多了。此時語言模型 agent 開始在這些任務上起色，而且當時沒像 Mini World of Bits 那樣訓練它們。

2022 到 2024 年間，CMU 實驗室有一項我認為是開創性的工作叫 WebArena。該項目建了很多模擬環境，比 WebShop 和 Mini World of Bits 真實。裡面包含非常真實的數據，通常是從真實網站抓取的。這些環境填充了來自亞馬遜、Reddit 等網站的真實數據，數據和環境都非常真實。我認為這也標誌著模型開始在這些問題上有所進步。

2024 年幾乎同期還發布了一個叫 OSWorld 的基準。我認為這是如今最標準的計算機使用基準之一。它同樣用真實應用和真實數據，但針對的是桌面操作而非網頁瀏覽，更通用，支持 Linux、Windows 等系統。這和 WebArena 不同，WebArena 是網頁瀏覽，OSWorld 則是完整的桌面操作。

2025 到 2026 年，情況又有了些變化。這是編程 agent 變強了很多，很多人開始端到端地生成環境。WebArena 和 OSWorld 的做法是拿這些應用的開源實現再填入真實數據，但所有軟件都是人寫好並開源的。Mind2Web-Bench 和 2025 到 2026 年前後的其他一些基準，則是用編程 agent 端到端地生成整個應用和網站。這裡展示的是一個 Gmail 克隆，外觀和真的非常接近，它完全是由一個 LLM 編程 agent 生成的。這裡預置的數據也全是合成的。可以說很多前沿 CUA 環境如今已經完全是生成的，數據也全是合成的。而且它們效果很好，有時甚至比真實應用還好，因為更乾淨、噪聲更少。

GUI World 也是 CMU 的項目，用的是真實軟件。我覺得 GUI World 很有意思，因為它用的軟件更偏長尾，比如天文學、生物學等領域使用的軟件。它從消費級應用延伸到了非常專業的桌面軟件。這裡的數據我認為也是真實數據，是從真實使用場景下載的，然後加載到這些環境裡。

好，這裡展示的是本月剛發布的一個演示，是 GPT-4o-extra，它在計算機使用上是一次巨大飛躍。我認為它基本解決了大多數計算機使用基準，目前已超過人類基線。它比之前的模型快了不少，但仍然很慢，很貴。演示的是 GPT-4o-extra 操作 CAD 軟件，它在做 3D 建模，畫面加速了 30 倍。實際上這個模型比你看到的要慢 30 倍。

重點是它能力很強，但依然又貴又慢，所以還有一些研究問題待解決。不過就能力而言，現在的模型已經很強了。你看，我們從 Mini World of Bits 的玩具環境，到 9 年後的今天，有了 GPT-4o-extra 在大量計算機任務上達到或超過普通人類的水平。進展非常快，令人興奮。

如果從研究或學術的角度看，我們可以想想該怎麼衡量這些問題。基準測試是衡量這些 agent 進步速度的核心手段之一。下面我們概覽幾個計算機使用基準，看它們衡量 agent 的哪些方面，agent 的表現。那麼想想該怎麼衡量計算機使用，其實比這門課講過的其他 agent 更有意思一些。從某種意義上說，計算機使用比起軟件工程或數學更難驗證一些。在軟件工程或數學裡，你有單元測試或符號驗證器能告訴你任務是否成功完成。計算機使用就不一樣了，因為一個任務算不算成功完成，就連人們自己通常也意見不一。所以寫程序化的驗證器會很有挑戰。

我們評估計算機使用 agent 有幾種方法。針對這些基準，最直接的一種是看動作本身對不對。比如可以衡量一次點擊是否點在了正確的元素上，也可以衡量結果。最端到端比如給它任務：幫我買個藍色馬克杯，然後衡量它是否真的買到了這件商品。這可以通過兩種方式：如果有模擬環境，就檢查環境狀態；或者看 agent 的軌跡，判斷它是否提供了足夠證據表明完成了任務。最後還要衡量模型是否遵守了任務中隱含或明確給出的約束，比如你可能要它進到結賬頁面，但不能真的結賬。所以還要有別的驗證器，確保它完成任務時遵守了各種用戶自定義的約束。

所以我認為評估 CUA 總體上非常有挑戰性。今天我們會講幾大類評估方法，大體上我把它們分成了四個類別。

第一個要講的是靜態評估。回到我們的任務：把一個 20 美元以下的藍色馬克杯加入購物車，但不要購買。靜態評估衡量 agent 軌跡上的每一步動作是否正確。比如你可能從這個截圖開始，agent 會嘗試點擊這裡的藍色馬克杯。我們可能有標準答案，比如要求 agent 預測的 XY 坐標落在目標框內。如果預測落在目標框內，比如這個紅框，就得一分，否則就得零分。意思是它在這一步沒有執行正確的下一個動作。所以對靜態評估來說，我們看的就是動作，對不對？看它每一步是否產生了正確的動作，因為它是靜態的，你沒法讓 agent 端到端地跑起來。我們只考察每一步的動作，判斷它是否成功完成了當前動作。

這個領域一個經典的基準叫 Screenspot-Pro。Screenspot-Pro 是 grounding 基準，測截圖動作定位。它涵蓋各種應用和操作系統，大約有 1500 個不同的截圖樣例。這裡的評估指標是逐點準確率。比如這個構建 UV 球面網格的任務，你看到的是一張 Blender 截圖。這只是一張截圖，不是真實環境，agent 沒有任何可交互的環境。它只拿到這張截圖，目標是判斷它產生的動作是否落在這個紅色邊界框裡。如果它預測的點擊落在這個邊界框內，就算動作正確，否則就算錯誤，不給任何獎勵。

靜態基準的另一個例子是 Mind2Web，它測試更多樣的動作。你可以把它理解為下一步動作的模仿，給定當前截圖和任務，比如在布魯克林中心租一輛車，我預測 agent 下一步動作。這個例子裡標準答案是點租車標籤頁。這個任務裡不會真正執行任何動作，你會拿到一系列截圖，agent 要根據截圖預測下一個動作。預測出動作後我們給它打分，然後從離線數據集裡給它下一張截圖。所以這同樣不是真的在環境裡執行動作，這裡根本沒有環境，它就是一組靜態截圖和標準答案動作。可以想見這種評測跑得很快，成本很低，因為你不用搭建環境或模擬器，你只要給它截圖，然後看它預測出的動作是否落在標準答案集合裡。

但可以想見靜態評測有個問題，會出現很多假陰性。意思是對同一張截圖和同一個任務，其實有很多不同的動作都可以算對。比如不一定要點租車標籤頁，可以先調日期，這同樣算一個有效動作。但在靜態評測裡，因為標準答案是固定的，這些動作會被判為錯誤。這是靜態評測的主要缺點之一：很快，但沒測到你真正關心的東西，也就是真正的端到端表現。我們真正關心的是 agent 最後有沒有把事情做成。

這就引出第二類評測：端到端評測。還是看這個例子：買一個 20 美元以下的藍色馬克杯。我們讓 agent 在環境或真實網頁執行任務，最後我們可以通過某種方式檢查它做得對不對，比如程序化的單元測試式檢查。

举个例子，agent 可能已经尝试了这个任务。在轨迹结束时，我们运行这些单元测试，看它是否真的完成了。这是在模拟环境里做的，我们可以通过 API 访问环境的全部后端和状态。我们可以检查马克杯是否在购物车里、是否低于20美元，以及 agent 是否没有真的下单，也就是检查订单数是不是0。只有所有单元测试都通过，才给它1分的奖励。

这本质上就是程序化检查。这时你确实有一个环境，agent 想怎么操作都行。我们不检查 agent 每一步执行的具体动作，而是检查它最后有没有靠这些单元测试真正完成任务。如果单元测试足够全面，这就是很好的奖励信号，因为我们不用监督模型的每一个动作，只在最后看它做没做对。

WebArena 就是最早这么做的基准之一。WebArena 是一个模拟网页导航基准，它包含几个环境。在 WebArena 搭载的4个不同应用上，大約有800个任务。Agent 要执行这全部800个任务，最后用我们刚才说的程序化验证器检查它做得对不对。比如目标是建个叫 awesome-llm-reading 的空仓库，agent 会进入这个模拟的 GitLab 仓库。重点是这是本地搭建的模拟环境，在 WebArena 里，agent 任何时刻都不会访问真实网页，只能在模拟环境里设法完成目标。

任务结束时，我们运行程序化验证器检查一堆条件，本质上就是看它有没有成功创建这个仓库。这些验证器都是手写的，其实是 CMU 的研究生写的。他们为 WebArena 里的每个任务都手写了验证器。假设学生们写得没问题，那么执行结束后，你就有了个验证器能告诉你 agent 到底成没成功。

由于验证器不够全面，还是会有一些假阴性和假阳性。但总体上这是个很不错的基准，它确实让业界开始更认真地对待计算机使用 agent 的评测。和之前的静态评测对比很重要，因为它测的是真正的端到端表现。你只看结果，不关心具体步骤，只要 agent 做对就行。但会有 reward hacking（奖励作弊），agent 可能会想办法骗过验证器，而不是真的去做那件事。这是大多数 CUA、agent 评测乃至训练中的常见问题。但现在 agent 评测上是巨大进步，它们确保任务在模拟沙箱里完成，而且衡量的是结果，而不是单个步骤。

VisualWebArena 是 WebArena 的扩展，它把这个问题当作多模态问题来处理。WebArena 发布时，大多数模型处理 CUA 或网页浏览任务用的是 accessibility tree（无障碍树），算是 HTML 的简化版。VisualWebArena 则想让大家相信该用截图方式操作。VisualWebArena 是 WebArena 的扩展，包含910个视觉定位任务，所以 VisualWebArena 里的问题都得用多模态表示解决。评测方式有点类似，同样有程序化的检查，但还加了些多模态程序化检查，有些问题只靠 HTML 解不出来。

这类基准的另一种评测方式是不程序化验证器，而是用另一个 LLM 来判断模型有没有把任务做对。拿到模型轨迹后，你去 prompt 另一个 VLM 或 LLM，即文本或多模态视觉语言模型，把模型的轨迹喂给它，问它任务有没有成功完成。这也是很常用的评测方法，因为你不可能给每个关心的任务都写验证器。这种情况下，你同样拿到 agent 完成的轨迹，但不用程序化验证器，而是给一组 rubric 评分细则，或干脆直接交给 LLM。你把 agent 的轨迹和任务一起给它，LLM 就会告诉你它认为 agent 有没有成功完成任务。

这些裁判通常先输出一小段思维链，再给出判断，比如通过或不通过，有时也打浮点分数，但一般就是告诉你通过还是不通过，这样更通用，因为不用给基准里的每个任务都写验证器。但它也更容易出现误判，因为你可以想象，LLM 裁判很容易被糊弄，以为任务完成了，其实并没有。不过总的来说，这种方式灵活得多。

采用这种裁判方式的基准包括 WebVoyager，它是最早测试 agent 在真实网页上导航能力的基准之一。这和 WebArena 很不一样，他们选了15个不同的网站，在上面设计了600个任务，要求 agent 真的上这些网站去完成目标。实际上去看基准里的网站，比如 Allrecipes 食谱网站，看 agent 的某些任务，你能在真实网页上看到之前 agent 试过的痕迹。这其实不太好，但也说明了为什么我们可能不想在真实网页上评测 agent。

不过 WebVoyager 还是很有价值，因为它测试了 agent 在非模拟环境下的能力，这基本上是最接近真实世界评测的方式了。让 agent 真的去网页上做这些事，比如找 star 数最多的气候变化数据可视化 GitHub 项目，他们让 agent 真的去 GitHub 上做一堆搜索，找出这个任务下 star 数确实最多的仓库。这种情况下，因为是在真实网页上，你没法用程序化验证器，因为你没法查询真实网页的状态。所以这里的评测就是我们说的 VLM 裁判。这个裁判是另一个 LLM 拿到 agent 执行的一系列动作和观察到的截图，它也拿到原始任务，看任务和 agent 做了什么，然后判断 agent 有没有成功。这个任务用 VLM 裁判来评，没有程序化验证器。你可以把它想象成相当狂野西部式的 eval，把东西部署到真实网页上跑一个裁判，最后告诉你成没成功。但很多人喜欢这种方式，因为它在某种程度上是最接近真实世界的评测。

Online-Mind2Web 是继 WebVoyager 之后的另一个 eval，它更全面一些，裁判也更强。他们证明裁判和人类的一致率大约是85%，这已经非常接近人类水平的裁判一致性了。Online-Mind2Web 本质上也是真实世界评测，他们扩展到大约136个网站、300个任务，让 LLM 上这些真实网站去完成特定任务。他们证明用这个裁判比 WebVoyager 的裁判更准确一些。他们的裁判更复杂，带不同 rubric 评分细则和标准。但本质上它同样上真实网页，也就继承了上真实网页带来的很多问题。和 WebVoyager 类似，不过它仍是个很好的 eval，因为某种程度上最接近真实世界的评测。整个流程全自动化，一个 LLM 在真实世界执行任务，另一个 LLM 评判。而且因为裁判非常接近人类评测，你就用了一条自动化流水线：LLM 在真实世界里做事情，再有一个接近人类的裁判来判断成没成功。所以我觉得这是个很好的基准，非常自动化。

不过现在人们已经不太用它了，因为它基本上已经被现代模型解决了。而且随着计算机使用 agent 越来越流行，大家在把它们部署到真实世界时也更谨慎了，因为这些网站的主人可不喜欢一大堆 agent 反复访问他们的网站跑基准。你可以想象，如果你的网站被收进这个基准，流量突然暴增，你大概也不会高兴。

对了，有一点很重要：我们讲过的这些评测指标，要么是程序化验证器，要么是 LLM 裁判，它们本质上都是 proxy 指标，用来判断我们有没有成功完成任务。但人工审查，也就是让人来判断 agent 做得怎么样，可能仍是黄金标准。这些论文也做了人工评估基线，让人类来审查 agent 的轨迹，每条轨迹找几个人判断 agent 是否成功了，最后再让几个人投票看 agent 到底成没成功。这在某种意义上仍是判断 agent 是否完成任务的黄金标准。但这样成本很高，不可能对基准里的每个任务、每次排查或验证运行都这么做。不过大多数基准的创建者还是会这么做，找人来尝试或评判任务，确认 agent 做得对不对。但这非常贵，所以一般只做一两次，确保你的 agent 或基准本身是合理的。

好，我们接着往下讲。另一类常见的评估也是端到端评估，但它们是在桌面或移动设备上做，不是网页。网页很有意思，因为能在上面做很多事，我个人大部分时间也花在 Chrome 上。但还有另一类任务要求你去操作一台真正的虚拟机或真正的桌面，也有好几个基准以端到端方式来衡量这一点。

我们前面讲过 OSWorld，它是最经典的 CUA 基准之一。这是一个可以启动的真实 Linux 虚拟机，包含大约369个任务，分布在9个不同的应用上，比如 GIMP、LibreOffice，还有 Chrome 等等，就是9个应用上的369个任务。每个任务也都有程序化验证器，agent 得进入这些虚拟机跨多个应用尝试完成任务。最后我们跑一些类似单元测试的检查，看它有没有成功。

OSWorld 里的任务举例来说，比如你要更新这张 LibreOffice Calc 表格，用的是另一文件夹里的收据。agent 得先导航到那个文件夹，找到收据，把对应的数值填进这个工作簿里，还要保存工作簿。它得在不同应用之间来回操作，在 LibreOffice 里录入这些条目，也就是说只凭一句初始用户指令就完成整个任务。等 agent 觉得做完了，我们就跑这些单元测试。我们会检查表格里是不是有我们认为该有的条目，然后同样给它打0或1的分数，看它是否成功。所以精神上跟 WebArena 很像，但这里用的是真实应用，这些都是人们日常真正用的应用，同样运行在完整虚拟机里。它不再局限于 Chrome 或网页，而是在包含9个应用的整个虚拟机里运行，所以它的覆盖面广得多。可以想见桌面 agent 能自动化的任务种类会比只用网页浏览 agent 多得多。

Windows Agent Arena 是另一个基准，灵感来自 OSWorld。这是微软创建的基准，用来测试 agent 在 Windows 机器上的表现。毕竟世界上很多实际工作就是在 Windows 机器上完成的。我觉得这个基准挺不错，因为它衡量 agent 能不能完成，这些任务在企业工作流或各类公司里非常常见。对，这里同样是你启动一台 Windows 虚拟机，让 agent 去尝试任务，最后用一些验证器来判断它做得对不对。而且同样因为用的是程序化验证器，有些也很容易出现假阳性或假阴性。不过它们和 LLM 裁判一样，各有优缺点。

这些基本上就是2024到2025年间大家探索的核心端到端 eval 基准。对，这些基准大多数其实已经被现代 CUA 解决得相当好了，比如最近发布的 GPT-4o-extra，在大多数基准上的成绩已经远超人类。所以社区最近其实把注意力从刚才这些基准上移开了一些，开始关注更长时程、更专门的基准吧，长时程计算机使用，其实任务类型还是一样的，但我们关心的问题时间跨度要长得多。有些任务真人要花几个小时，甚至两三个小时或更久才能完成。所以现在我们是在真正压测 CUA，让他们去做人类其实不想做的事，或者说我们让他们完成越来越长的任务。OSWorld、WebArena 里很多任务，人类大约10到20分钟甚至更短就能完成，但接下来几张幻灯片里的一些任务可能要花好几个小时，还要操作专门的软件。所以我们正朝着让 agent 超过人类专家用电脑的水平迈进。

很多这类长时程基准都采用非常相似的评估策略。你会有一个动作轨迹，记录 LLM 在这个环境里执行过哪些动作。还有几种不同检查。任务很长，人们更倾向用基于 rubric 评分细则的方法。只用一个最终结果奖励来判断成败，对长时程任务不太有用，因为信号太稀疏。奖励非常稀疏，agent 中间可能做了很多有用的工作，最后却拿不到满分。所以长时程计算机使用需要更细粒度的奖励。

这里有几种检查，状态检查就是我刚才说的阶段性奖励。它们类似基于 rubric 评分细则的奖励，检查 agent 是否完成某个中间任务。还有一种过程奖励，检查 agent 是否完成了整个任务，也就是端到端成功完成。这相当于最终奖励，但还需要一些中间奖励来保证长时程计算机使用有非零的信号。当然，你也可以对 agent 是否成功完成任务给出最终判定，但同样因为看的是长时程计算机使用，信号非常稀疏，很多模型的最终奖励常常拿零分，所以你需要中间的 rubric 评分细则或过程奖励。对，还有很重要的一点正如我提到的，最终交付物好并不总是长时程计算机使用的好指标，因为任务太长了，所以你需要一些阶段性奖励来确保模型一直在做有产出的事情。

Odyssey 是我们在 CMU 做的基准，衡量长时程网页浏览。Odyssey 包含200个任务，每个任务都有 rubric 评分细则，也就是我们认为模型应该完成的一组事项。比如这个任务：规划一趟去棕榈泉参加婚礼的行程。模型要满足8条 rubric 评分细则才能拿满分。比如你要找到一条从匹兹堡到洛杉矶的直飞航班，你还需要找到在上午9点到下午4点之间的车程，还有一堆这样的条件都要满足，才能成功完成任务。所以 Odyssey 是按多条 rubric 评分细则打分，这样你就能拿到部分奖励，而不是最后只有一个二元的通过或失败。

好，问题是CUA的动作空间到底是什么？这个我们很快会讲到，过几页幻灯片就说到了。本质上这因模型而异，也取决于你想把模型部署到什么环境里。

好，那CUA是怎么表示的？你可能已经猜到，和如今大多数AI模型一样，CUA基本上就是个LLM。它以特定格式接受输入，按特定方式prompt。更具体地说，它通常是视觉语言模型，因为大多数模型都以截图作为输入。目标通常用自然语言表示，抱歉又用同一个例子，目标可能是帮我买一个20美元以下的蓝色马克杯。另外还有一张初始截图，截图取决于环境最初的状态。所以你有目标和截图两个输入。这些输入进入你的策略，策略本质上就是一个LLM，然后LLM产出一个动作，通常以文本形式表示。LLM用文本生成它想执行的动作的结构化表示，比如一个带 $x, y$ 坐标的点击动作。接着我们执行这个动作，我们把它加进下一步喂给LLM的上下文里。执行后还会得到新截图，也就是在截图0上执行动作1得到截图1。我们再把它拼接到已有上下文里，再喂给LLM，它产出下一个要执行的动作。然后我们再截图，以上再执行这个动作，又得到一张新截图，拼进上下文再喂给LLM。就这样重复，直到LLM觉得做完了或者预算用完了。

对，这就是那个循环，通常叫ReAct循环，即推理加行动。每一步你都把产出的动作拼接进去，连同新截图一起加进不断增长的上下文，再喂回LLM。所以这是一份视觉语言交错的动作历史。你有自然语言形式的目标和动作，也有像素输入，可能还有其他元数据。这些内容本质上会被拼接成一条很长的序列，一条很长的多模态序列，然后喂给你的语言模型。这个序列会越来越长，人们有各种办法处理越来越长的上下文，但本质上你就是把上下文每一步都喂给LLM，由它在当下生成下一个动作。当然不是直接喂原始像素，大多数语言模型都会先做tokenize，你会把自然语言切分成文本token，把截图转换成视觉token或者某种基于像素的表示。现代语言模型的好处是这些通常直接拼接起来就行。对模型来说，看起来就是每一步都有一堆embedding被喂进去，模型产出一个动作，你把它tokenize之后拼到上下文里，就这样不断重复。每一步喂进去的token越来越多，模型每一步接受这些输入，以上下文为条件生成下一个动作，然后不断重复。我觉得这是一种非常简洁优雅的表示方式。

效果出奇的好。文本会转成token embedding，截图会转成视觉embedding，而这些最终都会整合到一起，交错拼接在一起传给语言模型。如今语言模型就是Transformer，很显然，由它来生成下一轮的动作。

回到刚才的问题，CUA通常用什么动作空间？不同模型的动作空间各不相同。粗略看的话他们大体相似，一般都有一组可以输出的动作，比如点击、滚动或者你环境里有的其他动作。不同模型输出动作的格式略有差异，比如可能输出成PyAutoGUI的指令，也可能输出成工具调用或XML，然后你需要解析它，传给能在环境里实际执行的东西。

说到训练模型，其实大多数计算机使用 Agent 都是基于预训练的视觉语言模型。训练分几个不同的阶段。显然，当你把 GPT-6 部署成计算机使用 Agent 的时候，你部署的并不是——你部署的不是只会计算机使用的 GPT-6 专用版，它是一个通用模型，计算机使用只是它的能力之一，而且大家越来越倾向于这么做。

计算机使用的专项训练分几个阶段：首先是预训练阶段，模型用大规模互联网数据来训练。CUA 专用数据通常以几种格式注入，比如 grounding 数据，它是引导模型去学习在截图中定位信息。这类数据通常长这样：有一张截图，再加上一串边界框和对应的坐标。模型在这里要学的是 grounding 能力，它学到的是想点某个按钮，就得给出这样的 $(x, y)$ 坐标。它学的就是最基础的能力，比如定位、grounding 等等。

另外还有一些即时动作形式的数据，这其实跟我们讲过的静态预报很像。你有一些截图，还有一些高层任务，目标是预测下一步要执行的动作。这同样是非常嘈杂的数据，甚至可能是合成生成的。但预训练阶段的目的只是引入某种定位和 grounding 能力。CUA 之后需要这些能力，才能给出准确的点击和其他类型的动作。

预训练之后，通常就进入后训练阶段。如今这一步通常和其他模型能力混在一起训练，但为了简化，我们先假设只关心 CUA。后训练阶段有两个步骤：第一步通常是做 SFT（监督微调），让模型模仿人类演示计算机使用任务的过程。你可以收集大量人类演示，或者从别处爬取一些。这些数据跟我们见过的轨迹很像。人类看到一张截图，然后做出某个操作，你把这个动作记录下来，可能是人类的一次点击，用专门的软件录下来。这样你就有了大量人类演示。本质上就是由一些人去记录人类做 CUA 任务的过程。

现在也常混入合成数据，比如 prompt 你的 Agent，或让更强的模型去做任务，然后保留你认为质量好的轨迹。这些数据由另一个模型或同一个模型合成生成，你也把它混进去。这种数据通常比人类数据质量低一些，噪声更大，但可以大规模生成，不需要人力来产出。所以在后训练阶段加入模型合成的数据，总体上还是相当有用的。

更有意思的部分是在后训练的 SFT 阶段之后，你的模型就初步具备了 CUA 的能力。SFT 后 prompt 一下，多数 CUA 任务做得很不错。更有意思的阶段是一年前还不常见，但现在 CUA 普遍都会经历一个强化学习阶段。具体做法是把 CUA 放进模拟环境或真实世界，给它一件事做，它就去做那件事。比如试着买蓝色马克杯，奖励可能来自 rubric 评分细则、验证器，或让 LLM 当裁判。总归用某种方式给它奖励，然后做强化学习来强化那些成功的轨迹。这挺有意思，因为这些任务没有人类演示，你就是把模型放进沙盒里放开跑，它尝试各种做法，从成功和失败中学习，然后不断重复这个过程，直到它能成功完成任务。现在大家对 RL 都非常兴奋，但其他阶段也很重要，它们保证模型有扎实的基础去做 RL。

我们更详细地讲讲各个阶段。预训练阶段，就像我说的，你会有这些截图。这些预训练数据的目标就是学会非常基础的能力，比如学会 grounding 能力。给定截图，模型通常被训练去预测一段很长描述的下一个 token，本质上就是在预测页面上各元素的位置、这个卡标签。模型要预测 $(x, y)$ 坐标或边界框、宽度和高度。所以这是很嘈杂的数据，但你可以想象能大规模拿到海量这种数据，比如这些截图数据来自具体的网站，边界框和 grounding 易生成，跑个 JavaScript 脚本能提取全部边界框。这类 grounding 数据很容易大规模收集，所以非常适合预训练。预训练正需要大量带噪声但体量大的数据。

人们有时还会收集另一类数据——动作预测。比如同样从 HTML 页面里你可以拿到元素名称或元素元数据，把页面上某些东西的，你也可以把这个作为输入喂给模型，让它再预测对应的 $(x, y)$ 坐标。这更偏于易理解，给它一个 HTML 元素，它要预测想做什么、想点哪里。同样，这些都是非常底层的能力，其实就是在教计算机使用 Agent 理解截图、定位页面上的各种元素。基本上就是学会理解截图、学会定位，也就是知道元素在页面上的位置，还能学元素之间的关系，比如知道租车按钮在酒店按钮右边，这类关系可能会以某种方式进入预训练数据。这类数据通常大规模生成，混入前沿模型预训练的早期阶段，让 Claude 之后学 grounding 和动作生成更轻松。

预训练之后，下一个阶段大家一般叫它后训练。这里同样忽略其他数据，只看计算机使用 Agent 的数据。这通常有两种形式：一种是人工数据，你付钱请一批人来标注轨迹。给个任务，找 3 小时能做完的墨西哥炖肉塔可食谱，然后由真人通过浏览器实际去完成这个任务。这里的例子来自 Mind2Web，他们收集了大约 36,000 条人类轨迹，他们收集了 36,000 条人类完成类似任务的演示，比如上网做各种操作，每一步都记录截图观察和人类的动作。最终你就得到一堆截图、动作、截图、动作这样的轨迹。他们还生成了一批合成轨迹，这个我们稍后会讲。

开源 CUA 数据集 Mind2Web，还有 AgentNet，这两篇论文本质上都收集了人类演示，都是这些任务的人类演示。这是训练计算机使用 Agent 模仿人类行为的好方法，也就是让模型以截图为条件预测序列中的下一个动作。

当然，如今这部分训练也可以生成一些合成数据。Mind2Web 是把网站的 Accessibility Tree（无障碍树）喂给模型。这个前面的问题里提到过，给模型元数据，它们的表现会好很多。他们有个训练过用 Accessibility Tree 的模型，然后把简化的 HTML 表示给模型，让它在 Accessibility Tree 空间里 rollout 动作，并收集同样的一批轨迹。这样你就拥有了一个在使用特权信息的模型，这些信息在实际评测和推理时是拿不到的，所以它比只用截图输入时表现好得多。Rollout 这个模型收集了约 10.5 万条合成轨迹。而且不是所有轨迹都会保留，你可以审视这些轨迹，按某种指标只留下质量较高的，比如用另一个 LLM 来评判或者用人工来筛选。

轨迹就是这样收集的，要么靠人类演示，要么靠合成数据。关于这种用特权信息做合成数据的方式，我很喜欢一个类比。我不确定是不是真的，但我听说 Tesla 在训练阶段，他们部署了装有 LiDAR 的车，这些车显然是在做自动驾驶，有三维 LiDAR 信息表现会好很多。他们收集这些轨迹，然后丢掉 LiDAR 信息，只训练模型使用像素信息。相当于有一个老师，用的信息比推理时能拿到的要好得多。我觉得很多计算机使用 Agent 应用里，大家也试过注入元数据或额外信息来收集更好的轨迹，所以我觉得这是引入合成数据的一个很好的方式。好。

大家应该能明白为什么 RL 需要模拟环境。很多任务我们并不想在真实世界里反复执行，比如你在 Uber 上订机场接送，订几次就会被封号或者钱花光了。所以你需要模拟环境来做强化学习。有几个基准就是针对强化学习这个范式设计的，我就不详细展开了，大家可以在幻灯片里查阅。

好，我们讲了 CUA 是怎么训练的。通常有几个训练阶段：预训练，后训练对人类演示和合成数据做行为克隆，最后还有点睛之笔的一步——模型强化学习阶段，也就是在模拟环境里运行，从环境中获取奖励。走完这套流程就得到强大的 CUA。大体上这就是如今多数实验室训练 CUA 的流程。

CUA 和其他 Agent 有些不同。它们很棒的一点是直接在和人类相同的界面上操作。评估 CUA 很棘手，人们也探索了一段时间，关键是要选对指标和行为层面。跨模态的设计是从交错的视觉历史中预测动作，上下文里交错着截图和你之前执行的动作，模型要基于这些来生成下一个动作。

模型训练分多阶段：先用大规模含噪数据预训练，然后是 SFT，对人类或合成演示做行为克隆，最后是 RL 阶段，让模型在模拟环境里自行探索，好的行为给奖励，坏的行为给惩罚。今天能讲的内容大概就到这里了，不过我建议大家去看看幻灯片，里面还有关于 CUA 未来可改进方向的一些看法。我觉得速度仍然是个问题，个性化则是很有潜力的研究方向，基础设施和用户体验也是大问题。另外我对多 Agent 系统也很期待。好，谢谢大家听我讲，剩下的时间欢迎提问。谢谢。
