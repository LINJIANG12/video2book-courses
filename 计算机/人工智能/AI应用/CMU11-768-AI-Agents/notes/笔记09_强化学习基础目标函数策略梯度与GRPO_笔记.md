# 强化学习基础：目标函数、策略梯度与 GRPO

## 强化学习三讲与作业三

   * **三讲编排**
       * 第一讲：基础的策略梯度方法，让 agent 与环境交互、获得反馈，据此更新权重，让拿到高奖励的行为更可能出现、拿到低奖励的行为更少出现。
       * 第二讲：更高级的强化学习算法，涉及离策略方法，以及要让强化学习稳定跑起来需要做哪些事。
       * 第三讲：强化学习系统，深入讲实用的框架、训练这些 agent 时需要思考和注意的东西，以及超参数。
       * 强化学习是本课程强化学习三讲中的第一讲，承接 agent 的监督微调（SFT）。

   * **作业三**
       * 目标是在两种设定下用强化学习训练模型。
       * 设定一：简单的沙盒环境 number search，本课拿它当贯穿全课的例子。
       * 设定二：简单合成环境，有点像 Minecraft。
       * 这两个作业比之前的作业需要更多算力，因此会更多地使用算力额度。

## number search

   * **number search（数字搜索）**
       * > **定义**：根据「太高了」还是「太低了」的反馈来猜出一个数字的强化学习任务，用来把强化学习的第一性原理一步步搭出来。
       * 环境里有一个 1 到 16 的整数，agent 不知道它是多少。
       * agent 最多有 4 次机会猜。
       * 每次猜完，猜对了环境说「正确」，否则说「应该猜高一点」或「应该猜低一点」，然后可以再猜一次。
       * 只要任何一次猜对，任务就结束，奖励为 1；4 次都猜完还没猜对，奖励为 0。
       * 任务小到可以手算，同时足够简单、对错一眼可见。
       * > **提示**：做强化学习需要一个能一眼看出对错、又足够简单的环境，先在上面把「轨迹—奖励—更新」整条链路走通，再去面对网页和代码库那种复杂环境。

   * **典型轨迹**
       * 隐藏数字为 11 时的一条轨迹：

```text
隐藏数字 = 11（agent 不知道）

猜 8   →  反馈：高一点
猜 12  →  反馈：低一点
猜 10  →  反馈：高一点
猜 11  →  反馈：正确        ← 任务结束，R(τ) = 1
```

       * 另一种尝试可能从一个更小的数开始。

   * **起始猜测的优劣**
       * 最好的起始数是中间值，把搜索空间对半拆，先猜 8。
       * 这与 20 问游戏、以及从信息论角度缩小搜索空间的 Wordle 首次猜测是同一类想法。
       * 从次优的第一次猜测 4 开始也可以：只要把反馈考虑进去，先高一点、再高一点、再低一点，不断调整，最终也能猜对。
       * 从很糟糕的 16 开始：除非碰巧猜对，否则反馈都是「低一点」，4 次之内很可能超时，任务失败。
       * 从 1 开始、然后 2、3、4 的策略同样很差，最后超时、任务失败。

## 奖励

   * **奖励（reward）**
       * > **定义**：给一条轨迹打的一个标量分，用来说明这条轨迹是好是坏。
       * 轨迹奖励写成所有中间时间步奖励的总和：$R(\tau) = \sum_{t=1}^{T} r_t$。
       * 在最一般的设定下，每采取一个动作或得到一个观测都可能拿到奖励；在动作后给奖励和观测后给奖励这两种写法可以等价。
       * 在 agent 场景里，奖励可能对应「你写的代码在 SWE-bench 上是否通过了全部单元测试」：全通过奖励 1，没全通过奖励 0。
       * 也可以不是 0 或 1，即非二值奖励，比如通过测试的比例。
       * number search 里只有超时或收到正确反馈之后才拿到奖励，所以奖励是二值的，且只在轨迹末尾出现。

   * **可验证奖励强化学习（Reinforcement Learning with Verifiable Rewards，RLVR）**
       * 现在很多被训练的领域用的奖励都是 0 或 1。
       * 关键在「可验证」：判定器是一段确定性的程序，不是一个有主观偏差的评委，所以奖励信号干净。
       * 该方法更通用，同样适用于任意标量奖励——REINFORCE 的整条推导从头到尾没有假设奖励是二值的。

## SFT 目标与三处失配

### SFT 损失

   * **监督微调（Supervised Fine-Tuning，SFT）损失**
       * > **定义**：把一条轨迹拆成步骤，给 agent 一个 prompt、一次猜测、环境反馈、更多反馈……训练 agent 去复制这个示范。
       * 给定示范动作 $a^*$，最大化 agent 在此前全部历史条件下给这些动作分配的概率。
       * $$\mathcal{L}_{\text{SFT}} = -\,\mathbb{E}_{(H,\,a^*)}\Big[\sum_{t} \log \pi_\theta\big(a^*_t \mid H_t\big)\Big]$$
       * 等价于最大化整个序列概率的对数，也就是最大化各个动作概率对数之和。
       * 示范动作的来源有三类：亲自演示任务的人；想模仿、蒸馏的更强模型；agent 自己生成的轨迹——最后这一种是要在模型中被「强化」的对象。

### 任务失配

   * **任务失配**
       * SFT 最大化的是每个时间点上被示范动作的概率，真正关心的是最大化 agent 成功完成任务的概率；两者很接近，但并不完全一样。
       * 原因一：成功完成任务的方式不止一种。第一次猜 8 最好，但从 4 开始只要利用好反馈也合理；第一步反馈之后同样有多种合理的动作可选。示范不管来自人还是别的模型，都只展示了一种解法。
       * 原因二：有些动作比另一些差，但在 SFT 看来它们一样。收到「应该猜高一点」后输出一个小于 8 的数非常糟糕，而 SFT 不区分没被示范过的动作——它只惩罚「没照着做」，不惩罚「做得更差」。
       * 无论 agent 把最高概率给了一个更差的备选动作，还是给了一个更好的、只是没被示范的动作，损失都是一样的。
       * **优化目标**：真正想要的是最大化期望奖励，也就是任务成功的概率，而不是最大化某条特定示范的对数概率。

### 数据失配

   * **数据失配**
       * 希望从次优数据中学习：即便示范就是完成任务的最佳方式，如果还能拿到一些没那么好甚至失败的示范，它们也能给模型提供有用的信号。
       * 一条已知是坏的轨迹（比如超时），不会想直接对它做 SFT、最大化那些动作的概率，但希望有一种方法能让模型不再走出这样的轨迹。
       * 强化学习做到这一点：坏轨迹不是被模仿的对象，而是被压低概率的对象。

### 曝光偏差

   * **曝光偏差**
       * SFT 训练模型根据一段固定的动作序列预测下一个动作，这段序列来自人或一个更强的模型。
       * 到了评估时，之前的动作是由模型自己生成的，是与环境交互的自回归过程。
       * 如果 agent 产生的动作跟训练时见过的历史分布差得很远，它给出的响应可能就没校准好，因为它从没见过那样的数据。
       * 例子：只在「下一个整数总是符合反馈」的示范上训练，反馈说更高就猜更高；生成时如果模型犯错采样到更小的数，可能就完全乱了，因为它没见过「我刚才猜错了」这种历史。
       * 强化学习让模型自己生成训练数据并学会从自己的错误中恢复，这样在生成时就能应对自己的错误。
       * 模型自己生成训练数据这个特性叫在策略（on-policy）：通常是好事，它让模型准备好应对自己的错误，且得到的监督信号与模型当前能预测的东西很匹配；但在效率上可能有取舍。
       * 放宽这些假设、更偏向离策略的方法构成另一条技术路线。
       * **附带效果**：大概三四年前人们对语言模型有很多不满，比如有重复倾向、会卡在循环里出不来；后来把强化学习作为最后的后训练步骤，模型能从自己的错误中恢复，这些问题大多解决。现在各类推理模型里看到的「自我纠错」行为，本质上就是在策略训练的直接产物。

## 强化学习大图

   * **强化学习的思路**
       * 不再用一条固定轨迹来通过最大化动作概率去模仿它，而是让 agent 或模型自己生成动作，评估这些动作在轨迹中的奖励，再调整参数：让高奖励的轨迹更可能出现，低奖励的轨迹更少出现。
       * 形式上，训练 agent 最大化它的期望奖励，也就是在 agent 和环境共同作用下的概率期望。
       * 任务失配因此被解决：直接训练 agent 去最大化期望奖励。
       * 数据失配因此被解决：agent 能从所有轨迹中学习，从坏轨迹得到信号，以后避免采取导致这类轨迹的动作。
       * 曝光偏差也得到缓解：训练用的轨迹由 agent 自己生成，犯了错、发现错误导致奖励很差就会因此受罚，以后学会避免。
       * **代价**：得真的在环境里去尝试各种方案，可能开销很大，还会给梯度引入一些噪声。

```text
  agent（策略 π_θ = 语言模型）        环境（沙盒 / 网站 / 测试用例）
  ──────────────────────────          ───────────────────────────
  读历史 H_t，按 π_θ(·|H_t) 采样动作   执行动作 a_t
            │                                 │
            │  动作 a_t ─────────────────────► │
            │                                 │  跑测试、出页面
            │  观测 o_{t+1} ◄──────────────── │
            │  奖励 r_{t+1} ◄──────────────── │
            ▼                                 ▼
              轨迹 τ = (o_1,a_1,r_1, …, o_T,a_T,r_T)
                                │
                                ▼
                    环境给出这条轨迹的标量奖励 R(τ)
                                │
                                ▼
              用 R(τ) 给采样出来的动作的 log 概率加权 → 求梯度 → 更新 θ
                                │
                                └──────► 回到左上角，重新采样（策略已经变了）
```

## 记号与概率分解

### 策略、历史与轨迹

   * **策略（policy）**
       * > **定义**：agent 的行为模型，记作 $\pi_\theta$，其中 $\theta$ 是驱动这个 agent 的语言模型的参数。
       * 把历史输入 agent 框架，就得到下一个 token 的分布，这些 token 对应环境里的动作。
       * agent 生成动作的方式是从语言模型里采样，再把采样结果放到它运行的框架里执行，然后在环境里执行这些动作，环境返回观测和奖励。

   * **历史（history）与轨迹（trajectory）**
       * 轨迹 $\tau$ 是动作和观测交错组成的序列。
       * 历史 $H$ 是到某个时间步为止的观测和动作序列，$H_t$ 包含到那个时刻为止的所有动作和观测。
       * 很多设定只在任务结束时给奖励，比如真正执行测试用例的时候；但所讲的内容几乎同样适用于有中间奖励的设定——每采取一个动作都得到一些关于该动作价值的奖励。

   * **两类奖励写法**
       * 在最一般的设定下，每采取一个动作或得到一个观测都可能拿到奖励。
       * 在动作后给奖励和观测后给奖励这两种写法可以等价。

### POMDP 与三类设定

   * **部分可观测马尔可夫决策过程（Partially Observable Markov Decision Process，POMDP）**
       * 环境的状态（决定环境的一切）和 agent 能观测到的东西是两回事。
       * 例：web agent 里背后数据库的上下文是隐藏状态，agent 只能观测到当前所在的页面；它可以执行点击、输入、滚动这些动作，还可能拿到中间奖励，比如任务描述里的子任务它已经完成了多少个。
       * 经典强化学习里有马尔可夫假设，即转移到下一个状态只取决于当前所处的状态和动作。
       * 这里处理的是 POMDP：看不到的底层状态和能看到的观测有区别，下一个观测的概率必须依赖之前所有的观测和动作，因为拿不到状态本身。
       * 写公式时这一点不影响推导：用「依赖完整历史」来写总是合法的，它只是把马尔可夫性放宽了，对 POMDP 来说更好用一点。

   * **三类设定的抽象结构**

| 设定 | 任务实例 | 观测 | 动作 | 奖励 |
| :--- | :--- | :--- | :--- | :--- |
| 文本生成 | 想补全的 prompt | 目前已有的 token | 下一个 token | judge 模型给的分数（如 RLHF） |
| Web agent | 任务本身 + 网站 | 当前所在页面（背后数据库是隐藏状态） | 点击 / 输入 / 滚动 | 任务完成的 0/1，也可按子任务完成比例给中间奖励 |
| number search | 要猜的那个数（对 agent 隐藏） | 高一点 / 低一点 / 正确 | 下一次猜测 | 猜对 1，超时 0 |

### 轨迹概率的链式分解

   * **轨迹概率 $P_\theta(\tau)$**
       * > **定义**：一条轨迹的产生概率，由 agent 给出的概率和环境给出的概率两部分相乘而成。
       * 用链式法则把产生整条轨迹的概率分解成各组成部分的乘积：
       * $$P_\theta(\tau) = \prod_{t=1}^{T} \underbrace{\pi_\theta(a_t \mid H_t)}_{\text{agent 策略}} \cdot \underbrace{P\big(o_{t+1},\, r_{t+1} \mid H_t,\, a_t\big)}_{\text{环境的概率}}$$
       * 环境的概率这一项，是在给定历史、agent 在这一步采取的动作以及这个任务的条件下，得到该观测与奖励的概率。
       * 策略那一项是 agent 产生下一个特定动作的概率。
       * > **注意**：强化学习的关键在于不需要了解环境的任何信息——不需要知道下一个观测出现的概率，也不需要知道和网站交互时下一个观测的概率。通过执行动作与环境交互相当于从观测和奖励的分布中采样，这些信息就足够学会怎么求导。
       * > **注意**：只能靠执行动作去看会发生什么，这导致强化学习算法有点慢，也是强化学习需要大量算力的原因——得反复与环境交互、观察结果，再把它当作一种比较间接的反馈来了解奖励如何依赖参数。

## 期望奖励目标函数

   * **$J(\theta)$**
       * > **定义**：语言模型参数的函数，等于从该参数化分布中采样轨迹后所获奖励的期望。
       * $$J(\theta) = \mathbb{E}_{\tau \sim P_\theta}\big[R(\tau)\big] = \sum_{\tau} R(\tau)\, P_\theta(\tau)$$
       * 采样做法是从语言模型里采样动作，再把动作喂给 agent 的框架去执行，得到一条轨迹并评估其奖励。
       * 这是在一个非常大的空间上求和，比如语言模型所有可能的轨迹，几乎不可能精确算出，但如果想算结果就是这个形式。

   * **四条轨迹的数值示例**
       * 假设语言模型实际能产出的轨迹只有四条，说明它学到了一个非常尖锐的策略，四条轨迹的概率分别是 0.3、0.2、0.25、0.25。
       * 成功轨迹奖励为 1，失败轨迹奖励为 0，期望奖励就是把这些奖励按策略下的概率加权求和：$J(\theta) = 0.3 \times 1 + 0.2 \times 0 + 0.25 \times 1 + 0.25 \times 0 = 0.5$。
       * 训练就是调整参数 $\theta$ 最大化这个量：把概率质量从奖励为 0 的轨迹挪到奖励为 1 的轨迹上；当前策略有相当高的概率（0.5）产出奖励为零的轨迹。
       * 实际 agent 能产出的可能轨迹不是无限多，但也是组合爆炸级别的数量，这里的可视化做了简化。
       * > **提示**：0.3/0.2/0.25/0.25 是策略概率而不是均匀分布。正是因为它们由 $\theta$ 决定，$J(\theta)$ 才是可优化的对象——如果能写出 $J$ 的解析式并对它求导，强化学习就成立；如果 $\theta$ 变了但权重不变，$\theta$ 就根本无从影响结果。

## 专家迭代与 ReST-EM

### ReST-EM 两步循环

   * **专家迭代（Expert Iteration）与强化自训练（Reinforcement Self-Training，ReST）**
       * > **定义**：专家迭代的一种特定形式，只对 SFT 做很简单的改动。
       * ReST 直接从当前策略生成数据，也就是从当前的语言模型参数生成，然后挑出成功的轨迹当作微调数据更新模型。
       * 「强化」这个词的由来：它会强化 agent 已经在产生的正确行为。
       * 与自蒸馏的区别只在于是否用奖励做筛选；自蒸馏也可以指在模型生成的全部轨迹上做训练。

   * **ReST-EM 的两步循环**
       * 名字取自期望最大化（Expectation-Maximization，EM），因为它看起来非常像 EM 算法。
       * 第一步：从当前策略采样任务实例与轨迹，得到它们的奖励。
       * 第二步：评估奖励并用一个阈值筛选，合并所有任务实例中保留下来的轨迹。
       * 随后用合并后的数据集做一次大规模 SFT（只对保留轨迹的动作做最大似然估计），然后重复。
       * 新采到的轨迹会加进已有的好轨迹集合里，由此形成一个不断增长的数据集。
       * 奖励是二值时筛选很简单：保留奖励为 1 的轨迹，丢掉奖励为 0 的；SFT 目标就是最大化这些被保留轨迹中动作的概率。

```text
  ┌──────────────┐   ① 从当前策略 π_θ 采样任务实例与轨迹
  │  当前策略 π_θ │ ───────────────────────────────────►
  └──────────────┘                                        │
            ▲                                            ▼
            │        ③ 用合并后的数据集做一次大规模 SFT
            │        （只对保留轨迹的动作做 MLE）
            │                                            │
            └────────────────────────  ② 评估奖励，用阈值筛选
                  合并所有任务实例中保留下来的轨迹
```

       * **定位**：严格来说它不算强化学习——它没有对奖励求梯度，只是把奖励当成了筛选器；但和强化学习有很多相似之处，都是用模型生成数据，再根据轨迹奖励决定怎么在这些数据上更新。
       * 它复用监督微调的全部机制，很适合二值化的奖励，是非常简单又相当有效的起点方法。
       * 在策略 / 离策略：先攒出一个很大的数据集再训练，可能对所有实例跑一个甚至多个 epoch。

### 采不到成功轨迹时

   * **采不到成功轨迹的应对**
       * 更基础的问题是：怎么保证轨迹里确实有奖励的正样本？最糟糕的情况是采样出来全是一堆失败的轨迹。
       * 如果模型根本产生不出有好奖励的轨迹，强化学习和这个方法可能都不太适用。
       * 办法一：准备一些好轨迹的示范来训练模型，冷启动（cold start）阶段先在推理轨迹上训练模型、再开始做强化学习，让强化学习更容易产生高奖励轨迹；很多推理模型的训练流程里都有这一步。
       * 办法二：用课程学习，先挑那些有足够轨迹能产生奖励的题目来训练，等模型变强了再去攻更难的题。
       * 办法三：用中间奖励——如果已知先探索代码仓库有用，就为此给奖励，希望模型学会之后能解锁解决整个任务。
       * **稀疏奖励的工程结论**：奖励太稀疏时，光靠策略梯度自己爬出去是很慢的，工程上通常要先人为搭一段梯子。

## REINFORCE

### 无法直接反向传播的原因

   * **REINFORCE**
       * > **定义**：Williams 在 1992 年提出的经典方法，用期望奖励的定义加上一些基本代数技巧算出梯度估计值——用模型采样出的样本，加上反向传播流程求对参数 $\theta$ 的偏导数。
       * 不能直接用反向传播的第一个原因：动作是从策略里采样出来的。
       * 第二个原因：接下来要在黑盒环境里执行这些动作，而这个环境几乎总是不客观的。
       * 动作是离散的、采样出来的，采样动作对参数的导数几乎处处为零——参数改变的是概率，但在到达某个阶跃点之前并不会改变采样出的动作；环境通常也不可微。

### 得分比值技巧

   * **得分比值技巧（score function trick）**
       * 先把求导移到求和号里面：$$\nabla_\theta J(\theta) = \sum_\tau R(\tau)\,\nabla_\theta P_\theta(\tau)$$。
       * 奖励项能被提出求导号，是因为右边只有 $P_\theta(\tau)$ 带 $\nabla_\theta$：奖励项只依赖于轨迹，一旦知道轨迹就知道奖励是多少，它不再依赖于参数。
       * 用乘上再除以 $P_\theta$ 这一项的代数技巧：$$\nabla_\theta P_\theta(\tau) = P_\theta(\tau)\,\nabla_\theta \log P_\theta(\tau)$$。
       * 两者相乘后 $P_\theta(\tau)$ 抵消，代回去写成期望形式：$$\nabla_\theta J(\theta) = \mathbb{E}_\tau\Big[R(\tau)\,\nabla_\theta \log P_\theta(\tau)\Big]$$。
       * 这一项与 SFT 里做的是同一个计算：同样在对一堆 token 的 $\log$ 概率求关于语言模型参数的偏导数，只是权重从「这条示范被展示过」变成了「这条轨迹拿到了多少奖励」。
       * 这个方法非常通用，对语言模型和环境都不做任何假设。

### 梯度估计的可执行形式

   * **三步估计**
       * 第一步：轨迹从 $P_\theta$ 采样——让语言模型加上它的 agent 去与环境交互，这和平时运行这个 agent 的流程一样。
       * 第二步：把 $\nabla_\theta \log P_\theta(\tau)$ 拆开。轨迹的 $\log$ 概率由语言模型加 agent 给出的部分、从环境得到那些特定观测和奖励的概率这两部分构成。
       * 关键在于后面这一部分完全不依赖语言模型的参数——环境不知道你的 $\theta$ 是多少，所以对轨迹的 $\log$ 概率求导时，环境那一整项直接消失。
       * 这一步主要是为了严谨做的记账——正是「环境项是常数」这个观察，让整套方法摆脱了对环境模型的需求。
       * $$\nabla_\theta \log P_\theta(\tau) = \nabla_\theta \log \pi_\theta(\tau) = \sum_{t=1}^{T} \nabla_\theta \log \pi_\theta(a_t \mid H_t)$$
       * 第三步：可以从这个分布里抽取若干样本再取平均来估计期望，所以采样 $N$ 条轨迹就得到梯度的估计。
       * $$\nabla_\theta J(\theta) \approx \frac{1}{N}\sum_{i=1}^{N} R(\tau_i)\sum_{t=1}^{T_i} \nabla_\theta \log \pi_\theta\big(a_t^{(i)} \mid H_t^{(i)}\big)$$
       * 三个组成部分：轨迹（通过采样得到）、任务层面的评估（来自环境）、这个梯度。
       * 梯度计算方式与监督微调相同，关键区别是这里的动作是采样出来的、来自 agent 本身，而不是由某个标准答案演示出来的。

### 掩码、加权与训练循环

   * **掩码与奖励加权**
       * 一条从 agent 采样出来的轨迹里，蓝色 token 是模型实际生成的；所有灰色 token 要么是 prompt 的一部分，要么来自环境，要么是脚手架加的。
       * 细节一：一个动作可能对应多个 token，复杂的工具调用会拆成多个 token；这些 token 的 $\log$ 概率直接加起来就是整个动作的 $\log$ 概率。
       * 细节二：掩码。拿到所有这些生成的 token，取它们在那个时刻的各个 token 分布上的 $\log$ 概率，再把这些对数概率全部乘以这条轨迹对应的奖励。
       * 写成损失：$$\mathcal{L} = -\,\frac{1}{N}\sum_{i=1}^{N} R(\tau_i)\sum_{t} \log \pi_\theta\big(a_t^{(i)} \mid H_t^{(i)}\big)$$。
       * 掩码就是实现这一点的手段：把一部分内容遮掉，只选出自己生成的那些 token，然后把它们全部乘以这条轨迹的奖励。

```text
[ prompt ][ 环境反馈 ][ agent 生成的 ][ …… ]
 ── 灰 ──     ── 灰 ──           ── 蓝 ──
    不算          不算                算 log 概率
```

       * > **提示**：负号来自「我们做的是梯度下降」这个约定；最小化 $-\log$ 概率等价于把这条轨迹的概率往上抬。等价说法是：把采样出来的 token 的 log 概率乘以奖励，然后做一次常规的 SFT 式反向传播。
       * 在相当复杂的任务上实现 REINFORCE 也可能异常简单：*Deal or No Deal* 这篇用强化学习优化对话模型的论文，实现基本上就是做一次 SFT 的梯度计算然后把梯度乘以奖励，数学上也完全成立。
       * > **注意**：REINFORCE 有很多问题，所以很少有人直接开箱就跑标准的 REINFORCE 策略梯度。

   * **训练循环**
       * 第一步：采样一些任务实例。
       * 第二步：评估它们的奖励。
       * 第三步：用刚才那个公式算出损失。
       * 第四步：做更新，对这一批样本里的所有实例做一次更新。
       * 标准 REINFORCE 每个例子只用一条轨迹，据此计算更新，所以 batch size 就是任务实例数。
       * GRPO 会为同一个任务实例 $i$ 生成多条可能的轨迹并全部用在更新里，那时 batch 的实际规模会再乘一个组大小。
       * 二值奖励下 REINFORCE 看起来很像 ReST：两者都只是用奖励去缩放动作的对数概率。区别是 REINFORCE 完全在线，采样出轨迹就直接在它们上面更新；ReST 是先攒出一个很大的数据集再训练。

## 优势与基线

### 从绝对奖励到相对好坏

   * **奖励是绝对的，动作的好坏是相对的**
       * 一条成功轨迹奖励为 1，按更新规则所有动作都会被上调权重。
       * 一条失败轨迹（第一次猜得很糟、最后超时）只用基础 REINFORCE 或 ReST 完全不会产生更新，因为更新要乘以奖励而奖励是 0——但其实是想学会别这么做的。
       * 猜 10 拿到奖励 1 值不值得表扬，取决于策略在这个例子上原本有多大概率能猜对。
       * 如果模型 95% 的时候都能拿到奖励 1，那剩下 5% 的时候犯了个很蠢的错、拿到奖励 0，就应该大力惩罚这些罕见但代价高的错误。

### 基线的定义与构造

   * **优势函数（advantage function）**
       * > **定义**：以到某个时间步为止的历史和一个动作为自变量，衡量「假设采取这个特定动作、剩下的轨迹都从语言模型里采样」相对于「直接从语言模型采样（包含这个动作）并继续走下去」的好坏。
       * 它告诉你的，考虑到语言模型之后会采取的所有动作，这个特定动作相对于整体价值有多好。
       * 很多强化学习算法就是从估计这些优势和价值的各种不同方法推导出来的，也就是这个动作的 $Q$ 值和相应的价值 $V$。
       * 如果不知道 $Q^\pi$ 或 $V^\pi$，可以估计它们：通过实际行动估计这个特定动作的期望奖励，或用基线函数估计预期表现有多好。

   * **基线（baseline）**
       * 基线就是一个「我原本预期能做到多好」的标尺，动作的奖励减去这个标尺才是真正想学的东西。
       * 基线本质是一种重新缩放奖励的方法：REINFORCE 用奖励缩放 $\log$ 概率的梯度，基于优势函数的方法一般是从奖励里减去一个基线；两者数值上并不等价，但都是估计策略梯度的有效方法。
       * 定义不同的基线就得到不同的强化学习算法。
       * 构造方式一：一个常数。
       * 构造方式二：目前见过的所有例子的奖励的滑动平均。
       * 构造方式三：一个训练出来的神经网络模型——Actor-Critic 方法和 PPO 就是这样，需要一个独立于策略之外的模型，成本可能很高。
       * 另一种做法是不用单独的模型，直接从策略本身采样来估计策略下的期望奖励，这就是 GRPO。
       * 基线也有缺点，而且基线用什么来构造有很多种选择；强化学习的很多内容其实就在于选好的方式来表示优势函数。

   * **猜数游戏中的优势**
       * 猜 8 反馈更高、猜 12 反馈更低之后，数字在 8 和 12 之间，只可能是 9、10 或 11。
       * 并不确切知道价值函数是什么（它取决于策略），但大概是 $\tfrac{2}{3}$ 到 1 之间：策略总是做到最好则总能赢，策略在合法选项里比较随机则更接近 $\tfrac{2}{3}$。
       * 猜 11 不太好，因为它在这个范围的一端，万一 11 不对就只剩两个候选数和一次机会，所以优势应该很低。
       * 猜 10 不错，因为就算猜错还剩一次机会，往高或往低都行。

   * **PPO 的方向**
       * PPO 基本上就是不用轨迹来计算优势函数，而是用一个单独的模型（通常和策略共享主干网络）来预测基线。

### 无偏性引理

   * **减去基线为什么不产生偏差**
       * 估计有偏差和方差：偏差说估计的均值可能偏离真值多少，方差说抽出来的估计值有多分散。
       * 引理：减去一个只依赖于到目前为止历史的基线，不会使梯度产生偏差。
       * 优势函数估计为 $\big(R(\tau) - b(H)\big)\nabla_\theta \log \pi_\theta(\tau)$，把它的期望拆开：
       * $$\mathbb{E}_\tau\Big[\big(R(\tau) - b(H)\big)\nabla_\theta \log \pi_\theta(\tau)\Big] = \nabla_\theta J(\theta) - \mathbb{E}_\tau\Big[b(H)\,\nabla_\theta \log \pi_\theta(\tau)\Big]$$
       * 第一项就是真正想要的 $\nabla_\theta J(\theta)$，只要第二项为 0 两者就相等。
       * 第二项为 0 的理由：它是对从策略采样的动作取期望，基线只依赖到目前为止的历史、不依赖当前动作，于是可以提到期望外面，再用同样的对数导数技巧改写。
       * $$\mathbb{E}_{a \sim \pi_\theta(\cdot \mid H)}\Big[b(H)\,\nabla_\theta \log \pi_\theta(a \mid H)\Big] = b(H)\cdot \nabla_\theta\,\mathbb{E}_{a \sim \pi_\theta(\cdot \mid H)}\big[\log \pi_\theta(a \mid H)\big]$$
       * 括号里那个期望是负的熵：$\sum_a \pi_\theta(a|H)\log \pi_\theta(a|H) = -\mathcal{H}_\pi(\cdot \mid H)$。
       * 一个分布的熵不依赖它自己的参数，所以对这个量关于 $\theta$ 求导结果为 0，整项也跟着变成 0。
       * > **易错点** ⚠️：这个结论成立的关键是基线不能看当前动作。如果基线里混进了 $a_t$ 的信息，$b$ 就不再能从求号里提出来，无偏性的整个证明就塌了。这也是 GRPO 特意强调「组均值只在每个例子内部计算」的原因。

### 双臂老虎机的数值例子

   * **设定**
       * 只有一次决策、两个动作：要么猜 A，要么猜 B。
       * 策略只有一个参数 $\theta$，对它应用 sigmoid 函数得到概率化的策略——sigmoid 把负无穷到正无穷的实数映射到 0 和 1 之间——把这个值当作选 A 的概率。
       * 当前策略的 $\theta$ 是 -1.1，最后给出很方便的概率：0.25 的概率猜 A，奖励 1；0.75 的概率猜 B，奖励 0。
       * 这是坏策略，因为它把更高的概率给了没有奖励的选项；希望 $\theta$ 变得更正，因为 $\theta$ 越大曲线越靠上，猜 A 的概率越高，而 A 正是奖励更高的选项。

   * **两个动作的 log 概率梯度**
       * $$\nabla_\theta \log \pi(A) = \nabla_\theta \log \sigma(\theta) = 1 - \sigma(\theta) = 1 - 0.25 = 0.75$$
       * $$\nabla_\theta \log \pi(B) = \nabla_\theta \log\big(1 - \sigma(\theta)\big) = -\sigma(\theta) = -0.25$$
       * 第二个是负的：$\theta$ 变大时 B 的概率在下降。
       * 不用基线时，采样到 A 的梯度估计是 $1 \times 0.75 = 0.75$；采样到 B 的梯度估计是 $0 \times (-0.25) = 0$——采样到奖励为 0 的动作就得不到任何梯度。

   * **加基线前后的对比**

| 估计量 | 采样到 A（R = 1） | 采样到 B（R = 0） | 加权期望 |
| :--- | :--- | :--- | :--- |
| 无基线 | $1 \times 0.75 = 0.75$ | $0 \times (-0.25) = 0$ | $0.25 \times 0.75 + 0.75 \times 0 = 0.1875$ |
| 基线 $b = 0.5$ | $(1 - 0.5) \times 0.75 = +0.375$ | $(0 - 0.5) \times (-0.25) = +0.125$ | $0.25 \times 0.375 + 0.75 \times 0.125 = 0.1875$ |

       * 这个设定只有两个动作，可以按策略梯度的严格定义精确算出来：把每个梯度乘上采样到该动作的概率。
       * 真正的策略梯度（对所有动作的期望）是 0.1875，约 0.18；但只能得到噪声很大的估计——25% 的概率会踩到 0.75，远高于 0.18，75% 的概率得到 0。
       * 加上基线 $b = 0.5$ 后改动只是从奖励里减去基线，其他计算都一样，每个单独的样本都更接近真值 0.18，基线确实降低了样本的方差。
       * 期望没有变，它只是让估计量的方差变小了——在真实数据上做这些估计做更新时，不想让梯度没必要的把参数晃来晃去。
       * 可视化上，基线为 0 时梯度估计只有 1 或 0 的缩放，加基线 0.5 后被往真期望拉近；滑动平均曲线显示有基线时方差更小。
       * 不管基线取多少，更新都会让模型更正确：更新会让 $\theta$ 变得更正，从而提高猜 A 的概率，只是估计方差更低时这个过程会更快。
       * 连续采样到好多次猜 B 后滑动平均才升回去，曲线最终确实会收敛，但用基线降低方差后通常离真值更近。
       * 这个非常简单的双臂老虎机设定里的直觉，一般也能迁移到更复杂的序贯决策设定中去。
       * > **易错点** ⚠️：表里「采样到 B」那一格的正号很反直觉，但它是正确的。优势 $(0-0.5)$ 是负的，可 B 自己的 $\log$ 概率梯度也是负的，两者相乘仍为正——方向依然是把概率推向 A，只是力度小得多。优势决定「该不该抬」，$\log$ 概率梯度决定「往哪抬」，两者符号不能混着看。

### 后续奖励

   * **后续奖励（return）**
       * 如果奖励在中间时间步给而不是只在轨迹末尾给，要把奖励缩放换成后续奖励，也就是未来各时间步奖励的总和：$G_t = \sum_{t' = t}^{T} r_{t'}$。
       * 这同样有助于降低方差。

## GRPO

### 用自身 rollout 当基线

   * **组相对策略优化（Group Relative Policy Optimization，GRPO）**
       * > **定义**：一种得到优势函数、估计基线的方法，用的是模型自身的 rollout。
       * 它出自 DeepSeek 的一篇论文，那篇工作在训练推理模型时非常注重效率。
       * 过去很多把强化学习用于语言模型的工作都需要一个单独的模型来预测基线；预测基线来降低方差非常重要，但做起来很难、大家都用单独的模型，成本很高。
       * DeepSeek 去掉单独的模型，直接用模型自身的多样本来估计策略下的期望奖励。
       * 具体做法是对同一个实例从模型采样多次、取每次的奖励，再对奖励做中心化：取这一组里所有采样奖励的均值，基本就拿它当基线。
       * 这样很合理，因为一个好的基线就是期望的策略下的奖励，而估计它的好办法就是把策略跑多次取奖励再求均值。
       * 任务实例就是一个要解决的强化学习问题，要从它生成多个 rollout，也就是把同一个问题解多次，每次重置环境，通过从 agent 采样得到完整轨迹。
       * 组大小一般取 8 左右。
       * 优势函数估计为 $\hat{A}_i^{\,j} = R_i^j - b_i$；组均值只在每个例子内部计算，别的实例的奖励不参与——价值函数应该只是对具体例子上奖励的估计，所以优势函数只应该看这个例子内部的奖励。
       * 优势函数还可以先减去均值、再除以实例内奖励的标准差。
       * 在策略梯度损失里，原本每个实例只取一个样本重新加权；GRPO 的批次中会有多个实例，每个实例的组内又有多条轨迹，每条轨迹都有一个优势函数，用它重新加权对数概率再求导。
       * 无偏性：这里的优势函数只取决于 prompt 和模型本身，从奖励中减去的那个基线函数其实就是语言模型自己的 rollout，它没有偷看当前这条轨迹的奖励，因此满足「只依赖历史」的条件，梯度估计是无偏的。

```text
同一个任务实例 i（同一个 prompt）
  1. 采样 G 条 rollout（每次重置环境），得到奖励 R_i^1 ... R_i^G
  2. 组内取均值 -> 基线 b_i = mean(R_i)
  3. 优势 = R_i^j - b_i        （b_i 只在实例 i 内部算）
  4. 每条轨迹的 log 概率 × 优势 -> 求梯度 -> 更新 θ
```

       * 实现层面：蓝色的是自己生成的 token；计算优势函数时取这条轨迹的奖励，减去同一组内其他所有轨迹的平均奖励；然后每个 token 的奖励除以常数 $C$ 归一化，$C$ 通常是可生成的 token 数；对组里所有轨迹的奖励都这么做，这些奖励可正可负、各不相同。

### 标准化与 Dr. GRPO

   * **标准化**
       * 原始 GRPO 论文里还做了标准化：算出这组轨迹奖励的标准差，然后除以这个标准差得到优势函数。
       * 实际上除以标准差这一步似乎并不是必要的，很多自称 GRPO 的实现都去掉了这一步，这样更贴近优势函数本身。
       * *Done Right GRPO*（Dr. GRPO）这篇论文更详细地讨论了这样做的动机。

   * **Dr. GRPO 的两处修改**
       * 第一处：不除以标准差，只减去组内奖励的均值。
       * 第一处的动机：如果除以标准差，优势函数就不再感知问题的难度了，等于把各种难度范围都重新缩放成了同一标准，这可能是有害的。
       * 第一处的例子：简单题组内奖励是 [1, 1, 0, 0]，难题组内奖励也是 [1, 1, 0, 0]，除以标准差之后两者得到的优势完全一样，可它们根本不是一回事。
       * 第二处：不要除以实际生成的 token 数，只除以一个常数 $C$（通常是可生成的最大 token 数）。
       * 第二处的动机：除以生成的 token 数会让模型偏向又长又错的答案——一条又长又全错的长答案，每个 token 分到的惩罚就被摊薄了。
       * $$\mathcal{L} = -\,\frac{1}{N}\sum_{i=1}^{N}\frac{1}{C}\sum_{j=1}^{G}\sum_{t=1}^{|y_i^j|}\Big(R_i^j - \mathrm{mean}_j(R_i)\Big)\log \pi_\theta\big(y_{i,t}^j \mid h_i, y_{i,<t}^j\big)$$
       * 这两处修改总体上是有帮助的，因为它们能避免 GRPO 里的一些偏差。
       * > **注意**：这里讲的并不是论文里定义的 GRPO 损失。论文里的损失还有一些额外的项：会对梯度做裁剪，防止一步迈得太远；还会对策略做正则化，避免偏离初始策略太远。这两项都是帮助稳定训练的额外手段。

### 组内全对或全错

   * **没有区分度就没有信号**
       * 如果所有奖励都是 0 就糟了：说明对当前策略来说任务可能太难了，就算有基线也得不到任何信号。
       * 如果所有轨迹都成功也有问题：说明对当前策略来说任务太简单了，二值奖励下 1 已经是能拿到的最好结果。
       * 一般来说只要样本之间没有区分度就不好：减完均值之后全是 0，整个加权的和就等于 0，GRPO 估计出的优势函数给不出任何信号。
       * 应对办法一：换不同的任务实例，去攻那些当前策略还有区分度的题。
       * 应对办法二：在 prompt 里注入一些知识，引导模型产出更可能正确的解法。
       * 应对办法三：加入示范——有些离策略强化学习方法会把正确的示范放进组里，或者更简单地先在这些正确示范上微调模型，再跑强化学习。
       * 应对办法四：用更有信息量的奖励，鼓励模型在生成完整轨迹之前就做出正确的中部决策，这叫奖励塑形（reward shaping）；比如给模型找到正确文件的奖励就是一个例子。
       * **信号来源**：GRPO 的信号强度完全来自组内奖励的离散程度。组内方差越大，优势估计越可靠，梯度信号越强；实践里调难度、筛任务，本质上都是在维护这个方差。

## 方法对照

   * **三种方法的定位**

| 方法 | 奖励假设 | 怎么给生成的动作重新加权 | 在策略 / 离策略 |
| :--- | :--- | :--- | :--- |
| ReST-EM | 假设奖励是 0/1 二值 | 只筛出正确的轨迹（R = 1），对它们做 SFT | 先攒出大数据集再训练，可能跑一个甚至多个 epoch |
| REINFORCE | 任意标量 | 直接用轨迹的奖励 $R(\tau)$ 缩放 $\log$ 概率 | 完全在线，采一批就更新一批 |
| GRPO | 任意标量 | 用优势函数：奖励做平移（可再按标准差缩放） | 在线，每个实例采 G 条 rollout 一起更新 |

   * **共同点与差异**
       * 每种方法都让 agent 在环境里执行动作，然后用 agent 产生的这些动作来计算损失；它们看起来都像某种自训练，区别只在于如何给生成的动作重新加权。
       * REINFORCE 用轨迹的奖励来重新加权损失也就是重新加权梯度；GRPO 用的是优势函数，奖励会做平移，还可能按模型对同一实例采样的其他轨迹的奖励来重新缩放。
       * 任务失配：REINFORCE 与 GRPO 直接最大化期望奖励，已经解决。
       * 数据失配：只要基线用得合适，现在就能从零奖励轨迹中学习。
       * 曝光偏差：这些方法在策略的特性也有助于应对曝光偏差，因为模型在训练时相当于自己在开车，所以它应该学会从自己的错误中恢复过来。
       * 代价：得真的在环境里去尝试各种方案，可能开销很大，还会给梯度引入一些噪声；基线是让这个过程更稳健的最重要的一种方法。
