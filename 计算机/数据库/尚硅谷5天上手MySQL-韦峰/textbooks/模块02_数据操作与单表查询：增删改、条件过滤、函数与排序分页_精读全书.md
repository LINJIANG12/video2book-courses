## 行是最小单位：从增删改一路摸到查询
> 对应块：BLK06 | 覆盖分集：P30-P35 | 块标题（分集名）：《30-数据操作篇-概念介绍和行基本单位》

写到这儿，先问一句：到此为止我们已经把什么干完了？库的创建建好了，表的创建建好了，表的修改也练过了。数据容器算是有了。那么接下来，是不是就该对容器里的数据动手了？

对。这一节正式进第三章节——数据操纵语言 DML。这个方向比前面那个方向简单得多，我们很快就能搞定它。

### 为什么把"查"单独剔了出去

DML 的作用说白了就三个：插入数据、更新数据、删除数据。这也不用兜圈子，大家应该都清楚，数据库无非就是个存数据、做操作的工具，而操作主要就四个方向：增、删、改、查。DML 把"查"剔开了，剩下增删改三个归它管。

那为什么单把查询分出去？因为查询跟它仨有本质区别。查询不会改变原有的数据——你不管怎么查，数据不会丢、不会多、不会少。但插、改、删这三个哥们儿是真的会动表里数据的，所以要把它们分开。

名字也顺一下。数据操纵语言也叫操作语言，操纵、操作一回事，英文是 Data Manipulation Language，缩写 DML。

> **定义**：DML（Data Manipulation Language，数据操纵语言）负责对库表中的数据做三类操作——插入、更新、删除，对应的关键字分别是 `INSERT`、`UPDATE`、`DELETE`。

> **注意**：DML 不会影响库表结构。不管你怎么删数据，别怕，你删不了表，也删不了库，它只对表内部的数据动刀。但反过来你也别真把数据都删干净了——那不是删库跑路了吗，对不对？它不影响结构，可是真删了，数据是真的没了。

这三个关键字大家一定要记住，等一下我就围着它们，把三个动作从头到尾讲一遍。

### 行：三个动作共同的最小单位

在动手之前，得先想清楚一件事：删除删的是哪些？修改改的是哪些？插入又是往哪儿插？

答案是一个东西——行。

之前介绍关系型数据库的时候提过，关系型数据库一共有四个单位：库、表、行、列。列是最小的单位，库是最大的单位，但**行是最基本的单位**。这三个尺寸里，列最小、库最大，可真正干活的时候，粒度卡在行上。

举个具体例子。假设我们有这么一张表，表中若干列。现在要插入数据，怎么插？先选中一行，往这一行里去填对应的列值。第二，修改数据怎么改？也是先锁定一行，或者锁定若干行（当然锁定哪些行是有条件准备的），锁定以后改的是这一行中的某些列。第三，删除怎么删？选中一行，把这一行的数据整个删掉就够了。

```text
                 数据库操作的基本单位：行
   ┌──────────┬──────────────────┬──────────────┐
   │   插入   │      修改        │     删除     │
   ├──────────┼──────────────────┼──────────────┤
   │ 选中一行 │  锁定一行或多行  │  选中一行    │
   │ 往里填值 │  改行中的某些列  │  把整行删掉  │
   └──────────┴──────────────────┴──────────────┘
   三件事的落脚点完全一样：先选中行，再动手
```

所以记住一句话：不管插入、删除还是修改，最基本的单位都是行。这句话你记住了，后面所有的语法都不会绕。

DML 这一部分的概说就到这儿。接下来的任务书分两小块：先把语法和概念讲清楚（就是刚才这一节），再进第二小节，逐个把增、删、改的语法讲一遍并且实战。我们先来插入。

### 插入：一行里的所有列、指定的列、还有好几行

插入我分三种情况来讲。第一种，插入一行中的所有列；第二种，插入一行但不插所有列，也就是指定列插入；第三种，同时插入多行数据。

在讲语法之前，大家在脑子里先回忆一下上面那句话：增删改查最基本单位是行，所以插入的时候，插的就是一行。

#### 全列插入

第一种方式，插入一行中的所有列，语法就是：

```sql
INSERT INTO 表名 VALUES (值1, 值2, ...);
```

`INSERT` 和 `INTO` 是一对好基友，不分家，后面紧跟你要插入的表名。`VALUES` 代表你要插入这一行里的值，后面那一个括号就代表一行。那一行里有几个列，你就在括号里写几个值，中间用逗号隔开就完事了。这就是为表中的一行插入数据。

举例：这张表里有三列，第一列是名字，第二列是年龄，第三列是性别。那你围绕这个写的时候，值 1 就应该是名字这个字符串，值 2 是年龄这个数值，值 3 前面用逗号隔开，再写个性别这个字符串，完事。

```sql
INSERT INTO student (name, age, sex) VALUES ('二狗子', 18, '男');
```

> **易错点**：全列插入的语法更简洁，表名加 `VALUES` 就行了，不用指定插入哪些列。但代价是——你得记住当初这个表里一共有哪些列，而且 `VALUES` 里值的顺序，必须跟表的列顺序一致。大家思考一个问题：如果一个表有 50 列、60 列，你能记得住吗？记不住的话，我第一个方案就不推荐了。

#### 指定列插入

如果你记不住这种列顺序，怎么办？用第二种方案，叫指定列插入：

```sql
INSERT INTO 表名 (列名1, 列名2, ...) VALUES (值1, 值2, ...);
```

跟上面一模一样，只不过在表名后边多了一个括号。这个括号里指定你要插入哪些列。写 `VALUES` 的时候，值就按照你前面指定列名的顺序去写，不再按照原表列的顺序。

这些列当然也可以是表中的全部列——指定三列完全可以；指定两列、一列也完全可以；顺序你自己随便定。灵活性就体现在这儿，而且括号里明明白白写着你要按哪个顺序去填值，容易正确，也就不容易出错。这就是我推荐的第二种方案。

| | 全列插入 | 指定列插入 |
| --- | --- | --- |
| 写法 | `INSERT INTO 表名 VALUES (...);` | `INSERT INTO 表名 (列名, ...) VALUES (...);` |
| 值跟谁对齐 | 表中**原有**的列顺序 | 你**指定**的列顺序 |
| 优点 | 语法简洁 | 灵活，不用记原有列顺序和列名 |
| 缺点 | 列一多就记不住，顺序错一个全崩 | 多打一个括号 |

#### 多行插入

有的时候我想一次插入多行数据怎么办？上面两种语法都不用变，只不过在后面多加一个逗号。前面说了一个括号就代表一行数据对吧？那我逗号隔开，再写一个括号，一行；再逗号，再写一个括号，又一行。多个括号，里面放多对值，就完事了。

但还是那句话，值的类型和顺序，必须跟表中的列名——或者你指定的列名和类型——一一对应。

#### 两个小结

讲完插入语法，有两个小结得记一下。

第一，写 `VALUES` 的地方，除了 `VALUES` 也可以写成 `VALUE`，这个关键字能换。但 `VALUES` 是标准语法，所以我们推荐用 `VALUES`。

第二，插入数据的时候，凡是字符串还是日期类型，别忘了在外面加一个单引号，代表它是个字符。

### 插入实战：从建库到四道题

语法讲完，我们切到实战页。这儿已经给大家准备好了表结构：创建一个叫 `dml_db` 的库，用一下这个库，库下边有个学生表，里有学号、姓名、年龄、生日、身高五列。下方有四个要求，都是插入数据，我们把它一个个实现掉。

先看全列插入，`VALUES` 或者 `VALUE` 都行，但推荐 `VALUES`。一个括号，写列值，值、值、逗号隔开、值……这里一定要记住：值的数量要等于这个表所有列的数量，值的类型和顺序要跟表里的列的类型和顺序一一对应。

指定列插入语法跟上方一模一样，只是在表的后边写个括号，括号里写你要插的列名。下方那些注意事项就跟着变了——不用再跟表中原有的列名对应了，而是：值的数量等于你**指定**的列的数量，类型和顺序跟**你指定**的这几列一一对应。只要你指定了，就以你指定的为准。这么一来，插入时根本不用记原有的表顺序和列名。

多行插入跟上面一模一样，语法一样，只是写作时可以写"逗号隔开括号、括号"，一个括号代表一行。

好，实战开始。第一步创建库，第二步 `USE` 切换到这个库，第三步在这个库里创建 `students` 学生表。库表建好，下面四个动作。

**第一个动作：插入一名学生的所有信息。**

既然要插入所有列，我就可以不指定了，且我记住了这个顺序，直接写 `VALUES` 加括号：

```sql
INSERT INTO students VALUES (1, '二狗子', 18, '1990-06-06', 185.5);
```

值按顺序来：第一个是学号，`INT` 类型，举个例子我写个 1——数值类型嘛，不用加单引号；第二个是姓名，那我加个引号，假如他叫二狗子；第三个逗号隔开，是年龄，又是一个数值，假如他 18；第四个是生日，大家记着，时间就是一个特殊格式的字符串，所以这儿加引号，假如生日是 1990-06-06；最后是身高，又是一个数值，假如他是 185.5。这就插进去了。

当然我也可以这么写——在前面把列名指定出来：

```sql
INSERT INTO students (stu_id, stu_name, stu_age, stu_birthday, stu_height)
VALUES (1, '二狗子', 18, '1990-06-06', 185.5);
```

这括号里就是列名。`VALUES` 后面的值就按你列名给的顺序写。当然你要是把 `stu_id` 挪到最后、把姓名挪到前面，那后面的值顺序跟着挪就行，规矩就一条：按你前面指定的顺序来。

> **易错点**：列名和表名都是关键字，**不要加引号**。只有值的位置，当它是个字符串的时候才需要加单引号。

**第二个动作：只插入学生的学号、姓名、年龄，其他列我们不用管。**

那就指定三列：

```sql
INSERT INTO students (stu_id, stu_name, stu_age) VALUES (3, '吕蛋蛋', 29);
```

这三列你当然可以自己调顺序，这代表我们选中的这三列。后面再写的时候就是 `VALUES` 加括号，学号写个 3，名字叫吕蛋蛋，年龄 29。这就相当于指定列插入，搞定。

指定了列、其它没指定的列，就走它的默认值。

**第三个动作：一次插入两名学生的信息，全都要。**

全都要，那就不用写列名了，假如我记住了就可以直接写全列插入：

```sql
INSERT INTO students VALUES
(4, '狗剩子', 20, '2020-02-20', 223.5),
(5, '石头仔', 20, '2000-01-01', 175.0);
```

第一行：学号 4，姓名狗剩子，年龄 20，生日 2020 年 02 月 20 日，身高 223.5。想插入多名学生的数据，逗号隔开再写一个括号，把值再写一遍，这个是 5，石头仔，后面再写它对应的数据就可以了。这就代表插入多条数据。

**第四个动作：有的列我想插空值。**

这一题跟第二个动作看着像，其实不一样。第二个动作说"其它列你不用管，走默认值"；这一题说的是"其它列你要**主动赋空**"。这是需要你把其它列显式写出来，主动赋一个空值的。

```sql
INSERT INTO students (stu_id, stu_name, stu_age, stu_birthday, stu_height)
VALUES (6, '小笨蛋', 20, NULL, NULL);
```

列名照样全写出来，`VALUES` 里学号 6、姓名小笨蛋、年龄 20，后面两个值他说要主动赋空——空在 SQL 中就直接写个 `NULL`，这就代表空值。

> **提示**：这个跟第二个动作到底差在哪？现在我们还没讲约束，后期会讲空约束、默认值约束。如果加了默认值约束以后，你**不插入**某一列，它会自动赋一个默认值；但如果你是**主动插入**且给一个空值，它就不会走默认值的路子了，它给的就是空值。所以现在结果可能看起来一样，但后期会分道扬镳：不指定列 → 走默认值；显式给 `NULL` → 就是空值。仅仅如此。

### 修改：UPDATE 加 SET，条件放 WHERE

接着是 DML 的另一个方向——修改语句。修改主要分两个方向。

第一是**全表修改**，指修改表中所有行的数据。举个例子：把学生表里所有人的年龄都加一岁，这边没有任何条件，不筛选任何行。

第二种是**条件修改**，在第一种的语法基础上加一个 `WHERE` 关键字，用它来筛选符合条件的行。比如去更新一下身高超过某个值的学生年龄，前面有条件，要超过某个值才去改。它就不是全表了，只改符合条件的行。

来看两个语法。

第一个，全表修改。关键字是 `UPDATE`，后面紧跟表名。除此之外还有一个关键字叫 `SET`，这个大家一定要记住——`SET` 代表你要把这行的哪些列等于哪个值：

```sql
UPDATE 表名 SET 列名 = 新值, 列名 = 新值;
```

一次想改行中的多个列，用逗号隔开就行，列名等于值、逗号、列名等于值。这就是全表修改，它会把表中所有行都按你 `SET` 后面的内容改掉。

第二个，条件修改，只不过在第一种的基础上加了个 `WHERE`：

```sql
UPDATE 表名 SET 列名 = 新值 WHERE 条件;
```

`WHERE` 关键字本次我们只是初步体验一下，等查询章节再着重讲。它指的是对表中的行进行筛选，筛到符合的行以后，再去修改这些行里对应的列。

> **注意**：不写 `WHERE`，代表修改一个表中**所有行**的数据；写了 `WHERE`，就只修改符合条件的那几行。改多个列的时候，`SET` 后面要写"列名等于值，逗号隔开，再写列名等于值"。

### 修改实战：四道题

我们在原有的学生表里准备一些数据，下面有四个练习，来强化对 `UPDATE` 的理解。

**第一题：把学号为 8 的学生，姓名改成"黄六"。**

这是全表修改还是条件修改？很明显，有一个条件叫"学号为"，所以是条件修改：

```sql
UPDATE students SET stu_name = '黄六' WHERE stu_id = 8;
```

前面是 `UPDATE` 加表名 `students`，把学生姓名改为黄六，列名是 `stu_name`，等于黄六——字符串，直接加引号。条件加个 `WHERE`，这读出来就叫"为"，说白了是不是就等于的意思：`stu_id` 等于 8。也就是学号等于 8、学号为 8 的改成黄六。执行完，学号为 8 的就变成黄六了。

它的执行顺序是这样的：**先按 `WHERE` 找到符合条件的行，再把行里的列改成新值**。找行在前，改列在后。

**第二题：把年龄小于 20 的学生，身高在原有基础上加 2.0。**

```sql
UPDATE students SET stu_height = stu_height + 2 WHERE stu_age < 20;
```

`WHERE` 条件是 `stu_age < 20`。身高怎么改，大家注意：符合条件的是两行，但它们改的值是不一样的——一个是 165.8，一个是 185.5，改完分别是 167.8 和 187.5。

这里有个容易搞错的地方：**`SET` 后面一旦写成一个固定值，它俩就都会变成同一个值**了，而不是各自相对地加 2。想让每行各自加 2，就得把原值取出来参与运算，写成 `stu_height = stu_height + 2`——这个语法指的是在取到原有值的基础上加 2。你是 165.8，加完变 167.8；你是 185.5，加完变 187.5。可以利用原值去做。

> **易错点**：有人说我学过 Java，Java 里面可以写 `+= 2`，这个语法是不支持的。Java 跟 SQL 的标准语法还是有区别的。SQL 的支持语法是：只取你原来的列，在右侧原有的列的值上去加。能加，也能减、能乘、能除，可以对原列做运算，但**没有 `+=` 这种写法**。

执行完影响了两行，167.8、187.5 就搞定了。

**第三题：把学号为 11 的学生的生日修改为 2003-07-10，且年龄改为 21。**

改两个列，而且有条件：

```sql
UPDATE students
SET stu_birthday = '2003-07-10', stu_age = 21
WHERE stu_id = 11;
```

时间是一个特殊格式的字符串，写上就可以了。这一个列改完，逗号隔开，另一个列 `stu_age = 21`。学号为 11 的是孙八，执行一下、刷新，孙八就变成 21 岁、7 月 10 号了。

**第四题：把所有的学生的年龄增加一岁。**

过年了，数据库里所有学生的年龄要长一岁。语法并不难：

```sql
UPDATE students SET stu_age = stu_age + 1;
```

取到原值，在右侧加 1，再赋给列名。因为没有条件——它代表找到每一行，把每一行的年龄都改一下，所以不用写 `WHERE`。刷新一下数据，大家会发现每个人都大了一岁。

### 删除：全表清空和按条件删

DML 的最后一个操作就是删除。网上经常有人开玩笑说"删库跑路"，那个删库其实是库表结构层面的操作，而我们这里的删除，指的是删除表中的相关数据。

删除一共分两种。第一种是**全表删除**，把一个表中的所有数据都删掉。说到这里，有些同学可能会回想起来，之前讲表的操作时也讲过清空表数据。它们两个动作的效果是类似的，都会把表中的所有数据删掉，但是 `DELETE` 这种删除的语法相较于清空表的 `TRUNCATE` 会更轻一些——它只删除当前表的数据，但不会删除表相关的记录，比如自增的最大 ID 值这些。

第二种是**条件删除**，删除的时候先选中符合条件的行。最基本的数据库操作单位是行，选中行以后再删。在开发中，99% 的需求其实全是条件删除。

两种语法分别是：

```sql
DELETE FROM 表名;                 -- 全表删除所有行
DELETE FROM 表名 WHERE 条件;      -- 条件删除，只删符合条件的行
```

在正式练习之前，先把 DML 的核心内容做个梳理。整个 DML 学完，大家需要拿下三个小目标：

> **第一个目标**：掌握 `INSERT`、`UPDATE`、`DELETE` 这三个关键字的基本语法结构和各自的作用。
>
> **第二个目标**：一定要理解数据库操作的最基本单位是行。无论插入、修改还是删除，针对的都是整行，理解了这点，操作时才不会困惑。
>
> **第三个目标**：掌握具体的三种语法细节——怎么全表插入、怎么指定列插入、怎么插多行；更新时怎么在原有的列上做修改、怎么指定多列更新；删除时怎么按条件清除。

#### DELETE 和 TRUNCATE 到底差在哪

这个差别值得单独说清楚。两者都会删除表中的全部数据，但 `TRUNCATE` 的删除程度更重一些：它不仅删表数据，还会重置数据库自增 ID 的最大记录值。`DELETE` 只删数据，不动自增记录。

怎么选？单纯删除数据，通常用 `DELETE`；如果项目推倒重来、要上新项目，需要把原有数据完全清空，那才用 `TRUNCATE`。而业务运行过程中，因为逻辑需要删掉某条数据，那必须用 `DELETE`。

#### 删除实战：四道题

**第一题：删除年龄大于 23 岁的学员。**

```sql
DELETE FROM students WHERE stu_age > 23;
```

这里的条件写法，无论在删除、修改还是后续的查询中都是通用的。具体的复杂条件写法，后续在查询章节会详细展开。

**第二题：删除身高高于两米、并且学号大于 10 的学员。**

这里包含两个条件，需要用"且"的关系：

```sql
DELETE FROM students WHERE stu_height > 200 AND stu_id > 10;
```

在 SQL 中，条件之间的逻辑关系可以用 `AND`、`OR` 这类关键字来连接。两个条件都必须符合时，用 `AND`。

**第三题：删除身高大于两米，或者学号大于 10 的学员。**

```sql
DELETE FROM students WHERE stu_height > 200 OR stu_id > 10;
```

中间是"或者"的关系，用关键字 `OR` 就行。

**第四题：把表中的数据全删掉。**

```sql
DELETE FROM students;
```

后面不加任何条件，执行后即可清空表中所有行的数据。打开表数据刷新验证，表中数据已被清空。

到这里，所有的 DML 操作就讲解完毕了。

### DQL 概述：为什么"查"值得一个章节

接下来进入第四章节，数据库的查询语句 DQL。本章节专门针对**单表**的查询语法进行讲解，多表查询会放到后续章节分开介绍。

本章节主要分五个方向：第一，对 DQL 进行整体介绍，说明单表与多表查询的区别；第二，介绍内部核心查询关键字 `SELECT` 的用法以及基本查询语句；第三，讲解查询语句中经常用到的运算符；第四，讲解 SQL 提供的单行函数和多行函数，以此扩充查询能力；第五，对查询结果进行升级与加工，实现分组、排序、分页截取等高级处理。

除了这五个要点，本章还会安排大量的查询练习。查询的语法本身并不难，但查询的需求场景和样式非常丰富多样，所以需要通过大量练习来加深理解。

DQL 全称 Data Query Language，数据查询语言，顾名思义主要用来执行数据的查询操作。它把查询从 DML 里的删除、保存、修改中单独区分出来梳理。DQL 和 DDL、DML 有一个共同点：都不会改变库表本身的物理结构。在此基础上，DQL 还有一个特性——**它不会修改原有的表数据**。

> **定义**：执行一条查询语句时，数据库会生成一张**临时的虚拟表**展示给用户，对底层的原有物理表没有任何影响。无论如何对表执行查询，原有的数据记录都不会发生改变。

这就是查询语句的核心意义。它内部最核心的关键字是 `SELECT`，代表选择与查询，用于从原有表中筛选出所需的数据结构。

### 单表查询和多表查询的差别

查询的分类主要分两类：单表查询和多表查询。

所谓单表，就是查询结果来自**单张**真实的数据库表，通过查询语法最终生成一张虚拟表。

单表查询需要学习的内容包括：作为开篇关键字的 `SELECT` 语法；用于按行筛选数据的 `WHERE` 条件语句；用于结果运算的各种运算符；用于丰富查询结果的内置函数；以及用于对结果进行分组、排序的高级操作。

多表查询并不是把单表查询的语法颠覆掉，它是在单表查询的基础之上**扩展了部分语法**。它的执行过程是这样的：

```text
  单表查询                              多表查询

  表 students                           表 A ──┐
      │                                     ├── 多表合并语法 ──┐
      │                                     │                 │
      ▼                                     表 B ──┘         │
  单表查询语法                                                   │
      │                                                         ▼
      ▼                                                    虚拟的中间表
  ┌─────────┐                                                 │
  │  虚拟表 │                                                 │
  └─────────┘                                                 ▼
                                                   套用单表的查询语法
                                                          │
                                                          ▼
                                                    ┌─────────┐
                                                    │ 目标虚拟表 │
                                                    └─────────┘
```

读图：单表是一条直线，从一张真实表生成一张虚拟表；多表是两步走——先用多表合并语法把多张真实表合并成一张虚拟的中间表，合并完之后，再正常套用单表的查询语句与语法，最终生成目标虚拟表。

所以结论很清楚：**只要学好单表查询，后续多表查询只需要额外掌握合并语法即可**，顺理成章就能拿下来。

### 基础 SELECT 的五种情况

现在进第二小节，讲单表查询的基本语法。基础语法常见于五种场景，我们一种一种来。

#### 非表查询

查询语句通常是对原有物理表做数据筛选、生成虚拟表，但也有特殊场景：查询时不指定具体表，直接快速输出一个结果，类似于 Java 中的控制台打印输出。

```sql
SELECT 1;
```

该语句直接输出数值 1。

```sql
SELECT 9 % 2;
```

该语句直接计算 9 取模 2 的运算结果。

```sql
SELECT version();
```

`version()` 是数据库提供的一个函数，用于获取当前 MySQL 的版本号。加上 `SELECT` 之后，就相当于把这个函数的执行结果打印输出，类似于 Java 中的 `System.out.println` 把函数返回值输出到控制台。

非表查询通常用于快速输出表达式的运算结果或函数的返回值，后面**不需要接 `FROM 表名`**。

#### 指定表查询

第二种场景是指定表查询，语法结构是：

```sql
SELECT 列名1, 列名2, ... FROM 表名;
```

`FROM` 后面指定需要参照查询的目标表，`SELECT` 后面跟上需要从该表中获取的具体列名，多列之间用英文逗号分隔。

学生表中有多个字段，但本次查询只需要展示两列或一列，最终虚拟表的结果就只包含你指定的那些列。书写列名时也可以采用 `表名.列名` 的格式。这种写法在多表查询中极为常用，用来避免多张表中存在同名字段时产生歧义；如果在单表中使用，直接写列名即可，数据库默认会从当前表中定位该字段。

如果需要获取表中的所有字段，可以写成 `表名.*`，也可以直接用通配符 `*`：

```sql
SELECT * FROM 表名;
```

星号通配符代表获取它后方指定表中的所有列——是单表就获取单表的所有列，是多表就获取多表的所有列。各字段在虚拟表中的排列顺序，与查询中书写的顺序保持一致。

#### 给列起别名

第三种场景是在查询时为列起别名。在 `SELECT` 关键字与 `FROM` 关键字之间配置列名，而表名之前可以放很多列名。如果查到一个列以后想给它起个别名，怎么办？用关键字 `AS`：

```sql
SELECT 列名 AS 别名 FROM 表名;
```

最终查到的结果，在虚拟表中会以别名作为基准来显示。

除此之外还可以怎么起？在中间加空格也可以，就是"列名 空格 别名"，这样可以省略 `AS`。但别写逗号——写逗号以后代表的就是多个列了。

为什么非要起别名？我说个场景。假如我们有一个 `student` 表，里面有 `student_id` 这个列，还有 `student_name` 这个列，我们要基于它查一个中间的虚拟表。最终假如我用 Java 语言开发，要把这个虚拟表存到 Java 中的一个类上。Java 中类在命名的时候就不能叫下划线了——假如我有一个 `Student` 类，内部是 `studentId`，用的是驼峰式命名，还有 `studentName`。后期我想让它自动映射，要求列名跟实体类的属性名一致。

现在不一致怎么办？办法就是在查询生成虚拟结果表的时候，**在虚拟结果表里给它起别名**：

```sql
SELECT
  student_id   AS studentId,
  student_name AS studentName
FROM student;
```

这样查到的表里的列名就叫 `studentId`、`studentName` 了，后期可以快速映射到 Java 的实体类上。原因就是数据库列名不等于实体类属性名，你需要给它起个别名，让虚拟结果跟它映射上，方便把数据映射到实体类。大家先记住起别名的语法，这个场景等我们在开发中用到再说。

#### DISTINCT 去重

第四种场景是去重复。有一个关键字叫 `DISTINCT`，它可以对查询出来的这些列的值去重。这边可以写一个列，也可以逗号隔开写多个列；如果写多个列，它就对多列的**综合结果**去重。

举个例子，单列的时候。假如有一个学生表 `student`，里面有 `age` 字段，年龄的值有 1、1、2、2、3、3、4。如果我想查这个表：

```sql
SELECT age FROM student;
```

这代表把表中所有行都拿到，取 `student` 表的 `age` 列。最终查到的虚拟结果里有 1、1、2、2、3、3、4，一共 6 个结果。如果我不想拿这么多，就想知道一共有几种年龄，重复的只出现一遍，只需要在这条语句前面加上 `DISTINCT` 关键字：

```sql
SELECT DISTINCT age FROM student;
```

因为是单列，它就对单列结果去重，最终拿到的结果只有 1、2、3、4。

`DISTINCT` 后面也可以写多列。比如写 `age`，再写一个别的列比如性别 `sex`，它是怎么去重的呢？它用两列的综合结果去重。比如这里有个"1-男"，年龄是 1、性别是男；还有一个"1-女"，年龄 1、性别是女。在查的时候它会把这两行作为一个综合来看，"1-男"和"1-女"这两项不是重复的，最终结果会查到"1-男"，也会查到"1-女"。所以是以两列的综合结果看是否重复才做去重。同样可以再写逗号写多个列，按照那几列的综合结果去重。

> **易错点**：`DISTINCT` 是对结果去重的，**必须加在 `SELECT` 的后边、列名的前方**，后面可以加一个列，也可以加多个列。

#### 查询常数

最后一种场景叫查询常数。查询常数指我们自己造一个数据，伪装一个列放到结果里。查询的时候这个位置可以写列名（列名指的是去表中找到这些列名），另外还可以写常量值，比如写 `'尚硅谷' AS 某一列`。这里边并没有"尚硅谷"这一列，它就是一个常量值，每次查询结果的时候都会多出一列，列里的值就叫"尚硅谷"，相当于人造出来的一个常数列、固定值。

假如我们有一个员工表，里面有员工 ID、有员工的 name。想查所有员工的信息：

```sql
SELECT * FROM 员工表;
```

它会把所有员工的 ID 和 name 两列都拿到。这些员工全是尚硅谷的，我想在查出的结果里再加一列表示它的公司，值全都是"尚硅谷"这个字符串。"尚硅谷"字符串就相当于一个常数，写的时候可以这么做：

```sql
SELECT *, '尚硅谷' AS 公司 FROM 员工表;
```

这样每一个行中都有一个常数列，叫"公司"，值等于"尚硅谷"。

### SELECT 的五种基础写法

准备好以后，我们先把刚才讲的 SQL 结构做一个总结。这里边指的就是**不包含查询条件**，只包含你怎么指定表、指定列以及去重等等，我们一个个来说。

#### 非表查询：拿 SELECT 当计算器

第一个叫非表查询，这个意思就是利用 `SELECT` 关键字快速输出一个运算结果或者函数，它类似于 Java 的控制台输出。它的语法其实很简单，就是：

```sql
SELECT 运算, 函数;
```

后面你可以写运算，多个之间用逗号隔开，还可以写一些函数就可以了。

下方我举个例子，假如说我们要查询一下当前时间。当前时间它是一个函数，它有一个叫 `NOW()` 的函数，你一调用它，就可以获取当前时间。但是你要想把当前时间去输出出来，我们的做法怎么做呢？咱们要写个：

```sql
SELECT NOW();
```

这就是它能获取当前时间，`SELECT` 相当于把它输出到我们虚拟表的结果中，我们就可以看见了。咱们来执行一遍，下面是不是有一个当前时间？这就搞定了。

#### 指定表查询：行全都要，列自己挑

第二叫指定表进行查询，这个是我们最常见的，就是我们在查询的时候，结果是来自于某一张表或者多张表。一张表叫单表查询，多表叫多表查询，对吧？它的语法其实很简单，就是：

```sql
SELECT 列名1, 列名2 FROM 表名;
```

这个位置放的是你要查询表中的哪些列。列写一个列名，逗号隔开，列名逗号隔开，你可以写多列。之后 `FROM` 后面放的是你要参照的表名。这就是我们的语法。也就是说你要把表中所有行都拿到，但是所有行你要拿哪些列呢？在这儿可以指定列相关的顺序就可以了。

大家注意，除了这么写，这些列名直接写就可以了，还有一种写法就是：

```sql
SELECT 表名.列名1, 表名.列名2 FROM 表名;
```

把它都粘过来，放表名点列名。注意可以这么写，表名点列名是可以这么做的。这么做的好处是什么？就是当多表的时候，大家注意，通常一般表名点列名是多表的时候需要这么做。因为多表的列名可能重复。假如说我有两张表，里面都有 `name` 这个列，你直接写 `name` 这个列，那它去哪张表查呢？你前面指定一个表名以后，它就知道去哪个表去查了。

除此之外，还有一个 `SELECT` 通配符就是星号 `*`：

```sql
SELECT * FROM 表名;
```

星号的意思就代表是表中的所有列的含义。大家可以写一个星号代表所有列。当然你也可以写成表名点星号：

```sql
SELECT 表名.* FROM 表名;
```

这也是在多表查询的时候，假如说我有三张表，某一张表的所有列我都要，那你就可以这张表点星号；其他表不要所有列，你就可以其他表名点列名。这就是来指定我们对应的怎么列查询。

下方有两个小练习，我们来练一下。第一个是查询全部员工信息，所谓全部就是全部行、全部列，那它的做法其实可以写成：

```sql
SELECT * FROM t_emp;
```

这不就完毕了吗？来，一执行。咱们看下边结果，是不是所有结果都出来了？当然你也可以写表名点星号也行，但这个绝对是没什么太大必要性，结果也是一样的。除此之外其实还可以怎么做？你还可以一个一个列都写一遍，那这就太麻烦了。大家知道，我们就不用这么做了。这是第一个，查询全部用星号。

第二个，查询全部员工的姓名和工资。大家注意，这也是查询全部员工，但它不要所有的列，它只要姓名和工资。怎么办呢？咱们的做法就是：

```sql
SELECT emp_name, salary FROM t_emp;
```

一个表中如果没有加 `WHERE` 条件，就是所有行数据都要。要了以后，我们要它的姓名，就是 `emp_name`，工资 `salary`，这就代表姓名和工资。当然这两列可以调过来写，就可以了。这样就搞定了。是不是只要两列？完毕。

接下来我们来说第三种场景，查询的时候可以给列起别名，**为了匹配我们后期的 Java 数据格式**。起别名怎么起呢？我们直接说：

#### DISTINCT：按结果列去重

有关键字叫 `DISTINCT`，后面加列名。当然可以写多列，这就代表以多列的结果、综合结果去重，最后写 `FROM` 表名就搞定了。

这么一查的话，就代表查到所有员工的性别，对吧？但其实种类只有两种，是不是男和女？这个怎么去重呢？在前方加上 `DISTINCT`：

SELECT DISTINCT gender FROM t_emp;

这个案例其实并不好，因为这个表发挥空间并不大，所以大家通过这个案例大致理解一下 `DISTINCT` 的作用就行了，后面我们再细说。

> **易错点**：去重一般单独使用。如果去重了，就不要写其它列。假如我在这前面写个 `emp_name`，再写个 `salary`，大家注意，这么写法是不合理的。因为去重它只是对结果去重，它也不知道这个结果到底属于哪个 `emp_name`。

#### 常数列：凭空造一列出来

下方我们有一个需求：查询员工的姓名和工资，并且添加一个 `company` 这一列为“尚硅谷”，大家都是尚硅谷的，表明一下。那怎么办呢？很自然，把上方的直接给它粘过来：

### 六个练习里冒出来的两个坑

最终我们来做这六个练习。大家注意，你就练，疯狂练就可以了。

第一个需求很轻，查询所有员工数据，所有行、所有列：

```sql
SELECT * FROM t_emp;
```

星号代表所有列，所有行后面加个 `t_emp` 就可以了。因为这时候你没有做 `WHERE` 筛选，就代表所有行里面拿到所有列，搞定，第一个就完事了。

第二个需求，查询所有员工信息，并且添加一列 `e_type` 等于“总部”。是不是还是常数列？前面的写法还是固定的，完毕以后下方加啥呢？逗号隔开，来看这儿：

```sql
SELECT *, '总部' AS e_type FROM t_emp;
```

这就搞定了。大家发现是不是多了一个“总部”？但是这里边有个小细节，我给大家演示一下。同样的代码大家看着，我把“总部”这个东西扔到前面去，后面再加个星号：

```sql
SELECT '总部' AS e_type, * FROM t_emp;
```

走，只是调了一个星号和其他列的位置，大家发现是不是报错了？

> **易错点**：如果有星号这种通配符，它必须放在第一位。星号必须放在前方，其他如果你还想写其他列，你往后面放就可以了，这是 SQL 语句的一个标准和规范。

第五个需求把坑挖得更深，我们重点说一说。查询所有员工的姓名、工资、每月奖金、每月总收入。咱们来看，这个表中，我们点开这个表的数据。员工的姓名有了，月薪有了，这儿大家发现它有什么？有一个叫奖金的比例，这个奖金占比，就是说他月薪的 0.65 是奖金，是这个意思吧？

有它以后其实我们能算出来，也就是说奖金占比去乘以月薪是不是等于他的奖金收入？总收入等于谁？总收入是不是等于月薪加上他的奖金值？那我们来看这个东西我们要怎么去做运算。

首先：

```sql
SELECT emp_name, salary, salary * commission_pct, salary + (salary * commission_pct) FROM t_emp;
```

大家注意，这儿可以乘以常量，但也可以乘以你原有的列。这儿乘的就是我们奖金占比这一列。这就相当于奖金。完毕以后下方还有谁？是不是他的一个总薪资？总薪资不就等于 `salary` 加他们俩相乘的一个结果？这就等于他的总薪资了。

我们先来看看这边有没有什么问题，我们来说一下怎么优化。第一步拿到了。但是你发现了，这个名字如果没起别名，是不是用它俩综合做的名字？这太不好看了，我们起个别名。第一个起别名叫姓名，第二个咱们可以省略 `AS`，这可以叫月薪，这个是奖金，后面这个运算完以后空格隔开，它叫月总收入：

```sql
SELECT 
    emp_name AS 姓名, 
    salary 月薪, 
    salary * commission_pct 奖金, 
    salary + (salary * commission_pct) 总收入 
FROM t_emp;
```

接下来我们再把它执行一下。大家发现这是不是就出来了？但出来以后还有一个小问题，我们在这儿提前去做优化。大家发现孙洪亮这个员工，他的月薪是 28000，他的奖金占比我没记错是 0.65，算完最终总薪资是这么多，这个数是没有问题的。但你发现第二个何敬也是没问题，但第三个邓超远就有问题了——你看他的月薪是 8000，但是他没有奖金，奖金是空 `NULL`，总薪资也是空。那这个是为什么呢？

因为这里边有个小细节：因为有些员工没有奖金，那他的奖金占比就是 `NULL`。如果是 `NULL` 的话，大家记住，空运算任何值它都等于空，在 SQL 语句中，你空跟任何运算都空。假如说如果我的奖金占比为空，那工资乘以奖金占比其实奖金值就为空；第二你看，薪水加空，它也等于空。能理解吗？这个等于空的结果是因为你跟空运算了，所以它等于空。

> **结论**：在 SQL 语句中，`NULL` 跟任何值做任何运算，结果都是 `NULL`。

那怎么解决这个方案呢？我再给大家介绍一个函数叫 `IFNULL`，咱们碰到就说。`IFNULL` 是 SQL 语句中提供的函数，第一个要写你的列，第二个写一个为空的时候你给予的默认值：

```sql
IFNULL(列名, 默认值)
```

啥意思？第一个你放个列名，第二个你给空给它一个默认值，它如果是空你想给它什么值。那这里边大家想个问题，如果他这个奖金占比为空，我给的值是不是应该是 0？那这样它就会跟 0 运算，它就得 0，就不会出现空了，能理解吗？

这个默认值完全是你自己定的。除了这以外大家举个例子，假如说我们公司这规定，如果你指定的奖金占比你就有，如果没指定的没关系，我们会有一个基础的，大家都是 0.05，谁都有奖金占比，如果为空没指定的就是 0.05，那这你就写成 `IFNULL(commission_pct, 0.05)`。还有某种场景，举例假如说我们有一个年终奖字段，每个公司大家都有年终奖，如果写了年终奖的值就是你写的值，如果没写大家都是 1000，我写空的，那是 1000，那怎么办呢？就 `IFNULL(年终奖, 1000)`，是不是就可以了？

还是同样这个 SQL 语句，咱们把它稍微变一下。月薪一定不为空就不用管；他的奖金是不是可能为 `NULL`？这块可能为 `NULL`，那你可以这么运算：奖金咱们给它括起来 `IFNULL(commission_pct, 0)`，括了以后，当它等于空的时候这个值等于 0。同样的把这个也放到后边这个运算里，它只要算出一个 0 以后，0 加月薪是不是等于他的总薪资？就可以了。

```sql
SELECT 
    emp_name AS 姓名, 
    salary AS 月薪, 
    salary * IFNULL(commission_pct, 0) AS 奖金, 
    salary + (salary * IFNULL(commission_pct, 0)) AS 月总收入 
FROM t_emp;
```

大家记住，在这一块我们又扩展一个事：第一，如果空跟其他运算都等于空；第二，如果想空算出一个值怎么办？用 `IFNULL` 让它等于 0 再运算就可以了。

### 表结构忘了怎么办：DESC 和 DESCRIBE

刚才我们已经介绍完了基本查询，就是拿到一个表中所有行的数据，怎么去过滤列。接下来我们来讲两点：第一点就是我们来去回顾一下 `DESC` 命令，去看一下这个表结构；第二，我们主要来讲一下查询中的关键——`WHERE` 条件。

先说第一点。在我们写 SQL 语句的时候，我忘这个表中有哪些列了，你也不能老去翻表结构，怎么来看一下呢？可以用两个关键字：第一个是 `DESCRIBE`，这是一个；第二个是 `DESC`，但我推荐使用 `DESC`，它更简洁些。你去后边指定一个表，它下方就会罗列出这个表中一共有哪些列，以及表中列的一些特征。

```sql
DESCRIBE 表名;
DESC 表名;
```

大家看这个效果。我们已经有员工表，那我想看一下员工表中有哪些列，列的类型怎么办呢？你就 `DESC`，表名就行了。之后我们执行一下。

结果中一共是有六个列的选项，我们一个个看：

| 选项 | 看的是什么 |
| --- | --- |
| Field | 表中对应的列名 |
| Type | 列的类型，`int`、`double`、枚举……你可以根据 Type 去判断你的列类型进行如何处理 |
| Null | 这一列能否为空。`NO` 代表不能为空，`YES` 代表可以为空，可以不赋值 |
| Key | 有没有索引、是不是主键。这个后边我们会着重讲，现在我们既没有主键也没有索引，所以这里边都是空 |
| Default | 这一列有没有默认值 |
| Extra | 额外描述，比如 `DEFAULT CURRENT_TIMESTAMP`、`ON UPDATE CURRENT_TIMESTAMP` |

大家发现了各位，就说我们的这个 `gender` 以及那个 `work_place`，这两块是有默认值的。如果说你在插入的时候，这两列你不传值，它会走默认值，而其它列是没有默认值的。

最后下方那个额外描述大家可能还记得，我们在讲这个时间类型的时候，如果时间类型你想加一个什么呢？自动在插入的时候去更新时间，或者保存的时候去更新时间，那相当于就是你对这一列除了类型以外还有一个额外的描述，`DEFAULT CURRENT_TIMESTAMP` 或者是 `ON UPDATE CURRENT_TIMESTAMP`。这个相当于就是如果有额外的描述，它会在这个位置进行展示；若无，这就不展示。

所以最终你通过看这六个选项，你就能明白这一个列中它的一个所属的一个状态，最终你在查询的时候，你可以针对性处理就可以了。

### WHERE：先筛行，再选列

这个是重点，这是重点，叫过滤条件。大家别看它只有一个简单一个语法，就是一个 `WHERE`，但这是重点。

我们在查询一个表的时候，各位不能、也很少会查询一个表中的所有行，一般都会有过滤。就像我们说的，查询身高大于多少的学生信息；查询性别为男的学生信息；查询分数大于多少的分数信息。大家想想，这些所谓的过滤条件都是在 `WHERE` 后边进行添加的。

> **定义**：`FROM` 是来指定表名的，`SELECT` 只是你 `WHERE` 生效以后的行、你要行中哪些列。它并不来做这个结果过滤，它只是说拿到行中的哪一列，它并不影响拿到哪些行，而 `WHERE` 会去做行的筛选。

下方我给大家准备了一个小动画，给大家演示一下这个效果。比如说第一个，我们有一个表，假如说一共有四行数据：

```text
   t_emp 原始 4 行数据
          |
          v
   [WHERE] 逐行判断条件，每行只得出 真 / 假
          |  假、假、真、真
          v
   留下的行：行3、行4
          |
          v
   [SELECT] 从留下的行里指定要哪几列
          |  假设只要前两列
          v
   行3、行4 的前两列
```

也就是说，`WHERE` 是每行都检查你的条件是否符合、符合、不符合。每行比较完以后，它只会有一个结果 `true` 或者 `false`，或者 1 或者 0。符合的话，我们就单独给它再筛选出来。假如说这里边只有两条符合，1、2 符合，那最终你的结果中就 1、2 行。拿到 1、2 行以后，接下来你再用 `SELECT` 的后边，根据它指定的列名，再去完成筛选。假如我只要前两列，那最终结果呢就前两列，就是前两行的前两列。

> **结论**：`WHERE` 的执行顺序是优先于 `SELECT` 的。大家要有这种感觉。

说完以后，我们来做条件查询的总结。啥意思呢？就是对表的行数据进行筛选，符合条件的行再进行结果列的查询——先筛选再查询。它的语法，我们知道，就是 `SELECT` 后边依然写列信息，你该怎么写怎么写；后边 `FROM` 后边依然放表信息，只不过在后边加个 `WHERE` 条件：

```sql
SELECT 列信息 FROM 表名 WHERE 条件;
```

它里面可以有一个、多个条件。之前我们大概也提过，它的条件里面可以加 `AND` 或者 `OR`，或者是一或等等进行拼接，最终形成一个综合的结果。最终这些条件的整合的结果，它只有一个值，要不然就是 `true`，要不然就是 `false`。最终若 `true` 这行就要，若 `false` 这行就不要。要的行才能去查对应的 `SELECT` 的列的信息。

好嘞，那我总结作用：

| 子句 | 作用 |
| --- | --- |
| `FROM` | 指定参照和查询的表 |
| `WHERE` | 进行表中行的数据筛选，注意它的执行早于 `SELECT` |
| `SELECT` | 对符合条件的行，再进行数据列的筛选 |

我们把上面这些查询给它过一过。第二个需求，查询工资高于 9000 的员工信息。大家注意，这里边条件是工资高于，高于不就是大于吗？那就是说员工信息，它也没有指定哪些列，那代表查询所有列：

```sql
SELECT * FROM t_emp WHERE salary > 9000;
```

它的做法，大家记住，它会先去根据你指定的表——现在表是哪个？员工表。接着它会逐行去比较这个条件。举例，第一行李红，工资大不大 9000？不大，那这行就被 pass 掉，最终的结果就没有这一行。第二行，大不大 9000？不是，依然 pass，一直 pass。pass 到哪一块？有没有大于 9000 的？那这个其实也没有大于 9000，它是 9000。最后到了这个吉日格勒，好嘞，它是大于 9000 的，那这行是要的。要完这行以后，它接着走什么呢？`SELECT` 你要选择哪些列，那所有列就拿这一行的所有列。是这么来的，先选行再选列。心里一定要清晰，行是最基本的抽取单位。

完毕以后看下方第三个需求，查询工资高于 20000 的员工的姓名、薪水和年薪。那这个做法就是：

```sql
SELECT emp_name, salary, salary * 12 AS 年薪 FROM t_emp WHERE salary > 20000;
```

大以后的各位，要哪些列？你就按这写。要什么？要员工的姓名、`salary`，年薪是啥？叫 `salary` 乘以 12。但如果说你觉得这一列不好看，你 `AS` 起个名字叫年薪，是不是就可以了？最后这个就出来了。所以前面是对结果、符合结果的列进行筛选的。

接下来下方这个是两个条件的，查询工资高于 8000 且性别为女的员工信息。员工信息代表所有的、所有列是吧？那我们写法就是：

```sql
SELECT * FROM t_emp WHERE salary > 8000 AND gender = '女';
```

那这个位置是大于多少？大于 8000。还有一个要写啥？叫 `gender` 等于女。那多条件之间大家记住，我们用什么呢？`AND` 或者 `OR`，或者异或。那这是“且”，是 `AND` 的关系。但大家不着急，这些所谓的中间这些细微运算符，我们在下节细化去讲。

### 算术运算符：既能出现在列位置，也能出现在条件里

那接下来我们来讲一下第三点，叫运算符的使用。在本次章节我们会讲解常见的数学运算符，以及比较运算符，以及逻辑运算符。这一节先把算术运算符细细地说一说。

算术运算符其实跟我们之前其它语言接触过的都差不多，它可以将列或者两个值进行数学值的运算。常见的这种算术运算符有以下几种：加、减、乘、除、取模。

在标准的 SQL 语句中，它给我们提供了几种对应的运算符，我们来看看：

| 运算 | 写法 | 说明 |
| --- | --- | --- |
| 加 | `+` | |
| 减 | `-` | |
| 乘 | `*` | |
| 除 | `/` | 浮点除，会计算出小数点后边的几位 |
| 除 | `DIV` | 整数除，自动丢掉小数部分，保留除后的整数部分 |
| 取模 | `%` | |
| 取模 | `MOD(被除数, 除数)` | |

首先取模它提供了两个：一个是百分号 `%`，一个是我们的 `MOD`。但是百分号可能就是在 Java 基础也好、其它语言也好，它用的也是这个。`MOD` 是 SQL 语句中提供的一种。注意，这两者都是标准的运算符，也就是说它们俩的作用都是一样的，都是做取模运算的，两种都可以。

接下来除呢它提供了两个，这块大家要简单看一眼。这个除，第一个就是我们正常的一个除号 `/`，这个除是一个浮点除，就是说它会计算出你除出来的一个小数点后边的几位，就是算出是个浮点值。而第二个 `DIV`，这个是一个整数除，它会自动去掉小数部分，保留它除后的整数部分的值。这是它们俩的区别。

> **结论**：这里的运算符可以出现在 `SELECT` 的列的位置——你在查询的时候 `SELECT` 某一个列你可以做运算；当然它也可以出现在 `WHERE` 条件后边，对 `WHERE` 条件后边的列或者值进行运算以后再进行比较，都是可以的，两个位置都可以出现。

那接下来我们来演示一下这几个加减乘除的基本使用，这相当于出现在列的位置，叫非表查询。直接去用这些运算符来算一下，来看这个结果：

| 表达式 | 结果 |
| --- | --- |
| `100 + 0` | 100 |
| `100 + 50` | 150 |
| `100 + 50 - 30` | 120 |
| `100 + 35.5` | 135.5 |
| `3 * 5` | 15 |
| `3 * 5.0` | 15.0 |
| `3 / 5` | 0.6 |
| `100 / 0` | `NULL` |
| `5 DIV 2` | 2 |
| `-5 DIV 2` | -2 |
| `100 / (1 - 1)` | `NULL` |
| `5 % 2` | 1 |
| `MOD(5, 2)` | 1 |
| `-5 % 2` | -1 |

大家注意 `100 + 35.5`，它正常如果碰见浮点类型了，它就会变成浮点类型 135.5；`3` 乘以 `5` 是 15，而 `3` 乘以 `5.0`，乘以浮点类型就会变成浮点类型，所以变成 15.0。

而下方各位这边是 100 除以 0，大家注意，100 除以 0，正常除 0 是报异常的，对吧？除 0 异常。但是在这个 SQL 语句中它不给你报异常，它除以 0 的话，它的返回结果就是 `NULL`，大家记住了吗？

再下方用 `5 DIV 2`，这种除法是整数除，它会去掉小数部分，它得的结果就是 2。负的 5 除以 2 它是负 2。

那下方 100 除以括号 1 减 1，那大家应该知道，括号这个东西，它相当于是把优先级提升，它是最先进行计算的。那也就说括号优先级第一，那就 1 减 1 得 0，那 100 除以 0 还是不报除 0 异常，但它返回的结果是 `NULL`。

说完了以后，我们再回到这个 PPT，大家看这个注意事项：

- 运算符的优先级就跟我们之前学习的一致，就是你的乘除法要高于加减法，这些运算符优先级都一致。如果你想要提升优先级，可以使用括号包裹起来。
- 如果运算中有浮点类型，那它的结果就是浮点类型；如果参数都是整数类型，它就是整数类型。
- 斜杠除和 `DIV` 的除区别，就是斜杠是浮点除法，而 `DIV` 是整数除法。
- 如果出现除以 0 的情况，返回值是 `NULL`，而不是抛异常。

而下方各位它还给出了取模，就说这取模我们就不用直接看了，就是 5 模 2 那不就等于 1 吗？`MOD(5, 2)` 也是等于 1，就它俩的运算形式是一样的。负的就等于负 1 就可以了。两种取模运算都是一样的。而且百分号和 `MOD` 都是关系型数据库的标准用法，所以说你喜欢哪个就选哪个。

说完了以后我们一样也是做几个练习。这四个需求看着眼熟，其实就是把这几个运算符往两个位置里塞：前两个练习把运算放到 `WHERE` 后边，先算出一个数、再拿它跟阈值比较；第三个练习把运算放到列的位置上，就是我们刚试过的奖金数额；第四个练习用取模判断奇偶——取模 2 等于 0 就是偶数，奇数呢就等于 1。运算符一共有这几个，最需要注意的就是除法和除 0 的时候要注意一下。

### 本讲提到的题目

#### 基础 SELECT 的六个练习

**查询所有员工数据。** 所有行、所有列。没有 `WHERE` 就是所有行，用星号拿所有列：

```sql
SELECT * FROM t_emp;
```

**查询所有员工信息，并且添加一列 `e_type` 等于“总部”。** 前面照旧，最后造一个常数列。注意星号必须打头：

```sql
SELECT *, '总部' AS e_type FROM t_emp;
```

**查询所有员工的姓名、工资和工作地址。** 这就相当于指定列：

```sql
SELECT emp_name, salary, work_place FROM t_emp;
```

**查询所有员工的姓名、月薪、年薪，年薪等于月薪乘以 12，将字段变为中文的姓名、月薪和年薪。** 也就是说你不仅要运算，还要起个别名：

```sql
SELECT emp_name AS 姓名, salary 月薪, salary * 12 AS 年薪 FROM t_emp;
```

**查询所有员工的姓名、工资、每月奖金、每月总收入。** 奖金等于月薪乘以奖金比例，总收入等于月薪加上奖金，`NULL` 的那一行要用 `IFNULL` 兜住：

```sql
SELECT 
    emp_name AS 姓名, 
    salary AS 月薪, 
    salary * IFNULL(commission_pct, 0) AS 奖金, 
    salary + (salary * IFNULL(commission_pct, 0)) AS 月总收入 
FROM t_emp;
```

**查询一共有几种薪资。** 有的是 5000 的、7100 的、8000 的，两个 8000 就算一种，这很明显就是去重：

```sql
SELECT DISTINCT salary FROM t_emp;
```

`DISTINCT` 要单独用，前面不要再带别的列。

#### WHERE 条件的四个练习

**查看员工表信息。** 用 `DESC`（或 `DESCRIBE`）看表结构。

**查询工资高于 9000 的员工信息。** “员工信息”没有指定列，代表所有列：

```sql
SELECT * FROM t_emp WHERE salary > 9000;
```

**查询工资高于 20000 的员工的姓名、薪水和年薪。** 先筛行，再从留下的行里取列：

```sql
SELECT emp_name, salary, salary * 12 AS 年薪 FROM t_emp WHERE salary > 20000;
```

**查询工资高于 8000 且性别为女的员工信息。** “且”用 `AND`：

```sql
SELECT * FROM t_emp WHERE salary > 8000 AND gender = '女';
```

#### 算术运算符的四个练习

**查询薪资和奖金、薪资奖金和大于 20000 的员工。** 运算出现在 `WHERE` 后边，奖金比例可能为空要用 `IFNULL` 兜成 0，不然整个条件都是空：

```sql
SELECT * FROM t_emp WHERE salary + IFNULL(commission_pct, 0) * salary > 20000;
```

**查询工资减去奖金的差小于 8000 的员工。** 做法跟上面类似，就是把加号换成减号：

```sql
SELECT * FROM t_emp WHERE salary - IFNULL(commission_pct, 0) * salary < 8000;
```

**查询所有员工的姓名、工资和奖金数额。** 查所有员工就没有 `WHERE`，运算回到列的位置：

```sql
SELECT emp_name, salary, salary * IFNULL(commission_pct, 0) FROM t_emp;
```

**查询工资金额、工资编号是偶数的员工。** 怎么判断奇偶数呢？其实这是一个经典的问题，是吧？取模嘛。取模 2 如果等于 0 是不是就是偶数啊：

```sql
SELECT * FROM t_emp WHERE emp_id % 2 = 0;
```

以上就是我们讲的一些基本查询，没有 `WHERE` 条件，就是对一个表中所有的列、所有的行数据进行查询以后的一个处理。大家把这个东西来练一练。

## 条件是一个一个拼起来的：比较运算符、逻辑运算符与函数分类
> 对应块：BLK08 | 覆盖分集：P39-P43 | 块标题（分集名）：《39-数据查询篇-比较运算符介绍和总结》

### 先把那张符号表认个脸

接下来我们来介绍一下比较运算符。咱们看一下左侧——这一屏从上到下排下来的符号不少：大于、大于等于、小于、小于等于、不等于、等于、安全等于、空值判断、区间、范围、模糊匹配……十几个挤在一起，猛一看是挺容易懵的。别慌，我带着你把这张表从左往右捋一遍；捋完你会发现，真正需要额外留神的其实只有一类，就是跟 NULL 有关的那几个。

| 符号 | 含义 | 备注 |
| --- | --- | --- |
| `>` `>=` `<` `<=` | 大于、大于等于、小于、小于等于 | 这几个大家都看得懂 |
| `<>` / `!=` | 不等于 | `<>` 是标准写法；`!=` 是 MySQL 迎合其他语言提供的方言。两种在 MySQL 里都能用，推荐 `<>` |
| `=` | 等于 | 一个等号，不是两个等号 |
| `<=>` | 安全等于 | 效果跟 `=` 一样，但能比较 NULL；它也是方言，不推荐 |
| `IS NULL` / `IS NOT NULL` | 为空 / 不为空 | 判断空值就用它俩 |
| `BETWEEN AND` / `NOT BETWEEN AND` | 在两值闭区间内 / 不在区间 | 前面放小值，后面放大值 |
| `IN` / `NOT IN` | 在给定的若干个值里 / 不在 | 多个值用逗号隔开 |
| `LIKE` / `NOT LIKE` | 模糊匹配 / 不匹配 | 配通配符 `%` 和 `_` |

> **结论**：比较运算的结果只可能是 1、0、NULL 三种。1 就代表 TRUE，0 代表 FALSE，NULL 在数据库看来也是 FALSE 的含义。

除了这三条，还要提前知道一件事：**比较的时候如果两边类型不一样，MySQL 会把字符串自动转成数值再来比**。所以字符串 `'1'` 等于数值 `1`，结果照样是 TRUE。也就是说写等号这类比较时，你不用太操心类型，碰到字符串它自己会转。

> **提示**：不是"不写就不用管"，而是"不用你先手动转"。真正需要小心类型的是两边**都是字符串**的时候——那时候它不转，会按字符串比。这一点后面演示不等号的时候会看到。

### 等于号的两种写法，以及 NULL 为什么咬不动

`=` 和 `<=>` 长得很像，但本事差一截。我们直接上终端看：

```sql
SELECT 1 = 0;          -- 0        1 当然不等于 0
SELECT '0' = 0;        -- 1        字符串自动转成数值 0，结果相等
SELECT 0.0 = 0;        -- 1        浮点和整型，值相同就算相等
SELECT '0.1' = 0.01;   -- 1        字符串转成 0.1，和 0.01 相等
SELECT 1 = 1;          -- 1
```

再来看安全等于：

```sql
SELECT 1 <=> 1;        -- 1        和普通等号一样
SELECT NULL <=> NULL;  -- 1        安全等于能比较空值，结果是 TRUE
SELECT NULL IS NULL;   -- 1        换一种写法，效果完全一样
SELECT 1 IS NULL;      -- 0        1 不是空
SELECT 1 <=> NULL;     -- 0        1 不等于空
```

把等号换回来，问题就暴露了：

```sql
SELECT NULL = NULL;    -- NULL（数据库里按 FALSE 看）
SELECT 1 = NULL;       -- NULL（数据库里按 FALSE 看）
```

大家听我说：一个等于号是**不能做空比较的**。`NULL = NULL` 不会给你 TRUE，只会给你 NULL，说白了 NULL 在我们数据库看来就是 FALSE。

> **易错点**：想做空值判断，用 `IS NULL`（为空）和 `IS NOT NULL`（不为空）。`NULL <=> NULL` 虽然也是 TRUE，但那是方言——所谓方言就是 MySQL 支持、其他标准数据库未必支持的那种写法。记不住安全等于，就记 `IS NULL` 这一条：它是"普通话"，任何标准关系数据库都认。

### 不等于、区间与范围

#### 不等于：两边都是字符串的时候，它不转数值

```sql
SELECT '0.1' <> '0.01';  -- 1    两边都是字符串，按字符串比，确实不相等
SELECT '0.1' <> 0.1;     -- 0    一边字符串一边数值，字符串转成 0.1，两边相等
SELECT 'jap' <> 'japp';  -- 1
```

第二条最值得看。为什么它返回 0（FALSE）？因为 `0.1` 是数值，`'0.1'` 会自动转成数值 `0.1`，两边本来就相等，你说不等于，它当然返回 0。

> **定义**：两个都是字符串，就按字符串比；只要有一边是数值，字符串就被转成数值再比。

#### 区间：`BETWEEN AND` 是闭区间，而且前面必须放小值

```sql
SELECT 2 BETWEEN 1 AND 3;   -- 1    1、2、3 都算，2 在里面
SELECT 2 BETWEEN 2 AND 3;   -- 1    两边都能取到，闭区间
SELECT 1 BETWEEN 2 AND 3;   -- 0    1 不在 2 和 3 之间
SELECT 2 BETWEEN 3 AND 1;   -- 0    反向区间，这里面是没有 2 的
SELECT 'b' BETWEEN 'a' AND 'c';  -- 1  字符串会转成 ASCII 编码比，b 排在 a 和 c 之间
```

记住两点：`BETWEEN AND` **左闭右闭**，两头都算；**前面放小值，后面放大值**，写反了就等于给了个空区间。第一个例子里写的那个 `2`，后面我们可以把它换成列名，就相当于"某列的值在这个区间内"。

#### 范围：`IN` 是"给定的几个值"，还能成组比

```sql
SELECT 2 IN (0, 3, 5, 7);            -- 0    里面没有 2
SELECT 'wef' IN ('we', 'wef', 'wf');  -- 1    对上了
SELECT 1 NOT IN (2, 3);              -- 1    不在里面，取反后是 TRUE
SELECT 'a' NOT IN ('a', 'b', 'c');   -- 0    在里面，取反后是 FALSE
```

`IN` 和 `BETWEEN AND` 的区别一定要分清：`BETWEEN 1 AND 5` 指 1、2、3、4、5 都行；`IN (1, 5)` 只指 1 或者 5 这两个值。

`IN` 还有一个别的区间没有的本领——**成组比较**：

```sql
SELECT (3, 4) IN ((1, 2), (3, 4));  -- 1   有一组对上了
SELECT (3, 4) IN ((1, 2), (3, 5));  -- 0   没有一组跟它值相同
SELECT (3, 4) IN ((4, 3), (3, 4));  -- 0   按顺序一对一对上，顺序换了就对不上
```

写法是：前面写几个值就用几个括号括起来成一组，`IN` 里面每一组也各自加括号。举个例子，假如我要查"工资和奖金都相同"的员工记录，两列同时相等，写法就是这种成组对比。它是**按位置一对一对上**的，所以 `(3, 4)` 跟 `(4, 3)` 不算同值。

#### 一次比多列：把整行括起来对

有些语法糖你了解一下就行，真要用的时候我不推荐：

```sql
(a, b) = (x, y)      -- 等价于：a = x AND b = y
(a, b) <=> (x, y)    -- 等价于：a <=> x AND b <=> y
(a, b) <> (x, y)     -- 等价于：a <> x OR b <> y
```

记住这个反差点：**用等号的时候，中间相当于"且"的关系；用不等于的时候，中间其实是"或"的关系**。安全等于跟等于一个道理，只不过它能做空判断。万一第一种写法你记不好，你就踏踏实实用 `AND`、`OR` 连起来，一个错都没有。

### 模糊查询：一个百分号顶一半的难题

模糊查询主要用来做字符串的模糊匹配。什么场景需要它？比如你想查**姓张的学员**，你只知道他姓张，完整名字不知道；再比如查手机号 **138 开头**的人。这种"只知道一部分"的活儿，就得交给 `LIKE` 和 `NOT LIKE`。

它靠两个通配符，先记下来：

- **百分号 `%`**：匹配任意多个字符，1 到 $n$ 个都算；
- **下划线 `_`**：只匹配任意**一个**字符。

不理解没关系，看几个例子就明白了：

```sql
SELECT 'aaa' LIKE '%';    -- 1    任意个字符，3 个 a 当然匹配得上
SELECT 'aaa' LIKE '_';    -- 0    一个下划线只吃一个字符，3 个字符匹配不了
SELECT 'aaa' LIKE '___';  -- 1    三个下划线对三个字符，正好
SELECT 'abc' LIKE '_a%';  -- 0    第一位随便，第二位要求是 a，而它是 b
SELECT 'abc' LIKE 'a__';  -- 1    首位 a 匹配上了，后两位任意
SELECT 'abc' LIKE '%c';   -- 1    最后一位是 c 就行，前边无所谓
```

`'_a%'` 那条最值得琢磨：下划线代表"这一位有一个字符，是啥不用管"，所以第一位没问题；可第二位你写死了一个 `a`，它就要求第二位必须是 a，而实际是 b，所以 FALSE。**下划线是"随便一个"，普通字符是"就必须是它"**，这两者的区别就是这一条的全部要点。

落到实际场景上，假设有一列叫 `name`：

```sql
name LIKE '张%';   -- 姓张：张三、张麻子、张巴拉巴拉都行
name LIKE '张_';   -- 只有两个字且姓张：张三、张四、张五
name LIKE '_伟';   -- 第二位是"伟"，而且总共就两个字
```

第三位如果你不写，它就代表"就两位、第二位是伟"。后面**再补一个百分号**，意思就变成：第一位是啥不用管，第二位是伟，后边有几位随便，有没有都行，可以匹配 0 到 $n$ 个字符。这就是模糊查询。

还有一类更常用的：查询手机号以 138 开头的。当我们建表时就知道 `tel` 一共 11 位，前 3 位固定、后 8 位不固定，可以这么写：

```sql
SELECT * FROM t_emp WHERE tel LIKE '138________';  -- 八个下划线
SELECT * FROM t_emp WHERE tel LIKE '138%';          -- 一个百分号，等价
```

这么写有点让人懵圈，把八个下划线换成一个百分号是不是方便多了？后边是几位我不管，只要前面是 138 就行。

### 把符号表再捋一遍

刚说的可能你也没记住多少，没事，我们打开思维导图快速过一遍，这几个场景平时碰得最多：

- **等于对比**：`=` 和 `<=>`。区别就一条——`=` 不能做空判断，`NULL = NULL` 得不到 TRUE；`<=>` 除了做普通值判断，还能做空判断，`NULL <=> NULL` 返回 TRUE。但它是方言。真想做等于判断，**推荐 `IS NULL`**，这是标准语言。
- **不等于对比**：`<>` 和 `!=`。`<>` 是标准语法，`!=` 是 MySQL 的方言——有些数据库也支持，但不代表所有标准数据库都支持。
- **大小比较**：`>`、`>=`、`<`、`<=`，这个不用记了。
- **空值处理**：为空 `IS NULL`，不为空 `IS NOT NULL`。
- **区间处理**：`BETWEEN AND`，前面小值后面大值，写 `1` 和 `5` 就表示 1、2、3、4、5 都行；不在区间内就加个 `NOT`。
- **范围处理**：`IN` 和 `NOT IN`。`IN` 里面可以写多值，$x, y, z$ 就代表你是 $x$ 或者 $y$ 或者 $z$ 都可以，效果等于：

```sql
k = x OR k = y OR k = z
```

`NOT IN` 指的是不在这些值里，任意一个都不行。

- **模糊匹配**：`LIKE` 和 `NOT LIKE`。当你不知道准确值、只知道一部分的时候用它。前面正常写列名 $k$，后面是"你知道的部分"：想找姓赵的，第一个字知道是"赵"，后边不管，就写 `k LIKE '赵%'`；想找第二个字是"伟"的，第一位写个下划线，第二位写"伟"，`k LIKE '_伟'`；第三个你不管，就写个百分号，代表任意；不写百分号，它就是两位。

> **结论**：这些比较符号要掌握住，实在记不住安全等于和 `!=`，就死记 `IS NULL` / `IS NOT NULL` 这一条和 `<>` 这一个推荐写法。

### 十三道练习：把比较符号挨个用一遍

光看不用手会骗人，下面十三道题我们挨个过一遍。都是老套路——`SELECT *` 全查，`WHERE` 后面挂条件。

**1. 查询员工编号为 1 的员工信息**

```sql
SELECT * FROM t_emp WHERE eid = 1;
```

没说查哪些列，那就 `*` 查全部。第二个写法也查得出来：

```sql
SELECT * FROM t_emp WHERE eid = '1';
```

因为 `eid` 拿到数据库里是数值，你这边写字符串，它自动转成数值再比。

**2. 查询薪资大于 5000 的员工信息**

```sql
SELECT * FROM t_emp WHERE salary > 5000;
```

`WHERE` 之前跟上面一模一样，只不过后面换了个符号。

**3. 查询有奖金的员工工资信息**

什么叫"有奖金"？这一列的值只要不是空，那就是有奖金，做个非空判断就行：

```sql
SELECT * FROM t_emp WHERE comm IS NOT NULL;
```

**4. 查询没有奖金的员工信息**

```sql
SELECT * FROM t_emp WHERE comm IS NULL;
SELECT * FROM t_emp WHERE comm <=> NULL;  -- 安全等于也能查出来
```

那能不能用等于号判别呢？

```sql
SELECT * FROM t_emp WHERE comm = NULL;    -- 查不出来
```

等于号是无法做空判断的，这就是两种等于的区别。到这儿大家能理解了吧？查有奖金和没奖金的，就是这一个差别。

**5. 查询出生日期在这两个值之间的员工信息**

```sql
SELECT * FROM t_emp WHERE birthday BETWEEN '1990-01-01' AND '2000-01-01';
```

时间就是特殊的格式字符串，直接带上单引号写就行。

**6. 查询性别为女性的员工**

```sql
SELECT * FROM t_emp WHERE gender = '女';
```

**7. 查询手机号以 138 开头的员工**

```sql
SELECT * FROM t_emp WHERE tel LIKE '138________';  -- 或 tel LIKE '138%'
```

**8. 查询邮箱以 `@atguigu.com` 结尾的员工**

刚才是查以谁开头，现在反过来查以谁结尾，写法是类似的，列名换成 `email`：

```sql
SELECT * FROM t_emp WHERE email LIKE '%@atguigu.com';
```

前面是什么我们不用管，前面写个百分号就行。

**9. 查询地址为空的员工**

```sql
SELECT * FROM t_emp WHERE address IS NULL;
```

**10. 查询工作地点在北京、上海、深圳的员工**

```sql
SELECT * FROM t_emp WHERE work_place IN ('北京', '上海', '深圳');
```

工作地点有三个区域，任意一个区域里就算符合。这里**不能写"或"**，要逗号隔开，任意一个命中就行。

**11. 查询姓张的员工**

```sql
SELECT * FROM t_emp WHERE emp_name LIKE '张%';
```

姓张就是以张开头，后边张三、张二麻子、张狗子都无所谓。

**12. 查询出生日期不在这个区间的员工**

```sql
SELECT * FROM t_emp WHERE birthday NOT BETWEEN '1990-01-01' AND '2000-01-01';
```

前面写"在"是 `BETWEEN`，这儿写"不在"，就加个 `NOT`，没什么好练的。

**13. 查询不是男的员工**

这一题我想跟大家强调个事。很多同学会写成 `gender = '女'`，答案是对的，但**思维是错的**。我们感觉男和女互斥呗，但你不能自行把 SQL 翻译成反对立面，你还是要用数据去说话。万一你这张表里去泰国的某个门店还记了第三种值呢？

它说是啥，我们就直译写啥：

```sql
SELECT * FROM t_emp WHERE gender != '男';
SELECT * FROM t_emp WHERE gender <> '男';
```

两种都能用，很多同学学过 Java，习惯性用 `!=`，在 MySQL 里也是一样的。

> **易错点**：写 SQL 有个禁忌点——**不能自行把条件翻译成"反对立面"**。查询"不是男的"就老老实实写"不等于男"。

最后补一题常客：查询员工编号为奇数的信息。奇数不就是取模 2 等于 1 吗？

```sql
SELECT * FROM t_emp WHERE eid % 2 = 1;
```

### 逻辑运算符：AND、OR、NOT 与 XOR

接下来我们进入到课程的 3.5 章节，讲讲逻辑运算符——如何利用逻辑运算符将多个条件进行拼接。

标准 SQL 里提供了以下四种逻辑运算符：

| 运算符 | 写法 | 含义 |
| --- | --- | --- |
| `AND` | `&&` | 逻辑且，两边都为 TRUE 结果才为 TRUE |
| `OR` | `\|\|` | 逻辑或，任意一方为 TRUE 结果就为 TRUE |
| `NOT` | `!` | 反转，把对应条件的结果取反 |
| `XOR` | — | 异或，双方一为 TRUE、一为 FALSE 时结果才为 TRUE |

> **定义**：在数据库里，只要**非空且非 0** 的值，结果就为 `TRUE`；`0` 或者空，则当作 `FALSE`。数据库中 TRUE 的表达值是 1，FALSE 的表达值是 0。

也就是说 `NOT 10` 结果是 FALSE（10 非 0 非空，按 TRUE 算，取反就变 FALSE，展示的值是 0）；`NOT 0` 结果是 TRUE（0 或空都是 FALSE，取反成 TRUE，展示的值是 1）。

### 把 TRUE 和 FALSE 摆上台面看一遍

我们直接用值来演示这几种关系：

| 表达式 | 结果 | 为什么 |
| --- | --- | --- |
| `NOT 10` | 0 | 10 按 TRUE 算，取反成 FALSE |
| `NOT 0` | 1 | 0 是 FALSE，取反成 TRUE |
| `1 AND 1` | 1 | 两个 TRUE，结果 TRUE（`10 AND 10` 同理） |
| `1 AND 0` | 0 | `AND` 要求双方都 TRUE |
| `1 OR 1` | 1 | 有 TRUE 就是 TRUE |
| `1 OR 0` | 1 | 一边 TRUE 一边 FALSE，OR 依然是 TRUE |
| `0 OR 0` | 0 | 两边都是 FALSE |
| `1 XOR 1` | 0 | 两边同为 TRUE，异或不成立 |
| `1 XOR 0` | 1 | 一 TRUE 一 FALSE，异或成立 |
| `NOT 1` | 0 | 1 是 TRUE，取反成 FALSE |

多个条件当然也能连起来。三个条件的时候：

```text
1 XOR 1 XOR 1  →  1
```

它按顺序运算：先算第一个 `1 XOR 1`，两边都是 TRUE，结果为 0；再拿这个 0 去异或最后一个 1，正好一 FALSE 一 TRUE，结果为 1。

> **提示**：我们这里是直接拿 TRUE、FALSE 对应的值来演示的。真正写查询时，每个条件可以是一整个比较表达式，它们算出来的结果就是 TRUE 或 FALSE，最后再用 `AND`、`OR`、`NOT`、`XOR` 把它们连到一起。

> **结论**：逻辑运算符的主要作用，就是把多个条件结果综合起来连到一起运算，最终生成**一个**结果。

### 逻辑运算实战：FIND_IN_SET 登场

语法已经在上面列全了，下面进练习。这一轮练习里会冒出一个新函数，我们边做边说。

**1. 查询工资大于 5000 且工作地点包含北京的员工**

两个条件，中间是"且"。`salary > 5000` 没问题，第二个条件就有意思了：

```sql
SELECT * FROM t_emp WHERE salary > 5000 AND work_place LIKE '%北京%';
```

要先说清楚 `work_place` 这列当初建表时是个 `SET`，但真正存到数据库里，底层它就是一个字符串。如果写成 `work_place = '北京'`，那在"北京,上海"这种值上能匹配上，可"上海,深圳"就不算北京了——可这人确实有一个工作地点在北京。所以等于号查不出来，得用模糊查询加百分号，只要里面包含北京就行。前后两个百分号，意思就是前面有啥不管、后面有啥不管，中间有北京就命中。

除了这种做法，还有一种更正规的。我们的数据库里专门有一个处理 `SET` 类型的函数，叫 **`FIND_IN_SET`**：

```sql
SELECT ename, FIND_IN_SET('北京', work_place) FROM t_emp;
```

它的语法是：第一个参数放你要找的值，第二个参数放 `SET` 那一列；返回结果只有 1 或 0——1 代表这个值出现过，0 代表没有。上面这条查出来返回 1 的那个员工，证明他这里面包含北京；有 0 就代表没包含。

用进条件里就是这样：

```sql
SELECT * FROM t_emp
WHERE salary > 5000 AND FIND_IN_SET('北京', work_place) = 1;
```

能不能不用 `LIKE`？能，答案就在这里。

**2. 查询奖金比例为空或者地址为空的员工**

两个空值判断，"或"的关系：

```sql
SELECT * FROM t_emp WHERE commission_pct IS NULL OR address IS NULL;
```

空有两种判断法——`IS NULL` 是一种，还有一种是我们说不太标准的 `<=> NULL`。这边我们用标准 SQL 语法。两个条件之间是"或"，写 `OR` 就行（写成两个竖杠 `||` 也一样，但通常大家记英文指令就够了）。

> **易错点**：我在这儿第一次写的时候，`FROM` 后面漏了个 `WHERE` 关键字，直接就报错了。**报错和没有结果是两回事**——没有结果可能只是没数据，报错是你 SQL 写错了。报错信息里会告诉你 `near 'LIKE' 附近` 之类的提示，检查检查就知道是哪儿漏了关键字。

**3. 查询生日在某日期之前，或者薪资小于 4000 的员工**

```sql
SELECT * FROM t_emp WHERE birthday < '1985-01-01' OR salary < 4000;
```

之前一说到日期我就有点懵。记住"在某日期之前"就是"比它更早"，时间相对当前时间是小于，1984 年当然比 1985 年早。时间是能正常用比较符号比的，格式字符串带上单引号就行。

**4. 查询性别为男且工作地点不包含上海的员工**

```sql
SELECT * FROM t_emp WHERE gender = '男' AND FIND_IN_SET('上海', work_place) = 0;
```

`FIND_IN_SET` 返回 0 就代表没出现，那就是"不为上海"。

**5. 查询工资大于 6000，或者邮箱以 `@tom.com` 结尾的员工**

```sql
SELECT * FROM t_emp WHERE salary > 6000 OR email LIKE '%tom.com';
```

查结尾，前面不管，加百分号，把结尾那段粘过来就行。

**6. 查询工作地点为上海，或者薪资小于 4500 的员工**

```sql
SELECT * FROM t_emp WHERE FIND_IN_SET('上海', work_place) = 1 OR salary < 4500;
```

**7. 查询员工编号为偶数且地址不为空的员工**

```sql
SELECT * FROM t_emp WHERE eid % 2 = 0 AND address IS NOT NULL;
```

`eid` 为偶数就是取模 2 等于 0；先做算术运算，运算完再用比较符号，最后再跟 `AND` 接上。查非空的标准写法就是 `IS NOT NULL`。

**8. 查询性别为女，或者薪资小于等于 5500 的员工**

```sql
SELECT * FROM t_emp WHERE gender = '女' OR salary <= 5500;
```

**9. 查询工资大于 5000，且工作地点为上海或北京的员工**

这里面的关系是"两个或"再用"且"挂起来：

```sql
SELECT * FROM t_emp
WHERE salary > 5000
  AND (FIND_IN_SET('上海', work_place) = 1 OR FIND_IN_SET('北京', work_place) = 1);
```

怎么让它俩先运算呢？咱们学数学不是有个叫什么？括号。**用括号括起来，优先级会更高，先执行**。括号里先算出一个 TRUE 或 FALSE 的"或"结果，再拿它跟工资条件做"且"的运算。

> **提示**：括号是优先级最高的东西。运算符优先级那一章我们马上讲，但这一条你现在就得记住——它是"让某些条件先算"的终极绝招。

**10. 查询姓名中包含 b 且地址为空的员工**

```sql
SELECT * FROM t_emp WHERE ename LIKE '%b%' AND address IS NULL;
```

前后各一个百分号，中间有个 b，只要名字里含 b 就行。执行时可能一条都没查到，这很正常，但语句本身没报错。

### 运算符优先级：括号说了算

第三节最后，我们把运算符之间的优先级简单介绍一下。

这张表里罗列了我们介绍过的所有运算符，编号从 1 排到 14。这里有个特别容易看反的地方：**不是编号越小优先级越高，而是编号越大优先级越高**。也就是说 `NOT` 的优先级最高。

了解优先级有什么用？记住两条规则就够了：

1. **优先级相同，从左到右依次运算**；
2. **优先级不同，先算优先级高的**。

为什么要分优先级？问大家一个问题：$5 + 5 \times 5$ 等于多少？打出来是 30，不是 50。因为它先算了乘，再算了加。

不过要真记不住也没关系，记住**终极绝招：括号**。哪个想让它先运算、想让它独立运算，给它加个括号就完了，优先级自然就最高了。

从高到低，这个阶梯长这样：

```text
优先级从高到低
  │
  │  ①  括号  ( )              最高。括号能改变任何优先级，终极绝招
  │  ②  取反 / 取非  NOT、负号(−)
  │  ③  乘、除、取模   *  /  %
  │  ④  加、减         +  −
  │  ⑤  比较运算符      =  <>  >  <  BETWEEN  IN  LIKE ……
  │  ⑥  逻辑运算符      AND  OR  XOR (连接多个条件的那种)     最低
  │
```

注意第 ② 条和第 ⑥ 条的区别：第 ② 条说的是**取反、取非**（比如 `1 + 1` 前面取个非），它优先级高得离谱；第 ⑥ 条说的是**把多个条件连起来**的逻辑运算，它必须等前面全算完才能动，所以最低。

几个例子走一遍：

- `SELECT NOT 1 + 1;` 结果是 1。为什么？`NOT` 优先级高，先把 1 取反——1 是 TRUE，变成 FALSE 也就是 0；0 + 1 最终等于 1。
- 乘除的例子：先算乘法再算加法，算出来是 3。同样的道理，加减的优先级低于乘除：

$$2 \times 3 = 6,\quad 6 + 1 = 7,\quad 7 \ge 2 \Rightarrow \text{TRUE}\ (1)$$

- 逻辑运算符最低，因为它得把多个比较运算符都算好了才能做逻辑运算。比如两个条件先各自算完，再用 `AND` 串起来，只要有一个是 FALSE，结果就是 0。

下面两道小练习，大家可以把视频暂停，在公屏上先打出结果再往下看。

**第一题，结果是 −0.5。** 外层括号里还套着括号，套括号的那层优先级最高，先算出 `−3`；接下来负号的优先级高于乘除，于是 $-3 \times 2 = -6$，再 $+5$ 得 $-1$；最后是浮点除法，$-1 \div 2 = -0.5$。写的时候记住"负值只作用于它后面紧跟的那个数"，别让负号跑到整个结果外面去。

**第二题，结果是 0。** 外面一个大括号把 `NOT` 和三个条件括住了，先执行括号里面的。里面用 `AND`、`OR` 把三个条件分开，而 `AND`、`OR` 优先级最低，所以先把每个条件算完：第一个是加法先于比较运算符，$3 + 1 = 4$，再拿 4 去比 4，结果 TRUE（1）；第二个 $5 > 2$，TRUE；第三个也是 TRUE。三者都成立后按从左到右运算，`AND` 那两个 TRUE 还是 TRUE，再 `OR` 上 TRUE 还是 TRUE——括号里最终是 TRUE。出了括号，外面的 `NOT` 再取一次反，就变成 FALSE 了，所以 result2 是 0。

> **提示**：这里演示优先级用的虽然是表达式，但放到 `WHERE` 后面是完全一样的道理。

到这里，第三章的运算符我们就讲完了——算术运算符、比较运算符、逻辑运算符，以及它们之间的优先级。符号是有点多，但你把这个 SQL 语句都练一遍，把比较符号再记一遍，问题不大。

> **结论**：看到任何一个运算符符号，你需要能**清晰地判断它优先级大致在哪个位置**，这是这一章真正要带走的东西。记不住就加括号。

### 函数：SQL 里被封装好的那点功能

接下来我们进入查询的第四章节，单行函数和多行函数的介绍。

在进这一章之前，先回忆一下——我们之前已经用过一些函数了，比如处理空值的 `IFNULL`，比如处理 `SET` 类型的 `FIND_IN_SET`。SQL 语句里的函数跟我们其它语言里的函数作用完全一样，它相当于**对某项功能的一个封装**，我们直接拿它去解决相关问题。

具体点说：你向函数输入一些相关的参数，函数执行完毕以后给你返回一个结果，这就是一个函数。

函数分两个来源：

- **内置函数**：数据库提供好的，我们拿来直接用就行，比如 `IFNULL`；
- **自定义函数**：数据库也允许，但这门课我们只讲内置函数，自定义的不提。

函数方法会非常多，但整个 SQL 语句大致把它们归纳成两大类：**单行函数**和**多行函数**。常见的这些——数值函数、日期函数、流程函数、时间函数、信息函数、聚合函数、字符串处理函数——全都归到这两类里。

```text
SQL 里的函数
├─ 内置函数    IFNULL、FIND_IN_SET …… 拿来就用（本课只讲这一类）
└─ 自定义函数  本课程不展开

内置函数按生效范围再分两类
├─ 单行函数   数值 / 日期 / 时间 / 流程 / 信息 / 字符串 ……
│             对查出来的每一行里的某个字段单独生效
└─ 多行函数   聚合函数：平均数、最大数、最小数 ……
              对所有符合条件的行一起统计，最后只产出 1 个结果
```

> **定义**：单行函数与多行函数的区别，**指的是函数生效的位置和范围**。单行函数对单行数据生效——我查了一条数据，这条数据里某个字段需要处理，就可以用单行函数去处理；多行函数的作用范围是多行，它是一种统计性的函数，要把所有符合条件的行一起做最终运算，单行是拿不到这个结果的。

举个例子，假如我查一条数据的时候，还想顺带展示一下当前的查询时间，那就用时间函数 `NOW()` 去获取当前时间。它把这个作用到你这一行的数据上，结果也放在你的单行结果里，这就是在单行生效。

多行函数也就是聚合函数，一般**单独使用，或者配合我们的分组来使用**。

> **结论**：记住这一条就够——**除了聚合函数，剩下的都是单行函数**。

## 单行函数实战：数值、字符与时间函数
> 对应块：BLK09 | 覆盖分集：P44-P49 | 块标题（分集名）：《44-数据查询篇-数值函数和实战》

学数据库的人大多有别的语言底子，所以第一次看到单行函数那张长长的列表时，第一反应往往不是"不会用"，而是"这名字怎么这么眼熟"。

确实眼熟。常用数学函数的命名，跟你学过的语言里那些做数学处理的函数基本是同一套路子。学别的语言时你记过一次，这里等于白捡一遍。后面字符函数、时间函数也是这个调性——我们只需要把 SQL 这一套特有的约定讲清楚。

先从数值函数开始。

### 数值函数：名字都是从别的语言搬来的

幻灯片左侧把常用数学函数罗列了出来，我们只说标蓝的那些。

`ABS` 取绝对值，这个不用讲。紧挨着它的那个函数更进一步：你传一个值进去，它判断这值到底是个正值还是负的——正值返回 1，负值返回 -1，零就返回 0。`PI` 取圆周率，3.1415926。

真正要留神的是取整那一组。`CEIL` 向上舍入，给它一个浮点数，它还你一个整数，而且是往上取的：32.3 得到 33。

> **易错点**：负数要格外小心。`CEIL(-32.3)` 得到的是 **-32**，不是 -33。因为 `CEIL` 是往"正"的方向取整，不是把绝对值取整了再补个负号。

`FLOOR` 正好反过来，向下舍入，名字就是"地板"（floor）的意思：32.3 得到 32，-32.3 得到 -33。往下这一侧，负数同样要留意：取的才是更小的那个。

再往下两个是用来在一把值里挑最小值和最大值的，手上有多个值的时候拿它们来用。`MOD` 取模，前面我们已经用过关键字形式的写法，封装成函数是一回事。

`RAND` 取 0 到 1 之间的随机数。它可以带一个参数，而这个参数的意思跟你在别的语言里的经验不一样。

> **提示**：`RAND` 的参数是**种子**，不是"随机数上界"。同一个种子算出来的随机数序列完全相同。

举个我们公司年会抽奖的例子：管理层有俩副总裁，谁都清楚这俩人的中奖概率得一样——你不能一个中一个不中，太难看。可随机数又没法让两个人撞上，怎么办？给这俩人在 `RAND` 里填**相同的种子**，他们各自算出来的随机数就是同一个数了，中奖概率自然一致。

> **结论**：`RAND(x)` 里的 `x` 是种子，不是范围上限。连续调用两次 `RAND(8)`，两次结果一模一样；下次再调，只要还是 8，还是一样的。我管这叫"一种作弊手段，就非随机了"——你把随机给固定住了，大家都一样。

对比一下：Java 里那一类随机数方法传个 `x`，含义是"生成 0 到 x 之间的随机数"；SQL 里这个 `x` 换了个身份，别搞混。

舍入的两个函数挨在下面。`ROUND` 跟 `CEIL`、`FLOOR` 有点像，但方向不一样：`CEIL` 一律向上，`FLOOR` 一律向下，`ROUND` 是四舍五入。给它 35.4 得到 35，给它 35.6 得到 36。`ROUND` 还能带第二个参数，写作 `ROUND(x, y)`，前边放要处理的数，后边 `y` 指的是要保留几位小数——它同样是按小数位四舍五入往上进位的。

`TRUNCATE` 跟 `ROUND` 长得几乎一样，也是 `TRUNCATE(x, y)`，`y` 代表小数位，但**唯一的区别是不四舍五入、直接截取**：不管后边小数位是什么，只截到你要的那一位，后面的一概不往四舍五入上凑。

> **易错点**：`ROUND` 四舍五入，`TRUNCATE` 直接截取——这是这两个函数唯一的差别，其余完全一致。`ROUND(2.36, 1)` 得 2.4，`TRUNCATE(2.36, 1)` 得 2.3。

上面这些讲完，脑子里大概率还是糊的。切到小海豚（客户端），我们把语法再捋一遍，然后一条 SQL 直接跑出来看。

单行函数可以直接用 `SELECT` 验证，不挂表、不写查询列，直接在语句里写表达式就行。语法复述一遍：`ABS` 取绝对值；`CEIL` 向上取整，`FLOOR` 向下取整；`RAND` 是随机数，带种子时相同种子出相同值；`ROUND` 单独一个参数是四舍五入取整，`ROUND(x, y)` 是保留 `y` 位小数、其余四舍五入；`TRUNCATE(x, y)` 保留 `y` 位但直接截取。

```sql
SELECT ABS(-5),
       CEIL(2.3),
       CEIL(-2.3),
       FLOOR(2.3),
       FLOOR(-2.3),
       RAND(),
       RAND(8),
       RAND(8),
       ROUND(2.3),
       ROUND(2.36, 1),
       TRUNCATE(2.36, 1);
```

结果一个一个对：

- `ABS(-5)` 是 5，没问题；
- `CEIL(2.3)` 是 3，天花板往上取；
- `CEIL(-2.3)` 是 **-2**——-2 比 -3 大，向上取就是要取更"正"的那个。前面刚强调过，别记成 -3；
- `FLOOR(2.3)` 是 2；
- `FLOOR(-2.3)` 是 -3，往下取自然取更"负"的那个；
- `RAND()` 随手甩出一串 0 点几；
- 两个 `RAND(8)` 结果一模一样，因为种子都是 8；
- `ROUND(2.3)` 是 2，小数部分连 5 都不到，往哪儿进位；
- `ROUND(2.36, 1)` 是 2.4，保留一位，末尾那个 6 往上进了一位；
- `TRUNCATE(2.36, 1)` 是 2.3，同样保留一位，但它只截不动。

还有一个细节值得说：**函数是可以互相套用的**，这跟你在其他语言里把函数套函数是一个道理。假设现在手上有个随机值，想让它保留两位小数，怎么办？套一层 `TRUNCATE` 就行。

```sql
SELECT TRUNCATE(RAND(), 2);
```

出来是 0.15 这类值。`TRUNCATE` 第一个参数是 `RAND()`，第二个参数 2 表示截取两位小数——这就是函数套函数，完全合法。数值函数到这儿就讲完了。

### 字符函数：长度、拼接和 FIND_IN_SET

轮到字符函数。同样是左侧列表里标蓝的那几个。

`CHAR_LENGTH` 返回字符数，你给它放个字符串，它告诉你有几个字符。`LENGTH` 看着像它的双胞胎，其实干的是另一件事：它返回的是这段字符**占的字节数**。

> **提示**：`CHAR_LENGTH` 数字符，`LENGTH` 数字节。因为一个字符占几个字节跟字符集有关，所以这两个结果很可能对不上，别当成同一个函数用。

`CONCAT` 是比较常用的一个，把多个字符串拼起来，后面做模糊查询会经常用到它。举个前端传参的例子：前端传了一个模糊查询的关键字过来，我需要在它前后各加一个百分号再拿去匹配，怎么办？把关键字内容放中间，前后写上百分号，用 `CONCAT` 直接拼到一起去就行。比如传过来的关键词叫"娃娃"，那就 `CONCAT('%', '娃娃', '%')`。

> **提示**：为什么不在 SQL 里直接写死 `'%娃娃%'`？因为前端传过来的一般只是匹配关键字本身，不会把百分号一起带上——百分号得由后端拼。

`SUBSTR` 是字符串截取：前面给一个字符串，`index` 是你要开始截取的下标，`len` 代表截取的长度。剩下还有一些大家自己扫一眼就行，我单独拎一个出来说：`FIND_IN_SET`。

这个函数我们前面用过，我当场还纠正了自己之前的说法——**`FIND_IN_SET` 是去 `set` 这种数据中去找有没有你指定的数据，有就返回它的下标。**说得再直白些：第二个参数 `s2` 是一段 `set` 格式的数据，也就是逗号隔开的一串字符串；你在里面找第一个参数 `s1`，找得到就把它的下标给你。有人说不懂啥意思，一会儿跑一遍就明白了。

语法层面有三个点要记住：

- `y` 是一种 `set` 数据格式，书写时它就是一个字符串，各个值之间用逗号隔开；
- 它找的是目标**处在逗号之间哪个位置**；
- 下标**从 1 开始**，而且**只找到第一个就终止**。

把客户端打开，语法再过一遍：`CHAR_LENGTH` 放一个字符或者对应的列都行，返回字符数；`CONCAT` 放多个字符，完成拼接；`FIND_IN_SET(s, y)` 就是去 `y` 里找 `s` 出现在哪个位置。

然后写出来执行：

```sql
SELECT CHAR_LENGTH('abc'),
       CONCAT('%', '娃娃', '%'),
       FIND_IN_SET('aa', 'cc,dd,aa,bb,gg,aa');
```

- `'abc'` 是 3 个字符，所以返回 3；
- 第二个拼出来就是 `%娃娃%`；
- 第三个在 `cc,dd,aa,bb,gg,aa` 里找 `aa`，逗号隔开的每个元素算一个位置，从 1 开始数，`aa` 排在第 3 位，所以返回 3。至于串末尾还藏了一个 `aa`，它压根不关心——找到第一个就收工了。

我认为常用的就是这三个：`CHAR_LENGTH` 算长度，`CONCAT` 拼字符串，`FIND_IN_SET` 在逗号串里定位。其余的心里有个印象，用到再回来查。字符函数也讲完了。

### 时间函数：分成四类来认

时间函数明显比前两族多，一个篇幅讲不完。所以一开始我就把它们分成了四类，我们顺着这个分类来认：拿当前时间、提取时间里的某一段、时间加减运算、时间格式化。抓住分类，就不容易乱。

#### 拿当前时间

第一类是取"此刻"。`CURRENT_DATE` 和 `CURDATE` 效果一样，返回 `date` 类型的当前时间，也就是年月日。`CURRENT_TIME` 返回当前的时分秒。`NOW` 和 `SYSDATE` 返回的是当前系统的完整年月日和时分秒。

再往下是 UTC 系列的。UTC 是世界标准时间，它**不考虑时区**。我们处在东八区，用 UTC 取出来的时间会比本地时间少 8 个小时。而上面那几个会考虑当前系统所在的时区，算出来就是你所在时区的当下时间。

> **提示**：记不住就记标蓝的——`CURRENT_DATE` 和 `NOW`，两个足够覆盖日常。UTC 那一套了解原理就行，实际业务里尽量别用。

切到小海豚之前，先把这几个语法收一下：要完整的年月日时分秒，记一个 `NOW()` 就够；要年月日，记 `CURRENT_DATE()`；要当前的时分秒，`CURRENT_TIME()`。下边 `UTC_DATE()`、`UTC_TIME()` 不考虑时区，在中国区用会少 8 小时，因为它按 0 时区在算。

#### 提取时间里的年、月、日和星期几

第二类是把一个时间拆开，拿里面某一段。

这批函数最好记的地方在于命名：基本就是英文原词，你把时间往里一扔，它就把对应的那一段取出来。`YEAR` 提年，`MONTH` 提月，底下依次是提时、分、秒的。

> **提示**：`WEEK` 值得单独拎出来说。大学里排课基本是按周排的——今年第几周上什么课。要判断 5 月 5 号是今年第几周，用的就是 `WEEK`，它给你算出这个日期是一年中的第多少周。

举个例子。员工表里有生日字段，现在想统计 5 月份过生日的员工。生日可能是 2000 年 10 月 10 号填的，光看这个值你判断不出他是不是 10 月份过生；把生日字段往 `MONTH` 里一扔，出来个 10，就知道他属于 10 月份了。

`DAY` 提取的是一个月中的第几日；旁边还有提小时、分钟、秒的，跟上面一路货色。另外还有一个 `DAYOFYEAR`，算的是一年中的第几天。

星期这块有两个函数要分清楚：

- `WEEKDAY` 返回星期几，**0 是周一，6 是星期日**；
- `DAYOFWEEK` 也是星期几，但它那套编号是**1 是星期日，2 是星期一**，一路排下去，7 就是星期六。

两套编号，作用一样，取值不同。此外还有返回英文月份的、返回星期英文名字的写法，跟 `MONTH`、`WEEKDAY` 这类返回数字的正好对应；`DAYOFMONTH` 则是提取一个月中的第几天，作用跟 `DAY` 一样。

现在把上面两类函数写进一条 SQL 一次跑掉。前面五列取当前时间，后面几列做时间提取，讲到哪看到哪：

```sql
SELECT
    NOW(),
    CURRENT_TIME(),
    CURRENT_DATE(),
    UTC_DATE(),
    UTC_TIME(),
    YEAR(NOW()),
    MONTH(NOW()),
    WEEK(NOW()),
    WEEKDAY(NOW()),
    DAYOFWEEK(NOW()),
    DAY(NOW()),
    DAYOFMONTH(NOW());
```

结果逐个对：

- `NOW()` 拿到完整的当前时间，假设是 17:23；
- `CURRENT_TIME()` 也是 17:23，跟你此刻所在的时间对得上；
- `UTC_DATE()` 的日期看不出差别，因为差的那 8 小时还没跨天；
- `UTC_TIME()` 是 9——正好比 17 少了 8 个小时。这就是世界标准时间，跟本地时区时间不是一回事，所以大家尽量别用；
- `YEAR(NOW())` 提取出年；
- `MONTH(NOW())` 是 4，月份从 1 开始数，这就说明是 4 月；
- `WEEK(NOW())` 是 15，今年第 15 周。我当场感慨了一句：今年已经过去了将近四分之一；
- `WEEKDAY(NOW())` 是 5，因为这天是周六——0 是周一往后数，周六正好落在 5；
- `DAYOFWEEK(NOW())` 是 7，它那套编号 1 是星期日，星期六排在 7。俩都能拿到星期几，区别只在表示的值；
- `DAY(NOW())` 是 20；
- `DAYOFMONTH(NOW())` 也是 20。写的时候手滑把 `DAYOFMONTH` 敲成了 `DAYOFWEEK`，当场发现改了回来，跑完发现俩结果一样。

> **结论**：这一堆里只有"星期几"存在两套编号，其他提取日期的方式结果都相同。直接记英文单词就好——它们本来就是不同版本迭代出来的不同方法，作用是一条心。真要查入职满几年、租约还剩多久，最常用的两个是 `YEAR` 和 `MONTH`。

#### 时间加减，以及两个时间点之间隔多久

第三类是做时间运算。举个生活里的例子：我想算 8 天以后是星期几——比如我约了 8 天后的牙医，得先算出当前时间加 8 天是多少，再用上一节的提取函数（比如 `DAYOFWEEK`）提出星期几。所以这一类就是教我们怎么做时间加减的。

这一类里最重点的是加减函数，它们成对出现：

- `DATE_ADD` 和 `ADDDATE` 一对，效果一样，完成时间的加；
- `DATE_SUB` 和 `SUBDATE` 一对，效果一样，完成时间的减。

参数结构完全一致，拆开看四段：

- 第一个参数是**锚点**，也就是你要基于哪个时间做加减；
- 逗号隔开，后面跟着关键字 `INTERVAL`——我给这个关键字开了个玩笑，说它是"乌龟的屁股——规定"，反正就是个固定写法，别写成别的；
- 再后面是**表达式**，可以放正值也可以放负值。想算 5 天以后就写 5；
- 最后跟一个**时间单位**，就是时间的英文单词：5 天写 `DAY`，5 个月写 `MONTH`，5 年写 `YEAR`。

> **提示**：只记 `DATE_ADD` / `ADDDATE` 这一个就够，减法靠负号。`ADDDATE(..., INTERVAL 5 DAY)` 是 5 天以后，`ADDDATE(..., INTERVAL -5 DAY)` 就是 5 天以前。正值代表未来的时间，负值代表以前。当然你非要记 `SUBDATE` / `DATE_SUB` 也没错，用法跟加法一模一样，只不过它填正值才是减。

再往下几个也得知道。`ADDTIME` 是拿秒数去加时间的：前一个参数给时间，后一个参数给秒数，正值就是多少秒以后，负值就是多少秒以前。比如 `ADDTIME('10:10:10', 10)` 得到 10:10:20，填 -10 就得到 10:10:00。`SUBTIME` 跟它是反着的——用它写正的秒数是减，写负的秒数才是加。记住一条规律就够了：加减的符号自己看着办，不用背。

`DATEDIFF` 我认为特别重要：它算两个**日期**之间隔了多少天。比如过年还有几天，把当前时间和过年那个时间节点往里一放，天数就出来了。

`TIMEDIFF` 是算两个**时间**之间的间隔，出来的结果是时、分、秒。比如 12:00:00 到 10:00:00，间隔两小时。

所以这一类要记的其实就两个：一个 `DATE_ADD` 或 `ADDDATE` 负责加减，一个 `DATEDIFF` 负责算天数。

这批函数还是一条 SQL 一起验。我第一次写的时候把 `NOW` 忘加括号，当场自己念叨了一句"函数都得用括号"，改过来才往下走：

```sql
SELECT
    ADDDATE(NOW(), INTERVAL 1 MONTH),
    ADDDATE(NOW(), INTERVAL -1 MONTH),
    ADDTIME('10:10:10', 20),
    DATEDIFF(CURRENT_DATE(), '2024-11-11'),
    TIMEDIFF('12:00:00', '10:00:00');
```

- 第一列，当前是 4 月 20 日，加一个月变成 5 月 20 日；
- 第二列，加法写负值当减法用，减一个月变成 3 月 20 日。当然你写 `SUBDATE(..., INTERVAL 1 MONTH)` 也一样；
- 第三列，10:10:10 加 20 秒变成 10:10:30；
- 第四列有点意思：结果是 **-205** 天。`DATEDIFF` 的顺序是大值放前面、小值放后面，`CURRENT_DATE()` 减去 2024-11-11 自然是负的。**有时候你并不确定两个时间谁大谁小，怎么办？套一层 `ABS`**，把绝对值取出来，这函数前面刚讲过；
- 第五列，两个时间点之间差两小时，出来是 `02:00:00` 这种时分秒形式。

#### 时间格式化

第四类只有三个函数，而且前两个作用类似、第三个正好跟它们相反。

`DATE_FORMAT` 和 `TIME_FORMAT`：给定一个时间类型，按你指定的格式把它提取成对应的字符串。标准的时间类型长什么样？`DATE` 的标准格式就是年-月-日，用 `-` 隔开。但我输出的时候未必想这么输出，比如我就想让它输出"2024年04月20日"——这就叫把标准时间格式化成自定义字符串，这两个函数干的就是这件事。一个管日期，一个管时分秒。

参数结构一样：前边放时间，后边放 format，也就是格式化字符串，你想格式化成什么样就写什么样。**这个跟 Java 里的 `SimpleDateFormat` 作用是一样的。**

第三个 `STR_TO_DATE` 刚好反过来：把一个**非标准的时间字符串**转成标准的时间类型。举例说前端要按时间查数据，如果它传过来的是"2024年04月20日"这种非标准格式，在数据库里是没法直接做比较的——要比，就得先把它变成 `2024-04-20` 这种标准格式，于是就要用 `STR_TO_DATE`：前面放那个非标准的字符串，后面放它对应的格式。

所以前两个是"时间转字符串"，这个是"非标准字符串转时间"，方向完全相反。

> **提示**：想只取出年月日，其实有两条路。笨办法是用 `YEAR`、`MONTH`、`DAY` 逐个提取，再用 `CONCAT` 拼起来——那太麻烦了。直接用 `DATE_FORMAT` 一把梭，方便得多。

格式怎么写？这里跟 Java 不一样，不是 `yyyy-MM-dd`：

| 占位符 | 含义 |
| --- | --- |
| `%Y` | 四位的年 |
| `%y` | 两位的年 |
| `%M` | 英文的月份 |
| `%m` | 两位的月，`01`、`02`、`03` |
| `%d` | 两位的日 |
| `%D` | 带序数后缀的日，一般不用这种 |
| `%H` | 小时，24 小时制 |
| `%h` | 小时，12 小时制 |
| `%I` | 小时，12 小时制（大写） |
| `%i` | 分，两位 |
| `%s` / `%S` | 秒，两位，大小写都一样 |

分为什么是小写的 `i`？因为大写的 `I` 已经被 12 小时制的小时占用了。

```sql
SELECT DATE_FORMAT(NOW(), '%Y-%m-%d');
SELECT DATE_FORMAT(NOW(), '%Y年%m月%d日');
SELECT TIME_FORMAT(NOW(), '%H:%i:%s');
```

- 第一条，从 `NOW()` 里把年月日提出来，`%Y` 是四位年、中间一个 `-`、`%m` 是两位月、`%d` 是两位日，出来就是标准日期；
- 第二条，把分隔符换成中文的"年月日"，一样能提出来。**可见中间不一定非写 `-`**，完全按你的格式来，你想让时间长什么样它就给你长什么样；
- 第三条用 `TIME_FORMAT` 提时分秒：小时是大写 `%H`（24 小时制），分是小写 `%i`，秒是 `%s`，大小写都行。

我敲第一条的时候把函数名写成了没有下划线的 `DATEFORMAT`，当场说了句"是不是中间有下划线的？这儿有下划线，因为它没变成粉色嘛，这就对了"——这个细节其实很实用：客户端里函数名没高亮，就说明拼错了。

再说最后一个 `STR_TO_DATE`：

```sql
SELECT STR_TO_DATE('2024年04月20日', '%Y年%m月%d日');
```

输出变成了 `2024-04-20`。前边那个字符串是前端传来的、不标准的带中文时间；后边那个格式串必须和它**一模一样**——原串里是 `%Y年%m月%d日`，那格式串里也得把"年""月""日"三个字原样写上，数据库才知道哪儿是年、哪儿是月、哪儿是日。转成标准时间之后，你才能拿它去做比较、去做时间运算。

> **结论**：`DATE_FORMAT` 和 `TIME_FORMAT` 是把标准时间转成你指定格式的字符串；`STR_TO_DATE` 是把非标准的时间字符串，按你写明的那个格式，转回标准时间，专治"前端传了个没法比较的时间"。格式串的口诀就一条：四位年大写 `%Y`、两位月小写 `%m`、两位日小写 `%d`、24 小时大写 `%H`、分小写 `%i`、秒 `%s` 或 `%S`。

### 四类时间函数，记住这些就够

时间函数是这一大块里最杂的，讲完之后值得摊开再收一遍。

| 类别 | 解决什么 | 重点记 |
| --- | --- | --- |
| 获取当前时间 | 拿系统此刻的日期与时间 | `NOW()`、`CURRENT_DATE()`、`CURRENT_TIME()` |
| 时间提取 | 从一个时间里拆出年、月、日、周几、一年中的第几周 | `YEAR`、`MONTH`、`DAY`、`WEEK` |
| 时间运算 | 时间点做加减、算两个时间点之间隔多久 | `DATE_ADD` / `ADDDATE`、`DATEDIFF`、`TIMEDIFF` |
| 时间格式化 | 时间与字符串互相转换 | `DATE_FORMAT`、`TIME_FORMAT`、`STR_TO_DATE` |

几个记法的要点再强调一下。提取类基本都是英文原名，把时间往里扔就行，不用死背。运算类**只记一个 `DATE_ADD` 或 `ADDDATE` 就够**——`SUB` 那一套完全可以不记，因为加个负号本来就是减。另外把 `DATEDIFF`（算间隔天数）和 `TIMEDIFF`（算间隔时分秒）一起记下。格式化类先记方向：前两个是"时间→字符串"，`STR_TO_DATE` 是"非标准字符串→标准时间"，再把那串 `%Y`、`%m`、`%d`、`%H`、`%i`、`%s` 的口诀念熟。

### 本讲提到的题目：五道时间函数练习

时间函数多到一个篇幅讲不完，所以这一讲还专门留了五道练习，全部围绕员工表 `t_emp` 的生日字段 `birthday` 展开。我们一一去实现一下，下面的解析和答案都来自现场演示。

**查询今天过生日的员工信息。** 今天是 04-20，也就是 2024 年 4 月 20 日。今天过生日的意思是：年份肯定对不上，年份一过去就不复返了，只要月和日这两位对得上就算。

解析：把生日的日提出来跟今天的日比，再把月提出来跟今天的月比，两个条件同时成立。`DAY` 负责从 `birthday` 里提出日（今天是 20 日），`NOW` 取当前时间、再由 `DAY(NOW())` 提出当前是第几日；`MONTH` 同理提出月份。提取出来一对比，没有就没有。

```sql
SELECT * FROM t_emp
WHERE DAY(birthday) = DAY(NOW())
  AND MONTH(birthday) = MONTH(NOW());
```

还有一种更省事的写法，用格式化把年月日都剥掉，只留月和日。`%m` 提月、`%d` 提日，两边格式化成同一个形状再比：

```sql
SELECT * FROM t_emp
WHERE DATE_FORMAT(birthday, '%m-%d') = DATE_FORMAT(NOW(), '%m-%d');
```

两种方案都可以。

**查询本月过生日的员工信息。** 这个相对简单，只提一个月就够了。把日的条件去掉，生日的月份跟当前月份相同，就是本月过生日：

```sql
SELECT * FROM t_emp
WHERE MONTH(birthday) = MONTH(NOW());
```

跑出来有几个，都是 4 月份过生日的。

**查询下月过生日的员工信息。** 下个月就是当前 `MONTH` 提出来的 4 加 1 变成 5，条件写成等于 `MONTH(NOW()) + 1` 就行：

```sql
SELECT * FROM t_emp
WHERE MONTH(birthday) = MONTH(NOW()) + 1;
```

跑出来是 5 月份过生日的那批。这个做法相当于把当前提取出的月份加 1，就等于下个月。

还有一种做法：能不能把当前时间本身再加一个月？可以，但不太合理。演示一下那个时间运算函数——获取当前时间，给它加上一个月，再提取月份：

```sql
SELECT * FROM t_emp
WHERE MONTH(birthday) = MONTH(DATE_ADD(NOW(), INTERVAL 1 MONTH));
```

跑出来也能得到 5。这道题正好把上一节的 `DATE_ADD` 用上了，权当复习，但还是前面那个加 1 的写法更方便。

**查询员工姓名、工资和年龄，保留小数点一位。** 表里没有年龄列，但有生日。年龄怎么来？生日到今天隔了多少天，除以 365，就是一个粗略的年龄。

解析：用 `DATEDIFF` 算间隔天数，当前时间是大值放前面、`birthday` 放后面；算出来的天数除以 365 就是年龄。问题是除完有四位小数，要保留一位怎么办？还记得吗，可以用 `TRUNCATE` 截断，也可以用 `ROUND` 四舍五入。我这里选四舍五入：

```sql
SELECT
  ename,
  salary,
  ROUND(DATEDIFF(NOW(), birthday) / 365, 1) AS age
FROM t_emp;
```

注意要把整个除法用括号括起来，括完之后再逗号写 1，`ROUND` 才会按 1 位小数去四舍五入。跑出来是 43.6 这类值。到这儿前面学的 `DATEDIFF` 和 `ROUND` 全串起来了。

**查询年龄在谁和谁之间的员工信息。** 年龄已经会算了，"在谁和谁之间"就是拿两个边界把它包起来。注意这个比较表达式放哪儿都行——放在查询列里，或者放在 `WHERE` 后面，都可以：

```sql
SELECT * FROM t_emp
WHERE DATEDIFF(NOW(), birthday) / 365 BETWEEN 25 AND 35;
```

`BETWEEN AND` 是闭区间，大于等于 25、小于等于 35。年龄落在这个区间里的员工就被筛出来了。题目里那两个边界换成别的数也一样，改 `BETWEEN` 两头的数字就行。

这就是时间函数，练习就练到这儿。

## 流程控制函数、聚合函数与分组查询
> 对应块：BLK10 | 覆盖分集：P50-P53 | 块标题（分集名）：《50-数据查询篇-流程控制函数介绍》

一说到流程控制函数，大家一定不陌生。只要是学过 Java 的同学就知道，在 Java 语言基础部分，最重要的内容之一就是流程控制——`if...else`、`switch...case`，一个都不少。

那什么是流程控制？其实很简单：**根据不同的条件，走不同的处理流程，最终得到不同的结果。**

生活里随手就能抓一个例子：假如我们根据员工的性别不同，给予不同的补助——判断是男的怎么处理，是女的怎么处理，是其他性别怎么处理，这本身就是一次流程控制。Java 里有这套东西，SQL 里也一样有，只不过它不以关键字的形式出现，而是以函数的形式出现。

落到 MySQL 里，承担流程控制任务的主要是 `IF`、`IFNULL` 以及 `CASE` 这几个函数。它们当然不是全部，还有很多，但这些是重点。前面我们把单行函数讲得差不多了，这几个是单行函数里的最后一部分。

### 两条岔路口：IF 与 IFNULL

#### IF：一个条件，两条路

先看 `IF`。它是一种条件函数，第一个参数放的是一个表达式，这个表达式的返回结果只能是 true 或者 false；为 true 就取第一个值，为 false 就取第二个值。

```sql
IF(表达式, 值1, 值2)
```

回到刚才补助的例子：性别等于男，补助 300，否则补助 500。

```sql
SELECT
  name,
  gender,
  IF(gender = '男', 300, 500) AS 补助
FROM emp;
```

语法上有个特别容易搞错的地方要拎出来说：`IF` 里用的是**一个**等号 `=`，那是比较；`then` 那种赋值语法在这里是没有的，别写俩。

> **易错点**：`IF` 只能处理 true / false 这**两个**结果。咱们这个 `emp` 表里只有男和女，用 `IF` 没问题；但要是去到性别分类更多的场景——讲师调侃地举了"人妖"那第三种——两个岔路口就不够用了。这个必须记住。

#### IFNULL：专门收拾空值的那个

第二个是 `IFNULL`，听名字就懂了：if null，如果为空怎么办。它跟名字一样直白，两个参数：第一个参数是一个**列名**，如果这一列的值为空，就给后面第二个位置上的值。

最典型的场景是员工表里的奖金比例列——一部分人填了，一部分人没填。没填不代表他真的没有奖金，很可能大家都是一个非特殊的默认比例，只是没必要写出来而已。这时候就可以用 `IFNULL` 兜一个底：

```sql
SELECT
  name,
  salary,
  IFNULL(pct_bonus, 0.01) AS 奖金比例
FROM emp;
```

有值的人用他自己的值，没值的人按 0.01 算。

还有另一套更常用的用法，源于空值的一个脾气：**空值跟其他数字做加减乘除，最后结果都是空。**算出来一片 null 观感很差，而我们真正想要的多半是"空当零"——最后得个 0 多好看。`IFNULL` 正好干这个：

```sql
SELECT
  name,
  salary,
  salary * IFNULL(pct_bonus, 0) AS 奖金额度
FROM emp;
```

到这里就能看出这两个函数的分工了：`IF` 专门处理两个条件的分叉，`IFNULL` 专门处理空值。那么问题自然就来了——**要是条件不止两个、流程分叉更多呢？**这就得请出 `CASE` 了。

### 多岔路口：CASE 的两种写法

`CASE` 用来实现多条件判断。还是补助那个例子：男的给多少、女的给多少、以及"第三种性别"给多少，三条线，就得上 `CASE`。

`CASE` 的语法有两种，都能实现同样的效果，只是写法稍有不同。

#### 语法一：条件写在 when 后面

第一种是 `case` 开头、`end` 结尾，`case` 后面直接跟 `when`：

```sql
CASE
  WHEN 表达式1 THEN 结果1
  WHEN 表达式2 THEN 结果2
  ELSE 默认结果
END
```

`when` 后面放一个表达式，这个表达式的结果是 true，就返回 `then` 后面的 `result1`，`case` 到此结束。

这里有个必须记牢的规则：**多个 `when` 加 `else` 之间，条件是从上到下、优先级依次递减的。**它会先执行第一个表达式，如果成立，就直接拿到结果，后面的一律不再走；只有第一个不成立，才去试第二个。所以第二个是第一个的备胎，第三个是第二个的备胎；如果全都不成立，最后落到 `else` 那个默认结果上。

```sql
SELECT
  name,
  gender,
  CASE
    WHEN gender = '男' THEN 300
    WHEN gender = '女' THEN 5000
    ELSE 1
  END AS 补助
FROM emp;
```

只有三条线，后面的 `when` 就不必再写了，一个 `else` 兜住"人妖"那一档就行。

#### 语法二：把列名或表达式前置

第二种写法，是把所谓的**条件表达式提到 `case` 后面**，`end` 里面放值：

```sql
CASE 列名或表达式
  WHEN 值1 THEN 结果1
  WHEN 值2 THEN 结果2
  ELSE 默认结果
END
```

刚才那套用第二种怎么写？`case` 后面直接放 `gender`（性别那一列名），`when` 后面写"男"这个字符串，`then` 后面写 300；下一个 `when` 写"女"，写 5000；`else` 写 1。

```sql
SELECT
  name,
  gender,
  CASE gender
    WHEN '男' THEN 300
    WHEN '女' THEN 5000
    ELSE 1
  END AS 补助
FROM emp;
```

用列名前置的时候，`when` 后面写的是一个**值**，默认是用等号去比较的：这个值跟列名相等，就走对应的结果。

`case` 后面的位置放的也不一定非得是列名，表达式同样可以放。假设放进去的表达式最终结果是 true 和 false：第一个为 true 走对应的值，第二个为 false 走 else，对不对？所以一般情况还是放列名比较多——"列名等于哪个值的时候，我们该怎么办"，这种需求在实际开发里最常见。

#### as 别名：什么时候该写，什么时候不该写

写完上面两种，`end` 后面通常还会跟一个方括号，表示可写不可写。这里要专门交代一句：**方括号不是 `CASE` 的语法，是之前讲过的给列起别名的语法。**

如果你想把查询到的这个结果作为一个**新列**呈现出来，那就得在后面加 `as` 给它起个列名；但如果你是拿它去参与别的运算——比如修改某一列等于一个值——那就不写 `as`，因为它只要能算出一个值就行，又不是要单独成列。

```sql
SELECT
  name,
  gender,
  CASE
    WHEN gender = '男' THEN 300
    WHEN gender = '女' THEN 5000
    ELSE 1
  END AS 补助
FROM emp;
```

上面查询要用 `as 补助`；下面这个更新里就不用了：

```sql
-- 伪代码：更新语句里也用 CASE
UPDATE 表名
SET 某列 = CASE
              WHEN 性别 = '男' THEN 300
              WHEN 性别 = '女' THEN 5000
              ELSE 1
            END;
```

`SET 列名 = 值` 这个位置直接放 `CASE` 就行，`WHEN...THEN...ELSE...END` 一路写完，后面不要再加 `as` 列名了——因为算出来的这个值会直接赋给前面那个列名。

### 流程控制实战：四道题

语法讲完了，来四道练习，看看是真掌握了还是只是听懂了。表统一用 `emp`。

#### 按生日涨薪

> 查询员工的姓名、生日、工资，以及涨薪后的工资。生日在 1990 年之前的涨薪 10%，否则涨薪 5%。

1990 是个节点，要判断它之前和之后有两种不同的处理结果，两个岔路口——用 `IF` 就够了。写的时候有个小前提：生日里存的是年月日，而我们要判断的是**年**，所以得先用提取函数 `YEAR` 把年抠出来。

```sql
SELECT
  name,
  salary,
  birthday,
  ROUND(IF(YEAR(birthday) > 1990, salary * 1.05, salary * 1.1), 1) AS new_salary
FROM emp;
```

这里 `IF` 里面又套了一个 `YEAR`，函数之间本来就是可以互相嵌套的。判断条件是 `YEAR(birthday) > 1990`，成立就是 `salary * 1.05`；不成立就代表是 1990 年之前——那相当于 1989 年的老一点的人——取 `salary * 1.1`。

> **易错点**：还有一个现实问题——它纯的底层数据结构是 `double`，跟 Java 一样，可能会失真。所以外面再套一层 `ROUND` 截一下小数点后几位。`ROUND` 两个参数：第一个是要处理的数字，第二个是保留小数点后几位，超出的位会四舍五入向上进。

执行出来看第一个员工：1980 年，28000 乘 1.1，正好是 30800，没问题。

#### 造一列"男员工 / 女员工"

> 查询员工的编号、姓名，以及一个 `type` 列，显示这个员工到底是男员工还是女员工。

`type` 这一列现在表里根本没有，是要**造**出来的。造的时候只有男、女两项，还是两个岔路口，继续用 `IF`：

```sql
SELECT
  id,
  name,
  gender,
  IF(gender = '男', '男员工', '女员工') AS type
FROM emp;
```

结果一跑出来，肘子、涛子这些都老老实实标上了男员工/女员工，这就对了。

再说一遍那句判断标准：咱们这批员工都是中国人，除了男就是女，没有中间性别，所以你可以放心用 `IF`；可要是真有第三性别，`IF` 就用不了了。

#### 奖金数额：把空值换成 0

> 查询员工的姓名、工资，以及奖金数额。奖金等于工资乘以奖金比例。

先老老实实写一版：

```sql
SELECT
  name,
  salary,
  salary * pct_bonus AS 奖金数额
FROM emp;
```

跑完立刻就撞上了前面讲过的那个老问题：有值的能算出来，没值的算出来是空。空就空呗——但空显示不好看，没有就是没有，肯定写个 0 呗。这时候 `IFNULL` 就该上场了：

```sql
SELECT
  name,
  salary,
  salary * IFNULL(pct_bonus, 0) AS 奖金数额
FROM emp;
```

有的用自己值，没有的按 0 算，每个人都拿得到一个数。

有同学会问：`salary * pct_bonus` 我在外边整个括号包起来行不行？**也是行的。**但建议还是单独去包指定的列，为什么？因为**这样更灵活**。举个例子，假如以后没奖金的人我们默认给他设成 0.05——这就是个"阳光普照奖"——包在外边就算不出来了，包在 `IFNULL` 里面，就可以单独给这一列再定一个默认值。给多少不一定非得是 0，**得根据业务去改。**

#### 补助金额：两种 CASE 语法各写一遍

> 查询员工的姓名、性别、补助金额。补助金额按奖金比例乘以一个基准值：男 2000，女 3000，其他为 0。另外奖金比例如果为空，就按 0.1 计算。

这题得两个函数一起上：比例可能为空，用 `IFNULL`；条件有三个，用 `CASE`。而且两种 `CASE` 语法都能实现，我们一种一种来。

先看 `IFNULL` 为什么要嵌在里面：比例为空就当成 0.1，那这个员工的补助金额依然是算得出来的。

**第一种语法，条件写在 `when` 后面：**

```sql
SELECT
  name,
  gender,
  pct_bonus,
  CASE
    WHEN gender = '男' THEN 2000 * IFNULL(pct_bonus, 0.1)
    WHEN gender = '女' THEN 3000 * IFNULL(pct_bonus, 0.1)
    ELSE 0
  END AS 补助金额
FROM emp;
```

三条线写完，加个 `end` 表示这个 `case` 收尾；因为是查询、这个结果要成为一个新列，所以后面得 `as 补助金额`。

**第二种语法，列名前置：**

```sql
SELECT
  name,
  gender,
  pct_bonus,
  CASE gender
    WHEN '男' THEN 2000 * IFNULL(pct_bonus, 0.1)
    WHEN '女' THEN 3000 * IFNULL(pct_bonus, 0.1)
    ELSE 0
  END AS 补助金额
FROM emp;
```

无非就是把 `gender` 从每个 `when` 里面提到 `case` 后头，`when` 那儿直接写"男"、"女"，靠等号去比。结果完全一样。

当然，你也可以把 `gender = '男'` 这么个表达式整体前置，那 `when` 后头写的就变成 true / false 了，效果一样。**一般做的话，都是把列名前置**，这个最常见。

### 换个视角看数据：聚合函数

单行函数讲完了，接下来要换一拨函数——多行函数里的聚合函数。

在讲函数之前，我已经给大家对比过单行函数和多行函数，这里再强调一遍。**单行函数是作用到每一行的，最终结果可能是多条；多行函数相当于开启了上帝视角，站在宏观角度上统计你的数据，最终的结果只有一条。**

> **定义**：聚合函数是作用于全部数据（或者后面要讲的分组数据）进行统计和计算的，最终结果只有一条。

有了它，我们才能干这些事：统计员工的数量、平均工资，或者每个部门的数量。

#### 五个聚合函数

一共五个，我们一个一个过。

| 函数 | 放什么 | 统计什么 | 对列的类型要求 |
| --- | --- | --- | --- |
| `AVG` | 列名 | 这一列的平均值 | 数值类型 |
| `SUM` | 列名 | 这一列的数值和 | 数值类型 |
| `MIN` | 列名 | 这一列的最小值 | 任意类型 |
| `MAX` | 列名 | 这一列的最大值 | 任意类型 |
| `COUNT` | 列名 / `*` / `1` | 出现次数（详见下一节） | 任意类型 |

`MIN` 和 `MAX` 前面四个都好理解，只有 `MIN`/`MAX` 稍微注意一下：**它俩要求的不是数值类型，任意类型都行。**数字当然能统计最小值、最大值，时间也可以；放字符串也能排，只不过会按照你当前 MySQL 指定编码格式的码表先后顺序来排——但字符串的最小最大值一般没什么意义，实用中统计数字和时间是绝大多数情况。

#### COUNT：列名、星号与 1

第五个 `COUNT` 稍微有点不好理解。`COUNT` 跟 `SUM` 不同：`SUM` 是求和，`COUNT` 是求出现的次数，不是求和。它的语法分两大种。

**第一种，放列名**：统计的是**这一列非空值出现的次数**。比如放 `salary`，那 28000 算一次，9000 算第二次，它统计的是"出现了多少次"，**不是它们的和**；要是某个值变成了空，这个位置就不计数了。

**第二种，放 `*` 或者 `1`**：作用是统计所有行的次数——这一行算 1，那一行算 2，这样数。跟放星号的效果是一样的。讲师的理解是：一行内只要有任意一列有值，就代表这一行是生效的。

所以这两个是**统计行的数量**和**统计列的数量**的区别，思路不一样。它们的值有可能相等——假如 `salary` 每行都有值，那 `COUNT(salary)` 的结果就等于 `COUNT(*)`；但**不保证一定相等**。举个例子，某一行是有数据的，但 salary 这一列为空，那么 `COUNT(salary)` 就比 `COUNT(*)` 少一。

> **结论**：要统计总条数，就用 `COUNT(*)` 或 `COUNT(1)`；要统计某一列出现的次数，就用列名。
>
> 另外还有一种写法：这个列可以放主键。主键永远不会为空，那放主键的时候两个值是一样的——不过这个下下章节才讲，先记住上面这一条就够了。

#### 练一：工资的最大、最小、平均与总和

> 求最大工资、最小工资、平均工资以及总工资。

```sql
SELECT
  AVG(salary) AS 平均工资,
  MIN(salary) AS 最小工资,
  MAX(salary) AS 最大工资,
  SUM(salary) AS 总工资
FROM emp;
```

最小工资放 `salary`，最大工资放 `salary`，平均就是 `AVG(salary)`，总工资 `SUM(salary)`，当然你依然可以给它们起别名。一条语句一次全出来。

#### 练二：年龄最大的员工，出生日期反而最小

> 求最大年龄和最小年龄的员工的生日。

这题有点意思，先动动脑子：谁的年龄最大？我们看看表里的数据就知道，**年龄大的，是年份值小的那个。**八零年比八四年大，八零年出生的人年龄更大；可是在日期值上，八零却是**更小**的。刚好是反过来的。

如果按 `MIN`/`MAX` 的字面意思去写，大概会写成这样：

```sql
SELECT
  MAX(birthday) AS 年龄最大员工的生日,
  MIN(birthday) AS 年龄最小员工的生日
FROM emp;
```

一执行就发现结果刚好相反了：查出来 `1995` 和 `1978`，而 1978 才是年龄最大的那个，1995 反而是年龄最小的。

因为 `MIN`/`MAX` 只是去比较**值**的大和小。值大的那个，生日大、年龄反而小；值小的那个，生日小、年龄反而大，这里会刚好逆反一下。

> **易错点**：想求的是"年龄"，而年龄正好是生日大小的反面。**最大年龄的员工，其生日应该是最小的；最小年龄的员工，其生日是最大的。**这个弯一定要在脑子里绕过来。

#### 练三：总人数与有奖金的人数

> 求所有员工的数量，以及拥有奖金的员工数量。

"拥有奖金"的意思就是：奖金列 `commission_pct` 这个值不为空，就代表有奖金。

```sql
SELECT
  COUNT(*)             AS 总员工数,
  COUNT(1)             AS 总员工数,
  COUNT(commission_pct) AS 拥有奖金的员工数
FROM emp;
```

结果前两个一样，都是 27；第三个是 **8**——只有 8 个人才有这个奖金。这就顺带把 `COUNT` 放列名和放 `*`/`1` 的区别演示了一遍。

#### 聚合函数对空值的态度，还有不能嵌套这条铁律

讲完练习，说两点要记牢的总结。

**第一，聚合函数碰到空值是怎么处理的。** `COUNT` 碰到空不计数，前面说的最大工资、最小工资、平均工资、总工资，碰到空也是一样的态度：**认为这个值不存在，既不算最大值，也不算最小值，也不单独列进平均值。**

> **结论**：碰到空，聚合函数是"冷漠"的——不计数、不处理、不关注。平均值不算它，求和也不算它，`COUNT` 同样不算它。

**第二，聚合函数之间不能互相嵌套。**这一条要记下。

最后再把函数的定位说清楚：首先要理解函数的作用，它是对功能的一种封装；其次要理解单行函数和多行函数的区别——单行函数作用到单条查询结果上，多行函数是站在宏观角度做整体处理；再就是把日期时间、字符串、数值这些单行函数，加上刚讲的聚合函数，回去好好记一记，后期开发里会经常用到。

到这里，**我们想讲的函数就全部介绍完毕了。**单表查询的前四个章节也讲完了，基本的简单查询大家都掌握了。接下来的方向是对查询结果做高级处理：分组查询、排序，以及把查询结果切一部分出来。另外还会把之前讲过的所有查询关键字——它们的语法先后顺序和执行顺序——一并做个总结，而 `WHERE` 到底什么时候执行，正是那时候要讲清楚的。

### 分组查询：把数据整成若干堆

#### 分组是什么：分完组，统计对象就换了

什么是分组查询？大家上学期间应该经常遇到分组这个动作：老师把班级所有学生分成若干个学习小组，做体育课也把你们分成若干组，聚在一起做活动。数据库里的分组也是同一个道理。

先不看概念，理解一下：所谓分组，就是**将数据按照某些特性分成若干个小组**。

关键在下一句——**分完组以后，统计的就不是单个人或单条数据了，而是组的数据。**要不然你分什么组，对不对？

所以分组查询的概念是：把数据行按照某一列或多列的值相同作为条件分成组。都是男性的分一组，都是女性的分一组；或者既是男性、又在同一个部门的分一组，意思就是这个。

那么分完组以后能查什么呢？**就两项东西，大家记死：**

```text
   分组前：四条独立的员工数据，每一行都是"一个人"

   +----+------+----------+------+
   | id | name | birthday | 颜色 |
   +----+------+----------+------+
   |  1 | 张三 | 1980-... | 黄色 |
   |  2 | 李四 | 1984-... | 绿色 |
   |  3 | 王五 | 1980-... | 黄色 |
   |  4 | 赵六 | 1984-... | 绿色 |
   +----+------+----------+------+

        按 颜色 分组 之后：四条数据变成两组

   +-------------------+          +-------------------+
   | [ 黄色组: 1, 3 ]   |          | [ 绿色组: 2, 4 ]   |
   |  颜色 = 黄色       |          |  颜色 = 绿色       |
   |  人数 / 平均值 ... |          |  人数 / 平均值 ... |
   +-------------------+          +-------------------+
```

读图：左边是分之前的四条明细，右边是按 `颜色` 分完组的两堆。同一个组里，**这一列的值一定是相同的**——分到一组就证明它们的特性列值一样。按性别分组，就不可能把男性和女性分到同一组里去。

所以分完组之后：

1. **查询结果只能是分组那个特性列**——你按哪列分组的，就可以查哪列；
2. **以及聚合函数**——按性别分组，就可以查每一组的平均值、最大值、总条数。

记这两个就够了：**分组列 + 聚合函数。**图上那个统计平均值的框，填的就是聚合函数。

#### 语法骨架：group by 与 where 平级，having 跟着它

语法很简单：

```sql
SELECT
  分组列,
  聚合函数
FROM 表名
[WHERE 条件]
GROUP BY 分组列1, 分组列2, ...
[HAVING 分组后条件];
```

几个点要交代清楚。

**`GROUP BY` 和 `WHERE` 是平级的。**不像之前那些比较符号必须跟在 `where` 后面，`GROUP BY` 可以单独存在。有 `WHERE` 条件就正常加 `WHERE`，没有就不用加；有 `WHERE` 又有 `GROUP BY` 的时候，`GROUP BY` 一定要写在 `WHERE` 的后边。

**分组列可以是多列，用逗号隔开。**想按性别和工作地点同时分组，就写 `gender, work_point`，这样分到一组的两个值一定都相同；当然写三列四列也行。

**最后那个 `HAVING` 是分组的"好兄弟"。**注意，`HAVING` 是 `GROUP BY` 的铁杆粉丝——**只有 `GROUP BY` 出现，`HAVING` 才可以出现。**`HAVING` 是分组后的条件，`WHERE` 是分组前的条件。这个区别下面还会展开。

#### 练一：按性别分组，人数和平均工资

> 查询每一种性别的员工数量，以及它对应的平均工资。

想象一下这个场景：让所有员工都站起来，男的站一排，女的站一排，站完了再统计数量——这不就是分组吗？先按 `gender` 这一列分组，**只有一列分组**；分完组以后，查分组特性列加聚合函数即可。

本题没有任何条件——既没说"必须长得帅的男员工才能分组"，也没说"平均工资必须达到多少"，所以 `WHERE` 和 `HAVING` 都不用考虑，**它俩都不是必须写的。**

```sql
SELECT
  gender,
  COUNT(*)        AS 数量,
  AVG(salary)     AS 平均工资
FROM emp
GROUP BY gender;
```

注意这里的 `COUNT` 和第一题不一样了：不分组的时候它统计全部，分了组之后，它统计的是**每个小组内部的条数**。

执行结果出来：男的一组 14 个人，女的一组 13 个人；而且**女性这一组的平均工资比男性还高一些**——巾巾帼不让须眉。

#### 练二：按出生年份分组

> 查询每个出生年份的人数和平均工资。

这一项是按生日分组的，但注意——**是按生日里边的"年份"分组。**假如有一条是 1980 年 10 月 8 日，能不能直接按 `birthday` 分组？不行。如果真按 `birthday` 分组，指的是 1980 年 10 月 8 号整体算一组数据，只有和它完全相同的才在一组。表里 1984 年 8 月 3 号和 1984 年 9 月 11 号，这俩就**不在一组**，因为值不相同。

那怎么才能按年份分组呢？很简单：**在分组之前，先用一个函数把生日里的年份提取出来**，按提取出来的这个值再分组。这个函数就是 `YEAR`。

```sql
SELECT
  YEAR(birthday) AS 出生年份,
  COUNT(*)        AS 人数,
  AVG(salary)     AS 平均工资
FROM emp
GROUP BY YEAR(birthday);
```

第一列查的其实就是分组列，只不过它带了一层函数运算——`YEAR(birthday)`，说白了就是把生日里边的年份抠出来；`GROUP BY` 后面跟的也是同一个表达式。

结果出来，能看出哪个年份有几个人（90 年最多），也能看出哪个年份的平均工资最高。大家还能发现一个规律：**年龄老的人少，但平均工资高。**这也从侧面说明，分组时是可以对列的结果做统计处理的。

#### 练三：工资高于 5000 的先筛出来（WHERE）

> 查询工资高于 5000 的每种性别的员工数量、平均工资等。

这题跟练一几乎一样，只是多了一个条件：工资高于 5000 的人才能进到这个统计里来。

想象领导会怎么说：**"工资高于 5000 的人先站起来，站完了以后再按性别分组。"**前半句是筛选，后半句才是分组。

```sql
SELECT
  gender,
  COUNT(*)    AS 数量,
  AVG(salary) AS 平均工资
FROM emp
WHERE salary > 5000
GROUP BY gender;
```

分组前的筛选条件，用 `WHERE` 就够了。（`WHERE` 的执行顺序早于 `GROUP BY`，这一点后面讲关键字执行顺序的时候会专门说。）

结果跑出来是 13 和 12——比练一里的 14、13 少了一个。**说明每个性别里边有一名员工的工资是低于 5000 的。**

#### 练四：平均工资高于 5000 的再筛（HAVING）

> 查询平均工资高于 5000 的性别，以及这个性别的人数。

这题有点绕，我还是打个比方：老师把学生分成若干个学习小组，假如有六个小组，现在要带学生出去游玩，但**只想带平均成绩高于 60 分的组**。那怎么做？第一步，老师要先给所有学生分完组；第二步，分完组以后，把这个分组的数据挨个统计出来；**第三步，统计完毕以后，再去看哪个组的平均分大于 60**——大于 60 的带出去玩，不大于 60 的，就老老实实跟老师好好学习。

关键就在这：**"平均工资大于 5000"这个条件，是分组之后才有的。**所以它是分组后的条件，就得由 `HAVING` 来处理——`HAVING` 专门干这个事，只有跟 `GROUP BY` 合作才会有分组后条件。

```sql
SELECT
  gender,
  COUNT(*)    AS 人数,
  AVG(salary) AS 平均工资
FROM emp
GROUP BY gender
HAVING AVG(salary) > 5000;
```

不过现场执行的时候有个小插曲：上一题刚卡完 5000，男的女的都还在，说明两个性别的平均工资都过了 5000，一眼看不出 `HAVING` 起没起作用。所以现场把阈值提到了 **1 万 1**——女性这一组的平均值差不多正好是 1 万 1——这样一卡，卡出来的就只剩女性了。`HAVING` 干没干活，一目了然。

#### WHERE 与 HAVING 的区别，以及 HAVING 里的别名

最后把细节收个尾，一共四条，一条一条记。

**第一，`HAVING` 只能写在 `GROUP BY` 后面。**没有 `GROUP BY`，它就没有出现的场合；`WHERE` 则是随时都能写，有没有 `GROUP BY` 都不影响。

**第二，`HAVING` 后面比较的一般是聚合函数。**它比较的位置，一定是算出来的一个聚合函数值，再拿去做大于、小于、等于的比较。为什么这么写？可以这么说——**99.999% 是这么回事**：你都分完组了，对一个组做排除法，你只能拿这个组统计出来的数据去排除；至于"男性不参与"这种条件，那是分组**前**用 `WHERE` 查女性就完事了，犯不着先分再排。而且分组查询本来就只能查分组列和聚合函数这两项。

反过来说，`WHERE` 后面可以是**任何比较**：大于、小于、等于都行，有没有函数都能比较，任意参数都能比。

**第三，`HAVING` 可以复用 `SELECT` 里查出来的列名。**前面那个例子里第一个 `AVG(salary)` 可以给它起个别名 `av`，然后在 `HAVING` 那里直接用：

```sql
SELECT
  gender,
  COUNT(*)    AS 人数,
  AVG(salary) AS av
FROM emp
GROUP BY gender
HAVING av > 5000;
```

至于为什么可以——这个得往后听才说得清：**`HAVING` 是在分组之后才执行的**，而分组之前平均值就已经算出来了，所以这个列已经存在了，可以直接拿来复用。这算是个小优化，记不住也没关系，老老实实写 `AVG(salary) > 5000` 一样跑得通。

**第四，`WHERE` 不能复用 `SELECT` 的列名。**一定要记住这一点，原因还是执行顺序：**`WHERE` 早于 `SELECT`**，你比人家找的东西还没查出来呢，怎么可能拿得到它的列名。

## 排序、切割与关键字书写顺序
> 对应块：BLK11 | 覆盖分集：P54-P56 | 块标题（分集名）：《54-数据查询篇-排序查询实战》

分组讲完了，我们来说说排序。排序这东西其实比分组好理解得多。

打个比方。假如说我们有一队列学生，我们按照大小个儿进行排序——那这里边就是根据身高进行排序。当然也可以是大个儿站前，或者是"小哥"站前，都可以。反正无非就是排个先后。

> **定义**：排序指的是按照某一个或者多个特性列，对数据进行排序。

但这里有一句话，大家一定要理解：排序不会影响结果的条数。就是说你不管怎么排，你这些学生不能丢俩，对不对？它只是改变了结果的一个顺序，仅此而已。

生活里到处都是排序。我们经常去一些网站买东西，商品按照价格排序，这就是排序。

### 排序查询的语法

排序的语法大家注意，它这么写。它跟 `WHERE` 平级：假如你该有 `where` 就写上，没有就没有，有没有条件自己加。`where` 后面加一个 `order by`，然后写排序列名。如果要正序写 `ASC`，倒序写 `DESC`。

```sql
SELECT 结果列
FROM 表名
[WHERE 条件]
ORDER BY 排序列 [ASC | DESC],
         第二排序列 [ASC | DESC], ...;
```

`ASC` 是正序，从小到大；`DESC` 是倒序，从大到小。如果要按多个列排序，用逗号隔开，第二个排序列也跟上 `ASC` 或者 `DESC`，以此类推。

> **注意**：`order by` 写也是在 `where` 后边去写，`group by`、`order by` 以及后面要讲的切割，它们都是跟 `where` 平级的。

单列的时候好说。假如说根据价格排序，价格的正序就是价格小的排在前方，价格的倒序就是贵的排在前面。

#### 多列排序：现任、备胎、千斤顶和阿杜

那如果要是两列怎么办？比如"价格、好评数"。听我说，如果有多列排序，默认只有当前一列相同时，第二列才会生效。也就是说，你这两列排序，只有第一列的结果它相同了、分不出谁大谁小了，第二列才会生效。

这是个备胎的感觉。你的女神失恋了，你才能上位，就是这种感觉。

当然还有第三列，那相当于是千斤顶——连备胎都没有。得第一列和第二列都相同，第三列才生效。第四列呢，那……除了千斤顶我也不会说了，还有什么比千斤顶还惨的吗？应该是阿杜吧，他应该在车底。第四列就得前三列都相同，它才生效。

这里有个非常关键的地方要记住：第二列生效的时候，只是在第一列相同值的那几行数据**内部**做位置调换，不会改变整体；第三列也一样，只在第一列和第二列都相同的那些行里排。

我们打开京东看看。在京东上搜手机，右边这几个排序项，第一它是综合排序，这个背后可能有个综合算法；第二你可以按销量排序，卖得最好的——你发现还是苹果手机；还可以按评论数排序等等。但是东哥我做的这个站呢，只能按单列排序，选不了多列。假如说京东能同时选一个评论数和一个销量，这俩一起选，如果销量是第一个，就代表销量；如果销量相同了，平均数（评论数）才能生效。你再点一下就把它取消了。而且它这里边也没有所谓的正序，往下指都是从大到小。

那语法这块我们总结几个细节：

- 细节一：如果是多列排序，只有上一列相同了，第二列才会生效；三列的话以此类推。
- 细节二：`ASC` 是正序从小到大，`DESC` 是倒序从大到小。
- 细节三：`ASC` 是默认值，可以不写。`ORDER BY price` 这一句就代表价格从小到大。你要是第二列想倒序，就写个 `DESC`，那代表着：如果第一列值相同了，这种第二列的数据是倒序进行排序的。

用一句话再钉一遍：现行、备胎、千斤顶、阿杜，以此类推。第一列是现任，第二列是备胎，第三列是千斤顶，第四列就相当于阿杜。

#### 排序的几个练习

练习很简单，练完排序就没问题了。

第一个，查询员工的信息，并且按照年龄正序排序。哪来的年龄啊？生日就是年龄呗。正序就是从小到大……但问题来了，这里边时间小的时候他的年龄反而是大。那如果你想按照年龄正序（从小到大）来写，应该反过来写，时间大的反过来就是年龄小。

```sql
SELECT * FROM t_emp
ORDER BY birthday DESC;
```

出来的结果是从小到大：李宏最小，陈浩最老。

第二个，按照工资的倒序查询一下员工的信息。

```sql
SELECT * FROM t_emp
ORDER BY salary DESC;
```

大的往前面排。最大的往最前头，最小的是 -1000。

第三个，如果工资相同，按照年龄的正序排序。注意这个"年龄正序"是年龄从小到大，而他的生日是从大到小，所以第二列还得写 `birthday DESC`。

```sql
SELECT * FROM t_emp
ORDER BY salary DESC,
         birthday DESC;
```

写的时候注意它的核心条件：先按工资排，工资相同了年龄才生效。执行完之后你再看，那一组工资相同的（9000 那组三条）互相调换了位置，1990 那条被换到了最前面——正好是时间的倒数和年龄刚好是相反的。其他没有相同工资的；如果有，同样会在那个相同工资的组内部按年龄的正序（生日倒序）来排。

第四个，查询所有有奖金的员工信息，按工资倒序。这里其实有两个东西：有奖金代表的是筛选，没有奖金就不要参与了，所以最终还得用 `where` 去筛选；倒序呢，这是排序。

```sql
SELECT * FROM t_emp
WHERE comm IS NOT NULL
ORDER BY salary DESC;
```

不为空是 `IS NOT NULL`，空是 `IS NULL`。`where` 正常加，也是加在它的前方。执行完看效果：这些有奖金的，工资高的到低的。

最后把排序再钉一遍：可以指定一个列或者多个列；`ASC` 从小到大，`DESC` 从大到小；如果有多列，第一列相同了第二列才生效，第二列和第一列都相同第三列才生效，以此类推，否则后边的列不一定能生效；而且它在生效的时候，处理的是前几列相同的这些数据行内部的位置调换。

### 切割查询：limit 把结果切一段

接下来进入高级查询处理的最后一个语法：数据切割，也就是我们常说的分页查询。

先给大家提个醒：我们要讲的切割语法是 MySQL 的方言，它有时候并不是标准的 SQL 语句，在其他数据库可能有其他的语法去替代。这个大家需要知道一下。

所谓的数据切割，就是把结果进行分页切割，按照一定的区域一段一段地进行展示。你查的结果数量很大、展示不来的话，怎么办呢？你可以切割其中的一部分进行展示。所以切割查询有时候也都叫分页查询。当然我们也可以查工资前三的员工，或者是工资最高的员工信息。

> **对比**：切割跟我们刚刚讲的排序就不同了。排序不会丢学生，排序是大小个儿排，排来排去学生都不会少；但切割这哥们儿，他真的会把学生给减少——切割它真的会影响结果。

#### limit 的语法

这个语法跟 `where` 也是平级的，在它后边加一个 `limit`：

```sql
SELECT 结果列
FROM 表名
[WHERE 条件]
LIMIT 偏移量, 行数;
```

它有两种写法。第一个是有两个值、逗号隔开；第二个写法是第一个值（加逗号）可以省略，写成 `LIMIT 行数`。

这两个值分别是什么意思呢？第一个值叫**偏移量**，第二个值是**要查询的行数**。什么叫偏移量？就是置顶——你要偏移几个开始查询。偏移量是一个可选参数，如果不写，连逗号都不写，只写行数，代表偏移量是零，零就是从头查询。行数指的是返回、要查询的条数；你指定 100 而库里没有 100 条数据也别怕，它只会返回你剩余的数据——"他要十条，我还给你造五条啊，我给你上哪去生去"。

> **易错点**：这边特别容易弄混的，大家都会以为它是下标——不是。它只是偏移量和查询条数。第一个值是偏移量，第二个是查询行数，千万不要记成"起始坐标"。

我们拿四条数据来演示一下：

```text
四条数据：   [ 第1条 ]  [ 第2条 ]  [ 第3条 ]  [ 第4条 ]

只查前两条          →  LIMIT 0, 2
                      偏移 0 个，从头开始查，查 2 条
                      0 可以省略      →  LIMIT 2

从第 2 条开始查 2 条 →  LIMIT 1, 2
                      偏移 1 个（跳过第 1 条），再查 2 条
                      这个 1 就不能省略了，只有 0 的时候才能省

再往后挪一格        →  LIMIT 2, 2
                      偏移 2 个，再查 2 条
```

回看一下：第一个是偏移量，0 的时候逗号可以省；第二个是查询行数。

> **注意**：`limit` 必须放在整段 SQL 语句的最后。因为 `limit` 相当于最终要返回的那个切割好的结果，它一定在最后。

#### limit 的三个练习

第一个，查询工资最高的员工信息。哎，我们刚学的切割怎么查最高呢？这里边考验两点：第一你可以先排序，再切割——根据工资进行倒序，那最大的时候就排到前方了；再切割一个，不就是工资最高的了嘛。

```sql
SELECT * FROM t_emp
ORDER BY salary DESC
LIMIT 0, 1;
```

我记住一点：只要有 `limit`，`limit` 一定放在最后，所以 `order by` 得写在它之前。零代表不偏移、切割第一个，这就是工资最高的。当然这么写也可以：零可以省略，直接写一，`LIMIT 1` 就相当于切割了。

第二个，查询工资第二高的员工。第二高指啥意思呢？大家想想，是不是也要排序啊？除了那个最高的，不就是第二高的了嘛。那咋办？你把最高的给排除掉。你切割写 `1, 1` 呀，第一个偏移把最高的偏移掉，最后再查一个，是不是就是第二高的了。

```sql
SELECT * FROM t_emp
ORDER BY salary DESC
LIMIT 1, 1;
```

这个 1 就不能省略了。

第三个，查询工资最高的女性员工信息。这时候你查之前是不是要先去筛选性别？你只有对男或者女性进行查询，再排序，这个做法其实很简单。把上一段粘过来一份，前面加个 `where` 就行了。

```sql
SELECT * FROM t_emp
WHERE sex = '女'
ORDER BY salary DESC
LIMIT 0, 1;
```

我们记住，`where` 一定早于 `order by`、`group by` 或者是 `limit`。到这儿，我们已经能大致捋出一点关键字的顺序了，咱们别着急，一会再总结。`where` 后边加 `sex = '女'`，这句现在首先是查询所有的女性；然后根据工资做倒序；最后再进行切割。

到这里，这句 SQL 的形状就完整了：筛选 → 排序 → 切割。

#### 分页公式：limit 的主力场景

`limit` 用的最常见的场景，其实就是分页查询。

还是打开京东那个站你看：这里我可以排序，也可以按评论数排序，但排序以后大家仔细看，展示的手机数据——在京东这个网站上，手机产品有 N 得有好几百万，你一个页面展示得下吗？展示不下，电脑的运行内存也吃不下，而且展示全了也太慢，加载数据。那咋办呢？其实我们在展示商品的时候，都会有分页进行展示。有些分页是明着的，像这种往下划、翻页；有些分页不是明着的，你划到最后滚动它才会加载，那其实也是分页加载。

那这个分页加载是怎么实现的？很简单，你要是 MySQL，就靠着 `limit` 这个关键字。因为分页不就是把数据切成若干页显示嘛，一次显示不下。分页就是靠着 `limit` 去实现的。

那我们在做分页的时候，一般都要推算公式。为什么呢？因为以后是前后端开发的时候。前端想查询数据，要向后端发起请求；后端给他返回数据——但后端返回的并不是完整数据，是他切割 `limit` 以后的分页数据。可后端能不能瞎切呢？切哪些数据是瞎切的吗？并不是。这时候需要前端给我们传过来一些参数，告诉我们要切割哪些数据。

一般情况下做分页查询，前端都会传两个参数：第一个参数就是第几页，第二个就是每一页显示多少条。他得给我这俩参数，我才知道后台怎么切割。而这俩参数到 `limit` 的这俩值，中间有个固定的公式。

我们画个图。假设我们的数据有 8 条，一页只能显示三条，`size` 固定等于 3：

```text
数据：    [1]  [2]  [3]  [4]  [5]  [6]  [7]  [8]

第 1 页： [1]  [2]  [3]                  →  LIMIT 0, 3
第 2 页：               [4]  [5]  [6]    →  LIMIT 3, 3
第 3 页：                          [7]  [8]  →  LIMIT 6, 3
                                          （没有那么多条，就只展示这两条）
```

看这三个值，后边这俩值算的时候有没有规律？

- 第 1 页：偏移 0 个，从头查，查 3 条 → `0, 3`
- 第 2 页：偏移 3 个（比第一页差了 3）→ `3, 3`
- 第 3 页：偏移 6 个 → `6, 3`

第一个偏移量的算法是：**当前页码减一乘以 size**。页码是 1，`1-1` 等于零乘以 `size`，就是 0；页码是 2，`2-1` 等于一乘以 3，就是 3；页码是 3，`3-1` 等于二乘以 3，就是 6。

第二个值相当于是个常量，就等于我每次查询的数量 `size`。

所以公式是固定的：

$$\text{offset} = (\text{页码} - 1) \times \text{size}, \qquad \text{行数} = \text{size}$$

> **注意**：页码是从 1 开始的。还有，写 `LIMIT 0, 5` 的时候，那 5 是偏移量，不是"起始坐标"，千万别记混了。

以后前端只要把参数一传过来，你就知道怎么算出这一页到底要切割哪些数据了，把这个公式往 `limit` 后边一套就完事。

### 关键字的书写顺序

到此为止，我们已经基本把单表查询的语法、关键字以及函数都介绍完毕了。想必很多同学有点懵——原因就是关键字太多了。

分开写我还会举个例子：假如说你来个排序，我会讲排序；来了分组，我会讲分组；切割我也会讲，加 `where` 条件也会讲。但如果这些东西混到一起，我们应该如何去写呢？

这一节主要解决两个问题。第一个问题是：这些关键字如果都融合到一起，我们正确的书写先后顺序是什么——这个是大家必须要掌握的。第二个问题是：这些关键字大概的执行顺序是什么样的——这个以了解为主，因为执行顺序会随着 MySQL 版本不同逐步优化，也并不一定是准的；但如果说面试问到了，你知道大概怎么说就可以了。

关键字的顺序是不能颠倒、错乱的，它有固定的顺序。写在 SQL 句子里它是长这样的：

```sql
SELECT 结果列          -- 先写 select，放要查询的结果列
FROM 表名              -- 再 from，指定表名
WHERE 分组前条件        -- 有 where 就写 where，最后放相关的条件
GROUP BY 分组字段       -- 有分组再加 group by，可以写多个分组字段
HAVING 分组后条件       -- 分组的好兄弟好基友，紧跟在 group by 后边
ORDER BY 排序列        -- 有 order by 就放排序列名，ASC 或 DESC
LIMIT 偏移量, 行数;     -- 最后加 limit，两个参数：offset 和 number
```

先写 `SELECT`，这是必然的，后边放要查询的结果列；再 `FROM` 指定表名；如果有 `where`，放相关的条件，条件之间可以正常用 `and`、`or` 等等一系列拼接。

然后是分组、排序、`limit` 这三块碰到一起。它们的顺序是这样的：

第一，`having` 跟 `group by` 它俩是死死挨在一起的，不可能分家——卧龙和凤雏。

第二，分组要优先。如果有分组，那分组要优先，因为分组指的是对整个结果产生了一种扭转和变化。之前查询的是全部的数据，要查询分组的数据，那应该先分组。

为什么不能把排序和分组错乱？大家思考一个问题：各位同学先按大小个儿全部都站好，站好以后呢，男生一组、女生一组。你感觉这个排序有什么意义？它没什么意义。要分组的话就先分组，分完组以后我们再排序，排序指的就是对我们分组结果的排序，而不是对分组之前的排序。

第三，`limit` 归位是在最后，一定追到最尾部。它是对整体结果的切割，你都查询完毕了、都已经筛选完毕了，这样我再进行下切割就可以了。

> **结论**：以上就是我们 SQL 句最关键的书写顺序，建议把这个顺序打在公屏上，深入地记一下。

### 关键字的执行顺序

执行顺序跟你书写的顺序可能是不一样的。

```text
FROM  →  WHERE  →  GROUP BY  →  HAVING  →  SELECT  →  ORDER BY  →  LIMIT
```

- `FROM`：先执行，先去指定我们哪个表作为数据源；
- `WHERE`：前置筛选；
- `GROUP BY`：分组；
- `HAVING`：分组后的条件；
- `SELECT`：最终显示的列信息；
- `ORDER BY`：排序；
- `LIMIT`：切割。

所以在执行的时候，顺序跟写的时候不一样。

| 关键字 | 书写顺序中的位置 | 执行时机 |
| :--- | :---: | :---: |
| `SELECT` | 第 1 个 | 第 5 步 |
| `FROM` | 第 2 个 | 第 1 步 |
| `WHERE` | 第 3 个 | 第 2 步 |
| `GROUP BY` | 第 4 个 | 第 3 步 |
| `HAVING` | 第 5 个 | 第 4 步 |
| `ORDER BY` | 第 6 个 | 第 6 步 |
| `LIMIT` | 第 7 个 | 第 7 步 |

执行顺序一般在面试中可能会问到；书写的顺序则是要求你写 SQL 语句的时候实时掌握的。

### 别名到底能在哪个位置用

知道了执行顺序，它有什么用呢？举个例子。假设我们在 `select` 的字段中造了一列别名，造一个列的别名。那大家记住，按照顺序来说，`select` 出现在 `order by`（还有 `limit`）的前面。`order by` 在排序时可以指定列名，也就是说，`order by` 可以用我们 `select` 里生成的这个别名进行排序——因为它的顺序早。

但是反过来看，如果说你在这里边能起个别名，那按顺序来说，在 `group by`、在 `where` 条件、或者在 `having` 这个位置，是不能使用的。但事实呢，可能并不是这样。

我们直接拿事实说话。放两条语句：第一条是查询年份，最终查一个年份对应的条数等等一些信息，`where` 后面用了这个别名；第二条呢，在 `group by` 和 `having` 后面也用了这个别名。

按我们刚才说的执行顺序来捋：先 `from`，然后 `where`，然后 `group by` 后面跟 `having`，最后是 `select` 这一列，下边跟 `order by`、`limit`。那么按执行顺序来说，这个别名列出现的位置应该在 `select` 这个位置。但是它却出现在 `where` 后边、`order by` 后边、`group by` 后边以及 `having` 后边——那这两条语句是不是都是错的呢？来，我们跑一下。

第一条，果然不出所料，报错了，报的是什么呢？`Unknown column`，就是说我不知道有这个别名，在 `where` 后边用不了。因为我先执行 `where` 的时候，你的 `select` 的别名还没有产生。

那第二个按理说应该也报这个问题对吧？大家看第二条——第一条是在 `where` 这个位置用了这个别名列，第二条呢在 `having` 后边用了 `select` 里对应的这个列，它按理说也该报错。但是大家发现，第二条是可以查询的。

那这里边大家可能有疑惑了：难道你讲的顺序是有问题的？顺序是固定的。顺序是固定的，但是呢，确实在过程中有些优化。大家看我下面这句话：

- 第一，在标准的 SQL 语句中，不允许在 `where` 后边使用、引用这个所谓的列的别名。这句话限制的是 `where`——在执行 `where` 的时候，列还没有产生。标准的 SQL 域中也是这么规定的。
- 第二，别名其实是可以在查询选择列的 `group by`、`order by` 以及 `having` 后边来使用的。这两句话是 MySQL 8 以后优化的一个特点：在 `group by` 以及 `having` 后边，是直接可以使用我们的别名的；而在 `where` 过程中，依然不能使用别名。

> **易错点**：为什么顺序上不能用、实际却能用？因为在数据处理过程中，顺序有很多优化，并且产生了很多虚拟表，中间也随着 MySQL 版本的不同有些变化。

所以大家最终就记住两条就够了：`where` 后面依然无法使用 `select` 产生的列别名（这时候确实还没有列产生，而且标准 SQL 也是这么规定的）；但经过优化和中间虚拟表的作用，`group by` 和 `having` 后面其实是可以使用 `select` 产生的这个列别名的。

> **结论**：这一块原理我们不用记那么多。关键字顺序怎么用、别名可以在哪使用，记住这两条就可以了。

### 本讲提到的题目

**偏移 2 个、查 2 条该怎么写**

把动画切一下，停在"从第 2 个位置开始查、取两条"之后，问我这两个值该填多少。答案是 `LIMIT 2, 2`——第一个值偏移两个，第二个值查两个条。第一个值是偏移量，为 0 的时候逗号可以省；第二个是查询行数，千万不要记成"起始坐标"。

**第二、第三、第四高的工资怎么查**

这题要想明白偏移量是干什么用的。先按工资倒序排（`ORDER BY salary DESC`），把最高的那条偏移掉，再连着查三条，出来的就是第二、第三、第四高：

```sql
SELECT * FROM t_emp
ORDER BY salary DESC
LIMIT 1, 3;
```

**工资最少的三名员工**

同样是排序加切割，只是"最少"意味着从小到大，所以用正序（`ASC` 是默认值，不写也行）；要从头开始查，偏移量就是 0，逗号都可以省；一共三名，所以行数是 3：

```sql
SELECT * FROM t_emp
ORDER BY salary
LIMIT 0, 3;
```

#### 建库、建表

第一步建库：

```sql
CREATE DATABASE IF NOT EXISTS test04_lib
  CHARACTER SET utf8;

USE test04_lib;
```

`IF NOT EXISTS` 的意思就是"如果不存在我们创建"。库名叫 `test04_lib` 也行，叫 `library` 也无所谓，字符集用 utf8。

第二步建表，关键字叫 `CREATE TABLE`，后面表名，括号内部放我们对应的列名，多列之间逗号隔开。我这里没指定表它所谓的字符集等等，这东西就走默认值：

```sql
CREATE TABLE books (
    b_id     INT,
    name     VARCHAR(...),
    author   VARCHAR(...),
    price    FLOAT,
    pub_date YEAR,
    note     VARCHAR(...),
    num      INT
);
```

这里特意练了一点：写列名的时候可以加反引号。什么时候加有意义？如果你的列名像 `name` 这种是关键字，加反引号相当于把它和关键字区分开，看着更清楚；不然的话一些关键字变成大写你看着不清晰。给 `author` 加就是没什么意义的。

> **提示**：反引号 ` 是标识符（列名、表名）的引号，单引号 ' 是字符串值的引号。这两个千万别搞混——`note = 'novel'` 左边不用引号，右边要加。

执行的时候分两步：先选中库，再执行创建表。

#### 三种插入方式

第三题是向表里插数据，练三种写法：

```sql
-- 1. 不指定列名：必须严格按照当初创建表的列顺序插入
INSERT INTO books VALUES (值1, 值2, 值3, ...);

-- 2. 指定列名：列名的顺序不必和建表时一致
INSERT INTO books (b_id, name, author, price, pub_date, note, num)
VALUES (值1, 值2, 值3, ...);

-- 3. 一次插入多条：括号逗号隔开，一组括号代表一条数据
INSERT INTO books (b_id, name, ...)
VALUES
  (...),
  (...),
  (...);
```

第一种最需要注意：不指定列名的时候，你插入的 `VALUES` 值**一定要按照当初创建表的列顺序**。第二种就自由了——列名不一定非得跟建表的列名顺序相一致，只要 `VALUES` 里的值跟列名一一对应就可以。第三种把多组括号一逗号隔开往下排就行。

这三题我就这么诱导大家过一下。代码都在 Navicat 里，大家自己写的时候一定要把它删掉，自己手写一遍，记住了。

### 改与删：UPDATE 和 DELETE

第一道练习：将小说类型（`note = 'novel'`）的书，价格都增加 5 元。这练的是 `UPDATE` 语句，语法是：

```sql
UPDATE 表名 SET 列名 = 新的值;
```

多列就再写一个列名等于新的值。当然也可以在原基础之上做运算以后赋给新值：

```sql
列名 = 列名 运算 新的数值
```

有条件的话正常加 `WHERE` 就可以了。所以这道题：

```sql
UPDATE books
SET price = price + 5
WHERE note = 'novel';
```

执行之前先刷新一下表数据看一眼价格，`Emma` 那本现在是 23，执行完变成 28。刷新，所有 `novel` 的书价格都涨了。

第二道更简单一点，就是改两个值：把名称为 `Emma` 的书，价格改为 40，类型改为 `drama`。

```sql
UPDATE books
SET price = 40,
    note  = 'drama'
WHERE name = 'Emma';
```

执行前 `Emma` 是 35、类型是 `joke`，执行完就变了。

第三道：删除库存为 0 的书。这个我们太会了，删库并跑路。语法先过一遍：

```sql
DELETE FROM 表名 [WHERE 条件];
```

如果没有条件就代表全表删除，一般删除都是有条件的。所以：

```sql
DELETE FROM books
WHERE num = 0;
```

刷新一下，没了。

> **提示**：`WHERE` 后边如果判断的是列名，直接写不加引号；如果是字符串值，正常要加单引号。`WHERE note = 'novel'` 和 `WHERE note = novel` 完全不是一回事。

### 查：模糊查询、聚合与排序

第四道：查询图书名里包含 `a` 的书。`name` 不知道完整的名称，只知道一部分——这不就是传说中的模糊查询 `LIKE` 吗？`LIKE` 就是一个运算符，它活在 `WHERE` 里面。

```sql
SELECT * FROM books WHERE name LIKE '%a%';
```

前后加百分号：前面有它不管，后面有它不管，**只要中间有一个 a 就行**。

第五道：查询书名中包含 `a` 的书的数量和总库存量。包含 `a` 是一个条件，剩下的问题是"查一个数量以及库存量"——这就用到了多行函数里的聚合函数：数量用 `COUNT`，求和用 `SUM`。前面那句可以复用，改一下就变成：

```sql
SELECT COUNT(1), SUM(num)
FROM books
WHERE name LIKE '%a%';
```

结果是一共 4 本，总库存 103。

> **定义**：多行函数是作用在多行上的，4 行进去，最后查出的结果是 1 条。这也是它和单行函数的分水岭——单行函数一行进一行出，多行函数多行进一行出。

第六道：找出 `novel` 类型的书，价格按降序。这就要 `ORDER BY` 了。写之前先回顾一下**多个关键字同时出现时的正确书写顺序**：

```text
SELECT   列名 / 别名
  FROM   表名
 WHERE   条件
GROUP BY 分组字段
HAVING   分组后的条件
ORDER BY 排序列 [ASC | DESC]
  LIMIT   偏移量, 条数
```

按图索骥，条件写完，后面加一个 `ORDER BY` 就行：

```sql
SELECT * FROM books
WHERE note = 'novel'
ORDER BY price DESC;
```

降序就是从大到小，`DESC`。你可以把 `DESC` 去掉试试，变成 `ASC` 就是升序，从小到大。

第七道稍微绕一点：查询图书信息，**按库存降序，如果库存相同按 `note` 升序**。

```sql
SELECT * FROM books
ORDER BY num DESC, note ASC;
```

这道题没有 `WHERE`，直接写排序即可。`ASC` 也可以不写，默认就是升序。

> **结论**：多列排序的规则是——只有第一列相同，才会走第二列。这一题执行下来库存这列没有相同的，所以 `note` 那列根本没起作用；但规则本身就是这样，不用怀疑。

### 分组与分组后过滤

第八道：按 `note` 分类统计图书的数量。分类统计，就是说 `note` 相同的书算一类——这跟统计男生和女生各多少人是一回事，碰到的是**分组问题**。

```sql
SELECT note, COUNT(1)
FROM books
GROUP BY note;
```

没条件，直接 `GROUP BY note`，然后统计 `note` 这一列的数量（`COUNT(1)` 或者 `COUNT(*)` 都可以）。结果是这个类型有两本，那几个类型各一本。

> **结论**：只要一用到分组，切记一条——`SELECT` 后面**只能是分组字段和聚合函数**。记死了。因为分组以后我们统计的就是组的特性了：只有分组字段在一组内是相同的，其他列组内各不相同，你也没法统计。

第九道：按 `note` 分类统计库存量，显示库存量超过 30 本的书。读题：先分组，统计每一组库存量的和，然后查这个和大于 30 的组。

这个"和"是什么条件？叫**分组后的条件**，`HAVING` 干的就是这个事：

```sql
SELECT note, SUM(num) AS nm
FROM books
GROUP BY note
HAVING nm > 30;
```

`SUM(num)` 这儿起了个别名叫 `nm`，所以 `HAVING nm > 30` 就直接查出来了。

> **提示**：`HAVING` 有点特别——虽然它书写位置在 `SELECT` 前面，但 MySQL 允许它直接使用 `SELECT` 里定义的别名。而 `ORDER BY` 因为本来就写在 `SELECT` 后面，用别名更是天经地义。这个"提前用别名"是 MySQL 的扩展，标准 SQL 并不这么宽容，写的时候心里有个数就行。

### 分页查询与偏移量公式

第十道：查询所有图书，每页显示 5 本，显示第 2 页。分页用 `LIMIT`。

`LIMIT` 后面有两个参数：一个是 offset 偏移量，一个是 num 条数。在分页场景下，如果前端给我传一个 `page` 和每页的数量 `size`，最后会得到一个公式：

$$\text{offset} = (\text{page} - 1) \times \text{size}, \quad \text{size}$$

直接拿这个值去用就行了。每页 5 本，`size` 等于 5；第 2 页，`page` 等于 2。所以：

$$\text{offset} = (2 - 1) \times 5 = 5$$

写出来就是：

```sql
SELECT * FROM books
LIMIT 5, 5;
```

> **结论**：数据不够的时候不会给你造数据。我们表里一共才 7 条，删过之后只剩 5 条，压根不够分页。假如改成每页显示 4 本——`LIMIT 4, 4`——你只能查出 1 条：一共 5 条数据，第 1 页 4 条过去了，第 2 页只剩 1 条。你想查 4 条，它也不可能给你凭空补出 4 条空的。

### 字符串函数与嵌套

第十一道：查询书名达到 10 个字符的书，且**不包含空格**。碰到这种问题，统计长度、去空格，肯定要用到函数，而且一定是**字符串的函数**。

统计长度的是 `CHAR_LENGTH`，它可以放一个列名，也可以放一个字符串。但你直接拿 `name` 去算是不行的——**它会把空格也算一个位**。所以还要先去掉空格，对应的函数叫 `REPLACE`：

```sql
REPLACE(要处理的字符串, 目标, 替换值)
```

它跟 Java 里的用法有点像。因为最终函数**可以嵌套**，所以先把名字里所有的空格干掉，干掉以后再求长度，最后判断大于 10：

```sql
SELECT *
FROM books
WHERE CHAR_LENGTH(REPLACE(name, ' ', '')) >= 10;
```

现场还踩了个小坑值得说一说：我第一次执行直接报了错，提示 1064。**只要碰到 1064，就证明 SQL 语句写错了**，报错信息里 `near` 附近的那一截会告诉你大概错在哪儿。一看就明白了——`WHERE` 后面忘写表名了，漏了 `FROM books`，补上就正常了。

顺带说一句，这本书去掉空格后是 1、2、3、4、5……大概 8 个字符，并没有超过 10 的书，所以我把条件改成 `> 5` 来演示——查出来一大堆，语法完全没问题。结论是：**函数与函数之间可以互相嵌套**。

> **提示**：具体函数名记不住没关系，回头翻一翻单行函数和多行函数那两章就行。这里真正要记住的是"统计长度 + 替换 + 嵌套"这个套路。

### CASE：把值翻译成一句话

第十二道：查询书名和类型——`note` 为 `novel` 就显示"小说"，为 `law` 显示"法律"，为医药显示"医药"，为卡通显示"卡通"，为 joke 显示"笑话"，不在这些之内的显示"其他"。

需求一说就明白：根据 `note` 的值不同，给出不同的查询结果，这就是**流程控制**。

- 如果只有两个结果，可以用 `IF` 函数；
- 如果是多个流程，用 `CASE`。

`CASE` 有两种用法，用法一是带比较运算表达式的：

```sql
CASE
    WHEN 比较运算表达式 THEN 值
    WHEN ...              THEN ...
    ELSE 默认值
END
```

所以第一种这么写：

```sql
SELECT
    name,
    note,
    CASE
        WHEN note = 'novel' THEN '小说'
        WHEN note = 'law' THEN '法律'
        WHEN note = 'medicine' THEN '医药'
        WHEN note = 'cartoon' THEN '卡通'
        WHEN note = 'joke' THEN '笑话'
        ELSE '其他'
    END AS 'type'
FROM books;
```

`ELSE` 后面就是不在这些之内的，叫"其他"。最后 `END` 代表完事，但这个 `CASE` 会产生一个新的列，所以再给它起个别名 `AS 'type'`。执行一下，搞定了。

第二种用法更简洁：`CASE` 后面直接放一个列名或者表达式，后面这个位置**不放表达式**，放的是"这个列名对应的值"。等于就返回对应的结果：

```sql
SELECT
    name,
    note,
    CASE note
        WHEN 'novel' THEN '小说'
        WHEN 'law' THEN '法律'
        WHEN 'medicine' THEN '医药'
        WHEN 'cartoon' THEN '卡通'
        WHEN 'joke' THEN '笑话'
        ELSE '其他'
    END AS 'type'
FROM books;
```

把第一种里的比较符号 `note =` 去掉，判定逻辑就变成了"这个值是否等于你传的这个"。两种都可以，随意研究。

> **结论**：`CASE` 和 Java 里的 `switch-case` 一个脾气——**只有当某一个 `WHEN` 满足以后，就不会往下再走了**。所以分支的书写顺序要按你的业务优先级来。

第十三道又是流程控制：查询书名、库存，库存超过 30 的显示"滞销"，大于 0 且小于 10 的显示"畅销"，等于 0 的显示"无货"。

库存大于 30 叫滞销，那 30 到 10 之间代表什么呢？代表正常。所以完整的一套是：大于 30 滞销，10 到 30 正常，大于 0 到 10 畅销，0 无库存。

```sql
SELECT
    name,
    num,
    CASE
        WHEN num > 30 THEN '滞销'
        WHEN num > 10 AND num <= 30 THEN '正常'
        WHEN num > 0 AND num <= 10 THEN '畅销'
        ELSE '无库存'
    END AS '库存状态'
FROM books;
```

> **易错点**：这些条件**一定是互斥的，从上到下**依次判断。所以 30 算正常（`num <= 30` 拦住了），不归滞销也不归畅销。

### WITH ROLLUP：分组小计加合计行

第十四道有点小弯弯绕，给大家扩散一下：统计每一种 `note` 的库存，**并合计总量**。

如果只统计一种 `note` 的库存，前面就练过了，按 `note` 分组：

```sql
SELECT note, SUM(num) FROM books GROUP BY note;
```

每个类型它的库存量是多少。题目真正的重点在后半句——**并合计总量**：最后把分组以后的整体和显示在下面，比如 $41 + 22 + 20 + 28 = 131$。

这里教大家一个小技巧，有个关键字特别好用，叫 `WITH ROLLUP`。它是 SQL 查询的一个子句，专门用来生成数据汇总行，只要在最后加上它即可：

```sql
SELECT note, SUM(num) FROM books GROUP BY note WITH ROLLUP;
```

它会把 `SUM` 求和这一列，也就是数据这一列，**自动帮你再算一个总和**。这就是它的作用。

但是弄完之后有个小问题：最后那一行的 `note` 是没有分组值的，显示为空，看着不好看。想让这一列为空的时候显示成"总量"，就用前面学过的 `IFNULL`：

```sql
SELECT IFNULL(note, '总量'), SUM(num)
FROM books
GROUP BY note WITH ROLLUP;
```

这样就齐活了。这块小语法还是挺有意义的。

下一道就换个列：统计每种 `note` 的数量并且求总量，这不又是同一个东西吗？只不过求的是数量：

```sql
SELECT IFNULL(note, '总量'), COUNT(*)
FROM books
GROUP BY note WITH ROLLUP;
```

一共是五种——四种类型加一个总量。

### 排名类查询：排序加 LIMIT

这几道都是同一个套路：**先排序，切第一名或者前几名**。

统计库存排名前三的书。前三名先得排序，倒序，再用 `LIMIT` 切割：

```sql
SELECT * FROM books
ORDER BY num DESC LIMIT 3;
```

`LIMIT 0, 3` 和 `LIMIT 3` 是一样的写法，0 可以省略。

找出出版最早的一本书。出版时间按升序排，最早的值就是最小值——**大家别弄混了，值越小代表越早**：

```sql
SELECT * FROM books
ORDER BY pub_date LIMIT 1;
```

找出某个类型中价格最高的一本书。做法是：先判定类型，再切割价格最高的那一本。这里是 `WHERE` 条件 + `ORDER BY` 排序 + `LIMIT` 切割三件套：

```sql
SELECT * FROM books
WHERE note = '<类型>'
ORDER BY price DESC
LIMIT 1;
```

> **结论**：`ORDER` 和 `LIMIT` 相遇，`LIMIT` 一定写在最后；`ORDER` 一定在 `WHERE` 后面。上面这句里角标填题目要求的那个类型。

找出书名中字数最多的一本书，同样不含空格。排序时就用刚学的 `CHAR_LENGTH` 和 `REPLACE` 去掉空格，再加切割：

```sql
SELECT *
FROM books
ORDER BY CHAR_LENGTH(REPLACE(name, ' ', '')) DESC
LIMIT 1;
```

顺便把"最多的"这类题再强调一次：**一般切最多都切第一条，前三名、后三名一般都用 `LIMIT` 切**。

> **定义**：`LIMIT` 是一种切割，它切的是 `ORDER BY` 排完之后的顺序。所以要"第一"就排序 + 切第一条，要"前三"就排序 + 切前三条，顺序千万别搞反。

还有一个和第 14 题同源的：按 `note` 分类统计图书的库存，显示库存最多的书。

前面第 14 题的代码还能继续复用：按 `note` 分类、统计每个类型的库存和。现在多了一个要求——**要最多的那个**。注意，**第一个不一定是最多**！所以做法是：第一，按 `nm` 这个库存和排序，排序最好倒序；第二，加 `LIMIT` 切第一条。

```sql
SELECT note, SUM(num) AS nm
FROM books
GROUP BY note
ORDER BY nm DESC
LIMIT 1;
```

`ORDER BY` 在 `GROUP BY` 后面，而 `ORDER BY` 是在 `SELECT` 后边的，所以可以正常使用前面 `SELECT` 里的这个 `nm`。这样就查出了库存最多的类别和库存数量。

### 约束：给表里的数据上一道锁

从这儿开始，我们正式进入课程的第五章。这一章讲数据库约束的概念，以及约束设计的常见面试题。

这一章我分五个主题来讲。第一个主题讲约束的概念、作用以及分类；第二个、第三个、第四个小节讲约束的具体实践——怎么添加约束、怎么删除约束、以及约束的效果；第五个小节讲约束设计的常见面试题。现在先进入第一个小节：约束的概述和分类。

先说"约束"这个词。大家在生活里经常能听到它：小时候学校会约束你不能去网吧、不能去游戏厅，你的家长也会约束你。真去了游戏厅被家长抓住，会怎么样？难免来一顿男女混合双打。

> **定义**：约束指的是对某些行为的一种限制。但这些限制并不一定是坏事，它可能对我们有一个保护作用。

数据库的约束是什么意思呢？**数据库的约束是一个表级别的一种规定，它是对表中数据的一种限制语法。** 注意，它限制的是数据。

那为什么突然要限制数据呢？举个例子，假如我们有一个学生表，里面有一个手机号列，我要求学生在填写的时候**必须**填写手机号——你要怎么限制呢？这时候就可以在手机号这一列加一个**非空约束**。除此之外还有很多，比如填身份证号不能重复、要有唯一约束等等，这些都属于约束。

> **结论**：约束的作用是来保证表中数据的准确性、可靠性和正确性。**你不要去相信录入数据的人，你更应该去相信约束给你带来的保障。** 如果数据不符合约束，最终在插入或修改的时候会直接报错。

约束添加的时机一共两种：一种是创建表的时候，在 `CREATE TABLE` 的时候添加；另一种是表创建完毕以后，用 DDL 里面的 `ALTER TABLE` 修改表的时候添加。通过这一章的学习，能让大家在创建表结构的时候，表会更加合理和清晰。

### 约束的三类

约束一共分为三类：列（或者域）级别的约束、实体（或者行）级别的约束、引用参照约束（一般叫引用约束，或者多表级别的约束）。这几个分类只是为了方便大家记忆，相当于给大家分了个子类。

它们之间的对比范围是**逐渐增大**的：

```text
  列 / 域级别   →   只用看自己这一列
        ↑
  实体 / 行级别  →   要跟同一个表里的其它行比
        ↑
  引用（外键）级  →   要跟另一张表比
```

#### 列级（域级）：只看自己这一列

什么叫列和域级别的约束？这一类约束**只对当前的列有效果**。像我们刚刚说的手机号不能为空，这就是一个列级别的约束。它不需要去关注其他的行、其他的列，只需要关注我自己是否符合这个约束。

具体的列级别约束大家记三个：

- **非空约束 `NOT NULL`**：要求某一列不为空；
- **默认值约束 `DEFAULT`**：在某一列给它一个默认值，插入数据的时候如果你不指定、或者指定空，它都会走默认值；
- **检查约束 `CHECK`**：检查某一列是否符合我们的一个规则。比如有个 `age` 列，要求插入的年龄必须大于 18 岁，这时候就可以在 `CHECK` 约束里写一个规则，要求大于 18 岁，否则无法插入。

> **提示**：`CHECK` 严格说并不是列级别的，它是表级别的——只不过放在这个位置讲也好理解，大家先这么记。它相当于一种**自定义约束**，可以写任何规则。

列级别的约束再强调一遍：只针对当前列有效，它不需要关注其它列。

#### 行级（实体级）：要跟同表其它行比

什么叫实体和行呢？MySQL 是一种关系型数据库，每个表代表一种大的类别，相当于我们之前 Java 中的 `Class` 的概念。而表里有个"行"的概念，行是操作的最基本单位，**一行就代表一个实体**——一行数据对应到 Java 语言里就是一个对象。

所谓行级约束的意思是：**此类约束需要对比同一个表中其它的行，才能得出结果**。之前列级别的约束只看单列就知道行不行，而行级别不行，它得对比其它行。

第一个例子是主键约束。主键约束代表**不为空且值要唯一**。大家思考一个问题：假如有一个表，表里有很多行，第一行有一个属性值叫 `id`，这个行上有个主键约束——那这一行要写 1，后面就不能再写 1 了，重复了；它还不能为 `NULL`。那么这一列到底能不能插入，是不是要**对比其它行的这一列**才能知道？

所以它要参照其它行才能得出结果，这类约束就叫行约束、或者实体级别约束。

第二个是唯一约束 `UNIQUE`。它跟主键约束的不同点在于：主键是唯一且不为空，而唯一约束**可以为空**。举个例子，刚刚的手机号如果加非空约束并不好——学生可能就没有手机号。换句话说：**如果有手机号，学生之间的手机号不应该重复**。所以我建议手机号加一个 `UNIQUE` 唯一约束：可以没有不写，但如果要写了，这一列里面的手机号之间就不能重复。它也是一个行级约束。

第三个是自增长约束，后面会讲。它对应主键类型，数值假如第一个是 1，第二个它就自动在原来基础上涨 1，变成 2、3——它会参照之前的一个值递增涨，所以这也是一个行级约束。

先记大概有哪些约束、大概的分类就可以了。

#### 引用（外键）：要跟另一张表比

最后这一类叫引用约束，其实也叫外键约束。这类约束有个特点：它需要对比的**不仅是不同的行，而是其它表**，才能得到效果，所以这类约束也叫多表约束。

怎么才能说对比多表才有效果呢？举个例子。假如我们有一个学生表，还有一个分数表：学生表里有学号和姓名，学号是 1 号、2 号；分数表里有分数、学科，还有学生的学号——分数是 99 分、学科是 Java，这儿写个 1 号学生；20 分是 MySQL，是 2 号学生。

那这个学号的值能瞎写吗？不能。假如你想写个 3，都没有这个学生，怎么能写 3 呢？这里就引出了多表之间的关系。

所以这时候我们可以对这一列加一个参照约束、也叫引用约束，叫 `FOREIGN KEY`。加了以后，这一列的值必须参照另外一个表的某一列的值，不匹配就报错。这类约束是限制多表之间的、限制跟另外一个表之间的数据是否匹配，所以叫多表级别的约束。

到这儿为止，三大类就齐了：

| 类别 | 对比范围 | 包含的约束 |
| --- | --- | --- |
| 列 / 域级别 | 只看自己这一列 | 非空 `NOT NULL`、默认值 `DEFAULT`、检查 `CHECK` |
| 实体 / 行级别 | 跟同表其它行比 | 主键、唯一 `UNIQUE`、自增长 |
| 引用（外键）级别 | 跟另一张表比 | 外键 `FOREIGN KEY` |

> **结论**：前两类都属于同一个表内的约束，第三类是跨表的。一共要学的约束是 $3 + 3 + 1$，一共 7 种。这一章我们会走三个方向：第一，理解每个约束的作用；第二，学会如何添加这类约束、怎么删除；第三，学会如何去删除这类约束。

### 非空约束

先讲非空约束。它的作用其实很简单，就是**限定某一个字段或者多个字段的值不能为 `NULL`**，关键字叫 `NOT NULL`。表里如果有两列 `age` 和 `name`，这两列的值都不能为 `NULL`，就需要给这两列都加上非空约束。

在说怎么添加之前，先说几个非空约束的特点：

- **第一，所有的类型都可以加非空约束**，包括数值类型。如果有数值类型的列，不添加非空约束也可以放空值 `NULL`，加了非空约束以后就变成不能为 `NULL` 了；
- **第二，非空约束是加在列上的**，在创建表过程中或修改表过程中，在列的后边直接追加非空约束；
- **第三，可以多次使用**，一个表中可以有 $N$ 个列加非空约束，并不是只有一个；
- **第四，关于空的判定**：空字符串不算空，数值的 `0` 也不算空，只有真的 `NULL` 才算空。

> **易错点**：这最后一条是高频错点。`''` 是空字符串，它有值，存得进去；`0` 是数值 0，它也有值。只有 `NULL` 才是真的空。

#### 怎么加，怎么删

添加方式有两种：创建表的时候添加，或者建表以后修改添加。

第一种，创建表的时候，只需要在字段、类型后面加个 `NOT NULL` 就可以了，代表当前这个列是非空的；有多个列就继续再加。

第二种，修改表，在 `ALTER TABLE` 后面写 `MODIFY`——修改某个表中的字段还有原类型，最后再加上 `NOT NULL`。`MODIFY` 可以修改字段的类型，如果类型不变，只要加 `NOT NULL`，就相当于对原有字段添加了一个非空约束：

```sql
ALTER TABLE 表名 MODIFY 列名 数据类型 NOT NULL;
```

删除也很简单，可以通过后续修改表把它变为空，两种写法：

```sql
ALTER TABLE 表名 MODIFY 列名 数据类型 NULL;
```

或者

```sql
ALTER TABLE 表名 MODIFY 列名 数据类型;
```

把 `NOT` 去掉写成 `NULL` 就可以了；后边啥也不写也可以——**如果一个列不写非空约束，默认就是允许为空的**。

#### 拿 emp1 走一遍全流程

建一个表叫 `emp1`，里面有一个 `name` 和一个 `age`。我们把 `name` 这一列放在创建表时加非空，`age` 放在后期修改表时再加非空约束：

```sql
CREATE TABLE emp1 (
    ename VARCHAR(20) NOT NULL,
    eage  INT
);
```

建好以后怎么看有没有非空约束呢？用 `DESC` 关键字查看表结构：

```sql
DESC emp1;
```

用 `DESC` 能看表结构，我们只关心 `Null` 这一列：

```text
  ename | NO    ← 建表时加了 NOT NULL，不能为空
   eage | YES   ← 建表时没加，允许为空
```

怎么在创建表以后加呢？用 `ALTER` 关键字：

```sql
ALTER TABLE emp1 MODIFY eage INT NOT NULL;
```

这就加上非空了。再 `DESC emp1;` 看一下表，这个位置也不能为空了。

搞定以后怎么删除非空约束？两种：

第一种，修改表时在后边加一个 `NULL`，代表它可以为空：

```sql
ALTER TABLE emp1 MODIFY eage INT NULL;
```

执行后再查看表结构，就是允许为空。第二种就是不写，默认就是允许为空：

```sql
ALTER TABLE emp1 MODIFY ename VARCHAR(20);
```

`ename` 的非空约束就这样给它删掉了，变成一个光秃秃的 `varchar(20)`。执行一下，大家看，是不是都可以为空了？

> **结论**：非空约束一句话总结——语法是在列后边加 `NOT NULL`；作用是限制某一个列或多个列的值不能为 `NULL`；添加时机可以是建表时，也可以是建表后用 `ALTER`；删除就是改回 `NULL` 或者干脆不写。
