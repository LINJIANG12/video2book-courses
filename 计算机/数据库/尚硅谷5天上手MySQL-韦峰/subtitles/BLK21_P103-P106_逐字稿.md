接下来进入到第13节，讲讲 MySQL 8 以后的两个非常重要的新特性。

首先先一一说明。第一个要讲解的新特性叫窗口函数。窗口函数这个概念并不是 MySQL 专有的，在其他数据库中很多都是支持的，只不过 MySQL 到 8 以后才支持。

什么是窗口函数？它有什么作用？先不用理解它是啥，先理解它的作用。它的作用就是允许在结果集执行聚合、分析、排序相关操作时，而不改变结果行数。

这句话什么意思？之前讲过单行函数还有多行函数。多行函数当时只讲了聚合函数，当然还有很多多行函数。如果一旦使用多行函数，返回的结果就不能再是多条了，它会直接帮你变成一条。也就是说，像聚合这类多行函数只能单独使用，无法跟我们正常的查询数据一起使用。

但是如果有了窗口函数，接下来就可以在查单条数据的时候去携带多行函数。意思是它不会把所有数据压缩成一行了，也会分散在各个的单行中去体现这些多行函数的结果。大家可能还不太理解，没关系，我能通过练习给大家演示懂就可以。

窗口函数应用的场景是多行函数，那除了之前讲的聚合函数，像平均值、最大值以外，还有哪几个比较重要的多行函数？

第一个是序号函数，来获取数据的排列序号、第几名等，都是它。假如有一个分数表，想查出考试分数排在第几名，就可以用这些来进行排序，最终能造出一个序号列。

下面还有分布函数，比如你的分数在排名的位置是前百分之多少还是后百分之多少。还有前后函数等。

这些多行函数加上之前学的聚合函数，可以额外去应用窗口函数。窗口函数有点相当于一个包装和加工函数，它可以让多行函数在单行中去获取结果。

具体窗口函数到底要怎么写？窗口函数的语法是这么做的，首先要加个多行函数，加了以后，下面加一个 `OVER` 就可以了。这个就是窗口函数语法。只要加了这一段，多行函数就可以在单行中去显示了。

窗口函数的语法格式如下：
```sql
多行函数() OVER (PARTITION BY 列名 ORDER BY 列名 DESC/ASC)
```

也可以声明一个窗口并复用窗口，这个稍后单独解释。也就是说，多行函数加一个 `OVER`，后面加个括号就可以了。

我们通过一个案例来说明。打开客户端，第一步先准备一个表结构，创建一个商品表 goods（货物表）。表里面有 id、类别、类别名称、对应的商品名、价钱、库存以及上架时间。先把数据插入进来，执行完毕。

演示一下窗口函数怎么用。语法就是写一个多行函数，加一个 `OVER`，括号里面写 `PARTITION BY 列名`，后面还可以加 `ORDER BY 列名 DESC` 或者 `ASC`。

需求是查询所有商品的编号、价格、类别名称以及整体的平均价格。查询编号、名称、价格以及它的类别名称：
```sql
SELECT id, name, price, category FROM goods;
```
这是正常的单表查询，返回结果当然是多条。

怎么查平均价格？之前做过，平均价格就是：
```sql
SELECT AVG(price) FROM goods;
```
聚合函数是对整体统计返回一条数据。现在前面的查询是返回多条数据，而聚合是返回一条数据。现在的需求是既要前面的单条数据，还想要一个整体平均值，这是矛盾的。如果直接写：
```sql
SELECT id, name, price, category, AVG(price) FROM goods;
```
这样会报错，因为用 `AVG()` 的话，还想查其他列，只能是放分组的列，或者就是单条行，放不了多个值。

这时候就可以用窗口函数，只需要在后面加上 `OVER()` 就行了，括号里面啥都不用写。这一句话的含义就是把这个值分散到多个行中，这就是窗口函数的作用：
```sql
SELECT id, name, price, category, AVG(price) OVER() FROM goods;
```
执行一下，这样整体的平均价格就出来了。整体计算平均算出来之后，每一行都会体现。

接下来看新的需求：查询商品编号、价格、类别，以及该商品所属类别对应的平均价格，而不是整体平均价格。这里也用聚合函数，但不是算整体，而是算类别对应的平均价格：
```sql
SELECT id, name, price, category, AVG(price) OVER(PARTITION BY category) FROM goods;
```
根据类别分组，上面的女装精品是 121，下面是 593。它会按照当前商品对应的类别分组，所以 `PARTITION BY` 其实就是分组统计。

`ORDER BY` 也很好理解，如果在最终完成类别的价钱倒序或正序，可以再去计算平均价钱。这就是窗口函数的基本概念。

接下来看看其他的多行函数怎么应用于窗口函数。

第一个讲一下序号函数。序号函数指把条数按照某一指标进行排序。第一个序号函数是 `ROW_NUMBER()`，用于对数据进行排序。

需求是：查询商品表中每个商品在分类下的按价格降序排序的序号。也就是说，把这些商品在各自的类别中从 1 到 6 排序，户外用品也从 1 到 6 排序，按照类别范围内进行排序，同时还要考虑价格降序。

先写基础查询：
```sql
SELECT id, category, name, price FROM goods;
```
接下来想排序，写上：
```sql
SELECT ROW_NUMBER() OVER() AS num, id, category, name, price FROM goods;
```
如果直接写 `OVER()`，代表对整体数据排序，序号就是 1 到 10，跟 ID 是一样的。

现在的需求是按照类别排序，也就是按照类别分组，排类别组里面的序号：
```sql
SELECT ROW_NUMBER() OVER(PARTITION BY category) AS num, id, category, name, price FROM goods;
```
执行后就是按照组内排成 1 到 6。

接着要求按照价格降序，也就是从大到小排序。在后面加上 `ORDER BY`：
```sql
SELECT ROW_NUMBER() OVER(PARTITION BY category ORDER BY price DESC) AS num, id, category, name, price FROM goods;
```
这样 ID 为 6 的商品价格最高，就排在第 1，这就是 `ROW_NUMBER()` 的用法。不管价格是否相同，它都是按照连续的序号排下来的。

看第二个需求：查询货物表中每个商品分类下价格最高的三种商品。
把刚才查出所有商品分类排序的查询当作一个中间表，最外层筛选出序号小于等于 3 即可：
```sql
SELECT * FROM (
    SELECT ROW_NUMBER() OVER(PARTITION BY category ORDER BY price DESC) AS num, id, category, name, price FROM goods
) AS t
WHERE num <= 3;
```
这个就相当于查询每个商品分类里面排名前三的商品。

接下来看 `RANK()`。`RANK()` 排序会跳过重复序号。如果有价格相同的，比如第二名并列有两个，后面再跳过的就是第四名。这就像平时考试排名，第一名有一人，第二名有三人并列，那后面就没有第三名和第四名了，直接从第五名开始。

用法就是把函数换成 `RANK()`：
```sql
SELECT RANK() OVER(PARTITION BY category ORDER BY price DESC) AS num, id, category, name, price FROM goods;
```
如果查类别为 1 的，排序是 1, 2, 2, 4，因为有两个都是 2，所以跳过了 3，直接到 4。

而 `DENSE_RANK()` 则是连续的，即便有并列第二，后面紧跟着还是第三，排序就是 1, 2, 2, 3。

接下来看分布函数。分布函数主要看 `PERCENT_RANK()`。分布函数指的是在范围内的百分比，它的值在 0 到 1 之间。

假如考试有四个人的分数：80 分、90 分、100 分、70 分。100 分占的值是多少？它的公式是：
$$\frac{\text{rank} - 1}{\text{rows} - 1}$$
按照排名来说，100 分排第一名，$(1 - 1) / (rows - 1) = 0$，所以 100 分是 0，是最靠前的。
90 分排第二名，$(2 - 1) / (4 - 1) = 1/3 \approx 0.33$。它会算出你在数据中的分布范围。

来看具体的 SQL：查询货物表中女装类别下商品的 RANK 值及百分比分布。
```sql
SELECT 
    id, category, name, price,
    RANK() OVER w AS rk,
    PERCENT_RANK() OVER w AS pr
FROM goods
WHERE category = '女装/女士精品'
WINDOW w AS (PARTITION BY category ORDER BY price DESC);
```
第一位是 0，第二高价格由于总共 6 个数，$(2 - 1) / (6 - 1) = 1 / 5 = 0.2$，接着是 0.6、0.8、1。这就计算出了分布的范围值。值越小，证明越靠前。

这里用到了第二种语法，也就是窗口的复用。如果两个窗口函数的 `OVER` 里面的写法完全一样，写两遍比较冗余，就可以复用。
在最后声明一个 `WINDOW w AS (PARTITION BY ... ORDER BY ...)`，然后在前面直接写 `OVER w` 即可，这就是窗口定义的复用。

除了分布函数，还有前后函数。前后函数顾名思义：返回当前行的前 $n$ 行数据，或返回当前行的后 $n$ 行数据。

需求：查询货物信息表中前一个商品价格与当前商品价格的差。不仅要查当前的价格，还要查与上一个商品的价格差：
```sql
SELECT 
    id, category, name, price,
    LAG(price, 1) OVER w AS pre_price,
    price - LAG(price, 1) OVER w AS diff_price
FROM goods
WINDOW w AS (PARTITION BY category ORDER BY price ASC);
```
`LAG(price, 1)` 中，第一个参数代表要获取哪个字段的值，第二个参数 1 代表前一个，2 就代表前两行。如果没有前一行就是 NULL。这就是用来取某一列的前几行值。

同理，`LEAD()` 则是取后几行的值。

还有首尾函数：`FIRST_VALUE()` 和 `LAST_VALUE()`，分别代表取第一行的值和最后一行的值。按照价格排序查询第一个商品的价格信息，就是使用 `FIRST_VALUE()`。

这就是窗口函数的使用。大家一定要把讲到的窗口函数这几个例子亲自练一遍。

接下来搞综合查询练习。
第一题：查询每个部门的平均工资。
需求是显示部门信息以及部门的平均工资。
分析一下：需要查哪些表？很明显，员工才会有薪水，所谓部门的平均薪资，实际上是员工按部门分组后的平均薪资。
所以数据来自于员工表和薪资表。

查询语法首先需要多表连接查询，将员工表作为逻辑主表；第二，要算部门的平均工资，再加上分组查询。分组查询只能查到分组字段和聚合函数。

编写 SQL 语句：
```sql
SELECT 
    e.department_id, 
    AVG(s.salary) AS avg_salary
FROM employees e
LEFT JOIN salaries s ON e.emp_id = s.emp_id
GROUP BY e.department_id;
```
这样就查出了每个部门的平均工资。

如果还想要部门的名称，就再去 `LEFT JOIN` 部门表：
```sql
SELECT 
    d.department_name, 
    AVG(s.salary) AS avg_salary
FROM employees e
LEFT JOIN salaries s ON e.emp_id = s.emp_id
LEFT JOIN departments d ON e.department_id = d.department_id
GROUP BY d.department_name;
```
执行之后，就查出了各个部门的平均工资。由于使用的是左外连接，没有部门的员工对应的平均薪资也能统计出来。这就完成了第一个综合练习题。
