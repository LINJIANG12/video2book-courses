第一章已经全部讲解完毕，数据库的准备工作已经全部搞定。接下来进入到课程的第二章节，去完成DDL语言的学习。通过DDL语言，我们掌握对数据库容器的创建、修改和删除。

在第二章节，也分为四个小节进行讲解。第一小节还是再去强调一下DDL的作用以及内部的关键字有哪些，让大家再次清晰一下。第二小节，在编写SQL语句之前，建议大家先把自己的行为和命名先规范起来，后期整体就会顺很多，所以在第二小节先讲讲SQL命名的规定和规范，怎么去命名会更好一些。第三小节开始讲关于容器的操作，主要讲对库管理的这些语句怎么写。第四小节主要讲对表管理的语句有哪些。

这就是一共四个小节。我们先进入第一小节，DDL，也就是数据定义语言的概述。

首先要先去思考一个问题，一条数据是如何插入到数据库的，它大概要经历哪些过程，为什么我们要先学DDL语言？

一条数据插入数据库大致分为四步。就像把大象装冰箱可能有三步，我们把数据插到数据库有四步：
第一步，首先要创建一个库。没库，就没地方装它，库是最大的一个容器。
创建完库以后，在当前库下应该创建表。但是大家注意，在创建表之前，先要明确存的这类数据应该有哪些字段。如果不明确字段，也没法创建表。
明确完字段以后，第三步再去创建表。假如说创建一个学生表，里面有哪些字段，这就好了。到前三步就把表准备好了。
第四步，我们就可以往表中去插入数据了。

我们正常的数据操作都由四步去组成，而前三步就是我们所说的数据定义语言。它主要是完成容器相关的操作，库管理和表管理。所以它一定是我们先行学习的一个方向。

大概理解了以后，接下来系统介绍一下数据定义语言的概念。老说DDL，它是怎么来的？数据定义语言是由三个单词缩写而成，分别是Data Definition Language，叫数据定义语言，简称为DDL。它的主要作用是用来定义和管理数据库的结构。这个结构包含要讲的库、表，以及后期可以优化扩展学习的索引、视图等等。这些对象都是在DDL语言去实现的，包括它们的创建、删除以及修改。创建一个库、删除一个库、修改库，创建表、修改表和删除表，它都能去搞定。我们本次重点学习对库和表的行为操作。

另外还要去理解一点，DDL不涉及对数据相关的操作。也就是说DDL不是玩数据的，它是玩容器的。当然也要理解，如果要删了库，库里面的数据也没了，那也得跑路。它专注的是对容器的操作，关注的是对数据结构和元数据，也就是容器的操作，这就是DDL。

了解了DDL之后，大概了解一下它内部到底有哪些关键字。学SQL语句其实就像学Java一样，记它的关键语法和关键字。

DDL一共有三个关键字，大家记住就可以了：
第一个叫 `CREATE`，单词的含义是创建。用这个关键字，最终可以完成库、表、索引等的创建。
第二个叫 `ALTER`，这个单词翻译过来是修改的意思，指的是可以用这个关键字去完成我们库、表等等相关的修改，以及列的修改。
还有一个叫 `DROP`，一个极其危险的关键字，删除。我们可以用它去完成库、表等等索引相关的删除。

大家先大概了解这三个关键字，后期在学的时候，都以这个关键字去引发、触发对应的动作。这就是DDL的一个介绍。

介绍完数据库的定义语言之后，在做编写SQL语句之前的最后一项准备工作，来说一说SQL语句的命名的规定和规范。

大家很多都是第一次接触SQL语句，希望大家能使用最标准的SQL命名规范来编写出漂亮的SQL语句。出去工作，让别人一看一夸：这小伙子、小姑娘真棒。接下来进入到第二小节，来讲讲SQL的命名规定和规范。

首先大家要知道，规定和规范是两个词，也是完全两个不同的意思。规定指的是不能这么做，要是这么做了，它相当于报错，类似于生活中的法律，是不能触犯的。规范指的是怎么做会更好，如果不这么做，也不报错，它类似于生活中的道德约束。举个例子，假如我去坐公交车，来了一个老头，我非常有道德，在没有座位的情况下可以让老头骑我脑门上，证明我这么做会更好；当然如果说我有座位，老头来了，我不给老头让座，这个东西我认为也不会有法律去触犯或者惩罚我。这就是规范。

了解了以后，先要讲的是规定，来确保大家先不犯错，再去说规范怎么做会更好。

首先来介绍一下标识符，也就是这些容器的名称命名的规定是什么。一共罗列出了五条规定，必须围绕这个用法：
第一条，关于命名的长度问题，不得超过30个字符。命名不要太长，不要超过30个字符。这是一般情况下很少会超过的点。
第二，命名只能包含大写的字母、小写的字母、0到9以及下划线。除此之除外，除了这63个字符，其他都不能包含。并且它也能像Java一样，不能用数字开头，这点大家一定要记住。
第三点，数据库、表、字段这些名称中，中间不能包含空格，不能写空格。
第四，在同一个软件中，库名不能重复。我们可以创建很多库，但是在同一个MySQL管理系统中，库是不能重复的。而在同一个库中，表是不能重复的。假如我有A库和B库，两个库中都有一个叫student表，这是没问题的；但如果在A库中不能出现两个student表。同一个库中表不能重复，而在同一个表中，字段也不能重复。因为一旦重复了，根本就不知道操作的到底是哪一列。这是我们的一些命名不能重复的规则。
第五点，必须保证字段没有保留字段、保留字，还有数据库的关键字等等。也就是说在命名的时候，不要去用数据库现在已有的那些关键字去用作表名和容器名。这其实跟Java一样，在Java中定义一个属性，能不能叫class？是不是也是不行的，也是同样道理。

如果坚决要使用关键字呢？举个例子，有一个订单表，订单就想起名叫 `order`。坚决要使用这个关键字，怎么办？`order` 除了订单的意思，它还有一个排序的意思，在数据库里面指的是排序关键字。如果非得用，需要在这个容器的名称加上着重符号，两个反引号包裹起来：

```sql
`order`
```

这就可以了，这样它就不识别为关键字了。后期如果想对这个表进行操作，在用的时候也记住，插入数据、读取数据、指定表的时候都要加这个反引号就可以了。所以只要非得用关键字，不能直接用，需要加反引号，也是可以用关键字的，但是不建议。

这就是SQL语句的五个命名规定，是不能打破的。

看一下哪些命名是可以命名的，哪些命名是不可以命名的。

可以命名的：都是英文，且没有超过30个字符；用下划线去连接；写两个下划线，中间加一个大写字母；这些都是可以命名的。

不可以命名的：
字符没有超长，也都是小写字母，但中间加了空格，不能包含空格；
虽然用了小写，但中间用了一个特殊符号进行拼接，我们只支持那63个字符，其他都不支持；
使用了 `select` 关键字，不建议把查询关键字放在前面，放了以后可能会误认为是一个关键字，所以会报错；
使用了数字开头；
中间包含空格。
所以这些是绝对不能这么叫的。

介绍完规定以后，接下来介绍规范。我们现在掌握了标识符的命名规则，知道这些东西可以这么叫。但是虽然可以这么叫，它到底好不好，或者是后期在创建库、表，还有列的时候，我们要怎么叫，其实我们心里边好像也没有一个标准。为什么会出现这样？因为现在只知道规定，只能知道不能这么做，但其实不知道规范应该要怎么做更好。只知道规定，但不知道规范，就没有标准。

接下来给大家说一说库、表、列的命名规范是什么，给大家做一个指导。

这套规范是来自于国内非常知名的阿里巴巴规范手册。基本上国内的Java开发都围绕阿里巴巴这套规范手册进行命名、定义变量。这里边它也做了SQL的规范，来确保效率、安全性和可维护性。规范中到底说了什么：

第一点，如果加了注释，注释是为了描述这段代码的，我们通过读取注释，不用看代码就知道它干什么。所以大家记住，一定要保证注释的描述一定是清晰的，而且简洁的。如果注释写得很乱又不简洁，建议别写注释，因为这成了一个错误的指南。
第二，库、表、列名应该使用小写。注意，这个所谓应该不是强制规定，可以用大写，但其实建议小写。为什么？因为很多开发工具会把关键字识别成大写，而名称是小写，这样就把它区分出来了。如果名称突然间写完以后变成大写了，证明写成关键字了。所以建议把这些名称写成小写字母。而且有多个词进行拼接，推荐使用下划线。下划线这种命名形式叫蛇形命名法（snake_case）。不推荐使用Java中的驼峰式，可以用，但不推荐。总结出来：命名用小写，如果多个单词之间用下划线拼接，这样最标准。
第三，库、表、列应该简洁明了，具有描述性。这跟Java中类似，起这些变量名一定是有描述性，别瞎搞，也别用拼音，实在不行找个翻译软件翻译一下。

接下来具体说说库、表、列的命名规范：

库的命名应该跟应用程序是一致的。后期一个应用对应的是一个库，建议库跟程序对应。举例子，如果有一个Java项目名，在数据库不建议写成大驼峰，把它们都变成小写，两个单词拼接不用驼峰式，用下划线进行连接就可以了。这就是库应该怎么命名。

表的命名最好遵循的是业务表。表对应的是某个业务，一个库中有很多表，表对应的应该是业务，例如支付任务、强制项目，还有一些配置等等，可以用业务的名称去命名表。当然也没说必须是两层，如果只是个字符，写成单层也是没问题的。这就是表的命名。

列的命名要遵循的是实体属性，因为列要装具体的某一个属性值，它代表的应该跟属性是一致的。它有点类似于Java中的属性命名。比如 `product_name`、`product_price`、`customer_id` 等等，用下划线进行拼接。表命名就相当于类命名，列命名就相当于属性命名，只不过不是驼峰式，而是用下划线进行拼接。

这就是阿里巴巴规范手册给我们的规定，我们应该怎样做会更好一些，这就是一个标准。

参考几个标准的命名：
库的命名：用下划线进行拼接，写两层、三层都可以，只要不超过30个字符，都是没问题的。
表的命名：写三层，但注意，后面其实有点冗余，后面的 `table` 可以不用加。假如说 `user_account` 用户的账号，或者是 `order_detail` 订单详情，或者是 `product_catalog` 等等，这都是可以的，后面的 `table` 就可以不用加了，省略一下更简短一些。
列的命名：比如 `customer_id`、`product_name` 等等，这就是对列的属性的一个描述。

这就是规范性的命名。这个章节我们就把MySQL命名的规定和规范讲完了。大家把这个好好去掌握一下，后期我们就按照这个规定和规范进行统一标准命名。

讲完SQL命名规定和规范以后，接下来正式去学习数据库定义语言之对应的库管理。

对库的管理无非包含几个方向：第一，库的创建；第二，库的删除；还有库的修改和查看等等。因为SQL指令特别多，我们一个方向一个方向慢慢去磨，慢慢去学。

首先讲讲关于库的创建的指令有哪些。

我们在创建数据库的时候，首先需要明确一个事情，只需要用对应的关键字，加上指定要创建数据库的名称就可以了，这就是必需的，必须指定的只有数据库名。除此之外，还可以在创建数据库的时候去指定字符集和排序方式。如果对字符集和排序方式不太了解，没关系，稍后会介绍。字符集和排序方式是可选的，如果不指定的话，库就会选用MySQL提供的默认字符集和排序方式。

接下来看看关于库的创建有几个相关的命令：

第一个命令：直接创建一个库，不指定字符集和排序方式，也就是选用MySQL默认的。它的语法非常之简单，DDL创建的关键字叫 `CREATE`，后面紧跟着空格，要跟一个 `DATABASE`。为什么要跟一个 `DATABASE`，不直接 `CREATE` 数据库呢？因为 `CREATE` 不仅能创建库，后期它也能创建表，所以要指定创建的方向是什么。这是一个联合关键字来创建库：

```sql
CREATE DATABASE 数据库名;
```

在写的时候是忽略大小写的，大小写都无所谓。空格就可以跟数据库名，分号结尾，这就是一个直接创建数据库的语句，特别简单。

第二个：创建的时候并且判断。第一个创建稍微有个弊端，如果创建的库存在，它会报错。第二种稍微是一种更优雅的创建方式：

```sql
CREATE DATABASE IF NOT EXISTS 数据库名;
```

如果这个数据库不存在，我就创建；如果要存在，也别报错，我就不创建。第二个有些判断，能避免库重复的时候报错。推荐使用第二种。

第三种指的是在创建库的过程中，可以去指定字符集或者排序方式：

```sql
CREATE DATABASE 数据库名 CHARACTER SET 字符集;
```

也可以加上 `IF NOT EXISTS`。如果想指定一个字符集，加一个 `CHARACTER SET 字符集` 就可以了。如果想指定一个排序方式：

```sql
CREATE DATABASE 数据库名 COLLATE 排序方式;
```

就可以了。这是单独去指定字符集或排序方式。如果指定了字符集，没有指定排序方式，那它的排序方式还走MySQL的默认值。

这是单向指定。如果想双向指定怎么办呢？也很简单，只需要写：

```sql
CREATE DATABASE 数据库名 CHARACTER SET 字符集 COLLATE 排序规则;
```

就可以了。它两不分先后，只要把它们都写上，代表又创建了一个库，同时自己指定了字符集和排序规则，这就搞定了。

问题来了，语法大概知道了，以后还得练，那字符集和排序规则到底是什么呢？

所谓的字符集就是我们常说的编码格式。我们存储的这些字符最终都是用字节存储的，字符集指的就是字符和底层存储的字节如何进行对应。我们要选择一个正确的字符集，否则就会出现常说的乱码问题。如果想使用中文，一般选用国际上知名的编码格式，即 UTF 系列，它内部可以进行中文的存储和映射。

在 MySQL 中常见的字符集有两个：一个是 `utf8`，这是 MySQL 早期版本的默认字符集。如果使用的是 5.7 或 5 系列版本，默认字符集就是 `utf8`。这个 `utf8` 用的是三个字节存储一个字符，不能完全覆盖中文的所有符号。因为只有三个字节，存储的位数少一些，有些符号找不到就会出现乱码，所以不推荐使用 `utf8`。随着 MySQL 的更新，现在使用的是 8 系列版本，现在的默认字符集叫做 `utf8mb4`。因为早期把 `utf8` 这个名称占用了，更新后就叫 `utf8mb4`。`utf8mb4` 指的是用四个字节去映射和存储字符，存储的宽度更广一些，基本能覆盖所有中文相关的存储内容，包括表情符号等都能进行存储，不会出现乱码。MySQL 8 系列版本默认的字符集就是 `utf8mb4`。

排序规则是在字符集的基础上，来决定字符之间如何进行比较的。例如在数据库里面存了一个小写的 `a` 和一个大写的 `A`，做等号比较判断。如果使用的排序规则是第一种 `utf8mb4_0900_ai_ci`，这种排序规则代表不区分大小写（大小写不敏感）。这两个字符在数据库中进行对比时，它的值是 true，即 1。另外一种是将 `ai_ci` 变成 `as_cs`（`utf8mb4_0900_as_cs`），这种代表区分大小写。如果把排序规则换成了它，这两种字符对比的结果就是 0（false），代表它会识别大小写。排序规则用来决定我们是否识别大小写。在 MySQL 8 系列版本中，默认选用的是第一种，即不区分大小写。后期在查询数据做对比时，大小写是忽略的，判定为相等。如果业务需求对大小写敏感，可以把排序规则换成 `as_cs`。

字符集决定是否乱码，排序规则决定字符如何对比。如果想查看当前配置，可以通过指令 `SHOW VARIABLES LIKE ...` 来查看字符集和当前数据库的排序规则。

接下来回顾创建数据库的语法：
首先选用 DDL 中的关键字 `CREATE`，如果要创建数据库，需要指定 `DATABASE`：

```sql
CREATE DATABASE 数据库名称;
```

判断并创建的语法：

```sql
CREATE DATABASE IF NOT EXISTS 数据库名;
```

创建数据库并指定字符集：

```sql
CREATE DATABASE 数据库名 CHARACTER SET 字符集;
```

创建数据库并指定排序方式：

```sql
CREATE DATABASE 数据库名 COLLATE 排序方式;
```

同时指定字符集和排序方式，中间用空格隔开即可：

```sql
CREATE DATABASE 数据库名 CHARACTER SET 字符集 COLLATE 排序方式;
```

在 MySQL 8 中，默认字符集是 `utf8mb4`，默认排序方式是 `utf8mb4_0900_ai_ci`，代表用四个字节存储字符且忽略大小写。查看对应参数的命令为：

```sql
SHOW VARIABLES LIKE 'character_set_database';
SHOW VARIABLES LIKE 'collation_database';
```

进行一个实战小练习，创建一个名为 `ddl_d1` 的库，指定字符集为 `utf8`，排序方式指定为大小写敏感的 `utf8mb4_0900_as_cs`：

```sql
CREATE DATABASE IF NOT EXISTS ddl_d1 CHARACTER SET utf8 COLLATE utf8mb4_0900_as_cs;
```

执行后会报错，提示排序规则不能在该字符集中使用。因为写的是 `utf8`，等同于 `utf8mb3`，与 `utf8mb4` 不是一套，排序规则必须在对应的字符集下设置。因此必须选用 `utf8mb4`：

```sql
CREATE DATABASE IF NOT EXISTS ddl_d1 CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_as_cs;
```

执行成功，刷新连接后数据库便创建完成了。

接下来讲解数据库的查看和使用。
查看 MySQL 中的所有库：

```sql
SHOW DATABASES;
```
注意因为有多个库，所以使用的是复数形式 `DATABASES`。

查看当前使用的数据库，使用的是一个函数：

```sql
SELECT DATABASE();
```
MySQL 中可以有很多数据库，对数据进行操作的前提是必须先选中一个库。要查看当前选中的是哪个库，就使用该命令。

查看某个数据库下的所有表：

```sql
SHOW TABLES FROM 数据库名;
```

查看当初创建该数据库时的建库语句：

```sql
SHOW CREATE DATABASE 数据库名;
```

接下来讲解修改和删除数据库的相关指令。
修改数据库只能修改字符集和排序方式，不能直接修改数据库的名称，MySQL 没有提供直接重命名数据库的语法。如果某些可视化工具提供了修改库名的功能，其底层做法无非是将旧库备份导出，创建新库导入数据，再将旧库删除。

修改字符集的关键字是 DDL 中的 `ALTER`：

```sql
ALTER DATABASE 数据库名 CHARACTER SET 字符集;
```

修改排序方式：

```sql
ALTER DATABASE 数据库名 COLLATE 排序方式;
```

如果两者同时修改：

```sql
ALTER DATABASE 数据库名 CHARACTER SET 字符集 COLLATE 排序方式;
```
一般将字符集写在前面，因为排序方式依赖于字符集。

需要注意：数据库中没有修改名称的指令。如果想改名字，需要先备份数据，删除旧库，创建新库并指定新名字，再恢复数据。

删除数据库是一个极其危险的操作，必须三思而后行。删除数据库有两种方式：
直接删除：

```sql
DROP DATABASE 数据库名;
```

带判断条件的优雅删除：

```sql
DROP DATABASE IF EXISTS 数据库名;
```
这种方式会先判断该数据库是否存在，如果存在则删除，不存在也不会报错。

但是它有 `IF EXISTS`。大家注意，当初我们在创建的时候有一个什么呢？有一个叫 `IF NOT EXISTS`，代表不存在创建；而删除指的是你有、存在才能删除，没有 `NOT`。下面是数据库名就可以了。

这里边大家要注意一个事情，删除是一个危险命令，要确认、明确再操作。如果没确认可别擅自做这个事，跑路犯不上。这就是关于我们库的几个修改和删除相关的命令，大家把这记下。这节课我们先到这，下一节课我们做一个综合小练习。

在创建之前我们需要理解几个：创建库和创建表有什么不同？
大家知道，创建库就好比我们在计算机中去创建了一个 Excel 表格文件，其实我们只需要指定文件的名字或者字符集就可以了，它就这么简单。而大家想个问题，如果你要创建表，那不就相当于我们在这个文件内创建一个表格吗？表格其实除了写名字、字符集等等，我认为它还有好多东西要写。例如表里边有哪些字段，字段都叫什么名，这个名字又有什么类型等等。所以说创建表的时候一般需要指定表名、字符集以及表中的字段，也就是所谓的列，和列的类型等等，还要加一些其他的描述符等等，它的语法会很复杂。

那么 MySQL 是怎么把创建表的这么多元化、复杂的这些内容混合到一个语句中呢？这个语句长什么样呢？不要急，我们一点点去拆解它。我们一起来接触一下创建表语句。
