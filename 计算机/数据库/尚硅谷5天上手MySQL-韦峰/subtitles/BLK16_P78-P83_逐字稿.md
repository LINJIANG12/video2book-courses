介绍完内连接的查询语法和特点以后，接下来我们具体做个实战。

首先我们先准备三张表，用于查询的备用。这三张表分别是一个岗位表，还有一个部门表，以及员工表。在部门表里面包含三个字段，分别是部门的编号、名称以及简介。岗位表里面包含岗位的编号、名称和简介。最后在员工表中有员工的基本信息。在员工表里面引用了岗位，在下方还引用了部门。也就是说，员工表相对来说是子表，这里边存在两个外键，分别引用了岗位和部门相关的信息。这里面就存在了主外键关系，一会儿我们就可以做多表查询了。

完成以后，下方一共准备了五个场景。在五个场景中，咱们细化讲讲内连接的使用。我们先打个断点，把表结构和数据准备好，咱们再依次练习五个场景。

在下发的资料中，有一个叫 `test`，会有 `07_DQL_多表` 的 SQL 代码。打开它以后，在第三个小模块中就有准备的表结构。第一个准备的是部门表，里面有三个字段：`did`、`dname` 以及描述，一共准备了六条部门数据。第二个准备了岗位表，里面有 `jid`、`jname` 以及它的描述，一共准备了 12 条岗位数据。最后下方准备的是员工表，员工表里面通过 `job_id` 以及 `did` 来引用岗位以及部门相关的编号，员工有 `eid`。下方一共插入了 27 条员工数据。部门六条，岗位 12 条，员工一共是 27 条。大家把这几张表执行一下。数据准备好以后，接下来我们在下方做查询练习。

看第一个场景，演示基本查询语法，以及演示笛卡尔积的问题。在本次查询中，我们不添加主外键相等条件，专门演示连接查询的实现原理，它到底是怎样实现的。

看需求：查询员工的编号、姓名以及所处的部门编号和部门名称。在分析表查询结果的时候大家会发现，前面的员工编号以及部门编号，其实在员工单张表中就可以拿到，编号、姓名以及部门编号都是有的。但是这次多要了一个部门名称，这在员工表里就没有了。部门名称就在我们的部门表中，也就是 `dname`。想要在一条结果中展示两个表中的数据，这很明显就要做多表查询了，而且这次应该做的是水平多表查询，拼到一行。

做水平多表查询之前，一定要分析一下它们有没有关系，答案是有的。两张表中存在主外键，`did` 是部门表的主键，而在员工表中的 `did` 是外键，那我们就可以做到这个事情。具体怎么写，我们分两种语法。

第一种用的是标准语法：
```text
表1 别名 inner join 表2 别名 on 主外键相等
```
其中 `inner` 可以省略。我们先不加主外键相等，先不加 `on` 条件去消除笛卡尔积。

第二种是非标准语法：
```text
from 表1 别名, 表2 别名 where 主外键相等
```
也就是把 `inner join` 换成逗号，把 `on` 变成 `where`。

我们一一进行展示。首先写标准语法：
```sql
select
    e.eid,
    e.ename,
    e.did
from t_emp e
inner join t_department d;
```
先不加主外键。先看连接语法是怎么实现的，就是把所有的行都拼接到一起。如果写成 `select *` 执行一下，前面到 `did` 为止都是员工的信息，后边一行中已经把部门拼接到一起了。所以取的时候，可以这样写：
```sql
select
    e.eid,
    e.ename,
    e.did,
    d.dname
from t_emp e
inner join t_department d;
```
这样就相当于把每行中想要的列筛选出来了。

这个数据到底对不对呢？我们把 `d.did` 也查一下：
```sql
select
    e.eid,
    e.ename,
    e.did,
    d.did,
    d.dname
from t_emp e
inner join t_department d;
```
执行后大家会发现这个数据并不对。孙洪亮是一号部门的，但一号部门是研发部，不是财务部。但是结果里面也有财务部，这是为什么呢？这就是我们说的一个经典问题。我们所谓的连接查询，就是将所有的行都拼接一遍，拼接成一张单表。现在没有做筛选，如果要筛选就要加主外键。大家理解完以后，这叫做笛卡尔积原理，但它也是连接查询的原理，把所有可能都拼接一遍，里面肯定有对的，但也会有错的。

是不是都拼接了一遍？我们可以算一下。通过聚合函数查询总条数：
```sql
select count(1)
from t_emp e
inner join t_department d;
```
员工一共有 27 条数据，部门一共有 6 条，结果应该等于 $6 \times 27 = 162$ 条数据。执行一下，结果确实是 162。所谓的连接查询就是全都拼接一遍，这就产生了笛卡尔积。

接下来我们再用非标准语法实现一遍，非常简单：
```sql
select
    e.eid,
    e.ename,
    e.did,
    d.dname
from t_emp e, t_department d;
```
只需要把 `from` 后的 `inner join` 去掉，两张表加逗号隔开即可。它用的底层原理也是内连接，全连接一遍，执行也能查出同样的结果。

这是第一种，我们演示了语法的基本使用，但现在存在一个问题，就是笛卡尔积。

怎么能去掉这个问题，拿到正确的数据呢？其实大家通过数据看一下就知道了。孙洪亮不是财务部的，排除掉；孙洪亮是研发部的，保留。孙洪亮也不是测试部、市场部、后勤部、人事部。何进不是财务部的，排除掉；何进是研发部的，保留。再往下看，黄西蒙是市场部的。到底什么样的数据是对的呢？在笛卡尔积全都拼接一遍之后，对的数据的特点非常明显，那就是主外键相等的记录。条件唯一，就是主外键相等才是正确的连接数据。

如果想要获取正确的数据该怎么办？我们来看第二种写法。

用标准写法，在后边加一个 `on` 即可。`on` 就是连接查询放主外键相等的关键字，用来筛选笛卡尔积：
```sql
select
    e.eid,
    e.ename,
    e.did,
    d.dname
from t_emp e
inner join t_department d
on e.did = d.did;
```
加上主外键相等，就能拿到正确的数据了。执行看一下，这次拿到的就是正确的数据。

如果用非标准语法怎么写？非标准语法不用加 `on`，直接加 `where` 就行了：
```sql
select
    e.eid,
    e.ename,
    e.did,
    d.dname
from t_emp e, t_department d
where e.did = d.did;
```
这样就搞定了。

做个小总结：如果想获取正确数据，需要添加主外键相等条件，这是唯一的要求，只要用连接查询，至少要加这个要求。如果是 `join` 这种标准语法，在 `on` 后面添加主外键；如果是非标准语法，也就是 `表1, 表2` 这种，在 `where` 后面添加主外键相等即可。加上主外键以后才能保证连接正确。至于 `on` 后面能不能加其他条件，其实能加，但是在当前阶段大家只要记住 `on` 后面加主外键就行，加其他条件的情况等讲到项目实战时再去介绍。

接下来看第三个：`inner join` 优化的概念。其实也很简单，标准语法中的 `inner` 是可以省略的：
```sql
select
    e.eid,
    e.ename,
    e.did,
    d.dname
from t_emp e
join t_department d
on e.did = d.did;
```
这也相当于内连接，结果是一样的。也就是说，`inner join` 等同于 `join`，它们都属于内连接。`inner` 是可以省略的。

看第四个场景：如果想加一些额外条件该怎么办？

现在我们是查所有员工，如果有个需求是查询编号大于 10 的员工所处的部门编号以及部门名称，这就多了一个额外条件。如果有条件，直接正常添加就行。

非标准语法中有 `where`，在 `where` 后面已经加了一个条件，可以再接一个条件：
```sql
select
    e.eid,
    e.ename,
    e.did,
    d.dname
from t_emp e, t_department d
where e.did = d.did
  and e.eid > 10;
```
主外键相等和我们的筛选条件之间是 `and` 的关系，既要满足主外键相等，又要满足员工编号大于 10。

如果用标准语法，也是可以加 `where` 的。连接查询只是把结果集拼接到一起，拼接完了以后，依然可以正常加条件筛选，以及使用高级查询中的分组、分页等等：
```sql
select
    e.eid,
    e.ename,
    e.did,
    d.dname
from t_emp e
join t_department d
on e.did = d.did
where e.eid > 10;
```
执行查询，结果就是从编号大于 10 的员工开始了。

总结一下：如果有额外的条件，即非主外键相等条件，两种语法都正常添加 `where` 即可。多表查询就是先把表结果进行拼接，最后依然正常使用查询语法。

接下来介绍第五种场景，多表之间的查询。刚才只讲了两表之间的查询，那如果是多张表呢？其实只要讲到三张表就够了，我们需要找一下多表查询时的具体规律是什么。

其实多表查询是一个伪命题，所谓的多表查询，本质上就是多个两表查询。比如两张表，就是一个两表查询；三张表，其实就是两个两表查询。每次在写连接查询的时候，只需要关注当下的表关系即可，关联下一张表是谁，下一张表关联的又是谁，无限往后写就行了。

看一下这个规律怎么找、怎么写。需求是查询三张表并做条件筛选：查询编号大于 10 的员工的员工编号、姓名、所处的部门编号以及对应的岗位编号和岗位名称。员工表里面的信息我们知道，部门表的信息也知道，现在还要连接岗位表。这三张表要连在一起进行展示。需要明确一点，岗位跟部门没有直接关系，岗位也是跟员工关联的。这个查询要做的事情，就是查员工和部门，以及员工和岗位，把它们的结果都拼到一起。

首先写前边已经掌握的部分：
```sql
select
    e.eid,
    e.ename,
    e.did,
    d.did,
    d.dname,
    e.job_id
from t_emp e
inner join t_department d
on e.did = d.did;
```
这一步查询查出了两张表的关系。两张表执行完后，相当于产生了一张虚拟表。如果还想要岗位名称，继续连接即可。写完一套 `inner join ... on` 以后，在后边继续添加 `inner join`，其中 `inner` 可以省略：
```sql
select
    e.eid,
    e.ename,
    e.did,
    d.dname,
    e.job_id,
    j.jname
from t_emp e
inner join t_department d
on e.did = d.did
inner join t_job j
on e.job_id = j.jid;
```
这里边的 `job_id` 是来自于员工表 `e`，它是外键；岗位表 `t_job` 别名为 `j`，它的主键是 `jid`。这样就完成了三张表的查询。

如果还需要加条件，在最后加上 `where` 即可：
```sql
select
    e.eid,
    e.ename,
    e.did,
    d.dname,
    e.job_id,
    j.jname
from t_emp e
inner join t_department d
on e.did = d.did
inner join t_job j
on e.job_id = j.jid
where e.eid > 10;
```
执行后就查出来了。如果是四张表，就继续 `inner join`；五张表也是继续 `inner join`。掌握了内连接的语法规则，不断往后连接即可。写完以后如果有额外条件，最后该加 `where` 加 `where`。

如果用非标准语法怎么写？那就更简单了：
```sql
select
    e.eid,
    e.ename,
    e.did,
    d.dname,
    e.job_id,
    j.jname
from t_emp e, t_department d, t_job j
where e.did = d.did
  and e.job_id = j.jid
  and e.eid > 10;
```
在 `from` 后面把表一、表二、表三用逗号隔开列出来。在 `where` 后面，首先把两对主外键相等条件用 `and` 连接好，如果有其他条件，继续使用 `and` 追加。

我们来做个总结：
1. 有三张表，至少有两对主外键相等条件，中间是 `and` 的关系。如果有 $N$ 张表，至少有 $N-1$ 对主外键相等条件。
2. 语法结构：
   - 标准语法：
     ```text
     表1 join 表2 on 主外键1 join 表3 on 主外键2 ... where 其他条件
     ```
   - 非标准语法：
     ```text
     from 表1, 表2, 表3 ... where 主外键1 and 主外键2 ... and 其他条件
     ```

掌握了规律以后，多表查询非常简单。

在这部分内容结束之前，提前预告一个下节讲外连接时的小问题。

回到最简单的两表查询：
```sql
select *
from t_emp e
inner join t_department d
on e.did = d.did;
```
这是查询所有员工及其关联的部门信息。我们一共有 27 个员工，但其中有一个叫“周周”的第 27 号员工，他的 `did` 为空，代表他没有部门。我们用内连接时介绍过，它要求双方必须都具备主外键对应关系才能查到。执行查询后会发现，从 1 号查到了李红，确实没有查到周周。

内连接查询的结果要求两个表中必须都存在主外键匹配才能查到。如果用内连接查，现在是没有周周这条数据的。这就是内连接的特点以及相关语法。

介绍完内连接以后，接下来我们介绍外连接。只要把内连接搞懂了，外连接基本也能拿下。

外连接和内连接有什么区别呢？用白话来说，刚才我们发现查数据的时候没有周周的数据，因为周周没有部门，所以没有查到；而如果用外连接的话，就可以查到周周的数据。说白了，区别就在于能不能把没有对应部门的周周给查出来。

那么我们来看看，到底啥是外连接？

外连接是一种多表查询的一种方式，这不用说了。与内连接不同的是，外连接会返回所有符合的行，也就是说外连接会返回两个表中主外键相等的行，同时也会返回未匹配的行。这个所谓未匹配指的就是，你可以指定一个表为逻辑主表，那就算这个表没有被引用或者没有外键，它也会全部返回，能理解吗？好。那最终外连接分为左外和右外，这个左和右，它指的就是来指定左侧和右侧哪个表为逻辑主表，能理解吗？这就是外连接。

那如果说我们刚刚说了，我们有一个员工还有一个部门，我想要查到员工里面的周芷若怎么办？你就可以通过方向指定员工表为逻辑主表，那最终的结果它就会查到员工的信息，能理解吗？那部门的位置没有怎么办？它就会置空。好嘞。那下方我们来先看一下这个语法。

我把这个工具打开，咱们来。语法来说大家听我说，第一个就是这个位置看，它只不过多了一个什么呢？LEFT或者RIGHT。它没有非标准语法，它都是标准语法。在下方输出外连接，它后面多了一个叫OUTER，之前是不是叫INNER啊？那这个OUTER是可以省略的。也就是说，LEFT OUTER JOIN或者是LEFT JOIN或者是RIGHT JOIN就是外连接，而直接写INNER JOIN或者JOIN就是内连接，剩下其他都一样。好，这就是一个内外连接。而LEFT和RIGHT是来指定哪个是逻辑主表，如果LEFT是左，那这就是逻辑主表；如果RIGHT右，那这就是逻辑主表。大家理解这个意思吗？好，这就搞定了。

之后我们来说说细节。第一个细节就是内外连接的区别，就是内连接只有满足匹配条件的行数才会返回，也就是说两个表中必须存在主外键值且这个值相等才会返回。能理解吗？也就是说它得判定主外键值相等且两值都得有才能返回。而外连接可以通过左右来指定一个表为逻辑主表，它或者它为逻辑主表。那逻辑主表数据一定会查到，那就算我的没有外键或者是没有被引用，我也能够查到，能理解吗？是这样一个需求。

之后，内外连接的语法都可以优化，就是外连接可以省略我们的OUTER，而内连接可以省略INNER。也就是说外连接写法就是RIGHT或者LEFT OUTER JOIN其实跟LEFT JOIN或者RIGHT JOIN它都是效果是一样的。而如果单纯只写一个JOIN那就是内连接，大家理解了吗？说前期大家容易弄混的就是区分不好内外连接，大家记住只写一个JOIN就是内连接，加上RIGHT和LEFT就是外连接。好，这就可以了。

之后下方还有一个就是连接的连续性，大家听我说。这里边这也算是一个小技巧，提前给大家说，就只要在开发中，一旦你写了找到一个逻辑主表，建议大家把这个逻辑主表放在第一位。那既然它为逻辑主表就是第一个用左外连接，是不是以它为主啊？而后续你都不用思考了，后续全都是左外连接。因为大家思考个问题，第一个为逻辑主表跟第二个表查出这个数据，如果剩下你变成了右外连接或者内连接，那相当于第一个左外连接是不是就没有意义了？大家能理解吗？所以说开发中是有规律的，一旦选择了左外连接，后续全是左外连接，也都不用思考，没有什么内外连接混合用的这种思维或这种场景。好嘞，那这是我们说的三个小细节。说完以后大家也可能不太理解内外连接和外连接的区别，在下方我给大家说一个场景，给大家演示一下，看这。
