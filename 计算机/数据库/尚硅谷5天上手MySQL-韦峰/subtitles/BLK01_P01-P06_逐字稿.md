在这边我们可以先拿现有的存储手段来说一说有没有能存储它。这边我先给大家举两个例子：
第一，我认为大家可以用现有的程序的运行变量去完成这些数据的存储。我这里边拿 Java 举例，Java 的运行变量其实支持丰富的类型，包括字符串、整数、集合类型，以及自定义类型，它是完全有能力去存储程序的这些展示内容的。但是我们想想，这种方式行不行呢？大家可以去思考一下。
很显然，这种方式有它不妥的点。因为运行变量虽然可以存储，但我们应该知道，所谓的运行变量，它是将程序存储在运行内存中，而当程序终止以后，这些运行变量会立即被释放，而且也没有主动的持久化手段，就是它不会把这些变量持久化到本地磁盘中。也就是说，当你下次再来到程序中，这些数据就已经丢失了，那很明显这种方案会产生数据丢失的问题。

我们再想第二种方案，叫本地文件加 I/O 流的方式。大家想，我可以在本地创建一个文本文件，同时在程序中用 I/O 流的技术对文本文件完成操作，对吧？但是这种方式能确保数据不丢失，但是有一个问题：本地的文本文件它没有格式。如果你对这个整个文本进行读和替换的动作，或者删除动作，那是可以实现的；但如果说你想对整个文本的局部进行条件化查询、条件化修改，或条件化更新，那你用起来就比较麻烦了，因为它们没有格式。所以说，第二种虽然是可以持久化存储，但是它没有格式，不方便操作。

所以说，综上所述，两种都有各自的缺点。我们来引出第三种，而真正开发中程序中的这些数据都是利用我们的数据库进行存储。而数据库能去规避上面两种出现的缺点，它是一种持久化存储手段，并且数据库是有格式的，它也会方便进行数据的读、写、删，还有改等相关的操作。

第一，我们先大概介绍一下数据库是干什么的。说完这一点以后，接下来我们来详细介绍一下数据库的概念。

首先在这儿我给大家总结了两点。
第一点我们要知道，数据库是按照数据结构来组织、存储和管理数据的仓库。到这一点你只要大致理解，它是一个存储数据的仓库就可以了。那它到底有什么特点呢？下方会进行说明，来看这：
是一个长期存储在计算机内、有组织、可共享、统一管理的大量数据的集合文件。这就是数据库以及数据库的特点。

但是，我说到这儿，我想大家如果要是初学者，你还是会很迷糊，对吧？那接下来我把这个数据库的特点给大家提炼一下。首先第一你要知道，数据库本质来说，它就是磁盘中的文件或者是运行内存中的一个数据。这边我举例用的是我们接下来要讲的 MySQL 类型的数据库，MySQL 这个数据库就会在我们的磁盘中去创建一个它指定格式的一个文件，最终在格式的文件中完成我们数据的存储。这是第一。
第二大家还要知道一点，就是数据库是一种长期的存储手段。这个长期指的是跟位置、存储位置没关系，并不是说一定是存储在磁盘中。它长期指的是

如果你存在数据库中的数据，只要不主动删除，它永远不应该丢失。这是长期存储的含义。

第三个特点叫有组织的。所谓有组织，指的是数据库在存数据的时候，它内部是有格式地进行存储。有了格式以后就方便对数据进行读、写、删、改等相关操作。

说到这，可能有些小伙伴不太理解，为什么有格式、有组织就方便操作呢？我给大家举个例子。北京下雪了，当然北京年年也下雪。只要一下雪，学校就要组织学生进行扫雪。因为上学期间大家应该知道，学生都是按照班级来划分的。去年校长是安排五年级学员扫的雪，今年校长为了公平说，今年五年级不用扫了，由六年级学员去扫雪。大家想想，这里边校长就根据班级这个组织结构去调动了学员。有组织是不是方便进行学员的查找？这就是有组织的特点，方便读写。

除此以外，大家应该还掌握最后一个点，什么意思呢？数据库是可共享的。注意，存在数据库中的数据，只要你赋予对方账号或者他主机访问权限，他就可以进行访问。所以它是一种可共享的存储手段。

综上所述，我们最终可以总结一下数据库的概念，它是一个长期存储且有格式、可共享的一个文件或一段数据，这就是数据库。本节课我们先介绍到这。

介绍完数据库的概念以后，接下来我们来介绍一下数据库的分类。

数据库根据数据的存储结构不同，我们将数据库分为两大类：一类叫非关系型数据库，一类叫关系型数据库。这里边很明显，它们俩差别就是一个是有关系，一个是没关系。

这里边我们通过分析关系词去讲一下数据库到底有什么特点。关系应该指的是两个事物之间，我举个例子，我和我媳妇是夫妻关系，我们俩之间。所谓数据库的关系指的是谁呢？当然了，数据库数据库，它关系指的是数据。

所谓的非关系型数据库，指的是它可以存多份数据，而数据和数据之间是不能建立关联的，每个数据都是独立的，这是非关系型数据库。而关系型数据库刚好跟它相反，它也可以创建多份，只不过这个数据之间你可以建立某一种关系。这就是两种数据库本质上的区别，是否可以建立数据之间的关系。但是建立有什么好处？没关系，我们下边细化再说。

下方我们来详细介绍一下两种数据库类型。第一，先介绍一下非关系型数据库。

非关系型数据库底层到底怎么去存储数据呢？到目前为止大家记住，非关系型数据库并没有一个统一标准。因为不同的非关系型数据库，它内部存储数据结构可能都不同，有些用的是键值，类似于 Map 这种 Key-Value 形式，例如 Redis；还有用的是文档，还有用的是 JSON 等等存储。它们没有具体的存储结构，但是它能保证一点，不管我怎么存，数据和数据之间都是没有关系的。而且因为数据之间没有关系，每个数据都是截然一身，所以它的性能相对来说会更好一些。

而关系型数据库，我们现在已经有了统一的存储标准。所有的关系型数据库都是将数据按照类别进行存储，就是数据你先分好类，而每个类别都存储到对应的一个容器叫表中。表和表之间是可以建立关联的，最终可以进行关联的操作。但是因为数据和数据之间有关联，它的性能相对来说一般。这叫关系型数据库。

我给大家解释一下什么是关系型数据库，举个案例。我们存学生和学生的分数，这里边可以存两个表，最终我们可以查询学生和学生关联的分数，它可以进行关联查询的操作，而非关系型是做不到这个事情的。

也就是说其实两个数据库都有各自的优缺点，大家也发现了。接下来我们来细化去总结每个数据库的特点。

首先先说一下非关系型，我为大家说了三个特点，我们再来说一遍。第一叫灵活的数据类型。这里边所谓的灵活，也就是说它内部的存储结构其实是多样化的。你可以根据你想要的数据结构选择对应的非关系型数据库就可以了，它现在没有一个统一标准，是这样的。

第二无固定的表结构，因为它本身内部就没有表这一说。所以你想存数据的时候，例如说键值对，你直接设置一个 Key 和 Value 就行了，不需要你提前像我们一会儿要讲关系型数据库要提前先声明好表结构等等，不需要。所以随时存、随时用，不需要做前置工作，这也是它的特点。

第三就是高性能。还是那句话，截然一身，没有任何藕断丝连，所以它这个数据库性能相对来说会更高一些。

非关系型介绍完毕以后，我们来介绍一下关系型数据库。关系型数据库我们总结了四个特点：

第一个特点叫数据结构化模型。也就是说它内部是有固定的结构的，就是用表存储。你可以把它理解成你平时做的表格。你想在做表存储之前，你想做一个表格是不是得先提前去规定好这个表内的表头是什么东西？所以关系型数据库需要你提前做一些表的前置准备工作，先设计好表名、表头等等一些相关的动作，需要做前置准备工作。

除此以外，它还支持事务。这个事务的特性后边我们会详细讲解，大概指的就是你发生了某些语句错误，它可以帮你进行数据的回滚。我举个例子，我给你转账，那我转账失败了，突然间因为网络，那钱不能丢了，怎么办呢？它会把钱再回滚到我之前的状态，给我返回来，是这种感觉。

除此以外，因为关系型数据库数据和数据之间是有联系的，所以它可以用关联查询，能查出学生和学生关联的分数，分数关联的课程等等，所以支持丰富的查询语句。

除此以外还有一个叫数据一致性。在关系型数据库中，它可以加一些所谓的约束概念，来保证数据的正确性和一致性。

这就是这两类数据库的特点。有的同学听到这儿以后肯定也说记不住，兄弟们，不用记。因为这些特点，首先我们本次要讲的是关系型数据库，这个我们慢慢都会接触到，在学的过程中就记住了。而非关系型数据库大家主要前期先了解一下就可以了。

介绍完毕以后，我给大家下个总结性定义。首先第一个关系型数据库你记住，它是能适用于强一致性和复杂的查询场景，它好用，是这种感觉。而所谓的非关系型数据库怎么办呢？你就记住一句话，灵活和性能会更好一些。这是两个数据库的特点，大家能理解了吧？

接下来在第一小节的最后，我们将讲解一下关系型数据库的存储和设计规则。只有了解了关系型数据库的存储和设计规则以后，才能方便我们后期对关系型数据库进行数据和容器相关的操作。

关系型数据库的存储和设计规则可以总结成一个叫 ER 模型。其实这个 ER 模型它指的就是，E 指的是 Entity 的缩写，它代表着实体。也就是说关系型数据库会将一类数据存储到一张表中，它也是说数据是按照类别存在表中。R 指的是 Relationship，它指的是这些表和表可以建立某种关系，最终我们可以通过关系进行关联操作。

举个例子，还是用我们之前的例子。学生和分数有两类数据，我们可以在关系型数据库中存到两个表中，最后表和表可以建立关系，最后可以查询学生和关联的分数，以及分数是哪个学生考的。这个就是关系型数据库的存储规则的一个总结，就叫 ER 模型。

这个 ER 模型内部具体有哪些单位呢？我来给大家解释一下。

首先第一个，数据最大的存储单位为库。也就是说在关系型数据库中，最大存储单位是一个库，但库里边可能不装具体的数据，它下边还有其他的容器。在库内部会装这个所谓的表。每类数据最终存储到一个表中，而表要存到库中。大家知道库和表两个概念有了。

表也会有一些特性列，这些特性列定义了表中如何进行存储。我有一个学生表，学生表里面到底要存什么属性呢？这个属性就是列，例如说有学生的姓名、年龄等等。

最后我们知道在表里边会形成行的数据，一行数据其实代表一个记录。最终关系型数据库的 ER 模型有的单位分别是有库、表、行、列，或者列、行都可以。

说到这里以后，可能有的同学突然间恍然大悟：这不就是我们平时操作的表格吗？对，大家可以把关系型数据库的内部存储结构抽象成我们用的 Excel 表格，其实本质来说，它们俩的结构是一致的。

接下来我们对比表格来说，来再去解释一下关系型数据库的这几个存储单位。大家想想，如果你想去表格去存储数据，你第一步是不是要先创建一个表格文件呢？整个表格文件大家理解就相当于我们要说的关系型数据库里边库这个单位，它代表整个文件。库也是我们关系型数据库中最大的存储单位。

创建完表格文件以后大家应该知道，那里面是不是可以创建多个页？每个页是不是代表一个表？第二步，表格中可以创建若干个页，若干个具体的表，那这就指的是它对应我们关系型数据库中的表的单位。大家知道每个页和每个表都存储的对应类别数据的集合。如果用 Java 去参考，那好比就 Java 里面的类的概念，对吗？

除此以外大家想想，表中是不是还有一些特性列？例如说我们有个授课讲师表，那这个授课讲师有什么属性，列？同时在我们的数据库中，表中也会包含列。列就有些特性，描述是你表中存储哪些属性。同时它也是存储的最小单位，最小的存储单位。大家注意，它类似于 Java 中对象的属性。

除此以外大家注意，我们真正要对数据进行操作，大家想想，我要删除数据，我是删除列吗？我要查询数据，我也不查列，我是进行行的相关操作。一行就代表一个实体，最终在表中一行的概念代表着一个具体实体。而在我们的数据库中它也有行的概念，行也是代表一个操作的最基本的实体，类似于 Java 中的对象。

最终各位对比表格我们来理解，我们有四个概念：库是最大的存储单位；内部装的表，表相当于一类数据的一个集合；而表中要有列的特性来标注你对表中到底要存哪些属性；而存完属性以后，每个实体都是一行代表一个实体；最终我们对这个数据库操作的时候，都是以行为单位进行数据库的数据操作就可以了。关系型数据库的 ER 原则最终总结出的单位就这个四个组成。大家去理解这四个单位，在脑子里面去抽象一下就可以了。
