兄弟们，我们介绍完多表概念以后，接下来具体来说说到底存在几种多表关系。
首先我们需要了解一个事，大家看这个标题，多表关系加了两个括号，第一“多”加了一个“两”，第二“表”后面加了一个“数据”。这个大家需要理解的一点就是：首先没有多表关系，这是个伪命题。所谓的多表，指的就是两两之间的一个关系。就算你项目中有100张表，最终在考虑表关系也是两两之间考虑，假如说A和B之间是什么关系，而A和C可能就换了关系，这个大家一定要理解。第二就是表是不存在关系的，表都是一个一个的表，怎么会有什么关系呢？大家注意，表关系指的是表中数据行之间的关系，它是行和行对应的关系，这个大家一定要理解。

介绍完毕以后，在下方我们来说说具体的表关系有几种：第一就是一对一，还有一个就是一对多，以及多对多。这里边也比较好理解。
一对一，它指的是两个表之间每行数据都对应唯一的对应关系。这里边有点绕，大意指的就是我的一行数据对应它的一行数据，它的一行数据对应我的一行数据，至多是对应一行，或者可以不对应，但至多能对应的是对应一行。这里边举出个例子，假如说员工和员工的唯一档案，就是我们有个员工实体，还有一个员工的档案实体，它们是一对一的关系，这就是一对一。
第二，一对多。一个表中关联了另一个表的多行数据，反之反向是关联一行数据。这个时候就是A可能关联了B的一行对应至多多行数据，但是B至多只对应A的一行数据。大家能理解吗？这就是一对多的关系。例如这里边搞了一个叫作者和多个文章的关系，也就是说一个作者可以写多篇文章，但是每个文章只能对应一个作者，这就是一对多的关系。
最后在下方还有一个多对多。多对多就是两张表的记录都可以对应对方的多条数据关联。这里边举个例子来看，首先就是学生和课程之间，一个学生可以选多门课，对吧？而一个课也可以被多个学生去选，这里边双方都是一个对多、一个对多，组成就是多对多的关系。
所以说大家注意，这里边表关系再强调一下，它指的是数据关系。第二点，表关系兄弟们，它是双向查看的。也就是说其实一对多指的是对一和对多，多对多指的是对多、对多，双向看都是对多就是多对多。大家记住了。
这就是我们大致分析出的表关系。接下来我们挨个系统去介绍一下。

首先我们先介绍一下一对一的关系。
这里边给大家举出个例子，举一个叫员工和员工的唯一档案。这里边就是我们把员工的姓名、年龄、性别存到一个表中，而把员工的地址、级别等等一些其他东西拆分成出。完毕以后大家看，它是怎么完成这个关系的呢？假如说有一个二狗这个员工，档案里边有一个它对应的地址信息；还有一个驴蛋蛋，也有它的信息。完毕以后大家听我说，分别员工表里边存在的是主键，而在档案表里边带一个外键，这样才能建立数据之间的关系。只要外键出现唯一一次，至多出现一次，这个大家想想是不是就是对一的关系？这大家指导一下。完毕以后在下方我们知道，数据和数据之间通过主外键能建立对一的关系。最终我们理解它的特点就是，一条员工至多对应一条档案数据，而一条档案也至多对应一条员工的数据，这个就是一对一的关系。

第二，我们来介绍一下叫一对多的关系。一个表中可以对应另外一个表多行数据，反之它只能对应你的一条数据。这里边给出的就是作者和文章表。大家想个问题，假如说这里有作者叫二狗子，他的文章有一个文章，没问题。对多指的是至多有多条，但它可以是一条或者是零条；对一至多只有一条。能理解吗？第二个我还有个作者叫驴蛋蛋，驴蛋蛋可以有多篇文章。那大家发现，这个不就是代表一对多吗？也就是说一个作者可能对应多个文章，但是每个文章是不是对应一个作者？这大家一定要理解这个关系。最终同样也存在主外键，所以说大家了解一个事，只要有表关系就一定有主外键，记住了吗？
这里边只不过是外键出现的次数不能唯一，可以出现多次，就产生了一对多，对不对？通过主外键建立的关联，最终作者和文章是一对多的关系。最终的特点就是一个作者对应多条文章，而一个文章只对应一个作者，对不对？搞定。

接下来下方我们来说一个多对多的关系。说到多对多的关系，大家想个问题，什么叫多对多？我对你多个，你对我多个，这是不是叫多对多？这里边举出的例子就是学生和课程。学生可以选多门课程，课程也可以被多个学生选。完毕以后大家看，这有个学生表，里面有一个二狗子和蛋蛋，课程当然这里边的s_id是它的主键。第二我们有课程表，有Java和H5，Java是常老师教的，H5是马老师教的。这里边它的c_id也是它的主键。这两个表之间，数据之间是多对多的关系。那我问大家一个问题，那数据之间到底怎么引用呢？有人说了，只要有表关系，你说了就应该有外键。那大家想想，这个外键到底加在学生表上还是加在课程表上呢？

而中间表里面可以包含两个外键，也就是说我跟学生表里面搞外键，我跟课程里面搞一个外键。最终数据可以通过这些间接引用的关系。你看，二狗子是不是上过常老师的课？是不是Java课？这里是不是建立了关系，1 1、1 2，是不是建立好这个关系了？这里边就完事了。但这个写得有问题兄弟们，这并不是2，这应该是不是也是1的问题？应该这个也是1，是不是？应该是s_id是1……是2，是2。马老师是2，没问题。第二个我们来看，驴蛋蛋是不是上过马老师的课，完了也选了马老师的课。看这个数据选得对不对，兄弟们？驴蛋蛋两个2，完了1、2，其实这个数据应该对应到哪儿？应该对应到1、2，是对应他俩，代表他们俩都上过两位老师的课，是不是这个意思？这边箭头指得有点问题。那这就是多对多。也就是说多对多需要建立一个中间表，我们是通过中间表完成数据的一个间接的关联。

第一，我们要理解拆表存储数据。关系型数据库中都是按照类别进行存储数据的，而每个表中存储的数据类型是单一的，对吧？这就是第一，分表存储。
第二，表和表的关系。表和表是可以通过主外键建立之间的数据关系的，对吧？包括多对多它也是间接地建立主外键。最终表关系指的就是表中数据行的关系。

首先我们先讲的是一对一的表关系的维护。
首先我们还是举员工和档案的数据。员工和档案是一对一的关系，也就是说一条员工数据对应一条档案数据，反过来说也是一条档案也只能对应一条员工的数据。最终数据之间是靠着主外键进行引用的，也就是说其实员工表中人家是主键，我们是来一个对应的外键，也就是说我们是子表，人家是主表，是吧？那这就是可以维持这个关系。

语法我们大家知道下。接下来我们再总结点小事：第一，大家注意，一对一这种表结构其实并不能解决数据冗余的问题。一对一这种东西的存在并不是为了解决数据冗余，因为大家思考一个问题，假如说二狗子只有一个地址，对一的关系，其实本身写到一张表中也是可以的。其实一对一是可以不拆表的，大家发现了吗？最终它也不会冗余的。之前说数据冗余指的是一个学生对应了多个分数，没办法，学生得出现多次，那这个只对应一是不冗余啊。所以一对一的本质不是来解决数据冗余问题的。那它存在的意义是什么呢？来，我给大家讲一下。

刚刚我们介绍了一下“一对一”的关系，接下来我们来说一下“一对多”的关系。你清晰了一对一，一对多就变得简单了。首先，我们举的例子还是作者和文章表。我们知道，一个作者可以对应多篇文章。大家看，二狗子这边对应了一个文章，对吧？但是驴蛋蛋他写了两篇文章。因为在文章里边存在外键引用了两遍所谓的驴蛋蛋的主键。通过这一点我们还要再去夯实一下，就是一对一、一对多，它们都是存在主外键的，是通过外键完成主表数据的一个引用，对吧？

那一对多和一对一的唯一的区别是什么呢？就是这个对于外键限制的问题。一对一外键必须是唯一，对吧？所以说你加了 UNIQUE 约束或者是作为主键。那一对多指的是外键可以出现多次，不能加唯一，或者外键也不能做主键。所以这里边，一对多来说，它都会有一个单独的主键，外键就正常加一个外键约束，只要不加限制就可以了。这就是一对多的关系。

内连接首先我们先做个介绍，它就是一种——我也不用看概念了，我直接给大家说——它就是一种将多个表可以水平连接到一起的一种语法。内连接主要的特点，它对比外连接来说，它得要求两个合并的表之间必须存在主外键相等的条件，才能进行合并。

大家记住这一句话，但你可能也记不住。没关系，你现在记不住，我们后边在讲完外连接以后，我对比我再强调你再记。内连接它要求两个表必须存在主外键相等这个条件以后才能进行合并。大家大概知道一下。

接下来我们来看看内连接具体的语法。这，大家有体现。首先内连接语法给大家提供两种：一种叫标准语法，一种叫非标准语法。

什么叫标准呢？标准就是 SQL 语句里面提供的一种关系型数据库全部支持的一种内连接语法；而非标准指的是你可以理解它是 MySQL 的一个方言，在 MySQL 里面支持，但在其他语言里面不支持。

两种我都给大家说一下，因为非标准相对来说会更简单一点，有点就像什么呢？你可能在老家，你老家有方言，你在跟老家在聊天的时候你很少、不会说普通话，你会说方言，因为你会更顺嘴一些。所以非标准在 MySQL 在写中可能会更顺手一些，但是标准来说会更通用。你说到底学啥呢？两个都学呗，对不对？

完毕以后我们先看看第一个标准语法。它的语法其实很简单：

```sql
SELECT ... FROM
```

还是之前我们要讲的那些东西，就是从哪个表查询数据、查哪列，这都一样。这是第一个表，看见了吧？那它用什么呢？用一个 `INNER JOIN`。

注意，`INNER` 加方括号原因就是代表 `INNER` 后面我们讲可以省略，不是说代表写的时候要加方括号，写的时候不要加方括号。就是说 `INNER` 可以写，可以不加。INNER 这个单词的意思就代表内，而 JOIN 代表啥？连接。

第一个表，你要连接哪个表？这写表 2，就可以了。这就叫做把它们两个表结果进行水平连接到一起。但是到现在为止的水平连接，一会儿我给你演示。


它只是把两个表的所有行全部拼接一次，就是一个笛卡尔积的问题，把内部的所有组合都排了一次。但是数据不一定正确，怎么保证数据正确呢？

如果用 inner，我们后面加个 ON 这个条件。ON 后面跟的就是两个表中判定主外键相等就可以了。ON 只能跟在 JOIN 这种关键字的后面，而且它后面加啥呢？一般情况下就加主外键相等，来取到正确的拼接行数据，就完事了。

但大家也会发现一个细节，在这写的时候，之前写列名我都直接写列名，但这没有直接写列名。大家发现我这写了个什么？是不是一个“表名.列名”？这是为什么呢？因为现在我们查数据是来自于两张表：表 1、表 2。而一般情况下，两张表的主外键命名都相同。那如果大家想想，不写表名直接写一个主键和外键，它俩的列名可能相同，那它也不知道到底是判定哪个表的列名。所以在多表查询的时候，我们一般做列的操作都需要用“表名.”，这样来指明这个列具体是哪个表下的列，防止有重名的时候不确定它是哪个表的列。大家先知道这个细节，一会咱们再说。

下方这是第一个标准查询语法。

第二个来说说非标准的。你看，第一个表起、第二张表起，后面就是 `SELECT * FROM` 一样。之前写单表就加一个表，多表怎么办呢？就加逗号隔开，再加个表就可以了，就这么简单。如果你再有第三张表，再加逗号加表；第三张表再加逗号加表就可以了。这就是多表查询，我们用非标准的内连接语法。

最后我们也同样需要后面加个 WHERE。JOIN 后面加 ON，而我们普通的非标准的就是正常加 WHERE。WHERE 后面依然要加主外键相等，否则你拿到也是错误的数据。

这个就是我们的内连接的两种语法。大家可以把视频暂停一下，在这记一下就可以了。

记完以后，我们再强调三个小细节。

第一个细节：两种语法效果在 MySQL 中都一致，但是我们推荐使用标准语法。你可以用它去理解，但是推荐要使用标准语法，这是我们推荐的。

第二，大家记住，为了避免有错误的水准连接的数据行，我们必须要添加主外键相等的条件。也就是说所有的连接查询，后面必须要加主外键相等的条件。那你说为什么加？其实大家也还没学过语法，也没到下一环节，你肯定不懂。我大致给大家说说啥含义，大家看这。

所谓连接查询，表 1、表 2 是不是连接查询？是不是要水平拼接？它本质就是将所有行互相都拼接一次，其实这个问题就叫笛卡尔积。都拼接一次，它只能保证这个数据肯定是有正确数据，但是里面一定有错误数据。例如举个例子，假如说 A 和 B 两张表进行连接查询，A 里面有 3 条数据，B 里面有 4 条数据，那你将得到的连接完以后的结果是多少呢？是 12 条数据，它都给你合并一遍。

它有点像什么呢？有点像小时候我们学数学加减法的时候，大家会有个九九乘法表或者加法表，还有减法表。它就把两个数字、九个数字之间的加减都给你拼接到一起，最后你想要哪个都能找得到。所谓的连接查询也是一样，它会把两个表中的所有行数据都给你拼到一起，你想要哪个里面都有。但是大家要知道，这种你都拼接的行，它不一定是正确的。因为有些可能不是它俩应该连到一起，你也给连到一起了。这是它的一个问题，这就是一个经典的叫笛卡尔积的问题，笛卡尔也叫笛卡尔乘积的问题。大家如果不知道这个事，也可以去网上查查。就是把所有都给你拼到一起。

怎么解决这个问题呢？我们需要添加主外键相等来获取正确数据。其实它在拼接的时候，只有主外键相等的两条数据才是正确的数据。所以最终为了避免错误数据，我们在做连接查询的时候都要加主外键相等。用 JOIN 在 ON 后面加，用普通的非标准的连接查询就在 WHERE 后面正常加主外键相等就行了。这个事一定要记住。

最后我们要聊一点列的问题。多表查询要考虑一下不同的表存在相同字段名的问题。之前单表你在写列名随便写没问题，但是现在写多表的时候，包括前面 SELECT 的，或者后面指定的条件等等这个位置，你不能随便写列名了。万一这个列名它要重呢？举个例子，假如说我在查的时候这个位置搞了一个叫 a，搞了一个 name。那有可能这个 name 在表 1、表 2 里面都存在，那它就会报一个错误，说不知道这个 name 到底是谁的，MySQL 就会给你报错。

怎么解决这个问题呢？其实很简单，我们在多表操作的时候，对于列的操作都需要写什么呢？“表名.列名”。这样的话就防止不确定它是哪个列的。当然有人说那列名我能不能直接写？也能写，但是你要保证这个列名不是重复的列名。你要保证不了，你就写“表名.列名”。

但是这里面又面临一个问题：表名一般都很长，表名每次写它很麻烦，是不是啊？那可以怎么办呢？大家记得之前我们在讲列的时候，SELECT 列的时候，我们可以在这个位置，假如取个列 `name`，我们可以 `AS` 起个别名，对吧？或者是 `name` 空格来个别名。我们可以给列起别名，其实表也一样可以起别名。

表允许你在写这个位置的时候可以给它起个别名。它起别名的语法有两种：第一就是“表名 空格 别名”；第二就是“表名 AS 别名”就可以了。我们可以给表起个别名，你可以把长的表的名字起得短一点。

举个例子，假如说我们之前用的员工表 `t_employee`，那我可以在后面给它 `AS` 起个名字，假如就叫一个 `e`，或者叫空格一个 `e` 就行了。你起完别名以后，后期在多表操作的时候我们都要求“表名.列名”，其实它也可以怎么做呢？也可以用表的“别名.列名”，这样是不是更方便一点？

所以我们在多表操作的时候，一般都会去给表起别名，就是为了用表名方便带出列名。具体语法在这体现：表名空格别名，或者表名 `AS` 别名都可以。

以上就是我们讨论的三个细节，以及内连接的语法。

完毕以后，我们先不讲它具体实战，下节课我们讲，都会一一给大家去说明。现在我先把把它总结一下，打开我们的教案本。

内连接查询，它的语法有两种：

第一种：
```sql
SELECT 列 FROM 表1 AS 别名 INNER JOIN 表2 别名 ON 表1别名.主键 = 表2别名.外键
```
SELECT 列 FROM 表 1，咱们 AS 起个别名，一般都这么做，是吧？完了用一个可以省略的 INNER JOIN 连接表 2，咱们空格也可以起个别名。大家别忘了，一定要加 ON，加上表 1 的别名.主键或者外键等于表 2 别名的.外键。这样就可以正确查到数据了，这是第一种。

第二种，我们直接把它 CV 一下。这种做法就变得更简单。第一种是标准语法，第二种非标准：
```sql
SELECT 列 FROM 表1 别名, 表2 别名 WHERE 表1别名.主键 = 表2别名.外键
```
直接可以在 SELECT 列 FROM 表 1 起个别名，下方直接逗号隔开，写第二表别名就行了。最后主外键相等正常用我们的 WHERE 条件，就搞定了。这就是我们的一点。

内连接可以做什么呢？它可以将多个表的数据行正确地水平拼接到一个结果集中。例如查询学生和学生对应的分数等等，是不是都是水平拼接？而且它还有一个特点，大家一定要记住：内连接查询到的结果，要求两个表中必须存在相同的主外键。这块我们一会儿再强调，大家先不用记。

完毕以后，下方我们说了几个注意事项，给大家强调一下：

第一，以上两种语法效果相同，但是推荐我们的 INNER JOIN 系列。这个是我们的标准语法，在哪都支持。

第二，我们要了解一点，为了避免错误的数据行连接，我们需要添加主外键相等，这样能去掉错误行。如果错误行连接，这个就我们说叫笛卡尔积问题。所谓的连接查询就是将所有行都水平拼接一遍。最后再加上所谓的主外键相等，把错误行给去掉就可以了。这就搞定。

最后一个细节我们要了解：因为多表中可能存在相同的列名，所以建议在对列操作的时候使用“表名.列名”，这样会更明确这个列是谁的列；或者是“表的别名.列名”。

表如何起别名呢？表可以在 FROM 后面起别名。你可以用“表 AS 别名”，或者“表 空格 别名”都可以。
