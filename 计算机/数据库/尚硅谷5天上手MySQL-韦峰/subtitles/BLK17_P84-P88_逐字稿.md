首先我们先介绍一下啥是子查询。子查询指的是，在一个 SQL 语句中去嵌套了另外一个完整的 select 语句，这就叫做子查询。也就是说语句之间形成嵌套，而嵌套的是一个 select 的语句。

下方我们给大家举了一个例子，例如下方大家看，下面这个案例就是来查询大于平均分的信息。那这里边我们就先通过一个 select 去 avg 一个聚合函数去算出平均分，最后把它作为一个条件值，加个括号，大家看见了吗？那再去查分数表，分数大于它就可以了。那这个就成为一个子查询。

但大家听我说，子查询不仅可以在 select 的语句中进行嵌套，可以在任何语句中，例如说 insert、update、delete 中都可以嵌套。它只要被嵌套的内容是 select 语句，这就称作叫子查询。

看第一题，这个题我们先理解，是查询研发部门的员工信息。那这边问题来了，它的条件是研发部门，而查询结果是员工信息。那大家发现一个问题，这个时候员工信息表中，这里边我们看到，它只有一个部门 ID，但是没有部门的名称。对吧？那这个咋办呢？其实这就是一个子查询。什么意思呢？我们可以把这个查询分为两步，咱们先来一个步骤一：先查询，根据部门名称查询部门的 ID。拿到 ID 以后，咱们来做步骤二：根据部门的 ID 查询员工的集合。

那这种就是一种很明显的间接条件，不能直接用，得需要跳一层才能用，那这个就明显用到子查询了。

注意怎么写呢？写的方法很简单：
```sql
SELECT did FROM t_department WHERE dname = '研发部';
```
这是我们第一条语句。第一条语句一执行，我们就能查到研发部所对应的 ID。

第二步，我们根据 ID 去查对应的员工信息。我们先把这语句先写上：
```sql
SELECT * FROM t_emp WHERE did = 1;
```
这样相对是不是就查到了一号部门的所有员工？那这个值到底是什么呢？它是由上面子查询的结果去体现的。那上面子查询就是单行单列，它就可以作为一个条件值，这种标量。那咋办呢？很简单，在这个位置加个括号，这就代表内部要先执行的一个查询，把这个查询咱们粘过来。大家注意不要粘分号，把它粘过来，就可以了：
```sql
SELECT * FROM t_emp WHERE did = (SELECT did FROM t_department WHERE dname = '研发部');
```
最终它会先执行括号里面的，查到 did，再拿单个值再作为一个条件值，再跟这个 did 做比较，就能查到员工的所有信息了。大家看见了吗？这句就查完了，所以说子查询相对说也比较简单，就相当于是把查询的步骤进行分类，然后进行嵌套就可以了。这是第一个。

第二个，我们再写一个。
查询每个部门的平均工资和公司的平均工资的差。这个有点意思。首先大家想一个问题，怎么去查公司的平均工资？还有一个就是查询部门的平均工资。

先做第一个，查公司的平均工资。这些员工不都是公司的吗？那他们的平均工资的话容易，就是把所谓的 salary 这一列算出平均值是不是就完事了？那我认为可以这么写，你看对不对：
```sql
SELECT AVG(salary) FROM t_emp;
```
这一写完以后，我不就算出了整个公司的平均工资吗？对不对？

而下方算啥呢？算每个部门的平均工资和公司的平均工资差。那怎么查部门的平均工资呢？你看员工表这里边，那他们到底有哪些部门呢？5 是一个部门，对不对？在这只要听到“每个”，查询每个部门，那大家注意，这就典型什么叫分组查询。我们可以把这些员工按部门分组，分组以后来计算每个部门的平均工资，是不是也可以了？

那我们可以写一下，先写查这个：
```sql
SELECT did, AVG(salary) FROM t_emp GROUP BY did;
```
这个语法是固定的，只要你分组，这个位置只能查分组字段和聚合函数，是不是这意思？搞定。那在下方，我们 `FROM t_emp GROUP BY did`。那这个我们就查到了公司的一共有多少组，以及组内的平均工资，是不是有了？

完备以后，大家思考问题：那怎么算每个部门的平均工资和公司的平均工资差呢？这不就公司的平均工资吗？那这个不就部门的平均工资吗？那用它来减不就得了吗？可以怎么做呢？这就是单个值，可以随便用。写在哪个位置呢？接着在这个位置写个逗号：
```sql
SELECT did, AVG(salary), AVG(salary) - (SELECT AVG(salary) FROM t_emp) FROM t_emp GROUP BY did;
```
这不就是我们部门的平均工资减去，写个括号，这就子查询，把它一放进去。这个就是单行单列叫标量子查询，它就可以直接作为一个值放这个位置。就相当于算出一个值放这个位置，一算完了以后就查出来了每个部门的平均工资，以及和公司平均工资的一个差，是不是完事了？

那这个就说完了。第一个我就先演示了在查询里面套查询，查询结果是单行单列的，就相当于是标量子查询，你可以把它正常当成一个值，大于、小于、等于比较，或者直接赋值、减值、加运算都是可以的。能理解吗？这节课我们先讲到这。

刚刚我们感受了一下 SELECT 里面去嵌套子查询是一种标量子查询，接下来我们来见识一下行子、列子以及表子查询。

首先先来说一下行子查询。也就是说，在我们子查询的结果是一个单行多列的一种结果。那这东西如何进行比较呢？

我们这有个需求：查询和白鹭性别和部门相同的员工信息。我们把它带到小系统吧，这个位置。我们点开员工表。打开以后，白鹭，他给了我们一个名字。我们要根据这个名字查到他所谓的性别 gender 以及他的部门 did。最终，我们的返回结果是什么？单行多列，那这就叫做了行子查询。那找到跟他相同的信息，看我们要怎么找。

首先我们可以这么做。第一，我们先查一下步骤一：
查询白鹭的性别和部门：
```sql
SELECT gender, did FROM t_emp WHERE ename = '白鹭';
```
这是我们已知条件，也就是说这个是将成为我们的嵌套子查询的部分，对吧？你看查到了，单行多列。

完毕以后，第二步，我们就可以查什么呢？步骤二：
查询和白鹭信息相同的其他员工。

那我们看怎么查。首先这个做法就是我们正常：
```sql
SELECT * FROM t_emp WHERE ...
```
那这个时候，我们的 WHERE 大家想一个问题，我们写法就是它的返回值是什么呢？是单行两列，是吧？那现在我要拿谁呢？我现在要做法就是也不能拆开比了，我要在一起比，做一个整体比较。拿谁呢？我就拿 gender 和我们的 did 一起比较。大家注意，在我们之前讲过，如果想一起比较的话……

把两个列加括号。加括号以后，这儿可以用等号，也可以用 IN，都是可以的。我们先用等号试一下。括号，这个位置写什么呢？把我们的结果嵌套进来。

这里的含义就是：`gender` 等于子查询查出的 `gender`，AND `did` 等于子查询查出的 `did`。这就是用我们之前讲的语法，叫两列同时判等。大家注意，这个位置一定要对应上。之后我们就可以执行一下。

我们可以加个 AND 排除掉白鹿，这里就不加了，这就搞定。当然这里除了用等号，也可以用 IN 关键字。一般 IN 也可以作为两列之间的判定等于。走，也是没问题的。

我们来简单解释一下。如果我们碰见所谓的行子查询，即返回单行多列的结果，一般都是整体比较，用括号把多列括起来，配合 IN 或者等号比较后面的行子查询结果。这就是我们想说的事。当然下边也可以在修改或者插入的时候去嵌套行子查询，我们在后面的语法再讲。

如果觉得这个记不住，其实可以拆分，把行子查询拆分成多个标量子查询。你可以把单行多列拆分成若干个单值。举个例子，白鹿这儿查部门和性别，你可以分开查。首先先查白鹿的性别，第二再查白鹿的部门，这就变成两个子查询了，都变成了标量子查询。完事以后，下边在查其他员工信息的时候，就可以单独写：
```sql
gender = (SELECT ... )
```
你可以转换，不转换就用 IN，这用等号写两个就行。之后再加上 AND 条件：
```sql
did = (SELECT ... )
```
这样也是可以去实现的。所以其实也不用特意去记什么行子、标子、列子，只要把语法灵活掌握就行了，就是查询里面嵌套查询，修改里面嵌套查询，删除里面嵌套查询，这样也是可以查的。到这里我们就讲完了行子查询。

刚刚我们介绍了行子查询，接下来介绍一下列子查询。所谓的列子查询就是返回多行单列。大家可以通俗地理解，就是查出的结果是多个值。那多个值怎么做比较呢？大家注意是这样一种场景。如果你返回的是多个值，比较时要加上 IN、NOT IN 或者 ANY、ALL 等关键字。

我们来看这道题：查询与白鹿和谢吉娜同部门的员工姓名和电话。这个目的就是第一步要先查询出他们两人的所属部门编号 did。他们俩可能属于同一个部门，也可能是两个。如果是一个，那就变成了一个标量子查询；如果是两个，就是我们说的列子查询，说白了就是有多个值。

我们来查一下：
```sql
SELECT did FROM t_emp WHERE ename = '谢吉娜' OR ename = '白鹿';
```
这么写没问题。也可以这么写：
```sql
SELECT did FROM t_emp WHERE ename IN ('谢吉娜', '白鹿');
```
一个列名等于多个值，中间可以用 IN。一个列用 IN 等于多个值，就代表是他或者他，跟上面是等价的关系。查出来的结果是 2 和 5。

第二步，查询 2 和 5 部门的员工信息。但你不能分开查，给你的值是 2 和 5 一起给你的，怎么处理？第一个处理方案，依然可以用 IN 处理：
```sql
SELECT * FROM t_emp WHERE did IN (
    SELECT did FROM t_emp WHERE ename IN ('谢吉娜', '白鹿')
);
```
最终可以把这句拿过来放进去。在这个范围内就用 IN，这就查到了跟那两个人相同部门的员工。如果要查跟他们不同部门的员工呢？不是 2 和 5，写 NOT IN，不在 2 和 5 中间，搞定。

除此之外，除了 IN，还可以怎么做？列子查询还可以使用 ANY 或者 ALL 这两个关键字去实现。怎么用呢？
我们在前面写 did 等于。如果直接写等号：
```sql
SELECT * FROM t_emp WHERE did = (
    SELECT did FROM t_emp WHERE ename IN ('谢吉娜', '白鹿')
);
```
执行后会报错。为什么报错呢？因为等号只能等于单值，也就是我们说的标量子查询。现在有两行值，没法等于。在这种有多个值的情况下，就可以加 ANY 和 ALL 关键字，加在这个等号的后边、子查询括号的前面。

如果满足任意一个都行，加什么呢？加 ANY。ANY 代表任意一个值，它的作用就等于 IN。ALL 代表所有值，判定的是且的关系。这里只要满足 ANY 其中任意一个值就可以了。如果查出的是列子查询（单列多行、多个值），在等于的时候加上 ANY 和 ALL 就行了。走，执行，也是可以的。

第二题我们再做一个：查询工资比他们三个都要高的员工信息。
第一步，先查询他们三个的工资。第二步，查询大于他们所有的工资。
首先查询他们三个的工资：
```sql
SELECT salary FROM t_emp WHERE ename = '白鹿' OR ename = '李思羽' OR ename = '黄冰茹';
```
查出来三行数据、单列的值。

现在要查比他们工资都大的，怎么做？
```sql
SELECT * FROM t_emp WHERE salary > ALL (
    SELECT salary FROM t_emp WHERE ename IN ('白鹿', '李思羽', '黄冰茹')
);
```
大于如果接的是标量子查询，是单值，直接写就行。但这回是多个值，比他们都大要用谁？这时候就要选择关键字 ANY 和 ALL 了。IN 和 NOT IN 指的是等于的场景下，这回你要用大于，就得大于 ANY 或 ALL。这里加 ANY 是什么意思呢？代表比他们任意一个大就行，也就是大于最小值就行。而这个题要求比他们三个都高，所以这块要写 ALL，ALL 代表比他们所有值都大。这就可以执行，查出比他们都大的。

当然这块其实也可以做转换，可以把列子查询变成标量子查询。比他们都大，那大于最大值就可以了：
```sql
SELECT MAX(salary) FROM t_emp WHERE ename IN ('白鹿', '李思羽', '黄冰茹');
```
这个返回的结果是单行单列的标量子查询。标量子查询做的时候就可以作为一个普通值，再写的时候就不用这么麻烦了，直接放进来：
```sql
SELECT * FROM t_emp WHERE salary > (
    SELECT MAX(salary) FROM t_emp WHERE ename IN ('白鹿', '李思羽', '黄冰茹')
);
```
它就是单值，不用加 ANY 和 ALL 了，直接大于单值就可以。这样效果跟上方是一样的，相当于是把列子查询变成了标量子查询。这就是我们讲的列子查询的介绍，注意 ANY、ALL、IN 关键字要怎么使用。

接下来我们介绍一下 SELECT 嵌套查询的最后一种，叫表子查询。我们的查询结果是一个多行多列的，这块做不了条件也做不了值，它一般作为一个虚拟表。

需求：查询所有部门的编号、名称以及部门的平均工资。这个题看着简单，我们用子查询看怎么去实现。打开部门表，发现部门表里面只有部门编号和名称，没有平均工资。现在想一行展示出这些数据，怎么展示？第一张表有它，没有后面的东西，我们就可以在这个位置用连接查询，做水平结果集拼接，把它们拼到一起。第一个来自于部门表。第二个平均工资来自于哪个表？来自员工表。但是员工表里面也没有部门的平均工资，它只有部门和员工。平均工资确实是靠着员工表来的，但是是靠着员工表里面做分组查询出来的。所以这并不是一个简单的部门表连接员工表，而是员工表先查询出结果，查询到以后再跟部门表连接。这个位置就是一个表子查询。

步骤一，要查询部门的平均工资，在员工表加分组查询：
```sql
SELECT did, AVG(salary) avs FROM t_emp GROUP BY did;
```
这就查出了部门的编号和部门的平均工资。这个可以作为一个虚拟表，去跟我们的部门表做主外键连接。did 主外键连接，不就能查出哪个部门的名称以及连接到部门的平均工资了吗？

步骤二，查询部门的信息和平均工资。这回我们的子查询就是多行多列，作为一个虚拟表，正常连接就行：
```sql

```
