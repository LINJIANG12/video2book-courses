兄弟们，接下来我们来讲一下行级约束的最后一个约束，叫自增长约束。

我们首先来介绍一下自增长约束以及它的一个使用场景。大家看这一块。

自增长约束是来限定某个整数类型的字段，整数的列。在插入数据的时候，不需要显式的赋值，就是说不需要你给这列赋值，它的值会自动增长。

这里边举个例子，假如说我们现在有一个表，有 id、age 和 phone。id 是一个主键列，且它是个整数类型。那大家想一个问题，每次你在插入数据的时候，如果没有自增长，你是不是得考虑插入 id 值、age 值和 phone 值，对吧？age 和 phone 还都好说，就按照你真实数据插就可以了。但 id 呢，你想想，你是不是在插入的时候就要考虑这个 id 的数值类型没有被插入过，说不能重复，是不是？那这个时期你自己要维护就很苦恼了。

如果说你把 id 这一列加上自增长的约束，那就变得方便多了。每次在插数据，你只需要关注插入 age 和 phone 这两列就行了，而自增长约束会自动按照之前的最大值，每次加 1 往下长，保证这一列永远不重复。所以自增长这个约束有什么好处呢？能让我们释放双手，不用我们自己去维护这个主键值在插入的时候，且它能保证主键值是唯一的。这就叫做自增长约束。

它的语法，下方已经给提下了，叫 AUTO_INCREMENT。那有人说这东西到底咋用呢？我给大家介绍它的特点。

首先添加的位置，自增长约束只能加在我们的主键或者是唯一约束这个列上，普通列是加不了的。这大家一定要记住。

第二，每个表中只能有一个自增长约束。而大部分情况下，绝大部分情况下，这个自增长约束都加在主键列上。能理解吗？

再下方，自增长约束对应的数值类型，它必须是整数类型。那如果说你主键列是个字符串类型，也是可以的，那你怎么自增长？你也不是 a、b、c、d、e、f、g，对不对？你的字符串可能很长，它也不会长，所以它只能要求是整数类型。大家能理解吗？

如果自增长约束加完了以后的这个字段设置为 0 或者为空，听我说，有三种场景：第一种，在插入的时候你直接不管它，你只管 age 和 phone，它就会自动增长；第二种，你可以把这个列给它赋一个 0，它也会自己增长；或者赋一个空，它也会自己增长。大家能理解吗？这就是自增长约束。

介绍完毕以后，它最终的作用就是来让我们解放双手，不用再去管主键的值了，对不对？

接下来我们来看看自增长约束的语法。其实很简单，兄弟们。

第一个语法，在创建表的时候，我们可以在主键后边或者是 UNIQUE KEY 后边加个 AUTO_INCREMENT，搞定，这就相当于加上自增长了。

删除也很简单，直接就 `ALTER TABLE ... MODIFY` 字段名，这加上数据类型就行了。后边不用加上 AUTO_INCREMENT，它就会把原有的 AUTO_INCREMENT 进行覆盖，而主键列或者唯一列依然存在。
