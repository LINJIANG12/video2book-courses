# MySQL环境搭建与数据库基础概念

## 程序数据的三种存储手段

* **程序运行变量**

    * > **定义**：程序运行时把数据放在内存里的变量，Java 中支持字符串、整数、集合类型、自定义类型等丰富类型。

    * 变量随进程生死，程序一终止内存立即被释放，且没有主动的持久化手段，不会把变量持久化到本地磁盘。

    * 下次再打开程序，数据已经丢了。

    * > **易错点**：内存 ≠ 存储。程序变量看起来「在电脑里」，但它随进程生死，进程一死数据就没了，这是数据丢失的直接原因。

* **本地文件 + I/O 流**

    * > **定义**：在本地创建文本文件，程序中用 I/O 流对这个文件做读写操作。

    * 解决了数据不丢的问题，但本地的文本文件没有格式。

    * 对整个文本做读取、替换、删除可以实现；对局部做条件化查询、条件化修改、条件化更新非常麻烦。

* **数据库**

    * > **定义**：开发中程序里的数据实际使用的存储手段，同时具备持久化和格式。

    * 既规避了运行变量持久性差的缺点，又规避了文本文件没有格式的缺点。

    * 有了格式，才能方便地对数据进行读、写、删、改等操作。

## 数据库的定义与三个特点

* **数据库（Database, DB）**

    * > **定义**：按照数据结构来组织、存储和管理数据的仓库。

    * 教科书式定义是：长期存储在计算机内、有组织、可共享、统一管理的大量数据的集合（文件）。

    * 本质是磁盘中的文件，或者运行内存中的一段数据；MySQL 会在磁盘中创建一个它指定格式的文件，数据最终在这个格式化文件里完成存储。

    * 长期：与位置和存储介质无关，指只要不主动删除，数据库中的数据永远不应该丢失。

    * 有组织：存数据时内部是按格式存储的，格式是能方便读、写、删、改的前提。

    * 可共享：只要赋予对方账号，或者开放他的主机访问权限，他就可以访问。

    * 综合起来，数据库就是一个长期存储、且有格式、可共享的文件或一段数据。

* **有组织为什么方便操作**

    * 学校按班级划分学生，校长按「班级」这个组织结构调动学员，有组织就方便查找学员。

    * 数据库的格式起的就是同样的作用。

## 关系型数据库与非关系型数据库

* **按存储结构分类**

    * > **定义**：数据库根据数据的存储结构不同，分为关系型数据库和非关系型数据库两大类。

    * 关系指的是两个事物之间的联系；放进数据库里，关系的双方不是人，而是数据。

    * 非关系型数据库能存多份数据，但数据和数据之间不能建立关联，每个数据都是独立的。

    * 关系型数据库也能创建多份数据，只不过这些数据之间可以建立某种关系。

    * 两者本质上的区别就是能不能建立数据之间的关系。

* **非关系型数据库（Non-relational Database）**

    * 至今没有一个统一标准，不同产品内部存储结构可能完全不同：有的用键值，类似于 Map 那种 Key-Value 形式，比如 Redis；有的用文档；有的用 JSON。

    * 灵活的数据类型：内部存储结构多样化，可以根据想要的数据结构选择对应的产品。

    * 无固定的表结构：内部没有「表」这一说，直接设置一个 Key 和 Value 就行，不需要提前声明表结构，随时存随时用。

    * 高性能：数据截然一身、没有任何藕断丝连，性能相对更好。

* **关系型数据库（Relational Database）**

    * 已有统一的存储标准：所有关系型数据库都按类别存储，数据先分好类，每个类别存到对应的一个容器里，这个容器叫表；表和表之间可以建立关联。

    * 数据结构化模型：用固定的表结构存储，做表之前要先提前设计好表名、表头等，属于必须做的前置准备工作。

    * 支持事务：某些语句执行出错了可以帮你回滚，比如转账到一半突然网络失败，事务会把钱回滚到之前的状态。

    * 支持关联查询：可以查出学生关联的分数、分数关联的课程等，支持非常丰富的查询语句。

    * 数据一致性：可以加「约束」概念，保证数据的正确性和一致性。

    * 因为数据和数据之间有关联，性能相对一般。

* **两类的分工**

    | 类型 | 适用场景 | 优势 |
    | --- | --- | --- |
    | 关系型数据库 | 强一致性和复杂查询的场景 | 好用 |
    | 非关系型数据库 | 灵活和性能优先的场景 | 灵活性与性能更好 |

    * 关系型与非关系型不是水和火的关系，两者可以兼容。

    * 开发中的实际做法是混合模式：程序的主体数据存关系型数据库，以它为主；缓存数据和高并发这类数据存非关系型数据库，以它为辅。

    * 例：关系型数据库存学生表和分数表两张表后能做关联查询，非关系型数据库做不到这件事。

## ER 模型与四个存储单位

* **ER 模型（Entity-Relationship Model）**

    * > **定义**：关系型数据库存储和设计规则的总结。

    * E 是 Entity 的缩写，代表「实体」，表达的是数据按类别存在表中这件事。

    * R 是 Relationship，代表「关系」，指表和表之间可以建立某种关系，最终能通过关系进行关联操作。

    * 例：把学生和分数这两类数据分存到两张表，让表和表之间建立关系后，既能查「某个学生和他关联的分数」，也能查「这个分数是哪个学生考的」。

* **四个存储单位**

    ```text
    库  ── 关系型数据库中最大的存储单位（库里可能还不装具体数据，
    │       它下面还有别的容器）
     └── 表 ── 每一类数据最终存储到一个表里，表要存到库中
          ├── 列 ── 表的特性列，定义表中如何存储。
          │         例如学生表要存什么属性：姓名、年龄……
          │         列是最小的存储单位
          └── 行 ── 在表里形成的一行数据，
                    一行数据其实代表一条记录、一个实体
    ```

    * 库是最大的存储单位。

    * 表是一类数据的集合。

    * 列标注这一类数据要存哪些属性，是最小的存储单位。

    * 行代表一个实体、一条记录，是操作数据的基本单位：删除和查询的对象都是行，不是列。

* **与 Excel 表格的对应**

    | Excel 表格 | 关系型数据库 | 说明 |
    | --- | --- | --- |
    | 整个表格文件 | 库 | 最大存储单位 |
    | 工作表（页） | 表 | 一类数据的集合，类似 Java 里的「类」 |
    | 列 | 列 | 描述这一类数据要存哪些属性，类似 Java 对象的属性；最小存储单位 |
    | 行 | 行 | 一个具体的实体，类似 Java 中的「对象」 |

## 数据库管理系统

* **数据库管理系统（Database Management System, DBMS）**

    * > **定义**：操作和管理数据库的大型软件，用户最终通过它完成对数据库中数据的操作。

    * 仓库管理员加上仓库才等于一个动态的仓库，二者缺一不可；数据库本身是静态的文件或内存数据，需要 DBMS 这个「仓库管理员」来操作。

    * 操作路径永远是先操作数据库管理系统，间接达到对数据库中数据的操作，不能直接去操作数据库文件。

* **常见的四款关系型数据库管理系统**

    | 管理系统 | 出身 | 擅长 | 费用 |
    | --- | --- | --- | --- |
    | Oracle | 行业绝对一哥，很多关系型管理系统的标准都是参照它定义的 | 大型项目；性能优异 | 企业使用需要收费，而且相当昂贵 |
    | MySQL | 最早由瑞典公司开发，后被 Oracle 收购，与 Oracle 同属甲骨文 | 中小型项目；性能也不差 | 企业使用有免费的开源版本 |
    | DB2 | IBM 的知名产品，IBM 生态圈的一环 | 金融项目、大型项目；数据恢复与数据安全管理更全一些 | 需要认证收费，价格也不便宜 |
    | SQLite | 小型嵌入式数据库 | 移动端 App、智能家居、智能眼镜等小型设备 | 企业免费 |

    * Oracle 被业界认为是最成功、性能最好的关系型管理系统，但企业使用收费且昂贵。

    * MySQL 是 Oracle 的小弟，性能也不差，适合中小型项目，企业有免费版本。

    * DB2 用在 IBM 的硬件服务器生态里，比较适合金融项目或大型项目，内部的数据恢复和安全管理更全面。

    * SQLite 比较小型，手机里的 App、智能家居、移动设备、智能眼镜里存数据都可以用它。

* **站在老板的角度选型**

    * 市场使用率排行前两位基本就是 Oracle 和 MySQL，两张图交叉着排第一、第二。

    * 阿里、百度、腾讯等一线大厂都有自己的数据库产品，不会用 Oracle 这种收费产品；用第三方收费产品的基本是中小型公司，而中小型公司一定把成本放在第一位。

    * 亚太地区对甲骨文的营销额只有 66 亿且呈下降态势，说明我们对性能可能没有那么极致的要求。

    * 综合市场使用率与成本，国内企业的数据库首选是 MySQL。

* **版本选择**

    * MySQL 长期并行维护两个稳定版本，一个 5.7 系列、一个 8.0 系列，不像常规软件那样更新到新版就丢掉旧版。

    * Oracle 在政策上已于 2023 年 10 月 25 日结束对 MySQL 5.7 的更新：5.7 作为末期维护版本只修 bug，不再做新功能研发，官方强烈建议尽快迁移到 8.0。

    * 8 相对 5.7 在性能、安全以及一些新特性上做了许多改进和更新，且新版本一般向下兼容。

    * 版本号从 5 系列直接跳到 8 系列，中间没有 6 和 7，表达的是 8 相对 5 系列做了一个很大的跨越。

    * 课程使用的是官方标注 GA（General Availability，即最新最稳定版本）的 8.2.0。

## Windows 上安装配置 MySQL

* **安装前的排雷**

    * 先检查常见问题和解决方案，再去做安装。

    * 安装 MySQL 需要电脑里具备其他环境包，缺少就会报错：比如弹出窗口报缺少 .NET Framework，还可能缺 C++ 的包或 DLL 文件，报了对应问题就下载安装，规律是缺什么补什么。

    * 安装完毕以后服务启动不起来只有一个原因：电脑用户名是中文。中文用户名会在电脑中生成对应的中文存储文件夹，MySQL 识别中文可能乱码，无法在该用户文件夹下初始化内容而报错。

    * > **易错点**：安装到最后「Execute」失败，别怀疑安装包有问题，九成是中文用户名导致的。先改成英文用户名，再回头重新安装。

* **安装步骤**

    * Windows 下用的是 MSI 格式的 8.2.0 可执行文件，双击安装。

    * 第一步双击安装包，同意认证协议，点 Next。

    * 第二步选择安装方式，选默认模式安装，点 Install；其中选择版本的步骤不用选，因为安装包里只有一个 MySQL 服务，没有什么其他工具。

    * 到这里「安装」这件事本身已经完成，接下来进入初始化配置：服务在后台占哪个端口号、初始化账号密码是什么。

* **三个必须记住的配置项**

    * 端口号默认是 3306，可以改但不建议改，因为后期其他软件连接 MySQL 时默认就找 3306 端口。

    * 超级管理员账号固定就叫 `root`，页面上方两个配置框填的是 root 的密码和重复密码，两遍都是密码；密码弱就弱，好记就行，下方是否添加其他非超级管理员账号前期先不添加。

    * 服务名一定要记住，因为后期可以通过 Windows 下的 DOS 命令去启动 MySQL 服务，就是根据这个服务名来的；服务名区分大小写，重复的服务名会导致安装失败。

    * 服务名之后的几步（初始化数据位置、是否创建数据）保持正常默认即可。

    * 点 Execute 正式初始化，只要 Start server 这一步成功就证明 MySQL 安装成功；最后 Next、Finish 收尾。

* **服务的开启与关闭**

    * MySQL 不像其他可视化工具那样在桌面上有可执行文件，它是一个后台服务。

    * 可视化方式：右键点「管理」进入「服务」，服务名以 M 开头，按 M 可快速定位到 `MySQL82`；默认 MySQL 服务是开机自启动的，装完就是开启状态，不用时可以右键停止，想用时再右键启动。

    * 命令方式：打开 `cmd` 并右键以管理员身份运行，否则没有对服务操作的权限；格式是 `net` + 空格 + `start`（或 `stop`）+ 空格 + 服务名。

    ```cmd
    net stop MySQL82
    net start MySQL82
    ```

    * 服务名是区分大小写的，写错了没反应。

    * > **注意**：进行数据库操作之前一定要先把 MySQL 服务启动，否则无法进行数据库操作。

* **配置环境变量**

    * 验证方式：确保服务已启动，在命令行里输入 `mysql`。

    * 报「不是内部或外部命令」说明 MySQL 没有配到环境变量 Path 中；Path 决定系统去哪里找可执行文件，可执行文件不在 Path 指到的文件夹里就认不出来。

    * 在 `cmd` 里敲 `mysql` 本身不需要管理员权限，只有启动和停止服务才需要。

    * 推荐做法：先在系统环境变量（任何用户都可以使用）里新建变量 `MYSQL_HOME`，值就是 MySQL 整个文件夹的地址；再双击打开 Path 新建一项，写上 `%MYSQL_HOME%\bin`。

    ```text
    MYSQL_HOME  =  C:\Program Files\MySQL          （MySQL 整个文件夹）

    然后在系统环境变量 Path 中追加一项：
        %MYSQL_HOME%\bin
    ```

    * 两个百分号代表「引用其他变量」，引用的就是刚声明的 `MYSQL_HOME`，这一行等价于完整路径加上 `\bin`。

    * 不推荐直接在 Path 里写完整路径：换安装位置时它要改 Path 里那一长串，容易漏、容易错；用 `MYSQL_HOME` 只需要改一个值，Path 那一行完全不用动。

    * > **注意**：有些机器打开 Path 是一整串用分号连着的，这时要在前面补一个分号，再继续写 `%MYSQL_HOME%\bin`。

    * 配完点两次「确定」后，必须把原来那个黑色 cmd 窗口关掉再重新打开，窗口不关还用着上次的变量值。

## Mac 上安装配置 MySQL

* **安装**

    * 整个准备过程分三步：完成 MySQL 的安装、掌握服务的启动和停止、配置环境变量。

    * 双击可执行文件，系统弹出窗口问要不要允许就允许，然后是介绍页继续。

    * 许可认证协议没有「不同意」这个选项，拖到最下面点继续，它还会再问一遍是否同意，同意。

    * 安装类型这一步位置不用改，用它默认的位置，这样配环境变量时找到的软件位置都是统一的。

    * 一路安装，中间要输入自己电脑的账号密码。

* **配置密码**

    * 装完软件，安装包会自动接着做 MySQL 相关的 Configuration 配置，这一段才是关键。

    * 第一个配置是选密码策略，走默认值即可。它给两份是因为 MySQL 5.7 和 8 版本的加密方式不同：选上方是 8 版本的加密方式，选下方等于用 MySQL 8 的软件但采用 5.7 的加密方式。

    * 第二个配置是输入超级管理员 `root` 账号对应的密码，要求至少 8 位、里面包含大小字符。

    * > **易错点**：Mac 下 root 密码有长度和大小写的要求，不像 Windows 下可以随意配置。

    * > **提示**：密码不要搞得太复杂，省得自己记不住，后面改密码比较麻烦。

    * 设置完点 Finish，这一步是让它直接初始化 MySQL 服务，可能还要再输一次当前电脑的登录密码。

* **服务的开启与关闭**

    * MySQL 服务在 Mac 打开电脑以后是自动开启的，所以真正要学的是怎么关它。

    * 系统「设置」里会多出一个 MySQL 选项，这一块直接体现服务当前是否在运行：绿色代表正在运行，点 Stop 停止，停止后这边变成 Start，再点 Start 就开起来了。

    * 下方还有一个 Uninstall 按钮，代表后期卸载 MySQL，点它就可以。

    * 做数据库操作之前，只要确保这个服务是绿的就是开启状态即可。

* **配置环境变量**

    * 终端输入 `mysql` 回车，如果报这个命令没有被识别，说明 MySQL 虽然安装成功了，但没有配到环境变量下。

    * Mac 的默认环境变量文件是当前用户下一个叫 `.bash_profile` 的隐藏文件。

    * 输入 `pwd` 看当前路径，如果这就是账号对应的文件夹，环境变量文件就在这里；前面带一个小飘号 `~` 就代表回到了当前用户文件夹。

    ```bash
    pwd
    ```

    * 回到家目录后输入 `ls -a` 查看隐藏文件（`-a` 代表查看隐藏文件），就能找到 `.bash_profile`。

    * 因为没有改变安装位置，MySQL 装在 `/usr/local` 下面（前面要加斜杠，是绝对路径），进去 `ls` 能看到 `mysql`，进去后有 `bin` 文件夹，`bin` 里有一个可执行文件叫 `mysql`。

    ```text
    /usr/local/mysql/bin
    ```

    * 先 `cd` 回家目录，用 `ls -a` 确认 `.bash_profile` 存在，再用文本编辑器命令 `vim` 打开它。

    ```bash
    vim .bash_profile
    ```

    * 找到 `PATH` 变量，PATH 里已有多个路径且用冒号隔开，追加时同样用冒号分隔。

    ```text
    /usr/local/mysql/bin:
    ```

    * 用 `vim` 进到编辑命令后，必须先按 `i` 进到编辑模式，不按 `i` 写不了东西。

    * 写完按 `Esc` 退出编辑模式，再按 `Shift` 加冒号输入 `wq`，相当于保存并退出。

    * > **注意**：这个地址加在 `PATH` 的前面或后面都行，但分割前后一定要加冒号。

    * 保存后还差一步，用 `source` 让环境变量立即生效。

    ```bash
    source .bash_profile
    ```

    * `source .` 指的是找当前文件夹下的这个文件，不在当前用户文件夹下会报找不到文件，要先 `cd` 回去再执行。

    * 验证：输入 `mysql --version` 能输出版本号，说明 MySQL 命令已被识别。

    ```bash
    mysql --version
    ```

## SQL 指令

* **软件的两类形态**

    * 图形用户界面类应用（Graphical User Interface, GUI）：游戏、QQ、微信这类都有用户界面，通过控制鼠标、键盘就能完成操作。

    * 无用户界面或后台服务类的应用：MySQL 属于这一类，只是默默在后台运行的服务，没有可视化操作界面。

    * 后台服务类应用没有可点的地方，必须输入一段特定的文本指令或命令与它交互，最后由它返回结果。

    ```sql
    show databases;
    use mysql;
    show tables;
    ```

* **结构化查询语言（Structured Query Language, SQL）**

    * > **定义**：操作 MySQL 这类关系型管理系统的一套基本命令，也叫 SQL 命令、SQL 语句、SQL 指令。

    * SQL 是这三个单词的缩写，翻译过来叫结构化查询语言。

    * 最早被美国国家标准局定义为关系型数据库的美国标准，最后被国际化标准组织采纳为国际标准的关系型数据库的标准语句。

    * 学完 SQL 可以操作所有关系型数据库，而非关系型数据库是操作不了的。

    * 指令、管理系统、数据库三者的层级关系如下。

    ```text
                    SQL 指令
                       │
                       ▼
            数据库管理系统（DBMS）
        MySQL / Oracle / DB2 / SQLite ...
                       │
                       ▼
                 数据库（DB）
    ```

    * MySQL 本身在安装完成后就成了过去式，后面讲的重点是 SQL 指令：到底有哪些指令、能对数据库做怎么样的操作。

* **标准与方言**

    * SQL 虽然是标准、支持所有关系型数据库，但针对不同的关系型管理系统它也有方言的概念。

    * 课程讲的是标准 SQL，所有关系型管理系统都支持；MySQL 的相关特性方言只有 MySQL 支持，其他数据库不支持。

    * 要操作 MySQL 这类关系型管理系统就必须学 SQL 语句，学的是标准 SQL 加 MySQL 相关方言。

## SQL 语句分类与学习顺序

* **按作用分类**

    | 分类 | 中文名 | 管什么 | 学习位置 |
    | --- | --- | --- | --- |
    | DDL | 数据定义语句 | 库、表、列等容器的创建、修改、删除 | 第一步，必学 |
    | DML | 数据操纵语句 | 表中数据的添加、修改、删除 | 第二步，必学 |
    | DQL | 数据查询语句 | 查询 | 第三步，最复杂，课程核心 |
    | DCL | 数据控制语句 | 创建账号、控制访问权限 | 扩展拔高 |
    | TCL | 事务控制语句 | 事务与失败回滚 | 扩展拔高 |

    * 增、删、改、查一定是最终目标，但一定不是最初的目标：关系型数据库内部是有容器的，插入数据前要先把库、表、行、列这些容器建好。

    * 就像 Java 分 Java SE、Java ME、Java EE 要按顺序学一样，SQL 内部的命令非常多，必须按分类的作用顺序学。

* **数据定义语句（Data Definition Language, DDL）**

    * 包含关于容器的创建、删除和修改相关的指令和命令，包括库的创建、表的创建、列的修改等动作。

    * 是学习时第一步要学的事情，先完成数据库相关容器的创建、修改和删除。

* **数据操纵语句（Data Manipulation Language, DML）**

    * 包含对数据的添加、修改以及删除这三个动作。

    * 不影响表和库等相关的结构，只对表中数据做增、删、改。

    * 容器建好后只有容器没有数据也不行，所以它是第二个要学的。

* **数据查询语句（Data Query Language, DQL）**

    * 只包含一个功能：查询，会根据表查询到结果。

    * 不管怎么查都不会影响表中的数据，更不会影响整个表结构。

    * 因为查询条件有单表、多表等非常多样化的情况，它是最复杂的，也是课程的重点核心。

* **数据控制语句（DCL）与事务控制语句（TCL）**

    * DCL 负责创建账号、对数据库的访问权限进行控制。

    * TCL 负责事务与失败后的回滚。

    * 两者属于对数据库的高级维护，是扩展和拔高部分，彼此谁先谁后没有任何顺序要求。

## 连接 MySQL 与基本命令

* **写 SQL 的位置**

    * > **定义**：黑窗口（Windows 的命令提示符 `cmd`、Mac 的终端）就是编写和输入 SQL 指令的编辑区与编辑工具。

    * 第一步打开右键「管理」进入「服务」，找到 MySQL 服务，要确保它处于正在启动状态。

    * 第二步打开 `cmd` 命令提示符（Mac 就打开终端），通过它连接到对应的 MySQL 服务，连接后就能向 MySQL 传递 SQL 指令。

* **连接参数**

    * 第一个必须先写的是 `mysql`，这是固定的，相当于调用 MySQL 的可执行文件，后边要跟一个空格。

    | 参数 | 含义 | 必填 | 写法要点 |
    | --- | --- | --- | --- |
    | `-u` | 要登录的账号用户名 | 必填 | 用户名紧贴 `-u` 或写空格都行 |
    | `-p` | 该账号的密码 | 必填 | 密码必须紧贴 `-p`，不能写空格 |
    | `-h` | MySQL 服务所在主机的 IP 地址 | 可省略 | 同一台电脑时默认本机 |
    | `-P` | MySQL 软件的端口号 | 可省略 | 大写 P，默认 3306 |
    | 库名 | 直接连接到的库 | 可省略 | 不写相当于连接所有库 |

    * `-h` 之所以要存在，是因为 MySQL 未必装在当前电脑上，通过 IP 地址就可以连接装在别处的 MySQL。

    * `-P`（大写 P）就是端口号，找到 IP 地址以后想定位具体软件还得知道它所在的位置，默认是 3306，安装时没改就是 3306。

    * `-h` 和 `-P` 在 MySQL 与黑窗口装在同一台电脑、且端口号没改时都可以省略，等于默认找本机 3306。

    * 末尾还可以写一个数据库名：写了就是直接连到某个库，不写相当于连接到所有库，之后再选择使用哪个库。

    * 必须写的只有 `-u` 和 `-p`，其余三项都可以省略。

* **密码不要明着写**

    ```bash
    mysql -uroot -proot
    ```

    ```bash
    mysql -u root -p root -h 127.0.0.1 -P 3306
    ```

    * 上面两种写法的效果相同，因为默认就连接本地和 3306。

    * > **易错点**：把密码直接写在命令里，开发中同事一眼就可能看到并记住你的密码，存在趁机登录你的数据库删库跑路的风险，密码不建议明着写。

    ```bash
    mysql -u root -p
    ```

    * 只写 `-p` 不跟密码，回车后系统会提示你输密码，这时输入的就是隐式密码；后面继续加 `-h 127.0.0.1` 之类也没问题。

    * 连接成功后前面会变成 `mysql>` 提示符，之后所有 SQL 命令都在此处编写。

* **三个基本命令**

    ```sql
    select version();
    ```

    * > **易错点**：MySQL 以分号判定语句是否结束，不加分号它认为你没结束，会把新输入的内容追加到之前的命令里；而且这个分号必须是英文分号。

    * 注释有三种方案，瞎写会被判定为不认识的指令。

    * 单行注释：`#` 开头。

    * 单行注释：`-- ` 开头，双减号后必须加一个空格，否则不被识别。

    * 多行注释：`/* */` 包围。

    * 退出连接用 `exit`，它是最后一个关键字了，也没有其他命令跟在后面，所以可以省略分号直接执行，执行后返回 `Bye`。

## 可视化工具的选型与使用

* **黑窗口的不足**

    * 没有 SQL 提示，只能自己硬写，也不能识别自己写对还是写错。

    * 不能备份，写了很多条语句想备份发给同事做不到。

    * 不方便粘贴。

    * 不能批量执行，只能单条语句单条语句执行。

    * 不能可视化，查出的结果和库都是非常丑的界面。

* **工具选型**

    | 工具 | 费用 | 特点 |
    | --- | --- | --- |
    | MySQL 官方工具 | 开源免费 | 功能比较强大；全英文界面；官方发布较晚，用得不多 |
    | Navicat | 收费，免费版功能阉割严重 | 功能更强大，有代码提示 |
    | SQLyog | 免费版功能较弱，无代码提示 | logo 与 MySQL 一致，俗称「小海豚」；课程选用 |

    * 课程环境基于 MySQL 8.2 + SQLyog 13。

    * > **提示**：前期学 MySQL 建议把所有指令都手敲一遍，不用提示和补全，以此强化练习；选用没有代码提示能力的 SQLyog 正是看中这一点。

    * 最终用哪个工具随便装，它就是编写 SQL 的工具，基本界面都差不多；Windows 下用 SQLyog，Mac 下没有 SQLyog 版本所以用 Navicat。

* **SQLyog 的安装与连接**

    * 双击安装社区版的可执行文件；打开后界面语言选中文点 OK，然后正常 → 我接受 → 下一步 → 下一步 → 安装 → 完成。

    * 新建连接弹窗要填 Host、用户、密码、端口号、数据库，这些内容和黑窗口连接 MySQL 时要填的是同一批信息。

    * Host 本机写 `localhost`，如果要连其他机器就改成对应 IP 地址。

    * 用户用 `root`，密码填安装时设置的密码。

    * 端口号不用改。

    * 数据库可写可不写，写了代表指定数据库，不写代表连接所有数据库。

    * 填完先点**测试**确认成功，再点**连接**。

* **SQLyog 的四个界面区域**

    * 左侧罗列当前有哪些库，点开加号还能看到表信息，可视化展示库和表。

    * 上方是**执行区域**：第一个按钮执行选中的那一条，第二个按钮是完整执行（批量执行），下方还有一个**刷新**。

    * 数据库选中状态区会显示「未选中」，后续要操作数据库必须先选中数据库。

    * 中间是**编写 SQL 语句的区域**。

    * 下方是**执行结果和表数据展示区域**，用来看结果。

    * 选中表后点**表数据**能看到表里有哪些列，但这里面没有数据。

    * 做了修改但表数据没变时：刷新库内部的表是选中库后点刷新，刷新库列表是点上方的连接去刷新里面的库。

* **SQLyog 的执行与保存**

    ```sql
    SELECT VERSION();
    ```

    * 工具会识别关键字并显示为蓝色大写，建议这条语句也加个分号。

    * 批量执行按钮会把这块写的所有 SQL 语句全部执行（execute all queries）。

    * 只想执行其中某一条时，先选中它再点第一个按钮「执行查询」；同时选中多条一起执行也可以。

    * 按 `Ctrl + S` 可以把写好的 SQL 语句保存成文件。

* **Navicat 的安装与连接**

    * Mac 下装 Navicat，双击可执行文件，点「我同意」，可以跳过验证过程，安装耗时较长，越到后边越慢。

    * 装的是专业版本，提供免费 14 天试用。

    * 先确保系统设置里的 MySQL 服务是启动状态。

    * 点开 `Connection`，点 `New MySQL`，给本次连接起个名字，它会在侧边显示出来。

    * Host 本机填 `127.0.0.1`，端口号填 `3306`，账号填 `root`，再填上密码。

    * 填完点**测试**，成功后再点 **Save** 保存连接信息；双击连接信息就代表与对应的 MySQL 建立了连接，右侧会显示连接软件的一些信息，下方展示有哪些库。

    ```text
    连接测试失败
    1045  ...  using password: YES
    ```

    * > **易错点**：连接测试失败且错误码是 1045、后缀写着 `using password: YES`，一定是密码错了。

    * > **注意**：连上后下方展示的这几个库是 MySQL 软件自带的仓库，不要删，删了就真得跑路了。

* **Navicat 里写 SQL**

    * 点 `New Query` 创建一个编写 SQL 语句的文本区，在里面写 `SELECT VERSION();`。

    * 写完后选中语句，点执行位置，就会在下方展示执行结果等信息。
