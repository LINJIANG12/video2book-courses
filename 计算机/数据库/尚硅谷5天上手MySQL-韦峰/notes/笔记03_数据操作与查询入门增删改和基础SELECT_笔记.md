# 数据操作与查询入门：增删改和基础SELECT

## DML 与 DQL 的分工

* **数据操纵语言（Data Manipulation Language，DML）**

    * > **定义**：负责对库表中的数据做三类操作——插入、更新、删除，对应的关键字分别是 `INSERT`、`UPDATE`、`DELETE`。

    * 「数据操纵语言」也叫「操作语言」，操纵和操作是同一回事的两种叫法。

    * 数据库的操作主要就四个方向：增、删、改、查。DML 把「查」剔开了，剩下增删改三个归它管。

    * 剔出「查」的原因：查询不会改变原有的数据——不管怎么查，数据不会丢、不会多、不会少；而插、改、删是真的会动表里数据的。

    * > **注意**：DML 不影响库表结构。不管怎么删数据，删不了表，也删不了库，它只对表内部的数据动刀。但真删了，数据是真的没了。

* **数据查询语言（Data Query Language，DQL）**

    * > **定义**：执行一条查询语句时，数据库会生成一张临时的虚拟表展示给用户，对底层的原有物理表没有任何影响。

    * DQL、DDL、DML 的共同点：都不会改变库表本身的物理结构。

    * DQL 独有的一条：它不会修改原有的表数据，无论如何查询，原有的数据记录都不会发生改变。

    * 核心关键字是 `SELECT`，代表选择与查询，用于从原有表中筛选出所需的数据结构。

    * 本章只针对单表查询，多表查询放到后续章节分开介绍。

    * 全章五个方向：DQL 整体介绍与单表/多表查询的区别；`SELECT` 的用法与基本查询语句；查询语句中常用的运算符；单行函数与多行函数；对查询结果做分组、排序、分页截取等升级加工。

    * 查询语法本身不难，难在需求场景和样式丰富多样，所以要靠大量练习加深理解。

## 行：数据操作的基本单位

* **行（Row）**

    * 关系型数据库一共有四个单位：库、表、行、列。

    * 列是最小的单位，库是最大的单位，但行是最基本的单位——真正干活的时候，粒度卡在行上。

    * 插入：选中一行，往这一行里去填对应的列值。

    * 修改：先锁定一行或若干行（锁定哪些行是有条件准备的），锁定以后改的是这一行中的某些列。

    * 删除：选中一行，把这一行的数据整个删掉就够了。

    ```text
                 数据库操作的基本单位：行
       ┌──────────┬──────────────────┬──────────────┐
       │   插入   │      修改        │     删除     │
       ├──────────┼──────────────────┼──────────────┤
       │ 选中一行 │  锁定一行或多行  │  选中一行    │
       │ 往里填值 │  改行中的某些列  │  把整行删掉  │
       └──────────┴──────────────────┴──────────────┘
       三件事的落脚点完全一样：先选中行，再动手
    ```

* **单表查询与多表查询**

    * 单表查询：查询结果来自单张真实的数据库表，通过查询语法最终生成一张虚拟表。

    * 单表查询要学的内容：`SELECT` 语法、按行筛选的 `WHERE`、各种运算符、内置函数，以及对结果做分组排序等高级操作。

    * 多表查询不是把单表查询的语法颠覆掉，而是在单表查询的基础之上扩展了部分语法。

    ```text
      单表查询                              多表查询

      表 students                           表 A ──┐
          │                                     ├── 多表合并语法 ──┐
          │                                     │                 │
          ▼                                     表 B ──┘         │
      单表查询语法                                                   │
          │                                                         ▼
          ▼                                                    虚拟的中间表
      ┌─────────┐                                                 │
      │  虚拟表 │                                                 │
      └─────────┘                                                 ▼
                                                   套用单表的查询语法
                                                          │
                                                          ▼
                                                    ┌────────────┐
                                                    │ 目标虚拟表 │
                                                    └────────────┘
    ```

    * 多表的执行是两步走：先用多表合并语法把多张真实表合并成一张虚拟的中间表，合并完之后再正常套用单表查询语句与语法。

    * 只要学好单表查询，多表查询只需要额外掌握合并语法即可。

## 插入的三种写法

* **全列插入**

    ```sql
    INSERT INTO 表名 VALUES (值1, 值2, ...);
    ```

    * `INSERT` 和 `INTO` 是一对，后面紧跟要插入的表名。

    * `VALUES` 代表你要插入这一行里的值，后面一个括号就代表一行；一行里有几个列，括号里就写几个值，中间用逗号隔开。

    * > **易错点**：语法更简洁，代价是必须记住当初建表时一共有哪些列，而且 `VALUES` 里值的顺序必须跟表的列顺序一致。一个表有五六十列时根本记不住，这种方案就不推荐。

* **指定列插入**

    ```sql
    INSERT INTO 表名 (列名1, 列名2, ...) VALUES (值1, 值2, ...);
    ```

    * 跟全列插入一模一样，只是在表名后边多一个括号，括号里指定你要插入哪些列。

    * 写 `VALUES` 时，值按你前面指定列名的顺序写，不再按原表列的顺序。

    * 括号里的列可以是全部列，也可以是两三列、一列，顺序自己随便定；灵活性就体现在这里。

    * 括号里明明白白写着按哪个顺序填值，容易正确，也就不容易出错。

    | 对比项 | 全列插入 | 指定列插入 |
    | --- | --- | --- |
    | 写法 | `INSERT INTO 表名 VALUES (...);` | `INSERT INTO 表名 (列名, ...) VALUES (...);` |
    | 值跟谁对齐 | 表中**原有**的列顺序 | 你**指定**的列顺序 |
    | 优点 | 语法简洁 | 灵活，不用记原有列顺序和列名 |
    | 缺点 | 列一多就记不住，顺序错一个全崩 | 多打一个括号 |

* **多行插入**

    * 上面两种语法都不用变，只在后面多加一个逗号：逗号隔开再写一个括号，是一行；再逗号，再写一个括号，又一行。

    * 多个括号里放多对值，就表示一次插入多条数据。

    * > **易错点**：无论哪种插入方式，值的类型和顺序都必须跟表中的列名——或者你指定的列名和类型——一一对应。

* **关键字与引号规则**

    * 写 `VALUES` 的地方也可以写成 `VALUE`，关键字能换，但 `VALUES` 是标准语法，推荐用 `VALUES`。

    * 插入数据时凡是字符串还是日期类型，外面都要加一个单引号，代表它是个字符；时间就是一个特殊格式的字符串。

    * > **易错点**：列名和表名都是关键字，不要加引号。只有值的位置，当它是个字符串的时候才需要加单引号。

* **不指定列与显式 NULL 的分岔**

    * 不指定某一列 → 该列走它的默认值。

    * 主动插入且给一个空值 → 它不走默认值的路子，给的就是空值，空在 SQL 中直接写 `NULL`。

    * 现在约束还没讲，结果可能看起来一样；后期会讲空约束和默认值约束，加了默认值约束以后这两条路径就分道扬镳。

* **在学生表上实操四个插入动作**

    * 准备：创建 `dml_db` 库，`USE` 切到该库，库下建 `students` 学生表，五列依次是学号、姓名、年龄、生日、身高，学号为 `INT`、姓名为字符串、年龄为数值、生日为时间、身高为数值。

    * 插一名学生的所有信息，全列插入：

    ```sql
    INSERT INTO students VALUES (1, '二狗子', 18, '1990-06-06', 185.5);
    ```

    * 值的数量要等于这个表所有列的数量，类型和顺序跟表里的列一一对应；也可以把列名写出来，值的顺序跟着列名顺序走：

    ```sql
    INSERT INTO students (stu_id, stu_name, stu_age, stu_birthday, stu_height)
    VALUES (1, '二狗子', 18, '1990-06-06', 185.5);
    ```

    * 只插学号、姓名、年龄，其他列不用管：

    ```sql
    INSERT INTO students (stu_id, stu_name, stu_age) VALUES (3, '吕蛋蛋', 29);
    ```

    * 一次插两名学生的信息，全都要，逗号隔开写两个括号：

    ```sql
    INSERT INTO students VALUES
    (4, '狗剩子', 20, '2020-02-20', 223.5),
    (5, '石头仔', 20, '2000-01-01', 175.0);
    ```

    * 有的列想插空值——列名照样全写出来，主动赋 `NULL`：

    ```sql
    INSERT INTO students (stu_id, stu_name, stu_age, stu_birthday, stu_height)
    VALUES (6, '小笨蛋', 20, NULL, NULL);
    ```

## 修改：UPDATE 加 SET，条件放 WHERE

* **全表修改**

    ```sql
    UPDATE 表名 SET 列名 = 新值, 列名 = 新值;
    ```

    * 关键字是 `UPDATE`，后面紧跟表名；另一个关键字是 `SET`，代表你要把这行的哪些列等于哪个值。

    * 一次想改行中的多个列，用逗号隔开，写成「列名等于值、逗号、列名等于值」。

    * 没有条件、不筛选任何行时，它会把表中所有行都按 `SET` 后面的内容改掉。

* **条件修改**

    ```sql
    UPDATE 表名 SET 列名 = 新值 WHERE 条件;
    ```

    * 就是在全表修改的语法基础上加一个 `WHERE`。

    * `WHERE` 对表中的行进行筛选，筛到符合的行以后，再去修改这些行里对应的列。

    * > **注意**：不写 `WHERE` 代表修改表中所有行的数据；写了 `WHERE` 就只修改符合条件的那几行。

* **执行顺序与基于原值运算**

    * 执行顺序是先按 `WHERE` 找到符合条件的行，再把行里的列改成新值——找行在前，改列在后。

    * 想让每行各自在原值上运算，就得把原值取出来参与运算，写成 `列名 = 列名 + 增量`。

    * > **易错点**：`SET` 后面一旦写成一个固定值，所有符合条件的行都会变成同一个值，而不是各自相对地加。

    * > **易错点**：Java 里的 `+= 2` 这种写法在 SQL 中不支持。SQL 只取你原来的列，在右侧原有的列的值上加减乘除，但没有 `+=`。

* **在学生表上实操四道修改题**

    * 把学号为 8 的学生姓名改成「黄六」：

    ```sql
    UPDATE students SET stu_name = '黄六' WHERE stu_id = 8;
    ```

    * 把年龄小于 20 的学生，身高在原有基础上加 2.0，符合条件的两行改完分别是 167.8 和 187.5：

    ```sql
    UPDATE students SET stu_height = stu_height + 2 WHERE stu_age < 20;
    ```

    * 把学号为 11 的学生生日改成 2003-07-10，且年龄改成 21，`SET` 后面两列用逗号隔开：

    ```sql
    UPDATE students
    SET stu_birthday = '2003-07-10', stu_age = 21
    WHERE stu_id = 11;
    ```

    * 把所有学生的年龄增加一岁，没有条件代表找到每一行，不用写 `WHERE`：

    ```sql
    UPDATE students SET stu_age = stu_age + 1;
    ```

## 删除：全表清空与按条件删

* **两种删除**

    ```sql
    DELETE FROM 表名;                 -- 全表删除所有行
    DELETE FROM 表名 WHERE 条件;      -- 条件删除，只删符合条件的行
    ```

    * 全表删除把一个表中的所有数据都删掉；条件删除是先选中符合条件的行，选中行以后再删。

    * 开发中 99% 的需求其实是条件删除。

    * 这里的删除指的是删除表中的相关数据，跟网上开玩笑的「删库跑路」不是一回事，后者是库表结构层面的操作。

* **DELETE 与 TRUNCATE 的差别**

    * 两者都会把表中的全部数据删掉，效果类似，但 `DELETE` 相对清空表的 `TRUNCATE` 更轻一些——它只删除当前表的数据，不删除表相关的记录，比如自增的最大 ID 值。

    * `TRUNCATE` 的删除程度更重：不仅删表数据，还会重置数据库自增 ID 的最大记录值。

    * 单纯删除数据通常用 `DELETE`；项目推倒重来、要上新项目需要把原有数据完全清空，才用 `TRUNCATE`；业务运行过程中因逻辑需要删掉某条数据，必须用 `DELETE`。

* **条件之间的逻辑关系**

    * SQL 中条件之间的逻辑关系用 `AND`、`OR` 这类关键字连接。

    * 两个条件都必须符合时用 `AND`；满足其一即可时用 `OR`；异或关系也可以在多条件拼接里用。

    * 删除身高高于两米并且学号大于 10 的学员：

    ```sql
    DELETE FROM students WHERE stu_height > 200 AND stu_id > 10;
    ```

    * 删除身高大于两米或者学号大于 10 的学员：

    ```sql
    DELETE FROM students WHERE stu_height > 200 OR stu_id > 10;
    ```

    * 后面不加任何条件，执行后即可清空表中所有行的数据：

    ```sql
    DELETE FROM students;
    ```

* **DML 要拿下的三个目标**

    * 掌握 `INSERT`、`UPDATE`、`DELETE` 三个关键字的基本语法结构和各自作用。

    * 理解数据库操作的最基本单位是行，无论插入、修改还是删除，针对的都是整行。

    * 掌握三种语法细节：怎么全表插入、怎么指定列插入、怎么插多行；更新时怎么在原有列上做修改、怎么指定多列更新；删除时怎么按条件清除。

## 基础 SELECT 的五种情况

* **非表查询**

    ```sql
    SELECT 运算, 函数;
    ```

    * 查询语句通常是对原有物理表做数据筛选、生成虚拟表，但也有特殊场景：查询时不指定具体表，直接快速输出一个结果，类似于 Java 中的控制台打印输出。

    * 后面不接 `FROM 表名`，可以写运算、可以写函数，多个之间用逗号隔开。

    * `SELECT 1;` 直接输出数值 1；`SELECT 9 % 2;` 直接计算 9 取模 2 的结果。

    * 函数同理，`SELECT version();` 把获取当前 MySQL 版本号的函数执行结果打印输出，类似 `System.out.println` 把函数返回值输出到控制台；`SELECT NOW();` 输出当前时间。

* **指定表查询**

    ```sql
    SELECT 列名1, 列名2, ... FROM 表名;
    ```

    * `FROM` 后面指定需要参照查询的目标表，`SELECT` 后面跟上需要从该表中获取的具体列名，多列之间用英文逗号分隔。

    * 不写 `WHERE` 条件时，代表把表中所有行都拿到；拿哪些列由 `SELECT` 后面的位置指定，列的顺序也可以自己调换。

    * 列名也可以采用 `表名.列名` 的格式，这种写法在多表查询中极为常用，用来避免多张表中存在同名字段时产生歧义；单表中直接写列名即可，数据库默认从当前表定位该字段。

    ```sql
    SELECT 表名.列名1, 表名.列名2 FROM 表名;
    ```

    * 获取所有字段可以写成 `*` 或 `表名.*`，星号通配符代表获取它后方指定表中的所有列——单表取单表所有列，多表取多表所有列。

    ```sql
    SELECT * FROM 表名;
    SELECT 表名.* FROM 表名;
    ```

    * 多表查询中常常某一张表所有列都要、其余表只要个别列，就写成这张表点星号加其他表名点列名。

    * 各字段在虚拟表中的排列顺序，与查询中书写的顺序保持一致。

* **给列起别名**

    ```sql
    SELECT 列名 AS 别名 FROM 表名;
    SELECT 列名 别名 FROM 表名;
    ```

    * 用关键字 `AS` 起别名；中间加空格也可以，就是「列名 空格 别名」，这样可以省略 `AS`。

    * 别只是空格，不是逗号——写逗号以后代表的就是多个列了。

    * 查到的结果在虚拟表中会以别名作为基准显示。

    * 起别名的主要场景是为了后期跟 Java 做映射：Java 类用驼峰式命名，`student_id` 对应的实体类属性叫 `studentId`，不一致时就在虚拟结果表里起别名。

    ```sql
    SELECT
      student_id   AS studentId,
      student_name AS studentName
    FROM student;
    ```

* **DISTINCT 去重**

    ```sql
    SELECT DISTINCT 列名 FROM 表名;
    ```

    * `DISTINCT` 对查询出来的这些列的值去重，可以写一列，也可以逗号隔开写多列。

    * 单列去重：`age` 列的值有 1、1、2、2、3、3、4，普通查询得到 6 个结果，加 `DISTINCT` 后只剩 1、2、3、4。

    ```sql
    SELECT age FROM student;
    SELECT DISTINCT age FROM student;
    ```

    * 写多列时按多列的综合结果去重：年龄 1、性别男与年龄 1、性别女是两项不同的综合结果，都会保留。

    * > **易错点**：`DISTINCT` 是对结果去重的，必须加在 `SELECT` 的后边、列名的前方。

    * > **易错点**：去重一般单独使用，去了重就不要再写其它列。因为去重只对结果去重，它不知道这个结果到底属于哪个 `emp_name`。

    * 查一共有几种薪资，5000、7100、8000 这样两个 8000 就算一种：

    ```sql
    SELECT DISTINCT salary FROM t_emp;
    ```

* **查询常数**

    ```sql
    SELECT 列名, '常数值' AS 别名 FROM 表名;
    ```

    * 查询常数指自己造一个数据，伪装一个列放到结果里；这个位置既可以写列名（去表中找到这些列名），也可以写常量值。

    * 字符串写单引号或双引号都行，数值就直接写数值；造出来的常数列可以起别名，`AS` 或空格都行，也可以造多个常数值和常数列。

    * 员工表里所有人的公司都是「尚硅谷」，就在结果里多造一列：

    ```sql
    SELECT *, '尚硅谷' AS 公司 FROM 员工表;
    SELECT emp_name, salary, '尚硅谷' AS company FROM t_emp;
    ```

    * > **易错点**：有星号这种通配符时，它必须放在第一位。星号必须在前方，其他列往后面放，这是 SQL 语句的一个标准和规范；把常数列写到 `*` 前面会直接报错。

## 练习用的员工表 t_emp

* **库与表的准备**

    * 先准备一个库叫 `test04_dql`，再 `USE` 使用这个库，库下建员工表 `t_emp`，随后插入 27 条数据。

    * 插入数据的写法是 `INSERT INTO` 表名、指定列名、后面 `VALUES` 一个括号是一行，多条数据之间用逗号隔开：

    ```sql
    INSERT INTO 表名 (列名1, 列名2, ...)
    VALUES (值1, 值2, ...),
           (值1, 值2, ...);
    ```

* **字段与类型**

    | 字段 | 类型 | 说明 |
    | --- | --- | --- |
    | 员工编号（`emp_id`） | INT | |
    | 员工姓名（`emp_name`） | VARCHAR | |
    | 工资（`salary`） | DOUBLE | |
    | 奖金比例（`commission_pct`） | DECIMAL | 月薪里有多少比例是奖金 |
    | 生日 | DATE | |
    | 性别（`gender`） | ENUM | 枚举，只能二选一 |
    | 手机号 | CHAR(11) | 国内手机号都是 11 位 |
    | 邮箱（`email`） | VARCHAR(32) | |
    | 地址 | VARCHAR(150) | 你的详细地址 |
    | 办公地址（`work_place`） | SET | 可以写多个值的字符串 |

* **ENUM 与 SET 的选值范围**

    * 枚举类型（ENUM）指枚举值之间可以用逗号隔开，选取时只能二选一，而且范围应该在这个范围之内。

    * > **定义**：`SET` 类型就是一个可以写多个值的字符串。枚举只能选一个，`SET` 可以选多个，但两者都必须在自己划定的范围之内进行选择。

    * 插入时办公地址是北京就写 `'北京'`；既在北京又在深圳办公就写 `'北京,深圳'`，多个值之间用逗号隔开。

    * 设计动机是取值范围是固定的：公司在北京有分公司，员工不能回老家去办公，所以办公地址被约束成一个固定的范围类型。

## 表结构查看：DESC 与 DESCRIBE

* **两个等价的关键字**

    ```sql
    DESCRIBE 表名;
    DESC 表名;
    ```

    * 写 SQL 语句时忘了表中有哪些列、又不能老去翻表结构，可以用这两个关键字指定表名，查看这个表一共有哪些列以及列的一些特征。

    * 两个关键字效果一样，推荐用 `DESC`，它更简洁些。

* **输出的六个选项**

    | 选项 | 看的是什么 |
    | --- | --- |
    | Field | 表中对应的列名 |
    | Type | 列的类型，`int`、`double`、枚举等，可以据此判断列类型该如何处理 |
    | Null | 这一列能否为空。`NO` 代表不能为空，`YES` 代表可以为空，可以不赋值 |
    | Key | 有没有索引、是不是主键 |
    | Default | 这一列有没有默认值 |
    | Extra | 额外描述，比如 `DEFAULT CURRENT_TIMESTAMP`、`ON UPDATE CURRENT_TIMESTAMP` |

    * `Key` 在没有主键也没有索引时是空的。

    * `Extra` 对应时间类型的额外描述：想在插入时自动更新时间或保存时更新时间，除了类型以外还有这么一段描述；有额外描述才展示，没有就不展示。

    * 看完这六个选项，就能明白一列的完整状态，查询时可以针对性处理。

    * `gender` 和 `work_place` 这两列是有默认值的，插入时这两列不传值就走默认值，其它列没有默认值。

## WHERE 条件过滤

* **定义与分工**

    * > **定义**：`FROM` 用来指定表名，`SELECT` 只是你 `WHERE` 生效以后那些行里要哪一列。`WHERE` 负责行的筛选，`SELECT` 不影响拿到哪些行。

    * 查一个表时几乎不会要所有行，一般都有过滤：查询身高大于多少的学生、性别为男的学生、分数大于多少的成绩，这些过滤条件都写在 `WHERE` 后面。

* **逐行判断的执行模型**

    * `WHERE` 对每一行都检查条件是否符合，每行比较完以后只会得出 `true` 或 `false`（或 1 或 0），符合的行才被筛选出来。

    ```text
       t_emp 原始 4 行数据
              |
              v
       [WHERE] 逐行判断条件，每行只得出 真 / 假
              |  假、假、真、真
              v
       留下的行：行3、行4
              |
              v
       [SELECT] 从留下的行里指定要哪几列
              |  假设只要前两列
              v
       行3、行4 的前两列
    ```

    * 假设只有两行符合，最终结果就是这两行；拿到这些行以后，再用 `SELECT` 后面指定的列名去取列。

    * > **结论**：`WHERE` 的执行顺序优先于 `SELECT`，先筛选行、再筛选列，行是最基本的抽取单位。

* **语法与多条件拼接**

    ```sql
    SELECT 列信息 FROM 表名 WHERE 条件;
    ```

    * `SELECT` 后边依然写列信息，`FROM` 后边依然放表信息，只是在后边加个 `WHERE` 条件。

    * 条件里可以有一个、多个条件，用 `AND`、`OR` 或者异或进行拼接，最终形成一个综合结果。

    * 综合结果只有一个值，要么 `true` 要么 `false`；为 `true` 的行要，为 `false` 的行不要，要的行才能去查 `SELECT` 指定的列。

    | 子句 | 作用 |
    | --- | --- |
    | `FROM` | 指定参照和查询的表 |
    | `WHERE` | 进行表中行的数据筛选，注意它的执行早于 `SELECT` |
    | `SELECT` | 对符合条件的行，再进行数据列的筛选 |

* **在员工表上实操条件查询**

    * 查询工资高于 9000 的员工信息，「员工信息」没指定列，代表所有列：

    ```sql
    SELECT * FROM t_emp WHERE salary > 9000;
    ```

    * 查询工资高于 20000 的员工的姓名、薪水和年薪，年薪就是月薪乘以 12：

    ```sql
    SELECT emp_name, salary, salary * 12 AS 年薪 FROM t_emp WHERE salary > 20000;
    ```

    * 查询工资高于 8000 且性别为女的员工信息，「且」用 `AND`：

    ```sql
    SELECT * FROM t_emp WHERE salary > 8000 AND gender = '女';
    ```

    * 运算也可以出现在 `WHERE` 后面，先算出数再跟阈值比较；奖金比例可能为空，要用 `IFNULL` 兜成 0，否则整个条件都是空：

    ```sql
    SELECT * FROM t_emp WHERE salary + IFNULL(commission_pct, 0) * salary > 20000;
    SELECT * FROM t_emp WHERE salary - IFNULL(commission_pct, 0) * salary < 8000;
    ```

    * 用取模判断奇偶：取模 2 等于 0 就是偶数，查工资金额、工资编号是偶数的员工：

    ```sql
    SELECT * FROM t_emp WHERE emp_id % 2 = 0;
    ```

## 算术运算符

* **运算符清单**

    * 算术运算符可以将列或者两个值进行数学值的运算，常见的有加、减、乘、除、取模。

    | 运算 | 写法 | 说明 |
    | --- | --- | --- |
    | 加 | `+` | |
    | 减 | `-` | |
    | 乘 | `*` | |
    | 除 | `/` | 浮点除，会计算出小数点后边的几位 |
    | 除 | `DIV` | 整数除，自动丢掉小数部分，保留除后的整数部分 |
    | 取模 | `%` | |
    | 取模 | `MOD(被除数, 除数)` | |

    * 取模提供两种写法：百分号 `%` 和 `MOD`，两者都是标准运算符，作用完全一样，喜欢哪个选哪个。

    * 除也提供两种写法：斜杠 `/` 是浮点除，会算出小数点后边的几位；`DIV` 是整数除，会自动去掉小数部分，只保留除后的整数部分。

* **可以出现的两个位置**

    * > **结论**：运算符可以出现在 `SELECT` 的列位置，也可以出现在 `WHERE` 条件后边，对条件后边的列或值先运算再比较，两个位置都可以出现。

    * 出现在列位置时可以把运算结果连同别名一起展示，比如姓名、月薪、奖金、月总收入：

    ```sql
    SELECT
        emp_name AS 姓名,
        salary 月薪,
        salary * IFNULL(commission_pct, 0) AS 奖金,
        salary + (salary * IFNULL(commission_pct, 0)) AS 月总收入
    FROM t_emp;
    ```

* **运算结果**

    | 表达式 | 结果 |
    | --- | --- |
    | `100 + 0` | 100 |
    | `100 + 50` | 150 |
    | `100 + 50 - 30` | 120 |
    | `100 + 35.5` | 135.5 |
    | `3 * 5` | 15 |
    | `3 * 5.0` | 15.0 |
    | `3 / 5` | 0.6 |
    | `100 / 0` | `NULL` |
    | `5 DIV 2` | 2 |
    | `-5 DIV 2` | -2 |
    | `100 / (1 - 1)` | `NULL` |
    | `5 % 2` | 1 |
    | `MOD(5, 2)` | 1 |
    | `-5 % 2` | -1 |

    * 优先级跟其他语言一致，乘除高于加减；想提升优先级用括号包裹，括号优先级第一。

    * 运算中有浮点类型，结果就是浮点类型；参数都是整数类型，结果就是整数类型——`100 + 35.5` 得 135.5，`3 * 5` 得 15 而 `3 * 5.0` 得 15.0。

    * > **易错点**：除以 0 不抛异常，返回值是 `NULL`。`100 / 0` 和 `100 / (1 - 1)` 都是 `NULL`，不要按其他语言的习惯以为会报除零异常。

* **非表查询形式演示运算符**

    * 不涉及表，直接用 `SELECT` 加运算符来算，结果就出现在虚拟表里：

    ```sql
    SELECT 3 / 5, 5 DIV 2, 5 % 2, MOD(5, 2);
    ```

## NULL 运算与 IFNULL

* **空值参与运算的规则**

    * > **结论**：在 SQL 语句中，`NULL` 跟任何值做任何运算，结果都是 `NULL`。

    * 表中有些员工的奖金比例是 `NULL`，他们的奖金计算结果、总收入计算结果都会是空。

    * 原因是空跟任何运算都空：奖金占比为空时，工资乘以奖金占比等于空；薪水加空也等于空。

* **用 IFNULL 给空值兜一个默认值**

    * > **定义**：`IFNULL(列名, 默认值)`，第一个参数写列名，第二个参数写为空时给予的默认值。

    ```sql
    IFNULL(列名, 默认值)
    ```

    * 默认值完全由自己定：公司规定没指定奖金比例的都按 0.05 算，就写 `IFNULL(commission_pct, 0.05)`；年终奖没写的一律 1000，就写 `IFNULL(年终奖, 1000)`。

    * 奖金占比为空时给 0，它就会跟 0 运算得到 0，不会出现空，0 加月薪也就等于总薪资了：

    ```sql
    SELECT
        emp_name AS 姓名,
        salary AS 月薪,
        salary * IFNULL(commission_pct, 0) AS 奖金,
        salary + (salary * IFNULL(commission_pct, 0)) AS 月总收入
    FROM t_emp;
    ```

    * 月薪一定不为空就不用管，只需要把可能为 `NULL` 的奖金比例括起来。
