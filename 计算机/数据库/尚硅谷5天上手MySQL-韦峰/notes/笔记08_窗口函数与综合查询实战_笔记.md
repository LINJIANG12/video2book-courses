# 窗口函数与综合查询实战

## 窗口函数解决的问题

### 窗口函数与多行函数

* **窗口函数（Window Function）**

    * > **定义**：允许在结果集上执行聚合、分析、排序等操作的同时不改变结果行数的函数。

    * 窗口函数不是 MySQL 专有的，其他数据库中很多都支持，只不过 MySQL 一直到 8 以后才支持。

    * 传统多行函数会把多行直接压成一行，聚合这类多行函数只能单独使用，没办法跟正常要查的列混在一起。

    * 一旦用了 `AVG()` 还想查其他列，被查的列只能是分组列或聚合函数本身，放不了多个普通列。

    * 窗口函数不会把所有数据压缩成一行，而是把多行函数算出的结果分散到各个单行里去体现。

    * 它自己不改变数据的粒度，只是一层包装和加工。

* **多行到一行的两种结果**

    ```text
      聚合函数：多行 → 一行
        10 行明细 ──AVG(price)──▶ 1 个值
        还想同时查 id、name、price？不行，只能 GROUP BY 之后取分组列

      窗口函数：多行 → 每行都挂一份
        10 行明细 ──AVG(price) OVER()──▶ 还是 10 行，每行后面挂着同一个平均值
        id、name、price 一条都不少，行数也一条不多
    ```

### 可加窗口的多行函数

* **可以额外应用窗口的多行函数**

    * 聚合函数：平均值、最大值这些。

    * 序号函数：获取数据的排列序号、第一名，假如有一张分数表要查考试分数排在第几名，最后能造出一个序号列。

    * 分布函数：判断你的分数在排名的位置是前百分之多少还是后百分之多少。

    * 前后函数：取当前行的前 $n$ 行或后 $n$ 行的数据。

    * 首尾函数：取第一行或者最后一行的数据。

### 窗口函数基础语法

* **基本写法**

    * > **定义**：`多行函数() OVER (PARTITION BY 列名 ORDER BY 列名 DESC/ASC)`

    * 先写一个多行函数，后面加一个 `OVER` 就可以了，只要加上这一段，多行函数就可以在单行中去显示。

    * 括号里现在是空的也行。

* **括号留空**

    * `OVER()` 什么都不写，含义是把这个值分散到多个行中。

    * 直接写 `OVER()` 对 `ROW_NUMBER()` 来说代表对整体数据排序，序号就是 1 到 10，跟 ID 是一样的。

    * > **易错点**：⚠️ `SELECT id, name, price, category, AVG(price) FROM goods;` 这样直接拼会报错，因为用了 `AVG()` 之后还想查其他列，被查的列只能是分组列或聚合函数本身。

### 分组统计与排序

* **整体平均价**

    * 需求：查询所有商品的编号、名称、价格、类别，以及整体的平均价格。

    * `AVG(price) OVER()` 的效果是整体算完之后，每一行都会体现它。

    ```sql
    SELECT id, name, price, category, AVG(price) OVER() FROM goods;
    ```

* **类别平均价**

    * 需求：查询商品编号、价格、类别，以及该商品所属类别对应的平均价格，而不是整体平均价格。

    * `PARTITION BY` 其实就是分组统计，它会按照当前商品对应的类别去分组。

    * 女装/女士精品这一组算出来是 121，户外用品那一组是 593。

    ```sql
    SELECT id, name, price, category, AVG(price) OVER(PARTITION BY category) FROM goods;
    ```

    ```text
      整体平均价：AVG(price) OVER ()
        id  name   price  category   平均价
         …    …      …     女装        121      ← 每行都挂同一个整体平均值
         …    …      …     户外        121

      类别平均价：AVG(price) OVER (PARTITION BY category)
        id  name   price  category   平均价
         …    …      …     女装        121      ← 女装这一组自己的平均
         …    …      …     户外        593      ← 户外这一组自己的平均
    ```

* **子句分工**

    * `ORDER BY` 很好理解，想让结果按类别的价钱做倒序或正序排列，就在 `OVER` 后面加 `ORDER BY 列名 DESC` 或者 `ASC`。

    * > **易错点**：`PARTITION BY` 决定分组统计的口径，`ORDER BY` 决定组内怎么排；求类别平均价只需要前者，一旦再加 `ORDER BY price DESC`，序号函数、排名的含义就跟着变了。

### 序号函数

* **三个序号函数**

    * > **定义**：把条数按照某一指标进行排序、造出一个序号列。

    * `ROW_NUMBER()` 用于对数据进行排序，不管价格是否相同，它都是按照连续的序号排下来的。

    * `RANK()` 排序会跳过重复序号，如果有价格相同的，比如第二名并列有两个，后面跳过的就直接是第四名。

    * 这就像平时考试排名——第一名有一人，第二名有三人并列，那后面就没有第三名和第四名了，直接从第五名开始。

    * `DENSE_RANK()` 是连续的，即便有并列第二，后面紧跟着还是第三。

    | 函数 | 排序列出现并列时 | 并列第二时的排序结果 |
    | :--- | :--- | :--- |
    | `ROW_NUMBER()` | 不管价格是否相同，一律连续编号 | 1、2、3、4、5、6 |
    | `RANK()` | 并列共享名次，后续名次跳过 | 1、2、2、4 |
    | `DENSE_RANK()` | 并列共享名次，后续名次紧跟 | 1、2、2、3 |

    * 到底用哪个，就看你想不想占位：要严格的前 N 名就用 `ROW_NUMBER()`（并列也各占一个名额），要和第几名同分的名次就用 `RANK()` / `DENSE_RANK()`。

* **按分类内价格降序编号**

    * 需求：查询商品表中每个商品在分类下按价格降序的序号，也就是各自类别里从 1 排下去。

    * 基础查询是 `SELECT id, category, name, price FROM goods;`，先写 `ROW_NUMBER() OVER()` 得到整体序号 1 到 10。

    * 加上 `PARTITION BY category` 后按类别分组、排类别组里面的序号。

    * 再加 `ORDER BY price DESC` 从大到小，ID 为 6 的商品价格最高，就排在第 1。

    ```sql
    SELECT ROW_NUMBER() OVER(PARTITION BY category ORDER BY price DESC) AS num,
           id, category, name, price
    FROM goods;
    ```

* **分类内价格最高的三种商品**

    * 需求：查询每个商品分类下价格最高的三种商品。

    * 把分类内排序的查询当成一个中间表，最外层筛选出序号小于等于 3 即可。

    ```sql
    SELECT * FROM (
        SELECT ROW_NUMBER() OVER(PARTITION BY category ORDER BY price DESC) AS num,
               id, category, name, price
        FROM goods
    ) AS t
    WHERE num <= 3;
    ```

    * > **提示**：这个「先算出带序号的中间结果，再在外面筛 `num <= 3`」的套子后面还会再遇到一次，因为窗口函数算出来的那一列在当前这层查询的 `WHERE` 里用不了。

### 分布函数

* **百分分布函数 `PERCENT_RANK()`**

    * > **定义**：在范围内的百分比分布，值在 0 到 1 之间，值越小证明越靠前。

    * 计算公式为

    $$\frac{\text{rank} - 1}{\text{rows} - 1}$$

    * 四人分数 80、90、100、70 的例子：100 分排第一名，$(1 - 1) / (\text{rows} - 1) = 0$，是最靠前的；90 分排第二名，$(2 - 1) / (4 - 1) = 1/3 \approx 0.33$。

* **女装类别的排名与分布**

    * 需求：查询货物表中女装类别下商品的 RANK 值及百分比分布。

    * 第二高价格这一组总共 6 个数，$(2 - 1) / (6 - 1) = 1 / 5 = 0.2$；接着是 0.6、0.8、1。

    ```sql
    SELECT
        id, category, name, price,
        RANK()      OVER w AS rk,
        PERCENT_RANK() OVER w AS pr
    FROM goods
    WHERE category = '女装/女士精品'
    WINDOW w AS (PARTITION BY category ORDER BY price DESC);
    ```

    | 名次 rank | 公式 (rank-1)/(rows-1) | 百分比分布 |
    | :--- | :--- | :--- |
    | 1 | (1-1)/(6-1) | 0 |
    | 2 | (2-1)/(6-1) | 0.2 |
    | 4 | (4-1)/(6-1) | 0.6 |
    | 5 | (5-1)/(6-1) | 0.8 |
    | 6 | (6-1)/(6-1) | 1 |

    * > **注意**：0.2 之后直接跳到 0.6，不是 0.4——因为第二名有并列，`RANK()` 把名次跳到了 4。

    * 分子里的 `rank` 用的是 `RANK()` 的名次，所以 `PERCENT_RANK()` 和 `RANK()` 一定要成对使用。

### 窗口的复用

* **命名窗口的定义与引用**

    * 如果两个窗口函数的 `OVER` 里面的写法完全一样，写两遍太冗余，就可以复用。

    * 在查询最后面声明一个 `WINDOW w AS (PARTITION BY ... ORDER BY ...)`，然后在前面直接写 `OVER w` 就可以了。

    ```sql
    WINDOW w AS (PARTITION BY category ORDER BY price ASC);
    ```

### 前后函数与首尾函数

* **前后函数**

    * 顾名思义：返回当前行的前 $n$ 行数据，或者返回当前行的后 $n$ 行数据。

    * `LAG(price, 1)` 里第一个参数代表要获取哪个字段的值，第二个参数 1 代表前一个，写 2 就代表前两行；没有前一行就是 `NULL`。

    * `LEAD()` 与之对应，取后几行的值。

    * 需求是查询货物信息表中前一个商品价格与当前商品价格的差。

    ```sql
    SELECT
        id, category, name, price,
        LAG(price, 1) OVER w               AS pre_price,
        price - LAG(price, 1) OVER w       AS diff_price
    FROM goods
    WINDOW w AS (PARTITION BY category ORDER BY price ASC);
    ```

* **首尾函数**

    * `FIRST_VALUE()` 代表取第一行的值，`LAST_VALUE()` 代表取最后一行的值。

    * 按照价格排序查询第一个商品的价格信息，就是使用 `FIRST_VALUE()`。

## 综合查询实战的表结构

### 实战用的四张表

* **员工表 `employees`**

    * 字段为员工 ID、员工姓名（分成 `first_name` 和 `last_name` 两列）、所属部门 ID。

* **部门表 `departments`**

    * 字段为部门 ID、部门名称。

* **薪资表 `salaries`**

    * 字段为员工 ID（主外键）、员工对应的薪水。

* **经理表 `managers`**

    * 字段为经理 ID、部门 ID，代表这个部门的经理是谁。

### 表间关系

* **四表关系图**

    ```text
      employees                          departments
      ├ employee_id  员工 ID               ├ department_id    部门 ID
      ├ first_name                          └ department_name  部门名称
      ├ last_name
      └ department_id ──────────────────────────────┐
            │                                        │ department_id
            │ employee_id                           │
            ▼                                        ▼
      salaries                            managers
      └ salary  薪水                       ├ manager_id     经理 ID
                                              └ department_id 部门 ID
                                                    │
                                                    └─► manager_id 回到 employees
                                                       查这个经理本人的姓名
    ```

* **经理 ID 的真实含义**

    * > **结论**：`managers.manager_id` 看起来是经理 ID，但它本质上是经理这个人的员工 ID。

    * 所以经理的姓名不在 managers 表里，得拿它回到 employees 表去拼。

    * 一号部门的经理是 id=1，这个 1 同时也是经理的员工 ID，也就是员工表里编号为 1 的那个人，他的 `first_name` 和 `last_name` 合到一起就是一号部门经理的名字。

## 综合查询实战的前五题

### 每个部门的平均工资

* **每部门的平均工资**

    * 需求是显示部门信息以及部门的平均工资。

    * 只有员工才有薪水，所谓部门的平均薪资实际上是员工按部门分组后的平均薪资，所以数据来自 employees 和 salaries 两张表。

    * 两个语法要点：要用多表连接查询，把员工表作为逻辑主表；要算部门的平均工资就得再加分组查询，而分组查询只能查分组字段和聚合函数。

    ```sql
    SELECT
        e.department_id,
        AVG(s.salary) AS avg_salary
    FROM employees e
    LEFT JOIN salaries s ON e.employee_id = s.employee_id
    GROUP BY e.department_id;
    ```

    * 如果还想要部门的名称，就再 `LEFT JOIN` 一次部门表，并把分组字段换成 `d.department_name`。

    ```sql
    SELECT
        d.department_name,
        AVG(s.salary) AS avg_salary
    FROM employees e
    LEFT JOIN salaries s ON e.employee_id = s.employee_id
    LEFT JOIN departments d ON e.department_id = d.department_id
    GROUP BY d.department_name;
    ```

    * 由于用的是左外连接，没有分配部门的员工对应的平均薪资也能统计出来。

### 每个部门的经理姓名与部门人数

* **部门经理姓名与部门人数**

    * 需求是查出每个部门的经理的姓名，以及他管理的部门的员工的数量。

    * 一条很好用的经验：只要需求里出现「每」这个字，一般都会涉及分组，因为以什么为单位它就「每」。

    * 连接路线是三张表联查：拿部门表去关联经理表，再拿经理表的 `manager_id` 去关联员工表的员工 ID，最后再拿员工表连接一遍。

    ```sql
    SELECT *
    FROM departments d
    LEFT JOIN managers m ON d.department_id = m.department_id
    LEFT JOIN employees e1 ON e1.employee_id = m.manager_id
    LEFT JOIN employees e2 ON e2.department_id = d.department_id;
    ```

    * `managers` 只用了一次，但 `employees` 用了两次——`e1` 是当「经理」用的，`e2` 是当「普通员工」用的；同一张表在一个查询里可以起多个别名，各司其职。

    * 经理的名字由 `first_name` 和 `last_name` 两列组成，用字符函数 `CONCAT` 把两个字符串拼到一起，`COUNT(1)` 就是一个部门的人数。

    ```sql
    SELECT
        d.department_name,
        CONCAT(e1.first_name, e1.last_name) AS manager_name,
        COUNT(1)                            AS num
    FROM departments d
    LEFT JOIN managers  m  ON d.department_id = m.department_id
    LEFT JOIN employees e1 ON e1.employee_id = m.manager_id
    LEFT JOIN employees e2 ON e2.department_id = d.department_id
    GROUP BY d.department_name, CONCAT(e1.first_name, e1.last_name);
    ```

    * > **易错点**：⚠️ 拼名字时 `CONCAT` 的两个参数都写成 `e1.first_name`，等于把每个员工自己的名字拼了两遍，导致同一个部门的经理名字都不一样。改回 `first_name`、`last_name` 之后，一号部门 3 个，二号部门 2 个，就对上了。

    * 名字一错分组就跟着错，因为分组是按这个表达式来的；这个 bug 特别隐蔽，因为 SQL 不会报错，只会给你一个「看起来挺像那么回事」的错误数字。

    * 只 `GROUP BY d.department_name` 会报错说 `manager_name` 不能用：一旦分组，SELECT 里就只能查分组字段和聚合函数；这两个值虽然数值上完全相同，只要想在结果里 `SELECT` 它们，就必须两个都写进 `GROUP BY`，哪怕写两遍是多余的。

### 没有分配部门的员工数量

* **没有分配部门的员工数量**

    * 需求是罗列出没有分配部门的员工数量，本质上就是一个 `NULL` 判断，单表查询直接写。

    ```sql
    SELECT COUNT(*)
    FROM employees
    WHERE department_id IS NULL;
    ```

    * > **易错点**：空值不能用等于号判断，`NULL = NULL` 的结果是 `UNKNOWN` 而不是 `TRUE`，要写 `IS NULL`。

### 每个部门的员工数量与平均工资

* **每部门的员工数量与平均工资**

    * 需求是查出每个部门员工的数量以及该部门的平均工资。

    * 员工表里有部门能查人数但没有工资，所以要拿员工表关联一下工资表，关联完再做一个聚合函数。

    * 一分组就只能查分组字段 `department_id` 和聚合函数，所以要查的东西只能往 `AVG(s.salary)`、`COUNT(1)` 里塞。

    ```sql
    SELECT
        e.department_id,
        AVG(s.salary) AS avg_salary,
        COUNT(1)      AS num
    FROM employees e
    LEFT JOIN salaries s ON e.employee_id = s.employee_id
    GROUP BY e.department_id;
    ```

### 每个员工的姓名与薪资等级

* **员工姓名与薪资等级**

    * 需求是查询每个员工的姓名以及他的薪资等级，条件是低于平均工资的是低档，高于平均工资的是高档。

    * 要查的列是员工 ID、姓名（`first_name` + `last_name`）、薪水 `s.salary`，以及用 `CASE WHEN` 算出的薪水等级。

    * 平均薪水是聚合函数，按理说只能单独使用；想在每条记录里都拿到聚合函数，还得靠最后讲的窗口函数，这里需要窗口函数加上流程控制。

    * 虽然这里既没有分组也没有 `ORDER BY`，但也必须加 `OVER()`，否则用不了。

    ```sql
    SELECT
        e.employee_id,
        CONCAT(e.first_name, e.last_name) AS name,
        s.salary,
        CASE
            WHEN s.salary < AVG(s.salary) OVER() THEN '低档'
            ELSE '高档'
        END AS salary_level
    FROM employees e
    LEFT JOIN salaries s ON e.employee_id = s.employee_id;
    ```

    * `CASE` 有两种写法，一种是在 `WHEN` 里面直接带条件，一种是先写一列再比；这里用的是前者，剩下的不用再写 `THEN`，用 `ELSE` 兜底就行。

    * 如果把 `CASE` 整体当一个值用，后面就不用写列名；如果想让它作为结果里的一列，就在 `END` 后面 `AS` 一个列名，这里叫 `salary_level`。

    * > **注意**：用 `ELSE` 兜底，工资正好等于平均值的人也会被算进「高档」这一档；业务上要把相等的情况单独拎出来，就把 `ELSE` 换成一个显式的 `WHEN s.salary > 平均值`，剩下的再兜底。

    * > **易错点**：`CASE` 表达式后面要跟一个逗号，漏了逗号会直接报语法错，错误信息就在 `case` 附近。

## 综合查询实战的后五题

### 薪资排名前十的员工

* **薪资排名前十的员工**

    * 需求是查出薪资排名前十的员工信息，这是基本连表查询，员工表和薪资表，因为员工表里没有薪水。

    * 排前十就要按薪水的倒序 `DESC` 排序，最后拿前十个，用 `LIMIT` 去切割。

    ```sql
    SELECT *
    FROM employees e
    LEFT JOIN salaries s ON e.employee_id = s.employee_id
    ORDER BY s.salary DESC
    LIMIT 10;
    ```

    * 写完 `JOIN` 以后，后边该有的高级处理还是得有：排序写 `ORDER BY`，取前十个写 `LIMIT 10`。

    * 如果只想拿前三名，就把 `LIMIT 10` 改成 `LIMIT 3`；如果想拿薪资第二多的，那就 `LIMIT 1, 1`——跳过 1 个，再取 1 个。

    * 虽然数据一共没十条，语法是完全正确的。

### 至少有两名员工的部门

* **至少有两名员工的部门**

    * 需求是查出至少有两名员工的部门，也就是按部门分组后这个部门的员工数量要不少于 2。

    * 条件放 `HAVING`：`ON` 里一般放主表与外键表的连接条件，`WHERE` 是分组前的条件，`HAVING` 紧跟着 `GROUP BY` 做分组后的条件。

    * 分组以后才知道哪个部门有几名员工，所以这显然是分组后条件。

    * `num` 不用再写一遍聚合表达式，它可以在 `HAVING` 里直接复用。

    ```sql
    SELECT
        e.department_id,
        COUNT(1) AS num
    FROM employees e
    GROUP BY e.department_id
    HAVING num >= 2;
    ```

    * > **提示**：`WHERE` 和 `HAVING` 的本质区别是执行的时机——`WHERE` 是拿到原始行的时候就过滤掉，`HAVING` 是分组、把每组压成一行之后再判断。

    * 凡是需要先聚合才知道结果的条件（「数量大于 N」「平均工资低于 X」），就只能放 `HAVING`。

### 排除经理后的部门平均薪资

* **排除经理后的部门平均薪资**

    * 需求是查出每个部门的平均薪资，但要排除经理。

    * 「排除经理」明显是分组前条件，就是在分组之前把经理排除掉，再分组、再算平均，所以在前面加 `WHERE`。

    * 判定方式是员工的 ID 不能等于经理的 ID，经理是 1 就不能等于 1，经理是 2 就不能等于 2。

    * 经理可不止一个——三个部门就有三个经理，等于多值用 `IN`，不等于多值用 `NOT IN`。

    * 经理的编号从 managers 表取，它的 `manager_id` 既是经理的编号也是员工的编号，所以要套一个子查询。

    ```sql
    SELECT
        e.department_id,
        AVG(s.salary) AS avg_salary
    FROM employees e
    LEFT JOIN salaries s ON e.employee_id = s.employee_id
    WHERE e.employee_id NOT IN (SELECT manager_id FROM managers)
    GROUP BY e.department_id;
    ```

    * `SELECT manager_id FROM managers` 单独执行一下就是所有经理的员工编号，连完之后排除掉再分组，查出来的就是每个部门去掉经理之后的平均工资。

### 部门内部的工资排名

* **部门内部的工资排名**

    * 需求是查出每个部门的姓名、薪水以及该部门内部的工资排名。

    * 排名是多行函数，得配合窗口函数才能用；又查部门、又查薪水、又要查它的排名，直接写肯定查不出来。

    * `OVER` 后面什么都不加的话，排的是整体排名；要的是部门内部的排名，所以要 `PARTITION BY` 部门 ID，再按薪水 `ORDER BY` 从大到小。

    ```sql
    SELECT
        e.first_name,
        s.salary,
        e.department_id,
        RANK() OVER (PARTITION BY e.department_id ORDER BY s.salary DESC) AS num
    FROM employees e
    LEFT JOIN salaries s ON e.employee_id = s.employee_id;
    ```

    * 这套表里员工名是分成 `first_name`、`last_name` 两列的，根本没有一个叫 `name` 的列；老外这套表就是这样，直接取 `first_name`，不做整合，不影响排名。

    * 执行结果是一号部门 1、1、2、3，薪水从高到低；二号部门那个是 1，三号部门那个也是 1。

    * > **结论**：窗口函数的排序要分成两层看——`PARTITION BY` 决定「在谁的范围内」排，`ORDER BY` 决定「按什么」排，两个一起给才是完整的排名语义。

### 部门里薪水最低的员工

* **部门里薪水最低的员工**

    * 需求是查出每个部门薪水最低的员工的工资，这个排名是正序排名，正序的第 1 名就是薪水最低的那个。

    * 谁是 1 谁就是最低的，但直接写 `WHERE num = 1` 会报错说没有这个列。

    * 正确做法是把这个结果括起来当成一个临时表，外层这一回 `FROM` 找得到它就能引用了。

    ```sql
    SELECT *
    FROM (
        SELECT
            e.first_name,
            s.salary,
            e.department_id,
            RANK() OVER (PARTITION BY e.department_id ORDER BY s.salary ASC) AS num
        FROM employees e
        LEFT JOIN salaries s ON e.employee_id = s.employee_id
    ) AS tmp
    WHERE tmp.num = 1;
    ```

    * > **结论**：直接查的时候，这个查询里产生的列在当前这层没法用；套一层之后里面先把结果算完、赋给临时表 `tmp`，外层 `from` 找得到 `tmp`，而 `from` 的执行顺序在 `where` 之前，所以外层的 `WHERE` 就能用里边的列了。

    * 查「每个分类下价格最高的三种商品」用的是同一个套路，都是把带窗口函数的结果当成一张临时表，再在外层过滤。

## 条件子句与执行顺序

### ON、WHERE、HAVING

* **三种条件子句的分工**

    * `ON` 里一般放主表与外键表的连接条件。

    * `WHERE` 是分组前的条件，拿到原始行的时候就过滤掉。

    * `HAVING` 紧跟着 `GROUP BY`，做分组后的条件，把每组压成一行之后再判断。

* **空值判断**

    * 空值不能用等于号判断，`NULL = NULL` 的结果是 `UNKNOWN` 而不是 `TRUE`，必须写 `IS NULL`。

### 分组对 SELECT 的限制

* **分组后的可查列**

    * 一旦分组，SELECT 里就只能查分组字段和聚合函数。

    * 分组字段只要想在结果里 `SELECT` 它，就必须写进 `GROUP BY`，哪怕写两遍是多余的也得写。

    * 用 `COUNT(1)` 统计人数时，聚合表达式可以在 `HAVING` 里用别名直接复用。

### 关键字执行顺序

* **执行顺序与窗口结果列**

    * 逻辑上是从 `FROM` 开始，紧跟着 `WHERE`，最后才是 `SELECT`。

    * 窗口函数算出来的那一列是在 `SELECT` 这个阶段才产生的，所以在同层的 `WHERE` 里根本用不到它。

    * 把带窗口函数的结果括成子查询当作临时表后，外层 `FROM` 先于 `WHERE` 执行，外层 `WHERE` 就能引用里边的列。

    * `CASE` 表达式后面要跟一个逗号，漏了逗号会直接报语法错。
