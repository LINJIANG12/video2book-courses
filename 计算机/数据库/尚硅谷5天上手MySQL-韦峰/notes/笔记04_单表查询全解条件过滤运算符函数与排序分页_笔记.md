# 单表查询全解：条件过滤、运算符、函数与排序分页

## 比较运算符与隐式类型转换

### 结果取值与真假口径

* **比较运算符（comparison operator）**

    * > **定义**：拿一个表达式的值跟另一个值比大小，结果只可能是 `1`、`0`、`NULL` 三种；`1` 代表 TRUE，`0` 代表 FALSE，`NULL` 在数据库看来也是 FALSE 的含义。
    * 符号分四类：大小比较 `>` `>=` `<` `<=`；等于 `=`；不等于 `<>` / `!=`；范围与模糊 `BETWEEN AND`、`IN`、`LIKE`，以及各自的 `NOT` 形式。
    * `<>` 是标准写法；`!=` 是 MySQL 迎合其他语言提供的方言，MySQL 里两者都能用，推荐 `<>`。
    * `=` 只有一个等号，不是两个。
    * 空值判断固定用 `IS NULL`（为空）和 `IS NOT NULL`（不为空）。

* **隐式类型转换（implicit type conversion）**

    * > **定义**：比较时如果两边类型不一样，MySQL 会把字符串自动转成数值再来比。
    * 所以 `eid = 1` 与 `eid = '1'` 结果相同，字符串 `'1'` 等于数值 `1`；`SELECT '0' = 0`、`SELECT '0.1' = 0.01` 都返回 1。
    * 真正要小心的是**两边都是字符串**的时候：此时不转换，按字符串本身比。`SELECT '0.1' <> 0.1` 返回 0，因为 `'0.1'` 被转成数值 `0.1` 后两边相等；`SELECT '0.1' <> '0.01'` 返回 1，按字符串比确实不等。
    * > **提示**：不是"不写就不用管"，而是"不用你先手动转"。

### 空值判断的三种写法

* **安全等于号 `<=>`**

    * > **定义**：写法跟 `=` 几乎一样，但能比较 NULL；`SELECT NULL <=> NULL` 返回 1，`SELECT 1 <=> NULL` 返回 0。
    * 它是 MySQL 方言，标准关系数据库未必支持，因此不推荐作为首选。

* **普通等号 `=` 判不了空**

    * `SELECT NULL = NULL` 与 `SELECT 1 = NULL` 都返回 NULL，数据库里按 FALSE 看。
    * 一个等于号不能做空比较，所以 `SELECT * FROM t_emp WHERE comm = NULL;` 查不出任何记录。

* **IS NULL / IS NOT NULL**

    * 记不住安全等于就记这一条：它是"普通话"，任何标准关系数据库都认。
    * 查有奖金写 `WHERE comm IS NOT NULL`，查没有奖金写 `WHERE comm IS NULL`；`WHERE comm <=> NULL` 也能查出同一批人。

    * > **易错点**：⚠️ 想判空必须换成 `IS NULL` / `IS NOT NULL`，用等号只会得到空结果集。

### 不等于、区间与范围

* **不等于 `<>` / `!=`**

    * 除不转数值外规则与等于号一致：两边都是字符串按字符串比，只要有一边是数值，字符串就转成数值再比。
    * > **易错点**：写 SQL 不能自行把条件翻译成"反对立面"。查"不是男的"要老老实实写 `WHERE gender <> '男'`，不能因为觉得男女互斥就改写成 `gender = '女'`——万一表里存了第三种值就漏了。

* **区间 `BETWEEN AND` / `NOT BETWEEN AND`**

    * > **定义**：判断值是否落在两值构成的**闭区间**内，左右两端都取到。
    * `SELECT 2 BETWEEN 2 AND 3` 返回 1，两边都能取到；`SELECT 1 BETWEEN 2 AND 3` 返回 0。
    * 前面放小值，后面放大值；`SELECT 2 BETWEEN 3 AND 1` 返回 0，等于给了一个空区间。
    * 字符串会转成 ASCII 编码比，`SELECT 'b' BETWEEN 'a' AND 'c'` 返回 1。
    * 不在区间就把 `NOT` 加在前面：`WHERE birthday NOT BETWEEN '1990-01-01' AND '2000-01-01'`。

* **范围 `IN` / `NOT IN`**

    * > **定义**：判断值是否在给定的若干个值里，多个值用逗号隔开，任意一个命中即成立。
    * 等价于用一串 `OR` 连起来：`IN (x, y, z)` 的效果等于 `k = x OR k = y OR k = z`。
    * `NOT IN` 表示不在这些值里，一个都不许命中。
    * 与 `BETWEEN` 的差别：`BETWEEN 1 AND 5` 指 1 到 5 之间的所有值，`IN (1, 5)` 只指 1 或者 5 这两个值。
    * 查多地点时用逗号隔开而不是写"或"：`WHERE work_place IN ('北京', '上海', '深圳')`。

### 模糊匹配与通配符

* **模糊查询 `LIKE` / `NOT LIKE`**

    * > **定义**：只知道自己要匹配的一部分信息时用它，典型场景是查姓张的学员、查手机号 138 开头的人。
    * 前面正常写列名，后面写"你知道的部分"：`k LIKE '赵%'` 找第一个字是赵的；`k LIKE '_伟'` 表示第一位任意、第二位是伟且总共就两位；`k LIKE '_伟%'` 则后面几位有几位算几位，也可以一个都没有。

* **通配符**

    * 百分号 `%`：匹配任意多个字符，$1$ 到 $n$ 个都算。
    * 下划线 `_`：只匹配任意**一个**字符。`SELECT 'aaa' LIKE '_'` 返回 0，`SELECT 'aaa' LIKE '___'` 返回 1。
    * > **易错点**：下划线是"随便一个"，普通字符是"就必须是它"。`SELECT 'abc' LIKE '_a%'` 返回 0，因为第二位写死的 `a` 位置上实际是 `b`；`SELECT 'abc' LIKE 'a__'` 返回 1。
    * 手机号 11 位、前 3 位固定后 8 位不定时，`tel LIKE '138________'` 与 `tel LIKE '138%'` 等价，写一个百分号更省事。
    * 查结尾就把百分号放前面：`WHERE email LIKE '%@atguigu.com'`、`WHERE email LIKE '%tom.com'`。

### 成组比较

* **`IN` 的成组比较**

    * 前面写几个值就用几个括号括起来成一组，`IN` 里面每一组也各自加括号，可以做"多列同时相等"的判断，如查"工资和奖金都相同"的员工记录。
    * 它是**按位置一对一对上**的：`SELECT (3, 4) IN ((1, 2), (3, 4))` 返回 1，`SELECT (3, 4) IN ((1, 2), (3, 5))` 返回 0，`SELECT (3, 4) IN ((4, 3), (3, 4))` 返回 0——顺序换了就对不上。

* **整行括起来比较**

    * `(a, b) = (x, y)` 等价于 `a = x AND b = y`；`(a, b) <=> (x, y)` 等价于 `a <=> x AND b <=> y`。
    * `(a, b) <> (x, y)` 等价于 `a <> x OR b <> y`。
    * > **提示**：用等号时中间相当于"且"，用不等于时中间其实是"或"。记不牢就直接用 `AND`、`OR` 连起来。

## 逻辑运算符与优先级

### 真值口径与四种运算符

* **真假值口径**

    * > **定义**：在数据库里只要**非空且非 0** 的值，结果就是 TRUE；`0` 或者空当作 FALSE。数据库中 TRUE 的表达值是 1，FALSE 的表达值是 0。
    * 因此 `NOT 10` 得 0（10 按 TRUE 算，取反成 FALSE），`NOT 0` 得 1（0 是 FALSE，取反成 TRUE）。

| 运算符 | 方言写法 | 含义 |
| :--- | :---: | :--- |
| `AND` | `&&` | 逻辑且，两边都为 TRUE 结果才为 TRUE |
| `OR` | `\|\|` | 逻辑或，任意一方为 TRUE 结果就为 TRUE |
| `NOT` | `!` | 反转，把对应条件的结果取反 |
| `XOR` | — | 异或，双方一为 TRUE、一为 FALSE 时结果才为 TRUE |

* **`XOR` 的顺序运算**

    * 多个条件连起来时按从左到右顺序算，不是把所有条件一次性两两配对。
    * `1 XOR 1 XOR 1` 结果是 1：先算 `1 XOR 1` 得 0，再拿 0 异或 1 得 1。

* **逻辑运算符的用途**

    * 真正写查询时，每个条件可以是一整个比较表达式，各算出的结果就是 TRUE 或 FALSE，最后再用 `AND`、`OR`、`NOT`、`XOR` 把它们连到一起。
    * 它的主要作用是把多个条件结果综合起来运算，最终生成**一个**结果。

### 条件组合与括号

* **基本组合**

    * 两个条件用"且"连：`WHERE salary > 5000 AND work_place LIKE '%北京%'`。
    * 两个条件用"或"连：`WHERE commission_pct IS NULL OR address IS NULL`。
    * 单条件的算术-比较-逻辑链：`WHERE eid % 2 = 0 AND address IS NOT NULL` 走的顺序是算术 → 比较 → 逻辑。

* **括号让条件先算**

    * `WHERE salary > 5000 AND (FIND_IN_SET('上海', work_place) = 1 OR FIND_IN_SET('北京', work_place) = 1)` 里，括号里先算出一个 TRUE 或 FALSE 的"或"结果，再拿它跟工资条件做"且"的运算。
    * > **提示**：括号是优先级最高的东西，是"让某些条件先算"的终极绝招。

* **求奇偶的固定套路**

    * 奇数就是取模 2 等于 1：`WHERE eid % 2 = 1`；偶数就是取模 2 等于 0。

### 优先级阶梯

* **两条基本规则**

    * 优先级相同，从左到右依次运算；优先级不同，先算优先级高的。
    * 分优先级是为了解决歧义，$5 + 5 \times 5$ 结果是 30 而不是 50，因为先算乘再算加。

* **从高到低的阶梯**

    * ```text
      优先级从高到低
        │
        │  ①  括号  ( )          最高。括号能改变任何优先级，终极绝招
        │  ②  取反 / 取非  NOT、负号(−)
        │  ③  乘、除、取模   *  /  %
        │  ④  加、减         +  −
        │  ⑤  比较运算符      =  <>  >  <  BETWEEN  IN  LIKE ……
        │  ⑥  逻辑运算符      AND  OR  XOR（连接多个条件的那种）  最低
        │
      ```

* **两处最易看反的地方**

    * 第 ② 条说的是**取反、取非**（比如 `1 + 1` 前面取个非），优先级高得离谱：`SELECT NOT 1 + 1;` 结果是 1，因为 `NOT` 先把 1 取反成 0，$0 + 1 = 1$。
    * 第 ⑥ 条说的是**把多个条件连起来**，必须等前面全算完才能动，所以最低。
    * 记不住就一律加括号；放到 `WHERE` 后面是完全一样的道理。

## 函数的分类与嵌套

### 单行函数与多行函数

* **单行函数（single-row function）**

    * > **定义**：对单行数据生效——查出一条数据，其中某个字段需要处理，就用它处理，结果放回这一行的结果里。
    * 常见成员有数值函数、字符函数、时间函数、流程控制函数、信息函数。
    * 例：查一条数据时顺带展示当前查询时间，用 `NOW()` 获取，结果落在单行结果里。

* **多行函数（aggregate function，聚合函数）**

    * > **定义**：作用范围是多行，所有符合条件的行一起做最终运算，最后只产出 1 个结果；单行拿不到这个结果。
    * 4 行进去 1 条出来，这是它和单行函数的分水岭。
    * 一般单独使用，或者配合分组使用。

* **划线标准**

    * 除了聚合函数，剩下的都是单行函数。

* **来源分类**

    * 内置函数：数据库提供好直接用，如 `IFNULL`、`FIND_IN_SET`。
    * 自定义函数：数据库也允许，但不是本课范围。
    * 函数本质是对某项功能的一个封装：输入参数，执行完毕返回一个结果。

    ```text
    SQL 里的函数
    ├─ 内置函数    IFNULL、FIND_IN_SET …… 拿来就用
    └─ 自定义函数  本课程不展开

    内置函数按生效范围再分两类
    ├─ 单行函数   数值 / 日期 / 时间 / 流程 / 信息 / 字符串 ……
    │             对查出来的每一行里的某个字段单独生效
    └─ 多行函数   聚合函数：平均数、最大数、最小数 ……
                  对所有符合条件的行一起统计，最后只产出 1 个结果
    ```

### 函数嵌套与直接验证

* **函数可以互相套用**

    * 跟其他语言里把函数套函数一个道理，完全合法。
    * 例：手上有个随机值想保留两位小数，套一层截取函数即可 `SELECT TRUNCATE(RAND(), 2);`，出来是 0.15 这类值。

* **单行函数不挂表就能验证**

    * 直接用 `SELECT` 写表达式，不挂表、不写查询列，一条 SQL 把多个函数的结果并排跑出来。
    * 例：`SELECT CHAR_LENGTH('abc'), CONCAT('%', '娃娃', '%'), FIND_IN_SET('aa', 'cc,dd,aa,bb,gg,aa');`

## 数值函数

### 取整与舍入

* **向上取整 `CEIL` / 向下取整 `FLOOR`**

    * > **定义**：`CEIL` 向上舍入，`FLOOR` 向下舍入，都是给浮点数返回一个整数。
    * `CEIL(2.3)` 得 3，`FLOOR(2.3)` 得 2，`FLOOR(-2.3)` 得 -3。
    * > **易错点**：⚠️ `CEIL(-32.3)` 得的是 **-32**，不是 -33。因为 `CEIL` 是往"正"的方向取整，不是把绝对值取整了再补个负号。
    * `FLOOR` 往下这一侧同理，取的是更小的那个数。

* **四舍五入 `ROUND` 与截取 `TRUNCATE`**

    * > **定义**：两者签名几乎一样，都是 `函数(x, y)`，`y` 代表保留几位小数，**唯一的区别是 `ROUND` 四舍五入、`TRUNCATE` 直接截取**。
    * `ROUND(2.3)` 得 2；`ROUND(2.36, 1)` 得 2.4；`TRUNCATE(2.36, 1)` 得 2.3。
    * `TRUNCATE` 不管后面小数位是什么，只截到指定的那一位，后面一概不往四舍五入上凑。
    * `ROUND` 还能在多行运算结果外面再套一层，抑制浮点失真，比如年龄列就靠它保留一位小数。

* **其他数值函数**

    * `ABS` 取绝对值，`SELECT ABS(-5)` 得 5。
    * 符号判断函数：传一个值进去，正值返回 1、负值返回 -1、零返回 0。
    * `PI` 取圆周率 3.1415926；`MOD` 取模，和关键字形式的写法是一回事。

### 其他数值函数

* **随机数 `RAND`**

    * > **定义**：取 0 到 1 之间的随机数，可以带一个参数。
    * > **提示**：这个参数是**种子**，不是"随机数上界"。同一个种子算出来的随机数序列完全相同，连续调用两次 `RAND(8)` 结果一模一样。
    * 典型用法是年会抽奖时给几个人填相同种子，让他们各自算出的随机数是同一个数，中奖概率自然一致——相当于把随机固定住了。
    * > **注意**：其他语言里随机数方法传 `x` 表示"生成 0 到 x 之间的随机数"，SQL 里这个 `x` 换了个身份，别搞混。

* **最小值与最大值**

    * 数值函数里有两个是用来在一堆值里挑最小值和最大值的，手上有多值时拿它们用。
    * 这两个函数的长文未给出函数名，只需记住用途。

## 字符函数

### 长度、拼接与截取

* **`CHAR_LENGTH` 与 `LENGTH`**

    * > **定义**：`CHAR_LENGTH` 返回字符数，`LENGTH` 返回这段字符**占的字节数**。
    * `SELECT CHAR_LENGTH('abc')` 得 3。
    * > **提示**：一个字符占几个字节跟字符集有关，所以这两个结果很可能对不上，别当成同一个函数用。

* **`CONCAT` 与 `SUBSTR`**

    * `CONCAT` 把多个字符串拼起来，做模糊查询时经常用到。
    * 前端传进来的往往只是匹配关键字本身、不带百分号，百分号得由后端拼：`CONCAT('%', '娃娃', '%')` 拼出 `%娃娃%`。
    * `SUBSTR` 做字符串截取：前面给字符串，`index` 是开始截取的下标，`len` 代表截取长度。

### 集合定位 FIND_IN_SET

* **`FIND_IN_SET(s1, s2)`**

    * > **定义**：去 `set` 这种数据中找有没有指定的数据，找到就返回它的下标。
    * 第二个参数 `s2` 是一段 `set` 格式的数据，书写时它就是一个字符串，各个值之间用逗号隔开。
    * 它找的是目标**处在逗号之间哪个位置**，下标**从 1 开始**，而且**只找到第一个就终止**。
    * `FIND_IN_SET('aa', 'cc,dd,aa,bb,gg,aa')` 返回 3；串末尾还藏着一个 `aa`，它压根不关心。

* **用在条件里判包含与不包含**

    * > **定义**：返回 1 代表这个值出现过，返回 0 代表没有。
    * 包含：`WHERE salary > 5000 AND FIND_IN_SET('北京', work_place) = 1`；不包含：`WHERE gender = '男' AND FIND_IN_SET('上海', work_place) = 0`。
    * > **提示**：这类列底层存的就是逗号串，`=` 在 `work_place = '北京'` 上能匹配"北京,上海"，但"上海,深圳"就不算北京了——这个人的确有一个工作地点在北京，所以等于号查不出来，得用 `FIND_IN_SET` 或 `LIKE '%北京%'`。

## 时间函数

### 取当前时间与时区

* **取"此刻"**

    * `CURRENT_DATE` 和 `CURDATE` 效果一样，返回 `date` 类型的当前年月日。
    * `CURRENT_TIME` 返回当前的时分秒。
    * `NOW` 和 `SYSDATE` 返回当前系统完整的年月日和时分秒。
    * 记忆要点：要完整年月日时分秒记一个 `NOW()`，要年月日记 `CURRENT_DATE()`，要时分秒记 `CURRENT_TIME()`。

* **UTC 系列**

    * > **定义**：UTC 是世界标准时间，**不考虑时区**。
    * 在东八区用 UTC 取出来的时间会比本地时间少 8 个小时；上面那几个会考虑当前系统所在时区，算出来就是当下时间。
    * 实际业务里尽量别用，了解原理即可。

### 时间要素提取

* **基本提取**

    * > **定义**：把一个时间拆开拿出某一段，命名基本就是英文原词，把时间往里一扔就取出来。
    * `YEAR` 提年、`MONTH` 提月、`DAY` 提月中的第几日，`DAYOFMONTH` 与 `DAY` 作用相同。
    * `WEEK` 算这个日期是一年中的第多少周；`DAYOFYEAR` 算一年中的第几天；其余还有提时、分、秒的。
    * 出生年份分组、统计某月份过生日都靠它：`YEAR(birthday)`、`MONTH(birthday) = MONTH(NOW())`。

* **星期两套编号**

    * > **定义**：`WEEKDAY` 与 `DAYOFWEEK` 都返回星期几，作用一样但取值不同。
    * `WEEKDAY` 的编号是 **0 是周一、6 是星期日**；周六落在 5。
    * `DAYOFWEEK` 的编号是 **1 是星期日、2 是星期一**一路排下去，7 就是星期六。
    * 这一堆里只有"星期几"存在两套编号，其他提取日期的方式结果都相同。

### 时间加减与间隔

* **日期加减**

    * > **定义**：`DATE_ADD` 与 `ADDDATE` 一对完成时间的加，`DATE_SUB` 与 `SUBDATE` 一对完成时间的减，参数结构完全一致。
    * 第一个参数是**锚点**，即基于哪个时间做加减；后面跟关键字 `INTERVAL`（固定写法，别写成别的）；再后面是**表达式**，可正可负；最后跟**时间单位**，如 `DAY`、`MONTH`、`YEAR`。
    * > **提示**：只记 `DATE_ADD` / `ADDDATE` 一个就够，减法靠负号。`ADDDATE(..., INTERVAL 5 DAY)` 是 5 天以后，`ADDDATE(..., INTERVAL -5 DAY)` 就是 5 天以前。
    * `SUBDATE(..., INTERVAL 1 MONTH)` 等价于加法写 -1。

* **时间点加减**

    * `ADDTIME` 拿秒数加时间：前一个参数给时间，后一个参数给秒数，正值是多少秒以后，负值是多少秒以前。`ADDTIME('10:10:10', 10)` 得 10:10:20，填 -10 得 10:10:00。
    * `SUBTIME` 跟它反着——填正的秒数是减，填负的秒数才是加。

* **两个时间点之间隔多久**

    * > **定义**：`DATEDIFF` 算两个**日期**之间隔了多少天，`TIMEDIFF` 算两个**时间**之间的间隔，结果是时、分、秒。
    * `DATEDIFF` 的顺序是大值放前面、小值放后面，`DATEDIFF(CURRENT_DATE(), '2024-11-11')` 结果是 **-205** 天。
    * 不确定两个时间谁大谁小时套一层绝对值函数。
    * `TIMEDIFF('12:00:00', '10:00:00')` 得 `02:00:00` 这种时分秒形式。
    * 这一类要记的其实就两个：一个负责加减，一个负责算天数。

### 时间格式化

* **`DATE_FORMAT` 与 `TIME_FORMAT`**

    * > **定义**：给定一个时间类型，按指定格式把它提取成对应的字符串，一个管日期一个管时分秒。
    * 参数结构一样：前边放时间，后边放 format 格式化字符串，想格式化成什么样就写什么样；作用跟 Java 里的 `SimpleDateFormat` 一样。
    * `DATE_FORMAT(NOW(), '%Y-%m-%d')` 出标准日期；`DATE_FORMAT(NOW(), '%Y年%m月%d日')` 出中文日期——中间不一定非写 `-`，你想让时间长什么样它就给你长什么样。

* **`STR_TO_DATE`**

    * > **定义**：把非标准的时间字符串转回标准的时间类型，方向跟上面两个正好相反。
    * 前端传进来的"2024年04月20日"在数据库里没法直接比较，得先变成 `2024-04-20`。
    * 后面那个格式串必须和原串**一模一样**，`STR_TO_DATE('2024年04月20日', '%Y年%m月%d日')` 里的"年""月""日"三个字要原样写上，数据库才知道哪儿是年、哪儿是月、哪儿是日。

* **格式占位符**

    * 跟 Java 不一样，这里不是 `yyyy-MM-dd` 这种写法。

    | 占位符 | 含义 |
    | :--- | :--- |
    | `%Y` | 四位的年 |
    | `%y` | 两位的年 |
    | `%M` | 英文的月份 |
    | `%m` | 两位的月，`01`、`02`、`03` |
    | `%d` | 两位的日 |
    | `%D` | 带序数后缀的日，一般不用这种 |
    | `%H` | 小时，24 小时制 |
    | `%h` | 小时，12 小时制 |
    | `%I` | 小时，12 小时制（大写） |
    | `%i` | 分，两位 |
    | `%s` / `%S` | 秒，两位，大小写都一样 |

    * 分为什么是小写 `i`：大写的 `I` 已经被 12 小时制的小时占用了。
    * 口诀：四位年大写 `%Y`、两位月小写 `%m`、两位日小写 `%d`、24 小时大写 `%H`、分小写 `%i`、秒 `%s` 或 `%S`。
    * > **提示**：想只取年月日有两条路——笨办法是用 `YEAR`、`MONTH`、`DAY` 逐个提取再 `CONCAT` 拼起来，太麻烦；直接 `DATE_FORMAT(NOW(), '%m-%d')` 一把梭，两边格式化成同一个形状再比即可。

## 流程控制函数

### IF 与 IFNULL

* **二选一 `IF(表达式, 值1, 值2)`**

    * > **定义**：第一个参数是一个表达式，返回结果只能是 true 或 false；为 true 取第一个值，为 false 取第二个值。
    * 例：`IF(gender = '男', 300, 500) AS 补助`。
    * 语法上 `IF` 里用的是**一个**等号，那是比较，不要写两个等号。
    * > **易错点**：⚠️ `IF` 只能处理 true / false **两个**结果。表里只有男和女时用 `IF` 没问题，性别分类更多的场景两个岔路口就不够用了。

* **空值兜底 `IFNULL(列名, 默认值)`**

    * > **定义**：第一个参数是一个列名，这一列的值为空时，就给第二个位置上的值。
    * 奖金比例列一部分人填了、一部分人没填，没填不代表真的没有奖金，可以用 `IFNULL(pct_bonus, 0.01)` 兜个底。
    * 更常见的用法是治空值参与运算：`salary * IFNULL(pct_bonus, 0)` 得到 `salary * pct_bonus`——因为空值跟其他数字做加减乘除，结果都是空。
    * > **提示**：建议单独去包指定的列而不是把整个算式包起来，这样更灵活——以后要改默认值（比如没奖金的人默认给 0.05）只改 `IFNULL` 里那一个数就行，**默认值给多少得根据业务去改**。
    * 底层数据是 `double`，可能失真，外面再套一层四舍五入函数截小数位。

* **两个函数的分工**

    * `IF` 专门处理两个条件的分叉，`IFNULL` 专门处理空值；条件不止两个时才需要 `CASE`。

### CASE 的两种语法

* **语法一：条件写在 `WHEN` 后面**

    ```sql
    CASE
      WHEN 表达式1 THEN 结果1
      WHEN 表达式2 THEN 结果2
      ELSE 默认结果
    END
    ```

    * `WHEN` 后面的表达式结果为 true 就返回 `THEN` 后面的值，`CASE` 到此结束。
    * 例：`CASE WHEN gender = '男' THEN 300 WHEN gender = '女' THEN 5000 ELSE 1 END AS 补助`。

* **语法二：把列名或表达式前置**

    ```sql
    CASE 列名或表达式
      WHEN 值1 THEN 结果1
      WHEN 值2 THEN 结果2
      ELSE 默认结果
    END
    ```

    * `CASE` 后面直接放 `gender`，`WHEN` 后面写值，默认**用等号去比较**，跟列名相等就走对应结果。
    * 这个位置放表达式也可以，那样 `WHEN` 后面写的就是 true / false；实际做的话都是把列名前置，"列名等于哪个值的时候我们该怎么办"最常见。

* **两种语法等效**

    * 同一个需求两种写法结果完全一样，只是把 `gender` 从每个 `WHEN` 里面提到 `CASE` 后头。
    * `CASE` 和 Java 里的 `switch-case` 一个脾气：只有当某一个 `WHEN` 满足以后就不会往下再走，分支的书写顺序要按业务优先级来。
    * > **易错点**：各分支条件必须互斥、从上到下依次判断。`WHEN num > 30 THEN '滞销'` 后面跟 `WHEN num > 10 AND num <= 30 THEN '正常'`，等于 30 的书被 `num <= 30` 拦住，归正常，不归滞销也不归畅销。

* **`END` 后面跟的是别名而不是 `CASE` 的语法**

    * 想把算出来的结果作为**新列**呈现，就加 `as` 给它起个列名，如 `END AS 补助金额`。
    * 拿它去参与别的运算就不写 `as`，因为只要能算出一个值就行，又不是要单独成列。
    * `UPDATE` 语句里 `SET 列名 = CASE ... END`，算出来的值直接赋给前面那个列名，后面不要再加 `as` 列名。

## 聚合函数

### 五个聚合函数

* **总览**

    * > **定义**：聚合函数作用于全部数据（或者分组数据）进行统计和计算，最终结果只有一条。
    * 单行函数作用到每一行、最终结果可能是多条；多行函数相当于开启上帝视角站在宏观角度统计，最终只有一条。

    | 函数 | 放什么 | 统计什么 | 对列的类型要求 |
    | :--- | :--- | :--- | :--- |
    | `AVG` | 列名 | 这一列的平均值 | 数值类型 |
    | `SUM` | 列名 | 这一列的数值和 | 数值类型 |
    | `MIN` | 列名 | 这一列的最小值 | 任意类型 |
    | `MAX` | 列名 | 这一列的最大值 | 任意类型 |
    | `COUNT` | 列名 / `*` / `1` | 出现次数 | 任意类型 |

* **类型要求**

    * `MIN` 和 `MAX` 要求的不是数值类型，任意类型都行：数字能统计最小最大，时间也可以；放字符串也能排，只是按当前编码格式的码表顺序排——但字符串的最小最大值一般没什么意义。
    * 实用中统计数字和时间是绝大多数情况。

* **生日与年龄方向相反**

    * > **易错点**：想求的是"年龄"，而年龄正好是生日大小的反面——**最大年龄的员工，其生日应该是最小的；最小年龄的员工，其生日是最大的**。
    * 按字面意思写 `MAX(birthday) AS 年龄最大员工的生日` 会得到 1995、`MIN(birthday)` 得到 1978，而 1978 才是年龄最大的。`MIN`/`MAX` 只比较**值**的大小，不理解"年龄"这个语义。

### COUNT 的两种参数

* **放列名**

    * 统计的是**这一列非空值出现的次数**，不是求和；某个值变成空，这个位置就不计数了。

* **放 `*` 或者 `1`**

    * 作用是统计所有行的次数，这一行算 1、那一行算 2；跟放星号的效果一样。
    * 理解方式是一行内只要有任意一列有值，就代表这一行是生效的。

* **两者的关系**

    * 这是"统计行数"和"统计列数"的区别，思路不一样。
    * 值有可能相等——假如每行都有值，`COUNT(salary)` 就等于 `COUNT(*)`；但**不保证一定相等**，某行有数据而该列为空时 `COUNT(salary)` 就比 `COUNT(*)` 少一。
    * 现场跑出来 `COUNT(*)` 和 `COUNT(1)` 都是 27，而 `COUNT(commission_pct)` 是 8，只有 8 个人有奖金。
    * 要统计总条数就用 `COUNT(*)` 或 `COUNT(1)`；要统计某一列出现的次数就用列名。

### 空值态度与嵌套禁令

* **碰到空值一律不处理**

    * `COUNT` 碰到空不计数；平均值、总工资、最小值、最大值碰到空也是同样态度——认为这个值不存在，既不算最大值，也不算最小值，也不单独列进平均值。
    * 求和与平均值都不算它。

* **聚合函数之间不能互相嵌套**

    * > **注意**：聚合函数不能互相嵌套，这是要记下的铁律。

## 分组查询

### 分组定义与可查项

* **分组是什么**

    * > **定义**：把数据行按照某一列或多列的值相同作为条件分成若干组。
    * 关键在于**分完组以后，统计的就不是单个人或单条数据了，而是组的数据**。

    ```text
       分组前：四条独立的员工数据，每一行都是"一个人"

   +----+------+----------+------+
   | id | name | birthday | 颜色 |
   +----+------+----------+------+
   |  1 | 张三 | 1980-... | 黄色 |
   |  2 | 李四 | 1984-... | 绿色 |
   |  3 | 王五 | 1980-... | 黄色 |
   |  4 | 赵六 | 1984-... | 绿色 |
   +----+------+----------+------+

        按 颜色 分组 之后：四条数据变成两组

   +-------------------+          +-------------------+
   | [ 黄色组: 1, 3 ]   |          | [ 绿色组: 2, 4 ]   |
   |  颜色 = 黄色       |          |  颜色 = 绿色       |
   |  人数 / 平均值 ... |          |  人数 / 平均值 ... |
   +-------------------+          +-------------------+
    ```

* **同组内特性列的值一定相同**

    * 分到一组就证明它们的特性列值一样，按性别分组就不可能把男性和女性分到同一组。
    * 由此推出分完组之后能查的只有两项：**分组列**（按哪列分组的就可以查哪列）**和聚合函数**。
    * 用到分组就记死一条：`SELECT` 后面**只能是分组字段和聚合函数**。其他列组内各不相同，没法统计。

* **分组列可以是多列**

    * 用逗号隔开，想按性别和工作地点同时分组就写 `gender, work_point`，分到一组的两个值一定都相同；写三列四列也行。
    * 需要按表达式分组时，先用函数把值抠出来再分：`GROUP BY YEAR(birthday)`；直接按 `birthday` 分组的话，1984 年 8 月 3 号和 1984 年 9 月 11 号不在一组，因为值不相同。

### 语法骨架与 WHERE 的位置

* **完整骨架**

    ```sql
    SELECT 分组列, 聚合函数
    FROM 表名
    [WHERE 条件]
    GROUP BY 分组列1, 分组列2, ...
    [HAVING 分组后条件];
    ```

* **`GROUP BY` 与 `WHERE` 平级**

    * 它不像比较符号必须跟在 `WHERE` 后面，可以单独存在；有 `WHERE` 条件就正常加，没有就不加。
    * 两者同时出现时，`GROUP BY` 一定要写在 `WHERE` 的后边。
    * 分组前的筛选用 `WHERE` 就够了：`FROM emp WHERE salary > 5000 GROUP BY gender` 跑出来是 13 和 12，比不筛选时的 14 和 13 各少一个。

* **`WHERE` 和 `HAVING` 都不是必须写的**

    * 没有筛选条件、也没有分组后限制时，两个都不写：`FROM emp GROUP BY gender` 就能查出男的一组 14 个人、女的一组 13 个人。
    * 分组后 `COUNT` 统计的是**每个小组内部的条数**，跟不分组时统计全部不一样。

### HAVING 与 WHERE 的分工

* **`HAVING` 只能跟在 `GROUP BY` 后面**

    * > **定义**：`HAVING` 是分组后的条件，`WHERE` 是分组前的条件；只有 `GROUP BY` 出现，`HAVING` 才可以出现。
    * "平均工资大于 5000"这个条件是分组之后才有的，所以只能由 `HAVING` 处理。
    * `WHERE` 则随时都能写，有没有 `GROUP BY` 都不影响。

* **`HAVING` 后面比的一般是聚合函数**

    * 它的比较位置一定是一个算出来的聚合函数值，再拿去做大于、小于、等于的比较。
    * 原因是对一个组做排除法只能拿这个组统计出来的数据去排除；"男性不参与"这种条件是分组**前**用 `WHERE` 查女性就完事了，犯不着先分再排。
    * `WHERE` 后面可以是任何比较——大于、小于、等于都行，有没有函数都能比较，任意参数都能比。

* **`HAVING` 可以复用 `SELECT` 里起的别名**

    * `AVG(salary) AS av` 之后直接写 `HAVING av > 5000` 能跑通，因为 `HAVING` 在分组之后才执行，而分组之前平均值已经算出来了，这个列已经存在。
    * 这算是个小优化，记不住就老老实实写 `HAVING AVG(salary) > 5000`，一样跑得通。

## 排序查询

### 语法与默认方向

* **排序的定义与作用**

    * > **定义**：按照某一个或者多个特性列对数据进行排序。
    * 排序不会影响结果的条数，它只是改变结果的顺序，一个都不会丢。

* **语法**

    ```sql
    SELECT 结果列
    FROM 表名
    [WHERE 条件]
    ORDER BY 排序列 [ASC | DESC],
             第二排序列 [ASC | DESC], ...;
    ```

* **方向与默认值**

    * `ASC` 是正序，从小到大；`DESC` 是倒序，从大到小。
    * `ASC` 是默认值，可以不写，`ORDER BY price` 就代表价格从小到大。
    * `ORDER BY` 写在 `WHERE` 后面，跟 `WHERE` 平级。

### 多列排序逐级生效

* **逐级生效规则**

    * 多列排序时默认只有当前一列相同时，第二列才会生效。
    * 第一列是现任，第二列是备胎（第一列相同了它才顶上），第三列是千斤顶（第一、二列都相同才生效），第四列要前三列都相同才生效，以此类推。
    * > **提示**：第二列生效时，只是在第一列相同值的那几行数据**内部**做位置调换，不改变整体；第三列也一样，只在第一、二列都相同的那些行里排。

* **实例**

    * 按工资倒序、工资相同按年龄正序：`ORDER BY salary DESC, birthday DESC`——年龄正序对应生日倒序。
    * 按库存降序、库存相同按类型升序：`ORDER BY num DESC, note ASC`；`ASC` 可以不写，默认就是升序。
    * 如果第一列没有相同的值，第二列根本没起作用，但规则本身就是这样，不用怀疑。

* **排序里的取反**

    * 时间小的时候年龄反而大，所以按年龄正序（从小到大）要写 `ORDER BY birthday DESC`，出来的结果才是年龄从小到大。
    * 找出版最早的一本书用 `ORDER BY pub_date LIMIT 1`，值越小代表越早。

## 切割与分页

### limit 的参数含义

* **`LIMIT 偏移量, 行数`**

    * > **定义**：第一个值叫**偏移量**，即要从头偏移几个开始查询；第二个值是**要查询的行数**。
    * 偏移量是可选参数，不写就连逗号都不写，只写行数，代表偏移量是零，也就是从头查询。
    * 行数指返回条数；指定 100 而库里没有 100 条也只返回剩余的数据——他要十条，我给你上哪去生去。
    * > **易错点**：⚠️ 特别容易弄混的点是大家都会以为它是下标。它只是偏移量和查询条数，千万别记成"起始坐标"。

    ```text
    四条数据：   [ 第1条 ]  [ 第2条 ]  [ 第3条 ]  [ 第4条 ]

    只查前两条          →  LIMIT 0, 2
                          偏移 0 个，从头开始查，查 2 条
                          0 可以省略      →  LIMIT 2

    从第 2 条开始查 2 条 →  LIMIT 1, 2
                          偏移 1 个（跳过第 1 条），再查 2 条
                          这个 1 就不能省略了，只有 0 的时候才能省

    再往后挪一格        →  LIMIT 2, 2
                          偏移 2 个，再查 2 条
    ```

* **位置约束**

    * `LIMIT` 必须放在整段 SQL 语句的最后，因为它相当于最终要返回的那个切割好的结果。
    * `WHERE` 一定早于 `ORDER BY`、`GROUP BY` 或者是 `LIMIT`。

### 排名类套路

* **第一高 / 第一名**

    * 先排序再切第一条：`ORDER BY salary DESC LIMIT 0, 1`，也可以直接写 `LIMIT 1`。
    * 查出版最早的一本：`ORDER BY pub_date LIMIT 1`。

* **第二高到第四高**

    * 先按工资倒序排，把最高的那条偏移掉，再连着查三条：`ORDER BY salary DESC LIMIT 1, 3`。
    * 工资第二高就是 `ORDER BY salary DESC LIMIT 1, 1`。

* **前 N 名 / 后 N 名**

    * 前三名 `ORDER BY num DESC LIMIT 3`（`LIMIT 0, 3` 等价）；最少的三名因为"最少"意味着从小到大，用正序且偏移量为 0：`ORDER BY salary LIMIT 0, 3`。
    * 带筛选的排名是三件套：`WHERE note = '<类型>' ORDER BY price DESC LIMIT 1`。
    * 分组后取最多的那个，注意第一个不一定是最多，要按和排序再切第一条：`GROUP BY note ORDER BY nm DESC LIMIT 1`。

* **排序的排序列也可以是表达式**

    * 找书名字数最多的（不含空格）：`ORDER BY CHAR_LENGTH(REPLACE(name, ' ', '')) DESC LIMIT 1`。
    * `ORDER BY` 一定在 `WHERE` 后面，`LIMIT` 一定写在最后。

### 分页偏移量公式

* **为什么需要推算**

    * 后端返回的不是完整数据，而是切割后的分页数据；切哪些数据不能瞎切，要靠前端传参告诉后端切哪一段。
    * 前端一般传两个参数：第几页、每页显示多少条。

* **固定公式**

    $$\text{offset} = (\text{页码} - 1) \times \text{size}, \qquad \text{行数} = \text{size}$$

    * 偏移量的算法是当前页码减一乘以 `size`，第二个值就是每次查询的数量 `size`。

    ```text
    数据：    [1]  [2]  [3]  [4]  [5]  [6]  [7]  [8]

    第 1 页： [1]  [2]  [3]                  →  LIMIT 0, 3
    第 2 页：               [4]  [5]  [6]    →  LIMIT 3, 3
    第 3 页：                          [7]  [8]  →  LIMIT 6, 3
                                            （没有那么多条，就只展示这两条）
    ```

* **两个边界**

    * 页码是从 1 开始的。
    * 数据不够的时候不会给你造数据：一共 5 条数据，第 1 页 4 条过去了，第 2 页只剩 1 条，`LIMIT 4, 4` 只查出 1 条，不可能凭空补出 4 条空的。

## 关键字顺序与别名可用范围

### 书写顺序

* **固定顺序**

    ```sql
    SELECT 结果列          -- 先写 select，放要查询的结果列
    FROM 表名              -- 再 from，指定表名
    WHERE 分组前条件        -- 有 where 就写 where
    GROUP BY 分组字段       -- 有分组再加 group by，可以写多个分组字段
    HAVING 分组后条件       -- 紧跟在 group by 后边
    ORDER BY 排序列        -- ASC 或 DESC
    LIMIT 偏移量, 行数;     -- 最后加 limit
    ```

* **三条顺序上的理由**

    * `HAVING` 跟 `GROUP BY` 死死挨在一起，不可能分家。
    * 分组要优先：先按大小个儿站好再分男生一组、女生一组，排序就没有意义了；排序是对分组结果排序，不是对分组之前排序。
    * `LIMIT` 一定追到最尾部，是对整体结果的切割。

### 执行顺序

* **执行链**

    ```text
    FROM  →  WHERE  →  GROUP BY  →  HAVING  →  SELECT  →  ORDER BY  →  LIMIT
    ```

    * 先指定数据源表，再做前置筛选，再分组，再筛分组后的条件，再算最终显示的列，再排序，最后切割。
    * 执行顺序跟书写顺序不一样；它一般会在面试中被问到，书写顺序则要求实时掌握。
    * > **注意**：执行顺序会随 MySQL 版本不同逐步优化，并不一定是准的，知道大概即可。

* **书写位次与执行位次对照**

    | 关键字 | 书写顺序中的位置 | 执行时机 |
    | :--- | :---: | :---: |
    | `SELECT` | 第 1 个 | 第 5 步 |
    | `FROM` | 第 2 个 | 第 1 步 |
    | `WHERE` | 第 3 个 | 第 2 步 |
    | `GROUP BY` | 第 4 个 | 第 3 步 |
    | `HAVING` | 第 5 个 | 第 4 步 |
    | `ORDER BY` | 第 6 个 | 第 6 步 |
    | `LIMIT` | 第 7 个 | 第 7 步 |

### 别名的可用位置

* **`ORDER BY` 可以用别名**

    * `SELECT` 出现在 `ORDER BY`（还有 `LIMIT`）的前面，按顺序别名先产生，所以排序时可以直接用 `SELECT` 里生成的别名。
    * `GROUP BY 分组字段 ORDER BY nm DESC` 里的 `nm` 就是 `SELECT` 中给 `SUM(num)` 起的别名。

* **`WHERE` 不能用别名**

    * 在标准 SQL 语句中，不允许在 `WHERE` 后边引用列的别名——执行 `WHERE` 的时候列还没有产生，标准 SQL 域也是这么规定的。
    * 现场验证：在 `WHERE` 后面用别名列会报 `Unknown column`。

* **`GROUP BY` 与 `HAVING` 可以用别名**

    * 虽然按执行顺序这个别名应该出现在 `SELECT` 位置，实际上这两处却能正常查询、不会报错。
    * 原因是数据处理过程中顺序有很多优化，产生了很多虚拟表，中间也随 MySQL 版本不同有所变化。
    * > **提示**：这种"提前用别名"是 MySQL 的扩展，标准 SQL 并不这么宽容，写的时候心里有个数就行。

## 单表查询综合实战

### 建库建表与三种插入

* **建库与建表**

    * `CREATE DATABASE IF NOT EXISTS test04_lib CHARACTER SET utf8;` 里的 `IF NOT EXISTS` 意思是"如果不存在我们创建"，库名和字符集都可自定。
    * `CREATE TABLE books (...)` 括号里放列名，多列之间逗号隔开；不指定表字符集就走默认值。
    * 写列名时可以加反引号，列名像 `name` 这种是关键字时，加反引号相当于和关键字区分开、看得更清楚。

* **两种引号不能搞混**

    * 反引号是标识符（列名、表名）的引号，单引号是字符串值的引号。
    * `WHERE note = 'novel'` 左边不用引号、右边要加；`WHERE note = novel` 完全不是一回事。
    * `WHERE` 后边判断列名时直接写不加引号，判断字符串值时正常加单引号。

* **三种插入方式**

    * ```sql
      -- 1. 不指定列名：必须严格按照当初创建表的列顺序插入
      INSERT INTO books VALUES (值1, 值2, 值3, ...);

      -- 2. 指定列名：列名的顺序不必和建表时一致
      INSERT INTO books (b_id, name, author, price, pub_date, note, num)
      VALUES (值1, 值2, 值3, ...);

      -- 3. 一次插入多条：括号逗号隔开，一组括号代表一条数据
      INSERT INTO books (b_id, name, ...)
      VALUES
        (...),
        (...),
        (...);
      ```

    * 第一种最需要注意：不指定列名时 `VALUES` 的值一定要按建表的列顺序；第二种的列名顺序可以和建表不一致，只要值跟列名一一对应即可。

### 改与删

* **修改 `UPDATE`**

    * 语法 `UPDATE 表名 SET 列名 = 新的值;`，多列就再写一个列名等于新的值。
    * 也可以在原基础之上做运算再赋值：`列名 = 列名 运算 新的数值`，`UPDATE books SET price = price + 5 WHERE note = 'novel';` 给小说类型的书整体涨 5 元。
    * 有条件就正常加 `WHERE`；`UPDATE books SET price = 40, note = 'drama' WHERE name = 'Emma';` 一次改两列两个值。

* **删除 `DELETE`**

    * 语法 `DELETE FROM 表名 [WHERE 条件];`。
    * 不带条件代表全表删除，一般删除都是有条件的：`DELETE FROM books WHERE num = 0;`。

### 查询串联套路

* **模糊 + 聚合**

    * `SELECT * FROM books WHERE name LIKE '%a%';` 前后加百分号，中间有一个 `a` 就行。
    * 同一条件换成统计：`SELECT COUNT(1), SUM(num) FROM books WHERE name LIKE '%a%';` 得到 4 本、总库存 103。

* **分组 + 分组后过滤**

    * 按类型统计数量：`SELECT note, COUNT(1) FROM books GROUP BY note;`。
    * 统计每组库存和并筛出超过 30 的：`SELECT note, SUM(num) AS nm FROM books GROUP BY note HAVING nm > 30;`。
    * 分类统计 + 总量用 `WITH ROLLUP`，它会把求和这一列自动再算一个总和放在最后：`GROUP BY note WITH ROLLUP`。
    * 最后那行没有分组值显示为空不好看，用 `SELECT IFNULL(note, '总量'), SUM(num) ...` 把它显示成"总量"；一共五种行——四种类型加一个总量。

* **字符串函数的嵌套套路**

    * 直接拿 `name` 算长度不行，它会把空格也算一位，先用替换函数去掉空格再求长度：`WHERE CHAR_LENGTH(REPLACE(name, ' ', '')) >= 10`。
    * 替换函数的参数是"要处理的字符串、目标、替换值"，跟 Java 里的用法有点像。
    * 套路固定为"统计长度 + 替换 + 嵌套"，函数名记不住回头翻单行函数那几章即可。

* **`CASE` 把值翻译成一句话**

    * 只有两个结果用 `IF`，多个流程用 `CASE`。
    * 第一种用法 `WHEN` 后放比较表达式；第二种把 `CASE` 后面放列名、后头不放表达式而放"这个列名对应的值"，等于就返回对应结果。
    * 两种都能实现，最后 `END` 代表完事；`CASE` 会产生新列，所以再起个别名。

* **报错与没有结果是两回事**

    * 没有结果可能只是没数据，报错是 SQL 写错了。
    * 碰到 `1064` 就证明语句写错了，报错信息里 `near` 附近的那一截会告诉你大概错在哪儿。
    * 现场两类典型：查空值时漏了 `WHERE` 关键字直接报错；查长度时 `WHERE` 后面忘写 `FROM books`，提示 1064。
    * 函数名在客户端里没高亮也是拼错的信号，比如把 `DATE_FORMAT` 敲成没有下划线的 `DATEFORMAT`。

## 数据库约束

### 约束的作用与添加时机

* **约束是什么**

    * > **定义**：约束是对某些行为的一种限制；数据库的约束是**表级别的一种规定**，是对表中数据的一种限制语法，限制的是数据。
    * 这些限制不一定是坏事，它可能对数据有一个保护作用。
    * 作用是保证表中数据的准确性、可靠性和正确性；不要去相信录入数据的人，更应该相信约束带来的保障。
    * 数据不符合约束时，最终在插入或修改的时候会直接报错。

* **添加时机只有两种**

    * 创建表的时候，在 `CREATE TABLE` 的时候添加。
    * 表创建完毕以后，用 DDL 里的 `ALTER TABLE` 修改表的时候添加。

* **分类的依据**

    * 分为三类只是为了方便记忆，相当于分了个子类；它们之间的对比范围是逐渐增大的。

    ```text
      列 / 域级别   →   只用看自己这一列
            ↑
      实体 / 行级别  →   要跟同一个表里的其它行比
            ↑
      引用（外键）级  →   要跟另一张表比
    ```

### 约束的三类

* **三类对照**

    | 类别 | 对比范围 | 包含的约束 |
    | :--- | :--- | :--- |
    | 列 / 域级别 | 只看自己这一列 | 非空 `NOT NULL`、默认值 `DEFAULT`、检查 `CHECK` |
    | 实体 / 行级别 | 跟同表其它行比 | 主键、唯一 `UNIQUE`、自增长 |
    | 引用（外键）级别 | 跟另一张表比 | 外键 `FOREIGN KEY` |

* **列级别（域级别）**

    * 非空约束 `NOT NULL`：要求某一列不为空。
    * 默认值约束 `DEFAULT`：插入数据时不指定、或者指定空，都会走默认值。
    * 检查约束 `CHECK`：检查某一列是否符合我们写的一个规则，比如要求插入的年龄必须大于 18 岁，否则无法插入。
    * > **提示**：`CHECK` 严格说并不是列级别的，它是表级别的——只不过放在这个位置讲也好理解。它相当于一种**自定义约束**，可以写任何规则。

* **行级别（实体级别）**

    * 关系型数据库里一行代表一个实体，一行数据对应到语言里就是一个对象；行级约束需要对比同一个表中其它的行才能得出结果。
    * 主键约束代表**不为空且值要唯一**，所以要参照其它行的这一列才知道能不能插入。
    * 唯一约束 `UNIQUE` 跟主键的区别是**可以为空**：可以没有不写，但要写了这一列的值之间就不能重复。
    * 自增长约束对应主键类型，数值第一个是 1，第二个就自动在原来基础上涨 1，它参照之前的值递增，所以也是行级约束。

* **引用（外键）级别**

    * > **定义**：对比的不仅是不同的行，而是其它表，所以也叫多表约束。
    * 关键字 `FOREIGN KEY`，加以后这一列的值必须参照另外一个表的某一列的值，不匹配就报错。
    * 前两类都属于同一个表内的约束，第三类是跨表的；一共 $3 + 3 + 1$ 共 7 种。

### 非空约束

* **作用与四个特点**

    * > **定义**：限定某一个字段或者多个字段的值不能为 `NULL`，关键字叫 `NOT NULL`。
    * 第一，所有的类型都可以加非空约束，包括数值类型。
    * 第二，非空约束是加在列上的，在创建表或修改表过程中在列的后边直接追加。
    * 第三，可以多次使用，一个表中可以有 $N$ 个列加非空约束。
    * 第四，空字符串不算空，数值 `0` 也不算空，只有真的 `NULL` 才算空。
    * > **易错点**：⚠️ 最后一条是高频错点。`''` 是空字符串，它有值，存得进去；`0` 是数值 0，它也有值。

* **添加**

    * 创建表时在字段、类型后面加 `NOT NULL` 即可，有多个列就继续再加。
    * 建表后修改添加用 `MODIFY`，它可以修改字段的类型，类型不变时只要加 `NOT NULL` 就相当于给原有字段添加了非空约束：`ALTER TABLE 表名 MODIFY 列名 数据类型 NOT NULL;`。
    * 查看表结构用 `DESC`，只关心 `Null` 这一列：`NO` 表示不能为空，`YES` 表示允许为空。

* **删除**

    * 改成 `NULL`：`ALTER TABLE 表名 MODIFY 列名 数据类型 NULL;`。
    * 干脆什么都不写：`ALTER TABLE 表名 MODIFY 列名 数据类型;`——不写非空约束默认就是允许为空的。
