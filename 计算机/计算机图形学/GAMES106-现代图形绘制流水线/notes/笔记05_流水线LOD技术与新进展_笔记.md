# 流水线LOD技术与新进展

## 流水线 LOD 的分类与切换

* **流水线 LOD**

    * > **定义**：细节层次（Level of Detail，LOD）技术的流水线级应用——把几何、纹理、着色器等各类资产的简化成果在整条绘制流水线里统一用起来，达到最终加速效果。

    * 前置能力：几何 LOD 用小三角面片表达复杂几何（基于几何距离的网格简化算法）；纹理 LOD 覆盖纹理压缩、滤波、mipmap 与材质压缩；着色器 LOD 覆盖简化着色器代码提速、预测绘制质量与自动优化。

    * 按形态可归为四类：离散、连续、视角相关、层次结构。

### 离散 LOD

* **离散 LOD（Discrete LOD）**

    * > **定义**：预先做出 LOD0、LOD1、LOD2、LOD3 等彼此分散的固定层级，运行时在层级之间整体切换。

    * 通用性最好：各层级之间不一定要有连续关系，不管做什么样的资产都可以用离散 LOD 来表示。

    * 核心缺点是切换跳变（popping）：层级一切换，模型、材质都会不断跳变，这是离散 LOD 第一个最关键的问题。

### popping 的压制手段

* **延迟切换**

    * 不在距离刚好到达关键点的地方直接跳变，稍微延缓一些再切。

* **几何 morphing**

    * 在 LOD1 与 LOD2 这类相邻层级之间，通过顶点的插值做一个几何的 morphing 过渡，当然还有其他几何 morph 的做法。

* **透明度混合（alpha blending）**

    * LOD0 到 LOD2 中间有不同层级时，根据距离的变化去做 alpha blending。

* **共同思路**

    * 几种手段的思路是一致的：把「跳变」尽可能变成「渐变」。

### 连续 LOD

* **连续 LOD（Continuous LOD）**

    * > **定义**：每个 LOD 节点之间可以通过一定的公式做连续插值，在每一个 position、每一个 distance 上都有一个合适的混合。

    * 地形过渡中不管怎么走都不会有 popping 的问题；真实感更高、过渡更自然、很平顺。

    * 走到非常近的时候，理论上可以通过解析的方式给到一个非常好的 LOD 层级。

### 视角相关 LOD

* **视角相关 LOD（View-Dependent LOD）**

    * > **定义**：对 LOD 的划分不一定对整个模型或整个材质统一处理，而是跟视线方向相关。

    * 判定规则：正对相机的地方，几何变形对视角相关的深度变化影响比较低，不需要很细节的几何；边缘、轮廓过渡的地方需要更光滑的几何过渡，用更高层级的 LOD；换成俯视角度，与相机方向垂直的表面 LOD 比较粗，边缘处 LOD 过渡比较平、比较细致。

    * 对一些大型物体——像地形、占据整个空间的物体——这种方法非常友好。

### 层次结构 LOD

* **层次结构 LOD（Hierarchical LOD，HLOD）**

    * > **定义**：对场景的表达先分层——比如人分头、身体、四肢，手再往下分手掌、手臂——这些 hierarchy 形成树状结构。

    * 绘制规则：头部用一个比较粗的 LOD 表达时，它所有的子节点都不会再被绘制；觉得头部不够细致，就把头部做划分，眼睛、鼻子各部分分别用更细致的表达。

    * 收益边界：细节分布不均的模型上收益最明显——做了层次 LOD 的船可以在窗户这类细致的地方有更好表达、平板的地方选粗犷的 LOD；没有层级化表示、整条船统一处理时，相同面片数下一些平面就没办法保持，桅杆之类的小物体会把整个几何都带得变形。

### 层级切换准则

* **逐帧选层**

    * > **定义**：真正绘制的过程中，每一帧对每一个模型、每一个物体独立地选择一个 LOD，因此需要寻找切换准则。

    * 常见方法有四类：

| 切换依据 | 做法 | 特点 |
| :--- | :--- | :--- |
| 代表点 | 在模型上选取一个代表点，用代表点与相机的距离变化来选择层级 | 最直接的距离度量 |
| 包围球 | 用包围球代替模型，把球的面积在屏幕空间做投影，按面积缩放选层级 | 比单点更贴近模型在画面里的大小 |
| 包围盒 | 用四四方方的包围盒做投影来选层级 | 比包围球更准确；投影算法五花八门，因为包围盒本身也有很多种简化的方法 |
| 面片数 | 给定一个目标面片总数，按它来分配各物体的层级 | 能把帧率稳住，但质量有时没法保证，会出现 artifact |

## 地形 LOD

* **地形的绘制难点**

    * mesh 非常大、整个模型非常大，可视范围也非常大——近的地方看得到树和草，远的地方只能看到一个轮廓。

    * 对变化这么剧烈的模型，离散、连续、视角相关、层次结构这几类技术会混起来使用，地形是最常见的混用场景。

    * 常见地形 LOD 技术有四类：

| 技术 | 形态归属 | 核心结构 | 标志性做法 |
| :--- | :--- | :--- | :--- |
| ROAM | 视角相关 + 连续 | 高度图 | 长边不断切分与合并，按投影误差决定分裂合并 |
| 几何 mipmap | 视角相关 + 离散 | 地形分块、块内 hierarchy | 几何 morphing 防 popping |
| Geometry Clipmaps | 环状嵌套网格 | 内圈最密、外圈最稀、远缘回升 | 随距离与移动整块整块更新 |
| Chunked LOD | 层次四叉树 | 按需向下细分 | 不同区域不同密度，避免均匀划分 |

### ROAM

* **实时最优自适应网格（Real-time Optimally Adapting Mesh，ROAM）**

    * > **定义**：视角相关与连续 LOD 的混杂——真正的裸数据用高度图表达地形变化，根据高度图上每一个点的高度、跟相机的距离，自适应地创建网格。

    * 疏密规则：高度变化剧烈、对视角会产生重大影响的地方，有非常细密的 LOD 表达；不容易观测到高度变化的地方，用比较粗糙的三角面片；视角变换时面片不停地细分或合并，实时做连续变化。

    * 划分方式：对三角面片选择长边不断地切分；合并是把那条边拿掉、并成一个更大的三角形，一个大三角形可以分解出很多层；每个顶点的高度由高度图决定。

    * 误差判定：把三角面片对应的区域投影到相机的平面空间，用近似后的面积和期望的高度直接算出一个误差估计，根据它确定分裂与合并。

### 几何 mipmap

* **几何 mipmap**

    * > **定义**：视角相关的离散 LOD——把纹理那边 mipmap 的技术继承到几何上。

    * 对整个地形做一个分块，每一小块有它自己不同的 hierarchy；根据这个地方的细节量、还有跟相机的距离，确定每一小块上选择哪一个层次的细节。

    * 同样会用几何 morphing 的技术去避免 popping 的问题。

### Geometry Clipmaps

* **几何裁剪映射（Geometry Clipmaps）**

    * > **定义**：以相机为中心一圈一圈往外嵌套的环状网格——距离最近的是一个环，随距离变远一层层往外变成更粗的层次，形成层层嵌套的网格形状。

    * 密度原则：越近的地方用越密集的表达，随距离增加表达越来越稀疏；而到了远处、平面空间上接近边缘的地方——这些地方的高度对视线有更大的影响——又会选择更密集的表达。

    * 最大好处是实现非常简单：不需要复杂的数据结构来表达、比较容易管理；随距离、移动的变化做整块整块的更新。

    * 对硬件、串流都比较友好，对存储的消耗也比较低。

```text
+-------------------------------------------+
|  outer ring : coarse (far)                |
|   +-----------------------------------+   |
|   |  middle ring : medium             |   |
|   |   +---------------------------+   |   |
|   |   | inner ring : dense (near) |   |   |
|   |   +---------------------------+   |   |
|   +-----------------------------------+   |
+-------------------------------------------+
```

### Chunked LOD

* **分块 LOD（Chunked LOD）**

    * > **定义**：用一个层次的四叉树去存储更多的细节——最上层用粗的四叉树，下一层划分成更细的四叉树依次表达，越接近叶节点细节越丰富。

    * 细分方式：只在需要的区域、需要的时候才去做层次划分，划分之后本身自带密度变化。

    * 最大好处：不同的区域可以有不同的密度表达，本质上可以避免对同一个区域做均匀的划分。

    * 效果：比较好地降低面片的数量、减低无效的渲染。

```text
level 0 (coarse)     level 1             level 2 (leaf)
+-----------+        +------+------+     +--+--+--+--+
|           |        |      |      |     |  |  |  |  |
|           |  --->  +------+------+ --> +--+--+--+--+
|           |        |      |      |     |  |  |  |  |
+-----------+        +------+------+     +--+--+--+--+
```

## 可微绘制流水线

### 正向、逆向与可微绘制

* **正向绘制**

    * > **定义**：有模型、光照、摄像机、纹理，用一个 forward 的方法——也就是绘制流水线——过一遍，得到最后的绘制结果。

* **逆向绘制（Inverse Rendering）**

    * > **定义**：有了一个绘制结果，把这个绘制流水线逆过来，去得到原始的几何、光照、纹理，还有 camera 的位置。

* **可微绘制（Differentiable Rendering）**

    * > **定义**：逆向绘制的一个变种（特殊类型）——把正向过程认为是一个函数，逆向过程就是这个正向函数的逆函数。

    * 梯度求解：有了这个逆函数，就可以用梯度反向传播把正向结果里某个 pixel 的颜色对每一个参数（材质、几何等）的导数关系直接求出来。

    * 优化方式：如果最后那个地方是一个 image space 的 error，就把这个 error 通过导数的形式传递回来，通过梯度下降朝着减小 error 的方向改变参数，达到优化场景参数的目的。

### 预算约束下的资产反推

* **反推流程**

    * 前提：构建一个完全可微的绘制流水线，让整个绘制流程步步可微。

    * 做法：给定一个 budget——三角面片的数量、纹理的分辨率、shading 的开销——用反向传播的方式使简化后材质画出来的结果与初始材质画出来的结果尽可能逼近，以此优化简化后的资产；这是另一种形式的获得 LOD、获得简化资产的方式。

    * 操作惯例：给定一个固定的压缩率，尽可能最小化简化前后的差异。

    * 衔接：LOD 资产得到之后，用 LOD 管理技术、切换技术放进游戏之中用起来。

* **适用边界**

    * 目前通过可微绘制流水线，常见的是优化纹理、优化几何，有时候也优化中间的一些函数。

    * 通过可微绘制流水线直接优化 shader code 还是研究内容：shader code 的变化比较非连续，本身是一个离散的 coding 空间，直接优化比较困难。

* **落地现状**

    * 通过可微绘制流水线做 LOD 资产生成是近一两年才开始兴起的话题；腾讯这类比较 aggressive 的公司已经开始用起来，并取得比较好的效果；GDC 2023 有专门的 talk。

### 全流水线的反向链路

* **反向链路**

    * 正向从几何（顶点数据）到光栅化、到 fragment shader、到 color blending 做出图片；逆过来就是从图片一路往回走。

```text
正向：  顶点数据 --> 光栅化 --> Fragment Shader --> Color Blending --> 图片
反向：  顶点数据 <-- 光栅化 <-- Fragment Shader <-- Color Blending <-- 图片
```

    * 反向传播时每一级都要解决「梯度怎么穿过这一级」：color blending 是解析可微的；shader 靠拆着色器做从着色到纹理和光照的映射；光栅化靠深度扰动；顶点阶段着色器（vertex shader、tessellation shader）的可微与 fragment shader 类似，最后通过一些几何的可微，返还到顶点的优化上。

### 图像空间的 loss

* **监督信息**

    * > **定义**：在绘制出的图片上计算 reference 与 render 结果的差异，作为整个优化过程的监督信息。

    * reference 是固定的：给定一个视角、给定一组场景参数之后它就是目标；render 结果随 mesh、texture、lighting、camera 这些参数在优化过程中不断变化。

    * 这个 loss 在该阶段貌似没办法对那些参数直接求导，但它可以往回传——在后面可微 shader 的阶段是可以针对这些参数做优化的。

    * 常见 loss 形式：L1、L2，以及 SSIM（一种结构性的相似性度量）。

### Blending 层的梯度

* **alpha blending 的解析可微**

    * blending 做的是不同 pass、不同通道的混合，一般用权重混合：$C = S\,C_s + D\,C_D$，权重 S 与 D 相加通常等于一。

    * blending 是一个解析的操作，所以梯度可以往回传；拿到各 pass 的混合系数 S 和 D，把 loss 往回传就非常直接。

    * 用混合结果 $C$ 对 $C_s$、$C_D$ 做偏导，得到的其实就是混合系数本身：$\partial C/\partial C_s = S$、$\partial C/\partial C_D = D$；把这个混合系数乘上 loss，就可以把梯度传回不同的 pass。

### 着色器的自动微分

* **计算图拆解**

    * 着色器是一堆 code 组成的，首先要把这些 code 解析成一个图（graph）——与 code 编译成 IR 相似，只是把语言变成更数学的符号、构建计算图的依赖关系。

    * 求导示例：$Y = D \times E$ 要对 $D$ 求导，导数就是 $E$；反过来对 $E$ 求导，导数就是 $D$；$D$ 又在别的函数里如 $D = A + B$，就继续做求导，一步一步把导数传进去。

* **非连续 OP 难点**

    * 真正在着色程序里做自动微分，特殊之处在于着色程序里有很多非连续的函数、非连续的 OP，做自动微分就必须考虑这些非连续的 OP。

* **手动微分与自动微分**

    * 手动微分：程序员挨个对每一个算子做拆解、给出显式的求导表达式——对代码、对数学的要求更高，但效率会很高。

    * 自动微分：要用工具去搜索整个计算图——内存消耗和一些计算消耗的代价都比较大，只能在离线的状态做。

* **面向 shader 的自动微分**

    * SIGGRAPH 2022 的工作 AutoDiff 专门做 shader 语言的自动微分；动机是现有的微分器都处理不了 shader、或绘制过程中 OP 的不连续性。

    * 对现有方案的评价：AD（PyTorch 这类做反向梯度传播的自动微分）对不连续的部分没做很好的处理，很难用于 shader code；FD 是有限差分，对不连续的情况有一定容忍，但性能比较低；一些面向特定问题的微分器（如面向 path tracing 的自动微分器）与 shader code 的场景也不太一样。

    * 手段：定义一个 DSL（领域专用语言）去涵盖 shader code 里常用的东西——算术表达式，常量、变量，微分的目标参数，加法、乘法操作，三角函数，原子操作等。

* **不连续积分的 box 滤波处理**

    * 核心思想：解决 shader 程序语言里不连续函数的积分问题——对 shader 来说，shading 是一个积分问题，这是跟普通函数不太一样的地方。

    * 对 Heaviside 这种不连续跳变：直接做梯度的话，它的积分是一个无穷大的值（跳变的范围无限逼近零）；用一个 box 滤波去替代原来的积分后，这个地方的梯度变成一个有一定范围的、有限的分段函数——区间内整个积分（包括梯度的积分）可以进行，梯度就可以继续往上传播。

    * 与传统 AD 对比的梯度法则：

        * 分段（跳跃）函数的积分规则：传统做法里导数直接就是零；经过 box 滤波处理之后，这一段是有梯度的。

        * 加法法则：与 AD 一致——积分的加法跟把各项拿出来再分别积分是一样的。

        * 乘法法则：与 AD 有一些不同——要考虑两个函数 $g$、$h$ 都不连续的可能性，不考虑这一点会产生累计误差；对另一个函数用一个 box 在整个函数域上去逼近，可认为这是 AD 乘法法则的进一步泛化。

        * 链式（函数）求导法则：跟 AD 相似，只是前面多了一个 $H'$；$H'$ 本身也可能不连续，所以对 $H'$ 的梯度用类似的 box 方法处理成可以连续的方式。

    * 二维工程化：理想的做法是做一个 2D 的 box 核函数滤波，但真正工程化时效率比较低；实际用近似的一维滤波核——某一段选择对 Y 轴滤波、某一段选择对 X 轴滤波，然后取最优，这是工程上的实现取舍。

### 可微光栅化

* **可微光栅化（Differentiable Rasterization）**

    * > **定义**：解决从屏幕空间出发、有了一个颜色怎么映射回三维空间的问题——正向是三角面片乘上变换矩阵后往屏幕空间投影、得到像素颜色的过程。

    * 现有工具：SoftRas、DIB-R、nvdiffrast（NVIDIA 的）等，它们在性能上、实现细节上有一些细微差别。

    * 正向公式化：每个三角形分别投影到 camera plane 上，投影结果得到 pixel，然后做 blending，最后把不同 plane 之间的结果聚合起来。

    * 逆过程难点：投影、变成 pixel 前面几步是直接可微的、非常容易；比较复杂的是最后聚合那一步——它是根据深度做混合的，每个像素都取离屏幕位置最近、也就是 Z 值（深度值）最小的那个去赋值。

    * > **易错点**⚠️：深度测试「取最近者」本质上是一个 if-else，是一个不连续的函数——这正是可微光栅化要专门解决的地方。

    * 解法：类似有限差分的思路——对深度做微小的扰动，这个扰动会得到不同平面 blend 出来的不同混合值，根据这些值就可以计算不同三角面片关于深度的梯度，把整个三角面片可微化所需要的结果求出来。

    * 真正需要的结果是一个平滑聚合图（smooth aggregate map）：像 alpha blending 一样，把屏幕空间的像素颜色倒传回每一个具体的三角面片上。

    * 梯度计算流程：优化过程中先每个都画一遍、得到 framebuffer，再做一个深度上的扰动，把关于深度的梯度求出来——这是它的核心 idea。

### 从像素回到顶点

* **error 回归顶点**

    * 有了可微光栅化，就可以把所有的数据倒推回到具体的三角面片上——error 从像素回归到了顶点上，最后一起做顶点上的操作。

* **顶点操作的梯度**

    * 顶点操作包括缩放（把这个三角形缩小、把边缩窄）与平移（把顶点挪动一下）。

    * 求导方式：挪动边的话，就算这个边的操作对像素 error loss 的微分；顶点同理——把一个顶点在各个方向上平移，做它对这个像素 error loss 的微分，同样可以得到它的梯度。

    * 有了这些，就可以通过 loss 去改变三角面片，整个 pipeline 就打通了。

## 基于图像的简化

* **基于图像的简化（Image-Based Simplification）**

    * > **定义**：一种非常极限的 LOD——既不单独优化几何、也不单独优化纹理，而是把几何和纹理一起拿来优化，最后用一张图片替代几何加纹理、加上 shader 的整个绘制结果。

    * 常见策略：billboard、billboard cloud、image cache、imposter、texture depth map。

    * 定位：最简单粗暴、最暴力、最极端的方法。

### 广告牌

* **广告牌（Billboard）**

    * > **定义**：用一张图片顶掉几何、纹理与 shader 的整个绘制结果。

    * 历史与用途：2000 年初或者更早的时候就有了，主要用来表达户外场景里的一些东西——树、云，尤其是云。

    * 关键机理：billboard 产生的物体只有一个面，相机走动时可能看到它侧边的边缘、那就露馅了——所以走的时候它也在转，始终面向观察的相机。

    * 适用场景一：物体离视线比较远——假设在无穷远，走动时它的方向基本不会变，billboard 的表达会比较好、不容易露馅。

    * 适用场景二：比较模糊的物体——像云，分不清正面、侧面、反面的区别，就算它跟着转也不容易露馅；对云、雾这类东西效果比较好。

* **多面广告牌**

    * 一个面表达容易穿帮，就用多个面表达：两个面、甚至 N 多个面叠加起来，走的过程中走到不同角度，它会显示不同角度上观测到的 image，以此增加随方向变化的细节。

    * 通常多边形越多、效果越好；而且随视角变化，它可以在视角之间做一个插值。

### 广告牌云

* **广告牌云（Billboard Cloud）**

    * > **定义**：把物体做分块，每一个区域、每个零部件分别都用一个 billboard 去表达——提供很多很多块板，而不是用一块板表达整个物体。

    * 效果：这些板结合起来之后，在某些特定的视角下跟原始的物体相差很小。

    * 视差容忍：板彼此之间有遮挡关系——这一面看到的是这块板，从上面看这块板可能被其他板遮住——所以提供了一定的视差变化的容忍性。

    * 定位：比广告牌精度更高的一种方法。

### Image Cache

* **图像缓存（Image Cache）**

    * > **定义**：对整个空间根据物体的密度等信息做一个四叉树或者八叉树的划分，形成的层次化图像缓存。

    * 适用对象：通常用在一些大物体上，像一整张大地图；但不限于地图，地形上的各种物体、背景都可以用。

    * 绘制规则：距离最近的一些节点上，用真实的几何去绘制这个区域的场景；远的地方用一个 RGBA 的广告牌图像去替代掉整个模型，最后做广告牌之间的 alpha blending，得到远景的效果。

    * 动态换进换出：随镜头不断移动，缓存和真实几何在动态地换进换出；被视线直接卡掉的地方不需要进行绘制。

### Imposter

* **替身（Imposter）**

    * > **定义**：做一个球（半球或者整个球），在球的每一个顶点上放一个摄像机，把每个顶点上观测到的物体存成纹理；真正画的时候，对这些预计算好的结果做插值、混合和读取，替代掉真实物体。

    * 覆盖范围：不同角度都存，这张纹理其实就包含了从 360 度每一个角度去观测这个物体所能看到的形状。

    * 现状：比较新一代的技术，非常常用在真实的游戏里——UE4、UE5 里面这种方式会比广告牌更常用，因为它不容易露馅。

    * 效果边界：因为不同角度、不同方向都记录了对应的视觉信息，可以通过 alpha blending 或某一些混合系数混出来；不过中间会有一些细微的跳变，看得到。

    * 与传统层次 LOD（HLOD）对比：用 imposter 的树看起来会更圆滑一些，效果会更平顺一些。

### Texture Depth Map

* **纹理深度图（Texture Depth Map）**

    * 做法：把一些远的物体——像成片的楼——全部根据它们的 depth map 去做几何的合并，把这些离散的模型变成一个连续的块，再把一些烘焙的结果、衰减的结果烘焙到这个连续的块上面。

    * 收尾：把这些 depth map 做一个三角化，得到一个类似于 imposter、但其实已经不是 imposter 的东西——可以认为它是一个简化后的几何加纹理，用这个来替代远景。

## 传统绘制的两种范式

* **基于光栅化的实时绘制流水线**

    * 比较传统的第一类：主要思想是把面片投影到屏幕空间，然后逐像素地做上色。

* **延迟绘制（Deferred Rendering）**

    * > **定义**：用两个 pass 把画面画出来——第一个 pass 先把几何的 G-buffer 画出来；第二个 pass 基于 G-buffer 里存的几何与材质信息，去做 lighting 的计算。

    * 缺陷：G-buffer 里只包含空间信息。

    * 补救方法：Light Probe（光照探针）、体素全局光照（VXGI）这类方案——当然这些都不是质量特别高的方法。

## 虚拟纹理

* **虚拟纹理（Virtual Texture）**

    * > **定义**：把虚拟内存的想法延伸到纹理——一个非常大的 virtual texture（其实会超过 GPU 的显存）加一个 page table，访问时先查表。

    * 背景：3A 游戏里很多大场景（比如一座城市）的纹理几乎是「无穷大」的；纹理一个个分散不好取——一是不方便取，二是所能用到的纹理大小会受到限制。

    * 访问流程：查 page table——命中（hit）就直接取回物理页；没命中（miss）就到内存或硬盘里把具体的内容换进来，整套流程和虚拟内存的换页如出一辙。

* **三个好处**

    * 支持高清的大规模纹理。

    * 动态地、按需地调度，这样可以减少内存和带宽的消耗。

    * 统一去访问虚拟纹理，可以避免很多零散分块的小纹理带来的对齐和拼缝问题。

### 带 LOD 的页表

* **页表的 LOD 结构**

    * 跟虚拟内存不一样的地方：虚拟纹理有一个 LOD 结构——低分辨率的 mip 和高分辨率的 mip 相互对应。

    * 索引方式：每一层里面都是分块的，而且每一块的 size 都是一样的，所以可以用一个 page table 去做索引；页表本身也带着 LOD 结构，不同层次之间可以互相查找。

    * 实际做 LOD 很方便：找一个低层级的虚拟纹理时，如果对应的物理纹理还没有加载进来，可以很方便地去找它的上层 LOD，用一个低分辨率的纹理先替代掉。

* **视角变化的表现**

    * 从远到近，实际加载的块和 LOD 在不断变化——非常远的地方，有些纹理是一个固定的块；走近了之后，这些块会被划分成更小的东西，如此不断变换。

### 预加载与 feedback pass

* **预加载问题**

    * 一个小小的缺点：需要把用到的纹理做提前的预加载——实际要渲染的画面里每一个区域都可以是一个虚拟纹理块，而这个块到底在不在物理显存里，GPU 其实是不知道的。

* **feedback pass**

    * 做法：先做一个 feedback rendering——用一个 pass 去尝试取一下纹理，如果不存在，它就自动去硬盘里取、作为预加载，最后再把画面真正画出来。

    * 代价：整个流程多了一个 feedback pass，不过这个 pass 的带宽其实很低，对实际性能的影响也很小。

### 从软件方案到硬件接口

* **硬件虚拟纹理**

    * 近几年来，硬件的虚拟纹理已经被厂商集成进了 API——OpenGL、Metal 都有对应的接口，直接在里面用就行。

    * 用法其实也差不多、实现的方法也差不多：先去找一个纹理块，再把具体的物理纹理块加载进来。

    * 边界：硬件层面上的具体实现，各个厂商都会有自己的差异，这些也不是完全公开的。

## 虚拟几何与 Nanite

* **虚拟几何（Virtual Geometry）**

    * > **定义**：基于虚拟纹理概念推出的虚拟几何、虚拟面片串流——UE5 的 Nanite 是代表，把几何也做得很大、有很大的三角面片量，并实时串流进来。

    * 动机：纹理通过虚拟纹理已经可以做得很大了，下一步就是把几何也做得很大——这样就不需要加载很高清的 Normal map，艺术家在 ZBrush 里雕出来的高清几何垫一些素材也能直接加载到游戏里。

    * 难度：基本 idea 跟虚拟纹理会有点像，但实现起来复杂很多——几何的合并、几何的存储都比纹理更复杂。

    * 三个关键技术点：加载判定、光栅化的加速、几何 LOD 树与串流。

### 靠遮挡剔除的加载判定

* **不能走 feedback pass**

    * 虚拟纹理可以用一个 feedback pass 去确定哪些部分要加载；虚拟几何不行——要知道哪些地方要、哪些地方不要，得真正做一次光栅化、把东西都投影过去才行。

    * 理论上走 feedback pass 这条路，就要先把所有的几何都已经放到 GPU 里面画一遍，整个虚拟几何的意义就失去了。

* **遮挡剔除方案**

    * 加载判定主要通过遮挡剔除：假设有一个 depth map，就可以通过它直接对物体级、对每个物体的 bounding box 做一个快速的剔除——一个物体、或者这一块的一群 mesh 的距离都小于这个 depth，那它肯定是被遮挡的，就不需要再去做了。

* **UE5 的 HZB 结构**

    * UE5 真正做的是用一个 hierarchical Z buffer（HZB）去做遮挡剔除：把面片分成一簇一簇（cluster），用视锥剔除加遮挡剔除把粗的部分快速去掉，不用去处理具体的小面片。

    * 剔除还用到了帧间连续性、做了两次：大部分移动在两帧之间是有相关性的，上一帧可见的面片大概率这一帧也是可见的——先把上一帧的面片在这一帧都重新画一遍、产生一个 z buffer；用这个 z buffer 先把整体的大部分面片剔除掉；剩下之后，再把剩下的一些面片画出来作为补充，把新增加的细节补上去。

    * 由于相邻帧之间的相关性很好，这个 cache hit 的准确率在实践中是非常高的。

### 混合光栅

* **小面片的带宽问题**

    * 光栅化是一个跟面片数量相关的事情：假设有很多小面片，每个小面片都往 framebuffer 里写一份完整的 G-buffer，带宽会非常大——传统 G-buffer 的通道太多了。

* **软光栅方案**

    * 对小面片，不去具体写它的传统 G-buffer，只写一个 instance id、一个 cluster id，再加上一个 depth——光栅化的时候写出来的东西很少，带宽就降下来了；到真正绘制的阶段，再通过这些 id 去读取具体的几何材质数据。

* **混合策略**

    * 大面片还是用传统的硬件光栅化——硬件做光栅化的效率还是更高；对小面片用软光栅——效率会比硬光栅更高；用这种复合的方式把两头的好处都拿到。

### 几何 LOD 树与串流

* **层次结构**

    * 根据 cluster 的误差（error）去做面片的划分，簇之间再去构造一个 hierarchical LOD 结构，形成一棵树：父节点包含两个子节点——父节点可以是一块面片、也可以认为是整只兔子，子节点就是兔子的两个部分——依次划分下去，最后看到的叶子是一些细的面片块。

    * 绘制规则：画了父节点，它对应的子节点其实肯定就不需要画了——都是表达同一个东西，只是用了不同的 mesh 数量去表达。

* **cut 维持与容错**

    * 根据视角的变化去维持一个 cut，确保这个 cut 上的节点在显存里面。

    * 如果 cut 需要往叶节点走、要画一个父节点的子节点，在加载的过程中可以先用父节点去暂时替代子节点——这样保证任何时刻都能画出一些正确的东西来，虽然细节可能不对。

* **popping 缓解**

    * 切换时的几何 popping，用之前讨论过的一些方法做缓解：主要是类似 TAA 的策略——可能不是 TAA 本身，是类似 TAA——做一些帧间的复用和 blending。

## 光栅化与光线追踪的混合

### 光线追踪与光栅化的分野

* **光线追踪（Ray Tracing）**

    * > **定义**：一个更物理的方法——不是把面片往相机上投影，而是直接从相机上发射光线，去对场景的面片（几何）做求交。

    * 求交之后：知道了光线的来向，就可以算出它反射的方向、折射的方向，在场景里做 bounce，一直弹到找到 light source 为止。

    * 全局光照优势：bounce 的过程中收集了整个场景多次 bounce 的光能传输变化，可以更好地描述全局光照（GI）。

* **光栅化做 GI 的短板**

    * 现在在光栅化的流水线里加入 GI 的方法，通常需要大量的艺术家去调，而且物理真实性并不一定准确。

    * 像镜面反射、折射这种东西，在光栅化的方法里其实是很难做到的。

* **path tracing 的能力边界**

    * ray tracing / path tracing（路径追踪）可以保证所有的 feature 都尽可能地逼近真实世界的物理结果。

    * > **提示**：path tracing 也不是所有 feature 都能做——像 caustics（焦散）还有一些类似的效果，需要更进一步的特殊算法才能做；但对大部分游戏场景来说，path tracing 产生的结果会比传统光栅化流水线产生的效果好很多。

### 混合流水线的分工

* **混合动机**

    * 原因很直接：光栅化快，ray tracing 慢——有一些效果用光栅化做比较快就用光栅化，有一些效果必须 ray tracing 才能做得好就用 ray tracing；把两个技术混到一块、不同效果用不同技术去做，是现在最主流的方法。

* **效果分工**

| 效果 | 更顺手的技术 | 原因 |
| :--- | :--- | :--- |
| 直接光的阴影 | 光栅化 | 光栅化可以做得很好；软阴影能做逼近，但光追更好 |
| 间接光照（GI） | 光线追踪 | 靠 bounce 收集整个场景的光能传输 |
| 环境光遮蔽（AO）、透明、后处理反射 | 不同组件混合 | 各效果按特点选择组件，再混合到一起 |

> **提示**：SSGI 这类屏幕空间 GI 其实还是属于传统的那套——它在 screen space 里做了一些 GI 的东西，但并没有真正做到全局光照。

### 光追管线的独立性与实现

* **两条完全不同的管线**

    * 光栅化是顶点着色器、光栅化、fragment shader 这么一条 pipeline；ray tracing 是发射一些光线、光线放到硬件里去做遍历与重新调度、去跟场景求交、得到交点做 shading、然后在 bounce 上做迭代——这两个东西完全不一样。

    * ray tracing 的管线是没办法放到现在光栅化的框架里面的，所以管线级的混合很复杂。

* **逻辑简单、计算复杂**

    * 逻辑：生成 ray，然后去场景里遍历——碰撞到或者没碰到；碰撞到的话又有两个 case：找任意一个碰撞（any hit），或者找最近的那个碰撞点（closest hit），然后做对应的处理。

    * 复杂点：所有 ray 在场景里的遍历、还有它的方向都是各异的；ray 的调度（scheduling）、merging 在硬件上同步非常复杂——要做光线跟包围盒的相交、BVH 的遍历，这个是很难做并行的。

* **硬件与软件现状**

    * NVIDIA 做了大量努力、搞了十几年：OptiX 从 2010 年就已经提出（之前还有一些更早的原型）；现在终于是能在民用市场用上，但实现上还是非常复杂——一部分要硬件上的支持，一部分要软件上的支持。

    * 硬件：像 NVIDIA 的 Ada 架构，要做一个真正的实时光线追踪，需要用到 Tensor Core、RT Core，还用到了 micro-meshes 这些专门为光追做加速的定制硬件；具体怎么实现目前不可知——NVIDIA 对 RT 库、Tensor Core 的实现比较保密、没有任何 paper，这是他们的核心技术、核心竞争优势。

    * 软件：OptiX、Vulkan、DirectX 都有做光追的一些接口，可以直接调用；厂商再根据这些接口做软件接口和硬件的结合，使用者不需要去关心。

### 蒙特卡洛噪声

* **噪声来源**

    * 光线追踪本质上是一个蒙特卡洛积分：积分过程就要采样，而采样积分就一定会产生 noise。

    * 规律：spp（每像素采样数）很低的时候噪声就非常大；稍高一些也还是大；而且越黑的地方——直接光越难接触到的地方——噪声就更大。

    * 后果：这种结果没办法直接放到游戏画面或应用场景里去，于是就产生了很多用 AI 的方法做后处理、做加速的工作。

## AI 降噪、采样与预测

* **AI 降噪的基本形态**

    * 给到一张 noisy 的图像，用它的 G-buffer 做先验，然后像做平滑滤波那样去滤，得到一个光滑的东西——比如 3 spp 的 noisy 结果，滤波之后就可以得到光滑结果；这是一个很 promising 的技术。

### 预测滤波核

* **核预测（Kernel Prediction）**

    * > **定义**：2017 年迪士尼做的工作——用神经网络去为每个像素预测一个滤波核，属于图像域的降噪。

    * 输入之一是 G-buffer：基本的筛选逻辑是如果物体本身、或颜色空间上有一定的连续性，这个 filter 就会更好地拟合物体的内部——车就跟车内部的 pixel 作为一个滤波去做卷积，车外部的就不要去卷。

    * 另一输入是 noisy 的 input，作为滤波预测的素材：有了核的预测之后，再对 noisy input 做一次卷积，就可以得到去噪的结果。

    * 组件拆解：网络里有一部分 component 是可以跟 albedo 解耦的——把一些高频的颜色直接传回去，不需要神经网络去学 albedo 这个 component。

    * 训练：用了大量的预训练配对数据——noisy 的 image，加上高 spp 的无 noise 的 image，这两样东西配起来学，神经网络可以学得很好。

### 路径空间降噪

* **路径空间降噪**

    * 动机：图像域的降噪会延伸到路径空间——每个 pixel 不仅是一个 pixel，它其实有很多次 bounce 的光线路径。

    * 困难：路径空间太高维了——bounce 一次，路径上就有 normal、texture、颜色、position，维度太高，没办法直接放到神经网络里面去。

    * 方案（约 2021 年的工作）：对路径做一个 embedding（嵌入）——在高维的路径空间里找一个流形（manifold），然后对特征做一个流形上的学习。

    * 效果：学习之前，同一个像素上的那些特征是很零散的、没有相似性；在这个空间里做完特征学习之后，整个特征空间就变得更平滑了——这就是在路径空间做降噪。

### 采样端优化

* **与滤波的分工**

    * 滤波是采样完了、有了 noisy 的结果之后去做后处理；采样端策略反过来——想办法让采样的 sample 更「对」，直接得到一个更好的结果。

    * 依据是蒙特卡洛采样的一条基本规律：采样的 sample 越接近真实的概率密度函数（PDF）、越接近真实的积分，这个积分的 noise 就越低。

* **神经逼近 PDF**

    * 2019 年的一个工作：用神经网络去做分段——学一个分段的 PDF 函数去拟合真实函数，并假设神经网络拟合的函数可以不断地优化、不断地逼近 ground truth 的 PDF 或 ground truth 的入射辐射度。

* **强化学习采样**

    * 2020 年的一个工作，直观类比是 AlphaGo：AlphaGo 就是一个策略、用强化学习做策略的选择；采样时「很大的采样空间里往哪里投点可以达到最高的效率」同样可以看成强化学习的策略问题。

    * 结构：训练一个 Q network（价值网络）和一个策略，去做策略的选择，不断地在这个非常大的采样空间里面投点。

### Combiner

* **无偏与有偏的加权混合**

    * 问题：前面那些降噪的结果可能是它有偏的——低 spp 下它效果好；但在高 spp 下，path tracing 这个不偏的结果本身就已经更好了、已经比 denoise 过的结果误差更低，这时它就没法收敛：滤波的结果误差反而下不去。

    * 方案：把蒙特卡洛降噪前的无偏结果，和降噪滤波后的有偏结果，再用一个神经网络去把它们混合起来、做一个加权混合，得到最终的 output。

    * 收益：对那种非常光泽的玻璃、还有一些 glinty（闪耀类）的东西，它可以保证最后结果的收敛性更好、质量更高。

    * 理论性质：它可以做到 consistent——spp 无限增加之后，最终可以收敛到数学上正确的一个结果。

### 时空样本重用

* **时空样本重用**

    * 两个重用方向：时间重用——上一帧采样的样本这一帧其实也可以拿来用一下；空间重用——相邻像素之间的样本也可以去做一个借用；都是为了增加样本密度。

    * 做法：做一个「池子」，把空域和时域的 sample、一个像素旁边的 sample 都放到池子里面去；真正绘制的时候，再从这个池子里 random 地重采样一部分 sample，来提高 noisy input 的质量。

    * 收尾：重用完之后，还可以跟 denoiser 的结果做一个 combine，得到最终的结果。

    * 归属：这个东西是 AMD 在推进的，所以很大概率上会用到 AMD 的 denoiser 或降噪的一些东西。

### 帧预测

* **帧预测**

    * 思路：渲染一帧太慢，就可以用上一帧直接去预测下一帧——下一帧就不渲了；不仅用在 ray tracing 或 path tracing 的结果上，对光栅化的结果同样可以做预测。

    * 与视频插帧的区别：在绘制过程中，可以用很低的代价去获取下一帧的 G-buffer——基于下一帧的 G-buffer 跟上一帧的绘制结果一起预测下一帧的绘制结果，预测出来的质量会比原来 video 那套好很多。

    * 手段：用 motion vector（运动矢量）做像素级的 warp，还有相邻两三帧的连续重用。

    * 理解方式：相当于对下一帧的 G-buffer 做了一层 encoding，之后再去用于预测。

### 神经超分辨率

* **神经超分辨率**

    * 思路：画一张分辨率很低的小图，然后把它做一个上采样，用的也是神经网络的方法——低分辨率图上采样后，会把断裂的东西、细节不足的东西都补全。

    * 机理：主要用了历史帧——若干帧的信息叠加，想法是通过历史、用时域的信息去填补空域信息的一个缺失。

    * 工业现状：超分辨率用得很多，现在的 DLSS 还有 FidelityFX 都会用到插帧和超分辨率的混合，是工业级应用；DLSS 没开源，具体实现没办法讨论。

## 从物理驱动到数据驱动

* **两种驱动范式**

    * rendering 偏物理驱动（知识驱动）：有一个物理模型，真实地去追溯场景中的光线或别的物理过程；打到物体上时，对表面材质做 BRDF 建模，把过程搞出来。

    * CV 做感知更多是大数据驱动（数据驱动）：不知道中间这个模型怎么建，用很多数据集、很多标签喂给一个神经网络，让它自动去拟合一个规则。

* **完整管线的资产来源**

    * 一个完整的图形管线还要考虑数字空间的资产怎么来：可能是从真实世界通过 CG/CV 的方法感知或重建过来，也可能是人手动建出来的。

    * 真正的复合应用（比如自动驾驶）需要「真实世界 → 数字空间 → 虚拟空间」一条完整的链；理想状态是整个 pipeline 都通过计算机自动完成、不需要人太多参与——这就涉及 CG 和 CV、感知和绘制之间的关系。

* **两者交融**

    * 原来这两个东西比较泾渭分明；最近这两年两者混合的趋势非常明显，尤其是在神经场景表达出来之后。

    * 交融的代表：神经表达——用神经网络的方法做一个呈现的任务；可微渲染（differentiable rendering）——反过来，用神经网络的方法去建模。

### NeRF

* **神经辐射场（Neural Radiance Fields，NeRF）**

    * > **定义**：用神经网络去表达一个物体或场景的辐射场——在任意一个位置输入一个 XYZ 再加上一个方向，拿这几个坐标去查询神经网络，它可以返回这个位置的颜色和密度。

    * 渲染方式：有了颜色和密度之后，用一个 volume render：沿一条光线、用体渲染的方式去积分这条光线上的密度和颜色，得到最终 color——跟体绘制（或医学图像显示里的体绘制）原理非常类似。

    * 真实感来源：优化辐射场表达的时候直接用拍到的照片去做，所以可以画出真实感极强的画面——艺术家做模型、做重建、各种调色很难画出来的东西，对神经表达来说很容易。

    * 素材意义：可以直接对现实场景的东西做转换、把现实场景转换成神经表达，极大丰富素材库。

    * 落地：很多引擎（包括 UE5、Unity）已经提供了把 NeRF 这种神经表达直接在场景里画出来的功能；UE5 可以直接画、不需要转 mesh——转 mesh 走的是 SDF 那条路，因为 NeRF 直接转 mesh 质量是很差的。

### Instant-NGP

* **Instant-NGP（NGP）**

    * 与 NeRF 的相同点：在体积分那一块其实是一样的。

    * 表达区别：不是用一个整个的大 MLP 去表达辐射场，而是搞了很多 hash grid（哈希网格）、做小块小块的表达——每一个位置、一个局部空间里的 grid 存的是特征，查询时在局部做插值，得到神经特征之后再通过一个非常小的 MLP 解码出颜色和密度；更有局部性。

    * 速度收益：更新过程中只需要去更新局部的参数，所以速度非常快；再加上其他工程优化，基本上有了 NGP 之后，NeRF 的绘制和训练就可以接近实时——物品级的重建几秒钟就可以做好。

### SDF

* **有符号距离场（Signed Distance Field，SDF）**

    * > **定义**：同样用神经网络，但表达的是一个有符号距离场——每个表面位置都可以查询到从这个点到最近的一个 surface 的距离；与 NeRF 的区别在于 NeRF 表达的是密度场。

    * 抽面能力：SDF 场有一个等势面的结构——找到零等值面，然后用 marching cubes 这种方式把几何的面抽出来。

    * 流程：重建过程中还是用 volume rendering 去做可微的体优化；优化完之后有了一个 SDF 场，直接把这个面抽出来就有了几何，可以跟现在的工程化、跟传统管线直接搭上去。

    * 意义：手工建模现在可以省掉了——可以用一些扫描、一些照片，直接把 mesh 建出来。

### 可微光追逆渲染

* **基于物理的逆渲染（Physical-Based Inverse Rendering）**

    * 路线：不去优化这个 SDF 场，直接优化面片。

    * 机理：通过一些可微的光线追踪，把这个导数传回到具体的面片上来、去改变面片的位置；同时也能改变面片的纹理、材质——这些都是可以优化的。

    * 过程形象：像捏小球一样——一开始是有一个初始化的小球、上面有大量三角面片，然后根据一些图像不断优化，得到各种各样的 shape；这是自动建模、自动场景优化的另一个方向。

### AIGC 资产生成

* **跨模态生成**

    * 前面的方法还是 2D 到 3D、视觉模态内部的转换；AIGC 已经可以做到跨模态的资产生成和资产转化——输入一段文字去描述一个东西（「一只兔子在一堆松饼上、在一个盆子上」），它就可以生成相应的资产。

    * 边界：生成的还不是 mesh，是神经的场景和物体表达；最终可以转成 mesh，那是另一个 topic。

* **纹理生成**

    * 白模给定、用一些文字描述，直接产生这个模型上面的 texture——白模可能好搞，但再去优化纹理、做一个很精致的贴图是很费劲的，能自动生成就非常适合游戏管线。

* **灯光生成**

    * 灯光也有最新工作可以自动生成：给定一个室内场景，用神经网络去不断生成——除了灯光的亮度之外，还生成灯光的样式、不同的位置应该摆什么灯、摆什么样的灯。

    * 规范约束：室内场景有一些装修规范——屋顶上要摆吊灯、不能随便乱摆——这些规范神经网络都可以帮着做掉。

## 从图形计算到 AI 计算

* **传统 GPU 的两个计算单元**

    * 现在传统地做一个绘制，还是基于 GPU 的两个核心计算单元：一个是 compute（compute shader）；要出光追就是 RT Core——但 GPU 其实还是一个专用硬件。

* **NPU 直接画图**

    * 思路：有没有办法直接用一个更通用、更简单的结构——NPU——去直接画图；最近有一些工作把这个事情做出来了。

    * 流水线逻辑改动：传统流水线里，光栅化是基于面片化、以面片为单位去画；基于光追是以光线为单位去画——这些都是比较物理的、粒度比较细的绘制单元；这个工作把流水线变成按物体去画——先画背景；然后在上面画一个物体，把这个物体对场景的影响预测出来；接着画下一个物体，不断叠加，每一个层次、每一个步骤增加一个物体，直到整个场景画出来。

    * 核心难点：要去找一个方法、一个神经化的方法，把「物体对场景的光能传输变化」这么一个抽象的函数存下来——这就是这个网络要做到的事情。
