# 几何处理与模型减面

## 三维模型的表示方式

* **参数化曲线曲面**

    * > **定义**：用参数控制形状的表示——二维曲线的两个坐标都可以写成一个参数 $t$ 的函数；嵌在三维空间中的一张表面（surface）用两个参数控制：一个 $u$ 方向的参数加一个 $v$ 方向的参数。

    * 模型呈现为一片一片的曲面片；Bézier 曲线、曲面就是这个路数。

    * 在 CAD（计算机辅助设计）、工业化制造这一块非常常见、非常流行，大家一般用它来表示三维模型、去做建模。

* **多边形网格（mesh）**

    * > **定义**：用很多多边形拼接起来逼近连续表面的离散表示，这种多边形的离散化方式可以逼近任何复杂的表面。

    * 多边形最常见的是三角形，也可以是四边形、五边形等，建筑里六边面还比较常用；但最终渲染的时候，还是要转成三角形来表示。

    * 对网格表面贴上贴图、赋予一些材质（比如颜色），就可以拿去做渲染。

* **点云**

    * > **定义**：离散地在模型表面上"踩"了一些点的表示。

    * 一般来自三维扫描仪——激光扫描仪扫出来的数据就是点云。

    * 只是想大概看到模型的样子，点云也够用。

* **距离场**

    * > **定义**：在整个空间中，对任意一点计算它到真实表面的距离的表示；空间中一点离表面越近值越小，由近及远有渐变。

    * 这种表达本身没有表面的样子——没有真实的网格数据，很难直接把表面画出来，需要用专门的技术把它转化、提取出来。

    * 优点：对它做距离一类的查询会非常方便。

* **神经网络表达（NeRF）**

    * > **定义**：用神经网络表达模型的数据：输入五维信息——$x,y,z$ 表示三维空间中的一个点，$\theta,\phi$ 表示观察到这个点的方向（比如一条视线的方向）；输出这个点的 RGB 颜色，以及 $\sigma$（density，密度信息）。

    * 输出要结合体渲染的方式才能把模型可视化出来；前面那些表示——点云、距离场、网格、参数化曲线曲面——是结合光栅化（rasterization）或光线追踪来渲染的。

    * 流行的原因：输入只是一些照片、数据量比较少，通过训练这个神经网络就能获得一个可以从更多视角去观察的模型表达，非常逼真；同类的还有 neural 的 SDF 等表示。

| 表示方式 | 一句话理解 | 用在哪、怎么渲染 |
| :--- | :--- | :--- |
| 参数化曲线曲面 | 参数 $t$ 控制曲线、$u,v$ 控制曲面，模型是一片片曲面片 | CAD、工业化制造建模 |
| 多边形网格 | 多边形拼接逼近任意复杂表面，渲染时转成三角形 | 光栅化、光线追踪 |
| 点云 | 离散"踩"在表面上的一堆点，多来自激光扫描 | 光栅化、光线追踪 |
| 距离场 | 空间中每点存到真实表面的距离，查询方便，画表面要先提取 | 光栅化、光线追踪 |
| 神经网络（NeRF） | 5D 输入换出颜色与密度，少量照片训出逼真模型 | 体渲染 |

## 网格、贴图与 UV 展开

* **形状与颜色的分工**

    * 网格——点、线、面和它们的组合——表达模型的形状：轮廓长什么样、原型如何、曲面怎么起伏，全靠网格数据。

    * 颜色靠一张图片表达，一般叫贴图（texture）；要做的就是把这张图贴到网格的表面上去。

* **UV 展开**

    * > **定义**：把三维表面摊开铺到二维平面的过程——建立"三维表面上任意一点"到"二维平面上一点"的对应关系；因平面有两个维度（一个 $u$ 坐标、一个 $v$ 坐标）而得名。

    * 对应最好是一一对应：这样三维表面上任意一点，都能在图上找到它对应的颜色、对应的 pixel；实际使用中反过来也希望二维平面上的任意一个点在三维空间中有对应。

    * 实际上一个图里的点可以映射到三维表面上的不同点，这样能更好地压缩信息。

    * 把复杂的三维表面摊到平面上、还能保持一一对应，往往需要对模型做 cut——把它切割成一片一片的（比如一大片对应脸部，另外两片是两只耳朵）。

    * 渲染时逐个三角形、逐个点去着色，就能从贴图里查询、获取对应的颜色，把模型的样子画出来。

## 网格的连接关系

* **连接关系**

    * > **定义**：把网格形成一种 graph（图），只不过除了点和边之外，还加上了面。

    * 网格不一定是三角形网格：四边形、五边形都可以，建筑里六边面还比较常用。

* **度数（degree）**

    * > **定义**：一个点相邻多少条边。

    * 也有人用一个点相邻多少个三角形来表示度数，这种说法常写作 valence。

    * > **易错点** ⚠️：顶点的"度"在网格文献里有两种口径——相邻边数，或相邻三角形数（valence）。两种说法都存在，读文献先看它怎么定义。

* **边界与内部**

    * 一条边如果只相邻一个三角形，一般就是边界边；如果相邻两个三角形，那它一般在内部——这是对流形模型而言的划分方式。

    * 边界上的点，它相邻的边数和相邻三角形的数目是不一样的，所以讲一个点的度数（或 valence）还是得根据上下文来辨别。

* **邻域**

    * 一阶邻域：通过一条边就能直接到达的点——围着中心点的"这一环"；这一环里的边，有时指从中心点连出去的边，有时指环上的边，还包括环里面的那些三角形。

    * 二阶邻域：走两条边（两步）能够到达的点，以及这样构建出来的整个局部网格里包含的信息。

## 流形与非流形

* **流形（manifold）**

    * > **定义**：表面网格是（二维）流形，当且仅当表面上任意一点的局部邻域都能同胚地建立与二维圆盘的一一映射——能摊平到一个圆盘上。

* **点的非流形**

    * 看一个点以及它一阶邻域里所有相邻的三角形：这堆三角形如果能围出一个环——边界是一个环——那它就能映射到圆盘上，没问题。

    * 如果像两把扇子只在顶点处相接那样、边界是两个环，那就是非流形。

    * 还有一种情况：某个点的邻域摊是摊开了，但边界并不是一个简单环——像麻花一样拧了一圈再接回来——它同样不同胚于圆盘，也不是流形。

* **边的非流形**

    * 一条边如果相邻的不只是两个三角形，而是三条、四条、五条等等，那也是非流形。

    * 对表面网格来说，非流形一般是点的非流形和边的非流形这两类。

```text
一条边挨着几个三角形？（对流形网格而言）
   1 个 → 边界边        2 个 → 内部边        3 个及以上 → 非流形边
```

## 欧拉–庞加莱公式

* **欧拉–庞加莱公式**

    * > **定义**：构建网格的点、线、面以及其它拓扑信息之间的一个恒等式；左边是纯粹的几何元素计数，右边把"几块、几个柄、几个洞"这些拓扑信息补进来，两边永远相等。

    * 记号：$V$ 是网格里顶点的数目，$E$ 是边的数目，$F$ 是面的数目——$F$ 是通用（general）多边形面数：模型里不管有三角面、四边面还是五边面，都算进去。

    * $S$ 连通数（number of components）：模型由几块互相连通的表面组成；一个模型有两块互不相连的表面——外面的环到不了里面、中间没有任何连接信息——连通数就是 2；一个球面，连通数就是 1。

    * $G$ 亏格（genus）：通俗地讲是把模型切开、切几刀它还连在一起；球面是 0——再 cut 一刀它就能整个翻开；环面是 1——切一刀它还是连在一起的。

    * $H$ 洞数：球面没有洞是 0；在球面上抠两个洞，它就带了边界、出现两个环，洞数就是 2。

$$V - E + F = 2S - 2G - H$$

## 常用几何量

* **边长**

    * > **定义**：两点一线，这条线段的长度就是边长。

* **面积**

    * 三角形面积很直接；三维空间中的四边形经常不是一个平面，它可能是个翘起来的曲面，这时算它的面积有一定的歧义。

    * 大家一般会把四边形拆成两个三角形来算，也可以拆成多个三角形，取决于具体应用。

    * > **易错点** ⚠️：三维空间中的四边形四点常不共面，"四边形的面积"并没有唯一答案——拆成两个三角形只是其中一种约定，换一种拆法结果可能不同。

* **二面角**

    * > **定义**：一条边相邻着两个三角形，这两个三角形所在平面之间的夹角。

    * 这个量非常常用，也是后文判定尖锐边、保持特征的判据。

* **法向**

    * > **定义**：三维表面上任意一点，垂直于该点切平面的那个方向，就是这个点的法向的朝向；它还需要是单位长度。法向就是平时说的法线。

* **相交**

    * 自相交：模型自己跟自己交叉——模型的面片自己插起来了（穿模）。

    * 另一类是一个模型跟另一个模型交叉：比如一个 human 的三维模型跟一个 box 交叉，一个模型深入到另一个里面去了。

* **退化单元**

    * 单元就是点、线、面这些元素；从拓扑角度来说，三个点、三条线段就只能表达出一个三角形，而几何上它可能是退化的。

    * 退化三角形：面积为零的三角形，可以退化成一条直线，甚至退化成一个点。

    * 退化边：边长等于零的边。

* **包围盒（bounding box）**

    * > **定义**：能把一个三维模型框起来的盒子（比如一辆汽车三维模型外罩的长方体）；有轴对齐（axis-aligned）的，也有非轴对齐的，都是一个长方体。

    * 包围盒跟被包围三维模型的紧致程度有关系；它的计算方式有很多种。

    * 用途：三维数据的模型大小差别可以非常大——面积可以接近于 0，模型放缩得非常大时又接近于无穷大；希望算法对各种尺度的模型都能处理，一般做法是把设置的算法参数跟包围盒的某个尺寸挂钩（比如以包围盒对角线的长度做归一化的基准），这样算法就跟模型的尺度基本不相关，有力提升算法的鲁棒性。

* **曲率**

    * > **定义**：描述模型表面弯曲程度的量。

    * 曲线上任意一点的曲率只有一个；对三维模型表面上一点，其实可能有无数个曲率——因为通过一点可以画无数条曲线，每条都有自己的曲率。

    * 在切平面（tangent plane）的参考下，可以从无数个曲率里辨别出两个主曲率（principal curvature）：一个是最小的曲率，一个是最大的曲率。

    * 主曲率的计算跟法向的定义非常相关。

## 特征的提取与保持

* **特征（feature）**

    * > **定义**：因不同的应用而不一样的概念，对它的理解需要真的结合上下文；同样的词在不同的算法里可能指完全不同的东西。

    * 例子：特征保持的六面体网格化工作中，"特征"指对模型表面做一个划分后提取出的 corner（角点），这套方法要"保持"的就是它们。

    * 读文献遇到 feature 时，先看那篇文章的应用背景是怎么定义它的。

* **尖锐边的判定**

    * 机器"看"出模型上棱角分明的地方，做法是先提取 corner，或者说比较尖锐的边。

    * 判据是二面角：一条边两侧两个面的夹角，如果离 180° 比较远——比如 120°、150°，或者 90°、60°——就认为它比较尖锐。

* **特征的结构**

    * 这些尖锐边会形成一个 graph；边与边之间、曲线与曲线之间又会形成一些 corner——一个 corner 上可能连着好几条 sharp 边。

    * 这些 graph 还有可能把表面划分成不同的区域，区域之间的边界就是这些尖锐边。

    * 做网格处理时保持特征：该尖的地方还是尖，该分开的区域还分开。

## 形状差异与网格缺陷的度量

* **Hausdorff 距离（豪斯多夫距离）**

    * > **定义**：衡量两个形状差异的距离——一个形状里"离对方最远的那个点"离对方有多远，Hausdorff 距离就是多少；它抓住的是最坏情况下的形状差异。

    * 算法：把 $A$ 上的每一个点都去找它在 $B$ 上最近的点、记下这个最近距离，所有这些距离里取最大值——这就是从 $A$ 到 $B$ 这一个方向的 Hausdorff 距离；反过来从 $B$ 到 $A$ 也可以同样算一遍。

    * 尤其在衡量几何处理算法效果的时候，经常用到它。

$$H(A,B)=\max_{a \in A}\ \min_{b \in B}\ \lVert a-b \rVert$$

* **面的翻转（flip）**

    * 前提：先对面方向做统一约定——所有三角面对顶点做一个排序（顺时针或者逆时针）、大家都取同一个方向；根据这个统一的方向去算平面的法向，所有面的朝向就都是一致的。

    * > **定义**：若某个面的法向朝向跟周围的面都不一样了，就说这个面翻转了。

    * 危害与 UV 直接相关：UV mesh 本身也是个网格，跟三维网格的面一一对应；如果 UV 网格里有一块发生了翻转（比如另外一个三角形覆盖了它），纹理上同一个图像点就同时映射到了两个三角形上，一个 color 就被分配到两个不同的地方，渲染出来这一块的颜色可能莫名其妙就跑到那里去了。

    * > **易错点** ⚠️：翻转最典型的受害者是 UV——纹理上同一个点被映射到两个三角形上，颜色被分配到两个地方，渲染时就"串色"了。

* **凸包**

    * > **定义**：能把一组点都包起来的、最简单的形状；二维里就是一个凸的 polygon。凸包跟凸集合的定义相关。

    * 凸多边形：里面每个内角都小于 180°，而且在它内部任意两点做线性插值、结果仍在这个凸多边形内部——这正是凸集合的性质。

    * 直观想象：拿一根橡皮筋从一个很大的区域开始收缩，直到不能收缩为止——最外圈那些边界点勾勒出来的轮廓，就是这个集合的凸包。

    * 三维的 mesh 同样有凸包的概念。

## 网格数据结构与半边结构

* **网格存什么**

    * 只看网格本身：知道点——每个点由三维坐标定义，这就是模型的轮廓形状；再加上三角形——它定义了这个 mesh 的连接关系；知道这两样就能恢复出完整的信息。

    * 除了位置，每个顶点上还可以存一些其他信息：颜色、UV，甚至动画模型里的蒙皮权重；再就是基本几何单元（边、面）的连接关系：这个点连接的边、面有哪些，这条边由哪几个点组成，这个面由哪几个点组成。

    * 数据结构设计是简洁性和效率之间的一个平衡——整个图形学其实就是在平衡两件事：表达逼真的效果，和希望用尽量快的速度；连接关系在程序实现时怎么取舍，对算法的设计有非常大的影响。

    * 考虑平衡主要有三方面：存储空间；如何能快速地获取数据；数据的更新——数据发生更改时如何快速地改掉，并且保持数据的全局一致性、局部一致性。

* **半边结构**

    * > **定义**：把一条边拆成两个半边来表示、这两个半边方向相对的网格数据结构；构思很巧妙，当然也有一点复杂性。

    * 一个顶点连着很多半边，只存一条出半边的索引就够用；一个面也只需要存一条它包含的半边的 id。

    * "左面"指沿半边方向看过去左手边的那个三角形：两个共享一条边的三角形，沿公共边各对应一条方向相反的半边，互为对边——比如从 v1 指向 v2 的半边，左面是 F0。

    * 靠这几个 id 可以非常快速地做数据的索引；最常用的例子是遍历一个顶点的一环邻域。

| 存储对象 | 存的内容 |
| :--- | :--- |
| 顶点 | 位置；一条从它出发的半边的索引 |
| 半边 | 起始点的索引；左手边那个连接面的索引；同一面内上一个、下一个半边的索引 |
| 面 | 它包含的某一个半边的索引 |

```text
从顶点 v 出发
  │ 取出 v 存的那条出半边 h
  ▼
跳到 h 的对边
  │ 对边是能拿到的
  ▼
在对边所在的面里取"下一个半边"
  │ 这条 next 半边又是从 v 出发的
  ▼
回到"跳对边"那一步，依次往复
  绕 v 一圈，v 的所有相邻面就都被提取出来了
```

## 减面的动机与 LOD

* **为什么要减面**

    * 游戏画面里的建筑、飘在空中的气球、花等全都是三维模型数据；数据量越大呈现的效果越逼真，但会对硬件和计算造成负担。

    * 手机游戏最典型：手机的存储、计算能力都非常有限，模型的数据大到甚至大于内存，就不可能有任何游戏体验；所以希望尽可能压缩数据的大小，同时尽可能保证一定的渲染效果。

* **LOD（Level of Detail，层次细节渲染）**

    * > **定义**：离视角越近用更多的数据、离视角越远用更少的数据的渲染手段。

    * 例子：一个约 5000 多面的原始白膜（没带任何材质的 mesh），近处看需要这么高保真的模型；视角拉得越来越远时，可以用 1000 多面、300 多面、80 多面甚至 20 多面的版本——远看它还是个球的样子。

    * 这些不同层级的数据一般要提前计算好；它们是怎么算出来的非常有讲究——正是模型简化要解决的问题。

* **网格模型的两个事实**

    * 面数的数目对渲染效率的影响非常大。

    * mesh 还有对应的一个二维的 mesh，也就是 UV mesh——两者的面是一一对应的，只是顶点的位置不一样。

## 减面的两条路线

* **保纹理的简化**

    * > **定义**：简化时只剪网格和 UV、不对纹理做任何操作，渲染时依然调用原来的那张纹理的简化方法。

    * 优点是省数据：一张贴图很大，能重用原来的贴图，就省掉了这一块图片的大小。

    * > **提示**：剪 UV 的时候，UV 的排布要尽可能地跟原来的排布一致——要保持从 UV 获取 texture 再贴到三维表面的一致性；原来贴图画的是一只站在花坛里的企鹅，简化完了之后它也得是这个外表。

    * 效果示例：从 18000 多个面简化到 9000 多个面、1000 多个面、900 多个面等；数据量越小失真越明显——模型里是花的地方、镂空的地方，在另一个模型里可能就是连在一起的。简化时实际上是尽可能保持外观一致，数据量的减少不可避免会带来损失，能做的是把损失降到最小。

* **不保纹理的简化**

    * > **定义**：剪完了面之后不用原来的纹理的简化方法——模型的连接关系已经完全打乱、重新组织了一个新的网格，UV 网格跟原来的相比 pattern 已经完全变了，需要再生成一张新的贴图来对应现在的网格。

    * 优点：可以获得更加简单的简化效果、同时跟原来的模型还挺相似——面数可以减到更少（同一个模型这里压到 290 多个面，保纹理的例子里是 900 多个）。

    * 这条路非常复杂，包含几个大的步骤：重新网格化 → 展 UV → 生成贴图，每一步内部都各有一堆方法可选。

| 对比项 | 保纹理的简化 | 不保纹理的简化 |
| :--- | :--- | :--- |
| 简化时动什么 | 只剪网格和 UV，纹理不动 | 连接关系完全打乱，重组新网格 |
| 渲染用哪张贴图 | 原来的那张，原样重用 | 重新生成、与新网格配套的贴图 |
| UV 排布 | 尽量与原来的排布一致 | pattern 完全变了 |
| 例子里压到的面数 | 900 多 | 290 多 |
| 流程 | 逐边坍缩等简化算法 | 重网格化 → 展 UV → 纹理烘焙 |

## 保纹理简化的方法版图

* **基于 QEM 的逐边坍缩（主流）**

    * 基于 QEM（Quadric Error Metric，二次误差度量）这种 metric 的简化方法，基本上可以说是保纹理简化方法的核心或主流——没有几百篇也得有几十篇这样的文章和思路。

    * 做法一般是通过逐条边地对每条边进行坍缩，来达到逐步减边、逐步简化的效果。

* **聚类式的简化**

    * 对输入的模型，根据一些衡量指标把三角面做聚类；聚完之后每一类的三角面可以用一个多边形表示出来；再对这个多边形重新做三角形划分，面数自然就减下来了。

* **四边形网格的简化**

    * 针对网格单元是四边形的模型——而且不一定非得是正四边形，可以是通用的四边形。

* **机器学习减面**

    * 用机器学习的方法给模型减面，同时尽可能保持原模型上某些顶点的位置。

    * 它实际上可以看成一种重新网格化的方式，应该是不会保持 UV 的。

* **内蕴三角形（intrinsic）的简化**

    * 前面几个工作里的三角形是外蕴三角形：每个三角形由三个点、三条边定义，边是欧式空间中的直线。

    * 内蕴三角形的一条边可以是欧式空间中的一条折线——用一堆折线来表达一条边。

    * 应用不在渲染，更多是在三维模型表面上做几何计算：表面上点的测地距离（geodesic distance）、对 mesh 做有限元计算、解 PDE 方程等。

## 保纹理减面的问题定义

* **模型背后的三份数据**

    * 渲染出来的模型背后其实存着三份数据：三维网格数据；UV 数据——它本质是一个二维网格，三角形面数跟三维网格完全一样，只是坐标从三维变成了二维；再加一份纹理贴图。

    * 渲染时不管走光栅化还是 ray tracing，都是在屏幕空间里逐三角形地工作：查这个三角形应该怎么上色，顺着它查到 UV 空间，再查到纹理坐标上对应的纹理像素值，然后染色。

* **输入**

    * 一个网格模型——可以是二维的也可以是三维的，不过一般来说都是三维的；它带着 UV（现实中可能带也可能不带，一般假设它带着）；还有对应的纹理贴图。

    * 另外还有一个输入：用户希望的目标面数，或者目标面数相对输入面数的比值——这是比较常用的、用户喜欢的参数设置。

* **输出**

    * 简化后的三维网格，和它对应的 UV 网格；纹理材质不会输出——因为输出模型用的就是输入那一套纹理材质。

* **无形中的要求**

    * 总要求：减面、压数据量的时候，让渲染出来的最终效果跟没压缩之前一样；有时候压得太狠确实保不住了，但要尽可能让它一样。

    * 保拓扑：输出模型跟输入模型的拓扑是一致的。

    * 不自相交：如果输入模型没有自相交（穿模），也希望输出没有。

    * 表面距离尽量小：模型的表面嵌在三维空间里，输入的表面和输出的表面之间可以定义各种距离（欧氏距离也好、别的距离也好），希望这个距离尽量小；严格说这不叫"保距离"，是让距离尽量小——距离小到零，两个模型就没有差别了。

    * 三维模型不只会拿去做渲染，还会拿去做动画、做物理模拟，那些应用可能会有额外的要求；具体问题都可能有具体的要求。

* **业界地位**

    * 这类方法其实二三十年前就有了，但一直到今天都还是业界做数据压缩比较偏好的方法；游戏行业除非实在没有别的办法，一般都更偏好它，因为它更省数据。

    * 在游戏里，数据量的大小对性能、对质量会产生非常多的影响；业界在优化数据量这件事上花的时间、精力、人力物力和计算资源是非常大量的——不说最多，也是数一数二的地方。

## 通用简化框架

* **框架主线**

    * 整个算法围绕"简化操作单元"展开；这个框架非常通用——不能说百分之百，但绝大部分保纹理的减面方法基本上都遵循这么一套框架。

    * 拿到输入模型之后，先定义清楚简化操作单元是什么；然后提取输入模型里所有的操作单元、计算它们的误差——操作单元是朝"降低模型复杂度"去的，一执行就会减少面数，面数一减少模型必然发生改变，模型一改变就能把这次改变算出一个误差来。

    * 误差都算完之后，根据它们构建所有操作单元的优先队列。

    * 主循环：只要队列不为空、并且还没有达到停止条件，就取出队列里的第一个操作单元，检查它是否有效；没通过检查就重复上面的动作、继续 pop 下一个；通过了就执行这个操作单元，并更新跟它相邻的那些操作单元、更新它们的误差、把它们加回优先队列；这样循环往复，直到达到停止条件为止。

```text
输入：带 UV 的三维网格 + 纹理贴图 + 目标面数（或面数比值）
   |
   v
定义简化操作单元（如：每一条可折叠的边）
   |
   v
提取所有操作单元，并计算每个操作的简化误差
   |
   v
按误差从小到大构建优先队列
   |
   v
主循环：
   队列为空 或 已满足停止条件？
     |-- 是 --> 输出简化结果，结束
     |-- 否：
           pop 队首操作单元（当前误差最小者）
           有效性检查不通过？
             |-- 是 --> 丢弃该记录，回到队首判断
             |-- 否 --> 执行该操作（如一次边折叠）
                        更新受影响的相邻操作单元及其误差
                        带时间戳重新加入优先队列
```

    * 几乎所有比较实用的保纹理简化方法都遵循这个框架；这个框架虽然简单，但有效、很实用。

* **停止条件**

    * 用户自己根据具体问题设置：比如已经简化到了想要的面数；或者简化后的渲染效果已经差到不能接受、不能再差了。

    * 最简单的、也是最常用的停止条件，就是目标面数或者面数比值。

## 简化操作单元

* **删点（vertex removal）**

    * > **定义**：选中某个点把它删掉，它一阶邻域里的所有三角形都跟着删掉；删完之后那里就成了一个多边形，最终要整个模型保持三角网格，所以要对它做一次重新三角化、重新连成三角网格。

    * 面数影响：删一个点就减少了两个三角形（例：原来 7 个三角形，删掉一个点、重新连完变成 5 个）。

* **塌边（edge collapse）**

    * > **定义**：把一条边的两个端点合并成一个点，这条边就没了，与此同时这条边原来相邻的三角形也被删掉。

    * 最常见、最常用的一种简化操作；被删的相邻三角形画出来是两个，实际中可能是一个或者多个，取决于模型的拓扑长什么样。

    * 这个算法对拓扑其实不敏感，它是个很通用的算法。

* **合并相近点**

    * > **定义**：输入模型里两个点之间并没有连接的边、但它们在空间里非常近，根据距离把它们合起来。

    * 它不会减少三角形的数目，只用它自己其实没什么用处；这种操作往往需要跟其他真正能减少面数的操作联合使用——比如先把相近的点合起来，会对后续的塌边有帮助、做得更顺。

    * 最常见的用武之地：输入模型里有些点是重复的——坐标一模一样、只是 id 不一样——这时候把它们 merge 起来，方便以后的操作。

* **其他操作与实现说明**

    * 还有别的操作单元，比如一次性移除整个三角形、一次移除一批三角形等。

    * > **提示**：不管选哪种操作单元，实现时都要遍历顶点、访问邻接信息；计算新顶点位置肯定要用到周围的信息，这绕不开，但遍历本身不一定非用半边结构——无非是把所有信息都存储起来，一样容易遍历，它本质上就是一个 graph。

| 操作单元 | 怎么做 | 对面数的影响 | 使用要点 |
| :--- | :--- | :--- | :--- |
| 删点 vertex removal | 删掉一个顶点及其一阶邻域内所有三角形，再把留下的洞重新三角化 | 删一个点约减两个三角形（例：7 → 5） | 需要重新三角化 |
| 塌边 edge collapse | 把一条边的两个端点合并成一个点，边随之消失 | 删掉该边相邻的三角形，一般两个 | 最常见最常用；对拓扑不敏感 |
| 合并相近点 | 把没有边相连但距离很近的两个点合并 | 不减少三角形 | 要与塌边等操作联合使用；常用于合并重复点 |

## 误差的定义

* **核心就两点**

    * 排序：输入模型里有那么多条边，先剪哪条边、再剪哪条边，这个顺序会大大影响最终简化出来的模型的质量。

    * 新顶点位置：collapse 合并两个点的时候会形成一个新的顶点，这个新顶点的位置对简化结果有非常大的影响——模型的外形基本上就是被点的位置大致勾勒出来的，再加上点与点的连接关系，渲染出来才是一个完整的三维模型。

* **几何误差**

    * 大部分误差研究是几何误差：衡量折叠之前和折叠之后这两个 mesh 的区别，可用的量有距离、距离的平方、法向、曲率等等。

    * Hausdorff 距离的连续定义：蓝色物体到绿色物体，每个点找对方最近点取最大，再从绿色物体到蓝色物体同样做一遍，两个方向各自的最大值里再取最大的；问题是这个距离真正算起来很慢，有时甚至无法精确算出来。

    * 比较常用的是基于采样的方法来近似：对折叠前后的两条曲线各采样一些点，算这两组点对之间的离散 Hausdorff 距离，或者算视觉领域里经常用的 chamfer distance；近似的具体做法有很多种。

    * > **易错点**：这种采样近似不是贝塞尔曲线式的计算——它跟贝塞尔曲线差别很远，完全是不同的定义。

* **视觉误差**

    * 除了几何上的量，还有工作把视觉因素加进来考虑：从不同的视角去看模型（比如茶壶），柄那种比较凹陷、被遮挡比较多的地方是看不到的，把视角离散化之后统计会发现这些区域被看到的视角数目相对少；而外凸的区域几乎哪个视角都看得见。

    * 有工作利用这种信息对整个模型做了一个"视觉影响"的估计，再把这个估计作为某种度量结合到 QEM 上面去指导简化——相当于给所有的边又做了一层区分度。

## 二次误差度量（QEM）

### 平面方程回顾

* 三维平面公式是 $ax + by + cz + d = 0$；满足这个公式的所有点都在这组系数所定义的平面上，当然也要求 $a^2 + b^2 + c^2 = 1$，也就是把法向归一化。

* 一个点在这个平面上，等价于它的齐次坐标跟平面系数做点积等于零：$v^\top p = 0$，其中 $v = (x, y, z, 1)^\top$、$p = (a, b, c, d)^\top$；点积等于零就是这点到平面的距离为零。

### QEM 的定义与塌边的连接

* QEM 是二十五年、二十六年前的一个算法，直到二十多年后的今天依然是工业界最常用、最经典的方法，也可以说是最实用的方法。

* > **定义**：QEM（二次误差度量）——一个顶点相对一组平面的误差，等于它到每个平面距离的平方和，$\Delta(v) = \sum_i \left(v^\top p_i\right)^2$；平方和越小，误差越小。

* 与塌边的连接：每个点在网格里相邻一组三角形，三点唯一确定一个平面，所以每个点都有相邻的一组平面；这个点到它自己相邻的这组平面的距离肯定是零——它的 QEM 值就是零；但两个点合并成一个新的点之后，这个新点就不一定还落在原来那一组平面上了。

* 于是定义：新点到原来这组平面的 QEM 值，就是这次塌边产生的 error——就这么简单。

* 去 remove 一个三角形、或者重新三角化式的 remove 一个点，稍微改一改也可以灵活地用上 QEM；而且 QEM 不仅能用在三角网格上，也能用在其他网格上。

### 矩阵化

* 把 $\Delta(v)$ 展开：每个平方项是 $v^\top p_i$ 再乘 $v^\top p_i$ 的转置，也就是 $v^\top p_i p_i^\top v$；因为 $v$ 只有一个，可以把求和挪进去——前提是把 $v$ 整成齐次坐标，也就是四维的 $(x, y, z, 1)^\top$：

$$\Delta(v) = \sum_i v^\top \left(p_i p_i^\top\right) v = v^\top \bar{Q}\, v, \qquad \bar{Q} = \sum_i p_i p_i^\top$$

$$\bar{Q} = \sum_i
\begin{bmatrix}
a^2 & ab & ac & ad \\
ab & b^2 & bc & bd \\
ac & bc & c^2 & cd \\
ad & bd & cd & d^2
\end{bmatrix}_i$$

* 把矩阵元素重新命名成 $q_{11}, q_{12}, \dots$；$v$ 就是 $x, y, z$ 加一个 1，直接把它展开，得到的就是一个标量——这一坨加起来就是 QEM。

### 塌边上的完整用法

* 折叠之前：输入模型的每个点，只要有这个点、有它相邻的一组平面，就可以构造出一个 Q。

* 折叠之后：直接把两个 Q 加起来 $\bar{Q} = \bar{Q}_1 + \bar{Q}_2$，作为新顶点 $\bar{v}$ 的 QEM 矩阵；于是这次塌边的误差就是 $\Delta(\bar{v}) = \bar{v}^\top \bar{Q}\, \bar{v}$。

* > **易错点** ⚠️：$\bar{Q}_1 + \bar{Q}_2$ 并不严格等于新顶点真实的 Q——两个顶点共有的那两个三角形平面被重复计了一次。工程上先忽略这点误差，换取"不用重算平方和"的速度；对精度有点影响，但可以先不管。

* 更重要的一件事：$\Delta$ 是关于 $\bar{v}$ 的二次形式，可以把整个东西整成一个优化式子——顶点位置对误差的影响非常大，可以比较容易地求得使误差最小的那个 $\bar{v}$：对 $\bar{v}$ 的三个分量 $x, y, z$ 分别求偏导、令偏导等于零就是极值（二次函数的极值点只有一个）。

* 比如对 $x$ 求偏导（$\bar{Q}$ 对称，写出来就是）：

$$\frac{\partial \Delta}{\partial x} = 2\,(q_{11}x + q_{12}y + q_{13}z + q_{14}) = 0$$

* 这是一个关于 $x, y, z$ 的线性方程；再对 $y$ 求偏导、对 $z$ 求偏导，就构建出三个线性方程；补上齐次坐标 $w = 1$ 这个约束，凑成一个 $4 \times 4$ 的线性方程组；矩阵里每个系数都是已知的，求逆就出来了。

* 求出位置之后，完全可以带回 $\Delta(\bar{v})$ 把这次操作的误差算出来——每一个简化操作（每一条边的折叠）都能算出一对新东西：最优顶点位置和它的误差。对输入模型提取所有的边、算出每条边折叠后的误差、按误差排序建优先队列、进入主循环，这就是 QEM 的完整用法。

### 解不唯一的三种情况

* 这套东西听上去很漂亮，但有的时候会有问题：这个解可能不唯一，取决于矩阵的形式，基本上可以归为三种情况。

* 第一种：有唯一的最小值解——就一个点、一个值；这种情况下矩阵是可逆的，能求出一个最小值点，皆大欢喜。

* 第二种：解是一条线——被折叠的这条边两个顶点所相邻的那些平面可以归成两类，每一类各自都是共面的（都在一个面上），最终实际上是在对两个互成夹角的平面求"距离平方和最小"的点，这样的点构成一条线。

* 第三种：那组平面全部共面、甚至全部平行，那解空间就是一个面。

* 后两种情况需要做一些选择：共线的时候，可以从这条边的两个端点（包括中点）里选一个误差最小的当新顶点；共面的时候也是选一个点交差——总之别让程序在退化情形上卡住。

## 有效性检查

* **检查的定位**

    * 有效性就是"做了这次简化之后，结果还能不能接受"；最简单的情况下可以不做任何有效性检查，最复杂的时候可以有一串检查——满足一、再 check 二、三、四、五，全都过了才算通过。

    * 下面是实践中比较有价值、比较常用的检查，是一种相对 cheap 但实用的检验方式。

### 距离检查：体素近似

* 简化之前和简化之后，局部表面的形变不能太大——局部那个表面跟简化之前的表面之间的距离（Hausdorff）超过很大就说明造成了很大的形变，希望限制这种距离。

* 直接算 Hausdorff 又耗时又费力、有时甚至无法精确算出来，所以有一种比较实用的近似：对输入模型做体素化（voxelize），并且用不同大小的体素格子做成层次化（hierarchical）的结构；随着简化的深入，让体素越来越大——也就是越来越宽容更大的距离偏差。

### 拓扑检查：link condition

* 希望简化之前和之后拓扑是一样的；最粗暴的做法是把连通数、亏格数、洞数都算出来、对比简化前后这些量是不是一样，但那太慢了。

* link 是每个顶点周围一圈相邻的元素——相邻的顶点、边、三角形。

* 判据：塌边之前先检查 $v_1$ 的 link 和 $v_2$ 的 link 的交集，是否等于边 $v_1 v_2$ 自己的 link；相等，这次折叠就不改变拓扑；不相等，就拒绝。

* 典型的失效场景：折叠这条边之后会产生非流形的三角形——折叠之前拓扑条件是满足的，折叠之后拓扑变了，就不满足了；通过这个条件可以比较快速地检验拓扑改没改变。

### 法向翻转检查

* 折叠之后不希望面发生翻转：原来一组三角形的法向都朝向一致（相互的点积都是正的），折叠之后其中某个三角形朝向反了，渲染时（尤其是单面渲染）会产生比较差的渲染效果，所以要经常避免这种情况。

* 常用的简单 trick：测试新表面那些三角形的法向，跟旧面法向做点积、看夹角，检查有没有发生翻转，用这种策略做一个快速的筛查；它并不能完全保证，但这是一个简单、快速的检查方法。

### 自相交检查：BVH 加速

* 如果输入模型本身没有穿模（自相交、交叉），希望最终输出也没有——穿模同样会让渲染质量很差，尤其单面渲染时看上去黑乎乎的；当然，如果输入模型已经有穿模了，那确实不好弄，这个不管。

* 自相交其实分两种情况：一种距离比较远——两块在流形空间上相距很远的区域相交；另一种是近距离的——在临近的 neighborhood 里自己跟自己相交，这种情况检查起来会稍微麻烦一点。

* 做法：把每个三角形组织成一个 BVH 这种加速结构，建 AABB 包围盒（bbox）来加速计算，让需要两两 check 的三角形对（pair）的数目大大减少；最粗暴的就是每个三角形 pair 都检查一下有没有真的相交、有没有 overlap。

* 现在也有一些公开的库做这个事情——不过真要把它做好，其实不是那么容易的。

### 数值鲁棒性检查：包围球兜底

* 做检验的时候坐标一般都是浮点数，浮点运算有精度问题；前面解顶点位置的时候，由于数值误差，那个点有可能直接飞出去。

* 一个比较粗暴的防止方法：预先定义一个包围球（bounding sphere），限制优化出来的点必须在这个球里面；一旦超出，就说明这个点因为数值误差飞出去了——那肯定是不对的、ugly 的——直接拒绝这个操作。

## 执行后的误差更新与时间戳

* **执行之后为什么要更新**

    * 操作执行完了之后要注意：它周围的那些三角形都发生了变化；而所有这些三角形面对应的平面也都变了——一个三角形定义一个平面，三个顶点里有一个的位置变了，这个平面就变了。

    * 最原始的论文：直接用 $\bar{Q}_1 + \bar{Q}_2$ 表示新顶点的误差，其他不更新。

    * 也可以用新顶点的误差去 update 周围受影响的边；甚至可以完全不 update——不 update 速度更快，但随着简化的边数越来越多，它会偏离原来的 surface 越来越远，那个 error 离真正想要的 error 就越来越远。

    * 所以很多时候希望更新一下：重新计算与它相连的、受影响的那些边的简化误差——误差更准，最终简化出来的效果更好一点；更新完了，把这些边带着新误差加回优先队列。

* **时间戳**

    * 这里面有个小坑：一条边可能被加入优先队列好几次。

    * 处理办法是放一个时间戳：每条边维护最新的时间戳，从队列里拿出来的时候对一下时间——如果它不是最新的，说明这条边已经被 collapse 过了、已经不存在了，直接丢掉就行。

    * > **易错点** ⚠️：优先队列里的旧记录不会自动消失。一条边被更新重入队之后，旧的那份记录还躺在队列里；不对时间戳，就会把一条已经不存在的边再 collapse 一遍。

## 边界保持

* **问题**

    * 模型有边界时（最简单的例子是一张正方形的三角网格片，希望简化完了还是一个正方形的样子；或者一个两边开口的圆柱），如果不做任何处理，最终优化出来的新点位置可能跑到别的地方去，形状就发生变化了——圆柱会简化成瘪掉的样子。

    * 很多情况下我们是希望保持模型边界的；给边加上约束之后，简化完依然很完美。

* **约束怎么加（三步）**

    * 先把模型的边界检测出来，确定哪些边界需要尽量保持。

    * 对每一条边界边加一个虚拟平面：一条边界边必然相邻一个三角形（也就是必然相邻一个平面），让这个虚拟平面跟它真实相邻的那个平面垂直。

    * 每个平面都能算一个 Q，给虚拟平面对应的 Q 负一个很大的权重：如果其他平面的权重都是 1，这个虚拟平面就给 1000。

    * 这样一来，collapse 之后误差会把这两个点强制拉回这条边界上——这个平面就保住了，边就不会变形。

* > **注意**：有效性检查长什么样、误差可以怎么定义、解空间不唯一怎么办、保持边界这种特殊情况怎么处理——这些细节看上去都简单，但在实际使用中处理不好就会出各种各样很奇葩的结果，值得抠。

## QEM 的推广

### 四边形网格

* 四边形网格可以用这套简化方法；重点不在 QEM 本身，而在于四边形网格是有一定规律的：希望简化完了之后它仍然是一个四边形网格——很 dense 的四边形网格简化一轮仍然是四边形网格，再继续简化仍然是，就一直保持四边形。

* 为什么要费这个劲：四边形网格有个好处——比较规则。

* 比较经典的一篇论文的做法：提取出一个 strip，然后在 strip 上做整体的塌边；有一种看法认为它用对偶网格（dual mesh）来提 strip 其实有点多余——直接开局，从一条边出发，找它的平行边（四边形的对边），再找平行边的平行边，一路找下去就能找出这个 loop。

* 找出来之后，这条 loop 上成对的两个顶点去做 edge collapse——相当于同时做一组边折叠；每一条被折叠的边看成一个新点（有的时候可能会看成多个点，但没关系），新生成点的位置还是照样用 QEM 的公式：它有前面的那些平面，照样可以算出一个最优点的位置。

### 体网格

* 体网格：不仅表面上有网格单元，模型内部也充满了单元；例子列的是六面体网格，其实里面也可以是四面体网格等等多种不同的离散化方式。

* 同样可以提取 strip，把一条线的两个端点拉成一个点；相关论文没有用 QEM 来优化，但 QEM 的应用可以很广，是可以用来做这个事情的。

### 把其他属性塞进 QEM

* 输入模型除了位置 $x, y, z$，每个顶点可能还有别的属性：颜色 RGB——AIGC 生成的那些模型大部分把颜色定义在顶点上；法向——一个顶点可能定义好几个法向；UV——要把纹理映射到 UV 上；或者在模型表面定义了一个高度场、一个热度场等各种属性；做边折叠时这些属性也要处理。

* 扩充办法很优美：把顶点的所有属性全堆着来，弄成一个很长很长的 vector——三点确定一个平面，属性堆在一起同样可以定义一个（高维空间里的）平面；直接往后怼，最终它仍然能推导出 QEM 这种表达方式。

* 于是整个简化流程、整个操作流程一模一样，计算出来的最优点——连同它的各个属性分量——也一模一样。

| 属性 | 天然约束 | 算飞了怎么办 |
| :--- | :--- | :--- |
| 颜色 RGB | 0～255，或归一化到 0～1 | 用 scale + translate 的线性变换拉回有效范围 |
| 法向 | $l^2 + m^2 + n^2 = 1$，长度为 1 | normalize |
| UV | 纹理空间有范围，如 0～1 | 同样用 scale + translate 拉回来 |

* 算出来的分量可能超范围：位置是从负无穷到正无穷解出来的，那算出来的颜色、UV 也可能从负无穷到正无穷——做一个 scale 加 translate 的线性变换，变换回有效值的范围；法向要求长度为一，那就对它做 normalize。

* 结果：顶点色的模型在做简化的时候，能同时很好地保持住颜色——把所有的属性整个纳入到同一个框架中。

## 不保纹理减面：定义与三步管线

* **定义**

    * > **定义**：简化后的模型不复用原模型的 UV 和贴图，而要重新展 UV、重新生成贴图的减面方法。

    * 自由与代价：不保持原来的纹理，一方面给算法设计增加了很大的自由度——不需要去保持原来模型的 UV；另一方面正因自由发挥空间极大，需要做很多额外的处理：重新生成 UV、重新展 UV、重新生成贴图。

* **优缺点**

    * 缺点很明显：会生成额外的数据量——做减面的主要目的就是减少数据量，结果反而多出来一块新的数据，这对算法的应用并不是好事情。

    * 优点：可以把面数减到极限——比如原模一万八千多个面可以减到两百多个，差不多 1% 到 1.5% 的量级，非常少。

* **三步管线**

    * 第一步重新网格化：只关心网格本身——点、线、面，把它的网格重新生成一遍；这一步最复杂、也最难——在图形学、几何处理这一块，内容的生成基本上总是最难的。

    * 第二步展 UV：对新网格计算 UV、展开 UV，摊到二维平面上去。

    * 第三步纹理烘焙：有了网格、有了 UV，根据原模和前两步生成的结果生成对应的纹理；"烘焙"就是把高模的信息通过某种方式转移（transfer）给低模、把纹理转移过去。

```text
输入：高模（原模）
     │
     ▼
① 重新网格化   只看点线面，重新生成一张干净的网格
     │
     ▼
② 展 UV        切割 → 参数化 → 装箱，得到 UV 网格
     │
     ▼
③ 纹理烘焙     把原模的外观迁移给低模，生成新贴图
     │
     ▼
输出：低模网格 + UV + 新纹理
```

    * 三步串成一条流水线，每一步的输出就是下一步的输入；原模型的 UV 和贴图过了第一步就不再沿用，最终贴图是第三步新烘焙出来的。

## 重新网格化

* **输出要满足三件事**

    * 面数越简单越好——别忘了主要目标：压缩数据、提高渲染效率。

    * 渲染出来的样子要跟原模尽量相似，保住视觉外观（visual appearance）——两个模型渲染出来的图片要尽量相似。

    * 输出的网格模型，拓扑结构和几何特征要尽量干净、简洁——整个不保纹理减面是一个管线，这只是第一大步，后面还要展 UV、做纹理烘焙；光展 UV 一个环节就有几十种甚至上百种算法、各有优缺点，给它的网格质量越好、拓扑越干净，展出来在实际应用中就越鲁棒，效果一般也会好一点。

* **输入有多脏：拿游戏建筑说事**

    * 实际应用中的建筑模型看上去非常简单——就是简简单单的外轮廓，感觉不是那么复杂的三维模型；但实际上它的拓扑和几何是非常复杂的。

    * 一个例子：将近六千个三角形的模型——六千已经是很少的面数，但为了玩家有更好的体验还是希望更低——它包含 151 个 components（互相分离、互不连接的连接体），另外还有五千多对互相交叉在一起的三角形；一般来说这种模型都比较 dirty，而且不是流形的（not manifold）。

    * 十几年前、几十年前的很多算法基本都会对模型做一堆美好的假设：假设它是二流形的、没有自相交、是封闭的；但实际应用中完全不是这样——美术在制作这种三维模型时根本不 care 拓扑，最重要的关心是看上去是不是好看、是不是满足他们的制作标准；建模的人的目标跟我们设计一套自动化算法的要求和目标是很不匹配的，正因为这种不匹配造成了挑战。

    * 建筑的复杂性还有很多：有的不仅有一层外皮，还有多层、上下结构、多孔结构、间隙结构；日式的、中式的、罗马的、中世纪的、现代式的各有各的复杂度；有的模型看上去是一个完整的建筑，实际上里面有大大小小的洞、缝隙；有的看起来是三角形的拓扑，但几何上完全面积为零、边长为零；有的模型有很多重复的点、重复的面——能想象到的各种奇葩的复杂性实际中都存在。

* **美术的成本就是自动化的机会**

    * 美术创建游戏资产（3D 的、2D 的，游戏里统称美术资产）的时候经常要花很多时间：不仅是生成原模，还要花很多时间生成低模网格（low poly model）——这正是重新网格化这一步的主要目标；他们为什么要花上几周？因为整个游戏开发中对 3D 资产的处理占的比重非常大，投入的人力、物理时间成本非常高、非常之高。

    * 这也是自动化算法有强烈现实意义需求的原因。

* **现有方案与实测**

    * 工业界：Blender（免费 license，个人开发者用起来没什么门槛）和 Unreal Engine 5——这两个更多是一个平台，里面集成了各种各样的插件或者他们自己开发的工具。

    * 更专业的是 Simplygon 和 InstaLOD：Simplygon 是一家瑞典创业公司的产品，2006 年开始做的，2017 年被微软收购，现在是微软的子公司；InstaLOD 是德国的一家创业公司——这两家专门处理美术资产，对 3D 资产做保纹理的减面、不保纹理的减面、重新网格化等各种处理。

    * 学术界也有一堆论文，非常多；还有一些开源软件：MeshLab 里面有减面，CGAL 这种计算几何处理库也有相关的重新网格化方法。

    * 实测（输入两个将近一万面的模型，记号 #T 表示三角形面片数目，拿 KSR、PolyFit、Blender、SPSR 这些不同算法去跑）：有的面数根本没降下来、还把模型破坏得乱七八糟完全没法用（游戏中对结果的要求还是很高的）；有的方法非常简单但跟原版差距挺大；有的完全不可用；还有鲁棒性问题、会 crash——鲁棒指程序运行中不崩溃。

    * > **结论**：直到现在，这个环节大部分还是通过手工或者交互的方式来做的。

    * 也有能达到好效果的工作：输入那个脏兮兮的建筑模型，输出非常简单；因为这种超简模型主要用在相机离得比较远的渲染里，看起来跟高模非常相似；细节可以搜论文，也公开了可执行的程序。

* **其他重新网格化思路**

    * 用一些大的平面片（比如四边形板子）交叉着把模型勾勒出来，每个板子对应贴图里的一大块，把它们排布起来；这类方法一般用来简化植被、建筑一类的模型。

    * 关注输入模型连接出来的 mesh 质量不太好的情形，对它做重新网格化，让它更加规律。

    * 根据输入模型先拟合出一组平面，再根据平面之间的交叉集合，用某种优化方法从中选出一组子平面，用它们表达出一个非常简化的原模型样子。

    * Visual Hull（视觉外壳）思路的两个工作：从某个视角观察、把看到的样子勾勒成一个体；换别的视角再勾勒；不同视角交叉出来的形状就是模型；第二个工作解决的是第一个的局限——第一个方法更适合处理建筑或者比较规则的形状。

### 代理网格方法：先造一个干净的中间模型

* **设计原则**

    * 从问题的根本要求出发：结果要能跟输入的模型视觉上尽量相似——设计方法时就重点考虑这一点。

    * 针对前面各种输入挑战——拓扑复杂、几何脏，还有零面积的三角形、零边长的边、大量重复的点面——与其直接对复杂的模型做减面操作（比如边折叠），不如先对输入模型计算一个代理网格（proxy mesh）。

    * > **定义**：proxy mesh（代理网格）是先造出来的中间模型，要满足两条：一，视觉上跟原模相似——从这个视角看、从那个视角看都跟原版很像；二，clean——拓扑比较干净、三角形尽量少，最好是水密的（watertight）、是流形的，几何上没有自相交这类复杂情况。

    * 先生成这个代理网格，然后再用 QEM 减面方法、通过边折叠来得到低模网格——这就是整个方法的设计原则。

* **三步流水线**

```text
输入：高模
     │
     ▼
① Visual mesh 生成（visual hull 式的「切」）
     │    选一组观察方向：投影出轮廓 → 拉成扫掠体 → 与当前结果做布尔交
     │    迭代几个视点后，这些视角下的外轮廓与高模一模一样
     ▼
② Carve mesh 生成（雕出凹处）
     │    选平面：把原模沿负方向投影成扫掠体，从当前结果里布尔差掉
     │    从任何视角都看不见的凹槽，在这一步补上
     ▼
③ QEM 边折叠简化（经典方法，一路减到目标面数）
     │
     ▼
输出：低模网格（拓扑干净、外观相似）
```

    * 三步分别对应"看出轮廓、雕出凹陷、减到目标面数"；前两步都是布尔运算的活，第三步才是真正的减面。

* **Visual mesh：把轮廓从各个视角"看"出来**

    * 对输入的模型先计算它的一个包围盒，从包围盒开始；对原模从周围 360 度做投影——平面的计算可以有一定的技巧：比如对原模的面片做平面片的聚类，聚出很多面片方向，然后从中选出一组观察方向。

    * 从选定的视点对三维模型做投影，投影出来就是平面上的一个轮廓（silhouette）；再沿着观察方向对这个平面的样子做 sweeping——把它"拉起来"，从下面往上拉都一样——拉起来之后就是一个体：这个体是封闭的、流形的、不会有自相交，而且是简单的。

    * 每个视点实际上就对应这么一个体（扫掠体，swept volume），特点是：从对应的视角看，它跟原模的样子一模一样——至少外轮廓一模一样。

    * 拿这个扫掠体去跟输入的包围盒做一个布尔交运算；再以交运算的结果为新的起点，从其余的视点继续对 mesh 做投影、再做切割——比如上一次选的是从上往下看的视角，这一次换一个视角，mesh 又被精细化了一次；这么迭代几次、选定几个视角之后，生成的模型从这几个视角看轮廓就跟高模一模一样。

    * 涉及的操作有两类布尔运算：一个是二维的——把三维模型投影到平面上、求出它的轮廓，这个计算实际上是一个矢量计算（用一个用起来还不错的二维几何布尔库）；另一个是三维 volume 的布尔交运算——不断地把这几个扫掠体求交，得到越来越精细化的 visual mesh。

* **Carve mesh：把看不见的凹处雕出来**

    * 问题：如果原模里面有凹陷的地方（比如凹槽），不管从哪个视角看都看不到凹的地方——因为渲染走的是直线的视线原则。

    * 做法：同样从原模里面选出一些平面；对一个平面，把原模沿着这个平面的负方向往平面做投影，投影完了也会得到一个扫掠体；然后把前面的 visual mesh 减去这个扫掠体（布尔差运算），就把这一块给剪出来了；不断地增加更多平面的扫掠体去做雕琢（carve），细节就慢慢被雕琢出来了。

    * Visual mesh 和 carve mesh 这两步基本上涉及同样的两件事：三维模型到二维平面的投影，加上三维体的布尔运算——前者求交，后者做差。

* **收尾与面数参数**

    * 第三步就是用传统 QEM 方法对 carve mesh 做边折叠，通过不断选择合适的边，生成简化的模型。

    * 减面算法的一个通用问题、通病：怎么选参数——希望生成的最终减面结果的面数是多少，这对自动化算法来说非常难设计；以往的做法是让用户指定最终减面的数目，缺点是使用算法的用户（一般都是美术）可能并不清楚这个模型能简化到什么程度、简化到什么程度比较好——比如减到 300 面效果还不错，但算法其实减到 250 面效果也很好；这就需要来回地调试（parameter tuning），实际用起来会比较费劲，尤其有的算法算一次、调一次参数还要计算好久。

    * 一个很简单的思路：先把模型直接一路减到底——减到底之后各种面数的结果就都有了；然后画一条曲线图，横轴是面数、每个面数对应一个模型质量（这需要一个模型质量的评估方法 metric）；根据这条曲线算一个 Pareto front（帕累托前沿）的最佳点，让用户从结果里面选。

* **效果**

    * 效果示例：非常复杂的中式、日式古建筑模型可以生成很简单的低模；维京时代那种用木头和茅草搭建起来的茅草屋模型，可以简化成外观跟原模很像、但又非常简单的样子。

    * 衡量指标有两个：面数；light field distance——衡量最终输出的结果在渲染时跟原模在同一视角渲染下来的差别，数值越小质量越好。从这两个数据来看综合效果最好；也跟商业的和学术界的算法在整个数据集上做了对比。

    * 重新网格化还有别的思路：更新的一个工作不仅仅针对建筑、更加通用，也能生成非常好的效果。

## 展 UV

* **输入、输出与映射**

    * 输入基本上就是网格模型（三维的，也可能有二维的）；输出是 UV 网格——计算 UV 网格实际上就是计算三维模型与贴图空间（texture space）之间的映射，有了 UV 网格之后就自然而然有了这个映射。

    * 贴图放在贴图空间里，通过 UV 网格和三维网格的对应关系映射到三维表面上去，渲染时才能看到带了材质贴图的效果、才有真实感。

    * 二维的 UV 网格和三维的网格模型，三角形数目是一一对应的、一样的，只是顶点的 index 可能有所不同——因为里面经常会涉及切割的问题，会把一条边切成两条边。

    * 展 UV 的方法非常多、不用纠结，有现成的公开库可以用（比如 xatlas），直接拿它来展就行。

* **五条要求**

| 约束 | 类型 | 要求 |
| :--- | :--- | :--- |
| 不翻转 | 硬约束 | 展开后三角形不能翻面 |
| 不自相交 | 硬约束 | 展开后不能重叠穿插 |
| 切割短 | 软约束 | 切缝的总长越短越好 |
| 扭曲小 | 软约束 | 映射带来的拉伸变形越小越好 |
| 装箱面积小 | 软约束 | patch 在贴图空间里排得越紧凑越好 |

* **约束背后的门道**

    * 不翻转、不自相交：三角形翻了之后，一个模型表面的多个区域可能对应到同一块颜色区域，造成一些不必要的 artifacts——所以不能翻、也不能自相交。

    * 切割为什么越短越好：一个三维模型的亏格可能很高、甚至它是封闭的——封闭的模型必须切割才能摊到平面上去；一条切割边在三维模型上是一条边，对应到二维 UV 网格里就成了两条边；纹理图是像素的、离散化的东西，渲染到三维表面上时要跟邻居的像素（纹理素，texel）做插值，切割数目多了往往会造成不连续——两个在三维空间里相连的边，两侧插值出来的纹理颜色往往是不一样的；这种切割的地方叫"缝"（seam），渲染时经常在那里出现不想要的效果。

    * 扭曲为什么越小越好：扭曲衡量三维跟二维之间映射关系的质量；扭曲大时，纹理图上一个正正好的三角形映射到三维表面上会变成一个非常狭长的三角形——本来纹理图上那个正三角形内部是比较合理的样式，到了三维空间被拉扯得完全不是想要的样子；扭曲尽量小，制作贴图的时候就会更轻松。

    * 装箱为什么越紧越好：把 mesh cut 开成一块块的 patch 后，往往不知道它在纹理空间中应该放在什么位置；装箱就是把一块块 UV mesh patch 放在一起、又不让它们互相重叠，越紧致越好——纹理图都是长方形的，那些没被 patch 盖住的区域基本都是浪费的，没有任何信息量、浪费数据量；这一切的目的就是为了压缩数据。

    * 展 UV 这个问题本身就可以算作一个管线、一个模块：先对模型进行切割；切割完了对切割成的 patch 做参数化（到二维平面的展开）；展开完了进行封装、装配（装箱）。

### 切割：Variational Shape Approximation

* **流程**

    * 切割可以基于 Lloyd 的算法——Variational Shape Approximation（VSA）：先决定要把模型切割成多少个 patch（每个 patch 就是一个连通的区域）；一开始不知道具体该在哪里切割，就先随机选几个三角形做种子点——想切成三块，就选三个三角形当种子。

    * 基于贪心的方式扩张：对某个种子相邻的几个三角形，算"把相邻三角形跟它合并在一起"的误差是多少，把这些都放进一个队列里做排序，然后一个一个去添加、不断地扩张，直到模型里面所有的三角形都被访问完毕——这样模型就完成了一个区域划分。

    * 接着对每个区域算一个误差（比如算一个区域的平均法向，以及这个法向跟区域里每个三角形法向的差别），根据这个差别信息去更新、找到新的三角形种子点，然后再重复上面的步骤，直到所谓的收敛；收敛的定义也比较模糊：可以指定迭代多少次，也可以指定误差降低到什么程度，总之达到一个比较好的分割效果就行。

* **两点注意与洞填补**

    * 这个算法需要指定切割的区域个数——VSA、Lloyd 这个方法就是这样的。

    * 切割的数目跟模型的复杂程度、以及前面那些要求（缝尽量短、扭曲尽量小）往往是互不沟通的——它没有把整个过程作为一个全局优化来打通；这也非常难（里面涉及拓扑、连续优化等等很多变量），现在还没有方法能把这些都放在一起优化，所以大家往往把这个问题拆分开来，每一步解决一个小问题。

    * VSA 做了一个设计：切割出来的每个区域，它的 UV 映射误差是能被约束（bound）在一个范围之内的——这样输入模型里有些区域没有被归类（它们无法被归到任何一个区域，因为只要一归类进去误差就会很大），剩下这些地方要做 hole filling（洞填补）：要么把它们单独整成一些区域，再跟周围的区域进行合并；合并完了之后，网格模型的切割过程就完成了。

    * 整个 UV 展开里切割模型只是第一步；切割完了还要把每个 patch 摊到二维平面上去，怎么摊非常讲究——关于怎么摊一个网格，至少有几十个不同的算法。

### 参数化：Tutte embedding 与 scaffold

* **Tutte embedding**

    * > **定义**：一个参数化理论——如果一个 patch（一个圆盘拓扑的图）的边界被映射到一个凸的边界上，那么通过 Tutte 这个算法，能保证计算出来的内部点的位置、算出来的这个网格，是没有翻转、没有自相交的。

    * 这是非常重要的一个理论，奠定了绝大多数 UV 参数化算法的基础。

* **从打底到保双射**

    * 从一个 patch 开始对它做 Tutte embedding、映射到平面上（凸域），但计算出来的这个参数化是有误差的，而且误差往往很大。

    * 可以运用一些连续优化的算法来减少这个误差；但减少误差的时候边界就会变形——来回旋转也好、自由扩张也好（实际中 patch 的形状会非常多样）——就可能造成自相交。

    * 自相交对纹理映射、对渲染来说不是想要的，希望这是一个 bijective（一一）映射——UV 和模型之间是一一映射。

    * 一个方法的核心思路：加一些三角形，叫 scaffold（脚手架）或者叫 cage；通过保证每个三角形它不翻转，就会使得里面的结果永远不会有自相交（细节有公开代码）。

### 装箱：bin packing

* 装箱研究得比较多的叫 bin packing：把每一个 patch 作为一个 bin、当作一个长方形来 pack。

* 一个效果还不错的方法：把每一个不规则的 patch 看成一个长方形，借鉴拼俄罗斯方块的那种思想设计了一个装箱算法（有公开的代码，想尝试还是比较容易的）。

* 拿几种方法对比过装箱的效果（用的都是各自论文发表时的结果）；这套流程算是比较接近实用的一个管线；要更实用一点，可以直接调用现成开源库（比如 xatlas）里的方法。

## 纹理烘焙

* **目标**

    * 有了前面的网格和它的 UV，需要把纹理、或者说整个模型的外观（appearance）从高模迁移给低模、生成新贴图——这个过程叫纹理烘焙；烘焙的方法在种类上相对少一些，主要有两大类：基于光投射（ray casting）的和基于可微渲染的。

### 光投射（ray casting）

* **思路：找对应点**

    * 原模（reference mesh）上的属性——比如每个顶点的颜色、法向，或者其他一些信息（做动画的时候还会用到蒙皮权重等）——要传递到低模网格上去。

    * 做法：把低模网格沿着某个方向往外拉一下，拉出来一个 mesh，它跟低模是一一对应的——拉出来的这个东西叫做 cage，它可以把 reference mesh 整个框住；然后从 cage 出发，朝原来低模网格的方向投射线；射线会跟 reference mesh 有交点，交到哪里，就把那个点的属性赋值过来。

    * 因为 cage 上的点跟低模上的点是一一对应的，所以这个方法实际上就是找对应点：找到了对应点，就可以把高模表面上的属性迁移到低模上去了。

```text
      cage（把低模整体向外拉一圈得到，与低模一一对应）
      ═══════════════════════════════════
         │          │          │
         │ 射线      │ 射线     │ 射线        （朝低模方向投）
         ▼          ▼          ▼
            高模（reference mesh）∿∿∿∿∿∿∿
            （射线与高模相交，取交点处的属性）
         │          │          │
         ▼          ▼          ▼
      低模 ━━━━━━━━━━━━━━━━━━━━━━━━
           cage 上的点与低模上的点一一对应，
           交点属性写进低模对应的点 → 完成迁移
```

* **为什么流行**

    * 它经过了时间的检验，实际应用中大家基本都用这个。

    * 低模和高模的几何拓扑往往是非常不一样的、差别非常大；发表论文里那些计算对应点、计算两个 surface 之间 correspondence 的方法有各种各样的假设，对现实应用中的情况往往不实用。

    * 光投射这个方法非常鲁棒——不管怎么着它不会 crash，总是能找到一个对应的结果；而且它可以非常容易地 GPU 化，全都在 GPU 上实现，速度非常快，秒速出。

    * 缺点：没法做到一一对应——低模和高模差距太大的时候，射线往往会投错，有些点就投到错误的地方去了。

### 可微渲染

* **什么是可微渲染**

    * 把渲染的这个过程做成一个连续的、可导的过程；它其实更多的不是"渲染"——可微化之后是用来优化渲染里的那些量：三维模型的形状、材质（material）、还有灯源的位置等等，只要能把它 formulate 成一个优化问题。

    * 为什么要做成可微：很多优化问题要做连续优化，就要求目标函数等是可导的，才能做连续化；可导了，它就会给一个下降的方向——让目标函数的能量值往下走的方向——这对优化来说比较容易，比较容易找到一个比较好的解。

```text
    x（渲染参数：模型形状 / 材质 / 灯源位置……）
         |
         v   f：渲染函数
         |   （rasterize / ray tracing / volume render ……）
         v
    y（输出图片）

    优化回路：
    高模渲染出 y，低模渲染出 y'
    g = ||y − y'||   （g 可微 → 得到下降方向 → 反向更新 x）
    烘焙用法：mesh 和 UV 已知，只把贴图当变量优化出来
```

* **烘焙用法**

    * 目标函数：高模渲染出的图片和低模渲染出的图片尽量相似——$g$ 取两者之差的某种范数 $g = \lVert y - y' \rVert$；whatever 一种 formulation，只要它是可微的，就可以用它来优化低模的某个变量。

    * 已经知道低模的 mesh、知道它的 UV，只想优化它的贴图——把贴图当变量优化出来，就可以做到这一点。

    * 结果：diffuse map（也就是 RGB）、specular map、normal map 等等都可以 bake 出来——都是优化出来的，因为梯度是可以计算出来的；烘完渲染出来的样子就跟原来一致。

    * 因为它是连续优化的方法，有些情况下效果比 ray casting 的方法要好很多（验证过）。

## 两条路线的对比

|  | 保纹理（QEM 一类） | 不保纹理 |
| :--- | :--- | :--- |
| 输入 | 模型网格 + 纹理 + UV | 网格本身（UV、纹理都不用管） |
| 输出 | 减面后的模型 | 低模网格 + 新 UV + 新烘焙贴图 |
| 框架 | 非常简单——太简单了，所以特别经典 | 三步管线，每一步都蛮难（烘焙相对简单些） |
| 鲁棒性 | 非常鲁棒，不太容易出 bug | 最关键看重新网格化之后的网格性质与质量 |
| 现状 | 经时间与实际应用检验的仍是 QEM 一类管线 | 展 UV、烘焙已有实用工具，重新网格化仍是难点 |

* 保纹理这一套：简化框架非常简单——太简单了所以特别经典，非常鲁棒、不太容易出 bug；经过时间检验、经过实际应用考验的，还是 QEM 一类的算法管线。

* 不保纹理的这一套非常复杂：把每一步具体实现出来、甚至构思它都不容易，每个步骤其实都蛮难（纹理烘焙的 ray casting 还算相对简单一些）；它的效果往往非常取决于重新网格化这一步——最关键的就是重新网格化之后网格的性质和质量。

* 展 UV 已经有实用的工具和算法，至少不是一个特别大的难点，有现成的工作可以去解决；纹理烘焙也一样有现成的工作，两个思路各有优缺点。
