Hello，同学们好，我是王希。欢迎大家回到 GAMES104 现代游戏引擎的理论与实践。

又到了一周一次大家互相比如肝度的时候，课程组又爆肝了一周，肝出了这一节的课程。这节课程应该来讲的话，我个人觉得是画面最美的一节课程，因为我们这一节课程要讲的就是我们大自然的一切，就是我叫 Mother Nature，最漂亮的、最好看的这个世界。

但是我觉得这节课程，我写完这个课件之后我的感受是这样的：第一就是拖堂可能是一定的，内容太大，我实在没有办法把它压缩在一个很短的课程中，但是我们总共只有四节讲 Rendering，所以应该是个信息量蛮大的一节课。听懂呢，我们也不能保证，因为里面有大量的数学公式。这一次为了准备这个课件的话，我们很多公式都是现场去打、现场去校验，说不定中间还有什么东西我们还没查出来。

那好，这节课我们在讲什么呢？首先的话，我们这节课的内容就是讲我们如何把这个自然渲染出来。这张图是《荒野大镖客》的，我个人觉得是非常的好看。它完美地诠释了我们所生活的这个 planet——这个星球上面的美轮美奂的世界。大家可以看到日夜变换，对吧？然后阳光，天上的云，然后下雨、树木、山川、河流，真的是非常非常的美。

所以这其实对于我们游戏的研发者来讲，尤其是对于我们的 Graphics Engineer，我们最大的一个挑战或者最让我们兴奋的东西是什么呢？就是这个世界太美了，然后我们怎么在虚拟的世界里面用 0 和 1 把这个世界表现出来？这件事情其实是非常非常痛苦的。经常是策划说我要一个什么东西，美术说我要一个什么东西，然后下面的 Graphics Engineer 就会跑断腿。

那我们这节课讲的，GAMES104 的精神是什么？教大家如何做游戏引擎，而不是教大家如何去……

用现有的引擎做出这些效果，如果你要学效果是很简单的，但是你要是做引擎的话，那我们就需要知道它下面到底有什么。

那么对这个世界的理解，我们首先从观察开始。这是大家看到的一张真实世界的照片。在这个照片里面，我们可以看到很多东西对不对？我们可以看到天空，看到大量的植被，看到河流，看到大量的小溪、石头、乱石这些东西。

回到我们故事的主角，大家还记得小明吗？我想上一节课基本上没有提小明的名字，但是我们的小明同学还是非常想把能干翻2042的游戏给做出来。他今天打开自己的游戏，看到的情况实在差得太远了。你看，我们好像很缺天空以及天空中云的表现，而且地面上的植被表现得非常差，地形也绘制得特别差。这就是今天我们这一节课要解决的问题。

我先从一个相对简单的东西开始，先教大家怎么画地形。这是一幅油画，我今天所有的 section 都是以油画开头。为什么呢？因为写到绘制和渲染这一趴的时候，人就会忍不住地觉得诗兴大发，确实是非常非常的美。而且从几个世纪以前，上千年前，我们的祖先看到这么美轮美奂的世界，他们就有一种强大的表达欲。

比如说我自己个人特别喜欢像西班牙洞穴里面的原始人画的岩画，包括毕加索的绘画也是受它的影响。因为我觉得人类对自然界的喜爱与表达是一种本能。所以当我成为了一个游戏引擎研发者的时候，我觉得这件事情是非常快乐的。所以这一次课程的标题，我取成痛苦、challenge，但又是乐趣，去表达自然之母的美。

其实在我们的游戏引擎团队里面，我们经常会把同学们根据他做的事情不同进行分工。

比如说，在我们的团队里我们有几个同学，我们叫他什么呢？叫“大地之神”。就是如何把大地上的一切表达得足够美。那还有一些同学我们叫什么呢？叫“天空之神”，对吧？那就是如何把天上的天光、云表现得特别美。这种称号真的不是说我们编出来的，而是团队自发给他们取的。因为我们这些技术 apply 上去之后，真的会让整个画面让我们都非常的喜欢。所以我们的第一 part，先从如何做“大地之神”开始。

首先给大家上两张美图。这个是微软的飞行模拟器。大家知道最近一代的微软飞行模拟器是丧心病狂，对吧？我忘了它的整个 package 有多大，好像是接近一个 T 吧。你是没有办法把它装到一张盘里面的，它整个要不断地，买了游戏之后不断要 streaming data，它跟必应的 Earth 地图整个连接在一起。想这么大的一个世界，这么多样地球的地貌它都能表达，这其实就是游戏引擎现在对于 terrain 的绘制能力。

这里面跟大家八卦一下什么叫 terrain。Terrain 这个词好像是古代英语中的地球，Earth，地球之母的意思，对吧？大家如果玩《星际争霸》的时候，就知道有一个种族好像就叫 Terran，就是人族，对吧？其实我还蛮喜欢这个词的，因为这个词总让我回想到上古的神话。所以地形在游戏引擎里面，在游戏的绘制里面，我们一般叫做 terrain。那么这是微软的飞行模拟器。

那我们这个技术只是在绘制地球吗？这里面也要点名另外一个游戏了，就是《无人深空》，对吧？这个游戏当年曾经欺骗了我们很多人的感情，但是我还是非常敬佩这个游戏的 studio，他们不放弃，一直在往前去越做越好。那我们可以发现，这样的一个技术它不仅要表达 Earth-like 的这样一个世界，我们还要表达 non-Earth-like，就是不像地球的这样一个世界，对不对？很 alien 的，就是很外星的地貌。比如现在大家特别想做那种火星地貌，对不对？比如说金星上的那种大裂谷这种感觉，其实都会让人觉得特别的 fantasy。所以这也是我们的地形绘……

技术要表达的东西。

GAMES104课的传统精神是什么呢？咱们先从最简单的开始：如何表达地形。

最简单的是什么呢？就是Heightfield，叫高程图。Heightfield这个东西并不是什么新的东西。其实早在几十年前，我们人类还不会有计算机游戏的时候，其实我们的社会就已经能够用contour，叫等高线，它已经能表达出我们的地形地貌的高低变化。比如大家看过去的战争片里面，那些将军面前都摆一个高清晰度的沙盘，包括人造卫星对地球的扫描，它也扫描出这种高程图。

大家看在这个图的左边，有一个用明暗表达的高度图。大家看这个图像什么呢？其实像不像右边那个等高线图，我建议大家仔细观察，它像我们在以前学过的一个什么概念？叫做分形。

分形是什么？大家也都知道的概念，就是它可以无限地放大，进入无限的自我相似的这么一个形状。其实大家如果学自然界的一切，无论是一片雪花，还是我们的海岸线，还是我们山脉的走线，它其实包括山脉上的这种腐蚀，它都是符合分形的原则的。

这个规律其实是非常有用的，因为我们后面会讲的就是如何让计算机帮我们自动生成各种各样的地貌，其实这个数学规律是非常有用的。

实际上，当我们得到了一个地方它的高程图的时候，实际上我们对它的渲染就会变得非常简单。

Heightfield这个技术非常的简单，但是大家可能想象不到，如果它和纹理、和光影去配合的时候，和材质配合的时候，你看这个效果。这两张图是我从ArtStation下载下来的，其实我自己也是非常surprised，因为在我的印象中，Heightfield是一个相对比较古老的技术，但实际上我发现真的是事在人为，就是说你真的用得好，它的表现力还是非常强。这也是为什么到今天，Heightfield还是在现代……

游戏里面地形渲染的主力方法。

拿到 Heightfield 之后怎么去渲染呢？其实最简单的方法，就是每隔一米或者每隔半米做一个均匀的网格。这个时候，把每个顶点根据高程图进行位移，进而形成想要的地形效果，非常简单。而且在上面 apply 它的各种属性，比如高度、材质等就可以了。

但这个方法我相信同学们很快就知道是有问题的。为什么？如果我要表达一个很大很大的世界，比如大家特别喜闻乐见的开放世界，那么这个方法显然是不行的。如果要表达一公里，一米一个格子，$1000 \times 1000 \times 2$，那是 200 万个三角形，现在的算力觉得还可以，没问题；但是如果要表达一个几千平方公里到上万平方公里的时候，显然是画不了的。

但是大家很快就会发现，这个事情并不难。观察地形时，在近处可以看到无数的细节，远端看不到细节，那么这个地方显然有大量的空间可以去优化。大家记得在前面的课程中一直在讲一个概念叫做 LOD。LOD 全称叫 Level of Detail，就是说根据在屏幕上占的像素、远近或者对信号的敏感度，可以设置不同的细节精度。

显然这里面是有 Level of Detail 空间的。但是不同于在前面讲的各种游戏里面的 object——大家还记得 game object 的概念吗？那些东西到远端的时候，切换成一个更低精度的模型没有什么太大问题，直接切就好了。但是地形有一个小细节，它是一路连续过去的，待会儿会跟大家讲一个概念叫 T-Junction。所以它的 LOD 是要用心去设计一下的。

这里面先跟大家讲一个最简单的思想，就是……

Mesh的tessellation，就是说我对这个网格进行不断地细分，tessellation这个词就是细分，它叫三角网格化。

那么这里面大家看到一个很有意思的问题是什么？就是当我在游戏中的任何一个时候，我看过去的时候，并不是360度看的，对不对？其实我们看到的一个东西只是一个眼睛看到的一个展开的一个锥体，这个锥体叫作什么呢？叫FOV，叫field of view。

我们会发现，实际上我们真正关心的是在这个FOV里面的东西，而不是在FOV外面的东西。所以你会发现，这里面已经给大家提前泄露我们方法的结果了，就是在FOV里面的这些三角形就会被很细密地去细化，我们可以看到很多的细节。但是FOV外面的和远处的，我们会把它三角形分布得非常的稀疏。这个效果你其实是看不出来的，因为我会保证在屏幕上每隔多少个像素，你看到的三角形密度永远是一致的，这个在数学上我们是可以做得到的。

这里面也跟大家讲一个经常大家容易犯的错误，最早大家刚开始在写地形的tessellation的时候，很容易会忘记一个变量，就是FOV，就是视角。因为大家看到在这个图的另外三个，你会发现它的FOV越来越窄，越来越窄。你会发现，为什么当我的FOV越来越窄的时候，我的三角形会越来越细密呢？大家想想这里面是不是有一个原理？

其实很简单，当我的FOV越来越窄的时候，在屏幕上我们看到的效果是什么？实际上是这个地形会被放得越来越大。这个效果在什么时候很有用呢？大家不是经常喜欢打PUBG，打吃鸡游戏？吃鸡游戏中大家最想获得的装备是什么？就是几倍镜吧，三倍镜、八倍镜。那三倍镜、八倍镜zoom in的效果是怎么实现的呢？实际上并不是真的我们做了一个光学的望远镜，实际上我们只改了一个很小的……

也就是把摄像机的参数 FOV 变小了。这样的话，在屏幕空间一下子那个东西就放得很大很大，但是你牺牲掉的东西是什么呢？是你看到的视场会变小，对不对？所以说会让你的眼睛更聚焦。所以在这里面的话，就是说当我们决定——其实不仅是地形，包括游戏里的物体，我要绘制它的时候，它的精度多少的时候，我们不仅要考虑它的远近，还要考虑到它的 FOV。原则上来讲，越昂贵的望远镜它的 FOV 就越小。大家在现实生活中也是这样，你们可以试一下戴上自己的望远镜，你会发现你观察的角度会越来越窄。那么这个东西最科学的一个解释就是说，假设你的屏幕是同等像素量的话，那么每一个三角形在小的 FOV 下占的像素量就会增加。所以这个知识我希望同学们一定要牢记在心，否则的话，你将来很容易写出一些 bug。

好，有了这样一个基础知识的话，我们其实就可以对网格进行简化了。这里面跟大家讲两个基础的原则。

第一个原则其实在上一页已经讲完了，就是说我们采取近处密一点，远处稀疏一点；FOV 越窄，那我就密集一点；FOV 越宽，我看表面越宽的话，我也稀疏一点。

第二个原则其实是一个比较麻烦的原则，我们叫做 Error Bound。这其实我们在数学上保证说，当我对这些网格进行无论是简化合并的时候，因为我的采样点变少了，那我导致的地形高低之间的误差不要超过一个给定的阈值。但注意，这个阈值实际上指的是在视空间上。也就是说，比如说你的误差是 0.1 米、10 厘米，那么如果在距离你比如 10 米之外的地方，你还是能注意到的，对不对？但是如果在距离你 100 米之外的时候，其实你注意不到了；1000 米之外的话，你可能根本注意不到了，对不对？所以我们要保证在屏幕上，你的视不要

超过比如说 0.1 个像素或者是一个像素，对吧？理想情况下是只要不超过一个像素，一般人是注意不到的。所以这个也是一个数学上，如果大家真的下去去写地形的 adaptive tessellation，就是说基于 view 的——不好意思，这个地方真不知道中文怎么讲了，就是基于 view-dependent 的 adaptive tessellation 的时候，大家会把这两个重要的原则引入。

好，那基本的方法论我们就知道了，对不对？我相信我们的 Games104 的同学们应该很聪明，应该能理解这件事情。接下来跟大家讲一个非常简单的起活方法，就是到底怎么去把这个三角形变得疏密相间。

其实最简单的做法，就是三角形的剖分，基于 triangle 的剖分。那么这个方法也是一个非常经典的方法了。

大家可以看到，我们一开始的地形是一个个的格子，对吧？我在格子中切一刀，它就变成两个等腰直角三角形。然后它这个算法就要求是说，如果你觉得你的密度不够，你永远在它的最长那一面——等腰直角三角形大家说最长的那一边是哪？是不是直角对的那条边？在那个边中间找一个点给它切一刀。那这一刀下去的话，大家是不是得到了两个等腰直角三角形，对吧？

所以它的整个算法的核心要求就是，你永远把一个等腰直角三角形的最长一边切一刀，这样你永远得到的是两个新的等腰直角三角形。那么这个结构是个什么结构呢？这其实就是一个二叉树的结构。所以这个方法也叫作 binary triangle-based subdivision 的方法。具体的 paper 的话，我们在后面 PDF link 上会给大家分享。

那么这个方法的话，其实它会产生一个很有意思的细节，这就是我们在做地形的时候大家一定要学会的一个黑话，叫作 T-Junction。这个词听上去是不是特别的高大上？实际上它非常的简单，就是说当我有两个相邻的三角形在同一条边上，有一个三角形这挑边没有被切分，它就是一条边拉直了，但是它另外……

相邻的几个三角形，在那个边上拉出了一个点。那么中间的这一个采样点，因为中间的高度会变化，这样的话会导致它们两个之间产生一个误差，你可以看到地形上有一个裂缝。

这个裂缝就是说，如果大家在做地形的这种 tessellation 的时候，如果你不去处理 T-junction 的话，你会发现那个地形看着大致都是对的，但远远的总有很多地方露出白边，因为露出的都是无穷远的天空的颜色。

所以这个是 graphics engineer 很早就去斗争的一个东西。那它的算法难不难呢？其实也不难，其实非常地简单。就是说如果你发现你边上有邻居，它对那个边的细分比你密，那你没办法，你就开始把这个边也给切掉，直到切到跟它的细分数是一样为止。具体的算法我就不展开，但是它基本的思想就是这个思想。

所以说用一个最简单的二叉树的结构，然后我永远用无数的等腰直角三角形，我就能拼出前面那一页大家看到的这个 mesh。这个 mesh 的话就是一个很典型，大家看到没有？高亮的区域就是你的 view 能看见的区域，黑色的就是看不见的。这个 view 好像有点大，一般我们游戏中的 view 没有那么大，这个 view 大概接近于已经快 135 度了吧。一般来讲，游戏里面我们的 view 很多时候做到大概 70 到 80 度左右。

这就是一个最简单的方法。但是这个方法实际上在我们的游戏行业用得不是特别多。

首先这个方法是很有意思的，这里面有一个用 Unity 做的一个 demo。这个 demo 大概是 50 × 50 的平方公里。这个面积很大了，50 × 50 那就是 2500 平方公里了。它用这个 triangle 在 GPU 上直接跑出来了。所以这个方法本身的效率、绘制都没有问题，特别像这种一望无垠的地形的表达。但这个方法其实是有一个很严重的问题的，就是说它无论是对地形数据的管理，包括

它中间的剖分算法，其实不符合我们在制作地形的一个直觉。大家想象一下，给你一个很大的地形，你最天然的思想是什么？是不是把它切成豆腐块？你是愿意处理一群豆腐块，还是愿意处理像七巧板一样各种各样的三角形？

所以在现代的游戏中，大家用得最多的还是基于四叉树的这样一个地形的表达。这个方法就非常的直觉了，大家看，我们给你一个比如 128 米或者 128 公里乘 128 公里的大地形，我就把它开始不停地切切切，切到最后，很多游戏引擎是以 512 米乘 512 米，大概半公里左右为一个 block。一个 block 我再切，比如切成 16 块，那么比如是一个 64 米乘 64 米的 patch。这个名字随便你取，但它核心的都是符合四叉树的结构。
