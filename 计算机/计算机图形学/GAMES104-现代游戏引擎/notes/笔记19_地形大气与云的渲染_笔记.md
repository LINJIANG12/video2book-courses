# 地形、大气与云的渲染

## 地形的几何表达

### 高程图与细节层次

* **高程图（Heightfield）**

    * > **定义**：用一张二维标量场为每个平面位置记录唯一高度，地形表面由这些高度值抬升而成。

    * 等高线、军事沙盘、卫星扫描得到的都是同一类数据，这种表达方式远早于计算机游戏。

    * 高度图的明暗起伏呈分形特征：雪花、海岸线、山脉走向与山体侵蚀都满足无限自相似，可用同一套数学自动生成地貌。

    * 配合纹理、光影与材质后表现力很强，至今仍是现代游戏地形渲染的主力方法。

* **细节层次（Level of Detail，LOD）**

    * > **定义**：按物体在屏幕上的像素占比、距离远近与信号敏感度分配不同的细节精度。

    * 普通物体在远处直接换成低模即可；地形是一路连续过去的表面，精度突变会在接缝处产生 T 型接缝（T-Junction），因此地形 LOD 必须专门设计。

* **均匀网格（Uniform Grid）**

    * 每隔一米或半米布一个顶点，按高程图位移顶点，再叠加高度与材质属性，地形就出来了。

    * 一公里见方、一米一格需要 $1000 \times 1000 \times 2 = 2{,}000{,}000$ 个三角形。

    * 开放世界动辄几千到上万平方公里，均匀网格的三角形数量不可承受；而地形近处细节多、远处无细节，本身留有大量 LOD 空间。

### 视场角与误差界

* **视场角（Field of View，FOV）**

    * 画面并不是 360 度全看，而只是眼睛展开的一个视锥，锥外的三角形不需要精细。

    * 刚开始写地形细分时常见的错误是漏掉 FOV：把 FOV 收窄，地形在屏幕上被放得更大，三角形理应更密；只按距离算密度就会算错。

    * 三倍镜、八倍镜的放大效果并非光学系统，只是把摄像机 FOV 调小，代价是可视范围变窄。

    * 判断任何物体要画多少精度，都要同时看距离与 FOV：屏幕像素量固定时，FOV 越小，单个三角形占的像素越多。

* **视空间误差界（Error Bound）**

    * 网格简化与合并会让采样点变少，由此产生的高度误差必须低于给定阈值，且该阈值指视空间误差，不是世界空间的米数。

    * 0.1 米的误差在 10 米处还能察觉，100 米外已难察觉，1000 米外完全不可见。

    * 工程目标是屏幕上的误差不超过 1 个像素，理想情况不超过 0.1 个像素。

* **自适应细分（Adaptive Tessellation）**

    * 基于视点相关（view-dependent）的第一条原则：近处密、远处疏；FOV 窄时密、FOV 宽时疏。

    * 第二条原则由误差界约束：无论怎么合并，屏幕上的误差都不能超过上限。

### 二叉三角形剖分

* **二叉三角形剖分（Binary Triangle-Based Subdivision）**

    * 先把方格沿对角线切成两个等腰直角三角形；密度不够时，永远在最长边也就是斜边的中点再切一刀，得到两个新的等腰直角三角形。

    * 整个结构因此是一棵二叉树，不同位置的细分次数可以不同。

    * 用这棵二叉树能拼出完整地形：视锥内画得很密，视锥外画得很疏。

    * 已有 GPU 实现跑到 50 × 50 平方公里（2500 平方公里），效率与绘制都没有问题，适合一望无际的地形；演示视角接近 135 度，一般游戏常用 70 到 80 度。

* **T 型接缝（T-Junction）**

    * > **定义**：同一条共享边被两侧以不同密度切分，一侧的直边上没有插入点，另一侧多出顶点，插值出的高度对不上，接缝处就裂开一条缝。

    * 裂缝露出的是无穷远天空的颜色，表现为地形远端一条条白边。

    * 二叉树的修法是：发现邻居对这条边的细分比自己密，就把自己这条边也切到相同细分数；代价是要改拓扑，夹在两侧时会出现奇怪形状，需要一套规则列表。

    * 这条路线真正的短板不在效率，而在数据管理与剖分算法都不符合制作地形的直觉：人愿意处理豆腐块，不愿意处理七巧板式的三角形。

### 四叉树与接缝吸附

* **四叉树（Quadtree）**

    * 把大地形不断四分：很多游戏以 512 米 × 512 米为一个 block（约半公里），block 再向下切到 64 米 × 64 米的 patch；四个小块合一，合到 block 为止。

    * block 是磁盘上的规范数据块，把一个地块的高程图、材质贴图、植被、树木、建筑打包在一起；看到该地块就整块载入。

    * 四叉树与纹理的方形存储天然一致，用三角形贴图会浪费一半存储；这也符合人按格子划分世界的直觉。

    * 它是现代引擎最主流的地形数据表达，Far Cry 的地形即由四叉树实现。

    * 三角形方案只是渲染方法，quad 方案暗含资源管理逻辑，虚拟纹理也建立在 quad 之上。

* **接缝吸附（Stitching）**

    * 邻居切得比自己密时，不动自己的拓扑，而是把邻居多出来的中间顶点吸附到自己边的端点上，使其与端点重合。

    * 重合后形成面积为零的三角形，即退化三角形（Degenerate Triangle）；它不影响水密性（watertight），接缝照样补上。

    * 自己写光栅化器时必须显式处理退化三角形：面积为零时可以选择不输出任何像素。

    * 这套做法比二叉树的补缝代码好写得多，是四叉树实用性的重要来源。

* **分页与统一资源管理**

    * 地形四叉树可以与场景物体使用的四叉树共用，价值在于用同一套 page 思想统一管理磁盘、主内存、显存之间的调度。

    * 开放世界里几乎任何资源规模都能撑爆内存或显存，分页是唯一出路。

### 不规则三角形与网格简化

* **不规则三角形（Irregular Triangle）**

    * 仍由高密度高程图生成，再用网格简化（Mesh Simplification）删掉多余顶点，并把顶点对齐到地形特征。

    * 大片平坦区域只需少量顶点，简化后的三角形被拉得很长，沙漠地形尤其适合。

    * 《现代战争》的沙漠场景采用此法，顶点被巧妙地对齐到一条条突出的山脊。

* **采样效率差异**

    * 四叉树的采样点只能落在等间隔的方格顶点上，无法对准信息量大的区域；不规则三角形的顶点由简化算法特意对齐到山脊等特征。

    * 在同样的视觉误差下，为特定信号定制的非均匀采样所需三角形更少。

    * 实测差距：四叉树 LOD 约五十多万个面，简化方案少接近一个数量级。

* **代价与适用**

    * 需要预处理，运行时很难调整。

    * 只在少数前沿游戏中使用，不是通用方案。

## GPU 细分与可变形地形

### 硬件细分管线

* **外壳着色器（Hull Shader）**

    * 生成供细分使用的 patch，即一小块由控制点控制的几何区域，可把平面化成立体光滑曲面。

    * 需要写两份：一份给出各控制点的数据，一份告诉细分器每条边要细分多少次。

* **细分器（Tessellator）**

    * 硬件固定功能管线，按外壳着色器给出的次数，把四边形或三角形打成细密三角形。

* **域着色器（Domain Shader）**

    * 对新插入的顶点采样高度图，按采样值位移顶点位置，形成地形起伏。

* **几何着色器（Geometry Shader）**

    * 对已被位移的顶点重算纹理 UV 等逐像素数据，相当于再走一遍顶点着色器的活；更贴切的叫法是细分后顶点着色器（post-tessellated vertex shader）。

### 网格着色器

* **网格着色器（Mesh Shader）**

    * 一个着色器承担从顶点着色器到外壳、细分、域、几何的全部工作，开发者自己生成 meshlet，即一小片顶点与三角形，并决定如何插值、如何取凸包。

    * 细分算法由开发者自己写，不再依赖硬件的固定细分功能。

    * 平台门槛为 DX12 及以上，Windows 从 Win10 才支持，Win7 机器无法使用。

* **管线对比**

    * DX11 路线：顶点 → 外壳 → 细分器 → 域 → 几何，细分由硬件固定功能完成。

    * Mesh Shader 路线：一个着色器全部承担，细分由开发者实现。

| 对比项 | DX11 细分管线 | Mesh Shader |
| :--- | :--- | :--- |
| 参与阶段 | 顶点 → 外壳 → 细分器 → 域 → 几何 | 一个 Mesh Shader 全部承担 |
| 谁来细分 | 硬件固定功能的细分器 | 开发者在着色器里自己写 |
| 平台门槛 | DX11 | DX12 及以上，Win10 起 |

### 可变形地形

* **动态地形形变（Deformable Terrain）**

    * 前提是地形顶点全部由 GPU 在运行时细分生成，位置可在着色器中随时调整。

    * 把地面以下想成一排小弹簧：受压力时下陷，同时把少量物质向上隆起，拖拉机开过稻田就能压出沟。

    * 炮弹炸出的坑同理，但坑更深时必须同步更新物理碰撞，否则角色会踩着虚空走过去。

* **形变纹理（Deformation Texture）**

    * 在玩家周边生成一张地形形变贴图，脚印、车辙、打斗痕迹都记录在上面。

    * 玩家移动时贴图跟随平移，并保证数据前后一致；GPU 细分出的顶点采样这张图取得高度偏移。

    * 雪地这类效果只影响视觉与移动速度，不改变角色高度，因此实现最简单。

### 高度场的表达边界

* **无效数挖洞（NaN）**

    * 把要挖掉区域的顶点位置写成无效数，GPU 在顶点处理后检查位置，发现无效即丢弃所有引用该顶点的三角形。

    * 等价于一把以三角形为单位的橡皮擦，可以一片片挖空地形。

    * 按三角形删除的边界必然是锯齿，实际靠美术做一个完整隧道模型盖在洞口，遮住锯齿。

    * 这暴露了高程图的根本边界：每个平面位置只能有一个高度，洞穴、倒钩、反向峭壁必须借助其他物体或 hack 补足。

* **体素地形（Voxel Terrain）**

    * 在三维空间撒采样点，每点存 0 到 16 的权重，同时表示该处有无物质与物质密度，整个世界成为一片标量场。

    * 三维表达没有「一个位置一个高度」的限制，可以任意挖洞、做奇形怪状的结构。

    * Minecraft 是体素表达的典型；全动态地形（真能打洞、绕到敌人背后）已有前沿工作，但算法仍不成熟，不属于行业典型方案。

* **等值面提取（Marching Cubes）**

    * 取每个 cube 八个顶点的数值，判断等值面从何处穿过；八点取值组合归并后约十四种情况，每种对应固定切分方式，把 cube 切成若干三角形。

    * 所有 cube 的三角形拼起来就是水密的三角面片集。

    * 同一算法用于 CT 体数据重建、空气动力学流场可视化，以及最早的数字人（逐层冷冻切片后重建）。

    * 地形上远近精度不同、相邻 cube 尺寸不一时，接缝要保持水密的情况约有一百多种，实现方式是查表。

## 地表材质与纹理混合

### 材质图与混合权重

* **金属度-粗糙度材质（Metallic-Roughness，MR）**

    * 在基于物理的渲染（Physically Based Rendering，PBR）体系下，一种材质需要 base color、normal、roughness、metallic 与 height 五类信息。

    * metallic 只占一个通道，可共包（co-pack）进 base color 的 alpha 通道，省一张贴图。

    * height 不只用于凹凸，还是后续材质混合的关键输入。

* **混合贴图（Splat Map）**

    * 每个通道对应一种材质的混合权重，美术用笔刷在图上刷出沙多还是石多。

    * 材质数量上升到几十上百种后，splat map 还要存材质索引，指明该点使用了哪几种材质。

    * 渲染时按索引查表取出对应材质，再按权重混合。

    * 真实项目的材质量级：《幽灵行动》有十几种生物群落（biome）、近 140 多种自然材质混在同一世界。

### 高度混合

* **透明度混合的缺陷**

    * 直接按权重做 alpha 混合，等于把几种材质的渲染结果加权平均。

    * 观感错误：沙地过渡到石头时，沙子像浮在石头缝上方、蒙在石头表面，而不是嵌进缝里。

    * 真实情况相反：草与石头的交界处，草先从石缝里蔓延出来，不会直接长在石头表面。

* **高度混合（Height Blending）**

    * 混合两种材质时，先把各自的 height 按权重调整，再比较大小。

    * 高度高的一方权重衰减更慢，高度低的一方很快退出，于是沙子看起来侵入石头内部，却不会盖在石头表面之上。

* **偏置（Bias）**

    * 纯比大小是 0 到 1 的硬切，相机移动时边界信息高频闪烁，低视角远看时界线又过于锐利。

    * 当两种材质加权后的高度差落在 0.2 以内时，改为按权重插值，让过渡区仍带 albedo 混合。

    * 效果是过渡更自然、结果更稳定；这就是常见的纹理泼溅（Texture Splatting）。

    * 长文说明该变量在原实现中叫 depth，本质就是一个偏置量。

### 纹理数组与三维纹理

* **纹理数组（Texture Array）**

    * 把许多张同尺寸纹理摞成一个数组，采样时 Z 轴是层号（index），必须给整数层，不能采样 1.5 层。

    * 层与层之间没有空间关系，不跨层插值，按层直取，采样便宜。

    * 恰好匹配地表材质彼此无关的需求；《幽灵行动》的 140 多种材质用几组 texture array 就能装下。

* **三维纹理（3D Texture）**

    * Z 轴是连续空间坐标，采样点几乎不会正好落在体素中心。

    * 一次采样要在上下两层各取 4 个 texel 做双线性插值，再把两个结果插值一次，即三线性插值，共 8 个 texel。

    * 适合体数据：CT、流场、雾；不适合互不相干的表面材质。

| 维度 | 3D Texture | Texture Array |
| :--- | :--- | :--- |
| Z 轴含义 | 连续的空间坐标 | 离散的层号 |
| 能否跨层插值 | 能，这正是采样的一部分 | 不能，必须给整数层 |
| 采样代价 | 8 个 texel，三线性 | 按层直取，便宜 |
| 典型用途 | 体数据：CT、流场、雾 | 互不相干的表面材质 |

> **易错点**：3D texture 与 texture array 常被当成一回事；前者 Z 轴连续且要跨层插值，后者 Z 轴只是层号、绝不插值。

### 视差与位移

* **视差贴图（Parallax Mapping）**

    * 假设表面下方真有凹凸，从斜角看过去应采样到的位置与平面 UV 不同。

    * 按视线方向与 height 做光线步进，一小步一小步走出真实采样位置，立体感明显增强。

    * 代价是每像素要多走若干步；且只产生视觉凹凸，几何轮廓依旧像刀切一样光滑。

* **位移贴图（Displacement Mapping）**

    * 先用细分把近处网格分得非常细，再按 height 真正推动顶点位置。

    * 轮廓真的凸出来，但网格面数暴涨，依赖细分能力。

    * 目前大部分游戏仍以 bump 为主，地形中位移贴图少见。

| 对比项 | Parallax Mapping | Displacement Mapping |
| :--- | :--- | :--- |
| 做法 | 沿视线步进，改采样位置 | 细分网格，按 height 真位移 |
| 代价 | 每像素多走几步 | 网格面数暴涨，靠细分 |
| 轮廓 | 依旧光滑，像刀切 | 真的凸出来 |
| 现状 | 常见 | 地形里少见 |

### 采样开销

* **单次纹理采样的成本**

    * 带多级渐远纹理（mipmap）的二维纹理一次采样：上层 4 个 texel、3 次插值，下层 4 个 texel、3 次插值，两个结果再插一次。

    * 合计 8 个 texel、7 次插值。

* **多材质叠加的成本**

    * 一个像素混四种材质，开销乘四：32 个 texel、28 次插值，尚未计入混合本身的加减乘除。

    * 只要地形在屏幕上，那片区域的每个像素都要重复这套运算，早期地形渲染因此常把纹理管线压垮。

* **地址跳跃（Address Jumping）**

    * texture array 的层号在 003、075、064 之间来回跳，显存访问不连续。

    * 内存没有磁盘读写头，但地址反复跳转的效率同样很低，这是 splatting 方案的另一重成本。

## 虚拟纹理

### 分块与金字塔

* **虚拟纹理（Virtual Texture）**

    * > **定义**：只把当前视角用得到的纹理块装进显存，其余留在硬盘，按需换入换出。

    * 核心事实：任何时刻看到的地形只是全部地形的一小部分，太远处可直接裁掉，留在画面里的也只需很粗的精度。

    * 最早的同源技术是 MegaTexture，由 John Carmack 提出：游戏包体巨大，但任一时刻只用到很小子集。

    * 类比：出差只带一个小工具袋，需要什么让徒弟从家里取，不把整屋工具背上。

* **瓦片金字塔（Tile Pyramid）**

    * 地块尺寸取 2 的幂；最密一级 4 米 × 4 米地块配 1024 × 1024 贴图。

    * 往外一级 8 米 × 8 米地块，仍用 1024 × 1024 就足够表达；再远同理。

    * 每一层按均匀尺寸切瓦片（tile），每个 tile 固定 128 × 128 像素；每往下一层，tile 总数少四倍。

    * 当前视角看到的是大大小小、层级不同的 tile 混合。

* **物理纹理（Physical Texture）**

    * tile 被需要时，把它的材质与几何内容烘焙（bake）进显存中的 cache，这张实际驻留的图就是 physical texture。

    * 绘制各个 tile 时通过索引反向指回 physical texture 的对应区域。

    * 显存需求的级数为 $\sum_{k=0}^{\infty}(1/4)^k = 4/3$，收敛且有上限，无论看多远都不会爆。

### 烘焙与调度

* **一次烘焙，多次采样**

    * 原本每个屏幕像素都要做的材质混合，改为在 tile 载入时做一次，结果留在 physical texture 中。

    * 之后绘制屏幕只需直接取烘焙好的值，不再重复混合。

    * 这是现代引擎最主流的地形绘制方法；逐像素 splatting 属于学院派理论做法，实战基本已被虚拟纹理取代。

* **三级存储调度**

    * 整个系统在硬盘、内存、显存之间来回搬数据，由内存管理器发出换入换出指令。

    * 它本质上是硬盘、内存、显存三个地方的数据调度问题，用的就是分页思想。

### 数据通路

* **传统路径**

    * 硬盘读到内存并解压成原始数据，CPU 下指令，再经总线搬到显存，最后供 GPU 采样。

    * 真正的消费者是显存，与内存、CPU 关系不大，这段绕行没有必要。

* **DirectStorage**

    * 数据经过内存时保持压缩，不解压；到 GPU 内再解压。

    * 硬盘到内存、内存到显存两段传输的都是压缩数据，传输效率显著提高。

    * 现代显卡算力至少是 CPU 的十倍，解压这点负载可以承担。

* **直接内存访问（Direct Memory Access，DMA）**

    * 更彻底：硬盘直接读到显存，完全跳过内存中转。

    * 显卡之间也可直连交换数据，不必回到内存转手。

```text
传统路径
  硬盘 ──▶ 内存（解压成原始数据）──▶ 显存 ──▶ GPU 采样

DirectStorage
  硬盘 ──▶ 内存（保持压缩）──▶ 显存 ──▶ GPU 内解压 ──▶ 采样

DMA
  硬盘 ────────────────────────▶ 显存 ──▶ GPU
```

## 大地图的浮点精度

### 精度衰减

* **浮点精度（Floating-Point Precision）**

    * 32 位浮点只有 32 个 0 和 1，能表达的信息量有限；数字越大，小数部分的精度越低。

    * 表示地球到月球尺度上的每个点时，误差甚至可以超过 1。

    * 相机与球保持相对位置不变一路外移，走到 6 万公里区间球就开始剧烈抖动，不是物体在动，而是顶点坐标精度不够。

* **深度精度冲突**

    * 一堵墙有嵌进墙面约 0.05 米的窗台，表面贴一张离墙 1 毫米的海报。

    * 墙移到 2 公里外，海报与墙在深度上分不开，开始疯狂打架、闪烁。

    * 把坐标全存成 double 可以缓解，但数据量与带宽代价过大，不是可行解。

### 坐标原点修正

* **相机相对渲染（Camera-Relative Rendering）**

    * 把相机位置强行设为原点，所有物体坐标减去相机位置后再送入渲染。

    * 世界尺度没变，只是换了原点，让需要分辨的差值落到浮点有效位充足的数量级。

    * 虚幻与 Unity 都把它作为标准做法。

* **子关卡（Sublevel）**

    * 虚幻 5 把大关卡切成许多小 sublevel，每个 sublevel 内重置一次世界坐标系。

    * 与相机相对渲染解决的是同一类问题，只是作用范围在关卡组织层。

* **物理模拟的精度后果**

    * 渲染还能用各种 hack 遮掩，物理模拟不行：超大场景的数值表达不准会直接导致模拟爆炸。

    * 已有研究用定点数做物理模拟来规避浮点误差。

    * 星际尺度游戏（如《无人深空》）必须依赖这类技术。

## 环境细节与程序化生成

### 植被

* **树木渲染（Tree Rendering）**

    * 近处使用真实网格模型；中距离换成插片，插片逐级稀疏且要让玩家察觉不到 LOD 切换；最远变成 billboard，一次批量绘制一大批。

    * 这是一整套专门技术，成熟中间件 SpeedTree 专注树木与植被（foliage）渲染，单个植被渲染插件可以卖到几十万。

* **装饰物（Decorator）**

    * 地面上的草、小灌木丛、小碎石都归入 decorator，尽量用最简单的网格表达。

    * 早期游戏的典型破绽：远看草地郁郁葱葱，低头走近，草面片会跟着视线旋转，因为用的是视点相关的插片。

    * 3A 项目的 decorator 实现复杂得多，但术语与分层思路一致。

### 道路与贴花

* **样条道路（Spline Road）**

    * 用样条曲线（Spline）给出一组控制点，拉动控制点即可生成蜿蜒山路或笔直高速。

    * 道路不只是铺贴图：整条路的贴图要生成，高程场还要做侵蚀（erosion），把山挖掉、把路面挖平，否则坡度太陡车辆无法行驶。

    * 道路之间会穿插，不能把两张贴图直接混合盖在一起，否则会出现斑马线、人行横道式伪影。

* **贴花（Decal）**

    * 小尺寸贴片，射击游戏中墙上的枪眼、弹孔是最典型用法。

    * 通常附带法线效果，有时用视差贴图制造真实凹陷感。

    * 尺寸小、存在时间短，玩家不会细究。

### 程序化生成

* **程序化生成（Procedural Generation）**

    * 可自动生成流水对山体的侵蚀（山脊的由来）、道路、按坡度分配材质（陡处石头、缓处土地）、按海拔分配植被（阔叶林过渡到针叶林）。

    * 现代地形编辑仍以高程图加美术手绘混合贴图为主，程序化生成的比例在提高。

* **环境要素统一烘焙**

    * 道路贴图与 decal 贴图最终都烘焙到虚拟纹理上：一块 64 米 × 64 米 tile 里先混地形材质，再把道路纹理、贴花拍上去。

    * 复杂全部堆在烘焙阶段，运行时不再区分来源，整块渲染即可；只要 tile 还在，就不需要更新。

## 天空与大气的物理基础

### 天空的几何模型

* **卡门线（Kármán Line）**

    * 天空可抽象成一个球，球面即大气层上限，称为卡门线，位于地表以上 100 公里。

    * 这条线也是「太空飞船」资格的通俗门槛：没飞过 100 公里就不算进入太空。

* **云的空间尺度**

    * 云距离地表只有几百米到上千米，移动时能感到它巨大的体量。

    * 云是三维体积，不是一张面，这决定了它必须用体积渲染求解。

* **雾（Fog）**

    * 雾也是大气现象，但在制作中更多被当作 artist 控制画面层次的效果。

    * 长文将其留到后讲效果时处理，不并入天空与云的物理模型。

> **易错点**：天空与云是两套截然不同的表达方法。天空是无限远球壳，用解析或预计算的光学模型算颜色；云是近处三维场，靠体积渲染求解。混在一起做，两边都做不好。

### 经验拟合方案

* **解析拟合天空模型**

    * 不做物理模拟，直接观察天空颜色并用模型拟合，类似材质里的 Blinn-Phong。

    * 只有两个输入：视线与天顶的夹角（通常取 0 到 $\pi$），以及视线方向与太阳方向的夹角 $\gamma$。

    * 给定两个角直接算解析解得到颜色，与实拍 ground truth 对比效果尚可，极其简单。

* **模型的适用边界**

    * 只能站在地表看；从太空穿越大气层落地这一过程无法表达。

    * 所有参数写死，无法表现下雨等天气变化。

    * 按 3A 标准无法使用，只适合要求不高的移动端项目。

### 参与介质与传输方程

* **参与介质（Participating Media）**

    * 空气中混着大量细小物质，既透明又不透明，光一路走一路与它们交互。

    * 两类粒子：气体分子（氮气、氧气、甲烷、二氧化碳）与气溶胶（aerosol，灰尘与细小悬浮颗粒）。

    * 两类粒子都会折射、反射光线；正因为不是真空，才有各种复杂的光学现象。

* **辐射传输方程（Radiative Transfer Equation，RTE）**

    * 光穿过一段介质只遭遇四件事：

        ```text
        入射光 ──► 介质微元 ──► 出射光
                      │
                      ├─► 吸收 absorption        σ_a，每单位距离被吃掉多少
                      ├─► 外散射 out-scattering   σ_s，被粒子弹向四面八方
                      ├─► 自发光 emission        高温或通电，游戏中很少真加
                      └─◄ 内散射 in-scattering   别处散射来的光又拐进这条光路
        ```

    * 吸收系数 $\sigma_a$ 表示每单位距离被吃掉的能量；外散射系数 $\sigma_s$ 表示被粒子弹向四面八方的能量。

    * 自发光来自高温（火焰）或通电（闪电），游戏中很少真的加入。

    * 内散射最要命：一个点收到的光还包括周边被点亮的气体分子散射过来的光，需要在球面上对所有方向积分。

    * 四项合起来是一维简化形式的 RTE；完整三维版本是积分微分方程，工程上不需要记公式。

* **体积渲染方程（Volume Rendering Equation，VRE）**

    * 从眼睛 $X_v$ 看向远处点 $X_m$，看到的能量等于通透度乘以该点自身的光，加上沿途散射进视线的能量：

        $$L(X_v,\omega) = T(X_m,X_v)\,L(X_m,\omega) + L_{\text{scatter}}(X_v,\omega)$$

    * 通透度 $T$（transmittance）是沿路径积分的结果，表示远处那点有多大比例能活着到达眼睛。

    * 散射项 $L_{\text{scatter}}$ 是沿途所有粒子把别处来的光拐进这条视线的能量总和，同样是路径积分。

    * RTE 描述每一点如何变化（微分形式），VRE 沿视线把这个变化积起来（积分形式）。

### 瑞利散射

* **瑞利散射（Rayleigh Scattering）**

    * 粒子尺寸远小于波长时（气体分子），光几乎朝四面八方均匀散射，方向性很弱。

    * 波长越短散射越强：强度系数含 $1/\lambda^4$，蓝光、紫光、紫外线被散射得最狠，红光最弱。

    * 相函数（phase function）只有两部分：几何形状为 $1+\cos^2\theta$，极坐标下是两头鼓、中间瘪的腰果形；另一部分是含波长、夹角、海拔的强度系数。

    * $\theta$ 绕光轴旋转不变，因此瑞利散射在方位上各向同性。

    * 海拔 $h$ 决定大气密度：海平面最大，越往上越稀薄；工程上直接假设线性变化，用标准密度 $N$ 与实际海拔密度描述散射变化。

* **蓝天与晚霞的成因**

    * 太阳直射时大量蓝光被散射、来回反弹，从各个方向进入眼睛，所以天空是蓝的；红光基本直接照到地面。

    * 傍晚太阳很斜，光要穿过很长一段大气，蓝光在到达眼睛前已被散射到大气边缘甚至散出大气，剩下的光偏红。

    * 大气吸收再把红色加重一层。

### 米氏散射

* **米氏散射（Mie Scattering）**

    * 粒子尺寸接近或大于波长（气溶胶、小水珠、灰尘）时的行为。

    * 方向性明显，沿光前进方向略强。

    * 对波长不敏感，所有波长一视同仁，因此不会给光染色。

    * 相函数由一堆 $\cos\theta$ 项拼成，形状像带鱼或章鱼，具体形状由各向异性参数 $g$ 控制。

* **各向异性参数（Anisotropy Parameter，g）**

    * $g=0$ 时退化成与瑞利散射相同的花生形。

    * $g$ 越接近 1，前向瓣越尖；$g<0$ 表示往光线相反方向反射更多。

    * 实际使用中 $g$ 基本取正数，并开放给 artist 调；调 $g$ 等于调粒子的手感。

* **米氏散射解释的现象**

    * 雾是白的：雾由空气中的小水珠构成，属于气溶胶，白光照下所有波长被无差别散射。

    * 太阳周围的日晕：前向散射把光聚进眼睛。

    * 雨雾天路灯周围的光晕，机理相同。

| 对比项 | 瑞利散射 | 米氏散射 |
| :--- | :--- | :--- |
| 粒子类型 | 气体分子 | 气溶胶、小水珠、灰尘 |
| 尺寸与波长 | 远小于 | 接近或大于 |
| 波长依赖 | 强，正比于 $1/\lambda^4$ | 基本无 |
| 方向性 | 弱，近似各向同性 | 强，前向略强 |
| 关键参数 | 海拔密度 $N(h)$ | 各向异性参数 $g$ |
| 典型现象 | 蓝天、晚霞 | 白雾、日晕、路灯光晕 |

### 大气吸收

* **臭氧与甲烷的吸收**

    * 两者都是吸收长波的高手，会把红光吃掉。

    * 海王星呈蓝色，是因为表面大量甲烷吸收了太阳光中的红光。

    * 臭氧以吸收紫外线闻名，但在可见光波段吸收偏向长波一端，两套机制分属不同波段。

* **均匀分布假设**

    * 计算大气时把臭氧与甲烷视为均匀分布在整个大气层。

    * 真实分布集中在某一层（如臭氧层），但按真实分布建模会复杂到不可用，工程上摊匀处理。

### 单次散射与多次散射

* **单次散射（Single Scattering）**

    * 视线上的每个粒子被太阳照亮，再按散射方程（瑞利与米氏各算一遍）向视线方向投出能量。

    * 每个粒子的贡献还要乘上它到眼睛这段路径的通透度，最后沿视线累加。

* **多次散射（Multi-Scattering）**

    * 不在视线上的粒子被照亮后，把光送给视线上的某个点，该点再沿视线方向送出能量。

    * 只算单次散射时，太阳压到地平线以下，天空会由暖转冷蓝，但山背面是死黑，因为那个方向没有被太阳直射的粒子。

    * 真实大气中头顶空气也被点亮，散射光会照亮山背后的空气，因此背光面仍有亮度。

* **与全局光照的区别**

    * 全局光照（Global Illumination，GI）依赖清晰表面：另一面山被照亮后把光反射过来。

    * 多次散射面对的是没有清晰表面的连续介质，充满整个空间的每个微元都在参与，必须全积分才有那个效果。

    * 类比经典物理的以太：每个微元都在做复杂的事。

    * > **易错点**：多次散射常被误当成 GI；GI 依赖清晰表面的反射，多次散射是连续介质中每个微元的积分，两者不可互换。

## 大气散射的求解方案

### 光线步进

* **光线步进（Ray Marching）**

    * 沿一条视线一步一步向前推进，把沿途效果逐段累加。

    * 所有大气效果算法本质上都采用这条思路。

* **单次散射的逐点计算**

    * 沿视线均匀采很多点，每点计算太阳照到该粒子的强度与方向，再按相函数算出向视线方向散射的能量。

    * 每个采样点到眼睛之间还要乘一次通透度，最后累加得到整条视线的单次散射亮度。

### 预计算大气散射

* **预计算大气散射（Precomputed Atmospheric Scattering）**

    * Bruneton 于 2008 年提出，用查表替代运行时积分。

    * 地球半径取 6440 公里，大气层边界在 6540 公里，即 100 公里厚。

    * 大气中需要预计算的只有两样：通透度与散射。

    * 运行时开销很小，日出日落、从地表一路飞到天上都能处理；FIFA、极品飞车等作品采用过这条路线，DICE 的工程实践把它推到生产可用。

* **通透度表**

    * 表按地表某点的海拔 $h$ 与视线天顶角的 $\cos\theta$ 组织，只存二维。

    * 不需要太阳方向：通透度只回答这条路有多透，与太阳在哪无关。

    * 表内存的是从该点沿该方向走到大气层边界的通透度；太空中能看见星星，说明 100 公里厚的大气仍是通透的，这张表就是把「有多通透」量化。

* **路径通透度的除法还原**

    * 通透度沿路径连乘：从 $X_v$ 到大气层顶，等于先走 $X_v \to X_m$ 再走 $X_m \to$ 顶。

    * 因此任意两点间通透度等于两个表值相除：

        $$T(X_m \to X_v) = \frac{T(X_v \to \text{top})}{T(X_m \to \text{top})}$$

    * 一张二维表加一次除法，就还原出原本四维的路径通透度。

* **单次散射表**

    * 参数化为三个立体角：视线天顶角、太阳天顶角（太阳在天顶时余弦趋近 1，压到地平线时趋近 0）、视线与太阳的夹角 $\phi$。

    * 大气是完美球形且各向同质，球面上任一点的天顶方向就是法线方向，因此这三个角足以描述该位置看向太空沿途的散射。

    * 再沿高度采样一遍构成第四维，打包进 3D texture；海拔 100 米、200 米、300 米各一格，站在 175 米就在 100 与 200 米之间插值。

    * 这些信号都是低频，插值不会出问题；打包时比纹理数组更合适的是 3D texture。

* **多次散射的迭代**

    * 把所有被散射照亮的点再通过通透度积一次分，得到二次散射；再积一次得到三次。

    * 实际做到三到四次就够，每增加一阶画面只亮一点点，后面看不出来。

    * 多次散射表与单次表结构相同，因为参数化相同，只是能量阶数不同。

    * > **提示**：终止条件是工程上的硬性阶数上限，不是物理阈值；所谓辐照度低于阈值只是理论说法。

* **远景的大气染色**

    * 远处物体不只要加雾，还要被大气染色。

    * 先算视线打在大气层边缘时的出射散射能量，再算远处物理点散射过来、被通透度削弱后的能量，两者之差就是远山接收到的天光。

    * 效果是远山越来越蓝，而不是单纯越来越暗。

### 预计算方案的代价

* **烘焙成本**

    * 每一张四维表都要做一次光线步进。

    * 手机上计算吃力；PC 上有 compute shader 也要几毫秒甚至到一秒。

    * 可摊到多帧，或在关卡加载时先烘一遍。

* **参数无法实时调整**

    * 预计算的表按固定大气参数烘焙。

    * artist 要做「蓝天白云突然转雨」，空气里多了大量小水珠，散射与折射全变，两个状态间还要平滑插值；每帧改参数等于每帧重烘表。

    * 结果是编辑器里无法实时调数值，动态天气不可行。

* **运行时插值也不便宜**

    * 空间换时间，但要大量高维表插值。

    * 四维数据硬塞进三维纹理，很多插值要手动做：取一个值要到四个点各采一次再自己插，内存跳来跳去。

### 可扩展实时方案

* **假设一：多次散射是低频的**

    * 对空气中的分子而言，来自四面八方的散射可近似为各向同性。

    * 若入射光各方向均匀，不论用什么相函数，出射光在各方向上也均匀；带方向的积分退化为纯百分比衰减，相当于大气分子被加热后再辐射，损失固定比例能量。

    * 只要算一阶到两阶散射标定这个比例，更高阶都是同一比例连乘，形成等比级数。

    * 等比级数求和给出无穷次反弹总贡献的闭式解，高中知识即可。

* **假设二：砍掉动态维度**

    * 位置每帧变化，为每个海拔存一份没有意义，去掉 $h$ 维。

    * 太阳每帧都在动，但在单帧内固定，去掉太阳方向维。

    * 只剩天顶角与 360 度环角两维，整个天空的多次散射用一张二维表表达。

    * 另做一张 3D texture 存沿路径累积的介质光学厚度（通透度的积分），按距离采样，雾效与远处衰减一并得到。

* **精度代价**

    * 高散射密度等情况下误差偏大，可能出现色偏。

    * 换来的是参数可实时调整：两个太阳、日月同照、气体成分变化、下雨起雾都能表达。

    * 这是迪士尼式取舍：不追求物理完全正确，追求 artist 好用。

| 对比项 | Bruneton 预计算 | 可扩展方案（UE 路线） |
| :--- | :--- | :--- |
| 多次散射 | 逐阶做完整路径积分，烘 3 到 4 阶 | 各向同性假设加等比级数，解析求和 |
| 表维度 | 四维：海拔、天顶角、太阳天顶角、视日夹角 | 二维：天顶角、环角，另加 3D 路径积分 |
| 动态天气 | 每帧重烘，实际不可行 | 参数可实时调整 |
| 精度 | 物理上更严谨 | 高散射密度下误差偏大，可能色偏 |
| 使用方式 | 离线烘焙为主 | 运行时主用 |

```text
   每帧预计算                            运行时
   ─────────                            ──────
   天顶角 × 环角  ──► 2D 多次散射表 ──┐
                                      ├──► 按视线方向查表插值 ──► 天空颜色
   沿路径距离     ──► 3D 光学厚度表 ──┘
```

## 体积云

### 云的类型与表达路线

* **云的三种基本形态**

    * 层云（Stratus）：薄薄的一层。

    * 积云（Cumulus）：堆起来、越来越厚。

    * 卷云（Cirrus）：像卷起来的羊毛。

    * 大气中的云基本是三类在不同高度上的组合：低空为层云与积云，中空几千米为高空层云与高空积云，再往上为卷状层云与卷状积云。

* **被淘汰的两条路线**

    * 用网格硬做：美术摆几个大块，再用噪声与侵蚀算法雕成云，偏学术，实际很少使用。

    * 用大量半透明插片与 alpha 混合堆云：十年前的网游常用，观感像天上飘的巨大棉花糖，达不到 3A 标准。

* **体积云建模（Volumetric Cloud Modeling）**

    * 全部在运行时由 GPU 生成，形态可任意变化、可漂移，是全动态方案。

    * 唯一缺点是算法复杂、开销极大，云做不好会拖垮整个游戏的效率。

    * 3A 项目基本都在使用。

### 天气图与噪声

* **天气纹理（Weather Texture）**

    * 提供两部分信息：云在空间上的随机分布（哪里有云、哪里没有），以及存在某个通道中的 0 到 1 厚度值。

    * 厚度值 0 附近是层云，中间是层云与积云混合的层积云（Stratocumulus），1 附近是积云。

    * 同一空间位置上把该值调高，云就肉眼可见地变厚。

    * 平移天气图云就飘动，对图做扰动云就变形。

* **柏林噪声（Perlin Noise）**

    * 用多项式即可生成棉花絮状的连续噪声。

* **沃利噪声（Worley Noise）**

    * 与 Voronoi 分割同源：给一堆点，把空间划成以这些点为最近中心的 cell，类似显微镜下以细胞核为中心形成的细胞壁。

    * 反过来使用即得到泡泡、絮状团块的观感。

    * 与 Perlin 互补：Perlin 像棉花丝，Worley 像絮状团块。

* **噪声腐蚀流程**

    * 只用天气纹理生成的云形状方正，像天上飘的白木头。

    * 先用低频噪声逐层咬掉一些区域，把大形状打碎；再用高频噪声补细节，把边缘做出絮状。

    * 多层噪声叠加是在逼近分形，真分形无法每帧计算。

    * 本质是着色器里的 hack，改一行或动一个 magic number，云的形态就明显变化。

### 步进渲染与成本

* **分段步长的光线步进**

    * 已知云大致在特定高度，先用 50 到 100 米的大步长快速推进到云层附近。

    * 命中第一块云后立即把步长缩到 10 到 20 米，一小步一小步挪，直到穿出云体边界才停止。

    * 每个采样点计算三件事：大气通透度、散射、多次散射。

    * 云不会真的生成面片：云的表面全是锯齿，做成几何需要上百万甚至上千万个面，无法绘制。

* **云内散射的简化**

    * 云内部散射是另一套技术，但比天空简单。

    * 原因一：做得太复杂计算机扛不住。

    * 原因二：云的通透度很低，方程里很多项可以直接砍掉，能做大量简化。

* **降采样与重建**

    * 每个像素都是一条光线，都要做多次采样与散射计算，成本极高。

    * 常见省钱办法是屏幕降采样：只用二分之一分辨率，即四分之一像素量，算完再模糊（blur）贴回。

    * 更后续的手段包括 DLSS 一类重建技术。

* **开销分布**

    * 生成那一半还好：噪声函数效率很高，很快能在一块 3D 纹理里腐蚀出一朵云。

    * 渲染才是大头：光线步进要采样，每点要算散射，还要把太阳与大气对云颜色的影响带进来，远在天边的云要从天光吸收光才自然。

    * 每个像素就是一整套运算。
