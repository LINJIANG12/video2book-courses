# 离散微分几何与微分坐标

## 三角网格的两种理解

* **二维到三维的映射**

    * > **定义**：网格曲面本质上是从二维参数域到三维空间的一个映射；规整情形是高度图那样的函数（每个点对应一个三维坐标），一般情形定义域可以是任意结构、任意拓扑。

    * 映射的本质由定义域的维数决定：值域维数比定义域低就是降维，比它高就是参数曲面——网格是参数型映射，只是映射函数分片线性。

    * 网格只是光滑性差一点，本质上仍是连续函数、连续曲面。

* **一张图的提升（lifting）**

    * > **定义**：网格本质上是一张 $R^2$ 的图（点、边、面），把每个顶点映射到空间位置就得到曲面；顶点坐标放进 $R^3$ 是三维嵌入，放进 $n$ 维就是 $n$ 维空间中的一张 $R^2$ 流形。

    * 拓扑学里这个操作叫提升：点的连接关系不变，只把顶点"拎"到三维——像平铺在地上的渔网被拎起来，变成一张下垂的曲面。

    * 提升只改变顶点位置，三角形、边这些关联关系都没变，所以网格本质上仍是二维流形。

* **分片线性逼近（piecewise linear approximation）**

    * > **定义**：从原曲面采样，把相邻采样点连成三角形，得到一张没有缝隙的分片线性曲面去逼近原光滑曲面，也叫离散曲面。

    * 整张网格只有 C0 连续、连 C1 都没有——三角形之间只是拼起来，不可能光滑。

    * 从泰勒展开的角度看，每个平面片相当于在曲面上某一点做的一阶（线性）展开，因此是非常低阶的逼近。

* **网格即参数化**

    * 平铺的那张图就是参数域：图上一个点对应曲面上一个点，空间坐标 $(x,y,z)$ 是 $(u,v)$ 的函数。

* **采样起点**

    * 扫描仪扫出的就是曲面上点的采样：点采得密网格就精细，点少就粗糙；原曲面方程未知，能做的只是采样后把相邻点连起来。

## 网格的数据结构与流形约定

* **图结构（graph）**

    * > **定义**：顶点集合加边集合构成的非线性数据结构；对网格而言，顶点集合存空间点坐标，边是顶点对 $(v_i,v_j)$（有顺序叫有向边，无顺序是无向边），面集合 $f$ 在此假设全为三角形。

    * 图在生活中的原型：路口与道路（导航背后就是图上的最短路算法）、人与人关系（社交网络）、论文之间的引用网络。

    * 网格的操作与后面更复杂的各种运算全是图上的活，这部分数据结构必须自己掌握扎实。

* **点、边、面的可推性**

    * 顶点坐标是最原始的几何信息，必须先给定；边与面携带的都只是连接关系。

    * OBJ 这类早期格式非常简单：`v` 行用三个实数记录一个顶点坐标，`f` 行记录一个面、引用顶点编号——边靠推算。

| 已知信息 | 能否推出第三样 | 怎么推 |
| :--- | :--- | :--- |
| 顶点 + 面 | 能推出边 | 收集每个面的三条边，去掉相邻面共享造成的重复 |
| 顶点 + 边 | 能推出面 | 从一条边出发不断找相邻的下一条边，绕回起点即得一个面 |
| 边 + 面 | 推不出顶点 | 边和面只带连接关系，顶点坐标是原始几何信息，必须先给定 |

* **多边形网格**

    * 任何多边形网格都可以转换成三角网格（如四边形中间加一条对角线），处理难度没有太大差别，所以只讨论三角网格。

* **流形（manifold）**

    * > **定义**：曲面上任何一点的无穷小邻域都拓扑同胚于圆盘，这样的曲面叫（二维）流形，否则就是非流形。

    * 典型非流形：两张面只在一个点相碰、两个圆锥共享一个顶点、一条边上有三个面——绕这些点/边转一圈不是两张面。

    * 非流形结构一概不讨论（微分几何与更广的数学在流形结构上都会顺利得多）；遇到就先改造成流形：把贴在一起的面拆开、去掉多余的面。

* **数据结构选型**

    * 没有最好的数据结构，只有适合应用的数据结构：半边结构是大部分几何框架（含 Utopia）的选择，libigl 用边表、矩阵式的存储；两者能做同样的处理，只是不同应用里效率各有高低。

    * 选型看软件或应用里哪类操作多、哪种结构对它优势大、总体效率会不会提升；初学者建议先用熟一种，别的结构只是点线面关系的存储逻辑不一样。

* **空间与时间的矛盾**

    * 存得多（把每个点的邻域都存下来）：关系直接查、不用找不用算，在线算得快、算法性能好，但内存消耗大。

    * 存得少（如半边结构找一个一邻域得顺着指针遍历一遍）：省内存，但在线消耗 CPU 时间、程序可能慢一点。

    * 存得多算得快还是存得少算得慢——要在内存和 CPU 之间打一个平衡，没有最完美的数据结构。

## 半边结构

* **半边结构（half-edge structure）**

    * > **定义**：把一条边拆成两个方向相反的半边、以边为中心存储网格邻接关系的数据结构；在大部分应用与项目里通用，是非常成熟的数据结构。

    * > **注意**：不同库的半边实现会有差异，有的可能多存几条信息，但基本上思路都是这一个。

* **半边的四个成员**

    * `vertex`：半边指向的顶点；`pair`：同一条边上与它方向相反的那另一个半边；`face`：它所属的面；`next`：同一面内的下一条半边。

    * 顶点存坐标外加一条从它出发的半边，面只存它边界上的某一条半边——三个结构体就这么多成员，后面所有邻域查询都靠这几个指针转出来。

```cpp
struct HalfEdge {
    Vertex*   vertex;    // 半边指向的顶点
    HalfEdge* pair;      // 配对的另一半边（同一条边、反向）
    Face*     face;      // 它所属的面
    HalfEdge* next;      // 同一面内的下一条半边
};
struct Vertex {
    Point3    position;  // 顶点坐标
    HalfEdge* halfedge;  // 从该顶点出发的某一条半边
};
struct Face {
    HalfEdge* halfedge;  // 该面边界上的某一条半边
};
```

* **两个半边与两侧邻面**

```text
           v2
          /  \
         / F1 \
        /      \
    v0 *--he--->* v1
       *<-pair--*
        \      /
         \ F2 /
          \  /
           v3
```

    * he 与 he->pair 是同一条边 $(v_0,v_1)$ 的两个方向，各归属一侧的面；四条指针正好对应半边结构体里的四个成员。

* **四类常用查询**

    * 找半边两端点：本半边存的顶点是终点，pair 存的顶点就是起点。

    * 找两侧邻面：本半边的 face 是一侧的邻面，pair 的 face 是另一侧的邻面。

    * 找面的所有半边：从面存的那条半边反复走 next，转回起始半边即停——一个循环就把面边界上所有半边拿到。

    * 找顶点周围所有半边：从顶点存的那条半边开始反复做 "pair 再 next"——pair 翻到边的另一侧，next 在那个面里转到下一条半边，正好是从此顶点出发的下一条半边，每转一步遇到下一个相邻顶点。

```cpp
Vertex* v1 = he->vertex;        // 半边指向的顶点（终点）
Vertex* v0 = he->pair->vertex;  // 配对半边指向的顶点，即本半边的起点
Face*   f1 = he->face;          // 本半边所在的面
Face*   f2 = he->pair->face;    // 另一侧的邻面

// 绕面一圈
HalfEdge* begin = face->halfedge;
HalfEdge* he    = begin->next;
while (he != begin) { he = he->next; }

// 绕顶点一圈
HalfEdge* begin2 = vertex->halfedge;
HalfEdge* h      = begin2;
do {
    h = h->pair->next;          // 下一条从该顶点出发的半边
} while (h != begin2);
```

## 曲线的微分几何

* **参数曲线与切向**

    * 光滑参数曲线 $C(u)$ 是单参数向量值函数：对每个分量分别求导得到 $C_u$（平面曲线是二维向量，空间曲线是三维向量）。

    * $C_u$ 与曲线在该点相切：切线在这一点与曲线只有唯一的交点。

* **Frenet 标架（Frenet frame）**

    * 二阶导数 $C_{uu}$ 一般与 $C_u$ 方向不一样，指向曲线弯转的那一侧（与主法向同向）。

    * $C_u$ 与 $C_{uu}$ 做叉积得到从法向 $\mathbf{B}$；从法向再与切向做叉积得到法向 $\mathbf{N}$。

    * 切向 $\mathbf{T}$、法向 $\mathbf{N}$、从法向 $\mathbf{B}$ 构成相互垂直的直角坐标架，并且是右手系——只要该点非退化就成立；若该点退化（如曲率为零），这个标架就不成立。

* **密切平面（osculating plane）**

    * 空间曲线在某点由切向与主法向张成的平面；它与曲线截出一条平面曲线。

    * 这张平面内与切线垂直、指向弯转一侧的方向，就是空间曲线在该点的法向。

* **曲率（curvature, $\kappa$）**

    * > **定义**：用二阶接触的密切圆定义——曲率是密切圆半径的倒数，度量该点弯曲的程度。

    * 曲率大表示密切圆半径小、弯得很厉害；直线可以看成一个无穷大的圆，曲率等于零。

    * 曲率与参数化无关：不管怎么参数化这条曲线，算出来的曲率都一样，它是曲线本身的几何量。

    * 曲线论基本定理：把每个点的曲率都给定，这条曲线的形状就唯一确定，只相差一个刚性变换（摆放位置）。

## 曲面的微分几何

* **参数曲面与切平面**

    * 曲面是三维空间中的二维流形，一定是双参数的：$S(u,v)$；偏导 $S_u$、$S_v$ 与向量值函数一样，是对三个分量分别求偏导得到的向量。

    * $S_u$ 与 $S_v$ 相互不共线（相互无关），于是可以张成一张平面——切平面。

    * 切平面上的任何一条直线都与曲面只有一个交点，都属于切线；曲面的"切线"不是某一条特定的线。

    * > **易错点**：要说"某一条切线"，必须先指定方向——切线是带方向的。

* **曲面法向**

    * 两个偏导做叉积、再归一化（让法向的模等于一）：

$$\mathbf{n}=\frac{S_u\times S_v}{\lVert S_u\times S_v\rVert}$$

* **方向曲率（directional curvature）**

    * > **定义**：在切平面里取一个方向 $\mathbf{t}$，由 $\mathbf{t}$ 和法向 $\mathbf{n}$ 张成一张平面，这张平面与曲面截出一条平面曲线，这条曲线的曲率就是该方向的方向曲率。

    * 这张截面平面可以绕 $\mathbf{n}$ 转满 360 度，每个方向交出一条曲线、对应一个曲率——在空间曲面上谈曲率都是带方向的。

* **主曲率（principal curvature）与欧拉公式**

    * 360 度里无穷多个方向中，有一个方向的曲率最大、一个最小，并且这两个方向一定相互垂直——这对任何曲面都成立；最大、最小曲率记 $\kappa_1$、$\kappa_2$，对应方向叫主方向。

    * 欧拉公式：与最大主曲率 $\kappa_1$ 方向夹角为 $\theta$ 的斜方向曲率

$$\kappa(\theta)=\kappa_1\cos^{2}\theta+\kappa_2\sin^{2}\theta$$

    * 两个组合系数 $\cos^2\theta$、$\sin^2\theta$ 都不小于零且相加等于一，所以任何方向的曲率都夹在最大主曲率与最小主曲率之间。

## 高斯曲率、平均曲率与特殊曲面

* **两个组合曲率**

    * 高斯曲率（Gaussian curvature, $K$）是两个主曲率的乘积；平均曲率（mean curvature, $H$）是两个主曲率的算术平均：

$$K=\kappa_1\kappa_2,\qquad H=\frac{\kappa_1+\kappa_2}{2}$$

* **等距不变量**

    * 等距变换：曲面发生变形时任意两点之间的距离不发生改变——如把纸卷成圆柱或圆锥，只做弯曲、没有撕裂与挤压。

    * 可以证明等距变换下高斯曲率不变；平面沿任何方向截出来都是直线、所有方向曲率为零（$\kappa_1=\kappa_2=0$），所以圆柱、圆锥每一点的高斯曲率一定等于零。

* **可展曲面（developable surface）**

    * > **定义**：能展开成一张平面、且展开过程不发生任何撕裂与挤压变形的曲面；特征是处处高斯曲率为零——反过来，处处高斯曲率为零的曲面一定可以等距展开成一张平面。

    * 三类可展曲面：柱面、锥面、切线面——切线面随便找一条空间曲线，由它的所有切线构成（拿一张纸随意扭一下就得到一个切线面）；切线是直线、沿直线方向不弯，所以切线面一定可展，且总能找到一条曲线使这个面恰好由曲线上每个点的切线所组成。

* **极小曲面（minimal surface）**

    * > **定义**：处处平均曲率等于零的曲面，是面积达到最小的曲面。

    * 现实原型是肥皂泡：肥皂膜在表面张力作用下缩成最小的面积，天然就是极小曲面；能用表达式写出来的代数曲面中也有天然就是极小曲面的。

    * 每个点都是鞍点：总有一个方向凹、另一个方向凸，所以整体看起来特别舒服；极小曲面上的点全是双曲点——平均曲率要等于零，必须一正一负才能抵消。

    * 建筑大屋顶用它有两个原因：面积最小，省材料、省制造成本；每个点都是鞍点，雨水雪落在上面是不稳定平衡、一定沿凹的地方流掉，屋顶不容易积水积雪、不会被压垮。

* **三类曲率点**

| 点型 | 主曲率特征 | 直观形状 |
| :--- | :--- | :--- |
| 椭圆点 | $\kappa_1$、$\kappa_2$ 同号 | 两个方向朝同一侧弯 |
| 抛物点 | 恰有一个主曲率为零 | 一个方向是直的 |
| 双曲点（马鞍点） | 一正一负 | 像马鞍面，两个方向朝相反侧弯 |

* **主方向场**

    * 每点的最大、最小主曲率方向都相互正交，两个方向画在一起是一个小十字；把整张曲面的主方向场画出来即可观察主曲率方向的分布。

* **局部与整体微分几何**

    * 局部微分几何研究一个曲面的无穷小邻域里的微分属性（法向、曲率这些性质）；整体微分几何研究亏格、欧拉示性数等整体性质。

## 从光滑到离散的估计思路

* **离散化的矛盾**

    * 网格曲面分片平面：每个平面片内部无穷阶光滑，但边上、顶点上各平面片不可能全部共面（全共面整张网格就成了一个平面），所以只有 C0 连续、达不到 C1——不光滑就不可微，曲率这些微分量没法按定义去算。

    * 网格顶点是从一张（可能光滑的）曲面上采样来的，原曲面一定有它的微分属性；任务是只凭观察到的采样点，把原光滑曲面上的法向、曲率估计出来——由此产生把微分几何离散化、针对离散三角网格研究的离散微分几何。

* **连续逼近路线**

    * 把附近的点找来，在这个邻域里用光滑曲面（如抛物面）拟合局部形状，拟合问题变成求曲面系数；再用拟合曲面在该点的属性充当曲率、高斯曲率这些量。

    * 精细做法：在该点建立局部坐标系——以法向为 z 轴、与法向垂直的切平面为 xy 平面，把邻域点当成这个局部标架下的数据点，拟合二次或三次函数（两个方向都有的双二次、双三次多项式）。

    * 用得好逼近阶可以做得比较高；逼近函数也可以换成分细曲面、隐式曲面等——这一类工作的差别主要是函数空间的选择。

* **离散直接路线**

    * 把周围相邻面片的法向平均一下作为该点的法向；更精确的做法是按面积加权——很小的三角形贡献就应该小一点。

* **一邻域（1-neighborhood, $N_1$）**

    * > **定义**：跟当前顶点只有一条边直接相连的那些顶点的集合；$N_2$ 是再往外扩一圈（把一邻域所有点的一邻域并进来），三邻域以此类推。

    * 离散情形的"无穷小邻域"就用面片组成的局部邻域来代替——只要网格足够密、边足够短，一邻域就是无穷小邻域的近似；无论算法还是曲率估计，大部分情况下用的都是一邻域信息。

    * 邻域越大考虑的几何信息越多；一邻域毕竟有时会受噪声影响，故意取更大的范围能稳一点。

* **经典文献**

    * 2003 年的名为"离散微分几何算子"的工作是开创性文献，非常详细地推导了平均曲率、高斯曲率等在网格上怎么做离散计算；后来发展考虑的东西更多，如外微分、曲面（黎曼几何）上的微分等，SIGGRAPH 上有专门讲离散微分几何的教程。

## 离散曲率公式

* **平均曲率：余切公式**

    * 对顶点 $\mathbf{x}_i$ 取一邻域 $N_1(i)$；每条边 $(\mathbf{x}_i,\mathbf{x}_j)$ 被两个三角形共享，取这条边所对的两个角 $\alpha$、$\beta$，把它们的余切加起来作为这条边的权：

$$\kappa_H(\mathbf{x}_i)\,\mathbf{n}_i=\frac{1}{2A_i}\sum_{\mathbf{x}_j\in N_1(i)}\bigl(\cot\alpha_{ij}+\cot\beta_{ij}\bigr)\bigl(\mathbf{x}_i-\mathbf{x}_j\bigr)$$

    * 等式左边是"平均曲率乘法向"这个向量：方向给出该点的法向，模长给出平均曲率的大小。

    * 分母中的 $A_i$ 取顶点 $i$ 的 Voronoi 区域面积（顶点周围一圈的阴影面积）；公式可从拉普拉斯–贝尔特拉米算子与平均曲率之间的经典定理一步一步离散化推导出来。

* **高斯曲率：角度亏量**

    * 由高斯–博内定理离散化推得：

$$K(\mathbf{x}_i)=\frac{2\pi-\sum_{j}\theta_j}{A_i}$$

    * 分子是 $2\pi$ 减去这一圈三角形在该顶点处的内角之和，分母是相应的 Voronoi 区域面积。

    * 直观理解：平面上这一圈角加起来恰好是 $2\pi$，高斯曲率就等于零；一圈角的和与 $2\pi$ 的差就是高斯曲率的来源。

* **Color Map 可视化**

    * 用颜色棒（color bar）把标量值画到曲面上：最小值映射蓝色，中间用绿色（有时是黄色），最大值映射红色；把算出来的值归一化到这个区间，每个值在颜色棒上找到一个颜色、填到曲面对应位置。

    * 高斯曲率、平均曲率都可以这样画：红色代表值比较高、该处比较弯曲（如眼睛、嘴巴这些地方），平坦的地方值很小。

## 极小曲面与平均曲率流

* **离散平均曲率流的局部迭代**

    * 思想：让顶点 $p$ 朝"平均曲率为零"的方向运动——实际就是朝它一邻域的重心走；一邻域的组合系数建议就用推离散平均曲率的那组权 $w_{ij}=\cot\alpha_{ij}+\cot\beta_{ij}$（边 $p j$ 两侧三角形一对角的余切之和）。

$$p \leftarrow p + \lambda\left(\frac{\sum_{j\in N(p)} w_{ij}\,p_j}{\sum_{j\in N(p)} w_{ij}} - p\right)$$

    * 一般不建议一步直接把点移过去，而是每次只挪一个比例 $\lambda$；挪一次曲面就光滑一点，不断迭代，最后每个点都会无限靠近它一邻域的中心。

* **步长 $\lambda$**

    * > **易错点**：$\lambda$ 千万不要取太大——$\lambda$ 等于 1 时等于一下子把点整个搬到重心上，反而可能导致不收敛；取小一点（0.1～0.2 可以），宁可迭代次数多一点。

* **一轮迭代的构成**

```text
边界点    ：全程不动（相当于铁丝框）
内部点 p  ：找一邻域 N(p)
           → 算加权重心 c = Σ w·p_j / Σ w
           → p ← p + λ·(c − p)
全部内部点各更新一次，才算一轮；回到开头做下一轮
```

* **实现要点**

    * 这种操作一般针对非封闭、带一条边界的曲面：模拟带边界的肥皂膜，边界相当于铁丝弯出来的框，先找到边界点、全程不动，只对里面的曲面做变换。

    * 边界识别判据：内部的边都有两个三角形相邻，而边界边只有 1 个邻接面。

    * > **易错点**：算某个点的更新一定要用老的顶点——把老顶点先存起来，所有点都按老位置算出新位置之后，再统一覆盖回去；边算边覆盖的话，后算的点会用到已经挪动过的邻居，结果就错了。

    * 迭代终止：设固定次数（设成 100、1000 都可以，就能看到曲面最终的样子），或者当迭代中新算出来的点跟老点的误差小于一定程度时停止。

* **收敛性质与局限**

    * 理论上可证明：当迭代次数趋向无穷时，这张曲面趋向一张极小曲面（边界固定时以这条边界为边界）；实际演化中边界不动、内部越来越光滑，边界附近若采样不足会显得欠光滑。

    * 封闭曲面若不固定任何点、每个点都按此操作，整张曲面会收缩到一个点——这是这个迭代算法的固有特性。

    * 局部迭代法的不足：有的地方慢、有的地方快，弄不好还容易产生自交——迭代过程中法向在不断更新，有的顶点收得快、有的收得慢，面片会发生翻转；后面介绍的全局方法能解决这个问题。

## 几何处理库与 Utopia 框架

### 开源几何库

* **CGAL**

    * 最大、最有名的几何库，工业界商业项目用得很多。

* **libigl**

    * 不用半边，用矩阵表达点与点之间的邻接关系；里面很多方法能够很快适配到别的地方、非常容易操作，还封装了 Python 接口——对 Python 更熟、对 C++ 不太熟也能做出很好的工作。

* **MeshLab / OpenMesh 与 PCL**

    * MeshLab、OpenMesh 是非常好用的开源工具；PCL 做点云特别合适。

    * 这些库代码都是开放的，看它的源码能学到很多编程的技巧、算法的技巧。

### Utopia 框架概览

* **框架定位**

    * 课程自研的几何处理框架（中文"无尽框架"），由助教历时大半年、将近一年搭建；比别的框架稍微小一点但很灵活，特别是有一套类似 Unity 游戏引擎的机制。

    * 推荐用它做练习——小巧、上手容易、有人随时答疑；但完全不限定库，用别的库、别的引擎甚至游戏引擎都可以。

* **总体架构**

```text
        编辑器：运行后看到的整套餐窗口
            ↑
    两大块：渲染 ｜ 逻辑（用户代码在逻辑层跑）
            ↑
    基础层：CMake、C++ 标准库、反射库、图形数学库
```

### 基础层

* **CMake 封装**

    * 框架在 CMake 上封装了很多功能，最终效果是写一点点代码就能得到一个内部做了很多事情的完整项目。

    * 核心配置就一段：添加一个项目，然后引入两个库——一个是底层的无头（headless）框架，另一个是几何结构的库；相关源码会自动添加进项目，本地目录下新建头文件或 cpp 文件也能自动加进项目。

* **图形数学库**

    * 设计思路是把数学上的概念写成不同的类：点（Point）、向量（Vector）、法向（Normal）、变换（Transform）；它们虽然都有 $x,y,z$ 三个坐标，但对应的几何概念完全不一样，同一个变换作用到不同对象上通过重载调用不同的函数、结果各不相同。

| 类型 | 它是什么 | 支持的典型操作 |
| :--- | :--- | :--- |
| Point | 空间中的一个位置 | 度量（算两点距离）；仿射变换（点加向量得另一个点） |
| Vector | 一个方向、一段位移 | 加法、数乘、范数、内积（点乘） |
| Normal | 曲面的法向 | 与向量共享大部分操作：内积、范数、度量、加法、数乘 |

    * 库把大量共同的操作组织成"组件"的形式以减少冗余：如向量由五个组件构成，法向由内积、范数、度量、加法、数乘这些公共组件拼出来。

    * > **提示**：读这个数学库的方法，就是看每个对象由哪些组件（功能）组成——确定了一个类由哪些功能组成，就知道它能做哪些操作（可不可以加、可不可以乘、可不可以点乘）。

    * 内积（InnerProduct）组件的接口很全：点乘；求范数平方、距离平方；求距离、范数；求两向量夹角余弦；余切值也可以算（正是余切权要用的东西）；求关于某个方向的投影、取垂直部分。

* **静态反射（static reflection）**

    * C++ 语言没有反射——本来 C++20 计划加入但没加进去，现在标准里只有 type_traits 这类能力比较局限的属性判断；框架用自写的静态反射，把类的名字、有哪些域（成员）、每个域有哪些属性全都保存起来，使得可以遍历、查找。

    * 用途：让数据结构在编辑器里把所有成员显示出来，还能挂额外信息——如给变量 lambdaScale 加属性"最小值 0"（Inspector 里就只能拉到 0，往负的方向拉不动）、加 tooltip 告诉编辑器"这是一个滑条"。

    * 标准流程：需要什么数据就往结构里加一个域 → 重新编译（自动生成一个新的反射注册文件）→ 再运行，编辑器窗口里就能看到新加的域，UI 都已写好、直接在上面调值——省去了过去自己写 UI 再调数据的麻烦。

### 渲染层

* **层次结构**

```text
          标准管线（目前就这一条）
                ↑
      framework：组织渲染对象、并行执行渲染代码
                ↑
      ShaderLib ── Material ── Mesh（较高级的对象）
                ↑
      DirectX：shader、纹理、Buffer
```

    * 越靠下越接近显卡，越靠上越接近"要渲染什么"；最底层图形接口用 DirectX——所以这个框架目前只能在 Windows 上跑，以后可以添加 Vulkan 这样的接口改善跨平台性。

    * 图形接口这一层能看到的对象：shader（写渲染程序用的编程语言）、纹理（纹理就是图片）、Buffer（顶点属性的 buffer、索引的 buffer）。

* **ShaderLib 与 Material**

    * 底层的 shader 用 HLSL 写；ShaderLib 给它添加声明信息——告诉它有哪些纹理（比如 albedo、emission 这些图片）、有哪些变量。

    * Material 把具体的图片确定下来：shader 里只说"需要几张图片"，没说具体是哪几张；类比——ShaderLib 像一个类型，Material 是照着它造的一个实例对象（如"铁锈"材质有漫反射、金属度等四张贴图）。

* **Mesh 与并行框架**

    * Mesh 就是三角网格：顶点数据（位置、法向、纹理坐标）放在 buffer 里，再加一个三角形索引的 buffer（每个三角形由哪些点组成）。

    * DX12 的理念是渲染代码应该并行地去执行，组织并行渲染代码的一个很好架构就是 framework；最后是具体使用哪种管线——目前只有一条标准管线。

### 逻辑层（ECS 架构）

* **实体-组件-系统（Entity-Component-System, ECS）**

    * World（世界）就是一个上下文，里面有很多实体（Entity）——实体相当于一个对象；每个实体的功能部分是组件（Component），组件就是一堆数据、没有逻辑。

    * 组件集合一样的实体是同一种类型，存放时也放在一处——一个实体"是什么类型"由它拥有的组件决定，实体加组件构成一种动态类型系统。

    * System 是逻辑部分，剥离于数据（类）、不和对象耦合：系统是这个世界的一条规则，对所有拥有相应组件的实体都执行同样的操作，读一些组件、写一些组件（如 LocalToWorldSystem 把位置变换与旋转变换相乘，读 Rotation、写 LocalToWorld；运动系统读 Velocity、写 Position）。

    * 把系统注册进 World、再创建实体；之后每次对世界做 update，就执行整个世界的逻辑——所有系统作用到所有带相应组件的实体上。

* **窗口里的对应**

    * Hierarchy 窗口里每一条项目都是一个实体；Inspector 窗口显示它的组件；SystemControl 窗口能看到整个框架有哪些系统、哪些正在运行（勾掉即停）。

    * 动手搭一个可见物体：右键创建实体 → 添加 MeshFilter（网格）和 MeshRenderer（网格渲染器）→ 附上模型、再加材质就能看到 → 调缩放、移相机。

    * 系统一多的关系可以可视化：橙色的框是系统、圈是组件；每个系统读一些组件、写一些组件，读写关系构成顺序依赖——谁先跑谁后跑看这张图就清楚。

* **两个世界**

    * 里面是 game 世界，外面整个是 editor 世界，各有自己的一套系统；系统面板控制的是 game 世界的系统——把那些系统全部禁掉，并不影响 editor 本身。

* **实践代码形态**

    * 数据和逻辑拆开写：一个组件 DenoiseData + 一个系统 DenoiseSystem；DenoiseData 是单例（singleton）——虽然也挂在组件上，但整个世界里只有这么一个组件；系统先获取这个单例拿到数据，再执行逻辑（如创建一个窗口、往上面加几个按钮）。

    * 数据在渲染网格和半边网格之间流动：

```text
渲染用三角网格 → 转成半边网格 → 加噪/去噪（要写的代码只动中间这一格）→ 传回三角网格
```

    * 两头的来回搬运框架都写好了；框架里现成的"加噪声"功能就是对半边网格遍历顶点、对每个顶点位置加随机噪声——照着它的样子写迭代即可；界面上有转半边网格、加噪声（幅度可调，如 20）、传回三角网格、恢复原状等按钮。

    * 可选的着色：把曲率当颜色画上去（演示用"法向当颜色"）；材质方面比较会用到线框（wireframe）和 color 两种——color 不带光照，直接把算出来的值画成颜色正合适。

### 半边网格库

* **模板式用法**

    * 用它的第一步是预声明整个库涉及的四种对象——顶点（Vertex）、边（Edge）、面（三角形/多边形）、半边（HalfEdge），得到一个 traits（特征）配置，接着就可以定义自己的对象。

    * 想给对象加什么属性就加什么：顶点可以有位置、也可以什么都不加（这个网格就只处理拓扑关系，只有连接关系没有位置）；边可以加函数，如"中点"（两端点位置求平均）；面可以加面积属性（先声明面积变量，再写 updateArea 函数去算）。

    * 整个半边结构并不局限于三角形、多边形也支持，所以面类型写的是 polygon；判断一个多边形是不是三角形，用底层提供的 degree 函数看它的顶点数是不是 3。

* **常用接口**

    * 遍历所有顶点是一个循环的事；取某个顶点的位置直接取；`isOnBoundary()` 告诉你在不在边界上；`adjVertices()` 拿到一邻域所有邻接顶点；`degree` 是邻接点个数——把邻接点的位置逐个加起来除以 degree，就得到均值点（一邻域加权平均的核心一步）。

    * 转换函数已写好：`meshToHalfMesh`（渲染用三角网格转半边网格）、`halfMeshToMesh`（转回去，其实就是把位置、法向更新一下）；加噪声怎么写、调颜色怎么调（对应可选着色）都有现成代码可以看。

    * 调试输出用 `spdlog`，可以直接输出到框架的 Log 窗口；这些类之间是继承关系，基类里有哪些操作看源码下面的注释就行。

    * > **易错点**：Point 与 Point 不能相加，硬加编译器直接报错——点加点没有几何意义；有时候不想关心这些区别，就直接用支持所有操作的通用向量类型 Vec。

## 拉普拉斯算子与微分坐标

### 从伞向量到拉普拉斯坐标

* **伞向量（umbrella vector）**

    * > **定义**：顶点 $v$ 与它一邻域平均点 $c$ 之差向量 $\delta$——平均点可以是等权重心，也可以是与几何相关的加权平均。

    * 这个向量衡量顶点偏离其（假设共面的）一邻域平面的远近：像一把伞，伞尖凸得越高向量越长、这个地方就越尖；向量等于零（两点重合）这个地方就很平。

```text
            v
            |\           v : 当前顶点（伞尖）
            | \
         δ  |  \          δ : 从 v 指向邻域平均点 c 的向量
            |   \
   ----------c----------   一邻域点近似张成的平面（伞沿）

   δ 越长，伞越尖；δ = 0 时 v 与 c 重合，此处是平的
```

* **网格上的拉普拉斯**

    * > **定义**：$\delta_i=\sum_{j\in N_1(i)}w_{ij}\,v_j-v_i$，即"一邻域加权平均减自身"——从顶点指向邻域平均点的那支箭头；它刻画顶点一邻域的性质，也叫拉普拉斯坐标（Laplacian coordinates）、微分坐标（differential coordinates）、伞形算子/伞形坐标（不引起歧义时这几个名字指同一个东西）。

    * 权可以取均匀权，也可以取加权；整体反号（写成"自身减邻域平均"）只差一个方向约定，不同文献不同场合看到的是同一个东西。

    * 两种等价写法：只要权是归一的（$\sum_j w_{ij}=1$），把 $v_i$ 挪进求和里，$\sum_{j} w_{ij}(v_j-v_i)$ 与 $\sum_j w_{ij} v_j - v_i$ 就一样——既是"每个邻域点与顶点之差的加权和"，也是"邻域平均减顶点"。

### 连续算子与差分类比

* **连续拉普拉斯算子（Laplacian）**

    * 二元函数的拉普拉斯是一个二阶微分算子（椭圆形）：

$$\Delta f=\frac{\partial^2 f}{\partial x^2}+\frac{\partial^2 f}{\partial y^2}$$

    * 一般多元情形形式一样：对每个变量求二阶偏导再加起来，三元四元只是变量多一点。

    * 几何角度：拉普拉斯是梯度的散度——先求梯度、再求散度"两层"，相当于梯度的平方，$\Delta=\nabla\cdot\nabla=\nabla^2$。

    * 上面是取定了坐标系的表达；对一般的流形甚至非欧几何上的流形，用 $\nabla\cdot\nabla$ 这种形式就可以推广过去。

    * "算子"就是一个操作（operation）的美称：这种运算不定义在普通欧式空间，可以定义在流形空间甚至黎曼空间，为了区别于一般空间中的一个计算而得名——理解成一种运算就行。

* **差分推导**

    * 一阶导数可以用差分近似：后一点减前一点 $\frac{f_{i+1}-f_i}{h}$ 是向前差分，用前一个点 $\frac{f_i-f_{i-1}}{h}$ 是向后差分；二阶导数就是一阶差分的差分：

$$\frac{(f_{i+1}-f_i)-(f_i-f_{i-1})}{h^2}=\frac{f_{i+1}-2f_i+f_{i-1}}{h^2}$$

    * 假设网格等距、间距取 1，系数就是 1、−2、1；二元函数 $z=f(x,y)$ 有 $x$、$y$ 两个方向（两个方向的二阶差分都用 $z$ 来写），每个方向各来一遍再相加：上下左右四个点的和减去中间点的四倍——每个方向中心都是 −2，两个方向合起来是 −4。

```text
                +1
                 |
   +1 ---- (-4) ---- +1
                 |
                +1

  z[i,j+1] + z[i,j-1] + z[i-1,j] + z[i+1,j] - 4·z[i,j]
    = 4·( 四邻域平均 - z[i,j] )
```

    * 类比推广：对一般的、不规整的网格，也用"一邻域的平均减去它自己"作为拉普拉斯算子的近似——这样近似在形式上是合理的。

    * 这个近似是否真正逼近理想的拉普拉斯算子要证极限：当网格顶点无限加密时，这个算子的极限趋向真正的拉普拉斯算子——数学上可以证明，但证明不平凡，需要对顶点分布满足一定条件。

### 平均曲率流定理的背书

* **定理内容**

    * 固定考察点 $v$ 不动，在它周围取一个非常小的封闭区域，边界记 $\gamma$；边界上每个点 $x$ 与中心点连成向量 $x-v$，把这个向量沿 $\gamma$ 关于弧长做线积分，再除以 $\gamma$ 的弧长做归一化。

$$\lim_{|\gamma|\to 0}\frac{1}{|\gamma|}\oint_{x\in\gamma}(x-v)\,\mathrm{d}s=H(v)\,\vec n(v)$$

    * $\gamma$ 可以随便取——不管封闭区域长什么样，把这个封闭区域越缩越小（$\gamma$ 的弧长趋向零，整个过程中 $v$ 始终在里面），这个比值有一个极限：一个常向量，只跟这一点的微分属性相关——方向沿法向，大小就是平均曲率。

* **离散对应**

    * 积分是求和的连续版本：线积分离散成 $\Sigma$；弧长归一变成点的个数归一；"中心点与边界点连成的向量"变成"顶点与一邻域点连成的向量"（正负号只差一个方向约定）——一离散，恰好就是拉普拉斯的形式。

    * 所以"邻域平均减自己"几何意义十足：它正是平均曲率流定理里那一部分的离散。

* **极限性质**

    * 拉普拉斯坐标刻画了顶点局部的平均曲率性质：邻域越来越小时，这个向量的方向逼近法向、长度逼近平均曲率。

    * > **注意**：这是一个极限性质——不是随便取一圈就精确相等，但至少可以作为平均曲率的一个近似。

### 均匀权与余切权

* **两种权**

    * 均匀权是简单算术平均、不考虑局部形状；余切权（cotangent weight, cotan 权）严格从平均曲率流推导出来、考虑了角度和边长的关系。

| 对比项 | 均匀权 | 余切权（cot 权） |
| :--- | :--- | :--- |
| 来源 | 简单算术平均 | 严格从平均曲率流的离散化推导出来 |
| 编码的几何 | 不考虑局部形状 | 考虑了角度和边长的关系 |
| 实际表现 | 收敛性、自交问题往往严重 | 自交轻得多（不是没有），收敛均匀，几何不随顶点疏密变形 |

* **收敛均匀性**

    * 均匀权下：顶点稀疏的那端拉普拉斯向量长、收缩得非常快；顶点密的那端（邻域边短）向量短、收得慢——一边收得厉害一边收得很慢，几何就跟着顶点疏密变形（顶点密的兔子耳朵处，尖角要经过很多次迭代才会消失）。

    * 换成余切权后收敛性就一致了：不管网格密还是稀，几何不会跟着变得太多。

    * > **提示**：以后做后面的应用、后面的编程，所有涉及拉普拉斯的地方，权全部取成余切权——它是严格从平均曲率流推导出来的。

## 拉普拉斯光滑与去噪

* **拉普拉斯光滑（Laplacian smooth）**

    * > **定义**：给拉普拉斯加一个步长 $\lambda$、对顶点做变换的更新操作：

$$v_i'=v_i+\lambda\,\delta_i$$

    * 顶点从旧位置挪到新位置，伞就没有那么尖了；有的书翻译成"光顺"、有的翻译成"平滑"，一个意思。

    * 这个向量也是几何细节的度量：向量越长越尖锐、越短越平滑，等于零（或很小）的地方非常光滑、没有细节——细节就是那些尖锐的地方所呈现的性质。

    * 类比曲面造型里的割角：顶点挪下来相当于用周围那些面片把这个角割掉；迭代五次就相当于割了五次角；边界定死不让动、做无穷多次，最后就变成一个以边界为边界的极小曲面。

* **滤波与去噪视角**

    * 网格顶点由于采样、测量仪器或者计算，会产生误差、带来噪声；去噪就是用周围点的平均把它平均掉、抹掉——这也是一种滤波（filter），滤波就是卷积。

    * 跟细分曲面的割角有点像，但比较特殊：一邻域的点都不动，只是把中间这个角用它周围的东西割掉，割完就不那么尖了——本质上是一种滤波算子、滤波操作。

    * 平时去噪一般不会 apply 无穷多次：稍微 apply 几次、把表面的细节和噪声干掉就可以——无穷次操作下去模型可能就缩成一个点了。

* **过光滑（over-smoothing）**

    * 去得比较多的时候太光滑了、丢掉很多细节（如兔子光滑到眼珠子都没了），中间才有一个程度细节保留得挺好——跟拟合里的过拟合（overfitting）一个道理。

    * "度"有两处：$\lambda$ 怎么取——太大了很容易造成过光滑；迭代次数怎么取——是做一千次还是做下去（永远做下去一定缩成一个点）；具体怎么定后面展开。

* **平均曲率流形式**

    * 拉普拉斯算子刻画了这个点局部的平均曲率；如果有办法知道这个点的平均曲率，可以直接写成平均曲率乘法向的形式：

$$\delta_i=H_i\,\vec n_i,\qquad v_i'=v_i+\lambda\,H_i\,\vec n_i$$

    * 法向 $\vec n$ 如果有更准确的信息，也可以替换进来；用这种形式做迭代就叫平均曲率流（mean curvature flow）。

* **余切权的完整形式**

    * 边 $(i,j)$ 在相邻两个三角形里各自对着的角为 $\alpha_{ij}$、$\beta_{ij}$，这条边的权是两个角的余切之和（写成平均的形式就是再除以二）；面积归一拿到求和外面：

$$\delta_i=\frac{1}{4A_i}\sum_{j\in N_1(i)}\bigl(\cot\alpha_{ij}+\cot\beta_{ij}\bigr)(v_j-v_i)$$

    * 其中 $A_i$ 是顶点的邻域面积；以后做一些几何相关的权，尽量用这一个。

## 全局拉普拉斯方程组

* **全局思路**

    * 局部迭代是一点一点地更新、有快慢不均和自交的毛病；全局做法把整个问题写成一组方程、一次解出来——把所有顶点 $v_1, v_2, \ldots, v_n$ 全部当作未知数，每个顶点贡献一个方程，网格有多少个顶点就有多少个方程。

    * 极小曲面长什么样：每个点都恰好落在它一邻域的中心上，也就是每个点的拉普拉斯向量（微分坐标）都等于零——不是通过局部操作一步步逼近 $\delta=0$，而是直接要求满足方程。

* **方程与稀疏矩阵**

    * 顶点 $v_i$ 对应的方程：

$$\delta_i = v_i - \sum_{j \in N(i)} \omega_{ij}\, v_j$$

    * 摆进矩阵就是一行：这一行本来要和所有顶点相乘，但真正非零的只有 $v_i$ 自己的位置（系数 1）和一环邻居的位置（系数 $-\omega_{ij}$），其余全是零。

```text
列 ->       v1    v2   ...  vi-1    vi   vi+1  ...  vn
行i ->     [ 0     0   ...  -wij     1    -wij  ...   0 ]

这一行共有 n 个元素（n 是顶点总数，一万甚至上百万）；
一环 6 个邻居 → 这一行只有 7 个非零；一环 5 个 → 6 个非零
```

    * 网格上多数顶点的一环就是六个邻居，所以这一行上万个元素里往往只有七个非零；对每个顶点都构造这样一行，就得到 $n \times n$ 的矩阵 $L$——一个非常稀疏的矩阵，规模越大稀疏性越明显。

    * 右边一般放的并不是零，而是这一点的目标拉普拉斯向量 $\delta_i$（求极小曲面时它就是 $0$）；边界上的点如果不动有两种处理：把含边界顶点的项移到方程右边当已知量，或者干脆把它们一起写进矩阵、只是不让它们动。

* **求解形态**

    * 对 $x$、$y$、$z$ 三个分量用的 $L$ 是同一个矩阵：$Lv_x=\delta_x$、$Lv_y=\delta_y$、$Lv_z=\delta_z$；写成向量形式 $Lv=\delta$——本质上是一个向量方程，实施时把每一步运算对三个分量各做一遍、解三个线性方程组而已。

|  | 局部迭代 | 全局方程组 |
| :--- | :--- | :--- |
| 怎么动点 | 每个点朝自己一邻域的中心挪一步，反复迭代 | 所有顶点作为未知数，一次解出 |
| $\delta = 0$ 的地位 | 一步步逼近的极限 | 直接写进方程组 |
| 代价 | 快慢不均、容易自交 | 要解一个大型稀疏方程组 |

* **微分坐标能存、能变、能还原**

    * 如果每个点的微分坐标 $\delta$ 都知道、表达邻居关系的 $L$ 也记下来了，那解一遍方程组就能把整个网格还原出来——$\delta$ 能"存"，存下来就等于记住了网格的局部形状。

    * 也能"变"：把每个 $\delta$ 整体缩短 10% 变成 $\delta'=0.9\delta$，然后用不变的 $L$ 和 $\delta'$ 再解一次方程，就重建出一个新网格——这正是局部迭代里"把每个 $\delta$ 缩短 10%、更新顶点"的全局版：局部法是每个点一步步做，这里是全体 $\delta$ 一起缩短、一次求解，直接得到结果。

    * 想求极小曲面就更干脆：令 $\delta=0$、解 $Lv=0$，解出来的 $v$ 就是极小曲面。

* **秩与约束**

    * $L$ 不是满秩的：网格是一个连通块时秩是 $n-1$；分成互不相连的 $c$ 块时秩是 $n-c$——基本上按一个连通网格来考虑。

    * 非满秩，解就不唯一——所以一定要加条件：约束住一个点，或者把边界点约束住，这个方程就可解；约束加多了以后可能就没有唯一解了，那就要用最小二乘来解。

* **稀疏方程组求解**

    * > **提示**：别自己写求解器——$100 \times 100$ 的方程组自己写也能搞定，但一万乘一万、十万乘十万甚至百万级别自己写的效率就不一定行了；这些数学库是几代数值计算研究者打磨出来的，方法好、数值表现也稳定；除非以后专门做高效求解、优化算法方向，否则直接调库。

    * 三对角方程组（如求三次样条时构造的三弯矩方程组）用追赶法求解，但三对角是非常特殊的结构才能用追赶法；这里的 $L$ 特殊在稀疏——计算数学里求解稀疏方程组有很成熟、很高效的方法，比如各种迭代法。

    * 库的选择：早年有 Intel 的 MKL；推荐 Eigen——名字取自 eigenvalue（特征值）、eigenvector（特征向量）。

    * 存储问题：最原始的存法是存 $n^2$ 个元素——$n$ 是一万那可是一亿个，根本吃不消；所以要用稀疏矩阵的存法：按索引只存非零元（数据结构里的十字链表——行有一套指针链表、列也有一套指针链表）；去看懂 Eigen 里稀疏矩阵是怎么存的，学会把邻接系数变成它的数据结构、扔给它求解、拿解出来的顶点坐标更新。

    * > **注意**：调稀疏矩阵相关的库，一定先看清它是以行为主（row-major）还是以列为主（column-major）——搞错了，求出来的结果就是不对的。

    * > **提示**：拉普拉斯方程组是后面很多几何处理的基础，这次稀疏求解值得亲手完整体验一遍。

## 网格参数化

* **参数化（Parameterization / Flattening）**

    * > **定义**：把三维空间中的一张二维曲面变成二维域上的一张图——给曲面上的每个点找到它在平面上的对应；点有了对应，三角形自然也有了对应（空间三角形 $p_1p_2p_3$ 对应平面三角形 $u_1u_2u_3$）。

    * 曲面本质上是参数域到空间的映射 $R^2 \to R^3$：$f(u,v) = \bigl(x(u,v),\; y(u,v),\; z(u,v)\bigr)$；参数化就是把曲面这个本真维度显式拍平，本质上是一种降维——很多三维曲面之间的关系都可以拿到参数空间里去处理。

    * 特殊情况很平凡：曲面恰好是高度场（height field）时，往 $xy$ 平面一投影就变成二维的。

    * 直观形象：在牛身上中间割一条缝，把这张"牛皮"摊开来——和把一张真的牛皮铺开是一个意思。

    * 里面有一堆性质值得讨论：三角形不能翻转（一翻转顶点就搅在一块儿）、扭曲要控制得很好、边界不要自交——属于后面的专门内容。

* **最直接的用场：贴纹理**

    * 纹理（texture）是一张事先存好的图片；曲面上的顶点通过它的 UV 坐标对应到图片上的一个位置，那个位置的颜色就被"引"到曲面上——三维曲面上看到的颜色就是这样通过参数化从纹理上取下来的。

    * 很多软件里这个操作叫 UV 展开；对美工来说，做 UV 是要花很多很多时间的工作。

* **地球的教训：展开必有扭曲**

    * 只有可展曲面才能做到每个点展开都没有扭曲；地球应该是不可展的，一般曲面展开一定有扭曲——有的地方挤压得厉害、有的地方挤压得少一些。

    * 规律：越靠近赤道扭曲越小（在赤道上摆一个圆，展开后大小形状基本保持）；越靠近南北极扭曲越大（球面上同样大小的一个圆，摆在哪里都这么大，展开后高纬度的那个被拉成了椭圆）。

    * 所以地图上的度量事实上是不可靠的，必须考虑扭曲之后的度量；北京到纽约在地图上拉一条线量不准——飞机走的不是地图上那条线，而是球面上最短的路径（大圆航线），从北冰洋那边绕过去再飞回来，地图上那条线比它长多了。

    * 切缝的位置也大有讲究：传统地图沿格林威治 0 度经线纵向切开，在上面量北京到纽约明显偏大、能差出将近一半；沿北纬一条纬线去切、把中国放到图中心的图，量出来就精确多了——军事上用的就是这种图。

* **最简单的线性参数化**

    * 做法：把开网格的一圈空间边界顶点按弧长比例映射到一个凸边框上（矩形、方形、圆都行，顶点顺序保持不变）——这段边界的弧长占整圈的比例是多少，就在矩形边框上摆到同样的比例；边界顶点是已知量、出现在方程右边的 $b$ 里；内部点是未知数 $x$、每点一个 $\delta=0$ 的方程进矩阵 $L$；解稀疏方程组 $Lx=b$。

```text
  空间中一圈边界顶点（封闭曲线）
        │ 按弧长比例映射，顶点顺序不变
        ▼
  平面凸边框上的已知点（矩形 / 方形 / 圆）→ 进方程右端 b
  内部顶点：每点一个方程 δ = 0 → 进矩阵 L，作为未知数 x
        ▼
     解稀疏方程组 L x = b
        ▼
  所有顶点落在平面上：二维嵌入 = 参数化
```

    * 因为约束边框是平面上的凸形状，解出来的所有点保证全部落在平面上——这就得到曲面在二维中的一个嵌入，也就是一种参数化；方程组跟极小曲面全局解法的那一套一模一样，做完极小曲面、把边界再处理一下就出来了。

    * Tutte（1963）证明了一个非常强的结论：只要边界位于一个凸多边形上（矩形、方形、圆都可以），方程 $Lx=b$ 的解保证内部的三角形一定不会翻转——原来右手系的顶点顺序，映过去还是右手系，不会出现任何一个左手系的三角形；这就同时保证了：如果网格是个流形，映射过来之后还是一个很好的流形（flip-free，无翻转）。

* **翻转（flip）**

    * flip 的根源：映射在这些点处的局部雅可比行列式（Jacobian）小于零。

    * 危害：一旦发生 flip，就有不同的顶点、不同的三角形被映射到同一片区域上；这时候往上面贴纹理，好几个三角形对应同一片纹理，那里就有鬼影、纹理就不连续了。

    * > **易错点**：判断参数化好不好，第一件事是查翻转——有翻转的参数化连"正确"都谈不上；无翻转但扭曲大，只是"不够好"，还有得救。

* **扭曲的表现与权**

    * 用格点纹理能把扭曲现形：格子能把拉伸压缩暴露出来——哪一片格子大、哪一片格子小，一眼看出哪一片被拉伸、哪一片被压缩了（换不同的纹理图案现象相同）。

    * 开口很小的地方顶点往往又密又多，参数化的时候全挤在一块儿——一个很小的区域里塞了好几百甚至上千个点，数值上一点点误差就可能出问题；空间里看起来大小差不多的三角形面片，摊到平面上这边的变得非常小、那边的还是那么大——这里扭曲极大，贴上纹理很不均匀。

    * 权的建议：用 cotan 权（cotangent weight）结果相对来说会好一点；用均匀权的话展开一般不好、歪歪扭扭——不用把不同的权都实现，用 cotan 就行。

    * 这个方法简单而且有效——"有效"就是不会发生翻转；怎么把扭曲均匀化是将来的事情，先接受"比较好的参数化、没有翻转、扭曲大了一点"这个结果。

* **图集与装箱**

    * 一整片区域直接摊容易出现一大堆点挤在一小块地方、扭曲大得不好看；所以常见做法是把一个大模型人工割成若干块（如头一块、身体一块），每一块单独参数化，然后把各块 packing（装箱）装进一个矩形纹理区域里，在上面画纹理、画完再映射回曲面。

    * 拼装出来的这张图叫纹理图集（atlas），展开出来的一片行话叫一个 chart；美工有时候也直接在这张 UV 图上画颜色。

    * 代价是空间浪费：比如纹理是 $1024 \times 1024$ 的，图上留白越多浪费越多——白的地方对曲面的纹理没有任何信息贡献，却照样占存储；怎么 packing 得更紧凑本身就是一个研究问题。

## 带约束的全局光滑

* **动机**

    * 全局光滑解 $Lv=\delta'$（如让每个 $\delta$ 缩短 10%）一次方程就得到一张光滑的网格，但这样光滑下去网格很容易发生坍塌、收缩；想钉住一些关键点（也叫特征点）让它们不动、别的地方照常收缩，就得往方程组里加约束。

* **硬约束与软约束**

    * 硬约束（hard constraint）：这个约束一定要满足，就像优化里的 $\min f(x)\ \text{s.t.}\ g(x)=0$——约束必须严格成立。

    * 软约束（soft constraint）：这个约束可以放松一点，写成 $\min f(x) + \lambda\,g(x)^2$——变成无约束优化，把约束变成了目标函数的一部分；希望整个值尽量小，$g(x)$ 就不能太大；$\lambda$ 越大 $g$ 就被压得越小、约束满足得越好，$\lambda$ 趋于无穷时软约束退化成硬约束。

* **加约束的方式**

    * 为方便加约束，把 $x$、$y$、$z$ 三个分量并排写在一起变成一个大矩阵——因为很多约束是对 $xyz$ 同时要满足的。

    * > **易错点**：想让某个点固定不动，最直接的想法是把它从未知数里抠掉变成已知量——能解、没问题，但求解这个方程组实际上是把误差在整个网格上平均分配，抠掉一个点，那个地方容易出现怪怪的尖点；所以一般不这么干，而是把它变成软约束，在矩阵下面再加几行约束（$x_k$ 等于多少、$y_k$ 等于多少、$z_k$ 等于多少）。

    * 约束还不限于顶点：三角形面心（face 中心）是三个顶点的线性组合而这三个顶点都是未知数，所以"某个三角形的中心保持不变"是一条线性方程、照样可以加进来；"边的中点保持不变"类似——只要约束对 $xyz$ 是线性的，都可以作为一行加到矩阵里。

* **最小二乘与法方程（normal equation）**

    * 带约束的拉普拉斯光滑变成：希望拉普拉斯尽量小（网格光滑），同时希望被约束的点尽量靠近指定目标位置，中间放一个系数 $\lambda$：

$$\min\;\|Lv\|^2 + \lambda\,\|Cv - d\|^2$$

    * $n$ 行拉普拉斯方程加 $m$ 行约束方程按行拼起来，矩阵变成狭长的非方阵 $A v\approx b$——非方阵没有逆，转而在最小二乘的意义下解：两边左乘 $A^T$ 得法方程 $A^TAv=A^Tb$，解 $v=(A^TA)^{-1}A^Tb$（与最小二乘拟合里的法方程同一个道理）。

```text
  n 行拉普拉斯方程（L v = δ）
  m 行约束方程（C v = d：顶点位置、面心、边中点……）
        │ 按行拼起来
        ▼
  狭长的非方阵 A v ≈ b
        │ 最小二乘
        ▼
  法方程：A^T A v = A^T b   →   v = (A^T A)^(-1) A^T b
```

    * $A^TA$ 总归是对称的半正定矩阵；只要 $A$ 列满秩，它就是正定的、一定有逆。

    * 解法方程的技巧：直接求逆比较烦；如果 $A$ 不变、只是坐标在变，那 $A^TA$ 就是固定的——这时候用分解技术，分解一次、之后每次求解都重复使用；Eigen 库里有现成的分解，不用自己实现。

* **效果**

    * 约束一些点不动相当于把它们钉牢了，曲面就不会收缩得很厉害；参数取值不一样、光滑的程度也不一样——越来越光滑就是 LOD（Level of Detail，细节层次）的概念。

## 网格编辑问题

* **交互设定**

    * 用户往往只编辑一个点（如把龙嘴上这一点往上移一点）；算法要做的是：根据这个点从这里移到这里，求出其他所有点的新坐标——更新完之后的效果有点像把龙的嘴巴掰开。

* **本质：保持拉普拉斯**

    * 每个点变成哪里由用户交互决定；能做的是尽量保持各点的拉普拉斯——拉普拉斯度量的是每个点的局部邻域、局部细节，保住了它就保住了曲面的性质。

    * 做法：编辑区域这一圈之外都不动，这一圈里面的顶点都作为变量，尽量保持原来的拉普拉斯向量。

* **旋转细节**

    * 拖动的点从这里移到那里，中间发生了一个小小的旋转，所以拉普拉斯向量也应该跟着做一个小的变换（旋转）才合理；死守原来的拉普拉斯不变，效果可能就不那么好——要点是每个点的局部拉普拉斯保持同样的长度、但方向允许发生旋转，具体处理在网格编辑中展开。
