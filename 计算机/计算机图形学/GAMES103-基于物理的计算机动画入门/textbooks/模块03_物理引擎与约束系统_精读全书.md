上上周还有上周，我们主要讲的是刚体，刚体的模拟这一块基本上告一段落了。其实围绕刚体还有很多延伸出来的话题，比如 articulated body，就是类似人体骨骼动画这样的东西。它跟约束相关，所以我们后面会专门有一节课来讲约束，那个话题暂时先放着。

布料这个东西，跟头发的模拟其实是有一定联系的。你可以把布料（cloth）想象成一个二维的面在三维中展开的状态；那头发是什么？头发是一维的一条线在三维中展开的状态。所以它们之间是有关系的。不过头发模拟有自己的特点：它有的时候要考虑自身的一些旋转，会用类似螺旋线的模型，相对来说就比较特殊。所以我们这里不往下展开头发，主要讨论比较通用的 cloth 怎么去 model、怎么去 simulate。

布料模拟相当于是我的一个老本行，我在这方面做了蛮久的工作。我打算把它分成三节课、三个礼拜来讲：

- **今天**：物理仿真模拟——怎么根据能量、根据力的模型，推导出衣服模拟的方式；
- **下周**：约束。大家可能经常听说过、游戏里用了很多的 PBD，下周我们会讨论那个东西；也会讨论 projective dynamics，就是基于 PBD 再延伸的、跟物理模拟相结合的一种方式；还会专门讨论一种用来处理约束的方法，叫做 constraints dynamics。基本上下周就是围绕着各种各样的约束，讨论怎么让约束跟模拟相结合；
- **最后一周**：碰撞。为什么在这个时刻才讨论碰撞？因为衣服的碰撞、布料的碰撞是最难的。你如果能把 cloth 的碰撞处理好，实际上做其他模拟的碰撞相对来说都会容易很多。所以到时候我们重点讲 cloth 是怎么处理碰撞的，你会发现这些类似的方法都可以用在其他的碰撞处理上。

模拟本身放在头两周，碰撞放到最后专门讨论。

### 一根理想弹簧：能量与力

先从弹簧讲起。一个理想的弹簧，初中物理、高中物理就学过：它满足胡克定律。胡克定律说了个什么事情？本质上就是：弹簧的力试图把弹簧恢复到原长，同时这个力跟拉伸的长度成正比。

只考虑一个很简单的一维情况：一根弹簧拴在原点上，当前的位置是 $x$，那弹簧的长度就是 $x$；设弹簧的原长是 $l$。那么弹簧的能量就是

$$E = \frac{1}{2}k(x-l)^2$$

$k$ 是弹簧的弹性系数，$x-l$ 就是形变量，也就是弹簧被拉了多少。平方一下、乘上弹性系数、除以二，就是能量。

> **定义**：力是能量对位置的导数取负，$F = -\dfrac{\mathrm{d}E}{\mathrm{d}x}$。

那力从哪里来？对 $x$ 求导，二跟二抵消掉，就得到

$$F = -k(x-l)$$

这其实就是我们中学学物理时直接给的那个公式。你会发现，力和能量之间就是一个简单的导数关系，前面加个负号而已。
### 把弹簧接在两个顶点之间

一维的情况以此类推，可以拓展到二维、三维。这个我们之前讨论过——第二节课讲数学求导的时候，就是拿这个弹簧举的例子，这里简单给大家回顾一下。

一根弹簧连接两个点 $i$ 和 $j$，原长是 $l$。能量还是二分之 $k$ 乘以拉伸量的平方：

$$E = \frac{1}{2}k\left(\lVert x_i - x_j \rVert - l\right)^2$$

拉伸量是什么？就是弹簧当前的长度减去它的原长。同样的，力就是能量对点的位置求导。这里有两个顶点、$i$ 点和 $j$ 点，也就意味着分别有两个力，前面各加一个负号。之前我们推过公式，这里就不重复了，反正就是：负的 $k$ 乘以形变量，再乘以方向、normalize 一下：

$$F_i = -k\left(\lVert x_i - x_j \rVert - l\right)\frac{x_i - x_j}{\lVert x_i - x_j \rVert}$$

然后牛顿说了：如果你把这两个顶点连同弹簧看成一个系统，总的力应该等于零——这是作用力跟反作用力。所以 $F_j = -F_i$，这一点从公式上也能直接看到：两个力刚好是相反的。推导过程这里不细展开，如果不太记得第二节课的内容、或者没上第二节课，可以回到第二节课最后的 PPT 上，把推导过程再看一遍。简单地说：有了能量之后，就可以得到两个相对应的力，分别作用在 $i$ 和 $j$ 上。
### 多根弹簧：能量与力都可以叠加

有了单根弹簧的模型，就可以构造更复杂一点的模型——多根弹簧。多根弹簧怎么办？根据物理里学过的知识，能量和力是可以叠加的。

假如顶点 $i$ 连接着另外四个顶点，四根弹簧把它们连接起来，那么相对应地就有四个能量 $e_0$、$e_1$、$e_2$、$e_3$，把它们全部加在一起就是总能量；总能量对位置求导，写出来带一个 transpose——这就是梯度的定义，之前讨论过：

$$E = e_0 + e_1 + e_2 + e_3, \qquad F(x) = -\left(\frac{\partial E}{\partial x}\right)^{T}$$

力也一样：把所有的力加合在一起，总的合力就是作用在这点上的力。这就是根据简单的物理加和，把能量和力加在一起。
### 结构化网格：横竖、对角与弯曲弹簧

实际模拟中，怎么去构造这个网络？有不同的方式。一种我们之前也讨论过，是结构化的方式：假设这块面料是由方方正正的格子构成的，用一个比较正规的网格来描述它，每一个交叉点就是一个顶点、一个节点。在这个网格上：

- **横竖弹簧**：横向的弹簧跟纵向的弹簧，描述面料在横向、纵向上的形变；
- **对角弹簧**：对角方向上的弹簧，用来防止面料在斜 45 度的方向上被拉伸。而且两个方向都要：斜 45 度一个、斜 135 度一个；
- **弯曲弹簧**（bending spring）：面料是有可能翻折的。如果没有这根弹簧，面料可以沿着某一条线自由地翻折。那怎么阻止它沿着这条线自由弯折？我可以在跨过这条线的方向上再加一根弹簧。也就是说，对于每一个点，跨过相邻的另一个点，跟另一侧的那个点加一根弹簧——这个就叫做弯曲弹簧。它主要的目的是防止面料很自由地沿着某一个方向做弯曲。

实际中，我个人有的时候比较喜欢用稍微简化一点的版本。简化的点在哪里？简化对角上的弹簧：不需要每一个小格子都加两根对角弹簧，可以形成一种格子错开的方式，每个格子上只选斜 45 度或者斜 135 度其中一项。

```text
每个格子都放两根对角            错开：每个格子只选一根
\ \ \                          \ / \
\ \ \                          / \ /
\ \ \                          \ / \
```

读图：左边每格两根对角线，弹簧多、方向统一；右边一格 45 度、一格 135 度地错开。

为什么不一律都用斜 45 度、或者一律都用斜 135 度？因为如果一直沿某一个方向，容易让你的模拟产生偏向性：比如一直沿 45 度，那它在 45 度方向上的抵抗就会比较强，而 135 度可能就没有什么抵抗。错开来的格子的好处在于 45 度跟 135 度都能兼顾——有的格子是 135 度，有的格子是 45 度。同时它还让你的弹簧数量减少。所以我个人比较喜欢这种错开来的方式。
### 不规则版型：三角网格上的弹簧

结构化是一种方式，还有一种也比较常见：很多设计中，我们做出来的 mesh 可能不是一个很规则的面料网格。比如设计衣服的时候，很多版型出来的形状既不是一个规则的方块、也不是一个长方形，很多时候是不规则的形状。这时候就要用三角网格，而且往往是一种非结构化的三角网格来描述它——所谓非结构化，就是它很乱、没有什么固定的结构，由很多三角形把这些点连接在一起。

给了这么一个三角形网格，怎么拿来做弹簧系统的模拟？一个简单的思路：把每条边都认为是一根弹簧。每条边产生一根弹簧，把这些边全都用弹簧连接起来，就构造出一个弹簧系统了。

当然还不够。为什么？因为这里其实还是没有对弯曲的抵抗。那怎么抵抗弯曲？思路跟刚才很像：对每一条内部的边，构造一根这样的弹簧来抵抗弯曲。这根弹簧连接这条内部边所对的两个顶点。把它俩连接起来之后，就意味着面料在这个方向上——这条内部边的方向上——产生抵抗了：它想弯曲的话，这个方向上就有个东西拉着它。这样面料相对来说就有了弯曲的抵抗。

这种弯曲弹簧会很多。为什么？因为内部边很多：对于每一条内部边，都需要加这么一根弹簧，最终把整个弹簧系统的弹簧全都构造出来。
### 从网格数据里抠出边来

有同学就会问了：给我一个三角形网格，我怎么把这些边从中抠出来？又怎么利用这些边去构造弹簧系统？这个是有一套计算方式的，我简单介绍一下几何上是怎么处理的。

先看三角网格在程序里是怎么表示的。拿一个非常简单的例子：三个三角形，连接了五个顶点 $x_0$ 到 $x_4$。一般来说，最原始的输入由两个列表（数组）构成：

- 第一个数组存的是**顶点的位置**。现在有五个顶点，每一个顶点是一个 3D 向量，所以顶点列表里存的就是五个 3D 向量；
- 第二个数组存的是**每个三角形的顶点索引**。现在有三个三角形：第一个由 1、2、3 这三个顶点构成，那我在列表里存的就是序号 1、2、3；蓝颜色的三角形由 0、1、3 构成，我就存 0、1、3；橙颜色的三角形由 0、3、4 构成，就存 0、3、4。靠这些序号去顶点列表里查，就知道对应的 3D 位置是什么了。

别人给我们三角网格数据的时候，最原始给的就是这个东西。

```text
          2
         / \
        /   \
       1-----3
        \   / \
         \ /   \
          0-----4

顶点列表   V = [x0, x1, x2, x3, x4]            （每个 xk 是一个 3D 位置）
三角形列表 F = [(1,2,3), (0,1,3), (0,3,4)]     （依次是绿、蓝、橙三个三角形）
```

读图：(1,2,3) 与 (0,1,3) 共享边 1–3，(0,1,3) 与 (0,3,4) 共享边 0–3，这两条被共享的边就是内部边。

关键问题来了：怎么从这两个数据里得到所有边的信息？为了构造拉伸弹簧，我需要有边的信息，有了边就能用边去描述弹簧；但边还不够，我还需要内部边的信息——做弯曲的时候前面讲了，要把内部边所对的两个顶点连接起来。

有一个简单的想法：每个三角形有三条相邻的边，那是不是直接把这三条边拿出来，就可以当三根弹簧了？**不行**。为什么？因为对内部边而言，它是有重复的。比如 0–3 这条边是一条内部边，它既相邻了 1 号三角形、又相邻了 2 号三角形。这就意味着，如果简单地把每个三角形的三条边全都拿出来，等于在内部边上装了两根弹簧。我不希望这样——我希望内部边上还是只有一根弹簧。所以需要做一个几何上的处理。

先构造一个 triple，就是三个数字：前两个数是每条边的顶点信息，最后一个数是三角形编号。比如 0 号三角形 (1,2,3)，它的三条边分别是 1–2、2–3、3–1，那我就针对 0 号三角形分别构造三个 triple。你可以把 triple 认为是一条原始的边：每个三角形都有三条原始边，三个三角形最终形成九个原始的 triple。

| 三角形 | 顶点索引 | 生成的三个 triple |
| :--- | :--- | :--- |
| 0 号（绿） | 1, 2, 3 | (1, 2, 0)、(2, 3, 0)、(1, 3, 0) |
| 1 号（蓝） | 0, 1, 3 | (0, 1, 1)、(1, 3, 1)、(0, 3, 1) |
| 2 号（橙） | 0, 3, 4 | (0, 3, 2)、(3, 4, 2)、(0, 4, 2) |

有了这九个 triple 之后，对它们做一个排序。为什么要排序？原因很简单：如果一条边是内部边，它的两个顶点会在这个结构里重复出现两次；对它进行排序之后，这两次出现就会落到相邻的位置上。比如 0–3 这条边，原来出现在两处不相邻的位置，排序之后就相邻了；1–3 这条边同理，原来不相邻，排完序就挨着了。

相邻的好处在于：我对这些原始边从头到尾检查一次，就可以把重复的边剔除掉——因为它永远是相邻的，我只要往前、往后看一下是不是出现同样的顶点对，如果顶点对一模一样，就剔除掉一个。这样整个边列表就构造出来了，剩下的都是没有重复的边，直接拿来当弹簧用，不用担心同样的位置产生两根弹簧。

```text
排序后（按顶点对）：
(0,1,1) (0,3,1) (0,3,2) (0,4,2) (1,2,0) (1,3,0) (1,3,1) (2,3,0) (3,4,2)
          ---------------                 ---------------
          0-3 出现两次，已相邻             1-3 出现两次，已相邻

剔除重复后剩下的边（直接当拉伸弹簧）：
(0,1) (0,3) (0,4) (1,2) (1,3) (2,3) (3,4)
```

读图：内部边的顶点对在排序后必然相邻，扫一遍剔掉一份即可；留下的七条边就是拉伸弹簧。

那弯曲弹簧怎么得到？要弯曲弹簧，实际上是要找到内部边。怎么知道哪些是内部边？很简单——刚才剔除的时候我们检查了重复，那么重复的边实际上就是内部边。这里内部边就是 0–3 跟 1–3。

有了内部边之后，就分别通过它的三角形顶点再做一次检查。比如我知道 0–3 相邻的是 1 号三角形跟 2 号三角形，那我就去查这两个三角形中对着 0–3 的顶点，分别是 1 跟 4——那我就把 1 跟 4 连接起来，这就是一根弯曲弹簧。

当然，你也可以存三角形的信息：比如存「1 号三角形和 2 号三角形相邻」「1 号三角形和 0 号三角形相邻」。这也可以，取决于你是想直接存弯曲弹簧的两个顶点，还是想存三角形的相邻关系，两种都行。

### 显式积分的模拟流程

有了这些边的信息，我就可以搭一个模拟系统了。怎么模拟？首先是一个简单的粒子系统：对每个顶点 $i$，计算它受到的力；有了力之后，除以质量、乘以 $\Delta t$、加上速度，得到新的速度；有了新的速度，乘以 $\Delta t$、加上位置，得到新的位置。

$$v_{\text{new}} = v + \frac{F}{m}\Delta t, \qquad x_{\text{new}} = x + v_{\text{new}}\,\Delta t$$

这是一个非常标准的粒子系统，大家可能之前见过，跟我们做刚体的模拟其实很像，只不过比刚体还要简单：这里没有任何旋转，每个点就是一个单纯的位置信息。

对弹簧系统而言，我只需要把弹簧插入到这个力的计算过程中就够了——力里面多一类，弹簧力。那怎么算力？对每一根弹簧——这里其实应该叫 spring，不应该叫 edge——它都连接着两个顶点。我用一个二维数组来定义：第一个 index 是弹簧自己的编号，后面两个 index 分别是它连接的两个顶点。比如第一根弹簧连接 0 跟 1，第二根连接 0 跟 3，第三根连接 0 跟 4，就是这么一个定义关系。

然后还有另一个列表，存的是每根弹簧的原始长度。这个东西一般来说通过预计算得到：事先把所有的边、所有的弹簧都过一遍，假设初始位置没有形变、就是原始位置，把初始长度保存下来。之后通过索引就能访问到每根弹簧的原始长度了。

算力的流程是这样的：

```text
# 第一遍：先把所有弹簧的力算出来，集中存进力的数组
for 每根弹簧 e:
    i, j = spring_vertex[e]        # 这根弹簧连接的两个顶点
    l0    = rest_length[e]         # 预计算好的原始长度
    f     = -k * (||x[i] - x[j]|| - l0) * normalize(x[i] - x[j])
    force[i] += f                  # 力分别加到 i 和 j 上
    force[j] -= f                  # 作用力与反作用力：方向相反

# 第二遍：再用算好的力更新每一个顶点
for 每个顶点 i:
    v[i] += (force[i] / m) * dt
    x[i] += v[i] * dt
```

这里我得多说一句：上面这两个循环如果直接连在一起写，其实有点容易误导。更合理的写法是分成前后两个部分：第一部分先把所有的力单独算出来，保存在一个力的数组里；算完这个力数组之后，再把所有的顶点过一遍、做积分。回头我会把 PPT 稍微改一下。

这基本上就是一个简单的显式积分（explicit integration）做弹簧系统模拟的方式，跟我们前面刚体那部分很像，无非就是多了一个力——弹簧力。
### 数值不稳定：overshooting

显式积分有一个很严重的问题，叫做 numerical instability——数值上不稳定。

什么叫数值上不稳定？给大家这么一个情况：就一根弹簧，最简单的一维情况，不要去想很复杂的情况。弹簧形变了，我根据这个力更新它的速度、更新它的位置。大家想一想：如果弹性系数 $k$ 非常非常大，会发生什么？

$k$ 非常大，会导致弹簧的弹力也非常大。给这个顶点施加一个这么大的力，它会跑得过于远。正常情况下我们讨论弹簧，很多都是假设能量守恒的：弹簧系统理论上，这个顶点不应该冲过原来的位置、跑到另一侧更远的地方去。但如果直接用简单的显式积分，给它施加一个很大的力，这个顶点就有可能跑过头、跑到另一侧，而且跑到一个更远的位置上。

然后，因为它跑得更远了，我下一刻算出来的弹簧力就比原来的力还要大；给这么大的力，再更新位置，下一刻它又会跑得更加远。如此反复，它会一次次超越自己，跑得越来越远，最终跑出整个屏幕、跑出我们整个模拟空间。

这个问题就叫做 overshooting。它本质上跟我们之前做碰撞时遇到的 overshooting 差不多意思：系数很大的时候，它会跑得过远。

> **易错点**：overshooting 一般在两种情况下出现——要么是 stiffness，这个 $k$ 很大；要么是时间步长 $\Delta t$ 很大。固定 $k$ 的情况下，步长一大，一步顶出去的位移就大，同样会跑得更远。

讲到这里，有同学问：$k$ 大不是弹力大吗？弹力不是把它拉回来吗？——对，没错：$k$ 很大的时候，它确实会把它推回来；但它不只是把它推回来，还把它推过头了，而且要推得远远的、超过原来的位置，推得比上一回更过头。因为这只是一根弹簧、只会左右晃，$k$ 一大，它就会直接穿过原来的位置，冲到另一头去。这就是问题所在。

那怎么解决这个问题？一个比较简单的思路，是把 $\Delta t$ 搞小一点。这可以做，但不是一个很好的思路：时间步长搞得越小，整个模拟的效率就会降低，而我们一般来说很在乎模拟的效率，希望性能上还是要比较高。

这就是为什么早年大家一般用显式积分比较多，但后来用隐式积分的就相对比较多了。
### 出路：隐式积分

接下来讨论另一种模拟方式：隐式积分。隐式积分我们之前讨论过怎么做：假如说我现在有速度跟位置两个变量，速度等于这么一个更新过程，位置等于这么一个更新过程——速度用的是力，位置用的是速度：

$$v_1 = v_0 + \Delta t\,\frac{F(x_1,\,v_1)}{m}, \qquad x_1 = x_0 + \Delta t\,v_1$$

那这里速度更新用的力 $F$ 是什么？是想要得到的那个新的状态下算出来的力——它是根据新的时刻、新的状态算出来的，是跟 $v_1$、$x_1$ 相关的一个力。

而这个力，我们是没有办法直接计算出来的。为什么？因为它是跟 $v_1$ 跟 $x_1$ 相关的，而我们事先并不知道 $v_1$ 跟 $x_1$。这个力到底怎么求出来，就是我们接下来要做的事情。

## 把隐式积分变成优化问题：从消元到牛顿法
> 对应块：BLK13 | 覆盖分集：P05中1 | 块标题（分集名）：《Lecture 05 Physics-based》

隐式积分有个先天的别扭之处：位置的更新式里写着未来时刻的速度 $v_1$，速度的更新式里又写着未来时刻的力，而力又作用在未来的位置 $x_1$ 上。于是 $x_1$ 得靠 $v_1$ 才能算出来，$v_1$ 本身却也是个未知数——两个未知量互相咬着，谁也没法先算。这个结怎么解？我的做法很朴素：先消元，把两个未知数砍成一个；砍完发现剩下的是一个非线性方程，直接解不太行；那就对问题再做一次变换，把它重新分装成一个优化问题；最后请出牛顿法，迭代着把它解掉。这一讲就沿着这条线走。

### 两个未知数，先消掉一个

先把两条公式摆在桌面上：

$$x_1 = x_0 + \Delta t\, v_1, \qquad v_1 = v_0 + \Delta t\, M^{-1} f_1$$

上面这条有 $v_1$，下面这条也有 $v_1$。想消元，就拿一条把另一条里的 $v_1$ 顶替掉：把下面这条代进上面这条，展开——

$$x_1 = x_0 + \Delta t\, v_0 + \Delta t^2 M^{-1} f_1$$

中间那项 $\Delta t\, v_0$，就是 $\Delta t$ 乘进括号之后挪过来的。这样 $v_1$ 就被消掉了，式子里只剩 $x_1$ 和 $f_1$ 两个东西。

第二条公式干脆反着推：原来是有 $v_1$ 算 $x_1$；现在反过来，有了 $x_1$，$v_1$ 怎么求？两个一相减、再除以 $\Delta t$：

$$v_1 = \frac{x_1 - x_0}{\Delta t}$$

两条放在一起看：下面这条是平凡的——只要 $x_1$ 已知，做一次减法、一次除法就完事；真正的问题全压在上面那条上。接下来整讲都围着它转。

### 只跟位置有关的力

消元的结果里还拖着一个 $f_1$。这里我要做一个关键假设：假设这个力只跟位置有关，跟速度没有什么关系。

什么样的力是这种力？重力算一个——事实上重力连顶点的位置都不依赖，它就是个常数，跟什么都没关系，更谈不上依赖别的变量；弹簧力也算一个，它只跟弹簧两端顶点的位置相关。

> **定义**：这种只跟位置有关系的力，叫做 holonomic 的力。

有了这个假设，$f_1$ 就可以写成一个关于顶点位置的函数：把下标 1 挪进括号里，$f_1$ 变成了 $f(x_1)$。方程于是变成

$$x_1 = x_0 + \Delta t\, v_0 + \Delta t^2 M^{-1} f(x_1)$$

未知量只剩 $x_1$，问题正式变成"解一个方程"。麻烦在哪儿？这个力可能不是位置的线性函数。以前学线性代数，一般都假设问题是线性的，然后利用消元法之类的手段把它解掉；这里力一旦非线性，那套手段就失效了，所以我们需要一些特殊的办法来处理。

### 改写成优化问题

接下来对问题再做一次变换，重新分装一下。原方程的毛病在于 $x_1$ 同时出现在等号的左边和右边，这样就没法解了。但我发现，这个方程跟一个非线性优化问题是等价的——$x_1$ 可以看成某一个函数取最小值的位置：

$$x_1 = \underset{x_1}{\arg\min}\; f(x_1), \qquad f(x_1) = \frac{1}{2\Delta t^2}\bigl\|x_1 - x_0 - \Delta t\, v_0\bigr\|_M^2 + E(x_1)$$

几个记号交代一下。范数里装的那一坨 $x_1 - x_0 - \Delta t\, v_0$，你就当成一个向量来看；带下标 $M$ 的范数是个简化写法，意思是"这个向量乘 $M$ 再乘它自己"：

$$\|u\|_M^2 = u^T M u$$

$M$ 是质量矩阵（mass matrix）——这个我刚才可能忘了说——一般来说它就是一个对角矩阵，对角线上放着各个质量的值。这里的 $x$ 不是单个点：把全部 $n$ 个顶点的信息摞在一起，就是一个 $3n$ 维的大向量，相当于以前用顶点列表存那些顶点，现在把它们竖过来摆成一列；$M$ 相应地是 $\mathbb{R}^{3n\times 3n}$ 的矩阵。所以上面那个东西不是一个方程，而是 $3n$ 个方程所构成的方程组——里面每一个分量都是未知数。这里我停一下，因为这一步挺关键，是后面一切的地基；它为什么等价，接下来马上推。

后半截的 $E(x_1)$ 是力所对应的能量。每一种力其实都有自己的能量表达式：模拟的东西里有弹簧，$E$ 里就对应弹簧的能量；有重力，里面就有重力势能。

> **提示**：有同学问，是不是只有保守力才能用能量？对，一般来说只有保守（conservative）的力才能用能量形式描述；如果是非保守力，比如摩擦力，一般来说没有办法用能量来表示。又有同学问，能量是不是要对力做积分才能得到？也不用——做模拟的时候可以直接把能量写出来，每种力都有自己的能量形式，不需要先算力再积分。

### 为什么等价：最小值处梯度为零

为什么说解那个方程，等价于求这个函数的最小值？

对一个优化问题而言，$x_1$ 是解，意思就是 $x_1$ 是这个函数取最小值的位置。回想一元函数：一个实数函数的最小值，出现在一阶导数为零的地方——那一点既没有办法增长、也没有进一步的下降空间了。对关于顶点位置的函数而言，"一阶导数"换成梯度，因为梯度本质上就是一阶导数的转置（transpose）。于是：

> **结论**：若 $x_1$ 是目标函数的最小值点，则目标函数在 $x_1$ 处的梯度必须等于零。反过来说，梯度等于零就是"最优解"必须满足的条件。

下面把梯度算出来。第一项是二次型，对它求梯度：把平方"拿"下来一个 2，跟系数里的 $\tfrac{1}{2}$ 抵消掉，$M$ 留在前面，括号里的向量本身保留（这一步不熟的话，翻一翻微积分里求导那一块就够用）：

$$
abla\left[\frac{1}{2\Delta t^2}\,u^T M u\right] = \frac{1}{\Delta t^2}\,M u, \qquad u = x_1 - x_0 - \Delta t\, v_0$$

第二项：对能量求梯度是什么？力是负的能量梯度，$
abla E(x_1) = -f(x_1)$，那对能量求梯度不就是负的力吗。两项拼起来、令梯度为零：

$$\frac{1}{\Delta t^2}M\bigl(x_1 - x_0 - \Delta t\, v_0\bigr) - f(x_1) = 0$$

把 $\Delta t^2$ 乘过去，再左乘 $M^{-1}$：

$$x_1 = x_0 + \Delta t\, v_0 + \Delta t^2 M^{-1} f(x_1)$$

——正是消元得到的那个方程。所以两种写法完全等价：按隐式积分直接写，得到的是一个方程组；写成 argmin，得到的是同一个问题的优化表述，只是换了一种表达方式。

### 换个写法，图什么？

费这么大劲换成优化问题，好处很实际：优化问题其实有很多很多现成的数值方法、数值套路，数学家早就把这些方式给我们提供好了，我们直接拿过来解这个优化问题就行。

而且注意，这个公式并不限于弹簧系统——对于任何想做隐式积分的 dynamics 模拟其实都适用；回头我们讲有限元的时候，也会再提到它。

有同学会问：这么解，会不会出现多个解？会不会恰好找到不对的那一个？是会出现的。这个问题先记下，讲到极值判断的时候回来收拾它。

> **易错点**：克服 overshooting 的不是"改写成优化"这个动作，而是隐式积分本身。隐式积分这个方法能够克服 overshooting，但它带来的麻烦是 $x$、$v$ 纠缠在一起不知道怎么算——本讲这一套消元、改写、牛顿法，解决的就是"怎么把它算出来"。

那"隐式积分能克服 overshooting"这件事怎么证明？这个我就没法在这儿给你证了——它属于数值方法、数值积分课程里的内容，证明还挺长。一般是通过对误差衰减的判定来做的：overshooting 的本质就是误差会越来越大、被一步步放大，所以要证明的是这个误差长期看是衰减的。

### 解方程组还是做优化？

还有几个零散的问题，都跟"这个问题的数学定位"有关，放在一块儿说。

有同学提到共轭梯度法（conjugate gradient）——那是另一种方法，我们这里暂时不讲。

有同学问 $x_1 = \arg\min$ 是怎么回事。它是这个问题的另一种描述方式：非线性优化问题，可以认为跟"一阶导数等于零"这个方程等价。所以"用牛顿法求根"跟"做优化"实际上是一回事情——你做优化，本质上就是对它的一阶导数求根；而对一阶导数求根，跟直接用牛顿法去解非线性方程，也是一回事情。解方程组可以看成优化问题的一个特例；数学家研究的时候，往往不是单纯地考虑解方程组，而是直接研究更一般的非线性优化问题，我们这里也是想把问题放到一个更通用、更广阔的数学框架上去讨论。往历史上看，早期关于模拟的一些论文，其实就是简单地把问题当作解方程组来处理的；最近几年大家发现优化问题的框架更广阔，可以借用很多处理优化问题的方式，模拟方法的选择也就跟着更多样了。

那为什么不干脆求反函数、拿解析解？如果你真有 $f$ 的反函数，你确实可以得到精确的解析解。但我们走的是数值路线：把问题变成一个方程，方程左右两边都含未知量，然后用数值方法迭代着求解——完全不依赖反函数，你只要能对它求导就行。

课后我会给大家一篇阅读：90 年代关于布料隐式积分的一篇比较经典的论文（Baraff 那篇）。它跟我这里讲的还稍微有点不一样——它是按解方程组的方式来写的，并不是能量优化的写法；它把那个方程做了线性化，所以你可以认为它只做了一次牛顿迭代。第一次接触这些东西，这里或者那里冒出些疑问很正常；对细节感兴趣的同学，可以把那篇论文仔细读一读。

### 牛顿法：沿着切线往谷底走

主角登场。这个方法全名叫 Newton–Raphson method，不过我们通常就叫它牛顿法。它最早被发明出来，就是为了解非线性优化问题：$x_1$ 等于某一个函数的最小值，我想让这个函数取到最小值，就得知道什么样的状态下它能取最小。

对函数有一个基本要求：连续。数学家后来发现，其实不要求它严格满足数学上那种一阶、二阶连续，它有的时候也能收敛、也能 work——可以认为 Lipschitz continuous（一种广义的连续）就够。不过你不用特别纠结这个名词，关键是函数必须连续：它要是不连续，你连导数都没办法求出来，后面就没法搞了。

先把前面同学那个追问正面回答掉：为什么梯度等于零就是最优解？拿一元函数 $f(x)$ 画条曲线：最小值就是曲线的最低点。最低点有个性质——切线是平的，一阶导数为零。因为一阶导数描述的就是这根函数升降的方向，到了最低点，它没有进一步的下降空间了。所以"一个函数取最小值"跟"一阶导数为零"，实际上是一个概念——取最小值的时候，一阶导数必须为零。变量是向量的时候，一阶导数就换成梯度。于是现在的问题收敛成一句：怎么样找到让一阶导数（梯度）等于零的那个解？

牛顿法的答案：做一个比较简单的一阶泰勒展开近似。真正的解 $x$ 是不知道的，它是未知量；但当前的位置是知道的，设当前在 $x_k$。把导数函数在 $x_k$ 附近线性化：

$$f'(x) \approx f'(x_k) + f''(x_k)\,(x - x_k)$$

令这个近似等于零，它就变成了一个很简单的小方程，$x$ 当场就能解出来。把这个改变量记作 $\Delta x$——让近似为零，意味着把 $f'(x_k)$ 挪到公式左边、除以 $f''(x_k)$、前面加个负号：

$$\Delta x = -\frac{f'(x_k)}{f''(x_k)}$$

然后把 $\Delta x$ 加到 $x_k$ 上，得到新的位置；再从新位置出发，算下一个 $\Delta x$，以此迭代。几何图像就是：从 $x_0$ 出发，按当前点的斜率跳一步，落到曲线上更低的地方；再从那里跳一步，以此类推，一步一步逐渐靠近函数的底部：

```text
f(x)
 │ \                            /
 │  \   x0                     /
 │   \   ●                   /
 │    \    ●               /
 │     \     ●           /
 │      \       ●      /
 │       \         ●  /
 │        \_____●_____/   ← 谷底：f'(x) = 0
 └────────────────────────────────► x
```

迭代一步步逼近谷底，帮我们找到 $x$ 这个解——这个方法就叫做牛顿法。

那这套迭代一定能收敛吗？我的答案是不一定，牛顿法不保证一定会收敛。后面我们讲有限元的时候，会给牛顿法加一些条件上的约束，能够保证它一定收敛，到时候再讨论。另外交代一句：这里的 $f$ 指的是要极小化的目标函数，就是根据前面隐式积分的公式推出来的那个东西。

### 导数为零不一定是最小值

还有个漏洞得堵上。一阶导数等于零，它其实既可以是最大值，也可以是最小值——最小值处切线是平的，最大值处切线同样是平的；而且这样的点在一个函数里可能有多个。那解出来到底是最大值还是最小值、到底合不合理呢？其实我就需要一个判定。用什么判定？用它的二阶导数。

高中里学抛物线的时候都见过：二阶导数实际上就是二次项的系数。二阶导数大于零，意味着开口向上；小于零，意味着开口向下。一个道理——把一阶导数为零的点算出来之后，看二阶导数的正负，看它是开口向上还是开口向下：大于零，开口向上，这是一个最小值；小于零，开口向下，是一个最大值。

但它不见得是全局的最大或最小。看这条曲线：

```text
f(x)
 │\            /\            /
 │ \          /  \          /
 │  \        /    \        /
 │   \      /      \      /
 │    \____/        \____/
 │
 │   局部最小     最大值    局部最小
 └────────────────────────────────► x
```

两个谷底都满足"一阶导数为零、二阶导数大于零"的极小条件，中间那座山峰满足极大条件——所以你解到的可能只是其中一个局部的小值（local minimal），而不是真正的最小值。存在局部极小的时候，说实话并没有一个特别好的通用处理方式，很多时候大家就用随机扰动之类各种各样奇奇怪怪的办法去对付。

不过，有的时候我们可以对函数本身提出一些要求——假如这个函数满足某些性质，事情就好办了。比如说，我知道一个函数的二阶导数永远是大于零的，不管在什么样的位置——那意味着什么？最大值的时候二阶导数是小于零的，所以这个函数不存在最大值。而它又是一个连续函数：假如它有两个最小值，那中间必然存在着一个小山峰，也就是一个最大值——矛盾。换句话说：

> **结论**：二阶导数处处大于零的函数不存在最大值，因而有且仅有一个最小值——它永远只有一个低谷。

大家可以把这个条件记住，因为我们回头讲模拟的时候，会回来利用这个条件——它在数学里面也是比较重要的一个信息。

### 推广到一堆顶点：梯度与海森矩阵

现在可以把牛顿法的思路，扩展到我们刚才的优化问题上去了。优化问题也是求一个函数的最小值，只不过对这个函数而言，变量不是实数，而是一个向量——$x$ 是很多个顶点所构成的一个大矢量。做法一模一样：当前有一个 $x_k$，用它来做近似。我们的解必须满足一阶导数等于零，也就是梯度等于零，那就对梯度做一阶泰勒展开：

$$
abla f(x) \approx 
abla f(x_k) + 
abla^2 f(x_k)\,(x - x_k)$$

令它等于零，把整个梯度挪到公式的右边，解出改变量：

$$\Delta x = -\bigl[
abla^2 f(x_k)\bigr]^{-1} 
abla f(x_k)$$

先把梯度算出来，再乘上二阶导数的逆、前面加个负号，就得到 $\Delta x$；把它加到顶点的位置上，就得到了新的顶点位置。如此不停地迭代下去。跟一维版对一下账，无非是两处升级：

| 对比项 | 一维牛顿法 | 向量版牛顿法 |
| :--- | :--- | :--- |
| 变量 | 一个实数 | $3n$ 维顶点位置大向量 |
| 一阶导数 | 数 $f'(x_k)$ | 梯度 $
abla f(x_k)$（向量） |
| 二阶导数 | 数 $f''(x_k)$ | 海森矩阵 $
abla^2 f(x_k)$ |
| 求 $\Delta x$ | 做除法 | 解线性方程组（乘矩阵的逆） |

一阶导数变成了一个向量（gradient），二阶导数变成了一个矩阵——$f$ 的海森矩阵（Hessian）；"除以二阶导数"变成了乘矩阵的逆，也就是说你需要矩阵的逆来把这个问题解出来。本质上，这跟我们前面看的一维牛顿法是一样的。

最后回到模拟问题上。我们的 $f$ 是什么？就是前面由隐式积分公式推出来的那个东西：

$$f(x_1) = \frac{1}{2\Delta t^2}\bigl\|x_1 - x_0 - \Delta t\, v_0\bigr\|_M^2 + E(x_1)$$

把这个具体的函数交给牛顿法，迭代出 $x_1$，再用 $v_1 = (x_1 - x_0)/\Delta t$ 把速度收回来。整讲的路子拼起来就是：

```text
隐式积分方程组                                消元
  x1 = x0 + Δt·v1          ──────────►   x1 = x0 + Δt·v0 + Δt²·M⁻¹·f(x1)
  v1 = v0 + Δt·M⁻¹·f1                    （只含 x1 的非线性方程组）
                                               │
                                           等价改写
                                               ▼
       x1 = argmin [ 1/(2Δt²)·‖x1 - x0 - Δt·v0‖²_M + E(x1) ]
                                               │
                                           牛顿法迭代
                                               ▼
                                   x1 ──► v1 = (x1 - x0)/Δt
```

读图：从互相纠缠的两个未知数出发，消元收敛到只含 $x_1$ 的非线性方程组；改写成优化问题后交给牛顿法迭代，解出位置再反推速度——隐式积分"到底怎么算"这件事，就闭环了。

## 把隐式积分写成优化问题：牛顿迭代、海塞与线性求解
> 对应块：BLK14 | 覆盖分集：P05下 | 块标题（分集名）：《Lecture 05 Physics-based》

### 先把目标函数摆正：梯度与海塞各由两部分构成

先接着上一段，把我们要优化的目标函数再摆一次：

$$E(x) \;=\; \frac{1}{2\,\Delta t^{2}}\left(x - x^{0} - \Delta t\, v^{0}\right)^{T} M \left(x - x^{0} - \Delta t\, v^{0}\right) + E_{\text{elastic}}(x)$$

这个式子前面给大家看过了，不记得也没关系——它就是我们这一段的主角：我想要优化的函数。第一项是惯性那一项，$x^{0}+\Delta t\,v^{0}$ 是这个时间步里顶点"靠惯性本来该到"的位置；第二项 $E_{\text{elastic}}$ 是弹性势能。

它的梯度分别由两部分构成：第一部分，对惯性那一项求个导，得到 $\frac{1}{\Delta t^{2}}M\left(x - x^{0} - \Delta t\,v^{0}\right)$；第二部分是负的力——势能对 $x$ 求导，得到的就是负的力：

$$
abla E(x) \;=\; \frac{1}{\Delta t^{2}} M\left(x - x^{0} - \Delta t\, v^{0}\right) \;-\; f(x)$$

它的海塞矩阵（Hessian）同样由两部分构成：第一部分是惯性项再求一次导，也就是除以 $\Delta t^{2}$，质量矩阵留着，得到 $\frac{1}{\Delta t^{2}}M$；第二部分是能量的海塞，即弹性势能对位置的二阶导数：

$$H(x) \;=\; \frac{1}{\Delta t^{2}} M \;+\; \frac{\partial^{2} E_{\text{elastic}}}{\partial x^{2}}$$

> **定义**：把一个时间步的隐式积分写成"最小化 $E(x)$"之后，梯度 $
abla E$ 自然拆成"惯性项的导数"加"负的弹力"两块；海塞 $H$ 同样拆成"$\frac{1}{\Delta t^{2}}M$"加"弹性势能的二阶导"两块。后面所有的讨论都围绕这两组"两块"展开。

### 牛顿迭代：一个时间步里做什么

有了海塞、有了梯度，就回到牛顿法上——把通用框架里对应的位置替换掉，就得到了我们的算法。一个时间步里就四件事。

第一件，对每个顶点的位置做一个初始化，也就是给牛顿迭代一个初始猜测。一般来说可以直接用原来的值，或者用原来的值加上速度的更新改变量（$x^{0}+\Delta t\,v^{0}$）——这取决于你不同的算法，遵循一个初始化就行。

第二件，解这么一个线性方程：

$$H\,\Delta x \;=\; -\,
abla E(x)$$

$\Delta x$ 是位置的更新改变量；前面的系数 $H$ 是二阶导数，右边是一阶导数（梯度取负）。

第三件，解完之后更新一下顶点位置：$x \leftarrow x + \Delta x$。

第四件，把新的位置跟老的位置的差除以 $\Delta t$，得到速度的更新：

$$v \;\leftarrow\; \frac{x - x^{0}}{\Delta t}$$

整个隐式积分的求解，核心就是这样一套"组装梯度与海塞、解线性方程、更新位置与速度"的流程。

### 只做一次牛顿法：早期论文的捷径与隐患

我课上反复提到的那篇论文，其实就是做了一次牛顿法。很多早期的论文没考虑得那么深：他们一般假设面对的是一个非线性方程组，把这个非线性方程组做一个线性化，然后把线性化之后的线性方程组解掉——你其实可以认为，这种早期的方式就是做了一次牛顿法。

但只解一次牛顿法，实际上是有可能出现很多模拟问题的，会出现不稳定。这也是我为什么想给大家讲非线性优化、而不是直接讲"解方程"的一个原因，下面展开说。

课后想让大家读的也正是这样一篇论文：对衣服模拟而言它蛮经典，是最早用隐式积分做衣服模拟的论文，也就是 Baraff 和 Witkin 那篇《Large Steps in Cloth Simulation》。它没有用弹簧系统，用的是另一套模型。你读下来就会发现：它也没有去解非线性方程，只是把非线性方程做了一个线性化操作——其实跟我做一次牛顿迭代是等价的，这一点论文里自己也说了。以后你们想做衣服模拟的项目、想进一步了解的话，这篇基本上是必读。

### 为什么非要站在"优化"的高度讲

为什么我想讲非线性优化，而不是直接讲解非线性方程？因为把问题化成非线性优化，是在一个更高的层次上理解这个问题；解线性方程、解非线性方程，是相对比较低的层次。在高层次上理解之后，其实有助于我们解释很多模拟中产生的现象。

第一次接触的同学在这一块可能会有点困惑，但我觉得还是有必要讲——因为我这里讲的东西，并不只是用来做弹簧系统。回头你以后想搞有限元、做弹性体的模拟，用的方法跟这个是一样的；很多物理模拟本质上采用的都是这种方式。无非就是说，对弹簧系统——比如模拟衣服、模拟布料——你这里的 $E$、$f$ 就是弹簧的能量跟弹簧的力；做有限元，用的就是有限元的能量跟有限元的力。不同的系统，相当于换不同的能量、换不同的力，但计算核心都可以认为是一个非线性优化问题。

课堂答疑里也有几个相关的问题，一并放在这里。

有同学问：刚体也能这么做吗？做刚体好像不是很常见，弹性体有限元、衣服模拟会更多一点。

有同学问多场耦合怎么办。可以这么想：如果所谓的"多场"同样都是粒子模型——比如模拟一块布掉到一个软体上——那你完全可以用这套模型来做；但如果布要跟流体相结合，流体那块就没法用这个东西做了。耦合一般有很多专门的耦合模型，通过"分别求解、中间加一步耦合过程"来实现，所以不太一样。耦合的具体内容其实还挺多的，我可能没有时间展开，怕基础不好的同学跟不上，这里就暂时不讲。

还有同学问生活中的场景，比如衣服吸水之后拧干。这个有不少人做过：让衣服的顶点上可以存一些水——就像海绵一样，存一定量的水在上面——然后当它受到一些力的时候，就可以把这些水给它挤出来、推出来。

再回答一个推导层面的问题：对隐式积分做泰勒展开做线性化，跟这里的优化问题等价吗？应该是等价的——等价到里面要求解的那个线性方程。另外要说明，我这里讲的是一个推导过程，帮你把来龙去脉看清楚；你真的写模拟的时候，其实可以完全直接利用这个非线性问题去构造优化，并不需要真的先把方程推一遍。而且这个套路不只限于这一种隐式积分——隐式积分有很多种，其他的隐式积分同样可以利用类似的套路，只是会更复杂一点；我们这里用的是比较简单的欧拉隐式积分，所以方程简单一点。

### 海塞矩阵长什么样：一根弹簧四个小块

这里我想再稍微讲一下：对弹簧系统，海塞怎么算。

之前讲弹簧系统的时候我们推过海塞：弹簧系统的海塞，实际上是由所有弹簧的贡献总和构成的，每一根弹簧都有一个小子系统与之对应。整个海塞是一个 $3n \times 3n$ 的矩阵——有多少个顶点，就是三乘以顶点的数量，因为每个顶点是一个三维向量。每根弹簧连接顶点 $i$ 和 $j$，贡献四个 $3\times 3$ 的小块：分别摆在 $i$ 顶点所处的那三行三列、$j$ 顶点所处的那三行三列，以及 $i$、$j$ 交叉的位置上。这些小块会重叠——0 号顶点占第 0、1、2 行（列），1 号顶点占第 3、4、5 行（列），2 号顶点占第 6、7、8 行（列），以此类推往下排。

举个简单的例子：三个顶点，一条边连接 0 跟 1，一条边连接 0 跟 2，那么拼出来的整体就是一个 $9\times 9$ 的矩阵：

```text
            顶点0          顶点1          顶点2
          ┌──────────────┬──────────────┬──────────────┐
  顶点0   │  H00(边01)   │  H01(边01)   │  H02(边02)   │
          │ +H00(边02)   │              │              │
          ├──────────────┼──────────────┼──────────────┤
  顶点1   │  H10(边01)   │  H11(边01)   │      0       │
          ├──────────────┼──────────────┼──────────────┤
  顶点2   │  H20(边02)   │      0       │  H22(边02)   │
          └──────────────┴──────────────┴──────────────┘
```

每个格子都是一个 $3\times 3$ 的 block。边多的话，每条边都有这么一组小块，全部叠加在一起——比如左上角那一块，就同时收了边 (0,1) 和边 (0,2) 两根弹簧的对角贡献。所以"弹簧系统的 H 在哪里算"的答案就是这里：每根弹簧利用公式算出一个 $3\times 3$ 矩阵，再按照摆放规则把它摆进这个大矩阵里去。

具体到某根弹簧的 $3\times 3$ 小块：第二节课推过这个公式（课件第 48 页），不记得可以回头看一下。记 $x_{ij} = x_i - x_j$——就是这两个顶点位置的差——$\hat{x}_{ij}$ 是它的单位方向向量，那么

$$H_{ij} \;=\; k\,\hat{x}_{ij}\hat{x}_{ij}^{T} \;+\; k\left(1 - \frac{l_0}{\lVert x_{ij}\rVert}\right)\left(I - \hat{x}_{ij}\hat{x}_{ij}^{T}\right)$$

我这里主要想讨论的不是公式本身，而是想给大家看清楚：这个东西是正定的。怎么看？取一个任意向量 $v$，把它夹在矩阵左右两边（算 $v^{T}H_{ij}v$）：第一部分变成 $k(\hat{x}_{ij}^{T}v)^{2}$——一个东西的平方，肯定大于等于零；第二部分括号里剩下的是 $\lVert v\rVert^{2}-(\hat{x}_{ij}^{T}v)^{2}$ 这类项，由柯西不等式保证大于等于零。两部分都大于等于零，所以这个矩阵是正定的。

> **提示**：更严格的说法是半正定（semi-positive definite），而不是通常说的对称正定（symmetric positive definite）——夹出来的结果保证的是"大于等于零"。

但有一个问题：前面那个系数 $1-\frac{l_0}{\lVert x_{ij}\rVert}$ 有可能是负的。当弹簧被压缩——长度小于原长 $l_0$ 的时候——$\frac{l_0}{\lVert x_{ij}\rVert}$ 就大于一，整个系数就是负的，那么这个矩阵就可能是负的、可能不正定了。

> **结论**：弹簧拉伸的时候，它的海塞小块一定是正定的；压缩的时候就有可能不正定。整个系统矩阵的正定性是由每一个小块的正定不正定决定的，只需要看每个 $h$ 是不是正定就行了。说"有可能"不正定，是因为整个 $A$ 里还有别的项——比如质量矩阵那一项——所以不能保证它一定不正定，但它确实存在不正定的风险。

另外有同学问：每个顶点的质量可以不同吗？可以不同，没关系。一般做法是：对每个三角形先算一个质量——三角形的质量可以认为跟它的面积相关——然后把三角形的质量分成三份，分布到三个顶点上去，这样每个顶点就有各自不同的质量了。

### 正定为什么重要：从二阶导数到唯一解

刚才说了半天这个矩阵正定不正定——费了半天劲，我为什么要讨论这个东西？

这个海塞矩阵是目标函数的二阶导数；它正不正，跟我们前面讲实数函数时"二阶导数是不是正的"实际上是一回事情。实数函数如果二阶导数永远是正的，它就存在唯一解、唯一的极小；现在二阶导数变成了一个矩阵，只要这个矩阵是正定的，我的函数也就存在唯一的极小解。对弹簧系统来说，这是非常重要的一点。

有同学问：$\Delta t$ 越小，前面惯性那一项就越大，是不是就可能更正定？这个同学问得非常好，答案是是的：$\Delta t$ 越小，你就越正定。可以这么想：$\Delta t$ 越小，意味着时间步长越小；时间步长越小，每一步就动那么一丁点——这跟显式积分里"步长小更稳定"其实是一回事情，可以让整个系统变得更好，模拟起来也就更稳定。

> **易错点**：正定是"存在唯一解"的充分条件，但不是必要条件——不能严格地说不正定就一定没有唯一解。所以我们很多时候只能做一个大的判断，实际模拟中能做的事情并不多；但有一点可以肯定：正定的时候系统相对来说会稳定很多，而压缩的时候它会更容易出问题。

### 压缩时为什么出问题：一根被压弯的弹簧

压缩的时候容易出什么问题？我给大家举一个现实生活中的例子，大家可以想一想：有这么一根弹簧，我去挤压它、试图压它。压它的话会是什么状况？它会卷起来、蜷起来，对不对？而且蜷的方式有好几种可能性：一种可能是往上卷起来翘起来，一种可能是往下翘起来——其实都有可能，对吧？

这针对的就是两种不同的 local minima（局部极小）：这两种状态都符合要求、都符合能量最小化，而你事先并不知道它会产生哪一种状态、不知道它最终会往哪一边翘——不同的方向其实都是可以接受的。这就是"压缩时非正定、解不唯一"的一个很直观的解释。

这个现象在三维里会出现，在一维里不会出现。因为一维里弹簧能量的二阶导数就是弹性系数 $k$，肯定大于零，没有这个问题；二维三维里，才有正定不正定的考量。也顺带回答另一个同学的问题：模拟结果有没有解析解可以对照？一维的话可能有——一维弹簧就是简单的简谐振动，有解析解；二维三维的话，一般就没有解析解了。

还有同学问：弹簧直线压缩拉伸，弹簧本身会不会弯？弯了怎么计算？我们的弹簧模型不能弯——它本质上只考虑两个端点的相对位置，假设弹簧永远是一条直线相连，没有考虑弹簧自身的弯曲。这其实会导致一些问题，下次课我会讲：如果只是单纯做这种弹簧模型，对弯曲的模拟会存在很大的问题。

### 不正定怎么办：最粗暴的修法

那如果压缩时真的不正定，怎么办？照理说，如果你只是为了把这个问题描述出来，正定不正定并不是一个很严重的问题——哪怕不正定，只要能解出一个东西来，对整个模拟来说总还是有一个结果。它主要影响的不是"解能不能解出来"，而是很多解方程的算法有约束：有一些线性求解方法会要求这个矩阵必须是正定的。很多时候这是出于算法稳定性的考量，不是数学模型稳定性的考量，更多是从算法的角度去考虑的。

我们比较常见的实操是：既然知道压缩的情况下后面那一部分（弹性海塞那一块）有可能不正定，那处理起来很直接——把这一项删掉就行了。压缩时它小于零？我直接把这一项抹掉，剩下的前面那部分（$\frac{1}{\Delta t^{2}}M$）肯定是正定的，那么就解决了。当然，这是一个比较粗暴的方法，还有其他各种各样的方法，我这里就不展开了。大家感兴趣的话，可以看一下那篇叫《Stable but Responsive Cloth》的论文，里面列举了很多各种不同的方法：矩阵不正定时应该怎么做、怎么样把它调整得更正定。

### 解线性方程：Jacobi 迭代与直接法

先回答一个同学的问题：这个线性方程会不会无解？我觉得不会。$H$ 虽然不一定正定，但应该是可逆的——单看弹性能量那部分的海塞，它是奇异的（半正定，可能有零奇异值）；可是前面加了质量矩阵那一项之后，大概率就不会是一个奇异矩阵了。判断能不能解，就是看它能不能求逆、看它有没有零奇异值：没有零奇异值就可逆，方程就有解。

#### Jacobi 迭代：盯着残差一步步修

下面稍微给大家讲一下解线性系统的方法，比如 Jacobi 方法（雅可比迭代）。学过数值分析、数值计算课的同学可能见过；没学过也不要紧，反正我们作业里也不会用到这些方法，这里就是给大家浏览一下大致的流程。

假如我要解的问题是 $A\,\Delta x = b$。我先给 $\Delta x$ 一个初值，然后计算它的残差（residual）——残差是什么？就是 $b - A\Delta x$。得到残差之后，对 $\Delta x$ 做更新：

$$\Delta x \;\leftarrow\; \Delta x + \alpha\, D^{-1}\, r, \qquad r = b - A\,\Delta x$$

其中 $D$ 是 $A$ 的对角矩阵（把 $A$ 对角线上的元素取出来组成的矩阵），$r$ 是刚才算的残差。这个就完了，多次迭代下去，这个就叫做 Jacobi 方法。

大家教科书里学到的 Jacobi 方法，一般来说就是 $\alpha = 1$ 的情况；$\alpha=1$ 时，我们一般要求矩阵是对角占优的。但很多时候矩阵没有办法保证对角占优，这就是为什么我们一般想要有一个 $\alpha$ 值——它能让这个方法在更多的条件下、更多的情况下收敛。我会比较推荐带一个 $\alpha$。

另外说明一下：牛顿迭代里面解线性方程用什么方法，各种各样的都可以；我这里用 Jacobi 只是举了一个例子，并不代表你就非要用 Jacobi。

#### 直接法还是迭代法

解线性系统有两种不同的套路：直接法与迭代法。直接法对 $A$ 的约束比较小，基本上都能操作，但一般在 CPU 上处理得比较常见；迭代法有收敛的问题，而且你如果想得到精确解，它会比较慢，但好处是 GPU、CPU 都能做，实现起来也比较容易。

| 对比项 | 直接法 | 迭代法 |
| :--- | :--- | :--- |
| 对矩阵 $A$ 的要求 | 约束小，基本都能操作 | 有收敛问题 |
| 常见平台 | 一般在 CPU 上 | GPU、CPU 都能做 |
| 拿到精确解 | 直接给出 | 想要精确解会比较慢 |
| 实现难度 | 通常依赖现成数学库 | 实现起来比较容易 |
| 内存开销 | 大，限制可解规模 | 小很多，能支撑更大规模 |

那怎么选？如果是我自己动手写，我会比较推荐用迭代法；如果有一些比较现成的数学库——Intel 的 MKL 库就很强大——那么我会建议用直接法。有同学问"迭代法能支持的维度是不是比直接法更大"——是的，直接法有一个内存开销的问题，迭代法的内存开销会小很多很多；这不单纯是计算量的问题，还要考虑到内存开销。

GPU 上的选择也顺带说一下：可以用 Jacobi 这类迭代法；直接法也可以用——反正 MKL 库很强大——不过会比你用迭代法稍微慢一点。至于共轭梯度（CG），它的效果其实取决于 preconditioner（预条件子）：没有 preconditioner 的话，共轭梯度的效率其实也不是特别高；而在 GPU 上，preconditioner 的选择比较有限；CPU 上一般用 ILU（incomplete LU 分解）会比较常见。

最后两点实操经验。一是一般来说我们不会用谱（spectrum）去衡量矩阵——矩阵很大的时候，谱根本没法算，所以那些分析手段一般用不上。二是调参很多时候就是试错：你发现它不收敛了，就把系数调小一点，再看它是不是收敛。但有一点可以肯定：只要你不断地调，肯定是能找到一组合适的参数让它收敛的，这个还是要保证的。

### 第二次作业：一块布和一个球

第二次作业跟现在讲的内容直接相关：模拟布料衣服。跟上次一样，代码包下载下来会有一个叫 Cloth 的场景。双击打开、转一下视角，你会看到一块布，还有一个球——球就是用来跟布做交互的。

这块布是 21×21 的网格，一共 441 个顶点；其中有两个固定点，分别是 0 号顶点和 20 号顶点，模拟时固定不动。模拟的目标就是这块布：用户可以拖拽小球跟布交互——布掉下来之后，你用鼠标点住球拖着走，布就被球撞来撞去，做出动画效果。我给大家看的这个结果 demo，就是用 PBD（Position Based Dynamics）实现的，也就是这一讲要讲的技术。

有两件事先交代清楚。第一，这份作业没有做布料的自相交，因为布料自相交做起来特别麻烦，只做了球和布料之间的碰撞。第二，碰撞的原理课上不展开：跟刚体的碰撞其实跟咱们之前讲的刚体碰撞是一样的，比较容易，所以作业里球撞布这部分就不再专门讲了；留到下周讲的，是布料的自碰撞。

#### 为什么这块布这么弹

看 demo 你会发现，这块布被球一撞就弹，感觉不太像布，倒有点像个弹簧。为什么会这样？实际上是因为收敛：PBD 是拿迭代法做的，而布的软硬由迭代数量控制。想让布更弹一点，就把迭代数量调少；想让它看起来更硬、更不弹，就要把迭代数量加上去。

> **提示**：在 PBD 里，控制布料“软硬”的旋钮主要就是迭代次数——迭代越多越接近收敛、越硬；迭代越少越弹。

#### 隐式积分那一半：一个“魔法公式”

作业实际由两个部分构成：一半是 PBD，另一半是上周讲的隐式积分。所以框架里会给你两个脚本——一个 PBD 脚本，一个隐式积分弹簧系统的脚本。想用第二种方式模拟，在场景里把脚本切换一下就行，也可以达到比较类似的效果。

之所以要放一个隐式积分的脚本，主要目的是帮大家巩固上周学的知识。上周讲隐式积分，我们主要抓两样东西：一个是梯度（gradient），一个是 Hessian 矩阵。但实际开发过程中你会发现，Hessian 搞起来很麻烦。所以作业里用了一个比较偷懒的近似：没有去真的算 Hessian，而是用一个简单的对角矩阵去近似它。在这种近似下，原来“解线性系统”的那一步，就变成一个很简单的更新操作——利用梯度，可以直接把顶点的更新算出来。作业描述里会具体告诉大家怎么做；现阶段你先把这个式子当成一个 magic equation 接受下来，先不要纠结这个公式是怎么来的。等后面讲到相应的方法时，我们再具体讲这到底是一个什么样的方法、为什么它也能收敛也能 work、本质原因是什么。

上周就有同学问：算牛顿法本来要用 Hessian，为什么对 Hessian 涂涂改改、修修改改，它也能收敛、也能 work？其实是同一个道理。做非线性优化的时候，用 Hessian 去解是一个理想状态；但你不用真正的 Hessian，用近似的方法去修改它，再拿修改过的矩阵去解线性系统、去做更新，其实也是可以收敛的。至于收敛的条件是什么、这个方法该换个什么名字，我们之后会具体讲——严格意义上讲，这就不能叫牛顿法了，它就是一种方法。

大家正好利用这个作业感受一下隐式积分大概是个什么样的操作流程：总体上跟我们上周讲的隐式积分解 cloth dynamics 基本一模一样——都是一个迭代方法，都是先构造 gradient，再利用 gradient 去找到对顶点的更新，然后去更新顶点，差不多就是这么一个流程。

### 弹簧系统的软肋：弯曲

回到今天的主线。上周讲了弹簧系统，今天把它细细地再讲一遍：它有什么缺陷、什么地方我们可以做得更好。其中有一个会比较严重的问题，就是弯曲。

一个简单的例子：假如有两个小三角形，把它们当成一小块布料。用弹簧系统去模拟弯曲，办法是在相对的两个顶点中间加一根弹簧——这就构成一根弯曲弹簧，它负责阻止这两个小三角形翻折，这是上周讲过的。

```text
        1 *-----------* 3
          |  T1    /  |
          |      /    |
          |   /  T2   |
          | /         |
        4 *-----------* 2
```

两个三角形 T1、T2 共享 3-4 这条边；1 和 2 是不在这条边上的两个相对顶点，弯曲弹簧就架在它们中间。

但这个方式其实有一个问题：当这两个三角形几乎是平面的时候，它略微弯一点，这根弹簧的长度几乎不怎么发生改变。顺着中间那条共享边看过去，两个三角形各自缩成一条线段：

```text
      完全放平（θ = 180°）             略微弯折一个小角（画得夸张了）

      1 *-------* 轴------* 2         1 *........* 2
                                            \    /
                                             \  /
                                              * 轴
```

图里中间那个点就是共享边，连接 1、2 的那一条就是弯曲弹簧。完全放平时，1、轴、2 三点共线；稍微弯一点，两个端点几乎只是在竖直往上挪——位移方向跟弹簧（横向的连线）基本垂直，一阶上根本不改弹簧的长度，长度要到二阶的小量才开始缩短。而弹簧的抵抗正比于长度的变化量，所以在布接近平面的时候，这种弯曲的抵抗是非常弱的。

> **结论**：弯曲弹簧拿“长度变化”来度量弯曲，而接近平面时的弯折引起的长度变化只是二阶小量，所以平面附近它几乎不提供抵抗——这正是弹簧系统的软肋。

这跟真实世界里很多物体的表现对不上：比如纸，你想弯它一点，抵抗马上就产生了；而弹簧模型因为拿长度变化来描述弯曲，平面附近抵抗却很弱。那到底该怎么构造“一弯就有”的弯曲抵抗？很直观的思路：可不可以不用长度、用角度？两个三角形之间本来就有一个夹角，那就搞一个模型，让弯曲力直接由这个夹角决定——这就是二面角方法（dihedral angle method）的简单思路。

### 二面角模型：用夹角构造弯曲力

二面角方法把弯曲力写成了二面角的函数。一个二面角涉及四个顶点，所以每个顶点上都有一个力，而每个力都拆成“大小 × 方向”：

$$\mathbf{F}_i = f(\theta)\,\mathbf{u}_i \qquad i = 1,2,3,4$$

关于二面角 $\theta$ 的函数 $f(\theta)$ 告诉你弯曲力的大小；后面的 $\mathbf{u}_i$ 告诉你这个顶点上弯曲力所在的方向——注意，这几个 $\mathbf{u}_i$ 跟力的大小没有关系，只管方向。于是构造这个模型就拆成两个步骤：第一步，确定弯曲力对每个顶点而言分别在什么样的方向上；第二步，搞一个函数，描述力的大小跟二面角有什么样的关系。

#### 第一步：把四个力的方向定下来

这一步是一串假设加推理。

第一个假设很自然：$\mathbf{u}_1$、$\mathbf{u}_2$ 应该分别在两个三角形各自的法向方向上——$\mathbf{u}_1$ 沿 $\mathbf{n}_1$，$\mathbf{u}_2$ 沿 $\mathbf{n}_2$。直观上应该就是这么回事：两个小三角形发生弯曲时，作用在两个端点上的力，就应该沿各自三角形的法向去推。

第二个假设：弯曲原则上不应该导致共享边 3-4 发生形变。弯曲想做的只是把这两个三角形转得更平一点、或者更不平一点，是让它们绕着这条边转，而不是去拉伸这条边。那么作用在顶点 3、4 上的力 $\mathbf{u}_3$、$\mathbf{u}_4$，它们的差——也就是这两个顶点之间的相对作用力——在这条边方向上的分量应该是零。换句话说，$\mathbf{u}_4-\mathbf{u}_3$ 与这条边垂直。

这里插一个几何观察：$\mathbf{n}_1$、$\mathbf{n}_2$ 是两个三角形的法向量，而法向量垂直于自己面内的所有方向，当然也垂直于 3-4 这条边。$\mathbf{u}_4-\mathbf{u}_3$ 垂直于这条边，$\mathbf{n}_1$、$\mathbf{n}_2$ 也垂直于这条边，那么 $\mathbf{u}_4-\mathbf{u}_3$ 就应该是 $\mathbf{n}_1$ 和 $\mathbf{n}_2$ 的线性组合。

第三个假设来自牛顿定律：这些弯曲的力对系统而言全是内力，内力加在一起必须是零，所以

$$\mathbf{u}_1 + \mathbf{u}_2 + \mathbf{u}_3 + \mathbf{u}_4 = \mathbf{0}$$

把 $\mathbf{u}_1$、$\mathbf{u}_2$ 挪到等式右边，就得到 $\mathbf{u}_3+\mathbf{u}_4 = -(\mathbf{u}_1+\mathbf{u}_2)$——而 $\mathbf{u}_1=\mathbf{n}_1$、$\mathbf{u}_2=\mathbf{n}_2$，所以 $\mathbf{u}_3+\mathbf{u}_4$ 也是 $\mathbf{n}_1$、$\mathbf{n}_2$ 的线性组合。一个向量的和与差都是 $\mathbf{n}_1$、$\mathbf{n}_2$ 的线性组合，那它俩自己也必然都是——于是 $\mathbf{u}_3$、$\mathbf{u}_4$ 都落在 $\mathbf{n}_1$、$\mathbf{n}_2$ 张成的平面里。

这一系列假设和推理如果一时搞不清楚也不要紧，重要的是结论。中间的推导我直接跳过，最后推出来的就是 slides 上给的那组公式：$\mathbf{u}_1$ 在 $\mathbf{n}_1$ 的方向，$\mathbf{u}_2$ 在 $\mathbf{n}_2$ 的方向，$\mathbf{u}_3$、$\mathbf{u}_4$ 分别是 $\mathbf{n}_1$ 方向跟 $\mathbf{n}_2$ 方向的一个线性组合，组合系数公式里都给好了。按定义，这四个向量加起来应该等于零——我没验证过，感兴趣的同学可以回头代进去验一下。

> **提示**：这里的 $\mathbf{n}$ 不是严格意义上的法向量，它只是做了个 cross product。cross product 会告诉你三角形 normal 的方向，但要真正得到法向量，还得对这个结果再做一步 normalization。论文里没有做归一化，直接拿 cross product 的结果来用——你可以把它理解成一个比较原始的、没有 normalize 过的 normal。

#### 第二步：把力的大小写成角度的函数

方向定了，接下来定大小。这个公式为什么是这个形式，我不解释，论文里怎么给的我就怎么照搬：力的大小是一个常数系数，乘以边长的平方、除以两个三角形的面积，再乘以

$$\sin\frac{\pi - \theta}{2}$$

顺带说一句，面积这一项就是拿边向量做 cross product 得到的——cross product 的模对应的就是三角形的面积，所以这个量很好算。

先看平面的情况：当 $\theta=180°$ 时，$\sin\frac{\pi-\pi}{2}=0$，力的大小等于零——两个三角形完全放平的时候没有任何弯曲力，这相当于一个静止的情况。这个模型比较好的一个优点，是很容易扩展到非平面的情况：假如我想让这块布静止时本身就不平、有一个初始的二面角 $\theta_0$，那只要在式子里再减去一项 $\sin\frac{\pi-\theta_0}{2}$ 就行，跟前面的公式是同一个形式。

> **定义**：$\theta_0$ 就是静止状态下这两个三角形之间的夹角。平面的情况你可以认为 $\theta_0=180°$，只不过这时那一项恰好为零，公式里就直接把它剔掉了；如果两个三角形静止的时候中间有一个非 180° 的夹角，那就要用 $\theta_0$ 把这个静止角度定义进去。

#### 有力没能量：适合显式，怕隐式

这个模型的缺点也比较明显。回头看我们整个推导的方式：假设力应该是什么方向、什么大小，完全是基于力构造出来的，这里面没有谈到任何关于能量的东西。直接的后果就是：拿它做显式积分会比较容易，做隐式积分就麻烦了——也不是说不能做，但你想要拿这个力模型去求导，会麻烦很多。

虽说如此，这个模型在一些系统里还是比较常见的，用的人也不少。我建议大家有时间把这篇 paper 从头到尾读一下：它是一篇相当经典的 paper，03 年的，里面不只讲了弯曲模型，还讲了自相交是怎么处理的、积分是怎么做的——因为年代比较早，它没有用隐式积分，采用的是比较显式的积分方式。里面还有一些蛮有意思的设计，值得通读。

### 曲率模型：把拉普拉斯写进能量

二面角模型直观——力的方向、大小都算得清清楚楚——但大家后来就想：有没有稍微简单一点、好操作一点的弯曲模型？于是又搞出了一个模型。它还是基于两个相邻三角形的结构，不过先立了两个假设：

第一个假设，两个三角形静止的时候是平面。对布料而言这个问题不大，反正布料静止的时候就是个平面，所以这个假设是 OK 的。第二个假设，模拟的时候三角形基本没有拉伸、没有什么形变，动画效果主要是由弯曲产生的，拉伸非常小。

在这两个假设的基础上，这个模型基于拉普拉斯变换，定义了这么一个能量函数。

#### 能量函数长什么样，又在算什么

整个能量是一个“矢量 × 矩阵 × 矢量”的二次型，前面除以 1/2：

$$E = \frac{1}{2}\,x^{T}\left(\frac{3}{A}\,q\,q^{T}\right)x$$

逐个部件拆开看：

- 矢量 $x$ 很简单，就是把四个顶点按顺序排一遍：每个顶点是三维的，四个顶点排成一个 $12\times1$ 的列向量。
- 小 $q$ 是一个 $12\times3$ 的矩阵，由一堆被缩放过的单位阵构成——每个单位阵都是 $3\times3$ 的，前面各乘一个系数：

```text
        +---------+
        |  c1*I   |      I ：3x3 单位阵
  q  =  |  c2*I   |      c1、c2 为正，c3、c4 为负
        | -c3*I   |      系数由图上标注的几个角算出
        +---------+      （就是 cotangent 权重）
```

$q$ 是 $12\times3$，$q\,q^{T}$ 就是一个 $12\times12$ 的矩阵；左边 $x^{T}$ 是 $1\times12$，右边 $x$ 是 $12\times1$，中间夹个 $12\times12$，乘出来正好是一个数。
- 前面的常数 $\dfrac{3}{A}$ 里，$A$ 是静止状态的面积，直接就能算出来，所以它是个常数。

把这个式子稍微变换一下，它在算什么就清楚了：

$$x^{T}\,q\,q^{T}\,x \;=\; (q^{T}x)^{T}(q^{T}x) \;=\; \lVert q^{T}x \rVert^{2}$$

$q^{T}x$ 这个三维向量，估算的就是这两个三角形的拉普拉斯。拉普拉斯是个什么玩意儿？它告诉你的是两个三角形之间的曲率；平方一下，就把曲率的大小算出来了。于是整个能量的含义就出来了：两个三角形是一个完美平面的时候，曲率是零，$q^{T}x$ 等于零，能量 $E$ 也就等于零；一旦开始弯曲，曲率向量越来越大，能量越来越大，相应产生的力也越来越大。

大家可以直接验证一下：四个顶点在同一个平面上时，按这些权重把贡献叠加，算出来的曲率向量就是零，$E$ 也等于零。这个我留成一个课后的思考题，文末再说。

#### cotangent 权重哪来的？能量是物理的吗？

有同学问：cotangent 权重是怎么出来的？它实际上是从拉普拉斯算子那儿来的。一个三角形网格可以看成一个曲面，而曲面网格的离散拉普拉斯算子，就是由 cotangent 权重拼出来的——所以这些权重是从那儿推出来的。这个推导过程我这里跳过了；而且有意思的是，我印象中那篇论文本身好像也没有给推导过程，就是直接把这些权重给了你。想深究的话可以去看论文；其实你自己也可以验证：假设四个顶点在一个平面上，按这些 cotangent 权重把贡献加起来，确实等于零——这个我之前是验证过的。

那这个能量是物理推出来的吗？其实不是，不能叫物理推出来的——它是根据数学上的曲率推出来的。我们算一个曲面的曲率、尤其是平均曲率的时候，用的就是拉普拉斯这一套，所以这个能量是顺着曲率的定义、按拉普拉斯描述曲面曲率的方式推出来的。如果按更物理的方式，照理说应该根据测量来做：设计一些实验，用实验数据去评估这个能量。这方面也确实有一些研究，但后来做的人不是特别多——我也不知道什么原因，可能一方面测量比较难搞，另一方面误差带来的影响也会比较大。所以一般来说，后来大家基本还是以这种根据曲率搞出来的模型、跟前面那个二面角模型为主。

#### 好在哪：Hessian 是白送的

跟二面角模型比，这个模型有个实打实的优点：它有能量的定义——前面说了，二面角模型压根没有 $E$，这正是它的一个缺点。而且它还有一个更好的优点：注意 $q$ 是一个常数矩阵，跟顶点的位置没有关系，$A$ 也是静止状态算好的常数。既然矩阵是常数，那记 $K=\dfrac{3}{A}qq^{T}$，能量就是一个关于 $x$ 的二次函数——一个标准的二次型 $E=\dfrac{1}{2}x^{T}Kx$。

二次型的好处是：一阶导（力）和 Hessian 都非常容易算。力怎么算？把 $K$ 乘上向量 $x$，前面加个负号就完了；Hessian 更简单，直接就是 $K$ 本身——$K$ 是常数矩阵，事先算出来存着就好。

$$\mathbf{F} = -Kx, \qquad 
abla^{2}E = K$$

它最大的好处就是拿它做隐式积分的时候特别方便：所有跟弯曲有关的这些矩阵、这些力，都特别容易算。

#### 什么时候会失灵

它的缺点也来自那两个假设。第一，如果面料拉伸得很厉害，“拉伸很小”这个假设就不准了——不是说不可以模拟，但它对曲率的描述就变得不太合理，模拟会出问题。第二，静止时两个三角形不是平的怎么办？基本模型假设了静止是平面，不平时也有办法：一个是论文的作者后来又搞的模型，叫 cubic shell——静止状态非平的情况下也能搞能量函数，只不过这个能量函数不再是二次的，而是关于顶点的三次函数了；还有一种方式是我们回头会讲的 projective dynamics，这个模型的论文里其实提到可以用这种方式来处理，这里先不展开。

两个模型放在一起看：

| 对比项 | 二面角模型 | 曲率模型 |
| :--- | :--- | :--- |
| 出发点 | 直接构造力：定方向、定大小 | 从数学上的曲率定义出发构造能量 |
| 能量 | 没有能量定义 | 有，而且是二次型 |
| 力与 Hessian | 求导麻烦 | 力 = -Kx，Hessian 就是 K（常数矩阵） |
| 隐式积分 | 比较麻烦 | 特别方便 |

### 本讲提到的题目

这一讲留了两个“动手验证”性质的小题，都围绕“该等于零的东西是不是真的等于零”。

**题目一：验证二面角模型的四个方向加起来为零。** 把二面角模型 slides 上给出的 $\mathbf{u}_1$、$\mathbf{u}_2$、$\mathbf{u}_3$、$\mathbf{u}_4$ 四个方向公式代入求和，验证 $\mathbf{u}_1+\mathbf{u}_2+\mathbf{u}_3+\mathbf{u}_4=\mathbf{0}$。

解析：推导方向时的第三个假设就是内力合力为零——弯曲力全是内力，所以 $\mathbf{u}_3+\mathbf{u}_4=-(\mathbf{u}_1+\mathbf{u}_2)$，而 $\mathbf{u}_1$、$\mathbf{u}_2$ 分别沿 $\mathbf{n}_1$、$\mathbf{n}_2$。最终的四个公式正是按这组约束推出来的，代进去四个向量应当恰好相消。按定义它就应该等于零，代入验证一遍算是做个检查。

**题目二（课后思考题）：证明共面时曲率能量为零。** 利用 cotangent 权重把四个顶点的贡献叠加起来，证明：当两个三角形完全共面（四个顶点在同一平面上）时，算出来的曲率向量为零，$E=0$。

解析：正文里说过，$q^{T}x$ 估算的是两个三角形之间的拉普拉斯，也就是它们之间的曲率。完全共面意味着两个三角形之间没有任何弯折，曲率本身就是零，所以叠加出来的曲率向量是零向量，能量自然为零。具体做法就是按那组 cotangent 权重（前两块为正、后两块为负）把四个顶点加权求和，共面时各项正好互相抵消——这一步我之前验证过，确实等于零。

## 布料为什么会弯不动：从 Locking Issue 到 PBD
> 对应块：BLK16 | 覆盖分集：P06中1 | 块标题（分集名）：《Lecture 06 Constrained A》

### 开场问答：没有能量也能做隐式积分吗

先接上一轮的尾巴，回答两个问题。

有同学问：没有能量的话，是不是隐式积分就没法做了？还是可以的。隐式积分真正要用的是对力的一阶导数——只要能对力求导，就能拿到需要的东西，并不强求先写出一个能量来。完全可以假设背后有一个力（自然也就等于假设有一个能量），但我们并不真的去计算这个能量，也不管它是什么形式，直接对力求导就行。只不过这么走，推导过程会麻烦很多，而且缺乏一些概念上的定义。

另一个问题：能量的思想能在刚体上模拟吗？一般来说不会。我们这里的能量是什么能量？它其实是弹性能量，也就是势能——做能量的主要目的，就是因为物体有弹性、有势能。刚体没有弹性，那就无所谓能量不能量了，所以刚体一般不太会用到能量的思想。

顺便把前面那篇论文的线索再交代一下：就是前面花了半天讲的那篇研究不可拉伸曲面（inextensible surface）弯曲模型的论文，我个人觉得是一篇蛮经典的 paper。有同学问 cubic shell 模型是什么——它基本上就是顺着这篇 paper 往下走的：同一批作者隔了一年又发的一篇论文，在这个模型的基础上做了一些扩展。感兴趣可以找来读一读，反正是同一个组、同一批人写的。

### Locking issue：拉伸把弯曲锁死

接下来讨论一个我个人觉得在布料模拟里蛮重要的问题，真问题——locking issue。

之前讨论弹簧系统、讨论各种弯曲模型，其实都藏着一个共同假设：布料的拉伸跟弯曲互不影响。那么原则上，一块几乎不能拉伸的布，还能不能自由地弯？现实里这种情况非常多：很多梭织面料没什么弹性，你很难把它拉长，但它照样可以弯。纸张是最典型的例子——很难拉动它，几乎没有弹性，可我们随手就能把它折起来。

#### 两个三角形的弯曲实验

模拟里也能做到这一点吗？拿最简单的网格想一下：一块布，就用两个三角形拼成。

```text
          0 ____________ 1
           |\            |
           | \           |
           |  \          |
           |   \    T1   |
           |    \        |
           | T2  \       |
           |      \      |
           |________\____|
          2            3

     s：两块三角形共享的对角边，
        它同时是一根"完全拉不动"的拉伸弹簧
```

两个三角形 T1、T2 共享对角边 s；s 不只是网格的一条边，它同时是一根拉伸弹簧——而且按我们的假设，这根弹簧非常非常 stiff、非常刚，完全拉不动。

现在考虑两种弯法。第一种，沿中间这条对角线弯：折线正好就是 s 这条边本身，两个三角形绕着它做刚体翻折，弹簧长度一点没变，所以想怎么折就怎么折，非常自由。

第二种，转个 90 度，换一个角度弯，沿着另一条对角线的方向折。这时折线不再是网格里的边，布一折，中间那根弹簧 s 就得跟着变形。而 s 完全拉不动——它会把两个三角形死死顶在那里，再怎么弯也弯不动，整个卡死在那里。

这是一种很奇特的现象：整块布、整件衣服的系统被锁死了，被它自己的弹簧系统锁死。这个现象就叫 locking issue。

> **定义**：Locking Issue——弯曲被拉伸弹簧的弹性所干扰：拉伸的弹性系数很大时，弯曲会受影响，让你觉得这块布好像变得很难弯，而实际上它本身的弯曲属性并没有那么强。

#### 根子：自由度被边吃掉了

被弹簧锁死只是表面现象。本质是什么？本质是自由度的丢失。

根据欧拉公式，对一个 manifold 的三角网格——所谓 manifold，大家就理解成常见的、比较正规的那种三角形网格（每条边最多被两个三角形共享），这里不展开——边的数量满足

$$|E| = 3|V| - 3 - |E_{bd}|$$

其中 $|V|$ 是顶点数，$|E|$ 是所有边的数量，$|E_{bd}|$ 是边界上边的数量，也就是布边缘那一圈。

现在算一笔账。模拟时有多少个变量？每个顶点三个坐标，总共 $3|V|$ 个。约束是什么？所有的边——每条边都是一根弹簧，都是一个约束。真正的自由度，就是变量减去约束：

$$3|V| - |E| = 3|V| - (3|V| - 3 - |E_{bd}|) = 3 + |E_{bd}|$$

所以说，做三角形网格的布料模拟，真正的自由度只有"3 加边界边数"这么多——自由度其实是不够的。而且如果模拟的是一块方方正正的布，自由度会更不够，因为它的边界边数量更少。

课上现场算个小例子：4 个顶点、5 条边，就是刚才那两个三角形。理论上的自由度是 $3 \times 4 = 12$；5 条边就是 5 个约束，减掉，实际自由度是 7。用公式验算：边界边 4 条，$3 + 4 = 7$，对上了。这里顺便排掉一个容易犯迷糊的点：有同学问"弹簧的约束是 12 是什么意思"——12 不是什么特殊的约束数，它就是 4 个顶点乘 3 得到的变量总数。

那 boundary edge 和 inner edge 的区别是什么？boundary edge 就是边缘上的边，inner edge 就是中间的边。还是这 5 条边：外围一圈 4 条是 boundary edge，两块三角形共享的那 1 条是 inner edge。

那布的顶点多一点会不会好？其实并不会——顶点多了，边也会跟着多，约束也就多了。比如在中间加一个点：多了一个顶点，多了 3 个自由度；但同时多了 3 条边、多了 3 个约束，最后自由度还是 7。所以单纯加点没有影响。但分辨率高、顶点排得更密，确实可以改善现象——注意，改善不是因为顶点数量多，而是因为顶点排列得密。

> **易错点**：加点 ≠ 提高分辨率。顶点变多时约束同步变多，自由度一分不变；顶点排得密，缓解的是现象本身，而不是自由度的账。

有同学问，把中间那根弹簧变成两段能不能解决？在当前这个弯法上可能没问题了，但换个方向弯，问题又回来了——比如中间加了点之后，想沿另一条边弯，照样卡死。加点也好、加边也好，都没办法从根本上解决问题，只能临时缓解。

换网格行不行？四边形网格可以一定程度上缓解这个问题，但只要中间又加了对角弹簧，现象还是会回来。有限元其实也有 locking issue，道理是一样的：约束太多，自由度就丧失了。

最后解释一个关键疑问：为什么弯曲会跟弹簧的 k 有关？理论上应该无关——拉伸与弯曲互不影响，这正是我们一开始的假设。会相关，是因为我们模拟时采用了弹簧系统这个数学模型，它会把网格锁死。你看图里那个方向：想沿那条边弯，内部那条边把它顶住，弯不下去。这是弹簧模型本质上自带的缺陷，不是布料本身的问题。

#### 现实中的缓解套路

那实际操作中怎么缓解？有很多各种各样的套路。

套路一：让弹簧压缩的时候弹性系数小一点。既然压不动、弯不动，那我把弹性系数搞小一点，是不是就能把它弯下去了？这是一个套路。

套路二：不要上来就施加弹簧的力。可以先假设这根弹簧在一定长度范围内可以自由活动，没有任何力、没有任何能量——相当于给它留一段松弛区。这也是一个套路。

还有一篇 paper 的思路是：把自由度改一改，不定义在顶点上，而是定义在边上。这样事情会搞得更复杂——把自由度挪到边上，又会引入其他的问题，实际很难用到我们的模拟里。所以我不建议大家花时间去读这篇 paper；在这里提一句，主要是提醒大家存在这个思路。

> **结论**：这些套路都不根本解决问题。目前也没有什么特别完美的解决方式，大家都是调参，或者用比较 hack 的方式绕过去。弹簧很 stiff、网格分辨率又低的时候，locking issue 会特别明显——布弯不下去，因为所有的弹簧都把它撑在那里。做动画、开发游戏时，把某些弹簧的弹性系数调小，可以让问题在视觉上不明显；但要清楚，这个问题始终存在。

本来还想讲一讲拿 shape matching 模拟布料的方式，这部分跳过，感兴趣的话可以回头自己看一下。

### 约束方法要解决什么问题

接下来进入今天的主话题：约束方法。今天讲的这一块内容都跟约束有关。先讲第一个东西——dynamics，也就是马上要讲的 PBD，因为它跟大家马上要做的作业直接相关，作业里会用到；之后有时间，再讲后面两个，比如 projective dynamics。

约束方法想解决什么问题？解决真实世界跟模拟的差异。真实世界里很多面料，对拉伸有比较强的抵抗，你很难拉动它；或者说它一开始比较有弹性，但拉到一定程度就很难再拉动了。可是在布料模拟里，把弹性系数 k 搞大会带来问题：对显式积分而言，会导致显式积分不稳定；对隐式积分而言，会导致系统病态（ill-conditioned）。

这些问题倒不算致命，都可以解决：显式积分可以用小步长，隐式积分可以多迭代。但难点在于，这些解决方式最终都会带来很大的计算量——不管走哪条路，都要花更多计算时间。于是大家自然会想：有没有什么办法，在系数很大的时候还能比较简单、比较好地去模拟？这就是约束方法的初衷。这个初衷不见得能被完美解决，但方向就是这个。

### 单根弹簧：把长度变成约束

#### 约束函数与投影函数

先从最简单的情况讨论起：如果只有一根弹簧，怎么构造这么一个模拟方式？

把这根弹簧的长度写成一个约束。约束本身是一个函数 $C$，实际上就是弹簧当前长度减去它的原长：

$$C(x_i, x_j) = \lVert x_i - x_j \rVert - \ell$$

我们希望 $C = 0$，也就是弹簧的长度刚好等于原长 $\ell$。这时候其实已经不应该叫它弹簧了——它就是一条边。

有了约束，接下来定义投影函数（projection function）。它做的事情是：修改这两个顶点的位置，修改完之后让约束被满足。举两个例子：这条边被拉伸了，两个顶点的距离大于原长，那就把两个顶点互相挪近一点，最终得到两个新位置，它们的距离满足原长的要求；压缩的情况反过来，让两个顶点互相远离，得到的新位置同样满足约束。

#### 在六维空间里看投影

这个问题可以想象成一个投影问题。两个顶点，每人三个坐标，拼起来是六维的；当前这组顶点位置，就是六维空间中的一个点。再把所有满足约束的状态的集合看成一个合理区域 $\Omega$，投影想做的就是：怎么修改顶点位置 $x$，让它落进这个合理区域里。

```text
        * x（当前状态：两个顶点位置拼成的六维点）
        |
        |  希望：挪动量尽量小
        v
  ~~~~~~~~~o~~~~~~~~~   <- Ω 的边界：所有满足 C = 0 的点

     o 就是那个"绿点"：正好落在边界上，
       又是离 x 最近的合法位置
```

光挪进区域还不够：我们还希望挪的变化量足够少——不是随便挪进去，而是要挪到最近的点。

写成数学，这就是一个带约束的优化问题：第一，挪完之后要满足约束，也就是结果落在合理区域内；第二，希望挪的改变量足够小，也就是结果尽量接近原来的位置：

$$\min_{x'} \; \lVert x' - x \rVert \qquad \text{s.t.}\;\; C(x') = 0$$

具体的推导过程这里不讲，感兴趣可以课后推一遍——看看到底是一个什么样的流程能得到这个结果。直观上，这个东西不难理解。

#### 两个前提，推出投影公式

不追推导，也可以从两条很直观的前提把公式"拼"出来。

前提一：质心不变。希望这两个顶点的质心永远待在同样的位置上，这是前提。

前提二：在质心不动的前提下，$i$ 和 $j$ 分别朝着质心、或者远离质心的方向运动——也就是说，它们的运动始终沿着原有这条边的方向；挪动量由两者的相对质量关系决定：质量越大，理论上挪得越少；质量越小，理论上挪得越大。

把这两条摆在一起，稍微解一下，就得到这两个公式（$\ell$ 为原长）：

$$\Delta x_i = -\frac{m_j}{m_i + m_j}\,\bigl(\lVert x_i - x_j \rVert - \ell\bigr)\,\frac{x_i - x_j}{\lVert x_i - x_j \rVert}$$

$$\Delta x_j = +\frac{m_i}{m_i + m_j}\,\bigl(\lVert x_i - x_j \rVert - \ell\bigr)\,\frac{x_i - x_j}{\lVert x_i - x_j \rVert}$$

课后可以做个验证：把两个新位置相减，长度刚好等于原长——说明新的这两个点满足约束；同时 $m_i \Delta x_i + m_j \Delta x_j = 0$，质心纹丝不动；质量大的那个点，分到的挪动量更小。

再说质量。做模拟的时候，很多时候我们对质量其实没有特别强的规定，大家比较偷懒，一般直接假设所有质量都等于 1，或者质量相同。

#### 固定点：质量无穷大，或者干脆不更新

有一种比较极端的情况：这是个固定点，我要把它固定住，怎么做？可以认为这个点的质量是无穷大。质量是无穷大，按公式一看，这个点就静止了，不会动了。当然，实际写代码不可能真把质量写成无穷大，一般来说就是用一个很大的数字去描述。

> **提示**：作业里给的要求比这还简单：直接把这个顶点从更新里去掉——不更新它，它就是固定点，很简单。如果还是想把固定点的处理统一放进模拟流程里，那就用质量无穷大（实际用很大的数）这一招。

### 多根弹簧：Gauss-Seidel 与 Jacobi

一根弹簧会处理了，问题来了：好多根弹簧怎么办？有两个方法。

#### Gauss-Seidel：按顺序一根一根来

第一个方法叫高斯-赛德尔（Gauss-Seidel）方法。这个名字是从线性系统的高斯-赛德尔方法引入过来的，借鉴了那个思想。意思是：假如有好多根弹簧，那就一根一根、按顺序处理过去就完了。

举个例子。两条边，分别连接 0–1 和 1–2，每段原长都是 1，当前长度都是 2：

```text
     初始             处理完 (0,1)        处理完 (1,2)

     x0                  x0                  x0
     |                   |                   |
     |  2                |  1                |  1.75
     |                   |                   |
     x1                  x1                  x1
     |                   |                   |
     |  2                |  2.5              |  1
     |                   |                   |
     x2                  x2                  x2

     两段原长都是 1；处理顺序：先 (0,1)，后 (1,2)
```

每处理一根弹簧，就按"质心不变"把它的两个端点往中间挪，把它改成原长；但这一挪会连累旁边的弹簧。

按顺序来。先处理上面这根：根据质心不变的原理，把 $x_0$、$x_1$ 分别往中间挪，长度变成 1，上面这根弹簧的问题解决了。接下来处理下面这根——注意，它的长度已经变了：本来是 2，刚才那一步把它带成了 2.5。还是按质心不变，把 $x_1$、$x_2$ 往质心挪，挪完之后下面这根也是 1，它的问题也解决了。

然后回过头来会发现什么？上面那根又不满足了。于是再回头处理上面那根，把它搞成 1；再回头处理下面那根，又把它搞成 1……以此类推：对每一根弹簧，按一个特定的顺序处理一遍，每处理一根，就修改与它相连的那两个点，然后再处理下一根。

从头到尾处理一遍，完了还不够，还要多处理几遍——因为光处理一遍，没办法保证所有弹簧的长度都满足约束。处理的遍数越多、迭代数量越多，你会发现弹簧长度慢慢收敛，逐渐往我们想要的原长靠，尽量满足约束条件。

这就是一个蛮简单的套路：搞两个循环。外层是迭代循环，目的是保证所有边都能相对比较好地满足约束；内层循环所有的边，每条边用前面的投影公式把相邻两个顶点 $i$、$j$ 的新位置算出来，直接更新这两个顶点的位置——把更新立即释放、施加出去，然后再处理下一根。

```text
  for 迭代 1..N:                  # 外层：整体多来几遍
      for 每条边，按固定顺序:       # 内层：一根一根处理
          用投影公式算出 i、j 的新位置
          立即写回 x_i、x_j         # 更新马上施加，下一条边接着用
```

话说回来，虽然整体有收敛的趋势，这些边在逐渐地、尽量地靠近原长，但没办法严格保证所有的边都满足约束——永远都会有一些边是不满足的。迭代数量越多，原则上这些约束就能满足得越好。

#### 关于 GS 的两个提醒

第一，它虽然叫高斯-赛德尔，其实并不是真正数学里的高斯-赛德尔，两者有差异。我自己发现，它其实跟随机梯度下降（stochastic gradient descent，SGD）更有关系一点——只不过这个东西不是 stochastic 的，它是有顺序的。

第二，它跟边的顺序有关。顺序会造成两个后果：一是顺序有可能造成 artifact、造成偏向性——你会发现面料有时就是歪向一边、不对称，这跟边的处理顺序有关；二是边的顺序会影响收敛速度——用某种顺序收敛得快一点，换一种顺序就慢一点。

也正因为这些，作业里想让大家尝试的是第二种方法。第一种方法虽然更简单一点，但毛病就在这里。

#### Jacobi：先记账，再取平均

第二种方法叫雅可比（Jacobi）方法。它主要有两个目的：一是减少由于边的顺序造成的影响；二是让这个方法能尽量并行——在 GPU 上，或者在 CPU 上做并行计算，它都是比较合适的选择。Gauss-Seidel 不是不能并行，硬要做也可以，但会复杂很多，得用像着色（coloring）这样的方法把边分类处理，这里就不展开了；Jacobi 并行起来容易得多。

它的思路很简单：每次算出一条边的更新时，不要把这个更新直接施加到顶点位置上，先保存下来，统统存着。这样一来，每个顶点会攒下很多个更新量——因为一个顶点相邻很多条边，每一条边都会告诉它一个更新。把这些全都加在一起，再做取平均的计算，得到一个总的更新，最后一起施加。

具体说：$\Delta x_i$ 并不是真正的新位置，它是一个叠加量，保存的是这个顶点收到的所有更新的和；同时还有一个计数 $N_i$，每收到一个更新就加一。拿到了"和"跟"数量"之后，取一个加权平均，才是这一轮真正施加给顶点的位移。

跟 Gauss-Seidel 一样，迭代次数越多，约束能够满足得越好；而它的好处在于并行起来很容易，也没有 GS 那些由顺序带来的偏向性问题。

| | Gauss-Seidel | Jacobi |
| :--- | :--- | :--- |
| 更新时机 | 每条边算完立即写回顶点位置 | 先攒账，取平均后统一施加 |
| 顺序影响 | 有：带来偏向性 artifact，也影响收敛速度 | 没有 |
| 并行 | 难，硬做要用着色等办法，复杂很多 | 容易，GPU / CPU 都合适 |
| 迭代越多 | 约束满足得越好（但无法严格全满足） | 一样，迭代越多满足得越好 |

### Position Based Dynamics（PBD）

到这里零件都齐了：有了约束，可以定义投影方式；投影不只是为一条边服务的，每条边都能做，而且各有两种方式——Gauss-Seidel 或 Jacobi。基于此，就可以开发我们的算法了。

第一种算法叫 Position Based Dynamics（PBD）。它做了个什么事情？其实就是利用前面讲的这些投影方式，组织出一个算法。

整个算法分两步。第一步，自由活动：先做正常的模拟，做简单的粒子模拟——就像之前做刚体 shape matching 那样（大家做作业的时候做过，很像那个方法），所有东西都可以自由地随便活动，对它们做速度跟位置的更新。这一步是自由活动的步骤。

第二步，施加约束：开始管这些边的长度约束了。先把顶点的位置做一次约束投影——用前面的 Jacobi 或者 Gauss-Seidel 方法对它投影，投影之后得到新的顶点位置，这就是新的位置；接着，利用位置更新的差除以 $\Delta t$，对速度也做了更新；最后，把新的顶点位置赋值给 $x$，把原来的位置覆盖掉。

```text
  PBD 一步的流程

  (1) 自由活动：正常做粒子模拟，外力驱动，
      对所有东西更新速度和位置
  (2) 约束投影：用 Gauss-Seidel / Jacobi 把所有边长
      约束投影到满足 C = 0，得到新位置 p
  (3) 速度更新：v = (p - x) / dt
      位置被投影挪了多少，速度就跟着改多少
  (4) 位置覆盖：x = p
```

一句话读图：先让系统自由跑一步，再把这一步造成的位置违反"掰"回来，最后用位置被挪的量反推速度。

如果大家做过第一次作业的附加题 shape matching，会发现 PBD 的思路跟 shape matching 几乎是一样的。

## PBD 的特性、局限与 Strain Limiting
> 对应块：BLK17 | 覆盖分集：P06下 | 块标题（分集名）：《Lecture 06 Constrained A》

先把上一半的线头接上：约束投影这一套，之前咱们讲刚体的时候，是那些刚体的约束；到这里，就换成了布料、弹簧的这些约束。约束方式上会有些变化，但基本上是一个套路。这一半就专门把 PBD（Position Based Dynamics）这个方法本身掰开看：它有什么特点、好在哪、毛病在哪；然后讲一个把它"放宽"了用的经典套路——strain limiting（应变限制）。

### 先把 PBD 的特点说清楚

#### 弹性从哪来：迭代数量与网格密度

PBD 有个很有意思的特点：你如果拿它来模拟弹性体或者布料，这个方法其实"没什么物理"。咱们正常说物理的时候，会有弹性系数这样的量——不管具体是什么形式，反正会有一些量去描述这个物体到底有没有弹性。做 PBD 的话，这个概念就没有了：自始至终，你看不到任何关于弹性强度（弹性系数）的东西。

那它模拟出来的弹性是由什么体现的？它会受两个东西的影响。

第一个是迭代的数量。迭代数量越多，约束就满足得越好；迭代数量越少，约束满足得就越差。所以迭代数量越少，布料就会感觉很有弹性；迭代数量多，布料看起来就会没有弹性，会很 stiff。

第二个是网格。这个方法跟网格有很大的关系：网格很小、顶点数量很少、没几个三角形的时候，它会很快地收敛——也就意味着同样的迭代次数，它会显得更硬。如果网格很大、顶点数量很多，就意味着你需要更多的迭代才能收敛；反过来说，给你一个固定数量的迭代，网格变大了，这个布就会看起来很有弹性。

| 你调的东西 | 往哪调 | 布料的观感 |
| :--- | :--- | :--- |
| 迭代数量 | 调多 | 约束满足得越好，布越 stiff |
| 迭代数量 | 调少 | 约束满足得越差，布越有弹性 |
| 网格顶点数 | 调多 | 收敛变慢，同样迭代下越有弹性 |
| 网格顶点数 | 调少 | 收敛变快，同样迭代下越 stiff |

做第二次作业的时候大家可以试一试：默认我设的是 $21 \times 21$ 个顶点，你可以把它改成 $11 \times 11$，或者改成 $31 \times 31$，然后用同样的迭代数量，看看结果是什么样子。通过调整网格密度、再加上调整迭代数量，其实就可以调整它的弹性效果——自己去感受一下。

#### 速度更新为什么用叠加

有同学做作业的时候问过速度更新这一块。这个速度更新很重要，因为它会影响到我们做 dynamics 的效果——模拟出来的动态对不对，跟它直接相关。

那为什么这里是叠加，而不是直接赋值？因为我这里的 $x$，是已经前面更新过的 $x$——已经被速度更新过的 $x$。这意味着你做 $x_{\text{new}} - x$ 的时候，这里面其实没有考虑到原有的速度：减出来的只是投影带来的那部分修正量。所以原有速度需要单独给它加上去：

$$v \leftarrow v + \frac{x_{\text{new}} - x}{\Delta t}$$

主要就是因为这个原因。

#### 不止布料：什么约束都能投影

这个方法其实也是一个相对比较通用的方法。我们完全可以做其他的约束——比如三角形的约束、体积的约束、碰撞的约束——其实都是可以用类似的方法去处理的，这里就不一一展开了。套路是共通的：对于不同的约束，比如体积约束，后面会讲——先给它搞一个约束的函数，有了这个函数之后，就可以做投影。

### PBD 的优点：简单、通用、好并行

先说优点。第一，它很容易并行。NVIDIA 的 physics engine、还有 NVIDIA 游戏里面很常用的 NvCloth 这种引擎，本质上都是基于 PBD 的；游戏里用到的那些布料引擎，很多都是基于这种约束方法、这种 PBD 方法。所以可以看到，这种方法用得还是很广泛的。

用得广还有一个原因：它本质上容易实现。你只要定义了约束，去搞一个类似这样的约束函数，就可以模拟了——你不需要去纠结隐式积分，你看它根本就没有隐式积分的概念，对吧？也没有什么合成力的概念，就是特别简单。而且它的通用性也比较强：很多时候你可以不只是拿它做布料的模拟、弹性体的模拟，甚至流体的模拟都可以用类似的方式去解，所以它很强。

效率上我应该这么讲：分辨率比较低的时候，它是比较有效率的、比较快的。那分辨率多低呢？拿我们在处理的网格来说，不到 1000 个顶点的网格，你还是可以以比较实时的效率去模拟的；但是超过 1000 个点，就会明显下降。

### PBD 的缺点：没有精确解，分辨率越高越吃亏

接下来讲它的缺点。第一个缺点就是它没有什么物理含义。整个弹性的表现会受网格的影响，也会受迭代数量的影响——这个其实是不太合理的。为什么？因为我们正常去描述一个物理现象的话，模拟的结果应该跟网格是没有关系的；而且理论上，随着你的网格越密，你应该会收敛到某一个精确的结果。对 PBD 而言，它就没有一个所谓的精确结果。因为如果你真的让迭代数量多到无穷多，会发生什么？会发生所有的边都没有任何拉伸——那反而会导致 locking issue，对不对？你本质上是不希望有 locking 的。所以说，它没有一个精确解。

还有一个点：当分辨率提高的时候，高分辨率下它的收敛性会明显下降，而且下降得非常明显。你就会发现 $11 \times 11$ 跟 $21 \times 21$ 跑出来的差距，其实就已经比较明显了。

有同学问：用高阶的积分方式能不能提升 PBD 的效率？我倒是不知道有什么高阶的方式。这个东西它没有所谓高阶不高阶——因为它本质上直接就是更新顶点的位置，没有物理含义，你甚至都没有办法用积分的方式去解释它，那用高阶的东西就更没办法讲了。

提升效率这一块，大家其实研究了一些方法。比如你可以去构造一个 hierarchy（层级网格）：先构造一个低分辨率的网格跟一个高分辨率的网格，先模拟低分辨率，然后把低分辨率的结果传到高分辨率上再去模拟，再到更高分辨率——类似层层模拟的方式，从低分辨率逐步模拟到高分辨率。这种方式可以做，但是对 PBD 而言会导致其他问题，比如说会导致一些抖动的问题，这个我就不展开了。我自己也做过一些，反正可以做，但这条路其实也不见得特别理想。

所以 PBD 我认为——这是我的感受——它比较适合低分辨率。游戏开发里面很多衣服的网格都是特别简单的网格，就比较适合用 PBD 的方法；想上到 1000 个顶点以上，可能就没有那么合适了，它的效率会相对来说比较弱。

给大家一个课后阅读：Matthias Müller 在 2008 年的一篇 paper，叫 Hierarchical PBD。他当时是在 NVIDIA 的，所以你也可以看到 NVIDIA 的很多物理引擎基本上都是基于 PBD 的；还有流体的 PBD 等等、各种各样的 PBD——基于这个方法，是一个比较常见的低精度、实时模拟的套路。

### Strain Limiting：把投影降级成纠错步骤

PBD 存在缺乏物理含义的问题，所以大家就在想：我可不可以不让这些投影方式、约束方式负担那么重？还是做物理模拟——比如我用隐式积分，或者做有限元模拟，用正常套路——我只是加入一步，专门用来防止大形变，让模拟更稳定一点。如果是出于这个目的，利用我们讨论的这个 projection 方法来做一些事情——这种方式，大家给它取了个名字，叫 strain limiting。

不过这里要自我纠正一下：我刚才这个描述其实并不是很准确。因为从历史上来讲，strain limiting 被发现的其实比 PBD 还要早——整个思想在 1995 年的时候就有了（Provot 那篇很早的 paper），而 PBD 到了差不多 2000 年前后才出现。所以你可以认为 strain limiting 实际上是 PBD 的一个"改进版"——只是历史顺序是反过来的：先有 strain limiting，后有 PBD。

它的结构跟 PBD 很像，也是把模拟分成两个步骤：第一个步骤做模拟，第二个步骤做投影。区别在于：做 strain limiting 的时候，你的第一个步骤不是简单地做一个粒子系统，而是做正常的模拟——比如我可以做正常的弹簧系统，做隐式积分，或者有些人做有限元，其实都是可以做的。而后面那个投影部分，其实只是做一个纠错的步骤：并不是说我要依赖后面这些投影的东西来做动画效果，后面这部分仅仅是为了满足一个目的——保证这个模拟稳定。

```text
PBD            ：  预测位置 ──► 约束投影(反复迭代) ──► 速度更新
                     动画效果完全由"投影"这一步承担

Strain Limiting：  第一步 正常物理模拟 ──► 第二步 投影纠错
                     (弹簧系统 + 隐式积分/有限元,   (把形变限制在允许范围内,
                      动画效果由它负责)              不负责动画效果, 只保稳定)
```

读图：两者的骨架相同，都是"模拟 + 投影"；差别在投影的地位——PBD 里投影是主角，strain limiting 里投影只是兜底的纠错。

### 弹簧上的投影函数：拉伸比例与应变

还是用弹簧来举这个例子。一根弹簧的原长是 $l$，我可以定义一个变量叫做 stretching ratio（拉伸比例）：当前长度除以原长，

$$\sigma = \frac{\lVert x_i - x_j \rVert}{l}$$

我的要求是：这个拉伸比例必须落在一定范围内——弹簧不能拉伸超过一定幅度，也不能压缩超过一定幅度。$\sigma_{\max}$ 和 $\sigma_{\min}$ 就分别是它最大和最小的拉伸比例：

$$\sigma_{\min} \le \sigma \le \sigma_{\max}$$

有了约束，接下来我希望构造我的投影函数。它跟我们之前的那个投影函数非常像，区别在于：投影之后的新位置，不是严格地让长度等于原长，而是我把要求放宽了——只要求长度满足约束的范围就够了。所以拉伸的时候，我还是希望两个顶点靠近一点，但是不要求靠近到原长的程度，只要求靠近到满足比例；压缩也一样，我希望这两个顶点远离一点，但也不要求它远离到原长，只要求远离到满足比例的程度就够了。大家可以发现，这个实际上就是放宽了的 PBD——我把约束给放宽了，把我的目标也放宽了。

投影函数具体怎么定义？先计算当前的拉伸比 $\sigma = \lVert x_i - x_j \rVert / l$，然后计算目标拉伸比：把这个拉伸比用 $\sigma_{\min}$ 和 $\sigma_{\max}$ 约束一下，把它夹进这个范围内——限制完之后的拉伸比，就是我想要得到的拉伸比：

$$\hat{\sigma} = \mathrm{clamp}\left(\sigma,\ \sigma_{\min},\ \sigma_{\max}\right)$$

有了目标拉伸比，我就把原来的原长 $l$ 替换掉：我想要的长度不再是 $l$，而是 $\hat{\sigma}\, l$。把它代到原来的投影公式里面，就得到了两个端点最终的新位置。

那这个跟 strain 有什么关系？拉伸比例减一，就叫做 strain（应变）——strain 就是描述形变的一个量。所以我们这里把它叫做 strain limiting 方法：限制的就是这个形变量。

> **定义**：$\mathrm{strain} = \sigma - 1$，衡量弹簧偏离原长的程度，是描述形变大小的基本量。把 $\sigma$ 限制在 $[\sigma_{\min}, \sigma_{\max}]$ 内，本质上就是在限制 strain——方法的名字就是这么来的。

有同学问这个是一维的吗？strain 可以是一维的，也可以是二维的、三维的。对弹簧而言，它的 strain 是一维的；我们回头讲有限元、讲到三角形和四面体的时候，就是二维和三维的了。这里先不讲那么多，就把它当一个一维的量。

两个边界情况值得记一下：

> **易错点**：$\sigma$ 永远等于一（$\sigma_{\min} = \sigma_{\max} = 1$）的情况，就是 PBD 的方法——PBD 可以认为是 strain limiting 的一个特例；反过来，如果你不想要做任何约束，把下界压到 0、上界放到正无穷就行了。

那限制拉伸是为了什么？它其实有不同的目的。一个是模拟很多面料的物理表现——很多面料拉伸到一定程度就会变得很 stiff；另一个是数值上的：很多时候形变大的时候，模拟会不太稳定——比如我们做有限元的时候，有很多数学模型在形变量很大的时候会变得很不稳定，会有抖动，甚至直接炸掉。用 strain limiting 把拉伸限制住，可以让模拟更稳定一点。所以它直接的目的是限制拉伸比的范围；背后的动机，你可以认为是面料本身的物理属性就有这样的表现，也可以认为是模拟过程中存在稳定性问题、需要算法上让它更稳一点——都是有可能存在的。

### 三角形面积约束：挪得少，还要满足面积

前面讲的约束都作用在边上，其实还有别的对象可以约束。比如我有一个三角形，它的面积是 $A$，我希望三角形的面积落在某个范围内。什么时候会想要这个？比如你不希望这个三角形被压扁——那么除了对这个三角形的边长有约束以外，同样也可以对它的面积进行一定的约束。

数学模型还是老套路：我希望挪动这三个顶点——三个顶点都尽量挪得足够少，同时满足面积约束。

实际过程中你会发现，这个操作非常简单。当三角形的面积大于或者小于给定范围时，我给它计算一个缩放量，把这个三角形缩放一下就行了。缩放量怎么算？把面积投影（夹）到允许范围内，得到想要的面积，再除以当前的面积，开个根号：

$$s = \sqrt{\frac{A_{\text{target}}}{A}}, \qquad A_{\text{target}} = \mathrm{clamp}\left(A,\ A_{\min},\ A_{\max}\right)$$

> **提示**：为什么要开根号？面积是长度的平方量——长度缩放 $s$ 倍，面积就变成 $s^2$ 倍。所以从"想要的面积 ÷ 当前的面积"反推长度缩放比，必须开根号；开完根号，$s$ 才是这个三角形应该缩放的比例。

剩下的步骤就很直接了。首先把三角形的质心算出来——因为我在做缩放的时候，希望它的质心是不变的。质心算出来之后，对每一个顶点：质心不变，质心加上顶点到质心的向量，按比例 $s$ 缩放，

$$x_i' = c + s\,(x_i - c)$$

分别对 $i$、$j$、$k$ 三个顶点做缩放，得到新的点的位置——这样我就得到了理想的三角形面积了。就是这么一个思路。

质心为什么必须不变？这里有两层解释。数学上，质心不变对应的是"顶点运动最少"的要求——我们希望所有顶点的移动量是最少的。物理上讲，质心不变意味着没有新的动量——你不希望这个物体被约束了以后，自己就开始做奇奇怪怪的运动；我希望它永远是在本地进行这么一个变形、约束。而且如果你根据数学公式去推，会发现这两者是等价的——质心不变跟顶点移动最少，其实就是一回事。我为了备这个课，自己也推了一下，发现确实是如此；你也可以回头推一遍验证。

### Strain limiting 到底有什么用

它的用处有两个，另外还能顺带缓解一个老问题。

第一是稳定性的问题。strain limiting 可以保证不发生大形变——我们的模拟中不会产生大形变；没有大形变，也就意味着整个模拟会更稳定一点，我们的 artifact（视觉瑕疵）也会更少。这是一个原因。

第二是模拟非线性的材质表现。很多布料都有这样的表现：一开始的时候它比较没有弹性，基本上不怎么抵抗拉伸；但是拉伸到一定程度之后，抵抗会迅速地增长，变得很大。这种非线性的表现，我们可以利用 strain limiting 来模拟。怎么模拟？把整个过程分成两个阶段：第一个阶段，如果拉伸量比较小，我就做正常的物理模拟；第二个阶段，如果拉伸量比较大，我就做 strain limiting。这也是做物理模拟的时候一个比较常见的套路。

这里多说一句"要不要大形变"的选型。刚才说大形变交给 strain limiting，主要是因为大形变的时候做物理模拟会有稳定性问题。但如果你的目的就是模拟史莱姆——大家玩过史莱姆吗？就是那种特别能拉伸的东西——那你确实需要大形变，就不需要做 strain limiting。而很多时候你想模拟的是肌肉：肌肉其实很少有很大的拉伸形变，这种情况下你就可以考虑做 strain limiting。

第三，strain limiting 可以帮助解决 locking issue。为什么？因为当我把整个模拟分成两个阶段之后，前面这个阶段我可以用比较小的弹性系数——弹性系数比较小的时候，弹簧是可以比较自由地弯曲的。本质上就相当于我可以把弹性系数 $k$ 给弄小了；把 $k$ 弄小了以后，locking issue 也就会变得不那么明显。

最后交代一下出处：这就是 1995 年 Provot 那篇很早的 paper。这篇我不太建议大家读——太老了，而且思想特别简单，课上讲的这些基本上就是这篇 paper 讲的思想；不过它比较经典，大家有时间的话，可以去读一读 95 年的这篇 paper 是怎么来描述这个问题的。

### 课堂问答

**作业二现在能做了吗？** 目前的内容已经可以做作业二了。作业二其实就是两块：一块是隐式积分，上周讲了；还有一块是 PBD，今天也讲了——都是可以做的。你只要完成其中一个，就算这个作业完成了；如果把两个都做完，就算是把附加题也完成了。框架本身有能力的话可以随便改，我看到有同学连纹理都换了。批改之后会告诉大家分数、哪里做得不对；想看正确答案的话，大概一周之后可以找助教要。

**PBD 中怎么控制刚度？** 就靠前面讲的两个因素：迭代数量和网格密度。网格密度一般来说你没法改，所以实际就是用迭代数量来控制——让迭代多一点或者少一点，这样来调节刚度。

**PBD 中"质量大位移小"有什么物理含义？** 这个跟物理里面力的相互作用、力的物理含义是一样的。你可以这么想：假如我有一根弹簧，连接了两个物体，两个物体质量不一样；弹簧连着这两个物体，力的大小是一样的，而两个物体获得的位移等于力除以质量——质量越大，位移就越小。PBD 里按质量分配修正量，含义就是这个。不过要说物理含义，它关于弹性的那一块真的没有什么物理含义；原作者尽量想把它搞得有物理含义一点，但我觉得在实际操作里，搞那么有物理含义，差别也不是很大。

**不同的约束可以用不同的迭代数量吗？** 得所有的都是同样的迭代数量，每一轮把所有的点都过一遍。

**用迭代数量控制 stiffness 有点玄学？** 确实。它就是没有物理含义，所以调参完全是肉眼去看——你觉得这个效果不太好，就给它系数再调一调。

**PBD 考虑塑性吗？** 做塑性的研究比较少。之前有一篇做内部摩擦力的，我记得印象中也就那一篇论文；具体做塑性的论文还是比较少的。

**用隐式积分做布料和球的碰撞是怎么做的？** 作业里做球的碰撞是作为后期处理（post-processing）的：碰撞不放在隐式积分里面——你可以认为隐式积分就只是更新布料，根据布料本身弹簧的力来更新点的位置；更新完了之后，再做碰撞处理。布料本质上就是有很多点构成的，所以作业里用的是粒子的碰撞处理方式，用 SDF（signed distance function）来判断。

```text
隐式积分更新布料 ──► SDF 判断顶点是否进入球 ──► 把进入球的顶点直接推出球面
(只管布料自身弹簧)     (碰撞被当成一种"投影")       (impulse based method)
```

读图：碰撞不掺在积分里，而是排在积分之后的一步独立"投影"。

那顶点具体怎么更新？你可以做得简单一点：不做任何摩擦力，直接把这个顶点从球里面推出来就行了——直接对顶点做一个 impulse based method。你要做 penalty 也可以，但直接用 impulse 把它推出来就可以了。

**科研里一般用什么渲染？** 一般来说不用 Unity，用 OpenGL、GLSL 写 shader 的比较多一点——GL 比较简单。如果说你要做后期渲染、在论文里想要一个比较好的效果，一般就会用一些离线渲染器——Mitsuba，或者 Maya 里面的 V-Ray，都挺常见。

**locking issue 那里，中间是压缩而不是真的弯曲？** 对。因为本质上就是中间那根弹簧没有办法真的弯曲——它只是一根线，只能拉伸或压缩；弯曲的时候中间必须压缩，而约束又不让它压缩，那我整个就弯不下去了，对不对？这就是 locking issue 的来源。

**多个约束一起求解的优化呢？** 前面说的高斯-赛德尔（Gauss-Seidel），其实也算是一种把多个约束放在一起求解的方式。

**那个 α 是怎么算出来的？** 不是算出来的，是调参调出来的。作业里我会给你这个参数——好像是 0.2 吧，反正你可以试试不同的参数。

**有没有办法一步把好几个约束都满足？** 我感觉做不到，因为数学还没有这个能力。这些都是非线性的约束，而非线性约束本质上是一个非线性优化问题——目前还没有什么方法能够一步就把所有的非线性约束都满足，咱们的数学家还不够牛逼。

这话可以展开说说。你看为什么我们线性问题研究那么多？线性代数是数学科要学的，然后解线性系统——就是因为线性问题是容易的，非线性问题是难的：线性问题可以一步解出来，而非线性是不能一步解出来的。那非线性怎么解？套路就是把所有的非线性问题都用线性的问题去近似一下，然后用线性的方法去解——这就是我们所有非线性优化问题的套路。大家解决问题的时候，永远都是想用知道的方法去解决不知道的问题嘛，就一个套路。

说个题外的感受：非线性优化听起来很复杂，反而我认为是我学过的很多数学里面最容易的一个数学。为什么？因为非线性太难了，数学家其实也没怎么搞明白；数学没怎么搞明白的结果，就是它的很多方法其实都特别简单。反过来，数学家已经研究得很深、搞得特别明白的那种数学，反而会很难——因为研究得深，你就没法搞明白了。其实就是这么回事。

今天就先到这里。有同学提到，感觉 projection、约束好像跟能量挺有关系的——没错，我们下次就会讲这个方法：Projective Dynamics，把投影的方式跟我们之前那种物理模拟结合起来，今天时间不够就不展开了。下周我们会接着 constraint 这一块往下讲，讲两个比 strain limiting 更高级一点、但可能也会更复杂一点的方法；后面就是有点科普性质为主了，大家如果听不懂的话，就跟着后面的 paper 读，看看能不能理解一下。之所以要讲后面那两个高级方法，主要也是因为有些地方确实会用到，给大家科普一下、给大家一个参考——但算法还是要复杂很多的。

## 把约束用出新花样：Projective Dynamics 与 Constrained Dynamics
> 对应块：BLK18 | 覆盖分集：P07上 | 块标题（分集名）：《Lecture 07 Other Constra》

开讲前先交代两件事。一是回答同学的问题：作业用其他引擎交、甚至用自己写的引擎交，都可以——我已经看到有同学拿自己写的引擎做了作业。二是课程计划要调一调：原定今天讲碰撞，但今天讲肯定讲不完，还会挤占下一次课；而下一次课要讲有限元，下次作业也是关于有限元的，万一有限元讲不完就会影响大家做作业。所以把碰撞往后挪，今天先把上周约束剩下的尾巴讲完，然后开始上有限元——这一周和下周都会围着有限元转，之后再讲碰撞。

言归正传。上周我们讲了用约束来模拟衣服、面料这一类物体的方法：PBD（Position Based Dynamics，基于位置的动力学），还有 strain limiting。PBD 好用，但有个绕不开的毛病：这种模拟方式**没有什么物理含义**。所以今天讨论另一条路：还是用约束，但整个模拟引擎的搭法，跟 PBD 那种"直接拿约束修改顶点位置"的方式要有一些不一样的点。这一块我觉得内容上可能会有一点超前，所以当作科普来讲——很多新技术、新引擎多多少少都会用到这些方法，今天把几个简单的方法给大家过一遍。前半部分讲方法，后半部分开始讨论有限元，今天能讲多少算多少。

### Projective Dynamics：投影不拿去改位置，拿去定义能量

第一个方法叫 Projective Dynamics。它跟我们上周用约束做 PBD 的方式有很多相同点，不同点也很明显，就体现在**拿约束来干什么**这件事上。上周讲 PBD 和 strain limiting 的时候，我们有了约束，也根据约束定义了一些投影方式——投影一下就能满足约束。PBD 的做法，是拿这些投影**直接修改顶点位置**。Projective Dynamics 说：我不要拿这些投影去改位置，我要**拿它去定义一个能量**。

举个最简单的例子。比如我现在有一个网格，上面有五条边。对其中一条边 $e$——连着顶点 $i$ 和 $j$，原长是 $l_e$——我定义这么一个能量函数：

$$E_e=\frac{k}{2}\left\|x_i-x_j-\left(x_i^{\text{new}}-x_j^{\text{new}}\right)\right\|^2$$

里面的 $x_i^{\text{new}}$、$x_j^{\text{new}}$，分别是投影之后、按约束更新出来的两个新顶点位置。注意，我不拿它们直接去修改顶点位置，只是把它们算出来，拿来构造这个函数——它们是**中间变量**。网格上有几条边，我就分别定义几个这样的能量项，合起来就是整个系统的能量。

```text
PBD：  约束投影 ──> 直接改写顶点位置（没有能量、没有力）

PD ：  约束投影 ──> 投影后的新位置（只是中间变量，不写回顶点）
                   ──> 定义能量 E ──> 求力、求 Hessian ──> 隐式积分
```

读图：两条路用的约束和投影函数完全一样，分岔点只在投影结果怎么用——PBD 把它当"答案"直接写回顶点，PD 把它当"素材"拿去构造能量。

### 化简能量：绕一大圈，回到弹簧

这个能量函数到底是个什么东西？我们把投影的性质代进去检查一下。

投影保证了什么？上周讲过：对一条边做投影，两个顶点是**沿着这条边自己的方向**挪动的，只不过挪近一点或者挪远一点，方向始终不变。所以投影完成之后，新边的长度应该正好等于原长 $l_e$，方向仍然沿 $x_i-x_j$：

$$x_i^{\text{new}}-x_j^{\text{new}}=l_e\,\frac{x_i-x_j}{\|x_i-x_j\|}$$

把它代回能量。把 $x_i-x_j$ 写成"当前长度 × 单位方向"，括号里就能提出一个公因子——单位方向向量：

$$(x_i-x_j)-l_e\,\frac{x_i-x_j}{\|x_i-x_j\|}=\left(\|x_i-x_j\|-l_e\right)\frac{x_i-x_j}{\|x_i-x_j\|}$$

取模的时候，单位方向向量的长度是 1，直接消掉，整个能量就变成了"长度减去原长的平方"：

$$E_e=\frac{k}{2}\left(\|x_i-x_j\|-l_e\right)^2$$

推导里"同乘长度、提出单位向量"这一步，大家回去把公式整理一遍，自己体会一下。整理完你会发现：**它跟弹簧的能量一模一样**。也就是说，我们绕了一大圈——搞约束、搞投影函数、引入中间变量——最后造出来的能量函数，跟弹簧的能量函数是一模一样的，只不过把投影算出来的两个新顶点位置当成了中间结果。

> **结论**：Projective Dynamics 的每条边能量，化简后就是弹簧能量 $\frac{k}{2}(\|x_i-x_j\|-l_e)^2$。

### 求力：又回到弹簧力

有了能量，力按定义来：$f_i=-\dfrac{\partial E}{\partial x_i}$，负能量梯度。

这里我做一个**大胆的假设**：把 $x_i^{\text{new}}-x_j^{\text{new}}$ 这一项当作**常数**，跟 $x$ 无关，先不管它。为什么要这么做、这个假设有什么问题，后面专门讨论。先看后果：括号里真正含 $x$ 的只剩前面那段，整个能量成了关于顶点位置的二次函数，求导是初级微积分——

$$f_i=-k\left((x_i-x_j)-\left(x_i^{\text{new}}-x_j^{\text{new}}\right)\right)$$

（$k$ 来自对二次函数求导，负号来自力的定义，不用管它。）再把投影性质代进去，把单位方向乘开、合并同向的项，得到：

$$f_i=-k\left(\|x_i-x_j\|-l_e\right)\frac{x_i-x_j}{\|x_i-x_j\|}$$

长度减原长，乘以方向——这就是**弹簧力**。这两步等价变形要是当场没跟上，回去慢慢推一下就行，两条式子是严格等价的。

所以你看，绕了一大圈：能量跟弹簧能量一样，对 $x$ 求导算出来的力跟弹簧力也一样。整个 Projective Dynamics 模型，跟正常模拟弹簧系统的能量、力**一模一样**，无非是引入了两个由投影算出来的中间变量，再拿它们构造出新的力和新的能量——结果跟正儿八经的弹簧一模一样。

### 真正的差别在 Hessian

那有同学就要问了：既然能量、力都跟弹簧系统一样，我何必多此一举，非要用中间结果去构造这一套？原因在于：**Hessian（黑塞矩阵，能量对位置的二阶导数）会不一样**。

用一个简单直观的例子来看：四颗顶点、五根弹簧。

```text
        0
       /|\
      / | \
     1  |  3
      \ | /
       \|/
        2
```

图里五条边是 0–1、0–2、0–3、1–2、2–3，为了好指认，分别记作绿、蓝、橙、黄、紫；每个顶点引出几条线，它就出现在几个能量项里——0 号顶点的力，就是绿、蓝、橙三个部分的和。

先看力。总能量是关于顶点位置的二次函数，所以求导很容易：求导时把括号外面的 2 消掉，把括号里的部分照抄下来；前面按定义补个负号，相当于把括号里前后两半换了个位置——这就形成了力的形式，没什么稀奇的。

真正特殊的是**矩阵**。Hessian 是能量对顶点位置的二次导数，这里用的假设跟求力时一样：所有带 new 的项——投影出来的新位置——都当成跟 $x$ 无关的常数。于是整个能量是关于 $x_0,x_1,x_2,x_3$ 的二次函数，Hessian 就变得非常简单，从图上直接就能读出来：

- **对角块数边**：每个顶点邻几条边，对角块就是几倍的 $kI$。0 号邻三条边（绿、蓝、橙），是 $3kI$；1 号邻两条（绿、黄），是 $2kI$；2 号邻三条（蓝、黄、紫），是 $3kI$；3 号邻两条（橙、紫），是 $2kI$。
- **非对角块存边**：绿边连着 0 和 1，那 $(0,1)$ 和 $(1,0)$ 的位置就放 $-kI$；蓝边连 0 和 2，对应位置放 $-kI$；没有边相连的位置就是零。

按拓扑把图翻译成矩阵：

$$H=\begin{pmatrix}3kI & -kI & -kI & -kI\\ -kI & 2kI & -kI & 0\\ -kI & -kI & 3kI & -kI\\ -kI & 0 & -kI & 2kI\end{pmatrix}$$

而且这个矩阵，跟把能量对顶点求二次导数算出来的结果是一样的——用的就是同一个假设。关键在于：它**不随顶点位置变化**，是个常数矩阵。

> **结论**：Projective Dynamics 绕一大圈的根本目的，就是利用"投影项是常数"这个假设，把能量变成顶点位置的二次函数，从而构造出一个**常数 Hessian 矩阵**。

> **易错点**：同一个顶点在不同边上的投影位置是不同的。0 号顶点连着三条边，就有三个不同的投影后位置，分别对应三条边——每个顶点对每条边都有自己的投影位置。（例子里我这些下标写得比较乱，大家回头有时间仔细看一下，大概能理解就行。）

### 常数矩阵值在哪：分解一次，一劳永逸

有了常数 Hessian，剩下的部分就跟正常做隐式积分的模拟方式一样了：质量矩阵、Hessian 矩阵，该解线性系统就解线性系统。无非前面多了一步——先算投影，再根据投影算力。这一步其实都不影响：弹簧系统里，投影算出来的力跟弹簧公式算出来的力相同，直接用弹簧公式算力完全可以，弹簧系统甚至不需要做任何投影；但有的东西必须投影，比如 Shape Matching——它没办法像弹簧那样直接算出一个力，所以得有投影那一步。其他环节跟隐式积分没有区别。你可以直接这样理解：我做隐式积分，只不过偷个懒，不直接去算真的 Hessian，而是用一个简单的方法去**估算**它，并且假设它是常数矩阵，于是整个东西就简单下来了。

那为什么非要把 Hessian 弄成常数？因为矩阵是常数，就可以用**直接法**去解。回忆第二节课讲的线性系统：用 LU 分解或者 Cholesky 分解去解 $Ax=b$，计算量的大头在**分解**上——先把矩阵拆成下三角和上三角，之后再分别对 L、U 做代入求解（前代、回代）。分解这一步贵，代入便宜。

模拟的时候矩阵每步都在变，直接法就得每步重新分解，非常贵；而 Projective Dynamics 的 Hessian 是常数——**只需要分解一次**，之后整个模拟都复用这次分解的结果，每步只做代入求解，整个模拟就能很快地跑起来。这就是 Projective Dynamics 这个方法被推出来的主要原因：最终目的就是搞一个常数矩阵，分解一次，一劳永逸地简单求解。

### 假 Hessian 为什么也能收敛

这里回应一个更普遍的疑问。正儿八经的牛顿法，需要真正的弹簧系统 Hessian——这是"正经"的做法。那为什么我不用真正的 Hessian，用各种各样"假"的，方法也能 work？这样的例子我们已经见了不少：

- 上上周讲过对 Hessian 做修改，**强制把它变成正定矩阵**——当时没细谈，有同学问这为什么也能收敛；
- 作业里是另一个新方法：干脆不做 Hessian 计算，直接给大家一个公式——一个"魔法公式"——拿它去算 $\Delta x$，居然也 work；
- 刚才的 Projective Dynamics，用一个常数矩阵去解，也 work。

注意用词：这些是**近似**，不是简化。事实上它们是一整套相通的方法，到讲有限元最后一天，我会专门谈它们为什么 work。简单的说：**不需要严格计算 Hessian，可以做各种近似；只要近似是合理的、是正定的，就能保证收敛**。收敛得好不好，取决于近似得像不像：跟真 Hessian 长得像，收敛就更好、更快；近似得完全风马牛不相及，效率就低。极端情况——连 Hessian 都不要，直接拿一个单位矩阵（identity matrix）当 Hessian——也能收敛，只不过效率很低。这一条先给大家提一笔，回头我们再进一步分析。

> **提示**：牛顿法这类解法对 Hessian 的要求其实是"正定"而不是"精确"——合理的正定近似保证收敛，近似质量只影响收敛快慢。

顺着这个话题，有同学问有限元那边的 Hessian 怎么算：下下周讲有限元的时候会谈到，那个东西确实挺复杂，到时候多半也是带大家过一遍它的意思，算个科普。

### 真正的时间开销在内存访问

回答另一个问题：PBD 和 Projective Dynamics 在游戏里用得多吗？游戏里做模拟，一般还是 PBD 为主；而且游戏里用得更多的其实是骨骼动画——通常模拟的是一件穿在人身上的衣服，用人体骨骼去驱动它，做成一种混合式的方案：一半的运动由人体骨骼带来，另一半用类似 PBD 的方式处理。游戏里 PBD 怎么用，其实还有蛮多细节，这里没时间展开。

这里有一点值得单独说，因为它跟直觉相反：**很多模拟方式其实都不是计算为主的**。听着奇怪——我们这一大堆公式难道不算计算吗？事实上，这些计算公式对当代的 GPU、CPU 来说占不了多少时间，真正的时间开销在**内存访问**上：每一次迭代都要去访问顶点位置，大量时间花在访问 main memory 或 GPU 的 global memory 上，计算过程本身反而很快。

从这个角度看 PBD：它最大的优点根本不是精准，而是**内存访问非常少**。它没有什么物理变量，连速度都可以暂时忽略不计，唯一需要访问的信息就是顶点位置。而其他方法——Projective Dynamics 也好、别的方式也好——总有一些别的物理变量要访问，内存开销自然就更大。所以真要追求非常非常高的性能，功夫应该花在优化内存访问上——怎么让内存访问得更连续——而不是简单地去调整计算方式；调计算带来的提升很少，真正的提升主要在内存访问上。这里面是个蛮大的学问，咱们这门课就不往下深讲了。

### 收敛曲线与优缺点

下面看 Projective Dynamics 的优缺点。先看一张从 Projective Dynamics 那篇 paper 里抠出来的图：蓝色和绿色是牛顿法，分别用两种不同的方式求解——蓝色是 Cholesky 分解，也就是解线性系统的直接法；绿色是 PCG，一种迭代法。红色是 Projective Dynamics。收敛曲线的形态是这样的：Projective Dynamics 一开始非常快——头上那一段特别快——但之后就比不过牛顿法了；再往后，如果精度要求很高，它的收敛还会逐渐放缓。

> **结论**：Projective Dynamics 是"起步快、后劲不足"的典型。

它的优点主要是跟 PBD 比：

- **有物理含义**：它跟正常的弹簧系统一样，跟正常做物理模拟的整个思路一致，力也好、能量也好，都是"真的"；
- **CPU 上效率很高**：可以用直接法解线性系统，而且只需要做一次分解，所以在 CPU 上很合适；
- **起步收敛快**：一开始那一段的收敛效率非常高。

缺点也很清楚：

- **GPU 上不合适**：直接法这种 LU 分解的套路，在 GPU 上并不合适；
- **整体收敛不理想**：一开始快，之后降下来，高精度场景吃亏；
- **约束改变时难处理**：什么叫约束改变？比如网格变了——本来五根弹簧，现在变成六根了；又或者想把碰撞也作为一种约束加进去。矩阵是由约束形成的，约束一变，矩阵就得跟着变，"常数矩阵、分解一次"的好处就没了，这就比较麻烦。

这算给大家做的科普。有时间的话建议去读一下那篇 paper，它讲得比较细；这里就是把方法给大家介绍一遍。

### Constrained Dynamics：为了硬约束而生

第二个方法叫 Constrained Dynamics。这个名字听着有点费解：我们前面讲的 PBD 也好、Projective Dynamics 也好，不都是用 constraint 吗？它跟前面那些方法有什么本质区别？这个方法我不打算花太多时间，把思路讲清楚就行。

它想干一件事：**处理非常非常 stiff（硬）的约束**。前面讲 PBD、Projective Dynamics，还有做隐式积分的弹簧系统，约束其实都很难严格保证；想要严格保证，就得做很多很多次迭代——这些方法本质上都要靠多次迭代，才能产生 stiff 的效果。迭代多了，计算量自然就大。那有没有办法：不做那么多迭代、不花那么大计算量，也能把很 stiff 的约束模拟好？这就是这个方法当初提出的思路。

这个方法也不只用在衣服这类东西上，很多时候它用在**刚体模拟**上。刚体里有一类叫 articulated body（铰接体）。最直观的例子是人体：把人看成很多刚体拼起来的——躯干、四肢、手臂、头、脖子，每一块是一个刚体；刚体和刚体之间用关节连接。那么每一个关节其实就是一个约束：比如上臂和躯干通过肩膀这个关节连接，那就要求手臂跟躯干在肩膀这个位置**必须重合**，是同一个点。这种约束我们希望它非常非常强。为什么？模拟人体动画的时候，如果这个约束不满足，四肢岂不是跟躯干分家了？那就一点都不合理了。所以模拟多刚体彼此之间的这类约束时，希望约束极硬——这个方法更多的时候就是用在刚体模拟上。这里我们还是用弹簧，把这个方法的思路走一遍。

### 把能量改写成约束的语言

还是一根弹簧：原长 $l_e$，约束是

$$\varphi=\|x_i-x_j\|-l_e$$

这个形式跟 PBD、Projective Dynamics 里的约束没有任何区别。能量呢？之前写成"二分之 $k$ 乘以（长度减去原长）的平方"。现在把这个形式改一改。先注意到，括号里那玩意其实就是约束 $\varphi$，所以我可以把能量写成**关于约束的函数**：原来是一个逐条求和的和式，现在把每一条约束的值都列进一个大的向量——约束总共有 $e$ 条，每条都有一个值：

$$\varphi=\begin{pmatrix}\varphi_0\\ \varphi_1\\ \vdots\\ \varphi_{e-1}\end{pmatrix}$$

再引入矩阵 $C$：它是 $k^{-1}$ 的对角矩阵，叫做 **compliance 矩阵**。它不再是 stiffness（刚度），而是刚度的倒数——柔软度，我们不妨叫它"软度"矩阵：

$$C=\operatorname{diag}\left(\frac{1}{k_0},\frac{1}{k_1},\dots,\frac{1}{k_{e-1}}\right)$$

能量就写成了：

$$E=\frac{1}{2}\,\varphi^{T}C^{-1}\varphi$$

> **定义**：柔度矩阵（compliance matrix）$C=\operatorname{diag}(1/k_e)$，是刚度的倒数。把这几个东西乘一乘就能验证：$\frac{1}{2}\varphi^{T}C^{-1}\varphi=\frac{1}{2}\sum_e k_e\varphi_e^2$，跟原来的能量形式完全等价，只是换了一种写法。

### 引入拉格朗日算子：力的全新形式

能量换了写法，力也要跟着换。力等于负能量梯度——这是定义，没别的可说。原来的能量直接是 $x$ 的函数，直接对 $x$ 求导就行；现在换了写法，$\varphi$ 成了能量函数的**中间变量**（$\varphi$ 是顶点位置的函数），所以用链式法则——微积分里都学过——把导数拆成两个因子，再把因子的前后顺序摆正（转置一做，约束对位置的导数跑到前面，能量对约束的导数落到后面）：

$$f=-
abla_x E=-\left(\frac{\partial \varphi}{\partial x}\right)^{T}\frac{\partial E}{\partial \varphi}$$

两个因子分别是什么？$\dfrac{\partial \varphi}{\partial x}$ 叫做**雅可比矩阵**（Jacobian），记作 $J$：约束对位置求导，是一个 $e\times 3n$ 的矩阵——$e$ 是约束条数，$3n$ 是全部顶点位置分量的个数。$\dfrac{\partial E}{\partial \varphi}$ 呢？看前面能量的定义，$\varphi$ 在里面出现了两次，求导之后 2 消掉一个，剩下 $C^{-1}\varphi$；负号从力的定义那里照抄过来。于是：

$$f=-J^{T}C^{-1}\varphi$$

现在我引入一个中间变量，把它叫做**拉格朗日算子**（Lagrange multiplier）：

$$\lambda=-C^{-1}\varphi$$

大家如果不知道什么叫拉格朗日算子也没关系，反正就是引入了这么一个变量，把带负号的 $C^{-1}\varphi$ 整个用 $\lambda$ 替换掉。于是力就有了一个全新的形式：

$$f=J^{T}\lambda$$

**力 = 雅可比转置 × λ**——这就是我想要的东西。$\lambda$ 就是所谓的对偶变量（dual variable），相当于第二个变量。为什么需要第二个变量？因为接下来做隐式积分的时候，未知量从一个变成了两个。

### 两个变量的隐式积分

之前做隐式积分只有一个变量：$v^{\text{new}}$（或者 $x^{\text{new}}$）。现在有了 $\lambda$，就有两个变量：顶点速度跟 $\lambda$。怎么用两个变量做模拟？两条方程，一条管动量，一条管约束。

**第一条：动量守恒。**质量乘以新速度，等于质量乘以老速度加上冲量；冲量等于力乘以时间，而这里的力就是 $J^{T}\lambda$：

$$M\,v^{\text{new}}=M\,v^{\text{old}}+\Delta t\,J^{T}\lambda^{\text{new}}$$

动量的变化等于冲量，这个应该没有什么问题。

**第二条：约束的定义，写在新的（未知的）状态上。**$\lambda$ 的定义是 $\lambda=-C^{-1}\varphi$，两边左乘 $C$ 就是 $C\lambda=-\varphi$。照抄这个定义，只不过在**新状态**下把它写出来：

$$C\,\lambda^{\text{new}}=-\varphi^{\text{new}}$$

新状态下的约束 $\varphi^{\text{new}}$ 是未知的，对它做泰勒展开：新约束约等于老约束，加上雅可比乘以位置的变化量；位置的变化量又等于速度乘以时间（$\Delta x=\Delta t\,v^{\text{new}}$）。代入整理：

$$C\,\lambda^{\text{new}}=-\varphi^{\text{old}}-\Delta t\,J\,v^{\text{new}}$$

两条方程都整理一下，第一条变成第一行、第二条变成第二行，合起来就是一个系统：

$$\begin{pmatrix}M & -\Delta t\,J^{T}\\ \Delta t\,J & C\end{pmatrix}\begin{pmatrix}v^{\text{new}}\\ \lambda^{\text{new}}\end{pmatrix}=\begin{pmatrix}M\,v^{\text{old}}\\ -\varphi^{\text{old}}\end{pmatrix}$$

我们本质上就是想要一个能往前模拟的公式——用速度代替位置其实也一样。跟之前隐式积分不同的点就一个：之前只解一个未知量，现在系统里有**两个变量**——主变量（顶点位置或速度）和对偶变量 $\lambda$——把两个变量同时解出来，就得到解。

### 两种解法，各有各的坑

拿到这个系统，有两种解法。

**方式一：直接法（primal-dual，两个变量一起解）。**有了系统就解系统——各种解线性系统的手段挑一个，把整个系统解出来，得到新的 $v$ 和新的 $\lambda$；用新的 $v$ 更新顶点位置，进入下一个时刻，一步一步往前模拟。这种两个变量同时求解的方式，在数学里叫做 primal-dual（原始–对偶）方法。它要特别小心一个坑：

> **易错点**：这个块矩阵**有可能不是正定的**。正定对解线性系统太重要了——很多解法在矩阵不正定的时候直接用不了。比如常规的共轭梯度法（Conjugate Gradient）就用不了，必须换用一些比较特殊的方法，比如 GMRES，才能解这个问题。

**方式二：消元，先 λ 后 v。**把 $v$ 消掉，只解 $\lambda$。从动量方程解出 $v^{\text{new}}=v^{\text{old}}+\Delta t\,M^{-1}J^{T}\lambda^{\text{new}}$，代进约束方程，就得到一个只含 $\lambda$ 的小系统：

$$(C+\Delta t^{2}\,J\,M^{-1}J^{T})\,\lambda^{\text{new}}=-\varphi^{\text{old}}-\Delta t\,J\,v^{\text{old}}$$

解出 $\lambda^{\text{new}}$，再代回动量方程把 $v^{\text{new}}$ 更新出来。这是分两步走：第一次先把 $\lambda$ 算出来，然后再根据 $\lambda$ 把 $v$ 算出来。

```text
方式一：primal-dual，联立一次解出
    [ M       -dt*J^T ] [ v_new ]   [ M *v_old ]
    [ dt*J      C     ] [ l_new ] = [ -phi_old ]     （l 即 lambda）

方式二：消元，分两步
    第一步  (C + dt^2 * J * M^-1 * J^T) * l_new = -phi_old - dt * J * v_old
    第二步  v_new = v_old + dt * M^-1 * J^T * l_new   （代回动量方程）
```

读图：两条路解的是同一个系统，区别只在解的次序和代价。方式二的坑在于：消元出来的那个矩阵不见得容易构造——矩阵比较复杂、质量矩阵比较复杂的时候，这个东西可能根本没法算；而且它很有可能**不稀疏**、比较稠密，这就导致第二种方法也不总是合适。所以是**各有各的坑**：取决于具体的问题，两种方式都可以用，具体问题具体分析。

### 越硬越好解：跟刚度的倒数打交道

说完坑，说它最大的好处：**可以处理非常非常硬的约束，甚至刚度可以假设成无穷大**。

以前我们用 $k$ 表示刚度，$k$ 趋向无穷大就没法模拟了——整个系统会变得特别 stiff。而在这个方法里，我们打交道的是 $C$，它是 $k^{-1}$ 的对角阵：$k$ 趋向无穷大？大不了把 $C$ 置成零，照样可以模拟。刚度越大，$C$ 越小，系统反而**更好**。换句话说，这个方法的难度跟 stiffness 的**倒数**相关，而不是跟 stiffness 本身相关——这正是它能对付硬约束的原因。

当然，今天主要是给大家一个思路：为了处理刚度很强的情况，可以这样引入 $\lambda$ 变量去求解。具体细节要看相关的 paper 和方法。我也实话实说：这个方法我自己从来没用过，只是了解过，算是现学现卖——就是希望大家有一个概念：**处理强约束问题的时候，比如 articulated body 这类多刚体系统，一般来说就是采用这种引入拉格朗日算子 $\lambda$ 去求解的模拟方式。**

最后把今天见到的三个方法放进一张表，方便回头对照：

| 方法 | 拿约束干什么 | 强项 | 软肋 |
| :--- | :--- | :--- | :--- |
| PBD | 投影结果直接改写顶点位置 | 内存访问最少，游戏里常用 | 没有物理含义 |
| Projective Dynamics | 投影结果拿去定义能量，换来常数 Hessian | 有物理含义；CPU 上分解一次、一劳永逸 | GPU 不合适；收敛后劲不足；约束一变矩阵就得变 |
| Constrained Dynamics | 引入拉格朗日算子 λ，把力与约束联立求解 | 越硬越好解，适合铰接刚体 | 联立与消元两种解法各有各的坑 |

## 从布偶动画到有限元：约束方法收尾与线性 FEM 开篇
> 对应块：BLK19 | 覆盖分集：P07下 | 块标题（分集名）：《Lecture 07 Other Constra》

上半节课的结论停在一句：引入对偶变量这套 constrained dynamics，能让系统处理很 stiff 的情况。有同学接着问：「模拟是不是找量纲相同的式子往上靠就行？」——说实话，我不太明白这个问题想问什么，什么叫「找量纲相同的式子往上靠」？这个问题先放一放，直接给大家看个 demo。

### 先看个 demo：摔在地上的布偶小人

这是我上课之前用 Unity 做的，因为 Unity 本身就带这个功能——做 articulated body（铰接体）。demo 里有个小人，我用 articulated body 模拟了一下，结果就是：duang 一下掉到地上，然后就倒在那儿了。它用的正是我们刚才说的 constrained dynamics。

这种动画有个名字，叫 ragdoll animation，布偶动画：假设人体由好多刚体构成，刚体和刚体之间连着一些约束，利用这些约束去做模拟，人摔在地上就是这么一副样子。

有同学问：小人的身体是不是分开建模的？这个我还真不知道，但我想应该不是——一般来说是一起建模，只是会把身体分块。而且这件事在 Unity 里做起来其实很简单：它直接提供了 ragdoll 这种 object，你只要创建一个，把身体的每个部分复制过去就可以了。Unity 其实帮大家做了很多事情。

顺着多聊两句：通常的骨骼动画是怎么来的？人体动画可以做动补，motion capture；如果是动画电影，动画一般完全由美术手工用关键帧做出来；游戏里很多骨骼动画则是预定义的——美术先用关键帧 k 好，再根据用户的选择去触发：让他跳就播跳的操作，让他跑就播跑的操作。一般都是用关键帧 k 出来的。

### 把 λ 消掉：绕回隐式积分

demo 看完，回到公式。对 constrained dynamics 那个系统，我们说过可以做高斯消元：把 $v$ 消掉之后，会得到一个关于 $\lambda$ 的式子。那反过来，如果把 $\lambda$ 消掉，大家猜会发生什么？——没错，得到的就是隐式积分的式子。因为 $\lambda$ 消掉以后就只剩 $v$ 了，它就变回我们之前讨论了半天的隐式积分那件事，一模一样。

有篇论文叫 Stable Constrained Dynamics，有兴趣的话可以去读。它说的其实就是这件事情：对式子做高斯消元、把 $\lambda$ 消掉，你会发现这跟隐式积分一模一样；只有一点稍微不一样——隐式积分里有一部分项，在做高斯消元之后是不存在的。而这篇论文说，把这块消失掉的项加回去之后，constrained dynamics 就变稳定了。论文讨论的就是这么一件事，给大家科普一下。

顺便交代一句：最后这块 constrained dynamics，我自己做 PPT 的时候也是看了半天才写出来的，所以你看得有点懵是很正常的——我自己也看了一会儿。

### 三种约束方法的同台盘点

简单总结一下讲过的几种处理约束的方法，各自站在哪里：

| 方法 | 怎么处理约束 | 优势 | 短板 |
|:---|:---|:---|:---|
| PBD / strain limiting | 为每个约束构造 projection 函数直接投影；Jacobi、GSL 两种解法 | 低分辨率下很快 | 高分辨率问题多；没有物理含义 |
| Projective dynamics | projection 写进能量，每次迭代重算后当作常数，再做隐式积分求解 | 矩阵是常数矩阵，可事先分解，CPU 上特别快 | 收敛得不够快，跟 PBD 类似 |
| Constrained dynamics | 引入对偶变量 $\lambda$，与 $v$ 联立求解 | 能处理非常 stiff 的问题 | 系统不再正定，求解有讲究 |

constrained dynamics 还带来一个视角上的变化。之前我们所有的模拟都只有一个变量——顶点位置，或者顶点速度；这里引入了一个新的变量，对偶变量（dual variable）$\lambda$。有了这个 dual variable，照样可以进行隐式积分，整个系统就变成由两个变量构成的系统，存在两种方式去模拟——上半节的两种消元方向，就是这两条路。

有同学问：作业实际上是不是 projective dynamics？并不完全是。咱们并没有用 projective dynamics 那一套方式去构造矩阵，我们的矩阵跟它不太一样；但思路确实比较接近——都是去做一个近似，搞一个常数矩阵出来，然后利用这个近似去做模拟。

还有同学问主流的布料模拟用什么。我个人觉得，现在主要的还是隐式积分，配上各种各样的近似——就像咱们作业里用到的这种，这是一大类；另一类比较多的就是 PBD。想做低分辨率的，比如游戏开发，一般就是 PBD；想要高精度、高质量的，弹簧系统加隐式积分这种比较多。

那移动平台上 GPU 功率小有什么建议？我没有什么好的建议——移动平台上各家 GPU 的性能都不太一样。正常的家用 GPU 是一个真正的并行处理器；移动平台上表面上是 GPU，但很多时候并不是真正的并行，更多是串行，有点伪并行。真要在移动平台上做的话，我觉得一般来说就是 PBD，可以参考 NVIDIA 的 Flex 那个库：它里面做了很多复杂的操作，如果把这些复杂操作去掉，其实效率还是比较高的。

今天数学的东西不少，回头感兴趣的话，课后花一点时间把这些读一读。反正今天就是给大家做个介绍。

### 有限元是个大坑：这门课的讲法

约束这一块到此为止，接下来讲有限元。有限元其实大家都知道是一个大坑吧？尤其学机械、学土木、学力学的同学，可能要学蛮久。所以咱们这个东西一方面是科普，会有一部分科普的内容；另一方面咱们也有作业的部分——有一个作业就是专门去写一个简单的有限元模拟，所以这里给大家的是一些简单的方法。

这一块我分成两部分讲：第一部分是 FEM，就是正常大家所知道的有限元，finite element method；另一个方法是图形学里也很常用的 finite volume method（FVM，有限体积方法）。对 linear element——也就是所谓的三角形或者四面体——大家会发现这两个东西是一样的。作业里有一个附加题，就是让大家实现两种不同的方式，然后发现写出来的模拟结果是一样的，验证这两个方法其实是等价的。

有同学问：机械里的有限元跟图形学的有限元有什么区别？如果是 linear element，是一样的，方法一样。但机械里很多时候用的不是 linear element：咱们图形学一般二维就是三角形、三维就是四面体；机械那边可能用立方体一类的有限元，还可能用高阶有限元——比如一个二阶的三角形，它会在边上再加额外的控制点，变成六个顶点的单元，复杂程度会高很多。咱们只考虑 linear 的话，基本可以认为是一样的。图形学里一般也是以 linear 为主，比较少用到高阶。

顺带把一般意义下的有限元套路也交代一下：先构造一个 strain——那个 strain 会比咱们的复杂得多，咱们这里就是一个简单的矩阵；然后构造一些形变模式去描述这个 strain，把这些形变模式写成一个能量、写成能量的函数，再利用能量密度去求导。大概是这么一个思路。

最后我还会讲一个弹性模型。这一块涉及得比较多，尤其是要模拟人体肌肉的时候，很多时候要用一些比较复杂的模型；当然作业里的模型会比较简单，给大家介绍一个简单的方式，想尝试高级 model 的也可以试一下。

对了，「有限元」这个名字怎么来的？我理解是因为这里有很多「单元」：你可以把三角形或者四面体认为是一个最小单元，单元里面假设它的形变是固定的——有点像咱们说的最小分割单位，这里就是把三角形当成形变的最小单位。

### 线性有限元的假设：单元内形变均匀

首先讲 FEM 这个方法。什么是 linear FEM？简单的说：我假设这个三角形在内部的形变是均匀的。

什么叫均匀的？比如我有一个三角形，三个顶点 $X_0$、$X_1$、$X_2$，把这个状态叫做 reference 状态——它没有形变、是静止的状态。假如这个三角形发生形变，跑到了一个新的位置，我用小写 $x_0$、$x_1$、$x_2$ 表示形变之后的状态，大写表示静止时候的状态。

```text
   reference（静止状态）              deformed（形变后）
        X2                                x2
       /  \                              /  \
      / ◆  \        x = F·X + c         / ◆  \
     /      \       ─────────>         /      \
    X0 ──── X1                        x0 ──── x1

   ◆：三角形内部随便找的一个点，它的映射同样由这同一个线性公式描述
```

然后我假设：这个三角形里面的每一个点，它的映射都可以用这么一个线性公式来描述：

$$x = F\,X + c$$

这里的 $x$ 可以是任意的 $x$——既可以是顶点的 $x$，也可以是三角形内部的 $x$：随便在三角形内部找一个点 $X$，它映射到的位置 $x$，都用这同一个线性公式描述。这就是有限元的一个思路。为什么叫「线性」的？因为这是一个线性公式嘛。

公式里 $F$ 是一个矩阵，对应的是形变跟旋转；$c$ 是一个向量，对应的是平移——位置也会发生改变嘛，所以映射里既有平移的部分，也有形变的部分。

### 形变梯度 F：用两条边把它解出来

这个 $F$ 有个名字，叫 deformation gradient，形变梯度。为什么这么叫？其实 $F$ 就等于 $\partial x / \partial X$——拿形变后的 $x$ 对静止的 $X$ 做一个求导，得到的就是它。

> **定义**：deformation gradient（形变梯度）$F = \dfrac{\partial x}{\partial X}$，把静止状态下的向量映射成形变后的向量；里面装着形变与旋转，与平移无关。

那现在第一步：给你一个三角形，位置发生变化了，怎么把 $F$ 算出来？

先注意一个现象。三角形内部有一条从 $A$ 到 $B$ 的向量，静止状态下记作 $X_{BA}$；形变状态下也有对应的向量 $x_{ba}$。按映射公式展开：

$$x_{ba} = \big(F\,X_B + c\big) - \big(F\,X_A + c\big) = F\,(X_B - X_A) = F\,X_{BA}$$

$c$ 在相减的时候自己抵消掉了。这意味着：对一个矢量而言，$F$ 就可以描述它的变化——之前是 $X_{BA}$，前面乘一个 $F$，就得到变换之后的 $x_{ba}$。照这样，我就能把 $F$ 求出来了。

怎么算呢？构造两条边：$X_{10} = X_1 - X_0$（0 指向 1）跟 $X_{20} = X_2 - X_0$（0 指向 2）。按刚才的描述：

$$F\,X_{10} = x_{10}, \qquad F\,X_{20} = x_{20}$$

把这两个公式合并一下——它们都是二维向量，两条边拼起来，就得到一个 2×2 矩阵对 2×2 矩阵的等式：

$$F\begin{bmatrix} X_{10} & X_{20} \end{bmatrix} = \begin{bmatrix} x_{10} & x_{20} \end{bmatrix}$$

把静止的边向量矩阵乘到公式的右边去（取逆），deformation gradient 就到手了：

$$F = \begin{bmatrix} x_{10} & x_{20} \end{bmatrix}\begin{bmatrix} X_{10} & X_{20} \end{bmatrix}^{-1}$$

也就是说，$F$ 可以完全由边向量矩阵算出来。而且注意：这个式子里已经没有 $c$ 了——位移这一项被抠掉了，$F$ 跟平移无关。

### F 里还藏着旋转：把它抠掉

问题来了：可不可以直接拿 $F$ 来描述形变？不可以。$F$ 跟形变有关，但它里面同样也有旋转：假如三角形没有任何形变、只在做刚体运动，$F$ 里面照样有值（是一个旋转）。这就不太理想了——我想描述的是形变，希望这个量跟刚体运动无关，因为刚体运动是没有形变的嘛。换句话说：平移已经去掉了，接下来要把旋转也去掉。

为了这个目的，来看 $F$ 到底是个什么玩意儿。之前讲过，$F$ 通过 SVD 可以分成三个部分：

$$F = U\,\Sigma\,V^T$$

```text
F = U * Σ * V^T

V^T ：先把方向转过去、对齐形变的主轴 —— 表面上是旋转，其实是形变的一部分
Σ   ：缩放，直接决定形变的大小
U   ：形变完成之后再调整物体姿势的旋转 —— 与形变无关，要抠掉的就是它
```

其中前面两个部分都跟形变有关：第一个部分表面上是旋转，实际上是用来调整形变的方向——我想沿着对角线形变，那就先转个 45 度；第二个缩放，直接决定形变的大小是什么。只有最后一个旋转跟形变没有关系——它是形变已经发生完了之后，再去调整这个物体姿势所产生的旋转。所以后面这个 $U$ 有它没它都无所谓，而且它跟形变没有关系。我的目的就是把 $U$ 抠掉。

怎么抠？一个思路是做 SVD，做完之后把 $U$ 删掉。但这个思路听起来就不是那么美好：为什么我得做 SVD 才行？有的同学不会 SVD，那怎么办？

咱们数学家又想了个办法：可以不做 SVD，直接拿 $F$ 乘上它自己的转置——

$$F^T F = V\,\Sigma\,\big(U^T U\big)\,\Sigma\,V^T = V\,\Sigma^2\,V^T$$

你会发现中间的 $U$ 自己对掉了，剩下的只有 $\Sigma$ 的平方夹在两个 $V$ 当中。在此基础上，最后减去 identity，前面乘个 $\tfrac{1}{2}$：

$$G = \frac{1}{2}\left(F^T F - I\right) = \frac{1}{2}\left(V\,\Sigma^2\,V^T - I\right)$$

这个东西有个名字，叫 Green strain，Green 应变。不用做 SVD，一样把旋转去掉了。

> **定义**：Green 应变 $G = \dfrac{1}{2}\left(F^T F - I\right)$。$F$ 里的旋转在 $F^T F$ 中间自动对消，$G$ 只反映形变本身。

> **提示**：这里乘的是 $F^T F$ 而不是 $F F^T$——$U$ 夹在中间才能自己对消，剩下 $V\,\Sigma^2\,V^T$；要是乘 $F F^T$，对消的就是 $V$，剩下的 $U\,\Sigma^2\,U^T$ 里仍然带着那个跟形变无关的旋转。

另外，$G$ 是一个对称矩阵——虽然说它是个 2×2 的矩阵，但只有三个变量，分别记作 $\varepsilon_{uu}$、$\varepsilon_{uv}$、$\varepsilon_{vv}$。

### 应变：描述形变的数学量

有同学可能不太了解什么叫做 strain（应变），这里简单地讲一讲。strain 就是我搞了一个数学的量，用这个量去描述物体的形变。这个量可以是一个实数——对弹簧来说，它就是一个实数；也可以是个矩阵——比如咱们三角形的例子，它就是个 2×2 的矩阵；三维的时候，它就是个 3×3 的矩阵。

这个 strain 有什么特点呢？首先，没有形变的时候它应该是零：没有形变，$F$ 就是单位阵，代进去 $G$ 就是零。其次，它的大小跟形变的大小正相关：形变越大，strain 也越大——$\Sigma$ 越大，Green strain 也会变大。所以它本质上就是一个描述「形变有无」跟「形变大小」的量。

最后一个特点，也是我们反复强调的：它跟旋转无关。哪怕之后你再给这个物体施加什么样的旋转，算出来的 Green strain 都是一样的。比如额外加一个旋转 $R$，总的 deformation gradient 就会变成 $R\,F$——$F$ 是之前的形变，$R$ 是额外做的那个旋转——代入定义：

$$\frac{1}{2}\left((R\,F)^T (R\,F) - I\right) = \frac{1}{2}\left(F^T\,R^T R\,F - I\right) = \frac{1}{2}\left(F^T F - I\right)$$

中间的 $R$ 对掉了，跟之前一模一样。也就是说，旋转不影响 strain——它描述的就是形变。

> **结论**：Green 应变满足三条——没有形变时为零、大小随形变增长、与刚体旋转无关，是一个纯粹描述形变的量。

### 从应变到能量：StVK 能量密度

有了 Green strain、有了形变之后，接下来就想搞能量了。咱们之前做模拟，一般来说都是要有个能量嘛：做弹簧系统的时候搞个弹簧能量，有了弹簧能量以后，后面的就好办了——拿能量去算力、算各种乱七八糟的东西，都可以算。有限元也是一样的：有了形变之后，我就想利用这个形变搞能量。

怎么搞？对这个三角形，定义一个新的函数，叫做能量密度：单位面积的能量，记作 $w$，它是 strain 的一个函数。

总的能量怎么算？很简单：密度乘以总面积不就得了嘛。三角形的面积是 $A$——注意它是静止状态下算出来的面积，所以叫 reference 面积（参考面积）。面积乘以能量密度，总能量就到手了：

$$E = A \cdot w(G)$$

为什么能直接这么乘？因为线性假设在这里兑现了红利：deformation gradient $F$ 在整个三角形内部是同一个常数，$G$ 也是常数，整个三角形内部每一处的能量密度一模一样——密度乘以面积，就是全部的能量。而这里的 $w$，正是写成了 strain 里那三个变量的函数。

那作业里具体用哪个能量密度函数？咱们用了个比较简单的，叫 St. Venant–Kirchhoff 模型（StVK）。这个模型在做模拟的里面用得并不多，尤其是力学里面用得并不多；但为什么图形学老喜欢用这个呢？因为这个模型特别特别简单。所以作业里我也就沿用了这个模型，帮大家把作业的工作量降一降。它的样子是：

$$w = \frac{\lambda}{2}\left(\mathrm{tr}\,G\right)^2 + \mu\,\mathrm{tr}\!\left(G^2\right)$$

这里面有两个参数，一个 $\lambda$，一个 $\mu$，叫做 Lamé parameters，拉梅参数。

### 对能量密度求导：Second Piola–Kirchhoff 应力

有了这个模型之后可以求导：拿 $w$ 分别对 strain 的这三个变量求导。比如对 $\varepsilon_{uu}$ 求导，二跟二对掉，得到 $\lambda\,(\varepsilon_{uu} + \varepsilon_{vv})$ 加上 $2\mu\,\varepsilon_{uu}$——学过微积分的话肯定会算，反正课后可以自己推一下，推出来就是这个样子。而且你会发现，这些结果可以直接用 Green strain 收拢成一个矩阵：

$$S = 2\mu\,G + \lambda\,\mathrm{tr}(G)\,I$$

这里的 $\mathrm{tr}$ 是 trace，就是一个矩阵的对角和。

这个 $S$ 矩阵是有名字的，它叫 Second Piola–Kirchhoff stress，第二类 Piola–Kirchhoff 应力张量。名字有点绕口，我这里先不解释，下一讲会给大家解释这个东西。但可以先给大家一个直观的概念：想想它是从什么推出来的？是能量密度对形变的一个导数。我们之前知道，能量对位移求导是力；而形变本质上描述的也是一种位移嘛，所以它算出来的也是力——不完全是力，相当于是一个力的密度，是跟力有关的一个东西。具体怎么个有关法，下一讲再具体分析这个 stress 到底做了什么，心里先有个数。

### 从能量到力：链式法则拆成两半

有了能量的定义——能量等于面积乘以能量密度，能量密度函数有了，能量密度对 strain 变量的导数也有了——是不是就可以算力了？可以，利用定义来算力。

力等于负能量对位置求导：$i$ 号顶点的力 $f_i$，就是能量对 $x_i$ 求导、前面加个负号。能量等于面积乘以能量密度，所以：

$$f_i = -\frac{\partial E}{\partial x_i} = -A\,\frac{\partial w}{\partial x_i}$$

能量密度是 strain 三个变量的函数，所以用偏微分做一个替代——就是一个很简单的链式法则：$w$ 分别对每一个 $\varepsilon$ 求导，再乘上 $\varepsilon$ 对顶点位置的导数：

$$\frac{\partial w}{\partial x_i} = \sum_{ab} \frac{\partial w}{\partial \varepsilon_{ab}} \cdot \frac{\partial \varepsilon_{ab}}{\partial x_i}$$

前半截咱们其实已经算过了——就在刚才那个 stress 里面，绿颜色的部分都是知道的、可以算出来的。我们不知道的，是后面灰颜色的部分：$\partial G / \partial x_i$。接下来看看灰颜色的东西怎么推。

### 笨办法：摊开硬求导

$F$ 是形变后的边向量矩阵乘以原来边向量矩阵的逆。先不管那个逆里面是啥，把它假设成 $a$、$b$、$c$、$d$ 四个变量的矩阵。那么 $F$ 本质上就是两列：第一列是 $a\,x_{10} + c\,x_{20}$，第二列是 $b\,x_{10} + d\,x_{20}$——简单做了一个矩阵乘。

然后根据 Green strain 的定义，把整个乘起来。我这里用了个简单粗暴的方法：全部乘开，得到一个大式子，再分别对 $x_1$、$x_2$ 求导。比如对 $x_1$ 求导：求导的时候，常数部分（那个 $-\tfrac{1}{2}$）直接扔掉；带 $\tfrac{1}{2}$ 的部分，因为这里相当于是一个平方，二跟它对消掉了；前面那部分本质上就是 $a$ 乘 $(x_1 - x_0)$，对 $x_1$ 求导就把 $a$ 留下来，乘以后面那一坨——这就是基本的微积分，不熟悉的话课后自己再推一遍。对 $\varepsilon_{vv}$ 求导也是一样的道理，把 $b$ 留下来；$\varepsilon_{uv}$ 那一项同理。对 $x_2$ 求导也照做一遍。完全从定义出发，知道 $G$ 里每一个变量长什么样，整个公式是可以推出来的。

当然，这些都是二次函数，不用什么工具、直接手推也是推得动的——以前的 paper 就是这么写的，二十年前的 paper 都是这样。

但大家有没有发现这个东西特别复杂？一大堆公式、一大堆变量。你要真的照着这个去写代码，我感觉大部分时间都在 debug：比如说哪里正负号写错了、哪里 $a$、$b$、$c$、$d$ 抄错了，你可能得花很多很多时间去 debug。

最早年的 paper——比如这里列的 09 年这一篇——就没有用后面要讲的这个简化。不做这些简化、直接照公式写有限元还是挺复杂的：好多好多公式、好多好多变量，推来推去，很容易犯错。

### 简化：把一坨求导收进矩阵乘法

咱们的目的没有变：算力——力等于能量对顶点位置的求导取负。把刚才推的那些结论带进去，得到一个大式子——我就是从前面那一页抄下来的，相信我没抄错。然后对这个式子做整理，你会发现它可以写成一个矩阵的乘法：左边一个矩阵、右边一个矢量，乘起来跟上面一模一样；再对这个式子整理一下，又会得到另一个形式——中间是一个矩阵，绿颜色的东西是 deformation gradient，也就是 $F$，还有我们前面算的 $\partial w/\partial G$，就是 $S$。

这下就简单了。其实我们没有必要去抄那么多公式、利用那么多公式乘来乘去——那个太复杂了，完全可以用矩阵的乘法来替代。1 号顶点的力可以做这样的简化，2 号顶点同理，以此类推，最终就是两个力：

$$f_1 = -A\,F\,S\,M^{-T}e_1, \qquad f_2 = -A\,F\,S\,M^{-T}e_2$$

其中 $M = \begin{bmatrix} X_{10} & X_{20} \end{bmatrix}$，$e_1$、$e_2$ 是用来挑出对应列的标准基向量；$M^{-T}e_1$ 挑出来的正是 $M^{-1}$ 的第一行——也就是刚才假设的 $a$、$b$ 那两个系数。负的参考面积，乘 deformation gradient，乘 Second Piola–Kirchhoff stress，再乘静止边向量矩阵的逆转置——是不是把一堆东西都搞得简单了？没必要再求来求去，求导还是很容易求错的，完全可以用这么一个简单的公式替代掉。

```text
静止边矩阵 M = [X10 X20]        形变后边矩阵 = [x10 x20]
         |                            |
         +-------------+--------------+
                       v
       F = [x10 x20] * M^{-1}            （解出形变梯度，平移已消去）
                       |
                       v
       G = 1/2 * (F^T * F - I)           （旋转自动对消 => Green 应变）
                       |
                       v
       w(G) = lambda/2 * tr(G)^2 + mu * tr(G^2)      （StVK 能量密度）
                       |
                       v
       S = 2*mu*G + lambda*tr(G)*I       （Second Piola-Kirchhoff 应力）
                       |
                       v
       f1 = -A * F * S * M^{-T} * e1
       f2 = -A * F * S * M^{-T} * e2
       f0 = -(f1 + f2)                   （牛顿定律：内力合力为零）
```

读图：从静止与形变后的边向量出发，先解出形变梯度 $F$（去掉平移），再经 $F^T F$ 消掉旋转得到 Green 应变 $G$，代入 StVK 能量密度并对 $G$ 求导得到应力 $S$，最后一行矩阵乘法给出全部顶点弹性力。

有同学可能会问：这里为什么只有两个力？只有 $x_1$ 跟 $x_2$，为什么不算 $x_0$？大家想想 $x_0$ 怎么算。——咱们可以利用牛顿定律：牛顿说了，合力为零嘛。所以：

$$f_0 = -(f_1 + f_2)$$

0 号顶点上的力，就直接这样推出来了。

很多时候就是推得很复杂，写代码会发现其实很简单。我甚至觉得这是咱们所有作业里面最简单的一次作业：基本上就是矩阵乘来乘去，然后就乘出来了。虽然说听起来很难，但这可能是最简单的一次作业。

大家以后去看早期的 paper，会发现每个人写法都不一样。就说图形学里面的 paper：最早比如 James O'Brien，二十年前那批形变体的 paper，甚至都没有用矩阵，用的是类似爱因斯坦标记的那种方式——把矩阵里每一个元素都用下标摊开来写，把整个东西搞得特别特别复杂。矩阵形式出来之后，一下子大家都觉得这个东西特别简单，后面的 paper 基本上都采用类似这门课里的写法，就简单很多了。

### 推广：四面体跟布料

有同学问：只有三角形这个模型是这样的，还是其他模型都这样？四面体也是一样的——只要是 linear FEM，都可以采用这样的套路。做法就是把所有的东西都挪到三维上：deformation gradient、Green strain tensor 都变成 3×3 的；力的话就是四个力了，四个顶点对应四个力——先算三个，最后一个顶点的力，用剩下三个力的和取负算出来。

不过三维的公式是真的复杂好多：Green strain 是对称矩阵，2×2 的对称矩阵有三个变量，3×3 的对称矩阵就有六个变量，公式就会特别特别复杂。

衣服模拟呢？要模拟衣服的话，用的就是 2D 的有限元，但它有一个比较特殊的点：衣服是在三维空间里模拟的，它的 reference 状态是二维的，而衣服实际的状态是三维的，所以它的 deformation gradient 不再是 2×2 的矩阵，而是一个 3×2 的变换——从二维静止状态映到三维世界状态。这是衣服比较特殊的地方，其他都一样。

实践上的话，最近有一篇讲用这种有限元方法模拟衣服的论文，这个方法其实也可以做到四面体的网格上——怎么做四面体网格？基本上一样，把之前二维的东西都挪到三维上就行。下一讲会给大家伪代码，照着伪代码会更容易理解一点。

### 顶点的力从哪来：积分的视角

有同学问：内部的力可以插值吗？其实我们这里没有「内部的力」这回事——我们没有算内部的力，只考虑顶点的力。咱们模拟都是顶点系统嘛，把每个顶点的力算出来就完了。那顶点的力是怎么来的？下一讲讲 finite volume method 的时候会解释：力是积分得来的。

直观地说：比如有个三角形，你可以把它分成三块，每一块对应一个顶点。0 号顶点对应的那一块里面会有很多力——$S$ 这个 stress tensor 贡献的——把这一块里面所有的力叠加起来，施加在这个顶点上。咱们刚才推出来的那些东西，你拿「做力的积分」这个思路去算，会发现结果是一样的——那套公式其实也是对力做了一个积分。

所以今天讲的有限元，跟咱们之前讲的弹簧系统、还有其他系统是一样的：都是求导，根据能量的导数把力推出来。下一讲换个思路：不求导了，用积分的形式来算。

有同学问：这套东西是不是还做隐式积分？是的，如果隐式积分的话会稍微更复杂一点，但其实跟咱们做弹簧系统模拟是一样的：一个单元算完了力，下一个单元再算力，所有单元算完之后，把所有的力加起来，然后更新顶点位置。

今天具体的内容就先到这儿，剩下的问题咱们下一讲继续。

### 本讲提到的题目

作业：写一个简单的有限元模拟。题面就是把正文那条链路实现一遍——算出三角形三个顶点的弹性力（StVK 能量密度、$S = 2\mu\,G + \lambda\,\mathrm{tr}(G)\,I$、$f_1$、$f_2$，以及 $f_0 = -(f_1 + f_2)$），单元算完力就累加，全部算完再更新顶点位置。解析就是正文本身：每一步推导都已经展开，落到代码里基本就是矩阵乘来乘去——这也是为什么它可能是所有作业里最简单的一次。

附加题：用两种不同的方式实现同一个 linear element 模拟——今天这种「能量求导」的 FEM 思路，和 finite volume method 的思路——然后验证两种方式写出来的模拟结果是一样的，也就是这两个方法在 linear element（三角形、四面体）下是等价的。解析在「顶点的力从哪来」一节：FVM 把每个顶点对应子区域里的力积分起来施加到顶点上，而按能量求导推出的顶点力公式，与做这个力的积分算出来的是一样的，两条路线殊途同归。
