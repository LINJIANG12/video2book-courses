# 有限元方法与碰撞处理

## 有限体积方法：从应力到节点力

### Traction 与 Stress

   * **有限体积方法（finite volume method）**

       * > **定义**：不从能量求导，而是对界面上 traction 做积分来得到节点力的方法——力被视为藏在分割弹性体的那条界面上。

       * 与有限元在三角形、四面体这类线性单元（linear element）下等价，推导与数学表述更清晰，写论文基本遵循有限体积方法的 formulation。

       * > **提示**：两者严格说不是同一个方法——一个算积分、一个算微分，更复杂的情况下并不一样；等价只在简单线性单元的特例下成立。

   * **Traction（$t$）**

       * > **定义**：单位面积（三维）或单位长度（二维）上的力；总合力等于 traction 沿整个表面（二维沿曲线）的积分。

       * 物理含义是作用在某个表面上的力的密度，很像压强（力除以面积）。

   * **应力（stress，$\sigma$）**

       * > **定义**：一个矩阵，完成从法向量 normal 到 traction 的一次映射：$t=\sigma n$。

       * 合力即该映射沿整个表面的积分：$f=\int \sigma n\,\mathrm{d}l$（三维换成对面积分）；后续全部推导从这一步出发。

### 三角形与四面体顶点的力

   * **顶点代表区域与中点假设**

       * 把顶点 $x_0$ 看作代表表面上的一块区域：区域内部的内力自己拉自己、对整块区域产生不了作用，真正起作用的合力是外轮廓一整圈 traction 的积分。

       * 切割曲线事先并不知道长什么样，假设它的两个端点钉在 $x_0$–$x_1$ 与 $x_0$–$x_2$ 两条边的中点上——依据是假设三角形产生的力对三个顶点平均、一家一份。

       * 边向量记法：$x_{10}=x_1-x_0$，以此类推。

   * **常数应力与散度定理**

       * 线性单元假设单元内部的形变、stress 处处一样是常数，$\sigma$ 可以提到积分号外。

       * 散度定理（divergence theorem）：normal 沿封闭曲线积一整圈结果是零——绕一圈方向全抵消，于是切割段的积分可用两条半边段的积分取负代替。

       * 直线边上的法向量处处一样，积分退化为法向量乘长度；端点钉在中点上，每段长度正好是整条边的一半。

       * 结果：$f_0=-\frac{1}{2}\,\sigma\left(\hat n_{10}\,|x_{10}|+\hat n_{20}\,|x_{20}|\right)$，$\hat n_{10}$、$\hat n_{20}$ 是两条边各自的法向量——除 $\sigma$ 外只用法向量与边长就能算。

       * > **提示**：所有三角形对 $x_0$ 的贡献加起来不会是零——每一个三角形的 $\sigma$ 都不一样；若 $\sigma$ 全都一样，合力才会抵消成零。

   * **四面体：三个面的三分之一**

       * 四面体的一个顶点相邻三个面；每个面的贡献除以三、均匀分给这个面的三个顶点，相邻三个面各做一次再分别加起来：$f_0=\frac{1}{3}\,\sigma\,(A_1 n_1+A_2 n_2+A_3 n_3)$。

       * 化简：面的面积等于两条边 cross product 的模除以二，normal 等于 cross product 除以它自己的模，两者相乘模跟模抵消，$A\,n$ 只剩二分之一的 cross product；整理得 $f_0=-\frac{1}{6}\,\sigma\,(c_1+c_2+c_3)$，$c_1,c_2,c_3$ 是相邻三条边两两做出来的三个 cross product。

       * 到这里力的公式有了，剩下唯一没讨论的问题是 $\sigma$ 怎么计算。

   * **高斯积分的适用边界**

       * 高斯积分是做高阶有限元时才会用到的数值积分方法；这里都是最简单的单元，没有必要用它。

       * 高斯积分本质上是要做采样的。

## 应力的三种形式

   * **Second Piola–Kirchhoff stress（$S$）**

       * > **定义**：把 reference 状态的 normal 映到 reference 状态 traction 的应力。

       * 能量密度定义在 reference 状态（乘以 reference 的面积、体积得到总能量），所以能量密度对格林应变（Green strain）求导得到的 $S=\partial W/\partial G$ 是 reference 口径的应力——这是会算的那一种。

   * **第一类 Piola-Kirchhoff 应力（first Piola-Kirchhoff stress，$P$）**

       * > **定义**：把 reference 状态的 normal 映到形变后 traction 的应力。

       * 与 $S$ 的关系：$P=F\,S$——traction 是个矢量，乘以形变梯度（deformation gradient，$F$）就从 reference 状态变到形变状态。

   * **柯西应力（Cauchy stress，$\sigma$）**

       * > **定义**：把形变后的 normal 映到形变后 traction 的应力——有限体积力公式里直接拿来算力的就是它。

       * 与 $P$ 的关系：$\sigma=\frac{1}{\det F}\,P\,F^{\mathrm T}$。

       * 模拟需要的是"转成 traction 就能直接算力"，所以这里的 normal 跟 traction 都取形变状态。

   * **为什么会有好几种应力**

       * stress 的本质是做映射，而 normal、traction 各有 reference／形变两种描述，组合起来共四种可能；"形变的 normal 映到 reference 的 traction"这一种没见过、不考虑。

       * 三种应力用哪一种都能把力算出来、而且算出来的力一样——区别只在公式右半部分用的几何量：柯西应力配形变之后的四面体，$P$ 配没有形变的静止状态顶点位置。

       * 既然殊途同归，就转化到对计算最友好的那一种形式上去。

| 应力 | normal 取自 | traction 取自 |
| :--- | :--- | :--- |
| Second Piola–Kirchhoff（$S$） | reference 状态 | reference 状态 |
| First Piola–Kirchhoff（$P$） | reference 状态 | 形变后状态 |
| Cauchy（$\sigma$） | 形变后状态 | 形变后状态 |

## 四面体节点力的落地计算

   * **用 $P$ 替换柯西应力**

       * 这个替换不走 $\sigma=\frac{1}{\det F}PF^{\mathrm T}$ 的转化公式：力公式里 cross product 算的本就是面的法向量，改用没有形变的 reference 顶点来算 cross product，输入从"形变的 normal"换成"reference normal"，配的自然是第一类应力——它跟柯西应力的唯一区别就是用的 normal 不一样。

       * 好处：方括号里的几何量全是 reference 常数，可以全部事先算好存起来，模拟时完全不需要实时计算——只赚不赔的简化。

       * 力公式落地为 $f=-\frac{1}{6}\,P\,b_1=-\frac{1}{6}\,F\,S\,b_1$；每个顶点有自己对应的 $b$：算 $x_1$ 上的力用 $b_1$，算 $x_2$ 用 $b_2$，以此类推。

   * **$b$ 向量的真面目**

       * $b_1$ 用于计算 $x_1$ 上的力；拿三条边分别跟它做点积，真面目就露出来：$x_{10}\cdot b_1=6V$（六倍四面体体积）；$x_{20}\cdot b_1=0$、$x_{30}\cdot b_1=0$——含 $x_{10}$ 及其负向量的 cross product 项与之垂直、点积直接抵消，含 $x_{20}$ 的项合并后变成自己跟自己 cross 再自己做点积、等于零。

       * 三个点积拼成矩阵关系：$[\,b_1\ \ b_2\ \ b_3\,]=6V\,D_m^{-\mathrm T}$，其中 $D_m=[\,x_{10}\ \ x_{20}\ \ x_{30}\,]$ 是 reference 边矩阵——出现的正是逆的转置（inverse transpose）。

       * 按列拆开看，$b_1$ 就是 $x_{20}\times x_{30}$——恰好是 $x_1$ 对面那个面上两条边做出来的 cross product。

       * $6V$ 其实就是 $\det D_m$：数据结构里不专门保存四面体体积，行列式一求、六倍体积就有了；配上边矩阵的逆，整个 $b$ 矩阵就齐了，全是 reference 状态的量、统统事先算好。

   * **预计算与逐步求解流程**

       * 整条链路如下——公式一多，常数跟转置最容易出错：

           ```text
           # 预计算（全是 reference 状态的常数，只算一次）
           D_m = [X10  X20  X30]                     # reference 边矩阵
           B   = [b1  b2  b3] = det(D_m)·D_m^{-T}    # 即 6V·D_m^{-T}

           # 每个时间步、每个四面体
           D_s = [x10  x20  x30]                     # 当前（形变后）边矩阵
           F   = D_s · D_m^{-1}                      # 形变梯度
           G   = (F^T·F - I) / 2                     # Green 应变
           S   = dW/dG                               # Second Piola-Kirchhoff stress
           P   = F·S                                 # First Piola-Kirchhoff stress
           [f1  f2  f3] = -(1/6) · P · B             # 三个顶点的力，一列一个
           f0  = -(f1 + f2 + f3)                     # 第四个顶点：合力为零倒出来
           ```

       * $f_0$ 的来历：把整个四面体本质上当成一个弹簧，作用力跟反作用力成对出现、四个力的总合力应该是零——先算三个、第四个加个负号倒出来，图的是动量守恒。

       * 形变后的边矩阵就是三条边：显式积分下当前状态已知，三个顶点的当前位置给出三列；得到力之后就是粒子系统的老流程——用力更新速度、用速度更新位置。

       * 中间这些量其实都是 $3\times3$ 的矩阵；除了欧拉网格那一路的流体，粒子系统这种方式贯穿所有模拟。

   * **实现自检**

       * 静态链测试：关掉重力让单个四面体静止 → 形变状态与参照状态一模一样 → $F=I$ → Green 应变算出来是零矩阵 → 应力是零 → 所有弹性力为零；链上任何一环不是预期的样子，问题就出在那一环。

       * 拉伸测试：把四个顶点坐标沿某个方向（如 $x$）缩放一下就是拉伸；弹性体的力永远阻碍形变，算出来的力理论上都应指向把四个顶点缩回去、恢复原状——看方向上有没有这个趋势即可判断计算对不对。

   * **实现要点**

       * 模型由一个个实心的四面体填充、内部是有东西的，不是只有四个面的壳。

       * 每个四面体可以配不同的材料（heterogeneous material，不均匀材料），就像每根弹簧可以配不同的弹性系数；图形学里用得比较多的还是均匀的 homogeneous。

       * 论文里一般把 $b_1,b_2,b_3$ 分别算出来、保存下来再做后续计算；实际上直接利用 $D_m$ 来做计算就行——结果一样，只是计算方式上省一些计算量。

       * 四面体网格没有可以直接拿来渲染的三角形网格，需要额外构造一套：把每个四面体的四个面一个个取出来，凑成一个大数组拿去渲染。

       * 规模边界：一千多个四面体的模型写完直接跑很难 debug（先只用一个四面体测）；四面体有限元模拟本身不太适合游戏开发，只在非常小的分辨率下适合。

       * > **注意**：对速度场做平滑就是每个点把它周围所有邻居的速度加起来、跟自己的速度做加权平均（跟 PBD 的更新思路、平滑滤波是一回事），放在流程前面或后面都可以；平滑过度会崩——该下落它还是会下落，只是运动平滑一点。

## 超弹性材料模型

### 各向同性与主拉伸

   * **超弹性材料（hyper elastic material）**

       * > **定义**：通过能量密度推出来的材料模型——利用能量密度函数，建立一个从形变到 stress 的映射。

       * 是描述力跟形变之间关系的通用模型；选不同的能量密度 $W$ 就模拟不同的弹性模型（STVK、Neo-Hookean 等，其实就是对 $W$ 做了不同的改变）。

   * **各向同性材料（isotropic material）**

       * > **定义**：在不同方向上拉伸、对它产生形变，效果都一样的材料（比如橡胶，横着压跟竖着压没有区别）；性质跟方向有关、横压竖压斜压都不一样的是各向异性材料（anisotropic material），不在此讨论。

       * $P$ 本质上是形变梯度 $F$ 的函数：$P=P(F)$；对 $F$ 做一次 SVD 得到三个部分——两个旋转加一个对角矩阵，对角元素描述三个主方向上拉伸的多少，叫主拉伸（principal stretch）$\lambda_1,\lambda_2,\lambda_3$。

       * 各向同性的好处：两个旋转都可以扣到外面去，$P=U\,\hat P(\lambda_1,\lambda_2,\lambda_3)\,V^{\mathrm T}$（$F=U\Sigma V^{\mathrm T}$，$\Sigma$ 是对角矩阵）——把旋转从问题里剔除掉，让 $P$ 直接跟主拉伸发生关系。

   * **主不变量（principal invariants）**

       * $I_1=\lambda_1^2+\lambda_2^2+\lambda_3^2$；$I_2=\lambda_1^4+\lambda_2^4+\lambda_3^4$；$I_3=\lambda_1^2\lambda_2^2+\lambda_2^2\lambda_3^2+\lambda_3^2\lambda_1^2$。

       * 很多论文喜欢用这三个中间变量去描述 $P$；了解一下就可以，不用特意去背。

### 应力的 SVD 直接计算

   * **SVD 直接公式**

       * $P=U\,\mathrm{diag}\left(\frac{\partial W}{\partial\lambda_1},\frac{\partial W}{\partial\lambda_2},\frac{\partial W}{\partial\lambda_3}\right)V^{\mathrm T}$——对能量密度关于三个主拉伸分别求偏导、放进对角矩阵，再用 $F$ 做 SVD 得到的两个旋转 $U$、$V$ 组装出来。

       * 跟旧路线相比多一步 SVD、稍微复杂一点（STVK 那套不需要 SVD）；SVD 的代码包里已经有，直接调用。

   * **两条路线的对照与勘误**

       * 旧路线：先从格林应变算 $S=\partial W/\partial G$，再用 $P=FS$ 得到 $P$；新路线：SVD 直接组装——对同样的模型，两条路算出来的结果应该一样。

       * > **易错点** ⚠️：算出来的不一样，肯定是哪里写错了、或者哪里理解得不对——可拿旧路线算出来的东西做验证。

       * > **注意**：附加题里给的 SVD 推导公式经推导勘误：公式本身是对的，只是前面差了个系数——应该是 $\frac{1}{8}$ 而不是 $\frac{1}{2}$；动笔前先把公式自己推一遍、确保跟理论一致。

### 常见材料模型

   * **Neo-Hookean（新胡克模型）**

       * > **定义**：更标准的胡克模型，有两项——一项主要目的是抵抗拉伸，另一项是为了阻止体积或者面积的改变。

       * 现实对应：拉一块橡皮的时候中间会缩短——它试图保持体积；既然希望体积不改变，第二项自然就是阻止体积改变的。

       * 材料力学里大家用得更常见的一个模型（相对 STVK 而言）。

   * **其他模型**

       * Mooney-Rivlin：Neo-Hookean 的一个增强版，一般拿来描述橡胶。

       * Fung 模型：一般用来模拟人体组织这一类材料。

       * 金属：形变一般来说比较小，一形变一般就变成塑性形变，比较简单的弹性模型可能就够了，跟 Neo-Hookean 的差别可能不是很大。

       * shearing 字面意思是剪切，但在这一语境里各种各样的拉伸其实都在 shearing 里面——拉伸也是一种 shear、不同方向上的 shear。

   * **泊松效应（Poisson effect）**

       * > **定义**：往一个方向拉一个东西的时候，两边会凹进去的现象；本质是它需要保体积——一端变长的时候，其他方向势必变小。

       * 用不同材料模型拉伸同一个小方块的演示里泊松效应显得比较弱，是弹性系数取得小的缘故——STVK 不太稳定，不敢用太大的力拉、怕它会炸掉。

### STVK 的软肋

   * **力-形变曲线的失效区**

       * 拉伸（$\lambda>1$）：力随形变增大，一切正常；压缩（$0<\lambda<1$）：压到一定程度抵抗反而越来越小，把所有点压到零（$\lambda=0$）时反而没有抵抗了。

       * 反转（$\lambda<0$）：力也会反转——四面体被反转之后不会回到静止状态，而是停在那个反转的状态上。

| 形变区间 | STVK 的表现 |
| :--- | :--- |
| 拉伸（$\lambda>1$） | 力随形变增大，一切正常 |
| 压缩（$0<\lambda<1$） | 压到一定程度抵抗反而越来越小，压到 $\lambda=0$ 完全没有抵抗 |
| 反转（$\lambda<0$） | 力跟着反向，停在翻转状态回不去 |

       * Neo-Hookean 避免了这个问题：压缩的时候力越来越大、甚至趋向于无穷大，最终能顶住、不会翻过去。

       * 真正的材料力学、结构力学和工程里 STVK 用得很少很少；图形学里用得多，因为大家有时想偷工减料、把事情搞得简单一点。

       * > **易错点** ⚠️：作业的小房子用的正是 STVK + 显式积分——抬得太狠，下面几条腿对应的四面体全被压塌、反转之后回不来；弹得太狠会直接炸掉。这个作业代码量最短，难点在读懂"怎么用有限元去计算力"。

   * **反转的判定与后果**

       * > **定义**：四面体的反转指某个顶点跑到了另一侧去——像一个气球被翻到另一侧的状态。

       * 验证方式：用之前算四面体体积的方式——如果反转了，体积会变成负的（凹进去了）。

       * 反转之后还能收敛、可以模拟成功，只是会非常怪异——压塌的腿趴在那里，回不去。

## 非线性优化与下降方法

   * **为什么学优化**

       * 隐式积分本身会变成一个非线性优化的问题；做有限元的论文主要就是在做优化——同样的优化问题、同样的非线性问题，怎么优化差别很大，一部分模拟引擎的效率就取自优化的能力。

       * 图形学用的方式、formulation 在计算物理、材料力学里一模一样；图形学关心的不是数学模型本身，而是怎么样算得快——模拟的模型基本固定了，但分辨率、顶点数量可以无限往上涨，计算量没有止境。

### 梯度下降与步长

   * **梯度下降（gradient descent）**

       * > **定义**：解 $\min_x f(x)$ 的基本迭代法——有一个初始位置，每次都朝负梯度的方向往前走一步，一步一步迭代、收敛到解上去。

       * 梯度是让函数值上升最快的方向、垂直于等位线；反着梯度方向走，就能最快地减少函数值。

       * 一个方向没办法一步到谷底：走到某个地方，再根据那个地方的梯度方向走一步……最终从原来的位置走到谷底——像一步步掉进坑里。

   * **步长（step size，$\alpha$）**

       * 走得太远：不但没下降、反而还上升了；走得太小：浪费步数——找到合适的步长是优化里经常讨论的问题。

   * **精确法**

       * > **定义**：沿给定方向找到一个能走到最优的步长。

       * 每一步都最优、收敛最快；但解这个步长本身又是一个非线性优化问题——问题套问题，这个 $\alpha$ 没法解，实际不太常用。

   * **回溯线搜索（backtracking line search）**

       * > **定义**：反复试错的步长法——初始步长故意取大一点，每次测一下用这个步长函数值下不下降；发现不下降就把步长乘一个 $\beta$（通常取 0.3、0.4 这样小的数）缩小再试，不断试、直到步长足够小、能让函数值下降为止。

       * 让函数下降的那个条件叫做 Wolfe condition。

       * 优点：特别简单、成本也比较小——只要计算一下函数值就可以，本质上是很简单的反复试错；做模拟的时候用得最多。

           ```text
           α ← 初始步长（故意取大一点）
           while f(x + α·d) 没有下降:
               α ← β·α        # β ≈ 0.3 ~ 0.4，缩小了再试
           ```

| | 精确法 | 回溯法（backtracking） |
| :--- | :--- | :--- |
| 思路 | 沿给定方向找最优步长 | 试错：不下降就乘 $\beta$ 缩小重来 |
| 收敛 | 每一步都最优，收敛最快 | 每步只保证下降 |
| 代价 | 本身又是一个非线性优化，得不偿失 | 只需计算函数值，非常便宜 |
| 实际使用 | 不太常用 | 模拟里用得最多 |

### 下降方向与下降方法

   * **下降方向的判定**

       * > **结论**：$d$ 是下降方向，当且仅当它与负梯度同侧；内积判据 $d^{\mathrm T}(-\nabla f)>0$——此时存在一个（小的）步长能让函数值真的开始下降。

       * 几何图像：在当前点画一条等位线的切线（正好垂直于负梯度方向），跟负梯度处在同侧的方向都是合理的下降方向，另一侧不合理。

       * 动机：随便找一个方向，有可能再怎么走都不可能下降；希望整个算法过程中永远都在下降、不白走一步。

   * **下降方法（descent method）**

       * 统一形式：$x_{k+1}=x_k+\alpha_k d_k$——把负梯度换成一般的方向 $d$、前面乘一个步长；配上步长保证每次都下降，得到 $x_0,x_1,x_2,x_3,\dots$ 最终得到一个结果。

   * **牛顿法作为下降方法**

       * 方向 $d=-H^{-1}\nabla f$；内积 $(-H^{-1}\nabla f)^{\mathrm T}(-\nabla f)=\nabla f^{\mathrm T}H^{-1}\nabla f>0$，只要海森矩阵（Hessian）$H$ 是正定的。

       * 海森正定的另一层意义：除了保证唯一解，它跟数值计算也有关系——最早的牛顿法不保证一定收敛；海森一定正定、配上步长（line search）每次都下降，就可以保证牛顿法收敛。

   * **正定矩阵修改梯度的大家族**

       * 任何利用一个正定矩阵去修改梯度的方法，$d=-P\nabla f$（$P$ 正定），都是一个下降方法——正负号相抵，同样保证内积大于零。

       * 作业里做衣服模拟、做隐式积分的方法能够起作用正是这个道理：用一个非常简单的对角矩阵作为 $P$，前面的小步长用一个常数替代——本质也是这么一个下降方法，所以能收敛、能 work。

| 方法 | $P$ 的取法 |
| :--- | :--- |
| 梯度下降 | 单位矩阵 $I$ |
| 牛顿法 | $H^{-1}$ |
| Projective Dynamics | 一个常数矩阵 |
| 另一些方法 | $H$ 的对角 / $H$ 的下三角 |

### 收敛与计算量的权衡

   * **总时间公式**

       * 总的计算时间 = 每一个迭代的时间 × 总的迭代量；不能说一个方法收敛得快就一定好。

       * 牛顿法收敛最快（用海森、二阶近似、迭代数量最少），但每一次迭代需要对系统做分解求解、这个成本很大，很多时候大家因此不用它。

   * **领域差异**

       * 工程（结构力学、材料力学）领域不在乎用什么方法、只要一个解，更多采用收敛快、方法直接的牛顿法；图形学很在乎计算时间、计算量、计算效率，因为它们决定应用场景。

   * **拟牛顿（quasi-Newton）**

       * 广义上可以把这一类方法归到一起；狭义上 quasi-Newton 是利用一种迭代的方式去对海森做近似——不太建议把这些方法都叫做拟牛顿。

       * 设计取向：让 $P$ 尽量接近海森（越接近收敛越好），另一方面又希望 $P$ 比较容易被解出来（迭代时间短）——图形学里总计算量是这两者的平衡，还要在不同的硬件上找平衡点。

   * **矩阵求逆的量级**

       * 一块 5×5 的布是 25 个顶点、乘 3 是 75 个自由度，矩阵是 75×75 的，高斯消元的计算量约 $75^3$——算矩阵的逆本身就慢。

## 碰撞检测的两阶段流水线

   * **碰撞的特点**

       * 很多概念都简单，但要自己做得很好，工作量大、算法复杂度特别高——跟弹簧、有限元模拟正好反过来：那些理论复杂一点、懂了之后代码相对好写；碰撞没那么多公式，处理起来特别麻烦。

       * 衣服（布料）的碰撞是所有碰撞处理里最难最困难的；能处理好衣服的碰撞，处理其他碰撞其实都容易——可以认为其他碰撞都是衣服碰撞的一个简化。

   * **两阶段流水线**

       * > **定义**：碰撞检测分两个部分——Broad phase collision culling（碰撞剔除）去除不可能出现碰撞的 pair；Narrow phase collision test（窄相碰撞测试）对这些候选 pair 具体做碰撞检测。

       * 动机：一万个元素两两检测就是一万乘一万的量级（去掉重复正好一半），差不多几千万次；上万个三角形的模型（如兔子）很常见，分辨率更高时两两检测的成本还会更大、无法承受。

       * Broad phase 输出候选 pair（pairs candidate）——不知道有没有碰撞，但离得比较近或有出现碰撞的趋势；Narrow phase 分 DCD（discrete，离散）与 CCD（continuous，连续）两种检测模式，输出真正有碰撞的 pair。

           ```text
           海量元素（三角形 / 点 / 四面体……）
                   │
                   ▼
           Broad Phase：碰撞剔除 —— 剔掉不可能碰撞的 pair
                   │  输出：候选 pair（pairs candidate）
                   ▼
           Narrow Phase：具体碰撞检测 —— DCD（离散）/ CCD（连续）
                   │  输出：真正有碰撞的 pair
                   ▼
                碰撞处理（响应）
           ```

### 空间划分：Spatial Hash

   * **Spatial hash（按空间划分，spatial partitioning）**

       * > **定义**：把整个 3D 空间用一个网格划分成很多小格子，每个三角形（或任意元素）根据位置存进它占有的格子；查询逻辑一句话——谁跟我共用格子，谁就是候选碰撞对象。

       * 例：t0 占 0、4、5 三个格子，t3 占 5、6、9、10——5 号格子里 t0 与 t3 共存，就把 (t0,t3) 作为 pair 输出送检。

       * 三角形在运动：把运动轨迹整个当成一个物体保存，按轨迹把占有的格子空间稍微放大（原来占 0、4、5，运动后跟 1 号格发生关系，就存 0、1、4、5）。

   * **直接存格子的问题**

       * 三维格子数爆炸：1m×1m 的空间按 1cm×1cm 划格，二维要 100×100 个，三维就是 100×100×100，存储量一下就上去了。

       * 事先不知道每个小格子里要存多少三角形，绝大多数格子一个都没有——花大量内存给每个格子配数组，而这些内存不是按需分配、大量浪费。

   * **排序：改成按需分配**

       * 把每个三角形展开成 (格子编号, 三角形编号) 记录——t0 占 0、4、5 就写成 (0,t0)、(4,t0)、(5,t0)；数组长度基本跟三角形数量成正比、跟整个空间大小没有直接关系（一万个三角形只需三四万条）。

       * 给记录按格子编号排序后，每个小格子对应数组里一段连续区间，记下起始、结束位置即可查询格子里存了什么；没有存任何三角形的格子（如 1 号格）在数组里直接消失。

   * **访问局部性与 Morton code**

       * 内存体系里有 cache（缓存）来优化内存访问，访问越局部越能发挥作用；碰撞检测永远想访问邻居，但按行列编号只有横向邻居的访问比较连续，纵向、深度方向的邻居访问跨度非常大（三维更严重）。

       * Morton code：把格子编号用 Z 字形图案编排——2×2 空间先按 Z 形访问四个格子，再对每个格子嵌套同样的 Z 形细分到 4×4、8×8……越相近的邻居在访问顺序里挨得越近、内存地址更加接近；三维同理、图案稍复杂；编码一般有现成代码可参考。

### 包围盒层级：BVH

   * **包围盒层级（bounding volume hierarchy，BVH）**

       * > **定义**：不对空间、而对物体划分——物体不是一堆毫无规律的点而有结构（机器人、人体），把部件逐层用包围盒抱起来、一层一层向上并，最后整个物体是根节点上的一个包围盒，构成一棵树。

       * 外部查询：先检查目标跟根节点的包围盒有没有相交——不相交则必不可能有相交、直接结束；相交则检查孩子，朝有相交的分支一直往下走，直到最底层具体的某一个三角形。

       * 对自身的三角形查相交也是同一个套路：一层一层遍历过来，定位到跟哪些底层三角形相交、哪些不相交。

   * **自相交的递归检测**

       * 自相交是碰撞检测中很重要的一部分；对节点 a 分两部分：自相交可能发生在左、右孩子各自内部——分别对两个孩子递归调用同一个检查；也可能发生在两孩子之间——先看两孩子包围盒是否相交，相交就换一个函数交叉递归检查它们的孩子。

           ```text
           selfCheck(a):                     # 检查以 a 为根的子树内部的自相交
               selfCheck(a.b)                # 左子树内部可能自相交
               selfCheck(a.c)                # 右子树内部可能自相交
               if overlap(a.b, a.c):         # 两棵子树之间可能相交
                   crossCheck(a.b, a.c)

           crossCheck(b, c):                 # 检查两棵子树之间
               for b' in b.children:
                   for c' in c.children:
                       if overlap(b', c'):
                           crossCheck(b', c')    # 有相交就递归往下查
           ```

   * **包围盒的形状**

       * AABB（轴对齐包围盒）：相交检测只需检查 x、y 各方向上区间有没有重叠——某个方向上有缝就不可能相交；不需要任何数值计算、只比大小，因此受欢迎、大家用得最多。

       * 包围球：把两个球心算一个距离、跟半径的和做比较，计算量稍微多一点。

       * OBB（不要求跟坐标轴对齐、可朝任意方向的包围盒）：实际操作中用得不多。

   * **局限与改进**

       * BVH 能剔除相距非常远的区域（手臂与腿一下就剔除掉），但对周遭很难有效剔除——判断一个三角形跟它的近邻之间有没有碰撞，得把整棵树走一遍。

       * energy-based self-collision culling：对每一个区域计算一个形变能量，设一个阈值判断这个区域有没有可能出现相交、再决定要不要检测——原理是静止状态没有相交、因形变才可能出现相交，形变越大可能性越大。

       * 适用边界：衣服模拟里大形变但并无相交的情形判断不出来、不太适用；对本身就很少出现大形变的物体（一些弹性体）比较有效。

   * **两种套路的取舍**

| 对比维度 | Spatial Hash（对空间划分） | BVH（对物体划分） |
| :--- | :--- | :--- |
| 实现难度 | 特别容易写，自己动手写碰撞的首选 | 写起来比较麻烦 |
| GPU 友好度 | 高，很多现成代码基于它 | 低——树结构不适合 GPU 存储 |
| 更新成本 | 物体每动一次都要重算格子归属（排序可把成本尽量减小） | 树结构不动，只需沿树更新包围盒 |

## 离散与连续碰撞检测

   * **两种模式对 pair 的需求**

       * 离散式的碰撞检测（DCD）需要的是"三角形—边"这样的对；连续碰撞（CCD）需要的是"点—三角形"对和"边—边"对。

       * > **注意**：spatial partitioning 和 BVH 都可以作为后面两种检测模式的输入——不是各只能服务某一种，只是针对不同检测模式对 pair 的需求不一样。

### DCD：离散相交检测

   * **离散碰撞检测（discrete collision detection，DCD）**

       * > **定义**：检测当前这个状态下物体有没有自相交、有没有跟别的物体发生相交——严格讲它检测的是相交（intersection）而不是碰撞，没有任何运动的概念，永远只有"某一个状态"这一个瞬间。

       * > **易错点** ⚠️：边-三角形求交里的 $t$ 不是时间——这里没有时间的概念，$t$ 代表的是交点在这条边上的差值比例。

   * **边-三角形相交检测**

       * 分两步：第一步对一条边，把它跟三角形所在的那个面做相交检测、求出交点对应的参数 $t$，交点位置为 $p=(1-t)\,x_1+t\,x_2$（$x_1,x_2$ 是边的两个顶点）；第二步检测这个交点是否落在三角形内部——是就表示有相交，不是就没有。

       * 边-三角形的相交检测是三角形网格最基本、最基础的检测，任何其他复杂的检测都可以利用它来实现；方式比较简单、也比较 robust。

### 隧穿效应与 CCD

   * **隧穿效应（tunneling effect）**

       * > **定义**：物体运动得特别快时，可能穿透另一个物体而没有被检测到的现象。

       * 场景：两个三角形上下互换位置——模拟前、后两个状态都没有任何相交，但中间某一时刻可能发生了碰撞、彼此穿过去了；只单纯做相交检测就发现不了。

       * 概率边界：四面体模拟、刚体模拟、体积比较大的物体隧穿概率比较低；物体特别薄——比如衣服、兔子耳朵那种特别薄特别细的部位——会出现 tunneling artifact，真的穿过去。

       * 缓解：把步长搞得小一点、让物体运动得慢一点，容易发现一点；根本上避免是不只检测两个状态上的相交，而应该去检测碰撞（两个状态之间的相交）。

       * DCD 的好处：效率比较高、比较简单、比较稳定。

   * **连续碰撞检测（continuous collision detection，CCD）**

       * > **定义**：把前后两个状态只当作时间的端点，检测它们之间有没有发生过相交。

       * 对三角形 mesh 而言，有两种基本的连续碰撞元素：点-三角形与边-边。

   * **点-三角形检测**

       * 思路：求在什么样的时间这四个运动点落在同一个平面上——四点共面意味着这四个点构成的四面体体积为零：$V(t)=\frac{1}{6}\,(x_3(t)-x_0(t))\cdot\left[(x_1(t)-x_0(t))\times(x_2(t)-x_0(t))\right]$。

       * 假设每一个点的运动都跟时间是线性关系，各位置差都是线性函数；点乘与叉乘两次乘法之后，得到一个关于时间 $t$ 的一元三次方程 $a\,t^3+b\,t^2+c\,t+d=0$——系数不用特意记，把体积公式展开自然就得到。

       * 解出来的 $t$ 就是相交的时间，有了相交时间就知道相交的位置；再检测 $t$ 时刻 $x_3$ 这个点是否落在三角形内部——是则这个点和三角形发生相交（碰撞），否则没有。

   * **边-边检测**

       * 两条边、四个端点都在运动，套路跟点-三角形非常像：先看什么时候这两条边满足相交的条件，同样得到一个一元三次方程；解完之后看那个时刻两条边是否真的相交——有相交就输出、检测到碰撞。

       * 为什么必须专门做边-边：两个三角形有可能只在边跟边上发生相交、点-三角形永远不发生相交——两个点各往各的方向走，两边就在边上一交叉，相交只发生在边上。

       * > **结论**：点-三角形和边-边两类测试都要做，才能保证整个 mesh 完全没有任何相交；少做一类，就会漏掉一类真实的碰撞。

       * 三角形对三角形不需要直接做判断：拆成点-三角形和边-边——先拿一个三角形的三个顶点跟另一个三角形做点-三角形判断，再把边跟边拿去做判断；基本元素之间都没有检测到相交，两个三角形必不可能有相交。

   * **代价对比**

       * DCD 里对应的方程是一个线性关系，直接通过一个除法就可以解出来；CCD 需要解一元三次方程，光这一步就贵了很多。

       * CCD 比 DCD 要慢很多，但检测的计算成本其实不是大头——真正的大头在前面做剔除的部分，这里计算成本高一点没什么。

### 一元三次方程求解

   * **求根公式的坑**

       * > **易错点** ⚠️：一元三次方程和一元二次方程一样有公式解，但求根公式需要开立方根、开根号这类运算数值误差很大——单精度浮点的相对误差约 $10^{-7}$，开立方后误差指数约 $7\div3$，数值误差变成 $10^{-2}$ 的量级（约 1%），已经相当惊人；尽量用数值方法去解，不要用求根公式。

   * **二分法**

       * 数值方法里不建议用牛顿法，二分法会比较简单；且有一个特别大的好处：只需知道 0 跟 1 之间有没有根——0、1 对应前后两个状态，区间外面有没有根不需要。

       * 流程：一开始设 $[0,1]$ 为区间，对它二分成一半，分别检测这两边有没有根（判断是不是都在同一侧、中间有没有拐点等）；某一半有根就对它再做二分，一步一步细分下去。

       * 多个解的处理：把 0 跟 1 之间所有的解先算出来，然后一个一个检查、看哪一个满足条件，找到真正发生碰撞的那一个。

   * **epsilon 放宽**

       * CCD 有浮点精度问题（求根以及浮点运算带来的），一般给一个 $\epsilon$：不需要严格保证根在 0 到 1 之间，把区间放大成 $[-\epsilon,\ 1+\epsilon]$。

       * 收益与代价：可以让检测更加稳定一点，但有可能导致 false positive——其实并没有任何碰撞却认为有。

       * 游戏里一般来说用的单精度比较多，GPU 也是以单精度为主，开发时要特别注意浮点误差的问题。

   * **CCD 的工程定位**

       * CCD 比较难以实现，自己写也经常出状况、是有挑战性的事情；想自己写游戏引擎（尤其游戏开发）的话不太建议自己写 CCD——离散的碰撞检测容易很多。

       * 碰撞代码需要积累：写一次有一点经验但会出现各种问题，写第二次、第三次、第四次才慢慢有经验、写得更好——概念简单、做好不容易。

       * 最早做连续碰撞处理的一篇工作，模拟倒很简单（很简单的显式积分），很大的精力都花在碰撞处理上——碰撞需要小步长的话，模拟本身的步长也不会特别大，横竖都需要小步长做精细的碰撞处理。

## 碰撞响应

   * **问题的起点**

       * 初始状态待在一个安全区域里（没有碰撞）；dynamics 模拟求解之后得到的状态有相交、有碰撞、不安全了——碰撞响应要做的就是把状态弄回没有碰撞的状态。

       * 两个比较标准的思路：内点法（Interior Point Method）与冲击区优化（Impact Zone Optimization）。

### 内点法

   * **内点法（Interior Point Method）**

       * > **定义**：从安全的位置出发，朝着模拟给出的位置一步一步往前走，保证走的过程中永远都在安全区域内，直到找到最终解——走到不能再进一步优化这个位置为止；这个位置理论上也是离想要的模拟结果最近的位置。

       * 名称由来：永远是在安全区域的内部。

       * 慢在两个地方：要保证步步安全，每一步很有可能不能太大、都要用小步长，不然一步就出去了；初始位置可能离目标位置非常远，要走很远很远才到目的地。

       * 好处：永远安全也就意味着永远都可以成功、不存在失败的问题——哪怕没有收敛到位、走得很慢，中间停下来结果也可以接受：没有相交就可以继续把模拟跑下去，有相交的结果才是不能接受的。

   * **对数障碍函数（log barrier function）**

       * > **定义**：内点法一个比较常见的例子——利用一个 log 函数的能量产生排斥力；距离越来越短，log 的互斥力会变得无穷大、产生的力也变得无穷大，只要采用足够小的步长就能把物体推出来。

       * 图形学里大家有时不太喜欢互斥力一直都存在（原来的 log 函数定义到无穷远），所以会给它做一个截断、把 log 函数的影响力限制在一个范围之内（近期的一些论文用到这种截断）。

       * 具体实现：定义优化目标——让点的位置跟目标的位置足够接近（定义一个距离函数），增加一个关于距离 $d$ 的 log 排斥项，然后用梯度下降法或别的什么方法模拟；IPC 那篇论文用的不是梯度下降、是牛顿法——有数值优化基础的各种方法都可以拿来做。

       * 步长很关键：步长太大就有可能跑到安全区域外面；每走一步都需要保证没有碰撞，也就是需要碰撞检测——所以内点法计算量其实挺大，每走一小步都要反复碰撞检测。

   * **约束优化路线**

       * 另外一套做法把问题搞成一个优化问题，跟前面有点像但不用能量、用一个约束（constraint）来做优化。

       * 约束优化有各种套路，比如增广拉格朗日（augmented Lagrangian）方法；没有约束优化基础的话比较困难，了解有这么一系列套路即可。

### 冲击区优化

   * **冲击区优化（Impact Zone Optimization）**

       * > **定义**：思路胆子比较大——不关心过程安不安全，从这个不安全的结果出发反复地优化它、进行投影操作，只要最终能够回到安全区域就可以。

       * 快的原因：模拟出来的点一般离安全区域不会特别远、可以很快投影回去；物体一般不可能所有地方都有碰撞，只是在某一小区域上有碰撞——只需集中优化那一小块区域（Impact Zone 名称的由来），其他没有碰撞的地方不需要动。

       * 步长胆子大：可以用很大的步长，只要最终结果能够回到安全区就可以接受。

       * 缺点：有可能不成功——时间步长很大、模拟结果离安全区域特别远的时候，可能没有办法顺利回到安全区域、就没法继续下去了；结果也有可能没有办法保证把碰撞处理掉。

   * **早期的冲击式约束做法**

       * 最早的连续碰撞处理工作不只做了碰撞检测也做了碰撞处理，用的是冲击区优化式的方法、以约束来实现：发现两个物体很近，就给它一个冲击、硬生生地拉出一段距离来——差不多是 PBD 约束的思路。

       * 这种方式都是在进行一种尝试：根据碰撞的趋势给这些点、三角形施加虚拟的冲量、试图让物体分开，不能保证最后的结果就真的没有碰撞。

| 对比项 | 内点法 | 冲击区优化 |
| :--- | :--- | :--- |
| 过程 | 步步安全，始终在安全区域内 | 过程可能不安全，终点安全即可 |
| 速度 | 慢：步子必须小，初始位置可能离目标很远 | 快：结果一般离安全区不远，很快能投影回去 |
| 优化范围 | 全程照看 | 只优化有碰撞的那一小块区域 |
| 步长 | 只能小步走，不然一步就出去了 | 胆子大，可以用很大的步长 |
| 失败风险 | 不存在失败，中途停下也可接受 | 有可能失败，回不到安全区域 |

### 兜底与实战组合

   * **刚性冲击区（Rigid Impact Zone）**

       * > **定义**：两种方法都试了还搞不定时的最后一根稻草——回到前一帧（没有相交的状态）；发现有一些物体缠在一起、有可能发生相交的时候，把这个区域整个冻住。

       * 区域被封冻起来之后里面就没有相对的位移，整个区域被当成一个刚体、封印起来，也就没有办法产生碰撞；非常简单、也非常安全。

       * artifact 也很明显：整个区域被锁死、没有相对的运动。

       * 使用趋势：早期的一些论文里用得比较多；近十年、甚至近二十年以来的论文一般来说很少采用。

   * **实战组合流程**

       * 比较现实的思路是把前面这些串起来：先用快的冲击区优化兜住大多数情况；剩下的难缠案例按计算预算二选一。

           ```text
           连续碰撞检测（CCD）
                 |
                 v
           Impact Zone Optimization        <-- 先用它: 快, 相对有效率
                 |
                 +--- 都搞定了 ---> 继续模拟
                 |
                 +--- 搞不定 ---> 内点法（慢, 但安全）
                                 或 Rigid Impact Zone
                                    （计算量不允许时: 把碰撞的区域锁死）
           ```

### 相交解除

   * **相交解除（untangling crossings）**

       * > **定义**：离散（非连续）碰撞处理的方法——相交不是一个灾难，只关心当前这个时刻有没有相交；有就把它解除掉，解除了还没解除干净不要紧，下一轮再想办法再解除。

       * 前提条件：不要求一定是没有相交的——可以有相交，但要想办法把它解除掉；碰撞时间、解一元三次方程这些太复杂的东西都不管。

       * 使用动机：前面那种想完美解除碰撞的方案失败时的兜底；处理用户的非法操作——比如 CAD 设计软件里很常见，用户拽着模型就产生相交了。

   * **SDF 与布的边界**

       * 对有体积（volume）的物体而言相交处理比较简单：检查这个点是不是落在物体的内部，是就把它朝着物体的外部推出去——给物体定义一个 SDF（signed distance function），利用 SDF 把点推出去；作业里球跟布料的模拟用的就是这条思路。

       * 布不能用 SDF：布不是封闭的曲面，没有办法利用封闭曲面来定义 SDF；布有正反面，但正反面并不代表里外——对一块布来说，"里面""外面"这个概念本身就不成立。

### 布料解缠

   * **按面积分段（《Untangling Cloth》）**

       * > **定义**：利用相交对布进行分段，判断哪一段大、哪一段小——小的那一段意味着是产生相交的那一段；判断出来之后把点往相应方向挪，把这个相交解除掉。

       * 判断歧义：相交发生的时候判断不出来到底是中间、左边还是右边发生了相交，只能根据面积大小——面积大的地方是没有相交的原始状态，面积小的是刚发生相交的状态；如果中间区域很大，则有可能是两边发生了相交。

       * 局限：没有办法很好地处理边界上的相交（内部的相交比较容易处理，边界上难以处理）；比较依赖对整个面积的评估、要比较各个分段的大小，在 GPU 上实现比较困难。

   * **相交曲线最小化（《Resolving Surface Collisions through Intersection Curve Minimization》）**

       * > **定义**：发现相交的时候会有一条相交的曲线，用最小化的方式让这条曲线变短——曲线长度变成零，也就意味着相交解除了。

       * 优点：边界上有相交，通过缩短相交曲线的方式同样可以处理；想了解在游戏里、GPU 上怎么处理衣服碰撞可以参考它。

       * 局限：基于局部观察、对曲线做局部优化的方式，有一些没有办法处理的状态。

### 经验与取舍

   * **摩擦放在哪一步做**

       * 比较简单的套路：把摩擦放到后面去做——先把碰撞全部检测完、全部处理完，把摩擦的力作为后面的后处理过程；缺点是不够精确。

       * 也有人把摩擦和碰撞放在一起处理、一起优化，那样优化起来更麻烦；一般来说很少做自碰撞的摩擦处理；跟刚体进行碰撞、摩擦相对容易一点。

   * **要物理，还是要快**

       * 碰撞处理本身的第一首要目标是没有相交、没有碰撞，物理反而是次要目标——真的要很物理：很小很小的步长、很大的 repulsion、内点法，肯定很物理但效率非常非常低。

       * 游戏开发的取舍：角色一般用一个胶囊的形状来实现，车就用一个盒子做简单碰撞；图形学就是需要在效果和效率之间尽量保持平衡——硬件能力越来越高，效果要求也会越来越高。

   * **与早期简化处理的区别**

       * PBD 时代的碰撞处理很简化：基于 SDF 来做检测，impulse 是一种离散的响应方式——只检测状态上的相交，物体猛地穿到另一侧、中间没检测到时 impulse 就没办法处理。

       * 那些方式是在特殊情况下可以用的（比如地面无限厚，就不存在隧穿、不存在穿透的问题）；这里讲的检测与响应以自碰撞、自相交为主，是比较通用的方式——物体不能发生形变（刚体、地面、简单球面）时碰撞响应容易，会形变又很薄（像衣服）就难得多。

   * **难度的定位**

       * 碰撞处理是动画里面最难的一个问题：有限元、衣服 solver 都是相对标准的套路，学明白了数学上都好处理；碰撞里面有很多算法的问题——比如一元三次方程求根公式的坑，没写过就会踩到。
