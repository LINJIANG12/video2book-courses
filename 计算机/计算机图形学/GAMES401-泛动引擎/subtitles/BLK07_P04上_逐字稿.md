首先简单回顾一下刚体动力学的一些基础。刚体动力学实际上更简化的话，其实可以理解为质点。质点是一个简化的模型，因为现实中实际上是不存在这个东西的，它假设具有一定的质量，但是不存在体积或者形状，这个时候当然也就不需要考虑旋转。所以对于一个质点的运动，它所需要的物理量其实比较简单，主要包括这里边有质量、有位置、有它的速度或者加速度、力，这些最基本的在高中物理里边应该都学过了。

如果已经知道这些物理量之后，接下来实际上要做的就是怎么让质点动起来。这里边实际上最常见的就是牛顿第二定律，标准形式当然就是质量乘以加速度等于力。当它积分，它的一个离散形式实际上就变成，相当于在 $\Delta t$ 时间步里边，$F/m$ 实际上就相当于它的加速度，在 $\Delta t$ 时间里边它应该更改多少速度，然后去更新它的速度。速度更新完了之后，当然进一步去更新它的位置。

因为我们实际上是一个时间序列，所以在时间片上就需要对它分片。比如我们初始化的时候，它的三个状态变量包含它的位置、它的速度、一个初始的力。有了之后，往后的话一步一步去更新它整个运动的状态，包括力其实也是在运动过程中逐步地去调整。反映在它的运动轨迹曲线上，你可以看到在受外力作用下，实际上它会形成一条运动曲线，这个东西就比较简单了。

连续的方程最终转换成我们在计算机上实现的话，实际上都离散成了一堆离散的状态，比如第 0 个时刻、第 $\Delta t$ 的时刻、$2\Delta t$ 的时刻，每个时刻相当于需要积分，然后不断地去更新它的运动状态，这样最终就形成了完整的一个运动轨迹。

对应到这个我们再拓展一下的话，刚体其实整个思路是一样的，但是这里唯一要更复杂的就是刚体包含一个旋转。旋转跟平移有很多东西是相似的，其实你发现下面列的物理量也是一一对应的。比如质点里边有一个质量，刚体跟质点不一样的地方在于刚体是有形状的，所以它在更新质量的时候，我们一般用它的质量矩阵，因为它实际上包含 $x, y, z$ 三个方向的一个衡量，所以这里一般用质量矩阵去替代。因为在形状上有一个分布，它不是单纯集中到某一个点上的质量。

对应到转动的话，质量对应到转动量实际上是惯性张量。张量什么概念其实之前应该讲过了。从直观上去理解，$I$ 代表你的质量越大，改变平移就越困难；转动的话也是一样的，惯性张量如果越大的话，越不容易让它发生旋转，这两个概念实际上差不多。

对应的平移有位置坐标，对应到旋转空间里边就会有旋转矩阵，或者实际上也可以是四元数，这两个东西是等效的，可以一一互相转换。同时位置或者旋转要更新的话，那就涉及到平移的速度，转动的话有个角速度。再往后要更新速度跟角速度，分别需要计算它的平移加速度以及角加速度。

但这里边有个不太一样的地方，平移整个实际上是一个线性空间。在线性空间里边去算速度，实际上可以直接通过位置求导算出来。但是在转动空间里边这个不一样，转动空间不能直接求导，因为它不是一个线性空间，不能直接说对旋转矩阵求偏导，比如里边是一个 $t$ 的函数直接求偏导，或者对四元数求偏导，这样一般是不太对的。后面会具体给出公式，之前应该也讲过了。所以这里边有一定的差别，主要是跟平移的线性空间不太一样。

最后涉及到还是外力，一个是平移的外力，旋转的话主要是扭矩，在扭矩作用下实际上会发生旋转。

刚体的运动状态更新跟质点是很类似的，在外力的作用下主要分成两部分：在外力作用下要去更新平移的速度，还有一个质心的位置；旋转那部分也是一样，需要考虑在外力作用下。因为刚体是有形状的，外力作用在不同点上产生的扭矩是不一样的，所以这个时候需要考虑旋转的姿态，包括整个计算惯性张量的时候也需要把旋转的变动考虑进来。

后面那两个方程其实是比较相似的，角速度的话需要角加速度乘上一个时间片，然后再去更新角速度。

再后面那个看着很诡异，实际上因为刚才前面提到旋转空间不是一个线性空间，所以旋转的时间导数实际上要更复杂一些，这里边实际上需要两个四元数相乘。这个是当前的角速度，同时因为角速度是一个三维的向量，四元数是一个四维的向量，两个相乘的话三维向量需要补一个 0，才能把这两个乘起来之后去更新四元数。四元数算完之后再回过来进一步计算旋转。所以整体也是不断地迭代，相当于从一个初始的状态，然后到 $\Delta t$……

第一步的时间步，到第二步时间步等等，然后再往后就逐步地更新了。当然这个过程看着很简单，但是实际做的时候就会比较复杂。主要复杂在哪？就是主要体现在，因为如果我们现在打个比方不考虑外力，这个东西它实际上你用任何的积分方法其实都可以去实现，比如欧拉积分，不管显式隐式都比较简单。但是实际上这里边的一个问题就在于，很多时候我们这个力，包括这个扭矩，实际上是不知道的。所以比如里边包含大量的刚体的时候，我们是需要去计算这个力包括它的扭矩到底是多少，有了那个之后，才能进一步地去更新那个状态。所以整体的话，你看刚体动力学仿真的流程，它其实就包含几步。当然这里边核心的你可以理解为其实就在算刚体的力或者扭矩。当然不同方法可能不一样，如果是基于速度层面的，那可能直接算力跟扭矩；当然如果基于位置的话，有可能直接是更新位置了。这个东西其实有一定的一个差别，但是笼统地讲，它其实主要分为两个阶段。首先第一步实际上就是要去做一个碰撞检测，我们要找出来到底哪两个刚体之间相互之间发生了一个碰撞。然后这个碰撞检测做完之后，这个时候碰撞触点之间相当于通过建立一系列的约束，然后再进一步地去求解，使得最终满足一定约束的一个状态。当然这个后面我们再会细讲。

这里边第一阶段的话其实会进一步地拆分成两个更小的步，一个叫宽阶段。宽阶段的主要一个目的其实就是为了加速整个碰撞检测的计算，相当于预先给它剔除掉，快速剔除掉哪些不太可能发生碰撞的这些物体。完了之后再把潜在的有可能会发生碰撞的物体，进一步地去做碰撞检测，最终找到这个触点。所以这个实际上是代表了一个完整的刚体仿真的流程。

接下来我们每一步再具体来看一下到底在做什么事情。首先第一个是叫宽阶段碰撞检测。这个阶段这次课主要讲的主要包含三部分内容：一个是包围盒；第二个是空间划分算法；另外最后，因为空间划分算法的话其实包含几类，比如CPU更适合的，或者GPU更适合的。因为这次课我们主要讲的还是面向GPU，怎么能开发出一个高效的并行计算算法，所以针对最后层次化包围盒这个结构，重点后面我会去讲叫 Linear BVH 的这么一个算法。它实际上是在 GPU 上运行的一个算法，它主要包含像 Morton 码，包括怎么并行构建、怎么并行遍历等等这几部分内容。

接下来我们就看一下什么是包围盒。其实包围盒的主要目的主要是为了快速剔除掉不太可能发生碰撞的物体，这样的话就可以进一步降低计算量。这个怎么理解呢？比如这里图上画了几个几何体，我们如果现在打个比方，两两之间直接就开始算，那你发现每一个物体它实际上都包含了非常复杂的几何结构。这个时候如果你直接在复杂的几何体之间去做碰撞检测的话，这个计算开销实际上是比较大的。因为比如这个牛、这个汽车，都可能离散成三角网格的话，实际上会包含大量的比如边边检测、点面检测等等，这个开销会比较大。这个时候怎么做呢？我们希望把这个模型简化成一些比较常见的、运算比较快的一些简单的几何体，就跟比如上次课我们讲的像这种 AABB。AABB 是什么概念呢？其实就相当于找这个物体的一个最小的一个紧致包络。当然这里边有个特点，它整个边实际上是跟轴对齐的，所以叫 axis-aligned。比如跟 $X$、$Y$、$Z$——当然三维的方向还有一个 $Z$——它实际上是跟 $X$、$Y$、$Z$ 三个方向整个边是对齐的。这种结构会有个什么好处呢？上次课我们也提了，它实际上只需要两个顶点就可以定义这么一个 AABB 的结构。另外计算的时候，它比较的话实际上也只需要用坐标去比较，所以整个计算非常地快。

第二种结构，当然这个有个不好的地方，因为整个是必须得是轴对齐的，也就是说它有可能对于某些特定的结构，比如像对于叶子，它实际上有可能不会特别地紧致。这里边当然如果要做到更加紧致的话，实际上就可以用中间的比如 OBB 的这个结构，就相当于对 AABB 做一个旋转。比如有些方向，像这个叶子沿着斜线方向实际上是比较长的，所以可以定义一个这么沿着斜线方向的长方体。这种就比较适合于相当于那种比较狭长的那种结构，这样的话可以增加碰撞检测的精度。

当然还有一种也比较常见的，实际上就是叫所谓的包围球。相当于它定义一个包含这个物体的最小的一个球体。当然从计算角度来讲，实际上最简单的应该是 AABB，因为无论后面的两个，实际上都还是有一定的一个计算量。最左边的理论上用的是最多的，所以后面的话我也是结合这个 AABB 来讲怎么用这个结构来做空间加速。

也就是说这个时候我们如果打个比方，对每一个物体都定义了一个 AABB 的话，实际上就相当于把原来那个物体简化成了一堆 AABB 的 box。我们事先去判断的话，就不需要对里边的每一个几何单元去做判断，而是直接对它的 bounding box 先预先去计算一下。比如这个牛跟车，两个之间它的 bounding box 如果是不可能发生相交的话，那也就意味着它内部任何的一个点也不可能跟汽车发生碰撞。同理也是类似，你做别的 pair 的话也是一样的。当然你会发现比如右面的两个，如果 bounding box 发生碰撞了，这个时候才需要进一步地去检测它实际上到底在哪个点发生碰撞。

定义了这个结构之后，接下来我们需要用一些算法怎么能把碰撞的那些 pair 给快速地找出来。比如像这个云跟这个叶子，它已经发生碰撞了，那它有可能存在进一步需要检测的一个可能性，这样的话我们需要把这个东西记录下来。

这里边传统的比如像 CPU 里边用的比较多的，实际上叫做一个叫排序扫描线算法，或者排序扫描算法。这个是什么意思呢？如果我们现在对于每一个物体已经定义完了它的 AABB 的包围盒，它其实在每一个方向上——因为整个是一个三维结构——比如我们可以先看沿着 $X$ 方向，可以把每个 bounding box 的起点跟终点实际上都投影到 $X$ 轴的方向上面。所有的 bounding box 它的起点跟终点都投影过来之后，它首先要做的就是需要根据起点跟终点做一个排序。整个排序完了之后，接下来再去挑潜在的碰撞对的话，其实就比较简单了。

具体做的时候怎么做呢？它第二步实际上就叫一个扫描的算法。第一步是排序，排序完之后第二个实际上是一个扫描。扫描怎么做呢？实际上就是从最左边打个比方从 $b_0$ 开始。

对，直播间里有问 GPU 上排序扫描不太合适？对，这个我先讲，因为刚才也讲实际上是一个 CPU 的算法。后面逐步地，因为最终的话实际上我们会去讲 GPU 的算法，所以这里我只先给大家科普一下有哪些算法。

如果我们具体做的话，如果按 CPU 上来做的话，你会发现怎么做呢？首先我们按照顶点的刚才排序的顺序，从左边开始逐个地去遍历。这个时候当碰到某个 bounding box 的起点之后，需要把这个东西加到 active list 里头。再往下到下一个点，这个时候你会发现 $b_1$ 其实也是它的一个起点，这个时候就需要把 $b_1$ 也要加到它的 active list。再往下的话，如果到 $e_0$ 了，$e_0$ 代表的是什么呢？就是你一个 bounding box、一个物体它的区间就已经结束了。这个时候实际上要去判定一下，一个结束的点出来之后，你要去判定一下 active list 里头到底包含哪些起点。也就是这里边所有的起点跟最终这里出现的，实际上是发生碰撞。比如你这里边已经有两个，然后这里又有一个 $e_0$ 之后，实际上跟前面那两个点是……

它们有相交，也就意味着在此时，$B_1$ 代表的起点的物体跟终点的 $E_0$ 实际上有可能会发生碰撞。所以这样的话，也就是从左到右逐步地去完成这么一个过程，把潜在的碰撞对，也就是沿着 $x$ 方向的碰撞对就可以找出来。当然这里边在 $x$ 方向做完之后其实还不够，因为标准的排扫算法其实要做三遍，一个是在 $x$ 方向，完了之后需要把整个投影，因为比如像这两个物体在 $x$ 方向其实是相交的，但是发现在 $y$ 方向其实是不相交的。所以这样的话其实需要在 $x$、$y$、$z$ 三个方向分别去做一遍，最终才能确定哪些可能是一个潜在相交的碰撞对。

但是刚才直播间里有同学问了，说这个东西不太适合 CPU 实现？这里边为什么不太适合，主要有两个点：一个是你发现在这里边需要有一个 active list，这个东西实际上是一个动态的结构。极端情况打个比方，我们可以假设一下，比如这里边我们有一个特别大的物体，它跟所有的物体都相交，这个时候会导致整个 active list 数据结构会非常的大。最终有可能，因为我们知道 GPU 里边其实无论是寄存器也好，或者 shared memory 也好，其实都比较小。这样的话实际上都不太适合在 GPU 上去运行。

当然因为整个这种算法的效率实际上如果按复杂度来讲其实是比较高的，所以一般来讲在 CPU 的一些引擎里面用的可能比较多，比如像 Bullet，比如像它有一个叫 `btAxisSweep3` 的这么一个实现，大家有兴趣可以去看一下。

接下来我们看一下，如果我们现在希望做并行算法，有什么数据结构来做这个事情？最常用的其实就是均匀网格。均匀网格什么意思呢？相当于就这个图画的，假设我分配一个足够大的空间均匀网格覆盖住所有的物体。覆盖住了之后，它实际上接下来会去判定每个物体跟背景网格的格网点到底跟哪个格网点相交，在那个格网点记录一下它的 ID。这个时候再进一步如果去碰撞检测的时候，比如这个苹果，它跟周围的四个格点相交了，在格点上记录一下苹果的 ID。同时后面它要去寻找相邻的格点，去判定相邻的格点有没有可能也是落在这个里边。

这种方法其实非常适合 GPU 并行来做，因为发现它整个存储空间是连续的，这个其实是比较高效的；第二其实整个计算也完全可并行。但是这里有一个问题，因为我这里特意画了一个特别小的物体，当物体跟网格格点大小类似的话，那实际上还好，因为这样的话像这个苹果充其量占的是四个格。但是有些物体有可能会特别大，这样的话它实际上会占的格子非常多。在跟格点相交的时候，比如同样的用一个线程去处理这个牛，一个线程去处理这个苹果的话，不同线程之间的计算量差别都会非常大。所以这个时候它整个负载不是特别均衡。

而且包括还有一个什么问题呢？实际上很多物体在空间中的分布不一定那么均匀，比如打个比方，在特别远的地方有可能也有一个物体，这个时候如果分配一个特别大的背景网格去把所有的刚体都覆盖住，那存储开销会非常的大。所以这种结构实际上比较适合物体尺寸单一、分布比较均匀的，比如在一个封闭的容器里边我们做一些流体模拟，或者做一些刚体颗粒的模拟，这样的话实际上是比较适合的。但是对于像有些分布得比较广，同时比较稀疏的结构实际上是不太适用的。

所以这里边其实就牵扯到另外一个最后要讲的结构，叫做层次化的一个包围盒。这是什么概念呢？因为本质上算法复杂度，一个是要保证它整个计算的复杂度降下来，第二个实际上是存储的开销尽可能要低。所以这种结构一个好处就是，因为原先致密的话其实会造成大量的浪费，所以相当于用一个自适应的二叉树结构把空间进行划分。

比如说我们可以看，首先从 CPU 的实现角度怎么去看这个问题。一开头也是一样的，跟均匀网格一样分配一个足够大的包围盒，把所有的物体都包在里头。接下来它要做的实际上就是对这个空间进行划分。当然因为是一个二叉树结构，比如它需要在中间切一刀，把里边所有的物体劈成两半，劈成左边 $N_1$ 有一个 bounding box，在右边有个 $N_2$ 的 bounding box，里边相当于各包含一部分刚体。再进一步，比如 $N_1$ 发现里边还有两个，这个时候可以再进一步细分，后面再拆出两个。当这个时候每个节点已经到了一个物体了，这个时候就不需要再细分了，就结束了。当然随后的因为有三个物体，也是需要逐步地去划分。

这种会发现它整个存储开销实际上就比较低了，因为基本是属于一个跟物体的数量对应的一个线性的开销。当然会发现它整个计算的开销要比均匀网格稍微大一点，但是总的来说，怎么去降低计算开销呢？最理想的肯定这样，树尽可能要平衡。因为整个查找的时候肯定都是从根节点开始逐渐往下遍历去查找，怎么尽可能让这棵树成为一个平衡二叉树，让每个叶子节点的深度尽可能保持一致的话，对整个查找效率实际上是比较有帮助的。

那接下来的主要问题是什么呢？因为刚才介绍那个过程实际上是从根节点开始再逐步往下去构建，这个时候 GPU 肯定没法这么去做，因为 GPU 包含可能有几千个线程，不可能说每个线程先去构建根节点，其他的这个时候都等着，等它更新完之后再去进一步更新它的子节点，这肯定是不现实的。所以这里就需要依赖一个怎么去并行的快速去构建层次化包围盒的算法。

接下来我重点讲一下 Linear BVH 这么一个算法，看看它具体是怎么来做的。当然这里边需要先讲一个基础的概念，这里有个叫莫顿码的内容，需要先讲一下到底是什么意思。因为我们知道，不论二维还是三维，以二维为例的话，一个点实际上分为两部分，比如它有 $x$ 的索引以及它的 $y$ 索引。这个时候如果打个比方，像前面均匀网格，我们知道在存储空间里边，不管你是自适应结构还是均匀网格，其实在显存或者在内存里面都是线性的，因为最后都是有一个寻址的地址。也就是这个时候不论什么分配结构，最后都会拉平。

如果空间结构有可能是一个二维的，或者有可能是三维的，我们怎么能让离得近的物体在空间排布上离得尽可能近，在内存的排布上，空间上比较近的怎么让它在内存上也离得比较近？为什么要这么做呢？因为我们知道整个 GPU 在寻址的时候实际上是一块一块去取的，相当于比如一次有 32 个线程进来了之后，它会连续地去取 32 个数据。所以这就意味着，如果你的数据在空间上整个是连续的……

这样的话，所取数据的时候发生 miss 的可能性会相对来说比较低。

针对这个问题，莫顿码主要做的一件事情就是：怎么把空间上离得近的，让它在内存里边尽可能离得也比较近。

它整个思路就是，比如说现在有两个坐标，即 $x$ 坐标跟 $y$ 坐标。$x$ 坐标比如说 0、1、2、3、4。如果单看 $x$，这肯定没问题，它是线性连续存储的。但是如果涉及到二维坐标，这个时候还有一个 $y$ 坐标。这里边有一个什么问题呢？对于 $(0, 1)$，就最下面这个 $(0, 1)$ 的位置，这个时候会发现，因为我们知道矩阵一般的存储要么是列主序，要么是行主序。比如行主序，先存行，这个时候就会发现，$(0, 1)$ 这个坐标跟 $(0, 0)$ 这个坐标实际上是离得比较远的，因为它需要在整个上面第一行所有的数据存完了之后，才能取到这个坐标。所以这样在查找 $(0, 1)$ 的时候，它的连续性其实不太好。

这个时候莫顿码怎么做呢？它实际上就是按照位，比如从最低位开始，交错地去构建它的 ID。比如看这个 $(0, 0)$，首先最低位 $x$ 的 0 放到最右边，其次接下来是 $y$ 的 0，然后再往后是 $x$ 的第二个 0，然后是 $y$ 的第二个 0。逐步把 $x$ 跟 $y$ 按位把所有的 ID 实际上都给打乱了。打乱之后会发现整个结构就变成了：以前如果按行存或者按列存，就变成了实际是一个 Z 字形的结构。背景里网格线可能不是特别清楚，但也能看出来，它实际上相当于 $(0, 0)$ 完了之后到 $(0, 1)$，然后到 $(1, 0)$，然后不是到 $(2, 0)$，而是直接到了 $(1, 1)$ 的位置。所以就会发现，这个点跟这个点离 $(0, 0)$ 实际上都比较近了，都是存在它的附近。这样实际上把整个空间上离得比较近的，在整个内存或者显存上也变得比较靠近。

我们具体来看一下针对刚体这个任务。还是一样，假设现在已经有一个背景的 ID。

这个结构对应到存储空间里边的话，那就变成了首先绿色空间是放在第一个的，其次就是橙色的三角形，再往后实际上就是灰色的，再往后就是棕色的。可以看到上面对应的莫顿码其实也是从小到大的排序，当然这个是因为排过序之后的，排过序之后相当于它是从小到大。
