## 距离场软阴影（Distance Field Soft Shadows）
> 对应块：BLK09 | 覆盖分集：P05上 | 块标题（分集名）：《Lecture5 Real-time Envir》

上一讲我们把阴影推到了 PCSS 的更深层次理解，又见识了 VSSM 这个非常聪明的做法：针对 PCSS 第一步和第三步慢的问题，用范围查询避开采样；后来还有引入更高阶 moments 的延伸版本。VSSM 在 temporal denoising 这一系列方法提出之后，用得渐渐没有 PCSS 多了——那为什么还要学？因为它实在太聪明了。学它能让我们更聪明：体会一下别人为什么能想到这么精妙的算法，这是非常有趣的一件事情。

今天先把 shadow 这块说完。阴影这里还缺一块知识：一种刚刚开始兴起的生成软阴影的新方式，叫做 distance field soft shadows，距离场软阴影。为什么一定要讲？因为它实在太好了，而且我觉得最近几年它会得到更广泛的应用——距离场最近研究的人非常多，还是跨领域的：几何、渲染，都在从不同的角度研究这个东西。

它到底好在哪、贵在哪？一条推特说得非常清楚：SDF shadow 非常快，比现在传统的 shadow map 快；Fortnite 没有百分之百用它，是因为它的存储有问题。一个好处、一个坏处，当场就齐了。后面还补了一句：对非常复杂的几何，用 SDF shadow 能达到原来得靠三个 shadow map 才能做到的效果；而且它不会有自遮挡（self-occlusion）问题，也没有阴影悬浮（peter-panning）这些老毛病——这两个问题咱们之前都提过。效果也确实立得住：用 distance field 生成的软阴影，比起硬阴影（hard shadow）效果要好非常多。

说完阴影，我们就进入这一讲的新话题：环境光照（environment lighting）该怎么处理。这里先把一件事说清楚：环境光照要解决的是 shading 问题，是忽略阴影时的 shading，标题可没打错——shading 和 shadow 的区别，GAMES101 早就说过了。环境光照是个挺困难的事情，这门课的难度到这儿已经降不下来了：实时渲染这么复杂的话题，首先就要求大家对渲染领域比较熟。这一讲的主角叫 IBL——具体什么意思之后再看——其中要用的 split sum 方法，非常非常依赖大家对以前知识的理解。有同学问今天讲不讲 spherical harmonics：不会，但很快就会讲到。至于环境光照下的阴影怎么做，最后有时间再说。

本篇先把第一块讲透：距离场软阴影。

### 距离场是什么：到物体表面的最近距离

distance field 和 distance function 是一回事。它定义的是：空间中的任何一个点，到某个物体表面上最近一个点的距离——或者说，它到物体表面的最小距离，完全是一回事。

> **定义**：signed distance function（SDF），带符号的距离场。在距离的基础上再规定正负号：物体内部为负，物体外部为正。这样它定义的就不只是一个距离，还是一个有向距离。平时我们说“距离场”，不管它有没有符号，一般都直接缩写成 SDF。

看一个二维的例子。把字母 A 打到一张图上，图上的任何一个点，都可以计算它到字母 A 轮廓的最近距离——二维情况下，“物体表面”就是物体的轮廓。这张图就是字母 A 的距离场。

同一个距离场有两种可视化方式。一种直接把值打印出来：A 的内部是黑的（负值）；A 的外部，随着点离 A 越来越远，距离值越来越大，整个画面看起来就像一圈在 A 周围糊开的晕影，非常有意思。另一种可视化被广泛应用在地图上——等值线的画法，类比地图的等高线：同样的颜色表示值一样。可以看到轮廓往外扩了一圈又一圈，每一圈到轮廓的距离都相等。

### 先热身：用 SDF blend 出会动的边界

SDF 非常非常有用。GAMES101 里做过一个例子，当时 PPT 画得不太清楚，这里重做了一遍，正好用来说明它最有意思的性质之一：对运动的边界做 blending。

设想 A 和 B 是两张图，一个黑白物体正从左往右移动。A 时刻，物体的边界——黑与白之间的分界线——在靠左大约三分之一处；B 时刻，物体移动了一段距离，边界也跟着挪到了新位置。这两张图我们都能拍到。

现在把两张图直接做线性插值：每一个像素，都取它在 A 里对应位置的值和它在 B 里对应位置的值，做 50% 对 50% 的平均。结果是什么？最左边三分之一，任何一个点在 A 里是黑的、在 B 里也是黑的，平均下来还是黑；最右边同理，还是白；坏就坏在中间——同一个位置，A 里是白的、B 里是黑的，一平均，变灰了。最后得到的东西，看起来就像边界糊开了一条灰色过渡带，而不是“一个位于中间的边界”。这自然不是我们想要的。

那想要什么？还是做这种线性插值，但插值完能恢复出一个位于正中间的边界。办法是：把 A、B 各自先转换成对应的 SDF——物体内部（黑的部分）是负值，外部是正值，边界上正好为 0，离边界越远绝对值越大。然后对两个 SDF 做同样的线性插值。看正中间那个位置：它在 A 的 SDF 里假如是 +5，在 B 的 SDF 里假如是 $-5$，一平均，正好是 0。而 SDF 等于 0 的地方，就是物体的边界——所以插值出来的这张 SDF 图，零值线恰好落在正中间。最后再按“SDF = 0 即边界”把它恢复成一幅图，就会发现：还是线性插值，只是插的对象换成了 SDF，恢复出来的结果就反映了边界在移动。原来如此，非常有意思。

这体现的是 SDF 一个非常不错的性质：它可以表示物体的边界——虽然咱们这节课用不着它。这也是人们喜欢 distance function 的原因：它可以对任意不同的形状做 blending，而且不需要关注它们之间的拓扑关系。比如一个球朝一个正方形移动，把两者各自转换成 distance field 再 blend，就能把它们最后融合到一块，得到几何上非常好的过渡。

再多说一句，既然这是一个提高课：SDF 的背后和一个理论关系非常密切，叫 optimal transport，最优传输。这一块顾险峰老师研究得非常透彻，应该能找到非常不错的资料。这也算学术前沿，我个人对这方面也非常有兴趣，希望把它弄到 rendering 层面上能有一些应用——当然也还在研究中。

### 第一种用法：Sphere Tracing，沿光线安全前进

SDF 最简单直接的第一种用法，就是大家耳熟能详的 ray marching：用光线追踪去追踪一个距离场，看最终会打到哪个物体表面。GAMES101 里没有讲过它（GAMES201 倒是简单提过），但它实在太简单了，即便不是渲染领域的人，看一眼也能理解。

前提假设是：整个场景的 SDF 你已经拿到了。现在有一根光线，要做的事情是让它和 SDF 定义的隐含表面求交。最简单直接的方式叫 sphere tracing，它背后用了一个非常聪明的规律。

回想 SDF 的定义：一点处的 SDF 值，是这一点到场景中其他物体的最小距离。既然是“最小”距离，它就隐含地告诉我们一件事情：在这个最小距离之内，不管你往哪个方向走，无论如何不可能与任何物体相交——否则就意味着一定有一个物体藏在这个范围里，那 SDF 记录的值就不对了。

> **结论**：空间中任何一点的 SDF 值，都定义了一个安全距离。不管往哪个方向走，只要走的距离不超过它，就一定不可能与任何物体发生碰撞。

于是求交变成了“走一步、查一步”：

```text
o ──SDF(o)──→ p1 ──SDF(p1)──→ p2 ──SDF(p2)──→ ……
每一步沿光线方向前进的长度 = 当前点的 SDF 值（安全距离）
停止：SDF 小到一定程度（足够接近表面），或已走出很远还没碰到（丢弃光线）
```

每一小段箭头的长度，就是该点 SDF 给出的安全距离；走一步查一步，直到命中或放弃。

具体走法：一开始看光线的起点，查它的 SDF，比如它告诉你安全距离是这么大——那就放心地把这个点沿光线方向移动这么长，因为这一步一定不会撞上任何东西；到了新的一点，再查一次 SDF，又知道能往前走多远。什么时候停？要么走到和物体足够接近——SDF 小到一定程度；要么光线已经往前走了非常远的距离，还什么都没碰到，那就把这根光线扔掉。总结成一句话：任何时候你在 $p$ 点，都可以沿给定方向放心地往前走 $\mathrm{SDF}(p)$ 那么长。

那 SDF 本身从哪来？这是刚才一直回避的问题，也是 SDF 的局限所在。SDF 的定义是空间中任何一个点到物体表面的最小距离——在三维场景中，SDF 就是一个三维的场，任何一个点都有一个值。对比一下 texture mapping：物体表面是二维的，所以贴图好办；而 SDF 得把场景中任何一点的值都先算出来，然后还要存储——相当于存一个覆盖整个场景的、巨大无比的三维格子。这中间当然有优化（后面会说），但不管怎么样，存储开销非常高——开头推特说的“存储是个问题”，说的就是它。顺带把一个概念说清楚：距离场虽然叫“场”，每个点保存的只是一个值——它的 SDF 值，这是个标量场，没有方向。

运动的物体能不能用？可以，没有问题。刚体运动的物体尤其好办，这里牵扯 SDF 一个非常好用的性质：“最小”是可以组合的。场景中有多个物体，每个都单独算了自己的 SDF；要做光线和整个场景的求交，在任何一个点上，取所有物体 SDF 值中最小的那个就可以了。道理显而易见：每个物体都告诉你“我离你最近有多远”，取最小值，自然就是这一点到场景中任何一个物体的最小距离。一个场景里所有物体的 SDF 合在一块，看起来就像给每个物体描了一圈边——沿轮廓向外晕开。

但形变的物体就不行了：形变意味着物体的 SDF 得重新算一遍。重算要多大开销、能不能根据形变只更新改变了的部分——那就是几何那边研究的事情了。

### 第二种用法：从安全角到软阴影

说完 ray marching，进入今天的第二个应用，也是重头戏：用 SDF 生成软阴影。

软阴影从哪来？GAMES101 最早就提过：因为光源是个有面积的面光源。看过去的时候，它有一部分被遮挡物挡住了——被挡住的比例是多少，最后的可见性 visibility 就是多少：全没挡住就是 1，全挡住了就是 0，挡了一半阴影就是半黑。所以软阴影的问题，本质上是估计“大概有多少比例的面光源被挡住”。

这里我们用 SDF 来近似地得到“大概有多大范围会被挡住”这么一个信息。先把话说清楚：它是不准的，但是挺符合我们的观察。

最重要的一个理解是这样的：刚才 ray marching 里，SDF 给你一个安全距离；现在往后稍微推一步，把安全距离变成安全角。

设想一个 shading point $o$，朝某个方向打了一根光线（往光源的方向看）。沿光线走，中间有一点 $p$，它的 SDF 值告诉你：$p$ 周围大概多远之内没有障碍物。那么从 shading point 朝这个方向看过去，其实可以稍微偏一点——再多偏一点——一直偏到某个方向上，都不会看到障碍物；再偏，就会被挡住一些了。这就是“安全距离”的一个简单延伸：把它变成了一个安全角度（safe angle）。

由此得到一个非常非常有用的观察：

> **结论**：在一个 shading point 上朝某个方向看，安全角越小，意味着你能看到的东西越少——看到的阴影就越黑。

反过来说：如果这一点的安全距离很大（一个很大的球），那就意味着很大的安全角——朝这个方向看过去，哪怕一个挺大的光源，中间都可能没有任何遮挡，最后可见性基本接近 1（偏白）；如果安全距离非常小，稍微偏一点就会出现遮挡——同样大小的光源，很大一部分被挡住了，visibility 就会减小（偏黑）。

所以真正要关心的就是：在 ray marching 的过程中，如何得到这个安全角。做法还是沿光线一步步走：

```text
  o ─────→ p1 ─────→ p2 ─────→ p3 ───→ 遮挡物
   \  θ1     \  θ2     \  θ3
    \         \         \
     \         \         \       ← 从 o 向各步对应的球作切线

  第 i 步：以 p_i 为球心、SDF(p_i) 为半径作一个球（图中是圆），
          从 o 向球作切线，切线与光线方向的夹角就是该步的安全角 θi
  整条光线的安全角：θ = min(θ1, θ2, θ3, …)
```

读法：从 $o$ 出发按 sphere tracing 沿某个方向走，p1 告诉你应该走到 p2，p2 告诉你走到 p3……在 p1 的位置上有一个圆（三维里是球），从起点 $o$ 向这个球作切线，就求出这一点的安全角 $\theta_1$；p2 处的球同理，从起点引切线得到 $\theta_2$……每一步都能求出一个自己的安全角。那整条光线的安全角是多少？自然应该取最小的那个——只要路上任何一点把你能偏的角度卡得再窄一点，整体就得按窄的算。

每一步都算一个安全角、最后取最小，这个角度一定程度上就能给出“阴影到底偏黑还是偏白”的估计。思路就这么简单：把 SDF 能给你的安全角，转换成最后阴影的值。

> **提示**：有同学问，安全角是不是应该有两个——刚才画了半边，另外半边呢？这恰恰说明这是一个非常大胆的近似。SDF 本来就不能告诉你方向在哪：它只告诉你遮挡物大概在这一圈之外、在这个圈上，并不知道阴影会出现在左边还是右边；到三维的情况下，你根本不知道它会出现在哪一个圆环里。既然不知道，就干脆当作整个圆周都是这种情况来处理——不去考虑遮挡物的位置，其实是自有道理的。

> **提示**：还有同学问，面光源怎么一条线就能算了？这里只是一个概念示意：安全角想告诉你的仅仅是——如果这儿有个面光源、大概这么大，它大概有百分之多少被挡住。我们最后需要的，仅仅是“角度的大小本身能决定阴影的软硬”这一条：安全角越大，结果越接近完全没被遮挡（偏白）；安全角非常小，结果就越来越偏黑。并不需要真的摆一个那么大的光源，去老老实实算它被覆盖的比例。

### 阴影公式：不求反三角，一个 k 定软硬

还剩一个问题：这个安全角具体怎么算？

从图上看其实挺好算——就是求一个球的切线。SDF 给你的距离是直角边，你走过的距离（从 shading point 到当前点 $p$ 的距离 $t$）是斜边，所以这一步的安全角是

$$\theta = \arcsin\frac{\mathrm{SDF}(p)}{t}$$

算一个 arcsin 就出来了。但是——这里先给大家精神污染一下：虽然可以这么算，但人们通常很愿意在 shader 里避免一些非常复杂的运算，反三角函数这种运算量非常大的东西，大家非常不喜欢。那怎么办？

人们很聪明地提出了这么一个做法。先不管和 1 取 min 的问题，就看中间这一块在干什么：arcsin 算的是“直角边除以斜边”，也就是 SDF 的值除以走过的距离。这两个量的比值本身，就已经能说明这个角度到底是大了还是小了——干嘛要算那么精确？所以干脆不算反三角，直接拿这个比值当作角度的近似，在上面乘一个系数 $k$；最后为了让结果是一个合法的 visibility（不能超过 1），再和 1 取最小：

$$\mathrm{visibility} = \min\left(1,\; k \cdot \frac{\mathrm{SDF}(p)}{t}\right)$$

march 过程中的每一步都算这个值，整体再取最小，就是最终的阴影。

这个 $k$ 的作用是在干什么？既然最后反正要把结果砍到 1 以下，$k$ 就决定了“比值多大才算全亮”：

| $k$ 的取值 | 比值 $\mathrm{SDF}(p)/t$ 达到多少就被当成 1 | 0 到 1 的过渡带 | 阴影观感 |
| :--- | :--- | :--- | :--- |
| $k = 1$ | 比值 $= 1$ | 全程都是过渡带 | 最软 |
| $k = 5$ | 比值 $= 0.2$ | 只剩 0 到 0.2 一小段 | 变硬 |
| $k = 100$ | 比值 $= 0.01$ | 只剩 0 到 0.01，极窄 | 几乎是硬阴影 |

规律一眼可见：$k$ 越大，很小的安全角也会被当成 1，0 和 1 之间的过渡带自然就越窄。推到极端，$k$ 极大的情况下，结果要么 0 要么 1，中间过渡非常非常小，就完全是硬阴影了。所以 $k$ 控制的就是阴影的软硬程度：到底多大的角度范围算软阴影的过渡、什么时候完全在阴影内、什么时候完全不在——就简单粗暴地用这一个 $k$ 来定。这是一个非常聪明的做法。

> **提示**：换我来做，我估计想不到这么个做法。要压缩 0 到 1 之间的过渡带，我的第一反应应该是上一个 sigmoid：一个线性函数过了 sigmoid，值就会被拉向两个极端——一头偏 0，一头偏 1。这不正是想要的吗？sigmoid 现在很火，我就不再解释它是什么了。但 sigmoid 的计算非常麻烦，肯定不如“乘一个 $k$、再和 1 取个 min”这么便宜。不管怎么样，大家知道 $k$ 的作用就好了：它负责削减可能产生阴影过渡的区域，这个区域被削减得越厉害，阴影就越硬。

### 算总账：快在哪，贵在哪

距离场做软阴影，好处坏处现在可以一起算了。

先说快。“快”是相对谁来说的？两点。第一，在 ray marching 的体系下：本来就要 march 去求光线和隐含表面的交点，在这个基础上，软阴影是自然而然就引入的——同样也可以假设一根 shadow ray 往光源的中心打，通过这种方式快速得到软阴影。软阴影和硬阴影在 ray marching 体系下的复杂程度没有任何区别，所以它快，没有问题。第二，跟 shadow map 比，要算得公平一点：查询 shadow map 本身就是一次 texture query，非常快；做软阴影也就若干次查询，不慢；ray marching 也就是几次 SDF 查询而已。所以单看“用”的阶段，两者是差不多快的。shadow map 真正的时间大头花在生成上——你得把整个场景朝光源方向重新渲染一遍。而推特里那句“SDF shadow 比 shadow map 快”，其实忽略了一个事情：距离场生成的时间。距离场的生成是预计算；只管用的话，ray marching 在 shader 里就能写，确实非常快。

再说贵，也就是它的问题。

- 生成 SDF 本身是一个预计算过程，生成完了还得把它存下来；
- 静态的场景、刚体都没问题，但对动态的物体还不行——一旦有形变，就得重新算它的距离场，非常麻烦；
- 存储对任何物体都不轻松：SDF 是三维的，三维的东西存储起来非常麻烦——等于存一张覆盖整个场景的巨大三维纹理；
- 实际用起来还会有一些 artifact，比如接缝处的各种问题，这是工业界比较关心的地方。当然，这不影响 SDF 给出质量非常不错的软阴影。

### 存储怎么压：层次化的 SDF

开头推特说的存储问题，人们自然不会坐视不管，现在有一些方法在研究怎么压缩。思路之一是给场景建一个类似 hierarchy 的结构——之前咱们说过的 kd 树、八叉树，任何空间划分的树形结构都可以。

不断往下划分的过程中会发现：有一些格子离场景中绝大多数物体都非常远。既然离得非常远，就根本没必要计算、也没必要存了——这个范围内的 SDF 值可以直接认为“非常大”，整个节点表示的一大片区域都不用算得很准。按这种方式继续往下划分，一直划分到物体的边缘——也就是 distance field 的值在一个节点里变化非常剧烈的地方——才细分得很厉害。最后就形成了一棵树：复杂的 SDF 值只需要存在叶子节点上；非叶子节点上认为是一个常数，也完全没有问题。

也有人试过用神经网络去压缩 SDF 的表示。这条路在实时渲染里基本走不通：查询 SDF 是个高频操作，而且要频繁查询，每一次查询都得过一遍神经网络，等于把解压缩的负担压到了每一次查询上——那这个方法就不可能再有人用了。

### 延伸：无限分辨率的字符渲染

最后分享一个我最近发现的、很有意思的 GitHub 项目：在实时渲染里显示完全没有锯齿、分辨率无限的字符。想在三维场景的墙上显示一个字符怎么办？贴 texture。但 texture 必然有分辨率限制。而如果把字符预先都转换成 SDF，再在比较精细的层级上做插值——做一种类似平滑的过渡，比如三线性插值之类——那么不管什么分辨率、离得远还是近，都能看到非常清晰的字体边界。

> **提示**：SDF 也有它自己的短板：用 SDF 生成的物体表面非常不好贴纹理——它的 UV，或者说它的参数化，是不好得到的。这个问题目前大家还在积极研究之中。

最后回应一个这几节课下来很多同学都有的感受："怎么感觉全是近似？"没错，一直到这门课结束，全是近似。但近似的目的首先是为了快，而且它不会牺牲特别大的质量——更妙的是，这些近似都非常的聪明。至于 SDF 到底好不好用？做阴影的时候，非常好用。

## 实时环境光照：从 IBL 到 Split Sum
> 对应块：BLK10 | 覆盖分集：P05下 | 块标题（分集名）：《Lecture5 Real-time Envir》

### 先把 SDF 软阴影收个尾

开讲之前，先把上一个话题的尾巴收掉。SDF 对实时渲染中软阴影的帮助，就简单说到这儿。SDF 是个跨领域的东西：它自己怎么生成、在其他领域还有什么应用，都是别的领域在研究的事；在 rendering 这边，我们就把它当成一个直接可以拿到的信息来用，仅此而已。

有同学问：SDF 得到的是真的阴影吗？并不是。SDF 得到的阴影反而会更"虚假"一些——回想它的近似思路就知道，这一步比之前的那些方法要大胆得多。

> **结论**：SDF 软阴影胜在便宜、可用，但它是一个更大胆的近似，给出的并不是物理上严格真实的阴影。

好，那就继续下一个话题：环境光照。这个话题现在才开始确实有点晚，而且今天很可能只能讲到一半，后面还有非常重要的内容等着。

### 环境光照：假设所有光都来自无穷远

环境光照这个事情，GAMES101 里就提过：用一张图，把"在场景中往任何一个方向看，能看到的光照"记录下来。就这么回事。

但这张图中间隐含着一个概念：这些光照全部来自无限远，也就是所谓的 distant lighting。这个假设直接带来一个后果——你放两个不同的物体在场景里，摆的位置不一样，它们接收到的环境光照却完全相同。再形象一点：如果环境贴图里有一张桌子，你是不可能把什么东西"放在桌子上"的，因为不管放在哪儿，那张桌子对它来说都在无限远处。所以用任何环境光照去渲染任何物体，看着总有一种"漂浮"的现象。

存储方式主流就两种：spherical map 和 cube map，各自的优缺点不再多说（GAMES101 讲过），咱们这门课就认为"不同的方向上能得到不同的光照"就够了；常见的 HDR 环境贴图就是 spherical map 的形式。至于环境光图本身怎么获得，那是另外一回事，这里不管。

那么问题也就出来了：给你一份环境光照，往场景里放一个物体，不考虑遮挡、不考虑阴影，怎么把物体上任何一个 shading point 的 shading 算出来？这套操作在工业界叫做 IBL，也就是 Image Based Lighting。说句实话，我不怎么认可这种命名方式，觉得它略大了一点，不是百分之百能接受——但毕竟大家都这么用了，IBL 或者说 environment lighting，指的就是这件事。

适用场景顺便说清楚：IBL 你想用在哪都能用，工业界用得特别多。它唯一的问题就是刚才那个"无限远"假设——一旦光源和物体之间有确定的距离，这套假设就不再成立，不能再这么用了。

### 渲染方程：蒙特卡洛能解，但实时付不起

给了 IBL，要求任何一个 shading point 的 shading 值，自然而然就是要解渲染方程（rendering equation），前面第二还是第三节课讲过（具体哪节我忘了）。实时渲染中，我们通常愿意把 visibility 拆出来单独处理，这样式子里的 lighting 指的就是"发光的 lighting"，而不是实际到达的 lighting。这里既然不考虑 visibility，被积的光照项就是环境光从四面八方来的 $L_i$：

$$L_o(\omega_o) = \int_{\Omega} L_i(\omega_i)\, f_r(\omega_i, \omega_o)\, \cos\theta_i \, d\omega_i$$

积分域 $\Omega$ 是上半球——任何方向都可能有光照，但渲染方程只考虑来自正半球的部分，就是之前说过的 cos 项前面加 $\max(0, \cdot)$ 那回事；"上半球"由 shading point 的法线定义，取法线点乘为正的那些方向。（至于 cos 为什么并进 BRDF 一起考虑，课程开头讲渲染方程时说过。）

通用的解法大家也熟：蒙特卡洛积分，写成求和就是 $\frac{1}{N}\sum_{i=1}^{N}\frac{f(x_i)}{p(x_i)}$——对任何积分，都可以拿任意 pdf 的样本来做数值上的近似，而且这个近似是无偏的，我们就说它"是对的"；求和分母里的 $p$ 就是采样分布的 pdf，GAMES101 大概 18 讲讲过这件事。但蒙特卡洛需要大量样本，才能让结果收敛到期望值。想一想整个场景，任何像素、任何 fragment 都要做一遍这个"四面八方光照"的积分，那得多少 sample？非常慢。

所以以前有个经验法则：只要在 shader 里——特别是 fragment shader——出现了 sampling，这个方法多半就不能用在实时渲染中。这句话现在要打个星号：最近几年，时间上和空间上的一系列滤波方法，让越来越多基于 sampling 的方法进入了实时渲染，以前这么认为，现在不一定了。顺带说下现状：除了 DLSS，神经网络 denoising 目前大家用得都不太多，并不怎么成功——实在太慢，跑一遍神经网络要几毫秒，在实时渲染里这就已经死了；特别是要在 shading 层面每个点都跑一遍神经网络，那就更完蛋了。以后会怎么样不知道，但至少眼下，能不采样当然最好。

于是核心问题就变成了：**在 IBL 的情况下，任何一个点的 shading，能不能不通过采样来算？**

### 拆分的依据：glossy 赢在 support 小，diffuse 赢在 smooth

基本思路，要从一个最简单的观察开始。回到刚才的积分：不考虑 visibility，里面就是两个函数相乘——一项是 lighting，一项是 BRDF（cos 就连着 BRDF 一起写）。渲染一幅图时，看的视角是固定的。顺带交代一句，实时渲染里 incident 这个词用得不太严格：不一定非得是光照方向才叫 incident，我们看出去的方向也常这么叫，只要不引起混淆，就这么用了。

在这个固定视角下看两种极端的 BRDF：

| BRDF 类型 | lobe 在球面上的覆盖（support） | 值的变化 |
| :--- | :--- | :--- |
| glossy | 很小，只覆盖镜面反射方向周围一小片 | 变化剧烈 |
| diffuse | 覆盖整个半球，范围非常大 | 非常 smooth：值本来就是常数，连上 cos 也只是一个相对平滑的过渡 |

这两种情况听起来是不是非常熟悉？正是之前那个经典近似——把两个函数乘积的积分拆开——的适用条件：当 $g$ 的 support 比较小，或者 $g$ 的值比较 smooth 的时候，拆出来就比较准。BRDF 恰好天生满足其中一条：glossy 对应第一种，diffuse 对应第二种。所以这个拆分完全可以做。

把近似写出来，这次显式地把 support 写进积分限。要把两个函数的乘积积分出来，可以把其中一个（这里是 BRDF，充当 $g$）留在积分里，把光照拿到外面：对光照在 BRDF 的 support $\Omega_{f_r}$ 上积分，再除以 support 的大小做 normalization——support 小的话，就不需要对整个半球积分，只在 BRDF 有值的地方积：

$$\int_{\Omega} L_i(\omega_i)\, f_r(\omega_i, \omega_o)\, \cos\theta_i \, d\omega_i \;\approx\; \frac{\int_{\Omega_{f_r}} L_i(\omega_i) \, d\omega_i}{\int_{\Omega_{f_r}} d\omega_i} \cdot \int_{\Omega} f_r(\omega_i, \omega_o)\, \cos\theta_i \, d\omega_i$$

注意别和拆阴影那次搞混：解释阴影的时候，拆出来的是 visibility 项，lighting 和 BRDF 都留在里面充当 $g$。同一个公式按需要选用，这次拆出来的是光照。

拆出来的前一半在干什么？它和 BRDF 再没有任何关系——这正是拆分的好处：light 和 BRDF 综合作用难算，拆开后光照这半可以单独处理。它说的是：把光照在 BRDF lobe 覆盖的那片范围上积分起来，再除以范围大小。这描述的其实就是一个"模糊"操作：任何一个点，取它周围一片范围，把这片范围的平均值写回这个点。

> **定义**：把光照拆出来，等价于定义了一种操作——filtering，对环境光做滤波；滤波核取多大，就是 BRDF lobe 占多大。

### Prefiltering：先把环境图全部模糊好

我的用词是 prefiltering，重点在一个"pre"：这张环境光图，在渲染之前、老早之前，就可以先 filter 好。拿到环境光之后，立刻花点时间，用不同大小的滤波核把它 filter 成一串新的图；核越大（也就是 BRDF lobe 覆盖越大），结果就越糊。这几张图全部在渲染开始前生成好，实际渲染时完全不用管它——这非常好。

那到时候要查某个大小的滤波结果怎么办？比如滤波核半径是 5，该查哪张图？这和之前说的 mipmap 非常像：预先按 filter 1、filter 2、filter 4、filter 8 生成一串图，要 filter 5，就在 filter 4 和 filter 8 之间插值一下——非常像三线性插值。这也是工业界的常用套路：查的不只是离散几档预计算好的值，任意大小的滤波结果都能插出来。

> **易错点**：滤波必须发生在球面上。spherical map 每个像素表示的立体角并不一样，所以不能对这张图做 uniform 的滤波；"取多大的 filter"指的是球面上的立体角范围，落到图上每个像素该 filter 什么形状、多大，都不一样。好在这一步属于预计算，图用多大分辨率、怎么存都没关系，只要保证滤波是在球面上做的就行。

几个查询细节也都顺理成章：

- diffuse 是特殊情况：lobe 覆盖整个半球，滤波差不多就是全图的平均（或者沿 normal 方向取平均），查询方向就是 lobe 的中心——normal。
- glossy 沿 lobe 的中心方向查，也就是镜面反射方向。有人问：glossy 的 roughness 不断变大，不就变成 diffuse 了吗，那不还得沿镜面反射方向查？没关系——实时渲染里大家通常把 diffuse 和 glossy 拆开处理。
- 滤波核得按一系列已知形状的 BRDF lobe 来做。好在正常的 BRDF lobe 都长得比较像高斯，做个近似、差不多就 ok。
- 程序化生成的 HDR 纹理能不能这么套？除非它本身支持动态的范围查询，否则不行——这算比较深的话题，以后再说。

### 前一半的用法：预滤波一次，查询一次

本来要精确算这个 shading，做法是去采样 BRDF 的 lobe：根据它的 glossiness 或者 roughness，在镜面反射方向周围分布一些采样点，把采样值做加权平均，得到这个 shading point 的值。

而"采样加权平均"和"把 environment lighting 先 filter 好、再在镜面反射方向直接查一次"，是同一件事：滤波后的图上任何一个点都是它周围一片点的加权平均，你查一次，就相当于查了它周围的一片值——只不过这片值是老早就 filter 好了的。是不是非常聪明的做法？

所以拆出来的前一半就完美解决了：理论上任何大小的滤波结果都能查，实际用的时候沿镜面反射方向取一次值就行，没有采样。

### 后一半：BRDF 自己的积分怎么不采样地算

可是问题还没完全解决：前一半没采样了，后一半不解决，整个问题就没解决。拆出来的后一半是对整个 BRDF 做积分：

$$\int_{\Omega} f_r(\omega_i, \omega_o)\, \cos\theta_i \, d\omega_i$$

看起来非常麻烦。先交代一句：现在有比这更好的解决方案，叫 LTC（Linearly Transformed Cosines），但它并不是严格意义上直接解决这个问题，只是和这里的东西相关，之后讲到了再说；也别把 LTC 想狭隘了，它不是只能算面光源。

回到主线，思路还是预计算，但这次的预计算比较麻烦：要算这个积分，得把所有参数的可能性都考虑进去。先做假设：假设它是 microfacet BRDF（GAMES101 讲过），那么最重要的就是两件事。第一，Fresnel 项：垂直看向物体表面时有多少能量被反射——这决定了基础反射率，也就决定了颜色；不垂直时反射量各不相同，随入射角度变化，在 grazing angle 下往上翘。第二，NDF：微表面的法线分布，一个很简单的一维函数，直接拿 roughness（粗糙度）描述——分布四面八方都有，表面就是 diffuse；法线集中在某个方向，就接近镜面。中间的 shadowing-masking 项这里不提。

然后算一笔维数的账：roughness 是一个数，一维；Fresnel 项很麻烦，它得告诉你基础反射率，本身还是入射角度的函数（某种随角度上涨的曲线）。这么一数，参数空间至少是五维的——$R_0$ 是个颜色占三维，入射角一维，roughness 一维。对每一组参数组合都要算出一个积分值，这是浩大的工程。打个五维的表还得了？三维纹理为什么平时都用得那么少？三维就已经组合爆炸、存储量很大了，四维五维更是如此，肯定不能这么无脑地预计算。

退一步，如果把 $R_0$ 当成灰度看，变量剩三个：入射角 $\theta$、基础反射率 $R_0$、粗糙度——三维预计算，仍然太麻烦。

这里先安个心：预计算是非常正常的做法，它相当于支撑了整个游戏界的发展；之后要讲的 PRT（precomputed radiance transfer，预计算辐射传输）也是预计算。人们承受不了的只是非常高维的预计算。所以思路很清楚：**不能预计算，就想办法让它能预计算。**

### 把 R0 拆出来：从五维到二维

先把两个材质参数的老底翻出来（都是 GAMES101 的内容，之后讲实时渲染材质/PBR 的时候还会提，这里简单回顾）。

Fresnel 项有一个著名的近似，叫 Schlick approximation：不同材质的 Fresnel 项在不同入射角度下，都长得像一条往上涨的指数曲线，于是近似成

$$F(\theta) = R_0 + (1 - R_0)\,(1 - \cos\theta)^5$$

它认为 Fresnel 项就是两个量的函数：基础反射率 $R_0$（一个颜色），以及入射角 $\theta$。实时渲染里还有个角度互换的惯例：入射角（入射光与法线的夹角）、出射角（出射光与法线的夹角）、半角（入射光和出射光夹角的一半，或者说入射光与半程向量 half vector 的夹角）——这几个角都认为差不多，可以互换，干脆统一用一个 $\theta$ 描述。

NDF 那边：法线分布是一个非常简单的一维分布，长得基本类似高斯——沿宏观法线周围分布多，其他地方分布少。以 Beckmann 分布为例，它有两个变量：$\alpha$ 定义 roughness，决定分布是胖还是瘦，也就是材质偏 diffuse 还是偏 glossy；另一个是 half vector 和法线之间的夹角 $\theta$，同样可以通过近似跟入射角互换。

于是圈出来就三个变量：入射角 $\theta$、基础反射率 $R_0$、粗糙度。硬预计算就是上一节说的三维表，还是太大。

人们聪明的地方就在这里：还能再降维。把积分里的 Fresnel 项显式地写出来——把 BRDF 写成"BRDF 除以 $F$ 再乘以 $F$"，完全没变；然后把 Schlick 形式的 $F$ 代进去整理：

$$F(\theta_i) = R_0 + (1-R_0)(1-\cos\theta_i)^5 = R_0\left[1-(1-\cos\theta_i)^5\right] + (1-\cos\theta_i)^5$$

对给定的材质，$R_0$ 是常数，于是积分里一切和 $R_0$ 相关的项都可以提到积分外，整理成两个积分：

$$\int_{\Omega} f_r \cos\theta_i \, d\omega_i \;\approx\; R_0 \int_{\Omega} \frac{f_r}{F}\left[1-(1-\cos\theta_i)^5\right]\cos\theta_i \, d\omega_i + \int_{\Omega} \frac{f_r}{F}\,(1-\cos\theta_i)^5\, \cos\theta_i \, d\omega_i$$

这个值肯定是个近似，但差不多。听起来好像变麻烦了，一个积分变俩？恰恰相反，结果反而简单了：**这个积分原本对基础反射率的依赖被消除了**。拆开之后，剩下的每个积分只依赖两个变量——第一，BRDF 的 roughness；第二，入射角 $\theta_i$（或者说 $\cos\theta_i$，无所谓）。

思路非常清楚：就是想把这个积分预计算成表格，又不希望表格维数太高，所以要把变量之间的联系拆开。中间这几步数学确实挺神奇的，那就能打表了：roughness 取 1、2、3……一列，$\cos\theta_i$ 取 0、0.1、0.2……一行，每个格子上填这个积分算出来的值——不管积分多复杂，算出来都是一个数。两个积分各打一张二维表。二维数组反映到实时渲染里是什么？就是一张纹理：预先算好，送到 shader 里，用的时候只管查。两张表还能塞进同一张纹理——每个积分值是一个数，用 R、G 两个通道分别存，一张纹理搞定。

运行时给你一种 microfacet BRDF：$R_0$ 已经拆出来了，只要查两次这张表，拆出来的右半边积分立刻得到。又没有采样了！

> **提示**：拆出来的式子里 BRDF 要除以 $F$，这个 $F$ 不用真算——分母仅仅是为了把式子写出来。microfacet BRDF 分子上本来就是 $F \cdot G \cdot D$，再除以一个 $F$ 直接消掉了。

> **提示**：菲涅尔项本身要不要预计算？不需要——它被我们拆开了。正是因为拆开了，它对不同变量的依赖才被解除，不要在这里绕晕。

### 为什么叫 Split Sum

这套方法是有名字的。工业界不太写积分——离线渲染里大家积分写得多，实时领域平常就写成求和了，求和式和积分描述的是完全一样的事情。这个方法做了两件事：第一，把一个积分（或者说求和式）拆成两半；第二，两边分别处理——一边 filter，一边查表——再各自求和。所以它叫 split sum，而不叫 split integral，原因也在这里。

split sum 是大名鼎鼎的 Unreal 引擎的 PBR 能做到这么牛的基础。它的环境光照在 split sum 下完全没有 noise——没有采样，当然没有 noise——而且结果和 reference（就理解成 path tracing 出来的结果）非常相近，diffuse 和 glossy 的情况都非常像。

两个实用细节：这张预计算图是固定的——任何不同的 BRDF，只要是同一种种类的 microfacet BRDF，查的都是同一张图，只需要把这一张传进去；BRDF 不同，算出来的图当然不同，但用 GGX 并不会多出参数来，还是这么写参数。

```text
渲染方程（不考虑 visibility）
  ∫ Li(ωi) · fr(ωi,ωo) · cosθi dωi
        │
        │  拆分近似：两个函数相乘的积分，拆成两半各管各的
        ▼
[前一半] 光照项 —— 环境光图预滤波（prefiltering）：按 BRDF lobe 的大小
                   把环境图模糊成一串不同粗细的图（filter 1/2/4/8…，
                   运行时插值出任意粗细），渲染时沿镜面反射方向查一次
        │
        ▼
[后一半] BRDF 项 —— 菲涅尔项按 Schlick 展开把 R0 提出积分外，
                   每个积分只剩 (roughness, cosθi) 两个变量，
                   预计算成一张纹理（R/G 双通道），渲染时查两次
        │
        ▼
两半相乘 = 最终 shading ：全程零采样、零噪声
```

读图：渲染方程被拆成"光照项 × BRDF 项"，前一半靠预滤波加一次查询，后一半靠把 $R_0$ 拆出后的二维查表，两半相乘就是无采样的 IBL 着色。

### 零采样的 IBL：回顾与下节课预告

到这里，split sum 方法就讲完了。这块大家提的问题不多，问题少说明什么？说明这块不好懂。没关系，真的把 high level 的想法想清楚就好了。回顾一下：通过两个部分分别处理——光照做 prefiltering，BRDF 积分查二维表——我们终于不需要任何采样，就能在环境光下渲染不同的物体；diffuse 和 glossy 都能得到和 reference 非常相似的结果。diffuse 和 glossy 的项其实还可以继续拆分，后面还有不少后续处理，这里不再多说。

至于环境光照下的遮挡怎么处理——这是个好问题，这节课时间有限不展开，先给个直接的总结：目前没什么好办法，下节课再谈。

下节课开始说实时的全局光照。这是非常复杂的一个话题，会比阴影还要难。大致可以分成三类：一类是在 3D 空间中怎么用这些方法，一类是在图像空间中怎么引入全局光照，最后一类是预计算。不出意外的话，下节课先讲三维空间里的方法——LPV、VXGI、RTX GI 这些缩写都是什么鬼，到时候见分晓；需要提前看的资料，我会记得先放出来。难度上给大家交个底：之后不会简单，但也不会比这节课难到哪去，差不多就是这个难度。

## 环境光照下的着色与阴影：从 split sum 到球谐函数
> 对应块：BLK11 | 覆盖分集：P06上 | 块标题（分集名）：《Lecture6 Real-time Envir》

### 从一次自我纠错说起

先交代一件我自己的"翻案"。上一讲收尾的时候，我随口说有一个更好的办法，叫做 LTC。回去想了想，这么说不合适。为什么？因为我这是想当然了：学术界普遍认为，如果能不预计算，得到的方法自然更好——我就顺着这个思路随口一说，LTC 既然可以不用预计算，效果当然应该比 split sum 好。事实并非如此：split sum 又可以更快，效果又更好；而且 LTC 这种方法之后我们会讲到，它其实也是需要一点点计算的——大家现在肯定还不知道 LTC 是什么，没关系，之后会说。所以对 split sum approximation，大家普遍认为它就是 state of the art，没问题的。

再回顾一下上一讲说了什么。阴影那一块我们基本算是说完了，补充了一个叫 distance field soft shadow 的知识，或者叫 signed distance field（SDF），总之 SDF 是一个非常强大的东西：它不只可以描述物体的表面，还可以在几乎没有其他代价的情况下，生成软阴影的效果。然后我们转向了另一个话题：如果给一个环境光照（environment lighting），怎么把任何一个点的着色（shading）算出来？当时给大家介绍了一个在 Unreal Engine 里用得非常好的技术，叫 split sum：我们做了很多操作，把 lighting 拆出来，又在后续的预计算过程中不断对参数空间降维，直到最后得到一个"可负担"（affordable）的预计算——只用打一张二维的表格，用的时候直接过来查它，非常方便。

但上一讲留了一个挺困难、没提到的话题：我们说的都是"不考虑 shadow 的情况下"怎么算 shading。那真的这 shadow 要怎么算呢？这就是今天的主线：真的给你环境光了，怎么实时地把它对应的 shading 和 shadow 都算出来。今天要讲的，就是一个叫 precomputed radiance transfer（预计算辐射传输）的东西，简称 PRT。它既可以做 environment lighting，又可以做全局光照，正好是两块知识之间的连接——所以咱们把课程顺序稍微调整了一下，先说它。

PRT 要求用到一个听起来比较复杂的数学知识：spherical harmonics，国内叫球面调和函数，简称 SH，也有人管它叫球谐函数，一回事。这东西挺麻烦的，今天咱们尽量从所谓 high level 的思想上把它说清楚。

关于"预计算"这种思路，我简单说一下。它大概在二十年前——准确说是二十年前到十年前这段时间——得到了非常普遍的应用。后来渐渐地，在各种实时的、比如游戏开发中，大家发明了各种各样的"又不需要预计算、又可以得到一些近似效果"的方法，预计算方法就用的不那么多了。但咱们仍然一定要说它，因为它是一个非常里程碑式的作品系列，直到今天学术界还在努力地把这个方向往前积极推动——UC Irvine 的赵爽老师，还有包括我在内的很多人，都做过不少 PRT 方面的研究。如果有同学问：它之后还会不会得到比较不错的应用？我的答案是：会。尤其是和 real-time ray tracing 结合起来，它可能会得到一个重新焕发生机的机会。咱们不能只看着现在工业界在做什么——研究 PRT 是非常有意义的一件事情。

### 环境光下的阴影为什么这么难

先把问题立起来。有了环境光照之后，怎么得到它照出来的物体各个地方的阴影？非常不幸的消息是：实时渲染下，我们不知道怎么做。如果非要一个最 high level 的答案，那就是——做不到，非常难。为什么难？我给大家提供几个不同的看法。

**看法一：把环境光看成很多光源。** 环境光可以理解成四面八方过来的光照，而四面八方来的光可以各不相同。环境光上有一片是白的，你就可以认为那儿有一个白色的面光源。所以环境光本质上是所谓的 many light 问题——这个名字非常直白，就是"使用很多光源"的问题。那么要渲染整个场景、把阴影弄出来，每一个光源是不是都得给它生成一张 shadow map？这还得了！每个光源一张 shadow map，代价线性于光源的数量，这是非常高的代价，自然是我们不愿意做的事情。

**看法二：采样解渲染方程。** 在任何一个 shading point，我自然知道来自整个上半球各个不同方向的光照是什么。要解 rendering equation，最简单的办法就是采样：采各个方向上不同的光照，还可以做重要性采样，哪一块亮就多采一点——这都没问题，但仍然需要大量的采样样本。真正的难度不在于采样光照，而在于：你并不知道从任何一个 shading point 往各个不同方向看出去，看到的 visibility term 是什么。这是一个非常现实的问题——visibility 才是最难的。它可能在四面八方不同的位置、不同的方向上，遮挡情况截然不同。你可以重要性采样环境光照，这可以；但你本来就不知道任何一个 shading point 周围不同方向的遮挡情况，你如何去采它呢？只能盲目地采样，是不是？所以 visibility 就挺难的。

**看法三：回到咱们之前那个拆分——咱们给它起个名字吧，就叫"实时渲染方程"。** 就是之前说的那个拆分的方式：$f(x)$ 和 $g(x)$ 乘起来积分。当时说过，想把一个 term 拿出来分别积分，得要求剩下的 $g(x)$ 的 support 比较小，或者说它的频率比较低、比较 smooth。现在想把 visibility 拆出来，看看剩下两项行不行：BRDF 这边，diffuse 的 BRDF 变得挺慢，是低频的，还好；但 glossy 的 BRDF 集中在中间很小的一个区域，然后瞬间衰减到非常小——它是非常高频的，做不到。光照项 $L$ 呢？它的 support 是多大？整个半球。之前说想把某个 term 拆出来，剩下在积分里的 term 要么保持低频，要么保证 support 很小——glossy 的 BRDF 做不到低频，lighting 也做不到小 support，两头都对不起。所以 visibility 不容易从整个 rendering equation 中提出来。我就想说这个事。

三个看法讲完，它为什么难就说清楚了——当然还可以有别的看法。

> **提示**：有同学问，能不能用环境光遮蔽（ambient occlusion，AO）来近似整个 visibility？这是可以的，但要注意它近似了一件非常重要的事情：AO 假设你是在一个 constant 的环境光下——我认为整个环境光是全白或者全灰——才可以做这个近似。如果真是任意变化的环境光，你又拿 AO 去近似，得到的结果自然就没那么准，看着别扭是正常的，这就是目前大家能做到的效果。

### 工业界的土办法、文献线索与一个判断

再给大家一个解决方案。这个方案听起来非常土，但它确实是现在绝大多数工业界在做的事情：环境光照里面，总有一个最最有代表性的光源吧？比如人们在野外跑的时候，最重要的光源就是太阳，而太阳肯定来自比较小的一个立体角。那我就主要生成太阳投射下来的阴影就好了——从最亮的光源生成一个阴影，稍微多一点就生成两三个，差不多了。这真的就是工业界的解决方案，而且效果还不错：大家打游戏里面基本上都是这样的。

如果你希望在"环境光阴影"这个方向上做点研究，有几条我可以立刻想到的线索。一个是一篇实时渲染的工作，叫 imperfect shadow maps：它理论上做的不是"来自环境光的阴影"，而是全局光照部分产生的各种各样的阴影。挺有意思的一篇文章，也挺好懂，它放出了 paper 和一些 PPT，用我们现在的知识去看应该没什么问题——特别是等之后两讲把全局光照说明白了之后，这块应该是挺容易的。另外一个是离线渲染里非常重要的、里程碑式的一系列工作，叫 light cuts：它的思路是把场景中的反射物当成很多小的光源——很多反射物就意味着很多光源；那这么多光源怎么去照亮场景中的一个点呢？我不想把它们全部都看一遍，就把它们做一做归类，用归类去近似出它们整体照亮某一个点的结果——这就是 light cuts 的思想。它解决的就是咱们刚才提的 many light 问题，有兴趣的话可以继续看这块的文章。

然后是我个人的一个理解：如果真的想完全解决"从环境光照过来的阴影"这个问题，那么很可能在未来 10 年之内，会出现一批用 real-time ray tracing（RTRT，实时光线追踪）来解决它的实用方法。RTRT 用的本来就是 path tracing 加 denoising 的思路，应该可以解决所有跟采样、样本不足有关的问题。如果让我来做的话，我觉得我差不多应该能想到一些办法。我的判断是：RTRT 很可能是一个终极解决方案。

而跟这节课最相关的东西，还是 PRT。因为咱们会说清楚：PRT 这种方法可以得到非常准确的、从环境光来的阴影。那按照咱们 GAMES 课程分析问题的一贯思路——PRT 能解决这个问题，自然而然就要问：**代价是什么？** 咱们就看一看 PRT 好处在哪、坏处在什么地方。

课上有同学问到游戏引擎里的全局光照，顺带说一句：像 RTX GI、屏幕空间的方法、基于 probe 的这些方法，通常在游戏引擎里不太可能只用一个，正常情况下都是一些大杂烩，把所有东西都放在一块。有些洞穴场景的全局光照，如果我没记错，就是几种不同方案的混合体，特别是一些屏幕空间上的 trace 和 probe 的结合。背后的科学咱们课里都会有覆盖，我还是想说一句：这些方法说起来其实都没那么难，关键是你如何把它写到一个引擎里面，还能让它非常快，而且对任何场景都可以 work、不至于出现巨大的问题——这才是本事，工程上的本事。

### 预备知识：傅里叶级数、频谱与滤波

为了 PRT，咱们做一些数学知识上的储备。要理解 spherical harmonics 到底在做什么，得从频域和滤波这些知识上着手，还需要了解一些基函数的知识——这些都回到 GAMES101 里讲过的内容，咱们快速过一遍。

**先说傅里叶级数展开。** GAMES101 里我们说过傅里叶变换——这里我更愿意把它说成傅里叶级数展开。拿一个不断周期性重复的 box 函数来说：这样的函数，可以用一系列函数描述起来——说白了就是一个常数的提升，加上一系列 sin 和 cos 函数；不断增加项数，就能得到不断更好的逼近。有同学可能会问：这里我怎么只看到 cos，没有 sin？那是因为这个函数本身是个特殊的函数——它是一个偶函数，左右对称，所以 sin 项自动就是零，仅仅是因为它特殊。正常情况下，任何一个函数都可以写成一个常数和若干 sin 项、cos 项的组合：

$$f(x)=a_0+\sum_{k}\left(a_k\cos k\omega x+b_k\sin k\omega x\right)$$

项里出现的 $\omega$、$3\omega$、$5\omega$、$7\omega$ 意味着：这些 sin、cos 的周期不一样，或者说频率不一样。频率不一样，从图上就能直观看出效果：一开始用一个 cos 函数，看起来挺 smooth；后来引入一个频率更高的项，变化就大很多，可以加入一些细节；再引入变化更快的 sin 和 cos，就能加入更多细节，最终把整个原始函数的样子描述出来。所以傅里叶级数展开告诉我们：任何一个函数，都可以写成一堆 sin 和 cos 的线性组合，并且这些 sin、cos 各自有对应的频率——从最低频（完全不变的一个 constant）开始，到稍微有一些频率上的变化，再到变化非常剧烈，它们之间隐含着一个由低到高的关系。

一个函数表示成其他这些函数的线性组合——那一堆"其他函数"，就是我们后面要用的基函数。

**频率是啥意思。** 咱们刚才说高频低频，高频低频说的就是这个信号变化的快还是不快。注意，不是指在真正的时间上这个信号一直在抖，而是说在空间上：你在空间上画一道线，这条线经过（比如一张图像上的）不同位置，把这些位置的值显示出来，看它变化是非常剧烈，还是比较平缓。人物头发那一块，一根一根的，变化非常剧烈——高频；背景上颜色差不多，变化非常不剧烈——低频。就这么个意思。

**频谱与滤波。** 对任何一个函数——一张图自然就是二维函数——我可以把它在频域上对应的内容显示出来，这就是它的频谱。频谱最中心这一块，我们认为它是最低频的内容；稍微向外一些的区域，就是高频的内容。对任何一张自然的图片来说，绝大多数都是低频内容：人脸上这些颜色变化比较少，人的衣服上变化也比较少。那如果做一个滤波操作——在频谱上只留下最低频的部分，再把它变回原来的图——就会发现：只用最低频的这些部分，就已经可以得到一张相对模糊的图了。这也正说明了一个问题：对一个信号来说，保留它的低频部分，其实还是基本能看明白这张图在干什么。

> **定义**：所谓滤波（filter），就是去掉一系列对应频率上的内容。像刚才这样留下最低频率的，叫低通滤波器（low pass filter）——比它频率高的地方都扔掉，对应的原始函数（信号）自然就由低频信号组成，看到的就是一些模糊的东西。

**卷积对应频域乘法。** 咱们之前还提过一件事：时域和频域之间有一个相对应的操作——在时域上做卷积，等于在频域上做乘积。卷积其实就是一个模糊操作，图形学里咱们不怎么特别说"卷积"这个词：拿一幅图，对任何一个点，取它周围 3×3 的区域，把这片区域里像素的颜色算一个平均，再写回这个点——3×3 挺小的；要是取 9×9，图就会变得非常模糊。这种"对任何一个点都取周围一片区域、把这片区域里的结果综合起来再写回这个点"的操作，就叫卷积。

在频域上看这件事：原始的图有它的频谱；卷积核——也就是"取周围多大一块"的那个东西——可以拿某种函数来表示，比如一个 3×3 的 box，它也有自己的频谱。box 变到频域之后，大体还是一个有些地方接近 1、有些地方是 0 的形状，边上会漏出一点高频的涟漪。两个频谱在频域发生逐点相乘：是 0 的地方乘完就是 0，就好像用了一个类似 Photoshop 里 mask 的东西；相乘之后剩下的这些，再做一个逆变换，就可以得到模糊之后的结果。

```text
图像 f          ──变换──▶   频谱 F
卷积核 h(3x3)   ──变换──▶   频谱 H（近似一块低通的"mask"）
卷积 f ⊛ h      ◀─逆变换─   逐点相乘 F · H
```

左边对图像直接做卷积，和右边把频谱逐点相乘再变回去，是完全对应的同一件事——频域和时域之间就是有这么一个相互对应的关系。

**这节课真正要用的观点。** 上面说的这些对应关系，在这节课上的应用绝对没有那么麻烦。咱们接受一个更通用的理解：卷积基本上就等于滤波。那么，两个函数乘起来再做积分，我就可以认为这是一个卷积操作，或者一个滤波操作。

> **定义**：product integral——一个函数 $f(x)$ 乘以一个 $g$，再把它积分起来。任何满足这种形态的操作，我们就认为它存在一定的滤波意义。

严格来说，这里相乘的两个变量应该区分开：写成 $f(x)$ 乘以某个 $g(y)$，再对 $x$ 积分，这样就清楚了——这是课上有同学指出来的，问得非常对。总之这个事情不是特别重要，大家差不多知道这么一件事就好：两个信号在时域上乘起来再积分，等价于它们各自的频谱在频域上相乘。

> **结论**：两个函数各自的频谱，只要有其中一个是低频的，频域上乘出来的结果就是低频的——相当于只留下了频谱中间的那一部分。所以乘积积分得到的结果，其频率一定由 $f$ 和 $g$ 各自频率中最低的那个来决定。

那什么叫低频？咱们有一个简单的理解：只要它看起来 smooth——之前做 split sum 的时候咱们说过这个事情——它的变化没有那么剧烈，这就叫低频。概念上理解到这儿就够了，这是用在后面分析 rendering equation 的。

### 基函数：能拼出任意函数的一族函数

接受上面那个观点之后，咱们给大家介绍一个基本概念，叫基函数（basis functions）。它是什么？其实刚才已经说过了。

> **定义**：用一系列函数 $b_i$ 的线性组合去描述一个函数——$f(x)=\sum_i c_i\, b_i(x)$，每个 $b_i$ 前面乘上某个系数 $c_i$，全部加起来得到原始函数——这一系列函数 $b_i$ 就叫基函数。

它的目的就是：用这套基函数的不同组合，可以描述不同的函数。刚才说的傅里叶那套——一堆 sin、cos，还有那个常数——就形成了一套基函数，因为它们可以描述前面那个周期 box 函数。同样道理，还有一套大家肯定在学微积分的时候就学过的常用基函数：多项式系列——$1$、$x$、$x^2$，一直到 $x$ 的高次。说一个函数可以描述成这些函数的线性组合，这和泰勒展开是非常像的：给你一个函数，展开成 $1+x+x^2+\dots$，就有这么个意思在里面。所以基函数不是一个非常复杂的话题：它就是一系列函数，它们的组合可以描述某个函数而已。

到这里，咱们要做的知识储备就差不多了。用这些知识，基本就可以进行后续对 environment lighting 的频域分析，以及 spherical harmonics。

### 球谐函数：定义在球面上的"傅里叶基"

还记得我们要解决的问题吗？环境光照下怎么样把这阴影给搞出来。咱们一步一步来，先解决一个简单问题：给你整个环境光，给你一个物体，这个物体全部都是 diffuse 的——在这种情况下，有没有什么好的办法，先把 shading 给做出来？shadow 咱们先不考虑。为此引入我们现在需要用的数学工具：spherical harmonics。这个概念工业界的朋友们肯定都接触过，但它一开始学起来挺麻烦：本身涉及频率的划分，又涉及各种各样的运算性质，还自带积分。但按我个人的理解方式，咱们没必要把它想得特别特别困难。

**SH 是一系列定义在球面上的二维基函数。** 首先，它不是一个函数，是一系列基函数；这个系列中的每一个都是二维的，并且都定义在球面上。什么叫"定义在球面上"？你可以理解成它是关于方向的函数：三维空间中任何一个方向，其实就是个二维的东西——一个方向可以拿 $\theta$ 和 $\phi$ 来描述嘛，两个数可以描述的东西，自然就是二维的。而单位球面上的一个点，就描述了一个独特的方向。所以整套 SH 定义在球面上：球面上不同的点（方向）取不同的值，每一个 SH 基函数都是一个独特的、定义在球面上的二维函数。

**它非常像一维情况下的傅里叶级数。** 傅里叶级数做的事，是给你任何一个函数，把它拆成不同频率的部分：常数、sin、cos，而且 sin 和 cos 各自的频率都不一样。SH 与此非常非常相似：它本身也存在不同频率的函数，而且不同频率的函数个数也不同。看 SH 的可视化——那些画成小球的图——它是分层的：$l=0$ 这一层只有 1 个函数，它是 uniform 的，球上任何一个方向值都一样，看起来就是一个均匀的球；$l=1$ 这一层有 3 个函数，相当于某个半球上有值、另外半球上对称地有相反的值，三个函数各自的朝向不一样；$l=2$ 这一层有 5 个函数，频率都一样，只是各自长得有区别；$l=3$ 这一层有 7 个，个数又多了些，形状或者旋转各不相同，但同一层内描述的频率是一样的。所以 SH 没有任何特殊的地方：它们仅仅是二维的函数，这些二维函数被归类成不同的频率段，每种频率上有若干个不同朝向、不同形状的二维函数而已。

那我问大家：$l$ 等于几的时候，有几个不同的函数？

| 阶 $l$ | 基函数个数 | 编号 $m$ 的取值 |
| :---: | :---: | :---: |
| 0 | 1 | 0 |
| 1 | 3 | $-1,0,1$ |
| 2 | 5 | $-2,-1,0,1,2$ |
| 3 | 7 | $-3,-2,-1,0,1,2,3$ |

有同学立刻答出来了：$2l+1$ 个，对，就是这么回事。

> **易错点**：第 $l$ 阶 SH 有 $2l+1$ 个基函数——是 $2l+1$，不是 2 的多少次方。每个基函数还有固定的编号 $m$，从 $-l$ 一直到 $l$：$l=0$ 只有编号 0，$l=1$ 是 $-1,0,1$，$l=2$ 就是 $-2$ 到 $2$，$l=3$ 就是 $-3$ 到 $3$。

再问一个：前 $n$ 阶总共有多少个基函数？比如前三阶，意思就是 $l=0,1,2$。这是个非常有趣的事情，答案也简单：$n^2$ 个。前 1 阶（就是第 0 阶）1 个；前 2 阶总共 4 个；前 3 阶 9 个；前 4 阶 16 个——$1+3+5+7=16$，就这么简单。这里"前 $n$ 阶"指的是 $l=0$ 一直到 $n-1$，咱们把这个说清楚。

**为什么不用"把地球展开成地图"那一招。** 可能有同学会问：傅里叶是可以做二维傅里叶变换的。那我给你一个球面函数，不把它展开成 $\theta$ 和 $\phi$ 的二维图吗？展开成二维图——不就像咱们之前说的把地球展开成地图嘛——地图不就是二维的图吗？我为什么不做一个二维的傅里叶变换，照样可以分析这些对应的属性呢？这里直接给大家一个结论：咱们平常在 rendering 里用到很多球面上的函数，如果你把它展开成二维傅里叶的这些基，根据不同的频率去考虑它、做一些近似，最后再把结果变回整个球面上，你会发现很可能球面上被你弄出缝来——这是很正常的一件事情。当然，球面展开成二维图本身是行的：咱们之前说的 environment map 就是这么回事，一张环境贴图就是一个球面展开成二维图的典型例子。但 spherical harmonics 本来就是定义在球面上任何一个不同方向的，从那些可视化大家也能看出来，它在球面上非常非常连续——也就是说，它很适用于直接拿来分析球面上函数的性质。

**每个基函数是怎么写出来的。** 肯定有同学会关心：$l=3$ 那一层那些长得好奇怪、很有意思的函数，是拿什么写出来的？给大家一个答案：每一个基函数，是利用所谓的勒让德多项式（Legendre polynomials）来写的。勒让德多项式是一个非常麻烦的多项式，但它毕竟是个多项式；数学上写起来挺麻烦，这也是我为什么不愿意把这个公式写上来——没有任何必要。你知道一个基函数长这样、可以用某些数学工具来定义它、不同的方向上值是多少，不就可以了吗？我非常不建议学 spherical harmonics 的时候去说他具体怎么写出来，那一点关系也没有。咱们要理解的是它到底在干什么：任何一个函数，都可以把它描述成基函数的组合；并且 spherical harmonics 类比于傅里叶级数的那些基函数，也有一个好处——它从低到高可以把不同的频率描述出来，从最低频到最高频。

**可视化里的颜色不是频率。** 有同学问图中间的颜色表示什么，这里专门说清楚：颜色不是频率，颜色表示的是值。越偏白的蓝色，那个地方的值越大；相应的，越偏白的黄色，表示值的绝对值越大——也就是说这些基函数有正有负。以 $l=1$、$m=0$ 中间那个函数为例：它在北极的地方值非常大（正），南极的地方值的绝对值非常大（负），而在整个赤道上值都是零。那频率看什么？看值的变化大还是不大，这个一眼就能看出来：$l=3$ 那一层长得跟花儿一样，变化这么剧烈，它的频率当然就比 $l=1$、$l=2$ 那些层要高。

希望通过这一系列观察分析，先打消大家对 SH 的恐惧感：它没有任何特殊的地方，真的就是一堆定义在球面上的二维基函数，被归类成了各种不同的频率段，每种频率上有若干个不同的基函数，仅此而已。

### 投影与重建：SH 怎么用

现在咱们引入了 spherical harmonics 的概念，就把它作为一个基函数来用。基函数是干什么的？给你一个函数，你用基函数的线性组合，就可以表述原来那个函数。那我自然而然要问一个问题：给你一个二维的球面函数 $f(\omega)$——$\omega$ 就是方向——如果我要把它展开成用 spherical harmonics 的线性组合来描述的函数，那么对应于任何一个 SH 基函数 $b_i$，它前面那个系数 $c_i$ 应该是谁？

这里有一个非常干净利落的性质：$c_i$ 就是咱们刚才说的 product integral——两个函数先乘起来再做积分，也就是对应位置逐点相乘，然后再做积分，就这么简单：

$$c_i=\int f(\omega)\, b_i(\omega)\, \mathrm{d}\omega$$

而且这是它非常不错的一个性质：给你任何一个球面函数 $f$，用整套 SH 基函数去描述它的时候，任何一个基函数前面的系数是多少，立刻就能求出来。

> **定义**：给你任何一个函数，用某一整套基函数（basis）去描述它时，求任何一个基函数前面系数的过程，就叫做投影（projection）。任何函数 $f(\omega)$ 都可以求出它在任何一个基函数上的投影。

知道了任何一个基函数前面的系数是多少，那我就可以恢复原来的函数。只不过这个时候，就是人们聪明的地方：spherical harmonics 照这种定义方法，$l$ 可以无限大——$l$ 等于 100，对应那一行大家就知道得有 201 个函数；基函数可以是无限多的。给你一个函数，我可以求出它对任何一个基函数投影出来的系数；但要恢复原函数，我其实并不想用那么多的基函数。比如我有一个函数，我就想用前四阶的 SH 来恢复——前四阶就是刚才说的 16 个基函数——那我就把这 16 个系数 $c_i$ 和对应的 16 个基函数 $b_i$ 乘起来，总共乘这么 16 个、加起来，就可以恢复出原来函数的一个近似了。

并且大家已经可以看到一个不错的事情：如果我用前四阶的 SH 恢复出来一个函数，那恢复出来的这个函数，是不是就只保留了 $l=3$ 所能表述出来的最高频率？更高的频率，我就把它扔了。这就好像傅里叶级数里取前面五项、前面七项：恢复出来的函数能表示的细节越来越多——用的基函数个数从低到高越多，就越能引入稍微更多一点的高频信息。

那 $f$ 是谁？$f$ 是任意的一个函数呀，不是某个特定的基函数——它可以表示任何的球面函数。咱们要用的那个应用是什么呢？就是环境光照：环境光是不是来自四面八方都有值？它是不是就是一个球面的函数？它就是咱们可以理解的 $f$。我可以把它投影到任意多阶的 SH 基函数上；不管投影了多少阶，我只要用前多少阶的 spherical harmonics 去恢复它，我就可以恢复出环境光里最低频的那些信息。

到这儿，spherical harmonics 这个概念就介绍完了：它没有任何特殊的地方，就是一堆函数，每一阶拥有一种频率，阶越高、描述的频率越高，对应的基函数数量也多一些。它的用法和所有基函数一样——投影求出系数，再取前若干阶做线性组合恢复，而"只取前若干阶"这个动作本身，就天然完成了一次只留低频的滤波。后续咱们要说它的应用：怎么拿这套工具，把环境光下的 shading、乃至那难缠的 shadow，真正实时地算出来。

## 球谐函数的第一次实战：Diffuse 环境光着色与 PRT 预计算
> 对应块：BLK12 | 覆盖分集：P06下 | 块标题（分集名）：《Lecture6 Real-time Envir》

### 开场先把几个疑问掰扯清楚

先从几个疑问说起——它们都问在了点子上，正好把基函数这块的线头收一收。

第一个疑问：环境光贴图到底怎么个"投影"法，是拿着图上每个像素投一遍吗？不是。整个环境光 environment map 描述的是球面上的一个二维函数；所谓投影，是这个函数对每一个基函数都算出一个值——一个系数。它不是按像素去投的，不是那个意思。

第二个疑问：基函数这么多，怎么挑出"重要"的一组？这里的"重要"说的是频率：我们公认最低频的信息最重要，所以取法就是从最低频到最高频顺着来——要恢复一个函数，只需要用它最低的前几阶，也就是前 $n$ 阶的基函数去恢复，这就对了。

那每一阶内部还要不要再挑？通常人们不挑：说用前多少阶，就是把前多少阶内部的这些基函数全用上。很少有人在一阶里面挑两个（比如说 $l=2$ 里挑两个）来描述函数，通常不会这么干。

第三个疑问最实际：投影那个积分怎么算？肯定要对不同的方向进行采样，想直接算出一个解析解没那么容易。那么自然而然就能得出一个结论：这个计算在实际渲染的时候很可能承担不起，得拿到渲染之前去做——这就是预计算的思想，马上就会用到。

### 从向量到基函数：同一套数学

求出这一串系数的过程叫投影。这个词不是随手借用的——GAMES101 里就说过：空间里有一组相互垂直的 $x$、$y$、$z$ 轴，给你任何一个向量，它的坐标就是它分别投影到三根轴上的值；反过来，任何一个向量都能写成

$$\vec v = c_x\,\hat x + c_y\,\hat y + c_z\,\hat z$$

数学这些东西都是相通的。在这种表述下，$x$ 轴、$y$ 轴、$z$ 轴就是三个基函数；"想用基函数的组合表示任意一个向量，前面的系数怎么求"——做投影，和把函数投影到基函数上是完全一样的道理。

还有更有意思的一层：把向量投影到 $x$ 轴或 $y$ 轴，做的是点乘；而把函数投影到基函数上，做的是一个积分——两个函数逐点相乘再积起来，我把它叫 product integral。马上就会说到，这个积分的本质就是一个点乘：点乘从向量推广到了函数而已。这些事情都是触类旁通的。

从类比里还能看出第三个概念：正交。$x$ 轴投影到 $y$ 轴、投影到 $z$ 轴，值都是零。那把一个基函数投影到另一个基函数上呢？比如把 $l=1, m=-1$ 这个函数投影到 $l=3, m=2$ 上去，得到的结果会不会也是零？如果是零，那能不能说这两个基函数互相垂直？能，这个性质就叫正交（orthogonality）。所以不管是线性代数里还是 Spherical Harmonics 里，这些概念的定义基本完完全全一样——这算我个人的一点点理解：数学都是相通的。

### 第一个实战：Diffuse 物体的环境光着色

#### 问题设定，和一段师承

引入基函数之后，先用它解决一个超级简单的问题：环境光照下 diffuse 物体的 shading。注意，这里仍然没有考虑 shadow，只是 shading。

这一部分的内容沿用 Ravi 教授当年做的课件，我完完全全不敢在上面改任何东西。为什么？Spherical Harmonics 就是我当年读博的老板 Ravi Ramamoorthi 教授引入图形学的——正是因为他做了这部分工作，才有了之后整个 PRT 的十年，可以说是引领了一个时代。

有同学问：之前不是已经说过 shading 怎么做了吗？对，没错。这里只是举一个例子，用它来引入后面更一般的情况——PRT 要怎么做。

#### 先回顾 Prefilter 的直觉

上节课说 split sum 的时候讲过一件事：对着环境光沿镜面反射方向直接查一个值，看到的就是一面镜子。那如果先把环境光做一个 filtering——filtering 是什么？不就是 convolution、不就是模糊嘛——先把整个球面函数模糊一遍，然后同样沿着镜面反射方向，在这个模糊过的环境光上查一次，得到的结果看起来就是 diffuse 的。

所以"prefilter 过的环境光 + 一次查询"，等价于"不做任何滤波，在一个点上往各个不同的方向查询、把整个 environment 的值都算一遍再平均"。这两个过程基本上是等价的——这就是之前说的 prefiltering。

#### Diffuse BRDF 本质是个低通滤波器

现在看 Ravi 当年在博士期间做的工作。在 diffuse BRDF 下，rendering equation 得到了一个非常好的简化。diffuse BRDF 为什么简单？因为它非常 smooth。这一步要算的是 lighting 乘以 BRDF 再积分：考虑 shading 就没有 visibility；cos 项暂时不单独操心，都归进"BRDF 项"。于是手头的活是：lighting 是整个 environment map 给出的球面函数，BRDF 是定义在整个半球上的一个很光滑的函数，两者逐点相乘再积起来——这就是两个函数的 product integral。

环境光可以非常复杂，低频高频都有；但如果 BRDF 是 diffuse 的，它就有一个非常好的性质——它就像一个低通滤波器。前面知识储备里那条思路直接派上用场：两个函数做 product integral，乘出来的结果的频率，由频率最低的那个函数决定。换句话讲，环境光不管有多高频，拿它来照亮一个 diffuse 物体，基本看不到什么高频信息。这件事想一想就显而易见：大家从来没有见过一个 diffuse 的球表面反射出非常复杂的光照吧？

#### 三阶实验：误差不超过 1%

既然 diffuse BRDF（连 cos 项带上）这么简单，Ravi 就想到：是不是可以用很少的 SH 基函数去描述它？SH 前面刚说过，从最低频开始描述，一点一点往高频走。

把 diffuse BRDF 投影到 SH 上会发生什么？有一张图（早期的图做得实在难看，但非常能说明问题）：横轴是阶数 $l$。第 0 阶、第 1 阶、第 2 阶投影出来都有值——各自得到系数 $c_i$；投到第 3 阶，基本上就没什么内容了；第 4 阶似乎有一点负的，但也很少。也就是说，从第三阶开始，投影不投影无所谓了：前三阶还有值，再往后就没值了。

这个现象非常有道理：后面几阶投影没有值，说明这个函数根本没有后面几阶所描述的高频信息。任何一个函数，如果用几个 cos 加 sin 描述到前几阶就 OK、后面根本没必要描述，那就说明这个函数本身挺低频的。这张图说明的就是：diffuse BRDF 就是挺低频的。

再往下推一步：BRDF 低频到第三阶就没内容了，那光照又何必描述那么高的频率呢？于是 Ravi 做了一个实验：一组是正确的积分结果；另一组依次用不同阶数的 SH 来描述光照——

- 只用前一阶：前一阶就是一个完全 constant 的函数，拿它去照亮球，得到一个非常平的结果，不太好；
- 用前两阶：结果看起来已经不错了；
- 用前三阶：和正确结果几乎完全一致，误差可以计算出来，小于等于 1%。

> **结论**：对任何光照条件，只要材质是 diffuse，都可以用前三阶 SH 来描述光照，然后拿它去照亮 diffuse 物体。

原理咱们已经说清楚了：刚才那张投影图说明，BRDF 的频率不会超过三阶 SH 能表示的频率；而现在做的事情，是光照项与 BRDF 项的 product integral，所以光照项也不需要超过三阶 SH 所能表示的频率。

有同学问：SH 近似的是什么？这里说清楚：是通过先分析 BRDF 的频率，来决定用多少阶 SH 去近似光照——仅仅是光照。而 $f$ 指的就是任意的环境光贴图，当然是个球面函数。

还有同学问：SH 是不是只能应用在 diffuse 上？这不一定。SH 其实非常适合描述低频的光照；这里的意思只是说，物体是 diffuse 的情况下，你根本用不着那么高频的光照。

#### 两行代码与一个博士学位

Ravi 把这套理论写进了自己的毕业论文，并且指出一件事：如果 SH 只用前三阶，最后的结果可以写成一个 polynomial——一个平方的、与 shading point 法线相关的函数。也就是说，diffuse 物体在 SH 光照下的结果，其实可以写成一个关于法线的二次型（quadratic）。这一块算 FYI，简单说一下。

说它的目的是告诉大家：Ravi 当时写了一个函数，用来计算环境光照下任何一个点的 shading 结果。这个函数用了多少行代码？两行。这就是历史上著名的"两行代码拿博士学位"的例子——这是真的。这两行代码背后的数学当然非常多，但不管怎么样，就这两行代码，他拿到了博士学位，并且引领了整个时代，开创了运用 Spherical Harmonics 去解决很多实际问题的时代，也算是开启了 PRT 的时代。

不过这里还是要说清楚：这仍然是 shading，不是 shadow；说的仅仅是"大家用 Spherical Harmonics"这么一个事情。

### 基函数的三条本事

到这里先把基函数的账归拢一下。

其一，基函数可以表示任何函数——只要基函数的个数足够多；对 SH 来说，就是取足够多的前 $n$ 阶。

其二，如果只想保留一个函数的低频信息，很简单：只取前面低阶的那些基函数和它们对应的系数，用它们重建原函数，得出来的必然是低频信号。

其三，前面埋了个伏笔：如果两个函数都是拿 SH 基函数来表述的，它们的 product integral 其实是一个点乘。这个结论刚才没展开，等推导完 diffuse 情形，大家自然就看到它是怎么回事。

### 问题升级：把阴影和任意 BRDF 都算进来

刚才那个例子解决的是 shading，而且还是 diffuse 物体、没有阴影。那现在有两个问题要解决：第一，我不希望它没有阴影，要把阴影引入进来；第二，能不能还是用同样的基函数思路，但去解决任意 BRDF 的问题——比如 glossy BRDF，不再限制是 diffuse。

解决这两件事的思路，自然而然就是 PRT：Precomputed Radiance Transfer，预计算辐射传输。

先把 PRT 的能力说清楚：它能从环境光出发，对任何 BRDF 的物体，把阴影——也就是遮挡关系——都考虑进去。而且它不仅仅能做环境光照下的 shadow 和 shading，还可以做全局光照。所以咱们先说环境光照怎么做，再通过它引入后续整个 global illumination 怎么做，我觉得再合适不过。

老规矩提醒一句：PRT 听起来不错，但它的代价是什么？这是咱们要关注的事情。

（这一部分材料要特别感谢我的另一位导师——我在清华读本科时带我 rendering 入门的徐昆老师，标准的 PRT 专家，人非常厉害；这里直接用当年上课的讲义。）

PRT 涉及到的知识真的一点儿也不难。之前人们会觉得它比较难，是因为基函数这些东西牵扯的多一些；咱们前面花了时间把基函数说清楚了，这样一来，用基函数去解决 PRT 这个问题，其实是非常简单的事。

### Triple Product：三项都是球面函数，但暴力算不动

在实时渲染中，人们更愿意把 rendering equation 写成 triple product 的形式：lighting 项、visibility 项、BRDF 项，三块乘起来再积分，得到的就是沿观察方向 $o$ 看过去的值：

$$L(o)=\int_{\Omega} L(\omega)\,V(\omega)\,f(\omega_o,\omega)\,(n\cdot\omega)\,d\omega$$

要真的解这个积分，采样是一个思路；不采样的做法，就是把所有可能的入射方向都考虑一遍。这时候会发现，三项全都是球面函数：

- lighting 是球面函数，cube map 就是它的描述法；
- visibility 也是球面函数：任何一个 shading point 往四面八方看，看到的就是一个球面。拿其中一个点来说，往下半球看完全是黑的，往上看，有些地方能看到 light，有些地方被东西挡着看不到。所以这一点的 visibility 要么是 0 要么是 1，把它记下来，自然也是个球面函数；
- BRDF 本来是四维函数（入射方向 × 出射方向），但现在从某个方向看，等于告诉了这个四维函数出射方向 $\omega_o$ 是什么，剩下的入射方向就是二维的东西——它也可以描述成一个球面函数。

最直观的解法就是：cube map 上对应的像素挨个乘，三个值乘起来，再按立体角加权，把所有方向的贡献加起来。

这个做法是不是非常费？假设 lighting 的 cube map 每面存成 64×64，一共 6 面，那么每个 shading point 都要做 $6\times 64\times 64$ 次"三个值相乘再累加"。每个点都要来这么一遍，非常非常麻烦——咱们自然不想干这种事。

### PRT 的核心假设：整个场景只有光照会变

Ravi 提出 Spherical Harmonics 之后，立刻有人联想到：是不是可以利用基函数的基本原理，先把一些比较复杂的东西预计算出来？这篇 paper 就是足以记入史册的一篇——Precomputed Radiance Transfer，标题后面还拖着一长串。之前讲 rendering equation 的时候说过"名字越短影响力越大"，所以我其实非常希望这篇 paper 的名字就叫 Precomputed Radiance Transfer，后面那串都没必要写——它的贡献已经非常大了。它要解决的就是：怎么才能让我算任何一个点带着 shadow 的 shading 结果算得快——说"带 shadow"，是因为现在 visibility 已经被考虑进来了。

PRT 的基本思想是一个假设：整个渲染的时候，场景里其他东西都可以不变，只有光照可以发生变化。光照怎么变都行——换一种光照可以，同一种光照做旋转也可以，都没有问题。

在这个假设下，rendering equation 里积分的东西就不用看得那么麻烦了，可以把它看成两部分：一部分叫 lighting，另一部分跟 lighting 无关，咱们管它叫 light transport。之前拆成三项也好，现在拆成两项也好，没关系，先把它拆成两部分。

> **定义**：PRT 的二分法——rendering equation 拆成"会变的 lighting"与"不会变的 light transport"；后者是每个 shading point 自己的性质，可以在渲染之前算好。

那 PRT 做了什么？把 lighting 拆成基函数：lighting 不是四面八方的二维球面函数嘛，可以写成一系列 basis function 与它们前面的系数相乘再相加，预计算的时候光照就按这个方式写出来。另一方面，既然假设只有 lighting 在变，那对任何一个 shading point 来说，它的 BRDF 不变，整个场景其他地方也不变——这就意味着 light transport 对任何一个点来说是一个固定的东西，可以认为是这个 shading point 自己的性质。既然固定，那就可以在渲染之前先把它算好。

预计算的到底是个什么东西？看 light transport 的构成：visibility 是这一点往任意不同方向看的结果，对每个方向 $\omega$ 有不同的值，是球面函数；BRDF 固定了观察方向 $o$ 之后剩下二维，没问题；后面 $n\cdot\omega$ 这一项，对这个点来说法线 $n$ 是常量，cos 项也是 $\omega$ 的函数。它们几个放在一块儿，本身还是个球面函数。既然是球面函数，light transport 是不是也可以写成基函数的表示？就是这么个思路。

### Diffuse 情形的完整推导：一路走到点乘

分两种情况看：glossy 和 diffuse。diffuse 自然简单，先把这块走完。

Diffuse 的情况下 BRDF 是什么？GAMES101 讲过：它就是一个常值。既然是常值，我放心把它拿出积分，跟这一点关系都没有。

> **易错点**：这里不是一个什么近似，是标标准准的等式——diffuse 的 BRDF 既然是常数，当然可以拿到积分外面，写成一个 $\rho$；大家可能更熟悉写成 $k_d$，无所谓，它就是一个数。

$$L(o)=\rho\int_{\Omega}L(\omega)\,V(\omega)\,(n\cdot\omega)\,d\omega$$

接着，把任何一个光照都写成基函数描述的形式——某一个系数乘以 SH 基函数，全部加起来：

$$L(\omega)=\sum_i l_i\,B_i(\omega)$$

把这个求和式带进积分，然后交换积分与求和的顺序。在微积分里，咱们经常探讨什么时候可以交换求和与积分；在图形学里从不考虑这件事，我们认定它一定可以交换。（当然，最近在 differentiable rendering 里大家真的要考虑这个问题了，但在 PRT 这个场合下是绝对不需要考虑的。）

交换之后，对每一个基函数 $B_i$ 的限制来说，$l_i$ 对积分而言是个常数，先拿出来。那积分里剩下的是什么？$V$ 乘以 cos 项，再乘以 $B_i$——这不就是 light transport 吗！light transport 这个球面函数乘以一个基函数、再积起来，正是前面说的事：light transport 投影到某个基函数上的系数是多少。

$$T_i=\int_{\Omega}V(\omega)\,(n\cdot\omega)\,B_i(\omega)\,d\omega$$

场景中只有 lighting 在变，其他什么都不变，所以任何一个 shading point 投影到任何一个基函数上的结果都可以预计算——投影上去得到的是一个数。每个 shading point 只需要把前若干阶 SH 对应的那些数记下来。

到了实际运算：给你一个光照，它已经写成基函数下的系数了；light transport 也预计算出一串数。对任何一个 shading point 算最后的 shading 值，只需要

$$L(o)=\rho\sum_i l_i\,T_i=\rho\;\vec l\cdot\vec T$$

对 $i$ 求和，每一项算 $l_i\times t_i$——给你两个向量，逐个元素相乘再全部加起来，这不就是这俩向量的点乘吗！所以任何一个 shading point 算 shading，就只需要算一个点乘，一下就非常好了。前面那个伏笔也在这儿兑现了：两个都用 SH 表述的函数做 product integral，落到运行时，就是一个点乘。

```text
PRT 的分工一览

  预计算（离线，时间当它无穷多）
      场景固定，光照不管
      light transport = V(ω) · cos(n·ω) · BRDF(ωo, ω)   ← 合起来是一个球面函数
            │  对每个 shading point 投影到各阶 SH 基函数
            ▼
      每个点存一个向量 (t1, t2, …, tn)

  运行时（在线，每点一次）
      新光照 L(ω) 投影到 SH  →  系数向量 (l1, l2, …, ln)
            │
            ▼
      shading = ρ · Σ li × ti   ← 就是一个点乘
```

读图：与光照无关、又极其昂贵的 light transport 整体挪到离线；在线每个 shading point 只剩一次点乘。

### 代价账本：什么被钉死了，什么还自由

中间听起来已经非常美好了，但我一直在问代价是什么。停一下，把账算清楚。

第一笔账：预计算 light transport，意味着 light transport 里面所有东西都定死了。cos 项是 rendering equation 自带的，不用操心；visibility 定下来意味着什么？任何一个 shading point 往四面八方看、被场景中其他东西挡住光的方式完全一样。这就意味着场景不能动。

> **注意**：场景不能动，是 PRT 预计算的硬代价。场景里那把椅子要是拿走，就完蛋了——地面上势必有很多点，它们的 visibility 这个球面函数要在某些地方发生变化。

第二笔账在 lighting 上，这笔反而是好消息：光照写成基函数之后，如果有两张不同的环境光贴图，一张室外、一张室内，各自预计算好，各自就对应一个向量（不同的 $l_i$）。那就可以换光源了——光源可以随便切换，只要这些光源都被预计算过。

那同一种光照只是转个角度呢？比如都是室内这一张，但光源本身可以旋转。这就不太行了：光照这个二维函数已经写成基函数描述了，它一旋转，不就等于换了一种光源嘛。那怎么办？这正是人们聪明的地方：这个问题是可以处理的。对预计算好的光源，把它投影到 SH 上之后，可以立刻得到旋转之后对应的 SH 系数怎么变化——这是 Spherical Harmonics 的一个性质，下面专门说。

顺带回答一个同学的问题：旋转光照不会影响 V 项吗？当然不影响。V 项是任意 shading point 往四面八方看某个方向是否被物体挡住，跟那个方向上具体是什么光照没关系——$L$ 和 $V$ 本来就是拆开的。那物理遮挡关系变了（比如物体形变）有没有办法解决？能，后续的 precomputation 研究里，真的有人在致力于解决物体形变之后怎么办。

### SH 的三个好性质

Spherical Harmonics 有很多不错的性质，这里说三个最要紧的。

**正交性。** 一个基函数投影到另外任意一个基函数上，得到零：$B_i$ 乘 $B_j$ 再做积分，结果等于 0。任何两个基函数都可以认为互相垂直——垂直就叫正交，两个说法一回事。只有投影到它自己的时候，结果才是 1。还是类比 $x$、$y$、$z$ 轴：$x$ 轴投影到 $x$ 轴是 1，投影到其他任何轴都是 0。所以说 SH 是一组正交基，就是这个意思。

**投影好算。** 给你任何一个函数，要把它投影到 SH 上，就是把这个函数和任何一个基函数做 product integral——一个积分换一个系数，完了。

**简单旋转（simple rotation）。** 这是要重点说的一件事，前面留了个尾巴：预计算好的光照一旋转，就成了一个新的二维函数，想拿到它新的 SH 系数，按老办法得重新投影一遍；而投影一次到一个基函数上，就要解一个积分——这多麻烦。SH 恰好有一个非常优秀的性质（这里直接给结论，展开说就太数学了）：SH 非常支持旋转。

思路是这样：一个函数（比如光照）投影到各基函数上，得到一组系数；旋转原始函数，是不是就相当于把对应的各个 SH 基函数都旋转同样的角度？旋转之后每个基函数再组合出来的线性组合，就相当于原始那张图旋转了。于是"旋转整张环境光"这个难题，被变换成了一个新问题："旋转任意一个 SH 基函数怎么做"。

结论是：任何一个 SH 基函数旋转之后，肯定就不再是基函数了——基函数是固定的，连朝向都是固定的——但它有一个非常好的性质：旋转后的函数，一定可以用同阶的 SH 基函数的线性组合表示。比如把 $l=3, m=-1$ 那个基函数随便怎么转、朝向完全变掉，描述它的仍然是同一行（同一阶）的那几个函数，只是组合系数变了。

这就意味着可以打一张表格：任意一个 SH 基函数怎么旋转、旋转后如何用同阶基函数线性组合，事先全部算好。于是整条逻辑理顺了——

```text
旋转整个环境光 L
    = 旋转表示它的每一个 SH 基函数 B_i（都转同一角度）
    = 每个旋转后的 B_i 用同阶基函数的线性组合表示   ← 查事先算好的旋转表
    ⇒ 立刻得到新的系数组合：改系数就好
```

也就是说，预计算好的光照是允许旋转的：可以任意旋转光照，立刻得到物体上任何一个点 shading 结果的变化。这是个非常好的性质。

**阶数与重建质量。** 基函数用多少，决定恢复得多好：用前多少阶去描述原始函数，阶数越多就越能逼近原图。同一张环境光贴图，分别用前两阶、前三阶、前五阶的 SH 基函数去恢复，都能看出个大概；用到前 26 阶——这就很多了——恢复效果已经相当不错了。

### Light Transport 预计算的另一种理解

把整套思路再串一遍，顺便给一个相对高阶的理解方式。

把任何一个光照写成预计算的形式：原本的光照现在拿一堆系数描述，这堆系数排成一行就是一个向量——光照变成了一个向量。这个向量怎么求？对每一个基函数做 product integral。要恢复原始的图呢？把投影出来的系数乘以对应的基函数，加起来就行。

Light transport 同理：把它投影到任何基函数上，得到一个值 $t_i$；每个 shading point 存一串这样的值——比如一个人头模型，每个点都存一份。

说白了，$t_i$ 好比是"用第 $i$ 个基函数所描述的环境光照去照亮这个物体"时，这个点上最后照出来的结果。预计算就是：对每一个这样的 basis、每一个 shading point，算一个最终照亮结果存下来。你看，这不就相当于 rendering equation 里把 $L$ 换成了 $B$ 嘛——环境光变成了基函数本身而已。这是另外一种理解方式，没什么问题。

所以实际运算再强调一遍：任何一个 shading point 算 shading，只需要 lighting vector 和 light transport vector 两者的点乘。PRT 的预计算思想，到这里差不多就说明白了。

### 这套方法到底换来了什么

最大的好处一目了然：任何一个 shading point 算最终结果，只需要一个点乘，非常非常快。

质量呢？说高质量得看时代。那是 2000 年刚出头、2002 年的时候，那个年代能拿到全局光照（环境光照）下的这种结果，是非常好的。

阴影是白送的：算 light transport 的时候带上 visibility 项，自然而然就得到有阴影的结果。之前只考虑 shading、不带 visibility 项的版本，得到的就是没有阴影的图——人们当然喜欢有 shadow 的。

更妙的是阴影加间接光照（shadow + indirect）这件事：预计算的时候，light transport 不仅可以考虑当前这一个 bounce 的光，还可以认为 light 可以 bounce 多次。在场景其他物体形状都不变的前提下，把光的多次 bounce 也当成一种 light transport 预计算下来，就等于把间接光照也引进来了。效果上看，有些阴影因为多次 bounce 的补光就不再那么明显，整个画面看起来非常自然。具体怎么做，这里就不展开了。

### 课尾答疑实录

散课前的问题比较密集，挑有内容的记在这里。

**问：shadow 具体怎么做的？** shadow 不就是考虑任何一个 shading point 的 visibility 吗？这就是 shadow。

**问：随时间变化的程序化纹理环境光，是不是就没法处理了？** 说得太对了，像这种一直在变的环境光，这套预计算的方法处理不了。

**问：处理效率提高了多少？** 提高了超级多倍。还记得 202 第一节课说的吗：那个年代靠预计算就能跑到几百帧每秒那种"恐怖的 FPS"，就是因为计算量太小了——算一个点乘，这还得了。那个年代的 shader 硬件都能做到几百帧，放到今天，上千帧都不止。

**问：存储开销呢？** 这正是下节课要说的事。既然预计算了，每个 shading point 肯定要存点东西。现在每点只需要存一个向量——light transport 形成的向量，也就是若干个数：顶多取前五阶 SH，那就 25 个数，每个点存 25 个数还是完全可行的。要是预计算的东西再多，就麻烦了。

**问：预计算能不能做天气系统？** 就是日出日落、晴天阴天那种。也许可以预计算一部分，我回去想一想。正常来说，游戏里目前也是预计算一部分，但不是像咱们说的这种方式把它完全都算进去。

**问：每个点的 visibility 怎么求？那个球面函数怎么得到？** 最暴力的方法：从任意点往任意不同的方向 trace 光线呗。这是预计算，这块时间可以当它无穷多——任意一个 shading point 往任意一个方向看一眼是不是被挡住，不就行了。

**问：环境光照和 GI 有关系吗？** 没关系。环境光照是直接光照——光线弹射一次，不管它来自哪个方向，弹到物体就被你看见了。

**问：real-time ray tracing 普及之后，PRT 要不要淘汰？** 之前刚说过：我认为不会，反而会让 PRT 这一块有更多的表现。

**问：PRT 怎么和 ray tracing 结合？** 这个问题太大了，我不太好回答，看 research 上有没有进展，之后再跟大家说。

最后有同学总结了一句：这可以理解成"花编译时间的开销，换运行时的效率"。对了，没问题——precompute 嘛，把大量要花的时间放到渲染之前，让渲染的时候有一个非常好的效率，这就是这件事的本质。

### 下一站：Glossy 与实时全局光照

Diffuse 这块到此讲完。PRT 声称解决两个问题——visibility 已经考虑进来了；也支持不只 diffuse 的物体表面。但这里只举了 diffuse 的例子（BRDF 是常数嘛）。glossy 的部分今天先不讲：它得多花不少时间，而且怕紧跟着 diffuse 讲，大家的理解会打架，留到下节课开头再说，应该问题不大。

下节课先把预计算的最后一点完结掉：glossy 为什么比 diffuse 复杂；glossy 情况下还想旋转视角、或者物体本身要支持旋转，这些要怎么算。然后再把这个话题推向更复杂的地方：不只考虑环境光照，还要考虑实时全局光照——多次 bounce 怎么解决，到时候就到了之前说的 3D 空间与屏幕空间的方案。

今天讲的东西确实挺困难，大家回去好好消化一下——glossy 不好做，就真的不好做。作业二就是关于 PRT 的，尽量在我回来的那周、甚至下节课之前发出；预计算相关的那些事（比如 CPU 预计算的结果怎么拿到 WebGL 里去用），助教会给大家提供足够的便利，不用担心，我们已经开始设计了。
