# 实时全局光照

## PRT 的 glossy 扩展

   * **预计算辐射传输（precomputed radiance transport，PRT）**

       * > **定义**：把渲染方程（rendering equation）拆成 lighting 与 light transport 两部分分别预计算，实时渲染时把两者的基函数系数做点乘（或乘矩阵）得到着色结果。

       * 两本账：一部分预计算 lighting；另一部分预计算积分里除 lighting 外的所有东西，统称 light transport——渲染时两者相乘、积分起来，就是这个 shading point 能看到的最终值。

       * shading point 指的就是几何顶点 vertex；两种运算次序等价可用：per-vertex shading（每个顶点先算好结果、三角形内插值）与 per-pixel（per-fragment）shading（先在三角形内插值 lighting 与 transport 两组向量、再在每个像素上算结果）。

       * diffuse 流程：每个顶点把 light transport 投影到球谐（spherical harmonics，SH）上得到一个向量；lighting 只投影一次得到一个向量；实时渲染就是一次向量点乘。SH 的阶数 $l$ 越高能表示的频率越高，$n$ 阶共 $n^2$ 个基函数，恢复原始函数属于频率截断式的恢复。

   * **双重求和的展开**

       * 换一个推导角度：不再考虑先后顺序，直接把 lighting 与 transport 各自展开成 SH 求和、再与积分交换顺序——名义上得到 $n\times n$ 共 $n^2$ 项的双重求和，每项 = 两个系数 × 一个基函数乘积积分（该积分与实际场景无关），形式如下：

       $$
       L_o=\sum_{p=1}^{n}\sum_{q=1}^{n}l_p\,t_q\int_{\Omega}B_p(\omega_i)\,B_q(\omega_i)\,\mathrm d\omega_i
       $$

   * **正交性把 $n^2$ 压回 $n$**

       * SH 基函数正交：把 $B_p$ 投影到 $B_q$ 上，只有 $p=q$ 时积分值为 1、其余全为 0（类比三维空间里 $x$ 轴投影到 $y$ 轴得零）——名义 $n^2$ 项的二维求和实际只有对角线上 $n$ 项非零，复杂度仍是 $O(n)$，与「两个向量点乘」的上一轮推导结果完全一致。

       * > **提示**：这个积分本身就是「把任意函数投影到某个基上」的操作，正交性让它只剩对角线。

```text
        B1   B2   B3  ...  Bn
  B1  [  1    0    0   ...  0 ]
  B2  [  0    1    0   ...  0 ]
  B3  [  0    0    1   ...  0 ]
  ..  [ ..   ..   ..  ...  .. ]
  Bn  [  0    0    0   ...  1 ]    <- 只有对角线非零，实际要算的只有 n 项
```

   * **glossy 的 transport 矩阵**

       * 区别全在 BRDF：diffuse 的 BRDF 是常数；glossy 是完整的 4D BRDF（两维入射方向、两维出射方向），换个观察方向 $\mathbf o$，transport 投影出的向量就完全不同。

       * 处理方式：把已投影到 $\omega_i$ 方向上的系数 $t_i$（现在只是 $\mathbf o$ 的二维函数）再投影到 SH 上——transport 从向量变成 $n\times n$ 矩阵；渲染时 lighting 向量 × transport 矩阵 = 关于出射方向的向量 $L_o(\mathbf o)$。

       * 直观根源：glossy 的结果与视角有关（diffuse 无关，转视角结果不变），所以 $L_o$ 必须是 $\mathbf o$ 的函数；「向量乘以什么才能得到另一个向量」也从另一头逼出矩阵形式。transport matrix 记录的就是从 $\omega_i$ 方向到 $\mathbf o$ 方向光是怎么传输的。

       * 视角方向要预先取定：在整个球面方向里选一个 grid，每个观察方向都要预计算一整套——这是个非常复杂的过程。

```text
 diffuse :  lighting 向量 l (n)  ·  transport 向量 t (n)       ->  标量 lo
 glossy  :  lighting 向量 l (n)  ×  transport 矩阵 T (n × n)  ->  向量 lo(o) (n)
```

   * **glossy 的代价与常用阶数**

       * 存储：5 阶 SH（25 个基函数）下 diffuse 每顶点存 25 个数，glossy 要存 $25\times25=625$ 个；计算从向量点乘升级为向量乘矩阵——用 16 个基函数时，diffuse 是两个 16 维向量的点乘，glossy 是 16 维向量乘 $16\times16$ 矩阵再得 16 维向量。

       * 常用阶数：三阶用来照亮 diffuse 物体已经足够；glossy 的 lobe 尖锐、偏高频，用得比较多的是四阶、五阶甚至更多；科研领域八阶、十阶都仍被认为是非常低频。

       * 速度：当年（约 2003 年前后）的硬件上 glossy PRT 跑 3.6 fps，已能渲染出高质量的整个环境光照；现在正常实现四阶 SH 的 glossy（真算向量乘矩阵）100 fps 没有任何问题。visibility 算得对不对差别巨大——不考虑时佛像脚下被身体挡住的方向不该亮却亮了。

   * **接近镜面：SH 帮不上忙**

       * glossiness 非常高（接近镜面反射）时 SH 描述不好，这是 PRT 解决不掉的问题，应换用其他基函数；另一条路是直接做光线追踪（ray tracing）——接近镜面意味着直接知道它如何反射，连预计算都不用做。

## 光路语言与 transport 预计算的本质

   * **材质三分类**

       * 实时渲染把材质区分成三种：diffuse（漫反射）、specular（完美镜面式的光滑，光完美地往镜面反射方向走）、glossy（介于两者之间——像镜子又有点糊，正常金属即此类）；要求不严格时 specular 有时泛指 glossy。

   * **光路记号**

       * L 表示 light、E 表示 eye；一切光路从 L 出发、以 E 结尾——中间的所有环节都是 light transport，多次弹射（interreflection，物体之间互相反射）也包含在内；可借鉴正则表达式描述一整个类型的路径。

       * > **定义**：caustics 指 $LSDE$ 型光路形成的光学现象——光经 specular 表面（玻璃杯内壁、戒指内壁这类非常光滑的东西）聚焦到 diffuse 物体上，再进入眼睛。

       * 「焦散」这个翻译并不合适（都「散」掉了还看得见吗），但已通用；记号还可扩展成 $LS^*(D\mid G)^*E$，道理相同；正则里的星号本就表示零次或多次，所以弹零次的直接光照也包含在 $L(D\mid G)^*E$ 里。

| 路径记号 | 光走了哪条路 | 对应现象 |
| :--- | :--- | :--- |
| $LE$ | 光源出来直接进眼睛 | 直接看到光源 |
| $L(D\mid G)E$ | 弹一次 diffuse 或 glossy 后进眼睛 | 直接光照 |
| $LGGE$ | 光源 → 壶嘴 → 壶身 → 眼睛 | 壶身上映出壶嘴的高光（两次 bounce） |
| $LSDE$ | 光源 → 镜面 → diffuse → 眼睛 | caustics |
| $L(D\mid G)^*E$ | 弹任意多次（含零次）后进眼睛 | 一般的 light transport |

   * **预计算 = 一次「奇怪的渲染」**

       * 把 light transport 投影到某一个基（比如第 16 号基）上 ≡ 拿该基函数当光照、正常渲染一遍场景并记下每个顶点的照亮结果；既然是正常渲染（有光照、有 rendering equation），path tracing 等任何方法都能解——光栅化里做不了这件事（正因如此才有专门的 ray tracing 硬件，DXR（DirectX Raytracing）已能在光栅化里结合实时光线追踪）。

       * 投影结果图的红蓝只是可视化约定：红得越厉害越正、蓝得越厉害越负、黑表示零；换成平常的可视化方法，就是一张用这种「光照」得到的渲染图。

       * 对任意 BRDF 都成立：各向异性（anisotropic）、spatially varying（不同位置拥有完全不同的 BRDF，整个函数升为 6 维——两维位置 + 四维 BRDF）都能做，只要能把它表述出来就肯定有办法预计算；spatially varying BRDF 常用 Perlin noise 之类的可控噪声来描述。

       * 预计算程序跑出来的结果存在硬盘等处，实时渲染时直接读取；可以把预计算结果理解为物理材质的一部分。

       * > **结论**：只要采用 PRT 的思路把 light 与 transport 拆分并预计算，实际渲染就非常简单——渲染时间与 transport 的复杂度无关；预计算时间会随复杂度增长，但渲染时间不增长。

## SH 的低频边界与 PRT 的得失

   * **SH 只适合低频**

       * > **易错点**：⚠️ 措辞是「实际中用不起」，不是「能力上表示不了」——只要给足够多的项，SH 也可以描述高频，但实际中给不起那么多项：五阶（25 个系数）去描述相当高频的环境光，恢复出来基本不剩什么；要 25 阶（625 个基函数）才能基本恢复出一些高频内容。

   * **PRT 的好处与代价**

       * 好处：可以比较准确地算出整个环境光照下、甚至多次 bounce 下整个场景最终渲染的结果，visibility 也能准确考虑。

       * 代价一：预计算即冻结——场景必须静态，连材质（BRDF）都预计算好了，不能动态改变。

       * 代价二：需要大量预计算数据，存储等负担在实际应用中不小。

       * 定位与应用：课程把 PRT 归为「介于 environment lighting 与全局光照之间」的东西；工业界应用其实很多（电影和游戏里 SH lighting 到处都是），但实现比较难写、用得不算特别多——想深入可参考 Ravi 写的 PRT survey（公认写得最好的一份）。

   * **后续突围路线**

       * 五条思路：研究新型基函数；预计算更多项（从两项相乘再积分变三项相乘再积分甚至更多）；既预计算又允许场景一定程度上变化；把 PRT 思路搬到复杂材质（半透明材质、头发）；不预计算、经一些近似把所需东西解析地解出来。

       * 解析路线的代表是 split sum：不算 visibility 的环境光 shading 基本可认为得到解析解（外加一张轻量的二维表）；正因为过去十来年解析方法渐渐兴起，PRT 并没有那么火；实时光线追踪兴起后，PRT 很有可能被重新提出。

       * 方法论观察：对科学家来说最难的是发现问题而不是解决问题——引入预计算之前，这些问题根本不存在、也就无人研究。

## 小波与球面高斯

   * **小波（wavelet，Haar）**

       * > **定义**：定义在图像块上、取值分正负（有点像 step function）的一系列基函数；此处指边界明确的哈尔小波（Haar），小波家族里也有长得非常奇怪的成员。

       * 定义域与 SH 完全不同：SH 的任何基函数都定义在整个球面上；小波定义在一个图像块上，且不同小波的定义域各不相同（比如第三列整个右半边没有、第三行整个下半边没有）。

   * **非线性逼近压缩**

       * SH 的压缩靠按阶截断（只用前若干阶恢复若干频率）；小波投影后大量系数接近零，保留系数最大的若干个、扔掉其余——即非线性逼近（nonlinear approximation）。

       * 最大好处：支持全频率表示——低频可以表示、高频也可以表示；用相同的存储量，小波可以渲染出非常高频的阴影（把高频 lighting 信息也描述下来了）。

   * **用 cube map 承载与递归分解**

       * 小波定义在平面上，描述球面上的二维函数自然改用 cube map（六个面各一张正方形图）：光照六张图各自独立做小波变换（把一张图投影成小波系数）。

       * 一次 Haar 分解把图拆成三块高频（右上、左下、右下）与一块低频（左上），左上还可以继续递归分解；几轮下来绝大多数系数都接近零——有同学说这很像四叉树，说得对。

       * JPEG 用的是同一道理的离散余弦变换（DCT）——类似小波变换但不是小波变换：先投影、再取投影出来的非零系数，得到非常强烈的压缩。

```text
┌────────────────┬────────────────┐
│                │                │
│  低频（左上）  │  高频（右上）  │
│  递归继续分解  │                │
│                │                │
├────────────────┼────────────────┤
│                │                │
│  高频（左下）  │  高频（右下）  │
│                │                │
└────────────────┴────────────────┘
```

   * **小波的死穴：不支持快速旋转**

       * 旋转光照等于旋转 basis：SH basis 旋转之后还可以用同阶的 basis 来描述；小波没有这个好性质——要旋转一个用小波表示的光照，只能把它当成全新光照，解开成 $6\times64\times64$ 的 cube map、重新投影到小波、再取出前面的系数，绕一大圈回到原点。

       * > **结论**：图形学里不太存在一种方法能完美地把其他所有方法都干掉的情况；小波表示静态光照非常漂亮，光照一旦要旋转就得整个推倒重投影——所有方法都各有利弊。

   * **球面高斯（spherical Gaussian，SG）**

       * 能描述频率非常高的环境光、把那些高频的「点」定位得非常清楚；严格说理论上不应该管它叫基函数。同类经典基函数工作还有 zonal harmonics、piecewise constant 基函数等。

## 实时全局光照的问题定义

   * **全局光照 = 直接光照 + 间接光照**

       * > **定义**：全局光照（global illumination，GI）= 直接光照 + 间接光照。

       * GI 极大地提升真实感：只用光栅化做直接光照时，天窗场景里大量直接照不到的地方会是黑的；真实画面里光线弹射很多次才进眼睛，没有任何地方全黑。

       * Blinn-Phong 的 ambient 项连近似都算不上（完全是 hack）：它假设任何点接收来自四面八方的间接光照都相同、与自身 normal 无关，说白了就是往结果上加一点亮度；而真实 GI 里书本底下各处亮度都不一样、桌面还有金属球反射的 caustics——简单提亮绝对做不到。

   * **实时语境：one-bounce 间接光照**

       * > **结论**：实时渲染中说「解决全局光照」，实际指的是比直接光照多一次弹射的间接光照（one-bounce indirect）。

       * 直接光照这一半，shadow mapping 系列的方法完全可以搞定；间接光弹射越多次越不好解，人们希望方案简单、快速——全局光照非常难算。

   * **次级光源**

       * > **定义**：一切被直接光照照亮的物体表面，都会把自己继续作为光源去照亮别人——称为次级光源（secondary light source）；真正的光源叫 primary light source。

       * 依据：从 p 打到 q 的光线收到的，是 q 点直接光照再反射出来的 radiance——p 并不关心这个 radiance 是光源直接来的还是哪个表面反射来的。

## RSM：反射阴影图

### 框架与核心假设

   * **反射阴影图（reflective shadow maps，RSM）**

       * > **定义**：在 shadow map 上多存几个通道，把每个 texel 对应的小片当作次级光源、去照亮 shading point，从而得到一次弹射间接光照的方法。

       * shadow map 重新理解：任何一个 texel 其实都对应场景中的一小片 patch（有自己在场景中的位置和朝向）——一张 $512\times512$ 的 shadow map 天然自带 $512\times512$ 个次级光源。

       * 要回答两件事：哪些是次级光源、各被照得多亮（从 0 到 1）——shadow map 天然回答（从点光源看向场景，看到什么什么就被照亮；光源是 area light 时可用 soft shadow mapping 一类方法得到不同点的入射光强度）；每个 patch 对 p 的贡献是多少——逐个求出来加起来。

       * 问题本身是 $N^2$ 形状：所有 patch 都可能贡献所有其他 patch——先想清楚问题本身的形状，再说怎么把它做快。

   * **反射物 diffuse 假设**

       * 次级光源 patch 的出射方向（往 p 去的方向）对不同 p 各不相同、事先不知道，shading 没法算——于是产生经典假设：所有反射物（reflector）都是 diffuse 的，从哪个方向看过去都一样。

       * > **易错点**：⚠️ 强调的是「反射物」——**不需要**假设接收物也是 diffuse；p 点的 BRDF 可以是 glossy。若要把 reflector 认为可以是 glossy，那就太难了。

### 单个次级光源的贡献

   * **辐射度量速查**

| 概念 | 描述的量 |
| :--- | :--- |
| flux / power | 总能量 |
| intensity（radiant intensity） | 单位立体角上的能量 |
| irradiance | 单位面积上的能量 |
| radiance | 单位立体角、单位面积上的能量 |

   * **面积分形式与黎曼近似**

       * 用一个 texel 的 patch 去照亮 p，解的是 area light 下的渲染方程；在 p 点对整个立体角采样会浪费很多 sample，按 path tracing light sampling 的思路做变量替换，把对立体角的积分改写成对光源面积的积分：

       $$
       L_o(p,\omega_o)=\int_{A} L_i(p,\omega_{pq})\,f_r(p,\omega_{pq},\omega_o)\,V(p,q)\,\frac{\cos\theta_p\,\cos\theta_q}{\|p-q\|^2}\,\mathrm{d}A_q
       $$

       * patch 本来就小，黎曼近似取 patch 中心点 q 的被积函数值（BRDF、visibility、cos 项都是已知量）乘上 patch 的真实面积 $\Delta A_q$ 即可——积分甚至都不用积。

   * **reflected flux 优化**

       * diffuse 反射物的 BRDF 是常数 $\rho/\pi$；出射 radiance = BRDF × 入射 irradiance：$L_o(q\to p)=f_r(q)\cdot E_q$，$E_q=\Phi_q/\Delta A_q$（$\Phi_q$ 是 q 接收到的入射 flux）。

       * 代回求和后 $\Delta A_q$ 正好消掉——想知道任何 reflector 反射出来的 radiance，直接用它的 BRDF 乘以它接收的 incident flux，而 incident flux 由光源决定。

       * $f_r(q)\cdot\Phi_q$ 被称为 reflected flux（反射通量，不算标准定义但通用）：RSM 上每个像素为得到它反射出去的 radiance，只需存这一个数，省掉「incident radiance + patch 面积」两个数——这是原论文的一个小优化。

       * p 点收到的间接光照，就是把每个次级光源的这几项乘起来求和（p 自己的 BRDF 不要求 diffuse，glossy 完全可以做）：

       $$
       L_o(p,\omega_o)\approx\sum_{q}f_r(p,\omega_{pq},\omega_o)\,[\,f_r(q)\,\Phi_q\,]\,V(p,q)\,\frac{\cos\theta_p\,\cos\theta_q}{\|p-q\|^2}
       $$

   * **可见性：不算**

       * 判定每个次级光源能否看见 shading point p 又是 $N^2$ 问题，不可能通过一张 shadow map 得到——RSM 干脆忽略 V，第二个 pass 里这一项直接不算；反正间接光照已经不像直接光照那么高频，不考虑好像也没有特别大。

   * **距离衰减：平方，不是四次方**

       * 正确推导的分母是距离的平方——它就是把立体角换成面积测度时必然产生的那一项（p 到 q 的 foreshortening）。

       * 原论文分母写四次方的真相：分子的点乘里用了未归一化的连线向量 $\vec d$（长度即两点间距离 $d$），两个点乘各多带一个距离，分子上多出 $d^2$、分母相应写成 $d^4$；把 $\vec d$ 归一化之后两种写法完全等价，谁都没有错：

       $$
       \frac{\left(\vec{n}_p\cdot\vec{d}\right)\left(\vec{n}_x\cdot\vec{d}\right)}{d^{4}}=\frac{\cos\theta_p\,\cos\theta_x}{d^{2}}
       $$

       * > **提示**：radiance 沿光线（真空、无介质）传播是不衰减的；随距离平方衰减的是分摊到单位面积上的能量那一系（irradiance）。看到对 radiance 再多除一次 $d^2$ 的写法，就要警惕是不是 double count 了。

### 采样、存储与表现

   * **只算身边的次级光源**

       * 方向淘汰：patch 法线与它到 p 的连线朝另一个方向去（如 $x_{-1}$）时，贡献必然为零；距离淘汰：贡献经过距离平方那一项，离得非常远的次级光源贡献本来就非常少。

       * 世界坐标下不好找邻近的次级光源 → 把 shading point p 投影到 shadow map 上、在它周围一圈的范围内找——认为 shadow map 上离得近（比如深度也离得近）的世界坐标里也近；通常不算不合理，但确实是一个比较大的假设。

       * 缩到一圈后范围仍可能不小，按 PCSS 同款思路随机采样：离 shading point 对应位置近的地方采得密一点，远处采得疏一点但权重大一点（一个样本代表一大片像素的贡献，面积大了权重自然要大）——都是非常 heuristic 的工业 trick。

       * 最终每个 shading point 从 RSM 上取大约 400 个 texel 当次级光源，对比 $512^2$ 全量是巨大节省。

   * **存储清单**

       * depth（shadow map 本职）+ 世界坐标（shading 时判断两个点的实际距离）+ 法线（反射物/次级光源的法线，算 cos 项）+ flux（反射通量；它跟光源相关、和各个表面的法线都没关系，通道看上去就像在做一个很平的 area light shading）。

   * **实战表现**

       * 手电筒场景最合适：覆盖范围相对较小 → 不需要很大的 RSM、分辨率可以压得低 → 快。现在的游戏一旦涉及手电筒都非常愿意用 RSM——《最后生还者》《战争机器 4》《神秘海域 4》都在用。

       * 间接光照肯定比直接光照暗很多，但正因为藤蔓在天花板上反射出的那一点点绿色细节，整个画面看起来会好特别多。

### 优点、局限与概念延伸

   * **优点**

       * 一句话：它就是 shadow map 的流程，容易实现——Pass 1 从光源渲染一张 RSM；Pass 2 从 camera 正常渲染，每个像素就是 shading point p，把各次级光源的贡献算出来加起来。

```text
Pass 1  从光源渲染一张 RSM：每个 texel 记录 depth + 世界坐标 + 法线 + flux
Pass 2  从 camera 正常渲染：每个像素就是 shading point p，
        把 p 投影到 RSM，取周围约 400 个 texel 当次级光源，按公式求和
```

   * **局限**

       * 继承 shadow map 自己的所有问题：有多少个直接光源（primary light source），就得做多少张 shadow map、也就得做多少张 RSM，会越来越慢。

       * 可见性没算：反射物到 shading point 之间不判遮挡，造成很多不真实的情况——人眼（训练出来的大脑）非常厉害，立刻就能分辨画面不自然；而且环境光下来自四面八方的间接光阴影是 $N\times M$ 或 $N^2$ 级问题，实时渲染里到今天仍然不太好解决。

       * 假设多：反射物必须 diffuse；shadow map 上的距离在一定程度上反映实际距离；采样本身永远有 trade-off——sample 多效果好但慢、少则快但效果差（写过 PCSS 作业都体会过）。

   * **概念延伸**

       * RSM 把 shadow map 上任何一个小像素都当成 surface patch 来看，与离线渲染中的 virtual point light（VPL）概念非常接近；VPL 属于更大的 instant radiosity（即时辐射度，IR）框架，且可以和光线追踪结合得非常好——文献里见到 VPL，理解成小的 surface patch 或点光源都没问题。

       * 空间归类：按「信息来自从光源开始的那张图」，RSM 可算图像空间方法；但按「不受最后 camera pass 可见性影响、不存在一开始就记录不到而丢信息」的标准，可归为 3D 空间方法——后续的 LPV 就建立在 RSM 基础上。

## LPV：光传播体积

   * **光传播体积（light propagation volumes，LPV）**

       * > **定义**：把次级光源的 radiance 注入三维网格（voxel），在网格中迭代传播至稳定，任意 shading point 查所在格子的入射 radiance 来做间接光照。

       * 名字即思路：volume 是体积——在三维空间中传播（propagate）光线，拿传播的结果做间接光照。

       * 最早在 Cry Engine 3 中引入（游戏《孤岛危机》，人称「显卡危机」），作者 Anton Kaplanyan；两个非常好的性质：非常快、质量也非常好——正好能一定程度解决 RSM 的部分问题。

       * 自己实现与工业界 demo 的效率差十倍是非常正常的事情：3D 空间中的实时全局光照细节实在太多。

   * **物理地基**

       * radiance 在空间中沿直线传播的过程中是不变的量——这是物理事实而非假设；path tracing 从 P 打一条线到 Q，Q 沿该线走回来的 radiance 就是 P 收到的，一直默认沿同一条线完全一样。

       * > **易错点**：别联想到「平方衰减」——intensity 之所以随传播衰减，是因为传播过程中面积不断增大、单位面积上的强度自然降低；radiance 本就是定义在基本一条线上、为描述传输而产生的量，传播中不变。

   * **四步流程**

       * 生成（generation）：与 RSM 一模一样——先算好直接光照，被直接照亮的物体表面就是次级光源，它们发出的 radiance 是间接光照的起点；可以在其中采样、把次级光源数量降下来（得到一系列虚拟光源）；每个直接光源仍要做一次 RSM——老问题并不解决。

       * 注入（injection）：场景切豆腐式地划分成 voxel（体素，类比 texel（纹素））；工业界直接用三维纹理（定义 texel 对应 3D 空间上哪一个 voxel）；把格内所有虚拟光源朝各方向的 radiance 算出来加在一起，得这个格子往四面八方的 radiance 初始分布，再用 SH 压缩——工业界只用两阶共 4 个系数（第一层 1 个、第二层 3 个），很粗糙（diffuse 物体接收光照理论上至少得按三阶处理）。

       * 传播（propagation）：认为 radiance 位于格子中心、往各个不同方向去；穿过哪个面就交给哪个邻居（共 6 向），接收方照样用 SH 表示、贡献直接加起来；全场不断重复直到稳定——迭代约四五次就够，光线传播没有其他外力，最后肯定达到稳定状态（往池塘投一块石头，波纹荡来荡去终会平稳）。

       * 渲染：传播完成，场景中任何格子的入射 radiance 都已知；渲染时对任意 shading point 找到它所在的格子，把该格子收到的入射 radiance（所有方向、SH 表示）拿出来直接做渲染。

   * **流程取舍**

       * 不考虑格子之间的可见性（与 RSM 同一个假设，一旦考虑就非常难）。

       * 不计算斜对角格子的传播：先往右传、再往上传，与直接往右上角传没有区别；一个格子可以被周围六个面同时贡献、也可以贡献给周围六个面，对等，省得考虑 27 个邻居。

       * 光在格子间传播时不改变方向；不考虑 multi-scale 或 cascade 的概念时也没有 KD-tree 那种层次结构，就是空间中几乘几乘几的格子。

       * 雾、云、烟这类 volumetric 的东西：有雾其实没问题，只是传播方式变——光线不再是直线了；已有 paper 用 LPV 的思想解决云、烟雾里的光线传输。

       * LPV 不是预计算的方法：实时的，每一帧都要把整套计算整个做一遍；每个 voxel 里存的东西可以理解成一份 light transport。

   * **light leaking（漏光）**

       * 现象：一堵薄墙左半边被直接光照照亮、反射只往左边去（绝不可能照亮右边），但注入时把这些点发出的 radiance 当成整个格子上 uniform 的分布 → P 点的 radiance 被认为格内处处相同 → 照亮了自己的背面与格内整面——棚顶明明朝上却照亮了自己底下，这就是漏光，与 VSM 当年的问题如出一辙。

       * > **结论**：根本原因是场景里有一段非常细的几何、它的粒度比一个格子还要小——当几何比格子还细时，「格内均匀」的近似必然出错。

       * 格子划分得无限小不行：存储吃不消、传播时要考虑的格子数量更多更慢；工业界用自适应划分——用不同分辨率的格子一起做传输和计算，实时渲染工业界叫 cascade，学术界/离线渲染叫 multi-scale 或 LOD，都是一回事，属这类方法的标准配置（VXGI 里也有）。

       * 格子数量一般至少要比像素的数量少一个数量级。

   * **能力边界**

       * 优点：结果挺稳定、对动态物体的处理非常好——直接光照不断变化时间接光照跟着变；移动的红布到哪，附近表面就越来越红。

       * glossy 的接收物实际不行：voxel 里的分布既然用 SH（还只两阶）表示，glossy 物体的反射分布一进 SH 就会糊掉——LPV 没必要假设反射体是 diffuse，但只要用了 SH 就基本得当 diffuse reflector 看待，只能处理 diffuse。

       * 现状：LPV 至今还在游戏中使用、用得还很多；另外还有一些基于 probe 的方法（放到实时光线追踪一起讲）。

## VXGI：体素全局光照

   * **体素全局光照（voxel global illumination，VXGI）**

       * > **定义**：把场景离散化成带层级结构（hierarchy）的体素，第一趟（light pass）记录每个体素的光照分布，第二趟从 camera 出发逐像素做 cone tracing 查询间接光照的两趟算法。

       * 与 RSM 的两个主要区别：其一，次级光源的载体从像素换成体素——场景完全离散化成一系列格子（把场景理解成乐高或《我的世界》），且用 hierarchy 组织成树：最细的层级是最小的格子、分布在物体表面上，逐层变大；其二，第二趟从 camera 出发，而不是像 LPV 那样全局传播。

       * 实时渲染很多方法都喜欢拆 pass：RSM 两趟、LPV 真算起来算四趟、VXGI 基本两趟——每个 pass 解决不同的问题。

   * **第一趟：light pass**

       * 直接光照用什么方法算都行（RSM 也可以），只要知道任何一个 patch 的直接光照；再对每个小格子做与 LPV 注入非常像的事情——记录格内所有表面反射光照的分布。

       * 每 voxel 记录两样东西：光源主要从哪些范围来（incident lighting 的分布，记成一个 lobe）+ 格内反射这些光照的表面法线的分布；两个分布一拼，不管格子是 glossy 还是 diffuse 都能直接算出出射分布——比 LPV「全 diffuse + SH 压缩」准得多。

       * 高层体素对小体素记录的分布是「收集在一块」，不是简单平均。

   * **第二趟：cone tracing**

       * camera ray 打到 glossy 材质会反射成一个锥（cone）；锥在传播过程中越变越大——按锥离初始点的距离算出它此刻覆盖的范围，直接到 hierarchy 上找「一个块差不多正好罩住这个范围」的层级查询：二维示意图里只用查四次就差不多；实际次数取决于 glossy lobe 到底多宽，diffuse 的锥数量增多、要查的次数肯定也增多。

       * 朴素做法（场景中所有 voxel 都判断是否与圆锥相交）非常慢、而且既然建了 hierarchy 就没必要——层级查询正是为了省去每次都查最小的、最细的体素。

       * diffuse 反射：不用一个超大号的 180 度圆锥（那会把场景中所有东西都罩进去），而用若干个小的圆锥把整个反射半球覆盖住——这个例子约 8 个，每个锥的中心和大小都是预先分配好的，各锥贡献相加；锥之间有缝、彼此有 overlap 的不准问题都不大，对 diffuse 完全可以接受。

   * **LPV 与 VXGI：一对镜像**

       * LPV：把所有次级光源的 radiance 先传播到整个场景的任何地方——传播只做一次，之后谁都能查；快，但格子与 SH 表示不怎么准、还会 light leaking。

       * VXGI：把所有次级光源记录成层次结构，每个 shading point 自己去找哪些次级光源能贡献到它（cone tracing）——慢；质量高，做法已经非常像 photon mapping（每个像素都要做一次 tracing，自然像离线渲染的操作）。

| 对比项 | LPV | VXGI |
| :--- | :--- | :--- |
| 次级光源载体 | 体素，出射 radiance 用 2 阶 SH 压缩 | 体素 + hierarchy，记录入射 lobe 与法线分布 |
| 间接光到达方式 | 全场传播一遍，任何位置查表 | 每个 shading point 自己做 cone tracing |
| 速度与质量 | 快；表示粗糙、会 light leaking | 慢；质量高，已很像 photon mapping |

   * **落地与代价**

       * 质量在那个年代非常不错、比 LPV 好（体素对场景的表示本身就表示得非常好）；但开销还是大了一点，应用受到限制。

       * 更大的问题：把场景先体素化是一件非常麻烦的事情、很可能需要预处理；动态物体动起来每一帧是不是都要重新体素化？实时地去体素化又会非常慢；而且它的体素非常小。

       * 实际案例：VXGI 最早出自约 2012 年的一篇 paper；PS4《蜘蛛侠》的全局光照就是 VXGI 实现的（此时硬件已比 2012 年好很多），全局光照做得特别好。

## 屏幕空间方法总览

   * **屏幕空间的定义**

       * > **定义**：屏幕空间方法的全部输入，就是「做全局光照之前的那张直接光照画面」；全局光照从这个起点上，用图像空间的后处理手段算出来。

       * 从 camera 渲染一趟能得到的东西——看得到的物体、它们的法线、它们的深度——就是全部信息；沙发背后是什么，不知道，因为从 camera 这边根本看不到。

       * 相关探索：训练一个神经网络，给直接光照、把间接光照猜出来、两者相加得全局光照——从效果上看好像还是 OK 的。

   * **三个空间的分家**

       * 代表方法全称：屏幕空间环境光遮蔽（screen space ambient occlusion，SSAO）与屏幕空间方向性遮挡（screen space directional occlusion，SSDO）；随后还有屏幕空间反射（screen space reflection，SSR）——虽以反射闻名，同样是屏幕空间做全局光照的方式。

| 空间 | 代表方法 | 信息来源 |
| :--- | :--- | :--- |
| 图像空间 image space | RSM | 从光源出发，shadow map 里的信息 |
| 屏幕空间 screen space | SSAO、SSDO | 当前屏幕这张直接光照图，没有其他视角 |
| 世界空间 world space | LPV、VXGI | 三维空间中的场景表示 |

## 环境光遮蔽的理论

   * **环境光遮蔽（ambient occlusion，AO）**

       * > **定义**：AO 靠所谓的 contact shadow（接触阴影）起作用——物体和物体接触、贴近的时候，中间这些地方会暗一些；正是这些暗部把物体之间的相对位置（立体感）交代得更清楚。

       * 做它的两个理由：能带来明显的视觉提升；实现非常非常容易。

       * 本质定位（SSAO 两层定义）：AO 首先是对全局光照的一个近似——物体贴近处变暗，其实是周围几何挡住了一部分间接光；「屏幕空间」说的是信息从哪来——camera pass 能看到的物体、法线、深度，这些就是全部。

       * 建模软件（离线渲染）里的「天光」（skylight）：拿一个纯白的环境光去渲染直接光照，渲染结果与 ambient occlusion 一模一样——工业界有各种各样神奇的名字。

       * 出处：Crytek 发明了 SSAO，引进在《孤岛危机》二代里；第三代做的才是 LPV 那些技术。

   * **SSAO 的三条假设**

       * 间接光照是常数：对任何 shading point、从任何方向过来，间接光照都是完全相同的数——与 Blinn-Phong 着色模型里 ambient 项的假设一模一样。

       * 不同的 shading point 有不同的 visibility：AO 比 ambient 假设进步的地方——visibility function 本来就是关于方向的函数，这里把它显式考虑出来（人头模型的眼窝往上看被眉骨挡住、收不到那个方向的间接光所以比额头黑；额头往四面八方都看得到）。

       * 物体是 diffuse 的：glossy 这些不管，就当 diffuse 物体来解 AO。

   * **从渲染方程推导**

       * 出发点：间接光的渲染方程；把乘积积分中的一项拆出去、除以一个空的积分做归一化（课上戏称 real-time rendering approximation）：

       $$
       L_o^{indirect}\approx\frac{\int_{\Omega^+}V(\omega_i)\cos\theta_i\,\mathrm{d}\omega_i}{\int_{\Omega^+}\cos\theta_i\,\mathrm{d}\omega_i}\cdot\int_{\Omega^+}L_i^{indirect}(\omega_i)\,f_r\cos\theta_i\,\mathrm{d}\omega_i
       $$

       * > **注意**：「real-time rendering approximation」（或 real-time rendering equation）这个概念并不存在，是这门课上自己起的名字——平时当黑话用、知道指什么就行，正式场合别这么说。

       * 分母对整个半球把 $\cos\theta$ 积起来，结果是 $\pi$（微积分忘了的话，把立体角微元拆成 $\sin\theta\,\mathrm d\theta\,\mathrm d\phi$，对 $\theta$、$\phi$ 分别积分即可）。

       * > **定义**：$k_A$ 就是 shading point 在上半球上按 cos 加权平均的 visibility，取值 $[0,1]$——别的都不管（光照不管、BRDF 不管），只看可见性。

       * 第二项里，间接光（假设常数 $L_i^{indirect}$）与 diffuse BRDF（$\rho/\pi$）都是常数，提出来后积分产生一个 $\pi$、与分母的 $\pi$ 消掉：

       $$
       L_o^{indirect}=k_A\cdot\rho\cdot L_i^{indirect}
       $$

       * 间接光强度反正不知道是多少、随便指定一个；diffuse 的 albedo 也可以随便指定一个——右边基本就是随便定一个颜色，真正要算的只有 $k_A$ 这一项。

   * **拆分的本质**

       * 把 $f$ 从 $f\cdot g$ 的积分里拆出来、除以空的积分归一化，就是求 $f$ 在 $g$ 的 support（覆盖范围）上的平均值——连续版的 $\sum_i f_i w_i \big/ \sum_i w_i$；归一化还有一个作用：让值不发生范围变化（visibility 本来 0 到 1，平均之后还是 0 到 1）。

       * 这样拆什么时候准确：$g$ 的覆盖范围较小、或 $g$ 比较光滑；而对 AO 来说 $g$（间接光 × BRDF）在假设下就是常数——百分之百准，不是近似。

   * **投影立体角**

       * > **易错点**：⚠️ AO 拆分式里分子分母的积分测度不是 $\mathrm d\omega_i$ 本身，而是 $\cos\theta_i\,\mathrm d\omega_i$ 这一整体——把它当成一个 $\mathrm d(\cdot)$ 来用。

       * 投影立体角（projected solid angle）：$\cos\theta_i\,\mathrm d\omega_i$ 正好等于把球面微元从球上投影到正下方单位圆上得到的微分面积；整个积出来自然就是单位圆的面积 $\pi\times1^2=\pi$——顺带解释了 $\int_{\Omega^+}\cos\theta\,\mathrm d\omega=\pi$。

       * 本质就是一次换元：原本「带着 $\cos\theta$ 在立体角上积分」，现在变成「不带 $\cos\theta$ 在投影立体角上积分」；没有哪篇 paper 专门提出这种拆分，基本是约定俗成、自己推一下也是对的。

       * LaTeX 细节：微分 d 要用直立的 `\mathrm{d}`（微积分里微分的 d 不斜体），前面最好加一个最小空格 `\,`，即写 `\,\mathrm{d}\omega`。

   * **更简单的推导**

       * 间接光照假设成了常数、diffuse BRDF 也是常数——直接把它们从 rendering equation 里拿出来就结束了：

       $$
       L_o^{indirect}=L_i^{indirect}\cdot\frac{\rho}{\pi}\cdot\int_{\Omega^+}V(\omega_i)\cos\theta_i\,\mathrm{d}\omega_i
       $$

       * 但这样剩下来的积分不是 visibility 的加权平均（缺了归一化常数），就会不明白工业界为什么非要引入 $k_A$、底下要除以 $\pi$——两种推法结果一样（里除一个 $\pi$、外边乘一个 $\pi$）；绕中间量（先推出 $E$ 等于什么）毫无必要、还多出一个 $\pi$ 徒增麻烦。

## SSAO 的实现

   * **先限制半径 R**

       * 不限 trace 距离的极端后果：封闭屋子里的任何 shading point 往任何方向 trace 最终都出不去 → 到处都被遮挡、算出来整个屋子全黑——出事了。

       * 反射光一定都是从有限的距离反射过来的，不可能用无限距离去算「能不能 trace 到物体」——限制一个范围，看这个范围内有没有遮挡即可。

       * > **提示**：R 是 trade-off——范围太大，封闭场景里所有东西最后肯定都被挡；范围太小，来源比 R 更远的间接光照就被忽略掉。AO 语境下（间接光反正当成一样）这么处理没问题，通常选一个折中的半径。

   * **算法两步**

       * 第一步：在任何 shading point 周围半径 R 的球体内部随机采样很多点——注意是在整个球覆盖的体积内随机撒点，不是只采方向（只采方向的话用球面上不同的点就行）。

       * 第二步：把撒下来的每个采样点投影到 camera 屏幕上、查这个像素之前记录的深度：采样点比记录的最浅深度更深 → 在物体内部、被挡住（红点）；更浅 → 一定在物体外部、看得到（绿点）；统计红绿点比例，得到平均 visibility（$k_A$）。

       * 深度图可以当做场景几何的一种简单近似（每个位置记的都是最浅深度），整套判断跟 shadow mapping 一模一样、只是反向使用；数据流：camera pass 出 color + depth → 球内撒点 → 投回屏幕比深度 → 数红绿点 → noisy AO → denoise → 平滑后叠加到直接光照等结果上。

       * 唯一会出问题的点：采样点在 camera 看到的最浅深度背后、按规则判为「在物体内部」，但几何在那里拐了个弯（有个尖），这个点其实在外面、能看到——深度只记录最浅的、拐弯的存在根本不知道；工业界就这一点点出错还能接受。

   * **无法线的年代：整球 + 红点过半**

       * AO 那个时代还不能假设 camera 渲染出来的东西既有深度又有 normal（深度可以有）——不知道法线方向，就不知道哪半球该考虑，所以干脆考虑整个球。

       * 补救规则：真有一个平面的话，必然一半的点在平面底下、肯定看不到——于是对任何几何都假设：撒在整球里的点，只有红点（看不到的点）个数过半的情况下才考虑 AO；超出「一半」的部分才是真正的遮挡。

       * 例：一共撒 10 个点、9 个红点 → 减去平面上本来就该看不到的 5 个，剩下 4 个点表示真的被挡住、还有 1 个点没被挡住，visibility $=1/(4+1)=20\%$。

       * > **提示**：红点不过半 → 当作没有遮挡；红点过半 → visibility = 绿点数 ÷（绿点数 + 超出半数的红点数）。

       * 这么做丢了一样东西：没有法线就不知道 cos 应该怎么加权——算出来的只是上半球不同方向 visibility 的一个近似平均，而不是 visibility 和 cos 的加权平均；没有法线的情况下工业界只能做到这么好。

   * **false occlusion**

       * 现象：石凳和地面根本不接触，凳脚那一圈地面却出现了变暗——不该有的、不自然的遮挡。

       * 机制：地板上取一点、取它周围 3D 空间中的一个球；球里某个采样点投影到 camera 时，查到的是石凳（离 camera 更近的面）记录的深度 → 采样点比它深 → 判为「在这个面背后、在物体内部」→ 背后这些点全部是红点 → 错误地认为石凳对地板这一点有 AO 贡献，凭空多出一圈变暗。

       * 根子还是那句话：camera 只能记录最前面的表面，它背后到底是什么、挡不挡，其实不知道。

   * **采样数量与降噪**

       * 球里选多少个 sample，和 PCSS 是一模一样的问题：sample 越多越好，但想要速度就不能太多。

       * 办法也一样：用少量 sample 先得到一张 noisy 的 AO 结果，再做一遍 denoise 糊掉；AO 正常很少单独看——都是加到直接光照或其他结果上，denoise 之后哪怕剩一点 noise，一加就差不多了。

   * **HBAO：有法线的升级**

       * 现代实时渲染里说只有 depth 没有 normal 是说不过去的（法线当然可以通过采样相邻深度纹理近似，但更多情况下渲染一趟就有）。

       * 有法线就知道该采样哪半球：在法线所在半球内选点、直接算红绿比例的可见性平均——比没有法线、考虑整个球要准；更进一步可以按 cos 加权（cos 靠近法线方向大、靠近两边小）得到更准的值——这套有法线的做法就是 HBAO（horizon based AO），仍是 SSAO 这一家的东西。

       * HBAO 对 false occlusion 也处理得好一些：不再像 SSAO 那样认为只要距离近——不管近多少——都算遮挡，而是只考虑在一定范围内的遮挡（遮挡还可以随距离衰减）；SSAO 很多边缘的地方出问题就是因为它不考虑 depth 到底差多远。代价：G-buffer 要多存一张 normal map。

| 对比项 | SSAO | HBAO |
| :--- | :--- | :--- |
| 法线信息 | 不需要（当年假设拿不到） | 需要，G-buffer 多存一张 normal map |
| 采样范围 | 整个球内撒点，红点过半才计遮挡 | 法线所在半球内采样 |
| cos 加权 | 做不到，只是可见性的平均 | 可以按 cos 加权，结果更准 |
| false occlusion | 明显（不看深度差多少） | 只计一定范围内的遮挡，基本消除 |

   * **参数取舍与工业地位**

       * 减小采样半径能不能减少 false occlusion？能，但同时整个 AO 都会变淡——半径减得特别小就基本没有 AO 了；减少 false occlusion 的同时也在减少真正的 occlusion，一切东西都是很平衡的。

       * 深度差的阈值也一样：这些操作只能说减轻问题、或可能引入新问题；动态采样半径是个挺有意思的可探索方向；HBAO 之后还有各种各样的改进方法，但思路不变。

       * AO 在工业界极其常用：现在基本上渲染都会有一个 AO；甚至真正算上了 GI，有时候还会有人再叠一个 AO 在上面，就为了表示物体之间的接触感。

## SSDO：屏幕空间方向性遮挡

   * **屏幕空间方向性遮挡（screen space directional occlusion，SSDO）**

       * > **定义**：SSDO 要真正把间接光照算出来——被直接光照照亮的、屏幕上的那些像素本身成为提供间接光照的次级光源；「screen space」意味着所有次级光源的信息都来自屏幕（不来自 reflective shadow maps）。

       * 动机：次级光源提供出去的直接光照，就是场景中的间接光照——这个信息其实已知，比 AO「间接光照到处都一样」的假设更精准。

       * 与 AO 的直观差别：AO 只能在接触的地方产生变亮或变暗；SSDO 能做到 color bleeding——光线在 diffuse 物体之间传播、不同颜色的 diffuse 物体互相照亮（蓝色的面沾一点黄光、黄色的面沾一点蓝光、地面上一样）。

   * **与 SSAO 完全相反的假设**

       * path tracing 视角：从 p 出发、上半球里的采样方向分两类——打得出去（附近什么都没有）与被附近物体挡住；两家的解读完全相反：

| 方向的处境 | SSAO 的解读 | SSDO / 路径追踪的解读 |
| :--- | :--- | :--- |
| 打得出去（附近无遮挡） | 有间接光照进来 | 只有直接光照，没有间接光 |
| 被附近物体挡住 | 没有间接光照 | 恰恰是间接光的来源 |

       * 根源：AO 背后的假设是来自环境中其他物体的间接光照都从比较远的地方来（所以考虑范围内打不到物体的方向才收得到）；DO 假设间接光只从非常近的地方来（范围内打得到的物体会反射间接光）——两者都不完全正确。

       * > **结论**：理论上的正确做法是把 AO 和 DO 合在一块做——来自近处的 indirect 部分由 DO 捕捉、来自远处的间接光照部分由 AO 捕捉；工业界不知道有没有人真这么用，但理论上来说该这样。

   * **算法**

       * 在 p 的上半球（假设法线已知）内撒点，按深度缓冲判定各方向是否被挡：$v=1$（往那个方向看不会被挡）的方向没有间接光——来的可能是环境光的直接光照之类，可顺便从该方向查环境光的值；$v=0$（打到某个物体 q）的方向——q 的小面片当次级光源：假设它是 diffuse（从 camera 看到它反射出的 radiance、与它反射向 p 的 radiance 一样）、它的直接光照已算好，按面片的面积与朝向算对 p 的贡献并加起来（面片法线背对 p 的贡献为零）。

       * 判定仍是「camera 到采样点」的可见性假设（不真正 trace 一根光线），和 AO 一样是非常大胆的假设，但一定程度上挺有效。

   * **camera 可见性 ≠ shading point 可见性**

       * > **易错点**：⚠️ 用深度缓冲判遮挡，回答的始终是「camera 能不能看到这个采样点」；算法真正想问的是「shading point 沿该方向有没有东西」——两种可见性经常凑巧一致，但会把结果正好判反：反例一，p 到 a 方向完全没被挡，但 a 前面正好悬浮一个物体、从 camera 看过去把 a 挡住了 → 被误判为挡住；反例二，camera 明显看得到 b（最小深度就记录在那），但从 p 往 b 方向看可能被别的东西挡住。想非常精准，就得在场景中打一条真正的光线——这就是之后的 SSR。

   * **轻量但天花板明显**

       * 计算量与 SSAO 差不多（都是取半球、撒点、用 camera 可见性近似 shading point 可见性），只是被挡住的方向多做几笔 shading 计算——总体仍是非常轻量的方法，质量不错、应用广泛；毕竟算是考虑了一点次级光源和 shading point 之间的可见性。

       * 三大问题：只能表示一个小范围内的间接光照；camera 可见性的近似不准；screen space 丢信息——屏幕空间相当于一层壳（从 camera 看过去每像素一个深度、记录的都是最浅深度），壳背后的东西一概不知：一个面旋转到 camera 看不见时，它对地板的反射贡献就直接消失——这是一切 screen space 方法共有的问题。

       * Cornell Box 反例：考虑的点周围范围取得再大，也覆盖不到右边的绿墙——绿墙对该点的贡献无论如何进不来；SSDO 只能处理所谓非常小范围内的全局光照或间接光照。

## SSR：屏幕空间光线追踪

### 定位与朴素求交

   * **SSR 的正确理解**

       * > **定义**：SSR 能够做的，是在屏幕空间上做光线追踪——不需要整个场景的三维网格、三角形这些，需要的仍然只是屏幕空间上已有的知识；把「反射」当成它的全部，是挺狭隘的理解。

       * 它仍然是一种在实时渲染中实现全局光照的方式；要解决两个问题：给定任何一根光线和这层壳怎么做求交；找到交点之后，怎么把交点那个像素对 shading point 的贡献（shading）算出来。

       * > **定义**：屏幕空间方法眼里的「场景」，就是从 camera 能看到的一层壳（shell）——每个像素只记录一个深度，所有像素的深度拼起来就是这层壳；深度值越小，代表离 camera 越近。

   * **反射本来就是全局光照**

       * camera ray 达到一个 shading point、往上反射正好到一个光源——光源到 shading point 再到眼睛，是直接光照；反射到的是一栋楼（被别人照亮的表面）——光源到楼面、到地面、再到眼睛，就是间接光照。反射本质上就是全局光照，只不过镜面反射在游戏里用得多、被单独拎出来当成一种效果。

   * **屏幕空间的基本赌注**

       * 反射出来的东西绝大多数在屏幕空间中已经有了（雨后街道、海景房地面反射出的正是画面上方那一块）——加反射不太需要额外的信息，用反射之前场景渲染出的信息就行；这个假设不一定对，但绝大部分情况成立。

   * **能 trace 什么**

       * 镜面（specular reflection）：一个非常完美的镜面，一根反射方向就行；glossy reflection：不是完全 diffuse 也没镜面那么好——按 BRDF 的 lobe 取多根光线，lobe 越细可以用越少的光线，lobe 越大（比如 diffuse）就需要越多光线。

       * 不挑几何：地面不平、不同位置有不同法线、任意物体都行——只要知道它的几何与法线，就可以往任何一个方向 trace；能做光线追踪，就能解决任何这类反射问题（比如不同位置不同 roughness）。

       * 工业黑话：smoothness（光滑程度），与平常说 BRDF 用的 roughness（粗糙程度）相反。

   * **朴素步进求交**

       * 在 shader 里取一个初始的点、往反射方向每次往前走一点、再走一点；判断依据始终是深度：起点本来就在壳之前（它是场景表面上的一点），每走一步就拿当前采样点的深度和深度缓冲比一次——一旦跨到壳（最浅深度）的背后，说明光线穿过了表面，交点必然在最后两步之间。

```text
  沿反射光逐步步进（在 shader 里每步往前走一点）：

  起点  *   场景表面上的一点，从 camera 看过去有确定的深度
  步 1  *   仍在壳之前
  步 2  *   仍在壳之前
  步 3  X   深度第一次落到壳（最浅深度）的背后
            -> 说明光线穿过了表面，交点就在上一步与这一步之间
```

   * **步长两难**

       * 步子迈得非常大：可能「找到」一个假交点——中间真正该有的交点被一步跨过去了；迈得非常小：判断非常准，但计算量大——而且这只是 trace 一根反射光线，每个 fragment shader 都要做一遍，代价一下子被放大。

       * 朴素做法里步长必须固定一个定值：因为没有 SDF（有向距离场）告诉你「往前走多少是一个安全距离」，只能盲目地往前试探。

### 层次化试探

   * **最小值 mipmap**

       * 把「一个像素在场景中描述的大小」算作一格；对屏幕上的深度做一份 mipmap，但与平常的图像金字塔不同——上层一个像素存的不是下层四个像素的平均，而是它们的最小值（深度越小离 camera 越近，即覆盖范围里「最近」的那个深度）。

```text
level 2 : [    min of 4 texels   ]
level 1 : [ min of 2 ][ min of 2 ]
level 0 : [ p0 ][ p1 ][ p2 ][ p3 ]
```

       * 换来的保守逻辑：如果一根光线和上层的一个节点（一个 texel）都不可能相交，那它绝对不可能和下层的子节点相交——直接整块跳过；反过来，如果和上层节点相交，就有可能和它的子节点相交，再根据光线相交在这块的左边还是右边，决定去看下面一层的哪一个节点。

       * 本质：对「能看到的壳」做一个非常简单的层次结构，用它快速计算光线在传播过程中到底会相交到哪一个像素——与 3D 里建 BVH / KD-tree 来扔掉大量不可能相交区域的思路同源。

   * **试探步流程**

       * 基本思想（借篮球术语「试探步」）：先保守一点、往前稍微走一点点；发现没事就胆子大一点、下一步迈得更大（升层）；一旦发现「有了一个交点」，就知道这时候不该迈这么大步——交点可能出现在更低的一些层上，必须降层继续找。一句话：在危险的边缘疯狂试探。

       * 一维完整走法（光线与壳的真正交点落在某个 level 0 格子上）：在最精细的 level 0 往前试探走一格、比深度没交点 → 升到 level 1 走一格（一次走两格）没交点 → 升到 level 2 走一格（一次四格）终于发现交点 → 这时可不能再激进往前 trace 八格，必须降层：交点在这大格的右半边 → 只考虑右边那个 level 1 的子节点 → 到 level 1 一看还是有交点、交点在左边 → 在 level 0 上考虑左边这个格子 → 一比没交点 → 又升回 level 1 往前走一格 → 又有交点、且交点在左半边 → 降回 level 0 对应的格子 → 找到交点，算法结束。

       * 什么时候停下来？两个条件：第一，找到了交点（代码里 level 会被暂时置成负的）；第二，在整个屏幕上都找遍了也没有交点（已经走出屏幕）。除了这两种情况都要继续走。

       * > **易错点**：⚠️ 降层没有那么简单，不是把 level 直接减一就完事——找到了交点就知道交点在哪，就知道它应该往哪一个子节点里继续找；对应到 2D mipmap 上，绝不会往一个节点的四个子节点分别都去划分。

       * 降层恰恰是工业界实现里最混乱的一步，标准化思路：回到 mipmap 第 0 层往前 trace 发现没交点时，一定应该先到 level 1（每两个格子形成的 node）上找；这种情况发现相交了，才会跟 level 0 上那一个格子去做求交（某个 SIGGRAPH course 的实现和它写的有点矛盾；按这个思路代码能写得比较干净）。

   * **mipmap 的对齐限制**

       * mipmap 可以做范围的查询、正方形的查询，但做不了准确的、起点不在 $2^k$ 边界上的查询（比如问「第 2 格和第 3 格合起来的最小值」）——硬要的话，只能拿左边格子记录的最小值和右边格子记录的最小值，在中间做一个平均、插值出来；是个近似，但应该还是 OK。

### 屏幕空间的天花板

   * **壳上无物**

       * screen space 所描述的场景几何，相当于从 camera 能看到的最外层一层壳：明知手背后面有手指肚，但对 camera 来说它完全看不到——它会认为根本不存在；于是反射出来的就是这层壳，看不到手指的指肚，看起来背后就好像没有手掌一样。

       * 这个问题跟光线追踪没关系，是对场景的理解只到壳为止——screen space 的问题。

   * **反射出屏**

       * 反射光稍微偏一点、反射过去就出屏幕了——屏幕外面发生任何事情都不知道，再也找不到相交的几何，画面上就会出现明显的一道 cut，非常不希望发生。

       * 补救：根据反射光走的距离做一个衰减——走远了就认为它反射的东西基本看不太着了；再把结果虚化掉，这道边界就不那么明显。

### 着色：把路径追踪整套搬过来

   * **只换求交**

       * SSR 仅仅把「光线追踪」这一步，从原本三维空间里光线和 BVH 求交，改成了光线和这层壳求交——之前 path tracing 的任何算法都可以直接过来用；trace 到的那些物体反射回来的 radiance，一定就是 p 点接收到的 incident radiance——这是完全正确的理解。

       $$
       L_o(\mathrm{p},\omega_o)=\int_{\Omega^+} L_i(\mathrm{p},\omega_i)\,f_r(\mathrm{p},\omega_i,\omega_o)\,\mathrm{d}\omega_i
       $$

       * 如果 BRDF 是完全 specular 的，那它是一个 $\delta$ 函数——积分里出现 delta 函数，积分就没了：不用采样，直接沿着反射方向找到它所达到的那个物体、看反射过来的 radiance；一般性的 BRDF（glossy 这些）用蒙特卡罗方法多采样几根。

   * **被反射物 diffuse 假设**

       * > **注意**：屏幕空间中看到的那些像素，记录的都是它们反射向 camera 的 radiance；那些像素 q 反射向任意一个 p 点的 radiance 是多少，并不知道——除非假设这些被反射的东西是 diffuse 的（那样它反射向 camera 还是反射向任何方向，radiance 都一样）。接收反射的一方（地板）完全可以是 glossy、镜面，都没有问题。

   * **BRDF sampling 的两个天然优势**

       * 任意一点的 shading 这么算，有没有距离衰减问题？没有——这里做的是 BRDF sampling：在立体角范围内、在 shading point 上做 trace；距离平方衰减是对某些次级光源的面积做积分、算次级光源贡献（light sampling）才会带来的东西。

       * 有没有处理好 shading point 和次级光源之间的可见性？处理得非常好——在任何 p 点往任何地方 trace，找到的都是第一个能够看到的物体，中间保证不会有看不见的东西。

       * > **结论**（离线渲染里值得记的一般规律）：做 BRDF sampling 的时候，不会有可见性和距离平方衰减这两个问题；做 light sampling 的时候，一定会出现这两个问题，并且都不好做。

   * **白送的现象（前提是 shading 做对）**

       * > **易错点**：shading 千万不是「trace 到了一个像素，就把那个颜色拿过来当作反射出来的颜色」——正确的理解是：trace 到的那些东西是 diffuse 的反射物，取它们所能出射的 radiance。

       * 镜面锐利、glossy 模糊：不同的 BRDF、不同数量的光线而已，绝对能做。

       * contact hardening（接触处更「硬」/清晰）：shading point 的 BRDF lobe 是一个往外打的锥，锥在传播过程中越传越大——shading point 离反射物比较远，锥传到平面上已罩住一大片、等于在平均一大范围里所有点的贡献，反射自然糊；离得非常近，同样的锥只达到非常小的范围，反射就清晰。用正确的 BRDF 来做这个操作，contact hardening 自然而然就有，没有任何额外操作。

       * specular elongation（镜面拉长）：雨天看红绿灯会觉得它们被垂直拉长——认为地面各向同性（法线分布跟各个方向都一样、类似一个圆），给定观察方向，反射出去的 BRDF lobe 其实就是一个上下拉长的长条椭圆。这个现象绝对不是特殊技巧，正确考虑了 shading 的 BRDF 项它就一定出现。

       * 不挑接受反射的东西：平面与否、normal 怎么样都没关系——本来在做的就是 path tracing，不同 normal 只是出射的光线不一样。

### 提升方向

   * **重要性采样**

       * 既然知道观察方向和 BRDF，就知道反射出去应该集中在 BRDF lobe 这个范围内——没有必要均匀地往四面八方随机采样，用一个长得跟 lobe 形状一样的 PDF，让光线更倾向于分布在 lobe 内；一定要正确地计算 PDF。

   * **噪声的两极**

       * glossy 到极致就变成镜面：反射方向完完全全是一个方向，不存在 noise；diffuse 则往四面八方都反射、需要大量的光线（还记得 VXGI 把半球拆成八个锥吗？八个还不够）——noise 最大。

       * 非常神奇的现象：什么样的材质最容易？diffuse——它是最低频的东西、BRDF 是常数，正是用 SH 描述光照的基础；什么样的材质最难？还是 diffuse。

   * **空间复用**

       * 任何 shading point 都可以利用它在屏幕上周围一圈（或稍大一点区域）像素 trace 到的信息：根据两个点各自对应的 BRDF，调整「这个 hit point 如果是由右边 shading point 的反射光打到的，贡献应该是多少」——原本两个点各 trace 一条（共两条），现在每个 hit point 都可以反过来算它对另一个 shading point 的贡献，好像两条光线起到了四条的作用。

       * 复用具体怎么做相对高端、背后要有离线渲染的内功；时间上的复用在实时光线追踪部分会大量讲。

   * **先滤波再查询**

       * split sum 的屏幕空间版：把屏幕空间得到的这张图（反射物）先 filter 一遍、预先模糊，之后对 glossy 的面很可能只需要沿着 specular 方向查一次——就好像在没 filter 的原始图上按真正 glossy 反射的范围查好多次。

       * 难点：屏幕空间这张图各个点的深度不一样（不像环境光假设所有方向都来自无穷远）——不希望做模糊时前景被糊到背景上、背景颜色跑到前景上；而且深度本身是不应该被 filter 的（把前景、背景的深度连续混合取平均没有物理意义）。这一系列 filter 怎么做，属于 joint bilateral filtering（联合双边滤波），留待实时光线追踪部分讲。

   * **总评**

       * 好处：效果非常好、速度又比较快，尤其是 glossy 或 specular 的反射——这也是大量使用这个技术时画面看起来特别「油」的原因（glossy 的反射稍微多了些）；没有那些 exclusion 的问题，也没有 spike（spike 与之前说的距离平方有一定的关系），一切光线追踪能提供的好处都有。

       * 不好处：screen space 的问题肯定会出现；对 diffuse 来说做 tracing 挺难——对任何一个 shading point 都要打出大量的光线往四面八方去。

       * 现状：实时光线追踪（RTRT）发展起来后，可以做非常高效的时间、空间上的 filter，使 diffuse 物体也可以放心去做 tracing；RTRT 与屏幕空间 tracing 本质上一样——都在解决「快速做光线追踪」——可以结合到任何最后的 shading 上；洞穴场景里全是 diffuse 物体、用 SSR 做整个间接光照，就是现成的应用。
