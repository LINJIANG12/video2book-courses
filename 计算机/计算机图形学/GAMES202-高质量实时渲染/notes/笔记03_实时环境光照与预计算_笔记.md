# 实时环境光照与预计算

## 距离场软阴影

### 距离场与带符号距离函数

* **距离场（Distance Field）**

    * > **定义**：空间中任何一个点到某个物体表面最近一个点的距离（到物体表面的最小距离）；distance field 与 distance function 是一回事。

* **带符号距离场（Signed Distance Function，SDF）**

    * > **定义**：在距离的基础上再规定正负号的距离场——物体内部为负、物体外部为正，定义的就不只是一个距离，还是一个有向距离。

    * 平时说"距离场"，不管它有没有符号，一般都直接缩写成 SDF。

    * SDF 是标量场：每个点保存的只是一个值（它的 SDF 值），没有方向。

* 可视化有两种方式：直接把值打印出来——物体内部是黑的（负值），外部随离物体越来越远值越来越大，整个画面像一圈在物体周围糊开的晕影；等值线画法——同样的颜色表示值一样，类比地图的等高线，轮廓往外扩一圈又一圈，每一圈到轮廓的距离都相等。

* 二维情形下"物体表面"就是物体的轮廓：把字母 A 打到一张图上，图上任何一个点到 A 轮廓的最近距离构成 A 的距离场。

### 边界混合性质

* **对图像直接线性插值**

    * 两幅图逐像素做 50% 对 50% 平均：重合区域颜色不变，中间同一位置一幅里是白的、另一幅里是黑的，一平均变灰——最后得到的是边界糊开的一条灰色过渡带，而不是"一个位于正中间的边界"。

* **对 SDF 做线性插值**

    * 先把两幅图各自转换成对应的 SDF（物体内部负值、外部正值、边界上正好为 0、离边界越远绝对值越大），再做同样的线性插值：正中间那个位置在两幅 SDF 里若是 $+5$ 与 $-5$，一平均正好是 0，而 SDF 等于 0 的地方就是物体的边界——零值线恰好落在正中间。

    * 按"SDF $=0$ 即边界"把插值结果恢复成一幅图，就反映了边界在移动：还是线性插值，只是插的对象换成了 SDF。

    * SDF 可以对任意不同的形状做 blending，而且不需要关注它们之间的拓扑关系：一个球朝一个正方形移动，两者各自转换成距离场再 blend，就能融合到一块、得到几何上非常好的过渡。

* SDF 的背后与最优传输（optimal transport）理论关系非常密切，属于学术前沿，把它弄到渲染层面上的一些应用仍在研究中。

### Sphere Tracing 求交

* **Sphere Tracing（球追踪）**

    * > **定义**：用光线追踪去追踪一个距离场、求光线与 SDF 隐含表面交点的 ray marching 方法；前提是整个场景的 SDF 已经拿到。

    * > **定义**：空间中任何一点的 SDF 值都定义了一个安全距离——不管往哪个方向走，只要走的距离不超过它，就一定不可能与任何物体发生碰撞（否则就意味着一定有物体藏在这个范围里，SDF 记录的值就不对了）。

    * 走法：一开始看光线的起点，查它的 SDF，把点沿光线方向移动这段安全距离（这一步一定不会撞上任何东西）；到了新的一点，再查一次 SDF，又知道能往前走多远——走一步、查一步。

    * 停止条件：走到和物体足够接近（SDF 小到一定程度），或光线已经往前走了非常远还什么都没碰到（把这根光线扔掉）。

    * ```text
      o ──SDF(o)──→ p1 ──SDF(p1)──→ p2 ──SDF(p2)──→ ……
      每一步沿光线方向前进的长度 = 当前点的 SDF 值（安全距离）
      ```

* SDF 从哪来是它的局限所在：三维场景中 SDF 是一个三维的场，得把空间中任何一点的值都先算出来、然后存储——相当于存一张覆盖整个场景的、巨大无比的三维格子，存储开销非常高。

* 多物体场景的 SDF 可以组合："最小"是可以取 min 的——每个物体单独算了自己的 SDF，在任何一点上取所有物体 SDF 值中最小的那个，就是这一点到场景中任何物体的最小距离；一个场景所有物体的 SDF 合在一块，像给每个物体描了一圈向外晕开的边。

* 刚体运动的物体没有问题；形变的物体不行——形变意味着物体的 SDF 得重新算一遍，重算多大开销、能否只更新改变了的部分，属于几何领域研究的事情。

### 安全角与软阴影

* 软阴影的本质：光源是有面积的面光源，看过去它有一部分被遮挡物挡住，被挡住的比例是多少，可见性 visibility 就是多少（全没挡 1、全挡 0、挡一半半黑）——问题本质是估计"大概有多少比例的面光源被挡住"。

* **安全角（Safe Angle）**

    * > **定义**：把 ray marching 里的安全距离往后推一步得到的延伸：从 shading point 朝某个方向打一根光线（往光源的方向看），沿途各点的 SDF 限定了视线再多偏多少才会看到障碍——这个可偏转的角度就是安全角。

    * > **结论**：在一个 shading point 上朝某个方向看，安全角越小，能看到的东西越少，阴影就越黑；安全距离很大则安全角很大，哪怕挺大的光源中间都可能没有任何遮挡，可见性基本接近 1（偏白）；安全距离非常小，稍微偏一点就出现遮挡，同样大小的光源很大一部分被挡住，visibility 减小（偏黑）。

    * 求法：沿光线 sphere tracing，第 $i$ 步以 $p_i$ 为球心、$\mathrm{SDF}(p_i)$ 为半径作一个球（二维图中是圆），从起点 $o$ 向这个球作切线，切线与光线方向的夹角就是该步的安全角 $\theta_i$。

    * 整条光线的安全角取最小：$\theta=\min(\theta_1,\theta_2,\theta_3,\dots)$——只要路上任何一点把能偏的角度卡得再窄一点，整体就得按窄的算。

    * ```text
      o ─────→ p1 ─────→ p2 ─────→ p3 ───→ 遮挡物
       \  θ1     \  θ2     \  θ3
      第 i 步：从 o 向以 p_i 为球心、SDF(p_i) 为半径的球作切线，
              切线与光线方向的夹角即该步安全角 θi；整条光线取 min
      ```

* 这是一个非常大胆的近似：SDF 不能告诉你方向在哪——它只告诉你遮挡物大概在这一圈之外、在这个圈上，并不知道阴影会出现在左边还是右边（三维下根本不知道会出现在哪一个圆环里）；既然不知道，就干脆当作整个圆周都是这种情况来处理，不去考虑遮挡物的位置。

* 也不需要真的摆一个面光源去老实计算被覆盖的比例：安全角想告诉你的仅仅是——如果这儿有个面光源、大概这么大，它大概有百分之多少被挡住；最后需要的只是"角度的大小本身能决定阴影的软硬"这一条。

### 阴影公式与软硬控制

* 每步安全角本可以精确求出：SDF 给出的距离是直角边，从 shading point 到当前点 $p$ 走过的距离 $t$ 是斜边，求一个球的切线就是算一个 arcsin：

    * $$\theta = \arcsin\frac{\mathrm{SDF}(p)}{t}$$

* 但 shader 里大家非常不愿意用反三角这种运算量非常大的复杂运算，于是不算 arcsin——两个量的比值本身就已说明角度是大了还是小了，直接拿比值当角度的近似、在上面乘一个系数 $k$，最后和 1 取 min 保证结果是不超过 1 的合法 visibility：

    * $$\mathrm{visibility} = \min\left(1,\; k \cdot \frac{\mathrm{SDF}(p)}{t}\right)$$

* march 过程中的每一步都算这个值，整体再取最小，就是最终的阴影。

* $k$ 的作用是决定"比值多大才算全亮"：既然最后反正要把结果砍到 1 以下，$k$ 越大，很小的安全角也会被当成 1，0 和 1 之间的过渡带自然就越窄。

| $k$ 的取值 | 比值 $\mathrm{SDF}(p)/t$ 达到多少被当成 1 | 0 到 1 的过渡带 | 阴影观感 |
| :--- | :--- | :--- | :--- |
| $k=1$ | 比值 $=1$ | 全程都是过渡带 | 最软 |
| $k=5$ | 比值 $=0.2$ | 只剩 0 到 0.2 一小段 | 变硬 |
| $k=100$ | 比值 $=0.01$ | 只剩 0 到 0.01，极窄 | 几乎是硬阴影 |

* $k$ 极大的情况下结果要么 0 要么 1、中间过渡非常小，就完全是硬阴影——到底多大的角度范围算软阴影的过渡、什么时候完全在阴影内，就简单粗暴地用这一个 $k$ 来定。

* 压缩过渡带的本能做法是上一个 sigmoid（线性函数过了 sigmoid 值被拉向 0、1 两个极端），但 sigmoid 的计算非常麻烦，肯定不如"乘一个 $k$、再和 1 取 min"这么便宜。

### 收益与代价

* 快在两点：在 ray marching 的体系下，本来就要 march 去求光线和隐含表面的交点，软阴影是自然而然引入的，与硬阴影在复杂程度上没有任何区别；单看"用"的阶段，与 shadow map 是差不多快的——查询 shadow map 本身就是一次 texture query，ray marching 也就几次 SDF 查询。

* 对非常复杂的几何，SDF shadow 能达到原来得靠三个 shadow map 才能做到的效果；而且它不会有自遮挡（self-occlusion）问题，也没有阴影悬浮（peter-panning）这些老毛病。

* > **易错点**："SDF shadow 比 shadow map 快"的说法忽略了一个事情——距离场生成的时间。SDF 的生成是预计算；shadow map 真正的时间大头花在生成上，得把整个场景朝光源方向重新渲染一遍。

* > **易错点**：⚠️ SDF 得到的并不是真的阴影——它的近似思路比之前的那些方法大胆得多，给出的阴影反而会更"虚假"一些；它胜在便宜、可用。

* 贵在四点：生成 SDF 是预计算、生成完还得存下来；静态场景和刚体没问题，动态形变物体不行（得重算距离场）；SDF 是三维的，存储对任何物体都不轻松；实际用起来还会有接缝处等各种 artifact，是工业界比较关心的地方——但不影响它给出质量非常不错的软阴影。工业界没有百分之百使用它，主要卡在存储问题上。

* 实时渲染从头到尾全是近似：目的首先是为了快，而且不牺牲特别大的质量。

### 存储压缩与延伸应用

* **层次化存储**

    * 思路之一是给场景建一个类似 hierarchy 的结构——kd 树、八叉树等任何空间划分的树形结构都可以。

    * 不断往下划分会发现：有一些格子离场景中绝大多数物体都非常远，根本没必要计算、也没必要存——整个节点表示的一大片区域的 SDF 值可以直接认为"非常大"；只在值变化剧烈的地方（物体边缘）才细分得很厉害。

    * 结果是一棵树：复杂的 SDF 值只需要存在叶子节点上，非叶子节点上认为是一个常数，完全没有问题。

* 用神经网络去压缩 SDF 的表示在实时渲染里基本走不通：查询 SDF 是个高频操作、而且要频繁查询，每一次查询都得过一遍神经网络，等于把解压缩的负担压到了每一次查询上。

* **无限分辨率字符渲染**：把字符预先转换成 SDF，再在比较精细的层级上做三线性插值之类的平滑过渡，那么不管什么分辨率、离得远还是近，都能看到非常清晰的字体边界——绕开 texture 显示字符的分辨率限制。

* SDF 自己的短板：用 SDF 生成的物体表面非常不好贴纹理——它的 UV（参数化）不好得到，这个问题目前仍在积极研究之中。

## 环境光照与 IBL

### 无限远假设

* **环境光照（Environment Lighting）**

    * > **定义**：用一张图，把"在场景中往任何一个方向看，能看到的光照"记录下来，用这张图做光照。

    * > **定义**：这张图中间隐含一个概念——这些光照全部来自无限远，即 distant lighting 假设。

* 假设的直接后果：放两个不同的物体在场景里，摆的位置不一样，它们接收到的环境光照却完全相同；环境贴图里有一张桌子，也不可能把什么东西"放在桌子上"——那张桌子对它来说都在无限远处；用任何环境光照去渲染任何物体，看着总有一种"漂浮"的现象。

* 存储方式主流就两种：spherical map 和 cube map；常见的 HDR 环境贴图是 spherical map 的形式。

* **基于图像的光照（Image Based Lighting，IBL）**

    * > **定义**：给了环境光照，往场景里放一个物体，不考虑遮挡、不考虑阴影，把物体上任何一个 shading point 的 shading 算出来——这套操作在工业界叫做 IBL，或者说 environment lighting，指的就是这件事。

    * 想用在哪都能用，工业界用得特别多；唯一的问题就是无限远假设——一旦光源和物体之间有确定的距离，这套假设就不再成立，不能再这么用。

### 渲染方程与采样困境

* **渲染方程（不考虑 visibility 项）**

    * > **定义**：实时渲染中通常把 visibility 拆出来单独处理，式子里的 lighting 指的是"发光的 lighting"，被积的光照项就是环境光从四面八方来的 $L_i$：

    * $$L_o(\omega_o) = \int_{\Omega} L_i(\omega_i)\, f_r(\omega_i, \omega_o)\, \cos\theta_i \, d\omega_i$$

    * 积分域 $\Omega$ 是上半球，由 shading point 的法线定义（取法线点乘为正的那些方向）；任何方向都可能有光照，但渲染方程只考虑来自正半球的部分。

* 通用解法是蒙特卡洛积分：$\frac{1}{N}\sum_{i=1}^{N}\frac{f(x_i)}{p(x_i)}$——对任何积分都可以拿任意 pdf 的样本来做数值近似，而且这个近似是无偏的；求和分母里的 $p$ 就是采样分布的 pdf。

* 实时困境：蒙特卡洛需要大量样本才能让结果收敛到期望值，而整个场景任何像素、任何 fragment 都要做一遍"四面八方光照"的积分，需要多少 sample？非常慢。

* 经验法则：只要在 shader 里——特别是 fragment shader——出现了 sampling，这个方法多半就不能用在实时渲染中；这句话现在要打个星号：最近几年时间上和空间上的一系列滤波方法，让越来越多基于 sampling 的方法进入了实时渲染，以前这么认为，现在不一定了。

* 神经网络 denoising 的现状：除了 DLSS，大家用得都不太多、并不怎么成功——实在太慢，跑一遍神经网络要几毫秒，在实时渲染里这就已经死了；特别是要在 shading 层面每个点都跑一遍就更完蛋；至少眼下，能不采样当然最好。

* 核心问题由此变成：**在 IBL 的情况下，任何一个点的 shading，能不能不通过采样来算？**

### 拆分近似的条件与形式

* 观察起点：渲染一幅图时看的视角是固定的，不考虑 visibility 时被积的就是两个函数相乘——一项 lighting、一项 BRDF（cos 连着 BRDF 一起写）。

* 经典近似的适用条件：把两个函数乘积的积分拆开，要求剩下的 $g$ 的 support 比较小，或者 $g$ 的值比较 smooth。

* 两种极端的 BRDF 恰好天生各满足其中一条：

| BRDF 类型 | lobe 在球面上的覆盖（support） | 值的变化 |
| :--- | :--- | :--- |
| glossy | 很小，只覆盖镜面反射方向周围一小片 | 变化剧烈 |
| diffuse | 覆盖整个半球，范围非常大 | 非常 smooth：值本来就是常数，连上 cos 也只是一个相对平滑的过渡 |

* 拆分公式：BRDF 留在积分里充当 $g$，光照拿到外面，在 BRDF 的 support $\Omega_{f_r}$ 上积分、再除以 support 的大小做 normalization：

    * $$\int_{\Omega} L_i(\omega_i)\, f_r(\omega_i, \omega_o)\, \cos\theta_i \, d\omega_i \;\approx\; \frac{\int_{\Omega_{f_r}} L_i(\omega_i) \, d\omega_i}{\int_{\Omega_{f_r}} d\omega_i} \cdot \int_{\Omega} f_r(\omega_i, \omega_o)\, \cos\theta_i \, d\omega_i$$

* > **易错点**：⚠️ 别和拆阴影那次搞混：解释阴影的时候，拆出来的是 visibility 项，lighting 和 BRDF 都留在里面充当 $g$；同一个公式按需要选用，这次拆出来的是光照。

* 拆出来的前一半和 BRDF 再没有任何关系——这正是拆分的好处：light 和 BRDF 综合作用难算，拆开后光照这半可以单独处理；它说的是把光照在 BRDF lobe 覆盖的那片范围上积分、再除以范围大小，描述的正是一个"模糊"操作。

* > **定义**：把光照拆出来，等价于定义了一种操作——filtering，对环境光做滤波；滤波核取多大，就是 BRDF lobe 占多大。

## Split Sum：预滤波与查表

### Prefiltering 与查询规则

* **预滤波（Prefiltering）**

    * > **定义**：重点在一个"pre"——这张环境光图在渲染之前、老早之前就先 filter 好：拿到环境光之后立刻花点时间，用不同大小的滤波核把它 filter 成一串新的图，核越大（也就是 BRDF lobe 覆盖越大）结果就越糊；这几张图全部在渲染开始前生成好，实际渲染时完全不用管它。

    * 要查某个大小的滤波结果，与 mipmap 非常像：预先按 filter 1、filter 2、filter 4、filter 8 生成一串图，要 filter 5 就在 filter 4 和 filter 8 之间插值一下——非常像三线性插值；工业界的常用套路，任意大小的滤波结果都能插出来，不只查离散几档。

    * > **易错点**：⚠️ 滤波必须发生在球面上——spherical map 每个像素表示的立体角并不一样，不能对这张图做 uniform 的滤波；"取多大的 filter"指的是球面上的立体角范围，落到图上每个像素该 filter 什么形状、多大，都不一样。好在这一步属于预计算，图用多大分辨率、怎么存都没关系，只要保证滤波是在球面上做的。

* 查询规则：

    * diffuse 是特殊情况：lobe 覆盖整个半球，滤波差不多就是全图的平均（或者沿 normal 方向取平均），查询方向就是 lobe 的中心——normal。

    * glossy 沿 lobe 的中心方向查，也就是镜面反射方向；glossy 的 roughness 不断变大不就变成 diffuse 了吗、那不还得沿镜面反射方向查——没关系，实时渲染里大家通常把 diffuse 和 glossy 拆开处理。

    * 滤波核得按一系列已知形状的 BRDF lobe 来做：好在正常的 BRDF lobe 都长得比较像高斯，做个近似、差不多就 ok。

    * 程序化生成的 HDR 纹理不能直接这么套，除非它本身支持动态的范围查询。

* 等价性：本来要精确算这个 shading，做法是去采样 BRDF 的 lobe——按 glossiness 或 roughness 在镜面反射方向周围分布采样点、把采样值做加权平均；而"采样加权平均"和"把 environment lighting 先 filter 好、再在镜面反射方向直接查一次"是同一件事：滤波后的图上任何一个点都是它周围一片点的加权平均，查一次就相当于查了它周围的一片值。前一半就此零采样解决。

### BRDF 积分的参数降维

* 拆出来的后一半是对整个 BRDF 做积分：$\int_{\Omega} f_r(\omega_i, \omega_o)\cos\theta_i \, d\omega_i$，思路还是预计算；有比这更好的方案叫 LTC（Linearly Transformed Cosines），但它并不是严格意义上直接解决这个问题，只是和这里的东西相关，也别把 LTC 想狭隘了——它不是只能算面光源。

* 预计算要把所有参数的可能性都考虑进去。假设是 microfacet BRDF，最重要的就是两件事：

    * Fresnel 项：垂直看向物体表面时有多少能量被反射——决定基础反射率、也就决定了颜色；不垂直时反射量随入射角度各不相同，在 grazing angle 下往上翘。

    * NDF（法线分布函数）：微表面的法线分布，一个非常简单的一维函数，直接拿 roughness（粗糙度）描述——分布四面八方都有，表面就是 diffuse；法线集中在某个方向，就接近镜面。shadowing-masking 项这里不提。

* 维数的账：$R_0$ 是个颜色占三维、入射角一维、roughness 一维——参数空间至少是五维的，对每一组参数组合都要算出一个积分值，打一个五维的表不可行（三维纹理平时都用得少：三维就已经组合爆炸、存储量很大，四维五维更是如此）；退一步把 $R_0$ 当成灰度看，变量剩三个（入射角 $\theta$、基础反射率 $R_0$、粗糙度），三维预计算仍然太麻烦。

* 预计算是非常正常的做法，相当于支撑了整个游戏界的发展；人们承受不了的只是非常高维的预计算——思路很清楚：**不能预计算，就想办法让它能预计算。**

* 角度互换惯例：入射角（入射光与法线的夹角）、出射角（出射光与法线的夹角）、半角（入射光和出射光夹角的一半，即入射光与半程向量 half vector 的夹角）——这几个角都认为差不多，可以互换，干脆统一用一个 $\theta$ 描述。

### R0 的拆分与二维查表

* Fresnel 项有一个著名的近似 Schlick approximation：不同材质的 Fresnel 项在不同入射角度下，都长得像一条往上涨的指数曲线：

    * $$F(\theta) = R_0 + (1 - R_0)\,(1 - \cos\theta)^5$$

    * 它认为 Fresnel 项就是两个量的函数：基础反射率 $R_0$（一个颜色），以及入射角 $\theta$。

* NDF 以 Beckmann 分布为例，有两个变量：$\alpha$ 定义 roughness，决定分布是胖还是瘦（材质偏 diffuse 还是偏 glossy）；另一个是 half vector 和法线之间的夹角 $\theta$，同样可以通过近似跟入射角互换。

* 降维手法：把积分里的 Fresnel 项显式地写出来——把 BRDF 写成"BRDF 除以 $F$ 再乘以 $F$"（完全没变），然后把 Schlick 形式的 $F$ 代进去整理：

    * $$F(\theta_i) = R_0\left[1-(1-\cos\theta_i)^5\right] + (1-\cos\theta_i)^5$$

* 对给定的材质 $R_0$ 是常数，于是积分里一切和 $R_0$ 相关的项都可以提到积分外，一个积分整理成两个：

    * $$\int_{\Omega} f_r \cos\theta_i \, d\omega_i \;\approx\; R_0 \int_{\Omega} \frac{f_r}{F}\left[1-(1-\cos\theta_i)^5\right]\cos\theta_i \, d\omega_i + \int_{\Omega} \frac{f_r}{F}\,(1-\cos\theta_i)^5\, \cos\theta_i \, d\omega_i$$

* 这个值肯定是个近似但差不多；听起来一个积分变两个好像变麻烦了，恰恰相反：**这个积分原本对基础反射率的依赖被消除了**——拆开之后，剩下的每个积分只依赖两个变量：BRDF 的 roughness，与入射角 $\theta_i$（或者说 $\cos\theta_i$，无所谓）。

* 落地成表：roughness 取一列、$\cos\theta_i$ 取一行，每个格子上填这个积分算出来的一个数——不管积分多复杂，算出来都是一个数；两个积分各打一张二维表。二维数组反映到实时渲染里就是一张纹理：预先算好送到 shader 里，用的时候只管查；两个积分值还可以用 R、G 两个通道分别存，一张纹理搞定。运行时给你一种 microfacet BRDF，$R_0$ 已经拆出来了，只要查两次这张表，又没有采样。

* > **提示**：拆出来的式子里 BRDF 要除以 $F$，这个 $F$ 不用真算——分母仅仅是为了把式子写出来；microfacet BRDF 分子上本来就是 $F \cdot G \cdot D$，再除以一个 $F$ 直接消掉了。

* > **易错点**：菲涅尔项本身要不要预计算？不需要——它被拆开了，正是因为拆开了，它对不同变量的依赖才被解除，不要在这里绕晕。

### 命名与效果

* **拆分求和（Split Sum）**

    * > **定义**：工业界不太写积分、平常就写成求和（求和式和积分描述的是完全一样的事情）；这个方法做了两件事——把一个积分（求和式）拆成两半，两边分别处理：一边 filter、一边查表，再各自求和。所以它叫 split sum，而不叫 split integral。

    * 它是大名鼎鼎的 Unreal 引擎的 PBR 能做到这么牛的基础：环境光照在 split sum 下完全没有 noise（没有采样，当然没有噪声），而且结果和 reference（就理解成 path tracing 出来的结果）非常相近，diffuse 和 glossy 的情况都非常像。

* 这张预计算图是固定的：任何不同的 BRDF，只要是同一种种类的 microfacet BRDF，查的都是同一张图，只需要把这一张传进去；BRDF 不同算出来的图当然不同，但用 GGX 并不会多出参数来，还是这么写参数。

* 对 split sum approximation，学术界普遍认为它就是 state of the art：又可以更快、效果又更好；LTC 这种方法其实也是需要一点点计算的，并不因为可以不用预计算就自然更好。

* diffuse 和 glossy 的项其实还可以继续拆分，后面还有不少后续处理。

* ```text
  渲染方程（不考虑 visibility）
    ∫ Li(ωi)·fr(ωi,ωo)·cosθi dωi
          │ 拆分近似：两个函数相乘的积分，拆成两半各管各的
          ▼
  [前一半] 光照项 —— 环境光图预滤波：按 BRDF lobe 的大小把环境图
                     模糊成 filter 1/2/4/8 一串图（运行时插值出任意
                     粗细），渲染时沿镜面反射方向查一次
          ▼
  [后一半] BRDF 项 —— Fresnel 按 Schlick 展开把 R0 提出积分外，
                     每个积分只剩 (roughness, cosθi) 两个变量，
                     预计算成一张纹理（R/G 双通道），运行时查两次
          ▼
  两半相乘 = 最终 shading：全程零采样、零噪声
  ```

## 环境光下的阴影难题

### 困难的三种视角

* 问题的位置：环境光照要解决的是忽略阴影时的 shading；真的给你环境光了，怎么实时地把它对应的 shading 和 shadow 都算出来——实时渲染下不知道怎么做，非常难。

* **看法一：环境光是 many light 问题**

    * 环境光可以理解成四面八方过来的光照、各不相同：环境光上有一片是白的，就可以认为那儿有一个白色的面光源——本质是所谓 many light（使用很多光源）问题。

    * 要渲染整个场景、把阴影弄出来，每一个光源都得给它生成一张 shadow map，代价线性于光源的数量，非常高的代价，自然不愿意做。

* **看法二：采样解渲染方程**

    * 在任何一个 shading point，知道来自整个上半球各方向的光照；最简单的办法就是采样，还可以重要性采样（哪一块亮就多采一点），但仍需要大量的采样样本。

    * 真正的难度不在于采样光照，而在于：并不知道从任何一个 shading point 往各个不同方向看出去的 visibility term 是什么——遮挡在四面八方不同的位置、不同的方向上截然不同；可以重要性采样环境光照，但不知道遮挡情况就没法针对性去采，只能盲目采样。

* **看法三：拆分近似失效**

    * 把之前"两个函数乘积的积分拆开"的思路用来拆 visibility，要求剩下的项 support 小或者低频 smooth：BRDF 这边，diffuse 的变化挺慢是低频的，还好；glossy 的集中在很小的一个区域、然后瞬间衰减到非常小，非常高频，做不到。

    * 光照项 $L$ 的 support 是多大？整个半球——两头都对不起，所以 visibility 不容易从整个 rendering equation 中提出来。

### 现有近似与出路

* **环境光遮蔽（Ambient Occlusion，AO）近似**：用 AO 近似整个 visibility 是可以的，但要注意它近似了一件非常重要的事——AO 假设你是在一个 constant 的环境光下（整个环境光全白或全灰）才可以做；如果真是任意变化的环境光，拿 AO 去近似，得到的结果自然就没那么准，看着别扭是正常的。

* **工业界的土办法**：环境光照里面总有一个最最有代表性的光源（比如人们在野外跑时最重要的太阳，来自比较小的立体角），主要生成它投射下来的阴影，稍微多一点就生成两三个——这就是现在绝大多数工业界在做的事情，效果还不错。

* 两条研究线索：imperfect shadow maps（实时渲染工作，理论上做的不是"来自环境光的阴影"，而是全局光照部分产生的各种各样的阴影）；light cuts（离线渲染里里程碑式的一系列工作，把场景中的反射物当成很多小的光源，不想把它们全部看一遍就用归类去近似它们整体照亮某一个点的结果——解决的就是 many light 问题）。

* 一个判断：如果真想完全解决"从环境光照过来的阴影"，很可能在未来 10 年之内会出现一批用 RTRT（real-time ray tracing，实时光线追踪）来解决它的实用方法——RTRT 用的本来就是 path tracing 加 denoising 的思路，应该可以解决所有跟采样、样本不足有关的问题，很可能是一个终极解决方案。

* 游戏引擎里的全局光照（RTX GI、屏幕空间的方法、基于 probe 的方法）通常不太可能只用一个，正常情况下都是一些大杂烩（例如几种不同方案的混合体、屏幕空间 trace 和 probe 的结合）；这些方法本身都没那么难，关键是如何写进引擎还能非常快、对任何场景都 work 不出巨大问题——这是工程上的本事。

## 频域分析与基函数

### 傅里叶级数与频率

* **傅里叶级数展开**

    * > **定义**：任何一个函数，都可以写成一个常数的提升加上一系列 sin 和 cos 函数的线性组合，且这些 sin、cos 各自的频率（周期）不一样：

    * $$f(x)=a_0+\sum_{k}\left(a_k\cos k\omega x+b_k\sin k\omega x\right)$$

    * 不断增加项数就能得到不断更好的逼近：一开始用一个 cos 看起来挺 smooth，引入频率更高的项变化大很多、可以加入细节，再引入变化更快的项加入更多细节，最终把整个原始函数的样子描述出来；各项之间隐含一个由低到高的频率关系。

    * 周期 box 函数的展开里只看到 cos、没有 sin，是因为这个函数是左右对称的偶函数，sin 项自动就是零——仅仅因为它特殊；正常情况下 sin、cos 都有。

* 频率说的就是信号变化的快还是不快——注意不是指时间上一直在抖，而是空间上：图像上一根一根的头发变化非常剧烈是高频，背景颜色变化不剧烈是低频。

* 一个函数表示成其他这些函数的线性组合——那一堆"其他函数"，就是后面要用的基函数。

### 频谱、滤波与卷积

* **频谱（Spectrum）**

    * > **定义**：对任何一个函数（一张图自然就是二维函数），把它在频域上对应的内容显示出来；频谱最中心这一块是最低频的内容，稍微向外的区域就是高频的内容。

    * 对任何一张自然的图片来说，绝大多数都是低频内容（人脸上颜色变化比较少、衣服上变化也比较少）；只保留最低频的部分变回原来的图，就得到一张相对模糊的图——保留低频部分，还是基本能看明白这张图在干什么。

* > **定义**：滤波（filter）就是去掉一系列对应频率上的内容；像这样留下最低频率的叫低通滤波器（low pass filter）——比它频率高的地方都扔掉，对应的信号由低频成分组成，看到的就是一些模糊的东西。

* **时域卷积 = 频域乘法**

    * 时域和频域之间有一个相对应的操作：在时域上做卷积，等于在频域上做乘积。卷积就是一个模糊操作——对任何一个点取周围一片区域、把这片区域里的结果综合起来再写回（取 3×3 挺小，取 9×9 图就会变得非常模糊）；图形学里不怎么特别说"卷积"这个词。

    * 频域视角：原始的图有频谱 $F$；卷积核（"取周围多大一块"的那个东西，如 3×3 的 box）也有自己的频谱 $H$——box 变到频域之后大体还是有些地方接近 1、有些地方是 0 的形状，边上会漏出一点高频的涟漪；两个频谱逐点相乘，是 0 的地方乘完就是 0，好像用了一个类似 mask 的东西；相乘之后再做逆变换，就得到模糊之后的结果。

    * ```text
      图像 f          ──变换──▶   频谱 F
      卷积核 h(3x3)   ──变换──▶   频谱 H（近似一块低通的"mask"）
      卷积 f ⊛ h      ◀─逆变换─   逐点相乘 F · H
      ```

* > **定义**：product integral——一个函数 $f(x)$ 乘以某个 $g$、再把它积分起来；任何满足这种形态的操作都认为它存在一定的滤波意义。严格来说相乘的两个变量应该区分开：写成 $f(x)$ 乘以某个 $g(y)$、再对 $x$ 积分；它的本质是两个向量的点乘从向量推广到了函数。

* 更通用的理解：卷积基本上就等于滤波；两个信号在时域上乘起来再积分，等价于它们各自的频谱在频域上相乘。

* > **结论**：两个函数各自的频谱，只要有其中一个是低频的，频域上乘出来的结果就是低频的——相当于只留下了频谱中间的那一部分；所以乘积积分得到的结果，其频率一定由 $f$ 和 $g$ 各自频率中最低的那个来决定。低频的简单理解：看起来 smooth、变化没有那么剧烈。

### 基函数

* > **定义**：基函数（basis functions）——用一系列函数 $b_i$ 的线性组合去描述一个函数：$f(x)=\sum_i c_i\, b_i(x)$，每个 $b_i$ 前面乘上某个系数 $c_i$、全部加起来得到原始函数，这一系列函数 $b_i$ 就叫基函数。

* 它的目的就是：用这套基函数的不同组合，可以描述不同的函数。

* 常见的两套：傅里叶那套（一个常数加一堆 sin、cos）；多项式系列——$1$、$x$、$x^2$ 一直到 $x$ 的高次，和泰勒展开（$1+x+x^2+\dots$）非常像。

* 三条本事：其一，只要基函数的个数足够多（对 SH 来说就是取足够多的前 $n$ 阶），可以表示任何函数；其二，只想保留一个函数的低频信息，就只取前面低阶的基函数与对应系数去重建，得出来的必然是低频信号；其三，两个函数如果都是拿 SH 基函数来表述的，它们的 product integral 其实是一个点乘。

## 球谐函数

### 定义与阶数结构

* **球谐函数（Spherical Harmonics，SH）**

    * > **定义**：一系列定义在球面上的二维基函数——系列中的每一个都是二维的、都定义在球面上；可以理解成关于方向的函数：三维空间中任何一个方向由 $\theta$ 和 $\phi$ 两个数描述（两个数描述的东西自然是二维的），单位球面上的一个点就描述了一个独特的方向，球面上不同的点（方向）取不同的值。

    * 它非常像一维情况下的傅里叶级数：本身也存在不同频率的函数，而且不同频率的函数个数也不同；同一层内描述的频率一样，只是形状或者旋转各不相同。

* 分层结构：$l=0$ 这一层只有 1 个函数，是 uniform 的——球上任何一个方向值都一样，看起来就是一个均匀的球；$l=1$ 这一层有 3 个函数——相当于某个半球上有值、另外半球上对称地有相反的值，三个函数各自的朝向不一样；$l=2$ 这一层有 5 个；$l=3$ 这一层有 7 个。

| 阶 $l$ | 基函数个数 | 编号 $m$ 的取值 |
| :---: | :---: | :---: |
| 0 | 1 | 0 |
| 1 | 3 | $-1,0,1$ |
| 2 | 5 | $-2,-1,0,1,2$ |
| 3 | 7 | $-3,-2,-1,0,1,2,3$ |

* > **易错点**：⚠️ 第 $l$ 阶 SH 有 $2l+1$ 个基函数——是 $2l+1$，不是 2 的多少次方；每个基函数还有固定的编号 $m$，从 $-l$ 一直到 $l$（$l=0$ 只有编号 0，$l=1$ 是 $-1,0,1$，$l=2$ 是 $-2$ 到 $2$，$l=3$ 是 $-3$ 到 $3$）。

* 前 $n$ 阶（指 $l=0$ 一直到 $n-1$）总共有 $n^2$ 个基函数：前 1 阶（就是第 0 阶）1 个、前 2 阶总共 4 个、前 3 阶 9 个、前 4 阶 16 个（$1+3+5+7=16$）。

### 球面连续性与二维展开的问题

* 球面函数当然可以先展开成 $\theta$ 和 $\phi$ 的二维图再做二维傅里叶变换——环境贴图本身就是"一个球面展开成二维图"的典型例子，这条路本身是行的。

* 但把球面函数用二维傅里叶的这些基、根据不同频率去做近似，最后再把结果变回整个球面上，很可能在球面上弄出缝来。

* SH 本来就是定义在球面上任何一个不同方向的，从可视化也能看出它在球面上非常连续——很适用于直接拿来分析球面上函数的性质，这是选它的原因。

### 可视化与来源

* 每一个 SH 基函数是利用勒让德多项式（Legendre polynomials）来写的；勒让德多项式数学上写起来挺麻烦，但没必要去管它具体怎么写出来——要理解的是它在干什么：任何一个函数都可以描述成基函数的组合，并且 SH 类比傅里叶级数，从低到高可以把不同的频率描述出来。

* > **易错点**：可视化小球图里的颜色不是频率，颜色表示的是值——越偏白的蓝，那个地方的值越大；越偏白的黄，表示值的绝对值越大（这些基函数有正有负）；频率看值的变化剧烈不剧烈，一眼就能看出来（$l=3$ 那一层长得像花儿一样变化剧烈，频率当然比 $l=1$、$l=2$ 的层要高）。

* 以 $l=1$、$m=0$ 中间那个函数为例：它在北极的地方值非常大（正），南极的地方值的绝对值非常大（负），而在整个赤道上值都是零。

### 投影与重建

* > **定义**：投影（projection）——给你任何一个函数，用某一整套基函数（basis）去描述它时，求任何一个基函数前面系数的过程；任何函数 $f(\omega)$ 都可以求出它在任何一个基函数上的投影。

* 系数有一个非常干净利落的性质：$c_i$ 就是 product integral——对应位置逐点相乘，然后再做积分：

    * $$c_i=\int f(\omega)\, b_i(\omega)\, \mathrm{d}\omega$$

* 投影不是拿着环境光贴图每个像素投一遍——整个环境光贴图描述的是球面上的一个二维函数，所谓投影是这个函数对每一个基函数都算出一个值（一个系数）。

* 基函数怎么挑"重要"的：公认最低频的信息最重要，所以取法就是从最低频到最高频顺着来——要恢复一个函数，只需要用它最低的前几阶（前 $n$ 阶）去恢复；每一阶内部通常不挑——说用前多少阶，就把前多少阶内部的这些基函数全用上，很少有人在一阶里面挑两个来描述函数。

* 投影那个积分怎么算：肯定要对不同的方向进行采样，想直接算出解析解没那么容易——这个计算在实际渲染的时候很可能承担不起，得拿到渲染之前去做，这就是预计算的思想。

* 重建：SH 照这种定义方法 $l$ 可以无限大（$l$ 等于 100 对应 201 个函数），但恢复原函数并不想用那么多的基函数——用前若干阶（比如前四阶 16 个）的系数与对应的基函数乘起来、加起来，就恢复出原来函数的一个近似。

* 只取前若干阶这个动作本身就天然完成了一次只留低频的滤波：用前四阶恢复出来的函数只保留 $l=3$ 所能表述的最高频率，更高的频率就被扔掉了；用的基函数个数从低到高越多，就越能引入多一点的高频信息（类比傅里叶级数取前面五项、七项）。

* 阶数与重建质量：同一张环境光贴图分别用前两阶、前三阶、前五阶的 SH 基函数去恢复，都能看出个大概；用到前 26 阶——这就很多了——恢复效果已经相当不错。

* 向量类比：空间里一组相互垂直的 $x,y,z$ 轴就是三个基函数，任何向量的坐标就是它分别投影到三根轴上的值，$\vec v = c_x\,\hat x + c_y\,\hat y + c_z\,\hat z$；把函数投影到基函数上做的是积分（product integral），与把向量投影到轴上做点乘是完全一样的道理；一个基函数投影到另一个基函数上得到零的性质叫正交（orthogonality），线性代数里和 SH 里这些概念的定义基本完完全全一样。

## Diffuse 环境光着色

### Diffuse BRDF 的低通滤波本质

* prefilter 的直觉：filtering 就是 convolution、就是模糊——先把整个球面函数（环境光）模糊一遍，然后沿着镜面反射方向在这个模糊过的环境光上查一次，得到的结果看起来就是 diffuse 的；"prefilter 过的环境光 + 一次查询"等价于"不做任何滤波、在一个点上往各个不同的方向查询、把整个 environment 的值都算一遍再平均"。

* diffuse BRDF 非常 smooth，rendering equation 得到一个非常好的简化：lighting 是整个 environment map 给出的球面函数，BRDF 是定义在整个半球上的一个很光滑的函数（cos 项暂时归进 BRDF 项；考虑 shading 就没有 visibility），两者逐点相乘再积起来——两个函数的 product integral。

* > **结论**：diffuse BRDF（连 cos 项带上）就像一个低通滤波器——两个函数做 product integral，乘出来的结果的频率由频率最低的那个函数决定；环境光可以非常复杂、低频高频都有，但拿它照亮一个 diffuse 物体，基本看不到什么高频信息（从来没人见过一个 diffuse 的球表面反射出非常复杂的光照）。

### 三阶近似实验

* 把 diffuse BRDF 投影到 SH 上会发生什么：第 0 阶、第 1 阶、第 2 阶投影出来都有值——各自得到系数 $c_i$；投到第 3 阶，基本上就没什么内容了；第 4 阶似乎有一点负的、但也很少——从第三阶开始，投影不投影无所谓了。

* 这个现象非常有道理：后面几阶投影没有值，说明这个函数根本没有后面几阶所描述的高频信息——diffuse BRDF 就是挺低频的。

* 光照侧的实验（一组是正确的积分结果，另一组依次用不同阶数的 SH 来描述光照）：

    * 只用前一阶：前一阶就是一个完全 constant 的函数，拿它去照亮球，得到一个非常平的结果，不太好；

    * 用前两阶：结果看起来已经不错了；

    * 用前三阶：和正确结果几乎完全一致，误差可以计算出来，小于等于 1%。

* > **结论**：对任何光照条件，只要材质是 diffuse，都可以用前三阶 SH 来描述光照，然后拿它去照亮 diffuse 物体——原理是 BRDF 的频率不会超过三阶 SH 能表示的频率，而光照项与 BRDF 项做的是 product integral，所以光照项也不需要超过三阶 SH 所能表示的频率。

* SH 近似的是什么：通过先分析 BRDF 的频率，来决定用多少阶 SH 去近似光照——仅仅是光照；$f$ 指的就是任意环境光贴图这个球面函数。

* SH 是不是只能应用在 diffuse 上？不一定：SH 非常适合描述低频的光照；diffuse 的意思只是说，物体是 diffuse 的情况下根本用不着那么高频的光照。

### 二次型与两行代码

* 如果 SH 只用前三阶，diffuse 物体在 SH 光照下的最后结果可以写成一个 polynomial——一个平方的、与 shading point 法线相关的函数（关于法线的二次型，quadratic）。

* 这套理论出自 Ravi Ramamoorthi 博士期间的工作——正是他把 Spherical Harmonics 引入图形学，才有了之后整个 PRT 的十年；他写的计算环境光照下任何一个点 shading 结果的函数用了多少行代码？两行。这就是历史上著名的"两行代码拿博士学位"的例子——背后的数学当然非常多，但就这两行代码他拿到了博士学位，开创了运用 Spherical Harmonics 解决实际问题的时代。

* 这里说清楚的仍然是 shading、不是 shadow——说的仅仅是"大家用 Spherical Harmonics"这么一个事情。

## PRT 预计算辐射传输

### 方法定位

* **预计算辐射传输（Precomputed Radiance Transfer，PRT）**

    * > **定义**：从环境光出发、对任何 BRDF 的物体把阴影（遮挡关系）都考虑进去的预计算方法；它不仅仅能做环境光照下的 shadow 和 shading，还可以做全局光照——正好是环境光照与全局光照两块知识之间的连接。

    * 动机：Ravi 提出 Spherical Harmonics 之后，立刻有人联想到利用基函数的基本原理先把比较复杂的东西预计算出来——成果就是足以记入史册的 Precomputed Radiance Transfer 论文；它要解决的是：怎么让"算任何一个点带 shadow 的 shading 结果"算得快。

    * PRT 可以得到非常准确的、从环境光来的阴影；按一贯的分析思路，紧接着要问的就是：代价是什么。

* 预计算思路大约在二十年前到十年前这段时间得到了非常普遍的应用；后来大家在游戏开发中发明了各种"又不需要预计算、又可以得到一些近似效果"的方法，预计算方法就用得不那么多了——但它是非常里程碑式的作品系列，直到今天学术界还在积极推进；尤其是和 real-time ray tracing 结合起来，它可能会得到重新焕发生机的机会。

### Triple Product 与暴力求解

* **Triple product 形式**

    * > **定义**：实时渲染中人们更愿意把 rendering equation 写成 lighting 项、visibility 项、BRDF 项三块乘起来再积分的形式，得到沿观察方向 $o$ 看过去的值：

    * $$L(o)=\int_{\Omega} L(\omega)\,V(\omega)\,f(\omega_o,\omega)\,(n\cdot\omega)\,d\omega$$

* 真要解这个积分，不采样的做法是把所有可能的入射方向都考虑一遍——这时会发现三项全都是球面函数：

    * lighting 是球面函数，cube map 就是它的描述法；

    * visibility 也是球面函数：任何一个 shading point 往四面八方看，看到的就是一个球面——往下半球看完全是黑的，往上看有些地方能看到 light、有些地方被东西挡着看不到；这一点的 visibility 要么是 0 要么是 1，记下来自然是个球面函数；

    * BRDF 本来是四维函数（入射方向 × 出射方向），现在从某个方向看，等于告诉了这个四维函数出射方向 $\omega_o$ 是什么，剩下的入射方向就是二维的——也可以描述成一个球面函数。

* 最直观的暴力解法：cube map 上对应的像素挨个乘，三个值乘起来，再按立体角加权、把所有方向的贡献加起来——假设 lighting 的 cube map 每面存成 64×64、共 6 面，那么每个 shading point 都要做 $6\times 64\times 64$ 次"三个值相乘再累加"，每个点都要来这么一遍，非常麻烦，不想干这种事。

### 核心假设与二分法

* > **定义**：PRT 的基本思想是一个假设——整个渲染的时候，场景里其他东西都可以不变，只有光照可以发生变化；光照怎么变都行：换一种光照可以，同一种光照做旋转也可以。

* > **定义**：二分法——rendering equation 里积分的东西拆成两部分：一部分叫 lighting（会变），另一部分跟 lighting 无关、叫 light transport（不会变）；后者是每个 shading point 自己的性质，可以在渲染之前算好。

* light transport 的构成：visibility 是这一点往任意不同方向看的结果、是球面函数；BRDF 固定了观察方向 $o$ 之后剩下二维；后面 $n\cdot\omega$ 这一项对这个点来说法线 $n$ 是常量、cos 项也是 $\omega$ 的函数——它们放在一块儿本身还是个球面函数，所以 light transport 也可以写成基函数的表示。

* 预计算的两件事：把 lighting 拆成基函数描述（一系列 basis function 与系数相乘再相加）；把每个 shading point 的 light transport（一个球面函数）也投影到基函数上，存成一串数。

### Diffuse 情形推导

* diffuse 的 BRDF 是什么？就是一个常值——放心把它拿出积分，写成 $\rho$（更熟悉写成 $k_d$ 也无所谓，它就是一个数）：

    * $$L(o)=\rho\int_{\Omega}L(\omega)\,V(\omega)\,(n\cdot\omega)\,d\omega$$

* > **易错点**：这一步不是一个什么近似，是标标准准的等式——diffuse 的 BRDF 既然是常数，当然可以拿到积分外面。

* 把任何一个光照都写成基函数描述的形式 $L(\omega)=\sum_i l_i\,B_i(\omega)$，把这个求和式带进积分、交换积分与求和的顺序——微积分里经常探讨什么时候可以交换，图形学里从不考虑这件事、认定它一定可以交换（可微渲染 differentiable rendering 里才真的要考虑，PRT 这个场合绝对不需要）。

* 交换之后 $l_i$ 对积分而言是个常数、先拿出来；积分里剩下 $V$ 乘 cos 项再乘 $B_i$——这正是 light transport 投影到基函数 $B_i$ 上的系数：

    * $$T_i=\int_{\Omega}V(\omega)\,(n\cdot\omega)\,B_i(\omega)\,d\omega$$

* 场景中只有 lighting 在变、其他什么都不变，所以任何一个 shading point 投影到任何一个基函数上的结果都可以预计算——投影上去得到的是一个数；每个 shading point 只需要把前若干阶 SH 对应的那些数记下来。

* 到了实际运算：光照已经写成基函数下的系数，light transport 也预计算出一串数——对任何一个 shading point 算最后的 shading 值，逐个元素相乘再全部加起来，就是一个点乘：

    * $$L(o)=\rho\sum_i l_i\,T_i=\rho\;\vec l\cdot\vec T$$

* 前面埋的伏笔在此兑现：两个都用 SH 表述的函数做 product integral，落到运行时就是一个点乘。

* ```text
  PRT 的分工一览

    预计算（离线，时间当它无穷多）
        场景固定，光照不管
        light transport = V(ω) · (n·ω) · BRDF(ωo, ω)   ← 合起来是球面函数
              │ 对每个 shading point 投影到各阶 SH 基函数
              ▼
        每个点存一个向量 (t1, t2, …, tn)

    运行时（在线，每点一次）
        新光照 L(ω) 投影到 SH → 系数向量 (l1, l2, …, ln)
              ▼
        shading = ρ · Σ li × ti   ← 就是一个点乘
  ```

* light transport 预计算的另一种理解：$t_i$ 好比"用第 $i$ 个基函数所描述的环境光照去照亮这个物体"时，这个点上最后照出来的结果——相当于在 rendering equation 里把 $L$ 换成了基函数 $B$，对每一个这样的 basis、每一个 shading point 算一个最终照亮结果存下来。

### 代价账本

* 第一笔账（硬代价）：预计算 light transport 意味着 light transport 里面所有东西都定死了——cos 项是渲染方程自带的不用操心；visibility 定下来意味着任何一个 shading point 往四面八方看、被场景中其他东西挡住光的方式完全一样，这就意味着**场景不能动**：场景里那把椅子要是拿走就完蛋了，地面上势必有很多点的 visibility 球面函数要在某些地方发生变化。

* 第二笔账在 lighting 上，反而是好消息：光照写成基函数之后，两张不同的环境光贴图（一张室外、一张室内）各自预计算好，各自就对应一个系数向量（不同的 $l_i$）——那就可以换光源了，光源可以随便切换，只要这些光源都被预计算过。

* 同一种光照只是转个角度：光照这个二维函数已经写成基函数描述了，它一旋转就等于换了一种光源——但这个问题是可以处理的，靠的是 SH 的简单旋转性质（见下节）；预计算好的光照是允许旋转的，可以任意旋转光照，立刻得到物体上任何一个点 shading 结果的变化。

* 旋转光照不会影响 $V$ 项：$V$ 项是任意 shading point 往四面八方看某个方向是否被物体挡住，跟那个方向上具体是什么光照没关系——$L$ 和 $V$ 本来就是拆开的。

* 物理遮挡关系变了（比如物体形变）有没有办法解决：能——后续的 precomputation 研究里，真的有人在致力于解决物体形变之后怎么办。

### SH 的三个关键性质

* **正交性（orthogonality）**：一个基函数投影到另外任意一个基函数上得到零——$B_i$ 乘 $B_j$ 再做积分，结果等于 0，任何两个基函数都可以认为互相垂直（垂直就叫正交，两个说法一回事）；只有投影到它自己的时候结果才是 1。类比 $x,y,z$ 轴：$x$ 轴投影到 $x$ 轴是 1、投影到其他任何轴都是 0——所以说 SH 是一组正交基。

* **投影好算**：给你任何一个函数，把它投影到 SH 上，就是把这个函数和任何一个基函数做 product integral——一个积分换一个系数，完了。

* **简单旋转（simple rotation）**

    * 思路：一个函数（比如光照）投影到各基函数上得到一组系数；旋转原始函数，就相当于把对应的各个 SH 基函数都旋转同样的角度。

    * 任何一个 SH 基函数旋转之后，肯定就不再是基函数了（基函数是固定的，连朝向都是固定的），但它有一个非常好的性质：旋转后的函数一定可以用**同阶**的 SH 基函数的线性组合表示——把 $l=3, m=-1$ 那个基函数随便怎么转、朝向完全变掉，描述它的仍然是同一阶的那几个函数，只是组合系数变了。

    * 于是可以打一张表格：任意一个 SH 基函数怎么旋转、旋转后如何用同阶基函数线性组合，事先全部算好——"旋转整张环境光"这个难题就被变换成"改系数"，不必按老办法重新投影一遍、解一遍积分。

    * ```text
      旋转整个环境光 L
          = 旋转表示它的每一个 SH 基函数 B_i（都转同一角度）
          = 每个旋转后的 B_i 用同阶基函数的线性组合表示 ← 查事先算好的旋转表
          ⇒ 立刻得到新的系数组合：改系数就好
      ```

### 收益

* 快：任何一个 shading point 算最终结果只需要一个点乘，计算量太小——那个年代（2000 年刚出头、2002 年）靠预计算就能跑到几百帧每秒那种"恐怖的 FPS"，放到今天上千帧都不止。

* 高质量：以那个年代（2002 年前后）的标准，能拿到全局光照（环境光照）下的这种结果是非常好的。

* 阴影是白送的：算 light transport 的时候带上 visibility 项，自然而然就得到有阴影的结果（shadow 的实现就是考虑任何一个 shading point 的 visibility）；只考虑 shading、不带 visibility 项的版本得到的就是没有阴影的图——人们当然喜欢有 shadow 的。

* 间接光照也能引进来：预计算的时候，light transport 不仅可以考虑当前这一个 bounce 的光，还可以认为光可以 bounce 多次——在场景其他物体形状都不变的前提下，把光的多次 bounce 也当成一种 light transport 预计算下来，就等于把间接光照引进来了；效果上看有些阴影因为多次 bounce 的补光就不再那么明显，整个画面看起来非常自然。

* 本质一句话：把大量要花的时间放到渲染之前——花编译时间的开销，换运行时的效率。

### 适用边界与常见疑问

* 随时间变化的程序化纹理环境光（一直在变的光照），这套预计算的方法处理不了；天气系统（日出日落、晴天阴天）也许可以预计算一部分——游戏里目前也是预计算一部分，但不是这种把它完全都算进去的方式。

* 存储开销：既然预计算了，每个 shading point 肯定要存点东西——现在每点只需要存一个向量（light transport 形成的若干个数）：顶多取前五阶 SH，那就 25 个数，每个点存 25 个数完全可行；要是预计算的东西再多就麻烦了。

* 每个点的 visibility 球面函数怎么得到：最暴力的方法——从任意点往任意不同的方向 trace 光线，看是不是被挡住；这是预计算，这块时间可以当它无穷多。

* 环境光照和 GI 的关系：没关系——环境光照是直接光照，光线弹射一次，不管它来自哪个方向，弹到物体就被你看见了；PRT 把多次 bounce 预计算进来时才引入间接光照。

* RTRT 普及之后 PRT 会不会被淘汰：不会，反而会让 PRT 这一块有更多的表现；PRT 怎么和 ray tracing 结合是太大的研究问题。

* PRT 声称解决两个问题——visibility 已经考虑进来了，也支持不只 diffuse 的物体表面（任意 BRDF）；diffuse 情形因 BRDF 是常数而最简单，可以推到点乘封闭解，glossy 情形更复杂，其处理不在上述 diffuse 推导之内。
