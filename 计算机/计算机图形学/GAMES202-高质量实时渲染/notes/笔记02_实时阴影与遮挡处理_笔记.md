# 实时阴影与遮挡处理

## Shadow Mapping 两趟算法

   * **阴影映射（Shadow Mapping）**

       * > **定义**：完全在图像空间里运行的两趟（two-pass）算法——先把整个场景从光源位置渲染一遍、记录每个像素能看到的最浅深度，再从相机位置渲染一遍、逐点比较深度判断可见性。

       * Pass 1：站在 light 的位置看向场景，渲染一遍，每个像素只记录它能看到的「最浅（最近）深度」，结果写进一张纹理——这张纹理就是 Shadow Map；之后的所有 pass 都可以拿它来用。

       * Pass 2：站在 camera 的位置真正渲染整个场景，对每个着色点 p 比较「p 到 light 的实际距离」与 Shadow Map 里记录的最浅深度：两者一致 → light 看得见 p → 被照亮；记录值更浅 → 中间有东西挡着 → p 在阴影里。

       ```text
       Pass 1（站在 light 位置看向场景）
           渲染整个场景，每个像素只记录它能看到的最近深度
           写进一张纹理 —— 就是 Shadow Map
       Pass 2（站在 camera 位置看向场景）
           对每个着色点 p：比较「p 到 light 的实际距离」与 Shadow Map 记录的最浅深度
           一致 → 被照亮；记录更浅 → 中间有遮挡 → 在阴影里
       ```

       * 判断的直观版：场景点连向 light，若 Shadow Map 对应位置记录的最浅深度与该点到 light 的距离一致则可见；若这个方向上 light 先看到一个更浅的物体，则该点一定在阴影里。

       * OpenGL 实现要点：第一个 pass 真的放一个相机看向场景，渲染到某个 framebuffer、落到某个 texture 上，fragment shader 往 `gl_FragColor` 里写的只是这个像素对应的深度——生成 Shadow Map 不需要 shading 结果；第二个 pass 直接使用这张纹理。

       * 效果与价值：阴影带来位置感——有阴影就知道这些物体在哪，而不是悬浮的、跟背景没有任何关系的贴图感。

   * **图像空间算法（image space algorithm）**

       * > **定义**：Shadow Map 一旦生成，就相当于场景的一种几何表示——为了得到阴影只需要这张图，不需要实际的场景几何。

       * 历史地位：在离线渲染早期也是非常有用的生成阴影的方法——《玩具总动员》时代连光线追踪对离线渲染都开销太大，当时用的就是 shadow map（如 Pixar 的 RenderMan）；做实时渲染更是必须从这里起步。

       * 代价：方法自带两个问题——self-occlusion（自遮挡）与走样（锯齿）。

   * **深度比较的口径**

       * 透视投影可以理解成「先挤压成平行投影、再拍平」两步，挤压过程中所有的点都会被推向远平面——投影之后得到的 $z$ 并不是几何点到 light 的实际距离，这是两个不同的量。

       * 两种口径都可行：整条链路统一用投影（MVP）之后的 $z$ 值比较前后关系；或统一用真实线性距离——fragment 的位置与 light 的位置都知道，连线取长度即可，Shadow Map 上也记录实际距离。

       * > **易错点** ⚠️：用投影后的 $z$ 或用真实线性距离比较都没问题，但整条链路必须统一用同一种口径，混着用一定会出错。

## 自遮挡与补救方案

   * **自遮挡（self-occlusion）**

       * > **定义**：Shadow Map 有分辨率，每个像素记录一个常数深度，相当于把连续场景曲解成一系列深度恒定的小片；斜照时地面某点的真实深度比所在格记录的值略深一点点，被判成「有东西挡在前面」——地板挡住了旁边的地板。

       * 表现：地板上出现一圈一圈的纹路。

       * > **易错点**：这不是摩尔纹——纹路的产生不是由采样造成的，而是由数值精度造成的。

       * 规律：light 从上往下垂直照时，记录的深度与平面一致、没有夹角，问题最小；light 非常偏、几乎平行地照向地面（grazing angle）时最严重——夕阳时分阴影拉得最长正是高发时刻，《塞尔达传说：旷野之息》里都实测可见。

       * 这是所有使用 shadow mapping 的方法都会有的问题。

   * **深度偏差（bias）**

       * 做法：判断遮挡不再只要求「记录深度比实际深度小」，而要求它**明显**比实际深度小——这一小段容忍区间就是 bias，障碍物只要出现在区间里就不算遮挡。

       * bias 可以不是常数：根据光线与地面的夹角调整（判断两个方向的夹角用一个 cosine 即可）——光垂直打时区间可以非常小、更精确；light 与地板夹角很大时让区间更长。

       * 副作用：bias 调得过大会丢失原本可能造成遮挡的物体产生的阴影——本应连着的阴影断开，称为 detached shadow（不接触的阴影），工业界戏称「彼得潘」。

       * 工业现实：没有人真正试图百分之百解决这个问题；业界就是找一个合适的 bias，既没有自遮挡又不出现 detached shadow——因为这是最简单的方法。

   * **次深深度阴影映射（second-depth shadow mapping）**

       * 做法：每个像素不仅存最小深度，还存第二小（次小）深度，用两者的中间深度做后续的阴影比较——不再需要 bias。

       * 为什么能解决：一个紧贴遮挡物底面的平面，是与「最浅深度与次浅深度的中点」比较，中点与底面有明显深度差异，会被正确判为遮挡。

       * 前提：所有物体必须 watertight（水密）——模型是封闭实体，有正面就必须有反面；要描述一张纸，也得把它做成一个很薄的盒子。

       * 边界：地板不是 watertight 物体，这是严重问题；地板有特殊办法——记录它的次浅距离为无穷大即可。

       * 实现代价：fragment 按无序顺序输入，要始终保持最小与次小两个值，比较与 swap 都更多；时间复杂度仍是 $O(n)$，但实现里多出不少 if。

       * 结局：听起来非常美好，实际中没有人用。

| 补救思路 | 核心做法 | 代价 / 前提 | 实际境遇 |
| :--- | :--- | :--- | :--- |
| 加 bias | 记录深度要「明显」更浅才算遮挡；容差可随光线与平面夹角调整 | bias 过大丢失接触阴影（detached shadow） | 工业界普遍做法：调参找平衡，没人真正百分之百解决 |
| second-depth shadow mapping | 每像素存最小与次小深度，取中间值比较，不用 bias | 要求所有物体 watertight；维护两个深度的实现更麻烦 | 听起来很美，实际中没有人用 |

## 实时渲染的速度观

   * **速度优先原则**

       * > **定义**：实时渲染不相信复杂度，正如电子竞技不相信眼泪——它只相信绝对的速度；$O$ 级别相同不代表能接受，两倍的 $n$ 就比一倍的 $n$ 慢很多，常数同样要命。

       * 预算量级：按 30 fps 计，给某一种新效果（例如镜头光斑）分配的时间约一毫秒；超过一毫秒，这种方法再好也不能用——会严重拖慢帧率，只能忍痛割爱。

       * 推论：为了达到 real-time，每帧只有非常少的时间给各种效果，对复杂度级别与常数的要求都非常苛刻。

## 阴影走样与分辨率策略

   * **阴影走样（aliasing）**

       * 成因：Shadow Map 分辨率有限，对场景只是有限分辨率的表达；每个像素是一个常数深度的小片，分辨率不够时阴影边缘就出现锯齿。

       * 对策方向：给 Shadow Map 不同位置不同分辨率的 cascaded 方法、各种动态分辨率的 Shadow Map——都是比较高端的工业技术。

       * > **易错点**：CSM 这个缩写在工业界指 Cascaded Shadow Mapping；另有同名缩写 Convolutional Shadow Mapping，两者不是一回事。

       * 技术版图：Convolutional Shadow Mapping 用得甚至不如 Moment Shadow Mapping 多；对速度要求非常高的话用 VSM（Variance Shadow Mapping）可能更好一点、快一点；Convolutional 有自己的一些问题。

## 拆分近似与 visibility 拆分

   * **拆分近似（split sum）**

       * > **定义**：两个函数乘积的积分可以近似拆成两个积分的乘积再除以积分域的测度——实时渲染各子领域通用的近似等式，这种拆分方式在实时渲染里叫做 split sum。

       * 拆分公式：$$\int_{\Omega} f(x)g(x)dx \approx \frac{\int_{\Omega} f(x)dx \cdot \int_{\Omega} g(x)dx}{\int_{\Omega} dx}$$

       * 分母 $\int_{\Omega}dx$ 积的是「空的东西」，起归一化作用：实际使用中它是常数，但不管怎么样是要算的。

       * 能量不会凭空放大：取 $f(x)$ 为常值 2、一维区间 $[0,3]$，左边是 $2\int_0^3 g(x)dx$，右边 $(2\times3)/3\cdot\int_0^3 g(x)dx$ 与左边一模一样。

       * 它最大的作用：把「$f$ 与 $g$ 乘积再积分」这件事，先拆成「积分再乘积」。

       * 实时渲染的态度：不关心「不等」，关心**近似相等**——把微积分里的不等式（Schwarz、Minkowski、Jensen、Hölder、切比雪夫等）拿来当约等式使用，在一系列条件下认为可接受；实时渲染的背后仍然是离线渲染、真正的渲染基本知识。

   * **拆分成立的条件（满足其一即可）**

       * 条件一：$g$ 的 support 非常小——实际的积分范围很小（如 $g$ 长得像高斯，只在很小位置上非零）；support 可以粗略理解成积分限，但并不严格是一回事。

       * 条件二：$g$ 足够光滑——在积分域内 min 与 max 差别不大、比较低频、变化不大；这里的 smooth 不是「连续」意义上的光滑。

       * 两个条件不要求同时成立，满足任意一个近似就比较准；拿 NumPy 把「乘积的积分」与「积分的乘积」各算一遍对比即可自行验证。

   * **visibility 拆分：Shadow Mapping 的理论根基**

       * 把渲染方程中的 visibility 项 $V$（从着色点看光源有没有被挡住）单独拆出并归一化：$$\int_{\Omega} L_i(\omega_i)V(\omega_i)f_r(\omega_i,\omega_o)\cos\theta_i\,d\omega_i \approx \frac{\int_{\Omega} V(\omega_i)d\omega_i}{\int_{\Omega} d\omega_i}\cdot\int_{\Omega} L_i(\omega_i)f_r(\omega_i,\omega_o)\cos\theta_i\,d\omega_i$$

       * 含义：右边没有 visibility，就是 shading；左边就是 visibility——结果被拆成 shading 部分与 visibility 部分再相乘，这正是「先做 shading、再把 visibility 乘上去」的 Shadow Mapping 基本思路。

       * 点光源与方向光源：积分范围最小能小成一个点（delta），没有积分什么事，拆分是准确的——这就是硬阴影（Shadow Mapping）背后的理论基础。

       * 光滑条件对号入座：面光源内部 radiance 各处不变（积分域是面光源与 shading point 形成的立体角）→ 光照项 smooth；BRDF 是 diffuse → 变化非常小、smooth；面光源 + diffuse 时拆分结果准确。

       * 边界：面光源或环境光（可算超大的面光源）配上 glossy BRDF 不适合用 Shadow Mapping——glossy 有的地方接近 0、有的地方值特别大，不再 smooth。

       * 两个条件都不怎么具备时也可以强行这么用：环境光遮蔽（ambient occlusion，AO）用的仍是这个约等式；这个拆分也是通用做法，还可以拆出其它的项。

## 软阴影与半影

   * **软阴影（soft shadow）**

       * > **定义**：阴影边界上没有一条「从有阴影到没有阴影」的锐利界线，而是存在一段亮度渐变的过渡，人看起来自然。

       * 成因：人们日常生活中更喜欢、也更常遇到的是软阴影——现实中绝大多数光源都是面光源，而 Shadow Mapping 的点光源只能给硬阴影。

       * 结构：接收面上正对遮挡物的部分完全收不到光，是本影（umbra）；往外一圈光源「露出来一部分」、亮度渐变，是半影（penumbra）——在半影区域看光源是部分被遮挡、部分没被遮挡。

       * 太阳对地球是一个非常明显的面光源（无论如何有很大的大小），日食这类现象都可以用半影理论解释。

   * **半影宽度（penumbra width）**

       * > **定义**：光从面光源两端擦着遮挡物（blocker）边缘投下、在接收平面（receiver）上摊开的过渡带宽度 $w$；$w$ 一定程度上就表示阴影软的程度，也就是「此处该 filter 多大」。

       * 相似三角形关系：光源的大小比上半影宽度，等于光源到遮挡物的距离比上遮挡物到接收面的距离。

       ```text
       ●━━━━━ w_light ━━━━━●           ← 面光源（大小已知）
        ╲                  ╱
         ╲                ╱
       ───────████───────              ← blocker（遮挡物）
               ╲  ╱
                ╲╱
       ─────────────────────           ← receiver（接收平面）
         ├── w_penumbra ──┤            ← 半影宽度：该 filter 多大
       ```

       * 半影公式：$$w_{\text{penumbra}} = w_{\text{light}}\cdot\frac{d_{\text{receiver}}-d_{\text{blocker}}}{d_{\text{blocker}}}$$

       * 极端情况：blocker 是一个点、light 也是点光源 → 半影宽度为零，就是硬阴影；light 非常大 → 投影摊开的范围非常大 → 该 filter 得更大。

       * blocker 的位置：拿得非常近、更靠近接收平面 → 对过来的范围更小，阴影更硬；拿高、靠近光源远离接收物 → 底下投射出来的范围非常大 → 要 filter 得更大，阴影更软。

       * 现实修正：blocker 可能是一个球、一段有深度范围的东西（如笔杆），所以平常考虑的 blocker depth 指 average blocker depth——对一个 shading point，在一定范围内统计能挡住它的像素并取深度平均。

       * 距离直觉实例：钢笔写字的阴影——笔尖离它的阴影（纸面）非常近，那里非常锐利、很像硬阴影；笔杆离它投出的那块阴影远，就非常虚。

       * > **易错点**：这里的近和远是遮挡物（blocker）与阴影接收物（receiver）之间的距离，不是和光源的距离。

| 变化 | 半影宽度 $w$ | 阴影观感 |
| :--- | :--- | :--- |
| 光源越大 | 越大 | 越软 |
| blocker 越靠近接收面 | 越小 | 越硬 |
| blocker 越靠近光源（拿高） | 越大 | 越软 |

## PCF 的滤波本质

   * **Percentage Closer Filtering（PCF）**

       * > **定义**：对 shading point，不查它在 Shadow Map 上对应的那一个像素，而是取投影位置周围一圈像素（如 7×7；3×3 只为解释方便），把每个像素记录的深度与着色点深度比较（各得非 0 即 1），再把比较结果平均成 0 到 1 之间的 visibility。

       * 出身：最早研发出来并不是为了生成软阴影，而是为了做抗锯齿/反走样——处理阴影边缘的锯齿；后来人们发现它还能被用来生成软阴影。两个名字要分开：PCF 指这个滤波操作本身，PCSS 指用它来做软阴影。

       * 数学形式：$V(x)=\sum_{q\in N(p)} W(p,q)\,\chi(s_q-d(x))$，其中 $d(x)$ 是 shading point 自己的深度，$s_q$ 是 Shadow Map 上 q 位置记录的深度；$\chi$ 是阶跃函数，括号内大于零取 1、小于零取 0。

       * 判定方向：$s_q-d(x)>0$ 说明 q 处记录的表面比 x 离光源更远，x 前面没有东西挡它，可见性取 1；反之取 0。

       * 权重可以加权、不一定是一个 box（靠近 p 的贡献多一点、远离的少一点）；filter、加权平均、卷积（convolution）在这里不特别区分——卷积 $(W\ast f)(p)=\sum_{q\in N(p)} W(p,q)f(q)$ 做的就是加权平均。

       * 开销：一个 shading point 从查一次 texture 变成查 $7\times7=49$ 或 $9\times9=81$ 次，而且每个着色点都要这么计算——非常慢，但可行。

   * **PCF 滤波的对象**

       * 它 filter 的是「任意一个 shading point 做的很多次不同阴影比较的结果」——Shadow Map 原样不动。

       * 不是对最终渲染出的阴影图做模糊：那是在平均已经画好的 visibility（$\sum_{y\in N(x)} W(x,y)V(y)$）——先得到一个走样的结果再在结果上模糊一点用都没有，与反走样不能事后补救是同一个道理。

       * 不是先去 filter Shadow Map 再比较：把深度图糊了，物体边界一圈得到的是「背景与边界位置中间的某种平均深度」，毫无物理意义；拿这种平均深度做深度测试，结果仍是非 0 即 1，等于什么都没做。

       * > **易错点** ⚠️：三件事看着都像「模糊一下」，对象完全不同——PCF 平均的是逐 texel 深度比较的结果；模糊 Shadow Map 平均的是深度本身；图像空间滤波平均的是已经画出来的阴影图。只有第一种是 PCF。

   * **滤波大小决定阴影软硬**

       * filter size 为 1×1 等于什么都没做、一点抗锯齿都没做；取很大（9×9 甚至 17×17）锯齿没了，但阴影也糊了——filter 的区域大小直接决定阴影是硬还是软。

       * 由此得到的启发：软阴影可以理解成「硬阴影 + 一个非常大的 filter」——本来是一个要调的参数，偏偏有人发现取很大时可以用它近似软阴影的效果。

       * 软硬各处不同：阴影接收物到投射物的距离近（笔尖离它的阴影非常近）就该 filter 得小、非常硬；距离远（笔杆投出的那块）就软。

       * 结论：想做软阴影，应该给硬阴影各处不同位置不同大小的 filter——大小由 blocker distance（更准确的说法是一个相对的、平均的遮挡物深度）决定。

## PCSS 三步算法

   * **Percentage Closer Soft Shadows（PCSS）**

       * > **定义**：在 PCF 之前加两步准备——估计平均遮挡深度、按相似三角形算出该处 filter 大小——让阴影各处软硬随遮挡物距离自适应变化的软阴影算法。

       * 一句话总结：PCSS 的核心就是一个适应性的 filter size。

       * 地位：方法比较古老，但它确实是现在的 state-of-the-art——中间有各种各样的探索，但最终多数情况下大家还是用它来实现软阴影。

       * 前提：面光源原本是不可能生成 Shadow Map 的；实际做法是把 camera 放在光源中间、当作点光源生成 Shadow Map，用它模拟面光源的软阴影。

       * 适用边界：点光源和方向光源本身就应该产生硬阴影，不需要也不应该用 PCSS。

       * 动态场景：运动的物体没有影响——任何一帧 Shadow Map 与真正的阴影都是重新算的，跟物体运动没有关系。

   * **三步流程**

       * 第一步 Blocker search：shading point 连向光源，在 Shadow Map 上取一片区域，区域内能挡住该点的 texel 记为 blocker，把它们的深度取平均（不能遮挡它的像素不管，它们不是 blocker）——得到 average blocker depth。

       * 第二步：套相似三角形的半影公式，算出此处该 filter 多大——这一步只是算一下尺寸，几乎没有成本。

       * 第三步：按这个大小做 PCF——多次深度比较取平均，得到软阴影；与普通 PCF 已无区别。

       ```text
       Step 1  Blocker search
               在 Shadow Map 上取一片区域，能挡住该点的 texel 记为 blocker
               把它们的深度取平均 → average blocker depth
       Step 2  套相似三角形公式 → 此处该 filter 多大
       Step 3  按这个大小做 PCF：多次深度比较取平均 → 软阴影
       ```

   * **Blocker search 的范围（鸡生蛋问题）**

       * 困境：原本是为了决定「该 filter 多大」才要知道 average blocker depth；而找 blocker、求深度平均这一步本身就已经需要一个搜索范围。

       * 方案一：取某一个固定大小的范围（如 5×5）。

       * 方案二（更好）：利用光源的视锥——把 shading point 连向光源，看它在 Shadow Map 上覆盖多大区域，就在这个区域里找 blocker；light 非常远时，本来要找的 blocker 就在 shading point 与 light 形成的锥里，应该找比较小的范围；light 较近或本身较大时，应该在相对更大的范围内找。

   * **开销与工程现状**

       * 开销账：blocker search 要把区域内所有 texel 都考虑一遍，PCF 又要把（更大的）区域内所有 texel 再走一遍，访问纹理的次数非常恐怖——先接受「PCSS 慢但正确」，怎么变快由后续技术解决。

       * 稀疏采样：区域内随机取部分样本可以减少访问纹理的次数（结果是近似的），代价是噪声（noise）；工业界的正常方案就是两步都稀疏采样，再做一遍图像空间的降噪——空间上可以直接对图像做滤波，还可以通过时间的累积来做。

       * flicker：不同帧取的随机数不一样，每帧的噪声长得都不一样，用很快的速度连播就会感觉画面特别抖——这个问题确实会出现，有些游戏就是会闪。

       * boiling artifact：降噪相当于低通滤波，低频的噪声也能通过；把很多帧都滤波过去再直接播放，会产生「沸腾」现象——很多游戏现在还会出现这类问题。

       * 多光源：Shadow Mapping 只能一个一个处理——$N$ 个光源速度降到原来的 $1/N$，需要 $N$ 张 Shadow Map，每个 shading point 对每个 light 各做一次 shading；所以游戏里基本很少用很多光源，通常只保留一个非常主要的阴影，其余忽略不计。

       * 实例：Dying Light 的树影——树根离地面比较近，那里 filter 得少、阴影锐利；树叶高高挂起、算出的 blocker depth 大，投下的阴影 filter 得非常大、非常软——这也是 PCSS 会广泛应用在实时渲染里的一个理由。

## VSSM 方差软阴影映射

### 动机与思路

   * **Variance Soft Shadow Mapping（VSSM，也叫 VSM）**

       * > **定义**：用「区域内深度分布的均值 + 方差」近似整个分布、再以切比雪夫不等式一步求出可见性的快速软阴影方法——针对 PCSS 第 1、3 步都要全量采样的性能问题。

       * 痛点：PCSS 的 blocker search 与 PCF 两步都要在区域内把所有 texel 记录的深度拿出来比较——区域在 texture 上占 64×64，就得把 4096 个 texel 一个个看一遍，对大的滤波范围肯定慢。

   * **问题转化：把深度比较变成考试排名**

       * PCF 本质在问：区域里记录的这堆深度，比 $t$ 浅的占百分之几（这些是挡住 x 的遮挡物），比 $t$ 深的又占百分之几——把 $t$ 在这片深度分布里的「排位」问清楚，x 的可见性就定了。

       * 这像一场考试：知道自己考了多少分，想知道能排到百分之几——把所有「成绩」逐个看一遍正是 PCF 在做、也正是想避免的。

       * 用画得比较细的直方图可以按落段估排位；更进一步，把成绩分布近似成一条正态分布曲线也行——而正态分布只需要两个数：均值（决定中心在哪、尖在哪）与方差（决定有多胖多瘦）。

       * 问题于是变成：给 Shadow Map 上一块区域，能不能快速拿到这块区域里深度的均值和方差。

### 均值与方差的快速获取

   * **均值：区域平均查询（range average query）**

       * 给 Shadow Map 框出一块区域、立刻求平均深度——mipmap 或 SAT 都可以做到。

       * mipmap 快速但近似、层间要插值、只能做正方形区域；SAT 精确、支持任意矩形——不管通过什么方式，怎么算都行。

   * **方差：一张存深度平方的 Shadow Map**

       * 方差公式：$$\mathrm{Var}(X) = E(X^2) - E(X)^2$$

       * $E(X)$：对原 Shadow Map 做区域平均查询即可得到；$E(X^2)$：另外生成一张每个元素记录「深度平方」的 Shadow Map，对它做同样的区域平均查询。

       * 实现技巧：OpenGL 里一个 texture 有四个通道——红色通道写深度、绿色通道写深度的平方，不需要额外一张 texture，也不需要 multiple render target 那一系列东西；生成 Shadow Map 的同时顺手算平方，等于没什么额外的存储开销。

### 切比雪夫不等式与 CDF

   * **切比雪夫不等式（Chebyshev inequality）**

       * > **定义**：只凭一个分布的均值 $\mu$ 与方差 $\sigma^2$，就能给出「随机变量取值超过 $t$」的概率上界——不需要知道这个分布具体满足什么样的分布形状（背后隐含假设它是一个比较简单的单峰分布）。

       * 不等式形式：$$P(x>t) \le \frac{\sigma^2}{\sigma^2+(t-\mu)^2}$$

       * 注意用词：给的是「不会超过」的上界，不是等于；$t$ 变大，得出来的结果肯定变小——「超过 $t$ 的东西占百分之多少」在变小。

       * 苛刻条件：要查询的数 $t$ 必须落在均值的**右边**；$t$ 落在均值左边，这个公式就不准了——神奇的是明明只有这半边好用，人们平常就一直这么用，效果还可以。

       * 假设盘点：一、不需要知道分布具体长什么样；二、右边这块概率只是一个上界、不是真实的值；三、$t$ 必须在均值右边——即便在这么多限制条件下，人们还是用它，因为它太简单了，比打表简单太多。

   * **求 CDF 的两条路**

       * 直接路线：要的「有百分之多少的值小于 $t$」就是分布的 CDF（曲线下的面积；分布本身是 PDF）；对高斯 PDF 直接积分没有解析解，这个积分值叫误差函数（error function）——C++ 里有现成的 `erf` 函数给出数值解，打表也可以但要付出额外存储；有数值解不代表有解析解。

       * 切比雪夫路线：切比雪夫给的是 $t$ 右边那块面积，CDF（从最左边叠到 $t$ 左边的面积）就是一减右侧面积——不必知道分布是高斯的还是正态的，照样可以近似得到它的 CDF 值。

       * > **易错点**：VSSM 并没有用正态分布去估计，它用的是切比雪夫——前面拿正态分布说事只是为了方便理解，切比雪夫根本连正态分布这一步都不用经过。

### Blocker search 的统计解

   * **三个平均深度**

       * > **定义**：设 shading point 深度为 $t$——$z_{\text{occ}}$ 为遮挡物（深度 $<t$ 的 texel）的平均深度，待求；$z_{\text{unocc}}$ 为非遮挡物（深度 $>t$）的平均深度，不知道也不关心；$z_{\text{avg}}$ 为整块区域所有 texel 的平均深度，mipmap/SAT 范围查询直接得到。

       * 要区分的是「遮挡物的平均深度」与「整个块的平均深度」：只有深度小于 $t$ 的 texel 才是遮挡物，深度 8、9 一类的深值都不是——整块平均谁都查得到，难的是遮挡物这一类的平均。

   * **按比例加权恒等式**

       * 恒等式：$$\frac{N_1}{N}z_{\text{unocc}} + \frac{N_2}{N}z_{\text{occ}} = z_{\text{avg}}$$

       * 这是百分之百对的直观观察：区域内只有遮挡与非遮挡两种 texel，非遮挡占 $N_1/N$、遮挡占 $N_2/N$，两类的平均深度按占比加权合起来，肯定等于总平均。

       * 两个比例由切比雪夫给出：$N_1/N$（比 $t$ 大的 texel 占比）就是 $P(x>t)$；$N_2/N = 1 - N_1/N$——比如 30% 都不是遮挡物，另外 70% 肯定就是。

   * **大胆假设与求解**

       * 假设：$z_{\text{unocc}} \approx t$——把所有非遮挡物的深度都当成当前 shading point 的深度 $t$；这是不得已的假设，但问题不大，因为绝大多数阴影的接收物是平面。

       * 解出平均遮挡深度：$$z_{\text{occ}} = \frac{z_{\text{avg}} - \dfrac{N_1}{N}z_{\text{unocc}}}{N_2/N}$$

       * 中间没有任何循环——blocker search 就这么解决了；至此 PCSS 两个慢步骤全都消掉了。

       * > **易错点**：接收面是曲面、甚至只是跟光源不平行的时候，「非遮挡物深度都等于 $t$」的假设就已经会出问题，artifact 挺明显。

### 完整流程与开销

   * **VSSM 全景流程**

       * 准备：生成 depth map（shadow map）的同时把深度的平方值也写进去，理解成另外一张 shadow map；再为两张图准备 mipmap 或 SAT，支持所有范围的查询。

       * 使用：在 Shadow Map 上随便指一个范围，立刻 O(1) 查到 $E(z)$ 与 $E(z^2)$ → 倒腾出方差 → 结合 shading point 真实的深度 $t$ 代入切比雪夫 → $P(x>t)$ 就是未被遮挡的比例，即 visibility——比如有 30% 的 texel 能挡住这一点，可见性就是 0.7。

       * 全程没有任何采样、没有任何循环——PCF 这一步非常圆满地得到了解决。

       ```text
       Shadow Map（记录深度 z）       平方 Shadow Map（记录 z²）
             │ mipmap / SAT                 │ mipmap / SAT
             ▼ O(1) 范围查询                 ▼
           区域均值 E(z)                  区域均值 E(z²)
             └──────────────┬───────────────┘
                            ▼
             Var = E(z²) − E(z)²
                            ▼
             切比雪夫 P(x>t) ≈ σ²/(σ²+(t−μ)²)
                            ▼
             未被遮挡的比例 = visibility（无采样、无循环）
       ```

   * **更新的代价**

       * 场景中间有物体移动，mipmap 就一定要更新；没有物体移动、光源移动也一样；其他东西全都静止、只要每一帧是新生成的 Shadow Map，这些 mipmap 操作就一次都少不了——它本身还是有一定开销的。

       * 但给一张 texture 生成 mipmap 是 GPU 硬件支持得非常到位的事情，几乎可以认为不花时间；SAT 会慢一点。

### 失手场景与漏光

   * **分布假设失手**

       * 多峰分布：shading point 往光源方向看、视线正好穿过三片分开的薄片时，对应 texel 的深度会集中在三个明显的峰上——不可能拿一个高斯来描述它，这时候描述就不准了。

       * 两种错误方向：分布不准，百分比就算不准——把遮挡估多了结果偏黑（通常能忍：本来就是阴影，黑了就黑了）；把可见性估高了，本该全影的地方突然变白——这是非常严重的问题。

   * **漏光（light leaking）**

       * > **定义**：本该全影的地方 visibility 被高估、光像从阴影里渗过去的现象——VSSM 分布描述不准的典型恶果。

       * 典型场景：一辆非常镂空的车，车底明明有底板、光不可能直接照到，却突然白了一下——一部分 texel 的深度集中在底板附近，还有一些零零散散集中在车顶天窗附近，明显不是正态分布；强行拿正态分布硬套，肯定有的地方偏暗、有的地方偏亮，偏亮的地方就像 light 从阴影里渗过去了。

       * 术语辨析：工业界很多说法叫 light bleeding，但不建议这么用——容易跟全局光照里的 color bleeding 混淆；叫 light leaking（漏光）更形象。

   * **其余边界**

       * 接收物不是平面的话会出问题，阴影会出现明显的 artifact、断掉。

       * 切比雪夫不等式自己也有条件——查询的深度必须超过平均值它才准，这里也可能造成问题。

       * Moment Shadow Mapping 要解决的就是其中「分布描述得不准」这一个问题；非平面接收物那些事它不解决。

### 与 PCSS 的现实取舍

   * **现实取舍**

       * 现在实际操作中人们更多用 PCSS 来做阴影：对图像空间做降噪的手段越来越好（特别是空间和时间结合，归功于 TAA 一类 temporal 方法），人们对噪声的容忍度越来越高——先比较快地得出带噪声的结果，之后一定有办法把噪声干掉，这就是 PCSS 渐渐压过 VSSM 的原因。

       * 两者关系：VSSM 是 PCSS 的快速版本，但它不能反过来「替换」PCSS——PCSS 可以作为一个 baseline、可参考的标准。

       * VSSM 的优点依旧成立：确实可以做得非常非常快，而且没有任何噪声；中间涉及很多技巧，值得自己写一写。

## SAT 与前缀和

   * **区域和表（Summed Area Table，SAT）**

       * > **定义**：二维前缀和数据结构——每个元素表示「从左上角加到这个元素」的整个矩形内的值；任意轴对齐（不许旋转、横平竖直）矩形的和/平均，查表即可快速且百分之百精确地得到。

       * 抽象问题：给一张图，如何快速得到图上任何一块矩形的平均值——范围求和与范围求平均完全是一个概念：知道平均乘以元素个数就是总和，知道总和除以元素个数就是平均。

       * 来源：NVIDIA 的一个经典做法，就是引入了 SAT 这个概念。

   * **mipmap 为什么不够用**

       * mipmap 做的是快速的、**近似的**方形范围查询——即便就是正方形，它也不见得能百分之百精确。

       * 不准来源一：查询的正方形若不正好对齐到某一层的像素（往右下偏一点点），就得对周围四个值做插值——插值是猜出来的，不准。

       * 不准来源二：正方形边长不是 2 的幂（如 6）要落到「第 2 点几层」，层与层之间还要做一次三线性插值，更不准；长方形就更不好做了。

       * 体感：过滤范围比较小的情况下还可以，一旦大了会看到明显的 artifact；各向异性过滤能帮忙，但这里要的是百分之百准确的方式。

| 对比项 | mipmap | SAT |
| :--- | :--- | :--- |
| 查询精度 | 近似（靠插值猜） | 百分之百精确 |
| 支持的区域 | 方形，边长最好为 2 的幂 | 任意轴对齐矩形 |
| 生成开销 | GPU 硬件支持，几乎不花时间 | 有一定开销，写得不好会慢 |
| 过滤范围大时 | 明显 artifact | 依然精准 |

   * **一维：前缀和（prefix sum）**

       * > **定义**：预处理出每个位置上「原数组从最左边元素加到这个元素的和」，任意连续区间的和 = 区间右端的前缀和 − 区间起点前一位的前缀和。

       * 朴素做法是把这一段逐个加起来，复杂度 $O(N)$——范围给得非常大时不可接受；预处理花 $O(N)$ 时间（数组本来就要读一遍）+ $O(N)$ 额外空间，换来查询 $O(1)$。

       ```text
       数组片段：   [ … │ 3 │ 7 │ 1 │ … ]      ← 目标：第 4~6 项的和
       前缀和：     S(前3项) = 9       S(前6项) = 20
       第 4~6 项的和 = S(前6项) − S(前3项) = 20 − 9 = 11 = 3 + 7 + 1
       ```

   * **二维：容斥查询**

       * 任意轴对齐矩形的和用容斥原理四次查表得到，结果是**精准**的求和。

       * 关键：参与运算的四个矩形（整体大块、左长条、上长条、左上小格）起点都是左上角，全是 SAT 里现成的元素；左上小格被多减了一次要加回来——最简单的容斥原理。

       ```text
       把整张图按目标矩形的两条边切成四块：
       ┌──────────────┬────────────────┐
       │ ① 左上小格   │ ② 上边长条     │
       ├──────────────┼────────────────┤
       │ ③ 左边长条   │ ④ 目标矩形     │
       └──────────────┴────────────────┘
       S(④) = S(①+②+③+④) − S(①+②) − S(①+③) + S(①)
       ```

       * 构建：每一行就是一个一维数组，每一行都做一遍前缀和；做完之后每一个点表示「这一行从左加到当前点」的值，再竖着按列做一遍——横着 $O(mn)$、竖着还是 $O(mn)$。

       * 概念区分：SAT 是一个数据结构，它对应的算法叫前缀和算法（两个词混用无妨）。

   * **存储、精度与实际速度**

       * 存储：SAT 的存储跟原图的存储一模一样——原图存得下，SAT 就可以认为存得下，$O(N)$ 没问题。

       * 精度：累加总归会损失数值精度，问题确实存在，但不是特别大。

       * 实际速度：实时渲染不管是不是 $O(N)$，只管实际跑的是不是足够快——SAT 行与行之间没有任何关系、可以并行，GPU 的并行度远比行数高，但算法写得不好很可能还是会有点慢；可用 CUDA 实现（实测把 Shadow Map 纹理当成一块内存去算 SAT，写得出来但不算快）或 compute shader；NVIDIA 公开过直接写 SAT 的实践。

       * 每次生成 Shadow Map，肯定要重新算一遍 mipmap 或对应的 SAT，这肯定是要花时间的——所以这一步必须足够快；总体而言 SAT 本身还是有一定开销，不像 mipmap 几乎可以当成免费。

       * > **提示**：这是贯穿整门课的实用主义——不等式当约等式用，复杂度 Big-O 不重要，实际跑得快才重要。

## Moment Shadow Mapping

   * **矩阴影映射（Moment Shadow Mapping）**

       * > **定义**：用更高阶的矩（moments）——记录数值本身、平方、三次方、四次方……——去描述 Shadow Map 区域内的深度分布，把 VSSM 里「分布描述不准」这一步做得更准。

       * 与 VSSM 的关系：VSSM 其实就等于用了**前两阶**矩——$z$ 与 $z^2$，两个数一倒腾就倒腾出一个 variance；多记录几阶（三次方、四次方……），对这个分布的估计就更准。

       * 核心结论：保留前 $m$ 阶矩，就可以表示一个由一系列阶跃函数堆起来的函数，并且能表示 $m/2$ 个台阶——某种意义上等于一种展开（跟泰勒展开、傅里叶展开一个道理）：可能恢复不完整之前的函数，但至少能恢复出一个足够像的函数。

       * 阶数与效果：用前四阶矩描述出来的 CDF 是一条有两个台阶的光滑曲线，结果与 PCF 挺相似（PCF 本身就可以认为是挺准的，只是有一点噪声）；三阶矩算一个半台阶，比四阶差一些、比两阶好一些；只用到前两阶就是 variance shadow map，恢复出的 CDF 和实际分布的 CDF 就差了好多了。

       * 矩是不是越多越好：越多越准——我们要的就是**过拟合**出真实分布，越多越好；但确实不能无限多，每个像素要存 $z$、$z^2$、$z^3$、$z^4$……存储就往上涨。

       * 效果对比：VSSM 的 light leaking 非常严重，moment shadow map 里非常干净、完全不会有 light leaking；VSSM 能做的两步——blocker search 和 PCF——它都可以做。

       * 难点：给你前四阶矩，怎么得到那个有两个台阶的函数——这件事非常复杂，只能去读原论文（论文也写得比较难懂）——这是它实现起来确实麻烦的根源。

       * 现状：temporal filter 的方法越来越流行、把 PCSS 重新焕发升级之后，用 moment shadow mapping 的人渐渐就没有特别多了。

   * **存储 packing 技巧**

       * 做法：两个 32 位 float 的数，各自表示成半精度 float16，再把两个 float16 拼在一块、仍作为一个 float32 的 channel 去存——省一半存储；还有划分到具体多少位的更细做法。

       * > **易错点** ⚠️：pack 过的数据**不能插值**——两个 16 位数拼成的 32 位数，插值的时候把它当成一个 32 位的数去算，中间值就全乱了；pack 起来的数据做插值是没有意义的。
