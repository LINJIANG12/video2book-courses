# 实时光线追踪与前沿展望

## 实时光线追踪的硬件起点

* **实时光线追踪（real-time ray tracing，RTRT）**

    * > **定义**：用带专用求交硬件的 GPU，在每像素约 1 个样本的预算内跑 path tracing，再靠降噪把结果做到能看的实时渲染路线。

    * 工业界流传已久的悖论笑话：「Ray tracing is the future, and ever will be.」——光线追踪是未来，并且永远都是未来，言下之意是永远见不到它真正进入游戏；直到 2018 年 NVIDIA 推出 GeForce RTX（图灵 Turing 架构），实时光追硬件才第一次落地。

    * RTX 宣称打开 2500 亿（250 billion）量级的市场，重要应用包括设计与建筑设计的高效渲染预览（省时间、减轻 artist 负担），以及影视中达不到电影级画质的制作改用实时渲染、从而省掉庞大的 CPU 渲染农场。

* **RT core（光线追踪核心）**

    * 光线追踪本质是 traversal（遍历）：光线沿 BVH / k-d tree 从根到叶走一遍，判定与哪些节点内的三角形相交；这种树的遍历 GPU 做不好，NVIDIA 因此在显卡上加装专门做光线追踪的部件（与 tensor core 并列的 RT core），让每秒可 trace 的光线数量出现质的飞跃。

    * RTX 的本质是硬件能力对光线追踪的突破，算法层面并没有新东西——它就是一种让人能 trace 光线的硬件架构。

* **光线预算与 1spp（1 sample per pixel）**

    * 每秒可 trace 的光线量级为 10 giga rays（一百亿条/秒），但要依次除以分辨率（1K、2K 上来就是百万级像素）、帧率（如 30fps）、以及留给降噪、gameplay 等其他工作的时间：

$$10\,\text{giga rays/s} \div \text{pixels} \div \text{fps} \div \text{other work} \approx 1\,\text{spp}$$

    * 一路除下来，实际允许做的就是一个像素一个光路样本；从 1spp 到 2spp 是成倍提升（远比 100→101 重要），当时一代硬件（2080 Ti）做到 1spp，下一代（3080 Ti）能否 2spp 尚不确定——若有 2spp，结果立刻上一个档次。

* **一个光路样本 = 四条光线**

    * primary ray 打到 primary hit point，对光源采样并连 shadow ray 判遮挡，得到直接光照；在该点按蒙特卡洛采出一个方向打 secondary ray 到 secondary hit point，再连第二条 shadow ray，得到一次弹射的间接光照——四条光线构成最基本的一条光路，做全局光照缺一不可，bounce 越多光线越多。

```text
camera ──primary ray──→ primary hit point ──shadow ray──→ 光源
                               │                        （得到直接光照）
                               │
                               └──secondary ray──→ secondary hit point ──shadow ray──→ 光源
                                                                             （一次弹射的间接光照）

四条光线 = 一条最基本的光路 = 一个光路样本
```

    * > **定义**：1spp 的「一个样本」＝一条完整光路。工业技巧：对 primary ray 做 tracing 与光栅化完全等价且光栅化更快，把所有 primary ray 换成一趟 rasterization 后，每像素只剩 3 条光线（1 根 secondary + 2 根 shadow）。

* **RTX 在做什么、demo 为什么都闪**

    * RTX 展示的三类典型效果：软阴影、反射、全局光照；反射本质就是 glossy 的全局光照（光线至少两次弹射到达眼睛），可与 diffuse 全局光照（需要大量光线模拟）区分开。

    * demo 场景普遍 glossy 成分很重，原因有二：对 glossy/近镜面物体求反射光并直接 trace 最容易，是光追最自然的应用；在 diffuse 场景上，光追与不依赖光追的实时全局光照方法看不出巨大区别。

    * 标志性对比：电梯间头盔的反射里能看到摄像机背后的内容——screen space reflection 的信息全在屏幕上、做不到，光线追踪可以。

* **复杂材质的边界**

    * 皮肤、毛发等体积/散射材质依赖大量前置理论：辐射传输方程（radiative transfer equation，RTE，比渲染方程更复杂的散射介质光传播）、BSSRDF 次表面散射（模拟光线在 volumetric 介质内多次弹射）；实时渲染对它们的简化必须讲得非常深，因此整体移入离线渲染课程体系，届时涉及散射介质中的光线行进（如 delta tracking）与毛发 dual scattering 等技术。

## 降噪：问题定义与现有方案的失败

* **降噪是唯一的核心技术**

    * path tracing 是蒙特卡洛积分，样本越多噪声越小；1spp 的噪声极其夸张（离线作业里 64spp 的结果都基本不能看）。RTRT 相比离线 path tracing 在算法上只有简化、没有新算法，突破全在硬件——让 1spp 结果能看的，核心技术就只有降噪（denoising）；state of the art 的降噪可以把基本没法看的输入变得与结果天壤之别。

    * 降噪与 DLSS 没有直接关系：DLSS 是把低分辨率图拉大到高分辨率图；两者可以协同运作、互相提高，背后原理有一定相关性。

* **降噪器的两个硬指标**

    * 质量：不能 over blur（滤波盒过大、把有用信息连同噪声一起滤掉、糊成一片），不能有 artifact（渲染中产生的不想要的可见瑕疵）；不过度模糊即保住细节。

    * 速度：降噪只是渲染流程的一小部分，预算绝不可能是 30ms（否则光降噪就锁死帧率）；量级是几毫秒——5ms 尚可，理想是小于 2ms 甚至 1ms。

    * > **易错点** ⚠️：1spp 输入 + 高质量 + 几毫秒，直觉上「绝对不可能」；工业界恰恰让这件不可能变成了可能。

* **现成降噪方法为何都不行**

| 路线 | 代表 | 为什么不行 |
| :--- | :--- | :--- |
| 切片滤波系列 | sheared filtering 系列（最快为 fast sheared filtering） | 理论复杂：牵涉采样、重建与高维傅里叶变换；无 RTX 的机器上简单场景约 10 FPS |
| 离线降噪 | 迪士尼的一系列 filter 方法 | 面向电影，通常支持几百 spp；滤波一幅图以分钟计 |
| 深度学习 | CNN、NVIDIA 的 recurrent autoencoder（RAE） | 推理要几十到几百毫秒；RAE 最快约 50ms，还需再快十倍 |
| 引擎自带 | NVIDIA OptiX API 自带降噪器 | 简化版：只滤当前帧、没做时间滤波；点击到降噪结束的延迟肉眼可感（即几十到几百毫秒级） |

    * 工业界的答案依赖三个最重要的想法：temporal、temporal、还是 temporal——时间复用是整套方案的根基。

## G-buffer：渲染顺手拿到的屏幕空间信息

* **G-buffer（geometry buffer，几何缓冲区）**

    * > **定义**：光栅化（替代 primary ray）打到物体的过程中顺带生成的、每像素一份的辅助信息；需要什么存什么，是老概念换的新名字。

    * 可存内容：深度、法线、世界坐标（用 RGB 三通道分别存 x/y/z）、漫反射系数 kd、直接光照结果、object id（每个物体一个编号颜色）等；多通道、按需生成。

    * 生成成本「for free」并非百分之百，但非常轻量，通常只相当于额外多截几张图。

    * 关键性质：G-buffer 完全没有噪声——以 normal 为例，一趟光栅化即可取得，与多次 bounce 无关；这使它能反过来指导带噪声的颜色滤波。

    * 本质是屏幕空间信息：只记录 camera 看得到的东西，屏幕之外无信息——这是 temporal 复用一系列问题的根源。

* **G-buffer 绝对不能反走样**

    * 深度图边缘有锯齿没关系：锯齿上每个像素表示的就是该像素中心对应的深度，意义明确；一旦做反走样把边缘抹成过渡，边缘像素就变成「介于前景与背景之间的深度」，完全不合理——normal 在边缘做混合同理。

    * 对 G-buffer 做任何 anti-aliasing，它的意义就完全没了——一定要让它走样，这样才是对的。

## Temporal 累积与 Motion Vector

* **时间复用的递归思想**

    * 滤波当前帧时，永远认为前一帧已经滤波好了——当前帧滤完就变成下一轮的「前一帧」，假设自洽；再假设场景运动非常连续、帧间无突变（突变按异常另行处理）。

    * 有了对应关系，就能把上一帧已降噪的颜色复用到当前帧：当前帧噪声多没关系，对应点在上一帧是 denoise 过的——相当于用上一帧的知识指导这一帧的结果。

    * > **易错点**：时间复用不是 1spp→2spp 的线性累加——上一帧也用了再上一帧的结果，各帧贡献以指数衰减的权重叠加进来，等效 spp 远比 2 高（具体数值没人真正推过）。

    * 找到对应后可直接使用上一帧最终渲染的结果——它已是干净、稠密的图，无需关心其内部经历了多少 pass；path tracing 之后的降噪操作基本都是图像空间操作（path space 上做降噪的研究存在，但又难又费、效果未必更好）。

* **motion vector（运动向量，工业界常缩写 motion vec）**

    * > **定义**：记录当前帧每个像素上的内容在上一帧的对应位置，建立帧间的一一对应。

    * 精确提法：要找的是「上一帧的哪一个像素，能看到当前帧这个像素里看到的那个点」——找的不是像素坐标本身，而是像素里内容（场景中点的世界坐标）在上一帧的投影位置。

* **back projection（反向投影）**

    * 链路三段：当前像素 → 当前帧世界坐标 → 上一帧世界坐标 → 上一帧像素。

    * 世界坐标优先直接从 G-buffer 取（专门生成一张每像素存命中点世界坐标的图）；没有也可逆推：先做逆视口变换，再倒序应用 MVP 的逆（先 $P^{-1}$、再 $V^{-1}$、最后 $M^{-1}$）。

    * 矩阵必须按 4×4 齐次坐标处理；输入必须带深度 $z$——视口变换只作用于 $x$、$y$，深度原样传递（没有世界坐标图时，深度图也可拿来逆推）。

    * 物体从上一帧到这一帧的运动记作变换 $T$：渲染方掌控每一帧之间物体怎么动、把 $T$ 存下来即可，用逆变换 $T^{-1}$ 退回上一帧世界坐标。

```text
当前帧像素 x（必须带着深度 z）
    │  E⁻¹   逆视口变换（只动 x、y，z 原样带着）
    ▼
    │  P⁻¹ → V⁻¹ → M⁻¹   （MVP 的逆，倒着应用）
    ▼
当前帧的世界坐标 X
    │  T⁻¹   物体"上一帧 → 这一帧"运动的逆变换
    ▼
上一帧的世界坐标 X′
    │  M′ → V′ → P′   （上一帧的正向 MVP）
    ▼
    │  E′   上一帧的视口变换（最容易漏的一步）
    ▼
上一帧像素 x′   ←←← motion vector 指向的位置
```

$$x' \;=\; E'\,P'\,V'\,M'\;T^{-1}\;M^{-1}V^{-1}P^{-1}E^{-1}\;x$$

    * > **提示**：链路两头都是视口变换、最容易漏——逆着走先做 $E^{-1}$，正向投影最后补 $E'$；中间正逆变换若有互相抵消的冗余，只会让计算更简单，原理不变。

* **与光流（optical flow）的对比**

    * 计算机视觉里跨时间找像素对应叫光流；motion vector 本质也是一种光流。

    * 区别在可靠性：光流基于两帧图像内容反推对应，要跑一整套 inference 框架、慢且不保证准；motion vector 是精确算法——渲染过程全在掌控中、矩阵清清楚楚，实测质量和速度都赶不上 motion vector。

* **两帧的线性混合**

    * 记号：头上打波浪线（$\tilde{C}$）表示未滤波、噪声多；打横线（$\bar{C}$）表示已滤波。当前帧噪声图先做一遍当前帧自己的空间降噪得 $\bar{C}_i$，再与上一帧对应像素（认定永远已降噪、带杠）做线性 blending：

$$\bar{C}_i \;=\; \alpha\,\bar{C}_i \;+\; (1-\alpha)\,\bar{C}_{i-1}(\bar{x}')$$

    * $\alpha$ 平常取 0.1~0.2，乘在当前帧结果上——最终融合结果里当前帧只占 10%~20%，80%~90% 的值来自上一帧，非常大胆地依赖历史信息。

    * > **易错点**：$\alpha$ 表示当前帧的贡献，千万别弄反——$\alpha=0.1$ 意味着主要信上一帧，而不是主要信当前帧。

    * 两帧之间光照改变厉害时，不能再依靠上一帧——这是 temporal 失效问题的入口。

* **滤波不改变亮度**

    * 所有降噪、滤波都保证能量守恒，绝不可能、也不应该让有噪声的图变亮或变暗。

    * path tracing 是无偏（unbiased）的：每个像素的期望都是正确结果，噪声应在真值上下浮动，整图不该偏暗。

    * 看起来变暗的真相：噪声图里有很多超过 1（超过显示器 255 上限）的极亮噪点，显示器把超界部分 clamp 掉，能量被砍、整图显暗；在一台真正的 HDR（High Dynamic Range）显示器上看同一张噪声图，就不会觉得它比降噪结果暗。

* **与 ground truth 的差距**

    * 降噪质量对照 1k spp 以上的收敛结果评估；主要损失在细小结构——contact hardening / contact shadow 这类细小接触阴影会被滤波糊掉，很正常；1spp 前提下该质量已可接受。

* **temporal 与 TAA 几乎是同一件事**

    * 时间抗锯齿（temporal anti-aliasing，TAA）与这套 temporal 复用几乎等同：都是复用上一帧对应位置的信息、无形中提高每像素采样数（一像素采四下远好于采一下）；一切利用上下帧对应信息的思路本质相同。

    * 尽管有种种失效，工业界照用不误：实际游戏中的极端情形较少，clamp 后的一点噪声可由更强的空间滤波盖住（稍糊但看不出来）；学术界则在研究降低 temporal failure 的可能性。

## Temporal 失效场景与补救

* **三类失效场景**

| 失灵场景 | 典型例子 | 根子在哪 |
| :--- | :--- | :--- |
| 场景 / 光照巨变 | 切换场景、蹦迪换灯、电影式切镜头 | 上一帧的信息已过时、不再可信 |
| 屏幕之外没有信息 | 相机后退，边缘不断出现新物体 | G-buffer 只覆盖屏幕内，图像之外搞不定 |
| Disocclusion | 物体挪开，露出原本被挡住的背景 | 被挡住的点，上一帧根本没有存 |

    * 光照突变：上一帧绿灯、这一帧红灯，camera 与人物都没动、对应找得到，但搬来的是绿色的旧光照——这一帧就被染绿；这类情况永远会发生。

    * 切镜头同样严重：电影式「谁说话镜头切到谁」的特写切换，帧间几乎无连续性可用。

    * 巨变后需要一段时间重新积累，这段预热时间叫 burning period（概念借自 Metropolis light transport）；切换场景更是完全没有历史信息可用，必然 failure。

    * 屏幕外新内容：刚进入屏幕的点在上一帧找不到对应（它当时还在屏幕外、motion vector 算出来指向屏幕外）；归因于 screen space——图像之外搞不定。

    * disocclusion（去遮挡）：物体挪开露出背景，motion vector 会指向「它背后那个点」，但上一帧该位置被遮挡、根本没有存——本质仍是 screen space 问题；把上一帧拆成不同深度的多层来补救，开销非常大，工业界几乎没人实际这么做。

* **强行复用的下场：拖影**

    * 明知对应错了还照用（上一帧权重至少 80%，常见 90% 甚至 95%），旧颜色整块搬来——画面既显示这一帧又叠着上一帧的东西，即 lagging / ghosting（拖尾、残影），不做处理时非常严重。

### Clamping：把上一帧拉近当前帧

* **clamping（钳制）**

    * 思路：应用上一帧值 $\bar{C}_{i-1}(\bar{x}')$ 之前，先把它拉到接近当前帧的结果（当前帧有噪声），再做线性混合——黄色箱子先被拉向白色拱门的方向、变得相似后再混合，就看不出问题。

    * 做法：对当前帧每点取一个小邻域（如暴力取 7×7），统计均值与方差，把上一帧对应值 clamp 到 $\mu \pm k\sigma$（$k$ 取 1、2、3 都可以）；以此压一压噪声造成的影响。

    * > **易错点** ⚠️：clamp 方向是「上一帧 → 当前帧」——用当前帧邻域的统计量收拢上一帧的值；反方向把当前帧拉到上一帧，ghosting 只会更严重。

### Detection 与 α 调整

* **detection：object id 验明正身**

    * 另渲染一张 object id 图（每个物体自己的颜色/编号）；motion vector 找到的上一帧位置若属于不同物体（0 号拱门找到 6 号箱子），判定「这根本不可能对」、该处 temporal 信息不可用。

    * 学术界有若干检测 temporal 失效位置的方法；关键是：只要检测到对应不可用，就有应对手段。

* **调整 α 的代价：噪声回来了**

    * 失效处可把 α 调成非零即一（完全不信上一帧、全信当前帧），或按 temporal failure 程度连续调整。

    * 代价：更信当前帧等于重新引入噪声；也可以反过来加强当前帧空间滤波（更糊但无噪声）——仍是 trade-off，有时问题不大、有时挺大。

    * 实验现象：做了 clamp 消灭拖影后，扫过的区域出现噪点——原本的拖影位置被替换成了噪声。

### 几何没动、Shading 动了

* **motion vector 追踪几何，追不了 shading**

    * 一类 temporal 问题与几何无关：几何没动所以 motion vector 说「没动」没有错，但 shading 变化剧烈，传统 motion vector 就搞不定。

    * 光源移动的栅栏场景：几何与相机全静止，任意像素 motion vector 严格为零，于是永远复用上一帧的阴影——严重阴影拖尾，引出 detached shadow（影子与光源脱节）；光源移动越快越明显。弃用 temporal 阴影则当前帧噪声非常明显；clamp / 检测后依旧 more noisy——同一代价。

    * glossy 反射滞后：地板不动、其上物体移动旋转，地板各点 motion vector 为零，反射影像要花一点时间才跟上物体的运动——打 FPS 游戏要出事。

* **时域 clamp 的标准写法**

    * 记号：无标记的 $c$ 表示已做 temporal 累积的 noise free 结果，$\bar{c}$ 表示本帧空间滤波结果；上一帧结果 $c_{i-1}$ 天然 noise free。对本帧 $\bar{c}_i$ 的每点取小邻域（如 7×7）统计 $\mu$、$\sigma$，超出 $\mu \pm k\sigma$ 的 $c_{i-1}$ 先拉回有效范围再混合：

$$c_i=\mathrm{Blend}\Big(\mathrm{Clamp}\big(c_{i-1},\ \mu(\bar{c}_i)\pm k\,\sigma(\bar{c}_i)\big),\ \bar{c}_i\Big)$$

```text
上一帧 noise-free 结果 c[i-1]
        |
        |  超出本帧邻域的 mu ± k·sigma 统计范围
        v
把 c[i-1] clamp 进本帧 7x7 邻域的有效范围
        |
        v
与本帧空域滤波结果 c_bar[i] 做 blend  ===>  本帧 noise-free 结果 c[i]
```

    * 邻域跨出图像边缘时有效样本变少（左上角的 7×7 实际只覆盖右下 4×4），影响不大。

    * 效果示例：白色拱门前找到黄色箱子的错误对应，clamp 后颜色被拽向本帧统计范围（接近白色），过一两帧错误就消失。

    * 本质是拿噪声换不留残影：上一帧本来 noise free，clamp 向当前帧就重新引入噪声——在 lagging / ghosting 与 noise 之间权衡；通常人们更不愿要残影，有 noise 还可再加大空间滤波，把 noise 换成 over blur（过度模糊）。

    * 整套 RTRT 流水线做的就是在 lagging / ghosting、noise、over blur 三者之间相互权衡——没有哪一步是免费的，每处理掉一种坏事都是把它换成另一种坏事；clamp 是 trick，不是解决思路。

* **学术界的推进与边界**

    * 《Temporally Reliable Motion Vectors》（发表于 Eurographics，EG）：在传统 motion vector 概念上提出能追踪阴影、反射、遮挡变化的新 motion vector，可部分缓解残影与噪声问题。

    * 边界：只要还依赖图像空间（相机后退看不到墙外、切换场景无历史），就不可能完全解决；针对性研究 RTRT motion vector 的文章长期仅此一篇。

## 空间滤波：高斯、双边与联合双边

* **空间滤波在做什么**

    * 在当前帧图像上滤波＝一种模糊操作，把 1spp 噪声图变成干净图；目标是低通滤波——保留低频信息、去掉高频噪声。

    * 两个隐藏问题：高频里也可能有信号，一刀切会把信号一起切没；噪声不一定高频，低频噪声也存在（帧间来回抖动的 boiling artifacts 就是低频噪声的表现）。

    * 滤波核（kernel）＝窗口 + 权重：对每个像素取周围范围、（加权）平均；窗口形状加各位置权重定义滤波器（box、Gaussian……）；核也不必然低通（提取图像边界的核专门取高频信息）；核可以每像素一样，也可以每像素不一样。

### 高斯滤波的正确写法

```text
for 每个像素 i:
    sum_of_weights         = 0    # 权的和
    sum_of_weighted_values = 0    # 加权后的值的和
    for i 周围窗口内的每个像素 j:
        w_ij = kernel(i, j)       # 由 |i - j| 查高斯得到权重，sigma 控制核的宽窄
        sum_of_weighted_values += w_ij * color(j)
        sum_of_weights        += w_ij
    filtered(i) = sum_of_weighted_values / sum_of_weights
```

$$\bar{C}_i=\frac{\sum_{j} w_{ij}\,\tilde{C}_j}{\sum_{j} w_{ij}}$$

* **两本账的实现要点**

    * 最后的除法是归一化：高斯核本身不必归一化（任意倍数缩放都行），「先累加、最后相除」保证滤波过程自动归一化、整图能量不变——box 核（$w_{ij}\equiv 1$）验证：恰好是算术平均，不亮不暗。

    * 该结构与渲染积分里拆出 visibility 项完全同构——分子是权乘值求和、分母是权自己求和：$\dfrac{\int V(x)\,w(x)\,\mathrm{d}x}{\int w(x)\,\mathrm{d}x}\Longleftrightarrow\dfrac{\sum_i w_i V_i}{\sum_i w_i}$，对任何核都不必操心其自身归不归一化。

    * 高斯核理论无限大，实际在 $\mu\pm 3\sigma$ 处截断，每像素只看半径约 $3\sigma$ 窗口内的邻居。

    * > **易错点**：除法之前必须检查权重和是否为零——高斯核至少有像素贡献自己、不可能为零；换成别的核就可能没有任何像素能贡献，结果按零处理。

    * 颜色是多通道的：RGB 各自累加进 sum_of_weighted_values，权重是单通道，相除后结果仍是多通道颜色。

### 双边滤波

$$w(i,j,k,l)=\exp\!\left(-\frac{(i-k)^2+(j-l)^2}{2\sigma_d^2}\right)\cdot\exp\!\left(-\frac{\big\|f(i,j)-f(k,l)\big\|^2}{2\sigma_r^2}\right)$$

* **bilateral filtering（双边滤波）**

    * > **定义**：在高斯空间距离核之外再乘一颗「颜色差异核」——两像素颜色差得越大，贡献被压得越低；模糊可以，边界别动。

    * 出发点观察：把人感知上的「边界」翻译成可计算判据——某处颜色变化非常剧烈，那里就是图像的边界（边界一定是高频信息，普通高斯会把它一起抹掉）。

    * 公式中 $(i,j)$、$(k,l)$ 是两个像素的二维坐标（与「中心 $i$/邻居 $j$」不是一套记号）：第一颗高斯管空间距离（$\sigma_d$），第二颗高斯作用在像素值之差上（$\sigma_r$）。

    * 效果：水面、天空滤得干净，山体细节（高频）被抹成大色块，所有边界依旧锐利。

    * > **注意**：降噪场景下这个判据会失灵——两点颜色差得多，可能正好跨在边界两侧，也可能只是噪声程度不同（一黑一白），双边滤波分不清噪声和边界；对噪声本来不严重的图（要处理的主要是细节）效果不错，严重噪声场景的解法在 SVGF 的方差项。

### 联合双边滤波

* **joint bilateral filtering（联合双边滤波，又称 cross bilateral filtering）**

    * > **定义**：双边滤波的泛化——用更多 feature（深度、法线、颜色、世界坐标、object id……）共同指导滤波，每种「距离」各配一颗衰减函数，差异大就压低贡献。

    * 特别适合对付蒙特卡洛路径追踪产生的噪声；代价只是滤波核里多算几组贡献、连乘起来，不费什么事；好处多、坏处不明显，因此用得非常普遍。

    * 用 G-buffer 当尺子是渲染者独有的优势：几何信息零噪声，比用带噪声的颜色自身指导可靠得多；object id 还能检测 motion vector 是否找错了物体。

    * 三把尺子各管一段：

| 点对 | 情形 | 出手的尺子 |
| :--- | :--- | :--- |
| a–b | 空间挨得不远不近，但一个面深一个面浅 | 深度 |
| b–c | 深度几乎一样，法线夹角接近 90° | 法线 |
| d–e | 阴影内外，颜色深浅悬殊 | 颜色 |

    * 深度项：$w_z=\exp\!\left(-\dfrac{(z_a-z_b)^2}{2\sigma_z^2}\right)$，深度差越大贡献越小——浅面与深面本来就不该互相掺和；法线项可用两向量点乘（cos 值本身随夹角衰减，天然是一颗核）；颜色项（传统高斯）能保住阴影边界不被糊掉——但噪声下用颜色判断不稳妥（坑由 SVGF 填）。

    * 核不必是高斯：唯一要求是随「距离」衰减（对距离取绝对值保证对称、套一个指数衰减即可）；用高斯也不必严格照抄教科书写法——归一化系数 $1/(\sqrt{2\pi}\,\sigma)$ 可整个去掉、$2\sigma^2$ 写成 $\sigma^2$ 也没问题，形状对了就行。

    * 各标准同时生效、不是二选一：每种距离各带各的 $\sigma$，几颗高斯连乘（常合写进同一个指数里，本质是几颗指数函数相乘）。

    * $\sigma$ 实践靠调，但每项可放宽：空间核可一开始就取巨大（64×64 甚至 128×128）；颜色范围 0~1，$\sigma_{\text{color}}=0.1$ 已算很大（差不多覆盖 0.5、0.6 的宽度）——每颗高斯都稍宽、单项不严格，合起来效果就不错。

    * > **注意**：作为尺子的 color 指最终渲染出来的噪声图的像素颜色，不是 albedo；albedo 本身也可以拿来当另一个独立的指导项。用什么 metric 各家不同，基本思想不变：把很多重要概念放在一起考虑。

## 大滤波器的两种实现

* **问题与被否决的 FFT**

    * 联合双边滤波允许每个 metric 松一点，滤波范围因此可以非常大（128×128 级别）；但逐像素算 n×n 邻域，n 小（7×7、9×9）没事，n 一大（如 64×64）滤波就特别慢。

    * FFT 路线（图变到频域 → 简单乘法 → 逆 FFT）理论可行，但 GPU 上 FFT 优化得并不好、非常慢，不采用。

### 拆分实现（separable）

* **先横一趟、再竖一趟**

    * 把 n×n 滤波拆成两趟：先水平 1×n、再在其结果上竖直 n×1，最后效果如同对每点做了一次完整 n×n 模糊；纹理访问从 $n^2$ 降到 $2n$（64² = 4096 → 64 + 64 = 128，降一个数量级还不止）。

    * 原理：二维 axis aligned 高斯本来就定义为 x 方向一维高斯乘 y 方向一维高斯，$G(x,y)=G_x(x)G_y(y)$，二重卷积可拆成先 x 后 y 两次一维卷积（内层积分时与 y 相关的项整体提出）；可以扁、可以长，但定义后旋转过的斜高斯不行。

    * 边界情况：双边滤波（两颗高斯相乘）起就拆不开 x、y，联合双边滤波（还有深度、法线点积项）更拆不开——理论上不能这么拆；但实际可以硬拆：只要 filter 不是特别大，横竖两趟基本没问题，32×32 拆成 1×32 + 32×1 看不出 artifact，再大可能出问题。

### à-trous 逐步增大的滤波

* **à-trous wavelet**

    * > **定义**：多趟滤波，每趟核大小固定 5×5，第 $i$ 趟（$i$ 从 0 开始数）样本间隔为 $2^i$；不是有些像素不处理——每一趟、每一个像素都要算，只是周围 5×5 个样本之间的距离在变大。

    * 五趟中的第 5 趟（$i=4$、间隔 16）5 个样本跨 64 像素，本质上做的就是 64×64 的滤波；代价每趟固定 25 次访存、五趟共 125 次，对比真做 64×64 的 4096 次。

    * 为什么必须从小到大：小 filter 去掉的是很高的频率，大 filter 开始要去更低的频率；逐趟增大相当于把整个频段分段处理、每一段针对性去除——上来就用大范围（直接做间隔 16 的第五层）不行，高频还没去掉，跳采样会造成大量频谱重复。

    * 为什么后面的趟敢跳采样：采样在频域做的事情是频谱复制平铺，采样稀疏则频谱拷贝间距小、会混叠（aliasing）。上一趟滤波已把所能表示的最高频率限制住，下一趟的采样间隔经过设计——搬移间隔正好是上一趟留下来的最高频率的两倍，频谱拷贝一张挨一张、恰好不混叠。

    * 实际问题：联合双边滤波有选择地保留高频（如边缘），上一趟滤波并不干净，跳采样的假设被破坏——经常出现格子状的 artifact；对策是在之后再做一趟小的滤波收拾干净。

    * 多趟 pass 的存储：用两个 buffer 来回倒（噪声图 A 滤完存 B，B 当输入滤完写回 A），不必为每趟单独开存储。

```text
一维示意（o 为本趟取的样本，- 为被跳过的像素，每趟都是 5 个点）

i=0（间隔 1）   ooooo
i=1（间隔 2）   o-o-o-o-o
i=2（间隔 4）   o---o---o---o---o
i=4（间隔 16）  o---------------o---------------o---------------o---------------o
```

* **两种实现对比**

| | 拆分实现（separable） | à-trous 逐步增大 |
| :--- | :--- | :--- |
| 适用对象 | 二维高斯严格可拆；双边、联合双边不太大可硬拆 | 想要多大的滤波范围都可以 |
| 每像素访问次数 | $n^2$ 降到 $2n$ | 每趟固定 25 次，总共趟数 × 25 |
| 主要注意点 | 32×32 以内基本看不出 artifact，再大可能出问题 | 滤波不干净时出格子状 artifact，结尾补一趟小滤波 |

* **空域滤波的迁移应用**

    * PCSS 的工业实现：每像素只采 shadow map 上少量点、先出结果，再滤波抹平。

    * 屏幕空间 tracing：每点只往周围打很少的光线产出 noisy 结果，再走一趟滤波——工业界基本范式：先产出 noisy 结果，再用空域、时域等降噪技术把噪声降下来。

## 离群点去除

* **outlier（离群点；rendering 里叫 firefly，萤火虫）**

    * > **定义**：蒙特卡洛渲染中偶然出现的超级亮像素——绝大多数像素颜色都属主流的某个样子，突然出现一个超级亮的，就是 outlier。

    * 与数字图像处理的椒盐噪声（salt and pepper）不同：椒盐噪声顶多顶到 255、最低按到 0；蒙特卡洛的颜色值不一定有上限、可以远超 1（HDR），所以会有超级亮的点。

    * 危害：7×7 小滤波会把一个亮点摊成更大的亮块——值确实降了但仍可能超过 1，结果还是 noisy 或出现 blocky artifacts，亮点被摊得更开、更难看。

* **时机与诚实的代价**

    * outlier removal 必须在滤波之前做，处理完再滤波，图里就没有特别亮的点了。

    * 理论上要得到百分之百准确的结果绝不该做 removal——应该等更多 sample 让 variance 真正降下去；但为了快速出图（尤其 RTRT）等不起，这是实时的取舍，能量确实少了一点。

* **检测与处理**

    * 对每个像素取小邻域（工业界正常处理用 7×7，5×5 也行，连 separable 都不用、直接扫），统计颜色的均值 μ 和方差 $\sigma^2$（有人用中位数代替均值，各种 heuristic 自行设计）；直接扫一遍就都算出来了，不需要 variance shadow mapping 那类复杂估计。

    * 有效范围 $$[\mu-k\sigma,\ \mu+k\sigma]$$，$k$ 取 1~3 都有，是权衡、没有定数；超出范围（太亮或太暗，一个道理）判为 outlier。

    * > **易错点** ⚠️：outlier removal 并不删除像素——真删除是让贡献变成零，实际是把超界值 clamp 回有效范围（例 μ=0、σ=0.1、k=1 时范围 [-0.1, 0.1]：10 → 0.1，-0.3 → -0.1）；「removal」只是叫法，别被它带偏。

    * 工业实现（TAA）更复杂：在某种颜色空间上做，范围可能不用简单区间、而用整个 3D 颜色空间上的高斯来描述；基本思想不变——单像素说不清颜色范围，靠周围一块区域的统计分布来检测并 clamp。

* **两个麻烦场景**

    * 场景里很小的光源会被当 outlier 干掉：对策是先渲染一个没有这个光源的场景去做 removal、滤波，最后再把光源装回去。

    * 像素恰在物体交界的几何边缘：邻域统计混合了两个物体的颜色、分布找不准——没有一定解决的完美解法，只能靠聪明的特殊处理。

## SVGF：时空方差引导滤波

* **SVGF（Spatio-Temporal Variance Guided Filtering，时空方差引导滤波）**

    * > **定义**：在 spatial-temporal 降噪框架上，用深度、法线、颜色（连同方差）三种因素指导滤波的实时光追降噪方案。

    * 名字梗：开头的 S 是 spatial + temporal 两个词捏在一起，按理应叫 STVGF；相比基础框架多两点——若干实现 trick，以及整张图每个像素同时记录 variance（方差）。

    * 经典三分对比：1spp 输入 → 滤波结果 → 1024 spp 渲到基本收敛的参考真值，SVGF 结果与参考图非常接近。

### 深度项：切平面上的深度差

$$w_z(p, q) = \exp\left(-\frac{\left|z_p - z_q\right|}{\sigma_z \cdot \left|\nabla z(p) \cdot (p - q)\right| + \varepsilon}\right)$$

* **逐块拆解**

    * 不是高斯（指数上那个变量没有平方），但只要是指数衰减的形状就可以；$\sigma_z$ 控制衰减快慢（深度影响的大小）。

    * $\varepsilon$（$10^{-6}$ 量级）防除零：$p$、$q$ 是同一个点时分母严格为零，而滤波本来就要遍历 $p$ 周围所有的 $q$，这种情况必然出现；不补会数值爆炸。

    * 分母里的深度梯度 $\nabla z$ 是关键：梯度乘以两点距离 = 按该面倾斜程度预期会发生的深度变化。侧向的面（斜对相机的斜面上颜色相近的 A、B 两点）实际深度差很大，但预期变化也大、分母大，同样的深度差一除衰减就不狠；正对相机的面梯度近乎零，分母基本只剩 $\varepsilon$，任何真实深度差都被老老实实罚下去——判别力没丢。

    * 结论：通常不直接用两点的深度差异，而用它们沿着所在面法线投影出来的深度差异——即切平面上的深度差。

### 法线项：点乘加指数

$$w_n(p, q) = \max\left(0,\; n_p \cdot n_q\right)^{\sigma_n}$$

* **逐块拆解**

    * 两个法线直接点乘：完全相同结果为 1，互相垂直乃至更远为 0（先 clamp 掉负值），中间平滑过渡；外面指数 $\sigma_n$ 控制衰减快慢、决定判定法线差异严不严格——与 Blinn-Phong 反射模型用指数控制 specular 高光大小完全一个道理；同样不要求是高斯。

    * > **注意**：场景用了法线贴图时，判断要只用没被法线贴图扰动之前的 normal——看起来平的墙因凹凸贴图各处法线不同，用扰动后的 normal 会把本来该滤到一起的同一平面像素拆散。插值出来的 shading normal 完全可以用，唯一的红线是别用被法线贴图改变过的 normal。

### 颜色项：方差决定信不信颜色差

$$w_l(p, q) = \exp\left(-\frac{\left|l_p - l_q\right|}{\sigma_l \cdot \sqrt{\mathrm{Var}_p} + \varepsilon}\right)$$

* **逐块拆解**

    * 朴素做法：RGB 转灰度叫 luminance（只是个名字，就当颜色），两点颜色差大就当靠近边界、不互混；但噪声会干扰——阴影里的点恰好被噪声抬亮，一比较就「该混的不混、不该混的混」。

    * SVGF 的办法：看两点颜色差异的同时掂量它可不可信——颜色差异除以中心点的标准差，中心点自己 variance 大（噪得厉害）就不太相信它与邻居的颜色差异。

    * 用标准差（方差开根）而不是方差：标准差和颜色值本身单位相同、直接可比；$\sigma_l$ 控制衰减速度，$\varepsilon$ 还是那个防除零的老朋友。

    * 为什么 7×7 之后还要 3×3、不直接上来一个大 kernel：通常习惯就是先做一次 spatial、再做一次 temporal、还不保险再补一次小的 spatial（大小随意）；真约束是想立刻、尽快把 variance 拿到手，不希望它自己还要过一遍非常大的 filter——那本身就挺慢。

    * > **注意** ⚠️：拿去降噪的输入必须是 HDR 的，不能先截断到 $[0,1]$——那样降噪出来的结果肯定要变暗。用 luminance 与 HDR 有关系；直接在 RGB 空间算两点距离或简单平均也都可以。

```text
中心点 p 的 variance 从哪来

 1. spatial ：取当前帧 p 周围 7×7 的区域，
    在这个区域里算出 variance
 2. temporal：用 motion vector 找上一帧的对应点，
    把 variance 也随时间平均下来
    ——跟颜色信息的 temporal 累积一模一样
 3. 用之前还不放心：再取 3×3 的小邻域做一次平均，
    让估计更平滑、更可信
 4. 开根号，换算成标准差，供颜色项使用
```

### SVGF 的脾气与失败案例

* **效果与脾气**

    * 效果：教室、走廊（人往里走、旋转视角）、San Miguel 经典测试场景都非常好；间接光照照亮的墙角多少露点怯（本来就困难）；over-blur 与 noise 有时被场景里的高频纹理、复杂几何掩盖，画面显得比实际好。

    * 脾气：手里有 variance，倾向于用 over-blur 解决 noise——在噪声与过度模糊之间一定选过度模糊，更不愿意留下噪声；有时画面看着特别干净，其实是被抹平了。

    * 改进版 A-SVGF：更精准地判断 temporal 上的不连续，不让 over-blur 那么厉害，并解决阴影之类在 temporal 上变化时的滞后、残影——代价是不再选 over-blur、会留下更多 noise，同一个 tradeoff 站到另一头。

* **boiling artifacts 与阴影残影**

    * boiling artifacts：filter 得很大之后画面仍可能在帧与帧之间来回抖——噪声并不只有高频，留下来的低频噪声逐帧产生的效果就像沸腾的水。

    * 实打实的失败案例：场景完全静止、只有光源移动（墙上影子移动），motion vector 严格为零，当前帧直接用上一帧的阴影——阴影残影、拖影，非常明显；这是 SVGF 的实打实不足。

## RAE：循环自编码器降噪

* **RAE（Recurrent Auto Encoder，循环自编码器）**

    * > **定义**：用带 recurrent 连接的 U 型神经网络，对蒙特卡洛路径追踪得到的图像做 reconstruction（即对 RTRT 做滤波、post processing 后期处理）的降噪网络。

    * 输入：当前帧 noisy 的图 + 渲染时拿到的 G-buffer 信息；输出：一张干净的图。全程不用 motion vector、也不给历史帧——temporal 累积由网络结构自动完成。

* **结构与机制**

    * auto encoder 是漏斗形：输入先被若干层压得非常小（这个小东西叫 latent），再不断展开成更大的、在过程中做要做的操作；画出来像 U 字，所以也叫 U 型神经网络，比较适合做图像上的操作；通常做成对称、最左最右之间连类似 skip / residual connection 的连接，方便训练。

    * 关键设计：每层神经网络是类似 convolution block 的东西，但带 recurrent 连接——每一层不止连向下一层，还要连回它自己。

```text
noisy image + G-buffer
        |
        v
[Block] -> [Block] -> latent -> [Block] -> [Block] -> clean image
   (o)       (o)                  (o)       (o)

(o) = recurrent self-loop：每一块除连向下一层外，还连回自己
```

    * 对一段图像序列连着跑：跑完一帧后信息留在网络里、每层又输给它自己——跑下一帧时上一帧的信息已在网络里，相当于上一帧给下一帧一个初始状态，temporal 累积自动发生；跑若干次之后更早的帧自然被忘掉。

    * 训练要求：不能单张进单张出，得用连续的帧序列喂网络（渲染整个场景自然能得到连续帧，不是问题）。

    * 找谁当对应是网络自己学出来、自己决定的，内部发生了什么不知道——因此根本不存在「屏幕外新内容找不到对应」的问题。

* **效果与毛病**

    * 优点：输出的图 noise 非常少。

    * 毛病一：几何边缘残影——旋转摄像机、几何在动时，在真实物体边缘旁边留下一条斜着的影子（网络不完美，没学会这里不该有残影）。

    * 毛病二：整个场景大量 over-blur——随便看哪棵植物基本都被明显糊掉。

    * 毛病三：整体偏暗——实时渲染里做得暗就意味着试图用暗遮掩问题；同场景 SVGF 展示的亮度更高、说明它更「自信」，RAE 亮度一提上去 over-blur、残影到处可见。

* **SVGF 与 RAE 对比**

| 维度 | SVGF | RAE |
| :--- | :--- | :--- |
| 质量 | 更干净，效果更好 | 尚可，但整体偏暗 |
| Artifact | 阴影残影；大 filter 之后仍有帧间抖动（boiling） | 几何边缘残影；大面积 over-blur |
| 性能 | 基于 temporal 累积，算 motion vector、累积都非常快 | 每帧过一遍网络，当时约 50ms 起步 |
| 可解释性 | 每一步发生了什么非常清楚 | 网络学到了什么，不知道 |

    * 结论：SVGF 的效果要比 RAE 好。

    * RAE 的独特优势：在不同 spp 的输入下 performance 固定——过一遍网络的代价与输入多少 spp 无关；SVGF 若渲染 16 spp，计算量明显增加很多。

    * NVIDIA 的简化应用：把 RAE 里的 recurrent block 拿掉、仍用 auto encoder 结构，放进光线追踪 API OptiX 内置为神经网络降噪器；在稍高 spp 下 work 得非常好，但它降噪的是单张图、没有 recurrent 时序。

    * RAE 当时没实用价值的另一半原因：还没有 Tensor Core，网络 inference 慢（约 50ms）；现在同样结构约 10ms——还是有点慢但在接近可用；NVIDIA 一直希望搞出好的神经网络降噪器，不久的将来应该能做成。

    * 发表趣事：SVGF 中了 HPG（High Performance Graphics），RAE 中了 SIGGRAPH——学术界导向不完全看工业实用度（RAE 当时对 RTRT 可以说一点实用价值没有），神经网络工作比较好中稿。

## 抗锯齿方法族

### TAA

* **TAA（temporal anti-aliasing，时间抗锯齿）**

    * temporal 思路的起点：最早不是为降噪而生、而是为解决 anti-aliasing——先有了 TAA 的巨大成功，才有它在 RTRT 里的应用。

    * 走样根源：一个像素里样本数量不足（只在像素中心采一个点势必要走样）；终极方案是每像素更多样本（MSAA 的思路）。

    * TAA 的路：仍要用更多 sample，但样本从上一帧、上上一帧复用——当前帧仍只用 1 spp（这里的 s 是 sample、一个样本一个点，不再是 pass），靠 temporal reuse 无形提高 spp；与 RTRT 里用 temporal 信息是一模一样的思路。

* **jittered sampling（抖动采样）**

    * 静止场景的复用方法：把像素内部划成网格，每一帧把采样点放在不同位置——如 4×4 网格、采样点四帧轮换一个角（左上→右上→右下→左下），sampling pattern 在时间上分布各不相同。

    * 复用是递归的：上一帧又用了上一帧……场景静止时等于把之前所有帧的样本结果做了平均——效果就好像当前帧做了一次 2×2 的 supersampling（4 个样本）。

    * 采样位置用固定 pattern 而不是随机生成：随机会在 temporal 里引入额外的高频信息；规定好一些较好的样本，每四帧完全相同、也不容易出现分布不均匀。

```text
一个像素内部划成 4×4 的抖动网格

   第1帧      第2帧      第3帧      第4帧
   # . . .    . . . #    . . . .    . . . .
   . . . .    . . . .    . . . .    . . . .
   . . . .    . . . .    . . . #    . . . .
   . . . .    . . . .    . . . .    # . . .
   (左上)      (右上)      (右下)      (左下)

   采样点每帧换一个角，四帧一轮回
```

* **运动场景与失效处理**

    * 场景运动时：当前像素打到的几何在上一帧的哪个像素里——用 motion vector 找到上一帧所在像素、用上一帧的结果，完完全全用 temporal 信息。

    * temporal 信息不可用时：还是用 clamp 那一套——与 RTRT 降噪几乎完全一样的一套思路。

### SSAA 与 MSAA

* **SSAA（super sampling AA，超采样抗锯齿）**

    * 做法：把场景按几倍分辨率先渲染、再降采样，相当于把几个像素捏成一个；思路基本上百分之百直观正确，但严格掉帧率——长宽各乘 2 就是严格四倍计算开销（4× MSAA 不见得把帧率掉到四分之一，SSAA 是真的会）。

* **MSAA（multi-sample AA，多重采样抗锯齿）**

    * 在 SSAA 基础上做小近似、把效率提上去，最重要就两件事。

    * 其一，对同一个 primitive（三角形）上的所有样本只做一次 shading：像素里 4 颗感知样本分属 2 个三角形时只 shade 2 次（SSAA 无论如何要 4 次）；为此 MSAA 内部维护一张表，记录每颗感知点的颜色和深度，用来求出一个平均的 shading 位置（不一定是正中心、可取某种代表位置）。

    * 其二，空间上的 sample reuse（不是时间上）：相邻像素之间复用样本——两个相邻像素共放 6 颗点、中间 2 颗恰骑在公共边上，被两个像素同时算作自己的贡献，近似相当于 8 颗。

    * 游戏里「渲染百分比」选项（100%/120%/200%）就是 SSAA：按更高分辨率渲染再压回原大小，效果非常好但代价严重，慎用；倾向 100% 正常渲染、有 MSAA 就打开。

### SMAA

* **SMAA（Enhanced Subpixel Morphological AA）**

    * 图像空间抗锯齿的当代主流；族谱：最早 FXAA（Fast Approximate AA）→ 升级版 MLAA（Morphological AA）→ 再提升的 SMAA，全是先渲染出有锯齿的图、再用图像方法把锯齿替换掉；别与 MSAA 搞混。

    * 做法（以 MLAA 为例）：取图像一小块，通过各种匹配方法识别「这里本应是一条斜直线边界」；分辨率受限没法直接显示无限精度的边界，就按边界在每个像素内的占比（覆盖率）把像素按比例填成亮暗混合。

    * 本质是矢量化：把像素描述的图提取成类似无限分辨率的边界、转换成矢量表示，再按覆盖率回填，且必须跑得非常快。

    * 速度：处理 720p~1080p 的图大约只要 1ms；正常打游戏有此选项时可以不开 MSAA、开 SMAA 效果就挺好。

## 超分辨率：DLSS 两代思路

* **super resolution（超分辨率）与 super sampling 是一回事**

    * 目的很字面：提高图像分辨率——给一张低分辨率的图、变成高分辨率的图；NVIDIA 的 DLSS 做的就是 super sampling，也是 temporal super resolution 的代表。

* **DLSS 1.0：纯靠猜**

    * 困境：信息来源什么都没有，只有当前帧低分辨率图，又不许糊——等于全靠猜（out of nowhere）。

    * 做法：给每一个游戏、甚至每个场景单独训练一个神经网络，数据驱动地学常见物体边缘，争取把小图拉大后模糊的边缘换成不模糊的边缘；效果不是特别好。

* **DLSS 2.0：temporal 信息的更严格用法**

    * 核心思想：应用 TAA 这一套，更多地用上一帧的信息填到当前帧——当前帧只给一张低分辨率小图，剩下的差距靠时间上的积累来补；分辨率提升不拿帧率换。

    * 关键约束：一旦发生 temporal failure，绝对不可以再用 clamping——按周围颜色「猜」出来的小像素值很像周围的点，得到的是一张很糊的「高分辨率」图。

    * 根源：DLSS 真正提升了分辨率，复用上一帧信息时额外背上「分辨率增加了」这个巨大负担——必须要求补出来的新像素值和之前的信息有本质上的不同，否则就糊掉；TAA 没这回事（分辨率不变，上一帧结果直接混合进当前像素即可）。

    * DLSS 2.0 的关键就一句话：找到一个更好地复用 temporal 信息的方案——综合当前帧采样信号与上一帧找回的历史样本，逼近真实的（未知的）信号曲线。

    * 网络做的事情非常妙：不输出任何混合之后的颜色，而是告诉你「关于上一帧所找到的 temporal 信息应该怎么用」。

```text
当前帧样本：· · · · ·          （自己的采样点，值已知）
上一帧样本：· · · · · · · ·    （靠 temporal 信息找回的历史样本）
     |
     v
网络不输出混合后的颜色，
只输出"上一帧的信息该怎么用"
     |
     v
输出结果：· · · · · · · · · ·   （采样密度更高，逼近真实的信号）
```

* **效果与开销**

    * 对比 540p→1080p：bicubic（双三次）插值的图糊在哪最明显看树叶；同样 540p 到 1080p 用 DLSS 的 temporal 方案，树叶清晰、树上纹理都在，有时比原生 1080p 效果还好——1080p 相对 540p 是 4 倍样本，temporal 复用的有效样本若比它还多，结果就可能超过原生。

    * 核心工程问题：训练出网络之后如何提升 inference（推理）性能——若 DLSS 每帧自己要跑 30ms 就绝对没人用；NVIDIA 针对自家硬件做了优化，具体怎么做连合作伙伴也无从得知（最高机密）。

    * 友商：AMD 的对应产品叫 FidelityFX Super Resolution（FSR），一回事；学术界 Facebook 也山寨过一篇 DLSS 式论文，解决方案更像 DLSS 1.0、基本不怎么 work，工业界完全不是这么用的。

    * > **提示**：判断「新驱动让效果翻倍」类宣传——硬件能力已被充分发挥时，软件侧再提升非常有限；某版驱动真能提升 50% 以上，宁可相信是上一版驱动写挂了、完全没发挥出硬件性能。

    * DLSS 与降噪：暂时没听说 DLSS 在做降噪；但随着神经网络 inference 越来越快，它很可能能够取代 SVGF——不一定永远「还是用 SVGF」。

## 延迟渲染

* **deferred shading（延迟渲染）**

    * > **定义**：把 shading 延迟到第二趟——第一趟只写深度（depth prepass，得到一层「深度壳」），第二趟只给深度等于最浅值的可见 fragment 着色；被 shading 的 fragment 数量降到可见 fragment 的数量。

    * 前向管线的问题：三角形打散成 fragment、过深度测试就要 shading；若三角形按从远到近进入流水线，每个 fragment 都会通过深度测试、全都要 shading——一般情况控制不了三角形送进流水线的顺序；最惨的情况复杂度是 $O(N_{\text{frag}} \times N_{\text{light}})$：有多少 fragment 乘多少 light。

    * 观察：很多 fragment 中间某个时刻过了深度测试、最后却被其他 fragment 覆盖看不到，对它们 shading 是纯浪费（深度测试本质是不断更新自己的深度缓存）。

```text
前向渲染：三角形 ──> fragment ──> 深度测试 ──(通过)──> shading ──> 像素
                  （随后被覆盖的 fragment 也做了 shading —— 白算）

延迟渲染（光栅化两遍）：
  第一遍  三角形 ──> fragment ──> 只更新深度缓冲   （得到一层"深度壳"，不着色）
  第二遍  三角形 ──> fragment ──> 深度==最浅才通过 ──> shading ──> 像素
                                  （通过者必定可见，一次都不白算）
```

    * 隐含假设（事实上成立）：把浪费掉的 fragment 拿去做 shading 开销非常大，而把整个场景再光栅化一遍开销非常小。

    * > **易错点** ⚠️：两趟都做不了多重采样式 AA——第一趟依赖深度缓冲、它就是 G-buffer，不能被 AA；第二趟要逐像素比对深度，同样不能有 AA。延迟管线的 AA 一律交给 TAA（与上一帧结合）或图像空间的后处理 AA。

    * AA 难题被解决后，deferred shading 基本成为了工业化的标准。

## Tiled 与 Clustered 着色

* **tiled shading（分块着色）**

    * 建立在 deferred shading 基础上：把屏幕切成小块（每块大概 32×32，数值随意），每个小块单独做 shading；核心收益是节省每个小块要考虑的光源数量——每块对应场景中一段 3D 区域，不是所有光源都影响它，逐块判定与哪些光源相交即可。

    * 光源可以圈出影响范围的依据：light sampling 中面积到立体角的转换带来按距离平方的衰减 $E \propto 1/r^2$，贡献随距离衰减到足够小就截断——每个光源的覆盖范围可以认为是一个球形。

    * 效果量级：能影响到每块的光源数量平均远远小于所有光源——从至少十几个的量级降到平均差不多 4 个左右。

* **clustered shading（分簇着色）**

    * 在 tile 基础上不止分屏幕块，还要沿深度切片——等于把 3D 空间拆成一个网格；长条覆盖的深度范围非常大，与长条相交的光源未必与其中切细的小格相交。

    * 切细之后平均每个小格里有影响的光源数量更少：大部分格子要么 1、要么 0，超过 1 的都不多，平均下来大约 1 上下的水平；实现起来越来越麻烦。

    * 格子之间不存在前后遮挡问题：格子（如 32×32 的区域）比像素大得多，一个球的边界和它的背景完全可以同时出现在一个格子里，前景背景共存很常见。

    * deferred → tiled → clustered 回答的是同一个问题：如何避免没有意义的 shading；非常聪明，但本身很简单。

## 级联：换了个名字的 LOD

* **cascaded（级联）= level of detail（LOD，细节层次）**

    * 本质就是「在不同情况下选择不同层级去用」的 LOD 思路换了个名字，没有任何神奇的地方；mipmap 就是 LOD 的原型——高层级细节少、但能很快算出区域平均，计算中选对 level 即可，免得一直进最精细的 level。

* **级联 shadow map**

    * 依据：shadow map 上一个 texel 离镜头比较近时覆盖屏幕上较大的区域、离相机远时覆盖范围非常小——离 camera 越远的地方，越可以用粗糙的 shadow map。

    * 实际很难生成一张「变分辨率」的 shadow map，做法是生成两种或更多分辨率相同、覆盖范围不同的 shadow map：近区用高分辨率小覆盖（格子细），远区用同分辨率大覆盖（相当于格子更粗），按看到的物体在场景中的位置选用哪张。

```text
级联 shadow map：分辨率相同，覆盖范围越大，格子越粗

  camera ──> [ 近区：高分辨率，格子细 ]----[ 远区：覆盖更大，格子粗 ]
                        └── 重叠带：按距离混合（偏近偏精细，偏远偏粗糙）──┘
```

* **级联 LPV**

    * LPV（light propagation，光传播）从已经照亮的点——虚拟的光源——出发往外 propagate；越往外传播越可以放粗：近处精细格子，传播远了换粗一点的格子、再远更粗。

    * 省的是传播路径穿过的格子数——一条线穿过多少格子，计算量就约等于多少。

* **层间过渡是真正的难点**

    * 突然切换层级会有明显的突变 artifact（用得好好的 shadow map 突然换成另一张）；对策：让两层重叠一部分，重叠带内按距离 blending——更偏近主要用精细层、更偏远主要用粗糙层。

    * 代价：重叠区域得算两遍，计算量稍微多一点。

    * 不管级联 shadow map 还是级联 LPV，最大的问题都是 transition（从一层转到另一层一定会出问题）；级联没有任何科学上的新东西，是实现上非常好的优化思路——level of detail 很好用。

## 几何 LOD 与 Nanite

* **geometric LOD（几何细节层次）**

    * 精细模型叫高模、模型简化后三角形数变少的叫低模；生成一系列层级，按 camera 离物体的远近来选择放什么模型进去。

    * 更聪明的用法：同一个物体不同部分用不同 LOD（一部分用更大更粗的三角形、另一部分用更小的）；可定义标准如「任何时候三角形都不要超过一个像素的大小」，据此动态告诉渲染管线要渲染哪个精细度级别、物体的哪一部分。

    * 突变 artifact：camera 推近是渐变过程，中途突然换成低模，几何看起来突然变化——popping artifacts。

    * popping 可以完全交给 TAA 处理：TAA 本质是复用上一帧的东西、起 temporal blending 的平滑作用——真的这么容易。

* **Nanite（虚幻引擎 5 的海量几何系统）**

    * > **定义**：一套动态选取 level of detail 的几何渲染做法——对于任何一个像素，选取这个像素覆盖的物体应该有的那个层级。

    * 实现形态：Epic 自己写的一套相当于光栅化的管线，自己决定在哪一层、什么地方用什么样的三角形；连 compute shader 这类高级 shader 都没用——可戏称「硬件软光栅」（CPU 上自己写光栅化叫软光栅，GPU 硬件自带的理论上才叫硬光栅）。

    * 引擎的本质：一个超级强大的实现、大杂烩，把各种算法集合进去——背后的科学性相对简单，难在具体技术。

* **三大实现难点**

    * 接缝：物体不同部位用不同层级、不同像素用不同层级几何，如何保证接得上而不产生缝——几何领域早有「不同简化层级在相邻区域无缝」的学术工作支撑，可以做到。

    * 动态加载与调度：不可能把所有层级（billion 级三角形）全存进 GPU——那样用不好 cache 与硬件吞吐；动态地加载和调度不同层级是非常现实的问题，有对应研究（类比虚拟纹理：对理论上无限大的纹理做调度；几何需要类似的调度，毕竟 GPU 容量非常有限）。

    * 几何表示：Nanite 用三角形网格；曾被猜测用几何纹理（geometry image）——那是另一种几何表示，好处是做 geometry LOD 更简单（在纹理上做 level of detail 就好），三角形网格上做简化麻烦一点；其他没什么区别，本质是「用什么去表示」。

    * 工程优化的分量：视锥（frustum）之外的物体根本不进光栅化（百分之百看不见）、部分可见只渲染看见的部分、背面的面不用渲染——这些裁剪剔除全是工程操作；同样的算法明明确确提供给你，写出来的速度可能比写引擎的人慢十倍——具体技术才是难点。

## 混合全局光照方案与 Lumen

* **为什么必须是混合方案（hybrid solution）**

    * 没有任何一种全局光照解决方法能把所有情况都解决掉；唯一真正能解决的实时光线追踪（理论正确的 path tracing）又太慢——不是所有硬件都支持、也不是所有部分都能拿它做，全都用的话游戏帧率上不去。

    * 工业思路：把所有方案拉到一块综合起来用——先做一套 SSR（screen space reflection，屏幕空间反射）得到近似估计；SSR 的 fail 之处很清楚：出了屏幕、物体在 camera 背后、只用了深度表示的那层壳（壳之后一无所知）；知道它不行的地方在哪，再用其他方案弥补，弥补手段分软件 tracing 与硬件 tracing 两路。

* **软件 tracing**

    * SDF：shading point 周围一定范围内的物体用高分辨率、高质量的 SDF，远处用低质量一点的 SDF 覆盖整个场景；在 shader 里 trace SDF 可以很快（做 BVH 上的、三角形的 trace 太慢），trace 到哪儿就按后续正常步骤算那块的光照。

    * 非常强的方向光源/点光源（手电筒类）：用 RSM。

    * 场景本身比较 diffuse 时：基于探针（probe）的 dynamic diffuse GI（DDGI）——3D 场景中均匀分布很多 probe，每个 probe 记录一些 radiance、用这些 probe 照亮整个场景；背后缺 many-light/VPL 理论所以未展开，但它是一套不错的工业界技术。

* **硬件 tracing**

    * 实时 trace 没必要用原始 geometry：算的是 indirect illumination、没必要那么准，用简化了的模型代替原始模型，tracing 速度大增、RTRT 就非常快。

    * RTRT 的思路结合 probe 的思路 = RTX GI（未展开）。

* **五条合体 = UE5 的 Lumen**

    * 屏幕空间光线追踪（SSR）+ 软件追踪（SDF、RSM、DDGI 探针）+ 硬件追踪（简化模型、RTX GI）加在一块就是 UE5 Lumen 的实现——本质是讨论「已知 GI 技术应该怎么结合」，听起来索然寡味，实现确实比较复杂。

## 尚未展开的前沿话题

* 课程已覆盖四块：实时阴影与环境光照、实时全局光照、实时 shading/材质（表面）、实时光线追踪；以下是明确列出的未展开话题版图。

* SDF 贴纹理：SDF 有各种问题，其中一个就是它自己贴纹理挺难；怎么贴有办法，未讲。

* 透明物体与 OIT（order independent transparency，顺序无关透明）：为什么涉及透明的物体，渲染顺序就有关系。

* 粒子上屏：粒子的模拟很简单；怎么把 particle 真正画到屏幕上，未讲。

* 后期处理：镜头光斑、景深（depth of field）这些效果全部是后期处理做出来的——先做出没有模糊的画面，再在后期加工。

* 随机数与蓝噪声：实时渲染中怎么生成、应用随机数（更准确地说是随机数种子），以及工业界说了很多的蓝噪声到底是什么。

* Foveated rendering（注视点渲染）：VR 等应用里，盯着的地方投入更多算力和分辨率、其他地方少一点。

* 基于探针的 GI 细节：DDGI 与 RTX GI 两个不同版本的具体实现（背后理论难）。

* ReSTIR（2020 年产生的方法）与 NeRF（neural radiance fields，神经辐射场）等更先进的新技术。

* Many-light 理论：渲染间接光影势必涉及的 many-light 理论，以及 Light Cuts、VPL（virtual point light）背后到底是什么。

* Participating media（参与介质）：云、烟、雾——背后涉及的知识太多，放到离线渲染里说。

* 次表面散射（subsurface scattering）：幻灯片上那一串「五个 S」对应的非常重要的渲染效果。

* Hair 等复杂外观：头发这些复杂的 appearance 完全未讲。

* 后续去向：皮肤、毛发等复杂材质与更复杂的光线传播方法（light transport）放入离线渲染课，内容三块——采样和光线传播理论、appearance（外观）、neural rendering 等研究热门话题。
