# 着色与纹理映射

## 采样与滤波的先后顺序

* **先滤波再采样（blur before sampling）**

    * > **定义**：反走样的正确次序是先用滤波去掉信号的高频成分、再采样；「先采样、再模糊」的次序注定失败。

    * 频域机理：采样会把原信号的频谱搬移、复制出无数份副本，副本一旦互相叠到一起，混叠就发生了。

    * 先采样后模糊等于在已经混叠的频谱上做截断——截断只是把带宽掐掉，已经发生的混叠救不回来，因此次序不可颠倒。

    * > **提示**：顺序问题的根因在于混叠发生在模糊之前，事后的滤波无法撤销已经发生的频谱混叠。

## 可见性与深度缓存

### 画家算法

* **画家算法（Painter's Algorithm）**

    * > **定义**：模仿油画家覆盖式作画的可见性算法——先画最远的物体，再从远到近逐层把近处物体画上去、覆盖先前画的内容，最终得到正确的遮挡。

    * 「画家」特指覆盖式作画的油画家；素描逐笔刻画、不靠覆盖顺序，与该算法无关。

    * 深度顺序难以定义：立方体的四个侧面离观测者深度几乎相同，换一个绘制顺序画面就会多出不该有的竖线——画对纯属巧合。

    * 致命失效：三个三角形两两互相覆盖（P 盖 Q、Q 盖 R、R 盖 P）构成深度环，深度关系根本无法定义，任何预先排序都注定出错。

    * 即便可排序，n 个三角形也要 $O(n \log n)$ 时间，因此实际渲染不采用画家算法。

### 深度缓存

* **深度缓存（z-buffer，深度缓冲）**

    * > **定义**：在每一个像素内，永远记录该像素当前看到的几何的最浅（最近）深度，用逐像素的深度比较解决遮挡。

    * 思路转变：三角形之间的远近难排序，但「这个像素看到的是哪个三角形的一部分」容易分析，于是放弃给三角形排序，改为逐像素记最浅深度。

    * 渲染成品图的同时同步生成一张深度图：帧缓存（frame buffer）存每个像素的颜色，深度缓存存每个像素看到的最浅深度，两图同步更新，靠深度图维护遮挡信息。

    * 深度图表现：离视点越近深度值越小、颜色越黑，越远值越大、颜色越白；近处黑是因为深度值直接映射成了颜色值。

    * 深度口径：此处的深度指点到相机的距离，非负、越小越近；与变换章节「相机朝 $-z$ 看、z 取负值」的口径不同，是便于计算的替换。

* **深度缓存算法流程**

    * 初始化：深度缓存中所有像素的深度记为无限大（C++ 有 `inf`；用不好也可取 $10^{10}$ 这类足够大的数当作无限大）。

    * 以任意顺序逐个光栅化三角形；对每个被覆盖的像素：若三角形在此像素的深度小于缓存记录值，则把缓存更新为更浅深度、并把该像素涂成此三角形的颜色，否则什么都不做。

    * 所有操作都发生在单个像素内，三角形未覆盖到的像素不受任何影响；三角形上任意位置的深度具体怎么算，靠后续的插值方法解决。

* **与 MSAA 的配合及边界**

    * 多重采样抗锯齿（multisample antialiasing，MSAA）在一个像素内取多个采样点时，深度缓存改为对每个采样点各记一份它能看到的深度，即从逐像素记录变为逐采样点记录。

    * 深度测试被几乎所有光栅化渲染采用、深度缓存应用于几乎所有硬件；明确的边界是透明物体——深度缓存一定处理不了，需要特殊处理。

### 复杂度与顺序无关性

* **线性复杂度（$O(n)$）**

    * 前提：每个三角形大小适中，覆盖常数个（如 100 个上下）像素。

    * 结论：每个三角形只处理常数个像素，总操作数正比于三角形个数，整个算法为 $O(n)$。

    * 为什么能突破排序下界：深度缓存并没有做排序，对每个像素只维护「当前见过的最小值」——如同挨家比价只随时记住当前最低价，并不给所有店排出完整名次；最小值以外的遮挡关系直接丢弃。

* **顺序无关性**

    * 只要深度缓存维护正确，三角形以任何顺序绘制，最终图像完全一致。

    * 前提：同一像素上不会出现两个深度完全相同的三角形——浮点数经过运算后判等几乎不可能成立，该假设经验上成立；它是经验假设，真实场景仍需考虑深度相同的处理办法。

## 着色基础

### 着色的定义

* **着色（shading）**

    * > **定义**：对不同的物体应用不同的材质的过程。

    * 动机：只做光栅化的画面里，同一立方体各面颜色毫无差别，大脑无法判断它在如何转动；不同朝向的面颜色略不同，真实感立刻不同——缺的这一步就是着色，回答「像素的颜色应该是什么」。

    * 字典义包含两件事：引入明暗的不同（darkening）与引入颜色的不同（coloring），与素描中高光、暗部、投影的画法一致。

    * 材质不同，就是不同材质与光线相互作用的方式不同，因此着色与材质可以放在一起讨论；换个角度说，不同的材质就是不同的着色方法，两者基本没有区别。

### 着色点与局部性

* **着色点（shading point）**

    * > **定义**：被分析光照的表面上的一个点；表面整体可以是曲面，但在着色点极小的局部范围内总可视为平面，因而可以定义法线。

    * 三个方向向量：法线 n、观测方向 v（view direction，从着色点指向相机）、光照方向 l（light direction，从着色点指向光源，由光源位置减着色点位置再归一化得到）；它们只表示方向，一律取单位向量。

    * 表面属性：shininess 刻画闪亮程度（上釉陶瓷非常亮、没上釉的像石膏），它与亮度无关；color 刻画各点颜色（如木头各处反射方式基本相同，仅颜色不同）。

* **着色的局部性**

    * 着色只考虑着色点自身，顶多加上光照与观测方向；不考虑该点是否在阴影内，也不考虑其他物体的存在——光线是否被别的东西挡住一概不看。

    * > **易错点**：⚠️ 着色（shading）≠ 阴影（shadow）。局部着色能给出明暗变化，但给不出阴影；两者英文拼写相近，容易搞混。

### Blinn-Phong 反射模型

* **Blinn-Phong 反射模型（Blinn-Phong reflectance model）**

    * > **定义**：最基础的着色模型，把一个着色点受到的光照拆成高光、漫反射、环境光三部分分别表示再相加；名称由 Blinn 与 Phong 两人合成，「反射」指光线如何与材质作用并反射。

    * 它是经验模型：推导有一定物理道理，但基本不考虑完全的物理真实性，追求的是近似正确的外观。

* **单光源下的三个组成部分**

| 组成部分 | 画面上的表现 | 成因 |
| :--- | :--- | :--- |
| 高光（specular highlight） | 特别亮的一小块 | 表面光滑，光朝镜面反射方向附近集中 |
| 漫反射（diffuse） | 变化不剧烈的明暗渐变 | 表面粗糙，光被反射向四面八方 |
| 环境光（ambient） | 直射照不到却不是黑的 | 间接光照，简化为四面八方的常量 |

* **间接光照（indirect lighting）**

    * 着色点看不到光源却不发黑，因为它接收到的是间接光照：光源照到墙面，粗糙墙面把一部分光弹到桌面，桌面再有一点反射进入人眼。

    * 间接光的完整计算复杂，属于全局光照；此处先假设每个点都会接收到来自环境、四面八方的反射光，且强度近似为常量。

## 漫反射

### Lambert 余弦定律

* **Lambert 余弦定律（Lambert's cosine law）**

    * > **定义**：表面接收到的光照能量，与光照方向 l 和法线方向 n 夹角的余弦成正比。

    * 离散图景：6 根等能量光线垂直打到表面时全部被接收；表面转开 60° 后只能接收到 3 根，能量减半、表面变暗。

    * 能量视角：固定考察一块单位面积、只改变它的朝向，接收能量随夹角变化——如同面积不变的太阳能板，朝向决定接收量。

    * 生活验证：四季的成因是夏季阳光直射北半球（光照接近垂直于地表）、同时斜射南半球，并非地球离太阳的远近变化；北半球是夏天时南半球正是冬天。

### 点光源的距离衰减

* **平方反比衰减（$I/r^2$）**

    * > **定义**：点光源向四面八方均匀辐射，任一位置单位面积接收的能量随传播距离按平方反比衰减。

    * 能量守恒推导：任一时刻辐射的能量集中在一张球壳上，球壳面积随距离增大、单位面积能量相应减少；由「半径 1 处强度 I」与「半径 r 处强度 $I_r$」总能量相等，$4\pi \cdot 1^2 \cdot I = 4\pi r^2 \cdot I_r$，得 $I_r = I/r^2$。

    * 按球壳面积而非圆周长推导，因为点光源在三维空间中向所有方向辐射，能量分布在球面上。

### 漫反射项公式

* **漫反射项（diffuse term）**

    * > **定义**：$L_d = k_d \cdot \frac{I}{r^2} \cdot \max(0,\ \mathbf{n}\cdot\mathbf{l})$，三个因子各管一件事——$I/r^2$ 管多少光到达，$\max(0,\mathbf{n}\cdot\mathbf{l})$ 管表面接住多少，$k_d$ 管材质留下多少、反射多少。

    * 余弦即两个单位向量的点乘；乘 $\max(0,\cdot)$ 是因为 n·l 为负表示光从表面下方穿入，对反射没有物理意义，一律记 0。

    * $k_d$ 为漫反射系数，刻画吸收比例：$k_d=1$ 完全不吸收、进来多少反射多少，最亮；$k_d=0$ 全部吸收，表面全黑。

    * 颜色的来源：点显色是因为它吸收了一部分能量、反射剩余部分；把 $k_d$ 写成 RGB 三个 0 到 1 之间的分量，不同波长吸收比例不同，就得到该点的颜色。

    * 最重要的性质：与观测方向 v 完全无关——漫反射把光均匀反射向四面八方，光源不动时从任何方向看同一位置的亮度一致。

    * > **易错点**：「与观察无关」不等于画面是平的。不同位置的表面朝向不同、n·l 不同，明暗当然随位置变化；它只保证同一位置从各方向看亮度相同。

    * Blinn-Phong 是经验模型：$k_d$ 并非严格的物理写法（准确模型需按能量守恒处理，在路径追踪部分说明）。

    * 所有量都在世界坐标中参与计算：着色点、光源、法线均用世界坐标描述，与模型空间无关。

    * 直观验证：石膏球在法线与光照方向一致处最亮（点乘接近 1），法线逐渐转向与光照垂直处点乘趋 0、渐黑，形成从白到黑的过渡；调整 $k_d$ 只改变整体亮度，不改变明暗分布形状。

## 高光

### 半程向量与高光条件

* **高光（specular highlight）**

    * > **定义**：光滑表面上的集中亮块；当观测方向 v 与镜面反射方向 R 足够接近时可见。

    * 物理图景：无限光滑的镜面给出射方向有且只有一个；光滑金属略糙，反射方向沿镜面反射方向 R 形成一个分布，v 落在分布内即看到高光。

    * > **提示**：磨砂表面并非绝对没有高光，取决于磨的程度。

* **半程向量（half vector，h）**

    * > **定义**：光照方向 l 与观测方向 v 的角平分线方向，$\mathbf{h} = \dfrac{\mathbf{l}+\mathbf{v}}{\lVert \mathbf{l}+\mathbf{v} \rVert}$——两个单位向量按平行四边形法则相加、再归一化即得。

    * Blinn-Phong 的关键假设：「v 接近 R」等价于「h 接近 n」，于是判断能否看见高光只需看 n 与 h 是否足够接近。

    * 相对 Phong 反射模型的改进：Phong 直接用 R·v，需先由入射方向与法线算出反射方向，计算量大；半程向量加一加、除以长度就好算得多，凭这一点 Blinn-Phong 胜出。

* **高光项公式**

    * $L_s = k_s \cdot \frac{I}{r^2} \cdot \max(0,\ \mathbf{n}\cdot\mathbf{h})^p$；$k_s$ 为镜面反射系数，高光通常被视为白色，$k_s$ 一般取白色。

    * 与漫反射不同，高光项没有能量吸收因子——这是经验模型的简化，它只关心「能否看见高光」（n 与 h 是否足够接近）。

### 高光指数 p

* **高光指数（p）**

    * > **定义**：加在 $\max(0,\mathbf{n}\cdot\mathbf{h})$ 上的指数，控制高光的大小。

    * 为什么需要：夹角余弦的容忍度太高——两向量夹 45° 时余弦仍给出较大值，直接用原始余弦会得到面积超大、不合理的高光。

    * 数值尺度：p 取 64 时约 20°~30° 内还能看到一点高光；实际常用 100~200，对应正常高光仅 3°~5° 的可见范围，之外基本消失。

    * 效果矩阵的读法：同一列增大 $k_s$ 只提高亮度；同一行增大 p，高光逐渐变小。演示时同时显示漫反射垫底，因为单独的高光项实在太小，几乎只剩几个点。

## 环境光与三项合成

### 环境光项

* **环境光（ambient lighting）**

    * > **定义**：$L_a = k_a I_a$，假设任何点接收到的环境光强度 $I_a$ 处处相同，$k_a$ 为该点的颜色系数——是对复杂间接光照的大胆简化。

    * 方向性质：与光照方向 l、观测方向 v、法线 n 全都无关，本质上是一个常数。

    * 作用只有一条：保证画面里没有地方是全黑的，把其他项垫起来、提升整体亮度；副作用是任何地方都垫着同一种颜色，画面显得平。

    * 凹陷处环境光并不因此变暗——这恰恰说明它是简化；要精确计算环境光需要全局光照知识，非常难。

### 三项合成与整体性质

* **完整 Blinn-Phong 模型**

    * 三项直接相加：$L = L_a + L_d + L_s$，式子非常简单。

| 分量 | 方向特点 | 视觉特征 |
| :--- | :--- | :--- |
| 环境光 $L_a$ | 与 l、v、n 全无关，是常数 | 保证没有地方是黑的 |
| 漫反射 $L_d$ | 与 v 无关，只看 n·l | 随光照角度明暗渐变 |
| 高光 $L_s$ | 只在 n·h 接近 1 处出现 | 极小区域、非常亮 |

    * 合成观感：有一点高光、有漫反射的明暗、又没有全黑的区域——像塑料，这是 Blinn-Phong 最经典的质感。

    * > **提示**：着色结果与物体到观察点的距离无关；「离得远看着暗」是另一种现象，要彻底解释需要辐射度量学（radiometry，其核心概念 radiance 与平常理解的能量并不一样）。

## 着色频率

### 三种着色频率

* **着色频率（shading frequency）**

    * > **定义**：着色被应用在哪些点上。同一几何模型应用不同着色频率，结果差异极大——三个球的边界完全相同（几何一样），着色后却截然不同。

* **Flat 着色（flat shading，逐三角形）**

    * > **定义**：对每个三角形算一次着色，整个面共用同一个颜色。

    * 面法线由两条边做叉积直接求出；三角形内部不可能有明暗变化，球面呈现一块块色片。

* **Gouraud 着色（Gouraud shading，逐顶点）**

    * > **定义**：每个顶点用各自的法线做一次着色，三角形内部的颜色由三个顶点插值得到。

    * 局限：三角形稍大时，高光可能整个落在顶点之间的区域里而看不见，着色效果并不算好。

* **Phong 着色（Phong shading，逐像素）**

    * > **定义**：把三个顶点的法线插值到三角形内部的每一个像素，让每个像素有独立的法线，再对每个像素做一次着色。

    * 效果比前两种好得多，代价是每个像素都要算一次着色。

    * > **易错点**：⚠️ Phong shading（逐像素着色，是一种着色频率）与 Blinn-Phong 反射模型（是一种着色模型）是两回事，只是碰巧由同一人发明；前者回答「在哪里着色」，后者回答「颜色怎么算」。

### 频率选择的权衡

* **按几何密度选择着色频率**

    * 判断标准：取决于面、顶点、像素本身出现的频率——几何定义得足够密集时，相对简单的着色方法效果已经很好。

    * 反直觉结论：若三角形数量超过像素数量，逐三角形着色的计算量反而大于逐像素着色，Flat shading 并不一定便宜。

    * 对面数不特别密集的常见模型，逐像素的 Phong shading 给出的结果最好。

### 法线的获取与插值

* **顶点法线（vertex normal）**

    * 理想情况：知道模型背后的真实曲面——用三角形逼近球时，顶点法线就是球心指向该顶点的方向，直接算。

    * 通用做法：把与该顶点相邻的各面法线求平均当作顶点法线；按三角形面积做加权平均比简单平均更好，是目前通行的算法。

* **逐像素法线**

    * 已知顶点法线后，在三角形内部对法线做平滑插值（工具是重心坐标），插出的法线供逐像素着色使用。

    * > **提示**：法线是方向不是位置——插值求出后必须重新归一化成单位向量，保证长度一致，这一步不能省。

## 图形管线与着色器

### 实时渲染管线

* **图形管线（graphics pipeline，实时渲染管线）**

    * > **定义**：从三维场景到最终一幅图中间经历的一整套固定操作流程，整体已在 GPU 硬件中实现。

    * 阶段与已学内容的对应：MVP 变换属顶点处理；对每个像素中心采样、判断是否在三角形内属光栅化；Z-Buffer 深度测试紧随光栅化（严格说也可归入光栅化）。

    * 着色发生在哪个阶段取决于着色频率：Gouraud 逐顶点着色发生在顶点处理阶段（顶点既可以投影也可以着色）；Phong 逐像素着色要等像素产生后在 fragment 里做。

    * 投影不改变点与点的连接关系：原来三个点组成三角形，投影后仍是这三个投影点组成三角形，因此只需对顶点统一操作；「先投影再连三角形」没有特殊含义，只是定义模型的方式。

* **管线流程**

```text
空间中的顶点（所有顶点 + 哪三个点组成一个三角形）
        |
        v
 (1) 顶点处理：MVP 等变换，把三维点投影到屏幕
        |
        v
 投影后的点连成三角形（点间连接关系不变）
        |
        v
 (2) 光栅化：屏幕是离散的，逐像素采样，把三角形
     打散成 fragment，配合 Z-Buffer 留下可见部分
        |
        v
 (3) 着色：逐顶点（Gouraud）或逐像素（Phong）算颜色
        |
        v
     最终图像
```

* **fragment（片段）**

    * > **定义**：光栅化把三角形打散后得到的最小绘制单元，借自 OpenGL 的概念，可类比像素。

    * 不做 MSAA 时一个 fragment 就是一个像素；使用 MSAA 时多个 fragment（采样点）各自维护深度与颜色，共同决定一个像素的最终颜色。

### 着色器

* **着色器（shader）**

    * > **定义**：由用户编写、嵌入渲染管线、控制顶点或像素（片段）如何着色的可编程代码；整个实时渲染界几乎天天在写的就是这部分代码。

    * 执行模型：shader 是对每个顶点或每个 fragment 各执行一次的通用程序——只描述单个顶点/单个像素如何运作，不需要写 for 循环。

    * 两类名称：操作顶点的叫 vertex shader（顶点着色器）；操作像素的叫 fragment shader 或 pixel shader（片段着色器/像素着色器），翻译不同，一回事。

* **GLSL 像素着色器示例**

    * `uniform` 声明全局变量，对所有像素取值相同（如一张纹理、一个固定的光照方向）；`varying` 声明由管线插值好的变量（uv、法线 norm）——顶点之间的插值由 OpenGL 机制自动完成，不用手写。

    * 常用内置工具：`texture2D` 查询纹理、`dot` 算点乘、`clamp(x,0,1)` 限幅、`normalize` 归一化；`vec3`/`vec4` 向量类型（`vec4` 可由一个 `vec3` 后跟一个数构造）；计算结果写入 `gl_FragColor`，即该像素的颜色。

```glsl
uniform sampler2D myTexture;   // 全局变量：一张纹理
uniform vec3 lightDir;         // 全局变量：光照方向（对所有像素固定）

varying vec2 uv;               // 插值得到的纹理坐标
varying vec3 norm;             // 插值得到的法线

void main() {
    vec3 kd = texture2D(myTexture, uv).rgb; // 漫反射系数，与纹理相关
    vec3 n  = normalize(norm);
    float diff = max(dot(n, lightDir), 0.0);
    gl_FragColor = vec4(kd * diff, 1.0);    // 这个像素/片段的颜色
}
```

    * > **注意**：该示例中 lightDir 是照向场景内部的入射方向，与「光照方向从着色点指向光源（朝外）」的约定相反，所以点乘前没有负号。

    * GLSL 与 C++ 非常相似：有全局变量、有插值出来的变量、中间是计算，再配各种方便的内置函数；写 shader 只需指定好每个像素如何着色。

* **着色器家族的扩展**

    * geometry shader（几何着色器）：对几何编程，可动态产生更多的三角形。

    * compute shader：可执行任意形式的通用 GPU 计算（general-purpose GPU，GPGPU），绝不仅限于图形计算。

    * Shadertoy：免搭建 OpenGL/DirectX 环境、在网页中只写着色器直接看渲染结果的平台；其经典蜗牛例子完全不用三角形，由数学定义的隐式几何构成，形体、投影方式与动画全部在 shader 中完成。

### GPU 与现代实时渲染

* **图形处理器（graphics processing unit，GPU）**

    * > **定义**：整套图形管线的硬件实现，本质是高度并行化的处理器。

    * 并行优势：CPU 几十核已属顶级，GPU 的并行度远超 CPU——单核性能不强，但无数像素执行的 shader 代码基本相同，天然适合大规模并行着色，能在很短时间内处理大量几何并完成着色。

    * 分集显与独显；作业框架在 CPU 上模拟 GPU 流程，帧率低属正常现象。

* **游戏引擎与新技术**

    * 游戏引擎（如 Unreal）把阴影、近似的实时全局光照等经典算法预先实现好放进实时画面，开发者可以专注游戏内容而不必关心图形底层。

    * DirectX 12 这类新 API 会在传统管线基础上带来许多新技术；实时渲染的目标是超级复杂场景的实时呈现。

## 纹理映射基础

### 纹理与 UV 坐标

* **纹理映射（texture mapping）**

    * > **定义**：把一张图（纹理，texture）当作有弹性的皮，蒙到三维物体表面上，从而为表面任何一点定义各自的属性。

    * 动机：同一着色模型下，球上不同位置颜色不同、地板处处显出木头纹路，区别只在各点的漫反射系数不同——需要一种方法给每个点定义自己的属性。

    * 前提：三维物体的表面是二维的（如地球仪的表面地图可剪开摊成平面），因此能与一张图建立一一对应关系。

    * 纹理可定义的不止漫反射系数，可以是任何属性；它与着色的关系是：纹理用来提供着色所需的、各点不同的属性。

* **UV 坐标**

    * > **定义**：纹理自带的二维坐标系；约定 u、v 都取 0 到 1，与纹理的分辨率和长宽比无关，处理起来方便。

    * 映射的最小单元：三角形的每个顶点各对应一个 uv（认为已知）；三角形内部点的 uv 由插值求出。

    * 不同位置可以映射到相同纹理位置——同一块纹理可以像贴瓷砖一样不断重复、铺满整个物体。

### 对应关系与可平铺纹理

* **uv 对应关系从哪来**

    * 人工途径：美工把模型的各部分展开、摆放到纹理的不同位置，人工定下对应关系；我们就认为三角形映射到哪儿是已知的，但对美工来说这是非常繁重的工作。

    * 自动途径：自动把模型展开成平面，希望展开前后三角形大小关系尽量保持（原小的仍小、原大的仍大，即少扭曲），原本无缝的表面映射后也无缝——这就是几何领域的重要研究方向参数化（parameterization），非常难。

* **可平铺纹理（tileable texture）**

    * > **定义**：往上下左右复制自身时能无缝衔接的纹理；UV 展开图上能看到一条条缝，渲染出来的场景上却看不出缝。

    * 设计无缝纹理有一系列算法，Wang tiling 是其中一种；纹理的无缝合成是值得研究的方向。

## 重心坐标插值

### 三角形内插值的目的

* **三角形内插值**

    * > **定义**：已知定义在三角形三个顶点上的属性，对三角形内部任何一点求出平滑过渡的属性值。

    * 原因：大量操作只在顶点上完成、计算，三角形内部需要一个平滑过渡的值。

    * 可插值的属性：纹理坐标 uv（空间三角形对应纹理上的哪个三角形）、颜色（三顶点红绿蓝的自然过渡）、法线（Phong shading 逐像素着色的前提）、深度（像素中心对应位置的深度）——顶点上的任意属性都可以插值。

### 重心坐标的定义与性质

* **重心坐标（barycentric coordinates）**

    * > **定义**：在三角形 ABC 所在平面内，任一点可写成 $P = \alpha A + \beta B + \gamma C$ 且 $\alpha + \beta + \gamma = 1$（A、B、C 即三顶点坐标），系数组 $(\alpha,\beta,\gamma)$ 就是该点的重心坐标。

    * 无需坐标系：不管 A、B、C 在什么坐标系里表示，只要点在三角形所在平面内，就能用满足条件的三个系数把它线性组合出来——描述位置不再依赖直角坐标系。

    * 自由度：三个数受「和为一」约束，实际只有两个独立量，与平面是二维的一致。

    * 条件的几何含义：$\alpha+\beta+\gamma=1$ 保证点落在三角形所在的平面内（可能在三角形外）；三个系数全部非负，点才一定在三角形内。

    * 顶点的重心坐标直接从定义读出：A 为 $(1,0,0)$，B 为 $(0,1,0)$，C 为 $(0,0,1)$。

### 面积比求法与属性插值

* **面积比求重心坐标**

    * 做法：把点 P 与三个顶点相连，每个顶点对面都出现一块小三角形（与该顶点不相邻的那块），每个系数等于该顶点对面小三角形的面积除以总面积。

$$\alpha = \frac{S_{PBC}}{S_{ABC}}, \qquad \beta = \frac{S_{PCA}}{S_{ABC}}, \qquad \gamma = \frac{S_{PAB}}{S_{ABC}}$$

    * 分子的下标含义：$S_{PBC}$ 是由 P 与 B、C 围成、不含 A 的小三角形面积，与 α 乘在 A 上相对应；面积用向量叉乘即可算出。

    * 特殊点：重心把大三角形分成三块等面积，故重心的重心坐标为 $(\frac{1}{3},\frac{1}{3},\frac{1}{3})$。

    * 任意点也可直接套坐标公式算出 α、β，γ 由 $1-\alpha-\beta$ 补足；公式不必背，会按定义计算即可。

* **属性插值公式**

    * 用法：先算出点位置的重心坐标，再用同一组系数线性组合顶点属性——$V = \alpha V_A + \beta V_B + \gamma V_C$；位置、uv、颜色、法线、深度都适用。

### 投影下的重心坐标陷阱

* **重心坐标不满足投影不变性**

    * > **易错点**：⚠️ 投影变换下不能保证重心坐标不变——空间三角形投影后形状改变，同一点按投影前后分别计算会得到不同的重心坐标。

    * 推论：插值三维空间中的属性（尤其深度）必须在三维空间中做——用三维坐标算出重心坐标、完成插值，再把结果对应回屏幕；不能直接在投影后的屏幕三角形里插值。

    * 深度插值的正确做法：光栅化时找到像素中心在空间三角形中对应的三维坐标（需用逆变换把屏幕上的点投回去），在三维空间中插值三个顶点的深度，再放回该像素。

    * > **提示**：三维属性在三维空间插值、再对应到二维屏幕结果，根本原因只有一条——重心坐标在投影操作下会变化。

## 纹理的查询问题

### 查询流程与最简用法

* **纹理最简用法**

    * 流程：屏幕上每个采样点（像素，或 MSAA 下的采样点）→ 用重心坐标插值出它的 uv → 到纹理中查询该 uv 的 texel 颜色 → 把颜色直接当作该点的漫反射系数 $k_d$。

    * 效果：图被贴到物体上，同时保留 Blinn-Phong 带来的明暗变化、高光等所有效果。

### 纹理放大与双线性插值

* **纹理放大问题**

    * 场景：4K 高分辨率画面配 256×256 的低分辨率纹理——盯着高清的墙查低清的图，查到的 uv 大量是非整数。

    * 术语：纹理上的像素叫 texel（纹理元素/纹素），与生成画面上的 pixel 相区分。

    * 四舍五入法：把非整数 uv 舍入到最近 texel，周围一片（3×3、5×5 等）像素共用同一 texel，画面呈一块块格子，难以接受。

    * 真正的问题：查询到非整数坐标时，如何得到纹理在该处的值——这就是插值要回答的。

* **线性插值（linear interpolation，lerp）**

    * > **定义**：$\mathrm{lerp}(v_0, v_1, x) = v_0 + x\,(v_1 - v_0)$，$x=0$ 取 $v_0$、$x=1$ 取 $v_1$，中间按比例过渡。

* **双线性插值（bilinear interpolation）**

    * > **定义**：取查询点邻近的 4 个 texel，先用 s 对下边两个 texel 做一趟线性插值、再用 s 对上边两个做一趟，最后用 t 把两个结果竖直插出来——水平、竖直两趟插值。

    * 记号：s、t 是查询点相对最近 texel 单元左下角的水平/竖直偏移比例，取值 0~1；这与 uv 自身的 0~1 范围是两回事。

```text
u01 -------- u11
    |      |
    |  *   |     * = 查询点（像素中心映射到纹理上的位置）
    |      |     s = 相对左下角的水平偏移比例，t = 竖直偏移比例
u00 -------- u10
```

    * 性质：查询点紧贴某个 texel 时结果趋近该 texel 值；位于四点正中央时恰为四点平均值；单元内处处平滑过渡，格子消失。

    * 先竖直再水平也一样，手推公式可知结果相同。

    * > **注意**：「双」线性指水平与竖直两个方向都要做插值（水平方向其实做了两次），不是说总共只插两次。

* **bicubic（双向三次插值）**

    * 取周围 16 个 texel，每次用 4 个点做三次插值；质量更高——人脸眼角等细节处双线性仍有轻微锯齿，bicubic 基本消除。

    * 运算量比 bilinear 大（16 个点对 4 个点）；图形学的普遍规律再次出现：质量越好，开销越大，后续思路就是把开销降下来。

### 纹理过大与走样

* **纹理过大的问题**

    * 反直觉：纹理小需要插值，纹理大似乎什么信息都有——但纹理太大反而引起更严重的问题。

    * 现象：贴满格纹的大平面从近处延伸到地平线，近处出现严重锯齿、远处出现摩尔纹（Moiré），本质都是走样，越远越糟。

    * 根因：近处一个像素覆盖的纹理区域小，用像素中心一点查值尚可近似整块；远处一个像素覆盖一大片纹理，用中心一点代表整片区域的平均完全不对。

    * 频域解释：远处一个像素内纹理变化频率很高，单用一个采样点采样必然跟不上，需要更高的采样频率。

    * 暴力解法及其代价：每个像素内放 512 个采样点、取值求平均（超采样），结果很好但算法特别慢，不可接受。

### 点查询与范围查询

* **换思路：避免采样**

    * 采样会引起走样，那就干脆不采样：若能立刻知道「某个区域内数值的平均」，就不必真的采一堆点再平均——把问题变成范围查询。

| 查询类型 | 问题形式 | 图形学中的例子 |
| :--- | :--- | :--- |
| 点查询（point query） | 给一个点，它的值是多少 | 双线性插值等一切直接取值 |
| 范围查询（range query） | 给一个区域，立刻得到区域内平均值 | mipmap |

    * 范围查询不止求平均一种——求区域最大值、最小值是另一类问题，方法不同。

    * 渲染的实际需求：近处像素覆盖的纹理区域小、远处大，因此范围查询要能处理任意不同大小的区域。

## Mipmap 与三线性插值

### Mipmap 的定义与层级

* **Mipmap**

    * > **定义**：从一张原图生成一系列逐层减半的图，用以支持快速、近似、仅限正方形的范围查询；词源为拉丁语，意为许多小东西合在一块。

    * 三个限定缺一不可：快（查询快）、近似（结果不精确）、只能查方形尤其是正方形区域。

    * 层级构造：原始纹理为第 0 层，第 i 层分辨率是第 i−1 层的一半（边长砍半）；128×128 的纹理要砍 $\log_2 128 = 7$ 次才到 1×1，一般地层数为 $\log_2 N$（N 为边长像素数），层号 $d = 0, 1, 2, \ldots$

    * 所有的层在渲染开始前提前计算好；同一概念在计算机视觉中叫图像金字塔（image pyramid）。

* **额外存储量**

    * 每层存储是上一层的 $\frac{1}{4}$，总存储 $1 + \frac{1}{4} + \frac{1}{16} + \cdots = \frac{4}{3}$，即额外开销只有原图的 $\frac{1}{3}$。

    * 直观论证：把每层存储都乘 3（只看比例不影响结论），三份第 0 层恰好占满 2×2 块的左上、右上、左下三个象限；右下象限内以同样方式放三份第 1 层，再剩的角里放三份第 2 层……无限嵌套的极限恰好填满整个 2×2 块，于是所有层之和等于 $\frac{4}{3}$ 个原图。

### 像素足迹与查询层号

* **像素足迹近似（footprint）**

    * 做法：把当前采样点 P 的中心、右邻点的中心、上邻点的中心分别投影到纹理空间，得到两段距离 $L_1$（P 到右邻）、$L_2$（P 到上邻）；取 $L = \max(L_1, L_2)$，用边长 L 的正方形近似该像素实际覆盖的不规则纹理区域。

```text
+---+---+
| N2|   |     P  = 当前采样点（像素中心）
+---+---+     N1 = 右邻，N2 = 上邻
| P |N1 |     L1 = P 与 N1 投影到纹理空间的距离
+---+---+     L2 = P 与 N2 投影到纹理空间的距离
              L  = max(L1, L2)
```

    * 计算本质是有限差分（finite difference）：屏幕上沿某方向移动一个像素，看 uv 随之移动多少；写成偏微分形式如下。

$$L = \max\left(\sqrt{\left(\frac{\partial u}{\partial x}\right)^{2}+\left(\frac{\partial v}{\partial x}\right)^{2}},\ \sqrt{\left(\frac{\partial u}{\partial y}\right)^{2}+\left(\frac{\partial v}{\partial y}\right)^{2}}\right)$$

    * 把像素四个顶点都投影过去、算出四条边取最大也完全可以——反正都是近似。

* **在第 $\log_2 L$ 层查询**

    * 规律：$L \times L$ 大小的纹理区域，在第 $D = \log_2 L$ 层上恰好缩成一个 texel；直接查该层对应 texel，其值就是原区域内的平均。

    * 校验：1×1 区域在第 0 层直接查原纹理；4×4 区域经第 1 层变 2×2、第 2 层变 1×1。

    * 直观验证：近处像素覆盖区域小、取低层、细节多；远处覆盖区域大、取高层；整体呈渐变。

    * 遗留问题：层号是离散整数，层与层切换处会出现跳变、形成不连续的缝——需要能查询「第 1.8 层」这样的连续层号。

### 三线性插值

* **三线性插值（trilinear interpolation）**

    * > **定义**：在相邻两层内各做一次双线性插值，再在层与层之间做一次线性插值——查第 1.8 层，就用 0.8 的权重取第 1 层结果、0.2 的权重取第 2 层结果。

    * 不是第三种新式插值：水平、竖直、层间共三趟插值，即双线性之上再加一个线性插值。

    * 效果：层内部连续、层与层之间也连续，任何浮点层号都能平滑查询，跳变的缝消失。

    * 开销：两次双线性查询加一次插值，代价很小，因此在各类游戏与实时渲染中被默认开启，可在设置里开关对比效果。

## 超出 Mipmap 的过滤方法

### Overblur 的根源

* **Overblur（过度模糊）**

    * 现象：以每像素 512 采样点的超采样结果为基准对照，mipmap 在远处把本不该糊掉的细节全部糊掉，称为 overblur。

    * 根源一：mipmap 只能查正方形区域——屏幕像素映射到纹理上常是斜长的不规则区域，用大方框去罩等于对更大的区域求平均，自然糊。

    * 根源二：三线性插值本身也是近似，并非精确计算。

### 各向异性过滤与 Ripmap

* **各向异性过滤（anisotropic filtering）**

    * > **定义**：对不同的长宽比也做预计算、从而支持矩形（长条形）区域快速范围查询的纹理过滤方法；「各向异性」指不同方向上的表现各不相同，与之相对的各向同性即水平竖直表现一致。

    * 结构对比：mipmap 只预计算长宽等比缩小的对角线层级；ripmap 把水平压缩、竖直压缩的各种组合全部预计算出来，构成完整网格——ripmap 就是各向异性过滤背后的那套结构。

```text
   mipmap：只预计算对角线层        ripmap：横压×纵压全预计算
+---+---+---+---+              +---+---+---+---+
| * |   |   |   |              | * | * | * | * |
+---+---+---+---+              +---+---+---+---+
|   | * |   |   |              | * | * | * | * |
+---+---+---+---+              +---+---+---+---+
|   |   | * |   |              | * | * | * | * |
+---+---+---+---+              +---+---+---+---+
|   |   |   | * |              | * | * | * | * |
+---+---+---+---+              +---+---+---+---+
* = 预计算的一层；ripmap 每格对应一种水平压缩×竖直压缩的组合
```

    * 原理：竖直方向压扁的图里一个 texel 对应原图上一块竖直拉伸的矩形区域，因此可对长条形的覆盖区域做快速范围查询，长条形问题基本完美解决。

    * 局限：覆盖区域若是斜着的块，用矩形去框仍然框不准，各向异性过滤无能为力。

    * 存储开销：生成全部压扁组合，总存储约为原图的 3 倍（对比 mipmap 总存储仅为原图的 4/3、额外 1/3）。

    * 游戏里的 2x、4x、8x、16x 指多算多少层；随倍数增大结果逐渐收敛，总存储趋近 3 倍——开多少倍对存储影响不大。

    * > **提示**：各向异性过滤与计算力基本无关，只对显存有一点要求；显存充足时直接开到最高即可，性能几乎不受影响。

### EWA 过滤

* **EWA 过滤（EWA filtering）**

    * > **定义**：把任意不规则的查询区域拆成若干个椭圆（圆）分别查询、共同覆盖的过滤方法。

    * 能处理斜向等任意形状的区域，突破 mipmap 与 ripmap 的形状限制；代价是每个椭圆都要查询一次，多次查询更耗时——质量越好代价越大的规律再次应验。

* **三种过滤方案对比**

| 方案 | 能查询的形状 | 存储开销 | 主要局限 |
| :--- | :--- | :--- | :--- |
| mipmap + 三线性插值 | 正方形（近似） | 额外 1/3 | 斜向区域被大方框罩住，造成 overblur |
| ripmap（各向异性过滤） | 矩形 | 3 倍 | 斜向区域仍无法准确查询 |
| EWA 过滤 | 任意区域（拆成多个椭圆覆盖） | 长文未说明 | 多次查询，更耗时 |
