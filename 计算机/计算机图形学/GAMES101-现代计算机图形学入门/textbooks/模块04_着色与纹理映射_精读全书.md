## 深度缓存与漫反射：遮挡问题的终点，着色的起点
> 对应块：BLK09 | 覆盖分集：P07 | 块标题（分集名）：《Lecture 07 Shading 1 (Il》

### 光栅化的尾巴：一道频域思考题

上一讲我们把“如何把一个三角形画到屏幕上”讲完了：屏幕就是一堆像素，每个像素是一个颜色均匀的小方块；用像素的中心对三角形覆盖到的信号做采样，再分析为什么这样采样会走样，以及为什么“先模糊、再采样”就能解决问题。做法是对的，但当时留了一个问题没有在课上展开：如果把顺序反过来，先采样、再模糊，为什么就不行？

放到频域里一看就清楚。采样在频域上的效果，是把频谱搬移、复制出无数份副本；副本一旦互相叠到一起，混叠就发生了。而“采样之后再模糊”，相当于在已经混叠的频谱上做截断——截断只是把带宽掐掉，混叠的还是那些混叠，救不回来。所以顺序必须是先滤掉高频、再采样，颠倒不得。

> **提示**：先采样后模糊之所以不行，根因在于混叠发生在模糊之前；事后的滤波截断无法撤销已经发生的频谱混叠。

到这里，光栅化这块就算顺利收官——一个三角形已经能够正确地画在屏幕上了。但请注意，这里强调的是“一个”三角形。实际场景里有很多很多不同的三角形，形状各异，各自离相机的距离也不一样。如何把这些三角形都画到屏幕上，并且让遮挡关系是对的——近处的永远要遮住远处的？这就是可见性或者叫遮挡的问题，今天来解答它。解决方法叫深度缓存，或者叫深度缓冲、z-buffering。解决完它，我们就进入着色环节：怎么做着色、怎么分析光照，还有现代的硬件图形管线——现在的硬件中是如何做着色的。今天这一讲，尽量把这些都覆盖到。

### 可见性问题：画家算法

场景中有很多不同的物体，要把它们都放到屏幕上，自然涉及一个顺序问题：先画什么、再画什么，最后整张图看起来才是对的。最直观的想法：先把最远的物体画上去，再逐渐把近的物体补在屏幕上，让它覆盖之前画的远处物体——从远到近一层层画出来，就能得到准确的结果。

这正是从前油画家作画的路数。画一幅画：先画远处的山；然后在山前面画近处的草地，草地挡住了山的一部分；草地上再添好多树，树又挡住之前画的草地，还挡住一部分山。一层覆盖一层，把“从远到近”这个过程完完整整做了出来。图形学里照搬这个思路的算法，就叫画家算法（Painter's Algorithm）。多说一句，这里的“画家”特指油画家：往上画新东西的时候，会覆盖掉以前画的东西；素描那种一点点刻出来的画法不涉及覆盖顺序，那是两码事。

具体到画一个立方体：先画最远的那个面，再画周围四个面，最后画最前面的面，把之前画的全挡上。结果正确——画家算法在一定情况下是适用的。

但要是有同学在这里稍微抬杠一下：周围这四个面，凭什么按那个顺序画？对观测者来说，这四个面离我们都差不多远，都比最远的面近一点、都比最近的面远一点，它们之间的顺序该怎么定？实际试一下就会发现：换个顺序画，比如先右、再上、再左，画面上就会多出一道不该有的竖线。也就是说，画对纯属巧合，顺序其实挺讲究——想给“深度”（离观测点的距离）下一个能拿来排序的定义，其实挺难。

更致命的是这种情况。三个空间三角形 P、Q、R：

```text
   P 覆盖 Q
   Q 覆盖 R
   R 覆盖 P    ← 兜一圈又回到 P，形成一个环
```

三者两两之间都存在覆盖关系，在深度上构成了一个环。这种情况下根本无法定义它们之间的深度关系，自然也就不可能用画家算法提前排好序、再按顺序画——因为那样永远都是错的。何况就算能排，n 个三角形排序一遍也要花 $O(n \log n)$ 的时间。所以实际做法中不能用画家算法。为了解决这个问题，图形学里引入了一个概念：深度缓存（深度缓冲，z-buffer），这是现在被广泛采用的算法。

### 深度缓存：给每个像素记最浅深度

这个算法的思路转变在于：空间中三角形之间的远近不好排，那就别排三角形——对每个像素来说，“这个像素看到的是这个三角形、那个三角形、还是另一个三角形的某些部分”，是挺容易分析的。于是干脆在每一个像素内，永远记录这个像素所表示的几何的最浅深度，也就是离我们最近的那个距离。

为了完成这件事，通常的做法是：在渲染最终成品图的同时，再生成另一张图，这张图只存任何一个像素所看到的几何的最浅深度。

```text
   一场渲染，同时生成两张图，永远同步更新：

     frame buffer                depth buffer
     每个像素是什么颜色          每个像素看到的最浅深度
     （最终的画面）              （用来维护遮挡信息）
```

读图：左边是你最终要的图像，存在 frame buffer（帧缓存）里；右边是配套的深度图，存在 depth buffer（深度缓存）里。两样东西同步生成，我们靠右边这张深度图来维护遮挡信息。

先把深度的口径统一起来。之前讲变换时我们始终假设相机放在原点、朝 $-z$ 方向看过去，所以看到的 z 都是负数，而且数字越小反而离我们越远、数字越大离我们越近。这里为了简化计算，把之前看到的 z 换一个概念：认为深度就是这个点到摄像机的距离——永远为正，越小的距离表示越近，越大表示越远。单纯对深度测试来说，这样假设好理解得多。

> **提示**：本讲的“深度”指到相机的距离，非负、越小越近；这与变换章节“相机朝 $-z$ 看、z 为负”的口径不同，只是为了讲解方便做的替换。

一张做对了的深度图长什么样？比如立方体这么放着，离你最近（离视点、眼睛或摄像机最近）的那个角，深度就浅、值就小；离视点远的点，深度就大，反映在颜色上就会越白。地板也一样：近处深度浅，远处深度大。顺带回答一个当场被问到的问题：深度图为什么近处是黑的？——因为近处深度值小，把深度值变成颜色值，值小可不就黑嘛。

那么算法该怎么进行？想象一下：先画地板，地板由三角形构成，某个三角形覆盖到某个像素，就把地板在这个像素上对应的深度记下来。然后把物体放上去，物体的三角形也覆盖这个像素，它在这个像素上有一个深度；一看，比 depth buffer 里记录的地板深度要小——新画进去的物体在这个像素上至少要遮住地板。于是做两件事：把这个像素画进左边的图，并且把右边图里这个像素的深度更新成更浅的值。反过来，如果新三角形在这个像素上的深度比已记录的更远，那它百分之百会被当前已记录深度的物体遮挡——既不画进结果，也不更新深度缓存。

把流程总结出来：

```text
   1. 初始化：深度缓存中所有像素的深度都记为无限大
   2. 以任意顺序，把一个个三角形做光栅化
   3. 对每个三角形覆盖到的每个像素（之前说的两重循环就是这意思）：
        若三角形在此像素的深度 < 深度缓存中记录的深度
            更新深度缓存为这个更浅的深度
            把该像素涂成这个三角形的颜色
        否则什么都不做（直接忽略）
```

初始化成无限大，C++ 里真的有“无限大”这个概念——`inf` 这样一个数；如果用不好它，也可以把初始值定义成一个足够大的数，比如 $10^{10}$，只要够大，就认为它是无限大。

再通过一个例子走一遍，就应该完全明白了。一开始深度缓存存的全是无限大的值。先光栅化红色三角形：它覆盖的每个像素都做一遍判断——三角形上不同位置有不同的深度（一个三角形在任意位置的深度怎么算，下节课讲），左上角像素的深度是 5，比原本记录的无限大浅，于是把三角形画进 frame buffer，并把该像素的最浅深度更新成 5；左下角等其他覆盖到的像素同理处理；三角形没覆盖到的区域影响不到——再次强调，深度缓存发生在任何一个像素内。

接下来在这个基础上插入蓝色三角形。这个蓝色三角形的左下角离视角更近，那条边离得更远——想象成一个从离你很近的点、向空间中更远方向延伸的空间三角形。逐像素判断：左上角像素，新三角形对应的深度是 8，而屏幕上已经有一个三角形占据这个像素、深度是 5——立刻知道新三角形在这里肯定被深度为 5 的三角形挡住，什么都不做；另一个深度为 7 的像素，和 5 一比仍然更大，同样被遮挡，直接忽略。而左下角那个像素，新三角形的深度是 3，比已记录的 5 更近——新的三角形会遮住原来的东西。做两件事：把这个像素涂成新三角形的颜色（新三角形在这里被看到），并且把这个像素对应的深度值从 5 更新成 3。所有像素都这么操作完，两个三角形各自遮住对方一部分的准确结果就出来了。

这就是深度缓存算法的核心：所有的操作都针对任何一个像素来说；用深度缓存维护任何一个像素当前能看到的最浅深度；整幅图的渲染结果和深度图同步更新，最后就会得到一个准确的结果。作业二要练的正是这件事：很多三角形叠在一块的时候，它们之间互相遮挡如何解决。

### 复杂度：为什么是 O(n)

画家算法对 n 个三角形排序一遍要 $O(n \log n)$；深度缓存的复杂度是多少？先加一个前提：认为每个三角形大小都不是特别大、不是特别小，会覆盖一定的常数个像素——比如都在 100 个上下。那么这个算法无非是一个个三角形往里填，每个三角形考虑它覆盖的常数个像素，总操作数就是常数乘以三角形个数——对 n 个三角形来说，这是一个 $O(n)$ 的算法。

有同学要问了：我们现在处理的是一个“顺序”问题，怎么可能用 $O(n)$ 的算法就把遮挡解决了？学算法课可不是这么说的——理论上要把一系列数字排序，至少得 $n \log n$ 的时间复杂度；这里确实得到了正确的“谁遮挡谁”的顺序，为什么只花了线性时间？

这里其实是一个误解：深度缓存并没有做排序。它对任何一个像素，始终只是在记录当前所看到的最小值。打个比方：你想知道同一种商品哪家店最便宜，只需要挨家把每一家看过来，随时记住当前最便宜的价格是多少——看完所有店，答案自然就有了。你并没有给所有店排出一个完整的名次。深度缓存对每个像素做的正是这件事：只求最小值，除了最小值以外、其他三角形之间互相的遮挡关系，直接就扔掉了——就那么简单。

### 顺序无关性与实践边界

深度缓存还有一个非常好的性质：结果和画三角形的顺序无关。先画紫色三角形再画红色三角形，得到的图和反过来画一模一样——不管你通过什么样的顺序、先画哪个后画哪个，只要把深度缓存维护对了，最后得到的一定是同样的结果。当然这里有一个前提假设：不会出现两个不同的三角形在一个像素上有相同的深度。

为什么敢假设这件事？其实有一定的道理。图形学的几何表示里，很多数字都是用浮点型精度来表示的——很难去准确表示一个有理数，用浮点型总会造成误差；而浮点型和浮点型判断相等，是非常非常困难的事情，尤其是两个通过运算得到的浮点数，实际中几乎不可能一样，基本上可以认为两个浮点型的数永远都不会相同。既然如此，自然就不会有两个完全相同的深度值。当然，这是一个强行解释：实际过程中确实真的会出现深度完全一样的情况，这种情况如何处理，这里就不多说了。

> **提示**：浮点数判等在工程上几乎总是不可靠的；“深度不会相同”是一条经验假设，真实场景里仍要考虑深度相同的处理办法。

深度缓存的地位要说清楚：这是一个非常非常重要、非常实用的算法，广泛应用在几乎所有的硬件中；目前所有光栅化渲染都会做深度测试——每个像素维护一份深度，就能得到正确的遮挡。

再呼应一下之前反走样说的 MSAA：一个像素内部取好多好多采样点。如果要在 MSAA 上应用深度缓存，就得对每一个采样点各记一份“它所能看到的深度”——相当于 z-buffer 不是对每个像素记录，而是对每个采样点记录。作业二里正好有这么一个提纲内容：感兴趣的话，可以对 MSAA 的结果做深度缓存，做对了会看到非常美观的边界效果。

最后一条边界要知道：透明物体。z-buffer 一定处理不了透明物体的深度，需要特殊处理。

### 着色的动机：画面里缺了什么

说完光栅化，再说着色。先从稍微高一点的层次看一下，到目前为止我们都讲了什么：有了空间中的一个模型，也可以定义一台摄像机；通过某些变换把模型变换成某种姿势，像那个机器人；再通过视图变换（view 变换）把摄像机始终放在原点、朝 $-z$ 看；变换完了，就要把三维空间中的东西变成二维的，这是投影变换；投影做完，所有东西都落在 $[-1,1]^3$ 的立方体里，根据它和屏幕的互相关系，我们知道 x 和 y 应该如何映射——相当于知道三角形在屏幕上会覆盖哪些屏幕空间的坐标；最后采样，也就是光栅化。Model、View、Projection 三个变换做完，再做 viewport 变换，再光栅化——现在我们已经能把东西填在屏幕上了。

那目前这些东西给出的结果是什么样的？看这么一个动画：一系列立方体（基本上是立方体）在屏幕上旋转。这张图看上去会有些视觉误差：有同学说它是逆时针转的，有同学说是顺时针转的。到底是怎么回事？正是因为画面出了问题，让我们的大脑无法接受它到底在怎么转——因为这并不是我们期待看到的结果。

我们期待看到的是另一幅：立方体虽然整体是同一个颜色，但同一个立方体的不同面，因为朝向不同，颜色略有不同。两幅一对比，后者明显真实得多。这中间差的那一步，就是下一步要做的操作——着色：当我把不同的三角形都画在屏幕上、都变成不同的像素之后，问这么一个问题——这些像素的值或者颜色，都应该是什么？

再从另一张图看得更明确一点。真实的世界非常复杂——当然这张图也不是真实世界，而是渲染的结果：某种巧克力奶茶（一开始差点认成咖啡），能看到它的泡沫、杯子里的茶、蛋挞，还有葡萄——当然那葡萄看起来不怎么真实。为什么不同的东西会显示出不同的颜色？为什么在不同的光照下——光源挪一个位置，看到的还是那些物体，它们并没有发生位置上的变化——颜色却发生了变化？我们暂时还没开始解决的这个问题，就是所谓着色。

### 着色的定义：给不同物体应用不同材质

既然要用“着色”这个概念，就先给它一个定义。查一查字典——韦氏词典告诉我们：shading 是名词，意思是 “darkening or coloring of an illustration or diagram with parallel lines or a block of color”。它做了两件事：第一，引入明暗的不同（darkening）——有些地方明亮一些、有些地方暗一些；第二，引入颜色的不同（coloring）——有些地方有颜色、有些地方颜色不同、有些地方没有颜色。绘画上就是通过排线或色块来引入明暗和颜色的。

如果学过素描，这个定义立刻有画面：画一个球，知道有一个光源；光源打到的球上某一块会形成一块挺亮的高光；背向光源的一面接受不到光，就比较暗；再画出投影，影子里面用比较深的颜色。图形学里做的工作大概就是这样——字典定义的没什么问题。

不过对这门课来说，我们把着色定义成：对不同的物体应用不同材质的过程。

> **定义**：着色（shading）＝对不同的物体应用不同的材质。

这个说法好理解：同样一个球，可以是石膏球、可以是金属球、也可以是木头球，看上去各不相同，正是因为它有着不同的材质。所谓材质不同，就是说不同的材质和光线相互作用有不同的方式。这么理解，就可以把着色和材质放在一块儿讲了。

### Blinn-Phong 反射模型的三块

这里给大家举一个最最基础的着色模型，叫 Blinn-Phong 反射模型。这个名字是把两个人的名字（Blinn 和 Phong）结合在一块得到的；叫它“反射模型”（reflectance model），是要说清光线如何与材质进行作用、并且如何去反射——把这个事情搞清楚就可以。

先看这么一组茶杯：光源在右上方向，照亮了所有茶杯。基本可以看到茶杯上有那么几个有特征的地方。

第一，可以明显在每个茶杯上看到一块高光（specular highlight）——这是绘画上的术语，就是特别亮的一块。

第二，除了高光，茶杯表面其余部分是变化相对不那么剧烈的颜色渐变：从黄颜色变到深一点的黄颜色、红颜色的深浅过渡。这一系列变化不剧烈的部分，我们管它叫漫反射（diffuse）。漫反射用学过的物理很好理解：一根光线打到墙面上，会被反射到四面八方去——说明墙特别粗糙，光被打到各个不同的地方去。高光同样可以这么理解：如果有一个表面特别光滑，一根光线打到它上面，就会往所谓镜面反射方向的附近去反射——这就是高光这一项。

第三项比较有意思，想一个问题：光源在右上，那按说被鼠标指着的这个位置，是不能被光源照亮的——它看不到光源。学过物理知道，一个点接收不到光，这一点应该是黑的；我们看到东西，说明这个点肯定接收到了光。这是怎么回事？这个点接收到的光照不是直接光照，而是一种间接光照。举个例子：光源打到墙面某一个位置，墙面是漫反射的，总有一部分光会打到桌面这个地方；桌面稍微有点镜面，多少有一点光再反射回到人的眼睛里。这样，这个点接收到的就不是直接光照，而是通过别的物体反射接收到的光照——这叫间接光照。间接光照整体相对复杂，之后讲路径追踪的时候再给大家介绍；这里先做一个假设：任何一个点上，它都会接收到来自环境的、四面八方的反射光，而且这个反射光基本上是一个常量——反射光本来很复杂，咱们把它简化掉。

从这幅图上总结：单说从这一个光源来看，着色就会形成三种不同的部分——高光、漫反射、环境光照。

| 组成部分 | 画面上的表现 | 成因 |
| :--- | :--- | :--- |
| 高光（specular） | 特别亮的一小块 | 表面光滑，光朝镜面反射方向附近集中 |
| 漫反射（diffuse） | 变化不剧烈的明暗渐变 | 表面粗糙，光被反射向四面八方 |
| 环境光（ambient） | 照不到直接光也不黑 | 间接光照，简化成四面八方的常量 |

把这三部分分别分析、表示出来，自然就可以做出一种材质，让它长得跟这个茶杯基本上很相似。

### 着色点、方向与局部性

在展开之前，需要把几样东西定义清楚：表面、光源、观测，各个不同的方向，事先说明白。

我们考虑的是任何一个点上的光照。把看到的这个点叫着色点（shading point），要考虑它的着色结果。着色点在一个物体表面上，表面可以是曲面；但我们认为，在一个局部的、非常小的范围内，它永远是一个平面——于是在这个极小的范围内可以定义平面的法线 n，也就是垂直于这个平面的方向。同样可以规定另外两个方向：观测方向——假设相机在这个位置，从着色点往相机连一个方向，记作 v（view direction，叫观察方向或观测方向都无所谓）；光照方向——从这个点看向光源，记作 l（light direction）。

多说一句：既然定义的是方向，这些向量自然而然都应该是单位向量——v 也好、n 也好、l 也好，长度永远是 1，因为我们只想表示方向。

另外，着色点本身是什么样的颜色，还要定义一些跟物体表面相关的属性。一个是它有多“闪亮”，叫 shininess：陶瓷的物体外面上了釉，看起来就非常亮；没上釉的，看上去基本上跟石膏很像。注意 shininess 和亮度没关系，是不同的事。另一个是颜色（color）：光打到木头上，各处可以看到纹路，但其实基本上反射光的方式是一样的，仅仅是各个地方有一个不同的颜色。每个点各不相同的物体表面属性，就用这些来描述。

最后在进展之前再多说一句，也就是着色的局部性：我们目前所说的着色，只考虑着色点自己，顶多加上光照和观测的方向；不考虑这个点是不是在阴影内，也不考虑其他物体的存在。比如画面里这么一个物体，可以猜测灯光在左上角，按说它应该投出一块阴影——但阴影我们不考虑：考虑这一点着色时，只看光线来的方向，并不看这根光线是不是被别的东西挡住了，只看它自己，别的都不管。

> **易错点**：着色（shading）≠ 阴影（shadow）。局部着色能给出明暗变化，但给不出阴影；阴影怎么生成之后再说。中文里“着色/阴影”分得清，英文里 shading 和 shadow 长得像，容易搞混。

### 漫反射：Lambert 余弦定律

三个部分，从最简单的漫反射开始。什么叫漫反射？一根光线打到物体表面的某个点，然后这个光会向各个方向反射出去——把这个事情表述出来就好。

但表述出来却没那么容易。先看一个现象：物体表面的朝向和光照有一定夹角的时候，得到的明暗是不一样的——前面那几个旋转的立方体大家已经看到了。这就很奇怪：同样的光，照到同样的表面上，以不同的角度照上去，为什么得到的明暗不一样？

用一个离散的图景把道理看明白。假设光是离散的，一共有 6 根光线，每一根代表一份固定的能量；有一个物体表面。如果表面和光线来源垂直，它会接收到所有的 6 根光线；把表面旋转某一个角度——在这里正好是 60 度——它就只能接收到 3 根了。接到的能量少了一半，物体表面就应该暗一点。推广开来：物体表面的法线方向 n 和光线来源方向 l 这两个方向的夹角，决定了物体表面应该有多么亮。这是通过观测就能找到的结论。

再换一个更科学的理解。光是一种能量——我们要看到的这些物体，其实是它们接收到了多少能量。大家用过太阳能：用多大的太阳能板，就能接收到多少能量。那么考虑一个着色点接收到多少能量，就要考虑它周围的一个单位面积——认为这个面积始终不变，看这块单位面积会收到多少能量，这样才有意义；否则结果就跟面积有关，说明不了问题。这也正是为什么刚才旋转表面的时候，单位面积的大小始终不变，只转它的朝向。

生活中我们其实早就观察到这件事了。想一个问题：地球上为什么有四季之分？为什么有冬天、夏天？并不是因为夏天地球离太阳近一些、冬天离远一些！真正的原因是：夏天我们所处的位置（比如北半球）会被光直射，光照几乎是垂直打在我们所处的地方。冷和暖的区别，其实是光线和我们所处的地球表面当前位置的夹角不同造成的。这也解释了为什么北半球是夏天的时候，南半球是冬天——光线直射北半球的时候，就没有直射南半球，南半球那边单位面积接收到的能量要小。道理完全一样。

把这个观测收拢成一条定律，叫 Lambert 余弦定律：接收到的能量，和光照方向 l 与法线方向 n 之间夹角的余弦成正比。当然有道理，拿特殊值试一下：法线方向和光照方向一样，就是直射，接收到所有的能量；如果物体表面被旋转到光照几乎和表面平行——也就是法线方向和光照方向接近垂直——这个单位面积几乎就接受不到多少光。

### 点光源的距离衰减

接收这一端说清楚了，再提“发生”这一端：能量是从哪儿来的。不同的物体被光所照亮，首先这个光得产生。想象光是一种能量，假设它来自一个点光源；这个点光源无时无刻不在以一定的方式，往四面八方辐射出能量。

有一个很聪明的观测方法：认为点光源往四面八方辐射的能量是一样的，那么任何一个时刻，辐射出去的能量一定集中在一张球壳上——某一个时刻能量集中在这里，下一个时刻它会传播到这里，仍然在一张球壳上，因为往各个方向去的速度我们也认为是一样的；过了很长时间，能量就集中在更远的一张球壳上。

但有一条定律：能量守恒。之前任何时刻辐射出来的能量没有任何损失，那么离中心近的球壳上的能量，和离中心远的球壳上的能量，应该是完全相同的。球在越变越大，球壳的表面积也越变越大——就意味着球壳上每一个点、每一个位置对应的能量越来越少。

定量地算：假设球壳与点光源的距离是 1，定义这个球壳上光的强度是 I（这里先把它叫“强度”，严格来说这个词并不合理——光传播的各种物理量之后会专门给大家定义，先这么说着），球壳面积为 $4\pi$；光传到距离为 r 的球壳上，面积为 $4\pi r^2$，该处的强度记作 $I_r$。能量守恒告诉我们：

$$4\pi \cdot 1^2 \cdot I = 4\pi r^2 \cdot I_r \quad\Longrightarrow\quad I_r = \frac{I}{r^2}$$

一推就推出来了。这件事告诉我们：光在传播过程中，任何位置的单位面积能接收到的能量，和光线传播的距离成平方反比——传播的距离越长，单位面积上接收到的能量就按 $1/r^2$ 衰减。

### 漫反射公式与观察无关性

现在两个结论都齐了，把它们结合在一块，就能得到漫反射的表示方法。假设有一个点光源，离着色点有一定距离 r，这个距离可以简单算出来。如果点光源在单位距离上的强度是 I，那么在这么远的距离上，传播到着色点的能量就是 $I/r^2$——这是“到达了多少能量”。到达了的能量，会被物体表面接收，接收多少取决于刚才的 Lambert 余弦定律，余弦就是两个单位向量的点乘——这是“接收了多少能量”。到达多少、接收多少都考虑完，漫反射最终让人看到的明暗就算出来了：

$$L_d = k_d \, \frac{I}{r^2} \max(0, \mathbf{n} \cdot \mathbf{l})$$

这里有很多事情需要交代。

第一，余弦好算：两个单位向量的点乘，早就说过了。那为什么要做一个 $\max(0, \cdot)$？当 n 和 l 点乘得到负数的时候，说明这根光线是从下方穿过物体打到这个表面的——我们考虑的是反射，没说折射什么的，这种情况没有任何物理意义，不可能有贡献，所以点乘为负时一律当成 0。

第二，$k_d$ 是漫反射系数，表示这个点吸收多少能量。$k_d = 1$：完全不吸收能量，进来多少能量反射出去多少，是最亮的；$k_d = 0$：所有能量都被吸收，没有能量反射出去，这个表面是黑的。那点的颜色从哪儿来？一个点有颜色只有一种可能：它吸收了一部分颜色（或者说能量），反射出去的是它不吸收的部分；不同的点有不同的吸收率，得出的结果就会产生不同的颜色，特别是对不同波长产生的颜色不同。把 $k_d$ 表示成一个向量——红、绿、蓝各自都在 0 到 1 之间——就能在当前这个着色点上定义某一种颜色：各色光被吸收的比例不同，剩下的反射出去，就是你看到的颜色。

> **定义**：$L_d = k_d \cdot \dfrac{I}{r^2} \cdot \max(0, \mathbf{n} \cdot \mathbf{l})$。三个因子各管一件事：$I/r^2$ 管“多少光到达”，$\max(0,\mathbf{n}\cdot\mathbf{l})$ 管“表面接住多少”，$k_d$ 管“材质留下多少、反射多少”。

第三，也是漫反射最重要的性质：它与观察方向完全无关。漫反射把光照均匀地反射向四面八方，那么不管从哪个方向观测这个点，看到的能量应该是一模一样的——漫反射这一项理应跟观察方向 v 完全没有关系。回看公式，也是如此：式子里考虑的是光线与法线之间的夹角 $\mathbf{n}\cdot\mathbf{l}$，完全没有考虑 v 的事情。这是有道理的。

要注意，“与观察无关”并不意味着看到的结果是平的。漫反射的明暗当然跟位置有关——不同位置表面朝向不同，$\mathbf{n}\cdot\mathbf{l}$ 就不同；它说的只是：光源不动（l、n 都不变）时，从正对着这个点的方向看、从侧面看，看到的结果亮度是一模一样的。这才是漫反射的基本原理。

### 石膏球验证与课后答疑

用公式验一验实物：一个石膏球，左上角有一个点光源在照亮它。会发现太有道理了：靠左上的地方是白的，从白渐渐过渡到黑。为什么这里是白的？因为这里接收到了更多的能量；为什么接收得多？因为这里的表面法线和光照方向是一致的，夹角余弦接近 1。为什么侧面上会变黑？侧面这一点的法线朝向观测者这边，而从左上角来的光照方向和它越来越接近垂直，点乘趋近于 0——这里接收到的能量相对较小。从白到黑的渐变，就是这么一个过程。

前面那个关于颜色的系数，则决定了整体上有多么明亮：每个点取相同的小一点的 $k_d$，是一幅图；取相对较大的 $k_d$，又是另一幅，整体亮度随之变化。

到这里，漫反射这部分就说明白了。收尾把几个当场提出的问题记下来，都值得想。

有同学提到：$k_d$ 考虑到能量守恒，是不是应该再加一个常数？其实应该是的。准确的模型上会给大家说这件事情——目前所说的 Blinn-Phong 是一个相对简单的模型，基本上不太考虑物理真实性；虽然中间还涉及到一点点推导，其实有一点道理，但它不是完全准确的。$k_d$ 叫漫反射系数，确实并不是一个准确的物理上的写法；到了路径追踪那一块，会着重把这件事情说明白。所以 Blinn-Phong 是一个经验性的模型，并不是完全符合物理的模型。

有同学问：为什么按球的表面积算衰减，而不是按圆的周长算？因为我们考虑的是三维空间中的能量辐射：三维空间中有一个点光源，它往三维空间的任何一个方向辐射，看到的自然是一个球的表面。

再一个：这些计算在哪个空间里做？没有关系——我们认为所有点都在世界坐标里，着色点、光源、法线，所有的东西都在世界坐标里用 x、y、z 描述、参与计算，跟模型空间无关。

课后需要理解的事情就两块：多少光到达着色点（距离衰减那一半），以及为什么点会有颜色（吸收与 $k_d$ 那一半）。深度测试那一块相对较容易，把伪代码稍微读一读，应该可以写得很顺利。下节课把高光和环境光这两项加回来，三项合在一块得到一个准确的结果，图形管线也应该可以一并说完。

### 先把漫反射捡回来

上节课我们提出了 Blinn-Phong 着色模型：在一定的光照下，算清楚一个点应该有什么样的亮度、什么样的颜色。从那几个茶杯的例子能看出，答案是三项：漫反射、高光、环境光，三项都要考虑进去。上节课讲完了漫反射项，动手之前先把两件配套的事情再强调一遍。

第一件：着色永远发生在某一个 shading point 上——就是图上那一个点。要想得到一整张图，就得在很多不同的地方把着色应用很多次。这个"应用在哪些点上"，就是这节课稍后要讲的着色频率问题。

第二件：方向约定。既然着色模型里全是各种方向，就把话说死：所有方向都是单位向量。比如光照方向 $l$，指的是从 shading point 指向光源——怎么算？光源位置减去着色点位置，然后归一化，把它变成单位长度。法线 $n$ 同理。上节课的课件里没有特别标出来，但我指的一直是这个意思，之后我就不再重复标注了。

然后回顾漫反射项本身，推导思路大家应该还记得：光源在传播过程中会根据距离产生能量衰减，$\frac{I}{r^2}$ 这一项表示有多少能量真正到达了 shading point；到达了还不够，还得被吸收——从冷热、冬天夏天那套分析我们知道，接收多少能量取决于入射方向和法线方向的夹角，夹角余弦就是两个单位向量的点乘。到达多少、吸收多少，就反射多少；如果材质本身有颜色，就在前面乘上漫反射系数 $k_d$：

$$L_d = k_d \, \frac{I}{r^2} \max(0,\ \mathbf{n} \cdot \mathbf{l})$$

这是个很经验性的模型，但它有一定的物理道理在里头。并且从式子直接能看出来：漫反射项和观测方向 $v$ 没有任何关系。还是那个球，光源在左上角，不同的 $k_d$ 只改变它的亮度或者颜色，明暗的分布形状不变。

### 高光从哪儿来

现在把高光项加进去。老规矩，先想清楚：什么是高光？或者说，在什么情况下我能看得到高光？

高光肯定出现在比较光滑的物体上。光滑物体的反射有一个特性：反射方向都非常接近镜面反射的方向。如果是一面镜子——无限光滑——给入射方向、给法线，出射方向有且只有一个；如果是光滑的金属，没有镜子那么光滑，它的反射方向就会沿着镜面反射方向 $R$ 形成一个分布。那什么时候能看到高光？自然是我的观察方向和镜面反射方向接近的时候；其他时候都看不到。这是一个基本的经验观察，而且很有道理：观察方向 $v$ 和镜面反射方向 $R$ 足够接近，我们就得到高光项。

Blinn-Phong 模型在此做了一个很聪明的事情。它注意到一个现象：当观察方向和镜面反射方向接近时，其实就等价于法线方向和一个"半程向量"（half vector）很接近。什么意思？我有一个入射方向 $l$、一个出射方向 $v$，把两者的角平分线方向求出来，这个方向就叫半程向量 $h$。两个单位向量求角平分线太简单了：根据平行四边形法则，把 $l$ 和 $v$ 直接相加，加出来的方向一定沿着两者中间的方向；再归一化把长度变成一，就得到

$$\mathbf{h} = \frac{\mathbf{l} + \mathbf{v}}{\lVert \mathbf{l} + \mathbf{v} \rVert}$$

从图上看，$l$ 和 $v$ 产生的这个半程向量，和法线挺接近的——而这恰好就对应着观察方向和镜面反射方向很接近的情形。所以 $v$ 接近 $R$ 就说明 $h$ 接近 $n$，两件事之间是有关系的，Blinn-Phong 就做了这么一个聪明的假设。

这么做的好处：我要衡量到底能不能看到高光，只需要看半程向量和法线是不是足够接近就够了。衡量的工具还是点乘——和漫反射那套分析同样的思路：两个方向足够接近，点乘结果自然接近一；离得比较远，就接近零（方向正好相反的情形咱们不考虑）。于是高光项写成：

$$L_s = k_s \, \frac{I}{r^2} \max(0,\ \mathbf{n} \cdot \mathbf{h})^p$$

$k_s$ 叫镜面反射系数（specular coefficient）。通常大家认为高光是白的，所以 $k_s$ 一般就取一个白色。

关于这一项，课上集中了三个好问题，一个个说。

第一个：漫反射里我们考虑了"多少能量被吸收"（那个 $\max(0, \mathbf{n}\cdot\mathbf{l})$），高光项怎么不管能量吸收了？这个说得非常对——真要做对的话，镜面反射项也确实应该考虑吸收，把那一项加上。Blinn-Phong 是经验模型，它把这一点简化掉了：这个模型主要关注的只是"我能不能看见高光"，也就是 $n$ 和 $h$ 是否足够接近。

第二个：为什么非要用半程向量和法线？我直接用镜面反射方向 $R$ 和观察方向 $v$ 点乘，不也行吗？当然行，没问题——那个模型就叫 Phong 反射模型（Phong reflectance model）；用 $n$ 和 $h$ 的，才叫 Blinn-Phong，它是对 Phong 的一个改进。为什么算改进？因为半程向量太好算了：给一个观察方向、一个光照方向，加起来除以它的长度就完事；而反射方向可不好算——给定入射方向和法线，怎么求出反射方向？公式你写得出来，没问题，但计算量会增加很多。就凭"好算"这一条，Blinn-Phong 胜出。

顺带一提，有同学问磨砂表面是不是就没有高光——不能完全这么说，看磨的程度。

### 指数 p：把高光收紧

第三个问题，也是看公式一定会注意到的：这里怎么多出一个指数 $p$？点乘确实能衡量两个方向接不接近，为什么还要在上面套个指数？

因为夹角余弦的容忍度太高了。看个例子：两个向量夹到 45 度的时候，你觉得它们已经离得挺远了，可夹角余弦仍然给出一个相对较大的值。这意味着如果真拿原始的夹角余弦去生成高光，你会看到一个超级大的高光——这就不太合理了。我们平常认为的高光都是非常亮、集中在很小很小的一片区域：两个方向只要离开得稍微远一点，就不算在高光里；离得非常近，才认为在高光里。

所以我们对夹角余弦做一个简单的操作：不是乘上什么数，而是给它加上若干个指数——取它的多少次方。效果立竿见影：取 64 次方的时候，大约 20~30 度以内还能看到一点高光，之外基本就看不见了，这就很合理。通常在 Blinn-Phong 模型里，指数 $p$ 会用到 100~200，也就是说 64 其实还不太够——正常情况下你能看到的高光，也就 3~5 度的范围，之外基本就没了。所以记住：$p$ 是用来控制高光到底有多大的。

实际看个例子。演示里是一堆球排成的矩阵，显示的是漫反射项加高光项——为什么不单看高光？因为高光项实在太小，不加漫反射垫底的话，看到的基本上就是几个点。竖着看，是镜面反射系数在增大，球的亮度随之提高，这没什么意思；有意思的是横着看：同一行里，随着指数 $p$ 增长，高光越来越小。$p$ 控制高光大小，一目了然。

### 环境光：一个大胆的假设

三项里还剩最后一项：环境光项。回忆茶杯的例子：茶杯有一系列地方根本不可能被光源直接照亮，但它却不是全黑的。为什么？因为很多光线会弹射很多次，从四面八方打到任何一个其他的点上——茶杯背面的一些点，也能接收到来自环境的光。

来自环境的光是个多么复杂的东西，可想而知。所以我们做一个大胆的假设：任何一个点接收到的来自环境的光永远都是相同的，强度记作 $I_a$；任何一个点当然可以有自己的颜色，这个系数就叫 $k_a$。两项一结合，环境光就近似出来了：

$$L_a = k_a \, I_a$$

它的性质从式子或者示意图都能看出来。第一，环境光不讲究从哪个地方进来，和实际直接光照的方向 $l$ 没有任何关系；第二，不管你从哪儿看，得到的结果都一样，和观测方向 $v$ 也没关系；它甚至连法线 $n$ 也不管。所以环境光其实是一个常数——任何一个地方都垫着同一种颜色，画面总会显得平。它的作用就一条：保证没有地方完全是黑的，把其他几项都垫起来、提升整体亮度。

当然，这是一个非常大胆的假设，事实上不是这么回事。要精确地计算环境光，需要用到全局光照的知识——之后会讲，那块非常难。有同学问：如果一个点凹下去，环境光是不是应该暗一些？从 Blinn-Phong 模型上看，并不是如此——这恰恰说明它是一个简化。

### 三项相加：完整的 Blinn-Phong 模型

把三项全部加起来：

$$L = L_a + L_d + L_s$$

这就是 Blinn-Phong 反射模型，式子上非常简单。三项各自的脾气：

| 分量 | 方向上的特点 | 视觉特征 |
| :--- | :--- | :--- |
| 环境光 $L_a$ | 与 $l$、$v$、$n$ 全都无关，是个常数 | 保证没有地方是黑的 |
| 漫反射 $L_d$ | 与 $v$ 无关，只看 $\mathbf{n}\cdot\mathbf{l}$ | 随光照角度明暗变化 |
| 高光 $L_s$ | 只在 $\mathbf{n}\cdot\mathbf{h}$ 接近 1 的地方出现 | 很少的地方产生，非常亮 |

合起来渲染的结果看起来非常有意思：有一点高光的感觉，又有漫反射的明暗，又不存在任何地方是全黑的——像塑料。这就是 Blinn-Phong 最经典的观感。

课上还留了一组关于距离的追问，一并答掉。漫反射不考虑观察点到物体的距离吗？不考虑。那物体到观察点的距离造成的能量损失呢？这里要老实交代：要把这件事彻底弄明白，得去学辐射度量学（radiometry），之后会专门讲。我们一直在说"能量"，其实光线传输里更常用的概念叫 radiance，它和大家平常理解的"能量"并不一样；至于"离得远看着暗"，那是另外一种现象，现在的知识还不足以解释它。现在只需要记住一条：着色结果和物体到观察点之间的距离没有关系。

### 着色频率：把着色用在哪里

着色模型有了、怎么用也有了：给我三维的模型、给我不同的光照条件，我已经可以得出渲染结果。下一步自然是对所有的点做一遍着色操作，整个场景就能看见。那么问题来了——着色要应用在"哪些点"上？

看三个球。它们的几何形状完全一样——从哪儿看出来？从边界。三个球颜色长得各不相同，但边界暴露了信息：三个球用的模型一模一样。那为什么着色之后结果差这么多？这就是着色频率的区别。所谓着色频率，就是：着色，我要把它应用在哪些点上。

#### Flat：逐三角形着色

最直接的想法：既然一个三角形（或者图里那种四边形面）是平面，它就有固定的法线——这个好求，两条边做叉积就行——然后用光照方向、观测方向对这个面算一次着色，整个面都长这个颜色。一个面只做一次着色，三角形内部自然不可能有着色的变化，得到的是完全一样的结果。结果自然不怎么好：球成了一块一块的色片。这种方法有自己的名字：Flat shading（平面着色）。

#### Gouraud：逐顶点着色

改进一步。每个顶点算出一个属于它自己的法线（顶点法线怎么求？这里先按下不表，马上就讲，现在先假设能求），在每个顶点上做一次着色。于是三个顶点围成的三角形内部，任何一点的颜色都可以用插值的方法算出来——所谓插值，就是我知道三个顶点的颜色，问三角形内部某一个点的颜色是什么，并且希望它平滑过渡。插值的具体做法之后详细说。逐顶点着色叫 Gouraud shading——这个名字显然不是英文的发音，读起来有点像"骨肉"。效果比 Flat shading 好，但也有局限：像球这种形体，当三角形稍微大一点，高光可能就看不见了，着色效果并不算特别好。

#### Phong：逐像素着色

再进一步，大家其实已经能猜到：把三角形的三个顶点各自的法线在三角形内部插值，让每一个像素都有一个自己独特的法线方向，然后对每一个像素进行一次着色。这样就能得到一个相对好得多的结果。这就叫 Phong shading（Phong 着色）。

这里务必区分两个概念，特别容易混：前面说的 Blinn-Phong 反射模型，是一种着色模型，只不过名字里出现了 Phong；这里的 Phong shading 指的是一种着色频率——逐像素做着色。两回事，碰巧由同一个人发明。多说一句：Phong 这个人真是天才，至少在这门课到目前为止的范围内，他就留下了两样东西——一是着色模型，二是逐像素着色。可惜天妒英才：据说他读博士期间就一直在和病魔作斗争，博士毕业后第二年左右就去世了。渲染界好像一直挺惨——去年还有一位欧洲的渲染大牛也英年早逝。所以，我们更应该把这些东西写好、讲清楚，就是这个意思。

#### 频率与开销：看几何密度

这三种频率硬要说谁好谁坏，其实取决于具体的模型，不能一口咬定 Flat shading 一定差。看那张 3×3 的球阵图：每一行用的着色方法都一样，行与行之间，越往下三角形越多——几何形体本身定义得越密集、越光滑。可以看到，当几何足够复杂的时候，用相对简单的着色模型，得到的结果其实还是挺好的。

反过来说，Phong shading 效果好，但每个像素都要做一次着色，开销肯定比 Flat shading 大。可要是模型复杂到三角形数量已经超过了像素数量呢？那逐三角形着色的计算量反而更大——可不是说 Flat shading 一定便宜。所以一切取决于具体的物体。对常见的、面本身不是特别密集的模型，还是逐像素的 Phong shading 给的结果最好。一句话：着色频率的选择，取决于面、顶点、像素它们本身出现的频率——面出现的频率已经很高时，就不再需要复杂的逐像素着色了。

### 两个遗留问题：法线从哪儿来

讲到这儿，留下两个问题：逐顶点的法线怎么求？逐像素的法线又是怎么插出来的？

先说顶点法线。理想化的情况：你知道模型背后真正想表示的是什么。比如用一堆三角形逼近一个球——那每个顶点对应的其实是球面上的点，它的法线自然就是从球心指向这个顶点的方向，直接算就行。可平常哪有这种好事？你不可能知道每个模型"背后本来是个什么"。于是人们发明了一个办法，很简单，而且到现在大家都还在用：任何一个顶点，都和若干个三角形相关联——比如图里的这个顶点，有四个三角形共用它——那就把这几个相邻面的法线求个平均，当作这个顶点的法线。

当然，简单的平均也许说明不了全部问题：如果有一个三角形超级小、另一个超级大，是不是大的应该贡献更多？也就是说，与其简单平均，不如做加权平均，权重就取三角形的面积——会不会得到更好的结果？答案是：会的，就是这么回事。所以目前大家的算法就是：把顶点所关联的面（三角形面也好、多边形面也好）的法线求平均，简单平均或加权平均都算。有同学问怎么知道一个点和哪些三角形相连——这属于模型本身怎么定义的问题，咱们到讲几何的时候再说。

再说逐像素法线。已知三角形的顶点法线，如何得到内部平滑过渡的法线？直觉上，左边顶点的法线、右边顶点的法线都知道，中间的法线应该朝那些过渡的方向去。这里要特别强调一件事：法线全是方向，插值求出来之后一定要重新归一化，把它变回单位向量，保证所有法线长度一致。

> **提示**：法线是方向不是位置——插值完必须归一化，这一步不能省。

至于具体怎么插值，需要用到所谓的重心坐标（barycentric coordinates）——马上下一讲就讲。

### 图形管线：从场景到一张图

现在回忆一下：着色模型说了，着色模型怎么用也说了。把所有东西合在一块——给我三维的模型、给我不同的光照条件，我已经可以得出渲染结果。这一整套从头到尾的流程，就叫图形管线（graphics pipeline）。当然这是古老的说法，我更愿意管它叫实时渲染管线：图形学涉及的东西太多，实时渲染在咱们课程里也只能算四分之一的内容（课时数稍微多一些）；而且其他的渲染方法并不是这么做的，这里说清楚。

管线说的是：从场景到最后一幅图，中间到底经历了一个什么样的过程。它其实是一系列不同的操作，咱们过一遍：

```text
空间中的顶点（定义所有顶点 + 哪三个顶点组成一个三角形）
        |
        v
 (1) 顶点处理：MVP 等变换，把三维空间中的点投影到屏幕上
        |
        v
 投影后的点连成三角形（点与点的连接关系不变）
        |
        v
 (2) 光栅化：屏幕是离散的，逐像素采样，把三角形打散成
     一个个 fragment（不做 MSAA 时就当作一个像素），
     并配合 Z-Buffer 深度测试，留下真正看得见的
        |
        v
 (3) 着色：逐顶点（Gouraud）或逐像素（Phong）算出颜色
        |
        v
     最终图像
```

读一遍这张图：输入是一堆空间中的点；第一步做投影，把三维空间中的点投到平面上、投到屏幕上；这些点连成三角形；要把三角形画在屏幕上，可屏幕是离散的，于是通过光栅化把它打散成不同的 fragment——这是借 OpenGL 的一个概念，类比像素：不做多重采样抗锯齿（multisample antialiasing，MSAA）时，一个 fragment 就是一个像素；打散成像素之后，就可以对它进行着色，每个像素都知道自己应该长什么样，最后就知道整个屏幕上是什么颜色。如果用了 MSAA，那就是好多个不同的 fragment 共同决定一个像素的颜色——做过这次作业的同学都知道：维护每个 fragment（或者说 sample）对应的深度和颜色，最后再拼成一张图，就不会拼出三角形的黑边。

整个过程已经在硬件里写好了：现在的显卡所做的操作，基本上就是这么一套，整个在 GPU 里进行。

有个细节值得说：为什么我说"把三维空间中的点投影到屏幕上去，然后再连成三角形"？其实没有什么特殊的意义，就是我们定义模型的方式：定义所有的顶点，再定义每三个顶点形成一个三角形——把这两步定义分开，和直接定义一堆三角形是一回事。投影之后，点与点之间的连接关系不会变：原来是这三个点组成三角形，投影之后仍然是这三个投影点组成三角形。所以我只需要对顶点进行操作就可以了。

学过的东西都能对号入座。MVP 变换——每个顶点做一个变换——发生在顶点处理；对屏幕上每个像素中心采样、判断是否在三角形内，这一步就是光栅化；判定可见性的 Z-Buffer（深度缓存）就发生在这一块——当然严格意义上也可以把它归为光栅化的一部分，这里分得比较细。着色呢？顶点和像素上都会发生，为什么？这取决于着色频率：如果做 Gouraud 逐顶点着色，着色就发生在顶点处理阶段——顶点既可以做投影也可以做着色，没有任何问题；如果做逐像素的 Phong shading，那就得等像素都产生了，在 fragment 里做。

### Shader：可编程的着色器

现代 GPU 的这套渲染管线，允许其中一些部分是可编程的。所谓可编程，就是你说了算：顶点如何被着色、像素如何被着色，由你定义。写一段代码，就能生成各种各样不同的着色结果——整个实时渲染界几乎天天在做的事情，就是写这部分代码。这部分代码就叫 shader（着色器），它控制顶点和像素如何进行着色。

shader 有两个要点。第一，shader 是每个顶点或每个 fragment 执行一次的通用程序：你不用为每个像素单独指定怎么执行，写一份通用程序，每个像素都会这么执行——所以写 shader 不需要 for 循环，你只管一个顶点或一个像素怎么运作。第二，名字分两种：写顶点操作的叫 vertex shader（顶点着色器）；写像素操作的叫 fragment shader 或 pixel shader——片段着色器、像素着色器，翻译不同，一回事。

看一个具体的例子：用 OpenGL 的着色语言 GLSL 写的一个简单的像素着色器。它要干的事情：告诉系统这个像素最后的颜色是什么——写清楚怎么算这个颜色，并且输出出去。

```glsl
uniform sampler2D myTexture;   // 全局变量：一张纹理
uniform vec3 lightDir;         // 全局变量：光照方向（对所有像素固定）

varying vec2 uv;               // 插值得到的纹理坐标
varying vec3 norm;             // 插值得到的法线

void main() {
    vec3 kd = texture2D(myTexture, uv).rgb; // 漫反射系数，与纹理相关
    vec3 n  = normalize(norm);
    float diff = max(dot(n, lightDir), 0.0);
    gl_FragColor = vec4(kd * diff, 1.0);    // 这个像素/片段的颜色
}
```

逐段解析。`uniform` 指全局变量，跟 C++ 里一个道理：这里有两个——一个纹理（纹理是什么，马上讲），一个光照方向，表示每个像素都用同一个固定的光照方向，不会变。`uv` 和 `norm` 是插值出来的变量：比如顶点法线，一个三角形三个顶点各有各的，但你完全不用管——到了像素这一层，OpenGL 整套机制已经替你把插值做好了，你拿到的直接就是每个像素插值好的法线 `norm`。`kd` 是漫反射系数，怎么算跟纹理相关，这里先忽略。核心计算就是最简版的漫反射：假设光照是个常数（超级简化的版本），漫反射系数乘以 $l$ 和 $n$ 夹角的余弦——两个向量点乘——再做 max(·, 0) 的处理，结果肯定不会超过一。

> **注意**：这段着色器代码里的光照方向是"照向场景内部"的入射方向，与本课程"入射方向从着色点指向光源（朝外）"的约定相反，所以这里点乘前面没有负号。

算完把结果返回给 `gl_FragColor`，它就表示这个像素（片段）的颜色是什么。整体看，GLSL 和 C++ 非常相似：有全局变量，有插值出来的变量，中间是计算，还有各种方便的内置函数——比如 `dot` 算两向量点乘，`clamp(x, 0, 1)` 把值限制在 0 到 1 之间。向量类型也省事：咱们用 Eigen 要写 `Vector3f` 表示 float 型的三元向量，这里一个 `vec3` 就解决；`vec4` 还可以直接用一个 `vec3` 后面跟个数构造出来。所以 GLSL 其实很好写，你只需指定好每一个像素如何去着色。理解到这一点就没问题：shader 就是能定义任意顶点怎么操作、任意像素（片段）怎么操作。

### Shadertoy：浏览器里的着色器游乐场

回到第一节课埋的伏笔：讲到这儿，整条图形管线已经全部涵盖。把作业做下来就会发现，光栅化、成像、实时渲染的基本思路你都有了。在这个基础上再看一系列图形 API，会发现非常简单：你只需要指定场景中的东西怎么运动、怎么旋转、怎么摆放，相机怎么摆——那些矩阵都不用自己算，API 会帮你生成；想写着色，就在顶点或像素里实现着色器，语法也容易，很方便就能写出来。到此为止，大家已经可以用所学的知识真正写一些实时渲染的代码了。

给大家推荐一个网站：Shadertoy。它免去你搭 OpenGL、DirectX 那一堆背后的东西，只关注场景怎么渲染——也就是只写着色器（顶点和像素如何着色），在网页上直接执行、直接看结果。我每次提到 Shadertoy 都会感叹：shader 真是千变万化，可以做出非常惊人的东西。

比如那个著名的蜗牛例子。整只蜗牛不是用任何三角形定义的，而是由各种各样不同的几何形体定义——所谓隐式的几何形体，全部通过数学方法定义（之后讲几何的时候会说）。而且还能通过 shader 不断调整几何形体该长什么样；连这些形体怎么投影到屏幕上，都和三角形的投影不一样。材质也漂亮：壳的质感很像固体，有点 CAD 的味道；蜗牛本身看着是透明的、半透明的感觉。更厉害的是它还会动——整个动画也是在 shader 里做的，确实是大神。这是超级高端的例子，大家叹为观止就好；链接都有，学到这里（或者学完这门课）没什么压力的时候，自己上去写写 Shadertoy 上的 shader，是非常非常有趣的事情。

### 现代实时渲染：游戏引擎与 GPU

现代图形学的发展方向说起来很简单：随着 GPU（graphics processing unit）的发展，现在的显卡可以在很短的时间内处理大量的几何并放到屏幕上，而且着色非常快、高度并行——你着色这个像素的时候，有很多其他的像素在同步着色，可以想见有多快。目标就是：超级复杂的场景，实时渲染。比如 Unreal（虚幻引擎）的实时渲染场景。虚幻引擎非常厉害：你想做一个游戏，但不需要了解特别多图形学、人工智能的知识——各方面它都已经写好了现成的东西供你直接用。作为游戏引擎，它肯定要把这些方面做好，特别是图形：阴影怎么做、近似的实时全局光照怎么做，这些经典算法都已经实现好，放进实时画面里，开发者就可以专注游戏开发，而不用特别关心图形背后的实现。对行业这是好事情；但对我们来说，我们恰恰希望搞明白背后的东西。我也很期待游戏引擎之后往什么方向发展、能不能做得更好更逼真。

回到 GPU 本身。可以把 GPU 理解成整套图形管线的硬件实现：三角形怎么做各种光栅化、投影怎么做，这些都在硬件层面实现了；其中有一部分是可编程的，就是我们说的着色器。前面提到顶点着色器和片段/像素着色器两种；随着 GPU 和技术的发展，着色器的类型越来越多。比如 geometry shader（几何着色器）：说是着色器，其实相当于某种操作，你可以定义几何的操作，动态产生更多的三角形——这有什么好处，之后会说。还有更厉害的 compute shader：它可以做任何形式的计算，千万别把它理解成只能做图形学内部的计算——用 compute shader 可以完成各式各样的通用 GPU 计算（general-purpose GPU，GPGPU）。DirectX 12 这类新的东西，会在传统的基础上带来很多新技术，是非常值得期待的发展。

顺便说两句显卡。GPU 分两种：集成的显卡（集显）和独立显卡，打游戏的都知道。GPU 本质上是一个高度并行化的处理器。咱们说 CPU，i7、i9，48 核已经"不得了"了，AMD 还推出了 64 核——所谓核心数量，可以理解成可以并行的线程数量。GPU 的并行度——同时并行进行的数量——要远远超过 CPU 的几十：虽然每一个核心的性能并不是特别强，但胜在并行度极高，所以特别适合图形学这种活儿：很多像素的着色方法一模一样，我定义一份 shader，无数像素执行的代码基本相同，这就非常非常利于并行计算。

有同学问：作业跑出来的帧率很低，正常吗？正常，没问题——因为我们是在用 CPU 模拟 GPU 的过程。

### 纹理映射：给每个点不同的属性

管线告一段落，回来解决遗留问题：我希望得到一个三角形，内部填充了某一张图——这怎么做？这就是纹理映射（texture mapping）。

先看动机。一幅很简单的图：两盏台灯照亮一块地板和一个球。只盯着球看：如果认为台灯的灯光是点光源，无非就是两个点光源的贡献加起来；用 Blinn-Phong 只看漫反射，就是漫反射系数乘以光源的衰减、乘以接收的分量——都能算，没问题。可是球上不同位置有不同的颜色：这里有个五角星，这里是黄颜色，那里是蓝颜色。它们的基本区别是什么？它们其实共用同一个着色模型，只是本身的漫反射系数发生了改变。地板也是一样：假设它是漫反射的，被灯光照亮，但它在任何一个地方都有自己的漫反射系数——这个系数反映在木头的纹路上。

所以我们希望有一种方法，能对物体上的任何一个点定义它自己的属性。这就是引入纹理映射最基本的思路。倒不是说纹理只能拿来定义漫反射系数——它可以定义任何各种各样的东西，根本作用就是：定义任何一个点的不同属性。有同学问纹理和着色的区别与关系，可以这么答：纹理就是用来定义着色时需要的、各个不同点的属性——我不希望着色的时候每个点都以同一种方式被着色，就用纹理来改变各个点的属性，就这么个意思。

那这些属性定义在哪儿？定义在物体表面上——毕竟着色算的就是物体表面任何一个点的颜色。这里先做一个声明：任何一个三维物体，它的表面其实都是二维的。怎么理解？看地球仪：地球仪显然是个三维的球，但它表面那张"地图"可以撕下来——中间割一道口子，把整张图拿下来往平面上一放，不就变成一个平面了？有同学要抬杠：那多个物体呢？多个物体就把表面展开成多个平面再放到一块儿，还是一个平面。就是说这个意思。

> **定义**：三维物体的表面是二维的，因此可以和一张图建立一一对应的关系。

于是我们定义纹理（texture）：纹理就是一张图。这张图可以任你撕开用其中一块、拉伸、压缩——把它当成一张有弹性的图，蒙在任何一个三维物体的表面上，这个过程就叫纹理映射。映射自然是一个一一对应的关系：物体表面任何一个点，都能找到纹理上和它对应的点。

### UV：把三角形钉到纹理上

具体怎么贴？看独眼巨人的例子：左边是用 Blinn-Phong 渲染出来的结果，没问题；但现在我想让它身上出现一张图，怎么办？按刚才的思路，要把一张图贴到表面上去，就得知道怎么贴。三维空间里最基本的东西是三角形：只要知道物体上的一个三角形应该映射到纹理上的哪儿——它在纹理空间里是哪儿——就行了。换句话说，任意一个三角形的每个顶点，都能找到它在纹理上对应的点。

有同学要问了：这个对应关系我怎么知道？两个办法。第一，靠艺术家的创造：现在很多模型都是这么做的——模型做好之后，美工通过一种展开的方式，把模型的各个部分摆放到纹理的不同位置上，把对应关系定下来。我们就认为任何一个三角形映射到哪儿是已知的；当然对美工来说，这活儿是个非常繁重的过程。第二，自动化的过程：给任何一个模型，自动把它展开成一个平面，并且希望展开产生的三角形尽可能少扭曲——原来挺小的三角形，展开到平面上还是挺小；原来挺大的，还是应该挺大。如果能保证这种性质就更好了；要是整个物体本来是无缝衔接的，映射到纹理上对应的颜色也能无缝衔接，那就更好了。这很难，是几何上一个非常重大的研究方向，叫参数化（parameterization），是几何领域非常厉害的研究。咱们不管它，就认为映射关系已经有了：三角形上的任何一个顶点，都已经规定了它在纹理上的坐标。

既然说纹理上的坐标，那就得在纹理上定义一个坐标系，真正能指定纹理上任何一个点的坐标。纹理有自己的坐标系，习惯叫 UV。有个直观的展示：纹理是一张图，红颜色表示 u 方向的值大，绿颜色表示 v 方向的值大，不同的颜色就对应不同的 uv 坐标；把左边那个模型的每个三角形映射到纹理上显示出来，就能看到它展开后的样子。多说一句 UV 的范围：约定俗成，不管纹理是不是正方形——哪怕它是矩形、长方形——都认为 u 在 0 到 1 之间、v 也在 0 到 1 之间。为什么这么定？这算是相对简单的处理方法：不管分辨率是多少、长宽比是多少，u 沿一个方向 0 到 1，另一个方向 0 到 1，处理起来方便。

于是纹理映射的最小单元就定下来了：三角形的三个顶点，每一个顶点都对应一个 uv——这就是纹理映射。这个 uv 是怎么知道的？和前面一样：我们就认为已经知道。

### 可平铺的纹理

纹理可以贴在各种各样不同的物体表面，而且不止贴一次。看一个早期的渲染图——挺难看的，但它说明问题：如果把物体上每一个点的纹理坐标显示出来，会看到一块纹理占着 0 到 1 的范围；然后不断地重复它、重复它，就好像贴瓷砖：这一块对应地板或墙面的一块石头纹理，贴上，再不断重复，就能把整个物体贴满。

所以，谁也没说纹理只能用一次：不同的位置当然可以映射到相同的纹理位置上，重复多次就是了。比如场景里这个位置和那个位置，映射到纹理上其实是同一个地方，没有任何问题。

这里还能看到一个有意思的现象：把纹理左右一重复，在 UV 展开图上能明显看到一条条缝；可回到渲染出来的场景上看，没有缝。这说明什么？说明纹理本身设计得好：它往上、往下、往左、往右复制自己的时候，会无缝衔接——纹理的右边自然而然接上它自己的左边，上下也是这样。这种纹理在图形学里叫 tileable texture——tile 就是一块，tileable 就是可平铺的。设计这样的纹理需要各种各样的算法，其中有一种叫 Wang tiling（借了"王"这个姓氏的名字），是大家在用的其中一种。纹理的无缝衔接合成是非常值得研究的方向，这里先知道有这么回事。

### 留给下一讲：插值与重心坐标

最后剩一个自然而然的问题：我知道三角形三个顶点各自对应的纹理坐标 $(u, v)$，那三角形内部任何一个点对应的 uv 是多少？这又回到插值问题。

插值的通用说法是：三角形的三个顶点各有各的属性——颜色也好、法线也好、纹理坐标也好——如何把属性在三角形内部做一个平滑的过渡，让我对任何一个内部点都能立刻算出它对应的属性值？这就是要解决的问题，用的工具叫重心坐标（barycentric coordinates），下节课专门讲。这节课的纹理部分，说到这儿就够了。

最后再答一个问题：着色和材质有什么区别？基本没什么区别——不同的材质，就是不同的着色方法，可以这么理解。

下节课我们讲怎么做插值（重心坐标），然后把整个 shading 部分说完，再看看有没有时间说一些稍微复杂一点的话题。今天东西多，但相对简单，回去把对应的课件看一眼就差不多了。

今天这一讲，说来其实和着色本身已经没有太大关系了——着色的基本原理咱们已经说清楚了，这节课主要说的，是关于纹理的一些应用。

先把前两节课的账理一理。着色的主要内容咱们已经说清楚：从着色模型讲起，特别是 Blinn-Phong 着色模型，漫反射、高光、环境光我们都手推了一遍，合在一块，就能得到一个看起来很像塑料的材质。结论是什么？就是我们如何定义不同的材质或表面与光线如何作用，就可以得到怎样的外观。所以最重要的事情，就是研究清楚光线与材质如何作用——这个话题，等讲完光线追踪之后，还会给大家更详细地说。

着色可以应用在不同的地方：应用在整个面上，这是 flat shading；应用在顶点上，叫 Gouraud shading；应用在像素上，就叫 Phong shading。不管哪种，中间都涉及大量的插值。做 Gouraud shading，算出三个顶点的着色结果，再在三角形内部做插值；做 Phong shading，先在三个顶点上各放一条法线，把法线插值到三角形内部的任何一个像素上，然后再对这个像素做一次着色。不管怎么样，我们会用到很多插值的方法——所以今天主要就说这个事情。

硬件上如何实现？整个光栅化构成一套图形管线，或者说实时渲染管线，其中最重要的两块：一块是顶点的变换或处理，另一块是像素（片段）的处理。这两处现在都是可编程的：对顶点的操作进行编程，写的东西叫 vertex shader（顶点着色器）；相应地，对像素编程，写的就是像素着色器——今天会体验到它的应用。

最后是最简单的纹理映射：把三维空间中实际上是二维的物体表面，贴上一张图——纹理其实就是图。我们提前得到物体表面上各个不同位置如何映射到纹理的不同地方（也就是顶点上的 uv）。今天咱们就沿着这个思想把着色讲完。有时间的话还会讲阴影怎么生成——我觉得今天应该没时间，那就安心把着色部分说完。

要说的是三个部分：第一，重心坐标，我们用它来做插值；第二，纹理可以贴在物体表面，但这不能一句话就解决——怎么贴，要研究；第三，纹理的一些其他应用——它不单单可以指定一些颜色，还有很多非常强大的应用。咱们从第一个话题开始。

### 三角形内插值：为什么插、插什么

第一个话题：如何在三角形内部对任何属性进行插值。为此我们引入一个概念——重心坐标（barycentric coordinates）。

动手之前，先把两个问题搞清楚。

第一个问题：为什么要在三角形内部进行插值？刚才回忆上节课内容时其实已经给出了答案——我们有很多操作是在三角形的顶点上完成、计算的，而在三角形内部，我们希望得到一个平滑的过渡。也就是说：当我知道顶点的属性时，我希望在三角形内部的任何一个点都能得到一个值，并且这个值从一个顶点过渡到另一个顶点是平滑的。这就是我们需要插值的原因。

第二个问题：插值什么内容？定义在三角形顶点上的属性可以各种各样：

- **纹理坐标（uv）**：空间中的一个三角形，应该对应纹理上的哪一个三角形？把三角形"贴过去"，就是知道三个顶点分别映射到纹理上的哪些 uv——那三角形内部这些地方呢？
- **颜色**：一个三角形三个顶点分别是红、绿、蓝，中间应该有一个自然的过渡，这也可以插值。
- **法线**：Phong shading 下每个顶点都有自己的一条法线，三角形内部要先把法线插值出来，再对像素做着色。
- **深度**：光栅化把三角形打散成像素时，一个像素中心对应位置的深度是多少？也是在三个顶点上定义深度，再把它插值出来。

大家从这里可以看出：插值基本上可以对三角形顶点上的任意属性进行——事实上也就是这样。那么怎么做？这就轮到重心坐标出场了。

### 重心坐标：不用坐标系也能定点

先说清楚一件事：重心坐标是定义在一个三角形上的。给你一个三角形，你就定义了一套重心坐标；换了一个三角形，那就是另外一套。

> **定义**：在三角形 ABC 所在的平面内，任何一个点 $(x,y)$ 都可以表示成三个顶点坐标的线性组合，且三个系数之和为一。

$$P = \alpha A + \beta B + \gamma C, \qquad \alpha + \beta + \gamma = 1$$

这里的 A、B、C 指的都是坐标：A 就是 $(x_A, y_A)$，B 就是 $(x_B, y_B)$，道理一样。当条件满足时，我们就管 $\alpha$、$\beta$、$\gamma$ 这三个数合在一起作为一个坐标，用来描述点 $(x, y)$——这就是它的重心坐标。

这个定义值得咂摸一下：为了描述一个点的位置，我再也不需要什么直角坐标系之类的坐标系了。只要给我任意三个点，不管这三个点 A、B、C 是在什么样的坐标系里表示的，只要有一个点在三角形 ABC 所在的平面上，我都可以通过满足 $\alpha+\beta+\gamma=1$ 的三个系数，把这一点线性组合出来。

有同学要问：既然 $\alpha+\beta+\gamma=1$，那我有 $\alpha$、有 $\beta$，不就知道 $\gamma$ 是 $1-\alpha-\beta$ 了吗？没有任何问题，就是这样。也就是说，重心坐标虽然写着三个数，但受到这个条件的限制，其实它就是两个数。这其实是有道理的，对不对？三角形所在平面自然是二维的，二维的用两个数就可以表示了，为什么要三个呢？

那为什么非要规定和为一？这是重心坐标自己要求的事情：如果这个条件不满足，你得到的点就不在三角形所在的平面内。严格解释起来相对复杂一些，这里记住这个结论就行：$\alpha+\beta+\gamma=1$，是为了限制你所要的那个点落在三角形所在的平面内。

另外，如果还要求这个点在三角形**内**，得再满足一个条件：三个系数都必须非负，$\alpha \ge 0$、$\beta \ge 0$、$\gamma \ge 0$。注意这是两件事：只满足和为一，这个点一定在三角形所在平面内，但有可能在三角形外；三个系数都非负，这个点才一定在三角形内。

从定义立刻能读出三个顶点自己的重心坐标。A 点可以写成 $1 \cdot A + 0 \cdot B + 0 \cdot C$，所以 A 的重心坐标就是 $(1, 0, 0)$；同理，B 是 $(0, 1, 0)$，C 是 $(0, 0, 1)$。这就是直接从定义读出来的。

### 用面积比求重心坐标

知道了定义，任意一个点的重心坐标怎么求？重心坐标在这里给出了第二个定义：可以通过**面积比**求出来。

做法：对三角形内的任意一点 P，把它和 A、B、C 都连上线。连完之后你会发现，每一个顶点的对面都一定有一个小三角形。什么叫对面？就是和它不相邻的那个小三角形——比如 A 点对面的三角形，就是连线之后与 A 不相邻的那一块。

于是，以 $\alpha$ 为例：$\alpha$ 乘在 A 上、跟 A 在一起用，那就找 A 对面的小三角形，它的面积除以整个三角形 ABC 的面积，就是 $\alpha$。同样道理，$\gamma$ 跟 C 在一起用，就找 C 对面的小三角形，面积除以总面积。三个系数都能这样求出来。这也是重心坐标的另一个定义，当然它也可以从线性组合的定义推出来，这里就不多展开了。

$$\alpha = \frac{S_{PBC}}{S_{ABC}}, \qquad \beta = \frac{S_{PCA}}{S_{ABC}}, \qquad \gamma = \frac{S_{PAB}}{S_{ABC}}$$

其中 $S_{PBC}$ 表示由点 P 与顶点 B、C 围成的小三角形面积——正好是不包含 A 的那一块。面积怎么算？任何一个点给出来，我又知道 A、B、C 在哪，三个小三角形的顶点位置都齐了，用咱们之前教过的叉乘，把面积算出来，没有任何问题；这一套用叉乘算面积的做法，其实也能把上面的式子推出来。

从这个定义立刻能得到一个非常特殊的点：三角形自己的重心。把重心和 A、B、C 连起来，你会发现它把大三角形 ABC 均等地分成了三份——三个等面积的三角形。既然都是等面积的，根据刚才的公式直接一算：重心的重心坐标就是 $(\frac{1}{3}, \frac{1}{3}, \frac{1}{3})$。

对于任意点，还有一个更简化的办法：直接套坐标公式。给定任意点 $(x, y)$ 和 A、B、C 的坐标，公式可以把 $\alpha$、$\beta$ 直接算出来；由于规定了三个系数的和为一，$\gamma$ 不用算，直接由 $1-\alpha-\beta$ 得出。这个表达式没有任何必要去记忆——定义我们都清楚了，对任何一点都能算出它的重心坐标，这就够了。

### 用重心坐标插值任意属性

有了重心坐标，就可以直接拿它做事情：对三角形内部的任何一点，插值任何属性。

位置本身可以组合：$P = \alpha A + \beta B + \gamma C$。重心坐标告诉我们：要插值的属性，同样也应该用重心坐标把它线性组合出来。假如三个顶点上有三个属性 $V_A$、$V_B$、$V_C$，那么三角形内部任何一点（重心坐标为 $\alpha, \beta, \gamma$）的属性值就是：

$$V = \alpha V_A + \beta V_B + \gamma V_C$$

这个属性可以是任何东西：位置、纹理坐标（uv）、颜色——例子里插的就是颜色——或者法线；还有咱们之前提到的：光栅化的时候三角形被打散成像素，一个像素中心对应位置的深度，也是在三个顶点上定义深度再插值出来的。

也就是说，重心坐标允许我们先算出一个点位置的重心坐标在哪儿，然后再用重心坐标做插值。就这么用的。

### 投影会破坏重心坐标：深度插值必须回三维空间

这里专门说一个问题——大家以后读其他 OpenGL 相关文章时也可能碰到。

重心坐标虽然不错，应用起来非常简单：任何一个点只要有重心坐标，我就可以插值任何属性。但它有一个问题：在投影变换下，**不能够保证重心坐标不变**。

什么意思？假如空间中有一个三角形，我可以算出中间某一点 V 对应的重心坐标。如果我把它投影到某一个平面上去，三角形的形状会发生变化，对吧？A、B、C 和中间这个点投影之后的坐标，都能算出来；投影之后我再从投影后的三角形算一遍这个点的重心坐标——会发现得到了一个不一样的重心坐标。这是很有可能的事情。

所以重心坐标并没有"在投影下不变"这么一个好性质：三维空间中的三角形，一个点投影了之后，它的重心坐标就不一样了。这件事告诉我们：如果想插值**三维空间中的属性**，就应该取三维空间中的坐标——A、B、C 用三维空间中的坐标，中间那个点也取三维空间中的坐标，在三维空间中算出它的重心坐标、做好插值；而不能在投影之后的三角形里面做。

专门为了说什么呢？我想说的就是**深度**。想象一下：咱们之前说光栅化，三角形都已经投影到屏幕上去了，会覆盖很多像素，像素都有中心。像素中心这个点，我知道它在投影了的三角形的哪里，没错吧？那我能直接在投影的三角形里，对这三个顶点的深度做插值吗？其实是不对的。应该怎么算呢：找到你这个像素中心对应三角形位置的三维空间中的坐标，然后在三维空间中把 A、B、C 的深度插值好，再放回来——这样才是对的。至于怎么样把已经投影到屏幕上的点再投影回去，应用逆变换就可以了；这一步大家在这个专业中会稍微碰到一点点，但不要求大家去做。

> **提示**：三维空间中的属性，建议在三维空间中做插值，再把插好的值对应到二维的屏幕结果上。根本原因就一条：重心坐标本身在投影操作下会发生变化。

### 纹理映射最简用法：查到的颜色直接当 kd

重心坐标的插值说完了，下一步：怎么把纹理应用在实际的渲染中。

其实提 shader 的时候咱们已经说过这个流程。屏幕上的任何一个采样点——不管是像素，还是用 MSAA 时它所代表的采样点——自己肯定有一个位置。在这个位置上，我可以插值出它的 uv：纹理坐标原来都定义在三角形的顶点上，现在对于任何一个点，我知道它在三角形的哪儿，用咱们刚才说的重心坐标做插值，就可以算出这一个点的 uv。

uv 算出来之后怎么办？到纹理上去查询这个 uv 的值，我就知道对应的纹理是什么颜色了。那这个颜色可以怎么用？我们可以认为，纹理定义的就是**漫反射系数**——大家还记得 Blinn-Phong 模型里那个 `kd` 吧？直接用查到的 texel 颜色去代替 `kd`，不就等于是把这张图贴到了物体上嘛！而且物体还保留着 Blinn-Phong 模型能带来的明暗变化、高光这一系列效果。

就是这么简单：任何一个屏幕上的点，找到它的纹理坐标，直接查。至于查到的颜色怎么用？随便。到这里，纹理映射最朴素的用法就成立了。

### 纹理太小：放大的问题

那继续进展，下一步看它到底出了什么问题：如果这么简单地做，会出什么问题？

第一个问题，我们管它叫**纹理的放大**：纹理太小了怎么办？

设想一个三维场景渲染出来，我们对着一堵墙看，墙上有一幅贴画。墙要应用这幅贴画很简单，把图贴上去就好。但现在的问题是：渲染出来的分辨率是 4K，非常高；而我们的纹理只有 256×256。也就是说，看着一堵很高分辨率的墙，任意一个点去查纹理，会查到大量的非整数值。纹理太小，就会被拉大，自然就会看到问题。

正常情况下，做游戏的人都会避免这个问题——不会让你在很重要的地方用很低分辨率的纹理。但这种情况普遍意义上还是会发生，就是我刚才说的例子：高清的一堵墙，上面贴的图却很低清。

怎么办？很简单。对于墙上的任何一个点（任何一个像素），都可以找到它对应的纹理上的一个位置；这个位置可能不是整数。不是整数怎么办？那就把它四舍五入成整数——0.4 我认为它是 0，0.6 我认为它是 1。这样一来，屏幕上一定范围内的很多像素（比如周围 3×3、5×5 那么多）都会被映射到同一个 texel 上去——因为纹理太小了。

这里补一个术语：纹理上的像素有个名字，叫 `texel`，中文叫纹理元素，或者纹素——反正这个翻译挺别扭。咱们就这么区分：`pixel` 是我生成的画面上面的一个像素，`texel` 是纹理上的一个像素。

如果我们做简单的四舍五入，就会得到一幅一格一格的图，很难看。我希望引入点模糊没什么问题，但最起码结果要稍微连续一点。这背后真正的问题是：当我在查询纹理的时候，如果给我一个非整数的坐标，我应该如何得到它的值？这就是双线性插值要回答的。

### 双线性插值：先横后竖插两趟

看一个具体的查询：高分辨率屏幕上一个像素的中心，映射到了纹理上一个非整数的位置。周围这块 4×4 的格子是 texel，也就是纹理。我想知道：纹理在这个红点处的值是多少？

```text
u01 ─────────── u11
    │         │
    │    ●    │
    │         │
u00 ─────────── u10
```

图中 `●` 就是查询点（像素中心映射到的位置），$u_{00}$、$u_{10}$、$u_{01}$、$u_{11}$ 是它邻近的四个 texel。最简单的办法是找离它最近的 texel：查询点在这一小块里就都用同一个点的值——于是整个这一块都显示相同的颜色，形成一块一块的格子。现在不想这样了。查询点邻近的四个点总可以找得到，我们用它们来算出一个平滑的值。

先定义一个操作：**线性插值**（linear interpolation，简称 lerp）。$v_0$ 和 $v_1$ 分别定义在位置 0 和位置 1 上，$x$ 是一个 0 到 1 之间的值：$x=0$ 时取 $v_0$，$x=1$ 时取 $v_1$，$x=0.5$ 正好在两者中间，$x=0.9$ 就靠近 $v_1$ 那边。写成公式：

$$\mathrm{lerp}(v_0, v_1, x) = v_0 + x\,(v_1 - v_0)$$

有了这个操作，具体做法就清楚了。屏幕空间咱们定义过：从左下角开始向右向上；同样，这四个 texel 总有个左下角。查询点离左下角的水平距离记 $s$，竖直距离记 $t$——因为相邻两个 texel 的间距算作 1，所以 $s$、$t$ 肯定都在 0 到 1 之间。（这里说的 0~1 是相对最近 texel 网格的偏移比例，别和 uv 本身的取值范围搞混。）

然后三步走：先用 $s$ 对下边一条边的两个 texel（$u_{00}$、$u_{10}$）做线性插值，得到一个值；再用 $s$ 对上边一条边的两个 texel（$u_{01}$、$u_{11}$）做线性插值，得到另一个值；最后用 $t$ 把这两个值竖直插出来，就是查询点处的值。水平一趟、竖直一趟——两趟线性插值做完，这个点的颜色就综合考虑了周围四个点的颜色。

> **定义**：双线性插值 = 水平、竖直各做一趟线性插值。下边一条边用 $s$ 插出一个值，上边一条边用 $s$ 插出一个值，再用 $t$ 把这两个值竖直插出来。

效果也可以验证：查询点如果非常靠近 $u_{00}$，得到的结果就应该和 $u_{00}$ 很像；查询点如果在正中间，结果就正好是这四个点的平均值。于是在四个点围成的区域里，任何一点都能得到平滑过渡的颜色。这是一个不错的做法。

顺带回答一个常见疑问：方向能不能反过来，先竖直再水平？能，没有任何问题。大家可以手推一推公式，就会发现结果一样。

> **注意**："双"线性不是说总共只做两次插值——水平方向上其实做了两次——而是指水平、竖直两个方向都要做插值。

看效果：四舍五入的做法满是格子；双线性插值的结果，格子没有了，挺不错。当然它也有问题：和一些更高级的方法比，质量还是差一些。更高级的这种做法叫 bicubic——双向三次插值，这词儿翻译起来总别扭，咱们干脆就用英文。道理好理解：它取的不是周围邻近的 4 个点，而是 16 个；同样做水平竖直的插值，只不过每次用 4 个点做的是三次的插值，不是线性的。运算量肯定比 bilinear 大——它取周围 16 个，bilinear 只用周围 4 个——但它带来更好的结果：像人脸眼角这类细节处看得特别清楚，双线性插值在那里还能看到一定的锯齿状，bicubic 就看不出什么锯齿了。

这里大家又一次体会到图形学里频繁遇到的问题：好的质量的东西，往往都伴随着更高的开销。通常的做法是：先提出这么一个东西，再去想怎么把开销降下去、同时又能得到好质量。这基本上就是一个不断提高的思路。纹理放大的问题就说到这儿。

### 纹理太大反而更糟：走样又来了

双线性效果已经不错了。刚才说的是纹理太小、看着很大的平面，纹理被拉大会出问题。那现在想另外一个事情：**纹理太大了会怎么样**？

大家想一想：纹理大了有什么问题吗？小了我当然需要插值出来，大了我不需要啊，大了怎么会有问题呢？答案是：纹理太大反而会引起更严重的问题。这和第一直觉不太一致——大家会觉得纹理大的话什么信息都有，怎么会引起问题呢？咱们来看。

看这么一个平面，往远处延伸，能看到地平线。平面上贴了一张纹理：水平竖直的格子。从某个角度看过去，近处的格子挺大，远处的挺小——咱们做透视投影嘛，肯定是这样的。

现在如果还照之前的操作：像素中心，找纹理坐标，求出纹理坐标上的值——我们已经知道怎么插值了，所以任意的坐标都能查到值——把这个值写回像素。会得到一个非常非常不对的东西：远处出现了很熟悉的东西，叫**摩尔纹**（Moiré）；近处是很严重的锯齿。大家从这画面上看出来，这和之前遇到的现象完全一样：**走样**。咱们又遇到它了。而且近处多少还能看到，越往远处越差。

那这个问题到底是怎么来的？分析一下。近处，一个像素覆盖的纹理区域相对较小——用像素的中心查询一下它的值，就可以近似认为这就是这块区域纹理的值，没问题。可是在远处，一个像素其实覆盖了一大片纹理、一个很大的区域。这时候还用它的中心去查，说"我就看这一个点，这个点的值我就认为是整个这一块区域的平均值"——这首先就不对：我用这一个点，如何能代表这么大一个区域里面这些不同点的颜色变化？代表不了。所以当像素覆盖的纹理区域大的时候，就不能这么简单地用像素中心去采样了。

那大家自然而然会问：之前锯齿怎么解决的来着？抗锯齿——引入 MSAA，或者说超采样，差不多一个概念：一个像素用更多的样本，去感知这么一个变化的函数。这里同样也可以这么做：每个像素里面用 512 个采样点，把这些点对应的位置在纹理上算出来、取出值；对于远处的一个像素，取它这 512 个值的平均，就可以得到一个不错的结果。超采样能得到很好的结果，没问题；但是同样道理，用这么多采样点，肯定会让整个算法变得特别慢——咱们不希望这么做。

回来看理论上到底应该怎么分析。咱们遇到的是走样问题。走样是怎么来的？大家还记得吧：信号变化过快，我们的采样速度（采样频率）跟不上。在纹理过大这个问题上如何体现"采样"这个概念？很简单：当纹理特别大的时候，一个像素内部这块纹理一直在变化——也就是说一个像素内频率很高，可你只用了一个采样点去采样，那肯定不行。不需要任何公式，咱们想就能想明白：一个像素内有着非常高频的信息，我希望把这个像素内的值重构出来，那我就需要一个更高频的采样方法。这就是为什么我们需要在一个像素内放非常多的采样点、取值再平均——超采样做的就是这个事。

### 换个思路：不做点查询，做范围查询

沿着老思路走，一个像素真的要 512 个采样点，太多了。这里提供另外一个完全不一样的思路：**采样会引起走样，那咱们不采样怎么样？**

什么叫避免采样？刚才说了，像素会在纹理上覆盖很大的一块区域。如果我立刻就可以知道这个区域里它的值的平均是多少——不用采一堆点再平均——那就很好了。所以现在的问题变成：给你图上任何一个区域，你能不能快速地告诉我它的平均值是多少？这就是我们要的结果。

这里停一下，说点题外话——这其实是一个**算法问题**，在数据结构、计算几何等很多领域都得到了应用。它涉及两类查询：

| 查询类型 | 问题形式 | 图形学里的例子 |
| :--- | :--- | :--- |
| 点查询（point query） | 给你一个点，它的值是多少？ | 双线性插值，以及任何一次直接的纹理取值 |
| 范围查询（range query） | 给你一个区域，立刻得到它内部的平均值 | 接下来 mipmap 要做的事 |

点查询很好理解：以纹理为例，给你一个点，它的值是多少——咱们刚才说的双线性插值，说的都是这个道理。另一个是**范围查询**（range query）：不做采样，给你任何一个区域，立刻得到它内部的平均值。range query 是一个经典问题，算法上有各种不同的方法去研究它；在图形学上，大家找了一个非常近似的、但是很快的方法来做范围查询。

多说一句：范围查询可不只是"求平均"这一种应用。我们要求的是范围内的平均值，这是我们要的结果；也有些范围查询是要查范围内的最大值、最小值——那个问题就完全不一样了。范围查询有很多不同种类。

再回到渲染的画面上看需求：以实际渲染的这幅图为例，窗台这块离大家挺近，一个像素在纹理上覆盖的区域相对较小；这块区域离我们很远，那一个像素覆盖在纹理上就应该非常大——而且假设用的是同一张纹理。所以，这个范围查询应该能够查询**任意不同大小**的区域。这就是接下来 mipmap 登场的理由。

### Mipmap：用 1/3 的额外存储换快速方形范围查询

引入概念：**mipmap**。它是图形学上得到广泛应用的经典概念，能干什么现在就可以告诉大家：允许做范围查询——正是我们要的东西。但有三个词要说清楚：第一，快（fast），范围查询做得快；第二，近似（approximate），它做的范围查询是不准的，中间涉及到近似——但因为它快，大家希望的东西当然跑得越快越好；第三，它能做的仅仅是方形、特别只有是**正方形**的范围查询。这点跟大家说清楚：mipmap 可以做范围查询，但只能做近似的、正方形的范围查询。不是正方形的怎么办？马上再说。

> **注意**：记住 mipmap 的三个限定——快、近似、只支持正方形区域。第三条是后面 overblur 问题的一半根源。

mipmap 这个词是从拉丁语来的，意思就是很多不同的小的东西合在一块儿。对应到图上：mipmap 就是从一张图生成一系列图。原始的纹理叫第 0 层；第 $i$ 层是第 $i-1$ 层缩小到一半——分辨率砍半，这样说比较明确。比如原始纹理是 128×128，这是第 0 层；第 1 层把图重新表示成 64×64——图里看到像素被拉大了，那只是为了显示，各层画得一样大只是告诉大家现在分辨率是多少，其实分辨率已经小了一半了；第 2 层再砍一半，32×32；第 3 层 16×16……做到最后还剩一个点。既然每一次把一条边砍一半，那就要砍 $\log_2 128 = 7$ 次才砍到 1×1——一般地要砍 $\log_2(\text{分辨率})$ 次。层号记作 $d = 0, 1, 2, \ldots$

关键在于：这些层可以**提前计算**。大家拿到一个纹理之后，在渲染之前，先花点时间把这些对应的 mipmap 都生成好——这就是关键。这套东西在计算机视觉界不叫 mipmap，叫 image pyramid（图像金字塔），一模一样的概念。

用 mipmap 之前，先问大家一个概念问题：原本有一张图，占据了一定的存储量；咱们生成了那么多其他层的图，总共引入了多大的**额外**存储量？如果认为原本的存储是 1，那我们多花了多少？大家可以猜一猜。

很显然不是 8 倍——其他图都是越来越小的，不能说其他图和原图存储量一模一样；也不是 log（边长）那么多倍——肯定比那个小。小多少呢？这是一个级数求和的问题：每次边长砍一半，每一层的存储量就是上一层的 1/4：

$$1 + \frac{1}{4} + \frac{1}{16} + \frac{1}{64} + \cdots = \frac{4}{3}$$

4/3 是什么概念？原本的图存储量算 1，所有这些层加起来的存储量只是原来的 4/3——也就是说，**额外引入的存储量只是原图的 1/3**。这个事情很不可思议，对不对？当然，等比数列都好算，没什么问题。

这里其实还有一个更简单的理解办法。前提是你要已经知道额外存储是 1/3——不知道的话，你也构造不出这种理解方式；它只是方便大家理解。咱们要的只是一个比例，那把每一层的存储都乘以 3，肯定不影响结果：把三份原图（第 0 层）分别放进一个大 2×2 块的左上、右上、左下三个格子；剩下右下角这一块，恰好可以把第 1 层也复制三份、按同样的摆法填进去；又缺了一个右下角，再把第 2 层的三份填上去……不管多少层，一直填下去，最后得到的极限就是恰好填满整个 2×2 块。于是 $3 \times$（所有层之和）$= 4 \times$（第 0 层），所有层之和是 $4/3$，额外存储自然就是 $1/3$。这是一个很精妙的论证。

```text
把每一层的存储都乘以 3（只看比例，不影响结论）：

┌──────────────┬──────────────┐
│              │              │
│      L0      │      L0      │  ← 左上、右上放第 0 层
│              │              │
├──────────────┼───────┬──────┤
│              │       │      │  ← 右下象限里放 3 份第 1 层
│      L0      │  L1   │  L1  │     （上左、上右、下左）
│              ├───────┼──┬───┤
│              │  L1   │L2│L2 │  ← 再剩的角放 3 份第 2 层……
└──────────────┴───────┴──┴───┘     无限嵌套，恰好填满整个 2×2 块
```

图中 L0、L1、L2 即第 0、1、2 层：三个 L0 占满左上、右上、左下三个象限；右下象限里以同样方式放三个 L1，又剩的角里放三个 L2，如此一直嵌套下去。

这也就是说：mipmap 仅仅是额外 1/3 的存储，所以非常好。

### 查询落在哪一层：像素足迹的近似

那有同学问了：我怎么知道我上来要查询的区域有多大、长什么样？它是不是都可以映射到纹理上的一个区域？

有一个近似的办法，很简单。我们认为一个像素（采样点）有它自己的中心，它的邻居也有中心。把这个点自己的中心、它右边邻居的中心、它上边邻居的中心，分别都投影到纹理（uv）上去：屏幕上，这个点到右边邻居的距离是一个像素，到上面邻居的距离也是一个像素；这三个点各自映射到纹理上之后，就能求出它们在纹理上占据的距离。

```text
┌───┬───┐
│N2 │   │      P  = 当前采样点（像素中心）
├───┼───┤      N1 = 右边邻居，N2 = 上边邻居
│ P │N1 │
└───┴───┘      把 P、N1、N2 的中心分别投影到纹理空间：
               L1 = P 与 N1 投影后的距离
               L2 = P 与 N2 投影后的距离
               L  = max(L1, L2)
```

记 $L_1$ 为这个点和它右边那个点映射到纹理空间后的距离，$L_2$ 为它和上面那个点映射后的距离。这两个长度当然可能会有所不同，简单起见，取最大的就可以了：$L = \max(L_1, L_2)$。这样就可以近似得出：假设这个像素覆盖的区域在纹理空间上仍然是一个正方形，它的边长就是 $L$——用一个正方形框，来近似这个像素实际覆盖的不规则区域。

写成偏微分的形式，就是下面这个看着有点复杂的式子——其实完全不是那么复杂，目的就是为了求这两个投影长度：

$$L = \max\left(\sqrt{\Big(\frac{\partial u}{\partial x}\Big)^{2} + \Big(\frac{\partial v}{\partial x}\Big)^{2}},\ \sqrt{\Big(\frac{\partial u}{\partial y}\Big)^{2} + \Big(\frac{\partial v}{\partial y}\Big)^{2}}\right)$$

这个计算其实相当于做了一个 finite difference（有限差分）：屏幕上一个点往某个方向移动一个像素的距离，我要知道它在纹理空间上要移动多少距离——说白了，相当于算了一个简单的微分。但咱们完全不用按微分去理解，就把右边和上面的点投影到纹理空间上、求对应的长度就行。

有同学说：那我能不能把像素的四个顶点都投影过去，用映射过去的四个顶点算出四个边长、再取最大？绝对可以，没问题——反正都是近似。

> **提示**：这套"右邻、上邻投影取最大"的算法，本质就是一句话——用 uv 沿屏幕两个方向的变化速度，估计该像素覆盖的纹理区域大小。

真正关键的问题来了：当我可以把任何一个像素覆盖的区域近似成为一个边长为 $L$ 的正方形之后，这个正方形的查询要怎么做？如何根据之前预计算好的 mipmap，查出边长为 $L$ 的区域的平均值？这就是 mipmap 聪明的地方。

问大家一个问题：如果这个区域的大小就是 1×1——一个 texel——那我直接在最原始的、没做过 mipmap 的那张纹理上找对应的 texel，它的值就是答案，对不对？那如果区域的大小是 4×4 呢？这个区域一定会在第二层上变成一个 texel：4×4 的区域，经过第一层 mipmap 之后变成 2×2，经过第二层之后变成 1×1。一般的规律：$L \times L$ 大小的区域，在第 $D = \log_2 L$ 层上一定对应到一个 texel。

也就是说，我要通过这个区域求出它在第几层会变成一个 texel 的大小，然后去查那个 texel，就可以立刻得出这个区域内的平均值是多少。这就是为什么查询是在第 $\log_2 L$ 层进行的。

如果对每个像素都算一遍它会投影到纹理上对应多大的区域、要在第几层 mipmap 上去找平均值，还可以做一个可视化：离我们非常近的地方，一个像素覆盖的区域小，颜色就非常深——要在很低的层去查，这里能看到很多细节；离我们特别远的地方，一个像素覆盖的区域非常大，就要在高层查。整体上，颜色基本是一个渐变。

但大家会发现一个问题：这个变化好像**不怎么连续**。我在某一区域是第 0 层查，突然到这儿，哎，我应该第 1 层查了；再往前，突然又该第 2 层查了。为什么？因为我们之前只算了离散的若干层——第 0 层、第 1 层、第 2 层，可没算 1.5 层是什么。咱们肯定不希望它在不同的层之间跳变——这样的话，查询到的结果保不准在层切换的地方就形成一道缝，不连续。那怎么办？我们希望它真正能查询"第 1.8 层"是什么东西。

### 三线性插值：把层与层的缝隙抹平

有第 1 层、有第 2 层……要查第 1.8 层，怎么办？很显然，大家又想到那个概念了——插值。

做法：我先在第 1 层内部用双线性插值，把这一层上对应位置的值查出来；再在第 2 层内部用双线性插值，把那一层的值也查出来。做出来之后，把这两个双线性插值的结果合在一块，在**层与层之间**再做一次线性插值——要的是第 1.8 层，那自然就是 0.8 的权重给第 1 层的结果、0.2 给第 2 层的结果。

这可不是第三种什么新式的插值——水平、竖直、再加层间，总共三步插值：双线性之上再加一个线性插值，所以我们管它叫**三线性插值**（trilinear interpolation）。

这样一来就没有任何死角了：在纹理内部，不管是整数坐标还是非整数坐标，都可以用双线性插值出一个平滑过渡的值；层与层之间，也可以插值出连续的值。对任何查询区域，通过三线性插值做一次查询，就可以得到这个区域所覆盖的整个面积内的平均值。

结果太漂亮了：原本黑了一片的地方，黑的和红的有了一个过渡；不同的区域——比如黄的和绿的——也有了连续变化的结果。（柱子上有些问题，那是几何本身的问题，咱们暂时不说。）基本上，通过三线性插值，我在某一个浮点型的、连续的层上查询，就可以了。

三线性插值非常有用，这就是为什么它在各种各样的游戏、各种实时渲染中间得到了非常广泛的应用——因为它可以得到一个完全连续的表达：层内部连续，层与层之间也连续。而它本身的开销呢？无非是做两次查询、再做一次插值，所以开销挺小。这就是为什么现在的游戏或者什么东西，默认都有这么一项选择。大家可以打任何游戏，试着把这项插值关掉、再打开，比较一下效果。

### Overblur：Mipmap 远处糊得过分

mipmap 效果挺好的，可是它是否真能完全解决问题？这是我们要思考的事情。

做个对照：我们认为一个像素用 512 个采样点应该已经够了，那就假设这个 512 倍超采样能够给我们准确的结果——也差不多，就当它是准确的。拿它和 mipmap 比，会发现区别：mipmap 到了远处的地方，会把所有的细节全部糊掉，出现了完完全全不应该糊掉的东西。这种情况我们管它叫 **overblur**——很简单，模糊得过分了。

为什么会出现这种情况？如果 mipmap 是对的，那一定不会有这个问题；它肯定哪儿不对。其实咱们一开始已经说过了：它首先只能查询方块——正方形区域——内的平均值；而且三线性插值本身也是近似插值，毕竟不是真正能算出来。

咱们先从方形查询这一点说。屏幕上一个像素映射到纹理上，可不一定都是一个规律的形状——很有可能出现超级斜着的区域。这种情况下，我要把它近似成一个方形的框，把这个框给框起来——你会发现，那我可不是求了一个**更大的区域**的平均嘛！框比实际的覆盖区域大了一圈，平均自然就糊——也就是说，这就会造成 overblur。

有没有办法？有一个办法可以部分解决三线性插值（mipmap）所产生的问题。

### 各向异性过滤：矩形范围查询与 Ripmap

这个办法叫**各向异性过滤**。打游戏打得多的话，估计大家接触过。它的效果会比三线性插值好：从这个例子上可以明显看出来，远处已经明显可以看到细节了，不是完全糊掉的。

先把名字说清楚。什么叫各向异性？就是在不同的方向上，它的表现各不相同。我们原本认为（正方形）在水平、竖直方向上的表现完全相同，这种就叫各向同性。有同学硬要说：一个矩形在各个方向上还是不一样的——确实是这样，但基本上我们还是认为它是各向同性的。各向异性，指的就是可以考虑不同的所谓**方向性**。就这个意思。

mipmap 本身做了什么事情？给你一张原始的图，把长宽各缩小一半、再各缩小一半……反映在预计算的图集上，mipmap 计算的其实只是**对角线上**的那么一些图片。各向异性过滤多做一些：对不同的长宽比也做预计算，这是 mipmap 没有的。比如看第一行：竖直方向的长度没有变化，只是水平方向被压缩了一下，而且每一行都是这么做的；再看每一列：宽度都不变，高度会发生变化。也就是说，它的结构比 mipmap 要多出一些东西。

```text
     Mipmap：只预计算对角线            Ripmap：整个网格都预计算
┌────┬────┬────┬────┐            ┌────┬────┬────┬────┐
│ ▓  │    │    │    │            │原图│横压│横压│横压│
├────┼────┼────┼────┤            ├────┼────┼────┼────┤
│    │ ▓  │    │    │            │纵压│    │    │    │
├────┼────┼────┼────┤            ├────┼────┼────┼────┤
│    │    │ ▓  │    │            │纵压│    │    │    │
├────┼────┼────┼────┤            ├────┼────┼────┼────┤
│    │    │    │ ▓  │            │纵压│    │    │    │
└────┴────┴────┴────┘            └────┴────┴────┴────┘
```

左图：mipmap 的预计算只有对角线（长宽等比缩小，▓ 表示算过的层）；右图：ripmap 把水平压缩（横压）、竖直压缩（纵压）各种组合全都预计算出来——这种"水平、竖直各自压扁"生成的图集本身有个名字，叫 **ripmap**。平常大家很少提这个概念，没有关系——反正这就是各向异性过滤背后的那套结构。

它为什么管用？看图集里一幅被竖直方向压缩得非常厉害的图：它的一个 texel，对应回原始的图上，是一个竖直方向拉伸了的区域——一个**矩形**区域。也就是说，通过这种方式的预计算，我可以查询任何一幅被压扁的图的任何一个位置，查到它对应原始图上的一个矩形区域，而不用限制在正方形区域上。屏幕上一个像素映射到纹理上的覆盖区域，如果是这种基本长条形的，各向异性过滤就允许我们对长条形的区域做一个快速的范围查询，自然得到的结果就会好很多——长条形的问题基本得到完美的解决。

但它仍然没能完全解决问题：倘若查询范围真的特别坑，是斜着的一块区域——就像前面说的那种超级斜的区域——拿一个矩形去框它，也不是特别好。总结一下各向异性过滤：它解决了一部分问题，对于矩形的查询可以得到一个更准确的结果，比正方形的 mipmap 要好；但是对于斜着的区域，没有办法。

存储开销呢？利用刚才分析 mipmap 的方法算一下：要生成各向异性过滤的这些中间的压扁图，总共的开销是原本的**三倍**——对比一下，mipmap 的额外开销只是原本的 1/3。这就是代价。

最后说说游戏里那个"多少 x"。大家打游戏还会接触到一个概念：2x、4x、8x、16x 各向异性过滤。意思就是说你计算多少层：2x 基本上就是在一个方向上压缩了一次，对应左上角那一小块 2×2 的图区域；4x 就是在竖直方向上又压缩了一倍，水平方向上也是一样，各多生成一块区域；8x、16x 一样往上加。大家会发现，随着这个 x 逐渐往上增加，最后的结果会逐渐收敛到总存储的三倍。也就是说，各向异性过滤的存储量，其实你开多少 x 关系不大。

> **提示**：各向异性过滤和计算力基本没有关系，只对显存有一点要求——其实也没有多少。所以只要显卡显存足够，游戏里尽量把各向异性过滤开到最高就好了：它对性能几乎不会有任何影响，显存也只是多那么一点点。

### EWA 过滤：不规则区域拆成多个椭圆

那斜着的区域到底怎么办？人们又发明了一些另外的方法，给大家举一个例子：**EWA 过滤**。

思路其实很简单：任意一个不规则的形状，都可以把它拆成很多不同的椭圆（圆）去覆盖。比如一个椭圆形状的覆盖区域，可以拆成三个不同的圆形去覆盖它；然后每一次我去查询一个圆形，多次查询下来，自然就可以覆盖这么一个不规则的形状。

当然可以，但代价大家应该已经听出来了：多次查询——查询肯定是要耗时的嘛。所以又一次体验到这个规律：质量越好，代价越大，一定对。

三种方案摆在一起看：

| 方案 | 能覆盖的查询形状 | 存储开销 | 主要局限 |
| :--- | :--- | :--- | :--- |
| Mipmap + 三线性插值 | 正方形（近似） | 额外 1/3 | 斜向区域被大方框罩住，造成 overblur |
| Ripmap（各向异性过滤） | 矩形 | 3 倍 | 斜向区域仍然无法准确查询 |
| EWA 过滤 | 任意不规则区域（拆成多个椭圆/圆覆盖） | —— | 多次查询，更耗时 |

到这儿，mipmap 这一块涉及的问题就整个说完了。
