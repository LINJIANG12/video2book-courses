# 仿真角色的驱动与控制

## 刚体仿真的基本框架

### 质点、刚体与惯性

   * **质点（particle）**

       * > **定义**：只有位置和速度、没有形状的最简物理对象，运动遵循牛顿第二定律 $F = ma$。

       * 旋转对质点不是一件事：不管质点怎么"旋转"，它所代表的状态都完全等价，因此质点没有朝向这个状态量。

       * 想让质点产生想要的运动，需要加一个合适的外力：力产生加速度，加速度再通过积分更新速度和位置，形成动作。

   * **刚体（rigid body）**

       * > **定义**：有形状的物理对象；刚体在不同朝向之下能观察到的外观不一样，不同朝向代表着刚体的不同状态——这是与质点完全不一样的地方。

       * 朝向（旋转）是角度的量、非线性的量：旋转矩阵的导数跟角速度之间还差一个坐标转换关系；IK 之所以要算 Jacobian，本质上就源于这种非线性。

       * 朝向的变化率本质上就是角速度 $\omega$。

   * **质量与转动惯量**

       * > **定义**：质量衡量物体抵抗线运动状态改变的能力；惯性张量（inertia tensor），也常叫转动惯量，衡量刚体抵抗旋转状态改变的能力——二者是同一个"惯性"概念在线性和角度上的两面。

       * 转动惯量本质上是每个质点自己的角动量在整个刚体上积分之后体现出来的整体效果，所以物体质量更大时转动惯量通常也更大。

       * 转动惯量跟物体形状有很大关系：质量分布越靠近物体的边缘，转动惯量通常越大；质量相同、初始状态相同的几个球，只要形状（质量分布）不同、转动惯量不同，整体运动表现就可能完全不一样。

### 力、力矩与刚体运动方程

   * **力矩（torque）**

       * > **定义**：让刚体角速度发生变化的"角度方向的力"，本质等价于力臂乘以力：$\tau = r \times F$，代表一个力对物体旋转带来的影响。

       * 任何一个外力都自带力矩的作用。

   * **欧拉运动定律（Euler's law of motion）**

       * > **定义**：角动量的时间变化率等于力矩：$\tau = \frac{\mathrm{d}L}{\mathrm{d}t} = I\alpha + \omega \times (I\omega)$。

       * 线性方向的定律是牛顿第二定律（动量的时间变化率等于力）；牛顿第二定律其实也算是欧拉运动定律的其中之一——欧拉定律相当于把线、角两条定律合在一起。

       * 比线性多出叉乘项的原因：转动惯量跟物体的形状和朝向同时相关，朝向一直在变、转动惯量也跟着变，所以对角动量求导除了"转动惯量 × 角加速度"之外，当前的角速度自己也会贡献一项额外的效应 $\omega \times (I\omega)$——它不是力，但代表了某种力的效应。

   * **刚体运动方程（equations of motion）**

       * 把力和力矩合到一起可以写成矩阵形式的运动方程：给定外力和外力矩，求解方程得到加速度（速度变化率）和角加速度，再通过积分得到最终的动作。

| | 线性（质点） | 角度（刚体） |
| :--- | :--- | :--- |
| 状态 | 位置 $x$、速度 $v$ | 朝向 $R$、角速度 $\omega$ |
| 惯性 | 质量 $m$ | 转动惯量 $I$ |
| 被什么驱动 | 力 $F$ | 力矩 $\tau$ |
| 运动定律 | $F=\frac{\mathrm{d}p}{\mathrm{d}t}$ | $\tau=\frac{\mathrm{d}L}{\mathrm{d}t}$ |

       * 刚体仿真就是这张表的两列同时上演：线性一侧和角度一侧各算各的，又通过"每个力都自带力矩"纠缠在一起。

### 在物理引擎里定义刚体与角色

   * **刚体的定义参数**

       * 惯性部分：质量和转动惯量，是相对固定的一组量，不管刚体怎么动都不变。

       * 运动部分：位置、朝向、速度、角速度。

       * 几何部分：形状（geometry）；不管什么物理引擎——游戏里常见的如 Bullet、Havok，各家大同小异——这些量都得给。

       * 刚体可以当成抽象对象看：不关心它具体长什么形状，只关心在给定质量和转动惯量之后、加上一个力会产生什么样的运动变化——形状本身与刚体的定义相对独立。

   * **形状带来的四类影响**

       * 外观：看到的物体到底长什么样——box、球、立方体，还是 mesh（人形、动物这样的网格）。

       * 转动惯量：box、球、球壳、实心球都会带来不同的转动惯量。

       * 质量：某种程度上跟形状相关——密度基本都跟水差不多，体积其实就代表了重量。

       * 碰撞检测：人能站在地上，是因为地面给了脚一个支持力；地面应该在什么地方给支持力，必须告诉引擎脚的形状。

   * **关节（joint）是一种约束**

       * > **定义**：两个物体在运动过程中必须满足、且不发生变化的某个相对关系（如"不能分开"）。

       * 为了维持这个相对关系得有力：两个刚体在运动中出现分开倾向时，约束会相应产生一个约束力，把它们拉住、保持合在一起——如同抓着一个物体往前扔时，不想让它离手就必须不断加力。

       * 一旦算出约束力，两个刚体本质上又是在所有外力之下独立运动的刚体：运动方程拼成更大的方程，关节约束是这些方程之外的额外方程，约束力由约束方程给出。

       * 更多物体也一样：正常人有十几个刚体和关节，构成更大的系统，每个关节带来相应的一行约束与一个对应的约束力；整个仿真就是构造含约束方程的运动方程、求解得到加速度、最后通过欧拉积分得到动作。

   * **在仿真器里搭建角色**

       * 人形角色的每个关节总是连接两个刚体，所以关节数比刚体数少一个，刚好保证整个连接关系成立。

       * 定义两块东西：每个刚体的各种属性（位置、朝向、转动惯量等），以及每个关节的性质（初始位置、类型）。

       * 仿真中通常用胶囊体（capsule）、立方体（box）、球（sphere）这类简单几何体代替角色外观网格，本质是为了碰撞检测：碰撞检测要判断两个几何体是否相交、相交位置在哪，还要能判断相交处哪一侧在物体里边、哪一侧在外边；不规则网格基本得把整个网格遍历一遍、里外也不好判断，简单几何体在这两件事上都轻松得多，能显著提高效率（也不绝对，很多时候也可以直接用 mesh）。

       * 关节初始位置的含义：关节在第一个刚体局部坐标系下对应的位置，和它在第二个刚体局部坐标系下对应的位置永远重合；这一对"对应位置"由初始化时关节的位置以及两个刚体的位置共同定义。

       * 关节类型带来更多约束：膝盖是单自由度关节，突然向旁边弯过去（骨折）肯定不对；hinge 关节除了要求关节两端不会分开之外，还要求在 hinge 这一个自由度之外的其他自由度上，两个刚体的旋转是相同的。

### 仿真器黑盒流水线

```text
t 时刻状态：每个刚体的位置、朝向、速度、角速度
   │
   ▼
┌─ 动力学仿真器（黑盒内部）──────────────────
│  1. 接触检测：脚的哪些部分跟地面接触
│  2. 碰撞建模：法向 penalty 力，或当作约束求解
│  3. 关节约束建模 + 其他用户输入建模
│  4. 构造运动方程并求解 → 得到加速度
│  5. 辛欧拉积分：先由加速度更新速度，
│     再用新速度更新位置
└──────────────────────────────────────────────
   │
   ▼
t+1 时刻状态：每个刚体新的位置、朝向、速度、角速度
```

   * **状态清单里没有关节位置**

       * 关节本身是一个约束，总满足"相对于某个刚体的相对位置保持不变"；只要知道每个刚体（每段肢体）的位置、朝向，对应关节的状态可以很容易地算出来，不需要单独存。

   * **接触检测（contact detection）**

       * 仿真器每个时间步先判断脚的哪些部分跟地面接触；接触之后要加上相应的碰撞模型。

   * **碰撞的两种建模**

       * 法向 penalty 模型：根据脚跟地面相交（穿透）的程度计算一个力，这个力保证脚是压在地面上的。

       * 约束式：把碰撞变成一个类似关节约束的约束来实现，在求解运动方程的过程中自动算出这个力。

   * **辛欧拉积分（symplectic Euler）**

       * 解出加速度后做两次积分：先积分加速度得到速度的更新，再用更新后的速度去更新位置——半隐式欧拉的积分方式，最终生成动作。

   * **ragdoll（布娃娃）**

       * > **定义**：把角色直接建入仿真器、不加任何控制跑出来的仿真形态：动作本身物理真实、完全满足物理规律，但只会瘫倒、摊成一堆——角色单纯在重力作用下运动。

       * 常见用途：表现角色失去意识时的动作。

       * 真实世界对应：人的神经反射有一定时间（约 0.2 秒），被绊倒之类突发事件后的零点几秒内大脑来不及反应，动作差不多就是 ragdoll 仿真；不过肌肉本身还有带弹性的一点点反抗力量，不会瘫得那么干净。

## 力矩驱动与关节力矩

   * **物理仿真只能加力，不能摆姿势**

       * 关键帧动画想让角色到达某个状态，直接把状态、位置设置成对应姿态即可；物理仿真不能这么干——只能在每个关节上、每个物体上施加力和力矩，这些力和力矩体现在运动方程里，改变每个刚体的速度、加速度，从而影响动作。这是物理仿真跟关键帧动画最大的区别。

   * **力的等效：合力加质心**

       * 不管加了多少力、在刚体的什么位置加力，最终都等价于"加在质心上的一个合力"加上"以质心为轴的一个力矩"；偏要加在刚体旁边也可以，等价于在质心上加一个同样大小的力，同时在质心上额外产生一个力矩效果。

       * 不加力、单纯只加一个力矩，等价于加了一对大小相同、方向相反的力：这对力在质心上的合力是零、不会产生质心速度的变化，但会让物体产生旋转的效应。

       * > **易错点**：⚠️ 对一个真实的物体，不可能"把一个力矩加上去"——力矩本质上只是数学描述，所有的力矩本质上都是力产生的效果（让角速度发生变化的那类效果），可以近似认为力矩就是一对力产生的效果。

   * **关节力矩（joint torque）**

       * > **定义**：驱动用关节连接在一起的一对刚体时，加在关节上的力矩；物理图像是把关节放大看成一个电机——磁场作用在线圈上产生一系列的力，这些力大小相同、方向相反，合力为零、总效果是一个力矩。

       * 落到刚体上的方式：在其中一个刚体上施加大小为 $\tau$ 的力矩，同时在另一个刚体上施加 $-\tau$ 的反作用力矩——习惯上把关节远离 root 一侧的刚体叫 child（子刚体），靠近 root 一侧的叫 parent（父刚体），child 加正向力矩 $+\tau$，parent 加反向力矩 $-\tau$。

       * 推导关键：设关节中心相对第一个刚体质心的位移是 $r_1$、各施力点相对关节中心的位移是 $r_i$，总力矩为 $\tau = \sum_i (r_1 + r_i) \times f_i = r_1 \times \sum_i f_i + \sum_i r_i \times f_i$；考虑到这组力本身合力为零（$\sum_i f_i = 0$），$r_1$ 项直接约掉，只剩 $\tau = \sum_i r_i \times f_i$——等效力矩跟关节装在刚体的哪个位置没有关系，只跟关节内部施力点相对于关节中心的距离 $r_i$ 相关。

       * 第二个刚体受到的是牛顿第三定律给出的相反反作用力组（推导完全一样，每个 $f_i$ 前面多个负号），同样因为合力为零，$r_2$ 的部分也被约掉。

```text
        root 方向
           │
     [parent 刚体]   ←── 施加 −τ（反向力矩）
           │
           ●  关节（想成一个电机：内部是一系列
           │     大小相同、方向相反的力，合力 = 0，
           │     总力矩 = τ）
           │
     [child 刚体]    ←── 施加 +τ（正向力矩）
           │
        远离 root 方向
```

   * **控制器（controller）**

       * > **定义**：根据角色当前的状态（位置、朝向、速度、角速度等），再加上额外的控制信号（想做什么动作、走到什么地方），实时地为每一个关节计算关节力矩、交给运动方程和仿真器去影响角色动作变化的模块。

       * "在每个关节上加力矩"只回答了加什么，力矩数值从哪来由控制器回答——这就是运动控制的整个过程。

## 运动方程的两种用法与欠驱动

### 前向动力学与逆动力学

   * **运动方程连接的两端**

       * 本质上就是 $f = ma$：左边是质量项贡献的加速度，再加上由速度带来的一部分所谓的惯性力；右边是加的外力以及约束力——方程在加速度和外力之间建立起连接。

   * **前向动力学（forward dynamics）**

       * > **定义**：给出加的所有外力（关节力矩、重力、碰撞力等），从当前状态求解运动方程得到加速度，进而算出 motion、算出动作的用法。

       * 通常讲的物理引擎、仿真器，实际上就是一个前向动力学的求解过程。

   * **逆动力学（inverse dynamics）**

       * > **定义**：已知一个加速度，反算这时候应该加多少力才能产生它——跟前向动力学刚好相反的过程。

       * 前向、逆动力学都是同一个运动方程的两种用法：方程还是那一个，只是给出的已知量不同、要求解的另一个量对应不同；控制部分在某种程度上可以认为是逆动力学（实际的控制要更复杂一点）。

```text
      想要的动作
          │  控制器（逆动力学）：想要什么动作，反推需要多大的力
          ▼
      关节力矩 τ
          │  仿真器（前向动力学）：解运动方程得加速度
          ▼
      加速度 → 速度 → 运动
          │
          ▼
      角色状态 ──▶ 回到控制器，循环往复
```

### 欠驱动与完全驱动

   * **欠驱动系统（underactuated）**

       * > **定义**：驱动力的自由度比角色本身状态的自由度要小的系统。

       * 人形角色是非常典型的欠驱动系统：根关节不固定，没有办法直接更改根关节的性质；关节数量比刚体数量少一个，关节所能提供的驱动自由度就一定比所有刚体状态的自由度总和要小。

       * 直观表现是无法直接控制全局姿态：宇航员在空间站失重且没有接触时只会漂浮，可以改变身体姿态，但整体质心、全身的位置不会变化——缺少对全身质心进行控制的力。

       * 走路同理：要小心地"控制地面"——给地面一个力，希望反作用力推动质心向前移动同时让自己不摔倒；本质是不可能直接控制质心位置，只能间接对外界施加影响、指望外界带来反作用。

       * 严格表述：完全驱动系统对任何一个运动目标（比如一个加速度）总能找到一组力产生它；欠驱动系统对很多需要的加速度没有办法找到一组力——驱动力自由度不足，无法产生所有想要的力矩。

       * 控制本质：希望系统不要落到无法控制的状态之下——系统总有一些状态可控，控制要做的就是始终待在可控范围里；保持平衡、走路等控制的主要目的就是这个。小脑平时就是在把我们限制在"始终可控"的范围内，被绊一跤摔倒的本质就是离开了"我能控制"的状态范围。

   * **完全驱动（fully actuated）**

       * > **定义**：驱动力的自由度与状态自由度相等或者更大的系统。

       * 最典型的例子是固定在一个位置上的机械臂：每一个关节的自由度都可以很精确地控制，能生成一系列不同的姿态。

       * 欠驱动系统的控制比完全驱动系统的控制难很多。

## 前馈控制与反馈控制

   * **控制策略（policy，常记作 $\pi$）**

       * > **定义**：以角色当前的状态（以及可能有的时间）为参数，计算下一时刻该加多少控制信号（比如关节力矩）的映射。

       * 关键点：控制策略使用哪些信息，决定了这个控制策略本身的性质。

   * **前馈控制（feedforward control）**

       * > **定义**：不考虑角色当前的状态、总是执行一个预定义好的控制信号计划的控制。

       * 计划本身可以预先定义得很好（可能考虑了系统的各种状态），但正因为它不看角色当前的真实状态，一旦系统在某一时刻遇到扰动、偏离了原计划里的状态，它就毫无办法。

       * 典型情形：角色不停地向前走、向前迈腿，完全没有考虑到自己正躺在床上——最后就是躺在床上不断做迈腿动作，但是站不起来。

   * **反馈控制（feedback control）**

       * > **定义**：根据角色当前的真实姿态去计算、调整相应的控制，使状态不会偏离某个预定目标太远的控制。

       * 设计心态：通常本来就期待会遇到一定的扰动——设计时预设"我可能会被推"，被推之后自动根据身体状态调整步子大小来保持平衡。

| | 前馈控制 | 反馈控制 |
| :--- | :--- | :--- |
| 依据的信息 | 预先定义好的控制计划（本质上是时间表） | 角色当前的真实状态 |
| 遇到扰动时 | 照旧执行原计划，状态偏了也浑然不觉 | 根据被扰后的状态调整控制，拉回目标附近 |
| 设计时的心态 | 把计划本身定义得尽量完美 | 默认扰动一定会发生，按"会被推"来设计 |

   * **前馈与反馈的尺度转化**

       * 一个控制器到底是前向的还是反馈的，取决于控制目标，可能有不同的结论：比例微分控制（proportional-derivative control，PD 控制）本质上是一个反馈控制，但在角色动画里使用时通常反而说它是前向控制——因为它所反馈的部分和真正想去控制的部分并不完全一致。

## 比例微分控制（PD 控制）

### 从珠子到公式

   * **问题原型**

       * 一根竖直杆上穿了一个只能沿杆移动的珠子，受重力会顺杆掉下去；要设计一个控制器，根据物体当前位置和速度计算一个力，把它拉到目标高度。

       * 这个问题本身可以直接算出精确解（知道重力就行）；但如果那个"重力"是一个非常复杂、经常变化的力，就不好算了——更简单的想法是压根不用管它到底是什么。

   * **比例控制（proportional control）**

       * > **定义**：加的力是偏差乘一个比例系数——刚度（stiffness）$K_p$：$F = K_p(x^* - x)$，其中 $x^*$ 是目标位置、$x$ 是当前位置。

       * 当前位置离目标比较远就加比较大的力、拉得更快一些；比较近就把力放小一点；物体在目标上方时偏差是负值，算出来就是向下的力。

       * 对这个非常简单的系统，一个比例控制就能实现"把物体拉到目标点"的功能。

   * **比例控制的振荡缺陷**

       * 只按位置控制，物体不会停在目标高度：在目标下方时总有向上的力加速它；刚好到达目标高度时误差是零、力也是零，可它还带着速度继续向上冲；冲到上方后力反过来给它减速；减速到头又掉下来——轨迹是一条不断振荡的正弦曲线。

       * 毛病所在：物体明明已经有向上的速度了，说明不加力它也能向上移动，这时候就不该再帮它。

   * **微分控制（derivative control）**

       * > **定义**：在按位置算的力后面加上第二项——当前物体速度乘一个系数的负项：$F = K_p(x^* - x) - K_d\dot{x}$；物体有向上移动的趋势时，就把需要加的力减小一点。

       * 换一个角度看，这一项代表一种耗散：相当于物体本身受到风阻一类的阻力，减小它移动的速度、把能量耗散掉，让它可能开始还有些震荡、最后逐渐停在目标位置附近。

   * **名称由来**

       * 把误差 $e = x^* - x$（目标位置减当前位置）作为想要最小的控制目标：前面一项是误差本身的正比部分（比例项），后面是误差的一阶导数（微分）的正比部分（微分项），合称比例微分控制。

   * **PD 的普适性**

       * PD 控制在控制领域非常简单、也非常常用：一边放水一边进水保持水位高度可以用它实现；工程领域好多看起来复杂的机器人、机械，本质上最终都是 PD 控制。

       * 想实现更复杂的控制，通常要求对对象（比如机器人）的整个动力系统、它跟环境交互的全过程足够了解；不了解时不可避免要做近似——把这个近似推到某种极限的程度，其实就还原成了 PD 控制。

### 稳态误差与积分项

   * **稳态误差（steady-state error）**

       * > **定义**：PD 控制一直加力运行最终停下时，停下的位置不在目标位置上、而是稍微偏下一点的那一点点小误差。

       * 成因：速度为零时微分项是零、不提供任何力，比例项产生的力由误差决定；要让物体停在某个位置不动，这个力必须跟重力大小相同，不然就掉下去——误差就必须满足相应的关系，所以总有一点小偏差；需要抵抗重力的场合，稳态误差几乎必然出现。

       * 由于需要抵消的重力固定，偏差大小跟刚度 $K_p$ 成反比：$x^* - x = \frac{mg}{K_p}$。

       * 提高 $K_p$ 会减小稳态误差、控制更精确，但整个系统会表现得非常坚硬、刚性，还会带来数值不稳定——所以 $K_p$ 通常不能设得太大，设一个合理的值就可以。

       * > **提示**：稳态误差不是 PD 控制"没调好"，而是"比例项的力必须恰好抵消重力"这个物理要求留下的必然残余；想靠一味调大 $K_p$ 消灭它，会撞上刚性和数值不稳定两堵墙。

   * **为什么动画里不用积分项**

       * PID（比例积分微分控制）的积分项是误差对时间的积分（一个积累）再取正比，因为这个积累效应，它可以使得最终没有稳态误差。

       * 动画里通常很少使用积分项，原因有两个：其一，比例项和微分项用当前时刻的误差、当前时刻的速度就可以直接算出来，积分项跟历史相关，得专门用一个变量记录前面一段时间误差是多少并不断累加，实现上带来麻烦；其二，特别是当目标本身在不断变化时，积分项会带来很多控制上的不稳定问题。

       * 所以对动画或常见控制，通常只用到 PD（比例微分）的部分，积分部分一般不用。

### 关节 PD 与参数手感

   * **关节 PD 公式**

       * 用 PD 控制计算每个关节上该加多少力矩，让关节连接的两个刚体之间的夹角达到一个目标位置，一般形式为：

$$\tau = K_p \left( q^* - q \right) + K_d \left( \dot{q}^* - \dot{q} \right)$$

       * 目标速度通常大部分时候是零，但运动本身不是零——因为目标会不断变化；角色动画、物理仿真里用的 PD 控制通常就是：

$$\tau = K_p \left( q^* - q \right) - K_d \dot{q}$$

       * 前一项是目标减当前关节旋转、乘一个比例；后一部分是阻尼项（当前旋转速度乘一个比例）；算出关节力矩后应用到每个刚体上，角色就产生运动。

   * **参数对动作的影响**

       * 设一组相对合理的 $K_p$、$K_d$，让角色从任意状态出发、把 T-pose 作为目标状态：刚度调小——产生的力很小，角色很难达到目标位置，而且不管经历多长时间都到不了（力不够）；刚度调大——角色非常硬、僵硬，会非常快地从任何姿势弹到 T-pose，整个角色硬邦邦。

       * 阻尼调小——角色有明显震动效果，像松手的弹簧，刚度大而阻尼小的角色跟踪目标位置时会不断超调、上下震荡；阻尼调大——还是可以正常跟踪姿势，但要花更多时间才能到达，过程又慢又绵长。

| 参数 | 调小 | 调大 |
| :--- | :--- | :--- |
| 刚度 $K_p$ | 力不够，怎么等也到不了目标姿势 | 非常硬、僵硬，瞬间弹回目标姿势 |
| 阻尼 $K_d$ | 不断超调、震荡，像松手的弹簧 | 最终能到目标姿势，但过程又慢又绵长 |

       * > **易错点**：⚠️ 刚度小和阻尼大在"慢"的观感上相似，本质完全不同——刚度小是"力不够，永远到不了"；阻尼大是"最终到得了，只是慢"。

### 跟踪控制（tracking control）

   * **结构**

       * > **定义**：给每个关节一条目标轨迹，每一时刻从轨迹里拿出一个状态作为目标状态、用 PD 控制算出关节力矩来驱动角色——有了 PD 控制，控制问题在形式上就变成了"去设计目标轨迹"。

```text
      目标轨迹 q*(t)
          │ 每一时刻取样
          ▼
目标状态 ──▶ PD 控制 ◀── 当前状态 (q, q̇)
          │
          ▼
      关节力矩 τ ──▶ 施加到每个刚体 ──▶ 产生运动
```

       * 全身动作：正常人有十几个到二十几个关节，每个关节对应自己的一条目标轨迹，各自算出当前时刻该加的关节力矩，全身同时在跑这套循环。

   * **轨迹设计与跟踪的困难**

       * 最关键的部分是如何设计一系列目标轨迹，让角色产生想要的动作；有很老的（1995 年）工作通过手工设计、对每一个动作专门设计一条轨迹，但手工设计非常麻烦。

       * 就算轨迹设计好了，PD 控制去跟踪也未必跟得住，原因有两个：一个是 PD 控制本身的稳态误差；另一个是相位差——生成的动作跟目标轨迹大概会差一点点相位（目标里手已经抬起来了，角色可能延迟大概零点几秒才抬起来）。

       * 后果：设计一个看着不错的后空翻动作，用 PD 控制去跟踪，生成的动作多半没办法把后空翻做完。

       * 直接用动捕数据当目标轨迹也一样：跟踪效果非常差——角色大体上还在做那个动作，但这是欠驱动系统，跟踪稍微有一点点偏差就会造成后面无法准确修复前面的偏差（质心偏离了目标，没有任何办法直接控制质心把它拉回来）。

       * > **易错点**：⚠️ PD 控制是反馈还是前馈，取决于站在哪个尺度上看：单看关节力矩这一层，公式用的是"目标位置减当前位置"，是反馈；看整个动作这一层，目标状态是从轨迹上按时间取下来的、跟角色当前的状态没有关系——是开环的前向（feedforward）控制。

## 根节点外力：上帝之手

   * **全身力矩总和为零**

       * 施加关节力矩时，总是把一个力矩加在 child 的刚体上、再把一个反向的力矩加在 parent 的刚体上，所以所有刚体见到的力矩总和其实是零。

       * > **结论**：全身力矩总和为零，意味着整体的质心、整体的朝向和位置这些全局量，靠内部关节力矩是无法改变的——角色会摔倒、跟踪会失败，本质就在这里。

   * **root force（根节点力）**

       * > **定义**：在根节点上额外施加的力或力矩——做法跟普通关节一样：想让根节点在运动中始终满足某一条轨迹，从轨迹上拿出目标点、跟根节点当前位置做一个 PD 控制，算出需要的力来施加。

       * 特殊性：根节点是一个特殊节点，只有一个子关节、没有父关节；在它上面施加力相当于对整个角色加了一个额外的外力，而这个外力**没有施力者**——不知道是什么东西加的力，真实世界里不存在，只在虚拟世界里可以加。

       * 效果与代价：会帮角色保持平衡、轨迹跟踪也能完成得比较好；但角色看起来像提线木偶——表演者通过一根根线拽着木偶移动，线的存在很明显，人很容易判断出"这个动作有点不自然，好像被什么拽着"。外号 hand of God（上帝之手）：一个虚拟的、不存在的"人"在某个地方施加力。

       * 直接在根节点上用 PD 控制加力，对应的是所谓的 physically plausible——不是物理准确，而是物理可接受的一种动画。

       * 与普通关节力矩的本质区别：普通关节力矩是一个 body 加 $\tau$、另一个 body 加 $-\tau$，两个力矩总和为零，等价于一根骨骼对另一根骨骼的作用与反作用（系统内力，没有外来的力做功）；根节点力矩只落在根节点自己的 body 上、找不到反作用对象，所以是一个非零的**外力**——动作变味的根源。

   * **游戏与应用**

       * 大量使用物理仿真的游戏（如《Party Animals》《Totally Accurate Battle Simulator》），主要仿真过程都在 root 上多少做些控制，保证角色总体可控；同时也能明显感觉到角色像被谁拽着腰、拽着往前移动——本质是加了没有施力者的外力，带来物理感觉上的问题。

       * ragdoll 与关键帧混合（很多游戏里已很常见的老做法）：如拳击击倒的动作——角色被击倒时切换到 ragdoll 仿真、跟踪一个摔倒的轨迹生成物理合理的动作，再把这个仿真动作跟一段关键帧（站起来或击打动作）用一个时间参数控制混合；既有物理仿真的反馈，又有可控的运动学动画。

   * **欠驱动面前的两条路**

       * 一条：加没有施力者的 root force——能帮角色跟踪动作、产生动作，缺点是效果差一点、动作看起来不自然。

       * 另一条：研究该如何控制全身的力，让角色在不加额外外力的情况下保持平衡、做出动作。

## PD 控制的稳定性与步长代价

### 两个天生缺陷

   * **同根同源**

       * PD 控制的力由当前状态与目标状态之间的偏差乘上比例系数算出——必须要有偏差才有这个力，没有偏差就没有力；稳态误差与相位延迟两个现象同根同源。

   * **稳态误差：有力就一定有偏差**

       * 小臂在竖直平面内绕肘关节转动、想端平的例子：只要有重力，重力就会在重心上加一个力矩让小臂往下垂；平衡时关节力矩至少要和重力的力矩相同才能保持稳定——而 PD 公式里出现了大于零的力，就说明误差一定大于零。

       * 把目标位置设置成水平状态去跟踪，小臂肯定不会水平：它必须垂下去一点，靠这点偏差"挣"出对抗重力的力矩。

       * > **结论**：稳态时 $k_p \cdot e = \tau_{\text{重力}}$，重力力矩恒定，所以稳态误差 $e = \tau_{\text{重力}} / k_p$，与 $k_p$ 成反比——目标设在哪里，就永远差在哪里。

   * **相位延迟：永远慢半拍**

       * 总得先有偏差才能算出力，有了力才能驱动角色运动：拿一条正弦曲线作控制目标，仿真生成的曲线通常比输入曲线有一个延后——输入已经到了最高点，仿真曲线要过一段时间才到最高点。

       * 对简单系统来说这个相位偏差可以算出来（属于控制论领域的技术知识），定性知道这回事即可。

### 调大 kp 的代价

   * $k_p$ 是所谓的刚性（stiffness）或增益（gain）：稳态时要平衡的是恒定的重力，力矩相同的情况下误差与 $k_p$ 的乘积一致、二者反比——$k_p$ 大时稳态误差小一点，跟踪轨迹的相位偏差也相对减小，但并非万事大吉，有两笔账要还。

   * 观感账：$k_p$ 很大时角色动作非常僵硬，整个人一直挺挺的，看起来很不自然。

   * 仿真账：比较大的 $k_p$ 会带来仿真上的稳定性问题——值得用最简单的弹簧振子把"步长多大才算安全"这笔账算清楚。

### 弹簧振子稳定性分析

   * **模型与半隐式欧拉迭代**

       * 弹簧（劲度系数 $k_p$）挂一个物体，旁边额外加一个按速度产生阻尼力的阻尼——本质就是一个 PD 控制器（比例项加阻尼项），只是比例项里的目标值设成了零：$F = -k_p x_n - k_d v_n$。

       * 半隐式欧拉（symplectic Euler，又称辛欧拉）的特点：力用当前时刻的状态算、先更新速度，再用更新之后的速度去更新位置：

$$v_{n+1} = v_n + h F(x_n, v_n), \qquad x_{n+1} = x_n + h v_{n+1}$$

       * $h$ 是时间步长（相邻两个时间点之间的距离，仿真里非常重要的量）；质量取 1、代入 PD 的力得到：

$$v_{n+1} = (1 - h k_d)\, v_n - h k_p\, x_n$$

$$x_{n+1} = h(1 - h k_d)\, v_n + (1 - h^2 k_p)\, x_n$$

       * 把 $v_n$、$x_n$ 打包成一个状态向量，两条式子拼成矩阵迭代 $\boldsymbol{s}_{n+1} = A\, \boldsymbol{s}_n$（对这个问题 $A$ 是不随时间变化的常数矩阵）：

$$A = \begin{bmatrix} 1 - h k_d & -h k_p \\ h(1 - h k_d) & 1 - h^2 k_p \end{bmatrix}$$

       * 每一步都是乘同一个 $A$，通项公式为 $\boldsymbol{s}_{n+1} = A^n \boldsymbol{s}_1$——问题变成：$A$ 的 n 次方随 n 增大到底是收敛还是发散。

   * **特征值：发散还是收敛的裁判**

       * $A$ 可以与一个对角阵相似：$A = P \Lambda P^{-1}$，$P$ 由两个不共线的特征向量拼成、是固定矩阵，$\Lambda = \begin{bmatrix} \lambda_1 & 0 \\ 0 & \lambda_2 \end{bmatrix}$；做变量代换 $z = P^{-1} s$ 后，迭代解耦成 $z_{n+1} = \Lambda^n z_1$。

       * 特征值不一定是实数、可能是复数，但复数总有模长 $|\lambda| = \sqrt{\operatorname{Re}(\lambda)^2 + \operatorname{Im}(\lambda)^2}$，且 $|\lambda^n| = |\lambda|^n$。

       * > **结论**：只要任何一个特征值（$\lambda_1$ 或 $\lambda_2$ 都一样）的模长大于 1，$|\lambda|^n$ 就趋于无穷、状态发散（画面上就是物体左右震动、越震越大，最后飞到无穷远）；要保证仿真稳定，需要 $A$ 的**所有**特征值模长都小于等于 1，最理想是严格小于 1——等于 1 其实也不算稳定。

   * **步长上限曲线**

       * 固定 $k_p = 500$、$k_d = 20$，横轴取时间步长 $h$、纵轴取 $A$ 的特征值模长最大值：步长很小时最大模长在 1 以下、单调上升，大概在 $h \approx 0.05$ 的位置碰到 1，再往后很快超过 1 且单调上升、不会再下去——这组参数下时间步长不能大于 0.05 左右，再大系统就崩。

       * 把 $k_p$ 增大到 5000，1 的门槛向左挪：步长必须压到 0.02 左右以下才能稳定；把 $k_d$ 调大，门槛向右偏移、能容忍更大的步长。

       * 结论很明确：$k_p$、$k_d$（特别是 $k_p$）调大虽然能让误差更小，但一方面让动作更僵硬，另一方面要求用更小的时间步长去做仿真。

### 参数选择与步长代价

   * **kp/kd 基本靠手调**

       * 真要控制人形角色，旋转本身非线性、关节多、自由度高，$k_p$、$k_d$ 在很大程度上影响角色运动起来的感觉（大了僵硬、小了无力跟踪不上）；设置比较考验经验，实际上没有特别好的办法，基本靠手调——调到一个感觉比较舒服的状态就可以一直用。

       * 好消息是范围不算苛刻：只要不差一个数量级，通常不会有非常大的偏差；常用的一种方案是给每个关节取 $k_p = 200$、$k_d = 20$（实际范围可以更大一点，按情况微调）。

| 场景 | kp / kd 怎么调 |
| :--- | :--- |
| 角色比较重 | $k_p$、$k_d$ 相应调大 |
| 快动作（跳高、后空翻） | 调大——不调大力量不够，会发现跳不起来 |
| 很轻的肢体（手只有几百克，比如腕关节） | $k_p$ 调小 |

   * **步长一小，计算就贵**

       * PD 的参数很容易把仿真推入不稳定区：一个 50 kg 的角色取 $k_p$、$k_d$ 为 200 和 20，步长百分之一秒时很有可能非常不稳定，甚至调到千分之一秒都可能不稳定——很多早年工作的仿真步长写 1/1000 甚至 1/2000 秒（1 ms 或 0.5 ms 的量级）才能保住稳定性；$k_p$ 再调大，要求的步长还会更小。

       * 代价机理：每推一个时间步都要做一次运动方程的求解，每一步的计算量基本固定、跟步长本身关系不大——步长越小，仿真一秒钟所需要的时间就越长。

       * 实时应用的矛盾：游戏为了保证连续性通常至少要 60 FPS，1/60 秒里要跑仿真、做渲染（非常慢的过程）、还要做逻辑计算；比较老的游戏全靠 CPU，里面的东西一多就非常慢，仿真本身再占掉一大块预算，对实时应用很不划算。

       * 场合区分：做机器人控制设计，仿真步长确实应该放小一点（计算更精确、没有实时性要求、相对好做）；但对普通的 PD 控制来说，时间步长通常不能放得太大——稍微放大一点，系统就会崩。

## Stable PD 控制

   * **为什么只隐式化速度**

       * 隐式欧拉计算力时不用当前时刻的状态，而是用下一时刻的状态，数值上是稳定的；但下一时刻未知，本质会变成一个方程、需要解方程才能获得下一时刻状态。

       * 麻烦在于：如果把力里的 $x_n$ 换成 $x_{n+1}$，从角速度变到旋转、变到四元数这一步的计算通常是非线性的——方程整个变成非线性的，求解变慢，不能像线性系统那样一个矩阵求逆就把答案拿到。

       * 折中方案：只把 PD 控制里的一部分变成隐式——把速度项隐式化。位置的部分经常是非线性的、不好算；但速度项在大部分情况下是线性关系，原因很简单：速度是导数，一旦求了导，很多东西的非线性就变成线性了。

   * **公式与解法**

       * 把阻尼项里的当前速度换成下一时刻的速度：

$$F = k_p (x^* - x_n) - k_d\, v_{n+1}$$

       * 系统方程从原来稍简单变得复杂了一点，但很容易解决——$v_{n+1}$ 就在这一行里，挪到等式一边、再除掉系数即可：

$$v_{n+1} = \frac{v_n + h\, k_p (x^* - x_n)}{1 + h k_d}, \qquad x_{n+1} = x_n + h\, v_{n+1}$$

   * **效果与实现**

       * 再画一次"特征值模长 vs 步长"曲线对比：普通显式 PD 的曲线大约在步长 0.01 的地方越过 1、宣告失败（步长必须小于 0.01）；用下一时刻 $v_{n+1}$ 算阻尼的版本，最大可用步长可以相当大、接近 1 这样的范围——两个门槛大概可以差几十倍。

       * > **定义**：Stable PD control——把 PD 阻尼项里的当前速度 $v_n$ 换成下一时刻速度 $v_{n+1}$（速度项隐式化），以换取大得多的稳定步长上限；稳定性最关键的部分就是用下一时刻的速度来计算阻尼项。

       * 两关节小角色的量级：用 stable PD，1/60 秒的步长就能稳定；不用的话，可能需要 1/600 秒左右（具体数值要实际测试）。

| 对比项 | 显式 PD | Stable PD（速度项隐式） |
| :--- | :--- | :--- |
| 阻尼项用的速度 | 当前时刻 $v_n$ | 下一时刻 $v_{n+1}$ |
| 稳定步长上限 | 很小：人形角色常要 1 ms 甚至 0.5 ms | 大几十倍：两关节小角色 1/60 s 即可稳定 |
| 实现方式 | 按 PD 公式直接加力 | 需干预求解器内部，通常自己实现，或借引擎的 velocity motor |

       * 工程注意：这一步相当于干预了仿真器、物理引擎内部的运算，通用物理引擎不一定提供这样的功能，通常需要自己去实现；另一个方向是利用仿真器自身的一些具体实现达到类似效果，比如所谓的 velocity motor（速度控制器）。

       * 不加隐式阻尼、只是 $k_p$ 比较大时，仿真非常不稳定、转着转着就飞掉；换成 stable PD（用 $v_{n+1}$ 计算的阻尼项）仿真会稳定很多，步长越大对比越明显。很多工作声称可以在 120 Hz 下做仿真，实际就意味着使用了 stable PD 这类做法。

## 轨迹优化

### 问题定义

   * **会解优化，不等于会控制**

       * IK 本身可以转化成一个优化问题，用各种迭代的下降方式去解：gradient descent、CCD（严格说不是梯度法，但同样是迭代的下降方法）、牛顿法、Levenberg-Marquardt（LM）法等；对简单的例子，这些方法可以比较容易地找到根、找到解，而且解还是唯一的，效果比较好。

       * 对象换成一个人、一个完整的复杂角色（比如想让角色跑步）情况就不同了：直接用 PD 控制去跟踪一段动捕轨迹是跑不起来的；通常把动捕数据作为优化的初始解，再用优化的方式找一条合理的控制轨迹，让角色真正跑起来。

       * 目标函数的核心是衡量当前仿真状态和目标轨迹之间的偏差，偏差可以用好多种方式定义（都可拿来当轨迹优化的目标）：算两个 pose 之间关节角度的偏差；算每个关节的全局绝对位置之间的偏差；算每个关节的速度；算角色质心的相对关系。

   * **为什么不能直接跟踪动捕**

       * 延迟这件事一下脚就会出事：正常往前走路需要身体和脚配合起来才不会摔倒，一旦身体和脚之间有了延迟，平衡就很容易失掉、动作也没法跟得准。

       * 所以真正的问题变成：如何找到一条控制轨迹，让我们不需要根节点来帮忙——把上帝之手的力去掉，让角色生成完整的、物理真实的动作。

       * 端平手臂的启示：目标状态正好设在端平的位置，PD 控制肯定不能让胳膊端平——总要有偏差；那就把目标位置设得比端平稍微靠上一点，这点误差产生的力正好让胳膊保持平衡。设计动作轨迹是同样的思路：想让角色滚动、走路、后滚翻，有一份动捕记录，但不能直接去跟踪这份记录，而要在它之上找一条"追得上"的轨迹去跟踪，才能通过仿真生成想要的动作。

       * 手工设计是一种方式（有公司如 NaturalMotion 做过这样的软件），但会非常困难；通常希望让计算机自己做些事情、自己去找到这样一套轨迹。

       * > **定义**：轨迹优化（trajectory optimization）——把"找到一条能被 PD 控制追上的目标轨迹"这件事本身，写成一个带约束的优化问题去求解；有时也叫 spacetime constraints 或 spacetime optimization（时空优化），名字不同、本质做的是同一件事。

   * **优化变量**

       * 优化一条仿真的轨迹：时间离散化之后，"轨迹"就是每一个时刻角色的状态——位置、速度、朝向、角速度等。

       * 同时优化一条控制轨迹：它可以就是 PD 控制器的目标轨迹（target trajectory）——有了目标轨迹，就可以用 PD 控制计算每一时刻的关节力矩，施加到角色上让它动起来。

       * 两个变量被运动方程拴在一起：目标轨迹 → PD 控制器逐时刻算出关节力矩 → 仿真向前推进一步 → 得到仿真轨迹 → 目标函数打分、约束把关 → 优化器回头调整目标轨迹，循环往复。

### 目标函数与约束

   * **目标函数的通用形式**

$$J = \Phi(s_N) + \sum_{n} L(s_n, \tau_n)$$

       * 一部分是轨迹结束时那个状态的代价；另一部分是每一时刻按"加了多少力、当时状态如何"算出的代价。

   * **约束**

       * 最主要的约束就是运动方程：角色的运动是"当前状态，加上这一时刻施加的力，通过仿真得到下一步的状态"——两个状态和这个力之间有一个非常固定的关系。

       * 之外可能还有一些其他约束：比如关节约束；再比如要求角色不能走到悬崖边上（不然会掉下去）——一个对位置的约束。

   * **奠基工作**

       * 这个方向较早的奠基性工作是 1988 年发表在 SIGGRAPH 上的皮克斯小台灯：优化"台灯跳起来到那里"的动作——状态是台灯每个关节的位置、每个关节的朝向角度、基座的位置以及它们的速度，还有一些直接加在每个关节上的力；通过不断优化这些位置和施加的力，最终生成那段动画。

   * **能算到底的小例子**

       * 一根杆上穿着一个物体、加力抵抗重力并跟着目标高度移动，力是 PD 的：$f = k_p(x^* - x) - k_d v$；目标是计算一条 PD 控制的目标轨迹 $x^*$，使得在这个控制下仿真结果 $x$ 是一个 sin 函数。

       * 目标函数写成最小二乘：$\min \sum_{n} \left(\sin(t_n) - x_n\right)^2$——让三角函数在 $t_n$ 时刻的值与 $x_n$ 在该时刻的值相同。

       * 约束：$x_n$ 和 $v_n$ 要满足运动方程——此例中就是前面那两条半隐式积分更新式（力的公式已知，每一步怎么更新完全确定）。

       * 通常还会加额外约束：约束不够时状态有很大的自由，可以选择取很大的值或很小的值；加正则项要求优化的量必须比较接近于零，整个输出的轨迹会比较平滑、比较正常。

### 硬约束与软约束

   * **硬约束**

       * 写在约束区里的等式形式；不管用哪个求解器，它都一定会尽可能满足——因为约束是必须满足的。

       * 代价：问题可能变得比较难解；从数值上讲，问题可能变得不太稳定、条件数会变差。

   * **软约束**

       * > **定义**：把硬约束从约束区挪进目标函数、写成带权重 $w$ 的惩罚项——原来要求两边必须相等，软约束的说法是两边尽可能相等（差尽可能小），允许一定程度上不等于零。

       * $w$ 代表软约束"软的程度"：$w$ 很大，表示这条约束尽可能一定要满足、相当于更"硬"一些；调节权重就能平衡"约束满足的程度"和"目标函数最优的程度"。

       * 软约束形式的优化问题通常求解起来更简单，两种形式可以互相转化。

### 变量规模与求解方法

   * **配点法（collocation methods）**

       * 动机：优化目标实际是离散化轨迹上每一个时刻的状态——仿真步长取千分之一秒，仿真一秒钟就是 1000 个状态；每个状态带位置、速度，再加上目标轨迹自己的变量，零零总总约 6000 个参数这个量级，给优化带来很大困难。

       * > **定义**：配点法认为 $x$、$v$ 和目标轨迹都满足某些预先定义好的参数曲线——比如都来自某条三次样条曲线（cubic spline）或某个多项式函数——把优化 6000 个参数简化成优化这些曲线的参数；通过近似的方法减少优化变量的技巧。

   * **求解器**

       * 常用基于梯度的方法（gradient based approach）：梯度下降；牛顿法，以及牛顿法里最常用的那一支 L-BFGS。

       * 简单例子有更好的性质：目标函数是二次函数、约束是线性等式约束，所以它是一个非常简单的 QP（二次规划）问题——有唯一解、很容易直接算出来；就算不直接解，用梯度下降这类方法迭代也一样能逼近答案。

## 梯度方法的局限与无梯度优化

### 梯度失灵的两个麻烦

   * **第一个麻烦：优化目标本身**

       * 优化的最终变量是姿态（关节旋转），天生非线性；角色自由度高、身上关节多、参数非常多，目标函数是一条高维曲面——高度非线性，甚至曲面本身都在不停震荡，有无穷多个局部最优解。

       * 这种情况下梯度的质量通常很差：它总是指向某一个局部最优解，而局部最优解又特别多，所以梯度指向的方向很有可能不太对。

   * **第二个麻烦：黑盒仿真**

       * 优化公式里有一项是整个系统的系统函数（system dynamics）：知道的系统它写在那儿就行，可对一般系统（比如一个机器人它该怎么动），很多时候无法准确建模。

       * 最基本的碰撞建模问题：一个球掉在地上该弹多高？现有的碰撞模型很多都是非常粗略的近似。

       * 软接触的例子：人的手是软的，用软软的手捏一支笔非常容易，软接触会带来非常稳定的接触点；仿真里角色的手是硬的，就像用筷子去夹一支笔，非常难——跟真实的人捏笔的过程完全不是一回事。

       * 整个运动过程很难准确建模，模型都不知道、梯度就更没法算——这正是基于梯度方法（gradient-based）的局限性：必须要一个梯度，而很多时候梯度算不出来；控制领域里凡是需要做轨迹优化的，都会碰到这么差的优化地形（landscape）。

### 无梯度方法的通用框架

   * **derivative-free optimization（无梯度优化方法）**

       * > **定义**：不需要 gradient、通过若干个样本点的信息来更新对最优解的估计的方法；通常是启发式的方法、基于随机的方法或基于采样的方法。

       * 好处很明显：不需要梯度；坏处也摆在那里：只能靠估计，一方面慢（估计的过程总比直接用函数算要慢），另一方面也不够精确——各有优缺点。

| 对比 | 基于梯度的方法 | 无梯度方法（derivative-free） |
| :--- | :--- | :--- |
| 前提 | 必须能算出梯度 | 只需要能算目标函数值 |
| 速度与精度 | 快，精确 | 慢（靠估计），不够精确 |
| 遇到黑盒系统 | 模型未知就没法算梯度，用不了 | 可以直接用 |

   * **通用流程**

       * 目标是找到一个变量 x、让某个目标函数最小化：首先用某种方式给出一个初步的估计（对跟踪任务来说，动捕数据本身就可以作为初始估计）。

       * 接下来循环迭代：根据当前估计生成一批样本点 → 对每个样本点计算目标函数的值 → 根据这些函数值更新对 x 的估计；这只是个框架，具体到不同方法，细节上的区别比较大。

   * **相关方法**

       * 贝叶斯优化；遗传算法（进化算法）；机器学习里非常常用的随机梯度下降（本质上也是这一类）；还有一些基于采样的方法。

       * 其中效果比较好的两种：CMA-ES 和 SAMCON。

## CMA-ES

   * **定义与核心思想**

       * > **定义**：CMA-ES（Covariance Matrix Adaptation Evolution Strategy，协方差矩阵自适应进化策略）——本质上是一个进化算法，特殊的地方在于把撒点、估计这个过程转化成维护一个高斯分布的估计：假设每次要采的样本点，总是从一个高维的高斯分布（正态分布）里采出来。

   * **流程**

       * 初始化一个高斯分布，可能就是一个圆形的分布。

       * 从分布里采样，比如撒 100 个点。

       * 对每个点计算目标函数的值——求值本质上相当于做了一次仿真：仿真生成一条比如几秒钟的轨迹，再在这条轨迹上算函数值（如要求轨迹跟某个参考动作相近、踢球时脚必须碰到球，都可以写成目标函数）。

       * 对这些函数值做排序：目标是最小化 f，从最小的往上找、保留 n 个——撒了 100 个点，可能只从里面拿 20 个作为更新的点（n 是一个可以算出来的参数）。

       * 用这批点更新高斯分布的均值 $\mu$ 和方差 $\sigma$；下一步从更新之后的高斯分布里继续采样。

   * **特征行为**

       * 一开始是一个圆形的初始化高斯分布；迭代中有些点的函数值相对较小，分布就会逐渐向函数值小的方向移动。

       * 移动开始时方差会逐渐增大——代表正在向外探索函数值更小的方向；当方向逐渐集中之后，方差又会逐渐变小，最后收敛到最优解附近。

   * **优点**

       * 比较稳定，对一些很复杂的函数实际效果也蛮好；确实是 derivative-free 的，哪怕是非常复杂的系统或者黑盒子系统，也可以直接应用。

   * **两个应用**

       * 2009 年的工作：人走路总是左脚着地、右脚着地，给出一些预测的落地点位置，用轨迹优化去找一个能满足每次落地点的走路形态；给的位置的距离、速度不同，走路的姿态也会不同；甚至角色的关节数量跟真人不一样，这种方法也能找到一个比较合理的走路过程。

       * 反过来只优化 PD 的目标轨迹、不优化仿真轨迹（目标轨迹给定之后，剩下的部分仿真直接就可以得到，仿真轨迹让仿真自己产生）：给一些非常简单的目标——比如"脚尽可能抬高，同时身体有一个旋转"——它就可能生成类似街舞一样的动作；这是 CMA-ES 加上仿真控制、再加上轨迹优化能够实现的效果。

   * **代价**

       * 每给出一个样本参数，都需要从头到尾做一遍仿真，然后才能更新参数，整个过程比较漫长。

       * 如果仿真的轨迹比较长，目标函数实际上会带来更多的局部最优解，让优化变得更难收敛。

## SAMCON

   * **定义与出发点**

       * > **定义**：SAMCON——本质上是一个 sequential Monte Carlo（序列蒙特卡罗）方法：要解决的问题跟 CMA-ES 相同（有一段动捕数据，需要找到一条目标轨迹、跟踪它来还原那段动捕），不同的点在于每次做采样只考虑下一帧、每次只优化一步，通过这一步来决定后面该怎么更新轨迹的值。

       * 这类方法的特点：从一些初始状态开始，采若干个样本点向前仿真；仿真完之后像 CMA-ES 一样，只从仿真结果里拿出一小部分样本点作为新的出发点，再去采更多的样本，依次类推，直到把整条轨迹走完。

   * **流程（以跟踪一段给定轨迹为例）**

       * 初始状态比如是站立（人往前走，肯定是从站着的状态开始）；直接用 PD 去跟踪这条轨迹偏差会比较大，为了跟踪得准，需要在轨迹上加一个偏移、然后去跟踪"加了偏移之后的轨迹"，让一部分状态跟参考轨迹比较接近。

       * 每次只优化一小段：偏移是不知道的，根据一个高斯分布对偏移进行采样（用均匀分布之类的也可以）；比如采 1000 个样本，每个样本对应原动作轨迹的一个偏移。

       * 对每一个偏移做一次仿真，每个片段仿真之后生成一个新状态——有一些离参考轨迹比较近，有一些比较远。

       * 只保留那些离轨迹比较近的状态；不会只保留一个——只留一个的话它可能是一个局部最优解，而这个局部最优解可能在后面的仿真过程中变成一个非常差的解；所以多保存一些，比如 1000 个里保留 100 个，作为下一阶段的起始状态。

       * 从保留的起始状态出发，随机地再产生比如 1000 个样本、进一步仿真，同样只留下离轨迹近的、扔掉远的；不断进行下去，最终得到一组轨迹，其中相当一部分离目标轨迹比较近，把其中最接近的那条找出来就是最终的解。

```text
  参考轨迹（动捕 / 动画师给定）
        │
        ▼
  初始状态（比如站立）──► 按高斯/均匀分布采样 1000 份偏移
        │
        ▼
  每份偏移仿真一小段 ──► 得到 1000 个候选状态
        │
        ▼
  只保留离参考轨迹最近的约 100 个，其余淘汰
        │
        ▼
  以保留状态为起点，继续采样、仿真、筛选，逐帧推进
        │
        ▼
  走完整条轨迹后，选出最贴近参考轨迹的那一条
```

   * **为什么有效**

       * 虽然每一步只考虑一步、是一个非常 local 的问题、非常容易陷入局部最优，但保留了多个状态——每一个局部最优解都会被延迟到后面若干步之后，再去判断它是不是真的最优解；每一步的判断不再局限于当前这个局部，整个优化过程更加有效率。

   * **效果**

       * 任何一个动作，只要有它的动捕数据，基本上就肯定可以找到一条控制轨迹把它还原出来。

       * 过程中还可以把环境做一些变化、或把角色本身做一些变化：retargeting 把动作重定向到另一个角色时不可避免出现穿模、角色跟环境碰撞接触的问题，都可以在优化的过程中处理掉；地上有一些鹅卵石、或者是冰面，角色也会自动受环境影响、产生动作的变化。

## 前馈与反馈的结合

   * **前馈的局限**

       * 轨迹优化得到的控制本质上是一种前馈控制（开环控制）：得到一条控制轨迹，播放的时候用 PD 控制去跟踪它、得到仿真轨迹——这就是它的全部。

       * 很大的问题：跟踪过程要求起始状态、以及仿真过程中的每一个状态，都必须处在获取这条轨迹时能够得到的状态范围之内——一开始对角色加扰动（推它一把），继续跟踪原来的轨迹，角色很快就会摔倒、状态偏离得越来越远，没有任何机制把它拉回来。

   * **反馈更正回路**

       * > **定义**：反馈控制在每一时刻由一个反馈策略根据当前状态和参考状态之间的偏差，自动计算出一个更正量加到原来的轨迹上，然后再用 PD 控制去跟踪这条更正后的轨迹。

```text
   参考轨迹 s0 ───►(+)───► PD 控制 ───► 物理仿真 ───► 实际状态 s1
                ▲                                       │
                │                                       │
                └──── 更正量 = f(s1 − s0) ◄─────────────┘
                     （反馈策略每一时刻实时计算）
```

       * 效果：并不指望它完全精确地回到目标轨迹上——它总是在轨迹附近，但每一步都有反馈策略往上加，可以保证整个仿真过程都贴着目标轨迹附近走、不会离得很远。

       * 跟踪控制加上反馈之后，角色就可以推了：推它，动作会受到相当的影响，但最终角色还是可以保持平衡。

       * > **提示**：前馈负责"怎么走"，反馈负责"走歪了怎么拉回来"，两者是配合关系，不是二选一。

| | 前馈控制（开环） | 反馈控制（闭环） |
| :--- | :--- | :--- |
| 控制量怎么来 | 离线优化得到一条固定的控制轨迹 | 每一时刻根据当前状态与目标实时计算 |
| 扰动来了会怎样 | 状态偏离后无人纠正，很快摔倒 | 自动更正，始终保持在目标轨迹附近 |

## 静态平衡

### 静态平衡的目标

   * **单一姿势跟踪缺什么**

       * 让 PD 控制去跟踪一个单一的姿势（比如 T-pose）：这个 pose 本身没有任何平衡控制，会比 ragdoll 好一点——ragdoll 是完全没有控制的、直接瘫在一起，而单一姿势跟踪能让角色撑住自己、保持这个姿势，但会逐渐地摔倒；缺的就是一个能在它将要摔倒时把它更正回来的反馈控制。

   * **静态平衡（static balance）**

       * > **定义**：在不发生移动的情况下（比如原地站着），通过非常简单的控制策略，让角色左右稍微摇晃一晃、或被推一下发生这些扰动时不会摔倒；甚至原地下蹲、原地晃晃肩之类的动作也能保证不摔。

       * 这是一个非常基础的控制，在这个之上可以做很 fancy 的效果。

### 平衡的判据

   * **support polygon（支撑面）**

       * > **定义**：站立时把两个脚面连起来的凸包，构成平面上的一个多边形，就是支撑面。

       * 圆柱墩子为什么稳：它有一个质心（重心），重心在地面上有一个投影；整个圆柱体的底面是一个圆（支撑面），重心投影落在支撑面内部、靠中心的位置——推翘起来一点也会在自重作用下回到原来的状态。

       * > **结论**：物体处于准静态（基本不动、没有速度）时，只要质心在地面上的投影落在支撑面之内，这个物体就是稳定的——哪怕翘起来一点也会被拉回来、落回中间。

       * 人站在那里同理：保持平衡只需要保证质心的投影始终在支撑平面内部，角色就不会摔、没有处于"正在摔倒"的状态。

       * 单腿站立难的原因：单腿站立时 support polygon 只有一只脚那么大，要让质心始终保持在支撑面之上比双脚站立难很多——双脚站立时两脚中间的凸包比一只脚大很多，控制起来容易得多。

```text
        俯视：双脚站立时的支撑面
      ┌──────────────────────┐
      │   ▭ 左脚              │
      │                      │
      │         ●            │
      │                      │
      │      ▭ 右脚           │
      └──────────────────────┘
      ● = 质心投影；外框 = 两脚脚面围成的凸包
```

   * **质心（重心）的计算**

       * > **定义**：人的质心 = 每一个肢体（刚体）的质量乘以它的位置、加起来除以整个人的质量——用质量对位置做加权平均，得到的位置就是重心：

$$c = \frac{\sum_i m_i x_i}{M}, \qquad M = \sum_i m_i$$

       * $m_i$、$x_i$ 分别是第 $i$ 个肢体的质量和位置，$M$ 是全身总质量；单个刚体的重心，是它内部每个小质点的质量乘以位置、再除以总质量。

### PD 控制质心

   * **静态平衡要做的两件事**

       * 跟踪一个本身比较稳定的自然站立姿势——比如立正一样、两脚水平地站在地面上（感觉一下就知道它是平衡的；单腿站立的姿势感觉就是不平衡的，很难实现静态平衡）。

       * 实时调整身体的控制，使得质心在水平面上的投影始终处于支撑面的中间。

   * **最简单的实现：在姿势 PD 之上再加一层 PD**

       * 思路：PD 跟踪姿势已经有一套力矩了；在这套力矩之上，再在一些关节上加上额外的力矩，这个额外力矩的目标是保证质心始终跟目标质心位置比较接近。

       * 目标质心位置通常可以取支撑面的中心；再简单一点，直接取两个脚中心连线的中点（一种近似）。

       * PD 写法：

$$\tau_{bal} = K_p\,(c_{target} - c) - K_d\,\dot{c}$$

       * $c$ 是当前质心在水平面上的投影位置，$c_{target}$ 是目标质心位置，$\dot{c}$ 是质心的速度（每个肢体的速度用质量加权平均）；这样算出来的东西当作一个力矩加到关节上。

       * 这里的 $K_p$ 和 $K_d$ 通常只能通过手调，多手工尝试几个值就可以得到比较好的效果（这种控制相对简单）。

   * **力矩加在哪里**

       * 常用的思路是加在踝关节（ankle，脚后跟那儿）或者髋关节（hip）上；自己可以体会：站在平面上让身体稍微向后倾斜，基本是脚踝或大腿根的髋关节在用力——实现上两种加一个就可以，不需要两个都加。

       * 左右两个 hip 或两个 ankle 完全可以采用不同的参数（当然实际上区别可能不是很大）。

### 雅可比转置控制

   * **virtual force（虚力）**

       * > **定义**：Jacobian transpose control 的目标——计算一套关节力矩，让它能够等价地实现某个力 $F$ 加在肢体某一点上的效果；这个力并没有真的加到肢体上，所以叫 virtual force（虚力），只是想实现它的效果。

       * 例子：在人的手上加一个力 $F$ 会让胳膊向上移动；这个向上移动的过程可以反过来等价地实现——给每个关节加力矩让它旋转、产生一个向上移动的动作，这组力矩就是 Jacobian transpose control 要计算的东西。

       * 与 IK 的联系：讲 IK 时有一个方法就叫 Jacobian transpose，这两个东西有非常大的联系——IK 同样是对前向运动学函数求导得到雅可比矩阵，而雅可比矩阵本质上就是 gradient，可以根据梯度做梯度下降或 Jacobian transpose 这类方法；对 hinge joint 或 ball joint，可以通过叉乘的方式计算出雅可比矩阵里的每一列。

   * **"效果相同"的衡量：功率相等**

       * 通常用做功来衡量，更进一步考虑瞬时状态：实际要求的是真实关节力矩做功的功率跟目标力做功的功率相同，功率是力乘以速度：

$$P = F^T \dot{x}, \qquad P = \tau^T \dot{q}$$

       * 力加在点上，这个点的全局坐标位置是每个关节转角的函数（前向运动学 $x = g(q)$，非线性函数）；它的导数（这个点的速度）是每个关节旋转的速度乘上一个雅可比矩阵：

$$\dot{x} = J(q)\,\dot{q}, \qquad J = \frac{\partial g}{\partial q}$$

       * 把 $\dot{x} = J\dot{q}$ 代入功率等式得 $F^T J \dot{q} = \tau^T \dot{q}$；要求这个等式对任意 $\dot{q}$ 都成立，那就是：

$$\tau = J^T F$$

       * 计算方式：对加力点 $x$ 的前向运动学函数求雅可比矩阵，转置一下、乘上 $F$。

   * **叉乘形式**

       * 力矩 $\tau$ 本质上是沿某一个轴的旋转，可以认为是沿三个不同旋转轴的一个叠加；从叉乘关系推导可得：每一个关节的关节力矩，可以直接用"从关节到加力点"的向量叉乘 $F$ 得到：

$$\tau_i = (x - p_i) \times F$$

       * $p_i$ 是关节的位置，$x$ 是加力点的位置。

       * > **易错点**：⚠️ 叉乘的顺序和向量的指向决定力矩的方向——从 root 向下算和从下往上算，加出来的力矩方向可能不一样，实现时要特别注意统一约定。

### 用虚力推质心：能力与边界

   * **虚力版平衡控制**

       * 换一种方式实现类似效果：还是用 PD 控制去计算，但算的不再是一个力矩、而是一个力；假设这个力加在质心上，目标是把质心推向目标质心位置。

       * "往质心上加力"本质上是没有任何真实的可能性的——正因为它是 virtual force，这个力不是真的加上去了、实际上也加不了；实际是通过一些关节力矩、用 Jacobian transpose 的方法来实现类似的效果。

       * 算法本质上跟前面一样：用质心相对各关节的位置组成向量，叉乘这个力 $F$，就得到那个关节需要加的力矩；有些时候要注意顺序（方向问题）——从 root 向下和 root 向上，加出来的力矩方向可能不一样。

       * 关节选择：通常上半身的关节可以不用关心（主要是下半身保持平衡），主要关心腿上的 hip（髋关节）、knee（膝关节）、ankle（踝关节）——两条腿一共六个关节，在每个关节上用 Jacobian transpose 加上相应的力矩，大概就可以实现平衡的效果。

   * **能做的更多效果**

       * 目标质心不只是一个平面上的投影点，它可以有高度：把目标质心的高度调一调，调低时角色就慢慢蹲下去、调高了再慢慢站起来——原地站起蹲下就是这样实现的。

       * 还可以加别的东西（比如朝向的控制）：在 virtual force 之外，用 PD 控制再算一些让角色左右转一转的力矩、额外加到腿上的关节上，角色就会稍微转一转身体。

   * **边界**

       * 这种方式实现的 balance 是非常弱的：稳稳地站住没有问题；微微地晃动、前后左右稍微转一转没有问题；推得小的时候没有问题（角色往前轻轻倾了一下又回来）；但推得大一点、大到这个角色必须往前走一步才能保持平衡时，这种控制就不 work 了，需要其他方式来控制。

### 控制角动量

   * **质心之外的扩展控制量**

       * 前面的控制都假设角色是不动的、没有速度；当角色有速度时，除了质心的位置之外，还可以控制质心的动量和角动量——比如让角动量尽可能小，它就会有相应的效果。

   * **走路摆手的角动量补偿**

       * 人正常自然走路时会不由自主地摆手、左右晃动手臂：本质上是在补偿走路时腿带来的角动量变化——在不顺拐的情况下，手的摆动带来的角动量跟脚的摆动带来的角动量会多少有一些 counterbalance（互相抵抗一部分），让整个身体的角动量比较小、更稳定。

       * 走顺拐、或者把手揣在兜里，实际上就要花额外的能量去控制角动量。

   * **不倒翁式平衡（2009 年的工作）**

       * 思路：通过控制角动量，可以实现动作幅度比较大的情况下仍然保持原地平衡这样的效果。

       * 它还求解一个一步的优化问题：前面讲的轨迹优化是优化一整条轨迹（可能一秒钟长）；这个方法里轨迹只优化一步，通过优化这一步得到下一时刻需要加多少力，来实现对动量和角动量的目标控制。

       * 效果：可以实现非常稳定的、不倒翁一样的平衡；但本质上来说它还是一个 static balance——还是一个原地的、站立不动的静态平衡。

### 静态与动态平衡的分界

   * **静态平衡的含义**

       * static balance 的意思：总是希望质心的投影待在支撑范围之内，整个控制过程都在保持这个状态。

   * **走路是动态平衡**

       * 走路（或者跑步，以及很多其他动物的运动）不是静态平衡：走路的时候不停地把质心往下落，其实就是不断摔倒的一个过程；但在摔倒的时候，刚好把脚移动到一个合适的地方把它撑住——人走路是非常典型的动态平衡。

       * 人总是要偷懒的：摔倒这样一个过程实际上可以帮人利用重力势能来增加速度、减少力的消耗。

       * 动态平衡（走路等动作）下该怎么控制角色保持平衡，是静态平衡方法之外的另一个问题。
