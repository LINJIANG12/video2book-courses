今天是 GAMES105 的第十次课，讲义上写的却是 Lecture 09，主题是 actuating simulated character——如何驱动虚拟角色产生动作。今天抓的是最基础的部分：怎么让角色动起来；等它能动了，后面几节课再讲怎么让它动得更好、更真实。

先把上节课的落点简单回顾一下。角色动画里处理的虚拟角色，大部分是由刚性的、不会变形的肢体加上关节构成的系统。要让角色动起来，就得在这个刚体系统上算出合适的合力和力矩——这主要是控制器（controller）要完成的任务。今天讲两件事：一是控制力到底是怎么施加到角色身上的；二是介绍一个非常简单的计算控制力的模型，就是所谓的比例微分控制（PD 控制）。

### 回看仿真：从质点到刚体

先快速过一遍上节课的仿真主线，今天要用的概念几乎都在里面。

从最简单的质点开始。给一个质点一个位置、一个速度，我们就可以根据速度不断更新它的位置，产生质点的运动。那如果想让质点产生我们想要的运动呢？通常需要在质点上加一个合适的外力：力产生加速度，加速度再通过积分去更新质点的速度和位置，最终形成动作。这套流程的根就是牛顿第二定律，大家非常熟了。

质点是个非常抽象的概念：它只有位置、只有速度，没有形状。这意味着不管质点怎么"旋转"，它所代表的状态都是完全等价的——旋转对质点来说根本不是一件事。

刚体就完全不同了。刚体和质点的区别在于：刚体是有形状的。形状会带来什么效果？刚体在不同的朝向之下，我们能观察到的外观是不一样的；换一个角度讲，不同朝向代表着刚体的不同状态。这是跟质点完全不一样的地方。

于是就引出了那个非常讨厌的东西：朝向，或者说旋转。它跟速度这类线性量不一样，是一个角度的量，而且是一个非线性的量。非线性会带来很多麻烦——上节课、包括以前讲各种跟关节旋转相关的操作时，我们已经反复领教过了。比如 IK 为什么要算 Jacobian？本质上就是因为这个非线性，我们只能通过那种方式来处理。

位置的变化率是速度；朝向的变化率，本质上就是角速度。但毕竟是个非线性的东西，旋转矩阵的导数跟角速度之间还有一点小区别——上节课讲过，它们之间差着一个坐标转换的关系。

### 惯性的两面：质量与转动惯量

质点除了位置和速度，还有质量。质量代表什么？代表对运动的某种抵抗。牛顿第一定律说的是：如果没有任何外力，物体会保持当前的运动状态。这种"保持运动状态"的趋势、或者说能力，就是这个物体的惯性；而惯性用什么来衡量？就是质量。

刚体的旋转也有一个对应的量，就是所谓的惯性张量，也常叫转动惯量。可以把它直接类比于质量：质量衡量的是对线运动改变的抵抗，转动惯量衡量的是改变一个旋转状态所需要克服的抵抗。

> **定义**：质量衡量物体抵抗线运动状态改变的能力；转动惯量（惯性张量）衡量刚体抵抗旋转状态改变的能力，二者是同一个"惯性"概念在线性和角度上的两面。

这个观念跟质量关系非常紧密。本质上，转动惯量是每个质点自己的角动量在整个刚体上积分之后体现出来的整体效果。所以一般来说，物体质量更大，转动惯量通常也会更大。

但转动惯量跟物体的形状同样有很大关系——这一点在上节课的公式里可以看得比较明确。上节课那个例子：几个球，质量大小相同，转动惯量却不一样。一方面，质量分布越靠近物体的边缘，带来的转动惯量通常越大；另一方面，不同的转动惯量对角速度变化的阻碍程度是不一样的。所以虽然质量相同、初始状态相同，这几个球的整体运动表现可能完全不一样——这就是转动惯量在起作用。

### 力、力矩与刚体运动方程

对质点，我们加一个力，力带来加速度的变化。刚体想让角速度变化，就要加一个跟角度相关的"力"——这个力就是力矩（torque）。而且实际上，任何一个外力都自带力矩的作用：力矩本质上等价于力臂乘以力，

$$\tau = r \times F$$

它代表这个力对物体旋转带来的影响。

线性方向上的定律是牛顿第二定律：$F = ma$；再进一步说，它其实应该是动量的时间变化率等于力。旋转方向上对应的则是欧拉运动定律：角动量的时间变化率等于力矩。其实牛顿第二定律也算是欧拉运动定律的其中之一——欧拉定律相当于把线、角这两条定律合在了一起。

唯一的区别，还是那个非线性的角度量。对速度求导，直接就得到加速度；但对角动量求导就没这么干脆了，因为角动量里的转动惯量跟物体的形状和朝向是同时相关的——朝向一直在变，转动惯量也跟着变。所以情况要稍微复杂一点：除了我们熟悉的"转动惯量 × 角加速度"这一项之外，当前的角速度自己也会贡献一项额外的效应——它不是力，但代表了某种力的效应，就是那一项叉乘：

$$\tau = \frac{\mathrm{d}L}{\mathrm{d}t} = I\alpha + \omega \times (I\omega)$$

把力和力矩合到一起，就是刚体的运动方程，可以把它写成矩阵的形式。给定一个外力和外力矩，求解这个运动方程，就得到在这样的外力作用下角加速度和加速度（速度变化率）是多少；再通过积分，进一步得到最终的动作——物体该怎么动、速度怎么变化、位置怎么变化。

到这里可以把整条对应关系摆在一起看：

|            | 线性（质点）             | 角度（刚体）                          |
| :--------- | :----------------------- | :------------------------------------ |
| 状态       | 位置 $x$、速度 $v$       | 朝向 $R$、角速度 $\omega$             |
| 惯性       | 质量 $m$                 | 转动惯量 $I$                          |
| 被什么驱动 | 力 $F$                   | 力矩 $\tau$                           |
| 运动定律   | 牛顿第二定律 $F=\frac{\mathrm{d}p}{\mathrm{d}t}$ | 欧拉运动定律 $\tau=\frac{\mathrm{d}L}{\mathrm{d}t}$ |

刚体仿真，本质上就是这张表的两列同时上演：线性一侧和角度一侧各算各的，又通过"每个力都自带力矩"纠缠在一起。

### 在物理引擎里定义一个刚体

这套运动方程还顺带告诉了我们一件很实际的事：如果需要在物理引擎里定义一个刚体，要给出哪些参数。不管什么物理引擎——游戏里常见的比如 Bullet、Havok，其他各家也大同小异——定义刚体的时候都需要给这些量。

首先是两个非常重要的参数：质量和转动惯量。它们代表刚体的惯性部分，而且不管刚体怎么动，都是相对固定的一组量。

其次，刚体有位置、有朝向、有速度、有角速度——这代表它运动的部分。

另外一部分就是所谓的 geometry，也就是刚体的形状。这里有个挺有意思的视角：刚体本身可以当成一个抽象对象来看——我们其实不关心它具体长什么形状，只关心在给定了这样的质量和转动惯量之后、加上一个力，它会产生什么样的运动变化。形状本身，通常来讲是跟刚体的定义相对独立的一个东西。

那形状带来什么？大致有这么几类影响：

- **外观**：我们看到的物体到底长什么样——是一个 box、一个球、一个立方体，还是一个 mesh（人形、动物这样的网格）；
- **转动惯量**：前面说了，转动惯量跟物理形状直接相关——box、球、球壳、实心球，都会带来不同的转动惯量；
- **质量**：某种程度上也跟形状相关——密度基本都跟水差不多，体积其实就代表了重量；
- **碰撞检测**：这一项非常重要。人能站在地上，是因为地面给了脚一个支持力；那地面应该在什么地方给支持力？你得告诉它，脚的形状是什么。

所以定义一个 rigid body，除了纯粹的物理量之外，还有相应的几何量，主要就是形状。不管哪一种物理引擎，这些都得给。

### 关节是一种约束

上面说的都是单个刚体。多个刚体怎么办？上节课讲的部分是：可以把多个刚体看成一系列独立的单个刚体分别来计算。而角色之所以是一个"整体"，是因为有关节把这些刚体连接起来。

关节代表什么？关节其实代表一种约束。约束是什么呢？比如两个物体，为了让它们在运动过程中不能分开——从几何的角度讲，就是它们俩必须满足某一个相对关系，而且这个关系在运动过程中不发生变化。

另一方面，为了维持这个相对关系，得有力。打个比方：我抓着一个物体往前扔，如果不想让物体离手，那我在运动过程中就必须不断给物体加力，才能让它不离开、不跟我的手分开。关节也是一样的：两个刚体（两段肢体）在运动过程中出现分开倾向的时候，约束就会相应地产生一个约束力，把它们拉住、保持合在一起。

一旦我们能计算出这个约束力，这两个刚体本质上就又是"在所有外力之下独立运动的刚体"了。写成运动方程的话，就是把两个刚体各自的部分拼在一起、拼成一个更大的方程；而关节约束是这些方程之外的额外方程，约束力就是由这个约束方程给出的。

这个方程写起来比较麻烦，可以把它简化成更紧凑的格式：把矩阵用简单的符号来代替，中间求导产生的叉乘项也可以用另外一个函数来定义——本质上是同一个东西，只是换了写法。

更多的物体也是一样。正常人可能有十几个刚体和关节，本质上构成一个更大的系统：每个关节带来相应的一行约束，同时产生一个对应的约束力。整个仿真过程，实际上就是在构造这样一个运动方程——包括每个关节约束对应的约束方程，以及所有外力和约束力共同决定的加速度——然后求解得到加速度，最后通过欧拉积分得到刚体运动的动作。

### 在仿真器里搭一个角色

定义单个刚体，要给质量、位置、形状。那定义一个角色呢？角色由若干刚体通过关节连接而成。对人形角色来说，每个关节总是连接两个刚体，所以刚体的数量和关节的数量刚好差一：关节数比刚体数少一个——这样刚好保证整个连接关系成立。

具体要定义两块东西。一块是每个刚体的各种属性：位置、朝向、转动惯量等等；另一块是刚体本身的形状。

形状通常跟角色本身的外观不完全一致。角色大部分情况下是一个网格——人形的网格，或者一只动物；但在仿真的过程中，我们通常会用更简单的几何体来代替它：胶囊体（capsule）、立方体（box）、球（sphere）这类。

为什么？本质上还是为了碰撞检测。碰撞检测做的事情是：判断两个几何体之间有没有相交，如果有的话，相交的位置在哪里。两个不规则网格之间做这件事很麻烦：网格形状不规则，要判断哪些部分相交，基本得把整个网格遍历一遍——虽然有一些数据结构能帮我们加速，但整体上还是比较耗时的过程。还有一层：我们处理碰撞是希望两个物体能分开，而不是互相嵌进去，所以要能判断相交处哪一侧在物体里边、哪一侧在外边；对网格来说，很多时候这个里外并不好判断。简单几何体在这两件事上都要轻松得多，能显著提高效率。当然这也不绝对，很多时候也可以直接用 mesh 来完成这个工作。

接着还要定义关节，因为关节最终会变成运动方程里的约束。最起码要知道：关节在初始化的时候在什么位置。关节的含义是，它所连接的两个物体在运动过程中、在关节这个位置永远不会分开——这意味着，关节位置在第一个物体局部坐标系下对应的位置，和它在第二个物体局部坐标系下对应的位置，永远重合。这一对"对应位置"，由初始化时关节的位置、以及两个刚体的位置共同定义出来。

关节的类型还会带来更多影响。膝盖非常典型：它是一个单自由度的关节。如果膝盖突然向旁边弯过去，那人多半就是骨折了——这肯定不对。所以不同类型的关节对应不同的约束方程：比如 hinge 关节，除了要求关节两端不会分开之外，还要求在 hinge 这一个自由度之外的其他自由度上，两个刚体的旋转是相同的。

总结一下：在仿真引擎里定义一个角色，就是定义每个刚体的性质（位置、朝向、转动惯量、形状），再定义每个关节的性质（初始位置、类型）。这样，这个角色就在仿真器里建立起来了。

### 仿真器黑盒里的流水线

角色建立起来之后，仿真过程大概可以写成这样一个框图。整个仿真最关心的是什么？是每一个刚体在仿真过程中位置、朝向、速度、角速度等等的变化——这些共同构成了整个角色的状态。

这里有个小问题值得停下来想一下：状态里为什么没有关节的位置？因为前面说了，关节本身是一个约束：它总是满足"相对于某个刚体的相对位置保持不变"，约束本身就决定了这件事。所以只要知道每个刚体（每段肢体）的位置、朝向这些信息，对应关节的性质可以很容易地算出来，不需要单独存。

```text
t 时刻状态：每个刚体的位置、朝向、速度、角速度
   │
   ▼
┌─ 动力学仿真器（黑盒子内部）──────────────────
│  1. 接触检测：脚的哪些部分跟地面接触
│  2. 碰撞建模：法向 penalty 力，或当作约束求解
│  3. 关节约束建模 + 其他用户输入建模
│  4. 构造运动方程并求解 → 得到加速度
│  5. 辛欧拉积分：先由加速度更新速度，
│     再用新速度更新位置
└──────────────────────────────────────────────
   │
   ▼
t+1 时刻状态：每个刚体新的位置、朝向、速度、角速度
```

读图：仿真器每个时间步吃进当前状态、吐出下一时刻状态；关节位置不在状态清单里，因为它由约束决定，随时可以从刚体状态推出来。

把黑盒子拆开看，大概分成这么几个环节。首先是接触检测（contact detection）：比如站在地上，要判断脚的哪些部分跟地面是接触的。接触之后要加上相应的碰撞模型：最简单的碰撞模型是基于法向的 penalty 模型——根据脚跟地面相交（穿透）的程度计算一个力，这个力可以保证脚是压在地面上的；另一类做法是把碰撞变成一个类似于关节约束的约束来实现，在求解运动方程的过程中自动算出这个力。碰撞检测完成之后，接下来是对关节约束的建模，以及对其他用户输入的建模，把这些共同变成运动方程，然后求解——解出来的是加速度。再对加速度做两次积分：这是辛欧拉（symplectic Euler）的积分方式，先积分加速度得到速度的更新，再用更新后的速度去更新位置，最终生成动作。

通常我们讲仿真、讲物理引擎，它对我们来说是一个黑盒子；但黑盒子里的流程大概就是这个样子。不管什么样的物理引擎，基本来说都是这么一个东西。

### 什么都不加：ragdoll

那直接把角色建到仿真器里、跑一个仿真，会看到什么？角色确实在仿真，动作本身是物理真实的、完全满足物理规律——但问题是，它只会瘫倒，摊成一堆。为什么？因为现在里面没有任何控制：我们就是让这个角色单纯地在重力作用下产生动作。

这个就是 ragdoll（布娃娃）仿真。其实挺常用的——第一节课我们就提过这个概念：比如一个角色失去意识了，它的动作差不多就是这个样子。

有意思的是，真实世界里也有对应的现象。人被绊倒的那一瞬间：人的神经反射是有一定时间的，大概 0.2 秒左右。被突发事件——比如说绊了一下——之后，大概零点几秒的范围内，大脑是来不及反应的，这个时候人的动作差不多就是 ragdoll 仿真。当然不会这么彻底、不会完全没有任何反抗：毕竟肌肉本身还是有一点点反抗的力量，带着一点弹性的效果，不会瘫得那么干净。但本质上，人无法即时反馈的时候，动作就是类似 ragdoll 这样的效果。

不过，如果仿真只能做到这样，那就比较无聊了——它做不出我们想要的复杂动作。为了让一个刚体、一个物体按照我们想要的方式去移动，通常需要对它施加外力。

### 只能加力，不能摆姿势

这里就是物理仿真跟前面关键帧动画最大的区别。关键帧动画：想让角色到达某个状态，直接把角色的状态、位置设置成对应的姿态就可以了。物理仿真不能这么干：我们不能直接做这样的设置，只能在每个关节上、每个物体上施加力和力矩。这些力和力矩会体现在运动方程里，改变每个刚体的速度、加速度，从而进一步影响角色的动作。

那力和力矩对一个刚体来说，具体怎么加？通常我们把它们等价地认为是加在刚体质心上的：不管加了多少力、在刚体的什么位置加力，最终都会体现成"加在质心上的一个合力"，加上"以质心为轴的一个力矩"。

如果我就是不加在质心上、偏要加在刚体旁边，也没有问题：这个力等价于在质心上加一个同样大小的力，同时在质心上额外产生一个力矩效果——就是一个等价改写。

还有上节课提到过的一种情况：我可能不加力，单纯只加一个力矩。这个力矩等价于什么？等价于加了一对大小相同、方向相反的力。这对力因为大小相同、方向相反，在质心上的合力是零——不会产生质心速度的变化；但它会让物体产生旋转的效应——这个效应就是力矩的效果。

> **易错点**：对一个真实的物体，我们其实不可能"把一个力矩加上去"。力矩本质上只是一个数学上的描述；所有的力矩，本质上都是力产生的效果（让角速度发生变化的那类效果）。可以近似地认为，力矩就是一对力产生的效果。

这一点很重要，因为它直接回答了下一节的第一个问题：说"在关节上加力矩"的时候，物理上真正发生的到底是什么。

### 关节力矩：从电机到 ±τ

以上是单个刚体：为了驱动它，可以对每个刚体单独加相应的力和力矩，整体推动这些刚体产生运动。但对一个由很多刚体通过关节连在一起的人形角色，更常见的方式是：为了驱动用关节连接在一起的一对刚体，在关节上加一个力矩——所谓的关节力矩（joint torque）。

关节力矩这个词我们会不断地提到，但要真正搞清楚，得多讲两句。这里有两个问题：第一，什么是关节力矩？凭什么可以在关节上加力矩？第二，我们的运动方程里其实没有"关节"这个东西——关节只是关于运动的一个约束，运动方程里真正起效果的力都是加在刚体上的。那"我在关节上加了 1 牛·米的力矩"这句话，到底对应把什么加到它所连的两个刚体上？

#### 凭什么关节上能加力矩

第一个问题，前面其实已经埋了答案。想一个机械臂：机械臂运动的过程中，真正驱动它的是电机、马达。电机的基本原理是什么？一个电磁铁（线圈）放在不断变化的磁场里，磁场给电磁铁产生力，这个力推动电机旋转。

关键在这一系列力的性质：它们是一系列大小相同、方向相反的力。合在一起合力为零，所以不会带来质心速度的变化；但会带来旋转的变化——本质上，这就是一个力矩的作用。

所以当我们说"在一个关节上加了一个力矩"的时候，可以想象关节里装着一个电机：一个转子在那儿转，转子带来的旋转效应，就是这个力矩。

#### 这个力矩怎么落到两个刚体上

再具体化。两个刚体中间用一个关节连接，把关节放大了看——它就是一个电机：磁场作用在线圈上，产生一系列的力。

这些力相当于什么呢？相当于其中一个刚体对另一个刚体施加的力，只不过施加的位置是一系列的点，不是一个点。

现在来算这组力对第一个刚体质心的总力矩。设关节中心相对第一个刚体质心的位移是 $r_1$，各个施力点相对关节中心的位移是 $r_i$，那么每个力 $f_i$ 相对第一个刚体质心的力臂就是 $r_1 + r_i$，总力矩就是

$$\tau = \sum_i \left( r_1 + r_i \right) \times f_i = r_1 \times \sum_i f_i + \sum_i r_i \times f_i$$

把 $r_1$ 提取到外面之后，再考虑到这组力本身的大小之和是零（$\sum_i f_i = 0$），第一项直接约掉，只剩下

$$\tau = \sum_i r_i \times f_i$$

这里你会发现一个挺有意思的结论：这组力对第一个刚体质心产生的等效力矩，跟关节装在刚体的哪个位置没有关系——$r_1$ 根本不出现在结果里，它只跟关节内部施力点相对于关节中心的距离 $r_i$ 相关。

对第二个刚体做类似的计算，但要小心一件事：前面这组力是第二个刚体施加给第一个刚体的；根据牛顿第三定律，第一个刚体也会对第二个刚体施加一组相反的反作用力。所以第二个刚体受到的力矩，就是这组反作用力带来的——推导完全一样，只是每个 $f_i$ 前面多了个负号；同样因为合力为零，$r_2$ 的部分也一样被约掉。

所以最终得到一个很干净的结论：这一系列力的总效果就是一个力矩 $\tau$——这就是我们说的"在关节上施加的力矩"。它落到刚体上的方式是：在其中一个刚体上施加大小为 $\tau$ 的力矩，同时在另一个刚体上施加大小为 $-\tau$ 的反作用力矩。

> **结论**：在关节上施加力矩，等价于在关节两端的两个刚体上分别加 $\tau$ 和 $-\tau$：远离 root 一侧的 child（子刚体）加正向力矩 $+\tau$，靠近 root 一侧的 parent（父刚体）加反向力矩 $-\tau$。

习惯上，把关节远离 root 一侧的刚体叫做 child（子刚体），靠近 root 一侧的叫做 parent（父刚体），力矩就是这样成对地加上去的：

```text
        root 方向
           │
     [parent 刚体]   ←── 施加 −τ（反向力矩）
           │
           ●  关节（想成一个电机：内部是一系列
           │     大小相同、方向相反的力，合力 = 0，
           │     总力矩 = τ）
           │
     [child 刚体]    ←── 施加 +τ（正向力矩）
           │
        远离 root 方向
```

读图：所谓"在关节上加一个力矩"，在运动方程里的实际操作，就是对这个关节连接的两个刚体，分别加上 $\tau$ 和 $-\tau$。

### 控制器：实时算出每个关节的力矩

到这里，"如何驱动一个角色、驱动一个多刚体系统来产生运动"的骨架已经有了：很简单的方式，就是在每个关节上加力矩。但注意，我们只是说了"加一个力矩"，还没有讲这个力矩该怎么加——数值从哪来？

"怎么加"这件事，在计算机动画里、在运动机器人控制里，有一个专门的模块来完成这个功能，就是所谓的控制器（controller）。

控制器是什么？简单描述：它是这样一个模块——根据角色当前的状态，比如当前的位置、朝向、速度、角速度等等，再加上一些额外的控制信号，比如想让它做出什么动作、想让它走到什么地方去；根据所有这些信息，实时地为每一个关节计算关节力矩，然后把这些关节力矩交给运动方程、交给仿真器，去影响最终角色动作的变化。

这就是运动控制的整个过程。

> **结论**：开场说的两件事，第一件——控制力怎么施加到角色身上——到这里已经有了完整的答案：力以"质心合力 + 力矩"的形式进入刚体，关节力矩则以 $\tau$ 与 $-\tau$ 成对地落在关节两端的刚体上，再由运动方程和积分变成动作。至于每个关节的力矩具体该怎么实时算出来，就是开场提到的那个最简单的模型——比例微分控制（PD 控制）——要回答的问题。

## 驱动仿真角色：运动方程、欠驱动与 PD 控制
> 对应块：BLK20 | 覆盖分集：P10下 | 块标题（分集名）：《Lecture09 Actuating Simu》

### 运动方程：一个方程，两种用法

先问一个问题：运动方程到底建立了谁和谁的联系？其实本质上就是 $f = m a$——速度、加速度和力之间的关系。拿方程里的项来说，$\dot{v}$ 是加速度，$f$ 是我加的外力，所以它实际上是加速度和外力之间建立起来的连接：左边是质量项贡献的加速度，再加上由速度带来的一部分所谓的惯性力；右边是我们加的外力，以及约束力。这就是我们的运动方程。

对一个运动方程来说，用法有两个方向。一方面，我可以给出加的所有外力——比如关节力矩、重力，或者碰撞力这些——然后去求解方程里的加速度。这个过程叫**前向动力学**（forward dynamics）：我知道当前的状态，加上力之后算出加速度，进而算出 motion，算出动作。

想想看，前面讲 IK 和 FK 的时候也遇到过这种成对的概念：前向运动学是给出每个关节的旋转，去计算末端点的位置；逆运动学是知道末端点的位置，反过来算每个关节的旋转。动力学这边完全类似：**前向动力学**是知道每个力，算它的加速度；**逆动力学**是知道了一个加速度，想知道这时候应该加多少力才能产生这个加速度——刚好是跟前向动力学相反的过程。

但本质上说，不管是前向动力学还是逆动力学，都是同一个运动方程的两种用法：方程还是那一个方程，只是给出的已知量不同，要求解的另一个量也对应不同。

通常讲的物理引擎、或者说仿真器，实际上就是一个前向动力学的求解过程：知道力的大小，通过求解运动方程得到加速度，得到速度，进而得到运动。反过来，控制部分在某种程度上可以认为是一个逆动力学的过程——我知道想让角色产生什么样的动作，需要计算出力是多少，才能生成这样的动作。当然，实际的控制要比这更复杂一点。

```text
      想要的动作
          │  控制器（逆动力学）：想要什么动作，反推需要多大的力
          ▼
      关节力矩 τ
          │  仿真器（前向动力学）：解运动方程得加速度
          ▼
      加速度 → 速度 → 运动
          │
          ▼
      角色状态 ──▶ 回到控制器，循环往复
```

读图说明：控制与仿真各占运动方程的一头——控制器从"想要的动作"反推力，仿真器从力正推运动，角色状态在两者之间循环流动。

### 欠驱动与完全驱动

控制器的作用，是根据角色当前的状态，计算出比如每个关节需要加多少关节力矩，才让这个角色动起来。这里算出来的关节力矩，它的总自由度——也就是总参数量——跟定义角色状态所需要的参数量之间，会有一个数量关系：反正是两个数量，总有一个大一个小。

> **定义**：如果驱动力的自由度比角色本身状态的自由度要小，这个系统叫做**欠驱动系统**（underactuated）；驱动力的自由度与状态自由度相等或者更大，就是**完全驱动**（fully actuated）。

最典型的完全驱动例子是机械臂。机械臂固定在一个位置上，每一个关节的自由度都可以很精确地去控制它——当然这里还有一些其他的控制问题，但理论来说，我们可以通过关节力矩精确控制机械臂每一个关节的位置，让它生成一系列不同的姿态。

而人形角色就是一个非常典型的欠驱动系统。为什么？主要因为角色的根关节是不固定的。不固定的意思是：我没有办法直接去更改根关节的性质。前面提过，这样的角色关节数量比刚体数量要少一个，因为每个关节连接两个刚体——关节少一个，关节所能提供的驱动自由度，就一定比所有刚体状态的自由度总和要小，所以整体上它是一个欠驱动系统。

从另一方面看也是同一件事：我们不能直接控制角色的全局姿态。比如宇航员在空间站的失重状态——如果没有任何跟空间站外壁的接触，他其实只会在空中漂浮。虽然可以改变身体的姿态，但整体的质心、全身的位置不会发生变化，因为这时候缺少对全身质心进行控制的力。这是欠驱动系统非常典型的一个性质。

再比如人走路。走路的时候，我们要非常小心地去"控制地面"：我给地面一个力，希望地面给我的反作用力能够推动质心向前移动，同时让我不摔倒。这个过程本质上也是因为我是一个欠驱动系统——我不可能直接控制质心的位置，只能间接地对外界施加一个影响，指望外界给我们带来一个反作用。

所以相对来讲，欠驱动系统的控制要比完全驱动系统的控制难很多。

前面只是个简单描述，说得更严格一点：对于完全驱动的系统，对任何一个运动目标——比如一个加速度——我们总是可以找到一组力，使得系统产生这样的加速度；而对欠驱动系统，对很多我们需要的加速度来说，没有办法找到一组力能产生这样的动作，因为驱动力的自由度不足，无法产生所有想要的力矩。

> **结论**：控制欠驱动系统，本质上就是希望它不要落到我们无法控制的那些状态之下——系统总有一些状态是可控的，控制要做的就是始终待在这个可控范围里。

后面讲的怎么保持平衡、怎么走路，主要目的就是这个：避免掉到一个无法控制的状态里。具体一点说，人正常走路时，小脑总是在帮助我们保持平衡，其实就是把我们限制在"始终可控"的范围内。那被绊了一跤为什么会摔倒？本质上就是离开了"我能控制"的那个状态范围。

### 前馈控制与反馈控制

控制策略做的事情，是根据角色当前的状态，计算出一系列控制信号——比如关节力矩等等。可以用一个符号来表示，比如控制器就是 $\pi$：它把当前的状态、以及可能有的时间作为参数，根据这些参数计算下一时刻该加的力。这里有一个关键点：**控制策略使用哪些信息，决定了这个控制策略本身的性质**。

**前馈控制**（feedforward control）：控制策略不考虑当前角色的状态，总是去执行一个预定义好的控制信号计划。这个计划本身可以预先定义得很好，可能考虑了系统的各种状态；但正因为它不看角色当前的真实状态，一旦系统在某一时刻遇到了扰动、偏离了原计划里的那个状态，它就毫无办法。比如一个角色不停地向前走、向前迈腿——它完全没有考虑到自己现在正躺在床上，于是最后就是躺在床上不断地做出迈腿的动作，但是站不起来。这就是前馈控制的特点。

**反馈控制**（feedback control）：最基本、最大的特征，是它会根据当前角色的姿态去计算、调整相应的控制，使得不会偏离某个预定的目标太远。而且反馈控制在设计过程中，通常本来就期待会遇到一定的扰动——比如走路过程中可能被人推了一下，设计时就预设了"我可能会被推"，于是被推之后会自动根据身体状态去调整步子的大小，来保持平衡。

| | 前馈控制 | 反馈控制 |
| :--- | :--- | :--- |
| 依据的信息 | 预先定义好的控制计划（本质上是时间表） | 角色当前的真实状态 |
| 遇到扰动时 | 照旧执行原计划，状态偏了也浑然不觉 | 根据被扰后的状态调整控制，拉回目标附近 |
| 设计时的心态 | 把计划本身定义得尽量完美 | 默认扰动一定会发生，按"会被推"来设计 |

实践中很常用的一类控制策略，就是**比例微分控制**（PD 控制）。它本质上是一个反馈控制。不过要注意，前面说的前馈、反馈，其实在不同的尺度上会互相转化：一个控制器到底是前向的还是反馈的，取决于我们的控制目标，可能会有不同的结论。比如 PD 控制通常说是反馈控制，但在角色动画里使用 PD 控制时，通常反而说它是前向控制——因为它所反馈的部分和我们真正想去控制的部分并不完全一致。这件事后面会有一个例子专门讲。

### 从一颗珠子开始：PD 控制的由来

什么是比例微分控制？举一个简单的例子：一根竖直放置的杆，上面穿了一个珠子（一个物体），这个物体只能沿着杆移动。杆是竖的，物体会受重力作用——如果没有任何外力，它就顺着杆掉下去了。

我们希望设计一个控制器：根据这个物体当前的位置和速度，计算出一个力，把这个物体拉到一个目标高度上。这个力应该是多少、该怎么算？

对这个问题本身来说，其实不难——我们知道重力，高中物理已经算过很多类似的题，可以直接算出一个非常精确的解。但如果这个"重力"不是一个简单的重力，而是一个非常复杂的、经常变化的力，那这个力就不太好算了。

为了解决这个问题，有一个更简单的想法：**压根不用管这个重力到底是什么**——我自己也不知道它是什么——我只知道这个物体跟我的目标之间差了一个偏差，它不在目标位置上。那我根据这个偏差乘以一个比例系数，来决定该加多少力：

$$F = K_p \left( x^* - x \right)$$

当前位置 $x$ 离目标位置 $x^*$ 比较远，就加一个比较大的力，把物体拉得更快一些；两者比较近，就把力放小一点——因为它已经足够好了。这就是**比例控制**：最终加的力是误差乘上一个比例系数，这个系数叫 stiffness，刚度系数 $K_p$。如果物体在目标上方，偏差是负值，算出来就是一个向下的力。对这个非常简单的系统来说，一个比例控制就能实现"把物体拉到目标点"这个功能。

但如果就按这个方式控制，你会发现物体**并不会停在目标高度上**。物体在目标高度下方时，总有一个向上的力在给它加速；等它刚好到达目标高度的时候，误差是零、力也是零，可它还带着速度，会继续向上冲；冲到上方之后，力反过来了，给它减速；减速到头又掉下来……这个过程不断重复，物体的轨迹大概是一条不断振荡的正弦曲线。

毛病出在哪？物体明明已经有向上的速度了，说明不加力它也能向上移动，这时候就不该再帮它。所以改进方向是：**如果物体有向上的速度，就把力减小一点**。写到公式里，就是在按位置算的力后面加第二项，代表当前物体的速度：

$$F = K_p \left( x^* - x \right) - K_d \dot{x}$$

物体速度朝上，就把需要加的力减掉一部分——这就是**微分控制**。它的出发点可以这样想：物体已经有向上移动的趋势时，我不需要再加大力。换一个角度看，这一项其实代表了一种**耗散**：相当于物体本身受到一些阻力、一些风阻，风阻会减小它移动的速度，最后让它——可能开始还有些震荡——逐渐停在目标位置附近。所以微分项本质上等价于一个阻力，把能量耗散掉。

为什么叫"比例微分"控制？把 $e = x^* - x$——目标位置减当前位置的差——作为控制目标，我们想让它最小：前面那一项是误差本身的正比部分，也就是比例项；后面那部分是误差的一阶导数、即误差的微分的正比部分，也就是微分项。合在一起，就叫比例微分控制。

### 稳态误差，以及为什么不加积分项

比例微分控制有一个非常重要的性质：用这个控制器一直加力运行下去，它最终会停在一个位置——但这个位置并不在目标位置上，而是比目标位置稍微偏下一点，总是有一点点小误差。这个小误差叫 steady-state error，稳态误差。

为什么会有稳态误差？首先，速度为零的时候，微分项是零，不提供任何力；而比例项产生的力的大小由误差决定。在我们这个例子里，物体受重力作用，要让物体停在某个位置不动，这个力必须跟重力大小相同，不然它就掉下去了。为了产生跟重力一样大的力，误差就必须满足相应的关系——所以我们总是会有这么一点小偏差。特别是这种需要抵抗重力的场合，稳态误差几乎必然出现。

而且由于需要抵消的力（重力）是固定的，这个偏差的大小跟刚度 $K_p$ 之间是反比关系：

$$x^* - x = \frac{m g}{K_p}$$

提高 $K_p$，最终会减小稳态误差，控制更精确。但坏处是什么？整个系统会表现得非常坚硬、非常刚性；另外它还会带来数值不稳定。所以 $K_p$ 通常不能设得太大，设一个合理的值就可以了——后面会有一个具体的例子。

> **提示**：稳态误差不是 PD 控制"没调好"，而是"比例项的力必须恰好抵消重力"这个物理要求留下的必然残余；想靠一味调大 $K_p$ 消灭它，会撞上刚性和数值不稳定两堵墙。

当然，还有另一种方式去掉这个误差，就是大家从小到大经常听到的一个词——**PID 控制**，比例积分微分控制。比例项是误差的正比关系，微分项是误差导数的正比关系，而积分项是误差对时间的积分、一个积累，再对这个积累取正比。因为这个积累效应，它可以使得最终没有稳态误差。

但在动画里我们通常很少使用积分项，原因有两个。其一，比例项和微分项，我知道当前时刻的误差、当前时刻的速度，就可以直接算出来；而积分项跟历史相关，为了计算它，还得专门用一个变量去记录前面这一段时间误差到底是多少，把它不断累加起来——这在实现上会带来麻烦。其二，特别是当目标本身在不断变化的时候，积分项会带来很多控制上的不稳定问题。所以对动画来说，或者对我们常见的这些控制来说，通常只用到 PD 的部分——比例微分的部分，积分的部分一般不用。

### 用 PD 控制驱动每一个关节

从珠子这个玩具模型，回到更真实的场景——比如一个人，一个物理仿真角色。我们通常通过 PD 控制，去计算需要在角色的每个关节上加多少力矩。形式上跟刚才那个玩具模型是一样的：目标是计算关节力矩——一个关节连着两个物体——用这个力矩让这两个刚体之间的夹角达到一个目标位置。

需要的关节力矩，首先是当前位置和目标位置之差乘一个比例，再加上当前速度和目标速度之差乘一个比例：

$$\tau = K_p \left( q^* - q \right) + K_d \left( \dot{q}^* - \dot{q} \right)$$

其中，目标速度通常大部分时候是零。虽然目标速度是零，但运动本身不是零——因为我们的目标会不断变化。所以在角色动画、物理仿真里用的 PD 控制，通常就是这样一个形式：

$$\tau = K_p \left( q^* - q \right) - K_d \dot{q}$$

前面一项是目标减掉当前关节的旋转、乘一个比例；第二部分是阻尼项，当前旋转速度乘一个比例；两者之和就是关节力矩。算出关节力矩之后，把力矩应用到每一个刚体上，就能让角色产生运动。

### 刚度与阻尼的手感

PD 控制里有两个参数：一个是 $K_p$，stiffness，刚性的参数；另一个是阻尼的参数 $K_d$。这两个参数对最终的动作、对跟踪的效果影响非常大。

看一组对比演示：随便设一组相对合理的 $K_p$ 和 $K_d$，让角色从任何一个状态开始，把 T-pose 作为目标状态，用 PD 控制计算每个关节的力矩、应用到角色身上——大概是那样一个效果。然后分别把两个参数往两个方向拧：

刚度 $K_p$ 调小：产生的力相对来说也很小，角色很难达到目标位置——而且不管经历多长时间都到不了，因为它的力不够大。

刚度 $K_p$ 调大：角色会表现得非常硬、非常僵硬，会非常快地从任何一个姿势弹到 T-pose 上，整个角色都硬邦邦的。

阻尼 $K_d$ 调小：角色会有很明显的震动效果。本质上这有点像弹簧——弹簧松手的时候会产生震动；刚度大而阻尼小的角色在跟踪目标位置的过程中，会不断地超调、上下震荡。

阻尼 $K_d$ 调大：角色还是可以正常跟踪一个姿势，但要花更多的时间才能到达那个姿势。这个视觉效果似乎跟刚度小的那个差不多，但区别在于：刚度小的时候，角色是**没有办法**达到那个姿势的，多久都不行；阻尼大的时候，花了很长时间之后，角色**最终会达到** T-pose，只不过过程显得比较慢、比较绵长。

| 参数 | 调小 | 调大 |
| :--- | :--- | :--- |
| 刚度 $K_p$ | 力不够，怎么等也到不了目标姿势 | 非常硬、僵硬，瞬间弹回目标姿势 |
| 阻尼 $K_d$ | 不断超调、震荡，像松手的弹簧 | 最终能到目标姿势，但过程又慢又绵长 |

> **易错点**：刚度小和阻尼大在"慢"的观感上相似，本质完全不同——刚度小是"力不够，永远到不了"；阻尼大是"最终到得了，只是慢"。

### 跟踪控制：给每个关节一条目标轨迹

有了 PD 控制，控制问题在形式上就变了：本质上变成了**去设计目标轨迹**——目标位置设计好之后，总可以通过 PD 控制算出关节力矩，去产生动作。

对一个关节，我们给它一条目标轨迹；在每一时刻，从这条轨迹里拿出一个状态来，作为目标状态，用 PD 控制算出关节力矩。全身动作呢？比如一个正常的人，身上有十几个到二十几个关节，每个关节都对应一条自己的目标轨迹；每个关节根据自己的目标轨迹，算出当前时刻该加多少关节力矩，来驱动角色产生动作。这就是所谓的跟踪控制（tracking control），通常是这样的结构：

```text
      目标轨迹 q*(t)
          │ 每一时刻取样
          ▼
目标状态 ──▶ PD 控制 ◀── 当前状态 (q, q̇)
          │
          ▼
      关节力矩 τ ──▶ 施加到每个刚体 ──▶ 产生运动
```

读图说明：每个关节一条目标轨迹，每一时刻取一个目标状态喂给 PD 控制，算出的力矩驱动刚体——全身十几二十个关节同时在跑这套循环。

跟踪控制最关键的部分，是我该如何设计一系列这样的轨迹，能让角色产生我们想要的动作。第一节课里其实已经放过这个视频了——那是很老的、95 年的一个工作：通过手工设计，对每一个动作专门设计一条轨迹，让角色用对应的跟踪控制计算关节力矩、产生动作。当然，手工设计是非常麻烦的。

而且就算轨迹设计好了，PD 控制去跟踪也未必跟得住，原因有两个。一个是 PD 控制本身的稳态误差；另一个是相位差——用 PD 控制跟踪某个轨迹的时候，生成的动作跟目标轨迹大概会差一点点相位：比如目标里这个手已经抬起来了，角色可能延迟大概零点几秒才能把手抬起来。

所有这些加在一起会导致什么？比如我设计了一个后空翻的动作，看着挺不错，但一旦用 PD 控制去跟踪这个轨迹，它生成的动作多半没办法把后空翻做完。

那手工设计麻烦，我们动捕一下吧。直接用动捕数据？一样的问题：用 PD 控制直接跟踪动捕数据，跟踪效果是非常差的——角色大体上还在做那个动作，但因为本质上这是一个欠驱动系统，跟踪稍微有一点点偏差，就会造成后面无法准确修复前面的偏差。比如质心偏离了目标，我没有任何办法直接控制质心把它拉回来——这就是欠驱动的问题。

> **易错点**：PD 控制到底是反馈还是前馈，取决于站在哪个尺度上看。单看关节力矩这一层：公式用的是"目标位置减当前位置"，是反馈；但看整个动作这一层：目标状态是从轨迹上按时间取下来的，跟角色当前的状态没有关系——从这个角度讲，它是开环的、前向的（feedforward）控制。

这就是前面埋的那个伏笔的答案：PD 控制所反馈的部分（关节力矩）和我们真正想控制的部分（整个动作）并不完全一致——反馈和前向，是在不同尺度之下得到的分类。

### 根节点上的"上帝之手"

前面说过，角色会摔倒、跟踪会失败，本质上是因为欠驱动：只用关节力矩去控制的时候，我们没办法控制一些全局的量，比如质心的位置、根关节的朝向。这在本质上是什么？本质是我们在施加关节力矩的时候，总是把其中一个力矩加在 child 的刚体上，再把一个反向的力矩加在 parent 的刚体上。所以总的来说，所有刚体所见到的力矩的总和其实是零。

> **结论**：全身力矩总和为零，意味着整体的质心、整体的朝向和位置这些全局量，靠内部关节力矩是无法改变的。

那如果想最直接地控制整体的朝向和位置呢？可以加一些额外的力，就是所谓的 **root force**——根关节的力或者力矩。做法跟普通关节一样：比如我想让角色运动过程中根节点始终满足某一个轨迹，同样从这个轨迹上拿出一个目标点，跟根节点当前的位置做一个 PD 控制，算出需要的力来施加。

但这个力跟普通关节力矩不同的地方在于：根节点是一个比较特殊的节点，它只有一个子关节，没有父关节。所以在它上面施加力的时候，相当于对整个角色加了一个额外的外力——而这个外力**没有施力者**：不知道是什么东西加的力，这个力在真实世界里是不存在的，只是在虚拟的世界里我们可以加。

它的效果是：会帮助根节点、帮助这个角色保持平衡，跟踪轨迹也能完成得比较好。但会带来额外的效果：因为这个力没有真正的施力者，它会让角色看起来好像是一个提线木偶。提线木偶本质上就是表演者通过一根一根线拽着木偶移动，你能很明显地看出线的存在。这里一样：我们确实帮角色保持了平衡、完成了动作，但通常人能很容易判断出来——"哎，这个动作看起来有点不自然，好像被什么拽着一样"。所以这个方法有个外号，叫 **hand of God**，上帝之手：一个虚拟的、不存在的"人"在某个地方施加一个力。

第一节课其实提到过：直接在根节点上用 PD 控制加力，对应的是所谓的 **physically plausible**——不是物理准确，而是物理可接受的一种动画。

我们之前看到的一些大量使用物理仿真的游戏，比如《Party Animals》，还有《Totally Accurate Battle Simulator》，效果都挺有意思。它们的主要仿真过程都是在 root 上多少做些控制，这样可以保证角色总体来说是可控的。当然你能明显感觉到，角色运动过程中好像被谁拽着腰、有人拽着它往前移动——本质上就是加了一个没有施力者的外力，这会带来物理感觉上的问题。

这种最简单的仿真还有一些其他的作用。最简单的比如 **ragdoll**（布娃娃）：让角色摔倒，让它在仿真的状态下摔倒。另外还可以把它跟普通的关键帧技术进行混合——这也是很老的一些工作，而且在很多游戏里已经很常见了。比如想做一个拳击里击倒的动作：角色被击倒的时候，切换到一个 ragdoll 仿真，跟踪一个摔倒的轨迹，生成物理合理的仿真动作；然后把这个仿真动作再跟一段关键帧——比如站起来，或者前面那些击打的动作——进行混合，用一个时间参数去控制它。这样产生的效果，既有物理仿真的反馈，又有可控的运动学动画。这是另一类混合仿真动画的效果。

### 不加外力，还能动吗

最后简单回顾一下。这一讲内容其实不算复杂：我们回顾了物理仿真、特别是刚体仿真里的一些基本公式和运动方程；讲了怎么对角色进行控制——通过 PD 控制（比例微分控制）计算相应的关节力矩，把力矩施加到角色的每个刚体上，产生动作。

要特别强调的一点：对一个人形，或者一般会动的、除了机械臂之外的这些角色，通常来讲都是一个欠驱动系统。对欠驱动系统，摆在我们面前的是两条路：一条是加这种没有施力者的 root force——它能帮角色跟踪动作、产生动作，缺点是效果会差一点，动作看起来不自然；另一条，是去研究该如何控制全身的力，让角色在不加额外外力的情况下保持平衡、做出动作。

这，就是接下来要研究的内容。

## 让角色摆脱"上帝之手"：PD 控制的稳定性与轨迹优化
> 对应块：BLK21 | 覆盖分集：P11上 | 块标题（分集名）：《Lecture10 Controlling Ch》

### 上一讲留下的尾巴

欢迎回到 GAMES105，这是第 11 次课。这一讲和上一讲连得非常紧：上一讲我们打好了 PD control 的基础，也留下一个悬而未决的问题——直接用 PD 控制去 track 一个 motion，很难做到物理准确，角色站不住、稳不住，只能在根节点上多加一些力，也就是所谓 "hand of god"（上帝之手）的虚拟力，靠它把角色的平衡撑住。这招管用，但会带来一些不好的效果。所以今天这节课的核心目标就一句话：**想办法把这个力去掉，让我们的角色生成完整的、物理真实的动作。**

围绕这个目标，今天主要讲两个比较简单的方法：一个是开环控制，也就是 feedforward（前馈）方面的一些内容；另外简单讲一些 feedback（反馈）控制——如何通过一些简单的策略，实现一个原地保持平衡的控制器。

```text
上一讲的困境
    PD 直接跟踪动捕数据 → 跟不上（稳态误差 + 相位延迟）
                       → 只好在根节点偷偷加虚拟力："hand of god"
                       → 这个力是非零外力 → 动作像提线木偶，不真实

本讲目标：把这个力去掉，生成物理真实的动作
    ├── 开环 / feedforward：找到一条"追得上"的目标轨迹
    └── 反馈 / feedback：用简单策略实现原地保持平衡的控制器
```

读图：上半段是上一讲遗留的问题链，下半段是今天预告的两条路线，本讲主体走前馈这条线。

### 先把 PD 控制捡回来

先把上一讲的 PD 控制捡回来。比如我想让肘关节转动到某一个角度：为了驱动角色运动，我们总是需要加一个关节力矩，这个力矩可以通过一个非常简单的线性公式来计算：

$$\tau = k_p \left(q^* - q\right) - k_d \dot{q}$$

第一部分是目标位置：比如要把肘关节转成 90 度，$q^*$ 就是这个目标角度；$q$ 是当前角度。两者之差就是偏差，偏差乘上比例系数，就得到需要加多少力矩。第二部分是阻尼项——如果只按偏差去算力，胳膊会不可避免地在目标位置附近震荡；为了让跟踪过程更平稳，我们根据当前速度来减少需要加的力的大小，震荡就被压住了。

PD 控制在控制领域里非常简单，也非常常用。不只是在角色动画里：想想一个很常见的问题——一边放水一边进水，怎么保持水位的高度？这就可以用 PD 控制来实现。工程领域里好多我们常见的机器人，甚至看起来复杂得多的机械，本质上最终还都是 PD 控制。

这里面还有一层值得咂摸的道理：我们想实现更复杂的控制，通常要求对对象——比如机器人——的整个动力系统、它跟环境交互的全过程足够了解，模型才能做得精确；但在不了解的情况下，我们不可避免地要做一些近似。如果把这个近似推到某种极限的程度，它其实就还原成了一个 PD 控制。所以说，PD 控制虽然简单，一方面很实用，另一方面它也确实是一个非常常用的控制策略。

### PD 控制的两个天生缺陷

当然，PD 控制本身还有一些很大的问题。上一讲我们用一个最简单的 toy model 介绍过最基本的那一条，这里把两个现象讲透。它们同根同源：**PD 控制的力，是由当前状态与目标状态之间的偏差乘上比例系数算出来的——必须要有这个偏差，才有这个力；没有偏差，就没有力。**

#### 稳态误差：有力就一定有偏差

还是那个胳膊的例子。小臂在竖直平面内绕肘关节转动，我想把小臂端平。但只要有重力，重力就会在重心上加一个力矩，让小臂往下垂；为了对抗这个力矩，我们必须加一个关节力矩，而且在平衡的时候，这个关节力矩至少要和重力的力矩相同，才能保持稳定状态。

麻烦就来了：用 PD 控制时，这里如果出现了大于零的力，那就说明误差一定大于零——比例公式就是这么定义的。所以，如果我们把目标位置设置在水平状态、去跟踪这个水平状态，小臂肯定不会水平：它必须垂下去一点，靠这点偏差"挣"出对抗重力的力矩。这是 PD 控制非常重要的一个特点。

> **结论**：稳态时 $k_p \cdot e = \tau_{\text{重力}}$，而重力力矩是恒定的，所以稳态误差 $e = \tau_{\text{重力}} / k_p$，与 $k_p$ 成反比。目标设在哪里，就永远差在哪里。

#### 相位延迟：永远慢半拍

另一个特点本质上跟第一个是同一个问题：总得先有偏差，才能算出力；有了力，才能驱动角色产生运动。拿一条正弦曲线作为控制目标，用 PD 控制去跟踪，你会发现仿真生成的曲线通常比输入曲线有一个延后：输入已经到了最高点，仿真曲线要过一段时间才到最高点——总会有这样一个相位偏差。

对一个简单的系统来说，这个相位偏差是多少是可以算出来的，那就属于控制论领域的技术知识了，有兴趣可以更深入地了解；这里我们定性地知道这回事就可以了。

### 把 kp 调大就万事大吉了吗

回到前面的问题。不管是稳态误差还是相位延迟，本质上都是因为我们要根据误差来计算力。那从另外一个角度讲：PD 控制前面那一项的系数 $k_p$，其实是一个所谓的刚性（stiffness），或者说增益（gain）。稳态时它要平衡重力，重力是恒定的；在力矩相同的情况下，误差和 $k_p$ 的乘积是一致的——所以它俩是反比关系。如果用一个 $k_p$ 很大的 PD 控制，稳态误差会小一点；跟踪轨迹时的相位偏差，在 $k_p$ 大的时候也会相对减小。

感觉好像把 $k_p$ 调大一点，什么问题都解决了？其实不是，有两笔账要还。

第一笔是观感账。上节课如果大家还有印象，我放过一段视频：用不同大小的 $k_p$ 去跟踪一个 T-pose。$k_p$ 很大的时候，角色动作会显得非常僵硬，整个人一直挺挺的，看起来就很不自然。

第二笔是仿真账。比较大的 $k_p$ 会带来仿真上的稳定性问题。这件事值得认真算一遍——下面我们就用一个最简单的弹簧振子，把"步长多大才算安全"这笔账算清楚。

### 从弹簧振子算清稳定性这笔账

#### 半隐式欧拉与矩阵迭代

用前面讲仿真时的例子：一个弹簧挂着物体，劲度系数 $k_p$；这次在弹簧旁边额外多加一个阻尼——除了弹性力，还按速度产生阻尼力。这样一来，这个系统本质上就是一个 PD 控制器：比例项加阻尼项，只不过比例项里的目标值设成了零（其实不是零也行，同样可以讨论，设成零只是简单一点）。物体受到的力就是

$$F = -k_p x_n - k_d v_n$$

在这样的力的影响下要计算物体的运动，就走仿真：把时间离散化，用欧拉积分一步一步算。这里用半隐式欧拉（也叫辛欧拉，symplectic Euler），它的特点是：**力用当前时刻的状态算，先更新速度；再用更新之后的速度去更新位置。**

$$v_{n+1} = v_n + h\, F(x_n, v_n), \qquad x_{n+1} = x_n + h\, v_{n+1}$$

这里的 $h$ 是时间步长——回想讲积分的时候，我们把时间均匀离散化，相邻两个时间点之间的距离就是步长，它是仿真里非常重要的一个量。为了式子简单，把质量取成 1（质量不是 1 也无所谓，同样的讨论），代入 PD 的力，得到

$$v_{n+1} = (1 - h k_d)\, v_n - h k_p\, x_n$$
$$x_{n+1} = h(1 - h k_d)\, v_n + (1 - h^2 k_p)\, x_n$$

把 $v_n$、$x_n$ 打包成一个状态向量，这两条式子就能拼成一个矩阵迭代：

$$\boldsymbol{s}_{n+1} = A\, \boldsymbol{s}_n, \qquad A = \begin{bmatrix} 1 - h k_d & -h k_p \\ h(1 - h k_d) & 1 - h^2 k_p \end{bmatrix}$$

对这个简单问题来说，$A$ 还是一个常数矩阵，不随时间变化。既然每一步都是乘同一个 $A$，就可以不断迭代展开：$s_{n+1} = A s_n$，$s_n = A^2 s_{n-1}$……如果 $s_1$ 是整个系统的初始状态，就有通项公式

$$\boldsymbol{s}_{n+1} = A^n \boldsymbol{s}_1$$

从固定的 $s_1$ 出发，每个时刻的状态都能直接算出来。于是问题变成：**$A$ 的 n 次方，随 n 增大到底是收敛还是发散？**

#### 特征值：发散还是收敛的裁判

$A$ 是个 2×2 方阵，这类矩阵的性质通常比较好。从简单起见，我们可以比较安全地假设它有两个特征值、两个特征向量（如果不符合，讨论会复杂一点，需要搬出若尔当标准型那一类代数知识，但实际结论上不会有太大区别）。特征值、特征向量是什么意思？看式子 $A v_1 = \lambda_1 v_1$：$A$ 作用在特征向量上，**不改变它的方向，只改变它的长度**，长度的缩放大小就由特征值给出。

两个特征向量可以很容易证明是不共线的，把它们拼成一个矩阵 $P$；回想代数知识，$A$ 就可以与一个对角阵相似，写成

$$A = P \Lambda P^{-1}, \qquad \Lambda = \begin{bmatrix} \lambda_1 & 0 \\ 0 & \lambda_2 \end{bmatrix}$$

$P$ 由 $v_1$、$v_2$ 组成，而 $A$ 是已知量，所以 $P$ 是固定的。把这个分解代回迭代式：

$$\boldsymbol{s}_{n+1} = P \Lambda P^{-1} \boldsymbol{s}_n$$

然后做一个变量代换：令 $z = P^{-1} s$。$P$ 固定，所以 $z_n = P^{-1} s_n$、$z_{n+1} = P^{-1} s_{n+1}$ 都能确定地写出来。在这套代换之下，迭代式变成

$$\boldsymbol{z}_{n+1} = \Lambda\, \boldsymbol{z}_n$$

对角阵乘向量，就是第一个分量乘 $\lambda_1$、第二个分量乘 $\lambda_2$，一步完成。通项公式也随之简化成 $z_{n+1} = \Lambda^n z_1$：对角阵的 n 次方，就是把对角线上的两个特征值各自取 n 次方；$z_1$ 也好求，$z_1 = P^{-1} s_1$。

现在裁判登场。$A$ 的两个特征值不一定是实数，可能是复数；但不管是实是虚，复数总有长度（模）：$|\lambda| = \sqrt{\operatorname{Re}(\lambda)^2 + \operatorname{Im}(\lambda)^2}$。而且一个复数取 n 次方，长度就是长度的 n 次方：$|\lambda^n| = |\lambda|^n$。于是能看到一件事情：只要任何一个特征值——$\lambda_1$ 或 $\lambda_2$ 都一样——的长度大于 1，随着我们从初始状态不断向后仿真、n 越来越大，$|\lambda|^n$ 就趋于无穷，$z_n$ 的长度也会变成无穷大；$P$ 是固定矩阵，$z$ 发散就意味着 $s$ 的长度也在发散。$s$ 本质上是速度和位置的线性组合，它越来越大、越来越远离中心，意味着什么？意味着系统不稳定——画面上就是那个物体左右震动、越震越大，最后飞到无穷远去，是一个非常不稳定的发散系统。

反过来，为了保证仿真系统稳定，我们需要 $A$ 的**所有**特征值的长度都小于等于 1；最理想是严格小于 1，因为等于 1 其实也不算稳定。

> **结论**：PD 控制 + 半隐式欧拉的系统稳不稳，就看迭代矩阵 $A$ 的全部特征值模长是否都小于 1。

#### 步长上限：一条曲线看明白

有了判据，就可以画一条非常直观的曲线。固定 $k_p = 500$、$k_d = 20$，横轴是时间步长 $h$，纵轴是 $A$ 的特征值模长的最大值。让步长从一个很小的值逐渐变大：一开始最大模长在 1 以下（看起来接近 1，但确实小于 1），然后单调上升；大概在 $h \approx 0.05$ 的位置碰到 1，再往后就很快超过 1，而且是单调上升、不会再下去。也就是说，在这组 $k_p$、$k_d$ 之下，**时间步长不能大于 0.05 左右**，再大系统就崩了。

把 $k_p$ 增大到 5000，这条 1 的门槛会向左挪：步长必须压到 0.02 左右以下才能保持稳定。类似的，把 $k_d$ 调大，门槛会向右偏移，能容忍更大的步长。所以结论很明确：$k_p$、$k_d$ 这两个值——特别是 $k_p$——虽然调大能让误差更小，但一方面会让动作更僵硬，另一方面会要求你用更小的时间步长去做仿真。

### kp/kd 怎么定，步长代价有多大

#### 参数基本靠手调

弹簧振子只是一个单变量、质量为 1 的小方块；真要控制人形角色，事情复杂得多——旋转本身是非线性的，关节多、自由度也高。这时首先要面对的就是：$k_p$、$k_d$ 这两个参数在很大程度上影响角色运动起来的感觉。回想上节课的例子：$k_p$ 大了很僵硬，$k_p$ 小了又跟踪不上、感觉非常无力。该怎么设置？这比较考验经验，实际上没有什么特别好的办法，基本靠手调——调到一个感觉比较舒服的状态，就可以一直用它。

好消息是范围不算苛刻：只要不差一个数量级，通常不会有非常大的偏差。比如我们常用的一种方案：因为 PD 算的是关节力矩，就给每个关节取 $k_p = 200$、$k_d = 20$。这是一种可行的方案，实际范围也可以更大一点，然后按情况微调：

| 场景 | kp / kd 怎么调 |
| :--- | :--- |
| 角色比较重 | $k_p$、$k_d$ 相应调大 |
| 快动作（跳高、后空翻） | 调大——不调大力量不够，你会发现跳不起来 |
| 很轻的肢体（手只有几百克，比如腕关节） | $k_p$ 调小 |

这些都是经验之谈：手工调整，调到一个觉得满意的范围就行。

#### 步长一小，计算就贵

另一件非常需要强调的事情：PD 的参数很容易把仿真推入不稳定区，就像刚才木块例子那样。木块那边其实还好——0.01 秒（100 Hz）一步也还能跑。但对人来说就不一样了：一个 50 kg 的角色，$k_p$、$k_d$ 取 200 和 20，在步长为百分之一秒时，很有可能非常不稳定；甚至调到千分之一秒都可能不稳定。这就是为什么很多早年的工作里，仿真步长写的是 1/1000 秒甚至 1/2000 秒——1 ms 或 0.5 ms 的量级，才能在这种控制下保住稳定性。$k_p$ 再调得更大，要求的步长还会更小。

步长小，代价是什么？每推一个时间步，都要做一次运动方程的求解，每一步的计算量基本固定，跟步长本身关系不大。这意味着步长越小，仿真一秒钟所需要的时间就越长。这对实时应用是个大问题：比如游戏，为了保证连续性，通常至少要 60 FPS——在这 1/60 秒里，我们要跑仿真、要做渲染（渲染是一个非常慢的过程）、还要做逻辑计算。特别是一些比较老的游戏，全靠 CPU 来算，里面的东西一多就已经非常慢了，仿真本身再占掉一大块预算，对实时应用来说就很不划算。

当然，看场合。如果做的是机器人控制设计，仿真步长确实应该放小一点：一方面让计算更精确，另一方面它没有实时性要求，相对来说也好做。但不管怎么样，对普通的 PD 控制来说，时间步长通常不能放得太大——稍微放大一点，系统就会崩。这个大家可以在下一个实验里试一试，会有相关的练习。

### Stable PD：把速度项藏进下一时刻

那这个问题有没有解？有，而且只需要对仿真器做一点小改动。

#### 为什么只隐式化速度

先回顾我们的半隐式欧拉：力用当前时刻的状态算，更新速度，再更新位置。前面讲仿真时说过，显式欧拉和半隐式欧拉在数值上都可能不稳定，而**隐式欧拉**是稳定的。什么是隐式欧拉？就是计算力的时候，不用当前时刻的状态，而是用**下一时刻**的状态。下一时刻是未知的，所以它本质上会变成一个方程，需要解这个方程才能获得下一时刻的状态。

麻烦在哪？如果把力里的 $x_n$ 换成 $x_{n+1}$：回想讲旋转积分的时候，如何从角速度变到旋转、变到四元数，这一步的计算通常是非线性的。非线性会让求解变慢，而且不能像线性系统那样一个矩阵求逆就把答案拿到——方程整个变成非线性的，求解会非常复杂。

所以有一个折中方案，比原始的 PD 稍微好一点：**只把 PD 控制里的一部分变成隐式的——把速度项隐式化**。位置的部分经常是非线性的、不好算；但速度项在大部分情况下是线性关系，原因很简单：速度是导数，一旦求了导，很多东西的非线性就变成线性了。做法就是：原来用当前时刻的速度，现在把这个速度换成下一时刻的速度：

$$F = k_p (x^* - x_n) - k_d\, v_{n+1}$$

这样系统方程从原来稍简单变得复杂了一点，但很容易解决：$v_{n+1}$ 就在这一行里，把它挪到等式一边、再除掉系数就行：

$$v_{n+1} = \frac{v_n + h\, k_p (x^* - x_n)}{1 + h k_d}, \qquad x_{n+1} = x_n + h\, v_{n+1}$$

#### 步长上限差了几十倍

把前面那个技巧再应用一遍——还是画那条「特征值模长 vs 步长」的曲线来对比。普通显式 PD 的曲线，大约在步长 0.01 的地方越过 1，宣告失败，步长必须小于 0.01；而新的这个用下一时刻 $v_{n+1}$ 算阻尼的版本，最大可用步长可以相当大，接近 1 这样的范围。两个门槛大概可以差几十倍。就这么一个简单的技巧，大大加强了 PD 控制仿真的稳定性——本质上它还是个 PD 控制，只是在仿真的实现上加了一点 trick。

工程上要提一句：这一步相当于干预了仿真器、物理引擎内部的运算，通用物理引擎不一定提供这样的功能，通常需要自己去实现。顺带说另一个方向：也可以利用仿真器自己的一些具体实现来达到类似的效果，比如采用所谓的 velocity motor（速度控制器），细节这里就不多计较了。总体上记住这一点就行：把速度变成隐式表达——用下一时刻的速度来算——可以很大程度上提高 PD 控制的稳定性。

这个方法在角色动画里经常被叫做 **stable PD control**，最早由一篇工作提出。但本质上就是我们刚才说的那件事：稳定性最关键的部分，就是用下一时刻的速度来计算阻尼项。

> **定义**：Stable PD control——把 PD 阻尼项里的当前速度 $v_n$ 换成下一时刻速度 $v_{n+1}$（速度项隐式化），以换取大得多的稳定步长上限。

效果立竿见影。不加这个隐式阻尼、只是 $k_p$ 比较大的时候，仿真非常不稳定，转着转着就飞掉了；换成 stable PD——也就是加上用 $v_{n+1}$ 计算的阻尼项——仿真会稳定很多，步长越大对比越明显。比如一个简单的两关节小角色：用 stable PD，1/60 秒的步长就能稳定；不用的话，可能需要 1/600 秒左右。具体数值要实际去测试。

| 对比项 | 显式 PD | Stable PD（速度项隐式） |
| :--- | :--- | :--- |
| 阻尼项用的速度 | 当前时刻 $v_n$ | 下一时刻 $v_{n+1}$ |
| 稳定步长上限 | 很小：人形角色常要 1 ms 甚至 0.5 ms | 大几十倍：两关节小角色 1/60 s 即可稳定 |
| 实现方式 | 按 PD 公式直接加力 | 需干预求解器内部，通常自己实现，或借引擎的 velocity motor |

所以回到前面的结论：用显式 PD，可能需要 1/1000 秒、1 ms 或者 0.5 ms 这样的时间步长；用 stable PD，要求就宽松多了。现在很多工作说自己可以在 120 Hz 下做仿真，那其实就意味着使用了 stable PD 这类做法。

### 直接跟踪动捕为什么不行

好，回到主线。我们只是简单地用 PD 去跟踪一个动作——把动捕数据作为 PD 控制器的目标轨迹直接去跟——通常是不 work 的，结果肯定不对。原因就是刚才说的两条：稳态误差，加上相位延迟。它们本质上都来自"力由误差算"这一件事，而延迟这件事一下脚就会出事：正常往前走路，需要身体和脚配合起来才不会摔倒；一旦身体和脚之间有了延迟，平衡就很容易失掉，动作也没法跟得很准。

之前为了让角色跟得准，我们在根节点上加了一个力。现在可以把这个力为什么讨人嫌讲清楚了。

### 提线木偶：根节点上说不通的外力

先回忆关节力矩平时是怎么加到角色身上的：我们通常在一个肢体（body）上加上力矩，同时在另一个 body 上加上一个反向的力矩——这样两个力矩总合为零，等价于把这个力矩理解为一根骨骼对另一根骨骼的作用、另一根骨骼给它的反作用。这是系统内部的事，没有外来的力对它做功。

```text
普通关节力矩：body A 加 τ，同时 body B 加 −τ
    → 两个力矩总和为零，等价于 A、B 之间的相互作用（内力）

根节点力矩：只有根节点自己的 body 加了 τ
    → 找不到反作用的对象，对整个系统是一个非零外力
    → 效果如同提线木偶：有人揪着腰带，角色才不摔倒
```

读图：力矩成对出现是"内力"；单方面落在根节点上，就变成了"外力"——这正是动作变味的根源。

而根关节的力矩不是这样：它只在一个地方——根节点的 body 上加了力矩，这个力矩没有反作用对象。前面为什么特意要在另一个 body 上补一个反向力矩？就是因为我们把那个力矩当作骨骼之间的相互作用；根节点这里没人跟它配对，所以它就是一个非零的**外力**。

这个外力会带来非常特殊的效果：像提线木偶一样。相当于有人撑着这个人的腰带，让他不会摔倒，但整个动作看起来奇奇怪怪。道理很简单：大家习惯了真实世界里的人——真实世界里没有人会揪着你的腰带往前走，所以看起来就很不自然。

### 要找的是一条追得上的轨迹

所以真正的问题变成：如何找到这么一条控制轨迹，让我们不需要根节点来帮忙。

这条轨迹的本质，回到手臂那个例子就明白了：为了让胳膊端平，如果目标状态正好设在端平的位置，PD 控制肯定不能让胳膊端平——它总要有偏差。那就把目标位置设得比端平稍微靠上一点，这点误差产生的力正好让胳膊保持平衡。设计动作轨迹也是同样的思路：我们想让角色去滚动、去走路、去做后滚翻——这些动作我们有一份动捕记录——但不能直接去跟踪这份记录，而要在它之上找一条轨迹，去跟踪那条轨迹，才能通过仿真生成想要的动作。

```text
动捕记录
    │  直接跟踪 → 跟不上（稳态误差 + 相位延迟）
    ▼
在动捕记录之上找一条"追得上"的轨迹，作为 PD 的目标
    │  就像端平手臂：目标设得偏上一点，让偏差顶住重力
    ▼
PD 控制器跟踪这条轨迹 → 仿真生成动作，全程无需外力
```

读图：目标轨迹不再等于动捕数据，而是动捕数据之上"为了能被追上"重新找出来的一条轨迹。

怎么找这条轨迹？方法有很多。之前提到过有个公司 NaturalMotion，做了一个软件，可以手工设计这样的轨迹——手工设计是一种方式，但会非常困难。我们通常还是希望让计算机做些事情，让它自己去找到这样一套轨迹。其中一种方法就是**轨迹优化**（trajectory optimization），有时我们也叫它别的名字，比如 spacetime constraints，或者 spacetime optimization——时空优化。名字不同，本质做的都是同一件事。

> **定义**：轨迹优化——把"找到一条能被 PD 控制追上的目标轨迹"这件事本身，写成一个带约束的优化问题去求解。

### 把找轨迹写成优化问题

用一句比较通用的话来描述：我们的目标是优化一条仿真的轨迹。时间离散化之后，"轨迹"其实就是每一个时刻角色的状态——角色的位置、速度、朝向、角速度等等；同时，我们也去优化一条**控制轨迹**，它可以就是 PD 控制器的目标轨迹（target trajectory）。有了目标轨迹，就可以用 PD 控制计算每一时刻的关节力矩，把这个力矩施加到角色上，它就会动起来。

```text
目标轨迹（控制轨迹，待优化的变量）
    → PD 控制器逐时刻算出关节力矩 τ
    → 施加到角色上，仿真向前推进一步
    → 得到仿真轨迹（每个时刻的状态：位置、速度、朝向、角速度……）
    → 目标函数打分 + 运动方程等约束把关
    → 优化器回头调整目标轨迹，循环往复
```

读图：优化器直接摆弄的变量是"目标轨迹"和"仿真轨迹"，两者被运动方程拴在一起。

整个过程中，我们要优化的目标函数可以泛化地写成两部分：

$$J = \Phi(s_N) + \sum_{n} L(s_n, \tau_n)$$

一部分是轨迹结束时那个状态的代价；另一部分是每一时刻按"加了多少力、当时状态如何"算出的代价。同时，优化过程中还需要满足一些约束。最主要的约束就是**运动方程**（equations of motion）：角色的运动是"当前状态，加上这一时刻施加的力，通过仿真得到下一步的状态"——所以两个状态和这个力之间有一个非常固定的关系，这个关系就是运动方程。除此之外可能还有一些其他约束：比如关节约束；再比如要求角色不能走到悬崖边上，不然会掉下去——这其实是一个对位置的约束。把所有这些放在一起，就构成了一个优化问题；求解它，就得到我们需要的运动轨迹。

这个方向有一篇比较早的、奠基性的工作——1988 年发在 SIGGRAPH 上，做的就是皮克斯那盏小台灯：想优化一个"台灯跳起来到那里"的动作。这里的状态就是台灯每个关节的位置、每个关节的朝向角度，加上基座的位置，以及它们的速度；还有一些力，直接加在每个关节上让它动起来。通过不断优化这些位置和施加的力，最终生成那段动画。

### 一个能算到底的小例子

再拿一个更具体的小例子——还是上节课用过的那个：一根杆上穿着一个物体，我可以在物体上加力，让这个刚体抵抗重力，并且跟着目标高度移动。这个力 f 是 PD 控制的：目标位置减掉当前位置，乘 $k_p$，再减去速度乘 $k_d$：

$$f = k_p (x^* - x) - k_d v$$

接下来的目标是：计算一条 PD 控制的目标轨迹 $x^*$，使得在这个控制下，仿真结果 $x$ 是一个 sin 函数。这就可以写成一个非常直观的优化问题。

目标函数：我需要 $x_n$ 的轨迹是 sin 函数，那就让三角函数在 $t_n$ 时刻的值，跟 $x_n$ 在这个时刻的值相同；"相同"写成最小二乘的形式，就是差的平方：

$$\min \sum_{n} \left(\sin(t_n) - x_n\right)^2$$

约束：$x_n$ 和 $v_n$ 要满足运动方程。对这个例子来说运动方程非常简单，就是前面写的那两条半隐式积分更新式——力的公式是已知的，每一步怎么更新是完全确定的，这两条式子本身就是约束。

通常来讲，除了这两条运动方程，我们还会加一些额外的约束。因为如果约束不够，状态有很大的自由——它可以选择取很大的值或者很小的值，$s$ 可能跑得非常大。所以可以额外加一些约束项，比如**正则项**：要求优化的量必须比较接近于零，这样整个输出的轨迹会比较平滑、比较正常。

### 硬约束与软约束

这里出现了一个值得区分的概念。刚才的约束写成"约束区"里的等式形式，我们把它叫做**硬约束**：不管用哪个求解器，它都一定会尽可能满足这个约束——因为约束是必须满足的。但这会带来一些问题：问题可能变得比较难解；从数值上讲，问题可能变得不太稳定，条件数会变差，诸如此类。

所以有些时候，我们会把硬约束变成**软约束**。本质上是把它从约束区挪进目标函数：原来要求左边右边必须相等；软约束的说法是，这两个东西尽可能相等——也就是它们的差尽可能小——但允许一定程度上不等于零。写成惩罚项，前面配一个权重 $w$：$w$ 代表软约束"软的程度"，$w$ 很大，就表示要求这条约束尽可能一定要满足，相当于更"硬"一些。调节这个权重，就能平衡"约束满足的程度"和"目标函数最优的程度"。通常来讲，软约束形式的优化问题求解起来更简单一些。两种形式可以互相转化。

### 变量太多怎么办：配点法

还有一些相关技巧，处理的是参数量的问题。我们的优化目标实际上是离散化轨迹上每一个时刻的状态：仿真步长取千分之一秒，仿真一秒钟就是 1000 个状态；每个状态带位置、速度，再加上目标轨迹自己的变量，零零总总就是 6000 个参数这个量级。参数量这么大，给优化带来很大困难。

有一类方法叫 **collocation methods**（配点法）——名字听着有点怪，但想法非常简单：6000 个参数太多、优化问题太大，那就做点简化。我们认为 $x$、$v$ 和目标轨迹都满足某些预先定义好的参数曲线——比如都来自某条三次样条曲线（cubic spline），或者来自某个多项式函数。这样一来，优化 6000 个参数就简化成优化这些曲线的参数，而曲线的参数肯定比完整的参数少很多，优化问题就变得简单了。说白了，就是通过近似的方法减少优化变量，是一种技巧。

### 怎么解：从 QP 到梯度下降

但不管用哪一种方法，最终还是需要去优化这样一个函数。优化的方法很多，常用的一类是**基于梯度的方法**（gradient based approach）：比如大家比较熟悉的梯度下降；还有牛顿法，以及牛顿法里最常用的那一支 L-BFGS——那个词的全称我一时想不起来了，总之这一类方法都很常用。

对我们上面这个简单的问题，其实还能看出更好的性质：目标函数是二次函数，约束是线性等式约束，所以它是一个非常简单的 QP 问题——二次规划问题。这种问题有唯一解，很容易直接算出来。就算不直接解，用前面提到的梯度下降这类方法去迭代，也一样能逼近答案。

到这里，摆脱"上帝之手"的第一步就走通了：不再把动捕数据直接塞给 PD 控制器，而是让优化替我们算出一条追得上的目标轨迹，再交给 PD 去追——角色就能在没有外力的情况下，靠自己的关节力矩把动作做出来。至于今天计划的另一半——怎么用简单的反馈策略让角色原地保持平衡——接着往下看。

## 角色控制：从轨迹优化到静态平衡
> 对应块：BLK22 | 覆盖分集：P11下 | 块标题（分集名）：《Lecture10 Controlling Ch》

### 从 IK 说起：会解优化，不等于会控制

讲 IK 的时候我们已经碰过这个问题：IK 本身可以转化成一个优化问题，而这类优化问题可以用各种迭代的下降方式去解——gradient descent 也好，CCD 也好（CCD 严格说不是梯度法，但它同样是一个迭代的下降方法），还有牛顿法、Levenberg-Marquardt（LM）法等等。对简单的例子来说，这些方法可以比较容易地找到根、找到解，而且这个解还是唯一的，效果比较好。

可一旦对象换成一个人、一个完整的复杂角色，比如我想让这个角色跑步，情况就不同了。回到我们前面的例子：如果直接用 PD 控制去跟踪一段动捕轨迹，它是跑不起来的。所以我们通常的做法是：把动捕数据作为优化的初始解，再用优化的方式去找一条合理的控制轨迹，让角色真正跑起来。

这个目标函数写起来倒不难，核心就是衡量当前仿真状态和目标轨迹之间的偏差。偏差可以用好多种方式来定义：

- 算两个 pose 之间关节角度的偏差；
- 算每个关节的全局绝对位置之间的偏差；
- 算每个关节的速度；
- 算角色质心的相对关系。

这些都可以拿来当轨迹优化的目标。

### 梯度为什么靠不住

目标函数定义好了，按理说接下来就该上优化方法了。但对一个全身的复杂角色，你会发现两个大麻烦。

第一个麻烦出在优化目标本身。我们优化的最终变量是姿态，也就是关节的旋转——关节旋转天生就是一个非线性的东西；再加上角色自由度高、身上的关节多、参数非常多，这个目标函数的"曲线"到这时候就应该是一个高维曲面了。把它画出来，你会看到它高度非线性，甚至曲面本身都在不停地震荡，有无穷多个局部最优解。这种情况下你想去计算它的 gradient，通常来讲梯度的质量是很差的：它总是指向某一个局部最优解，而局部最优解又特别多，所以梯度指向的方向很有可能是不太对的。

第二个麻烦更根本：很多时候我们的仿真是一个黑盒子。前面优化公式里有一项是整个系统的系统函数，也就是 system dynamics——对知道的系统它写在那儿就行，可对一般系统，比如一个机器人它该怎么动，我们很多时候是无法准确建模的。最基本的问题就是碰撞该怎么建模：比如一个球掉在地上，它该弹多高？现有的碰撞模型很多都是非常非常粗略的近似。再比如，人的手是软的，用软软的手去捏一支笔，非常容易，软接触会带来非常稳定的接触点；可如果仿真里角色的手是硬的，你可以想象用筷子去夹一支笔，会非常难——这跟真实的人捏笔的过程完全不是一回事。整个运动过程我们很难准确建模；模型都不知道，梯度就更没法算了。

这正是基于梯度方法（gradient-based）的局限性：它必须要一个梯度，而很多时候梯度是算不出来的。不光是角色动画，控制领域里凡是需要做轨迹优化的，都会碰到这么一个非常差的 landscape——优化函数长成这样，基于梯度的方法就没辙了。

### 不要梯度的优化长什么样

gradient-free 的思路，就是去找一些不需要 gradient 的 derivative-free optimization methods。这类方法通常是一些启发式的方法、基于随机的方法，或者基于采样的方法：它们通过若干个样本点的信息，来更新我对最优解的估计。

好处很明显：不需要梯度。坏处也摆在那里：正因为不用梯度、只能靠估计，一方面慢——估计的过程总是比直接用函数算要慢；另一方面也不是很精确。总是各有优缺点。

| 对比 | 基于梯度的方法 | 无梯度方法（derivative-free） |
| :--- | :--- | :--- |
| 前提 | 必须能算出梯度 | 只需要能算目标函数值 |
| 速度与精度 | 快，精确 | 慢（靠估计），不够精确 |
| 遇到黑盒系统 | 模型未知就没法算梯度，用不了 | 可以直接用 |

这类方法大体上都遵循同一个流程：目标是找到一个变量 x，让某个目标函数最小化。首先用某种方式给出一个初步的估计——比如对跟踪任务来说，想让角色跟踪一段动捕数据，那动捕数据本身就可以作为这个初始估计。接下来是一个迭代过程：根据当前估计生成一批样本点；对每个样本点计算目标函数的值；再根据这些函数值更新对 x 的估计。注意这只是一个框架，具体到不同方法，细节上的区别会比较大。

```text
   初始估计 x（比如动捕数据）
        │
        ▼
 ┌─► 按当前估计生成一批样本点
 │        │
 │        ▼
 │   逐个样本计算目标函数值
 │        │
 │        ▼
 │   根据函数值更新 x 的估计
 │        │
 └────────┘  循环迭代，直到收敛
```

读图：无梯度方法的共同骨架就是"估计—采样—求值—更新"这一圈，反复转。

相关的方法有很多：贝叶斯优化；遗传算法，也就是进化算法；机器学习里非常常用的随机梯度下降，其实本质上也是这一类方法；还有一些基于采样的方法等等。这里我们只介绍两种、也算效果比较好的方法：CMA-ES 和 SAMCON。

### CMA-ES：把撒点采样变成调一个高斯

CMA-ES，全称 Covariance Matrix Adaptation Evolution Strategy（协方差矩阵自适应进化策略），本质上还是一个进化算法——还是我们刚才说的那套：撒一些点，根据这些点来更新我对最优解的估计。它特殊的地方在于，把撒点、估计这个过程，转化成了维护一个高斯分布的估计：假设每次要采的样本点，总是从一个高维的高斯分布（高斯就是正态分布）里采出来。

整个流程是这样：

1. 首先初始化一个高斯分布，可能就是一个圆形的分布；
2. 从分布里采样，比如撒 100 个点；
3. 对每个点计算目标函数的值。这里再强调一下目标函数是什么：它在每个状态下的函数值是求和，所以对它求值，本质上相当于做了一次仿真——仿真生成一条比如几秒钟的轨迹，再在这条轨迹上算函数值。比如我要求这条轨迹跟某个参考动作相近，或者要求踢球时你的脚必须碰到球，这些都可以写成目标函数；
4. 对这些函数值做排序。因为目标是最小化 f，所以从最小的往上找，保留 n 个——比如撒了 100 个点，可能只从里面拿 20 个作为更新的点。这个 n 是一个可以算出来的参数；
5. 用这批点更新高斯分布的均值 μ 和方差 σ；
6. 下一步，从更新之后的高斯分布里继续采样。

整个过程在心里过一遍画面：一开始是一个圆形的初始化高斯分布；迭代中你会发现有些点的函数值相对比较小，分布就会逐渐向函数值小的那个方向移动；而在移动的过程中，开始时方差会逐渐增大——这代表我们正在向外探索函数值更小的方向；当方向逐渐集中之后，方差又会逐渐变小，最后收敛到最优解附近。这是 CMA-ES 很有特点的一个行为。

它的好处：首先，这是一个比较稳定的方法，对一些很复杂的函数，实际效果也蛮好；另外，它确实是 derivative-free 的，不是基于梯度的，所以哪怕是非常复杂的系统、或者黑盒子系统，我们也可以直接把它应用起来。

### CMA-ES 的两个应用和一个代价

CMA-ES 这类方法在角色控制上有一些很漂亮的应用。

一个 2009 年的工作做的事情是这样的：人走路总是左脚着地、右脚着地，那我给出一些预测的落地点位置，然后用轨迹优化去找一个能满足每次落地点的走路形态。效果蛮好：我开始随便给"左右左右"这样一串位置，它可以根据这些位置生成一段走路；给的位置的距离、速度不同，走路的姿态也会不同；甚至如果角色的关节数量跟真人不一样——不像真人——这种方法也能找到一个比较合理的走路过程。

另外还有一些工作，出发点是：刚才那种方法是同时去优化仿真的轨迹以及控制变量。但我们知道，用 PD 控制时，真正需要控制的量其实就是目标轨迹——目标轨迹给定之后，剩下的部分仿真直接就可以得到。所以完全可以反过来：只去优化 PD 的目标轨迹，不去优化仿真轨迹，仿真轨迹让仿真自己去产生。这种方法同样可以得到控制：给一些非常简单的目标，比如"脚尽可能抬高，同时身体有一个旋转"，它就可能生成类似街舞一样的动作。这其实就是 CMA-ES 加上仿真控制、再加上轨迹优化能够实现的效果。

当然，CMA-ES 有一个绕不开的代价：每给出一个样本参数，我们都需要从头到尾做一遍仿真，然后才能去更新参数，整个过程比较漫长。而且另一方面，如果仿真的轨迹比较长，目标函数实际上会带来更多的局部最优解，让优化变得更难收敛。

### SAMCON：每一步只优化一帧

针对这个代价，还有一类方法——SAMCON，这是大约十年前提出的一类方法。它要解决的问题跟前面一样：我们有一段动捕数据，需要找到一条目标轨迹，跟踪这个目标轨迹、还原那段动捕——优化问题本质上跟 CMA-ES 那个是相同的。不同的点在于：每次做采样，我们只考虑下一帧，每次只优化一步，通过这一步来决定后面该怎么更新轨迹的值。

它本质上是一个 sequential Monte Carlo（序列蒙特卡罗）方法。这类方法的特点是：从一些初始状态开始，采若干个样本点，向前仿真；仿真完之后，像 CMA-ES 一样，只从仿真结果里拿出一小部分样本点作为新的出发点，再去采更多的样本，依次类推，直到把整条轨迹走完。

具体到我们的例子。假设这是一段需要跟踪的轨迹，也许是动画师建的一段动作，也许是一些其他的控制；初始状态比如是站立——人往前走，肯定是从站着的状态开始的。我们知道，如果直接用 PD 控制去跟踪这条轨迹，那肯定是偏的，偏差会比较大。为了能够跟踪得比较准，我们需要在轨迹上加一个偏移，然后去跟踪"加了偏移之后的轨迹"——这样就会有一部分状态跟参考轨迹比较接近了。这是基本的优化目标。

优化过程还是把轨迹分割开，每次只优化一小段。在这一小段里：

- 偏移是我们不知道的，所以根据一个高斯分布对偏移进行采样——也不一定是高斯分布，用均匀分布之类的也是可以的；
- 比如采 1000 个样本，每个样本都对应原动作轨迹的一个偏移；
- 对每一个偏移做一次仿真，每个片段仿真之后会生成一个新状态——有一些离参考轨迹比较近，有一些比较远；
- 只保留那些离轨迹比较近的状态。当然不会只保留一个：只保留一个的话，它可能是一个局部最优解，而这个局部最优解可能在后面的仿真过程中变成一个非常差的解。所以我们多保存一些，比如 1000 个里保留 100 个，作为下一阶段的起始状态；
- 接下来从保留的这些起始状态出发，随机地再产生比如 1000 个样本，进一步仿真，同样只留下离轨迹近的、扔掉远的；
- 这样不断进行下去，最终会得到一组轨迹，其中相当一部分离目标轨迹比较近；把其中最接近的那条找出来，就是最终的解。

```text
  参考轨迹（动捕 / 动画师给定）
        │
        ▼
  初始状态（比如站立）──► 按高斯/均匀分布采样 1000 份偏移
        │
        ▼
  每份偏移仿真一小段 ──► 得到 1000 个候选状态
        │
        ▼
  只保留离参考轨迹最近的约 100 个，其余淘汰
        │
        ▼
  以保留状态为起点，继续采样、仿真、筛选，逐帧推进
        │
        ▼
  走完整条轨迹后，选出最贴近参考轨迹的那一条
```

读图：SAMCON 每轮"采样—仿真—筛选"只把轨迹推进一小段，多路候选并行走完全程。

这个过程本质上是什么？虽然每一步只考虑一步，是一个非常 local 的问题、非常容易陷入局部最优，但因为我们保留了多个状态，每一个局部最优解都会被延迟到后面若干步之后，再去判断它是不是真的最优解。通过这种方式，每一步的判断就不再局限于当前这个局部，整个优化过程也会更加有效率。

这种方法的结果：首先，任何一个动作，只要我们有它的动捕数据，基本上就肯定可以找到一条控制轨迹把它还原出来。而且在这个过程中，我们还可以把环境做一些变化，或者把角色本身做一些变化——还记得 retargeting 吗？把一个动作重定向到另外一个角色的时候，不可避免会出现穿模、角色跟环境发生碰撞接触这些问题，这些问题都可以在优化的过程中处理掉；地上有一些鹅卵石、或者是冰面，角色也会自动受环境影响，产生动作的变化。这些都是这类方法能得到的效果。

### 前馈不够，反馈来补

到这里得到的控制，本质上是一种 feedforward control——前馈控制，或者叫开环控制。什么意思呢？我们前面得到的其实是一条控制轨迹，播放的时候用 PD 控制去跟踪这条轨迹，得到仿真轨迹——这就是它的全部。

但它有一个很大的问题：这个跟踪过程要求，我的起始状态、以及仿真过程中的每一个状态，都必须处在我获取这条轨迹时能够得到的状态范围之内。这话什么意思？比如一开始的时候，我对角色加一些扰动，推它一把——如果继续跟踪原来这条轨迹，你会发现角色很快就会摔倒，状态偏离得越来越远，没有任何机制把它拉回来。这是前馈控制一个很大的问题。

所以为了能够解决这个问题，我们需要引入反馈控制（feedback control）。反馈控制做的是：每一时刻有一个反馈策略，它根据当前状态和参考状态之间的偏差，自动计算出一个更正量，加到原来的轨迹上；然后我再用 PD 控制去跟踪这条更正后的轨迹。这样，状态就不会越跑越远——我并不指望它完全精确地回到目标轨迹上，它总是在轨迹附近，但每一步都有反馈策略往上加，就可以保证整个仿真过程中，它都贴着目标轨迹附近走，不会离得很远。

跟踪控制加上反馈之后，角色就可以推了：推它，动作会受到相当的影响，但最终角色还是可以保持平衡的。

```text
   参考轨迹 s0 ───►(+)───► PD 控制 ───► 物理仿真 ───► 实际状态 s1
                ▲                                       │
                │                                       │
                └──── 更正量 = f(s1 − s0) ◄─────────────┘
                     （反馈策略每一时刻实时计算）
```

读图：反馈控制在目标轨迹与实际状态之间加了一条实时修正回路，偏差多大，更正就跟着变。

> **提示**：前馈负责"怎么走"，反馈负责"走歪了怎么拉回来"，两者是配合关系，不是二选一。

| | 前馈控制（开环） | 反馈控制（闭环） |
| :--- | :--- | :--- |
| 控制量怎么来 | 离线优化得到一条固定的控制轨迹 | 每一时刻根据当前状态与目标实时计算 |
| 扰动来了会怎样 | 状态偏离后无人纠正，很快摔倒 | 自动更正，始终保持在目标轨迹附近 |

### 什么是平衡：质心投影与支撑面

反馈控制这一节只讲一个非常简单的例子：静态平衡（static balance）。

先看动机。上节课举过这个例子：让 PD 控制去跟踪一个单一的姿势，比如一个 T-pose。这个 pose 本身没有任何平衡控制。它其实会比 ragdoll 好一点——ragdoll 是完全没有控制的，这个人就直接瘫在一起了——但如果只是跟踪一个单一姿势，你会发现角色虽然能撑住自己、保持这个姿势，但会逐渐地摔倒。缺的就是一个反馈控制，能在它将要摔倒的时候把它更正回来。

那我们的目标是什么呢？所谓 static balance，说的是：在不发生移动的情况下——比如原地站着——通过一些非常简单的控制策略，让角色左右稍微摇晃一晃，或者推它一下、让它发生这些扰动，它不会摔倒；甚至可以让它做一些原地下蹲、原地晃晃肩之类的动作，也能保证不摔。这是一个非常基础的控制，在这个之上我们可以做很 fancy 的效果。

这里最基本的问题来了：什么是平衡？或者说，什么是静态平衡？

想象一个圆柱体的墩子放在地上。它非常稳定，我们一般推是推不倒它的，甚至把它稍微推翘起来一点，它也会在自重的作用下回到原来的状态。为什么它能平衡？首先，这个物体有一个质心（重心），重心在地面上有一个投影；整个圆柱体的底面是一个圆，这个圆我们可以把它叫作 support polygon——支撑面。你会发现，重心在地面上的投影，落在这个支撑面的内部、靠中心的位置。

> **结论**：物体处于准静态（基本不动、没有速度）时，只要质心在地面上的投影落在支撑面之内，这个物体就是稳定的——哪怕翘起来一点，也会被拉回来，落回中间。

对人也一样。人的质心怎么算？这个概念其实一直没讲，但它很简单：每一个刚体的重心，是它内部每个小质点的质量乘以位置、再除以总质量；对人来说，就是每一个肢体（刚体）的质量乘以它的位置，加起来除以整个人的质量——相当于用质量对位置做加权平均，得到的位置就是重心。

$$c = \frac{\sum_i m_i x_i}{M}, \qquad M = \sum_i m_i$$

其中 $m_i$、$x_i$ 分别是第 $i$ 个肢体的质量和位置，$M$ 是全身总质量。

人站在那里，质心在地面上同样有一个投影。比如我两只脚很平稳地站在地上，两个脚之间就构成了一个平面上的多边形——把两个脚面连起来的凸包，就是所谓的支撑平面（support polygon）。保持平衡时，我只需要保证质心的投影始终在这个支撑平面内部，角色就不会摔，就没有处于"正在摔倒"的状态。

单腿站立为什么难？主要原因就是单腿站立的时候，你的 support polygon 只有一只脚那么大，要让质心始终保持在支撑面之上，比双脚站立要难很多——双脚站立时，两脚中间的凸包比一只脚大很多，控制起来容易得多。

```text
        俯视：双脚站立时的支撑面
      ┌──────────────────────┐
      │   ▭ 左脚              │
      │                      │
      │         ●            │
      │                      │
      │      ▭ 右脚           │
      └──────────────────────┘
      ● = 质心投影；外框 = 两脚脚面围成的凸包
```

读图：支撑面就是两脚脚面的凸包，平衡控制要做的就是把这个质心投影摁在这块面里。

### 最简单的静态平衡：PD 控质心

实现静态平衡要做两件事。第一，跟踪一个本身比较稳定的自然站立姿势——比如立正一样，两脚水平地站在地面上。这样的姿态我们感觉一下就知道它是平衡的；如果是单腿站立的姿势，感觉就是不平衡的，那就很难实现静态平衡。第二，实时调整身体的控制，使得质心在水平面上的投影，始终处于支撑面（support polygon）的中间。做到这两条，我们其实就可以保持平衡了。

不知道该怎么办的时候，最简单的方法就是拿 PD 控制来干这件事情。思路是：角色本身要保持这个姿势，PD 控制跟踪姿势，已经有一套力矩了；在这套力矩之上，再在一些关节上加上额外的力矩，这个额外力矩的目标，是保证质心始终跟目标质心位置比较接近。

目标质心位置通常来讲可以取支撑面的中心；再简单一点，直接取两个脚中心连线的中点——这是一种近似。PD 的写法是：

$$\tau_{bal} = K_p\,(c_{target} - c) - K_d\,\dot c$$

其中 $c$ 是当前质心在水平面上的投影位置，$c_{target}$ 是目标质心位置（支撑面中心），$\dot c$ 是质心的速度——也就是每个肢体（body）的速度用质量加权平均。这样算出来的东西，我们把它当作一个力矩加到关节上。

这里有两个重要的参数 Kp 和 Kd——就是 PD 控制的参数。这两个参数通常来讲只能通过手调，多手工尝试几个值就可以得到比较好的效果，因为这种控制相对简单。

那这个力矩该加在哪里？常用的思路是加在踝关节上，也就是脚后跟那儿；或者加在髋关节（hip）上，也是一种思路。其实你们可以自己感受一下：站在平面上保持平衡，让身体稍微向后倾斜一下，体会一下到底是哪里在用力——基本上是脚踝，或者是大腿根的髋关节在用力。所以实现上也是这个思路：两种加一个就可以，不需要两个都加。另外，左右两个 hip、或者两个 ankle，完全可以采用不同的参数，这没有问题，当然实际上区别可能不是很大。

通过这种方式，我们就可以很简单地实现一个 static balance。

### 雅可比转置控制：把一个力等效到关节上

这里我们再多介绍一个控制策略：雅可比转置（Jacobian transpose）。这个名字应该很熟悉——我们讲 IK 的时候有一个方法就叫 Jacobian transpose。实际上，这两个东西有非常大的联系。

看这样一个例子：这个人站在这里，我在他的手上加了一个力 F。当然，这个力我没有真的加——我只是说，如果要在这里加一个力的话，这个力会让他的胳膊向上移动。这个向上移动的过程，可以反过来等价地实现：给每个关节加力矩，让它旋转，产生一个向上移动的动作。接下来的问题就是：我加一组合适的关节力矩，让它产生的动作，刚好跟我在手指上加一个力产生的动作相同——这时候得到的这组力矩 τ，就是 Jacobian transpose control 要计算的东西。

> **定义**：Jacobian transpose control 的目标，是计算出一套关节力矩，让它能够等价地实现某个力 F 加在肢体某一点上的效果。这个力并没有真的加到肢体上，所以通常叫 virtual force，虚力——它只是我们想要实现它的效果。

"效果相同"该怎么定义？我们通常用做功来进行衡量。更进一步，其实我们更考虑一个瞬时的状态，所以实际要求的是：真实的关节力矩做功的功率，跟目标要实现的这个力做功的功率，应该是相同的。功率是力乘以速度：

$$P = F^T \dot x, \qquad P = \tau^T \dot q$$

力 F 加在一个点上，这个点有全局坐标的位置。我们知道，它是每个关节转角的函数——这就是前向运动学，记作 $x = g(q)$，它是一个非线性函数。有了这个函数，x 的导数——也就是这个点的速度——应该是每个关节旋转的速度乘上一个雅可比矩阵：

$$\dot x = J(q)\,\dot q, \qquad J = \frac{\partial g}{\partial q}$$

有了这个关系，把 $\dot x = J\dot q$ 代入上面的功率等式，得到 $F^T J \dot q = \tau^T \dot q$。注意，这个等式要求对任意一个 $\dot q$ 都成立，那其实就要求：

$$\tau^T = F^T J \;\;\Longrightarrow\;\; \tau = J^T F$$

这就是 Jacobian transpose control 本质上做的事情：我想让这些关节力矩，实现跟把力 F 加在 x 上得到同样的效果，那就需要计算加力点 x 的前向运动学函数的雅可比矩阵，转置一下、乘上 F。

回去回忆一下，这个东西本质上来说就是 IK 问题。IK 的时候我们其实做了同样的事情：对前向运动学这个函数求导，得到雅可比矩阵；而雅可比矩阵本质上就是 gradient，我们可以根据梯度做各种事情，比如梯度下降，或者 Jacobian transpose 这类方法。雅可比矩阵有很多种不同的计算方式，比如对 hinge joint 或者 ball joint 来说，可以通过叉乘的方式计算出雅可比矩阵里的每一列——回忆一下讲 IK 那一节的内容。

$\tau = J^T F$ 还可以再往下推一步。力矩 τ 本质上是沿着某一个轴的旋转，可以认为是沿着三个不同旋转轴的一个叠加；从叉乘这个关系做一些推导——推导这里就不再仔细做了——可以得出一个结论：**每一个关节的关节力矩，可以直接用"从关节到加力点"的向量叉乘 F 得到**：

$$\tau_i = (x - p_i) \times F$$

其中 $p_i$ 是关节的位置，$x$ 是加力点的位置。

> **易错点**：叉乘的顺序和向量的指向决定力矩的方向。从 root 向下算和从下往上算，加出来的力矩方向可能是不一样的，实现时要特别注意统一约定。

### 用虚力推质心：下蹲、转身，以及这套控制的边界

有了雅可比转置，回到静态平衡。前面那种"直接算一个力矩、加到 hip 上"的方式，只能做非常简单的平衡控制。除此之外，我们可以换一种方式——通过 virtual force（虚力）来实现类似的效果：

- 还是用 PD 控制去计算一个东西，但这个东西不再是一个力矩，而是一个力；
- 而且更直观：假设这个力是加在质心上的，它的目标是把质心推向目标质心位置；
- 当然，"往质心上加力"这件事，本质上是没有任何真实的可能性的——正因为它是 virtual force，这个力不是真的加上去了，实际上也加不了。我们是通过一些关节力矩，用 Jacobian transpose 的方法，来实现类似的效果。

怎么算？本质上跟前面一样：用质心相对各关节的位置组成向量，叉乘这个力 F，就得到那个关节需要加的力矩。有些时候要注意一下顺序——就是方向问题：比如从 root 向下和 root 向上，加出来的力矩方向可能是不一样的，要特别小心。

通常来讲，上半身的关节可以不用关心，因为主要是下半身保持平衡。我们主要关心腿上的这几个关节：hip（髋关节）、knee（膝关节）、ankle（踝关节）——两条腿一共六个关节，在每个关节上加上相应的力矩（用 Jacobian transpose 算），大概就可以实现平衡的效果。

除了平衡，这套方式还可以实现更复杂的效果。比如目标质心不只是一个平面上的投影点，它可以有高度：把目标质心的高度调一调，调低的时候角色就慢慢蹲下去，调高了再慢慢站起来——原地站起蹲下就是这样实现的。甚至还可以加别的东西，比如朝向的控制：在 virtual force 之外，用 PD 控制再算一些让角色左右转一转的力矩，额外加到腿上的关节上，角色就会稍微转一转身体。这些都是可以通过这种方式来实现的。

不过要说清楚：这种方式实现的 balance 是非常弱的。稳稳地站住，没有问题；角色微微地晃动、前后左右稍微转一转，也没有问题。推一下，推得小的时候没有问题——角色往前轻轻倾了一下，又回来了。但稍微推得大一点，大到这个角色必须往前走一步才能保持平衡的时候，这种控制就不 work 了，需要其他的方式来控制。

### 控制角动量：不倒翁是怎么站住的

这方面其实还有一些更 fancy、更漂亮的工作，比如 2009 年一篇非常有意思的文章。我们前面的控制都假设角色是不动的、没有速度的；当角色有速度时，其实可以额外控制：除了质心的位置之外，还可以控制质心的动量和角动量。比如我想让角动量尽可能小，它就会有相应的效果。

想象一下人走路：人在很多时候走路的动作里，你也是在尽可能保持角动量比较小。人正常自然走路的时候，会不由自主地摆手、左右晃动手臂。为什么？本质上，你是在补偿走路时腿带来的角动量变化。在不顺拐的情况下，你去算一下会发现，手的摆动带来的角动量，跟脚的摆动带来的角动量，会多少有一些 counterbalance，互相抵抗一部分，让整个身体的角动量比较小——这样更稳定。而如果走顺拐，或者把手揣在兜里，实际上你就要花额外的能量去控制角动量。

那篇文章的具体细节我不讲，只是从思路上说：通过控制角动量，可以实现动作幅度比较大的情况下，仍然保持原地平衡这样的效果。除此之外，它还求解了一个一步的优化问题——我们前面讲的轨迹优化，是优化一整条轨迹，可能一秒钟长；这个方法里轨迹只优化一步，通过优化这一步，得到下一时刻需要加多少力，来实现对动量和角动量的目标控制。

结合这些方法，它可以实现一个非常稳定的、不倒翁一样的效果。但本质上来说，它还是一个 static balance——还是一个原地的、站立不动的静态平衡。

### 走路是动态平衡，不是静态平衡

但实际上，很多动作并不是 static balance。static balance 的意思，是我们总是希望质心的投影待在支撑范围之内，整个控制过程都在保持这个状态。而走路——或者跑步，以及很多其他动物的运动——不是这样。人的走路是一个非常典型的动态平衡：走路的时候，你不停地把质心往下落，其实就是不断摔倒的一个过程；但在摔倒的时候，你刚好把你的脚移动到一个合适的地方，把它撑住。

而且人总是要偷懒的：摔倒这样一个过程，实际上可以帮你利用重力势能来增加速度、减少力的消耗。所以走路是一个非常典型的动态平衡，不是静态平衡。这种情况下该怎么控制角色保持平衡，是另外一个问题，这一讲就不讲了，下一节课会做进一步的介绍。

最后回顾一下这一讲：我们衔接上节课的内容，把 PD 控制——比例微分控制——的一些性质讲完了；然后讲了一些轨迹优化的基本知识，通过轨迹优化、包括 CMA-ES 这样的 derivative-free 方法，我们可以优化非常复杂的开环运动控制；为了实现更稳定的控制，通常还需要闭环的反馈控制，它会根据角色当前的状态和目标，实时更改控制的参数；最后我们做了一个非常简单的例子，讲如何通过 PD 控制，加上 virtual force 或者 Jacobian transpose control，实现原地平衡的效果。下一节课，我们要把最后一件事讲完：走路是一个动态平衡的过程，如何实现动态平衡、如何实现走路的控制。

## 从站到走：支撑多边形与零力矩点（ZMP）
> 对应块：BLK23 | 覆盖分集：P12上 | 块标题（分集名）：《Lecture11 Learning to Wa》

上节课收尾的时候，我们其实已经做到了一件事：让一个物理仿真的角色原地站稳。往前捋一捋这几节课的线索：第一节课讲物理仿真，怎么把一个虚拟角色仿真出来；第二节课讲控制，怎么让这个虚拟角色保持住一个姿势；上节课在这个基础之上稍微加了一点反馈控制，实现的是一个静态的原地平衡控制器。

这个原地平衡控制器看着只能站在原地，但结合前两节课的内容，它能干的事就多了：上半身用跟踪控制，让控制器去跟踪手、肢体的一些移动；下半身用上节课讲的、利用雅可比转置（Jacobian Transpose Control）实现的平衡控制器。两边一搭，角色就能一边保持平衡、一边做动作。像我们做过的一个工作，本质上就是"平衡 + 跟踪动捕数据"这样的效果，作业里也会有类似的内容。这类方法还有一个纯运动学给不了的好处——细节。比如角色挥手的时候，身体会跟着微微摇晃：手臂一动就带来动量上的变化，身体得靠反作用把它对抗掉，才能维持平衡。这些细节用纯粹的动作数据、基于运动学的方法不太容易做出来，但它恰恰是动作真实感的来源。

不过，只会原地站着，能做的事情还是太少了。我们很多时候希望角色至少能在场景里移动起来——这是我们对可控角色动画的一个基本要求。所以今天就在上节课的基础上再往前走一步，讲走路。

### 物理角色怎么挪地方：不能瞬移，只能蹬地

"移动"这件事，对基于运动学的方法来说非常简单。前面讲运动合成的时候说过：直接在关节上、在这个身体上，把它设置到一个合适的位置、一个合适的姿态，角色自然就移动了。要特别注意的是，这个位置不能设得太差、一步跨得太远——不然你就会看到这个人在不停地瞬移，那显然就不真实了。

但对物理仿真来说，问题就大了：我们不能直接去控制一个角色的全局位置。唯一的办法，是让角色跟地面发生交互——它给地面一个力，地面还它一个反作用力，这个反作用力把角色往前推。所以难点变成了：我们该怎么去规划这样一个全身的控制，让角色能够自己动起来。

### 走路曾是这个领域的头号课题

今天的内容其实不算多，主要就是讲走路。别看"走路"两个字朴素：在深度学习起来之前的二十来年——大概从 2000 年前后，到 2010 年、2015 年之前——基于仿真的角色动画这个方向，大家研究的主要内容就是走路。走路这件事，是非常难以实现的。

而且这不只是角色动画的事。大家熟悉的机器人、特别是人形机器人，走路同样是核心难题：马斯克搞的公司，最近不是又发了新款人形机器人；Boston Dynamics 也一直在做；再早一点，本田的 ASIMO，2000 年前后登场，之后好些年里都是最有名的双足人形机器人；国内像优必选（UBTECH），做得也相当不错。

这两个领域的关系值得多说一句。深度学习之前，角色动画本质上是在仿真一个虚拟角色——比起真的机器人，它的约束要少一点——但大部分情况下，我们采用的还是双足机器人领域发展出来的那些技术，把它们拿过来驱动仿真里的虚拟角色。深度学习之后，角色动画的方法更多来自深度学习、深度强化学习这些方向，对传统机器人控制策略的依赖反而变少了。不过我觉得这恰好是这门课的一个机会：稍微讲一讲机器人控制这边的一些基本内容，对理解这一块是很有好处的。

所以今天的安排是：先把走路讲清楚，包括怎么去定义"平衡"；然后举三个例子，看看过去那段时间大家怎么用简化模型来实现走路的控制——都是零几年到 10 年左右的工作。作业这边也顺便说一下：原计划仿真部分有 Lab 3 和 Lab 4 两个作业，因为时间关系，我们会把它们合成一个实验，总体内容不会差太多。其中一个实验是挑战任务：希望大家能实现一个能步行的机器人。不一定非要用这节课讲的方法，用下节课要讲的基于学习的方法，同样可以完成。

### 走路与跑步：分界线是飞行相

走路这件事，大家应该是非常熟悉的——毕竟差不多每个人都会走。也正因为它是大家都了解的动作，另一方面又相对稳定，所以不管在生物学、医学还是机器人领域，对走路的研究都非常多。为什么说它稳定？因为它慢。慢，就意味着我们有更多的时间去控制。

如果不加任何风格化之类的约束，走路其实是一个非常朴素的过程：两条腿交替移动，左右左右，不断重复。在这个过程里，我们定义几个名词。第一个叫单支撑（single support，也叫 single stance）：一只脚在空中摆动的时候，另一只脚落在地上，由它自己支撑整个身体——所以也叫 stance，一只脚站在那里。另一个是走路特有的时刻：某一个瞬间，两只脚同时在地上，这个时间段叫双脚支撑（double support，也叫 double stance）。走路就是不断重复这样的交替：每只脚轮流当支撑脚，另一只当摆动脚，以此类推。

把这件事画在时间轴上会非常直观：把"左脚与地面接触的时间段"和"右脚与地面接触的时间段"分别画出来，两段一定有重合的地方——重合的部分，对应的就是双脚支撑；只有一只脚触地的时间段，就是单支撑。

```text
时间  ────────────────────────────────────────→

左脚触地  ████████████
右脚触地        ████████████
                ^^^^^^
                重合的区间 = 双脚支撑（double support）
```

两根横条各是一只脚的触地时段，中间叠住的那一小截就是双脚支撑；两头只有一根条的地方，就是单脚支撑。

跟走路相对的就是跑步。从定义上讲，什么是走路、什么时候算跑步？就看有没有飞行相（flight phase）：跑步存在那么一瞬间，左脚右脚同时离地——有这个瞬间，它就不再是走路了，可以把它定义成跑步或者一些别的动作。

这里有个大家可能看过的例子：奥运田径里的竞走。竞走有一条最主要的规则——不允许有"肉眼可见的"飞行时间，你必须保持至少有一只脚跟地面接触，这才叫走路；否则你就不是在走，是在跑了。所以看竞走比赛经常能看到犯规，而且很多都是这个犯规——因为跑肯定比走快，竞走运动员干的事情，就是在尽可能接近跑的状态下"走"。当然，我们这节课不研究跑步，主要还是研究走路。

### 静态平衡走法：能走，但只能慢慢挪

走路时两只脚总在交替向前移动。那怎么让物理角色走出这一步一步？最直接的思路，是拿上节课讲的静态平衡来凑。

静态平衡，或者叫静力平衡，上节课没有给出严格的定义，这里简单说：就是这个对象在基本不动的情况下，怎么摆、怎么放才能保持平衡。判据是保证质心（COM）的投影始终落在支撑多边形（support polygon）里面——质心不跑出支撑面，绕哪条潜在的翻转轴都不会产生把人掀翻的力矩。

> **定义**：静态平衡（静力平衡）——物体在基本不动的情况下保持平衡；判据是质心的地面投影始终落在支撑多边形之内。

用到走路里：单支撑的瞬间，一只脚着地，这只脚本身就是你的支撑多边形——它就是支撑面。那在控制过程中，我们就要让质心的地面投影，始终保持在这个支撑多边形的上边。而到了双脚支撑，两只脚同时落地，支撑区域一下子就大了：它是两只脚的凸包（convex hull）。

为什么说双脚支撑是走路的"机会"？因为如果走静态平衡这条路，我们就需要利用这一段时间，把质心从原来那只脚的上方，挪到另外一只脚的上方；等另一只脚进入单支撑的时候，质心已经在它上边了，平衡就保持住了。这是一种实现走路的策略，而且实际上你真的可以通过这种方式实现走路——当然，策略的细节需要好好设计。大家将来做实验的时候可以去尝试一下。

但它最大的问题在于：静态平衡非常不稳定。你试一下就会发现，它只能勉勉强强保持住角色姿态的平衡。原因在于，静态平衡本质上假设角色处于不动的状态；一旦角色在动，这个假设就被破坏了。动会带来什么？动量的变化，特别是角动量的变化。比如人正在向前移动、只有一只脚站在地上，这个移动相对于旋转轴就有角动量——如果不能很好地平衡这个角动量，就很难保持身体的平衡。

> **易错点**：静态平衡的前提是"角色不动"。角色一旦运动，动量与角动量就不再为零，光靠"质心投影在支撑多边形内"是保不住平衡的。

所以静态平衡能实现的，是非常慢速的、一点一点往前挪的走路。想要看起来更灵活的走路，除了对质心位置的控制，还需要对动量、角动量做更仔细的控制。其实在 2000 年之前的很长一段时间里，双足机器人怎么实现走路，很多时候就是通过对动量的控制来完成的。

而这里就引出一个非常重要的概念：零力矩点（Zero Moment Point，ZMP）。后面好几个非常成功的双足角色，之所以能走出稳定的步子，主要靠的就是对 ZMP 的控制。

> **提示**：ZMP 里的 M 是 Moment（力矩），不是动量（momentum）。它衡量的正是"绕哪个点的翻转力矩为零"，背后关心的则是力与动量、角动量是否互相平衡。

### 受力分析：从整个人到一只脚

ZMP 是怎么来的？我们从一个例子开始。一个虚拟角色，由很多刚体组成，现在正处于走路的状态——看起来可能有点像跑步，但我们认为他是在走。取某一个瞬间，比如单脚支撑的状态，对这个人整体做一个简单的受力分析：首先，人受重力；其次，这只脚落在地面上，地面要给他一个支持力；同时这个人又在移动，而且有加速度——正常走路的时候，人的速度其实是不均匀的，总处在加速、减速交替的状态。那是什么在提供这个加速度？完全是地面反作用力（Ground Reaction Force，GRF）。

GRF 说穿了就是前面讲过的两个力的合体：物体放在地面上，地面给它的支持力；物体有移动趋势的时候，地面给它的摩擦力。这两个力合在一起，就是地面施加给支撑点的反作用力。

从控制的角度看：整个身体的动作，我们前面可以用 PD 控制让角色去跟踪某条轨迹，从而产生相应的动作；但这里我们真正关心的是——怎么控制这个 GRF，让它帮我们把平衡维持住。

这里可以做一个关键的简化。脚不是直接焊在躯干上的，它跟上半身通过关节连接。所以上半身的其他部位——不管多复杂——对这只脚的影响，最终都要通过关节施力、施加力矩来实现。把这一部分独立出来单独做受力分析，这个做法叫隔离（isolate）。

回想一下以前讲过的情形：两个刚体，中间用一个关节点连接。关节是一个约束，它会分别给两个刚体施加力——两个力大小相等、方向相反——保证两个刚体在运动中不会分开：一旦有分开的趋势，它就加一个力拽回来。而这个力一旦算出来，剩下的仿真过程就完全不需要关心另一个刚体长什么样：只看这个刚体此刻受这样一个力，让它按这个力的方向运动，两个刚体就不会分开。

所以回到走路的例子：上半身再复杂都无关紧要，因为它跟脚的交互，只能通过踝关节上的力和力矩来完成。假设我们已经通过动力学把踝关节的力和力矩算出来了，那这只脚作为刚体，受到的作用就剩三路：

```text
      上半身（再复杂也无关紧要）
            │
            │ 踝关节：力 F_a + 力矩 τ_a
            ▼
       ┌─────────┐
       │   脚    │── 重力 m·g（作用在脚的质心 x_c）
       └─────────┘
        ▲   ▲   ▲
        │   │   │   接触力 f_i = 支持力（竖直向上）+ 摩擦力（平行于地面）
══════════════════════════════════ 地面（假设水平、平坦）
```

三路作用：踝关节传来的力和力矩、脚自身的重力、地面接触面上分散的接触力。接下来所有的推导，都只围绕这只被隔离出来的脚。

### 一片接触力，合成一个力和一个力矩

先说地面接触力。地面给脚的力，其实并不是施加在一个点上的。想象一下正常站立或者走路：脚是平平地贴在地上的，脚跟地面的接触是一个面，这个面上每一个点都受到地面的接触力，同时也受到摩擦力。我们可以假设有若干个接触点：第 $i$ 个点 $p_i$ 上，作用着一个力 $f_i$。至于每个点上力的大小，我们先不关心，只要知道每个点上有一个力、施力位置就是那个点就行。每个 $f_i$ 由两部分构成：支持力，总是竖直向上；摩擦力，永远与接触面平行——这是基于摩擦模型得出的力的构成。

这么多力作用在一个刚体上，刚体有个好处：不管加多少个力，总可以把它们等价成施加在某一个点 $p$ 上的一个合力，再配上一个合力矩。这个点 $p$ 选在哪里都行。等价的意思是：接触面上所有力的和，等于加在 $p$ 点上的这个力；同时，原来每一个力都对物体有力矩，把它们合并到一点之后，就相当于在 $p$ 点上有一个合力矩。这就是我们以前讲过的力和力矩的合成公式：

$$F = \sum_i f_i, \qquad \tau_p = \sum_i (p_i - p) \times f_i$$

接下来做一个非常常见、也非常合理的假设：地面是水平的，而且是平坦的——大部分场景都是这样，比如在房间里走路。在这个假设下，所有施力点 $p_i$ 和参考点 $p$ 都在地面上，$p_i - p$ 一定与地面平行。

把每个 $f_i$ 拆成两部分：竖直分量 $f_{i,y}$ 和水平分量 $f_{i,xz}$。竖直方向是确定的，水平方向则是平面内的任意一个方向。代回力矩公式：

$$\tau_p = \sum_i (p_i - p) \times f_{i,y} \;+\; \sum_i (p_i - p) \times f_{i,xz}$$

第一项：与地面平行的向量，叉乘一个与地面垂直的向量，结果一定躺在水平面内；第二项：两个向量都跟地面平行，用右手定则一比划就知道，叉乘结果沿着竖直方向。也就是说，接触力的总力矩可以分解成两块：水平面内的力矩，和绕竖直轴的力矩。

这里要建立一个直观印象：说一个力矩是"竖直"的，指的是它沿着竖直那一条轴——它的效应是让你绕竖直轴旋转，原地打转；而水平面内的力矩，绕的是平面里的某条水平轴，比如沿着脚边缘方向的那条轴，它的效应是把脚向上翻转。

这个公式还能再变形：$p$ 在求和项里是公共的，把它提到求和号外面：

$$\tau_p = \sum_i p_i \times f_i \;-\; p \times \sum_i f_i$$

### 压力中心：让水平力矩消失的那个点

现在有个很有意思的问题：$p$ 本来是在平面上随便选的一个参考点，那有没有可能找到一个点，使得水平面内的这部分力矩正好是零？从上面公式的形式大概能看出来：似乎有可能——只要前一半跟后一半相等，它就是零。而且这样的点确实存在，是一个确定的点，它叫压力中心（Center of Pressure，CoP）：脚踩在地上，压力的"重心"。

它的定义跟质心非常像。质心怎么定义的？每个刚体的位置乘以它的质量，加权平均。这里则相当于：每个接触点的位置上有一个力，我们只关心其中竖直方向的压力——另外那部分是摩擦力，不参与——用压力的大小对位置做加权平均，得到的就是压力中心的位置：

$$p_{\mathrm{CoP}} = \frac{\sum_i f_{i,y}\, p_i}{\sum_i f_{i,y}}$$

把 $p_{\mathrm{CoP}}$ 代回上面的力矩公式，可以比较容易地得到：所有的力——支持力加上摩擦力——绕这个点的力矩，水平方向的分量是零。这是个非常有意思的性质。再把合成结果完整说一遍：合力的大小不变，就是所有力之和；而以 CoP 为参考点时，所有力的力矩没有水平分量，只剩竖直分量——竖直分量只能让物体绕竖直轴旋转。所以 CoP 是一个非常特殊的点。

> **定义**：压力中心（CoP）——接触面上各点位置按竖直方向压力大小加权平均得到的点；所有地面接触力绕它的力矩没有水平分量，只剩绕竖直轴的分量。

### 从脚的平衡方程里解出 ZMP

接着假设角色处于支撑相（stance phase）。想一想自己走路的样子：支撑的那只脚一般是不动的，动的只是向前摆的摆动腿；支撑腿在整个过程中基本保持与地面接触。我们进一步假设：这只脚始终保持水平、与地面完整接触。

在这个前提下，我们把地面给脚的所有接触力，看成施加在某一个点 $p$ 上。这个点本来可以随便选，特殊情况下可以选 CoP。但问题来了：要算 CoP，得知道每个接触点上各加了多大的力；如果这些点上的力没法测量、我们只知道一个总的力，那 CoP 具体在哪里，暂时就不知道了。不过没关系——我们可以假设存在一个点，满足"绕它的水平力矩为零"这个条件。也就是说，把所有 GRF 都认成是施加在这个点上的，那 GRF 相对于这个点的力矩，就应该满足那个关系。

现在看这只脚的平衡。它在这一时刻受到很多力，但不管身体是什么状态，最终都可以归并成：$p$ 点上的地面反作用力（外加一个力矩）、踝关节力和力矩、脚的重力。所有这些力共同作用的效果，是脚始终在地面上保持不动——这说明脚处于平衡状态。平衡有两条要求：第一，所有的力加在一起等于零；第二，沿着任选的一个参考点 $o$，所有的力和力矩的总力矩等于零。这不是零会怎样？说明这个东西要旋转——净力矩不为零它就转起来了，就不再是平衡状态。

> **定义**：刚体的平衡条件——合外力为零，且对任选参考点的合外力矩为零。

对参考点 $o$ 的总力矩，用每个力的作用点相对 $o$ 的连线叉乘这个力来算。把所有项写开：

$$(p - o) \times F_{\mathrm{GRF}} \;+\; \tau_{\mathrm{GRF}} \;+\; (x_c - o) \times m g \;+\; (p_a - o) \times F_a \;+\; \tau_a = 0$$

五项分别是：地面反作用力（施加在 $p$ 上）的力矩、它附带的力矩 $\tau_{\mathrm{GRF}}$、脚的重力（作用在脚的质心 $x_c$）、踝关节力（作用在踝关节 $p_a$）、踝关节力矩。

我们其实只关心水平方向。合力矩等于零，意味着它的水平分量（$xz$ 方向）和竖直分量（$y$ 方向）分别等于零，把水平分量单独拿出来就行。这里有两个要注意的地方。第一，在我们的假设之下，地面反作用力附带的力矩 $\tau_{\mathrm{GRF}}$ 只有竖直方向的分量——只看水平方向的话，这一项就没了。所以原来五项，现在只剩四项。第二，重力 $m g$ 始终竖直向下，它的力矩必然与重力垂直、躺在水平面里，没有竖直分量，所以原封不动地留在方程里。这样得到四项的水平力矩方程：

$$(p - o) \times F_{\mathrm{GRF}} \;+\; (x_c - o) \times m g \;+\; (p_a - o) \times F_a \;+\; \tau_a = 0$$

这一条看着是一个方程，实际上蕴含了两个方程：它本质上是 $xz$ 平面里的二维向量式，$x$、$z$ 两个分量分别为零。数一数已知量和未知量：$o$ 是我们自己选的，知道；$x_c$ 是脚的质心，知道；各个力的大小都假设已知——踝关节的力和力矩可以通过动力学解出来。唯一的未知数是 $p$，而 $p$ 在水平面上，只有两个自由度。两个方程、两个未知数——这个方程组可以把 $p$ 解出来。理论上，我们通过解这个方程，就能算出 $p$ 点的位置。

解出来的这个 $p$，就是一个非常重要的点：零力矩点（Zero Moment Point，ZMP）。为什么叫这个名字？因为它是在"这样的关系成立"的假设之下算出来的 $p$ 的位置；换句话说，$p$ 是让那个让你翻转的力矩等于零、让总合力矩的水平分量为零的点。所以它叫"零力矩点"——这个名字的中文其实不太好翻译，大家记住 ZMP 这个缩写就好。

### ZMP 跑到脚外，人就要摔

但要注意：ZMP 这个说法成立是有条件的——$p$ 必须落在支撑多边形里面。比如单脚支撑的时候，$p$ 必须在脚的内部，它才是有意义的。

为什么这么说？因为我们列方程的时候，只是做了一个假设——假设那一项等于零——这个假设并不必然是真的。在这个假设之下，我们总能解出一个 $p$：它是"能够满足假设"的点。可如果人正处在倾倒的状态，比如正在往前摔，你依然能通过方程算出一个 $p$ 的位置——只不过你会发现，这个 $p$ 跑到脚的外面去了。正常平衡的时候，$p$ 在脚的中间；哪一时刻你算出 $p$ 在脚外边，这说明什么？

说明这个 $p$ 不是 CoP。CoP 按定义是所有外力在脚上的加权平均点，而所有的力都施加在脚的内部，加权平均点无论如何不可能跑到外面去。所以算出来在外面，它就肯定不是 CoP。

```text
   平衡：ZMP 落在脚内                向前倾倒：ZMP 被解到脚尖之外
  ┌──────────┐                     ┌──────────┐
  │    ●     │ ← ZMP = CoP         │          │ ● ← 解出的 p（不是 CoP）
  └──────────┘                     └──────────┘
   真实水平力矩 = 0                  真实水平力矩 ≠ 0
                                    → 脚绕前缘往前翻 → 人摔倒
```

左边：解出的点落在支撑面内，接触力真的能等效成"作用在这点上的力"，脚不翻。右边：解出的点落在支撑面外，它不可能是真实的压力中心。

不是 CoP，又意味着什么？换个角度讲：如果真有另一个点 $p'$ 是真实的压力中心，而 $p' \neq p$，那么把 $p'$ 代到上面那个式子里，左边就不会等于零——而那个式子的左边，正是脚所受的合外力矩（的水平分量）。合外力矩不为零，水平方向的合外力矩意味着：脚要绕平面内的某条水平轴翻转——相当于脚往前翻。这个力矩会把脚掀起来，而脚一抬起来，往往就变得更加不稳定，人就翻过去、摔倒了。

### 把 ZMP 摁在支撑多边形里

总的来说，ZMP 是双足机器人、机器人控制领域里非常重要的一个概念、一个指标：它告诉我们，这个角色现在是不是处于动态平衡的状态——是不是同时满足力的平衡，以及动量、角动量（力矩）上的互相平衡，从而不会再进一步翻转。

换成控制的语言：如果我们在控制角色的时候，始终能够保持 ZMP 处于支撑多边形的里边，那其实就相当于保证了角色是平衡的。

> **结论**：行走平衡的控制判据——让 ZMP 始终落在支撑多边形之内。

那接下来的问题自然就是：怎么实现这样的平衡？怎么去控制 ZMP？这其实是一个非常复杂的问题——前面我们只是讲了 CoP、ZMP 这样一个概念，而如何控制它，复杂到值得专门用一门课来介绍。这里我们只从思路上简单讲一讲。好在问题的起点倒是不难分析的：如果对象只是一个物体——顶多上面再加几个外力——分析起来相对容易。把最简单的情形吃透，再一步步回到整个角色，这正是接下来几个简化模型例子的路线。

> **承前启后**：上一节讲完「从站到走：支撑多边形与零力矩点（ZMP）」，下一节接着讲「从 ZMP 到倒立摆：简化模型如何让角色走起来」。

## 从 ZMP 到倒立摆：简化模型如何让角色走起来
> 对应块：BLK24 | 覆盖分集：P12下 | 块标题（分集名）：《Lecture11 Learning to Wa》

对一个物体——比如一块刚体——我们可以很容易地写出它本身的力学方程；有了力学方程，再用优化、或者下一讲要讲的最优控制这类方法，就能实现对它的控制。但对人来说，事情完全是另一回事：人是一个非常复杂的系统，身上有二三十个不同的刚体，每一个刚体受到的干扰，都可能影响到力的控制。所以想对整个人直接做分析、做控制，是非常困难的。

为了让这个问题变得可控，通常的做法是使用所谓的**简化模型**方法。

### 为什么要简化模型

简化模型做的是什么呢？人（或者一个双足机器人）的身体上有很多状态——每个关节的位置、每个关节的旋转速度等等——它们确实都会影响控制，但影响有大有小。我们要做的，就是从这些状态里找出最关键的、最影响运动平衡性的那些量，把它们单独拿出来，建立一个简化的模型。

通常来讲，我们会把**质心（COM）**拿出来，因为质心的位置和**支撑多边形（support polygon，也就是支撑面、支撑点的位置）**的相对关系，跟平衡性是高度相关的。所以很多时候就是把这两部分拿出来，再加上一些其他的信息，构成一个简化模型，或者叫抽象模型。这类抽象模型有很多种不同的做法，经典的就有好几种——这一讲就把其中最有代表性的几种走一遍。

> **定义**：简化模型，就是从人这样的复杂角色里，挑出对运动平衡最关键的量（质心位置、支撑多边形等）单独建立的抽象模型。

### 简化模型的通用用法：规划质心，还原全身

抽象模型虽然是被简化过的，但它本身仍然满足物理规律。所以我们可以仿真它的运动，甚至仿真它在外界控制之下的运动：比如在简化模型上施加一个力，这个力会影响简化模型的运动，带着它产生新的轨迹。于是我们可以通过控制、规划这些力，让简化模型生成满足要求的轨迹——比如，希望质心（它通常是简化模型的一部分）的轨迹向前移动。质心本来就是角色的一部分，质心向前移动，其实就相当于角色在向前移动。

当然，简化模型只会告诉你质心怎么移动。最终你还是要把简化模型规划出来的质心轨迹，"释放"到真正的机器人或者角色身上。方式有很多种：最简单的是用**逆运动学（IK）**——根据质心的位置，加上腿和脚的位置，反算出腿的姿势、甚至全身的姿势，再用 PD 控制去跟踪这个姿势，大概上就能实现想要的效果；更复杂一点的，可以用**逆动力学（inverse dynamics）**的计算，从质心的移动估计出全身需要加多少力矩。

把这套流程画出来就是：

```text
真实角色（二三十个刚体，状态太多，难以直接控制）
   │  抽取最关键的量：质心位置、支撑多边形……
   ▼
【简化模型】满足物理规律，可以仿真
   │  在模型上加力 / 规划力 ⇒ 生成满足要求的质心轨迹
   ▼
IK：质心位置 + 脚的位置 ⇒ 腿部 / 全身姿势
   ▼
PD 控制跟踪姿势 ⇒ 真实角色动起来
```

读图：上半段是在简化模型里"想"——加力、规划力，得到质心轨迹；下半段是在真实角色上"做"——IK 加 PD，把轨迹变成动作。

所以，简化模型并不是一个非常真实的模型。我们是**假设真实模型会按照简化模型的方式移动**，然后通过控制简化模型，为真实模型的控制提供相应的信号——这就是简化模型方法的本质。

### 小车-桌子模型：ZMP 步行控制

一个简单又非常经典的例子，是 2003 年的一篇工作。它要控制的其实是一个很复杂的机器人，但可以把它简化成什么呢？一张桌子，桌上放着一辆小车；桌子本身有一条腿——这条腿就是支撑脚。

支撑脚踩在地上，地面会给它反作用力，所以整个系统可以计算 ZMP（零力矩点）落在哪里。回想前面 ZMP 的计算可以看到，它跟系统所受的外力有关：小车对桌子施加力和力矩；反过来，桌子对上面的小车也有对应的反作用力。于是对这样一个简化模型，我们就可以**通过控制小车在桌面上的运动，来实现对地面力矩——也就是对 ZMP——的控制**。

```text
          ●  小车：质量 ≈ 整个机器人的质心，由驱动控制加减速
          │
   ┌──────┴──────┐
   │    桌 面    │
   └──────┬──────┘
          │   ← 桌腿 = 支撑脚
 ─────────┴────────────   地面
          ▲
   地面反作用力的作用点 = ZMP
```

读图：小车在桌面上的加减速，会改变整个系统压向地面的力矩，从而挪动 ZMP 的位置。

对这个简化模型做具体分析，可以写出它的运动方程。有了运动方程，目标是什么呢？希望 ZMP 满足一些**预定义的轨迹**。角色正在向前移动、在两只脚之间不停地切换——回想前面讲的：ZMP 始终要保持在支撑多边形里面，而人向前走时，支撑多边形先在这只脚，然后逐渐移到另一只脚，再移回来。所以目标 ZMP 轨迹，就是在两只脚之间不停地切换。接下来就可以用优化的方式，求出小车在桌面上需要采取什么样的加速度，才能让 ZMP 满足这个要求。

因为小车本身有质量，它其实就相当于整个机器人的质心。在跟踪 ZMP 的过程中，质心会产生出一条轨迹——这就是我们规划出来的轨迹。对机器人来说，质心通常在机身中心附近，比如 root 关节（比如腰）那个节点的位置；而 ZMP 代表支撑多边形，也就是脚的位置。有了这两个位置，就可以用 IK 算出关节的姿势，再用 PD 控制让角色做出这样的姿势，从而跟踪运动轨迹。

用这套方式可以实现比较复杂的运动：让角色上楼梯、走更复杂的场景，都可以。这是 ZMP 方向一个很经典、也很早的工作。

说到 ZMP 步行，最有名的产品要数本田（Honda）的 ASIMO：它在各个展会上都有展示，非常灵活。但很遗憾，这个项目现在已经停止了，最终也没有真正商业化。从机器人的角度讲，这某种程度上也像波士顿动力（Boston Dynamics）——机器人虽然非常灵活，但商业化还是多少有些困难。

从步态上就能明显看出这是一个 ZMP 控制。ZMP 控制有什么特点呢？

- **脚基本与地面平行**：所有控制都建立在"脚与地面完整接触"这个假设上；
- **腿始终保持弯曲**：为了进一步保持平衡，走路时膝盖是弯着的；
- **整体移动速度比较缓慢**：因为 ZMP 始终要保持在支撑多边形内部——你可以到边缘，但不能跑得更远。

当然，真实机器人里用的东西远不止 ZMP 控制，还有比如 foot planning（脚步规划）这样的方式来帮助保持平衡。我们这里讲的 ZMP 控制，只是其中一个非常简单的例子。

### 人真正走路的样子：不停摔倒，又不停接住

这种动作放在机器人上很自然——它就是机器人嘛。但人走路不是这个样子。人其实始终处于一种不平衡的状态：走路的时候，我们的质心会移出脚的范围，真正待在脚正上方的时间其实很短。质心一旦移出了脚的范围，人就朝着某个方向倾倒——这时候你会迈腿，把脚放到一个合适的位置，让自己在倾倒中先加一下速，然后正好靠新落的那条腿减速，让质心始终保持在两只脚之间、处于可控的状态。

> **提示**：必须待在支撑多边形里的是 ZMP，不是质心。ZMP 控制靠弯腿、慢速把质心也"摁"在支撑面里；而人走路是放任质心冲出去，用下一步落脚把平衡接回来。

这背后其实有生物学基础。从生物学的角度讲，人是很喜欢偷懒的：不光是走路，哪怕原地站着，你也处在"轻微失去平衡、再把自己推回来"的状态里。生物学的研究也说，这种不停失去平衡又恢复的方式，比始终让质心和脚保持非常仔细的平衡状态，反而更省力。

这里有一个很有意思的研究。前面讲的角色都需要电机去驱动，但既然走路本质上就是不停地往下摔、同时不停地重新规划下一只脚的位置，把这两件事结合起来，就可以让一个机器人在自己重力的作用下向前摔倒，同时又不停把脚移到合适的位置——这就实现了一种很简单的走路。这叫 **Passive Dynamic Walker（被动动态行走）**。它虽然不是这一讲要具体展开的内容，但非常有意思：机器人在下坡的时候完全不需要任何电源驱动，纯靠重力自身的运动就能往前走。后来他们做了一个改进，在上面加一点点驱动，让机器人用非常少的能量一直往前走——印象里有个视频，就是让这个机器人在操场上走圈，能走很多很多圈。

不过我们只是拿它当一个例子：走路除了 ZMP 控制之外，本质上可以"放任它摔倒"，但在摔倒之后，要合理地规划脚步的位置，保证后面能重新平衡起来。那问题就来了：基于这样的模型，该怎么规划脚步的位置？

### 倒立摆与倒立摆小车

常用的一种简化模型，叫 IPM（inverted pendulum model，倒立摆模型）。什么是摆？钟摆大家都见过：上面有一个轴，一根杆或一根线连下来，下面挂一个重物，重物被轴限制着，在下面摆动——这是正常的摆。倒立摆则反过来：轴在底下，物体在上面。

给上面的物体一个初速度，它会朝那个方向移动；同时物体受重力作用，重力对底部的旋转轴会产生力矩。这里跟正常摆正好相反：正常摆的重力力矩是把摆球往回拉的，是恢复力矩；倒立摆的重力力矩是把物体越推越偏的——偏得越多，摔得越快。没有其他外力时，自己简单推导一下就能得到摆角满足的关系：重力 $mg$ 作用在摆球上，对转轴的力臂是 $l\sin\theta$（$\theta$ 为摆杆偏离竖直方向的角度），力矩除以转动惯量 $ml^2$，就是角加速度：

$$\ddot{\theta} = \frac{g}{l}\sin\theta$$

角加速度跟重力大小 $g$ 和杆长 $l$ 都相关。这也是为什么倒立摆顶端的平衡是不稳定平衡——顶点是平衡点，但任何一点偏差都会被重力放大。

> **提示**：后面规划落脚点时还会用到这条物理的另一面：当摆球朝着顶点爬升时，重力力矩变成"刹车"，动能在不断转化为势能——若爬到顶点时速度恰好为零，摆就能稳稳停在最高点。

如果只是一根光杆，这个模型其实没有太大意义：一摆上去就掉下来了，谈不上任何控制。所以控制领域里真正经典的，是所谓**倒立摆小车（inverted pendulum cart，IPC）**：杆的下面是一个小车，我们控制的是小车。杆向哪边倾倒，小车就朝哪边快速移动一下，抢在杆摔下去之前钻到它底下，把物体稳住。相信大家以前都玩过类似的游戏：把扫帚立在手指上，手指跟着挪，扫帚就不会倒——本质上就是这样一个东西。

IPC 是控制领域一个非常经典的问题，有很多控制方法都能实现非常稳定的控制；强化学习、动态规划，也经常拿它作为经典模型来分析。还可以做得更复杂：双倒立摆（上面串两根杆）、三倒立摆，反正就更复杂一些。

而我们这一讲关心的是：怎么用倒立摆这个模型，来规划脚的落点，从而让角色往前移动、同时保持平衡。

### 用倒立摆规划落脚点

动画领域有一个我个人觉得相当经典的工作：2010 年的 Generalized Biped Control。它用的就是这个思路——用倒立摆来规划脚步的位置。

思路本身非常简单。角色有一个质心，质心到支撑脚的连线，就构成了一个倒立摆：摆的重量就是角色的重量，摆球的位置就是角色质心的位置，摆的转轴就是支撑脚踝关节的位置。为什么能这么对应？因为在单脚支撑（single stance）的时候，这只脚是不动的——这差不多就是一个倒立摆的状态。

首先要把角色的状态映射到倒立摆模型上：我知道质心在哪里、脚在哪里，也知道质心的速度是多少（人在向前移动嘛）。

然后是它提出的关键思路：人正常行走时是正在摔倒的——向前走失去平衡之后会摔倒，速度会越来越大。我希望找到一个脚的落点，使得"当前质心 + 新落点"构成的倒立摆，在落地之后逐渐摆动到脚的正上方，并且刚好在到达正上方的那一刻达到稳定状态——速度恰好为零。这样控制下去，角色的速度就始终处在一个可控范围内：每一次都让角色在最高点上把速度归零，走下一步时再稍微加速，下一步又回到零。

那这个落点怎么算呢？其实非常简单，本质上就是一次能量守恒。设在某一时刻摆球（质心）的速度是 $v$，质心相对某个候选落点构成一个倒立摆，杆长是 $l$。在摆球朝顶点爬升的过程中，动能不断转化为势能；摆到最高点时，动能恰好为零，势能达到最大，而那个高度刚好等于摆的长度 $l$。让当前状态的机械能等于最高点的机械能：

$$\frac{1}{2}mv^2 + mgh = mgl \quad\Longrightarrow\quad l = h + \frac{v^2}{2g}$$

其中 $h$ 是当前质心的高度（走路过程中基本不变）。知道了杆长，再由几何关系（勾股定理）就能算出这个摆相对当前质心需要水平挪多少距离：

$$\Delta x = \sqrt{l^2 - h^2}$$

把这个距离加到质心的位置上，就是脚的落点。这样一来，落地点——也就是下一个摆的转轴位置——就求出来了。

有了目标落点之后：从脚当前的位置到目标位置，做一条轨迹（插值或者样条），这就是脚的轨迹。有了脚的轨迹，就可以用 IK——通过质心的位置加上脚的位置，算出一个目标姿态；再加上 PD 控制，我们就可以实现对角色的控制。

这个方法非常经典，也非常通用，效果非常好：

- **对很多角色都适用**：腿的长度可以变，角色的大小也可以变。
- **非常鲁棒**：角色上半身可以做很多动作，甚至可以让角色互相碰撞，也照样保持平衡。主要就是因为倒立摆会实时根据当前状态规划下一次的状态——你从左边推角色一下，它会自动把脚的落点向左边多挪一些来保持平衡。姿态变化、推东西、拿东西，也都可以通过这个方式实现。

当然，这个方法相对来说还是稍微复杂一点：用倒立摆算落点本身并不复杂，但要把这个位置转化成 IK、转化成控制姿势，这一步其实需要花一点功夫。所以实际上还有一些更简单、也更早的方法——SIMBICON。

### SIMBICON：极简反馈实现鲁棒步行

SIMBICON（Simple Biped Locomotion Control）是康康老师 2007 年的工作，是这个领域非常经典的一份工作——它第一个在角色动画领域用非常简单的反馈，实现了比较鲁棒的步行控制。有兴趣的话，建议把这几篇工作找来读一读。

它的出发点是上节课讲的框架。上节课我们讲开环控制：可以优化一条控制轨迹，用 PD 控制器去跟踪它，生成一段动作。但这里有个问题：如果仿真过程中角色受到了扰动，还继续跟踪原来那条开环控制轨迹的话，它就会摔倒——因为开环控制不能根据当前状态做反馈。所以我们需要反馈策略（feedback policy）。SIMBICON 本质上就是"跟踪控制器 + 反馈"这种方法的一个实例、一个特例，它包括两到三部分：

#### 跟踪控制器：状态机或动捕片段

第一部分，本质上就是一个跟踪控制器。这个方法刚提出时是用状态机实现的：定义四个不同的姿态，让角色在这几个姿态之间切换，PD 控制器的跟踪目标就在这几个姿态之间切换。但其实完全可以不用状态机——用一段运动轨迹、一段动捕数据来代替它。所以本质上，它就是一个开环跟踪控制。

#### 上半身保持竖直：合力矩必须为零

第二部分是一些技巧。人保持平衡，很大程度上需要上半身处于竖直状态；不竖直的话人很容易摔，竖直总体来说是一个更容易稳定的状态。为了控制上半身，它让两个大腿根的髋关节加上腰部关节协作，共同控制整个上半身。

具体来说：我们希望躯干（root）在全局方向上保持竖直，那就可以用 PD 控制算出一个"加在躯干上就能让它保持竖直"的力矩。但这里有个约束：整个角色的净合力矩必须是零。这一点之前讨论过——净合力矩不是零的话，角色看起来就不真实，而且物理上也不准确，因为从物理角度讲，每个力都有反作用力。

> **易错点**：关节力矩是内力，全身合起来必须为零。想要一个"凭空"扶正躯干的力矩，就必须让别的关节出一份反向力矩来抵消，不能只算不管。

所以它的做法是：一方面，用 PD 算出保持躯干竖直所需要的力矩；另一方面，摆动腿也有一个目标旋转加 PD 控制，会算出一个力矩。这两个力矩都是我们想要实现、也算得出来的。而支撑腿的力矩，直接用"三个力矩求和等于零"这个简单方程解出来。这样，就通过这套计算保证了 root（躯干）的旋转始终处于竖直状态。

#### 质心平衡反馈：线性外推下一步

第三部分是最重要的部分：质心的平衡。前面这几种方法的目标，并不是让质心保持在当前支撑面正上方，而是估计下一个脚步的位置，让质心的移动始终处于可控范围内。SIMBICON 用了一个非常简单的思路：根据当前质心的速度和位置，估计下一次脚应该落在哪里。

前面用 IPM 也是同样的目标，只不过 IPM 是用倒立摆这个物理模型来做估算。SIMBICON 则更简化、更"偷懒"。大家可以想象生活中的经验：脚被绊了一下、正在向前跌倒，那肯定要往前迈大一点，才能恢复平衡；要是有人从后面推了你一把——你向前的速度比较小——下一步就会往后收一点，甚至向后退一步来保持平衡。所以，向前的速度越大，摆动腿就要向前摆得越快、越远。质心的速度和位置，跟下一步落点之间确实存在关系，但这个关系很可能很复杂，很难直接分析出来。

为了实现控制，可以做一个非常大、也非常粗暴的简化：认为质心的位置、速度，跟摆动腿向前摆动的目标角度呈**线性关系**。对二维角色来说，质心位置是一个一维量，速度也是一个一维量，所以就是两个参数的事：

$$\theta_{\mathrm{swing}} = \theta_{\mathrm{ref}} + k_1\,p_{\mathrm{COM}} + k_2\,v_{\mathrm{COM}}$$

$\theta_{\mathrm{swing}}$ 是摆动腿的目标角度，$\theta_{\mathrm{ref}}$ 是当前跟踪的参考轨迹给出的角度，$p_{\mathrm{COM}}$、$v_{\mathrm{COM}}$ 是质心的位置和速度，$k_1$、$k_2$ 就是那两个手动调的参数。大概是什么意思呢：如果发现质心速度过快——可能正在摔倒——那就意味着摆动腿需要摆得更快一点。因为摆动腿是用 PD 控制的，所以只要把摆动腿的目标角度再往上抬一点，PD 控制下的摆动腿就会摆得更快，保证下一步能及时落地、保持平衡。角色本来在跟踪一条轨迹，公式里前面的部分就是参考的跟踪轨迹，后面的部分就是反馈量。

这是一个非常简单的策略：实际上你可以手动调这两个参数，找到一组合适的参数，让角色比较稳定地走起来。对二维角色来说，这两个参数还是比较容易调出来的，当时也做出了非常有意思的例子——让二维角色跟踪不同的轨迹，配上相应的反馈参数，都能走起来。

不过，这种线性反馈跟前面的 IPM 不太一样：它更简单、更粗暴，实现起来容易，但反馈的鲁棒性相对弱一些——不同的动作，你需要专门去设置相应的反馈参数。另外，作为一个比较早期的工作，它其实也能控制三维角色：三维里需要同时控制向前移动和向侧面移动两个方向的旋转，所以要用两个独立的反馈控制策略，各管一个方向。还有一方面，作为一个非常简单的控制器，它的动作质量稍微有一点不尽如人意，看起来还是比较像一个机器人。但总的来说，这是一个非常简单的方法，能够实现比较稳定的步行控制。

把两种落脚点方案放在一起对比一下：

| 对比维度 | 倒立摆规划落脚点（2010） | SIMBICON 线性反馈（2007） |
| :--- | :--- | :--- |
| 落脚点怎么算 | 倒立摆模型 + 能量守恒 | 质心位置、速度乘系数，直接修正摆腿目标角 |
| 简单程度 | 落点转 IK、转控制姿势要花功夫 | 简单粗暴，实现容易 |
| 鲁棒性 | 强：受推、碰撞都会实时重规划 | 弱一些：换动作要重新调参数 |

### 简化模型的局限与泛化难题

这一讲我们用"走路"这个非常经典的例子，看了过去这个领域是怎么分析它、控制它的，特别是基于简化模型的方法。除了提到的这三个工作——小车-桌子的 ZMP 控制、用倒立摆规划落脚点、SIMBICON——简化模型方向还有很多其他工作，能实现相对更好的效果。

总体来说，简化模型的思路就是：把角色最重要的、跟运动最相关的部分——比如质心、支撑脚的位置——拿出来构成简化模型；在简化模型上进行计算、规划，得到简化模型运动的估计；再根据这个计算还原到完整模型上，让角色动起来。

但缺点也很明显：我们用的这些简化模型，大多来自对"走路"这一个特定动作的大量分析——它们是**特化**的，基本只能做走路。想让它做别的动作，比如后空翻，你是找不到一个相应的简化模型让你轻松实现的。近年来也确实出现了一些复杂得多的方法，可以做出后空翻、侧手翻这类动作，但整个系统会非常非常复杂，实现起来也更困难。

所以一个很大的问题就是：如何把这些控制**泛化**到更多的 motion？对更广泛的动作，该怎么实现控制？在深度学习、深度强化学习兴起之前，学界其实没有特别好的办法，大家基本还是沿着机器人控制这一类思路去做设计。机器学习出现之后，情况就不一样了：只要给一些参考数据，或者给一些更明确的指标，我们就可以通过优化、强化学习等各种手段，训练出相应的控制策略，实现更复杂的控制。

不过，基于学习的方法有一个短板：解释性更差。角色现在很平衡，可它到底有多平衡？能承受多大的外力？用学习到的方法，你很难轻松地把这些算出来。而 ZMP 这类基于简化模型的方法，很多时候是可以具体计算的——我能大致算出这个角色当前有多平衡、能承受多大的外力而不摔倒。这一点对机械类应用来说要友好得多。不管怎么说，作为非常经典的方法，这一套东西非常值得进一步了解。

## 最优化控制:从轨迹优化到贝尔曼方程

### 最后一课,从最优化控制说起

今天是 GAMES105 的最后一节课。这节课先讲一类跟强化学习关系非常近的控制理论——最优化控制(optimal control),从它出发,再去讲强化学习和那些传统方法的区别。为什么把它放在最前面?因为在角色动画、特别是基于物理的角色动画的发展过程中,有相当一批很好的工作就是基于这类方法做出来的;后面我们还会介绍一类通过优化直接得到比较简单控制策略的工作。最后再回顾强化学习的一些基本知识——想把那些算法的细节都准确讲清楚是不现实的,这里只提一些概念、方法和关键字,有兴趣的话,课后可以自己去深入了解。

其实前面几节课我们不停地在讲控制:从开环控制讲到闭环控制,再用简化模型去控制一些最基础的运动形式,比如原地走、走路。在正式进入新内容之前,先把"控制"这个问题本身重新捋一遍。

### 把控制写成优化问题

回想一下,我们对角色能做的事只有一件:在身体上施加力和力矩——其实主要是关节力矩——来实现对角色的驱动。那么问题来了:这个力矩该怎么算?

设想我想让角色做一个后空翻:我手里有一段参考运动轨迹,希望自动找到一整套控制信号——一般来说是一串 PD target——执行它之后,仿真的轨迹能和参考运动轨迹对上。前面讲过,这件事可以建模成一个优化问题:仿真每走一步,就计算当前这一步和参考运动数据的偏差;把这些偏差沿着仿真步长、沿着轨迹长度累加起来,就构成了优化目标;优化的对象,则是每一步所施加的力。写成公式就是

$$\min_{a_0,a_1,\dots,a_{T-1}}\ \sum_{t=0}^{T-1}h(s_t,a_t)\;+\;h(s_T)$$

其中 $h$ 是每一时刻的偏差子项,$s_t$ 是状态,$a_t$ 是这一步的控制信号。

这个建模里有一个非常重要的要点:优化的时候,必须满足当前的物理规律。要提醒一句——仿真里的物理规律并不是真的物理规律,它是物理规律的一个简化,但本质上仍然是物理规律。这套规律可以抽象地写成一个函数:给定当前状态和控制信号,给出下一时刻的状态,

$$s_{t+1}=f(s_t,a_t)$$

如果做的是刚体仿真,前面介绍过,它可以用一系列带约束的方程来描述。于是"找一串控制信号"就变成了一个带约束的优化问题:目标函数负责贴合参考运动,约束负责物理上说得通。

### 开环、前馈与反馈

有了这个框架,可以把几个容易混的词掰清楚。如果只优化一条轨迹,拿到的是开环控制,或者叫前馈控制。这两个词从细节上讲还有一点小区别:

- **开环控制**:完全不在乎输入的变化,单纯地执行预先定好的控制;
- **前馈控制**:稍稍多一点点——比如状态上加了一个扰动,前馈会根据 prediction(预测)把开环的那个控制器修改一点点。但它毕竟是基于 prediction 的,并没有真正去读当前的实际状态。

> **易错点**:开环控制和前馈控制平时经常混着说,我们前面也是把它们混在一起讲的。但严格来说,它们共同的本质是:都不根据状态本身来改变,只是按某种预定义的策略去修改控制信号。

真正要对付扰动带来的问题,需要引入反馈策略:它根据角色受扰动之后的实际状态,实时地更新控制信号,保证整个运行过程中,不管你怎么干扰这个控制对象,它总能把动作保持住。

反馈控制同样可以描述成一个优化问题,形式跟轨迹优化非常像,唯一的区别在于:轨迹优化里,优化的是每一时刻对应的那个控制信号;反馈控制里,优化的是控制策略本身——一个函数,输入当前角色的状态,输出控制信号。

### 最优控制的两类问题

不管是轨迹优化还是闭环控制的优化,它们都属于最优化控制这个大类下的不同类型,而且这两类问题长得完全不一样:

|                | 开环控制(轨迹优化)                                       | 反馈控制(优化策略)                                     |
| :------------- | :--------------------------------------------------------- | :------------------------------------------------------- |
| 给定什么       | 起始状态 + 目标状态                                        | 不管从哪个状态出发都行                                   |
| 算出什么       | 一条控制信号的轨迹,沿它执行就能从起点走到终点              | 每个状态各对应一个控制信号                               |
| 好处           | 只需要计算控制信号,问题相对简单                           | 不管从哪个状态开始,都会被逐渐推到目标状态                |
| 代价           | 中途受到任何扰动,大概率无法继续执行,会离目标越来越远       | 要考虑状态空间里所有状态的情况,难得多                    |

反馈控制实际上算出来的东西,有点像计算了一个"场":状态空间里每一个状态都有一个相应的控制信号,总体上会把角色——不管它从哪个状态开始——逐渐推到目标状态上去。想象一下就知道这个问题比开环难:理论上你需要照顾空间里所有的状态。

前面讲的轨迹优化,对应的就是开环这一类;而我们讲最优控制,大部分情况处理的是反馈这一类,它的理论基础来自 dynamic programming——动态规划。刷过题的话,对这个词应该非常不陌生,算法题里很常用的一类。我们先把开环这版(简单版)的求解讲清楚,再回到它。

### 带约束优化:拉格朗日乘子法

轨迹优化该怎么求解?这个问题今天会稍微多讲一点,把它怎么分析过一遍。这里不得不先提一件事:它是一个带约束的优化问题——优化一个函数,同时满足一个约束。带约束优化是常见优化问题里的一大类;为了简单起见,我们只考虑等式约束的情形。

先看没有约束的时候怎么办:用梯度下降去找解。算出目标函数 $f$ 的梯度——梯度代表函数值增长最快的方向——沿着相反的方向移动,函数值就会越来越小。当然,这样只能找到一个局部最优解。

那约束会带来什么不同?画个图看一个特例。设目标函数是 $f(x,y)=x^2+y^2$,它的值就是每个点到原点的距离,函数的等高线画出来是一圈一圈的同心圆;另一个函数 $g$ 是约束,在二维平面上呈现为一条曲线。"$g=0$"的含义是:解必须落在这条曲线上。所以要做的,就是在曲线上找让 $f$ 最小的点。

一个偷懒的办法是把硬约束转成软约束:给 $g$ 乘一个系数,直接加到优化目标里,变成 $f+\lambda g$。这样优化到最优点时,一方面 $f$ 本身要小,另一方面 $g$ 也要小——虽然解可能不在线上,但离这根线不会太远。好处很明显:没有约束了,问题变好解;但代价也明显:这个问题的解跟原来那个问题的解不一样,最优解有可能不严格落在线上,只是在线附近。

如果不走软约束这条路,还是希望严格保证解在曲线上,怎么办?回到几何,把极值点的样子分析出来。沿着约束曲线移动时,我们的移动方向始终是曲线的切线方向。看这个切线方向与 $f$ 的梯度方向的夹角:夹角小于 90°,说明移动方向和 $f$ 下降的方向一致,越移动 $f$ 越小;夹角等于 90°,不管怎么移动都不会改变 $f$ 的值;再往前走,切线方向跟 $f$ 的方向相反了,越移动 $f$ 反而越大。所以极值点就出现在切线与 $
abla f$ 垂直的位置——二维情况是一条切线,到了三维可能就是一个切面。

另一方面,约束函数 $g$ 的梯度方向,本来就与这条曲线的切线垂直。两个向量都垂直于同一条切线,它们俩就只能平行——平行就是共线。也就是说,如果 $x$ 是这个带约束优化问题的极值点,那么目标函数 $f$ 在这一点的导数方向,和约束函数 $g$ 在这一点的导数方向必然平行:总可以找到一个标量 $\lambda$,乘在 $
abla g$ 上得到 $
abla f$。这就是拉格朗日乘子法的来源。具体做法是定义拉格朗日函数

$$\mathcal{L}(x,y,\lambda)=f(x,y)+\lambda\,g(x,y)$$

其中 $\lambda$ 就叫拉格朗日乘子,对应的差不多就是共线之后两个梯度之间的那个标量系数。对这个 $\mathcal{L}$ 关于 $x$、$y$ 求导并令其为零,得到的就是"两个梯度平行"的条件;对 $\lambda$ 求导并令其为零,得到的恰好是原约束 $g=0$。让拉格朗日函数取得极值的那个 $x$,正是让原优化问题取得极值的 $x$。这是求解等式约束优化问题最常用的一类方法。

> **注意**:上面这个平行条件是必要条件,不是充分条件。$x$ 是最优点时,它一定满足这个条件;但反过来,满足条件的点不一定是全局最优,可能是局部最优点,也可能是鞍点,情况会比较复杂。

还有一点要交代:前面建模运动方程的时候,支持力和摩擦力通常不是等式约束,而是不等式约束。这种情况下,拉格朗日乘子法就会变成 KKT 条件,那套东西更复杂一点,这里不再展开。

### 轨迹优化的拉格朗日:协态与 PMP

现在把拉格朗日乘子法装回轨迹优化问题。目标是沿时间积累的——理论上,如果是一个连续时间问题,这里应该是一个积分;但仿真里我们把它离散化了,所以写出来是一个求和号,两者本质上高度相关。约束就是那条运动方程。目标函数这一行,加上 $\lambda$ 的转置乘以约束这一行,就得到拉格朗日函数:

$$\mathcal{L}=\sum_{t=0}^{T-1}\Big[h(s_t,a_t)+\lambda_{t+1}^{\top}\big(f(s_t,a_t)-s_{t+1}\big)\Big]+h(s_T)$$

看着比较复杂,但结构跟前面二维例子一模一样。

拉格朗日函数的极值点,就是对每个变量求导、令导数等于零得到的那个解——所以求导对象包括:轨迹里每个状态 $s_t$、每个控制信号 $a_t$,以及每个 $\lambda_t$。这个求导过程看起来吓人,但求和号帮了大忙:每一项只跟当前时刻 $t$ 和下一时刻 $t+1$ 相关,所以对中间任何一个变量求导,最多牵出两项——当前时刻这一项,和上一个时刻那一项。对 $s_T$ 求导时,后面那段求和是不参与的,因为它是最后一个状态;对中间时刻求导,则会多出一项。把求导结果整理、把要解的变量解出来,得到四组条件:

- 对 $\lambda$ 求导,得到的就是原来的运动方程 $s_{t+1}=f(s_t,a_t)$——根据当前时刻的状态加上控制信号,算出下一时刻的状态;
- 终端条件:轨迹结束那一刻,$\lambda$ 的最后一项等于终端子项对状态的导数(把 $
abla_{\!s}h$ 简写成 $h'$);
- $\lambda_t$ 满足一个递推公式:算出最后一帧之后,就能从后往前一帧一帧地递推出前面所有的 $\lambda_t$,不断调用这个递推式往回求解;
- 对 $a_t$ 求导的条件稍微复杂一点。把 $s_t$ 固定,把 $h(s_t,a)$ 和 $\lambda_{t+1}^{\top}f(s_t,a)$ 都看成 $a$ 的函数——那么这个条件等价于:把两者加起来当成一个优化函数,对它求极小值。求极小要算导数,而它的导数恰好就是条件右边的部分。

写成紧凑的形式,后三条是

$$\lambda_T=
abla_{\!s}\,h(s_T),\qquad \lambda_t=
abla_{\!s}\,h(s_t,a_t)+\Big(\tfrac{\partial f}{\partial s}\Big)^{\!\top}\lambda_{t+1},\qquad 
abla_{\!a}\,h(s_t,a_t)+\Big(\tfrac{\partial f}{\partial a}\Big)^{\!\top}\lambda_{t+1}=0$$

其中最后那条也常直接写成内层优化的形式:$a_t=\arg\min_{a}\big[h(s_t,a)+\lambda_{t+1}^{\top}f(s_t,a)\big]$。

这些 $\lambda$ 通常还有一个名字:协态(costate)。这个名字很形象——它的表现确实有点像一个状态:正常的状态在控制信号的作用下不断向前演化,那是正向仿真;而 $\lambda$ 像一个逆向的过程,我们是在做一次逆向的仿真。

把上面四组条件合在一起,就得到所谓的庞特里亚金极大值原理(Pontryagin's Maximum Principle,简称 PMP):在最优控制理论里,它是开环控制取得最优的必要条件。庞特里亚金是一位俄国的数学家,这套理论很老了,最早是为了研究火箭的控制而发展出来的。对一些比较简单的系统来说,它至今仍是一个很方便的分析工具。

### Shooting method:前向、后向与更新

PMP 最直接的一个应用,就是所谓的 shooting method:利用 PMP 来实现对轨迹的优化。整个过程是一个前向过程、一个后向过程,再加一个更新过程:

```text
前向:  猜一组控制信号 a0, a1, ..., aT-1,逐帧仿真并记录状态
       s0 --a0--> s1 --a1--> s2 --...--> sT      (记录全部 s_t)

后向:  用记录下来的 s 和 a,从最后一帧开始递推协态
       λT = h'(sT)  <-  λT-1  <-  ...  <-  λ0

更新:  用 λ 和 s 解关于 a 的优化,沿梯度更新 a,回到前向,继续迭代
```

读图说明:我们的目标是不断优化 $a$,让轨迹真正满足"从这里出发、到那里结束"。一开始不知道 $a$ 该取什么值,就用某种方式估计、猜一组;猜出来的 $a$ 执行下去,肯定离目标比较远,没关系,先把这一遍跑完,把每次执行 $a$ 得到的状态都记录下来——$s_0$ 出发执行 $a_0$ 得到 $s_1$,类似地得到 $s_2$、$s_3$……这就是前向过程,实际上就是反复调用前向方程函数。接下来是后向过程:用记录下来的 $s$ 和 $a$ 去调用协态方程,从最后一帧算出 $\lambda_T$,然后依次往前,一路回到 $s_0$,得到每个状态对应的 $\lambda$。这个后向过程有点像链式法则——就是求解神经网络时用的那一套东西。

到了更新这一步还有个宽松之处:那个关于 $a$ 的优化问题,通常并不需要真的求出最优解,只要计算一下梯度、用梯度把 $a$ 更新一下,这一步迭代就算完成了;不断迭代下去,才能逐步逼近最优解。这是一个非常简单、也非常经典的轨迹优化方法。

当然,它有缺点,而且缺点跟目标函数的性质直接相关。前面讲轨迹优化时看过几张图:对一个人走路或者跑步做优化,它的目标函数是非常差的——存在大量的局部极值点,让优化变得非常难做。shooting method 对这种复杂函数通常表现就比较差。所以实际使用时,一般要搭配别的技术,比如 collocation method、multiple shooting,合在一起用;或者把它当作一种分析的方式,真正做优化的时候,改用 derivative-free 这类无导数优化方法。

### 闭环控制:从最短路问题说起

开环控制的理论分析到此为止。闭环控制要的是什么?找到一个策略 $\pi$:对任意一个状态 $s$(也许再加上时间 $t$ 作为输入),都能算出一个合适的 action——一个控制信号——让我最终达到目标。

这件事可以从一个非常经典的算法题入手:最短路问题。图上有一些节点,两个节点之间可能存在有方向的路径,每条路径有自己的代价,比如是距离的函数;我们总希望从一个点出发,找到一条最短的路径到达另一个点。这个问题有很多种解法,其中一类就是动态规划。

从数学描述上讲,我希望找到的是一条路径——一系列状态组成的轨迹。把轨迹上任何两个节点之间那条边的代价定义为单步代价,优化目标就是:找到一条轨迹,让所有边的代价总和最小。

换一个角度看同一个问题:比如从某个状态出发,它有三条出边,可以沿三个不同的方向移动——这三个方向,对应的正是三个不同的控制信号。于是前面的优化问题也可以理解成:找一系列控制信号,让总代价最小;而控制信号会带来运动方程——根据当前状态加上控制信号,得到下一时刻的状态。比如在这个状态下选了 $a_2$,下一时刻自然就到了 $a_2$ 指向的那个节点。

再进一步,就是反馈控制:找一组控制策略,不管从图中哪一个状态出发,都能自动算出该执行哪一条边;沿着这个策略一直执行下去,既能到达目标,总代价又是最小的。这里做个简化:不考虑时间,认为策略只跟状态 $s$ 直接相关。这就是最短路问题底下的控制策略问题。

### 贝尔曼最优性原理

这个策略版的问题里,有一个非常重要的必要条件,它回答"什么情况下这个策略才是最优策略"。这就是贝尔曼最优性原理(Bellman's principle of optimality)——注意,它针对的是控制策略,而不是前面 PMP 针对的那条控制轨迹。

它说的是:如果 $\pi$ 是这个问题上的最优策略,那么不管从图中哪个状态出发、也不管在这个状态下执行了哪一个 action(从而到达一个新的状态),在这个新状态下继续执行 $\pi$,最终一定能达到目标;而且执行 $\pi$ 得到的这条轨迹,恰好就是以这个新状态作为初始状态所能找到的最短路。

> **定义**:最优策略的任何"余下部分"仍然是最优的——从一个状态出发,无论第一步走到哪,后续沿着最优策略走出的轨迹,就是从那个新状态出发的最优轨迹。

当然,这跟问题本身有关,有些问题并不满足这样的条件。能满足这个条件的问题,我们说它具有最优子结构(optimal substructure)——这正好也是动态规划能够成立的那类问题所具有的性质,这两个说法差不多是同一件事:从任何一点出发,如果这个点在某条最优轨迹上,那么从它出发到终点的这段轨迹,一定也是最优的。

### 价值函数:有它就能选动作

从贝尔曼最优性原理出发,可以定义一个函数,叫 value function(价值函数),或者叫某个状态的 value。它在每一个状态下计算一个值,这个值代表:从这个点出发、到目标,所经历的所有轨迹里最优的那条轨迹的代价。换一个角度说:如果 $\pi$ 是最优策略,那么 $V(s)$ 就等于从 $s$ 出发不断执行 $\pi$ 得到的那条轨迹上、所有边的代价之和。

> **定义**:$V(s)$ = 从状态 $s$ 出发到目标,所有轨迹里最优那条的代价;在最优策略下,它也等于沿 $\pi$ 走出的轨迹的累计代价。

value function 重要的地方在于:它会直接告诉你该怎么选 action。设想我要计算从 $s_0$ 出发该选哪个 action,而手上已经有 value function 了:

```text
           --代价 5--->  [V = 30]
     s0    --代价 1--->  [V = 25]
           --代价 12-->  [V = 22]
```

读图说明:比如某个后继节点的 value 是 30,意思是我不知道它后面具体会走什么轨迹,但知道从它出发到目标、整体最优的那个最小代价是 30;另外两个节点分别是 25 和 22。

那么结论可以直接算出来:把边的代价加上那个点的 value function,得到的值就是"从 $s_0$ 沿这条边走能达到的最小值"。三个后继分别是 $5+30=35$、$1+25=26$、$12+22=34$,最小的是 26——所以从 $s_0$ 出发想最快到达目标,直接选代价为 1 的那条边就对了。

再一般化一步:只要有了 value function,那么在每个时刻选 action,只需要计算"每个 action 的代价 + 下一个节点的 value",取和最小的那个 action 就是该选的。按这个方式选 action 的策略,恰好就是最优策略。

### 贝尔曼方程与 Q 函数

回到最短路问题——这里只用它当例子——把"有 V 就能选动作"这件事写成递推。$V(s)$ 的原始定义,是对后面一整串 action 求最小。可以把这一串 action 拆开:对第一个 action 求最小,里面再套一个对剩下的 action 求最小(注意一层下标从 0 开始、一层从 1 开始):

$$V(s_0)=\min_{a_0,a_1,\dots}\Big[h(s_0,a_0)+h(s_1,a_1)+\cdots\Big]=\min_{a_0}\Big[h(s_0,a_0)+\min_{a_1,a_2,\dots}\big(h(s_1,a_1)+\cdots\big)\Big]$$

可以证明这两种写法是等价的。再看后面套着的这一半:它的定义形式跟 $V$ 的原始定义一模一样,只是起点换成了 $s_1$——也就是说,它就是 value function 在新位置 $s_1$ 上的取值 $V(s_1)$。于是相邻两帧的 value function 之间有了一个固定的递推关系,这个关系就叫贝尔曼方程(Bellman equation):最优策略下得到的每个状态的 value function,一定满足

$$V(s)=\min_{a}\ \big[\,h(s,a)+V(s')\,\big],\qquad s'=f(s,a)$$

用文字读一遍:从任何一个状态出发,该状态的 value,等于"沿某个 action 走一步"所产生的两件事之和再取最小——action 本身带来一个代价(loss、cost,随你怎么叫);通过运动方程移动到下一个状态,那个状态也有自己的 value。不同的 $a$ 会到达不同的状态、给出不同的和;所有 $a$ 里最小的那个和,就是当前状态的 value function。贝尔曼方程的意义就在于:它刻画了 value function 达到最优(成为最优价值函数)时所必须满足的要求。

反过来看,一旦拿到了最优价值函数,最优策略——不管它是什么形式——总可以写成这样一个优化问题:总是选那个 action,让"当前这一步的直接代价 + 后面价值函数"的和最小:

$$\pi^{*}(s)=\arg\min_{a}\ \big[h(s,a)+V(s')\big]$$

还可以再整理一下形式:把方括号里这两项之和单独记成一个函数,记作 $Q$,这就是 Q 函数:

$$Q(s,a)=h(s,a)+V(s')$$

它本质上说的是:在当前状态 $s$ 下取一个 action $a$,得到的是"当前这个 action 的代价",加上"转移到新状态之后、那个状态的 value function"。后面讲 Q-learning、讲强化学习的时候会反复用到它,它的另外一个名字叫 state-action value function——说的都是同一个东西。有了 $Q$,最优策略写起来更干净:$\pi^{*}(s)=\arg\min_{a}Q(s,a)$。

把这一整段串起来看,会发现 value function 和 Q function 是极其核心的概念:很多最优化控制、强化学习的算法,最主要的目的就是把 $V$、$Q$ 学出来——因为一旦知道了它们,再去计算 policy 就是相对容易的事。

不过"取最小"这一步本身也有讲究,它自己就是一个优化问题:有了 $V$ 的函数表示之后,要对所有候选 $a$ 求最小值。如果 $a$ 是离散的、只有有限个,这个问题很好解——对所有候选做一遍线性搜索,就能得到结果。典型场景是玩游戏:手柄上就有限个按键,键盘上也是有限个按键,只要算出了 value function,就能用这种方式得到 action。(下围棋当然也是离散的,但围棋的状态空间太大,所以才要换个"稍微简单一点的例子"。)

但如果 $a$ 是连续的呢?比如我们真正关心的人体运动控制:运动时施加的力肯定是一个连续变化的力,而不是几个固定的档位。对连续的 $a$,这个"对所有 a 取最小"的优化目标就不好解了,所以通常需要用别的方法去定义 policy。这就引出一类非常经典、而且有闭式解的特例。

### LQR:线性与二次的特殊组合

先交代一个背景:对反馈控制,我们真正想要的 $V$ 和 $\pi$,通常很难找到简单的解——所谓闭式解(closed form),就是有明确公式、直接写出来就能算的那种。对大部分最优化控制问题,我们都很难找到这样一个显式公式去计算 $V$。但对一些特定的、比较简单的问题,确实存在闭式解。最经典的例子就是 LQR——linear quadratic regulator,线性二次型调节器——控制领域非常经典的一类问题。虽然它只是"一类"问题,能覆盖的范围其实并不小。

LQR 是一个特殊的最优控制问题,特殊在两条硬性规定上。一般来说,我们对目标函数的形状没有任何约束;而 LQR 规定:目标函数必须是一个二次函数——高维情形就是一个二次型。另外,它要求运动方程必须是线性函数。听起来限制很大,但其实未必:回想之前提过的一个非常简单的例子——一个滑块吊在竖直的轨道上,用一个力(比如 PD 控制)去控制它,希望它走出的结果贴着某条给定曲线,比如一条正弦曲线。当时推过:对这样的 PD 控制,再加上欧拉积分,把速度 $v$ 和位置 $x$ 合在一起当作状态变量,你会发现这个状态变量在逐步更新的过程中,跟上一帧的状态以及控制信号之间是一个线性关系;而下面的优化目标,可以很明显看出是一个二次函数——式子里的 $\sin$ 项其实无所谓,因为 $\sin$ 是一个参数,整个过程固定不变,不是优化对象,所以整体仍然是关于优化变量的二次函数。这就是一个非常典型的 LQR 问题。

把两条规定写成标准形式:下一时刻的状态,等于上一时刻的状态乘一个矩阵,加上控制信号乘一个矩阵,

$$s_{t+1}=A_t\,s_t+B_t\,a_t$$

目标函数则是关于状态和控制的二次型。这就是 LQR。

那怎么求解?想想前面刚讲过的贝尔曼方程和最优性原理:要找最佳策略,只需要知道"下一个状态的所有可能性里,每个状态的 value";而根据贝尔曼方程的迭代关系,这个 value 又依赖更下一个状态的 value。所以为了算出 $s_0$ 的 value,就得先算终端时刻的 value,然后从终点往回倒,依次算出 $T-1$、$T-2$……每个状态的 value,一路这样迭代下去。

具体到 LQR,从最后一步看起。终端时刻 $s_T$ 的 value function,按说也要对 $a_T$ 做优化才能得到;但终端的代价项里根本没有 $a$,所以这个 value 可以直接读出来——就是目标函数里终端那一项,一个二次型(系数矩阵记作 $Q_f$):

$$V(s_T)=s_T^{\top}Q_f\,s_T$$

知道这一项之后,往前看一步,看终端前面那一步、也就是第 $T-1$ 步。按贝尔曼方程,这里的 $Q$ 函数等于"执行 $a_{T-1}$ 之后得到下一个状态"相关的两项之和:第 $T-1$ 步自身的代价(这一帧的代价只有中间那一项,没有终端项),加上 $V(s_T)$:

$$Q(s_{T-1},a_{T-1})=h(s_{T-1},a_{T-1})+V(s_T)$$

接下来用运动方程做代换:运动方程告诉我们 $s_T=A_{T-1}s_{T-1}+B_{T-1}a_{T-1}$,把它直接代进上式。展开出来是一个非常复杂的公式,但本质上就是把 $s_T$ 摊开成 $s_{T-1}$ 和 $a_{T-1}$ 的线性组合。摊开之后可以看到,式子里只剩 $s_{T-1}$、$a_{T-1}$ 和一堆系数,把同类项分别合并,整理成关于 $(s_{T-1},a_{T-1})$ 的二次型——这就是这一帧的 $Q$ 函数。

接下来求最优的 $a_{T-1}$。按贝尔曼方程那一部分的规定,最优策略给出的控制信号,应当让 $Q$ 函数对 $a$ 取到最小。好消息是:$Q$ 对 $a$ 是个二次函数,二次函数的最小值非常好求——把二次项的系数矩阵求逆,乘到一次项的系数上,得到的就是让 $Q$ 最小的那个 $a$。比如对形如

$$q(a)=\tfrac{1}{2}a^{\top}Ca+d^{\top}a+e$$

的二次函数,极小点就是 $a^{*}=-C^{-1}d$。于是,"使 $Q$ 最小的 $a$"——也就是最优控制信号——满足一个明确的公式;而且这个公式里前面那一项都是固定的量,每一步都能直接算出来。

于是整套流程就成型了:终端的 value 直接读出来;往前一帧,代入运动方程、合并同类项、对 $a$ 求极小,得到这一帧的最优控制信号;再往前一帧,照同样的次序处理,依次迭代——从终点一路倒推回起点,每一帧的 value 和最优控制信号就都算出来了。

## 从 LQR 到强化学习：让物理角色学会控制自己
> 对应块：BLK26 | 覆盖分集：P13下 | 块标题（分集名）：《Lecture12 Optimal Contro》

上一段推导里，Q 函数还是一大堆矩阵项；把极值点一求，事情突然变得非常干净。前提是这些都是确定的值，而且 $s_{t+1}$ 只跟当前状态相关——所以前面那一整段其实可以合在一起写：它就是一堆矩阵计算，可以用一个矩阵来表示，就叫它 $K$。这时你会发现，最优策略跟当前状态的关系，刚好就是一个线性函数：最优动作就是用一个矩阵乘上当前的状态。也就是说，最优控制其实是一个线性反馈控制策略。$K$ 本身的表达式稍微复杂一点，但形式已经定下来了。

### 收官 LQR：从 Q 到 V 的倒推

既然能算出最优动作 $a$，自然可以得到 $V$。$V$ 是什么？$V$ 就是 $Q$ 在所有 $a$ 上的最小值：

$$V(s) = \min_a Q(s,a)$$

本质来说，就是当 $a$ 取到刚才那个值时 $Q$ 达到的最小值。这个公式项数太多，展开会很复杂，但最终我们可以整理出一个非常关键的结构：$V_{t-1}$ 刚好是一个二次函数的形式，而且它跟前面的 $V_t$ 形式相同，唯一的区别是中间那个二次型矩阵 $P$ 需要根据 $Q_t$ 来计算。

> **结论**：每往前倒推一步，value function 仍然是同一个形式的二次函数，只是二次型矩阵 $P$ 要重新算一次。

这就带来一个非常有意思的过程。每一次迭代：在 $t$ 时刻，它是一个形式非常简单的二次函数；经过一系列计算推到 $t-1$，得到的还是一个二次函数；再进一步类推，$t-2$ 时刻的 value function 也是同样的形式。这样我们就构成了一个从后往前的倒推公式——$P$ 的公式很复杂，但我们总是可以从最后一帧往前计算，递推出每一个时刻的 $P$ 矩阵。

所以 LQR 这个特例可以非常容易地求解，而且求解的结论很漂亮：一个随时间变化的线性反馈参数。每个时刻的系数 $K_t$ 不同，但每一步都是"状态变一点、最优动作跟着变"的反馈控制。

### 滑块、火箭与人体的差距

回到之前那个 PD 控制滑块的问题：我们想让滑块沿着轨迹移动，过程中可能有扰动——比如我伸手拽它一下——但还是希望滑块尽快回到跟踪 3D 轨迹的状态。这时就可以直接施加用 LQR 算出来的线性反馈控制，它能保证滑块在扰动之下始终跟住轨迹。

当然，LQR 能成立是有条件的：运动方程是线性的，目标函数是二次的。对滑块这种问题非常容易；再复杂一点的问题，比如发射火箭、控制火箭的速度，很大程度上也是线性的，你可以把它某种程度地线性化。但是更复杂的问题怎么办？比如人体动作。我们不断强调人的动作，因为它涉及三维旋转，是一个非线性问题：运动学方程里速度的部分是线性的，但从速度到角度的这一段是非线性的。另一方面，我们很多时候会定义更加复杂的目标函数，大部分情况下它不是二次曲线，而是一个更通用的函数。

这就进入了更通用的非线性问题：优化一个随时间积累的求和目标，同时要求满足运动方程。

### 把非线性问题化回 LQR：iLQR 与 DDP

LQR 好解，所以一种很自然的思路是：把非线性问题线性化，把它近似变成一个 LQR 问题。

具体来说，目标函数 $h$ 是一个很复杂的非线性函数。当然我们还是要有一些假设——假设 $h$ 的性质比较好，那么可以在某一个点、某一个初始解附近把 $h$ 展开，展开到二次项，就得到一个二次函数的优化问题。同时，运动方程 $f$ 也是一个非常复杂的非线性函数；同样假设它性质比较好，就可以对 $f$ 做泰勒展开——展到一次项还是二次项，取决于 $f$ 的形式。

> **定义**：把 $f$ 展开到一次项，对应的算法叫 iterative LQR（iLQR）；展开到二次项，对应的另一个算法叫 DDP（Differential Dynamic Programming，微分动态规划）。

这就是我们在求解非线性最优控制问题时，可以采取的策略。

### 最优控制的软肋：调参靠手艺，模型是门槛

用最优化控制来实现全身的动作，很早之前就有一个非常好的工作：2009 年有了第一篇，隔了一年又做了些改进。从当时来看，效果还是相当不错的——通过最优化控制的设计，可以让角色在外界的控制之下走路；同时遇到一些扰动，还能让角色做出反应。

但最优控制最大的问题是什么呢？它的表现，受前面优化问题里的 $Q$ 和 $R$ 影响比较大。所以选择一组比较好的 $Q$ 和 $R$ 来实现一个好的动作，其实是需要一点工程上技巧的事情。

另一方面，为了求解这个问题，我们需要显式地建模运动方程。这就涉及到所谓的 model-based 方法和 model-free 方法的区别。最优控制最大的特点就是：所有的控制都假设运动方程是知道的——如果不知道，前面最优控制那些推导根本没法推下去。这类方法基本都是 model-based 的：我们知道运动方程的模型，根据这个模型来进行运动控制的计算。

#### 模型总不完美

model-based 方法在很多时候是有局限性的。首先，这个 model 函数可能根本不知道；其次，函数本身可能不精确。这两条对人的仿真、对一般的物理动画都是非常成立的。比如碰撞的仿真：我们可以把它描述成一个 penalty、描述成 PD 控制、描述成一个 LCP（线性互补问题）、或者描述成一个约束——但不管哪一种，都是对真实碰撞过程的一个近似，而且这个近似很多时候不太准确。比如常用的基于约束的 LCP 碰撞方程有个缺点：不太容易反弹。正常来讲，我扔一个东西掉到地上，它是会弹起来的；但基于约束的话，反弹的效果不大容易实现。摩擦力的仿真也一样，不同的模型会带来不同的效果。

对真实机器人来说更是如此。首先你的测量是不准确的，总是有误差；其次仿真里的建模跟真实世界之间有区别——不管你怎么建模，仿真都跟真实世界不完全一样；除此之外，整个系统过程中可能有噪音，这对真实机器人很常见：不管控制方面还是传感器方面，都会有噪音。再加上问题本身可能高度非线性，比如人的运动——这种情况下要算梯度、做泰勒展开，如果 $f$ 的性质很差，梯度基本不会给你带来非常有用的信息。

所以在很多时候，model-based 方法对复杂的系统来说可能很难使用；但对简单系统来说，它是非常高效、非常有效、可解释可分析的一类方法。

#### model-free 的底线：模型可以是黑盒，但必须能仿真

后面我们要讲的很多方法都是所谓的 model-free 方法，包括前面已经用过的 CMA 这种基于采样的轨迹优化方法。model-free 指的是：我们不知道运动方程的准确表达，只知道优化函数该怎么优化。

但注意，"不知道 model"不等于完全用不上它：我们还是需要能够以某种方式——用仿真的方式——计算出下一个时刻的状态。方程是个黑盒没关系，但它总要告诉我下一个状态是什么。这是 model-free 方法的一个基本要求。

> **易错点**：model-free 的"不知道模型"，指的是不知道运动方程的准确表达，而不是完全绕开模型——仿真这个"黑盒"必须还在，否则连轨迹都产不出来。

### 用采样优化一个策略：CMA-ES

model-free 方法里非常常用的一类，就是基于采样来优化控制策略。讲轨迹优化时我们提到过：可以用 CMA-ES 这个非常经典的基于采样的优化方法，去优化控制轨迹、优化一条开环轨迹。同样的方法，也可以用来优化控制策略本身。

整个流程跟前面相似，只不过目标变成了一个控制策略。首先对策略进行参数化：比如它是一个线性函数，那这个矩阵就是优化目标；也可以更复杂一点，比如它是一个神经网络，那网络的系数就是优化目标。给定参数 $\theta$ 就给定了一个 policy，我们希望找到最优的参数，使得沿轨迹求和的优化目标最小。

优化过程是这样的：先初始化一个 $\theta$；接下来不断对 $\theta$ 做一点扰动，在它附近找若干个可能更好的 $\theta$；对每一个策略进行若干次仿真，每次仿真产生一条轨迹；在仿真轨迹上计算优化目标函数；最后根据计算得到的结果更新 $\theta$。

怎么更新？不同方法有不同的更新策略。CMA-ES 本质上是把 $\theta$ 看成一个高斯分布——一个高维正态分布，每次更新这个正态分布的均值和方差，让它逐渐移动到最优解附近。

这是我们自己以前的一个工作：直接用 CMA 去优化，实现了一段比较复杂的动作。

### 三步走：开环兜底、线性反馈、采样优化

这么复杂的一个控制，实际该怎么实践？大概三步走。

```text
开环兜底：参考动作 ──CMA 轨迹优化──▶ 开环控制轨迹（能复现动作，但怕扰动）
线性反馈：状态偏移 Δs ──矩阵 M──▶ 控制修正 Δa，把被干扰的状态拉回目标附近
采样优化：CMA 在反馈系数附近扰动、仿真、按目标函数打分、更新分布
```

读图：先把"能动、动得像"的开环轨迹做出来，再叠一层线性反馈负责抗扰动，最后把反馈系数整体交给采样优化去调。

#### 先有开环轨迹

首先要找一个开环控制。原因在于我们使用了线性反馈控制——线性的东西意味着它不能离开工作点太远。因为很多时候我们需要对一个函数做线性化，而线性化肯定离函数越远越不准，这是泰勒展开给我们的基本结论。

所以先通过开环的轨迹优化（比如用 CMA）得到一条开环控制轨迹。开环控制轨迹的好处是：直接执行这一串 action 序列，差不多可以得到相似的动作。缺点是：如果状态被扰动到另一个地方，开环策略没办法更新它的控制信号。这时候就需要反馈控制来更新控制信号，让被干扰过的状态还能回到目标状态附近。

#### 反馈就是一个线性映射

做法非常简单：我们非常简单地认为，干扰带来的状态偏移，跟需要施加的控制信号偏移之间是一个线性关系——乘上一个系数就得到了控制量。这个矩阵 $M$ 代表了状态的变化和控制信号的变化之间的关系。

进一步可以把 $M$ 做分解，写成两个更小的矩阵的乘积：先用一个扁矩阵，把很高维的状态表示映射到一个低维的状态表示；再用一个瘦高矩阵，把这个小的表示映射回一个完整维度的控制信号表示。

```text
高维状态 s ──扁矩阵──▶ 低维瓶颈特征 ──瘦高矩阵──▶ 完整控制信号 a
```

读图：分解的两个好处都落在中间这个"窄口"上——既砍参数量，又滤掉状态里没用的信息。

分解的好处是什么呢？首先是参数量。$M$ 本身是一个矩阵，它的所有参数量是长乘以宽，有些时候这个数量会非常大，对我们的优化来说比较困难；如果我们选择一个比较好的中间维度，一个瘦高、一个矮胖，两个小矩阵的参数总量会比原来的 $M$ 小很多，优化也就更简单一点。另一个角度：通过这种变换，我们其实可以强制把状态里不需要的信息，从控制里拿掉。

#### 挑状态、挑关节：工程上的讲究

为了实现这个控制，我们加了一点工程上的 trick。讲角色的状态，本来可能包括所有关节的旋转、所有刚体的位置等等；但为了让线性函数工作得更好，我们手工挑了一些非常有效的特征。这其实是非常有道理的：状态表示里包括质心位置、质心速度、根节点的旋转，还有到支撑脚的位置——回想一下上节课讲走路：质心和支撑多边形（support polygon）的相对关系，对平衡是非常重要的。这些特征正好就是决定平衡的那几个量。

控制端反过来也一样，是通过挑选出来的关节来加反馈的：为了实现跑步，实际上只需要在少数几个关节上加反馈，就可以让角色比较稳定地奔跑，并且能承受一定的扰动。对平衡来说，一般是两个髋关节（hip）加腰部关节，就可以实现这样的跑步了。

#### 最后交给 CMA

剩下的主要就是优化了。认定这个线性模型之后，直接用 CMA 按前面讲的基于采样的优化过程，去优化线性反馈的系数。因为策略本身比较简单、参数量也非常小，这种优化比现在常见的强化学习要快很多——跑个几分钟就能出结果。

当然，这个效果最主要的还是因为我们首先有一个开环控制，在这个基础之上再做线性反馈，它就能实现比较复杂的运动。当时看起来还挺复杂的，现在感觉好像比较简单了——大家随随便便用强化学习就可能实现这样的一些动作。但非常有意思的是：它只需要线性控制，不需要更复杂的神经网络，就可以实现这样的效果。

### 最优控制与强化学习：同一目标，两条路线

前面讲的都是最优控制；而现在大部分新的、更好的、更高效的工作，用的都是强化学习。实际上，最优控制和强化学习之间有非常强烈的联系。

首先，它们有差不多相同的优化目标：每一个时刻算一个代价函数，然后这个代价函数在整条轨迹的所有时间上进行求和或者积分，在这个基础上去求极值。最优控制的写法通常求最小值——当然求最大值还是最小值其实无所谓，关键是求一个极值；强化学习一般习惯写成求最大值。

差别在路线。最优控制一般是基于模型的方法：它要求我们知道系统的所有方方面面，可以非常精确地写出系统的运动方程。强化学习则不要求知道精确的运动方程，它完全是通过不断跟世界进行交互、进行采样，来更新策略，使得回报取得极值。

不过，虽然 RL 不要求一个准确的系统描述，它还是可以利用一个比较好的系统模型来帮助自己学习。这种模型通常来讲不是直接给出的解析模型，而是可以通过数据学习得到的：先学出一个模型，再用这个模型来指导更有效的策略学习。这是很大一类强化学习方法，叫 model-based RL——研究该怎么学习这样一个模型，以及怎么利用这个模型，帮助更有效地学习控制策略。

### 马尔可夫决策过程：强化学习的问题定义

再多讲一点 RL 的基本知识。强化学习实际在求解的问题，叫马尔可夫决策过程（Markov Decision Process, MDP）。

#### Agent 与环境的循环

简单描述一下这个问题：整个系统里有两个主要的对象。一个是 agent——执行我们策略的小机器人；另一部分是整个外界环境，它可能是非常复杂的环境。

整个过程是这样：小机器人根据某一个控制策略，由当前的状态计算一个 action（控制信号）；然后小机器人在环境里执行这个控制信号，让它的状态更新到下一个状态；同时，环境会告诉机器人：你在执行这个东西的过程中，获得了什么样的代价、什么样的奖励。

不断执行这个循环：从 $s_0$ 开始取 $a_0$，到达 $s_1$；再取 $a_1$，到达 $s_2$……就得到一条很长很长的轨迹——我们一般叫它仿真轨迹，或者控制轨迹，都可以。在这条轨迹上，把每个时刻的回报积累下来，最后得到的值就是状态 $s_0$ 时刻的 return：从 $s_0$ 出发、不断执行这个策略的轨迹上的求和。

```text
s_t ──策略 π──▶ a_t ──环境执行──▶ (s_{t+1}, r_t) ──▶ 回到 s_{t+1}，循环往复
```

读图：一圈就是"状态 → 动作 → 新状态与奖励"；轨迹就是把这个圈一环环连起来，return 是整条轨迹上奖励的累加。

#### 无限长轨迹与折扣因子

RL 里后面要研究的很多问题，都假设轨迹是无限长的。无限长会带来什么问题？如果像最优控制里那样直接求和，而每个点的值都有一个非零的下限，那么无限长的求和之后肯定是无限大，这个问题就没法解了。

所以通常来讲，我们考察的是折扣回报：每一帧的 reward 前面加一个系数 $\gamma$，$\gamma$ 小于 1，通常取很接近 1 的值，比如 0.9、0.99，有些时候 0.999。它的效果是：轨迹越往后，我们认为后面的状态受当前状态的影响会稍微小一点，因为中间有很多各种干扰；换句话说，离当前状态非常远的那些状态，它们的好坏不影响对当前状态的判断。

$$G_t = r_t + \gamma\,r_{t+1} + \gamma^2\,r_{t+2} + \cdots, \qquad \gamma < 1$$

一个非常典型的例子：一个跟踪问题——本质上是一个轨迹优化问题——可以把它变成一个 MDP 问题。主要就是 reward 这部分：像做轨迹优化时一样，用仿真的结果跟参考数据的结果做一个差，作为 reward function。这其实就相当于用一个强化学习来实现跟踪控制。

#### 四元组与马尔可夫性

从数学描述上来说，MDP 是一个离散时间的随机控制问题。MDP 包括 RL，其实是一个非常好用的 framework，我们可以用它来做非常复杂问题的训练。它最基本的要求有两条：一，它不假设状态转移的概率是已知的——系统照样在运行，但我们可能并不知道它；二，它必须是一个马尔可夫过程，一定要有马尔可夫性（Markov property）。

马尔可夫性说的是什么？其实我们前面一直在用这条性质，只是没有显式把它说出来：下一时刻的状态，只跟当前时刻的状态相关；在知道当前状态之后，下一时刻的状态不会跟之前任何时刻的状态相关。

更精确的 MDP 定义，通常给出一个四元组 $(S, A, P, R)$：$S$ 是所有可能状态的集合，它可能是连续的空间，也可能是离散的空间；$A$ 是所有可能的控制信号（action）的空间；$P$ 是状态转移的概率——它对应的其实就是我们的运动学方程，虽然形式上写在这里，但可以不知道它；$R$ 是 reward，也就是代价函数。

#### 为什么优化的是期望回报

求解 MDP 问题，我们其实是要干什么？找一个策略 $\pi$——跟前面的最优控制一样——然后去优化期望回报（expected return）。这一点有点不太一样：前面讲最优控制的时候，我们是直接找最优解、直接优化那个方程，而且当时其实假设 $\pi$ 是一个确定性的函数。MDP 问题里，我们会假设 $\pi$ 和所有的状态转移都带噪音：比如控制噪音、传感器噪音等等。这些噪音会带来什么呢？实际施加的控制、实际转向哪个状态，都是按概率变化的。

当然也有些系统不一定是噪音，而是它本身就随着概率变化——非常简单的一个例子就是薛定谔的猫，它就是随着概率去变化的。

这种情况下，我们通常把优化目标定义成：从任何一个状态出发，执行 $\pi$，得到一系列可能的轨迹；每一条轨迹会给一个 return；在所有可能的轨迹上计算 return 的期望，让它最大。这就是 MDP 的优化目标。

### Value function、Bellman 方程与 value-based 方法

#### 两种定义的差别

回忆最优控制里 value function 的形式：它是一个 Bellman 方程；Q function——state-action value function——其实也是 Bellman 方程的形式。在知道了 Bellman 方程之后，$\pi$ 就是求这个函数的最优解：对它取极值，就得到我们的控制信号。

RL 里呢？特别是对连续状态空间、连续控制信号下的 RL：value function 通常来讲定义在某个策略 $\pi$ 之上——针对某一个策略，而不是最优策略。最优控制里那几个对应的其实是最优策略；而对 RL 来说，很多时候是说：这个 value function 是根据当前的某一个策略定义的——它是在这个 policy 下执行的所有可能的仿真轨迹，所计算出的 return 的值。Q function 也是类似的。

同时，它们也都满足前面 Bellman 方程的迭代形式。这个相对关系在强化学习里非常重要——为什么？因为我们后面很多强化学习的方法，都是基于 Bellman 方程进行设计的。

#### value-based 方法怎么学

value-based 方法的基本思想：去计算 value function 或者 Q function——Q function 本质上也是一个 value function。过程中不断产生新的 trajectory，在这些新的轨迹上，用前后两帧、利用迭代公式去计算期望的 value function 值；然后让当前的 value function 向那个期望值靠近——通过不断优化这样一个代价函数的表示，最终得到一个最优的 value function。

得到最优的 Q function 之后，对应得到控制策略：对每一个 action 取最小值或者最大值，就得到了控制策略。

value-based 的方法很多时候用在控制信号离散的问题里。有一些非常经典的算法：value iteration、Q-learning，还有 DQN。

#### DQN：登上 Nature 的里程碑

DQN 是一个非常有意思的工作，发表在 Nature 上。应该说它在某种程度上开启了深度强化学习的一个新时代：一方面让这些东西变成了大家都知道的问题，另一方面它提出的一系列方法也推动了强化学习在动画还有很多其他领域的应用。

它实际做的事：用 Q-learning 去控制一个摇杆。摇杆乍一想好像是连续空间，但它把摇杆可能的控制方向做了离散化，所以最终只有十几个不同的控制信号。它最终通过 value 函数的学习：对当前某一个状态——比如这一帧的图像——每一个摇杆移动方向都对应一个 Q 值；得到之后去找最大值，只要把所有可能性遍历一遍，就可以控制角色移动。

这篇论文实现的效果是：通过这种简单的策略、简单的代价函数加上训练，就可以达到一个人玩这个游戏所能达到的平均分数，甚至比人的平均分数还要高。这是 2015 年的工作，非常经典。DeepMind 从这开始变成了一个非常知名的学术机构。

#### 动画里的 DQN：用离散选择做高层控制

在角色动画里，我们同样可以用 DQN 来做比较复杂动作的控制。注意 value-based 方法有一个非常基本的要求：状态空间可以是连续的，但控制空间必须是离散的。所以我们实际上可以用它来做一些高阶的控制。

我们之前的一个工作就是这样：先学一个控制器，这个控制器里角色在玩滑板；玩滑板的过程中，比如撞到了物体——如果继续执行之前玩滑板的动作，可能就摔倒了；所以为了不摔倒，它需要跳转到某一个滑板技术上，然后在这个基础上去比较好地越过坡道。那该选择哪一个时刻跳转、跳转到控制器的哪一部分？这就可以通过 DQN 来实现：本质上我们把整个控制策略按时间切成片，选择就变成了一个离散的集合，正好满足 value-based 方法对离散控制的要求，于是可以用 DQN 实现这样完整的控制。

### Policy gradient 与 Actor-Critic

另一大类强化学习方法，是所谓的 policy gradient approach。它还有另外一个跟 value function 合在一起的版本，叫 actor-critic——本质上就是 policy gradient 跟基于 value function 的方法的结合。

#### 梯度从哪来

policy gradient 方法的第一步，跟基于 value function 的方法是一样的：最终还是需要学习一个 value function——可以通过 Bellman 方程；如果能采到很长的序列，当然也可以直接在长序列上计算，就不需要 Bellman 方程了。但不管怎么样，总需要这么一个东西来近似地学习 value function 的表示。

有了 value function 之后，我们就可以用仿真得到的样本点，通过蒙特卡罗法去计算一个近似的 policy gradient。想一想前面怎么优化一个函数：我们求的是函数本身的 gradient。对 policy 来说，本质上去优化一个 policy，是希望它能够优化整个 value function；所以我们最终计算的 policy gradient，实际上是 value function 对 policy 的参数求导得到的那个 gradient。

这个 gradient 直接计算是没法算的——因为仿真的模型我们不知道，所以没法算。所以 policy gradient 方法一般是通过一些统计的技巧，把不能算的部分从公式里去掉，得到对 policy gradient 的一个近似。有了这个近似梯度，就可以直接用 gradient ascent 去更新 policy 的参数。

#### 跟 value-based 的根本区别

这种方式的好处是：整个计算过程中同时有两个函数在更新——一个是 value function，另一个是显式定义好的 policy，它可能是一个神经网络，也可能是其他奇奇怪怪的表示。而前面 value function 的方法里，policy 是没有显式定义的，只有 value function 是显式定义的。这是两类方法非常大的区别。

| 对比 | value-based 方法 | policy gradient 方法 |
| :--- | :--- | :--- |
| policy 是否显式定义 | 否，只有 value function 显式定义 | 是，显式定义（如神经网络） |
| 如何得到动作 | 对最优 Q 的每个 action 取极值 | 直接对 policy 函数求值 |
| 适合的控制空间 | 离散控制信号 | 连续问题更有效 |
| 代表算法 | value iteration、Q-learning、DQN | REINFORCE、TRPO、PPO |

正因为显式定义了控制 policy，我们就不需要每一步去求解一个优化问题来找到下一个 action——只需要直接对 policy 的函数求值，就可以得到需要的 action。所以它对连续的问题会更加有效。非常经典的方法比如 REINFORCE、TRPO、PPO，差不多都是这一类。特别是 PPO，应该说在角色动画领域、特别是物理仿真动画里，应用非常非常广泛。

#### 理论与现实的落差

RL 的方法其实蛮多，也有很多新方法，但最关键的一步是计算 approximate policy gradient。很多现在常见的强化学习方法都基于一个假设：假设采了无限多的样本，在无限多的样本点下，用求期望的方式去计算 gradient。但真实的场景里，我们不可能采无限多的样本；而且像人的控制、角色动画的控制，整个状态空间的维度非常高——在维度非常高的情况下，撒几万个样本点，对一个 100 维的空间来说也是非常稀疏的。这种情况下，方法实际得到的效果，可能跟理论分析上多少会有一些出入。

所以实际上大家很多时候用的方法是什么呢？是这个方法本身在很多人用了之后，发现它的实际鲁棒性或者有效性相对好一点，于是大家都用。PPO 为什么用的人大概这么多？确实因为它实际效果还是蛮好的。当然很多其他方法可能效果更好，只是大家在使用上还没有注意到它们。

### 强化学习给物理动画带来了什么

不管怎么说，使用强化学习加上一点点的轨迹优化控制，我们就可以实现非常复杂的动作。现在应该说：只要有一份动捕数据——当然动捕数据的质量不要太差——不管什么动作，我们都可以学习一个控制器，使得物理仿真的角色能够做出这个动作。

而且在这个过程中我们可以调整很多参数：比如角色运动的速度、角色的高矮胖瘦——把这些东西作为额外的参数给到控制策略，得到的运动控制就能自动适应不同的角色和不同的控制信号。这是强化学习给物理动画带来的非常大的进步。

在这个基础上还可以做一些应用：比如把大量控制不同动作的控制策略结合起来——像 motion graph 一样，做一个 control graph，用状态机的方式实现对角色的灵活控制。

### 把生成模型装进控制策略

前面几种常用的跟踪控制里，我们的控制策略通常会建模成一个神经网络。神经网络从结构上来说有很多技巧可用。前面讲基于学习的运动学动画方法时提到过很多生成模型：autoencoder、VAE、GAN（生成对抗网络）、标准化流（normalizing flow），还有今年特别火的 diffusion model（扩散模型）。这些生成模型带来的是网络结构上的新设计，同样可以用在我们的物理角色动画里、用在基于强化学习的控制策略学习里：把控制策略的部分换成相应的生成模型网络。

生成模型带来的效果非常好：随便给一个随机噪音，通过仿真就能得到一些完全不同的动作。

但学习这样一个生成模型通常来说相对困难。一方面是 RL 本身的不稳定问题——对比一下运动生成模型那边：那里我们可以直接通过监督学习（supervised learning）来实现学习，而监督学习是非常稳定的学习方法，每次运行不用怎么调参数，就可以得到一个相对还可以的结果。GAN 就是一个非常典型的不太稳定的训练过程，因为它本质上不是一个直接的监督学习，而是通过一个判别器来进行监督。对 RL 来说也一样：虽然我们可以换成不同的生成模型网络来实现类似生成的效果，但学习这样一个生成模型相对困难——RL 的不稳定加上生成模型本身的不稳定，不同的生成模型可能还有各自的不稳定问题。所以解决这些问题，是我们最近一些工作的重点。

### 物理动画离工业落地还有多远

回头看角色动画领域很多技术的发展过程：最早的状态机模型，到 motion graph，到最近大家看到的基于学习的各种运动生成方法——这代表了基于运动学的方法这么长时间的发展脉络。而最近一段时间，从基于强化学习的、可以比较容易训练很复杂动作的大量技术，到这两年很多大学、研究机构（包括我们这边）提出的各种可控运动生成方法，其实带来了一种新的可能性。

我个人是觉得：我们总说物理动画是未来的动画技术，它似乎可以完全代替关键帧这一类方法和基于运动学的方法，因为它可以提供更真实的体现。但前面也提到，运动控制上的难度、可编辑的难度、风格化的难度，都会给实际应用带来很大的挑战。近两年的发展让我们看到：这些方法好像真的有可能在比较近的时间内，用到真正的工业场景里去。这是一个非常有意思、非常有可能的方向。

### 通往人工小脑与数字演员

现在大部分情况下，我们还是一个动作一个动作地去学一个新的动作。随着生成模型、运动生成模型控制这一类技术的发展，以后我们可能就不再一个动作一个动作地学了。

可以进一步扩大化：现在讲图像、音频、语音，可以看到大量大规模预训练模型，可以在下游任务上完成更好的操作、取得更好的效果。对运动来说，特别是运动控制，一个非常有意思、近未来可能很快就会有人做的方向是：我们是不是有可能从大量的运动控制里，学习一个大规模预训练模型——有点像人的小脑。人的大脑是用来做认知、做高级决策的，但人的移动、协调全身的动作，很多时候来自小脑。把这些大量的动作合在一起，构成一个人工的小脑，为更高级的人工智能提供可移动的能力——这非常有意思。

另外就是跨模态的学习和生成。这两年非常火的 ChatGPT，大家可以试着玩一玩，它会带来一些以前完全想不到的特性。实际上通过大量语言学出来的模型，聊天其实有点大材小用了——你会发现它里面隐含了很多新的知识、很多语言里可以挖掘出来的知识。这些知识作为一个新的模态，可能在我们做运动生成的时候帮上忙。最直接的应用：是不是有可能通过语言模型跟音乐、声音等各种跨模态的共同学习，真正生成一个数字演员——不是那种皮套人，而是完全靠语言或者某些任务驱动，能够自动做出合适的动作、通过仿真跟环境做出逼真交互的数字演员。这也是非常有意思的方向。当然还有很多可以想的事情，这里就先留白。

### 肌肉、人群与没讲完的话

还有一些基础的问题。我们做角色动画，仿真的时候通常用关节力矩来控制；但对真人来说，人是通过肌肉来控制的——人不可能直接产生关节力矩，总是通过肌肉收缩来进行控制。特别是对一些要求精度的场合，这些很重要：我们是不是能够通过更复杂的肌肉仿真，实现更真实的人的动作？

另外还有一些相关的领域，比如 crowd simulation（人群仿真），跟游戏基本相关，因为时间关系课程没有涉及：比如春运这种大规模人群的相互移动；也不一定是人群，也可能是少数人——比如两个人合作摔跤，比如我们要一起把家具装起来——整个过程中人的行为该怎么生成、怎么建模？这些都是非常好玩的方向和领域。
