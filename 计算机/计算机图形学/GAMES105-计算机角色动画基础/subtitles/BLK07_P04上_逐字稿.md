首先就是回顾一下我们上节课讲的内容：角色运动学。当然主要是前向运动学，是从知道 pose、知道每个关节旋转去计算每个关节的位置，还有逆向运动学，我们知道末端节点，比如手的位置，我们想要去反算出每个关节的位置，这是我们上节课主要讲的内容。

我们先简要回顾一下我们前向运动学的部分。我们知道我们对于任何一个角色，比如这样一个人类的角色，我们通常来讲会把它抽象化成由若干个关节和若干个骨骼构成的这样一个模型。当然骨骼总是围绕着关节旋转，并且在我们常见的角色里面，一般来讲我们关节是不会分开的。分开的游戏特殊角色它是会分开的，但大部分情况下骨骼只会围绕着关节旋转而不会让它分开。

这样一个结构的话，我们之前也说过，我们可以把它表示成一个树状的结构。从根节点开始，根节点通常来讲我们会把它放在腰部、髋部。然后从根节点出发，我们有若干条运动学链，从根节点到脚，从根节点到手，从根节点到脑部等等。每条链合在一起构成一个树状的结构。

在定义的时候，其实这个角色它有一个初始化的姿势，在这个姿势里面，每两个关节之间，就是每个关节到它的父关节，它们之间这个距离其实是在父关节局部坐标系下的一个坐标表示。

在这样的定义之下，如果说我们每个关节加上了一个旋转，其实这个角色就会被旋转到一个新的姿势。在这个姿势下，我们的前向运动学（FK）要做的事情就是说，当我给出了这样一个姿势之后，我们需要去计算每个关节的朝向、每个关节的位置。

当我说朝向的时候，实际是说假如说我们有一个坐标系，它粘在对应的关节上，当我旋转完之后，这个局部坐标系在世界坐标系它的方向、它的旋转，我们通常会把它叫做朝向。

在这个过程中，我们前向运动学计算基本上来说是一个迭代的过程。我们从根节点出发，沿着每一条运动学链去依次积累每一个关节上的旋转。同样地，其实我们如果说计算出了它的父节点的朝向，我们把父节点的朝向乘以当前关节的旋转，其实也就得到当前关节的朝向。类似地，关节的位置其实也可以通过同样的、这种迭代式的计算来进行完成。

这里需要注意的是说，如果说我们知道了每一个关节的朝向，朝向是什么？朝向是全局的一个旋转，代表了每个关节它自己内部坐标系在世界坐标系的位置。如果说我们知道每一个关节的朝向之后，如果说我们想要计算每个关节的旋转，这个其实相对来说是比较容易的。我们只需要用父节点的朝向的逆——旋转矩阵来说它的逆就是它的转置——用父节点旋转的转置乘以当前节点的旋转，那得到的就是这个关节的旋转。这是一个非常简单的关系。

当然我们上面也提到了，其实包括作业里面也用到了，我们一般来讲很多动作我们可以把它存在文件里。一般来讲一个动作它是由多个姿势来构成的，那每一个姿势可能就是带有了若干个参数化的参数。

BVH 文件，我们作业里也会用到，它是一个非常常用的动作捕捉的文件类型。BVH 文件的具体格式，大家可以去看一下我们这里的链接，其实我们作业里面也提供了一个中文的链接，也是我们一个助教写的一个简短的文档，大家可以去作为参考。

大概来说，其实对于 BVH 文件来说，或者说对于任何一个动作捕捉或者动作的文件类型来说，它可能不是 BVH，哪怕是 FBX，哪怕比如是 AMC、AMF 这样的文件来说，它大概来说都会分成两部分。

其中一个部分，比如 BVH 文件来说，它的这个文件的一开头它会定义一个角色的模型，其实就是这个模型。它怎么定义这个模型？它是通过每个关节相对于它父节点的偏移，它是一个三维的向量，通过这个偏移来告诉你这个模型长什么样子。比如它会告诉你肩膀的关节到中间脊柱的关节，它的偏移是多少，一般来讲可能是一个 $x$ 方向的一个向量；然后类似膝盖的关节在髋关节的下方多远，它会给出你这样的一个偏移来定义这样一个角色。

接下来一般来讲第二部分，对这个文件来说第二部分它一般来讲会有若干行或者若干个区块，每一个区块它会定义一个姿势。怎么定义呢？因为上面角色的关节其实已经在上面文件的前方已经定义好了，我们接下来其实后面只需要定义每个关节它的旋转，以及根节点的位置和朝向，其实我们就可以定义好这个角色的姿势了。我们把一系列的角色姿势放在同一个文件里，它就是定义了一个动作。这是一个常用的文件表示。

当然这里就有一个问题，就是说对于我们一个角色来说，通常来讲我们有这样一个初始的姿势，把每个关节加上了旋转之后，它会变到一个新的姿势。那么在这个初始的姿势，其实我们认为它的旋转应该是等于 0 的，或者说它的每一个关节的朝向都等于——如果用矩阵表示的话——都等于单位阵。

这样的一个 pose，通常来讲我们会有一个专有的名字，我们叫它 T-pose。有些时候可能也叫它 bind pose 或者叫 reference pose。总而言之，不管它这个 pose 是什么形状的，我们讲 reference pose 或者讲 T-pose 的时候，我们总是指的是所有旋转都等于 0 的这样一个姿势。其实比如这是一个具体的一个角色，把它绑到一个三维的角色模型之上，其实这个 T-pose 大概是这个样子。

当然实际上我们常见的除了 T-pose 之外，还有另外一类叫做 A-pose。其实 A-pose 有很多种了，非 T-pose 就是 A-pose。A-pose 一般来讲常见的这种就是说这个手不是水平举起来的，因为水平举起来就是一个字母 T 嘛。它一般来讲我们这个手可能是半举这样一个状态，看起来好像是一个 A 字母，所以一般来讲把它叫做 A-pose。

实际上比如在我们的很多见角色模型的时候，我们有时候会见到 T-pose，有些时候会见到 A-pose。其实用哪一种 pose 对于我们做动画来说，如果说我们只关心骨骼的移动来说，这个其实关系并不是很大。

但是实际上，如果我们的听众里面或者我们的学生有做过动画方向的，比如做过建模的，可能你可能有些经验。至少我的了解，做动画师他在做绑定的时候，他会比较喜欢 A-pose。

这个原因其实有两个吧：一方面是说，比如我从一个正常的姿态，因为我正常人站起来站着的时候，其实手是下垂的，这是一个比较自然的一个状态。那如果说我要把手举平，那这个时候我的肩膀附近这边的肌肉和皮肤，它会有比较大的形变。那这个时候我如果把它绑在一个 3D 模型事实上，那我做其他动作的时候，这个形变有些时候会带来一些 artifact，会带来一些走样的问题。

那另外一方面其实也是，不知道大家有没有注意过，当你把这个手抬平做出这样一个 T-pose 姿势的时候，实际不只你的肩膀这个关节会旋转，其实你的 clavicle，应该叫锁骨，这一带其实也会往上移动。整体来说这个其实也是给我的绑定带来一些难度，就当我做其他姿势的时候，你会感觉这个角色看起来就不自然。所以很多时候动画师绑定的时候，他会喜欢用 A-pose 做绑定。

那这样就带来了一个什么问题呢？就是说我们动捕这边，大家做动捕的时候，一般来讲标准都是做 T-pose，然后你的角色其实反而是 A-pose，所以经常有些时候会带来一些问题。

当然实际上 A-pose、T-pose，大家可能比较标准了，我们说 T-pose 基本来就是这种两臂平伸、两脚竖直站立，这是一个 T-pose。A-pose 它的总数就很多了，比如说这一种 A-pose，这样也是一种 A-pose，你看这个脚会分得开一点；当然这个也是一个 A-pose，手可能再分得角度不一样一点；当然这个也是一个——当然不叫 A-pose，反正是某一个 pose。

这个 pose 在什么时候会出现呢？其实有时候也经常会看到，特别是有时候我以前经常比如从动画师那边拿了一个绑定的模型，然后我把所有的关节设成 0 之后，哎呀，那个角色就变成这么一个奇怪的姿势了。

那为什么是这样一个姿势呢？其实这个可能在某种程度上可能跟动画师的经验有关。就是说通常来讲，比如你在 Maya 里面，比如这个软件，我是怎么建角色的呢？我通常来说是先建好一个胳膊，然后把这个胳膊复制一份做一个镜像，然后再跟另外一个胳膊拼在一起，然后腿甚至可能都跟胳膊是从一个地方来的，然后最后建成这么一个 pose。

那在这个过程中，其实 Maya 比如这种软件，它做镜像的时候，它会把那个镜像对应的 transformation，叫那个变换，其实是会记录下来的。那这个 transformation 其实会带来什么问题呢？它是一个非零的旋转，把它设成变成 0 之后，transformation 就会旋转到原来没有变的状态下，那就可能会出现这样一个姿势。

当然可能有些建模师他有经验的话，他可能会做完这个建模之后，他会先做一步这种清零的操作，让软件自动地重置一下每个关节的相对位置。这样的话可以保证我这个姿势是比较正确的，那否则你也会出现这种问题。

当然 A-pose 和 T-pose，当然这个只是一般来说只是这两个 reference pose 的问题了。当然这里有一个非常重要的问题，就是说比如我这两个角色，一个是 T-pose，一个是 A-pose，对吧？那如果说我让这两个角色同时把两个胳膊向上旋转 90 度，那会发生什么事情呢？

我们看到同样旋转了 90 度，对于 T-pose 来说，它其实是做出了这样一个类似于欢呼的姿势；那对于 A-pose 来说，因为他开始的时候手臂垂得更低一点，所以说向上旋转 90 度之后，它会变成这样一个姿势，就没有前面 T-pose 举得高。或者反过来，比如我让他们同时向下旋转 90 度，那对于 T-pose 来说是一个比较正常的姿势，而对于 A-pose 来说它其实会旋转的感觉明显过头了，变成另外一个姿势了。

这样就是说对于这个参考姿势，其实对于我们用相同的姿态参数，就是比如每个关节旋转多少度，用相同的这一套姿态参数放在不同的 reference pose 下，比如放在 T-pose 下或者放在 A-pose 下，它所能呈现出来的这样一个姿态其实是不同的。

比如这是一个我找了一个非常简单的例子，其实左边这是一个 T-pose，右边是一个 A-pose，但是我把 T-pose 的每个关键旋转让它去放在右边那个 A-pose 上去进行播放。你可以看到对于同一个动作，对于这个 T-pose 看起来是一个正常的人在走路，那 A-pose 这个人感觉是稍微有点不大正常，手总是会放开。所以这是一个非常典型的 A-pose 和 T-pose 的一个问题。

所以说这里我们需要解决什么问题？如果说我们想要用一些，比如我们的角色就是 A-pose 建好的，它就是按照 A-pose 绑定的，但是我们的动作，比如我们动捕数据，它是一个 T-pose 采的数据，那我们该怎么把一个 T-pose 的数据映射到 A-pose，让 A-pose 的这个角色能够使用 T-pose 的数据呢？

当然这就是一个所谓 retargeting 问题。再讲具体一点，就说比如我有一个骨骼，一个 skeleton，它的 pose 它是用 A-pose 来定义的，也就是它所有的旋转都等于 0 的时候，它是这样一个姿态。然后在这个骨骼上我摆了一个姿势，是这样一个姿势，然后我假设这里边每一个关节的旋转分别旋转了一个角度，这个角度我总体来说记为一个 $R_A$，它是已知的，那这个动作可能是来自于我们的动捕数据。

那另外一个，比如我有一个 A-pose，这是我绑定好的角色，那我也想让这个角色它也做出同样的姿势。那我这个旋转对应的是 $R_B$。那对这个情况来说，$R_B$ 我是不知道的，我是想要计算的。

那接下来的问题就是说，我能不能从 $R_A$ 算出 $R_B$ 等于多少？那这个就是 motion retargeting 问题，就是我们的动作重定向的一个非常基本的问题。

当然这个是前提条件是说什么呢？就是我们只考虑关节旋转带来的问题。当然动作重定向还有很多其他内容，比如关节的长度变化，那可能会带来一些比如穿模、动作奇怪的这些问题，那个其实不是很好解决的，那个不是我们今天会解决的问题。

回到这个问题，这件事情该怎么做？

我们可以从一个非常简单的任务开始来看。比如我现在有两个物体，两个刚体，两个物体。那一开始的时候，这两个物体其实开始它的初始状态是不一样的。就是说我们认为比如这个物体，它是在旋转等于 0 的时候，它是表现出一个横放的一个姿态；然后这个物体，它一开始的时候是斜着放的，然后它也是旋转等于 0 的状态。这两个物体我在创建的时候，就创建成这两个姿势，然后他们俩都是在这个旋转等于 0 的时候是表现出这样姿势。

那如果这个 A 物体，因为这两个物体如果它大小相同的话，那实际上我们总是可以把 A 物体按照某一个方式旋转，让它跟 B 物体是方向相同的，就是能够重合的。那假如说这个旋转是 $R_{A \to B}$，就用这样一个旋转矩阵来表示。也就是说这个 A 这样一个物体，当它的旋转是 $R_{A \to B}$ 的时候，它所呈现的这个形状是跟 B 完全重合的，朝向和位置其实是完全一样的。

我们可以稍微简记一下，就是 $R_{A \to B}$ 是把这个物体旋转到 B 这样一个位置的时候，它所对应的朝向。那特别注意到这个 B 本身它的旋转是 0，所以说这是两个不同的物体。

那接下来，比如我有一个目标的一个姿势、目标的一个朝向，我把这个 A 物体经过某一个旋转、已知的旋转 $R_A$，旋转到了这样一个姿势。

那接下来我想问的是说，我该如何旋转 B 物体，使得 B 物体能够达到这个姿势？

其实这就是一个 retargeting 问题，当然这是针对一个物体来做的。

那这个过程怎么做呢？其实我们知道从 A 物体到 B 物体，让它旋转到跟 B 物体重合，是需要做一个 $R_{A \to B}$ 的这样一个旋转的。那反过来，如果我想把 B 旋转到跟 A 物体重合，那我需要做什么旋转？那其实非常简单，我们就直接把 $R_{A \to B}$ 的这个旋转把它做一次逆变换就可以做了。当然这个逆变换：

$$R_{B \to A} = R_{A \to B}^T$$

因为旋转矩阵，逆就是它的转置。

那我做完第一步之后，那这个时候 B 物体的旋转就跟 A 物体重合了。那接下来，因为我们目标这个姿态是 A 物体这样一个姿态通过 $R_A$ 旋转得到的，所以说为了把 B 物体旋转成这个姿势，我们首先把 B 物体旋转得跟 A 重合，然后接下来再用 A 物体对应的一个旋转去旋转这个时候的 B 物体。

那总的旋转应该等于多少呢？它其实是做了两次旋转：B 物体首先做了一次 $B \to A$ 的旋转，然后才做了一次 $R_A$ 的旋转。回想一下我们第二节课讲的关于旋转的组合的这样一个过程，我们可以知道为了把 B 物体旋转到这样一个姿势，那它所需要达到的旋转是什么呢？它的旋转是 $R_A$——后旋转应该放在前面——然后乘上 $R_{A \to B}$ 的转置：

$$R_B = R_A R_{A \to B}^T$$

$R_{A \to B}$ 的转置其实也就是往回走的这样旋转。

那这个其实就是我们想要的关系。就是说当 A 物体和 B 物体只有单个物体的时候，我们知道 A 物体到某一个姿态的旋转之后，那 B 物体到这个姿态的旋转是可以通过这样一个公式直接得到的。

前面我们其实提到的是一个单个物体，那如果说我们这不是一个单个物体，而是一个两个关节的这样一个链条或者一个角色。为了标记简单，我们假设前面这个是一个父关节，前面可能是固定不动的，也许是动的，这是无所谓的，就是它是一个父关节；然后右边这个关节是一个子关节。

那同样地 B 它也是一个两个关节的、跟 A 是完全相同的一个角色，这么一个链条。那当然它在初始化所有的旋转等于 0 的时候，它跟 B 的位置是不一样的，它是斜着的，然后 A 是直着的。那同样地一个是父节点，用 $p_i$ 表示，一个是子节点用 $i$ 表示。

那我们进一步地假设，假设我们是知道的，我们是知道从 A 物体的这个子关节，它的全局的朝向跟 B 物体的作为子关节的这个关节，它的全局朝向之间的差是：

$$Q_{i, A \to B}$$

这样的一个矩阵表示。

那父关节我们在全局的表示之下，它也是：

$$Q_{p_i, A \to B}$$

这是我们的假设，这是我们知道的部分。

然后另外，比如我有一个目标的一个姿态，从这个 A 物体旋转到目标的姿态，我分别需要把 $p$ 的朝向变成 $R_{p, A}$，然后 $p_i$ 和 $p$ 之间的这个关节它的旋转应该是 $R_{i, A}$，这是我们知道的。

那接下来实际上我们可以很容易地计算出，因为我们知道这两个关节的旋转，所以我们可以很容易地计算出这两个关节在这个姿态下的朝向应该是多少，分别是 $Q_{p, A}$，是这样算出来的；然后 $Q_{i, A}$，就是子关节，它应该是父关节的朝向乘以关节的旋转，得到了这样一个关系。

那接下来我们从另外一个方面，比如从 B 如何能够得到这个关节的旋转。

那首先父关节，因为这是我们要求的，假如说我们知道了父关节它的旋转应该是 $R_{p_i, B}$，那子关节的旋转应该是 $R_{i, B}$，这两个量是我们要求的量。

那假如说我们这两个东西在知道的情况下，那我们其实可以算出来在这个从 B 看来，这样一个姿势里面父关节的朝向应该是 $R_{p_i, B}$，然后子关节相对于 B 链条的 $i$，它的朝向应该是 $Q_{i, B}$，它其实应该是父关节的朝向乘以关节的旋转。

所以整个这里边，这一部分是知道的，这个也是知道的，然后 $R_A$ 是知道的，所以说整个 $R_A$ 的这个朝向我知道了；然后 $R_B$ 这边的朝向和旋转我们都是不知道的，是我们要求得的。

那我们应该怎么求呢？其实回想一下我们刚才在讲单个刚体的旋转的时候，我们知道 B 的朝向——因为单个刚体来说我们没有旋转，我们每个刚体的旋转就是它的朝向——它的朝向等于 A 的朝向乘以 A 和 B 的朝向的差的逆，这是我们对于单个物体、单个链条的时候它的计算方式。

那同样地，其实前面我们把它所有的关节的旋转都转成关节的朝向之后，那我们其实可以把每个关节的父关节和子关节分别单独去处理。对于父关节来说，我这个变换其实是可以写成父关节在 A 下面的这个朝向，乘以两个链条它们之间父关节的朝向的差；那子关节也是类似的，我们可以做出这样的计算。

那接下来，实际上我们其实这个时候已经知道了在骨骼 B 这样一个条件下，它的旋转旋转到同样的一个姿势的情况下的父关节的朝向和子关节的朝向我们都知道了。那这个时候我们想要去求这个 B 的中间这个关节、子关节的旋转，那么它应该是父关节的朝向的逆乘以子关节的朝向，那得到应该是指关节的旋转。

那我们其实可以把它展开，因为这里我得到了它们两个用 A 和 $A \to B$ 表示的一个形式，那我们可以把它们分别展开：

$$R_{i, B} = Q_{p_i, B}^T Q_{i, B} = (Q_{p_i, A} Q_{p_i, A \to B}^T)^T (Q_{i, A} Q_{i, A \to B}^T) = Q_{p_i, A \to B} Q_{p_i, A}^T Q_{i, A} Q_{i, A \to B}^T$$

注意到中间这一块，中间这里其实是 A 骨骼的父关节朝向和子关节朝向，所以说这两个东西其实是可以算出来，它刚好是等于骨骼 A 里面它所对应的关节的旋转：

$$Q_{p_i, A}^T Q_{i, A} = R_{i, A}$$

其实就回到我们刚才这里面，就是说实际上对于这两个 A 骨骼和 B 骨骼，就是 A 链条和 B 链条，如果说我们知道它们每一个链条的节点，父节点和子节点分别在全局下的旋转的偏移，以及 A 旋转到某一个姿势下需要做的这个旋转，那么 B 旋转到同样的姿势，那么它这个关节所需要做的旋转其实是可以通过这样的一个表达能够算出来：

$$R_{i, B} = Q_{p_i, A \to B} R_{i, A} Q_{i, A \to B}^T$$

就是父节点的全局偏移乘以子节点在 A 下面的旋转，然后再乘以子节点的全局偏移的转置，这样一个形式。

当然这里对于父节点来说，因为父节点它没有父节点了，所以说前面这个是没有的。所以说对于父节点的计算，我们只需要考虑后面这一半就可以了。

这其实就是两个链条，两个关节的链条，我们其实可以通过这样的方式实现两个骨骼旋转 T-pose 和 A-pose，或者是 A-pose 和 B-pose 之间的动作的迁移。

类似地，如果说我们把它再复杂一点，其实两个链条再泛化其实就是我们正常的一个角色的迁移了。比如还是回到我们刚才那个问题，我们有一个 A 角色它是 T-pose，有一个 B 角色它是一个 A-pose，然后 A 角色做出这样一个姿势的时候它需要做 $R_A$ 的旋转，然后 B 角色做出同样的姿势它需要做 $R_B$ 的旋转，这两个旋转一般是不同的。

那 $R_B$ 跟 $R_A$ 是什么关系？其实根据刚才我们的两个链条的一个旋转关系，其实我们可以很容易地得到：对于任何一个关节，就内部的关节，我们可以知道摆到同一个 pose 的情况下，B 的角色它每一个关节所需要的旋转和 A 的角色每一个关节所需要的旋转有这样一个关系：

$$R_{i, B} = Q_{p_i, A \to B} R_{i, A} Q_{i, A \to B}^T$$

那这个就是我们的 motion retargeting 一个最基本的一个旋转关系。

所以说其实你不需要用 IK，不需要用什么特别奇怪的一些不知道什么的方法。其实如果说只是关节 T-pose 和 A-pose 之间的转换的话，我们可以很容易地通过这种方式来进行迁移。

当然还有一些其他的问题，就是说比如这两个 pose，比如 A 角色和 B 角色如果它的骨骼数量不一样该怎么办？那这个其实是稍微复杂一点，主要是说骨骼数量不一样的情况下，我们需要决定我们把哪一个关节的旋转映射到另外一个角色的哪一个关节上。这个其实是经常出现的问题。而且有些时候不一定是骨骼数量不一样，可能骨骼名字都不一样，所以你可能需要手动做一些映射。当然好处是什么呢？如果说我们这两个角色……

刚才我们说到，其实我们要做的 retargeting，一方面是说每一个关节，我们需要把名字——比如一个角色的关节多，另外一个关节少，或者反过来，或者是名字不一样——通常来说需要做一些手动的映射。当然对于人来说，比如都是人形角色，我们可以期待他们俩肯定都会有相同数量的腿，腿上有相同数量的关节，然后胳膊上有相同数量的关节，所以我们总是一定程度上可以建立好这个映射。建立好映射之后，我们进一步去处理 A-pose 和 T-pose 之间的关系，或者说 T-pose 和一个奇形怪状的 pose 之间的关系，那我们就可以比较不错地让一个动作能够在一个角色的身上展示出来。

前面主要是我们对前向运动学的一些回顾，当然我们稍微补充了点内容，就是 retargeting。

接下来回顾一下逆向运动学的部分。逆向运动学其实稍微比较难一点，因为通常来说，逆向问题总归会比前向问题难一些。

前面也提到了逆向运动学的问题，它其实可以表示成什么呢？我们通过前向运动学可以计算出每一个关节的位置，特别是可以计算出末端节点的位置。末端节点不一定是最后一个关节，可能是中间的某一个关节，只要是链条上的最后一个点，就认为它是末端节点。整个计算过程总归可以表达成一个函数，具体形式不用管，符号上把它表示成一个函数 $x = f(\theta)$。$\theta$ 其实就是每一个关节的旋转表示，可能是欧拉角、轴角，或者是四元数，这其实无所谓。

对于末端关节来说有一个目标位置 $\tilde{x}$（x tilde）。想要把末端点挪到目标位置的时候，需要计算对应的 $\theta$ 应该是多少。实际上是在求解一个方程，因为最终目标是想要 $f(\theta)$ 的位置跟 $\tilde{x}$ 相同，相当于去求解方程：

$$\tilde{x} - f(\theta) = 0$$

上节课也提到，这个方程可以等价地写成一个优化问题，形式上写成类似的形式。群里也有同学问，为什么这里是 $\frac{1}{2}$，为什么这里是平方？这完全是为了后面求导方便，求导之后 $\frac{1}{2}$ 就可以直接被消掉，否则总是带着 2 很麻烦。

这个优化问题有好多种不同的解法，其中一种解法就是所谓的循环坐标下降方法（Cyclic Coordinate Descent, CCD）。因为这里的坐标 $\theta$ 是一个向量，比如对于这个关节来说，至少有四个参数需要优化。对于每一个参数来说，循环坐标下降做法就是分别沿着每一个参数所对应的坐标去做搜索；搜索到某一个值的时候，这个值能够把沿着这个坐标轴上的所有目标函数的值变到最小，就认为下一次迭代从这个点开始。每一步都在解一个优化问题，只不过这个优化问题是一个只优化该函数的一个变量的优化问题，所以它是一个循环坐标下降的方法。

表现在 IK 问题里面，上节课也提到过，其实是一个非常简单的、有点像启发式算法的过程。每次依次旋转关节，按照一个确定的顺序。每次比如旋转关节 3 的时候，会把关节 3 旋转，使得末端节点和目标点的连线方向跟关节 3 和目标点的连线方向相同。依次类推，关节 2 同样做旋转，关节 1 做旋转，关节 0 做旋转，直到旋转到足够近。

为什么要做这样的旋转，或者为什么要把末端节点旋转到跟 3 到 $x$ 之间的向量平行或者重合呢？主要是因为本质上是在求解一个优化问题，这个优化问题本质上是想让 4 这个节点跟 $x$ 尽可能近。在旋转 3 的时候，如果让 3 旋转一圈，4 所划过的空间就是一个圆周或者一个圆球。圆周上离 $x$ 最近的点，肯定是 3 跟 $x$ 的连线跟圆周的交点。具体证明大家可以自己去证，很容易证明。这也是为什么要把 4 旋转到这个点，因为这个点其实是这个函数在只优化 3 的时候的最小值点。

如果有关节不是旋转关节，比如还是一个很像的链条，但是关节 2 不再是一个旋转的关节，不能转，但是可以伸长。对于这样一个关节来说，该怎么做 CCD 呢？

做第一次坐标下降是没有问题的，因为 3 是一个可旋转的关节，所以依然把 3 旋转到重合于连线的方向上。接下来 2 该怎么办？关节 2 现在是一个可以伸长的关节。伸长关节类似于打气筒，打气筒就是一个可以伸长的关节，它不能旋转，不能沿着打气筒的位置旋转。假设 2-3 之间是一个打气筒，在打气的过程中去把伸长缩短。在这个过程中你会发现，随着 3、4 关节沿着 2 的方向去移动，4 所走过的这条线，其实应该是跟 2-3 关节方向平行的一条直线。接下来按照 CCD 的基本算法，目标是想要去找到一个长度（对 2 来说它的参数就是伸长的量），找到这么一个长度，使得 4 的位置跟 $x$ 尽可能近。

问题就来了：离 $x$ 最近的点在哪里？

前面也说了，如果 3、4 沿着 2 的方向随便移动，会形成一条直线。离它最近的点，应该是外面这个点到这条直线的距离，具体是这个点到直线的垂线的距离。实际上可以沿着 $x$ 向 2-3 的方向做一条垂线，这条垂线上的点跟 4 能够达到的点，就应该是对应的极值点。也就是说会把 2-3 伸长，直到伸到 4 跟垂线重合的时候，对应的就是极值点。所以实际上如果你知道了坐标循环下降本质上就是一个优化问题，对于更加奇形怪状的关节，其实可以用同样的思路去分析，然后找到一个合适的解。

类似地，剩下的关节就是旋转关节，可以继续做这样的循环，继续拉长、旋转。这就是循环坐标下降。

当然前面也提到了，循环坐标下降不是一个非常快的方法。想要更快一点，需要用一些雅可比矩阵的方法。雅可比矩阵需要用到的是：前向运动学把它写成一个函数之后，它对每一个参数的导数。因为 $f$ 本身是一个三维向量，是一个高维的函数，这个函数对它每一维的参数做偏导，把每一个偏导写成一列，写成矩阵之后，这个矩阵叫做雅可比矩阵。如果大家对这件事情搞不清楚的话，建议可以看一下大一下半年线性代数或有关多元微积分的部分，那里会比较详细地讲这个导数到底是什么。

在知道雅可比矩阵之后，其实可以做两种不同的方式来进行迭代：

一种方式是雅可比转置的方式（Jacobian Transpose）。实际上是说，知道当前末端点位置和目标点位置的偏差，比如记成 $\Delta$。雅可比转置的方法，实际上用 $\Delta$ 乘以雅可比矩阵的转置，给出了一个方向，这个方向是更新参数 $\theta$ 的方向。

另外一种方式就是逆雅可比矩阵（Jacobian Inverse），或者用伪逆（Pseudo-inverse）。其实跟前面的形式非常相近，唯一的区别是这里不再是转置，而是一个雅可比矩阵的伪逆。上节课也提到了伪逆，为什么要做伪逆呢？因为雅可比矩阵不是方阵。对于不是方阵的情况，只能去算它的伪逆。

这里非常重要的就是雅可比矩阵怎么算。前面也提到了，很简便的方法是用 PyTorch 实现一遍 forward kinematics，实现一遍 FK，对那个方程求导就得到了雅可比矩阵。如果不用这种方式，其实只是对一些特定的问题，比如说所有关节都是 hinge joint，可以通过叉乘的方式来计算雅可比矩阵里的每一列。雅可比矩阵的每一列对应的是某其中一个关节的旋转参数。如果所有都是 hinge joint 的话，其实就是一个 hinge joint 的旋转角度。这个时候，这一列的数值应该是 hinge joint 这个旋转关节的旋转轴，叉乘关节端点到末端点的位移向量：

$$J_i = \omega_i \times (x - p_i)$$

这是每一列，需要对每一列分别算一个计算。

上节课有一个遗留问题：如果不是一个 hinge joint，而是一个 ball joint，该怎么办？

首先 ball joint 来说，一个 ball 其实可以有三个自由度旋转。对应的话，需要用三个参数来表示它，本质上就是一个正常的旋转表示。如果把这个旋转表示成一个欧拉角，欧拉角是三个旋转的叠加，欧拉角可以等价地认为它是三个 hinge joint 级联，依次连接，但是它们连接之间的长度是 0，所以它们三个点在同一个位置。对应的雅可比矩阵应该是对应的三列，每一列分别对应于欧拉角三个角的偏导数。

每一列应该是轴乘以 $r$。对于这样一个欧拉角，假设先不管 $z$ 轴，只管 $R_x \times R_y$，它对应的是什么旋转呢？先沿着实心的坐标轴沿着 $x$ 做了旋转，$x$ 轴不会变，那 $y$ 轴和 $z$ 轴会稍微旋转一点，转到这样一个角度上。然后再做 $y$ 的旋转，它是沿着旋转之后的坐标轴去旋转。其实是这样去表示的，这是一个 intrinsic 的表示。总是可以理解成这样的旋转：$R_x \times R_y$，先沿着没有变过的 $x$ 轴旋转，然后再沿着变过的 $y$ 轴旋转，做了两次旋转。

对于第一次旋转来说，对于 $x$ 的参数来说，如果把它假设成一个 hinge joint，它的旋转轴应该就是世界坐标系的 $x$ 轴。在后面做 $y$ 旋转，它的旋转轴是哪一个？旋转的是局部坐标系的 $y$ 轴。局部坐标系的 $y$ 轴实际上是通过 $x$ 轴旋转之后得到的，所以它对应的是世界坐标系的 $R_x \cdot \mathbf{y}$ 这样一个轴。

在此之外，因为这不是第一个关节，不是根关节，所以它的父关节本身也带有一些旋转。一开始 $x$ 的旋转是在父关节旋转之后得到的，所以它在世界坐标系的表示应该是父关节的旋转朝向乘以这个轴，得到世界坐标系的轴。对应的 $y$ 在最前面还要再乘一个朝向。这就回到了上节课所得到的结论：为什么三个轴用这样的方式，实际是用欧拉角得到的结果。

这里还有一个非常自然的问题：旋转的参数表示有好几种，其中一种是轴角表示。轴角表示好像非常自然，因为前面一直说的都是轴，轴的方向叉乘距离。如果把它表示成轴角表示，雅可比矩阵是不是也可以这么算呢？

结论是不可以。主要是因为对于轴角表示来说，参数是轴角表示的三个变量。这三个变量在改变的时候，同时改变了旋转角度，并且改变了旋转轴的方向，要理解这件事情。如果用轴角表示一个旋转，用轴角表示来参数化一个 ball joint 的话，它的雅可比矩阵计算相对来说要复杂很多，公式就不写了，大家只要知道这个东西复杂很多。如果真的需要计算的话，很建议用 PyTorch 自己写一遍，然后用 PyTorch 来算，可能还更准确一点，更不容易出错。

回到上节课讲的内容。上节课放了一个视频，看起来非常 fancy 的一个 character rig，可以随便去调 character，上面有很多很多不同的关节，可以去改变其中的关节来调关键的姿势。这里就是前面提到的所谓的 Character IK。

对于一个链条来说，可能就一个末端点，就可以解决问题了。但是对于一个角色来说，它的关节很多，而且实际上可能同时会要求，比如两个脚不要动，身体动，手可以动也可以不动，类似这样子。每一条要求其实都会对应于一个优化问题。总的姿势其实是所有这些子优化问题的总和，最后可以加一个正则项来避免旋转过多。建好这个优化问题之后，自然可以算雅可比矩阵，然后用雅可比矩阵去做 Jacobian Transpose 也好，做 Jacobian Inverse 也好，都是可以做的。

实际上还有一些其他的方式，更加 heuristic、更加启发式的方法。通常来讲，角色抽象来说是由若干个链条来构成的，每次都是从根节点开始。比如要移动手的位置，要求根节点不要发生变化，其实可以只把这当成一根链条。前面讲 IK 的时候一直都是用一根链条来做展示的，从根节点开始做这一条一根链条，非常简单，前面的 IK 算法都可以直接拿来用，包括怎么算雅可比矩阵也可以用上。

另外一个问题稍微复杂一点：如果做链条移动的时候，做 IK 的时候想让手移动到这里来，但是要求脚不要动。这个时候其实从脚开始，从脚到小腿、大腿，到根关节，然后到躯干，再到手腕，这一整条是一个链条。这个链条本身其实也是可以去使用 IK 的。

这里需要注意一个什么问题呢？这个链条跟刚才前面那个问题不同点在哪？在于它穿过了根节点。一般的角色姿态的表达来说，是给出根节点的位置和朝向，加上每一个关节的旋转。这里的根节点是比较特殊的。

为了做 IK，大概可以分两步走、三步走：

首先先不管根节点，就用链条上的每一个关节先去算一遍 IK。IK 会给出每个关节的旋转。给出每个关节的旋转之后，再做一遍 FK。实际上做 IK 的时候已经在不断做 FK 了，所以实际上就用最后一次 FK 的结果。FK 结果里面其他关节无所谓，但是根关节的位置是比较重要的。假设这个点不动，沿着这个链条做一次 FK，会算出新的根节点的位置。然后把根节点位置设置成算 IK 得到的这个位置，朝向也是算 IK 得到的朝向。

接下来还需要做一件事：从这个关节出发向上走，比如膝盖这个关节算出来的旋转，其实是从子关节看来去旋转父关节的一个旋转。但实际上在参数化的时候，是从根节点开始，从胯关节开始，实际上要求的是从父节点看来去旋转子节点的旋转。这两个刚好逆过来了。所以实际上从这个节点出发到上面去，算出的这三个关节的旋转，当把它转化成从 root 出发的正常的姿态表示的时候，这三个关节的旋转需要求反。因为对于脚来说其实是旋转了父节点，而对于根节点来说旋转的是子节点，它俩是相反的。这个其实也是需要注意的地方。

类似地，如果有两个 constraint，如果还是刚才那个问题，前面是移动手，另外一个问题就是移动 root。前面视频里面其实很多这样的例子：两个脚不动，挪动一下躯干，其实腿会相应地发生变化，然后躯干位置发生移动，而脚位置是不变的。实际上这个问题跟前一个问题是一样的，其实比前一个问题还要再简单一点。因为前面的问题其实是要算到手，这个问题只要算到 root 就可以了，所以本质上它是同样的方法可以解决的。

另外一个稍微复杂一点的问题：如果同时要求两个脚都不动，然后去移动根节点或者移动上面的关节（比如头）。这个时候该怎么办呢？

这就稍微复杂一点了，有两种方式：

一种方式是构造一个更加复杂、更加通用的优化问题，继续算雅可比矩阵，算雅可比矩阵的转置之类去算优化。

另外一种方式也是启发式的：先从左脚开始算这个链条，把右脚先忽略掉，它怎么动先不管。这个链条移动完之后，这时候发现左脚已经偏离原来的位置了，再把它拽回来。大概是这么一个 heuristic 的方法，其实也可以实现类似的效果。

实际上包括前面视频里面的角色模型，它的 IK 实际上是多个 IK 的一个总和。通常来讲，这个角色可能会建很多的 IK，比如从根节点出发到两个脚分别是两个 IK 的链条，到两个手是两个 IK 链条，到头是一个 IK 链条，可能还有很多其他复杂的骨骼链条系统。每次用户要去挪动根节点的时候，其实可能是同时去让所有这些链条都启用，然后来实现不要出现移动的问题，在计算过程中可以同时保证每个手的位置或者脚的位置不变。如果只移动脚的时候，可能其他的链条是不会被启动的，这样的话只会通过求解这一个 IK 链条来实现对脚的移动。在这个过程中，比如有些链条可能是不启用的，比如可能用 IK 来移动手，可能会带动上半身发生一些移动。这个过程中实际上其他链条……
