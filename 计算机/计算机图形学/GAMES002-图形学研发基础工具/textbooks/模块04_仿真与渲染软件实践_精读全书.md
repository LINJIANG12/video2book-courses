## 三维处理软件：几何处理、渲染与重建的工具地图
> 对应块：BLK13 | 覆盖分集：P08 | 块标题（分集名）：《三维处理软件》

这是 GAMES002 的倒数第二节课，按大纲的安排，今天讲三维处理的工具。

什么叫三维处理工具？指的是图形学里那些专门用来做几何处理、做渲染、做重建的软件。它们都围着三维数据打转，但真到用的时候你会发现，它们各管一摊：有的只把"看清点云"这一件事做好，有的只管把网格简化到你能接受的面片数。所以今天的讲法不是报菜名，而是按几何处理、渲染、重建这三摊，把每一摊里最常用、最有代表性的工具拉出来，讲清它们各自擅长什么、彼此怎么衔接。

### 三个板块，两种形态

今天的内容分三块推进：先讲基本的几何处理软件，CloudCompare、MeshLab 这些比较知名的；再讲怎么通过调库的方式做几何处理，比如用 Open3D 这个代码库；接着是渲染工具，Blender 或者 KeyShot 这一类；最后是几何重建工具，最常用的 COLMAP 和商用的 ContextCapture。三块讲完，最后布置一次作业。

| 板块 | 代表工具 | 要解决的问题 |
| :--- | :--- | :--- |
| 几何处理 | CloudCompare、MeshLab、Open3D | 点云的变换与过滤、网格的简化与编辑、结果的查看 |
| 渲染 | Blender、Houdini、KeyShot、UE4、Unity | 给已经成形的几何加上材质与光照，出图 |
| 几何重建 | COLMAP、ContextCapture、Metashape、Meshroom | 从一组照片反推出三维几何 |

表格只是先把名字摆齐，后面一个个说它们的分寸在哪。

有一条线索贯穿今天的所有工具：它们的形态其实只有两种，要么是有图形界面的软件，要么是能嵌进代码的库。CloudCompare、MeshLab、Blender 是软件，重心在界面；Open3D 是库，没有可交互的界面，只有 API；PyMeshLab 是 MeshLab 的 Python 绑定，等于把软件变成了库；COLMAP 和 ContextCapture 两头都占，既有界面又有 Python API。后面你会发现，选工具时的很多纠结，本质上就是在"界面好上手"和"代码能批量"之间做取舍。

### CloudCompare：先把点云看清楚

名字已经把定位说透了——CloudCompare 是做点云处理的。它也支持一些额外功能，比如网格处理，但主力始终是对 3D 点云做几何处理：点云的变换、点云的过滤，都在它的射程之内。

它是开源软件，网上能找到 C++ 源码。这句话对写 C++ 程序的人有实际意义：你可以直接调用它的一些函数，不必被它的界面框死。

作为一个软件，它自带图形化界面，而这个界面正是它最省事的地方。它有一系列插件：给了点云之后估计法向、做点云过滤（比如把异常点剔掉）、做点云分割，都有现成的插件可用。插件在 CloudCompare 里是非常通用的机制，既有一批标准插件，也支持自定义插件，这些插件合起来构成了它的扩展功能。

最基础的功能是看：点云、坐标轴、比例尺，都在那个 3D 查看界面里。界面的左侧和上方排着大量按钮，点云编辑与点云处理都从这里进；具体每个按键做什么，去 CloudCompare 的主页上查最准。渲染这一层它基于 OpenGL，底层调的是 C++ 的处理库，我印象里是 PCL。

> **定义**：点云是一堆带坐标的点，点与点之间没有连接关系；三角网格额外记录了哪些点连成哪个面。所以处理点云的算法和处理网格的算法不是一回事，这也是为什么看完点云还要换一个工具。

### MeshLab：能上手改的网格工作台

CloudCompare 基本上只能做点云的处理和渲染。但我们平时更通用的一种数据格式是三角网格，也就是 MeshLab 名字里的那个 Mesh。所以 MeshLab 比 CloudCompare 更通用：点云它能处理，三角网格也能处理，而功能的重心落在网格上。它同样是开源软件，用 C++ 编写。

除了图形化界面，MeshLab 还提供 Python API——你可以在 Python 代码里调用它的 API 完成想要的功能，不必在界面上手点。网格算法它支持得很全，网格简化、凸包计算这些都有，完整的清单在主页的官方文档里。

界面上，网格可以直接打开显示，比如 Stanford Bunny。顶点能单独显示出来，三角面片也能以 wireframe 的形式叠加，每个面是怎么连的一目了然。更要紧的是它允许直接在界面里编辑 3D 数据：框选一片网格，再做剔除或者别的变换。被选中的部分显示为红色三角面片，动过哪些面看得很清楚。

> **提示**：为什么界面编辑这件事值得单说？因为有些交互操作靠纯代码很难表达——比如"把这一块看着多余的面删掉"，你想用代码描述"这一块"，先得写一堆选择逻辑；在界面上点两下就完事了。MeshLab 作为三维可视化查看软件，最主要的价值正在这里。

### PyMeshLab：把界面操作录成脚本

PyMeshLab 是 MeshLab 的 Python 绑定，pip 或者 conda 装一下就能用。装好之后直接调 MeshLab 内置的函数：载入网格（load mesh）、计算凸包、保存当前网格，都是函数调用的形式。它支持哪些 API、每个 API 能干什么，PyMeshLab 的文档列得很全。

它有一个别的工具少见的特殊功能：可以定义过滤器。做法是先生成一个 MeshSet，在上面串一系列操作——比如对坐标做拉普拉斯平滑——最后用 `save_filter_script` 把这一串操作保存成本地文件。这个文件记的不是处理结果，而是操作序列本身。下次想复刻同样的处理，把文件载进来，对新的输入网格执行同一串操作就行。

> **结论**：MeshLab 兼顾了图形化界面与编程化管理方式。先在界面里验证、试参数，验证通了把操作录成脚本，再拿去批量处理几何单元。这个"先手动、后脚本"的路子，比纯软件和纯库都更省事。

### Open3D：几何处理搬进代码

严格来说，Open3D 不能算几何处理软件——它本身没有图形化交互界面，是一套代码库。但它比 MeshLab 更通用，3D 几何处理的各个方面基本都覆盖到了。

它本身是用 C++ 编写的代码库，同时提供 Python 绑定，从 Python 里调用非常容易。点云处理、网格处理，以及射线求交这类计算几何算法，都在它的支持范围里。官方文档写得很清楚，这对接手一个陌生库的人来说是最实际的门槛。

它也有可视化功能，但用法和前面几个软件完全不同：前面是"打开软件，在界面里操作"；Open3D 是"调用代码，让代码给你开一个窗口"，然后在窗口里看结果。

#### 官方示例怎么组织

文档里提供了大量 Python 示例，每个功能都对应一个 `.py` 文件和一段示例代码，照着读、照着改就行。常翻的几类：处理相机、处理相机轨迹、点云与网格处理（在 `geometry` 模块里）、点云和网格数据的读取与保存（在 `io` 模块里），以及常用的可视化功能。

#### 和 MeshLab 的分工

平时这两个工具通常是配合着用的，理由很实际：MeshLab 本质上是个软件，在 Python 代码里调它相对重；Open3D 是库，API 轻便，适合直接嵌进代码里做点云处理或者网格简化。

于是几何处理工具就自然分成两类：一类注重可视化，像 MeshLab，适合在开发初期快速验证——方法对不对、结果能不能用，看一眼就有数；确定方法可用之后，再换 Open3D 这类库，把几何处理的逻辑整合进代码里，批量跑。

```text
MeshLab（图形界面）
    │  手动验证：结果对不对、方法可不可行
    ▼
Open3D（Python 代码）
    │  批量处理、整合进工程
    ▼
最终数据
```

读图：两类工具不是替代关系，而是先后关系——验证阶段用界面换效率，落地阶段用代码换规模。

### 渲染：Blender 与它的同行

#### Blender：功能多到必须挑着学

渲染这块最主要的是 Blender。它在渲染里是非常重要的工具，几乎什么内容都能在 Blender 里渲出来。它本身是开源软件，脚本层用 Python，既有图形化界面，也提供 Python API。

界面是一个非常复杂的系统，各种功能都支持。和偏轻量的 MeshLab 比，Blender 在渲染工具里属于工业级，上手难度高很多：支持的功能太多、系统太复杂，需要花不少时间才摸得清用法。官方提供了中文手册，官方教程也能在上面找到；网上的教程更丰富——GitHub 上有专门做学术渲染的库，比如 BlenderToolbox，提供了丰富的示例脚本；知乎、YouTube 以及 B 站上也有许多博主做的优质教程。

> **提示**：正因为 Blender 复杂，不要抱着"从第一页读到最后一页"的心态去学它。按自己眼下要做的效果去检索对应教程，缺什么补什么，是唯一划算的路径。

#### Houdini、KeyShot 与综合引擎

除了 Blender，渲染还有几个不同的方向：

- Houdini：非常著名的工具，主要用于电影特效和游戏特效制作，门槛相对更高；
- KeyShot：和偏光栅化渲染的 Blender 不同，它更注重真实感渲染，采用光线追踪算法，是一款重量级的商业软件；
- UE4、Unity：把渲染模块集成进来的综合引擎，不只是渲染器。

> **定义**：光栅化是把几何投影到屏幕上、逐片元着色再靠深度测试定前后，所以快；光线追踪是沿着光线的传播路径求解，物理上更接近真实成像，真实感更好，代价也更高。前面说 Blender 偏光栅化、KeyShot 走光追，差别就在这条成像路线上。

有同学问，有没有网页端的光线追踪渲染工具。这个我还真不了解。网页端的计算能力现在其实非常有限，想在网页端做光追，对 WebGL 来说不太实际。后面 Chrome 那边搞了 WebGPU 的支持，说不定将来能支持网页端的光追——我本身不是做渲染的，所以这块说不太准。

### 三维重建：从一组照片里长出一个模型

我自己是做三维重建的，所以这第三块讲得细一些，它也正好是我最熟悉的领域。

三维重建，指的是从一系列照片里恢复出 3D 模型的算法。先分清数据来源：3D 模型要么来自 CAD 手工建模、艺术家创作，要么是用算法从真实世界里恢复——后者又分雷达扫描和基于图像的重建两条路。这里讲的重建工具，专指从图像恢复几何的那一支：对着一个物体或一片场景拍一组照片，把照片喂给算法，算法自动生成所拍场景的三维模型。

#### COLMAP：位姿、稀疏与稠密

COLMAP 是重建里最重要的工具之一，它源自一篇学术论文所附带的工具。

它的功能是一条环环相扣的链：

1. 位姿估计：确定每张图片拍摄时的相机姿态。这是后续一切的基础——不知道相机在哪、朝哪，就没法把照片上的像素对应回空间里的位置。
2. 稀疏重建：根据相机姿态估算三维物体所在的位置，确认物体表面特征点的位置，最终输出稀疏点云。
3. 稠密重建：稀疏点云难以直接用于高质量的可视化，所以还要用泊松重建这类方法，把位姿和稀疏点云转化为稠密点云或者网格模型。

```text
一组照片
    │
    ▼
位姿估计  ──►  每张照片的相机姿态
    │
    ▼
稀疏重建  ──►  稀疏点云（物体表面特征点的位置）
    │
    ▼
稠密重建（泊松重建等）
    │
    ▼
稠密点云 / 网格模型  ──►  导入 MeshLab 查看与渲染
```

读图：前一步的输出就是后一步的输入，位姿是整条链的地基；稀疏与稠密是同一件事的两个尺度——先确认"东西在哪"，再补足"表面长什么样"。

COLMAP 是开源软件，可以在 GitHub 上找到 C++ 源码；它依赖 CUDA 运行；提供简单的图形化界面与 Python API，界面比 Blender 简洁得多。典型流程是围绕物体拍摄多张图像，COLMAP 最终重建出物体的三维模型，同时确定所有拍摄照片对应的相机位姿——在界面里以红色锥体表示。重建出的模型可以导入 MeshLab 这类工具中查看与渲染。

#### ContextCapture：工业级的大场景

商业领域里还有一个更重量级的工具：ContextCapture。和 COLMAP 比，它是闭源的商业付费软件。

它更擅长处理户外大场景，比如无人机航拍生成的结果；它是针对工业级应用设计的，提供了更专业的位姿估计和重建算法，同样支持图形化界面与 Python API。

操作上感觉比较简单，不像 Blender 那样特别难上手，整体是一个比较自然的过程。但流程和 COLMAP 是同一回事：先确定相机的位置，再做稀疏重建和稠密重建，最终得到的也是同样的网格模型。差别在于它是工业级软件，很多算法细节上做了性能调整：一方面是能生成更准确的相机姿态，另一方面是对最后生成的网格做了大量精细化处理，所以最后能生成非常精美的网格。

它的文档是官方提供的中文文档，一份很简单的用户手册；Python 的调用在手册里也有说明，等于你可以直接从 Python 代码去使用它。

看效果最能说明问题：一组从无人机拍到的真实户外照片，喂进去之后出来的是一个相当精美的三维模型，逼真度很高——不像有时候用 COLMAP，得到的只是一个非常粗糙的模型。那组示例的拍摄地点是 Brown University。

除了这两种，还有一些别的重建工具，像 Metashape 以及 Meshroom。它们本身可能没有前面提到的这些那么知名，按自己的情况选择使用即可。

### 工具不止这些，关键是怎么选

先把话说清楚：图形学里的三维处理工具肯定不止今天列出来的这些。除了几何处理、渲染、重建，你可能还会遇到针对某个细分领域的专用工具。今天只是做一个概括性的介绍，列出最常用的一批，以及它们各自的特点和使用文档在哪。

而且不是所有工具都值得花同样的力气去啃：

- CloudCompare、MeshLab 这类基本是为我们做可视化服务的，把软件下载下来自己试一遍，就有一个初步的使用了解了；
- Open3D、Blender 这类，可能需要细致地查看它的官方文档，甚至要在网上找一些教程或样例代码来辅助学习；
- COLMAP、ContextCapture 这类，在图形学里其实并不是那么通用——几何处理和渲染是通用的，重建只是因为刚好我熟悉这个领域，才拿出来讲一下，这样的工具还有很多。

真正要选的时候，最主要的还是看自己的需求。几个绕不开的判断维度：

| 维度 | 为什么要看它 |
| :--- | :--- |
| 是否开源 | 能不能读源码、能不能直接调它的函数、要不要付费 |
| 有没有图形化界面 | 早期验证与手动编辑要付出的成本 |
| 有没有 Python API | 能不能嵌进代码里做批量处理 |
| 软件本身的性能 | 同等任务下的处理速度与结果质量 |

学习方法上，我自己的经验是这样：学习初期多尝试几个，把工具之间的区别先摸清楚；慢慢熟练、逐渐掌握之后，选一个你认为最好的往下深挖。等你成了某个工具的专家，后续再出现类似的问题，其实都可以举一反三、以不变应万变地去解决。我在几何处理上最熟的是 Open3D，所以遇到的很多问题都能用它解决。

顺带一提，另一位主讲者的方向是物理仿真与模拟，后面可能会介绍物理仿真的软件，或者介绍像 Houdini 这样的工具。

## 仿真渲染软件：用 Houdini 渲染水滴动画
> 对应块：BLK14 | 覆盖分集：P09上 | 块标题（分集名）：《仿真渲染软件》

### 为什么需要仿真渲染软件

今天这一讲的主题是仿真渲染软件。为什么要专门讲这么一个内容？其实主要就是因为：图形学的科研做到最后，总是需要一个结果的展示——无论是通过一段视频，还是通过某种模型，一般都会展示一个 3D 的最终结果。这也是图形学最直观的体现之一：我们一般最后都能做出一个成品，是大家可以直接看到的。

在科研从推进到调出结果的过程中，一般会经历这样一个循环：

```text
算法生成 3D 模型 / 序列
        |
        v
借助软件做 3D 可视化，预览结果
        |
        v
看哪里出了问题，回头调试算法
        |
        +--> 不满意？回到「预览结果」再来一轮
        |
        v （若干轮迭代后：算法改到足够鲁棒，结果满意）
把预览结果渲染成很漂亮的样子（最终成品）
```

读图：左边这条主线是"生成、可视化、调试、渲染"，其中可视化到调试之间会来回迭代若干轮，直到算法足够鲁棒。

这个循环的第一步就得借助软件，因为 3D 的绘制比 2D 难很多：它涉及三维的透视变换等一整套事情。用人眼去观察一个 3D 模型，和用人眼直接去看一张平面的画，肯定不是一回事。2D 的绘制你很可能自己就能写——虽然也有很多方便的 API，但 2D 难度毕竟小很多；换到 3D，每次都自己写就非常麻烦了。所以这个时候，我们往往需要借助一些软件和工具，很方便地把你的结果可视化出来。

预览和最终渲染的差别，拿我做的物理模拟来举例子最直观。做流体常用一种方法叫粒子法：把流体离散化成一堆粒子。预览的时候，结果很可能就只是把那些粒子在三维空间里的位置打出来——这里有一个粒子，就在这里显示一个点，流体看上去就是一堆散点。但到了渲染这一步，我们需要把这些散点转化成流体表面的样子，让它看上去真的像水、像烟雾。今天要讲的，就是针对后面这两个环节——预览结果与渲染结果——的工具。

### 本讲路线：两个软件与 Houdini 自学入口

今天讲的内容其实可以分为两部分，主要是通过两个例子分别介绍两个软件：第一个是 Houdini（胡迪尼）的用法，第二个是 ParaView 的用法。第一部分，我们会通过渲染流体动画的一个例子，带大家入门 Houdini。今天展示的只能说是一小部分——很小很小的一部分功能，它还有很多强大的功能，是大家可以自己去探索的。

课后可以直接去 Houdini 官网学：点 Learn，会拉出一个菜单，选 Learning Paths，就能找到这样一套教程——非常详细，而且是 case by case 的教学：你点进去，它会带你完成一个例子，再通过这个例子给你介绍 Houdini 有哪些强大的功能。

### 先认界面：四大块

打开 Houdini 之后弹出的窗口，就是这样一个布局，主要有几个区域：

```text
+----------------------------------------------------------
|                              |  右上: 参数视图
|                              |  (调试光照、相机、物体的位置
|   左: 场景视图                |   与旋转等, 凡是需要调参数的
|   (整个窗口左边最大的一块;     |   东西, 一般都在这里调)
|    还没加东西时, 只有 Y=0     |
|    的地平面, 平面上划分了     |  右下: 节点网络视图
|    一些网格)                  |  (拖拽模块、串联输入输出,
|                              |   形成完整的工作流)
+----------------------------------------------------------
|  底部长条: 播放 / 快进 / 停止 按钮 + 进度条
|  (导入序列后, 可以像动画一样一帧一帧地播放)
+----------------------------------------------------------
```

读图：左半边是看效果的场景视图，右半边上下两块分别是调参数和搭节点网络的地方，底部一条是播放控制。

最左边最大块的是场景视图。现在我们还没有加任何东西，所以场景视图里只有一个地平面——也就是 Y=0 的平面，这个平面上还划分了一些网格。右上角那一小块是参数视图：后面会看到，凡是需要调参数的东西——比如光照、相机，或者物体的位置和旋转等等这些属性——一般都是在这个视图里调的。

右下角是节点网络视图，这是 Houdini 的工作模式：它是一个拖拽节点、拖拽模块的方式，有点像拖模块去进行编程的感觉。每个模块会有一些接口——一些输入接口和一些输出接口——你通过串联它们的输入输出，把这些模块串起来，从而让它形成一个完整的工作流。包括你在 Houdini 里加载一个正常的几何图形什么的，也都是通过节点去加载的：一个几何，就对应一个节点。

最后是下面这一条长条：有一个进度条的显示，左下角还有播放、快进、停止这些按钮。当你在 Houdini 里导入一个序列的时候，它可以像动画一样一帧一帧地给你播放出来——这个对于我们直接去可视化，是非常方便的。

### 搭建场景：把粒子序列导进来

下面直接讲具体用法：如何用 Houdini 渲染一段水滴动画。前提是我手上已经有了一个水滴动画的素材，要做的事情就是把它导入 Houdini，并且渲染成一个很漂亮的结果。

#### geometry 与 file 节点

第一步是添加物体。添加物体的方式，就是在节点网络视图里插入一个叫 geometry 的模块：在网络视图中按下 Tab，它就可以让你输入一些字母，并根据你输入的字符去查找相应的模块——直接输入 geometry，它就能帮你找到。放置好模块之后，双击进入这个 geometry 模块，里面又是一个空的页面；在这个页面下，继续插入一个 file 模块。file 模块的意思，是帮你导入一个或者多个文件——如果你想导入多个文件，那它就是按帧给你导入的。

按帧导入靠的是文件名的写法：把文件名命名成"字符串 + 数字 + 后缀"的形式。这个例子里，文件名就是 `surface_particles.$F.obj`——其中的 `$F` 在 Houdini 里会被替换成 0、1、2、3……你有多少个文件，它就编到多少号；它就按照这个数字的顺序，替你把所有的 OBJ 文件加载进来。

#### OBJ 文件：三角网格与裸粒子

可能有同学不太了解 OBJ 文件，我简单说一下：OBJ 文件就是一个描述 3D 模型的文件。比如你在游戏当中遇到的人物模型，一般都是用三角网格（triangle mesh）完成的——它要存这些三角形的顶点所在的坐标，以及每一个三角形三条边的连接关系；OBJ 文件就可以去描述这样一个三角 mesh 的数据结构。另外，它也可以去描述粒子：粒子其实就相当于你只把顶点坐标列上去，不给任何连接关系——那就是粒子了。

所以我们今天这个例子，就是一个用粒子描述的流体水滴：这个水滴里包含很多粒子，这些粒子被放在了 OBJ 文件里，每一帧对应一个 OBJ 文件。所以当你导入一个序列的时候，相当于把整个水滴的动态——每一个粒子的动态——都已经导入进来了。

插入 file 模块之后，在参数视图中就可以修改它需要读取的文件。这样指定之后，左边场景视图里就能看到这些粒子的位置了——它直接给你可视化出来。

#### merge 与圆锥体

指定完文件，还有一种常见情况：假如场景里有很多个水滴，每个水滴只有自己的一个 OBJ 文件，而你想把所有的水都渲染出来，那就需要把所有的粒子合并在一起。这个事情，就是在 geometry 模块里加上一个 merge（合并）模块来做的。

这个例子里有两路文件：surface particles 指的是流体表面的粒子，inner particles 指的是流体内部的粒子。要渲染整个流体，就需要把表面粒子和内部粒子合并起来——直接把这两个 file 模块的输出，接到 merge 模块的输入上，它就可以把两个 OBJ 文件里的所有粒子都加进来了。

场景里另外一种东西是一个圆锥体。这个例子最终想可视化的，就是水滴往下落、然后被这个锥体刺破刺穿的动态。圆锥体也是同样的做法：插入一个几何模块，然后在参数视图当中指定圆锥的底面半径、中心点以及高度，这些参数就可以了。

加好了所有物体之后，我们的场景其实已经 setup 好了。在这个状态下，你就可以点击底部那个绿色的部分，直接点击播放，看到动画效果了。只不过，现在这个动画只给你展示了正确的动态，看上去还是很丑的：水还是一堆粒子，底下的圆锥也没有任何材质，就是一个光秃秃的东西。

### 从粒子到流体表面

接下来的一步，是把那一堆粒子变成流体的表面。先看此时水这个几何内部节点网络的全貌：

```text
[file: surface particles] ---+
                             +--> merge --> particle to VDB --> smooth --> convert VDB
[file: inner particles] -----+
```

读图：前半段（两个 file 加一个 merge）是前面已经搭好的——把两路粒子读进来、合并到一起；接下来要新增的是后面三个节点，把合并后的粒子一步步变成可以拿去渲染的表面。

#### 思路：每个粒子撑成一个小球

我们的思路是这样的：把每一个粒子都扩充成一个有一定半径的小球。粒子一多，相邻粒子之间就会有一些交集；我们把这些相交的球，提取一个公共的表面出来。你可以想象一个很大的水滴，里面充满了粒子——每个粒子都扩充成一个球，这些球的表面合并在一起，就相当于这个大水滴的表面了。

只不过这样做有个问题：每个粒子都是一个球，把它们的表面直接求并，不可避免地会产生一些很小的凸起，表面看起来是 bumpy 的。这个"把粒子扩成球、再把球的表面合在一起"的过程，就是在 particle to VDB 这个模块里做的。

#### Point Radius Scale：大了穿模，小了散架

particle to VDB 也有参数可以调，比如每个粒子可以扩充到一个多大的球体，对应的就是 Point Radius Scale 这个参数：这个参数越大，每个粒子扩充出来的球半径就越大。

这个参数不能随手填，两头都有坑：

| 取值 | 表面效果 | 后果 |
| :--- | :--- | :--- |
| 太大 | 表面几乎不再有凸起 | 表面向外扩充太多，水滴会比原来大很多。这不是好看不好看的问题，是会出错：粒子碰撞锥体的时候，粒子是严格贴在锥体表面上的；你把粒子往外扩充太多，扩充出来的表面已经嵌到锥体里面，就相当于出现了穿模 |
| 太小（小于粒子间距的一半） | 相邻两个球没有交集 | 表面就变成这两个球体各自的表面，本质上看上去还是一对粒子，不可能把它合并成一个水的表面 |
| 合适 | 相邻球面有交集、能融合 | 表面连续，又不会明显外扩 |

幸运的是，调这个参数并不费劲：点击参数面板最右边那个小按钮，左边的视图就会直接可视化这个操作之后的结果；你可以拖动进度条，看一下现在的半径是过大了还是过小了。所以这个问题就不大。

#### Voxel Size：三维图像的分辨率

还有一个需要注意的参数：Voxel Size。它最好比 Radius Scale 小一些，至少不能比它大。Voxel Size 相当于你的三维图像的分辨率，比如这里的 0.01，代表的就是网格的边长。如果你的网格边长比粒子扩充的半径还要大，那这个网格就非常粗糙、不够精细，根本没办法表示出你想要的那个表面。

#### Smooth 与 Convert VDB：抹平凸起，转成网格

为什么转成 VDB 之后还要做 smoothing？因为刚才直接得到的表面是很 bumpy 的、有凸起的，所以要做一次平滑处理。Smooth 也有参数：按照多大的邻域去平滑。这个参数同样有一个合适的值，大家也可以直接可视化它，拖动进度条自己手调，看哪个值最合适。下面的 Iteration 是迭代次数——迭代次数也不是越高越好：越高肯定是越慢的，但越慢其实并不一定越好，这个你们自己实践的时候就可以调好。

Smooth 之后，我们拿到的数据结构还是 VDB 结构。VDB 结构并不能直接渲染，还是要把它转化成 polygon mesh（多边形网格）的结构，就像三角形网格那样。这对应最后一个节点：Convert VDB。这个节点可以把 VDB 转化成各种各样的数据类型，注意把 Convert To 这个参数设成 Polygon，确保它能够转化成一个多边形 mesh 的数据结构，就好了。

做完这一套，场景视图就变样了：刚才上面那团"圆球"——原来是一堆粒子——现在就已经变成一个连续的表面了。

从粒子获得流体表面的全过程，概括起来就是：把每个粒子变成一个小球，把小球的表面融合合并到一起，再进行一个平滑，最后转化成 mesh。

### 赋材质：把玻璃调成水

现在流体有了一个连续的表面，但它看上去还是不透明的——因为你没有赋予它任何材质。可视化的时候，Houdini 会按照一个默认的材质去给你显示，就是什么都没有、白花花的一种默认模型。接下来要让它看上去真的很像水，我们就需要给这个水的表面赋予材质。

首先，从材料库里找到你想要的材料。材料库也在整个界面右下角的网络视图当中：网络视图其实有多个小标签，我们选第三个标签，叫 Material Palette，材质面板。选到材质面板之后，左侧就会有一系列 Houdini 自带的材质，还是挺丰富的。

对水来说，我们一般用自带的 glass，也就是玻璃这个材质。因为水其实和玻璃很像：都是透明的，只不过折射率、反射率可能不太一样，所以我们只需要改些参数就行了。你最后渲染出结果就会发现，直接把它当玻璃来渲染，也已经很像水了——因为你这个水的动态很丰富，只要是透明的，看上去就很合理。下面那个锥体，我准备用另外一种材质——金子做的，那就把 gold 也一起拖过来就好。这一步相当于先准备好你所需要的材料有哪些，只是在这里准备一下。

材质的具体属性，在右上角的参数视图里去改。直接点击 glass 材质，右上角就会变成这个材质的参数面板，里面反映着材质的各种属性：Reflection（反射）、Transparency（透明度）、Emission（发光度）等等——这些都是渲染中的一些术语，了解过渲染的同学应该会对它们很熟悉。

具体来说，想做一个很像水的材质，我们这样调：

| 参数 | 调成 | 说明 |
| :--- | :--- | :--- |
| IOR | 1.33（默认 1.5） | 折射率 |
| Reflection | 0.2 | 反射度 |
| Transparency | 0.8 | 透明度 |
| Emission | 0.04，光的颜色为蓝色 | 原来是 0；调到 0.04 让它轻微发一些光，光的颜色是蓝色 |

调完这几项，它看上去就比较像水了——或者说，至少很像一般动画里的水。

材质属性配置完，我们需要的所有材质就都准备好了。接下来把右下角的网络视图切换回 OBJ 标签——也就是刚才插入几何的那个界面。可以看到，这个几何界面里已经插入了两个几何：一个是我们的水，一个是圆锥体。想改水的材质，就选中水所对应的几何模块，在上面的参数面板中选到 Render 标签，下面会有一个 Material 属性——把材质指定成刚才我们拖进来的 glass 就好了。同样，想让圆锥体变成金子做的，就把圆锥所对应的材质设成 gold。

### 相机与光照：渲染前的必备两件套

材质配好之后还是不够。你要去完整地渲染一个场景，还需要两个必备的元素：相机和光照。相机，指的就是你拍摄的视角是什么。

#### 相机：先绑定视角，调好再解绑

添加相机的方法：在左边大片场景视图的右上角，有一个 No Cam 标记——它表示你现在是一个自由的视角，和任何一个相机都没有关系。在这里点下去，就可以添加一个新的 Camera。

添加这个新相机之后，选择 Tie View to Camera or Light，意思是把当前场景视图的视角，和你插入的这个相机绑定到一起。这样一来，你后续拖拽整个场景、视角发生变化的时候，相机是跟你的视角同步去变化的——这样就可以很方便地把相机设置成一个你想拍摄的视角。调完之后，再把 Tie View to Camera or Light 取消勾选就可以了，这个相机其实就设置好了。

点了 New Camera 之后，右边的网络视图里其实就会多出一个 Camera 模块；你在左边把它调好，它右边模块的一些属性其实也是自动帮你更新好的，不用管它。

#### 环境光：一个框住整个场景的包围盒

添加光照，同样是在右边的网络视图中按 Tab，然后输入 light，去找到所有和 light 相关的模块——这里面就是 Houdini 所支持的所有光照。这个例子里，我们选的是环境光照 Environment Light：相当于环境有一个包围盒，它是一个六面体——你可以理解为一个长方体——把我们整个场景，包括水滴以及圆锥体，都框在里面。这个包围盒很大，Light 就是整个包围盒所发出的光。

一般来讲，Environment Light 这种光的默认参数就可以直接渲染了，但你可能还是需要调一些参数，才能让它达到你所期望的结果：比如光照的强度、光照的颜色。Environment Light 还可以选择光源在最终渲染视图中可不可见，这里有个容易混淆的点：

- 没有加光照：渲染出来是一张完全黑的图片；
- 加了环境光照、但没有选"能看到光源"：物体其实已经被环境光照亮了，只是渲染的背景是黑的；
- 选了"能看到光源"：物体不仅被照亮，背景也是亮的。

这个大家回去试一下就可以体会到了。

### 用 Mantra 渲染并导出序列

配置好所有这些对象之后，就可以开始渲染了。Houdini 主要有两种渲染器：一种是 Mantra，另外一种是 Karma。先介绍 Mantra。Mantra 渲染的特点是只支持 CPU，但功能比较全——只是比较慢而已——而且它的各种参数也都非常灵活。

#### 插入 Mantra：out 标签下的渲染器模块

想添加一个 Mantra 渲染器，还是要回到网络视图：点击 OBJ 这个标签，切换到 out 标签——out 就是用来给你插入渲染器模块的。在这里直接搜索 mantra，插入就可以了。

#### Output Picture 与采样参数

对插入的 Mantra 模块，还是可以在参数视图里调一些参数。Images 标签页下有一个 Output Picture 属性，指的是你应该输出什么样格式的文件：比如默认的设置，就是在 $HIP 这个目录下、按这个名字格式输出一个 .exr 文件——这里你可以把后缀直接改成 PNG，它就会直接输出 PNG 图片。

然后可以切换到 Rendering 标签页，这里主要配置一些渲染的参数。Pixel Samples 指的是每一个像素给它采样多少次：采样次数越高，渲染的结果会越精细，一般来讲噪声也会越低；但带来的代价就是渲染一帧会非常慢。后面还有 Ray Samples，指的是一条射线去采样多少次。这些都是渲染的参数了——渲染其实我懂得也不是特别的深，很多参数我也不能给你们解释具体是什么，大家有兴趣的话可以自己去查一下。

#### 渐进式预览，满意再批量导出

配置好 Mantra 渲染器之后，就可以切换到渲染视图。渲染视图其实就是刚才场景视图的一个平齐标签：刚才场景视图亮的是最左边那个 Scene View 标签，你直接切换到 Render View 这个标签，就可以看到我们 Mantra 渲染的结果了。当然，你需要先点击一下 Render 按钮。

点击 Render 之后会出现一个进度条，它慢慢把这张图片"打"出来：刚开始你可能刚点击 Render，图片会只有几个像素点，然后慢慢把图片填充起来，噪声很多；随着进度条继续往后推移，噪声会越来越小——因为它相当于在不断采样、计算每个像素点的颜色，随着采样数越来越多，最后的渲染结果也就越来越准确。

在 Render View 下预览一帧渲染是什么样子，如果这一帧的预渲染效果你觉得已经很棒了，那就可以去导出整个图片序列，最后做成视频。导出的方法，还是点击刚才的 Mantra 节点：在这里配置输出的路径以及文件名（前面说过的那套），后面的扩展名可以改成 JPG、PNG，或者用它默认的 .exr。

最后不要忘了 Valid Frame Range 这个参数：它默认是 Render Current Frame，也就是只渲染当前帧——这样的话，最后渲染它只会给你输出一张图片。要把它改成渲染一个范围：指定一个起始帧、一个终止帧，渲染这个区间内所有的帧。然后点一下 Render to Disk，它就会开始批量渲染：从你指定的第一帧开始，到你指定的最后一帧结束，并给你展示一个进度条。在一些参数的设置下它可能会比较慢——我自己实践的时候，渲染这个视频大概花了三个多小时，三小时四十分钟。渲完这一批图片序列，拼成视频，就是大家最后看到的那段成片了。

## 仿真渲染：Houdini Karma 与 ParaView
> 对应块：BLK15 | 覆盖分集：P09下 | 块标题（分集名）：《仿真渲染软件》

先把开头这个 demo 的来历交代清楚：它是我的上一篇工作，SIGGRAPH Asia 2022 年的一篇论文。我们在 position based fluids（PBF）流体的框架下做了一个表面张力——这里也小小的打一个广告。你们看到的这个水滴 demo，就是我在 Houdini 里把它复现了一遍。当然原文里的这个 demo 会更好看一点：当时跑的粒子数更多，材质也是更加精挑细选的。

好，demo 交代完，接下来正式讲 Karma 渲染。

### Karma 渲染：换到 SOLARIS 的工作流

Karma 这个渲染器的好处，就是它支持 CPU 和 GPU 混合渲染，也就是能用 GPU 给你的渲染加速。

不过用它渲染，走的就不是 Mantra 那套流程了，相当于另有一套工作流程：刚才 Mantra 是直接在网络视图里切到 out 标签，在那儿插一个 Mantra 节点就可以；Karma 要从切换视图开始。

#### 从 Build 切到 SOLARIS

在整个窗口左上角的选项卡里有一个 build——我们要把这个视图切换成 SOLARIS。切换过去之后，整个窗口的布局都会变：下面会多出一些功能区，但右上角的参数视图和右下角的网络视图还在。

这时候把网络视图切换到 stage——刚才是 out，现在要切到 stage。

> **注意**：stage 是一个全新的环境，它不知道你刚才做过的所有操作。所以第一步是把之前场景里的东西全部导入进来：几何物体——水滴粒子和圆锥体——还有环境光照和相机，一样都不能少。

#### SOP Import：把场景搬进 stage

导入的方式，是在 stage 标签下插入一个 SOP Import 模块，它叫场景导入。SOP Import 的参数里有一项 objects，把刚才 obj 里的所有东西都填到这里，用空格隔开就可以了。

这里一共包括四个东西：一个是水（水滴粒子），一个是底下的圆锥体，一个是环境光照，还有一个 camera 相机。

#### Karma Render Settings：配置与出图

场景导入进来之后，接着插入一个 Karma 渲染模块。有个很方便的地方：插入 Karma 之后，它会自动给你生成一对已经连好的模块。第一个是 Karma Render Settings，负责 Karma 渲染的各项设置；它需要接收 SOP Import 的输入——这相当于把刚才导入的场景全都告诉了 Karma：我有这些光照、这些相机、这些物体。

选中 Render Settings 这个模块，到参数视图里去调它的属性：

- 输出：和 Mantra 一样，在输出目录 output picture 下配置输出路径和文件名；
- 相机：camera 这里要指定我们 import 进来的 camera1，告诉它用哪个视角去渲染；
- 分辨率：后面可以调图片的 resolution；
- 渲染引擎：一定要把 render engine 调成 XPU 引擎。它默认是 CPU 引擎，CPU 引擎用不到 GPU，速度还是会很慢的——这一步最容易漏；
- 采样：samples 就是采样的数量，再往下还有一些更多的图像处理和渲染参数。

都配置好之后，选中 Karma settings 这个模块——就是那个红色的模块，它叫 USD Render ROP——下面有一个 Render to Disk 按钮，点一下它就会一帧一帧地给你渲染。渲染之前，记得把渲染范围调成你想要的帧区间。

整条流程可以用一张图串起来：

```text
（Build 视图）──切换──▶（SOLARIS 视图，网络视图切到 stage）

  obj 里的场景：水滴粒子 / 圆锥体 / 环境光 / camera1
        │
        ▼
  [ SOP Import ]   ← objects 参数里用空格列出全部物体
        │
        ▼
  [ Karma Render Settings ] ──▶ [ Karma ]
     输出路径 / camera1 / 分辨率
     Render Engine = XPU / 采样数
        │
        ▼
   Render to Disk：按帧区间逐帧出图
```

读图就一句话：obj 里的东西经 SOP Import 进 stage，Karma Render Settings 汇总场景、配好参数，最后 Render to Disk 逐帧出图。

#### 实时预览，以及和 Mantra 的差异

你可能会问：Karma 要怎么预览？Mantra 有一个单独的预览阶段，而 Karma 其实就是实时渲染。在 SOLARIS 界面的右上角有两个视图标签，把左边那个调成 Karma XPU render 的 view，场景立刻就变成 Karma 渲染器渲染的结果了。而且这个结果你可以直接拖视角——它不一定非得绑定在你那个 camera 上，你拖到哪儿，它就跟着你的视角实时重新渲染。

不过要注意：Karma 渲染的结果很可能跟 Mantra 渲染的不太一样。有些 Mantra 里能支持的东西，Karma 里不能支持，可能需要重新配置一下参数——材质应该还好，主要是光照，你可能需要在 Karma 里重新配一遍。重新配也不麻烦，直接在 stage 标签下去拖这些模块就好。

| 对比点 | Mantra | Karma |
| :--- | :--- | :--- |
| 渲染入口 | 网络视图切到 out，插一个渲染节点 | 先切 SOLARIS，在 stage 网络里搭场景 |
| 预览方式 | 有单独的预览阶段 | 本身就是实时渲染，视角可随意拖 |
| 场景兼容 | — | 少数光照可能要重新配，材质基本没问题 |

我们最终期待的效果，就是刚才那个视频：可能有些细节不完全一样，但总体上水像水，圆锥体有点金属光泽、有点这种反光的效果，就可以了。有兴趣的话可以再去调一调参数，让它特别好看。

Houdini 的部分到这里就讲完了。

### 什么是体数据可视化

接下来换一个例子——速度场这种体数据的可视化——来介绍 ParaView 的基本用法。ParaView 也一样，我把它的官网和文档教程都附在 PPT 里了，想要了解高级功能，就点进去看。

什么是体数据可视化？体数据其实就是一个三维的场。拿速度场来说：流体是占据一定三维空间的，在这个定义域上会定义一个向量场——流体的速度场。这个场在自然界肯定是连续的，定义域内处处有定义，每个点都会给你一个速度的值。但在计算机里，体数据往往要转化成体素（voxel），其实就是把它网格化：只存每个网格格点处的值，格点之间就用插值来算。

> **定义**：体素（voxel）对应二维里的像素，指的就是三维网格中的一个格点。

常用的体数据可视化方法有三种：一种是体渲染，也就是我们接下来要用的方法；还有等值面提取，以及切片可视化。

这项技术在图形学之外也用得很广，这也是为什么可视化领域会有一个专门的课题，去研究怎么把体数据可视化得更直观。ParaView 官网展示的两张图就很典型：一张是医学成像——大家应该看得出来那是个肺，我推测应该是切片可视化；另一张是一种类似皮肤一样的材料的设计，可视化的是这个 skin 材料的应变（strain）——也就是它形变时的应变分布，用的应该是等值面提取。总之这些可视化非常强大，可以把人体内很精细的结构都给你一览无余。

### 两个涡环的碰撞：从速度场到涡量

进入我们的例子：我们想做两个涡环进行碰撞的一个效果。要可视化的本来是流体的速度场，但速度场是一个三维的向量场——域里面的每一个点都对应一个三维向量。而我们一般来讲，体数据可视化都是可视化一个标量场，那怎么办？只能牺牲一些信息：我们选择可视化流速场的涡量。

> **定义**：涡量，通俗地讲，就是描述流体在某一个点处转得有多快的一个物理量。三维里涡量本身是一个向量，我们现在可视化的是涡量的模长：模长越大，代表流体在这一块转得越快；越小就代表转得越慢。

现在假设我们已经拿到涡量场了——它是一个浮点的三维数组，一个 NumPy 数组：每一个维度对应网格的每一个维度，每一个值就是网格格点处的一个值。设整个定义域的坐标范围是 $x_{\min}\sim x_{\max}$、$y_{\min}\sim y_{\max}$、$z_{\min}\sim z_{\max}$，分辨率是 $X_N\times Y_N\times Z_N$，那么这个三维数组的形状就是 $X_N\times Y_N\times Z_N$。

接下来要把这个 NumPy 数组转化成 VTI 格式、写进 VTI 文件里，这样 ParaView 才能接收并可视化。转化的方式是用一段 Python 脚本，主要借助 Python 里的 VTK 包：先 import vtk，把数组转化成一个 VTK 格式的数据（vtk data），再用一个 writer 把它写到我们指定的 VTI 文件当中。

这个细节我不逐行讲了，代码就放在课件里，不太重要。如果你真的要可视化某个三维的体数据，去查一下 VTK 这些接口该怎么用；如果只是想实现一个和本节课一样的功能，直接复制这段代码就好了——你只需要注意每一个参数的含义就可以。

### ParaView 上手：导入、显示与播放

ParaView 的界面比 Houdini 要简单许多。它不是那种拖模块的工作方式了，其实就是一些文件，把这些文件整个混合到你的场景里。

第一步，把刚才生成的一堆 VTI 文件直接拖拽进中间这个框框的范围里。要导入一个序列的话，就按顺序选中所有 VTI 文件，一起拖进来。你会发现文件名最后带个星号（*）——带星号就表示它是一个文件组，是一串序列。不想拖拽的话，也可以直接右键去打开文件，指定路径之后选择一系列文件，直接导入过来就好。

导入之后，直接点左边那个眼睛的小图标——它默认是闭上的，也就是隐藏的，点一下它就会显示。但刚显示的时候，因为你是一个网格的数据，它其实只会显示出整个数据外面的一层包围盒，也就是一个长方体的棱。想显示出其中的内容，要把上面那个可视化方式的下拉条打开，选择 volume——体数据的可视化方式。选完之后，它立刻就变成了体渲染的图像。

现在你能看到两个环状的东西，它们就是那两个涡环。越靠内部，颜色越偏红——右下角的色标告诉我们：越偏红表示涡量越大，越偏蓝表示涡量越小。也就是说，这两个涡环越靠中心，转得越快。

视图操作和 Houdini 很像，直接拖鼠标调整视角就好。这里没有所谓的 camera 概念——ParaView 默认就是拿你当前的视角作为相机视角去渲染。

到这一步其实已经可以可视化了：直接点播放的图标，它就能把导入的整个 VTI 序列一帧一帧地显示出来。如果你导入的是一个连续的动画，它就会展现出涡环的动态。

这个播放是很快的，比 Houdini 快，这是 ParaView 的一个好处。当然可能也跟你现在这个例子有关，但总体我使用的感觉就是 ParaView 会更轻量一点：直接导入进来，点播放，它就可以很流畅地开始播放。而 Houdini 刚导入粒子的时候，你点播放，它每一帧都会给你卡一下，看起来不是很流畅。

### 渲染出片：地平面、光追与光源

觉得这个结构比较好，就可以开始渲染了。渲染其实就是多引入一些东西、再改一些参数。

第一步，导入一个地平面。因为我们想要阴影的效果：涡量越深的地方，阻挡光线阻挡得越厉害，从而在地上形成一个阴影。而形成阴影，你不能是个虚空，所以需要一个地平面——就像刚才水滴有阴影，是因为底下有一个圆锥体，才能在这个圆锥体上映出水滴的一些倒影。现在你可以把中间这两个涡环理解为两团烟雾，你需要一个依托，才能打出它们的倒影。做法很简单：加一个很大很大的平面。这个平面可以自己写一个 OBJ 文件——平面就是一个正方形，正方形由两个三角形组成，这两个三角形构成了一个 mesh，就是我们想要的平面，大家自己写就可以了。

第二步，开启光线追踪。在左下角 properties 标签下往下拉，最后有一个 ray tracing rendering 的部分，里面有一个 enable ray tracing 的开关，默认是不勾选的——因为默认只是给你可视化一下，没有开启光线追踪的渲染，这也是为了效率。你想生成高质量的结果，就把它勾上，这样就可以开始光追渲染，效果会提升很多。接着把下面的 shadows 也勾上，就会出现阴影投射的效果。

> **注意**：勾上这两项之后，你会发现 ParaView 瞬间变慢了，拖拽视角、播放序列都会变得一卡一卡。所以这个时候就尽量不要去拖动中间视图里的东西了，直接在右边继续添加光源。

第三步，添加光源。ParaView 会默认给你一个叫 light kit 的光源，这个勾选框默认是勾上的——把它取消掉，添加自己的光源就好。光源类型可以自己选，是点光源还是平行光；我们这里选 directional，directional 的意思就是平行光。平行光的光束方向，就是从 light position 指向 focal point 的这样一个方向。

加完之后可以看到，这个光相当于是从右上角的位置打过来的：看那个坐标系——原点在左下角，加上屏幕向里的方向——光源相当于是原点相对的位置，也就是屏幕向外、并且在右上角这样一个方向。所以它打出的阴影，正好就在现在的这个位置。

场景配置到这里就差不多了，接下来的任务就是把动画导出。很简单：直接 File → Save Animation，选定一个路径和文件名之后，会弹出一个保存选项。这里有一个 suffix format——它其实跟 Houdini 一样，生成的也是一系列图片，从第 0 帧到第一帧、再到若干帧。帧与帧之间的命名，是通过给文件名后面加一个后缀来做的：像 %04d 这样的格式，第 0 帧就是 .0000，第 1 帧是 .0001，然后 .0002，一直以此类推地生成下去。

最后把这些图片用 FFmpeg 串起来就好了。FFmpeg 这个东西，第一次作业我就给大家留过了，做过的话应该不陌生——它就是命令行里的一个工具，直接敲个命令行，它就可以把相应的一系列图片给你串成视频，还是很方便的。最后的效果，大概就是刚才那个样子。

把整条「数据到成片」的流水线画出来就是：

```text
涡量场：浮点三维数组，形状 XN × YN × ZN
        │  Python + VTK：NumPy 数组 → vtk data → writer 写盘
        ▼
   一系列 .vti 文件（第 0 帧、第 1 帧、……）
        │  按顺序全选拖进 ParaView（文件名带 * 即一组序列）
        ▼
   Representation = Volume，体渲染显示出两个涡环
        │  + 地平面 OBJ + Enable Ray Tracing / Shadows + 自建平行光
        ▼
   Save Animation：%04d 后缀逐帧出图 ──▶ FFmpeg 串成视频
```

这些方式生成的物理模拟结果都可以，只要你在最终的文档里指明你这个动画是哪来的就行。报告要求用 LaTeX 来生成 PDF——LaTeX 我几周前的课给大家讲过，希望大家没有忘掉。

顺手把答疑里两个共性问题说清楚。要不要传工程文件？我留的作业都只需要交 PDF。课程网站不能上传视频，所以你生成的动画，我们会要求你抽一些关键帧、截图放到报告里。要不要贴代码？一般来说，贴代码是一个很不优美的事情——没人知道你写的是什么意思，所以尽可能用自然语言去描述；实在需要展示代码，就截取最核心的那部分贴到报告里。

### 结课的话：以实践为主，别攒问题

今天讲的内容，我觉得是很实用的，但其实只是这两款软件很小的一部分、冰山一角，它们实际的功能要强大许多。我只是用两个很简单的例子给大家展示一些基本的用法，有更多需求的话，还是需要上网去找官方的教程和文档。

很遗憾，今天由于设备的限制，不能带大家一起实践一下这两款软件。但我还是很希望大家课后能够自己去实践其中任意一个——它们在你后续的科研当中应该还是非常实用的。课件把每一个流程都截图截出来了，比较详细，大家照着一步步做；哪个步骤出问题了，及时在群里联系我，或者直接私信我都可以。

答疑的时候有同学问点云是什么——正好这次课也有点设计。最开始讲粒子法流体怎么渲染的时候，我们导入了一堆粒子，这些粒子你就可以理解为点云。点云其实很简单：三维场景中有一堆点、有 N 个点，每个点都有一个三维的坐标，所以整个点云就是 N 乘 3 个数字，表示 N 个点的位置。在物理模拟当中，它指的就是粒子系统——因为这些粒子可能会带上一些其他属性：除了位置，可能还有速度、质量、密度等等。如果这类图形学的基本概念你不了解的比较多，可以在群里提出来，我和叶开都在群里，也会有其他同学帮助你；问题不多的话，像点云这种概念，网上搜一下就有。

这门课没有前置课程——这个课程本身已经是前置课程了，不能再有前置课程了。内容来讲应该还是比较入门级的。大家有什么问题也不要藏着：如果你现在从入门开始就已经积攒问题，到后续做科研，可能就会积攒太多问题，导致后面寸步难行。所以现在有什么问题，一定要及时提出来。

我是一直鼓励大家实践的，包括我讲的这些课——从最开始的 Linux shell，到后面 Windows 下的命令行，以及文档编辑工具，再到现在的这些软件，大家都可以把课上讲的东西稍微复现一下。比如今天讲的东西，你就可以下载一个 Houdini 或者一个 ParaView，自己去复现一遍。你稍微实践之后，才会发现更多的问题，解决了之后才会真正入门。我个人感觉，图形学这个东西，通过实践入门会比较快一些——只学理论不实践，那肯定是不行的。

有同学说，上次课好像没有讲得特别详细，主要是介绍了很多软件、附上了链接，让你们自己去查。这个确实比较考验你们网络上信息检索的能力，而在科研当中这也是很重要的：你要逐渐学会自学，学会怎么去检索。起步的时候，你可以在群里问，大家可以帮你；但是到后面，这种层面的帮助会越来越少，越来越需要靠自己去解决这些问题。

如果照着课上讲的步骤一步步实践，理论上你应该能达到课件上展示出的那些结果；如果你改动了一些、做了些其他的操作、不知道对不对，也可以发到群里大家讨论一下——我们建群就是为了这个：让大家在实践过程中遇到什么问题，可以交流一下。

行，我觉得时间也差不多了。今天应该是我们这个课程的结课日，如果大家还有后续什么问题，就在群里提出吧。
