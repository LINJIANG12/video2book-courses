## Linux 与 shell：科研工具的第一课
> 对应块：BLK01 | 覆盖分集：P01上 | 块标题（分集名）：《Linux + shell》

同学们晚上好，今天是 GAMES002 的第一课。先自我介绍一下：我是陈宝权，来自北京大学。GAMES002 这门课由我和金瑞、叶开两位同学一起上，今天由我开头，后面的课程由他们两位主讲。

### 科研是一种生活方式

大学里做科研的本科生并不算多，这全凭个人兴趣；而在大多数同学眼里，科研也是件挺神秘的事。所以在北大，我们专门开了一门讲科研实践的课——讲科研是什么、培养科研的基本能力，也安排了一些方法来加强科研训练。

科研到底是什么？除了大家通常了解的那个"科学发现的过程"，它其实也是一种自我训练的方式，是对自己能力的培养。科学家把科研作为职业，但对很多人来说——不只是以科研为职业的人——它其实是一种生活方式，可以渗透到我们生活的方方面面：培养我们怎么去思考问题、面对问题、解决问题。所以我觉得，本科期间如果能参与一定的科研实践活动，是非常有收益的。

当然，这门课不针对科研的方方面面，它提供的是工具。

### 这门课从哪儿来：科研实践课的三块拼图

科研工具的介绍，是我们科研实践课的一部分。这门课是我在北大开的，跨两个学期，主要内容在第一学期，大概分成三大块：

- **科研方法**：怎么做研究，主要由我来讲；
- **科研工具**：要进入科研，你可能先要掌握相应的工具，上手才比较容易——总的来说，就是把科研的门槛降低，让大家比较顺滑地进去；
- **导师面对面**：我们请一批科研导师进课堂，讲各个方向上的研究问题，让学生对不同的研究领域、不同的导师都有很好的了解，形成一对一的交流；未来你可以选择去心仪导师的实验室，做比较长期的实习。

顺带说一句，寻找科研导师这件事本身非常重要。导师不只是有经验、能给你分享问题：实验室有设备、计算资源等各方面的条件；一般来说导师还有研究生，他们也可以共同指导你。找到导师之后就是实践——只有在实践当中，你才能学到真东西，learn by doing，边做边学，这和课堂的学习非常不一样。

整套设计的意图，就是让从大二开始的本科生，如果想了解科研、想进入科研实践，能方便一点。不过不上这门课也没有关系：刚才说的这些元素，你自己其实也可以去发现，导师也可以主动去联络，科研工具通过这门课也能有所了解。只要你主动、有这个意识，是不是有这门课，其实无所谓。

### 科研的基本功与几篇经典文章

科研方法这块到底讲些什么？大概就是这些：

- **心态与责任**：科研作为一种生活方式，我们需要什么样的心理和心态？做科研是有责任的，也涉及科研道德，这些需要提前了解；
- **阅读与写作**：阅读的能力很重要，读文献、写科技论文（或者说科技报告）的能力很重要。这可以靠讨论和经验分享来练——网络上有很多这类经验分享的文章，大家可以有意识地去读；
- **交流与展示**：科研的过程不是一个人关起门来闭门造车，实际上要不断和别人讨论沟通；有了成果以后，你也需要展示你的成果。怎么交流、怎么做报告，都是要专门培养的能力。

课堂上我会分享一些文章，跟大家一起讨论。比如有一篇对图灵奖得主 Sutherland 教授的访谈；还有一篇在网络上可能特别经典的报告，是 Richard Hamming 写的《你和你的研究》（You and Your Research）——你到网上一搜，这篇文章就会出来，读他的报告总结，应该可以获得很多收益。另外还有一位已经过世的温斯顿教授，他有一场关于"怎么做好报告"的非常经典的演讲，这方面的经验分享非常值得去听。

这些阅读不限于课堂。你感兴趣，也可以自己找相应的文章，和同学们互相讨论——不见得在课堂上，在课外组个兴趣小组也行。主动，比什么都重要。

### 肩膀不止导师一个

我们都知道那句名言："如果你看得远，是因为你站在巨人的肩膀上。"确实是这样——甭管是巨人还是多高的人，总之你能站在他的肩膀上，就能看得更远。我们每一个阶段的科研实践和经历，其实都在帮助我们站得更高、看得更远，所以"寻找这样的肩膀"变得特别重要。

这样的肩膀挺多的，不只是导师：

- **导师的合作者**：他们来访问、来交流，同样能给你一手的经验和指导；
- **课题组的学长学姐**：也是一手的经验；
- **你的同学**：三人行必有我师，这一点都不假。如果有一个很好的同学团队，相互之间是可以学到很多的；
- **来访的杰出讲者、学者**：把眼界再放开一点；
- **国际会议上的同行**：慢慢你也能去参加国际会议，在那里认识这个领域里非常优秀的学者。

还有一件很重要的事：如果你未来更多地投入到科研当中，你会发现每一个方向都有自己的社区（community）。在国内它就是所谓的专业委员会——比如你是做图形的，就有图形方面的专业委员会；国际上 ACM 等组织也有对应不同学科方向的社区。你去参会，会议本身就构成了一个社区：见到的都是你的同行。这样的社区非常有意义，你可以从他们身上学到很多经验。

### 交流要随时随地

我特别强调：科研当中，交流特别重要——而且是各种各样的交流。

想法不成熟的时候，你需要跟人家交流，把这个想法变得更清楚；有了一个比较清楚的想法，怎么解决？或者你提出了一个很有意义的问题，怎么去解决它？也需要跟大家交流。不是说你有了成熟的想法和解决方案才去分享——不是这样的，分享的是发现问题、解决问题的过程，它绝对不是最后结果的呈现。

这和课堂的学习不一样：课堂学习，你认真听讲、能独立完成作业，就很好了。但即便在课程学习当中，交流也变得很重要。而且我是鼓励随时随地的交流。这里我故意用了两张照片：一个是吃饭的时候也可以交流——吃饭时不只说娱乐、八卦，如果你在科研这个状态里，也可以聊一聊各自遇到的问题，在放松的状态下可能突然就有灵感；还有就是在走廊上碰到，我们叫 hallway conversation——走着走着碰上了，"我最近有个想法跟你交流一下"，两人就聊上了，三言两语把你脑子里的问题描述一下。所有这些看起来是特别小的行为，其实一点都不小，对科研很有帮助。

做科研需要一个很好的环境，也需要一个好的文化。你可能会说，环境和文化是现成的——实际上，科研的环境和文化，是每一个身处其中的人都能参与构建、甚至改变的。

### 漫画里的文化差异

在科研的文化意识上，我们有些时候需要打开既有的一些思维和行为方式——打开之后对你的科研是有益的。要打开方式，首先要认识到一些不足，或者说看到一些对比。这里我借用了在德国的一位华裔女生的系列插画（illustration），她用非常形象、又带点幽默的绘画来表达东西方文化的不一样。分享几组：

- 成长过程中，每个人从小朋友长大，得到的关注（attention）可能不一样；
- 作为个人，自我的认同、自我的认定和感受，在不同的社会文化环境下也会不一样；
- "我的导师、我的老板，到底在群体中间是什么样的位置"——这个认知不一样，也决定了你思维时的态度：你是不是能主动地表达你的想法，是不是能够挑战、质疑老师或者有经验的人的想法；
- 生活方式：你是喜欢独立行动，还是什么事情都要跟大家一样、不要我跟别人不一样；
- 社交场合的行为方式：是大家围成一个圈比较有序，还是很自由地探索、三三两两碰到熟人打个招呼；
- 出现意见的时候，是直接表达，还是通过很复杂的方式表达；
- 出现问题的时候，是直接去解决问题，还是习惯性地绕开问题。

这些对比不一定那么准确，但确实让我们意识到文化的不同。就科研而言，我的建议是：大家能够直接地表达自己的想法，这非常重要；出现了问题，我们要习惯性地面对问题、解决问题，而不是绕开它——这些都是思维上的习惯。

### 同伴的力量与实验室的传统

榜样的力量，或者说团体的力量，很重要。各位同学如果有意进入科研，就要去寻找同伴、寻找志同道合的人，跟优秀的同学学习，慢慢形成自己的群体——优秀的人互相学习，可以更快地进步。

在我的实验室，我们有一个比较常态的传统：本科同学来实习。基本上每年都有本科的同学参与，一般从大二暑期正式开始进实验室、做研究，最后研究成果也得到发表。有一批同学都是这样走过来的，本科期间就把论文发表在我们领域的顶会 SIGGRAPH 上——其中就包括这门课的两位主讲金瑞和叶开，一会你们就能见到真人。这些同学都非常积极地参与科研，也都有一些成果。

总的来说，科研还是一件很有意思的事情，它和课堂的学习不大一样。本科阶段如果你有兴趣、也有精力，进入到科研当中——大家能来上这门课，应该也表明了对科研感兴趣，这就是一个很好的开始。保持一个良好的心态，在各个方面锻炼自己：跟导师打交道、跟同学打交道、跟学长学姐打交道；发现问题、解决问题；怎么平衡学习和科研，在繁忙的学习之上还做科研，安排好自己的时间、做好时间管理；还有你自己其他的很多兴趣也要去探索，处理好各种事情之间的平衡。以及在科研实践当中，像前面说的，要跟人交流、讲述自己的工作——把最后的结果先放在一边，这个过程本身就非常受益。

### Linux 是什么：四个关键词

那我们就正式开始，今天讲的是 Linux 和 shell。

> **定义**：Linux 是一群开源的、基于 Linux 内核的类 UNIX 操作系统的集合。

这个说法念起来比较绕，拆开就是四个关键词：**开源**、**Linux 内核**、**类 UNIX**、**操作系统的集合**。

#### 开源

开源的意思是：Linux 的核心代码你都是可以找到的，也可以使用；如果你有条件，也可以跑、也可以去修改它。在开源社区里，你都可以做出一些贡献，都没有问题。Linux 这个系统的代码在 GitHub 上有公开的仓库，谁都可以去看。

#### Linux 内核：一层套一层的橘子

什么叫内核？学过计算机操作系统的同学应该就会很熟悉：计算机其实就是一层一层的抽象，一层抽象包着一层抽象，形成一个橘子——橘子皮不断往里剥，或者说是一种套娃的结构。

最中心的部分就是直接的计算机硬件，叫 hardware；直接控制硬件的外面一层，叫内核（kernel）——这些内核是直接跟硬件打交道的。可以想象，内核其实非常不适合让人类来直接操作，你可以把它理解成像机器语言一样复杂。所以我们就需要再次对它进行一个封装，这次封装就到了 shell。shell 这个词的中文意思其实就是"一层壳"——它是外面外界和内部之间的一层壳。这个壳的作用就是和 kernel 去打交道，打交道的方式是通过一行行的命令行：你一般会打开一个 shell 的窗口，一个类似 DOS 的窗口，在里面输入一系列的命令，让计算机去做一些事情——这个窗口里运行的就是一个叫 shell 的程序。

但 shell 其实也并不是我们最常接触到的东西。我们最常接触的应该是更外层的 application，也就是应用：五花八门的、有图形化界面的应用软件，这才是我们日常使用最多的级别。

```text
应用 application            ← 五花八门的图形界面软件，我们最常接触的层级
  └─ 壳 shell               ← 外界与内部之间的一层壳，用一行行命令和内核打交道
      └─ 内核 kernel        ← 直接控制硬件，复杂得像机器语言，不适合人直接操作
          └─ 硬件 hardware  ← 最中心的部分，计算机硬件本身
```

从外往里一层包一层，这就是那颗"橘子"。刚才说的内核，指的就是 kernel 这一层——因为它是 Linux 的，所以说"基于 Linux 内核"。

#### 类 UNIX：linux is not unix

说 Linux 是"类 UNIX"，其实主要是想强调一点：它不是 UNIX。这里有一个流传的笑话：LINUX 的全称是 "Linux Is Not UniX"——说的就是这样一个事情：Linux 和 UNIX 其实是不一样的，但它们很类似。

#### 操作系统集合：Ubuntu 在其中

最后，Linux 并不是一个单独的操作系统，而是一个操作系统群。到 2007 年为止（一个比较老的时间线），各个时期出现的操作系统——每一个系统其实都是 Linux 系统——这些系统的总称才叫 Linux。我们今天会做一些实践，实践都是在 Ubuntu（乌邦图）这个系统上进行的，它大概是时间线右上角的一个棕色的小点。

### 为什么我们要用 Linux

为什么我们要用 Linux？首先它有一系列的优点：快、稳定、有很方便的包管理、开源，另外功能也齐全。

开源为什么算个好处？因为开源，世界各地的 contributor——开发者——都会对这个项目进行贡献，所以它的生态会非常好：它不是只局限在一个公司内的封闭工作模式，而是一种很开放的工作模式。而且如果东西是开源的，你又非常了解它的内核——开发者就能非常详细地了解这个 Linux 内核——那就可以很针对性地为 Linux 提出一些优化方法，或者其他方面的优化。所以开源一般会导致一个比较好的生态环境，这也是 Linux 所具有的优势之一。

而在我们科研或者学习当中，会有很多应用场景需要用到 Linux。我这里列出了三点，但其实这只是冰山一角：

- **远程服务器**：一般来讲，如果你想做科研、要跑一个很大的模型，或者说跑一个深度神经网络（deep neural network），你可能会需要租服务器——这个时候你就只能远程去连那台服务器，而那台服务器上的操作系统一般就是 Linux 的，所以这个时候你就避免不了 Linux；
- **仿真环境**：如果做机器人学（robotics），应该会比较熟悉，比如 Gazebo 这种有物理仿真的仿真环境——只能在 Linux 上运行，或者说只在 Linux 上运行得比较好，其他系统兼容得不太好；
- **其他领域**：其实在图形学领域，用 Linux 还算比较少的，主要就是前面两点说的这样的用途——以我个人的理解，图形学还是 Windows 要用得多一些；但是在操作系统以及计算机网络这些方向，还有比如你想做软件开发，都很有可能只用 Linux、不用 Windows。

这些用途也列得都不全，有别的可以补充。

### 三种方式访问 Linux

那如何访问 Linux 呢？就是怎么样去访问一个 Linux 系统、怎么用它。有这样三种方法。

#### 从白板电脑装起

第一种是真的安装一个 Linux 系统：从一台白板电脑开始去安装。这个过程会比较复杂，你需要用一个 U 盘启动盘，或者用一张 CD，就是一个光盘。具体的安装步骤，课后点一下课件里的链接就可以看到，或者说你在网上随便一搜就可以搜到。关键是要下对镜像——下对那个镜像的版本就行，一般来讲用的都是 Ubuntu 18.04 或者 20.04，这些版本也许有更新的也可以。

#### WSL：Windows 里的 Linux 子系统

第二种是用 WSL，它的全称叫做 Windows Subsystem for Linux。WSL 其实是 Windows 下的一个应用程序，这个应用程序模拟了一个 Linux 的环境。它的界面就是弹出一个窗口，这个窗口里面就是 Linux 的 prompt，你可以输入 Linux 的各种命令行去执行——就像在使用一台 Linux 服务器一样去使用你的电脑。

WSL 其实非常好用。比如你只有 Windows 系统，然后你从某个 GitHub 的仓库上 clone 了一份代码，但这个代码只能在 Linux 上跑通——这个时候就可以用 WSL。而且 WSL 还有一个好处：这个 Linux 子系统的文件系统，和你本机的 Windows 系统其实是共享的，你的 Windows 可以访问到 Linux 的文件系统，Linux 子系统也可以访问到你 Windows 的文件系统，两边都是共通的，这是一个非常方便的事情。至于怎么安装 WSL，一般来讲要到 Windows 10 这个系统版本以上才能安装，安装方法可以直接参考课件里的官方文档链接。

#### 虚拟机：完整但隔离

第三种是使用虚拟机去进入一个 Linux。虚拟机一般用 VMware 或者 VirtualBox 这种虚拟机软件来实现，然后你还需要下一个乌邦图的镜像，就是 Linux 系统的镜像，这样它才可以运行。虚拟机其实比 WSL 要完善得多：它会有一个完整的图形界面，不只是终端。但是虚拟机里面的东西，一般来讲和本机的文件是不共享的——一般的手段通不了，你可能要通过一些特殊的手段，但实际上通常只能通过网络的方法来传输文件。

三种方式放在一起看：

| 访问方式 | 它是什么 | 和 Windows 的文件互通 | 要注意什么 |
| :--- | :--- | :--- | :--- |
| 真机安装 | 在白板电脑上直接安装 Linux | ——（它本身就是操作系统） | 过程复杂，需要 U 盘启动盘或光盘；下对 Ubuntu 镜像版本，18.04 / 20.04 常用 |
| WSL | Windows 下的应用程序，模拟 Linux 环境，弹出命令行窗口 | 双向共享，非常方便 | 需 Windows 10 及以上；像用一台 Linux 服务器 |
| 虚拟机 | VMware / VirtualBox 加 Ubuntu 镜像 | 一般不共享，多靠网络传输 | 有完整图形界面，比 WSL 完善 |

### 打开你的第一个 shell

接下来的步骤，如果大家手边有电脑，其实可以跟着课件一起去操作，后面我也会实机演示一些 shell 里的命令和操作。

第一步就是要打开你的 shell。如果你用的是 Linux 系统，或者 Linux 虚拟机：直接切到桌面，按 `Ctrl+Alt+T` 就可以打出终端；或者说你在程序里搜索 terminal 这个词，也可以打开终端。Windows 用户：可以打开 PowerShell——它是 Windows 里类似 shell 的一个程序——在 PowerShell 里面输入 `wsl` 然后回车，前提当然是你已经安装好了 WSL。比如我现在给大家演示一下：打开 PowerShell，输入 `wsl`，稍等一下，它的光标就变成另一个样子了——这个样子就说明我们已经进入了 Linux 子系统。

进了 shell，先认一下提示符这一行字符串代表什么意思：

```text
user@hostname:~$
│    │       │
│    │       └─ 冒号后面：你当前所在的路径
│    └─ @ 后面：这台电脑的名称
└─ @ 前面：你的用户名称
```

一句话读图：@ 前面是你（用户名称），@ 后面是你的机器（电脑的名称），冒号后面是你现在站的位置（当前所在路径）。然后我先切换到我们今天讲课用的路径下面，就可以开始了。

> **提示**：WSL 用一还是用二，区别不是很大——至少对这门课来说没有区别；但如果你想运行一些比较 fancy 的、在 Linux 上跑的程序，那推荐用 WSL 2。

### 从 hello world 看懂一行命令

学任何一门语言，我们的第一个任务都是能让这个语言输出 hello world 这个字符串。现在学 shell，我们也用同样的思路。

先看这样四行语句：

```bash
echo hello world
echo hello\ world
echo "hello world"
echo 'hello world'
```

其中 echo 的意思，就是将后面跟着的参数原封不动地输出到屏幕——它本身就是一个 shell 的指令。这四行输出的结果，大家可以先猜一下分别是什么样的、有没有区别。其实不用猜，直接试：我先输入 `echo hello world`，它输出了 hello world；在空格前面加一个反斜杠，输出的还是 hello world；去掉反斜杠、加上双引号，输出的还是 hello world；把双引号换成单引号，还是 hello world。**这四行语句的输出结果完全一样，但它们的工作机理完全不一样。**

为什么不一样？我们来看一行命令的结构。它的第一个单词表示它的指令——echo 指令的作用，就是将后面跟着的参数输出到屏幕；用空格来结束第一个单词；空格后面的东西全都是参数，参数与参数之间也是用空格隔开的。

第一行跟了两个参数：一个 hello，一个 world。回车之后，echo 会把两个参数按照顺序输出，并且在中间隔一个空格。所以如果你在第一行指令里、hello 和 world 中间输入多个空格，它最后输出的也是只有一个空格的版本——我可以给大家试一下：hello 和 world 之间打很多空格，回车一下，发现中间还是只有一个空格。这就是因为 hello 和 world 是两个不同的参数，中间的这些空格其实都被视为了两个参数之间的分隔符。

> **易错点**：连续的空格不会出现在输出里——它们只是参数分隔符。想让空格成为内容本身，就要靠转义或者引号。

第二行为什么不一样？因为空格前面加了一个转义字符，反斜杠 `\`。转义符的意思是：把转义符后面紧跟着的那个字符，变成字符串中的一部分。因为反斜杠的存在，前面的 hello 和后面的 world 就由中间这个空格连在一起了——所以在第二行里，`hello\ world` 是作为一个整体、作为一个参数传给 echo 的，然后 echo 把它原封不动地输出。

第三行和第四行其实也是类似的：你在字符串外面扩上一层引号，中间的这个空格就会失去它的含义，变成字符串的一部分——整个引号括起来的内容作为一个参数传给 echo，单引号和双引号在这里效果一样。

这里面其实还涉及一个小知识：引号在 shell 里的用法也是有一定讲究的，有可能会出现很复杂的情况。我这里给大家留了一个链接，课后可以去了解一下——之后如果遇到更复杂的指令，大家也能够看得懂。

echo 只是一个例子，它可以替换成很多常用的命令。常见的命令可以列成一张表，其中加粗的是比较常用的。但要注意一点：有一些命令可能是系统不自带的，运行的时候有可能会提示你去安装一个什么东西，那你就需要安装上相应的程序，才能执行这个命令。这张表我就先跳过，大家可以课后去看。

### shell 到底是怎么干活的

接下来讲一下 shell 是如何工作的。回到我们刚才说的：对于一个指令，shell 会把它拆成第一个单词和后面的部分。第一个单词，其实指定了一个系统内置的程序的名称——shell 工作的方式，就是说去调用一系列的程序，来执行你的命令。

前面那条指令我们调用了 echo，其实就是因为你的系统内置了一个名为 echo 的程序：在你输入这条指令的时候，它调用 echo 这个程序，把你后面输入的内容打印在屏幕上。

> **结论**：命令行的第一个词，就是你指定的程序名称，用空格去结束它；空格之后跟的东西都是参数——参数是作为那个程序的一个输入的。

当然，程序还有别的输入方式，比如后面会讲到的文件输入，这里说的只是参数输入。

## Linux 命令行基础：从敲下回车到跑起自己的脚本
> 对应块：BLK02 | 覆盖分集：P01下 | 块标题（分集名）：《Linux + shell》

在命令行里输完一整条命令、敲下回车的那一刻，究竟发生了什么？这得从 shell 的本质说起。shell 其实也是你计算机系统上的一个程序，只不过它是一个专门"调用别的程序"的程序。你敲下回车，它并不是自己在跑你的命令，而是开启一个子进程去跑你想要调用的那个程序——那个程序和当前这个 shell 是相互独立的。只不过按了回车之后，shell 就处于挂起状态，等你的程序运行完，再由 shell 把屏幕的控制权接管回来。所以看上去两者像在同一个进程里无缝衔接，实际上是"开子进程、等它跑完、收回控制权"这么一个过程。

如果你上过 ICS 这门计算机导论课，应该碰到过一个经典 lab：写一个 tiny shell——其实就是让你亲手实现"一个能调用其他程序的程序"，也就是刚才说的这件事。

### shell 怎么找到你的程序：PATH

shell 的职责是"选择一个程序来跑"，那么下一个问题就自然引出来了：shell 要如何找到我想要调用的程序呢？我只是给了它一个名称，它怎么知道这个程序在哪儿？

答案就在环境变量里——具体说，是一个名为 PATH（大写）的变量。用 echo 指令可以把环境变量的内容输出出来看。这里请注意一个细节：想输出一个变量的内容，必须在变量名前面加上一个 dollar 符号（`$`），否则你的变量名会被解析成一个字符串。

```bash
echo $PATH
```

敲下回车，会看到很长很长的一串字符。仔细看，它其实是一堆用冒号分隔开的路径，每一个路径就是一块搜索空间：

```text
PATH = 路径1 : 路径2 : 路径3 : …
```

也就是说，你输入一个命令时，shell 会按顺序遍历 PATH 中的所有路径来搜索你想调用的程序：找到就执行，找不到就报错。

### 路径：绝对路径与相对路径

Linux 当中的路径，大致就是这样一个字符串：里面有一堆斜杠，斜杠中间夹着一串文件名或文件夹名。这里要区分两个概念——Linux 有两种路径，绝对路径和相对路径，其实 Windows 上也差不多。

绝对路径以斜杠开头，而这个斜杠本身也是一个路径，它叫根目录。相对路径一般以 `./` 开头——一个小数点加一个斜杠——表示从当前路径出发去索引你想要的路径；绝对路径则是从根目录出发。

那"当前路径"是什么？就是终端提示符里冒号后面的那部分，表示你现在所在的位置，相对路径都以它为起点。

查看当前路径用 pwd 指令：输入 pwd，它就会输出当前路径的完整名称。切换当前路径用 cd：cd 后面跟一个路径，绝对路径、相对路径都可以：

```bash
pwd             # 查看当前路径的完整名称
cd /            # 直接切到根目录
cd ./home/xjr   # 用相对路径切换
cd home/xjr     # ./ 可以省去，效果相同
```

> **易错点**：想用相对路径时，千万不要用斜杠开头——斜杠开头意味着"从根目录从头开始找"，那就不是相对路径了。

此外还有一些特殊的路径写法：

| 写法 | 含义 | 类比 Windows |
| :--- | :--- | :--- |
| `.` | 当前路径 | — |
| `..` | 父路径，也就是返回上一级 | 资源管理器的"向上"按钮 |
| `-` | 上次到达的路径 | "后退" |
| `~` | home 文件夹所在的路径，即你的用户文件夹所在位置 | — |

在我这台机器上，`~` 就是 `/home/xjr` 这样一个路径。

### 一切皆文件

这里要提一个 Linux 的宗旨：一切皆文件。它会把所有资源都视为文件来管理——包括所有的硬件设备，甚至是网络。比如你想通过网络远程给另一台设备发送一些消息，方式其实也是往某一个特殊的文件里写这条消息；写完，这个消息就发送过去了。这个的学术名词叫网络套接字（socket），你们以后学计算机网络的时候会正式接触到。

它带来的好处是：不同类别的资源可以用同样的方式管理——我只需要按照管理文件的那一套方式，去管理所有资源就可以了。

举个具体的例子。/sys/class 这个目录下，每一个文件夹都代表了一种硬件设备，里面的所有文件可以查看设备的各种参数。进去看看：

```bash
cd /sys/class
ls
cd power_supply
cat uevent
```

ls 一看，里面有很多东西，比如 power_supply 就是我的电源，还有很多乱七八糟的条目——有些我也不具体知道是什么。进到 power_supply，里面是电池相关的信息，其中有一个 uevent 文件，用 cat 查看它的内容，就能看到和电池相关的各种参数：类型、是否满电、容量等等，非常丰富。

所以你看，我的电池在 Linux 系统下就是一个文件，就这么简单。

### 重定向与管道

讲完路径，再来介绍管道。先把概念分清：文件重定向和管道是两个东西。

#### 重定向：改变输入输出流

shell 当中每个指令都有输入和输出流，默认情况下都是标准输入输出（standard input / output）——也就是直接从屏幕读取输入、直接输出到屏幕。如果你想让某个指令输出到文件，或者从文件里读入一些信息，就用小于号和大于号：

| 写法 | 作用 |
| :--- | :--- |
| `< 文件` | 改变输入流：从这个文件里读取信息 |
| `> 文件` | 向这个文件里写东西（默认清空文件、从头开始写） |
| `>> 文件` | 在文件末尾追加，原来的内容保留 |

#### 管道：把 A 的输出接给 B 的输入

管道用一根竖线 `|` 表示：竖线前面是一条指令 A，后面是另一条指令 B，意思是把 A 的输出作为 B 的输入。左边 cat 后面跟一个文件名，本来是把文件里的所有内容输出到屏幕；右边 grep 后面跟一个字符串，表示在给它的输入当中查找这个字符串。两者用管道接起来：

```bash
cat blank.txt | grep eth
```

cat 读出的内容不会输出到屏幕，而是传给 grep 去查找。光说有点抽象，做个示范：先看 cat 的功能——blank.txt 里就一行 something。接上管道后，在内容里找 eth：something 这个词里正好含着 eth，回车你就会发现 eth 被标了出来，找到了；如果找一个不存在的，比如 etb，那就什么都不会输出。

### 权限位：读懂它，再修改它

接下来是比较重要的一个话题：Linux 下的用户权限。

先用 ls 加一个选项：`ls -l`，查看当前路径下所有文件和文件夹的更多信息。只输入 ls 的话，只会孤零零地显示文件名，了解不到任何其他信息；加上 `-l` 就能显示出各种信息，每行开头那串由 r、w、x 和减号组成的字符串，就是权限位。

#### 权限位怎么读

第一位叫文件种类，有几种可能：l 表示软链接（link 的缩写），d 表示目录（directory 的缩写），减号就是一般的普通文件。后面九位每三位一组：

```text
-  rwx  rwx  rwx
|   |    |    |
|   |    |    +--- 其他用户权限
|   |    +-------- 组权限
|   +------------- 用户权限
+----------------- 文件种类
```

也就是：第一位标文件种类，后面三组从左到右依次是用户权限、组权限、其他用户权限。用户权限指当前这个用户可以对这个文件做什么；组权限指当前用户所在的这个组可以对它做什么；其他用户权限指其他组的其他用户可以对它做什么。权限位之后还有两个名字：一个是用户名称，标明这个文件是哪个用户创建的；另一个是组名称，标明文件所有者所在的组。

那 r、w、x 和减号分别是什么意思？

| 字符 | 全称 | 意义 |
| :--- | :--- | :--- |
| r | read | 读取权限：可以查看这个文件 |
| w | write | 写入权限：可以往文件里写、修改这个文件 |
| x | execute | 执行权限：可以把这个文件当作可执行文件来运行 |

#### chmod 方式一：逐位加减

权限是可以修改的，命令叫 chmod——全称 change mode，用它去修改权限位。修改方式有两种，命令最后都跟一个文件名，表示要修改的对象。

第一种是逐位修改，中间是一个三字符的字符串：

| 位置 | 取值 | 含义 |
| :--- | :--- | :--- |
| 第一个字符 | u / g / o / a | 改用户权限 / 改组权限 / 改其他用户权限 / 三组一起改 |
| 第二个字符 | `+` / `-` | 添加这个权限 / 剥夺这个权限 |
| 第三个字符 | r / w / x | 读 / 写 / 执行 |

u 是 user，改的是权限串第一组那三位；g 是 group，改的是中间那三位的组权限；o 同理，改最后一组；a 是 all，表示所有权限位一起改——用户权限、组权限、其他用户权限全包括。

做个示例。比如我想取消 copy.py 这个文件所有用户的执行权限：所有用户对应 a，去除权限用减号，去除的是执行权限所以第三个字符写 x，最后跟上文件名：

```bash
sudo chmod a-x copy.py
```

这里需要一个 sudo——因为 copy.py 不是个简单文件，它是 root 账户创建的文件，改它的权限需要更高的权限。root 是什么，马上就讲到，这里先用 sudo。改完再用 ls -l 看，copy.py 权限位里所有 x 的地方都变成了减号；再把执行权限加回来，那些 x 位又都亮回来了。

#### chmod 方式二：三位八进制数

第二种方式更直接：中间那三个字符换成一个三位的八进制数，它的每一位分别对应第一组、中间一组、最后一组权限位。方法是：有权限记为二进制中的 1，没权限记为二进制中的 0；三位三位地看，把每组的二进制数换算成一个八进制数，填到八进制数的对应位上。

比如权限串 rwx rw- r-x 对应的就是八进制 765：

```text
rwx  rw-  r-x
111  110  101
 7    6    5     -->  765
```

每一列从上到下就是：权限符号、对应的二进制、换算出的八进制位。试一下，还是改 copy.py，这次用第二种方式：

```bash
chmod 765 copy.py
```

再用 ls -l 看，权限串就变成了 rwx rw- r-x，跟刚才推出的 765 完全对应。看完再改回去。

### root 与 sudo：一个经典的坑

Linux 系统里总会存在一个最高的用户，这个用户一直存在，它叫 root。root 永远具有最高权限，想做什么都可以——换句话说，其他用户所能做的所有操作，都是 root 能做的操作的子集。

我们现在的用户是 xjr，它不是 root。如果想以 root 的身份去做某些事情，就在命令前面加一个 sudo。它的全称其实是 super do：super 就是超级、超级管理员的意思，后面再加上你想调用的命令就可以了。

但 sudo 并不是万能的。我们的习惯是：某个指令运行失败了、提示权限不够，就在前面加个 sudo 再跑一遍——多数时候真能过，但它不完全是这么回事。看一个反例。

blank.txt 是 root 创建的文件，权限位上只有 root 用户和 root 组下的用户有 w 权限，其他用户没有写权限——我们现在就属于"其他用户"这个范畴，直接写是写不进去的。那么问题来了：**在不修改拥有者、也不修改权限位的前提下，怎么往 blank.txt 里写入内容？**

先按没有权限约束时的常规操作来：echo 一个字符串，然后重定向到 blank.txt 里：

```bash
echo something > blank.txt
```

一试，permission denied——只有 root 才有写权限，被拒绝了。那就按习惯加个 sudo 再试：

```bash
sudo echo something > blank.txt
```

发现也被拒绝了。这是为什么呢？

因为 sudo 只管得到 echo 这一条命令，管理员权限只给了 echo；而后面的重定向写入这个操作，是由 shell 本身来做的——shell 不是以 root 身份登录的，它自己没有 root 权限，自然改不了 blank.txt。

> **易错点**：`sudo` 提升的只是紧跟其后那一条命令的权限；`>` 这类重定向的接线工作始终由 shell 亲自完成，shell 不会因为你写了 sudo 就变成 root。

正确做法是换一种方式，把"写入文件"这个动作交给一条真正被 sudo 提权的命令：

```bash
echo something | sudo tee blank.txt
```

这里引入一个新命令 tee：它从标准输入接收输入的字符串，后面跟一个文件名，把接收到的内容写进这个文件。在这条命令里，前面 echo 的输出 something 通过管道进入 tee 的标准输入，tee 再把它写到 blank.txt 里；而 tee 被 sudo 提了权，有 root 权限去修改这个文件，写入就成功了：

```text
echo 的输出 ──> tee 的标准输入 ──> tee（被 sudo 提权）──> 写入 blank.txt
```

读这条链就能看出关键：整条写入路径上被提权的只有 tee，而它恰好就是真正执行写入的那个角色。这次不再报错，something 成功写进了 blank.txt。

### 包管理：dpkg、apt 与换源

下一个概念是包管理。用一台新电脑的时候，它一般不会自带很多软件——就是个空壳。我们通常需要用 shell 去下载各种各样的软件并安装，才能使用。

安装方式有两种。第一种最主流：从网站上手动下载一个 .deb 软件包（扩展名就是 .deb），下载完打开 shell，输入 dpkg 命令，后面加上 `-i`——i 就是 install：

```bash
dpkg -i 软件包.deb
```

它的操作就是把这个 .deb 文件解压并安装。但这个方法其实很不好用：首先你得自己从网上找软件包；自己找的包不一定靠谱，有可能携带病毒什么的，硬装上去可能对电脑造成损害。所以我们推荐第二种，用 apt 指令做包管理。想安装一个名为 xxx 的软件包，就用：

```bash
sudo apt-get install exa
```

这个软件包的名称其实是需要你去调研的东西，不是很好知道。比如 exa：我这台电脑上本来没有 exa 这个命令，输入 exa 之后它会报错，并提示你可以 try 一下 apt install exa，照着装就行。当然提示的名称也不一定就对，总之这个名称可能需要去网上查一下。你给出名称之后，apt 会去一个指定的地方——Ubuntu 的源服务器——去找，所以找到的都是官方提供的软件包，下载下来的软件一定是安全可靠的。

因为默认从 Ubuntu 的服务器上下载，在国内可能会比较慢。想加速可以换源，比如换成清华源——换源教程在课件给的链接里，点开照做即可。切换源之后，需要执行：

```bash
sudo apt-get update
```

update 一下，才能真正切换成新的源。以后再去执行 install 命令，就都是从新源上获取软件包再安装了，一般都比较快，不会出现网络卡顿的情况。

> **提示**：课件的换源说明写得比较早，当时还没有北大源，所以写的是清华源；现在已经有北大源了，推荐大家直接搜"北大源"来用。

### 变量：shell 变量与环境变量

下一个概念是变量。

#### 声明、访问与空格陷阱

变量的声明和赋值其实跟 Python 有点像：直接写一个名称，接上等号，后面接上它的值：

```bash
fu=bar
```

前面 fu 是变量名，后面 bar 是它的内容，一个字符串。

> **易错点**：等号两边不能加空格。空格在 shell 里是分隔符：如果写成 `fu = bar`，shell 会把 fu 理解为你要调用的命令名，把等号和 bar 作为两个参数传给这个"命令"——这肯定不是你想要的，这一行多半会报"没有 fu 这个命令"的错误。

赋值完想访问这个变量、查看它的内容，方法在讲环境变量时介绍过：在前面加一个 dollar 符号：

```bash
echo $fu
```

它就会显示出 bar。实际上，$fu 的本质是一次字符串替换：shell 会把 $fu 这个部分替换成 bar。所以在命令行里输入 $fu，完全等价于直接输入 bar。

#### env 与 set：两份变量清单

有一类特殊的变量就是环境变量。用 env 指令可以查看所有的环境变量：能看到很多很多条，每一条都是"变量名=值"的格式。

还有一个命令 set。set 会显示更多的东西，非常得多——里面也包含 env 显示的那些变量。所以 set 查看的是环境变量与 shell 变量的并集：它不仅包含环境变量，还包含当前 shell 环境下的所有变量。

环境变量和 shell 变量是相互隔离的两个概念。刚才新建的 fu=bar，只会被添加到 shell 变量的集合里，不会进环境变量的集合。shell 变量有点类似"每一次进程里加载出来的变量"：每次打开 shell，它都会重新加载。验证很简单——把 shell 关掉再重新打开（我现场就是关掉又打开了 WSL），再 echo $fu，它就没有了，输出是空的，明明刚才还是 bar。

所以 shell 变量在退出 shell 的时候就会被清空；而环境变量，则是每次启动 shell 的时候必然加载到当前 shell 环境里的变量——所以它才叫"环境"变量。

| | shell 变量 | 环境变量 |
| :--- | :--- | :--- |
| 典型例子 | `fu=bar` 这样直接赋的值 | `PATH` 这类系统级变量 |
| 生命周期 | 退出 shell 即清空 | 每次启动 shell 必然自动加载 |
| 查看方式 | `set`（环境变量与 shell 变量的并集） | `env` |

#### export 与 .bashrc：把变量固化下来

想把某些变量加进环境变量，用 export 命令：在赋值语句前面加上 export：

```bash
export fu=bar
```

这样 fu 就被添加到环境变量里去了。但注意，这个添加也是一次性的：它只发生在当前这个已经启动的 shell 里——下次重启 shell，环境变量里还是不会有 fu。

想永久添加也可以做到。这个方法的直观意义是：每次启动 shell 的时候，都先执行一下这条 export 语句——那自然每次启动之后，环境变量里就都有这个变量了。具体做法就是把 export 赋值语句放进 home 文件夹下的 .bashrc 文件里。

.bashrc 因为是点开头的，在 Linux 下是一个隐藏文件，平常的 ls 看不到它，要用 `ls -a` 才能看到。这个文件的内容其实就是一堆 shell 代码——一堆 shell 命令。想永久加入某个环境变量，在这个文件的末尾追加一条 export 语句就好。

加完之后如果想让本次就生效——刚加完这条语句它是不会执行的，要重启 shell 窗口才执行——不想退出窗口的话，就用 source：

```bash
source .bashrc
```

它就会执行 .bashrc 里所有的命令，也就把刚才加进去的环境变量加载进来了。

### 命令替换与进程替换

接下来是命令替换和进程替换这两个操作。以我个人的经验看，它们不是特别常用，但值得介绍一下。

有时候我们希望把一条命令的输出结果拿来当参数用。方法：dollar 符号后面跟一个括号，括号里放你想执行的命令，即 `$(命令)`。它做的事情是：把括号里的命令执行完之后，用它的输出替换掉整个 `$(...)` 串。这样一来，命令的执行结果就被放进了命令行，成为其中的一部分。

还有一个类似的功能：小于号后面跟一个括号，括号里填上一条命令，即 `<(命令)`。它的作用是：把命令的输出重定向到一个临时文件——这个文件是临时的、虚拟的，并不会真的在你的某个目录下创建出来，但你可以把它当作存在的文件来用；整个 `<(命令)` 会被那个临时文件名自动替换掉。

它最典型的用法：diff 可以比较两个文件的差别，但如果我想比较的不是两个文件，而是两条命令的输出——比如比较两次 echo 的输出是否一样——diff 后面只能跟文件名，怎么办？用进程替换，把每条命令的输出都变成一个"文件"，diff 就能用了：

```bash
diff <(第一条命令) <(第二条命令)
```

现场就是这么演示的：比较两次 echo 的输出是否一样，一条输出 hello world，另一条内容略有不同，diff 把两者的差异显示了出来。

### 脚本语言与编译语言

后面还有一个概念：shell 脚本。先介绍一个更大的概念——脚本语言。

脚本语言是通过解释器运行的一种语言。bash——就是 shell 所用的那种语言——还有 dash、Python，都是脚本语言。它是边执行边编译的：你可以理解为解释器先读取一行的指令，立刻开始执行这一行；执行完再读下一行、执行下一行。Python 和 bash 都是这样的工作流程。

另一种语言叫编译型语言，就是需要预编译的语言，典型的比如 C 和 C++。它的工作流程很不一样：需要提前有一个编译器，把你的程序源文件读进来，转换成另一种语言——机器语言。编译器先把你的语言转化成一种中间表示，中间表示再转化成汇编语言，汇编语言再转化成二进制的机器语言，最后用这些二进制机器语言生成一个 .exe 文件——在 Linux 下没有 .exe 这个后缀，就是生成一个可执行文件：

```text
源代码 ──> 中间表示 ──> 汇编语言 ──> 二进制机器语言 ──> 可执行文件
```

这条流水线由编译器提前做完，得到的可执行文件完全是二进制文件。你需要单独去运行这个可执行文件，才能真正运行你程序的内容——前面的编译过程本身并不会执行你的程序。而解释器那边是边编译边执行。这就是脚本语言和需要编译的语言之间最大的差别。

### shebang：给脚本指派解释器

如果我们想写一个脚本，需要用一个符号：shebang——一个井号加一个叹号（`#!`），作为这个文件的开头。系统看到它，就会把这个文件解析成一种脚本来对待。

shebang 后面跟什么呢？跟一个路径。这个路径的含义是：我想用哪个解释器去运行这个脚本。如果这个文件是 Python 脚本，后面就跟着 Python 解释器所在的路径；如果是 bash 脚本，就跟 bash 解释器的路径。书写格式是：先写解释器的路径，空格再跟上解释器的名称。

实际运行之前，一定要记得用前面学过的 chmod 给这个文本文件加上可执行权限。加上之后，就可以直接输入文件名来运行了。一般来讲，想运行一个 Python 文件，你需要先输入 python、空格、文件名；现在有了 shebang、权限位也设好了，直接输入这个文件的名字，就可以让 Python 解释器去解释运行它。

这里还有一个很巧的设计：Python 和 bash 里，井号（#）都是注释符号。所以解释器去读取这个脚本文件的时候，会把第一行忽略掉——第一行写的那个路径即使不符合语法也不会被看到，很巧妙地就绕过去了；而系统层面，这一行又起到了引导"用哪个解释器来运行"的作用。一行两用。

### 把 copy.py 跑起来

来看现成的例子。有一个已经写好的文件叫 copy.py，先看看它长什么样：第一行是 shebang，后面跟的是 python3 这个解释器的路径——按刚才说的格式，先解释器的路径，空格跟上解释器的名称；底下就是普通的 Python 代码，跑起来会把 hello world 打印出来。

先用 ls -l 检查 copy.py 的权限位：x 位都亮着，说明它有执行权限。那就可以直接执行：

```bash
./copy.py
```

它就把 hello world 输出出来了。这个过程是这样的：输入 ./copy.py 之后，shell 先去读取 copy.py 这个文件，发现第一行有 shebang 符号，于是到那个路径下找到 python3 解释器，然后运行 python3 copy.py——它实际执行的就是 python3 copy.py 这么一条指令。

这样一来，写好一个脚本文件之后，就可以直接双击运行，或者在终端里 ./copy.py。不过这里要纠正一句：直接敲 copy.py 是不行的，还是要带上前面的 ./——这样已经方便很多了，不需要在前面总带着解释器的名称，你可以把它当一个可执行文件一样看待。

为什么必须带 ./？有同学正好问到这个问题。我一开始猜是 shell 本身的特性，想了一下才反应过来——答案就在前面讲过的 PATH 里：你的环境变量 PATH 里没有当前路径，所以 shell 在里面搜索不到 copy.py 这个文件，就会显示 command not found。如果把当前这个路径添加进 PATH，它就能找到 copy.py，你就可以省去 ./ 了。所以 ./ 起到的就是指示"这个路径到底在哪"的作用：. 表示当前路径，./copy.py 就是当前路径下的 copy.py。

在 bash 里输入 ./文件名，shell 会把这个文件当作可执行文件直接去运行；如果它没有可执行权限，就会报错。比如 ./blank.txt——你看，permission denied，因为我没有可执行权限；即便 sudo 也不行，root 用户也没有这个权限——整个文件的权限位上一个 x 都没有，谁都执行不了它。

## Windows 与它的两个 Shell：CMD 和 PowerShell
> 对应块：BLK03 | 覆盖分集：P02 | 块标题（分集名）：《Windows+cmd+PowerShell》

上一讲我们把 Linux 系统和 Linux shell 的基本用法过了一遍；这一讲接着往下走，讲 Windows 系统，以及它底下两个最常用的 shell：CMD 和 PowerShell。Windows 大家天天都在用，但天天用不等于了解它——它是一个什么样的家族？CMD 和 PowerShell 到底是不是一回事？变量怎么设、脚本怎么跑？这一讲就把这些一次讲清楚。

### 先认识 Windows：一个闭源的图形化操作系统家族

Windows 是一组由微软开发、经营、销售的图形化操作系统家族。它和 Linux 最大的差别就在这里：Linux 是开源的，而 Windows 从里到外都握在微软一家手里。另一个关键词是"家族"——Windows 不是一个单一的操作系统，而是一整棵系统树。我们用一张结构图来看它：

```text
Windows 操作系统家族
├── Windows 9x —— 最老的一支（95、98……数字就是发布年份）
├── Windows IoT —— 旧名 Windows Embedded，装在嵌入式设备上
└── Windows NT（New Technology，取代 9x 的现代内核）
    ├── Windows Server —— 服务器线：NT 3.1~4.0、2000、2003 … 2022
    └── 其他（others）—— 个人电脑线：XP → 7 → 10 → 11
```

这张图从上往下读。最老的 9x 一系年代感十足：9x 里的数字就是发布年份，Windows 98 就是 1998 年发布的。IoT 大家应该都知道，是 Internet of Things（物联网）；Windows IoT 的旧名称叫 Windows Embedded，这个家族里的所有系统都是嵌入式系统——安装在一些比较微小的设备上，比如你的手表、可穿戴设备，甚至眼镜也算。而我们现在所用的系统，其实都属于 Windows NT 这个家族。

NT 家族内部分两类。一类是 Windows Server，就是安装在服务器上的 Windows，从老到新有 NT 3.1 到 4.0、Windows 2000、2003，一直到 2022。不过就我们科研来讲，Windows Server 可能没有 Linux Server 那么常用。另一类我把它叫作 others——说实话，我没有找到一个官方的名词能够概括这一类操作系统：它们就是装在我们个人电脑上的那些 Windows。这一支从世纪之交的 Windows XP，到 Windows 7、Windows 10——我标出的这三个名字，应该可以说几乎没有人没听过吧；你如果出生得晚、没赶上 XP，那就从 7 开始用起。

微软的更新节奏也值得留意：Windows 7 推出一段时间之后，微软其实已经停更了 Windows XP；同理，Windows 11 推出一段时间之后，Windows 7 也被完全停更——相当于强制大家更新系统。现在我们有 Windows 11，而且用过电脑的人都有一定经验：更新提示经常在推荐你把电脑升级到 Windows 11。我个人认为，它之后应该也会用 Windows 11 全面取代 Windows 10。

至于 Windows 的发展史，从图标的发展史就能窥见一斑：1985 年的 Windows 还依附在 DOS 系统上，图标都是字符的；到 1991 年才出现我们很经典的四格窗口标志；再往后是 2001 年的 XP，然后是 Win8、Win10 以及 Win11。一路看下来，这个图标演化史也挺有趣的。

### 为什么要用 Windows，又怎么获得它

先说优点。Windows 最突出的优点是图形化界面非常强大；其次是用户基数大——基数大，意味着在这个基础系统之上开发的软件也会很多，所以很多东西它只支持 Windows，那你就不得不用 Windows，就是这么个事情。再者它有很强的兼容性，硬件兼容、软件兼容都挺强；还有就是简单易用，图形化界面非常 interactive、非常简便。

应用场景呢？我觉得可以说是 almost anything。尤其在图形学里，大家日常使用的电脑基本都是 Windows 系统——因为在这个系统上做图形化的开发应该是最简单的。

至于访问 Windows，我觉得没必要多说。你正常买的电脑，比如联想的，就会自带一个 Windows——你买的那个价钱里面就包含了正版系统。如果你实在是买了一台从零开始、自己攒的机器，没有系统，那也需要先去购买 Windows，然后用启动盘安装——这和 Linux 一样。另外还可以使用虚拟机，在虚拟机里放一个 Windows。用虚拟机的好处主要是什么？你可以把程序放到虚拟机里运行，就像放在沙盒里一样：如果这东西带一点病毒，它破坏的只是虚拟机的环境，不会影响到你外面这个系统的环境。所以在运行一些来源不确定的程序时，这样更安全。
### 先划清界限：CMD 不等于 PowerShell

在讲 CMD 和 PowerShell 的用法之前，我们先立一个不等式：CMD ≠ PowerShell。上一讲就有同学问：CMD 和 PowerShell 难道不是一样的吗？为什么要分开讲？实际上它们非常不一样——可以说是完全独立的两个东西，没有任何包含关系。

那为什么把 CMD 命令敲进 PowerShell 里，看上去也能 work、行为还和 CMD 里非常相似？这不是因为这些 CMD 命令属于 PowerShell，而是因为 PowerShell 提供了一种叫 alias（别名）的机制：它把 PowerShell 中的一些指令映射到 CMD 那些简写的形式上。你在调用 CMD 指令的时候，它会被自动转化成对应的 PowerShell 指令——而那些 PowerShell 指令和 CMD 指令的行为又非常相似，于是看上去 CMD 像是 PowerShell 的一个子集。但实际上不是这样。

不过，从"能干什么"的角度，你确实可以说 CMD 被包含于 PowerShell：CMD 能做的事情，几乎所有事情 PowerShell 都可以干。

两者的实质差别有这么几点。第一，PowerShell 的每条命令叫 commandlet，每条都比 CMD 的命令复杂——它们其实都是一个小型的命令程序。第二，设计理念不同：CMD 本质上只希望你用它干一些很简单的事情，比如批处理——一堆文件要做重命名、拷贝这类操作；PowerShell 支持的功能就复杂得多了，它可以说就是一种高级语言：能运行复杂脚本，而且是面向对象的——没错，它和 Python 一样是面向对象的语言，CMD 则不是。第三，最能体现这个差别的一点：CMD 里指令之间传输信息只靠字符串；PowerShell 则可以把一个整个的结构化对象在指令之间传递。

总的概括来说：PowerShell 比 CMD 要强大得多，还支持跨平台和一些可扩展性。它唯一的"不足"是提出得比 Windows 晚，很早很早的微软 Windows 版本不支持 PowerShell——但这其实不是什么问题，没有人才会去用那些系统了。CMD 就不一样，它是系统自带的 shell，和系统同时出现，所以哪儿都有它。

### 把 Shell 打开：三种启动方式

大家可以跟着我一起，把电脑里的 CMD 或 PowerShell 启动起来。我建议大家先启动 CMD，因为有些命令在 PowerShell 里的行为跟 CMD 里表现的不太一样，我们先以 CMD 为准。

启动方法大家应该很清楚了：用开始菜单就可以启动；或者用 Win+R，输入相应的 shell 名称回车。还有一种很便捷的方式：如果你已经打开了一个文件夹、想在这个文件夹里直接打开 PowerShell——按住 Shift，再右键单击文件夹的空白处，这时菜单里会多出一个选项"在此处打开 PowerShell 窗口"。点开之后你会发现，PowerShell 的当前路径已经被直接设定成了这个文件夹的路径，省得你再 cd 一层。

另外，可能会有很少很少一部分同学需要安装或更新 PowerShell——电脑上没有 PowerShell 基本不可能；你如果实在需要，就先打开 CMD，然后去官网安装一下。
### CMD 命令行的格式与它的怪脾气

#### 格式、路径与选项

CMD 命令行的格式和 Linux shell 非常相似：第一个单词是命令——你想让它做的事，后面跟上若干个参数。每个参数可以是三种情况之一：文件名、路径、选项。文件名的用法和 Linux 一样；路径和选项则有些门道。

先说路径。Windows 下的路径是用反斜杠 `\` 连起来的，而 Linux 用的是正斜杠 `/`（也就是除号）。在 CMD 里我建议大家都用反斜杠，因为这东西其实挺迷惑人的：有的时候你用正斜杠它可以 work，但在另外一些情况下用正斜杠它就报错了；而反斜杠一直都是支持的。所以大家习惯一下，用反斜杠来打路径。

另一个和 Linux 的不同点：Linux 不是有一个统一的根目录吗？Windows 不太一样——它把磁盘分区直接暴露给了用户，所以分出了 C 盘、D 盘、E 盘这种东西。Windows 路径的开头是一个盘符：一个字母加一个冒号，比如 C:、D:。

再说选项。选项一般以正斜杠或者减号开头，后面一般跟一个字母（也有跟多个字符的情况），作用类似 Linux 当中的选项：有些选项后面会跟一个别的参数，这个 argument 有特殊的含义；也有的选项本身就是一个类似开关的东西——写上这个选项表示开关打开，没有就表示关闭。看一个例子：

```bat
erase /f myfile.txt
```

erase 是删除，/f 是强制执行的意思，这条指令的作用就是强制删除 myfile.txt 这个文件。

对了，还有一个 cd 的坑要提前说：CMD 的 cd 指令如果想切换盘符，是没办法直接切过去的——你需要再单独输入一下盘符，它才能真正切换到你想要的那个路径下。

#### 空格与引号不按常理出牌

CMD 不像 Linux 那么好用的一个重要原因：它有些地方空格和引号的含义是不规律的。我实际敲给大家看。

先看 echo。我敲 `echo hello         world`——在 Linux 里，这代表 hello 和 world 是两个参数，输出的时候 shell 会自动在两个参数之间加一个空格。但这里不一样了：不管我敲多少个空格，它都会原样不动地输出。也就是说，echo 后面的所有内容——你输的是空格还是非空格的字符——都会被当成字符串，所以它就这么输出来了，很奇怪。

那我加上引号呢？引号也会被原样输出来——它把引号也看作 echo 后面跟的那个字符串的一部分了。

> **易错点**：在 echo 里，引号不表示"括起来"，会被原样打印；这与大多数指令对引号的处理不一样。

但在别的地方，引号又可以正常表示"括起来"的意思。比如我想切换到一个路径，这个路径下有一个我故意设置的、包含空格的名字 space dir——这时加上引号就是没有问题的，它相当于把 space dir 括到了一个子串里：

```bat
cd "space dir"
```

在所有 CMD 里涉及路径的地方，只要路径里包含空格，你都可以用引号括起来，这是没有问题的。唯独在 echo 里，引号就失去了它的含义。所以在 CMD 里面，每条指令的"协议"、它的规则不太统一——这也是它没有 Linux 那么好用的地方。

#### 重定向、管道与常用命令对照

CMD 也支持重定向和管道，和 Linux 一样。上一讲我留过一个小问题：重定向一个指令的输入、重定向指令的输出、在文件末尾追加、管道，分别是什么符号？大家可以自己想一下——这里我就不再重提了，记不清的话回上一讲补一补。

另外，我准备了一张 CMD 常用命令的表（放在课件里），最右边一列是功能类似的 Linux shell 命令。注意这里的"功能类似"只是类似，并不能说是完全一样——具体有什么差别，你们可以自己去命令行里输入对比一下。你可以发现 CMD 和 Linux shell 的使用方法其实非常类似，因为每一个操作基本都能找到对应的指令。这张表大家课后去看一下、把表里的指令记住就好了——基本上你也就只会用 CMD 干这么多事了，更高级的功能，一般写个 Python 脚本会方便很多。
### 账户与权限：从用户到文件

#### 三类账户与"以管理员身份运行"

Windows 里的账户分为三类不同权限：

| 账户类型 | 能做什么 | 不能做什么 |
| :--- | :--- | :--- |
| 管理员账户 | 拥有最高权限，可以完全使用计算机，并管理其他账户（类似 Linux 的 root） | —— |
| 标准用户账户 | 正常访问计算机、执行程序 | 更改其他用户的设置与系统设置；安装新软件 |
| 来宾账户 | 只适用于临时访问，权限最低 | 更改系统设置；安装应用；访问部分私密文件 |

来宾账户我们现在很少用了。它的场景是：你把电脑锁定之后，又想临时把电脑给另外一个人用——那基本上就只能让他用来宾账户。现在的情况是：Windows 有一个 Microsoft 账户体系，如果你把 Microsoft 账户绑定到电脑里、而且电脑里只有你一个 Microsoft 账户，那你基本上就是有管理员权限的。

当然，我们正常使用的时候，还是以标准用户账户的身份去做的。你肯定遇到过这个情形：从网上下载了一个安装程序，双击运行的时候，它会弹出一个窗口让你授权"能不能运行"——其实就是让你以管理员身份去授权它。如果你这个账户没有管理员权限，那就授权不了，或者说需要输入管理员的密码才能够授权。

那如果我想做类似 Linux 里 sudo 的操作——提升我这条指令的权限——在 Windows 里怎么办？方法就是：在打开 CMD 或者 PowerShell 的时候，右键单击它，选"以管理员身份运行"就可以了。任何程序其实都可以以管理员身份运行，这样你就相当于给了那个程序管理员的权限，它就可以任意地操作你的电脑了。所以在做这个事情之前，你也得确认：这个程序没有攻击性、不会伤害你的电脑。

#### 文件的访问控制列表（ACL）

刚刚讲的是用户权限，接下来是文件权限。Windows 管理文件权限的方式叫访问控制列表，英文名 Access Control List，缩写 ACL。要理解它，先要知道文件权限有两种管理方式：一种是 file-centric（以文件为中心），一种是 user-centric（以用户为中心）。user-centric 相当于在每一个用户底下记录、维护一个列表，表示"我这个用户可以以什么样的权限去操作哪些文件"；而 Windows 这种 file-centric 的方式是：为每一个文件维护这样一个列表，列表里表示"有哪些用户可以访问我、可以以哪些权限访问我"。

> **定义**：ACL（访问控制列表）是挂在每个文件上的清单，记录"哪些用户可以以什么权限访问我"——一种 file-centric 的权限管理方式。

这个访问控制列表怎么查看呢？很简单：右键单击一个文件，点击属性，再点击"安全"选项卡。上面那个框列出的是可以访问这个文件的用户有哪些；你在上面选中一个用户，下面显示的就是这个用户对应的权限。比如 users 组对这个文件就只有读取和执行的权限；而 administrator——管理员账户——就是完全控制的权限。

### CMD 里的变量：set、百分号与 setx

CMD 其实也是有变量的，而且很类似 Linux 的 shell——只是每一处写法都不太一样。

#### 临时变量：set 与百分号

先看赋值。CMD 的赋值跟 Linux 不太一样的地方是：前面要加一个 set。Linux 里直接 `foo=bar` 就可以了；CMD 里你就需要前面加一个 set，写成 `set foo=bar`，表示这是一条赋值语句。

赋完值之后，访问这个变量怎么做？在变量名的前面和后面分别加上一个百分号：`%foo%`。这个的意思就是把这段字符串替换成变量存的那个值。回想一下 Linux 怎么访问变量——是在前面加一个 `$`。

Windows 下也有一个叫 PATH 的环境变量，和 Linux 下的 PATH 是一个意思：我要运行程序的时候，如果在 CMD 里不加任何路径前缀，系统就在 PATH 列出的这些路径里面去搜索我想要的这个程序——搜到了就运行，搜不到就报错。

那如果我想用命令行给 PATH 添加一条路径，要怎么做呢？用这样一条指令：

```bat
set PATH=%PATH%;C:\mytools
```

右边的 `%PATH%` 会先展开成 PATH 当前的值，然后在末尾用一个分号接上我的新路径（这里以 C:\mytools 为例）。你可以先 `echo %PATH%` 看一眼现有的这些目录；执行之后再 echo 一次，就会发现新路径已经连接到末尾了——非常简单。

删除一个变量更简单：把赋值号后面的东西放空就可以了。`set foo=` 后面什么都没有，就表示我要删除这个变量。

那 set 后面什么都不跟呢？它表示查看所有环境变量和当前局部变量——有点类似 Linux 中的 set 命令，列出当前这个 shell 里面所有可以看到、可以使用的变量。set 后面也可以跟一个名称，比如 `set fo`，就表示查看所有变量名中包含 fo 的变量。

要记住：和 Linux 一样，set 做的赋值只会影响当前的 CMD 窗口。无论是像刚才那样修改了 PATH，还是新建了一个变量，关掉 CMD 再启动之后，这些修改和添加就都不存在了。

#### 永久修改：setx 与图形界面

想要永久修改，就要用到 setx 指令。注意它没有等号了：setx 后面跟两个东西，一个是变量名，一个是用引号括起来的值——这个字符串就是它的值。比如我想永久地创建一个变量 foo、值是 bar：

```bat
setx foo "bar"
```

它的操作是添加或修改"当前用户的环境变量"。Windows 里的环境变量是分用户的：有一部分叫当前用户的环境变量，这些是用户之间不共享的；另一部分叫系统环境变量，不管你登录哪个用户，都会有这些环境变量。如果我想修改或添加的是系统环境变量，就在后面加一个 /M 选项就可以了，非常简单。

但是 setx 有些局限：它没有办法永久删除一个环境变量——或者说，CMD 里面就没有这种能删除环境变量的指令。那要怎么删除呢？我们想想：Windows 其实是一个图形化的操作系统，它的任何高级操作都可以用图形化的方式来解决，其实没有必要非用命令行。

用图形界面编辑环境变量的方法：右键桌面上的"此电脑"图标，点属性，再点进去"高级系统设置"，然后点"环境变量"，就可以看到这样一个窗口：上面是用户变量，下面是系统变量。想编辑的话，直接选中一个点"编辑"或者双击就可以了；新建的话这里也有；包括删除也有。我是 Windows 11 系统，Win10 可能会跟我稍微有点不一样，但其实差不多：比如我想改 PATH，就在列表里找到它，双击进去就可以新建、删除、上移、下移；想删掉某个变量，选中它点删除就好了。

所以在 Windows 下很多情况下，你只需要用图形化界面就能解决问题了，没有必要非去用命令行——Windows 的设计理念就是：尽可能地让你用图形化的界面去解决你想要做的事情。
### 批处理脚本：.bat 文件

#### 从建文件到运行

脚本的创建方法：先新建一个空白文档（默认是 .txt 后缀），然后把它的后缀名改成 .bat。bat 是 batch（批处理）的缩写，所以这种脚本文件在 Windows 下也叫批处理文件。

这里有一个 Windows 和 Linux 很本质的差别。在 Linux 下，判断一个文件是否可执行是通过权限位；Windows 也有类似的权限位，但它不是以此为依据判断"是否为可执行文件"，而是看后缀名（扩展名）：如果是 .exe 文件，就默认它是一个可执行文件；如果是 .bat 文件，就默认它是一个用 CMD 这个解释器去解释的脚本文件。

> **注意**：不要把其他类型的文件强行改成 .exe。改完之后 Windows 真的会把它当可执行文件：你双击它，系统就会直接把这个文件内容的二进制看成计算机执行的代码去运行——会试图弹出一个 DOS 窗口然后运行，结果肯定会报错，因为它本身就不是 exe。

有了 .bat 文件，想写脚本程序怎么办？右键单击这个文件，在菜单栏里选"编辑"那一项，点完之后会弹出一个记事本窗口。它其实就是一个文本文件，只不过扩展名换成 .bat 之后，你再去运行这个文件，Windows 会默认调用 CMD 去解释文件里的文本。写入一系列 CMD 命令，保存退出，接下来你双击就可以直接运行了。当然也可以用命令行去调用它：比如用 call 指令后面跟一个 .bat 文件；或者切换到这个文件所在的目录，直接把文件名输入进来，它也可以运行。

#### 两行脚本拆解

来看一个实际的例子，就两行代码——批量创建 file0 到 file5、text0 到 text5 十个空文件：

```bat
@echo off
for /L %%i in (0,1,5) do (echo. > file%%i.txt & echo. > text%%i.txt)
```

逐行看。第一行 @echo off 的意思是：把接下来所有指令的回显提示都关掉——此后所有的指令，无论运行正常与否，都是 silent 的。当然，前提是我保证 echo off 之后的每条指令都是对的。注意这是 CMD 里才有的功能，PowerShell 里没有。

第二行是一个 for 循环。CMD 脚本也像其他高级语言一样，有分支结构、循环结构，而且每一条指令其实都是有返回值的。这个循环的意思是：i 从 0 开始，步长为 1，到 5 结束——要注意，0 和 5 都是包含在内的。do 后面跟的是想要执行的操作；括号里可以有多个操作，之间用 & 分开，这两个操作都会运行。

这里的 echo 后面紧跟一个点（echo.），表示什么都不输出：echo 本来会把它后面的字符串原样输出，紧跟一个点就表示什么都不干、什么都不输出。那它在这里有什么用？用处就在后面的重定向符号上：`echo. > file%%i.txt` 表示把空内容重定向输出到 file%%i.txt 这个文件——如果这个文件不存在，它就会先把这个文件创建出来，然后往里面输出空内容，这就相当于把这个空文件创建出来了。后面的 text%%i.txt 也一样。

还有一个细节：这里的循环变量跟刚才不太一样——刚才是前后各跟一个百分号，这里它又是两个百分号（%%i）。CMD 脚本的这套语法是比较复杂的，想深入学的话，可以去参考 Wikibooks 上的资料。

我双击运行一下这个脚本：你会看到它闪过一个窗口然后退出，这就表示它执行完了。再看目录，多出来了 file0 到 file5 以及 text0 到 text5 这几个文件，任意打开一个都是空的。

清理的时候正好有个小插曲给大家提个醒：我顺手就想敲 rm——rm 是 Linux bash 下的指令！Windows 里面要用 erase 或者 del（delete 的缩写）去执行删除，配合通配符一把清掉：

```bat
erase file* text*
```

这里的星号就是一个通配符，表示匹配任何串——讲 PowerShell 的时候我们还会再遇到它。

#### 学 .bat，还是学 Python？

说实话，我个人不推荐大家去深学这套 .bat 语法——我自己其实也不会。一是因为这个东西学起来比较费时间，二是有更好的替代方案：Python。Python 应该说是比 PowerShell 还要跨平台，几乎所有的系统上都可以运行 Python 脚本，功能也会更强大；而且你想做科研、做深度学习什么的，肯定都离不开 Python，所以学 Python 相当于一举多得——所有东西都可以用 Python 去做。CMD 说到底就是一些很简单的指令，把前面那张对照表里的指令记住就好了；更高级的功能，一般写个 Python 脚本会方便很多。
### PowerShell：动词-名词的命令世界

#### 每条命令都是一个 commandlet

接下来进入 PowerShell。刚才说了，它的每一条指令都比 CMD 的复杂，每条指令有一个别称叫 commandlet。commandlet 的长相也跟 CMD 里不一样：都是一个 Verb-Noun（动词-名词）的组合——你可以把它想成一个动名词短语：前面是我想要执行的动作，后面是我要执行的对象。

有几个很有用的观察指令。第一个是 Get-Verb：它的含义是显示出所有指令的前半部分，也就是 verb 的部分。我运行一下，它会弹出来一大列：第一列就是所有的 verb——你会发现 Get 也在里边，Get 本身就是个 verb——后面还展示了这个 verb 所属的组（group）：Common、Data，还有 Lifecycle、Diagnostic、Communication、Security、Other。

与它相对的相似指令是 Get-Command：输出 PowerShell 里所有内置的指令。运行之后你会发现屏幕刷了好久——它有超级多的指令。随便看一条，比如 Register-EngineEvent：前面 Register 是个动词，后面是个名词——都是这样的动名词结构。

这也让 PowerShell 的指令可读性强了很多。回想 CMD 或 Linux shell：都是用小写字母缩写来代替一个指令，我们很可能需要查阅文档才能知道它什么意思；而 PowerShell 的指令一般看一眼，就知道它大致做的是什么了。

#### 查帮助、传参数、用通配符

然后是 Get-Help，类似于 CMD 里面的 help 指令，用来查帮助文档。我输入 Get-Help 回车之后，也会出来一堆文字——这些就是帮助文档。当然，它只会告诉你怎么使用 Get-Help 这个指令本身；如果你想真正查询某一个指令是怎么用的，就在 Get-Help 后面跟上一个指令：比如我想知道 Get-Command 怎么用，那就输入 `Get-Help Get-Command`，回车之后，它就会把 Get-Command 的语法都展示出来，还有它的别名——gcm，gcm 和 Get-Command 是完全等价的。

PowerShell 命令行的格式也很类似：第一个词是我的指令，后面都是 argument。带名字的参数，参数名要以减号开头——这很类似你写 C++ 或者 Python 里的函数：每个函数都有一些参数，每个参数都有参数名，如果你想给某个名称的参数赋值，就需要以减号开头。比如我要给 Get-Command 指定名称，这个参数的名称叫 Name，那就加上 -Name，后面空格跟上字符串，相当于传给了 Get-Command 的 Name 参数：

```powershell
Get-Command -Name *-process
```

它会把所有以 -process 结尾的这些指令都显示出来。这里的星号是一个通配符，表示匹配任何串都可以，空串也可以。

> **提示**：无论是 CMD 还是 PowerShell，在很多接受字符串输入的地方都支持通配符，有些地方可能还支持正则表达式——刚才删除文件用的 file*、text* 里的星号就是通配符。通配符能让我们很方便地做批量操作，这个大家可以自己去了解一下。

### 对象、类型与别名

#### 用 Get-Member 看对象

PowerShell 是一个面向对象的编程语言，像 Python 一样也有对象这个概念。如果我想查看对象，用 Get-Member 这个指令——但注意它的用法：它是用管道的方式来输入的：

```powershell
Get-Process | Get-Member
```

这条命令的关键在管道里流的东西：Get-Process 这个指令的输出是一个对象——它的输出不再像 CMD 里那样是一个 string 字符串，而是一个更高级的对象；把这个对象通过管道直接传给 Get-Member，Get-Member 就相当于把这个对象的信息展示出来——包括它的属性（property），还有它的方法（method，类似我们的成员函数，是可以调用的）。

我运行一下看效果：首先它会输出 TypeName，也就是 Get-Process 输出的这个对象的类型是什么——这里叫 System.Diagnostics.Process；后面就跟出了这个类型所有的成员，包括 AliasProperty、Event、Method，还有一些 Property 等类别。

PowerShell 里常见的类型，也跟我们的编程语言一样：字符串、int、double（整数、小数）、布尔类型，还有数组；高级一点的包括 DateTime，就是表示时间的一个类型；还有 hash table，就是哈希表；还有文件信息和目录信息这样的一些类型。当然，所有 .NET 的类型它都支持。.NET 也可以理解为一门语言，是一个非常跨平台的语言，可以用来跑各种各样的程序。

#### 别名：Get-Alias 的两个方向

别名机制前面又说了一次：把 PowerShell 的一些指令映射到一个很短小的缩写字符串当中，以后调用那些缩写字符串，相当于直接调用对应的 PowerShell 指令——PowerShell 看上去能支持很多 CMD 指令，就归功于这个别名机制。查看别名与指令名的对应关系，用的是 Get-Alias 这条指令。

我们以 Get-Member 和 gm 为例——gm 就是 Get-Member 的首字母。有两种查询方向。

一是只知道别名、想知道它对应的 PowerShell 指令是什么：用 Get-Alias 加上 Name 参数，输入 gm：

```powershell
Get-Alias -Name gm
```

Name 参数是一个 positional argument（位置参数），它排在第一位，所以 -Name 一般可以省略掉，直接 `Get-Alias gm` 就行。输出里可以看到，gm 所对应的指令名就是 Get-Member。

二是反过来，只知道一个指令名、想知道它短一点的别名（免得每次都打这么长的名称）：跟上 Definition 参数，值为指定的指令名：

```powershell
Get-Alias -Definition Get-Member
```

切记：Definition 因为不是 positional argument，这个东西是不可以省略的！两个方向跑一下，你会发现它输出的是同样的内容，从这些信息当中都能获取到它的别名叫 gm。这应该都很好理解。
### PowerShell 脚本：.ps1

PowerShell 脚本的创建方式跟 CMD 是一样的：新建文本文件、改扩展名——只不过文件后缀不再是 .bat，而是 .ps1，同样是用文本的方式编辑。扩展名改成 .ps1 之后，Windows 会自动调用 PowerShell 去解释、解析你这个文件里的代码。

观察一下 PowerShell 脚本的代码你会发现：大括号、小括号这些符号就一目了然了，它更加接近一门高级语言。还是刚才那个任务——创建 file0 到 file5、text0 到 text5 的空文件——用这样一个 for 循环就可以写完：循环条件里的 `$i -le 5` 表示 i 小于等于 5，PowerShell 的比较运算符都长这样，一个减号接两个字母。把代码输到 .ps1 文件里保存。

运行的时候注意：.ps1 不太能双击运行，你得用 PowerShell 来跑。在 PowerShell 里直接输入脚本文件名——这里有个跟 Linux 一样的规矩：你不加点杠的话，就等于没有指明它的路径，系统会从环境变量 PATH 里去搜索；而 PATH 里没有当前这个目录，所以 script.ps1 就找不到，会报错。加上 `.\` 前缀，就表示我明确指定了它的路径就在当前路径下：

```powershell
.\script.ps1
```

跑完之后再看，窗口里确实多了 file0 到 file5 这些文件，以及 text0 到 text5 这些文件——当然，同样可以用 erase 或 del 配合通配符把它们清掉。

如果大家想学 PowerShell 脚本，可以去参考官方文档。PowerShell 就比 CMD 复杂多了，因为它功能也很强大：跨平台、面向对象的高级语言。但我给大家的建议还是同样的：学 PowerShell 不如学 Python——我们刚才讲的所有操作，用 Python 里一个叫 os 的模块都是可以做到的。

## 把云服务器用起来：SSH 连接、tmux 多路复用与命令行操作
> 对应块：BLK04 | 覆盖分集：P03上 | 块标题（分集名）：《远程控制工具+命令行环境》

大家好，欢迎来到 GAMES002 的第三节课。我是叶开，来自北京大学，这一讲给大家介绍远程控制工具和命令行环境。整节课分两大块：第一块是远程服务器的使用，包括它的介绍、远程控制的基础方法和远程控制的工具；第二块简单介绍一下和远程控制配套的命令行环境，包括命令行参数和 ZSH 这个 shell 的使用——这部分放在后面展开。我们先把第一块讲透：从云服务器是什么讲起，到终端的连接与退出、终端多路复用，再到文件的传输与操作、程序的运行与中断。

### 云服务器是什么、从哪里来

先简单介绍一下远程服务器，或者说云服务器。它其实是用来做高性能计算的：由服务器供应商提供的远端计算设备。有了云服务器之后，你就可以直接通过远程连接来使用这些设备做高性能计算，而不需要自己去管理硬件、配置硬件。

在图形学或者智能科学里，最常见的云服务器就是 Linux 操作系统的云主机。这些主机基本上都具有强大的硬件配置：32GB 以上的内存、多核的 CPU 处理器，以及我们常用到的英伟达显卡，用来做密集的并行计算。

云服务器的来源基本上有两种。一种是通过租赁的方式，从腾讯云、百度云、阿里云、华为云这些服务器厂商那里租，计费方式有按周、按月或者包年之类。第二种来源是找同样的云服务器厂商，但以科研实验室或者个人为单位自行购置服务器，并且自己来维护它——比如放在你的实验室或者工作单位，然后你在家里或者别的地方远程连接这些服务器。

> **结论**：云服务器的意义就是"远程使用"——你不需要带着它跑来跑去，只要有需要，随时可以从远程连接它，获得方便的使用。

不管来源怎么样，我们都要面临同一个问题：需要从远程去使用这台云服务器。也正因为这个特点，很多云服务器其实是没有图形界面的，需要你做终端的连接。当然，现在也有一些云服务器提供图形界面，可以通过 VNC 服务连接到它的远程桌面——这个我们就不介绍了，因为我们主要面向的还是这个场景：当你没有图形界面时，怎么去使用你的云服务器；或者说，当你通过终端去连接云服务器时，怎么把它用起来。

这需要借助命令行和一些辅助软件来完成，概括起来是这几件事：终端的连接、退出，多路复用，文件的传输、查看、编辑、比较，以及最后程序的运行和中断。下面逐一展开。

### 用 SSH 从终端连上去

云服务器的连接，首先就是通过 SSH 在终端进行的。有的云服务器会提供一些其他的连接方式（比如刚才提到的 VNC），但不管怎么样，大部分云服务器一定能通过 SSH，让你在终端去连接。

具体操作很简单：在本地打开一个终端——不管你是 Windows 用户还是 Mac 用户，都可以打开一个 CMD 或者 terminal。现在我们的电脑一般来说都自带一个 `ssh` 命令，直接用它做远程连接就行。

连接命令由三个部分组成：先填你的账号名称，然后加上服务器地址，以及服务器开放连接的端口。这三样东西在你租赁或者购买云服务器的时候，供应商就会提供给你。记住这三个部分，之后你就可以在任意设备上——自己的个人电脑、移动的笔记本——用这条命令做一个连接：

```bash
ssh -p <端口> <用户名>@<服务器地址>
```

服务器地址既可以是一个网址一样的地址，也可以是纯数字的 IP 地址，比如 `162.105.x.x` 这样下去的一串数字。不管什么样的地址，给定端口、地址以及用户名之后，就可以去做连接了：终端会提示你输入密码，你输入正确的密码之后，就会看到提示——已经连接到了远程的服务器上。

这里有一个非常关键的部分：当你连接到远程服务器的时候，你需要一个验证方式来证明你是这个服务器的所有者。一般来说，默认的方式都是你提供一个密码——就像刚才那样，在终端里输入当时租赁时给你的密码。另外还有一种方式是通过密钥：你可以在本地用 SSH 生成一个密钥，以后登录的时候，它会自动判断你有没有这个密钥、这个密钥是否匹配服务器上的一个公钥；如果匹配的话，就不需要输入密码，你就可以自动登录进去。

> **提示**：密码和密钥是两种验证方式。密钥方式配置好之后，登录时由本机密钥与服务器上的公钥自动比对，不用每次再敲密码。

当你通过这种方式登录进服务器的时候，它会告诉你已经成功连接了，上面的一大串信息就是服务器上显示的欢迎内容。更直观的变化在命令行提示符上：登录之前，它是你本机的用户名和本机的电脑地址；登录进去之后，它就会切换成远程服务器的用户名和地址——这时命令行已经在远程的服务器里了。这就是一个终端连接，基本上是比较简单的。

### 退出连接的几种方式

说到连接，肯定也有终端的退出：当我们连接上了之后，怎么从这里退出去。最简单的方式是直接把这个窗口关掉，它肯定会退出。但这不算标准的退出方式——远程终端是"意外地发现"你退出了。更正常的做法是通过快捷键或者命令主动退出，相当于你告诉远程终端"现在你要退出了"，然后远程终端会执行一个标准的退出过程。

主动退出有三种做法：在远程终端界面按 `Ctrl+D`；或者直接输入 `exit`；或者输入 `logout`，都可以退出。退出之后，你会发现你回到了本地的命令行，而且随时可以重新连接回来。

还有一种情况是被动退出。远程连接是需要联网的，你要一直保持电脑的网络连接。所以如果你登录之后闲置了太久、把电脑合上了，或者突然没网了，这个连接在过了超时时长之后就会断开，你在本地会收到一条信息，告诉你"远程主机重置了连接"或者"远程主机关闭了连接"。

这里要特别注意：不管是哪种退出，都会终止终端中所有的子进程。比如你连接上远程服务器之后，在命令行里跑一个程序，一旦终端退出——不管是主动退、直接关窗口还是断网超时——你终端中运行的所有进程都会全部被终止掉。

> **易错点**：终端退出不只是断开连接。终端里运行的所有进程都会一并被终止。

这就带来一个大问题。设想深度学习里我们要训练一个神经网络，训练可能比较久，比如要训练个一天一夜。这个训练命令是我们通过远程连接在服务器上执行的——比如跑一个 `train_xxx` 这样的训练脚本——一旦你把终端关掉了，远程服务器也会终止掉这个训练过程。这对我们来说是不可接受的：你使用远程服务器的主要目的，就是想方便地在它上面做训练，本地只需要通过命令行简单地操作它；要训练一天一夜的时候，你肯定不希望把本机的电脑也一直开着。

那么，怎么样让终端退出之后，终端里运行的进程仍然正常运行呢？这就涉及终端多路复用。

### 终端多路复用：断线了，进程照跑

终端多路复用是我自己会经常用到的一个功能。它主要解决的就是刚才那个问题：关闭远程连接后，原有的进程不会中断，你可以通过一些命令再次恢复出它。除此之外它还有一些其他功能：一是多个用户实际上可以看到同一个会话——你可以跟别人分享你终端里的一些情况；二是你可以在单个窗口下进行分屏。

以 Linux 为例（Windows 的话，我们一般是通过图形界面的方式来操作终端），Linux 下要操作终端，就需要多路复用软件，比如 tmux，或者下面演示会用到的 screen。

#### 会话、窗口与子窗口

以 tmux 为例，它的结构分出三种东西。

**会话（session）**：比如我现在连到远程服务器了，那么我就是一个 session；我退出了，这个 session 就关闭了。一个 session 下可能有很多进程，当我关闭这个 session 的时候，下面的所有进程都被关闭了——这就是我们刚才说的那个问题。

**窗口（window）**：一个会话里可以开很多个窗口，就像我们的浏览器一样。

**子窗口**：在窗口里面还可以做一些更复杂的分屏功能，这个后面会讲到。

用浏览器的类比来说：会话就是浏览器的整个程序，窗口就是浏览器里的标签页，子窗口就是你在标签页里做的分屏。

```text
tmux
└── 会话（session）…… "整个登录进来"的这一层，关掉它，下面的进程全没
    ├── 窗口 0（window）…… 进入 tmux 时默认打开
    │   └── 子窗口（pane）…… 在窗口里分屏后出现
    ├── 窗口 1 ……
    └── ……
```

读图：会话是顶层容器，里面可以开多个窗口，每个窗口还能再分屏出子窗口；关掉会话，整棵树上的进程都会跟着结束。

进入 tmux 之后，注意最下面那行绿色的状态栏：上面有一个 `0` 的标记，说的就是 tmux 默认帮你打开了一个编号为零的 window。

#### 新建、列出与恢复

新建一个会话，就是通过 `tmux new`，然后可以用 `-s` 给这个会话取个名字。比如 `tmux new -s test`，我们就进来了一个新的会话，名字叫 test。

列出全部会话用 `tmux ls`。我这里执行它会告诉你没有正在运行的会话——因为我刚才那个 test 会话已经被我退出了。

说到这里，正好我发现有个快捷键冲突：我这台 Mac 把截屏和录制的快捷键设成了 `Ctrl+B`，跟 tmux 的前缀键撞上了，需要先把系统那个快捷键关掉，才能正常用 tmux。所以这一段我们换 screen 为例来演示，用法是一样的：

```bash
screen -ls    # 列出正在运行的会话，和 tmux ls 类似
```

我这台服务器上已经有一个正在运行的会话，`screen -ls` 会告诉你这个会话是从什么时间开始运行的、它的状态是怎么样。你可以看到，这个会话是我去年 12 月就打开的，一直运行到现在。那么你实际上可以通过恢复的操作重新接上它——在 screen 里就是 `screen -r`。

恢复过来之后可以发现，你恢复出了当时正在运行的那个进程和它的状态：这是我的一个服务器进程，日志还在那里。如果我们不通过终端多路复用的方法去运行程序，那么当我关掉这个终端，或者当我的 Mac 电脑关机了，整个进程就会终止掉；而通过终端多路复用的方式，我们可以暂时地退出这个进程——它告诉我们的是这个进程被挂起了，或者说被隐藏到后台了，而不是像之前那样直接把它退出掉。通过这种方式，我们就可以在服务器的后台去运行一些复杂的进程命令。

#### 组合键与会话操作

那么我刚才到底是怎么样退出那个会话的？这里就涉及到一些组合键，这是 tmux 的一个特殊操作：先按 `Ctrl+B`，这是告诉 tmux"你要开始做一些特殊操作了"；之后它会根据你输入的到底是什么操作，来执行相应的行为。比如 `Ctrl+B s`，就会让你选择切换到哪一个会话。

展示一个例子：先创建一个叫 test 的会话，再创建一个叫 test2 的会话；这时按 `Ctrl+B s`，就可以发现有两个会话可以选，比如从 test2 切到 test。在 test 里按 `Ctrl+B d`，就是断开当前的会话——它会告诉你"你从当前的会话断开了"，但是你还是可以重新连接回去，用的就是刚才提到的接入会话的命令：

```bash
tmux a -t test    # 接入（attach）名叫 test 的会话
```

执行之后，我就又回来了。反正类似的就是这样一个操作；具体使用大家在遇到情况的时候，也可以根据 PPT 的内容，或者自行上网搜索一些资料继续深入。

这里有一组概念务必分清：在 tmux 会话里按 `Ctrl+D` 退出，是一个**终止**——像终止进程一样，真的把这个窗口给终止了；而另一种退出是断开当前会话的连接，把当前会话放到后台去——它可以让你在后台运行一些命令，而不会因为你本机电脑的关机或者其他操作，导致这个进程断开。

| 操作 | 性质 | 会话里的进程 |
| :--- | :--- | :--- |
| `Ctrl+D` | 终止会话 | 被真正终止 |
| `Ctrl+B d` | 断开连接（detach） | 挂到后台，继续运行 |

总结一下，终端多路复用就是为了做这样一件事情：我需要在远程服务器上后台运行一些比较复杂的进程，而不希望因为我本地电脑的关闭，导致这些后台进程断开。

### 文件传输：交给图形化工具

接着是涉及远程服务器的另一个重要内容：文件的传输。这是我们会经常遇到的一个功能——云服务器有它自己的文件系统，我们本地有一些本地的重要文件，想要上传到云服务器上；或者想要在云服务器上进行和本地类似的文件操作，比如传输、查看、编辑。

一般来说，这需要通过额外的软件来进行。常见的有 XFTP 和 WinSCP，这两个软件都可以用来做文件传输。这些软件进行传输用的协议其实都是 SFTP，所以你基本上可以找到非常多的变种或者替代品，选一个顺手的就行。

这里用 WinSCP 做一个简单的示例：界面左边显示的是本地电脑的一个文件夹，右边显示的是远程电脑的文件夹；把文件从左边拖到右边、或者从右边拖到左边，就可以做一些文件传输的操作。

文件的查看、编辑、比较，其实也可以通过上述软件来完成。但有些情况下会比较麻烦：比如要查看远程的某一个文件，实际上你需要先把它下载到本地，然后再在本地打开它，这样有时候显得比较麻烦。

### 终端里的文件命令

所以在终端中，我们有时候也会直接进行文件操作，这就和 Linux 下的一些命令有关了。你可以编写一些 Python 脚本来做，也可以通过 Linux 自带的命令做一些查看、编辑和比较。这里不详细展开，给大家过一遍常见操作。

先 `cd` 到某个地方。最简单的命令就是 `ls`，它可以列出当前目录下都有哪些文件夹；`ls -alF` 可以列出更详细的信息，包括文件的权限、它的所有者、它的创建时间以及它的大小。我们也可以递归地列出目录下所有的文件，比如 `find <目录>`——执行之后你会发现它列了一大串东西，把这个目录下所有递归的文件全部列了出来。

如果不想让它输出这么复杂，我们也可以做一个筛选，列出具有特定文件名的文件——比如只想要以 `.jpg` 为后缀的文件，或者只想要 `txt` 相关的。这时用 `grep` 这个命令做字符串处理就很方便：比如我只看所有路径里包含 `txt` 这三个字母的路径，它就可以给你筛出来——当前文件夹下面所有包含 `txt` 字样的路径都能列出来，你就可以根据这个来做特定文件的筛选。

再比如统计目录占用的空间，用 `du` 命令：它会告诉你当前文件夹占了 56G，其中最大的那个文件夹占了 44 个 G，大概就是这个意思。以及一些统计硬盘剩余空间的命令。还有查看文件的内容——直接在命令行里看，比如 `cat` 某个文件；如果这个文件太长，可以用后面那条查看命令来看。

| 命令 | 作用 |
| :--- | :--- |
| `ls` | 列出当前目录下都有哪些文件和文件夹 |
| `ls -alF` | 列出详细信息：权限、所有者、创建时间、大小 |
| `find <目录>` | 递归列出目录下所有文件 |
| `grep` | 字符串筛选，比如只保留包含 `txt` 的路径 |
| `du` | 统计目录占用的空间 |
| `cat` | 在命令行里查看文件内容 |

这些复杂的文件操作，其实我们不一定要完全掌握，因为它只是提供一种便利性。比如列出目录这件事，你在文件传输的软件里就可以简单直观地看到，不需要通过命令行；统计目录占用空间、递归列出某些文件的文件名，也可以通过编写 Python 脚本或者 C++ 脚本，根据你自己的需求把这个事完成出来。之所以要介绍这一页，主要目的还是：有些特定情况下，记住这些命令会更加方便——比如你真的只打开了一个终端，没有打开其他软件，就想简单看一下某个目录下面有什么，这时候简简单单的一句命令是更加方便的。所以不需要特地学，它会在大家使用远程服务器的过程中逐渐熟悉起来。文件的编辑、复制、移动、删除，还有文件的比较操作，也都是这样，会在使用中熟能生巧。

还要说明一点：之后我们会介绍不是这么"原始"的方式——使用 VS Code 这样的远程控制软件去做更加方便的事，比如直接在本地方便地比较文件、比较目录。本节介绍的这些，都是最基本的方法。

### 在远程终端里运行程序

接下来简单介绍一下程序的部分：怎么在远程终端中运行程序。一般来说这反而是比较简单的，可以这样理解：当你进入一个远程终端之后，在命令行里输入一个命令，它实际上就运行了一个程序了。比如我输入一个 `ls`，它本身就是一个程序；或者输入一些更复杂的 Python 命令，它其实也是一种程序。

这些程序运行起来，就像是在你本地的电脑上打开一个窗口一样。你想要关掉它，在本地——比如 Windows 系统——点一个叉，或者在右下角的任务栏点一个退出，就可以让这个程序退出掉。但是我们在远程终端里运行的程序，一般来说不能通过简单地"点个关闭"来退出：有些复杂的程序需要做标准的退出，而不是突然关掉、让程序反应不过来——那样它的一些日志、一些输出都会中断掉。

那么怎么中断一个正在运行的程序？我们一般是可以通过 `Ctrl+C` 来进行中断的。举个实际的例子：我这里运行了一个 `cat` 程序，总而言之它就卡在那里了；这个 `cat` 程序一直在运行，你就没有办法从这个命令行环境退出去敲别的命令。这个时候按 `Ctrl+C`，就把这个程序终止掉了——你会发现你回到了原来的命令行，可以去做一些其他的事情。也就是说，一个正在运行的程序，我们一般都是可以通过 `Ctrl+C` 来做程序中断的。

也有一些情况下，这些程序可能因为它卡住了，或者因为它特殊处理了 `Ctrl+C` 这个中断信号，你通过 `Ctrl+C` 不能简单地把它中断掉。这种情况下，就需要使用更复杂的 `kill` 命令来强制终止程序。不过这种情况一般比较少——正常来说，我们不应该使用 `kill` 来强制终止一个程序，除非它遇到了一些意外状况，比如卡住了。

> **提示**：中断程序的顺序是先 `Ctrl+C`；`kill` 是兜底手段，只在程序卡住、对 `Ctrl+C` 做了特殊处理这类意外状况下才用。

### 看看机器上正在跑什么

还有一种办法可以查看正在运行的程序。比如通过 `ps aux`，可以查看当前机器上所有运行的进程；每个进程它都会告诉你：是谁谁在使用、它的 ID 是多少、它占用的 CPU 和内存是多少。要注意 `ps` 是在你输入的瞬间去做统计的，拿到的是那一刻的快照。

也正因为 `ps` 只统计输入瞬间的情况，你还可以通过 `top` 命令来实时查看 CPU 的变化。它会每三秒监测一下所有正在运行的进程的 CPU 占用，并且从高到低做一个排序——三秒刷新一次，就像我们的任务管理器一样，为我们统计出目前正在运行的所有进程，让你有一个直观的感受：谁在使用最高的资源。这个地方你可以通过 `Ctrl+C`，也可以通过 `q` 来退出。

还有一些命令可以去查看显卡的占用情况。比如示例里这张卡：我有一张 24G 的显卡，它已经用了 500MB，大概就是这样。也可以去查看内存使用的情况，总之就是类似的：比如这台机器可能有一个 T 的内存，现在已经用了 100G，还有 900G 可以用。这些就是一些简单的程序运行、中断，以及怎么样查看这些正在运行中的程序的方法。

### 重定向与管道

最后这一部分，对于 Linux 命令行来说非常重要——大家之前可能已经接触到过，但这里要做一个更详细的阐述。我们有两个基本操作：一个叫重定向，另一个叫管道。

我们的程序本来是会输出一些东西的。比如我要查看显卡的情况，它就会给我输出一张表——这整张表都是这个程序的输出内容。有的时候，我们不希望这些输出内容打到我的屏幕上，而希望把它保存成一个文件，这个时候就需要把输入输出流进行一个重定向。管道也是类似的，它的功能就是让一个程序的输出，重定向到另一个程序的输入流。

```text
程序输出 ──默认──> 屏幕
   │
   ├── 重定向 ──> 保存成一个文件
   └── 管道   ──> 另一个程序的输入流
```

读图：默认情况下，程序的输出直接打到屏幕上；重定向把输出改道送进文件，管道则把一个程序的输出直接接到另一个程序的输入上。

这到底是什么意思呢？我们可以简单来看几个例子。首先大家要知道 Linux 里的 `echo` 这个程序：它的功能就是你输入什么就输出什么。比如我给 `echo` 传一个 `apple`，它就会打印出来一个 `apple`；`echo` 一个 `something`，它就会打印出来一个 `something`。有了这个最直白的"你说什么它吐什么"的演示程序，重定向和管道的效果就能看得非常直观了。

## 把命令行用顺手：输出重定向、远程控制工具与 ZSH
> 对应块：BLK05 | 覆盖分集：P03下 | 块标题（分集名）：《远程控制工具+命令行环境》

这一讲从一句特别朴素的愿望开始：我在终端里 echo 出来一段话，想把它存到一个文件里去，该怎么办？答案是，一个大于号就够。顺着这条线，我们先把"让命令互相配合"的几件小工具讲透——输出重定向、管道、程序返回值；然后回答一个对新手更实际的问题：前面那一大堆终端操作都有门槛，有没有更省事的入门方式？有，带图形界面的远程控制工具；最后我们回到命令行本身，看看一条命令在服务器上到底是怎么被执行的，再认识一个会帮你记住历史命令的 shell——ZSH。

### 输出重定向：大于号与双大于号

先解决开场那个愿望。我在终端里打印了一句 something，现在想让它进文件——在命令后面加一个大于号 `>`，再跟上文件名：

```bash
echo something > apple.txt
```

这个 `>` 就是输出重定向。程序默认的行为，是把打印出来的东西送到屏幕上；加了重定向之后，本来要打到屏幕上的内容就改道写进了文件。回车之后，当前目录下就多出了一个 apple.txt。它里面有什么？用 `cat` 查看一下，你会发现里面写的正是那句 something。

> **定义**：输出重定向（`>`）——把程序本来要打印到屏幕上的输出，改写到指定的文件里。

不过这里有个要留心的行为：`>` 会覆盖文件原来的内容。比如我现在打印的不是 something，而是 apple，仍然重定向到同一个 apple.txt——再打开看，里面的东西已经全部变成 apple 了，原来那句 something 没了。

> **易错点**：`>` 的默认行为是覆盖写入，文件旧内容会被整个替换掉；想保留旧内容，别用单个大于号。

有时候我们要的恰恰不是覆盖，而是把新内容追加到文件末尾。这就要用两个大于号 `>>`：

```bash
echo something >> apple.txt
```

这条命令的意思是：在 apple.txt 的末尾追加一句 something。原来文件里只有一句 apple，执行完再看，它多了一行 something，旧内容原封不动。

| 写法 | 行为 | 演示后 apple.txt 的内容 |
| :--- | :--- | :--- |
| `echo apple > apple.txt` | 覆盖：原内容全部丢掉 | 只剩 `apple` |
| `echo something >> apple.txt` | 追加：接在原内容末尾 | `apple` 下面多一行 `something` |

有了重定向，很多操作的组合就成为可能。比如你有一个脚本文件，本来要在控制台（屏幕）上打印一大堆日志——那就让 Python 跑脚本的时候，把所有输出都重定向到一个 log 文件里：

```bash
python xxx.py > log.txt
```

跑完打开这个 log.txt，发生了什么事一目了然。

### 管道：把一个程序的输出接到另一个程序的输入

管道提供的是和重定向相似的功能，但稍微复杂一些。切入点是这样的：一个程序，有它的输入，也有它的输出。比如 `ps aux`，前面我们已经遇到过，它的功能是打印当前系统的一些使用情况——每个进程用了多少 CPU、多少内存。

一般来说，`ps aux` 敲下去会出来一个特别复杂、特别长的列表。这时我们可能只关心其中某一个用户的使用情况，那就用 `grep` 来做筛选：

```bash
ps aux | grep 用户名
```

中间这个竖线 `|` 就是管道：它把左边 `ps aux` 的输出，接到右边 `grep` 的输入上。执行完你会发现，列出来的所有行都只跟这个用户相关。类似的玩法还有：做递归搜索文件时，如果只关心特定后缀的文件，在后面接上这一句管道，结果就只包含所有 jpg 格式的文件。

grep 为什么能筛？单看它自己就明白了。运行 `grep text`，你可以随手往里输入一些文本：不管你输什么，只要输入里没有 text 这个词，它不会有任何输出；可一旦某一行里有 text，它就会把这一行原样输出回来。

接到管道里，这个性质就变成了对整个输出的筛选：前一个程序的输出，必须包含 grep 规定的那个词，grep 才会把它重新输出一遍；除此之外，grep 都会把你的输入吞掉。所以 `ps aux | grep 用户名` 里，某一行只有包含了那个词，才会被打印出来——筛选功能就这么完成了。

```text
ps aux 吐出一长串进程行（每行一个进程）
   │
   ▼
grep 用户名：行里含这个词的，原样放行；不含的，悄悄吞掉
   │
   ▼
终端上只剩下你关心的那几行
```

读图说明：竖线 `|` 把左边程序的输出接到右边程序的输入上，而 grep"只放行含关键词的行"的特性，就成了挂在整股输出上的一个筛子。

以上就是 Linux 里标准输出流的重定向，以及一些复杂的管道操作。

### 输出太长会丢：存文件，或者两头兼顾

顺着刚才的例子往下想。当我们成功运行了一个 Python 脚本，它有一大堆输出、全打印在终端上——这时你会遇到一个问题：终端能显示的内容是有上限的，往上拉到头就到顶了；打印的东西太长，最开头溢出去的部分就丢掉了。

所以这种情况下，我们其实希望把输出结果保存成一个文件，而不是显示在终端上——用前面的重定向就行。比如把 `ps aux` 的输出传到 apple.txt 里，你会发现终端上什么都不打印，全部存到这个文件里去了。

那有没有既能看、又能存的？也有一些管道操作支持"既显示在终端，也保存到文件"。单纯的 `>` 是把输出全部改道进文件，终端上一行不剩；而这类更复杂的管道写法相当于它的加强版——不仅让输出显示在终端，也能同时保存到你想要的文件里。输出很长、又想一边跑一边盯着看的时候，就用它。

### 返回值与 &&：让失败拦住后面的命令

最后讲一下每个程序在命令行里运行时的成功与失败。正常来说，运行一个程序，跑完之后没抛出异常、没报错，它其实会有一个返回值——写 C++ 或者 C 程序的时候你见过：就是 main 函数 return 的那个值。按约定，0 表示正常返回；一旦不是 0，就说明返回时发生了异常。

终端里可以利用这一点来串联命令，用的是 `&&` 这个操作符。它是逻辑与，而且是一个短路的操作符：一旦前面某个值为 false，后面的所有值都不会再去求值。

```bash
program1 && program2
```

在我们这个例子里，如果 program1 出现了异常——比如它报错了——program2 就不会继续运行。通过这种方式，可以做一个很简单的"成功性检验"：保证前面所有程序都正常运行之后，才去运行接下来的程序。

### 这些操作没有难点，只有熟与不熟

把这一部分收个尾。到这里，终端的连接、退出与多路复用，文件的传输、查看、编辑和比较，再到程序的运行和中断，基本操作就都过了一遍。这里其实没有什么特别复杂的概念。这类知识的特点是：某一个点，你知道了之后就一直知道；一开始不知道，就得花些功夫去查资料。

资料方面，中文的像 CSDN、菜鸟教程都可以用，也可以去外网查 Stack Overflow 这类英文资料。这一部分没有特别困难的东西，大家在使用远程服务器的过程中，逐渐就会熟练起来。前面这么一大堆看起来很复杂的知识，最后都会变成你熟能生巧、得心应手的技能。

### 远程控制工具：给命令行装上图形界面

基础操作都过了一遍之后，还有个现实问题：第二部分里讲了那么多东西，对一个初学者来说——或者对一个刚希望入门图形学研究的人，甚至哪怕只是刚买了一台新服务器、第一次使用远程服务器的人来说——之前那些各种操作都是有些门槛的。怎么以最简单的方式来学会使用它？有一些远程控制工具可以直接拿来用。

我知道的两个比较主流的：一个是 Xshell，一款集成式的软件，命令行、文件、程序运行，所有的远程控制它都能做；另一个是 VS Code——它本身只是一个编辑器，但里面有各种各样的插件，可以支持你做远程控制。这两种工具都能让你在本地有一个图形化的界面去操作，而不需要特别复杂的终端命令行控制。我的建议是：如果你一开始不是特别熟悉，肯定先用这种带图形界面的远程控制工具比较好。

下面用 VS Code 做一个简单的例子。

#### 用 VS Code 远程连接一台服务器

以 VS Code 为例走一遍。它的左下角有一个打开远端窗口的按钮，按一下，会出来两个选项：一个是"连接到主机"，一个是"将当前窗口连接到主机"——两个差不多，点哪个都行。

点开之后，它会展示你已经配置好的一些主机；也可以输入 `ssh username@host -p port` 这样一串命令来添加新的 SSH 主机。具体来说，username、host、port 这三个东西分别填什么，之前讲到过：租服务器的时候，供应商会把这三个信息给你；有了它们，你就可以完成远程服务器的连接了。

比如我选一台配好的服务器去连接，它会提示你需要输入密码——这个过程和我们在终端里做的操作一模一样。输入密码，就登上去了。这时左下角会告诉你：你正在远程服务器上进行编辑。

接着可以打开命令面板，从里面打开一个终端——这个时候，它其实就和你在自己的终端里远程连接到这台服务器是一样的。

那你可能要问：这样两种方式有什么区别呢？在 VS Code 里和直接在终端里，区别在哪？其实到这一步为止还没有区别——因为我们目前只是连到了远程服务器上，VS Code 还不能确定你要在哪个文件目录下工作。所以还需要再选择一个文件夹去打开：比如远程服务器上有一个文件夹，打开它之后，VS Code 就知道你要在这个文件目录下工作，会把这个文件夹里（远程服务器上的）所有文件都读取出来，列在左边的资源管理器里。这个过程就和你在本地使用 VS Code 一模一样：左边能看到当前文件夹下有哪些文件——但实际上，这些文件都在远程服务器上。

所以通过 VS Code 这种方式，我们可以在远程服务器上，像在自己本地机子上那样工作。

文件传输也变得很直观：想把本地文件传上去，直接从本地文件夹里把文件拖到左边这一栏，就完成了上传；想下载，选中其中一个文件，右键点击下载，就可以下载到本地；想查看某一个文件，直接点它就可以了。上传、下载、查看，就这么简单。你甚至可以同时打开多个终端。

如果想做一些更复杂的操作——比如比较两个文件、代码高亮、代码的智能提示——VS Code 提供了非常多的扩展：到扩展商店里搜索大家常用的插件，安装起来就能用。举个例子，我装了一个 Markdown 查看器插件：Markdown 文件有自己的格式，没装插件时你看到的全是文本，相当于 Markdown 的原始文件；装上之后，界面上会多出来一个按钮，点开预览，左边那份原始文本就在右边渲染成了排版好的样子。

各种各样文件的查看和编辑它都支持——你可以根据自己的需求去扩展商店里查，甚至可以自己编写一些扩展。总体来说，通过像 VS Code 这样提供远程连接服务的集成式工具，远程控制会非常方便，而且基本上不需要你做太多学习——有时候你只需要搜一下"怎么用 VS Code 做某件事"，或者在 VS Code 的社区里做些搜索，就能找到相关的功能。

#### Xshell 和 VS Code 怎么选

这两个工具到底有什么区别？可以简单看一下。

Xshell 更像是商用的、专业的软件，定位是付费的商用产品——有没有免费版我不太清楚，但肯定有付费的商用使用版。而 VS Code 大家都知道是免费的——开不开源我有点忘了，反正它免费，并且提供了一系列插件的接口；那些插件，都是用户社区群策群力贡献出来的。

所以对比下来：VS Code 的优势是有一大堆插件，你可以自己去选择和使用；Xshell 因为本身闭源，没有这种插件支持，好处可能是它自带的一些功能比较强大。

总体而言，远程控制工具可以给远程服务器的使用提供非常大的帮助。

### 命令行是怎么工作的：shell 这个中介

讲完工具，我们回到命令行环境本身，看一看命令行到底是怎么样工作的。

在一个远程服务器场景里，实际上有两台主机：一个是我们用户的终端，相当于你在本地、自己的电脑上；另一个是远程服务器，它可以运行一些复杂的事情。

那我在命令行里输入一条命令之后，发生了什么？把这条链拆开看：

```text
你在终端敲入一条命令
   │
   ▼
命令传给远程服务器上的 shell
   │
   ▼
shell 读取命令，判断该干什么
（跑一个程序 / 查看所有进程 / 退出登录……）
   │
   ▼
shell 告诉具体进程怎么操作，服务器去执行
   │
   ▼
操作结果产生在远程服务器上
   │
   ▼
shell 把结果传回你的终端，你看到输出
```

读图说明：shell 在这条链上负责两头——一头读取你的命令，一头把服务器的执行结果传回来。

这个过程中有一个非常重要的角色，就是 shell。它扮演的是从"我们用户的输入"到"服务器到底要干什么"之间的中介：shell 读取了你的命令，就知道该干什么事了——到底是跑一个程序，还是查看所有进程的使用情况，还是退出登录……然后它告诉具体的进程该怎么样操作，服务器执行完，操作结果也是先落在远程服务器上，再由 shell 传回到你的终端上，你才看到刚才那句命令的结果。

> **定义**：shell 就是"用户的输入"到"服务器到底要干什么"之间的中介。

这个中介其实有很多种选择：Windows 这边常见的有 Windows Terminal、cmd、PowerShell，Linux 上则有 bash、zsh——都是扮演同样角色的常见 shell。

### 命令行参数：没有图形界面的定制入口

不管是常用的哪一种 shell，都有一个最基本的功能：命令行参数。

想一想，当我们想运行一个程序、又想特殊定制这个程序的某些选项时，在 Windows 或者带图形界面的电脑上是怎么做的？你有一个窗口：可以从上面打开一个侧边栏，有一系列窗口、一系列命令选项，你甚至可以去做文件的配置、打开命令行面板——VS Code 就是这样一个现成的例子。

但在真正的远程服务器上，可能就没有这样的图形界面让你来配置想要的功能了。那它以什么形式存在呢？基本上都是以命令行参数的形式：你给一个程序输入一个参数，这个程序就知道你要做什么特殊的定制。

课上展示过一个特别复杂的程序（名字类似 process_data 的数据处理程序），它后面跟着一大堆命令行参数——就是这些参数，定制了这个程序的各项功能。

其实在我们的编程中，早就见过对这些参数的处理了：比如 C 和 C++ 的 main 函数，本身就带了两个参数，专门用来接住并解析这些命令行参数；Python 也有一个默认的库，专门提供命令行参数的处理。

那就自然引出一个问题：当一条命令的参数特别复杂的时候，我们有时候会希望——能不能查找以前使用过的命令行参数？就像浏览器历史一样：我收藏过的网页记得住，几天前用过的网页也找得回来。命令行有没有这种功能？

### ZSH：会记历史、会补全的 shell

有的，这个功能由一种特殊的 shell 提供——ZSH。我觉得它算是比较通用、功能也比较强大的一个 shell，我自己终端里用的就是它。

#### 历史自动补全

它首先能做命令行的补全。比如我输入 pyt，它就已经帮我补全成 python 了；再敲一个空格，它又能帮我补全到上一句用过的那条 python 命令；这时按一下右方向键，整条命令就全部补上了，我可以在这个基础上再做修改。命令行参数的历史，加上自动补全——我觉得这是个蛮实用的功能。

> **提示**：这套自动补全并不是 ZSH 默认自带的——一个默认的 ZSH 绝对没有这个功能。它来自 oh-my-zsh 里的一个插件，名字带 suggestion 字样，算是相当知名的插件，大多数教程里都能找到，大家可以自己试试看。

说到配置：ZSH 本身的配置是非常复杂的，但有人提供了一个开源的配置方案，叫 oh-my-zsh，GitHub 上有它的项目主页；网上也能搜到很多相关资料和中文配置教程，照着那些简单的配置方法就能配起来。配置完成之后，它有不少功能——除了刚才说的命令行历史和补全，还有下面这些。

#### 快速目录操作

先看平时的痛点：想进入某一个文件夹，一般来说先 `ls` 一下，看看我要哪个文件夹，然后 `cd` 进去。如果文件夹的名字特别长，把它整个打进去其实蛮麻烦的。有了命令行历史，你可以直接翻到历史里的那条命令再进去；但 ZSH 还提供了别的办法——

你只需要打前面几个字符，按一下 Tab，它就会帮你自动补全成这个目录下的文件名。

再来看一个特殊情况：假设目录里有两个文件，前缀都叫 mg——比如一个叫 mg37、一个叫 mg42——我想用 `ls` 查其中一个的大小。这时输入前三个字母，再按一下 Tab，你会发现 ZSH 帮你补全到了它们最长的公共前缀；在这个基础上，想要 37 那个文件，就再输入一个 3，按 Tab，它就帮你补全好了；想要 42 那个，就输入一个 4，再按 Tab，同样补全。

更实用的场景是这个：跑一个 Python 程序，需要指定一个 data 路径，而这个 data 离你当前目录特别远——你得先出去一层再去找，可你又不知道外面那一层文件夹里有什么。这时输入 `../` 再按 Tab，它就会把外面那一层目录下的所有目录补全给你看。比如我知道 data 在 output 里：输入一个 o，可能它就能自动补全成 output；这时再按一下 Tab，我就能知道 output 里到底有什么——比如它补全出了 example；example 下有什么？再按 Tab，它告诉你 example 下面有这五个文件；我知道我的 data 在 spark 里，再按一下 Tab 补全——甚至可以连按两下 Tab 来做一个选择。

这种路径的自动选择功能还是比较强大的。虽然还是比不上直接在 VS Code 里做图形界面的操作，但对命令行来说，这种快速目录操作已经非常实用。而且有时候 VS Code 反而会有麻烦的时候：比如要找的东西特别远，又不在当前文件夹下，而是在几个其他犄角旮旯的文件夹里——这时用命令行反而会快一些。

#### 状态与属性的辅助标注

除此之外，ZSH 还有一些辅助功能。它会标注出时间，比如提示符旁边显示当前的时间；也会用颜色区分文件属性——`ls` 里三个文件颜色不一样，就是因为文件属性不一样，比如 zip 压缩包，ZSH 会给它一个特殊的颜色。如果你用了 Python 的虚拟环境，比如 conda（miniconda、anaconda 这类），提示符里会显示 conda 环境的名字：比如我现在叫 base，切到某一个环境，这里就会改成那个环境对应的名字。还有 git 状态：如果当前文件夹是一个 git 仓库，这里会标注出 git 的状态——显示叉叉，说明你当前有一些文件已经被修改掉了；显示一个圈，说明当前文件全部都是最新的、没有被修改过。

总体来说，ZSH 就是这样一个命令行工具。

### 要不要刻意练命令行

最后回应几个现场的问题，我觉得值得单独说。

有同学提到图形界面：不管怎么说，如果有一个图形界面而不是命令行，肯定是图形界面最方便。除了一些非常特殊的情况——比如在命令行里做一个历史查找，会比图形界面更方便——其他情况，像我们的各种文件操作，都是图形界面更加方便。所以大家不用要求自己"一定要锻炼命令行操作的能力""一定要熟悉 Linux 命令"——当你有图形化界面的时候，肯定就不需要原来那些复杂的东西了。

可以类比一个具体问题：我们现在已经有 VS Code 的远程连接了，还需不需要用 vim 在命令行里去编辑文本文件？我的回答是：大部分情况下，绝对是在 VS Code 里直接编辑文件更方便；但也一定有一些情况是 vim 更方便的。要不要为了那些情况去专门学 vim？我觉得其实不需要——你最终要看自己在更高频率下使用的、更得心应手的那个工具，去专门熟悉它，而不是把时间花在命令行上。

当然，已经学了 vim 也没关系，学了绝对会给你带来很多方便——这是一个多多益善的事情。像我自己，现在一直都在用 VS Code，但第二部分说的那一大堆终端操作、文件操作的方法，我最后也都会了。
