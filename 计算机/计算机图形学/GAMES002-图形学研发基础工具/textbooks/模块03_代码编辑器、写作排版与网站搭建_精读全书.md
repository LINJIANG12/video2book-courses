## 代码编辑器与文档写作工具：Vim、VS Code 与 Markdown
> 对应块：BLK10 | 覆盖分集：P06上 | 块标题（分集名）：《代码编译器与笔记软件使用技巧》

好久不见——上一周是五一假期，我们停了一次课，相信大家都过了一个比较愉快的假期。今天要跟大家讨论的，是和代码、文档编辑相关的一组工具。今天的内容主要分成两块，我会介绍四种工具：前两种，Vim 和 Visual Studio Code，都是代码编辑器，用来编写代码；后两种，Markdown 和 LaTeX，是用来写文档的。我们先从"集成开发环境"这个概念说起。

### 什么是集成开发环境

集成开发环境，简单理解：它最主要的功能，就是给你一个编写代码的地方；此外，它还可以集成一些其他的工具，让你的代码能编译、能运行、能调试——其他一些功能也都可以有。

> **定义**：集成开发环境（IDE）＝以编写代码为核心、同时集成编译、运行、调试等工具的开发软件。

这里展示两张统计图，都是截止到 2023 年的统计信息——今年的统计信息还没有出来。

#### 2023 年：谁的用户最多

左边这张统计图，显示的是目前最热门的一些集成开发环境的用户数量。可以看到，Visual Studio Code 处在一个断层第一的状态——它的用户最多、用户基数最大。排第二的，是同样由微软开发的 Visual Studio，它是一个更强大、规模也更大的集成开发环境。今天要讲的另外一个工具 Vim，也比较常见，排得比较靠前。再往后看，是 PyCharm 和 Jupyter Notebook——写 Python 的同学可能会比较熟悉，这两个是比较专业、也比较常用的 Python 开发工具（当然是除了 Visual Studio Code 之外的工具）。

#### 谁对谁感兴趣：一张用户流向图

右边这张统计图，显示的是几个常用代码编辑器对用户的吸引力。这张图的意思是：每一个半圆（扇形）对应一个代码编辑器；每一条半透明的边从 A 连到 B，表示"正在使用 A 的用户里，对 B 感兴趣的数量"——边越粗，代表数量越多。我们主要关注三个：Visual Studio Code、Vim，还有 Neovim——Neovim 其实就是 Vim 的一个更新版本。

先看 Visual Studio Code 的部分。前面那一小段，是它"指出"的边：意思是用户正在使用 VS Code，但对其他一些软件感兴趣。后面更大的部分，是"入边"：用户正在使用其他的软件，但对 VS Code 感兴趣——其中还包括一些粘性很高的用户，就是正在使用 VS Code、并且只对这一个软件感兴趣的用户。

更有意思的是 Neovim。有一条从 Visual Studio Code 指向 Neovim 的边，代表的是正在使用 VS Code、但对 Neovim 感兴趣的那部分用户；而最有意思的是，其他部分所有使用 Neovim 的用户，都只对它这一个软件感兴趣，不会去看其他的。大概可以看出来：习惯了使用 Vim 这类风格编辑器的用户，可能就很难再去接受其他的编辑器了。Vim 自己也只有一条比较细的边指向 Visual Studio Code——这也是因为 VS Code 应该可以配置成跟 Vim 的操作几乎一样的样子，所以还能够符合 Vim 用户的操作习惯。

### Vim：一台五个状态的模式自动机

接下来给大家介绍 Vim。因为不涉及特别高级的功能，接下来的内容对 Vim 和 Neovim 都是适用的。

先交代一下我自己的情况：我个人其实是不会用 Vim 的——我只知道它怎么工作，但用得特别不熟练，所以也不习惯用它。那为什么这次课还要介绍它？主要有两个目的。第一，如果你听完这份介绍之后对 Vim 非常感兴趣，那么欢迎你继续去查 Vim 的文档，拿这份内容当一个引子，开始尝试 Vim，慢慢熟悉它——不过需要提醒你：Vim 的学习过程可能会很困难，会很慢。第二，对于那些对 Vim 不太感兴趣的同学，也有几点是你们一定需要了解的：其一，Vim 的模式——它其实就是一个五个状态的自动机，这几个状态之间怎么来回切换，你要清楚；其二，也是很重要的一点，你要知道打开 Vim 之后怎么退出、怎么保存。因为你有的时候避免不了要打开 Vim，那个时候如果连退出或保存都不知道怎么做，就会陷入很麻烦的困境。

有同学问：Vim 大概要多久可以掌握？这个我不清楚，因为我没系统学过。我的建议是：慎学。如果你是真的想追求极致的代码体验，那可以用 Vim；但大多数情况下，我个人认为用普通的编辑器，速度就足够了。要是真想学，建议找一个 Vim 大佬带一带——毕竟我自己就是不熟练使用 Vim 的。

顺便回应一条弹幕的建议：可以先在自己熟悉的编辑器里装一个 Vim 插件。这是完全可以的——这样你可以很方便地"拆卸"Vim，用不惯随时退回来。

#### 历史比图形界面还久：只能跑在命令行里

Vim 的特点，主要是使用广泛，以及历史很悠久：它比 Windows 这种操作系统历史还要悠久，是在图形化界面的操作系统出现之前就已经有的编辑器。所以它可以完全运行于命令行，而且也只能运行于命令行。放到今天来讲：假如你要 SSH 远程连接到一台服务器上，而那台服务器很可能没有图形化界面，这时你要用文本编辑器，大概率就要用到 Vim。当然，还有一个更接近现代编辑器的选择，叫做 Nano——功能应该不如 Vim 强大，但用法更接近现在的编辑器。也正因为 Linux 很多时候不需要图形化界面（这时你用不了 VS Code，只能用 Vim），Linux 上 Vim 用得特别多；而且大多数情况下，你用的是 Linux、或者 Windows 里的 WSL，它们其实都是自带 Vim 的，打开终端就可以用。

Vim 确实非常难以学习，但如果你真的能熟练使用它，收益是非常高的：一般来讲，用 Vim 的用户，开发速度、打字速度等等，都会比用其他软件的开发者快一些，效率要高一些。

Vim 还有一个大特点：可编程，有高度的自由性——也就是有高度的个性化能力，你可以把它配置成你想要的样子。可配置的东西包括但不限于：重新映射键盘、设置你自己习惯的快捷键，还有高亮、缩进等等的规则。Vim 的配置文件，类似我们之前讲过的 bash 的 `.bashrc`：Vim 有一个叫做 `.vimrc` 的东西；Neovim 则不太一样，它叫做 `init.vim`。总之，更高级的设置都可以写进配置文件。另外，Vim 还会借助大量第三方插件，去实现编辑文本之外的其他功能。

#### 五种模式：一台自动机的状态图

在讲具体按键之前，请大家先记住这样五个状态。Vim 最常用的状态、也是我们刚打开 Vim 时所处在的状态，叫做 Normal。Normal 状态其实跟我们现在的文本编辑器不一样：你在键盘上敲一些字符，它不会直接在光标处插入那些字符，而是会把你敲入的字符识别成一些命令——这些命令，就作为这台自动机的转移条件。比如说，你敲一个大写的 R，它就会从 Normal 切换到 Replace 状态。

Replace 状态主要用来替换一段文本，替换一段长文本来使用。Insert 状态最接近我们现代的文本编辑器：在这个状态下输入字符，它会真正地在光标处插入，就是正常地编辑文本。Visual 状态用于选择一段文本，就好比我们现在文本编辑器里用鼠标框选一段内容。还有一个 Command-line 状态，就是命令行：在这个状态下输入的字符会被解析成命令，让 Vim 去做你指定它做的事情。

> **定义**：Vim 是一个五状态的"模式自动机"——大部分时候，你敲下的字符不是内容，而是状态转移的条件。

把这五个状态之间的来回切换画成图，就是下面这个样子：

```text
   Normal ── i / I / s ─────────▶ Insert        打字、编辑文本
   Normal ── R ────────────────▶ Replace       替换长文本
   Normal ── v / V / Ctrl+V ───▶ Visual         框选文本
   Normal ── : ────────────────▶ Command-line   输入并执行命令

   Insert / Replace ──按 ESC─────────▶ Normal
   Visual ──按 y（复制）或 d（剪切）──▶ Normal
   Command-line ──敲完命令按回车─────▶ Normal
```

读图：上面四行的按键，都是在 Normal 模式下敲的；打开 Vim 时停在 Normal；下面三行是各模式回到 Normal 的方式，其中最通用的按键是 ESC。

#### Normal 模式：h j k l 与"少动手"的哲学

Normal 模式下最需要知道的，就是上下左右移动可以分别用 `h` `j` `k` `l` 这四个键去代替：`h` 是左，`j` 是下，`k` 是上，`l` 是右。大家可以看一下键盘——h j k l 正好是连续一排的四个键，所以这个分布跟上下左右箭头键的分布不太一样，要注意一下。

为什么用这四个键移动？因为 Vim 有一个宗旨：它尽可能不用鼠标；不仅不用鼠标，还让你尽可能少地使用键盘上"远处"的按键。它会让你所有的工作，都能够在数字排、常规的字母键，再加上 ESC 以及 Shift、Ctrl 这类普通快捷键上完成——也就是五个手指最容易够到的地方，这些按键就足以完成所有的任务了。旁边那种小的数字键盘，你可以用，但用了就相当于是浪费时间；甚至上下左右的箭头键也可以不用——用了也是浪费时间。这就是 Vim 的哲学之一。它的另外两条哲学，前面其实都说过了：一是区分模式，二是可编程、配置自由。

Normal 模式下也不只有这四个最基础的移动，还有其他花式的跳转：比如跳到单词的开头、结尾，左括号和右括号之间的跳转，行内、段落间的移动，或者上下翻页——这些很高级的、现在编辑器里有的功能，Vim 里都有，它们对应的就是在 Normal 模式下的不同按键。具体的按键我就不一一列了，大家课后可以对着资料挨个按一遍、实践一下。

#### Insert 模式与"不切模式"的快速修改

进入插入模式的方法：在 Normal 模式下按小写 `i` 就可以了。进入 Insert 模式之后做的事情，就是在当前光标位置进行编辑。还有一些花式进入 Insert 模式的方法，本质都是"先把光标移动过去，再进入插入"：比如先跳到当前行的行首再进入插入模式，用大写 `I`（Shift+i）就可以实现；其他几种方式这里就不一一列了。

此外，有一些对文本的简单修改，你可以不需要进入 Insert 模式，只在 Normal 模式下就完成它。比如按小写 `s`，相当于删除当前字符，然后再进入 Insert 模式；等价地，按小写 `x`，就只会删除当前字符，不会进入 Insert 模式。类似的按键还有一些，可以让你不做模式切换，就完成最简单的编辑操作。

还有一个 Replace 模式，按大写 `R` 进入，主要用于长文本的替换。这里就不详细介绍了，因为它确实不是一个很常用的模式——一般我们最常用的还是 Insert 模式，用来编辑文本。

#### Visual 模式：移动即框选

接下来是 Visual 模式——Vim 里选择文本的方式。进入 Visual 模式之后，你按的还是刚才那些移动键（`h j k l`，以及 Normal 模式下的那些高级移动键），用它们移动光标，光标移动的道路上会框选住所有经过的文本——移动光标就是框选文本，就这么简单。

进入 Visual 模式有三种方式：

| 进入按键 | 框选方式 |
|:-----------|:-----------------------------------------------------------|
| `v`（小写） | 按字符框选：现代文本编辑器里最常用的那种模式，光标经过的字符被选中 |
| `V`（大写） | 按行框选：光标经过的行，整行都被选中 |
| `Ctrl+V` | 列选择模式：光标所经过的列被选中 |

选中之后，你还处在 Visual 模式里，这时可以按 `y`，表示复制选中的内容——按完 `y`，Visual 模式退出、回到 Normal 模式；剪切 `d` 也是同理。复制或剪切完、回到 Normal 模式之后，再按一下 `p`，就可以在当前光标位置进行粘贴。

我们可以稍微比较一下 Vim 的操作和现在文本编辑器的操作。在现在的文本编辑器里，想把一段话复制到文本的开头：用鼠标框选住一段话，按 Ctrl+C，再用鼠标点一下开头，按 Ctrl+V；不想用鼠标的话，就用上下左右键先移动到想框选的位置、框选住，Ctrl+C 完之后按一下 Home 键或者 Ctrl+Home 键，回到整个文档的开头，再按 Ctrl+V 粘贴。而在 Vim 里是这样：在 Normal 模式下把光标移动到你框选的开始位置，进入 Visual 模式，移动光标，直到把所有想复制的文本都框选下来，按一下 `y`，退回 Normal 模式；再移动光标到文本的开头，按一下 `p`——这就是刚才那套 Ctrl+C、Ctrl+V 的全部过程。

所以 Vim 跟我们平时的操作，最关键的区别在于：我们平时的快捷键，是通过一系列组合键来实现它的复杂性的；而 Vim 的复杂性都在这个状态机上，在于模式之间的切换。所以你会看到，熟练使用 Vim 的人，经常会把 ESC 敲烂——就是因为他们经常需要回到 Normal 模式，而最常用的回到 Normal 模式的按键，就是 ESC。

#### 命令行模式：这几条命令必须记住

Vim 的最后一个状态，叫做命令行（Command-line）模式。它是在 Normal 模式下敲冒号 `:` 进入的。进入之后，整个终端窗口的最下面一行会显示出一行，开头是一个冒号，你接下来输入的所有字符都会显示在冒号后面——这一串字符，就会被解析成你要 Vim 执行的指令。

最常见的命令有以下几个，接下来这几条是大家需要记住的——即使你对 Vim 不感兴趣、不使用它，也要记住：

| 命令 | 作用 |
|:-------------------|:---------------------------------------|
| `:w` | 保存文件 |
| `:w !sudo tee %` | 用 sudo（root）权限保存文件 |
| `:wq` / `:x` / `ZZ` | 保存并退出（这三条等价） |
| `:q!` / `ZQ` | 退出但不保存 |

先说回车的作用：敲完指令后按回车，表示结束指令输入，并且直接执行。所以敲一个单个的 `w` 再回车，就是保存文件。`w` 后面跟一个叹号、再跟 `sudo tee %`，意思是用 sudo 的权限去保存文件——也就是说，如果你没有用 sudo、没有以管理员（root）的身份打开 Vim，而又编辑完了这个文本，不想退出再重新编辑的话，就可以用这个方式，直接用 root 权限把文件保存下来。

> **提示**：命令里的叹号 `!` 表示一个 shell 命令的开头。`w` 后面跟 `!命令`，就是把保存这件事交给叹号后面那条 shell 命令去做；你也可以不加 `w`，直接用 `!` 开头跟一条 shell 命令，意思就是在 shell 环境下执行后面的命令。（`%` 代表当前编辑的这个文件。）

上面这四条，我觉得大家是需要记住的：即使你不用 Vim，也要记住，这样你至少知道怎么保存、怎么退出。后面的命令就是一些更高级的用法了，大家课后自己查阅就可以了。

### VS Code：一个"像浏览器"的轻量编辑器

接下来是 Visual Studio Code 的介绍。首先要明确两个概念：Visual Studio Code 和 Visual Studio 其实没有什么太大关系，它们是两个完全不同的东西。

Visual Studio 是一个功能更加强大、更加完整的集成开发环境：它有一套完整的工具链，包括编译器、链接器，以及调试功能、调试程序，还有单元测试——所有功能都集成在一套软件里，这个叫做 VS。也就是说，你下载 VS 之后，编译器、链接器、调试程序、单元测试功能都是一并给你下好的——这就是为什么你安装 VS，安装一整天都有可能。而安装 VS Code 就不一样了，你可能两三分钟就可以把它下完、装完。因为裸的 VS Code 其实就是一个轻量的文本编辑器，它只做文本编辑这一个功能。

VS Code 其实更像一个浏览器——当然，VS 你完全不能把它等价为浏览器。你如果打开 VS Code 的属性对话框，可以看到其中有一个属性是 Chromium，表示它的内核、它这个"浏览器"的内核。也就是说，Visual Studio Code 所用的内核，其实跟我们的 Chrome 浏览器、Edge 浏览器是一样的。

那我们也会经常看到，VS Code 可以实现非常像 VS 一样强大的功能——也可以调试、也可以运行、也可以编译，这是为什么呢？这都归功于它的插件（extension）。VS Code 刚下载下来，可能只带很少的插件，甚至是不带插件的：你想让它能编译 C++，或者能高亮显示 C++、Python 的语法，都需要去额外安装这些扩展；语法高亮、自动补全这些功能，刚开始都是没有的。刚下载下来的 VS Code，你可以把它理解成等价于 Notepad——就是 Windows 下面那个记事本。

VS Code 也是一个高度可配置的软件，它的配置文件都是 JSON 格式。它跟 Vim 不同：比 Vim 好用得多，基本上不需要上手——你只要会打字就能用；而且它是一个图形界面的应用程序，所以自然有这种易用性。

#### 远程连接：像在本地一样操作服务器

之前我们其实已经介绍过远程连接的 SSH 命令，也介绍过在 VS Code 里怎么运用这个命令；课件里也详细写了怎么用 VS Code 去连接远程服务器、怎么添加一份配置，让你在第二次以及之后更多次连接的时候，不用重新配置——点一个选项就可以直接连接上。具体步骤这里就不再展开，照着资料操作即可。

VS Code 远程连接的好处在于：你连上之后，它会弹出一个新的窗口，这个窗口就好像是你在远端服务器上打开的一个 Visual Studio Code。最直观的体现在左边的文件资源管理器里：里面显示的目录和文件，都是远程服务器上的文件系统——就好像你在本地一样去操作，但实际上你操作的是远程服务器上的内容。这是它非常方便的一点。

> **注意**：用 VS Code 远程连接，也要求你的远端装了 VS Code，不然是没办法连的。

#### 设置：齿轮、JSON 与多设备同步

VS Code 整个软件的通用设置入口，在左下角的一个齿轮图标，它叫做 Settings。点击它就可以进入设置界面，在这里设置一些最基本的属性。比如：Tab 字符的宽度是四个、八个还是两个，根据你的习惯；要不要自动缩进；要不要自动删除行末多余的空白字符；等等。这些基本的编辑器属性都可以在这里设置，而且这些设置是可以多设备同步的。

更高级的设置，首先可能是跟插件相关的：对插件的设置，你要点到 Extension（扩展）里面，选中那个插件，插件那里有一个齿轮图标，你在那个齿轮图标里去设置就好。插件的设置，以及 VS Code 针对当前一个工作区的设置，都是通过 JSON 文件去配置的，在 JSON 文件里指定每一个属性。这个 JSON 配置的内容其实挺多也挺复杂，我个人的建议是：遇到什么问题，就去网上搜对应的配置是哪一条；如果想系统性地了解，可以去看文档。

#### 多光标：一次编辑多行

VS Code 还有一个小特性：多光标。它可以一下子产生多个光标——你的当前位置不再只是一个位置，可能是多个位置。

产生多光标的方法有两种：一种是按住鼠标中键，拖动一个矩形区域，矩形所涉及到的所有行都会各自生成一个新的光标；另一种是按住 Ctrl+Alt，再按上、下方向键，就可以往上或者往下一行产生一个新的光标。

多光标的作用是：你可以同时删除，也可以同时插入。比如这几行都是按位或 `|`，我想把它们全都变成按位异或 `^`——多光标选中，直接按一下异或符号，就一下子全都改过来了，非常方便。

产生多行光标之后，你还可以把它当成"一行"来编辑，各种快捷键照常生效。比如想全选整行，就按住 Shift 再按方向键，把这些行都选中；按 End，可以把所有光标放到行尾；按 Home，放到行首——所以这些光标其实不一定在一条竖线上。再比如，把光标移到行尾后按住 Ctrl 再按方向键，所有光标就会同时按"一个单词一个单词"跳跃的方式移动。总之根据你的需求去用，不过它的自由性没有特别大——比如每一行各自指定一个任意位置的多光标，还是比较难做到的。

有同学问：能不能"第一行输入 1、第二行自动 2"这样按行递增地一次输入？这个应该是没有的——我目前了解是没有这个功能。遇到这种情况，我一般就自己手打；如果你实在要编辑一个特别特别长的文本，可以写个脚本去改它的字符。

### Markdown：所有工具里最易学的一个

接下来进入到文档的编辑、也就是文档的写作部分——前面代码编辑器的部分就讲完了。严格地说，接下来介绍的不一定是某个"编辑器"，它其实是文档编辑的一种语言。第一个是 Markdown。它的图标是一个 M 加一个向下的箭头——Mark 和 down，很好记。

Markdown 的特点，首先它是一个很简单的标记语言，非常简单——是今天讲的所有东西里面最容易学的一个。它甚至不需要专门"学习"，你照着某个文档抄一两遍就会了。第二，它是纯文本格式的：Markdown 文件的后缀名是 `.md`，这个 `.md` 文件就是一个纯文本文件。第三，Markdown 可以让你轻松地排版。

在常见的用途当中，GitHub 上的 README 一般都是用 Markdown 来写的，简书等写作平台也在用它。它还是你平时做笔记、以及科研记录进度的一个绝佳工具——正因为它特别简单：它不像 LaTeX 那样，想加一个公式、加一句话、加一个表、加一张图片什么的，不需要输入一长串代码，直接加就行了，直接加你的文本内容就可以。所以平时用 Markdown 记笔记什么的，还是非常方便的。

教程有两个：第一个是官方教程，更系统、更全面；第二个是交互式教程，非常有意思——它是一个网页，会一步一步地指导你了解每一条语法，让你自己去输入那个语法、了解它是怎么工作的，交互性比较强。

#### 用什么写 Markdown

其实任何一个纯文本编辑器都可以写 Markdown——用 Vim、用 Notepad 都可以写，因为它本质上就是一个文本文件；区别只不过在于能不能渲染。用 VS Code 写的话，需要装一下 Markdown 的插件，才可以做到实时渲染——左边分栏是源代码，右边是渲染结果。

另外，还有一个专门编辑 Markdown 的软件，叫做 Typora。这个软件应该是要付费的，但它渲染出的 Markdown 效果比较好看。而且它跟 VS Code 那种"左边源代码、右边渲染结果"的分栏不一样：你是直接编辑，它就直接给你预览当前编辑的效果——相当于直接在一个渲染好的界面上面去修改。

#### 先过三个最常用的语法

Markdown 的常用语法，我简单地过一下。

首先是标题，用井号 `#` 来表示：井号的个数越多，表示标题的级别越低——也就是级数越高、字体越小。

然后是强调：用两个星号框住一段文本，表示把这段文本加粗；用一个星号框住，就是倾斜；如果又要加粗又要倾斜，那就用三个星号框住它——两边各加三个星号。

```markdown
# 一级标题
## 二级标题（井号越多，级别越低，字体越小）

**加粗**
*倾斜*
***又粗又斜***
```

最后是换行规则——这一点比较重要，它跟我们在 Word 里的编辑习惯不一样：Markdown 里要敲两个换行，才是一个真正的换行，才是真正的分段。

```markdown
第一行（这两行之间在源码里只敲了一个换行）
第二行

第三行（前面空了一整行，这才是真正的分段）
```

看上面源码的渲染效果：如果源码里只敲了一个换行（第一行到第二行），渲染之后就是"段落内的换行"——这两行虽然换了行，但还在同一个段落里；而敲了两个换行（第三行前面空了一行），才相当于重新新开了一个自然段。另外要注意，有一些 Markdown 渲染器会直接忽略单个回车——那样的话，只隔一个换行的两行就会被并成一行显示。

> **易错点**：从 Word 带过来的手感是"敲一次回车就是一段"。在 Markdown 里，单个回车只是段落内的换行（有的渲染器甚至会忽略它、把两行并成一行）；空一行——也就是敲两个换行——才是新开一个自然段。

## Markdown 进阶语法与 LaTeX 排版入门
> 对应块：BLK11 | 覆盖分集：P06下 | 块标题（分集名）：《代码编译器与笔记软件使用技巧》

### 换行、列表与复选框

先把换行这个渲染规则说完整：Markdown 渲染的时候，会直接忽略单个回车——也就是说，源码里前两行中间你只敲了一个回车，渲染之后这两行会直接并成一行。想要真正地分段，就得敲两个回车，这一点刚上手时最容易踩坑。

然后是列表。列表的写法就是在前面加一个短横线 `-` 加空格，短横线就代表一个列表的开始符，渲染出来就是那个小圆点。列表里面可以添加子列表；在列表里面也可以按照刚才说的换行方式来处理，敲两个回车、敲一个回车，都会有对应的效果。这里要注意：**列表是缩进敏感的**。它识别你是不是二级列表，依据就是二级列表的缩进比一级列表更靠前，也就是缩进更多。

> **易错点**：子列表全靠缩进来识别，二级列表的缩进必须比一级列表更多；缩进量不够，渲染器就不会把它当成下一级。

还有一种特殊的列表，是带复选框的：渲染出来是一个可以点击勾选、也可以取消勾选的复选框列表。写法是一个减号、一个空格，再跟一对中括号 `- [ ]`。记住这个细节：不勾选的时候，中括号中间要留一个空格；要勾选的话，中间就写一个 `x`。

顺带回应一个编辑器的问题：有同学提到 Mark Text，我还没有听说过，如果有免费的版本那就更好了。Typora 应该算是一个比较官方的版本，它其实以前也是不收费的、以前也是免费的，应该是近几年才开始收费。

### 公式、引用块与代码块

接下来是公式，就是数学公式。公式一般用美元符号框起来：单个 `$` 框起来的是行内公式，两个 `$$` 框起来的是行间公式。区别看渲染效果就明白：行内公式不换行，嵌在文字中间；行间公式会强行给你换一行，让你这个公式单独处在一行。

至于公式里面那些符号怎么打，这套语法其实是 LaTeX 的语法，接下来讲 LaTeX 的时候就会讲到。

Markdown 还有一个引用的格式，效果类似于你在文章中引用一段诗、一首歌词，或者引用别的文章里的一个说法、一句话。方法就是大于号 `>` 加空格。如果用多个大于号，可以实现引用里面再加引用的嵌套效果。

再一个是代码块的概念，也分行内和行间。行内的话，你只需要用一个反引号括起来就可以了。这个反引号在你的键盘左上角、ESC 的下面——大多数键盘的布局都是这样——不需要按 Shift，打出来就是这个符号。行间的代码块用三个这样的反引号围起来；并且在开头三个反引号之后，可以指定它是哪种语言，比如我这里指定的是 Python，你还可以指定 c# 或者 c++ 这样。

### 超链接与锚点跳转

另外一个常用的是超链接。格式是：用中括号括起来你想添加超链接的内容，后面跟一个小括号，小括号里是这个超链接所指向的地址。它有点类似于你在 Word 或者 PPT 里选中一段文本，然后右键添加超链接——只不过你右键选中的那个内容，在这里是用中括号框起来的，这样讲应该都理解。

除了链接到网页，还有一个锚点机制：比如行内有一段内容，你想把它变成可以点击的东西，点击之后跳转到文本的另外一个位置。方法是在中括号显示内容的后面再跟一个中括号——注意，这里跟的是**中括号**，而不是小括号——这个中括号里是一个 marker，是你任意的一个字符串。然后你还需要在后面用同样的一个字符串加上冒号，再指定跳转目标，这样就把它们俩链接起来了。它的意思就是成对的：行内这里我用中括号把显示内容框起来、后面跟一个 marker，后面我还需要定义一下这个 marker 跳转的目标是什么。

跳转目标可以是像刚才一样的网页链接，也可以是某一个标题。如果你想跳的是当前文档中的某一个标题或子标题——任意一级标题都可以——就必须在标题前面加一个井号，写成 `[marker]: #TITLE` 这样的格式。这样就相当于是添加了一个锚点。渲染之后，「显示内容」这几个字会变成超链接的样子：底下加个下划线、字体变蓝；点击它之后，文档就会自动滚动到你指定的标题那个地方。

### 插入图片、目录与表格

插入图片的语法和超链接非常相像，只不过在最前面多了一个感叹号。另外一个不同点是：中括号里的内容只是一个注释，有点像 comment——也就是说，只有图片挂了、图片不存在的时候，它才会去显示中括号里的这些文本；图片正常的话，就正常显示图片。你也可以把这个中括号直接留空。后面小括号里的图片地址，可以是本地的一个目录，也可以是一个网站的网址。

在 Markdown 里插图片确实是一个问题：如果你想把它传到网上，很可能需要把这个图片上传到一个图床服务器上——把图片上传到某个服务器，给它生成一个固定的网址，然后你在小括号里填上那个网址就可以了。比如 GitHub 的 README 里要插图，其实就不需要这样操作：直接在后面那个地址填一个相对路径就可以了。

然后是目录：想给文档插一个目录，直接在那个地方写一个中括号 `[TOC]` 就可以了。分隔线是三个星号。

还有一个比较重要的是表格，Markdown 的表格比 LaTeX 里面要简单得多：你手打、手搓一个表格出来就好了，源码大概就是那个样子，对应渲染出来就是一个表格。这里有个细节：第二行里那些冒号和减号，指定的就是当前这一列是左对齐、居中还是右对齐。规律也不难看出：只有左边有冒号是左对齐，只有右边有冒号是右对齐，两边都有冒号就是居中。

| 第二行的写法 | 对齐效果 |
| :--- | :--- |
| 冒号只在左边 | 左对齐 |
| 冒号只在右边 | 右对齐 |
| 两边都有冒号 | 居中 |

### LaTeX：一个要编译的排版系统

Markdown 的内容到这里就是全部了，接下来讲 LaTeX。先说个发音的事：我一直读「拉泰克」，是因为最近查了一下这个词的发音——之前其实一直习惯读它「雷泰克斯」。实际上，当这个词专指我们这个文档工具的时候，它的读音是「拉泰克」，后面那个 X 只发一半的音；具体可以去找创始人他那本书，里面有一个介绍。另外 LaTeX 这个单词还有一个意思：全小写的 latex 是「乳胶」的意思——表示乳胶的时候，那个 X 是正常发音的；但在我们现在这个语境下，它就应该读成「拉泰克」。不过这个不重要了，只要大家都明白，你随便怎么发音都好。

LaTeX 的主要特点：它是一个很高效、也很高质量的排版系统，它生成的文本一般会比 Markdown 的要专业的多。一般来讲，你发 paper、甚至出书，都是用 LaTeX 写的，基本上不会用 Markdown 写——Markdown 相比它来说还是更随意一些。

但 LaTeX 有一个缺点：**它需要编译**，不像 Markdown 一样可以即时渲染。Markdown 有点类似于「即时解释」，很轻量，相当于一种 mapping——字符串之间的映射一样，是很简单的操作；LaTeX 不一样，它是类似 C++ 这样的一种语言：你把整个代码写好之后，需要编译这份代码，从而转化成 PDF 的输出。

LaTeX 也有很多很多的宏包，就跟正规的编程语言是一样的，都需要各种外部的包；宏包也是可以开发的，你自己也是可以开发的。另外有一个 LaTeX 的官方文档，大家遇到很详细的问题，可以去搜一下。

### Overleaf 与 VS Code

LaTeX 一般用什么编辑器？最常用的还是 Overleaf，就是 www.overleaf.com 这样一个网站。这个网站其实就是一个管理你所有 LaTeX 文档的网站、一个服务器；每一个文档你都可以添加合作者，这些合作者就可以协同地在线编译，有点类似于现在的腾讯文档——它是实时编译的：你现在敲一个字，协同的人如果在线，立马就可以看到。当然，前提是要网好。

Overleaf 还有一个比较方便的点：它有很多的模板可以使用。进入 Overleaf 主页、登录之后，它会直接到你的 project 页面，然后点上面这一栏的 templates，你会发现有很多很多的模板，包括书、文章、引用等等等等。如果你想搜一个——比如我随便搜一个 CVPR 的文章模板——理论上是可以搜到的，每一年的都是可以搜到的。点进去直接 open，open 之后它会自动存下来，存到你的项目里；接下来改个名什么的，再改一下对应的作者信息、正文信息、摘要等等就可以了。所以这个还是非常方便的——你会发现项目里已经多了一个 CVPR 的文档，你刚才只要打开它，它就自动给你保存下来了。

另外一个写 LaTeX 的编辑器是 VS Code。但同样的，你还需要安装 TeX Live，还需要配置编译环境，然后你的 VS Code 里面也需要安装对应的插件，这样才能充分地利用起来。我个人还是推荐使用 Overleaf——只要你网好。

### 文档框架与导言区

LaTeX 的一些常用语法，这里也介绍一下。首先是一个最简单的文章的基本框架。开头要用 `\documentclass` 来指定文档的类型，比如 `article`；如果文章中要中文的话，你需要换成 `ctexart`。和一般的编程语言都一样，LaTeX 也有注释：行注释用百分号 `%` 开头就可以了。

```latex
\documentclass{article}   % 要写中文，就换成 ctexart
% 导言区：引入宏包、声明全局变量，用 \newcommand 定义快捷命令
\begin{document}
这里才是你真正想显示的内容
\end{document}
```

接下来就是 `\begin{document}`，进入 document 环境。document 环境里面才是你真正想要显示的内容：所有的文本、图片、表格、标题什么的、列表，所有东西都在 document 这个环境里去输入。它有点类似于 C++ 里的 main 函数——你真正要执行的代码都在这个环境下面。

那 document 环境外面、中间的那一段是什么呢？叫**导言区**。导言区有点像 Python 里的 import、C++ 里的 include：说明你要包含哪些宏包；也有一些 predefined 的变量，比如说作者的名字；你还可以在 LaTeX 里去定义一些 command，就是一些快捷的命令，定义的方法是用 `
ewcommand` 这样一个指令。所以导言区就类似于引入宏包、声明全局变量，有点这个意思。

### 标题、章节与列表

标题和章节怎么做？因为要用中文，这里 documentclass 就换成了 ctexart。添加标题用 `\title` 指定这个文档的标题，`\author` 指定作者的名字，接下来还可以用 `\today` 显示今天的日期——我这个截图是比较早的截图，所以日期是很早的，大家忽略这一点就好；你在编辑的时候，用 `\today` 表示的就是今天的日期。

> **易错点**：在导言区里只是定义了文档的标题、作者的名称和日期，它并不会自动显示出来。要真的让它显示出来，得在 document 环境里面写一个 `\maketitle`，它会把你在导言区定义的所有东西打出来。

如果想开一个新的章节，就用 `\section`；新的子章节就是 `\subsection`，这就类似于 Markdown 里的一级标题和二级标题。以此类推，subsection 下面还可以有 subsubsection，但应该最多就到 subsubsection——再之后理论上不应该再分更细的章节了。如果你想再分得更细，可能需要用一些其他的方式，比如字体加粗。再往后其实还有一些类似的东西，比如 `\paragraph`：一个段的段首，你可以用 `\paragraph` 来指定段首的一个小标题。

LaTeX 里也有列表，类似于 Markdown。像 Markdown 里那种圆点的列表，就用 itemize 环境 `\begin{itemize}`，每一个条目的前面都需要加一个 `\item`；如果是以数字开头的列表，换成 enumerate 就可以了。这里面还有更多样式的调整，可以点击链接去看一下。

### 公式环境与交叉引用

LaTeX 里面也可以插入公式。`\begin{equation}` 到 `\end{equation}`，其实就对应于 Markdown 里双美元符号括起来的公式，它就是行间公式；行内公式也是和 Markdown 一样，用一对单个的美元符号括起来就可以了。

其实 LaTeX 也可以不用 equation 环境，像 Markdown 一样用双美元符号把一个公式括起来，它也可以变成行间公式。但和 equation 的区别是：equation 会给你带一个后面的 label，也就是公式编号；用双美元符号括起来的，就不会给你带那个 label。

还有一些更高级的公式环境。比如你想把多个等式并列地写，需要用 align 环境：它可以让你写多行公式，并且可以让你只对齐等号，或者对齐最左边、对齐最右边，这些都可以设置。要用这个环境的话，你应该是需要加一个 amsmath 宏包，`\usepackage{amsmath}` 这句话就放在刚才所说的那个导言区里。

然后是引用的问题。如果你想引用一个公式，就在这个公式的环境里面加一句 `\label{...}`；label 后面表示的是你这个引用，相当于声明了一个变量，这个变量所代表的就是这个公式。接下来想引用这个公式的话，就在行文里用 `\ref{...}`——ref 是 reference 的缩写——后面的大括号里写同样的这个变量名就可以了。渲染出来，这一行里 `\ref` 对应的就是这条公式的编号，比如 1；生成 PDF 之后，你点一下这个 1，它就可以自动跳转到公式所在的那一行。

### 插图与浮动体

LaTeX 里插入图片，用的是 figure 环境。当然，你可以直接插图，就是直接使用 `\includegraphics`：中括号里写的是参数，一般就是用来指定这个图片的缩放，比如 `0.7\textwidth`，就表示我把图片缩放到它的宽度等于 0.7 倍的文本宽度；后面大括号跟的是图片的文件名。如果你在 Overleaf 上插图的话，需要在 Overleaf 这个项目里面去导入这个图片，然后这里的路径也就是 Overleaf 项目里那个图片所对应的路径；如果是本地的话，这个路径相当于就是一个相对路径，你也可以用绝对路径。

但我们一般不会直接用 `\includegraphics` 去插图片，因为这样的话，它不会有标题、对图片的引用这些——都不太行；包括我们想控制图片的位置，也很难。所以一般插入图片，我们都会把它放在一个**浮动体**里。所谓的浮动体，其实就是 figure 环境。`\includegraphics` 放在 figure 环境里面，还有一些其他的选项：比如 `\centering`，表示我想把这个图片放到整个文档居中的位置；然后可以加一个 `\caption`，就是标题；后面还可以像公式一样去加一个 `\label`，然后通过和公式一样的方法去引用这张图片。

还注意到一个细节：`\begin{figure}` 这一行的后面有一个中括号 `[htbp]`。h 表示 here，就是我希望让这个图片尽可能放在当前位置；t 表示 top，希望这个图片尽可能放在这一页的顶端；b 就是 bottom，底端的意思；还有一个 p 这里没打，它表示的是 float page，也就是图片单独放在一页里面。这其实是给 LaTeX 的一个排版建议：优先去考虑能不能放在 here、放在当前这个位置；如果不行——比如图片太大了——那你再去考虑能不能放在某一页的顶端；再不行的话，再去考虑放页底端；再不行，再去考虑其他选项。

但这其实也只是给 LaTeX 的一个建议，它有的时候在一些情况下不会采取你的建议，会直接忽略。如果你想坚持自己的想法、强烈地建议它，可以在这个前面加一个叹号；但这个时候 LaTeX 还是有可能忽略你的建议。想再强硬地强制它把图片安排在当前位置，可以用大写的 H。不过，这种强制放图片位置的做法其实一般是不提倡的。LaTeX 的宗旨是：尽可能按照 LaTeX 编译器自己的审美去排版，不要按照你的审美去排版——因为如果你按照你自己的审美去排版，很可能会产生大量的空白，导致不美观。我们一般都是按照 LaTeX 他自己的习惯去排版图片就好。

### 表格

表格也有和图片一样的安排位置的方式：你也可以用中括号去建议它放在哪里。

表格本身可能就会比 Markdown 里面要难一些。先去生成一个最简单的表格：在 tabular 环境里生成一个两列的表格——一行只有两个项目。tabular 后面会跟一个大括号框起来的 `{cc}`，这两个 c 都表示的是居中的意思：当前列的内容都居中，两个 c 就表示两列都会居中。这个字母也可以替换成 l 或者 r，l 表示左对齐，r 表示右对齐，很好理解。

接下来是怎么排版格子的内容。你先输入内容；如果想切换到同一行的下一个格子，就加一个 `&` 符号，然后再输入第二个格子的内容；如果你想换行的话，就用双反斜杠 `\\`，它就表示换行、换到下一行，再用同样的方式输入 `C & D`。这样的话，我们就生成了一个 2×2 的表格：A B 和 C D。

但这样的表格显然非常 low，它什么线都没有。如果想添加竖线，就在 tabular 后面那个大括号里、c 和 c 的中间去加一些竖线，就表示表格的列与列之间是由竖线分隔的。如果要加横线的话：你不仅要换行，你在换行之后还需要加入单独的一行 `\hline`，`\hline` 之后再换行，这样才会在行与行之间添加一条横线。

> **易错点**：`\hline` 只在它出现的位置画线。比如你只在第一行和第二行之间加了一个 `\hline`，那就只会在这两行之间加这一条横线，表格的上面和下面其实是不会加的；如果上面和下面也要有横线，你必须在第一行的前面也加一个 `\hline`，最后一行的后面也加一个。

LaTeX 的表格应该还会有很多很多其他的选项、很多其他高级的排版方式。这个东西你们不用愁，我这里有一个工具：Excel2LaTeX。它是一个网页，你可以直接在网页上传一个 Excel，或者在网页上直接手动编辑一个表格，然后它可以自动给你转化成 LaTeX 代码，你复制过来就好了。

### 论文引用：BibTeX

这应该是最后一个语法了：论文引用。论文引用一般采用 BibTeX 的格式去引用。你需要做的事情：首先是在 LaTeX 项目里添加一个 `.bib` 文件，这个文件存有 BibTeX 格式的所有文献引用——把所有文献引用相当于列个清单，在这个文件里保存下来。

然后你在正文当中去加引用。位置就是刚才说的 document 环境：在 `\end{document}` 之前，也就是正文最后的地方。加引用的方式：首先用 `\bibliographystyle` 去指定引用的风格；然后在之后使用 `\bibliography` 这个命令，后面的大括号跟的就是你这个 .bib 文件的文件名——注意，这里的文件名不要加那个后缀名。这一句就是指定你用哪个 BibTeX 文件去作为引用库。

```latex
\bibliographystyle{...}   % 指定引用的风格
\bibliography{...}        % 大括号里是 .bib 文件的文件名，不要加后缀名
```

接下来你只需要在行文当中去加引用：如果行文中需要引用某一篇文章，比如要引用爱因斯坦这篇文章，你直接在那个地方输入 `\cite{einstein}` 就可以了。这里「爱因斯坦」这个词，就是每一条 BibTeX 条目的第一个参数：每一条 BibTeX 都遵循这样一个格式，格式中的第一个参数就是你 `\cite` 后面跟的那个字符串；后面其他的参数会指定它的文章名、作者名，哪个 journal、哪一页、哪个号，年份等等的信息，都可以指定在这个 BibTeX 条目里面。

那如何找到一篇文献的 BibTeX 是什么样子的呢？你可以在谷歌学术上面找到一个条目的「引用」，点一下，它会弹出来一个对话框；对话框里面你再点一下 BibTeX，它就会弹出一个页面，页面里显示的就是它真正的 BibTeX 格式，你直接复制到你的 .bib 文件里面就可以了。

但是要注意：谷歌学术里面的这个格式，可能包含的信息并不完全，有的时候你直接复制它是不太可信的、是不够的——有些文章的信息可能不完全。这个时候你可能需要找到这篇文章作者的主页，去作者主页里的 publication，找作者自己写好的那个 BibTeX 格式。

### 公式语法同源与打公式的姿势

答疑环节先说公式。Markdown 和 LaTeX 其实打公式的语法是一样的：它们的格式都是 TeX math。其实公式这个事情，最开始 Markdown 是不支持的，是 Markdown 加了一些扩展，才能够支持 LaTeX 里面的数学公式——所以它们的数学公式语法就是一样的。

有人想把公式直接放 figure 里：那有点太麻烦了，而且在很多时候放 figure 也不规范，所以公式最好还是手打。其实公式这个东西，你用 VS Code 的话，它会有一个「作弊表」，叫 snippet panel，它会告诉你公式里那些符号都怎么打。

还有人提到 Typst。我其实没用过 Typst，不太了解；它好像是一种类似 LaTeX 的新语言，可能很方便吧，之后我也了解一下。

### 正规场合绕不开 LaTeX

最后这几个点，大家一定要注意。现在最最最主流的会议，你想投会议什么的，还得是用 LaTeX 排版：他们一般只接受用 LaTeX 或者用 Word 排版的格式，用其他的可能就不接收了。所以正规场合一般都是要用 LaTeX 的，投会议一般会有要求——不是你随便编辑一下一个 PDF 就能交上去的。

包括挂 arXiv。arxiv.org 大家应该知道，就是可以搜论文的那个网站。如果你想把一篇文章传到 arXiv 上的话，其实是很麻烦的：它不接受直接传 PDF，你必须传一整个 LaTeX 项目，然后由它帮你去编译；而且它的编译器还经常出问题。所以传 arXiv 也是一个很复杂、很麻烦的事情。有人问能不能只传 PDF——好像不行吧，我记得我上次传过一次，还没传上，很难用。

那挂 arXiv 是为了什么？就是一些还没有正式发表的东西，你可以先提前挂到 arXiv 上，让学界的所有同行看到——这样的话相当于你占了个坑，就不会出现撞题这种尴尬的事情。具体一点说：arXiv 上挂的是你正在研究的东西，你不想让别人跟你研究的重复了，要说明你是第一个研究它的，所以你先提前把你的 paper 挂到 arXiv 上。可能你想投某个会议，但那个会议的 DDL 还没有到，你还没有去投它，你可以提前挂到 arXiv 上，表示你正要投了；然后其他想做这个问题的人，就先停一停吧——我已经做掉了，你们就不要再抢了。大概是这个意思。

arXiv 这个事情我就不多说了，我怕我说错，因为我个人也没有用太多 arXiv；这个事情如果大家感兴趣的话，可以自己去了解，我怕误导大家。

顺带说一下 Word。有些会议现在还是接收 Word 的，也就是接受 Word 编辑出来的 PDF。但 Word 并不是你想象中那么简单：它可能需要很高级的操作，有的时候 Word 也需要写一些脚本才行；Word 涉及到的这种高级用法，可能就要比 LaTeX 难多了、复杂多了。

## 从浏览器到服务器：Web 服务与网站搭建
> 对应块：BLK12 | 覆盖分集：P07 | 块标题（分集名）：《网站搭建基础》

这一章比较简单。在 GAMES 这套图形学辅助工具的版图里，网站可能并不是大家经常会涉及到的东西，但排大纲的时候还是把这一节加了进来，作为一个小小的补充——等你哪天真的要跟网页打交道，至少知道这套东西是怎么运转的。

本讲会讲三个部分：首先是 Web 服务的原理——前端是什么、后端是什么，这些原理性的知识做一个概括性的介绍。如果你之前不熟悉网页服务的原理，这一部分就是给你做的补充；但要做深入的理解和展开，还得根据自己的情况去了解相应的框架或者库。后面则介绍 Web 服务的两个主要分类：一种是基于本地 IP 的，做科研开发、本地开发的时候会用到；另一种是开放了公网 IP 的，面向的是互联网上的所有用户，会有更多的配置和更多的要求。

### 一次网页访问，背后发生了什么

我们平时上网，浏览网页、看页面的呈现、点页面上的按钮做交互，在大家看来可能是非常自然的一件事。但实际上，这背后有一系列复杂的机制。这里有一张我从 CSDN 找来的图，它标注了一次 Web 服务从发起到完成的 11 个步骤。我们顺着这条链路，把关键环节走一遍。

在这套机制里，浏览器是用户唯一能够直接看到的 Web 服务接口。你在它上面看到网页渲染出来的结果，看到可以点击的按钮、可以输入的文本框；你把这一系列操作输入给浏览器，剩下的事都由浏览器来处理——去真正的服务器上取数据，弄清楚这个网页长什么样，再把它渲染到你电脑的屏幕上。这些过程，浏览器内部都已经帮你做好了。

而网页本身，往往是部署在服务器上的：百度的网页部署在百度的服务器上，北京大学的主页就部署在北大自己的服务器上。浏览器要显示这个网页，就需要向服务端的程序发起一个请求，获取这个网页长什么样、有哪些元素。这些请求靠一套分层的底层机制来完成：先由 TCP 建立连接；TCP 的上面一层，用的是 HTTP 协议的格式，把所有的请求和响应全部包装起来。

所以你随手做一个操作，浏览器其实默默做了三件事：先建立 TCP 的连接；再把你要请求的数据打包成 HTTP 格式；最后通过 TCP 传给服务器。服务器内部也有它自己的一套处理：你访问了一个网址，服务器会得到这个 URL，然后去解析——根据这个网址，我该返回给你什么东西；执行第 5、6、7 步，得到一个结果，再以同样的方式经过网络，传回你本地的浏览器。浏览器拿到 HTTP 格式的响应之后，就把对应的内容渲染出来。

```text
用户操作（点按钮 / 输入网址 / 填文本框）
        |
        v
     浏 览 器
     - 与服务器建立 TCP 连接
     - 把要请求的数据打包成 HTTP 格式
     - 通过 TCP 把请求发给服务器
        |
        v    （请求经过网络）
     服 务 器
     拿到 URL，解析"该返回给你什么"，
     执行第 5、6、7 步，得到结果
        |
        v    （响应沿同样的路传回来）
     浏 览 器
     收到 HTTP 格式的响应，渲染出页面
        |
        v
用户看见网页
```

一次网页访问的骨架就是这样：用户的操作交给浏览器，浏览器建立连接、打包请求、发给服务器；服务器解析处理，把响应原路送回；浏览器渲染，用户看见。CSDN 那张图标的 11 个步骤，展开的都是这条"浏览器 → 服务器 → 浏览器"链路上的细节。

拿 CSDN 的网页举例：你在浏览器里输入网址点进去，页面显示完成的那一刻，上面这 11 个步骤其实就已经完整走了一遍。这时候你要再点一些别的按钮——比如点一个"订阅专栏"——实际上又会完成一次一模一样的 11 步流程：从浏览器到服务器，再回到浏览器，最后被用户看见。

> **易错点**：不要以为网页"加载一次就完事了"。页面上的每一次交互——点一个按钮、提交一次搜索——背后都是一轮完整的"浏览器 → 服务器 → 浏览器"请求-响应。

所以总体来说，Web 服务并没有特别复杂的原理。经过这么多年的发展，不管你用什么语言——C++ 也好、Python 也好——Web 服务都有了成熟的框架和 API。相当于我们不用做任何非常底层的操作，就可以完成一个 Web 服务的提供。

### 前端：浏览器里看得见的部分

刚才这个过程，其实能明显感觉到 Web 服务可以分成两个部分。一部分是"浏览器怎么把网页的内容显示出来"：像 CSDN 的界面，它有自己的布局、字体的大小，还有按钮的形状、按钮的颜色等等——这些是可视化给用户看的东西。另一部分是服务器自己在幕后做的事：比如你要在搜索框里做搜索，这个搜索其实是在 CSDN 它自己的服务器上完成的。

> **定义**：前端是用户和浏览器之间的可视化与交互部分——布局、字体、按钮的形状颜色，都属于它。
> **定义**：后端更注重服务器自己在后面怎么处理——一些特殊功能、网址的解析，都属于它。

#### 从原生 HTML 到 Vue、React

前端大家可能已经听说过了：它有一些像 JavaScript、TypeScript 这样的语言，这些语言运行在浏览器上，负责浏览器里那些复杂的交互功能。而浏览器本身还有一套原生的功能，用来显示出页面上的元素——显示一个按钮也好、显示一段文字也好。如果你什么框架都不引入，只用浏览器原生的功能，那就是 HTML5 加上 CSS3 这两种语言——或者说这两种格式——结合在一起，组成的可视化方案。

不过说实话，原生的 HTML5 + CSS3 到现在已经比较过时了，基本上没有人会直接手写这种纯原生的代码。但作为了解还是有必要的：你要做一个网页的简单前端开发，可能还是需要认识它们。网上资料很多，比如菜鸟教程就做了系统的讲解。

它的基本格式是"成对的 tag"：一个开标签，加一个带斜杠的闭标签，两个 tag 中间的部分就是这个 tag 的内容。整个 HTML 基本上都是用这种方式来组织渲染的——你写下这些代码，它就代表了一个网页；浏览器拿到这些代码之后逐个解析：看到 title 这个 tag，就知道这里要放一行字，而且字体要比较大、可能还要加粗；看到 video 这个 tag，就知道要在这里放一个内嵌的视频，视频的具体参数则可以从后续的属性里得知。总而言之，HTML5 还是比较简单的，涉及到 Web 前端编写的时候，简单了解一下即可。

而真正开发的时候，我们用的会是更复杂的框架——最著名的就是 Vue 和 React 这两个，它们都有成熟的中文文档。通过 JavaScript 或 TypeScript，再配合这两种框架之一，就能非常容易地做出像 CSDN 那样的界面。

#### 真实开发还差一套工具链

如果你真的要做前端开发，还会碰到几样额外的东西。

首先是包管理。你要用上面说的那些框架，甚至要用一些组件库——比如你不想自己手写一个 button，而是想用别人已经写好的成熟组件库，里面有 button、slider 等各种各样的 Web 前端组件——这些组件库怎么管理，就需要一个专用的包管理工具：Node.js 运行时，加上 npm 这个工具。这个角色在别的语言里你其实已经见过：C++ 里是 vcpkg，Python 里是 pip 或者 conda。它们干的是同一件事——帮你管理项目里涉及到的依赖库。

其次是 Node 本身的版本管理。Node 可以简单理解为一种运行时：你的 JavaScript 实际上是运行在某个版本的 Node 上的，而 Node 各个版本之间差异可能比较大，所以你需要用一些专用的工具去管理 Node 的版本。

最后，构建项目的时候可能会用到模板——比如怎么快速做出一个个人主页——这就有项目构建的专用工具来帮你。

所以说前端其实还是比较复杂的。具体学习的过程中，推荐的路径是：先了解一下 HTML 的基本功能，然后去了解 CSS，最后在这个基础上去接触两种框架中的一种，做简单的学习。这就是 Web 前端入门的一条路径。

### 后端：服务器在幕后做什么

看完前端，再看后端：前端把请求发给后端之后，后端要做些什么事？这里最主要的是两样东西。

一样是服务器。你发起一个请求——比如在百度上点一下搜索，这个点击的过程就是向服务器发送了一条请求——怎么处理这些请求，需要后端部署一个专用的 server。以 Python 语言为例，就有 Flask、Django 这样的专用框架来专门处理。

另一样是数据库。如果你的 Web 服务更复杂一点，可能会有数据库的需求。简单的 Web 应用可以完全不用数据库；有时候用一些简单的数据库就够了；也有时候需要像 MySQL 这样更复杂的数据库。这一块根据自己的情况来具体配置就行。

### 本地 IP 的 Web 服务：远程开发的可视化通道

说了这么多原理，来看 Web 服务对我们到底有什么意义。前面说过，Web 服务可以按部署位置简单分成两类：本地 IP 和公网 IP。所谓本地 IP，就是这个 Web 服务的地址部署在你本地的回环地址上，只有你这台机子能够看见、能够访问它。公网 IP 则相反：比如你想把自己的主页、一个博客，或者公司、学校的主页放到互联网上，让所有人都能看到，你就需要把这个 Web 服务部署到公网上去。公网上的地址有两种形式：一种是一串数字组成的公网 IP，另一种就是我们日常见到的网址（域名）。

这两种 Web 服务各有各的特点，也各有各的用途。先讲本地 IP——也不能说大家一定经常会遇到吧，但在我自己开发的过程中，我确实会经常性地用到它。为什么呢？

#### 回环地址与端口转发

拿我自己做深度学习的场景来说：代码跑在远程服务器上——就是之前讲过的那种服务器，你必须用 VS Code 或者命令行去做远程连接。这种时候，很难在服务器上打开一个可视化的图形窗口；而这个代码在本地又运行不了，只能放到服务器上跑；可服务器本身又没有图形界面，没办法显示可视化的东西。两头堵死了。

我的解法就是 Web 服务：在远端服务器上部署一个 Web 服务，然后把它的端口转发到我的本地——相当于这个服务在我本地完成了一次部署。比如我自己开发中就遇到过这样一行 Python 命令，它在本地回环地址上打开了一个 Web 服务；点击这个地址，浏览器里就会打开一个界面，可以在上面做可视化的交互。关键是，这个转发过程 VS Code 会自动帮你做；转发之后，你就可以在本地浏览器里打开交互界面，和远程服务器渲染出来的结果做交互。

```text
远程服务器（你的代码在这里跑，没有图形界面）
    |
    |  在回环地址上部署一个 Web 服务（只有服务器自己能访问）
    v
端口转发（VS Code 远程连接时自动帮你完成）
    |
    v
你的本地机器
    └─ 本地浏览器打开转发过来的端口
         → 看到远程渲染的结果，还能继续做交互
```

读这张图：服务真正运行在远程服务器上，但经过端口转发之后，访问它的动作发生在你的本地浏览器里——这正是本地 IP 的 Web 服务最主要的功能：当你在开发自己的工程、而服务器上不能直接打开可视化界面的时候，布置一个简单的 Web 服务，把它转发到本地。

#### 两个现成的例子：Nerfstudio 与 Jupyter Notebook

要从头自己写这套代码还是挺困难的，但成熟的代码框架很多。这里列举一个：Nerfstudio，一个 NeRF 相关的代码框架。大家不用具体知道这个框架是干什么的，只需要知道它的基本功能——把我远程服务器上的一些三维数据，显示到我的本地浏览器上。它的 README 里给了几个例子，比如在远程端重建出一个三维场景，这个框架给它部署好了 Web 服务，我们就可以在本地打开浏览器，在浏览器里拖动整个场景，观察这个场景可视化的情况。

更进一步，你甚至可以在网页端设置一些可以调整的系数或参数，这些参数会和后端的服务器进行交互——等于说你只需要在本地网页上简单点几个按钮、调整几个数值，就可以操纵你在远程服务器上的一些三维资产。

框架怎么选？取决于你的需求和你的语言。如果你确实有一个需要 Web 服务的需求——比如你的远程服务器上有一个三维的、或者图形学算法得到的结果，需要对它做可视化、甚至要跟它交互——那就看你自己用的是哪门语言，用这门语言下对应的框架。我的代码用的就是 Python，Nerfstudio 是一个 Python 的框架，所以我很自然地直接用它了；如果你用的是 C 或者 C++ 做开发，遇到了同样的需求，GitHub 上也有很多 C/C++ 的 Web 服务库，直接去用它们提供的 API，把远程服务器上的结果放到本地做交互、可视化，就可以了。

另一个例子大家可能已经比较熟悉了：Jupyter Notebook。对 Python 开发人员来说它是个熟面孔，对初学者来说，它最主要的好处是能把远程渲染出来的图片直接放到网页里显示出来——不像之前在命令行里，很难直接查看某一张图片。Jupyter Notebook 本质上也是一种"把 Web 服务放到本地转发"的框架，它提供了一些非常方便的功能：你可以在网页里编写代码、查看图片，还可以和图片做交互——比如有一些库可以在 Jupyter Notebook 里显示一个可交互的东西，好比一个三维物体，你可以直接在网页里拖动它，看到更丰富的可视化结果。

#### 动手起一个最简单的本地服务

总结一下：部署在本地 IP 的 Web 服务，基本上都是为了项目开发而服务的；而可视化是图形学里非常重要的一环——当你在远程服务器上没法直接开图形界面、没法直接可视化的时候，用 Web 服务是一个非常方便的选择。

那自己动手，最简单能简单到什么程度？以 Python 为例，有一个非常简单的命令——只要你装了 Python，输入它就能打开一个非常简单的本地 Web 服务：

```bash
python -m http.server 7007
```

`http.server` 是 Python 自带的模块，不用装任何东西；`7007` 就是我指定的端口。我在浏览器里输入这个端口的地址，就能看到它把 Web 服务根目录（也就是运行命令时所在的目录）下的所有文件全部列了出来——这种情况下，你就已经成功打开了一个 Web 服务。再去点击里面的某一个 HTML 文件，就能得到一个全新的网页。

当时我还想顺手演示一个用来可视化三维场景的网页：目录下有一个 index.html，按惯例服务会直接解析到它、把它作为首页打开。结果页面有点卡，换了个端口之后发现这个例子行不通——那个页面是用一个框架构建的，光靠这个静态文件服务跑不起来。那就换个方式：用刚才提到的 Node.js 运行时去运行它，网页里就打开了一个三维可视化的窗口，可以拖动它、查看里面的细节。这也是个很简单的应用例子，顺便也说明了一件事：纯静态的页面，一行 Python 就能伺候；用了框架的页面，就得配上对应的运行时。

### 公网 IP 的 Web 服务：把主页挂上互联网

当我们需要把项目放到互联网上，或者把个人主页挂到网上的时候，就需要部署另一种 Web 服务了——公网 IP 的 Web 服务。它有一些更加麻烦的配置。

#### 完整方案：域名、证书、服务器与 Nginx

麻烦在哪？它需要配置你的域名；如果你需要一个安全的 HTTP 协议，就需要一张支持 HTTPS 的证书；并且你需要购买一台专用的服务器。有了这三样东西之后，你可能还需要用 Nginx 去配一个端口转发，或者说去代理整个 Web 服务的请求。当然，这些就过于复杂了，已经超出了我们这门图形学辅助工具课需要讨论的范围。

#### 轻量方案：主页模板与 GitHub Pages

但公网 IP 其实还有一些非常简单的部署方法。大家应该见到过一些个人主页——举个例子，陈老师的个人主页，这种主页就可以通过公网 Web 服务来支撑。我自己的主页呢，其实是用了他的一个框架，等于说我一点前端代码都没有编写，完全用这个框架搭了起来。

GitHub 上这种库蛮多的：它帮你一键生成网页，你只需要改动一些非常简单的地方，就可以得到一个自己的主页。包括我们在一些项目主页上见到的样子——上面有很多 demo，有一个 GitHub 的跳转链接，可能还有一些可视化的结果——长得其实都很像，都是用同一类模板生成的。

具体来说，GitHub Pages 是 GitHub 提供的一种特殊服务，原理是：GitHub 把服务器、域名、证书这一切全都包了，你只需要按照 GitHub Pages 的一些要求，简单配置一下自己的项目信息，就可以完成部署。这种项目主页，包括一个文档主页，都可以用这种方式来配置。这基本上就是我们可能涉及到的公网 IP 的主要应用了。

### 两种服务怎么选

那么总结一下。网站搭建这件事，首先要搞清楚你的项目里是否需要用到网页服务、需要的是哪一种：

| | 本地 IP 的 Web 服务 | 公网 IP 的 Web 服务 |
|:---|:---|:---|
| 部署在哪 | 本地回环地址 | 公网（数字公网 IP 或网址域名） |
| 谁能访问 | 只有你这台机子 | 互联网上的所有用户 |
| 面向场景 | 开发自己的程序时，靠端口转发完成远程服务器上的可视化 | 个人主页、个人博客、项目主页、项目文档、在线 demo |
| 配置负担 | 几乎没有，端口转发 VS Code 自动完成 | 域名、HTTPS 证书、专用服务器，还要 Nginx 做转发代理 |

这两种需求，基本上就涵盖了我们图形学中涉及到的所有网站配置需求。比如你有一个项目要做一个 demo，要放到网上给大家看，这就需要一个公网 IP 的 Web 服务；或者你本身要写一个很简单的可视化程序，但它在远程服务器上没法直接运行显示，这时候你就需要一些可视化的方法，把它放到本地浏览器上去显示——这就是本地 IP 的场景。

大部分时候，我们其实不需要去搞清楚其中的细节，直接用你自己使用的那种语言下对应的一些 Web 服务的库，就可以简单地完成这件事。但面对一些复杂的需求，可能就需要我们去了解具体的 Web 服务原理，包括它的前端、后端，甚至需要去学习具体的前端语言和后端语言，对它做一个整体性的开发。

我自己的项目经历里就有这样的时刻：曾经做一个课题的时候，用到了小程序开发的功能，那里其实就相当于是一个 Web 服务——微信小程序涉及到界面怎么写、前端怎么显示，以及后端连接一个数据库。当时的后端就是用 Python 加 Django 搭的一个数据库，里面有一些管理员支持的功能；这个项目涉及的前端和后端，就比前面例子里的复杂多了。相当于说，如果我们真的有这么复杂的需求——比如编写小程序——才需要仔细了解 Web 服务的原理、仔细了解它的前端和后端，甚至去学习微信小程序开发的文档；除此之外的大部分情况，我们都可以通过简单地使用别人提供好的 API 和库来完成。

今天的内容其实非常简单，就是给大家介绍一下 Web 服务的原理。总体来说，我们图形学中涉及到的 Web 服务并不是特别多，大家着重把握我在本地 IP 和公网 IP 下举的那两个例子，就够用了。

### 课后问答：在网页里看三维模型

正课结束后，有同学问了一个很实际的问题：网页显示三维模型要怎么做？我们展开说一下。

先想本地是怎么查看三维数据的：可能用 CloudCompare——我自己会用这个软件——也可能涉及到 MATLAB，或者 Blender。这类软件是没有办法在远程服务器上打开的。比如说服务器上有一个工程，里面有一个点云文件，我想看看这个点云长什么样：一个办法是把它从服务器上下载到本地，用本地的可视化软件打开；另一种方式是可以直接跳过下载这一步——在远程服务器上部署一个 Web 服务，把这个服务转发到本地端口，最后在本地浏览器上打开。

具体举个例子：比如 3D 高斯——不管怎么说，它是一种类似点云一样的三维物体对象。要对它做可视化，我这里有一个代码，能够直接在远程服务器上部署一个 Web 服务；部署完之后点击这个主页，就可以看到它的显示——这个显示是在我本地浏览器里打开的，并且可以对它做一些交互、查看。如果你涉及的是普通的 mesh 或者点云，我这里 reference 到的一个库也可以完成这件事。当时我本想现场跑一个 demo 给大家看，折腾了半天没能跑起来，只好换回刚才的例子——不过思路不受影响：通过一个简单的调用产生端口转发，我们就可以在本地浏览器里打开一个显示。

总结一下这个问题的两种解法：正常来讲，你应该通过本机上的一个渲染程序、或者一个三维查看软件，去打开点云或者 mesh；如果这种方式不奏效——比如远程服务器没法做这件事——第一种是最简单的，把它下到本地重新查看；第二种就是在远程打开一个 Web 服务，这样我们就可以在本地更方便地查看。
