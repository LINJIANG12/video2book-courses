# 代码编辑器与写作排版工具

## 集成开发环境与编辑器格局

   * **集成开发环境（Integrated Development Environment，IDE）**

       * > **定义**：以编写代码为核心、同时集成编译、运行、调试等工具的开发软件。

       * 截止 2023 年的统计：Visual Studio Code 用户数断层第一、用户基数最大；第二名是同样出自微软的 Visual Studio——功能更强大、规模也更大的 IDE；Vim 也比较常见、排名靠前；其后是写 Python 时比较专业、常用的 PyCharm 与 Jupyter Notebook。

   * **编辑器用户流向图**

       * 机制：每个半圆（扇形）对应一个编辑器；每条半透明的边从 A 连到 B，表示「正在使用 A 的用户里对 B 感兴趣的数量」——边越粗，数量越多。

       * Visual Studio Code：指出的边只占一小段，更大的是入边——其他软件的用户对它感兴趣；其中还包括粘性很高的用户，即正在使用 VS Code、且只对它这一个软件感兴趣的用户。

       * Neovim 是 Vim 的更新版本；除一条从 VS Code 指向它的边外，其余使用 Neovim 的用户都只对它一个软件感兴趣——习惯了 Vim 这类风格的编辑器，就很难再接受别的。

       * Vim 只有一条比较细的边指向 VS Code：因为 VS Code 可以配置成跟 Vim 操作几乎一样的样子，仍符合 Vim 用户的操作习惯。

## Vim 的定位与学习成本

   * **Vim**

       * 历史比 Windows 这类操作系统还悠久，诞生于图形界面操作系统出现之前，因此完全运行于命令行、也只能运行于命令行；SSH 远程连接一台很可能没有图形界面的服务器时，要用文本编辑器大概率就是它。

       * Linux 与 Windows 的 WSL 大多自带 Vim，打开终端就能用；同场景下另一个选择是 Nano——用法更接近现代编辑器，但功能不如 Vim 强大。

       * 熟练后收益很高：用 Vim 的用户开发速度、打字速度一般都比其他开发者快一些；但学习过程困难且慢，是否要学要慎量——真追求极致代码体验再学，多数情况普通编辑器的速度已足够。

       * 入门路径：找熟练的 Vim 用户带一带；或先在自己熟悉的编辑器里装 Vim 插件——可以很方便地「拆卸」，用不惯随时退回来。

       * 即使不打算用 Vim，也有两件事必须会：分清五个模式怎么来回切换；打开 Vim 之后怎么保存、怎么退出——否则打开它就会陷入很麻烦的困境。

   * **可编程与配置文件**

       * 高度自由、高度个性化：可重新映射键盘、设置自己习惯的快捷键、定义高亮与缩进等规则，并借助大量第三方插件实现编辑文本之外的功能。

       * 配置文件：Vim 用 `.vimrc`，角色类似 bash 的 `.bashrc`；Neovim 不一样，叫 `init.vim`；更高级的设置都写进配置文件。

## Vim 的五种模式

   * **模式自动机**

       * > **定义**：Vim 是一台五状态的「模式自动机」——大部分时候你敲下的字符不是内容，而是状态转移的条件；以下内容对 Vim 与 Neovim 都适用。

       * Normal：打开 Vim 时所处的状态；敲字符不会在光标处插入，而是被识别成命令。

       * Insert：最接近现代文本编辑器——输入的字符真正在光标处插入，正常编辑文本。

       * Replace：替换一段长文本用。

       * Visual：选择一段文本，好比在现在的文本编辑器里用鼠标框选。

       * Command-line（命令行）：输入的字符串被解析成命令，让 Vim 执行你指定它做的事。

   * **状态转移**

       * 进入各模式的按键都在 Normal 模式下敲入；各模式回到 Normal 的方式见下图，其中最通用的按键是 ESC。

```text
   Normal ── i / I / s ──────────▶ Insert        打字、编辑文本
   Normal ── R ─────────────────▶ Replace       替换长文本
   Normal ── v / V / Ctrl+V ────▶ Visual         框选文本
   Normal ── : ─────────────────▶ Command-line   输入并执行命令

   Insert / Replace ──按 ESC─────────▶ Normal
   Visual ──按 y（复制）或 d（剪切）──▶ Normal
   Command-line ──敲完命令按回车─────▶ Normal
```

## Normal 模式与移动哲学

   * **方向移动**

       * `h` 左、`j` 下、`k` 上、`l` 右：这四个键正好是键盘上连续的一排，分布跟上下左右箭头键的分布不太一样，注意区分。

   * **少动手哲学**

       * 尽可能不用鼠标；也让你尽可能少用键盘「远处」的按键——数字小键盘、上下左右箭头键都能用，但用了就相当于是浪费时间。

       * 所有工作都在数字排、常规字母键，加上 ESC、Shift、Ctrl 这类普通快捷键上完成——即五个手指最容易够到的地方。

       * 哲学共三条：区分模式；可编程、配置自由；操作收敛在最易够到的键位上。

   * **花式跳转**

       * 跳到单词的开头/结尾、左括号和右括号之间跳转、行内与段落间移动、上下翻页等现在编辑器里有的功能，Vim 里都有对应的 Normal 模式按键。

## Insert、Replace 与免切换修改

   * **进入 Insert**

       * 小写 `i` 在当前光标位置进入插入；大写 `I`（Shift+i）先跳到当前行的行首再进入插入。

       * 其他花式进入方式的本质都一样：先把光标移动过去，再进入插入。

   * **不切模式的快速修改**

       * `s`：删除当前字符并进入 Insert；`x`：只删除当前字符、不进入 Insert——最简单的编辑不做模式切换就能完成。

       * Replace 模式由大写 `R` 进入，用于长文本替换，不算常用；日常最常用的还是 Insert。

---

## Visual 模式与复制粘贴

   * **移动即框选**

       * 进入 Visual 后按的仍是 `h j k l` 与各高级移动键：光标移动的道路上会框选住所有经过的文本——移动光标就是框选文本。

   * **三种进入方式**

| 进入按键 | 框选方式 |
| :--- | :--- |
| `v`（小写） | 按字符框选：现代文本编辑器里最常用的那种 |
| `V`（大写） | 按行框选：光标经过的行整行被选中 |
| `Ctrl+V` | 列选择模式：光标经过的列被选中 |

   * **复制、剪切与粘贴**

       * 选中后按 `y` 复制、按 `d` 剪切，两者都会退出 Visual、回到 Normal；回到 Normal 后按 `p` 在当前光标位置粘贴。

       * 全流程示例：Normal 移到框选起点 → 进 Visual → 移动光标框完 → `y` → 移到目标位置 → `p`，等价于平时 Ctrl+C、Ctrl+V 的全过程。

   * **与现代编辑器的本质区别**

       * 现代编辑器的复杂性由一系列组合键实现；Vim 的复杂性都在状态机上、在模式之间的切换里——所以熟练用户经常把 ESC 敲烂：最常用的回 Normal 按键就是 ESC。

## 命令行模式：保存与退出

   * **进入与执行**

       * Normal 模式下敲冒号 `:` 进入；终端窗口最下面一行会显示出一个开头为冒号的行，其后输入的所有字符被解析成要 Vim 执行的指令，敲回车即结束输入并直接执行。

   * **必记命令**

| 命令 | 作用 |
| :--- | :--- |
| `:w` | 保存文件 |
| `:w !sudo tee %` | 用 sudo（root）权限保存文件 |
| `:wq` / `:x` / `ZZ` | 保存并退出（这三条等价） |
| `:q!` / `ZQ` | 退出但不保存 |

       * `:w !sudo tee %` 的场景：没用 sudo、没以管理员（root）身份打开 Vim，却已经编辑完、不想退出重新编辑——直接用 root 权限把文件保存下来。

       * `!` 表示一条 shell 命令的开头：`w` 后跟 `!命令` 是把保存这件事交给那条 shell 命令去做；不加 `w`、直接以 `!` 开头跟命令，就是在 shell 环境下执行它；`%` 代表当前编辑的这个文件。

## VS Code 的定位与配置

   * **Visual Studio（VS）与 Visual Studio Code（VS Code）**

       * 两者其实没有太大关系，是完全不同的两个软件。

| 对比项 | Visual Studio（VS） | Visual Studio Code（VS Code） |
| :--- | :--- | :--- |
| 定位 | 功能更强大、更完整的 IDE | 轻量文本编辑器，只做文本编辑这一个功能 |
| 工具链 | 编译器、链接器、调试程序、单元测试集成于一身，下载即带 | 调试、运行、编译能力全靠额外安装插件（extension） |
| 安装耗时 | 可能装一整天 | 两三分钟下完装完 |

       * VS Code 更像一个浏览器：打开它的属性对话框能看到内核属性是 Chromium——与 Chrome、Edge 浏览器的内核一样；VS 则完全不能等价为浏览器。

       * 刚下载的 VS Code 等价于 Windows 的记事本 Notepad：语法高亮、自动补全这些功能刚开始都没有，想要什么就去额外装什么扩展。

   * **易用性与设置体系**

       * 图形界面应用程序，比 Vim 好用得多、基本上不需要上手——会打字就能用；同时高度可配置，配置文件都是 JSON 格式。

       * 通用设置入口在左下角的齿轮图标 Settings：Tab 字符宽度（四个、八个还是两个）、要不要自动缩进、要不要自动删除行末多余空白等基本属性都在这里设，且设置可多设备同步。

       * 插件设置：点到 Extension（扩展）里选中插件，点插件处的齿轮图标去设置；插件设置与针对当前一个工作区的设置，都通过 JSON 文件逐项指定。

       * JSON 配置的内容挺多也挺杂：遇到什么问题就去网上搜对应的配置是哪一条，想系统性了解再去看文档。

## VS Code 的远程连接与多光标

### 远程连接

   * 连接成功后会弹出一个新的窗口，就好像你在远端服务器上打开了一个 VS Code；最直观的体现在左侧文件资源管理器：显示的目录和文件都是远程服务器上的文件系统——操作远程内容如同操作本地。

   * 添加好一份连接配置后，第二次及之后更多次连接不用重新配置，点一个选项就可以直接连上。

   * > **注意**：远端服务器上也必须装了 VS Code，不然是没办法连的。

### 多光标

   * 产生方式有两种：按住鼠标中键拖动一个矩形区域，矩形涉及到的所有行各自生成一个新的光标；或按住 Ctrl+Alt 再按上、下方向键，往上或往下一行产生一个新光标。

   * 作用是同时删除、同时插入：比如多行里都是按位或 `|`，多光标选中后直接按一下异或符号，就一下子全改成 `^`。

   * 多行光标可以当成「一行」来编辑，各快捷键照常生效：按住 Shift 加方向键把这些行全选；按 End 把所有光标放到行尾、按 Home 放到行首——所以这些光标不一定在一条竖线上；移到行尾后按住 Ctrl 加方向键，所有光标同时按「一个单词一个单词」跳跃的方式移动。

   * 边界：自由性没有特别大——每一行各自指定一个任意位置的多光标比较难做到；「第一行输 1、第二行自动 2」的按行递增输入没有对应功能，量少就手打，特别长的文本可以写个脚本去改。

## Markdown 定位与写作环境

   * **Markdown**

       * > **定义**：一种非常简单的纯文本标记语言——今天这类工具里最容易学的一个，甚至不需要专门学习，照着文档抄一两遍就会；文件后缀 `.md`，本质就是一个纯文本文件，能让你轻松排版。

       * 常见用途：GitHub 上的 README、简书等写作平台；也是平时做笔记、科研记录进度的绝佳工具——不像 LaTeX 那样加一个公式、一句话、一个表、一张图都要输入一长串代码，直接加文本内容就行。

       * 任何一个纯文本编辑器都能写 Markdown（Vim、Notepad 都可以），区别只不过在于能不能渲染。

   * **渲染工具**

       * VS Code：需要装 Markdown 插件才可以实时渲染——左边分栏是源代码，右边是渲染结果。

       * Typora：专门编辑 Markdown 的软件，渲染效果比较好看；与分栏式不同，它是直接编辑、直接预览当前编辑的效果——相当于直接在一个渲染好的界面上修改；它以前也是免费的，近几年才开始收费。

   * **教程资源**

       * 官方教程更系统、更全面；交互式教程是一个网页，一步一步地指导你了解每一条语法、自己输入那个语法并看它怎么工作，交互性比较强。

## Markdown 基础语法：标题、强调与换行

   * **标题**

       * 井号 `#` 表示标题：井号的个数越多，标题的级别越低——级数越高、字体越小。

   * **强调**

       * 两个星号框住一段文本是加粗；一个星号框住是倾斜；又要加粗又要倾斜就用三个星号框住它——两边各加三个星号。

   * **换行规则**

       * 渲染时单个回车会被直接忽略：源码里两行之间只敲一个换行，渲染后这两行并成一行；单个回车至多是段落内的换行，敲两个换行（中间空了一整行）才是真正的分段。

       * > ⚠️ **易错点**：从 Word 带过来的手感是「敲一次回车就是一段」；Markdown 里单个回车只是段落内的换行（有的渲染器甚至会忽略它、把两行并成一行显示），空一行——也就是敲两个换行——才是新开一个自然段。

## Markdown 列表、引用、代码块与公式

   * **列表**

       * 减号 `-` 加空格开头即一个列表项，渲染出来就是那个小圆点；列表里面可以添加子列表，列表内也按同样的换行方式处理，敲两个回车、敲一个回车都有对应效果。

       * > ⚠️ **易错点**：列表是缩进敏感的——识别二级列表的依据就是它的缩进比一级列表更靠前、更多；缩进量不够，渲染器就不会把它当成下一级。

   * **复选框列表**

       * 写法是一个减号、一个空格再跟一对中括号 `- [ ]`，渲染成可以点击勾选、也可以取消勾选的复选框列表；不勾选时中括号中间要留一个空格，要勾选就在中间写一个 `x`。

   * **引用块**

       * 大于号 `>` 加空格，效果类似在文章中引用一段诗、一首歌词，或别的文章里的一个说法；用多个大于号可以实现引用里面再加引用的嵌套效果。

   * **代码块**

       * 行内代码用一个反引号括起来；这个反引号在键盘左上角、ESC 的下面，不需要按 Shift 就能打出来。

       * 行间代码块用三个反引号围起来，并且在开头三个反引号之后可以指定语言，比如 `python`，也可以指定 `c#`、`c++` 等。

   * **公式**

       * 单个 `$` 框起来的是行内公式：不换行、嵌在文字中间；两个 `$$` 框起来的是行间公式：会强行换一行，让公式单独处在一行。

       * 公式里那些符号怎么打，沿用的正是 LaTeX 的语法。

## Markdown 超链接、图片与表格

   * **超链接**

       * 中括号括住你想添加超链接的内容，后面跟一个小括号，小括号里是超链接指向的地址；有点类似在 Word 或 PPT 里选中一段文本右键添加超链接。

   * **锚点跳转**

       * 行内显示内容的中括号后面再跟一个中括号（里面是一个 marker，任意的一个字符串），然后在后文用同样的字符串加上冒号、指定跳转目标——两者成对，把显示内容和目标链接起来。

       * > **注意**：锚点这里跟的是中括号，而不是小括号。

       * 跳转目标可以是网页链接，也可以是当前文档中的某一个标题或子标题——任意一级标题都可以，此时必须写成 `[marker]: #TITLE` 的格式，在标题前加一个井号。

       * 渲染后显示内容变成超链接的样子：底下加下划线、字体变蓝；点击之后文档自动滚动到你指定的标题那个地方。

   * **插图**

       * 语法和超链接非常相像，只不过在最前面多了一个感叹号；中括号里的内容只是一个注释（有点像 comment）：只有图片挂了、图片不存在时才会显示这些文本，图片正常就正常显示图片，也可以把中括号直接留空；小括号里的地址可以是本地的一个目录，也可以是网站的网址。

       * 在 Markdown 里插图片确实是个问题：要把文档传到网上，很可能得先把图片上传到图床服务器——给它生成一个固定的网址再填进小括号；GitHub 的 README 插图不用这样操作，直接填一个相对路径就可以。

   * **目录与分隔线**

       * 想给文档插一个目录，直接在那个地方写一个中括号 `[TOC]` 就可以；分隔线是三个星号。

   * **表格**

       * 比 LaTeX 里面的表格简单得多：手打、手搓一个出来就好；第二行里那些冒号和减号指定的是当前这一列的对齐方式。

| 第二行的写法 | 对齐效果 |
| :--- | :--- |
| 冒号只在左边 | 左对齐 |
| 冒号只在右边 | 右对齐 |
| 两边都有冒号 | 居中 |

## LaTeX 定位与编译模型

   * **LaTeX**

       * 发音：专指这个文档工具时读「拉泰克」，后面那个 X 只发一半的音；全小写的 latex 本义是「乳胶」，表示乳胶时 X 正常发音——日常怎么读都好，大家明白就行。

       * > **定义**：一个很高效、也很高质量的排版系统，生成的文本一般比 Markdown 专业得多；发 paper、甚至出书都是用 LaTeX 写的，Markdown 相比之下更随意。

       * 与 Markdown 的本质差异：Markdown 有点类似「即时解释」，很轻量，相当于字符串之间的映射；LaTeX 类似 C++ 这样的语言——把整个代码写好之后需要编译这份代码，才能转化成 PDF 输出。

       * 有很多很多的宏包，跟正规的编程语言一样需要各种外部的包；宏包也可以自己开发；遇到很详细的问题可以去搜官方文档。

       * Typst：一种类似 LaTeX 的新排版语言，具体细节长文未说明。

## LaTeX 编辑器：Overleaf 与本地方案

### Overleaf

   * 最常用的 LaTeX 编辑器，是一个管理你所有 LaTeX 文档的网站（www.overleaf.com）、一个服务器；每个文档都可以添加合作者协同在线编译，有点类似现在的腾讯文档——它是实时编译的：你敲一个字，在线的协同者立马就可以看到，前提是要网好。

   * 模板很多：登录后进入 project 页面，点上面一栏的 templates，有书、文章、引用等等大量模板；想搜某个会议的模板（如 CVPR 的文章模板）理论上每一年的都可以搜到；点进去直接 open，它会自动存到你的项目里，接下来改个名、再改对应的作者信息、正文、摘要等就可以用了。

### VS Code 本地方案

   * 用 VS Code 写 LaTeX 需要安装 TeX Live、配置编译环境，并且 VS Code 里也要安装对应的插件，这样才能充分利用起来。

   * 两者之间还是推荐使用 Overleaf——只要你网好。

## LaTeX 文档框架与导言区

   * **基本框架**

       * 开头用 `\documentclass` 指定文档的类型，比如 `article`；文章中要写中文的话，需要换成 `ctexart`。

       * 和一般编程语言一样，LaTeX 也有注释：行注释用百分号 `%` 开头。

       * `document` 环境里才是你真正想显示的内容：所有的文本、图片、表格、标题、列表都写在 `\begin{document}` 与 `\end{document}` 之间——它有点类似于 C++ 里的 main 函数，你真正要执行的代码都在这个环境下面。

```latex
\documentclass{article}   % 要写中文，就换成 ctexart
% 导言区：引入宏包、声明全局变量
\begin{document}
这里才是你真正想显示的内容
\end{document}
```

   * **导言区**

       * `document` 环境外面、前面那一段叫导言区，有点像 Python 里的 import、C++ 里的 include：说明你要包含哪些宏包；也有一些 predefined 的变量，比如作者的名字。

       * 导言区里可以定义一些快捷命令（command），定义的方法是用 `\newcommand` 这个指令。

## LaTeX 标题、章节与列表

   * **标题三件套**

       * `\title` 指定文档的标题、`\author` 指定作者的名字、`\today` 显示今天的日期。

       * > ⚠️ **易错点**：在导言区里只是定义了标题、作者和日期，它们并不会自动显示出来；要真的显示，得在 document 环境里面写一个 `\maketitle`，它会把你在导言区定义的所有东西打出来。

   * **章节层级**

       * 开新章节用 `\section`，新的子章节是 `\subsection`——类似于 Markdown 里的一级标题和二级标题；再往下是 subsubsection，但应该最多就到这一级，理论上不应该再分更细的章节，想再细分得用其他方式，比如字体加粗。

       * `\paragraph` 用于指定一个段的段首小标题。

   * **列表**

       * 类似 Markdown 圆点列表的用 itemize 环境 `\begin{itemize}`，每一个条目的前面都需要加一个 `\item`；以数字开头的列表，换成 enumerate 环境就可以了。

## LaTeX 公式与交叉引用

   * **行内与行间公式**

       * 行内公式和 Markdown 一样，用一对单个的美元符号括起来。

       * 行间公式用 `\begin{equation}` 到 `\end{equation}`，对应于 Markdown 里双美元符号括起来的公式；也可以像 Markdown 一样直接用双美元符号括——区别是 equation 会给你带一个后面的 label（公式编号），双美元符号括起来的不带。

   * **多行对齐公式**

       * 想把多个等式并列地写，用 align 环境：可以写多行公式，并且可以只对齐等号，或者对齐最左边、对齐最右边，都可以设置；要用它需要加 amsmath 宏包——`\usepackage{amsmath}` 这句话放在导言区里。

   * **交叉引用**

       * 想引用一个公式，就在这个公式的环境里面加一句 `\label{...}`：相当于声明了一个变量，这个变量代表这个公式；行文里用 `\ref{...}`（ref 是 reference 的缩写），后面大括号里写同样的变量名。

       * 渲染出来，`\ref` 对应的位置显示的就是这条公式的编号（比如 1）；生成 PDF 之后点一下这个编号，就可以自动跳转到公式所在的那一行。

   * **公式语法同源**

       * Markdown 和 LaTeX 打公式的格式都是 TeX math：最开始 Markdown 不支持公式，是加了一些扩展才支持 LaTeX 里的数学公式——所以它们的数学公式语法是一样的。

       * 公式最好还是手打：直接放 figure 里有点太麻烦，而且很多时候放 figure 也不规范；用 VS Code 的话它有一个「作弊表」叫 snippet panel，会告诉你公式里那些符号都怎么打。

## LaTeX 插图与浮动体

   * **直接插图**

       * `\includegraphics`：中括号里写参数，一般是用来指定图片的缩放，比如 `0.7\textwidth` 就表示把图片缩放到宽度等于 0.7 倍的文本宽度；后面大括号跟图片的文件名。

       * 在 Overleaf 上插图需要先在项目里导入这个图片，路径就是项目里图片对应的路径；本地的话相当于相对路径，也可以用绝对路径。

   * **浮动体（figure 环境）**

       * 一般不会直接用 `\includegraphics` 插图：这样没有标题、对图片的引用这些，都不太行，想控制图片的位置也很难；所以一般都把图片放在浮动体里——所谓浮动体，其实就是 figure 环境。

       * figure 环境里还可以加：`\centering` 表示把图片放到整个文档居中的位置；`\caption` 是标题；后面还可以像公式一样加一个 `\label`，然后用和公式一样的方法引用这张图片。

   * **位置建议 [htbp]**

       * `h` 表示 here，希望图片尽可能放在当前位置；`t` 表示 top，尽可能放这一页的顶端；`b` 就是 bottom，放页底端；`p` 表示 float page，图片单独放在一页里——这是一份按顺序给的排版建议：当前位置放不下（比如图片太大）再考虑页顶端，再不行页底端，再不行其他选项。

       * 这只是给 LaTeX 的建议，它有时在一些情况下不会采取、会直接忽略；想强烈建议可以在前面加一个叹号 `!`，但这时 LaTeX 还是有可能忽略；想再强硬地强制它把图片安排在当前位置，可以用大写的 `H`——不过这种强制放图片位置的做法一般是不提倡的。

       * > **注意**：LaTeX 的宗旨是尽可能按照编译器自己的审美去排版，而不是按照你的审美——按你自己的审美排版很可能产生大量的空白，导致不美观；一般都是按照 LaTeX 自己的习惯去排图片。

## LaTeX 表格

   * **tabular 环境**

       * 表格也有和图片一样的安排位置的方式：可以用中括号去建议它放在哪里。

       * `\begin{tabular}{cc}` 后面大括号里的字母逐列指定对齐：`c` 表示该列内容居中，两个 c 就是两列都居中；也可以替换成 `l`（左对齐）或 `r`（右对齐）。

       * 排格子：先输入内容；想切到同一行的下一个格子就加一个 `&` 再输入下一格内容；想换行就用双反斜杠 `\\` 换到下一行——这样就生成了一个 2×2 的表格。

   * **加线**

       * 竖线：加在 tabular 后面大括号里 c 和 c 的中间，就表示表格的列与列之间由竖线分隔。

       * 横线：不仅要换行，换行之后还需要加入单独的一行 `\hline`，`\hline` 之后再换行，才会在行与行之间添加一条横线。

       * > ⚠️ **易错点**：`\hline` 只在它出现的位置画线——只在第一行和第二行之间加了一个，就只会在这两行之间有这一条横线，表格的上面和下面是不会加的；要上面和下面也有横线，必须在第一行的前面、最后一行的后面也各加一个 `\hline`。

   * **转换工具**

       * Excel2LaTeX 是一个网页：直接在网页上传一个 Excel，或在网页上手动编辑一个表格，它可以自动转化成 LaTeX 代码，复制过来就好——表格还有很多其他高级排版选项，用它代劳不用愁。

## LaTeX 论文引用与 BibTeX

   * **引用库**

       * 论文引用一般采用 BibTeX 格式：在 LaTeX 项目里添加一个 `.bib` 文件，把所有文献引用相当于列个清单，以 BibTeX 格式保存在这个文件里。

   * **启用引用**

```latex
\bibliographystyle{...}   % 指定引用的风格
\bibliography{...}        % 大括号里是 .bib 文件的文件名，不要加后缀名
```

       * 这两句写在 document 环境当中、`\end{document}` 之前，也就是正文最后的地方：先用 `\bibliographystyle` 指定引用的风格，再用 `\bibliography` 指定用哪个 BibTeX 文件作为引用库。

   * **行文引用**

       * 行文中需要引用某篇文章时，直接在那个地方输入 `\cite{条目名}`：大括号里的字符串就是每一条 BibTeX 条目的第一个参数；条目里后面其他的参数会指定文章名、作者名、哪个 journal、哪一页、哪个号、年份等等的信息。

   * **获取途径**

       * 谷歌学术：找到一个条目的「引用」点一下，弹出对话框；对话框里再点一下 BibTeX，就会弹出一个页面，显示它真正的 BibTeX 格式，直接复制到你的 `.bib` 文件里就可以。

       * > **注意**：谷歌学术里的这个格式可能包含的信息并不完全，有时直接复制是不太可信、不够用的——有些文章的信息可能不全；这时需要找到这篇文章作者的主页，去主页的 publication 里找作者自己写好的 BibTeX 格式。

## 正规场合的排版硬约束

   * **会议投稿**

       * 现在最主流的会议，投稿一般只接受用 LaTeX 或者用 Word 排版的格式，用其他的可能就不接收了——不是随便编辑一个 PDF 就能交上去的。

   * **arXiv**

       * 把文章传到 arXiv 上不接受直接传 PDF：必须传一整个 LaTeX 项目，由它帮你去编译，而且它的编译器还经常出问题——所以挂 arXiv 是个很复杂、很麻烦的事情。

       * 挂 arXiv 的意义：还没有正式发表的东西先提前挂上去，让学界的所有同行看到——相当于占了个坑，不会出现撞题的尴尬；比如想投某个会议但它的 DDL 还没到，可以先挂上 arXiv，表明这个问题你已经做掉了、正要投出。

   * **Word**

       * 有些会议现在还是接收 Word 编辑出来的 PDF；但 Word 并不是想象中那么简单：它可能需要很高级的操作，有时也需要写一些脚本才行——Word 涉及的高级用法可能比 LaTeX 难多了、复杂多了。
