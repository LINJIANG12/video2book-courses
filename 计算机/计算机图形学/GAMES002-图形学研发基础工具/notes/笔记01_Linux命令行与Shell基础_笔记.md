# Linux命令行与Shell基础

## Linux 与分层结构

* **Linux**

    * > **定义**：一群开源的、基于 Linux 内核的类 UNIX 操作系统的集合。

    * 定义拆开是四个关键词：开源、Linux 内核、类 UNIX、操作系统的集合。

* **开源**

    * Linux 的核心代码人人可以找到、可以使用；有条件也可以运行、修改它，并向开源社区做贡献。

    * Linux 系统的代码在 GitHub 上有公开仓库，谁都可以去看。

* **内核（kernel）**

    * > **定义**：直接控制硬件的那一层，位于计算机层层抽象的最中心。

    * 计算机的本质是一层抽象包着一层抽象，像不断往里剥的橘子，也像套娃。

    * 内核直接跟硬件打交道，复杂得像机器语言，不适合让人类直接操作。

* **壳（shell）**

    * > **定义**：封装在内核外面的一层壳，是外界与计算机内部之间的接口。

    * shell 与内核打交道的方式是一行行的命令行：打开一个类似 DOS 的窗口，在里面输入一系列命令让计算机做事——这个窗口里运行的就是 shell 程序。

    * 比 shell 更外层的是应用（application）：五花八门、有图形化界面的软件，这才是日常使用最多的层级。

    * 分层结构（从外往里一层包一层）：

    ```text
    应用 application            ← 五花八门的图形界面软件，我们最常接触的层级
      └─ 壳 shell               ← 外界与内部之间的一层壳，用一行行命令和内核打交道
          └─ 内核 kernel        ← 直接控制硬件，复杂得像机器语言，不适合人直接操作
              └─ 硬件 hardware  ← 最中心的部分，计算机硬件本身
    ```

* **类 UNIX**

    * 强调的是 Linux 不是 UNIX：流传的笑话是把 LINUX 解析成 "Linux Is Not UniX"。

    * Linux 与 UNIX 不一样，但很类似。

* **Ubuntu（乌邦图）**

    * Linux 并不是一个单独的操作系统，而是一个操作系统群：各个时期出现的每一个系统其实都是 Linux 系统，这些系统的总称才叫 Linux。

    * Ubuntu 是这个家族中的一员（位于系统时间线的右上角）。

## 使用 Linux 的理由

* **系统优点**

    * 快、稳定、有很方便的包管理、开源、功能齐全。

    * 开源带来好生态：世界各地的开发者（contributor）都会对项目做贡献，不是局限在一个公司内的封闭工作模式。

    * 东西是开源的、开发者又能非常详细地了解内核，就可以很有针对性地为 Linux 提出优化方法。

* **远程服务器**

    * 跑很大的模型或深度神经网络（deep neural network，DNN）往往要租服务器，只能远程连接，而那台服务器上的操作系统一般就是 Linux，避免不了。

* **仿真环境**

    * 机器人学（robotics）常用的 Gazebo 这类带物理仿真的仿真环境，只能在 Linux 上运行、或者说只在 Linux 上运行得比较好，其他系统兼容得不太好。

* **领域差异**

    * 图形学领域用 Linux 反而比较少，Windows 用得多一些。

    * 操作系统、计算机网络方向，以及软件开发，都很有可能只用 Linux、不用 Windows。

    * 上述用途只是冰山一角，并不全。

## 访问 Linux 的三种方式

* **真机安装**

    * 从一台白板电脑开始直接安装 Linux，过程比较复杂。

    * 需要 U 盘启动盘，或者一张 CD 光盘；关键是下对镜像的版本，一般用 Ubuntu 18.04 或 20.04，有更新的版本也可以。

* **WSL（Windows Subsystem for Linux）**

    * > **定义**：Windows 下的一个应用程序，它模拟出一个 Linux 环境。

    * 界面是弹出一个窗口，里面就是 Linux 的 prompt，可以像使用一台 Linux 服务器一样输入各种 Linux 命令。

    * 典型用途：Windows 上从 GitHub clone 了一份只能在 Linux 上跑通的代码，这时就用 WSL 跑。

    * Linux 子系统的文件系统与本机 Windows 双向共享：Windows 能访问 Linux 的文件系统，Linux 子系统也能访问 Windows 的文件系统，非常方便。

    * 一般要到 Windows 10 及以上系统版本才能安装。

* **虚拟机**

    * 用 VMware 或 VirtualBox 这类虚拟机软件，再下一个 Ubuntu 的系统镜像即可运行。

    * 比 WSL 完善得多：有完整的图形界面，不只是终端。

    * 虚拟机里的东西一般和本机文件不共享，一般手段通不了，通常只能通过网络的方法传输文件。

* 三种方式对比：

| 访问方式 | 它是什么 | 和 Windows 的文件互通 | 要注意什么 |
| :--- | :--- | :--- | :--- |
| 真机安装 | 在白板电脑上直接安装 Linux | ——（它本身就是操作系统） | 过程复杂，需要 U 盘启动盘或光盘；下对 Ubuntu 镜像版本，18.04 / 20.04 常用 |
| WSL | Windows 下的应用程序，模拟 Linux 环境，弹出命令行窗口 | 双向共享，非常方便 | 需 Windows 10 及以上；像用一台 Linux 服务器 |
| 虚拟机 | VMware / VirtualBox 加 Ubuntu 镜像 | 一般不共享，多靠网络传输 | 有完整图形界面，比 WSL 完善 |

## 终端与提示符

* **打开终端**

    * Linux 系统或 Linux 虚拟机：切到桌面按 `Ctrl+Alt+T`，或者在程序里搜索 terminal。

    * Windows：打开 PowerShell（Windows 里类似 shell 的一个程序），输入 `wsl` 回车——光标变成另一个样子，就说明进入了 Linux 子系统（前提是已装好 WSL）。

* **提示符（prompt）**

    * 进了 shell，先认提示符这一行字符串：

    ```text
    user@hostname:~$
    │    │       │
    │    │       └─ 冒号后面：你当前所在的路径
    │    └─ @ 后面：这台电脑的名称
    └─ @ 前面：你的用户名称
    ```

    * 一句话读图：@ 前面是你（用户名称），@ 后面是你的机器（电脑的名称），冒号后面是你现在站的位置（当前所在路径）。

* **WSL 1 与 WSL 2**

    * 用一还是用二区别不是很大；但要运行一些比较 fancy 的、在 Linux 上跑的程序，推荐用 WSL 2。

## 命令结构与 shell 的工作机理

* **shell 的工作机理**

    * > **定义**：shell 本身也是计算机系统上的一个程序，是一个专门"调用别的程序"的程序。

    * 敲下回车后，shell 并不是自己在跑你的命令，而是开启一个子进程去运行你想调用的程序，那个程序与当前 shell 相互独立。

    * 回车之后 shell 处于挂起状态，等程序运行完，再由 shell 把屏幕的控制权接管回来——看上去两者像在同一个进程里无缝衔接，实际是"开子进程、等它跑完、收回控制权"。

    * 计算机导论课（ICS）的经典 lab「tiny shell」就是亲手实现这个"能调用其他程序的程序"。

* **命令的结构**

    * > **规则**：一行命令的第一个单词是你要调用的程序名称，用空格结束它；空格后面的内容全部是参数，参数与参数之间也用空格隔开。

    * 参数是那个程序的输入之一；程序还有别的输入方式，比如文件输入。

    * shell 收到指令后，就调用第一个单词对应的系统内置程序来执行命令——比如调用 echo 这个程序，把后面输入的内容打印在屏幕上。

    * > **注意**：有一些命令系统不自带，运行时会提示安装相应程序，装上才能执行。

* **空格与参数**

    * 参数之间的空格都被视为分隔符：hello 和 world 之间打很多个空格，echo 输出的中间仍然只有一个空格。

    * > **易错点**：连续的空格不会出现在输出里——它们只是参数分隔符。想让空格成为内容本身，就要靠转义或者引号。

* **echo 与同一输出的四种机理**

    * > **定义**：echo 将后面跟着的参数原封不动地输出到屏幕，它本身就是一个 shell 指令；多个参数按顺序输出、中间隔一个空格。

    * 下面四行输出结果完全一样，但工作机理完全不一样：

    ```bash
    echo hello world      # 两个参数：hello、world
    echo hello\ world     # 反斜杠转义空格，整体作为这一个参数
    echo "hello world"    # 双引号括成一个参数
    echo 'hello world'    # 单引号括成一个参数
    ```

    * 反斜杠 `\` 是转义字符：把转义符后面紧跟着的那个字符变成字符串中的一部分，于是 `hello\ world` 作为一个整体、一个参数传给 echo。

    * 在字符串外面扩上一层引号，中间的空格就失去分隔符的含义、变成字符串的一部分；单引号和双引号在这里效果一样。

    * > **提示**：引号在 shell 里的用法有讲究，还可能出现更复杂的情况，之后遇到更复杂的指令时值得进一步了解。

## PATH 与程序搜索

* **PATH**

    * > **定义**：一个名为 PATH（大写）的环境变量，内容是一堆用冒号分隔开的路径，每一个路径就是一块搜索空间，形如 `路径1 : 路径2 : 路径3 : …`。

    * shell 的职责是"选择一个程序来跑"：你只给了它一个名称，它就按顺序遍历 PATH 中的所有路径来搜索想调用的程序——找到就执行，找不到就报错。

    * 查看方式：`echo $PATH`，会输出很长一串冒号分隔的路径。

    * > **注意**：想输出一个变量的内容，必须在变量名前面加上美元符号 `$`，否则变量名会被解析成一个字符串。

## 路径：绝对路径与相对路径

* **路径**

    * Linux 的路径就是一个字符串：里面有一堆斜杠，斜杠中间夹着一串文件名或文件夹名。

* **绝对路径**

    * 以斜杠开头；这个斜杠本身也是一个路径，叫根目录。

    * 绝对路径从根目录出发去索引。

* **相对路径**

    * 一般以 `./` 开头（一个小数点加一个斜杠），表示从当前路径出发去索引想要的路径。

    * "当前路径"就是终端提示符里冒号后面的那部分，即你现在所在的位置，相对路径都以它为起点。

    * > **易错点**：想用相对路径时，千万不要用斜杠开头——斜杠开头意味着"从根目录从头开始找"，那就不是相对路径了。

* **pwd 与 cd**

    * `pwd`：输出当前路径的完整名称。

    * `cd 路径`：切换当前路径，绝对路径、相对路径都可以。

    ```bash
    pwd             # 查看当前路径的完整名称
    cd /            # 直接切到根目录
    cd ./home/xjr   # 用相对路径切换
    cd home/xjr     # ./ 可以省去，效果相同
    ```

* **特殊路径写法**

| 写法 | 含义 | 类比 Windows |
| :--- | :--- | :--- |
| `.` | 当前路径 | — |
| `..` | 父路径，也就是返回上一级 | 资源管理器的"向上"按钮 |
| `-` | 上次到达的路径 | "后退" |
| `~` | home 文件夹所在的路径，即你的用户文件夹所在位置 | — |

    * 示例：`~` 就是 `/home/xjr` 这样的一个路径。

## 一切皆文件

* **一切皆文件**

    * > **定义**：Linux 的宗旨——把所有资源都视为文件来管理，包括所有的硬件设备，甚至是网络。

    * 想通过网络远程给另一台设备发送消息，方式也是往某一个特殊的文件里写这条消息，写完消息就发送过去了；这个的学术名词叫网络套接字（socket），学计算机网络时会正式接触到。

    * 带来的好处：不同类别的资源可以用同样的方式管理——只需要按照管理文件的那一套方式，去管理所有资源。

* **/sys/class 实例**

    * /sys/class 这个目录下，每一个文件夹都代表了一种硬件设备，里面的所有文件可以查看设备的各种参数。

    * 例：`power_supply` 是电源，进到里面用 `cat uevent` 查看 uevent 文件，就能看到电池相关的各种参数——类型、是否满电、容量等等。电池在 Linux 系统下就是一个文件。

## 重定向与管道

* **标准输入输出**

    * shell 当中每个指令都有输入和输出流，默认情况下是标准输入输出（standard input / output）——直接从屏幕读取输入、直接输出到屏幕。

    * 想让某个指令输出到文件，或者从文件里读入信息，就用小于号和大于号。

* **重定向**

    * > **定义**：用小于号、大于号改变指令输入输出流的去向，让它从文件读入或写出到文件。

| 写法 | 作用 |
| :--- | :--- |
| `< 文件` | 改变输入流：从这个文件里读取信息 |
| `> 文件` | 向这个文件里写东西（默认清空文件、从头开始写） |
| `>> 文件` | 在文件末尾追加，原来的内容保留 |

* **管道**

    * > **定义**：用一根竖线 `|` 把两条指令接起来——竖线前面是一条指令 A，后面是另一条指令 B，意思是把 A 的输出作为 B 的输入。

    * 例：`cat blank.txt | grep eth`——cat 本来会把文件里的所有内容输出到屏幕，接上管道后这些内容不输出到屏幕，而是传给 grep；grep 在给它的输入当中查找字符串 eth，找到了就把结果标出来，找一个不存在的（如 etb）就什么都不会输出。

    * > **注意**：文件重定向和管道是两个东西，先把概念分清。

## 权限位

* **权限位**

    * > **定义**：`ls -l` 输出中每行开头那串由 r、w、x 和减号组成的字符串，标明各类用户对这个文件能做什么。

    * 只输入 `ls` 只会孤零零地显示文件名；加上 `-l` 选项才能查看当前路径下所有文件和文件夹的更多信息。

* **第一位的文件种类**

    * `l`：软链接（link 的缩写）；`d`：目录（directory 的缩写）；`-`：一般的普通文件。

* **后九位的三组权限**

    * 后九位每三位一组，从左到右依次是：用户权限、组权限、其他用户权限。

    * 用户权限：当前这个用户可以对这个文件做什么；组权限：当前用户所在的这个组可以对它做什么；其他用户权限：其他组的其他用户可以对它做什么。

    * 权限位之后还有两个名字：用户名称（标明这个文件是哪个用户创建的）与组名称（标明文件所有者所在的组）。

    * 结构示意：

    ```text
    -  rwx  rwx  rwx
    |   |    |    |
    |   |    |    +--- 其他用户权限
    |   |    +-------- 组权限
    |   +------------- 用户权限
    +----------------- 文件种类
    ```

* **r、w、x 的含义**

| 字符 | 全称 | 意义 |
| :--- | :--- | :--- |
| r | read | 读取权限：可以查看这个文件 |
| w | write | 写入权限：可以往文件里写、修改这个文件 |
| x | execute | 执行权限：可以把这个文件当作可执行文件来运行 |

## chmod：修改权限位

* **chmod（change mode）**

    * > **定义**：修改权限位的命令，有两种修改方式，命令最后都跟一个文件名，表示要修改的对象。

* **方式一：逐位加减**

    * 中间是一个三字符的字符串：

| 位置 | 取值 | 含义 |
| :--- | :--- | :--- |
| 第一个字符 | u / g / o / a | 改用户权限 / 改组权限 / 改其他用户权限 / 三组一起改 |
| 第二个字符 | `+` / `-` | 添加这个权限 / 剥夺这个权限 |
| 第三个字符 | r / w / x | 读 / 写 / 执行 |

    * u 是 user，改权限串第一组那三位；g 是 group，改中间那三位的组权限；o 同理改最后一组；a 是 all，表示所有权限位一起改——用户权限、组权限、其他用户权限全包括。

    * 例：`sudo chmod a-x copy.py` 取消所有用户对 copy.py 的执行权限——这个文件是 root 账户创建的，改它的权限需要 sudo 提权；改完用 `ls -l` 看，权限位里所有 x 的地方都变成减号，再把执行权限加回来，x 位又都亮回来。

* **方式二：三位八进制数**

    * 把三字符字符串换成一个三位的八进制数，每一位分别对应第一组、中间一组、最后一组权限位。

    * 换算方法：有权限记为二进制中的 1，没权限记为 0；三位三位地看，把每组的二进制数换算成一个八进制数，填到八进制数的对应位上。

    * 例：权限串 rwx rw- r-x 对应八进制 765：

    ```text
    rwx  rw-  r-x
    111  110  101
      7    6    5     -->  765
    ```

    * `chmod 765 copy.py` 之后再用 `ls -l` 看，权限串就变成 rwx rw- r-x，与推出的 765 完全对应。

## root 与 sudo

* **root**

    * > **定义**：Linux 系统里总会存在的最高用户，永远具有最高权限，想做什么都可以。

    * 其他用户所能做的所有操作，都是 root 能做的操作的子集。

* **sudo（super do）**

    * 当前用户不是 root 时，想以 root 的身份做某些事情，就在命令前面加一个 sudo——super 就是超级、超级管理员的意思，后面再加上想调用的命令。

    * 习惯是指令运行失败、提示权限不够，就在前面加个 sudo 再跑一遍——多数时候真能过，但它不完全是这么回事。

* **sudo 管不到重定向**

    * 场景：blank.txt 是 root 创建的文件，权限位上只有 root 用户和 root 组下的用户有 w 权限，其他用户没有写权限；要求在不修改拥有者、也不修改权限位的前提下往里写入内容。

    * `echo something > blank.txt` → permission denied；按习惯加 sudo 改成 `sudo echo something > blank.txt` → 同样被拒绝。

    * 原因：sudo 只管得到 echo 这一条命令，管理员权限只给了 echo；而后面的重定向写入这个操作是由 shell 本身来做的——shell 不是以 root 身份登录的，自己没有 root 权限，自然改不了 blank.txt。

    * > **易错点**：`sudo` 提升的只是紧跟其后那一条命令的权限；`>` 这类重定向的接线工作始终由 shell 亲自完成，shell 不会因为你写了 sudo 就变成 root。

* **tee：把写入交给被提权的命令**

    * > **定义**：tee 从标准输入接收输入的字符串，后面跟一个文件名，把接收到的内容写进这个文件。

    * 正确做法：`echo something | sudo tee blank.txt`——echo 的输出 something 通过管道进入 tee 的标准输入，tee 再把它写到 blank.txt 里；tee 被 sudo 提了权，有 root 权限去修改这个文件，写入就成功。

    * 关键在读这条链：整条写入路径上被提权的只有 tee，而它恰好就是真正执行写入的那个角色。

    ```text
    echo 的输出 ──> tee 的标准输入 ──> tee（被 sudo 提权）──> 写入 blank.txt
    ```

## 包管理：dpkg 与 apt

* **dpkg：手动安装 .deb 包**

    * 从网站上手动下载一个 .deb 软件包（扩展名就是 .deb），然后在 shell 里输入 `dpkg -i 软件包.deb`（i 就是 install），把这个 .deb 文件解压并安装。

    * 这个方法很不好用：得自己从网上找软件包；自己找的包不一定靠谱，有可能携带病毒，硬装上去可能对电脑造成损害。

* **apt：从源服务器安装**

    * 推荐方式：`sudo apt-get install 软件包名`，apt 会去一个指定的地方——Ubuntu 的源服务器——去找，找到的都是官方提供的软件包，下载下来的一定安全可靠。

    * 软件包的名称需要自己去调研，不是很好知道：比如输入没有的命令 exa 会报错，并提示 try 一下 `apt install exa`，照着装就行；但提示的名称也不一定就对，必要时上网查。

* **换源与 update**

    * 默认从 Ubuntu 的服务器上下载，在国内可能会比较慢；想加速可以换源，比如换成清华源，现在已经有北大源了，推荐直接搜「北大源」来用。

    * 切换源之后需要执行 `sudo apt-get update`，才能真正切换成新的源；以后再执行 install 命令就都从新源上获取软件包，一般都比较快。

## shell 变量与环境变量

* **赋值与访问**

    * 变量的声明和赋值跟 Python 有点像：直接写一个名称，接上等号，后面接上它的值，如 `fu=bar`——fu 是变量名，bar 是它的内容（一个字符串）。

    * 访问变量：在前面加一个美元符号，如 `echo $fu` 就会显示出 bar。

    * `$fu` 的本质是一次字符串替换：shell 会把 `$fu` 这个部分替换成 bar，所以在命令行里输入 `$fu` 完全等价于直接输入 bar。

    * > **易错点**：等号两边不能加空格。空格在 shell 里是分隔符：写成 `fu = bar`，shell 会把 fu 理解为你要调用的命令名，把等号和 bar 作为两个参数传给这个"命令"——这肯定不是你想要的，多半报"没有 fu 这个命令"的错误。

* **env 与 set**

    * `env`：查看所有的环境变量，每一条都是"变量名=值"的格式。

    * `set`：显示更多的东西，里面也包含 env 显示的那些变量——它查看的是环境变量与 shell 变量的并集，还包含当前 shell 环境下的所有变量。

* **两套变量相互隔离**

    * 环境变量和 shell 变量是相互隔离的两个概念：`fu=bar` 只会被添加到 shell 变量的集合里，不会进环境变量的集合。

    * shell 变量有点类似"每一次进程里加载出来的变量"：每次打开 shell 都会重新加载，退出 shell 的时候就被清空——把 shell 关掉再重新打开，`echo $fu` 就没有值了。

    * 环境变量则是每次启动 shell 的时候必然加载到当前 shell 环境里的变量——所以它才叫"环境"变量。

| | shell 变量 | 环境变量 |
| :--- | :--- | :--- |
| 典型例子 | `fu=bar` 这样直接赋的值 | `PATH` 这类系统级变量 |
| 生命周期 | 退出 shell 即清空 | 每次启动 shell 必然自动加载 |
| 查看方式 | `set`（环境变量与 shell 变量的并集） | `env` |

* **export 与 .bashrc**

    * `export fu=bar`：在赋值语句前面加上 export，就把 fu 添加到环境变量里去了；但这个添加也是一次性的——只发生在当前这个已经启动的 shell 里，下次重启 shell，环境变量里还是不会有 fu。

    * 永久添加：把 export 赋值语句放进 home 文件夹下的 .bashrc 文件末尾——直观意义是每次启动 shell 的时候都先执行一下这条语句，那自然每次启动之后环境变量里都有这个变量。

    * .bashrc 因为是点开头的，在 Linux 下是一个隐藏文件，平常的 `ls` 看不到它，要用 `ls -a` 才能看到；它的内容其实就是一堆 shell 命令。

    * 刚加进 .bashrc 的语句不会立刻执行，要重启 shell 窗口才执行；不想退出窗口的话就用 `source .bashrc`——它会执行 .bashrc 里所有的命令，把刚加进去的环境变量加载进来。

## 命令替换与进程替换

* **命令替换 `$(命令)`**

    * > **定义**：美元符号后面跟一个括号、括号里放想执行的命令；把括号里的命令执行完之后，用它的输出替换掉整个 `$(...)` 串。

    * 效果：把一条命令的输出结果拿来当参数用，命令的执行结果被放进了命令行、成为其中的一部分。

* **进程替换 `<(命令)`**

    * 小于号后面跟一个括号、括号里填上一条命令：把命令的输出重定向到一个临时文件——这个文件是临时的、虚拟的，并不会真的在某个目录下创建出来，但可以把它当作存在的文件来用；整个 `<(命令)` 会被那个临时文件名自动替换掉。

    * 最典型的用法：diff 可以比较两个文件的差别，但 diff 后面只能跟文件名；想比较的不是两个文件、而是两条命令的输出（比如比较两次 echo 的输出是否一样）时，用进程替换把每条命令的输出都变成一个"文件"：

    ```bash
    diff <(第一条命令) <(第二条命令)
    ```

    * 这两个操作按经验不算特别常用，但值得掌握。

## 脚本语言与编译语言

* **脚本语言**

    * > **定义**：通过解释器运行的语言，边执行边编译——解释器先读取一行的指令、立刻开始执行这一行，执行完再读下一行、执行下一行。

    * bash（就是 shell 所用的那种语言）、dash、Python 都是脚本语言。

* **编译型语言**

    * > **定义**：需要预编译的语言，典型的比如 C 和 C++。

    * 需要提前有一个编译器，把程序源文件读进来、转换成另一种语言——机器语言。

    * 编译流水线：

    ```text
    源代码 ──> 中间表示 ──> 汇编语言 ──> 二进制机器语言 ──> 可执行文件
    ```

    * 编译得到的可执行文件完全是二进制文件（Windows 下是 .exe 文件，Linux 下没有 .exe 这个后缀，就是可执行文件）；编译过程本身并不会执行你的程序，需要单独去运行这个可执行文件，才能真正运行程序的内容。

* **最大差别**

    * 脚本语言由解释器边编译边执行；编译型语言由编译器提前把源码编译成二进制可执行文件，运行的是编译产物。

## shebang 与脚本运行

* **shebang（#!）**

    * > **定义**：一个井号加一个叹号（`#!`），写在脚本文件的开头；系统看到它，就会把这个文件解析成一种脚本来对待。

    * shebang 后面跟一个路径，含义是想用哪个解释器去运行这个脚本：Python 脚本后面跟 Python 解释器所在的路径，bash 脚本就跟 bash 解释器的路径；书写格式是先写解释器的路径，空格再跟上解释器的名称。

    * > **提示**：Python 和 bash 里井号 `#` 都是注释符号，解释器读脚本时会把第一行忽略掉——第一行写的路径即使不符合语法也不会被看到；而系统层面，这一行又起到了引导"用哪个解释器来运行"的作用，一行两用。

* **运行脚本的前提**

    * 实际运行之前，一定要记得用 chmod 给这个文本文件加上可执行权限；加上之后直接输入文件名就可以运行——不需要先输入 python、空格、文件名，可以把它当一个可执行文件一样看待。

    * 实际过程：输入 `./copy.py` 后，shell 先去读取 copy.py 这个文件，发现第一行有 shebang 符号，于是到那个路径下找到 python3 解释器，然后运行 python3 copy.py——实际执行的就是这么一条指令。

* **为什么必须带 ./**

    * 直接敲 copy.py 是不行的，要带上前面的 `./`：环境变量 PATH 里没有当前路径，shell 在里面搜索不到 copy.py 这个文件，就会显示 command not found。

    * `./` 起到指示"这个路径到底在哪"的作用：`.` 表示当前路径，`./copy.py` 就是当前路径下的 copy.py。

    * 把当前这个路径添加进 PATH，shell 就能找到 copy.py，可以省去 `./`。

* **没有执行权限的后果**

    * 在 bash 里输入 `./文件名`，shell 会把这个文件当作可执行文件直接去运行；如果它没有可执行权限，就会报错。

    * `./blank.txt` → permission denied；即便 sudo 也不行，root 用户也没有这个权限——整个文件的权限位上一个 x 都没有，谁都执行不了它。

## 终端里的文本编辑

* **编辑器的选择**

    * 在终端里写代码文件一般还是用编辑器：装了 VS Code 之后如果有 `code` 命令，`code copy.py` 就会弹出 VS Code 打开这个文件。

    * vim：非常难用，有很多很多奇怪的快捷键，会用 vim 的都是大佬。

    * nano：比 vim 新手友好一点。

    * emacs：也可以，它的快捷键方式和 vim 很不一样，同样有一堆快捷键。

* **硬核写法**

    * 用 echo 加文件重定向，一行一行地往文件里写，后面想加内容就继续追加——确实也能把文件写出来，但非常麻烦，还是建议用编辑器。
