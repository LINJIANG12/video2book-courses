# 仿真渲染软件工具链

## 预览与渲染的分工

* **科研出结果的工作循环**

    * > **定义**：图形学研究从算法推进到展示的固定循环：算法生成 3D 模型或序列 → 借助软件做 3D 可视化、预览结果 → 看哪里出了问题、回头调试算法 → 不满意就回到预览再来一轮；若干轮迭代、算法足够鲁棒之后，把预览结果渲染成漂亮的样子作为最终成品。

    * 图形学最直观的体现之一：最后总能做出一个大家可以直接看到的成品，一般是一段视频或一个 3D 模型。

* **为什么 3D 可视化要借助软件**

    * 3D 的绘制比 2D 难很多：涉及三维透视变换等一整套事情，用人眼看 3D 模型和看一张平面画不是一回事；2D 绘制尚可自己写，3D 每次都自己写就非常麻烦，需要软件工具把结果方便地可视化出来。

* **预览与最终渲染的差别（以粒子法流体为例）**

    * 粒子法把流体离散化成一堆粒子；预览阶段通常只把粒子在三维空间里的位置打出来——有一个粒子就显示一个点，流体看上去就是一堆散点。

    * 渲染阶段要做的是把这些散点转化成流体表面的样子，让它看上去真的像水、像烟雾；预览结果与渲染结果正是软件工具链覆盖的两个环节。

* **两个软件的分工**

    * Houdini（胡迪尼）：通过渲染一段流体水滴动画入门，覆盖从导入粒子序列到渲染出片的全流程。

    * ParaView：通过速度场这类体数据的可视化介绍基本用法，界面更简单、播放更轻量。

## Houdini 界面布局

* **场景视图（Scene View）**

    * 整个窗口左边最大的一块，用来看效果；还没加任何东西时，场景里只有 Y=0 的地平面，平面上划分了一些网格。

* **参数视图（右上角）**

    * 凡是需要调参数的东西——光照、相机、物体的位置与旋转等属性——一般都在这里调。

* **节点网络视图（右下角）**

    * > **定义**：Houdini 的工作模式：拖拽节点（模块）、串联各模块的输入输出接口，把它们连成完整的工作流，有点像拖模块进行编程；加载一个几何图形也是通过节点完成的，一个几何对应一个节点。

    * 在网络视图里按 Tab，可以输入一些字母，根据输入的字符查找相应的模块。

    * 网络视图有多个标签页：OBJ 放几何物体，out 用来插渲染器模块，第三个标签 Material Palette 是材质面板；切到 SOLARIS 后还有 stage 标签。

* **底部播放条**

    * 播放、快进、停止按钮加进度条；导入序列后可以像动画一样一帧一帧播放，对直接可视化非常方便。

## 粒子序列导入与场景搭建

### geometry 与 file 节点

* **添加物体：geometry 节点**

    * 在节点网络视图按 Tab 输入 geometry，查找到并放置 geometry 模块；双击进入模块内部，里面又是一个空页面，可继续插入节点。

* **导入文件：file 节点**

    * 在 geometry 内部插入 file 模块，用来导入一个或多个文件；导入多个文件时按帧逐个导入。

    * 按帧导入靠文件名写法：命名成「字符串 + 数字 + 后缀」的形式，并把数字位写成 `$F`；`$F` 会被替换成 0、1、2、3……有多少个文件就编到多少号，按数字顺序把所有 OBJ 文件加载进来。示例命名：`surface_particles.$F.obj`。

* **粒子序列与显示**

    * 示例中的流体水滴用粒子描述，粒子放在 OBJ 文件里，每一帧对应一个 OBJ 文件；导入序列相当于把整个水滴（每个粒子）的动态都导入进来。

    * 插入 file 模块后在参数视图中修改要读取的文件，左侧场景视图就会直接把粒子位置可视化出来。

### OBJ 文件格式

* **三角网格（triangle mesh）**

    * > **定义**：OBJ 是一种描述 3D 模型的文件；游戏里的人物模型一般用三角网格完成，OBJ 就可以描述这种三角 mesh 数据结构。

    * 三角网格要存两类信息：三角形顶点所在的坐标，以及每个三角形三条边的连接关系。

* **裸粒子**

    * OBJ 也可以描述粒子：只把顶点坐标列上去、不给任何连接关系，那就是粒子。

* **点云（point cloud）**

    * > **定义**：三维场景中有一堆点、共 N 个点，每个点有一个三维坐标，整个点云就是 N×3 个数字，表示 N 个点的位置；导入的那一堆粒子就可以理解为点云。

    * 在物理模拟中它对应粒子系统：粒子除位置外还可能带速度、质量、密度等其他属性。

### merge 合并与圆锥体

* **merge（合并）节点**

    * 场景里有多个水滴、每个水滴只有自己的一个 OBJ 文件、又想把所有的水都渲染出来时，在 geometry 模块里加一个 merge 模块，把所有粒子合并在一起。

    * 示例有两路文件：surface particles（流体表面的粒子）与 inner particles（流体内部的粒子）；渲染整个流体要把两路合并——把两个 file 模块的输出接到 merge 模块的输入上，两个 OBJ 文件里的所有粒子就都加进来了。

* **圆锥体**

    * 同样插入一个几何模块，在参数视图中指定底面半径、中心点以及高度等参数即可；示例最终要可视化的就是水滴往下落、被锥体刺破刺穿的动态。

* **场景就绪的标志**

    * 所有物体加好后场景 setup 完成，点击底部的绿色播放即可看动画；此时动态正确但很丑：水还是一堆粒子，底下的圆锥没有任何材质、光秃秃的。

## 粒子转流体表面

### 转表面思路与节点链

* **扩球求并的思路**

    * > **定义**：把每个粒子扩充成一个有一定半径的小球；粒子一多，相邻粒子之间就有一些交集，把这些相交的球提取一个公共表面出来——想象一个很大的水滴里充满粒子，每个粒子扩成球，这些球的表面合并在一起，就相当于大水滴的表面。

    * 直接把所有球的表面求并，不可避免会产生一些很小的凸起，表面看起来是 bumpy 的——这正是后面平滑步骤存在的原因。

* **水几何内部的节点链**

    * 前半段（两个 file 加一个 merge）是搭场景时已经完成的：把两路粒子读进来、合并到一起；新增的是后三个节点，把合并后的粒子一步步变成可以拿去渲染的表面。

```text
[file: surface particles] ---+
                             +--> merge --> particle to VDB --> smooth --> convert VDB
[file: inner particles] -----+
```

### particle to VDB 关键参数

* **particle to VDB 节点**

    * 负责「把粒子扩成球、再把球的表面合在一起」这一过程。

* **Point Radius Scale（粒子半径缩放）**

    * > **定义**：控制每个粒子扩充出的球体大小的参数，参数越大，每个粒子扩充出来的球半径就越大。

    * > **易错点**：这个参数不能随手填，两头都有坑（取值后果见下表）；「太大」不是好看难看的问题，而是会出错——粒子碰撞锥体时严格贴在锥体表面上，向外扩充太多，扩充出来的表面已经嵌到锥体里面，相当于出现穿模。

    * 调参并不费劲：点击参数面板最右边的小按钮，左边的视图就会直接可视化这个操作之后的结果；拖动进度条就能看出当前半径是过大还是过小。

| 取值 | 表面效果 | 后果 |
| :--- | :--- | :--- |
| 太大 | 表面几乎不再有凸起 | 表面向外扩充太多，水滴比原来大很多，外扩的表面嵌进锥体，出现穿模 |
| 太小（小于粒子间距的一半） | 相邻两个球没有交集 | 表面变成两个球各自的表面，本质上看上去还是一对粒子，不可能合并成一个水的表面 |
| 合适 | 相邻球面有交集、能融合 | 表面连续，又不会明显外扩 |

* **Voxel Size（体素尺寸）**

    * > **定义**：相当于三维图像的分辨率，即网格的边长（示例取 0.01）。

    * 规则：最好比 Point Radius Scale 小一些，至少不能比它大；网格边长比粒子扩充的半径还要大时，网格就非常粗糙、不够精细，根本没办法表示出想要的表面。

### Smooth 与 Convert VDB

* **Smooth（平滑）**

    * 作用：particle to VDB 直接得到的表面很 bumpy、有凸起，要做一次平滑处理。

    * 参数：按照多大的邻域去平滑，同样有一个合适的值，可以直接可视化、拖动进度条自己手调。

    * Iteration（迭代次数）不是越高越好：越高肯定越慢，但越慢并不一定越好，实践时调到合适即可。

* **Convert VDB**

    * 作用：Smooth 之后拿到的数据结构还是 VDB 结构，而 VDB 并不能直接渲染，要转化成 polygon mesh（多边形网格）的结构——就像三角形网格那样。

    * 用法：该节点可以把 VDB 转化成各种各样的数据类型，把 Convert To 参数设成 Polygon，确保它转化成一个多边形 mesh 的数据结构即可。

* **全流程概括**

    * 把每个粒子变成一个小球 → 把小球的表面融合合并到一起 → 再进行平滑 → 最后转化成 mesh；做完这一套，场景视图里那团「圆球」就变成一个连续的表面了。

## 材质赋予

* **默认材质**

    * 没有赋任何材质时，Houdini 会按一个默认材质显示——什么都没有、白花花的一种默认模型，所以有了连续表面也还不像水。

* **Material Palette（材质面板）**

    * 网络视图的第三个标签；选进去后左侧列出一系列 Houdini 自带材质，还是挺丰富的。材质先在这里拖出来准备，具体属性在右上角的参数视图里改。

* **水用 glass（玻璃）材质**

    * 依据：水和玻璃很像——都是透明的，只不过折射率、反射率可能不太一样，改些参数就行；水的动态很丰富，只要是透明的，直接把它当玻璃渲染就已经很像水（至少很像一般动画里的水）。

    * 参数（点击 glass 材质后右上角出现该材质的参数面板）：

        * IOR（折射率）：调成 1.33，默认是 1.5。

        * Reflection（反射度）：调成 0.2。

        * Transparency（透明度）：调成 0.8。

        * Emission（发光度）：原来是 0，调到 0.04 让它轻微发一些光，光的颜色为蓝色。

    * 这几项调完，看上去就比较像水了。

* **锥体用 gold（金子）材质**

    * 把 gold 也一起从材质库拖过来，将圆锥所对应的材质设成 gold。

* **材质指定方法**

    * 把网络视图切回 OBJ 标签（插入几何的界面），里面已有两个几何：水和圆锥体；选中水对应的几何模块，在上面的参数面板选到 Render 标签，下面会有一个 Material 属性——把材质指定成拖进来的 glass 就好；想让圆锥变成金子做的，同理设成 gold。

## 相机与光照

* **渲染前的必备两件套**

    * 材质配好之后还不够，要完整地渲染一个场景，还需要两个必备元素：相机（拍摄的视角是什么）和光照。

### 相机

* **添加相机**

    * 场景视图右上角有一个 No Cam 标记——表示当前是一个自由的视角，和任何一个相机都没有关系；在这里点下去，就可以添加一个新的 Camera。

* **绑定视角调机位**

    * 添加后选择 Tie View to Camera or Light，把当前场景视图的视角和这个相机绑定到一起；之后拖拽整个场景、视角发生变化时，相机跟着视角同步变化，可以很方便地把相机设置成想拍摄的视角。

    * 调好之后再把 Tie View to Camera or Light 取消勾选，相机就设置好了。

* **属性自动同步**

    * 点 New Camera 之后，右边的网络视图里会多出一个 Camera 模块；在左边把视角调好，右边模块的一些属性会自动更新，不用管。

### 环境光照（Environment Light）

* **添加方式**

    * 在网络视图按 Tab 输入 light，会列出 Houdini 支持的所有光照；示例选环境光照 Environment Light。

* **本质**

    * > **定义**：相当于环境有一个包围盒——一个六面体（可以理解成一个长方体），把整个场景包括水滴、圆锥体都框在里面；Light 就是整个包围盒所发出的光。

* **参数**

    * 一般来讲，Environment Light 的默认参数就可以直接渲染；可能还需要调一些参数来达到期望结果，比如光照的强度、光照的颜色。

    * 还可以选择光源在最终渲染视图中可不可见。

* **光源可见性三态**

    * 没有加光照：渲染出来是一张完全黑的图片。

    * 加了环境光照、但没有选「能看到光源」：物体其实已经被环境光照亮了，只是渲染的背景是黑的。

    * 选了「能看到光源」：物体不仅被照亮，背景也是亮的。

## Mantra 渲染

* **Houdini 的两种渲染器**

    * Mantra 与 Karma 两种；Mantra 的特点是只支持 CPU，但功能比较全——只是比较慢——而且各种参数都非常灵活。

* **插入方式**

    * 网络视图点击 OBJ 标签、切到 out 标签（out 就是用来插渲染器模块的），直接搜索 mantra 插入即可。

* **Output Picture（输出文件）**

    * 在 Images 标签页下配置输出什么样格式的文件；默认是在 `$HIP` 这个目录下、按默认名字格式输出一个 .exr 文件，后缀可以直接改成 PNG（导出时扩展名也可以改成 JPG、PNG，或用默认的 .exr）。

* **Pixel Samples（像素采样数）**

    * > **定义**：每一个像素给它采样多少次；采样次数越高，渲染结果越精细、一般来讲噪声也越低，代价是渲染一帧会非常慢。

* **Ray Samples（射线采样数）**

    * 指一条射线去采样多少次，同属 Rendering 标签页下的渲染参数。

* **Render View 渐进式预览**

    * Render View 是场景视图的一个平齐标签；切换过去后需要先点一下 Render 按钮，然后出现进度条慢慢把图「打」出来：刚开始只有几个像素点、噪声很多，随着进度条往后推移，噪声越来越小——因为它在不断采样、计算每个像素点的颜色，采样数越来越多，渲染结果也就越来越准确。

    * 在 Render View 下预览一帧渲染效果，觉得已经很棒了，再去导出整个图片序列、最后做成视频。

* **批量导出与 Valid Frame Range**

    * > **易错点**：Valid Frame Range 默认是 Render Current Frame，只渲染当前帧——这样最后只会输出一张图片；要把它改成渲染一个范围：指定一个起始帧、一个终止帧，渲染区间内所有的帧。

    * 改好后点一下 Render to Disk，它就开始批量渲染：从指定的第一帧开始到最后一帧结束，并展示一个进度条；一些参数设置下它可能会比较慢——实测渲染整段视频花了三个多小时（三小时四十分钟），渲完的图片序列拼成视频就是最后的成片。

## Karma 渲染

### SOLARIS 工作流与场景导入

* **Karma 的特点**

    * 支持 CPU 和 GPU 混合渲染，能用 GPU 给渲染加速；但用它渲染走的不是 Mantra 那套流程，另有一套工作流。

* **切换到 SOLARIS**

    * 在整个窗口左上角的选项卡里有一个 build，把它切换成 SOLARIS；整个窗口布局都会变：下面多出一些功能区，但右上角的参数视图和右下角的网络视图还在。

    * 把网络视图切换到 stage 标签（刚才是 out）。

    * > **注意**：stage 是一个全新的环境，它不知道你刚才做过的所有操作；所以第一步是把之前场景里的东西全部导入进来——几何物体（水滴粒子和圆锥体）、环境光照、相机，一样都不能少。

* **SOP Import（场景导入）**

    * > **定义**：stage 标签下的场景导入模块；参数里有一项 objects，把 obj 里的所有东西都填到这里，用空格隔开就可以了。

    * 示例共导入四个东西：水（水滴粒子）、底下的圆锥体、环境光照，还有一个 camera 相机。

### 渲染设置与出图

* **插入 Karma 自动配对模块**

    * 插入 Karma 之后，它会自动生成一对已经连好的模块：第一个是 Karma Render Settings，负责 Karma 渲染的各项设置，它需要接收 SOP Import 的输入——相当于把导入的场景全都告诉了 Karma（有哪些光照、哪些相机、哪些物体）；另一个是 Karma 渲染模块，红色的那个叫 USD Render ROP。

* **Karma Render Settings 的参数**

    * 输出：和 Mantra 一样，在输出目录 output picture 下配置输出路径和文件名。

    * 相机：camera 这里要指定导入进来的 camera1，告诉它用哪个视角去渲染。

    * 分辨率：后面可以调图片的 resolution。

    * 渲染引擎：render engine 一定要调成 XPU 引擎。

    * > **易错点**：render engine 默认是 CPU 引擎，CPU 引擎用不到 GPU，速度还是会很慢——这一步最容易漏。

    * 采样：samples 就是采样的数量，再往下还有一些更多的图像处理和渲染参数。

* **出图**

    * 选中红色的 Karma settings 模块（USD Render ROP），下面有一个 Render to Disk 按钮，点一下它就会一帧一帧地渲染；渲染之前，记得把渲染范围调成想要的帧区间。

```text
（Build 视图）--切换-->（SOLARIS 视图, 网络视图切到 stage）

obj 里的场景: 水滴粒子 / 圆锥体 / 环境光 / camera1
        |
        v
[SOP Import]   objects 参数里用空格列出全部物体
        |
        v
[Karma Render Settings] --> [Karma (USD Render ROP)]
   输出路径 / camera1 / 分辨率
   Render Engine = XPU / 采样数
        |
        v
Render to Disk: 按帧区间逐帧出图
```

### 实时预览与 Mantra 差异

* **实时渲染预览**

    * Mantra 有一个单独的预览阶段，而 Karma 本身就是实时渲染：SOLARIS 界面右上角有两个视图标签，把左边那个调成 Karma XPU render 的 view，场景立刻就变成 Karma 渲染器渲染的结果。

    * 这个结果可以直接拖视角——不一定非得绑定在那个 camera 上，拖到哪儿，它就跟着视角实时重新渲染。

* **兼容性差异**

    * Karma 渲染的结果很可能跟 Mantra 渲染的不太一样：有些 Mantra 里能支持的东西，Karma 里不能支持，可能需要重新配置一下参数。

    * 材质应该还好，主要是光照——可能需要在 Karma 里重新配一遍；重新配也不麻烦，直接在 stage 标签下去拖这些模块就好。

    * 最终期待的效果：总体上水像水，圆锥体有点金属光泽、有点反光的效果就可以；有兴趣的话可以再去调一调参数，让它特别好看。

* **Mantra 与 Karma 对比**

| 对比点 | Mantra | Karma |
| :--- | :--- | :--- |
| 硬件支持 | 只支持 CPU | CPU 和 GPU 混合渲染 |
| 渲染入口 | 网络视图切到 out，插一个渲染节点 | 先切 SOLARIS，在 stage 网络里搭场景 |
| 预览方式 | 有单独的预览阶段 | 本身就是实时渲染，视角可随意拖 |
| 场景兼容 | — | 少数光照可能要重新配，材质基本没问题 |

## 体数据可视化基础

* **体数据**

    * > **定义**：就是一个三维的场。以速度场为例：流体是占据一定三维空间的，在这个定义域上会定义一个向量场——流体的速度场。

    * 这个场在自然界是连续的：定义域内处处有定义，每个点都会给一个速度的值。

* **体素（voxel）**

    * > **定义**：对应二维里的像素，指的就是三维网格中的一个格点。

    * 在计算机里，体数据往往要转化成体素，其实就是网格化：只存每个网格格点处的值，格点之间就用插值来算。

* **三种常用可视化方法**

    * 体渲染（示例所用的方法）、等值面提取、切片可视化。

* **跨领域应用**

    * 这项技术在图形学之外也用得很广，可视化领域有一个专门的课题，研究怎么把体数据可视化得更直观。

    * 典型例子：医学成像把人体内很精细的结构一览无余（如肺部，切片可视化）；一种类似皮肤一样的材料设计中，可视化它形变时的应变（strain）分布（等值面提取）。

* **ParaView 的定位**

    * 界面比 Houdini 简单许多：它不是那种拖模块的工作方式，其实就是一些文件，把这些文件整个混合到场景里；官网提供文档教程，想了解高级功能就点进去看。

## 涡量场与 VTI 数据准备

* **示例与标量化取舍**

    * 目标是做两个涡环进行碰撞的效果；要可视化的本来是流体的速度场，但速度场是一个三维的向量场——域里每一个点都对应一个三维向量，而一般来讲体数据可视化都是可视化一个标量场，只能牺牲一些信息：选择可视化流速场的涡量。

* **涡量（vorticity）**

    * > **定义**：通俗地讲，就是描述流体在某一个点处转得有多快的一个物理量；三维里涡量本身是一个向量，这里可视化的是涡量的模长——模长越大，代表流体在这一块转得越快；越小就代表转得越慢。

* **数据形态**

    * 涡量场是一个浮点的三维数组（NumPy 数组）：每一个维度对应网格的每一个维度，每一个值就是网格格点处的一个值。

    * 设整个定义域的坐标范围是 $x_{\min}\sim x_{\max}$、$y_{\min}\sim y_{\max}$、$z_{\min}\sim z_{\max}$，分辨率是 $X_N\times Y_N\times Z_N$，那么这个三维数组的形状就是 $X_N\times Y_N\times Z_N$。

* **NumPy 转 VTI**

    * ParaView 能接收并可视化的是 VTI 格式；转化用一段 Python 脚本，主要借助 Python 里的 VTK 包：先 `import vtk`，把数组转化成一个 VTK 格式的数据（vtk data），再用一个 writer 把它写到指定的 VTI 文件当中。

    * 如果真的要可视化某个三维体数据，去查一下 VTK 这些接口该怎么用；如果只是想实现同样的功能，直接复制这段代码就好了——只需要注意每一个参数的含义。

## ParaView 显示与播放

* **导入序列**

    * 把生成的一堆 VTI 文件直接拖拽进中间框框的范围里；要导入一个序列的话，就按顺序选中所有 VTI 文件一起拖进来——文件名最后带个星号（*）就表示它是一个文件组、一串序列。

    * 不想拖拽的话，也可以直接右键去打开文件，指定路径之后选择一系列文件，直接导入过来。

* **显示开关**

    * 导入之后，直接点左边那个眼睛的小图标——它默认是闭上的（隐藏），点一下它就会显示。

* **Representation 选 volume**

    * 刚显示的时候，因为是网格的数据，它其实只会显示出整个数据外面的一层包围盒，也就是一个长方体的棱；想显示出其中的内容，要把上面那个可视化方式的下拉条打开，选择 volume（体数据的可视化方式）——选完之后立刻变成体渲染的图像。

* **色标判读**

    * 右下角的色标：越偏红表示涡量越大，越偏蓝表示涡量越小；两个涡环越靠内部，颜色越偏红——也就是越靠中心转得越快。

* **视角操作**

    * 直接拖鼠标调整视角就好，和 Houdini 很像；这里没有所谓的 camera 概念——ParaView 默认就是拿当前的视角作为相机视角去渲染。

* **播放与轻量性**

    * 直接点播放的图标，它就能把导入的整个 VTI 序列一帧一帧地显示出来；如果导入的是一个连续的动画，它就会展现出涡环的动态。

    * 这个播放很快、比 Houdini 快，这是 ParaView 的一个好处；总体使用感觉是 ParaView 更轻量：直接导入进来、点播放，就可以很流畅地开始播放；而 Houdini 刚导入粒子的时候点播放，每一帧都会卡一下、看起来不流畅（当然也可能跟具体例子有关）。

## ParaView 渲染出片

* **加地平面**

    * 目的：想要阴影的效果——涡量越深的地方，阻挡光线阻挡得越厉害，从而在地上形成一个阴影；而形成阴影不能是个虚空，需要一个依托（把两个涡环理解为两团烟雾，需要一个依托才能打出它们的倒影；类比水滴有阴影，是因为底下有圆锥体，才能在圆锥体上映出倒影）。

    * 做法：加一个很大很大的平面；这个平面可以自己写一个 OBJ 文件——平面就是一个正方形，正方形由两个三角形组成，这两个三角形构成了一个 mesh，就是想要的平面。

* **开启光线追踪与阴影**

    * 位置：左下角 properties 标签下往下拉，最后有一个 ray tracing rendering 的部分。

    * enable ray tracing 开关默认是不勾选的——因为默认只是给你可视化一下，没有开启光线追踪的渲染，这是为了效率；想生成高质量的结果就把它勾上，就可以开始光追渲染，效果会提升很多。

    * 接着把下面的 shadows 也勾上，就会出现阴影投射的效果。

    * > **注意**：勾上这两项之后，ParaView 瞬间变慢，拖拽视角、播放序列都会变得一卡一卡；所以这个时候尽量不要去拖动中间视图里的东西，直接在右边继续添加光源。

* **添加光源**

    * ParaView 会默认给一个叫 light kit 的光源，这个勾选框默认是勾上的——把它取消掉，添加自己的光源就好。

    * 光源类型可以自己选：点光源还是平行光；这里选 directional，directional 的意思就是平行光——平行光的光束方向，就是从 light position 指向 focal point 的这样一个方向。

    * 光位与阴影：示例中坐标系原点在左下角、加上屏幕向里的方向，光源相当于是原点相对的位置——屏幕向外、并且在右上角这样一个方向，所以它打出的阴影正好在相应位置。

* **导出动画**

    * 直接 File → Save Animation，选定一个路径和文件名之后，会弹出一个保存选项；这里有一个 suffix format——跟 Houdini 一样，生成的也是一系列图片，从第 0 帧开始逐帧生成，帧与帧之间的命名靠给文件名后面加一个后缀来做：像 `%04d` 这样的格式，第 0 帧就是 .0000，第 1 帧是 .0001，然后 .0002，以此类推。

* **FFmpeg 合成视频**

    * FFmpeg 是命令行里的一个工具，直接敲个命令行，它就可以把相应的一系列图片串成视频，很方便。

```text
涡量场: 浮点三维数组, 形状 XN x YN x ZN
        |  Python + VTK: NumPy 数组 -> vtk data -> writer 写盘
        v
一系列 .vti 文件（第 0 帧、第 1 帧、……）
        |  按顺序全选拖进 ParaView（文件名带 * 即一组序列）
        v
Representation = Volume, 体渲染显示出两个涡环
        |  + 地平面 OBJ + Enable Ray Tracing / Shadows + 自建平行光
        v
Save Animation: %04d 后缀逐帧出图 --> FFmpeg 串成视频
```
