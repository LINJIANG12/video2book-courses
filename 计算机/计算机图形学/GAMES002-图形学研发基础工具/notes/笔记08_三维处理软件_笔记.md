# 三维处理软件

## 工具版图

### 三大板块

   * **几何处理（Geometry Processing）**

       * 对象是点云与三角网格；任务是点云的变换与过滤、网格的简化与编辑、处理结果的查看。

       * 代表工具：CloudCompare、MeshLab、Open3D。

   * **渲染（Rendering）**

       * 对象是已经成形的几何；任务是加上材质与光照，出图。

       * 代表工具：Blender、Houdini、KeyShot，以及集成渲染模块的 UE4、Unity。

   * **几何重建（3D Reconstruction）**

       * 对象是一组照片；任务是从照片反推出所拍对象或场景的三维几何。

       * 代表工具：COLMAP、ContextCapture、Metashape、Meshroom。

### 软件与库

   * **图形界面软件**

       * CloudCompare、MeshLab、Blender 的重心在界面，操作靠点按完成。

       * 优势在早期验证与手动编辑：方法对不对、结果能不能用，看一眼就有数。

   * **代码库**

       * Open3D 没有可交互界面，只有 API。

       * 优势在批量与集成：直接嵌进工程代码，对大量几何单元重复执行同一套处理。

   * **绑定形态**

       * PyMeshLab 是 MeshLab 的 Python 绑定，等于把软件变成库。

       * COLMAP、ContextCapture 两头都占：既有图形界面，又有 Python API。

   * **取舍**

       * 选工具时的纠结，本质上是在「界面好上手」与「代码能批量」之间做取舍。

       * 界面与代码不是互斥选项：先用界面验证、再换库批量，是常见的衔接方式。

## 点云与三角网格

   * **点云（Point Cloud）**

       * > **定义**：一堆带坐标的点，点与点之间没有连接关系。

       * 常见处理：变换、过滤（剔除异常点）、法向估计、分割。

   * **三角网格（Triangle Mesh）**

       * > **定义**：在点坐标之外，额外记录哪些点连成哪个面，面片通常为三角形。

       * 点云算法与网格算法不是一回事：一个只面对离散点，一个要维护点与面的连接关系。

       * 这也是处理完点云往往要换一个工具的原因。

       * 显示方式：顶点可单独显示，三角面片可用 wireframe 叠加，每个面怎么连一目了然。

   * **格式与材质**

       * 点云与网格结果常以 `.obj`、`.ply` 等格式交付。

       * 网格只提供连接关系，不含材质；Bunny 这类模型本身没有材质，材质要另行定义。

## CloudCompare

   * **CloudCompare**

       * > **定义**：开源的点云处理软件，主力是对三维点云做几何处理。

       * 能力边界：点云的变换与过滤在射程之内；也支持网格处理等额外功能，但重心始终在点云。

       * 开源且公开 C++ 源码：写 C++ 程序的人可以直接调用它的函数，不必被界面框死。

       * 界面：3D 查看区显示点云、坐标轴与比例尺；左侧和上方排布大量按钮，点云编辑与处理都从这里进入。

       * 渲染基于 OpenGL，底层调用 C++ 处理库（PCL）。

   * **插件机制**

       * 插件是通用扩展方式：既有标准插件，也支持自定义插件。

       * 现成插件覆盖法向估计、点云过滤（剔除异常点）与点云分割。

       * 具体按键的功能以官方主页说明为准。

---

## MeshLab

   * **MeshLab**

       * > **定义**：开源 C++ 的网格处理与可视化软件，点云与三角网格都能处理，重心落在网格上。

       * 与 CloudCompare 的分工：后者以点云处理与渲染为主，网格只是额外功能；MeshLab 更通用，点云与网格都管。

       * 算法覆盖：网格简化、凸包计算等，完整清单见官方文档。

       * 除图形界面外提供 Python API，可在代码里调用，不必在界面上手点。

   * **界面内编辑**

       * 网格可直接打开显示，例如 Stanford Bunny；顶点能单独显示，三角面片能以 wireframe 叠加。

       * 支持直接在界面里改三维数据：框选一片网格后剔除，或做其他变换。

       * 被选中的部分显示为红色三角面片，动过哪些面看得很清楚。

       * 价值：有些交互用纯代码很难表达——要删「看着多余的那一块」，先用代码描述「这一块」就得写一堆选择逻辑，界面上点两下即可完成。

## PyMeshLab

   * **PyMeshLab**

       * > **定义**：MeshLab 的 Python 绑定，用 pip 或 conda 安装后即可调用 MeshLab 的内置函数。

       * 典型调用：载入网格（load mesh）、计算凸包、保存当前网格，都是函数调用的形式。

       * 支持的 API 与每个 API 的作用，以 PyMeshLab 文档为准。

   * **过滤器脚本（Filter Script）**

       * 做法：先生成一个 MeshSet，在其上串一系列操作（例如对坐标做拉普拉斯平滑），最后用 `save_filter_script` 保存成本地文件。

       * 文件记录的是操作序列本身，不是处理结果。

       * 复刻方式：载入该文件，对新的输入网格执行同一串操作。

       * > **提示**：先在界面里验证方法与参数，验证通了把操作录成脚本，再拿去批量处理几何单元；这个「先手动、后脚本」的路子比纯软件和纯库都省事。

## Open3D

   * **Open3D**

       * > **定义**：C++ 编写、提供 Python 绑定的三维几何处理代码库，本身没有图形化交互界面。

       * 覆盖面比 MeshLab 更通用：点云处理、网格处理、射线求交等计算几何算法都在支持范围内。

       * 官方文档写得清楚，这是接手一个陌生库时最实际的门槛。

       * 可视化用法与软件不同：调用代码让代码开一个窗口，在窗口里看结果。

   * **示例组织**

       * 每个功能对应一个 `.py` 文件与一段示例代码，照着读、照着改。

       * 常翻的几类：相机、相机轨迹、点云与网格处理（`geometry` 模块）、点云与网格数据的读取与保存（`io` 模块）、常用可视化功能。

   * **与 MeshLab 的分工**

       * MeshLab 本质是软件，在 Python 代码里调它相对重；Open3D 是库，API 轻便，适合直接嵌进代码。

       * 验证阶段用 MeshLab：手动确认方法可行、结果可用；落地阶段换 Open3D：把几何处理逻辑整合进代码，批量跑。

       * 两类工具是先后关系而非替代关系。

```text
MeshLab（图形界面）
    │  手动验证：方法是否可行、结果是否可用
    ▼
Open3D（Python 代码）
    │  批量处理、整合进工程
    ▼
最终数据
```

## 渲染工具

### Blender

   * **Blender**

       * > **定义**：开源的渲染软件，脚本层用 Python，同时提供图形化界面与 Python API。

       * 定位工业级：几乎所有内容都能在 Blender 里渲出来；功能太多、系统太复杂，上手难度远高于偏轻量的 MeshLab。

       * 界面是一个复杂的系统，各种功能都支持。

       * 官方提供中文手册，官方教程也能一并找到。

   * **学习方式**

       * 官方教程之外，GitHub 上面向学术渲染的 BlenderToolbox 提供了丰富的示例脚本。

       * 知乎、YouTube、B 站上有许多博主做的教程，覆盖面比官方文档更广。

       * > **提示**：不要抱着从第一页读到最后一页的心态去学；按眼下要做的效果检索对应教程，缺什么补什么，是唯一划算的路径。

### 其他渲染方向

   * **Houdini**

       * 主要用于电影特效与游戏特效制作，门槛相对更高。

   * **KeyShot**

       * 重量级商业软件，注重真实感渲染，采用光线追踪算法。

   * **UE4 与 Unity**

       * 把渲染模块集成进来的综合引擎，不只是渲染器。

### 光栅化与光线追踪

   * **光栅化（Rasterization）**

       * > **定义**：把几何投影到屏幕上，逐片元着色，再靠深度测试定前后。

       * 特点是快；Blender 偏这条成像路线。

   * **光线追踪（Ray Tracing）**

       * > **定义**：沿着光线的传播路径求解成像。

       * 物理上更接近真实成像，真实感更好，代价也更高；KeyShot 走这条路线。

   * **网页端光追的边界**

       * 网页端计算能力有限，用 WebGL 做光追不实际。

       * Chrome 的 WebGPU 支持出现后，网页端光追将来或许可行，目前没有确定结论。

## 三维重建

   * **三维重建（3D Reconstruction）**

       * > **定义**：从一系列照片恢复出三维模型的算法。

       * 输入是一组围绕同一物体或场景拍摄的照片，输出是所拍对象的三维模型。

   * **模型来源**

       * CAD 手工建模与艺术家创作：从零构造几何。

       * 算法从真实世界恢复：又分雷达扫描与基于图像的重建两条路。

       * 重建工具专指基于图像的一支：拍一组照片喂给算法，算法自动生成所拍场景的三维模型。

### COLMAP

   * **COLMAP**

       * > **定义**：源自学术论文附带工具的开源重建软件，GitHub 上有 C++ 源码，依赖 CUDA 运行。

       * 形态：提供简单的图形化界面与 Python API，界面比 Blender 简洁得多。

       * 输出：物体的三维模型，以及所有照片对应的相机位姿。

       * 相机位姿在界面里以红色锥体表示。

       * 重建结果可导入 MeshLab 这类工具查看与渲染。

   * **三段处理链**

       * 位姿估计：确定每张图片拍摄时的相机姿态；不知道相机在哪、朝哪，就无法把照片上的像素对应回空间位置。

       * 稀疏重建：根据相机姿态估算三维物体所在位置，确认物体表面特征点的位置，输出稀疏点云。

       * 稠密重建：稀疏点云难以直接支撑高质量可视化，用泊松重建等方法把位姿与稀疏点云转成稠密点云或网格模型。

       * 前一步的输出就是后一步的输入，位姿是整条链的地基。

       * 稀疏与稠密是同一件事的两个尺度：先确认「东西在哪」，再补足「表面长什么样」。

```text
一组照片
    │
    ▼
位姿估计  ──►  每张照片的相机姿态
    │
    ▼
稀疏重建  ──►  稀疏点云（物体表面特征点的位置）
    │
    ▼
稠密重建（泊松重建等）
    │
    ▼
稠密点云 / 网格模型  ──►  导入 MeshLab 查看与渲染
```

### ContextCapture

   * **ContextCapture**

       * > **定义**：闭源商业付费的重建软件，面向工业级应用。

       * 擅长户外大场景，例如无人机航拍生成的结果；提供更专业的位姿估计与重建算法。

       * 流程与 COLMAP 相同：先确定相机位置，再做稀疏重建与稠密重建，最终得到网格模型。

       * 性能调优在两处：生成更准确的相机姿态；对最终网格做大量精细化处理，输出更精美。

       * 操作上感觉比较简单，不像 Blender 那样难上手，整体是一个比较自然的过程。

       * 官方提供中文用户手册，Python 调用在手册里也有说明。

       * 效果差异：同一组无人机实拍户外照片，COLMAP 有时只能得到很粗糙的模型，ContextCapture 能输出逼真度很高的精美模型。

   * **与 COLMAP 的分野**

       * 授权：COLMAP 开源且公开 C++ 源码；ContextCapture 闭源、商业付费。

       * 场景：COLMAP 围绕物体拍多张照片；ContextCapture 更擅长户外大场景与无人机航拍。

       * 质量：COLMAP 的模型有时较粗糙；ContextCapture 的相机姿态更准、网格更精细。

       * 共同点：流程都是定位姿、稀疏重建、稠密重建、出网格，且都支持图形界面与 Python API。

   * **其他重建工具**

       * Metashape 与 Meshroom 的知名度不及前两者，按自己的情况选择使用。

       * 重建工具在图形学里并不通用，同类工具还有很多。

## 工具选型

### 投入力度分级

   * CloudCompare、MeshLab 基本是为可视化服务的，下载下来自己试一遍，就有初步的使用了解。

   * Open3D、Blender 需要细致查看官方文档，甚至要在网上找教程或样例代码辅助学习。

   * COLMAP、ContextCapture 在图形学里并不通用：几何处理与渲染是通用的，重建只是特定领域才用得上。

### 判断维度

   * 是否开源：能不能读源码、能不能直接调它的函数、要不要付费。

   * 有没有图形化界面：早期验证与手动编辑要付出的成本。

   * 有没有 Python API：能不能嵌进代码做批量处理。

   * 软件本身的性能：同等任务下的处理速度与结果质量。

### 学习策略

   * 学习初期多尝试几个工具，先把工具之间的区别摸清楚。

   * 熟练之后选一个认为最好的往下深挖，成为某个工具的专家。

   * 专家化之后，后续同类问题可以举一反三、以不变应万变。

   * 三维处理工具远不止列出的这些；除几何处理、渲染、重建，还会遇到针对细分领域的专用工具。

## 资产交付

### 网格简化

   * 简化结果按面片数分两档交付：非常简化的版本控制在 100 到 1000 面。

   * 稍微精细的版本控制在 1000 到 10000 面。

   * 两档结果都以 `.obj`、`.ply` 等格式提交。

### 材质与渲染

   * Bunny 模型本身没有材质，只提供网格之间的连接关系。

   * 材质需要自己定义；多试几种材质与光照，对比渲染效果。

   * 渲染可由任意软件完成，Blender 与 KeyShot 都在可选范围。
