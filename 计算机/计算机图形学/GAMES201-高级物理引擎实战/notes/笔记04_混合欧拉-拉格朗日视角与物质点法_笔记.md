# 混合欧拉-拉格朗日视角与物质点法

## 两种模拟视角

   * **拉格朗日视角（Lagrangian view）**

       * > **定义**：观察者跟着材料一起移动，每时每刻问的是"我的位置是什么、我的速度是什么"，如同一条随波逐流的小船。

       * 通常用粒子（particle）作表示：SPH、position based dynamics 都是基于粒子的拉格朗日方法；粒子表示的最大好处是各种形状、各种材料都能表示。

       * 视角和表示方式是两回事：有限元（FEM）也是拉格朗日视角，但它用的是 mesh 而不是粒子。

   * **欧拉视角（Eulerian view）**

       * > **定义**：观察点（"传感器"）固定不动，每时每刻问的是"对于经过我这个位置的材料，它的速度是什么"，如同插在水里从不移动的桩子。

       * 一般用网格（grid）作表示：经典的烟雾模拟把速度、density、烟雾浓度等所有物理属性全部放在纯背景网格上，没有粒子。

   * 两种视角在图形学里都非常常用，纯拉格朗日与纯欧拉都是主流模拟方法。

## 评判方法优劣的标准

   * > **定义**：先定标准再谈哪个更好——"每个层面都好"的算法非常少见，有人这么说多半在忽悠；一般算法只在几个层面占优，要按具体情况选。

   * **守恒性**

       * 动量守恒是至少要实现的底线；再往上是角动量守恒、体积守恒（模拟不可压缩流体时希望体积守恒）、能量守恒（机械能别莫名其妙消失）。

       * 这些守恒量看似 trivial，真正做到非常不容易；角动量不守恒一般不是爆炸，而是慢慢消失，与能量耗散直接相关。

   * **性能**

       * 两个因素：并行性（parallelism，方法容易不容易并行）与局部性（locality，访存的 spatial / temporal 局部性好不好）。

       * 现代体系结构上浮点计算（flop）非常廉价，真正昂贵的是把数据从主内存移动到寄存器这一步（时钟周期与能量上都是）；谈性能必须结合体系结构。

   * **实现复杂度**

       * 算法太复杂就没人能正确实现出来——实现不出来当然就不守恒；复杂也意味着难优化，连擅长优化的人都可能因工作量太大不愿接手。

## 网格与粒子的互补性

   * **流体求解器的两个组件**

       * 平流（advection）：负责移动流体的场。

       * 投影（projection）：把速度场的散度分量投影掉，即 enforce 不可压缩性。

       * 两个组件喜欢的表示不一样——这正是混合方法的出发点。

   * **欧拉网格：投影的好手**

       * 离散化容易：均匀网格上五点泊松 stencil（中间 −4、上下左右各 1，取个负号反过来也行）很容易写出离散拉普拉斯算子。

       * 邻居查找容易：$(i, j)$ 的上下左右就是 $(i, j \pm 1)$，内存里均匀排布。

       * 预条件容易：很容易上几何多重网格（geometric multigrid）做 preconditioning，收敛非常快。

       * 平流是短板：semi-Lagrangian、MacCormack、BFECC 无论选哪个都改变不了数值耗散——图标转几圈自己变模糊，能量与几何细节丢失；流体显得过黏（too viscous），兔子形状的量搬运几圈就糊成一团球，准确性也不好。

   * **粒子：平流的好手**

       * 移动粒子只需 $\mathbf{x} \mathrel{+}= \Delta t\,\mathbf{v}$（或更高级格式），把物理量在空间中移动简单直接。

       * 天然守恒：粒子从头到尾不生不灭，用粒子 track 质量则质量自动守恒，动量也很容易守恒；网格移动后要做额外操作才保动量守恒。

       * 投影是短板：粒子在空间中分布不规则，"左边是哪个粒子"都定义不清，离散化 tricky；SPH 的 shape function（kernel function）为在粒子上离散化搞出好多变种；施加算子要找邻居，得靠 hash grid 等复杂数据结构——纯粒子方法里邻居查找及邻居上的操作就是瓶颈。

   * 混合方法的动机：网格擅长 projection 不擅长 advection，粒子擅长 advection 不擅长 projection——把两者长处 smart combine，各取其长、避免其短。

## 混合方法的通用框架

   * **地位分工**

       * 拉格朗日粒子是一等公民：大部分信息主要存在粒子上，是状态的最终持有者。

       * 欧拉网格是二等公民：附属表示，只用来计算中间结果。

       * 粒子远多于网格时，网格内存可忽略不计：流体模拟二维每个 cell 往往至少 4 个粒子、三维至少 8 个，粒子占的空间比网格多很多。

   * **通用循环**

```text
拉格朗日粒子（一等公民：存着几乎全部状态）
    │  P2G：particle to grid，把粒子数据撒（scatter）到网格
    ▼
欧拉网格（二等公民：只算中间结果）
    │  网格操作：pressure projection、边界条件……
    ▼
    │  G2P：grid to particle，把信息收（gather）回粒子
    ▼
粒子更新：移动粒子，更新形变梯度、体积等属性
```

       * 网格操作的内容：流体做 pressure projection 与边界条件；MPM 算柯西应力导致的内力。

       * 来回倒本身有代价：传输会造成信息损失、增大计算量——后续各种格式都是围绕这一点的改进。

   * > **提示**：scatter 指每个粒子把自己的贡献分配给周围 3×3 的窗口（网格节点）；gather 是反过来的收集。

## PIC 传输格式

   * **粒子网格法（particle-in-cell，PIC）**

       * > **定义**：最古老的混合欧拉-拉格朗日方法：P2G 把粒子物理量按权重撒到周围网格节点，网格操作完再按同样的权重收集回粒子。

       * 传输范围：二维下每个粒子把信息传给它周围 3×3 的 grid node；传输量最常见是速度，偶尔是温度或力（MPM 里就传力）。

       * 权重原则：粒子不平等对待邻居，节点离得越近 importance 越高；二维权重是 x、y 两个方向核函数值的乘积，$w_{ij} = w^x_i \cdot w^y_j$。

       * 核函数（kernel function，也叫插值函数）常用 B-spline 三档：linear 就是最简单的帐篷函数（tent function），实现只要取绝对值 fabs；quadratic 要算平方；cubic 要算立方。

       * 档位选择：linear 不够 smooth，有时导致模拟系统不稳定；quadratic 一般已足够 smooth，是用得最多的（尤其在 MPM 里）；FLIP、流体里常用 linear；cubic 相对少。

       * 网格约定：cell-centered grid——节点放在每个 cell 中心，位置必带 0.5dx 分量（如 $(2.5dx, 0.5dx)$）；粒子周围 3×3 范围左下角节点的坐标 = 粒子位置除以 dx 再减 0.5。

       * 每个节点存两种信息：权重 × 物理量（真正的物理量）与权重本身——后者是从"加权平均"里把权除掉的依据，不做归一化就破坏守恒。

       * 网格归一化（normalization）：只处理权重大于零的格点（权重为零的格点不在任何粒子触及范围内），物理量除以权重和。

       * G2P 与 P2G 一模一样：算同样的左下角节点与权重，把周围节点速度加权叠加回粒子。

       * 粒子更新：位置累加 $\Delta t$ 乘上一步的 v（这是显式欧拉；用新 v 也可以），再用新 v 更新粒子速度。

```python
# PIC 的 P2G / G2P 骨架（G2P 反向加权收集）
base = x_p / dx - 0.5                    # 物理坐标 → 网格坐标；减 0.5 对齐 cell-centered
wx, wy = b_spline_weights(x_p, base)     # x 方向 3 个、y 方向 3 个权重（向量操作）
for i in range(3):
    for j in range(3):
        w = wx[i] * wy[j]
        grid_q[base + (i, j)] += w * q_p # P2G 信息一：权重 × 物理量
        grid_w[base + (i, j)] += w       # P2G 信息二：只有权重本身
        # G2P：v_new += w * grid_v[base + (i, j)]
```

   * **PIC 流体模拟器**

       * 纯 PIC 没什么用（只是在移动粒子）；与基于网格的泊松求解器联合起来才成为流体模拟器。

```text
particle ──P2G：scatter 速度──▶ 网格速度场
    ├── grid normalization（除以权重和）
    ├── 在网格上解 pressure，把 pressure 的梯度 apply 到速度场
    ▼
无散网格速度场 ──G2P：gather──▶ particle
    └── 用无散速度场移动粒子（二阶/三阶/四阶格式皆可，高阶更准确）
```

       * 因为有 pressure projection，新速度场是无散的，目的在于保体积（不可压缩流体）。

       * 缺点实测：体积不太守恒（GPU 实现用 Jacobi 而非共轭梯度，迭代次数不够）；分辨率越低数值耗散越大，128×128 下像一团糖浆；涡量转着转着就没了——过于 dissipative，一般很少直接使用 PIC。

   * **耗散的根源：自由度压缩**

       * 二维 3×3 邻域有 9 个节点、每节点 x/y 两个速度分量，网格侧共 18 个自由度；粒子上只存速度两个分量，2 个自由度——18 → 2 的传输必然丢信息。

       * 平移恰好是那 2 个自由度能表达的模态，所以唯一保得住；旋转、拉伸（dilation）、剪切（shearing）这些更丰富的速度模式全被平均掉了。

       * 两条改进路线：多传信息（APIC 加局部仿射速度场、PolyPIC 加更多局部多项式速度场），或不传总量只传增量（FLIP）。

## APIC 传输格式

   * **仿射粒子网格法（Affine Particle-in-Cell，APIC）**

       * > **定义**：PIC 的变种（2016 年 SIGGRAPH），每个粒子额外维护一个矩阵 $\mathbf{C}$（二维 2×2、三维 3×3），记录粒子周围速度场的仿射（affine）部分——$\mathbf{v} = \mathbf{A}\mathbf{x} + \mathbf{b}$ 里随 x 变化的量记进 $\mathbf{C}$，不变的那项 $\mathbf{b}$ 就是粒子速度 $\mathbf{v}_p$；一般认为 $\mathbf{C}$ 就是一个速度梯度。

       * APIC 是典型 PIC 系格式的三步循环：P2G → 网格操作 → G2P。

       * P2G 求两个量：网格动量 $m_i\mathbf{v}_i$ 与网格质量 $m_i$——质量是把粒子质量加权 scatter 上去，动量是把粒子动量加权 scatter 上去；网格上动量除以质量就是速度。

       * 网格上最容易做的操作是 pressure projection，一般在这里 solve 一个 Poisson equation。

       * P2G 与 PIC 几乎一模一样，唯一变化是多了一个仿射速度场：$\mathbf{v}_{\text{affine}} = \mathbf{C}\,(\mathbf{x}_{\text{node}} - \mathbf{x}_p)$，其中节点位置减粒子位置。

       * > **易错点**：P2G 动量里每个粒子的贡献除了加权 $m_p\mathbf{C}_p$，还有 $m_p\mathbf{v}_p$ 一项，容易漏掉；APIC 里比较重要的恰恰是 $m_p\mathbf{C}_p$ 这一项。

       * G2P 除速度外还要收集 $\mathbf{C}$：把「grid node 的位置 − particle 的位置」做外积（outer product，列向量乘行向量得矩阵），乘一个系列系数后叠加——quadratic B-spline 下该系数对应 $4/\Delta x^2$。

       * P2G 与 G2P 都是角动量守恒的（推导复杂，有专门文章写）。

       * 实现：三行代码（甚至 2.5 行）搞定，数学复杂度与实现复杂度反差极大；整个算法二三十行可写完。

       * 位置更新 $\mathbf{x}_p \leftarrow \mathbf{x}_p + \Delta t\,\mathbf{v}_p$，是辛欧拉（symplectic Euler）。

   * **速度场模态（mode）**

       * 模态指速度场的空间 pattern：PIC 粒子上只有常量速度 $v_0, v_1$ 两个模态；APIC 用 $\mathbf{C}$ 补齐了拉伸与剪切四个模态。

| 模态 | 速度场长什么样 | 对应的运动 |
| :--- | :--- | :--- |
| $v_0,\ v_1$ | 全场恒定的常量速度 | 平移 |
| $C_{00}$ / $C_{11}$ | 速度的 x（y）分量随 x（y）增大而增大 | 沿 x（y）方向拉伸（dilation） |
| $C_{10}$ / $C_{01}$ | 速度的 y 分量随 x 增大 / x 分量随 y 增大 | 剪切（shear） |

       * 旋转可以认为是 dilation 和 shear 组合得到的东西——所以 PIC 连旋转都保不住，而 APIC 的 $\mathbf{C}$ 覆盖了这些模态。

   * **效果**

       * 平移、旋转、剪切、拉伸四种初始速度场在 APIC 下全部流畅保持，不再出现 PIC 那种转着转着能量耗散掉的情况。

       * 对比之下 PIC 的拉伸耗散极快：PIC 倾向于不断把速度场平均化（smooth），而拉伸场上每一点的速度都不一样，被逐渐抹平后就不动了。

## PolyPIC 与 FLIP

   * **PolyPIC**

       * 思路：网格侧 3×3 邻域共 18 个自由度，粒子上也带满 18 个自由度——constant、linear 之外再加 bilinear、quadratic 模态，网格传回粒子就是 18 对 18。

       * 若这 18 个自由度线性无关，传输可做到无损，能量保持更好；实现比 APIC 稍复杂。

       * 定位：2017 年 SIGGRAPH Asia 的工作，在 APIC 之上用更多模态把无损传输再推一步。

   * **FLIP**

       * > **定义**：不 gather 物理量本身，只 gather 物理量在网格操作上的增量（delta），把增量 gather 回来直接叠加到粒子旧值上。

       * 增量的内容：流体是 pressure projection 与边界条件；固体是算出来的内力与边界条件。

       * 历史：1986 年在 JCP 上提出，2005 年第一次引入图形学。

       * 实现与 PIC 差别小到惊人：gather 的是新速度场与旧速度场的差，叠加到粒子旧值上——信息多了一条 particle 到 particle 的直通路径，避开"全部信息都过一遍网格"的压缩。

```text
PIC ： particle ── P2G ──> grid（各种操作）── G2P ──> particle
        全部信息都过一遍网格：18 个自由度被压成 2 个

FLIP： particle ────────────────────────────(+Δ)──▶ particle
        粒子旧值不走网格，直通下一步
             └── P2G ──> grid（操作产生增量 Δ）── G2P（只取 Δ）──┘
```

       * > **易错点**：FLIP 本身只是一个传输格式（transfer scheme），不是一整个 solver；VFX 业界口语常拿 FLIP 指代「网格 pressure projection + FLIP 平流」那一整套管线，看资料要分清语境。 ⚠️

       * 缺点一：噪声大——纯 FLIP 下表面非常 noisy，粒子整个看起来是"炸"的。

       * 缺点二：实现要多 allocate 一个网格，存新的与旧的网格值才能算出 grid delta，各种 field 都要多存一份。

       * 取长补短：FLIP 0.99——0.99 乘 FLIP 的操作，加 0.01 乘 PIC 的操作；PIC 的阻尼非常大，只掺 0.01 就已足够压制噪声，同时保住 FLIP 的能量与活力。

       * 实现细节：速度更新完之后，用 PIC 的速度场还是 FLIP 的速度场去移动粒子有多种做法；用 PIC 速度场移动效果会稍好一点。

## 传输格式选型

| 方法 | 传输策略 | 突出优点 | 主要代价 |
| :--- | :--- | :--- | :--- |
| PIC | 全量 gather | 实现最直接、结果安静 | 阻尼过大，模式与能量迅速耗散 |
| APIC | 全量 + 局部仿射速度 | 改动约三行、角动量守恒、非常稳定、视觉效果好 | 粒子上多存一个 C |
| PolyPIC | 全量 + 高阶多项式模态 | 传输趋近无损、能量保持更好 | 实现更复杂 |
| FLIP | 只 gather 增量 | 保能量、有活力 | 噪声大，要多开网格存新旧值 |

   * 起步建议用 APIC：对存储非常友好（不需要备份速度场）、角动量守恒、非常 stable、视觉效果也比较好，站在各种方法的 sweet spot。

   * PIC 基本不用（过阻尼，很多模式很快就没了）；要精益求精可用 PolyPIC；FLIP 噪声大且要多开网格，实现稍复杂。

## 物质点法总览

   * **物质点法（MPM）**

       * > **定义**：一个 standalone 的混合欧拉-拉格朗日模拟 scheme，靠拉格朗日粒子和欧拉网格完成整个模拟过程，不需要外接别的 solver。

       * 与 PIC / APIC 的区别：那些 scheme 只有 advection，做投影得另配 multigrid、MGPCG 之类的求解器去解压强；MPM 自己就是完整方案。

       * 粒子上存的不只是速度：还有形变梯度（deformation gradient）、当前的体积，模拟别的材料还得存别的物理量。

       * 欧拉网格在 MPM 里的主要角色是 resolve collision 与 self collision——粒子和粒子碰撞的过程通过欧拉网格实现；网格更多时候不是用来做 pressure projection 的（虽然也可以做）。

   * **理论定位**

       * MPM 与 FEM 一样属于伽辽金方法（Galerkin method），方程通过弱形式（weak formulation）推导，是 weak-form consistent 的离散化方法。

       * MPM 没有 element（元素）概念，归类为无元素伽辽金（element-free Galerkin，EFG）。

       * MPM 的粒子对应 FEM 里的积分点（quadrature point），不是 FEM 的元素；粒子可以随模拟到处跑，所以能模拟大形变之类非常奇异的现象。

       * MPM 只有约 20 多年历史，比 FEM 年轻得多，高阶格式相对少见。

   * **历史与热度**

       * Sulsky 等人约 1996 年提出；2013 年首次引入图形学，最早用来模拟雪；《冰雪奇缘》雪场景是它发扬光大的标志性场景，当时模拟了一个星期。

       * 现在有了 GPU、MLS 这些技巧与太极加成，用 88 行代码在自己电脑上跑一个 MPM 基本没有难度；2020 年图形学至少有五篇 MPM 论文，其中很多是 GPU MPM。

   * **能力与优点**

       * 自动混合材料：流体、固体、关键的颗粒材料（granular materials，如沙子、米饭）可以同时模拟。

       * 自动处理碰撞：自体和自体的碰撞、不同材料之间的碰撞都能 handle。

       * 自动断裂（fracture）：物体拉得太长自动断裂；这不是数值上准确的断裂模拟，但很多时候够用，还可以与连续损伤力学（CDM）整合。

       * 擅长大形变：graphics / visual effects 里角色扭来扭去、耳朵拖得很长、中弹大变形等夸张效果非常有用。

   * **可研究方向**

       * 材料侧：雪、泡沫、沙子等各种材料模型；网格侧：sparse grid、OpenVDB、多个 grid 等数据结构；传输侧：PIC、APIC、PolyPIC、GIMP、移动最小二乘传输、用于模拟切割的 compatible 格式；再往外是 MPM 与刚体的耦合。

   * **早期流程**

       * 早期 MPM 的 simulation cycle 差不多十步：先有 state → P2G 到网格上 → 网格上估计粒子体积（这一步现已不做了）→ 网格上算受力、做各种更新 → 加边界条件 → 可能做隐式时间积分 → 更新回粒子循环。

   * **太极自带的递进示例**

       * 88 行版：最简单的单材料 MPM 流体求解器，用 APIC 传输，能较好保持流体的涡旋效果。

       * 99 行版：三种材料——一种液体、一种红色果冻（弹性物体）、白色的雪。

       * 128 行版：再加更多材料与用户界面——鼠标拖动操作粒子、按 R 重置、按 W/S/D 加不同方向的重力（默认无重力）。

## 符号约定

   * 标量不加粗：$m_i$ 是第 $i$ 个 grid node 的质量，$V_p^0$ 是第 $p$ 个 particle 在时间零的体积。

   * 向量与矩阵加粗：$\mathbf{v}_p$ 是粒子速度（向量），$\mathbf{C}_p$ 是粒子上的仿射矩阵。

   * 下标 $i$ 指代所有 grid node，下标 $p$ 指代 particle：$\mathbf{v}_i$ 是节点 $i$ 上的速度，$\mathbf{v}_p$ 是粒子 $p$ 的速度。

   * 上标表示时间：$\mathbf{x}_p^n$ 是粒子在 n 时刻的位置；欧拉网格节点从来不移动，给 $\mathbf{x}_i$ 标 n 没有太大意义。

## MLS-MPM 的两处核心改动

   * **移动最小二乘物质点法（Moving Least Squares MPM，MLS-MPM）**

       * > **定义**：整篇论文一句话——用 MLS shape function 在 MPM 里作为 basis function；SIGGRAPH 2018 提出（前置工作 APIC 2016 年才出现），比 2013 年经典 B-spline MPM 容易实现很多，可能快两倍以上；关键是很多量可以直接从 APIC 的 $\mathbf{C}$ 里拿到。

       * MLS-MPM 基本上就是 APIC 再加十几行代码加入 MPM 的部分；从 APIC 到 MPM 只改两处：一要做形变更新（根据局部速度梯度更新形变梯度 $\mathbf{F}$），二在网格动量里多出粒子的弹力项。

       * G2P 基本一模一样、没有任何改动；解弹性物体时不做不可压缩性的 projection，但有一个网格上的边界条件操作。

   * **形变梯度为什么会变**

       * 根因：材料局部速度场的梯度不是零。局部速度场恒定（梯度为零）时材料只作整体平移——把弹球上每一部分按恒定速度场移动，球不会发生任何形变。

       * $\nabla\mathbf{v}$ 是速度（三维向量）对位置（三维向量）求导，得出 3×3 矩阵；有的文献多写一个转置——符号从未统一，graphics 里 MPM 的文章一般不写转置。

       * 更新公式与 MLS-MPM 的替换：

$$\mathbf{F}_p \leftarrow \left(\mathbf{I} + \Delta t\, \nabla\mathbf{v}\right)\mathbf{F}_p \qquad\Rightarrow\qquad \mathbf{F}_p \leftarrow \left(\mathbf{I} + \Delta t\, \mathbf{C}_p\right)\mathbf{F}_p$$

       * 直接拿 APIC 的 $\mathbf{C}$ 作 $\nabla\mathbf{v}$ 的近似，省掉"用插值函数的导数求 $\nabla\mathbf{v}$"这条计算量大的路。

       * 形变更新挪进 P2G：更新 $\mathbf{F}$ 只需要用到 $\mathbf{C}$，而 $\mathbf{C}$ 存在粒子上、G2P 会算出它——挪完后 G2P 不需要读 $\mathbf{F}$ 数组，省 memory bandwidth；2013 年原版是在 G2P 之后做形变更新。

   * **弹力项从哪来：假装网格动了**

       * 量纲先行：更新的是节点动量，叠加上去的必须是冲量——节点上的力乘上 $\Delta t$。

       * 超弹性材料节点受力：$\mathbf{f}_i = -\dfrac{\partial U}{\partial \mathbf{x}_i}$，其中总弹性势能 $U = \sum_p V_p^0\,\psi(\mathbf{F}_p)$；$\psi$ 是能量密度（energy density），乘体积才是粒子的弹性势能，体积用初始体积 $V_p^0$——因为 $\psi$ 定义在没有形变的那个坐标系下。

       * 障碍与技巧：MPM 的网格永远不变形、节点位置从不变，怎么对 $\mathbf{x}_i$ 求导？——假设节点沿 $\mathbf{x}_i^\tau = \mathbf{x}_i + \tau\,\mathbf{v}_i$（前向欧拉，$\tau$ 趋近于零）虚动一下，对 $\mathbf{x}_i$ 的导数就换成对 $\tau$ 的导数再除以 $\tau$；配合 $\mathbf{F}_p^\tau = (\mathbf{I} + \tau\,\mathbf{C}_p)\mathbf{F}_p$，其中 $\mathbf{C}$ 的算法完全从 APIC 抄来。

       * 链式法则拆成三个都能算的因子：

```text
∂ψ/∂v_i  =    ∂ψ/∂F̂      ×      ∂F̂/∂C_p      ×      ∂C_p/∂v_i
              PK1 stress          含 F 的转置         4·w_i/Δx²（无转置）
```

       * 三个因子的身份：$\psi$ 对 $\mathbf{F}$ 求导就是第一 Piola-Kirchhoff 应力（PK1 stress）；$\partial\mathbf{F}^\tau / \partial\mathbf{C}_p$ 是矩阵左乘的导数，必须带 $\mathbf{F}$ 的转置（不是约定问题）；$\partial\mathbf{C}_p / \partial\mathbf{v}_i$ 无转置，等于 $4 w_i / \Delta x^2$。

       * 88 行代码里 $\Delta x^2$ 与那个 4 的来源就是这里——出自 APIC 的 C 收集公式。

   * **为什么又简单又快**

       * 原因一：用 $\mathbf{C}$ 近似 $\nabla\mathbf{v}$ 更新 $\mathbf{F}$，不求插值函数的梯度，省大量 FLOPs——MPM 的 P2G/G2P 是被浮点操作限制的（compute-bound），省浮点才有效；若是 memory-bound，降浮点就没有意义。

       * 原因二：形变更新从 G2P 挪到 P2G，G2P 完全不碰 $\mathbf{F}$，省 memory bandwidth——MPM 要尽量少与主存通信，把 memory bytes fetch 到寄存器非常昂贵。

       * 原因三：P2G 里动量的贡献可以被 factor 起来（乘法分配率）——因为都是 MLS 的，可以塞在一起，又省浮点运算。

       * 正确性口径：与 weak form consistent，是关于空间的一阶近似格式；论文里的正确性证明比较难，只想实现的话看 88 行 / 99 行代码就完全足够。

## 物质点法的实现骨架

   * **常量与初始化**

       * 8192 个粒子；最重要的是初始化太极并指定 GPU 后端（在 CUDA、OpenGL 或 Metal 上运行）；网格 128×128；指定时间步长 dt。

       * 每个粒子有自己的 volume 和 density，质量 = volume × density；E 扮演刚度的角色，在液体里就是体积模量（bulk modulus）。

   * **P2G：stress 并入 affine**

       * 与 APIC 唯一的区别是多了一个 stress：液体被压缩以后有一个抵抗压缩的过程，通过柯西应力（Cauchy stress）体现——推动每个粒子去推开周围的粒子。

       * MPM 的粒子之间从来不直接相互作用：作用是"先推开周围的网格"间接实现的。

       * 最小化改动的好处：stress 与 APIC 的 C 叠加到一起、统一用一个 affine 矩阵存储，scatter 一次完成（不需要先 scatter 力、再 scatter 速度分开做），计算量直接少一倍，而且更简单。

```python
# MLS-MPM 的 P2G：与 APIC 相比，只多了 stress 混进 affine
affine = C_p + stress_part               # stress 与 APIC 的 C 合并成同一个矩阵
for i in range(3):
    for j in range(3):
        w = wx[i] * wy[j]
        dpos = node_xy - x_p             # 节点位置 − 粒子位置
        grid_v[base + (i, j)] += w * (v_p + affine @ dpos)
        grid_m[base + (i, j)] += w
```

   * **归一化与最简边界**

       * 只对质量大于 0 的地方做 normalization——这一段与 PIC、APIC、PolyPIC 共用同一套骨架。

       * 最简边界条件：节点离边界太近，就把它速度的某个分量设成 0。

   * **G2P 与主循环**

       * G2P 与 APIC 相比唯一新增是更新 J（粒子的体积比），公式见流体模型一节。

       * 主程序：初始化粒子、创建窗口、不断调用 substep；每次做 MPM cycle 之前必须把网格上的速度和质量都设成 0——网格是每一步重建的中间结果，延续状态的一等公民始终是粒子。

       * 88 行版本实际只有 87 行，取"8"的口彩叫 88 行。

## 网格上的边界条件

   * **为什么必须在网格上施加**

       * MPM 是伽辽金方法：weak form 里边界条件是通过分部积分和散度定理得到的，而这些必然在网格上做；自由度也存在网格上——所以边界条件必须在网格上 enforce。

       * 施加对象：所有在边界内部（碰撞物体/墙内部）的节点。

   * **三种边界条件**

| 边界条件 | 粒子行为 | 施加方式 |
| :--- | :--- | :--- |
| sticky | 到那儿就粘住，完全不动 | 速度直接设为零 |
| slip | 不能穿墙（法向无速度），可贴着墙滑动 | 投影掉法向分量 |
| separate | 不能穿墙，且可以正常离开墙面 | 靠近时投影掉法向分量，脱离时不管 |

       * slip 公式：$\mathbf{v} \leftarrow \mathbf{v} - (\mathbf{n} \cdot \mathbf{v})\,\mathbf{n}$（$\mathbf{n}$ 是墙的 surface normal，点乘取出法向分量再减掉）；副作用：粒子想离开边界时有一定阻力——法向分量被统一清零了。

       * > **易错点**：slip 是「第二种边界条件」，不是「第二类边界条件」。

       * separate：看粒子速度方向——脱离 surface 就不做任何操作（和零取一个 minimum），靠近 surface 才把靠近的分量投影掉；不确定正统物理里用不用，graphics 里经常用。

   * **三个工程扩展**

       * 重力：$\mathbf{v}_i \leftarrow \mathbf{v}_i + \Delta t\,\mathbf{g}$，一行代码。

       * > **易错点**：重力必须放在边界条件之前做，否则材料可能会因为重力缓慢地滑向墙里面。 ⚠️

       * 移动边界（如水里有自己在动的球）：把 $\mathbf{v}_i$ 减去球移动的速度，在相对速度上做边界条件，做完再把它加上去——实际做了一个坐标系变换。

       * 摩擦：一般用库伦（Coulomb）模型；比 slip 的投影公式稍复杂，但一行代码也可以实现。

## 本构模型总览

   * **本构模型（constitutive model）**

       * > **定义**：材料的响应模型；在 MPM 里实现它有两个成分——一是怎么更新材料的形变（按公式更新形变梯度，有塑性形变时要特殊处理），二是算 stress（有了 stress，粒子才能对周围 grid node 施加正确的力、发生正确的物理作用）。

       * > **提示**：ad hoc 指临时的、不系统的解决方案——没有太多理论、没有太多证明，但实际使用情况下一般 work 得还不错。

   * **三大类材料**

| 材料类别 | 常用模型 | 备注 |
| :--- | :--- | :--- |
| 弹性体 | neo-Hookean、corotated | corotated 可能是图形学特色；neo-Hookean 在正经材料科学常用 |
| 流体 | 状态方程（equation of states，EOS） | MPM 一般不做不可压缩流体；硬要做可以在 MPM 里也加 projection |
| 弹塑性体 | 雪：box 屈服准则；沙：Cam-clay、Drucker-Prager 等 | MPM 的特色应用；最简单的是 2013 年雪论文里 clamp 单个奇异值的 ad hoc 方案 |

## 弹性体模型

   * 形变更新：把 $\mathbf{F}_p$ 左乘 $(\mathbf{I} + \Delta t\,\mathbf{C}_p)$，一步完成，非常简单。

   * stress 用 PK1：即 $\psi$ 对 $\mathbf{F}$ 求导；弹力公式里 PK1 要右乘一个 $\mathbf{F}^T$；PK1 与柯西应力基本只差一个 $1/J$ 因子——用 PK1 完全是因为前面公式里用的就是它，而且只要求导就能算，相对容易。

   * $\psi$ 里有 $\mu$、$\lambda$ 两个 Lamé 参数。

   * **neo-Hookean 与 corotated**

       * neo-Hookean 的好处：不需要对 $\mathbf{F}$ 做 decomposition（SVD）。

       * corotated 需要做 SVD：分解出旋转分量 $\mathbf{R}$（$\mathbf{F} = \mathbf{R}\mathbf{S}$ 的分解）；但实际情况中大家用 corotated 可能更多——可能因为最早的 MPM 论文用的就是 corotated，延续成传统；neo-Hookean 实测完全可以。

       * > **注意**：担心 neo-Hookean 里的 $\log J$ 会爆炸一般多余——$J$ 以乘法方式更新，只要不把它乘上一个负数，就不会出现 log 负数的情况，实际可以放心使用。

## 流体模型与 J 的数值陷阱

   * **状态方程（弱可压缩流体）**

       * 关键量是体积比（volume ratio）$J$ = 当前体积 ÷ 初始体积 = $\det(\mathbf{F}_p^n)$——矩阵的行列式就是它映射的体积变化比；$J < 1$ 即被压缩，流体会产生压强推开周围粒子/格点以恢复体积。

       * 压强公式（hack 但好用好写、颇受青睐）：$p = k\,(1 - J)$；stress 取 $\boldsymbol{\sigma} = -p\,\mathbf{I}$。

       * > **注意**：graphics 文献里的 $k$ 不是纯粹的体积模量（bulk modulus），而是插了一堆系数的 bulk modulus——调参时大家也不太 care，常忽略这个区别。

       * > **易错点**：MPM 流体示例是弱可压缩（weakly compressible）而非不可压缩——stress 由 $(J-1)$ 乘一坨系数得到：$J < 1$（被压缩）产生推开周围格点速度的力，$J > 1$（被拉开）产生拉近的力；本质是靠维护 J 保持体积的可压缩流体，只是看起来不太可压缩。 ⚠️

   * **灾难性消去（catastrophic cancellation）**

       * > **易错点**：二维行列式 $\det\mathbf{F} = f_{00}f_{11} - f_{01}f_{10}$ 里那个减号非常坏——元素很大时两个巨大的浮点数相减（如 10000 − 10001 = −1），得到的浮点数精度非常着急；3×3 行列式加减项更多，数值偏移更大，几乎不能用了。 ⚠️

       * 弹性体为什么没事：neo-Hookean、corotated 的能量函数盯着 $\mathbf{F}$ 的元素，形变想大也被能量函数照着，元素不会特别大。

       * 流体为什么会炸：流体的能量纯粹基于行列式，只罚行列式的变大变小——行列式可以正常，但矩阵元素可以涨得非常大，时间模拟长了就爆炸。

       * double precision（64 位浮点）不是系统解法：占用更多 FLOPs 与 memory bandwidth。

   * **系统解法：只存 J，不存 F**

       * 对 $\mathbf{F}$ 更新公式两边取行列式：矩阵乘积的行列式 = 行列式的乘积；$\Delta t$ 非常小，$\det(\mathbf{I} + \Delta t\,\mathbf{C})$ 就是 $1 + \Delta t\,\mathrm{tr}(\mathbf{C})$。

$$J_p \leftarrow \bigl(1 + \Delta t\,\mathrm{tr}(\mathbf{C}_p)\bigr)\,J_p$$

       * 为什么是 trace：$\mathbf{C}$ 里只有对角线上的项（$C_{00}$、$C_{11}$ 的 dilation 分量）对体积有贡献，非对角项全是 shear 分量、对体积没有贡献。

       * 效果：模拟流体时直接在每个粒子上维护标量 $J$，绕开 $\mathbf{F}$ 的数值不稳定。

   * **偷懒方案：把 μ 设成零**

       * 把流体当弹性体但令 $\mu = 0$、$\lambda \neq 0$：corotated 能量 $\mu \times$(奇异值项) $+ \dfrac{\lambda}{2}(J-1)^2$ 的前一项消失，只剩罚体积的后一项——不用额外实现一套流体模型。

       * 仍要算 $J = \det\mathbf{F}$、仍有数值不稳定问题：trick 是每次更新后把 $\mathbf{F}$ 重新设置成单位阵、只把对角线上的第一个元素设置成原来的 $J$——这样 $\mathbf{F}$ 就不会爆炸。

## 奇异值分解

   * **奇异值分解（singular value decomposition，SVD）**

       * > **定义**：任意实矩阵 $\mathbf{M}$（n×m）都存在分解 $\mathbf{M} = \mathbf{U}\,\boldsymbol{\Sigma}\,\mathbf{V}^T$——$\mathbf{U}$（n×n）与 $\mathbf{V}$（m×m）是正交阵，$\boldsymbol{\Sigma}$（n×m）是对角矩阵（非方阵也可以是对角阵），对角线上的值叫奇异值。

       * 几何直观：任意线性变换拆成三步——旋转（$\mathbf{V}^T$）→ 沿坐标轴缩放（$\boldsymbol{\Sigma}$）→ 旋转（$\mathbf{U}$）；正交阵只做旋转或反射、不改形状，真正的拉伸压缩都在中间的对角阵里。

```text
输入 ──Vᵀ(旋转)──▶ ──Σ(沿坐标轴 scale)──▶ ──U(旋转)──▶ 输出
```

       * 塑性为什么需要它：转一转一个球不会发生形变——塑性形变里不希望考虑旋转部分，SVD 把旋转完全剔除，只留中间真正发生形变的缩放部分。

       * 唯一性约定：正交阵也可以是反射（reflection）、行列式可以是 $-1$；这里约定 $\mathbf{U}$、$\mathbf{V}$ 的行列式为 1（只取旋转）；奇异值按绝对值降序，若有负奇异值只允许最小的那一个为负——不加约定 SVD 不唯一，太极的 `ti.svd` 就按这套约定返回。

       * 太极里 `ti.svd` 一次返回 $\mathbf{U}$、$\boldsymbol{\Sigma}$、$\mathbf{V}$ 三个矩阵；底层是模拟领域常用的 3×3 SVD 实现，性能非常高，CPU 与 GPU 代码都能生成。

## 弹塑性与雪的屈服准则

   * **弹性-塑性分解**

       * 把粒子上的形变梯度拆成两部分：弹性形变 + 塑性形变；弹性形变是比较小的一部分，塑性形变是比较大的一部分。

       * 塑性的机理：粒子把塑性形变梯度"忘了"——不再尝试恢复原来的样子；能量函数只定义在弹性形变上，塑性形变不被惩罚，能量只把弹性部分推向恢复原状。

   * **yield（屈服）与 clamping**

       * > **提示**：yield 中文叫「屈服」，非常传神——材料形变太大就弃疗，不再恢复原来的形状，即发生了塑性形变。

       * > **提示**：clamping 就是先取最大值、再取最小值，把一个值夹进上下界规定的区间里。

   * **box 屈服准则（2013 年雪论文，最简单最 ad hoc 的方案）**

```text
① 按原公式更新 F，得到临时的 F̂ = (I + Δt·C)·F
② 对 F̂ 做 SVD：F̂ = U·Σ̂·Vᵀ   （U、V 是旋转，Σ̂ 是真正发生拉伸的部分）
③ 对 Σ̂ 的每个奇异值 clamp：
      σ ← min(σ, 1 + θ_s)    再    σ ← max(σ, 1 − θ_c)
      （θ_s：拉伸上限 stretching；θ_c：压缩界限 compression）
④ 用 U·Σ·Vᵀ 重构新的弹性形变梯度；clamp 掉的分量移进塑性形变梯度
```

       * 拉伸不允许拉得太大：超过 $1 + \theta_s$ 就屈服不回复；压缩超过 $1 - \theta_c$ 同样屈服——超出界限的形变直接"忘了"，再也不恢复原状态。

       * 塑性形变梯度联系雪的硬化（hardening）：把雪团成一团硬度上升，把雪拉开硬度下降。

       * 评价：box 模型是暴力的 hack、最不物理，但 work 得还不错；MPM 社区后来有 Cam-clay 这些更正统的模型。

## 拉格朗日力与数值断裂

   * **拉格朗日力（Lagrangian forces）**

       * > **定义**：用 MPM 粒子表示 FEM 的顶点、用 FEM 的能量模型去模拟——此时粒子上不再需要存形变梯度，已经不是严格的 MPM 粒子；需要一张 triangular mesh。

       * 实现：用太极的 autodiff（自动微分）——粒子受力等于势能函数对位置的导数；自带示例代码非常短。

       * 对比 FEM 的优势：能比较好地处理自碰撞——FEM 很难处理自己和自己碰撞；自碰撞是 MPM 的一大优势（低分辨率下布与布之间的 gap 是粒子分辨率问题）。

       * 对比 MPM 的优势：避免数值断裂。

   * **数值断裂（numerical fracture）**

       * 机理：MPM 粒子之间要相互作用得通过网格，每个粒子只能接触周围 3×3 的网格节点；两个粒子的 3×3 网格完全不重合时，它们就不能相互作用、没有关联，于是断裂。

       * 触发条件：粒子采样密度不够高、粒子离得太远。

       * 何时可取：模拟雪时一切都是 hack，继续用数值断裂没有问题；模拟布拉得太长、橡皮筋拉得太长就断，则不好。

       * 更系统的断裂方案：连续损伤力学 + MPM（CDM-MPM），系统地解决了 MPM 的断裂问题。

## 太极实现要点

   * **field 取代 tensor**

       * 新版太极完全弃用 tensor 概念：既然大家都觉得 vector、matrix 也可以算 tensor，这个词歧义大，统一换成 field。

       * 全局变量分配：`ti.Vector.field`（每个 entry 是 vector）、`ti.Matrix.field`（每个 entry 是 matrix）、`ti.field`（标量场，替代弃用的 `ti.var`），如 `ti.field(ti.f32, shape=...)`。

       * 只有一个元素的 field：shape 设成空，访问时必须带下标 `field[None]`。

       * field 就是太极的全局变量：带 field 的是全局变量（所有 kernel 都能访问），局部定义的 `ti.Vector(...)` 是局部变量——区分全局与局部一目了然。

       * field 一语双关：数据库意义是「域」——一个 record 的各种属性（粒子的 mass、volume、velocity、position），对应一维数组；物理意义是「场」——每个点都有一个物理量（速度场、密度场、柯西应力场），对应高维数组；中文的两个翻译正好把两种含义分清。

   * **版本更新**

       * `pip install --upgrade taichi==0.6.22`；开课以来更新了 15 个版本（一周两次）；更新基本全部向前兼容，代码一般不会因升级跑不了。

   * **自动原子操作**

       * 太极里所有 `+=` 都是自动 atomic（原子累加）：P2G 里不同粒子同时累加同一个 grid node 不会有 data race；有的版本写 `ti.atomic_add` 是显式写法。

       * 想关掉自动 atomic：显式写成 `grid_v[node] = grid_v[node] + x`（`a = a + b` 的形式）就不是 atomic 了。
