# 物理仿真导论与拉格朗日视角

## 物理引擎：概念与应用

   * **物理引擎（Physics Engine）**

       * > **定义**：对物理系统（刚体动力学、软体动力学、流体动力学等）做近似模拟的计算机软件；一句话概括：在你的电脑里模拟这个世界。

       * 主要应用在计算机图形学，即游戏与电影；其他方向：工业软件（设计阶段先在电脑里做应力分析，免去"做实物—试—返工"的迭代成本）、电影视觉特效、VR/AR（虚拟世界物理规律与现实一致，交互才带来沉浸感）、机器人训练（无人驾驶先在虚拟街道开，不冒真实交通事故的风险）。

   * **可微模拟（Differentiable Simulation）**

       * > **定义**：与正向模拟相反的提问方式——正向模拟回答"给定初始状态，预测十秒后系统什么样"；可微模拟求"初始状态的扰动对结果的影响"，这个答案就是梯度，也是一切优化的起点。

       * 典型例子：求一组初始水面高度，使系统经过 512 个 time step 后恰好演化出"太极"图案。

   * **高性能模拟的关键词**

       * 离散化：把连续物理装进计算机，从程序员直觉理解各种离散化。

       * 有效率的求解器：写 fluid solver 很长一段时间都花在 linear solver 上，不同 solver 性能天壤之别，涉及预条件子（preconditioner）。

       * 生产力：用尽量短的代码实现高效模拟——代码行数虽是糟糕的 metric，却很难想到更好的替代。

       * 性能与硬件体系结构：大规模模拟一次要等一天，不快就没法迭代；不了解硬件就吃不满它，CPU 与 GPU 算吞吐量一般差一个数量级，用四个 GPU 可以模拟约 1 亿个 particle。

       * 复杂的数据结构、复杂的并行，以及模拟器的导数——求出 simulator 的导数就能做控制优化，例如带四块"肌肉"的软体机器人。

## 太极语言基础

### 安装与初始化

   * **太极（Taichi）**

       * > **定义**：嵌入在 Python 里的高性能领域特定语言（Domain Specific Language，DSL），语法与 Python 高度一致，专为计算机图形学应用设计。

       * 设计上注重生产力（图形学算法研究者写算法的效率）与可移植性（太极程序复制到另一台装了太极的机器基本就能跑，不像 OpenGL/CUDA 要装一堆依赖）。

       * 语言特性：面向对象、自动并行、mega-kernel、稀疏数据结构、可微编程支持。

       * 安装：`pip install taichi`（Python 3.6/3.7/3.8）；支持三大主流操作系统，CPU 与 GPU（CUDA、OpenGL、Apple Metal）均可运行；ARM 或 Python 3.9 以上须从源码 build；国内镜像源可能滞后于官方源，装完要确认版本。暂不支持多 GPU。

   * **ti.init 与 backend（后端）**

       * > **定义**：backend 指执行程序的硬件——程序跑在 CPU 上，CPU 就是 backend；`ti.init` 是任何太极操作之前必须先调用的初始化。

       * `arch` 参数选择后端（`ti.x64` / `ti.arm` / `ti.cuda` / `ti.opengl` / `ti.metal` 等），前提是系统支持；建议用 `ti.cpu` 或 `ti.gpu`——`ti.x64` 到 ARM 机器上跑不了，而 `ti.cpu`/`ti.gpu` 会自动检测硬件。

```text
ti.gpu 的自动探测：
    try CUDA ──失败──► try Metal ──失败──► try OpenGL ──失败──► 回落到 CPU
```

### 数据：类型与张量

   * **数据类型（Data Type）**

       * 整型 8/16/32/64 位（各分带符号与不带符号），浮点数 32/64 位；作者惯用带符号 32 位整型与 32 位浮点（f32）。

       * 暂不支持布尔类型，所有比较的返回值都用 32 位整型存储。

       * 并非所有后端支持所有类型（例如 OpenGL 可能不支持 64 位浮点/整型），各后端支持矩阵查文档。

       * 不支持 pointer：pointer 妨碍编译器优化，还容易触发 undefined behavior，程序会莫名其妙挂掉。

   * **张量（Tensor）**

       * > **定义**：太极里的张量就是高维数组（没有物理中协变/逆变的含义）；0 维张量是标量，1 维是向量，2 维是矩阵。

       * 张量的元素（element）本身可以是标量、向量或矩阵；访问元素永远用 `a[i, j, k]` 下标语法；张量暂不能套张量。

       * 定义方式：`ti.var(dt, shape)` 定义元素为标量的张量；`ti.Vector(3, dt, shape)` 第一个 3 是元素的维度、`shape` 才是张量形状；`ti.Matrix(2, 2, dt, shape)` 同理。`a = ti.var(dt=ti.f32, shape=(42, 63))` 是 42×63 个标量；`b = ti.Vector(3, dt=ti.f32, shape=4)` 是 4 个 3 维向量组成的张量；`c = ti.Matrix(2, 2, dt=ti.f32, shape=(3, 5))` 是 3×5 个 2×2 矩阵；`loss = ti.var(dt=ti.f32, shape=())` 是只有一个元素的 0-D 张量。

       * 0-D 张量没有下标，访问写作 `loss[None] = 3.0`；给向量元素可一次赋一个 list（`b[0] = [1, 2, 3]`）；直接打印一个向量（`print(b[0])`）当时暂不支持。

       * > **易错点** ⚠️：写 `loss = 3` 不是赋值给张量，而是真的把 loss 变成整数 3、它不再是一个张量——这是 Python 语法的限制。

       * > **易错点**：数学上矩阵有时被认为是某种张量，但太极严格区分 tensor 与 matrix，混着理解后面会非常 confused。

### kernel 与 function

   * **kernel（Taichi 的计算函数）**

       * > **定义**：太极的 kernel 就是"用来计算的那个函数"：内部语言与 Python 高度相似，但会被 JIT 即时编译，摆脱 Python 运行慢的问题。

       * kernel 内语言静态类型、词法作用域（scope 以 block 为单位，比 Python 以 function 为单位更紧）、自动并行、某些情况下可微分。

       * 用 `@ti.kernel` 装饰让编译器识别；传参必须写参数类型，有返回值必须写返回值类型 hint（如 `def calculate() -> ti.i32`）。

       * mega-kernel：与深度学习框架里 composability 弱、只能做两个张量加减乘的 kernel 不同，Taichi 的一个 kernel 可容纳任意复杂的计算——计算多、访存相对少，arithmetic intensity 更高。

   * **function（ti.func）**

       * > **定义**：`@ti.func` 修饰的设备端函数：不能被 Python 直接调用，供 kernel 与其他 function 调用。

       * 调用链是一条单向链：`Python → @ti.kernel → @ti.func → @ti.func`；kernel 不能调 kernel。

       * 对照 CUDA：kernel 约等于 global function，function 约等于 device function——但一个 ti.kernel 可能被拆成多个 CUDA global kernel，中间有抽象层；function 会被强行 inline（实现暂简陋，多数情况够用）。

       * 太极暂不支持递归；一个 function 里最多只能有一个 return statement。

## 太极的语法与运算

### 与 Python 一致的语法

   * **常用数学函数**

       * 支持 `sin`、`cos`、`arcsin`、`arctan`、`atan2`、`floor`、`ceil`。

       * > **提示**：`atan2` 的参数顺序是 y 在前、x 在后，写 `atan2(y, x)`——数学函数里最容易踩的坑。

       * `ti.random` 的返回范围由数据类型决定：int32 给 0~2147483647 的随机整数，uint16 给 0~65535，float32 给 0~1 的随机浮点数。

       * `abs` 是 Python 关键字，直接用、不加 `ti.` 前缀；`int`/`float` 做类型转换；`max`/`min` 支持任意多个参数；幂运算写 `x ** y`。

   * **除法与比较**

       * 太极沿用 Python 3 的规矩：`a / b` 永远返回浮点数（不像 C/C++ 依操作数类型决定是否取整）；要整数商就用整除 `a // b`。

       * 支持链式比较（chained comparison），极端如 `a < b <= c != d` 都合法。

### 小矩阵与大张量

   * **matrix 与 vector**

       * `ti.matrix` 只装很小的数组（3×3、4×4、1×3、3×1 这一档）；要 10×10 就该考虑 tensor——太极对小数组运算非常快，大数组则很慢。

       * vector 本质上就是一列的矩阵（列向量），与 matrix 没有本质区别。

   * **乘法与常用矩阵运算**

       * > **易错点** ⚠️：`*` 是逐元素（element-wise）乘，`@` 才是矩阵乘法——两个不同的运算符，不自己动手试很容易写出 bug。

       * 常用运算：`transpose`（转置）、`inverse`（逆）、`trace`（迹，对角线元素之和）、`determinant`（行列式）、`normalize`（只对列向量，除以自身模长）、`a.norm`（向量的 2-范数即长度）、`a.cast`（整批元素类型转换）、极分解（polar decomposition）、奇异值分解（SVD）——这些运算全部不是 in-place，都返回新对象而不修改原矩阵。

       * 所有标量运算符都可以直接作用在矩阵上做逐元素运算，例如 `ti.sign(a)` 得到逐元素符号矩阵。

## 并行编程模型

### 两种 for 循环

   * **range-for（范围循环）**

       * > **定义**：与 Python `for i in range(n)` 行为基本一致的循环；太极里**最外层**的 range-for 会被自动并行。

       * 内层循环不并行，在每个外层线程里串行执行；"最外层"指最外层的 scope——for 外面再套一个 if，它就被视为串行。

       * `ti.ndrange` 是多维 range：`for i, j, k in ti.ndrange((3, 8), (1, 6), (0, 9))` 表示 i∈[3,8)、j∈[1,6)、k∈[0,9)，末端点都取不到；三维的它同样自动并行。

   * **struct-for（结构循环）**

       * > **定义**：`for i, j in pixels`——并行遍历张量里的所有下标；做任何稀疏计算基本全靠它。

       * 稠密张量的所有下标都是 active 的；稀疏张量则只遍历其中 active 的部分。

### 原子操作（Atomic Operation）

   * **原子操作**

       * > **定义**：太极里 augmented assignment（`+=` 这类复合赋值）自动就是原子操作；并行修改全局变量就靠它。

       * for 里出现前后依赖（如把累加求和放到最外层）也不用手改——编译器在后台做了非常繁琐的变换自动处理。

   * **并行求和的三种写法**

```python
total[None] += x[i]                    # 方式一：+= 自动原子，最简洁
ti.atomic_add(total[None], x[i])       # 方式二：显式原子，返回加之前的旧值
total[None] = total[None] + x[i]       # 方式三：错误！非原子，有 data race
```

       * `ti.atomic_add` 是 read-modify-write：返回加之前 `total[None]` 的旧值，可控性更强但不如方式一简洁。

       * 方式三要先把数读进来、加完再写回去，期间别的线程可能已做完同样一套，结果就错了——非原子就会 data race。

       * > **易错点**：访问张量永远要带方括号；0 维张量也必须写 `total[None]`，不能裸写 `total`。

### Taichi scope 与程序阶段

   * **Taichi scope 与 Python scope**

       * > **定义**：被 `@ti.kernel` 与 `@ti.func` 修饰的函数体叫 Taichi scope；不在 Taichi scope 里的代码都是 Python scope。

       * Taichi scope 的代码由太极编译器编译、跑在并行设备上；Python scope 由 Python 解释器执行，可以随意调 pytorch 等库、把结果喂给太极（太极有 PyTorch 接口，`to_torch`/`from_torch` 换数据）。

       * Taichi scope 里 print 一个 vector 或 matrix 会把整个打印出来；但因为是并行设备上的 print，仅同一 thread 内部的顺序有保证，thread 之间的先后没有保证。

   * **程序的三个阶段**

       * 初始化（`ti.init`）→ 张量分配（只有这个阶段能用 `ti.var` / `ti.Vector` / `ti.Matrix` 定义张量）→ 计算。

       * 进入计算阶段的时机：第一次 launch 一个 kernel，或在 Python scope 里访问张量；一旦进入就不能再分配新张量；`ti.reset()` 可全部砍掉重来（一般用不到，程序结束自动重来）。

       * 端到端最小程序骨架（一个 30 行的 Julia 分形渲染器）：`ti.init` → 定义 640×320 的 f32 张量 pixels → `@ti.func`（用二维 vector 表示复数的 complex_square）→ `@ti.kernel`（struct-for 遍历像素并行渲染）→ `ti.GUI` 主循环（paint → set_image → show）。

```text
初始化(ti.init) ──► 张量分配阶段 ────────────────► 计算阶段
                    只有这里能定义张量：
                    ti.var / ti.vector / ti.matrix

                    进入计算阶段的时机：
                    · 第一次 launch 一个 kernel
                    · 在 Python scope 里访问 tensor

                    进入后不能再分配新的张量
                    （想全部砍掉重来：ti.reset()）
```

## 调试与工具链

   * **调试（Debug）**

       * 基础手段：print，或把结果写进张量、回到 Python 里打印。

       * `ti.init(debug=True)` 开启额外检查——典型抓法：kernel 里 `a[i] = b[i + 1]`，i=9 时越界访问 `b[10]`，debug 模式直接暴露。

       * 非 debug 模式不查越界是性能考量：每次张量访问都检查会让程序慢成狗；debug 时慢一点无所谓。

   * **示例与输出工具**

       * `ti example` 列出所有可运行示例；没有 `ti` 命令时用 `python3 -m taichi` 等价替代；`ti example 名字 -p` 打印源码、`-P` 语法高亮打印（需装 rich）、`-s` 把 demo 存到当前目录。

       * 入门示例：`mpm128` 是 128 行、可交互（鼠标加引力）的 MPM；waterwave 约 100 行，是有限差分时间推进（finite difference time marching）的水波 solver。

       * 导出动画：先用 `ti.GUI.show()`（带文件名）或 `imageio.imwrite` 把帧写到磁盘，再 `ti video` 合成 MP4（可指定 24/60 帧率），再转 GIF；都依赖 ffmpeg——Linux/Mac 大概率自带，Windows 要手动装。

       * 环境杂项：Python 自带 IDLE 跑太极有问题，换 ipython 或 Jupyter Notebook（Jupyter 的 print 会打到启动 server 的终端而非页面）；代码风格交给 `yapf -i a.py` 自动格式化；编译慢可关高级优化 `ti.core.toggle_advanced_optimization(False)`。

## 拉格朗日视角与欧拉视角

   * **拉格朗日视角（Lagrangian View）**

       * > **定义**：模拟介质时想象往介质里塞满随波逐流的传感器——节点跟着材料一起移动，每个节点像一个 sensor，不断检测自己的位置和速度；口诀"拉格朗日方法，随波逐流"。

       * 温度计比喻：温度计跟着水一起移动，就是拉格朗日式温度计；插在水里一点也不动，就是欧拉式温度计。

       * 通常配粒子（也有三角形网格、规则网格等形态）；典型例子：基于 position based dynamics（PBD，基于位置的动力学）的绳索/布料模拟、粒子模拟水。

   * **欧拉视角（Eulerian View）**

       * > **定义**：传感器固定不动，像打在水里的木桩，检测"穿过该点的材料速度"。

       * 通常配背景网格；典型例子：烟雾模拟——背景网格每个点记录穿过该点的流体速度。

       * > **易错点**：欧拉网格点不存位置——用 $i, j, k$ 下标乘网格间距 $\Delta x$ 就能算出来；拉格朗日粒子随介质不断移动，必须在粒子上额外记一个位置。"存不存位置"是两种视角的直观差别。

| 对比项 | 拉格朗日视角 | 欧拉视角 |
| :--- | :--- | :--- |
| 传感器像什么 | 随波逐流的小纸船 | 打在水里不动的木桩 |
| 检测什么 | 自己的位置和速度 | 穿过该点的材料速度 |
| 常用表示 | 粒子（也可用三角网格、规则网格） | 背景网格 |
| 位置存不存 | 粒子上额外记一个位置 | 不记，由下标算出 |

## 弹簧质点系统

   * **弹簧质点系统（Mass-Spring System）**

       * > **定义**：用很多弹簧把质点两两连接的最简单力学模型；弹簧怎么连接，就决定被模拟对象（布料、头发、弹性材料）的性质。

       * 应用面很广：布料、头发、各种弹性材料；游戏里同样常见，如《粘粘世界》——用弹簧质点搭桥，搭得越高下方弹簧受力越大，保持平衡并不容易。

   * **胡克定律（Hooke's Law）**

       * > **定义**：质点 $i$ 受到来自相连质点 $j$ 的弹簧力 $f_{ij} = k \left( \lVert x_i - x_j \rVert - l_0 \right) \dfrac{x_j - x_i}{\lVert x_i - x_j \rVert}$，$k$ 是弹簧 stiffness，$l_0$ 是静止长度。

       * 标量部分是"当前距离减静止长度"：为正（拉长）就把 $i$ 往 $j$ 方向拉，为负（压缩）就把 $i$ 往外推——弹簧总想把两端拉回静止长度。

       * 质点总受力 = 所有相邻弹簧力之和，再加重力 $mg$；配合牛顿第二定律得 $\dot v = f/m$、$\dot x = v$。仿真惯用"质量倒数乘力"——乘法比除法廉价，质量倒数提前算好存着。

   * **stiffness（刚度）与 damping（阻尼）的手感**

       * stiffness 可类比杨氏模量（Young's modulus），决定弹簧多硬：调大则材料坚如磐石，但显式时间积分可能当场爆炸；调小则整个系统"蔫了"、连重力都撑不起；先调软再调硬，形状可能卡在一起回不去。

       * damping 决定运动黏滞程度：调小运动灵活、系统像果冻一样晃个不停；调大显得黏滞（演示程序取 20）——很多游戏故意把阻尼调大，免得物体一直摆。

       * > **注意**：直接在速度上做指数衰减的"粗暴阻尼"会把整体平移运动也拖住；更常见的做法是把阻尼加在弹簧上。

## 时间积分

   * **离散化与 Δt**

       * 连续的常微分方程要装进计算机：时间只能离散，取一个较小的时间步长 $\Delta t$（如 $10^{-3}$、$10^{-4}$，按物理系统参数定）；$\Delta t$ 越大模拟同样时长越快、一般越大越好，但大了会带来不稳定。

   * **显式积分器（Explicit Integrator）**

       * > **定义**：未来状态只依赖过去状态的时间积分器——整个程序就是一个从过去推向未来的递推，非常好写，但容易爆炸。

       * forward Euler（前向欧拉）：$v_{t+1} = v_t + \Delta t\, a_t$，$x_{t+1} = x_t + \Delta t\, v_t$——用 $t$ 时刻的速度更新位置，用得较少。

       * semi-implicit Euler（半隐式欧拉，又叫 symplectic Euler 辛欧拉）：$v_{t+1} = v_t + \Delta t\, a_t$，$x_{t+1} = x_t + \Delta t\, v_{t+1}$——与 forward Euler 唯一的区别是位置更新用 $t+1$ 时刻的速度；这个看似极小的差别常带来本质的准确性提升，还带守恒性质（在哈密顿系统里做的理论分析）；更高阶的显式格式还有 RK2/RK3/RK4，数值精度更高。

       * 稳定性红线：$\Delta t \le \sqrt{\dfrac{m}{k}}$——质量越大允许步长越大，刚度越大允许步长越小，所以显式方法不适合特别硬的材料。

       * 直觉来源：弹簧振动角频率 $\omega = \sqrt{k/m}$，$\Delta t \le \sqrt{m/k}$ 正是它的倒数（差一个常数）——若一个 time step 内系统本该震荡一个周期却没捕捉到，往往就出问题；严格结论可用矩阵方法做数值稳定性分析。

       * 量级感受：$m=1$、$\Delta t=10^{-3}$ 时允许的 $k$ 约 $10^6$；stiffness 从 1 万一路调到 50 万已越来越硬，60 万接近临界、进入"偶尔才稳"的状态；这个临界并非非黑即白——公式里的 $k$、$m$ 本就是代表性近似值，靠近临界时只在特定配置下出事。

       * > **易错点** ⚠️：semi-implicit Euler 名字里带 implicit，实为显式格式；"semi-implicit"是个被滥用（abuse）的词，各种东西都能这么叫。

   * **substep（子步）**

       * > **定义**：模拟 time step 通常远小于展示帧间隔（游戏 60 FPS 即 1/60 秒、电影 24 FPS 即 1/24 秒），一帧要拆成若干 substep 往前推，每个 substep 用 semi-implicit Euler 走三步。

```text
对每个质点 i：
  阻尼：对 v_i 做一次指数衰减
  求合力：重力 m*g
          再遍历其余质点 j（rest_len 为 0 表示两点间没有弹簧，
          非 0 表示有弹簧），按胡克定律累加弹簧力
  用合力更新 v_i                     <- 半隐式欧拉第一步
  与地面碰撞：发现有下穿地面的趋向，就把 v_i 的 y 分量清零
  把 v_i 累加到位置上，得到新的 x_i   <- 半隐式欧拉第二步
```

       * 碰撞夹在"更新速度之后、更新位置之前"是有讲究的：不这样处理，速度 y 分量仍为负，粒子会陷进地底；发现下穿趋向就立刻把 y 分量清零。

       * 实现代价：对每个质点都要枚举其余所有质点找弹簧（rest_len 为 0 表示无弹簧），整个 kernel 是 $n^2$ 重循环，约 20 行代码。

       * 碰撞是边界条件的一种；完整边界条件处理起来 nasty，此处的 demo 只做碰撞这一种。

   * **隐式积分器（Implicit Integrator）**

       * > **定义**：未来不只依赖过去、还依赖未来——未知数依赖未知数，像鸡生蛋蛋生鸡，因此每步要解一个（线性）系统；典型如 backward Euler 与中点法。

       * 优点：每一步能容忍的 time step 更大；缺点有三个：难实现（难以做向量化、GPU 共享内存等底层优化）、每步更贵（步长收益与单步开销互相打架，要看谁胜出）、可能带来额外的数值阻尼（numerical damping）甚至 locking——有限元模拟一件衣服时，太硬的衣服会僵得像石头。

       * 弹簧质点系统的 backward Euler 三公式：$x_{t+1} = x_t + \Delta t\, v_{t+1}$；$v_{t+1} = v_t + \Delta t\, m^{-1} f(x_{t+1})$；把第一式代入第二式消元得 $v_{t+1} = v_t + \Delta t\, m^{-1} f(x_t + \Delta t\, v_{t+1})$。

       * $m^{-1}$ 是质量矩阵（$f=ma$ 即 $a=m^{-1}f$ 的矩阵版）；$n$ 个三维粒子的状态向量长 $3n$，二维则是 $2n$。第三式里力函数的参数藏着未知数 $v_{t+1}$，方程是非线性的。

## 隐式积分的线性化与求解

   * **线性化（Linearization）**

       * > **定义**：把非线性力函数在当前状态 $x_t$ 处做一阶泰勒展开 $f(x_t) + \left.\dfrac{\partial f}{\partial x}\right|_{x_t} \Delta t\, v_{t+1}$，让隐式格式的方程组变成线性方程组；$\partial f/\partial x$ 是雅可比矩阵（Jacobian），作用在向量上就是线性算子。

       * 整理出的线性系统：$\left(I - \Delta t^2\, M^{-1} \left.\dfrac{\partial f}{\partial x}\right|_{x_t}\right) v_{t+1} = v_t + \Delta t\, M^{-1} f(x_t)$——系数矩阵与右端项在当前时刻都已知，解出下一时刻速度 $v_{t+1}$。

   * **一个 β 统一显式与隐式**

       * 把力函数参数写成 $x_t + \beta\, \Delta t\, v_{t+1}$：$\beta = 0$ 时左边整项退化成单位矩阵，得到显式积分器；$\beta = 1/2$ 是中点法（midpoint method），某些情况数值精度更好；$\beta = 1$ 就是隐式欧拉（backward Euler）。

   * **Jacobi 迭代（Jacobi Iteration）**

       * > **定义**：最朴素的线性系统迭代法——每轮把每个未知数换成一个"只看本行方程恰好被满足"的新值。

       * 局部更新的代价：修好这一行、下一行可能挂了，要迭代很多轮才收敛；且并非总收敛——对矩阵谱半径有要求；收敛速度比共轭梯度慢。

       * 常伴指标：残差 $residual = b - Ax$，看它的 L2 范数是否随迭代变小。

       * 练习路径：把质量弹簧 demo 与 Jacobi demo 拼起来即可得到隐式质量弹簧系统——先线性化组装线性系统，再用 Jacobi kernel 解出 $v_{t+1}$ 后更新位置；难点在组装雅可比 $\partial f/\partial x$。

   * **解法谱系与为什么不求逆**

       * 同族方法：Gauss-Seidel 迭代、共轭梯度（Conjugate Gradient）及其众多变种与预条件子——对称正定系统直接用共轭梯度，不对称或对称不正定各有变种对付；统称 Krylov 子空间求解器。

       * > **注意**：不要直接写 $v_{t+1} = A^{-1}b$——求逆昂贵，且 $A$ 是稀疏矩阵时其逆很可能是稠密的，大矩阵的逆根本存不下；也可用直接解法（direct solver）如 Pardiso，迭代法则胜在容易在太极里实现。

       * 规模上去之后（成千上万弹簧/质点）：要用稀疏矩阵、共轭梯度加预条件，还要在物理模型层面做精度与速度的取舍（如 position based dynamics，PBD）；另有名文《Fast Simulation of Mass-Spring Systems》用不同 formulation 求解更快，可作扩展阅读。

## SPH 粒子流体

### SPH 的基本思想

   * **光滑粒子流体动力学（Smoothed Particle Hydrodynamics，SPH）**

       * > **定义**：拉格朗日视角解流体力学的方法——用一坨粒子各带物理量，再用核函数（kernel）加权近似连续场：$A(x) \approx \sum_j A_j\, W(x - x_j, h)$。

       * 核函数中间大、两边小：靠近 $x$ 的粒子贡献多，距离超过 support（半径 $h$）的粒子贡献为零；整体做的是类似 smoothing 的操作。$A$ 可以是速度、density、temperature 等几乎任意随空间变化的量——但求导数是完全不同的另一套故事。

       * 直观理解：每个粒子是一小包水（严格来讲并不是，但入门这么理解没问题）；SPH 起源于天体物理。

       * 朴素实现的每个时间步要对每个粒子枚举其余全部粒子来估密度与压强，复杂度 $O(n^2)$——粒子数百万级时不可接受（加速见邻居搜索一节）。

   * **自由表面流体（Free Surface Fluid）**

       * > **定义**：存在可自由运动的流体界面的流体——如一盆水的水-空气界面。

       * 烟雾不算自由表面流体：不管有没有烟，整个空间都被空气填满；用 SPH 做烟要把整个空间填满粒子，开销大，且 particle 的 overhead 本来就比 grid 高——做烟一般用 background grid 存背景速度场，较少有人用 SPH。

### 弱可压缩 SPH

   * **材料导数（Material Derivative）**

       * > **定义**：$\dfrac{D}{Dt}$ 表示跟着粒子一起运动时看到的时间变化率；SPH 的每个粒子就是一个"跟着流体走"的观察者，粒子速度的时间导数写作 $\dfrac{Dv}{Dt}$。

       * 别名众多：material derivative、Lagrangian derivative、convective derivative、advection derivative——记住"大 D 是跟着粒子动的导数"即可。

       * > **易错点**：WCSPH 原文用的是小 $d$，容易误读成全微分；粒子方法里一般用大 $D$ 表示物质导数，别被原文符号误导。

   * **弱可压缩 SPH（Weakly Compressible SPH，WCSPH）的核心方程**

       * > **定义**：最简单的 SPH 流体实现——真正的不可压缩要下一番功夫，入门先允许流体微弱压缩，用压强梯度驱动流体。

       * 动量方程 $\dfrac{Dv}{Dt} = -\dfrac{\nabla p}{\rho} + g$：它是欧拉方程（Euler equations，即不考虑黏性的 Navier–Stokes 方程）——压强梯度除以密度是流体内力产生的加速度；$g$ 是重力等外力（有时图省事把各种外力都算进 $g$）。

       * 状态方程（equation of state）：$p = B \left[ \left( \dfrac{\rho}{\rho_0} \right)^{\gamma} - 1 \right]$——$B$ 是体积模量（bulk modulus），$\rho_0$ 是理想密度；密度大→压强高→把周围粒子推开，等于在尝试保持自己的体积。

       * 密度估计：$\rho_i = \sum_j m_j\, W(x_i - x_j, h)$——粒子自己携带的是质量而不是密度，密度由周围粒子的质量加权估出。

       * WCSPH 原文还讲了表面张力、黏性的加法；想深入可看图形学里最懂 SPH 的一批人做的流体/固体 SPH 物理动画 tutorial。

   * **SPH 的梯度算符**

       * SPH 有一套专属梯度公式：形式奇怪、无法从核函数近似直接推出、数值也不太准——但它是对称的，保证动量守恒；不用它算 $\nabla p$，系统会出现各种不稳定。

       * > **提示**：牺牲一点精度换对称性（动量守恒），这笔账在流体模拟里是划算的。

       * 高阶导数另有一套公式：算黏性要用拉普拉斯 $\nabla^2$，SPH 里又有一套额外算式——SPH 不太优雅的地方。

   * **时间步三步流程**

```text
WCSPH 每个时间步：
  第一步  对每个粒子估计它局部的 density
          注意：粒子自己不 carry density，它 carry 的是质量，
          density 是通过周围粒子的质量估计出来的
  第二步  有了每个粒子上的 density，用 SPH 的梯度公式
          算出每个粒子这个地方压强的梯度 grad p
  第三步  把 grad p 代入 Dv/Dt = -grad p / rho + g，
          后面用一步 symplectic Euler（辛欧拉，也叫半隐式欧拉）更新
```

       * 第三步与弹簧质点系统的积分几乎一模一样——可以把 SPH 想象成：每个粒子与周围半径 $h$ 内的粒子之间都连着一根"弹簧"，只不过它遵循的不是胡克定律，而是 SPH 推出的物理关系。

### SPH 的变种

   * **PCISPH（预测-校正 SPH）**

       * > **定义**：偏隐式的 SPH——做隐式时间积分但为性能做了取舍，用预测—校正（predict–correct）格式反复校正粒子位置/速度。

       * 校正收敛出的速度场散度更小——速度场无散就意味着流体更接近不可压缩。

   * **PBF（Position Based Fluids，基于位置的流体）**

       * > **定义**：把实时领域高频使用的 PBD 与 SPH 结合得到的流体模拟方法，近年非常流行；太极内置了它的示例。

   * **DFSPH（Divergence Free SPH）**

       * > **定义**：强行把速度场 enforce 成无散（divergence free）来逼近不可压缩的 SPH 变种。

       * 隐式 SPH 家族还有很多（如 IISPH）；入门可先读较早的《SPH in computer graphics》，进阶看带 demo 的新版 tutorial。

## CFL 条件与邻居搜索

   * **CFL 条件（CFL Condition）**

       * > **定义**：从粒子运动速度限制显式时间步长的条件——库朗数（Courant number）$C = \dfrac{u\, \Delta t}{\Delta x}$，含义是"一个时间步内，粒子最多能挪过几个网格间距"；模拟必须满足 $C \le C_{\max}$。

       * $u$ 是粒子最大速度，$u\Delta t$ 即单步最大移动距离；SPH 里 $\Delta x$ 一般取 $h$（差个常数），可理解为粒子半径。

       * 它与 $\Delta t \le c\sqrt{m/k}$ 是两条不同的红线：前者从材料刚度出发，CFL 从运动速度出发——做任何显式时间积分都得守着，否则特别容易炸。

       * $C_{\max}$ 取决于各 simulator 数值稳定性的脾气：0.1 到 10 都有，一般取几个接近 1 的值；粒子跑得太快就减小 $\Delta t$。

| 方法 | 典型 $C_{\max}$ |
| :--- | :--- |
| SPH | 接近 0.4 |
| MPM（Material Point Method，物质点法） | 0.3 ~ 1 |
| FLIP（FLuid Implicit Particle，做 smoke） | 1、5，甚至 10、20 |

   * **邻居搜索（Neighborhood Search）**

       * > **定义**：对每个粒子找出距离不超过 $h$ 的所有粒子——有了它就不必枚举全场粒子，是把 SPH 从 $O(n^2)$ 压到 $O(n)$ 的关键，也是 SPH 的首要瓶颈。

       * 标准做法：背景体素网格（background voxel grid），每个 voxel 维护一个 list 装着落在其中的粒子；查邻居 = 先定位粒子所在 voxel → 只枚举它周围一圈 voxel（二维 3×3 共 9 个，三维 3×3×3 共 27 个）→ 枚举这些 voxel 里的粒子。

       * 每个 voxel 的粒子数是常数（几到几十个量级），单粒子只需检查几十到一两百个候选，相比全场可能上百万个 voxel 是极小的子集。

       * 进一步加速：位压缩技巧、用 Morton coding 提高访存局部性等单线程方法；邻居列表（neighbor list）的构建本身也有专文优化。

```text
      ┌───┬───┬───┐
      │   │ ? │   │       对粒子 P 找邻居：
      ├───┼───┼───┤       先定位 P 所在的 voxel，
      │ ? │ P │ ? │       再只枚举它周围的 voxel
      ├───┼───┼───┤       （二维 3x3，三维 3x3x3，
      │   │ ? │   │         一共 9~27 个），
      └───┴───┴───┘       而不是全场可能上百万个 voxel。
```

## 粒子方法家族与结果后处理

   * **同族的粒子方法**

       * DEM（Discrete Element Method，离散元素法）：把每个粒子看成一个带复杂物理的刚体小球，图形学常用，可模拟沙子等物质。

       * MPS（Moving Particle Simulation）：与 SPH 相近，但在局部解一个泊松方程（Poisson equation），流体的不可压缩性更好。

       * Power Particles：用 power diagram（Voronoi diagram 的推广）加粒子构建不可压缩流体 solver；视觉上的主要好处是粒子间距非常均匀。

       * Peridynamics（近场动力学）：图形学里也有有趣的应用。

   * **SPH 与刚体的耦合（Coupling）**

       * 弱耦合：先解流体 → 流体作为边界条件解刚体 → 刚体作为边界条件解流体，两边轮流解，耦合较弱。

       * 强耦合：解线性系统或迭代时把流体、刚体两个系统联立同时求解——"联立"二字是强弱耦合的分水岭。

       * SPH/MPS 这类方法容易做流体、弹性体、刚体间的介质耦合（已有用 SPH 模拟雪、本质是模拟一堆刚体的工作）；代价是每帧计算耗时很长，远非实时。

       * > **注意**：SPH 视觉上偏 splashy——粒子四处飞溅、splash 中间往往是空的，观感未必好；加表面张力能减轻。

   * **表面重建（Surface Reconstruction）**

       * > **定义**：从模拟粒子生成水面 mesh 的话题；最经典基本的方法是 marching cubes——打背景网格、在每个网格点算粒子密度、提取等值面（isosurface，某个量等于常数的面），用三角形网格近似填充。

       * marching cubes 情况分支极多（常见情况就有 14 种，复杂情况远不止），实现麻烦，但基本绕不开。

       * 工业流程：先做 smoothing 等预处理；用 OpenVDB 把粒子光栅化到背景网格得到距离场，在 level set 上做变圆滑/变尖锐等操作得到 density field，再上 marching cubes；OpenVDB 被很多电影使用，拿过奥斯卡学院奖。

   * **屏幕空间方法（Screen-Space Methods）**

       * 把粒子直接投影到屏幕（framebuffer）上，在屏幕空间做折射、反射等操作——实时渲染的路数，靠各种近似在有限算力里换可接受的帧率，实时应用常见。

       * 电影里很少用：镜头不断移动，屏幕空间的假设不成立。

## 形变与形变梯度

   * **形变（Deformation）**

       * > **定义**：材料现在的位置相对静止状态的位置发生了变化；描述工具是 deformation map $\phi$——把静止位置映射到形变位置的函数（三维情形是三维向量到三维向量的向量函数）。

       * 二维直观例（海绵宝宝 demo）：$\begin{bmatrix} 1 & 0 \\ 0.5 & 1 \end{bmatrix}$ 是剪切（shearing），$\begin{bmatrix} 1 & 0 \\ 0 & 2 \end{bmatrix}$ 纵向拉伸，$\begin{bmatrix} 2 & 0 \\ 0 & 1 \end{bmatrix}$ 横向拉伸——形变梯度第一行管横向缩放、第二行管纵向。

   * **形变梯度（Deformation Gradient）**

       * > **定义**：$F = \dfrac{\partial \phi}{\partial X}$——deformation map 对静止位置的导数；$J = \det F = \dfrac{V_{\text{deformed}}}{V_{\text{rest}}}$ 是形变后体积与静止体积之比（Jacobian determinant）。

       * 平移不产生形变：两个 deformation map 只差一个常数（最终位置平移）时形变梯度相同——常数求导后消失，所以平移不受弹性势能惩罚。

       * 有限元弹性长条 demo 的两个已知短板：显式积分下大力移动碰撞体会立刻失稳（边界条件做得不细）；二维里物体自己穿透自己（自碰撞/自相交），不物理真实——有限元处理自碰撞一直头疼，时髦搞法是用 RTX 这类光线追踪硬件。

## 超弹性与应力张量

### 超弹性（Hyperelasticity）

   * **超弹性与应变能密度**

       * > **定义**：弹性 = 材料恢复自己静止状态的性质（橡皮筋拉开松手会回去）；超弹性模型的标志性性质是应力-应变关系由应变能密度函数（strain energy density function）$\Psi$ 定义——$\Psi$ 是 $F$ 的函数，本质是惩罚形变的势能，且是单位体积的能量密度而非总能量。

       * 为什么先学弹性：视觉上 Q 弹好看；实现不难（用太极一百多行就能写一个 2D FEM 弹性模拟器）；弹性是粘弹性、弹塑性等更复杂材料的基础——后者都是在弹性上做细微修改。

       * > **易错点**：$\Psi$（大写 Psi，应变能密度函数）和 $\phi$（deformation map）长得像，但两者完全不相关。

   * **应力与应变（Stress & Strain）**

       * stress（应力）：材料内部的弹性力，把材料拉回原来的体积与形状；strain（应变）：材料形变的度量。

       * 两者都有非常多种表述（各种 stress tensor、各种 strain 描述）；本课程里见到 strain，直接用形变梯度 $F$ 替换即可。

### 应力张量（Stress Tensor）

   * **应力张量与 traction**

       * > **定义**：应力张量是 $3\times 3$ 矩阵（二阶张量）；给材料一个很小的截面，把截面法向量乘上应力张量，得到的就是这块材料向周围施加的力——traction。

   * **第一 Piola-Kirchhoff 应力（PK1）**

       * > **定义**：$P = \dfrac{\partial \Psi}{\partial F}$——应变能密度对形变梯度求导；在静止空间（rest space）求值，非常容易计算。

       * 局限：它是 rest space 里的张量，要算材料形变后的实际受力，还得变换到形变后空间。

   * **Cauchy 应力与 Kirchhoff 应力**

       * Cauchy stress 又叫 true stress：形变后空间里真实的内部应力张量；对称——原因是角动量守恒。

       * Kirchhoff stress $\tau$：$\tau = J\sigma$，标量乘对称矩阵仍是对称矩阵。

   * **换算公式与对称性**

       * $\tau = J\sigma = P F^T$，$P = J\sigma F^{-T}$；$F^{-T}$ 是"先转置再求逆"（等价于先求逆再转置）——出现 $F^{-T}$ 是因为被变换的对象是截面法向量，法向量的变换公式用的就是 $F^{-T}$。

       * PK1 不对称一眼可见：$\sigma$ 对称但 $F$ 不对称，$\sigma F^{-T}$ 自然不对称；对称版本还有 PK2 stress，但用得更少。弹性模拟里真正用到的其实只有 PK1。

| 应力张量 | 所在空间 | 对称性 | 备注 |
| :--- | :--- | :--- | :--- |
| 第一 Piola-Kirchhoff $P$ | 静止空间 | 不对称 | $P=\partial\Psi/\partial F$，最容易计算 |
| Cauchy $\sigma$（true stress） | 形变后空间 | 对称（角动量守恒） | 真实的内部应力 |
| Kirchhoff $\tau$ | 形变后空间 | 对称 | $\tau = J\sigma$ |

## 材料参数与弹性模型

### 材料参数（Material Parameters）

   * **杨氏模量与泊松比**

       * 杨氏模量（Young's modulus）$E$：最简单的理解是弹簧里那个 $k$。

       * 泊松比（Poisson's ratio）$\nu$：刻画拉伸时横向收缩——$\nu=0$ 时拉长截面不缩小；$\nu$ 越大越接近不可压缩（拉长又要保体积，中间就得变细，符合橡皮筋拉了会变细的直觉）。

       * auxetics：负泊松比材料——拉长后中间反而变粗；3D 打印可以造出这种结构。

   * **体积模量与 Lamé 参数**

       * 体积模量（bulk modulus）$K$：刻画"压强关于体积变化"的刚度，模拟可压缩液体时用得多，平时用得少。

       * Lamé 参数 $\lambda, \mu$：$\mu$ 又叫剪切模量（shear modulus），有时写作 $G$；固体计算常用。

       * 换算惯例：这些参数都正比于 $E$——指定 $E$ 和 $\nu$ 后其余全部可算；大家习惯只给 $E, \nu$，再算出不太直观的 $\lambda, \mu$。

| 参数 | 符号 | 直觉 | 什么时候用 |
| :--- | :--- | :--- | :--- |
| 杨氏模量 | $E$ | 相当于弹簧的刚度 $k$ | 和 $\nu$ 搭配，是指定材料的标准方式 |
| 泊松比 | $\nu$ | 拉伸时横向收缩的程度：0 不收缩，越大越接近不可压缩 | 与 $E$ 一起给定，其余参数全能算出 |
| 体积模量 | $K$ | 压强对体积变化的刚度 | 模拟可压缩液体 |
| Lamé 参数 | $\lambda,\ \mu$ | $\mu$ 又叫剪切模量，有时写作 $G$ | 固体计算常用，由 $E,\nu$ 换算 |

### 常用超弹性模型

   * **线性弹性（Linear Elasticity）**

       * > **定义**：最简单的弹性近似——适合小形变分析（无宏观形变、不旋转），导出的方程组是线性的、非常易解。

       * 致命伤：旋转一个线性弹性材料，其体积可能无条件变大而不受任何惩罚——势能保持为 0 但体积变大，不物理。

   * **Corotated 与 Neo-Hookean**

       * Corotated 为修复线性弹性的旋转问题而生；最初的版本有点小问题，后来的修正版 Fixed Corotated 成为今天说"Corotated"时的默认所指。

       * Neo-Hookean 在力学社区更常用；图形学里各向同性（isotropic）的弹性介质基本默认采用 Neo-Hookean；弹性长条与 2D FEM 示例都用它。

       * 模型公式会用到 $F$ 的奇异值（singular values）：奇异值把 $F$ 里旋转的部分剔掉，刻画剩下的纯拉伸/压缩。

       * > **易错点**：超弹性公式里的 $\sigma$ 指奇异值，不是应力——应力张量恰好也用 $\sigma$ 表示，重名纯属巧合。

       * 有了 $\Psi(F)$ 就能求 PK1（一阶导数）；写隐式求解器还要二阶导数——三维里是 $3\times3\times3\times3$ 共 81 个元素的四阶张量，推导体验很差。

## 有限元方法

### Galerkin 方法与弱形式

   * **有限元（Finite Element Method，FEM）**

       * > **定义**：一套 Galerkin 方法——解决"连续 PDE 装进只有离散值的计算机"的问题：把连续 PDE 换成离散方程组。

       * 不用逐点满足的强形式（strong form），而是引入 test function，要求方程残差（residual）对 test function 的积分满足——这就是弱形式（weak formulation）。

   * **单元（Element）与自由度（DOF）**

       * 求解域被剖分成小 element：二维是三角形/四边形，三维是四面体/六面体；还有更花哨的元素（网上有基于 FEEC 离散微分几何的"有限元素周期表"FEM Table）。

       * 未知数（自由度，degrees of freedom，DOF）暂时可假设存在顶点上；复杂元素的 DOF 也可能放在边上或体里；图形学最常用三角形/四边形元素。

### 线性三角形有限元

   * **仿射假设（Affine Assumption）**

       * > **定义**：线性三角/四面体 FEM 的最简假设——deformation map 在每个元素内部是仿射变换（$Ax+b$），即形变梯度 $F$ 在元素内部是常数。

       * 假设范围是"元素内"而非整个模拟域——全域共享一个 $F$ 意味着物体几乎不能形变，谈不上模拟弹性体；真正的弹性体是每个元素自由形变。

       * 元素内 $x' = Fx + b$，$b$ 是平移偏移量——它不被势能 penalize（平移不产生形变，自然不产生弹性势能）。

   * **元素弹性势能**

       * $U_e = \int_{\Omega_e} \Psi\, dx = V_e\, \Psi(F_e)$：$F$ 在元素内是常数，$\Psi$ 也是常数，积分退化为密度乘体积（二维是面积），$V_e$ 是元素静止体积。

       * 力 = 势能对位置求导再取负——这是势能的定义，有了 $U_e$ 便可求力。

   * **形变梯度 F = D B⁻¹ 的手推**

       * 三个顶点各满足 $x' = Fx + b$；相邻两式相减消掉 $b$：$x'_A - x'_C = F(x_A - x_C)$，$x'_B - x'_C = F(x_B - x_C)$。

       * 记 $B = \begin{bmatrix} x_A - x_C & x_B - x_C \end{bmatrix}$、$D = \begin{bmatrix} x'_A - x'_C & x'_B - x'_C \end{bmatrix}$，两个向量方程（共四条线性约束）合成 $D = FB$——$F$ 是 $2\times2$ 共四个未知项，恰好解出 $F = D B^{-1}$；二维三角形推广到三维就是四顶点的四面体。

       * > **提示**：$B$ 只由静止状态的顶点位置决定，是常数——提前求好逆存起来即可；矩阵求逆不便宜（至少要算一次行列式的倒数再做除法），没必要每个时间步重算。

## FEM 的时间积分

### 显式 FEM 与自动微分

   * **显式积分与力的链式法则**

       * 积分照旧用 semi-implicit Euler：$v_{i+1} = v_i + \Delta t\, \dfrac{f(t_i)}{m}$，$x_{i+1} = x_i + \Delta t\, v_{i+1}$——唯一缺的是力 $f(t_i)$。

       * 力 = 势能对位置导数取负；总势能 $U = \sum_e U_e$，链式法则展开 $\dfrac{\partial U_e}{\partial x} = V_e\, \dfrac{\partial \Psi(F_e)}{\partial F_e}\, \dfrac{\partial F_e}{\partial x}$——中间因子正是 PK1 stress，末因子 $\partial F_e/\partial x$ 需要手推。

       * > **易错点** ⚠️：链式法则里多出来的体积是元素的静止体积 $V_e$，不是形变以后的体积（好在这也是常数）。

   * **自动微分（AutoDiff）实现**

       * 不想手推 $\Psi(F)$ 与 $\partial F/\partial x$，可以把求导整体交给 Taichi 自动微分：程序里不需要受力函数，只写一个总能量函数 `compute_total_energy`，在 `ti.Tape` 里调用、执行完反传即得 $\partial U/\partial x$。

       * > **提示**：Neo-Hookean 能量里有 $\log J$ 项，$J$ 一旦变负就会出现 infinity/NaN 让模拟崩掉——把 $J$ 与 0.2 取 max 是一道保命闸。

```text
x, v ──▶ compute_total_energy(x)      （Neo-Hookean 能量，含 max(J, 0.2) 保护）
            │ ti.Tape 记录下全部计算
            ▼
      backpropagation：自动得到 ∂U/∂x
            │
            ▼
v ← v + Δt·(−∂U/∂x)/m ──▶ x ← x + Δt·v   （semi-implicit Euler：先 v 后 x）
```

       * 重力目前单独按 $-g\cdot dt$ 积分；其实可以把重力势能并进总能量、全部交给自动微分；只要能定义出势能，弹簧质点系统同样可用自动微分。

### 隐式 FEM 的难点

   * **二阶导数（Force Differential）**

       * backward Euler 配一次 Newton-Raphson（一阶泰勒展开）就把问题化成解线性系统，系统里出现 $\dfrac{\partial f}{\partial x}$——而 $f$ 本质是 $\Psi$ 对 $x$ 的导数（差个负号），再求一次导就是二阶导，求起来非常头疼；三维中间量是 81 元素的四阶张量。

       * Taichi 自动微分目前不支持二阶导数，这一步只能手推；两份弹性/有限元教程里有各种材料二阶导数的现成推导可照着写——即便如此也容易写错。

       * > **注意**：写隐式求解器大约 10% 的时间在写代码、90% 在 debug；组队互相验算公式、review 代码能显著提高生产力——当局者迷，旁观者清。

   * **质量矩阵 M 与 mass lumping**

       * $M$ 是对角矩阵，对角线是各 node 的质量；FEM 里严格构造 $M$ 需要 mass lumping 技术来简化。

       * 图形学里一般不 care：用任何方便的近似都行——直接取元素质量，或取顶点质量 = 周围元素质量加权。

## Taichi 高级特性：ODOP

   * **面向数据的面向对象编程（Objective Data-Oriented Programming，ODOP）**

       * > **定义**：Taichi 本是面向数据（data-oriented）的语言——性能高但难模块化；它从面向对象编程（OOP）借来概念组成混合方案，用 class 提高代码可复用性（reusability）。

       * 三个 decorator 撑起整套方案：`@ti.data_oriented` 修饰整个 class；`@ti.kernel` 修饰成员 kernel（与外部 kernel 用法一模一样，只多带一个 self）；`@ti.func` 修饰成员 function，可再叠加 Python 的 `@staticmethod`（demo 里用它生成范围内的随机数）。

       * 旧写法 `ti.class_kernel`/`ti.class_func` 已废弃——老代码里见到直接当成 `ti.kernel`/`ti.func` 忽略掉。

   * **class 化的收益与初始化分工**

       * 成员张量在 class 里定义与外部无区别（只是多了 self）；用法与普通 Python class 一致：构造器传参、直接给成员张量赋值、像调方法一样调 kernel；参考 demo `odop_solar`（行星绕日，太极 0.6.10 起可用），其中 `integrate` kernel 做的就是 symplectic Euler 积分。

       * class 化的实际好处：一个文件定义 class、另一个文件调用——散写 kernel/function 时多文件很麻烦；拆成多文件后每个文件更小、维护成本低。

       * > **注意**：`ti.init` 不负责初始化张量；class 里的数据初始化交给自己的 initialize 方法。

| decorator | 修饰谁 | 作用 |
| :--- | :--- | :--- |
| `@ti.data_oriented` | 整个 class | 声明这是一个面向数据的 Taichi class |
| `@ti.kernel` | class 成员函数 | 成员 kernel，用法与外部 kernel 一致，多带 self |
| `@ti.func` | class 成员函数 | 成员 function，可再叠加 Python 的 `@staticmethod` |

## Taichi 元编程

### ti.template() 与懒惰实例化

   * **ti.template() 的用法**

       * > **定义**：kernel 参数的类型标注写成 `ti.template()`（两个括号必须加，不加可能编译错误），即可把 tensor、class、class 实例、function 甚至数值传进 kernel——不用它很难把张量当参数传。

       * 典型例子：`def copy(x: ti.template(), y: ti.template(), c: ti.f32)` 里 `for i in x: y[i] = x[i] + c`。

   * **懒惰实例化与实例化开销**

       * kernel 是懒惰实例化（instantiation）的：定义了不调用就不编译，很多计算可在编译期完成、运行时少花时间；每个 kernel 其实都是 template kernel，区别只是模板参数个数——随手写的 kernel 有 0 个 template argument。

       * > **注意**：template kernel 的实例化开销不小——参数标 `ti.template()` 时传不同值各生成一个实例，循环传 100 个值就会编译出 100 份 kernel（第二轮同样的循环复用不再新建）；传普通数值（如 `ti.i32`）只生成一个实例。kernel 复杂时编译 100 遍的代价很明显。

### 编译期工具

   * **ti.grouped 与维度无关编程**

       * `for I in ti.grouped(y)` 把 y 的下标打包成整型向量 I（y 是 n 维张量，I 就是 n 维向量）；`x[I] = y[I]` 一行通吃 0D/1D/2D/3D 张量；分量可单独取用（`I[0]` 相当于 i，`I[1]` 相当于 j）。

       * 维度无关的价值：FEM 的二维/三维代码高度相似（二维向量对三维向量、三角形对四面体、2×2 对 3×3 矩阵），一份代码二维调对了三维基本自动对，调试时间缩短；Taichi 标准库大量用元编程实现。

   * **编译期反射与编译期分支**

       * 编译期反射（reflection/自省）：可在编译期查询张量是几维、shape 是什么样（demo 会把 shape 打印出来）。

       * `if ti.static(cond):` 把分支判断挪到编译期，零运行时开销——等价于 C++17 的 `if constexpr`；典型用途是"处理/不处理碰撞"这类功能开关（如 `enable_projection`）。

   * **循环展开与下标限制**

       * `for k in ti.static(range(3))` 强行展开循环（loop unrolling），减少循环本身的开销、可能拿到更高性能。

       * 更硬的理由：向量与矩阵的下标必须是编译期常数——想用循环变量访问向量/矩阵内部，就得先把循环 unroll 掉，让循环变量变成编译期常数。

```text
访问标量 a[i][k] 实际分两步：

  第一步  a[i] ：从 tensor 里取出第 i 个 element（一个向量/矩阵）    i 可以是运行时变量
  第二步  [k]  ：从向量/矩阵里取出第 k 个 scalar                    k 必须是编译期常数
```

   * **变量别名（Variable Aliasing）**

       * `A, B, func = ti.static(tensor_A, tensor_B, some_function)` 给长名字建短引用；写 five-point stencil 这类张量名要出现五次的代码时很省事。

       * 必须用 `ti.static`——直接 `A = tensor_A` 语法不过；别名是按引用（by reference）：通过别名改"新变量"会影响旧变量，像 C++ 的 `&`。

## 可微编程

### 反向模式自动微分

   * **反向模式自动微分（Reverse-Mode Autodiff）**

       * > **定义**：普通程序在 evaluate——算 $f$ 就是算 $f(x)$；可微编程求 $f(x)$ 关于 $x$ 的偏导数（Jacobian）。Taichi 的 reverse-mode autodiff 对标量 loss function 做反向传播，得到它关于每个元素的导数。

       * 求导两条路：`with ti.Tape(loss=...):` 包住 forward kernel，Tape 生命周期结束时自动生成并执行 backward，全自动；或用 gradient kernel——想要更多控制时用。

       * 最小例子：$L(x) = 0.5\sum_i (x_i - y_i)^2$，则 $\partial L/\partial x_i = x_i - y_i$（demo 里 y 是固定目标，目标为零时梯度就是 x 本身）。

       * > **提示**：别把"导数等于 x"当普适结论背下来——它只对平方差这一形式成立。

   * **ti.Tape 求导三步**

       * 第一步：分配张量时给要求导的变量加 `needs_grad=True`（默认不开，不加就不求梯度）：`x = ti.var(ti.f32, shape=n, needs_grad=True)`；loss 是标量张量 `L = ti.var(ti.f32, shape=(), needs_grad=True)`。

       * 第二步：写 forward kernel，累加 loss 用原子的 `+=`：`L[None] += 0.5 * (x[i] - y[i]) ** 2`。

       * 第三步：在 Tape 作用域里调 forward，结束后拿 `x.grad` 做梯度下降 `x[i] -= x.grad[i]`——这是做 optimization 最简单的搞法。

```text
forward：with ti.Tape(loss=L): 里调用的每个 kernel 都被 Tape 记录下来
            reduce()  →  ...  →  ...
backward：Tape 生命周期结束时，按「颠倒的顺序」自动调用每个 kernel 的 gradient kernel
            ..._grad()  →  reduce_grad()    回放完毕，x.grad 就绪
```

       * `ti.Tape` 本质就是深度学习里的 backpropagation（backward pass）；可通过 `to_torch`/`from_torch` 与 PyTorch 交换数据配合使用。

       * 现成 demo：`autodiff_minimization`——L2 loss 加定步长梯度下降本是指数下降过程，收敛非常快；`autodiff_regression`——用三阶多项式拟合三次函数生成的数据点，约 80 行。

### 可微编程的应用

   * **应用一：势能求导得受力**

       * 力 = 势能对位置导数的负值——用自动微分省掉手推各种导数；FEM 之外，MPM 里的拉格朗日力（Lagrangian forces）同款可用，与 FEM 非常像。

       * MPM 与 FEM 的关键区别在碰撞：MPM 有背景网格，物体自相交会在背景网格上自动得到碰撞处理；FEM 的自相交（self-intersection）要显式处理、非常头疼。

   * **应用二：优化整个物理过程（DiffTaichi）**

       * > **定义**：若每一步受力都靠手推、没用自动微分，那台"求导机器"就可以整体拿去对物理过程本身求导——优化物理系统的初始状态或控制器（controller）。

       * 实测熟练后两三个小时就能写出一个可微物理模拟器；已用它实现十个 differentiable simulator。

       * 代表 demo：双足机器人（每条腿两块肌肉，神经网络控制；没有微分时只能用强化学习、效率很低，有梯度后一般一二十个 iteration 就能走）；2D/3D MPM 机器人（3D 下 MPM 自动处理水与弹性体的耦合）；水面 height field（求一组初始水波，演化若干步后拼出"太极"图案——反向模拟）；刚体弹簧机器人（弹簧质点系统，同样一二十个 iteration 收敛）；台球（优化白球初始位置与速度，让蓝球最终抵达目标点）。

       * 对抗样本：走"可微水面模拟器 → 可微水面渲染器 → 可微神经网络（VGG）"三阶段可微管线，求一组初始水波，让折射后的松鼠图片被 VGG 以 99.91% 的信心判定为鲸鱼——链路每一环可微，梯度就能从识别结果一路回传到初始水面；说明神经网络鲁棒性有限，知道导数就能攻击。

   * **内存代价与 checkpointing**

       * 可微程序每个 time step 的状态都得记下来：本来 n 个粒子开一维张量即可，现在要开"时间步 × 粒子"的二维张量，内存占用显著上升。

       * checkpointing 是 auto-diff 常用的空间换时间技术，按需选择档位：

| 空间占用 | 时间代价 | 说明 |
| :--- | :--- | :--- |
| $O(n)$ | $O(n)$ | 不做 checkpointing：每个时间步全记 |
| $O(\sqrt{n})$ | $O(n)$ | 常规档：空间压到根号级，时间量级不变 |
| $O(\sqrt[3]{n})$ | $O(n)$ | 再压一档，常数项变大 |
| $O(\log n)$ | $O(n\log n)$ | 极端情况：空间压到对数级，时间多一个 $\log$ 因子 |

## 可视化输出

   * **ti.GUI（二维可视化）**

       * `gui = ti.GUI("Taichi MLS-MPM 128", res=512)` 创建带标题与分辨率的窗口，还可指定背景颜色；支持画圆、线、三角形，也可把张量作为 image 展示。

       * 主循环三连：`paint(t)` 算一帧 → `gui.set_image(pixels)` 显示结果 → `gui.show()` 呈现在屏幕上；太极自带这套极小化 GUI 正是为可移植性——代码复制粘贴就能跑。

   * **PLY 与 Houdini（三维结果）**

       * 太极自带 GUI 主要为 2D 设计；三维结果用 `ti.PLYWriter` 输出 PLY——可二进制也可人类可读（ASCII）的三维数据格式，header 之后是二进制、存储效率高，能装三维粒子与网格。

       * Houdini（File → Import → Geometry）能自动把一批 PLY 识别成序列，改时间轴、拖进度条即可播放粒子动画；学徒版（Apprentice）免费；Houdini 是电影工作室常用的特效软件，本身也能做模拟。三维网格输出可看 `export_mesh` 示例。

   * **推荐阅读材料**

       * 有限元：Fedkiw 写的有限元教程——从计算机/图形学角度切入、通俗易懂。

       * MPM：蒋老师与 UCLA 一批 MPM 研究者合写的 MPM 理论教程，写得非常好。
