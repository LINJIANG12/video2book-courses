## 在电脑里模拟一个世界：物理引擎开篇与太极语言初识
> 对应块：BLK01 | 覆盖分集：P01上 | 块标题（分集名）：《Lecture 1 课程介绍》

大家好，我是胡渊鸣，现在在 MIT 读书。非常高兴有这么多同学一起来上《高级物理引擎实战指南 2020》这门课。

### 开场：这是一门要动手的课

这门课整个基于太极（Taichi）编程语言，内容就是怎么写物理引擎。我们非常注重物理引擎的实战，所以希望每位同学都能在这门课里写一点自己的代码——因为你亲手写的代码，和听我讲数学公式，感觉是完全不一样的，你会很有成就感。

这门课的目标，就是自己动手打造一个影视级的物理引擎。适合人群：0~99 岁的计算机图形学爱好者。如果大家有一点高等数学，或者 Python，或者任何一门编程语言的预备知识，那就最好不过了。

课程安排在每周一，北京时间晚上八点半到九点半，一共十节课。一个小时的课有可能根据大家的反馈往后延长，比如八点半讲到十点。我这边（波士顿）正好是早上八点半到九点半——两边正好十二个小时的时差，所以一般都是把 AM 换成 PM（或者反过来），就能对上波士顿和北京的时间。课程内容这里就不多说了，后面我们会具体再讲。

### 物理引擎是什么：在你的电脑里模拟世界

先开门见山定义一下什么叫物理引擎。Wikipedia 上的定义是：物理引擎是一个计算机软件，它提供对一个物理系统的近似的模拟——比如刚体动力学、软体动力学，以及流体动力学；主要的 application 在 computer graphics 里面，也就是游戏和电影。

这个定义可能非常长，其实一句话就能说清楚：**在你的电脑里面模拟这个世界**。我想很多同学都想过做这件事——我小时候就非常想：怎么在电脑里面模拟一个世界出来？这还是很有意思的。

> **定义**：物理引擎 = 一个计算机软件，对物理系统（刚体动力学、软体动力学、流体动力学……）做近似的模拟。一句话：在你的电脑里模拟这个世界。

### 物理引擎能干什么

除了游戏和电影，物理引擎还有好几个很重要的应用方向。

**工业软件**。比如你设计一个模型，要做它的应力分析，可以先在电脑里面算一算，看看做出来以后应力分析大概会是什么样。这样你就不用真的把它做出来、试一试、发现"诶，这个不行"、再重做一个——这种迭代过程可以完全在计算机里面进行。

**电影里的视觉特效**。这个很重要：现在的电影，特别是动画电影，基本上每个电影里都有非常非常多的镜头，是用物理效果模拟出来的。

**虚拟现实、增强现实**。这个应该不用多说：如果你在 VR 里有一个基于物理的世界，你的沉浸感会增强很多——因为你可以和这个世界交互了，并且这个虚拟世界里的物理规律和现实世界里的物理规律是一致的，所以你会有更好的 VR 体验。

**训练机器人**。现在很多人用物理引擎来训练机器人，比如无人驾驶：我搞一个街道的物理引擎，车就可以在虚拟世界里面开，不用到真实世界里面去冒产生交通事故的危险。

当然，大家最关心的物理引擎用处还是在**游戏**里面。那我就仔细讲一讲游戏。

### 第一篇 SIGGRAPH 论文与十亿体素的 FEM

接下来这个是我的第一篇 SIGGRAPH 论文。我们用 MPM（物质点法）做了各种切割的模拟，实现了固体和液体的显式耦合——而"切割"是这个耦合的一个副作用。我们可以切香蕉、切兔子、切奶酪，还可以切沙子，或者说搅拌沙子。

在这篇文章里，我还提出了一种基于移动最小二乘（moving least squares）的新的物质点法，它比之前的 CPIC 物质点法要快两倍。它是基于蒋老师 2015 年那篇 Affine Particle-in-Cell（APIC）的 paper 做的一个算法上的精简，使得计算的时候工作量会小一半。

有同学问渲染时间和粒子数目的关系，这个我可以说一说：这篇 paper 里面基本上没有实时的东西。像切兔子、切奶酪，基本上都是 100 万到 300~400 万个粒子；右下角搅拌沙子那个例子，我记得大概有 350 万个粒子，当时模拟它得等上一天，还是挺费时间的。不过 MPM 这个算法的性能在逐渐提升，所以逐渐地，很多实时的应用应该也会出现。

再往下是一个更大规模的例子，SIGGRAPH Asia 2018 的一个工作：我们做了一个在一台机器上模拟十亿个 voxel 的 FEM。用 FEM 做完以后，我们有 sensitivity analysis（敏感性分析），然后就可以做 topology optimization（拓扑优化）。这些概念后面都会提到，现在大家只要记住 voxel 数目非常多就行了。这个工作网上也有，大家可以自己下载下来跑一跑——跑的时间就非常长了：我记得这个 demo 跑了得有一个星期，中间还挂了一次，我还重启了。我对这个事情印象特别深刻——所以，性能在物理模拟里面是非常重要的。

### 可微模拟：把模拟反过来算

最近我在搞的是可微模拟。这个东西其实很早以前也有，只不过我们最近把它的流程搞简化了一遍。

正常的模拟是：给你一个初始的状况，然后让你预测，比如说十秒钟以后这个系统是什么样的。可微模拟是反过来的：我希望求出初始状况的一个扰动，对于结果的影响是什么样的——这其实就是要求一个梯度。当你有了梯度的时候，你就可以对初始状况进行各种各样的优化。

```text
正向模拟：  初始状态 ─────────►  预测 10 秒以后的系统
可微模拟：  初始状态的扰动 ───►  它对结果的影响（求梯度）
```

也就是说，正向模拟回答"给我初始条件，未来会怎样"；可微模拟回答"想让未来变成某个样子，初始条件该怎么动"——这个答案就是梯度，也是一切优化的起点。比如这个例子里，我们就在求一个初始的水面高度，使得经过 512 个 time step 以后，可以得到一个"太极"的 pattern。现在解释有点抽象，我们后面会继续讲。

### 为什么我去写了编译器

刚才讲了过去十年的故事。到今年，我在 MIT 读博士第三年了，我还是在做物理模拟，但我花了很多时间去写编译器。为什么呢？因为我发现：如果你没有一个好的编程语言、没有一个好的编译器，你要写高性能的 simulation 是非常非常难的，就是非常非常费时间。所以我重新造了一个编程语言，这样大家就可以更容易地写自己的 simulator。

现在基本上可以说，我有一半的时间都在做这个太极编程语言。当然，这里面有非常非常多的贡献是太极社区的同学们一起帮忙做的，真的非常不容易：我每天早上一起来，就能看到 GitHub 上面好多的 issue，就跟开黑打网游下副本一样——解决一个个很难修的 bug，进行各种各样的设计决策，真的非常有意思。

我最近也开了这么个课，主要是想跟大家分享一下怎么样去写物理引擎，比较有意思；当然也做做直播，"带货"带一带这个太极编程语言——希望大家都能尝试一下这个新东西。

### 这门课的关键词

接下来讲讲这门课会把注意力集中在哪些关键词上面。

**离散化**。我们会简单讲讲各种各样的离散化。这部分数学比较 involved，所以可能不会讲得特别深。更多的时候——因为我自己主要是做计算机方面的——我会更多讲一讲：从一个程序员的角度，怎么去直观地理解各种各样的离散化。

**有效率的求解器**。比如现在你要写一个 fluid solver，很长一段时间很可能就是花在 linear solver 上面——不同的 linear solver，性能有天壤之别。后面我们会详细介绍这些 preconditioner（预条件子）。

**生产力**。怎么样用比较短的代码，实现一个高效的物理模拟。你别看"短代码"这个事，听起来好像是一个非常糟糕的 metric——用代码行数去 measure 一个软件，是非常糟糕的一个 metric。但是你仔细想想：有别的更好的 metric 吗？其实你很难想到比代码行数更好的 metric。这也是为什么我喜欢用这种 metric，来证明一个东西可以用很少的代码写出来。

**性能**。刚才提到很多模拟都要等上一天的时间，那你要再去做迭代的话，就非常非常费时间了。

**硬件的体系结构**。你要写高性能 solver，就得去了解一下你的硬件是什么样的；如果你不了解硬件，就很难把它全部利用起来。

**复杂的数据结构**。我们会讲讲各种各样的复杂数据结构——不过太极让数据结构的使用变得更加简单了，后面会详细介绍。

**复杂的并行**。现在并行硬件大行其道：CPU 和 GPU 如果算吞吐量的话，真的是天壤之别，一般能差上一个数量级。这边展示的是 2020 年一篇比较新的 paper，结果非常非常 impressive：他们可以用四个 GPU，模拟应该是 1 亿个 particle——这在之前是前所未有的。有兴趣的同学可以去读一读这个 paper。

**模拟器的导数**。最后我们会讲讲怎么去求 simulator 的导数。导数求出来，你就可以做很多有意思的事情。比如我们这边还有两个机器人，都是软体机器人：上面这个是 MPM 机器人，它有四块"肌肉"——两条腿，每条腿分左右两半，每一半可以伸缩，也就是变长或者变短，相当于你的肌肉，可以收缩或者舒张；下面这个是一个弹簧质点的机器人。

### 太极：嵌在 Python 里的高性能图形学 DSL

先说明一下：这套 slides 我在整个课程期间会不断地更新，因为今天只能讲一讲最简单最简单的内容，后面我们会逐渐加入太极里面一些比较复杂的 feature。课程结束以后，这些 slides 都会在网上有，所以大家不用担心。如果 slides 里有任何没介绍到的东西，大家可以去看 Taichi 的文档——现在在大家的努力下，英文文档和中文文档应该都是比较可读的。特别是中文文档，真的非常不容易：大家基本上是以"迅雷不及掩耳盗铃儿响叮当仁不让"之势，把中文文档全部翻译好了。当然，很多我今天讲到的 feature，并不是我一个人写的，很多 feature 是我们社区一起写的；我也不是唯一的 developer。

那么什么是太极呢？太极是一个高性能的领域特定语言（DSL），它嵌入在 Python 里面，所以它的语法和 Python 非常非常像——你如果会 Python，基本上很快就可以学会太极怎么用。这个语言是专门为计算机图形学的应用来设计的。我们在设计的时候，非常非常注重两样东西：生产力和可移植性——这两样东西，以前在计算机图形学里面是非常难以做到的。

我说的生产力，不是说你用游戏引擎做游戏的生产力；我说的是，对于一个想研究图形学算法的人，去写一个图形学算法的生产力。我们也很注重可移植性：这门课建议大家都使用太极编程语言，因为太极程序有个好处——你在一台机器上写的太极程序，复制粘贴到另外一台机器，只要那台机器装了太极，基本上都是能跑的。这和你用 OpenGL、用 CUDA 写的程序就完全不一样：如果不用太极，你会碰到各种各样的依赖——为了让程序画一个三角形，你可能要装三四个包，非常非常麻烦。

太极是面向对象的，它是自动并行的，并且它的 kernel 是 mega-kernel——这和深度学习里面那种 composability 比较弱的 kernel 是不一样的。我们还有一些比较好的稀疏数据结构以及可微编程的支持，这个后面再介绍。

那今天其实就讲几个非常简单的内容：怎么安装、怎么定义数据、怎么做计算，然后怎么进行调试。

### 安装与初始化

如果你用 Python 3.6、3.7 或者 3.8，你就可以直接用 pip 去装太极：

```bash
pip install taichi
```

要注意一下（我之前闲聊的时候也说过）：国内源有的时候有一点延迟——比如官方源已经 0.6.7 了，镜像源可能还是 0.6，装出来的太极可能就不是最新的版本。这个我自己没有去实践过，但是之前知乎上面有很多人跟我说这个事情，所以大家装完要确认一下版本。

三大主流的操作系统我们都是支持的。太极程序既可以在 CPU 上面运行，也可以在 GPU 上面运行——GPU 我们支持 CUDA、OpenGL 和 Apple Metal。如果你有一些"神奇的配置"——比如说你的 CPU 是 ARM，或者你非要用 Python 3.9 以上——那也没办法，你就得 build from source：把太极的源代码 down 下来自己装。最新的 Python 已经到 3.9 了（我记得 5 月底的时候 3.9 刚刚出现），但是大部分同学应该都是 3.6 或者 3.7，3.8 可能都是相对少数——不过我们也是支持 3.8 的。

接下来是初始化太极，这个非常重要：

> **提示**：每当你运行一个太极程序的时候，请总是先调用 `ti.init`（就是 initialize），before you do any taichi operations。

在 `ti.init` 里面，你可以 specify 指定你的后端，比如用 `arch` 参数——这是最最最常用的参数。指定了 arch 以后，你就可以选择到底在什么硬件上面跑：可以是 x64，可以是 arm，可以是 cuda，可以是 opengl，可以是 metal——你可以随意选择一个 backend。当然，你系统得支持；你系统不支持，那我们也没有办法。

```python
import taichi as ti

ti.init(arch=ti.gpu)   # 也可以是 ti.cpu / ti.cuda / ti.opengl / ti.metal / ti.x64 / ti.arm ...
```

建议大家使用 `ti.cpu` 或者 `ti.gpu`。为什么呢？如果你用 `ti.x64`，那到了 ARM 的机器上就跑不了了；用 `ti.cpu`，它会自动检测你的 CPU 是什么样子的；用 `ti.gpu`，它会自动检测你的 GPU——它会先 try CUDA，然后 try Metal，然后 try OpenGL；如果什么都没有检测到，太极就会回落到 CPU 上面去运行。

```text
ti.gpu 的自动探测：
    try CUDA ──失败──► try Metal ──失败──► try OpenGL ──失败──► 回落到 CPU
```

也就是说，`ti.gpu` 会从 CUDA 一路试到 OpenGL，全都不可用就退回 CPU——所以在什么机器上都能跑起来。当然，`ti.init` 还有各种各样别的参数，后面我们会介绍。

### 数据：类型、张量，还有那个"神奇"的 loss

接下来介绍太极里面最最基本的概念：数据（data）。你运行一个程序，总得有一些数组之类的东西，来存这个程序的状态。

**数据类型**。太极支持的数据类型，和 C 非常像：有 8 位、16 位、32 位、64 位的整型，整型里面又分为带符号的和不带符号的；还有浮点数类型，有 32 位和 64 位。我自己一般来说非常喜欢用 32 位的类型：带符号的整型和 32 位浮点数。

| 类型 | 位宽 | 说明 |
| :--- | :--- | :--- |
| 整型 | 8 / 16 / 32 / 64 位 | 又分带符号与不带符号 |
| 浮点数 | 32 / 64 位 | 我常用的是 32 位浮点 |
| 布尔 | 暂不支持 | 比较的返回值都用 32 位整型来存储 |

我们现在还暂时不支持布尔类型，不支持 true/false 这种类型，所以我们所有的比较返回值，都要用 32 位整型（int32）来存储。当然，并不是所有的后端都支持所有的数据类型——毕竟，比如说 OpenGL 里面，可能就不支持 64 位的浮点数（有些可能需要 extension 才能用），或者不支持 64 位整型。文档里面有一张表，详细写了每一个后端支持什么样的数据类型，大家可以看一看。

**backend 是什么**。有同学问：backend 是什么意思？backend 就是用来执行你的程序的硬件：你的程序在 CPU 上面运行，CPU 就是你的 backend；在 GPU 上面运行，GPU 就是你的 backend。这是一个编译器里的概念，它的意义其实不是特别明确，是一个非常经常被滥用（abused）的词，有很多很多的意思——在这里，它就表示"执行计算的硬件"。

**张量（tensor）**。接下来介绍数据里面最重要的一个概念：tensor。tensor 就是张量——张量其实是一个 fancy 的名字。一般来说，你可以认为张量就是高维数组。物理里面它有协变张量、逆变张量这些别的含义，但在太极里面，它的张量没有物理含义，它就是一个高维数组。这个数组的维度可以是 0 维、1 维、2 维、3 维……你可以认为：0 维的张量就是一个标量，一维的张量是一个向量，二维的张量是一个矩阵。

这里就有一个地方可能比较 confusing：你的张量里面的每一个元素，又可以是一个标量、向量或者矩阵。所以我们在太极里面，会把"张量"和"矩阵"严格地区分开来。

> **易错点**：虽然在数学上面，矩阵有的时候会被认为是某种张量，但在太极里面，tensor 和 matrix 是两个完全不一样的概念。大家一定要注意区分，不注意区分的话，后面会非常 confused。tensor 的元素（element）可以是 scalar、vector 或者 matrix；访问 tensor 的 element，永远用 a[i, j, k] 这种下标语法。

太极里面不支持 pointer。pointer 有的时候是万恶之源：你用了 pointer，编译器就很难优化你的程序；而且你会容易触发一些 undefined behavior，程序就会因为莫名其妙的原因挂掉。

a[i, j, k] 可能给你返回一个 scalar，也可能返回一个 vector 或者一个 matrix；如果返回的是 matrix，你可能还需要再用 [p, q]，去访问返回的矩阵里面真正的一个数。这个是有一点 confusing，后面我们会给一个例子来介绍。

来看一个例子。这个例子里我们定义了四个 tensor：a、b、c 和 loss。

```python
a = ti.var(dt=ti.f32, shape=(42, 63))         # 标量张量：42×63 个元素，每个元素是一个标量
b = ti.Vector(3, dt=ti.f32, shape=4)          # 向量张量：4 个 3 维向量
c = ti.Matrix(2, 2, dt=ti.f32, shape=(3, 5))  # 矩阵张量：3×5 个 2×2 矩阵
loss = ti.var(dt=ti.f32, shape=())            # 0-D 张量：只有一个标量元素
```

a 是一个"标量张量"——这听起来可能有点 confusing：它是一个张量，这个张量有 42×63 个元素，每一个元素是一个标量。

b 这里要多花一点时间：`ti.Vector(3, ...)` 里面的第一个 3，是说这个向量有多少个元素——这是一个 3D 的 vector，所以放个 3 在这边；后面又有一个 shape，这个 shape 是 tensor 的 shape。所以 b 这个东西，是"4 个 3D vector 组成的一个张量"。c 同理：`ti.Matrix(2, 2, ...)` 说的是它的元素是一个 2×2 的矩阵，后面的 shape 是 tensor 的 shape——所以这是一个 3×5 的 tensor，里面每一个 element 是一个 2×2 的矩阵。现在大家应该清楚了。

| 张量 | 元素是什么 | tensor 的 shape | 一句话理解 |
| :--- | :--- | :--- | :--- |
| a | 标量 | (42, 63) | 42×63 个标量 |
| b | 3 维向量 | 4 | 4 个 3D 向量组成的张量 |
| c | 2×2 矩阵 | (3, 5) | 3×5 个 2×2 矩阵组成的张量 |
| loss | 标量 | ()（空） | 0-D 张量，只有一个元素 |

loss 是一个比较神奇的东西。你看它的 shape 是空的——shape 里面的东西是张量的维度，shape 是空的，说明它是一个 0-D 的张量。0-D 的张量是个什么概念？就是只有一个元素的张量。这个元素用的是 f32，说明它是一个标量。

然后我们就可以在太极里面给张量里的元素赋值了：

```python
a[3, 4] = 1          # 给 a 的 (3, 4) 这个元素设置成 1
print(a[3, 4])       # 然后可以把它 print 出来

b[0] = [1, 2, 3]     # 一次给一个向量赋一个 list，
                     # 把向量里面的值设置成这个 list 里面的值

loss[None] = 3.0     # 0-D 张量没有下标，就用 [None] 当下标
```

注意一下：大家可能会想直接 print b 的第 0 个元素——第 0 个元素是什么？是一个向量，对吧。你可能会想 `print(b[0])`，但这个我们暂时还不支持，后面我们很快就会支持，社区的同学正在非常辛苦地 work on 这个东西。

loss 那个地方一定要注意：因为它是一个 0-D 的张量，所以访问它的时候必须用下标。那怎么办呢？我们给它一个下标，叫做 None——"没有下标"，就表示 0-D 的张量。

> **易错点**：为什么不能写 `loss = 3`？写了 `loss = 3`，你就真的把 loss 的值设成 3 了——你这个 loss 以后就是 3，它不再是一个张量。这是 Python 语法的限制。后面大家程序写多了就会知道：这个地方的设计其实很不容易，但我们已经尽我们最大的努力了。

### 计算：kernel 与 function

来看一看计算。计算里面最重要的概念，就叫做 kernel。

kernel 有非常非常多的意思：操作系统有 kernel，浏览器也有可能叫 kernel，各种各样的东西都有可能。太极里面的 kernel 是什么呢？太极里面的 kernel，就是**用来计算的那个函数**。大家可以记住这个解释。

刚才我讲的其实全部都是 Python 的语法，现在讲讲太极自己的语法。Taichi kernel 里面自己有一个语言，这个语言和 Python 非常非常像，唯一的区别是：这个语言会被 just-in-time（JIT）即时编译。太极自带一个编译器，把 kernel 里面的语言编译成高性能的 kernel，这样就能摆脱 Python 运行很慢的问题。

这个语言是静态类型的，而且是 lexically scoped——它不像 Python 那样：Python 的 scope 是以 function 为单位的；太极的 kernel 里面，scope 更紧一点，是以 block 为单位的。kernel 会被自动地并行，并且在某些情况下是可微分的。

kernel 必须被 Taichi 认出来。你要让 Taichi 知道这个函数是 kernel，必须给这个函数前面加一个 decorator，就是 `ti.kernel`。有了这个 decorator 以后，太极的编译器就会把这个函数拿到，进行编译；编译以后，就把这个跑得很慢的函数，替换成一个跑得很快的、并行跑在 CPU 或者 GPU 上的高性能函数。

如果你想给 kernel 传一些参数的话，请一定记得给它加上参数类型——毕竟太极是一个强类型的东西。

我们这边有两个例子。第一个例子是 hello world——你会看到它和 Python 非常非常像。但为了让它和 Python 非常非常像，我们花了很多精力：要不然大家学起来负担就比较高了，对吧？重新学习一门新的编程语言，是要花很多时间的。现在基本上你会 Python，那你上来就可以写太极——我觉得这是一个非常好的设计取舍。

如果你要让 kernel 有返回值，那请一定记得给返回值也加上一个数据类型的 hint。比如 calculate 这个函数返回的是一个 32 位整型，那你 define 它的时候，就要给它写明返回值的类型：

```python
@ti.kernel
def calculate() -> ti.i32:   # 返回值一定要加类型 hint
    ...
```

刚才讲了，kernel 其实也是函数，function 也是函数，它们有什么区别呢？其实区别非常简单：太极的 kernel 可以被 Python 直接调用，但是太极的 function（`ti.func`）不能够被 Python 调用；kernel 里面可以调用 function，function 里面也可以调用其他的 function。这个大家可以通过写代码去仔细体会，它到底是一个什么行为。当然，function 这边也需要一个 decorator，去指定它的函数类型。

写过 CUDA 的同学可能会一下子就反应过来：function 其实是 device function，对吧？kernel 这边，其实就是 CUDA 里面的 global function。这么说基本上是对的——但有的时候，一个 ti.kernel 会被拆分成好几个 CUDA 的 global kernel，所以我们中间还是有一些抽象的。不过如果你学过 CUDA，基本上确实可以认为：一个是 device，一个是 global。

那么太极的 function，是会被强行 inline 的——现在我们这个实现稍微有点挫（强行 inline），但大部分情况下绝对是够用的。

### 和 Python 保持一致的语法细节

太极的设计原则之一，就是尽量和 Python 保持一致——你只要会 Python，就可以写太极。这一节把写仿真程序时最常用的几样东西过一遍。

#### 常用数学函数

写程序时经常会用到一些常用的数学函数，比如 `sin`、`cos`、`arcsin`、`arctan`，还有 `atan2`、`floor`、`ceil`，这些都是支持的。

其中 `atan2` 要特别留意参数顺序。

> **提示**：`atan2` 的参数顺序是 **y 在前、x 在后**，写作 `atan2(y, x)`。这是数学函数里最容易踩的一个坑，写的时候别把顺序弄反。

还有一个很特殊的函数 `ti.random`，用来生成随机数。它的返回值范围由你的数据类型决定：

| 数据类型 | ti.random() 的返回范围 |
| :--- | :--- |
| int32 | 0 ~ 2147483647 之间的随机整数 |
| uint16 | 0 ~ 65535 之间的随机整数 |
| float32 | 0 ~ 1 之间的随机浮点数 |

同一个 `ti.random`，你给 int32，它就在 0 到 2147483647 里取一个随机整数；给 float32，它就返回 0 到 1 之间的随机浮点数。

#### 内建函数与幂运算

有一些函数是 Python 自带的，太极直接沿用，不用加 `ti.` 前缀。`abs` 求绝对值——它是 Python 的关键字，所以直接写 `abs` 就行，不用写 `ti.abs`，这样比较方便，也符合"和 Python 尽量接近"的原则。`int` 和 `float` 负责类型转换，把输入 convert 成整数或者浮点类型。`max` 和 `min` 则像 Python 一样支持超过两个参数，`max(x, y, z)` 随便你想怎么弄都可以。

幂运算就是 `x ** y`，即 x 的 y 次方——同样和 Python 保持一致，最后得到的就这么个设计。

#### 除法：Python 3 改过的规矩

除法这里要注意一下，因为 Python 3 把除法的含义给改了。如果你以前写 C++ 或者别的语言，`a / b` 的结果取决于 a 和 b 是整型还是浮点型：a 是 5、b 是 2，`a / b` 会告诉你 2；如果 a 是 5.0、b 是 2.0，两个都是浮点数，`a / b` 就返回 2.5。这是 C 语言里的行为。

Python 不一样：`a / b` **永远返回浮点数**。那想要整数商怎么办？Python 3 为此新造了一个符号——整除 `a // b`，我觉得还挺有意思的。太极为了保持和 Python 的统一性，把这些行为全部沿用。这样你只要会 Python，就可以写太极。

#### 链式比较

Python 还有一些有意思的东西，比如链式比较（chained comparison）。太极支持到什么程度？`a < b <= c != d` 都可以——这个例子给得挺极端的，确实挺乱的；平时我们只写 `a < b`，最多情况下写个 `a < b < c` 就到头了。但你如果真的要写很复杂的 chained comparisons，太极也是支持的。

### 小矩阵与大张量

说到物理仿真，很多时候就得用上线性代数了。

#### matrix、vector 与 tensor 的分工

`ti.matrix` 是用来做小矩阵的。前面讲过，tensor 表示很大的高维数组；matrix 虽然你也可以用数组去理解它，但它只能是一个非常非常小的数组。什么概念？3x3、4x4、1x3、3x1 这种属于小矩阵；你要是搞个 10x10，那就要考虑一下要不要用 tensor 来表示了。因为太极里面有些机制决定了：你用一个很大的数组，它会非常慢；但是小数组，太极会非常非常快。

vector 和 matrix 本质上是一样的，唯一的区别是 vector 只有一列——vector 一般被认为是列向量，所以它就是只有一列的矩阵。

#### 两种乘法，千万别混

这里有一个要非常非常注意的地方，大家一定要小心：**逐元素（element-wise）乘积**和**矩阵乘积**是两回事。

矩阵乘积，就是数学上两个矩阵相乘的矩阵乘法；而逐元素乘积，是把 a 和 b 对应位置的元素取出来、相乘，给你一个新的矩阵。在太极里这两种乘法是不同的运算符：`*` 是逐元素乘，`@` 是矩阵乘法。

> **易错点**：光在这听一遍可能有点干枯无力，这个大家最好得自己试一试。这个点如果不注意的话，很容易写出 bug。

#### 常用矩阵运算

常用的矩阵运算有一批。`transpose` 求转置，`inverse` 求矩阵的逆。但要注意：**这些所有的运算全部都不是 in-place 的**——不是 `a.transpose()` 会把 a 本身给转置掉，而是返回给用户一个被转置过的 a。

`trace` 求矩阵的迹，就是对角线元素之和——中文好像就叫"迹"，痕迹的迹。`determinant` 求行列式，各种数据类型都可以。`normalize` 只对列向量有用，它把向量除以自己的模长再返回。这里我还漏了一个：`a.norm`——对向量来说，它会返回这个向量的 2-范数，也就是它的长度。

你想把矩阵里所有元素都做一遍类型转换，可以用 `a.cast`，把它转化成另外一个数据类型。我们也支持一些简单小矩阵的常规操作，比如极分解（polar decomposition），还有 SVD。

还有一个很方便的用法：如果你想给 a 里的每一个元素都取 sign、得到一个新的矩阵，直接把 `ti.sign` 作用到 a 上面就行。这是一个 element-wise 的操作——**所有的标量运算符都可以直接在矩阵上面运算**，这个就比较方便了。

### 两种 for 循环：并行的核心

接下来要讲一个非常重要的东西：并行 for 循环。太极里面有两种 for 循环。

#### range-for：最外层自动并行

第一种叫 range-for loop，它和 Python 的 for loop 基本上行为没有任何区别，就是 `for i in range(n)` 这种。这里一定要非常注意的一件事是：太极里最外层的 range-for loop 会被自动并行运行。for 可以嵌套，但自动并行的只有最外层。

> **结论**：只有最外层的 for 会被自动并行；内层循环在每一个外层线程里串行执行。

看第一个例子 fill。先回忆一下：kernel 是 Python 可以调用的，function 是 Python 不能调用的，function 可以被 kernel 调用。fill 是一个 kernel，它最外层是 `for i in range(10)`——它就会并行地对 0 到 9（注意这个 10 是不包含的，是 0123456789）的所有元素做操作，操作是给 `x[i]` 加上 i。后面还有一段小循环，算一个 0 到 4 所有数的和：由于它是第二层 for 循环，它不会被自动并行，它是在每一个第一层循环的线程里面串行执行的。

```python
@ti.kernel
def fill():
    for i in range(10):      # 最外层：自动并行，遍历 0~9（不含 10）
        x[i] += i
        s = 0
        for j in range(5):   # 第二层：不并行，在每个并行线程里串行执行
            s += j           # 累加 0~4
```

而且"最外层"指的是最外层的 scope。比如一个 foo 函数，它的顶层语句就是一个 for，那这个 for 会被自动并行；但你如果在 for 外面再嵌套一个 if，它就不会被自动并行了，会被认为是串行的。做过并行编程的同学应该很能理解为什么会这样设计。

#### ti.ndrange：多维的 range

第二个例子 fill_3d 里出现了一个很有意思的函数 `ti.ndrange`。它还是一个 range-for loop，但这个 range 非常特殊：不是一个下标，而是三个下标。`for i, j, k in ti.ndrange((3, 8), (1, 6), (0, 9))` 的意思是：i 从 3 到 8，j 从 1 到 6，k 从 0 到 9——当然 8、6、9 这些末端点都是不包含的。这个三维的 range-for 同样是自动并行的，然后你可以做操作，比如按三个下标算出一个值，写进 `x[i, j, k]`。

```python
for i, j, k in ti.ndrange((3, 8), (1, 6), (0, 9)):
    # i ∈ [3, 8)，j ∈ [1, 6)，k ∈ [0, 9)，末端点都取不到
    ...                      # 对每个 (i, j, k) 做操作
```

#### struct-for：遍历张量的每个元素

第二种 for 循环叫 struct-for loop。这个东西非常常用——特别是你要做任何稀疏计算的时候，基本上全部都靠 struct-for。它是干啥的呢？它会遍历张量里面的所有元素。刚才讲的例子全部都是稠密张量，但太极里有一个非常有特色的功能叫做**稀疏张量**——这一讲不会展开，因为它挺复杂的，后面再讲。

看这个例子，这个程序是可以跑的，大家可以自己去跑一跑、玩一玩。顺便说一下：课件是 PDF 格式的，如果你直接复制粘贴里面的代码，格式上会有点问题、不能正常运行；课程结束以后我会给出里面所有能跑的例子的 Python 源文件，这样大家跑起来就方便一点。

这个程序先初始化——做任何太极操作之前，记得一定要初始化——然后定义了一个 tensor，叫 pixels，里面每一个 element 是一个 32 位浮点数 f32，shape 是 640 乘 320。kernel 叫 paint，里面做了一个操作：`for i, j in pixels`。什么意思？pixels 是一个 tensor，tensor 是有下标的：从 (0, 0)、(1, 0)、(2, 0)，一路列到 (639, 319)。也就是说，i、j 会**并行遍历这个 tensor 里面的所有下标**。

```python
@ti.kernel
def paint():
    for i, j in pixels:      # i、j 并行遍历 pixels 的所有下标
        ...                  # 对每个像素做操作
```

这个 pixels 是稠密张量，所有下标都是 active 的；如果你是稀疏张量，struct-for 就只会遍历其中 active 的部分——这个后面我们会详细介绍。

### 课间快问快答

讲到这里我看同学有一些问题，先回答几个现在就能解答的，免得后面越来越 confusing。

**kernel 可以调用 kernel 吗？** 这是个很好的问题。kernel 不能调 kernel，但是 function 可以调 function。所以调用关系是一条链：

```text
Python 代码 ──可以调用──> @ti.kernel ──可以调用──> @ti.func ──可以调用──> @ti.func
```

读图说明：链条上的每一环都成立，链条之外都不行——kernel 不能调 kernel，function 也不能被 Python 直接调用。

**为什么有的 kernel 是串行的？** 其实大部分情况我们希望 kernel 是并行的，但有的时候有的东西没法并行，所以就有了串行的情况。

**串行和并行到底是什么意思？** 有同学打了个比方：串行是一个人搬完 100 块砖，并行是 100 个人一起搬完 100 块砖——差不多就是这个意思。并行就是有很多个 worker（工作者），一起同时做一个高度重复性的工作。这也正是 GPU 非常适合做并行的原因：GPU 的 thread 数目非常多。

**for 里面有前后依赖怎么办？** 这个问题问得很好。比如那个求和的小循环——`s = 0`，然后 `for j in range(5): s += j`——如果把它放到最外层，它就会被并行，但循环体对外面的 s 有依赖。怎么办？说多了都是泪：我们在编译器里面做了非常繁琐的变换，使得你感觉不到这是一个问题。编译器背后做了很头疼的事情，让它可以自动处理——所以大家不用担心。

### 原子操作：并行写入的记账规则

刚才说到太极里很多操作都是并行的，那我们很多时候就需要做原子操作。在太极里面，**augmented assignment（`+=` 这类复合赋值）自动就是原子操作**。所以如果你要并行地修改全局变量，确认一下你把 augmented assignment 用好了就行。

举个例子：想把 x 里的所有元素求和，有三种 approach。

方式一，`total[None] += x[i]`，这是可以的。为什么用 `total[None]` 而不是直接 `total`？因为 total 是一个 0 维的 tensor，而在太极里面，**访问 tensor 永远都要用方括号**。这个大家得记住——这不是一个最理想的设计，但是没有办法的办法。

> **易错点**：0 维张量也要写成 `total[None]`，不能裸写 `total`。在太极里访问 tensor，永远都要带方括号。

方式一为什么对？因为 `+=` 在太极里面是原子的。

方式二，`ti.atomic_add(total[None], x[i])`，也是 OK 的，这同样是一个原子操作。它和方式一有什么区别？`atomic_add` 会返回一个值——total[None] 在进行这次 atomic add 之前的值，相当于一个 read-modify-write 操作。方式二提供了更多的可控制性，但是没有方式一简洁。

方式三就不太对了：`total[None] = total[None] + x[i]`。由于你没有用 augmented assignment，就得先把数读进来，加上之后再写回去。问题在哪？在你把数读进来、还没写回去的过程中，别的 thread 可能也已经做了"读进来、加上、写回去"这一套——你最后的结果就不对了。因为它不是原子操作，就会有 data race，data race 就会出问题。

```python
total[None] += x[i]                    # 方式一：+= 自动原子，最简洁
ti.atomic_add(total[None], x[i])       # 方式二：显式原子，返回加之前的旧值
total[None] = total[None] + x[i]       # 方式三：错误！非原子，有 data race
```

### Taichi scope 与 Python scope

接下来讲一个非常重要的概念：Taichi scope 和 Python scope 的区别。刚才提到很多太极的 operation，既可以在 kernel 里进行，又可以在普通的 Python 里进行，所以这里得介绍两个有点冗杂的术语。大家可能比较讨厌术语，但是有了术语，我们把说法定下来，它就指这个意思。

> **定义**：任何被 `@ti.kernel` 以及 `@ti.function` 修饰的函数的函数体，叫做 **Taichi scope**；任何不在 Taichi scope 里面的代码，都是 **Python scope**。一份 Python 代码，要么是 Taichi scope，要么是 Python scope。

区别有两条。第一，Taichi scope 里面的代码会被太极的 compiler 编译，并且在并行设备上运行。第二，Python scope 里面的代码就是普通的 Python 代码，由 Python interpreter 去执行——所以你在 Python scope 里可以 do whatever you want：比如你可以 import pytorch，在里面做一些 pytorch 操作，然后把 pytorch 的结果喂给太极，再到 Taichi scope 里去做太极的操作。

在 Taichi scope 里也可以玩 tensor，写法和在 Python scope 里操作非常非常像，但 Taichi scope 里还有个更好的地方：你去 print 一个 vector 或者 matrix 的时候，它会直接把整个 vector 或 matrix 打印出来。这一点是彭于斌很给力地帮忙实现的。这个功能非常重要——以前没有"print 整个 vector 或整个 matrix"这个功能的时候，大家都得手动把 vector 和 matrix 的每个 item 打出来，非常麻烦；现在就方便了。整个太极框架也在大家的努力下变得越来越易用。

不过要注意：因为你是在并行设备上 print，print 不一定 follow 它在代码里面的顺序。这很容易理解——你如果有 20 台打印机一起往外打印东西，谁先打印出来就很难说了，它们是并行的，顺序没有保障。但同一个 thread 内部的顺序是保证的，thread 之间的顺序没有保证。大家记得这个就可以。

> **注意**：Taichi scope 里 print，单个 thread 内部的顺序有保证；thread 之间的先后顺序没有保证。

### 程序的三个阶段

一个太极程序有好几个 phase——phase 就可以认为是阶段。第一个 phase 叫 initialization，初始化；第二个 phase 叫 tensor allocation，张量分配；然后是 computation，计算。

在 tensor allocation 阶段，你可以用 `ti.var` 定义一个标量的 tensor，用 `ti.vector` 定义一个矢量的 tensor，用 `ti.matrix` 定义一个矩阵的 tensor。**你只能在 tensor allocation 这个 phase 里定义 tensor**，一旦进入 computation phase，就不能再定义新的 tensor 了。这是一个有点局限性的地方，后面我们会考虑把这个局限移除掉，但大家现在还是要记住：tensor allocation 和 computation 中间有一个明确的分隔。

那什么时候进入 computation phase 呢？你第一次 launch 一个 kernel，或者你在 Python scope 里面访问一个 tensor 的时候，太极就从 tensor allocation phase 进入了 computation phase。一旦进入，就不能再 allocate 新的 tensor 了。

当然，你如果觉得需要砍掉重来，可以调用 `ti.reset()`，它会把整个东西全部砍掉重来，然后你重新 `ti.init()`、重新执行一个新的太极程序。不过一般情况下大家是用不到 `ti.reset()` 的——程序结束的时候，自动就重来了。

```text
初始化(ti.init) ──► 张量分配阶段 ────────────────► 计算阶段
                    只有这里能定义张量：
                    ti.var / ti.vector / ti.matrix

                    进入计算阶段的时机：
                    · 第一次 launch 一个 kernel
                    · 在 Python scope 里访问 tensor

                    进入后不能再分配新的张量
                    （想全部砍掉重来：ti.reset()）
```

读图说明：流程是单向的，张量的"定义权"只属于中间那个阶段；跨进计算阶段就回不来了，除非用 `ti.reset()` 全部推倒重来。

第一行，每一个太极程序的第一行都应该是 `import taichi as ti`。然后初始化太极，接着进入 tensor allocation，定义一个 tensor 叫 pixels——640 乘 320 个 element，每一个 element 是一个 32 位浮点数 f32。

### 调试太极程序

最后讲一个非常重要的技能：怎么调试一个太极程序。首先，你可以用 print 去调试；也可以把结果写到太极 tensor 里，然后在 Python 里 print 出来——这些都可以。这里讲一个自动的调试模式：初始化太极的时候，把 `debug` 设成 True，也就是 `ti.init(debug=True)`，它就会做一些额外的检查。

比如有一个叫 shift 的 kernel，干的事是把 `b[i + 1]` 拷贝到 `a[i]`。看起来好像没有什么问题，但你仔细想想：当 i 等于 9 的时候，i 加一就是 10，你就会访问 `b[10]`——可是 b 这个 tensor 的范围只有 0 到 9。这个时候，其实就是数组访问越界了。

```python
@ti.kernel
def shift():
    for i in range(10):
        a[i] = b[i + 1]      # i = 9 时访问 b[10]：越界！
```

那太极为什么不默认做检查？非 debug 模式下，出于性能的原因——你不可能每一次 tensor 访问都去检查一下有没有越界，那你的程序慢成狗了。所以只有在 debug mode 的情况下，才会去检查数组有没有越界；反正你在 debug，慢一点也没有关系。在 debug 模式下跑这个程序，就很容易发现程序里的这个问题。这就是数组越界检查的一个很快速的方法。

### 再答一波问题

**tensor 可以套 tensor 吗？** 暂时不行。不过想一想：如果你想要一个三维 tensor 里面再套一个 tensor，那为什么不直接 allocate 一个三维 tensor 呢？为什么有必要用 tensor 套 tensor？这是一个奇怪的需求，但这个问题本身非常好。相关的特性正在开发，还没有完全搞定。

**meta-kernel 是什么意思？** meta-kernel 就是说 kernel 里面可以随便定义各种各样的操作。对比一下：如果你用 TensorFlow 或者 PyTorch，一个 kernel 能做什么？把两个 tensor 加起来、把两个 tensor 乘起来——就这点事。kernel 里内容这么简单，会有什么问题？计算非常少，访存非常多，你的程序完全就是在被访存支配。用 meta-kernel 的话，一个 kernel 里的计算就多得多、访存相对少，这就提高了计算强度，让 arithmetic intensity 变得更高。

**太极能和 Python 生态的其他框架结合吗？** 可以，我们有 PyTorch 的接口。

**除了 GitHub 上那几个 demo，还有别的 demo 吗？** 其实是有的，后面我会讲。

**太极支持多 GPU 吗？** 暂时还不支持。不过之前提到的 2020 年那篇多 GPU MPM 论文是支持多 GPU 的，大家可以去看那篇 paper。至于怎么自动地用一个编译器搞定多 GPU——还没有，我还没有想好怎么去实现，这是一个很好的研究问题。

在论坛里贴代码也是常见问题。论坛其实是 Markdown 格式的：在代码的开头和结尾各打三个反引号——就是键盘上 Tab 上面、Esc 下面那个符号——并在开头那行写上 `python`，代码就会被自动语法高亮，看起来非常舒服；写 C++ 的话标 `cpp` 也可以。不加这三个反引号的话，贴出来的代码会非常杂乱，缩进都没了，所以大家记得加上。

还有两件小事提前说。想输出一个动画发到论坛上炫一下的，这节课后面会提到新版本的太极怎么导出 GIF 文件上传论坛。觉得编译速度比较慢的，可以把高级优化关掉——高级优化本身也是比较耗时的优化，关掉之后编译会相对快一点：`ti.core.toggle_advanced_optimization(False)`。

### 两个视角：随波逐流的小纸船与钉死不动的木桩

说到模拟基于物理的动画里的各种介质，就不得不谈到两个视角：拉格朗日视角和欧拉视角。这两个词听起来好像非常艰深，但是其实非常容易理解。

所谓拉格朗日视角，就是我们去模拟介质的时候，想象自己在介质里面塞了很多很多个随波逐流的小纸船，这些小纸船会跟着介质一起移动。只要你的节点是随着材料一起动的，这就是拉格朗日视角。视角里的每个节点，你可以认为是一个很小的 sensor（传感器），它不断地检测自己的位置和速度。

欧拉视角就不一样了：放在那里的 sensor 永远都不移动，你可以认为它们是一些打在水里的木桩。这些木桩上的 sensor 不断检测的是另一件事——如果我站在这儿不动，那么穿过我的材料，它的速度是多少。

有个口诀：**拉格朗日方法，随波逐流**。其实你只要记住这个区别就可以了。

用温度计来打个比方：温度计就可以认为是一个 sensor。如果你的温度计跟着水一起移动，那它就是一个拉格朗日式的温度计；如果你的温度计插在水里一点也不动，那它就是一个欧拉视角的温度计。这两个概念后面还会再提，这里只做一个最初步的介绍。

> **定义**：拉格朗日视角——传感器跟着材料走，随波逐流，检测自己的位置和速度；欧拉视角——传感器固定不动，检测穿过该点的材料速度。

通常来说，用拉格朗日视角的时候你很可能在用粒子，用欧拉视角的时候你很可能在用网格——但这不绝对：拉格朗日的三角形网格、方形的规则网格都是有可能的。当然最最常见的情况，还是拉格朗日配各种各样的粒子。

| | 拉格朗日视角 | 欧拉视角 |
| :--- | :--- | :--- |
| 传感器像什么 | 随波逐流的小纸船 | 打在水里不动的木桩 |
| 检测什么 | 自己的位置和速度 | 穿过该点的材料速度 |
| 常用表示 | 粒子（也可用三角网格、规则网格） | 背景网格 |
| 位置存不存 | 每个粒子额外记一个位置 | 不记，由下标算出 |

举两个例子。拉格朗日这一侧，比如基于 position based dynamics（基于位置的动力学）的模拟：各种各样的粒子通过各种方式连接起来，可以表示降落伞的绳子——降落伞上面其实拴着一只兔子，图形学里大家很喜欢用斯坦福三维扫描出来的兔子来当例子；粒子也可以用来模拟水，能模拟各种各样的东西。欧拉这一侧典型的例子是烟雾模拟：用一张背景网格，网格上的每一个点表示穿过这个点的流体的速度。

基于粒子的模拟里，每个粒子会携带它自己的速度和位置。这就带出一个常见的对比：位置到底记在谁身上？

> **易错点**：欧拉的网格里的每个点，我们不记它的位置——因为位置很容易算出来，根据它的 $i, j, k$ 下标乘上网格间距 $\Delta x$，就知道这个格点在什么地方；但拉格朗日的粒子会随着被模拟的介质不断地移动，所以必须在粒子上面额外记一个位置。"存不存位置"本身就是两种视角的一个直观差别。

### 弹簧质点系统能做什么

今天我们主要讲两个东西：一个叫 mass-spring system，弹簧质点系统；另一个是 SPH，后面会提到。

弹簧质点系统是一个非常非常简单的模型，但是非常非常有用，可以模拟很多很多有意思的东西：可以用它来模拟布料，可以模拟头发，可以模拟各种弹性的材料。比如有一只小狗，被非常"残忍"地用弹簧质点模型表示了出来，还有几个点把它固定在空间中。

如果用弹簧质点模型来模拟布料，那就相当于用很多很多的弹簧把一些点连起来——而你怎么连接这些弹簧，其实就决定了你的布料的性质。在这个基础的布料表示里，每一个红点是一个质点，每一条白线是一根弹簧。这个其实非常好理解，大家小时候应该都玩过弹簧；后面我们会给出更数学一些的表述。

弹簧质点模型在游戏里也非常有用。我小时候就玩过一个游戏，叫《粘粘世界》：让你用弹簧质点模型把点不断连接起来，搭起一座桥——我记得当时有两种模式，一种是要搭到一个目的地，另一种是越搭越高。搭高了以后，下面的弹簧受到的力就会越来越大，要一直保持平衡并不容易，是个挺有意思的游戏。最近又有一个游戏，我自己其实没玩过，网上视频很多，看起来也挺有意思：它里面的物理也可以认为是一个比较简单的弹簧质点模型——用一些不锈钢的材料把结构不断连起来，使得你的车能够从左边顺利地开到右边去。我小时候好像玩过很多类似这样的游戏。

### 数学：胡克定律加牛顿第二定律

刚才看了弹簧质点系统跑起来的效果，现在把背后的数学摊开。其实它非常简单，大家不要被公式吓到——说白了就两个东西：胡克定律和牛顿第二定律。

先看胡克定律。质点 $i$ 受到的、来自与它相连的质点 $j$ 的弹簧力是

$$f_{ij} = k \left( \lVert x_i - x_j \rVert - l_0 \right) \frac{x_j - x_i}{\lVert x_i - x_j \rVert}$$

$k$ 是弹簧的 stiffness；标量部分是"两个质点当前的距离减去弹簧的静止距离"做出的差；前面算出来是个标量，还得再乘一个单位向量——方向从 $i$ 指向 $j$。乘起来就得到两个质点之间弹簧的受力：拉长了（距离大于静止长度）这个力就把 $i$ 往 $j$ 的方向拉，压缩了（标量为负）就把 $i$ 往外推——弹簧总是想把两端拉回静止长度。

对于其中的一个质点，我们得把它所有相邻质点给的力都求和，加起来就得到质点 $i$ 受到的所有外力——当然这边还有一个重力 $mg$，公式里我没写出来，代码里有。

有了力，就上牛顿第二定律：$f = ma$，$a = f/m$，所以速度的导数等于力除以质量；再加上最后一行——位置的导数等于速度，整个模型就齐了：

$$\dot{v} = \frac{f}{m}, \qquad \dot{x} = v$$

在 simulation 里，大家经常写的是"质量的倒数乘以力"。因为在模拟的计算里，乘法比除法要更加廉价一点，所以一般会把质量提前取好倒数，需要用的时候再把它们乘起来。

### 时间积分：把连续方程装进计算机

刚才写出来的方程全部都是连续的，相当于一坨常微分方程。要在计算机里表示它，就遇到一个问题：计算机里的时间全部是离散的，可用的计算资源也全是离散的，你不可能取一个无穷小的时间单位来记录这个系统。那大家一般怎么办呢？取一个 $\Delta t$，比如 $10^{-3}$、$10^{-4}$ 这样比较小的值，具体根据物理系统的各种参数来取。一般来说大家会喜欢选一个比较大的 $\Delta t$：$\Delta t$ 比较大，模拟同样长时间的物理过程就跑得比较快，所以 $\Delta t$ 一般认为是越大越好——当然大了以后又会有很多不稳定性的问题，这个我们后面会提到。

做了离散化以后，$v$ 就不再是连续的了：记 $v_t$ 为 $t$ 时刻的 $v$，$v_{t+1}$ 就是下一个时间步的 $v$。

有了这个记号，最简单的想法叫前向欧拉法（forward Euler）：根据现有的状态，直接推测以后的状态。可以得到这么一组简单的公式：

$$v_{t+1} = v_t + \Delta t \, a_t, \qquad x_{t+1} = x_t + \Delta t \, v_t$$

这应该很容易理解：$v$ 是 $x$ 的导数，我们其实向前累进了一步。不过 forward Euler 大家用得其实比较少了，用得比较多的是 semi-implicit Euler，有的时候大家也叫它 symplectic Euler。它同样是"根据现有状态推测未来"的一种时间积分方式，和 forward Euler 唯一的区别在位置更新这一行：forward Euler 用的是 $t$ 时刻的速度，semi-implicit Euler 用的是 $t+1$ 时刻的速度：

$$v_{t+1} = v_t + \Delta t \, a_t, \qquad x_{t+1} = x_t + \Delta t \, v_{t+1}$$

这个看起来是非常非常小的差别，但是其实很多时候，它会带来本质的准确性提升。semi-implicit Euler 之所以有时又叫 symplectic Euler，是因为它有一些守恒的性质——那是在哈密顿系统里做的理论分析。

再高级一点，有的时候大家会用 backward Euler，它通常会结合成隐式（implicit）的形式——这个后面我们会继续讨论。今天大家只要记得 semi-implicit Euler 就行了。这两个公式其实非常简单，直觉就是：假设在 $\Delta t$ 这么小的间隔里 $v$ 和 $x$ 都是常数，那就朝前做匀速直线运动嘛。

### 一个 substep 在做什么

用 semi-implicit Euler 来实现弹簧质点系统，其实非常容易，就三步：首先计算新的速度；计算完新的速度以后，和地面做一次碰撞；然后用新的速度来计算新的位置。看代码的话，可能也就 20 行。这个 kernel 叫 substep，表示把 simulation 朝前推进一步。

为什么叫 substep？因为做 simulation 的时候，你的 time step size 一般不会和你实际展示出来的 time step 一样：玩游戏的话，帧率一般是 60 FPS；做电影的话，一般是 24 FPS。游戏和电影里帧与帧之间的间隔，也就是展示的 step size，一般是 1/60 或者 1/24 秒。但在模拟里，很多时候你的 time step 取不到这么大的数值，只能取一个非常非常小的值。那怎么办？把这么一帧分成若干个 substep，在每个 substep 里用 semi-implicit Euler 往前推。

这个 substep kernel 非常简单，它做的事如下：

```text
对每个质点 i：
  阻尼：对 v_i 做一次指数衰减
  求合力：重力 m*g
          再遍历其余质点 j（rest_len 为 0 表示两点间没有弹簧，
          非 0 表示有弹簧），按胡克定律累加弹簧力
  用合力更新 v_i                     <- 半隐式欧拉第一步
  与地面碰撞：发现有下穿地面的趋向，就把 v_i 的 y 分量清零
  把 v_i 累加到位置上，得到新的 x_i   <- 半隐式欧拉第二步
```

kernel 一上来是一个 $n^2$ 的循环：先把所有的 $i$ 枚举一遍，做一下 damping；计算总受力的时候，先算 $g = mg$（重力乘上粒子的质量），再去枚举其余所有的粒子、看它们之间是不是有弹簧连接——有就按照胡克定律的公式算这个粒子的受力。力算出来以后，用力来更新速度——这就是 semi-implicit Euler 的第一步。

那为什么碰撞要放在中间？这其实是有学问的。如果不在这里处理，速度的 y 分量可能还是负的，直接拿它去更新位置，粒子就会陷到地底下去，看起来就非常不自然。所以对弹簧质点系统，我们一般是在计算完力和速度之后，立刻和地面做一次碰撞——这个时候一旦发现粒子有陷到地底下的趋向，就立刻把它的速度的 y 分量设成零。接下来就很容易了：直接把速度累加到位置上面去，就得到了新的位置。

### 显式积分器：好写，但容易爆炸

刚才提到，semi-implicit Euler 是一个显式（explicit）的时间积分器；那还有很多隐式的时间积分器，它们有什么区别？这门课后面会讲到很多很多这样的积分器，一次全讲大家肯定听得比较无聊，所以今天就讲一些比较初步的东西。

显式积分器的一大特点，是未来的状态只依赖于过去的状态——所以它非常非常容易实现：整个程序就是一个递推，从以前的时间直接推到未来的时间。显式积分器有很多种，除了讲过的 forward Euler 和 semi-implicit Euler，还有更高阶的显式格式，比如 RK2、RK3、RK4，它们的数值精度会更高一些。

但显式积分器有一个不太好的特点：非常容易爆炸。什么叫爆炸？我刚才其实已经演示过了。有一个公式：$\Delta t$ 必须满足

$$\Delta t \le \sqrt{\frac{m}{k}}$$

看这个公式：粒子的质量变得越大，它能允许的 $\Delta t$ 就越大；粒子质量非常小的时候，限制就更紧，允许的 $\Delta t$ 就变小。反过来，弹簧的刚度 $k$ 越大，允许的 $\Delta t$ 也越小——所以显式方法对特别硬的材料其实并不适合。

拿刚才的 demo 算一笔账：$m = 1$、$\Delta t = 10^{-3}$，可以推出允许的 $k$ 大概是 $10^6$。演示里 stiffness 本来是 1 万，我一路把它往硬里调：到 50 万的时候弹簧已经越来越硬，接下来每按一下"更硬"的键都有可能爆炸——我猜可能快了，哈哈，果不其然。60 万其实已经接近预测的 100 万了（前面还差一个常数），系统处在一种勉强稳定的状态：有些时候还能勉强保持稳定，你一不小心它就挂了。把 stiffness 减到临界值以下，基本上就不会发生爆炸了。要注意这个临界值不是非黑即白的：靠近它之后，有时只在特定的配置下才会出问题——因为公式里的 $k$ 和 $m$ 本来就是取的一些有代表性的近似值。

这个公式怎么来的？弹簧的振动角频率是 $\omega = \sqrt{k/m}$，而 $\Delta t \le \sqrt{m/k}$ 正好是它的倒数（差一个常数）。直觉是说：如果你在一个 time step 里面，系统本来应该震荡一个周期，但是你现在没有完全 capture 它——比如系统震荡了两个周期，而你只有一个 time step——这种情况下往往就会出问题。这是一个比较直观的理解；严格的推理方法也有，forward Euler 和 semi-implicit Euler 都可以用矩阵方法来分析数值稳定性，大家可以去看各种文献，数值分析的书里很容易找到这样的内容。

> **提示**：$\omega = \sqrt{k/m}$ 和 $\Delta t \le \sqrt{m/k}$ 互为倒数——步长的上限由系统里最快的振动决定：材料越硬、质量越轻，振动越快，步长就得越小。

### 隐式积分器：拿复杂度换大步长

显式之外，很多时候大家会用隐式（implicit）时间积分器，比如 backward Euler 或者中点法——中点法我们后面会讲到。为什么叫它"隐式"？因为它有一个特点：你的未来不只依赖于你的过去，还依赖于你的未来——这有点像鸡生蛋、蛋生鸡的问题。未知数会依赖于未知数，你就得去解一个线性系统。

通常来说，implicit solver 更难实现；一个 time step 里面的每一步也更加昂贵。但它有好处：每一步能容忍的 time step 可以更大。

那 implicit 是不是一定就好？那倒也不一定。它首先有一个很大的缺点：难以实现——难以实现就意味着难以优化。程序写得很复杂的话，你就做不了各种计算机底层的优化，比如向量化、在 GPU 上用 shared memory（共享内存）之类的操作。所以"复杂"是 implicit solver 一个很大的问题。另一个问题在于权衡：由于它的每一个 time step 更贵，你就得衡量——到底是 time step 变大带来的加速更多，还是每一步变昂贵带来的拖累更多？这两个会 fight against each other，互相打架，你得看哪一个方面更胜出，这就决定了这个 solver 到底是变快了还是变慢了。它还有一个问题：implicit solver 有时会带来额外的 numerical damping，甚至出现 locking 的问题。所谓 locking，比如你用有限元去模拟一件衣服：当衣服非常硬的时候，implicit Euler 再加上各种 damping 的问题，这件衣服就会变得像一块石头一样——没有人想穿一件非常坚硬的衣服。

所以 implicit 在很多时候有它的好处，但也有它的坏处。

### 弹簧质点系统的隐式积分：三个公式

最后来看弹簧质点系统的 implicit time integration 应该是什么样子——这是对 backward Euler 的描述。

公式一：还是和之前一样的假设，这个时间步内的速度是恒定的——但注意，$x_{t+1}$ 依赖的是 $v_{t+1}$：

$$x_{t+1} = x_t + \Delta t \, v_{t+1}$$

公式二：下一个时间段的速度，等于上一个时间点的速度加上 $\Delta t$ 乘这个时间段内的加速度——注意这个加速度用的是 $x_{t+1}$ 时候的力：

$$v_{t+1} = v_t + \Delta t \, m^{-1} f(x_{t+1})$$

一依赖于二，二又依赖于一。怎么办？先做一步化简：把公式一代入公式二，就得到公式三：

$$v_{t+1} = v_t + \Delta t \, m^{-1} f(x_t + \Delta t \, v_{t+1})$$

这里的 $m^{-1}$ 是质量矩阵——其实就是 $f = ma$、$a = m^{-1} f$ 那一套，只不过现在我们把所有粒子的 $x$ 都拍平成了一个单独的向量：如果有 $n$ 个粒子、在三维里每个粒子有 $x, y, z$ 三个分量，那 $x$ 就是一个 $3n$ 维的向量；如果是二维的话，$x$ 和 $v$ 的长度都是 $2n$。

到这里你会发现，公式三是一个非线性方程——力 $f$ 本身是位置的函数，而括号里的位置又藏着未知的 $v_{t+1}$。为什么它非线性、这个方程要怎么解出来，就是接下来的内容了。

## 隐式时间积分与 SPH 粒子流体
> 对应块：BLK04 | 覆盖分集：P02下 | 块标题（分集名）：《Lecture 2 拉格朗日视角（1）》

把弹簧质点系统的隐式欧拉更新式摆出来，接着往下推。现在未知数很显然只有一个：$v_{t+1}$——$v_t$ 和 $x_t$ 都是已知的。那这个非线性来自哪？来自 $f$：力函数往往是一个非线性的函数，它把 $v_{t+1}$ 藏在自己的参数里，直接解是解不动的。这一节就从这个卡点出发：先把这个非线性拉直，解出 $v_{t+1}$；然后带着这套工具，进入拉格朗日视角的下一个主角——SPH 粒子流体。

### 非线性卡在哪：一阶泰勒展开与线性化

办法是老朋友：泰勒展开。把 $f$ 在 $x_t$ 点处做一阶泰勒展开，$f(x_t + \Delta t\, v_{t+1})$ 就展开成

$$f(x_t) + \left.\frac{\partial f}{\partial x}\right|_{x_t} \Delta t\, v_{t+1}$$

这其实就是一个一阶泰勒展开。这一步操作叫线性化：做了这个操作以后，你整个系统就变成线性了——因为这里的 $\partial f/\partial x$ 是一个雅可比矩阵（Jacobian），它作用在向量上就是一个线性算子。

把它代回隐式欧拉的更新式，再做一下移项整理，就得到一个非常 nice 的线性系统：

$$A = I - \Delta t^2\, M^{-1} \left.\frac{\partial f}{\partial x}\right|_{x_t}, \qquad b = v_t + \Delta t\, M^{-1} f(x_t)$$

$$A\, v_{t+1} = b$$

系数矩阵 $A$ 和右端项 $b$ 在当前时刻都是已知的，要解的就是下一时刻的速度 $v_{t+1}$。

> **定义**：线性化（linearization）——把非线性项用它在当前状态处的一阶泰勒展开替换，使隐式格式的方程组变成线性方程组。

### Jacobi 迭代：最朴素的线性系统解法

解线性系统在物理模拟里面是一个非常重要的问题，有各种各样的方式来解。今天由于时间关系，只介绍最简单的一种：Jacobi 迭代。除了 Jacobi 迭代，还有 Gauss–Seidel 迭代；还有共轭梯度（Conjugate Gradient）——共轭梯度里面花样就多了：可以加各种各样的 preconditioner（预条件子），共轭梯度本身还有各种变种。比如你的系统是对称正定的，就可以直接用共轭梯度；有的系统不对称，有的系统对称但不正定，那就有各种共轭梯度的变种来对付。这些一般统称 Krylov subspace solvers，后面我们会专门有一讲，介绍怎么用它们来解线性系统。

那 Jacobi 迭代在干啥？它的直觉是：每一次迭代，都把未知数的一项换成一个值，这个值能使得——如果只看矩阵的这一行的话——右端项恰好被满足。这话说起来有点绕，但是你看代码的话其实非常容易：单独一步 Jacobi 迭代的代码非常短，只有十几行。

这里有一个可以直接跑的小 demo：创建一个 $20 \times 20$ 的矩阵 $A$、一个向量 $x$，还有一个右端项 $b$；每次迭代就是一个小 kernel，叫 iterate；除了迭代，有时候还需要算一下 residual——$b$ 减去 $Ax$ 就叫 residual——顺便算一下 residual 的 L2 范数；然后初始化矩阵，就可以开始算了。跑起来你会看到：一开始 residual 非常大，经过若干次迭代，residual 迅速变得非常小。不过说实话，这个收敛速度还算比较慢的——你如果用共轭梯度，根本用不了这么多次迭代。这边只是为了图简单，搞了一个比较简单的 Jacobi 迭代。

这个算法的直觉值得再啰嗦一遍：每次都更新一下 $x$，使得 $x$ 能够把矩阵的某一行的方程满足。但你每次做这种更新，不见得每一行都能满足——因为每个更新都是局部的：你改了 $x$ 以后，可能修好了这一行，下一行挂了；修了第二行，第三行又挂了。所以要迭代很多很多次，才会不断收敛到一个值。而且它也不是总是收敛的：它只会对一些性质比较好的矩阵收敛，也就是说对谱半径得有一些要求。今天我们只讲怎么用太极（Taichi）实现这么一个非常简单的概念，后面会讲更多关于线性系统怎么求解的方法。

### 一个 β 统一显式与隐式

回头看刚才那个复杂的公式，其实你会发现：只要往公式里面加入一个数，叫做 β，我们就可以把 forward Euler 和 backward Euler 整合到一起。做法是让力函数的参数变成 $x_t + \beta\, \Delta t\, v_{t+1}$：

$$v_{t+1} = v_t + \Delta t\, M^{-1} f\!\left(x_t + \beta\, \Delta t\, v_{t+1}\right)$$

线性化、整理之后：

$$\left(I - \beta\, \Delta t^2\, M^{-1} \left.\frac{\partial f}{\partial x}\right|_{x_t}\right) v_{t+1} = v_t + \Delta t\, M^{-1} f(x_t)$$

β 取不同的值，得到的积分器就不一样：

| β 的取值 | 得到的格式 |
| :--- | :--- |
| $\beta = 0$ | 左边这一整项就是单位矩阵，直接消掉，得到 $v_{t+1} = v_t + \Delta t\, M^{-1} f(x_t)$，相当于一个显式的积分器 |
| $\beta = 1/2$ | 中点法（midpoint method），数值精度上有些情况会好一点 |
| $\beta = 1$ | 就是刚才推导的那个隐式欧拉（backward Euler）公式 |

### 为什么不直接求逆矩阵

有同学问：$A\, v_{t+1} = b$，那不就有现成公式 $v_{t+1} = A^{-1} b$ 吗，为什么不直接求逆？这是一个很好的问题。求逆是一个非常昂贵的操作：矩阵比较小的时候，你求一求逆还比较省事；但矩阵非常大的时候，很多时候逆矩阵根本就存不下。为什么？因为 $A$ 往往是一个稀疏矩阵（后面会提到），但它的逆就不一定是稀疏矩阵了——$A$ 的逆很可能变成一个稠密矩阵，那你的内存就存不下。

另外还有一些别的方法：不求逆，直接用直接解法（direct solver），比如 Pardiso。如果你有 Pardiso，用它解这样的稀疏线性系统还是挺省事的。这边之所以讲迭代法，是因为迭代法比较容易在太极里面实现；后面我们会提到各种解线性系统的方法。

### 当弹簧质点系统长大之后

再往前想一步：如果说我们有成千上万个弹簧、成千上万个质点，那怎么办？这个时候我们就得使用稀疏矩阵，可能得使用一下共轭梯度，还得做各种各样的预条件（preconditioning），还得做一些物理模型层面、精度和速度上的取舍——比如说你可以用基于位置的物理（position based dynamics，PBD）。

另外也有一些完全不同的、解决弹簧质点问题的路数。有一篇很有名的 paper，叫 Fast Simulation of Mass-Spring Systems，这是一个非常好的 paper：它用了一个不同的 formulation，让这个问题 solve 得更快了。大家有兴趣的话，可以作为扩展阅读去看一看。

### SPH：用一坨粒子和一个核函数逼近连续场

弹簧质点模型讲完了，接下来讲 smooth particle hydrodynamics——用拉格朗日视角解流体力学的方法，一般大家叫 SPH（Smoothed Particle Hydrodynamics，光滑粒子流体动力学）。

SPH 的高层 idea 是什么？就是我们用一坨粒子，每个粒子上面携带一些物理量，再用一个核函数（kernel）去近似一个连续的场。这个公式其实非常直观：在 $x$ 这一点，某个物理场的值等于什么？给周围求个和，求和的时候用核函数去加权平均周围的粒子：

$$A(x) \approx \sum_j A_j\, W(x - x_j, h)$$

严格来说这并不是加权平均，直观上它做的是类似 smoothing 的操作：把周围的粒子光滑了一下。核函数中间大、两边小，所以它可以让接近 $x$ 的粒子贡献更多，远离 $x$ 的粒子贡献更小；当粒子特别远、超过一定的范围——比如超过 $h$，$h$ 就是这个核函数的 support，或者叫它的半径——贡献就是零了。这里的 $A$ 可以是几乎任何随空间变化的物理量：可以是速度，可以是 density，可以是 temperature。当然，如果你要求导数的时候，那完全是一个不同的故事，后面我们会提到。

SPH 一开始是用来做天体物理的。它有一个最大的好处：不需要 mesh，非常非常适合用来模拟自由表面流体。

> **定义**：自由表面流体（free surface fluid）——存在一个可以自由运动的流体界面的流体。比如你有一盆水，水有一个水和空气的界面，这种就叫自由表面流体。反过来，烟雾模拟就不是自由表面流体：不管你有没有烟，你都是有空气的，整个空间都被填满了，所以烟雾不算。

也正因为如此，比较少有人用 SPH 来做烟雾模拟：你用 SPH 做烟雾模拟，得把整个空间全部用粒子填满，有的时候就比较 costly。而且相比于其他把空间填满的模型，比如 grid，particle 的 overhead 还是比 grid 要高一些。所以一般情况下如果要做烟的话，大家会用一个 background grid 来表示背景的速度场。

SPH 还有一个很大的好处，我觉得值得单独说：它直观上面非常非常容易理解。你可以理解成每一个粒子是一小包水。当然严格来讲它并不是这样，但你一开始这么理解，其实没有什么问题。

### WCSPH：从弱可压缩做起

用 SPH 来模拟流体，最简单最简单的方法叫做 WCSPH——weakly compressible SPH（弱可压缩 SPH）。大家都知道，水其实是不可压缩的，对吧？但是你要实现真正的不可压缩，其实是要下一番功夫的。所以一般情况下，入门的时候大家会先做一个可压缩的流体模拟。

WCSPH 最关键的其实就这么一个公式：

$$\frac{D v}{D t} = -\frac{
abla p}{\rho} + g$$

左边这个大 $D$ 是材料导数。为什么用大 $D$，而不是用小 $d$ 或者偏导 $\partial$？下一讲我们会提到。这个材料导数非常 confusing，它有好多好多名字：可以叫 material derivative，可以叫 Lagrangian derivative，可以叫 convective derivative，还可以叫 advection derivative。大家只要记得：大 $D$ 表示跟着粒子动的那个导数，就可以了。

> **定义**：材料导数（material derivative）$\dfrac{D}{Dt}$：跟着粒子一起运动时看到的时间变化率。SPH 里每个粒子就是一个"跟着流体走"的观察者，所以粒子速度的时间导数写成 $\dfrac{Dv}{Dt}$。

具体到这个方程：液体里面都有个压强，你的压强的梯度，就会影响流体粒子的速度——当然你得把压强梯度除以密度，才得到它的加速度。所以左边是流体的内力；加号右边是重力，就是流体受到的外力。这个 $g$，一般来说有的时候大家用它专指重力，有的时候大家就图省事，把各种各样的外力都算到 $g$ 里头。

那压强是什么呢？刚才我们提到 SPH 可以用来近似表示流体在某一点的密度；在 WCSPH 里面，压强就用一个叫做 equation of state（状态方程）的方法来表示：

$$p = B \left[ \left( \frac{\rho}{\rho_0} \right)^{\gamma} - 1 \right]$$

这里的 $B$ 是 bulk modulus（体积模量），$\rho_0$ 是一个理想的密度。直观上来看：如果 $\rho$ 非常大，那你这个 $p$ 就会非常高；压强很高呢，它就会推着周围粒子离开自己——相当于它在尝试保持自己的体积。

然后 WCSPH 还是用经典的那套 SPH 近似来做：基本上所有 SPH 里面，每一个粒子上的 $\rho$，都是通过它周围粒子的质量来加权得到的：

$$\rho_i = \sum_j m_j\, W(x_i - x_j, h)$$

如果你去仔细读 WCSPH 这篇 paper，会发现它里面还讲到各种各样的扩展，比如说怎么去加表面张力、怎么样去加黏性。另外有一个非常非常好的 tutorial——一个网站，主题是流体和固体里面的 SPH 物理动画技术——是现在图形学里面最懂 SPH 的一帮人做的教程，非常非常好，大家可以打开来看一看。

> **易错点**：WCSPH 原文里的导数用的是小 $d$。小 $d$ 在这种情况下就有一点歧义——它给人感觉是一个全微分，非常 confusing。一般来说在 particle 方法里，我们会用大 $D$ 表示物质导数。大家不要被这篇 paper 里的符号误导。

### SPH 的梯度算符：不精确，但守恒

有了核函数近似，每一个粒子所在位置的物理量的值都能算出来了。但很多时候我们需要算它的梯度——比如刚才就有一个压强梯度 $
abla p$ 要算。SPH 里面有一套自己的理论：算梯度有一个特别的算符，这个算符长得好像很奇怪。你仔细去推呢，会发现它其实并不能按照上面那个核函数近似直接推出来，而且它的值也不是特别准确。

那为什么大家还用这个梯度公式？因为它至少在 SPH 里面是对称的，能保证它是动量守恒的。有了这个公式，大家就可以去计算 $
abla p$；反过来，如果你不用这个公式去算 $
abla p$，你的系统就会出现各种各样的不稳定性。

> **提示**：这个梯度算符牺牲了一点精度，换来的是对称性（动量守恒）——不守恒的算法会让系统出现各种各样的不稳定性，这笔账在流体模拟里是划算的。

如果要算高阶的导数，比如拉普拉斯 $
abla^2$（你要算黏性的话，就得算拉普拉斯），那 SPH 里面又有一套额外的公式来算。所以这个地方可能是 SPH 里不太优雅的一个地方。

### 三步跑起一个 WCSPH

讲了这么多，其实你要写一个 SPH 也非常容易。先把两个公式认清楚：上面第一个公式实际是欧拉方程（Euler equations）——就是不考虑黏性的 Navier–Stokes equation；右边压强那个是 equation of state，说的是压强关于密度的关系。

整个算法每个时间步就三步：

```text
WCSPH 每个时间步：
  第一步  对每个粒子估计它局部的 density
          注意：粒子自己不 carry density，它 carry 的是质量，
          density 是通过周围粒子的质量估计出来的
  第二步  有了每个粒子上的 density，用 SPH 的梯度公式
          算出每个粒子这个地方压强的梯度 grad p
  第三步  把 grad p 代入 Dv/Dt = -grad p / rho + g，
          后面用一步 symplectic Euler（辛欧拉，也叫半隐式欧拉）更新
```

读图：三步各司其职——密度估计、压强梯度、时间积分，一个最朴素的 SPH 流体就齐了。

第三步其实非常好算：把速度的导数直接代入进来，后面用一个 symplectic Euler 更新就行——和刚才的弹簧质点模型几乎一模一样。你可以看到，SPH 和弹簧质点模型在很多层面上是非常像的。你甚至可以认为，SPH 里面的"弹簧"长这样：一个粒子，和它周围以 $h$ 为半径的粒子，中间都连着一根弹簧——只不过这个弹簧遵循的不是胡克定律，而是 SPH 推出来的那些物理关系。

### SPH 的三个变种

SPH 有很多很多的变种，这里讲几个我还算有一点了解的。

#### PCISPH：预测—校正逼近不可压

刚才讲的 WCSPH，你可以认为它是一个显式的格式。PCISPH 呢，有点像一个 implicit 的 SPH：它做的是隐式的时间积分，但又为了性能做了一些取舍，不完全是隐式的。它用的是一种叫预测—校正（predict–correct）的格式：每次先预测一下粒子的位置或者速度，然后根据这个预测做出一些校正，不断这样校正、不断这样校正，就得到一个比较好的速度场。这个速度场有什么特点？它的散度比较小——速度场无散，就意味着你这个流体更加接近不可压缩。

#### PBF：位置法动力学遇上 SPH

另外一个变种最近非常流行，是几年前提出来的。position based dynamics（PBD）在实时的情况里面被非常频繁地使用，把它和 SPH 结合起来以后，就得到了一个模拟流体的方法：PBF（position based fluids）。太极里面其实有这个例子，是荒野大神给我们无私贡献的。正好太极刚发布了新版本，跑之前我还有点不确定能不能用——一跑，没有什么问题。这就是一个 position based fluid 的 demo，大家有兴趣的话可以自己去跑一跑，我觉得还是挺有意思的。

#### DFSPH：把速度场摁成无散

最近还有一个变种叫 DFSPH（divergence free SPH）。类似的，它也是一个强行去 enforce 不可压缩性的方法。divergence free 说的就是：它的速度场是 divergence free 的——无散。

想学更多 SPH 的话，有两份材料。比较早的是 2014 年那篇 SPH in computer graphics——我上大二还是大三的时候，就是看这篇 paper 入门的。不过最近有一些更新的材料，就是前面提到的那个 tutorial，里面有各种各样的 demo，想学 SPH 的话可以去看它。

### CFL 条件：显式积分的爆炸红线

说到显式时间积分，或者说 SPH，有一个东西非常重要，叫做 CFL condition。

之前我们提到显式时间积分有一个时间步长公式：

$$\Delta t \le c \sqrt{\frac{m}{k}}$$

当你的系统比较 stiff（硬）的时候，$\Delta t$ 就不能太大，要不然你的系统就会爆炸。这是从材料的刚度、材料的硬度角度来考虑的时间步长限制。另外大家还会有另外一个限制：从粒子运动的速度来考虑时间步长，这个量叫 Courant number（库朗数）：

$$C = \frac{u\, \Delta t}{\Delta x}$$

$u$ 是粒子运动的最大速度，$u \cdot \Delta t$ 是什么意思呢？就是在一个时间步之内，粒子移动的最大距离。$\Delta x$ 在 SPH 里面一般就是 $h$，顶多差一个常数——一般可以认为是粒子的半径。

> **定义**：Courant number：$C = u\,\Delta t / \Delta x$，物理含义是"一个时间步内，粒子最多能挪过几个网格间距"。模拟的时候必须让它满足 $C \le C_{\max}$。

$C_{\max}$ 大家一般会取几个接近 1 的值，不过 0.1 到 10 之间都有可能，取决于不同 simulator 的数值稳定性的脾气：脾气好的，你可以做到 10；脾气差的，可能 0.1 以上就炸了。这个 $C$ 一般叫做 CFL number，或者叫 Courant number，大家索性就叫它 CFL——因为 Courant 这个词不是很容易读。

那这个公式有什么用呢？用处大了。如果你做任何的显式时间积分，可能都得考虑这么一个公式，要不然你的 simulation 特别容易炸。比如 SPH 里面，CFL 一般大家就取一个接近 0.4 的值；如果说你的粒子运动太快了，怎么办？这个时候你就得考虑一下，是不是该把 $\Delta t$ 减少一点，要不然你的系统就会非常不稳定。MPM（Material Point Method）里面大家一般取 0.3 到 1。FLIP（FLuid Implicit Particle）是一系列方法，如果用 FLIP 做 smoke 的话，一般可以用一个比较大的值，1、5 甚至 10、20 都有可能。MPM 和 FLIP 我们后面会详细介绍。

| 方法 | 典型的 $C_{\max}$ |
| :--- | :--- |
| SPH | 接近 0.4 |
| MPM | 0.3 ~ 1 |
| FLIP（做 smoke） | 1、5，甚至 10、20 |

### 邻居搜索：从 O(n²) 到 O(n)

如果你要加速 SPH，那这里面学问可大了。目前为止我们看到的 SPH，每一个时间步的时间复杂度是多少？是 $O(n^2)$，$n$ 是粒子数目。为什么？因为对于每一个粒子，你都得去枚举其他所有的粒子，去估计这个粒子局部的 density 也好、压强也好。但实际情况中，$O(n^2)$ 是一个非常非常大的数字：$n$ 一般可能是 100 万，甚至 1000 万，那 $n^2$ 肯定就不能接受了。

实际情况下，大家会采用一些空间数据结构来加速 neighborhood search（邻居搜索），把时间复杂度从 $O(n^2)$ 降到 $O(n)$。所谓 neighborhood search 就是：对于每一个粒子，如果说我能够精确地找到和它距离不超过 $h$ 的所有粒子，那我们是不是就不需要去 loop over 其他所有的粒子，而只需要去 loop over 和我比较近的这些粒子就可以了？

怎么找？其实也非常简单：直接搞一个数据结构——一个 background voxel grid（背景体素网格），里面每一个 voxel 去维护一个 list，装着落在这个 voxel 里的所有粒子。对于每一个需要查找邻居的粒子：先 locate 它所在的 voxel；找到这个 voxel 以后，把它周围的 voxel 都枚举一遍；然后对于每个 voxel，去枚举它包含的所有粒子。由于每一个 voxel 里面包含的粒子数目一般来说是一个常数——几到几十这个数量级——所以每一个粒子一般只需要找几十个、顶多一两百个周围的粒子检查一下就可以了。

```text
      ┌───┬───┬───┐
      │   │ ? │   │       对粒子 P 找邻居：
      ├───┼───┼───┤       先定位 P 所在的 voxel，
      │ ? │ P │ ? │       再只枚举它周围的 voxel
      ├───┼───┼───┤       （二维 3x3，三维 3x3x3，
      │   │ ? │   │         一共 9~27 个），
      └───┴───┴───┘       而不是全场可能上百万个 voxel。
```

读图：只看周围 9~27 个 voxel，而不是全场可能上百万个 voxel，这就是把 $O(n^2)$ 压到 $O(n)$ 的关键。

有同学问：voxel 的数目不也很大吗？对，数目确实很大。但是对于每一个 particle，我们不需要去 loop over 所有的 voxel，只需要 loop over 它周围的 3×3——这是二维；如果是三维，就是 3×3×3，也就是 9 到 27 个 voxel。9~27 个 voxel，相比于总体可能有 100 万个 voxel 来比，还是一个很小很小的子集。

Neighborhood search 一般就是 SPH 的瓶颈，所以大家想了各种各样 fancy 的方法来加速它：比如各种位压缩的技巧，用 Morton coding 来提高访存的 locality，各种各样的单线程的方法。大家可以去看一看最近的一些 paper：比如有一篇比较新的 SPH 加速方法，同一组人后来好像又在 Eurographics 上发了一个更新的、构建 neighbor list 的方法。这里面加速的学问可大了，这边我就不继续说了。

### 同族的粒子方法

其实基于粒子的模拟方法还有很多很多。

一个是 DEM（Discrete Element Method，离散元素法），在 graphics 里面也很常用。所谓 DEM，相当于你把每一个粒子看成一个刚体小球，再加上一些复杂的物理；可以用它来模拟沙子、模拟一些其他的物质。

还有 MPS（Moving Particle Simulation），它其实是一个和 SPH 有点相近的方法，但它会在局部建一个泊松方程（Poisson equation），把泊松方程 solve 一遍——这样使得你的流体的不可压缩性更好。

还有 Power Particles：用 power diagram 加一些 particle 来做的一个不可压缩流体 solver。power diagram 其实就是 Voronoi diagram 的一个 generalization；他们用这个构建粒子周围的 Voronoi diagram。它视觉上主要的一个好处，就是粒子之间的间距会非常非常均匀。

另外还有 Peridynamics（近场动力学）。如果大家对它在图形学里面的应用感兴趣，可以去看一看课件里展示的那篇文章，还是挺有意思的。

### 把结果导出成 MP4 和 GIF

讲完 SPH，接下来讲一个实用技巧：怎么把你的结果输出成一个 MP4，然后再把 MP4 转换成 GIF——这样你就可以在论坛上面 share 一个 GIF，比 share 一个静态图炫酷多了。这部分主要还是看文档，这边只是大概介绍一下。

如果说你要从模拟的帧做一个 MP4 video，首先得把这些帧写到磁盘上面。有两种方法：你如果用 ti.GUI，可以用 ti.GUI.show()，带上一个文件名，就可以把这些帧全部存到磁盘上；或者，如果你手上是一张现成的图——一个 image、一个 numpy array——可以直接用 imageio.imwrite 把它写到磁盘上。

磁盘上有了这些帧以后，用一个命令叫 ti video，它就可以把你所有的帧变成一个 mp4；这个时候你还可以指定一下帧率，可以是 24 帧，或者 60 帧，都可以。有了 mp4 以后，可以把它 convert 成 GIF。论坛上面我看到有同学提供了怎么用 ffmpeg 的方法——那个方法学起来有点难，但是可定制性更强一点。太极提供的这些简单的函数，其实就是基于 ffmpeg 的简单封装，功能比较少，但大部分情况下也够用。

### SPH 与刚体的耦合：一篇近期论文

如果大家对 SPH 感兴趣，可以去 check 一下：我们有一个助教同学写了一个基于 C++ 和 CUDA 的 SPH simulator，GitHub 上面有代码，上面实现了 WCSPH，还有 PBF、刚才提到的 DFSPH。我本来想写一个基于太极的版本，但是后来一直没有时间；不过我相信论坛上面很快就会有同学写出来，大家可以看一看它的实现。当然，实现一个最基础版本的 SPH 也不会特别难。

接下来我们看一篇最近的、很好的 SPH paper。这篇 paper 是做 SPH 和刚体的耦合的。所谓耦合，就是说你的刚体和你的 SPH 模拟的流体能够双向交互。当然，耦合有单向耦合和双向耦合之分：刚体和流体能够双向交互，那就是双向耦合。这篇 paper 做的是所谓的强耦合。强耦合一般来说是指：我在解线性系统的时候，或者我在迭代的时候，把两个系统同时进行联立的求解。弱耦合就更简单一点：我先解流体，然后把流体作为刚体的边界条件去解刚体，再把解出来的刚体作为边界条件去解流体——这个耦合就相对来说更弱一些。这篇 paper 提出的就是一个强耦合的方法。

```text
弱耦合：解流体 -> 流体作为边界条件 -> 解刚体 -> 刚体作为边界条件 -> 解流体 -> ...
强耦合：解线性系统 / 迭代时，把流体和刚体两个系统联立起来同时求解
```

读图：区别就在"联立"两个字——弱耦合是你先我后轮流解，强耦合是把两边放进同一个方程组里一起解。

这篇 paper 配了好几个演示视频，其中我最喜欢的那个 demo，无论如何、就算播放有点卡也要放一下。从这些 demo 可以看到，SPH 现在早就不是只做流体了：今年 SIGGRAPH 还有一篇用 SPH 模拟雪的方法，其实它是用 SPH 在模拟很多刚体。SPH 和 MPS 这类方法有一个很大的好处：它可以比较好、比较容易地模拟各种介质的耦合——比如流体、弹性物体、刚体，都可以。当然，这些 demo 每一帧都是要算很长时间的，远远没有达到实时的标准。

SPH 有的时候在视觉上看起来会非常 splashy——你会觉得它的粒子好像在空中、有点爆炸的那种感觉，我个人不是很喜欢；当然有一些场景可能确实需要这样的效果。这个 splash 的问题在于：粒子会生成很多很多的 splash，而 splash 中间往往是空的，看起来有的时候就不会特别好。当然你如果加了表面张力，这个问题可能会减轻一点。

### 从粒子到水面：Marching Cubes 与 OpenVDB

答疑环节有同学问：模拟输出粒子以后，怎么生成真实的水面？这是一个很好的问题。这叫 surface reconstruction（表面重建）——从粒子生成表面的 mesh，是一个很大的话题，一般来说有很多很多搞法。最典型、最基本的一个方法叫做 marching cubes。

Marching cubes 做的事情是：把整个空间用很多网格打一个背景网格，然后对于网格上面的每一个点，去算一下粒子的密度，再尝试画出它的 isosurface——等值面，也就是某个量等于常数（比如等于零）的那个等值面、等势面。这个等值面，其实就是用各种三角网格去近似的，相当于用三角形去填充这些网格。

Marching cubes 是一个非常非常经典的方法，但它实现起来会稍微有点麻烦：因为情况非常多，光是常见情况就有 14 种，如果你把更多不同的复杂情况考虑上去，远远不止 14 种，实践起来还是挺烦的。但它毕竟还是那个绕不开的方法——可能你不管怎么弄，最后都得上 marching cubes。

在做 marching cubes 之前，还有各种各样的预处理，比如 smoothing 之类的操作。大家可以去看 OpenVDB，里面有各种各样的 operator。现在工业界里面一般来说比较常用的搞法是：用 OpenVDB 先把粒子光栅化到一个背景网格上面，然后在背景网格上面做一些适当的 level set 操作。所谓 level set 就是：粒子被光栅化到背景网格上以后，你会得到一个距离场；在这个距离场上面可以做各种各样的操作，比如让它变得更圆滑，或者让它变得更加尖锐，这些都可以。你在做完 OpenVDB 的各种操作以后，就得到一个 density field，然后就可以上 marching cubes 了。

OpenVDB 还是一个非常成功的一个系统，很多电影都有用它。VDB 是拿了奥斯卡奖的——因为 VDB 拿了一个奥斯卡学院奖，还是很厉害的。

### 为什么要学弹性

模拟弹性物体是一件非常有意思的事情，理由至少有三条。首先它会带来不错的视觉效果——一个东西很 Q 弹，看着就很有意思。其次它不会特别难实现：用 Taichi 的话，可能一百多行代码就能实现一个简单的 2D FEM 弹性模拟器。最关键的是，弹性是其他材料的基础——粘弹性、弹塑性，包括各种各样更 fancy 的材料，都是在弹性材料的基础上做比较细微的修改得到的。所以这一讲讲的是比较基础的内容，课后有兴趣的话，可以看一看图形学领域里大家比较喜欢的两份关于弹性、关于有限元的教程，都属于写得非常通俗易懂的那类。

### 形变与形变梯度

什么是形变？一个材料现在的位置和它静止状态的位置发生了变化，我们就认为它发生了形变。怎么描述形变？最常用的描述叫做 deformation map：一个函数，能够把静止位置映射到形变位置。三维情形下，它就是一个从三维向量到三维向量的向量函数。把 deformation map 对静止位置求导，得到的就是 deformation gradient，也就是形变的梯度。

> **定义**：deformation map $\phi$ 把静止位置映射到形变位置；deformation gradient $F = \frac{\partial \phi}{\partial X}$ 是它对静止位置的导数；$J = \det F$ 是形变以后体积与静止状态体积之比。

观察 deformation map 的性质，可以得到两个很有用的结论。第一，如果有两个 deformation map $\phi_1$ 和 $\phi_2$，它们只是在最终位置上差了一个常数，那它们的形变梯度其实是一样的——因为常数求导以后就消失了。第二，$J$ 是形变以后的体积除以静止状态的体积，它就是 $F$ 的行列式，也就是 Jacobian determinant，描述的是体积的变化。

$$J = \det F = \frac{V_{\text{deformed}}}{V_{\text{rest}}}$$

这里我准备了一个海绵宝宝的 demo。给这个容易形变的物体做一个切向的形变：左边是它静止的位置，右边是形变以后的位置——这是一个非常清晰的逐点映射。头上右上角的一个点 $X_{\text{rest}}$（它的静止位置），对应的就是形变后右上角的那个点；左上角的点对应左上角；连两只鞋子都是一一对应的。

程序里显示的 deformation gradient 是 $1, 0, 0.5, 1$，其实是一个 shearing（剪切）矩阵。我把它改成 $1, 0, 0, 2$，这个形变就会在纵向拉伸海绵宝宝；再改成 $2, 0, 0, 1$，就横向拉伸了它：

$$\begin{bmatrix} 1 & 0 \\ 0.5 & 1 \end{bmatrix} \qquad \begin{bmatrix} 1 & 0 \\ 0 & 2 \end{bmatrix} \qquad \begin{bmatrix} 2 & 0 \\ 0 & 1 \end{bmatrix}$$

从左到右依次是：剪切、纵向拉伸、横向拉伸。规律就在这里：把形变梯度第一行整体乘上一个常数，海绵宝宝就会在横向按照这个常数做拉伸；类似地，第二行管的是纵向。

### 弹性是什么：超弹性材料

什么是弹性？拿根橡皮筋拉一拉，松开以后它会回到静止状态。弹性就是材料恢复自己静止状态的这么一个性质。这一讲我们讲一个比较简单的弹性模型，叫做超弹性模型（Hyperelasticity）。它有一个标志性性质：stress-strain relationship（应力-应变关系）是被一个 strain energy density function 来定义的。

直观地理解：$\Psi$ 是一个 potential energy（势能），它会惩罚你的形变。在超弹性材料里，它实际上是 $F$ 的函数。注意它是一个密度——单位体积的势能密度，不是一个总的能量。

把术语捋一捋。stress 中文叫应力：材料内部有一种内部的弹性力，在超弹性框架里它就是用来恢复材料原来体积、形状的内力。strain 中文叫应变：材料形变的一个 measure。说明一下，我本科没有专业学过这些东西，学它的时候已经是在一个英文的环境里，所以有的中文对应关系我不是特别清楚，只能尽量地说，如果说错了请大家原谅。stress 和 strain 都有很多很多种表述：stress 有各种各样的 stress tensor，strain 也有各种各样的描述。在我们这门课里，大家看到 strain，把它用 deformation gradient $F$ 替换掉就可以了。至于 Green strain 之类乱七八糟的很多术语，这里就不细细讲了——概念太多了，讲了以后可能反而影响教学质量。

> **易错点**：$\Psi$ 和 $\phi$ 长得很像，但它们完全不相关：$\Psi$（大写 Psi）用来表示 strain energy density function，$\phi$ 用来表示 deformation map。

### 应力张量：乘上法向量就得到力

考虑一个材料的微元。stress 直观上理解，就是材料微元会和其他材料微元进行一些推拉之类的相互作用。stress tensor 是一个 $3\times 3$ 的矩阵，或者说你可以认为它是一个二阶张量。它有什么作用？给它一个很小很小的截面，把截面的法向量乘上 stress tensor，得到的力就是这块材料向周围 neighborhood 施加的力——这个力叫做 traction（它的中文译名我也不太清楚，课后查一查再补充给大家，或者大家自己去查一查）。

图形学里根据不同的需要，常用的 stress tensor 有三种。

#### 第一 Piola-Kirchhoff 应力（PK1）

第一种常用的是第一 Piola-Kirchhoff stress，一般大家简称叫做 PK1 stress。它有一个很好的性质：$P$（PK1 stress）在 $F$ 点的求值，等于 $\Psi(F)$ 关于 $F$ 的求导——strain energy density function 对 deformation gradient 求导，得到的就是 PK1 stress：

$$P = \frac{\partial \Psi}{\partial F}$$

这个计算是在 rest space（静止空间）里进行的，非常容易算。但它有一个问题：它是 rest space 里面的一个 tensor。你如果实际上要算材料的受力，得在它形变以后的空间里去计算，那么就得做一些变换。

#### Cauchy 应力与 Kirchhoff 应力

在形变后的空间里，大家一般会用 Kirchhoff stress 或者 Cauchy stress，其实更常用的是 Cauchy stress。Cauchy stress 一般也叫做 true stress——它是真正的、在形变空间以后的内部应力张量。这个 tensor 有一个重要性质：它是对称的，原因是角动量守恒。这背后有一个推导过程，这里由于时间关系不详细展开。

#### 换算公式与对称性

这三种 tensor 之间是可以相互转换的：

$$\tau = J\sigma = P F^T, \qquad P = J\sigma F^{-T}$$

所谓负转置 $F^{-T}$，就是先取转置再取逆，或者先取逆再去转置——这两个是一样的。这个关系乍一看有点复杂：为什么是 $F^{-T}$？为什么不是 $F^{-1}$ 或者 $F^T$？因为我们这里要变换的是 normal——材料截面的法向量，而法向量的变换公式用的就是 $F^{-T}$。这个推导大家可以课后自己推一推。

| 应力张量 | 所在空间 | 对称性 | 备注 |
| :--- | :--- | :--- | :--- |
| 第一 Piola-Kirchhoff $P$ | 静止空间 | 不对称 | $P=\partial\Psi/\partial F$，最容易计算 |
| Cauchy $\sigma$（true stress） | 形变后空间 | 对称（角动量守恒） | 真实的内部应力 |
| Kirchhoff $\tau$ | 形变后空间 | 对称 | $\tau = J\sigma$ |

最后说说对称性，这也是答疑时被问到的问题：PK1 stress 不是对称的。从换算关系一看便知——true stress tensor $\sigma$ 因为角动量守恒是对称的，但 $F$ 本身不是一个对称的东西，$\sigma$ 乘上一个 $F$ 的负转置，乘出来的矩阵当然就不对称。对称的版本有一个 PK2 stress，不过 PK2 用的就更少了。$\tau$ 是对称的：$\tau = J\sigma$，$J$ 是一个常数、一个标量，标量乘上一个对称矩阵得到的还是对称矩阵。

### 材料参数：从杨氏模量到 Lamé 参数

接下来看几个常用的、描述材料弹性属性的参数。

首先是杨氏模量（Young's modulus），大学物理里都会讲到，高中物理可能也提到过。它最简单的理解：你可以认为它就是弹簧里那个 $k$。对于三维的材料稍微复杂一些——你去拉这个材料，比如手里有根橡皮筋，你去拉它，会发现中间的那一部分其实是会变窄的。

变窄这件事由泊松比（Poisson's ratio）来刻画。定性地讲：如果泊松比是 $0$，那你拉这根橡皮筋，它中间的截面面积是不会缩小的——你拉多长，体积很大程度上就变大多少。如果泊松比比较大，它就更接近于不可压缩，尽可能地接近保持自己的体积。这意味着什么？你左手右手一拉，橡皮筋变长了，要保持自己的体积，它就会把中间变细一些。这其实更符合大家的直觉：橡皮筋拉了以后肯定是中间越来越细，细到一定程度就断了。

有没有泊松比为负的材料？也有，这类材料一般叫做 auxetics。什么样的材料会这么奇葩？我以前搞过一段时间 3D 打印，3D 打印里可以打印出带负泊松比的材料。负的泊松比是什么概念：你拉这根橡皮筋以后，它中间反而会变粗——听起来就非常奇特。

既然拉伸会带来体积变化，那自然会想到刻画"压强关于体积变化"的 modulus，这就是 bulk modulus（体积模量）$K$，一般在液体里用得比较多——可压缩液体的模拟里就会用到它。

再往下是 Lamé parameters，一般写成 $\lambda$ 和 $\mu$。$\mu$ 有的时候也叫 shear modulus（剪切模量），有的时候写成 $G$，图形学里一般就写 $\lambda$ 和 $\mu$。这些材料参数其实都可以相互转换，它们都正比于 Young's modulus $E$——所以一般指定了 $E$ 和泊松比 $
u$ 以后，其他的全部都是可以算出来的，大家一般也就只指定 $E$ 和 $
u$。固体里一般用 $\lambda$ 和 $\mu$，但它们不是特别直观——大家刻画材料习惯于用 $E$ 和 $
u$——所以常见做法是给定 $E$ 和 $
u$，再通过它们算出 $\lambda$ 和 $\mu$。$K$ 一般是在模拟可压缩液体的时候才用得上，用的不是特别多。

| :--- | :--- | :--- | :--- |

### 常用超弹性模型

图形学里大家常用的是 Neo-Hookean 和 Corotated。Neo-Hookean 在力学社区里可能更加常用；在图形学里，基本上所有的弹性介质——如果是各向同性（isotropic）的话——很多时候大家就默认采用 Neo-Hookean。

除非你的形变非常非常小，那可能会用线性弹性（linear elasticity）。线性弹性有一个问题：你旋转了它以后，它并没有保持自己——旋转一个 linear elasticity 的材料，它的体积可能无条件地变大，不受到任何惩罚。这就非常奇怪：一个材料你去转一转它，势能还是能保持为 0，但体积会变大，这个不是特别物理。那为什么线性弹性还是很有用？如果你做的是小形变的分析——没有宏观上的 deformation，也不会去旋转它——这个时候线性弹性就非常好用，而且它导出来的方程一般是一个线性方程组，非常容易去解它。

为了 fix 线性弹性旋转以后体积无条件变大的问题，大家就提出了 Corotated。Corotated 一开始提出的版本稍微有一点小问题，所以后来大家又搞出来 Fixed Corotated。现在如果说 Corotated，一般就是指 Fixed Corotated model。

它的 $\Psi$ 是一个关于 $F$ 的函数，公式直接给在课件上。中间其实有一些推导过程，比如你可能会要求 $F$ 的奇异值（singular values）。奇异值一般是什么含义？$F$ 里有旋转的部分，把旋转的部分给它剔掉，剔了以后就只剩下延伸（拉伸）的部分，奇异值刻画的正是这部分。

> **易错点**：公式里出现的 $\sigma$ 指的是奇异值，不是应力——尽管应力张量也用 $\sigma$ 表示，重名纯属巧合，注意别搞混。

有了 $\Psi$ 关于 $F$ 的公式，就可以求出它的 PK1，也就是 $\Psi$ 关于 $F$ 的导数。求导这个过程还是挺有意思的，大家可以自己推一推，或者看一看那两份教程里面是怎么推的——这个导数一开始的话，说实话不是特别容易把它搞对。

不过这还只是一阶导数。如果写 implicit solver，你得求二阶导数——那就酸爽了：三维里算出来是一个 $3\times3\times3\times3$、81 个元素的四阶张量，推导过程体验不是特别好。所以我自己其实也不太喜欢 implicit solver，因为太复杂了。隐式格式的麻烦，后面专门有一节细说。

### 有限元：Galerkin 方法与弱形式

讲了弹性，接下来简单介绍一下有限元（FEM）。有限元其实是一套非常博大精深的理论，它是一个 Galerkin 方法。它要解决的事情是：PDE 不是连续的吗？但我在计算机里面只能表示离散的值，我只能有离散个值，那怎么办？必须做一个离散化的工作，把连续的 PDE 换成一个离散的方程组。

我们肯定不能用 PDE 那种逐点方程的方式——或者说它的强形式（strong form）——来描述物理系统。那怎么办？我去搞一些小的 test function，把强形式在局部做一个积分：不要求方程逐点满足，而是要求方程的 residual 关于 test function 积分以后得到满足。这就是所谓的弱形式（weak formulation）。后面的细节在课程后面会深入讲，现在大家只要知道：FEM 是一个 Galerkin 方法，它用 weak formulation。

弱形式里的积分落到空间上，就是把二维空间也好、三维空间也好，分成很小很小的 element。element 是什么？二维里可以是三角形，可以是正方形——或者叫做四边形；三维里可能是四面体或者六面体。当然还有很多很多更加 fancy 的 element。网上有一个"有限元素周期表"，叫 FEM Table，挺有意思的，其实有点丧心病狂——我到现在也没有完全搞懂这个东西。它是用 FEEC（有限元素外微分）做的，本质上是用离散微分几何的方式来讲各种有限元元素。网站上有一个简单的 background 介绍，但说实话可读性不是很好，大家如果不想自虐的话可以暂时不去读。不过有这么个东西还是挺有意思的，和化学里面的元素周期表有异曲同工之妙。

那未知数存在哪儿？暂时大家可以这么 assume：存在元素的顶点上面。但其实可以看到，更加复杂的元素，它的 DOF（degrees of freedom，自由度）不见得存在顶点上，可能存在边上，也可能存在它这个体里面。图形学里最常用的其实就是最简单的这些——三角形元素、四边形元素。今天就讲三角元素。

### 线性三角形有限元

FEM 里面我们讲一个最最基本的东西：linear tetrahedral / triangular FEM。解弹性问题的时候，大家经常会用到线性的三角网格或者四面体网格。它做一个最最最简单的 assumption：deformation map $\phi$ 在每一个元素里面是一个 affine 变换——或者说，它的 deformation gradient 在元素内部是一个 constant。什么是 affine 变换？$Ax+b$ 就是 affine 变换。

注意，这说的是一个元素之内，不是你的整个 simulation domain。如果整个 simulation domain 都是这么一个变换的话，那你这个 $F$ 就是整个 domain 都共享一个 $F$——但那样的话，你基本上就不是在模拟弹性物体了，物体的限制就太大了。一般弹性物体是每一个元素都可以自由地变换、自由地发生形变。

在一个元素之内，我们有这么个关系：形变以后的位置等于静止的位置乘上 $F$，再加上一个 $b$，$b$ 是一个 offset：

$$x' = F\,x + b$$

前面提到过，这个 $b$ 其实是不会被你的势能 penalize 的：你平移一个物体，它并不会产生形变，自然也就不产生弹性势能。

对于每一个元素，我们可以去计算它的弹性势能。弹性势能是什么？strain energy density function 是一个能量密度函数，把它关于体积积分，积出来就是弹性势能（课件上这里少写了一个 $dx$，这里补上）：

$$U_e = \int_{\Omega_e} \Psi \, dx$$

我们有 assumption：$F$ 在这个 element 上面是一个常数。$\Psi$ 是 $F$ 的函数，$F$ 是常数，那么 $\Psi$ 在这个元素里就是一个常量，这个积分可以直接换成"密度乘体积"：

$$U_e = V_e \,\Psi(F_e)$$

其中 $V_e$ 就是这个元素的体积，二维里面就是面积。弹性势能算出来，很多事情就很好解决了——因为力就是势能关于位置求导数以后再取一个负，这是势能的定义。

### 手推三角元素的形变梯度

怎么去计算一个元素的 deformation gradient？对于三角元素的话，这个非常容易计算，我们现场推导一遍。出发点还是那个关系：deformed 等于 $F$ 乘 rest 加 $b$。

二维三角形有三个顶点，静止位置记为 $A$、$B$、$C$，形变以后的位置记为 $A'$、$B'$、$C'$。（二维的三角形推广到三维就是四面体，它有四个顶点 $A$、$B$、$C$、$D$；出于简单性，我们用二维情况来思考。）在一个线性的三角元素里，$F$ 是一个常数，于是三个顶点各自满足：

$$x'_A = F\,x_A + b, \qquad x'_B = F\,x_B + b, \qquad x'_C = F\,x_C + b$$

小心记号：右端项里的 $b$ 是平移偏移量，它和顶点 $B$ 只是长得像，没有任何关系。

我们要做的第一件事情是：我们并不关心这个 constant offset，先把 $b$ 消掉。怎么消呢？很简单——第一式减第三式，第二式也减第三式，再稍微移项，就得到：

$$x'_A - x'_C = F\,(x_A - x_C), \qquad x'_B - x'_C = F\,(x_B - x_C)$$

注意每一个都是一个向量方程：左边是一个二维向量，右边也是一个二维向量。两个向量方程加起来一共有四条线性约束——而 $F$ 是 $2\times2$ 矩阵，恰好四个未知项，所以 $F$ 里面的所有项全部都能求出来。

具体求法：首先构造一个矩阵 $B$，它有两列，第一列是 $x_A - x_C$，第二列是 $x_B - x_C$；然后构造一个矩阵 $D$，第一列是 $x'_A - x'_C$，第二列是 $x'_B - x'_C$：

$$B = \begin{bmatrix} x_A - x_C & x_B - x_C \end{bmatrix}, \qquad D = \begin{bmatrix} x'_A - x'_C & x'_B - x'_C \end{bmatrix}$$

刚才那两个向量方程合起来正好就是 $D = F\,B$，于是：

$$F = D\,B^{-1}$$

> **提示**：$B$ 在整个物理过程中是一个常数——因为它只和静止状态中三角元素三个顶点的位置有关系。所以我们会把它提前算好，提前把矩阵求逆给它求好、存起来。矩阵求逆还是一个比较 costly 的操作，至少得算一次行列式的倒数、再做一次除法，没必要每个时间步重算，调用的时候直接从内存里取出来就行。

### 显式时间积分：把求导交给 Taichi

有了 $F$ 的算法，我们现在可以很容易地写出来一个显式时间格式的时间积分。一般情况下大家是不用 forward Euler 的，大家一般是用 semi-implicit Euler，或者又叫做 symplectic Euler：先更新 $v$，然后再更新 $x$——

$$v_{i+1} = v_i + \Delta t\,\frac{f(t_i)}{m}, \qquad x_{i+1} = x_i + \Delta t\,v_{i+1}$$

你看这个方程式里面，唯一不知道的就是 $f(t_i)$。

> **易错点**：semi-implicit Euler 虽然名字里带 implicit，它是一个显式格式。"semi-implicit" 是一个被 abuse 的词，各种各样的东西都可以叫做 semi-implicit。

$f(t_i)$ 怎么求它？求起来其实非常容易：顶点的受力是势能关于顶点的位置求导数以后再取一个负——这是势能的定义。总的弹性势能等于每一个元素的弹性势能之和：$U = \sum_e U_e$，而每个元素的 $U_e$ 我们已经知道怎么算了。代入 $U_e = V_e\,\Psi(F_e)$，再用链式法则展开：

$$\frac{\partial U_e}{\partial x} = V_e\,\frac{\partial \Psi(F_e)}{\partial F_e}\,\frac{\partial F_e}{\partial x}$$

求了以后你会发现中间那个因子是什么？是 PK1 stress——$\Psi$ 对 $F$ 的导数。最后还有一个因子 $\partial F_e/\partial x$，形变梯度关于位置的导数，这个有一个求导的过程，大家可以手动推一推。

> **易错点**：链式法则里多出来的那个体积，是元素的静止状态下的体积 $V_e$，不是形变以后的体积——好在这也是一个常数。

如果你不想去计算 $\Psi(F)$、也不想计算 $F$ 对 $x$ 的导数怎么办？用 Taichi 的自动微分系统。用了自动微分，后面那些你就不需要理解了——你只需要懂到前两个等号就可以了，后面就不用管了。

这里先给大家看一看在 Taichi 里怎么实现这个显式的 FEM。整个程序其实就 100 多行，里面值得注意的几处：整个程序里其实并没有一个计算受力的函数，只有一个计算总的弹性能量的函数 `compute_total_energy`，材料模型用的是 Neo-Hookean。注意代码里把 $J$ 和 0.2 取了一个 max：

> **提示**：Neo-Hookean 的能量里有一个 $\log J$ 项。$J$ 如果变成负数，整个 simulation 就会挂——出现各种 infinity、Not a Number 这些数，非常不稳定。所以为了让它稍微稳定一点，把 $J$ 和 0.2 取一个最大值，不让它变成接近 0 的数。

`compute_total_energy` 是在一个 `ti.Tape` 里面被调用的。`ti.Tape` 其实就是 Taichi 里面自动微分的"磁带"：tape 里这些操作会被记录下来，函数执行完以后进行 backpropagation，也就是求导数。求出来的导数在哪里被用上？就在 semi-implicit Euler 里：把总能量关于 $x$ 的导数的负值除上你的质量，就得到加速度，再往下积分。整条数据流是这样的：

```text
x, v ──▶ compute_total_energy(x)      （Neo-Hookean 能量，含 max(J, 0.2) 保护）
            │ ti.Tape 记录下全部计算
            ▼
      backpropagation：自动得到 ∂U/∂x
            │
            ▼
v ← v + Δt·(−∂U/∂x)/m ──▶ x ← x + Δt·v   （semi-implicit Euler：先 v 后 x）
```

读图说明：能量函数只负责算"总势能有多大"，力的计算完全交给自动微分反传完成，积分环节按 semi-implicit Euler 先更新速度、再更新位置。

重力这一项目前是单独的 $-g\cdot dt$ 积分。其实完全可以把重力势能也加到总的能量里面，然后整个全部交给 Taichi 自动微分——这样你就不用手动去求这些乱七八糟的东西了。mass-spring system 可不可以用自动微分？完全也可以：只要你能定义出来一个势能，就可以进行自动微分。

求导这个过程是非常非常头疼的。我以前花过很多时间，浪费在求导数、以及检查我推出来的导数到底哪儿错了这么些问题上面。现在有了自动微分，求导大家就不用去头疼了。

### 隐式时间积分：难在二阶导数

看完显式的，我们看一看隐式的时间积分。回顾一下之前讲过的一个看起来稍微有点复杂的公式——backward Euler 的隐式时间积分：它需要 solve 一个 linear system。如果我们用一次 Newton-Raphson，在局部做一个一阶 Taylor 展开来建立方程，就可以得到一个线性方程组——看到它就头疼了：里面有了一个 $\frac{\partial f}{\partial x}$ 这么一项。

$f$ 是什么？前面推导过，$f$ 本质上是 $\Psi$ 关于 $x$ 的导数（差一个负号）。现在要把它再对 $x$ 求一次导数，那你就要去求二阶导数了。求这个二阶导数叫做 force differential，求起来就非常头疼。在三维里面的话，中间过程中会要用到 $\Psi$ 关于 $F$ 的二阶导数——刚才说过了，那是一个 81 个元素的四阶张量，算起来相当不友好。

很遗憾，Taichi 的自动微分目前还不能求二阶导数，所以这一步大家还是要手动推一下。不想手动推的话，可以去看前面提到的那两份教程：它里面有各种各样材料的二阶导数，两篇教程写得非常清楚，你可以照着它写。不过我得坦白说：就算公式告诉你了，你自己去写还是挺麻烦的。我自己也写过，不是特别容易写，很容易写错。

这就是为什么我建议大家组队：组队以后就可以相互检查。写这类代码，很多时候你可能 10% 的时间在写代码，90% 的时间在 debug 你的代码。一个人写、另外一个人看着，或者一个人写、另外一个人 review 一下，你会发现很多别人的错误可能一眼就看出来了——当局者迷，旁观者清嘛。合作其实能很大程度上提高你的生产力。

剩下最后一个问题：$M$ 怎么求？这个 $M$ 其实就是一个质量的矩阵——对角矩阵，对角线上每一个元素就是这一个 node 的质量。在 FEM 里面，这个 $M$ 矩阵还是有点复杂的，它需要用一个叫做 mass lumping 的技术来把它简化。在 graphics 里面大家一般不 care：$M_i$ 可以用任何你觉得方便的 approximation——直接设成元素的质量，或者设成这个顶点的质量是周围元素质量加权以后得到的东西，都可以。

第一部分就到这里。这部分稍微有点难，但大家不要担心：就算推导没完全跟上，你看代码也会知道这个东西应该怎么写。各种 stress tensor 虽然定义讲了一圈，我们真正用到的，其实只是 PK1 stress。

### 面向数据的语言，为什么要借面向对象的壳

Taichi 是一门面向数据（data-oriented）的编程语言。DOP 在很多时候性能很高，但想把它模块化就比较难。为了提高代码的可复用性（reusability），Taichi 从面向对象编程（OOP）里借来一些概念，组成一个混合方案——我们叫它 ODOP：objective data-oriented programming。其实大家交的作业里已经有很多人自觉用上了 class。

这套方案靠三个非常重要的 decorator 撑起来：

| decorator | 修饰谁 | 作用 |
| :--- | :--- | :--- |
| `ti.data_oriented` | 整个 class | 声明这是一个面向数据的 Taichi class；普通 Python class 不用修饰 |
| `ti.kernel` | class 成员函数 | 成员 kernel，用法与外面的 kernel 一模一样，只是多带一个 `self` |
| `ti.func` | class 成员函数 | 成员 function，还可以再叠加 Python 的 `staticmethod` 修饰 |

以前没有这么方便，得写 `ti.class_kernel` 和 `ti.class_func`，现在这两个已经废弃不用了——老代码里看到它们，直接当成 `ti.kernel`、`ti.func` 忽略掉就行。这背后有一段很长的开发故事：旷野大神写过一篇 Taichi 的开发 post，讲的就是为了让大家能写 `ti.kernel` 而不是 `ti.class_kernel`，背后工作量有多大。开发一门编程语言真的是工作量非常大的辛苦工作，不过我认为非常有意义；对 Python 内部机制感兴趣的同学可以去看一看那篇 post。

最简单的入门例子是行星绕日系统，demo 叫 `odop_solar`。这个例子是 Taichi 0.6.10 才有的，所以先把你的 Taichi 更新到 0.6.10。跑起来就是一个很简单的粒子系统：中间一个太阳，几颗行星绕着它转。代码骨架大致如下（按课堂口述整理的示意，不是完整源码）：

```python
@ti.data_oriented                     # 面向数据的 class，必须用它修饰
class SolarSystem:
    def __init__(self, n, dt):        # n 是行星数量，dt 是 time step size
        ...                           # 成员 tensor 定义在这里，和写在外面没有任何区别

    @staticmethod
    @ti.func
    def random_in_range(...):         # staticmethod：生成一个范围内的随机数
        ...

    @ti.func
    def some_member_func(self, ...):  # 非 static 的成员 function，直接用 ti.func
        ...

    @ti.kernel
    def integrate(self):              # 成员 kernel：做 symplectic Euler 积分
        ...

solar = SolarSystem(9, dt)            # 用法与普通 Python class 一模一样
solar.integrate()                     # 像调普通 class 方法一样调 kernel
```

逐条看要点。class 里可以有很多成员 tensor，和你在外面写没有任何区别，唯一的区别就是多了各种各样的 `self`；但一旦写成 class，可复用性就高了——下次使用只要定义一个 `SolarSystem` instance。`ti.func` 成员函数可以被一个额外的 `staticmethod` 修饰，含义和 Python 里的 staticmethod 一模一样，demo 里就用它生成一个范围内的随机数。class 里的 kernel 也和外面的 kernel 一模一样，唯一区别是带一个 `self`——就像 Python class 的方法与普通函数的区别一样。`integrate` 这个 kernel 做的是 symplectic Euler 积分。

用法也和普通 Python class 一模一样：constructor 收两个参数，$n$ 是行星数量，$dt$ 是时间步长；还可以直接给 class 里的成员 tensor 赋值——demo 里把中心天体的位置设成了 0.5、0.5；然后像调普通 class function 一样调 kernel。这个程序还是比较简单的，大家自己跑一跑、自己写一写 Taichi 的 class。

用 class 还有一个实际好处：可以在一个文件里实现 class，在另一个文件里调用它，这样就支持多文件了。直接散着写 kernel 和 function 的话，多文件是比较麻烦的事情；拆成多个文件之后每个文件小一点，维护成本就比较低。

有同学问 `ti.init` 能不能变成 kernel？暂时应该不行，我从来没这么用过，你可以试一下，但我猜是不行的。这里要把分工理清楚：`ti.init` 不是去初始化你的 tensor 的；class 里定义的是各种 member、field 和 kernel，真正的数据初始化交给 class 自己的 `initialize` 方法——它会把你的所有 tensor 初始化一遍。

### 元编程：把运行时开销挪到编译期

Taichi 提供了很丰富的元编程工具。它能带来四件实事：

- **几乎什么都能传进 kernel**：用户可以 pass 几乎所有的东西给 Taichi 的 kernel；
- **提高运行时效**：做了元编程以后，很多量在编译期就知道了，运行时间的开销可以挪到编译时间；
- **维度无关编程**：可以把二维和三维的模拟代码写在一起。想一想 FEM——二维和三维其实非常像，唯一的区别就是二维向量对三维向量、三角形对四面体、$2\times2$ 矩阵对 $3\times3$ 矩阵。用元编程很容易实现维度无关。好处是调试时间缩短：只有一份代码，很多时候二维的搞对了，三维的自动也就对了。以前写 C++ 的时候用模板元编程也能做到，但比较费事，Taichi 就非常方便；
- **简化标准库的实现**：Taichi 的标准库，包括底层很多东西，其实大量是用元编程写的。

先建立一个心智模型：Taichi 的 kernel 是懒惰实例化（instantiation）的。你定义了一个 kernel 但不用它，它就不会被编译；很多计算可以在编译期完成，运行的时候就少花时间。大家一般更在乎运行时间而不是编译时间——虽然现在有些极端情况 Taichi 编译有点慢，但一般情况下编译都是很快的。

顺带把概念摆正：每一个 kernel 在 Taichi 里其实都是 template kernel，唯一的区别只是它有多少个 template argument。你现在随手写的 kernel 也是 template kernel——只不过它有 0 个 template argument。

#### ti.template()：把 tensor 传进 kernel

先看最简单的用法——把 tensor 当参数传进去。`copy` kernel 做的事情是把 $y_i$ 设置成 $x_i + c$：

```python
@ti.kernel
def copy(x: ti.template(), y: ti.template(), c: ti.f32):
    for i in x:
        y[i] = x[i] + c
```

注意 type hint 写的是 `ti.template()`——**两个括号一定要加上**，不加可能会有编译错误。调用时传两个一维 tensor（大小最好一样）再加一个 offset 值就行。不用 template 的话，你很难把 tensor 当成 argument 传给 kernel。写模拟器的时候大家多半已经遇到过这个需求，知道 template 怎么用，就能少写很多代码。

除了 tensor，`ti.template()` 还可以接 class、class 的 instance、你的 function，或者各种数值。

但要注意一个问题：**template kernel 的 instantiation 是 overhead 比较大的操作**。看一对函数：

```python
@ti.kernel
def hello(i: ti.template()):    # i 可以接受任何东西，传不同值就会 instantiate
    ...

@ti.kernel
def world(i: ti.i32):           # i 是普通数值，不触发 instantiate
    ...

for i in range(100):
    hello(i)                    # 创建 100 个不同的 hello 实例
for i in range(100):
    hello(i)                    # 复用第一次创建的那 100 个，不再新建
```

`hello` 的参数是 `ti.template()`，传不同值就会被 instantiate：第一趟 `for i in range(100)` 会创建 100 个不同的 `hello` kernel；第二趟再跑同样的循环，会复用第一次创建出来的那 100 个。而 `world` 的参数是普通整型 `ti.i32`——它是数值而不是模板值，所以只会创建一个 instance。在这个 use case 下，`world` 明显比 `hello` 更好：`hello` 生成了 100 份 kernel。当然这个函数太简单，真跑起来性能差不多；但如果 `hello` 是一个非常复杂的函数，差异就出来了——它得编译 100 遍，很多时候编译 100 遍还是挺花时间的。

#### 维度无关：ti.grouped 把索引打包

刚才的 `copy` 只对一维 tensor 有用。如果想把 y 的所有值赋给对应的 x，而 x、y 可以是 0D、1D、2D、3D tensor——零维的都算——怎么办？语法是：

```python
@ti.kernel
def copy(x: ti.template(), y: ti.template()):
    for I in ti.grouped(y):
        x[I] = y[I]
```

关键在 `ti.grouped`：它把 y 的 index 全部拿出来做一个打包。`I` 用大写只是我的书写 convention，大小写无所谓；重要的是——如果 y 是 nD tensor，`I` 就是一个 n 维整型向量。tensor 的 index 可以直接接收整型向量，所以 `x[I] = y[I]` 一行通吃所有维度，少写很多代码。

`I` 既然就是一个普通向量，分量还能单独拿出来用：`I[0]` 相当于 i，`I[1]` 相当于 j（如果你的 tensor 是二维的话）。

#### 编译期反射与编译期分支

我们在编译期还能做 tensor size 的 reflection——查询这个 tensor 到底是几维的、shape 是什么样。reflection 的意思是程序检查自身的行为，也叫 inspection，翻译成"自省"可能好一点——"反射"这个中文翻译实在太奇怪了，平时很少听人这么说。大家可以运行 demo 程序，它会把 x tensor 的 shape 打印出来。

编译期分支用 `ti.static` 修饰 if 的 condition：

```python
if ti.static(enable_projection):    # 分支判断在编译期完成，没有运行时开销
    ...
```

它和 `if enable_projection:` 的区别就是：前者的 branching 在编译期进行，是一个没有运行时 overhead 的分支。比如程序里有一个 `enable_projection` 开关——projection 可以是碰撞处理——想让模拟器"处理碰撞/不处理碰撞"来回切，就这么做。如果你用 C++17，这就相当于 `if constexpr`。

#### 循环展开，以及"向量下标必须是编译期常数"

`ti.static` 还能强行 unroll 你的 for loop（循环展开）。例子：给一个"向量的 tensor"填充——每个 element 是一个三维向量，要把每个向量赋值成 0、1、2：

```python
@ti.kernel
def fill():
    for i in a:
        for k in ti.static(range(3)):    # 强行展开，k 在编译期就是 0、1、2
            a[i][k] = k
```

强行展开的用处很直接：loop unrolling 之后减少了 loop 本身的 overhead，可能拿到更高的性能。但还有一个更硬的理由——Taichi 有一条限制：**向量与矩阵的下标必须是编译期常数**。

```text
访问标量 a[i][k] 实际分两步：

  第一步  a[i] ：从 tensor 里取出第 i 个 element（一个向量/矩阵）    i 可以是运行时变量
  第二步  [k]  ：从向量/矩阵里取出第 k 个 scalar                    k 必须是编译期常数
```

第一步是从 tensor 里取 element，第二步才是从这个向量/矩阵里取出标量元素，而第二步的下标必须是编译期常数。这是 Taichi 一开始设计时就定下的 limitation，大部分时候影响不大；但如果你想用循环变量去访问向量/矩阵的元素，就得 unroll 这个循环——展开之后，循环变量就变成了编译期常数。这可能稍微有点绕，大家看程序、看编译错误，很快就能体会到为什么要这么搞。

#### 变量别名：variable aliasing

有的时候变量名特别特别长，你希望在局部给它做一个短的 reference。比如一个 kernel 要把 tensor_A 的每个元素喂给 some_function，结果写进 tensor_B 的对应位置：

```python
@ti.kernel
def some_kernel():
    A, B, func = ti.static(tensor_A, tensor_B, some_function)   # 创建别名
    for i in tensor_A:
        B[i] = func(A[i])        # 之后用短名就行
```

`A, B, func = ti.static(...)` 就是给 tensor_A、tensor_B 和 some_function 创建了别名，之后用别名就行，方便很多。这个例子里 A、B 只出现一次，其实不算好例子；真实的场景比如写 stencil——五点的 five-point stencil——tensor_A 在 kernel 里要出现 5 次，每次都写全名就太长了，先缩写成 A，后面用 A 就很方便。

两个高频疑问在这里一并说清。第一，**必须用 `ti.static`**：直接写 `A = tensor_A` 会出问题（语法错误），Taichi 语法要求必须加 `ti.static`，去掉以后语义就不明确了，编译不过——大家遵守这个写法就好。第二，通过别名改"新变量"会影响旧变量：这是 by reference 的 aliasing，不是按值拷贝，就像 C++ 里的 `&` 符号一样，加了 `&` 就是按引用去拷贝。

### 可微编程：让程序替你求导

一般的程序是在 evaluate：给定输入算输出，算 $f$ 就是算 $f(x)$。可微编程求的是 $f(x)$ 关于 $x$ 的偏导数，也就是 Jacobian。Taichi 支持 reverse-mode autodiff（反向模式自动微分）——名字有点长，但大家如果觉得 confused 完全没关系，这不是特别重要的概念，作为用户你只要知道怎么用。它能做的事就是反向传播：把你的 loss function——一个 scalar function——关于每一个元素的导数都算出来。

这个非常有用，前面已经见过了：求力的时候可以用自动微分求出力，而不是用手动求导。

求导数有两种方式：

- 用 `ti.Tape`：`with ti.Tape(loss=...):` 包住你的 forward kernel，它会自动生成并执行 backward，全自动；
- 用 gradient kernel：想要更多控制的时候用，这个后面会讲。

看一个 trivial 到极点的例子：定义 loss $L(x)$，x 是一个向量，$L$ 算的是 x 和 y 的差的平方的和，再乘 0.5：

$$L(x) = 0.5\sum_i (x_i - y_i)^2$$

它的导数很 trivial：$L(x)$ 对 $x$ 的导数就是 $x - y$——当目标 $y$ 取零向量时就是 $x$ 本身。

> **提示**：别把"导数是 x"当成普适结论背下来。对这个具体的平方差形式，$\partial L/\partial x_i = x_i - y_i$；demo 里 y 是固定的目标值，如果目标是零，梯度自然就等于 x。

怎么用它做优化？三步。

第一步，allocate tensor 的时候记得加上 `needs_grad=True`，这样它才会求出 $L$ 关于 $x$ 的 gradient。一定要注意：不加 `needs_grad=True` 就不求 gradient——很多时候你并不需要求导，所以默认是不开的。

```python
x = ti.var(ti.f32, shape=n, needs_grad=True)   # 要求导的变量必须 needs_grad=True
y = ti.var(ti.f32, shape=n)
L = ti.var(ti.f32, shape=(), needs_grad=True)  # loss 是标量
```

第二步，定义 forward。`reduce` kernel 基本和 $L(x)$ 一一对应：把差的平方乘 0.5，全部 accumulate 到 $L$ 上。注意 Taichi 里的加等于号是**原子的** `+=`。

```python
@ti.kernel
def reduce():
    for i in x:
        L[None] += 0.5 * (x[i] - y[i]) ** 2    # 原子的加等于
```

第三步，在 Tape 的作用域里调 forward；Tape 生命周期结束时自动做 backward，求出 `x.grad`；然后做 gradient descent，把 x 更新到更接近目标值的位置——这是做 optimization 最简单的搞法。

```python
with ti.Tape(loss=L):    # 作用域内正常跑 forward
    reduce()

for i in range(n):
    x[i] -= x.grad[i]    # gradient descent
```

Tape 的机制画出来就是：

```text
forward：with ti.Tape(loss=L): 里调用的每个 kernel 都被 Tape 记录下来
            reduce()  →  ...  →  ...
backward：Tape 生命周期结束时，按「颠倒的顺序」自动调用每个 kernel 的 gradient kernel
            ..._grad()  →  reduce_grad()    回放完毕，x.grad 就绪
```

说白了就是创建一个磁带，它记录你的 kernel launch；launch 完了以后，以颠倒的顺序去调这些 kernel 的 gradient kernel，你就可以做这样的求导数操作。就这么多东西，非常简单。

跑一下这个 demo，叫 `autodiff_minimization`。画面比较无聊：就是 loss 在不断下降。L2 loss 加上定步长的 gradient descent 本来就是一个指数下降的过程，所以收敛非常快。

顺带回答两个常被问到的问题。`ti.Tape` 本质上是不是 backpropagation？对，exactly 就是 backpropagation——做过 deep learning 的话，它就是 backward pass。那 Taichi 的反向传播能不能直接嵌入 PyTorch？可以的：用 `to_torch` 和 `from_torch` 把数据在两边倒，再定义一个 PyTorch operator，就能和 PyTorch 交互了。直接敲 `ti example` 会把所有 example 列出来，里面能找到和外部数组交互（interacting with external arrays）的例子；PyTorch 的专门例子一时想不起来在哪，但确实有。

### 可微编程的两个应用

可微编程有两个 application。第一个很简单、之前已经提过；第二个更有意思。

#### 用势能的导数求受力

对势能关于位置求导，我们就知道顶点的受力——受力就是势能对位置导数的负值。这里用可微编程主要是简化数学上的推导：用不着去手推那些乱七八糟的导数了。上一部分演示过 FEM 的例子，这里再跑一个 MPM 的：它是 MPM 里叫拉格朗日力（Lagrangian forces）的模型，和 FEM 非常非常像。

它和 FEM 最关键的区别在碰撞。MPM 由于有一个背景网格，所以能够在背景网格上额外做碰撞处理。FEM 很容易自相交（self-intersection），自相交非常非常头疼，处理起来非常讨厌；而在 MPM 里，物体自己和自己的相交会在背景网格上自动做一些碰撞处理，你就不用显式地去处理碰撞了。

这个 demo 计算本身应该是 60 FPS，但可视化非常卡（可能跟我开着直播也有关系），为什么画出来这么卡我一直也没搞清楚。细节等到 MPM 部分再展开，大家可以自己先跑一跑。

#### 优化整个物理过程：DiffTaichi

如果你的受力是手动求出来的——每一步都没有用 Autodiff——那 Autodiff 这台机器就省下来了，可以拿去求**整个物理过程**的导数。求出整个物理过程的导数有什么用？你可以做物理系统初始状态的优化，或者做物理系统控制器（controller）的优化，非常有意思。

看我之前做的研究项目 DiffTaichi。现在这个工具链已经非常成熟，熟练的话两三个小时就能写出一个可微物理模拟器。我们之前用它写了十个 differentiable simulator，证明 DiffTaichi 确实是一个可用的东西。

头一个 demo 是双足机器人：两条腿，每条腿上有两块肌肉，通过肌肉的收缩和拉伸相当于迈开腿，迈开腿就能往右边动。控制是用神经网络来做的。没有 DiffTaichi 的时候，你得用 Reinforcement Learning（强化学习）去学神经网络的权重，效率非常低；有了 DiffTaichi，可以直接用梯度下降来优化。梯度下降的导数导向性非常非常强，一般一二十个 iteration 之后，机器人基本上就能动了。

剩下的 demo 快速过一遍：

- **2D 版本**：MPM 加上 DiffTaichi，differentiate 整个 MPM 的过程，让机器人朝前走；
- **3D 版本**：MPM 能自动处理水和 elastic object 的耦合，所以可以往机器人身上加上一些水，移动慢一些，但还是在朝前移动；
- **水面**：height field 的 water simulation，白色表示水面更高、黑色表示水面更低，可以认为是水波荡漾的模拟。我们求一个初始水波，使得它经过一些 time steps 之后形成一个太极 pattern——相当于求一个反向的模拟：找出一组初始条件，让模拟的结果正好是想要的图案；
- **对抗样本**：之前一段时间非常火的东西。我们求一个初始水面的 height field，走"可微水面模拟器 + 可微水面渲染器 + 可微神经网络"这么一个三阶段的可微程序，求出一个水波，使水波的折射加到松鼠的图片上以后，VGG（图片识别网络）认为这张松鼠图片是鲸鱼——而且信心相当高：99.91% 是鲸鱼。这就是对抗样本，说明神经网络有时候鲁棒性不是特别好；如果你知道它的导数，就可以做一些攻击；
- **刚体**：可微刚体物理模拟器。机器人身上装着各种弹簧，弹簧拉动它朝前走，本质是个弹簧质点系统。弹簧这种比较简单的情形收敛非常快，一般一二十个 iteration 就收敛，大家可以下载下来跑一跑；
- **台球**：机器学习打台球——优化白色球的初始位置和速度，使得蓝色球最后能到达黑色点。

对抗样本那个三阶段管线值得单独画出来：

```text
初始水面 height field
   │  ① 可微水面模拟器（DiffTaichi）：演化若干步得到水波
   ▼
水波
   │  ② 可微水面渲染器：把水波的折射叠加到松鼠图片上
   ▼
被水波折射过的松鼠图片
   │  ③ 可微神经网络：VGG
   ▼
判定：鲸鱼（信心 99.91%）
```

整条链上每一环都可微，梯度就能从"VGG 认为这是鲸鱼"一路传回"初始水面长什么样"，于是优化器可以专门挑出那种能把松鼠骗成鲸鱼的初始水波。

#### 内存代价与 checkpointing

写可微程序有一个绕不开的代价：每一个 time step 都得记下来。不能只开一个 time step 的 tensor 记最新的一步，必须把整个模拟过程全部记录，所以内存占用一般比较高。本来 n 个 particle，给每个 particle 的位置开一个一维 tensor 就够了；用可微编程就得开一个二维 tensor——第一个维度是多少个时间步，第二个维度才是多少个 particle。

空间吃不消怎么办？用 checkpointing，这是 auto-diff 里常用的技术，核心是空间换时间：

| 空间占用 | 时间代价 | 说明 |
| :--- | :--- | :--- |
| $O(n)$ | $O(n)$ | 不做 checkpointing：每个时间步全记 |
| $O(\sqrt{n})$ | $O(n)$ | 常规档：空间压到根号级，时间量级不变 |
| $O(\sqrt[3]{n})$ | $O(n)$ | 再压一档，常数项变大 |
| $O(\log n)$ | $O(n\log n)$ | 极端情况：空间压到对数级，时间多一个 $\log$ 因子 |

本来计算 $O(n)$、空间 $O(n)$；用了 checkpointing，空间可以降到 $O(\sqrt{n})$ 甚至 $O(\sqrt[3]{n})$ 而时间量级不变，极端情况下空间压到 $O(\log n)$、时间变成 $O(n\log n)$——用空间换时间，按需选择。

### 二维可视化：ti.GUI 就够了

### 三维结果：PLY 输出与 Houdini

真正值得多说几句的是怎么可视化你的三维结果——很多同学已经迫不及待想从二维挪到三维了。助教团队上周非常辛苦、非常给力地开发了一个 `ti.PLYWriter`，文档里会讲怎么输出 PLY 格式。PLY 是一个可以二进制、也可以人类可读的三维数据格式；有了 PLY，你就可以用 Houdini 把它打开。

跑一下 export PLY 的 example：当前目录下会出现一大堆 `example.ply`。打开看它的内容，开头是一个 header，过了 header 之后就是二进制，所以存储效率是比较高的；当然你也可以选择输出 ASCII 格式，就是人类可读的格式。

一般来说，搞 simulation 是用 Houdini 来打开这些东西。Houdini 可以在官网上下载到，各平台都支持，学徒版（Apprentice）是免费的，还是非常好用。顺便说一句，Houdini 是现在电影工作室里非常常用的特效制作软件，它本身就可以做各种各样的模拟。

引入刚才的 PLY：点 File → Import → Geometry，到刚才那个目录，Houdini 会自动识别出这批 example 是一个序列，打开之后把底部时间轴改成 0 到 9（我们那批一共十帧），然后拖动进度条就能看到粒子在动，点播放按钮就能播放粒子运动——这已经是一系列动画了。

现场演示时，这台"年纪大了"的电脑一直在转菊花，加载等了好久，拖动也卡——大家正常的电脑上不会等这么长时间，正常情况下拖动是非常 smooth 的。这个软件比较重量级，大家自己装一个 Houdini、自己点一下播放就行。
