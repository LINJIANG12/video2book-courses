所以我可以讲一下刚才那个 QRgen 的暴毙。AI 是怎么暴毙的？它是一个非常明确的需求：我要一个 QR code 的 Excel，然后我只是使用 Excel 2019 兼容的公式，把输入的任意一个字符串先用 Base64 编码，然后转成 QR code 动画，每一帧是什么什么。当然我开始让 AI 做的时候，还发现这个任务经常做着做着就停下来问我。然后我说不要，这个很容易失败，你不要问我了，必须把它做成为止。

但是很遗憾，AI 对这个需求的理解是不到位的。我说清楚了，确实我就是要作这个东西。但是，这是 GPT-5.6 啊，GPT-5.6 依然误解了我到底要一个什么东西。GPT-5.6 说得对，因为它看到了我的完整的 slides，但我没有告诉它我是怎么做的。AI 哪里容易犯错呢？AI 容易在小 corner case 上犯错。GPT-5.6 第一秒钟就被带歪了，它希望做一个对于任意的 $s$ 都满足正确性的东西，这就已经错了。不是的，软件工程的第一步：不要扩大，做最简单的东西，不会失败。它没有理解这一点。

事实上是这样的，我后来做了一个受控的实验。因为第一个版本是我带着 AI 做的，所以做的时候还比较顺利。后来我就直接把 specification（就这个）告诉 AI。GLM-5.3 第一次思考了 25 分钟，然后开始疯狂地输出，写了超过 32k 的 output token，直接把我的 Claude Code 乾暴了。它说你已经超过了默认的 output 限制了，然后被截断了，然后它再跑。总共跑了——我没有监管——跑了 6 个小时才跑完，但是对的。

所以智谱它一直说自己厉害的地方是它可以做 Long-Horizon 的任务，是对的，它后续训练确实，GLM-5.3 在 Long-Horizon 任务上真的做得很好。

而 DeepSeek-V3 Pro 也是晚上放着跑的。它已经没有办法遵循指令了，我第二天早上看的时候，它给了一个 Base64 是硬编码的，它用 Python 算了一个 Base64。这明显就不符合这个指令，把一个输入的任意字符串先用 64 进制编码，正常人的理解应该是 Base64 编码是用 Excel 公式来编码的。它已经不听指令了，它是用 Python 算了一个 Base64 贴到那个公式框里。如果我的字符串改了，它的 Base64 是不会改的。然后我就骂它了。我骂完以后，它那个 chain-of-thought 就说：“This is a fundamental design flaw, we need to rethink.”

不管怎么样，它们两个最终都完成了任务，所以 Agent 完成任务能力很强。但它们生成的都是没有办法继续维护下去的 AI Slop。它和 1.nju.edu.cn 的死法是完全一样的，就是软件工程里面最经典的死法：上来我知道需求了，我把这个需求实现了就好了，直接就陷入了维护的泥潭。他们没有想一个好的软件架构，使得这个软件能够——有一个比较夸张的说法是，我们能不能做一个软件生存 100 年？100 年的时间里面软件会发生很大的变化。你想过去没有 100 年，50 年操作系统发生了什么样的变化，图形界面发生了什么样的变化，用户界面、应用程序发生了什么样的变化。有没有一个软件能生存 100 年？还不知道。但是你看连 GPT-5.6 都还不知道，其实我们需要一个好的架构才能完成这个任务。

我是怎么办到的呢？你们可以想一下，如果你们要一个 quick quiz，如果你们要实现这个 QRgen，你们会怎么写？怎么 prompt AI？

实际上我只用了少量的 prompt，GLM-5.3 在 200k 上下文里面就完成了第一个正确的版本。当时是我升级了 GLM-5.3，我就想测试一下它的能力。

我干了这样的一件事：我让它设计各种各样的 Python 类，就有点像编译器一样。比如说，我要设计一个 Python 的函数叫 `XOR`，一个符号系统，因为这里面涉及位运算。然后这个东西既可以在 Python 里面直接执行，又可以翻译成 Excel。也就是说我做了一个像编译器一样的基础设施。然后我有 `XOR`、`CONCAT`，也就是说我做了一个中间语言。有点像如果你们今天做 AI Infra 的话，你们会需要 Tile-lang 这样的中间语言。我让它先设计一个中间语言，这个中间语言既对 Python 友好，也对 Excel 友好。

然后我只需要验证的是，我的每一个翻译都是正确的，到 Excel 翻译是正确的，到 Python 的结果是正确的。然后我可以在 Python 世界里面验证我的 Base64 编码算得对不对，我的二维码的每一个像素算得对不对。然后我再单独验证每一个东西和 Excel 的公式翻译的正确性、兼容性。最后一把头生成就直接正确。

代码非常的干净，也不长。可能长，但是维护性远比——大家可以看一下 AI Slop。GLM-5.3 的 build Excel，我真的觉得 AI 还是挺厉害的，无穷多的硬编码。

所以在今天，你还需要深层次软件工程，需要这门课。我作为一个软工人员，其实是做软件工程的，把我的毕生所学……虽然我觉得 AI 应该也懂的，但我不知道为什么，可能是因为后训练的原因，使 AI 上手解决问题的欲望太强了，导致了做得还不是特别好。

这里面核心的问题是什么呢？当我们要用 AI 解决问题的时候，我们有三个空间。

第一个空间叫 Intention，是你的意图，就是你脑子里面想的是什么。比如说，老板说“我要做一个国民级的应用”，这是他的 Intention。或者说“我要做一个小程序，给我挣一个亿”，这是那个 Intention。小程序可能有一些情怀：“同学们点外卖不方便，我要做一个点外卖的小程序，挣一个亿就可以了。”在 Intention space 里面，这已经很大了。有的人想做外卖，有的人就想做 AI 读论文，AI 梗图鞋。

在 Intention space 里面，每一个 Intention 都有很多种可能的实现，这是 Specification。Specification 就是说这个程序的功能是什么，选用什么样的架构，满足什么样的要求。它有几个界面，每个界面有什么功能，比如这个就是 Specification。

以这个例子，Intention 是“我要造一个能够偷出、二维码偷出数据的 Excel”，这是一个 Intention。然后 Spec 就是刚才说的一句话。

你看到，我的这个 Spec，选用不同的架构、选用不同的实现方式，像刚才那种实现方式，就会带来巨大的差别。而同样都是满足 Spec 的，还有不同的 Implementation。哪怕是满足同一个 Spec 的，都有大量的 Implementation。

所以软件工程真正的 gap 就在于这些东西之间是有 gap 的，都是有 gap 的。

因为在你的 Intention space 里面，提需求的可能是老板、可能是甲方，他没有任何计算机的经验。校长说“我们要一个教务系统”，公司说“我可以搞定”。Intention 就在这，我要教务系统，要把学校里面所有同学相关事情的信息化，没了，就这一句话。

然后在 Specification space 里面又有好多好多的选择，不同的方式。这个界面到底怎么呈现？我觉得这个界面设计得很糟糕。然后到界面完了以后，这个数据库的 schema 应该怎么定？到底应该分哪几张表，每张表里面有哪些列？我到底要选择 key-value 型的数据库，还是关系型的数据库？每一个选择都会带来截然不同的结果。

这是一个软件工程在很早的时候的一个梗图。它讲的就是这个 gap。在各个维度上，程序员所想的，和产品经理所想的，和客户所想的，是完全不一样的。客户是这样解释他的需求的，Project Leader 是这样理解它的，分析的人又是这样想的，宣传的人又是这样宣传的，最后实际上 customer 要的是这个，但是最后造出来的是这个。这就是这个梗图。

造成这个的根本原因，实际上就是这些 space 之间的 gap。而当我们谈软件工程，不管是软件工程还是深层次软件工程的时候，我们要做的就是补上这些 gap。

而今天，这些 gap 是怎么补的呢？模型用的是猜。模型就说“既然说了这句话，那我猜应该是这个吧，我就去实现”。为什么呢？因为后训练的时候，模型是有 reward 的，我们每个人都是 reward hacker。模型受到奖励，任务做对了、做完了、测试通过了，就会得到奖励。所以它就会形成一种倾向，它会疯狂地立即上手去把这个任务尽可能快地完成。因为做慢了要挨骂，对吧？它能够越来越多地做一些简单任务，这当然是好事，但是和我们人解决问题的方式还是不一样的。你看作为计算机或者软件工程的学生，你们是怎么学习的，怎么弥补这个 gap 的？你到大一第一门课是什么？C 语言程序设计。所以你先学的是这个东西里面有什么。

你跳出你学习的框架。你现在学的是这个 implementation space 里面有什么东西，把这里的东西都弄得非常熟练了，“这个需求可以这样实现，这个需求可以这样实现”。然后你再去上什么软件工程课，这样一点一点的把你对这件事情的任务给补全。

但是，在 AI 时代这件事情当然是发生了变化，对吧？你既要阻止 AI 去乱猜，你又要尽可能的发挥 AI 能够从 A 到 B 的能力。这个时候，我想这就是我这个学期要讨论的讨论的问题。

讨论的问题就是我们的生成式软件工程想要想要告诉大家的。我开个头，对吧。《人月神话》（*The Mythical Man-Month*），大型动物一旦陷入这个焦油坑就很难逃脱，对吧？它像泥潭一样陷进去以后，而且濒死的动物又会引来各种掠食者，然后它们也进到焦油坑，它们也出不去。

这里面有一个很经典的论断，是如果一个团队已经开始，或者一个软件产品已经开始失败了，你加进去更多的人只会让它变得更失败，不会变得更成功。也就是说，就跟刚才那个 QRJ 一样，当一个产品已经开始，AI 已经开始产生 slop 的时候，你投入更多的 token，你也只会让它变得更失败。AI 会不断地在它那个失败的东西上面再往上浮起来一点、浮起来一点、浮起来一点，直到你再也付不起那个 token 为止。

然后你看，教务系统不就是这样的吗？随着工程不断地，我觉得每一年你打开那个教务系统，你都发现它增加了功能，你们也发现了？然后我的感受就是学校又花了很多纳税人的钱。Anyway，这也许多半是坏事，因为他促进了经济的发展。

然而软件工程，软件工程研究的就是怎么样在这个 gap 实际存在的情况下，把一件足够大的事，就是一个真的，对吧？刚才我们讲的是一个很小的事。教务系统是一个相对来说比较大的，就你真的去能够挣几百万、几千万的上市公司的，不是上市公司，你是真的可以挣到很多钱的一个产业级的产品。然后再到你真的要做一个国民级的新的新的东西，它有一套方法论。然后这个方法论就是这些人在投入了 billions of dollars 里面得到的教训，对吧？他管理了很多人，每一个人都很聪明，结果陷入了焦油坑。软件工程是有技术的，对吧？因为打个比方，南大有很多做软件工程老师，比如说他做什么程序分析、测试的，那他就是说如果你生成了一个，在 implementation space 里面已经有一个代码，我能不能自动地为它生成更多的测试用例？或者生成一个代码的审查的东西，在这个代码不满足 specification 的时候，或者潜在不满足 intention 的时候，我能够给你一个 warning。他就是做了一件非常非常在这个 big picture 里面非常非常微小的事情。

然后我们有的时候，比如你们在课题组里面开始加入课题组做研究的时候，你们就看到那个非常微小的事情，忘记了这个 big picture 其实是这样的，对吧？软件工程是一个有技术，也有人类学、也有社会学、也有管理学的部分。然后恰好我觉得在生成式软件工程里面把它们变成了 AI。对吧，你管一个一堆不会和你抬杠、只会“You are absolutely right”的，他会听你的话的人。在软件工程里面他要研究，这个人不听你话怎么办？对吧，你怎么样管控这个团队的风险？这个人离职了怎么办？跳槽了怎么办？到竞争对手去怎么办？这都是软件工程要研究的。

然后如果你去看比如说一个软件工程的研究领域的话，它也是一个非常广的，对吧？AI for SE, SE for AI，架构、设计、可靠性、演化、这个软件能不能长期生存下去、human social aspects、需求，这个特别特别重要。因为越早的时候这个 gap 是放大的，你在这里微小地变一点，你会在甚至这里产生巨大的变化。所以一般来，这些大型的软件系统都是在这个点上面出错了，没有做好，导致了整机全部的崩盘。

这里面有一个我觉得是我们现行教育体系的一个很大的问题，你们从高考过来到现在，你们所有的考试题都是分钟级能解决的，对吧？假设你做大作业你就可以用豆包摸鱼。那你所有上了考场的题目都是如果人五分钟解决不了，那这个题它一般赖说就不会出了。所以你们长久以往你们训练的就是解决，就和你们训练的那个 reward 和 agent 训练的 reward 是一样的。你能不能五分钟解决？agent 能不能五秒钟解决？

最后是 agent 它有更多的数据，它有更明确的反馈信号，所以它做得比你好。如果你没有一种很强的去好奇心，想要知道这个世界是怎么运行的，一个产品到底是怎么开发的，你很有可能你没有这种 self-motivation，你就没有去训练自己去解决这种 long-horizon 的问题。最后就是你解决 long-horizon 的问题还不如 agent。

这是一个，当然我觉得所谓软件工程挺好的，它有些课，我知道有些软件工程同学在抱怨他们的课程，说我上了文科，然后怎么怎么怎么。当然你回过头来，在如果你能把技术映射回这些文科的东西的时候，你会发现其实软件工程还是，这就是一个文科嘛，就是一个管理学，这是一本管理学的书。在它里面确实有很多真实的、有趣的这些东西。

实际上在大人语言模型的时代，软件工程失败的定义没有变，就是从 intent 到 specification 到 implementation 的翻译错了，对吧？要么就是 intent 和 spec 之间不满足，我做了一个东西其实不是我要的。然后我做了一个实现，但是不满足我的 specification，比如正确性或者性能。

但是今天模型模型，因为它有这种 reinforcement learning，它对于这种真正的长程信号的 reward 还是做得不够好的，它更多还是在怎么样机械地完成任务。所以你会发现不管是 GPT、Claude 的 Faber 还是我们现在用的比如 GLM 或者 DeepSeek，它在面对这个 Excel 问题的时候，它都不会去想让像我一样先去设计一个 DSL。对吧，虽然这个模型有足够的智能可以设计一个非常好的中间语言来把这个问题非常干净漂亮可维护地解决，但是 AI 的第一反应就像大家一样，它已经被训练成做题家了。我们现在还没有，现在我觉得还没有把 AI 怎么样变成一个好的设计者，大家都说 AI 现在最缺的是品味嘛，这个好的工程品味给训练出来。
