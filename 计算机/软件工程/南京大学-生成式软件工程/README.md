## 怎么学

课程主线是一条从「怎么学」到「怎么造」的完整链路：**AI 时代的能力分工与学习范式 → 提示词与上下文工程 → 软件仓库与版本控制体系 → 软件工程的本质与第一性原理 → 需求工程与架构设计**。建议：

- **先建立新的能力坐标** → 从模块 01 前两章读起，弄懂「把会做事交给 AI」到底意味着什么、自己该把功夫花在哪；这两章还给出整门课的知识地图，后面几册都是它的展开
- **攻克上下文工程** → 重点研读模块 01 后两章，提示词只是入口，真正的难点是注意力预算、上下文窗口与人机协作的边界
- **吃透版本控制体系** → 模块 02 是本课分量最重的一册，四章连成一条线：项目为什么要「有记忆」→ Git 作为可审计工程系统 → AI 时代为什么要重新设计版本管理 → 多 Agent 并发下版本控制如何跟上
- **建立历史观** → 模块 03 两章回答「软件都快没了，为什么还要谈软件工程」，并从瀑布式返工讲到可验证演进的第一性原理
- **落到工程实践的起点** → 模块 04 从「软件为什么一点都不软」讲起需求挖掘与架构设计的完整来路，以 `getopt` 到事件溯源的演化作结
- **考前/面试速查与架构复盘** → 直接查阅 `notes/` 目录下的 5 篇速查笔记
