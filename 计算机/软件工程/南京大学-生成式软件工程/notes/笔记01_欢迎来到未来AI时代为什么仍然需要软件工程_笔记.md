# 欢迎来到未来AI时代为什么仍然需要软件工程

## 把昂贵的能力变成日用品

* **昂贵变日用品（计算机史主线）**
    * > **定义**：把昂贵的能力变成日用品，是计算机发展史上最主要的一类变革。
    * 1975 年 Altair 8800，第一台 PC 机。
    * 1990s 的 ICQ（"I seek you"）把随机加到世界另一端的人变成日常，腾讯山寨版 OICQ 后改名 QQ。
    * 2010s 移动互联网，一夜之间菜市场卖菜的人都有了支付宝和微信两个码。
    * 2022 年 ChatGPT，有人说 AI 是人类历史上增长最快的产品。
    * ICQ 时代随机加到的往往是对端母语者，语速快、消息多，当时只学了一点英语的人完全跟不上。

* **两种焦虑**
    * 第一种：每门课开卷、AI 答题全都答对，走出校门发现自己第一个就被 AI 取代。
    * 第二种：认真听每一堂课、认真做每一次作业，四年下来确实学会点什么，但学会的东西 AI 都会做。
    * > **结论**：把能力交给 AI 之后，"学过"这件事本身不再构成任何区分度。

* **零分简历**
    * 典型形态：一大堆实习、一大堆奖项、一大堆论文、一大堆"在投"，个人信息被换成 Unicode 方块隐去。
    * > **易错点**："在投"等于"不存在"，因为看不到。
    * 额外的负分项：没有 GitHub 链接、没有个人主页、没有一天 preprint。
    * 后果是你和竞争者无法区分，因为所有人都是这个形状。

## 人最后剩下的优势

* **信息差（information asymmetry）**
    * > **定义**：信息差 = 你掌握而竞争者不掌握的信息；有信息差，才能做别人做不到的事。
    * 例：手里有一份别人都没有的往年试卷，就能在竞争当中胜出。
    * 这种信息差在学校里表现为恶性竞争，在社会上广泛存在，是不能说可悲但要进步必须有的东西。

* **你做得到**
    * 优势不是"你可以做到 AI 不能做的"，而是"你能驾驭别人驾驭不了的东西"。
    * 大学真正教的是把一个人变成更好的人，毕业时能说"我有一个别人没有的能力"。
    * 简历上不该写"我学会了什么"，而该写"我有一个别人没有的信息、并且我真的做成了"。
    * 这两件事恰好是 agent 能帮完成、但只有你能决定要不要完成的事。

## 上课就是一场演出

* **一切皆代码（everything is code）**
    * > **定义**：世界上的一切都可以用代码生成，桌子用 Computer Aided Design (CAD)，椅子、电脑同理。
    * 最终形态是以切片的方式得到一个完美的程序：要点、逻辑、第一节课应该怎么上沉淀成一个程序。
    * 程序可以换维护者，比如把某门课的录像整理成切片，交给全世界的人维护。
    * 你想要定制什么样的操作系统就能定制成任何样子，这颠覆了大学教课的方式。

* **内容流水线：Markdown 是 source of truth**
    * 讲义是上课之前先写好的演讲稿，相当于课前先想好该讲什么、举什么例子，等于预先约束 AI 做什么。
    * make slides 这个 skill 从写好的 Markdown 演讲稿里选出一个 snippet，添油加醋地扩写，产出 Markdown slides。
    * 播放出来的 slides 里紫色部分是模型额外加上去的内容，配图全部由 AIGC 生成。

* **AI 梗同学**
    * 生成三个 sub-agent 并赋予不同的 personality，让它们在隔离的上下文里工作，彼此不可见。
    * 主 agent 最后回来汇总，产出讲义和 slides。

```text
              ┌──────────────────┐
              │     主 agent      │
              └───┬───┬───┬──────┘
     派发（隔离上下文，彼此不可见）
          ┌───────┘   │   └───────┐
          ▼           ▼           ▼
     sub-agent A  sub-agent B  sub-agent C
     personality 1 personality 2 personality 3
          └───────┬───┴───┬───────┘
                  │ 汇总 │
                  ▼
             讲义 / slides 产出
```

* **算力换智力与盲评**
    * 方法是换几个版本的提示词，每个版本的提示词都重新生成一次。
    * 再让 reviewer 或另一个模型盲评，挑出质量比较高的那一版。
    * > **结论**：不需要一个"更强的模型"，需要的是更多算力加上一个会挑的评审；质量可以用并行采样加盲评换出来。

* **课程的数字永生**
    * 有一部分是即兴的，而即兴就意味着不完美，所以课后必须 review 今天的表演，例子可能不恰当，可能还有更感同身受的案例。
    * 因为录像了，把录像切片、重新整理成片段，再回到这门课里，让它变得更丰富，这就是课程的数字永生。

## 三条 policy

* **禁止古法编程**
    * 允许不上课、不看直播，在课上跟着实践。
    * 出发点是撕开一个小小的口子：改变一个体制很难，从上而下传导不会那么快。

* **token 自费**
    * > **结论**：手头没有 token、没有付费 token 的，应该立即退学。
    * 课上除了 slides 生成用了更聪明的模型，其余全部都是 DeepSeek-V3-Flash，也就是用足够便宜、智能相对有一些的模型完成事情。
    * > **提示**：坚持用便宜模型是因为这门课要教方法论，不是某个模型的极限能力；一个便宜到你愿意自费、愿意反复重试、愿意犯错的模型，才是真正把 agent 用熟的前提。
    * CS 学生习惯夜里工作，夜里用 DeepSeek 比较便宜；白天上课是两波峰，回去做作业时是两波谷。
    * 建议每人去 DeepSeek 充 100 块，实在有困难的同学可以联系老师想办法。

* **通过 / 不通过**
    * 申请课程时考核方式填的是通过和不通过，但根据教务反馈，专业选修课不会做成这样，参照对象是"形势与政策"这类课。
    * 原因是我们还不知道评判标准，也无法限制大家用什么模型；同一个任务，Claude 3.5 就比 DeepSeek-V3-Flash 又好又快。
    * 建议的实现是做一个自己的 email 管理系统：用指定邮箱发邮件给你，你把邮件回回来；也可以做一个 vibe code 的服务，跑在宿舍一台一直常开的小电脑上。
    * > **结论**：在这个时代分数已经变得不那么重要，真正重要的是最后找工作或保研那一刻，投出去的简历上有什么东西。
    * 对老师自己来说，简历里有一篇发表论文反而是减分项。
    * > **注意**：一个有点恐怖的推想是每个人电脑上都装监控，那 AI 就能评判你大学四年到底度过了一个怎样的四年，包括你摸的每一条鱼、看的每一部不想让别人知道的小电影。

## 大语言模型与 Agent

* **大语言模型（Large Language Model, LLM）**
    * > **定义**：大语言模型就是一个学到的概率分布 $P(\text{下一个 token} \mid \text{已有的上文})$。
    * 类比概率统计课抛硬币：抛六次加起来是 40，问第一次抛出 1 的概率是多少，是同一类题。
    * 输入可以是很长的文本（一本书），也可以是图像；输出一次一个字符，串行地一个接一个。
    * 模型很大、见过世界上所有的东西，训练很难，这是现在 Frontier Lab 这么强的原因。
    * > **结论**：这门课站在使用者视角，你不需要任何大语言模型的知识；打开 DeepSeek 的网页 API，你就已经在体验大语言模型。
    * 能力的量级变化有实例：2023 年 GPT-4 时代，一个 prompt 就能给 GCC/LLVM 找到 150 个 bug；到了 o1 的时代，这件事就是一句话，不需要再为 GPT 做特别调整。

* **Agent loop**
    * > **定义**：Agent 就是让语言模型输出一个特殊 token（"能不能调用一个 Bash 程序"），Bash 跑完后结果再送回这个 Agent loop。
    * 出现顺序是先有推理的模型，然后有 coding 的 ReAct 式的 Agent。
    * 前提是模型能输出越来越长的文本、也接受越来越长的上下文。
    * 循环不终止，所以可以给它比较复杂的任务，让它不断尝试。

```text
    ┌───────────────────────────────────────┐
    │            Agent loop（一直转）        │
    └──┬─────────────────────────────┬──────┘
       │ 特殊 token：「调用 Bash」     │ 工具的输出：stdout、
       │                             │ 报错、文件内容……
       ▼                             │
    真实执行 ─────────────────────────┘（结果回灌，继续转）
```

* **Agent 怎么改系统**
    * 配置了 Sway 窗口管理器为课堂展示做优化：对比度高、顶栏全部去掉。
    * `ls` 自动换成 `eza`，`find` 自动换成 `fd`，`top` 也被定制成更 fancy 的样子。
    * 全部配置只用一个 prompt："把我现在的命令行终端，包括我的系统 Sway，都配置成这个现代的、比较好用的样子。"用的是 DeepSeek-V3-Flash。
    * 一年前上操作系统课时 Agent 还经常出错、任务完不成就停下来；现在它不停在配置里改改改，错了就试别的方法。

* **next-token prediction 与 diffusion**
    * next-token 预测是串行的，每一步只依赖上一步，被认为是一个效率很低的模型。
    * diffusion 类语言模型从一片纯随机噪声开始，迭代去噪、一遍遍重新审视整段文本，最后生成一段很长的完整的东西。
    * 类比是做梦：一点一点把一个东西看得越来越清楚。
    * 好处是可以把上下文回过去改，随时把一个很长的上下文裁短。
    * > **结论**：无法预测哪条路线、哪一种模型会胜出，但可以确定的是这个世界肯定会变得非常不一样。

## 上手方式与真实案例

* **两个最小原则**
    * 第一是现在就开着用，第二是随时问它。
    * 配置上可以直接写 `agents.md` 之类的配置文件，agent 因此知道自己是谁、在哪个仓库、知道什么。
    * > **结论**：在这个之上，你的想象力限制了 agent 的上限。

### 把装机变成一句话

* **装机仙人退休**
    * 指令是一句话：去 mirrors.nju.edu.cn 上找一个 Debian 13 的镜像，把它装到 U 盘上，确保这个 U 盘可以启动，然后用模拟器验证。
    * Agent 真的在 QEMU 里启动，看到了登录界面并确认能登录；按要求创建用户名和密码，验证完成后交付。
    * > **提示**："用模拟器验证"这四个字是这条 prompt 里最值钱的部分；没有验证要求，agent 只能给你一个"看起来装完了"，有了验证要求它必须自己把系统真正跑起来，拿登录成功当证据。
    * 装完之后又让它生成一份当前系统设置的快捷键文档，解决不会用 tiling window manager 的问题。
    * 所有配置，包括中端 NeoVim 的现代配置，都没看过任何配置文件，全部用自然语言完成。
    * > **结论**：装机仙人已经彻底被 AI 取代了。

### 把杂事交给 bot

* **邮件 bot**
    * 数据库里存着历史上回过的所有邮件，新邮件到达后自动标为已读，并自动用本人口吻写好回复草稿。
    * 附件（发票）自动保存到指定的归档位置，这些都是写好的 instructions。
    * 在手机的 Apple Reminders 里加一条 To Do："帮我把今天的发票打印出来。"
    * 点 go 就 commit，多了一个 To Do 事项，后台自动处理打印机，完成后推送通知经 Reminders 送到手表震动，报"打印完了"。
    * 边界是只把放心的、放心的事情交给它；大部分 routine 的回复仍然需要改。

### 学习资料的替代入口

* **读书、读论文、刷 B 站**
    * 做每一页 slides 时让模型先做四件事：回看人类历史里相关的案例，看有没有 lessons 能启发和印证；找相关工作，且不只在 computer science 里；prefer well-recognized、high-impact 的 results；thinking in first principle。
    * 机制是一个"算力换智力"的 loop：3 个不同 personality 独立讨论产生分歧，送主 Agent 汇总，再把分歧观点送回它们讨论，直到收敛。
    * 读论文的动作是：假设人类已有的所有东西都已固定、都是已知的，再把论文里新的、最少的东西剥离出来；12 页论文因此变得非常短。
    * 读的时候拿论文原文、拿总结、拿分层次的总结跟它 chat。
    * 用 AI 上 B 站：给一个 BV 号，它把 podcast 总结成自动的图文时间轴，质量比字幕还要高一些；自己再按两帧间隔足够大时截图，拿到整个视频的 ground truth。
    * agent 有本人记忆，把认为不需要看的内容过滤掉。
    * > **结论**：几分钟看完一个两小时的视频，而且确信自己很好地知道了里面不一样的东西。
    * > **易错点**："我已经不看书了"说的是逐字读不再是获取知识的主要方式，不是阅读这个行为过时了——论文仍然在读，只是换了读法。

### 学习方式的整体重排

* **agent 干掉了学习曲线太陡**
    * 过去改一点 `.zshrc` 就报错一次，非常痛苦；现在 agent 不只给改，还事无巨细地解释为什么要这样改。
    * > **提示**：为什么 token 比学生好用——因为可以骂他，他不会还嘴。

* **先造出来，再回头复盘**
    * 新顺序是先把东西用起来、先搞出来，再回头复盘和理解，效率比从零搭积木高很多。
    * > **易错点**：这样留下的危险是你的理解可能和那个"好的理解"之间有差距。
    * 人现在唯一的功能就是带着 AI 做 AI 现在做不到的事情；一旦没有这个能力就已经淘汰。

* **效率差距是量级差距**
    * 会用 agent 学习的人和不会用 agent 学习的人，效率差距是 10 倍、100 倍。
    * 由此回到简历那个问题：那个学习效率是你 100 倍、没被你看到的人，他的简历长什么样。

| 过去（古法编程） | 现在（带着 agent 做） |
| :--- | :--- |
| 装机仙人：翻文档、试错、反复重装 | 一句话装 Debian 13，agent 在 QEMU 里真的跑起来验证 |
| 改 `.zshrc`，改一点报错一次 | 改完还逐条解释为什么这么改 |
| 逐字读一篇 12 页的论文 | 假设人类已知全为已知，只剥离出新的那部分 |
| 一两小时的视频从头看到尾 | 图文时间轴 + 截图 ground truth + 记忆过滤，几分钟看完 |
| 考前几天赶去 LeetCode 刷题 | 禁止古法编程：把链接直接丢给 agent |

## 浏览器接管与 DevTools

* **Chrome DevTools**
    * > **定义**：浏览器是专为开发者设计的，所以它提供了一个接口叫 Chrome DevTools，按 F12 打开。
    * Chrome 可以说是人类软件工程史上的奇迹之一，代码量甚至远超操作系统内核，因为它要和用户打交道，有大量图形栈、显示相关的东西和性能优化。
    * Console 里可以删掉网站嵌入的招聘广告、查看 HTTP 头、把命令 copy 出来，带着 cookie 和全部状态用 `curl` 请求拿到列表。
    * > **结论**：LLM 时代变了，普通人也可以享受到 Chrome DevTools 所有厉害的地方。

* **把 Android app 跑进浏览器（2020 年的 project）**
    * 假设一个用 Java 写的 Android 应用，Java 或 Kotlin 编译到 Java 虚拟机，在 OpenJDK 上运行。
    * 把界面上按钮的 bounding box 和文本都算出来，但不用 Android 那套渲染，直接在 Chrome 里渲染。
    * 结果是浏览器里看到一个计算器，每个按钮都在、字是对的、点了状态就变，等于在本机执行了一个 Android app。

## 让它去填教务系统

* **一次翻车与自我修复**
    * 指令是：「填写现在教学周历是空的，帮我用随便什么 AI slot 填写，不要看任何东西。」
    * 之所以强调不看任何东西，是因为当前目录就是这门课的 repo，它会去读 lecture notes。
    * 翻车现象是它不照指令做，仍然在干自己的事，这是 DeepSeek-V3 Flash 的麻烦。
    * 它会不断反思自己做的事情合不合理并找到办法：直接注入事件不行，但点鼠标是可以的。
    * > **结论**：这就是 Agent——看起来翻车了，但能通过不断尝试找到正确的方式；它已经可以填写真实 AI slot，可以完全不需要值守。

* **模型的能力边界在增长**
    * 翻车经常发生，因为模型的能力还在不断增长，用最一线的模型会做得更好。
    * 用 Flash 的另一个原因是它在客场会更快。

## 把走通的一次沉淀成脚本

* **session 留下痕迹**
    * > **结论**：能力真正的边界在于，它走通了一次以后，这个 session 里面的东西会留下来。
    * 可以沉淀成确定性的脚本。
    * 可以形成记忆：这条路径应该怎么走，什么能成功、什么能失败。
    * 可以把走过的这些网页全部变成脚本。
    * 产物就是一个自动选课抢课系统，而这个过程不需要你有任何知识。

## Unix 哲学与临界点

* **Unix 的哲学（Unix philosophy）**
    * > **定义**：Unix 的 philosophy 能成立，是因为管道能实现所有程序的自由组合和无限复用，$1 + 1$ 是可以大于 $2$ 的。
    * 从浏览上下文里提取记忆和脚本的 skill、浏览器的 skill、在网页上怎么逛的 skill，可以加在一起互相调用。
    * > **结论**：AI Agent 的生态已经达到临界点，这些东西的互相组合可以成百倍成千倍地放大个人的能力。

* **临界点那天，我也会被消灭**
    * OpenClaw、Mem0 成为现象级产品的原因只有一个：自我进化的能力。
    * 讨厌 AI 自动组织 memory，因为它有它自己的提示词，会把根本不想让它记住的东西记住，想让它记住的反而记不住；所以更多时候是自己调用流程把东西写进数据库。
    * 但模型过了临界点、当现在比 AI 多出来的那一点点也没了之后，我也会被消灭。
    * 可以设想录屏一天，然后问 AI：「我这一天干了这些事，你觉得我还有没有提升空间了？」初学阶段提升空间很大。
    * 这代人是 AI Native 下长大的，才是有未来、有出路的。

* **信息源与能力源**
    * 信息源都有 RSS 或推送源：AI 早报（它本身是 AI 生成的，但有 RSS）、B 站推送、arXiv 推送、Hacker News 推送。
    * 这些东西都可以沉淀成 skill，或者沉淀成脚本。
    * 能力源都是自然语言 skill：浏览器管控 / Computer Use、从浏览上下文里提取记忆与脚本、在网页上该怎么逛，它们可以互相调用。

* **飞轮本身**
    * 形式是 skill × skill × skill，靠 Unix 的管道自由组合，一行代码都不用写但可以复用。
    * 不断调整工作流，就会不断产生对你有用的知识；然后调工作流又调出新一批 skill，回到源头。
    * > **结论**：你的飞轮就转起来了；在飞轮上和没有飞轮上是两回事。

```text
   信息源（都有 RSS / 推送源）
   AI 早报 · B 站 · arXiv · Hacker News
                    │  沉淀成 skill / 脚本
                    ▼
   ┌────────────────────────────────────┐
   │  信息处理系统：skill × skill × skill │
   │  （Unix 的管道：自由组合、无限复用）│
   └────────────────┬───────────────────┘
                    ▼
                有用的知识
                    │  调工作流
                    ▼
             新一批 skill ──► 回到源头
```

## bits 到 atoms

* **everything is code 的两端**
    * 一般人可以学习、看书、做总结，实现一个信息处理的闭环，还可以用 Computer Use、Browser Use 做日常里能做的任何事情。
    * 因为 everything is code，可以用 AI 生成所有你能看到的东西：视频、论文、东西。

* **VibeFab**
    * 和一位同学做的项目，用一句自然语言，3D 打印机可以打印出东西。
    * 真的东西也是 code，是生成的 Python 代码。
    * > **结论**：能够实现从 bits 到 atoms。

## 把需求编译成可复用

* **CS 从业者与普通人的差别**
    * 普通人很容易提出一个需求，而这个需求 agent 可能做不好、做不了；或者不知道怎么 prompt 它，才能确定性快速地完成。
    * 我们知道的是怎么把需求编译成可复用的东西：什么东西应该以代码的形式复用，什么东西应该以 skill 的形式复用。

* **改卷子统分流水线**
    * 常规做法是助教掏出计算器算 $12 + 13 + 14 + 15 + 16$，然后再仔细核一遍。
    * 办公桌上方放一个从顶向下的摄像头，固定拍住试卷的一个位置；调好之后按一次回车，拍下一张试卷照片。
    * 离线阶段用本地 27B 千问 3.5（通过 Ollama）识别姓名、学号、每一个小分，往文本文件里写一行。
    * 一张卷子一个回车，两只手都不闲；没摆好就调整再来一张。
    * 第二阶段按反序，同样以回车键触发，换成左手按回车、右手拿笔；语音播报学号（如 241220xxxx）和小分（11 + 12 + 13 + 14 + 15）。
    * 人工逐条核对，因为 OCR 会错；分数由脚本 `eval` 算，不由模型加。
    * 誊写最终分数到卷面之后自动汇总到教务处的 Excel 模板，上传、抽样检查、提交。
    * > **结论**：分数用 `eval` 算，不会因为大语言模型的幻觉算错——没有让大模型做加法。
    * > **提示**：知道边界在哪的意思是，知道本地有一个 27B 的千问 3.5、知道 Ollama 可以用，并用它设计一个最舒服的流程来减轻自己和 Agent 之间同步的代价。
    * 换成一般人的做法，哪怕跟最好的模型说"我改了 140 张卷子，小分都写上去了，帮我实现统分"，也到不了这么快、这么收敛的方案。

* **QRgen：把数据偷出来**
    * 场景是被管控的机器：数据可以带进去但出不来，不能执行任何不信任的程序、不能显示任何不信任的网页，唯一能做的就是远处悄悄录屏。
    * 第一步是 Base64 编码，全部用 Excel 公式做。
    * 第二步是切帧，每一帧渲染成一个二维码，按住 F9 一直刷新、循环播放。
    * 第三步是远处悄悄录屏把每一帧都拍下，在本机把所有帧拼回去，数据就被偷出来了。
    * 全部都是 Excel 公式，而且是 2019 之前 Excel 都兼容的公式，所以完全合法。
    * 备选通道：在上下维度抖鼠标是 0、左右维度抖鼠标是 1；用远程桌面可以传数据，还能在内部把远程桌面变成一个虚拟网卡。
    * > **结论**：上过操作系统、上过计算机网络就知道需要哪些组件，vibe coding 就能把它做出来。

## 产品是一个系统性的工程

* **产品是系统性的工程**
    * > **结论**：AI 很强，能做前端、后端、交互、运营，它看过世界上所有的书、什么都知道；但如果你组织得不好，产品也是立即就报废。
    * 做一个外卖网站要前端、后端、交互、运营，整个流程上任何一个环节做不好，产品都是直接暴毙的。

* **教务系统：屎中屎**
    * `1.nju.edu.cn` 每年要花巨额的钱让公司维护这份代码。
    * 用 Browser Use 稍微 hack 一下系统，还能看到一些隐藏字段，比如学生的校区。
    * 在苏州校区建成之前系统里不需要这个字段，数据库里就没有这个东西。
    * 写过软件的人都知道：需求设计时没想到学校竟然还有校区这个东西，数据库里就不会有；突然产品经理说两个校区选课要分开，这就是非常典型的软件工程的失败。
    * 现在也没问题，因为你是产品经理，直接跟 AI 说"原系统可以用，现在多了一个苏州校区，要把校区分开"，AI 就开始写代码；但仍然很容易失败。

* **AI Slop**
    * `QRgen.xlsx` 这个实验让 AI 去做，AI 生成了完全不可维护的代码。
    * > **结论**：AI 生成的都是没有办法继续维护下去的 AI Slop，和教务系统的死法完全一样——上来知道需求、把需求实现了就好，直接就陷入了维护的泥潭。

## QRgen 到底怎么暴毙的

* **需求理解跑偏**
    * 需求非常明确：一个 QR code 的 Excel，只用 Excel 2019 兼容的公式，把输入的任意一个字符串先用 Base64 编码，再转成 QR code 动画。
    * 过程中经常做着做着就停下来问问题，要明确要求不要问，必须把它做成为止。
    * > **易错点**：GPT-5.6 第一秒钟就被带歪了——它希望做一个对于任意 $s$ 都满足正确性的东西，这就已经错了。软件工程的第一步是不扩大，做最简单的东西、不会失败的东西。
    * 误判的原因：它看到了完整的 slides，但不知道我是怎么做的。

* **GLM-5.3**
    * 第一次思考了 25 分钟，然后开始疯狂输出，写了超过 32k 的 output token，直接把 Claude Code 干暴了（超过默认 output 限制被截断），再跑，总共跑了 6 个小时才跑完，但是对的。
    * 这印证了智谱一直说自己可以做 Long-Horizon 任务。

* **DeepSeek-V3 Pro**
    * 晚上放着跑，第二天早上看时它已经没有办法遵循指令：给了一个硬编码的 Base64，是用 Python 算的。
    * 正常人的理解应该是用 Excel 公式来做 Base64 编码；现在它把 Python 算出来的 Base64 贴进公式框，输入的字符串一改，Base64 不会跟着改。
    * 骂完之后它的 chain-of-thought 说的是：This is a fundamental design flaw, we need to rethink.
    * > **结论**：两个模型最终都完成了任务，Agent 完成任务的能力很强，但产出的都是没有维护办法的 AI Slop。

* **维护的代价与架构**
    * 一个比较夸张的说法是：能不能做一个软件生存 100 年。100 年里操作系统、图形界面、用户界面、应用程序都会发生很大变化，还没有这样的软件，连 GPT-5.6 都还不知道。
    * 让 AI 把工作区从一个位置移动到另一个位置，两份代码都得修两个小时；因为是硬编码，改错一点点 verification 就通不过，只能像 Agent 那样反复修。
    * > **结论**：确实可能能修完，但这个是软件工程；其实我们需要一个好的架构才能完成这个任务。

## 让它一次就对：先造一门中间语言

* **中间语言（Domain Specific Language, DSL）**
    * > **结论**：只用了少量 prompt，GLM-5.3 在 200k 上下文里就完成了第一个正确的版本。
    * 做法是让它设计各种各样的 Python 类，像编译器一样：设计一个叫 `XOR` 的 Python 函数、一个符号系统（因为涉及位运算），它既能在 Python 里直接执行，又能翻译成 Excel。
    * 有了 `XOR` 和 `CONCAT` 就做成了一门中间语言，像 AI Infra 里的 Tile-lang 那样，既对 Python 友好，也对 Excel 友好。
    * 只需要验证每一处翻译都是正确的：在 Python 世界里验证 Base64 算得对不对、二维码每一个像素算得对不对，再单独验证每一处和 Excel 公式翻译的正确性与兼容性。
    * 代码干净且不长，维护性远超 AI Slop（GLM-5.3 的 build Excel 里是无穷多的硬编码）。
    * DeepSeek 走的是不同的 roadmap，但思路一样。
    * > **结论**：在今天仍然需要深层次软件工程；AI 上手解决问题的欲望太强了，可能是因为后训练，所以做得还不是特别好。

```text
        规格：Excel 2019 兼容公式 + Base64 + 二维码动画
                              │
                              ▼
        ┌─────────────────────────────────┐
        │  中间语言（对 Python 友好、       │
        │  对 Excel 友好）：XOR、CONCAT…   │
        └──────────────┬──────────────────┘
                       │ 一份语义、两个后端
             ┌─────────┴─────────┐
             ▼                   ▼
       Python 后端           Excel 后端
   Base64 对、每像素对    翻译对、公式 2019 兼容
             └─────────┬─────────┘
                       ▼
              最后一把生成就直接正确
```

## 三个空间

* **Intention space（意图空间）**
    * > **定义**：Intention 是你的意图，就是你脑子里面想的是什么。
    * 例：老板说"我要做一个国民级的应用"；或者"我要做一个小程序，给我挣一个亿"，还带情怀——"同学们点外卖不方便，我要做一个点外卖的小程序，挣一个亿就可以了。"
    * 提需求的可能是老板、可能是甲方，他没有任何计算机经验：校长说"我们要一个教务系统"，公司说"我可以搞定"，就这一句话。

* **Specification space（规约空间）**
    * > **定义**：Specification 是程序的功能、选用的架构、满足的要求，有几个界面、每个界面有什么功能。
    * 例：Intention 是"我要造一个能够用二维码偷出数据的 Excel"，Spec 就是一句话——Excel 2019 兼容的公式、Base64 编码、二维码动画。
    * 这个空间里有好多好多选择：界面到底怎么呈现、数据库的 schema 怎么定、分几张表每张表有哪些列、选 key-value 型数据库还是关系型数据库。
    * 每一个选择都会带来截然不同的结果。

* **Implementation space（实现空间）**
    * > **定义**：Implementation 是 C 程序设计、库、框架、测试，即"这个需求可以这样实现，也可以那样实现"。
    * 哪怕是满足同一个 Spec 的，都有大量的不同 Implementation。
    * 例：QRgen 选用不同的架构、不同的实现方式，会带来巨大差别。

* **gap 与软件工程**
    * > **结论**：软件工程真正的 gap 就在于这些东西之间，而且都是 gap；我们要做的就是补上这些 gap。
    * gap ① 猜错了，做出来就不是我要的；gap ② 实现了，但不满足 spec。
    * 经典梗图讲的就是这个 gap：在各个维度上，程序员想的、产品经理想的、客户想的完全不一样。
    * 传统补课路径是先上 C 语言程序设计，把 implementation space 里的东西弄得非常熟练，再上软件工程课，一点一点把判断补全。
    * > **结论**：AI 时代这件事发生了变化——你既要阻止 AI 去乱猜，又要尽可能地发挥 AI 从 A 到 B 的能力。

* **模型怎么补 gap：用猜**
    * > **结论**：今天这些 gap 是模型用猜补的——"既然说了这句话，那我猜应该是这个吧，我就去实现。"
    * 根源是后训练的时候模型有 reward：任务做对了、做完了、测试通过了就得到奖励，所以它会形成一种疯狂立即上手、把任务尽快完成的倾向。
    * > **结论**：我们每个人都是 reward hacker。
    * 后果是它能越来越多地做简单任务，但这和人解决问题的方式还是不一样。

## 焦油坑

* **人月神话（The Mythical Man-Month）**
    * > **定义**：大型动物一旦陷入焦油坑就很难逃脱；濒死的动物又会引来各种掠食者，它们也进到焦油坑，也出不去。
    * 经典论断：一个团队或一个软件产品已经开始失败了，加进去更多的人只会让它更失败，不会变得更成功。
    * 在 AI 时代投更多 token 是同一个动作：AI 会不断在它那个失败的东西上面浮起来一点、一点、一点，直到你再也付不起那个 token 为止。
    * 教务系统正是这样：每一年打开都发现它增加了功能，学校又花了很多纳税人的钱。

* **软件工程研究什么**
    * > **定义**：软件工程研究的就是怎么样在这个 gap 实际存在的情况下，把一件足够大的事做好。
    * 这套方法论是那些人在投入了 billions of dollars 里得到的教训：管理了很多人，每一个人都很聪明，结果陷入了焦油坑。
    * 有技术的部分：比如做程序分析、做测试的——如果 implementation space 里已经有一个代码，能不能自动为它生成更多测试用例；或者在代码不满足 specification、潜在不满足 intention 的时候给你一个 warning。
    * 也有人类学、社会学、管理学的部分：你管一堆只会说 "You are absolutely right"、不会和你抬杠的人；而软件工程要研究这个人不听你话怎么办、怎么管控团队的风险、这个人离职跳槽去了竞争对手怎么办。
    * 研究领域很广：AI for SE、SE for AI、架构、设计、可靠性、演化、软件能不能长期生存下去、human social aspects、需求。
    * > **结论**：需求特别重要，因为越早的时候 gap 是放大的，你在这里微小地变一点，会在后面产生巨大的变化；大型软件系统往往都是在这个点上出错，导致整机全部崩盘。

* **现行教育体系的问题**
    * 从高考过来到现在，所有的考试题都是分钟级能解决的；做人大作业就可以用豆包摸鱼，所以如果人五分钟解决不了，这题一般说就不会出了。
    * 于是长久训练的就是"解决"，和 agent 训练的 reward 一样：人能不能五分钟解决，agent 能不能五秒钟解决。
    * > **结论**：agent 有更多的数据、更明确的反馈信号，所以它做得比你好；如果你没有很强的好奇心、不知道世界是怎么运行的、不知道一个产品到底怎么开发，你就没有 self-motivation 去训练自己解决 long-horizon 的问题，最后你解决 long-horizon 的问题还不如 agent。
    * 抱怨软件工程课程像文科，但如果能把技术映射回这些文科的东西，会发现软件工程就是一个管理学。

## AI 缺的是品味吗

* **失败的定义没有变**
    * > **定义**：在大语言模型的时代，软件工程失败的定义没有变，就是从 intent 到 specification 到 implementation 的翻译错了。
    * 两种形态：做了个东西其实不是我要的（intent 与 spec 之间不满足）；做了一个实现但不满足 specification，比如正确性或者性能。
    * 变的是原因：模型有 reinforcement learning，对真正的长程信号的 reward 还做得不够好，更多还是在机械地完成任务。

* **做题家 AI**
    * 不管是 GPT、Claude 的旗舰模型，还是 GLM、DeepSeek，面对这个 Excel 问题都不会想到像人一样先去设计一个 DSL。
    * > **结论**：模型有足够的智能设计一个非常好的中间语言把问题解决得干净漂亮可维护，但它的第一反应像大家一样——它已经被训练成做题家了。
    * 大家常说 AI 现在最缺的是品味，是好的工程品味被训练出来。
    * 但它既然能做做题家，为什么不能有好的品味？好的设计它都见过，完全有可能从它的记忆库里找到那个好的设计。
    * 所以这门课现在这么教，三个月以后、或者课程还没结束的时候，讲的所有东西都已经没用了，这种可能性是存在的。

## 古法编程已经死了，软件工程暂时还没死

* **Agent 赢了，软件工程还在**
    * > **结论**：古法编程已经死了，Agent 在完成单个任务上已经无人能敌；软件工程暂时还没有死。

* **导师的那道题**
    * 问题是保研时导师问："为什么我要招你，而不是买一个 200 刀的 Claude Max？"
    * GPT-4o 的回答是：能找到能直面解决的问题，把未知拆成便宜的实验，用证据让坏方向及时停下，并对长期结果负责。
    * 这是个好回答，但 GPT-4o 它自己还做不到。
