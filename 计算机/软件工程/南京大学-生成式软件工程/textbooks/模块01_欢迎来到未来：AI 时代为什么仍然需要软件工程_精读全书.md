### 从 Altair 8800 到 ChatGPT：把昂贵变成日用品

我刚才干了什么呢？我按了 F5，浏览器弹出来，slides 开始播，然后我们就可以正式上课了。

我们今天站在一个非常重要的交叉路口。你们是 Computer Science 的同学，从你们刚开始进学校那天起回想，计算机发展历史上其实经历了很多次非常重要的变革。我觉得最主要的一类，是把昂贵的能力变成了日用品。

```text
  1975        Altair 8800      第一台 PC 机
  1990s       ICQ / OICQ       "I seek you"，腾讯山寨版，后来叫 QQ
  2010s       移动互联网      一夜之间菜市场卖菜的都有两个码
  2022        ChatGPT          有人说 AI 是增长最快的产品
  ------------------------------------------------------------------
              每一格都是同一件事：把昂贵的能力变成日用品
```

屏幕上那张 Altair 8800 的图也是 AI 生成的，你们一眼就能看出它有非常明显的 AI 味，而且它不是一个特别强的模型。没关系——我说过我上课是跟大家一个比较松散的讨论和交流过程，课后我会把这门课重新再切片、再整理一次。

从 PC 到互联网，互联网连接了我们的所有人。我至今都还记得你们没有经历过的那个时代：我上小学快毕业的时候，装了一个软件叫 ICQ，你们没有听说过这个名字吧？ICQ 就是 "I seek you"。那个时候腾讯的山寨版还叫 OICQ，后来腾讯把它改成了 QQ。你在那个时候可以随机地加到世界另一端的人，然后你加到的往往就是 native speaker，他跟你说英语，而且他一下子发很多英语、打得非常快，你完全无法理解他在跟你说什么——因为我们那时候可能刚学一点点英语，只会 "Hello"、"Good morning"。

再从互联网到移动互联网，我印象很深，是**一夜之间**所有的菜市场卖菜的人都有支付宝和微信两个二维码。就在很短的时间里，一直在改变我们生活的方式。

然后到 2022 年是 ChatGPT。有人说 AI 是人类历史上增长最快的产品。

> **结论**：在这样一个人类命运的交叉路口，我觉得我们上课的方式、我们该学什么，都需要重新思考一下。就在这样的背景下，我决定还是应该开这样一门 vibe coding 的课程。

### "AI 替我上大学"：随之而来的两种焦虑

前一段时间有一个说法，叫"AI 替我上学"。我觉得这个说法很对。你想：老师用豆包出题，大家用豆包做作业，那么在整个闭环过程当中，**只有学生没有受到训练**。

现在 vibe coding 很厉害。操作系统这门课的作业，以前折磨大家，大家在痛苦的折磨中获得提升；现在不要了——你把那个作业的链接直接丢到 Codex 里面，你都不需要有复制粘贴的过程，你甚至都不需要给它链接，直接说"蒋老师的操作系统课第八个实验能不能去帮我实现"，好，就结束了。

所以，在这样的时代我们还怎么做？到底应不应该学编程这样的东西？那答案肯定是既应该也不应该——有些能力你还是需要的，但应该怎么做，我们不知道。

所以我看到其实大家都处在一种非常焦虑的状态上。我把它分成两种：

**第一种焦虑**：AI 帮我上大学了，那我上完以后最后走，什么都没学会。我每门课都很好；如果每门课都开卷考试、都是 AI 答题，我全都答对了，但我出来以后发现，我第一个就被 AI 取代了。

**第二种焦虑**：我相信这边还有另外的同学，可能延伸了你中学时候很听老师话的状态——老师说什么你就做什么，每一堂课你都认真听，每一次作业你都认真做。做完了以后你发现，四年毕业的时候你被大学骗了：你确实学会了点什么，但是你学会的东西 AI 都会做，然后你也很迷茫。

这两种焦虑其实指向同一个结论：把能力交给 AI 之后，**"学过"这件事本身不再构成任何区分度**。

### 一份零分简历，和人最后剩下的优势

当然，我觉得同学们现在最切实、最痛苦的事情就是保研。你们投了很多简历，海投很多地方，我也收到了很多这样的简历。

说实话我觉得很糟糕。这是一个简历，你们看：所有这一切都是 AI 做的，我没有干任何事；我只告诉他"有一份简历，然后我现在需要在上课的时候展示一下，我需要把他的个人信息给去掉"——这是他把字符替换成 Unicode 的方块，如果你复制粘贴的话，你会看到这是一个方块的字符，希望他把这些信息都隐掉了。

就这样的一份简历，非常完美：一篇 CCF 期刊列表上面的论文，然后 accepted。当然大家都说"在投"就等于"不存在"，因为你看不到。

但这个简历对我来说是一个**零分**的简历。因为它没有额外的信息：他甚至没有一个 GitHub 的链接，没有一个个人的主页，没有一天 preprint。

我不知道这位同学发生了什么，但是对我来说，这样的一份简历非常糟糕。更糟糕的是，我收到过无数份这样的简历，可能你们的简历多多少少也是长这个样子的。然后这个时候你就发现，你和你的竞争者已经无法区分了——所有人都是"我有一大堆实习、一大堆奖项、一大堆论文、一大堆在投"。

是什么能让你从这些简历里面脱颖而出？如果刚才那份简历都被我认为是零分，你们应该怎么样向你们未来的导师去展示你自己？

我们经常听说，作为人和 AI 比，你的优势在哪里？是因为"你可以做到 AI 不能做的"。实际上我觉得大学里能教你的、或者说能作为人、你在大学毕业的时候能拥有的能力，比较重要的是第一个：**信息差**。

> **定义**：信息差 = 你掌握而竞争者不掌握的信息。这是人类社会不能说可悲吧、但要进步必须有的事情。你有信息差，你有别人不知道的信息，你才能做别人做不到的事。

所以在学校里面多多少少也会有这种恶性竞争。你想想一个情况：你拥有一份别人都没有的往年试卷，那你就可以在竞争当中胜出——这就是一种你们身边的信息差。当然还有很多其它的、不能说的信息差，在社会上面广泛地存在。

除了信息差以外，你作为一个人的优势是**你做得到**。大学里真正教你的是怎么样成为一个更好的人，就是你能够驾驭别人驾驭不了的东西。你在大学毕业的时候可以说："我是个更好的人，我有一个别人没有的能力。"

所以可能这门课试着去帮大家建立的，就是驾驭人工智能的能力。

> **结论**：这两点合起来就是这门课存在的理由——你的简历上不该是"我学会了什么"，而应该是"我有一个别人没有的信息、并且我真的做成了"。而这两件事，在 AI 时代恰恰是 agent 能帮你完成、但只有你能决定要不要完成的事。

### 上课就是一场演出：everything is code

这门课怎么上呢？我希望用一个案例为主的、比较松散的组织方式。

- 如果你是有兴趣来、想跟我讨论的同学，想 challenge 我说"老师你这样做不对"，那就欢迎大家来线下；
- 如果你是一个听课型的同学，就是你希望从这门课里获取知识，那我完全建议大家既不用到课，也不用看直播。

为什么我可以这么讲？因为我今年想做一个非常有趣的尝试。

我已经看到了，这是我的 slides，我按 F5 的时候可以播放。然后你可以看到，这个 F5 播放出来的 slides 和刚才那个 Markdown 是有点不一样的。我把它关掉——左边是我上课之前写的讲义，相当于我会先想好我今天上课的时候大概在这个时间应该讲什么、举什么样的例子，相当于我要**约束好 AI 做什么**。当你看到 F5 播放的这个 slides 的时候，有这个紫色的部分，紫色的部分就是 GPT-5.6 给我添油加醋加上去的部分。

#### 内容流水线：Markdown 是 source of truth

我有一个 skill 叫 make slides，我就可以从一个我写好的 Markdown、也就是我写好的演讲稿里面，让它添油加醋地去做点有趣的事情。

```text
   Markdown 讲义（source of truth，课前我先写好）
                  │
                  │   选中其中一个 snippet
                  ▼
        ┌───────────────────────┐
        │  make slides (skill)   │  添油加醋地扩写
        └───────────┬───────────┘
                    ▼
             Markdown slides
                    │
                    ▼
          浏览器里渲染出来（F5 播放）
                    │
                    ▼
        幻灯片版式 + 配图（图片全部 AIGC 生成）
```

我还有一个类似于"AI 梗同学"的 skill，我会让它生成三个 sub-agent，然后给他们赋予不同的 personality。这非常有效果：有的 agent 会干这个，有的 agent 会干那个，他们在隔离的上下文里工作，然后最后我的主 agent 会回来汇总。

```text
                ┌──────────────────┐
                │     主 agent      │
                └───┬───┬───┬──────┘
       派发（隔离上下文，彼此不可见） │
            ┌───────┘   │   └───────┐
            ▼           ▼           ▼
       sub-agent A  sub-agent B  sub-agent C
       personality 1 personality 2 personality 3
            └───────┬───┴───┬───────┘
                    │ 汇总 │
                    ▼
               讲义/ slides 产出
```

这样我就可以通过**算力换智力**——我付出更多的算力，我就有更多的智力。

至于怎么挑出好的那一个：我经过对比了，我换了几个版本的提示词，然后每一个版本的提示词我都会重新生成一次，然后我最终会有一个 reviewer、另一个别的模型在盲评，到底哪一个生成的 slides 质量比较高，然后我基本上就挑到了一个可能相对来说质量比较高的 slides。所以你看到，图片全部都是生成的，所有的图片都是生成的。

> **结论**：我不需要一个"更强的模型"来做这件事。我需要的是更多的算力，加上一个会挑的评审。质量是可以用并行采样加盲评换出来的。

那我为什么要这么干？因为**上课是一种表演**。我说我是个演员，要调动大家的情绪。所以上课的时候跟大家交流，然后根据我预先设定好的剧本去做一场演出。演出完了以后，我需要做一件很重要的事：我要 **review 我今天的表演**。因为有时候我今天举的这个例子可能不是特别恰当，或者在我回过头来的时候，我想也许我想另外一个案例大家能够更加地感同身受。

#### 课程的数字永生

你看到我有一部分是即兴的，但即兴就意味着其实不完美的。而我在课后，我会把我的课程——因为我录像了——把录像切片，重新整理成片段。因为我是从 content-as-code 来的，everything is code，我就可以把我上课的录像、这次的表演重新回到这门课上，把它变得更丰富。然后我不就实现了数字永生了吗？我就实现了一个**课程的数字永生**。

everything is code 是什么意思？你能看到这个世界里面的一切都可以用代码来生成：包括这个桌子，Computer Aided Design (CAD)，桌子、椅子、电脑。

我希望的最终形态是：能够以**切片**的方式得到一个完美的程序。比如我今天要讲生成式软件工程，它的要点是什么、逻辑是什么、第一节课应该怎么上，沉淀成一个程序。然后这个程序也许现在是由我维护的；也许比如有一天我不维护了——操作系统课我今天不上了——我会把操作系统课我 B 站的录像整理成这样的切片，然后可以由全世界的人来维护它。

对吧，你想要定制一个什么样的我的操作系统，你就可以把它定制成任何样子。你看，这不就把所有这个大学教课的方式给颠覆了嘛。

我觉得这是一个可能实现的路线，所以我会在这一门课上做一个比较新的尝试，也欢迎大家随时可以给我反馈。

### 三条 policy

#### 禁止古法编程

我这门课的 policy 是希望重新找回同学们心中在大学的时候那种"上课耽误学习"的感觉。虽然你们可能还是要上课，但我推荐大家第一个，你们可以不要上课，然后你们去在这门课上实践，我会带着大家实践。我后面有很多真正实践的案例，让你们知道在 AI 的时代，你们学习的方式变了，你们工作的方式也变了，你们可以尽快地适应这样一个非常有趣的时代。

然后我的要求是：**禁止古法编程**。

我相信你们各个都是古法编程的好手，因为你们要考试，马上要保研、要机试了。要机试的时候就把你们一关，小黑屋里一关，你们看过我以前出的题，然后就吓尿了，对吧，然后赶快再去 LeetCode 上刷刷一下。

但我觉得总有一天这个事情会改变的。可能从上而下传导不会那么快——你要改变一个体制很难。但是我非常想要**撕开一个小小的口子**。

#### token 自费

本来我是想去拉一些 token 的赞助的，想拉一些赞助 token。但是当我看到选课学生的数量之后，我想，哎，还是算了，我也没有必要再跟他们拉着脸去要好多好多的 token，也比较麻烦。

首先我有一个个人观点：**如果你们手头没有 token、没有付费的 token，应该立即退学。**

可能你们确实不需要 token maxi——在硅谷有一种"你要死命地烧 token"的做法，你没有必要。在我的课上，我做的所有演示，除了我的这个 slides 的生成是用了一个更聪明的模型（我觉得它能给我更好的质量）以外，你看到的这个幻灯片、这个 lecture 里面的东西，包括这些生成的这些 assets，**全部都是 DeepSeek-V3-Flash**。

也就是说，我在这门课上会用一个足够便宜、但是智能相对有一些的模型，来带大家完成这些事情。

> **提示**：为什么坚持用便宜模型？因为这门课要教的是方法论，不是某个模型的极限能力。一个便宜到你愿意自费、愿意反复重试、愿意犯错的模型，才是能真正把 agent 用熟的前提。

我也知道大家都是夜猫子，对吧，大家都是 Computer Science 的学生，你们喜欢在夜里工作。然后在夜里工作 DeepSeek 是比较便宜的。我建议大家在两波谷的时间做——你看，白天你们要上课，正好是两波峰的时间；等你们回去做作业的时候，这个就是两波谷的时间了。

所以 token 非常重要。你们每一个同学，你去 DeepSeek 充 100 块，这个好像还 OK。如果实在 token 有困难的同学，可能可以联系我来帮助大家想一点办法。

#### 通过 / 不通过

还有一个很重要的 policy：我希望用一个通过或者不通过来 evaluate 这个课程。所以我在我申请这门课程的时候，我的考核方式就填的是通过和不通过。

但根据教务的反馈，专业选修课大家是不会做成这样的；一般来说，像"形势与政策"这样的课是通过和不通过的。因为我们现在还不知道这个评判标准是什么——你可能用更好的模型你就可以有更好的质量。同一个任务，你让 Claude 3.5 来做，就是比 DeepSeek-V3-Flash 要做得又好又快。我们没有办法限制大家用什么样的模型，那怎么评判？尤其是这样一个 vibe coding 的、我们是做 project 的课程。

我大概会有一些建议的想法，我回头会更新课程网站，上面会告诉大家：

- 建议你们实现一个**自己的 email 管理系统**；
- 你可以回我的 email，然后我会用一个指定邮箱给你发邮件，你可以把邮件给我回回来；
- 你可以做一个尝试 vibe code 的这样的服务，跑在你宿舍的一个一直常开的小电脑上。

这就是一个比较不错的实验。有的同学可能会做得复杂一点，有的同学做得简单一点。我可能会用我的邮箱去跟大家通信。

但到底什么叫做好、什么叫做不好？到底该给多少分？

> **结论**：在这个时代，分数已经变得不那么重要了。真正重要的就是在你最后找工作、或者在你保研的那一刻，投出去那个简历上面有什么东西。

所以我最终希望这门课大家能够最后在简历里面写一个："我在生成式软件工程里面实现了这个 A、B、C、D、E"，然后有很多链接，然后它是一个让每一个东西都做得很漂亮，它让每一个都说你完成了设计、实现了，然后它里面了不起的地方是什么。

对我来说，其实我觉得你有一篇发表论文是一个减分项，但可能对很多其他人来说可能还不是的。

> **提示**：再往前一步，是一个有点恐怖的想象——如果每一个人的电脑上面都安装一个监控，那我就知道你大学四年干的所有事情，然后我的 AI 就可以评判你大学四年到底度过了一个怎样的大学四年。当然这是一个非常恐怖的事情，因为你摸的每一条鱼、你看的每一部不想让别人知道的小电影，它都在你的电脑上发生，所以都知道。我不知道什么时候人类社会会演进到那个程度，但是保持 open——这是我们课程的 policy。

大概我课程开了一个头了。接下来我们就可以进入技术性的内容了。

### 大语言模型就是一个概率分布

首先讲一讲什么是大语言模型。今天我**不讲**大语言模型。

大语言模型就是一个概率分布，跟你们在概率统计课上面学的抛硬币一样。我抛了六次硬币加起来是 40，你问我第一次抛出 1 的概率是多少——你们在概率课上都做过类似的题目，没有任何的区别。它是一个学到的概率分布。

```text
    给它很长的文本（我带了一本书）——当然也可以是图像
                          │
                          ▼
          ┌───────────────────────────────┐
          │   一个学到的概率分布            │
          │   P(下一个 token | 已有的上文)  │
          └───────────────┬───────────────┘
                          │
        在书的最后再写几个字，比如：
        "能不能帮我总结一下这本书？"
                          │
                          ▼
        下一个 token → 下一个 token → 下一个 token → ……
        （一次输出一个字符、一个字符、一个字符）
```

这个模型很大，它见过世界上所有的东西，然后训练它很难——所以这是为什么现在 Frontier Lab 这么牛逼。

> **重要**：但这门课是站在**使用者**的视角上。也就是说，你们只要知道存在一个东西叫大语言模型。你可以打开 DeepSeek 的网页 API，它会告诉你：你现在就在体验大语言模型。所以你**不需要任何大语言模型的知识**。

#### 我第一次被按在地上打：给 5 岁孩子讲扫描电子显微镜

大语言模型是怎么样进入我的世界的？

我第一次被大语言模型按在地上打，是 2023 年，GPT-4 的时代——那个时候 GPT-4 是一个幻觉非常严重的模型。我拿它给我 5 岁的孩子解释什么是扫描电子显微镜。

我大概有这样一个 prompt，那个时候我们就在玩 prompt engineering：我说我希望用朴素的语言打一个合适的比方，帮助他理解这个事。

所以有一天我给我的 5 岁的孩子讲故事的时候，不知道为什么讲到了扫描电子显微镜——我想不下去了。讲不下去以后，GPT-4 给了我一个比方。这个比方打得挺好，这是 o1 给的，我让他写的：

> 你现在有一座山，这个山的形状你闭着眼看不到，但你想知道那座山是什么形状的，怎么办？那你就闭着眼睛对着那座山扔石头、扔石头。有的方向石头穿过去了，有的方向石头弹回来了，弹回来你能听到声音。通过哪些地方穿过去了、哪些地方没有穿过去——就像 ray tracing 一样——你就可以推测出这座山的形状。

小朋友大概听懂了，但小朋友也不可能 100% 听懂。而他打的这个比方让我觉得非常震惊：首先他有这个知识；其次我后来还特意去查了资料，他这个比方**打得是对的**。你看 o1 给了更严谨的一个答案，而且因为它有 reasoning，所以它还给了更好的解释。

同样地在 GPT-4 那个时代，我们用一个 prompt 就可以给 GCC/LLVM 找到 150 个 bug。而在今天——在 o1 的时代——你这个工作就是一句话的事情，真的是一句话，不需要再做任何的为 GPT 的特别的调整。

#### Agent 是怎么长出来的

从一个能预测下一个 token 的概率分布，随着大家发现模型可以输出越来越长的文本、也接受越来越长的上下文，Agent 就出现了。先有了推理的模型，然后有了 coding 的 ReAct 式的 Agent。

Agent 就是：语言模型可以输出下一个 token，那我就可以让它输出一个**特殊的 token**——"能不能调用一个 Bash 程序"。然后这个 Bash 程序会运行，运行以后，Bash 程序的结果会重新送回到这个 Agent loop 里。这样 Agent 就可以自主运行了，你就可以给它一个比较复杂的任务，它可以不断地尝试、尝试、尝试、尝试。

```text
        ┌──────────────────────────────────┐
        │        Agent loop（一直转）        │
        │                                  │◀─────────┐
        └───┬──────────────────────┬───────┘          │
            │                      │                  │
   特殊 token：               工具的输出：            │
   "调用 Bash"              stdout / 报错 /           │
            │                文件内容……              │
            ▼                      │                  │
        真实执行  ─────────────────┴──────────────────┘
```

我自己的例子就在这个循环里。我配置了一个 Sway 的窗口管理器——它为课堂展示做了优化：对比度比较高，顶栏全部去掉了，这样你们在上课的时候可以看得更清楚。

我还有一些你们可能刚才没注意到的细节。你们都喜欢用 `top` 这个命令来查看系统里的进程；如果你不做定制，你看到的就是一个比较土的 `top`。但我这里有一个更 fancy 的 `top`——顺便，OBS 还在，还在浪费我的算力。

还有，你们看到我 `ls` 的时候，我用的不是 `ls`。这个细节大家刚才有没有注意到？我在 `ls` 的时候，它自动把 `ls` 换成了 `eza` 这个命令。然后当我要 `find` 的时候，它也自动帮我换成了 `fd`——`fd` 的行为和 `find` 稍微有点不一样。你看到我 `ls` 的输出里面，是不是也很 fancy？这是个目录，这是一个 Markdown，这是一个 Makefile，还有特殊显示的效果。

我所有的这些配置都是用 Agent 配置的。我只有一个 prompt："你能不能帮我把我现在的命令行终端，包括我的系统 Sway，都配置成这个现代的、比较好用的样子。"结束了。DeepSeek-V3-Flash，没有更好的模型。所以今天有了 ReAct 这种类型的 Agent 以后，它就不停地在 configuration 里面去改改改，它错了以后会去试，试别的方法，然后最终它把任务能完成。

大概去年我上操作系统的时候，那个 Agent 还不怎么能用，各种出错，然后任务完成不了，它就停下来了。但到今年我上操作系统课的时候，这个 Agent 就非常非常能用了。到现在你看，Agent 产品爆发，到处铺天盖地都是 Agent 产品的广告——WalkBuddy、豆包的那个 Agent，就是这样的 ReAct 类型的 Agent。

#### Agent 的能力还远远没有被释放

但这个故事其实远远没有结束。今天你们已经感受到 Agent 非常强了，但是我认为 **Agent 的能力还远远没有被释放出来**。

我认为 next-token prediction 其实是一个效率很低的模型。比如说现在已经有 diffusion model 了。

```text
   next-token 预测                          diffusion
   ─────────────────                       ──────────
   "……然后" → 一个 token                   一片纯随机噪声
            → 一个 token                            │
            → 一个 token                    迭代去噪，一遍遍
            → 一个 token  ……                重新审视整段文本
   串行、每一步只依赖上一步                          │
                                            ▓▒░ 一段很长的、完整的东西 ░▒▓
```

我可以说一句 "Write an AI Slop novel."，然后你看它给我写这个 AI Slop 的过程——它是从一个随机的噪声开始的，就像 diffusion 生成图片那样，一点一点、一点一点，就生成了一个很长的东西。

它可以生成一个很长的东西，就像人做梦一样：在你的梦境当中，一点一点把一个东西看得越来越清楚、越来越清楚、越来越清楚。我们有很多未来的、未来的可能性。

这种 diffusion 类型的语言模型，甚至不是我 predict next token：我可以把上下文回过去改，随时可以把一个很长的上下文裁短。对吧，这些都是今天很多人在研究的东西。

现在的模型已经非常强了。如果我们三个月以后又有一个新的突破，模型变得更强了；一年以后模型又突破了，又变得更强了——整个 AI 的 research 大家都在赌这件事情要发生。摩尔定律还在。

> **结论**：我现在很难想未来会变成什么，我不能预测未来，不能预测到底哪一条路线会胜出、哪一种模型会胜出。但是你可以遇见的是：**这个世界肯定会变得非常的不一样**。而在这个世界上，我们应该怎么办，是每一个同学我觉得都值得好好考虑一下的问题。

### 怎么上手：立刻用，随时问

好，吓唬人的事情说完了。我们可以吸一口气，我也可以真的告诉大家应该怎么样来实际操作我们的 agent——这还是这门课主要要讲的。

所以我首先站在普通人的视角来给大家科普一下。我先假设大家其实不太会用 agent：从我上个学期帮大家改期末考试题的感觉来看，好像就是——如果你要用 agent 给我的课出一份期末考试卷子，这个应该怎么办？我发现大家用 agent 的方式可能需要我来稍微解锁一下。如果大家有特别好的想法，你们可以随时打断我。

首先，agent 作为 AI native 的一代人，你要知道：给它一个合适的指令，它就可以把这个指令完成。

我在课上选的是 Pi。你只要跟它说就可以了。然后你可以写一些配置文件，比如说 `agents.md`。

你可以问它"你是谁"——你看，它还说它是生成式软件工程的教学辅助 agent。那你可以问它："你不就是个模型吗？为什么还知道生成式软件工程？"

对吧，你可以自由地、任意地问。它回答了。它之所以知道这门课、知道这个仓库，是 `agents.md` 的配置——这部分是临时的。

> **结论**：使用 agent 的第一个原则是**现在就开着用**；第二个原则是**随时问它**。这是最小的第一个原则。
>
> 在这个之上，其实是你的想象力限制了你的 agent 的上限。所以正好一会儿课间的时候，大家可以想一想：**你们用 agent 做的最酷的一件事情是什么？** 想象力是你们的上限。

### 我怎么真的在用 agent

#### 装机仙人退休：一句话把 Debian 13 装进 U 盘

我的第一个例子是今天上课的这个系统——刚才我给大家展示了，我也说了，所有的配置安装都是由 AI 完成的。

我要在 U 盘上。一直以来这是我上操作系统课的一个特色：我会带一个 U 盘，这个 U 盘里面装一个 Linux 操作系统，然后这个 Linux 操作系统可以直接插在教室的电脑上就启动。所以你看到我现在这个是我的 U 盘，然后这是电脑的硬盘——我有一年的操作系统课上把这个硬盘给抹掉了，然后抹掉以后下一个上课的老师就叫业务事故了。抹掉它是为了就地展示这个操作系统的原理。

装机是一个很痛苦的事情。我曾经是装机仙人。这里有个知乎链接，这个是 pre-LLM 的时代，你看，2021 年 7 月。我各种定制、各种定制系统，装机仙人。

> **结论**：装机仙人现在已经彻底被 AI 取代了。

因为我只用了一句话，我说："你去 mirrors.nju.edu.cn 上找一个 Debian 13 的镜像，把它装到我的 U 盘上。"这时候 U 盘插在里面。然后——**点睛之笔是这个"用模拟器验证"**——"确保这个 U 盘可以启动，然后用模拟器验证。"

它就装完了。当然我是有 knowledge 的，所以我知道它是怎么完成这个安装的：它真的在 QEMU 里面启动，然后去看到了那个登录界面，告诉我确实可以登录了，它登录成功了。我告诉它我要创建一个用户名，用户名是什么、密码是什么，它全部都做好，验证完成后交给我。

> **提示**："用模拟器验证"这四个字是这个 prompt 里最值钱的部分。没有验证要求，agent 只能给你一个"看起来装完了"；有了验证要求，它必须自己把系统真正跑起来，拿登录成功当证据。**给 agent 下任务时，一定要把"怎么证明你做对了"写进指令里。**

然后我就启动了这个 USB 的镜像，启动以后我说："我要装一个 tile-based window manager。"你看我现在操作是很顺滑的：我按 Windows 加回车，它就产生了一个新的窗口在右边，和你们用窗口的方式不太一样；当然我也可以用 Windows 加空格把它挪出来。

不会用怎么办？对吧，你可能听说过在某一个 B 站的直播间里面，看到有一个同学他用的很酷的东西。不会用怎么办？我直接让 DeepSeek-V3-Flash 给我生成了一个文档。我说："哎，你能不能看一下我系统现在的设置里面，我要做各种事情怎么办？"它告诉我 Super 加 Enter 是打开 terminal，Super 加 D 是打开一个 app launcher——所以比如说，我按 Windows 加 D，我就可以打开一个 OBS 或者 Chromium browser。

所有的文档，包括你看到的这个中端 NeoVim 的现代配置，我没有看过任何一眼配置文件，所有的一切都是用自然语言完成的。我只是让它保交付：我要什么，你帮我再检查一下，就全部都完成了。

> **提示**：你的学习目标要换。传统顺序是"先学知识，再自己动手做"；现在更高效的是：**你更多的时候需要知道它能做什么、你感知到它能做什么、能做到什么程度，然后你带着它去做一件更大的、它做不到的事情。**

所以我觉得我毕生的修炼——作为一个教 computer science 的老师，我记得我大四的时候，可能跟你们一样大的时候，就在看 Intel 那个几千页的 CPU 的 specification，去看那个每一个 CPU 的 feature 是干什么用的。然后我就突然觉得，在这个时间点上，有一个人可以跟我沟通，他把这些东西全看了，都懂，能做对。

而我现在需要做的，是解锁它的能力。

#### 邮件 bot：把打印机接到我的手表震动上

第二个例子是收发邮件、写草稿。我有一个自己的 skill（我就不展示了）。我的数据库里面有我历史上回过的所有的邮件，所以每当我收到一封邮件的时候，它会自动把它变成一个已读的状态，然后自动帮我写好回复的草稿，用我的口吻。

虽然我现在觉得它做的还不够好——除了一些简单的 routine 性质的东西可以直接用它的回复以外，大部分时候我还得去改——但是我得到了一个 AI 的 bot。它还会把重要的东西处理掉，比如邮件里面的附件：如果我收到一张发票，它就会把我的发票自动保存到一个指定的归档位置。当然这都是我写好的 instructions。

我可以干一件什么事呢？我可以像跟你们的那个 OpenClaw 或者 Hermes 一样，但我用的是我自己的 Apple 的 Reminders。我可以找到我的手机，在我的备忘录里加一个，说："帮我把今天的发票打印出来。"

```text
    新邮件到达
        │
        ├──▶ 自动标记为已读
        │
        ├──▶ 附件（发票…）──▶ 自动归档到指定位置
        │
        └──▶ 生成回复草稿（用我的口吻）
                    │
     手机 Reminders 里加一条 To Do：
     「帮我把今天的发票打印出来」
                    │
             我点 go ──▶ commit
                    ▼
             多了一个 To Do 事项
                    │
            后台自动处理（打印机）
                    │
             推送通知 ──▶ Reminders ──▶ 手表震动
                                                   │
                                        「打印完了。」
```

好，我只要点 go，它就 commit，我就多了一个 To Do 的事项。就跟你们在 Telegram 里跟你的那个 bot 聊天是一样的。然后只要等就行了，他在后台会处理。等到弄好了以后，他会重新给我一个推送的通知，然后这个通知会通过我的手表送到我的手表上，然后我的手表会震动，它会告诉我："OK，打印完了。"然后我所有的日常事务都可以交给它来处理——前提是我放心的、放心的事情。

我在一个叫 bot 的地方加一条："把我收到的上一个发票打印出来。"你看，现在是空的。

**刚才我的发票已经打印好了。** 我收到一条通知叫"发票已打印"，然后我只要回到打印机那里拿走就可以了。

所以它可以干任何事——literally，我那台电脑能干的事情，所有的都能干。我很想，如果有时间的话，如果大学倒闭了，我就弄一个机械手，让它能够做更多的事情。我现在还做不到，但它可以操作我的打印机。

我觉得我现在就可以做这件事情，也就是打印一张纸，浪费一张打印机纸。我觉得这比 Telegram 聊天网页好。而且这个流程会不断地进步——我在 OpenClaw 之前我就这样了。然后我觉得 OpenClaw 或者 Hermes 不是个人 agent 产品的终极形态，这个产品还可以做得更好，所以未来还有很多的空间。

#### 不看书的人：读书、读论文、刷 B 站

第三个例子是最吓人的一个。

你们还在读书吗？你们还看书吗？——看。你们还看论文吗？——看。看论文痛苦吗？——痛苦。痛苦吗？——不痛苦。（大家笑）

我是个很喜欢看书的人。我在你们这么大的时候，每年教科书就要看几十本，还会看很多闲书。但我今天已经不看书了。**我现在已经不看书了。**

> **提示**："我已经不看书了，但我为了上这门课又买了一些。"——这句话最容易被记错。我不读书，说的不是阅读这个行为过时了，而是**"逐字读"不再是获取知识的主要方式**。

但我还是买了一本，因为我上这个生成式软件工程的课，所以我又买了一些。我带了几本来，这些都是我读书的时候仔细仔细看过、甚至看过不止一遍的书。

这个是 Fred Brooks 的 The Mythical Man-Month，《人月神话》。这个标题起得又非常 misleading。首先什么叫"人月"？你们想到的是那个人和月亮吗？就是每到月亮出来的时候就会变成狼人吗？对，that's a joke。Man-Month 就很好理解了，就是仗人力，人力神话。然后这"神话"也不对——神话你们想到的是盘古开天地，是有这种美好的东西。所以这本书应该叫《人月鬼话》，人月是一个鬼话，mythical，The Mythical Man-Month。

还有一些像这个，John Ousterhout 的 A Philosophy of Software Design。这本书非常紧凑，感觉比我当年看的英文版还要紧凑一些。里面有很多真正的软件工程的智慧，非常好。

然后我就读了，我又重温了一下当年读书的感觉，读了第一章。**然后我读完了第一章以后，Agent 启动。**

我会怎么样读书呢？我比 GPT-4o 做得要更好一点。我的"AI 梗同学"会比它更强一点，会比它更 harsh 一些。

我在这里为了做每一页 slides，我会让 GPT-4o 首先做这些事：

1. **先去回看人类的历史**——人类历史里和我讲的这些相关的案例里面，有没有一些 lessons，能得到启发和印证；
2. 根据我讲的这个东西，**找一些相关工作**，而且不只是在 computer science 里；
3. 让它 **prefer well-recognized、high-impact 的 results**——当然这是因为我要上课，我希望跟大家讲比较经典的东西；
4. **thinking in first principle**——在我的"AI 梗同学"里面我有更多的这样的 personality。

```text
     人类历史的 lessons ／ 相关工作检索
                    │
                    ▼
        ┌──────────────────────────┐
        │   3 个不同 personality     │ ◀── 随机性：反复抽卡
        │     独立地讨论             │      每次换一批
        └────────────┬─────────────┘
                     │ 产生分歧的观点
                     ▼
              送给主 Agent 汇总
                     │
                     ▼
        把分歧的观点再送回它们回来讨论
                     │
                     ▼
              直到收敛为止
```

所以我有一个"算力换智力"的 loop。

然后这样我就可以去读、review 那些论文。我会明确地知道自己大概是这样读的：如果我要 review 一篇论文或者读一篇论文，我会说——**从人类已有的知识开始，假设人类已有的所有的东西都已经固定下来了、都是已知的**；然后我要把这篇论文里面**新的东西、最少的东西**给剥离出来。

> **结论**：这么一来，一篇 12 页的论文基本上就没有剩下多少了，会变得非常非常短。这是读论文方法的核心动作：不是"读懂它说了什么"，而是"把它相对于人类已有知识、**增量地**说了什么"给抽出来。

所以我现在读论文的效率非常高。而且我会跟它 chat：我会拿着论文的原文，拿着这个总结，拿着分层次的总结，我跟它 chat。所以我现在读一篇论文的效率会比我以前高得多。

我仍然是读论文的。所以我不是那种只看微信公众号的老登啊——我先 claim，我不是看微信公众号学习的那种人。

最后，我还用 AI 上 B 站。（当然这剥夺了你们的娱乐：如果你想要娱乐，看一个什么华强买瓜的衍生视频，那就不要用 AI 读。）

我是怎么读的？我就给它一个 BV 号。比如我上学期的课程，给一个 BV 号，1 个小时 27 分钟。它会把这个 podcast——比如 Matt Pocock 又发了一个什么他的软件工程实践（其实我觉得他也挺神棍的，有些经验可能不完全适合我们的课程）——总结成一个**自动的图文的时间轴**。

你看这个整理过的文本，质量还是可以的，**比字幕的质量要高一些**。这就是全文。这个图文版的图片会稍微少一些，实际上我的截图的密度会更大一些：就是我当两帧图片之间的间隔大到一定程度的时候，我就会截图。这样我就得到了这个视频所有的 **ground truth**。

这时候"AI 梗同学"就可以上线了。它会为我消化这一个多小时的视频。因为它有我的记忆，把我认为不需要看的东西——比如这里面所有的东西都是我非常清楚的东西——那么我就不需要看它，去掉。

> **结论**：我就可以在**几分钟**的时间里面看完一个**两小时**的视频。而且我基本上确信，我还是很好地知道了那里面不一样的东西。这是个非常可怕的事情。

#### 课间彩蛋：把掉线的采集卡接回去

我们课间休息之前，刚才还有一个非常好的案例。

在直播的时候，我的 USB 的摄像头卡了。教室里面大概是这样的：它有一个采集卡，视频的采集卡可能会从网络或者什么，因为这边还有好几台机器。我不知道为什么学校里面用了一个成本那么大的方案，我觉得我可能用 500 到 1000 块应该就能解决整个问题了。

一个成本很高的方案，然后它有一个采集卡进来，但是那个采集卡的 USB 断开了。你看到现在我用左边挥挥手，画面是动的——说明信号源是好的——但是 USB 就断掉了，不知道为什么断掉了。

断掉了以后，我刚才就立即让 Agent 修了一下。直接，这就是一个 prompt：

```text
prompt: 我先看看系统的 USB 设备的情况，找出设备……
        我的 USB video 有问题，能不能 reconnect？
```

这是 DeepSeek-V3-Flash 干的，它用你们前所未见的 Linux 命令——有些其实我有概念，但是我也不知道它具体是怎么样工作的。

## 从白板 π 到飞轮：Agent 的生态、软件工程，和做题家 AI
> 对应块：BLK02 | 覆盖分集：P01下 | 块标题（分集名）：《欢迎来到未来 [01-Raw_26生成式软件工程》

我刚才说了，π 不是 AI 的真正的形态。

### 白板 π 只是起点，Agent 是一个生态

作为普通人，刚才我给大家展示的是一个白版的 π——什么也没有。你在 π 的官方网站上把它安装下来，配置一个 DeepSeek-V3 Flash 的 API key，你立即就可以得到刚才所有那些东西。多么可怕的一件事，对吧？

但是 Agent 远不止于此，Agent 拥有一个完整的生态系统。

我上课的时候一直会说 Computer Science 的定律：**如果有一件事情它是合理的，并且你想做，那么百分之百一定也有别人会想做。** 在 pre-AI 的时代，开源社区多多少少会来公开一些脚本——我今天又发布了一个新的脚本可以干这件事，你到 GitHub 上把它拉下来就可以做这件事。在 AI 时代，做这件事情、复用别人的能力，变得前所未有的轻松。

我可以往 SkillHub 上面发一个 skill，然后你可以在 π 的插件生态上面找到它。所以你们想想，作为普通人，下一步你做应该做什么？

**应该用插件把浏览器管控起来，应该用插件把电脑管控起来。**

### 接管浏览器：Chrome DevTools 到底有多强

浏览器是一个非常好的工程产品。我们用的是 Chrome，那其实是一个非常好的工程产品，它可以说是人类软件工程史上的奇迹之一，非常地复杂。看起来就是一个浏览器，显示网页的，它的代码量甚至远超操作系统内核。因为它要和用户打交道，它有大量的比如说图形栈，对吧？还有这个显示相关的东西、性能优化等等。

而浏览器是专为开发者设计的，它有个接口叫 **Chrome DevTools**。你们应该是用过的，对吧？比如说你们打开 Chromium，然后你们按那个 F12。

你们都改过。比如说你很讨厌这个东西，对吧？——是有点讨厌。好，讨厌就 delete 把它删了，对吧？它就没有了。当然你这里是可以调试它的，对吧？所以一般来说网站都会在这个 Console 上面嵌入招聘广告。招聘广告，这个同学们应该也是发现过的吧？比如说你们上 B 站，然后 F12，它没有招聘广告了吗？我记得 B 站也是有的。

在这里你可以看到很多的信息。比如说你可以找到这里的 HTTP 的头啊等等。然后你可以把这个链接 copy，可以把它的命令给 copy 出来。这样你就可以在浏览器里带着它的 cookie、带着所有的状态，用 `curl` 这个命令去请求，这样你就可以得到列表。这都是以前，就是在 pre-LLM 时代开发者做的事情。

> **结论**：但是在 LLM 时代，变了。**普通人也可以享受到 Chrome DevTools 的所有厉害的地方。**

我记得我们在 2020 年的时候，我们做过一个非常疯狂的 project。大家都知道 Android 的应用是可以写 Java 的，我们假设是一个 Java 的应用，然后 Java 或者这个 Kotlin 都编译到 Java 虚拟机，然后我们就可以在 OpenJDK 上运行一个 Android app。

然后这个运行 Android app 的时候，会把界面上面的按钮——比如说这个按钮的 bounding box，就是那个它的坐标都算出来，上面的文本也知道。但是我不用 Android 的那套渲染，我直接在浏览器里面渲染。你可以在那个 Chrome 里面看到一个计算器，然后那个计算器里面每一个按钮都在，上面的字也是对的，然后你可以点，点了以后那个计算器的状态就变了。我在本机执行了一个 Android app。

所以这是一个非常非常 powerful 的工具，但我今天不讲这个。

### 让它去填教务系统：一次真实的翻车与自我修复

让我们来干一件事吧。你们都讨厌教务系统吧？我也很讨厌。这个我一会儿会讲的，就是当我讲到软件工程的时候，我还会特别讲到这个教务系统是一个软件工程的非常反面的例子。

我刚才在 π 里面说"帮我打开浏览器"，这个浏览器是属于 π 的。所以你们可以干什么呢？比如说我很讨厌动不动叫我们填东西，所以我说——

这个时候你看豆包输入法的含金量又提升了，对吧？我在做这些日常任务的时候，我会按一个键，然后打开豆包输入法和它对话。当然在这里我的 Linux 没有豆包输入法，而且我好像没有配置这个语音输入，因为它的声音输入可能会有点麻烦。

我说的是这句：

`填写现在教学周历是空的，帮我用随便什么 AI slot 填写，不要看任何东西。`

对吧？因为它如果知道这门课——现在的目录是这门课的 repo 的话——它其实会读我的什么 lecture notes 之类的。我不要不要不要。

你看，它还在干这个事。你看它，它就不听指令，这是 DeepSeek-V3 Flash 的麻烦。如果是 Full text 它会知道。这就是 DeepSeek-V3 Flash 的问题，它不看。翻车也是经常有的。所以就是模型其实还在不断的能力增长中：如果我用最一线的模型，它就会做得更好。我用 Flash 还有一个原因，就是它在客场会更快。

没关系，它会了。**这就是 Agent**，你看到它的过程——你看，它会不断地反思它做的这件事情合不合理，然后它能够找到应该怎么办。

对吧？看起来翻车了，它刚开始在尝试，尝试以后它找到正确的方式。所以说 Chrome DevTools 是一个非常强大的工具，它最终发现它用那些比如说直接注入一个事件的方式是不行的，但是点鼠标是可以的。

然后这意味着什么呢？你看它已经开始可以填写真实 AI slot。我完全可以不需要值守，让它随便给我填点什么 AI slot。

### 能力真正的边界：把走通的一次沉淀成脚本

能力真正的边界在哪里？**当它走通了一次以后，这个 session 里面的东西会留下来。**

我可以把它沉淀成确定性的脚本，对吧？它可以形成记忆，就说这条路径应该怎么走，什么能成功，什么能失败；它也可以把这个走过的这些网页全部变成脚本。

然后你就得到了一个自动选课抢课的系统。

```text
        │   Agent 在 π 浏览器里走通了   │
        │   一次「填教学周历 AI slot」  │
        └──────────────┬───────────────┘
                       │  这个 session 留下了痕迹
        ┌──────────────┼──────────────┬────────────────────┐
        ▼              ▼              ▼                    ▼
   ┌─────────┐   ┌──────────┐   ┌──────────┐   ┌────────────────┐
   │ 确定性的 │   │  记忆     │   │ 把走过的 │   │   产物：        │
   │  脚本    │   │ 哪条路能走 │   │ 网页全变成│   │ 自动选课抢课系统│
   │          │   │ 哪条会翻车 │   │  脚本     │   │                │
   └─────────┘   └──────────┘   └──────────┘   └────────────────┘
```

所以这是多么恐怖的一件事，对吧？你不需要有任何的知识，它就在这里帮我填 AI slot。如果本科生院一定要我填的话，我就用这个方式出击。

### Unix 的哲学：管道、自由组合与无限复用

而这其实是一整个生态，它不是——你们会觉得 OK 好，这又是一个很 fancy 的案例，对吧？我今天讲了好多，哎，我可以这样用、这样用、这样用，每一个都很厉害。

而因为我是教操作系统的嘛：操作系统上面的应用程序，Unix 的 philosophy 它能成立的原因，就是那个管道能实现所有程序的自由组合和无限复用。$1 + 1$ 是可以大于 $2$ 的。

而刚才我说的所有的东西——比如从一个浏览上下文里面提取这个记忆和脚本的 skill、刚才那个浏览器的 skill、我又有一个什么在网页上面怎么浏览的 skill——它们是可以加在一起互相调用的。

所以，现在这个 AI Agent 的这个生态其实已经达到了一个**临界点**了。马上你就会看到这些东西的互相组合，可以成百倍成千倍地放大个人的能力。

### 飞轮：把世界上所有信息源变成自己的知识

真正对于一个一般人来说，他可以做的，他可以去找到世界上各种各样的信息源。我不知道你们有没有订阅那个什么 AI 早报，对吧？每天早上起来刷牙的时候就听一下，反正它也是 AI 生成的——但它是有 RSS 的，它是有这个推送源的。然后你有这个 B 站的推送，你有 arXiv 的推送，你有 Hacker News 的推送。

然后这些东西都可以沉淀成 skill，或者沉淀成脚本。

```text
   信息源（都有 RSS / 推送源）        能力源（都是自然语言 skill）
   ───────────────────────────        ───────────────────────────────
   · AI 早报（AI 生成的，但有 RSS）   · 浏览器管控 / Computer Use
   · B 站推送                        · 从浏览上下文里提取记忆与脚本
   · arXiv 推送                      · 在网页上该怎么逛
   · Hacker News 推送                · ……它们可以互相调用
            │                                  │
            └───────────────┬──────────────────┘
                            ▼
             ┌───────────────────────────────┐
             │         信息处理系统          │
             │   skill × skill × skill      │
             │  （Unix 的管道：自由组合）   │
             └───────────────┬───────────────┘
                             ▼
                        有用的知识
                             │
                             └────►  调工作流，调出新一批 skill
                                         回到源头，飞轮转起来
```

这里面就是由各种各样的 skill 构成的，都是自然语言，所有的你一行代码都不用写，但是它可以复用。你会不断地调整这个工作流，然后它就会不断地产生对你有用的知识。**你的飞轮就转起来了。**

然后你想象一个拥有这样飞轮的人，你在这个飞轮上和没有飞轮上，这是一个多么可怕的事情。

### everything is code：从 bits 到 atoms

我们总结一下。作为一般人，一般人可以学习、看书、做总结，然后可以实现一个这样的信息处理的闭环，还可以操作，用 Computer Use、Browser Use 去做任何你平时日常里面可以做的事情。

同时因为 everything is code，我可以用 AI 生成你能看到的所有东西：视频、论文、东西。

我和一个同学做了一个叫 **VibeFab** 的项目，用一个自然语言，3D 打印机可以打印一个东西出来。真的东西也是 code，也是 Python 代码，生成的 Python 代码。所以能够实现从 bits 到 atoms。

这个未来已经来了。我们看着 AI 的能力只会变强不会变弱。那么下一个问题就是：**它什么时候来，以及我们应该怎么面对它。**

### 临界点那天，我也会被消灭

这时候你可以理解为什么 OpenClaw、Mem0 这是一个现象级的产品，对吧？为什么它们能给人这么惊奇？就一个自我进化的能力。

虽然我作为一个 CS professional，我其实不惊讶。而且我其实挺讨厌它去组织一个 memory 的——因为它有它的提示词，然后它会把一些我根本不想让它记住的东西记住，我想让它记住的东西不记住。所以我更多的时候是我调用我自己的流程，把这个东西写到我的数据库里，然后 AI 会做这些事。

但也许只得有一天——这正是因为现在的产品还不够成熟，模型可能还不够强。但有一天模型过了那个临界点的时候，我现在就比 AI 多一点点，我比 AI 多的那一点点也没了以后，我就也被消灭了，我也被消灭了。

然后在这一项你能想到很多很多更有趣的事。比如说我刚才说的录屏，对吧？你就录屏一天，让 AI 自动改进你的流程，你就问 AI：

`我这一天干了这些事，你觉得我还有没有提升空间了？`

很有可能，就尤其是大家在初学者的阶段，还有很大的提升空间。所以你们是，这代人在 AI Native 下长大，你们这一代人才是有未来、才有出路的。像我现在已经被迫处理很多事务性的事情，我已经没有这个机会了。

虽然现在还没有完全地准备好，但我真的是很难理解为什么有些旧人类，尤其是老登们，为什么还要心安理得地每天去做重复的事情。

出了出了一些小问题，但是 doesn't matter。我只要让它修就行了，这个不重要。显然我需要一个更好的模型。但是我不理解为什么这些人不意识到——可能公众号的消息和真正你第一手用过的感受是很不一样的。

但这个时代来了，所以我们需要认真地思考这个问题。**这是普通人的视角。**

### 改卷子统分流水线：我怎么和 Agent 协作

那接下来是我的 Computer Science 从业人员的视角。如果你们只用 Agent、Codex 刷的方法抄抄写写把作业做了，那你们真的是太小看它了。

我们是 Computer Science 的人，我们非常知道编程的能力界限在哪里。一般人很容易提出一个需求，然后这个需求 Agent 可能做不好、做不了；或者说他不知道应该怎么样 prompt 这个 Agent，能够确定性快速地完成。但我们知道。**我们知道的是，我们是怎么可以把需求编译成可复用的东西**：什么东西应该以代码的形式复用，什么东西应该以 skill 的形式复用，我们会非常地清楚。

我举个例子。这件事情如果是一般人和 AI 协作，可能现在 AI 还做不到。我改卷子，改完以后我要统分。一般来说这个任务就是给助教的，助教你去把这个分加了吧。然后助教就掏出一个计算器，$12 + 13 + 14 + 15 + 16$，然后再仔细核一遍。

所以我觉得我对我的学生太好了，这样也不行。我今年尝试了这样的流水线：**我基本上第一遍先是 vibe coding 让它出脚本，测试，测试完了以后我就一遍头把它跑完。**

我的流程大概是这样的：

```text
   办公桌 · 从顶向下的摄像头（固定拍住试卷的一个位置）
   │
   │  按一次回车
   ▼
   拍下一张试卷照片
   │
   ▼
   ┌────────────────────────────────────────────────┐
   │  离线阶段：本地 27B 千问 3.5（Ollama）         │
   │  识别 → 姓名 / 学号 / 每一个小分                │
   │  输出 → 往文本文件里写一行                      │
   └────────────────────────────────────────────────┘
   │
   ▼
   ┌────────────────────────────────┐
   │  一张卷子一个回车，左右手不闲  │
   │  没摆好 → 调整 → 再来一张      │
   └────────────────────────────────┘
   │
   │  再按一次回车（第二阶段，反序）
   ▼
   ┌────────────────────────────────────────────────┐
   │  语音播报：学号 241220xxxx                     │
   │            小分 11 + 12 + 13 + 14 + 15         │
   │  同时：左手按回车，右手拿笔                    │
   └────────────────────────────────────────────────┘
   │
   ▼
   ┌────────────────────────────────┐
   │  人工逐条核对（OCR 会错）      │
   │  分数由脚本 eval 算，不由模型加│
   └────────────────────────────────┘
   │
   ▼
   誊写最终分数到卷面
   │
   ▼
   自动汇总 → 教务处 Excel 模板 → 上传 → 抽样检查 → 提交
```

我基本上第一遍先是 vibe coding 让它出脚本。我刚才说摄像头在办公桌上，从顶向下，拍到试卷的一个固定位置，我把它先调好。调好了以后，我按一个回车，它就会拍一张照。拍一张照以后，它就会回头去 offline 去生成，去用千问去识别姓名、学号、小分，每一个小分。然后它会写一行到一个文本文件里面。

所以我是一张卷子一个回车，一张卷子一个回车，我是两只手的，我两只手都没闲着。如果我这张卷子没有摆好，我就可以调整一下然后再来。

第一个阶段完了以后第二个阶段，按照反序，我还是以回车键。这时候我左右手就换了，我左手按回车，右手拿笔。按回车以后，我会用语音来播报谁的学号是什么 241220 几几几，然后它把每一个小分都报出来：11 + 12 + 13 + 14 + 15。

我一边报我一定要检查，因为 OCR 会有错。我不信任它，我要对我的班上的每一个同学负责。我检查过没问题以后，我就会把它报的最终的分数给誊写到卷面上。这个分数是用脚本、用 `eval` 算出来的，所以它是不会错的，**它不会因为大语言模型的幻觉算错——我没有让大模型做加法。** 所以我对所有同学是负责的，每一个分数我都看过的。

最后分数会自动汇总到教务处的 Excel 的模板上。我可以用这个方式把那个 Excel 文件上传，然后我再抽样检查，确保没有问题以后再来提交。

> **结论**：确实是配合一个豆包舒服，但因为我是一个 CS professional，所以我知道边界在哪里。我知道我的本地有一个 27B 的千问 3.5，然后 Ollama 可以用，然后我知道应该用这样的流程、一个最舒服的流程，减轻我和 Agent 之间同步的代价。

而这些东西都是如果一般人也试一下：回头哪怕是跟最好的模型说"我现在改了 140 张卷子，改好了，小分都写上去了，我要统分，帮我实现它"，到不了一个这么快、收敛的方案。

所以有些时候现在我还需要人和 AI 要共建。但我也赌有一天 AI 的能力能够强到它能够感知我的一切，然后能帮我做一个完美的东西。

### 把数据偷出来：QRgen 是怎么来的

那我们就可以回到软件工程的话题了。毕竟这是生成式软件工程，我们来做一个小的软件工程的产品吧。

因为我选它正好是前几天一个星期左右的时间里，我们在群里面闲聊，说机器被管控了很讨厌。然后我们就想有没有可能——你假设你现在在一个金融公司里，这个金融公司的数据是可以带进去的，但是数据是出不来的。比如你插一个 U 盘，你可以把一个 Word 或 Excel 拷进去，拷进去以后它就进去了，但是没有任何文件可以拷出来。机器做了管控，它不能执行任何不信任的程序，不能显示任何不信任的网页，你唯一能做的就是在远处悄悄录屏。**但是你想把一个很大的文件给偷出来，你怎么办？**

这就是 Computer Science 的人才能想到的事情。

我做了这样的一个程序。这是一个典型的软件工程任务。这是一个二维码，然后我可以把任何一个文件的内容——比如我现在文件内容就是 hello world——放进去。Hello world 完了以后，你看这个二维码就变了。你们可以扫，扫一下，我也扫一下。这个二维码没有危害，应该不会封号吧。扫出来是一个 Base64 编码的字符串，它是 0001，Base64 编码的字符串。

然后我这可以是一个非常非常长的字符串。比如我有一个很长的 hello world，我就可以编码成一个二维码的动画。

```text
   任意文件内容             "hello world"
              │
              │  ①  Base64 编码（全部用 Excel 公式）
              ▼
   "aGVsbG8gd29ybGQ..."     ← 可以非常非常长
              │
              │  ②  切帧：每一帧渲染成一个二维码
              ▼
   ┌─────────┬─────────┬─────────┐
   │ [ QR ]  │ [ QR ]  │ [ QR ]  │   帧号 6、7、8……
   │  帧 6   │  帧 7   │  帧 8   │   按住 F9 一直刷新
   └─────────┴─────────┴─────────┘   循环播放
              │
              │  ③  远处悄悄录屏，把每一帧都拍下来
              ▼
   在本机把所有帧拼回去 → 数据被偷出来了
```

你只要偷偷地录屏，然后你把所有的每一帧——它是循环播放的——都拍到，你就把这里的数据给偷走了。

所以我用完全合法的方式：Excel 是合法的。然后我用了所有的东西都是公式，大家可以看一下，公式在这里。全部都是 Excel 的公式，都是合法的 Excel 公式，而且是 2019 之前 Excel 都兼容的公式，然后把这个二维码偷出来。

你也可以如果能在那个机器里面装 exe 的话（当然一般是不行的），可以用抖鼠标的方式：在上下维度抖鼠标就是 0，左右维度抖鼠标就是 1。然后你用一个远程桌面连进去，然后你就可以往里面传输数据，然后你用二维码的动画就可以往外送数据。你只要有一个远程桌面，你就可以在内部做个虚拟网卡——你可以把远程桌面变成虚拟网卡，然后你就可以和它连起来。

你是 Computer Science 的学生，你知道上过操作系统、上过计算机网络，你知道这里面需要的组件是什么，你就可以把它 vibe coding 出来。**这是一个 AI Agent 可以做到的。**

### AI 交出来的两份作业，都死在维护的泥潭里

当然这就是一个有意思的例子，我这个 Excel 是用 AI 生成的。**你的想象力限制了你能做什么。**

然后时代的车来了，我已经躺在车底下了。不着急，AI 也不是完全完美的。在 LLM 之前的时代就有个老梗说：idea 都有了，我们是商学院的——不知道你们商学院同学有没有跟你们说过这个，"idea 都有了就差一个程序员了，我们去挣一个亿吧"。ABCD 轮也都有了，"就差一个天使投资人了，没有人投资我们"。

没有那么简单。首先 AI 很强，我展示了 AI 可以做什么，但是**产品是一个系统性的工程**。你要做一个外卖，你想做一个外卖网站，你要做前端、后端、交互、运营，整个流程上面任何一个环节做不好，产品都是直接暴毙的。虽然 AI 都可以做，AI 也能设计前端，也能做后端，也能交互，也能运营，它看过世界上所有的书，它什么都知道。但是如果你组织得不好，也是立即就报废。

实际上，我的 `QRgen.xlsx` 做了一个实验让 AI 去做，AI 生成了完全不可维护的代码。我马上就会讲到软件工程领域。

#### 教务系统：每年花巨额的钱，养一个屎中屎

`1.nju.edu.cn` 难用吗？难用吧，屎中屎。每年学校都会花巨额的钱让公司维护这份代码。

因为他要添一个功能，打个比方。因为我在用 Browser Use 的时候，还稍微 hack 了一下系统，我发现有些隐藏的字段，比如说你能够看到一个学生的校区。

在苏州校区建成之前，这个系统里面是不需要这个字段的。为了兼容苏州校区——**写过软件的人都知道，你们在需求设计的时候，没有想到学校竟然还有校区这个东西，数据库里就没有这个东西。** 突然有一天你的产品经理说："哎呀，我们两个校区选课要分开的时候……"

当然，现在是没问题，因为你是产品经理，你就跟 AI 说："现在原系统是可以用的，我现在多了一个校区——苏州校区，我要把校区分开。" 然后 AI 就开始写代码。但是还是很容易失败的。这就是非常典型的软件工程的失败。

#### QRgen 到底是怎么暴毙的

它是一个非常明确的需求：我要一个 QR code 的 Excel，然后我只是使用 Excel 2019 兼容的公式，把输入的任意一个字符串先用 Base64 编码，然后转成 QR code 动画，每一帧是什么什么。当然我开始让 AI 做的时候，还发现这个任务经常做着做着就停下来问我。然后我说不要，这个很容易失败，你不要问我了，必须把它做成为止。

但是很遗憾，AI 对这个需求的理解是不到位的。GPT-5.6 啊，GPT-5.6 依然误解了我到底要一个什么东西。GPT-5.6 说得对，因为它看到了我的完整的 slides，但我没有告诉它我是怎么做的。

> **易错点**：AI 哪里容易犯错呢？AI 容易在小 corner case 上犯错。GPT-5.6 第一秒钟就被带歪了——**它希望做一个对于任意的 $s$ 都满足正确性的东西，这就已经错了。** 不是的。软件工程的第一步：**不要扩大，做最简单的东西，不会失败。** 它没有理解这一点。

事实上是这样的，我后来做了一个受控的实验。因为第一个版本是我带着 AI 做的，所以做的时候还比较顺利。后来我就直接把 specification 告诉 AI。

**GLM-5.3** 第一次思考了 25 分钟，然后开始疯狂地输出，写了超过 32k 的 output token，直接把我的 Claude Code 干暴了。它说你已经超过了默认的 output 限制了，然后被截断了，然后它再跑。总共跑了——我没有监管——跑了 6 个小时才跑完，但是对的。

所以智谱它一直说自己厉害的地方是它可以做 Long-Horizon 的任务，是对的，它后续训练确实，GLM-5.3 在 Long-Horizon 任务上真的做得很好。

而 **DeepSeek-V3 Pro** 也是晚上放着跑的。它已经没有办法遵循指令了：我第二天早上看的时候，它给了一个 Base64 是硬编码的，它用 Python 算了一个 Base64。这明显就不符合这个指令——把一个输入的任意字符串先用 64 进制编码，正常人的理解应该是 Base64 编码是用 Excel 公式来编码的。它已经不听指令了，它是用 Python 算了一个 Base64 贴到那个公式框里。如果我的字符串改了，它的 Base64 是不会改的。然后我就骂它了。我骂完以后，它那个 chain-of-thought 就说：

> This is a fundamental design flaw, we need to rethink.

不管怎么样，它们两个最终都完成了任务，所以 Agent 完成任务能力很强。**但它们生成的都是没有办法继续维护下去的 AI Slop。** 它和 `1.nju.edu.cn` 的死法是完全一样的，就是软件工程里面最经典的死法：上来我知道需求了，我把这个需求实现了就好了，直接就陷入了维护的泥潭。他们没有想一个好的软件架构，使得这个软件能够——

有一个比较夸张的说法是：我们能不能做一个软件生存 100 年？100 年的时间里面软件会发生很大的变化。你想过去没有 100 年，50 年操作系统发生了什么样的变化，图形界面发生了什么样的变化，用户界面、应用程序发生了什么样的变化。有没有一个软件能生存 100 年？还不知道。但是你看连 GPT-5.6 都还不知道。**其实我们需要一个好的架构才能完成这个任务。**

### 让它一次就对：先造一门中间语言

我是怎么办到的呢？你们可以想一下，如果你们要一个 quick quiz，如果你们要实现这个 QRgen，你们会怎么写？怎么 prompt AI？

实际上我只用了少量的 prompt，**GLM-5.3 在 200k 上下文里面就完成了第一个正确的版本。** 当时是我升级了 GLM-5.3，我就想测试一下它的能力。

我干了这样的一件事：我让它设计各种各样的 Python 类，就有点像编译器一样。比如说，我要设计一个 Python 函数叫 `XOR`，一个符号系统，因为这里面涉及位运算。然后这个东西既可以在 Python 里面直接执行，又可以翻译成 Excel。也就是说我做了一个像编译器一样的基础设施。

然后我有 `XOR`、有 `CONCAT`，也就是说我做了一个中间语言。有点像如果你们今天做 AI Infra 的话，你们会需要 Tile-lang 这样的中间语言。我让它先设计一个中间语言，这个中间语言既对 Python 友好，也对 Excel 友好。

```text
                 规格（Specification）
            「Excel 2019 兼容公式 + Base64 + 二维码动画」
                              │
                              ▼
        ┌─────────────────────────────────────┐
        │   中间语言（既对 Python 友好，       │
        │          也对 Excel 友好）           │
        │   符号系统：XOR、CONCAT ……         │
        └──────────────┬──────────────────────┘
                       │   像编译器一样，一份语义、两个后端
              ┌────────┴────────┐
              ▼                 ▼
      ┌──────────────┐  ┌──────────────────┐
      │  Python 后端  │  │   Excel 后端     │
      │  在这里验证：  │  │  在这里验证：     │
      │  Base64 算得对 │  │  翻译正确        │
      │  每一个像素算得对│  │  公式 2019 兼容  │
      └──────────────┘  └──────────────────┘
              │                 │
              └────────┬────────┘
                       ▼
                 最后一把生成就直接正确
```

然后我只需要验证的是，我的每一个翻译都是正确的，到 Excel 翻译是正确的，到 Python 的结果是正确的。然后我可以在 Python 世界里面验证我的 Base64 编码算得对不对，我的二维码的每一个像素算得对不对。然后我再单独验证每一个东西和 Excel 的公式翻译的正确性、兼容性。

代码非常的干净，也不长。可能长，但是维护性远比——大家可以看一下 AI Slop。GLM-5.3 的 build Excel，我真的觉得 AI 还是挺厉害的，无穷多的硬编码。

然后再看一下 DeepSeek。不同的 roadmap，但是一样的思路。

这两份代码，我让它们把工作区从一个位置移动到另外一个位置，它都得修两个小时。它不停地错，因为它是硬编码，只要改错一点点地方，它的 verification 就通不过，它得再像 Agent 那样修。确实可能能修完，但是这个是软件工程。

> **结论**：所以在今天，你还需要深层次软件工程，需要这门课。我作为一个软工人员，其实是做软件工程的，把我的毕生所学……虽然我觉得 AI 应该也懂的，但我不知道为什么，可能是因为后训练的原因，使 AI 上手解决问题的欲望太强了，导致了做得还不是特别好。

### 三个空间：Intention、Specification、Implementation

这里面核心的问题是什么呢？当我们要用 AI 解决问题的时候，我们有三个空间。

```text
  ┌──────────────────────────────────────────────────────────────┐
  │  Intention space          老板 / 甲方 脑子里的那一句        │
  │  "我要一个教务系统"   "做个小程序，给我挣一个亿"            │
  └────────────────────────────┬─────────────────────────────────┘
                               │
                               │  gap ①  猜错了，做出来就不是我要的
                               ▼
  ┌──────────────────────────────────────────────────────────────┐
  │  Specification space      功能、架构、界面、要求              │
  │  界面怎么呈现？schema 怎么定？分几张表？                    │
  │  key-value 还是关系型数据库？每一步都带来截然不同的结果      │
  └────────────────────────────┬─────────────────────────────────┘
                               │
                               │  gap ②  实现了，但不满足 spec
                               ▼
  ┌──────────────────────────────────────────────────────────────┐
  │  Implementation space     C 程序设计、库、框架、测试          │
  │  "这个需求可以这样实现，也可以那样实现"                     │
  └──────────────────────────────────────────────────────────────┘
```

> **定义**：第一个空间叫 **Intention**，是你的意图，就是你脑子里面想的是什么。比如说，老板说"我要做一个国民级的应用"，这是他的 Intention；或者说"我要做一个小程序，给我挣一个亿"，这也是那个 Intention。小程序可能有一些情怀："同学们点外卖不方便，我要做一个点外卖的小程序，挣一个亿就可以了。" 在 Intention space 里面，这已经很大了。有的人想做外卖，有的人就想做 AI 读论文、AI 梗图。

在 Intention space 里面，每一个 Intention 都有很多种可能的实现，这是 **Specification**。Specification 就是说这个程序的功能是什么，选用什么样的架构，满足什么样的要求，它有几个界面、每个界面有什么功能。

以刚才这个例子，Intention 是"我要造一个能够用二维码偷出数据的 Excel"，这是一个 Intention。然后 Spec 就是刚才说的一句话：Excel 2019 兼容的公式、Base64 编码、二维码动画。

你看到，我的这个 Spec，选用不同的架构、选用不同的实现方式，像刚才那种实现方式，就会带来巨大的差别。而同样都是满足 Spec 的，还有不同的 **Implementation**。哪怕是满足同一个 Spec 的，都有大量的 Implementation。

**所以软件工程真正的 gap 就在于这些东西之间是有 gap 的，都是有 gap 的。**

因为在你的 Intention space 里面，提需求的可能是老板、可能是甲方，他没有任何计算机的经验。校长说"我们要一个教务系统"，公司说"我可以搞定"。Intention 就在这：我要教务系统，要把学校里面所有同学相关事情的信息化，没了，就这一句话。

然后在 Specification space 里面又有好多好多的选择，不同的方式。这个界面到底怎么呈现？我觉得这个界面设计得很糟糕。然后到界面完了以后，这个数据库的 schema 应该怎么定？到底应该分哪几张表，每张表里面有哪些列？我到底要选择 key-value 型的数据库，还是关系型的数据库？每一个选择都会带来截然不同的结果。

这是软件工程在很早的时候的一个梗图。它讲的就是这个 gap：**在各个维度上，程序员所想的、和产品经理所想的、和客户所想的，是完全不一样的。** 客户是这样解释他的需求的，Project Leader 是这样理解它的，分析的人又是这样想的，宣传的人又是这样宣传的，最后实际上 customer 要的是这个，但是最后造出来的是这个。这就是这个梗图。

造成这个的根本原因，实际上就是这些 space 之间的 gap。而当我们谈软件工程，不管是软件工程还是深层次软件工程的时候，**我们要做的就是补上这些 gap。**

而今天，这些 gap 是怎么补的呢？**模型用的是猜。** 模型就说"既然说了这句话，那我猜应该是这个吧，我就去实现"。

为什么呢？因为后训练的时候，模型是有 reward 的。**我们每个人都是 reward hacker。** 模型受到奖励，任务做对了、做完了、测试通过了，就会得到奖励。所以它就会形成一种倾向，它会疯狂地立即上手去把这个任务尽可能快地完成。因为做慢了要挨骂，对吧？

它能够越来越多地做一些简单任务，这当然是好事，但是和我们人解决问题的方式还是不一样的。

你看作为计算机或者软件工程的学生，你们是怎么学习的，怎么弥补这个 gap 的？你到大一第一门课是什么？C 语言程序设计。所以你先学的是这个东西里面有什么。

**你跳出你学习的框架。** 你现在学的是这个 implementation space 里面有什么东西，把这里的东西都弄得非常熟练了，"这个需求可以这样实现，这个需求可以这样实现"。然后你再去上什么软件工程课，这样一点一点地把你对这件事情的判断给补全。

但是，在 AI 时代这件事情当然是发生了变化，对吧？**你既要阻止 AI 去乱猜，你又要尽可能地发挥 AI 能够从 A 到 B 的能力。** 这个时候，我想这就是我这个学期要讨论的问题。

### 焦油坑：人月神话留给我们的那个警告

讨论的问题就是我们的生成式软件工程想要告诉大家的。我开个头，《人月神话》（*The Mythical Man-Month*）：大型动物一旦陷入这个焦油坑就很难逃脱，对吧？它像泥潭一样陷进去以后，而且濒死的动物又会引来各种掠食者，然后它们也进到焦油坑，它们也出不去。

这里面有一个非常经典的论断：**如果一个团队已经开始，或者一个软件产品已经开始失败了，你加进去更多的人只会让它变得更失败，不会变得更成功。**

也就是说，就跟刚才那个 QRgen 一样，当一个产品已经开始，AI 已经开始产生 slop 的时候，你投入更多的 token，你也只会让它变得更失败。**AI 会不断地在它那个失败的东西上面再往上浮起来一点、浮起来一点、浮起来一点，直到你再也付不起那个 token 为止。**

然后你看，教务系统不就是这样的吗？随着工程不断地，我觉得每一年你打开那个教务系统，你都发现它增加了功能，你们也发现了？然后我的感受就是学校又花了很多纳税人的钱。Anyway，这也许多半是坏事，因为他促进了经济的发展。

然而软件工程研究的就是：怎么样在这个 gap 实际存在的情况下，把一件足够大的事做好。刚才我们讲的是一个很小的事；教务系统是一个相对来说比较大的、真的可以挣到很多钱的一个产业级的产品；再到你真的要做一个国民级的、新的东西，它有一套方法论。

**这个方法论就是这些人在投入了 billions of dollars 里面得到的教训**，对吧？他管理了很多人，每一个人都很聪明，结果陷入了焦油坑。

软件工程是有技术的，对吧？因为打个比方，南大有很多做软件工程的老师，比如说他做什么程序分析、做测试的。那他就是说：如果你在 implementation space 里面已经有一个代码，我能不能自动地为它生成更多的测试用例？或者生成一个代码的审查的东西，在这个代码不满足 specification 的时候，或者潜在不满足 intention 的时候，我能够给你一个 warning。他就是做了一件在这个 big picture 里面非常非常微小的事情。

然后我们有的时候，比如你们在课题组里面开始加入课题组做研究的时候，你们就看到那个非常微小的事情，忘记了这个 big picture 其实是这样。**软件工程是一个有技术，也有人类学、也有社会学、也有管理学的部分。**

然后恰好我觉得在生成式软件工程里面把它们变成了 AI。你管一堆不会和你抬杠、只会 "You are absolutely right"、会听你话的人。而在软件工程里面，他要研究：这个人不听你话怎么办？对吧，你怎么样管控这个团队的风险？这个人离职了怎么办？跳槽了怎么办？到竞争对手去怎么办？这都是软件工程要研究的。

然后如果你去看一个软件工程的研究领域的话，它也是一个非常广的，对吧？AI for SE、SE for AI、架构、设计、可靠性、演化、这个软件能不能长期生存下去、human social aspects、需求。这个特别特别重要，**因为越早的时候这个 gap 是放大的，你在这里微小地变一点，你会在甚至这里产生巨大的变化。** 所以一般来，这些大型的软件系统都是在这个点上面出错了，没有做好，导致了整机全部的崩盘。

这里面有一个我觉得是我们现行教育体系的一个很大的问题。你们从高考过来到现在，你们所有的考试题都是分钟级能解决的，对吧？假设你做大作业你就可以用豆包摸鱼。那你所有上了考场的题目都是——如果人五分钟解决不了，那这个题它一般说就不会出了。

所以你们长久以往你们训练的就是"解决"，就和你们训练的那个 reward、和 agent 训练的 reward 是一样的。**你能不能五分钟解决？agent 能不能五秒钟解决？** 最后是 agent，它有更多的数据，它有更明确的反馈信号，所以它做得比你好。

如果你没有一种很强的去好奇心，想要知道这个世界是怎么运行的，一个产品到底是怎么开发的，你很有可能你没有这种 self-motivation，你就没有去训练自己去解决这种 long-horizon 的问题。**最后就是你解决 long-horizon 的问题还不如 agent。**

这是一个——当然我觉得所谓软件工程挺好的，它有些课，我知道有些软件工程同学在抱怨他们的课程，说我上了文科，然后怎么怎么怎么。当然你回过头来，如果你能把技术映射回这些文科的东西的时候，你会发现其实软件工程这就是一个文科嘛，就是一个管理学，这是一本管理学的书。在它里面确实有很多真实的、有趣的这些东西。

### AI 缺的是品味吗

实际上在大语言模型的时代，软件工程失败的定义没有变，就是从 intent 到 specification 到 implementation 的翻译错了，对吧？要么就是 intent 和 spec 之间不满足，我做了一个东西其实不是我要的；要么就是我做了一个实现，但是不满足我的 specification，比如正确性或者性能。

但是今天模型，因为它有这种 reinforcement learning，它对于这种真正的长程信号的 reward 还是做得不够好的，它更多还是在怎么样机械地完成任务。

所以你会发现，不管是 GPT、Claude 的旗舰模型，还是我们现在用的比如 GLM、DeepSeek，它在面对这个 Excel 问题的时候，**它都不会去想到像我一样先去设计一个 DSL**。对吧，虽然这个模型有足够的智能可以设计一个非常好的中间语言来把这个问题非常干净漂亮可维护地解决，但是 AI 的第一反应就像大家一样，**它已经被训练成做题家了。**

我们现在还没有把 AI 怎么样变成一个好的设计者。大家都说 AI 现在最缺的是品味嘛，这个好的工程品味给训练出来。

但同时我也觉得，既然它能做做题家，它为什么不能有好的品味呢？我觉得可能是有的，所以我还是有危机感的。虽然就是我觉得这门课我现在这么教，可能三个月以后，或者我这门课还没有结束的时候，我讲的所有东西都已经没用了，这都是有可能发生的。因为我其实非常确信，对吧：它既然能解决数学问题，它既然能解决这种编程里面很细碎的逻辑，它为什么不能——因为它都知道这些好的设计，它都见过，它为什么不能从它的记忆库里面找到那个好的设计，然后来解决这个问题呢？**我觉得是可以的。甚至我有一些 skills 就能够朝这个方向来做。**

所以我觉得这是一个都值得我们深思的问题。

### 古法编程已经死了，软件工程暂时还没死

最后一页，首先古法编程已经死了，对吧？Agent 在完成一个单个任务上已经无人能敌了。软件工程暂时还没有死。

但我希望每一个同学经过这一门课的可以说是探讨吧，我也不能说我做对或者怎么样，试图回答一个问题：

> 在保研的时候，你的导师问你——**"为什么我要招你，而不是买一个 200 刀的 Claude Max？"** 怎么接住这个问题？

我觉得在这个问题上 GPT-4o 回答得还挺好的，虽然它做不到。对吧，它说他**能找到能直面解决的问题，把未知拆成便宜的实验，用证据让坏方向及时停下，并对长期结果负责。**

这是个好的回答，但是我发现 GPT-4o 它还做不到，很有意思。

### 本讲提到的题目

**一、quick quiz：如果你要实现这个 QRgen，你会怎么写？怎么 prompt AI？**

- 现场给出的信息：我只用了少量的 prompt，GLM-5.3 在 200k 上下文里面就完成了第一个正确的版本。
- 现场给出的关键做法：让它设计各种各样的 Python 类，像编译器一样；设计一个叫 `XOR` 的符号系统（因为涉及位运算），这个东西既能在 Python 里直接执行，又能翻译成 Excel；再加上 `CONCAT`，就做成一门中间语言，像 AI Infra 里的 Tile-lang 那样，既对 Python 友好，也对 Excel 友好。只验证"每一处翻译都是正确的"，在 Python 世界里验证 Base64 和二维码每一个像素算得对不对，再单独验证每一处和 Excel 公式翻译的正确性与兼容性。
- 反面教材（也是这道题的答案要点）：GPT-5.6 第一秒就被带歪，去追求"对任意的 $s$ 都满足正确性"，这就已经错了。软件工程的第一步是不要扩大，做最简单的东西，不会失败。

**二、怎么阻挡 QRgen 的开发，然后怎么设计 `1.nju.edu.cn` 的 engine？**

- 现场给出的信息：可以告诉大家的是，GPT-4o 给我的答案非常糟糕。这两个设计都是一定会失败的软件工程设计。

**三、导师问你：为什么我要招你，而不是买一个 200 刀的 Claude Max？**

- 现场给出的信息（GPT-4o 的回答）：能找到能直面解决的问题，把未知拆成便宜的实验，用证据让坏方向及时停下，并对长期结果负责。
