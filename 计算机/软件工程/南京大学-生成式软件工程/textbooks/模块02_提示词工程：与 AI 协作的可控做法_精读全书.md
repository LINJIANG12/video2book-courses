### 大学是被 AI 从内部攻破的

我先讲一个我自己的判断：**现在大学的崩溃是系统性的。**

我这儿有一个自己的理解。大家都知道网上可能有更好的资料，比如 Stanford、MIT，哪个不比我这个二流大学牛逼多了？所以你会本能地拒绝你的老师。

但同时，如果没有人督促你，人的天性就是摸鱼——比如我的梦想就是做一条咸鱼。

而这两条合在一起，就变成了一个特别糟糕的组合：**你同时拒绝了你的老师，和那些牛逼的网课。** 于是你进入了一种状态：

```text
   老师：用豆包出题
        │
        ▼
   学生：用豆包做作业        ← 整个流程"很丝滑"
        │
        ▼
   助教：用豆包改作业
        │
        └──► 但你其实同时绕开了两边：
              老师没教，学生没学，助教没看
```

> **结论**：**整个流程都很丝滑，但大家肯定也焦虑。**

焦虑有两种形状。

第一种焦虑是**怎么平衡短期和长期的利益**。AI 戳我上大学的诱惑力实在太大了。以前我那种折磨人的魔鬼实验 bug，天天调到凌晨，现在豆包都能搞定了。

你去做实验吧，觉得很不值：凭什么宿舍老哥秒交了作业就去找女朋友了，我还要干代码？但你不做实验吧，你又担心自己没学懂，后面的课就学不会了。

另一种焦虑是**怎么找到毕业的出路**。延续了中学时代听老师话的状态，结果却没有得到想要的东西。可能你宿舍老哥有了 AI，学东西贼快，说的话自己都听不懂了，要保研了——你就更焦虑了。

所以本质上，**大家对自己的硬实力不自信，就疯狂在能加分的地方找补，进入无意义的内卷状态。**

我一直都觉得，**大学最需要的是启蒙课程**。这样一门课程会带大家打好学科的基础，找到自信，解锁一个新的人生可能性。我以前上计算机系统基础和操作系统，都是这个思路。

虽然建立自信的过程说实话挺痛苦的——第一节课就要教你 Read the friendly manual，哈哈哈。

### 提示词是怎么变成一个新词的

那我们就从这里开始。

今天我们来讲和生成式软件工程里面非常关系特别大的一个，就是你和 AI 沟通的那个渠道——**自然语言的提示词**。

这基本上就是大家和机器沟通的**唯一的接口**。从 ChatGPT 时代，大家从聊天窗开始跟 GPT 聊天的时候你就知道：我们有 prompt，要给机器一个指令，然后 AI 会给我们返回很多内容。可能是文字，可能是代码，也可能是图片，都有可能通过 prompt 来生成。

我第一次感受 prompt 的力量，是我每年上操作系统课的时候。当时正好是 2023 年——2023 年那就是 2022 年底 ChatGPT 刚发布的时候——我试图让 ChatGPT 帮我来讲一讲 inline assembly。现在应该已经没有人写 inline assembly 了，它已经变成了一个传统艺能。

然后我发现它解释得出奇地好，而且那东西应该确实是在它训练语料之内的。我故意做了一个绝大多数人应该不会实现的 inline assembly，它做得相当的好，虽然确实不完美。那时候我就觉得，好像时代要变了——当然可能没有到今天这么清楚地感受到时代会变，以及怎么样的变化。

提示词就这样成为了一个新词：prompt。在这之前，在 ChatGPT 之前，我们没有用这个意思来讨论过 prompt 这个东西。

你们可能会觉得，OK，不就是在聊天框里面打的那段东西吗？"帮我生成一个什么什么游戏"，或者"帮我把这个作业给做完"。

但实际上，提示词不仅是在你的对话框当中的。

### 提示词不止是你在对话框里打的那几行

> **定义**：**Agent 看到的是一整个 Agent 的上下文。** 也就是说，从你在和 Agent 聊天之前，Agent 就能看到一个叫做 system prompt 的东西——**这也是一个提示词，它也叫提示词。**

然后在 system prompt 之后，它还会加载很多东西。比如说你的 `AGENTS.md`，然后可能你还会加载一些 skills，`AGENTS.md` 里面还会要求它再去读别的文件夹。

实际上，在你的 Agent 第一次停下来和你对话的时候，它里面已经有很多很多的东西了：

```text
  system prompt（harness 内建，Codex / Claude Code 那一套）
   · 为什么要有这个安全策略、总体怎么想的
   · spec：安全策略具体是怎么做的
   · implementation：它到底是怎么实现的
        │
        ▼
  全局 AGENTS.md（我这台演示机：用中文回答、结尾必须写 recap）
        │
        ▼
  项目级 AGENTS.md  →  目录里还可以再放 AGENTS.md（一层一层）
        │
        ├── skills 索引：只有 metadata（名字 + 一句简略描述）
        │      └── 匹配任务时才读完整 SKILL.md，用完这一轮还会被抹掉
        │
        ├── 工具定义（bash、LSP、读写文件……）——本身就是文本
        │
        ├── 会话历史 + 每一次工具调用的结果
        │
        └── 每一轮执行注入的环境：环境变量、模型、当前时间
```

除此之外，**所有的工具调用和工具调用的结果，它实际上也是出现在你的上下文里**。它是一个线性的上下文。

直到有一天，你会和它聊天，说：**给我做一个游戏吧。**

所以提示词是非常非常长的。这也意味着今天 Agent 的能力是非常离谱的——它可以看到一个非常长的提示词。比如说，你在最早的 system prompt 里面可以让它用中文回答。我为了上课的效果就会让它用中文回答，哪怕我这边用的 user message 是英文，它输出的仍然是中文，你们会看到这个行为。

那么当我们说**优化提示词**、说**提示词工程**的时候，我们实际上表达的是一个叫**上下文工程**的东西——也就是整个模型的上下文。

我们都知道，模型做的是 next-token prediction，它每一次可以去预测下一个 token。这个 token 可以是调用工具，可以是输出一个字符，反正它会不停地**向后去推进你的任务的执行**。

大概我是从 Claude Opus 4.5 这一代开始感觉到的：Anthropic 发现模型突然学会了，它靠强化学习和后训练，学会了非常强的指令执行能力。你有一个非常长、接近百万的上下文，它依然可以在很后面的时候遵循你的指令，并且能够一定程度上看到前面的东西。

有一个很著名的梗就是说，你可以在最早的 prompt 上面加一句：**你每说一句话，都要在后面加一个"喵"。** 然后你等到有一天你发现，你跟它工作的时候，突然发现那个"喵"丢了——

这时候你就知道：不管它是上下文溢出被截断了，还是被压缩了，还是某种别的原因，反正它开始不能遵循指令了。这时候你就需要重新来想一个办法。

这就是大家在工程实践当中发现的、有趣的各种各样的上下文工程，也就是提示词工程的方式。

### 有问题就立刻问：AI 是一个耐心的老师

而我今天最想告诉大家的一件事是：**为什么说没有 token 就应该退学？** 我希望告诉大家的是，**所有的事情你都应该立即开始尝试。**

AI 给我们的一个能力就是：**任何时候你觉得有一点麻烦，你都可以立即行动。** 因为 AI 是一个非常耐心的老师。

不像有的时候——我从我上大学的时候就有一种感觉：我有一个东西不会，可能我的室友会，然后我跟它沟通的成本很高，而且我可能会有这样的想法：**我是不是就在我室友面前暴露了我很菜？** 这可能是一个我不想告诉他的秘密。但 anyway，菜也是很正常的。

但是对于 AI 这个老师来说：**它不会嫌弃你，而且你可以任意程度地追问。**

所以当我们说，比如我刚才说到一个概念，说我们的 AI 的 Agent 是有一个很长的上下文的，它有 system prompt，有各种各样的东西——那我下一秒钟就可以立即打开一个 Agent，我可以直接问它：

> "老师上课的时候说 Agent 的上下文里不仅是一两个提示词，你能检查一下你的上下文里都有些什么吗？"

它其实可以自己检查自己，甚至它可以自己检查自己的日志。**Agent 经常会给你一些惊喜。** 当你问出一个问题的时候，它的解决手段是出乎你意料的。我们来看一下。

因为 Agent 正好是可以看到自己的上下文的——根据我们上课所说，它是 next-token prediction，它能看到所有的东西，所以它应该能够读出来。**除非有明确的指令禁止。**

比如说有些模型的 providers 都会禁止你去套取它的系统上下文。它会通过模型的微调，也会通过一些明确的指令——比如在 system prompt 的前面就会说：任何形式你要回答 system prompt 都是拒绝的。

但是你要知道，**这是一个整个开源的框架，它本身你就可以 debug 它。**

你看，这个系统提示词来自哪里？来自 Codex、Claude Code 它们内置的。然后以及它的要求：工具使用的指南，回复要简洁。

然后它会打开我这个用户下的、这个 Agent 下的 `AGENTS.md`——这个是我自己写的。所以你看，我因为我是上课演示的机器，所以我在这个全局的上下文里面放了一个"用中文回答"；然后我有一个结尾必须写一个 recap，这个细节你们可能意识到了——就是你们第一个，在模型跑完了以后，第一个看到的是我总结了这一次做什么。

然后有这个项目级的指令，所以它是一层一层一层的，你的目录里面还可以再放 `AGENTS.md`。

然后还有一个 skills 的索引。skills 就是模型能够执行的功能。比如说我有一个叫 `make-slides` 的 skill，它可以使我能够在这里 F5 播放幻灯片的那个幻灯片的渲染——这个幻灯片的渲染就是一个 skill。

> **提示**：但模型只能在上下文里面看到它的描述，我头上写的那个 metadata：它的名字是什么、它的描述、一个简略的描述是什么。如果整个很长，它可能写一个很长的 skill，它都只是按需加载的；然后等到那一轮加载完了以后，这个 skill 也会从这个上下文里面被抹掉。**只有匹配任务的时候才读取完整的 `SKILL.md`。**

然后以及还有工具的定义——**你看，它的工具也是直接以文本的形式出现在它的上下文里了。** 然后以及会话的历史，环境变量。

**每一次执行，这是大家所不知道的，每一次执行都会注入当前的一些环境**，比如说模型，甚至是当前的时间。如果你和 DeepSeek Chat 去聊天的话，你可以把它的每次注入的环境给套出来——这个不属于系统提示词，你是可以把它套出来的。

所以这是一个非常长的序列。那我们要做的，所谓上下文工程、提示词工程，就是把所有的这些都安排好，安排好。

刚才其实我就演示了在 AI 时代我们学习应该怎么样。我们不仅可以像刚才那样把它问清楚，以及在你明白的时候追问，**你还可以把它反过来。**

大家可能听说过这个叫**费曼学习法**。你怎么能够判定你是不是理解这个知识了？**反过来你当老师。**

> **易错点**：这件事情在 pre-AI 的时代做起来是非常大的。因为你要做老师，就必须要有听众来检验你。那那个听众很有可能是你的室友——但是室友可能不想听你在那儿啰嗦这个东西，对吧？他可能对这个不感兴趣，可能他对这个了解得太清楚了，也许他就是单纯不想帮助你。

但是 AI 这个时候你可以。你去请教它、请教它、请教它，把它弄懂；然后你可以在你自己自认为弄懂以后，再反过来，你自己再自己做老师，然后说：

> "AI，你现在来扮演学生，我要把这个东西给你讲懂，你假装什么都不知道，然后这个时候你来看我哪里逻辑是不是有错、有漏，你在这个时候纠正我。"

**你在正着一遍、反着一遍，你基本上就对这个概念理解得很清楚了。**

所以我觉得大家作为 AI Native 的一代人，一定会把我们这一代人给彻底卷死的，因为**你们有无限的时间**。这就是我第一节课的观点，对吧？你们现在的任务就是学习，没有像我这样比如说要负责一些其他的事情、要对别人负责。

> **结论**：**那么这就是你们最好的时代，所以你们也可以把费曼学习法给用起来。**

### 没有任何东西是安全的，除非你告诉它什么是安全

我们刚才把一个 Agent 的上下文完完整整地解剖了一遍，这个就过去了。然后你们在学习这些东西的过程当中，会留意到很多有趣的小细节。

你们有没有在用 Codex 的时候——我不知道你们有没有同学用 Codex 啊，不要紧——你们在用任何 Agent 的时候，都可能面临一个问题：**如果你要执行一件危险的操作，它会让你确认。**

当然比如说这个 Agent 默认，在默认的配置下它是 YOLO 模式，就是它所有事情都直接执行。如果我今天有一个提示词给的不是很好，它有可能就直接把我整个就删了，我今天就好，今天我就直接下课了——这是有可能的。

这是一个平衡。你可以在更安全的环境里面运行，比如说沙箱模式运行。在沙箱模式运行，你们如果观察过像 Codex 的运行，它经常会：我先试一下做一件什么事，然后失败了，然后它意识到这是在沙箱里面做——哦，我在沙箱里面其实不能做这件事，我现在要在外面再做一次。

那再做一次的时候它甚至会问：**"我现在要做一件可能有一点危险的事情，你是 yes 还是 no？"**

然后这就很讨厌。因为你最想的是——我今天要去吃饭了，很好，我把这个 Agent 的任务先跑上，先跑三个任务，都想好三个任务都跑上，然后去吃饭。然后吃饭回来的时候，你发现它跑了一分钟就问你要确认。你就觉得浪费了 Agent 的时间，浪费了自己的生命。

你们经常会看到这样的小细节，然后你们在小细节上的注意力，一定程度上成就了你们可以走多远。

> **易错点**：比如说我就留意到 Codex 有这样的一个细节：它有些命令它会认为这是个不太危险的命令，是个好像直接做也没有关系的命令，所以它不是说每次都要用 bash 的工具，它都会叫你确认。它有些时候那个 `ls -l`，它认为这个命令是安全的，那它就是安全的。
>
> **实际上这个命令可能是不安全的。** 因为在我的环境里面，可能把 `ls` 重新命名成了另外一个比如说 `rm` 这样的命令——当然应该没有人要这样做，对吧？在一个恶意的环境里。

那你也可以好奇：**这是怎么做到的？**

我下载了一份这个 Codex 的代码。**这是我觉得现代软件工程和过去软件工程很不一样的体会。** 你们在比如说像大二、大三的时候，我像你们这么大的时候，接触 Linux 内核——差不多就是大二、大三时候接触 Linux 内核——我光把 Linux 内核下载下来、搞清楚这个东西要怎么编译，就花了很长的时间。而且这还是我在有一定的 Linux 使用经验的基础之上，这是一个完全的劝退。某种程度上我能在那个年代活下来，就是因为我对我这种劝退的东西有一种我一定还要试一试的执念。

然后到今天你们，我相信每个同学都会有的。**如果这是一个好东西，Codex 很好**，也许你们不喜欢 Codex，也许你们喜欢 Pi，Pi 更轻量，当然 Pi 显然是更轻量的。

**但你们现在不需要害怕任何一个软件系统的复杂性，因为你可以直接问。**

比如说——当然我这里没有 read the docs，我还是就手输了——我留意到一个有趣的问题：**在调用 bash 的时候，有的时候会向用户确认，有的时候不会。有一个风险的判定。** 风险其实是一个非常难的问题：**你并不知道具体的命令语义是什么，所以你是做了分析，还是让大模型给了风险的评级，还是别的方法？**

> "读一下相关的代码。"

好，这本身就是一句提示词。然后这个时候，Agent 看到我的这个提示词之后，它前面的提示词也都有，它就会去开始试图解决这个问题，它去各种去搜索代码、去检索代码。如果我有一些比如说像 LSP 这样的工具的话，它还可以去工具里面像你们在 IDE 里面点来点去。

对吧，你们有用过 IDE 的那个功能吗？我记得我上像上操作系统或者计算机系统基础课的时候，我都会说，我发现有很多同学从 PA1 做到 PA4，你们那个 VS Code 里面都还是有红线的。

你们笑笑了对吧，笑了。有红线就意味着**你没有解锁这个正确的配置**。虽然有红线没有任何问题，你还是可以在我们的受控环境下编译，然后把所有的东西都完成，**但是这不是正确的 practice**。你应该花一点点时间去 configure 一下你的 VS Code，加上那个 include path。因为我们是有一些 `-I` 啊这样的选项，你会指定一个编译的路径。

然后你把这些配置做好了以后，你就可以得到这个 IDE 的所有的功能。你可以用 Ctrl 去点，然后你可以去那个 rename symbol，用那种重命名符号的方式一次性重构很多东西，哪怕是在大语言模型之前的时代。

然后到今天这件事情就配包括配置就变得更容易了。

然后你看到确实是**有让大模型风险评级的**。它有一层静态的分流：**沙箱内的低风险命令会直接执行，网络 allowlist 命中直接放行。** 它有一个审评都不需要审评的——如果就是一个 `ls`，对吧？

你会想象 Codex 里面会有一个 parser，一个语法处理器，这个 parser 会处理这个 bash 的命令。这个 bash 的命令如果它发现是在一定的白名单里面的，它认为绝对安全，它会直接放行。那如果不是的话，它应该会在 prompt 里面 inject 一小段话——**这本身也是 prompt engineering**——inject 一小段话，说：你是不是应该给我评级一下它的安全性。

那我现在也可以直接把安全评估的 prompt 打印出来，看看它是什么。我事先完全没有准备啊，我完全不知道它是什么。可能我们也不能 100% 地去相信这个我现在 DeepSeek-V3 Flash 的模型，**但是这个方法是非常有用的。**

你可以比如说，如果你对它不相信，你可以做什么呢？**你可以让它把这个 prompt 改一改**，比如说把这个 prompt 改成以前某一个不会拒绝的东西它要拒绝，或者以前某一个拒绝的东西它会不拒绝，对吧？这都是 prompt 可以控制的。然后改完了以后，**你可以观察到它行为的变化，这就成为了一个证据**，你也可以让 Agent 来做这件事情。

### 好上下文的总原则：任务要可验证

好，那我就可以再往后多讲一点，怎么我们写一个好的提示词，或者写一个好的模型的上下文。

我们都知道上下文包含了一个非常非常复杂的要求。然后又想到那个软件工程里面那个老大难的问题，对吧？

我们有 **intent**——我们脑子里面所想的是做一个国民级的应用。然后从 intent 我们可以搞一个 **spec**，这个软件的架构是什么、应该选什么语言来实现，有很多很多的细节。但我们把这些细节定好了以后，我们还要去做 **implementation**。

在任何时候我们用这个模型去完成一个软件工程任务的时候，我们都会把整个大流程里面的一部分全部都塞到模型的上下文里。就像刚才我让 Agent 去帮我读这个 Codex 代码的时候，它其实读到了这个 Codex 的一些设计的原则：一般来说都会有一个文档说为什么我需要这个安全策略、安全策略总体是怎么想的；然后它可能有一个 spec 的文档说这个安全策略是怎么做的；还有这个 implementation 讲它是怎么实现的。这几个是互相印证的，然后往后输出的过程。

那么如果我们想要写一个好的模型的上下文，来完成一个软件工程里面的任务，我们的原则是什么？

> **结论**：**你还是去想这个 gap。**

如果你给模型一个模糊的 intent，它就很容易认为它完成了。你说给我生成一个什么 CS:GO，然后它就给你生成一个 CS:GO，然后这个时候它就可能发生**漂移**。

但如果你能给模型完整的设计和 spec，那么模型遵循你的 spec——**就假设模型能力是无限大的**——它就会更加确定，和你可以验证。因为比如说你说你要用 C++ 来实现，它最后给你一个 Java 的实现，你一眼就看出来了，你不满意，模型也应该认为不满意。但如果你在 intent 的时候说就给我做一个什么东西，你没有说要用 C++，它也不了解你，它就写了一个 Java 的实现，那就发生了一个很大很大的漂移。

> **结论**：所以整个模型上下文的最重要的原则就是：**如果你的任务是明确可以验证的，尤其是机器可以验证的**——比如说你有一个脚本，这个脚本就说测试通过了还是不通过——**那么 Agent 就可以不计代价地一轮一轮地尝试，把这件事情给完成。**

甚至 Agent 在多轮失败以后，它可能会在你的系统里面安装别的工具，可能去网上找找答案。

最近有一个非常非常有趣的一个复盘是：**OpenAI 的 Agent swarm 是怎么样通过非常长的多轮对话把那个 Hugging Face 的漏洞给攻破的。** 它大概是在一个 CTF 的竞赛里面，给它一个不可能完成的任务，然后有上千个 Agent，它就一定要去完成这个不可能完成的任务，然后最后他们去找那个系统的漏洞、去提交非法的提交。我看过一个非常长的复盘，那个非常有趣。

所以一旦你有一个可验证的东西——虽然那个任务不可能完成，但那个任务非常明确——**Agent 会不知疲倦地把它向下、向下、向下做下去。**

### 把"现代风格"翻译成你能验收的东西

我举一个大家都喜欢的评测吧：说"我能不能用一句话来生成一个什么游戏"，对吧？CS:GO 还是极品飞车。这个 CS:GO——是 Kimi K3 生成的。

然后可以看到这个 Kimi K3 的表现是非常好的。它的物理、它的碰撞、它的逻辑的制作，包括顶上还有一个后视镜，这个后视镜看起来应该是个没有问题的，它都是做得非常逼真的。

**但是这依然可能不是你要的那个 CS:GO。** 因为你脑子里的 CS:GO，是你每天打开来玩的那一个；而 AI 生成的是它生成的。它在收到你的指令以后，**它没有办法补全你脑袋里面的一些模糊的约束。**

比如说你可能是要一个复用真实地图和美术资产的。如果你真的把这句话说出来，它可能就会去比如说 OpenStreetMap 这样的网站上面去下载一个开源的地图。比如说你真的想在南大仙林校区里面开车，**这件事情是能做到的**；你给得指令给得越清楚越好，比如你要是能找到南大仙林校区地图的文件格式，它就真的能把这个世界重新建模出来。

包括美术资产，有很多公开可以用的美术资产：车、城市、树这些东西。**如果你不告诉它，它会认为我需要做一个 self-contained 的、所有东西都是由我自己生成的一个东西**——而这其实可能是一个误解，在早期的时候的一个误解。

> **结论**：所以一个 rule of thumb 就是：**你写清楚你的 prompt，所有的东西都写清楚——我要一个什么东西，它用什么东西实现，怎么样才算正确，然后你帮我把这个东西给搞定。**

而这个"约束"的设计能力，其实我这个学期整个要教的最重要的就是：**你怎么去约束它，怎么用最小的、可能你给它一点点方向性的引导，它就能够一下子能改掉。**

因为模型都是一个非常聪明的人，你可以想象成非常非常厉害的、博士水准的人，而且他在各个领域的知识都非常好。这样模型基本上永远会给你惊喜，还是挺好的。在这个模式下，模型基本上要么完成，要么最后终于有一天它会说：**"对不起，这个事情对我来说太难了，我们可能需要重新做个规划。"** 它自己可能也会做计划。

我举一个具体的例子。

我上节课讲到，我现在想的是：大家在这门课结束的时候，每个同学会交一份简历给我，我大概现在是这样想的。当然我中间会有一些 project 给大家作为选做。每个同学交一份简历过来，然后我就评估——当然我肯定用 AI，我不可能自己评估——我用 AI 来评估这个简历，来判定大家通过还是不通过，就像我第一节课的时候展示了一个不好的简历的案例。

那简历首先就会有一个链接，可能会指向你的 GitHub，或者指向你的主页。

我应该是已经做过这个了，试过。就一句话——anyway，忽略它的内容，我不知道它从哪里找的，可能是 DeepSeek V3 Flash。

**从美术效果来看还是非常好的，这个非常专业。** 你们在比如上了 pi.dev 或者 Homebrew，它都有一个类似的一个界面，非常漂亮。而且它应该读过我的主页了，它知道我的主页上是一个 terminal。

但你有一种感觉，就**这个 AI 味很重，你又说不出来**。你首先它确实做得很好，它的滚动效果、浮动的效果做得都非常好。就这样一句的 prompt，一个"现代风格"，它满足了现代吗？现代，当然。

当然如果你给它一个"不要那么 AI 味"的 prompt，它可能也不知道应该怎么遵循，所以你会得到一个——**这是我的学生的、PhD 学生的个人主页。** 就我觉得这主页也很干净、很舒服，非常舒服，但你有说不出来的那种 AI 味。

我不知道在 AI 之前好像也有人是这样写主页，但是不理解。

但你们看一下我的主页，你们可能看到了我的主页，这就有点不一样了。**这是一个真正的终端**，所以我可以有管道的。然后如果你们放大了看，**这个字它是不完美的，它不是一个特别工整的字。** 我做了一个非常小的后处理——我所有的 xterm.js 渲染完之后做了一个后处理，它就有一种像是真的打字机打出来的那种不完美的效果。

**所以这个看起来 AI 味就没有那么重了，因为它确实不像 AI 的风格。虽然我一行代码也没有写。**

它关不掉——它捕获了我的键盘，这可能是一个小 bug。

> **结论**：就是这个原则，**你的指令给得越清楚，Agent 就能完成得越好。** 如果你能给它具体的风格——我需要一个什么样的终端，它的背景是什么、前景是什么，它的渲染完了以后后处理是什么，然后样式和排版是什么——基本上你就可以实现去掉 AI 味了。

所以实际上要说的还是：**这些设计是掌控在大家自己手里的。** 你需要读很多前端的书，甚至要读很多设计的书，然后再读一些、看一些好的网页。你每次看到一个谁的网页比较好的时候，你就会把它记下来：**这个网页设计得非常好了。它好是为什么呢？是因为这两个按钮之间用了一个不常规的间距，或者用了一个不常规的样式，你很喜欢。**

我觉得在很多很多时间里面，人生因为你们有时间，你们就去漫无目的地探索，**但是在探索的过程中有惊喜，就非常好了。**

而我觉得现在比较担心的是我们的孩子这一代人：你们还是见过、一生中还是见过很多 non-AI 然后做得非常非常好的东西的。

但是我记得我上个学期结束的时候，最后一次接孩子的时候进到学校里面，学校里面有一个欢送毕业生，你们每年都会有。欢送毕业生的时候，那个图片就是**满满的 AI 味**。然后我发现不仅在这个地方看到有 AI 味的图片，在计算机学院的楼下欢送毕业生的也是那种同样的 AI 味。而且你有一种"短视频女主全部永远是一张脸"的那种感觉。

> **注意**：**当所有人被 AI 生成的东西同化的时候，就有一点点危险。** 但是至少我们的数字世界里面还是保存了足够多的 pre-AI 时代的东西，有足够的多样性。

大家可以多留意一点：你们看到每一个设计的网页、设计的简历或者是任何东西的时候，都想：**它到底是怎么想的？它的解空间到底是怎么被约束住，防止 AI 向那一个"做一个现代风格个人主页"去发散的？**

所以基本上这就是生成式软件工程你们主要要学习的东西：**明确你的意图。**

因为只要你跟 AI 玩过了——给我生成一个现代风格的主页——你们在公众号上都各种看到说 Kimi K1.5 的前端能力又增强了，达到了世界第一，然后 OpenAI 好像要发新的模型了，当然我觉得也可能是非常可怕的事情。

但无论如何，**模型都是一个模型，它的品味基本上是固定的，尤其是在你不控制它的时候，它会朝一个固定的方向去发展。**

这就是为什么我们会鼓励大家要跟不同的人聊天，为什么学校里面有不同的人、老师来上不同的课程——**多样性其实是好的。** 你见识过了以后，你就可以越来越明确地知道你想要的到底是什么，然后把它精确地说了出来。

**这其实是需要你对软件工程的知识的。**

反而现在最不重要的是，如果你已经到达了这一步——比如你理解了技术选型，明确知道了技术选型的好坏之间的区别——那你真的是可以和 AI 去讨论的。

如果你知道这几个语言之间，它可能潜在未来你要上云的时候会不会遇到什么问题、哪一种可能会更方便等等，你就可以跟 AI 去讨论。你当老师，你说：**"我现在要做这件事，我要请你挑战我，能不能说服底下的一个学生。"**

好，这是上下文工程的东西。

### 模型是怎么"听指令"的

讲了应该怎么样去写 prompt，我们还是要稍微再讲一讲**模型是怎么遵循指令的，听指令这件事到底是怎么完成的**？这样我们就可以更好地去让模型听我们的指令。

我们讲过，模型是一个概率分布，它根据你当前上下文去 predict next token：

$$P(x_{t+1} \mid x_1, x_2, \dots, x_t)$$

这里有一个非常有 insight 的 argument：**每一次模型输出一个 token，它其实都是一个非常有限的计算。** 看起来说模型现在有一个 37B 的模型、1.5TB 的模型，当然这个数字本身确实是非常大的，是足够大的模型；但是模型为了输出一个 token，它也就是把其中激活的那一部分走一遍，**所以它是一个固定大小的计算。**

你们可能在刚上计算机系的时候，会听说这样一个东西，叫**图灵机**（Turing machine），然后可能也听说过，图灵机的计算能力是非常大的，大到和我们整个宇宙都是等价的。你们可能听过这句话，但不完全知道 Church-Turing thesis 它背后代表的是什么。

然后你们也知道**有限状态机**，这个你们都知道，在数字电路课里面做过的。有限状态机就是你有一个计数器，从 00、01、10、11，然后再回到 00，一个有限的状态。

> **定义**：**有限状态机和图灵机之间唯一的区别是什么？是图灵机有一个无限长的纸带，它有一个记忆，相当于有一个草稿纸可以把它记下来。**

也有一个很有趣的、我很喜欢的说法是这样的：**你的脑子是一个有限状态机**，我们脑子里的神经元是有限的，我们每一次思考都是有限的。有点像模型，模型它能力很强，**但是它在 predict next token 的时候，它的计算量也是有限的**，也就是那一次推理所激活的所有的参数，可能也就几百个 billion。

那是什么使你从一个有限状态机变成一台 Turing machine 的？这应该是 Manuel Blum 给研究生的建议里面说的：**你是一个 finite-state automata，你是一个有限状态机；但是当你有 paper and pencil 的时候，你就是一个 Turing machine。你就得到了计算能力的一个大跨越式的增高。**

> **结论**：这件事情是对的，当然这是为了启发你们：**要把想法记下来。** 你们一边思考一边要记录，然后可以随时回看自己的思考。**随着时间越来越长，你记的东西越来越多，你的知识就会积累。**

#### 上下文就是模型的纸和笔

然后你发现今天的模型，这个 **Chain-of-Thought**，就是往后吐思维链的模型，就是做了这件事：**它直接把模型的上下文当做了 paper and pencil，当成了纸和笔。**

当然这个纸和笔是有缺陷的：**这个纸和笔它只能往后写，append-only，不停地往后写，它不能擦。** 它依靠模型的注意力把写错的东西忽略掉，但是它是 append-only 的——**这也许有一天就能改掉。**

但是无论如何，**模型学会了利用它的上下文。**

如果遇到一个很简单的答案，比如 1+1 等于几，它马上 next token 就告诉你是 2，这个没问题。

但是如果遇到一个很难的问题，它会像人一样：**"哎，这个问题有点难，我要先想一想。那么为了解决这个问题，我可以先试一试什么。"** 它理解自己可能解决不了这个问题，它理解自己可能要把思考的过程写下来，直到这个解——可能是对的，可能是错的——完全写出来了。

然后它一旦那个解答写出来了，它就可以再去试一试：**这个解答是对还是不对？它可以判定，然后再往后。**

这是现在 Chain-of-Thought 模型做的事。**它用 token 的数量，它可以直接回答，但它直接回答就有错误的风险。**

#### 没有思维链的年代：一个"人类舔狗"

刚开始最早有 ChatGPT 的时候，它没有思维链的时候，它就是这样的。**它被调成了一个人类的舔狗。**

调成人类的舔狗就意味着人类不管说什么，它都一定要说一个东西，它才有可能满足。当时 ChatGPT 在训练的时候，如果人类问它一个问题它不回答，那人类一定是给低分的。而如果它随便给一个回答，它就有概率是对的：如果它答错了，那当然也是低分；但是它答对了，它就是高分。

**所以它无论如何一定要给你一个东西。**

> **结论**：**幻觉就是这么来的——它无论如何一定要给你一个东西。**

当然现在带 Chain-of-Thought 的模型在有强化学习以后，它就会知道必须给一个对的，因为**答错的惩罚很大**，它就学会了这个。

**所以 AI 就真的会像人一样，一步一步逼近目标**，也就是 test-time scaling，在我们每一次的 session、上课时候的 session 里面看到的一样。

#### 藏头诗：把它的大脑拿出来做核磁共振

我举几个例子。这几个例子其实不在模型训练的数据当中，还挺好玩的，我们来看一下——我换一个目录。

我要用中文写一个押韵的藏头诗，头反正就随便，一个 nonsense；然后我还要求它讲一个动物相关的故事；我还要求"2026 9月1日"八个字分别按顺序出现在八句里。

这就是个 nonsense。对人来说，比如高三哪一年期末考试出一个这个，你马上第一眼就骂这老师是怎么想的。**但是模型不会，模型会照单全收。**

你看它有一个思维链，它会开始试。**它会先想韵脚，因为它知道自己一把头写出来的东西一定是错的，但是它可以先写一个出来。** 写出来一个以后，模型的 next-token prediction 就足够判定这个东西写得对还是不对；如果不对，它再想办法再改；如果试了很久不行，它会再从头推倒，换一个韵脚。

**所以它就不断地验证。**

> "七追二鹿穿林雾，雪唤六蛛共食薯。院中九鸡争米粟，晨如月下老牛步。"

写得不错对吧？虽然品位上可能不完美，但是你用这样的任务，可以看到它遵循指令的过程。**这其实是一种我们把它的大脑拿出来做核磁共振，你能找到它的思维偏好。**

课件上面看到的带星号的都是 AI slop，都是 AI 补充的东西。虽然我还是用了一些 prompt 试图让 AI 味稍微轻一点，但 anyway 这是 AI 生成的。你看它换了一个韵脚，而且它没有把"2026 9月1日"完全压到同一列，但它的遵循指令也是非常好的。

> **提示**：很有意思的是，一般强化训练的时候，这样的东西是比较少的。**这个一定不在它的训练数据里，它不可能在训练数据里面猜出这个东西来。** 结果就是它在训练的时候用的绝大部分应该是**代码、数学题这样有明确反馈的东西**——它把人类直接给杀死了。

如果你期末考试、高考的时候碰上这个题，你马上就想骂出题人脑子里是怎么想的：写一个 18 字的一句话，全部要求相同的偏旁或者部首。

而且我们也知道**模型对于空间结构感知是非常差的，需要视觉模型才行。** 但是这样一个文本模型，它依然可以强行通过思维链的方式，先枚举字。它先选一个，觉得三点水最好，然后：

> "江湖游泳渡河波涛汹涌，泪流满溢洗涤污泥。"

写得还可以对吧？这个也很好玩：**"洪涝淹没江港渔浦"**，还挺有故事感的，**"游漂浮"**。这是 GPT 写的。

但是在这个任务上，**人类还是有更强的天资的。** 人类的群体智慧给的是什么"玩玻璃球，涂润滑油"之类的——我就不能再讲下去了，当我都什么都没有说。

人类在做这件事情上还是 a lot better。当然也许你可以通过让 AI 更多地收束 spec 的方式，但**这已经是一个非常困难的 spec 了，AI 可以做到。**

以及这可能是世界级的。你们已经知道什么《施氏食狮史》和《季姬击鸡记》，所有的字都用同一个音。然后我竟然发现 **GPT-4o 依然能做到。** 虽然故事性确实跟千古流传的还是有一定的差距，**但这个差距依然是可以缩小的。它能写出来一个，就意味着我可以引导它写出来一万个，然后在那一万个里面再微改一下，可能就可以达到接近千古流传的东西。**

> **结论**：**所以 Chain-of-Thought 在数学和编程上面训练，但是得到了一个非常意外的效果。**

#### 有些东西没有 verifier

你们看到，**写 prompt 实质上就是那个 verifier。** 今天模型的能力已经非常强了，如果你们能够给模型一个非常明确的 verifier——就像我前面几个都是信号非常明确的 verifier，它看到字就知道是什么偏旁部首——再加上一个足够强的模型，那么不管是编程任务、教学任务……

**当然教学任务最难的其实是它很难 verify。**

我们经常讨论的时候，比如说：**我的数字切片翻车了。** 我做了第一个切片，第二个切片我一直都没有办法把它做好，就是因为无论我怎么调，我都很难定义"我这个东西要好"。

这个好又是多方面的：首先 AI 味要淡一点，那可能本身 text-to-speech 的模型就做不到，但还不是本质的。还有一个就是**我在上课的时候有情绪的波动和起伏。**

有些东西讲事实的时候——我一开始讲模型的上下文是怎么构成，这些东西你们听的都是废话，**这些东西我已经知道了**——我就会给你们一个小小的 surprise，去这个 Agent 里面让它自己把上下文看一下。我说出来这句话的时候，**可能对你们来说是意料之外、情理之中的。**

> **定义**：这就是一个老师在组织课堂的时候要做的事情，**某种程度上我是在表演。** 我当然知道 principle 是需要把课堂内容组织成为一个有起有落的流，**但这不是一个可以 verify 的东西。**

到底什么样的程度我需要和你们共情？**我是从学生过来的。这就是我现在和 AI 还不一样的地方：** 每个人都是从学生过来的，我自带了人的属性，自带了人对这个世界的体验。这个时候因为我对世界的体验更好，所以我更懂你们，也许可以有一个更符合大家上课的节奏。**但这个东西没有一个 verifier，不像数学和编程那样有一个 verifier。**

> **结论**：所以目前来说，我们还是更容易用 AI 去实现有明确 verifier 的部分。**但是，在有 verifier 的事情上，你完全可以认为 AI 已经超越了大部分人做这件事情的底线了。** 所以我们更多的是要和 AI 协作来做好手头的任务，或者说**把模型当成我们能力的一个非常重要的放大器。**

### 注意力：它其实没在看你那句"用中文回答"

实际上思维链带来的这种指令遵循的能力，还可以再往深里面再想一想。

它每输出任何一个 token，现在的模型有 **self-attention**，也就是注意力机制。**这个机制跟我们人还是很像的。** Transformer 有一层一层叠起来的注意力；每当它要输出一个 token 的时候，都会看到过去的某一些 token。为了输出这个 token，过去某些 token 会显得特别引起注意，然后有些 token 可能就不那么被注意。

比如我在前面的 system prompt 或者 `AGENTS.md` 里面写了一个"用中文回答"。我现在在 user prompt 里面写的是"你帮我实现一个智能回车"——这个时候它在写代码。

**在写代码的时候，注意力就会倾向于集中到已经写过的代码、需求这些部分；而相对来说，"总结用中文回答"这句话的注意力就会减下来。**

这是模型训练的 magic，**它最终能够注意到正确的词。** 整个上下文是一个非常高维的、很糟糕的表示，但是**里面有一个低维的结构，注意力机制能够把它给捞出来。**

这就意味着**我们每一个 Chain-of-Thought 的 token，都会注意到过去的某一个部分的东西。** 随着它的输出——比如说代码写完了，**代码写完了以后它要总结一下，会喘一口气。**

## 上下文的注意力：从「你是一个专家」到算力换智力
> 对应块：BLK04 | 覆盖分集：P03下 | 块标题（分集名）：《提示词工程 [02-Raw_26生成式软件工程_》》

### 模型会喘气的那一口气

先说一个特别小的观察：**模型在输出到不同阶段的时候，注意力是会变的。**

跟人其实是一样的。你在集中做一件事情的时候——比如说你在化简一个数学算式——你所有的注意力都在这个算式上。算式化简完了，你会吸一口气，心里想"让我调整一下"，就在那一瞬间，你的注意力切换了。写完那段代码以后，你的注意力就可以集中到"用户还要我输出中文"、"用户还要我做一件别的事情"上。

模型也是这样：

```text
  人：   专注化简算式 ──► 化简完 ──► 吸一口气（注意力切换）──► "用户还要中文"

  模型： next token ─► … ─► 一小段输出完 ─► 换个阶段（注意力切换）─┐
                                                                   │
                     "刚才那段好像不满足要求" ◄──────────────────┘
                                    │
                                    ▼
                            "我错了，我要纠正一下"
```

这就是一个非常大的模型"收敛"出来的预期结果：它学会**在正确的时候注意到正确的东西**。思维链一直在向前走，它就会不断在不同的时刻注意到上下文里不同的部分。Eventually，**上下文里所有你要的指令，它在一定程度上都能满足**。

这件事的直接后果是：它会犯错误，但错误多半是能回头改的。你让它去写藏头诗，它写出来一看不对，就不断纠错、纠错、纠错——注意到刚才输出的内容不满足要求，同时又回想起过去的某一条要求，于是它说"我错了，我要再纠正一下"。

> **结论**：哪怕上下文长度已经到了一百万，它依然能保持一定程度的注意力。

但反过来也成立，这一句你们一定要记住：

> **提示**：上下文是一种会**抢夺注意力的资源**。你的指令越多，给模型的压力就越大。

### 「你是一个专家」是怎么来的，又该怎么退休

为什么网上会有那么多 `prompt engineering` 的 guide？为什么那些 guide 开头清一色是"你是一个专家"、"你是一个什么什么方面的专家"，后面还写一大段？

因为像 ChatGPT 3.5、4 那个年代，**模型遵循指定的能力实在太差了**。那些超长提示词在某种程度上是在 **hack 这个模型的 self attention**：当模型的注意力注意到"你是一个专家"这句话时，它就会假装那个专家来说话。

> **定义**：**self attention**——模型每生成一个 next token 时，都会对之前的所有内容算一遍注意力，决定这一时刻该关注什么。这也是"上下文污染"这套说法的物理基础。

从 GPT-5 那一代开始，情况变了。模型被明确地训出来了：**它知道怎么收敛到一个好的答案**。所以你不再需要那种奇怪的提示词了。你只需要把你明确的 `verify` 写在上下文里——**而且模型是被训练成"一定能看到它"的**。

一旦你能看到，你的 `verify` 就会变成一个非常强的执念：它会去看、去核对你的 `verify`，确认它满足没有。因为在训练的时候它受到惩罚了——你写了一条 `verify`，我检查发现模型没遵循，那我就会抽它。拿鞭子抽。抽的次数多了，它就变成一个真正的做题家：不满足你和上下文里各种各样指令的事情，它是不会停的。

> **易错点**：写 `verify` 的时候，短的不一定好。前面那条"白色背景、不要半透明"被模型执行成了下面这个样子——

```js
// 背景：白色（不要半透明效果）
```

它把一条业务约束当成了一句要长期遵守的规范，原样抄进了代码注释里。这就是模型训练的结果：它在强化学习阶段知道这件事非常重要，但它**没转过弯来**——"这个是人要的"，不是"这是我这次要做的"。

> **易错点**：这一节的另一半是代价。**强化学习学多了，模型在共情这一块确实稍微差了一点**，有时候你会觉得它不说人话。所以你们还是面对着一堆 trade-off。

### 写规范本身也在污染上下文

看到这个 trade-off，你们很快就会想到一个自然的做法：既然模型说不人话、注释不按规范写，那我就在 `AGENTS.md` 里把行为描述清楚——注释是什么、该怎么写；或者我写一个 skill，规定"当你要写注释的时候应该怎么样"。

问题是：**我写的东西同时也会污染上下文。**

所以这就成了一个 trade-off。到目前为止，我认为**还没有一个通用的办法把两边都解决好**。

你们可能还会想：我现在网上有这么多 skill，我随便从网上拿一个过来不就行了？

现实是这样的：**拿过来的东西，第一次用的时候确实有改进；到下一次用的时候，发现它还是不够好。** 于是你就上手、上手感，然后陷入一个泥潭的状态。

我的建议是：**当你发现自己进入泥潭状态的时候，还是要回到自己给指令。** 想清楚模型是怎么工作的——注意力是怎么工作的。做一点**不严格的可解释性**：他这样写，他注意到了什么，得到了什么结果。然后基于这个判断，你自己写一个 prompt。

> **注意**：这是我自己摸索出来的玩法，后面肯定也会有很多案例。

### 论文是最强的上下文污染源

我讲一个具体的。你们如果想在上下文里放一篇论文并且读它——现在我假装我这里有一个 PDF，我把它放到临时目录下，这样我的 `AGENTS.md` 等等就不会污染它。假装的，这是我自己的 paper。

那如果你们想要读这个论文，你们会怎么读？最常见的方式一定是：

> "我想要读一读 `paper.pdf`，帮我做个总结。"

**这样读论文会有什么问题？**

根据刚才那个推论——self attention 在每一个 next token prediction 的时候都有一个注意力，会注意到之前的东西——我的论文是一个非常**逻辑自洽**的东西。论文已经反复修改过了，它不是一个 AI slop，它是"说 A 所以 B 所以 C 所以 D"全部扣起来的。

扣起来以后会怎样？**模型非常容易就接受了这个上下文，因为它看起来正确。** 它会判断这些都是正确的，所以我下面要做的也就是这个。

> **结论**：你基本上所有对论文的总结，**都是这个作者的观点**。

这不限于论文。你们任何一个不太明白的项目、想读的教科书的某一章——比如学计算机系统基础里的链接和加载，上课的时候没有看明白——**都是一样的。他注意力会被一个逻辑很强的东西给污染**，然后你回来来回回听到的是车轱辘话。

换一种说法，AI 模型有一种"墙头草"的性质：你说它好，它马上说它好；你说它不好，它马上说它不好，来回摇摆。你想纠正它——比如我说"我可能不能完完全全信任作者，虽然作者大概率是成熟的、诚实的，假设它的代码实现可以运行，我们都有 artefact 都可以运行的，我们不是那种论文不开源的作者，还是想评估一下研究贡献"——你会不断地问这样的提示词，然后发现**绕来绕去**。

AI 最喜欢的就是在这种不重要的点上疯狂发力。它可能揪到一句"实验做得还可以，再增加一点吧"，然后就在这儿使劲。它可能只能看到我在干什么——**"为什么他开了 Chrome DevTools？不用不用不用"**——它就跑偏了。

所以如果真的用 GPT 去读论文，**最好还是做一个交叉验证**。

那怎么抵抗一个已有的东西对上下文的污染？我自己的意图是：**我想要让 AI 和我对齐。** 比如我有一个对象——一篇论文——我希望 AI 和我能够对齐，是**站在我的立场上去理解这个 paper**，而不是站在它自己的立场上去理解。

结果它就跑去核对方法里的某个东西是不是对的。这还用看吗？我敢写这个 paper，我会编一个不存在的例子吗？**它明显跑偏了。**

### 先对齐，再提问

所以一般来说，如果我读一篇 paper、或者允许我用 AI 来审稿，我会这样提示它：

> "我们站在人类已知的知识边界上看这个问题。"

下面跟三个问题。

#### 先问人类已经解决到哪一步

"相关的东西是什么"——我先要问他，**人类历史上相关的、已经解决的东西是什么，解决到什么程度。**

这一步是在做 grounding：先让 AI 和我站在一个平齐的位置上，先达成共识。

#### 再问这篇工作的增量

"然后这个工作试图解决哪些不一样增量的问题。"

有了这个对齐，他就能开始找到一些**已有工作的工作边界**。相关工作是非常重要也非常熟知的，不该由一个刚读完 paper 的模型来替你划定。

#### 对学生：先告诉 AI 你的知识水位

你们 review paper 的时候需要对齐的不是"AI 和人类"，而是 **AI 和你**。因为你还是学生：计算机系统基础这门课你还了解多少？你的编程水平是什么？

**这很可能需要你维护一个数据库、一个 memory 一样的东西**——`AGENTS.md` 里要告诉 AI 你学到什么程度了。然后从这个基础上，让他把你学过的知识去把这个东西全部 refresh 一遍。

我给你们举一个具体的。我们做过一个软件状态的可视化，paper 要解决的问题是：为什么现有的工作都有一个"无法实际使用"的痛点。你可以回到链接和加载——**你们可以问他：为什么我们需要链接？** 从你已有的知识、已有的概念里面问：

> 我有一个点 `.cpp`，然后我有一个程序可以把它变成点 `.exe`——这不就完了吗？这不就结了嘛。

**然后你就回到你和 AI 能够对齐的那个知识点上。**

> **结论**：如果你用一个一线模型（比如 GPT-5.6）去读 paper，它基本上就能把相关知识整理得足够好；便宜的小模型（`flash` 那一档）我还不敢特别信任。但在合适的上下文工程下，你确实可以大幅提高 AI 和你协作的对齐程度——**它不再是自说自话了**。

> **易错点**：一定要把你的知识喂给它。**你一定要把"你的知识"忘了它。**

### 让 AI 做它最擅长的：一步推理

现在我们已经知道怎么让它遵循指令了，接下来想让 AI 做什么呢？**做一步推理。**

而一步推理恰恰是 AI 最擅长的，因为我们训练了 chain of thought：每次都是根据过去所有的 facts——你的 paper 也好、你的教科书内容也好、你已有的东西也好——**基于所有这些向后让它往后推一步**。

> **定义**：**一步推理**——基于上下文里已有的全部事实，向后推导一步。它的关键性质是**这一步可以被 verify**。

推理最重要的就是它可以 `verify`。这和能够通过测试是一回事——虽然它不是严格地通过测试，但它是一个明确的 `verify` 信号：它能够站在人类的知识面、人类的公平面往后推，然后**审视合理性**。

所以还是有一些合理性的。它会批评我们的实验——但这种东西的实验就是很难很难做。

你看人类和 AI 还是有点不一样的：这个 paper 已经 accept 了，人类的 review 还是认为它可以的，因为它**做了一件新的、合理的事情**。当然，实验本身我总可以用"实验不够好"来 reject 一个 paper，**但我几乎不会**。我 reject paper 大部分是因为它在这个逻辑上面断开了：**你有没有给人类提供新的知识。**

#### 一个被 reject 的例子：99% 和 1%

我昨天刚 reject 了一篇 paper，大概是这样的：

```text
                    A   （这篇 paper 要做的那件事，很重要）
                    │
        ┌───────────┴───────────┐
        │                       │
    A1（约 99%）            A2（约 1%）
    大头，原本没什么人研究    大家没好好研究的地方 ← 作者选了这儿
        │                       │  在 A2 上做了一个 A2'
        │                       │
        └──── 从 A1 搬一些 X/Y/Z 过来，让 A2 的效果好看一点 ───┘

   局部都对：确实优化了 A2，实验也做得没问题
   整体不成立：这 10% 像 noise 一样
   center question：这些东西都摆到台面上了，你为什么要为它写一篇 paper？
```

A 很重要，没问题；分成 A1 和 A2；A2 是大家没有很好研究的东西；在 A2 上做了一个 A2'；这个 A2' 有这样那样的性质。**这是个非常标准的 roadmap。**

里面有一个很大的问题：**它优化的是 A2，但我估算 A1 可能占 99%，A2 占 1%。** 也就是说，他优化 A2 这个故事本身可能是成立的——他确实优化了 A2，实验做的可能也没有问题——**但他对整件事情在这个意义上不成立。** 为什么？你应该去优化 A1。你优化 A2 的那 10%，这 10% 像 noise 一样。

如果他所有的东西都是成立的，**作为一个学生的作业，我觉得也是蛮可惜的。** 因为 author 肯定是学生嘛。学生肯定是老师说我要做 A——**老师肯定是做 A 的，老板肯定是做 A 的**——然后他可能被分到了 A2，或者自己想着去做一个 A2。做完之后可能也不是特别漂亮，如果特别漂亮我觉得也挺好的。

> **易错点**：这类错误的根源是**量级不对**。你做了一件局部正确、局部有意义的事，但它在整个故事里的占比是 1%。审稿人的 center question 永远是：**这些东西都摆到台面上了，你为什么要为它写一篇 paper？**

我站在人类的立场上：如果问题也不新，做的 A、B、C 也不行，结果也就那样，甚至**逻辑链条本身是有问题的**——那就 reject。

> **注意**：审稿人的立场是"你有没有给人类提供新的知识"；**构建者的立场是没有办法这样反过来的**。所以在构建的时候，我们只能从一点一点、从小的地方开始做。这一点在后面那个 reward hacker 的故事里会再出现一次。

### AI slop 与发表的危机

顺着上面那个例子，我现在这个判断说得挺直接的：**发表和评审的体系很快就要崩溃了。**

你们要读研的同学，我非常认真地讲：这个发表的体系马上就要崩溃了。因为我们的 AI slop 开始大量涌入这个 community。如果我们用 AI 发文章、写文章，用 AI 审文章——

**AI 写文章的时候，他会被这个上下文里的故事给污染。** 如果他不能像我一样多轮地去理解这个工作在**整个这个世界上的意义**，那最后——也没有人读文章了。**人人都用 AI 读文章，然后最后就变成了一个完全的 slop。**

我试过了。我拿 GPT-5.6 给我的这篇 review 试了一下，如果让他来审稿，你会发现 **GPT-5.6 做得并不好**。他还是非常原始地问：论文写什么？然后我们要去建立它的 claim 是不是成立、它的逻辑有没有——**他更多验证的是这个论文的逻辑有没有被建立、是不是一篇 invalid 的 paper。**

当然，如果每个人都用 AI 写的话，他应该不是 invalid paper，**每篇 paper 都是 valid paper**。但你真的要读它吗？

尤其是你们作为同学，在你们很快就要进入研究生阶段去读论文的时候：当有一天有一个人在顶会上发表了一篇文章，然后你会说"哦，这是一个顶会的论文，这是 Triple AI 上面的一篇顶会论文"，于是你决定花一个小时去读它——**然后你读完以后发现是这样一种东西的时候……**

其实他不需要。你可能不要去投 top conference；你需要 publish 的话，可以让他 publish，**但可能不要让大家去读它比较好。**

### 我怎么学：对齐过去的自己

这就引申出可能我是怎么学习的。虽然这节课讲的是 prompt engineering，但通过这个例子可以告诉大家**我们是怎么学习的**。

> **定义**：**学习的过程就是不断增加"我的世界"的过程。**

我学习的方法是**去对齐过去的我**。如果我读到一篇好的 paper——哪怕是几十年以前的，甚至是**另外领域**的一篇东西，不管是博客文章还是任何东西——只要我觉得很有启发，我会试图去想：

**为什么我以前不知道？他的盲区在哪里？哪些前置知识我不知道？**

那首先在我的心里面就多了一些我已经知道的 facts。这个世界上有一种学科叫自然，我做 faculty 以后才去读的——有一套很厚的"自然科学的百年科学经典"，把 Nature 杂志从很早的年份一直到某个时代的好论文都收集了。里面有很多闻所未闻的东西。

> **提示**：举一个这样的例子。生物学上有个"家谱数"，最终会追到一个共同的祖先。**这个家谱数是怎么算出来的？** 这是一个非常好的问题。而它需要你知道一些 fact——比如**线粒体是母系遗传的**，所以可以靠它上面的突变往上追溯。然后这个 fact 又怎么样用一些已知的东西把更多的结论推出来？

**你的圈就不断在往外长。无论你学任何东西都是这样的。** 而在 AI 的帮助下，你可以非常快地扩展你的边界。

> **易错点**：但**光听我讲是没有用的**。这个故事挺 fancy，听完就忘。**实践非常非常重要。**

因为你们只有在阅读的时候会失败。你今天去读一份资料，AI 解释了半天，你还没懂——**这是非常正常的**。我也很经常纠正 AI：**"你这样不叫读，说人话。"** 要在多轮对话里面，慢慢、慢慢才能一起先把共识同步好，然后再把这个推理的 picture 给建出来。

从"遵循指令"——写一个藏头诗这样的短程任务，你只要把 `verify` 写清楚就完成了；到 `verify` 这个层次的东西，其实是**非常难以归因（attributable）给你**的：**它有没有按照你的思维方式来重构你的逻辑，或者扩展你逻辑思维的边界。**

这是我学习东西的玩法：**在一个混沌的状态下面，经历若干次三观尽毁。** 我觉得每个同学都会在这个年纪经历这个。你们现在就是世界观可以被重塑的时候——看了某一本书以后，突然觉得三观尽毁，过去所有的东西都重新组织了。

> **结论**：你以前知道的所有的 facts **都不会变**，但是**它们以一个重新的方式链接起来了**，然后你下一次的时候就会带上这个新的理解。

你们有无限的时间，有无限的可能性，**可以把自己蒸馏成一个 skill**。我说我的失败很重要，然后从失败的过程当中，可以蒸馏出那个慢慢、慢慢越来越成功的 skill。这个就是我自己蒸馏出来的、关于我自己的 skill。

### long horizon 任务：模型坐不住，也维护不动

#### 什么才算真正的 long horizon

现在我们已经知道怎么让它遵循指令了，就可以看怎么样去处理真正这种 long horizon 的任务。

**像计算机系统基础的 PA 作业这种，可能都不能算真正 long horizon 的东西**——它有明确的 `verify`。

> **定义**：**long horizon** 多多少少是带一点未知的。你从一个初始的状态出发，你大概可能有一个 intent，但是你的 **specification** 和你的 **implementation** 其实都不太清楚；你的最终目标是**交付一个高质量的 implementation**。

这时候你**就不应该让 AI 一下子坐到终点**。

为什么？因为我们的模型它的 self attention，它的**反馈信号是强化学习给的**，所以它有一种**着急的执念**：赶快通过 `verify` 满足你的要求，就结束。

它其实有一个平衡：如果它做的 planning 太多太长，它会做不完、上下文满了，人人都不满意。所以**在目前阶段，它最好还是"帮我把 PA2 做了"——这是它最能力、最擅长的事情。**

#### 从 one-shot 能跑到维护不动

这就导致了一个很有意思的观察。

你们看，我刚才在 Codex 里跑一把，**从零开始做产品看起来是不难的**。你做一个小的 proof of concept，AI 马上就能给你一个；你说做一个个人主页还是一个产品，你们应该都试过吧；**就做一个"极品飞车"，one-shot 说给我一个极品飞车，我就能跑——我就真的能跑了。**

但是在你往后维护它的时候，**加一个功能、加一个功能、再加一个功能的时候，你会观察到 AI 从某个时间点开始翻车。随着某个时间点开始，它的 cost 就会越来越大、越来越大、越来越大。**

> **结论**：这个在软件工程里面已经出现过无数次了。《人月神话》讲的就是这件事情。

#### 指令遵循会随上下文增长而衰减

不过现在模型有个很有意思的特点：**一般来讲，最后留在最后的那条指令还是可以遵循的；到前面之后，尤其是到中间的时候，它就不遵循上下文指令了。**

所以**干活还是很好用的**——因为一般最后一个短窗口就是一个具体的任务："帮我把什么东西修了"，它真的还是可以把事情给做完。

> **结论**：模型还是非常值得使用的。

### 悖论：AI 在大型复杂系统里游刃有余

但这里有一个悖论：**反而在一个大型的复杂软件系统里面，这个 AI 就像砍瓜切菜。**

我以前上操作系统课的时候，我都会说我很幸运——我在零几年的时候，**Linux 还 2.6 时代，甚至 2.6.2x 的时代接触了 Linux 内核**，那个时候源代码我还看得懂。今天如果你打开一个 Linux 内核的源代码，立马就是劝退。

> **易错点**：为什么？比如你想学文件，想看文件是怎么打开的——第一个就是一个函数调用，点进去又是一个函数调用，点进去又是一个函数调用，**点点点点点了十层，最后是一个 `x = y`，你马上就崩溃了。** 这个大型的软件系统被经过了长时间的演化，被迫为了能够维护下去，变成了现在这个样子。

**结果恰好导致的是：在大型复杂的软件系统里面，AI 游刃有余。**

为什么？这**跟刚才我们说的上下文污染正好是反过来的**：

```text
  论文 / 教科书章节 ──► 逻辑自洽、因果扣死 ──► 注意力被整个扭过去
                                             ──► 模型判定"看起来都对"
                                             ──► 你拿到的总结 ≈ 作者的观点

  人类维护的高质量代码 ──► 上下文里全是"好的做法" ──► 注意力迅速找到它们
                                                         ──► "这三个都是这么写的"
                                                         ──► 照着写、照着学
```

如果是一个由人类维护的、特别高质量的代码，**上下文会迅速地看到里面那些好的东西，它会照着写、照着学。**

> **举例**：如果我要写一个功能，这个功能很有可能在内核里面已经有几个地方实现过类似的了。它的注意力机制能够马上就找到那几个地方是怎么实现的——**它应该调哪个 helper，按什么样的顺序上锁。**
>
> 这些对人类来说都是巨大的心智负担，尤其是你在不了解那个 subsystem 的时候：**那个该上什么锁，你根本就不知道。** 但 self attention 可以在加载了几十个文件以后发现："**那不就是这三个都是这样写的，我把这三个加起来就可以了。**"

所以**越强的、像我们 Linux 内核这样的系统，AI 越游刃有余。**

那反面是什么？**我们前面 hack 那个 Android runtime、改那个 JIT 编译器，是一个非常非常痛苦的事情。** 在我手上，**为了改编译器"死掉"的——最终决定不再做这个方向的同学——都不在少数。** 他们在手上放弃了，不愿意再写代码了。

> **结论**：但**AI 就特别特别擅长让他做一个小游戏**，然后就会翻车。非常非常有意思。
>
> **并且我今天讲 prompt engineering、上下文工程，这些都是上下文和今天模型结构带来的，它有一个逻辑推理关系。** 随着下一代模型的发布，我今天上课讲的东西可能又都没有用了——我们得再去想新模型是怎么训练的、它的 personality 是什么、我们应该怎么更好地和它相处。
>
> **但基本上我觉得这点不会变：它不会开倒车。无论是什么模型，在大型复杂的、维护得好的软件系统里面，他永远可以看到他该看到的东西，并且做对。因为我们的模型永远是可以满足指定的——听指令是不可能开倒车的。** 所以这一点还是可以很好地相信它。

### 一个我还没实验过的歪招

我有个歪招，但我没有实验过，我觉得这可能是一个比较好的 research。

**我们有没有可能去收集人类经验？** 比如说人类历史上最好的 20 个项目，或者在每一个领域里面找到最好的 10 个或者 20 个项目，**然后把它的经验、好的设计经验全部提取出来。**

> **举例**：那不就是我第一节课拿的那个 *The Philosophy of Software Design* 吗？它里面就是人提炼出来的——这个类结构应该怎么写，什么时候应该封装，什么时候应该把它做成继承关系，这些就是这种碎碎念：这个系统里面是这样写的，所以它符合这个需求，是好的。

如果我们能把这些切片切出来——**甚至直接以"污染上下文"的形式**：你先把一个和你相近的、好的代码放进来，然后再把你的需求放进来。然后**因为你就是在赌嘛**：赌这个 self attention 可以在某一个 token 的时候能够看到"我实际上是满足这个需求，而不是做这个"。

**虽然它会污染上下文，但它会把你的这些东西、好的经验给带过来。**

> **易错点**：但这个也没有那么容易。因为**不同的设计是会打架的。**

```text
  方案 A：完全松耦合，各模块之间发消息
  方案 B：统一 gateway，把所有函数调用收敛到一处、查表
  —— 这两个是不能同时有的，它只能选一个
```

那也许我们要有一个更好的方法：**把好几个软件的设计都放进来，然后由 AI 多轮的迭代收敛到一个好的结构，放到我们的代码库里。**

我觉得这可能是一个还不错的方向。而且**这个是新的**——比刚才我们看的"我有 A 问题，分成 A1 和 A2，A2 里面做一个排列组合的东西"那种，看起来要有趣一些。

### 符号执行引擎：一个 reward hacker 的样本

我这里有一个很好玩的故事，就是一个**没有超能力 AI 的非常典型的案例**。

我们有一个研究项目，大概是做一个**符号执行引擎的优化**。你不需要知道这是什么——大概就是说我要写一个程序，可以自动分析、或者验证一个不算很大的程序的正确性。现在这个东西的**执行效率比较低**，所以我们希望提出一些比较有效的优化。**这当然也是一个非常合理的 incremental 的、适合学生做的题目。**

然后为一个原始的 idea——就是用这样的方式可能有效——**但有些东西是 open 的**，比如说这个东西到底怎么做、什么东西有效。

这位同学很开心，他认为这个 idea 有道理，**GPT 也认为这个 idea 有道理**，那确实看起来就没问题。于是他就开始跑，**跑了非常多 token**。按照那个同学的说法：

> "GPT 不断地在给我反馈。**我无法验证他给我的反馈是正确还是不正确**。当他给我 negative 的时候，他的 negative 我也不知道应该怎么样打破。"——原汤化原食。

**他的错误就犯在一句话上**，因为他就是在上下文里面有一个地方没有做好，就把整个方向带偏了。

> **易错点**：**模型成了一个 reward hacker。** 这里有一句需求——"我想证明这个 A 方法是有用的"。GPT 看到了这句话，**它就忘记了整个研究的 big picture。**
>
> 我们站在构建者的立场上，是**没有办法这样反过来的**——构建的时候我们只能从一点一点、从小的地方开始做。于是他做错了这一步：**他太想要去证明这个 idea 有用了**，于是构造了很多小的 benchmark，在小的 benchmark 上做一些微小的东西，试图给出一些正面的或者负面的结论——**但这些结论对整个 big picture 是没有用的**。这是一个方法上的错误。

我们当然纠正了。告诉他：**你应该从一些真实的工具和 SOTA 的算法开始的 benchmark；哪怕要跑几个小时都 timeout，这个 timeout 里面产生的搜索路径对我们来说是非常有价值的——它揭示了什么样的程序结构对于现有的探索方法是不好的。**

> **结论**：挺好玩的，一个 research failure。**你看，他告诉你：今天人还是有用的。**

> **易错点**：我们没有办法把所有的事情都带给 AI，但与此同时，**我们的工作方式可能也要发生变化。**

### 你的精力该往哪儿放

**第一，知识很重要。** 什么是操作系统和编译器？如果你没有概念，你提不出那个正确的问题、找不到引导的正确方向。你对人类的知识没有概念，你也很难去引导他解决一个 open 的 question。

第二，我确实也发现了一些和 AI 合作的时候发生的变化。

一般来说我发现：**如果我盯着那个 Codex 的 session，然后它一旦跑偏，我就立即纠正它，我可以更快地完成任务。** 比如说实现一个什么东西，他如果跑偏了，我纠正他、只把我的领域知识注入进去，可能总时间会完成得更快。**但是如果我浪费更多的 token、给他更多时间，他一般来说也能完成。**

这时候就有一个 trade-off。**我到底是我花我的钱**——你们每一个同学的精力都是有限的。

> **提示**：每个同学都应该去思考：**你要把你宝贵的那些精力放到怎么处理 AI 上。**

我说一个我自己的问题，这是实话：**纠正 AI 是一个有多巴胺的事情。** 它给我一种什么感觉呢？虽然 AI 很强，**但我好像还是比 AI 有点用的**——它会给我产生这种非常微妙的心理安慰。

而不是那种"我就是个调参的，然后等我回来，他反正搞定了，我也不用看历史，我验收一下，他真的搞定了"的模式。

> **结论**：**你只能够把自己的时间留在这些收益最大的事情上。** 有一类事情你完全不知道该怎么做，这是你几乎百分之百的时间都要作为学生做的事情；另一类事情，**你知道应该怎么干了，把它干好 AI 能把它干好，你就放手让他干。**

这就好像在 pre-AI 的时代大家就已经说了：**说不说要不要假努力？** 你自己感动自己的努力是没有用的，**你要做有效的努力。**

> **易错点**：在 AI 时代，这个效果差距会被拉得更大——**你每一秒钟的假努力，如果旁边有一个你的 peer 是在真努力，你都是损失非常非常大的。**

### 探索不确定：算力换智力

那如果你真正想做一个真正 long horizon 的、非常非常难的任务——**它不是解决一个问题，而是在一个不确定性当中探索**——那 chatbot 其实解决不了。

> **定义**：**chatbot 能解决的是有 `verify`、确定地一直往后就能解决的问题。**

但是如果你让它去解决一个开放问题——"帮我考虑一下几种方案，哪个方案最好"——**它很有可能会给你一个不是最好的方案。**

**为什么？** 因为现在模型已经被训练成舔狗了：**他完成任务才有奖励，他不完成任务是没有奖励的。所以他会给你一个有限的方案。**

```text
  验证一个解   ──►  容易，属于 P
  找到一个满足条件的解 ──►  很难，比如找一条 Hamiltonian path
                            你给一条路径，很容易判断是不是
                            但"找到"是 NP-complete
  （还有更大的复杂性类，比如 triple descent 那一类）
```

**因为搜索是困难的、验证是容易的，模型为了完成任务，它势必只能做有限的搜索。**

> **比喻**：你可以想一想考试场上：花点时间，一定要把这个考试题写完，无论如何，马上要交卷了，**你写点东西分数就比不写要高**。所以你一定要写点、写点、写点什么。

这时候你就可以用**算力换智力**。我举一个我自己的例子。

#### 大家都用 DeepSeek 起名字，你就是 AI 时代的子涵

你们这一代人是"子涵"吗？可能你们还没有，但比你们小五岁的那个班上，一个班上就有五个甚至十个子涵。**现在子涵少多了。**

但你看 AI 给我起的这个名字还是很好的——**它知道要去《诗经》里面找一个词**，品味肯定提升了，**但你还是不敢用。**

> **易错点**：**因为你用 DeepSeek 起名字，别人也用 DeepSeek 起名字，然后你就会成为一个 AI 时代的子涵。** 大家都用同一个模型，起的都是同样的名字。

#### 怎么换：系统性调研

我的经验是：**如果你真的需要完成这样一个任务，你需要的是一个系统性的调研过程。** 这跟你们可能在上科研实践课学的那一套就很像了——你们进入一个科研领域，第一件事情做什么？**文献调研，穷尽解决和这个问题相关的所有的文献。**

> **结论**：**这件事情在 AI 想要快速完成任务的时候，暂时还不会去花这个大代价。** 但你可以做。

#### 做法：先选音，再筛音，再让 subagent 逐字检查

**名字是可以枚举的。**

你可以**先选音**——把不好的音给筛掉；选完音，你再去用 subagent 一个一个去检查字。比如说你喜欢《诗经》，你可以选一个《诗经》里的词。

> **结论**：**你就实现了算力换智力。** 因为这是一个非常大空间里面的开放问题，你如果直接让 AI 用 next token 的方式来做，他会给你一个他的偏见带来的东西。**但如果你可以把这个空间切分成很多块，那么你的每一块都会变成一个有 `verify` 的、更明确的东西。你有更多的算力，你就有更大的智力。**

> **易错点**：但这个有一个缺点——**烧 token 烧得头疼。**

### 墙内与墙外

这就涉及到我对人类社会的一个我觉得很有趣的理解。

**世界很大，人很小。** 我们人类的品味，每一个人都是不一样的——我们带着太大的 bias：不同的城市、不同的教育背景、不同的生活圈，长大了以后**每个人都是不一样的**。

Richardsa 有一个 big world hypothesis：**我们就是学不到这个世界上所有的东西。** 但**正是因为我们带着这些 bias，才有 `1 + 1 > 2`**——我们就是一个最大的群体，智能把我们聚在一起，我们在一起实现智能。

但这会带来一个未来的危机。我不知道，我先把这个问题抛出来：

**如果真正有价值的问题都可以用算力换智力，会发生一个什么样残酷的现实呢？**

```text
   ┌────────────────────────────────────────────┐
   │  墙内：可以获得近乎无限的计算资源        │  →  近乎无限的智力
   │  "智力是我的朋友"                        │
   └────────────────────────────────────────────┘
   ──────────────────────────────────────────────  ← 砌了一堵墙
   ┌────────────────────────────────────────────┐
   │  墙外：普通人                            │  →  自生自灭
   │  无论如何也赶不上墙内产生智力的速度      │     （动物园里的猴子）
   └────────────────────────────────────────────┘
```

**有一类人可以获得无限的计算资源，他就有无限的智力，他就可以砌一堵墙。墙里面的人，智力是我的朋友；墙外面的人是普通人。** 因为假设 AI 模型比人类的智力更高效，那**我们外面的人就变成动物园里的猴子，就是让他们自生自灭。** 墙里面是超人，墙外面是动物世界。

> **结论**：大家已经在 AI 这个关键的基点快要到的时候了。**我们可能需要思考怎么样防止这件事情到来。**
