## HTML入门、常用标签与表单
> 对应块：BLK01 | 覆盖分集：P01-P07

前端开发是构建现代互联网世界的关键一环。无论你是打算为自己的个人项目搭建一个网站，还是在公司里参与构建大规模的商业应用程序，前端开发都是一项令人兴奋且极具发展潜力的技能。对于非计算机专业、打算转行做程序员的同学来说，前端也是进入互联网行业的最佳选择——它的入门门槛相对较低，所写即所见，见效极快，是最容易上手掌握的 Web 开发技能。

说白了，Web 前端的核心职责就是“做网页”。我们在浏览器中随意打开一个网站，例如我们的技术教程站点，映入眼帘的会有排版各异的文字、图片、可点击的按钮，甚至还可以嵌入音频和视频。我平时讲课所演示的演示文稿（PPT），本质上也是使用前端技术搭建出来的网页。这些视觉元素究竟是如何呈现在浏览器窗口中的？这正是前端工程师要解决的核心问题。在谷歌浏览器（Google Chrome）中，我们可以直接通过鼠标右键点击“查看网页源代码”，或者按下快捷键 `F12` 打开开发者工具，在“元素”（Elements）面板中，就能清晰地看到页面各个区域与底层代码块的一一对应关系。

### 前端技术体系与网页呈现原理

#### 前端定位与核心价值

在正式编写代码之前，我们需要理清“前端”与“网页”二者之间的底层关系。简而言之，前端是构建网页的核心组成部分，专门负责处理用户在浏览器中所能看到的一切界面元素，以及用户与页面产生的所有交互行为；而网页则是浏览器用来解析并呈现内容的物理文件或载体页面。

前端开发之所以具备极高的学习反馈效率，在于它构建的所有成果都直接依托于浏览器进行可视化渲染。用户每一次移动鼠标、点击按钮、输入表单，都是在与前端代码直接对话。掌握了前端技术，就拥有了在互联网上直接表达创意与搭建数字化工具的完整能力。

#### 核心技术分工与网页关系

一个标准的网页通常由三大核心技术协同构建而成：超文本标记语言（HTML, HyperText Markup Language）、层叠样式表（CSS, Cascading Style Sheets）以及 JavaScript（简称 JS）。它们在网页呈现中各自承担着完全不同的职责：

```text
+-------------------------------------------------------------+
|                           网页呈现                          |
+-------------------------------------------------------------+
|  HTML (结构与内容)  : 搭建骨架，定义标题、段落、图像与超链接 |
|  CSS  (样式与布局)  : 美化外观，定义按钮色彩、文字字阶与栅格 |
|  JS   (交互与逻辑)  : 驱动行为，实现数据校验、动效与异步通信 |
+-------------------------------------------------------------+
```

上图展示了网页前端三大核心技术的职能分工：HTML 负责骨架构建，CSS 负责视觉呈现，JavaScript 负责行为交互。

HTML 负责定义页面的“结构和内容”。文本写在哪里、图片放在何处、哪些文字需要变成可跳转的链接，全部由 HTML 决定。

CSS 用于控制页面的“样式和布局”。比如为什么教程网站上的视频播放按钮底色是明亮的黄色，而周围其他背景区域都是深沉的黑色？又比如网站名称“极客侠”为什么呈现为灰色，而下方的辅助说明文字则是纯白色？这些色彩、字体、间距与布局定位，全都是 CSS 规则在起作用。按下 `F12` 打开开发者工具时，右侧展示的样式面板就是当前元素所生效的 CSS 代码。

JavaScript（JS）则专门用来为页面注入“交互性与动态功能”。包括点击按钮弹出对话框、表单数据的动态校验、不用刷新网页就能加载新内容等，都依赖 JS 来驱动。明确了这三者的分工，我们便能明确本阶段的学习路径：先攻克负责骨架的 HTML，再进阶负责外观的 CSS，最后融入负责动态交互的 JS。

#### 前端核心开发插件

为了让写代码更加高效顺畅，我们需要在 VS Code 中预先安装三款前端开发不可或缺的核心插件：

| 插件名称 | 核心作用与价值 |
| :--- | :--- |
| `HTML CSS Support` | 编写 CSS 与 HTML 时提供强大的类名智能补全与语法提示 |
| `Live Server` | 启动本地实时热更新开发服务器，保存代码即可在浏览器中实时预览改动 |
| `Auto Rename Tag` | 修改 HTML 开始标签或结束标签时，自动同步重命名成对的另一端标签 |

在扩展面板中依次检索并安装：

- 其次是 `Live Server`（下载量超四千万次）。在以往传统的开发流程中，每次修改了 HTML 代码，我们都必须手动切换到浏览器并按下 `F5` 刷新页面才能看到效果。而安装了 `Live Server` 之后，我们只需在编辑器中保存代码，浏览器页面便会毫秒级同步重载，真正实现“边写边看”的实时预览体验；
- 最后是 `Auto Rename Tag`。HTML 标签大多成对出现，在重构或调整标签时，如果手动修改了前面的标签名而忘记修改后面的结束标签，就会导致页面结构解析混乱。这款插件能够确保修改成对标签中的任意一端时，另一端即时自动跟随重命名。

### HTML 文档结构与环境运行

#### 标签语法与单双标签分类

HTML 的全称是超文本标记语言（HyperText Markup Language）。我们无需去咬文嚼字死磕“标记语言”这四个字的理论定义，只需把握其本质作用：**HTML 是用来给网页内容提供结构的，它明确告诉浏览器哪一部分是一级标题、哪一部分是自然段落、哪一部分是列表，哪一部分是多媒体资源**。

那么 HTML 依靠什么来向浏览器传递这些结构指令呢？核心载体就是**标签（Tag）**。标签通过尖括号 `< >` 语法进行组织，并根据其是否闭合分为两大阵营：

```text
双标签结构:
<开始标签 属性="值">包含的内容文本或子元素</结束标签>
   └── 开始标签 ──┘                       └── 结束标签 (带反斜杠) ──┘

单标签结构:
<单标签名 属性="值">  (无结束标签，不包裹内容)
```

上图对比了 HTML 中双标签与单标签的基本语法形态。

双标签通常成对出现，由开始标签（`<tag>`）和带有反斜杠的结束标签（`</tag>`）共同组成，具体的内容包裹在两者中间。比如表示段落的 `<p>内容</p>`、表示一级标题的 `<h1>内容</h1>`、以及创建超链接的 `<a>内容</a>`。双标签的典型特征是用于承载具体文本或嵌套子级元素。

与双标签对应的是单标签。单标签顾名思义没有结束标签，仅凭单个标签本身独立存在。例如用户输入控件 `<input>`、强制换行标签 `<br>` 以及水平分割线标签 `<hr>`。单标签的存在逻辑非常明确：它们主要用于在页面上创建独立的功能控件或排版符号，内部无需承载任何文本内容。

#### 标准文档骨架与元信息

一个规范标准的 HTML 文档绝非代码的随意堆砌，它拥有严密的基础树状骨架：

```text
<!DOCTYPE html>  ─────────────────── 1. 文档类型声明 (HTML5)
<html lang="zh-CN">  ─────────────── 2. 根元素 (文档最外层容器)
  <head>  ────────────────────────── 3. 文档头部 (存放元信息、编码、标题)
    <meta charset="UTF-8">
    <title>网页标题</title>
  </head>
  <body>  ────────────────────────── 4. 文档主体 (存放实际渲染的可视内容)
    <!-- 所有在浏览器窗口中看到的文本、图片、链接均写在此处 -->
  </body>
</html>
```

上图展示了标准 HTML5 文档的四大核心骨架层次及其嵌套边界。

我们来逐层拆解这四个基本构成部分：
1. `<!DOCTYPE html>`：位于文档的最顶端，用于告知浏览器当前页面采用最新的 HTML5 标准规范进行解析和渲染，确保现代浏览器不会陷入混杂渲染模式。
2. `<html>...</html>`：HTML 文档的根元素（Root Element）。它是整篇文档的最外层容器，标志着 HTML 文档的起点与终点，包裹着页面内的所有其他标签。
3. `<head>...</head>`：文档的头部区域。这里面的内容主要用于向浏览器和搜索引擎声明文件的**元信息（Metadata）**，比如网页的字符编码格式（UTF-8）、移动端视口设置，以及浏览器标签页上显示的页面标题 `<title>`。此外，外部引入的 CSS 样式表和 JavaScript 脚本也通常挂载在 `<head>` 内。需要强调的是，除了 `<title>` 会在浏览器的标签栏显示外，`<head>` 内部声明的元数据不会直接呈现在浏览器的正文区域中。
4. `<body>...</body>`：文档的主体区域。这里存放的是所有最终需要在浏览器可视窗口内呈现给用户的实际内容，包括文字、段落、图片、音频、视频、超链接以及表单组件等。

> **注意**：我们在后续课程中进行的所有 HTML 界面标签练习，**必须全部编写在 `<body>` 标签对的内部**。如果将可视化内容误写在 `<head>` 或 `<body>` 外部，浏览器虽然具备一定的容错机制，但极易引发不可预知的解析异常和渲染错位。

#### 工作区创建与 Emmet 快捷生成

理解了标准文档骨架后，我们在本地建立一个规范的前端练习工作区。操作流程如下：
1. 在本地硬盘中创建一个专门的练习文件夹，例如命名为 `front-end practice`。
2. 进入该文件夹后，在资源管理器路径栏输入 `cmd` 打开命令行终端，执行启动命令：
   ```bash
   code .
   ```
   该命令利用我们在安装时勾选的系统 PATH，直接将当前工作目录挂载至 VS Code 工作区中打开。当然，你也可以直接在 VS Code 主界面左上角点击“文件” -> “打开文件夹”，选中该目录。
3. 在 VS Code 的资源管理器中新建一个文件，命名为 `demo.html`。

难道我们每次新建网页，都要从头手敲一遍 `<!DOCTYPE html>`、`<html>`、`<head>`、`<body>` 这些繁琐的骨架代码吗？完全不需要。VS Code 原生内置了强大的 Emmet 语法缩写引擎：在空白的 `.html` 文件首行，只需直接输入一个英文半角感叹号 `!`，编辑器会自动弹出 Emmet 语法联想提示；此时按下键盘上的 `Tab` 键（或回车键），一套结构完整、符合工业标准的 HTML5 文档骨架便瞬间自动生成。

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>HTML练习</title>
</head>
<body>
  
</body>
</html>
```

我们可以将 `<title>` 标签内部默认的 `Document` 修改为“HTML练习”。此时在编辑器空白处点击鼠标右键，在弹出菜单中选择 `Open with Live Server`。浏览器会自动启动一个本地服务页面，在标签页栏上可以清楚地看到标题即刻变成了“HTML练习”。如果我们在代码中将其重新改回“Document”并保存，无需手动刷新，浏览器标签页标题便会实时同步还原。这就是 Live Server 带来的高效开发体验。

### 常用文本与排版标签

#### 标题与段落排版

在 `<body>` 内部组织文章结构时，最基础的两个排版标签是标题标签与段落标签。

HTML 提供了六级标题标签，从 `<h1>` 到 `<h6>` 依次递减：
- `<h1>` 表示最高级别的一级标题；
- `<h2>` 表示二级副标题；
- `<h3>` 到 `<h6>` 依次作为更次级的层次小标题。

在编辑器中书写时，直接输入标签名（如 `h1`）然后按下 `Tab` 键，Emmet 会自动补全成对标签 `<h1></h1>`。我们在开始标签与结束标签中间填入具体内容：

```html
<h1>一级标题</h1>
<h2>二级标题</h2>
<h3>三级标题</h3>
<h4>四级标题</h4>
<h5>五级标题</h5>
<h6>六级标题</h6>
```

在浏览器渲染中，从 `<h1>` 到 `<h6>` 的字号大小与字重粗细会逐级衰减。并且，得益于我们预先配置的 `Auto Rename Tag` 插件，后续若需要将某一个 `<h2>` 调整为 `<h3>`，只需光标选中修改前面的开始标签，后面的结束标签便会同步完成改写。

与标题对应的是段落标签 `<p>`（Paragraph）。用于包裹大段的普通正文文本：

```html
<p>这是一个段落标签，用于展示自然排版的正文内容。</p>
```

> **提示**：标题标签在浏览器中默认会附带加粗效果以及显著的字号差异；而 `<p>` 标签则展现为默认字重的普通文本，且在上下段落之间会自动留出一段外边距作为段间空隙。

#### 文本格式化与强调语义

在日常书写中，为了突出特定词汇的重要性或改变文本在行内的视觉呈现，我们需要用到文本格式化标签：

```html
<p>
  文本格式化演示：
  <b>粗体呈现</b> 与 <strong>强化强调加粗</strong>，
  <i>斜体文本</i>，
  <u>带下划线的内容</u>，
  <s>删除线文本</s>。
</p>
```

我们来细致分析这组格式化标签的特征：
- **字体加粗**：可以使用 `<b>`（Bold）或 `<strong>` 标签。在浏览器视觉呈现上，两者都会将内部文字进行加粗；但从语义化角度来看，`<strong>` 承载了强烈的“重要性强调”语境，更易被屏幕阅读器和搜索引擎抓取。
- **斜体显示**：使用 `<i>`（Italic）标签，文本将以倾斜字体渲染（在后续行内元素中我们还会见到表达语义强调的 `<em>` 标签）。
- **下划线**：使用 `<u>`（Underline）标签，在文本底部添加一条下划线。
- **删除线**：使用 `<s>`（Strikethrough）标签，在文字正中穿过一条横线，常用于展示失效的原价或废弃内容。

在书写 HTML 时，标签的换行排版并不会影响浏览器中的实际渲染。例如将 `<p>` 标签的开始标签、文本内容与结束标签分三行书写，浏览器依然会将其折叠为连续的单行文本。若想改变文字的具体像素大小或定制复杂字色，则需要借助后续课程的 CSS 来实现。

#### 列表结构与项目组织

除了扁平的自然段落，页面排版中最常见的信息聚合结构当属“列表”。HTML 将列表划分为无序列表与有序列表两种基本形态：

```html
<!-- 无序列表 -->
<ul>
  <li>无序列表元素1</li>
  <li>无序列表元素2</li>
  <li>无序列表元素3</li>
</ul>

<!-- 有序列表 -->
<ol>
  <li>有序列表元素1</li>
  <li>有序列表元素2</li>
  <li>有序列表元素3</li>
</ol>
```

无序列表使用 `<ul>`（Unordered List）作为外层容器，内部包裹具体的列表项 `<li>`（List Item）。浏览器在渲染无序列表时，每个 `<li>` 项前默认会渲染一个小实心圆点作为项目符号。

有序列表则使用 `<ol>`（Ordered List）作为外层容器，内部同样包裹 `<li>` 列表项。与无序列表唯一的区别在于，浏览器会自动在每个有序列表项前方递增标注数字序号（如 `1.`、`2.`、`3.`）。两者在结构包裹与使用语法上完全一致。

#### 表格结构与数据单元

表格（Table）相比于线性排列的列表更加复杂。列表本质上是一维的行集合，而表格则是兼具“行”与“列”的二维数据网络。在 HTML 中构建一个标准数据表格，需要由外至内嵌套多层标签：

```text
+-------------------------------------------------------------+
|  table (表格根容器)                                          |
|  +-------------------------------------------------------+  |
|  |  tr (第1行: 表头行)                                    |  |
|  |  +-----------------+-----------------+-------------+  |  |
|  |  | th (列表头1)    | th (列表头2)    | th ...      |  |  |
|  |  +-----------------+-----------------+-------------+  |  |
|  +-------------------------------------------------------+  |
|  +-------------------------------------------------------+  |
|  |  tr (第2行: 数据行)                                    |  |
|  |  +-----------------+-----------------+-------------+  |  |
|  |  | td (数据单元格) | td (数据单元格) | td ...      |  |  |
|  |  +-----------------+-----------------+-------------+  |  |
|  +-------------------------------------------------------+  |
+-------------------------------------------------------------+
```

上图清晰描绘了 HTML 表格的标签拓扑层次：`table` 包裹多行 `tr`，行内按需分配表头 `th` 或数据 `td`。

构建表格的核心标签体系包含：
1. `<table>`：定义整个表格的最外层根元素；
2. `<tr>`（Table Row）：定义表格的一行；
3. `<th>`（Table Header）：定义表头单元格。通常位于表格的首行，内部文字默认加粗并居中对齐；
4. `<td>`（Table Data）：定义普通数据单元格，承载表格的具体数值或文本。

代码实操如下：

```html
<table border="1">
  <tr>
    <th>列表题1</th>
    <th>列表题2</th>
    <th>列表题3</th>
  </tr>
  <tr>
    <td>21</td>
    <td>22</td>
    <td>23</td>
  </tr>
  <tr>
    <td>31</td>
    <td>32</td>
    <td>33</td>
  </tr>
</table>
```

默认情况下，原生 HTML 的表格是没有边框线的，单元格内容松散地排列在一起。为了让表格具有明确的网格边界，我们可以在 `<table>` 开始标签中添加一个 `border="1"`。加上之后，表格立刻呈现出规整的双线网格边框。而这里的 `border`，正是我们接下来要重点剖析的——HTML 标签属性。

### HTML 标签属性与核心机制

#### 属性语法规范与大小写规则

每个 HTML 元素（标签）不仅能展示内容，还可以通过**属性（Attribute）**来进一步描述该元素的特征、提供补充参数或控制其行为。

属性的基本语法规范如下：
- 属性必须书写在**开始标签**中，紧跟在标签名称之后，用空格隔开；
- 语法格式采用键值对形式：`属性名="属性值"`；
- 属性名与属性值之间使用等号 `=` 连接，属性值必须使用引号包裹（单引号或双引号均可，行业通常约定使用双引号）；
- 一个标签内可以同时承载多个属性，各个属性之间以空格隔开。

例如段落标签可以同时具备类名与唯一标识符：
```html
<p id="describe" class="section">带有属性的段落元素</p>
```

> **易错点**：**HTML 属性名称对大小写不敏感，但属性值对大小写极为敏感！**

我们通过下面三行图像代码的对照实验来直观理解这一点：
```html
<!-- 实例 1：标准小写属性名与小写属性值 -->
<img src="example.jpg" alt="示例图片">

<!-- 实例 2：属性名大写 (SRC)，属性值保持一致 -->
<img SRC="example.jpg" alt="示例图片">

<!-- 实例 3：属性名小写，属性值大写 (EXAMPLE.JPG) -->
<img src="EXAMPLE.JPG" alt="示例图片">
```

在上述代码中：
- 实例 1 与实例 2 的运行结果是完全相同的。虽然实例 2 将属性名写成了大写的 `SRC`，但由于 HTML 解析器对属性名大小写不敏感，浏览器依然能正确识别为资源寻址属性；
- 然而实例 3 与前两者有着本质区别！属性值 `"EXAMPLE.JPG"` 属于文件路径引用。在很多严格区分大小写的 Web 服务器操作系统（如 Linux）中，`example.jpg` 与 `EXAMPLE.JPG` 是两个完全独立的文件。属性值一旦大小写搞错，就会导致资源 404 无法命中。因此，我们必须养成规范的小写书写习惯，并严谨核对属性值的大小写。

此外，HTML 属性分为“大部分标签通用的全局属性”与“特定标签独有的专用属性”：
- 通用属性：如 `class`（为标签定义类名，便于批量挂载 CSS 样式）、`id`（为标签定义在全页面中**唯一**的标识符）、`style`（用于写入内联 CSS 样式）。
- 特殊专用属性：仅针对特定标签生效，最具代表性的当属超链接标签 `<a>` 和图像标签 `<img>`。

#### 超链接标签与跳转行为

超链接标签 `<a>`（Anchor，锚点）常用于实现网页之间的跳转、定位到页面的特定位置，或链接到外部资源。

直接输入 `a` 并按 `Tab` 键，VS Code 会自动生成带有 `href` 属性的骨架：
```html
<a href="https://docs.geeksman.com">这是一个超链接</a>
```

`<a>` 标签有两个最核心的属性：
1. `href`（Hypertext Reference，超文本引用）：定义目标资源的地址。它可以是外部网页的完整 URL（如 `https://docs.geeksman.com`）、本地文件的相对/绝对路径、电子邮箱地址，甚至是电话拨号指令。如果标签中间不写任何文字，浏览器中将没有任何可点击的可视内容；若暂时不需要真实跳转，可以输入 `#` 作为占位锚点。
2. `target`：用于定义目标链接的打开窗口模式。在编辑器中输入 `target` 时，IDE 会给出四个常见候选值：
   - `_self`：**默认值**。链接会在当前所在的窗口或标签页中直接打开并覆盖当前页面；
   - `_blank`：链接会在**新建的窗口或全新标签页**中打开，原网页得以完整保留；
   - `_parent`：在父级窗口或父级框架中打开目标页面；
   - `_top`：跳出所有框架层级，在最顶层的顶层窗口中打开该页面。

```html
<!-- 在新标签页中打开链接 -->
<a href="https://docs.geeksman.com" target="_blank">点击在新标签页打开极客侠文档</a>
```

赋予 `target="_blank"` 属性后，用户点击链接时便不会打断当前页面的浏览体验，这在跳转外部站点时极为常用。

#### 图像标签与媒体资源加载

在网页中嵌入图像需要用到 `<img>` 标签。`<img>` 是一个单标签，输入 `img` 敲击 `Tab` 后，默认会自动生成 `src` 和 `alt` 两个基础属性：

```html
<img src="logo.png" alt="网站徽标" width="200" height="100">
```

我们来逐项拆解图像标签的核心属性：
- `src`（Source）：指定要显示的图像文件的物理存储路径或网络 URL。它可以是位于同一目录下的本地文件（如同级目录下的相对路径 `logo.png`）、多级嵌套路径，也可以是互联网上的网络图片绝对链接。
- `alt`（Alternative Text）：定义图像的“替代文本”。如果因为图片路径拼写错误（例如将 `logo.png` 误写成 `lg.png` 或 `log.png`）、本地文件被误删或者用户网络卡顿导致图片无法成功加载，浏览器就会在原本应该显示图片的位置展示 `alt` 中填写的文字（例如“该图片无法显示”）。这不仅是对视障用户屏幕阅读器的重要无障碍支持，也是网络故障时的优雅降级保障。
- `width` 与 `height`：用于直接在 HTML 标签层级定义图像的宽度与高度（单位通常默认为像素）。例如设置 `width="200"` `height="100"`，浏览器便会将图片严格缩放到指定的几何尺寸中进行呈现。

> **提示**：细心的同学在运行代码时会发现一个有趣的现象：前面的标题 `<h1>`、段落 `<p>`、表格 `<table>` 都是各自霸道地独占整整一行；而我们刚刚写的两个超链接 `<a>`、两张图片 `<img>`，却整整齐齐地紧挨在同一行并排显示！如果想让它们分行，甚至需要我们手动插入换行标签 `<br>` 或分割线 `<hr>`。这背后的渲染规律是什么？这便引出了前端最关键的底层布局概念——块级元素与行内元素。

### 块级元素与行内元素

#### 元素显示特性与嵌套规则

在 HTML 中，所有可见的元素依据其在浏览器中的排版表现形式，天然划分为两大类：**块级元素（Block-level Elements）**与**行内元素（Inline Elements）**。

> **注意**：我们所讨论的“独占一行”，严格是指**在浏览器的渲染窗口中独占一行**，而绝不是指在 VS Code 代码编辑器中把代码写在不同行。即使你在编辑器中把多个块级标签写在同一行，浏览器渲染时它们依然会强行另起一行。

```text
浏览器渲染视图对比:

块级元素渲染 (例如 <div>, <p>, <h1>):
+-------------------------------------------------------------+
| 块级元素 1: 自动占满容器整行宽度 (即使文字只有几个字)       |
+-------------------------------------------------------------+
| 块级元素 2: 强制从新的一行开始，霸占整行                     |
+-------------------------------------------------------------+

行内元素渲染 (例如 <span>, <a>, <img>):
+-------------------------------------------------------------+
| [行内元素1: 依内容收缩] [行内元素2: 紧随其后] [行内元素3...]  |
+-------------------------------------------------------------+
```

上图展示了块级元素与行内元素在浏览器渲染引擎中的几何排布差异。

两类元素的核心技术特征与规则对比详见下表：

| 特性维度 | 块级元素（Block-level） | 行内元素（Inline） |
| :--- | :--- | :--- |
| **起始位置** | 总是从新的一行开始渲染 | 与前一个元素并排排在同一行，直到排满才换行 |
| **宽度表现** | 默认撑满父级容器的整行宽度（100%） | 仅占据自身内容所需的实际宽度，紧凑收缩 |
| **页面角色** | 通常用于搭建页面骨架、组织结构与划分宏观区块 | 通常用于包裹段落局部的词句，做行内微观修饰 |
| **嵌套规则** | **能够包含其他的块级元素以及行内元素** | **严禁包含块级元素**，只能嵌套其他行内元素或纯文本 |
| **常见标签** | `div`、`p`、`h1`~`<h6>`、`ul`、`ol`、`li`、`table`、`form` | `span`、`a`、`strong`、`em`、`b`、`i`、`img`、`br`、`input` |

理解了上述规则，就能明白为什么 `<p>` 里面不能胡乱嵌套 `<div>`，而 `<div>` 内部却可以肆无忌惮地塞入 `<p>`、`<a>` 和 `<img>`。

#### 通用容器划分与布局结构

在熟练掌握语义化标签之后，我们在实际工程开发中打交道最多的，反而是两个“完全没有语义”的通用容器标签：块级容器 `<div>` 与行内容器 `<span>`。

`<div>` 的全称是 Division（分区、划分）。它是一个最纯粹的块级元素，标签本身没有任何预设的样式，也不带有任何特定语义，它的天职就是**充当布局容器**。在现代网页架构中，页面通常被清晰地划分为不同的功能板块，例如顶部的页眉与导航栏（Navigation Bar）、侧边栏、中间的主体内容区域（Content）、底部的页脚（Footer）等。这些宏观大块通常统一采用 `<div>` 进行包裹和隔离。

在 VS Code 中创建 `<div>` 时，Emmet 提供了极速简写语法：
- 输入 `.类名` 按 `Tab`：自动生成带有 class 的 div。例如输入 `.nav` 敲击 `Tab`，即刻生成 `<div class="nav"></div>`（亦可完整输入 `div.nav`）；
- 输入 `#id名` 按 `Tab`：自动生成带有唯一 id 的 div。例如输入 `#nav` 敲击 `Tab`，即刻生成 `<div id="nav"></div>`（亦可完整输入 `div#nav`）。

我们来看一个利用 `<div>` 构建页面宏观布局的典型代码片段：

```html
<!-- 顶部导航栏区块 -->
<div class="nav">
  <a href="#">首页</a>
  <a href="#">课程列表</a>
  <a href="#">技术文档</a>
  <a href="#">用户中心</a>
  <a href="#">关于我们</a>
</div>

<hr>

<!-- 主体内容区块 -->
<div class="content">
  <h1>精选文章标题</h1>
  <p>这是文章的第一段叙述内容，由标准的段落标签包裹。</p>
  <p>这是文章的第二段叙述内容，承载主体技术逻辑。</p>
  <p>这是文章的第三段叙述内容，展示总结性论述。</p>
</div>
```

与 `<div>` 遥相呼应的则是 `<span>`。`<span>` 是行内元素中最纯净的无语义容器。你可以把它理解为一个“既没有链接跳转功能的 `<a>` 标签，也没有图片展示功能的 `<img>` 标签”。它的核心价值在于：**把一段大段文本中的极少数几个词句单独挑出来打上包装**，以便在未来的 CSS 学习中为这几个词精准涂抹特定的颜色、字体，或者利用 JS 绑定专属的点击动效。

```html
<p>
  这是一段普通的文章描述，我们可以在行内使用 
  <span>被包装的重点短语</span> 
  来实施独立修饰，甚至在行内嵌入 
  <a href="#">直达外部详情的超链接</a>。
</p>
```

总结而言：`<div>` 负责在宏观世界里“圈地建房”，构建整齐划一的排版区块；`<span>` 负责在微观行内“划重点”，为精细化修饰铺路。二者在后续结合 CSS 与 JS 时，将迸发出巨大的工程能量。

### HTML 表单与交互控件

#### 表单容器与数据提交机制

网页不仅用于单向向用户输出信息，更重要的是允许用户向网站输入并提交数据，这正是通过 **HTML 表单（Form）** 来实现的。

表单在互联网产品中无处不在：
- 招聘求职网站上的全局搜索框，属于表单；
- 在职位列表页按城市与行政区进行筛选（例如点击“上海”后联动选择“徐汇区”），属于表单；
- 用户登录注册页面：输入 11 位手机号码、获取并输入短信验证码、勾选用户服务协议复选框、最后点击“立即登录”大按钮，这一整套完整的工作流，全都是表单的经典应用。

在 HTML 中，所有参与交互与收集数据的输入控件，必须统一包裹在 `<form>` 表单根容器内部：

```html
<form action="#" method="get">
  <!-- 内部包裹各类输入框、单选、多选与提交按钮 -->
</form>
```

`<form>` 标签自带一个最为核心的属性——`action`。`action` 用于指定当用户点击提交按钮后，**表单中所收集的这批数据究竟应该发送到何处**。因此，`action` 的属性值必须是一个合法的目标 URL 地址，指向后端服务器所提供的 API 接口。

> **提示**：在前端初期学习阶段，我们尚未搭建后端服务器与数据库，没有真实的后端接收接口。此时切忌在 `action` 中胡乱填写地址，而是应该直接输入一个井号 `#`（即 `action="#"`）。这能让页面保持在当前视图，起到锚点占位和防止页面刷新跳转的作用。

#### 输入控件类型与状态配置

在 `<form>` 内部，使用频率最高的核心标签是输入标签 `<input>`。`<input>` 是一个单标签，拥有几十种可选属性，但其灵魂所在在于 **`type` 属性**。`type` 决定了这个输入框以何种形态和控件逻辑呈现在用户面前：

```html
<!-- 1. 单行文本输入框 -->
<input type="text" placeholder="搜索职位和公司">

<!-- 2. 预置真实值的文本输入框 -->
<input type="text" value="请输入内容">

<!-- 3. 密码掩码输入框 -->
<input type="password" placeholder="请输入密码">

<!-- 4. 单选框 (互斥组) -->
<input type="radio" name="gender"> 男
<input type="radio" name="gender"> 女
<input type="radio" name="gender"> 其他

<!-- 5. 多选复选框 -->
<input type="checkbox" name="hobby"> 唱歌
<input type="checkbox" name="hobby"> 跳舞
<input type="checkbox" name="hobby"> rap
<input type="checkbox" name="hobby"> 篮球

<!-- 6. 表单提交按钮 -->
<input type="submit" value="上传">
```

我们深入剖析这几种核心 `type` 及其配合属性：

1. **普通单行文本框（`type="text"`）**：这是默认类型。用户可以在其中键入任意字符。
   - `placeholder` 属性：占位提示符。例如招聘网站搜索框里浅灰色的“搜索职位和公司”。当输入框处于空白状态时显示，一旦用户点击并开始输入文字，提示文字立即自动隐匿；清空文字后又会优雅复原。
   - `value` 属性：规定该 input 元素的**实际预设值**。注意它与 `placeholder` 的本质区别：`placeholder` 仅仅是视觉提示，不计入表单数据；而 `value` 中写入的内容是真实填充在输入框里的数据，如果不清空，提交表单时会直接打包发送给后端。

2. **密码输入框（`type="password"`）**：用户输入的账号用户名通常以明文展示，但密码绝不能明文暴露在屏幕上。将 `type` 设为 `password` 后，用户在键盘上敲入的每一个字母和数字，在浏览器界面中都会自动被黑圆点或星号遮盖掩码，杜绝旁人窥探。

3. **单选框（`type="radio"`）**：用于在互斥选项中只选其一（例如性别选择：男、女、其他）。
   - **关键互斥机制**：很多初学者在写单选框时，发现自己可以同时勾选“男”和“女”，完全丧失了单选意义！这是因为缺少了 `name` 属性。
   > **注意**：要想实现真正的互斥单选，**同一逻辑组内的所有单选 input 标签，必须配置完全相同的 `name` 属性值**（例如全部指定 `name="gender"`）。浏览器正是通过识别相同的 `name`，才将它们归入同一单选池实现“选此退彼”的互斥效果。

4. **多选复选框（`type="checkbox"`）**：允许用户在一个集合中同时勾选零个、一个或多个选项。例如收集用户的爱好：唱歌、跳舞、rap、篮球。与单选框类似，属于同一分类属性的多选框也建议赋予一致的 `name` 属性（如 `name="hobby"`），便于后端统一接收数组型数据。

5. **提交按钮（`type="submit"`）**：专门用于触发表单提交行为的功能控件。点击该按钮后，浏览器会自动将当前 `<form>` 内部所有带有 `name` 属性的控件数据，打包发送给 `action` 所指向的服务器接口。
   - 浏览器默认渲染的按钮文字是“提交”；
   - 若我们希望将按钮文字自定义为其他文案（例如“上传”、“立即注册”、“登录”），只需在标签内添加 `value` 属性，例如 `value="上传"`，即可覆盖默认文案。

#### 表单文本标注与字段绑定

在实际构建登录页面时，文本框前方往往会标明“用户名”、“密码”等文字标签。如果我们仅仅在输入框前放一个普通的 `<span>` 标签，虽然视觉上并无二致，但在底层逻辑上它与后面的输入框没有任何关联。

HTML 表单提供了专属的标注标签——`<label>`。`<label>` 标签不仅提供语义化的字段说明，更重要的是它支持通过 `for` 属性与目标控件的 `id` 属性进行深度绑定：

```text
+-------------------------------------------------------------+
|  <label for="username"> 用户名 </label>                     |
|         │                                                   |
|         └── 逻辑指向相同的唯一标识 ────────────────┐         |
|                                                    ▼        |
|  <input type="text" id="username" name="username"> [ 输入框 ]|
+-------------------------------------------------------------+
```

上图展示了 `<label>` 的 `for` 属性与 `<input>` 的 `id` 属性之间的绑定映射。

绑定机制的实操代码如下：
```html
<label for="username">用户名：</label>
<input type="text" id="username" name="username" placeholder="请输入用户名">

<br><br>

<label for="pwd">密 码：</label>
<input type="password" id="pwd" name="password" placeholder="请输入密码">
```

在此处的技术细节中：
- `<label for="username">` 中的 `for` 取值必须精确等于输入框的 `id="username"`；
- 密码输入框的 `id` 设定为 `pwd`，对应的 `<label for="pwd">` 形成一对一绑定。
- 需要再次厘清 `id` 与 `name` 的定位区别：`id` 具有全页面绝对唯一性，专职负责被 `label` 绑定或供 CSS/JS 寻址；而 `name` 则是向服务器发送数据时的键名（Key），同时用于控制单选框的互斥分组。

最后，我们将本模块所学的所有表单组件融会贯通，写成一个结构完备、语义清晰的用户注册表单实战范例：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>用户注册表单实战</title>
</head>
<body>

  <!-- 表单容器：action 使用 # 占位防跳转 -->
  <form action="#">
    
    <!-- 账号字段 -->
    <label for="username">用户名：</label>
    <input type="text" id="username" name="username" placeholder="请输入用户名">
    
    <br><br>

    <!-- 密码字段 -->
    <label for="pwd">密　码：</label>
    <input type="password" id="pwd" name="password" placeholder="请输入密码">
    
    <br><br>

    <!-- 单选字段：通过统一的 name="gender" 实现互斥 -->
    <label>性　别：</label>
    <input type="radio" name="gender" value="male"> 男
    <input type="radio" name="gender" value="female"> 女
    <input type="radio" name="gender" value="other"> 其他
    
    <br><br>

    <!-- 多选字段：通过统一的 name="hobby" 归组 -->
    <label>爱　好：</label>
    <input type="checkbox" name="hobby" value="sing"> 唱歌
    <input type="checkbox" name="hobby" value="dance"> 跳舞
    <input type="checkbox" name="hobby" value="rap"> rap
    <input type="checkbox" name="hobby" value="basketball"> 篮球
    
    <br><br>

    <!-- 表单提交按钮：自定义文案为“上传注册信息” -->
    <input type="submit" value="上传注册信息">
    
  </form>

</body>
</html>
```

至此，从网页的基本呈现机理、VS Code 高效开发工具链的搭建，到 HTML 常用文本与骨架标签、标签属性运作规律、块级与行内元素底层排版差异，再到可交互的表单输入体系，整个 HTML 模块的核心知识脉络全部理清。打牢了这份清晰的骨架，我们在下一模块为页面注入色彩与排版（CSS）时，才能游刃有余。

## CSS选择器、常用属性与盒模型浮动
> 对应块：BLK02 | 覆盖分集：P08-P12

学习完 HTML 之后，我们接着来学习 CSS。纯粹依靠 HTML 搭建出来的网页，只有最基础的文字、输入框与多媒体排布，视觉呈现十分简陋。如果希望网页具有赏心悦目的色彩、优雅舒适的排版以及井然有序的结构，就必须由 CSS 出场接管视觉设计。CSS 赋予了开发者精准控制页面每一个像素外观的能力，是前端界面开发的核心支柱。

### CSS核心概念与引入方式

#### 网页结构与装修隐喻

CSS 的全称是层叠样式表（Cascading Style Sheets）。从定位上看，CSS 是一种专门用于定义网页样式和布局的样式表语言。在现代 Web 开发的职责划分中，HTML 与 CSS 始终紧密结合、相辅相成：HTML 专门负责定义页面的“结构和内容”，而 CSS 则全权负责控制页面的“外观和样式”。

我们可以借助盖房子的过程来建立一个直观的认知模型：

```text
+-------------------------------------------------------------+
|                      现代网页构建模型                       |
+-------------------------------------------------------------+
|  HTML (骨架与框架) : 承重墙、门窗孔洞、楼梯、房间物理隔断   |
|  CSS  (精装与美化) : 墙面色彩、吊灯造型、窗框线条、家具陈列 |
+-------------------------------------------------------------+
```

上图直观展示了 HTML 与 CSS 在网页构建中的职能协同：HTML 构筑不可或缺的基础框架，CSS 负责全方位的精装与美化。

当我们规划一栋住宅时，首先需要用钢筋混凝土浇筑出房屋的主体骨架。承重墙立在何处、房门开在哪个方位、窗户留在哪面墙上、楼梯如何通向二楼，这些最基本的物理空间结构全部由 HTML 来定义。毛坯骨架落成后，房子显然还不适合直接舒适居住，接下来必须进场施工的是室内装修工程。我们想把客厅墙面刷成天蓝色还是纯白色、主卧吊灯挑选何种几何造型、窗框采用木质还是金属质感、沙发与茶几在地面如何摆放，这一整套视觉与布局设计，对应的正是 CSS 样式的职责。

如果想要构建出令人赏心悦目的现代网页，骨架和装修缺一不可。通过 CSS，我们可以精准指定页面中各个元素的文字颜色、字号尺寸、行间距、边框纹理、背景图案以及空间间距，从而让原本生硬的文档转变为生动的数字化界面。

#### CSS基本语法与声明规则

建筑工程有着严格的行业建筑规范，编程语言同样具备严密的语法体系。一条最基础的 CSS 规则通常由两个核心部分构成：**选择器（Selector）**以及紧随其后的**声明块（Declaration Block）**。

```text
选择器 {
    属性名1: 属性值1;
    属性名2: 属性值2;
}
```

上图展示了 CSS 规则的基本语法范式：选择器负责定位目标，大括号内的声明块负责定制样式细节。

选择器后面跟随着一对花括号 `{}`，花括号内部包裹的所有内容统称为该选择器的“声明”。在声明块内部，我们可以书写任意多条具体的样式规则，但每一条规则都必须严格遵循“键值对”的组织形式：

> **定义**：CSS 声明采用 `属性名: 属性值;` 的格式书写，冒号用于分隔属性与属性值，每条声明末尾必须以英文半角分号 `;` 闭合。

我们通过一个最基础的段落样式定义来剖析其执行逻辑：

```css
p {
    color: blue;
    font-size: 16px;
}
```

在这段代码中：
1. `p` 是元素选择器，明确告知浏览器接下来这组样式要施加给页面中所有的 `<p>` 段落标签；
2. 内部包含两条独立的声明：第一条属性名为 `color`，对应属性值为 `blue`，作用是将段落文字的前景色染成纯正的蓝色；第二条属性名为 `font-size`，对应属性值为 `16px`，作用是将段落文字的大小显式设定为 16 像素；
3. 只要页面被浏览器解析渲染，所有的 `<p>` 元素都会同时接收这两项样式规则。

在开发工具（如 VS Code）的日常编码实践中，借助 Emmet 智能代码补全可以大幅提升书写效率。例如想要编写 `font-size` 属性时，无需逐个敲入全部字母，只需在选择器内部键入缩写 `fs`，编辑器便会自动弹出代码建议，敲击回车即可直接补全为 `font-size: ;`。若要临时屏蔽某段样式以对比渲染差异，可以选中对应的代码行并按下快捷键 `Ctrl + /`，代码就会被快速包裹为 CSS 注释语法 `/* ... */`。如果发现将段落字号设置为默认的 16 像素在视觉上并不明显，我们可以随手调整为 `26px`，保存后刷新页面即可直观看到字体显著放大的变化。

#### 三种引入方式与工程实践

为了让 CSS 样式真正作用于 HTML 文档，我们需要通过特定的技术途径将二者连接起来。在 CSS 规范中，引入样式表主要存在三种经典方式，分别适用于不同的开发场景：

| 引入方式 | 书写位置 | 核心语法特征 | 适用场景 |
| :--- | :--- | :--- | :--- |
| **内联样式**（行内样式） | 目标 HTML 开始标签内部 | 通过标签的原生 `style` 属性直接赋值 | 临时调试或修改极个别特异元素的样式 |
| **内部样式表** | HTML 文档的 `<head>` 头部区域 | 嵌套在独立的 `<style>` 双标签内 | 独立单页面练习或轻量级 Demo 页面 |
| **外部样式表** | 独立的 `.css` 物理文件 | 在 `<head>` 中通过 `<link>` 标签链接引入 | 商业项目开发与跨页面样式复用规范 |

第一种是**内联样式（Inline Style，又称行内样式）**。几乎所有的 HTML 元素标签都原生支持一个通用的 `style` 属性。我们可以直接将样式声明写入该属性内：

```html
<h1 style="color: red;">这是一个应用内联样式的一级标题</h1>
```

内联样式的优势在于简单粗暴、所见即所得，但缺陷同样致命：样式与结构高度交织纠缠，如果页面有数十个相同样式的标题，开发者必须机械地复制数十次代码，极难维护。

第二种是**内部样式表（Internal Style Sheet）**。它将样式从标签本体中剥离出来，统一收拢到 HTML 文档的 `<head>` 区域，写在 `<title>` 标签正下方的 `<style>` 标签内：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
    <meta charset="UTF-8">
    <title>内部样式表示例</title>
    <style>
        h2 {
            color: green;
        }
    </style>
</head>
<body>
    <h2>这是一个应用内部样式的二级标题</h2>
</body>
</html>
```

这种做法初步实现了当前页面内结构与样式的解耦，我们在下方 `<body>` 中书写内容时无需关心样式细节，所有的视觉控制统一在文档顶部集中管理。

第三种是**外部样式表（External Style Sheet）**，这是正规项目开发中绝对推荐的标准形态。在大型 Web 应用中，站点通常包含几十甚至上百个网页，若各个页面的导航栏、通用按钮和页脚都需要使用统一的视觉标准，内部样式表便无能为力。我们不可能把成千上万行样式复制到每一个 HTML 页面中，一旦品牌主色调变更，重构工作将苦不堪言。

外部样式表彻底终结了这种重复冗余。它的实施步骤非常规范：
1. 在项目源码根目录中建立一个专门的目录，通常命名为 `css`，用于收拢管理所有样式文件；
2. 在该目录下新建一个纯文本样式文件，以 `.css` 为后缀名，例如 `style.css`；
3. 在 `style.css` 内部无需编写任何 HTML 标签或 `<style>` 容器，直接书写纯粹的 CSS 规则：

```css
/* css/style.css */
h3 {
    color: purple;
}
```

4. 在需要应用该样式的 HTML 文档的 `<head>` 内部，使用单标签 `<link>` 将该外部样式文件接入：

```html
<link rel="stylesheet" href="css/style.css">
```

> **提示**：`<link>` 标签中的 `rel` 属性代表关系（Relationship），取值 `stylesheet` 明确告知浏览器当前引入的是一份样式表文件；`href`（Hypertext Reference）属性则填入样式文件的物理存储路径，通常推荐使用清晰的相对路径（如 `css/style.css`）。

借助外部样式表，多个页面可以共同链接同一份样式源文件。当需要统一调整全站配色时，只需在 `style.css` 中修改一行代码，全站所有页面立刻同步生效，这正是软件工程中“高内聚、低耦合”设计原则在前端开发中的最佳落地。

#### 样式引入优先级与覆盖机制

当同一个 HTML 元素同时被内联样式、内部样式表以及外部样式表锁定时，浏览器究竟会听从谁的指挥？这引出了 CSS 中极为重要的“优先级覆盖机制”。

> **结论**：在常规规则下，不同样式引入方式的优先级高低排序为：**内联样式 > 内部样式表 > 外部样式表**。优先级高的样式规则将无条件覆盖优先级低的同名属性规则。

我们可以设计一组环环相扣的实验来推导并验证这一链条：

1. **外部与内部的博弈**：假设我们在外部样式表 `css/style.css` 中将 `<h3>` 的文字颜色设置为 `purple`（或 `yellowgreen`）；此时在 HTML 的 `<head>` 内部样式表 `<style>` 中，同样针对 `h3` 补充一条声明 `color: aqua;`。保存并在浏览器中观察，标题文字立刻呈现为明快的天蓝色（aqua），原本外部样式表赋予的颜色被彻底覆盖。这证明内部样式表能够压制外部样式表。
2. **内联样式的绝对压制**：接下来，我们直接在该 `<h3>` 标签本体上添加行内样式 `<h3 style="color: red;">`。刷新页面后，原本的天蓝色瞬间被抹去，文字显现出刺目的纯红色。这证明内联样式凌驾于内部样式表之上。
3. **低优先级无法反向越级**：反过来，对于原生书写了 `<h1 style="color: red;">` 的一级标题，无论我们在内部样式表 `<style>` 还是外部文件 `style.css` 中怎样尝试书写 `h1 { color: white; }`，页面中的 `h1` 依然死守红色，低优先级的规则在面对高优先级规则时毫无招架之力。

### CSS选择器体系与匹配机制

#### 基础选择器与语法规则

选择器是整个 CSS 语法的引导者与调度核心。在日常开发中，单凭元素标签名往往无法应对精细化、差异化的界面设计诉求。最常用的四大基础选择器构成了选择器大厦的基石：

```text
基础选择器分类与标识符:
1. 元素选择器 : 标签名直接定位 (如 h2)
2. 类选择器   : 英文句点前缀 (如 .highlight)
3. ID选择器   : 井号前缀 (如 #header)
4. 通用选择器 : 单个星号 (如 *)
```

上图梳理了四大基础选择器的标识符语法：通过前缀符号的差异，浏览器得以在 DOM 树中建立不同维度的节点匹配逻辑。

第一种是**元素选择器（又称标签选择器）**。它直接以 HTML 标签名称挂载：

```css
h2 {
    color: aqua;
}
```

元素选择器的匹配策略是“全员通选”。页面中出现的每一个 `<h2>` 元素都会无差别染上天蓝色。它适合用于定义某些全局通用的基准排版样式。

第二种是**类选择器（Class Selector）**。如果我们页面上有两个并列的 `<h3>` 标签，但业务需求明确要求：第一个标题必须带有鲜明的黄色背景以示高亮，而第二个标题必须保持常规底色。此时元素选择器显然会误伤全局，必须改用类选择器。

类选择器的使用分为两步：首先在 HTML 标签中通过 `class` 属性赋予其一个或多个类名标识符；随后在 CSS 中以**英文句点 `.`** 作为前缀后接类名进行精确定位：

```html
<h3 class="highlight">这是一个应用类选择器的示例</h3>
<h3>这是另一个普通的类选择器示例</h3>
```

```css
.highlight {
    background-color: yellow;
}
```

在 Emmet 快捷输入中，我们只需键入 `h3.highlight` 并按下回车，编辑器便会自动展开为 `<h3 class="highlight"></h3>`。类名可以根据业务含义自由起名（如 `nav-item`、`btn-primary` 等）。同一个类名可以同时挂载在多个不同的元素上，从而实现样式模块的按需复用。

第三种是**ID选择器（ID Selector）**。如果页面中某个特定区域具有唯一的排版特征，我们可以为标签绑定一个 `id` 属性，并在 CSS 中以**井号 `#`** 开头进行选中：

```html
<h4 id="header">这是一个应用 ID 选择器的示例</h4>
```

```css
#header {
    font-size: 35px;
}
```

在 VS Code 中，输入 `h4#header` 敲击 Tab 键即可快速生成对应标签。尽管类选择器和 ID 选择器在语法上非常对称，但两者的工程定位截然不同：在规范的 HTML 架构中，同一个 `id` 在单个网页文档中应当是唯一的，就像公民的身份证号码；而 `class` 则相当于群组标签，允许多个元素共同拥有。

第四种是**通用选择器（Universal Selector，通配符选择器）**。它使用单个**星号 `*`** 来声明，意味着无条件命中页面中的一切 HTML 元素：

```css
* {
    font-family: "楷体";
    font-weight: bolder;
}
```

通用选择器常用于页面初始化阶段，例如将全站所有文本的字体统一设置为指定的中文字体系列（如 `"楷体"`，注意中文字体名称需要用引号包裹），或者统一定制全站的字体粗细 `font-weight: bolder;`。

#### 子代与后代的关系推导

在真实的网页 DOM 树中，标签与标签之间存在着错综复杂的嵌套关系。外层容器包裹着内层容器，大标签嵌套着小标签，这种嵌套关系在技术上被自然抽象为父子亲属链条：处于外层的容器相对于其直接内部标签被称为“父元素”，而被包裹的内层标签则被称为“子元素”。

面对多层嵌套结构，CSS 提供了两种名字相近但匹配机理存在根本差异的选择器：**子元素选择器（子代选择器）**与**后代选择器（包含选择器）**。

为了讲透二者的差异，我们构造一个具有三层嵌套的典型结构模型：

```html
<div class="father">
    <p class="son">这是一个子元素选择器示例</p>
    <div>
        <p class="grandson">这是一个后代选择器示例</p>
    </div>
</div>
```

我们用一张树状拓扑图来具象化展示这套 DOM 嵌套关系与亲属代际映射：

```text
           div.father (祖父 / 父代)
           /        \
          /          \ (直接子节点)
         v            v
      p.son        div (中间容器)
   (直接儿子)         |
                      v (直接子节点)
                  p.grandson
               (孙子辈 / 间接后代)
```

上图展示了三层嵌套标签的家族代际映射：`p.son` 属于 `father` 的直接子代，而深层嵌套在内层容器中的 `p.grandson` 属于孙代，二者对于最外层的 `father` 而言分属于不同代际。

在上面的结构中：
- `.father` 是最外层的大容器；
- `p.son` 直接裸露在 `.father` 内部第一层，它是 `.father` 的亲生儿子（子代）；
- 内层的 `<div>` 同样是 `.father` 的亲生儿子，但这个内部 `div` 内部包裹的 `p.grandson`，相对于最外层的 `.father` 而言，则是名副其实的“孙子”；
- 换句话说，`p.son` 与 `p.grandson` 之间其实是一对“叔侄关系”。

明确了代际划分后，两者的语法与匹配边界便一目了然：

**子元素选择器**采用**尖括号（大于号 `>`）**连接，其严格的匹配法则为：**只选择直接位于父元素内部的第一代亲生子节点**：

```css
.father > .son {
    color: yellowgreen;
}
```

如果我们将子选择器写为 `.father > p`，页面中只有直接作为子代的 `p.son` 会被染成黄绿色；而那个深埋在内层 `div` 内部的 `p.grandson` 绝不会产生任何变化，因为它是孙子，根本不在直接子代的管辖范围内。

**后代选择器**则直接采用**单个空格**作为连接符，其核心法则为：**包含目标父容器内部的所有后代节点，无论是儿子、孙子、重孙，一律全盘选中**：

```css
.father p {
    color: brown;
    font-size: larger;
}
```

> **结论**：后代选择器在范围上是包含子代选择器的。后代涵盖了所有子代与更深层的衍生代际；而子代仅仅精确框定在父容器直接挂载的第一层级。

此处还隐藏着一个极为经典的权重匹配陷阱：假设我们同时在样式表中书写了后代选择器 `.father p { color: brown; }` 以及子代选择器 `.father > .son { color: yellowgreen; }`。由于在 CSS 权重计算规则中，类选择器的优先级高于纯元素选择器（`ID > 类 > 标签`），带有 `.son` 类名的子选择器具有更高的选择特异性，因此第一层的段落稳固地保持为黄绿色，而后代选择器则顺利渗透并染红了深层的孙子标签 `p.grandson`。

#### 相邻兄弟与亲属关系选择

除了纵向的父子后代关系，DOM 树在同一个容器内部还存在大量并列平级的“兄弟关系”。针对处于同一层级、拥有相同父节点的元素，CSS 提供了**相邻兄弟选择器（Adjacent Sibling Selector）**。

相邻兄弟选择器采用**加号 `+`** 作为连接符。我们通过实际的 HTML 序列来进行实验推演：

```html
<p>这是一个处于上方的普通段落</p>
<h3>这是一个作为基准的相邻兄弟选择器示例</h3>
<p>这是紧跟在标题下方的一个段落</p>
<p>这是距离标题更远的第三个段落</p>
```

现在我们为其附加一条样式规则：

```css
h3 + p {
    background-color: red;
}
```

刷新浏览器后，呈现出的视觉效果极具规律性：处于 `<h3>` 正上方的那一个 `<p>` 没有颜色；紧随在 `<h3>` 正下方、紧紧挨着它的那一个 `<p>` 被准确赋予了醒目的红色底色；而更靠下方的第三个 `<p>` 同样不受任何影响。

> **注意**：相邻兄弟选择器具有严格的**同级紧跟、单向向下**的匹配准则：它只会在相同父级层面的兄弟元素中，精确选中紧跟在指定目标元素之后的**第一个**符合条件的兄弟节点。

#### 伪类与伪元素状态机制

在常规的选择器体系中，我们都是针对 HTML 文档中客观存在的静态标签属性进行锁定。然而在现代网页应用中，元素会频繁遭遇用户交互或处于特定的文档结构位次，这种依赖于环境状态的特殊样式，需要由伪类与伪元素共同支撑。

**伪类选择器（Pseudo-classes）**以**单冒号 `:`** 作为标识前缀。它专门用于捕捉 HTML 元素的特定状态、特定用户交互行为或特定的文档位置关系：

```html
<h3 id="element">这是一个应用伪类选择器的交互示例</h3>
```

```css
#element:hover {
    background-color: purple;
}
```

在这段代码中，`:hover` 代表鼠标指针悬停在元素上方时的交互瞬态。在浏览器中预览时，默认状态下该标题没有特殊底色；一旦我们将鼠标光标移动到文字区域上方停留，标题所在的整行瞬间被激发出深邃的紫色底色；光标一旦移开，背景立刻优雅褪去恢复原状。

除了 `:hover` 这一高频交互伪类，伪类家族还广泛覆盖结构与激活状态：
- `:first-child`：专门命中其父容器内部的第一个子元素，常用于清除列表中首个项的顶部分割线；
- `:nth-child(n)`：通过传入数字或公式精准锁定父容器内指定序列的第 $n$ 个子元素，实现斑马线相间排版；
- `:active`：当超链接、按钮等被用户鼠标按下但尚未松开时的物理激活瞬态。

**伪元素选择器（Pseudo-elements）**则以**双冒号 `::`** 作为标识前缀。与伪类不同，伪元素不是去选择已有的实体节点，而是在 DOM 树之外凭空构造出一个看不见的“虚拟占位节点”，并允许开发者对其施加任意样式控制：

```text
+-----------------------------------------------------------+
|                      伪元素插入机制                       |
+-----------------------------------------------------------+
|  [ ::before 虚拟节点 ] -> 实际文本内容 -> [ ::after 虚拟节点 ] |
+-----------------------------------------------------------+
```

上图展示了伪元素的空间插入逻辑：`::before` 锚定在内容前端，`::after` 锚定在内容末尾，二者均为虚拟生成的渲染节点。

最典型的伪元素当属 `::before` 与 `::after`。它们能够以纯 CSS 的手段，在被选中元素的实际内容最前面或最后面注入虚拟内容（通常需要配合 `content` 属性）。伪元素机制彻底避免了为了某些微小的修饰图标而向 HTML 结构中堆积无意义的垃圾空标签，在后续解决浮动塌陷等工业级场景中更承载着核心底座价值。

### 文本样式与元素显示模式

#### 字体文本属性与复合属性语法

CSS 属性浩如烟海，在主流开发文档或规范手册中收录的属性多达上百个。但对于初学者而言，绝无必要陷入死记硬背的死胡同。在真实的日常开发中，真正高频调用的核心基础属性不过数十个，其余绝大多数属性要么使用频次极低，要么功能高度细分。

在这些常用属性中，文本与字体相关的控制是每个界面最基础的构成单元：
- `color`：定义文本前景色，支持英文色彩单词（如 `aqua`, `yellowgreen`）、十六进制色彩值（如 `#ff0000`）或 RGB 格式（如 `rgb(255, 0, 0)`）；
- `font-size`：定义文字尺寸字号，可以传入标准像素值（如 `16px`, `50px`），也可以传入语义化关键字（如 `larger`）；
- `font-family`：定义文字所采用的字体族。中文字体名称（如 `"楷体"`, `"微软雅黑"`）在声明中必须用半角引号包裹；
- `font-weight`：定义文字字重笔画粗细，常用属性值包括 `normal`（常规）、`bold`（加粗）、`bolder`（特粗）。

在学习这些细分属性时，必须重点掌握 CSS 中至关重要的机制——**复合属性（Shorthand Property，简写属性）**。

> **定义**：复合属性允许开发者通过单个属性名称，同时向其传入多个按照特定规则空格隔开的属性值，从而一条语句打包设置多个分散的样式特征。

以最典型的 `font` 复合属性为例，如果我们希望为一个标题同时指定加粗笔画、50 像素超大字号以及楷体字形，传统的写法需要分散声明三行代码：

```css
h1 {
    font-weight: bolder;
    font-size: 50px;
    font-family: "楷体";
}
```

而利用 `font` 这一复合属性，代码可以高度提炼为单行声明：

```html
<h1 style='font: bolder 50px "楷体";'>这是一个 font 复合属性示例</h1>
```

浏览器能够智能识别出这条复合声明中各个参数的物理归属：将 `bolder` 派发给字重，将 `50px` 派发给尺寸，将 `"楷体"` 派发给字体系列。这种复合属性不仅大幅减少了代码冗余，更能显著增强样式书写的凝练度与可读性。

#### 行高调节与排版透气感

长篇幅文本在网页中的视觉呈现，不仅取决于字体大小，更深受垂直行距的深刻影响。为此，CSS 提供了专门用于控制基准行间距的核心属性：`line-height`（行高）。

当一段较长的文本在有限宽度的容器内自动折成多行显示时，如果不加干预，浏览器默认计算出的基准行距往往非常局促，上一行的文字底边紧贴着下一行的文字顶头，整段内容密密麻麻挤压在一起，带来极其强烈的压抑感与阅读疲劳。

我们可以通过设置显式的行高来重构版面的透气感：

```html
<p style="line-height: 40px;">
    这是一段非常冗长的连续长文本。当我们在有限的窗口宽度内排版阅读时，如果行与行之间挨得过紧，
    视觉体验会极其沉闷压抑。通过为文本容器施加充足的行高设定，原本局促拥挤的排版能够瞬间舒展开来，
    在字里行间营造出极具现代设计审美的留白与呼吸感。
</p>
```

将 `line-height` 设定为 `40px` 后，浏览器会以 40 像素为基准分配每一行文字的垂直高度，行与行之间的间距被均匀而自然地撑开，原本拥挤密闭的文字方阵立刻变得舒展易读。

#### 元素三态与显示模式差异

在深入网页布局之前，必须彻底击穿 HTML 元素的“显示模式（Display Types）”。在早期的 HTML 基础学习中，我们已经接触过块级元素与行内元素的基本划分，而在 CSS 布局中，真实世界的元素呈现出更加立体的“三态”格局：

| 元素显示模式 | 典型标签代表 | 排布规则与独占特性 | 宽高与内外边距可控性 | 容器嵌套容纳能力 |
| :--- | :--- | :--- | :--- | :--- |
| **块级元素**（Block） | `<div>`, `<h1>`-`<h6>`, `<p>` | 始终自起新行，默认横向独占一整行宽度 | 可自由显式设定 `width` 与 `height`，完全支持内外边距 | 可容纳其他块级元素与行内元素 |
| **行内元素**（Inline） | `<span>`, `<a>` | 水平并排排列在同一行，不单独起行 | **无法直接设置宽高**（宽高由内部文本被动撑开） | 严禁容纳块级元素，仅可容纳文本或行内元素 |
| **行内块元素**（Inline-block） | `<img>`, `<input>` | 水平并排排列在同一行，遇父级边界自动折行 | 可自由显式设定 `width` 与 `height`，完全支持内外边距 | 可自由容纳其他行内或块级元素 |

我们通过代码对比来验证三者的物理表现差异：

```html
<div class="block">这是一个块级元素 (div)</div>
<span class="inline">这是一个行内元素 (span)</span>
<img class="inline-block" src="logo.png" alt="图片">
```

```css
.block {
    background-color: lightgray;
    width: 150px;
    height: 100px;
}

.inline {
    background-color: yellow;
    width: 200px;  /* 无效设置 */
    height: 200px; /* 无效设置 */
}

.inline-block {
    width: 100px;
    height: 100px;
}
```

在上面的实验中：
1. `.block` 作为块级元素，不仅被准确限制在宽 150 像素、高 100 像素的矩形框内，而且它的下方被强制隔断，绝不允许后续的任何元素跟它挤在同一行；即使把宽度缩小到 150px，它右侧的空白区域仍然被其独占；
2. `.inline` 作为行内元素，虽然在 CSS 中气势汹汹地写下了宽 200px、高 200px，但浏览器在渲染时完全无视这两条宽高指令，其黄色背景的大小仅仅紧紧裹住内部那几个文字本身；
3. `<img>` 作为天生的行内块元素，既能够跟其他行内元素排在同一行水平相连，又能够严格遵照开发者的指令被精确缩放为 100×100 的方块。如果不定义高度只给宽度，图片会等比例缩放；若同时定义了不成比例的宽高，图片就会被拉伸变形。在各大电商平台的商品陈列瀑布流中，这种需要横向并排、同时又必须规整限定尺寸的商品卡片，正是行内块特性的经典舞台。

#### 元素显示模式转换机制

如果页面中的商品卡片仅仅是一张图片，原生 `<img>` 标签自然能够轻松胜任；但在真实的业务开发中，商品卡片是一个复合容器，里面既有产品主图，又有商品标题、价格标签以及抢购按钮。负责包裹这些复杂内容的通常是语义中立的 `<div>` 或 `<span>`。

这就带来了一个严峻的矛盾：`<div>` 是块级元素，默认会横向独占一整行，两个 `div` 卡片根本无法在一行并排陈列；而 `<span>` 虽然能够在一行并排，但又极其顽固地“油盐不进”，拒绝接受我们为它设定的卡片宽度与高度。

面对这种窘境，CSS 提供了极为强大的**显示模式转换机制**，其核心枢纽正是 `display` 属性。元素的原生显示模式并不是一成不变的，通过调整 `display` 的属性值，我们可以打破原生标签的物理限制：

```text
               +-----------------------------+
               |      display: inline        |
        +----->| (化身为行内: 失去宽高可控性) |
        |      +-----------------------------+
 原生元素
        |      +-----------------------------+
        +----->|    display: inline-block    |
        |      | (化身为行内块: 并排且控尺寸)|
        |      +-----------------------------+
        |      +-----------------------------+
        +----->|       display: block        |
               | (化身为块级: 独占行且控尺寸)|
               +-----------------------------+
```

上图清晰展示了通过 `display` 属性在不同显示模式之间自由切换的机制路径。

我们来动手进行一次精准的类型改造实验：

```html
<div class="div-inline">这是一个原本是块级、现已被转换为行内属性的 div 标签</div>
<span class="span-inline-block">这是一个原本是行内、现已被转换为行内块属性的 span 标签</span>
<span class="span-block">这是一个原本是行内、现已被转换为纯块级的 span 标签</span>
```

```css
.div-inline {
    display: inline;
    background-color: lightblue;
}

.span-inline-block {
    display: inline-block;
    background-color: blueviolet;
    width: 300px;
    height: 60px;
}

.span-block {
    display: block;
    background-color: coral;
}
```

细致观察渲染结果：
- 当给原本横行霸道、独占整行的 `<div>` 赋予 `display: inline;` 之后，它的蓝色背景不再贯穿整屏，而是瞬间收缩至文本边际，完完全全展现出普通行内文本的排布举止；
- 当给原本不接受尺寸约束的 `<span>` 赋予 `display: inline-block;` 之后，奇迹发生了：它依然老老实实与前方的元素并列呆在同一行，但我们为它设定的宽 300 像素、高 60 像素的巨幅尺寸被浏览器完整接受，渲染出一个规整的大色块；
- 若将 `<span>` 设置为 `display: block;`，它则彻底摆脱行内束缚，强行霸占后续整行空间。此外，`display: none;` 还可以将元素彻底从屏幕渲染树中抹去，不仅看不见，更完全不占任何地面空间。掌握了 `display` 转换，任何标签都可以被我们捏合成最理想的排版构件。

### 盒子模型与空间尺寸控制

#### 盒子模型四大组成结构

掌握了元素显示模式之后，我们便迈入了 CSS 布局体系中最核心的技术命门——**CSS 盒子模型（Box Model）**。

在浏览器的底层渲染引擎眼中，HTML 页面中的每一个元素，无论是文本标题、段落、容器还是图片，全部被抽象看待为一个拥有四层结构的“矩形盒子”。我们写页面排版，本质上就是在不同层级的容器里对这一批矩形盒子进行尺寸测算与摆放。

一个完整的标准 CSS 盒子由内向外由四个核心区域层层包裹而成：

```text
+-----------------------------------------------------------+
|                          margin (外边距)                   |
|   +---------------------------------------------------+   |
|   |                      border (边框)                 |   |
|   |   +-------------------------------------------+   |   |
|   |   |                  padding (内边距)          |   |   |
|   |   |   +-----------------------------------+   |   |   |
|   |   |   |                                   |   |   |   |
|   |   |   |          content (核心内容)       |   |   |   |
|   |   |   |                                   |   |   |   |
|   |   |   +-----------------------------------+   |   |   |
|   |   +-------------------------------------------+   |   |
|   +---------------------------------------------------+   |
+-----------------------------------------------------------+
```

上图直观展示了标准 CSS 盒子模型的四层纵深嵌套结构：由最内侧的内容区域向外依次为内边距、实体边框以及最外层的物理外边距。

这四大区域各司其职，协同构成了盒子的完整空间占用：
1. **内容区域（Content）**：盒子的核心内核，由文字、图标或内嵌图像等实体构成，通常由 `width` 和 `height` 属性直接控制其物理宽度与高度；
2. **内边距（Padding）**：围绕在内容外围、位于内容与边框之间的空白缓冲区。它就像包裹贵重物品时的泡沫填充层，用于防止核心内容紧贴硬质外壳；由 `padding` 属性控制；
3. **边框（Border）**：包裹在内边距外围的物理物理边界，直接决定了盒子的外在轮廓视觉表现；由 `border` 属性控制；
4. **外边距（Margin）**：位于边框最外层，用于隔离当前盒子与周边其他邻近盒子之间的空隙距离；由 `margin` 属性控制。

值得强调的是，`padding`、`border` 与 `margin` 每一个全都是功能强大的复合属性，支持从各个微观方向展开独立或联合控制。

#### 边框复合属性与方向控制

我们首先以 `border` 边框属性为切入点展开推导：

```html
<div class="demo">B站搜索罗大富</div>
```

```css
.demo {
    background-color: aqua;
    display: inline-block;
    border: 5px solid yellowgreen;
}
```

在这段演示中，我们利用 `border: 5px solid yellowgreen;` 迅速勾勒出了一个复合边框。这条简写指令实际上包含了三个维度的属性值：
- 边框宽度：`5px`，数值越大边框线条越粗；
- 边框样式：`solid`，代表最常见的连续实线；
- 边框颜色：`yellowgreen`（黄绿色），支持任意合法的色彩语法。

边框的视觉样式绝非只有实线一种，CSS 原生支持多种经典线型：
- `solid`：标准实线边框；
- `dashed`：由短划线断续组成的虚线边框；
- `dotted`：由微小圆点密集连接的点线边框；
- `double`：两条细实线平行的双实线边框。

如果不使用三合一的 `border` 简写属性，我们完全可以通过更具针对性的分项属性来定制边框细节：`border-style`（样式）、`border-width`（宽度）以及 `border-color`（颜色）。

更为重要的是，盒子拥有上下左右（Top、Right、Bottom、Left）四个物理方向，所有的分项属性都允许精准定制单侧边界：

```html
<div class="border-demo">这是一个边框示例</div>
```

如果我们希望仅仅给盒子的左侧绘制一条 10 像素宽的棕色实线竖条，而其余上、右、下三边完全不显示任何边框，我们可以直接使用针对单侧的复合属性：

```css
.border-demo {
    width: 300px;
    height: 200px;
    background-color: yellow;
    border-left: 10px solid brown;
}
```

`border-left` 自身仍然是一个复合属性，它还可以进一步向下拆解为 `border-left-width`、`border-left-style` 以及 `border-left-color`。同理，上、右、下三个方向分别对应着 `border-top`、`border-right` 与 `border-bottom` 系列。一旦理解了方向与维度的组合构词规则，我们就自然掌握了这一大类数十个细分属性的使用逻辑，完全无需死记硬背。

#### 四值顺时针旋转顺延规则

当我们在设置边框宽度（`border-width`）、内边距（`padding`）或外边距（`margin`）时，经常会遇到在单行声明中传入多个参数的场景。这套多值传入机制有着极其精妙且统一的几何设计规则：**顺时针旋转顺延法则**。

```text
                  12 点钟方向: Top (上)
                           ^
                           |
    9 点钟: Left (左) <----+----> 3 点钟: Right (右)
                           |
                           v
                  6 点钟方向: Bottom (下)
```

上图展示了四值赋参时遵循的顺时针空间循环：严格以 12 点钟方向的“顶部”为起点，顺时针旋转至右、下、左。

当我们在一个属性后面赋予不同数量的数值时，浏览器会严格按照如下顺延机制进行方向解构：

```css
/* 1. 传入四个值: 上 右 下 左 (顺时针旋转一周) */
padding: 10px 0 20px 40px;
/* 含义: 上边距 10px，右边距 0，下边距 20px，左边距 40px */

/* 2. 传入三个值: 上 左右 下 (左边缺省，自动取对面的右边) */
padding: 10px 0 20px;
/* 含义: 上边距 10px，左右两侧均为 0，下边距 20px */

/* 3. 传入两个值: 上下 左右 (下缺省取上，左缺省取右) */
padding: 10px 0;
/* 含义: 上下两端均为 10px，左右两侧均为 0 */

/* 4. 传入一个值: 上下左右四向统一 */
padding: 10px;
/* 含义: 上、右、下、左四个方向无差别均为 10px */
```

> **易错点**：在书写 CSS 尺寸时，如果数值为 `0`，可以安全地省略长度单位（写 `0` 即可）；但只要数值不为 0（例如 `10px`, `20px`），**必须严格附加显式单位 `px`**。初学者极易口误或漏写单位写成 `padding: 10 0 20;`，浏览器解析引擎会直接将该非法声明判定为语法错误并全盘抛弃忽略。

同样的顺延逻辑不仅适用于 `padding` 和 `margin`，更完美适用于 `border-width`、`border-style`（如 `border-style: solid dashed dotted double;` 分别对应上实、右虚、下点、左双）以及 `border-color`。整套系统的设计高度和谐自洽。

#### 内边距与外边距排版实践

理解了多值控制后，我们把内边距与外边距代入实战案例中观察盒子的空间膨胀：

```css
.demo {
    background-color: aqua;
    display: inline-block;
    border: 5px solid yellowgreen;
    padding: 50px;
    margin: 40px;
}
```

1. **内边距膨胀（`padding: 50px;`）**：当我们追加了该属性后，文字内容与四周黄绿色的实线边框之间，立刻被撑开了一圈厚达 50 像素的均匀空白保护区。内边距直接受容器背景色彩的浸润，文字不再逼仄地贴在边框内壁，整个盒子的内部呼吸感瞬间立显；
2. **外边距推离（`margin: 40px;`）**：外边距作用于边框之外，它强制要求当前盒子的黄绿色边框，与浏览器视口左上角边缘以及页面中其他所有邻近兄弟盒子的边框之间，必须保持至少 40 像素的“社交距离”。外边距是透明的，专门负责在微观模块与宏观页面之间构建起恰到好处的留白间隔。

### 浮动机制与布局流重构

#### 网页常见布局方式对比

在正式向传统网页布局的核心利器——**浮动（Float）**发起攻坚之前，我们需要站在顶层视角通盘鸟瞰现代网页开发中的常见布局形态。在漫长的前端演进史中，沉淀出了五种经典的排版模式：

```text
+-------------------------------------------------------------+
|                     常见网页布局模式演进                    |
+-------------------------------------------------------------+
|  1. 标准流 (Normal Flow) : 默认文档流，单向竖排或横排       |
|  2. 浮动 (Float)         : 突破标准流，实现多块紧密并排     |
|  3. 定位 (Position)      : 空间坐标系映射，实现精准重叠放置 |
|  4. 弹性盒 (Flexbox)     : 现代化一维轴线响应式自适应布局   |
|  5. 网格 (Grid)          : 现代化二维网格系统响应式布局     |
+-------------------------------------------------------------+
```

上图梳理了网页布局的五大核心方案：从最基础的标准流到响应式时代的 Flex 与 Grid，其技术演进构成了前端排版的全貌。

这五种方案各具特色：
1. **标准流（Normal Flow，又称普通流或文档流）**：浏览器最基本、默认遵循的排版法则。所有的 HTML 标签在不做特殊样式修饰时，严格按照标签的默认行为排列——块级元素自上而下逐行竖向罗列，每个独霸一行；行内元素自左向右依次横向贴合，填满一行自动换到下一行。标准流是所有布局的母体，但单凭标准流，我们根本无法在同一行优雅排布多个固定尺寸的复杂大板块；
2. **浮动（Float）**：传统 CSS 布局中最强悍的破局手段，专门用于打破标准流的死板限制，使得原本互不相让的多个块级元素能够横向并排陈列；
3. **定位（Position）**：通过坐标轴系的定位方式，让盒子能够跳脱出流式文档，在屏幕中绝对固定或层叠覆盖；
4. **弹性盒子（Flexbox）与网格布局（Grid）**：属于现代自适应与响应式布局方案。它们提供了高度弹性的排版选项，使得同一个页面在窄小的移动端手机屏幕与宽阔的桌面端显示器之间能够自如伸缩适配。

尽管方案各异，但万变不离其宗：**网页布局的本质，全都是在屏幕上“摆盒子”**。开发者所做的一切工作，无非是计算各个盒子的尺寸，并运用恰当的布局机制将盒子安放到最合适的位置。在真实的工业级开发中，往往是标准流打底、局部穿插浮动与定位、整体依托 Flexbox 的复合实战体系。

#### 浮动机制与行内块核心差异

很多学习者在接触浮动时都会产生一个强烈的直觉疑问：前面我们刚刚学过，通过设置 `display: inline-block;` 就能把多个块级 `<div>` 变成行内块元素，让它们在一行内并排显示且能自由定义宽高。既然如此，我们为什么还要大费周章地学习浮动呢？

两者的核心分水岭在于：**微观空白缝隙（Whitespace Bug）**。

当我们将多个盒子设置为行内块元素并排显示时，如果我们在 HTML 源代码的标签之间敲下了回车键换行或者留有空格，浏览器在解析时会极为“贴心”地将这段代码层面的空白字符渲染为一个极小的物理空白间隙（通常约为 4 到 8 像素）。这就导致并列排布的几个行内块盒子之间无论如何都无法做到严丝合缝的紧密贴合，极易导致预先精确计算好的百分比宽度总和超过父容器整行宽度，引发灾难性的换行跌落。

而**浮动（Float）**则彻底杜绝了这种缝隙：

> **核心差异**：设置了浮动的元素，其排列方式是**完全相互紧密贴靠在一起的，元素之间没有任何多余的间隙**。如果父级容器的宽度足够，浮动盒子会在同一行内紧密排开；一旦父级宽度装不下这些浮动的盒子，多出去的盒子会干净利落地自动跌落到下一行继续紧贴排列。

此外必须牢记一个先决条件：**浮动是相对于其直接父元素展开的，浮动盒子只会在其父元素的内部有效区域内游弋位移**，绝不会擅自溢出跑到父级边界之外。

浮动的语法本身极其精炼：

```css
.box {
    float: left;  /* 左浮动 */
    float: right; /* 右浮动 */
    float: none;  /* 默认值，不浮动 */
}
```

#### 浮动三大核心特性

要彻底驾驭浮动，必须在脑海中深刻烙印浮动的三大核心底层物理特性：

```text
浮动三大核心特性:
1. 脱标 (脱离标准流)    : 失去物理地面占位，腾空浮起，后续标准流顶替原位置
2. 一行显示，顶部对齐  : 多盒子并排靠拢，无缝贴合，顶端严格保持对齐
3. 具备行内块特性      : 任意元素施加浮动后，无需 display 即可直接定宽高
```

上图高度概括了浮动的本质物理特征：脱标改变了层级与占位，同行顶对齐规范了微观排列，而行内块特性赋予了尺寸操纵权。

第一大特性：**脱标（脱离标准流）**。
这是浮动最具震撼力的特性。“脱标”顾名思义就是脱离标准文档流的约束控制。一旦一个元素被赋予了 `float: left` 或 `float: right`，它就会瞬间“腾空升起”，脱离原来的平面地表，如同漂浮在半空中的热气球。**浮动的盒子在原本的标准流地表上不再保留哪怕一个像素的占位空间**。原本站在它后方的标准流元素，会误以为前方空无一物，立刻主动上移向前推进，强行占领它原本遗留在地面的物理地基。

第二大特性：**一行显示，顶部对齐**。
当多个兄弟盒子同时被赋予浮动属性时，它们会按照代码书写的先后顺序，沿着指定的浮动方向（靠左或靠右）依次紧贴并排陈列。更关键的是，无论各个盒子自身的高度是高是矮，它们在水平线上**始终严格保持顶部基准对齐**，绝不会参差不齐。

第三大特性：**具备行内块特性**。
无论元素原本属于何种显示模式，即便是天生无法直接设置宽高的行内元素 `<span>` 或 `<a>`，只要被追加了浮动属性，它就会在底层瞬间隐式激活类似于行内块元素的物理机能——开发者无需多此一举地书写 `display: inline-block;`，直接为其赋值 `width` 和 `height`，尺寸即可完整无误地生效。

我们通过一段左右双栏浮动的标准实战来检验这三大特性：

```html
<div class="father">
    <div class="left-son">左浮动盒子</div>
    <div class="right-son">右浮动盒子</div>
</div>
```

```css
.father {
    background-color: lightgray;
    height: 150px;
}

.left-son {
    width: 100px;
    height: 100px;
    background-color: yellowgreen;
    float: left;
}

.right-son {
    width: 100px;
    height: 100px;
    background-color: yellow;
    float: right;
}
```

在编辑器中书写宽高时，善用 Emmet 语法能够大幅缩短键入时间：输入 `w100+h100` 敲下 Tab 键，VS Code 便会一气呵成自动展开为 `width: 100px; height: 100px;`。在未设置浮动前，两个子元素作为标准的块级 `div`，只能上下纵向堆叠；一旦分别赋予 `float: left` 与 `float: right`，左盒子立刻稳稳吸附在父容器的最左边缘，右盒子则风驰电掣般飞跃吸附在最右侧边缘，二者在同一水平线上顶端对称排布。如果我们多复制几个 `.left-son`，它们会依次向右紧密靠拢；一旦一整行的横向像素被挤满，多出的左浮动盒子便整齐划一地换到第二行最左侧继续贴紧排列。

#### 父元素高度坍塌与清除浮动方案

浮动机制虽然极为巧妙地解决了多块并排的难题，但在实际工程应用中，它带来了一个臭名昭著且破坏力极强的副作用：**父元素高度坍塌**。

我们在前面的范例中，刻意给父容器 `.father` 显式写死了一个高度 `height: 150px;`。但在绝大多数真实的商业网页中，父容器内部装载的内容是动态变化的（例如文章列表条目可能由后端数据库实时推送，时而 3 条，时而 10 条）。在规范的前端开发习惯中，**父容器通常不应当写死固定高度，而是由内部的子元素自然撑开**。

当父元素没有指定高度时，灾难发生了：

```text
+-----------------------------------------------------------+
|               父元素高度坍塌的机理与破坏表现              |
+-----------------------------------------------------------+
|  .father (未设高度, 误以为内部无子元素, 实际高度缩为 0px) |
+-----------------------------------------------------------+
       ^                                      ^
       | (子盒子脱标腾空)                      | (子盒子脱标腾空)
  [ .left-son ]                          [ .right-son ]
  (飘浮在半空)                            (飘浮在半空)
-------------------------------------------------------------
  地面标准流文本: "这是一段文本内容" (原本应在下方，由于地面
  空无一物，被迫强行穿插上移，直接钻入两个浮动盒子的中间空隙)
```

上图展示了高度坍塌的根本机理：子元素全员浮动脱标升空，地表缺乏占位支撑，导致父容器自身高度归零，后续标准流盲目上移穿插。

我们还原这一车祸现场：一旦把 `.father` 样式中的 `height: 150px;` 注释掉，并为父元素增加一条边框线 `border: 3px solid brown;`：
1. 两个子元素 `.left-son` 与 `.right-son` 由于施加了浮动，双双脱标升空；
2. 处于地表的父容器 `.father` 环顾四周，发现地面上居然没有任何一个正常标准流元素支撑，于是认定自身内容为空，**其物理高度瞬间塌缩为零**；
3. 父容器的浅灰色背景色凭空消失不见，原本应当包裹住两个子盒子的棕色边框，由于高度为零，缩成了一条细细的水平线；
4. 如果紧随 `.father` 之后原本书写了一个普通的段落 `<p>这是一段正文内容</p>`，按照常理它应当规整出现在所有浮动盒子的正下方。但由于前面的父容器高度已经塌陷为 0，这个标准流段落会径直冲到上方，硬生生卡在左右两个浮动盒子的缝隙中间，整个页面结构彻底错乱穿帮。

为了解决这一顽疾，我们必须引入**清除浮动（闭合浮动）**的手段，强制让父容器感知到浮动子元素的存在并重新闭合高度。在工业实践中，最经典且优雅的解决方案有两种：

**方案一：父容器添加 `overflow: hidden;`（最简单高效的单行杀手锏）**

```css
.father {
    border: 3px solid brown;
    overflow: hidden; /* 核心关键: 闭合浮动并撑开高度 */
}
```

在父元素上追加 `overflow: hidden;` 属性后，刷新页面，原本塌陷成一条线的边框瞬间被重新撑开，稳稳当当地将左右两个浮动子盒子重新包揽在怀中，下方的普通段落也被规规矩矩排挤回了盒子的正下方。其底层技术原理在于，`overflow: hidden;` 触发了浏览器的块格式化上下文（BFC, Block Formatting Context），在 BFC 规范中，计算容器自身高度时，浮动元素必须全额计入空间统计，从而立竿见影地解决了高度坍塌。

**方案二：父容器伪元素清除法（Clearfix，现代工业级标准典范）**

尽管 `overflow: hidden` 极为便捷，但在某些特定场景下（例如子容器内部包含需要刻意溢出显示的下拉子菜单或悬浮提示框），`hidden` 会粗暴地将溢出部分强行裁剪切掉。因此，现代大型 CSS 框架与正规项目中普遍奉行的黄金法则是**伪元素清除法**。

我们在之前学习选择器时已经讲过，伪元素可以在目标容器的最末端虚拟构造一个节点。我们直接针对浮动元素的父容器挂载 `::after`：

```css
.father::after {
    content: "";
    display: table;
    clear: both;
}
```

剖析这段代码的底层协同逻辑：
1. `::after` 在父容器的物理内容最末尾凭空生成了一个虚拟伪节点；
2. `content: "";` 保持注入的伪节点内容为空，不影响视觉呈现；
3. `display: table;` 将该虚拟节点转换为具有块级特征的表格格式化上下文；
4. 最关键的 `clear: both;`：该属性严厉声明当前节点的左右两侧绝对不允许存在任何浮动元素。既然不允许有浮动元素与它为邻，这个看不见的虚拟节点就只能被强行排挤到所有左浮动和右浮动盒子的最底端。作为父容器的最后一个物理子节点，它的落底自然而然地将父容器的下边界一直推到最下方，从而实现了 100% 纯天然的高度自适应撑开。

通过上述两种清除浮动的方案，我们既享受了浮动带来的多块水平无缝排列的强大便利，又彻底化解了高度坍塌引发的排版乱象，为构建稳健规范的网页版面奠定了最坚实的基石。
