# 设备类型与设备管理改造

## 对照原型的改造套路

* **原型对照式改造**

    * > **定义**：把代码生成器产出的「标准长相」页面，按业务原型逐块掰成业务需要的样子。

    * 固定顺序：条件搜索区 → 按钮区 → 列表展示区 → 增改对话框。

    * 做法是先把原型截图缩小放到右上角，跟生成的页面并排摆着，逐块比对哪里要删、哪里要挪、哪里要改，再动手。

    * 判据只有一条：跟原型一致的原地保留，不一致的删掉或改掉，页面立刻干净。

    * > **提示**：改造要克制。少动一行就少一处出错的可能，跟原型一致的地方原样留着不是偷懒。

    * 数据库里有这个字段，不等于页面就要露出来；原型没要求就不显示。

## 设备类型：搜索区与列表区

* **搜索区裁剪**

    * 生成的设备类型管理条件区有「型号名称」和「型号编码」两个搜索框。

    * 原型只有型号名称，型号编码搜索框整行删掉。

    * 改造后条件区只剩型号名称一个条件。

* **列表区三处小改动**

    * 复选框保留，批量操作依赖它。

    * 主键列删掉，原型不展示序号。

    * 型号名称、型号编码、设备图片、货道的行列、设备容量这几列与原型顺序完全一致，不动。

    * 创建时间不做展示，数据库中并没有这个字段。

    * 操作列「修改」「删除」按钮把前面的图标删掉。

    * 实际动作只有删除和图标两处，其余保持生成代码原样。

## 设备类型新增对话框

### 输入控件换数字框

* **货道数的输入约束**

    * > **定义**：货道数这一表单项对应货道的行跟列，要求在同一行内显示，且只能输入数字。

    * 原型文字说明：货道的行、货道的列、货道容量均为十以内的整数。

    * 生成页面里数字和文本都能输入，不满足要求，必须换标签。

    * 改造分两步：文本框改数字框并加上大小限制，设备容量同样处理；设备图片移到表单最下方，即设备容量下方。

* **数字输入框（el-input-number）**

    * > **定义**：只能输入数字、支持加减操作、且自带最大最小值限制的表单控件，源码标签是 `el-input-number`。

    * 通过 `v-model` 做双向绑定。

    * 通过 `min` 限制最小值、`max` 限制最大值，官网示例是最小值 1、最大值 10。

    * 另带 placeholder 占位符。

* **拿到数字框写法的两条路**

    * 第一条：查 Element Plus 官网，左侧菜单往下拉到表单组件，input 是文本框、input number 是数字输入框，点进去看源码确认官方写法。

    * 第二条：把已有的 input 标签复制给通义灵码，附一句提示词让它改写。

    * 提示词写法：`原有的文本框我们需要改为数字输入框，且最小值是一，最大值是十`。

    * 生成结果回到官网比对，标签、`v-model`、`min`/`max`、placeholder 都对得上才算验证过。

    * > **提示**：两条路是串起来用的——先查官网确认官方写法，再让通义灵码按需求生成，最后回官网比对；只有生成没有核对等于没有验证。

### 合并货道表单项

* **货道数挤进一行**

    * 把原来的「货道的行」和「货道的列」两个表单项合并成一个表单项，label 改为「货道数」。

    * 合并时删掉「货道的列」的 label 属性，两个数字框拼在同一个表单项里。

    * 两个数字输入框的最小值都是 1、最大值都是 10。

    * 两个数字框后方各加一个汉字提示，第一个叫「行」，第二个叫「列」。

    * 两个数字框之间用不换行空格实体 `&nbsp;` 加两个空格隔开。

    ```vue
    <el-form-item label="货道数">
      <el-input-number v-model="form.channel" :min="1" :max="10" /> 行&nbsp;&nbsp;<el-input-number v-model="form.channelColumn" :min="1" :max="10" /> 列
    </el-form-item>
    ```

    * 两个数字框分别绑行与列，字段名以生成的实体为准。

    * 不点加减按钮直接键入超限值也会被钳到 10，限制不只在按钮上。

* **新增与修改的实操验证**

    * 新增「盲盒机」，型号编码尾号由 14 改成 15，货道数设五行四列，最大容量设 10，图片从资料中选取。

    * 点修改时数据回显正常，把容量由 10 改为 6 保存后列表显示为 6。

## 前端模拟数据字典

### 原理与两步做法

* **前端模拟数据字典**

    * > **定义**：不写多表嵌套查询，改由前端预先查回主数据列表，再用模板指令把外键 id 翻译成名称。

    * 页面需要显示设备型号名称和合作商名称，而数据库里存的只是外键字段。

    * 以往用持久层框架 MyBatis 的嵌套查询做多表联合查询，这次换成前端模拟数据字典的方案。

    * 好处：后端不必为每次前端请求执行复杂多表查询，减轻数据库负担，数据量大时尤其明显，同时简化后端逻辑。

* **两步做法**

    * 第一步：页面启动、访问时预先查询所有合作商和设备型号信息列表，这份数据量不大，存进响应式集合。

    * 第二步：需要显示名称时用 `v-for` 遍历该集合，再用 `v-if` 判断当前遍历项的 id 与要显示的 id 是否一致，一致就显示对应名称。

* **若依数据字典的原理**

    * 若依页面先做预加载，拉取全部字典项信息。

    * 列表区使用自定义字典标签，源码里先用 `v-for` 遍历字典选项，再做条件判断：当数据库返回的字典值与字典标签对应的值相同时，显示对应名称。

    * 设备型号和合作商是数据库外键字段而非数据字典，不能直接套用数据字典标签，只能用前端代码模拟。

### 预加载主数据

* **引入与查询方法**

    * 引入两个查询方法与一个查询条件对象。

    ```js
    import { listVmType } from '@/api/iot/manager/deviceType'
    import { listPartner } from '@/api/iot/manager/partner'
    import { loadOrParams } from '@/api/common'
    ```

    * `loadOrParams` 是查询全部数据的条件对象，两个查询方法都以它为入参。

    * 响应式集合要先声明再写赋值方法。

    ```js
    // 查询设备类型列表
    const vmTypeList = ref([])
    const getVmTypeList = () => {
      listVmType(loadOrParams).then(res => {
        vmTypeList.value = res.rows;
      })
    }
    ```

    * 合作商同理：声明 `partnerList`，`getPartnerList()` 调 `listPartner(loadOrParams)`，把返回结果的 `rows` 赋给 `partnerList`。

    * 点位同理：引入 `listNode`，声明 `nodeList` 与 `getNodeList()`。

    * 区域同理：引入 `listRegion`，声明 `regionList` 与 `getRegionList()`。

* **加载时机与验证**

    * 页面加载完毕后执行 `getVmTypeList()` 和 `getPartnerList()` 触发查询。

    * 验证时刷新页面并打开 Network，能看到两条查询请求，合作商和设备类型都正常返回。

    * 手打方法名后接 `from` 关键字再敲 `@/`，通义灵码会给出路径提示，按 Tab 直接补全即可。

    * 只写完第一个查询方法，第二个的声明与方法体通义灵码能结合上下文自动补出来。

### 表格里翻译外键

* **列标签改造**

    * 列标签由单标签改为双标签，内部加 `template` 模板插槽。

    * 外层 `div` 用 `v-for` 遍历集合，每个元素记为 `item`，并用 `:key="item.id"` 指定唯一标识，否则会报错。

    * 内层 `span` 用 `v-if` 比较 `item.id` 与当前行的外键 id，相等才显示名称。

    ```vue
    <el-table-column label="设备型号" align="center" prop="vmTypeId">
      <template #default="scope">
        <div v-for="item in vmTypeList" :key="item.id">
          <span v-if="item.id === scope.row.vmTypeId">{{ item.name }}</span>
        </div>
      </template>
    </el-table-column>
    ```

* **合作商列与易错点**

    * 合作商列写法完全相同，遍历集合换成 `partnerList`，比较对象换成 `scope.row.partnerId`。

    * 合作商表字段是 `partner_name`，所以显示名称要写 `item.partnerName` 而不是 `item.name`。

    ```vue
    <el-table-column label="合作商" align="center" prop="partnerId">
      <template #default="scope">
        <div v-for="item in partnerList" :key="item.id">
          <span v-if="item.id === scope.row.partnerId">{{ item.partnerName }}</span>
        </div>
      </template>
    </el-table-column>
    ```

    * > **易错点**：这个 `v-if` 必须加。`v-for` 会把整个集合无条件遍历一遍，不加判断每行设备后面都会跟一整串合作商名称。外层 `v-for` 负责遍历，内层 `v-if` 负责挑出匹配项。

    * 改造后页面只对设备表做了单表查询，就能显示型号名称与合作商名称。

### 下拉框复用预加载结果

* **选择型号直接复用**

    * 「选择型号」复用列表展示已经预加载的 `vmTypeList`，不必再写额外 JS。

    * `el-select` 做双向绑定并给 placeholder，提示文案改成「请选择设备型号」而不是「请输入」。

    * `el-option` 用 `v-for` 遍历 `vmTypeList`，`:key` 取 `item.id`，`:label` 显示型号名称，`:value` 提交型号 id。

    ```vue
    <el-form-item label="选择型号">
      <el-select v-model="form.vmTypeId" placeholder="请选择设备型号">
        <el-option v-for="item in vmTypeList" :key="item.id" :label="item.name" :value="item.id" />
      </el-select>
    </el-form-item>
    ```

* **选择点位自己查一次**

    * 「选择点位」在列表预加载里没有，必须自己再查一次。

    * 点位下拉的 `el-option` 与型号同理，只是显示名称字段是 `nodeName` 而不是 `name`。

    ```vue
    <el-form-item label="选择点位">
      <el-select v-model="form.nodeId" placeholder="请选择点位">
        <el-option v-for="item in nodeList" :key="item.id" :label="item.nodeName" :value="item.id" />
      </el-select>
    </el-form-item>
    ```

    * 点位信息里的三里屯、五道口、北京奥运博物馆，正是点位管理中的三个点位；选定后 id 提交后台完成设备与点位的关联。

## 一套对话框两种面孔

### 回显字段清单与开关

* **一套代码两种用途**

    * > **定义**：用同一套新增修改对话框配合条件渲染，分别呈现新增页和修改页两种形态。

    * 原型里修改对话框比新增多出一批回显字段，且部分字段在新增时要隐藏。

    * 回显信息包含设备编号、供货时间、设备类型、设备容量、设备点位、合作商、所属区域、设备地址。

    * 这些字段有一部分设备表提供了，有一部分没有：设备编号是 `innerCode`，供货时间是上次补货时间 `lastSupplierTime`，设备容量可直接回显，设备地址对应详细地址 `addr`。

    * 设备类型、合作商、所属区域在设备表里只有外键字段（`vmTypeId`、`partnerId`、`regionId`），都要按 id 查回名称再回显。

    * 只有设备点位允许修改，型号在修改时不允许改。

    * 判断依据只有一个：设备编号 `innerCode`。新增时不带编号，修改时带编号。

    * 回显类字段统一加 `v-if="form.innerCode"`；「选择型号」加 `v-if="!form.innerCode"`。

    * 结果是新增对话框只剩设备编号、选择型号、选择点位三项。

### 逐个表单项的写法

* **设备编号交给后台**

    * 新增时设备编号应由系统后台自动生成，不需要手动录入的文本框。

    * 把输入框改成 `span` 标签，一行三元运算符同时满足新增提示与修改回显：编号为空显示「系统自动生成」，否则回显编号。

    ```vue
    <el-form-item label="设备编号">
      <span>{{ form.innerCode ? form.innerCode : '系统自动生成' }}</span>
    </el-form-item>
    ```

    * 修改时编号做回显，用户不能做任何修改操作。

* **供货时间交给 parseTime**

    * 供货时间表单项在设备编号表单项下方复制一份并改 label 即可。

    * 这一项是纯展示不参与提交，`prop` 属性可以删掉，`prop` 是给表单校验用的绑点。

    * 原始时间格式不优雅，用前端方法 `parseTime` 转换，传入时间值和格式串两个参数。

    * 时间格式串为 `{y}-{m}-{d} {h}:{i}:{s}`。

    | 想显示 | 占位符 |
    | :--- | :--- |
    | 年 | `{y}` |
    | 月 | `{m}` |
    | 日 | `{d}` |
    | 时 | `{h}` |
    | 分 | `{i}` |
    | 秒 | `{s}` |

    ```vue
    <el-form-item label="供货时间" v-if="form.innerCode">
      <span>{{ parseTime(form.lastSupplierTime, '{y}-{m}-{d} {h}:{i}:{s}') }}</span>
    </el-form-item>
    ```

    * > **易错点**：`parseTime` 里分钟对应 `{i}` 而不是 `{m}`，`{m}` 是月。写错不报错，只会安静地显示一串错误数字，所以改完一定要回浏览器看实际效果。

* **复制模板补齐剩余回显**

    * 做法是以供货时间表单项为模板连续复制，只改 label、判断对象和显示内容。

    * 设备类型：复用列表展示那套 `div` 遍历加 `span` 判断，把比较对象从 `scope.row.vmTypeId` 换成 `form.vmTypeId`。

    ```vue
    <el-form-item label="设备类型" v-if="form.innerCode">
      <div v-for="item in vmTypeList" :key="item.id">
        <span v-if="item.id === form.vmTypeId">{{ item.name }}</span>
      </div>
    </el-form-item>
    ```

    * 设备容量：直接回显 `form.channelMax`。

    * 选择型号：判断条件取反，编号为空时才显示。

    * 合作商：复用列表的合作商展示写法，比较对象换成 `form.partnerId`，显示 `item.partnerName`。

    * 所属区域：遍历 `regionList`，比较对象换成 `form.regionId`，显示 `item.regionName`。

    * 设备地址：不需要遍历，改回 `span` 插值回显 `form.addr`。

    * > **提示**：手打应用程序接口（Application Programming Interface，API）路径时 `manger` 与 `manager` 只差一个字母，最容易踩；前端构建失败会直接报出出错的那一行，照着提示改比通读整段堆栈快得多。

## 新增设备：一次动四张表

* **新增设备的真实代价**

    * > **定义**：用户在对话框里只提交设备型号 id 和点位 id 两个参数，后端却要写四张表。

    * 设备表与货道表是新增写入，点位表与设备类型表是查询读取。

    * 前端没给的那一大片字段全靠后端补齐：设备编号、设备容量、详细地址、商圈类型、区域 id、合作商 id 等。

    * 每台设备对应一堆货道，一行一列就是一杠一、一杠二，二行一列就是二杠一，以此类推。

    * 一台饮料机配置 5 行 6 列，就要跟着建出 30 条货道记录。

```text
[前端 新增设备对话框]  提交：设备型号 id + 点位 id
        |
        v
[VmServiceImpl#insert   方法上挂 @Transactional]
        |
        +--> 写设备表 VmService.insert
        |        查设备类型表：取容量 / 行 / 列 / 货道最大容量
        |        查点位表  ：取地址 / 商圈类型 / 区域 id / 合作商 id
        |
        +--> 写货道表 VmChannelService.batchInsertChannels
                 查设备类型表：取行 / 列 / 货道最大容量
```

### 设备表字段补齐

* **哪些字段要补**

    * 主键 id 由数据库自增，不碰。

    * 设备编号 `inner_code` 必须唯一，用项目里现成的 UUID 工具类生成八位标识。

    * 设备容量：拿前端给的设备型号 id 去查设备类型表，把容量取出来赋给设备表。

    * 点位 id：虽然也是前端提交的，但光有 id 不够，还要再查一次点位表，把详细地址、商圈类型、区域 id、合作商 id 这些冗余字段补进来。

    * 暂不提交的字段：上次补货时间、运行状态、经纬度、客户端链接 id、策略 id——它们要等售货机真正运营起来才有，现在提交就是凭空造数据。

    * 设备状态设为 0，表示设备尚未投放。

    * 创建时间和修改时间手动记录。

    * > **提示**：像 `status = 0` 这种，数据库明明有默认值、不写也不影响运行，但仍然建议加上这一行——不为功能，为可读性，三个月后回看得靠注释才知道这个 0 是什么意思。

* **八位设备编号怎么来的**

    * 工具类在 `common` 包下，思路是：通用唯一标识符（Universally Unique Identifier，UUID）先生成 32 位随机字符串，拆成 8 组每组 4 个字符，每组转成 16 进制数，再对预先定义好的字符数组取模，用取模结果当下标取出一个字符，存进 StringBuffer，遍历 8 次。

    ```text
    UUID 生成 32 位随机字符串
      -> 拆成 8 组，每组 4 个字符
      -> 每组转成 16 进制数
      -> 对字符数组 [a-z 0-9 A-Z] 取模，用结果当下标取出一个字符
      -> 存进 StringBuffer，遍历 8 次
      -> 得到 8 位唯一标识，例如 a3F0k2Zq
    ```

    * 那个字符数组装的是小写字母 a~z、数字 0~9、大写字母 A~Z。

    * 用起来只有一行。

    ```java
    vm.setInnerCode(UuidUtils.getUuid());
    ```

* **设备容量与点位信息**

    * 查设备类型表要先注入 `VmTypeService`，service 里直接依赖它。

    * 主键查询方法的参数直接传设备实体对象，从它身上就能拿到设备型号 id。

    ```java
    @Autowired
    private VmTypeService vmTypeService;

    // 查询售货机类型表，补充设备的容量
    VmType vmType = vmTypeService.selectVmTypeById(vm);
    vm.setCapacity(vmType.getCapacity());
    ```

    * 点位信息同理，注入 `NodeService`，用设备实体作参数查点位表。

    ```java
    @Autowired
    private NodeService nodeService;

    // 查询点位表，补充区域点位、合作商等信息
    Node node = nodeService.selectNodeById(vm);
    ```

### 属性拷贝与状态常量

* **属性拷贝 BeanUtils**

    * `BeanUtils` 是 Hutool 提供的属性拷贝工具类，接收三个参数：来源、目标、忽略信息。

    * 商圈类型、区域 id、合作商 id 字段名两边一致，拷贝一次就完事，省掉一个一个 `set` 的繁琐操作。

    ```java
    // 忽略 id：把商圈类型、区域 id、合作商 id 拷贝到设备实体
    BeanUtils.copyProperties(node, vm, "id");
    ```

    * > **易错点**：拷贝前一定要想清楚忽略字段。点位表和设备实体都有主键 id 且字段名一模一样，不忽略的话点位 id 会直接覆盖设备 id；设备还没落库主键就被顶掉，后面全乱。

    * 点位表的地址属性是 `address`，设备表的地址字段是 `addr`，名称不一致无法完成拷贝，要手动补一次。

    ```java
    vm.setAddr(node.getAddress());   // 设备地址
    ```

* **设备状态用常量**

    * 项目在 `common` 包下定义了现成的常量实体类，装了售货机全套状态：0 未投放、1 运营中、3 撤机。

    * > **提示**：光秃秃写个 `0`，别的程序员看不出什么意思；用常量写法见名知意，可读性立刻上来。

    ```java
    vm.setStatus(VmStatus.NO_DEPLOY);   // 设备状态：未投放
    ```

    * 创建时间和修改时间用框架自带的日期工具类取当前时间。

    ```java
    vm.setCreateTime(DateUtils.getNowDate());   // 创建时间
    vm.setUpdateTime(DateUtils.getNowDate());   // 更新时间
    ```

### 新增方法的两步结构

* **两大步与事务**

    * 改造位置是 service 的新增方法，把它清晰地分成两大步：新增设备、新增货道。

    * 第一步里放创建时间设置与设备插入，插入方法返回影响行数，用 `result` 接住，最后 `return result`。

    * 设备表与货道表两张表的新增必须保证数据一致性和完整性，要么都成功要么都失败，所以方法上方要挂 `@Transactional`。

    ```java
    @Transactional
    public int insert(Vm vm) {
        // ---------- 第一大步：新增设备 ----------
        vm.setInnerCode(UuidUtils.getUuid());
        VmType vmType = vmTypeService.selectVmTypeById(vm);
        vm.setCapacity(vmType.getCapacity());
        Node node = nodeService.selectNodeById(vm);
        BeanUtils.copyProperties(node, vm, "id");
        vm.setAddr(node.getAddress());
        vm.setStatus(VmStatus.NO_DEPLOY);
        vm.setCreateTime(DateUtils.getNowDate());
        vm.setUpdateTime(DateUtils.getNowDate());
        int result = baseMapper.insert(vm);

        // ---------- 第二大步：新增货道 ----------
        ...
        return result;
    }
    ```

## 货道表：行列算出的编号

### 编号算法

* **哪些字段先不填**

    * 主键 id 交给数据库自增。

    * 商品 id、货道当前容量、上次补货时间、剩余容量这些新增时先不提交，它们是设备运营之后跟货道关联的商品和补货产生的数据。

    * 售货机 id 和售货机编号由设备表刚生成的 id 与设备编号提供。

    * 货道最大容量仍从设备类型表拿。

    * 创建时间和修改时间手动补上。

* **货道编号由行列算出**

    * > **定义**：货道编号 `channel_code` 不是随手起的，而是由设备类型表里的行和列计算组成，一行一列就是一杠一，一行两列就是一杠二。

    * 算法是双层 for 循环：外层循环行，内层循环列。

    ```java
    // 双层 for 循环：外层遍历行，内层遍历列
    for (int i = 1; i <= vmType.getVmRow(); i++) {          // 外层：行
        for (int j = 1; j <= vmType.getVmColumn(); j++) {    // 内层：列
            // 封装 Channel 货道对象
        }
    }
    ```

    * 5 行 6 列展开后是一张 30 格的表，从 1-1 排到 5-6。

    ```text
          列1    列2    列3    列4    列5    列6
    行1   1-1    1-2    1-3    1-4    1-5    1-6
    行2   2-1    2-2    2-3    2-4    2-5    2-6
    行3   3-1    3-2    3-3    3-4    3-5    3-6
    行4   4-1    4-2    4-3    4-4    4-5    4-6
    行5   5-1    5-2    5-3    5-4    5-5    5-6

    5 行 x 6 列 = 30 条货道，从 1-1 一直排到 5-6
    ```

    * 每轮拿到行号 i 和列号 j，拼成 `i + "-" + j` 就是货道编号，其余字段从设备实体和 `vmType` 上取。

    ```java
    Channel channel = new Channel();
    channel.setChannelCode(i + "-" + j);                            // 货道编号：1-1、1-2…
    channel.setVmId(vm.getId());                                   // 售货机 id
    channel.setInnerCode(vm.getInnerCode());                        // 售货机编号
    channel.setMaxCapacity(vmType.getChannelMaxCapacity());         // 货道最大容量
    channel.setCreateTime(DateUtils.getNowDate());                  // 创建时间
    channel.setUpdateTime(DateUtils.getNowDate());                  // 修改时间
    ```

### 批量插入三层改造

* **为什么要批量**

    * 遍历一次保存一次，5 行 6 列就会执行 30 条 SQL 语句；底层每次都要跟数据库建立连接、执行、再断开、再建连接，性能非常差。

    * 框架自带的代码没有提供批量新增操作，这部分需要自己改造。

    * 改造对象是货道新增的 mapper XML，原来是一个单条记录的新增操作并包着动态 `<if>` 标签。

    * 交给通义灵码改写时的提示词：`你是一名软件工程师，请把下面的 XML 改成批量新增。注意不需要动态 SQL，因为批量新增的话，你传哪个值我就添加哪个值。`

    * 生成结果的关键三点：`insert` 改成 `batchInsertChannels`；移除 `if` 标签让所有字段都进 SQL；后面加 `<foreach>` 遍历，通过 Java 传入的集合逐个设置货道编号、商品 id、设备 id 等。

    ```xml
    <insert id="batchInsertChannels">
        insert into vm_channel
            (channel_code, vm_id, inner_code, max_capacity, create_time, update_time)
        values
        <foreach collection="list" item="item" separator=",">
            (#{item.channelCode}, #{item.vmId}, #{item.innerCode},
             #{item.maxCapacity}, #{item.createTime}, #{item.updateTime})
        </foreach>
    </insert>
    ```

    * > **提示**：批量插入的 `collection` 写什么取决于 mapper 方法上的参数名。方法参数没加 `@Param` 就要在接口上补上，否则 foreach 取不到集合。

* **三层都要铺到位**

    * 第一层：mapper 接口最下方加方法，返回值仍是影响行数，入参是货道对象集合。

    ```java
    /**
     * 批量新增售货机货道
     */
    int batchInsertChannels(List<Channel> channelList);
    ```

    * 第二层：service 接口加同签名方法，命名格式可照抄 mapper 层；实现类里重写并转调 mapper 的批量新增。

    ```java
    @Override
    public int batchInsertChannels(List<Channel> channelList) {
        return baseMapper.batchInsertChannels(channelList);
    }
    ```

    * 第三层：设备 service 新增代码里注释掉添加单个货道那行，声明集合容器，双层循环里封装并 add，循环外侧一次性批量保存。

    ```java
    // 2-1 声明货道集合
    List<Channel> channelList = new ArrayList<>();
    // 2-2 双层 for 循环
    // 2-3 封装货道对象，并添加到集合
    channelList.add(channel);
    // 2-4 在循环外侧批量保存
    vmChannelService.batchInsertChannels(channelList);
    ```

    * > **提示**：接口方法上方记得补注释；回看自己的代码、或让同事接手时，注释是唯一的信息来源。

### sku_id 与地址列

* **sku_id 不能存成 NULL**

    * 货道记录里包含 `sku_id`，即未来要给货道关联的商品 id。

    * 批量新增时这些默认值都是 NULL，但业务约定是 sku_id 为 0 表示该货道没有关联商品。

    * > **易错点**：存成 NULL，后期做「sku_id 为 0」这类逻辑判断就可能空指针异常。

    * 方案一：建表时给这个字段加默认值 0，批量新增不包含 `sku_id`，插入时自动取默认值。

    * 方案二：添加货道对象时把 `skuId` 属性显式设为 0，存进数据库就是 0。

    * 采用方案一：在 mapper 的 XML 里把 `sku_id` 从批量插入字段列表删除，对应 `<foreach>` 里的占位符也一起删掉。

    * 热部署更新后先清掉历史数据，重新添加一台设备，新数据 `sku_id` 就都是 0。

* **详细地址列老是换行**

    * 列表展示第七列详细地址总要换行、占掉半屏。

    * 给列加 `show-overflow-tooltip`，隐藏多余行的显示内容。

    * 同时把对齐方式设为 `left` 左对齐。

    ```vue
    <el-table-column label="详细地址" align="left" prop="addr" show-overflow-tooltip>
    ```

    * 验证时选饮料机（5 行 6 列）加北京奥运博物馆新增，货道表里能看到 30 条记录，编号从 1-1 一直到 5-6。

### 设备状态列的渲染

* **字段含义与空值风险**

    * > **定义**：这列对应设备表的 `running_status` 字段，是智能售货机投放后通过物联网实时上报的运行状况，前端拿到的是一段序列化对象表示法（JavaScript Object Notation，JSON）字符串。

    ```text
    设备表.running_status
      -> 后端返回一段 JSON 字符串：{"status":true,...}
      -> JSON.parse(...) 解析成 JS 对象
      -> 取对象的 status
      -> true 显示「正常」，false 显示「异常」
      -> 为 NULL 时显示「异常」
    ```

    * JSON 里有个 `status` 状态码，为 true 表示正常状态，为 false 表示异常状态。

    * > **易错点**：刚添加还没投放的设备这个数据是空值，直接取 `status` 会空指针异常，取值之前必须先做非空判断。

    * 先用 `v-if` 写：给列标签加 `v-if`，通过 `scope` 取当前行的 `runningStatus`，不为空就取出 `status` 判断显示正常或异常，再加 `v-else` 处理为空时显示异常。

    * 不加 `v-else` 时，运营状态没值会把设备状态的 0 和 1 直接显示出来，设计不合理。

* **从 v-if 简化到嵌套三元**

    * 简化做法是把两个 `span` 加 `v-if` 的非空判断嵌进三元运算符，一行搞定：字段不为空就执行 JSON 转换判断 `status`，否则显示异常。

    ```vue
    <el-table-column label="设备状态" align="center" prop="status">
      <template #default="scope">
        <span>
          {{ scope.row.runningStatus == null
               ? '异常'
               : (JSON.parse(scope.row.runningStatus).status === true ? '正常' : '异常') }}
        </span>
      </template>
    </el-table-column>
    ```

    * 效果是只有 `status` 为 true 才显示正常，其余全部显示异常。

    * > **提示**：两种写法按项目风格和团队规范挑；嵌套三元更紧凑，可读性上也更费劲一点。

## 货道编号算法题

* **题干与解法**

    * 一台售货机在设备类型表里配置了 5 行 6 列，新增它时要在货道表中创建全部货道，编号形如「一杠一」「一杠二」。

    * 本质是把「行 × 列」的二维结构展开成一维编号列表。

    * 两层嵌套遍历，外层控制行、内层控制列，每轮拿到行号 i 和列号 j，拼成 `i-j`。

    ```java
    for (int i = 1; i <= vmType.getVmRow(); i++) {
        for (int j = 1; j <= vmType.getVmColumn(); j++) {
            Channel channel = new Channel();
            channel.setChannelCode(i + "-" + j);
            // ... 其余字段
            channelList.add(channel);
        }
    }
    ```

    * 5 行 6 列跑完依次得到 1-1、1-2、1-3……直到 5-6，一共 30 条。

    * 延伸结论：遍历出的 30 条对象不要在循环里一条条 save，攒进 `List` 里最后调一次 `batchInsertChannels`——每条都落一次库就要建一次连接、断一次连接，性能非常差。
