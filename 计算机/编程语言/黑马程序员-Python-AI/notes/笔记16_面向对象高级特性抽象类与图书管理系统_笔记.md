# 面向对象高级：特性、抽象类与图书管理系统

## 封装特性与访问控制机制

### 成员访问边界与公有私有

* **封装（Encapsulation）**

    * > **定义**：将数据（属性）与操作该数据的函数（方法）捆绑为一个独立类单元，并隐藏类内部的具体实现细节，仅对外暴露必要公有交互接口的机制。

    * 核心诉求：收敛高危传动逻辑与敏感隐私数据，杜绝外部随意读取与篡改，降低系统维护成本。

    * 架构隐喻：汽车将燃油喷射 `__control_fuel`、变速齿轮切换 `__gear_shift` 等精密机械与算法封闭在底盘车壳内，仅向驾驶员暴露方向盘、油门踏板、刹车踏板等公有接口。

    ```text
    +-------------------------------------------------------------------------+
    |                         汽车封装边界架构模型                            |
    +-------------------------------------------------------------------------+
    |  [外部世界 / 驾驶员 / 客户端代码]                                       |
    |      | 仅调用公有接口                                                   |
    |      v                                                                  |
    |  +-------------------------------------------------------------------+  |
    |  | 外部暴露层 (Public Interface): 方向盘, 油门, 刹车, 品牌型号       |  |
    |  +-----------------------------------+-------------------------------+  |
    |                                      | 内部协同调用                     |
    |                                      v                                  |
    |  +-------------------------------------------------------------------+  |
    |  | 内部实现细节与敏感数据 (Private): __control_fuel(), __owner 隐私   |  |
    |  +-------------------------------------------------------------------+  |
    +-------------------------------------------------------------------------+
    ```

* **公有成员（Public Member）**

    * > **定义**：在类中直接定义、未施加特殊下划线前缀的属性与方法。

    * 访问权限：对内对外均无限制，类方法内通过 `self.attr` 与 `self.func()` 访问，类外部通过实例对象 `obj.attr` 与 `obj.func()` 直接调用。

    * 架构职责：构成类的公有服务契约（Public APIs）。

* **私有成员（Private Member）**

    * > **定义**：在属性名或方法名前加上双下划线 `__`、且末尾不以双下划线结尾的类内部成员。

    * 访问拦截：外部通过 `obj.__attr` 或 `obj.__func()` 直接访问时，Python 解释器抛出 `AttributeError` 异常（提示对象不存在该属性）。

    * 作用域可见性：处于本类作用域之内的方法可正常通过 `self.__attr` 和 `self.__func()` 读写与调用。

* **访问器方法（Getter Method）**

    * > **定义**：在类内部定义的公有读取方法，充当外部获取私有属性的受控中介通道。

    * 核心功能：在返回底层私有数据前执行有效性校验、数据过滤或脱敏处理（例如车主姓名仅暴露首字，其余字符使用 `**` 遮盖脱敏）。

    * 代码实现范式：

    ```python
    def get_owner(self) -> str:
        if isinstance(self.__owner, str) and len(self.__owner) > 0:
            return self.__owner[0] + "**"
        return "未知车主"
    ```

### 名称修饰机理与约定约束

* **名称修饰（Name Mangling）**

    * > **定义**：Python 解释器在编译与运行期，自动将以双下划线开头且非双下划线结尾的标识符改写为包含类名前缀形态的底层重命名机制。

    * 转换规则：`_` + `所属类名` + `双下划线标识符`。例如 `Car` 类中的 `self.__owner` 实际存储为 `self._Car__owner`，`def __control_fuel()` 转换为 `def _Car__control_fuel()`。

    * 穿透途径：外部直接调用 `obj._Car__owner` 可绕过拦截读取底层变量。

    * 设计初衷：防范派生子类在继承树中意外覆盖父类的关键内部属性，而非构建物理级安全防护墙；Python 内部不存在真正的物理私有化，核心遵循约定大于配置原则。

* **魔法方法（Magic Method）**

    * > **定义**：以双下划线开头且必须以双下划线结尾的内置协议方法（Special / Dunder Method）。

    * 典型成员：`__init__`（构造初始化）、`__str__`（字符串表示）、`__del__`（析构注销）。

    * 权限属性：属于公开协议钩子接口，绝非私有成员；不触发名称修饰，子类能正常继承并在实例化时自动生效。

## 继承体系与多继承冲突仲裁

### 单继承与根基类

* **继承（Inheritance）**

    * > **定义**：描述类与类之间泛化与特化关系的机制，表示“子类是一个父类（is-a）”的血统从属。

    * 核心价值：抽取公共属性与通用行为至基类，派生子类自动复用父类非私有能力，消除重复代码。

    * 语法格式：`class SubClassName(BaseClassName): pass`。

* **终极基类（Object Class）**

    * > **定义**：Python 面向对象体系的顶层根节点类，所有内置类型与自定义类均直接或间接派生自该类。

    * 隐式规则：在 Python 3 中，类定义未显式声明父类时，默认隐式继承自 `object`；即 `class Car:` 与 `class Car(object):` 在底层完全等价。

* **继承边界（Inheritance Boundary）**

    * 传递范围：子类自动继承父类的所有公有属性、公有方法以及魔法方法（如 `__init__`）。

    * 隔离规则：> **易错点**：⚠️ 子类仅能继承父类的非私有成员，父类的私有属性与私有方法受名称修饰隔离，子类实例无法直接继承或调用。

### 方法重写与父类协同调用

* **方法重写（Method Overriding）**

    * > **定义**：子类在继承父类后，重新定义与父类同名的方法，以子类特化实现覆盖父类通用逻辑的技术。

    * 调度行为：子类实例调用该方法时，解释器优先命中子类自身的实现版本，遮蔽父类逻辑。

* **super 代理调用（Super Proxy Call）**

    * > **定义**：通过内置 `super()` 函数获取代理对象，依据当前类的方法解析顺序协同触发父类逻辑的调用机制。

    * 传参规则：`super().method()` 在运行时自动捕获调用上下文中的实例对象并隐式传递 `self`，括号内无需手动传入 `self`。

    * 适用场景：在保留父类通用流程的基础上，在方法执行前后扩展子类专属特化逻辑。

* **未绑定父类调用（Unbound Method Call）**

    * > **定义**：通过指定父类类名以普通函数形式显式触发父类方法的调用机制。

    * 语法格式：`BaseClassName.method(self, *args, **kwargs)`。

    * 参数约束：> **易错点**：⚠️ 直接通过类名调用函数时该方法处于未绑定状态（Unbound Method），不会自动注入实例指针，必须手动将当前实例 `self` 作为第一个实参传递；若漏传 `self`，运行时立即抛出 `TypeError: BaseClass.method() missing 1 required positional argument: 'self'`。

### 多继承与方法解析顺序

* **多继承（Multiple Inheritance）**

    * > **定义**：一个子类在定义时显式声明继承两个或两个以上的父类，同时聚合多个父类能力的机制。

    * 语法格式：`class SubClassName(Base1, Base2, ...): pass`。

    * 能力聚合：子类实例自动获得所有父类的公开非私有成员（例如 `WenjieCar(Car, HuaweiAI_Driven)` 同时具备机械底盘与智能驾驶能力）。

* **方法解析顺序（Method Resolution Order，MRO）**

    * > **定义**：Python 在多继承体系下用于确定属性与方法搜索优先路径的核心线性化算法规则。

    * 搜索机理：自底向上、自左向右依次级联检索，直至匹配到首个符合条件的成员或落入终极基类 `object`。

    * 冲突仲裁：若多个父类中存在同名属性或未重写的方法，优先调用在继承参数列表中排在最左侧（第一个）的父类实现。

    * 拓扑查看途径：

        * `类名.__mro__`：返回包含解析路径类对象的元组（Tuple）。

        * `类名.mro()`：返回包含相同顺序类对象的列表（List）。

    ```text
    WenjieCar 查找拓扑:
    WenjieCar(子类优先) -> Car(第1父类) -> HuaweiAI_Driven(第2父类) -> object(终极祖先)
    ```

* **多父类初始化解耦（Multiple Superclass Initialization）**

    * 结构冲突：在多继承体系下，若多个父类的 `__init__` 构造函数形参签名不一致，使用 `super().__init__()` 仅会路由至 MRO 首位父类，导致后续父类属性未能绑定至实例。

    * 解耦方案：在子类 `__init__` 中使用显式类名分别调用各父类的构造函数，并手动透传 `self`：

    ```python
    class WenjieCar(Car, HuaweiAI_Driven):
        def __init__(self, brand: str, model: str, color: str, owner: str, version: str = "ADS 2.0"):
            Car.__init__(self, brand, model, color, owner)
            HuaweiAI_Driven.__init__(self, version)
    ```

    * 同名方法聚合：若子类需要同时执行多个父类的同名动作，重写该方法并在内部依次使用 `父类名.方法名(self)` 显式触发。

## 多态机制与抽象基类契约

### 多态形态与鸭子类型

* **多态（Polymorphism）**

    * > **定义**：同一个方法调用在不同类型的对象上呈现出完全不同的行为形态。

    * 经典实现：基类声明统一接口（如 `Car.charge()`），不同子类分别重写（`FuelCar` 执行加油，`ElectricCar` 执行充电），消费端调度函数统一接收基类类型并调用该接口，运行时动态分发。

    * 架构收益：符合开闭原则（对扩展开放，对修改关闭），新增子类时无需调整已有的通用调度逻辑。

* **鸭子类型（Duck Typing）**

    * > **定义**：动态类型语言特有的多态哲学，关注对象的行为（能否响应特定方法或属性）而非其显式血统类型。

    * 核心格言：“如果它走起路来像鸭子，叫起来也像鸭子，那么在 Python 看来，它就是一只鸭子。”

    * 解耦特性：协同工作的各个类之间无需存在共同的父类或继承关系；只要各对象均实现了同名方法（如 `Duck`、`Dog`、`Pig` 均提供 `swimming()`），消费函数即可统一调用执行。

* **类型注解（Type Hinting）**

    * > **定义**：在函数形参或变量后使用冒号声明类型的辅助标注语法（例如 `def handle(car: Car):`）。

    * 运行机理：属于非强制性的文档与元数据标注，专为 IDE 智能提示与静态类型检查工具提供支持；Python 解释器在运行时不对实参类型进行强制拦截，不影响动态分发。

* 静态语言多态与鸭子类型特性对照：

| 维度 | 经典静态语言多态（Java / C++） | Python 动态多态（鸭子类型） |
| :--- | :--- | :--- |
| **继承依赖** | 强依赖统一的父类继承体系或接口契约 | 完全不依赖继承树，类与类之间可完全独立 |
| **校验时机** | 编译期强类型匹配，签名不符编译报错 | 运行时动态寻址，只要对象包含目标方法即可调用 |
| **关注核心** | 严格关注“你是谁（对象的类继承血统）” | 务实关注“你能做什么（对象的行为与方法契约）” |
| **扩展代价** | 新增对象必须实现预设接口，类间耦合度高 | 即插即用，只要具备匹配的方法即可无缝融入协同 |

### 抽象基类与接口强制契约

* **传统继承约束漏洞（Unenforced Base Method）**

    * 缺陷表现：普通基类中仅用 `pass` 声明的空方法对子类无强制实现效力。

    * 异常前置缺失：> **易错点**：⚠️ 子类若遗漏重写空方法仍可成功实例化，但进入具体业务逻辑时（例如执行 `len(books) >= self.get_max_books()`），继承获得的空方法默认返回 `None`，导致在运算比较时抛出 `TypeError: '>=' not supported between instances of 'int' and 'NoneType'`；且未完成的普通基类自身也可被直接实例化。

* **抽象基类（Abstract Base Class，ABC）**

    * > **定义**：只能被继承、绝对不能被直接实例化的特殊基类，专门用于规范子类必须遵循的公共行为接口。

    * 语法依赖：必须显式继承自标准库模块 `abc` 中的 `ABC` 基类（`class Member(ABC):`）。

    * 实例化约束：> **易错点**：⚠️ 任何直接调用抽象基类构造函数（如 `Member(...)`）的代码，解释器立即拦截并抛出 `TypeError: Can't instantiate abstract class Member with abstract methods`。

* **抽象方法装饰器（Abstract Method Decorator）**

    * > **定义**：标准库提供的 `@abstractmethod` 装饰器，专门标注在抽象基类中暂不实现、要求子类必须强制重写的方法上。

    * 拦截机制：若派生子类未完整重写所有被 `@abstractmethod` 标注的方法，在尝试实例化该子类的瞬间，解释器直接抛出 `TypeError: Can't instantiate abstract class SubClass with abstract method ...`，将潜在的运行时错误前置至对象构建期。

## 图书管理系统实体架构与业务实现

### 领域实体模型与持久化数据映射

* **持久化数据规约（JSON Data Specification）**

    * 书籍档案 `data/books.json`：存储图书静态指标，键名包含 `"编号"`（`book_id`）、`"标题"`（`title`）、`"作者"`（`author`）、`"数量"`（`total_number`）。动态在架可用数量（`available_number`）不在文件持久化，由内存对象初始化时设为总数。

    * 会员档案 `data/members.json`：键名包含 `"卡号"`（`card_id`）、`"姓名"`（`name`）、`"密码"`（`password`）；VIP 会员独有键名 `"会员等级"`（`vip_level`，缺省默认为 1）。

    * 会员类型识别规则：卡号以 `'N'` 开头为普通会员，以 `'V'` 开头为 VIP 会员。

* **图书实体（Book Entity）**

    * 状态定义：公有属性 `book_id`、`title`、`author`、`total_number`（或 `count`）；内部私有状态 `__available_number`（可用库存数量）。

    * 封装依据：可用数量属于核心易变状态，设为私有防止外部随意赋值导致库存超卖与数据撕裂。

    * 状态流转方法：

        * `borrow_book() -> bool`：若 `__available_number > 0` 则自减 1 并返回 `True`，否则拒绝借阅返回 `False`。

        * `return_book() -> None`：可用库存自增 1（`__available_number += 1`）。

        * `get_available_number() -> int`：公有只读访问器。

* **会员抽象体系（Member Hierarchy）**

    * 抽象基类 `Member(ABC)`：封装卡号 `member_id`、姓名 `name`、私有登录凭证 `__password` 与私有在借列表 `__borrowed_books`（直接聚合 `Book` 实体对象）。

    * 抽象契约：`@abstractmethod def get_max_books(self) -> int: pass`。

    * 普通会员 `NormalMember(Member)`：继承父类构造，重写限额方法固定返回常量 `3`。

    * VIP 会员 `VIPMember(Member)`：通过 `super().__init__(member_id, name, password)` 委派基础初始化，新增专属实例属性 `vip_level`；重写限额方法执行动态计算：
      $$\text{最大借阅数量} = 6 + \text{vip\_level}$$

* **借还事务校验机制（Borrow and Return Validation）**

    * 借书双重检查（`borrow_book(book: Book) -> bool`）：

        * 阶段一（个人配额）：核验 `len(self.__borrowed_books) >= self.get_max_books()`，超限直接阻断并返回 `False`。

        * 阶段二（图书物理库存）：调用 `book.borrow_book()`，若扣减成功则将 `book` 追加至 `__borrowed_books` 并返回 `True`，若库存为 0 阻断并返回 `False`。

    * 还书持有性断言（`return_book(book: Book) -> None`）：

        * 前置校验 `if book in self.__borrowed_books:`，确认为名下在借图书后，调用 `book.return_book()` 回补库存，并从列表中移除该对象。

        * 防御边界：若会员未借阅该书，拒绝执行任何库存操作并提示报错，防止虚增库存。

### 系统调度控制器与会话交互

* **控制器哈希索引（Controller Hash Indexing）**

    * 实体映射选型：`self.books: dict[str, Book]` 与 `self.members: dict[str, Member]`。

    * 性能权衡：摒弃线性列表遍历的 $O(n)$ 查找开销，利用图书编号与会员卡号作为哈希键，实现 $O(1)$ 常数级快速检索。

    * 会话跟踪：`self.current_member: Member | None = None`，用于暂存当前成功登录的会员实例，退出或未登录时置为 `None`。

* **数据载入与多态装配（Data Loading and Instantiation）**

    * 触发时机：绑定在 `LibrarySystem.__init__` 构造方法中自动触发 `load_books_data()` 与 `load_members_data()`，确保对象构建完成即处于高可用就绪状态。

    * 多态映射实现：

    ```python
    # 读取 members.json 列表并根据前缀多态实例化具体子类
    if card_id.startswith("N"):
        self.members[card_id] = NormalMember(card_id, name, password)
    elif card_id.startswith("V"):
        vip_level = member_item.get("会员等级", 1)
        self.members[card_id] = VIPMember(card_id, name, password, vip_level)
    ```

* **会话鉴权与重试机制（Session Guard and Retry）**

    * 鉴权流程：`login() -> bool` 方法运行在 `while True` 交互死循环中，先后执行卡号存在性校验与受控密码比对（`member.get_password() == password`）。

    * 重试容错：卡号不存在或密码错误时输出明确提示，并通过 `continue` 开启下一轮输入；验证通过后将对象绑定至 `self.current_member` 并执行 `return True`。

* **事件循环与模式匹配（Event Loop and Pattern Matching）**

    * 运行守卫：主入口 `run()` 实行前置鉴权守卫 `if self.login():`，认证未通过严禁暴露业务菜单。

    * 结构化路由：控制台打印标准操作菜单后，采用 Python 3.10+ 的 `match-case` 模式分发输入指令：

        * `case "1"`：调用 `self.borrow_book()`。

        * `case "2"`：调用 `self.return_book()`。

        * `case "3"`：调用 `self.show_borrowed_books()`。

        * `case "4"`：打印提示并执行 `break` 跳出循环终结进程。

        * `case _`：通配模式捕获非法选项并提示重选，自动流转至下一轮菜单刷新。

* **跨对象协作调度（Cross-Object Collaboration）**

    * 借还书委托：控制器仅负责根据用户输入的编号进行哈希存在性检验，随后直接执行 `self.current_member.borrow_book(book)` 或 `self.current_member.return_book(book)`。

    * 控制器去中心化：控制器不包含任何会员类别或库存增减计算的条件分支，全权交由 `Member` 多态实现与 `Book` 内部状态机自治流转。

    * 空态体验：查阅或还书前检查在借清单，若无在借书籍给出友好提示，避免控制台空白。

* **实战工程排错要点（Engineering Pitfalls）**

    * 字符串前缀 API 规范：判定前缀必须使用标准方法 `startswith()`；若误写为 `start_with()` 会触发 `AttributeError: 'str' object has no attribute 'start_with'`。

    * 格式化占位符防泄漏：f-string 的表达式界定符为纯花括号 `{}`，误写为 `${expr}` 会导致控制台原样输出带有前缀字符的字符串（如 `$周茹`）。

    * 交互控制流选型：带重试机制的交互循环中，校验失败必须使用 `continue` 保持迭代；若误用 `return False` 会导致整个系统非预期提前中断。
