# AI应用：Streamlit界面开发与多轮交互

## Streamlit 框架定位与运行环境

### 框架特性与适用边界

* **Streamlit Web 框架（Streamlit Web Framework, Streamlit）**

    * > **定义**：专为数据科学、机器学习与人工智能应用设计的开源 Python Web 框架，开发者无需原生前端技术栈即可通过纯 Python 脚本构建并发布交互式 Web 应用。

    * **核心特征**：极速原型化开发，前端浏览器渲染完全由 Python 脚本中的声明式 API 调用生成，底层屏蔽 HTML、CSS 与 JavaScript 编写细节。

    * **适用范围**：数据分析报告、数据可视化大屏、机器学习模型演示以及 AI 应用的原型界面。

    * **能力边界**：无法替代传统前端构建高并发、深度定制化或复杂业务链路的大型商业系统（如大型电商平台、复杂企业级管理系统）。

    * **官方文档查阅规范**：核心参考路径为 `Develop -> API reference`，分类包含文本元素（Text elements）、媒体元素（Media elements）、数据展示元素（Data elements）与用户输入组件（Inputs）；文档中参数 `body` 指代文本主体内容，`anchor` 指代组件锚点。

### 环境安装与标准开发流

* **Streamlit 标准开发流程（Standard Development Workflow）**

    * > **定义**：从依赖安装到本地 Web 服务构建并调起的四步工程闭环。

    * **执行链路**：
        ```text
        [1. 环境安装]              [2. 引入模块]            [3. 构建界面]            [4. 终端启动]
        pip install streamlit --> import streamlit as st --> st.title(...)  --> streamlit run app.py
                                                              st.write(...)           |
                                                              st.image(...)           v
                                                                                [浏览器访问 8501]
        ```

    * **依赖安装**：在命令行环境中执行 `pip install streamlit` 完成全局或虚拟环境安装。

    * **模块导入规范**：遵循社区约定引入模块并设置别名 `import streamlit as st`，后续页面元素统一通过 `st.<方法名>()` 声明。

### 服务端启动与网络监听

* **命令行启动机制（CLI Run Mechanism）**

    * > **定义**：Streamlit 应用程序专用的命令行引导与服务托管机制。

    * **运行命令**：必须在终端中执行专用命令 `streamlit run <脚本文件名>.py`；键入前缀后支持 Tab 键自动补全路径，包含空格或中文时终端自动添加双引号并带 `./` 前缀。

    * **网络监听特征**：底层基于 Tornado 架构启动 Web 服务器，默认占用 **8501** 端口，自动监听本地回环地址 `http://localhost:8501` 与局域网网络地址 `http://192.168.x.x:8501`，并自动唤起系统默认浏览器。

    * **界面主题配置**：右上角菜单“Settings”支持切换外观主题，包括系统跟随（Use system setting）、亮色主题（Light）与暗色主题（Dark），系统默认采用深色暗黑主题。

    * **运行时热重载（Hot Reloading）**：终端保持运行状态下，Python 脚本修改并保存后，浏览器直接点击刷新或启用 Always rerun 即可同步呈现最新页面效果，无需重启服务进程。

    * > **易错点**：⚠️ 严禁使用常规 Python 脚本的右键 Run 方式直接运行 Streamlit 程序；常规运行不会启动 Web 服务与浏览器，控制台会输出警告信息。

## 基础渲染与表单交互组件

### 标题层级与正文排版

* **层级标题组件体系（Hierarchical Title Elements）**

    * > **定义**：Streamlit 提供的按视觉权重与字号规范化排布的页面语义标题 API。

    * **API 层级映射**：
        | 方法名 | 对应的文档层级 | 样式特征与排版用途 |
        | :--- | :--- | :--- |
        | `st.title()` | 页面主标题 | 字号最大、权重最高，一般全页面仅使用一次，代表整个应用的名称 |
        | `st.header()` | 一级标题 | 字号次之，用于划分应用的主要功能大模块 |
        | `st.subheader()` | 二级标题 | 字号适中，用于一级大模块内部各个子任务或信息组的细分 |

    * **调用语法**：直接传入标题文本字符串，系统自动处理字号、粗细以及与后续组件的上下间距。

* **通用正文渲染器（st.write）**

    * > **定义**：Streamlit 内置的多类型自适应万能输出接口。

    * **不定长传参机制**：接收不定长参数 `*args`，支持直接解析纯文本字符串、字典、列表、NumPy 数组、Pandas 数据帧或 Matplotlib 图表。

    * **内置 Markdown 引擎**：当传入参数为字符串类型时，底层自动调用 `st.markdown()` 解析排版语法。

    * **段落封装特性**：每次调用 `st.write()` 输出文本均被封装为浏览器中的独立段落块，系统自动处理段前段后间距。

### 富媒体资源与品牌标识

* **多媒体呈现组件（Media Elements）**

    * > **定义**：将 HTML5 多媒体标签封装为单行函数调用的媒体渲染接口集合。

    * **静态资源规范**：建议在脚本同级目录建立专门的 `resources/` 文件夹存放媒体素材，脚本中通过相对路径引用（如 `resources/cat.jpg` 或 `./resources/cat.jpg`）。

    * **图片渲染器（st.image）**：唯一必填参数为图片路径；支持通过关键字参数 `width` 指定像素尺寸（如 `width=300`）；控件右上角原生集成无损全屏放大预览与恢复按钮。

    * **音频播放器（st.audio）**：自动生成交互式音频播放控件，内置播放/暂停、进度拖拽条、时间戳及音量静音调节滑块。

    * **视频播放器（st.video）**：自动渲染自适应视频播放窗口，支持平滑播放控制、音量调节以及右下角全屏最大化与还原。

* **全局品牌图标（st.logo）**

    * > **定义**：脱离常规正文线性排版流、固定锚定在页面全局品牌区域的网站 Logo 配置组件。

    * **视觉位置特征**：调用 `st.logo("resources/logo.png")` 后，当侧边栏展开时固定悬浮于侧边栏顶部，侧边栏折叠时平滑迁移并固定于主界面左上角边缘。

    * > **易错点**：⚠️ 设定全局品牌 Logo 必须调用 `st.logo()`；若错误调用 `st.image()`，图片会作为普通正文元素被混杂排版在页面的纵向线性内容流中。

### 结构化数据展示

* **静态二维表格组件（st.table）**

    * > **定义**：将 Python 基础复合字典或 Pandas 数据帧直接映射并渲染为规整静态二维网格的展示组件。

    * **复合字典映射原理**：
        ```text
        字典键名 (Key, str) -------->  [ 表头 Header ] :  姓名   |  学号  |  语文  |  数学
                                                      -------+-------+-------+------
        列表元素 (Value, list) ----->  [ 行 1 (Row 0) ] :  王林   | 10001 |   95  |   98
                                       [ 行 2 (Row 1) ] : 李慕婉  | 10002 |   98  |   92
        ```

    * **数据映射规则**：字典的每个键名（字符串类型）自动映射为表格顶部的列标题；键对应的列表元素按顺序自上而下填充对应列的单元格；表格最左侧自动生成从 `0` 开始递增的整数行号索引。

### 用户交互输入组件

* **单行文本输入框（st.text_input）**

    * > **定义**：用于采集终端用户单行短文本输入的交互表单组件。

    * **返回值与事件触发**：首个必填参数为输入框提示标签（Label），返回值为用户输入的字符串文本；用户在输入框中按下回车键（Enter）或鼠标移出失焦后，系统捕获输入值并触发脚本全量重新执行。

    * **密码隐藏模式**：传入关键字参数 `type="password"` 时，输入内容被黑色圆点掩码遮蔽，输入框右侧自动生成眼睛图标按钮，支持一键切换明文显示与掩码遮蔽。

* **单选按钮组件（st.radio）**

    * > **定义**：用于在互斥选项集合中采集单一选中值的枚举选择组件。

    * **互斥选择保证**：接收提示标签和候选选项列表（如 `["男", "女", "未知"]`），严格保证全局同时仅有一个选项处于激活选中态。

    * **默认勾选索引控制**：默认勾选列表索引为 `0` 的首项；通过关键字参数 `index` 可显式指定初始默认选中项（基于 0 的整数索引，如 `index=1` 默认勾选第二项）。

## 页面全局视口与 AI 对话交互框架

### 页面全局配置

* **顶层页面配置方法（st.set_page_config）**

    * > **定义**：用于设定浏览器标签页元数据、视口拉伸布局、侧边栏初始状态及右上角系统菜单的顶层控制 API。

    * **视口布局模式（layout）**：
        | 参数取值 | 页面表现形式 | 适用场景与技术特征 |
        | :--- | :--- | :--- |
        | `"centered"` | 内容区域限制在固定的居中宽度内，屏幕左右两侧留出等宽空白。 | 默认行为。适合长篇文本、学术论文排版、单栏轻量表单等阅读场景。 |
        | `"wide"` | 页面内容拉伸铺满整个浏览器水平视口，自适应各屏幕分辨率。 | 复杂交互系统、数据可视化仪表盘、多栏并排应用（如 AI 伴侣实战界面）。 |
        | `None` | 不做显式指定，系统自动回退至默认配置。 | 等价于缺省配置，底层依然按照 `"centered"` 进行渲染。 |

    * **标签页标识（page_title, page_icon）**：`page_title` 接收字符串定义浏览器标签页名称；`page_icon` 接收本地图片相对路径或 Unicode Emoji 表情字符（如 `"🤖"`）作为 Favicon 图标。

    * **侧边栏初始状态（initial_sidebar_state）**：可选 `"auto"`（自适应屏幕）、`"expanded"`（强制展开）与 `"collapsed"`（强制折叠）。

    * **系统菜单定制（menu_items）**：接收包含 `"Get help"`、`"Report a bug"`、`"About"` 的字典以重定向外部链接或定制关于模态框；传入空字典 `{}` 则清空所有自定义入口，仅保留底层设置功能。

    * > **易错点**：⚠️ `st.set_page_config` 必须作为 Python 脚本中调用的第一个 Streamlit 执行命令，紧随 `import` 语句之后放置；若此前存在任何渲染组件 API 调用，系统会抛出配置异常或直接忽略配置。

### AI 辅助编程环境搭建

* **通义灵码插件（TONGYI Lingma）**

    * > **定义**：阿里巴巴推出的多语言免费 AI 编程辅助工具，支持 PyCharm、VS Code 等 IDE 环境。

    * **工程研发分工定位**：基础语法阶段纯手敲代码以建立底层排错能力，项目实战阶段借助 AI 工具生成样板代码与 API 参数提示，工程师专注于系统架构设计与逻辑校准。

    * **安装与免密授权链路**：在 PyCharm 插件市场（Marketplace）检索“灵码”安装并重启 IDE；通过右侧工具栏面板呼出，选择个人版登录并通过阿里云账号或支付宝扫码完成免密授权。

    * **双交互形态**：右侧面板问答模式（Chat Mode）用于自然语言概念检索与代码骨架生成；编辑器行内预测补全（Inline Completion）通过后台感知上下文与注释，支持快捷键 `Alt + P` 强制唤起预测，按下 `Tab` 键一键采纳建议。

### 对话交互组件与双栏架构

* **AI 智能伴侣双栏拓扑（Dual-Column Layout Topology）**

    * > **定义**：将对话型应用划分为左侧侧边栏控制区与右侧核心主工作区的系统界面架构。

    * **双栏分区架构**：
        ```text
        +-------------------------------------------------------------------------+
        | [Logo] AI智能伴侣 (st.set_page_config: page_title, page_icon, layout)    |
        +-------------------+-----------------------------------------------------+
        | 左侧控制侧边栏    | 右侧核心交互展示区                                  |
        | (st.sidebar)      |                                                     |
        |                   |  st.title("AI智能伴侣")                             |
        |  [AI控制面板]     |  st.logo("resources/logo.png")                      |
        |  - 新建会话       |                                                     |
        |  - 保存会话       |  -------------------------------------------------  |
        |  - 历史会话列表   |  [对话消息展示流 (持续滚动更新)]                    |
        |  - 删除会话       |                                                     |
        |                   |  st.chat_message("user"):                           |
        |  ---------------- |    你好，你是谁？                                   |
        |  [伴侣设定]       |                                                     |
        |  - 伴侣姓名输入框 |  st.chat_message("assistant"):                      |
        |  - 伴侣性格输入框 |    你好，我是小甜甜，一个温柔可爱的AI助手。         |
        |                   |                                                     |
        |                   |  -------------------------------------------------  |
        |                   |  st.chat_input("请输入您要问的问题")                |
        +-------------------+-----------------------------------------------------+
        ```

* **聊天输入框（st.chat_input）**

    * > **定义**：专为对话场景设计、全局固定吸附在浏览器视口底部的用户交互输入组件。

    * **隐式布尔转换特性**：无输入时返回 `None`，提交时返回字符串；在 Python 中 `None` 与空字符串 `""` 在布尔语境下等价于 `False`，非空字符串等价于 `True`，通过 `if prompt:` 可同时拦截空提交与初始无输入刷新。

    * **变量命名规范**：声明局部变量 `prompt` 时需防范 IDE 自动补全误引入第三方库（如 `from click import prompt`）。

* **角色化消息容器（st.chat_message）**

    * > **定义**：用于承载特定发言主体内容并渲染原生头像与卡片气泡的对话容器组件。

    * **角色参数（name）**：传入 `"user"`（或 `"human"`）渲染用户默认头像与气泡；传入 `"assistant"`（或 `"ai"`）渲染大模型机器人头像与气泡。

    * **调用语法形态**：支持链式调用 `st.chat_message("user").write(prompt)`，或上下文管理器语法 `with st.chat_message("user"): st.write(prompt)`。

    * **输出边界**：`st.write` 负责将内容渲染至客户端浏览器 DOM 树；`print` 负责输出至服务端系统终端，用于后台数据流跟踪与联调。

## 会话状态管理与流式记忆交互

### 脚本重跑机制与状态持久化

* **响应式脚本重跑机制（Script Re-run Execution Model）**

    * > **定义**：Streamlit 框架的核心执行模型；当页面上的交互控件发生状态变更时（敲击回车、点击按钮、组件失焦），Streamlit 会将当前 Python 脚本自顶向下完整重新执行一遍。

    * **消息覆盖根因**：由于全脚本重新执行，普通 Python 局部变量在执行栈重置后丢失；若代码仅编写渲染最新捕获的单轮输入与输出，页面 DOM 会被重新生成的元素完全冲刷覆盖。

* **会话状态共享容器（st.session_state）**

    * > **定义**：Streamlit 提供的服务端内存级键值存储机制，用于在同一浏览器标签页的多次脚本重跑之间共享变量与状态数据，生命周期与当前会话绑定。

    * **读写语法**：支持属性点号 `st.session_state.key` 与字典索引 `st.session_state["key"]`，二者底层完全等效。

    * **防御式初始化规则**：
        ```python
        if "messages" not in st.session_state:
            st.session_state.messages = []
        ```
        必须使用 `if "key" not in st.session_state:` 包裹初始化语句，防止在脚本重跑流中对状态容器发生无意识的二次置空。

    * **消息结构与精简遍历渲染**：列表元素采用结构化字典 `{"role": "user"|"assistant", "content": "..."}`；重跑时通过单行精简写法分发渲染：
        ```python
        for message in st.session_state.messages:
            st.chat_message(message["role"]).write(message["content"])
        ```
        直接将字典中的 `role` 传给 `st.chat_message`，消除冗余的 `if-else` 分支判断。

### 大模型无状态与滚雪球会话记忆

* **滚雪球上下文机制（Snowballing Context Mechanism）**

    * > **定义**：客户端将自会话开启以来的所有历史交互记录全量回传给大模型作为先验上下文的技术方案。

    * **大模型通信机理**：大语言模型 API 基于标准 HTTP/HTTPS RESTful 协议，底层完全无状态（Stateless），服务端不保留会话上下文；若仅发送当前单轮提问，多轮对话上下文必然丢失。

    * **交互时序推进**：
        ```text
        [第 1 轮交互]
        客户端发送: [System, User1]
        模型端响应: Assistant1

        [第 2 轮交互 (滚雪球累加)]
        客户端发送: [System, User1, Assistant1, User2]
        模型端响应: Assistant2

        [第 3 轮交互 (滚雪球继续膨胀)]
        客户端发送: [System, User1, Assistant1, User2, Assistant2, User3]
        模型端响应: Assistant3
        ```

    * **星号列表解包运算（Asterisk Unpacking, `*`）**：
        ```python
        messages = [
            {"role": "system", "content": system_prompt},
            *st.session_state.messages
        ]
        ```
        利用 `*` 运算符将历史列表打散并平铺进新列表中，杜绝列表嵌套；在执行解包前已将本次提问追加至 `st.session_state.messages` 末尾，请求报文天然满足首项为人设、中间为历史上下文、末项为本次提问的时序要求。

### 流式通信与动态占位渲染

* **流式通信协议（Server-Sent Events, SSE）**

    * > **定义**：服务端通过建立单向持久 HTTP 通道，将大模型生成的 Token 增量以数据包序列（Chunks）持续推送至客户端的通信机制。

    * **通信模式比对**：
        | 比较维度 | 非流式响应（`stream=False`） | 流式数据块（`stream=True` 产生的单个 Chunk） |
        | :--- | :--- | :--- |
        | **传输形态** | 单次 HTTP 完整响应包 | 多个 SSE 数据帧分片持续推流 |
        | **主体字段** | `response.choices[0].message` | `chunk.choices[0].delta` |
        | **文本内容** | `message.content`（全量完整字符串） | `delta.content`（当前分片的单字或词组增量） |
        | **数据完成度** | 拿到的即为终态结果 | 每次仅代表一个细微的瞬时切片 |

    * > **易错点**：⚠️ 开启 `stream=True` 后，接口返回对象从静态 ChatCompletion 变为流生成器迭代对象（Stream Generator）；沿用非流式模式下的 `response.choices[0].message.content` 读取将抛出 AttributeError 异常。

* **单元素占位容器（st.empty）**

    * > **定义**：在页面当前物理位置插入空白占位符并返回对象句柄的容器组件，对该句柄重复执行渲染会直接原地覆写替换旧内容，绝不生成冗余 DOM 节点。

    * **流式渲染演进与陷阱排查**：
        * *循环外聚合渲染（假流式）*：循环内累加字符串而在循环外一次性输出，用户依然面临长时间无反馈空白等待。
        * *循环内直接调用 chat_message（消息风暴）*：循环内每次产生 Token 均调用 `st.chat_message`，导致屏幕生成上百个递增冗余气泡框。
        * *empty 原地更新（标准方案）*：
            ```python
            response_message = st.empty()
            full_response = ""
            for chunk in response:
                if chunk.choices[0].delta.content is not None:
                    content = chunk.choices[0].delta.content
                    full_response += content
                    response_message.chat_message("assistant").write(full_response)
            st.session_state.messages.append({"role": "assistant", "content": full_response})
            ```
            在占位容器内原地刷新累加文本实现打字机视觉，流式传输结束后将完整文本追加归档至 `session_state`。

## 侧边栏控制面板与会话管理架构

### 侧边栏容器布局与语法

* **侧边栏命名空间（st.sidebar）**

    * > **定义**：Streamlit 提供的用于将系统配置与状态管理组件从主视口剥离、挂载至页面左侧独立面板的容器模块。

    * **语法形态比对**：
        | 语法形态 | 核心写法 | 优势 | 潜在缺陷 |
        | :--- | :--- | :--- | :--- |
        | **链式调用** | `st.sidebar.<component>()` | 单个组件声明直观，无需代码缩进。 | 多组件时代码冗长，遗漏 `sidebar` 会导致渲染漂移至主区。 |
        | **上下文管理器** | `with st.sidebar:` | 代码结构块状清晰，作用域明确，契合复杂侧边栏工程开发。 | 需要一层代码缩进。 |

    * **折叠响应与图标联动**：侧边栏右上角提供折叠箭头（`<<` / `>>`）；`st.logo` 在侧边栏展开时固定于其顶部，折叠后自动迁移至主界面左上角边缘。

### 伴侣属性组件与动态人设注入

* **伴侣人设组件选型（Widget Selection）**

    * > **定义**：根据采集文本长度与排版特性选用的侧边栏表单组件组合。

    * **单行文本输入（st.text_input）**：用于伴侣昵称输入，保持侧边栏视觉紧凑。

    * **多行文本域（st.text_area）**：提供垂直方向可拉伸文本编辑区域，支持输入长句与回车换行，用于伴侣性格设定。

    * **核心参数规范**：
        * `placeholder`：输入框为空时展示的半透明灰色提示词，点击聚焦输入字符后自动隐藏。
        * `value`：组件首次挂载渲染时的初始默认文本，默认为空字符串 `""`。

* **提示词模板化与动态人设注入（Dynamic Prompt Injection）**

    * > **定义**：将固定规则沉淀为占位符模板，并在运行时动态注入侧边栏配置变量的大模型人格生成机制。

    * **系统提示词七大拟人规则**：单条回复约束、禁止场景或状态描述性文字、匹配用户语言风格、回复简短如微信聊天、适度使用 Emoji、口吻契合伴侣性格、具象化地域性格特征。

    * **状态双向绑定与模板格式化实现**：
        ```python
        # 1. 初始化并双向绑定状态
        if "nickname" not in st.session_state:
            st.session_state.nickname = "小甜甜"
        if "nature" not in st.session_state:
            st.session_state.nature = "活泼开朗的东北姑娘"

        with st.sidebar:
            st.subheader("伴侣信息")
            nickname = st.text_input("昵称", value=st.session_state.nickname)
            if nickname:
                st.session_state.nickname = nickname
            nature = st.text_area("性格", value=st.session_state.nature)
            if nature:
                st.session_state.nature = nature

        # 2. 动态格式化注入大模型
        current_system_prompt = SYSTEM_PROMPT_TEMPLATE % (
            st.session_state.nickname, 
            st.session_state.nature
        )
        messages = [{"role": "system", "content": current_system_prompt}]
        ```

### 多会话生命周期与数据持久化

* **会话持久化架构（Session Persistence Architecture）**

    * > **定义**：将易失性内存中维护的对话状态、元数据与消息流序列化保存到磁盘文件中，以实现服务重启不丢失与多会话切换隔离的系统架构。

    * **存储介质权衡**：`st.session_state` 属于服务端内存存储，读写响应极快，但进程重启、代码保存或刷新页面会导致数据归零；磁盘 JSON 文件存储具备非易失性，支持抗断电、跨会话留存与持久化读取。

* **会话标识与文件命名策略（Session Identification & Naming）**

    * > **定义**：采用会话建立时的精确时间戳作为磁盘文件唯一标识的命名方案。

    * **命名范式**：以 `20260109_160520.json` 形式命名文件。

    * **技术优势**：保证全局唯一性避免命名冲突；具备天然时间有序性，文件遍历时直接按文件名自然排序即可实现历史会话倒序排布；具备高可读性，可直接作为前端侧边栏历史会话列表条目的展示标题。

* **新建会话生命周期时序（New Session Lifecycle）**

    * > **定义**：触发新建会话操作时底层执行的两阶段事务逻辑。

    * **时序推进链路**：
        ```text
        [用户点击 "新建会话" 按钮]
                  │
                  ▼
        [步骤 1: 归档当前活动会话]
          ├─ 检查当前会话是否存在未保存的交互记录
          └─ 将 messages、nickname、nature 等完整快照写入当前磁盘文件
                  │
                  ▼
        [步骤 2: 初始化全新活动会话]
          ├─ 生成全局唯一的新会话时间戳文件名 (如: 2026-01-09_16-05-20.json)
          ├─ 重置内存中的 messages 消息列表为空列表 []
          └─ 立即在磁盘上创建并落盘该新会话的基础骨架文件
                  │
                  ▼
        [步骤 3: 触发界面全量重绘 (Rerun)]
          └─ 历史会话列表呈现新条目，右侧交互区呈现清空后的对话初始态
        ```

    * **执行时序准则**：必须执行“先持久化当前旧会话快照，再创建并挂载新会话标识”的两阶段事务逻辑，防止当前活动上下文发生静默丢失。

* **会话持久化数据结构（Session JSON Schema）**

    * > **定义**：固化保存于本地磁盘的标准化 JSON 会话快照数据契约。

    * **JSON 结构范式**：
        ```json
        {
          "messages": [
            {
              "role": "user",
              "content": "今天好累啊"
            },
            {
              "role": "assistant",
              "content": "抱抱你，辛苦啦！晚上给你炖排骨补补~"
            }
          ],
          "nickname": "小甜甜",
          "nature": "活泼开朗的东北姑娘",
          "current_session": "2026-01-09 16:05:20"
        }
        ```

    * **字段职能契约**：
        | 字段名称 | 数据类型 | 业务职能与不可或缺性分析 |
        | :--- | :--- | :--- |
        | `messages` | `list[dict]` | 承载用户与 AI 大模型交互的全部历史记录，每一项为一个包含 `role` 与 `content` 的字典。用于在切换回该会话时，完整复原主界面的气泡消息流并续接上下文。 |
        | `nickname` | `str` | 记录当前会话下定制的伴侣姓名。用户在不同会话中完全可能创建不同名字的伴侣，还原会话时必须同步还原名字输入框。 |
        | `nature` | `str` | 记录当前会话下定制的伴侣性格。切换会话时必须还原该会话专属的人设性格与语言风格，否则将导致人设错乱。 |
        | `current_session` | `str` | 当前会话的唯一标识与名称（基于时间戳生成），用于系统内部校验与前端高亮定位。 |
