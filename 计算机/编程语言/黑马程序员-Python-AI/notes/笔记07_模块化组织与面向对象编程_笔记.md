# 模块化组织与面向对象编程
## 模块与模块化组织


### 模块的定义与两类来源

* **模块（module）**
    * > **定义**：每一个以 `.py` 结尾的 Python 文件就是一个 Python 模块
    * 模块是 Python 程序开发的基本组织单位，一个项目可以包含若干个模块。
    * 模块内部可以定义变量、函数、类以及其他任何可执行的代码。
    * 每个 Python 文件都有自己独立的一套名字，A 文件里定义的名字默认对 B 文件不可见；跨文件调用必须先导入。
    * 未导入时表现：开发工具提示「未解析的引用」，右键执行报「名字为 `circle_area` 的函数未定义」。

* **自定义模块与内置模块**
    * 自定义模块指项目自己定义的模块，模块名就是文件的名字，写导入语句时不带 `.py`。
    * 内置模块（标准库）由 Python 官方提供，常用代表：`math`（数学运算）、`random`（随机数）、`os`（操作系统相关信息）、`sys`（系统层面参数信息）、`datetime` 与 `time`（时间日期）、`csv`（读写 csv 文件）。
    * 两类模块并列，导入语法完全相同；想用模块就必须先导入，不导入用不了。

### 模块化的收益与名字边界

* **模块化的三重收益**
    * 提高代码复用性：常用功能已封装成模块，导入调用即可，不必重写。
    * 降低开发门槛：官方内置模块数量足够多，不必逐个从零实现，开发成本与门槛一起下降。
    * 避免命名冲突：命名冲突的排查范围从整个项目缩小到同一个模块内部，只需保证单模块内名字不冲突、不重复。

* **拆模块的现实动因**
    * 不按功能与职责拆分的后果：一个项目组可能几十号甚至上百人改同一个文件，不便于团队协作开发，也不便于项目后期维护。
    * 常规做法是按功能模块和代码职责把项目拆成若干模块，每个模块承担自己的职责。
    * 真实项目拆分的职责示例：`config` 承载项目配置信息，`session` 管理会话信息，`ai_partner` 承载主干逻辑。

## 导入模块的语法与调用形式


### 导入整模块与导入指定功能

* **整模块导入（`import 模块名`）**
    * 语法最短，`import` 后面跟模块名；要一次性导入多个模块，模块名之间用逗号分隔，如 `import random, os`。
    * 进来看见的是整个模块，取用功能必须走「模块名.功能名」，点号后的功能名用来指定调用模块里的哪一个功能。

* **指定功能导入（`from 模块名 import 功能名`）**
    * `from` 后面是功能的出处，`import` 后面才是功能本身；多个功能名之间用逗号分隔，如 `from random import randint, choice`。
    * 进来看见的是功能本身，调用处直接写功能名，`my_function.` 这类前缀可整个省掉。
    * 「功能」的范围包括变量、函数、类、方法。
    * > **易错点**：`from 模块名 import 功能名` 之后调用不能再加模块名，写成 `random.randint(...)` 会报错。
    * > **易错点**：没有导入的功能就是不能调用，只导入了 `log_separator1` 与 `log_separator3` 时调用 `log_separator2` 会直接报错。

* **调用形式的判定规则**
    * 只看 `import` 后面写的是模块还是功能：写模块，调用要带模块名（或别名）；写功能，调用直接写功能名。
    * `import *` 导入的仍是功能本身，因此同样直接写功能名调用。

### 别名写法与通配导入

* **别名（`as`）**
    * 起别名的语法是在后面加 `as 别名`，模块与功能都适用：`import random as rd`、`from random import randint as rint`。
    * 起别名后导入的仍然是原来那个模块或功能，只是名字变了：模块起别名后调用必须走别名（`rd.randint(1, 100)`），原来写 `random.randint(...)` 反而不对；功能起别名后原来的功能名也不能再用。

* **通配导入（`from 模块名 import *`）**
    * `import` 后面直接写 `*`，星号是通配符，代表该模块里的功能集合。
    * 导入之后调用直接写功能名。
    * > **易错点**：导入所有功能并不等于该模块的所有功能都会进来，`import *` 的实际范围可能被自定义模块里的 `__all__` 收窄，标准库模块自己也做了同样的控制。

### 导入语句的位置约定

* **`import` 写在文件最上面**
    * 约定：`import` 导入语句写在整个 Python 文件的最上面，具体可执行的代码写在导入语句下面。
    * 理由有两条：打开文件一眼就能看清用到了哪些模块，不用翻到中间去找；模块操作一定是先导入再使用，导入放最上面下面的代码自然能直接用。
    * > **提示**：这条位置约定不是语法强制而是可读性约定，写到文件中间程序多半还能跑，只是读代码的人得自己去找依赖。

* **未使用的导入与断点提示**
    * 某句 `import` 写完后呈灰色，说明模块导入进来却没有被使用，开发工具用颜色提醒。

## 自定义模块的导入行为


### 模块内的常量与功能定义

* **常量（constant）**
    * 常量指不会发生变化的数据；常量名称全部大写是 Python 的命名约定，如 `PI = 3.1415926`、`NAME = "黑马涛哥"`。
    * > **易错点**：Python 当中并没有严格意义上的常量，名字全大写后本质上仍是变量，照样可以被修改；全大写只是提醒后面不要再改这两个数据。

* **字符串重复输出**
    * `"- " * 30` 让「横杠加空格」重复输出 30 次，最终在一行里输出 30 遍；想输出 50 次把 `30` 改成 `50`。
    * 这种写法的好处是不用手动往后拉一串横杠，也不用担心数错个数。
    * 模块里只定义函数而不写调用语句时，直接运行该模块什么都不会输出，想让函数执行必须在下面写调用。

* **模块名与文件名的对应与命名建议**
    * 模块的名字就是文件的名字，导入时只写文件名、不带 `.py`。
    * > **注意**：文件名可以是中文也可以是英文，但项目开发中建议按 Python 标识符的定义规范命名，不建议使用中文——运行没问题，真实项目里几乎见不到中文文件名。

### 导入执行顶层代码与测试代码保护

* **导入即执行模块顶层代码**
    * 用 `import` 把模块导入进来时，模块当中的代码是会执行的：导入的不只是常量与函数定义，还有写在顶层的可执行代码。
    * 现象：`main.py` 里并没有调用 `log_separator1`，输出里却多出一道横杠；把那句顶层调用注释掉再运行，多出来的横杠就消失。
    * 删除或注释测试代码的办法行不通，下一次要再测这个模块还得恢复回来，来回折腾。

* **`__name__`（双下划线内置变量）**
    * > **定义**：`__name__` 是 Python 的内置变量，表示当前模块的名字；凡是前后都带双下划线的变量或方法都是特殊的内置变量或方法
    * 取值分岔：直接运行当前模块时值为字符串 `"__main__"`；该模块被别的模块导入时值就是模块名（即文件名）。
    * 用法：把测试代码放进 `if __name__ == "__main__":` 条件里，只有当前模块被直接运行时才执行，被导入时不执行。
    * 该变量不需要自己定义，直接就能用。
    * > **提示**：在开发工具里输入 `main` 会出现快捷方式，选中后自动生成 `if __name__ == "__main__":` 结构。

* **两个模块级特殊变量对照**

| 特殊变量 | 取值规则 | 作用 |
| :--- | :--- | :--- |
| `__name__` | 直接运行本模块时为 `"__main__"`，被导入时为模块名 | 判断当前模块是被直接运行还是被导入，用来保护测试代码 |
| `__all__` | 模块中定义的字符串列表 | 指定 `from 模块名 import *` 到底导入哪些功能，不影响导入具体功能 |

### 星号导入范围的控制

* **`__all__` 的写法与生效范围**
    * `__all__` 是前后各两个下划线的模块级特殊变量，作用是指定 `from 模块名 import *` 里星号通配了哪些功能。
    * 写法：写在模块最上面，后面跟一个列表，列表里以字符串形式写明要让星号带出去的功能，如 `__all__ = ["log_separator1", "log_separator3", "PI"]`。
    * 边界：`__all__` 只影响星号的导入范围，正常导入具体功能不受它影响——明确写 `from my_function import NAME` 照样能导进来。

* **星号范围的判定与标准库佐证**
    * 判定规则：模块里定义了 `__all__`，导入的就是列表里指定的那些功能；没有定义，导入的才是整个模块的所有功能。
    * 实测表现：`__all__` 里没有 `NAME`，`main.py` 里用到 `NAME` 的位置立刻报错、强行执行提示 `NAME` 未定义；不在列表里的 `log_separator2`、`log_separator4` 同样报未定义。
    * 标准库佐证：按住 `Ctrl` 点击 `random` 跳到源码 `random.py`，能见到 `__all__`，它就是一个列表，其中每个字符串元素指定的正是 `from random import *` 中星号代表的功能。

## 软件包与包的导入


### 包的本质与 `__init__.py`

* **软件包（package）**
    * > **定义**：软件包本质上就是一个文件夹，文件夹下可以存放若干个 Python 文件，而每一个 Python 文件都是一个模块
    * 作用是对模块做归类处理（数据处理、网络应用开发、常见工具操作各归一类），便于项目管理、开发与后期维护。
    * 层级关系：包的内层是一个个模块，模块内部才是一个个具体功能（变量、常量、函数等）；也可把包看成一个模块，而这个模块下包含若干子模块。
    * 判定规则只有一条：文件夹里有 `__init__.py` 就是 Python 软件包，没有这个文件就只是个普通文件夹。

* **包结构示意图**

    ```text
    utils/                  <- 包（文件夹 + __init__.py）
    ├── __init__.py         <- 包的描述文件
    ├── my_var.py           <- 模块：常量 PI、NAME
    └── my_function.py      <- 模块：函数 log_separator1 ~ 4
    ```

* **`__init__.py` 的作用**
    * 作用一是标识当前目录是一个包而不是普通文件夹：这个文件一出现在文件夹下，图标就从普通文件夹变成带小圆点的包。
    * 作用二是描述当前包的信息，包括声明 `__all__` 特殊变量以指定 `import *` 导入哪些模块。
    * 内容不是必须的，什么都不定义完全可以；也可以写包信息，如 `__version__ = "1.0.0"`（包版本）与 `__author__ = "黑马涛哥"`（包作者）。
    * 项目开发中该文件有时还会完成初始化环境准备的工作。

* **包的创建方式**
    * 方式一：右键新建 Python 文件，文件名写成两个下划线 + `init` + 两个下划线，回车后 `__init__.py` 即建好。
    * 方式二：在文件夹上右键新建，菜单里选 **Python 软件包**（图标前带一个小圆圈），随便起名如 `abc` 回车，文件夹里自动多出一个内容为空的 `__init__.py`。

### 导入包中模块的五种形式

* **五种写法与调用方式**
    * 与导入模块的语法类似，变化在于模块名前面多了一级包名，原来写模块的地方现在写成 `包名.模块名`。
    * 前三种导入的都是模块，后两种导入的是模块当中的功能。
    * 调用形式遵循同一条规律：`import` 后面写的是包名加模块名就带上包名和模块名，写的是模块名就只带模块名，写的是功能名就直接写功能名。

* **五种形式对照表**

| 形式 | 语法 | 调用方式 | 导入对象 |
| :--- | :--- | :--- | :--- |
| 一 | `import 包名.模块名` | `包名.模块名.功能名` | 整个模块 |
| 二 | `from 包名 import 模块名` | `模块名.功能名` | 包下的指定模块 |
| 三 | `from 包名 import *` | `模块名.功能名` | 包下的所有模块 |
| 四 | `from 包名.模块名 import 功能名` | `功能名` | 模块中的指定功能 |
| 五 | `from 包名.模块名 import *` | `功能名` | 模块中的所有功能 |

* **导入整模块与导入指定模块的调用差异**
    * `import utils.my_function` 的调用形式是三级——包名、模块名、功能名，如 `utils.my_function.log_separator1()`。
    * 直接写 `import my_function` 会没有提示并且报错，因为该模块在 `utils` 这个包下面，导入时必须把包名带上。
    * `from utils import my_function` 时 `import` 后面是模块名，调用处不再需要包名，写「模块名.功能名」就够。
    * `from utils.my_function import log_separator1, log_separator3` 导入的是功能，调用时直接写功能名。
    * > **提示**：第一种写法偶尔会遇到开发工具提示「找不到 my_function」但程序依然正常运行，那是工具静态分析的问题，语法本身没问题。

### 包星号导入的条件与路径写法

* **`from 包名 import *` 的前置条件**
    * 该写法默认不允许直接使用：把调用代码原样搬过来会报未解析的 `my_function`，运行时提示 `my_function` 未定义。
    * 解决办法是在 `__init__.py` 中声明 `__all__` 指定星号代表哪些模块，如 `__all__ = ["my_function", "my_var"]`；补上之后报错处立刻恢复正常。
    * 列表里去掉 `my_var`，星号就只带进 `my_function`，`my_var` 用不了。
    * > **易错点**：要通过 `from 包名 import *` 导入包下所有模块，必须在 `__init__.py` 中声明 `__all__`，没有这个变量导入就会失败。

* **`from` 后面是路径：相对与绝对**
    * `from` 后面那一串「包名.模块名」其实是一种路径的写法，写法不同决定查找起点不同。
    * 相对路径从当前 Python 文件所在目录找起：文件在包含 `utils` 的目录下时 `from utils.my_function import ...` 正常，把文件移到 `my_module` 目录下立刻报未解析的引用 `utils`，移回原目录报错消失。
    * 绝对路径从项目根目录开始找：`from 第二章.utils.my_function import log_separator1`，先找第一级目录 `第二章`，其下有包 `utils`，包下有模块 `my_function`，因此文件移到目录外面依然能正常运行。
    * 两种写法都可以用，选哪种取决于文件放在哪里、想不想让代码对目录位置敏感。
    * > **提示**：中文文件夹名、包名与文件名运行起来没问题，但实际项目开发中一般都是英文。

* **包相关结论的收束**
    * 包的本质是一个文件夹，用来管理 Python 当中的多个模块，通过归类处理方便项目管理与后期维护。
    * 导入包的方式多种多样，特别要注意导入包下所有模块必须在 `__init__.py` 中声明 `__all__`。
    * 模块在实际项目中的应用场景以及一些高级用法，会在后面的案例中继续剖析和使用。

## 面向对象编程的思想与基本概念


### 面向过程与面向对象

* **面向过程编程（Procedural Programming）**
    * > **定义**：面向过程编程把一个大的需求拆解为一系列要执行的细化步骤，然后按照步骤依次执行这些任务
    * 关注点在「流程」和「步骤」上——先分析第一步做什么、第二步做什么，再按分析出的步骤一步步把需求实现出来。
    * 适用场景是简单的、线性的任务，对这类任务分析步骤后逐步完成即可。

* **建房的步骤拆解示意**

    ```text
    盖一栋房子（面向过程的拆解）

      1. 平整地基
           |
           v
      2. 在地基当中打桩
           |
           v
      3. 浇筑地基
           |
           v
      4. 主体施工
           |
           v
      5. 砌墙
           |
           v
      6. 外墙施工（外立面）
           |
           v
      7. 室内硬装
           |
           v
      8. 室内软装
    ```

* **面向对象编程（Object-Oriented Programming，OOP）**
    * 关注点在「谁来帮我做这件事」：要打地基就让推土机对象帮我推平、挖掘，要浇筑就让水泥罐车对象帮我浇筑。
    * 组织方式是像指挥者一样，谁能帮我干这件事就让谁来做，调用对象的方法完成操作。
    * 面向对象是 Python 核心语法的最后一个部分，分「面向对象基础」与「面向对象高级」两段，高级部分讲封装、继承、多态。

* **两种编程方式对照**

| 对比项 | 面向过程编程 | 面向对象编程 |
| :--- | :--- | :--- |
| 关注点 | 需求实现的流程与步骤 | 谁来帮我完成这件事 |
| 组织方式 | 把需求拆成一系列步骤依次执行 | 把特征与功能打包成对象，再指挥对象去做 |
| 写法特点 | 直接、偏向线性推进 | 像指挥者，调用对象的方法完成操作 |
| 适用场景 | 简单的、线性的任务 | 以对象为基本单元组织的程序 |

### 对象、属性与方法

* **对象（object）**
    * > **定义**：把一个人或者物的特征与功能打包到一起，就组成了一个对象；对象是面向对象编程的基本单元
    * 对象可以简单理解为现实当中具体的人或者物，是这些人和物数字化的化身，「万物皆对象」。
    * > **易错点**：说到「对象」时要同时想到模板与产物两层含义，类是模板，对象是基于这个模板制造出来的实际物品，别把两者混为一谈。

* **属性与方法**
    * 对象由属性和方法构成：属性是对象的特征，方法是对象所具备的功能。
    * 属性示例：推土机的颜色、油耗、马力；水泥罐车的容量、颜色、臂长；工人的工种、年龄、工服颜色、技能。
    * 方法示例：推土机的推平、挖掘；数据容器部分讲过的 `list`、`set`、字典、元组各自的方法也是对象的方法——每种数据容器其实都是一种对象。

### 类与对象的关系

* **类（class）**
    * > **定义**：类（class）是描述一组具有相同属性和方法的模板
    * 类描述的是一组具有相同特征和相同功能的模板，特征在面向对象中叫属性、功能叫方法。
    * 类名遵循大驼峰命名法，如 `Car`、`UserInfo`、`UserAccounts`。

* **对象与实例化**
    * 对象是类的实例，是基于类创建出来的，也叫实例对象；实例是按图纸造出来的具体、实际的东西。
    * 创建对象的这个过程称为对象的实例化，写法是类名后面跟一对小括号。
    * 一个类可以实例化出多个对象，一个类可以创建出无数个对象；同一套类构建出来的对象具备的属性都一样，只是属性值不一样。

* **类与对象关系示意**

    ```text
            类 Car：一组具有相同属性和方法的模板
            +--------------------------------+
            |  属性（特征）                  |
            |  方法（功能）                  |
            +---------------+----------------+
                            |
                            | 实例化：类名 + 小括号
                            v
          +-----------------+-----------------+
          |                 |                 |
          v                 v                 v
       对象 c1           对象 c2           对象 c3 ...
    ```

### 面向对象基础的内容构成

* **学习路线与各块解决的问题**
    * 类与对象解决如何构建一个类以及如何基于类创建出对应的对象。
    * 实例方法是对象当中的方法之一；魔法方法也是对象当中的方法之一。
    * 对象当中的属性指实例属性与类属性；最后用一组小案例加深对面向对象基础语法的理解与掌握。

* **后续内容的衔接**
    * 面向对象高级部分的内容——封装、继承、多态——在后面详细讲解。

## 类的定义与对象创建


### 类名规范与最简单的类

* **大驼峰命名法（UpperCamelCase）**
    * 类名遵循大驼峰命名法：每个单词的首字母都是大写，多个单词之间没有分隔符，直接拼接在一起。
    * 示例：`user` + `info` 得 `UserInfo`；`user` + `accounts` 得 `UserAccounts`。
    * 变量名与函数名不以大写开头，按小写字母加下划线书写，如 `c1`、`c_brand`、`total_cost`。
    * > **提示**：类名用大驼峰，变量名和函数名用小写字母加下划线，两套规范不要混用。

* **最简单的类与对象创建**
    * 定义类用关键字 `class`，后跟类名与冒号，缩进代码块里定义类的结构。
    * 结构什么都不定义时要保证语法完整，在代码块里写一个 `pass` 空语句，如 `class Car:` 换行缩进 `pass`。
    * 创建对象的语法是前面写一个对象名（变量名），后面基于类构建对象，写法是类名加上一对小括号，如 `c1 = Car()`。

### 动态添加属性的问题

* **`对象名.属性名` 动态添加属性**
    * 写法是 `对象名.属性名 = 属性值`，一个对象可以添加多个属性，有多少个就在后面继续写多少个。
    * 示例：`c1.color = "红色"`、`c1.brand = "BMW"`、`c1.name = "X5"`、`c1.price = 500000`。

* **不推荐在创建完对象后动态添加属性**
    * > 结论：不推荐在创建完对象之后动态地为对象添加属性
    * 理由是会降低项目的可读性、代码的可读性与可维护性，并增加开发难度。
    * 更关键的是类描述的就是一组具有相同属性和方法的模板，而这样写并没有起到模板的作用：每个对象有哪些属性是创建完对象之后自己添加上去的，调用对象时不便于管理和维护。

### `__init__` 与属性声明

* **函数与方法的区别**
    * > 结论：方法本质还是一个函数，区别只在于编写的位置——定义在类的里面就称为方法，定义在类的外面就称为函数
    * 推荐写法里的 `__init__` 定义在类的里面，所以它是一个方法，用来指定这个类所创建出来的实例对象有哪些属性。

* **`__init__` 初始化方法**
    * `__init__` 是初始化方法，方法名固定，前后各两个下划线。
    * 它在对象创建后自动调用，不是手动调用，而是对象创建完毕后由 Python 解释器自动调用。
    * 它用来设置对象的初始状态，当前主要是设置对象的属性，也可以完成其他一些初始化的操作。

* **`self` 参数与属性赋值写法**
    * `__init__` 形参列表当中的第一个形参必须是 `self`，它代表所创建出来的对象实例、代表当前对象；接触过 Java 或 JS 的话，它相当于那里的 `this`。
    * 在 `__init__` 里通过 `self` 为属性赋值，写法是 `self.属性名 = 参数名`，有多个属性就逐个赋值。
    * 示例：`self.brand = c_brand`、`self.name = c_name`、`self.price = c_price`。

* **创建对象时的参数传递**
    * 类中增加 `__init__` 之后，创建对象时类名后的小括号里要指定参数列表，这些参数最终传递给 `__init__` 的形参列表。
    * 形参列表里定义了多少个参数（`self` 不算），实例化对象时就要指定多少个参数；少传直接报错，提示缺少这几个参数。
    * 示例：`c1 = Car("BMW", "X5", 500000)`，三个值按位置分别传给 `c_brand`、`c_name`、`c_price`。
    * > **提示**：`self` 代表当前创建出来的实例对象，基于类构建对象时这个参数不用传递。

* **以 `__init__` 声明属性的完整写法**
    * 展开写法：`def __init__(self, c_color, c_brand, c_name, c_price):` 中形参名统一加 `c_` 前缀，是为了与属性名区分开——`c_brand` 这些是传进来的参数值，`color`、`brand` 这些才是对象的属性。
    * 创建对象时小括号里传四个参数（`self` 不用管），如 `c1 = Car("红色", "BMW", "X7", 800000)`。
    * 运行后初始化方法的 `print` 输出说明构建实例对象时确实调用了 `__init__`，属性随之赋值。

### 对象的输出与属性查看

* **直接输出对象得到内存地址**
    * 直接输出对象得到的是对象的内存地址，它是十六进制数，形如 `<__main__.Car object at 0x0000...>`。
    * 逐段解读：`Car` 代表该对象由哪个类创建出来，即它是 `Car` 这个类型的；`object` 代表这是一个对象实例；`at` 后面的 `0x...` 是内存地址。
    * 对象创建后在内存中要占用内存空间，每块内存区域都有地址指向它；每次运行程序这个内存地址都会发生变化。
    * 十六进制用 0 到 9 再加上 `a b c d e f` 描述，十进制只用 0 到 9。

* **`__dict__` 查看全部属性**
    * `__dict__` 是 Python 当中用户自定义实例对象的一个特殊属性，以字典形式存储对象当中所有的属性——把属性与属性值以键值对形式存起来。
    * 示例输出：`{'color': '红色', 'brand': 'BMW', 'name': 'X7', 'price': 800000}`。
    * 只想查看某一个属性时直接按「对象名.属性名」取值，如 `c1.brand`，不用输出 `__dict__`。

* **定义类时的两个关键点**

| 关键点 | 结论 |
| :--- | :--- |
| 类名的命名规范 | 遵守大驼峰命名法：所有单词首字母都大写，多个单词之间直接挨着写，不用分隔符 |
| `__init__` 的作用 | 初始化方法，在对象创建时自动调用（不是手动调用）；可以在其中为对象设置对应的属性，也可以完成其他初始化操作 |
| `self` 的作用 | `__init__` 的第一个参数，代表当前创建出来的对象实例；通过它就能获取当前实例对象，从而操作这个实例当中的属性 |

## 实例方法


### 定义语法与 `self`

* **实例方法的定义语法**
    * 与 `__init__` 对齐，在类中一个一个地定义；定义类用 `class` 关键字后跟类名，方法定义在类的缩进块内。
    * 实例方法的形参列表第一个参数需要定义 `self`，通过它就能拿到当前实例对象。
    * 方法体里用 `self.属性名` 取当前实例对象的属性，如 `self.brand`、`self.name`。

* **无返回值的方法**
    * 只输出一句话的方法参数只有一个 `self`，方法体里用格式化字符串拼接属性输出，如 `print(f"{self.brand} {self.name} 正在高速行驶中")`。
    * 没有返回值就不用写 `return`。

### 带参数与返回值的方法

* **方法参数与返回值**
    * 接收三个参数：第一个是 `self` 即当前实例对象，后面两个是业务参数，如 `discount`（购车价折扣）与 `rate`（税率）。
    * 计算式：`total_cost = self.price * discount + rate * self.price`，车价用 `self.price` 取自对象属性，结果用变量接收后 `return` 返回。
    * 有返回值就正常 `return`，没有返回值就不需要 `return`。
    * 需要说明参数时按函数的文档注释写法加三引号注释，写清方法作用、参数含义与返回值。

* **实例化与方法调用**
    * 类定义好之后在下面构建实例对象：类名后跟小括号并传入参数列表，如 `c1 = Car("红色", "BMW", "X7", 800000)`，四个参数最终赋给四个属性。
    * 对象创建好后打点即可调用其中的方法：`c1.running()`；带参方法按提示传参，如 `total = c1.total_cost(0.9, 0.1)`。
    * 传折扣 0.9 与税率 0.1 时结果仍是 80 万，因为 0.9 加 0.1 正好等于 1。
    * > **提示**：定义实例方法时第一个参数要写 `self`，调用这个方法时不用传递 `self`——定义时写、调用时不写。

* **`self` 的写处对照**

| 环节 | 写法 | 说明 |
| :--- | :--- | :--- |
| 定义 | `def total_cost(self, discount, rate):` | 形参列表第一个必须是 `self` |
| 调用 | `c1.total_cost(0.9, 0.1)` | 只传 `self` 之后的参数，`self` 不用传 |

### 参数默认值与不定长参数

* **参数默认值**
    * 实例方法的定义与函数定义语法一致，参数同样可以有默认值，写法如 `def total_cost(self, discount, rate=0.1):`。
    * 传了费率 `c1.total_cost(0.9, 0.1)` 与不传费率 `c1.total_cost(0.9)` 两次结果一样，不传时使用默认值 0.1。

* **不定长参数与统一结论**
    * 不定长参数的写法与函数完全相同。
    * > 结论：实例方法的定义与函数定义语法一致，参数默认值、不定长参数的写法也一致；唯一的额外约定是形参列表的第一个参数 `self` 代表当前实例对象，且调用时不需要传递它

## 魔法方法


### 魔法方法的定义与调用时机

* **魔法方法（magic method）**
    * > **定义**：魔法方法（magic method）是以双下划线开头、并以双下划线结尾的特殊方法，用于定义类的特殊行为
    * `__init__` 就是以双下划线开头、以双下划线结尾的方法，所以它就是一个魔法方法。
    * 统一外观与统一调用方式：方法名都是 `__xxx__` 形式，不需要手动调用，Python 解释器会在合适的时间、在底层自动调用；做项目开发时按项目需求定义这些魔法方法即可。

* **常见魔法方法清单**
    * `__init__` 名称来源 initialize，是初始化方法，创建对象时自动调用，为实例对象设置属性。
    * `__str__` 名称来源 string，是对象字符串表示的方法。
    * `__eq__` 是 equals 的简写 eq，比较两个对象是否相等。
    * `__lt__`、`__le__`、`__gt__`、`__ge__` 分别来自 less than、less than or equals、greater than、greater than or equals，对应小于、小于等于、大于、大于等于。
    * 对象与对象之间也是可以比较大小的，要比较大小就需要定义后四个魔法方法。

### 不定义魔法方法时的默认行为

* **输出对象默认输出内存地址**
    * 直接输出对象本身，得到的默认就是对象的内存地址，是一个十六进制的数，形如 `<__main__.Car object at 0x...>`。
    * 输出 `c1` 得到 c1 的内存地址，输出 `c2` 得到 c2 的内存地址，每个对象的内存地址都不一样。

* **`==` 默认比较内存地址**
    * 两个对象属性完全一样（同颜色、同品牌、同名字、同价格）时，`c1 == c2` 输出仍是 `False`。
    * 原因：直接对比两个对象是否相等时，比较的不是里面一个一个的属性是否相等，而是两个对象的地址值——地址不一样，结果就是 `False`。

* **比较大小默认直接报错**
    * 默认情况下比较两个自定义对象的大小会报错：`TypeError: '>' not supported between instances of 'Car' and 'Car'`。
    * 该错误说明大于号、小于号这类操作符不能用于这两个对象之间的对比，即默认自定义的对象之间不可以进行大小比较。

* **默认行为与定制后的行为对照**

| 问题 | 不定义魔法方法时 | 定义魔法方法之后 |
| :--- | :--- | :--- |
| 输出对象 | 输出对象的内存地址（十六进制） | `__str__` 返回的字符串 |
| 两个对象是否相等 | 比较两个对象的内存地址 | `__eq__` 当中定义的属性比较逻辑 |
| 两个对象比较大小 | 报错：操作符不支持 | `__lt__` 等定义比较规则（如按价格比较） |

### 对象字符串表示与相等判定

* **`__str__` 定制输出内容**
    * 作用是把当前对象转成一个字符串；一旦加了它并在里面把对象实例转成字符串 `return` 返回，再输出这个对象时就会自动调用它，输出返回的字符串而不是默认的地址值。
    * 写法示例：`return f"{self.color} {self.brand} {self.name} {self.price}"`，四个属性依次取出、用空格分开拼成一个字符串返回。
    * 输出形式完全可以自己定义，不想用空格想用横杠就去改 `__str__` 里的逻辑。
    * > **提示**：`__str__` 必须返回字符串，否则输出对象时会报错。

* **`__eq__` 按属性判断相等**
    * `__eq__` 接受两个参数：`self` 代表当前对象，`other` 代表另外一个对象，即对比的是当前对象跟哪个对象。
    * 返回布尔类型结果，多个属性条件之间用逻辑运算符 `and` 连接，所有属性都相等才认为两个对象相等。
    * 写法示例：`return (self.color == other.color and self.brand == other.brand and self.name == other.name and self.price == other.price)`。
    * 把其中一个价格改成 180001 再运行，`c1 == c2` 输出 `False`；具体怎么比较完全由自己根据业务需要决定。
    * > **提示**：`==` 触发的是 `__eq__`；一旦自己定义了 `__eq__`，两个对象是否相等就由此处的逻辑决定，不再是默认的内存地址比较。

### 对象之间的大小比较

* **`__lt__` 定义比较规则**
    * 比较对象大小先要有对比规则——根据对象的什么来比，示例按车辆价格比较。
    * 小于对应 less than，方法为 `__lt__`，写法 `return self.price < other.price`；比较运算符的结果要么 `True` 要么 `False`，所以 `return` 的也必须是布尔值。
    * 两个价格都是 18 万时 `c1 < c2` 返回 `False`，把一个价格改成 180001 则返回 `True`。

* **大于号的回退机制与四个方法的分工**
    * `c1 > c2` 走的是左操作数的 `__gt__`；当左操作数没有实现 `__gt__` 时，Python 会退回到右操作数的 `__lt__`，并把两个操作数交换过来，等价于执行 `c2.__lt__(c1)`。
    * 在只定义了 `__lt__` 的类上大于号也能算出来，但它算的是「右对象是否小于左对象」，与 `c1 < c2` 的结果并不互为简单求反。
    * 要让小于、小于等于、大于、大于等于四种比较都按自己的规则生效，就把 `__lt__`、`__le__`、`__gt__`、`__ge__` 这四个方法都定义上。

* **魔法方法的统一结论**
    * > 结论：魔法方法以双下划线开头、双下划线结尾，定义好之后不需要手工调用，由 Python 解释器在合适的时机自动调用；需要什么样的相等规则和大小规则，就在对应的魔法方法里写清楚
    * 不定义这些比较用的魔法方法，两个对象之间不能进行大小比较，会报错。

## 实例属性与类属性


### 实例属性

* **实例属性（instance attribute）**
    * > **定义**：实例属性（instance attribute）是属于每个具体实例对象的属性；实例指的就是实例对象，所以对象的属性就叫实例属性
    * 每个对象都是独立的，各对象特有的数据通常就定义为实例属性。
    * 写法是在 `__init__` 里用 `self.属性名 = 参数名`；`self` 就是当前的实例对象，挂在它身上的属性都是实例属性。
    * 示例：`c1 = Car('黑色', '宝马', 'X5', 600000)` 与 `c2 = Car('白色', '奔驰', 'S400', 900000)`，两车品牌互不干扰。

* **实例属性的取值方式**
    * 取值方式是「对象名点属性名」，如 `print(c1.brand)`。
    * `self.brand` 与 `c1.brand` 是同一件事的两种写处：定义时用 `self`，使用时用对象名。

### 类属性

* **类属性（class attribute）**
    * > **定义**：类属性（class attribute）是属于类本身的属性，是所有实例共享的数据；可以把所有实例对象共享的数据或配置定义为类属性
    * 写法是单独定义在类当中、缩进与 `__init__` 齐平，如 `wheel = 4`（轮胎数量）与 `tax_rate = 0.1`（购置税税率）。
    * 这类数据所有实例都一样，属于共享数据，由该类创建出来的所有实例对象共享。
    * > **易错点**：类属性不要放在 `__init__` 里——`__init__` 当中基于 `self` 操作的属性都叫实例属性，写进去就变味了。

* **类属性的访问方式**
    * 操作方式是「类名点属性名」，如 `print(Car.wheel)` 输出 4。
    * 由于类属性是所有实例共享的，通过实例对象点属性名同样能访问到它：`print(c1.wheel)` 一样拿到 4，即使从未为 `c1` 定义过 `wheel` 这个实例属性。

* **两类属性的操作方式对照**

| 属性类型 | 定义位置 | 操作方式 | 归属 |
| :--- | :--- | :--- | :--- |
| 实例属性 | `__init__` 中基于 `self` 赋值 | 对象名.属性名 | 每个对象独立一份 |
| 类属性 | 类体中直接赋值（不在 `__init__` 内） | 类名.属性名（实例名也能访问） | 全部实例共享一份 |

### 属性查找顺序与选用标准

* **查找顺序：先实例、后类**
    * > 结论：通过实例对象查找属性时，先查找实例属性；实例属性不存在，再查找类属性
    * 冲突场景：类属性 `wheel = 4` 已存在，又在某个方法里加上 `self.wheel = 2` 构成实例属性，此时 `c1.wheel` 输出 2；删掉那句实例属性赋值后回头去找类属性，输出 4。
    * 分叉点只发生在实例属性这一层：实例属性有值就到此为止，不会再去看类属性；只有这一层空了查找才继续往下走到类属性。
    * > **易错点**：类属性和实例属性同名时实例属性优先，写 `Car.wheel` 拿到的仍然是类属性的 4，写 `c1.wheel` 拿到的才可能是实例属性覆盖后的值——同一个名字，两条访问路径，结果可以不同。

* **`c1.wheel` 查找路径示意**

    ```text
    c1.wheel 查找路径
      |
      +-- 实例属性中存在 wheel ？ --是--> 用实例属性的值（2）
      |
      +-- 否
            |
            +-- 类属性中存在 wheel ？ --是--> 用类属性的值（4）
    ```

* **选用标准**
    * > 结论：判断标准只有一条——这份数据是「每个对象各有一份」还是「所有对象共用一份」。前者进 `__init__`，用 `self.属性名` 赋值；后者写在类体里，用类名访问
    * 属性是各个对象特有的数据就定义为实例属性，如汽车的品牌、颜色、价格，每一辆车都不一样。
    * 属性是所有实例对象共享的数据、所有实例在这个位置上的值都一样，就定义为类属性。
