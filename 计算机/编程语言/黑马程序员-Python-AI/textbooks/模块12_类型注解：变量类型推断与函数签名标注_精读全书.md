## 核心语法-类型注解-介绍
> 对应分集：P71 | 原始标题：《71. 核心语法-类型注解-介绍》

订单总金额计算器写完并且测过之后，回过头再看那个函数，有一个体验问题很扎眼。调用时传进去的一组商品信息，第一个是名称、第二个是价格、第三个是数量。假设编写代码时稍不留神，把第二件商品的价格写成了字符串 `"88"`：开发工具里不报错，也没有任何提示，这个 `"88"` 看起来完全正常。但最后运行时是跑不通的——int 类型和 str 类型不能做加法，因为价格和数量相乘之后，所有商品的金额还要做累加运算。

问题就在这个时间差上：写代码时没有任何提示，只有运行到最后一步才报错。写的时候不知道这段代码有没有问题，跑起来才知道有问题，开发体验很差。能不能做到写到这儿就直接提示这一块有问题、写的时候就把它规避掉？能，用 Python 提供的类型注解解决。

### 类型注解的定义与作用

> **定义**：类型注解也叫类型提示（type hint），是 Python 语言中的一种语法特性，作用是明确所定义的变量、函数的参数及函数返回值的数据类型。

类型注解锚定在数据类型层面。为变量、函数参数和返回值定义了清晰的数据类型之后，代码会更清晰、更安全，少写一些 bug，也更有利于后期维护。

### 变量的类型注解写法

以前定义变量就是变量名等于具体的值，比如 `a = 695`、`score = 98.5`、`hobby = "篮球"`，并没有指定类型。

要指定类型，就在定义变量时于变量名后面加一个冒号，冒号后面写具体类型，然后照常赋值：

```python
a: int = 695
score: float = 98.5
hobby: str = "篮球"
flag: bool = True
pic: None = None
```

列表、集合、字典、元组的写法和上面类似，只是稍微有点变化：冒号后面跟容器类型，中括号里写容器内部元素的类型。

```python
names: list[str] = ["张三", "李四"]
phones: set[str] = {"13800000000", "13900000000"}
data: dict[str, int] = {"语文": 90, "数学": 95}
info: tuple[str, int, int] = ("鼠标", 188, 2)
```

字典的中括号里为什么要写两种类型？因为字典里有 key 也有 value，`dict[str, int]` 表示 key 是 str、value 是 int。

| 写法 | 含义 |
| --- | --- |
| `list[str]` | 列表，其中每个元素都是 str |
| `set[str]` | 集合，其中每个元素都是 str |
| `dict[str, int]` | 字典，key 是 str，value 是 int |
| `tuple[str, int, int]` | 元组，第一个元素是 str，第二、第三个都是 int |

> **提示**：冒号后面都留了一个空格，这是规范不是规定，不加也能跑。Python 官方的代码规范要求在写类型注解时于冒号后面加一个空格。

这样定义出来的变量，一眼就能知道它将来存的是什么类型的数据。

### 类型注解带来的语法提示

打开准备好的演示文件，上面一组变量没写类型注解，就是以前的定义方式；下面一组变量在定义时写上了 `a2: int`、`score2: float`、`hobby2: str`、`flag2: bool`、`pic2: None`，以及 `names2`、`phones2` 这类容器注解。

下面的写法明显比上面复杂，优势体现在两处。第一，看到变量就知道它将来存什么数据；第二，编写代码时会有清晰的提示，写错了会直接报出来。

`names2` 是一个列表，调用它的 `append` 方法添加元素：添加字符串 `x` 没问题；改添加 `10010` 这个 int 类型的数据，立刻就给出提示；鼠标放到提示上，显示这里应该是 str 类型，因为定义这个列表时已经指定了元素是 str，而实际传入的却是 int。写代码期间就能知道这一块可能有问题。

如果这个列表的元素既可以是 str 也可以是 int，就在 `str` 后面加一个竖线（回车键上面那个键），再写 `int`：

```python
names2: list[str | int] = ["张三", "李四"]
names2.append(10010)      # 没问题
names2.append(3.14)       # 提示：应该是 str 或 int，实际是 float
```

`list[str | int]` 表示列表中的元素是 str 类型或者 int 类型，此时再添加 int 就不报错了；但如果添加的是 float 类型，又会报错，提示里面应该是 str 或者 int，而实际传进来的是 float。

### 类型推断机制

那按以前的方式定义变量、不写注解，为什么也有提示？`names` 是一个列表，`append` 一个字符串没有问题；再 `append` 一个 `10010`，会发现同样有提示，告诉里面应该是 str 类型、而传进来的是 int 类型。

> **定义**：类型推断指的是 Python 解释器会自动根据代码推断出变量、表达式或函数返回值的类型。定义 `a = 695`，解释器知道 695 是 int 类型，于是推断出 `a` 的类型是 int。

推断的前提是这些变量被赋了值——它是根据赋的值来推断变量类型的。所以以前定义变量虽然没指定类型，解释器也会基于类型推断得出它们的类型。

在编辑器里把鼠标悬浮到变量上，下面就会浮出这个变量的类型：`names` 后面显示 `list[str]`，这正是类型推断的产物。

既然变量一旦赋值，解释器就能推断出类型，那还有必要写这些变量的类型注解吗？其实可以不用。

> **结论**：如果定义变量时直接赋值，或者涉及变量的运算，或者涉及容器内的推导，这些场景下解释器会自动推断出变量的类型，定义这些变量时可以不指定类型；不指定也会有语法提示。

回到 PyCharm 验证一遍：鼠标悬浮到 `a` 上，类型是 int；悬浮到 `score` 上是 `float`；再往下是 `str`、`bool`、`None`；悬浮到 `names` 上是 `list[str]`，和手工声明的写法一模一样；`phones` 是 `set[str]`，字典是 `dict[str, int]`。

在列表里加上一个 100 之后，悬浮展示的类型变成了 `str | int`，表示这个列表的元素可以是 str 也可以是 int。此时追加字符串类型、追加 int 类型都没问题。

那能不能追加一个 float 类型？编辑器会提示不能是 float。但实际运行输出一下 `names`，这个 float 确实被添加进列表了。

> **易错点**：Python 是动态类型的语言。添加类型注解、或者靠类型推断得出具体类型，都只是提示，不是强制性的约束，并不会改变 Python 是动态类型语言这一特性。即使加了类型注解，也不改变这一事实。

### 三个问题的小结

- **类型注解怎么写**：变量后面写冒号，再写数据类型。
- **常见类型怎么写**：`int`、`float`、`bool`、`str`、`None`、`list`、`set`、`tuple`、`dict`；一个变量要存多种类型时，多种类型之间用竖线分割。
- **为什么要加类型注解**：一是让代码结构更清晰、更安全——更安全指的是很多错误在编写代码期间就能预见，从而及时调整代码；二是让代码提示更精准——已经清楚变量是 list 类型，就能准确提示出 list 常用的方法；三是能提前发现代码中潜在的问题。

还有两点要强调。第一，定义变量时直接赋值了、或者对变量做了相关运算操作，可以不用为它加类型注解，因为解释器有类型推断机制会自动推断出类型。第二，Python 是动态类型语言，类型注解只是多了一个提示、带来那些好处，但它可加可不加——以前写的代码从来没写过类型注解，一样能运行；加上它也不是强制性的约束。

## 核心语法-类型注解-函数的类型注解
> 对应分集：P72 | 原始标题：《72. 核心语法-类型注解-函数的类型注解》

知道类型注解是什么、怎么写之后，还要解决函数的类型注解。所谓函数的类型注解，就是在定义函数时为函数的参数以及函数的返回值添加类型注解。

### 参数与返回值的注解语法

为函数的参数添加类型注解，就在定义函数时于形参名称后面指定这个参数对应的类型，写法和变量的类型注解完全一样：形参名后面加冒号，冒号后面写类型。

```python
def scores_avg(scores: list[int]) -> float:
    ...
```

`scores` 是 list 列表类型，冒号后面直接写 `list`，中括号里写的是这个列表当中每一个元素的类型。

为函数的返回值指定类型，要在参数列表后面加一个由横杠和大于号组成的箭头 `->`，箭头后面写返回值的类型。如果函数返回了多个值，多个值会被封装到一个元组里，所以这里写 `tuple`，后面方括号里逐个写元组中每个元素的类型：

```python
def area_and_perimeter(r: float) -> tuple[float, float]:
    ...
```

> **易错点**：返回值注解的位置在形参列表的右括号之后、冒号之前，写 `-> tuple[float, float]:`；不要把它写进形参列表里面。

### 用圆的计算函数看类型推断的边界

演示用的函数根据圆的半径计算圆的面积和圆的周长，返回两项数据，调用时传半径 10：

```python
import math

def circle(r):
    area = math.pi * r ** 2
    perimeter = 2 * math.pi * r
    return area, perimeter

print(circle(10))
```

输出的是圆的面积和周长，这两项数据被封装在一个元组里。注意这个函数既没有指定参数类型，也没有指定返回值类型。

Python 有类型推断机制，那它能不能推断出 `r` 是什么类型？把鼠标放在函数调用的位置上，显示 `r: Any`——`Any` 代表任意类型，也就是没推断出来。

原因在于类型推断的依据是赋的值：定义 `a = 695`，一看是 int 类型，就推断 `a` 是 int；看到 `flag` 的值是 `True`，就推断它是 bool 类型。而函数定义处只写了一个裸的 `r`，没有赋值，自然推断不出来。

> **结论**：在函数调用过程中类型推断依然生效，但前提是这个参数有默认值。给 `r` 设一个默认值，鼠标再悬浮过去，类型就推断出来了，是 int 类型。

返回值则不受这个限制，它可以被推断出来：显示 `tuple`，里面两个元素都是 float 类型，因为函数体里涉及浮点数的运算。

现在手工给参数加上类型注解。半径可能是 float 也可能是 int，直接写 `float` 就可以——float 能够兼容 int，因为 int 可以转成 float，所以传整数进去没问题；传浮点数当然也没问题；但如果传一个字符串，马上就会提示这里应该传 float 而不是 str。

一旦在定义函数时指定了参数类型，调用时类型不对就会立刻提示，代码出错的概率随之下降：看到提示就知道这里要的是 float，改过来即可。

返回值类型同样可以加上，虽然它本身能被推断出来，可加可不加；既然讲的是语法，就把它补全：

```python
import math

def circle(r: float) -> tuple[float, float]:
    """根据半径计算圆的面积和圆的周长"""
    area = math.pi * r ** 2
    perimeter = 2 * math.pi * r
    return area, perimeter

print(circle(10))
```

### 用类型注解修掉订单计算器的隐患

回到订单金额计算器那个函数：调用时把价格传成了字符串，运行时才报错，而编写代码的过程中没有任何提示。类型注解正好解决这个问题。

这个函数一共有四个参数。后面三个参数其实不用加类型注解，因为它们有默认值，编辑器能据此推断出类型。把鼠标悬浮到函数调用上，这几个参数的类型都被推断出来了，只有 `args` 推断不出来，显示 `Any`——因为 `args` 没有默认值。

`args` 接收的是基于位置传递的不定长参数，它本身就是一个元组。给不定长参数加注解时，冒号后面要写的是这个元组当中每一个元素的类型，因为不定长参数本身已经是元组了。

它里面每一个元素也都是一项元组（一件商品），而这项元组里三个元素分别是：名称是字符串、价格是浮点数、数量是整数。

```python
def calc_order_cost(*args: tuple[str, float, int],
                    coupon: int = 0,
                    score: int = 0,
                    express: float = 0.0) -> float:
    """根据传入的这批商品数据以及优惠信息、运费信息，计算订单的金额"""
    # 第一步：计算商品的总金额
    total_price = [goods[1] * goods[2] for goods in args]
    total_cost = sum(total_price)

    # 第二步：扣减优惠券
    if total_cost >= 5000 and coupon <= total_cost:
        total_cost -= coupon

    # 第三步：扣减积分抵扣（100 积分抵 1 元，只能整百抵扣）
    if total_cost >= 5000 and score // 100 <= total_cost:
        total_cost -= score // 100

    # 第四步：添加运费
    total_cost += express
    return total_cost
```

加上注解之后，鼠标悬浮到 `args` 上，显示的类型是：整个是一个元组，元组里每一个元素又是一个元组，内层元组里有三个元素，分别是 str、float 和 int。

再往下看调用处，一旦在参数上指定了 `args` 里元素的类型，下面立刻就提示有错误：第二个参数应该是 float，实际传进来的是 str。写代码时就暴露出来了，接下来把价格改成浮点数即可。

> **提示**：float 可以兼容 int，所以商品数量写成 int 不会有问题；而把价格写成字符串就会被提示出来。

后面三个参数因为有默认值，注解加不加都行，既然在演示语法就一并加上：优惠券都是整数的优惠券，写 `int`；积分也都是整数，同样写 `int`；邮费是浮点数，写 `float`。

返回值也要指定。编辑器提示出来的是 `tuple`，但实际返回的并不是元组，而是一个 float，所以写 `float`。

```python
result = calc_order_cost(
    ("鼠标", 188, 2), ("键盘", 388, 1), ("手机", 3999, 1),
    coupon=10, score=4000, express=9.9
)
print(result)
```

把商品信息写成 `(100, 99, 2)` 这样时，马上就会有语法提示，告诉第一位应该是 str、应该是一个字符串。以后调用这个函数就不怕写错了，写错就有对应的语法提示。运行结果依然是正确的。

### 函数类型注解的取舍

函数类型注解的语法就是两句话：为参数加注解，在形参名称后面加冒号并指定类型；为返回值加注解，在形参列表后面加箭头并指定返回值的类型。

> **结论**：函数的类型注解可以加也可以不加。不加也不影响函数的正常运行，只不过有一些错误要到运行时才会被发现，代码的可维护性不高；加了之后，一些错误在编写代码时就会马上暴露出来，从而降低出错的概率。

所以对于需要团队协作、长期维护的项目，为了便于后期维护，推荐使用类型注解。如果 Python 解释器能够推断出变量或参数的类型，加不加都可以；而推断不出来的情况，比如 `scores` 这种没有赋值的参数，不加注解就一定推断不出来，建议加上类型注解，让代码更便于后期维护。
