## 核心语法-数据容器-元组tuple-基本操作
> 对应分集：P46 | 原始标题：《46. 核心语法-数据容器-元组tuple-基本操作》

### 有了列表，为什么还需要元组

数据容器学到第三种——元组（tuple）。它和列表一样，也能存储多项数据。但在动手之前，先得回答一个听上去有点别扭的问题：既然列表已经能把多项数据存起来了，为什么还要再学一个元组？

答案要去列表自己的特点里找。列表有三大特点：可以存储多项元素，元素可以重复；元素有序；**列表当中所有的元素都是可以修改的**。

问题就出在第三条上。项目开发中会遇到这样一种场景：需要存储一组数据，但这组数据是固定不变的——只能用来做查询，不能进行修改。这时候还能用列表存吗？不能。因为列表的元素天生就是可改的，用它来装一份「不该改」的数据，等于把保险柜的锁拆了只留门。

> **定义**：元组一旦定义完成，里面所有的元素就不允许修改，只能够进行查询。可变与不可变，就是元组和列表最大的不同点，也是元组存在的意义。

所以选容器的判断依据很直接：这组数据将来会不会变？会变就用列表；只查不改，就用元组。

### 元组的定义与特点

元组是一种不可变的序列，类似列表，但一旦创建之后就不能再做修改操作。

它的特点可以从两个层面记。和列表相同的地方：可以存储不同类型的元素；元素可以重复；元素有序。和列表唯一不同的地方：里面的元素不可以修改。由于元组同样是一种序列类型，它照样支持索引访问，也支持切片操作，访问方式与切片方式跟列表完全一致。

> **结论**：元组与列表类似，两者唯一的区别是一个可变、一个不可变。可变指的是元素可以修改，不可变指的是元素不可以修改。

定义元组把小括号用起来，元素之间用逗号分隔：

```python
# 定义一个有元素的元组
t1 = (80, 95, 78, 50, 76, 80, 85, 20)
```

`t1` 是元组对象的名字，后面用小括号括起来，括号里罗列要存储的元素。里面的元素可以重复——上面这个元组里 `80` 就出现了两次。

定义空元组有两种写法：

```python
# 方式一：直接写一对小括号
t2 = ()

# 方式二：调用 tuple
t3 = tuple()
```

`tuple` 这里是一个函数。两种方式都能定义出空元组，但方式一更简洁更高效，所以空元组直接写一对小括号就行。

### 两个查询方法：count 与 index

元组的方法很少，常用的就两个。原因也简单：元组不支持任何修改操作，只能查询，方法自然全都跟查询统计相关。

| 方法 | 作用 | 返回值要点 |
| --- | --- | --- |
| `count` | 统计元素在元组中出现的次数 | 出现几次就返回几次 |
| `index` | 查找某个元素在元组中的索引位置 | 元素重复时返回**第一次**出现的位置 |

这两个方法和列表的同名方法作用类似。但 `index` 有一个必须留意的点：元组允许存在重复元素，所以 `index` 返回的是匹配到的第一次出现的位置。比如用 `index` 去查 `5` 的位置，拿到的就是第一个 `5` 对应的索引。

> **易错点**：元素在元组里出现多次时，`index` 只给第一个匹配位置，它不会告诉你后面还有没有。想知道一共有几个，还得用 `count`。

### 索引访问与切片

元组是有序序列，所以可以按索引取元素，正向索引和反向索引都行。

```python
t1 = (80, 95, 78, 50, 76, 80, 85, 20)

print(t1[0])    # 80，第一个元素
print(t1[-1])   # 20，最后一个元素
print(type(t1))
```

`t1[0]` 取到的是第一个元素 `80`，`t1[-1]` 取到的是最后一个元素 `20`。用 `type` 看一下类型，输出是 `<class 'tuple'>`，`tuple` 代表的就是元组类型。

切片语法与列表切片一致，切出前面 5 个元素：

```python
print(t1[0:5])   # (80, 95, 78, 50, 76)
```

索引从 `0` 开始，所以索引为 `5` 的位置其实是第 6 个元素，切片不包含结束位置，`0:5` 取到的正好是前 5 个。

### 不可修改：赋值一改就报错

真正把元组和列表区分开的行为，是修改元素的那一刻。往元组里重新赋值，程序会立刻报错：

```python
t1 = (80, 95, 78, 50, 76, 80, 85, 20)

t1[0] = 100      # TypeError: 'tuple' object does not support item assignment
```

错误信息说得很清楚：元组对象不支持这项赋值操作。开发工具同样会在这一行下面直接标红，提示元组不支持重新赋值，因为它是不可变的。

> **提示**：报错本身就是元组的价值所在。一份不允许被改动的数据，被误改时当场中断，比悄悄改掉之后再往下跑安全得多。

`count` 与 `index` 的实际效果，用同一个元组验证一下：

```python
t1 = (80, 95, 78, 50, 76, 80, 85, 20)

print(t1.count(80))   # 2，80 出现了两次
print(t1.index(80))   # 0，第一个 80 的位置是 0
```

元组里有两个 `80`，所以 `count` 返回 `2`；而 `index` 返回的是第一个 `80` 的索引，也就是 `0`。

> **提示**：在对象后面敲一个点，编辑器里弹出的候选方法就是这两个——`count` 和 `index`。候选列表里还会带出一些以双下划线开头结尾的东西，那属于面向对象的内容，后面讲到类的时候再展开，目前只用这两个方法。

### 定义元组时的注意事项

#### 空元组

```python
t2 = ()
print(t2)         # ()
print(type(t2))   # <class 'tuple'>
```

里面什么都不写，直接一对小括号，定义出来的就是空元组，类型依然是 `tuple`。

#### 单元素元组必须加逗号

想定义一个只有单个元素的元组时，最直觉的写法是错的：

```python
t3 = (100)
print(type(t3))   # <class 'int'>
```

这里 `t3` 不是元组，而是 `int` 类型。编辑器也会在下面画一条波浪线，提示可以移除这个冗余的圆括号——因为这样写和直接写 `t3 = 100` 效果完全一样。

原因是小括号在 Python 里的身份不止一个。它除了用来定义元组，还用来把表达式括起来。前面讲运算符时为了提高优先级用过括号，讲多条件判断时为了让条件成为一个整体也用过括号。当括号里只有一个元素时，解释器会认为这就是一个普通的括号，而不是在定义元组。

> **易错点**：定义单元素元组，必须在元素后面加一个逗号。`(100)` 是整数 `100`，`(100,)` 才是元组。

```python
t3 = (100,)
print(t3)         # (100,)
print(type(t3))   # <class 'tuple'>
```

加上逗号之后，元组里就只有一个元素 `100`，类型是 `tuple`。

### 小结

这一段要立住三个点：

1. **元组的特点**——元素可以重复、元素有序、元素不可以修改。它是只读的，只能查询，不能修改；
2. **两个查询方法**——`count` 统计元素数量，`index` 获取指定元素的索引；元素不存在时 `index` 会报错，这一点可以自己动手测一下；
3. **单元素元组加逗号**——比如 `a,` 就代表定义了一个单元素元组。

## 核心语法-数据容器-元组tuple-组包与解包
> 对应分集：P47 | 原始标题：《47. 核心语法-数据容器-元组tuple-组包与解包》

### 组包与解包的含义

组包与解包是两项对立的操作，前面讲列表案例时其实已经碰过其中一个，这里把它补全。

- **组包**：将多个值合并到一个容器中，这个过程称为组包。把多个值合并进元组、或者合并进列表，都是在做组包。
- **解包**：反向操作，将容器解开成独立的元素，再分别赋值给多个变量。把一个元组或列表这个整体拆开，拆成一个一个独立的元素，再分别赋给多个变量，这个过程就是解包。

```text
组包：  5 7 9 1     ──────►   (5, 7, 9, 1)
                            多个值 → 一个容器

解包：  (5, 7, 9, 1) ──────►  a=5, b=7, c=9, d=1
                            一个容器 → 多个独立元素
```

读图说明：上面一行是组包的方向，把散的多个值收进一个容器；下面一行是解包的方向，把一个容器拆开分给多个变量，两者的方向正好相反。

### 组包：定义元组本身就是组包

定义元组的过程就是组包的过程。写一个元组、里面指定四个元素 `5, 7, 9, 1`，这就是把四个值合并到了元组这一个容器当中：

```python
t1 = (5, 7, 9, 1)
```

定义元组还有一种语法：括号可以不写。

```python
t2 = 5, 7, 9, 1
print(t2)   # (5, 7, 9, 1)
```

直接写 `5, 7, 9, 1`，省略括号同样可以，Python 解释器在执行时会认为这就是一个元组，最终也会把括号加上，所以输出结果与写法一完全一致。

> **提示**：两种写法都合法，但建议定义元组时把括号加上。括号一写上去，一眼就能看出这是个元组。

### 基础解包

解包把容器里的元素拆成独立的值，再赋给不同的变量。拿四个元素的元组试一下：

```python
t1 = (5, 7, 9, 1)

a, b, c, d = t1
```

等号右边是元组，左边是四个变量，赋值之后 `a` 对应元组的第一个元素 `5`，`b` 对应第二个元素 `7`，`c` 对应第三个元素 `9`，`d` 对应第四个元素 `1`。

这就是**基础解包**：容器里有多少个元素，前面就定义多少个变量来接收。

元素多了以后，基础解包的变量个数必须跟着涨。先给一个七元素的元组：

```python
t1 = (5, 7, 9, 22, 26, 90, 2)

a, b, c, d, e, f, g = t1
print(a, b, c, d, e, f, g)   # 5 7 9 22 26 90 2
```

把 `g` 删掉，只用六个变量去接收七个元素，编辑器立刻报红提示「值太多，无法解包」，运行也会直接抛错：

```text
ValueError: too many values to unpack (expected 6)
```

`too many values` 是值太多，`to unpack` 指的是解包操作，错误信息的意思是：期望的是六个值，但实际取出来有七个。

> **易错点**：基础解包必须保证变量个数与容器元素个数一致，多一个少一个都不行。

### 扩展解包：星号收集剩余元素

实际需求往往不需要把所有元素都一个个写出来。比如只想要元组里的第一个、第二个和最后一个，中间那一段不想逐个接收——这时候用一个星号就够了。

```python
t1 = (5, 7, 9, 22, 26, 90, 2)

first, second, *other, last = t1
print(first, second)   # 5 7
print(other)           # [9, 22, 26, 90]
print(last)            # 2
```

星号写在变量前面，代表「收集剩余的所有元素」。解释器处理时的顺序是：先把不带宽窄问题的位置定下来——`first` 接第一个元素，`last` 接最后一个元素；剩下的元素全部由带星的 `other` 收走。

上面这个元组有七个元素，头尾各分掉一个，中间剩下四个，于是 `other` 收到 `[9, 22, 26, 90]`。

星号放在最前面时，逻辑一样，只是先看后面有几个变量的位置是确定的：

```python
*other, last2, last1 = t1
print(other)    # [5, 7, 9, 22, 26]
print(last2)    # 90，倒数第二个元素
print(last1)    # 2，倒数第一个元素
```

`last2` 接收倒数第二个元素，`last1` 接收倒数第一个元素，其余的所有元素封装进 `other`。中间一段真正被收走的是 `5, 7, 9, 22, 26` 这五个。

> **定义**：带星号的变量收集剩余的所有元素。它相当于在解包语法里开了一个「数量不确定」的口子，让解包能够处理元素个数事先不好写死的情况。

### 星号收集的结果是列表

有一点值得单独记住：带星的变量收集到多个元素时，最终生成的是一个**列表**，不是元组。

```python
first, second, *other, last = (5, 7, 9, 22, 26, 90, 2)
print(type(other))   # <class 'list'>
```

这背后是有道理的。元组里的数据无法改变，是不可变的；列表里的数据是可变的。解包时收集到的剩余元素数量不确定，往往还要拿去做进一步处理，所以 Python 给的是列表，方便后续对里面的数据进行修改。

> **提示**：`*other` 收到几个元素都是列表；即使恰好只收到一个元素，它也是列表。判断类型时不要凭「长得像元组」猜。

### 用解包优化变量交换

两个变量交换值、三个变量交换值，这两道题前面做过。当时的思路是借第三个空杯子：一杯雪碧、一杯可乐，想互换必须再拿一个空杯子，转换成代码就是定义一个临时变量，绕一圈完成交换。

现在储备了组包与解包，这件事可以一行做完：

```python
a = 10
b = 20

a, b = b, a
print(a)   # 20
print(b)   # 10
```

这一行里其实发生了两步操作，拆开看就清楚了：

```python
a = 10
b = 20

# 第一步：组包，把 b、a 两个值合并成一个元组
t = b, a

# 第二步：解包，把元组里的值依次赋给 a、b
a, b = t
```

`b, a` 这种逗号分隔、不带括号的写法，就是定义元组的写法，所以它相当于做了一次组包，把 `b` 和 `a` 两个值合并进了元组 `t`。接着 `a, b = t` 就是解包：元组的第一个元素（也就是原来的 `b`）赋给 `a`，第二个元素（原来的 `a`）赋给 `b`。

把中间那个临时变量 `t` 换成 `b, a` 直接写回等号右边，两行就合并成了一行 `a, b = b, a`。

三个变量的交换同理，需求是把 `a, b, c` 的值分别赋给 `c, a, b`：

```python
a = 100
b = 200
c = 300

c, a, b = a, b, c
print(a, b, c)   # 200 300 100
```

右先组包，把 `a, b, c` 合并成元组；左再解包，把元组里的值按位置赋给 `c`、`a`、`b`。于是 `a` 的值 `100` 落到 `c`，`b` 的值 `200` 落到 `a`，`c` 的值 `300` 落到 `b`。输出验证：`c` 是 `100`，`a` 是 `200`，`b` 是 `300`。

> **结论**：随着储备的知识越来越多，很多需求实现起来会越来越简单、越来越优雅——原来要一个临时变量才敢动的交换，现在一行组包加解包就够。

### 小结

组包与解包要立住的就是两句话加一个符号：

- **组包**：将多个值合并到一个容器的过程；
- **解包**：将容器拆解成一个个独立的值，再分别赋值给多个变量的过程。

两者一个是正向操作，一个是逆向操作。解包里特殊的那个符号是星号：它收集剩余的所有元素，并把它们封装到一个列表当中，从而让解包可以处理数量不确定的元素。

## 核心语法-数据容器-元组tuple-案例
> 对应分集：P48 | 原始标题：《48. 核心语法-数据容器-元组tuple-案例》

### 案例需求

数据容器学到元组，需要一个案例把列表、元组和字符串格式化串起来用一遍。这个案例的输入是一张学生成绩单，形式类似一张表：第一列是学号，第二列是姓名，第三列到第五列是三科成绩——语文、数学、英语，全表一共 10 条学生记录。

基于这份成绩单要做三件事：

1. 计算每个学生的总分、各科的平均分，连同学生的基本信息与各科成绩一并输出；
2. 统计各科成绩的最低分、最高分、平均分并输出——语文的最高分、最低分、平均分，数学和英语同样各算一遍；
3. 查找成绩比较优秀的学生：平均分大于 90 分的学生，把其信息输出出来。

> **提示**：第三个需求里的标准是「大于 90」，不是「大于等于 90」，判断条件写的时候要照需求来。

### 数据该用什么容器存

要程序处理这份数据，先得解决怎么存的问题。

像字符串、`int`、`float` 这些普通数据类型，一个变量只能存一个值，而这张表里的数据很多，所以必须用数据容器。

再往下想一层：容器里装的到底是什么？看这张表会发现，它是一条一条的数据，一条数据就是一个学生的信息，包含学号、姓名、三科成绩，一共 10 条。那么外层容器的每一个元素就是一个学生的信息，共 10 个元素。

那么外层用列表还是元组？还是拿可变性判断：数据可变就用列表，数据只能查询、不能修改就用元组。学生的成绩信息一旦录入完毕、确认完毕之后是不应该再被修改的，所以外层直接用元组来存。

再看每个学生的信息本身：学号、姓名、三科成绩，这几项也是固定的一组数据，于是每条学生信息同样用一个元组来存。两层都是元组，结构就是**元组里面套元组**。

```python
students = (
    ("S001", "王林", 85, 92, 78),
    ("S002", "李木宛", 92, 88, 95),
    # ...其余 8 位学生的信息
)
```

内层元组的 5 个元素依次是学号、姓名、语文、数学、英语。第一个学生的信息描述完，用逗号分隔，接着描述第二个学生，依此类推。剩下的 8 位学生信息同样是这个结构。

```text
students ── tuple
 ├── 0 ── ("S001", "王林",   85, 92, 78)   ← 学号 姓名 语文 数学 英语
 ├── 1 ── ("S002", "李木宛", 92, 88, 95)
 ├── ...
 └── 9 ── 第 10 位学生的信息
```

读图说明：外层是一个 10 个元素的元组，每个元素本身又是一个 5 元素的元组，按固定的列序存放这个学生的学号、姓名和三科成绩。

这种一条条罗列的数据初次编写时可以手动敲一遍，目的是熟悉结构。等到后面做案例时，这类体力活完全可以交给 AI 来生成，但现在还在打基础，建议先自己敲，把基本语法结构摸熟，之后再谈用 AI 提效。

### 每个学生的总分与平均分

第一个需求要算每个学生的总分和平均分，还得把学生信息一并输出。要算每一个学生的数据，就得从容器里把每一个元素依次拿出来，这就需要循环。

```python
for s in students:
    # s 本身也是一个元组，即一位学生的信息
    total = s[2] + s[3] + s[4]
    avg = total / 3
```

`for s in students` 遍历出来的 `s` 就是外层元组里的每一个元素，而每个元素本身又是一个元组。所以要拿三科成绩，就按索引把内层元组的第 3、4、5 个元素取出来相加——`s[2]` 是语文，`s[3]` 是数学，`s[4]` 是英语。加完就是总分。

> **易错点**：算平均分要除以 `3`，也就是科目数。这里的 `3` 是写死的常数，**不是** `len(students)`——`len(students)` 是学生人数，除它会得到毫无意义的数字。

拿到总分和平均分就可以输出。用格式化字符串把学号、姓名、三科成绩、总分、平均分依次排好：

```python
for s in students:
    total = s[2] + s[3] + s[4]
    avg = total / 3
    print(f"{s[0]} {s[1]} {s[2]} {s[3]} {s[4]} {total} {avg}")
```

`s[0]` 是学号，`s[1]` 是姓名，后面三个是语数外成绩，最后是总分和平均分。

#### 让平均分保留一位小数

跑一遍会发现输出很凌乱，主要问题出在平均分上。计算平均分涉及除法，除法结果可能是浮点数，存在除不尽的情况，所以平均值会拖出一长串小数。

解决办法是在格式化时指定这个变量的显示格式。在格式化字符串的大括号里，变量名后面加一个冒号，冒号后面的内容就是对这个变量的格式说明；要保留一位小数就写 `.1`；又因为 `avg` 是浮点数，还要说明按浮点数形式处理，所以再加上一个 `f`——`f` 代表 float。

```python
print(f"{s[0]} {s[1]} {s[2]} {s[3]} {s[4]} {total} {avg:.1f}")
```

> **定义**：格式化字符串中 `{变量:.1f}` 表示按浮点数处理并保留一位小数。冒号后面是格式说明，`.1` 是小数位数，`f` 是 float。

改完再跑，所有浮点数都缩成一位小数，输出立刻整齐了很多。

#### 表头与制表符对齐

整齐之后还有两个问题：内容太密挤在一起，而且光看 `85`、`92` 不知道哪个数是哪一科。所以要在循环之前先输出一行表头。

```python
print("学号\t\t姓名\t\t语文\t\t数学\t\t英语\t\t总分\t\t平均分")
```

`\t` 是转义字符，输出的是一个制表符。每一列之间用两个制表符分割，表头里依次是学号、姓名、语文、数学、英语、总分、平均分。

下面逐行输出的数据也得用制表符来分隔，否则列对不上表头：

```python
for s in students:
    total = s[2] + s[3] + s[4]
    avg = total / 3
    print(f"{s[0]}\t{s[1]}\t{s[2]}\t{s[3]}\t{s[4]}\t{total}\t{avg:.1f}")
```

制表符用几个需要试一下：数据行里用两个制表符会太宽，改成每处只留一个制表符就正好。跑出来的效果是学号、姓名、语文、数学、英语、总分、平均分七列清清楚楚，跟表头一一对齐。

### 各科成绩的最低分、最高分、平均分

第二个需求换了一个统计角度：不再是每个学生的纵切，而是每一科的横切。要算语文的最低分、最高分、平均分，就必须先把所有学生的语文成绩集中到一起。

这一步拆成两小步：先取到各科的成绩列表，再基于列表算最小值、最大值、平均分。

#### 用列表推导式取各科成绩

取语文成绩列表，需要遍历 `students`，把每个学生元组的第三个元素取出来。这正是列表推导式该出场的地方：

```python
chinese_scores = [s[2] for s in students]
```

推导式里先写循环 `for s in students`，前面写要往列表里放的表达式。要放的不是 `s` 本身，而是这个元组的第 3 个元素，也就是 `s[2]`。

> **易错点**：推导式里放进列表的表达式必须是具体的列，写成 `[s for s in students]` 得到的是一个个学生元组，不是成绩。

先把这个列表输出出来核对一遍，确认取到的是所有学生的语文分数，然后照猫画虎改两个索引位置就得到数学和英语的成绩列表：

```python
chinese_scores = [s[2] for s in students]   # 语文成绩
math_scores    = [s[3] for s in students]   # 数学成绩
english_scores = [s[4] for s in students]   # 英语成绩
```

变量名做到见名知意，语文用 `chinese_scores`，数学用 `math_scores`，英语用 `english_scores`。

#### 计算最低分、最高分与平均分

有了单科成绩列表，统计就简单了。最低分用 `min`，最高分用 `max`，平均分用 `sum` 除以 `len`：

```python
print(f"语文最低分：{min(chinese_scores)}，最高分：{max(chinese_scores)}，平均分：{sum(chinese_scores) / len(chinese_scores)}")
```

`min(chinese_scores)` 取列表里的最小值，也就是最低分；`max` 换成最大值，也就是最高分；平均分需要先累加求和，再除以列表的长度，`len(chinese_scores)` 算的就是这个列表的元素个数。

> **提示**：最低分和最高分也可以用另一种方式拿——先把列表排序，排序后的第一个元素就是最小值，最后一个元素就是最大值。

语文这一组写好后，复制两份，把里面的列表换掉即可：

```python
print(f"语文最低分：{min(chinese_scores)}，最高分：{max(chinese_scores)}，平均分：{sum(chinese_scores) / len(chinese_scores)}")
print(f"数学最低分：{min(math_scores)}，最高分：{max(math_scores)}，平均分：{sum(math_scores) / len(math_scores)}")
print(f"英语最低分：{min(english_scores)}，最高分：{max(english_scores)}，平均分：{sum(english_scores) / len(english_scores)}")
```

跑起来核对一下结果是否可信：语文最低分是 `66`，对应的是成绩单里第 3 个元素那一列；语文最高分是 `95`，是学生周毅的分数，都对得上。

### 查找优秀学生

第三个需求最简单，思路也直接：遍历 `students`，算出每个学生的平均分，判断是否大于 90，满足就把这个学生的信息输出出来。

```python
print("优秀学生名单如下：")
for s in students:
    total = s[2] + s[3] + s[4]
    avg = total / 3
    if avg > 90:
        print(f"{s[0]} {s[1]} 平均分：{avg}")
```

平均分的算法和第一个需求一致，先拿总分再除以 3。判断条件写成 `avg > 90`，大于 90 就是优秀学生，于是把他的学号 `s[0]`、姓名 `s[1]` 和平均分 `avg` 一起输出。跑出来的结果是 4 位优秀学生，平均分都在 90 以上，学号和姓名一并列出。

输出里那个平均分同样是浮点数，用 `.1f` 处理一下就只保留一位小数。

```python
print(f"{s[0]} {s[1]} 平均分：{avg:.1f}")
```

### 输出分隔

三个需求的结果连着打印，中间没有任何分隔，读起来容易混在一起。最容易的处理方式是在每块结果之间各打印一个空行：

```python
print()
```

加上空行之后，三块输出的边界清楚了，整体结构也就清晰了。

### 案例小结

这个案例里用到的东西分三类：数据的存储靠列表与元组——外层用元组装 10 条学生记录，内层再用元组装每个学生的学号、姓名和三科成绩；数据的提取靠循环遍历、列表推导式与索引访问；数据的呈现靠字符串的格式化处理，包括 `{变量:.1f}` 控制小数位数、`\t` 制表符对齐列。

> **结论**：面对一张表格式的数据，先定容器、再定结构——按「数据会不会变」选可变或不可变容器，按「一行是一条记录」决定容器是否嵌套，后面的统计与筛选都是从这套结构上取数计算。

> 对应分集：P49 | 原始标题：《49. 核心语法-数据容器-元组tuple-案例(优化)》

学生成绩统计那个案例，功能我们已经全做完了。做完了先别急着往下走，回过头看一眼那段代码——我在取元组里的元素时，用的全是索引。

那我就问一句：`s[2]` 取到的是学生的什么信息？`s[4]` 呢？`s[3]` 呢？

> **结论**：索引取值没有任何问题，能实现需求。问题在于它**要求读代码的人同时记住这套数据结构每一位存的是什么**。

现在这门课只有三个科目，索引和内容的对应关系还勉强记得住。可要是七八个科目呢？一堆裸下标摆在面前，读起来就吃力了。索引没错，但它把「这个位置是什么」的负担全部推给了读者。

这一节就演示这段代码的第二种写法。

---

### 索引取值的可读性问题

先把两种写法的差异摆出来。

```python
students = [
    ('1001', '王林', 90, 95, 88),
    ('1002', '韩立', 88, 92, 90),
    ('1003', '李慕婉', 76, 85, 79),
]

# 方式一：全靠索引
for s in students:
    total = s[2] + s[3] + s[4]
    print(f'学号是{s[0]}, 姓名是{s[1]}, 语文是{s[2]}, 数学是{s[3]}, 英语是{s[4]}, 总分是{total}')
```

`s` 是遍历出来的那个元素，它本身就是一个元组，里面一共五个元素，依次是学号、姓名、语文、数学、英语。`s[0]` 到 `s[4]` 能取到值，但光看这一行代码，你**说不出来** `s[2]` 到底是语文还是数学——必须回头翻那条元组的定义。

#### 要读的数据结构越大越费劲

> **提示**：真正的成本不在敲代码的时候，而在**回读**的时候。写的时候你知道每个位置代表什么，隔一周再看，就只剩下一串数字。

三个科目时这个问题还不算致命；科目一多，索引法就从「能用」变成「难维护」。

#### 方式二：元组解包

既然 `s` 是一个五元素的元组，那就可以把元组里的元素**一个一个解开**，分别赋给五个变量。

```python
for s in students:
    id, name, chinese, math, english = s
    total = chinese + math + english
    print(f'学号是{id}, 姓名是{name}, 语文是{chinese}, 数学是{math}, 英语是{english}, 总分是{total}')
```

`s` 里就是五个元素，那就在这个位置写五个变量：学号叫 `id`，姓名叫 `name`，语文叫 `chinese`，数学叫 `math`，英语叫 `english`。

> **提示**：`id` 在程序开发里叫**唯一标识**，含义是「这个东西是唯一的」。学号恰好就是唯一的，所以这个位置用 `id` 命名很合适。

原来那一行只有一个 `s`，现在把 `s` 这个元组解包出来，把其中的元素赋值给了这五个变量。下面再操作时，就不用每次都通过索引一个个取了。

#### 两种写法的取舍

| 变量 | 代表的字段 | 方式一取值 | 方式二取值 |
| --- | --- | --- | --- |
| `id` | 学号 | `s[0]` | 解包变量 |
| `name` | 姓名 | `s[1]` | 解包变量 |
| `chinese` | 语文 | `s[2]` | 解包变量 |
| `math` | 数学 | `s[3]` | 解包变量 |
| `english` | 英语 | `s[4]` | 解包变量 |

改完之后右键运行，效果完全一样，这就是元组解包的应用。

> **结论**：两种方式**哪种都可以**，方式二的优势只在可读性——输出时更直观。引出元组解包，是为了让大家知道它在这种场景下怎么用。

### 用解包改写第二个需求

紧接着的第二个需求，我没有替换。原因很直接：那里的代码只需要取其中**一个**元素（第三个元素，也就是索引为 2 的那个）。

真要为了取一个元素去写解包，就得再定义五个变量，反而更麻烦了。

> **易错点**：解包不是「越用越高级」的语法，覆盖不到全部元素时硬解包，只会引入五个用不上的变量。

所以这个需求保持索引写法即可。

### 用解包改写第三个需求

再往下那一块属于同一类情况，可以照样用元组解包改写。

```python
for s in students:

    total = chinese + math + english
```

做法就是把已经定义好的那五个变量直接拿到这里，把 `s` 这个元组换掉，再计算就直接写 `chinese + math + english`、`id`、`name`。右键运行，效果同样一样。


## 核心语法-数据容器-集合set-基本操作
> 对应分集：P50 | 原始标题：《50. 核心语法-数据容器-集合set-基本操作》

前面三种数据容器——列表、字符串、元组——已经学完了。接下来是第四种：`set` 集合。

列表、元组、集合都能存多项数据，那我为什么还要再学一个集合？它到底解决什么问题？

### 集合的应用场景

假设我在做业务系统开发，现在需要定义一个变量，存储一批用户的手机号。

手机号、身份证号、银行卡号这类信息，会不会重复？不会重复。

那问题来了：这种数据能不能用列表或者元组来存？

不能。因为列表和元组里**可以存重复元素**——用它俩来存手机号，里面就可能出现重复的手机号、重复的身份证号、重复的银行卡号，这就不满足需求了。

这种场景就该用 `set` 集合来存。集合会自动去重：即使你往里面存了重复的元素，它也会自动去掉，不会存在重复元素。

> **结论**：需要存储一批**不重复、唯一**的数据时，就用 `set` 集合。

集合这块我们分两部分讲：先讲基本操作，再一起完成一个案例。

### 集合的三个特点

> **定义**：`set` 集合是一种**无序的、不可重复的、可修改的**数据容器。一句话就描述了它的三个特点。

#### 无序

集合是无序的，没有顺序。这一点跟前三种数据容器都不一样——列表、元组、字符串都是有序的。

有序的容器可以通过索引访问指定元素，集合无序，那就**没法通过索引访问元素**。

> **易错点**：不要依赖控制台打印出来的顺序。它这次是 `0 64 2 3 5`，下次可能是别的次序，那不是 bug。

#### 不可重复

集合里存储的元素不会重复，即使存了重复元素，它也会自动去重。

#### 可修改

集合里的元素是可以修改的：我们可以往集合里添加元素，也可以从集合里删除元素。

### 集合的定义

定义集合用的符号是**花括号（大括号）**。回头看前面的容器：列表用方括号，元组用小括号，集合用大括号。括号里罗列一个个元素，元素之间用逗号分割。

```python
s1 = {5, 3, 2, 0, 9, 12, 43, 64, 22, 5, 0}
print(s1)
print(type(s1))
```

我在里面专门存了两个 `5`、两个 `0`，就是要看它能不能自动去重。右键运行，输出是这样的：

```text
{0, 64, 2, 3, 5, 9, 12, 43, 22}
<class 'set'>
```

两点对上了：定义时写的是 `5 3 2 0 9 …`，输出却从 `0` 开始——没有顺序；定义了两个 `5`、两个 `0`，输出里只剩一个 `0`、一个 `5`——自动去重。类型输出为 `set`，说明定义出来的确实是集合。

#### 空集合的写法

要定义空集合，就得注意了：这里需要调用 `set()` 这个语句，它本身是个函数，直接调用 `set()` 就能定义一个空集合。

> **易错点**：空大括号定义出来的**不是集合，而是字典**。字典是最后一种数据容器，后面会讲。所以空集合不可以用大括号来定义。

```python
s2 = set()
print(s2)
print(type(s2))
```

输出就是 `set()`：

```text
set()
<class 'set'>
```

空集合打印出来是 `set()`，而不是那个空花括号，再强调一次。

#### 不支持索引访问

因为集合无序，所以它不支持索引访问。这跟列表、元组、字符串都不一样。

### 集合的常用方法

集合常用的方法主要列了七个，先快速过一遍它们的语义。

| 方法 | 作用 | 备注 |
| --- | --- | --- |
| `add` | 添加元素 | 往集合里加一个元素 |
| `remove` | 删除指定元素 | 元素不存在时会报错 |
| `pop` | 随机删除一个元素并返回 | 不能指定索引，因为无序 |
| `clear` | 清空集合 | 清空后留下一个空集合 |
| `difference` | 求两个集合的差集 | 结果与前后顺序有关 |
| `union` | 求两个集合的并集 | 结果与前后顺序无关 |
| `intersection` | 求两个集合的交集 | 结果与前后顺序无关 |

#### add、remove、pop、clear 的实测

我打上断点一步步 Debug，每个方法走一步看一眼集合的变化。

```python
s1 = {100, 200, 300, 400, 500, 600, 700, 800}
print(s1)

s1.add(1200)
print(s1)

s1.remove(200)
print(s1)

e = s1.pop()
print('本次删掉的是:', e)
print(s1)

s1.clear()
print(s1)
```

逐个看效果：

- `add`：添加 `1200`。往下走一步，`1200` 落在了 `400` 到 `500` 之间——因为无序，它就会插在这个位置。
- `remove`：删除指定的 `200`。再输出一次，`200` 没了。注意，如果这个元素不存在，`remove` 将会报错。
- `pop`：随机删除集合中的元素并返回。不一定删谁，随机删的；删除的元素会返回回来，用一个变量就能接住。这一次删掉的是 `800`。
- `clear`：清空集合。清空之后集合里没有元素了。空集合的表示方式就是 `set()`，不是那个空花括号。

#### 差集、并集、交集

剩下这三个方法是针对**两个集合**做运算的，涉及的是初中数学里的概念。

假设这是 `s1`，这是 `s2`，两个集合中间有一部分是**重叠**的：重叠的部分叫交集；包含在第一个集合、但不包含在第二个集合里的元素叫差集；两个集合的全部元素加在一起叫并集。

```text
       s1                          s2
  ┌─────────────┐             ┌─────────────┐
  │   a   b     │             │             │
  │         ┌───┼─────────────┼───┐         │
  │      d  │ x │   c     e   │ y │   z     │
  │         └───┼─────────────┼───┘         │
  │             │             │             │
  └─────────────┘             └─────────────┘
                └─ 交集：两个集合共有的元素

  差集 s1 - s2：在 s1 中、不在 s2 中     差集 s2 - s1：在 s2 中、不在 s1 中
  并集 s1 | s2：整个区域，包含共有部分
```

图意：中间重叠部分是交集；只在左边一侧出现的是 `s1 - s2` 的差集，只在右边一侧出现的是 `s2 - s1` 的差集；把整个区域合起来就是并集。

求差集调用的是 `difference`，写成 `s1.difference(s2)`，含义是「包含在第一个集合当中、但不包含在第二个集合当中的元素」。

```python
s2 = {'a', 'b', 'd', 'x'}
s3 = {'c', 'e', 'y', 'z'}

print(s2.difference(s3))
print(s3.difference(s2))
print(s2.union(s3))
print(s3.union(s2))
print(s2.intersection(s3))
```

结果如下：

```text
{'a', 'b', 'd', 'x'}        # s2.difference(s3)：只在 s2 中
{'z'}                       # s3.difference(s2)：只在 s3 中
{'a', 'b', 'd', 'x', 'c', 'e', 'y', 'z'}   # 并集
{'a', 'b', 'd', 'x', 'c', 'e', 'y', 'z'}   # 并集，前后调换结果相同
{'c', 'e', 'y'}             # 交集
```

差集是有方向的：`s2` 在前、`s3` 在后，求的是「在 `s2` 中有、在 `s3` 中没有」的元素，结果是 `a b d x`；反过来把 `s3` 放前面，结果就变成 `z`。

并集和交集则跟顺序无关。并集我特意输出了两次，把 `s2`、`s3` 前后调换，结果一样；交集也再输出一次对比，两次内容一致。

> **结论**：差集区分前后顺序，并集和交集不区分。

#### 可修改性的验证

跑完这些方法，也就验证了集合的第三个特点：它确实可以修改——能往里加元素，也能从里面删元素。

### 小结与练习

回来明确两个问题。

一是集合的特点：**无序、不可重复、可修改**。因为它无序，操作时就不要依赖控制台输出的顺序。

二是集合的定义与常见操作。定义用大括号把元素括起来，多个元素之间逗号分割；要定义空的集合，不能直接写花括号，得写 `set()`，直接调用这个语句定义出来的才是空集合。常用方法分三类：添加是 `add`；删除是 `remove`、`pop`、`clear`；集合运算是求交集、并集、差集。

最后，集合的应用场景就是存储不会重复、唯一的数据——手机号、银行卡号、身份证号，还有学号，都可以用集合来存。

## 核心语法-数据容器-集合set-案例
> 对应分集：P51 | 原始标题：《51. 核心语法-数据容器-集合set-案例》

基本操作学完之后，我们用案例再走一遍集合。这一节要解决的需求，来自一份班级学生的选课情况。

数据是四个集合，分别记录选修足球、篮球、法语、艺术的学生名单：

```python
Football_set = {'天运子', '韩立', '厉飞雨', '紫灵', '遁天', '徐笠果', '乌醜', '江老道', '虎刨', '红蝶'}
Basketball_set = {'天运子', '韩立', '厉飞雨', '江老道', '虎刨', '红蝶'}
French_set = {'天运子', '韩立', '江老道', '虎刨', '王林', '李慕婉'}
Arts_set = {'天运子', '韩立', '江老道', '虎刨', '紫灵', '遁天'}
```

> **提示**：这些基础数据在配套课程讲义里也提供了，在讲义最后一栏「课程案例数据」里可以直接复制，当然也可以自己构造一组。

需求一共四个：找出同时选修了法语和艺术的学生；找出同时选修了所有四门课程的学生；找出选修了足球但没有选修篮球的学生；统计每一个学生选修课程的数量。

### 需求一：同时选修法语与艺术

既选修了法语、又选修了艺术，那关联的就是法语和艺术这两个集合。要求的元素是这两个集合共有的那部分，也就是**交集**。

上一节讲过集合的三种运算：并集、交集、差集。求交集对应的方法是 `intersection`，把第二个集合传进去即可。

```python
# 方式一：调用 intersection 方法求交集
fa_set = French_set.intersection(Arts_set)
print(f'同时选修了法语和艺术的课程的学生是: {fa_set}')
```

拿到交集之后用一个变量接收，变量名就叫 `fa_set`——`fa` 是 `French` 和 `Arts` 两个单词的首字母简写。输出用的是格式化字符串，前面加上 `f`。

为了跟方式二对比，这个方式二不覆盖原来的值，另起一个变量：

```python
# 方式二：使用 & 运算符求交集
fa_set2 = French_set & Arts_set
print(f'同时选修了法语和艺术的课程的学生是: {fa_set2}')
```

方式二也是求交集，只是写法略有差异：在 Python 里，集合求交集可以直接用一个**运算符**，这个运算符叫 **and 符**，也就是键盘上数字 `7` 上面的那个符号，读作「与」。

> **易错点**：这个符号在编辑器里因为字体原因会显示得很像 `and` 三个字母，它并不是关键字 `and`，而是 `&`。也可以通过复制代码的方式确认它到底是什么字符。

```text
&    求交集（与）
|    求并集（竖线）
-    求差集（减号）
```

> **提示**：`|` 是**竖线**，不是斜杠。因为写在注释里会跟着注释一起倾斜，容易看错。

两种方式运行结果一模一样，同时选修法语和艺术的学生有四个：江老道、韩立、天运子、虎刨。逐个对上，这四个人在两份名单里都出现了。

```text
同时选修了法语和艺术的课程的学生是: {'天运子', '韩立', '江老道', '虎刨'}
```

> **结论**：下面那种写法明显更简洁。

### 需求二：同时选修四门课程

四门课程都选了，那求的就是这四个集合的交集。这次直接使用「与」符号把四个集合串起来。

```python
# 求四个集合的交集
all_set = Football_set & Basketball_set & French_set & Arts_set
print(f'同时选修了四门课程的学生是: {all_set}')
```

第一种写法是调用方法，比如 `Football_set.intersection(Basketball_set)` 得到一个结果集合，再继续往后 `.intersection(French_set)`、`.intersection(Arts_set)`，这样写也没问题；第二种就是现在这样直接用运算符。这里我用了运算符。

```text
Football  ∩  Basketball  ∩  French  ∩  Arts
   │            │            │         │
   └────────────┴────────────┴─────────┘
                    │
                    v
          同时选修四门课程的学生
```

图意：四个集合逐层求交集，最后剩下的元素必须在四份名单里都存在。

运行结果是两位：天运子和韩立。验证的办法很直接——在编辑器里双击「天运子」这个学生名字，四个集合里是不是都高亮选中了？是的；再双击「韩立」，四门课程同样都选了。看其他的学生，都没有把四门课程全选中，结果没问题。

### 需求三：选修足球但没选篮球

这个需求说的是：在足球的集合当中存在，但是在篮球的集合当中**不存在**。这正是集合的差集能解决的场景。差集同样有多种方式。

#### 方式一：difference 方法

```python
# 方式一：调用 difference 方法求差集
fb_set = Football_set.difference(Basketball_set)
print(f'选修了足球但没有选修篮球的学生是: {fb_set}')
```

求差集要调用的方法是 `difference`，后面把 `Basketball_set` 传进去——这是选修篮球课程的学生名单。运算结果就是在第一个集合中存在、但在第二个集合中不存在的学生。

结果是四个元素：紫灵、遁天、徐笠果、乌醜。逐个验证：紫灵选的是足球，在篮球名单里没有；遁天没有；徐笠果没有；乌醜也没有。而像厉飞雨、天运子这些学生，既选了足球又选了篮球，所以不会出现在差集里。

#### 方式二：减号运算符

差集也有简化的运算符写法，那就是**减号**。

```python
# 方式二：使用 - 运算符求差集
fb_set2 = Football_set - Basketball_set
print(f'选修了足球但没有选修篮球的学生是: {fb_set2}')
```

不用再调方法，一个运算符就解决：`Football_set - Basketball_set`，求取的就是在 `Football_set` 中存在、在 `Basketball_set` 中不存在的元素。右键运行，两个结果一模一样。

#### 方式三：集合推导式

这个需求还有第三种方式——用**集合推导式**实现。

这个名字应该似曾相识：讲列表的时候我们讲过列表推导式，而集合推导式是用来**快速构建一个集合**的。

先看语法：它构建的是一个集合，所以外层是一对大括号；里面可以做正常的循环操作；如果要加条件判断，就在后面接 `if` 带上条件，只有条件成立，才会把这个数据加入到集合当中。

```python
# 方式三：集合推导式
fb_set3 = {s for s in Football_set if s not in Basketball_set}
print(f'选修了足球但没有选修篮球的学生是: {fb_set3}')
```

一步一步拆开看。最终要构造的集合，里存的元素是「在 `Football_set` 中存在、但在 `Basketball_set` 中不存在的」学生，所以先写 `for s in Football_set`，把足球集合里的元素循环出来。

那集合里要存的是什么？后面加条件判断：判断一个元素在某个集合里是否存在，用的是前面讲过的 `in` 操作符，集合同样适用，所以写 `s in Basketball_set`。

但这样写的含义是「在 `Football_set` 中存在（`s` 本来就是从它里面遍历出来的），并且在 `Basketball_set` 中也存在」——因为 `in` 判断元素是否存在，存在就返回 `True`。而我们要的恰恰是**不存在**，所以在前面加上 `not`，写成 `if s not in Basketball_set`。符合这个条件的，就把遍历出来的 `s`（学生名字）加入集合，所以「要添加的元素」就是 `s`。

```text
{   s            for s in Football_set        if s not in Basketball_set   }
    │             │                              │
    │             │                              └─ 过滤：不在篮球名单里
    │             └─ 循环：从足球名单里逐个取出
    └─ 往新集合里放的元素
```

图意：大括号内的三个部分依次是「放什么元素」「从哪里取」「满足什么条件」。

三种方式的结果完全一致。

> **结论**：就这个需求来说，**第二种方式最简单**——`Football_set - Basketball_set` 一行就够。

### 需求四：统计每人选修的课程数量

最后一个需求要统计每一个学生选修了多少门课程，然后把数量输出出来。

已知条件就是那四个集合。要算每个学生选了几门课，得先想清楚两件事：能不能先拿到所有学生的名单？怎么知道某个名字出现了多少次？

#### 第一步：求四个集合的并集拿到名单

所有学生的名单，等于这四个集合的并集——并集之后会自动去重，正好就是一份不重复的名单。

```python
# 方式一：调用 union 方法求并集
all_set = Football_set.union(Basketball_set).union(French_set).union(Arts_set)

# 方式二：使用 | 运算符求并集
all_set = Football_set | Basketball_set | French_set | Arts_set

print(f'所有学生的名单是: {all_set}')
```

`union` 就是求并集的方法，`Football_set.union(Basketball_set)` 先得到一个新集合，后面继续 `.union(French_set)`、`.union(Arts_set)`，这样写没问题。

当然还有简化写法：既然求交集、差集都有对应的运算符，求并集也有——就是**竖线** `|`。写成四个集合用竖线串起来，求的就是这四个集合的并集。

输出验证，学生名单拿到了，而且一定是去重之后的结果——并集运算得到的结果本身也是一个 `set` 集合，会自动去重。

#### 第二步：用一个列表统计出现次数

`all_set` 已经是去重后的结果，可它只给出了名单，我并不知道某个学生的名字出现了多少次。要知道每个学生选了几门课，就得知道这个名字在四个集合当中一共出现过几次。

问题在于：集合里不允许存在重复元素。那反过来想，谁的里面**可以**存在重复元素？列表。

所以再定义一个列表 `all_list`，用来存储所有学生选课的记录——把四个集合里的数据汇总到这一个列表里。

```python
all_list = [*Football_set, *Basketball_set, *French_set, *Arts_set]
```

这里在四个集合前面各加了一个星号。这是**解包**语法：把集合一个个拆开，把里面的元素一个个取出来，再合并到列表当中。这样合并出来的列表里就允许存在重复元素了。

```text
Football_set     Basketball_set     French_set     Arts_set
     │                  │               │             │
     └── * 解包 ────────┴───────────────┴─────────────┘
                          │
                          v
      all_list = [名字, 名字, 名字, ...]   ← 同一名字会重复出现
```

图意：星号把每个集合的元素摊平，全部塞进同一个列表，重复的名字在这里被完整保留下来。

#### 第三步：循环名单并统计

有了名单和完整记录，就可以循环 `all_set` 拿到每一个学生的名字，再输出他选了几门课。

```python
for s in all_set:
    print(f'{s} 选修了 {all_list.count(s)} 门课程')
```

某个学生具体选了多少门课，就看 `all_list` 当中这个名字出现了多少次。列表里统计元素出现次数的方法是 `count`，把 `s` 传进去，它就会去统计这个学生的名字在 `all_list` 里出现了几次——出现几次，就代表选了几门课程。

运行效果：红蝶选修了一门课程，天运子选修了四门课程，紫灵选修了两门课程，每个学生的选课数量都输出了。

```text
红蝶 选修了 1 门课程
天运子 选修了 4 门课程
紫灵 选修了 2 门课程
...
```

> **提示**：结果对不对可以这样验证——在编辑器里双击某个名字，看它在四个集合里被选中几次。红蝶只有一个选中，天运子有四个，紫灵有两个，跟输出的数字完全对应，说明统计逻辑没问题。

### 小结与练习

这个案例里涉及两块新知识。

第一块是集合运算的运算符：`&`（与）求交集，`|`（竖线）求并集，`-`（减号）求差集。

第二块是集合推导式的写法。集合推导式和列表推导式的语法结构完全一致，唯一的区别就是外层括号不一样——列表用方括号，集合用大括号。

```text
                     求交集      求并集      求差集
运算符                 &           |           -
方法                intersection  union    difference
顺序是否影响结果        否          否          是
```

> **结论**：如果这几个需求你都能独立完成，集合这块的内容就算掌握了。掌握之后，就可以进入最后一种数据容器的学习——字典。

## 核心语法-数据容器-字典dict-介绍
> 对应分集：P52 | 原始标题：《52. 核心语法-数据容器-字典dict-介绍》

数据容器的最后一种——字典 `dict`。

提到「字典」，大家并不陌生：上学期间接触过各种字典，汉语字典、英语字典、成语字典。字典的用法就是根据字去查找这个字对应的解释——前面是这个字，后面是这个字对应的解释。而且字典里每个字都跟着一个解释，这个字（词）是**不能重复**的。

Python 里的字典也是这个逻辑。

### Python 中的字典与键值对

> **定义**：Python 中的字典（`dict`）是一种数据类型，里面存储的是**键值对**类型的数据。

键就类似于传统字典里前面那部分「字」，值就类似于这个字对应的「解释」。在编程语言里，键一般叫 `key`，值叫 `value`，所以字典里存的就是 `key-value` 形式的键值对。`key` 和 `value` 之间用**冒号**分割，表示这是一个键值对。

在字典里查找 `value` 的时候，要根据 `key` 来找对应的 `value`。

> **易错点**：查找方向是 `key → value`，反不过来。字典里没有「根据值找键」这种用法。

字典类型名 `dict` 来自英文单词 `dictionary`（字典）的简写 `d-i-c-t`。这种键值对类型的数据在不同编程语言里叫法有差异：在 Python 里叫 `dict`（字典），在别的语言里有的叫映射（map），有的叫哈希（hash），指的都是键值对类型的数据。

### 字典的应用场景

需求是这样的：存储班级学员的高考成绩，王林 670 分，韩立 556 分，李慕婉 582 分，紫灵 435 分，徐立国 608 分。

没有字典的话，这组数据该怎么存？要批量存这么多数据，必然得用数据容器——列表、元组或者集合。

集合不行，集合是无序的。那用列表或元组，就得定义**两个列表**：一个存学生姓名，一个存高考成绩。

#### 双列表存储的对齐要求

用两个列表存，就必须保证一件事：第一个列表里第一个元素是「王林」，那下面那个列表里第一个元素必须放王林对应的分数；第二个姓名是「韩立」，第二个元素必须放韩立的分数。上面的姓名和下面的分数必须**一一对应**。

```text
 姓名列表   ['王林', '韩立', '李慕婉', '紫灵', '徐立国']
               │       │        │       │       │
               ▼       ▼        ▼       ▼       ▼
 分数列表   [670,    556,     582,    435,    608]
             └──────── 下标必须严格对齐 ────────┘
```

图意：两个列表靠下标维持对应关系，一旦其中一个列表插入或删除了元素，另一个列表的对应关系就会整体错位。

#### 双列表查找与字典对照

这样做在程序开发时比较繁琐：要定义两个列表，还要考虑它们的顺序。查找也不方便——想找徐立国对应的分数，首先得到第一个列表里找出「徐立国」这个元素对应的索引位置，然后再到第二个列表里按这个索引找分数，查找繁琐，效率也比较低。

回过头看这组数据：王林对应 670，那王林不就是 `key`、670 不就是 `value` 吗？这种键值对类型的需求，非常适合用字典来存。

```python
dict1 = {'王林': 670, '韩立': 556, '李慕婉': 582, '紫灵': 435, '徐立国': 608}
```

外层是大括号，里面是键值对：王林冒号 670，我就知道王林的分数是 670；韩立冒号 556，韩立的分数就是 556。获取某个学生分数时，直接根据 `key` 就能找到对应的 `value`，更简洁，也更高效。

> **结论**：字典的主要应用场景，就是存储键值对类型的数据。

字典这一章分三部分：先讲字典的定义和定义时的注意事项，再讲字典的常用操作，最后用一组案例巩固。

### 字典的三个特点

- **以键值对的形式存储数据**。
- **同一个字典中 `key` 不能重复**。想想上学时用的字典，里面的字有没有重复的？没有。
- **存储的数据可以修改**。

### 定义语法与空字典

定义字典依然使用**大括号**，外层跟定义集合一样；区别在于大括号里面套的是 `key: value` 形式的键值对，多个键值对之间用逗号分割。

```python
dict1 = {'王林': 675, '李慕婉': 608}
```

王林是键，675 是值，中间冒号分割；逗号之后跟上第二组键值对，李慕婉冒号 608。

定义空字典有两种写法：

```python
d1 = {}        # 空大括号 → 空字典
d2 = dict()    # 调用 dict() → 空字典
```

> **提示**：还记得定义空集合不能用空大括号吗？因为空的大括号代表的就是**空字典**。这正好是空字典的第一种写法。

### 三个注意事项

#### value 可以是任意类型

定义字典时，`value` 可以是任意类型的数据。

#### key 必须是不可变类型

`key` 不能为可变类型——也就是前面学过的列表、集合、字典这三种可以修改的数据类型，都不能当 `key`。

不可变类型才可以：字符串、`int`、`float`、元组。

这个约束好理解：`key` 就像学校图书馆书本上的那个编号，每本书都有一个编号；如果这个编号变了，那还能找得到这本书吗？对应不上了。

> **结论**：字典的 `key` 不允许发生变化，必须得是不可变类型。

```python
dict2 = {'王林': 670, 0: 1, 1: 2, 2: 3, 3: 4, 1.5: 'float', (1, 2): 'tuple'}
```

在编辑器里逐个实测：

- 字符串作 `key`：没问题。
- `int` 作 `key`：用 `0`、`1`、`2`、`3` 试，能正常输出，可以。
- `float` 作 `key`：写 `1.5`，注意小数点要写英文的点，运行也可以。
- 元组作 `key`：写 `(1, 2)`，运行也可以。这样写暂时没有业务意义，只是演示 `key` 必须得是不可变类型。

换成列表试试：

```python
d = {['a', 'b']: 1}
```

运行会直接报错，报的是**不能使用 list 作为字典的 key**——因为列表是可变的。

> **易错点**：常见的可变类型 `list`、`set`、`dict` 都不能作为 `key`。

#### 没有索引下标

字典没有索引下标，只能根据 `key` 获取对应的 `value`。

### 访问与修改元素

访问字典数据用方括号指定 `key`：

```python
print(dict1['李慕婉'])   # 获取值
```

代表从字典里查找「李慕婉」这个 `key` 对应的值。运行输出 `608`。

修改值同样是方括号定位，然后重新赋值：

```python
dict1['李慕婉'] = 688
print(dict1)
```

刚才获取值时是把内容直接输出，现在要为它重新赋一个值，写 `=` 688 即可。再输出一次 `dict1`，李慕婉对应的值变了——说明字典是可以修改的。

> **易错点**：字典里可以修改的是 `key` 对应的 **`value`**，`key` 本身不能修改，因为 `key` 是不可变类型。

### 重复 key 的覆盖行为

定义一个字典，保存学生的高考分数。

```python
dict1 = {'王林': 670, '李慕婉': 608, '徐立国': 580, '韩立': 688}
```

注意，**一个键值对是一项数据**，这里存了四个键值对。输出 `dict1`，四个键值对都输出了；再看类型，确实是 `dict`。

那 `key` 能不能重复？在后面再补一个王林：

```python
dict1 = {'王林': 670, '李慕婉': 608, '徐立国': 580, '韩立': 688, '王林': 700}
```

写完编辑器会提示：字典当中包含重复的键王林。这是开发工具的提示，可以忽略它。重点看运行结果——运行并没有报错，但**王林这块的分数变成了 700**。

原因是 `key` 重复了，后面的值会把前面那个值**覆盖**掉。

> **结论**：`key` 不能重复；如果重复，后面的值会覆盖前面的值。

### 小结与练习

字典的存储形式是 `key-value`，也就是键值对。特点有三个：以键值对存储；`key` 得是唯一的；元素可以修改，但修改的是 `key` 对应的 `value`，不能改 `key`——因为 `key` 是不可变类型。

定义语法是大括号里写键值对；想根据键获取值，就在后面加方括号、里面写 `key`；定义空字典直接写一对空的大括号即可。

三个注意事项：`value` 可以是任意类型——字符串、布尔类型、`int`、`float` 以及其他任意类型都行，但 `key` 不能是任意类型，必须得是不可变类型，不能是 `list`、`set`、`dict`；`key` 不允许重复，重复时后面覆盖前面；字典没有索引下标，只能根据 `key` 获取对应的 `value`。

这一块的练习可以自己动手做一遍：打开 PyCharm，把这几种 `key` 类型都试一次，把重复 `key` 的效果跑一次，再看看用列表作 `key` 报的是什么错。自己跑过一遍，这几个注意事项才真正记得住。

## 核心语法-数据容器-字典dict-常用操作
> 对应分集：P53 | 原始标题：《53. 核心语法-数据容器-字典dict-常用操作》

字典这种数据类型的特点我们已经清楚了，接下来要解决的是一件更实际的事：**里面存的那些键值对，怎么操作？**

答案就是数据操作逃不掉的那四件事——增、删、改、查。

### 数据结构与数据修改

先把要操作的对象摆清楚，它长这样：

```python
dict1 = {'小智': 90, '李四': 80, '李奇': 70, '小黑': 60, '温涛': 50}
```

五个键值对。要往这个字典里加数据、改数据、删数据、查数据，就分别对应下面四类操作。

### 新增与修改数据

#### 语法

新增数据的写法，是字典名后面跟一对方括号，方括号里写指定的 `key`，等号后面指定对应的 `value`：

```python
字典名[key] = value
```

#### 按 key 是否存在判定

比如现在这个字典里没有一个叫 `Tao哥` 的 key，我想增加一个「Tao哥 688 分」的键值对，那就直接这么写：

```python
dict1['Tao哥'] = 688
```

写完你就会发现一件事：**新增和修改的语法是一样的**。

那什么时候是新增、什么时候是修改？判断依据只有一条：看这个 key 在字典里存在不存在。

- key 不存在 → 执行添加操作；
- key 存在 → 执行修改操作。

比如 `小智` 这个 key，在字典里本来是存在的，给它重新赋值，动到的是原来那条数据，也就是修改。

| 指定的 key | 在字典中是否存在 | 实际执行的操作 |
| --- | --- | --- |
| `Tao哥` | 不存在 | 添加一条新键值对 |
| `小智` | 存在 | 修改该 key 原来的 value |

> **结论**：一句话就能背下来——key 不存在就是添加，key 存在就是修改。同一个语法承担两种语义，所以判断完全落在 key 上。

#### 代码演示

先在 PyCharm 里准备一个字典，先把它整个打印出来做对照：

```python
dict1 = {'小智': 90, '李四': 80, '李奇': 70, '小黑': 60, '温涛': 50}
print(dict1)
```

运行后输出的是这四组键值对。

在断点处往下走一步，执行到给 `Tao哥` 赋值那一行。因为字典里原本没有 `Tao哥` 这个 key，所以执行的就是新增，执行完之后字典里多出了 `Tao哥: 550`。

继续往下，此时字典里已经有了 `Tao哥` 这个 key，再给它赋值，执行的就是修改：

```python
dict1['Tao哥'] = 550
dict1['Tao哥'] = 620
```

走完第二步，`Tao哥` 的成绩从 550 分变成了 620 分——从学渣一跃成为学霸。

### 删除数据

删除有两条路，效果都是按指定的 key 把整个键值对删掉。

#### del 关键字

`del` 是我们前面学过的关键字，直接删掉指定的键值对：

```python
del dict1['韩立']
```

删除时只需要指定 key，这个 key 以及它对应的 value，一整个键值对一起被删掉。

#### pop 方法

另一种方式是调用字典对象提供的 `pop` 方法：

```python
dict1.pop('许利果')
```

`pop` 同样是删除指定的 key，但多做了一件事：**把删掉的那个值返回回来**。执行删除「许利果」时，返回的就是它对应的 580 分。

> **易错点**：`del` 和 `pop` 都能按 key 删除键值对，区别只有一个——`pop` 能拿到被删除的值，`del` 拿不到。需要用到被删掉的那个值，就只能走 `pop`。

删完之后再看字典，「许利果: 580」「韩立: ...」这两个键值对就都没有了。

### 查询数据

查询涉及的方法比较多，分两类。

#### 按 key 取 value：方括号与 get

第一种写法是直接写方括号，里面写 key：

```python
print(dict1['Tao哥'])
```

第二种是调用字典对象的 `get` 方法，传入一个 key：

```python
print(dict1.get('Tao哥'))
```

两种方式效果一样，取到的都是 `620`——正是刚才把 `Tao哥` 改上去的那个成绩。

#### keys、values、items

另外三个方法用来一次性取出一批数据。

`.keys()` 获取字典里所有的 key。以小智、李四、李奇、小黑、温涛这个字典为例，这些 key 都会被取出来，并被封装到一个容器里。封装出来的类型叫做 `dict_keys`，`dict_keys` 代表的就是「所有的 key」，里面装的看起来就像是一个一个元素的列表。

`.values()` 获取所有的 value，封装成 `dict_values` 类型，里面是一个一个的值。

`.items()` 获取所有的键值对。item 翻译过来叫「项」，简单说就是键值对。它封装成 `dict_items` 类型，里面装的是一个一个的键值对。

| 方法 | 取出的内容 | 封装后的类型 |
| --- | --- | --- |
| `keys()` | 所有的 key | `dict_keys` |
| `values()` | 所有的 value | `dict_values` |
| `items()` | 所有的键值对 | `dict_items` |

### 遍历字典

字典怎么遍历？方式有多种，因为拿到数据的入口不止一个：能用 `keys()` 拿到所有 key，再遍历这些 key；也能用 `items()` 直接拿到所有键值对。下面三种写法效果完全一致。

#### 按 key 遍历

先拿到所有的 key，再遍历它，就能一个一个拿到 key，然后按 key 取到对应的 value：

```python
for key in dict1.keys():
    print(f'{key}: {dict1[key]}')
```

运行输出：

```text
王林: 670
李慕婉: 608
Tao哥: 620
```

三个键值对都遍历出来了。

#### 按 items 遍历

第二种方式是用 `items()` 拿到所有的键值对，循环变量 `item` 代表其中的一个键值对：

```python
for item in dict1.items():
    print(item)
```

这里的 `item` 里面封装的是一个元组：小括号括起来，第一个元素是 key，第二个元素是 value。所以取第一个元素用方括号加 `0`，取第二个元素用方括号加 `1`：

```python
for item in dict1.items():
    print(item[0], item[1])
```

效果和第一种一样。

#### 解包遍历

既然 `item` 里就是两个元素，那就可以直接解包：写两个变量，一个是 key，一个是 value。循环时，`item` 的第一个元素赋给 key，第二个元素赋给 value，输出这两个变量即可：

```python
for key, value in dict1.items():
    print(f'{key}: {value}')
```

执行结果还是那份数据。同一个字典，多种方式都能遍历输出，活学活用就行。

### 小结

这一节要明确的就是两件事：字典增删改查涉及哪些方法，以及字典怎么遍历。

- 添加和修改：语法完全相同，靠 key 在不在字典里来区分。key 不存在就是新增，key 存在就是修改。
- 删除：`del` 关键字，或者 `pop` 方法。区别是 `pop` 能拿到被删除的值，`del` 拿不到。
- 查询：可以按 key 取 value，也可以取出所有的 key、所有的 value、所有的键值对。
- 遍历：用 `for` 循环即可——先用 `keys()`、`values()` 或 `items()` 拿到数据，再用 `for` 循环遍历拿到的这些数据。

## 核心语法-数据容器-字典dict-案例实现
> 对应分集：P54 | 原始标题：《54. 核心语法-数据容器-字典dict-案例实现》

字典的特点、定义、常用操作，前面两节都已经过了一遍。这一节换个方式加深理解：动手做一个案例——**购物车系统**，把商品信息的增、修、删、查真正写出来。

### 需求说明

案例要开发的这个购物车系统，功能就四件事：在购物车中实现商品信息的增加、修改、删除和查询，说白了就是商品信息的增删改查。有两条硬性要求：

- 使用字典结构来存储商品数据；
- 通过控制台菜单与用户进行交互。

所谓「控制台菜单与用户交互」，就是程序运行之后，控制台上先出现一个购物车系统菜单，菜单一共五个选项：添加购物车、修改购物车、删除购物车、查询购物车、退出购物车。然后把菜单打印给用户，让用户输入要执行的操作编号——你这次到底是要添加、删除，还是退出——输入不同编号就执行不同操作。

五个功能各自的输入要求：

- **添加购物车**：让用户录入商品的名称、商品的价格、商品的数量，一共三项，然后把录入的信息保存到购物车里。想想我们平时在电商网站上添加购物车，要填的是不是就是这几项。
- **修改购物车**：先让用户输入要修改的是哪个商品，也就是商品名称；名称输入完，再提示他输入这个商品最新的价格和最新的数量，然后据此修改购物车数据。
- **删除购物车**：让用户输入要删除的商品名称，再根据名称把对应的商品删掉。
- **查询购物车**：把购物车里的数据展示出来，展示成「商品名称是什么、商品价格是多少、商品数量是多少」。

> **提示**：注意「修改」和「删除」这两个操作的共同点——它们都是**先根据商品名称找到这件商品的信息**，再执行操作。这一点直接决定了数据该怎么存，下一页就会用到。

### 数据结构设计

需求里提示了用字典来存，但字典具体怎么设计，得先想清楚，再动手写代码。

#### 方案一：单个商品的三项信息

第一种结构，是用字典直接存一个商品的信息：`name` 代表商品名称，`price` 代表商品价格，`number` 代表商品数量。

```python
{'name': 'Mate 80', 'price': 6999, 'number': 2}
```

这么存行不行？不行。

原因在于，一个购物车里会包含多个商品。而 `name` 这个 key 在字典里只能存在一个，所以这样设计出来的字典只能存一个商品的购物车数据，别的商品再也加不进来。

#### 方案二：列表里放商品字典

那在列表里放多个字典呢？列表有多个元素，每个元素是一个字典，字典里存的是这个商品的购物车信息，包括名称、价格、数量：

```python
[{'name': 'Mate 80', 'price': 6999, 'number': 2}]
```

乍一看好像是能满足需求：购物车里添多个商品，每个商品就是列表中的一个元素，元素内部用字典存就行了。

但前面已经点出来过：修改购物车要根据商品名称找到这件商品的信息，删除购物车也要先输入商品名称。这个结构方不方便做修改和删除？

不方便。原因很关键——**你把商品名称设计成了字典的 value，而不是字典的 key**。

字典的删除也好、修改也好、添加也好，都是根据 key 来操作的，删除尤其如此，必须根据 key 才能删掉指定的键值对。把商品名称放进 value 里，我们在操作时就失去了一按名称直达的入口。

> **易错点**：判断一个字典结构好不好用，就看操作时**靠哪个字段定位**。定位字段必须放在 key 的位置上，放在 value 里就只能遍历着找。

#### 方案三：商品名称作 key 的嵌套字典

第三种结构完全不同：整个数据结构就是一个字典，里面全是键值对。

- key 设计为商品名称，比如 `Mate 80`、`鼠标`；
- value 又是一个字典，这个字典里有两个 key：`price` 代表商品的价格，`number` 代表商品的数量。

```python
{'Mate 80': {'price': 6999, 'number': 2},
 '鼠标': {'price': 199, 'number': 1}}
```

如果 key 是「鼠标」，那后面的字典里存的就是鼠标对应的价格和数量。

再回头看修改和删除：我们的 key 就是商品名称，删除时直接输入一个商品名称，就能直接根据这个 key 把购物车的数据删掉；修改同理。

```text
shopping_cart
 |
 +-- 'Mate 80' --> { 'price': 6999, 'number': 2 }   <- 该商品的价格与数量
 |
 +-- '鼠标'    --> { 'price': 199,  'number': 1 }
      ^
      |
   外层字典的 key 就是商品名称，操作时用它直接定位
```

这张图画的是最终采用的结构：外层字典的每一个键值对代表一种商品，键是商品名称，值是那件商品的价格和数量组成的字典。

数据结构的分析到这儿就结束了，接下来直接开 PyCharm 把需求实现出来。写代码之前把这个结构再确认一遍：商品名称作为字典的 key，它的值又是一个字典，那个字典里有两个 key，`price` 是价格，`number` 是数量——外层字典里的每一个键值对，就代表一种商品。

### 菜单制作与操作选择

菜单其实就是 `print` 语句打印出来的一段字符串。所以顺序是：先做菜单，再让用户输入要执行的操作，然后根据输入的 1 到 5 判断执行哪个功能。

#### 初始化购物车与菜单字符串

购物车目前初始化为一个空字典，里面什么都没有，随着用户的输入再往里面添加数据。

菜单内容是多行字符串，用三引号定义，交给一个变量保存：

```python
print('欢迎使用购物车管理系统')

menu = '''################################################
##            购物车系统                        ##
##            1. 添加购物车                     ##
##            2. 修改购物车                     ##
##            3. 删除购物车                     ##
##            4. 查询购物车                     ##
##            5. 退出购物车                     ##
################################################'''

print(menu)

shopping_cart = {}
```

构造菜单时用到了一个提效的动作：五行的行首、行尾都要加井号，一行一行地改太慢，可以直接用**列编辑**。按住键盘上的 `Alt` 加 `Shift` 不放，鼠标点住第一行往下拖动，五行前面就同时出现光标，此时输入一次「井号 + 空格」，五行一起加上；再同样操作一次，给行尾补上井号。这样菜单字符串就构建好了，运行打印出来看一眼，效果差不多。

> **提示**：菜单变量在后面不会再被修改，所以直接定义在上面，不必放在循环里反复构造。

#### 用 match 做等值匹配

接着提示用户输入要执行的操作，用一个变量接收，就叫 `choice`：

```python
choice = input('请选择要执行的操作(1-5): ')
```

拿到 1 到 5 之后就要分支执行。如果写成 `if` 加一串 `elif`，每个条件都得重复写 `choice == 数字`，这块的等值匹配用模式匹配更合适，也就是前面学过的 `match`：

```python
match choice:
    case '1':
        # 添加购物车
        pass
    case '2':
        # 修改购物车
        pass
    case '3':
        # 删除购物车
        pass
    case '4':
        # 查询购物车
        pass
    case '5':
        # 退出购物车
        pass
    case _:
        # 匹配其他所有情况
        print('非法操作，不支持')
```

> **易错点**：在结构模式匹配的语法里，匹配其他情况用下划线 `_`，**不要加引号**。写成 `case '_'` 就变成了「匹配字符串下划线」，那才是真的错。

架子搭好，接下来往每个分支里填具体的操作。先从最简单的填起：输入的数不在 1 到 5 之间时，输出一句提示信息「非法操作，不支持」。

### 添加购物车

按需求，添加时要录入商品的名称、价格、数量，再把商品保存到购物车中，所以这个分支里要接收三次键盘录入：

```python
goods_name = input('请输入商品的名称：')
goods_price = float(input('请输入商品的价格：'))
goods_number = int(input('请输入商品的数量：'))
```

商品的名称就是字符串，直接接收；商品的价格不是字符串，是 `float`，也就是小数类型——商品价格不一定是整数，可能是小数，所以要调用 `float` 把输入的字符串转成小数；商品的数量更明确，用 `int` 把字符串转成整数类型。

录入完成，接着做添加，也就是往 `shopping_cart` 这个字典里存数据。这里有个前提要处理：**得确保购物车中这件商品之前不存在，才能添加**。如果已经存在了，就给个提示，让他重新选择要执行的操作。

那怎么判断这个商品名称在购物车里存不存在？用前面讲列表、集合时用过的 `in` 运算符：

```python
if goods_name in shopping_cart:
    print('该商品已存在，请重新选择要执行的操作')
else:
    shopping_cart[goods_name] = {'price': goods_price, 'number': goods_number}
    print('商品添加完毕')
```

`goods_name in shopping_cart` 执行完，商品在购物车里就返回 `True`，否则返回 `False`。

不存在时走 `else`，往购物车里添加：方括号里写的 key 就是商品名称 `goods_name`，等号后面是这个 key 对应的值——注意这个值本身又是一个字典，所以直接写一对大括号，里面装 `price` 和 `number` 两项，分别对应录入进来的价格和数量。

到这里第一个功能就完成了。

### 修改购物车

修改购物车同样需要输入商品名称、商品的价格、商品的数量，所以接收录入的三行代码直接从上面复制下来，只把提示语改清楚：要修改的商品名称、商品最新的价格、商品最新的数量。

修改的操作逻辑和添加类似，但判断方向正好相反：如果用户输入的商品名称在购物车中**不存在**，那根本不用修改，说明他输入的名称有问题，直接提示即可。所以这里用的是 `not in`：

```python
if goods_name not in shopping_cart:
    print('商品不存在，请重新选择')
else:
    shopping_cart[goods_name] = {'price': goods_price, 'number': goods_number}
    print('商品修改完毕')
```

商品不存在就提示「商品不存在，请重新选择」——你都不存在，我修改什么？存在则进入 `else`，把商品的信息直接改掉。

> **结论**：新增和修改这两块代码是一模一样的，区别只在于 key 到底存在不存在——key 不存在就是新增，key 存在就是修改。所以添加分支判断「已存在」，修改分支判断「不存在」，只是入口条件不同。

### 删除购物车

删除只需要输入商品的名称，然后根据名称把购物车里的信息删除，键盘录入这一句从上面拷过来即可：

```python
goods_name = input('请输入要删除的商品名称：')
```

删除同样有前提：你得先有，我才能删。随便输一个商品名称，而这个名称在购物车里不存在，那就不需要执行删除，所以判断逻辑和修改那块一样——不存在就提示错误信息让他重新选择，存在才真正删除：

```python
if goods_name not in shopping_cart:
    print('商品不存在，请重新选择')
else:
    del shopping_cart[goods_name]
    print('商品删除完毕')
```

删除的方式有两种：用关键字 `del`，或者调用 `pop` 方法，两者都能按商品名称把对应的商品信息删掉。

### 查询购物车

查询就是把购物车里的数据展示出来，相对简单，用一个 `for` 循环取到所有的 key——而所有的 key 其实就是所有的商品名称：

```python
for goods_name in shopping_cart.keys():
    goods_info = shopping_cart[goods_name]
    print(f"商品名称：{goods_name}，商品的价格：{goods_info['price']}，商品的数量：{goods_info['number']}")
```

循环变量 `goods_name` 只是 key，打印时还要拿到里面对应的值。做法是 `shopping_cart[goods_name]`，按商品名称取出里面那个由 `price` 和 `number` 组成的字典，交给变量 `goods_info`。

接着按需求里定的格式输出：商品名称直接用 `goods_name`；商品的价格到 `goods_info` 里取，它是一个字典，按 key 取 value 就行，也就是 `goods_info['price']`；商品的数量同理，取的是 `goods_info['number']`。

> **提示**：怎么存的就怎么取。存的时候值是 `{'price': ..., 'number': ...}`，取的时候就用这两个 key 去拿。

### 退出购物车与循环结构

代码写完先运行一把。菜单展示出来了，输入 1，匹配到 `case '1'`，于是提示录入商品名称、价格、数量，然后是「商品添加完毕」。

但问题也来了：提示完之后**程序直接结束了**。这合理吗？不合理。既然是一个系统，添加完了很可能还要继续执行其他操作；只有选到 5 的时候，才应该退出购物车系统。

也就是说，现在的程序只能选一次。怎么解决？把下面的这段代码放进循环里，选到 5 时才退出循环；上面那句欢迎信息不必放进循环。

循环用 `while`，因为我们并不知道要循环多少次：

```python
print('欢迎使用购物车管理系统')
menu = '''...'''
shopping_cart = {}

while True:
    print(menu)
    choice = input('请选择要执行的操作(1-5): ')
    match choice:
        case '1':
            # 添加购物车
            pass
        case '2':
            # 修改购物车
            pass
        case '3':
            # 删除购物车
            pass
        case '4':
            # 查询购物车
            pass
        case '5':
            print('拜拜')
            break
        case _:
            print('非法操作，不支持')
```

这个系统要一直运行，直到用户选择退出购物车为止。所以在 `case '5'` 里先输出一句「拜拜」，再执行关键字 `break` 退出循环。

这样整个案例的代码就搞定了：添加购物车、修改购物车、删除购物车、查询购物车这四个需求都实现了。代码的测试放到下一节进行。

### 非法输入的处理

### 修改功能与 continue 优化

#### 修改不存在的商品

接着测修改，输入 `2`。程序问要修改哪个商品，这里故意输一个购物车中**没有**的商品 `矿泉水`。

回车之后，程序提示输入价格 `2`，再输入数量 `5`，走完才告诉我们「该商品不存在，请重新选择」。功能上是拦住了，但顺序上明显有浪费：商品都不存在，前面还让人白填了一遍价格和数量。

#### 用 continue 提前结束本轮

这个逻辑有优化空间：应该在**输入完商品名称之后就直接判断**，如果商品不存在，直接给出提示，不用再让他输入价格和数量。

做法是把判断逻辑整体剪切到输入商品名称的后面。但这里还有一个容易忽略的点：提示完之后，下面的代码还是会被执行到，所以必须让这一轮循环就此结束，不再往下走。这就要用关键字 `continue`：

```python
goods_name = input('要修改的商品名称：')
if goods_name not in shopping_cart:
    print('该商品不存在，请重新选择')
    continue
goods_price = float(input('请输入商品最新的价格：'))
goods_number = int(input('请输入商品最新的数量：'))
shopping_cart[goods_name] = {'price': goods_price, 'number': goods_number}
print('商品修改完毕')
```

`continue` 代表中断本次循环，直接进入下一次循环，于是程序回到上面重新让用户输入商品名称。

另一个连带的好处是：既然上面已经做过判断，代码能执行到下面，就说明这个商品在购物车中一定存在，所以下面那块就不用再做判断了，`else` 也可以删掉，直接修改即可。

> **易错点**：把 `continue` 当成 `break` 是常见错误。`continue` 只结束这一次循环、进入下一轮，循环本身照常运行；把整个系统退出去的是 `break`。

### 重新运行后的数据丢失

代码改完，重新运行。这次先输入 `4` 查询购物车，结果没有任何反应——上一轮添加的 `Mate80` 和 `茶叶` 都不见了。

原因在于：之前往字典、往购物车里写的数据，全都保存在**内存**当中。一旦把当前这个服务停掉、重新运行，内存当中的数据就已经丢失了，所以重启之后数据就没了。

> **结论**：目前购物车的数据是内存数据，程序一重启就归零。这个问题在后面讲文件操作之后就能解决——把这些数据持久化保存到文件当中即可。

## 核心语法-数据容器-总结
> 对应分集：P56 | 原始标题：《56. 核心语法-数据容器-总结》

Python 当中常见的五种数据容器，到这里就全部讲完了：字符串、列表、元组、集合、字典。

它们各自的特点和应用场景，现在需要回过头来做一次全方位的对比——把五种放在一起看，才能看清什么时候该用哪一个。

### 六个对比维度

下面这张表从六个维度对比这五种数据容器。

| 维度 | 字符串 `str` | 列表 `list` | 元组 `tuple` | 集合 `set` | 字典 `dict` |
| --- | --- | --- | --- | --- | --- |
| 有序性 | 有序 | 有序 | 有序 | 无序 | 有序（3.7 之后） |
| 重复元素 | 允许 | 允许 | 允许 | 不允许 | value 可重复，key 不可重复 |
| 可变性 | 不可变 | 可变 | 不可变 | 可变 | 可变 |
| 索引访问 | 支持 | 支持 | 支持 | 不支持 | 不支持 |
| 切片操作 | 支持 | 支持 | 支持 | 不支持 | 不支持 |

### 有序性

在有序性这个维度上，五种数据类型里只有一种是**无序**的，就是 `set` 集合。

其他的都是有序的：字符串有序，列表有序，元组也有序。而字典呢，在 Python 3.7 版本之后，它里面存储的 key 也是有序的，这一点可以自己去测一测。

不过话说回来，我们访问字典的时候，都是根据 key 去访问 value，并不是根据索引去访问，所以这一块不用特别关注，但得知道它是有序的。

### 重复元素

字符串、列表、元组，都允许存在重复性的元素。

集合不能存在重复性的元素，这是集合最大的一个特点——不可以重复。

字典则是分开算的：value 可以重复，但 key 不能重复。如果 key 重复了，后面的是不是会把前面的覆盖掉？

### 可变性

字符串是不可变的，元组也是不可变的。一旦定义好了，里面的元素就不允许发生变化，我们不能去修改里面的元素。

列表、集合和字典这三个，都是可变的。

### 索引访问与切片

索引其实就是下标。字符串、列表、元组都支持索引访问，既支持正向索引，也支持反向索引——正向索引从 0 开始，反向索引从 -1 开始。

集合和字典这两个不支持索引访问。也正因为它们不支持索引访问，所以它们**也不能进行切片操作**。

而字符串、列表、元组既支持索引访问，也就支持切片操作，也就是说可以截取这个字符串、列表或者元组其中的一部分。

> **结论**：索引访问和切片是捆绑在一起的——不支持索引访问的容器，切片也无从谈起。

### 应用场景与选型

把这五种数据容器各自的特点分清楚之后，在什么场景下该选哪一个，自然就清楚了。

字符串主要用于文本处理，处理文本的时候用它来存储。

如果要存储一批数据，可以考虑列表、元组或者集合。具体选哪种，就看两件事——**是否允许存在重复性的元素**，以及**能不能改变其中的元素**：

- 要存重复性的元素，并且还要对元素做修改，就用列表；
- 不能修改里面的元素、但允许存在重复性的元素，就考虑元组——元组不允许修改，但允许重复元素；
- 有一种场景需要对数据**去重**、不允许存在重复性的数据，比如存储用户的身份证号、手机号、银行卡号，那就考虑用集合 `set`；
- 字典则是用来存储键值对类型的数据的。

> **提示**：身份证号、手机号、银行卡号这几类信息天然不会重复，且业务上往往要求唯一，这正是集合最典型的落点。
