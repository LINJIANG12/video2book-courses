其实到这里该功能已经可以正常运行了。但是，如果每一次都以字典形式来封装，容易把 key 敲错（比如把 data 误写成 date，前端就无法识别了）。在 FastAPI 当中，我们可以将结果封装到一个对象当中，在对象中设置 code、message、data 三个属性。

那么这个类怎么定义呢？在 FastAPI 中，封装数据的模型类需要继承一个统一的父类 BaseModel。BaseModel 是 pydantic 模块提供的，FastAPI 底层默认集成了 pydantic。继承 BaseModel 之后，直接在类中声明属性并加上类型注解，不需要再手动写 `__init__` 初始化方法。

我们定义一个响应数据模型类叫 APIResponse，继承 BaseModel：
```python
class APIResponse(BaseModel):
    code: int
    message: str
    data: Any
```
其中 code 是 int 类型的状态码，message 是 str 类型的提示信息，data 的类型不固定（可能是字符串、列表、字典、元组或自定义对象），在 Python 中如果不确定具体类型，可以使用 typing 模块中的 Any，表示任意类型数据。

改造接口返回值：函数返回值注解写 `APIResponse`，在 return 时实例化 `APIResponse(code=200, message="创建会话成功", data=session_id)`。注意这里以关键字参数的形式传参。当接口直接返回这个模型对象时，FastAPI 会使用 Pydantic 对各个属性进行类型校验，并自动将其序列化为 JSON 格式响应给前端。

测试重启后再次访问，新建会话接口同样返回 200，前端正常解析并展示会话名称，验证了基于 BaseModel 数据模型封装响应对象的正确性。

好的，完成了第一个新建会话的功能之后，接下来这小节呢，我们再来完成第二个功能，就是与 AI 进行对话的这个功能的开发。

所谓与 AI 交互，指的就是在输入框中输入问题或答案，点击发送后去请求服务器，服务器再去请求 AI 大模型，大模型根据提示词响应结果并返回给前端展示。

我们打开浏览器按 F12 抓包分析：在输入框中输入“你好”，点击“发送”，界面提示“发送消息失败，请重试”。查看 Network，发现前端发起了一个向 `/api/chats` 的 POST 请求，状态码是 404（因为服务端接口尚未开发）。

进一步查看请求详情：
1. 请求路径：`/api/chats`；
2. 请求方法：POST；
3. 请求参数：在 Headers 的 Payload（载荷/请求体）中，点击 View Source 可以看到传递的是一段 JSON 格式的数据，包含两个 key：
   - `session_id`：当前会话的标识；
   - `message`：用户输入的消息内容（比如“你好”）。

响应数据同样需要遵循规范，返回标准的 APIResponse 格式（包含 code、message、data）。

那么在 FastAPI 中，服务端如何接收 POST 请求体中传递的 JSON 格式参数呢？
FastAPI 推荐使用基于 Pydantic 的数据模型来接收。我们定义一个继承自 BaseModel 的请求模型类 `ChatRequest`：
```python
class ChatRequest(BaseModel):
    session_id: str
    message: str
```
类中的属性名称必须与前端传递的 JSON 数据中的 key 完全一致（即 session_id 和 message）。

然后在路径操作函数中声明该类型的参数：
```python
@app.post("/api/chats")
def chat(request: ChatRequest) -> APIResponse:
    print(f"与AI交互，session_id: {request.session_id}, message: {request.message}")
    return APIResponse(code=200, message="请求成功", data="AI大模型返回的数据")
```
当请求到达时，FastAPI 会自动解析请求体中的 JSON 数据，根据 key 与属性名的匹配关系，将值赋给 `request.session_id` 和 `request.message`，完成自动反序列化与参数校验。

在 PyCharm 中编写上述代码后重启服务进行测试：在前端输入框输入“你好呀”并点击发送，控制台成功打印出了接收到的 `session_id` 和 `message` 内容（“你好呀”），服务端返回给前端写死的测试数据 `"AI大模型返回的数据"`，前端页面也成功渲染展示了出来，Response 同样是包含 code、message、data 的标准 JSON。

这验证了通过 Pydantic 数据模型接收请求体 JSON 参数并自动封装为对象的可行性与规范性。下一节将在此基础上继续实现调用大模型的具体业务逻辑。
