## 面向对象里的小细节：java bean、测试类与数据安全
> 对应块：BLK22 | 覆盖分集：P87-P89 | 块标题（分集名）：《第8章-面向对象-03-面向对象中的小细节》

前面咱们把面向对象思想过了一遍，也跟着写了不少小案例。只不过那些代码里头还藏着几个小细节，不留意就容易栽跟头。这一讲先把这些细节一个一个挑出来，再拿老师和厨师两个需求练练手。

练完之后还有一件更要命的事：咱们写出来的代码，自己看着挺安全，其实谁都能往里面塞一堆垃圾数据，而且塞进去它一声不吭。这个，咱们放到后半程专门解决。

### 面向对象里的三个小细节

**第一个小细节，是一个称呼的问题。** 以后凡是描述一类事物的类，我们都把它叫做 java bean 类。前面写的 Dog 类、Student 类、Phone 类，其实全都是 java bean 类。

这里要把一句话记牢：

> **定义**：java bean 类是用来描述一类事物的类，它不是程序的主入口。

既然它不是主入口，那 java bean 类当中就不写 `main` 方法。而刚刚我们写的那种带着 `main` 方法的类，我们叫它**测试类**。

| 对比项 | java bean 类 | 测试类 |
| :--- | :--- | :--- |
| 干什么用 | 描述一类事物 | 写程序主入口、创建对象 |
| 有没有 `main` 方法 | 没有 | 有 |
| 里面写什么 | 属性和行为（方法） | 创建对象、给属性赋值、调用行为 |

这两个类是一对搭档：java bean 类负责把"这一类事物长什么样、能干什么"说清楚；测试类负责创建出具体的对象，给它的属性赋值，再调用它的行为。分工不同，别混了。

**第二个小细节，其实就藏在第一个里面**——java bean 类中不写 `main` 方法，写了也没用，因为程序不会从那儿启动。

**第三个小细节**，就是 java bean 类当中除了能写属性，额外还可以写一些**行为**。行为本质上就是方法，它表示这一类事物能干什么。比如说你觉得手机能干什么呀？打电话、发短信、玩游戏。那我们就可以以方法的形式写在 java bean 当中。

只不过要注意的是：

> **结论**：在 java bean 类里面书写的方法是不加 `static` 的，其他部分跟之前写的方法一模一样。

不加 `static` 这一点特别容易忘，考试也是高频考点，记住这一条就够了。

### 两个热身案例：老师和厨师

细节讲完了，接下来用刚刚所学写两个小练习，把要求截了图放到 IDE 右上角，我们一边写一边对。

#### 老师：姓名、年龄，加上三件事

需求很清楚：利用面向对象思想去表示老师，它里面有属性——姓名跟年龄；行为——授课、吃饭和睡觉。

老规矩，先右键 `new package` 新建一个包。注意现在右键的是 `com.itheima`，在这个里面新建包，所以直接写第三集的包名 `op.test3` 就可以。回车进去，右键 `new Java class`，要表示老师，类名就叫 `Teacher`。

属性有两个，第一个是名字，写 `String name`；年龄写 `int age`。

写完属性往下是第二部分——行为。行为是这一类事物能干什么，以方法的形式体现，而这个方法是不加 `static` 的。

```java
public class Teacher {
    // 属性
    String name;
    int age;

    // 行为
    public void teach() {
        System.out.println("老师在授课");
    }

    public void eat() {
        System.out.println("老师在吃饭");
    }

    public void sleep() {
        System.out.println("老师在睡觉");
    }
}
```

写第二个行为吃饭的时候，可以直接 `Ctrl+C`、`Ctrl+V` 把上一个方法整个粘过来，改一下里面的方法名和打印内容即可。第三个行为睡觉同理，方法名就叫 `sleep`。

到这里，描述老师的 java bean 类就全部写完了。接下来创建对象，这一步要写在测试类当中。新建一个测试类 `Test`，`psvm` 写一个程序的主入口，格式就三段：

```java
public class Test {
    public static void main(String[] args) {
        Teacher t = new Teacher();

        t.name = "阿伟";
        t.age = 18;

        System.out.println(t.name);
        System.out.println(t.age);

        t.teach();
        t.eat();
        t.sleep();
    }
}
```

赋值的时候我就说一句——阿伟永远是最年轻的，18 岁。`Ctrl+D` 向下复制一行，再获取 `age` 进行打印，右键 `run`，控制台就出来"阿伟 18 岁"了。

然后调用行为。调用行为相当于是让老师去干活儿，老师能干的活在 java bean 类里已经全部罗列出来了，他就只能干这三个：上课、吃饭和睡觉。所以直接用 `t` 去调用 `teach`、`eat`、`sleep` 三个方法，右键 `run`，控制台就会依次打出"老师在授课""老师在吃饭""老师在睡觉"。老师就开始干活了。

#### 厨师：多一个属性，顺便说说返回值类型

public class Cook {

### 年龄填成负数，代码居然不报错

好了，接下来解决一个正经问题：代码当中的数据安全问题。

先来看一段代码。前面我们写过一个 java bean 类去描述小狗，又在测试类当中创建了小狗的对象去记录它的属性。代码写成现在这个样子，其实并不安全。

为什么？咱们看这个赋值的地方——如果说我手一抖，小狗的年龄赋了一个负数，代码是不会报错的。因为左边 `age` 我们写的是 `int` 类型，`int` 的取值范围可以是负数，没有任何问题。

但是跟实际情况就不符合了。你要想想，如果说我养一只小狗，这只小狗还没出生，再过 200 年它才能出生，想想都觉得诡异。所以年龄为负数是不对的。

那怎么办呢？如何解决这个问题？

说到这个地方，有的兄弟会想：简单啊，赋值之前判断一下不就完事了。咱们现在提个问：你觉得这种方式行不行？

创建一个小狗的对象，这么写一遍其实无所谓。但如果我要创建的对象有很多，每一次都要判断一下，每一次都要判断一下，不觉得非常麻烦吗？

所以正确的操作，就要用到我们接下来要学习的两个知识点：`private` 关键字和 `get`、`set` 方法。

### private：先把属性藏起来

`private` 关键字是一个**权限修饰符**，可以用来修饰成员变量，还可以修饰成员方法。

> **定义**：成员变量就是我们刚刚写的属性——定义在方法外面、类里面的变量；成员方法就是我们刚刚写的那个行为。

`private` 翻译过来是"私有的"意思。一旦被 `private` 修饰，那么此时只能在本类当中访问，在外界是无法访问的。

所以还是回到刚刚的代码，在 `age` 的前面加上 `private`：

```java
public class Dog {
    private String name;
    private int age;
}
```

一旦成员变量用 `private` 修饰之后，就表示当前成员变量私有了，简单理解就是**藏起来了**，只能在本类当中去使用，而在其他的类当中就不能够直接用了。

所以在测试类当中，你用 `d` 直接去调用 `age`，此时就会报错。

| 修饰符 | 含义 | 访问范围 |
| :--- | :--- | :--- |
| `private` | 私有的 | 只能在本类当中访问 |
| `public` | 公共的 | 在所有的类当中都可以使用 |

到这里，数据安全的问题其实已经解决了一半——在外界已经无法赋值错误的数据了。但是呢，它又带来了一个新的问题：**如果我想给 `age` 赋一个正确的数据，其实也不行了。**

> **易错点**：`private` 一加就全堵死了，外界连正确的值也赋不进去，这显然不是我们想要的。

那该怎么办呢？

### get 和 set：留个门，门槛自己定

其实很简单。我们可以在 java bean 类当中，针对 `age` 去提供一个 `public` 修饰的 `get` 和 `set` 方法。`public` 也是一个权限修饰符，它跟 `private` 是反过来的，表示公共的，在所有的类当中都可以使用。

这两个方法的作用是不一样的：

- **`setAge`** 是用来进行赋值的。此时我们就可以对传递过来的数据进行判断——如果你符合要求，我就正常赋值；如果你不符合要求，是一个错误的数据，我就不给你赋值。这样子就可以进行过滤。
- **`getAge`** 其实很简单，就是对外提供 `age` 的数据。

那么在以后的测试类当中，我们就不要再用对象名直接去调用属性了，而是去调用 `get` 或者是 `set` 方法。这样就可以实现我们想要的效果：正确的数据赋值成功，错误的数据赋值失败。完美解决面向对象当中数据安全的问题。

回顾一下刚刚的操作，我们是怎么解决数据安全问题的呢？其实就分为两步：

> **结论**：解决数据安全问题分两步。
>
> 第一步，**私有化成员变量**。在以后的 java bean 类当中，所有的成员变量我们都要用 `private` 进行修饰，只能在本类当中访问，其他的类里面就不能够直接使用了。
>
> 第二步，**私有化的成员变量都要提供其对应的 `get` 和 `set` 方法**。其中 `get` 方法是用来获取值的，`set` 方法是用来赋值的。在赋值的时候我们就可以对数据进行过滤——正确的赋值成功，错误的赋值失败。

### 小狗案例：把两步完整走一遍

光说不练假把式，打开 IDE 来个小练习。

需求：面向对象练习小狗。小狗有属性——姓名跟年龄；有行为——吃骨头。三个要求：

- 小狗的年龄范围是 0~15 岁，如果赋了其他的是错误的；
- 打印小狗所有的信息；
- 小白两岁，调用吃骨头的方法，打印的效果是"两岁的小白正在吃骨头"。

因为是新练习，新建一个包 `op.test5`，需求也粘过来了。

#### 先制造一次报错

第一步还是要新建一个 java bean 类，名字就叫做 `Dog`，里面两个属性：姓名和年龄。

注意了，从现在开始，所有的属性我们都要用 `private` 来进行修饰：

```java
public class Dog {
    private String name;
    private int age;
}
```

下面的 `get`、`set` 方法咱先不忙写，我们先到测试类当中去创建对象，去看一看一旦用 `private` 修饰之后会出现什么样的效果。

```java
Dog d = new Dog();
d.name = "小白";
```

这个时候你看，程序都不用运行，你发现什么了？直接报错了。因为 `private` 修饰的它只能在本类当中使用，在其他的类当中是不能用的。如果把 `private` 删掉，你会发现是不是瞬间就好了。

这个就是 `private` 这个关键字的作用。

#### java bean 这一侧：四个方法加一个行为

继续往下，我们再写对应的 `get` 和 `set` 方法。所有私有化的成员变量都要提供其对应的 `get` 和 `set` 方法——如果你有两个私有化的成员变量，我们一共要写四个对应的方法。

先写 `name` 的 `setName`。在小括号当中要去写一个参数 `String value`，给它写一下注释：它表示将来要赋的值。一会儿我们会用 `d` 去调用 `setName` 方法，会把"小白"传递过来，谁接收啊，就是用这个 `value` 去接收，然后我们会把 `value` 赋值给这里的 `name`，相当于就是给对象里面的属性进行赋值了。

```java
public class Dog {
    private String name;
    private int age;

    public void setName(String value) {
        // 给对象中的属性进行赋值
        name = value;
    }

    public String getName() {
        return name;
    }

    public void setAge(int name) {
        // 给对象中的属性进行赋值
        if (name >= 0 && name <= 15) {
            age = name;
        } else {
            System.out.println("当前的" + name + "不在合理范围之内");
        }
    }

    public int getAge() {
        return age;
    }
}
```

`get` 方法跟上面的 `set` 不一样：`get` 方法是有返回值的，因为 `get` 是对外提供对应的属性。`name` 是 `String` 类型的，所以返回值就是 `String`，方法名就叫 `getName`，方法体当中直接 `return name`，就可以了。

接着写 `age` 对应的 `setAge`，形参写 `int name`。这个 `name` 跟上面的 `value` 是一样的，都表示将来要赋的值，只不过这个字段是 `age`。只不过呢，在赋值的时候我们可以对它来做一个判断：如果 `name` 大于等于 0，而且小于等于 15，那此时就正常进行赋值；否则 `else` 我们就可以直接打印一句话——"当前的……不在合理范围之内"。

> **提示**：`setAge` 的形参也叫 `name`，会跟同名的成员变量撞脸。`age = name` 赋的确实是形参传进来的值（形参把同名字段遮住了），但读代码时特别容易绕晕，换成 `value`、`n` 这类名字就清爽多了。

`getAge` 就是对外提供小狗的年龄，返回值是 `int`，方法体当中直接 `return age`。

四个方法写完，回到第三个需求——它里面还有一个行为，就是吃骨头的 `eat` 方法，打印的效果是"两岁的小白正在吃骨头"。所以在 java bean 类当中，我们再往下还要去补一个行为：

```java
public void eat() {
    System.out.println(age + "岁的小" + name + "正在吃骨头");
}
```

这里面的 `age` 是有可能随时变化的，所以要把它挪到双引号外面，直接写 `age` 就可以了；这里的"小白"就是小狗的名字，我们也可以把它挪到外面去。

> **提示**：往字符串里塞变量这件事，很多同学写的时候要么少写一个引号，要么少写一个加号，非常的恶心。分享一个小绝招：如果在字符串当中要把一个变量挪到外面，先选中这个变量 `Ctrl+X`；然后光标不要动，按两下双引号把光标放到中间；按加号；在这两个加号当中 `Ctrl+V`。这样就绝不会少双引号，也不会少加号，这是一个固定的套路。

#### 测试类这一侧：先传错的 200，再传对的 2

回到测试类当中。第一步先去创建对象，然后进行赋值。现在要赋的是"小白"和"两岁"，我们就可以用 `d` 去调用 `setName` 方法把"小白"传递过来，然后往下用 `d` 去调用 `setAge` 方法把 2 传递过来。

但是现在呢，我先不忙传正确的数据，我先传一个错误的数据——200，注意这不在范围当中：

```java
public class Test {
    public static void main(String[] args) {
        Dog d = new Dog();

        d.setName("小白");
        d.setAge(200);

        System.out.println(d.getName() + " " + d.getAge());

        d.setAge(2);
        System.out.println(d.getName() + " " + d.getAge());

        d.eat();
    }
}
```

右键 `run`，程序运行完毕，打印出来"当前的200不在合理范围之内"。

此时呢它正常的调用关系是这个样子的，来画个图解释一下：

```text
    Test                                  Dog
     │                                      │
     │  d.setAge(200)                       │
     │------------------------------------->│
                                            │  200 被形参 name 接住
                                            │
                                            │  name >= 0 && name <= 15 ?
                                            │       否            是
                                            │       │             │
                                            │       │       age = name
                                            │       │       赋值成功
                                            │       v
                                            │  走 else 分支，打印
                                            │  "当前的200不在合理范围之内"
                                            │  age 不赋值，保持默认值 0
```

读图：调用从测试类发出，200 先被形参接住，判断在 `setAge` 内部完成；不满足条件就走 `else` 打印提示，压根不会碰成员变量。

那如果说我传递的数据是正确的呢？小白是两岁，会出现什么样的调用关系呢？其实跟刚刚是一样的：还是先把 2 传递给这里的形参，形参此时记录的就是 2，然后去判断它是不是在 0~15 这个范围之内，是的，所以它要走 `if` 这行代码，就是把 2 赋值给 `age`，成功赋值。

再获取一下，看有没有成功赋值。此时在获取的时候，就不能直接用 `d.name`、`d.age` 了，我们要用新的，就是 `d.getName()`，再加上逗号空格，还有 `d.getAge()`，右键 `run`，"小白 2"是不是就已经出来了。

> **易错点**：如果赋的是一个错误的数据，没有成功赋值，要注意它是有**默认初始化值**的——这一条跟数组一模一样。

| 成员变量的类型 | 默认初始化值 |
| :--- | :--- |
| 引用数据类型（比如 `String`） | `null` |
| 整数（`int`） | `0` |
| 小数（`double`） | `0.0` |

所以刚才那个传 200 的例子之后，`d.getAge()` 取出来的就是 `0`，而不是 200，也不是报错。

第一个需求跟第二个需求打印完了，第三个需求里调用 `d.eat()`，右键 `run`，"2岁的小白正在吃骨头"就出来了。

到这里，关于面向对象当中数据安全的问题就全部学习完毕了。回到资料里我们给它做个小结：java bean 类当中如果直接定义属性、前面没有加 `private`，那么在测试类里面我们是可以直接通过点的方式去调用里面的属性的，在这种情况下代码是简单了，但是有可能会引发数据安全的问题——给它赋一个错误的数据，代码没有任何提示，这不是我想要的。所以要解决它，分为两步：第一，所有属性私有化，也就是前面加 `private`；第二，针对每一个私有化的成员变量，都提供其对应的 `get` 和 `set` 方法。`private` 是权限修饰符，修饰成员变量也修饰成员方法，一旦被 `private` 修饰，只能在本类当中访问，外面是用不上的；而 `set` 和 `get` 这两个对外的方法，用 `public` 修饰。

## 就近原则、this 关键字与对象内存分配
> 对应块：BLK23 | 覆盖分集：P90-P94 | 块标题（分集名）：《第8章-面向对象-06-就近原则和this关键字》

这一讲我们接着往下啃。先看刚刚写完的那段学生代码，我盯着看了一会儿，越看越不对劲。

问题出在 setter 的形参上。我原来给它起名叫 `nm`，可它表示的明明是外界调用 `setXxx` 传过来的年龄，按标准它就该叫 `age`。可一旦真改成 `age`，方法体里的局部变量和上面那个成员变量就撞名了——更要命的是，下面那行打印语句里头到底用的是哪一个？你说这是局部变量还是成员变量？哥们不造啊。

不造就对了。因为 Java 在这儿悄悄立了一条规则，只要你先把这规则搞明白，后面 `this`、构造方法、甚至整个对象在内存里的样子，都会顺理成章。

### 变量重名之后：就近原则与 this 关键字

先把两个名词对齐，后面才好说话。

定义在方法外面、类里面的那个变量，叫**成员变量**，比如学生类里的 `age`。定义在方法里面、或者定义在方法形参（小括号里）那个，叫**局部变量**。这套叫法前面讲变量的时候就说过了，这里再拎出来一次，因为本讲全靠它俩打交道。

#### 查找顺序：谁离我近我就用谁

在使用变量的时候，Java 有个规律，叫**就近原则**：谁离我近，我就用谁。听好，这句话听着像废话，其实一点都不废话。

具体到代码里是这样的：在方法中直接写一个变量名时，JVM **先在方法里面找有没有对应的局部变量**；找到了，直接就用它；只有当方法里压根没有这个局部变量时，才会往上走，去用成员变量。

```java
public class Student {
    private int age;              // 成员变量

    public void setAge() {
        int age = 18;             // 局部变量
        System.out.println(age);  // 离得近，用局部变量 → 18
    }

    public int getAge() {
        System.out.println(age);  // 方法里没有局部变量 → 用成员变量 age
        return age;
    }
}
```

对照着看：打印语句里那个光秃秃的 `age`，跟同方法的局部变量 `age` 只隔了两行，跟成员变量 `age` 却隔着一层大括号——近得明明白白，所以它拿的是局部变量。而 `getAge` 方法里根本没定义局部变量，查找时在方法内扑了个空，只能往上找，于是用上了成员位置的 `age`。

> **定义**：就近原则 = 在方法中直接使用变量时的查找顺序：先找方法内的局部变量，有就用它；没有再使用成员变量。

#### this 关键字：点名要那个成员变量

那新问题就来了——局部变量和成员变量重名的情况下，我**就是**想用成员变量，怎么办？

这时候就轮到 `this` 出场了。`this` 代表的就是当前对象。想直接访问成员变量，在变量前面加一个 `this.` 前缀，谁也不许抢。

回到上面那段 `setAge`，按就近原则改写就出事了：

```java
public void setAge(int age) {
    age = age;
}
```

等号左边没有 `this`，用的是局部变量；等号右边也没有 `this`，用的还是同一个局部变量。所以这一行的真实含义是「把局部变量 `age` 里的值，又复制给了它自己」，对象里的那个 `age` 连边都没沾上。给对象年龄赋值，失败。

改之前你心里得先有一句话：**我原本的意图，是把外界传进来的数据，赋值给对象里面的 `age`**。既然意图明确，改法就明确了——把左边那个加上 `this.`：

```java
public void setAge(int age) {
    this.age = age;
}
```

拆开看：等号右边没有 `this`，取的是局部变量 `age`，它代表外界传递过来的数据；等号左边有 `this.`，明确指向对象里的成员变量。于是「外界数据 → 对象属性」这条赋值链才真正打通。

> **结论**：`this` 的作用就是区分成员变量和局部变量。直接写变量名会触发就近原则，前面加上 `this.` 则强制使用成员变量。

### 构造方法：创建对象时就把属性赋值了

再来看一个我们都写熟的场面：创建对象，然后给对象的属性赋值。

```java
Student s = new Student();
s.setName("张三");
s.setAge(23);
s.setGender("男");
s.setHeight(175);
```

属性少的时候还好，可一旦对象里的属性多起来，这个代码就非常难受——每个属性都得单独写一行。我就在想，能不能简单点，创建对象的同时就把里面的属性给了？一行搞定，那也太爽了。

当然能。这就是构造方法。

构造方法也叫构造器、构造函数，平时我们习惯叫构造方法。它的作用是：**在创建对象的同时，给成员变量进行初始化**。还记得什么是初始化吗——说白了就是**第一次赋值**。

> **定义**：构造方法 = 与类名同名、无返回值类型、在创建对象时由虚拟机自动调用、用来给成员变量做初始化（第一次赋值）的方法。

#### 格式与三个特点

格式跟普通方法长得几乎一样，就是几处不一样：

```java
修饰符 类名(参数) {
    // 方法体：给成员变量赋值的代码
}
```

它有三个特点，一个都不能错：

- **方法名必须跟类名完全一致，连大小写都要一致。** 类叫 `Student`，构造方法就必须叫 `Student`。
- **没有返回值类型，连 `void` 都没有。** 写的时候在修饰符后面直接就是类名。
- **没有具体的返回值，也不能写 `return`。** 所以方法体里千万不能写 `return`。

#### 什么时候被调用

这是最容易被误解的一点：**构造方法不是你手动调用的，而是在创建对象的时候由虚拟机自动调用的。**

虚拟机是根据你创建对象时小括号里面的参数，来决定到底调用哪一个构造方法的。小括号空着，就调用空参构造；小括号里填了属性值，就调用带全部参数的构造。

而且是**每创建一次对象，就调用一次构造方法**。上面示例里创建了两个对象，第一次走空参，第二次走带参，两次调用各归各的。

#### 四属性的学生类

来道需求题：写一个 JavaBean 类描述学生，四个属性——姓名、年龄、性别、身高。

不管什么样的类，我们有个习惯：**至少写两个构造方法，一个空的，一个带全部参数的。这两个请一定要加上。**

```java
public class Student {
    // 私有化成员变量
    private String name;
    private int age;
    private String gender;
    private int height;

    // 空参构造方法：什么都不写，直接空着
    public Student() {
    }

    // 带全部参数的构造方法
    public Student(String name, int age, String gender, int height) {
        this.name = name;
        this.age = age;
        this.gender = gender;
        this.height = height;
    }

    // 每一个私有化成员变量都提供对应的 get 和 set
    public void setName(String name) {
        this.name = name;
    }

    public String getName() {
        return name;
    }

    public void setAge(int age) {
        this.age = age;
    }

    public int getAge() {
        return age;
    }

    public void setGender(String gender) {
        this.gender = gender;
    }

    public String getGender() {
        return gender;
    }

    public void setHeight(int height) {
        this.height = height;
    }

    public int getHeight() {
        return height;
    }
}
```

构造方法里那四行 `this.xxx = xxx;` 的赋值，全部都能用上刚学过的 `this` 来理解：等号右边是传进来的形参，等号左边带 `this.`，明确指向对象里的属性。

测试类里跑一下：

```java
Student s = new Student();                          // 调用空参构造
System.out.println(s.getName() + s.getAge() + s.getGender() + s.getHeight());

Student ss = new Student("张三", 23, "男", 175);    // 调用带全部参数的构造
System.out.println(ss.getName() + ss.getAge() + ss.getGender() + ss.getHeight());
```

第一个对象打印出来是 `null0null0`。因为走的是空参构造，里面什么都没写，数据保持默认值——`String` 这种引用数据类型的默认值是 `null`，`int` 整数的默认值是 `0`。第二个对象打印的是 `张三23男175`，因为带参构造里我们把赋值代码都写好了。

> **易错点**：不能拿对象名去手动调构造方法。写 `s.Student()` 是直接报错的——构造方法只在创建对象的那一刻由虚拟机自动调用。

### 构造方法的注意事项

构造方法有这么几条规则。前三条听个明白就行，**真正需要你记的只有最后一条**。

#### 没写构造方法时，系统会补一个默认无参构造

以前我们只写私有化成员变量和对应的 get、set，压根没写构造方法，可测试类里直接 `new Student()` 也不报错——原因就在这儿，系统给了一个默认的无参构造。

那系统给不给带全部参数的构造呢？给了的话这行就不会报错：

```java
Student s = new Student("张三", 23);   // 报错：系统没有提供带参构造
```

所以答案已经有了。

#### 只要自己写了任意一个构造方法，默认无参构造就没了

把类里刚写的那个空参构造剪切掉，只留带参构造。此时测试类里：

```java
Student s = new Student();                      // 直接报错
Student ss = new Student("张三", 23, "男", 175); // 没问题
```

上面那行报错的原因很直白：右边的无参构造已经被你剪切走了，系统也不会再补一个。

| 你写了哪些构造 | `new Student()` | `new Student("张三", 23)` |
| --- | --- | --- |
| 一个都没写 | 系统补默认无参，能用 | 报错 |
| 只写带参构造 | 报错 | 能用 |
| 只写无参构造 | 能用 | 报错 |
| 两个都写 | 能用 | 能用 |

#### 带参与无参：构造方法也是重载

带参构造和无参构造，方法名字相同、参数不同——这就叫**方法的重载**。所以你会发现，构造方法其实也是一个特殊的方法：虽然不能手动调用、不能写返回值、方法体里也不能写 `return`，但本质上它就是个方法。

说了这么多，其实都不需要你记。养成一个习惯就行：**不管你用不用、不管你用什么，都手动的把无参构造和带全部参数的构造这两个写上。**

### 面向对象基础篇小结

到这里，面向对象的基础篇算是过完了。我们把这块的知识捋一遍。

#### 什么是面向对象

这个词要拆成两个来理解，其中重点是「什么是对象」。所谓**对象，就是把相关的数据和方法组织成一个整体来看待**。这样做的好处是，以后我们面对的就是一个又一个的整体，而不是一堆零零散散的数据——需要用到什么，从对象里直接取就行了。

所以所谓面向对象，就是以后做软件开发时，我们面对的是一个又一个的整体。但对象里到底有哪些属性、哪些行为，**由 JavaBean 类说了算**。所以创建对象之前，得先定义一个类来描述这一类事物：属性用成员变量体现，行为用方法体现。

#### 一个 JavaBean 该怎么写

写类有几条规矩：

- **类名要见名知意。** 描述学生就叫 `Student`，描述猫就叫 `Cat`，描述小狗就叫 `Dog`，以此类推，不能随便乱写。
- **所有成员变量都要用 `private` 修饰。** 私有化，不让外界直接访问。
- **针对每一个私有化成员变量，都要提供对应的 get 和 set 方法。** 好处是我们可以在 set 里对要赋的值做过滤：正确的数据赋值成功，错误的数据干脆不让你赋。
- **额外再写两个构造方法**，一个无参，一个带全部参数。好处是创建对象时可以把属性一次性全给了。
- **还有其他行为的，也写在这个下面。** 比如学生的学习、吃饭、睡觉，都要以方法的形式写在这个类里。

有人到这儿会想：那我以后是不是就可以直接用构造方法创建对象并赋值了？其实也不是。**如果创建对象的时候你并不知道所有的属性**，那还是得先用无参构造把对象创建出来，等以后知道了，再用 set 一个一个赋。每一块内容都有它各自的应用场景。

#### 创建对象与读写属性

创建对象的格式还记得吧：`类名 对象名 = new 类名();`

一旦对象创建完毕，就好比我们有了一个大空间，去管理那些零零散散的数据。于是：用 set 给里面每个属性赋值；等以后要用到属性了，再通过 get 一个一个把数据取出来。

> **易错点**：写在测试类里、写在 `main` 方法下面的方法，需要加 `static`；写在 JavaBean 类里的方法不加。这是两者的区别。

#### 几个 IDEA 快捷键，让效率翻倍

写 JavaBean 的时候成员变量还得一个个敲，其实有捷径。类建好、私有化成员变量敲完，剩下的全可以一键生成——这就是 `Alt + Insert`。

| 操作 | 步骤 |
| --- | --- |
| 生成空参构造 | `Alt + Insert` → 选 `Constructor` → 回车 → 鼠标点 `Select None`（或连按两下 `Tab`）→ 回车 |
| 生成带全部参数的构造 | `Alt + Insert` → 选 `Constructor` → 回车 → `Ctrl + A` 全选 → 回车 |
| 生成 get 和 set | `Alt + Insert` → 选第四项 `Getter and Setter` → `Ctrl + A` 全选 → 回车 |

这里有几个细节：弹框名字是 `Generate`；要生成空参构造，`Constructor` 那一项是默认帮你勾上了 `name` 的，直接点 OK 生成的是带 `name` 的构造，不是我们想要的，所以要么鼠标点 `Select None`（表示什么都不选），要么不碰鼠标，按两下 `Tab`——第一下取消默认勾选的 `name`，第二下让 `Select None` 被选中——再回车。生成 get 和 set 时注意别选第二项 `Getter` 或第三项 `Setter`，要选第四项两个一起的。

另外，`Insert` 键每个键盘位置不一样，大概率在退格键上方。如果按了 `Alt + Insert` 一点反应都没有，再加上 `Fn` 键，三个一起按。不是所有电脑都必须三个键的，先试试两键。

#### 练习：姓名年龄加三个行为

需求：利用 JavaBean 写一个学生，有属性姓名、年龄，行为是学习、吃饭、睡觉。

```java
public class Student {
    private String name;
    private int age;

    public Student() {
    }

    public Student(String name, int age) {
        this.name = name;
        this.age = age;
    }

    // get / set 省略，由快捷键一键生成

    public void study() {
        System.out.println(name + "正在学习");
    }

    public void eat() {
        System.out.println(name + "正在吃饭");
    }

    public void sleep() {
        System.out.println(name + "正在睡觉");
    }
}
```

测试类里两个对象，正好把两种创建方式都用上：

```java
Student stu1 = new Student();                 // 空参：先创建出来
System.out.println(stu1.getName() + stu1.getAge());   // null0，还没赋值

stu1.setName("张三");
stu1.setAge(23);                              // 知道了再一个一个 set
stu1.study();
stu1.eat();
stu1.sleep();

Student stu2 = new Student("李四", 24);       // 全参：一次性给完
System.out.println(stu2.getName() + stu2.getAge());   // 李四24
stu2.study();
stu2.eat();
stu2.sleep();
```

第一个对象用空参创建，刚创建完直接取属性，打出来的是默认初始化值 `null` 和 `0`，这是合理的——你还没赋值呢。补上 set 之后数据就进去了，两个行为也打印「张三正在学习」「张三正在吃饭」「张三正在睡觉」。第二个对象用带全部参数的构造创建，就没必要再一个个 set 了。

> **提示**：写的时候注意包。我们已经写过很多个 `Student` 了，这时候要用的可能是新包里的那个，千万别选错。

### 对象在内存里到底长什么样

新一天的课程，难度上来了：今天学的是**面向对象的原理篇**，包含两部分——面向对象的内存管理，还有 `this` 关键字在内存当中真正的含义。难度确实不小，但非常重要，不能跳过，可以二刷三刷。

#### 回顾：只需要记住三块区域

每一款软件运行的时候都要占据一块内存区域，Java 也不例外。虚拟机为了更好地管理这块空间，把它分成了五个部分：**栈内存、堆内存、方法区、本地方法栈、程序计数器**。每一部分都有各自的作用，但后两个不需要我们记忆，只要掌握前面三块就够了。

- **栈内存**：跟方法有关。方法被调用进栈执行，方法里所有代码执行完毕，就从栈里出去。
- **堆内存**：用来存储对象、数组、字符串常量池。只要是通过 `new` 关键字创建的小空间，一定在堆里。
- **方法区**：用来存储字节码信息。一个类要运行的时候，会把这个类的字节码文件（也就是 class 文件）先加载到方法区当中。

#### 创建对象的七个动作

现在我们来看一看，创建一个对象在内存当中到底是怎么回事。这三块内存都用得上。

假设 student 类里有两个属性 `name`、`age`，还有一个 `study()` 方法。执行 `Student stu = new Student();` 时，虚拟机一共做了七个动作：

```text
① 加载 class 文件 ──▶ 把 Student 的字节码文件加载到方法区临时存储
                     此时方法区里有了 Student 的全部信息：属性 name、age，行为 study()

② 声明局部变量   ──▶ 执行等号左边，给 stu 声明这个局部变量
                     stu 是数据类型，意思是它以后能存 Student 类对象的地址值
                     注意：stu 虽叫对象名，但在内存角度它就是一个变量

③ 堆中开辟空间   ──▶ 执行等号右边的 new Student()，在堆里开辟一个小空间
                     堆里每一块空间都有内存地址，假设这块的地址就是 0x0011

④ 默认初始化     ──▶ name 这个引用数据类型默认为 null，age 这个 int 默认为 0

⑤ 显示初始化     ──▶ 如果在类里定义成员变量时直接赋了值，这一步才生效
                     我们一般不这么写，所以这步可以忽略

⑥ 构造方法初始化 ──▶ 调用构造方法给 name、age 赋值
                     用的是空参构造，里面一般不写代码，这步也可以忽略
                     若是用带全部参数的构造创建的对象，这一步属性就有值了

⑦ 赋地址值       ──▶ 执行中间的等号，把堆中对象的内存地址 0x0011 复制给左边的 stu
```

走完这七步，内存里大致是这么个样子：

```text
┌──────────────────────── 方法区 ─────────────────────────┐
│  Student.class                                          │
│  name、age、study() …… 这个类里所有的属性与方法信息      │
└──────────────────────────────────────────────────────────┘

┌──────────────────────── 栈内存 ─────────────────────────┐
│  main()                                                 │
│  ┌──────────────────┐                                   │
│  │ stu : 0x0011     │                                   │
│  └──────────────────┘                                   │
└──────────────────────────────────────────────────────────┘

┌──────────────────────── 堆内存 ─────────────────────────┐
│  0x0011                                                 │
│  ┌──────────────────────────────────┐                  │
│  │ name : null                      │                  │
│  │ age  : 0                         │                  │
│  │ study() 的内存地址                │                  │
│  └──────────────────────────────────┘                  │
└──────────────────────────────────────────────────────────┘
```

自上往下读就是刚才七步的推进顺序：方法区里先有类的全部信息，栈里的 `stu` 只是一个变量，堆里的 `0x0011` 才是我们平时所说的**对象**。对象里除了属性，还记着所有成员方法的内存地址——记这个是为了以后用对象调方法的时候能找到对应的方法。

顺带一提，堆里这个对象上还记着方法的地址，`new` 创建出来的这块空间才是对象，`stu` 从头到尾只是个拿着地址的变量。

#### 访问属性和调用方法，都是两跳查找

**用 `stu` 去访问 `name`、`age`**，查找过程是这样的：

```text
stu（栈内存里的变量）
   │  ① 读出 stu 里记录的内存地址
   ▼
0x0011（堆内存中的对象）
   │  ② 在对象里找到 name、age
   ▼
null 和 0
```

所以第一遍打印结果是 `null` 和 `0`。接着给 `name` 赋值，走的也是同一个查找过程：最终 `name` 赋值为「小诗诗」，`age` 赋值为 23，赋完之后再查一次，打印出来就是「小诗诗 23岁」。

> **注意**：变量记录什么，打印就是什么。要直接打印 `stu`，打出来的绝不是 `name` 和 `age`，而是 `Student` 在内存中的地址。只不过 Java 对内存地址做了一个优化，打印时会在前面加上「包名.类名@」，最后那串才是真正的十六进制内存地址。这样我们读地址时，就能更方便地知道当前对象是哪个包、哪个类创建出来的。

**用 `stu` 去调用 `study()`**，过程是：

```text
stu.study()
   │
   ├─ ① stu 里记录的是谁的内存地址？→ 0x0011，找到堆中的对象
   │
   ├─ ② 在对象里查有没有 study 这个方法的地址
   │       对象里除了属性，还有成员方法的内存地址
   │       有 → ③ 把 study 方法加载进栈，开始执行里面的代码
   │       没有（比如调用 aaabbb）→ 调用失败
   │
   └─ ④ study 里只有一行输出语句，打印「学生正在学习」
          方法里代码执行完毕，study 从栈里出去
```

`study` 执行完，`main` 方法也就执行完了。`main` 一出栈，我们就又多知道了一个知识点。

#### 什么时候消失

方法都没有了，方法里面的变量还会存在吗？不会。`main` 方法从栈里出去，里面的 `stu` 也就随之消失。变量一消失，就没有人再去用右边那个对象了，对象也会从内存当中随之消失。

> **结论**：当没有任何地方在使用这个对象的时候，对象就会从内存当中消失。但**方法区里的字节码信息一般不会消失**，它在内存里会永远存在，除非整个虚拟机停掉了——也就是把我们心爱的 IDEA 给关掉，那时方法区里的字节码信息才会消失。

本讲要掌握的就这么三个问题：

- **创建对象分哪七步。** 这七步不要求大家背，但要能看懂内存图里画的七步，尤其是三处赋值（默认初始化、显示初始化、构造方法初始化）的关系。
- **方法出栈之后，方法里面的变量也会随之消失。**
- **没有任何地方使用堆里的对象，对象也会从内存里消失；但方法区里的字节码信息一般不会消失，除非关掉整个虚拟机。**

### 对象在方法中传递，传过去的是内存地址

前面那几步已经讲过，就不多重复了：加载字节码文件，`main` 方法进栈，等号左边申请变量 `stu`，等号右边因为有 `new`，在堆里开辟一块空间作为对象，再把这个对象的内存地址赋给 `stu`。所以 `stu` 里记的是 `0x0011`，它顺着 `0x0011` 就能找到右边那个对象，打印的时候自然能拿到"小诗诗，23 岁"。

现在把这个对象传给 `change` 方法，会发生什么呢？

```text
        栈（main）                        栈（change）              堆
┌──────────────────────┐   ┌──────────────────────┐    ┌──────────────────────┐
│ stu ──► 0x0011       │   │ stu ──► 0x0011       │    │ name = 小丹丹        │
│                      ├───┤                      ├────►                      │
│                      │   │                      │    │ age  = 19             │
└──────────────────────┘   └──────────────────────┘    └──────────────────────┘
```

看到这个结构，眼熟吧同学们？之前讲数组的时候咱们说过一个画面：相当于你把你家的家庭住址告诉我了，我就可以到你家把你家的水果吃光。那你在回家的时候，看到的是什么？完整的水果还是果皮？那肯定是果皮。

现在也是一模一样的道理。调用方法的时候，**变量里面记录的是什么，就传递什么**。`main` 里的 `stu` 记着 `0x0011`，那么传进 `change` 的形参 `stu`，记着的也是 `0x0011`。两个变量，指向的是同一个对象。

完整的执行过程按时间顺序排一遍：

```text
① main 执行 Student stu = new Student()  → 堆里造对象，stu = 0x0011
② main 打印 stu.name / stu.age          → 小诗诗 / 23
③ 调用 change(stu)                       → change 进栈，形参 stu 拿到 0x0011
④ change 里改成 小丹丹 / 19              → 改的还是同一个对象
⑤ change 出栈，形参 stu 消失             → 对象还在，因为 main 的 stu 还在用
⑥ main 再次打印                          → 小丹丹 / 19
⑦ main 出栈                              → 没人再用了，对象才消失
```

关键就在第⑤步和第⑦步的差别。`change` 执行完要从栈里出去，里面的变量随之消失——**但对象不会消失**，因为栈里还有 `main` 的 `stu` 在用它。只要有人用，对象就不会消失。等 `main` 也执行完毕出栈了，栈里的变量也没了，这时没人再引用这个对象，它才从内存中消失。

> **结论**：把一个对象传递给方法，实际传递的是对象的**内存地址**。此时栈里就有多个变量指向同一个对象。只要有一个变量修改了对象中的属性，其他变量再次访问时拿到的，就是修改之后的结果。

这一个知识点到这里就全了。暂停视频，自己整理一遍。

### this 的本质：所在方法调用者的地址值

`this` 咱们之前学过作用——区分成员变量和局部变量。直接用变量名会触发**就近原则**：谁离我近我就用谁，所以下面这行打印出来是 `10`：

```java
public class Student {
    String name;
    int age;

    public void study() {
        int age = 10;
        System.out.println(age);              // 10，局部变量离得更近
        System.out.println(this.age);         // 18，走 this 拿成员变量
    }
}
```

想用成员变量就在前面加个 `this.` 当前缀，这就是 `this` 最基本的使用原则。但我一直在想：**为什么 `this` 能区分？它的原理是什么？在内存当中它又是怎么回事？**

> **定义**：`this` 的本质，就是**它所在方法的调用者的内存地址值**。一句话说完，后面所有现象都是这一句的推论。

要讲清楚这句话，得看一段代码。测试类里创建两个对象，分别去调用 `study` 方法：

```java
public class Test {
    public static void main(String[] args) {
        Student s1 = new Student();
        s1.name = "小诗诗";
        s1.age = 18;

        Student s2 = new Student();
        s2.name = "小丹丹";
        s2.age = 19;

        s1.study();
        s2.study();
    }
}
```

那么问题是：`this.age` 打印出来到底是 `18` 还是 `19`？不造没关系，一起来在内存里走一遍。

```text
       栈                                         堆
┌────────────────────────┐     ┌────────────────────────────────────┐
│ main()                 │     │ Student 对象①  @0x0011            │
│   s1 ────────────►     ├────►│    name = 小诗诗    age = 18       │
│   s2 ────────────►     │     ├────────────────────────────────────┤
│                        │     │ Student 对象②  @0x0022            │
└────────────────────────┘     │    name = 小丹丹    age = 19       │
┌────────────────────────┐     └────────────────────────────────────┘
│ study()      ← s1 调用 │                        ▲
│   this ────────────────┼────────────────────────┘
│   age = 10（局部变量）  │
└────────────────────────┘
```

创建第一个对象时，方法区里还没有 `Student` 的字节码信息，`new` 触发类加载，字节码进方法区；等号左边在栈里申请变量 `s1`，等号右边在堆里创建对象、复制默认值（`name` 为小诗诗、`age` 为 18），最后把地址 `0x0011` 赋给 `s1`。

创建第二个对象时要注意：方法区里**已经有** `Student` 的字节码信息了，所以不会重复加载，直接在栈里申请 `s2`，在堆里创建新对象（小丹丹、19），把 `0x0022` 赋给 `s2`。

现在关键的地方来了。

`S1` 去调用 `study`，`study` 被加载进栈——**在方法当中，它会记录调用者的内存地址**。此时是 `s1` 调的，所以记录下来的是 `0x0011`。这个记录下来的东西，就是 `this`。

方法体里的执行：第一行定义局部变量 `age = 10`，此时 `study` 栈帧里有一个 `age` 记着 10。接着打印 `age`，没有 `this` 前缀，触发就近原则，方法里的局部变量离得更近，所以打印 10。再往下打印 `this.age`，`this` 是方法调用者的地址值，也就是刚才记下的 `0x0011`，顺着它找到右边第一个对象，拿到 18。

`study` 里所有代码执行完毕，出栈，`s1.study()` 这行结束。往下执行 `s2.study()`，`study` 第二次被加载进栈——**调用者不是 `s1` 了，而是 `s2`**，所以这次记录的 `this` 是 `0x0022`。方法里面的过程一模一样：局部变量 `age = 10`，打印 `age` 走就近原则仍是 10，打印 `this.age` 顺着 `0x0022` 找到第二个对象，拿到的是 19。

> **结论**：`this` 就是当前方法的调用者地址。同一个方法被不同对象调用，`this` 记的就是不同的地址，取到的成员变量自然也就不同。所以这一块咱们只需要牢牢记住一句话——**`this` 表示所在方法调用者的内存地址**。

### 共享：全班只有一个老师

回到描述一类事物的老套路：先定义一个 JavaBean 类，写上这类事物的属性和行为，比如学生的姓名、年龄，行为是吃饭、学习；然后创建对象，给属性赋值。

但有一个特殊情况：**如果有一个属性是被所有对象共享的**，按以前的写法就有点麻烦了。举学生老师的例子，一个班级里所有学生是不是共享一个老师？如果按老写法，每一个对象我都要单独复制一份老师姓名——更要命的是，第二个学生觉得小文老师讲得不好、要申请换成阿伟老师，此时第一个对象里的 `teacherName` 并不会跟着变。这跟实际情况不符。

所以关于共享数据，我想要达成的效果有两个：

> **结论**：共享数据要做到两点才算完美。第一，不管你有多少对象，共享数据的赋值我只想写一次，写完所有对象用的都是同一个值——这才叫共享；第二，任意一个对象修改了共享数据，其他对象再次访问时拿到的就是修改之后的结果。

要实现这两个效果，就得用上今天第一个知识点：`static`。

`static` 表示静态的意思，它是 Java 里的一个修饰符，可以修饰**成员变量**和**成员方法**。成员变量就是类里的属性，比如 `String name`、`int age`；成员方法就是类里的行为，比如 `sleep`、`eat`。

先看 `static` 修饰成员变量。被 `static` 修饰的成员变量，我们叫它**静态变量**，它的特点就是被这个类所有的对象共享。一旦共享，前面说的两个效果自动就达成了：赋值只要一次，任意一个对象改了共享数据，其他对象再访问就是改后的结果。

#### 加不加 static，标准就俩字：共享

有人会问：一个类里的属性，到底谁加谁不加？标准就两个字——**共享**。你就看当前的属性，它是对象独有的，还是所有对象共享的。

比如下面这个 `Student`：

```java
public class Student {
    // 姓名
    String name;
    // 年龄
    int age;
    // 老师的名字
    static String teacherName;
}
```

`name` 和 `age` 每一个对象都有自己的，是独有的，**不能加** `static`；而 `teacherName`，一个班级的学生共享一个老师，是当前这个类所有对象都共享同一个值，那就**要加** `static`。

这里有个细节我先说明白：我现在没有给这三个属性加 `private`，是因为一旦加上就会衍生出后面的知识点，先用最简单的方式书写。

#### 静态变量的两种调用方式

第一种，用**类名**调用；第二种跟以前一样，用**对象名**调用也能用，只不过我们推荐用第一种：

```java
Student.teacherName = "小文老师";   // 推荐
stu1.teacherName = "小文老师";     // 不推荐，能用但 IDEA 都不给自动提示
```

你不信邪可以试一下，把 `stu1.teacherName` 敲出来，IDEA 压根不给你提示——因为这种方式本身就不推荐。真要写就得强行手打，打完也不会报错。

#### 用 static 模拟"换老师"

现在拿题目练手：学生有姓名、年龄、老师的名字三个属性，一个班级里所有学生共享同一个老师。现在有两个学生对象，第一个小诗诗 19 岁，第二个小丹丹 19 岁；最初老师是小文老师；有一天小丹丹申请更换老师，换成了阿伟老师。请用 `static` 模拟上述效果。

```java
public class Test {
    public static void main(String[] args) {
        Student stu1 = new Student();
        stu1.name = "小诗诗";
        stu1.age = 19;
        Student.teacherName = "小文老师";

        Student stu2 = new Student();
        stu2.name = "小丹丹";
        stu2.age = 19;
        // 注意：我没有用 stu2 去给 teacherName 赋值

        System.out.println(stu1.name + " " + stu1.age + " " + stu1.teacherName);
        System.out.println(stu2.name + " " + stu2.age + " " + stu2.teacherName);
    }
}
```

```text
输出：
小诗诗 19 小文老师
小丹丹 19 小文老师
```

第二个对象明明没有赋过值，为什么 `teacherName` 不是默认的 `null` 而是"小文老师"？因为当前的 `teacherName` 用了 `static` 修饰，一旦修饰，这个类所有对象全都共享同一个值。

那如果我现在头铁，把 `static` 删掉再运行呢？`teacherName` 就变成对象独有的了：我用 `stu1` 赋值，那只有 `stu1` 里有"小文老师"，第二个学生对象访问不到，它就是默认初始化值 `null`。这个对照实验一定要亲手敲一遍，比听十遍都管用。

把 `static` 加回去，再看第二个效果。先在最开始用类名赋值，把下面的赋值删掉，运行，所有学生都是小文老师。然后有一天小丹丹申请换老师——小丹丹换的，所以就用 `stu2` 去改：

```java
        stu2.teacherName = "阿伟老师";
```

再运行，两个对象的 `teacherName` **全变了**。这就是共享的第二个特性：只要有一个对象对变量进行了修改，其他对象再次访问时就是修改之后的结果。

### 哪些属性该加 static：看图说话

第二个练习叫**看图说话**——我给你 N 多个属性，你要能告诉我它到底用不用 `static` 修饰。如果用，为什么；如果不用，为什么。开始：

| 属性 | 加 static 吗 | 为什么 |
| --- | --- | --- |
| `name` 姓名 | 不加 | 加了就表示所有学生共享同一个名字。你叫张三，全班所有人都叫张三，这不可能 |
| `pen` 笔 | 不加 | 所有学生都有自己的笔，不是共享的 |
| `teacherName` 老师姓名 | 得看业务场景 | 在学校里一个班级共享同一个老师，要加；但如果这老师是你的家庭私教，一个学生只对一个老师，就不能加 |
| 水杯 | 不加 | 所有人都用同一个水杯，这叫怎么回事儿 |
| 饮水机 | 加 | 不用的话就是每个学生都有自己的饮水机，我上课旁边放一个饮水机，这不现实吧 |

`teacherName` 那一行最值得记：**到底用还是不用，要有具体的业务场景。** 判断标准始终是那两个字——共享。

到这里，关于用 `static` 修饰成员变量最基本的知识点就全了。下一个视频讲它在内存里到底长什么样。

### 静态变量在内存里长什么样

还是刚才那段代码，只不过我在 `Student` 类里额外加了一个 `show` 方法，把 `name`、`age`、`teacherName` 打印出来。这次我们不背结论，直接看内存图。

```text
         栈                    堆                             方法区
┌────────────────────┐  ┌────────────────────────┐  ┌──────────────────┐
│ main()             │  │ 静态区（Student 类）   │  │ Test.class       │
│  s1 ─► 0x0011 ─────┼─►│  teacherName = 阿伟    │  │ Student.class    │
│  s2 ─► 0x0022 ─────┼─►├────────────────────────┤  └──────────────────┘
│                    │  │ 对象① @0x0011         │
│                    │  │  name = null          │
│                    │  │  age  = 0             │
│                    │  │  ── 静态区地址 ───────┼─┐
│                    │  ├────────────────────────┤ │
│                    │  │ 对象② @0x0022         │ │
│                    │  │  name = null          │ │
│                    │  │  age  = 0             │ │
│                    │  │  ── 静态区地址 ───────┼─┼─► 都指向同一个静态区
└────────────────────┘  └────────────────────────┘ │
```

读图顺序是这样的：运行测试类 `Memory`，它的字节码文件先加载到方法区，JVM 调用 `main`，`main` 进栈开始执行。第一行代码里用到了 `Student` 类——**类一被用到，字节码文件就加载到方法区，并且在内存中同时创建出一个单独存放静态变量的空间，这个空间叫静态区**。静态区里放着这个类所有的静态变量，`teacherName` 默认初始化值 `null`。

这里有个细节必须强调：**此刻内存当中还没有对象**。静态变量是随着类的加载而加载的，它跟对象没有任何关系，优先于对象而存在；对象是通过 `new` 创建出来的，你不 `new` 就不会有对象。

第一行代码执行完毕，因为里面还做了赋值，`teacherName` 从 `null` 变成了"阿伟老师"。

再看第二行，出现 `new` 了，对象这才在内存中出现。等号左边定义变量 `s1`，等号右边在堆里开一个小空间，假设地址是 `0x0011`，这个小空间就是对象，里面存着**所有非静态的成员变量**（`name` 默认 `null`、`age` 默认 0）。与此同时，它还会记录静态区的地址——因为代码里我们也可以通过对象名调用静态变量。最后把 `0x0011` 赋给 `s1`。

下面给 `name`、`age` 赋值，堆里的 `name` 变成"小诗诗"、`age` 变成 23。然后 `s1` 调用 `show` 方法，`show` 进栈，调用者是 `s1`，于是记录 `0x0011`。方法里直接用变量名，触发就近原则——但 `show` 里并没有定义局部变量 `name`、`age`、`teacherName`，所以它就去查调用者 `0x0011` 里的 `name`、`age`，再查静态区里的 `teacherName`，打印出"小诗诗 23 阿伟老师"。

`show` 出栈。接着创建第二个对象，过程就是把刚才的重复一遍：栈里申请 `s2`，堆里开新空间 `0x0022`，存非静态成员变量 `name`、`age`，同样记录静态区地址。然后 `s2` 调用 `show`，这次调用者记的是 `0x0022`，打印出来的是 `null`、`0`，还有到静态区找到的"阿伟老师"。

> 你看，两个对象打印出来的 `teacherName` 完全一样——**所有的对象都共享同一份数据**，静态区里只有一份，谁要谁去拿。

`show` 出栈，`main` 也出栈，栈里的变量和堆里的对象随之消失。**但静态区里的变量、方法区里的字节码信息，这两个是永远存在的**，除非把整个虚拟机关闭，它们才会消失。

到这里静态变量的内存图就讲完了，最后小结一下静态变量的三个特点：

> **结论**：第一，一旦被 `static` 修饰，这个变量就叫静态变量，它被这个类所有的对象共享——注意"共享"这个词，内存当中其实只有一份，放在静态区里，谁要谁去拿；某个对象改了它，其他对象再访问拿到的就是改后的结果。第二，静态变量因为是所有对象共享的，所以它**不属于某一个特定的对象，而是属于类的**。第三，静态变量是**随着类的加载而加载**的，优先于所有对象而存在，只要这个类被使用，静态的东西就已经在内存中出现了；而对象一定要通过 `new` 关键字执行了才会出现。

调用方式再补一句：静态变量有两种调用方式，可以用类名调用，也可以用对象名调用，只不过更推荐用类名。因为它不属于某一个对象，你用对象去调它感觉不合适。

### 工具类：不描述事物，只帮你做事

被 `static` 修饰的成员方法叫**静态方法**，这种方法一般用在测试类或者工具类里，在 JavaBean 类里我们很少使用。调用方式和静态变量一样，可以用类名调用，也可以用对象调用，但同样推荐用类名。

看到这儿我心里有点纳闷：又冒出来一个新名词"工具类"，什么意思？咱们把到目前为止学过的类汇总一下，其实已经学过两种类了：

| 类型 | 有没有 `main` | 干什么用 | 例子 |
| --- | --- | --- | --- |
| JavaBean 类 | 没有 | 描述一类事物 | Dog、Cat、Student、Teacher、Cooker |
| 测试类 | 有，程序主入口 | 让程序跑起来 | 测试类 |
| 工具类 | 没有 | 帮你做一些事情 | `ArrayUtil` |

所谓工具类，它**不是用来描述一类事物的，也没有 `main` 方法，而是帮我们做一些事情的类**。

举个数组合并的例子。现在有一个数组，我要遍历它、求最大值、求最小值。以前为了提高代码复用性，我们会把这些代码单独写成一个方法，写在 `main` 方法的下面。但这么写有点不方便：**如果在其他的类里面也要遍历、也要求最大、求最小，还得把这些方法再写一遍**，太麻烦了。

屏幕上兄弟姐妹们有没有什么想法？这些代码都是重复的，能不能把经常用到的功能单独抽取出来，放在一个独立的类当中？以后要用直接到这个类里去找，不就不需要再写一遍了吗。像这种能帮我们做一些事情的类，就是工具类。

#### 工具类的三步写法

**第一步，看名字就能猜出它是干什么的。** 如果是数组的工具类，一般叫 `ArrayUtil`——`array` 表示数组，`Util` 是命名工具类的习惯，工具类一般都会以 `Util` 结尾。以后别人看到这个名字，就知道这是一个数组的工具类。

**第二步，私有化构造方法。** 工具类不是用来描述一类事物的，创建它的对象没有任何意义，那干脆就私有化构造方法，不让外界去创建对象。

你问真的是这样吗？我们试一试。先写一个 `private ArrayUtil() {}`，然后到测试类里创建对象 `new ArrayUtil()`——程序都不用运行，直接就报错了，鼠标悬停上去提示：`ArrayUtil()` 在这个类里是 `private` 私有的。如果我头铁一下把它改成 `public`，确实就可以了；但我们还是回归原位，改回 `private`，一旦是 `private`，外界就不能创建它的对象了。

**第三步，所有的方法都定义为静态的。** 私有化构造方法之后外界创建不了对象，那对象里面的方法怎么调用呢？所以方法必须全部写成静态的，直接用类名调用。

```java
public class ArrayUtil {

    private ArrayUtil() {
    }

    public static void printArr(int[] arr) {
        // ...
    }

    public static double getAverage(int[] arr) {
        // ...
    }
}
```

一句话记住为什么：**如果不写成静态的话，外面根本没法调用——既没有对象，又不能用类名调用，你怎么调？完全调不了。**

#### 动手写一个 ArrayUtil

题目需求：在实际开发中经常会用到数组的工具类，请按照如下需求编写一个工具类，第一个提供一个方法 `printArr` 用于遍历数组，格式如下；第二个提供一个方法 `getAverage` 用于获取数组的平均值。

先写 `printArr`。题目说只要考虑整数数组，所以形参就是 `int[] arr`。遍历的格式是这样的：先打印一个左方括号，然后遍历数组 `arr`，对 `i` 做判断——如果 `i` 是当前的最大索引 `arr.length - 1`，就打印 `arr[i]` 加上一个右方括号；如果不是，就打印数据加上逗号空格。

> **注意**：这里记得把 `println` 的 `ln` 给去掉，只有打印完最后一个数据的时候才有换行。

```java
    // 1. 遍历数组
    public static void printArr(int[] arr) {
        System.out.print("[");
        for (int i = 0; i < arr.length; i++) {
            if (i == arr.length - 1) {
                System.out.print(arr[i] + "]");
            } else {
                System.out.print(arr[i] + ", ");
            }
        }
        System.out.println();
    }
```

测试类里创建一个数组 `int[] arr = {1, 2, 3, 4, 5, 10}`，格式化一下代码（`Ctrl + Alt + L`），然后遍历就不需要自己写了，直接调用工具类里的方法：`ArrayUtil.printArr(arr)`，运行，`[1, 2, 3, 4, 5, 10]` 打印出来。以后再遍历数组，代码一行都不用写，直接用工具类，**一劳永逸**：整个项目当中我只要写一次，用到了直接调。

当然这个代码还可以改写。如果我不想直接打印，想把它拼接成一个字符串返回，该怎么办？也有办法——把返回值改成 `String`，先定义一个字符串 `result` 默认赋值空串，下面不打印了，而是把要打印的内容拼接到 `result` 上面：

```java
    // 2. 遍历数组（返回字符串版）
    public static String printArr(int[] arr) {
        String result = "";
        result += "[";
        for (int i = 0; i < arr.length; i++) {
            if (i == arr.length - 1) {
                result += arr[i] + "]";
            } else {
                result += arr[i] + ", ";
            }
        }
        return result;
    }
```

回到测试类，调用完之后还要做一件事情：**用一个变量去接收一下**，`String res = ArrayUtil.printArr(arr);`，然后直接打印 `res`，运行，结果跟刚才一样。所以 `printArr` 有两种写法，一个是直接打印，一个是拼接成字符串返回；返回之后你想打印，或者想做一些其他操作，都随你。

继续第二个需求 `getAverage`，返回数组的平均分。思路是一样的：要平均分就得先有数组，所以形参是 `int[] arr`；要求平均分得先求总和，`int sum = 0`，遍历数组把每一个数据都累加到 `sum` 里，循环结束之后 `sum` 就是总分；平均分就是拿 `sum` 除以 `arr.length`，也就是数组里数据的个数。

```java
    // 3. 求平均值
    public static double getAverage(int[] arr) {
        int sum = 0;
        for (int i = 0; i < arr.length; i++) {
            sum += arr[i];
        }
        double avg = sum * 1.0 / arr.length;
        return avg;
    }
```

> **易错点**：这个地方有个小坑，千万别忘。假设数组里的数据是 `1 2 3 4 7`，口算总和是多少？17，对吧。那 17 除以 5 呢？在程序当中**整数跟整数相除只能得到整数**，所以你得到的结果应该是 `3`。但这不符合数学规律，求平均分一般来讲都是一个小数。所以必须先拿着 `sum` 去乘以 `1.0`，先把它变成小数参与计算，这样结果才是一个小数。当然，如果你不想定义变量，直接把这个结果 return 回去也是 OK 的。

测试类里 `int[] arr2 = {1, 2, 3, 4, 7}`，然后直接调用 `ArrayUtil.getAverage(arr2)`。这里再分享一个快捷键：**`Ctrl + Alt + V` 可以自动生成左边的接收变量**。点一下方法按这个快捷键，左边的变量就不需要我自己写了，直接自动生成好。

然后打印 `avg`，运行，`3.4` 就有了。那如果说我在刚刚没有加那个乘 `1.0`，右键再运行，结果是不是就变成 `3` 了？这个小坑咱们千万别忘。

#### 编写数组工具类

## static 的边界、final 与枚举
> 对应块：BLK25 | 覆盖分集：P100-P102 | 块标题（分集名）：《第10章-面向对象进阶-04-static关键字》

到目前为止，`static` 关键字我们算是彻彻底底学完了。前面讲了静态变量怎么定义、静态方法怎么用，今天最后这一段，我们把 `static` 的注意事项收个尾，然后一路往后面推——`final` 关键字，还有枚举。

先说一句实话：`static` 的这三条注意事项，听起来是有点拗口的。"静态方法只能访问静态"，"非静态可以访问所有"，"静态方法里没有 `this`"，三句话连着背，容易背串。所以今天我不打算让你背，我会带你在内存里走一遍，走完这三条就是水到渠成的事。

### static 的三条边界

先把代码摆出来，你一眼就能看出边界在哪。

```java
public class Test {
    // 普通成员变量
    int a;
    // 静态成员变量
    static int b;
    // 普通成员方法
    public void showA() {
    }
    // 静态方法
    public static void methodA() {
        System.out.println(a);   // 红色报错：调用了非静态的内容
        System.out.println(b);   // 正确
        showA();                 // 红色报错
        methodA();               // 正确
    }
}
```

`methodA` 是静态方法，里面调 `a`（普通成员变量）报错、调 `showA()`（普通成员方法）报错，调 `b`（静态变量）和 `methodA()`（静态方法）都对。

> **结论**：静态只能访问静态。

第二条就反过来写。同一个类里再补一个 `showB`，注意它**没有写 `static`**，所以它就是一个普通的成员方法：

```java
    public void showB() {
        System.out.println(a);   // 正确
        System.out.println(b);   // 正确
        showA();                 // 正确
        methodA();               // 正确
    }
```

不管调用静态的还是非静态的，全部正确。

> **结论**：非静态能调用所有。

第三条最简单：静态方法里面没有 `this` 关键字，你不能用 `this` 去点调用其他的内容。

三条边界合起来就是：**静态只能访问静态；非静态可以访问所有；静态方法里面没有 `this` 关键字。**

### 为什么是这条边界：跟着内存走一遍

光背结论没用，我们得知道它为什么是这样。之前学过一个说法——**静态的内容是随着类的加载而加载的，它先进内存，优先于对象而存在**；而**非静态的内容是跟对象有关的，要有对象才有非静态的成员变量**。

就这一句话，两条结论全出来了：静态的进了内存，此时不一定有对象，所以静态只能调静态；非静态的内容出现在内存里，说明什么？说明类已经加载了、静态变量已经加载了，对象也创建好了，所以非静态可以调用所有。

道理是这个道理，我们还是拿 `Student` 实地跑一遍，看看内存里到底发生了什么。

```java
public class Student {
    // 非静态的 name
    String name;
    // 静态的 teacherName
    static String teacherName;

    public static void methodA() {
        System.out.println(name);         // 红色报错
        System.out.println(teacherName);  // 正确
    }

    public void show() {
        System.out.println(name);
        System.out.println(teacherName);
    }
}

public class Test {
    public static void main(String[] args) {
        // 第一行：先给静态变量赋值
        Student.teacherName = "老王";
        // 第二行：调用静态方法
        Student.methodA();
        // 想调用 show，必须先创建对象，再用对象去调
        Student stu = new Student();
        stu.show();
    }
}
```

**第一步，`main` 进栈，开始执行第一行代码。** 第一行用到了 `Student`，于是 `Student` 的字节码文件被加载到方法区当中。

```text
 Step 1:  main() 第一行用到了 Student，字节码先进方法区

   Stack / 栈                   Method Area / 方法区
 +-------------------+        +----------------------------------+
 |  main()           |        |  Student.class                   |
 |    frame          | -----> |    static  区:                    |
 |                   |  加载   |      teacherName = null          |
 +-------------------+        |    instance 区:                   |
                              |      name   (还没有对象，不存在)  |
                              +----------------------------------+

   Heap / 堆:  空，一个 Student 对象都还没有
```

这里有个细节你一定要卡住：**静态变量 `teacherName` 是随着类的加载而加载的，优先于对象存在**。所以我管你有没有创建对象，此刻静态区里已经躺着一个 `teacherName` 了，默认初始化值 `null`。

而 `name` 呢？它是个普通成员变量，你得先创建对象才会有 `name`。所以现在堆里根本没有对象，内存中就不存在 `name`。

**第二步，`main` 继续执行第二行，调用静态方法 `methodA()`。** `methodA` 进栈。

```text
 Step 2:  调用静态方法 methodA()

 +--------------------------------+
 |  methodA() frame      (栈)     |
 |    没有 this，不记录调用者地址 |
 |                                 |
 |    name        -> 堆里根本没有 |
 |                   对象，压根找  |
 |                   不到 -> 报错 |
 |    teacherName  -> 直接去静态区 |
 |                   取 null      |
 +--------------------------------+

 Step 3:  就算这里已经创建了对象，也照样不行

 +--------------------------------+       +------------------------+
 |  methodA() frame                |  ?    | Heap: Student 对象   |
 |    没有 this，压根不知道找谁   | ----> |        (0X0011)      |
 +--------------------------------+       +------------------------+
```

方法里我要拿 `name` 和 `teacherName` 两个变量。问题就来了——堆里面现在**有没有对象**？我还没创建对象呢！所以这个 `name` 它获取谁呀？它根本就找不到，所以直接报错。

`teacherName` 就没这个问题了：`Student` 加载到方法区的时候，静态区就已经出现了，它直接到静态区里把值取出来就行。

而且就算我"作势"先创建了对象，又能怎样？**因为静态方法里没有 `this`，它不会记录调用者的内存地址，就算去找，它也不知道自己该找谁。**

> **易错点**：静态方法当中无法调用非静态的内容。就算你在调用点前面已经 `new` 出了对象，静态方法里没有 `this` 指引，照样找不到人。

**第三步，换成非静态的 `show` 试试。** 非静态的成员方法只有一种调用方式，就是用对象来调，它不能用类名调。所以想调 `show`，必须先 `new` 一个 `Student`，再用对象去调。

```text
 Step 4:  用对象 stu 调用 show()

   Stack / 栈                     Heap / 堆
 +----------------------+      +-----------------------------+
 |  main()              |      |  Student 对象 (0X0011)      |
 +----------------------+      |    name        = null       |
            |                  |    teacherName = "老王"     |
            | new              +-----------------------------+
            v                            ^
 +----------------------+                |
 |  show() frame         | --- this --->  |  调用者就是它自己      |
 |    this = 0X0011      |                |
 +----------------------+
```

`show` 进栈的那一刻，它**会记录调用者的内存地址 `0X0011`**——非静态的成员方法里是有 `this` 的。

然后在方法体里要拿 `name` 和 `teacherName`，直接写变量名，触发**就近原则**：先到方法自己里面看有没有对应的局部变量；没有，再去看调用者 `this`，也就是 `0X0011` 那个对象。`name` 找到值是 `null`，`teacherName` 也能找到。于是最终数据就出来了。

> **结论**：非静态的成员方法里可以调用静态的内容，也可以调用非静态的内容，可以调用所有。

### 把 static 一次收口

到这儿 `static` 就彻底学完了，我们完整回顾一遍。

`static` 是 Java 里的一个修饰符，可以修饰成员方法，也可以修饰成员变量。

修饰成员变量时，这个变量就叫**静态变量**。它有四个特点：被该类所有的对象共享、跟对象无关、随着类的加载而加载、优先于对象而存在。它有两种调用方式，可以用类名调用，也可以用对象来调用，**推荐用第一种**。

修饰方法时，这个方法就叫**静态方法**。它多用在测试类和工具类当中，在 JavaBean 里面很少使用。它的调用方式跟静态变量一样，类名和对象都能调，一样推荐用类名。

### 重新认识 main 方法

`main` 方法里的那几个关键字，到今天也全部学完了：`public`、`static`、`void`、`main`、`String[] args`。现在我们可以重新、认真地认识它一次。

```java
public class Test {
    public static void main(String[] args) {

    }
}
```

- `public`：访问权限，公共的，权限最大，虚拟机可以在任意地方调用它。
- `static`：静态。正因为 `main` 方法是静态的，虚拟机在调用的时候就可以用类名直接调。也正因为它是静态的，如果我们在测试类下面再写其他的方法，**这些方法也得写成静态的**。
- `void`：表示 `main` 方法没有返回值。
- `main`：它其实**不是关键字，而是方法名**，是一个被虚拟机识别的固定名字。你要是写成 `AAA`、`BBB`、`CCC`，虚拟机就不认识了，它只认识 `main`。
- `String[] args`：字符串类型的数组，用来接收运行参数，这个数组我们暂时用不到。

### final：不可变

第二个知识点，`final`。

`final` 翻译成中文就是**最终、不可变**。它一共可以修饰三样东西：变量、类、方法。

其中用 `final` 修饰类、修饰方法，这会涉及到后面的继承知识点，所以今天我们先把第一个——**用 `final` 修饰变量**——学透。

#### 常量的定义与两个特点

用 `final` 修饰完的变量，就叫**常量**。写法特别简单，在变量的前面直接加一个 `final` 关键字：

```java
public class FinalTest {
    // 定义一个常量
    final int NUMBER = 100;

    public static void main(String[] args) {
        // 常量的使用跟变量一样，可以加减乘除，也可以直接输出打印
        System.out.println(NUMBER);        // 100
        System.out.println(NUMBER + 100);  // 200

        // NUMBER = 200;                   // 报错：cannot assign a value
    }
}
```

常量有两个特点：

- **只能被赋值一次**，一旦赋值成功，就不能再改变里面的数据了；
- **为了跟其他变量区分开**，常量的名字我们一般是大写的；如果有多个单词，需要用下划线隔开。

注意这里有个细节：常量定义完之后，在下面试图修改 `NUMBER` 的值，程序都不用运行，直接红色波浪线就报错了。把鼠标悬停上去，它告诉你 `cannot assign a value`。

忘了为什么会报错也没关系，选中它右键用通义灵码问一句就行——它给的回答跟我们的解释完全一致：常量一旦初始化，也就是一旦赋值成功之后，就不能够再被修改了。

#### 基本数据类型：变的是数据本身

但这里有个小细节，而这个细节跟我们修不修 `final` 的变量有关：**因为变量是有数据类型的，而数据类型分两种**——一种叫基本数据类型，一种叫引用数据类型。`final` 修这两种类型的时候，结果是不一样的。

基本数据类型还记得吧，就是 `byte`、`short`、`int`、`long`、`float`、`double`、`char`、`boolean`，四类八种。除此之外所有数据类型都是引用数据类型，比如之前写的数组、之前写的 `Student`、`Teacher`，都算引用数据类型。

```java
public class FinalTest2 {
    // 基本数据类型：变量里面记录的是真实的数据
    final int A = 10;
    // 此时变量里面记录的数据无法发生改变
}
```

在基本数据类型当中，变量里记录的是**真实的数据**。现在写一个 `int a = 10`，这个 10 是真真切切就存在变量 `a` 里面的。所以我们用 `final` 修饰之后，不变的就是**变量里面记录的数据**。

#### 引用数据类型：变的是内存地址

那如果是引用数据类型呢？先建一个 `Student`：

```java
public class Student {
    private String name;
    private int age;

    public Student() {
    }

    public Student(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public int getAge() {
        return age;
    }

    public void setAge(int age) {
        this.age = age;
    }
}
```

回到 `main` 方法。如果 `student` 前面用了 `final` 修饰，你觉得还是数据不能改变吗？

**其实不是的。**

因为在引用数据类型当中，变量里面记录的不是"张三""李四"这种数据，它里面记录的是**对象的内存地址**。所以不可改变的是这个变量记录的内存地址，而**对象里面的属性值它还是可以发生改变的**。

```java
final Student STU = new Student("张三", 23);

// STU = new Student();          // 报错：相当于把第二个对象的地址赋给了 STU
STU.setName("李四");              // OK
STU.setAge(23);                  // OK
System.out.println(STU.getName());
System.out.println(STU.getAge());
```

如果你在下面再 `new` 一个 `Student`，这相当于创建了第二个对象，把第二个对象的地址值赋值给了 `STU`，也就是修改了这个变量里面记录的内存地址，所以直接报错，是不行的。但修改对象本身的属性值是可以的。

用内存图看一眼就特别清楚：

```text
   STU 这个变量（final 修饰的是它本身）
   +------------------+
   |  0X0011          |   <-- 这个内存地址不可再改变
   +------------------+
            |
            v
   +-------------------------------+
   |  Student 对象                  |
   |    name   = "李四"   可以改   |
   |    age    = 23        可以改 |
   +-------------------------------+
```

代码里 `final` 加在 `Student` 类型的变量前面，它修饰的**根本不是** `name` 和 `age`。既然没修饰，那对象里的这些属性当然可以变化。

> **结论**：`final` 修饰哪个变量，哪个变量里面记录的内容就无法再次发生改变。基本数据类型变的是数据本身；引用数据类型变的是内存地址。

#### 想让属性也不变，就得加在属性上

有的同学会想：那如果我想让 `name`、想让 `age` 也不发生变化，怎么办呢？

其实很简单，你只要在 `name` 的前面、或者 `age` 的前面也加上 `final` 就可以了，这样对象里面的属性就不会发生变化了。

```java
public class Student {
    // 属性前面也加上 final, 就得手动赋值
    final String name = "张三";
    final int age = 23;

    public String getName() {
        return name;
    }

    public int getAge() {
        return age;
    }
}
```

一加上 `final`，问题就来了：`set` 方法直接报错。因为 `final` 修饰的变量只能赋值一次，赋值成功之后后面就不能再改，所以这里的 `set` 方法跟 `final` 冲突了，我们要把 `set` 方法删掉。

删完 `set` 方法还不够，构造方法在这里它也有冲突——IDEA 认为你在构造方法里也发生修改了。所以构造方法也得删掉，改成在上面手动进行赋值，`name` 就直接写死成 `"张三"`，`age` 就写死成 `23`，代码一下子就对了。

回到测试类：

```java
public class FinalTest3 {
    public static void main(String[] args) {
        // 创建一个引用数据类型的变量
        Student stu = new Student();

        // stu.name = "AAAA";     // 报错：final 修饰的 name 不能修改

        // 不能改, 但是可以获取
        System.out.println(stu.name);         // 张三
        System.out.println(stu.getName());    // 张三, 通过 get 方法同样能获取到
    }
}
```

> **易错点**：`final` 禁止的是"再次赋值"，不是"读取"。属性被 `final` 修饰之后，你照样可以用对象直接去点它取值，也可以通过 `get` 方法取值。

### final 的结论再捋一遍

用 `final` 修饰一个变量，这个变量就叫做常量。常量的特点有两个：**只能被赋值一次**，一旦赋值无法再次修改；**常量的名字大写**，涉及到多个单词要用下划线隔开。

然后是两种情况。变量有基本数据类型和引用数据类型之分：如果 `final` 修饰的是基本数据类型——四类八种——那么不能改变的是**变量里面记录的数据**；如果 `final` 修饰的是引用数据类型，那么真正不能改变的是变量记录的**内存地址**，对象里面的属性还是可以发生改变的。想要属性也不变，就得像刚才那样，在属性定义的时候也得加上 `final`。

到这儿关于 `final` 修饰变量就全部学完了。

### 练一个 Circle：final 在开发里的样子

暂停一下，我们来写一个小练习，看一看 `final` 在实际开发当中到底有什么作用。

**题目的需求**：定一个 JavaBean 类去描述圆，圆里面有两个属性，一个是半径 `radius`，还有一个是圆周率 `pi`；在类里面要提供两个行为，也就是方法，第一个是计算圆的面积，第二个是计算圆的周长。

打开 IDEA，新建一个类，就叫 `Circle`。

```java
public class Circle {
    // 半径
    private double radius;

    // 圆周率
    private static final double PI = 3.14;

    public Circle() {
    }

    public Circle(double radius) {
        this.radius = radius;
    }

    public double getRadius() {
        return radius;
    }

    public void setRadius(double radius) {
        this.radius = radius;
    }

    // 常量只有 get 方法, 没有 set 方法
    public static double getPI() {
        return PI;
    }

    // 行为: 计算圆的面积
    public double getArea() {
        return PI * radius * radius;
    }

    // 行为: 计算圆的周长
    public double getLength() {
        return PI * radius * 2;
    }
}
```

写属性的时候，`radius` 你也可以写成 `RADIUS`，都是可以的。而 `PI` 这里你要注意了——**它有可能发生变化吗？它不可能**。所以说在这个前面我们用 `final` 来进行修饰，一旦修饰完了之后，`PI` 就变成常量，记得一定要大写。

那个派是多少来着，3.141592653589… 算了不背了哈，咱就直接写成 `3.14`，这就 OK 了。

然后按照 JavaBean 的规矩，我们还要写构造方法，再针对每一个私有化的成员变量提供对应的 `get` 和 `set` 方法。这里有个特别直观的细节：**IDEA 在生成构造方法的时候，根本就没有管那个 `PI`**，为什么？因为它是常量，一旦赋值下面就不要再去改动了。

再生成 `get and set` 的时候，默认选中的是半径；如果我把 `PI` 也一起选中，点击 OK——你看到了吗？**它没有生成 `setPI` 那个方法**，只生成了一个 `get` 方法。这就是常量：只能赋值一次，不能再进行修改。

最后把两个行为补上。面积就是 $S = \pi r^2$，周长就是 $C = 2\pi r$，所以方法体里直接 `return PI * radius * radius;` 和 `return PI * radius * 2;` 就完事了。

回到测试类跑一遍：

```java
public class FinalTest4 {
    public static void main(String[] args) {
        // 创建一个圆的对象
        Circle c = new Circle();
        c.setRadius(1.5);

        // 获取圆里面的属性
        System.out.println(c.getRadius());  // 1.5
        System.out.println(c.getPI());       // 3.14

        // 调用圆里面的两个行为
        System.out.println(c.getArea());    // 面积
        System.out.println(c.getLength());  // 周长
    }
}
```

右键 Run，半径、`PI`、面积、周长都出来了。

> **结论**：`final` 在实际开发当中真正的应用场景，说白了就是：**以后你发现一个数据它是固定的、不能变的，那你就直接用 `final` 修饰它**，这样就可以了。

### 枚举：给对象的个数划一条上限

第三个知识点，枚举。

#### JavaBean 挡不住"不能多不能少"

先看一个案例。假设我现在有一个 JavaBean 类 `Dog`，那么根据之前所学，我就可以根据 `Dog` 类去创建小狗的对象。要注意，此时我创建对象的个数是**没有任何限制**的，我可以创建无数个小狗的对象。

这种写法在大多数情况下是合理的，我们也是这么干的。**但是**在某些特殊的情况下，如果说我要求对象的个数是有限个的，假设我规定它只有 5 个、只有 6 个，那么这种写法就不合理了。

比如电商项目当中**订单的状态**。假设现在我规定订单的状态只能有 6 个，不能多，不能少，不能自己编造其他的状态。那么此时用之前学习的 JavaBean 就不合理了，因为你直接用 JavaBean，你没有办法控制我到底创建多少个对象。我现在可以讲规矩就创建 6 个，但是**如果我不讲规矩呢**？我创建 60 个、600 个，甚至 6000 个对象，在语法当中都是可以的。

所以当对象的个数要求是有限个的时候，就不能够用以前的 JavaBean 的形式了，得用枚举。

**那什么是枚举？枚举其实它也是一个特殊的 JavaBean，只不过这个类里面的对象它是有限个的。** 比如订单状态，我规定了只有这 6 个，你不能有其他的，那就得用枚举。

除了订单状态，现实生活里这种"数量有限"的东西一抓一大把：

| 场景 | 有限的状态 |
| --- | --- |
| 电商订单 | 待支付、处理中、已发货、配送中、已送达、已取消 |
| 月份 | 一年只有 12 个 |
| 星期 | 一周只有 7 个 |
| 游戏职业 | 战士、法师、弓箭手…… |
| OA 项目会议室预约 | 空闲、已预订、申请中 |
| 物联网设备监控 | 未开机、已启动、正常、异常 |

这些场景有一个共同点：**对象的个数是有限个的**。所以在这些情况下，我们就得用枚举。

#### 枚举的定义格式与枚举项

枚举的定义格式是这样的。因为枚举它也是一个特殊的 JavaBean 类，所以说在这个里面它也有属性，还有行为。只不过在定义的时候你不能用 `class` 了——`class` 它表示定义一个普通的类，此时得用 `enum`，用这个关键字去定义一个枚举，后面跟随着枚举类的类名。

```text
+--------------------------------------------------------------+
|  enum 枚举名 {                                                |
|                                                              |
|      枚举项1(参数), 枚举项2(参数), 枚举项3(参数);             |
|                                                              |
|      // 属性                                                 |
|      // 构造方法（必须私有化）                                |
|      // 成员方法                                             |
|  }                                                           |
+--------------------------------------------------------------+
```

枚举里面的内容该怎么写呢？不着急，我们来推导一下。通过刚刚的学习我们知道，枚举最大的特点就是**它对象的个数是有限个的**。那我怎么去限定别人到底创建多少个对象呢？

其实很简单：**我可以提前把所有的对象都创建出来，然后把这些对象写在枚举类的第一行**，对象跟对象之间用逗号隔开，最后以分号结尾。

枚举类的对象有一个专业的称呼，叫做**枚举项**。所以每一个枚举项其实就是当前枚举类的对象。那么在外界如果说我要使用对象了，就不需要自己再创建了，直接去调用就可以了。

这里再补一个特别容易被忽略的小细节：**在程序当中什么才叫"一行代码"？是以换行为标记吗？不是，它是以分号为标记。** 看到一个分号，这个语句才叫一行代码。所以即使你的枚举项写了很长很长，前面的这一大堆，在编译器眼里它就是一行代码。

#### 把 OrderState 从 JavaBean 改写成枚举

打开 IDEA，新建一个包 `enumtest`，然后我们用枚举来做一个小练习。

因为现在我们是第一次写枚举，写得还不是特别熟，所以我的建议是：**先去写 JavaBean，再去把这个 JavaBean 改成枚举**就可以了，因为枚举本身就是一个特殊的 JavaBean。

先看标准 JavaBean 的写法：

```java
public class OrderState {
    // 属性: 当前状态的名字
    private String name;

    public OrderState() {
    }

    public OrderState(String name) {
        this.name = name;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }
}
```

属性其实只有一个，就是当前状态的名字，像"待支付""处理中""已发货"，这些其实就是 `name`。然后空参构造、全参构造，再给私有化的成员变量提供 `get` 和 `set`，一个标准 JavaBean 就写完了。

在外界创建对象也很简单：

```java
OrderState o1 = new OrderState();
o1.setName("待支付");
```

只不过这种写法不太合适，因为我们可以创建无数个订单状态的对象，这不符合题目的需求。接下来把它改成枚举，**一共四刀**。

**第一刀，把定义的关键字改掉。** 不用 `class` 了，改用 `enum`。改完之后你注意看左边——**它的图标也变了，变成一个紫色的 "E"**，就表示当前定义的是一个枚举。

**第二刀，在枚举的第一行写出这个类所有的对象。** 一共有 6 个。顺序跟创建对象的语句一一对应：

```java
public enum OrderState {
    PAYMENT_PENDING("待支付"),
    PROCESSING("处理中"),
    SHIPPED("已发货"),
    OUT_FOR_DELIVERY("配送中"),
    DELIVERED("已送达"),
    CANCELLED("已取消");
```

具体的做法是，把创建对象那行代码 `Ctrl+X`、`Ctrl+V` 粘贴过来，从里面取两部分：**第一部分是对象的名字**，它就是枚举项；**后面小括号里的内容也得搬过来**——它表示我创建这个对象需要调用哪个构造方法，我调用的是下面的有参构造，你需要把"待支付"传递过去。

这就是枚举项完整的写法：前面一部分表示对象名，后面这部分表示创建这个对象要传的参数。第一个枚举项写完，后面五个就都是体力活了，`Ctrl+C`、`Ctrl+V` 一路复制下来即可。

> **易错点**：**最后一个枚举项的后面，记得一定要用分号来作为结尾。**

嫌太长？折行就行；或者每一个枚举项单独写成一行也完全可以，反正编译器只认分号。

**第三刀，空参构造删掉。** 因为创建对象的时候我统一用的都是有参构造，空参构造对我来讲没有用了。

**第四刀，有参构造的修饰符改成 `private`，同时把 `setName` 删掉。**

为什么构造方法要私有化？因为**你不让外界创建对象嘛**。如果说你强行写成 `public` 的，你看，它是报错的，因为它跟枚举的设计初衷就违背了——你写 `public`，外界就能创建对象了。所以要改成 `private`。

而 `setName` 为什么删？因为所有的对象我都已经罗列出来了，我根本就不需要去修改里面的属性值了，所以这里的 `setName` 对我来讲也没有用了，直接保留 `getName` 就可以。

整理完就是这样一个标准的枚举类：

```java
public enum OrderState {
    PAYMENT_PENDING("待支付"),
    PROCESSING("处理中"),
    SHIPPED("已发货"),
    OUT_FOR_DELIVERY("配送中"),
    DELIVERED("已送达"),
    CANCELLED("已取消");

    private String name;

    private OrderState(String name) {
        this.name = name;
    }

    public String getName() {
        return name;
    }
}
```

#### 取出枚举项并 switch 匹配

回到测试类。有一个小细节要跟大家说：**所有的枚举项都是默认使用 `public static final` 去修饰的**，就算你没写，虚拟机在前面也会给你加上。

好，现在你看到了，有 `public`，有 `static`，所以你想到了怎么调用了？是不是可以直接用枚举类的类名去调用？

```java
OrderState.PAYMENT_PENDING
```

就表示待支付的对象。写完右边，`Ctrl+Alt+V` 自动生成左边的变量名，起个名字叫 `o1`：

```java
public class EnumTest {
    public static void main(String[] args) {
        // 取出枚举项
        OrderState o1 = OrderState.PAYMENT_PENDING;

        System.out.println(o1);                 // 第一个对象就打印出来了
        System.out.println(o1.getName());        // 待支付

        // 拿状态去匹配
        switch (o1) {
            case PAYMENT_PENDING:
                System.out.println("当前是待支付状态");
                break;
            case PROCESSING:
                System.out.println("当前是处理中状态");
                break;
            case SHIPPED:
                System.out.println("当前是已发货状态");
                break;
            case OUT_FOR_DELIVERY:
                System.out.println("当前是配送中状态");
                break;
            case DELIVERED:
                System.out.println("当前是已送达状态");
                break;
            case CANCELLED:
                System.out.println("当前是已取消状态");
                break;
        }
    }
}
```

拿到 `o1` 之后，我就可以用 `switch` 来进行匹配，拿它跟你所有的状态去比对，看你当前订单到底是什么状态。右键 Run，输出"当前是待支付状态"。

以后在真实的企业级项目当中，就是这样：**先去获取你当前订单的状态，然后拿着这个状态跟我所有的状态进行匹配。** 至于用 `if` 还是用 `switch`，你看着来。

### 本讲提到的题目

这一讲里一共出现了两道题目，都在课上完整写完了，解析也都跟在代码后面，这里只把题干和结论重新收拢一遍，方便你回头自己复现。

**Circle 题（`final` 的实际应用）**：定义一个 JavaBean 类去描述圆，包含半径 `radius` 与圆周率 `pi` 两个属性，并提供计算圆的面积与周长两个方法。

解析的关键只有一处：`pi` 是一个永远不会变的数据，所以必须用 `final` 修饰，并且名字要大写成 `PI`。AreaID 在生成构造方法和 `get and set` 时会自动跳过 `PI`——不给它生成 `setPI`，这本身就是常量"只能赋值一次"最直观的证据。两个行为分别是 $S = \pi r^2$ 与 $C = 2\pi r$。详细写法见《练一个 Circle：final 在开发里的样子》。

**OrderState 题（枚举的定义与使用）**：定义一个 JavaBean 类去描述电商项目中订单的状态，状态共 6 个：待支付、处理中、已发货、配送中、已送达、已取消。

解析：先写标准 JavaBean，再四刀改成枚举——`class` 改 `enum`；把所有对象以枚举项的形式写在第一行，用逗号隔开、末尾以分号结尾；空参构造删掉；有参构造改为 `private`；`setName` 删掉只留 `getName`。使用时 `OrderState.PAYMENT_PENDING` 直接通过类名取出（枚举项默认被 `public static final` 修饰），再配合 `switch` 做状态匹配。详细写法见《把 OrderState 从 JavaBean 改写成枚举》。
