## 枚举的五个注意点，以及继承与复杂继承体系的设计
> 对应块：BLK26 | 覆盖分集：P103-P105 | 块标题（分集名）：《第10章-面向对象进阶-07-枚举的注意事项》

前面咱们已经把"什么是枚举"学完了，接下来要过的是枚举的注意事项。别看只有五条，真正容易被忽略的细节全藏在这里——比如你明明一个 `public static final` 都没写，为什么反编译出来却满是这三个关键字。

不过这一块内容比较杂，咱们先把枚举的坑点讲透，然后一路开进继承：继承是什么、父子关系怎么建、什么时候才该抽父类，最后再解决一个更实际的问题——**面对一堆有重叠的类，继承体系到底该怎么设计**。

### 枚举的五个注意点

第一条：**每一个枚举项都是该类的对象**。这句话还得再补半句——每一个对象都是通过构造方法创建出来的。

第二条：**枚举项在底层其实就是一个常量**，前面默认使用 `public static final` 修饰。`public` 权限最大，任意地方都能调用这个枚举项；`static` 表示静态，可以用类名点的方式调用；`final` 表示不可变。

第三条：**枚举类的第一行必须是枚举项**，枚举项之间用逗号隔开，以分号结尾。后面的半句话，前面是它的半句话——要万分注意，第一行必须是枚举项，不能写别的。

第四条：**枚举类的构造方法必须是 `private` 的**，目的是不让外界创建本类的对象。

第五条：**编译器会给枚举类新增两个默认方法**，一个是 `values`，一个是 `valueOf`。就算我们不写这两个方法，它们也能直接用，是编译器自动加上的。

下面打开 IDEA，一个一个用代码说明。

#### 每一个枚举项，都是一个被构造出来的对象

先看第一条。咱们准备了一个订单状态的枚举 `OrderState`，里面有六个枚举项：待支付、处理中、已发货、配送中、已送达、已取消。为了验证"枚举项是对象"，我干了一件很朴素的事——**在构造方法的第一行加一句打印**：

```java
public enum OrderState {
    待支付("待支付"), 处理中("处理中"), 已发货("已发货"),
    配送中("配送中"), 已送达("已送达"), 已取消("已取消");

    private final String name;

    private OrderState(String name) {
        System.out.println("看看我执行了吗" + name);
        this.name = name;
    }

    public String getName() {
        return name;
    }
}
```

然后在测试类里，只要通过类名点一个枚举项出来，再把它的名字打印：

```java
OrderState o1 = OrderState.处理中;
System.out.println(o1.getName());
```

运行结果：

```text
看看我执行了吗待支付
看看我执行了吗处理中
看看我执行了吗已发货
看看我执行了吗配送中
看看我执行了吗已送达
看看我执行了吗已取消
处理中
```

最后那行"处理中"是 `o1.getName()` 打出来的，不重要；**重要的是上面那六行**——它是在我们刚刚那个构造方法里打印的。

这就把第一条讲透了：当我运行 `OrderState.处理中` 的时候，程序底层已经把六个对象**全部创建出来**放在那儿了，等着以后去用；而且每一个对象都是通过构造方法创建出来的。要不然那句话根本不会打印，对吧？

现在我用的是有参构造，那我如果想用无参构造创建呢？把无参构造再补一个过来，小括号里什么都不写就行：

```java
public enum OrderState {
    待支付, 处理中, 已发货, 配送中, 已送达, 已取消;

    private OrderState() {
        System.out.println("看看我执行了吗");
    }
}
```

把 `处理中(name)` 改成 `处理中()`，你发现它同样是正确的——此时这六个对象就是通过无参构造创建的。当然，实际开发里我们还是会把描述信息放进字段里，用有参构造更常见。

#### 枚举项在底层就是常量

第二个注意点。回到上面那段原始代码，注意看：**我没有写 `public static final`**，但这三个关键字虚拟机（准确说是编译器）会自动帮我们加上。

怎么证明？不能光靠嘴说，咱们把编译出来的 class 文件翻出来看。

class 文件在项目里的 `out/production/<模块名>/<包路径>/` 下面，找到 `OrderState.class`。直接右键用记事本打开是看不了的——那里面是二进制。

正确做法是反汇编。在 `out` 目录的地址栏里点一下，输入 `CMD` 回车，然后用 JDK 自带的 `javap` 命令：

```bash
javap OrderState.class
```

反汇编出来的东西大致长这样：

```text
Compiled from "OrderState.java"
public final class com.idheima.enumtest.OrderState extends java.lang.Enum<...> {
  public static final ...OrderState 待支付;
  public static final ...OrderState 处理中;
  public static final ...OrderState 已发货;
  public static final ...OrderState 配送中;
  public static final ...OrderState 已送达;
  public static final ...OrderState 已取消;

  public static ...OrderState[] values();
  public static ...OrderState valueOf(java.lang.String);
}
```

你看清楚了：**每一个枚举项的前面都老老实实挂着 `public static final` 三个关键字**，而我们源码里一个都没写。这就是编译器自动加的。

> **结论**：写代码的时候不用手动加，写了反而是冗余；`public static final` 是枚举项在底层真实的样子。

> **易错点**：`javap` 严格说是"反汇编"，把 class 文件里的字节码摊成可读的结构，而不是还原成一份能直接编译的 `.java` 源文件。但要看清修饰符和方法签名，用它足够了。

#### 第一行必须是枚举项

第三个注意点。枚举类的第一行必须是所有枚举项，枚举项之间用逗号隔开，最后以分号结尾。

如果你图省事，把 `name`、`age` 这类属性写在第一行，程序"啪"的一下就报错了：

```java
// 错误示范：属性被写到了第一行
public enum OrderState {
    private String name;      // 报错！
    待支付, 处理中, 已发货
}
```

第一行只能是枚举项。

不过如果枚举项太长，是可以折行的：

```java
public enum OrderState {
    待支付, 处理中, 已发货, 配送中,
    已送达, 已取消;
    // ...
}
```

因为在程序当中，我们认为**分号是这一行的结束**。你只要最后能补上一个分号，折不折行它都认。

#### 构造方法默认 private

第四个注意点。枚举类的构造方法必须是 `private` 修饰的，不让外界创建本类的对象。

这里有个细节在 IDEA 里特别显眼：你写出来的 `private` 是**灰色的**——因为 IDEA 会告诉你，这个 `private` 省略不写也完全没问题，少写一个关键字它不会报错。

也就是说：

> **结论**：枚举类的构造方法默认使用 `private` 修饰，就算咱们不写，虚拟机也会帮我们加上 `private`。

那它带来的是什么效果？就是**在外边你没法自己再 new 它的对象了**：

```java
// 错误示范
OrderState os = new OrderState();   // 报错
```

把鼠标悬停上去，提示写得很直白：枚举类不能创建它的对象。

再看一眼构造函数里我们加的那句 `System.out.println`——所有对象都只能由编译器在类加载时创建，外部完全没有插手的机会，这正是枚举"单例且不可乱造"的根本原因。

#### values 与 valueOf 是编译器送的两个方法

第五个注意点。编译器会给枚举新增两个默认方法，刚才反汇编的时候我们已经见过它们了。

**`values()`**：获取本类所有的枚举项。它默认是 `static` 修饰的，所以可以用类名 `OrderState` 去点，返回值是一个数组。

**`valueOf(String)`**：获取一个指定的枚举项，同样是静态的，参数传一个字符串名字，返回那个指定的枚举项。

这两个方法咱们写代码时一次都没写，但完全不影响使用。下面分别演示一下。

先看 `values`：

```java
OrderState[] arr = OrderState.values();
for (OrderState os : arr) {
    System.out.println(os);
}
```

运行结果：

```text
看看我执行了吗待支付
看看我执行了吗处理中
看看我执行了吗已发货
看看我执行了吗配送中
看看我执行了吗已送达
看看我执行了吗已取消
待支付
处理中
已发货
配送中
已送达
已取消
```

上面那六行还是构造方法里那句打印，**只看下面这六行**：1、2、3、4、5、6 六个枚举项全出现了。

再看 `valueOf`。我要获取第三个枚举项"已发货"：

```java
OrderState os3 = OrderState.valueOf("已发货");
System.out.println(os3);
```

```text
--------------------------------
已发货
```

> **易错点**：`valueOf` 传的是**枚举项的名字**，也就是你在 `enum` 第一行写的那几个字，而不是构造方法括号里存的那个字符串。名字和括号里的描述必须一字不差地对应上，大小写、多一个字少一个字都不行。

要是你传了括号里那个描述字符串，或者随手写了点别的字符串，程序直接就崩了：

```text
Exception in thread "main" java.lang.IllegalArgumentException:
No enum constant com.idheima.enumtest.OrderState.xxx
```

翻译成人话就是"没有这个枚举"。IDEA 右下角有 AI 分析的按钮，点一下它等几秒，AI 会直接告诉你"你获取的方式使用错了，正确写法应该是这样"——给的正是我们上面第一次那种写法。

至此，枚举的五个注意事项就全部过完了。打开你心爱的 IDEA，把这五个小点自己练一遍。

### 继承是什么

坐稳扶好，系上安全带，咱们正式发车。今天要学的是面向对象剩下的内容：继承、多态、抽象类、接口、内部类，第一个就是继承。

说到继承，咱们先说一说面向对象的三大特征：**封装、继承、多态**。

#### 三个特征里的第一个：先回头看一眼封装

封装咱们之前学过。还记得咱们写 JavaBean 的时候吗——那就是封装：把一些零散的数据和一些行为封装成一个整体。

这样带来的好处是，以后面对的就不是一个又一个零散的数据了，而是一个又一个的整体。传数据的时候不需要传一堆零散的字段，只要传这个整体就可以了；方法当中需要什么，通过 get 方法获取出来就行。

当然封装的时候还有一些特殊的操作：

- 为了数据安全性，给每一个成员变量都提供 `private` 关键字，并提供 `get` 和 `set` 方法，避免外界给属性赋一些非法的数据；
- 在这个类下面我们还写了构造方法，方便我们在创建这个整体（也就是创建对象）的时候，把所有已知的数据一次性给它，省得一个一个地 set。

> **定义**：把一些零散的数据和行为变成一个整体，这个就叫封装。

#### 两个类里的重复数据，和现实里的爸爸儿子

接下来是面向对象的第二大特征——继承。

先看一个案例。等我们书写的 JavaBean 类越来越多之后，你会发现它里面其实有很多重复的数据。比如成员变量 `name`、`age`，还有成员方法 `eat()`，在 `Student` 和 `Teacher` 两个类当中是都有的。

那像这种重复的数据，我们该怎么处理呢？总不能在每一个类里面都写一遍吧？两个类写一下还好，那如果我这里有五个类、十个类、一百个类呢，是不是每个都要写一遍？感觉就太麻烦了。

其实是不需要的。**我们可以把这些重复的数据抽取出来，放到一个单独的 `Person` 类当中**；在下面的 `Student` 和 `Teacher` 里面，重复的内容就不需要再写了，只写自己单独的那部分数据。

这个结构长这样：

```text
              ┌──────────────────────────────┐
              │          Person              │  ← 父类（爸爸）
              │  String name                 │
              │  int    age                  │
              │  void   eat()                │
              └──────────────┬───────────────┘
                             │
             ┌───────────────┴───────────────┐
             │                               │
   ┌─────────┴─────────┐           ┌─────────┴─────────┐
   │     Student       │           │     Teacher       │  ← 子类（儿子）
   │  String grade     │           │  String subject   │
   │  void   study()   │           │  void   teach()   │
   └───────────────────┘           └───────────────────┘
```

上面的 `Person` 就是爸爸，下面的 `Student` 和 `Teacher` 就是儿子。这跟现实生活当中是一样的：爸爸有的东西，儿子都可以去用。在代码当中其实也是一样——爸爸中的 `name`、`age` 以及这里的 `eat()`，两个儿子里面就不需要再写一遍了，要用到的时候直接到父亲里面去拿。

> **定义**：继承就是类跟类之间的一种父子关系。有了这种关系之后，我们就可以少写很多重复的代码。

#### extends 关键字与父类子类的多种叫法

在 Java 当中提供了一个关键字 `extends`，用这个关键字可以让一个类和另外一个类建立起继承关系，代码就这么写：

```java
public class Student extends Person {
}
```

这行代码读作：我现在定义了一个 `Student` 类，让它去继承了 `Person` 类。其中前面的 `Student` 就是**子类**，也叫**派生类**；后面的 `Person` 就叫做**父类**，也叫**基类**或者是**超类**。

那为什么会有这么多不同的称呼呢？因为这些东西啊，原版都是老外编写的。比如说 Java 之父 James Gosling 就写了很多 Java 的书籍，不同的人翻译的时候都加上了自己的理解，所以叫起来的名字有点不一样。

一般来讲，我们更多的是叫**子类**和**父类**，因为这种称呼更加清晰。

```text
              ┌──────────────────────────────┐
              │          Person              │
              └──────────────┬───────────────┘
             ┌───────────────┴───────────────┐
   ┌─────────┴─────────┐           ┌─────────┴─────────┐
   │     Student       │           │     Teacher       │
   └───────────────────┘           └───────────────────┘
```

#### 继承带来的两个好处

有了继承关系之后会有什么好处呢？其实一共有两个。

**第一个好处：可以把多个子类中重复的代码抽取到父类当中**，在子类里面我就不需要再写一遍了，从而提高代码的**复用性**。这就是我们前面一直在说的那件事。

**第二个好处：子类可以在父类的基础上增加其他的功能，让子类更加强大。**

假设父类里面有 `eat()`、`sleep()` 这两个方法，那么在子类当中，父类的方法我能直接用，而且我还可以在父类的基础上再去添加额外的——比如说学生有 `study()`、`game()` 这两个新的方法。

所以到这里为止，我们就简单了解了什么是继承。接下来一起做个小练习爽一下。

### 第一次动手：把学生和老师抽到一个父类里

题目的需求是：利用继承去定义下面的 JavaBean 类，并描述老师跟学生。

> 学生里面有姓名、年龄，还有年级，行为呢是吃饭和睡觉；老师呢有三个属性：姓名、年龄，还有 `subject` 学科，以及行为：吃饭和教书。

一看就知道，这两个类里面它有共同的属性，那怎么办？**把它抽取到一个父类当中**。

先写父类 `Person`。这里我们先不忙写 `private`，因为你加上 `private` 之后会涉及到继承当中成员变量的特点，咱们先把最简单的模式写出来：只写共有的属性和共同的行为。

```java
public class Person {
    String name;
    int age;

    public void eat() {
        System.out.println("吃饭");
    }
}
```

父类定义完毕，接下来说定义两个子类。**父子关系一定要通过 `extends` 关键字来构建**，不是说我这边起了个名字，这就叫子、这就叫父，Java 就知道它俩谁是爸爸谁是儿子了——其实就是在后面加上 `extends` 关键字就可以，这句代码读作"我定义了一个 `Student` 类，让它认 `Person` 为爹"。一旦认了爹，我就可以使用父类里面的东西了。

子类里面只写特有的内容，分为两个：特有的属性，和特有的行为。

```java
public class Student extends Person {
    // 特有的属性：年级
    String grade;

    // 特有的行为：学生在学习
    public void study() {
        System.out.println("学生在学习");
    }
}
```

```java
public class Teacher extends Person {
    // 特有的属性：老师教哪个学科
    String subject;

    // 特有的行为：教书
    public void teach() {
        System.out.println("老师在教书");
    }
}
```

最后写测试类。注意咱们一般是不在实体类里写 `main` 方法的，只有在 `main` 方法里面才能创建对象，并进行赋值、调用。

```java
public class Test1 {
    public static void main(String[] args) {
        // 创建学生对象
        Student s = new Student();
        s.name = "小诗诗";
        s.age = 19;          // 小诗诗在我心里面永远是最美的
        s.grade = "一年级";
        System.out.println(s.name + " " + s.age + " " + s.grade);
        s.eat();             // 父类的
        s.study();           // 子类的

        // 创建老师对象
        Teacher t = new Teacher();
        t.name = "阿伟老师";
        t.age = 20;
        t.subject = "计算机"; // 你是什么呀？我教计算机的
        System.out.println(t.name + " " + t.age + " " + t.subject);
        t.eat();
        t.teach();
    }
}
```

运行结果：

```text
小诗诗 19 一年级
吃饭
学生在学习
阿伟老师 20 计算机
吃饭
老师在教书
```

这里有一个细节特别值得说。`Student` 里面我其实只写了一个 `grade`，为什么现在它能直接调用 `name` 和 `age` 呢？因为这两个是从父类里面继承下来的。

> **提示**：在 IDEA 里其实已经有体现了——你看那种**黑色加粗**的成员，是子类里面独有的，比如 `grade`、`study`；而额外其他能调用的、黑色没有加粗的，其实就是从父类当中继承下来的 `age`、`name`、`eat`。加粗与否，是继承关系最直观的提示。

另外注意，反过来是不行的：老师对象 `t` 调用不了 `grade`，因为 `grade` 是学生里面独有的属性。老师能调用的独有属性是 `subject`。

到这里，关于什么是继承以及继承的好处就学完了。这个知识点希望大家掌握四个内容：

- **什么是继承**——它是面向对象的三大特征之一，可以让类跟类之间产生父子关系；
- **父子关系有什么用**——可以把多个子类中重复的代码抽取到父类里面，子类没必要再写一遍，要用到直接去父类里面拿，减少冗余代码，提高复用性；
- **代码怎么写**——掌握 `extends` 关键字，定义一个子类，让它去继承后面的父类；
- **继承之后子类有什么好处**——两个：得到父类的属性和行为直接可用；在父类的基础上新增其他功能，让子类更加强大。

### 什么时候才该用继承

刚才那个小案例代码并不复杂，光凭想象就能把整个结构画出来。但是——**如果继承结构比较复杂，涉及的类比较多，我们该怎么去设计一个继承体系呢？**

先声明一下，我不是安卓党，也不是苹果党，安卓、苹果、鸿蒙三个操作系统哥们我都用过，每一个操作系统都有自己各自的特点，我都很喜欢。现在呢我们只是写一个小案例而已。

来看题目的需求，一共三个设备：

| 类 | 属性 | 行为 |
| --- | --- | --- |
| 安卓 | 品牌、价格 | 打电话、发短信、NFC |
| 苹果 | 品牌、价格 | 打电话、发短信 |
| 笔记本电脑 | 品牌、价格 | coding（编程） |

这个结构该怎么设计？继承就有一点小麻烦了。所以咱们先不忙写代码，先来学习一下：如何正确地设计一个继承结构。

#### 两个必须同时成立的条件

怎么去设计呢？第一个要问自己的问题是：**我什么时候会用到继承？有没有一个标准？**

有，记住这句话：

> **结论**：当类跟类之间**存在相同内容**的时候，注意这是第一个条件——存在相同内容；**而且还要满足第二个条件——子类是父类中的一种**。这个时候我就可以考虑用继承来优化代码。

两条必须同时成立，缺一不可。

#### 三个例子，一个正、一个反、一个更反

有了这两条标准，我们拿三个例子去检验一下。

**例一：`Student` 和 `Teacher` 抽一个父类。**

`Student` 里有姓名和年龄，`Teacher` 里也有姓名和年龄，存在相同内容；父类可以叫 `Person`，注意**父类的名字也是有讲究的，不能随便乱起，父类要能代表所有的子类**。再检验第二条：学生是人中的一种，老师是人的一种——这没毛病。

反过来，如果父类我取名叫 `AAA` 呢？那这就明显不合理了。学生是 `AAA` 的一种？老师是 `AAA` 的一种？`AAA` 到底是什么东西啊？所以这就是不对的。

**例二：项目经理和程序员抽一个父类。**

项目经理 `Manager` 里面有姓名、工资、管理奖金三个属性；程序员 `Coder` 里面只有姓名和工资这两个属性。

父类你能不能叫 `animal`？这是不行的。你说项目经理是动物的一种，程序员是动物的一种——咱哥们儿是人，不是牛马，所以父类叫 `animal` 明显不合适。父类你得叫 `Employee`（员工），项目经理和程序员都是员工的一种，这才是可以的。

但这里有个坑要注意：**如果你把"管理奖金"也放到父类当中，这就不合理了。**

> **易错点**：父类里面的内容代表的是子类的**共性**。一旦把管理奖金写在父类当中，就等于表示项目经理有管理奖金、程序员也有管理奖金，那这不合理啊——管理奖金是项目经理独有的，所以你得把它写在子类当中。

**例三：这个是错误示范，你们一定要答对。**

现在有两个类：程序员 `Coder`，里面有工号 id、姓名、年龄三个属性；手机 `Phone`，里面也有商品编号 id（也就是 id）、手机的名字、手机的价格三个属性。

有的同学想：哎，它俩也有重复的属性啊，那就可以设计一个"商品类" `Goods`，把共同的属性抽取上去。

**这对吗？给大家五秒钟的时间自己思考一下**，你可以把答案打在弹幕里。

……

时间到。这是错误的，你回答对了吗？

虽然说这种写法在语法当中没什么问题，程序不会报错，**但是它是不符合实际情况的**。如果你真的这么写代码了，百分之一万会挨骂。

为什么？因为在设计继承结构的时候，**你不能光看到相同的内容就抽取**，你还得满足后面的这句话——叫做子类是父类中的一种。

`Goods` 翻译过来是商品、东西的意思。你说手机是商品的一种，这没毛病；但程序员他是商品吗？他不是啊，**绝逼不是**。我们程序员是一个活生生、有思想、有品位的人。所以这么设计是不符合逻辑的。

那该怎么办呢？其实很简单——此时你就不要写继承结构了，`Coder` 和 `Phone` 单独写成两个类就可以了。

> **结论**：在实际开发当中，不要想着把所有的类全都塞进同一个继承结构当中，这是不合理的。我们在实际开发中，它会有很多不同的继承结构。

### 画图法设计复杂继承体系

那回到咱们上面那三个设备，怎么设计？咱们现在教一个非常完美的设计方式：**画图法**。

#### 先记两条画图规则

那该怎么画图？在画图之前先跟大家分享两个小规则。

**规则一：画图的时候要从下往上画。** 下面是子类，然后在子类当中抽取共性的内容放到父类里面，所以要从下往上画。

**规则二：画图的时候要学会分类。** 我们要把相同的子类归为一类，不同的把它扔到外面去。

就这两条，够了。

#### 三个设备，三层结构

先打开画图板，把三个类分别画成三个圈：

```text
     ┌─────────────────┐  ┌─────────────────┐  ┌─────────────────┐
     │     安卓         │  │     苹果         │  │   笔记本电脑     │
     │ 品牌 价格        │  │ 品牌 价格        │  │ 品牌 价格        │
     │ 打电话 发短信 NFC│  │ 打电话 发短信     │  │ coding          │
     └─────────────────┘  └─────────────────┘  └─────────────────┘
```

接下来要来看：**这三个子类当中，谁跟谁是一类啊？或者说三个都是同一类？**

很明显，安卓手机跟苹果手机这两个是一类，这两个都是手机；但是右边的这个笔记本电脑，它不是手机。所以此时在分类的时候，你就要把安卓手机跟苹果手机归为一类，然后在它们两个往上去抽取共性。

那这个父类叫做什么？叫做手机 `Phone`。因为安卓手机它是手机的一种，苹果手机也是手机的一种，这个没毛病。把下面子类共有的属性——品牌和价格——复制到父类当中，然后行为打电话、发短信也复制到父类当中。

在子类里面就只要写独有的了。更爽的是，苹果手机里面什么都不用写了，直接全部删掉——它既没有独有的属性，也没有独有的行为。

那这就完事了吗？**还没有。**

因为手机和笔记本电脑里面，它俩还有重复的东西啊——属性里的品牌、价格是重复的。所以此时我要把手机和笔记本电脑这两个再归为一类，把它们两个再往上抽取共性。

那上面这个父类叫做什么？叫手机不对，叫电脑也不对——我们要叫**智能设备** `SmartDevice`。然后把下面共性的内容再往上抽取：属性就是品牌和价格，行为就不用管了，因为每个设备特有的方式不一样，把特有的方式写在子类当中。

最终的继承结构就变成了这个样子：

```text
                    ┌────────────────────────────────┐
                    │         SmartDevice             │
                    │  String brand                   │
                    │  double price                   │
                    │  （没有共有的行为）              │
                    └───────────────┬────────────────┘
                                    │
             ┌──────────────────────┴──────────────────────┐
             │                                             │
  ┌──────────┴──────────┐                        ┌─────────┴─────────┐
  │        Phone        │                        │      Laptop       │
  │  call()             │                        │  coding()         │
  │  sendMessage()      │                        │  （品牌价格继承）   │
  └──────┬───────┬──────┘                        └───────────────────┘
         │       │
  ┌──────┴─┐  ┌──┴────────┐
  │ Android │  │   IOS     │
  │  nfc()  │  │ （空类）  │
  └─────────┘  └───────────┘
```

#### 图省事的那条路，为什么不够完美

有的兄弟想：我能不能不搞这么复杂，我就把这三个类同时往上抽取，最上面的父类就叫智能设备，下面三个类——安卓、苹果、还有笔记本电脑，都是它的子类？

这样写呢，**在语法当中是没问题的**。但是呢，你发现在这两个中间它是不是还是有重复的功能啊——打电话、发短信，在 `Phone` 和 `SmartDevice` 之间重复了一遍。

所以呢这种方式它不够完美，还是用我们刚刚那种方式是最好的。

### 把图画成代码

前面画图是从下往上画，但**写代码的时候要从上往下写**——先写父类，再写子类。

为什么？因为如果你先写这个子类，比如说先写安卓，它要去继承 `Phone`，可是 `Phone` 这个类还没写，你告诉我你继承谁？你没法继承，对吧。

这个顺序记牢：**画图从下往上，写代码从上往下。**

先写最上面的智能设备：

```java
public class SmartDevice {
    String brand;
    double price;
}
```

这个最上面的父类里只写两个属性。为什么没有行为？因为打电话、发短信是在手机这个类里面的，而笔记本里面的 coding 编程是在笔记本里面的，它们都是独有的，没有公有的行为。

接下来写手机 `Phone`，让它去 `extends SmartDevice`，在它里面写共有的行为：

```java
public class Phone extends SmartDevice {
    public void call() {
        System.out.println("利用手机打电话");
    }

    public void sendMessage() {
        System.out.println("利用手机去发短信");
    }
}
```

再往下写安卓和苹果。**安卓是继承手机的，它不是继承那个智能设备的，千万不要写错了哟：**

```java
public class Android extends Phone {
    public void nfc() {
        System.out.println("安卓手机可以使用NFC功能");
    }
}
```

苹果也去继承 `Phone`，但是它里面什么都没有，所以我们就空着不写：

```java
public class IOS extends Phone {
}
```

最后一个笔记本电脑。还是那句话：**千万不要忘了笔记本电脑，它不是继承手机的，它是直接继承上面那个智能设备的**，所以要写 `extends SmartDevice`。它里面的品牌、价格不需要再写了，直接使用父类里面的就行，只要写一个独立的行为：

```java
public class Laptop extends SmartDevice {
    public void coding() {
        System.out.println("正在利用笔记本电脑进行编程");
    }
}
```

五个类全部写完，现在去测试类里创建对象、赋值、调用。

```java
public class Test2 {
    public static void main(String[] args) {
        // 安卓手机：能打电话、发短信，还能用 NFC
        Android a = new Android();
        a.brand = "魅族";
        a.price = 1999;
        System.out.println(a.brand + " " + a.price);
        a.call();
        a.sendMessage();
        a.nfc();

        System.out.println("--------------------------------");

        // 苹果手机：品牌价格从 SmartDevice 继承，电话短信从 Phone 继承
        IOS i = new IOS();
        i.brand = "苹果";
        i.price = 5999;
        System.out.println(i.brand + " " + i.price);
        i.call();
        i.sendMessage();
        // i.nfc();   // 报错！NFC 是安卓独有的功能
        System.out.println("--------------------------------");

        // 笔记本电脑：直接继承 SmartDevice，只能 coding
        Laptop l = new Laptop();
        l.brand = "拯救者";
        l.price = 10000;
        System.out.println(l.brand + " " + l.price);
        l.coding();
    }
}
```

运行结果：

```text
魅族 1999.0
利用手机打电话
利用手机去发短信
安卓手机可以使用NFC功能
--------------------------------
苹果 5999.0
利用手机打电话
利用手机去发短信
--------------------------------
拯救者 10000.0
正在利用笔记本电脑进行编程
```

> **易错点**：`IOS` 对象调不了 `nfc()`，因为 NFC 是安卓里面独有的功能。这个报错跟前面枚举的 `new OrderState()` 是同一类问题——**子类能拿到父类的一切，但兄弟子类之间是隔离的**。三个对象分属三条不同的继承线，各自"能干什么"完全由它在树上挂的位置决定。

好，到这里关于一个复杂的继承结构就全部写完了。回到知识点本身，我们对它做个小结：

- **第一步，用画图法**——打开画图板去画图。一开始先进行分类，把相同的子类归为一类，然后就可以不断地去抽取共性的内容，往上抽。注意画图的时候要从下往上画，先画子类，再去画父类。
- **第二步，编写代码**——先写父类，再写子类。

## 继承的特点，以及继承结构中的成员变量与成员方法
> 对应块：BLK27 | 覆盖分集：P106-P108 | 块标题（分集名）：《第11章-面向对象高级-03-继承的特点》

继承本身这个东西，讲到"特点"其实就一句话说完：**Java 只支持单继承，不支持多继承，但是可以多层继承。** 真正让人晕的从来不是这句话本身，而是它俩后面拖着的一串细节——什么叫单继承，为什么 Java 非要砍掉多继承，多层继承到底层数能有多深，以及这堆类往上捋的时候，那个叫 `Object` 的老祖宗是怎么冒出来的。

再往下，继承结构里面的东西才是重头。成员变量怎么抽取、名字重了在重名的时候怎么找、重名了用 `this` 和 `super` 点名；成员方法怎么抽取、怎么调；最后是方法重写——什么时候该重、怎么重、写错了会报什么错。这三块连起来，就是继承这个知识点剩下的全部内容。

### 继承的特点

#### 只支持单继承，不支持多继承

单继承的意思是，一个子类只能继承一个父类。这个跟现实生活是一样的：一个儿子只能有一个爸爸。

不支持多继承的意思是，一个子类不能同时继承多个父类。这个现实生活也给你答案了：一个儿子不能有两个亲爸，这是不允许的。

那 Java 为什么非要这么设计？当时 Java 之父 James Gosling 设计 Java，是为了改进 C++ 里各种不合理的设计，而 C++ 是允许多继承的——在 C++ 里一个儿子是可以有多个爸爸的。他发现如果 Java 也沿袭这个设计，会有一个很大的问题。

我给你设想一下：现在有两个父类，第一个父类让儿子去**吃饭**，第二个父类让儿子去**吃面条**，子类同时继承了这两个父类。那么我在外面创建子类对象，调用那个 E 的方法，你说它到底是吃饭呀还是吃面条啊？那我当场就懵了呀。

```text
        父类A                 父类B
          │                     │
      void eat(){            void eat(){
        吃饭                    吃面条
      }                       }
          └──────────┬──────────┘
                     │
                     ▼
                 子类（编译报错）
        调用 eat() 时：吃饭？还是吃面条？
```

所以为了避免这么尴尬的问题出现，Java 在设计的时候就把多继承取消了。

#### 但可以多层继承

多层继承是什么意思呢？子类 A 可以继承父类 B，而这里的父类 B 又可以继承它自己的父类 C。这就像我们现实生活中的祖孙三代关系。

```text
        Object（顶级父类：所有类的祖宗）
              ↑
             爷爷 ────── 间接父类
              ↑
             爸爸 ────── 直接父类
              ↑
        ┌─────┴─────┐
      儿子         叔叔 ← 跟儿子没有任何关系
```

刚才那张图，左右两两成对看：在左边这两个类里，儿子是子、爸爸是父；在右边这两个类里，爸爸是子、爷爷是父。

#### 爷爷不是"爷爷"

刚那张图一出来，肯定有同学要问：那孙子跟爷爷之间，这算什么关系啊？

有同学想：这简单啊，爷爷呗。其实这不对。

你想啊，如果 Java 里真的存在"爷爷"这种概念，那岂不是还得有曾祖父、高祖父、天祖父、烈祖父……关系哪有那么复杂。所以在 Java 当中，爷爷、太爷爷、祖爷爷这一整串关系都被**模糊掉了，统称为父类**。

> **定义**：直接继承的那个父类，叫**直接父类**（图里的爸爸）；再往上一层的爷爷、太爷爷那些，叫**间接父类**。爸爸是儿子的直接父类，爷爷是爸爸的直接父类，同时又是孙子的间接父类；爷爷再往上如果还有父类，那对孙子来说也依然是间接父类。

这就是第一个细节：直接父类和间接父类。

#### 万物之上都有一个 Object

顺着这张图再往下想一层：这种继承关系有没有个头？有没有一个最大的祖宗类？

有的。Java 里有一个顶级的父类，叫 `Object`，是 Java 已经提前写好的类。每一个类都是直接或者间接地继承于 `Object` 类，它相当于 Java 里面所有类的祖宗。

那问题来了：我在代码里写 `class A extends B`，A 是子类、B 是父类，这没有任何问题。但如果我压根没写这个继承关系，难道 A 就没有爸爸了吗？

不是的。**A 会默认继承于 `Object` 类。**

这里要注意一个关系：这不是我们自己写上去的，是虚拟机在运行的时候自动帮你加上去的。虚拟机会先查看你这个类有没有爸爸，如果有，那没事，它不会给你加；但如果这个类没有父类，虚拟机就会给它加一个默认的继承关系——继承于 `Object` 类。

也正是因为这个原因，你会发现我们写代码的时候，除了从父类继承下来的属性和行为以外，还能调用 `equals()`、`hashCode()` 这些方法——这些方法其实就是从 `Object` 里面继承下来的。

> **结论**：Java 中所有的类，都是直接或间接继承于 `Object` 的。继承体系最上面的那些类都是默认继承于 `Object`，下面所有的类都是间接继承于 `Object`。

最后把这一节的规矩收个口，在一个继承体系当中，针对任意一个子类而言：它可以使用自己直接父类里面的内容，也可以使用自己间接父类里面的内容；但是它**不能**使用那种类似于"叔叔类"里面的内容。你甭管这两个人长得有多像，在代码当中，这俩类之间是没有任何关系的。

所以关于继承的特点，大家掌握三点就够了：**Java 只能单继承、不能多继承、但可以多层继承；直接继承的父类叫直接父类，间接继承的爷爷太爷爷那些叫间接父类；Java 中所有的类都直接或间接继承于 `Object`。**

### 成员变量：先把共性抽到父类

讲完了继承本身，我们进到继承结构内部看成员。继承结构里的成员不外乎三样：成员变量、成员方法、构造方法。先从成员变量开始。

继承结构下成员变量的**书写规则**只有一条：把多个子类当中相同的属性，抽取到父类当中。这里的"属性"其实就是成员变量。

为什么抽取？想想我们之前写的 `Person`、`Student`、`Teacher` 这套代码——`Student` 和 `Teacher` 两个子类里面是不是都有 `name` 和 `age`？既然两个子类都有，那这两个共性就该往上抽，抽取到父类 `Person` 当中去。抽取完毕，接下来调用的时候它就会遵守**就近原则**。

### 完整版的就近原则

"就近原则"咱哥们不陌生，之前学过，总结而言就是一句话：**谁离我近，我就用谁。** 但之前咱哥们还没学继承，所以那时候只学了就近原则的一部分，是个"阉割版"。现在把继承学完了，再回来看就近原则，才是完整版的。

看这段代码：

```java
class Fu {
    String name = "父";
}

class Zi extends Fu {
    String name = "子";

    public void show() {
        System.out.println(name);
    }
}
```

如果此时我调用这个 `show()` 方法，程序最终的结果是什么呢？

它首先会在方法里面去找，看看有没有局部变量叫 `name`。如果有，就用。如果没有，那就到本类的成员位置去找，看有没有一个变量叫 `name`。如果有，就用。但是现在本类里没有 `name`——注意了，这个时候它**不会报错**，还会继续往上到它的父类里面去找，看有没有成员变量叫 `name`，一级一级往上。

那么如果说在整个继承体系当中都没有变量叫 `name`，在这个时候才会报错。

```text
  show() 里直接写 name
          │
          ▼
  ① 方法里的局部位置找 name   ──有──► 用它，结束
          │ 没有
          ▼
  ② 本类的成员位置找 name     ──有──► 用它，结束
          │ 没有
          ▼
  ③ 父类的成员位置找 name     ──有──► 用它，结束
          │ 没有
          ▼
  ④ 爷爷的成员位置找 name     ──有──► 用它，结束
          │ 没有
          ▼
  整个继承体系都没有 → 报错
```

所以这段代码运行的结果就是 `父`。

### 重名了怎么点名：this 和 super

光知道查找顺序还不够，咱们给它加点料。

我在这个代码当中添加了两部分：在子类的成员位置，我添加了 `name` 赋值为 `"子"`；在方法当中，我添加了一个局部变量 `name` 赋值为 `"子秀"`。那么请问，现在我还是直接去调用 `show()` 方法，程序运行的结果是什么呢？

给它五秒钟时间自己思考一下。

好，时间到，正确答案是**子秀**。

为什么呀？因为此时它会先到方法里面去找，有没有局部变量叫 `name`——有啊，一下子就找到了，所以上面这两个 `name` 呢，它就再也不会找了。最终打印结果就是"子秀"。

```java
class Fu {
    String name = "父";
}

class Zi extends Fu {
    String name = "子";

    public void show() {
        String name = "子秀";          // 局部变量

        System.out.println(name);        // 子秀：先在本方法里找
        System.out.println(this.name);   // 子：跳过局部，从本类成员开始
        System.out.println(super.name);  // 父：跳过局部和本类，从父类开始
    }
}
```

那很多同学会接着想：那如果说在这种重名的情况下，我依然想要去打印"子"、想要去打印"父"，代码该怎么写呢？

想打印"子"其实非常简单，根据之前所学，前面的加上 `this` 就可以了。加上 `this` 之后，它就不会在方法里面去找，而是直接到本类的成员位置去找 `name`，所以说就会打印"子"。

那如果我现在想打印"父"怎么办呢？那就要跟大家介绍一个新的关键字了，叫 `super`，就表示使用父类里面的内容。在 `name` 的前面加上 `super`，此时它就会直接到父类的成员位置去找 `name`，最终打印结果就是"父"。

打开我们心爱的 IDEA 来看一下实际效果。这个代码当中，父里面有一个 `name`，子里面有一个 `name`，方法里面有一个局部变量 `name`，下面三个输出语句跑出来就是：

```text
子秀
子
父
```

跟你刚刚推断的结果完全一样。

> **结论**：重名的时候，三种写法对应三个不同的"查找起点"。

| 写法 | 从哪儿开始找 | 依次会经过 |
| --- | --- | --- |
| `name` | 方法里的局部位置 | 本类成员 → 父类成员 → 爷爷… |
| `this.name` | 本类的成员位置 | 父类成员 → 爷爷… |
| `super.name` | 父类的成员位置 | 爷爷… |

> **易错点**：那有的兄弟会想，如果我还有一个爷爷类，爷爷里面也有一个变量赋值为一，此时我想打印这个爷，有没有办法？是不是 `super.super.name`？
>
> 不用试，程序都不用运行，它就直接报错了。在程序当中，如果我们在子类里面想要往上获取成员变量，在这种重名的情况下，**我们最多只能访问到父类**；而更上面的爷爷类，你是没办法直接去访问的。`super` 只跨一层，没有"套娃"写法。

### 课堂练习：父子同名的 name 与父类独有的 address

看这段代码：父类 `Fu` 里有一个 `name` 赋值为 `"父"`，还有一个 `address` 地址赋值为 `"南京"`；子类 `Zi` 里只有一个 `name` 叫 `"子"`，没有那个 `address`；子里面有一个 `ziShow()` 方法。当我们在外界创建子类对象、去调用 `ziShow()` 的时候，我想要这三个结果——"子"、"子"、"父"。

先看第一个：想输出"子"，代码该怎么写？根据我们刚刚所学，我们有几种书写方式？我们是不是有两种？直接打印 `name` 行不行？行——方法里面又没有局部变量，所以直接写 `name` 是 OK 的。还有第二种写法，在前面加一个 `this.`，这也是 OK 的。

继续往下：想输出"父"，也就是打印父类里面的这个 `name`，代码该怎么写？有几种写法？很简单，在这个地方你只有一种写法。因为此时 `name` 它是有重名的，你直接打印 `name` 是访问不到"父"的，它打印的是这里的"子"。所以如果想打印"父"，前面必须要加一个 `super.` 作为前缀，表示现在我访问的是父类里面的 `name`。

那真正难的是第三个：想输出"南京"，也就是输出这里的 `address`，代码该怎么写？有几种写法？给大家五秒钟时间自己思考。

好，时间到，我们一起来推断。首先我想问大家一个问题：我直接写 `address` 行还是不行？不知道没关系，右键 Run，程序运行完毕，你发现直接打印 `address`，他居然也是可以的。

为什么？因为根据我们刚刚的就近原则，他先在方法里面找，没有 `address`；再到本类的成员位置找，也没有 `address`。那这个时候怎么办？继续往上呗，找父类的成员位置，是不是这个时候就能访问到 `address` 里面的"南京"了呀。

第二种写法是在前面加 `this.`，这也是没有任何问题的。因为这个时候我会先在本类的成员位置找——没有，怎么办？继续往上找呗，在父类里面同样地找到了 `address`。所以前面加上 `this.` 也是 OK 的。

同理还有第三种写法，就是我在前面加 `super`，这也是行的。我不找子类了，直接到父类里面去找 `address`，打印"南京"。

所以这三种写法都可以输出。右键 Run，"南京、南京、南京"，没问题。

```java
class Fu {
    String name = "父";
    String address = "南京";
}

class Zi extends Fu {
    String name = "子";

    public void ziShow() {
        // 要输出"子"：两种写法都打印 子
        System.out.println(name);
        System.out.println(this.name);

        // 要输出"父"：只有一种写法
        System.out.println(super.name);

        // 要输出"南京"：三种写法都可以
        System.out.println(address);
        System.out.println(this.address);
        System.out.println(super.address);
    }
}
```

> **提示**：这里为了方便大家阅读，把三个类写在了同一个文件里。而在真正的企业级开发当中，我们最好还是一个文件里面就写一个类，仿照我们之前的习惯就可以了；现在这么写只是为了省得多个类当中双击切换看的麻烦。

到这儿，关于成员变量的特点就学完了。回到知识点本身做个小结，需要掌握三个问题：

第一个，继承结构当中成员变量的**书写规则**——注意书写规则怎么写，四个字就能理解，就是**抽取共性**。

第二个，继承结构当中成员变量的**访问特点**——也是四个字，**遵守就近原则**，而且是完整版的就近原则：先在方法里面的局部位置找，有就用；没有就到本类的成员位置找；还没有就到父类的成员位置找，一级一级往上；如果整个继承体系当中都没有对应的成员变量，那么这个时候才会报错。

第三个，出现**重名变量**的时候该怎么办？那就要知道上面那三种写法的访问规则了：直接使用一个变量，是从方法里面的局部位置开始一级一级往上找；前面加上 `this` 关键字，是从本类成员位置开始一级一级往上找；如果写的是 `super.name`，那就是从父类的成员位置开始一级一级往上找。

### 成员方法：抽取共性，调用遵守就近原则

接下来我们一起再往下来学习继承当中成员方法的特点。它跟成员变量其实是非常类似的：在书写的时候，也是把多个子类当中共性的方法去抽取到父类当中；在调用的时候，同样也遵守**就近原则**。

先看一个小练习。这段代码里，最上面是一个测试类，创建了子类的对象并去调用 `drink` 方法；下面有一个父类，还有两个子类，子类里面有共性的 `eat`，还有共性的 `drink` 方法。

你觉得这个代码该怎么优化？当多个子类当中有共性内容的时候，我们就可以把共性的内容抽取到父类当中。那么在子类里面就没必要再写了，直接删掉就可以。

```java
class Fu {
    public void eat() {
        System.out.println("吃饭");
    }

    public void drink() {
        System.out.println("喝开水");
    }
}

class Zi1 extends Fu {
    // eat 和 drink 已经抽取到父类，这里原样删掉
}

class Zi2 extends Fu {
    // 同上
}
```

> **结论**：这就是在继承结构当中成员方法我到底该怎么写，跟成员变量一样，无非就是**向上抽取共性**而已。

#### 调用的两种情况

在继承结构当中，成员方法的调用关系有两种情况。

第一种，是我在外界去创建子类的对象并去调用方法，就是现在我们看到的这个。此时他会先去到子类里面去找有没有这个 `drink` 方法；如果子类里面有，它就会调用子类的。但是现在子类里面没有啊，那就再去到父类里面去找——所以最后运行的是父类里面的 `drink`，也就是打印"喝开水"。右键 Run，"喝开水"就有了。

```java
// 测试类
Zi1 z = new Zi1();
z.drink();   // 子类没有 → 去父类找到 → 打印 喝开水
```

第二种，是我在本类当中去调用其他的方法。比如说我现在在子类里面去添加一个方法，叫 `lunch()`，吃午饭。那你说吃午饭我要干嘛呀？我要吃米饭、吃菜，还有喝开水。因为这个逻辑我已经写过了，我没必要再写一遍，所以这个时候就涉及到第二种情况：在本类当中去调用其他的方法。

那调用其他的方法怎么调？跟以前一样，直接写方法名就可以了，直接 `eat()`、直接 `drink()`。那这种写法其实等同于前面加一个 `this`，用 `this` 去调用 `eat` 的方法、用 `this` 去调用 `drink` 的方法，这两种写法是完全等价的。在调用的时候，他会先去看本类里面有没有 `eat`、有没有 `drink`，如果有就看本类的；如果没有，再去到父类里面去找。

那第二种书写方式呢？既然我要调用父类的，我干嘛还要在本类里面再找一遍呢？我直接利用 `super` 到父类里面去拿，这不就完了吗？所以同样的，我们也可以用 `super` 去调用 `eat`、用 `super` 去调用 `drink` 方法，这也是可以的。在这种情况下，他就不会在本类里面去找，直接到父类里面去看。

```java
class Zi1 extends Fu {
    public void lunch() {
        eat();          // 等价于 this.eat()
        drink();        // 等价于 this.drink()

        // 也可以直接点名父类：
        // super.eat();
        // super.drink();
    }
}
```

### 什么是方法的重写

除了上面这两个最基本的，成员方法这里还有一个新知识点——**方法的重写**。

方法重写顾名思义，就是在子类当中，我把父类的方法再写一遍。再写一遍的时候，**方法的声明要跟父类里面保持一致**。这里的方法声明指的就是方法的修饰符、方法的名字，还有方法小括号里面的参数列表，这三样你要跟父类里面完全保持一致。

> **定义**：方法的重写就是——在继承当中，子类出现了和父类当中一模一样的方法声明，此时我们就称子类的这个方法，是重写父类的方法。

那它有什么作用呢？在实际开发当中它的作用非常的大：**如果父类的方法不能满足我子类的要求了在这个时候就一定要用到方法的重写。**

### 练习一：三代手机

我们来看一个小练习。题目需求是这样的：在手机的发展历史当中，第一代手机的功能比较单一，它只能用来打电话，比如说我们在电视当中经常看到的大哥大；那么随着第二代数字移动通信技术的发展，手机的体系越来越小，开始具备短信、彩信的基本功能；到了 21 世纪，主要是 2009 年左右，智能手机开始普及。

按照这个背景，我们要设计三个手机的 Java 类。第一代手机里面只有一个行为，就是打电话；第二代手机里面的行为有两个，一个是打电话，一个是发短信；第三代手机要注意了，打电话升级成了视频通话——在这种情况下，父类里面的功能不能满足我子类的需求了，那么此时在子类当中，我就要把这个方法重写一遍。额外还有发短信、玩游戏。

代码该怎么写呢？打开我们心爱的 IDEA 来写。

首先写第一个类 `FirstGenerationPhone`，第一代手机，它里面有一个功能就是打电话：

```java
public class FirstGenerationPhone {
    public void call() {
        System.out.println("利用手机打电话");
    }
}
```

接下来写第二个类 `SecondGenerationPhone`，第二代手机，让它 `extends FirstGenerationPhone` 继承第一代手机。第二代手机有两个行为，一个是打电话一个是发短信；因为现在我写了继承关系，在第一代手机里面的打电话我就可以直接拿过来用，所以这里没必要写了，我直接写第二个方法 `sendMessage()` 就可以了：

```java
public class SecondGenerationPhone extends FirstGenerationPhone {
    public void sendMessage() {
        System.out.println("利用手机发短信");
    }
}
```

第三个 `ThirdGenerationPhone`，第三代手机，**注意它不是继承第一代，它是继承第二代**：

```java
public class ThirdGenerationPhone extends SecondGenerationPhone {
    @Override
    public void call() {
        System.out.println("开启视频");
        System.out.println("利用手机进行打电话");
    }

    public void playGame() {
        System.out.println("利用手机玩游戏");
    }
}
```

这三个类摆在一起，结构非常清晰——它是爷爷，它是爸爸，它是儿子：

```text
   FirstGenerationPhone          call()
            │
            │  extends
   SecondGenerationPhone         sendMessage()
            │
            │  extends  + 重写 call()
   ThirdGenerationPhone          playGame()
```

如果我现在在第三个类里面对打电话没有进行任何的改动，那么在外界创建第三个的对象并去调用里面的方法，它最终调用的还是第一代手机里面的 `call`，并没有进行升级。那怎么办？此时就要用到方法重写：当父类里面的方法不能满足我现在的需求了，我就要对它进行重写。

重写怎么写呢？需要我 `Ctrl+C`、`Ctrl+V` 把这个方法复制过来吗？告诉大家，**不需要**。我们只要点击空白处，按快捷键 `Alt+Insert`，选择 Override Methods，你要重写父类里面的哪些方法，现在有这么多方法可以重写，那我现在就选择这里的 `call`，一个回车——你看它是不是就自动帮我们重写好了。

```java
    @Override
    public void call() {
        System.out.println("开启视频");
        System.out.println("利用手机进行打电话");
    }
```

那这个 `@Override` 是什么东西呢？它是我们方法重写里面一个关键的东西，叫做**注解**。这个注解跟我们之前学的注释是类似的，它们都是对代码的解释说明。只不过注释是给我们程序员看的，它都是一些文字性的内容；而注解它不是给我们程序员看的，他是**给虚拟机看的**。

虚拟机看到了这里的 `@Override` 之后，它就知道了：你下面这个方法是重写父类的。其实就是做了一个小标记而已。而一旦有了这个标记之后，它就确定了——你方法在重写的时候，上面的这个方法的声明要跟父类里面这个方法的声明要完全保持一致。如果说你不一致，比如说上面我就写 `call`，下面我就要写 `call2`，你发现程序都不用运行，直接就报错了。还有一个就是，如果说我这个地方多加了一个形参，你发现他是不是也报错了呀。

> **结论**：`@Override` 就是给虚拟机看的，让虚拟机帮我们去检查下面重写的这个语法我有没有写对；写对了它就没问题，写错了它就会有红色的波浪线。

方法重写完毕，那接下来我们就要在测试类当中去创建对象并调用里面的方法了。一开始创建第一代手机的对象 `phone1`，用 `phone1` 去调用 `call()`，右键 Run——"利用手机打电话"，这就有了。

继续创建第二代手机的对象 `phone2`，用 `phone2` 去调用父类里面的 `call()` 方法，还有用 `phone2` 去调用第二个类里面的 `sendMessage()` 方法，右键 Run，输出也就有了。当然这些都不是重要的，**最重要的是创建第三代手机的对象** `phone3`，因为在这个类里面有我们重写的 `call` 方法。

```java
// 测试类
FirstGenerationPhone phone1 = new FirstGenerationPhone();
phone1.call();                 // 利用手机打电话（第一代）

SecondGenerationPhone phone2 = new SecondGenerationPhone();
phone2.call();                 // 继承自第一代：利用手机打电话
phone2.sendMessage();          // 第二代新增：利用手机发短信

ThirdGenerationPhone phone3 = new ThirdGenerationPhone();
phone3.call();                 // 重写之后：视频通话
phone3.sendMessage();          // 第三代没改动，继承第二代：利用手机发短信
phone3.playGame();             // 第三代新增：利用手机玩游戏
```

右键 Run，第三代那套输出——视频通话、发短信、玩游戏——全都有了。

这里有个细节要注意：**发短信的方法在第三代手机里面没有任何的改变**，所以我们没必要对它进行重写。它在第三代里面能调到，靠的是继承，不是重写。

所以方法的重写就是这么回事：当父类里面的方法不能满足我子类需求了，那这个时候怎么办？很简单，把这个方法再写一遍，这就行。只不过别忘了在重写方法的上面，我要加一个 `@Override` 的注解，相当于告诉虚拟机，我下面这个方法是重写父类的。

### 练习二：计算商品的价格

第二个关于方法重写的练习，计算商品的价格。

看一下题目的需求：某电商项目售卖智能设备，智能设备包含了三种，分别是手机、笔记本电脑，还有平板。那么要完成以下的三个要求。

第一个，所有的智能设备都有以下的属性：商品的名字 `name`，还有价格 `price`；以及有一个行为，计算当前商品的价格。这里要注意，不是说你这个商品标价 1000 块钱，那我就真的付 1000 块钱的，它有一个计算的折扣：

| `price` 所在区间 | 折扣 | 实际应付 |
| --- | --- | --- |
| 0 ≤ `price` < 1000（含 0，不含 1000） | 不打折 | `price` |
| 1000 < `price` < 5000 | 九折 | `price * 0.9` |
| 5000 ≤ `price` < 10000 | 八折 | `price * 0.8` |
| `price` ≥ 10000 | 七折 | `price * 0.7` |
| 其余（`price` 小于 0） | 价格不对 | `0` |

第二个需求：手机它享受额外的补贴，也就是折上折，在原有的基础上统一再去打九折。还有笔记本电脑、还有平板电脑，没有额外的补贴。

那这个题目该怎么做呢？因为是一个新的练习，所以新建了一个包，把题目需求粘贴过来。首先我们还是要先去写那个继承结构：最下面的是手机、笔记本电脑，还有平板；它里面的共性我要抽到一个叫做智能设备 `SmartDevice` 当中，所以我先去写上面的父类智能设备，再去写下面的三个子类。

先写父类 `SmartDevice`，它里面有两个属性：商品的名字 `String name`，商品的价格 `double price`。更重要的是这里的行为，计算它的价格：

```java
public class SmartDevice {
    String name;
    double price;

    public double payments() {
        if (price >= 0 && price < 1000) {
            return price;
        } else if (price > 1000 && price < 5000) {
            return price * 0.9;
        } else if (price >= 5000 && price < 10000) {
            return price * 0.8;
        } else if (price >= 10000) {
            return price * 0.7;
        } else {
            return 0;
        }
    }
}
```

写完把它 `Ctrl+C`、`Ctrl+V` 粘贴过来之后，其实我们就是对 `price` 来做一个比较判断就可以了。

接下来写三个子类。第一个就是我们现在的重点手机，让它去 `extends SmartDevice` 继承智能设备。手机里面要注意它是享受额外的补贴的，你要在原有的基础上再打九折。什么意思啊？其实很简单，就是你当前父类里面的行为是不符合我当前要求的，那我怎么办？进行方法的重写，我就要把这个方法再写一遍，上面去加一个 `@Override`，这就可以了。

那我要在原有的基础上再打九折，怎么办？有很多同学想，那这简单啊，把父类里这段代码直接复制粘贴过来就行。你看行不行？当然那是 OK 的，只不过呢，你发现了没有，这段代码我在父类里面已经写过一遍了。所以在这种情况下我就可以这么办——这段代码没必要再写，我可以先调用父类里面的方法，先计算出商品的价格，我就可以用 `super` 去调用 `payments` 这个方法，`Ctrl+Alt+V` 自动生成左边，此时得到一个价格；那么这个价格是我现在要支付的钱，然后呢在这个基础上我再去打九折。

```java
public class Phone extends SmartDevice {
    @Override
    public double payments() {
        return super.payments() * 0.9;
    }
}
```

这就是**少写一段代码**的写法。

继续往下，还有第二个子类笔记本电脑。让它去继承 `SmartDevice`。那么在笔记本电脑这个里面呢，它没有额外的补贴，所以此时我们不需要对 `payments()` 这个方法进行重写，直接保持原样，这就可以了。还有平板电脑，叫 `Pad`，去继承 `SmartDevice`，一样的道理，它没有额外的折扣，所以说在这个里面我们也是空着什么都不写。

```java
public class Laptop extends SmartDevice {
}

public class Pad extends SmartDevice {
}
```

回到测试类当中，在这里我们就要来创建三个子类的对象，然后并查看它的计算结果。首先先去创建手机的对象 `Phone p = new Phone()`，然后我要对这个 `p` 来进行赋值——因为在这个里面我没有写构造方法，所以它里面的每一个属性，我要一个一个地点这么进行赋值。手机我可以赋"小米"，然后 `p` 点 `price`，给它赋值 4999。那我真正付的是多少钱呢？用 `p` 去调用 `payments()`，`Ctrl+Alt+V` 自动生成左边，然后呢再把最终的结果打印出来。

右键 Run，程序运行完毕，最终的结果就有了——`4049.19...`。

那为什么是这个数呢？其实呢它调用的就是这里的 `Phone` 的方法：先通过父类得到一个结果，在这个结果的基础当中再去打九折。相当于先打九折再打九折，也就是打了一个 0.81 折，最终的结果就是 4049.19。

只不过呢我们会有一个小疑问：它这个后面怎么有这么长一个后缀呀？别忘了，在计算机当中，小数直接参与计算，它的结果就是有可能是不精确的。那如果说我想四舍五入、想保留小数点后面两位，这个不着急，在我们后面学的 `BigDecimal` 的时候，我们会详细地讲。

继续往下，我还要再来创建笔记本电脑的对象 `Laptop lt = new Laptop()`，给它赋值：`lt.name = "联想"`，然后 `lt.price` 给它赋个 10000 块钱，再用 `lt` 去调用 `payments()`，给它起个名字叫 `payment2`，打印出来。

右键 Run——要注意的是，笔记本电脑它没有额外的补贴，所以此时在计算支付金额的时候，他直接用的是父类里面的逻辑，10000 块钱打七折，最终的结果就是 `7000.0`，没有任何问题。

```java
// 测试类
Phone p = new Phone();
p.name = "小米";
p.price = 4999;
double payment = p.payments();      // 4049.19...（4999 × 0.9 × 0.9）

Laptop lt = new Laptop();
lt.name = "联想";
lt.price = 10000;
double payment2 = lt.payments();    // 7000.0（没有额外补贴，直接用父类逻辑）

Pad pd = new Pad();                 // Pad 没重写，同样直接走父类逻辑
```

> **结论**：方法重写的时候要注意两种情况。如果父类里面的代码我一行都不想用，那么此时只要把子类当中的方法体重新完整地写一遍就可以了；如果父类里面的代码我还想用，我只是在父类的基础上再去加其他的业务逻辑（比如刚刚那个折上折），那么我就可以先通过 `super` 关键字先去调用一下父类里面的方法，得到一个结果，然后呢对这个结果再进行二次操作。

### 重写时的注意事项

方法重写里面有几个小注意事项，这些注意事项不需要兄弟们去背，记是没有用的，咱们能理解、看懂就可以了。当以后代码报错了，我们知道是哪报错、知道怎么改就 OK 了。这些其实都是一些语法层面的东西——你读两遍、读三遍去混个眼熟，那以后不管是百度还是问 AI，你能修改，并且能知道他为什么报错，这就够了。

**第一个，重写的方法，方法的名字还有小括号里面的参数，必须跟父类当中完全保持一致。** 如果说不一样，代码就会直接报错。名字呢指的是方法名：如果说父类里面叫做 `method`，我子类里面叫做 `method2`，你看代码直接报错。还有参数列表：如果说父类里面它是没有参数的，而我子类里面多了一个参数，是不是也报错了？那同理，如果说父类里面是有参数的，我子类里面没写、或者说我子类里面的参数又多了一个，你看是不是也报错了。

这里的第一条还有一个后半句话：**方法体按照实际的需求来进行书写。** 我相信通过刚刚的两个练习，大家都能理解——子类里面你现在要干什么，你就直接写就可以了。如果说在书写的过程当中，你要用到父类里面的方法了，我是不是还可以通过 `super` 关键字来进行调用啊？得到一个结果，在子类当中再进行二次修改就可以了。

**第二个，子类在重写父类方法的时候，访问权限（也就是前面的那个 `public`）子类必须大于等于父类。** 这个咱们不需要死记，了解一下就可以了，知道有这么回事就行。在 Java 当中，权限修饰符一共有四个，最小的是 `private` 的私有——你只能在本类当中访问；最大的是 `public`——你在所有的地方都能够使用。那在 `private` 跟 `public` 中间还有两个，一个呢是空着不写（包权限），还有一个是 `protected`。

```text
public  ＞  protected  ＞  （空着不写）  ＞  private
```

现在咱们先混个眼熟，后面我们会有专门的章节去讲。把父类里面前面的修饰符去改成 `protected`，你看代码没有任何报错；但是如果说父类里面是 `public`，子类里面你写成 `protected`，你发现一下子就报错了。所以在大多数情况下，我们还是把它写成完全一样的就行。

**第三个，子类重写父类方法的时候，返回值类型子类必须小于等于父类。** 返回值类型是什么？其实就是这里的方法返回类型。打个比方，如果说父类当中返回的是一个对象——比如说我们在 test1 这个里面写了一个继承结构，`Person` 是父类，下面有两个子类，一个是 `Student`，一个是 `Teacher`。那么如果说在父类当中，你返回的是一个 `Person`，我们来写 `return new Person()`；现在在子类当中，你必须要小于等于它才行。你返回 `Person`，等于，这是 OK 的；我把它改成 `Student`，你看它也是可以的。但是如果说我子类的返回值类型是 `Object`，`Object` 是大于 `Person` 的（`Person` 继承了 `Object`），那么这个时候代码就直接报错了。当然在实际开发当中，我们一般来讲，返回值类型也是跟父类完全保持一致，这就就可以了。

**第四个（也是最重要的一个），`final` 修饰的类叫最终类，里面所有的方法全都不能被重写，而且 `final` 所修饰的类它不能够被子类继承。** `final` 这个关键字呢我们之前曾经学习过——用 `final` 去修饰一个变量之后，这个变量就叫常量，它的值只能被赋值一次，后面不能再次被修改，你下面强行修改的话代码直接报错。所以 `final` 你就可以把它理解成是"最终"的意思。那现在呢咱哥们就把 `final` 学习完整：`final` 除了可以修饰变量以外，它还可以修饰类，还可以修饰方法。

当 `final` 去修饰一个类的时候，那么要注意就是这个类现在就是最终类，它不能够被继承——也就是说他是最后一代了，后面没有后代了，没有子类了，也没有孙子了。我们来试一试：直接写在 `class` 前面，你发现在这怎么了？是不是就直接报错了？那么既然它是最终类了，你都不能被继承了，那方法还能重写吗？那肯定也不能了呀。

**第五个，`final` 修饰的方法表示这个方法是最终的方法，不能被子类重写。** 这个修饰呢你可以把它写在 `public` 的前面，你也可以把它把它写在 `public` 的后面，位置无所谓，但一般来讲我们把它写在 `public` 的后面。那么现在你看我用 `final` 去修饰了一个方法，这个方法怎么样？直接就报错了。这就说明了 `final` 修饰的最终方法是不能够被重写的。

**第六个，如果父类里面的方法是被 `private` 私有修饰的，或者是被 `static` 静态修饰了，那么这两种方法同样也不能被重写。** 我们也来试一试：父类那里我加一个 `private` 私有，下面子类是不是也报错了？其实是很好理解的——你想，父类里面 `private` 私有修饰的行为，是不是相当于爸爸的一些小秘密呀？爸爸的小秘密，儿子能知道吗？儿子能去干吗？绝逼不可以啊。所以 `private` 修饰的私有方法，也是不能够被子类继承的。父类那里再写一个 `static` 静态的，静态方法在子类当中同样的也是不能够被继承。

好，到这里，关于继承结构当中成员方法的知识点就全部学习完毕了。需要大家掌握的就是这几条：

第一个，在继承结构当中成员方法的书写规则——抽取共性，把多个子类当中共性的行为去抽取到父类当中。

第二个，代码该怎么调——就近原则，先去访问子类，如果子类有我就用子类的，子类没有就到父类里面去找。同时还会涉及到两个关键字：`this` 是先访问子类、再访问父类；而 `super` 是不会访问子类的，直接去访问父类。

第三个，方法的重写。在继承当中子类出现了和父类当中一模一样的方法声明，那么此时我们就称子类的这个方法是重写父类的方法。在重写的时候，记得方法的上面要加 `@Override` 这个注解，用来检验重写的语法是不是正确。什么时候能用到呢？一句话就能说明白：当父类里面的方法不能满足我子类要求了，此时你就需要进行方法的重写。

第四个，重写时候的注意事项——声明跟父类保持一致；不用记什么权限修饰符大于等于、返回值类型小于等于这些，实际开发重写的方法一般来讲都是跟父类完全保持一致的。**但如果父类里面的方法是私有的、是静态的、是最终的，这三种方法你在子类当中是不能重写的。**

### 本讲提到的题目

**题目一：同名变量到底打哪一个**

父类 `Fu` 中有 `name = "父"` 和 `address = "南京"`；子类 `Zi` 中只有 `name = "子"`，没有 `address`；`Zi` 中有 `ziShow()` 方法。从外界创建子类对象并调用 `ziShow()`，要求依次打印出：`子`、`子`、`父`、`南京`。

答案与解析见上文《课堂练习》一节。要点：打印"子"有两种写法（`name`、`this.name`）；打印"父"只有一种写法（`super.name`），因为重名时直接写 `name` 只会拿到子类的；打印"南京"有三种写法（`address`、`this.address`、`super.address`），因为子类里根本没有这个变量，往上一找就在父类里找到了。

**题目二：三代手机**

设计三个手机类——第一代只有打电话；第二代在第一代基础上增加发短信；第三代继承第二代，把打电话升级为视频通话，另外增加玩游戏。

答案：三代之间是 `extends` 链式继承，第三代重写 `call()`（加 `@Override`），`sendMessage()` 不重写（靠继承），`playGame()` 是第三代新增。第三代对象调用 `call()` 得到的是重写后的视频通话输出——父类方法能满足需求时不要重写，只有不能满足时才重写。

**题目三：计算商品的价格**

智能设备有 `name`、`price` 两个属性和一个 `payments()` 行为：0 到 1000 之间（不含 1000）不打折，1000 到 5000 之间打九折，5000 到 1 万之间打八折，超出 1 万打七折。手机在原有基础上统一再打九折（折上折），笔记本电脑和平板没有额外补贴。

答案与解析见上文《练习二》一节。要点：三个子类都 `extends SmartDevice`，只有 `Phone` 重写 `payments()`，且用 `super.payments() * 0.9` 复用父类逻辑；`Laptop`、`Pad` 空着即可。验证结果——"小米" 4999 最终应付约 4049.19（$0.9 \times 0.9 = 0.81$ 折），"联想" 10000 最终应付 7000.0（无补贴，直接走父类七折）。小数结果后面那一长串后缀是浮点数精度问题，保留两位小数的做法会在 `BigDecimal` 里详细讲。

> 对应块：BLK28 | 覆盖分集：P109 | 块标题（分集名）：《第11章-面向对象高级-06-继承中构造方法的特》

在刚刚我们已经把继承当中**成员变量**和**成员方法**的特点学习完了，接下来继续往下来看继承当中**构造方法**的特点。

构造方法这个东西啊，非常简单，没有像之前那么多的弯弯绕绕。只要记住一个最核心的一句话就可以——

> **结论**：父类当中的构造方法不会被子类继承，只能通过 `super` 关键字来调用。

这一句记住，剩下的全是它俩展开出来的故事。`super` 那半句到底怎么用、为什么必须用、什么时候用，咱们一个一个来看。

### 父类的构造方法为什么不能被子类继承

所谓继承，就是父类里面有的，我子类里面也有。

那我们顺着这句话往下推一下：**假如**构造方法是可以被子类继承的，那就相当于子类里面也有了这样两个构造，对吧？

但是要注意，以前我们曾经讲过，**构造方法的名字要跟类名完全保持一致**。

你现在拿眼睛看一看：这俩名字一样吗？完全不一样啊。

所以结论就出来了——父类里面的构造方法，是不能够被子类继承的。

> **易错点**：这不是"Java 不让你继承"，而是名字根本对不上。构造方法必须与类名同名，`Person` 的构造方法就叫 `Person()`，它到了子类里也不可能改名叫 `Student()`，改了就违背构造方法的命名规则了。

### 用 super 去调父类的构造方法

既然不能继承，那就只剩下一条路：通过 `super` 关键字去调用。

真正的子类应该这么写：利用 `super` 关键字去调用父类里面的构造方法。规则非常简单，就看 `super` 后面的小括号里有没有东西：

| 写法 | 小括号里 | 调用的是父类的 |
| --- | --- | --- |
| `super()` | 空的 | 无参构造 |
| `super("张三", 23)` | 有实参 | 带参构造 |

格式知道了，那么这么写**有什么作用**呢？其实跟之前一样：**在创建对象的时候，方便给成员变量进行赋值。**

我们把场景捋一遍。假设我在外界创建了子类对象，并且赋了值——"张三，二十三"：

```java
Student stu = new Student("张三", 23, "一年级");
```

那么这个"张三 23"，相当于是传递给了子类的构造方法。

那么问题来了：假如我在子类的构造里面不去调用父类的构造方法，而是跟之前一样，写：

```java
this.name = name;
this.age = age;
```

你觉得这合理吗？其实这是不合理的。

为什么？因为此时 `name` 和 `age`，我已经作为共有的内容抽取到父类当中了。

> **结论**：属性在哪个类里面，你就要在哪个类里面赋值。

所以此时我们就可以利用 `super` 的小括号，把"张三 二十三"传递给父类的构造方法，让父类的带参构造去给成员变量赋值。

上面的空参构造也是一样的道理，只不过它对成员变量的值不做任何变动，保持默认初始化就可以了。

### 搭一套真实的继承结构

接下来我们利用刚刚所学去写一个小练习。不着急，打开一下我们心爱的 IDEA。

这里我已经新建好了一个包，叫做 `test9`，题目的需求我也粘贴过来了。

写继承结构的时候还是跟之前一样：我们要先去观察多个子类当中，有没有共性的内容。

现在我看到了：在子类里面它有两个共有的属性，分别是姓名跟年龄，所以说要把它们两个写在父类当中；而剩余的年级还有学科，是作为子类特有的属性，分别写在子类里面。

OK，继承结构确定了，接下来开始写代码。

#### 先写父类 Person

书写代码的时候**先写父类**。右键 `new → Java Class`，起个名字就叫 `person`，然后在里面写共有的属性：

```java
public class Person {
    String name;
    int age;
}
```

接下来我要写构造方法，构造方法写两个：一个是空参构造，还有一个带全部参数的构造。这个跟之前是一样的。

`Alt + Insert` → 选择 `Constructor` → 用鼠标点击这里的 `Select none`，或者是按两下 `Tab` 一个回车，空参构造就有了。只不过现在我在这个空参构造里面要去加一句话：

```java
public Person() {
    System.out.println("父类的空参构造执行了");
}
```

OK，继续往下，我再写带参构造。`Alt + Insert` → `Constructor` → `Ctrl + A` 全选 → 一个回车，在这个里面我也加一句话：

```java
public Person(String name, int age) {
    this.name = name;
    this.age = age;
    System.out.println("父类的带参构造执行了");
}
```

把这一段 `Ctrl + C`、`Ctrl + V` 改一下里面的字就好了。`Person` 写完，把它给关掉。

#### 再写子类 Student：带参构造的参数是"父类 + 子类"的全集

继续往下写第一个子类 `Student`，右键 `new → Java Class`，起个名字 `Student`，让它去继承 `Person`。

在子类当中我们要去写它特有的属性。刚刚看到了，它只有一个，就是年级：

```java
public class Student extends Person {
    String grade;
}
```

接下来我要去写构造方法，构造方法写两个。第一个是空参构造，跟之前一样，在里面加一句话：

```java
public Student() {
    System.out.println("子类student的空参构造执行了");
}
```

第二个要注意了，它是带全部参数的构造，只不过要注意这里的"全部参数"指的是**谁**。全部参数只有一个 `grade` 吗？

啊不，你别忘了，刚刚我们还是把两个属性抽取到父类当中的 `name` 跟 `age`，所以这里的带全部参数的构造指的是**父类 + 子类**，现在一共有三个：

```java
public Student(String name, int age, String grade) {
    super(name, age);
    this.grade = grade;
    System.out.println("子类student的带参构造执行了");
}
```

这里面的门道非常清楚：

- 父类中的属性，我们是通过 `super` 的小括号里写上参数的形式，传递给父类的构造方法进行赋值；
- 子类里面独有的属性，是我们自己赋值的，直接写 `this.grade = grade` 就可以了。

> **结论**：父类的属性交给父类赋值，子类独有的我们自己赋值。这才是我们最正确的代码。

#### 第二个子类 Teacher：快捷键弹出的两个框

继续往下写第二个子类 `Teacher`，让它去继承 `Person`。老师里面呢也有一个独立的属性，就是那个学科 `subject`。

因为刚刚我已经手动地写过一遍了，现在跟大家分享快捷键。快捷键跟之前一样，也是 `Alt + Insert`，选择第一个 `Constructor`，只不过现在弹出的界面跟以前有点不太一样，它会弹两个界面。

第一个界面：`Choose super class constructor`。它问你——这是你父类里面的构造方法，你要不要仿照父类里面的构造方法去生成子类的构造啊？我要，所以把这两个方法 `Ctrl + A` 全选，点击 OK。

那么现在它又有第二个弹框：你要不要去选择此类 `Teacher` 里面的 `subject` 这个属性啊？我当然也是要的，所以保持默认选择，点击 OK。

好，现在它就会生成两个构造。生成出来之后，空参构造要加一个处理，就是把这里的参数去删掉。上面的这个就是我们想要的空参构造，下面的这个就是带全部参数的构造。

而且这里的带全部参数，指的还是**父类 + 子类**。其中父类里面的 `name` 跟 `age` 交给父类赋值，子类里面独有的 `subject` 是子类自己进行赋值的——跟 `Student` 一模一样，只是在最后多一句输出语句。

到这里为止，整个的继承结构咱们就全部写完了。

### 创建对象时：先父类，后子类

到测试类当中我们就要来创建对象。先创建第一个 `Student` 的对象。

现在因为我代码写得比较多，`Student` 在多个包里面都有，**千万别选错了**，此时我要用的是 `test9` 里面的这个。

创建对象时参数的那个顺序我忘了怎么办？没关系，我可以用鼠标点在小括号上，按快捷键 `Ctrl + P`，我们心爱的 IDEA 它就有自动提示。它说现在呢有两个构造能让你选择：第一个是 `No parameters`，没有参数的构造；第二个是有三个参数的构造，分别是 `name`、`age` 还有 `grade`。

那我就选择第二个吧：

```java
Student stu = new Student("张三", 23, "一年级");
System.out.println(stu.name + " " + stu.age + " " + stu.grade);
```

右键 Run，当当当当——程序运行完毕。它执行了三个语句：父类的带参构造执行了、子类student的带参构造执行了，然后打印了学生的名字年龄还有他的年级。

它为什么是这个顺序呢？我们一起来分析一下。

我现在创建学生对象，是通过带参构造创建的，所以此时他会去调用 `Student` 里面的这段代码。但是呢，在这一段的**第一行**，我是不是先写了一个 `super` 啊？它去调用了父类的构造。

所以此时他就会先到父类当中去，把 `name`、`age` 进行赋值，所以"父类的带参构造执行了"这句话先执行；然后呢再去执行子类里面的 `this.grade = grade`，再去打印"子类student的带参构造执行了"。是这么一个逻辑。

```text
new Student("张三", 23, "一年级")
        |
        v
  +-------------------------------------+
  | 1. 进入 Student 的带参构造          |
  |    第一行 super("张三", 23);        |
  +-------------------------------------+
        |
        v
  +-------------------------------------+
  | 2. Person 的带参构造执行            |
  |    this.name = "张三";              |
  |    this.age  = 23;                  |
  |    打印：父类的带参构造执行了       |
  +-------------------------------------+
        |
        v
  +-------------------------------------+
  | 3. 回到 Student 的下一行            |
  |    this.grade = "一年级";           |
  |    打印：子类student的带参构造执行了|
  +-------------------------------------+
```

这张图读起来就一句话：`new` 出来的瞬间，先往父类跑一趟把父类的字段填好，再回到子类把子类自己的字段填好，子类构造方法体里剩下的代码这时才开始跑。

> **结论**：在创建对象的时候，他先去使用父类的构造方法，再使用子类的构造方法。

### 三个必须记住的小细节

知识点讲完了，我们对它做一个小扩展：来说一说在继承结构当中构造方法的小细节，它一共呢有三个。

#### 第一行默认就藏着 super()

第一个小细节就是：子类的构造方法第一行，它有一个默认的 `super()`，默认去访问父类的无参构造。那如果我们没有书写，JVM 虚拟机也会自动加上。

OK，那么这个呢是默认。真的是这样吗？我们来试一下。

看这个地方，我现在 `Student` 的空参构造，在这个地方我没有写那个 `super()` 小括号吧。现在我在测试类当中创建对象，我就用那个无参的，看看它的执行结果到底是什么：

```java
Student stu = new Student();
```

右键 Run。它有两个输出语句：第一个"父类的空参构造执行了"，第二个"子类student的空参构造执行了"。

为什么是这样的呢？因为现在我在小括号里面什么都没写，所以说它调用的是 `Student` 里面的无参构造。刚刚我们说了，如果我们没有写那个 `super()`，那么虚拟机在第一行也会加一个默认的 `super()`，这个是虚拟机自动加的，目的就是为了访问父类的无参构造，所以说这句话它就会执行。

#### 想调父类的带参构造，这行代码绝不能省

第二个小细节：如果我想要访问父类的带参构造，那么 `super` 的小括号里有参数，这段代码我必须手动地写上，不能省略。

这个呢就好比是我们刚刚这一段代码。如果说现在把第 16 行这行代码给注释掉，那么此时我再来运行代码，把这个注释上面的给放开，右键 Run，你来看父类里面的哪个构造执行了？是不是空参构造呀？

所以想要访问父类的带参构造，这句代码你**千万不能省**。

#### 新 JDK 破了规矩，我们还是守老规矩

第三个就是在创建对象的时候，是先执行父类的构造方法，再执行子类的构造方法。

这个很简单，因为构造方法的第一行，他直接就调用的父类的构造方法。先去调用父类的，再执行子类的，这就 OK 了。

只不过呢在这里跟兄弟们去多说一句：在老版本当中，这里的 `super()` 你必须要写在构造方法的第一行，它是严格按照先执行父类的构造方法、再执行子类的构造方法这种方式来执行的。

但是呢在现在最新的 JDK 版本当中，`super` 你可以写在下面了，你看它也没有报错，而且呢在运行的时候，它也可以先执行子类、再执行父类了。

只不过这种方式跟我们之前写的代码有很大的出入，所以说呢现在我们还是遵守以前的习惯，把 `super()` 严格还是放在构造方法的第一行，这样就可以了。

> **结论**：子类里面不能够继承父类的构造方法，但可以通过 `super` 关键字进行调用；子类构造方法的第一行有一个默认的 `super()` 去访问父类的无参构造，不写的话虚拟机也会自动帮你加上；如果你不想访问无参构造、要访问有参构造，那么这一段代码就不能省了，需要自己手动地写上；`super()` 必须写在构造方法的第一行，先执行父类的构造方法，再执行子类的构造——只不过在最新的 JDK 版本当中可以打破这个规则，但我们一般不会这么干，还是会遵守以前的书写规范。

### this 与 super 到底怎么分工

到目前为止，咱哥们已经把继承当中成员的特点全部学习完毕了。在书写代码的过程中，我们曾经大量使用到了 `this` 还有 `super`，所以说接下来我们把这两个关键字来做一个汇总。

先来看 `this`。`this` 我们很熟悉。在**内存的角度**来讲，它表示当前方法调用者的内存地址——谁来调用当前的方法，`this` 就表示它的地址值。

那么在**代码的角度**呢，它可以区分局部变量和成员变量。所以说通过 `this` 在代码当中，我可以去调用本类的成员，比如说成员变量，比如说成员方法，还有构造方法。

而 `super` 呢，就表示我是调用父类中的内容。

用一张图去汇总一下：

```text
   ┌───────────────────────┐           ┌───────────────────────┐
   │   this 指向本类       │           │   super 指向父类      │
   ├───────────────────────┤           ├───────────────────────┤
   │ this.name    成员变量 │           │ super.name   成员变量 │
   │ this.show()  成员方法 │           │ super.show() 成员方法 │
   │ this(...)    构造方法 │           │ super(...)   构造方法 │
   └───────────────────────┘           └───────────────────────┘
```

在这张图当中，我们用 `this` 去调用成员变量、成员方法，以及用 `super` 去调用成员变量、成员方法，还有用 `super` 去调用父类的构造方法，这五个我们都很熟悉了。

唯一一个有点陌生的就是 `this()`——它表示调用本类的其他构造。那这是什么意思呢？它又有什么样的应用场景呢？接下来我们来做一个小练习。

### 让对象天生带默认值：this() 登场

看题目的需求：按照下面的需求去书写一个 `Student`，它里面呢有两个属性，分别是 `name` 跟 `age`。

下面还有一个需求，就是当我们在学校里面不认识某一个同学的时候，你怎么称呼他？有同学说我称呼他儿子、兄弟——你都不认识他，这么称呼你不怕打起来啊，对吧？所以一般来讲我们都会称呼对方"同学"。

所以说现在我就认为：学生默认的名字就是"同学"，默认的年龄就是 18 岁。

打开 IDEA，这里新建好了一个包 `test10`，题目的需求也粘贴过来了。其实很简单，我们只要写一个 `Student` 类就可以了，它里面有两个属性，一个是 `name`，还有一个是 `age`。

按照以前所写，我们就可以写一个空参的构造，以及带全部参数的构造。然后右键把它挪到右边的包里，在测试类当中我们就可以来创建学生的对象：

```java
Student stu = new Student();
System.out.println(stu.name + " " + stu.age);
```

右键 Run，发现它的默认值呢就是 `null` 和 0。

那么现在在题目当中我说了，我不想默认值叫 null 和 0，我想默认是"同学"、18 岁。那这个怎么做呢？此时有两种写法。

#### 写法一：直接在成员位置给默认值

第一种写法呢，就是我可以在成员位置直接给数据进行赋值：

```java
public class Student {
    String name = "同学";
    int age = 18;

    public Student() {
    }

    public Student(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

外界在创建对象的时候，此时默认 `name` 就是"同学"，`age` 就是 18。右键 Run，"同学 18"是不是就已经有了。

那么如果说我在这儿手动地进行赋值的话，那么此时手动赋值的"张三 23"就会把默认的值给覆盖，右键一运行，它的结果就是张三跟 23。

#### 写法二：空参构造里用 this(...)

除此之外额外还有第二种写法，就是现在我们要学习的 `this()`——它表示调用本类的其他构造方法。

比如说在本类当中，我们就可以在空参构造里面去写上 `this("同学", 18);`，把默认的值"同学"还有这里的 18 传递过来：

```java
public class Student {
    String name;
    int age;

    public Student() {
        this("同学", 18);
    }

    public Student(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

上面的成员赋值就可以直接删掉不写了。现在当我调用空参构造创建对象的时候，他看到 `this` 了，此时呢就会去调用下面的带参构造，把"同学"传递给 `name`，18 传递给 `age`，下面呢就可以对成员变量进行赋值。右键 Run，"同学 18"是不是就有了。

> **结论**：以后当我们想要一个对象有默认值的时候，就可以用 `this()` 这种写法。

| | 写法一：成员位置给默认值 | 写法二：空参构造里 `this(...)` |
| --- | --- | --- |
| 默认值写在哪 | 成员变量的声明处 | 空参构造的第一行 |
| 手动赋值能否覆盖默认值 | 能 | 能 |
| 多个构造时要注意 | 无影响 | 不能互相调用，必须留一个去调父类 |

### this() 的三个小细节

只不过在使用的时候，它里面有一个非常重要非常重要的小细节，兄弟们一定要认真看。

#### 不能互相调用，必须给父类留个出口

第一个小细节：就是说如果说在此类当中有多个构造方法的时候，咱们**不能**利用 `this()` 进行互相调用，一定要预留一个去调用父类的构造方法。

这是什么意思呢？比如说看右边，在右边呢此时我就有两个构造方法。现在我空参的构造是调有参的，那有参的我在这个地方呢再去写一个 `this()`，去掉空参的那一个——那你发现代码是不是就直接报错了呀？

你钓我，我钓你，那什么时候是个头啊。

所以必须要预留其中一个，在它的第一行有一个隐藏的 `super()` 去调用父类的构造，这才是可以的。因为你要想，如果说现在 `Student` 呢它还有一个父类 `Person`，父类里面有一些共有的属性，如果呢在这儿你全部都是 `this` 互相调、自己没有一个调父类的话，那父类里面的属性我怎么赋值啊？他也没法赋值啊，对吧？

> **易错点**：如果子类当中有多个构造的时候，不能用 `this()` 进行互相调用，一定要预留一个去调用父类的构造方法。

#### 有 this 就不能有 super

第二个小细节：如果构造方法当中写上了 `this()` 去调用其它的构造，那么此时你就不能再写 `super()` 了，而且虚拟机也不会自动地给你去添加那个 `super()`。

我们可以来试一试：在这个地方呢我可以再去加一个 `super()`，你发现程序都不用运行，是不是就直接报错了呀？

所以这两个它只能存在一个：**有 `this` 就不能有 `super`，有 `super` 就不能有 `this`。**

#### 新版本不再限定写在第一行

第三个小细节：在老版本当中，`this()` 调用本类的其他构造，你只能写在构造方法的第一行。但是呢在新版本当中去掉了这一限制，只不过呢我们为了跟以前的代码去统一起来，一般来讲呢还是会把这个代码去写在构造方法的第一行。

我们可以来试一试：在这个下面呢我可以去打印一句话，叫做"student无参构造被执行了"。那么在以前的版本当中，代码只能这么写；但是现在新版本里面呢，`this` 可以写在最下面，我们同样的可以右键 Run，你来看一看，程序运行完毕，是不是也没报错呀？

只不过呢这种写法基本上没人用。我们一般来讲，还是把 `this()` 写在构造方法的第一行。

至此，关于继承结构当中的 `this` 还有 `super` 关键字，我们就已经全部学习完毕了。

#### 题目二：给不认识的同学一个默认称呼

**题干**：请书写一个 `Student`，它有两个属性 `name` 和 `age`。当我们在学校里不认识某一个同学的时候，我们一般都会称呼对方"同学"，所以学生的默认名字就是"同学"，默认年龄就是 18 岁。

**解析**：默认值只可能在两个位置产生——要么在成员变量的声明处直接给初值（写法一），要么在空参构造里用 `this(...)` 把默认值转交给带参构造（写法二）。两种写法都允许后续手动赋值把默认值覆盖掉。

**答案**：

```java
// 写法一：在成员位置给默认值
public class Student {
    String name = "同学";
    int age = 18;

    public Student() {
    }

    public Student(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

```java
// 写法二：空参构造里用 this(...) 调用本类其他构造
public class Student {
    String name;
    int age;

    public Student() {
        this("同学", 18);
    }

    public Student(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

### 能调用，不等于能继承

在往下扒之前，有一个点必须先掰扯清楚：**子类能调用的，不等于子类继承下来了**。

什么叫继承？所谓继承就是父类有的，子类也有。但"调用"那完全是另一回事。子类里面没有的东西，它可以拿来用父类里面的东西，这叫调用，不叫继承。

这个就好比现实生活当中：爸爸的钱你可以用，但你不能说"我把爸爸的钱复制一份放到子类里面"——爸爸有你也有，这不对。所以这叫子类能调用，但不是真正的继承。

> **结论**：很多课程拿"钱"去举例继承，其实是非常不合理的。真正合适的案例应该是这样的：假如我们是武学世家，爸爸会武功，那么儿子是真的能把武功继承下来的，爸爸那儿有一份，儿子也有一份。左边是子类能调用，右边才是子类能继承。

那在 Java 当中，子类真正能继承父类的哪些东西？

### 先把结论摆在桌子上

| 父类里的东西 | 能不能被子类继承 | 子类能不能直接调用 |
| --- | --- | --- |
| 构造方法 | 不能 | 不能继承，但可以用 `super` 关键字调用 |
| 成员变量 | 能，哪怕用 `private` 私有修饰的也能 | `private` 的不能直接调用，得走 `getXxx` / `setXxx` |
| 虚方法（普通成员方法） | 能 | 能 |
| `final` 修饰的最终方法 | 不能 | 能 |
| `static` 修饰的静态方法 | 不能 | 能 |
| `private` 修饰的私有方法 | 不能 | 不能 |

构造方法这一条最简单，也完全没有任何争议：它不能被子类继承，但是可以用 `super` 关键字去调用。

成员变量就要复杂一点了——成员变量可以被子类继承，哪怕你这个成员变量是用 `private` 私有修饰的，它也是可以被子类继承的，只不过私有的成员变量你没法直接调用，想用就得用 `get` 和 `set` 方法。

成员方法更复杂，分四种情况：虚方法可以被继承；`final` 修饰的最终方法不能被继承，但可以被调用；`static` 修饰的静态方法不能被继承，同样也可以被子类直接调用；最后 `private` 修饰的私有方法，既不能被继承，也不能被子类调用。

> **易错点**：看到这么多你是不是感觉一脸懵，我好像只能理解最后一句话。别急，跟着我的节奏一个一个来。先画图，再讲底层原理。

### 对象在内存里被一分为二

我们先看一段最简单的继承结构：

```java
class Person {
    String name;
    int    h;
}

class Student extends Person {
    String grade;          // 子类独有的属性
}

public class Test {
    public static void main(String[] args) {
        Student stu = new Student();
        System.out.println(stu);                                  // 打印出来是内存地址
        stu.name = "小丹丹";
        stu.h = 19;
        stu.grade = "2年级";
        System.out.println(stu.name + stu.h + "岁" + stu.grade);
    }
}
```

父类里有两个成员变量 `name` 和 `h`；子类 `Student` 继承了父类，另外有一个自己独有的属性 `grade`；测试类里创建子类对象、赋值、打印。就这么点东西，我们把它摊到内存里看看。

这段代码用到了栈、堆、方法区。程序刚开始运行的时候，会把测试类 `Test` 的字节码文件先加载到内存当中，然后执行 `main` 方法，此时 `main` 方法被加载进栈，开始执行里面的第一行代码。

现在要注意了：这里用到了 `Student` 类，按照之前所学的，我们要把 `Student` 的字节码文件加载到内存当中。但是它一加载就发现，`Student` 还有一个父类 `Person`，所以加载的顺序是**先加载父类，再加载子类**。这个跟之前不一样了，之前没有继承这层关系，现在多了一个加载顺序的问题。

加载顺序在方法区里看得很清楚：

```text
方法区 Method Area（字节码文件的家）

  Test.class      <-- 测试类，最先加载，main 进栈开始执行
        |
        v
  Person.class    <-- 发现 Student 有父类，先加载父类
        |
        v
  Student.class   <-- 最后才轮到子类
```

接下来创建对象的过程跟之前就一样了。

```text
栈 Stack                          堆 Heap
+---------------------------+    +------------------------------+
| main                      |    |  对象 @ 0X0011               |
|                           |    |                              |
|   Student stu;   <---- 等号左边：在栈里声明变量             |
|                           |    |                              |
|   stu = 0X0011;  <---- 等号右边：new 在堆里开空间             |
|                           |    |   内存地址就是 0X0011         |
+---------------------------+    +------------------------------+
```

等号左边，其实就是在栈里面声明了一个变量，变量名叫 `stu`，数据类型是 `Student`，意味着这个变量以后只能存储 `Student` 这个对象的内存地址。

等号右边有 `new` 关键字，看到 `new` 我就知道，它会在堆里面去开辟一个空间，这个空间就是我们平时所说的对象。假设它的内存地址是 `0X0011`，这个对象还会记录下面字节码文件里成员方法的内存地址。这些跟之前都一样。

**不一样的是**，此时它会把对象里面一分为二：左边去记录从父类继承下来的 `name` 和 `h`，右边去记录子类独有的属性 `grade`，然后分别进行默认初始化。

```text
+------------------------------------------+
| 对象头：哈希信息、锁信息，先不看           |
+------------------------------------------+
| 类型指针 -> Student.class 的地址          |
+------------------------------------------+
| 父类继承下来的   | 子类独有的             |
|------------------|-----------------------|
| name = null      | grade = null          |
| h    = 0         |                       |
+------------------------------------------+
```

左半边是父类的部分，右半边是子类的部分，默认初始化就是引用类型给 `null`、基本类型给 `0`。

最后执行中间的等号赋值运算符，其实就是把右边对象的内存地址复制给左边的变量 `stu`。

所以跟之前不一样的点就两个：**第一，加载字节码文件的顺序不一样**，之前创建 `Student` 就只加载 `Student`，现在有继承了，它先加载父类再加载子类；**第二，对象内部一分为二**，左边存从父类继承下来的属性，右边存子类独有的属性。

接下来是赋值，这里头还有一条规则非常关键。

给对象里的 `name`、`h` 赋值的时候，规则是**先看子类，再看父类**。它会先去你的子类里面找有没有 `name` 和 `h`，如果有，就给子类里的赋值，父类里的就不管了；但是现在子类里面没有 `name` 和 `h`，所以这个时候才会给父类里面继承下来的 `name` 和 `h` 赋值——小丹丹，19 岁。

然后再赋值 `grade`，跟刚刚一样还是先看子类，发现子类里确实有一个独有的属性 `grade`，就直接给它赋值 2 年级。所以最后程序打印出来的就是：小丹丹，19 岁，2 年级。

> **结论**：通过这张内存图你会发现，父类里面的属性在子类里面是真真正正继承下来的，而不是简简单单的调用。

### 继承来的是一把带锁的保险柜

但是——注意啊——哪怕父类里面的属性是用 `private` 私有来修饰的，`Student` 也是可以把它继承下来的。只不过此时你就不能直接用 `stu.name` 去访问了，得通过 `get` 或者 `set` 方法来调用。

这个就好比什么？就好比你从父类里面继承下来的，是一个带锁的保险柜。你能把它搬回家，但你不能直接用里面的东西；如果你实在想要用，怎么办？用钥匙。而这个钥匙，就是我们之前所看到的 `get` 和 `set` 方法。

> **结论**：关于成员变量的最终结论就是——父类里面的成员变量是可以被子类继承的，哪怕是私有的也能够继承，只不过私有的你不能够直接调用。

### 用内存分析工具扒开对象看

第二行分为两截，后面那一段表示的就是 `Student` 这个字节码文件的内存地址，你可以把它理解成这个对象的类型，一会儿我们就是通过它去方法区里查字节码文件信息的。

再往下就是成员变量了。你看，父类里的 `a`、`b`，我在子类里有没有继承下来？有。`b` 有没有继承下来？也有。

至此，成员变量的结论就被工具实打实地验证了。

### 虚方法：不带那三个修饰符的普通方法

接下来我们一起来看继承结构当中成员方法的情况。先研究第一个问题：什么是虚方法？

虚方法不难，其实就是普通的成员方法——非 `final`、非 `static`、非 `private` 所修饰的方法就是虚方法。比如说我们之前经常写的 `eat`、`sleep`，这些都是虚方法。简单吧？

> **提示**：所以判断一个方法是不是虚方法，就看它前面有没有那三个修饰符，一个都没有，它才是虚方法。

### Object 里到底有几个虚方法

那我们来个课堂提问。在 Java 当中有一个顶级的父类 `Object` 类，所有的类都是直接或者间接继承于 `Object`  类的。那么请问，在 `Object` 这个类当中，一共有几个虚方法呢？

打开 IDEA，`Ctrl + N` 输入 `Object`，回车，`Object` 所有的代码全罗列出来了。但你千万不要从头拉到尾，代码太长了，拉不到头的。再来一个快捷键 `Ctrl + F12`，所有的方法全都罗列出来了。第一个 `Object()` 小括号，它是一个构造方法，这个我们不管，我们是从第二个方法开始数起的。

你先自己数一数，数完心里有个数。

好，正确答案：一共有五个虚方法。我们一个一个来数。

| 方法 | 前面有没有 `private` / `static` / `final` | 算不算虚方法 |
| --- | --- | --- |
| `clone()` | 都没有 | 是，第一个 |
| `equals()` | 都没有 | 是，第二个 |
| `finalize()` | 都没有 | 是，第三个 |
| `hashCode()` | 都没有 | 是，第四个 |
| `toString()` | 都没有 | 是，第五个 |
| `getClass()` | 有 `final` | 不是，是最终方法 |
| `notify()` / `notifyAll()` | 都有 `final` | 不是 |
| `wait()`（三个重载） | 都有 `final` | 不是 |

### 虚方法表：一层一层往下传的表

弄清楚了虚方法是什么，我们来看一张表。

在一个继承结构当中，假设是 A 继承 B、B 继承 C。先看最顶级的父类 C：它会把自己类里所有虚方法的内存地址找到，把这些地址汇总到一张表当中，这张表我们也叫做**虚方法表**。

在继承的时候呢，会把这张虚方法表交给它的子类；子类在这张表的基础上，再添加自己的虚方法。那同理，A 在继承 B 的时候，也会拿到 B 的虚方法表，在 B 的基础上再添加自己的虚方法。

```text
+------------------+----------------------------------+
| Object           | 虚方法 5 个                      |
+------------------+----------------------------------+
| Fu（父类）       | 虚方法 6 个（5 + 父秀一）        |
+------------------+----------------------------------+
| Zi（子类）       | 虚方法 7 个（6 + 子秀一）        |
+------------------+----------------------------------+
```

这就是整张表往下传的路径：`Object` 先把自己那 5 个方法的地址装进表里，交给 `Fu`；`Fu` 在 5 的基础上加上自己的 `fuShow1`，变成 6，再交给 `Zi`；`Zi` 再加上自己的 `ziShow1`，变成 7。

那么现在，如果我们在测试类当中去创建 `A` 的对象，并调用里面的 `show` 方法，此时会到虚方法表里面去找 `show` 方法对应的内存地址 `0X0011`，然后再把这个 `show` 方法加载到栈里面运行。这就是它查找跟调用的关系。

### 重写的本质，是改表里那个地址

额外还有一个点：如果我现在在 A 类里面重写了 `show` 方法，要注意，**方法重写的本质其实就是替换虚方法表里面的内存地址**。所以重写完 `show` 方法之后，虚方法表里它的内存地址就变成新的了，假设是 `0X0055`，那以后我调用 `show` 方法，调用的就是新的 `0X0055` 这个 `show` 方法。

> **提示**：所以重写不会让虚方法表变长。签名相同，重写只是把那个槽位上的地址换掉，表的长度一动不动。

### 一个子类对象调三个方法，三种命运

接下来我们来看实际的内存。这里准备了两段代码：父类里有 `public` 修饰的 `fuShow1` 和 `private` 修饰的 `fuShow2`；子类里有自己的 `ziShow1`；然后创建子类对象 `zi`，分别用这个子类对象去调三个方法。

```java
class Fu {
    public  void fuShow1() { System.out.println("public父秀一"); }
    private void fuShow2() { System.out.println("父秀二"); }
}

class Zi extends Fu {
    public void ziShow1() { System.out.println("public子秀"); }
}

public class Test {
    public static void main(String[] args) {
        Zi zi = new Zi();
        zi.ziShow1();
        zi.fuShow1();
        zi.fuShow2();
    }
}
```

这段代码用到了栈、堆、方法区。程序刚开始运行的时候，把测试类的字节码文件加载到内存，再执行 `main` 方法，`main` 进栈，开始执行第一行代码——创建子类对象。

这时候会用到 `Zi` 这个类。字节码文件里会有所有的成员变量、还有所有的成员方法，但现在我们关心的是方法，所以先把成员变量先行忽略。那么加载的时候呢，它发现了子类是有爸爸的，是有一个父类的，怎么办？它此时会先加载父类，再加载子类。而父类呢也有默认继承的 `Object`，所以完整、最正确的加载顺序是：**先加载 `Object`，然后再加载父类，最后再去加载子类**。

```text
Object  ->  Fu（父类）  ->  Zi（子类）
```

这是一个完整的加载过程。

每一个类里面都有自己的虚方法表。`Object` 这个类里面我们刚数过了，一共有五个虚方法，所以 `Object` 类的虚方法表里记录的就是这五个方法的内存地址。在继承的时候，它把这张表交给父类，父类在这张表的基础上又添加了自己的虚方法——你来看父类里有几个虚方法？`fuShow1` 是不是虚方法？`fuShow2` 是不是？不是，因为它前面有 `private` 进行修饰。所以在父类的虚方法表里面一共有六个方法。

继续往下，现在又有一个子类去继承父类了，所以又把父类的虚方法表交给子类，子类呢在它的基础上继续增加自己的虚方法。所以最终子类的虚方法表里面，一共有七个方法。

> **提示**：兄弟，你发现没有，在加载字节码文件的时候，虚拟机做的事情哇，哦好多呀。

这些都是加载字节码文件的时候干的事。接下来是创建对象的过程，这个我们很熟悉：等号左边在栈里面声明了一个变量 `zi`，用来记录对象的内存地址；等号右边因为有 `new` 关键字了，所以在堆里面开辟了一个空间，假设地址是 `0X0011`，这个就是我们平时所说的对象，同时会记录下面成员方法的地址；然后通过中间的等号赋值运算符，把对象的内存地址赋值给 `zi`。所以打印 `zi` 的时候，你会发现它其实就是对象的内存地址。

现在关键点来了。此时我用 `zi` 去调用 `ziShow1`，要注意：`ziShow1` 是通过 `zi` 去调用的，而这个 `zi` 就是这边的对象，这个对象是不是子类类型的呀？那当然是。所以他就会去找**子类**里面的虚方法表，找到对应的方法加载进内存，执行里面的代码，打印 `public子秀`。方法运行完毕，出栈。

继续往下，再用 `zi` 去调用 `fuShow1`，其实也是一样，找到子类的虚方法表，那么因为 `fuShow1` 这个方法在虚方法表里面是真实存在的，所以也能加载进栈执行里面的代码，打印 `public父秀一`。方法执行完毕，出栈。

最后还有一个，我用 `zi` 去调用 `fuShow2`，你会发现这个时候调用失败了。

为什么调用失败呢？因为这个方法它是用 `private` 私有修饰的，在子类的虚方法表里面是没有的。虚方法表里面没有的方法，在这个时候他就会一级一级往上去找。在找的过程当中要注意：**私有的方法它不是虚方法，它不在父类的虚方法表里面**，但是在父类这个类里面它还是真实存在的。那么现在找到了 `fuShow2` 之后，他发现是私有的，有权限的限制，子类无法直接调用，所以此时调用失败。

> **易错点**：在真实的 Java 里，`zi.fuShow2()` 这一行在**编译期**就直接报错了，根本轮不到运行时。上面那段是按虚方法表的思路帮你把"为什么调不到"讲透：表里没有它，你就得往上找；找到了，权限又不允许。理解了这层机制，你以后看到"子类访问父类私有方法失败"，就不用再背了。

### 表里的数字：7、6、5 和那个 null

打开 IDEA 再验一次。代码跟上面一样，父类里 `fuShow1` 是 `public`、`fuShow2` 是 `private`，子类里有 `ziShow1`，另外我还重写了一下父类里的 `fuShow1`。

那它的父类呢？展开它上面的 `super_class`，在父类的虚方法表里找 `v_table_length`，是不是就是 **6**？跟我们刚刚推断的一模一样。

它是 `null`。所以从内存分析工具的角度，我们又印证了：在 Java 当中，最顶级的父类就是 `Object`，它上面就没有其他父类了。

### final 与 static：查找发生在编译期

回到资料，接下来我们还要研究 `final`、`static`、`private` 这几种方法到底是什么样的。

先看 `final`。`final` 修饰的最终方法，它是不能够被子类继承的，但是可以被子类进行调用。它的调用关系呢，是有两个阶段的。

第一个阶段是编译器，也就是把 java 文件变成 class 文件的时候。在这个时候他会一级一级往上，子找父、父找爷爷，去遍历整个继承链，确定我最终要调用的方法在哪。那如果确定是在 A 类里面，此时就会**记录这个方法的内存地址**。注意，是编译的时候就记录这个方法的内存地址。

第二个阶段是运行：那么在运行的时候就会直接运行。

这种方式呢，虽然降低了编译的速度，但是我程序运行的速度就可以得到保证了——程序在运行的时候就不需要一级一级往上了，这个查找的过程是发生在编译期的。

那 `static` 其实也是一样的。如果说我现在没有用类名直接调用，我是用对象去调用这里的静态方法，那么在编译的时候，他也会一级一级往上去遍历整个的继承链，要确定最终调用的静态方法是在 A 类里面的。那这个时候注意了，他会把"对象调用方法"**直接修改成类名调用**，然后在运行的时候就可以直接运行了。

> **结论**：所以以后我们做静态方法调用的时候，是不是还是直接写成 `类名.方法名`？是这样的。因为如果你写成对象去调用的话，它会额外地做很多很多的事情，编译的时间会受到影响。

### Java 为什么这么设计：空间换时间

学习完了这些东西之后，我心里面会有一个疑问：那你说 Java 它为什么这么设计呢？

其实啊，还是因为效率问题。虚方法是我们平时在开发当中使用最多的方法，那如果说我们在调用虚方法的时候，每次也要一级一级地往上找，那这太麻烦了，太影响性能了。所以说呢，Java 就提前把经常用到的虚方法放到一个表当中，就是虚方法表。在用到的时候，我直接到表里面去找，这就可以了，这样的效率呢会得到一定的提升。

而这种思想，也是我们编程里面为了提高效率最常见的思想，叫做**空间换时间**。

我现在是浪费了内存空间，但是我提高了程序的运行效率啊。空间你浪费就浪费无所谓，现在的内存空间非常的大，16G、32G，你多用几 KB 无所谓，洒洒水啦。但是多浪费了这几 KB 的空间，我程序运行的效率会得到显著的提升，这个是非常重要的。

这个其实也是我们中国人的思想：两者相害取其轻，两者相权取其利。

好，到目前为止，关于子类真正能继承父类当中的内容，我们已经全部学习完毕了。这些内容非常地底层、比较难，如果你们感觉我没听懂，其实可以二刷三刷，把自己的学习心得记下来互相讨论。当然，你也可以直接记住我们最后展示的那个最终结论。

### 本讲提到的题目

**第一题：父子各有一个 `name`，输出的到底是什么**

题目：父类里面只有一个属性 `name`；子类继承了父类，子类里面也有一个 `name`；子类里有一个 `show` 方法，先打印自己的 `name`，再打印父类里面的 `name`。测试类中创建子类对象，然后给 `name` 赋值 `"AAA"`。直接调用 `show` 方法，程序运行的结果是什么？

```java
class Fu {
    String name;
}

class Zi extends Fu {
    String name;                       // 子类又自己声明了一个同名的 name

    public void show() {
        System.out.println(name);          // 自己的 name
        System.out.println(super.name);     // 父类里的 name
    }
}

public class Test {
    public static void main(String[] args) {
        Zi zi = new Zi();
        zi.name = "AAA";
        zi.show();
    }
}
```

**答案**：

```text
AAA
null
```

**解析**：依据在"对象在内存里被一分为二"那一节讲过的赋值规则——先看子类，再看父类。`zi` 的类型是 `Zi`，而 `Zi` 自己声明了一个同名的 `name`，所以 `zi.name = "AAA"` 落到的是子类的那个 `name`，父类的 `name` 压根没被碰过，它保持默认初始化的 `null`。于是打印自己的 `name` 是 `AAA`，打印 `super.name` 就是 `null`。

反过来说，如果子类没有声明这个同名的 `name`，那一行赋值就会落到父类上，父子两个 `name` 拿到的都是 `"AAA"`。**成员变量在子类里同名，就是一次遮蔽（也叫隐藏）**，遮蔽和重写的区别，也正是这一章后面要展开的内容。

**第二题：`Object` 类里一共有几个虚方法**

题目：Java 中顶级的父类 `Object` 类，一共有几个虚方法？

**答案**：一共 **5 个**，分别是 `clone()`、`equals()`、`finalize()`、`hashCode()`、`toString()`。而 `getClass()`、`notify()`、`notifyAll()` 以及三个重载的 `wait()` 前面都有 `final`，所以它们是最终方法，不算虚方法。

**解析**：判定标准就是"前面有没有 `private` / `static` / `final`"。在 IDEA 里 `Ctrl + N` 搜 `Object`，再用 `Ctrl + F12` 把所有方法列出来逐个看修饰符即可。
