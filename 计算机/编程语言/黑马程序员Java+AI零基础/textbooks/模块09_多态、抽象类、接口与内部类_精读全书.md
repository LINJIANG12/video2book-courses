## 手写一套带继承结构的标准 JavaBean：从画图到七个类落地
> 对应块：BLK29 | 覆盖分集：P110-P111 | 块标题（分集名）：《第11章-面向对象高级-07-带有继承结构的标准》

### 这道练习的分量

到目前为止，继承结构当中最基本的知识点我们都已经学完了。接下来这一节不是学新东西，而是把刚刚学的东西综合运用一下：写一个带有继承结构的标准 JavaBean，里面要包含私有化成员变量、get/set 方法、构造方法，以及其他的成员方法。

先把这句话放在这儿：**这个练习写完，以后写所有练习都照着这个案例的样式来写。** 所以它非常的重要，请大家务必自己独立地练一遍。

看一下题目的需求。现在有四个类，分别是本科学生、硕士研究生、专业课老师、通识课老师，每一个类里面都有自己的属性和行为。另外还有一个额外的需求：过了一段时间之后，硕士研究生的住宿条件升级，他要在豪华版的学生公寓里睡觉。那么这个继承结构该怎么写？

### 分类：先问两条硬标准

这一题跟之前写过的那些小练习不一样。之前无非就是两个类、三个类，我们靠脑子就能想象出来；现在整个结构比较复杂，就最好别再靠脑子想怎么办了。还是那句老话：**先画图，再写代码**，思路会清晰很多。

画图的第一步是分类。怎么分？有人说这简单啊，学生跟学生分为一类，老师跟老师分为一类，这不就完了吗？

不一定。我能不能按照学科分？我能不能按照专业来分？都是可以的。所以分类的时候要抓住两个特性：

> **定义**：分类的两条硬标准——一是事物之间是不是同一类；二是同一类事物当中有没有共性的内容。

第一条好理解，你不能把学生跟手机分为一类吧，这不对。第二条才是关键：如果两个类当中它没有共性的内容，我怎么往上抽取成父类？没法抽了呀。

回到这一题。学生这一边，本科学生里面有姓名、年龄、年级，硕士研究生也有姓名、年龄、年级，行为也一样，都是吃饭、睡觉、学习——它是有共性内容的。**所以在这一题当中，我们就是把学生跟学生分为一类，老师跟老师分为一类。**

### 抽取：三层继承体系怎么长出来

#### 第一步，学生归学生，老师归老师

分完类之后，就不断往上抽取共性的内容。

学生往上一抽，抽成一个类，就叫 `Student`。它里面的共性属性是姓名、年龄、年级，直接写到父类当中；子类里面这些属性没必要再写一遍，直接删掉就行了。行为上的吃饭、睡觉、学习同样抽到父类。

只不过要注意：**本科学生学习的内容跟硕士研究生学习的内容是不一样的**，所以 `study()` 这个方法在两个子类当中都要重写。第一个继承体系就初步形成了。

老师这一边也一样。专业课老师教的是跟你就业相关的一些东西，通识课老师相当于教语文、数学这些东西。专业课老师有姓名、年龄、学科，通识课老师也有姓名、年龄、学科——这里我少打了一个学科，我给它补上去。重复的内容重复的不少，姓名、年龄、学科放到父类，父类的名字就叫 `Teacher`。行为上吃饭、睡觉、教书也放到父类，**只不过专业课老师和通识课老师教的内容不一样，所以 `teach()` 同样要重写。**

#### 第二步，学生和老师都是人，再往上抽一层

你觉这就完了吗？还没完。再看这两个继承体系之间有没有共性：`Student` 里面有姓名、年龄，有吃饭、睡觉；`Teacher` 里是不是也有？有。那就继续往上抽，抽成一个叫 `Person` 的类——因为学生和老师都是人嘛，抽成 `Person` 没有任何问题。

于是姓名、年龄上移到 `Person`，吃饭、睡觉也上移到 `Person`。此刻 `Student` 独有的属性就只剩年级、独有的行为就只剩学习；`Teacher` 独有的属性是学科、独有的行为是教书。到这一步，整个继承体系才算画完。

```text
Person                     姓名 name、年龄 age
 ├─ eat()  吃饭
 ├─ sleep()  睡觉
 │
 ├─ Student                 年级 grade
 │   ├─ study()  学习（被子类重写）
 │   ├─ BachelorStudent      无独有属性，重写 study()
 │   └─ MasterStudent        无独有属性，重写 study()、sleep()
 │
 └─ Teacher                 学科 subject
     ├─ teach()  教书（被子类重写）
     ├─ MajorTeacher         无独有属性，重写 teach()
     └─ GeneralTeacher       无独有属性，重写 teach()
```

七个类，一层套一层，全部落到纸上之后你才有底。

### 重写了，为什么还要往父类抽

画到 Student 的时候，很多同学会有个小疑问：**既然 `study()` 一定要重写，那我为什么还要把它抽到父类里？我不抽，当作特有的方法写在两个子类当中，这不也行吗？**

你想得很对，在这个练习当中确实是可以的。但是我们得考虑代码的通用性：如果我现在还有第三个学生、第四个学生、第五个学生，它没有什么特有的东西，那我是不是就可以直接去使用父类里面 `study()` 的方法了呀？

所以结论很清楚：

> **结论**：该抽取的还是要往上抽取。抽取的理由不是"子类现在用得上"，而是"以后所有的子类都用得上"。

### 标准 JavaBean 缺一不可的四件套

画完图就打开 IDEA 落地。写代码的时候有一个顺序一定要记牢：**从上往下写，先写父类，再写子类。**

一个标准的 JavaBean 到底由什么组成？我直接给你列全：

> **定义**：私有化成员变量、get/set 方法、构造方法、其他成员方法——这四部分缺一不可。构造方法一般写两个：空参构造和带全部参数的构造。

Person 里有两个属性、两个行为，就照着这四件套往下填：私有化 `name`、`age`；两个构造方法；针对每一个私有化的成员变量都提供对应的 get 和 set；最后还有 eat()、sleep() 两个行为。IDEA 里这些都不用手写，`Alt + Insert` 一路点下去就有了——空参构造选 Constructor 里的 `0 - none`，或者连按两下 Tab 再回车；带全部参数的构造选第一个 Constructor，`Ctrl + A` 全选回车；get/set 选 Getter and Setter，全选回车。

```java
public class Person {
    private String name;
    private int age;

    public Person() {
    }

    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public int getAge() {
        return age;
    }

    public void setAge(int age) {
        this.age = age;
    }

    public void eat() {
        System.out.println("吃饭");
    }

    public void sleep() {
        System.out.println("睡觉");
    }
}
```

写完 Person 接着写中间的 `Student` 和 `Teacher`，同样 `Alt + Insert` → Constructor。第一个弹框会问你父类里面有两个构造，要不要仿照父类的构造来生成子类的构造方法——**必须的**，`Ctrl + A` 全选点下去；第二个弹框会问你子类里面独有的 `grade` 要不要加到那两个构造里面——那当然要，默认选中直接点。

生成之后还要动一刀：把带全部参数的那个改成空参的，这样才是标准的两个构造。

### Student：独有的只有 grade 和 study

在 `Student` 里我只写独有的东西：私有化的 `grade`，以及独有的行为 `study()`。构造方法必须是"父类的加上自己的"，也就是 `super(name, age)` 再接 `this.grade = grade`，这样才叫带全部参数。

```java
public class Student extends Person {
    private String grade;

    public Student() {
    }

    public Student(String name, int age, String grade) {
        super(name, age);
        this.grade = grade;
    }

    public String getGrade() {
        return grade;
    }

    public void setGrade(String grade) {
        this.grade = grade;
    }

    public void study() {
        System.out.println("学生正在学习");
    }
}
```

讲到这儿我给大家出个题，五秒钟时间自己思考：**我现在有三个属性，你觉得我要写几个 get/set？是写两个、四个还是六个？**

答案是**两个**。你想，`name` 和 `age` 的那四个 get/set 方法，需要我自己写吗？不需要，父类里面已经写完了，子类里面没必要再写一遍，直接拿过来用就好了。所以这两个是针对于此类独有的 `grade` 的。你看 IDEA 默认生成的也只有一个属性，就是这个道理。

`Teacher` 跟它是一模一样的套路：独有的属性换成 `subject`，独有的行为换成 `teach()`，构造里 `super(name, age)` 接 `this.subject = subject`，get/set 只生成 `subject` 的那一对。

```java
public class Teacher extends Person {
    private String subject;

    public Teacher() {
    }

    public Teacher(String name, int age, String subject) {
        super(name, age);
        this.subject = subject;
    }

    public String getSubject() {
        return subject;
    }

    public void setSubject(String subject) {
        this.subject = subject;
    }

    public void teach() {
        System.out.println("老师正在教书");
    }
}
```

> **易错点**：同名的 `Person`、`Student` 在别的包里也有一大堆，新写子类时千万别继承错了，选的一定是当前这个包里的那个。

### 四个叶子类：没有独有属性，也就没有 get/set

#### 本科学生和硕士研究生

本科学生起个名字叫 `BachelorStudent`，让它继承 `Student`。说实话我不太愿意给本科的兄弟用这个单词，`bachelor` 这个单词还有一个意思叫单身汉——咱哥们这么帅，凭什么是单身狗，你说对吧？但没办法，英文当中他就是这样的，所以还是用它，这个词就是学士学位。

`BachelorStudent` 里面**没有独立的属性**，所以私有化成员变量我们就不写；因为没有独有的成员变量，get/set 也不用写；直接补两个构造方法，再重写 `study()` 就行。

这里有个关键点容易搞错：

> **易错点**：叶子类的"带全部参数的构造方法"，要把间接父类 `Person` 的属性也带上——间接父类 + 直接父类 + 自己，全部包含进来，这才叫带全部参数。

`Alt + Insert` → Constructor，`Ctrl + A` 全选回车，IDEA 会自动把 `super(name, age, grade)` 串好。接着 `Alt + Insert` 选第三个 Override Methods，勾选 `study()`，回车。父类里那句"学生正在学习"我现在一个都不想用，把这段代码删掉，直接打印一句话。

```java
public class BachelorStudent extends Student {

    public BachelorStudent() {
    }

    public BachelorStudent(String name, int age, String grade) {
        super(name, age, grade);
    }

    @Override
    public void study() {
        System.out.println("本科的同学正在攻读本科的内容");
    }
}
```

`MasterStudent` 继承 `Student`，一模一样：没有独立属性，补两个构造，重写 `study()`，打印换成"硕士研究生的同学正在攻读硕士的内容"。刚才那段代码直接 `Ctrl + C`、`Ctrl + V` 粘过来，改一句话就行。

#### 专业课老师和通识课老师

专业课老师叫 `MajorTeacher`，继承 `Teacher`；同样没有独立属性，补两个构造，然后 `Alt + Insert` → Override Methods 重写 `Teacher` 里的 `teach()`，打印"专业课老师正在教授专业课的知识"。

通识课老师叫 `GeneralTeacher`，也继承 `Teacher`，同样补构造、重写 `teach()`，打印"通识课老师正在教授通识课的知识"。

到这里整个继承体系全部写完。写完你会觉得——好麻烦呀。一共写了 1、2、3、4、5、6、7，一共七个类。没错的，正是因为这个继承体系相对来讲比较复杂，**所以一定一定不要通过脑子去想，一定要先画图再写代码，这样会更稳妥。**

| 类 | 继承自 | 独有属性 | 独有方法 |
| --- | --- | --- | --- |
| `Person` | — | `name`、`age` | `eat()`、`sleep()` |
| `Student` | `Person` | `grade` | `study()` |
| `Teacher` | `Person` | `subject` | `teach()` |
| `BachelorStudent` | `Student` | 无 | 重写 `study()` |
| `MasterStudent` | `Student` | 无 | 重写 `study()`、`sleep()` |
| `MajorTeacher` | `Teacher` | 无 | 重写 `teach()` |
| `GeneralTeacher` | `Teacher` | 无 | 重写 `teach()` |

### 追加需求：硕士生的豪华版学生公寓

题目下面还说了一句话：过了一段时间，硕士研究生住宿条件升级，他在豪华版的学生公寓睡觉。这该怎么实现？

说白了就是**父类里面的那个 `sleep()` 方法已经不能满足现在子类的需求了**。父类里那个 `sleep()` 只是打印一个"睡觉"，表示我是在普通宿舍里面睡觉的——我现在住宿条件升级了，那怎么办？重写一下就可以了。

`Alt + Insert` 选第三个 Override Methods，或者你直接手写 `sleep()` 也可以，IDEA 会自动帮你生成方法签名。

```java
    @Override
    public void sleep() {
        System.out.println("硕士研究生正在豪华版学生公寓睡觉");
    }
```

到这里，整个代码就全部写完了。

### 跑一遍：小诗诗，19 岁，大一新生

现在创建对象，调用里面的方法。我们先创建本科同学的对象，起个名字叫 `bs`，后面的小括号当中传递对应的数据：一个名字，一个年龄，还有一个年级。名字呢，哥们也可以叫做小诗诗——她在我心里面永远是最美丽的；19 岁，年级大一新生。当然大一新生一般来讲都是 18 岁，19 岁就已经大二了，对吧。

然后在下面就可以调用了：`bs.getName()` 把名字取出来，逗号空格，`bs.getAge()`，逗号空格，`bs.getGrade()`。然后再用 `bs` 去调用里面的一些行为——有父类里面的 `eat()`、父类里面的 `sleep()`，以及 `study()`。

```java
public class StudentTest {
    public static void main(String[] args) {
        BachelorStudent bs = new BachelorStudent("小诗诗", 19, "大一新生");

        System.out.println(bs.getName() + " " + bs.getAge() + " " + bs.getGrade());

        bs.eat();
        bs.sleep();
        bs.study();
    }
}
```

右键 Run，程序运行完毕，输出就是：名字、年龄、年级，然后吃饭、睡觉，最后一句"本科的同学正在攻读本科的内容"。这就对了。其他几个对象的创建跟现在一模一样，我就不多重复了，大家可以自己练一下。

到这里，关于带有继承结构的标准 JavaBean 我们就全部写完了。书写的时候一定要切记，**私有化成员变量、get/set、构造方法、其他成员方法，这四样缺一不可。**

### 本讲提到的题目

#### 题干

现在有四个类：本科学生、硕士研究生、专业课老师、通识课老师。每一个类里面都有自己的属性和行为。另外还有一个额外需求：过了一段时间之后，硕士研究生的住宿条件升级，他要在豪华版的学生公寓睡觉。那么这个继承结构该怎么写？

#### 解析

1. **先画图，别用脑子想**。四个类、七个类的规模，靠想象一定会乱，先在纸上把结构画出来。
2. **分类抓两条标准**：是不是同一类（不能把学生跟手机分为一类）；同一类当中有没有共性内容（没有共性就抽不成父类）。本题学生一类、老师一类，因为共性摆在那儿。
3. **由下往上分两层抽取**：学生这一边抽出 `Student`，老师这一边抽出 `Teacher`；再看两个体系之间的共性，抽出 `Person`。
4. **该重写的方法一定重写**：`study()` 和 `teach()` 在叶子类里各写各的；但方法照样要留在父类里，为的是通用性。
5. **写代码从上往下**：先 `Person`，再 `Student`、`Teacher`，最后四个叶子类；每个类都按私有化成员变量 → 两个构造 → get/set → 其他成员方法这四步走。
6. **带全部参数的构造方法要带全**：叶子类要把间接父类、直接父类和自己的属性全部包含进来，用 `super(...)` 一层层往上带。
7. **最后补上重写 `sleep()` 的追加需求**。

#### 答案

结构如下，代码见上文各节，两个叶子老师类补齐如下：

```text
Person                     姓名 name、年龄 age
 ├─ eat()  吃饭
 ├─ sleep()  睡觉
 │
 ├─ Student                 年级 grade
 │   ├─ study()  学习（被子类重写）
 │   ├─ BachelorStudent      重写 study()
 │   └─ MasterStudent        重写 study()、sleep()
 │
 └─ Teacher                 学科 subject
     ├─ teach()  教书（被子类重写）
     ├─ MajorTeacher         重写 teach()
     └─ GeneralTeacher       重写 teach()
```

```java
public class MajorTeacher extends Teacher {

    public MajorTeacher() {
    }

    public MajorTeacher(String name, int age, String subject) {
        super(name, age, subject);
    }

    @Override
    public void teach() {
        System.out.println("专业课老师正在教授专业课的知识");
    }
}
```

```java
public class GeneralTeacher extends Teacher {

    public GeneralTeacher() {
    }

    public GeneralTeacher(String name, int age, String subject) {
        super(name, age, subject);
    }

    @Override
    public void teach() {
        System.out.println("通识课老师正在教授通识课的知识");
    }
}
```

```java
public class MasterStudent extends Student {

    public MasterStudent() {
    }

    public MasterStudent(String name, int age, String grade) {
        super(name, age, grade);
    }

    @Override
    public void study() {
        System.out.println("硕士研究生的同学正在攻读硕士的内容");
    }

    @Override
    public void sleep() {
        System.out.println("硕士研究生正在豪华版学生公寓睡觉");
    }
}
```

## 权限修饰符与多态：访问的边界，调用的规则
> 对应块：BLK31 | 覆盖分集：P113-P115 | 块标题（分集名）：《第11章-面向对象高级-10-Java中的权限修》

继承那一讲收尾的时候，我们说过一条规矩：**子类重写父类方法的时候，访问权限必须大于等于父类**。

当时就有人问了——这里的"访问权限"，到底是个什么东西？

今天这个疑问正好一并解决。权限修饰符是什么、多态又是什么、多态下调用成员为什么有那两条奇奇怪怪的规则、以及怎么把多态的弊端补上，这四件事是一条线上的东西，一次性讲透。

---

### 权限修饰符控制的到底是什么

> **定义**：Java 中的权限修饰符就是 Java 的关键字，作用是控制一个成员被访问的范围。它可以修饰成员变量、成员方法、构造方法等等。

Java 里权限修饰符一共有四种，按作用范围从小到大排列：

| 修饰符 | 名字 | 作用范围 |
| --- | --- | --- |
| `private` | 私有 | 只能在本类当中访问，其他地方一律无法使用 |
| 不写 | 缺省（默认） | 本类当中可以，本包中其他类里面也可以，其他包里面不行 |
| `protected` | 受保护的 | 除了本类和本包当中，在其他包里面的子类也可以使用 |
| `public` | 公共的 | 所有的地方都可以使用 |

> **结论**：`private` < 不写 < `protected` < `public`。范围是从小到大一级一级放开的。

第二种"空着不写"，在有的课程里也叫**缺省**或者**默认**。这个我们其实一直在用——之前定义一个 `name`，前面什么都没写，用的就是它。

而在实际开发当中，我们一般只会用到最小的 `private` 和最大的 `public` 就够了，中间那两个简单了解一下就行。

> **提示**：为什么中间那两个很少用？因为 `private` 和 `public` 已经覆盖了绝大多数场景的诉求。真遇到"子类要用、父类又不想完全公开"的中间地带，再回头调 `protected` 也不迟。

#### 用四个类把范围测一遍

光背定义没用，我们直接写代码验证。设计这么几个类：

```text
aaa 包
├── Person                     父类，被观察的对象
├── Student extends Person     本包的子类
└── Test01                     本包的测试类

bbb 包
├── Teacher extends Person     不同包的子类
└── Test                       不同包的无关类（与 Person 没有任何继承关系）
```

这四个类摆开，关系立刻就清楚了：`Person` 是最上面的父类；`Student` 和 `Teacher` 都继承了它，区别只在于一个在同包、一个在别的包；`Test` 跟 `Person` 八竿子打不着，是彻底无关的类。

> **易错点**：`Student` 是"本包中的其他类"，无论它是不是子类，本包的其他类访问权限的逻辑是完全一样的。所以我这里只准备了一个本包子类，你就算在本包再写一个无关的 `Test`，测试结论也一模一样，没必要重复造。

被观察的 `Person` 上面，就一个成员变量和一个成员方法：

```java
package aaa;

public class Person {
    String name;          // 被观察的成员变量

    void test() {         // 被观察的成员方法
        System.out.println("test");
    }
}
```

```java
package aaa;

// 本包的子类
public class Student extends Person {
    public void show() {
        System.out.println(name);   // 访问父类的成员变量
        test();                     // 访问父类的成员方法
    }
}
```

```java
package bbb;

// 不同包的子类
public class Teacher extends Person {
    public void show() {
        System.out.println(name);
        test();
    }
}
```

```java
package bbb;

// 不同包的无关类
public class Test {
    public void show() {
        System.out.println(name);   // 编译报错
        test();                     // 编译报错
    }
}
```

现在唯一的变量就是 `name` 和 `test` 前面那个修饰符，我们一路改一路看。

**第一步，全部改成 `private`。**

本类里面用，不报错。本包的其他类里用——`Student` 明明继承了 `Person`，去打印 `name`、去调 `test()`，直接报错。不同包里面用，同样报错。

结论很清楚：`private` 一修饰，谁都别想用，只能本类自己用。

**第二步，把修饰符直接删掉，变成缺省。**

本类的 `Student` 一下就"唰"地变好了，不报错了。但下面 `bbb` 包里的两个类还是在报错。

结论：缺省范围只能到本包。这也正好解释了我们以前写的那些 `Test` 类，为什么总是和被测试的类放在同一个包里——

```java
package aaa;

// 和 Person 同包，所以这里可以直接访问 name、调用 test()
public class Test01 {
    public static void main(String[] args) {
        Person p = new Person();
        p.name = "张三";
        p.test();
    }
}
```

换成在 `bbb` 包里创建 `Person` 对象再去访问它的成员变量、调用它的方法，就直接报错了。

**第三步，改成 `protected`。**

本类不报错，本包其他类不报错，更重要的是——下面不同包的子类 `Teacher` 也"唰"地变好了。但 `bbb` 包里的无关类 `Test` 还是报错，还是不能用。

**第四步，改成 `public`。**

最大的一位，所有地方全都能用了。

四种修饰符到这里就全测完了。

> **结论**：这一节真正需要背下来的只有两句——`private` 修饰的成员变量和方法只能在本类中使用；`public` 修饰的成员变量和成员方法，在所有的地方都能使用。中间那两个，知道范围是怎么一级一级放大的就行。

### 什么是多态：一个注册方法怎么写才不恶心

接下来是高级篇的第二个知识点：**多态**。

> **定义**：多态是面向对象的三大特征之一。我们已经学过了封装和继承，现在来学最后一个——多态。

#### 同一件事的两种形态

多态，顾名思义，就是**事物的多种形态**。

```text
              ┌──────────┐
              │  Person  │  姓名 / 账号 / 密码 / work()
              └────┬─────┘
        ┌──────────┼──────────┐
     ┌──▼───┐  ┌───▼───┐  ┌───▼──┐
     │Student│  │Teacher│  │Admin │
     └───────┘  └───────┘  └──────┘
```

以前我们创建对象，只有一种玩法：

```java
Student stu = new Student();   // 学生形态
```

现在有了多态，还可以这么玩——把一个学生对象，赋值给它的父类类型：

```java
Person p = new Student();      // 人的形态
```

同一个对象，于是有了两种形态：一个是学生形态，一个是人的形态。**这就是多态。**

那它有什么用？用处大去了，我们来看一个场景。

#### 形参写父类，才能接住所有子类

各位看客老爷在学校里应该都听说过学生管理系统或者教务管理系统。系统里有三个不可或缺的角色：`Student` 学生、`Teacher` 老师、`Admin` 管理员。而每一个角色在使用之前，都必须先注册账号。

假设现在有一个 `register` 注册方法。**它的形参写什么类型比较好？**

先别急着回答，我先问你：写 `Student` 行不行？行的话，学生是能注册了，那老师和管理员这两个角色你怎么处理？`register` 方法接受不了啊，他俩就不开心了呀。

那换个形参，写 `Teacher` 行不行？老师能注册了，那学生和管理员呢？还是没法处理。

所以按照我们以前的写法，想实现这个效果，只能写**三个**注册方法，分别对应老师、学生、管理员。

> **易错点**：这种设计方案是好的吗？不好，甚至是愚蠢的。假如我还有别的角色呢？比如辅导员，比如就业指导老师，你怎么办？每一个角色都要写一个对应的 `register` 方法吗？那这太恶心了呀。

怎么办？遇到问题不怕，咱们要学会思考。先想清楚我们到底想要什么——**想要的是一个 `register` 方法，能同时注册所有的角色**。

那形参写什么？写他们共同的父类 `Person`，不就可以了。

```java
public void register(Person p) { ... }
```

传一个 `Student` 对象过来——哎，这不正是刚学的多态吗？把子类对象赋值给父类的类型。同理，传 `Teacher` 对象、传 `Admin` 对象，全都可以赋值给父类类型。以后哪怕再加新角色，只要它继承自 `Person`，这个方法照样能接住。

这就是多态的第一个好处。

> **结论**：多态好处之一——方法形参写父类类型，就能接收它所有的子类对象，当前方法能接收的类型会更多。

除此之外还有第二个好处：**如果在 `register` 里面用对象调方法，只要子类重写了 `show` 方法，多态就能根据你传进来的实际对象，调用到不同类里面的方法**。

传的是学生，`register` 里调用的就是 `Student` 的 `show`；传的是老师，调用的就是 `Teacher` 的 `show`；传的是管理员，调用的就是 `Admin` 的 `show`。方法体的代码一个字都不用改。

所以总结起来：

> **定义**：多态就是事物的多种形态。它的代码表现形式，就是把子类对象赋值给它的父类类型。

#### 多态成立的三个条件

多态可不是想写就能写的。三个条件：

**第一，必须有继承关系或者实现关系。** 后面的"实现"跟我们马上要学的接口有关，现在还没学到，所以暂时只关注继承。没有真的写 `子类 extends 父类`，这行代码直接报错。

**第二，必须有父类引用指向子类对象。** 说的就是刚才那个书写格式：

```java
Person p = new Student();
//   ↑              ↑
//   │              └── 子类对象
//   └───────────────── 父类引用
```

左边是父类类型的变量，中间是等号，右边是 `new` 出来的子类对象。

> **易错点**：如果左边变量不是父类，而是 `Student s = new Student()`，那就不是多态，是我们最普通的创建对象的方式。

**第三，子类当中需要对父类的方法进行重写。**

但这一条是**可选的**。

> **提示**：如果子类没有重写父类的方法，代码**一样不会报错**。只不过调用 `show` 时，拿到的是父类的 `show` 而不是子类的。所以真正卡住你的，只有前两条——没有继承关系、或者左边的变量不是父类类型，代码当场就报错。第三条重写，影响的是你能不能享受多态的第二个好处。

### 亲手写一遍：学生管理系统

光讲不如写。我们打开 IDEA，新建一个项目 `op-polymorphic`，`op` 是面向对象的意思，后面的 `polymorphic` 就是多态。

需求一共四个 JavaBean：

- `Student`，属性是姓名、账号、密码，行为是"学生的工作是学习"
- `Teacher`，同样的三个属性，行为是"老师的工作是教书"
- `Admin`，同样的三个属性，行为是"管理员的工作是管理网站"
- `StudentManager`，只有**一个**行为，就是注册 `register`，要求这一个方法能注册所有的角色

调 `register` 的时候，要输出这样一段话：姓名为张三的同学注册成功，账号是张三，密码是 123456。

这道题有坑。我们以前说过，构建继承结构第一步要先**分类**。那现在这四个类怎么分？

你发现根本没法直接往一起抽——学生、老师、管理员这仨是人，而第四个学生管理系统是一个系统、一个软件，跟上面根本不是一类。

所以真正的继承结构是这样的：

```text
              ┌──────────┐
              │  Person  │   ← 学生、老师、管理员往上抽出的共性
              └────┬─────┘
        ┌──────────┼──────────┐
     ┌──▼───┐  ┌───▼───┐  ┌───▼──┐
     │Student│  │Teacher│  │Admin │
     └───────┘  └───────┘  └──────┘

  ┌────────────────┐
  │ StudentManager │   ← 独立于继承体系之外，它只是持有 Person 并调用它
  └────────────────┘
```

这两块儿之间没有任何关联。

先写父类：

```java
public class Person {
    // 姓名
    private String name;
    // 注册的时候使用的账号
    private String username;
    // 注册的时候设置的密码
    private String password;

    public Person() {
    }

    public Person(String name, String username, String password) {
        this.name = name;
        this.username = username;
        this.password = password;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public String getUsername() {
        return username;
    }

    public void setUsername(String username) {
        this.username = username;
    }

    public String getPassword() {
        return password;
    }

    public void setPassword(String password) {
        this.password = password;
    }

    // 行为：每个人都需要工作，具体工作内容子类去重写
    public void work() {
        System.out.println("每个人都需要工作");
    }
}
```

> **提示**：空参构造和带全部参数的构造，让 AI 生成没问题。但 `get` / `set` 方法最好不要交给 AI——它一次只能生成一段，而 `get` / `set` 太多了。这种事直接上快捷键 `Alt + Insert`，选第四个 getter and setter，`Ctrl + A` 全选，回车，搞定。

`work` 这个行为，学生、老师、管理员**当然有共性**——每个人都有工作，只不过每个人工作的内容不一样而已。没关系，大不了子类重写。父类这里就先写一句"每个人都需要工作"。

接着写三个子类。`Student` 的名字、账号、密码全都已经抽取到父类了，独有属性一个没有，所以只要构造方法和重写的 `work`：

```java
public class Student extends Person {
    public Student() {
    }

    public Student(String name, String username, String password) {
        super(name, username, password);
    }

    @Override
    public void work() {
        System.out.println("学生的工作是学习");
    }
}
```

```java
public class Teacher extends Person {
    public Teacher() {
    }

    public Teacher(String name, String username, String password) {
        super(name, username, password);
    }

    @Override
    public void work() {
        System.out.println("老师的工作是教书");
    }
}
```

```java
public class Admin extends Person {
    public Admin() {
    }

    public Admin(String name, String username, String password) {
        super(name, username, password);
    }

    @Override
    public void work() {
        System.out.println("管理员的工作是管理网站");
    }
}
```

> **提示**：AI 生成构造方法的时候，有时会顺手给你写上一句 `super()`。这一行留不留都行——不写它，编译器也会在构造函数第一行隐式地加一句 `super()`，去调用父类的无参构造。这是最基本的 Java 知识，别丢了。

最后写第四个 `StudentManager`。**注意千万不要给它写 `extends`**——它跟刚才那个继承体系没有任何关系，我们是用它去管理那三个角色的：

```java
public class StudentManager {
    /**
     * 注册用户
     */
    public void register(Person p) {
        // p 可以是 Person 本身的对象，也可以是 Person 所有子类的对象
        System.out.println("姓名为" + p.getName() + "的用户注册成功");
        System.out.println("账号是" + p.getUsername());
        System.out.println("密码是" + p.getPassword());

        // 调用成员方法，看看传不同对象进来会不会调到不同的 work
        p.work();
    }
}
```

> **提示**：这里本来 AI 给我生成的是"姓名为 xxx 的**同学**注册成功"。`Student` 是同学，没毛病；可 `Teacher` 是老师呀，这句话就露馅了。所以我把提示语换成通用的"用户"，账号密码再单独打一行。这样三种角色都能用。

现在到测试类。注意 `register` 需要你传一个 `Person` 对象进去，所以调用之前得先造出对象来：

```java
public class Test {
    public static void main(String[] args) {
        // 创建一个学生的对象
        Student stu = new Student("张三", "zhangsan", "123456");
        // 创建学生管理系统的对象
        StudentManager sm = new StudentManager();
        // 把学生注册到学生管理系统当中
        sm.register(stu);

        // 再创建一个老师的对象
        Teacher t = new Teacher("李四", "lisi", "12345678");
        // 同样注册进去
        sm.register(t);
    }
}
```

运行结果：

```text
姓名为张三的用户注册成功
账号是zhangsan
密码是123456
学生的工作是学习

姓名为李四的用户注册成功
账号是lisi
密码是12345678
老师的工作是教书
```

重点看 `register` 方法体里那句 `p.work()`——第一次传的是学生，它调用的就是 `Student` 里重写的 `work`；第二次传的是老师，调用的就是 `Teacher` 里重写的 `work`。**方法体一个字没改，行为却跟着对象走了**，这就是多态第二个好处的实感。

### 多态调用成员的两条铁律

基础概念过完了，我们来看一个更细的问题：在多态状态下，调用成员变量和调用成员方法，规则是不太一样的。

成员就两种——成员变量和成员方法。

> **结论**：
> - 调用**成员变量**：编译看左边，运行也看左边。
> - 调用**成员方法**：编译看左边，运行看右边。

这十二个字就是全部，但每一个字都有讲究，我们挨个拆开。

先摆一个最简单的继承结构。父类里有一个成员变量 `name` 赋值为"父"，有两个成员方法：`fuXiu()` 和 `show()`。子类里也有一个同名的成员变量 `name`，赋值为"子"，还有两个方法：`ziXiu()` 是子类独有的，`show()` 是重写了父类的。

```java
public class Fu {
    String name = "父";

    public void fuXiu() {
        System.out.println("父类的 fuXiu 方法被调用了");
    }

    public void show() {
        System.out.println("父类的 show 方法被调用了");
    }
}
```

```java
public class Zi extends Fu {
    String name = "子";

    // 子类独有的方法
    public void ziXiu() {
        System.out.println("子类的 ziXiu 方法被调用了");
    }

    // 重写父类的方法
    @Override
    public void show() {
        System.out.println("子类的 show 方法被调用了");
    }
}
```

在测试类里，我们用多态的方式创建对象：

```java
Fu f = new Zi();   // 这就是多态方式创建对象
```

#### 成员变量：编译看左，运行也看左

先解释"编译看左边"。

这个"载"是"加载"的意思，指的是把 `.java` 文件编译成 `.class` 文件的过程。编译的时候，它看的是**父类当中有没有这个变量**——有，编译成功；没有，编译失败。

```java
System.out.println(f.name);   // 编译的时候检查父类 Fu 里有没有 name，有，编译通过
System.out.println(f.age);    // 父类里没有 age，程序都不用运行，编译阶段就报错了
```

再解释"运行也看左边"。

代码真正跑起来的时候，用的还是父类中变量的值。父类的 `name` 是"父"，子类的 `name` 是"子"，跑一下你就知道打印出来的是哪一个。

#### 成员方法：编译看左边，运行看右边

"编译看左边"跟刚才一模一样——编译的时候看父类里面有没有这个方法，没有就报错，有就编译通过。

但后半句变了：**运行看右边**。代码真正运行的时候，它运行的是子类里面的方法。

```java
f.show();    // 父类有 show，编译通过；运行时找的是子类重写的 show
```

跑出来是"子类的 show 方法被调用了"。

那"运行看右边"还有半句：**如果子类没有重写父类里面的方法，那么此时使用的还是父类的。**

我们用 `f` 去调 `fuXiu()`——它是父类的方法，子类没有重写。代码没有报错，那运行结果是什么？给大家五秒钟时间思考一下，答案打在弹幕里。

先回答第一个问题：**为什么调用 `fuXiu()` 程序没报错？** 因为编译看左边。编译的时候它看左边，也就是父类 `Fu` 当中有没有 `fuXiu`——有的，父类里有这个方法，程序就正常编译通过。

第二个问题：**运行结果是什么？** 运行看右边。真正运行的时候，它会到子类 `Zi` 里去找 `fuXiu`——诶，你发现它没有。那怎么办？**额外再做一步，到父类里面去找**，找到了 `fuXiu` 方法。

所以运行结果是父类的 `fuXiu` 方法被调用了。完整的查找过程是这样的：

```text
  f.show()
      │
      ├─ ① 子类 Zi 里有没有重写的 show？
      │        有 ──→ 调子类的 show
      │        没有 ↓
      │
      └─ ② 回父类 Fu 里找 ──→ 找到，调父类的 show
```

> **结论**：子类重写了就真跑子类的，子类没重写，我也会先去子类看一眼，发现没有，再调用父类的。

所以"重写了"和"没重写"两种情况，方法的查找顺序确实是不一样的。

#### 儿子穿上了爸爸的衣服

这两句话听着抽象，我讲个小故事，你一下就明白了。

这里的 `new Zi()`，好比是这个世界上有一个儿子。我们把子类的对象赋值给父类的类型，这就好比是**儿子穿上了爸爸的衣服**。

现在你要想：一个儿子穿上了爸爸的衣服，在外人的眼中，这个人是儿子还是爸爸？当然是爸爸呀。

所以 `f.name` 这句话，相当于是在问外人眼中——这个穿上了爸爸衣服的人到底是谁？当然是爸爸。打印结果就是"父"。

那 `f.show()` 好比什么呢？**是让这个人开始干活。**

你说这个穿上了爸爸衣服的儿子，他一干活不就露馅儿了吗？爸爸干的这些事，儿子不会，他只能干自己的事儿。所以一旦开始干活，调用的就是子类里面重写的 `show` 方法。

```text
  Zi 对象 —— 穿上 Fu 的衣服 —— 对外就表现为 Fu

  f.name    （问「你是谁」）  →  父的值      露不出馅
  f.show()  （让「你」干活）  →  子的实现    一干活就露馅
```

两句话到这里就讲透了：

| 调用什么 | 编译期看 | 运行期看 | 实际结果 |
| --- | --- | --- | --- |
| 成员变量 | 左边（父类） | 左边（父类） | 拿到父类的值，子类同名变量被无视 |
| 成员方法 | 左边（父类） | 右边（子类） | 调到子类重写的版本，没重写就调父类的 |

### 多态的弊端与类型转换

但就在刚才的调用过程中，我们发现了一个多态的弊端。

我刚才还写了另一个方法 `ziXiu()`，要注意，它在父类里面**没有**，是子类独有的。现在用 `f` 去调它，会怎么样？

直接报错。同样给大家五秒钟思考——为什么？答案还是那十二个字：我调用方法的时候是编译看左边的。我用 `f` 去调 `ziXiu`，编译的时候先去父类里找 `ziXiu`，父类里没有，所以程序直接就报错了，**根本不需要运行**。

> **结论**：多态的弊端就是——**它不能去调用子类的特有方法**。

那如果我就是想用子类的独有功能，该怎么办？

这就得学一个新的知识点了：**类型转换**。类型转换分两种。

#### 向上转型与向下转型

**从小到大，也叫自动类型转换。** 把子类类型转成父类类型——其实这个说的就是多态本身：把子类的对象赋值给父类类型的变量。程序中它是自动进行的，不需要我们做任何额外操作。

```java
Person p = new Student();   // 子 → 父，小 → 大，自动
```

**从大到小，就是强制类型转换。** 把父类类型的变量转成子类类型的，程序**不会**自动进行，需要我们自己写代码实现：

```java
Zi z = (Zi) p;              // 父 → 子，大 → 小，强制
```

一句话就说清楚了：**你想要转成什么类型，在前面的小括号当中就写什么。**

这个代码熟不熟？之前学基本数据类型，把 `double` 转成 `int`，不就是在前面的小括号里写 `int` 吗？对象的转换，规则一模一样。

#### 用类型转换把弊端补上

回到刚才报错的地方，我们来把这个问题解决掉。解决方案就是：**把对象再转回子类类型。**

上面我用多态的方式创建了对象，赋值给了父类变量的 `f`，那么现在只要把 `f` 再转回子类就行了：

```java
Zi z = (Zi) f;
z.ziXiu();        // 子类的 ziXiu 方法被调用了
```

前面加个小括号，小括号里写上 `Zi`，下面用 `z` 去调用，IDEA 立刻就把 `ziXiu` 自动提示出来了，运行一切正常。

至此，多态的弊端就补上了——**转回来之后，子类的特有功能就能正常调用了**。

#### 转错了会抛 ClassCastException

不过呢，在这个转换的时候，有**万分万分**要注意的点。

假设有一个继承结构是爷爷、爸爸跟儿子。我在下面创建的是**爸爸的对象**，赋值给了爷爷类型的变量。那么现在进行强制类型转换的时候，**只能转到爸爸类型，你不能转成儿子类型**。

这个也很好理解：你这个对象只能转成它自己的类型嘛。我创建的就是爸爸的对象，你把它转成儿子的类型，那就不是我的类型了，我怎么能转呢？

我们写个代码验证一下。在这个基础上再加一个爷爷：

```java
public class Ye {   // 爷爷
}
```

把原来的 `Fu` 直接 `extends Ye`，然后在测试类里这么写：

```java
Ye y = new Fu();   // 爷爷类型的变量，指向的是爸爸的对象

Fu ff = (Fu) y;    // ✔ 转成自己的类型，编译没报错，运行也没报错
```

但是如果我"小手一抖"，把它转成子类类型：

```java
Zi zz = (Zi) y;    // ✘ 编译居然没报错，但一运行就炸
```

运行结果：

```text
Exception in thread "main" java.lang.ClassCastException:
    class ...Fu cannot be cast to class ...Zi
```

`Exception`，异常，也就是错误的意思；异常的名字叫 `ClassCastException`，类型转换异常。后面那一大堆解释就是在说：爸爸这个类型，不能转换成儿子这个类型，你的写法有问题。

> **易错点**：强转这件事，**编译期是抓不住的**。代码写完不报错，跑起来才炸。所以千万不要上来就转。

#### 转之前先问一句：instanceof

那该怎么判断呢？其实很简单——转之前先问一下这个变量到底是不是我要的类型。

这就用到一个 Java 的关键字：**`instanceof`**。

```java
if (y instanceof Fu) {      // 判断 y 是不是 Fu 类型的
    Fu ff = (Fu) y;         // 是，才转
    ff.fuXiu();              // 转换成功，父类方法可以调
    ff.show();               // 子类重写的方法也可以调
} else {
    System.out.println("请确定好类型再进行转换");
}
```

`instanceof` 的写法要注意：**前面写变量名，后面写类名**，它的意思就是判断一下 `y` 是不是 `Fu` 类型的。结果是就返回 `true`，不是就返回 `false`。

运行一下，完全没有报错。一旦类型转换成功，`ff` 既能调父类的 `fuXiu()`，也能调子类的 `show()`。

> **结论**：记住这三件事——
> 1. 多态方式的弊端是**不能使用子类特有的功能**；
> 2. 引用数据类型转换有两种：**自动转换**（子→父，也叫**向上转型**，就是多态创建对象的基本格式）和**强制转换**（父→子，也叫**向下转型**）；
> 3. 强转能把对象转成它真正的子类类型，从而调用子类里的独有功能；但**转换的类型跟真实对象的类型不一致，代码会直接报错**，所以转换前最好用 `instanceof` 判断一下，条件满足了再转，这样能避免程序出错。

## 抽象类与抽象方法：写不出方法体的父类，该拿它怎么办
> 对应块：BLK32 | 覆盖分集：P116-P117 | 块标题（分集名）：《第11章-面向对象高级-13-多态的综合练习》

### 继承解决了重复，却顺手造出了新麻烦

前面我们已经把面向对象里的一大块知识点走完了。要描述一类事物，就定义一个 JavaBean，把零零散散的数据和行为封装成一个整体，这套打法我们已经很熟。

可类一多，问题就冒出来了：如果好几个 JavaBean 里有重复的内容，那要写的代码也太多了。这个我们早就解决过——**继承**。把同一类事物里的共性内容抽到父类里，子类就不用再抄一遍，代码复用性立刻就上来了。

可继承用着用着，新的麻烦来了。

举个例子，`eat` 这个方法，猫是吃鱼的，狗是吃骨头的，两个子类的方法体根本不是一回事。现在你把这个方法抽到父类里，问题就来了：**哥们儿，这个方法体我到底该怎么写？**

写不了啊。根本就没法写。

但在那个版本里，我们受语法的限制，不得不写一个方法体上去，于是就干了一件很别扭的事：在父类里**随便写**一个方法体，先让程序不报错，然后再让各个子类按照真实需求去重写。

写的时候我们心里都清楚——**上面这个方法体，它没有任何意义**。屏幕前的兄弟姐妹们，大家说对不对？

这是第一个问题：把共性内容抽到父类之后，父类里这个方法体是没有任何意义的。

还有第二个问题，而且这个更让人无力：如果这个子类**不是你写的，是别人写的**呢？写代码的那哥们儿偷懒了，`eat` 他压根没重写。这时候你拿它没有任何办法，因为**此时语法它不会报错**。

两个问题摆在面前，能不能同时解决？

当然能。这就是我们接下来要学的——**抽象类和抽象方法**。

### 抽象方法：写不出方法体，那就干脆别写

父类里的方法体既然是"没有意义的"，那干嘛还写？干脆不写。此时这个 `eat` 方法就被定义成了抽象方法。

语法上有三处变化，看清楚：

```java
public abstract void eat();
```

- 方法前面多了一个 `abstract` 关键字；
- 后面**没有方法体**，把大括号去掉；
- 用**分号**作为结尾。

> **定义**：在一个继承结构中，我们把共性的行为（方法）抽取到父类之后，由于每一个子类的方法体都不一样，所以在父类里面我们**不能确定具体的方法体**，那么此时这个方法就可以定义为抽象方法。

所以抽象方法的核心，其实就一句话：

> **结论**：如果说有一个方法我不能确定它的方法体了，那么此时这个方法就要定义成抽象的。

而且它一旦定义成抽象的，会立刻带来一个连带效果——**强制让子类去重写**。你在子类里不重写，代码就直接报错。

这样一来，前面那两个问题是不是同时解决了？

- 父类不用再纠结方法体到底写什么——干脆没有方法体，不存在"写得没意义"这回事；
- 别人偷懒不重写——**语法会强制他去重写**，跑不过编译这一关。

> **提示**：所以学抽象类之前，我们要先学抽象方法。抽象方法是里子，抽象类是面子，顺序别反了。

### 抽象类：装抽象方法的容器

抽象方法有了，它总得有个地方待着。这就是抽象类。

规则只有一条，而且非常朴素：

> **结论**：如果说一个类当中存在抽象方法，那么此时这个类就**必须声明为抽象类**，否则代码就会直接报错。

写起来也很简单，在类的声明前面加一个 `abstract` 关键字就完事了：

```java
public abstract class Animal {
}
```

抽象方法和抽象类的格式，一起看就是这两行：

```java
public abstract class Animal {          // 抽象类：类前面加 abstract

    public abstract void eat();          // 抽象方法：方法前面加 abstract，去掉方法体，用分号结尾
}
```

### 猫、狗、动物：先想清楚哪些该往上抽

现在开始动手写代码。我们先不急着敲键盘，先在脑子里把这个继承结构设计出来。

需求是这样的：写两个 JavaBean。猫类有 `name`、`color` 两个属性，三个行为——猫吃鱼、猫抓老鼠、猫喝水；狗类同样两个属性，三个行为——狗吃骨头、狗看家、狗喝水。

真正动手的时候肯定不是只写两个，因为两个还要往上抽，一共要写三个类。

那么第一个问题来了：**你先想，这两者里面有没有共性的内容？**

有。两个都有名字和颜色，这两个属性直接抽到父类里，子类就完全没必要再写一遍了。

再往下看行为，一共三个，一个一个过：

| 行为 | 猫 | 狗 | 归属 | 原因 |
| --- | --- | --- | --- | --- |
| `eat` | 猫吃鱼 | 狗吃骨头 | 抽到父类，**定义成抽象方法** | 都叫"吃"，但方法体不一样，父类确定不了 |
| 抓老鼠 / 看家 | 猫抓老鼠 | （无） | 各自留在子类里 | 猫独有的行为，没必要往上抽 |
| `drink` | 猫喝水 | 狗喝水 | 抽到父类，**普通方法** | 两个方法体一样，父类里能确定 |

所以最后的继承结构长这样：

```text
                 ┌──────────────────────────────┐
                 │   abstract class Animal      │
                 │  ------------------------------│
                 │  name     （共性属性）        │
                 │  color    （共性属性）        │
                 │  drink()  （普通方法，能确定）│
                 │  eat()    （抽象方法，确定不了）
                 └──────────────────────────────┘
                       ▲                ▲
          ┌────────────┘                └────────────┐
          │                                          │
 ┌────────────────────────┐              ┌────────────────────────┐
 │       class Cat         │              │       class Dog         │
 │  ---------------------  │              │  ---------------------  │
 │  重写 eat() → 猫吃鱼    │              │  重写 eat() → 狗吃骨头  │
 │  catchMouse() 猫抓老鼠 │              │  lookHome()  狗看家     │
 │  drink() 继承自父类     │              │  drink() 继承自父类     │
 └────────────────────────┘              └────────────────────────┘
```

> 读图：`name`/`color` 和 `drink` 顺着实线一路往下传；只有 `eat` 在父类那里断了根，两个子类各自接上自己的实现。

这里有一条特别值得单独拎出来说的经验：

> **提示**：以后写继承结构的时候，**不是所有的父类都定义成抽象的**。你要先去观察父类里有没有哪些方法体你确定不了——**有**就定义成抽象方法，这个类就定义成抽象类；如果父类里所有方法的方法体我都能确定，那你压根没必要定义抽象方法，也没必要定义抽象类，直接按之前书写的逻辑来就完事了。

### IDEA 里的两次一键修复

结构想清楚了，代码怎么落？这里有两个地方在 IDEA 里几乎是一按就完事，但**你得知道它给你的是什么选项**，不然容易按错。

#### 父类里删掉方法体之后

先写 `Animal`。属性 `name`、`color` 两个，空参构造和带全部参数的构造、getter/setter 都让 AI 生成好，这些都没问题。行为在父类里一共要写两个。

第一个是 `eat`。前面刚推断出来，`eat` 要写成抽象的，那就把方法体删掉，换成 `分号`。一删完，程序立刻报错——红波浪线出来了。

这时候你有两种方式：第一种是自己在前面加上 `abstract` 关键字，没有任何问题；第二种更省事，用鼠标点一下红色波浪线，按快捷键 **`Alt` + `Enter`**，这是 IDEA 里自动修复代码的快捷键。

它会给你两条修改建议：

- `Add method body` —— 给这个方法加一个方法体。**我不需要**，这不是我想要的；
- `Make it abstract` —— 让当前的方法变成抽象的。

选第二条。注意它会做**两件事**：一是给当前方法加上 `abstract` 关键字，二是**同时把当前的这个类，也就是 `Animal` 前面也加上 `abstract`**。这显然就是我们想要的，一按两件事一起办了。

#### 子类空着不写的时候

再写 `Cat`，让它 `extends Animal`。刚继承下来、代码还没写的时候，红波浪线就出来了。

同样点一下红波浪线，`Alt` + `Enter`，这次给的是两条建议：

- `Make Cat abstract` —— 让当前这个类也变得抽象；
- `Implement methods` —— 去把父类里面的抽象方法进行重写。

选第二条，IDEA 会自动帮你把父类的抽象方法重写出来，你只要在方法体里补一句输出语句，比如"猫吃鱼"，就完事了。

```java
@Override
public void eat() {
    System.out.println("猫吃鱼");
}
```

> **易错点**：继承了一个抽象类却没重写它的抽象方法，**代码是会报错的**。这正是抽象方法第二个好处的直接体现——**它强制让子类必须重写抽象方法，否则代码就会报错**。

#### 跑起来看看

在测试类里创建对象、赋值、调用，把结果打出来：

```text
咪咪
白色
猫吃鱼
猫抓老鼠
喝水
```

属性、继承来的 `drink`、重写的 `eat`、子类独有的 `catchMouse`，全都在。

### 四个必须记住的注意点

至此抽象类和抽象方法的基本知识点就学完了。接下来是四个注意事项，我一个一个说，你跟着我在 IDEA 里试。

#### 抽象类不能被实例化

`Animal` 我们是定义成 `abstract` 抽象的。那我**不信邪**，强行创建它的对象：

```java
Animal a = new Animal();
```

程序直接报错，鼠标悬停上去，它告诉你：`Animal is abstract; cannot be instantiated`——这个类是抽象的，你不能对它创建对象。

这里额外再多说一句为什么。**如果可以创建抽象类的对象，那么我就可以用这个对象去调用一个没有方法体的抽象方法**，这种调用是没有任何意义的。所以 Java 在设计的时候，干脆就加了这么一个规定：抽象类，你不能创建它的对象。

#### 抽象类里面不一定有抽象方法

这句话有两半，前半句是字面意思，后半句才是重点。

前半句好验证。新建一个类叫 `Person`，声明成 `abstract`，然后在里面定义三个方法，每一个都是有方法体的。程序**根本没有报错**。所以抽象类里它是不一定有抽象方法的。

那问题就来了——**表面我理解了，但我心里面有一个小疑惑：它有什么用呢？** 你抽象类里面不写抽象方法，那这个类为什么还要抽象？我定义成普通的类不就 OK 了吗？

我说你有这样的想法，代表你思考了。但这句话有它各自的作用，我们看一段代码。

假设现在有一个抽象父类，里面有**十个抽象方法**。按照我们刚学的，如果我定义一个子类去继承它，那怎么办？**我没有任何办法**，我只能把这十个抽象方法从头到尾再写一遍，这是语法的要求。

但是现在不是所有的方法我都要用啊。假设我现在只要用第三个方法，其他的方法我用不着。那么因为语法的限制，另外九个方法我不得不重写——重写完了之后我一看，**这太浪费了呀**，我压根用不着，我写了干嘛？

所以在实际开发当中，我们一般这么干：**不让子类直接继承于父类，而是在子跟父中间加一个中间层**。中间层的命名有讲究，**前面用父类的名字，后面加一个后缀 `Adapter`**，一个回车。

```text
   method1() method2() method3() ... method10()      ← 抽象父类（10 个抽象方法）
                         │
                         ▼
      ┌──────────────────────────────────────┐
      │  abstract class 父类Adapter extends 父类  │   ← 中间层：10 个方法全部"空实现"
      │  方法体空着什么都不写                     │
      └──────────────────────────────────────┘
                         │
                         ▼
            ┌────────────────────────┐
            │      class 子类          │   ← 真正使用的类
            │  只需要重写 method3()    │
            │  想用哪个就重写哪个        │
            └────────────────────────┘
```

`Adapter` 翻译过来就是**转换器**的意思，相当于我们把这里的抽象父类做了一个转换，让它去继承父类。此时我们可以对里面**所有的抽象方法进行一个空实现**——所谓空实现，就是方法体里面空着什么都不写。

然后子类不要继承父类了，**直接继承中间的 `Adapter`**。这时候就非常方便了。记住一句话：**想要用哪个方法，就重写哪个方法。** 我现在要用到 `method3`，那我就只重写 `method3`，其他的一概不用管。代码的阅读性一下就上来了。

还没完。在这个情况下，中间层 `Adapter` 这个类其实是**没有任何意义的**，你在外界创建它的对象根本就没用。所以我在它前面干脆就直接加上 `abstract`，**不让外界创建它的对象**。

所以你现在回头看这句话——

> **结论**：抽象类里面不一定有抽象方法。它的作用，其实就是为了**不让外界创建本类的对象**。

这个注意点还有后半句：**有抽象方法的类一定是抽象类**。这一句好理解，是刚才已经学过的正常内容。

#### 抽象类里面可以有构造方法

这个很好理解。刚才写 `Animal` 的时候你就看到了，里面有空参构造，也有带全部参数的构造，构造方法我是可以写的。

**但是呢，不知道兄弟们有没有想过一个问题：你抽象类既然不能创建对象，那我这个构造方法的作用是什么呢？**

要回答这个问题，我们得先回去把一件事掰扯清楚：**构造方法本身的作用，到底是什么？是创建对象的吗？**

有兄弟能回答我吗？如果你**觉得**构造方法是创建对象的，那么**这个认知是非常错误的**。

之前我们说过，真正创建对象的是谁？**根本就不是构造方法，是 `new` 关键字创建的。** 我们拿 `Student stu = new Student()` 这句代码举例，`new` 在内存当中一共进行七步：

1. **加载 `Student` 的字节码文件**；
2. 等号左边，在**栈内存**里申请一个局部变量 `stu`；
3. 等号右边有 `new` 了，所以在**堆内存**里开辟了一个小空间——这个空间就是我们平时所说的**对象**，里面会有所有的属性，比如 `name`；
4. 此时这两个属性**还没有值**，所以给**成员变量默认初始化**；
5. **显式初始化**；
6. **构造方法初始化**；
7. 把堆内存里空间的内存地址**赋值给左边的变量**。

```text
            栈内存                          堆内存
         ┌───────────┐
 stu →   │  变量 stu  │ ──── 地址 ────▶  ┌──────────────────┐
         └───────────┘                   │  Student 对象     │
                                         │  name = null(默认) │
                                         │  age  = 0  (默认)  │
                                         └──────────────────┘
                                          ④ 默认初始化 → ⑤ 显式初始化
                                              → ⑥ 构造方法初始化
                                              → ⑦ 变量拿到地址
```

在这七步当中你再去看构造方法，它是不是**只是其中的一小步**啊？它的作用就是给里面的属性进行赋值的。

所以回到我们刚才的问题：抽象类里有构造方法，构造方法的作用是什么？

> **结论**：构造方法的作用**不是创建对象，而是给成员变量进行初始化（赋值）**。在抽象类里，它的意义就是**给子类抽取上来的那些共性内容——`name`、`color` 进行赋值**，仅此而已。

#### 抽象类的子类只有两种写法

抽象类的子类只有两种写法：

- 第一种：**重写抽象类里面所有的抽象方法**，这是我们平时的正常写法；
- 第二种：**子类也是一个抽象类**。

第二种我们刚才其实已经见过了。还记得写 `Cat` 的时候，一按 `Alt` + `Enter`，第一条建议就是 `Make Cat abstract` 吗？一旦当前的类抽象了，此时我就没必要去重写父类里面的抽象方法了。

**但是呢，这种写法其实意义并不是特别大。**

为什么？因为你如果把子类抽象了，那么在这个时候你还要**再写一个孙子类去继承这个子类，并且重写里面所有的抽象方法**。只有这样，我才能在外界去创建孙子类的对象，再去调用你们的方法。因为此类你是抽象的嘛，抽象是不能创建对象的，对吧。

所以这种方式我们一般不用。一般来讲，**子类就是重写父类里面所有的抽象方法**，这是我们正常的使用方式。

### 那我能不能干脆不写抽象方法？

学完之后很多兄弟心里会有一个疑问：哥们我感觉抽象方法这有点多余啊——我定义完了抽象方法，我子类还得再重写一遍，感觉好麻烦。我能不能不写抽象方法，把这个方法直接放到子类里当我的特有功能，这不也 OK 吗？而且我父类的方法不用写代码，还写得更少呢。

**这么写是有问题的。**

因为在企业当中，一个完整项目不可能是一个人独立开发出来的。假设这里的 `Dog` 和 `Cat` 是**两个人**写的，我们都知道人是有独立思想的。

假设写 `Cat` 的这哥们儿英文不太好，所以他的方法名就叫 `ABC`；而且他还给这个方法加了一个**形参**，表示你喂什么猫就吃什么。这是 `Cat` 这边。

再看右边的 `Dog`，他是**第二个人**写的。这位哥们把方法名定义成了 `eat`，只不过他给这个方法**加了一个返回值**，他觉得你吃饭不能只进不出。

```java
// 开发者 A 写的 Cat
public void ABC(String food) {
    System.out.println("猫吃" + food);
}

// 开发者 B 写的 Dog
public String eat() {
    return "狗吃骨头";
}
```

现在，屏幕前的兄弟姐妹们，大家觉得这两段代码有没有问题？

**其实呢，从语法层面来讲，这两段代码完全没有任何问题。** 但是后面在使用的时候，这就彻底完犊子了。

假设现在有第三个人，他要去调用 `eat` 的方法了。那么因为每一个 `eat` 的方法写的都不一样，那这个时候你说他怎么办？**没有任何的办法**，他只能挨个挨个地去查看每一个类。

那么现在如果这样的类越来越多、越来越多，每一次都要去查看，根本就看不过来——**史山代码**，这就形成了。

问题到这里已经摆出来了。那我再问一句：**形成这个问题，其最根本的原因是什么？**

其实很简单：**就是因为子类你在写 `eat` 这个方法的时候，没有统一而造成的。**

所以啊，在代码当中我们就要定义抽象方法。**抽象方法其实还有一个隐藏的含义：我要强制子类必须要按照这种格式来进行重写，否则代码就会直接报错。**

那么此时一旦统一之后，在调用的时候就非常爽了。因为此时我**根本就没必要去看子类，直接看父类就可以了**，方便了代码的使用，美滋滋。

> **结论**：这就是抽象类和抽象方法的意义。

### 这一讲要掌握的清单

最后做个小结。这一个知识点，需要大家掌握的就是这么几件事：

**第一，什么是抽象类和抽象方法。** 当多个子类抽取共性的时候，如果你没有办法去确定方法体，此时我们就要把父类当中的方法定义成抽象的，**强制让子类按照当前格式来进行重写**。另外注意：抽象方法一旦写完了，**抽象方法所在的类必须是抽象类**。

**第二，格式怎么写。** 格式其实非常简单，只要记住**一个关键字 `abstract`** 就可以了。

**第三，如果要继承一个抽象类，有哪些要注意的。** 真正需要掌握的只有三条：

1. **抽象类不能被实例化**，抽象类你不能创建它的对象，只要创建了代码就会出错；
2. 继承一个抽象类的时候只有两种方式——**要么重写抽象类里面所有的抽象方法，要么子类也是一个抽象类**。只不过如果采取了第二种方式，此时的子类**还是不能创建对象**；那如果说你要创建一个对象的话，还要**再写一个孙子类去继承子类**，去把里面所有的抽象方法进行重写，这才是可以的；
3. 抽象类里面**可以有构造方法**，但构造方法的作用不是创建对象，而是给成员变量进行初始化。

这几句话不需要背，以后代码出错了你能想起来"我怎么解决"就可以了。

**题干**：写两个 JavaBean，猫类和狗类，并且用继承把共性内容抽取到父类。

- **猫类**：属性两个——`name`、`color`；行为三个——猫吃鱼、猫抓老鼠、猫喝水；
- **狗类**：属性两个——`name`、`color`；行为三个——狗吃骨头、狗看家、狗喝水。

**解析**：先找共性——`name`、`color` 两个属性直接上提到父类，定义父类为 `Animal`。再逐个看行为：`eat` 猫狗方法体不同，父类确定不了，抽上去并定义成**抽象方法**，所以 `Animal` 必须是**抽象类**；`catchMouse`（猫抓老鼠）和 `lookHome`（狗看家）都是各自独有的，留在子类里不上提；`drink` 猫狗方法体完全一致，直接抽到父类并写成**普通方法**。推导依据见上文「猫、狗、动物：先想清楚哪些该往上抽」。

```java
package test4;

/*
    需求：
    定义猫类和狗类
    猫类：属性 name、color；行为 eat(猫吃鱼)、catchMouse(猫抓老鼠)、drink(喝水)
    狗类：属性 name、color；行为 eat(狗吃骨头)、lookHome(狗看家)、drink(喝水)
*/

public abstract class Animal {

    private String name;
    private String color;

    public Animal() {
    }

    public Animal(String name, String color) {
        this.name = name;
        this.color = color;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public String getColor() {
        return color;
    }

    public void setColor(String color) {
        this.color = color;
    }

    // 猫吃鱼、狗吃骨头，父类确定不了方法体 -> 抽象方法
    public abstract void eat();

    // 猫喝水、狗喝水一样，方法体能确定 -> 普通方法
    public void drink() {
        System.out.println("喝水");
    }
}
```

## 接口：独立于继承体系之外的一条规则
> 对应块：BLK33 | 覆盖分集：P118 | 块标题（分集名）：《第11章-面向对象高级-15-接口和接口中的成员》

高级篇的第四个知识点，我们来聊接口。上一轮我们把抽象类讲透了，抽象类解决的是"父子之间共性往上抽"的问题，那接口呢？接口是来解决另一类问题的。先别急着记语法，我们从一个场景说起，这个场景你一定会觉得眼熟。

### 兔子不会游泳，这事该写在哪里

假设现在我有这样一个继承体系：上面的父类是 `Animal` 动物类，下面的子类分别是兔子类、青蛙类、狗类。

父类 `Animal` 里定义的是整个体系共有的内容，所以每一个动物都有的共有行为——比如吃饭、喝水——就可以直接定义在父类当中。这些放到父类里，没有任何问题。

现在问题来了：如果我要给这个继承体系添加第三个行为——**游泳**——我能把它写在父类里吗？

答案显而易见，不行。为什么？因为父类里写的是共性的内容。下面的青蛙、狗会游泳，这没有任何问题；但兔子它不会呀，兔子就算扑腾了两下，马上就会凉凉。所以把 `swim()` 写在 `Animal` 里，对兔子来说是不合理的。

好，发现了，我要解决啊——游泳到底写在哪里才合理呢？

按照我们之前所学的，很多兄弟第一反应是：我可不可以把它写在各个子类当中，就当作子类的一个特有行为呢？其实这么写语法上没有任何问题，但有一个致命的弊端：**我无法确定各个子类中方法的书写格式**。

青蛙那个哥们写 `public void swim()`，没有任何问题；写狗类的那个哥们儿说，我觉得游泳是一个动词，应该写成 `swimming`——其实呢这也没错。你看，方法一旦不统一，后续我在调用的时候就非常麻烦，每次调用我都要去看一看它到底叫什么，非常的恶心。

那我该怎么办呢？那么在这个时候，接口其实就出现了。

此时我们可以定义一个"游泳"的接口，在接口里面定义游泳的抽象方法。你想让哪个动物拥有游泳的功能，就让这个类跟接口发生关系就可以了。这样就可以强制青蛙类和狗类，按照我现有的这个格式去进行重写。

> **定义**：接口其实它就是一种规则，而且是一个独立于继承体系以外的规则。

这里有个特别好记的比喻，你把接口理解成"干碟"（干爹）就行。之前学的那个父类是"亲爹"。在刚刚的继承结构当中，游泳作为部分子类共性的内容，你直接写在父类当中不合适，写在子类当中当作特有的行为也不合适。那么在这个时候，我们就可以把游泳写到接口当中——想让哪个子类拥有游泳的功能，就让这个子类认那个接口为干爹，这就完事了。

那么"接口是一种规则"这句话该怎么理解？其实这个规则就体现在抽象方法当中：你的子类必须按照我接口里面规定的这个方法的格式去重写，否则代码就会直接出错。这个就是接口出现的意义。

### 认亲爹与认干爹：interface 与 implements

那接口该怎么定义呢？其实定义接口跟定义一个类非常类似，区别就在关键字上——我们用到的关键字是 `interface`：

```java
public interface Swim {

    public abstract void swim();
}
```

这里有三个地方一定要注意：

第一，我现在定义的是接口，不能用 `class`，用的是 `interface`。写完之后你会发现，左边那个小圆圈变成绿色的，那就是接口的标识。

第二，接口跟类之间它不是继承关系，它叫做**实现关系**，用关键字 `implements` 来实现。

```java
public class Frog extends Animal implements Swim {
}
```

第三，万一在新建的时候一不小心把它定义成类了，有没有补救的办法？也有。你只要把关键字 `class` 改成 `interface` 就可以了。

这跟我们之前继承一个父类非常类似，只不过：继承一个父类相当于认亲爹，用 `extends`；实现一个接口是认干爹，用 `implements`。

那在实现一个接口的时候，有三个小点需要我们注意：

1. **接口不能实例化**。也就是表示接口不能创建它的对象。
2. **接口的子类我们也叫实现类**。在实现类当中，我们必须要么重写接口里面所有的抽象方法，要么实现类本身它是一个抽象类。当然在际开发当中，更多用的是前一种方式。
3. **一个类可以实现多个接口**，也可以在继承一个类的同时去实现多个接口。很好理解——亲爹只能有一个，但是干爹可以有无数个。

### 把这套关系在 IDEA 里搭出来

光说不练假把式，我们打开我们心爱的 IDEA，把它真写出来。

在这个项目里我已经新建好了一个包，叫做 `test1`，题目的需求我也粘贴过来了。接下来我们开始写，还是老规矩，先写父类再写子类。

先看父类 `Animal`。青蛙、狗、兔子里面都有共有的属性——名字还有颜色，我们就这样写：

```java
package com.itheima.test1;

public abstract class Animal {

    private String name;
    private String color;

    public Animal() {
    }

    public Animal(String name, String color) {
        this.name = name;
        this.color = color;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public String getColor() {
        return color;
    }

    public void setColor(String color) {
        this.color = color;
    }

    public abstract void eat();
}
```

空参构造、带全部参数的构造、get/set，这些都可以让 IDEA 自动生成，不用手敲。

关键在最后那个 `eat()`。AI 自动帮我们生成的时候还多给了两个方法——`show()` 和 `it()`，`show()` 用不上，删掉；`it()` 我们要保留，但是因为每一个子类吃的东西是不一样的，这个方法体你根本不知道写什么，所以我们把它定义成抽象的：直接删掉方法体，加一个分号，前面补一个 `abstract`。

补完之后记得把上面的类也去补一个 `abstract`，因为**抽象方法所在的类必须要是抽象类**。

当然我们也有一个更简单的方式：用鼠标点一下红色波浪线，`Alt + Enter`，选择第二个 `Make it abstract`。你看，爱护的 IDEA 会自动帮我们把当前的方法变成抽象，与此同时它也会把上面的类添加一个 `abstract`，一个回车就完事了，非常的爽。

接下来写干爹接口。右键 `new Java class`，起个名字就叫做 `Swim`。这里要注意，你千万不能直接回车——现在我要定义的是接口，所以要选择这里的 `Interface`，再来一个回车。

```java
package com.itheima.test1;

public interface Swim {

    public abstract void swim();
}
```

然后是三个子类：

```java
package com.itheima.test1;

public class Rabbit extends Animal {

    public Rabbit() {
    }

    public Rabbit(String name, String color) {
        super(name, color);
    }

    @Override
    public void eat() {
        System.out.println("兔子在吃胡萝卜");
    }
}
```

兔子是不会游泳的，所以我直接让它 `extends Animal` 就完事了。写完空参构造和带全部参数的构造之后，父类里面的抽象方法需要重写，还是点红色波浪线 `Alt + Enter`，选择第二个 `Implement methods`，把 `eat()` 重写掉。

青蛙不一样，它是一个动物，它也会游泳，所以要让它继承 `Animal` 的同时还要 `implements Swim`：

```java
package com.itheima.test1;

public class Frog extends Animal implements Swim {

    public Frog() {
    }

    public Frog(String name, String color) {
        super(name, color);
    }

    @Override
    public void eat() {
        System.out.println("青蛙在吃虫子");
    }

    @Override
    public void swim() {
        System.out.println("青蛙正在蛙泳");
    }
}
```

注意这一次我重写的不止一个方法了：我既继承了一个抽象类，又实现了一个接口，那么现在你**必须要把这两个里面所有的抽象方法全部进行重写**。还是 `Alt + Enter` → `Implement methods`，你会看到父类里面的 `eat`、接口里面的 `swim` 都被默认选中了，点一下就自动全部生成，然后我再补上输出语句就行。

狗跟青蛙是一模一样的，`extends Animal` 加 `implements Swim`，重写之后是"狗正在吃骨头"、"狗正在狗刨"。

到此为止，父类动物类、接口 `Swim`、下面三个子类，一共五个类，12345 全部写完。

最后到测试类里创建对象并调用方法。我创建一个青蛙的对象，它叫小青青，颜色那肯定是青色的咯：

```java
Frog f = new Frog("小青青", "青色");
System.out.println(f.getName() + " " + f.getColor());
f.eat();
f.swim();
```

右键 Run，输出是这样的：

```text
小青青 青色
青蛙在吃虫子
青蛙正在蛙泳
```

兔子类和狗类也是同样的方式，只不过我们要注意一点：**如果我们创建兔子类的对象，是不能调用 `swim()` 的。** 为什么？因为刚刚在书写的时候，我们并没有让它去 `implements Swim` 那个接口。方法压根不在它身上，编译期就直接给你拦下来了。

到这里，关于什么是接口，我们就已经全部学习完毕了。

### 接口里到底能装些什么

接下来我们学习接口里面成员的特点。接口里的成员其实就分为三种：成员变量、成员方法，还有一个构造方法，我们一个一个来看。

#### 成员变量：只能是常量

接口当中的成员变量，它**只能是常量**，默认会使用 `public static final` 进行修饰。

这句话什么意思？简单来说，如果我在接口里面去定义了一个 `int A` 这么一个变量，那么前面虚拟机呢会默认地帮你去加上这三个修饰符 `public static final`。

我们不靠嘴说，直接写代码验证。我新建一个接口 `Inter`，在下面直接定义一个变量：

```java
package com.itheima.test2;

public interface Inter {

    int A;
}
```

代码写完你发现它直接报错了。为什么？因为它默认被 `final` 修饰了，你是一个常量，常量需要手动地赋值。所以在这儿我就给它赋值为十：

```java
package com.itheima.test2;

public interface Inter {

    int A = 10;
}
```

赋值完毕之后代码就成功了。顺便呢我把这个名字进行大写——因为常量名字要大写。

光能编译通过还不够，我们来验证另外两个修饰符。回到测试类当中，此时我们就可以来测试一下了：先写一个输出语句，然后我可以直接 `Inter.A` 写上。你发现直接能点出变量名——这就表示前面一定有一个 `static` 来修饰。右键 Run，运行完毕，十，这就有了。

另外还有一点：我可以在其他的包（也就是 `test1` 这个里面）去把刚刚的代码粘贴过来使用，你发现它也没有任何的报错。注意哦，我们现在的操作是在**其他包的类中**去使用 `Inter` 里面的 `A`。那么你想，如果我是用 `private` 修饰的、或者用 `protected` 修饰的，它都无法实现这个效果——跨包访问不到。所以这就证明了它前面有一个默认的 `public`。

那三个修饰符里我们已经用代码验证了两个，第三个我们再换个更硬核的方式：反编译。所谓反编译，就是把字节码文件再变回 java 文件，让我们直接看到代码的效果。

怎么反编译呢？我们可以找到项目里的 `out` 文件夹，因为 `out` 文件夹里面装的就是我们编译之后所有的 class 文件。找到 `out` → `production` → `OP` → `com` → `itheima` → `test2`，你会看到刚刚编译完的 `Inter.class` 文件。

在上面那个路径里输入 CMD，回车，反编译我们会用到一个命令，就是 `javap`：

```bash
javap Inter
```

这里补一个小技巧：写这个接口名字的时候，没必要把名字全部都打出来，直接打它前几个首字母，然后 `Tab` 一下就可以了；如果这个文件夹里有多个重名的，你就多按几下 `Tab`。

结果出来你看：在刚刚我的代码里面只写了一个 `int A`，前面的这三个我是没写的，那为什么现在出现了呢？其实很好理解，就是我们 JVM 虚拟机在编译的时候，会把前面的三个修饰符自动地加上。

```text
Compiled from "Inter.java"
public interface com.itheima.test2.Inter {
  public static final int A = 10;
}
```

所以在以后我们定义这个变量的时候，写熟了你直接写 `int A = 10` 没有任何问题。但是呢，现在我们是初学者，刚开始学习，建议大家还是把前面的这些修饰符自己手动地加上，这样会利于我们代码的学习。

> **提示**：还有一条很好用的经验——在我们心爱的 IDEA 当中，如果某些关键字写完之后变灰了，那就表示当前可以省略不写，在编译的时候虚拟机会帮你自动加上。

#### 构造方法：干脆就没有

第二个，构造方法。这个最简单——在接口当中没有构造方法。

我不相信，我要自己手动地强制书写一下。按照构造方法的格式，我写 `public Inter() { }`，你发现唰的一下它就报错了。所以构造方法在接口当中是没有的。

那为什么没有呢？你有没有想过这个问题？

因为接口它是不能创建对象的，而且接口里面所有的成员变量它都是常量，已经有真实的数据了，所以我们就无需在创建对象的时候，再给它进行赋值了。

你再回忆一下我们之前讲过的构造方法——构造方法的作用是什么？不就是创建对象的时候给成员变量进行赋值吗？现在你又不能创建对象，而且你里面的变量都是常量、已经有数据了；既不能创建对象，又不需要赋值，那你说我还要构造方法干嘛呀？所以接口当中干脆就没有构造方法。

#### 成员方法：只能是抽象方法

第三个，成员方法。在 JDK7 以前，在接口当中我只能定义抽象方法，你不能写那种有方法体的方法，默认使用 `public abstract` 来进行修饰。

在 JDK8 还有 JDK9 开始的时候，接口当中又有了这种有方法体的方法。那现在呢，我们先忽略下面的这两个新成员，先去学习以前的这种方式。

来写一写。在这个下面我前面不写修饰符，哥们直接写 `void method()` 的小括号分号：

```java
package com.itheima.test2;

public interface Inter {

    int A = 10;

    void method();
}
```

你发现代码也没有报错。而且在这里我准备了一个类，我用它去 `implements Inter` 这个接口的时候，选择第二个 `Implement methods`，你看它是不是也可以正常地进行重写呀？

同样的，我们再用反编译的方式去验证一下这个观点。只不过在反编译之前，我们要先右键 Run 运行一下，让它重新编译——因为刚刚我们写完方法之后没有重新编译这个接口，现在这个接口的 class 文件当中还只有这么一个成员。重新 Run 之后再 `javap Inter`：

```text
Compiled from "Inter.java"
public interface com.itheima.test2.Inter {
  public static final int A;

  public abstract void method();
}
```

你看前面是不是默认加上了 `public abstract` 这两个修饰符呀。到此为止，关于接口里面成员的特点，我们就已经全部学习完毕了。

### 三种关系，一次说清

最后我们来看接口和类之间的关系，他们的关系一共有三种：

| 关系 | 关键字 | 能不能多 |
| --- | --- | --- |
| 类 与 类 | `extends` | 单继承，不能多继承，但可以多层继承 |
| 类 与 接口 | `implements` | 单实现、多实现都行，还能边继承类边实现多个接口 |
| 接口 与 接口 | `extends` | 单继承、多继承都行 |

第一条我们之前学过，一个类可以继承另外一个类，只能单继承不能多继承，但可以多层继承，这里就不多重复了。我们重点研究下面两个。

#### 类与接口：实现关系

一个类可以实现另外一个接口，在实现的时候可以单实现，也可以多实现，还可以在继承一个类的同时去实现多个接口。

写的时候有个命名习惯：如果你不知道怎么起名，前面是接口的名字，后面加上 `Impl`，就表示我当前的类是前面这个接口的实现类。我们这里已经有 `Inter1` 和 `Inter2` 两个接口了，我写一个 `Inter1Impl`：

```java
package com.itheima.test3;

public interface Inter1 {

    void method1();

    void method2();
}

public interface Inter2 {

    void method3();

    void method4();
}
```

```java
package com.itheima.test3;

public class Inter1Impl implements Inter1, Inter2 {

    @Override
    public void method1() {
    }

    @Override
    public void method2() {
    }

    @Override
    public void method3() {
    }

    @Override
    public void method4() {
    }
}
```

那如果说我要去实现多个接口呢？其实很简单，只要把第二个接口写在后面就可以了，接口跟接口之间记得要用**逗号**来进行隔开。

这里有一个小小的注意点：**如果一个类实现了多个接口，那么就要重写多个接口中所有的抽象方法。** 我们来试一下：点红色波浪线，`Alt + Enter` → `Implement methods`，你会发现 `Inter1` 里面的 `method1`、`method2`，`Inter2` 里面的 `method3`、`method4`，它是不是都默认选择了呀？点击一下，全部生成。但凡你少写一个，代码就会直接报错。

后面还有一句话：在继承一个类的同时去实现多个接口。我下面提前写好了一个 `Person` 类，里面有 `name`、`age`、空参构造、全部参数的构造、get/set 的方法，还有一个 `show` 方法。现在让 `Inter1Impl` 去 `extends Person`，并且去实现后面这两个接口：

```java
package com.itheima.test3;

public class Inter1Impl extends Person implements Inter1, Inter2 {

    // Inter1 与 Inter2 中全部抽象方法的实现
}
```

你发现代码也没报错。但是呢你要注意哈，**如果说我们把 `extends` 写在 `implements` 的后面，这个时候它就报错了**。为什么？你要想嘛，亲爹的地位那肯定是比干爹要更大的呀，所以亲爹一定要写在前面。

在这种方式当中，我们有两个地方需要我们兄弟们注意，我们一个一个来。

**第一个注意点：如果父类 `Person` 它也是一个抽象类的话，那么在子类当中需要把所有的抽象方法进行重写，要么子类本身也是一个抽象类。** 当然呢我们也知道，"子类本身也是一个抽象类"这个一般用的不多，用的还是"把抽象方法全都重写"这个会比较多。简单来说，就是此时我们要把抽象父类 `Person`，还有后面这两个接口，一共三个类里面所有的抽象方法全部进行重写，这才是可以的。

我们也来演示一下。我打开 `Person`，在里面补一个抽象方法 `public abstract void aaa();`，然后在类的上面也补一个 `abstract`。回到 `Inter1Impl` 当中，你发现代码是不是就直接报错了？把下面的实现删掉，点红色波浪线 `Alt + Enter` → 第二个，你看父类里面的、两个接口里面的所有抽象方法，IDEA 是不是默认都让你重写呀？点击一下，你看在这种情况下代码才是正确的。

**第二个注意点：如果多个接口当中出现了重复的抽象方法，那么此时我们只要重写一次就可以了。**

这句话是什么意思，我们一起来看。比如说在 `Inter1` 这个接口当中，我们去补一个抽象方法 `public abstract void bbb();`，然后呢在 `Inter2` 里面我也有一个 `bbb`。那么这个时候你想，在实现类 `Inter1Impl` 当中，关于那个 `bbb` 我只要写几个？根据我们刚刚所说，其实我们只要写一个就可以了。`bbb` 你发现是不是刷的一下就好了，程序就不会报错了。

这个该怎么理解呢？其实很好理解：第一个干爹他让你做这件事，第二个干爹他也让你做这件事。那你说我只要做几次？我是不是在子类当中只要做一次就可以了呀。

甚至是如果说我父类 `Person` 里面，还有接口里面的方法都重复了，那么在这种情况下，我也只要重写一次就行。比如说我在抽象父类里面有一个 `aaa`，`Inter1` 里面我也有一个 `aaa`，然后呢 `Inter2` 里面我也有个 `aaa`，那现在你看我在子类 `Inter1Impl` 当中，也只要把 `aaa` 只写一次，这就可以了。跟刚刚一样：亲爹让我干这件事，两个干爹也让我干这件事，那我同样的只要做一次。

#### 接口与接口：也是继承关系

第三个，接口跟接口之间他们两个也是**继承关系**，用 `extends`，可以单继承也可以多继承。

我新建一个接口叫 `MyInter`，让它去继承 `Inter1` 还有 `Inter2`：

```java
package com.itheima.test3;

public interface MyInter extends Inter1, Inter2 {
}
```

一旦继承完了之后，就相当于把这两个接口里面所有的抽象方法全都继承到 `MyInter` 里面了。那么后面如果说我还有一个子类，比如说我写一个 `MyInterImpl`，我去实现 `MyInter` 的时候，你必须把它继承的所有抽象方法全都进行重写。你来看 IDEA 是不是默认全选中了，点击一下，全部重写，这才行。

这个关系只有一个注意点：**如果有一个接口 A 它继承了多个接口，那么此时相当于就是把多个接口中的抽象方法全部继承下来了**；那么在以后，实现类在实现接口 A 的时候，就要把它继承来的所有抽象方法全都进行重写，这才是可以的。

到这里，关于类跟类、类跟接口、还有接口跟接口之间的这三个关系，我们就已经全部学习完毕了。其实最重要的、需要大家重点掌握的，就是下面的这两个小注意点。

> **提示**：本讲留了三段动手练习——按题目需求把接口版的继承体系（父类 `Animal` + 接口 `Swim` + 三个子类）在 IDEA 里自己写一遍，再把接口成员变量的三段代码（默认值、常量的验证、反编译）自己敲一遍，最后把这三种关系的三段代码自己练习一下。这三段都没讲具体的题面细节，就按课上讲的顺序自己补齐即可。

### 先来一道题：四个都要说出话的人

到目前为止，接口那些最基本的语法我们已经全部学完了，最后拿一道综合案例收一收——编写一套带有接口、还有抽象类的标准类。

题目结构有点复杂，所以先别急着写代码，我们先去分析需求。

需求很简单：我们有乒乓球运动员、篮球运动员，还有乒乓球教练、篮球教练。为了出国交流，**凡是跟乒乓球相关的人，都要学英语**。

           乒乓球运动员            篮球运动员
           姓名、年龄              姓名、年龄

### 别急着写代码，先把继承结构画出来

再强调一次：**不要上来就写代码，一定要先画继承结构，然后再去写代码。**

画图的时候是从下往上画的，也就是先画子类，在不断地往上抽取，形成一个继承结构。既然子类有四个，那我就在画图板上一共画四个圈，把四个子类先粘贴过来：

```text
┌──────────────┐ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐

│ 说英语        │ │                │ │ 说英语         │ │               │
└──────────────┘ └──────────────┘ └──────────────┘ └──────────────┘
```

四个子类铺完了，往上抽。

### 先看看别人交上来的答案错在哪

之前有同学是这么设计的：在四个子类上面直接写一个父类 `Person`，把共有的属性都往上抽——姓名、年龄，四处重复的就全删掉。属性这一层没抽错。

接下来抽行为的时候就出事了。四个子类里没有一个行为是大家都有的，所以很多同学的做法是：在上面再定义三个接口，一个说英语接口、一个学接口、一个教接口，谁有什么行为就实现哪个接口，同时四个子类还共同继承 `Person`。

```text
        ┌───────────┐  ┌────────┐  ┌────────┐
        │ 说英语(接口) │  │ 学(接口) │  │ 教(接口) │
        └─────▲─────┘  └───▲────┘  └────▲───┘
              │            │           │
              └────────────┴─────┬─────┘
                                 │
                         ┌───────────────┐
                         │     Person     │   姓名、年龄
                         └───────────────┘
                ┌──────────┬───┴────┬──────────┐
           乒乓球运动员  篮球运动员  乒乓球教练  篮球教练
           (学、说英语)   (学)      (教、说英语)   (教)
```

这个思路好吗？想都不用想——看这里的线，你看晕了吧？这种思路**不好**。

我们之前说过，什么情况下才能用继承：**你需要满足子类是父类中的一种。**

而且这里面还有一层更隐含的味道：一个父类中，它所有的子类需要是同一种事物，这样子才可以。

现在跟着我一起来思考两个问题：

- 乒乓球运动员跟篮球教练这两种，它的关系大吗？红色框起来的那两类事物，感觉根本就没有什么太大的联系。
- 那反过来，篮球运动员跟乒乓球教练，这两个的关系大吗？也不大吧。

既然都不大，你为什么要让他们去认同一个"当爹"的呢？

> **易错点**：属性相同不等于可以抽成父类。用继承的前提是 **is-a** 关系成立——子类得是父类中的一种事物。共有的字段可以抽、共有的方法可以抽，但**共有的属性不构成父子关系**。

### 两条能走通的路

正确的设计要从下往上重新抽，而且有两种完全不同的分类方式。

#### 按项目分：乒乓球从业者 / 篮球从业者

第一种思路，把跟乒乓球相关的归为一类，跟篮球相关的归为一类。左边这两个往上抽一个父类，叫 `乒乓球从业者`；右边的往上抽一个父类，叫 `篮球从业者`；这两个再往上抽，就是 `Person`（人）。人当中只留共有的姓名和年龄。

行为方面：乒乓球从业者和篮球从业者都有"说英语"吗？没有。乒乓球从业者的共性行为是**说英语**——所以说英语可以留在乒乓球从业者里，篮球从业者那边就什么都不用留。

而"学"和"教"这两个行为，横跨了左右两个体系，抽不出来单独作为父类，那就做成两个接口横切在体系之外。

```text
                          ┌─────────────────┐
                          │      Person     │    姓名、年龄
                          └────────┬────────┘
                 ┌─────────────────┴─────────────────┐
          ┌───────┴────────┐              ┌───────────┴──────┐
          │   乒乓球从业者   │              │    篮球从业者     │
          │  姓名、年龄      │              │    姓名、年龄     │
          │  说英语          │              │                  │
          └───┬─────────┬───┘              └───┬──────────┬───┘
              │         │                        │          │
       ┌──────┴──┐  ┌───┴─────┐            ┌──────┴──┐  ┌────┴─────┐
       │乒乓球运动员│  │乒乓球教练│            │篮球运动员│  │ 篮球教练  │
       └─────────┘  └─────────┘            └──────────┘  └──────────┘
           │ 学         │ 教                    │ 学         │ 教
           └────────────┴──────────┬───────────┴────────────┘
                        （学接口、教接口横切在体系之外）
```

这就是第一个思路：**三级结构**，最上层是人，中间一层是跟乒乓球相关的和跟篮球相关的，第三层才是我们要的四个子类。

#### 按角色分：运动员 / 教练

其实还有第二个、更好的思路。我们还有一种分类的方式：**把运动员跟运动员放在一起，教练跟教练放在一起**，你觉得这样子是不是也可以？

往上抽，运动员这一支的父类就叫 `Sporter`，教练那一支的父类就叫 `Coach`。

- 运动员里面的共性属性是姓名、年龄，抽到 `Sporter` 里。
- 运动员的共性行为是"学习"。但学习的内容不一样怎么办？**学习的内容不一样，我完全可以把它定义成抽象的呀**，方法名就叫 `study`。
- 抽完之后，乒乓球运动员里就只剩一个独有的"说英语"了；篮球运动员里的"学"也被父类的抽象 `study` 接管了。
- 教练那一支同理，共性行为是"教"，教什么不一样？那也定义成抽象的，方法名 `teach`；抽完之后乒乓球教练手里也只剩一个"说英语"。
- 两个"说英语"，横跨了运动员和教练两个体系，抽不出父类——那就单独做成接口。

再往上，`Sporter` 和 `Coach` 继续抽，就是 `Person`，里面只放姓名和年龄。

```text
                          ┌─────────────────┐
                          │      Person     │    姓名、年龄
                          └────────┬────────┘
                 ┌─────────────────┴─────────────────┐
          ┌───────┴────────┐              ┌───────────┴──────┐
          │     Sporter    │              │      Coach       │
          │    运动员       │              │      教练         │
          │ 抽象方法 study() │              │ 抽象方法 teach()  │
          └───┬─────────┬───┘              └───┬──────────┬───┘
              │         │                        │          │
       ┌──────┴──┐  ┌───┴─────┐            ┌──────┴──┐  ┌────┴─────┐
       │乒乓球运动员│  │乒乓球教练│            │篮球运动员│  │ 篮球教练  │
       └─────────┘  └─────────┘            └──────────┘  └──────────┘
           │              │                       │
           └──── 实现 English 接口 ──────────────┘
                （只有乒乓球一方要说英语）
```

### 为什么第二条路更简洁

把两个思路摆在一起对比一下，你会发现：**它们都是三层结构，最上层都是人，往下都是四个子类，光看继承结构几乎一模一样。**

真正的差别在中间层和接口上：

| | 按项目分（思路一） | 按角色分（思路二） |
|---|---|---|
| 中间层 | 乒乓球从业者、篮球从业者 | Sporter（运动员）、Coach（教练） |
| 中间层里的抽象行为 | 无（抽象方法都跑到接口里了） | `study()`、`teach()` 两个抽象方法 |
| 体系外还要额外加的接口 | 学接口、教接口（两个） | 说英语接口（一个） |
| 说英语放在哪 | 乒乓球从业者的方法 | 说英语接口 |

**接口上面的这种思路（思路二）会更简洁一些。** 所以我们在写代码的时候，就按这种方式来开始写。

### 把图翻译成代码

在 IDEA 里新建一个包，写代码的顺序是**从上往下**：先写父类，再写子类。

#### 人：顶层的 Person

```java
public abstract class Person {
    private String name;
    private int age;

    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public int getAge() {
        return age;
    }

    public void setAge(int age) {
        this.age = age;
    }
}
```

> **提示**：针对每一个私有化的成员变量，都要提供其对应的 get 和 set 方法。在 IDEA 里可以直接 `Alt + A` 全选，再回车一键生成。

#### 角色：Sporter 与 Coach

```java
public abstract class Sporter extends Person {

    public Sporter() {
    }

    public Sporter(String name, int age) {
        super(name, age);
    }

    public abstract void study();
}
```

为什么要写成抽象的？因为下面的运动员学的内容是不一样的：乒乓球运动员学的是打乒乓球，篮球运动员学的是打篮球，**方法体不一样**，那就可以把 `study()` 定义成抽象方法。

> **结论**：抽象方法所在的类必须是抽象类。上面空参构造和带全部参数的构造，都要写上。

`Coach` 是一模一样的路子：

```java
public abstract class Coach extends Person {

    public Coach() {
    }

    public Coach(String name, int age) {
        super(name, age);
    }

    public abstract void teach();
}
```

下面的乒乓球教练跟篮球教练教的东西是不一样的，所以抽取到父类当中，`teach()` 需要是 abstract 的。

#### 能力：说英语接口

```java
public interface English {
    public abstract void speakEnglish();
}
```

#### 四个具体类

```java
public class PingPongSporter extends Sporter implements English {

    public PingPongSporter() {
    }

    public PingPongSporter(String name, int age) {
        super(name, age);
    }

    @Override
    public void study() {
        System.out.println("乒乓球运动员正在学习如何打乒乓球");
    }

    @Override
    public void speakEnglish() {
        System.out.println("乒乓球运动员在说英语");
    }
}
```

写完类声明之后，鼠标点一下红色波浪线，`Alt + 回车` 选第一个（Implement methods），默认全选，点 OK，IDEA 就把所有抽象方法都给你重写好了；`Alt + Insert` 选 Constructor，`Ctrl + A` 全选回车，构造方法也有了。这样创建对象时，用空参或者带全部参数的构造都可以。

四个类的完整关系是这样的：

public class PingPongCoach extends Coach implements English {

### 顺手一刀：顶层的 Person 也该抽象掉

写完之后有一个小细节需要说一下。刚刚我们把 `Coach`、`Sporter` 中间这两个类都定义成 abstract 抽象的了，因为它们里面有抽象方法，抽象方法所在的类必须是抽象类。

那这样一来，我们可以把顶层的 `Person` 也去定义成 abstract。

**为什么要把它写成抽象的？** 因为现在我不想让外界去直接创建 `Person` 的对象——直接创建顶层父类 `Person` 的对象，此时是没有意义的。

```java
public abstract class Person {
    // 抽象掉之后，外界再 new Person() 就直接报错了
}
```

目的就是不让外界去创建 `Person` 的对象。测试类里创建的都是运动员或者教练的对象，这才是有意义的。

### 接口升级，逼出了 JDK8 和 JDK9 的新特性

接口的基本使用到这里就全学完了，接下来看接口在不同版本下的一些特性。

#### 结论先摆出来

先把最终的结论摆出来，一次看全：

| 版本 | 接口里能定义什么 | 格式 |
|---|---|---|
| JDK7 及以前 | 只能写抽象方法 | `public abstract void speak();` |
| JDK8 新增 | 默认方法、静态方法（有了方法体） | `public default void show();` / `public static void show();` |
| JDK9 新增 | 私有方法（普通私有方法、静态私有方法） | `private void check();` / `private static void check();` |

JDK7 以前的接口还比较纯粹，它里面只能写抽象方法，就是我们之前所学的那一套。

到了 JDK8，**为了接口升级时向下兼容**，接口里面就可以定义有方法体的方法了，有方法体的方法分为两种：一个是默认的方法，还有一个是加 `static` 的静态方法。

到了 JDK9，**为了抽取重复的代码**，接口当中又可以定义一种方法，就是私有方法；私有方法也分为两种，一个是私有的普通方法，还有一个是私有的静态方法。

#### 需求变了，实现类却不好改

说到这里我就要好奇了：**为什么 Java 会这么设计呢？它加了这么多的方法，它的作用又是什么呢？**

我们先来看一个问题：所有的软件都不是一下子就能开发到最终效果的。比如小破站在刚开始的时候，它并没有这么多的功能，通过不停的版本迭代、软件的升级，才逐渐地完善的。几乎所有的软件都是这个样子。

现在假设哥们开发的是第一个版本，接口叫 `Inter`，里面有一个方法叫 `method`。接口写完要怎么样？是不是要交给别人去使用啊——所以下面的两个小弟就按照我现在接口定义的规则，重写了 `method` 方法。此时程序写完安稳运行。

那么过了几天——注意，是**过了几天**——需求发生改变了，需要在接口里面再添加新的规则。

这个时候问题就出现了：**当接口中的抽象方法发生变化的时候，受限于语法的要求，实现类就不得不发生改变，否则你的代码就会直接报错，运行都运行不了。**

但是如果这个时候我实现类不方便修改呢？就会非常尴尬：一方面你不改就会报错，而现在我实现了又不方便改。

所以接口自己就琢磨了，说这帮家伙真难伺候，但是现在我又想添加新的规则，又想让他们的代码不报错，那怎么办呢？有没有两全其美的办法？

**是有的，其实只要定义有方法体的方法就可以了。** 所以说 JDK8 和 JDK9 的新特性就是这么出现的。

有了这个新特性，实际开发当中就非常方便了。项目 1.0 版本里定义了接口 `Inter`，有两个类 `InterImplA` 和 `InterImplB` 实现了它，项目上线没有任何问题。但是过了一段时间，项目 2.0 要开发了，功能比 1.0 得多，那我就要在 `Inter` 里面加入十个新的方法——**在接口里面添加新的东西，这就叫做接口升级**。

而升级的时候就可以使用有方法体的方法了。现在就不需要实现类立马进行修改，代码不会报错，等以后你用到了某个规则了，用到了再进行重写就可以了。

### 默认方法

JDK8 以后，接口中允许定义默认方法，需要用关键字 `default` 来修饰。它的作用就是为了在接口升级的时候，代码不报错。

定义非常简单，只要在 `public` 的后面加一个 `default` 关键字就可以了。

```java
public interface InterA {

    public abstract void method1();

    public abstract void method2();

    public default void function() {
        System.out.println("接口A当中新增的默认方法");
    }
}
```

测试类里创建实现类的对象，就能直接调用默认方法：

```java
public class InterImpl implements InterA {
    @Override
    public void method1() {
    }

    @Override
    public void method2() {
    }
}

public class Test {
    public static void main(String[] args) {
        InterImpl ii = new InterImpl();
        ii.function();
    }
}
```

运行结果：

```text
接口A当中新增的默认方法
```

#### 它不是抽象方法，不强制重写

第一个注意点：默认方法它不是抽象方法，它是有方法体的，所以**不会强制要求实现类去重写**。你看上面这个 `InterImpl` 我是不是也没有重写 `function`？代码没报错，而且还能正常地运行。

如果说被重写了，在重写的时候需要注意：**你需要去掉 `default` 关键字。**

```java
public class InterImpl implements InterA {
    @Override
    public void method1() {
    }

    @Override
    public void method2() {
    }

    @Override
    public void function() {
        System.out.println("实现类重写了默认的方法");
    }
}
```

注意看这个 `function` 前面有没有 `default`——没有。如果强行加一个 `default`，反而报错了。所以 `default` 在重写的时候是要去掉的。运行的时候，走的就是重写的方法。

#### public 能省，default 不能省

第二个注意点：`public` 是可以省略的，`default` 是不能省的。

这个其实非常非常好理解，根本就不需要你去记：**因为你写完代码之后，你就会发现能省略的它都是这种灰色的形式，而 `default` 是灰的吗？它不是的，它是高亮显示的。**

那如果我"小手一抖"把它给删掉、省略了呢？你看它就会直接报错，鼠标悬停上去，它会说：

```text
Interface abstract method cannot have a body.
```

抽象方法不能够拥有方法体。你前面什么都不写，虚拟机就认为你当前的这个方法是一个抽象的方法，而抽象方法是不能有方法体的。所以切记，`default` 是不能省略的。

#### 两个接口撞名，必须显式重写

第三个注意点：如果说实现类实现了多个接口，多个接口当中存在**名字相同的默认方法**，那么现在子类就必须要对这个方法进行重写，如果不重写代码就会报错了。

我们把它验证一下。新建一个 `InterB`，同样有一个叫 `function` 的默认方法：

```java
public interface InterB {

    public default void function() {
        System.out.println("接口B当中新增的默认方法");
    }
}
```

然后实现类同时实现这两个接口：

```java
public class InterImpl implements InterA, InterB {
    @Override
    public void method1() {
    }

    @Override
    public void method2() {
    }
}
```

`InterA` 和 `InterB` 里都定义了同名 `function` 默认方法，实现类谁的都没重写——**程序直接报错**。鼠标悬停，提示的意思就是：你当前的 `InterImpl` 这个类实现了 `InterA` 和 `InterB` 这两个接口，但是在这两个接口当中存在了相同名字的默认方法 `function`，你必须要进行重写。

> **提示**：这么长的一串提示看着头大怎么办？其实有办法。把报错选中 `Ctrl + C`，复制到 IDEA 的小风车（AI 插件）里粘贴，做一个简单的描述"程序报错，报错信息如下，请告诉我为什么"，等几秒钟它就给你生成一大段解释。但它叭叭叭说了一大堆，**其根本的原因就是**：我当前的实现类同时从 A 还有 B 里面继承了同名的 `function` 方法，它冲突了。冲突了怎么办？下面有解决方案——在实现类当中显式地去重写这个方法。

```java
public class InterImpl implements InterA, InterB {
    @Override
    public void method1() {
    }

    @Override
    public void method2() {
    }

    @Override
    public void function() {
        System.out.println("重写接口里面的function方法");
    }
}
```

> **总结**：默认方法的格式和注意事项，其实都不需要大家去背。真正需要大家记住的就是格式本身，而下面的注意事项读熟了就行——当以后代码报错了，你知道为什么、知道怎么改，就可以了。

### 静态方法

#### 格式与调用

静态方法需要用 `static` 来修饰，它的定义格式跟之前我们学习的是一模一样的——只不过在 JDK7 以前，它是不能写在接口当中的，从 JDK8 开始就可以写在接口里面了。

```java
public interface Inter {

    public static void method() {
        System.out.println("接口当中的静态方法");
    }
}
```

```java
public class InterImpl implements Inter {
}
```

写完实现类之后你会发现，静态方法它同样是不要求你强制重写的，因为它现在已经有方法体了。

调用的时候有两条要注意：

1. 静态方法**只能通过接口的名字进行调用**，不能通过实现类的类名或者对象的名字来调用；
2. 在书写的时候，`public` 可以省略，`static` 同样的也不能省略。

```java
public class Test {
    public static void main(String[] args) {
        Inter.method();          // 正确
        InterImpl.method();     // 错误，程序都不用运行，直接报错
        InterImpl ii = new InterImpl();
        ii.method();            // 同样直接报错
    }
}
```

运行结果：

```text
接口当中的静态方法
```

#### 为什么 @Override 用不了：虚方法表

那问题来了：既然静态方法不要求重写，如果我偏要重写呢？

我们在实现类里写一个一模一样的 `method`，再加一个 `@Override` 注解——你发现它是不是就直接报错了？提示是 `Static method cannot be annotated with @Override`。

**为什么呀？** 我们之前讲过一个知识点，叫做虚方法表。什么样的方法可以进到虚方法表当中？就是非静态、非 final、非私有的方法，你才能够进到虚方法表里面。

> **结论**：只有虚方法表里面的方法才能够被重写。而方法重写的实际意义，就是替换了虚方法表当中记录的方法的内存地址。现在这个静态方法，你又不在虚方法表里面，我这个时候怎么替换啊？没法替换，所以它不能够被重写。

那如果说你实现类里面也想要有一个 `method` 方法，怎么办？你就把这个 `@Override` 注解去掉，一删反而好了。但这种方式它不叫重写，它叫——你接口（也就是你"干爹"）里面有个方法，我这个类里面恰好也有这个方法，**碰巧了两个方法是一样的而已，这两个方法不构成重写的关系**。

#### 亲爹和干爹的区别

有人说："这不对呀，这跟我之前学的不一样啊。在之前我用对象去调方法的时候，我是可以调父类里面的静态方法的呀。"

来，我们试试。写一个父类 `Fu`，里面有个静态方法：

```java
public class Fu {
    public static void aaa() {
        System.out.println("父类中的静态方法");
    }
}
```

然后让实现类 `extends Fu`，再用对象去调 `aaa()`——你发现它居然是可以的，运行出来就是"父类中的静态方法"。

那这是为什么呢？其实这就说到了**亲爹跟干爹的区别**。我们的虚拟机虽然说不推荐用对象去调用静态方法，但是在语法当中这种写法是 OK 的。如果说你这么去调用的话，它首先会去看你本类当中有没有这个 `aaa` 方法；如果说没有，他会看整个的继承链——看他爹后面的接口，**会看吗？是不会看的**。

所以这就是跟我们之前的区别。

> **结论**：接口当中静态的方法，只能通过接口的名字来进行调用，不能够通过实现类的类名或者对象的名字来进行调用。这个必须记住。

### 私有方法

#### JDK8 的尴尬：抽出来的 check 谁都能调

我们先来看一段代码。假设接口当中定义了两个默认的方法，一个是默认的 `login`，一个是默认的 `register`。

方法一旦有了方法体，有一个问题就无法避免：**多个方法当中有可能会有重复的代码。**

看这两个功能：`login` 是登录，先检查网络是不是畅通，再检查用户名跟密码的格式是不是正确，然后再检查用户名是否存在，最后执行登录的业务逻辑；`register` 是注册，也是先检查网络、检查用户名跟密码的格式、再检查用户名是否存在，如果一切都 OK，再去执行注册的逻辑。

你发现在这两个功能里面，是不是有大量重复的代码呀？

那你说既然有重复的代码，我该怎么办？你不能每次都写一遍吧。按照我们之前所学，我们就要把重复的代码去抽取出来，放到一个单独的方法当中。

**在 JDK8 的时候，它是这么玩的。** 额外再去定义一个 `default` 默认的方法，把重复的代码抽取出来，然后在 `login` 跟 `register` 当中直接调用这个方法就可以了：

```java
public interface Inter {

    public default void login() {
        check();
        System.out.println("登录的业务逻辑");
    }

    public default void register() {
        check();
        System.out.println("注册的业务逻辑");
    }

    public default void check() {
        System.out.println("检查网络是否畅通");
        System.out.println("检查用户名和密码格式");
        System.out.println("检查用户名是否存在");
    }
}
```

但是这种写法会有一个问题：**你抽取出来的这个 `check` 方法，它里面的代码是为本接口服务的，我不需要其他的类来访问。其他类访问这里的 `check` 方法是没有任何意义的。**

来验证一下。新建一个 `InterImpl implements Inter`，对里面的 default 方法不进行重写，在测试类里直接创建对象，然后用对象去调 `check`——**它居然是能调的**，因为它是用 `public` 来修饰的，在所有的地方全都能进行访问。

但你在外界直接调用它是没有意义的。所以 JDK 就在 9 的时候修复了这个 bug，**新增了私有方法**。

#### 普通私有方法

书写格式：前面的修饰符是 `private`，后面直接写返回值类型还有方法名，后面跟小括号大括号，小括号里面是方法的形参，大括号里面就是方法体。

```java
public interface Inter {

    public default void login() {
        check();
        System.out.println("登录的业务逻辑");
    }

    public default void register() {
        check();
        System.out.println("注册的业务逻辑");
    }

    private void check() {
        System.out.println("检查网络是否畅通");
        System.out.println("检查用户名和密码格式");
        System.out.println("检查用户名是否存在");
    }
}
```

现在再回到外界去调用 `check`——**调不到了，代码直接报错**。

> **结论**：接口当中普通私有方法存在的意义，就是为了抽取默认方法当中重复的代码而出现的。

#### 静态私有方法

私有方法还有第二种，叫做静态的私有方法。它的逻辑跟上面是一样的，只不过它是为了抽取**静态方法**当中重复的代码而出现的。

```java
public interface Inter {

    public static void login() {
        check();
        System.out.println("登录的业务逻辑");
    }

    public static void register() {
        check();
        System.out.println("注册的业务逻辑");
    }

    private static void check() {
        System.out.println("检查网络是否畅通");
        System.out.println("检查用户名和密码格式");
        System.out.println("检查用户名是否存在");
    }
}
```

注意，默认方法里**不能**写普通的私有方法去调用，得写成静态的私有方法——其实就是在它的基础上再加一个 `static` 关键字就可以了。

这一块零碎的小点会比较多，我把真正要掌握的压缩成四句话：JDK7 及以前（含 JDK7）接口里只能定义 `abstract` 修饰的抽象方法；到 JDK8，接口里可以定义有方法体的方法，分为 `default` 默认方法和 `static` 静态方法两种；一旦方法有了方法体，就不可避免会出现重复代码，所以在 JDK9 额外有了私有方法，分为普通的私有方法（抽取默认方法中的重复代码）和静态的私有方法（抽取静态方法中的重复代码）。

## 内部类：从汽车与发动机，讲到 `Outer.this.a`

### 累不累：今天最后一个知识点

各位同学，接下来我们来学习今天最后一个知识点。累不累？——"累"是哪两个字？内部类。什么是内部类呢？顾名思义，其实就是一个类的里面，再去定义一个类。

比如说，我可以在 `Outer` 这个类里面，再去定义一个 `Inner`。那么此时 `Outer` 就是外部类，`Inner` 就是内部类。就这么简单，一句话说完。

但是你们先别急着走。内部类为什么会被发明出来？它在什么场景下出现？咱们来看一个需求。

### 汽车和发动机：一个改了两遍的需求

需求是这样的：如果要写一个类去描述汽车，它的属性有——汽车的品牌、车龄、颜色，还有发动机的品牌，以及发动机的使用年限。

按照我们以前所学，你觉得该怎么写？想都不用想，哥们肯定要定义一个 `Car`，然后在里面去定义属性：汽车的品牌、汽车的车龄、汽车的颜色，还有发动机的品牌，以及发动机的使用年限。

```java
public class Car {
    // 汽车的品牌
    String carBrand;
    // 汽车的车龄
    int carAge;
    // 汽车的颜色
    String carColor;
    // 发动机的品牌
    String engineBrand;
    // 发动机的使用年限
    int engineUseYears;
}
```

写完之后，屏幕前的兄弟姐妹们，大家来说：你觉得这种写法好吗？

乍看上去好像没有什么太大问题，但是你品，你细品。这里的发动机，它是一个独立的个体，其实跟车本身还是有一定区别的。所以发动机的相关属性，我们不应该跟车的属性定义在一起。

那该怎么办呢？有同学想：这简单啊，再去定义一个发动机的类 `Engine`，这不就 OK 了吗？

是的，你说得没错，**但是这还不够**。因为发动机它是需要依赖车才能存在的，发动机单独出现，其实呢是没有什么实际意义的。

所以最好的解决方案，就是把 `Engine` 这个类，去定义在 `Car` 这个类的里面。这样就可以满足要求了：表示车里面有发动机，同时发动机又是一个独立的个体。那么此时 `Car` 就是外部类，而 `Engine` 就是内部类。

> **结论**：我们在定义内部类的时候，一般会遵守这样的规则——内部类表示的事物，它是外部类中的一部分；而且更重要的是，内部类单独存在是没有什么实际意义的，它需要依赖外部类才能存在。

这两条不是所有"有点关系"的类都该写成内部类的判据——只有"是别人一部分"且"自己单拎出来没意义"的，才配写在里面。

打开我们心爱的 IDEA，因为是一个新的知识点，哥们又新建了一个新的项目：面向对象 → 内部类。内部类题目的需求我也粘贴过来了。

```java
public class Car {
    // 汽车的品牌
    String carBrand;
    // 汽车的车龄
    int carAge;
    // 汽车的颜色
    String carColor;

    // 发动机：属于汽车的一部分，单独存在没有意义
    class Engine {
        // 发动机的品牌
        String engineBrand;
        // 发动机的使用年限
        int engineUseYears;
    }
}
```

代码的细节我不多说，你们写的时候注意两点：一是属性名跟注释要对得上；二是新建完类之后，IDEA 的 AI 会自动把注释里描述的属性给你补齐——你看它自动生成 `carAge`、`carColor`，还会顺手给你加一个 `run` 方法，那个 `run` 目前为止没有什么用，直接删掉就行。

这个知识点我们就先学习到这里。

### 内部类一共四种，今天只死磕一种

在刚刚咱们已经初步了解了一下什么是内部类，那么接下来我们就系统地学习一下。

内部类一共分为以下的四种：

| 分类 | 写在哪里、怎么写 | 今天要掌握吗 |
| --- | --- | --- |
| 成员内部类 | 写在成员位置（类中方法外），不加 `static` | 是，重点讲 |
| 静态内部类 | 写在成员位置，加 `static` 修饰 | 混个眼熟 |
| 局部内部类 | 写在方法里面 | 混个眼熟 |
| 匿名内部类 | 没有名字的内部类 | 必须认真听 |

其中前三种其实没有什么用，我们自己呢一般也不会单独地去书写，所以前三个知识点，大家混个眼熟，这就可以了。

但是最后一个匿名内部类，它非常的重要。**匿名内部类它是 lambda 表达式的前提，而 lambda 表达式又是方法引用的前提。** 一环扣一环，如果其中有一个听不懂，后面的全废。

所以说呢，大家在一会儿只要把最后一个匿名内部类认真地听，这就可以了，前三个就无所谓啦。

### 成员内部类：跟成员变量一个地位

好，接下来我们先来学习第一个，成员内部类。

成员内部类它是写在成员位置的，也就是写在**类中方法外**，它属于外部类的成员之一。比如说我们刚刚所书写的代码，其中 `Car` 就是外部类，而 `Engine` 发动机就是成员内部类。

这里的成员内部类，其实它跟外部类的成员变量、成员方法的地位是一样的。所以成员内部类也可以被一些修饰符所修饰。

#### 五种修饰符，五种可见范围

`private` 私有、默认、`protected` 受保护的、`public` 公共的，还有 `static` 静态关键字。

先说 `private`。如果说成员内部类被 `private` 私有的修饰，那么此时如果你想在外面的测试类当中直接创建成员内部类的对象，这是不行的，因为它已经私有了。

这是为什么呀？因为你要想，如果哥们现在把上面的成员变量 `name`、`age`、`color` 也加上 `private` 私有，那你说我在外面是不是也不能够直接去访问它呀？是这样的。所以私有修饰的成员内部类一个道理，你也不能在外面直接创建它的对象。

那如果说你此时想要创建私有成员内部类的对象，该怎么办？那此时你只能在本类，也就是外部类 `Car` 这个里面去创建对象。私有修饰了，我只能在本类当中使用。

那如果我在定义成员内部类的前面，我什么都不写，那此时跟上面的成员变量是一样的，相当于那就是默认的权限。此时我只能在同一个包当中去创建成员内部类的对象；如果我是在其他的包里面，想要创建成员内部类的对象，这就不行了。

那如果说我被 `protected` 受保护来修饰，那你还记得它的作用范围是什么吗？屏幕前的兄弟姐妹们，你还记不记得？可以打在弹幕当中告诉我。

> **定义**：`protected` 的作用范围是——我在本包里面可以使用它，我在其他包的子类当中也可以使用它。你回答对了吗？

还有一个，如果说我被 `public` 公共的修饰了，那这个作用范围就非常的大了，我在所有的地方都可以去创建成员内部类的对象。

至于 `static`，如果说成员内部类被 `static` 静态关键字修饰，那么它就变成了静态内部类，这个我们一会儿会单独地去说。

| 修饰符 | 能不能在外部直接创建成员内部类的对象 |
| --- | --- |
| `private` | 不能，只能在外部类本类里创建 |
| 默认 | 只能在同一个包中创建 |
| `protected` | 本包中 + 其他包的子类中 |
| `public` | 所有地方都行 |
| `static` | 此时它就不算成员内部类了，叫静态内部类 |

#### JDK16 之前，内部类里连静态变量都不许写

在成员内部类里面，**JDK16 以前是不能够定义静态变量的**，但是到了 JDK16 开始，我们就可以定义静态变量了。那么现在我们使用的是最新版本，所以此时我们是可以在成员内部类当中去定义静态变量的。

当然，这个结论是可以验证的。在成员内部类当中我们定义一个 `static int a`，你发现没有任何问题，因为我们用的版本比 16 要高。那怎么去调节这个版本呢？

注意了，铁子们。我们可以点击左上角的 `File`，先点击 `File`，然后再点击这个叫做 `Project Structure`（项目结构）。在这里呢，先点 `Project`，然后在右边的界面当中，它就可以去切换版本。

### 怎么 new 出成员内部类的对象

知道了成员内部类的细节之后，再一会儿我们还会继续往下去学习如何创建成员内部类的对象，它的这个格式稍微有点怪异。这个不着急，我们一会儿会详细地拆解去讲解。

打开我们心爱的 IDEA，我已经新建好了一个包 `a02`，测试类也新建好了。接下来给大家演示刚刚所学习的两部分内容：第一，编写成员内部类的时候要注意哪些；第二，如何去获取成员内部类的对象。

先新建一个外部类 `Outer`，在 `Outer` 类当中我要再写一个 `class Inner`，这个就是内部类。

#### 从 `new Student()` 一步步推过去

我们先讲一个最基本的创建对象的方式。这个东西呢虽然说相对来讲比较难，但是它是最基本的。那首先我们要来回顾一下，在以前我们创建对象的方式是什么样的？还记得吧？`类名 对象名 = new 类名()`，小括号、分号。你还记得这个格式吗？`Student s = new Student()`，这个格式应该写得很熟了才对。

那接下来我们就一起来推导一下。

一开始在这，你要想到我要创建的是**谁**的对象？谁的对象？内部类的对象啊，对吧。内部类叫什么？那就叫做 `Inner`。

那在之前我们又说了，`Inner` 它单独存在是没有意义的，所以我们还给它加一个 `Outer` 类的标识，前面加上一个 `Outer` 点。那么 `Outer.Inner`，这就表示我现在呢创建的这个对象是 `Outer` 这个外部类当中的 `Inner` 这个内部类的对象。这就是**等号左边的类名**，这个类名呢我们也叫数据类型。

```java
Outer.Inner oi = new Outer().new Inner();
```

那么后面呢我们再去写一个名字，`oi`。这个很简单，相当于呢我在创建对象的时候，你要不要去起一个变量，用来记录对象的地址值啊？那肯定要，对不对呀，所以说呢在这里我可以叫做 `oi`。当然呢你可以写成 `abc`、`bcd`，也是没有任何毛病的。

那么接下来继续，**等号的右边**是什么意思呢？你要来想啊，如果说看这里我在 `Outer` 类当中有一个 `String name`，那你告诉我这一个 `name` 你该怎么调用？是不是首先要先去 `new` 一个 `Outer`，也就是创建一个 `Outer` 类的对象，然后再把这个对象的地址值去赋值给一个变量，变量的类型就是 `Outer`，起个名字，那就是 `o`，再用这个 `o` 去调用 `name`。在以前我们是不是这么干的呀？是的。

那么获取完了之后，我把这个 `name` 的值做一个打印。但是你有没有想过，这个 `o` 如果说我不写，那我能不能这么干呢？直接用对象点上的 `name`。可不可以？完全可以啊，这就是我们之前所讲的链式编程，让我们去少定一个变量了。这也是完全 OK 的。

那为什么这么写？你要想，因为 `name` 是一个成员变量，想要调用只能通过对象去调用，这就是我们调用 `name` 的方式。

> **结论**：成员内部类的地位跟成员变量、成员方法一模一样，所以它也必须用外部类的对象去调用。推导 `Outer.Inner oi = new Outer().new Inner();` 的过程，与推导"访问 `Outer` 里的成员变量 `name`"的过程，是同构的。

把这个注释打开，通过这种方式呢我们就能获取到成员内部类的对象。其中**等号的右边非常的难以理解**，但是呢我们可以把它分成两部分：左边 `new Outer()` 的这一部分，你可以把它理解成是**外部类的对象**，他是一个调用者，调谁就用来调用后面成员内部类的对象；右边 `.new Inner()` 就是获取到的内部类对象，再把对象的地址值赋值给变量 `oi`。

知道了获取对象的方式之后，接下来我们再反过来去研究上面的这些细节，就非常的轻松了。

#### private 之后：两种拿对象的办法

首先我们一起来看，成员内部类它是可以被一些修饰符所修饰的，比如说 `private` 私有。

各位铁子，我用 `private` 私有去修饰成员内部类 `Inner`，那么你看在外界还能获取吗？还能获取吗？获取不了啦，是不是报红报错了呀？我们可以用鼠标点一下红色，Alt 加回车，在这里你会看到 IDEA 就会给我们一些解决方案，其中最简单的一个解决方案我相信大家都能看得懂——最后一个 `make Inner public`，它是不是让你把这个 `Inner` 内部类变成 `public` 就可以了？

那么此时呢我们就知道了第一点：成员内部类它呢是可以用 `private` 私有来修饰的，一旦私有了，那么在外界就不能直接创建它的对象。

那如果说我现在就是想要获取成员内部类的对象，有没有办法呢？有。在这里你会看到，我们可以在外部类去编写方法，对外提供内部类的对象。

```java
public class Outer {
    private class Inner {
    }

    public Inner getInstance() {
        return new Inner();
    }
}
```

那么在外界呢，我们就不需要直接创建了，怎么办？是不是可以创建外部类的对象 `Outer o = new Outer()`，然后呢用 `o` 去调用 `getInstance` 就可以了呀。这样就可以获取到内部类的对象了。

那么在等号的左边呢，其实还有一个小细节，我们一起来看。如果说你的类型还是写 `Outer.Inner` 的话，那么代码它就报错。为什么呀？因为现在你要想，`Inner` 它是不是一个私有的呀？那在外界它根本就不知道 `Outer` 里面有这个 `Inner`，所以说我们不能直接这么去表示。

那怎么去写呢？有两种方式。第一个，你可以用 `Inner` 的父类类型形成一个多态。那 `Inner` 它爹是谁？在这儿它没有 `extends`，没有 `extends` 就默认继承 `Object`，所以说呢我们可以用 `Object` 去进行接收。

```java
Outer o = new Outer();
Object oi = o.getInstance();   // 用父类类型接收，形成多态
```

第二种方式就是，等号的左边你不要去用变量接了，在这里我就直接使用这个方法获取到的对象就可以了，这也是可以的。

右键运行，我们来看一下结果：程序运行完毕，你看 `Outer` 这个类里面的 `Inner` 它是不是打印出来了？打印出来的是一个对象的地址值。

而且你看这里这里呢还有一个小细节，就是在我们的 Java 当中，内部类它在表示类型的时候，在 Java 的底层它是通过这种 `$` 的形式进行区分的：`$` 左边它是外部类的类名，`$` 的右边它是不是内部类的类名。

> **易错点**：起名字的时候，你最好不要去用下划线，也不要去用这个美元符 `$`。因为下划线它是给常量用的，而这里的 `$` 符它是给内部类去用的。Java 底层就是靠 `$` 来区分外部类名和内部类名，你自己起名的时候离它远一点，省得跟编译器生成的类名撞车。

上面这些就是关于第一个小细节。回顾一下，在编写成员内部类的时候，如果说成员内部类用 `private` 私有的去修饰，那么在外界我们是不能直接创建 `Inner` 的对象的。如果说你直接创建，看这里它是不是就会报错？怎么办？两种解决方案：第一，你就把权限修饰符去改一改，不要用 `private`，用 `public` 修饰；第二种方式就是，我在外部类当中提供一个方法，方法当中返回内部类的对象，在外界我就直接通过方法去获取内部类的对象就可以了。

剩下的几种修饰符咱们也快速验证一下。把 `private` 删掉什么都不写，它就是默认权限，默认权限修饰符在本包当中——看右边这个测试类呢，跟 `Outer` 它是在同一个包里面的，所以说我能直接用没有任何问题。但是如果说我在不同的包当中，我在这儿再来新建一个包 `test`，在 `test` 包里面再去新建一个 `Test` 类，写一个 `psvm`，你看我是不是就没有办法进行创建了呀？看这他报错了。我们可以把这个 `test` 也 delete 删掉，知道这个小细节就可以了，不需要去记。

`protected` 受保护的：一旦用受保护的去修饰，那么只能在本包，还有其他包的子类里面能用。`public` 就很简单了，公共的，在所有的地方是不是都可以直接创建内部类的对象啊？

#### 真实工程里的写法：`ArrayList` 的 `ITR`

那么这两种拿对象的方式，在什么时候用哪个呢？

第一个，在外部类当中编写方法、对外提供内部类的对象——这种方式呢其实并不是所有的时候都用的。一般来讲，我们是用在 `private` 去修饰内部类的时候，我们就会用第一种方式来获取内部类的对象。但是如果说你的内部类没有用私有，你用的是其他的修饰符去修饰的，那么一般我们会用第二种方式去获取它的对象。

这个知识点呢在以后我们也是会用到的。我们也可以来看一下之前带着大家看的那个 `ArrayList` 的源码：用鼠标点进去，注意了，我们要看 `java.util` 包下的。在这儿按 `Ctrl + F12`，找到这个 `ITR` 内部类。

那么在以后我们学习集合的高级遍历方式——迭代器的时候，你说我是不是要获取到这个迭代器的对象啊？是的。但是你发现了这个内部类它用什么修饰了吗？那我在外界如何获取到这个迭代器的对象呢？

你要想，刚刚我们是不是讲过一个办法——我们可以在外部类当中提供一个方法，对外提供内部类的对象。那你说 Java 有没有提供呢？看这里，就在它的上面有一个叫 `iterator()` 的方法，它是不是 `return` 了一个内部类的对象？

那么它返回的类型你来看，不是这个 `ITR` 的类型，而是 `ITR implements` 实现的接口的类型。所以说呢在外界你就用这个接口的类型去接收就可以了，相当于就形成了我们刚刚所讲的**多态**的形式。

```java
public Iterator<E> iterator() {
    return new ITR();   // 返回的是接口类型，不是内部类类型
}
```

好，那么这个呢就是关于成员内部类的一个应用场景。

### 三个 a 都叫 a：内部类怎么拿外部类的成员变量

到目前为止，我们已经把前面的两个小点都已经讲解完毕了：我们知道在成员内部类当中代码该怎么写以及书写代码的细节；第二，我们也知道如何去获取成员内部类的对象了。

那么接下来呢我们再来看最后一个：成员内部类如何获取外部类的成员变量。在这呢我通过一个小案例的形式，带着大家一起去分析。

#### 先按就近原则试一遍

在外部类当中，我有一个成员变量 `a`，记录的值是 `10`；内部类当中也有一个 `a`，是 `20`；内部类里面有一个方法叫做 `show`，方法里面有一个局部变量，名字也是 `a`，记录的是 `30`。那么现在在方法里面它有三个输出语句，现在我想要的是这三个输出语句，它打印的结果分别是 `10`、`20`、`30`。那你说这个括号里面我们该怎么去写呢？

那么这个题目的难点是什么？难点其实呢就在这儿：**局部变量、成员变量，还有外部类的成员变量，这三者之间它是不是有重名了呀。**

如果没有重名，那很简单，你直接打就可以了。你看，现在我局部的 `a`、还有我内部类成员位置的 `a` 都被我注释掉了，那么在方法当中我直接打 `a` 的话，那肯定就是外部类成员的 `a` 咯，这个结果肯定是 `10` 咯，对不对呀？在右边调用一下给你看看——创建内部类的对象，并调用里面的 `show` 方法：

```java
Outer.Inner oi = new Outer().new Inner();   // 要先用外部类的对象去调用，再去点 new
oi.show();
```

程序运行完毕，结果是 `10`，完全没有任何问题对吧。所以说如果在以后没有出现重名的情况，那我直接打就好了。但是现在有重名了，你该怎么打呢？

在之前针对于这种写法，我们曾经讲过一个叫**就近原则**。在方法里如果说我直接写 `a`，注意了，我先直接写 `a`，那么它是怎么找的？它是不是先在本方法里面找啊？是的。所以说我如果直接写 `a`，在这儿它打印的是 `30`。

那如果说我不想在方法里面找，我想直接在本类的成员位置找，我想要打印内部类成员位置的 `a`，我前面得加一个什么来着的？`this` 点 `a`。我们先把这两行代码来运行一下——你会发现 `30`、`20`，搞定了吧？

#### 为什么这里用不了 `super`

那么现在有问题了：外部类第四行的这个 `a` 怎么办？

在上课的时候，有的铁子跟我说：你用 `super` 调不就行了吗。

你要注意了啊，铁子，这个时候 `Inner` 跟 `Outer` 它不是继承关系。继承是什么？继承你是得在后面写 `extends` 才行啊，对不对呀？现在外部类它不是内部类的爹，不是这样的。你要想汽车跟发动机，汽车是发动机的爹吗？不是的；人跟心脏，人是心脏的爹吗？不是的。

**所以说在这里你不能用 `super`，`super` 表示的是父类。**

那怎么办呢？告诉你答案：在这儿我们可以写 `Outer.this.a` 这种方式，获取的就是外部类的成员变量。

```java
public class Outer {
    int a = 10;              // 外部类的成员变量

    class Inner {
        int a = 20;          // 内部类的成员变量

        public void show() {
            int a = 30;      // 局部变量

            System.out.println(Outer.this.a);   // 10 —— 外部类
            System.out.println(this.a);        // 20 —— 内部类
            System.out.println(a);             // 30 —— 局部变量
        }
    }
}
```

右键运行看一下效果，结果是 `10`、`20`、`30`，是不是达到我们想要的效果了呀？

有的人说不对：老师你刚刚在题目当中要求打的是 `10`、`20`、`30`，那你调个个不就得了吗。对呀。那么现在关键点是什么？`Outer.this.a` 哥们看不懂，哥们不知道啊。

在很多课程当中，会把它当做一个固定格式跟大家讲解，让大家记忆。但是呢我呢，不喜欢这样。我要跟大家去讲解这个东西，它到底是怎么一回事。

#### 内存里到底发生了什么

先来看一下代码，这就是我们刚刚在 IDEA 当中自己书写的：在这儿我写了一个外部类 `Outer`，内部类 `Inner`，内部类当中有一个 `show` 方法，在这儿局部位置有一个变量 `a`，内部类的成员位置有一个变量 `a`，外部类的成员位置也有一个变量 `a`。那么在 `show` 方法当中，我就用三种方式去调用了这里的 `a`。在下面还有测试类，测试类当中创建内部类的对象，并用对象去调用 `show` 方法。

那么接下来我们就一起来看，在内存当中这个过程到底是什么样的。

首先一开始，还是 `Test` 它的字节码文件加载到内存，然后虚拟机呢会自动地调用 `main` 方法，`main` 方法会加载到栈，开始执行 `main` 方法里面的第一行代码。那这个时候发现第一行代码里面，是不是用到了 `Outer` 也用到了 `Inner` 啊？所以说就会把外部类还有内部类的字节码文件加载到内存当中。

在这儿我们要注意：**外部类还有内部类在内存当中呢，是两个独立的字节码文件。** 那如果你不相信呢，我可以先带着你去看一看：右键点击它，这里有一个 `Open In`，再选择 `Explorer` 打开本地的 Java 文件。在这呢我们要找到 `out` 文件夹，因为所有的字节码文件都在 `out` 文件夹当中。双击打开 `production`，再找到当前的模块，点进去，找到这里的 `a03demo3`——你看外部类 `Outer`，内部类是不是有 `Outer$Inner`？在编译之后，它是不是两个互相独立的字节码文件？

回到正题：`Outer.class` 还有 `Outer$Inner.class` 都已经加载到内存，那么接下来呢我们就要真正地执行这一行代码：

```java
Outer.Inner oi = new Outer().new Inner();
```

先来看**等号的左边**。左边相当于呢就是一个变量，变量名字叫 `oi`，变量的类型就是 `Outer.Inner`——那就表示在这个变量当中，以后能记录 `Outer` 里面 `Inner` 这一个对象的地址值。

然后呢再来看**等号的右边**。等号的右边呢，它一共是有两个部分。

**第一部分就是 `new Outer()`。** 你看到 `new` 关键字了，那现在哥们 new 的是谁啊？是不是 new 的外部类的对象啊？所以说在堆内存当中，它会创建一个外部类的对象，在这个对象里面它会记录成员变量的值，`a` 里面的值呢就是 `10`，因为在外部类当中成员变量所记录的值就是 `10`。第一部分执行完毕了。

**再来看第二部分。** 第二部分又是 `new`，所以说它在堆里面会再次开辟一个空间，而这个空间注意了，就是内部类的对象。那么在内部类的对象当中，它是不是也要存储成员变量的信息啊？是的，所以说有一个 `int a = 20`。

还没完，铁子。与此同时，Java 还会给内部类的对象去加一个**隐藏的成员变量**，这个 `this` 它就用来记录外部类对象的地址值。注意了，内部类的对象里面有一个这么隐藏的 `this$0` 在。

那你说这个时候我对象创建完毕了，是不是要把这个对象的地址去赋值给左边的变量 `oi`？那你猜，你觉得是把 `001` 赋过去，还是把 `002` 赋过去？告诉我，你可以把你认为正确的答案打在弹幕当中。给你五秒钟的时间自己思考。

时间到，正确答案是 `002`。为什么是 `002`？你要想，如果说我在这里记的是 `001` 的话，那么这里的类型就不应该这么写，类型你就直接写 `Outer` 就可以了，那就表示它记录的是外部类的地址值。但是我们现在写的是 `Outer.Inner`，那就表示现在 `oi` 记录的是内部类的地址值。

```text
堆内存
┌────────────────┐      ┌───────────────────────────────────────────┐
│ 001: Outer     │      │ 002: Inner                               │
│                │◀─────│                                           │
│   int a = 10   │      │   int a = 20                              │
│                │      │   final Outer this$0 ── 记录 001 的地址    │
└────────────────┘      └───────────────────────────────────────────┘

栈内存
┌───────────────────────────────────────────────────────────────┐
│ main()                                                         │
│   Outer.Inner oi = 002         // 只记内部类对象的地址         │
├───────────────────────────────────────────────────────────────┤
│ show()   this = 002             // 方法的调用者是 oi           │
│   int a = 30                    // 局部变量                    │
└───────────────────────────────────────────────────────────────┘
```

到目前为止，第一行代码才算是执行完毕。接下来再来走第二行，用 `oi` 去调用 `show` 方法。那这个时候呢 `show` 方法就会被加载到栈当中。我们说方法它是有调用者的，那么现在你来看 `show` 方法是谁调的？它是不是 `oi` 调的？所以说这里的 `this` 记录的就是调用者的地址值，`002`。

再往下，方法里面我定义了一个局部变量 `a`，它记录 `30`，所以说呢这个 `a` 就是在 `show` 方法当中的。

再来看这个里面的输出语句。我们先说最简单的，我直接输出 `a`，它呢会触发就近原则，先到本方法里面找，找到了吧？找到了，找到了。所以说直接打印 `a` 它就是 `30`。

那么再往下，我打印 `this.a`，那么 `this` 是什么？`this` 是记录调用者的地址值，当前这个方法它是 `002` 调用的，所以说这句话我们就可以把它理解成：我要打印 `002` 里面的 `a`。那 `002` 是谁啊？是不是找到了右边内部类的这个对象啊？所以说他打印的结果就是 `20`。

那么再来第三行，最后我打印的是 `Outer.this.a`，那要注意前面有一个 `Outer` 作为前缀。那这个时候他在找的时候，就不会找自己这个里面的 `20` 了，他是会找谁？会先找自己这个里面的 `this`，找我的外部类对象是谁呀。好，外部类对象找到了，就是左边的 `001`。那这个时候再去打印 `001` 这个里面的 `a`，所以说打印的结果呢就是 `10`。

> **结论**：在整个内存当中，跟以前不一样的是什么？内部类对象里面有一个隐藏的 `this`，用来记录外部类对象的地址值——就是这一点不一样。

第四个问题，**当外部类的成员变量和内部类的成员变量重名的时候，我在内部类当中如何访问**——那就是 `Outer.this` 再点变量名，这种方式呢它可以直接获取到外部类的成员变量。

解析：发动机的两个属性描述的是一个**独立的个体**，不能和平级地塞进 `Car` 里；但发动机脱离汽车又**没有实际意义**，所以只能把它定义成 `Car` 的内部类。

#### 三个 `a` 都叫 `a`

题干：外部类的成员变量 `a` 记 `10`，内部类的成员变量 `a` 记 `20`，内部类中 `show` 方法内的局部变量 `a` 记 `30`。请在 `show` 方法里写三行输出语句，使它们依次打印出 `10`、`20`、`30`。

解析：

- 直接写 `a` 会触发**就近原则**，先在本方法（局部变量）里找，拿到 `30`；
- 想要内部类的成员变量，需要跳过局部作用域一层，用 `this.a` 拿到 `20`；
- 想要外部类的成员变量，用 `Outer.this.a`。这里**不能用 `super`**——`Inner` 与 `Outer` 之间是包含关系而非继承关系，继承必须写 `extends`；汽车不是发动机的爹，人也不是心脏的爹。

答案：

```java
public class Outer {
    int a = 10;

    class Inner {
        int a = 20;

        public void show() {
            int a = 30;

            System.out.println(Outer.this.a);   // 10
            System.out.println(this.a);        // 20
            System.out.println(a);             // 30
        }
    }
}
```

调用与输出：

```java
Outer.Inner oi = new Outer().new Inner();
oi.show();
// 10
// 20
// 30
```

关键机制：`Inner` 的对象里被虚拟机自动加了一个 `final Outer this$0`，专门记录外部类对象的地址值——`Outer.this` 走的就是这条路。

## 三种内部类：加个 static、藏进方法里、干脆不要名字
> 对应块：BLK36 | 覆盖分集：P123-P124 | 块标题（分集名）：《第11章-面向对象高级-20-静态内部类和匿名内》

成员内部类学完了，接下来我们往下走。第二种内部类，叫静态内部类。说白了它一点都不神秘——成员内部类前面加上 `static` 关键字，它就叫静态内部类了。

真正让人挠头的不是这个定义，而是紧跟着它的两条注意事项，以及这一讲最后那个重头戏：匿名内部类。放心，后面那个才是真正要命的，前面这两个好懂得多。

### 静态内部类：给成员内部类加一个 static

#### 它就是加了 static 的成员内部类

这句话特别好理解。你想，如果这个 `static` 不写，它是不是就是我们刚刚学过的那个成员内部类了？是的。所以静态内部类本身就是成员内部类的一种，前提就一个：前面有 `static`。

在 IDEA 里长什么样呢？外部类叫 `Outer`，里面写了一个内部类叫 `Inner`，然后用 `static` 去修饰它——这个 `Inner` 就是我们现在要说的静态内部类。

#### 只能访问外部类里静态的东西

写静态内部类之前，先记住它的第一条注意事项：

> **易错点**：静态内部类当中，只能访问外部类中的静态变量和静态方法。

光记结论没劲，我们往前倒一步问一句——**为什么**？

其实跟我们之前学过的内容是一模一样的。现在先别管内部类，就看这样一个类：类名叫 `Car`，里面有一个静态方法 `show`。

请问，在这个静态方法 `show` 里面，我能不能访问 `Car` 的成员变量 `carName`、`carAge`？不能。因为之前就学过的规则摆在那儿：**静态只能访问静态**。

那如果我非要访问 `carName` 怎么办？只有一个办法——在 `show` 方法里面先去创建一个 `Car` 对象，用这个对象去访问。

现在把这个结论原封不动地搬到静态内部类里面，规则一点没变：

```text
外部类 Outer
├── int a = 10;                 非静态成员变量
├── static int b = 20;          静态成员变量
│
└── static class Inner          静态内部类
    ├── public void show()
    │       System.out.println(b);   ->  可以，b 是静态的
    │       System.out.println(a);   ->  报错，a 是非静态的
    │
    └── public static void show2()
            System.out.println(b);   ->  可以
            System.out.println(a);   ->  一样报错
```

而在静态内部类的某个方法里，如果想访问非静态的 `a`，就必须先创建外部类的对象，再用对象去访问：

```java
class Outer {
    int a = 10;
    static int b = 20;

    static class Inner {
        public void show() {
            System.out.println(b);   // 静态变量，直接访问，OK

            // System.out.println(a);   // 非静态变量，直接访问，编译报错

            // 想访问 a，就得先造一个外部类的对象出来
            Outer outer = new Outer();
            System.out.println(outer.a);   // 这样才可以
        }

        public static void show2() {
            System.out.println(b);        // 静态方法里访问静态变量，一样可以
            // System.out.println(a);     // 静态方法里访问非静态变量，照样报错
        }
    }
}
```

> **结论**："静态只能访问静态"这条规矩，在静态内部类身上一点没打折。你在外部类的静态方法里怎么写的，在静态内部类里就怎么写。

#### 怎么创建对象、怎么调用方法

接下来要动手了：怎么创建静态内部类的对象，怎么调用它里面的方法。这里你只要死死抓住一个核心，所有代码就都能想出来了：

> **结论**：只要是静态的东西，都可以用「类名 + 点」直接拿到。

所以创建静态内部类的对象，等号左边写 `Outer.Inner oi`，前面这一段表示的是**类型**，就相当于给对象起了个名字。

等号右边稍微绕一点，一定要注意：

> **易错点**：`new` 的**不是** `Outer` 这个对象，`new` 的是 **`Outer` 里面那个 `Inner` 类的对象**。

也就是说，`new` 关键字和 `Inner` 发生关系，整句话是「用外部类的名字直接点进去，拿到里面的 `Inner`」：

```java
class InnerClassDemo4 {
    public static void main(String[] args) {
        // 创建静态内部类的对象
        Outer.Inner oi = new Outer.Inner();

        // 调用里面的非静态方法：必须先有对象，再用对象去调
        oi.show();

        // 调用里面的静态方法：不需要创建对象，类名一路点到底
        Outer.Inner.show2();
    }
}
```

有了对象之后调非静态方法，这一步很自然：既然是对象，那当然用对象去调。

那调静态方法呢？我用 `oi` 这个对象能不能调？**能**，运行时不会出错。但是你要注意——用对象去调静态方法的时候，IDEA **是不给你提示的**。因为静态的东西虽然用对象也能调，但在 Java 里是不提倡这么干的，所以 IDEA 直接不提示你。你强行写了也不会报错，这点要清楚。

正确的调法是直接用类名一路点到底：

```java
Outer.Inner.show2();
```

跑一下，`show()` 和 `show2()` 的打印就都出来了。

关于静态内部类，我们只要掌握这么三个小问题就够了：

- **它是什么**：一种特殊的成员内部类，前面用 `static` 修饰；
- **怎么创建对象**：`Outer.Inner oi = new Outer.Inner();`，左边是类型，右边 `new` 的是 `Inner`，不是 `Outer`；
- **怎么调方法**：非静态方法用对象调，静态方法用类名直接调，不用创建对象。

大家可以先暂停一下视频，把静态内部类自己整理一遍。

### 局部内部类：定义在方法里面的内部类

#### 它的地位，和局部变量一模一样

局部内部类就是把内部类定义在方法里面，这样定义出来的类就叫局部内部类。它的地位呢，**类似于方法里面的局部变量**——你把它理解成局部变量，很多事情就都通了。

先说最基本的一点：既然要写局部内部类，那前提是你得先定义一个方法。没有方法，你压根就没地方去写它。

在方法里面直接写 `class Inner { }`，这个 `Inner` 就是局部内部类。它和刚才的静态内部类写法上只差一个 `static`，但性质上已经完全不同了。

修饰符的规则，跟着局部变量走：

> **结论**：**能**修饰局部变量的，**都可以**用来修饰局部内部类；**不能**修饰局部变量的，**就一定不能**修饰局部内部类。

拿两个例子对一下就明白了。`final` 能不能修饰局部变量？能，修饰完这个局部变量就变成常量了。那同理，`final` 也能修饰局部内部类。

那 `public` 呢？`public`、`protected`、默认访问权限、还有 `private`——这几个都是**只能修饰成员**的，局部变量是接受不了它们的。所以你要是把 `public` 写在局部内部类的前面，它一样会报错。

一句话总结：**局部内部类跟局部变量是一路货**，谁行谁不行，完全对得上。

#### 外界用不了它，得回方法里去造

第二条注意事项：外界是无法直接使用局部内部类的。

这句话怎么理解？如果你暂时不理解，我换一个方式跟你说。在外界，比如在测试类当中，它无法直接使用 `show` 方法里面的**局部变量 `a`**。这句话你认可吧？

为什么？因为我们现在 `Outer o = new Outer();` 拿到的是一个对象，然后用 `o` 去访问 `a`——这里的 `a` 表示的是**成员变量 `a`**，它并不能表示局部变量 `a`。在外界，我没有办法直接使用方法里的局部变量。

顺着这个逻辑往下走一步就通了：**既然外界不能直接使用这里的方法局部变量，那外界也不能直接使用这里定义在方法里的局部内部类 `Inner`**。

那你要用怎么办？只有一个办法：**需要在方法里面创建局部内部类的对象**，才能用。

```java
class Outer {
    public void show() {
        int a = 10;

        class Inner {                       // 局部内部类：写在方法里面
            String name;
            int h;

            public void method1() {
                System.out.println("局部内部类中的method1方法");
            }

            public static void method2() {
                System.out.println("局部内部类中的method2静态方法");
            }
        }

        // 只能在方法里面创建局部内部类的对象
        Inner i = new Inner();

        // 有了对象，就能访问里面所有的成员
        System.out.println(i.name);         // 默认值 null
        System.out.println(i.h);            // int 类型，默认值 0

        i.method1();                        // 非静态方法，用对象调
        Inner.method2();                    // 静态方法，用类名调
    }
}
```

测试类里怎么让它跑起来呢？很简单，就是创建 `Outer` 对象，然后用 `o` 去调 `show()`：

```java
class InnerClassDemo5 {
    public static void main(String[] args) {
        Outer o = new Outer();
        o.show();
    }
}
```

运行结果里，`name` 打印出来是 `null`——`String` 的默认值；`h` 打印出来是 `0`——`int` 类型的默认初始化值零。接着 `i.method1()` 的打印出来了，静态方法 `Inner.method2()` 里面的代码也执行了。整条链路就是这么跑通的。

#### 它能访问什么：外部类成员 + 方法里的局部变量

第三条：局部内部类可以直接访问外部类的成员，也可以访问方法里面的局部变量。

这个很好理解。如果 `Outer` 里有一个成员变量 `int b = 20`，那么在局部内部类的方法当中，我就可以直接拿到 `b` 并打印出来。前面那个方法里的局部变量 `a`，我在局部内部类里同样能直接拿到。

你回头看上面那段代码，其实已经把这件事演示完了：方法一进来先定义 `int a = 10;`，紧接着定义的 `Inner` 里，`method1` 完全可以直接访问它。

局部内部类就这三点——定义在方法里、类似局部变量、外界不能直接用但能访问外部类成员和方法的局部变量。

> **提示**：那这东西到底有什么用？说实话，这东西确实没什么用。了解一下、知道有它的存在就可以了。

我们马上就要学习内部类当中**最最最最最最最重要的匿名内部类**了，你准备好了吗？

### 匿名内部类：不用名字的内部类

#### 先不想它，用传统方式把需求做一遍

什么是匿名内部类呢？其实很好理解，顾名思义——它就是一个**没有名字的内部类**。

在以后的代码当中，如果我在继承一个类，或者实现一个接口的时候，**想要少写一个文件**，在这个时候我就可以用匿名内部类。

先别急着想匿名内不匿名，我们先用传统的方式去完成这个需求，用传统的方式做完，你才能看出它到底省了什么东西。

现在有一个测试类 `Test`，还有一个接口 `Swim`。我的要求是：在测试类的 `main` 方法里面，去调用下面的 `goSwimming()` 方法。那你觉得该怎么做呢？

先看 `goSwimming()` 这个方法，它需要传递一个 `Swim` 类型的参数，而 `Swim` 又是一个接口。所以我们就可以这么认为：**在调用这个方法的时候，需要传递 `Swim` 这个接口的实现类对象**。

于是代码就这样来了：右键 `new Java Class`，新建一个类叫 `Student`，让它 `implements` 实现 `Swim` 这个接口，让学生拥有游泳的功能，然后重写接口里的抽象方法，打印一句「学生正在游泳」。

回到测试类当中，创建学生的对象，把 `s` 传过去：

```java
interface Swim {
    void swim();
}

// Student.java —— 单独的一个 java 文件
class Student implements Swim {
    @Override
    public void swim() {
        System.out.println("学生正在游泳");
    }
}
```

```java
class Test {
    public static void main(String[] args) {
        Student s = new Student();
        goSwimming(s);
    }

    public static void goSwimming(Swim s) {
        s.swim();
    }
}
```

右键运行，「学生正在游泳」这句话就打印出来了。这是我们传统方式的完整操作，我们回顾一下：第一步，新建一个 java 文件，在文件当中再新建一个 `Student` 类，让它去实现 `Swim` 接口，还要重写里面的抽象方法；第二步，在测试类当中创建学生的对象；第三步，再去调用方法。

#### 顺手就能看出一个问题

现在代码写完了，哥们儿发现一个 special 的问题：**如果说这个 `Student` 类我只要用到一次**，那么这个 java 文件你单独再新建出来，是不是感觉有点浪费？

那哥们儿我能不能不新建这个 java 文件，只要里面的代码呢？当然也是可以的。所以，**匿名内部类这就出现了**。

> **结论**：匿名内部类的作用，其实就是**让我们少定义一个 java 文件**而已，仅此而已。

#### 它的格式，以及为什么这么写

匿名内部类的定义格式如下：`new 类名或接口名 ( ) { }`，在大括号当中，我们要去重写类或者接口里面的抽象方法。写出来就是这样：

```java
new Swim() {
    @Override
    public void swim() {
        System.out.println("学生正在游泳");
    }
}
```

看完这个格式之后，很多同学会感觉到有点懵：**你匿名内部类，你不是一个类吗？你怎么会有一个 `new` 关键字呢？**

所以千万不要把它的名字跟这个格式去混淆。匿名内部类这个名字，迷惑性是非常大的。我们把这个格式拆开来看，它其实是由下面这几部分组成的：

```text
        new   Swim    ( )   {  @Override public void swim(){ ... }  }
         ④      ②      ─┬─   └────────────── ① ──────────────────────┘
          │      │      │                   │
          │      │      │                   └─ ③ 在大括号里重写接口/类里的抽象方法
          │      │      └─ 构造方法的括号；接口没有构造方法，这里是空的
          │      └─ ② 继承或实现关系：前面写类名→继承，写接口名→实现
          └─ ④ 创建对象：new 的是后面那个没有名字的类，不是接口本身

        整体理解：一个「没有名字的 java 类」的对象
```

挨个说清楚：

- **① 没有名字的 java 类**，其实就是后面这个**大括号**，是这一堆。为什么又说它是**内部类**呢？因为它写在别的类里面的——外面还有一个 `Test`，我是写在 `Test` 这个类里面的，而它又是一个没有名字的类，所以它才是我们真正要说的匿名内部类。
- **② 继承或者是实现关系**，就是这大括号跟前面 `Swim` 的关系：**这个没有名字的 java 类实现了 `Swim` 接口**。具体是继承还是实现，看你前面写的是什么——前面是类，就是继承关系；前面是接口，就是实现关系。
- **③ 重写方法**。实现接口要不要重写里面的抽象方法？要。所以我们要把 `Swim` 里的抽象方法写在这个大括号当中。而且是**所有**的抽象方法都要重写，不是一个。
- **④ 创建对象**，说的就是前面的这个 `new`。

关于第三点再强调一次，因为它是最容易漏的。假设我这个接口里除了 `swim()`，还有 `aaa()`、`bbb()` 两个额外的抽象方法，那按照我们学的，我必须在这个没有名字的 java 类当中把它们**全部重写**：`swim` 要重写，`aaa` 要重写，`bbb` 也要重写。等你重写完了，上面 `swim` 这个位置的红色波浪线就消失了；只要有一个没重写，它立刻就报红波浪线，告诉你里面还有抽象方法没有被重写。

关于第四点，这是最容易被绕晕的地方，一定要注意：

> **易错点**：这个 `new`，`new` 的**不是** `Swim` 这个接口，它 `new` 的是**后面那个没有名字的类的对象**。

`new` 关键字作用的是后面这个没有名字的 java 类，相当于创建了它的对象。所以整体你就可以这么理解：**我创建了一个 `Swim` 实现类的对象，只不过这个类没有名字而已**。

那等号的右边既然是实现类对象，我把它赋值给接口类型的变量，能不能？当然是能的。这一行代码其实就等同于我们之前写过的 `Swim s = new Student();`——`Student` 也是一个实现类，我把一个实现类的对象赋给接口类型，**这叫什么？这不就是多态吗？**

#### 两种写法，随你挑

因为它整体是一个对象，所以自然有两种操作方式。

**第一种**，把整个匿名内部类直接写在 `goSwimming()` 调用的参数位置里：

```java
class Test {
    public static void main(String[] args) {
        goSwimming(new Swim() {
            @Override
            public void swim() {
                System.out.println("学生正在游泳");
            }
        });
    }

    public static void goSwimming(Swim s) {
        s.swim();
    }
}
```

右键运行，「学生正在游泳」一样打印出来了。

**第二种**，它既然是一个对象，那对象能不能赋值给一个变量？当然能。我们可以直接把它赋值给一个 `Swim` 类型的变量，注意最后要加一个分号结尾；后面如果还想再调用 `swim` 方法，直接把这个对象的引用 `s` 传过去就行：

```java
class Test {
    public static void main(String[] args) {
        Swim s = new Swim() {
            @Override
            public void swim() {
                System.out.println("学生正在游泳");
            }
        };

        goSwimming(s);
    }

    public static void goSwimming(Swim s) {
        s.swim();
    }
}
```

两种写法跑出来，结果是一样的。

#### 什么时候才值得用它

回到资料，我们把匿名内部类做个小结，你要掌握四个问题：

- **它是什么**：本质就是一个没有名字的内部类。这个类你可以写在**成员位置**，也可以写在**局部位置**（局部位置就是方法当中）。
- **它的格式**：`new 类名或接口名 ( ) { }`，大括号里面重写类或接口里的抽象方法。
- **格式怎么理解**：等价于四部分——先定义一个没有名字的类（就是大括号），这个类实现了前面的接口或继承了前面的类；如果类或接口里有抽象方法，就在大括号里重写；最后是创建对象，就是前面的 `new` 关键字，它创建的是后面那个没有名字的 java 类的对象。
- **什么时候用**：只有一句话——**如果说我的子类或者实现类我只要用一次，我不想再新建一个 java 文件了**，那么在这个时候我就可以用匿名内部类去简化代码。

有的兄弟可能会想：那以后我不想偷懒了，我每次都去新建一个 java 文件，是不是就不会用到匿名内部类了呢？如果你这么想，代表兄弟你思考了。

但是呢，在后面我们还有一个非常重要的知识点，就是 **lambda 表达式**。lambda 表达式在实际开发当中会大量用到，而**匿名内部类就是 lambda 表达式的前置知识点**。所以如果说匿名内部类这个格式你不能理解，那么 lambda 表达式根本就学不明白。

> **提示**：所以现在请大家一定一定要把刚刚那个格式，自己至少写两遍。打开 IDEA 练一练，这个格式越熟，后面学 lambda 就越轻松。

关于这个知识点，我们就先学习到这里。
