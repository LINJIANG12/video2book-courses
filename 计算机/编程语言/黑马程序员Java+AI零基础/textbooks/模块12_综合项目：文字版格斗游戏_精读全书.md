### 成品长什么样：一个纯控制台的文字格斗游戏

这个项目是一个**文字版的格斗游戏**，没有画面，全靠控制台。

进去第一眼看到的是游戏的**登录注册页面**，它给了你三个选择：**1 登录、2 注册、3 退出**。

我们从注册开始看一遍，把规则捋清楚。

#### 注册这一步，键盘能把你卡住三次

选 2 进注册，先让你输用户名。太短会直接提示"用户名的长度需要是 3~6 位"。那就 `AAA`，回车。

接着是密码。密码也有限制，长度得是 6~12 位。再输 `123456`，还是不行——它还有一条：**密码只能是字母加数字的组合**。那就 `1234qwer`。

然后是确认密码，**两次密码必须一样**，否则不算注册成功。

一旦三项都对上，它会自动注册，并且给你生成一个随机的 id，同时把你刚注册的用户名和密码落下来，账户立刻变为可用状态。

#### 登录连错三次，账号直接锁死

注册完选 1 登录。第一次故意输错，它提示"登录失败，用户名或密码错误，你还剩下两次机会"。第二次错，提示只剩一次机会。第三次再错——

> **注意**：这个时候不是再给你机会了，而是直接告诉你当前账号已被锁定，请联系黑马程序员官方客服。后面你再选这个账号登录，它上来就告诉你这个账号被锁定，直接用不了了。

这时候你只有两条路：要么联系客服给你解锁，要么重新注册一个。所以演示里我就重新注册了一个 `BBB`，密码 `1234qwer`，这次注册成功，登录也一次过。

登录成功之后，游戏直接启动：**"欢迎 BBB 来到文字版的格斗游戏"**。

#### 登录之后：建号、分配属性、然后打人

游戏启动后先让你创建角色，角色的名字就是你刚才登录用的那个用户名。接下来给你 **20 个属性点**，要你自己分配到生命、攻击、防御上，随便分一分就行。分配完提示角色创建成功，比如这样一套初始属性：

```text
角色：BBB
生命值：200
攻击力：20
防御力：5
拥有技能：普通攻击 / 强力一击 / 回血技能
```

然后进入战斗。第一次遇到的是一个随机战斗人员——**神秘法师**，生命值 70，攻击力 25，防御力 8。

每个回合先把双方血条打出来，血条后面跟着当前生命值，非常直观。到谁回合谁动手。我上来先选强力一击，这个技能有技能加成，但**要消耗自己 10 点血**，造成 28 点伤害。神秘法师的回合打过来一个火球术，**这个技能有 50% 的概率**，命中给我造成 40 点伤害。

第一场打完三回合：

| 回合 | 我方剩余血量 | 敌方剩余血量 | 说明 |
| --- | --- | --- | --- |
| 开局 | 200 | 70 | 神秘法师 攻击 25 / 防御 8 |
| 第 1 回合 | 190 | 42 | 我消耗 10 血释放强力一击，造成 28 伤害；敌方火球术造成 40 伤害 |
| 第 2 回合 | 120 | 14 | 强力一击 28 伤害，敌方造成 20 伤害 |
| 第 3 回合 | 110 | 0 | 强力一击 28 伤害，击败神秘法师，战斗结束恢复 22 点生命 |

然后打印当前胜场，问你要不要继续。继续。

第二场随机到**敏捷的刺客**，连续三个强力一击，击败。第三场同样三个强力一击，拿下。

三场打完之后，出现属性成长提示：

> 恭喜你获得了属性提升：最大生命 +30，攻击 +5，防御 +3。

也就是**每胜利三场，最大生命、攻击、防御都要有所增长**。

第四场遇到初级战士，这回是真打不过了。中途我想回个血——注意**回血这个技能也是有概率的**：消耗 10 点血，恢复了 20 点生命，净涨 10 点血。对方打了我 16 点，我只剩 19 点血。再打一个强力一击，我给他造成 29 点伤害，他给我打了 28 点——输了。

游戏结束，总胜场 3 场，最后来一句"感谢您游玩文字格斗游戏"。

### 用户类长什么样：四个属性

需求文档里写得很清楚：游戏具有登录和注册的功能，**登录成功之后才去启动游戏**。这里会涉及到一个用户类，它里面会有四个属性：`id`、用户名、密码，还有状态。下面文档对每一个属性都做了详细解释。

#### id：不是你能敲出来的

`id` 是用户无法设置的，**由系统自动生成**。

你看到系统生成了，你想到什么？这个 id 就**不能用 Scanner 键盘录入**，你得用 Random 或者其他技术去生成。它的格式是：**前面固定是"黑马"，后面再加五个数字**，比如 `黑马12345`。黑马是固定的，后面五个是随机生成的。

#### 用户名：唯一、长度、还得不是纯数字

用户名的要求相对复杂一些：

- **唯一**，不能重复；
- **长度 3~6 位**。当然你也可以把它写长一点，比如 3~16 位，这样限制更宽松；
- **只能由字母和数字组成，但不能是纯数字**。

第三条最容易搞错，我们拿例子过一遍：

| 用户名 | 是否合规 | 原因 |
| --- | --- | --- |
| `张三` | 合规 | 字母加数字组成，不是纯数字 |
| `张3at` | 不合规 | 混进了第三个字符 `t`，只有字母和数字两种 |
| `张3123` | 合规 | 字母加数字组成，不是纯数字 |
| `123456` | 不合规 | 纯数字 |

#### 密码：同样是字母加数字，但细节不一样

密码的长度是 6~12 位，同样只能是字母加数字的组合，不能有其他字符。

但是你看完了这两个要求之后，会发现**它里面的细节还是不一样的**。

我来问你：现在假如说用户名是纯字母，行不行？是可以的，它符合要求，因为要求是"只能由字母跟数字组成、不能是纯数字"，纯字母完全满足。

但是如果你的密码是这样的 `abcdefg`，注意，它是不行的。为什么？因为**密码必须是字母加数字的组合**，你在这个后面还要再加上数字，`abcdefg123`，这才是符合要求的。

> **易错点**：用户名允许纯字母，密码不允许纯字母——这是两者最容易被忽略的差别。

#### 状态：三次输错就变 false

第四个属性叫 `state`，它表示**用户的状态**，决定了你当前这个用户是否可用。

对应到我们刚才演示的那段逻辑：登录的时候如果密码连续错了三次，这个时候就要把 `state` 改成 `false`，账户就被锁定了。后续再怎么选这个账号登录，都直接判定为被锁定。

### 建项目、拆包、放启动类

因为咱们要新写一个项目了，所以点左上角菜单栏，`File → New → Project`，创建一个新项目。

名字咱们就叫文字格斗游戏的名字（test fighting game），选下面的 JDK 版本，默认 25，然后点 `create`。

它会弹一个框，问你新项目是在**当前窗口展示**，还是**创建一个新窗口**：

- 选 `This Window`：当前这个项目就关闭了；
- 选 `New Window`：当前这个项目不关闭，两个项目同时展示。

两个随便选哪个都可以，我选第一个 `This Window`，把当前项目关掉。

接下来正式开始写代码。右键 `src → New → Package`，新建一个包，名字叫 **`com.itheima.ui`**。UI 就是界面的意思。

然后右键 `src → New → Java Class`，起个名字叫 **`App`**。

> **定义**：`App` 是程序的**启动类**。这个类只负责启动，整个程序不写任何业务逻辑。

那么它主要启动的是哪个类呢？登录注册页面还没写呢。这个页面要写在 UI 包当中，右键 `New → Java Class`，名字就叫 `Login`。

在这个里面呢，**你就不要再写 main 方法了**。因为 main 方法表示的是程序的启动入口，这个入口我已经写在 `App` 中了。所以 `Login` 当中我只写普通的成员方法就可以。

我们写一个 `public void` 的方法，名叫 `start`，给它加一个注释：这个方法表示的就是登录注册的主页面。只不过页面展示的东西我们现在暂时还没学，所以现在这个页面是以**控制台的形式**来展示的。方法里面先写一个输出语句："游戏的登录注册页面打开了"。

然后在 `App` 当中，就可以创建 `Login` 的对象，用变量 `L` 接住，再用 `L` 去调用里面的 `start` 方法：

```java
public class App {
    public static void main(String[] args) {
        Login l = new Login();
        l.start();
    }
}
```

右键 run，程序运行完毕，你看——游戏的登录注册页面是不是就打开了。

所以现在我们就直接去写那个 `start` 方法就可以了。

### start 方法：提示语 + Scanner + switch

`start` 方法里面写什么呢？在刚刚我们画图的时候曾经推导过，它里面主要写两块内容：**第一个是提示的文字，第二个是下面给用户的选择**。

这个提示的文字不需要大家自己写，我们可以打开需求文档，把这一块 **Ctrl+C、Ctrl+V** 直接粘贴过来，这就可以了。

下面就让用户进行选择。选择要写什么？是不是写一个 `Scanner` 啊。因为这是用户的选择，我用一个变量记录，就叫 `choose`。然后用 `switch` 对用户的选择做一个匹配：

```java
package com.itheima.ui;

import java.util.Scanner;

public class Login {

    // 这个方法表示的就是登录注册的主页面
    public void start() {
        // 提示文字：直接从需求文档里 Ctrl+C、Ctrl+V 粘贴

        // 让用户做出选择
        Scanner sc = new Scanner(System.in);
        String choose = sc.next();

        switch (choose) {
            case "1" -> System.out.println("用户选择了登录操作");
            case "2" -> System.out.println("用户选择了注册操作");
            case "3" -> System.out.println("用户选择了退出操作");
            default -> System.out.println("再见，或者输入有误，请重新输入");
        }
    }
}
```

屏幕前的兄弟姐妹们，这种**箭头的写法**你还记得吧？它是我们 **JDK 12 关于 switch 的新特性**。

当然呢，如果说你比较陌生，你也可以用传统的方式：后面不写箭头，把输出语句写在这，然后呢这个下面**别忘了还要再写一个 `break`**，因为如果说你不写 `break` 的话，它有可能会导致 **case 穿透**现象。

这两种写法都是可以的，只不过这两种写法**不能同时存在**——你要么就全都用箭头，要么全都用传统的写法。我还是一律都用这种新的箭头的方式。

### 把业务挪出去：login 与 register 两个方法

好，主界面写完了。那接下来我要去优化一下代码。

因为刚刚我们已经知道了，`login` 里面有非常多的代码，`register` 注册里面也有非常多的代码，**我们不可能把所有代码全都写在 switch 里面**，这样子代码就太臃肿了。

所以在这个下面我要再去定义两个方法：

```java
    // 用户登录的操作
    public void login() {
        // 具体逻辑后面再补充
    }

    // 用户注册的操作
    public void register() {
        // 具体逻辑后面再补充
    }
```

这两个方法名其实不用自己想，AI 插件会自动帮你生成 `login` 和 `register`，直接调用就行了。

所以 switch 就可以简化成这样——主页面只负责"提示 + 分发"，真正的业务全部交给下面这两个方法：

```java
        switch (choose) {
            case "1" -> login();
            case "2" -> register();
            case "3" -> {
                // 退出操作，下面单独讲
            }
            default -> System.out.println("再见，或者输入有误，请重新输入");
        }
```

> **结论**：这就是一和二这两种选择。**主页面只管分发，方法里面只管业务**——这个习惯从这一个项目开始就要立住，后面游戏主界面的 310 行代码也全是靠它撑起来的。

### 退出：System.exit(0) 停止虚拟机

第三个就是用户选择了退出的操作。退出呢，我们有一个非常粗暴的方式，就是**可以直接停止虚拟机运行**。

这个代码请大家注意，在之前我们没有讲过怎么写。

> **定义**：在 Java 当中有一个类叫做 `System`，这个类里面定义的所有方法都是跟系统相关的。我们可以用 `System.` 调用里面的方法 `exit`。

按住 Ctrl 不松鼠标左键点一下 `exit`，你会发现这个是 Java 里面**已经定义好的方法**，`static` 静态的，所以可以用类名 `System` 直接去调用。

它里面需要传一个参数，参数有**两种写法**：第一个是 `0`，第二个是**非 0**（比如 `123`、`456`、`789`、`10`，只要不是 0 就都叫非 0）。

- 小括号里写 **`0`**：表示当前程序是**正常停止**；
- 小括号里写**非 0**（不管 `12345` 还是别的，只要不是 0）：程序就是**异常终止**。

用户选择 3，那肯定是正常停止，所以我选一个 0 就可以了。上面再加一个输出语句"用户选择了退出操作"，先提示一下，下面直接停止虚拟机的运行：

```java
        switch (choose) {
            case "1" -> login();
            case "2" -> register();
            case "3" -> {
                System.out.println("用户选择了退出操作");
                System.exit(0);
            }
            default -> System.out.println("再见，或者输入有误，请重新输入");
        }
```

**一旦虚拟机停止了，其他所有的代码全都不执行了。** 我们来试一试，写一个测试类：

```java
public class Test {
    public static void main(String[] args) {
        System.out.println("123");
        System.exit(0);
        System.out.println("看看我执行了吗？");
    }
}
```

右键 run，程序运行完。你来看看，"看看我执行了吗？"这句话**没有了**。因为当代码执行到第二行的时候，整个虚拟机就停止了——虚拟机停止之后，里面还有什么方法、循环、代码，你觉得还会继续走吗？它就不会再走了，对吧。

> **易错点**：这个方法名是 `exit`，中间是个 `e`。容易手快打成 `excit` 或者 `exit `，一编译就报"找不到符号"，右键 delete 把测试类删掉，回到主要的游戏代码当中。

## User 类与注册业务闭环
> 对应块：BLK44 | 覆盖分集：P136 | 块标题（分集名）：《第13章-02-用户类和注册的业务》

登录注册页面的界面部分，咱们已经全部写完了。接下来要补的，是这个页面背后的两大逻辑：**登录**和**注册**。

现在我问大家一个问题——你觉得兄弟，我先写登录啊，还是先写注册呀？屏幕前的兄弟姐妹们，你可以把答案打在弹幕上。

咱们别急着动手，先分析。

### 先写登录，还是先写注册

先说什么叫做注册，能不能用大白话讲给我听？其实很简单：让用户先去键盘录入用户的信息，这里的信息包含用户名、密码这些信息；一旦录完了之后，你再去把它存到一个容器当中——这不就是注册吗？

现在用户输"张三"，密码是 `123`；输"李四"，密码是 `1234`；然后我把这个信息存到一个容器当中。这不就是注册吗？

好，那登录是什么？登录其实也一样：用户键盘录入用户的信息，但下面就不是保存了，而是拿着用户名和密码到容器当中去判断是否存在。比如我现在键盘录入的是"张三 / 123"，那就判断容器里是不是存在；存在，登录成功。但我如果录的是"张三 / 12345"呢？它不存在，不存在就登录失败呗。

```text
注册 register                            登录 login
┌────────────────────┐                   ┌────────────────────┐
│ 键盘录入用户名密码   │                   │ 键盘录入用户名密码   │
└─────────┬──────────┘                   └─────────┬──────────┘
          ▼                                      ▼
┌────────────────────┐                   ┌────────────────────┐
│ 校验格式：本地判断   │                   │ 校验格式：本地判断   │
└─────────┬──────────┘                   └─────────┬──────────┘
          ▼                                      ▼
┌────────────────────┐                   ┌────────────────────┐
│ 校验唯一（要联网）   │                   │ 拿用户名密码去比对   │
└─────────┬──────────┘                   └─────────┬──────────┘
          ▼                                      ▼
┌────────────────────┐                   ┌────────────────────┐
│ 封装 User 放进集合   │                   │ 存在则登录成功       │
│ 提示注册成功         │                   │ 不存在则登录失败     │
└────────────────────┘                   └────────────────────┘
```

左边是注册，右边是登录。两者的**输入段几乎一样**，分岔只发生在最后：注册是"往里写"，登录是"拿出来查"。

既然逻辑已经清楚了，那就先去写注册呀。因为你要先有这么一个数据，我才能登录啊。没有下面这份数据，我登录什么？我没法登。

> **注意**：当然，硬要先写登录也能行。只不过在那种情况下需要添加**假数据**，也叫测试数据——你得提前准备一个容器，里面预先放几条用户信息（比如"张三 / 123"、"李四 / 1234"），先有了这么个数据，登录才能进行判断。

但咱们为了代码更简洁，所以先写 `register` 注册。

### 集合，还是数组

刚才我们判断 register 的时候就知道，我们是**把用户键盘录入的数据保存在一个容器当中**。那这个容器我要写什么？

在实际的企业级开发当中，这个容器有一个专业的东西叫**数据库**，也就是数据存储的仓库，我把用户名密码全都存在这个数据库里面。但是现在这东西哥们还没学呀。

按照我们目前已有的知识，容器咱们只学过两个：一个是数组，还有一个是集合。那你觉得我用哪个？

我肯定要用集合呀。因为集合包含了数组所有的特点，而且更重要的是，**集合的长度是可长可短的**，我不需要去关心它的长度，直接往里面加就行了。

所以要这样写：

```java
ArrayList<User> list = new ArrayList<>();
```

然后问题马上又来了：**泛型写什么？** 我要添加用户的信息，泛型你正常来讲要写个 `user` 啊。但是现在看左边，我有没有？没有。所以我们真正要写的第一步就是——得先有一个 `User` 类。

### 给 User 单独开一个包

右键 `src` → `new` → `package`，命名 `com.itheima.domain`。

为什么非要单独再新建一个包？因为在实际开发当中，每一个包它都是有各自的作用的。在刚刚我们书写的是那个 login——相当于呢是一个页面，而这里的 UI 它就表示页面的意思。那此时我们现在写的第二个类是那个 `user`，`user` 可不是那个页面，`user` 是一个 JavaBean 对吧。

所以我要单独地再建一个包，专门地去存放 JavaBean。以后呢，我们看到 `bean` 或者是看到 `domain` 这些包的时候，我就知道了：这个包里面装的就是所有的 JavaBean 类。

在 `domain` 包上右键 → `new` → `Java Class`，起个名字 `User`。

### User 的四个属性

这里面的属性是什么呢？哥们忘了。忘了没关系，**打开需求文档**——所有的东西忘了，直接看需求文档里面要的效果，逻辑全都在需求文档当中。

看这里，属性一共有四个：`id`、用户名、密码，还有一个 `state` 状态。

回到我们心爱的 IDEA 当中，把它 `Ctrl+V` 粘贴过来，然后逐个改：

第一个 `id`，那我就写 `private String id` 就可以了哦。它自动生成的是一个 `Integer`，这不对，我要是 `String`。为什么？因为 id 里面的格式是"黑马"后面再加五个数字，如果说你是一个整数的话，那也不行。

继续往下：用户名 `username`、密码 `password`，还有第四个 `state` 状态。那么状态呢我也要改一改，AI 生成的这个 `int` 不对，我要用 `boolean`。为什么？因为状态有两种：如果说你是 `false`，就表示我当前的账户是被禁用的；但是如果说你是 `true`，就表示当前的账户它是可用的。它只有这两个结果。

> **定义**：`state` 表达的是账户的可用状态，只有"可用"和"禁用"两个取值，所以它天然是一个布尔量，而不是一个可以塞进任意数字的 `int`。

然后生成**空参构造**、**带全部参数的构造**，以及针对于每一个私有化的成员变量，都生成其对应的 `get` 和 `set` 方法。

### createId：黑马加五个随机数字

写完之后我再来看一下，在这个 User 类里面，我要不要去写一些额外的成员方法呢？哥们不造。没关系，还是看需求文档。

在需求文档当中再看下面的，它说 **id 用户是没有办法进行设置的**。那么注意这句话表示了什么？它就是说，你在创建对象的时候，你不需要把那个 id 给我，我是**在代码当中自动生成**的。它的格式是这样：黑马再加五个随机的数字。

所以呢在我们 JavaBean 当中，你要去写一个方法去生成随机的 id，好。

方法名我就叫 `createId`，创建一个 id。它的格式呢是黑马加五个随机的数字——你想到了随机，还有字符串的拼接。所以在这个下面我要去生成 `StringBuilder`，`sb` 等于 `new StringBuilder()`，里面默认的值我就写"黑马"。

然后再往下，随机 `Random r = new Random()`，用 `r` 去调用里面的 `nextInt` 的方法，小括号里面写 `10`，那么这样呢我就可以在 0~9 之间去生成一个随机数，用一个变量去接收一下。

那么现在呢是一个随机的数字，那这不行啊，我要**五个**呀。怎么办？循环嘛。选择它 `Ctrl+Alt+T`，点上 for，选 `i`，粘贴过来——循环五次，这样黑马后面就拼接了五个随机数字。

最后我再把它 `return`。只不过呢 return 的时候要**万分注意**：现在呢 `sb` 它不是一个字符串，它是 `StringBuilder`，所以你看，我要去调用 `toString` 方法，变回字符串，这才是可以的。

```java
// 生成随机id：黑马 + 5位随机数字
public String createId() {
    StringBuilder sb = new StringBuilder();
    sb.append("黑马");

    Random r = new Random();
    for (int i = 0; i < 5; i++) {
        int n = r.nextInt(10);   // 0~9 之间取一个随机数
        sb.append(n);
    }

    return sb.toString();   // sb 不是字符串，必须转一下
}
```

方法写完，在上面空参构造当中，我们就可以去调用 `createId` 方法，然后呢去设置 id，所以呢里面我就写 `id = createId()`。这个方法一定要用就行。

### state 的默认值必须手动改

然后呢继续再来，我们还要做一件事情：就是要修改一下 `state` 的值。

为什么要修改它？因为在之前我们曾经说过，关于我们成员变量啊，它是有一些默认值的：

| 成员变量类型 | 默认值 |
| --- | --- |
| `byte` / `short` / `int` / `long` | `0` |
| `float` / `double` | `0.0` |
| `boolean` | `false` |

那你觉得 `false` 这个默认值在我这道题目当中能用吗？**不能用**。`false` 表示当前账户是禁用的——我刚注册一个用户，上来就给我禁用，不合理吧？默认应该是 `true`。

所以说在这儿我要去修改一下 state 默认的值，把它赋值为 `true`，这才是 OK 的。

有参构造呢也是一样的道理，Ctrl+C、Ctrl+V 修改一下。形参这里 id 还有这里的 state，你就不要给我了——你在创建对象的时候直接给我用户名跟密码就可以了，里面的 id 还有 state，构造里自己生成、自己赋值。

这样 User 就齐了：

```java
package com.itheima.domain;

import java.util.Random;

public class User {
    private String id;
    private String username;
    private String password;
    private boolean state;

    public User() {
        this.id = createId();
        this.state = true;
    }

    public User(String username, String password) {
        this.id = createId();
        this.username = username;
        this.password = password;
        this.state = true;
    }

    // 生成随机id：黑马 + 5位随机数字
    public String createId() {
        StringBuilder sb = new StringBuilder();
        sb.append("黑马");

        Random r = new Random();
        for (int i = 0; i < 5; i++) {
            int n = r.nextInt(10);
            sb.append(n);
        }
        return sb.toString();
    }

    public String getId() { return id; }
    public void setId(String id) { this.id = id; }

    public String getUsername() { return username; }
    public void setUsername(String username) { this.username = username; }

    public String getPassword() { return password; }
    public void setPassword(String password) { this.password = password; }

    public boolean isState() { return state; }
    public void setState(boolean state) { this.state = state; }
}
```

> **易错点**：`state` 的取值方向别搞反——`false` 是**被禁用**，`true` 才是**可用**。新注册的账户默认必然是 `true`。

### 集合一定要写在循环外面

User 写完关掉。此时我们就可以在登录界面当中去创建一个集合了：

```java
ArrayList<User> list = new ArrayList<>();
```

泛型就写 `User`，起个名字 `list`，等于 `new ArrayList<>()`。

但在创建 `ArrayList` 的时候，兄弟们一定要**万分注意**：这个集合你不能够写在循环的里面。因为如果你写在循环里面了，就变成什么效果了？看好，就是我在注册的时候，我用的是这个集合；那么现在注册完了，代码回到上面重新再来运行——看好了，它是不是又创建了一个新的集合呀？**每一次循环都会创建一个新的集合**。

那就会导致什么？注册是一个集合，登录又是另外的一个集合，那你这肯定不对呀。我想要操作的是你注册还有这个登录，我要你操作**同一个集合**，这才是 OK 的。

> **结论**：集合一定要定义在循环的外面。

然后呢还没完，我要把 `login` 还有 `register` 这个方法当中，把这个集合都传递过去，这样才能实现我注册跟登录操作的都是同一个集合：

```java
public static void register(ArrayList<User> list) { }
public static void login(ArrayList<User> list) { }
```

那么继续再来，我们就可以对三个变量进行判断了。要求是什么？把它一起粘贴过来：

> - 字母至少有一个
> - 数字可以有也可以没有
> - 其他字符一定不能有

字母至少有一个，其实呢说的就是这里的 `charCount`，它必须是**大于零**的才行，你不能等于零。而这里的数字可以有也可以没有呢，就是说它是要**大于等于零**的；还有一个 `otherCount`，它不能有，就是说你必须要**等于零**。

是不是要**同时满足**这三个条件才可以啊？

```java
public boolean checkUsername(String username) {
    int charCount = 0;    // 字母的个数
    int numberCount = 0;  // 数字的个数
    int otherCount = 0;   // 其他字符的个数

    for (int i = 0; i < username.length(); i++) {
        char c = username.charAt(i);
        if ((c >= 'a' && c <= 'z') || (c >= 'A' && c <= 'Z')) {
            charCount++;
        } else if (c >= '0' && c <= '9') {
            numberCount++;
        } else {
            otherCount++;
        }
    }

    return charCount > 0 && numberCount >= 0 && otherCount == 0;
}
```

> **提示**：需求里"数字可以有也可以没有"这一句，是被原样翻译成了 `numberCount >= 0`。计数器是从 0 开始往上加的，这个条件天然成立，它对应的是"数字不是强制要求"。等咱们给密码改规则的时候，这一行才会真正动刀。

```java
        if (user.getUsername().equals(username)) {
            return true;
        }
    }
    return false;
}
```

```java

public int[] getCount(String userInfo) {
    int charCount = 0;
    int numberCount = 0;
    int otherCount = 0;

    for (int i = 0; i < userInfo.length(); i++) {
        char c = userInfo.charAt(i);
        if ((c >= 'a' && c <= 'z') || (c >= 'A' && c <= 'Z')) {
            charCount++;
        } else if (c >= '0' && c <= '9') {
            numberCount++;
        } else {
            otherCount++;
        }
    }

    return new int[]{charCount, numberCount, otherCount};
}
```

那么最终的代码你要注意了，我是要把上面的三个 `count` 来做一个返回。哎，这怎么返呀？在之前我们曾经学习了，我返回一个单独的整数，我可以把返回值写成 `int`，但是现在我要返回**三个**呀，怎么写？难道我写 `st...` 吗？嘿嘿注意了，Java 当中没这写法。

### 验证码：先把需求文档上的规则读成代码

先读规则，这一条都不能错：

- 验证码的长度是 5；
- 由**四位**大写或者小写的字母 + **一个**数字组成；
- 同一个字母可以重复出现；
- 数字可以出现在任意位置。

举例来说，`AQAEK` 就是一个合法的验证码——`A` 出现了两次，数字 `6` 冒到了第一个位置上。

> **提示**：整个需求里最容易被忽略、也最容易被面试官追问的，就是"数字可以出现在任意位置"这一条。如果偷懒把数字直接拼在末尾，代码能跑、演示能过，但需求是不满足的。

下面按五步来写，每一步都能单独跑起来给你看。

#### 把 52 个大小写字母装进一个集合

题目要随机抽字母，那前提是手里得有一堆字母。这一步就是把 `a` 到 `z`、`A` 到 `Z` 全塞进一个容器。

之前写作业的时候我们是把字母放进**数组**里的，现在集合学完了，集合当然也能放。只不过有一个细节：

```java
ArrayList<Character> list = new ArrayList<>();
for (int i = 0; i < 26; i++) {
    list.add((char) ('a' + i));
    list.add((char) ('A' + i));
}
```

> **易错点**：集合的泛型里**不能写 `char`**。泛型参数只能是引用类型，而 `char` 是基本数据类型。要存字符，就必须写它对应的包装类 `Character`。

那 `add` 的时候能不能直接传 `char`？能。虽然你在代码里写的是个字符 `'a'`，但真正加进集合的时候，Java 会自动把它装箱成 `Character` 对象。这个地方特别顺手，不用手写转换。

方法刚建好还没有返回值，代码会飘红报错。这很正常——**先 `return null` 让它能跑**，跑通了再往下写。这是个好习惯：每一小步都跑一次，出了问题立刻知道是哪一步的事。

```java
public static String getCode() {
    ArrayList<Character> list = new ArrayList<>();
    for (int i = 0; i < 26; i++) {
        list.add((char) ('a' + i));
        list.add((char) ('A' + i));
    }
    System.out.println(list);
    return null;   // 先占位，保证此刻能跑起来
}
```

跑一下，控制台老老实实把 52 个字母全吐出来了。用集合确实方便：我们不需要考虑索引，也不需要提前算好元素个数，有了数据往里塞就完事了。

#### 随机抽四个字母，用 StringBuilder 拼起来

容器有了，接着抽四个。这一步的写法我们写过很多遍了——`Random` 生成，随机索引取元素：

```java
Random r = new Random();
StringBuilder sb = new StringBuilder();
for (int i = 0; i < 4; i++) {
    int index = r.nextInt(list.size());
    char c = list.get(index);
    sb.append(c);
}
```

`nextInt(list.size())` 取的是**集合的索引**，所以边界是 `0 ~ 51`。左边用 `index` 变量记录，右边 `list.get(index)` 把数据拿出来。

拿出来的结果你用 `Character` 接也行，用 `char` 接也行，这两种写法都合法。

抽出来四个字母之后不能只打印一个就算完——我们要的是把这四个**拼起来**。拼接有两种写法，一种是用字符串本身的方式拼，一种是用我们学过的 `StringBuilder`。这里选 `StringBuilder`，因为它就是为反复追加设计的。

```java
StringBuilder sb = new StringBuilder();
for (int i = 0; i < 4; i++) {
    int index = r.nextInt(list.size());
    char c = list.get(index);
    sb.append(c);
}
System.out.println(sb);
```

连着运行几次，每次都是四个随机字母，题目要求已经满足了一半。

#### 再补上一位随机数字

题目说还有一个数字，范围就是 `0~9`。这个太简单了：

```java
sb.append(r.nextInt(10));
System.out.println(sb);
```

这里顺便说一下为什么能这么写：Java 是**先把右边的表达式算出来，再去调用左边的方法**。所以运行时它会先去求 `r.nextInt(10)`，得到一个 0 到 9 之间的随机数，再把这个数追加进 `sb`。省掉一个中间变量，很干净。

跑一下，`YQ6oz`、`GOTKR9` 这种就出来了。

#### 把数字换到任意位置

到目前为止，我们的基本代码已经写完了。但真正的难点在这儿：**数字的位置可以是任意的**。

现在数字被固定追加在了末尾，怎么把它挪到任意位置？本质上就是——我要修改字符串里面的内容。

字符串是不可变的，想改内容，我们之前说过一个办法：先 `sb.toString()` 变成字符串，再调用字符串的 `toCharArray()` 把它变成字符数组，在数组里改完，最后再变回字符串。

```java
char[] arr = sb.toString().toCharArray();
```

> **易错点**：看清楚现在是谁在调 `toCharArray()`——**不是 `sb` 在调**，是 `sb.toString()` 的结果（也就是那个字符串）在调。链式调用一旦写错对象，编译就直接报错。

拿到数组之后要干的事就一句话：把**最大索引**上的数据，跟一个**随机索引**上的数据交换位置。

随机索引好说，还是老样子：

```java
int index = r.nextInt(arr.length);
```

最大索引是多少？你当然可以直接写死 `4`，本题里这么写一点问题都没有。但我强烈建议大家写得通用一点：

```java
char temp = arr[index];                    // 先记下随机位置上原来的数据
arr[index] = arr[arr.length - 1];          // 再把最大索引的数据挪到随机位置
arr[arr.length - 1] = temp;                // 最后把 temp 挪回最大索引
```

> **易错点**：**别把最大索引写死成 `4`**。写死只在本题成立，等哪天字符串长度变成 10 或者 20，直接越界。写成 `arr.length - 1`，不管多长，拿到的都稳稳是最大索引。

三行就是教科书式的交换：借一个 `temp` 中转站，先存、再覆盖、最后还回去。写完打印一下数组，你会看到数字已经随机落在五个位置中的任意一个了。

#### 数组换回字符串返回

最后一步，把字符数组再变回字符串交出去：

```java
String code = new String(arr);
return code;
```

完整的 `getCode` 到这里就齐活了：

```java
public class CodeUtil {

    public static String getCode() {
        /*
            验证码的长度是 5
            由四位大写或者小写的字母 + 一个数字组成
            同一个字母可以出现多次
        */

        // 第一步：把所有的大写和小写字母都放到一个容器当中
        ArrayList<Character> list = new ArrayList<>();
        for (int i = 0; i < 26; i++) {
            list.add((char) ('a' + i));
            list.add((char) ('A' + i));
        }

        // 第二步：从集合当中随机抽取 4 个字母，拼接到 StringBuilder 当中
        Random r = new Random();
        StringBuilder sb = new StringBuilder();
        for (int i = 0; i < 4; i++) {
            int index = r.nextInt(list.size());
            char c = list.get(index);
            sb.append(c);
        }

        // 第三步：再追加一个 0~9 的随机数字
        sb.append(r.nextInt(10));

        // 第四步：数字位置任意 —— 字符串变字符数组，交换最大索引与随机索引
        char[] arr = sb.toString().toCharArray();
        int index = r.nextInt(arr.length);
        char temp = arr[index];
        arr[index] = arr[arr.length - 1];
        arr[arr.length - 1] = temp;

        // 第五步：字符数组变回字符串返回
        String code = new String(arr);
        return code;
    }
}
```

### 登录：先判断不合理的，再判断合理的

验证码搞定，回到登录。需求文档上关于登录的补充只有两条，但都很要命：

- 登录的时候，密码最多重试**三次**；
- 三次全错，账号就**锁定**。

所谓锁定，其实就是把 `User` 的第四个属性 `state` 置为 `false`，没有别的花活。

难点在于判断的**顺序**。文档上写着登录时要录用户名、密码、验证码，那代码里是不是就该按这个顺序先录密码？**不是。** 想想场景：用户名压根没注册，你让用户输入密码，输入完了告诉他"这账号不存在"——这不是耍人玩吗？

所以正确的顺序是：**先把不合理的可能性全部排除掉，剩下的那条路才是正常流程**。

- 用户名不存在 → 提示当前用户名未注册，请先注册；
- 用户名已存在 → 接着看这个账号有没有被锁定，锁定了就让他联系客服；
- 没锁定 → 才轮到验证码；
- 验证码对了 → 最后才是密码。

> **结论**：登录的判断链是「用户名 → 账号状态 → 验证码 → 密码」。前三层都是异常分支，只有最后一层是正常分支。写代码时先验证不合理的，最后剩下的自然就合理了。

```text
                                  进入下一轮      锁定账号 + return
```

光看这个判断链就够了吗？动手之前先解决一个很实际的问题：`login` 方法写得太长了，方法体已经在屏幕下面了，怎么跳回来？

有两种办法，都很好用：

- 按住 `Ctrl` 不松，用鼠标左键点一下 `login` 这个方法名，直接跳过来；
- 按 `Ctrl + F12`，当前类里所有的方法会全部罗列出来，双击 `login` 也能跳。

> **提示**：这两个快捷键在代码量一大之后就是救命的，别等到找不到方法时才想起来学。

#### 把用户名先录进来

第一步当然还是让用户键盘录入，用的还是老朋友 `Scanner`：

```java
Scanner sc = new Scanner(System.in);

System.out.print("请输入用户名：");
String username = sc.nextLine();
```

`nextLine()` 我们用过很多次了，它能完整地拿到一行字符串——用户名里万一有空格也不会断。

#### 用户名不存在，直接结束登录

第二步就是判断 `username` 在集合里存不存在。

这一步的代码你**根本不用自己写**——注册那一步我们已经抽过一个 `contains` 方法了，直接调就行：

```java
if (!contains(USER_LIST, username)) {
    System.out.println("当前的用户名" + username + "未注册，请先注册之后再进行登录");
    return;
}
```

> **提示**：**把代码抽成一个方法，越往后越顺。**刚开始写项目的时候，这个判断要写、那个循环也要抽，会觉得好麻烦；但等代码量起来了，你会发现后面根本不用再写，直接调就行。

注意这里的关键词是 **`return`**，不是 `break`，也不是 `continue`。

为什么？因为 `break` 只跳出当前循环，`continue` 只是跳过本次迭代——它们都在循环**内部**用。而我们现在根本不在循环里，我们要做的是**直接结束整个 `login` 方法**，让程序回到选择界面，让用户先去注册，注册完再来登录。用 `break`/`continue` 根本达不到这个效果。

所以这里一定要写上注释：

```java
// 如果用户名不存在，那么结束登录的行为，回到选择界面当中，先去注册
return;
```

#### 用户已存在，先拿到 User 对象再看状态

用户已存在了，接下来干什么？是不是可以直接判密码了？

**不行。** 你得先判断这个账号当前的状态。

那问题来了：状态是存在对象里面的，我要看状态，是不是得先把这个对象拿到手？答案是肯定的。

所以我们再抽一个方法出来，专门干一件事：**在集合中找到 `username` 所在的索引**。

举个例子你就明白了。假设集合里有三个对象：

| 对象 | 用户名 | 密码 | 状态 |
| --- | --- | --- | --- |
| 第一个 | 张三 | 123 | `true` |
| 第二个 | 李四 | 1234 | `false` |
| 第三个 | 王五 | 12345 | `true` |

现在用户键盘录入的是"张三"。你光知道"张三"这三个字是没用的，你得先通过它把**整个对象**拿到手，然后才能看到这个对象的密码是多少、状态是 `true` 还是 `false`。

所以这个方法是这样的：

```java
private static int findIndex(ArrayList<User> list, String username) {
    for (int i = 0; i < list.size(); i++) {
        User user = list.get(i);
        if (user.getUsername().equals(username)) {
            return i;          // 存在，直接返回当前索引
        }
    }
    return -1;                 // 循环结束还没找到，返回 -1
}
```

大家看这个方法，是不是跟上面那个 `contains` 长得特别像？它们的确是一家人：

- `contains` 判断的是**在不在**；
- `findIndex` 判断的是**在第几个**。

方法名一开始不知道返回值类型，先写个 `void` 也行，主体写完回头一看——它返回的是索引，所以必须改成 `int`。

方法写完把代码块 `Ctrl+C` 收起来，回到 `login` 里 `Ctrl+V`：

```java
int index = findIndex(USER_LIST, username);
User u = USER_LIST.get(index);

if (!u.isState()) {
    System.out.println("当前的用户已经被禁用，请联系客服 xxxxxxxxxxxx");
    // 如果用户名被禁用，结束登录的行为，回到选择界面当中
    return;
}
```

`User u = USER_LIST.get(index);` 这一句就是"拿到整个对象"，后面的所有判断都挂在 `u` 身上。

这里还有一个特别容易懵的点，写的时候可能会卡住：对象明明是用快捷键自动生成的，为什么 `u.` 后面就是没有我要的那个方法？

往下拉一拉就明白了——它不叫 `getState`，它叫 **`isState`**。

> **定义**：这是**布尔类型**变量的命名规律。`int`、`String` 这类属性的 getter 叫 `getXxx`；而 `boolean` 类型的 getter 约定俗成地叫 **`isXxx`**，语义上也更顺——`isState()` 直译就是"是不是处于可用状态"，比 `getState()` 自然得多。

还有，这里的 `!` 别忘了。你要判断的是**不正常**，状态 `false` 才是不正常，所以 `if (!u.isState())` 才是"如果被禁用"。少了这个叹号，逻辑整个反过来。

跟前面那个 `return` 一样，账户被禁用了，你再怎么想登也登不进去，直接 `return` 结束方法，让他回选择界面重新注册别的账号。

#### 验证码：先生成，再让用户录

前两个异常排掉之后，终于轮到验证码和密码了。这里有个非常容易搞反的顺序问题。

**验证码不能让用户随便输。** 你得先有一个正确的验证码生成出来，用户才知道该输什么。所以这一小段的顺序必须是：

1. 调用 `getCode()` 生成正确的验证码；
2. 把正确的验证码打印出来；
3. 提示用户录入；
4. 用户录入；
5. 拿两个做比较。

我一开始是写成"先提示录入、再生成"的，后来自己也觉得别扭——**没有正确的，我录什么呀？我又看不到。** 这种顺序一定要自己心里默念一遍。

比较的方式也要选对：

```java
String rightCode = getCode();          // 我自己生成的
System.out.println("请注意：验证码为：" + rightCode);

System.out.print("请输入验证码：");
String code = sc.nextLine();            // 用户键盘录入的

if (rightCode.equalsIgnoreCase(code)) {
    System.out.println("验证码输入正确");
    break;
} else {
    System.out.println("验证码输入错误");
    continue;
}
```

> **易错点**：这里用的是 **`equalsIgnoreCase`**，不是 `equals`。`equals` 要求大小写完全一致，但验证码这种字符串，大小写无所谓——用户手抖打了个小写 `q`，直接判定失败是很糟糕的体验。

那输错了怎么办？必须**重新生成一个新的验证码**，并且**让用户重新输入**，两件事都得做。光换验证码不让人重录不行，光让人重录不换验证码也不行。

用 `while (true)` 把这一段包起来，输对就 `break`，输错就 `continue`：

```java
// while(true)：生成一个验证码并反复校验，直到输对为止
while (true) {
    String rightCode = getCode();
    System.out.println("请注意：验证码为：" + rightCode);

    System.out.print("请输入验证码：");
    String code = sc.nextLine();

    if (rightCode.equalsIgnoreCase(code)) {
        System.out.println("验证码输入正确");
        break;          // 验证码输入正确，跳出循环，继续判断密码
    } else {
        System.out.println("验证码输入错误");
        continue;       // 重新生成一个验证码，并让用户重新输入
    }
}
```

在 `while (true)` 里，`break` 和 `continue` 终于用对地方了——它们的作用域正好就是这个循环本身。

#### 密码：三次机会，用完就锁

验证码这一关过了，才轮到密码。

正确的密码从哪来？往上翻一翻——刚才我们通过 `username` 已经把 `User` 对象 `u` 拿到了呀，密码不就在对象里吗：

```java
String rightPassword = u.getPassword();
```

正确的有了，自己键盘录入的也有了，那就比吧。而且题目允许你多试三次：

```java
for (int i = 0; i < 3; i++) {
    // 键盘录入密码
    System.out.print("请输入密码：");
    String password = sc.nextLine();

    // 生成并校验验证码（每次验密码都要来一遍）
    while (true) {
        ...
    }

    // 校验密码
    String rightPassword = u.getPassword();
    if (rightPassword.equals(password)) {
        System.out.println("登录成功，游戏启动");
        break;
    } else {
        System.out.println("登录失败，密码输入错误");
        if (i == 2) {
            // 三次机会全部用完，锁定账号
            u.setState(false);
            System.out.println("当前账号" + username + "已锁定，请联系客服 xxxxxxxxxxxx");
            return;
        } else {
            System.out.println("密码错误，你还剩下" + (2 - i) + "次机会");
        }
    }
}
```

这里有三个细节值得单独拎出来。

**第一，`for` 循环要包的范围比想象的大。**

我们可不能只把"判断密码"这一行包进循环里。必须把**键盘录入密码**和**上面那一整段验证码校验**全放进去。

这样形成的效果就是：**每一次验证密码，都要先输一次验证码。**

这正是验证码存在的意义——防止别人用机器、或者用其他技术手段，不断地来破解你的密码。一次性验证一个验证码，挡不住脚本循环重试；每次都验证，才挡得住。

**第二，密码的比较用的是 `equals`。**

验证码可以忽略大小写，密码不行。密码必须大小写完全一致，这是 `equals` 的职责，别弄混了。

**第三，剩余次数是 `2 - i`，不是 `3 - i`。**

因为 `i` 从 0 开始。第一轮 `i=0` 的时候其实还剩两次（第二、三轮），第二轮 `i=1` 剩一次，所以是 `2 - i`。而 `i == 2` 那一轮是最后一轮，输错就意味着三次全用完，直接 `u.setState(false)` 锁死，提示"已锁定，请联系客服"，然后 `return` 结束整个方法。

#### 把注册和登录完整跑一遍

代码写完了，`login`、`register` 全部就位，来看真实效果。运行 `App`，我们从注册开始：

先注册一个用户「张三」，输错一次提示不对，输上正确的用户名，再输密码和验证码，**张三注册成功**。

接下来登录。我们故意输「李四」：

```text

```

判断链的第一层就把他挡住了，连密码和验证码都不让他碰。

重新选一次登录，这次输「张三」。密码输错，验证码粘贴正确的那个，提示：

```text

密码错误，你还剩下2次机会
```

第二次继续，密码仍旧输错，验证码再粘一次：

```text

```

第三次，**最后一次机会我还输错的**：


然后我们再登录一次「张三」试试：

注意看——**它根本没有让你继续往后输密码、输验证码**，账号状态那一层直接就把人拦下了。这正是我们判断顺序设计对了的证据。

### 文字格斗游戏：回合制是怎么打一场的

登录注册页面全部完成，接下来是这个游戏的**第二个功能，也是最核心的功能**——游戏本身的完整过程。

先看需求文档。游戏名称叫**文字格斗游戏**，类型是"基于控制台版的回合制文字 RPG 游戏"。这里有个词特别重要：**回合制**。

什么叫做回合制？玩过游戏的兄弟都不陌生——**你 A 我一下，然后我 A 你一下**。这里这个 "A" 就是"打"的意思。你打我一下，我打你一下，这就是回合制。

游戏目标写得很清楚：玩家通过创建角色、分配属性、使用技能，去战胜一系列敌人；同时要获得胜利的场次，并提升角色的属性。

看到"一系列敌人"这句你就明白了——**不是打赢一个就完事**。

需求文档把核心机制拆成了四块：

| 系统 | 它要解决的问题 |
| --- | --- |
| 角色创建与属性的分配系统 | 我方控制谁？敌人有几个？手上的点数怎么分？ |
| 回合制的战斗系统 | 打一下之后发生什么，什么时候算结束 |
| 技能系统 | 打的时候不一定只是普通攻击，还可能放技能 |
| 胜场累积与成长系统 | 赢了多少场要记着，赢了的奖励是什么 |

前面三个系统好理解，重点看**回合制的完整战斗过程**。这就是我们一会儿要翻译成代码的东西：

```text
        我方出手攻击敌人
                |
                v
        敌人生命值为 0 ?
           |            |
          是            否
           |            |
           v            v
      敌人被击败      敌人还手打我
      结束本场        |
      进入下一场      v
                我方生命值为 0 ?
                   |            |
                  是            否
                   |            |
                   v            v
              人物死亡      回到回合开头
              本场结束      再打一次
```

把这段话翻译一下就很清楚了：我打敌人一下，**打完了不是就完事了**，还得判断敌人血量是不是零。是零，就代表我打败他了，本场结束，进下一场；不是零，他就要还手。他打完了，也得判断我血量是不是零。是零，人物死亡，结束；不是零，那就重复上面的打斗过程。

**胜场累积**也很好理解：既然要打多个敌人，那在打斗过程中我就得把胜利的次数记录下来。在代码里其实只要**定义一个变量**就行——赢一场就加一，赢一场就加一，就这么简单。

**成长系统**则是：赢一场要不要给点奖励？奖励可能是道具，也可能是属性点。版本一更新，装备、升级、技能树都要往上加。

### 一个角色到底有哪些属性

接下来先把两个角色的属性分析清楚，还是老规矩，先看需求文档。

#### 名字直接用登录的用户名

文档里说角色的创建分两大块。第一块是**角色的名字**，这个东西**不需要用户输入**——它是登录而来的。你登录时用的用户名是张三，角色的名字就叫张三。

#### 属性 = 初始属性 + 分配点数 × 比例

第二块是属性点，它由**初始属性**和**分配的属性**共同决定：把 20 个初始属性点分配到血量、攻击、防御这三个属性当中。

这句话怎么理解？看文档里以 HP 为例的那句话就明白了：生命值的基础值是 100 点。什么叫"属性分配"？就是我把这 20 点属性值里的一部分分给血量。那此时真正的血量应该是多少？

因为我们**一个属性点折算成 10 点生命**，所以：

> **公式**：角色属性 = 初始属性 + 分配点数 × 比例，其中生命值的比例是 10（一个属性点 = 10 点生命）。

对到 HP 上就很顺了：

- 一个点都不分给血量 → 那你的血量就是初始的 100 点；
- 分配了 20 点 → $100 + 20 \times 10 = 300$ 点血。

#### 为什么 hp 和 maxHp 必须是两个属性

接下来这一条是很多人第一次写都会漏的：血量你**要写两个属性**——`hp` 记录**当前**血量，`maxHp` 记录**最大**血量。

为什么非要拆成两个？有两条硬理由：

**第一，文档写着每胜利三场要加 30 点**，加的这个 30 加的是**最大生命**的 30，是给上限抬高的，不是直接往当前血量上砸。

**第二，技能列表里有一个技能叫"生命的摄取"，也就是回血。** 那你说我回血有没有可能超过最大生命？不可能。假设当前生命是 150，最大生命是 200，我现在回 100 点血——血量变成 250？不可能吧，你最多只能到 200。

所以这两个数字必须分开记：一个是"现在还剩多少"，一个是"最多能有多少"。少了后者，回血的封顶就没法写；少了前者，加血和扣血都无从谈起。

#### 技能：一个用集合，一个用变量

文档里玩家这一侧列的是**技能列表**。注意这个"列表"——玩家一共有三个技能。

三个技能要装到一个地方，所以玩家这边用一个**集合**来表示，比如 `ArrayList<String>`。

敌人的情况不一样。文档里明确列了四种敌人：初级战士、敏捷刺客、重装坦克、神秘法师。这四种敌人，每一种**只有一个技能**。一个技能，用集合装纯属浪费，所以敌方这边用一个**普通变量** `String skill` 表示就够。

#### 敌人多出来的 defending 属性

敌方属性和玩家几乎一样：名字、当前生命、最大生命、攻击力、防御力、技能。但有一个小细节值得盯住——看那个**重装坦克**。

它的技能叫**防御姿态**，效果是**让下一个回合的伤害减半**。

看出来了吗？这个技能不是一个伤害技能，它是**给自己加一个 Buff**。那问题就来了：你怎么知道当前这个敌人到底有没有挂上这个 Buff？

最简单的方式：给敌人再加一个属性，就叫 `defending`，类型 `boolean`。当前值记 `true` 就表示身上有这个减伤 Buff，记 `false` 就是没有——没有的话，你该受多少伤害就受多少伤害。

> **结论**：我方角色 = `name` + `hp` + `maxHp` + `attack` + `defense` + 技能集合（至少六项）；敌方角色 = 前五项 + 技能变量 + `defending`。

到这里，两个角色的属性就分析完了。下面写代码之前，还是按老规矩：**先画图，再写代码。**

### 把两个角色抽成一个父类

现在把上面分析的属性摆在一起看。回头想想面向对象课上讲过的那句话：**同一类事物，如果有共有的属性或者共有的行为，就要往上抽取。**

我方角色和敌方角色是不是都是"游戏人物"？那就可以往上抽一个父类，名字就用 `character` 这个单词——它就是"角色"的意思。

父类放共有的 `name`、`hp`、`maxHp`、`attack`、`defense`，子类只放自己独有的东西：

```text
                 Character  (游戏人物)
    name | hp | maxHp | attack | defense
    isAlive()  heal()  takeDamage()  show()
              /                  \
             /                    \
   HeroCharacter              EnemyCharacter
  skillList : ArrayList<String>   skill : String
     (我方, 3 个技能)             defending : boolean
                                  (敌方, 1 个技能 + 减伤 Buff)
```

现在打开 IDEA，在 `domain` 包下面右键 `New Java Class`，先写父类 `Character`。

#### 父类的属性和构造方法

```java
public class Character {

    // 游戏人物的名称
    public String name;
    // 游戏人物当前的生命值
    public int hp;
    // 游戏人物最大的生命值
    public int maxHp;
    // 攻击力
    public int attack;
    // 防御力
    public int defense;

    public Character() {
    }

    public Character(String name, int hp, int attack, int defense) {
        this.name = name;
        // 刚开始创建人物的时候，血量是满的
        this.hp = this.maxHp = hp;
        this.attack = attack;
        this.defense = defense;
    }
}
```

写到这里发现一个小细节：AI 生成的有参构造只让你传了一个 `hp`，`maxHp` 并没有跟着传进来。这是**故意**的——**刚开始创建人物的时候，他的血量是满的**，所以直接把传进来的 `hp` 同时赋给当前生命和最大生命，一行搞定。

另外提前说一句：这里我们把成员变量直接写成 `public`，没有逐个生成 `getXxx`/`setXxx`。这算"偷懒"，但好处很实在——后面调用属性的时候不用一个一个 `get` 一个一个 `set`，直接点出来就行，写起来简洁多了。

#### 父类里写四个行为

属性写完了，接下来是行为。父类里一共有四个行为，它们**两个子类都能用**。

**判断是否存活。** 因为是回合制游戏，我打敌人要判断敌人血量是不是零，敌人打我也要判断我血量是不是零，两个子类都要这个能力，所以放在父类：

```java
// 判断当前的游戏人物是否存活
public boolean isAlive() {
    return hp > 0;
}
```

大于零就是存活，小于等于零就是不存活。就这么一行。

**恢复血量。** 这跟我们刚写完的验证码很像——`getCode` 抽出来了，登录那边直接调。父类的行为也一样，两个子类都能直接用：

```java
// 恢复血量：amount 表示具体回了多少血
public void heal(int amount) {
    hp += amount;
    // 如果超过了最大生命，重置为最大生命
    if (hp > maxHp) {
        hp = maxHp;
    }
}
```

形参 `amount` 的含义很好理解——回了 10 点、20 点还是 30 点，得由调用方告诉我，这个信息就是 `amount` 提供的。

> **提示**：这里有个地方特别值得琢磨。有人会问，**回血不是只有玩家才有的技能吗？敌人根本没有回血技能**——战士是猛击，刺客是快速攻击，坦克是给自己加减伤 Buff，神秘法师是丢一个火球，都没有回血。那凭什么写在父类里？
>
> 因为我们写代码不能只看眼前这一个版本。随着工作经验越来越多，你会越来越明白：**版本会一点点往上加**。策划下一版会不会加一个叫萨满、或者叫医生的角色？会不会带一个回血技能？非常有可能。与其到时候再改继承结构，不如现在就把这个能力提前铺在父类里。这就是**为什么把回血写在父类中**。

**受到伤害。** 这是第三个行为：

```java
// 受到 damage 点伤害之后，还剩多少血
public void takeDamage(int damage) {
    hp -= damage;
    // 在游戏当中，人物的血量不可能为负数
    if (hp < 0) {
        hp = 0;
    }
}
```

`hp -= damage` 这行拆开就是 `hp = hp - damage`：当前生命减去受到的伤害。比如当前 100 点，受了 20 点伤害，得到 80，再赋回当前生命。

后面那个 `if` 判断同样重要——**血量不能是负数**。所以减完血之后如果小于零，就强制置为零。

**展示属性。** 最后一个行为，也最简单的：

```java
// 展示人物的属性
public void show() {
    System.out.println("姓名：" + name);
    System.out.println("生命值：" + hp);
    System.out.println("攻击力：" + attack);
    System.out.println("防御力：" + defense);
}
```

人物一创建出来，我真正关心的就这四样：你叫什么（你是谁）、你当前还有多少血、你的攻击力多少、你的防御力多少。至于技能啊、状态啊那些，我不想看，我只要这四个。所以 `show` 直接写在父类，子类拿来用就行。

#### 敌方为什么必须重写 takeDamage

到这里三个行为写完了。但有一个行为，敌方角色**必须重写**——就是 `takeDamage`。为什么？

因为敌方身上有一个 Buff：**减少伤害的状态**。拥有这个状态时，受到的伤害要减半。我方角色身上没有这个 Buff，所以 `HeroCharacter` 里**根本不用重写**，直接调父类的就行。

敌方就不一样了。需求文档里写着伤害的计算公式：**受到的伤害 = 攻击力 − 防御力**。

举个正例：我的攻击力是 40，敌方防御力 20，那伤害就是 $40 - 20 = 20$。但如果此时敌人正处在**防御姿态**下，就要拿这个 20 再去除以二，得到 10，这才是最终受到的伤害。

再来看一个**特殊情况**。假设我的攻击力是 20，敌方的防御力高到 40，**在没算防御姿态的情况下**，这个伤害已经被压到最小了。这时候再按规则除以二——伤害变成 `1 ÷ 2 = 0.5`，这行吗？

不行。两个原因：

1. Java 里整数相除，结果**还是整数**。`1 / 2` 的结果直接就是 `0`；
2. `0` 和"至少造成 1 点伤害"这个设定**直接矛盾**。

所以对防御状态下最终受到的结果，还要再做一次判断：**如果小于 1，就重置为 1**。

翻成代码就是：

```java
public class EnemyCharacter extends Character {

    // 敌人只有一个技能，用一个变量来表示
    public String skill;

    // 当前是否拥有减少伤害的状态（true 表示有 Buff）
    public boolean defending;

    public EnemyCharacter() {
    }

    public EnemyCharacter(String name, int hp, int attack, int defense,
                         String skill, boolean defending) {
        super(name, hp, attack, defense);
        this.skill = skill;
        this.defending = defending;
    }

    @Override
    public void takeDamage(int damage) {
        // 如果处于防御状态，那么此时我受到的伤害就要减半
        if (defending) {
            // 至少造成 1 点伤害
            damage = Math.max(1, damage / 2);
        }

        // 调用父类的方法去扣除血量
        super.takeDamage(damage);

        // 防御的状态只能持续一个回合
        this.defending = false;
    }
}
```

写完回头一看，会发现一件很有意思的事：**这一段扣血的逻辑，跟父类里的 `takeDamage` 是不是一模一样？**

一模一样的。既然一模一样，那在 `EnemyCharacter` 里面这扣血的部分就没必要自己再写一遍，直接用 `super` 去调父类的方法，然后把 `damage` 传过去就行了：

```java
if (defending) {
    damage = Math.max(1, damage / 2);
}

super.takeDamage(damage);   // 调用父类的方法去扣除血量

this.defending = false;
```

**子类只负责自己不一样的部分**——算出真正的伤害值；扣血这件苦力活，交给父类。

最后那行 `this.defending = false` 也很关键。防御姿态**只能持续一个回合**：这一回合我减伤了，减完之后马上把这个标记撤掉，下一回合它就不好使了。

对照着看，`HeroCharacter` 那边就清爽得多：

```java
public class HeroCharacter extends Character {

    // 我方角色有多个技能，所以用集合来表示
    public ArrayList<String> skillList;

    public HeroCharacter() {
        this.skillList = new ArrayList<>();
    }

    public HeroCharacter(String name, int hp, int attack, int defense) {
        super(name, hp, attack, defense);
        this.skillList = new ArrayList<>();
    }
}
```

注意空参构造里那句 `new ArrayList<>()`。AI 生成空参构造的时候顺手把这行也给你填上了，这**不是多余的**。它的好处是：以后在外部要给角色添加技能的时候，**不需要你自己创建集合**，直接 `add` 就行。

所以到这里，完整的继承结构就是：

- **父类 `Character`**（游戏人物），五个属性 `name` / `hp` / `maxHp` / `attack` / `defense`，四个行为 `isAlive()` / `heal(int)` / `takeDamage(int)` / `show()`；
- **子类 `HeroCharacter`**（我方角色），独有的只有一个 `skillList` 技能集合；
- **子类 `EnemyCharacter`**（敌方角色），独有的两个：单技能变量 `skill`，以及减伤 Buff 标记 `defending`，并且**重写**了 `takeDamage`。

共性的东西抽到父类，差异留在子类，这个结构就搭完了。

### 创建玩家角色：返回值与属性分配

接下来是难的部分：创建玩家的角色。创建的过程中要写一个挺难的东西，叫做属性分配。

先在 `FightingGame` 里写一个方法。返回值先不知道，先写 `void`，方法名就叫 `createPlayerCharacter`——`create` 创建、`player` 玩家、`character` 角色，这个方法的作用就是创建一个玩家的角色。参数把用户名 `username` 传进去，并给它写上注释。

#### 返回值：这个方法必须把角色交出来

它要不要返回值？所谓返回值，其实就是这个方法的结果。这个方法的结果是什么呢？你要想方法的作用是用来创建一个玩家的角色，那这个结果基本就呼之欲出了——结果就是我创建好的玩家角色。

我要不要把这个结果返回给调用处？结果是必须要的。为什么？因为第二步里我调用了 `createPlayerCharacter` 之后，下面我要用这个玩家角色去跟电脑的角色进行战斗啊，那肯定是要的吧，用它去 vs 它。所以我在下面是必须要使用到玩家角色这个对象的。

> **结论**：所以此时其实就是我们刚刚所写的 `HeroCharacter` 这个类的对象，返回值就是 `HeroCharacter`。把这个方法的方法体补全就可以了。

#### 三段雷同的代码

先写一个输出语句提示用户「创建您的角色」，然后在下面把用户名打印出来，就是「您的角色名为」后面直接加上 `username`。这就可以了。

接下来是属性分配。一共有多少点？在需求文档里已经看到了，它一共有 20 点，所以定义一个变量 `int points = 20`，这就是我现在要分配的属性点。

分配需要一个一个来：生命值每点加 10 点 HP，攻击力每点加 2 点 attack，防御力每点加 1 点 defense。这几行提示要先打出来，然后是生命值的录入。先按最直白的方式写一版：

```java
// 属性分配，一共 20 点
int points = 20;
System.out.println("请分配属性点（共" + points + "点）：");
System.out.println("生命值：每点加 10 点HP");
System.out.println("攻击力：每点加 2 点攻击");
System.out.println("防御力：每点加 1 点防御");

Scanner sc = new Scanner(System.in);

// 先写生命值这一段
int hpPoint = sc.nextInt();
if (hpPoint < 0) {
    System.out.println("无效的输入，默认分配 0 点");
    hpPoint = 0;
}
if (hpPoint >= points) {
    System.out.println("剩余的属性点是不足的");
    hpPoint = points;
}
points -= hpPoint;
```

攻击力和防御力这两段，跟上面**一字不差**，直接 `Ctrl+C` / `Ctrl+V` 复制过来，改一下变量名（`atkPoint`、`defPoint`）和提示语就完事了。

但这么写下去不行。在两段代码中间加个分割线你就能看出来——这两段是不是极度雷同？那你猜我下面还有一个防御力，是不是也会一模一样？当然是。

> **易错点**：我们现在在分配属性点的时候，其实就是把这一段代码循环执行三次。所以必须把这两段代码做一个改进。

#### 两道防线：负数和超额

在改进之前，先要考虑清楚它里面有哪些东西是不一样的。

先看录入之后的判断。键盘录入是可以接受负数的，那这负数我不想要，所以要判断：如果是小于零的，提示「无效输入」，说一句默认分配 0 点，然后把 `hpPoint` 强制变成零。

上面是负数的判断，那你觉得接下来我要判断什么？还能想到什么？还要判断一个东西：如果我键盘录入的值过大，超出了 20 点，你剩余的这个点数不够了，怎么办？你是不是也要修改？所以还要来一个判断——如果录入的值大于等于你剩余的 `points`，此时也得来一个提示，叫做「剩余的属性点是不足的」，然后把剩余的属性点全都分配到我当前要配置的这一项里，直接把当前的 `points` 赋值给 `hpPoint`。

| 你输入了什么 | 程序怎么判 | 提示 | 最终生效的值 |
| --- | --- | --- | --- |
| 负数 | `input < 0` | 无效的输入，默认分配 0 点 | `input = 0` |
| 超过剩余点数 | `input > points` | 属性点不足！剩余的属性点已全部分配到这一项 | `input = points` |
| 合法的值 | 两个条件都不成立 | 无 | 原样参与扣减 |

两道防线走完，真正的分配才开始。假设我现在生命值分配了 10 点，那我是不是先写 `points = points - hpPoint`？意思是现在 20 点，分配 10 点，那你剩余多少？还剩 10 点，再去把剩余的那个 10 点赋值给 `points`。

#### 用循环把三段合成一段

现在动手改进。第一样不一样的是**提示的属性名**：一开始是生命值，然后是攻击力，第三个肯定是防御力。所以先把三行输出语句合并成一个数组存起来：

```java
// 提示用的三个属性名
String[] attributes = {"生命值", "攻击力", "防御力"};

// 第二个数组用来记录三项各自分了多少属性点
// 比如生命值 10 点、攻击力 5 点、防御力 5 点，就是 {10, 5, 5}
int[] values = new int[3];
```

注意了，这第二个数组是用来记录三个属性分配的属性点的。再定义一个 `Scanner sc = new Scanner(System.in)`，然后用循环去分配属性点。循环可以直接遍历 `attributes`，当然你直接写 `for` 拿 `i` 去控制下标也都是可以的。

```java
Scanner sc = new Scanner(System.in);

for (int i = 0; i < attributes.length; i++) {
    // 提示：这一轮分的是哪个属性，还有多少点可以分
    System.out.print("分配点数到" + attributes[i] + "（剩余" + points + "点）：");

    // 当前用户键盘录入的属性点
    int input = sc.nextInt();

    // 第一道防线：不能是负数
    if (input < 0) {
        System.out.println("无效的输入，默认分配 0 点");
        input = 0;
    }

    // 第二道防线：不能超过剩余点数
    if (input > points) {
        System.out.println("属性点不足！剩余的属性点已全部分配到" + attributes[i] + "中");
        input = points;
    }

    // 计算一下剩余还有多少个属性点：20 - 10 = 10
    points -= input;

    // 把这一轮分配的属性点存下来
    values[i] = input;
}
```

这里有两个细节值得停一下。

第一个是**动态提示**。你说「分配点数到……剩余多少点」，这句话里的「生命值」是有可能发生变动的，可能是生命、可能是攻击、也可能是防御力。所以代码写成 `attributes[i]`：当 `i` 是零的时候，提示的就是「分配点数到生命值」；当 `i` 是 1 的时候就是攻击力；`i` 是 2 的时候就是防御力，就形成了一个动态提示的效果。后面再拼上「剩余 `points` 点」——这个没有任何问题，只不过要跟需求文档完全保持一致，需求文档里「剩余点数」后面没有点号，但有右括号，右括号的后面还有一个冒号。

第二个是**那段 `points -= input` 的位置**。代码执行到这里，意味着什么？意味着你当前键盘录入的、也就是你要分配的那个属性点，它不是负数，剩余的属性点它也是足够的。举个例子，假设我现在剩余的是 20 点，我键盘录入的是 10 点，那接下来我怎么办？很简单吧，我是不是要拿着 20 去减 10，计算一下还剩多少个属性点。

#### 用数组把分配结果记下来

然后再做一件事情：把键盘录入的、也就是那个 `input` 的分配属性点保存下来。保存到哪？保存到刚刚的 `values` 数组当中，`values[i] = input`，这就 OK 了。

至此属性分配的循环全部写完。循环结束之后，用户要分配的属性点是多少已经知道了，这个值在哪儿呢？就是在 `values` 这个数组当中：用户分配了多少属性点到生命值就是 `values[0]`，到攻击力就是 `values[1]`，防御力就是 `values[2]`，直接从数组当中拿，继续往下。

### 创建对象、挂技能，再原样返回


有同学说不对呀，这个公式你从哪来的？别忘了需求文档当中已经给出了。往上拉看这个地方，看生命值：初始血量 100，再加分配的点数去乘以十；攻击力就是十，加分配的点数乘以二；防御力默认是没有的，你分配一点他就加一点防御。这就是他计算的公式。

| 属性 | 基础值 | 每点加成 | 最终取值 |
| --- | --- | --- | --- |

| 攻击力 | 10 | × 2 | `10 + values[1] * 2` |
| 防御力 | 0 | × 1 | `0 + values[2] * 1` |

```java
// 展示当前角色拥有的所有技能
public String showSkill() {
    StringBuilder sb = new StringBuilder();

    for (int i = 0; i < skillList.size(); i++) {
        sb.append(skillList.get(i));

        // 如果不是最后一个元素，才补一个逗号空格
        if (i != skillList.size() - 1) {
            sb.append(", ");
        }
    }

    return sb.toString();
}
```

循环结束之后，就表示我那个集合里面所有的技能都已经拼接成了 `StringBuilder`，最后直接 `return sb.toString()` 变回字符串来进行返回。回到外面，此时就直接去拼接 `player` 点 `showSkill` 这个方法就可以了，相当于先去调用这个方法，再去把这个方法的结果跟前面的字符串做一个拼接。

## 战斗前的准备与回合内的结算：属性递增、随机抽敌与血条
> 对应块：BLK47 | 覆盖分集：P140-P141 | 块标题（分集名）：《第13章-06-战斗前（增强属性，选择敌人，打印》

接下来这一段是最难的，也是最刺激的——准备战斗。它难在哪儿？因为从这一步开始，"循环"第一次真正接进了游戏的主干里。

我们先把里面的步骤捋一遍。

### 战斗前的两步准备

第一步，重置敌人的属性。经常玩游戏的兄弟肯定知道，游戏里每一个敌人都应该遵守一个叫"越来越难打"的逻辑。假如你每个敌人的属性都跟刚创建出来那会儿一模一样——每次都是这样——那这游戏玩起来还有什么刺激感？每场都要有"挑战新 Boss"的感觉，对吧。

> **规则**：每场战斗，敌人的最大生命 +10、攻击 +3、防御 +2。

只不过有一点很容易忽略：**这个加点不是从第一场就开始的，是从第二场才开始**。第一场还是默认的初始属性。

第二步，随机选择敌人。这一步就简单了，用 `Random` 从集合里随机获取一个敌人，进来打就行。

敌人一旦选中，下面就到了回合制的核心逻辑：你打我一下，我打你一下，直到敌我双方有一方的血量为零为止。一旦有一方归零，就进入战斗结算。

#### 两个计数器，和一个大 while

动手之前先想清楚"谁在循环"这件事。

游戏里有个提示叫"第一场战斗开始"。这里面的"一"是一个可变的呀——第一场、第二场、第三场，你怎么打印？肯定得定义一个变量来统计。所以：

```java
int count = 1;   // 记录我当前是跟第几个敌人战斗
int wins  = 0;   // 记录我当前胜利了几场
```

然后是外层循环。我在这个游戏里是依次跟第一个敌人、第二个敌人、第三个敌人、第四个、第五个……一直打下去，直到我的生命值为零，游戏才结束。

```java
while (player.isAlive()) {
    // 里面依次做：重置属性、随机抽敌、打一场
}
```

> **提示**：`isAlive()` 是咱们在 `Character` 里早就写好的方法，判断角色的生命值是不是零，这里直接拿来当循环条件就行。

#### 重置敌人的属性

加属性这个动作有个前提：从第二场才开始。第二场开始意味着什么？意味着我第一场赢了。所以在下面的 `if` 里有两种写法，都对：

- 判断 `count > 1`；
- 判断 `wins != 0`——只要赢过一场，那就已经不是第一场了，第二场、第三场、第四场、第五场都算。

条件满足之后，就得拿到每一个敌人的信息，把属性点加上去。敌人的信息在哪？就在上面写好的那个集合里，遍历一遍：

```java
if (count > 1) {                       // 也可以写成 if (wins != 0)
    for (int i = 0; i < enemyList.size(); i++) {
        Character c = enemyList.get(i);

        // 最大生命 +10
        c.setMaxHp(c.getMaxHp() + 10);
        c.setHp(c.getMaxHp());         // 当前生命也要跟着一起改

        // 攻击 +3
        c.setAtk(c.getAtk() + 3);

        // 防御 +2
        c.setDefense(c.getDefense() + 2);

        // 很多同学会忽略：每场战斗前，把上一场的减伤 Buff 清空
        c.setDefending(false);
    }
}
```

`getMaxHp() + 10` 算完再 `setMaxHp` 回去，和直接写 `c.setMaxHp(c.getMaxHp() + 10)` 是一回事，这两种写法都 OK，下面几个属性同理。

> **易错点**：`setMaxHp` 改完，别忘了把 `setHp` 也跟着改一遍。血量上限涨了，人还躺在上一场的老血上，后面结算时的回血比例会全乱套。
> **易错点**：`defending` 这个减伤 Buff 必须每场清空。不清的话，上一场挨打时留下的格挡状态会一路带到下一场。

#### 随机选择敌人

程序一跑起来，外层 `while` 直接进循环——现在还没有战斗逻辑呀，它就会从集合里不停地、停不下来地在抽敌人。

这个过程怎么控制？非常简单：在下面再加一行代码，直接让程序停止。


### 两层循环的分工

接下来是游戏里最好玩、也最有意思的完整战斗过程。过程相对比较复杂，咱们先分析，再做代码实现。

在 IDEA 里新建一个 `test` 类，先把过程写成注释——它里面会有一些错误的伪代码，分析完就整个多行注释掉。

到现在为止咱们写了哪些东西？两个变量：`count` 记录当前跟第几个敌人战斗，`wins` 记录当前胜利了几场。第三部分是一个循环，循环里判断当前的玩家是否存活。

> **结论**：为什么要写这个循环？在游戏里我是依次跟多个敌人战斗的——敌人一、敌人二、敌人三、敌人四、敌人五，以此类推，只要玩家的生命不为零，就一直战斗下去。

循环里面的内容是这样的：

```text
count = 1, wins = 0

while (player.isAlive()) {                // 外循环
    5.1  重置敌人的属性
    5.2  随机抽取一个敌人

    round = 1
    while (player.isAlive()) {            // 内循环
        打印第 round 回合 + 双方血条
        我打敌人一下
        if 敌人血量 == 0  -> 结束内循环，回到外循环
        else 敌人还手打我一下
            if 我的血量 == 0  -> 结束整个游戏
            else round++，回到内循环顶部
    }

    5.4  结算：按比例回血 / 每胜三场加属性点 / 询问是否继续
}
```

要细化的主要就是第三步。回合制听起来简单，但我跟单个的敌人打斗，不可能说我打你一下、你打我一下这就完事了吧？所以跟单个敌人的战斗本身也得是一个循环，它的结束条件就是：直到有一方的血量为零，跟单个敌人的战斗才会结束。

| 循环 | 条件 | 管的是 |
| --- | --- | --- |
| 外循环 | `player.isAlive()` | 跟多个敌人依次战斗，一场接一场 |

内循环里的完整过程，顺序一点都不能乱：

1. 我打敌人一下，打完之后判断的是**敌人**的血量——因为此时挨打的是敌人。如果敌人的血量为零，就要结束当前的战斗，回到外循环去跟下一个敌人打。
2. 如果敌人的血量不为零，它就要还手，A 我一下。打完判断的就不是敌人了，而是**我**自己的血量——因为现在挨打的是我。如果为零，此时就要结束整个游戏。
3. 如果我的血量不为零，回到内循环的顶部；继续进入下一个回合之前，记得让 `round` 加加。

#### 一个方法搞定双方

敌我双方都要打印，所以在下面定义一个方法：想打印我方就把我方的数据传进去，想打印敌方就把敌方的数据传进去，非常简单。

```java
public String getHpBar(String name, int hp, int maxHp) {
    // 满血状态下，一共打印 20 个方块
    int barLength = 20;

    // 当前血量在总血量中的比例，换算成要点亮多少格
    int filled = (int) (hp * 1.0 / maxHp * barLength);

    StringBuilder sb = new StringBuilder();
    sb.append(name).append(": [");

    for (int i = 0; i < barLength; i++) {
        if (i < filled) {
            sb.append("■");
        } else {
            sb.append(" ");
        }
    }

    sb.append("] ").append(hp).append("/").append(maxHp).append(" ");
    return sb.toString();
}
```

返回值是 `String`，因为最终效果一定是一个字符串。参数一共三个：人物的名字、当前的血量、最大血量。就这三个数据就够用了。

**那方块的个数到底是怎么算出来的？** 假设最大生命是 200，而当前生命是 100——这个都不用口算，我就知道一定是 10 个方块加 10 个空白。但关键是这个"10"怎么算出来的。我们在数学里学过分数和百分比，当前生命除以最大生命就是一个分数，再去乘以 20，就是格数。

> **易错点**：这里必须先给 `hp` 乘一个 `1.0`。因为在 Java 当中整数相除，最终的结果只能得到一个整数。举个例子，当前生命是 10、最大生命是 200，真值是 `0.05`；如果你没乘 `1.0`，整数相除的结果就直接给你 `0` 了，那这一格就打成 0 个方块——明显不合理。乘上 `1.0` 之后它才是一个小数，再去乘 `barLength`，最后把结果**强转**成 `int`，这才是我想要的。

链式 `append` 这件事值得多说一句。很多人写字符串拼接会老老实实一行一个 `sb.append(...)`，其实不用这么费劲——按住 `Ctrl` 不松，用鼠标左键点一下 `append` 进去看看，非常有意思，它 `return` 的是一个 `this`，简单来说就是把那个调用者给你返回了。所以后面可以继续 `.append` 去添加冒号、添加左括号。

循环固定 20 次就行，直接写死 20 次，或者用上面的 `barLength` 去控制 `for` 的次数，这是一回事。

最后还差右括号、当前生命、斜杠、最大生命这几段。这部分让 AI 自动生成往往会把右括号安到 `hp` 后面去，不是你想要的，直接照需求文档里的最终效果粘过来改就行。所有数据都拼接完，`return sb.toString()`，把它转回字符串再返回上去。


#### 把 default 挪到最上面去省代码

写完记得加 `break`，不然会引发 case 穿透现象。

那有没有异常情况？比如用户键盘录入的是 4、5、6，那要不要判断？肯定要。我的处理是：**默认采取普通攻击**。所以 `default` 里面也去执行普通攻击。

你发现没有——`default` 里面的代码，跟 `case 1` 里面的代码完全一致。既然一样，之前我们学过，当多个 `case` 里的语句体是一样的时候，就可以用 case 穿透来节约代码。所以我把 `default` 写在最上面，没有任何问题：


#### 先把伤害公式抽成一个方法

普通攻击是什么？不就是我打你一下吗。我打你一下的效果怎么表示？非常简单，就是用我方的攻击力减去对方的防御力，这样就得到一个伤害。这个计算公式在需求文档里已经写了。

但有一个问题：**最小的伤害是一点**。这句话什么意思？假设我方攻击是 40 点，对方防御力是 50 点，那么 40 减 50 是负数——你总不能给对方去回血吧？所以在这种情况下，最小伤害应该是一点。

而在代码当中我很多地方都要去计算伤害：普通攻击要算、强力一击要算，等一会儿敌人打我的时候是不是也要算？所以此时我干脆在下面再去写一个方法，专门用来计算双方战斗时造成的伤害：

```java
public int calculateDamage(int attack, int defense) {
    int damage = attack - defense;
    if (damage < 1) {          // 写成 damage <= 0 也一样
        damage = 1;
    }
    return damage;
}
```

这个方法只有两个形参：攻击 `attack` 和防御 `defense`。让 AI 直接生成 `return attack - defense` 是不对的，得先把 AI 生成的代码改动一下，用一个变量记录下来，再判断。

在外面调用的时候：想算普通攻击的伤害，就把 `player` 的攻击力、`enemy` 的防御力作为参数传进去；如果我是用技能去打对面，那在传递之前先把攻击力乘上百分比算好，再传给方法，这样方法就能算技能攻击造成的伤害了。

### 用一个随机数把 50% 掷出来

先定义一个变量 `action`，它表示敌人一会儿要采取的攻击手段，默认赋值成"普通攻击"。这个默认值是刻意的——**不管后面怎么随机，先按普攻兜住**。

概率怎么写？`Random r = new Random()`，然后 `r.nextInt(10)`，取到的就是 0 到 9，一共十个数字：0、1、2、3、4 是五个，5、6、7、8、9 又是五个。所以随机到 0~4 就是普通攻击，随机到 5~9 就是技能攻击——各占一半，刚好对上需求里的 50%。

如果命中的是技能攻击，再去问当前这个敌人到底是谁、用什么技能。因为 `enemy` 对象里有一个 `skill` 属性，直接用对象去调用里面的技能，把它赋值给 `action` 就行了。

```java
// 敌人要采取的攻击手段，默认普通攻击
String action = "普通攻击";

Random r = new Random();
int n = r.nextInt(10);          // 0~9
if (n >= 5) {
    // 技能攻击：具体是哪个技能，看当前敌人是谁
    action = enemy.getSkill();
}
```

`n` 这段按 Ctrl + V 的时候 IDEA 会在左边自动生成名字，别自己想半天叫什么，就叫 `n`。这段逻辑捋一遍：先定义 `action` 默认普通攻击，下面掷骰子算概率，如果 `n >= 5` 就认为要采取技能攻击，再把当前敌人的技能拿出来赋值给这个变量。**你当前敌人是谁，我就把他的技能拿过来赋给这个变量。**

### 一个 switch 走完五种出手

`action` 现在有值了，接下来就是对它做判断，用 `switch (action)`，把小括号里的 `action` 传进去，下面写多个 `case`。五种情况，全部列出来：

| 敌人 | 技能 | 效果 |
| --- | --- | --- |
| 通用 | 普通攻击 | 按公式原样计算伤害 |
| 战士 | 猛击 | 伤害乘 150%，结果强转 int |
| 刺客 | 快速攻击 | 伤害乘 50%，但要打两次，两次累加 |
| 坦克 | 防御姿态 | 不造成伤害，自身进入减伤 Buff |
| 法师 | 火球术 | 伤害乘 180%，结果强转 int |

```java
switch (action) {
    case "普通攻击":
        // ...
        break;
    case "猛击":
        // ...
        break;
    case "快速攻击":
        // ...
        break;
    case "防御姿态":
        // ...
        break;
    case "火球术":
        // ...
        break;
}
```

只有这五种情况，没有其他情况，因为代码里就只写了这些。所以 `switch` 后面那个 `default`，想写也可以，不写也没问题。接下来一个一个把它们填完。

#### 普通攻击：伤害先算，再扣血

跟刚刚一样，先调前面写好的 `calculateDamage` 方法，把这一段复制粘贴过来就行。但这里有个必须改的地方：

```java
case "普通攻击":
    // 计算敌人用普通攻击给我造成了多少点伤害
    int damage1 = calculateDamage(enemy.getAttack(), player.getDefense());

    System.out.println("💥" + enemy.getName()
            + " 对你使用了普通攻击，造成 " + damage1 + " 点伤害");

    player.takeDamage(damage1);
    break;
```

> **易错点**：现在是**敌人打我**，所以传进去的顺序是敌人的攻击、玩家的防御。我方回合里正好是反过来的——玩家的攻击、敌人的防御。两个方法名长得像，参数一换方向就整个反了，这里改之前务必再看一眼。

打完之后 enemy 打了 player，血量要扣，所以用 `player` 去调 `takeDamage`，把真正造成的伤害 `damage1` 传进去。写完按 Ctrl + Alt + L 格式化一下代码。

#### 猛击：乘 1.5，还得强转

战士的技能是猛击。先算伤害，同样把 `calculateDamage` 那一段粘过来。但百分比是多少？往上翻需求文档：**战士的技能百分比是 150%，刺客是 50%（但是要打两次），坦克是加一个 Buff，法师是 180%。**

所以猛击这里要乘以 1.5。又因为它最终计算的结果是一个小数，所以要对它做一个强转，把它强转成 int 类型的整数。

```java
case "猛击":
    int damage2 = (int) (calculateDamage(enemy.getAttack(), player.getDefense()) * 1.5);

    System.out.println("💥" + enemy.getName()
            + " 对你使用了猛击，造成 " + damage2 + " 点伤害");

    player.takeDamage(damage2);
    break;
```

提示语不用自己写——需求文档里本来就有，一个爆炸的图标加上"敌人对你使用了猛击，造成 XX 点伤害"，直接 Ctrl + C 再 Ctrl + V 粘过来，把变量换掉就行。下面还是一样，我方扣血，用 `player` 去调 `takeDamage`，把 `damage2` 传过去。

> **提示**：`(int) (伤害 * 1.5)` 里的强转不能省。不强转的话，方法返回的 double 赋给 int 变量会直接编译不过；就算能过，多出来的那点小数伤害也不会体现在血量上。

#### 快速攻击：打两次，得有个累加器

刺客的快速攻击跟前面不一样，**它是要打两次的**。所以要写一个循环，`for (int i = 0; i < 2; i++)`，在循环里面计算当前的值。因为快速攻击是 50%，所以直接用 `calculateDamage(...)` 的结果除以 2 就可以了。

麻烦的地方在：两次伤害要做一个**累积**。所以在循环外面先定义一个变量 `damage3` 并赋值为 0，循环里面再改一个临时的变量叫 `temp`，每算出来一次就把 temp 累加到外面的 `damage3` 上。

```java
case "快速攻击":
    int damage3 = 0;                       // 两次伤害的总和

    for (int i = 0; i < 2; i++) {
        int temp = (int) (calculateDamage(enemy.getAttack(), player.getDefense()) / 2);
        damage3 = damage3 + temp;          // temp 是临时的，累加给 damage3
    }

    System.out.println(enemy.getName()
            + " 对你使用了快速攻击，造成 " + damage3 + " 点伤害");

    player.takeDamage(damage3);
    break;
```

`temp` 就是 temporary 的意思，temp、time end 都表示"临时的"。当循环结束之后，就表示刺客对我这两次攻击造成的**总伤害**已经计算出来了。

下面提示语继续从需求文档粘——小圈圈的图标，后面拼上 `enemy.getName()`，其实就是刺客的名字，然后说"对你使用了快速攻击，造成 XX 点伤害"。再往下照旧扣血，把 `damage3` 传过去。

#### 防御姿态：唯一不造成伤害的技能

坦克的技能防御姿态跟前面完全不一样——**它相当于给自己加了一个 Buff，不会给对方造成伤害**。所以这里不调 `calculateDamage`，也不调 `takeDamage`，只做一件事：把变量置为 `true`。

哪个变量？还记得前面写"加 buff"的时候，我在敌人这个类里面定义了变量 `defending`，它就是用来统计当前这个敌人是不是有这个 Buff 的。它是**成员变量**，成员变量是有默认初始化值的，布尔类型的默认初始化值是 `false`，就表示你当前没有这个状态。但如果我在代码里把它改成 `true`，是不是就表示当前拥有了这个状态？

```java
case "防御姿态":
    enemy.defending = true;

    System.out.println("🛡" + enemy.getName() + " 摆出了防御的姿态");
    break;
```

一旦拥有状态之后会怎样？我在下面已经对 `takeDamage` 这个方法做了一个**重写**——当我用 `enemy` 去调 `takeDamage` 的时候，他一开始会去判断你当前的这个值是不是 `true`。是 `true` 的话，当前受到的伤害就会**除以二**，也就是减半；如果没有这个状态，就直接去调用父类的方法，直接扣除血量。这就是我们一开始写的那段代码。

不过现在我要问屏幕前的兄弟姐妹们一句：**你觉得这个 `defending` 在什么时候还能变回 `false`？你还记得吗？**

在 `EnemyCharacter` 里面的 `takeDamage` 方法里——只要你挨了一次伤害，就把它再置为 `false`。相当于这个防御的效果**只能持续一个回合**。

#### 火球术：一个模子刻到底

最后一个，法师的火球术。逻辑跟猛击一模一样：先调 `calculateDamage` 把伤害算出来，把敌人的伤害和我方的防御传进去，方法会把造成的伤害计算好返回给你。

```java
case "火球术":
    int damage4 = (int) (calculateDamage(enemy.getAttack(), player.getDefense()) * 1.8);

    System.out.println("🔥" + enemy.getName()
            + " 对你使用了火球术，造成 " + damage4 + " 点伤害");

    player.takeDamage(damage4);
    break;
```

提示语同样从需求文档粘——"谁谁谁对你使用了火球术，造成多少点伤害"，改一下里面的变量。下面扣血，把 `damage4` 传进去，最后别忘了写 `break`。

整个敌方回合的流程长这样：

```text
enemyTurn(enemy, player)
        │
        ├─ action = "普通攻击"          ← 默认先按普攻兜底
        ├─ n = r.nextInt(10)            ← 掷一个 0~9 的骰子
        │    └─ n >= 5 → action = enemy.getSkill()   ← 技能攻击，具体技能看敌人是谁
        │
        └─ switch (action)
             ├─ 普通攻击 → calculateDamage(enemy.attack, player.defense) → takeDamage
             ├─ 猛击     → 伤害 × 1.5（强转 int）        → takeDamage
             ├─ 快速攻击 → for 两次，每次伤害 ÷ 2，temp 累加进 damage3 → takeDamage
             ├─ 防御姿态 → enemy.defending = true（不打人，挨打时伤害减半）
             └─ 火球术   → 伤害 × 1.8（强转 int）        → takeDamage
```

读图就是一句话：**先把"用哪一招"这件事定下来，再按这一招去算伤害、扣血；唯独防御姿态例外，它根本不算伤害，只是把自己标记成挨打减半的状态。**

> **结论**：这段代码比我方的回合要复杂一点，原因就在"不同的敌人走不同的分支"上。多出来的复杂度全部来自这个 switch，伤害计算和扣血这两件事本身和玩家回合没有任何区别。

```java
// 判断玩家是否被击败
```

### 结算该写在哪儿

战斗过程写完了，接下来是第 5.8 步——**战斗结算**。跟一个敌人的战斗结束之后，玩家胜利就恢复生命值、继续战斗；玩家失败，整个游戏就会停止。

这段代码相对来讲比较复杂，所以先回到 `Test` 类里去分析整体结构，再动手写。现在内层 `while` 已经全部写完了，先回顾一下两个循环各管什么：

```text
while (还有敌人)                    ← 外循环：表示我现在要跟多个敌人进行战斗
{
    while (还有一方没倒下)           ← 内循环：跟单个敌人进行多回合的战斗
    {
        playerTurn();                        // 5.4 我方回合
        if (!enemy.isAlive()) break;         // 5.5 判断敌人是不是被击败
        enemyTurn(enemy, player);            // 5.6 敌方回合
        if (!player.isAlive()) break;        // 5.7 判断玩家是不是被击败
        round++;
    }

    // 跟单个敌人的战斗结束了 → 战斗结算写在这里
    // （内循环的外面、外循环的里面）
    if (player.isAlive())
    {
        // 5.8  恢复血量
        // 5.9  每胜三场，提升属性
        // 5.10 询问玩家是否继续
    }
}
```

> **定义**：**内循环的结束点，就是单场战斗的结束点。** 结算必须写在"内循环之外、外循环之内"——写在它里面会每回合结算一次，写在外面则整场游戏只结算一次。

回到 `FightingGame` 类里，先把内循环收起来，这样写代码会更加清晰，然后在它下面写 5.8。先来一段注释：**跟一个敌人的战斗结束之后，如果玩家胜利我们要继续战斗，如果玩家失败游戏就会整个停止。**

然后 `if (player.isAlive())` 判断玩家是否存活，存活了就往下走。结算一共三部分：给我方进行一定的回血；如果连胜三场，增加我方人物的属性；再问你**要不要继续下一次战斗**——要玩就再给你随机第二个敌人，不玩了整个游戏全部结束。

#### 恢复血量：20 到 40 之间随机

恢复多少？需求文档的战斗系统下面有战斗结算这块：**胜利的时候恢复 20~40 点生命，胜利的场数加一，每三场要去属性点进行提升，失败的时候游戏要结束。**

随机 20~40 有两种写法。第一种直接写上下界：

```java
// 计算玩家要恢复多少点血
int hp = r.nextInt(20, 41);   // 包头不包尾、包左不包右，41 取不到
```

第二种是 `r.nextInt(21) + 20`。为什么这样子也可以？前面这一部分相当于就是在 0~20 之间获取一个随机数，那么在这个范围当中不管随机到的是什么数，统一都加 20，最终的结果不就是 20~40 吗？

```java
// 计算玩家要恢复多少点血
int hp = r.nextInt(21) + 20;   // 0~20 统一加 20，结果同样是 20~40
```

代码写完之后你会发现这里的 `r` 报错了——它说变量 `r` 已经重复了。往上找找，就会发现在上面**随机选择敌人**的时候已经创建过一个 `r` 的对象了。所以下面直接用上面那个 `r` 去调用就行了，没必要反复创建，删掉这一句就好。

然后是真正恢复血量：

```java
// 计算玩家要恢复多少点血
int hp = r.nextInt(21) + 20;

// 恢复玩家的血量
player.heal(hp);

// 战斗结束了
System.out.println("战斗结束了，你恢复了 " + hp + " 点生命值");
// 胜利的 N 场
```

注释我写得更清楚一点：一个管"计算玩家要恢复多少点血"，一个管真正的回复血量——这两句很容易混在一起。

下面的提示语句需求文档里现成的就有，找一找："你击败了敏捷刺客之后"，下面要有一个提示，就是**战斗结束了、你恢复了 36 点生命值**，然后再统计一下当前你胜利了几场。这两段可以直接从需求文档 Ctrl + C，回到 IDEA 里 Ctrl + V 粘过来，**甚至可以用 AI 自动生成**——你发现战斗结束了、你恢复了这么多点血、胜利的 N 场，AI 全给你生成了，然后把注释删掉，非常方便，不需要我们自己写。

#### 每胜三场：加的是最大生命，不是当前生命

成长值在需求文档里也有：每胜利三场，**最大生命加 30，攻击力加 5，防御力加 3**。

先做判断。前置条件还是玩家存活——玩家不存活，增加属性点是没有意义的。第二个条件是 `wins`，还记得这个变量是什么吗？往上翻，`wins` 记录的就是我当前胜利了几场，在内循环当中我方胜利的时候对它做了一个 `++`，连胜的计数器自增。

```java
if (player.isAlive() && wins > 0 && wins % 3 == 0) {
    System.out.println("恭喜你获得了属性点的提升");

    player.maxHp += 30;      // 最大生命 +30
    player.attack += 5;      // 攻击力 +5
    player.defense += 3;     // 防御力 +3

    System.out.println("当前最大生命值已经加了 30，攻击力也加了 5，防御力也加了 3");
    System.out.println("当前属性：" + player.show());
}
```

`wins % 3 == 0` 表示的是三的整数倍，那就是每胜利三场呗。

> **易错点**：这里加的**不是当前生命，是最大生命**。当前生命是上面回血那部分管的，这里提升的是 `maxHp`。用 `maxHp = maxHp + 30` 再赋值回去当然也对，直接写 `maxHp += 30` 同样没问题，怎么方便怎么来。

最后再输出一条提示，把人物当前的属性打印一下——直接用 `player` 去调 `show` 方法，刚好把 `show` 方法的返回值进行一个打印。

#### 问一句要不要继续

继续的前提同样还是玩家存活，所以先 `if (player.isAlive())`，看看你当前的生命是不是大于零的。活着的话，就让你键盘录入：

```java
System.out.println("请问你是否需要继续下一场战斗（yes/no）");
Scanner sc = new Scanner(System.in);
String choose = sc.nextLine();          // 用户的选择
```

接下来用 `choose` 去调用 `equals`。**注意**：如果说用户在键盘录入的时候录的是小写的或者大写的，我认为你都是同意的，所以调用 `equals` 的时候最好是调用 `equalsIgnoreCase`，这样可以忽略大小写。

用户输入 `yes`，就表示战斗继续。那要修改哪个变量呢？就是 `count`，要去 `++`。按住 Ctrl 点一下 `count`，它就会跳转到上面定义的地方——它是记录了当前我是跟第几个敌人进行战斗的。

> **易错点**：如果在这个地方没有做 `count++`，就会形成我们刚刚运行的那个结果——一开始是第一个敌人，等第一个敌人打败了，下面还是第一个敌人。最根本的原因就是 `count` 没有自增，而"你是第 count 场战斗开始"这句提示用的正是 `count`。现在对它加加，后面提示的时候就会有错落的感觉：第一场、第二场、第三场。

```java
if (choose.equalsIgnoreCase("Y")) {
    count++;                 // 下一场是第几个敌人
    continue;                // 结束本次循环，继续下次循环
} else {
    // 玩家不想继续玩了，跳出循环，整个游戏全部结束
}
```

`count++` 之后再来一个 `continue`。这里 `continue` 的意思就是**循环我要继续执行**，开始跟下一个敌人来进行战斗。你要想嘛，`continue` 是什么？它叫做**结束本次循环，继续下次循环**，相当于就直接跳转到外循环的这个地方，看，是不是就准备开始战斗了。

> **提示**：`choose.equalsIgnoreCase("Y")` 这样写没问题，但以后遇到这种**已经明确知道数据是什么**的字符串比较，一般会把那个确定的常量写在前面——`"Y".equalsIgnoreCase(choose)`。这样代码会更稳妥，不容易出异常。

至于选 `no` 的分支，直接 Ctrl + C、Ctrl + V 粘过来，那是一个 `N`，如果是 `no` 的话循环就结束，它表示玩家不想继续玩了，这时候就会跳出循环，整个游戏全部结束。

还有第三种情况：用户录的既不是 `Y` 也不是 `N`，是别的怎么办？那就提示"没有这个选项"，然后**默认游戏继续**，相当于就是按任意键继续了。

到这里，单场战斗结束之后的战斗结算就全部写完了：**恢复血量、每胜三场提升属性、再提示用户是不是继续**。这三段自己完成一下，稍等几秒钟，我们要去写整个游戏的最终结算了。

> **结论**：结算的三块都挂在同一个前提之下——`player.isAlive()`。玩家一旦倒下，回血、成长、继续这三件事统统不该发生，游戏到此为止。这一个判断，把整段结算干净地切成了"继续"和"结束"两种命运。

### 最终结算写在哪：外循环之外

动笔之前先分析结构，这次要回答的问题很具体：**最终结算这段代码，我到底写在哪儿？写在外循环的里面，还是写在外循环的外面？**

这个位置很重要，不能想当然。

```text
public class FightingGame {

    public static void main(String[] args) {

        ① 显示游戏封面
        ② 创建玩家角色 Role
        ③ 显示玩家属性和技能
        ④ 创建多个敌人

        ⑤ while (还有存活敌人) {            ← 外循环：一场一场地打
               随机选中一个敌人
               第二场战斗开始……
               我方回合
               敌方回合
               战斗结算：回血、连胜三场升级、
                         问玩家是否继续下一场
           }

        ⑥ 最终结算                          ← 写在 while 的外面
        ⑦ System.exit(0);
    }
}
```

> **易错点**：把结算代码写在 `while` 里面，它结算的就不是整个游戏，而是**单场战斗**——也就是你跟单个敌人打完之后的结算。现在这个场景是"我整个游戏都不想玩了，要看总账"，所以必须写在**外循环的外面**，这样它在整个 main 里只会被执行一次。

> **定义**：外循环的作用是"我要跟多个敌人进行战斗"。一轮 = 一场单挑；外循环退出 = 整场游戏结束。所以"单场结算"挂在内层，"最终结算"挂在外层之后——这两层各管各的账。

先把之前那段临时代码注释掉，然后打开 `FightingGame` 来写。为了让代码看得清楚一点，把内外两层循环折叠起来，整个 main 的骨架一下子清爽了：五步准备，第六步结算，第七步停机。

### 结算代码与一次完整试玩

最终结算就是几个输出语句。为了跟别处的输出做区分，第一句先打印一条华丽的分隔线——把前面写过的那条 `Ctrl + V` 直接粘过来。然后是"游戏结束！"，再是总胜场，后面把刚刚那个 `wins` 拼上去，最后一句感谢玩家。


`System.exit(0)` 括号里写 `0`，虚拟机就停了。**别忘了写这一句**——不写的话程序虽然算完了 `main`，控制台还挂着，你也看不出这是一个"完整跑完"的游戏。

### Math 类：一个用来做数学计算的工具类

现在开始学 Java 里的常见 API。

API 这个词其实我们并不陌生——**它就是 JDK 提供的各种功能的 java 类**。这些类 java 已经提前写好了，我们不需要关心类里面是怎么实现的，知道它们如何使用就可以了。

之前我们已经学过几个：表示键盘录入的 `Scanner`、表示获取随机数的 `Random`、表示字符串的 `String`、以及可以存储多个数据的集合 `ArrayList`。

> **定义**：API（Application Programming Interface，应用程序编程接口）。在 Java 里，它的落地形态就是 JDK 提供的那些现成的类——你调它的方法，它替你干活。

本阶段要继续往下学的有：跟数学相关的 `Math`，跟系统相关的 `System`，所有类的爹 `Object` 以及对象工具类 `Objects`，还有八个基本数据类型所对应的**包装类**，以及表示大正数的 `BigInteger`、进行精确运算的 `BigDecimal`，跟时间日期相关的所有的类，还有可以操作数组的工具类 `Arrays`，以及最后一个——可以对字符串的格式进行校验的**正则表达式**。

内容稍微有点多，但都不难，无非就是方法的调用而已。以前我们可能还需要去背这些方法，但现在不用了，有了 AI 不需要记，**知道它们在什么时候用**就可以了。

#### 工具类的书写格式

先从 `Math` 开始。它是一个可以用于进行数学计算的工具类。

说到工具类，你还记得它是怎么写的吗？规则三条：

```text
① 类名要见名知意
② 构造方法要私有化，不让外界创建它的对象
③ 里面的方法都定义成静态的，直接用类名调用
```

`Math` 完全遵守这三条。它的构造方法被 java 私有了，所以我们在代码当中**无法创建它的对象**。你要是强行去写 `Math m = new Math()`，立刻就出红色波浪线，鼠标悬停上去提示得很清楚：构造方法已经被 `private` 关键字修饰了。

它里面所有的方法都是用 `static` 修饰的，所以都是静态的，后面调用的时候**直接用类名 `Math` 点一下就可以**。

#### abs 与两种取整：ceil 和 floor

第一个方法 `abs`，获取绝对值。正数就是它本身，负数就是它的相反数。

```java
int n1 = Math.abs(10);      // 10
int n2 = Math.abs(-10);     // 10
```

第二个方法 `ceil`，**向上取整**。传进去 `10.11`，结果是 `11.0`；传 `11.55`，结果还是 `11`。所谓向上取整，其实就是我们数学当中说的**进一法**。

第三个方法 `floor`，跟 `ceil` 正好相反，它叫**向下取整**，也就是数学里的**去尾法**——不管小数点后面是多少，一律去掉。

```java
System.out.println(Math.ceil(10.11));    // 11.0
System.out.println(Math.ceil(11.55));    // 11.0
System.out.println(Math.floor(10.11));   // 10.0
```

> **提示**：`ceil` 和 `floor` 的返回值都是 `double`，所以打印出来会带 `.0`。`ceil` 是进一法（跟"天花板"同名，向上顶到整数），`floor` 是去尾法（跟"地板"同名，直接往下掉到整数），名字已经把行为告诉你了。

#### round：正数人人都会，负数在点五上翻车

第四个方法 `round`，表示四舍五入。正数这里我相信你不需要演示：

```java
System.out.println(Math.round(10.11));   // 10  后面没满五，四舍五入还是 10
System.out.println(Math.round(11.55));   // 12  后面满五，向上进位
```

但这个方法有个**小细节**——它跟数学里的四舍五入，其实还是有一点点小小的区别。区别在哪儿？在**负数**的情况下。

```java
System.out.println(Math.round(-10.11));   // -10
System.out.println(Math.round(-10.55));   // -11
System.out.println(Math.round(-10.5));    // -10   ← 注意，不是 -11
```

很多同学看到第三条会喊：不对吧？`-10.5` 四舍五入明明该是 `-11`，怎么是 `-10`？

我们来看它的规则。`round` 方法在底层的规则是这样的：**返回与参数最近的整数；如果说有多个，就返回正无穷大方向的那个数据。**

这句话怎么理解？画一个数轴就明白了——数轴是朝着正无穷大方向延伸的：

```text
                    正无穷方向 →
   ...───┼───┼───┼───┼───┼───┼───┼───...
       -3  -2  -1   0   1  1.5  2   3
                   ●
      参数 1.5：最近的整数有两个 → 1 和 2
                取正无穷方向的那个 → 结果是 2


                    正无穷方向 →
   ...───┼───┼───┼───┼───┼───┼───┼───...
       -4  -3  -2  -1.5 -1  0   1   2
                  ●
      参数 -1.5：最近的整数有两个 → -2 和 -1
                 取正无穷方向的那个 → 结果是 -1
```

所以看图就明白了：`1.5` 的结果刚好跟四舍五入一致，因为正无穷方向是 `2`；而 `-1.5` 最近的整数有两个——`-2` 和 `-1`，正无穷方向的那个是 `-1`。同理，`Math.round(-10.5)` 返回的就是 `-10`。

> **易错点**：`round` 可以理解成四舍五入，但它跟数学上的四舍五入**唯一的区别**就是：**负数的小数位刚好是 `.5` 的时候，它采取的是舍去操作**。所以判断"四舍五入后是不是它"，一定要避开 `-10.5` 这种临界值去自测。

#### max 与 min：一行三元运算符

第五个 `max` 我相信非常简单——就算我现在不知道这个方法，自己写代码也能实现。它就是**返回两个数据当中的较大值**：

```java
System.out.println(Math.max(10, 20));   // 20
System.out.println(Math.min(10, 20));   // 10
```

它可以传 `int` 类型，也可以传 `long`、`float`、`double`，重载了好几份。点进源码你会发现，它内部就是一句三元运算符的比较而已。

与它对应的还有一个 `min`，返回两个数据当中的**较小值**。

#### pow：一个方法，三种用法

下面这个叫 `pow`，它可以返回 a 的 b 次方。

之前我们写 2 的 3 次方是怎么写的？`2 * 2 * 2` 咯，写出来的代码相对来讲比较 low。学完 `pow` 之后就非常简单了：

```java
System.out.println(Math.pow(2, 3));    // 8.0
```

调用同样是类名点方法名，里面两个参数，第一个是 a，第二个是 b，计算的是 a 的 b 次方。注意最终的结果是一个 `double` 类型的小数。

而 `pow` 真正的价值，在于它的**隐藏用法**。

**第一种：开根号。** 四开根号等于几？不就是 2 吗。三开根号等于 1.732……一大堆小数。那 `pow` 怎么开根号？非常简单——前面写 4，后面写 `0.5`。`0.5` 的意思就是获取 4 的 $1/2$ 次方，那不就是开根号吗。

```java
System.out.println(Math.pow(4, 0.5));     // 2.0     √4
System.out.println(Math.pow(3, 0.5));     // 1.732…  √3
```

**第二种：负指数，也就是倒数。** 四的 `-0.5` 次方是什么？就是 4 的 $-1/2$ 次方，$1/2$ 开根号再加一个负数。

```java
System.out.println(Math.pow(4, -0.5));    // 0.5     即 1/√4
```

`pow` 这个方法用处非常非常广，只不过平时用得最多的是上面第一种。以后要做一些复杂的数学计算，下面的隐藏用法你也会用到。

**那什么时候用 `pow`，什么时候用专门的方法？** 如果你现在**仅仅**是想获取平方根或者立方根这种比较特殊的开方操作，其实有两种写法：

| 需求 | 写法 A | 写法 B |
| --- | --- | --- |
| 平方根 | `Math.pow(n, 0.5)` | `Math.sqrt(n)` |
| 立方根 | `Math.pow(n, 1 / 3)` | `Math.cbrt(n)` |

左边是用 `pow` 写，第二个参数写 `0.5`；立方根你就写 `1 / 3` 就可以了——因为 $\frac{1}{3}$ 是 `0.33` 循环的，你光写一个 `0.3` 是没有用的（那算的是 0.3 次方，压根不是立方根）。

右边是 `Math` 专门为平方根和立方根准备的两个方法：`sqrt` 直接获取平方根，`cbrt` 直接获取立方根。

```java
System.out.println(Math.sqrt(4));    // 2.0   √4
System.out.println(Math.cbrt(27));   // 3.0   ∛27
```

所以以后如果你想获取平方根或者立方根，直接用这两个方法就可以了。但是如果数学计算比较复杂，比如要获取 $-1/2$ 次方，那只能老老实实用 `pow`。

#### random：0.0 到 1.0，和它的底层

最后一个方法叫 `random`，获取随机数。这个混个眼熟就行，不需要掌握。

它可以获取 **0.0 到 1.0 之间的随机小数，包含 0.0，但不包含 1.0**——就是我们之前说的**包左不包右、包头不包尾**。

```java
System.out.println(Math.random());   // 0.523…
System.out.println(Math.random());
```

它是**空参方法**，返回值是一个 `double`。只不过这个方法以后我们不常用，真要获取随机数还是用以前那个 `Random`。

> **提示**：不过我们可以点进源码看看 Java 到底是怎么做的。源码里那一大堆东西最后调用的是 `nextDouble`。怎么断定前面那一大坨是个对象呢？因为方法在调用的时候一定会有小括号。至于具体是什么对象，再点进去一看就明白了——它就是创建了一个 `Random` 的对象。
>
> 所以 `Math.random()` 的底层其实是：**先创建一个 `Random` 对象，再用对象去调用 `nextDouble` 方法**，在 0.0 到 1.0 之间取一个随机小数。

关于 `Math`，我们只要知道三个问题就可以了：它是一个帮助我们进行数学计算的工具类；它里面所有的方法都是静态的，调用的时候直接类名点方法名；常见的方法有 `abs`（绝对值）、`ceil`、`floor`、`round`、`max`、`min`、`pow`（a 的 b 次幂、开平方根、开立方根），以及最后的 `random`（获取随机小数）。

### 算法小题：判断一个数是不是质数

学完 `Math`，我们立刻拿它去做两道算法小题。先看第一题：**定一个方法，判断一个整数是不是一个质数。**

这道题我们不陌生，之前写过：

```java
public static boolean isPrime(int number) {
    for (int i = 2; i < number; i++) {
        if (number % i == 0) {
            return false;    // 能被整除，不是质数
        }
    }
    return true;             // 一路都没找到，是质数
}
```

代码的效果是能达成的，但是**效率比较低**。我们来改进一下。

你要想：判断 13 是不是质数，从 2 开始一直判断到 12，要循环整整 11 次。13 这个数字还小，循环 11 次根本感觉不出来。那现在要判断的数字比较大呢？997 也是一个质数，按老代码的习惯从 2 一直判断到 996，**整整要循环 900 多次**，循环次数太多，效率太低。

效率低的原因就是循环次数多，那要提高效率，就得减少循环次数。怎么减？

先看几个具体案例。数字 8 不是质数，它除了能被 1 和 8 整除之外，还能被 2 和 4 整除。数字 16 也不是质数，除了 1 和 16，还能被 2 和 8、4 和 4 整除。27 除了能被 1 和 27 整除，还能被 3 整除——那跟 3 对应的因子是多少？是 9。

在数学当中，后面这些数字叫做**因子**，而因子是**成对出现**的，所有情况都是这样。跟着我们的节奏，**每一对因子的特点是：其中一个因子必定小于等于平方根，另一个因子必定大于等于平方根**，绝逼是这样，没有特殊情况。

用数轴表示出来是这样的：

```text
16 的因子（成对出现）
     1 × 16          2 × 8          4 × 4
      │                 │               │
  ────┼─────────────────┼───────────────┼────────────→ 数轴
      1      2     3    4      5       8             16
                        ↑
                     √16 = 4

每一对因子：一个在 √n 的左边，一个在 √n 的右边
所以只需要检查 [2, √n] 这一段就够了
```

20 也是一样的规律，它的平方根是四点几，位于 4 到 5 之间，它每一对因子也是一个在左边、一个在右边。

> **结论**：既然因子是一对一对出现的，那我只看**一半**不就可以了吗。以 16 为例，循环只要循环到 4 就可以了。循环过程中如果发现一个数字能被 16 整除，那右边必定有一个数字跟它对应；反之，如果一个数据都没有看到，那右边肯定也没有数据跟它对应。

所以，**判断一个数是不是质数，循环的结束条件就是它的平方根。**

把代码写出来：

```java
public static boolean isPrime(int number) {
    for (int i = 2; i <= Math.sqrt(number); i++) {
        if (number % i == 0) {
            return false;
        }
    }
    return true;
}
```

> **易错点**：这里必须是 `<=` 而不是 `<`。因为如果 number 是 16，中间那个平方数 4 本身也得参与判断——`16 % 4 == 0`，它就是个非质数。所以我们要**从 2 开始，小于等于平方根**。

上面 `Math.sqrt(number)` 这一句，正好用到了我们刚学的 `sqrt`。

再补一个写测试类时的规矩：**写在测试类里面的方法，一定要加 `static`**。为什么？因为 `main` 方法是静态的，而静态只能调用静态。你要是写成非静态的 `AA` 方法，在静态的 `main` 里直接调用就报错了——非静态需要用对象来调用，你还得先 `MyTest mt = new MyTest()`，再用 `mt` 去调 `AA`，你不觉得非常麻烦吗？所以我们在测试类当中写的方法，一般也是静态的，这样在 `main` 方法当中就可以直接调用了。

验证一下：传 `16` 进去，输出"16 不是一个质数"；传 `997` 进去，输出"997 是质数"。想知道 997 这个过程循环了几次？在循环里打印一下 `i` 就知道了——**整个循环只要 30 次**就能得到最终结果，跟之前的 900 多次比，效率是不是大大提升了？

### 算法小题：自幂数与那个藏起来的坑

第二题是**自幂数**。

所谓自幂数，就是一个 N 位的自然数，它等于自身各个位数上的数字的 N 次幂之和。

定义有点拗口，看个案例就明白了。三位数 153，把每一位拿出来，因为当前是三位数，所以每一位都求三次方：$1^3 + 5^3 + 3^3$ 总和刚好是 153，所以 153 就是一个自幂数。那如果是一个四位数呢？四位数跟刚刚不一样，你求的是四次方。

> **定义**：自幂数（也叫水仙花数）的判定式为——若 $n$ 是 N 位自然数，则 $\sum_{i} d_i^{\,N} = n$，其中 $d_i$ 是 $n$ 的第 $i$ 位数字。

需求是：键盘录入一个任意的整数，判断它是不是一个自幂数。

> **提示**：这道题真正的难点**不是计算的过程**。如果我现在已经确定录入的数字就是 153，那我获取它的个位、十位、百位，一个一个取出来，再求个位的三次方、十位的三次方、百位的三次方，跟 153 做判断——相等就是自幂数，不等就不是。代码非常简单。
>
> 关键问题在于：**这个数字是键盘录入的，我事先不知道它是几位数。** 这才是难点。

我们一步一步来。

**第一步，录入一个正整数。** 这个简单，直接 `Scanner`。

```java
Scanner sc = new Scanner(System.in);
System.out.println("请输入一个正整数");
int number = sc.nextInt();
```

**第二步，拿到每一位。** 假设现在录入的是 123。最右边的那个数字不就是个位吗？先定义一个变量 `lastNumber` 存它，怎么求？**拿着 number 对 10 取模**：

```java
int lastNumber = number % 10;   // 123 % 10 = 3
number = number / 10;           // 123 去掉个位的 3，变成 12
```

有了 12 之后，其实就可以把上面的过程重复一遍了：再取最右边的数字，`12 % 10` 就是 2；取到 2 之后再去掉 2，number 变成 1；再取就是 1；取到 1 之后再去掉 1，number 变成 0。

> **结论**：**0 就是循环的结束条件**。number 不等于 0 就继续循环，等于 0 循环就结束。

```java
while (number != 0) {
    int lastNumber = number % 10;   // 取最右边的数字
    System.out.println(lastNumber);
    number = number / 10;           // 去掉最右边的数字
}
```

跑一下：录入 `123`，打印出 3、2、1，每一位都拿到了；录入 `123456`，同样每一位都拿到了。**最核心的一步已经做完了——拿到里面的每一个数字。**

**第三步，位数是多少？** 接下来该怎么做呢？刚才循环里是拿 `lastNumber` 去求它的 N 次幂，那问题来了——**这里的 N 到底是一位数、两位数、三位数，我不知道啊。**

很多同学会想：简单，我再拿一个循环去判断一下不就得了吗，对 10 取模不等于 0，每去掉一个数字我定一个计数器 `count` 加加。这个思路可以，但相对来讲有点麻烦。

我们之前学过字符串，能不能获取一个字符串的长度？当然可以。**把 number 看作一个字符串，然后调用它里面的 `length` 方法，字符串的长度就是数字的位数。**

那怎么把 number 看作字符串呢？很简单——**直接用 number 加上一个长度为 0 的、什么内容都没有的字符串**。字符串加任意数据类型，它都是进行**拼接操作**。如果 number 是 123，一旦拼接完了之后就变成字符串 `"123"` 了。

```java
int len = (number + "").length();
```

> **注意**：括号不能省。`number + ""` 算出来是一个字符串对象，如果不加小括号，`.length()` 就作用不到它身上。

**第四步，求幂并累加。** 位数拿到之后就可以计算了，拿每一个数字 `lastNumber` 去求它的 N 次幂，N 就是上面这个 `len`。累加的话在外面定一个求和变量 `sum`。`pow` 方法第一个参数写 `lastNumber`，第二个参数写 `len`。

```java
sum += (int) Math.pow(lastNumber, len);
```

写完这一句你发现它居然报错了。鼠标悬停上去一看：`Math.pow` 的返回值是一个 `double`，你拿着一个小数去加一个整数，结果还是一个小数，然后你把这个小数赋值给整数类型的 `sum`——那肯定就报错了。所以这里要对它做一个**强转**。

**第五步，最后判断。**

```java
if (sum == number) {
    System.out.println("当前的数字是一个自幂数");
} else {
    System.out.println("当前的数字不是自幂数");
}
```

到这里代码就算写完了。

#### 那个坑：循环把 number 吃掉了

我现在要问大家：**你觉得这个代码对吗？** 给五秒钟时间自己思考一下。

我觉得很多同学心里想的是：看上去好像没什么问题啊。

但是——**如果说这个代码完全正确的话，你就不会那么问我了**。你的家伙是不是在给我挖坑？

嘿嘿，你说对了。我们来试一试：右键运行，键盘录入 `153`。你发现 **153 它居然是一个非自幂数**。这跟我们刚刚看到的结果不一样呀——刚才我们打印 `sum` 的时候，求和结果明明也是 153，按照题目需求它应该是一个自幂数啊，为什么在这儿走到了 `else` 呢？

> **提示**：当代码出现问题了，你不要慌，也**不要从上往下一点点地看**。我们先看问题出现的地方。它打印"非自幂数"这行，表示什么？表示你的 `sum` 跟 `number` 这两个数字不相等。那我心里就有疑问了：我键盘录入的明明是 153，为什么在这儿不相等呢？我不信那个邪，把这两个数字都打印出来看看。

一打印，关键点来了：求和的结果是 `153`，但是 `number` 变成了 **0**。

为什么是 0 呀？关键就在这个循环——**在循环的过程当中，我是不是不断地去修改了 number 里面记录的值**。number 不为零我就取最右边的数字，取完了再去掉，直到 number 为零循环才结束。所以你在下面打印 number 的时候，它就是零了。也就是因为这个原因，你在判断 `sum == number` 的时候，它俩根本不可能相等。

> **易错点**：**循环变量和被比较的原始数据，不能是同一个变量。** 只要你在循环里拿它做"不断去掉末位"的运算，它的原始值就一定会被改掉。

问题发现了，代码怎么改？教大家一招：因为下面我要不断地去修改 number 的值，而且更重要的是，**最后我还需要用 number 原来的数据**。在这种情况下，就可以**再去定义一个第三方变量**，拿着这个变量去记录原来的值：

```java
int temp = number;                    // 一进来就把原值备份下来
```

循环照旧改 `number`，最后再判断的时候，**就不是跟 `number` 比了，跟 `temp` 比**：

```java
if (sum == temp) {
    System.out.println("当前的数字是一个自幂数");
} else {
    System.out.println("当前的数字不是自幂数");
}
```

再跑一次，录入 `153`——这才是正确的。

最后说一句写在代码里的体会。你有没有发现，我写这个算法题的时候，是从上往下一行一行地写的吗？

并没有。我是**先写主体的思路，然后发现问题了，再回头去补**。

这才是真的写代码，你的思路才会更加通畅。以后看到一个复杂问题的时候，先别慌，**想到多少写多少**；在书写的过程当中遇到问题了，或者是缺少变量了，你再回头去补，这就可以了。

### 本讲提到的题目

#### 算法小题一：判断一个整数是不是质数

**题干**：定义一个方法，判断一个整数是不是一个质数。

**解析**：思路在正文中已经推导完整。关键是因子的**成对出现**性质——每一对因子中必有一个 $\le \sqrt{n}$、另一个 $\ge \sqrt{n}$，因此循环只需从 2 遍历到 $\sqrt{n}$。平方根用本讲刚学的 `Math.sqrt(number)` 求，循环条件是 `<=` 而不是 `<`（否则 `16 % 4 == 0` 会漏判）。循环中一旦找到能整除的因子立刻返回 `false`，循环走完都没找到才返回 `true`。

**答案**：

```java
public static boolean isPrime(int number) {
    for (int i = 2; i <= Math.sqrt(number); i++) {
        if (number % i == 0) {
            return false;
        }
    }
    return true;
}
```

测试：`isPrime(16)` 为 `false`，`isPrime(997)` 为 `true`，此时循环 30 次。

#### 算法小题二：自幂数

**题干**：键盘录入一个任意的整数，判断它是不是一个自幂数。所谓自幂数，就是一个 N 位的自然数，它等于自身各个位数上的数字的 N 次幂之和。例如三位数 153，$1^3 + 5^3 + 3^3 = 153$，它就是自幂数；四位数则求四次方。

**解析**：难点不是计算，而是**位数 N 事先未知**。三条关键结论在正文中都已给出：位数的取法是 `(number + "").length()`；拆位的循环条件是 `number != 0`，每次 `lastNumber = number % 10` 再 `number = number / 10`；求和用 `sum += (int) Math.pow(lastNumber, len)`，`pow` 返回 `double`，赋给 `int` 必须强转。最后那个坑要避开——循环会把 `number` 改写成 0，所以要用第三方变量 `temp` 备份原值再比较。

**答案**：

```java
Scanner sc = new Scanner(System.in);
System.out.println("请输入一个正整数");
int number = sc.nextInt();

int temp = number;                        // 备份原值
int len = (number + "").length();         // 位数
int sum = 0;

while (number != 0) {
    int lastNumber = number % 10;         // 取最右边的数字
    sum += (int) Math.pow(lastNumber, len);
    number = number / 10;                 // 去掉最右边的数字
}

if (sum == temp) {
    System.out.println("当前的数字是一个自幂数");
} else {
    System.out.println("当前的数字不是自幂数");
}
```
