# 循环结构与循环控制

## 写循环前必问的三个问题

### 三个问题与代码位置的对应

* **三问法**

    * > **定义**：每写一个循环先问自己三个问题，答案分别落在 for 的三段结构里。

        * 循环的开始条件是什么 → 初始化语句。
        * 循环的结束条件是什么 → 条件判断语句。
        * 题目当中真正要重复执行的代码是什么 → 循环体。

    * 第三个问题最容易漏，不要凭感觉，照着题目抄。

    * 「控制条件」大多数情况下都是加一，即 `i++`，不需要专门去问。

* **for 循环骨架**

    ```java
    for (初始化语句; 条件判断语句; 条件控制语句) {
        循环体语句;
    }
    ```

### 正向与反向遍历的差别

* **正着打印 1~5**

    ```java
    for (int i = 1; i <= 5; i++) {
        System.out.println(i);
    }
    ```

* **倒着打印 5~1**

    ```java
    for (int i = 5; i >= 1; i--) {
        System.out.println(i);
    }
    ```

* 两个版本只差三处

    | 需求 | 初始化语句 | 条件判断语句 | 条件控制语句 | 输出 |
    | :--- | :--- | :--- | :--- | :--- |
    | 1~5 | `int i = 1;` | `i <= 5` | `i++` | 1 2 3 4 5 |
    | 5~1 | `int i = 5;` | `i >= 1` | `i--` | 5 4 3 2 1 |

* 循环体里直接打印循环变量 `i`，因为它是全程按 1、2、3、4、5 变化的那个量。

* > **易错点**：倒着打印最容易错的是判断写成 `i <= 1`、控制写成 `i++`。方向一旦写反，要么一次都不进循环，要么死循环。

### 多跑一轮判断

* > **结论**：只有条件判断语句为 `false` 时循环才结束，循环体执行完并不代表循环已终止。

* 打印 1~5 的完整走向：`i` 依次取 1、2、3、4、5 各进一次循环体，每次结束前执行 `i++`；`i` 变成 6 之后还要再做第六次判断，用 6 跟 5 比较结果为 `false`，循环才真正结束。

* > **易错点**：不少人会认为「第五次循环一结束循环就结束了」。代码实际还会多跑一次判断，判断语句为 `false` 才是唯一的出口。

## 累加与统计

### 累加思想

* **累加思想**

    * > **定义**：先循环拿到范围内每一个数字，再定义一个初值为零的求和变量，把每个数字累加进去。

    * 求和变量命名为 `sum`，初始必须赋值为 `0`，因为还没开始累加。

    * 累加的动作是 `sum = sum + i`：把新得到的 `i` 加到 `sum`，得到新结果再赋值回 `sum`。

    * 求和变量必须定义在循环外面，只有这样才能跨轮次接着上一轮的结果往下滚。

* **1~5 求和的逐轮状态**

    | 轮次 | `i` | 进入循环体时的 `sum` | 计算 | 结束后 `sum` |
    | :--- | :--- | :--- | :--- | :--- |
    | 第 1 次 | 1 | 0 | 1 + 0 = 1 | 1 |
    | 第 2 次 | 2 | 1 | 2 + 1 = 3 | 3 |
    | 第 3 次 | 3 | 3 | 3 + 3 = 6 | 6 |
    | 第 4 次 | 4 | 6 | 4 + 6 = 10 | 10 |
    | 第 5 次 | 5 | 10 | 5 + 10 = 15 | 15 |

    * `sum` 那一列不是每轮重新从 0 开始，而是接着上一轮的结果继续滚；起始的那个 0 是「循环之前」写下的。

* **累加的等价写法**

    * `sum = sum + i;` 与 `sum += i;` 运行结果一致，后者用加等运算符。

    * 循环前先定义 `int sum = 0;`，循环后再 `System.out.println("1~5之间的数字和为：" + sum);` 做字符串拼接让输出更有意义。

* **把求和变量挪进循环的后果**

    * 只挪 `int sum = 0;` 而输出语句留在循环外：循环外找不到 `sum`，因为出了循环变量就消失，直接报错。

    * 把输出语句也一起挪进循环体：能编译通过，但结果是错的。`sum` 每进一次循环就被重新赋值为 0，只累加了当轮那一个 `i`，控制台上打出 1、2、3、4、5 五个各自独立的数，而不是 15。

### 统计思想

* **统计思想**

    * > **定义**：先定义一个初值为 `0` 的计数器变量，满足条件时让它自增，所有情况判断完毕后计数器记录的值就是要的个数。

    * 计数器命名为 `count`，命名成 `a`、`b`、`c`、`d` 也能工作，关键是让它只在满足题目条件时自增。

* **能被 3 和 5 同时整除的数字个数**

    * 第一步键盘录入两个数字：用户可能录 3 和 13，也可能录 10 和 30，直接从 `num1` 循环到 `num2` 会得到错误范围。

    * 第二步先求最大值与最小值，用三元运算符一行搞定：

    ```java
    int max = num1 > num2 ? num1 : num2;
    int min = num1 > num2 ? num2 : num1;
    ```

    * 第三步循环 `min` 到 `max` 的每一个数字。

    * 第四步判断 `i % 3 == 0 && i % 5 == 0`；题目说的是「既能又能」，两个条件要同时满足，用 `&&` 连接。

    * 命中条件时执行 `count++`，循环结束后对 `count` 判断再输出，避免范围太小时只输出一个零让人看不懂：

    ```java
    // 定义变量用于统计个数
    int count = 0;

    for (int i = min; i <= max; i++) {
        if (i % 3 == 0 && i % 5 == 0) {
            count++;
        }
    }

    if (count == 0) {
        System.out.println("在" + min + "~" + max + "之间没有满足要求的数字");
    } else {
        System.out.println("在" + min + "~" + max + "之间满足要求的数字有" + count + "个");
    }
    ```

    * 范围取 1~100 时结果是 6 个。

* > **易错点**：双引号里的 `min`、`max` 不会被当成变量，它们会原样输出。把变量选中 `Ctrl+X` 剪切，光标原地不动按双引号，在双引号中间加 `++`，再在中间 `Ctrl+V` 粘贴，等于拿前面的字符串跟变量拼接。从左到右一个一个写容易少加号或少引号。

### 范围求和与筛选条件

* **1~100 之间的偶数和**

    * 分三步搭：先循环拿到 1~100 每一个数字，再加 `if` 筛出偶数，最后累加求和。

    * 判断偶数写作 `i % 2 == 0`，即对 2 取余等于 0；不是 0 的是奇数，直接跳过不管。

    * 最正统的写法：

    ```java
    // 定义一个变量用于求和
    int sum = 0;

    for (int i = 1; i <= 100; i++) {
        if (i % 2 == 0) {
            sum = sum + i;
        }
    }

    // 循环结束，所有的偶数全都累加进去了
    System.out.println(sum);
    ```

    * 结果是 2550。

* **等价变形：从 2 开始每次加 2**

    * 条件控制语句每次加 2，循环内拿到的直接就是 2、4、6、8、10……，连 `if` 都可以省掉：

    ```java
    int sum = 0;

    for (int i = 2; i <= 100; i += 2) {
        System.out.println(i);
        sum = sum + i;
    }

    System.out.println(sum);
    ```

    * 结果与带 `if` 的版本一模一样，都是 2550。

* > **提示**：写循环时先不要急着累加，先在循环体里打印 `i` 验证循环本身对不对，再回来补累加。写一步输出一步，上一步对不对立刻可见。

### 找规律的三变量递推

* **题目形态**

    * > **定义**：一组特殊数字，从第三项开始每一项都是前两项的和，问第十项是多少。首两项预先给定为 0 和 1。

    * 数列为 0、1、1、2、3、5、8……第十项是 34。

    * 学完数组可以用数组做，学完方法可以用递归做；只学了判断、选择、循环时，用三个变量滚动即可。

* **三组对照**

    ```text
          第 1 组           第 2 组           第 3 组
       ┌─────┬─────┐      ┌─────┬─────┐      ┌─────┬─────┐
       │   a │ b   │  ->  │   a │ b   │  ->  │   a │ b   │
       │   0 │ 1   │      │   1 │ 1   │      │   1 │ 2   │
       └─────┴─────┘      └─────┴─────┘      └─────┴─────┘
          c = 1              c = 2              c = 3
    ```

    * 每一组的 `c` 等于本组 `a + b`，下一组的 `a` 等于本组的 `b`，下一组的 `b` 等于本组的 `c`。

    * `c = a + b` 相当于求前一组最后一个值，下面修改 `a`、`b` 相当于求下一组前两个值；`i++` 进入下一次循环时，`c` 的值已经就位。

* **实现**

    ```java
    int a = 0;
    int b = 1;
    int c = 0;

    for (int i = 3; i <= 10; i++) {
        // 求 c 的值
        c = a + b;
        // 修改 a 和 b 记录的值
        a = b;
        b = c;
    }

    // 循环结束，此时 c 就是第十项的数字
    System.out.println(c);
    ```

    * 开始条件写 3 而不是 1，因为计算从第三项才开始；结束条件写 10，对应要算第十项。

### 奇偶交替累加

* **题目形态**

    * 求数列前 N 项和，数列规律是 $1 - 2 + 3 - 4 + 5 - \ldots$，示例中 $S4 = 1 - 2 + 3 - 4 = -2$。

    * 看到「求某某和」第一反应是累加思想，但累加规则要先确定。

    * 规律是奇数项相加、偶数项相减，所以要先判断奇偶再决定用加还是用减。

* **先主干后细节的写法**

    * 第一步键盘录入 `n`，确定循环范围。

    * 第二步先只把循环写出来，循环体里先打印 `i` 验证范围正确。

    * 第三步再回到上面补上求和变量，再在循环体里补上奇偶分支：

    ```java
    // 第二步：定义求和变量
    int sum = 0;

    // 第三步：循环获取 1~n 的每一个数字，并按奇偶累加
    for (int i = 1; i <= n; i++) {
        if (i % 2 == 1) {
            sum = sum + i;
        } else {
            sum = sum - i;
        }
    }

    // 循环结束，sum 里面记录的就是我们最终的结果
    System.out.println(sum);
    ```

    * 若 `if` 里写的是 `i % 2 == 0`，那么 `if` 分支里就该放偶数逻辑、`else` 里放奇数逻辑。

    * 录 4 得 -2，录 5 得 3。

    * > **提示**：刚开始写时想不到求和变量是常事，先把主干逻辑想明白，细节回头补，这叫有逻辑地写代码。

## for 与 while

### 相同的执行流程

* **结论**

    * > **结论**：`for` 和 `while` 的执行流程完全相同——初始化只执行一次，之后就是「判断 → 循环体 + 条件控制 → 回到判断」这样转下去，判断语句为 `false` 才停。

* while 的写法把结构拆开摆放：初始化语句写在循环外面，条件判断语句写在小括号里，循环体语句和条件控制语句一起写在大括号里。

    ```java
    // 初始化语句写在循环外面
    int i = 1;

    while (i <= 10) {
        // 循环体
        System.out.println("游戏人物跳跃了一次");
        // 条件控制语句
        i++;
    }
    ```

    * 判断成立就进入大括号执行循环体和控制语句，这一轮算结束，再回到小括号做第二次判断；判断为 `false` 则循环结束，继续往下执行。

### 选择标准

* **结论**

    * > **结论**：知道循环次数或循环范围用 `for`；不知道这些信息、只知道循环结束条件用 `while`。

* 理由是格式带来的阅读成本：程序代码量很大时，目光只看循环本身，`for` 一眼就能看出开始条件与结束条件；而 `while` 的开始条件写在循环之外，要往上翻很长的代码才能找到谁是开始条件。

* 反过来，只知道结束条件时 `while` 小括号里就只有一个条件，目光非常清晰；此时 `for` 那一大串东西反而要多找中间那一块。

* **三道判断题**

    | 题目 | 该用哪个循环 | 为什么 |
    | :--- | :--- | :--- |
    | 获取 1~100 之间的每一个数字 | for | 这就是它的范围，范围明确 |
    | 循环读取本地文件中的数据，每次读一个字 | while | 不知道有多少个字，只知道读到文件末尾就结束 |
    | 登录密码输错后重试，最多三次 | for | 三就是循环次数，通过次数可以推导出范围（0~2 或 1~3） |

### 语法层面的区分不成立

* 常见的说法是：`for` 里的控制变量归属于 for 的语法结构，循环结束后不能再用；`while` 里的变量定义在循环外面，循环结束后还能继续用。

* 这个说法不绝对——把 `for` 的初始化语句也写到循环外面，两种循环在语法上就没有任何区别了：

    ```java
    int i = 1;

    for (; i <= 10; i++) {
        System.out.println("游戏人物跳跃了一次");
    }
    ```

* 所以两种循环真正的区别在**使用习惯**层面，不在语法层面。

## do-while

### 语法结构

* 格式相当于把 `while` 整个颠倒：初始化语句写在最外面，然后 `do` 大括号，大括号里先写循环体、再写条件控制语句，最后写 `while` 和条件判断语句。

    ```java
    int i = 1;
    do {
        System.out.println("hello world");
        i++;
    } while (i <= 5);
    ```

    * 执行时先执行循环体和 `i++`，最后才判断；判断成立就回到大括号继续，不成立就结束。

* **执行流程对比**

    ```text
        while 循环                    do-while 循环

         1) 判断条件                  1) 执行循环体
              |                       2) 执行 i++
              v                       3) 判断条件
            条件成立?                     |
           否 --> 结束                   条件成立?
            |                            |
            v 是                     否 --> 结束
         2) 执行循环体                    |
              |                          v 是  回到 1)
              +----> 回到 1)
    ```

### 先执行后判断

* > **结论**：`for` 和 `while` 是先判断后执行；`do-while` 是先执行后判断，循环体至少执行一次。

    * 把 `i` 初始化成 10 再去判断 `i <= 5`，第一次判断就是 `false`。放进 `for` 或 `while` 里一次都不执行循环体，没有任何输出；放进 `do-while` 里循环体照样执行了一次，`hello world` 照样打出来。

    * 比方是吃饭：`for`、`while` 是先掏兜看有没有钱，有钱就吃、没钱就走；`do-while` 是甭管有钱没钱先坐下来吃，吃完再看兜里，有钱继续吃、没钱吃一次就走人。

* 实际开发中用得极少，记住语法即可，不用额外找练习。

## 只知结束条件的 while 练习

### 复利与单利

* **单利与复利**

    * > **定义**：单利是利息不计入本金，每年算出来的利息固定；复利的利息要计入本金，第二年算利息时拿的是「原本本金 + 第一年的利息」。

    * 复利就是常说的「利滚利」。

* **复利计算器**

    * 本金 10 万、年利率 1.7%，问多少年之后本金翻倍到 20 万。循环次数正是要求出来的量，只能用 `while`。

    * 三个变量：`money` 记录当前本金、`expectMoney` 记录期望本金、`year` 记录过了多少年。

    ```java
    // 1. 定义变量记录本金
    double money = 100000;

    // 2. 定义变量记录期望的本金
    double expectMoney = 200000;

    // 3. 定义变量记录年数
    int year = 0;

    // 本金不到 20 万就继续累积，到了就停
    while (money < expectMoney) {
        // 计算一年结束后的账户余额：本金 + 本金 * 利率
        money = money + money * 0.017;
        // 又过了一年
        year++;
    }

    System.out.println(year);
    ```

    * 跑出来是 **42 年**。

* > **易错点**：利率是 1.7% 不是 1.7。百分号要换算成小数 `0.017`，写成 `1.7` 意味着年利率 170%。

* **单利不需要循环**

    * 单利每年利息固定为 `money * 0.017`，攒够 10 万利息所需年数直接除即可：

    ```java
    double money = 100000;
    // 后面这一堆必须用小括号括起来
    System.out.println(money / (money * 0.017));
    ```

    * 结果是 **59 年**；同样 10 万、同样 1.7%，复利比单利少 17 年。

* > **提示**：分母那一堆一定要加小括号。运算符是从左到右依次计算的，不加括号变成 `money / money * 0.017`，先除后乘，算出来永远是 `0.017`。

### 折叠纸张

* **题目与翻译**

    * 珠穆朗玛峰高 8848.86 毫米，一张厚度 0.1 毫米、足够大的白纸，问折叠多少次才能超过珠峰高度。

    * 折叠在代码里的全部表现就是厚度翻倍：定义厚度为 `paper`，折叠一次即 `paper = paper * 2`。

* 循环次数同样是要求出来的，只知道「厚度小于珠峰高度就继续」，所以用 `while`。

    ```java
    // 1. 定义变量记录纸张厚度，一开始 0.1
    double paper = 0.1;

    // 2. 定义变量记录山峰高度（毫米）
    double height = 8848.86;

    // 3. 循环折叠，循环外还要一个计数器
    int count = 0;

    while (paper < height) {
        paper = paper * 2;
        count++;
    }

    System.out.println(count);
    ```

    * 跑出来是 **27 次**。

* > **注意**：凡是两个要比较的数，单位必须先统一，否则比较出来的结果毫无意义。这类错误编译器不会提醒，只能自己长记性。

* > **提示**：想不起 `count` 这个变量名不用硬憋，先把循环写完，等发现题目还缺东西再回头补这个变量。先有骨架，再添血肉。

* 数学延伸：一直算下去，折叠 105 次纸张的理论厚度能到 4000 亿光年，超过现在可观测宇宙的直径。

### 求各位数字之和

* **题目**

    * 给定整数 N 计算所有位数的和，N 为负数先取绝对值。`N = 12` 得 3，`N = -305` 得 8。

* **绝对值**

    * 正数与零的绝对值是本身，负数的绝对值是相反数：

    ```java
    if (number < 0) {
        number = -number;   // 负负得正
    }
    ```

* **不能拿公式硬取某一位**

    * 个位 `number % 10`、十位 `number / 10 % 10`、百位 `number / 100 % 10`，公式本身没错，错在位数不可控——两位、三位到八位都有可能，写死几个 `% 10` 就是错的。

    * 必须用循环，方法是**取个位，再去掉个位，重复**：

    ```text
        number = 305
            number % 10  ->  5      取出个位
            number / 10  -> 30      扔掉个位

        number = 30
            number % 10  ->  0
            number / 10  ->  3

        number = 3
            number % 10  ->  3
            number / 10  ->  0      循环结束
    ```

    * 循环条件是 `number != 0`：只要不等于 0 就继续取、继续扔，等于 0 说明位子取干净了。因为 `3 / 10` 是商 0 余 3，整数相除结果就是一个整数。

    ```java
    // 第三步：定义求和变量
    int sum = 0;

    // 第四步：循环取位并累加
    while (number != 0) {
        int geWei = number % 10;   // 取个位
        sum = sum + geWei;         // 累加到 sum
        number = number / 10;      // 去掉个位
    }

    System.out.println(sum);
    ```

    * 输 `-305` 得 8，输 `12345` 得 15，多少位都照样算得出来。

* > **易错点**：`number = number / 10;` 千万别写成 `number = number % 10;`。取余是留下个位，整除才是扔掉个位，两个符号在这里是死对头，写反了循环永远出不来。

## 无限循环

### 三种格式

* > **定义**：无限循环也叫死循环，就是循环一直在进行、永远停不下来，有三种格式。

* **for 格式**：小括号里直接两个分号，初始化、条件判断、条件控制都可以空着不写，不写条件判断默认成立。

    ```java
    // for 格式：小括号里直接两个分号
    for (;;) {
        System.out.println("阿伟好帅");
    }
    ```

    * > **易错点**：那两个分号不能省。空的是里面的内容，分号必须老老实实写上。

* **while 格式**：小括号里直接写 `true`。

    ```java
    while (true) {
        System.out.println("阿伟好帅");
    }
    ```

* **do-while 格式**：小括号里同样写 `true`，但末尾要带分号。

    ```java
    do {
        System.out.println("阿伟好帅");
    } while (true);
    ```

    * > **易错点**：`while` 和 `do-while` 小括号里的 `true` 不能省略，写 `while ()` 或 `while {}` 会直接报错。

* 三种写法跑起来效果完全一样，只能手动点运行指示灯强制结束。

* **该用哪一种**

    * 先排除 `do-while`，因为它几乎不用。剩下的 `for` 与 `while` 按老标准来：无限循环的次数和范围都不知道，所以用 `while`。

### 位置限制

* 无限循环永远停不下来，**在它的下面不能写任何其他代码**，一旦写了直接报错，程序都不用运行。

    ```java
    while (true) {
        System.out.println("阿伟好帅");
    }
    System.out.println("看看我执行了吗");   // unreachable statement
    ```

    * 鼠标悬停上去会看到 `unreachable statement`（永远不能到达的语句），因为循环停不下来，下面的代码永远执行不到。

## 循环控制语句

### break 的作用与限制

* **break**

    * > **定义**：`break` 表示结束、跳出，出现在 `switch` 或循环里面，跑到它之后循环直接结束，后面的代码不再走。

    * `break` 不能单独书写，单独写一个 `break` 程序都不用运行，鼠标悬停会提示 `break outside of switch or loop`。

    * > **结论**：看到 `break` 关键字，循环就直接结束，这一次执行与后面还剩多少次循环没有关系。

* **作用域**

    * 在循环里判断 `i == 15` 就 `break`、否则打印当前的 `i`，答案是 C，能看到 1~14。

     ```text
        第 15 次循环，i = 15
        ---------------------------------------------
          if (i == 15)
              |
              v
            break  ------------------>  跳出整个循环
                                              |
          System.out.println(i);  <--- 不会执行   跳到这里（循环外面）
    ```

    * 1~14 期间 `i` 不等于 15，执行不到 `break`，正常打印；第 15 次循环执行到 `break`，整个循环结束，直接跳到外面，它下面那句输出根本不会再走。

* **IDEA 快捷生成循环**

    * 输入循环次数，比如 `100`，再输入 `.for` 加回车，IDEA 就自动生成 `for (int i = 0; i < 100; i++) {`，这是 IDEA 自带的，不是 AI 生成的。

    * 它默认从 0 开始且**不包含 100**，因为条件写的是「小于 100 才能执行」；把开始改成 1、结束改成小于等于也完全可以。

### break 改造数据校验

* **场景**：游戏人物血条，初始生命值 200，受到 X 点伤害又恢复 Y 点伤害，X 与 Y 都由键盘录入。顺着主体逻辑往下写会留下一个坑——录入负数时跟题目逻辑不符。

* **思路**：让用户不断录入，录入完判断，数据合法才继续往下走，否则一直让他录。

    ```java
    int heart = 0;

    System.out.println("请输入当前受到的伤害");
    while (true) {
        heart = sc.nextInt();
        if (heart > 0) {
            break;
        } else {
            System.out.println("当前受到的伤害不能为负数，请输入正确的数据");
        }
    }
    ```

    * 恢复的血量同理，也要套一层 `while (true)`，变量名为 `add`。

* **变量必须定义在循环外面**

    * 把 `heart` 直接定义在循环里面，循环一结束下面再用 `heart` 就报错，因为定义在循环里的变量出了循环就不能用了。

    * 解决办法是提升作用域：把 `heart` 定义在循环**外面**并先赋个初值，循环里不再定义，只给 `heart` 赋值。`add` 同样处理。

    * 效果：输 `-150` 提示不合法，输 `-100` 仍不通过，直到输 `50` 才跳出循环继续往下，此时剩余血量变成 150；恢复量再输一个正数，血量按 `200 - heart + add` 算。

* > **提示**：凡是循环结束后还要用的变量，一开始就要定义在循环外面。这个坑在质数那题还会再撞一次。

* > **结论**：知道范围和次数用 `for`，只知道结束条件用 `while`；数据不合法就用 `while (true)` 加 `break` 卡住它。

### continue 的作用与限制

* **continue**

    * > **定义**：`continue` 表示结束本次循环、继续下次循环，它跳转到 `i++`，本次循环中下面的代码不再执行，直接开始下一次。

    * 在 `for (int i = 1; i <= 10; i++)` 中判断 `i == 3` 就 `continue`，输出结果是 1、2、4、5、6、7、8、9、10，`3` 消失而其余照常。

    ```text
      一次循环体：
          System.out.println(i);
          ...
          // 循环体内剩余的代码
                        |
            ┌───────────┴───────────┐
            ▼                       ▼
          break                  continue
            |                       |
            ▼                       ▼
       整个循环结束              本次循环结束，
       跳出循环，                循环体剩下的代码一行都不执行，
       执行循环下面的代码        直接跳到 i++ 继续下一轮
    ```

* **两个关键字的对照**

    | | `break` | `continue` |
    | :--- | :--- | :--- |
    | 能不能单独书写 | 不能 | 不能 |
    | 能出现在哪儿 | `switch` 和循环里 | 只能在循环里 |
    | 跑到它之后 | 整个循环结束 | 本次循环结束 |
    | 接下来跳到哪 | 循环下面的代码 | `i++`，开下一次 |

    * > **易错点**：`break` 可以写在 `switch` 里面，`continue` 不行——`switch` 不是循环，写了 `continue` 直接编译报错。这两条限制是编译器强制的，不是背出来的。

### continue 的实战：逢七过

* **题目**

    * 循环打印 1~100 之间的每一个数字，如果这个数字包含七或者是七的倍数，就不打印数字，直接输出「过」。

* **条件的翻译**

    * 「包含七」等价于个位是 7 或者十位是 7，即 `i % 10 == 7 || i / 10 % 10 == 7`，涵盖 17、27、37、47、57、67、77、71、72 等。

    * 范围是 1~100，没有需要考虑的百位（百位只有一个 1），所以只考虑个位与十位。

    * 「七的倍数」翻译为 `i % 7 == 0`，涵盖 14、21、28、35 等。

    * 两个条件是**或者**的关系，不是「并且」，满足其一就打印「过」。

* **实现**

    ```java
    for (int i = 1; i <= 100; i++) {
        if (i % 10 == 7 || i / 10 % 10 == 7 || i % 7 == 0) {
            System.out.println("过");
            continue;
        }
        System.out.println(i);
    }
    ```

    * 整段逻辑的走向：

    ```text
        for (int i = 1; i <= 100; i++)
                         |
                         ▼
        ┌────────────────────────────┐
        │  i % 10 == 7               │   ← 个位是 7
        │  || i / 10 % 10 == 7       │   ← 十位是 7
        │  || i % 7 == 0             │   ← 7 的倍数
        └────────────────────────────┘
                         │
                 ┌───────┴───────┐
                 ▼               ▼
              条件成立         条件不成立
                 │               │
                 ▼               ▼
            打印「过」        打印 i
                 │
                 ▼
            continue ──► 回到 i++，本次就此打住
    ```

* **同类变体**

    * 牛牛数数：数字包含四或四的倍数就跳过，条件逐个翻译成 `i % 10 == 4 || i / 10 % 10 == 4 || i % 4 == 0`，命中用 `continue` 跳过当前这一轮。

## 随机数与猜数字

### Random 的三种取值方式

* **Random**

    * > **定义**：`Random` 是 Java 写好的类，用来生成随机数，用法和 `Scanner` 一样分两步：先找到类，再让它干活。

    * 第一步找到类：`Random r = new Random();`，这行是固定的，小括号里空着什么都不写。

    * 第二步让它干活：`int n = r.nextInt();`，等号右边生成随机数，赋值给左边的变量 `n`。

    * 写完 `Random r = new Random();` 上面会多出 `import java.util.Random;`，这不是 AI 也不是手写的，是 IDEA 自动加的，用来定位 `Random` 的位置——它在 `java.base` 包下的 `java.util` 包中，和 `Scanner` 在同一个包里。

* **三种写法的范围**

    | 写法 | 小括号里写什么 | 取值范围 | 出现版本 |
    | :--- | :--- | :--- | :--- |
    | `r.nextInt()` | 空着 | `int` 的全部取值范围 | — |
    | `r.nextInt(n)` | 一个数 `n` | $0 \sim n-1$ | JDK 1.2 |
    | `r.nextInt(a, b)` | 两个数 `a`、`b` | $a \sim b-1$ | JDK 17 |

    ```text
      r.nextInt()         →  负 21 亿 ~ 正 21 亿   （范围太大，基本不用）
      r.nextInt(10)       →   0  ~   9
      r.nextInt(1, 10)    →   1  ~   9
    ```

    * 包头不包尾、包左不包右：写 `10` 得到的是 9 以内，写 `1, 100` 得到的是 1~99。验证办法是把它放进循环生成 100 次，看最小值和最大值分别落在哪里。

    * 第一种写法默认在 `int` 的整个取值范围（负 21 亿多到正 21 亿多）内取值，一般不怎么用。

* > **提示**：写完 `r.nextInt(10)` 之后，小括号前面会出现一个灰底的 `bound` 提示，光标左右移都选不中，那是 IDEA 在告诉你这个 `10` 表示的是**范围**。

* 第二种与第三种都需要掌握：第二种在 JDK 1.2 就出现，企业开发最低版本不低于 8，通用性更强；第三种要 JDK 17，版本过低的公司里用不了。

### 循环该包住哪几步

* **题目**：生成一个 1~100 之间的随机数，用键盘录入模拟猜的动作，一直猜，猜中为止。

* **第一步生成随机数**，放在循环外面，只执行一次：

    ```java
    Random r = new Random();
    int number = r.nextInt(100) + 1;   // 或者 r.nextInt(1, 101)
    ```

    * 写完按 `Ctrl + Alt + L` 格式化代码。

* **第二步键盘录入猜一个数**：

    ```java
    Scanner sc = new Scanner(System.in);
    System.out.println("请输入您要猜的数字");
    int guessNumber = sc.nextInt();
    ```

* **第三步比较并给提示**：

    ```java
    if (guessNumber > number) {
        System.out.println("你猜的数字太大了");
    } else if (guessNumber < number) {
        System.out.println("你猜的数字太小了");
    } else {
        System.out.println("恭喜你猜对了");
    }
    ```

* **循环只包第二、三步**

    ```text
      循环外面（只执行一次）
        第 1 步：生成 1~100 的随机数 number
                            |
                            ▼
      循环 while (猜中为止)
            第 2 步：键盘录入，猜一个数 guessNumber
            计数器 countA++、countB++（保底机制才需要）
            第 3 步：和 number 比较
                     太大 → 提示；太小 → 提示；猜中 → break
                            |
                            ▼
                  保底机制判断
    ```

    * 三段全放进循环的话，每猜一次就产生一个新的随机数，每次猜中的概率只有 1%。只把二、三放进去，随机数全程固定，然后反复猜；猜中之后补一个 `break` 并注释「猜中了循环结束」。

    * 选中代码按 `Ctrl + Alt + T` 可以用指定结构**包裹**（提示是 `surround with`），选 `while` 就自动生成循环把代码包起来。

### 大保底与小保底

* **业务逻辑**

    * 小保底：三次没猜中就提示用户随机数的范围，范围取 `number ± 5`。

    * 大保底：十次没猜中就甭管了，直接告诉用户「你猜中了」。

* **两个计数器**

    ```java
    int countA = 0; // 小保底计数器
    int countB = 0; // 大保底计数器
    // 循环里每猜一次：
    countA++;
    countB++;
    ```

    * 计数器写在循环中，用户每猜一次自增一次。

* **小保底的判断用取余而不是等号**

    * 「三次没猜中」不等于「正好第三次」——三次算、六次算、九次算、十二次也算，所以不是 `countA == 3`，而是判断猜的次数是不是三的倍数：

    ```java
    if (countA % 3 == 0) {
        System.out.println("触发小保底机制，随机数字的范围是 " + (number - 5) + " 到 " + (number + 5) + " 之间");
    }
    ```

* **小保底必须写在比较之后**

    * > **易错点**：把保底判断写在比较**之前**，会出现「明明猜中了却提示范围」的怪事，因为在比较之前你还不知道他猜没猜中。凡是「兜底/补救」性质的逻辑，都得等主判断先跑完再补。

* **大保底的两种写法**

    ```java
    if (countB == 10) {
        System.out.println("恭喜你猜对了");
        break;
    }
    ```

    ```java
    if (countB == 10) {
        guessNumber = number; // 用技术手段去弥补用户的缺失
    }
    ```

    * 第一种直接提示猜中然后 `break`；第二种把用户猜的数字改成正确的那个，让它继续往下走比较环节。

* **两者的对照**

    | | 小保底 | 大保底 |
    | :--- | :--- | :--- |
    | 计数器 | `countA` | `countB` |
    | 触发条件 | `countA % 3 == 0` | `countB == 10` |
    | 含义 | 猜的次数是 3 的倍数且没中 | 十次都没中 |
    | 效果 | 提示 `number ± 5` 的范围 | 直接判你赢 |
    | 写在哪儿 | 必须写在比较**之后** | 两种写法，写哪都行 |

## 质数判定

### 判断思路

* **质数**

    * > **定义**：只能被 1 和它本身整除的数字就是质数，比如 2、3、5、7、11、13、17；100 不是质数，因为它除了能被 1 和 100 整除，还能被 2、50 等其他数字整除。

* **缩小循环范围**

    * 朴素思路是从 1 循环到 `number`，数一数有多少个数能被 `number` 整除，只有两个就是质数。

    * 简化后的思路是从 **2** 开始循环到 `number - 1`，只要这个范围里没有任何数字能整除 `number`，`number` 就是质数。比如选 19，循环 2~18，没有一个能整除它，就断定它是质数。

* **键盘录入同样要套 while (true)**

    ```java
    Scanner sc = new Scanner(System.in);

    int number = 0;   // 定义在循环外面，扩大作用域

    while (true) {
        System.out.println("请输入一个大于等于二的整数");
        number = sc.nextInt();
        if (number >= 2) {
            break;
        } else {
            System.out.println("当前录入的数字是不合法的");
        }
    }

    System.out.println(number);
    ```

    * 别人用你的代码不一定按提示来，录个负的、录个 0 都有可能，所以录入也要做校验。

* **实现：计数器加循环外的结论**

    ```java
    int count = 0;

    for (int i = 2; i < number; i++) {
        if (number % i == 0) {
            count++;
        }
    }

    if (count == 0) {
        System.out.println(number + "是一个质数");
    } else {
        System.out.println(number + "不是一个质数");
    }
    ```

    * 这次用 `for`，因为循环范围有界。用 IDEA 的 `number.for` 生成后把开始改成 2，结束不用改，它本身就是「小于 `number`」，不包含 `number`；写成 `i <= number - 1` 也完全一样。

    * 输 100 时能在循环里看到 2、5、10、20、25、50 都能整除它，所以不是质数；输 13 结果是质数。

### 循环范围的收缩

* **扩展一：一个 break 就能省下大量循环**

    ```java
    if (number % i == 0) {
        count++;
        break;   // 找到一个就够了
    }
    ```

    * 只要找到了一个数字能被 `number` 整除，它就不是质数，后面的数据没必要再判断，效率提升非常明显，对最终结果没有任何影响。

* **扩展二：结论只能写在循环外面**

    * 把「是不是质数」的判断直接写进循环里的 `if`、`else` 分支是不行的。输 21 会得到两个结果，一个说是、一个说不是。

    * 循环从 2 到 20，第一次 `i = 2` 不能整除 21，于是直接走 `else` 打印「是质数」，但只判断了一个数字就下结论非常不合理。必须等整个范围里的每一个数字都判断完毕，才能下结论。

    * 「不是质数」可以写在循环里，因为一旦找到一个能整除 `number` 的数，后面的数据就没必要再判断，直接停止循环就行。

    * > **结论**：`不是质数` 的判断可以写在循环里，`是质数` 的判断只能写在循环外。不过没必要搞得这么复杂，管它是还是不是，一律写在循环外面一定不会出错。

* **扩展三：范围收缩到平方根**

    ```text
        1 * 100 = 100
        2 *  50 = 100
        4 *  25 = 100
        5 *  20 = 100
       10 *  10 = 100

        数轴（100 的因数）：
        1 -- 2 -- 4 -- 5 -- 10 -- 20 -- 25 -- 50 -- 100
                            |
                            sqrt(100)
    ```

    * 因数是**成对出现**的，每一对里其中一个一定小于等于平方根，另一个一定大于等于平方根。不可能存在两个数都在分界线左边而乘积刚好等于 100，也不可能两个都在右边。

    * 所以循环结束条件没必要把整个范围判断一遍，直接写平方根就行——左边没有，右边一定也没有：

    ```java
    for (int i = 2; i <= Math.sqrt(number); i++) {
        if (number % i == 0) {
            count++;
            break;
        }
    }
    ```

    * `Math` 是 Java 里专门做数学运算的类，其中的 `sqrt` 方法传进 `number` 就能求出平方根。

    * > **提示**：平方根是后面的知识点，暂时写成 `number - 1` 也就够了，但「因数成对出现」的思想要能理解、能听懂。

## 循环嵌套

### 嵌套的读法

* **循环嵌套**

    * > **定义**：循环里面还有其他循环叫嵌套，外面那个是外循环，里面那个是内循环。

    * 读法是一句话：**看循环嵌套的代码，先忽略外循环，重点研究内循环干了什么事儿。**

    * 内循环才是嵌套的核心，外循环无非就是把里面这件事又重复了 N 次；把内循环看明白了，外循环就是一个数字的事。

* **从笨办法改出嵌套**

    * 目标图形是四行五列的星，最笨的办法是五行 `System.out.println("*")` 手写出来，但输出结果是一个星独占一行。

    * `System.out.println` 的规则是**先打印再换行**；只想打印不换行就把 `LN` 删掉，变成 `System.out.print`，光标留在星后面继续打印。按住 `Alt` 用鼠标左键竖着选中五行的 `LN` 一起删掉即可。

    * > **提示**：以后看到任何「一行要打印好几个东西」的题目，第一反应就该是把 `println` 换成 `print`，换行单独拎出来做。这是打印图形题的第一块砖。

* **两层循环的分工**

    ```java
    for (int i = 1; i <= 4; i++) {
        for (int j = 1; j <= 5; j++) {
            System.out.print("*");
        }
        System.out.println();   // 打印完一行之后换行
    }
    ```

    * 外循环控制行数，内循环控制一行打印多少个星，`System.out.println()` 属于**外**循环。

    * 内外循环都叫 `i` 时一屏全是 i 且极容易改错，把内层改成 `j`：选中变量名按 `Shift + F6` 批量重命名，所有用到它的地方会一起改。

    * > **易错点**：内循环的 `System.out.println()` 千万别漏，也别放错位置。一行五颗星全部打完才换一次行；放进内循环就变成一颗星一行，重新掉回最笨的写法。

### 从长方形到三角形

* **正三角形**

    ```java
    for (int i = 1; i <= 5; i++) {
        for (int j = 1; j <= i; j++) {
            System.out.print("*");
        }
        System.out.println();
    }
    ```

    * 外循环的作用是「把在一行打印 N 颗星这件事重复五次」。

    * 手写五行时循环体完全一样，唯一不同的是结束条件分别是 1、2、3、4、5；拿一个从 1 变到 5 的变量把内循环结束条件替换掉即可，那就是外循环的 `i`。

    * 与打印长方形的代码相比，差别就只有内循环的结束条件这一处。

* **倒三角形的两种写法**

    * 第一种还是控制内循环的结束条件，写成 `6 - i`：

    ```java
    for (int i = 1; i <= 5; i++) {
        for (int j = 1; j <= 6 - i; j++) {
            System.out.print("*");
        }
        System.out.println();
    }
    ```

    * `i` 是 1、2、3、4、5 依次变化，拿 6 去减就得到 5、4、3、2、1。

    * 第二种把结束条件固定写成 5，开始条件改成 `i`：

    ```java
    for (int i = 1; i <= 5; i++) {
        for (int j = i; j <= 5; j++) {
            System.out.print("*");
        }
        System.out.println();
    }
    ```

    * `i` 等于 1 时是 1 到 5，打印五颗星；等于 2 时是 2 到 5，打印四颗星，依次类推。

    * > **提示**：这两种写法的本质都是「用外循环变量反推内循环的次数」。`6 - i` 是让上界跟着 `i` 变，`j = i` 是让下界跟着 `i` 变。先把次数数列写出来（1、2、3… 或者 5、4、3…），再决定动上界还是动下界，绝大多数图形题都是这个套路。

### 复杂图形的两种拆法

* **先凑成长方形**

    * 打印复杂图形的技巧是**第一步先把它凑成一个长方形**，比如平行四边形先补星凑成 6 列，再分成 N 多的小块一块一块打印。

    ```text
      ★★        ← 补两颗星，凑成 6 列
       ★★            ← 补一颗星
    ★★                ← 不补
    ```

* **平行四边形：找规律版**

    ```java
    // 平行四边形：3 行 6 列
    for (int i = 1; i <= 3; i++) {
        // 第一块：左上角的倒三角
        for (int j = i; j <= 2; j++) {
            System.out.print("#");
        }
        // 第二块：中间的长方形，每一行都是 6 个星
        for (int j = 1; j <= 6; j++) {
            System.out.print("*");
        }
        System.out.println();
    }
    ```

    * 左上角是倒三角，外循环从 1 到 3 结束控制图形行数，内循环开始条件写 `i`、结束条件写小于等于 2。

    * 别忘了把 `LN` 都删掉，两段打完统一换行；最后再把井号 `#` 改成空格，平行四边形就出来了。

* **梯形：规律不好找的时候**

    * 梯形第一行三个、第二行五个、第三行七个，结束条件要按 3、5、7 这么变化。

    * 对数学敏感的话能发现规律是**二乘以 i 再加一**：

    ```java
    // 内循环的结束条件
    for (int j = 1; j <= 2 * i + 1; j++) {
        System.out.print("*");
    }
    ```

* **平行四边形：拆块版**

    * 第二种思路是把长方形和三角形当作基础形状，把复杂图形拆成 N 多个长方形与三角形的组合：

    ```text
      第1行：[空2] [★1] [★★★] [★★]
      第2行：[空1] [★★] [★★★] [★]
      第3行：[空0] [★★★] [★★★] [空0]
              块1    块2    块3    块4
    ```

    * 绿色那块是三角形，蓝色的是长方形，右上角青色的是小三角形；右下角那块是空格可以忽略。

    ```java
    for (int i = 1; i <= 3; i++) {
        // 第一块：左上角倒三角，最后把 "#" 换成空格
        for (int j = i; j <= 2; j++) {
            System.out.print("#");
        }
        // 第二块：正三角，1 到 i 个星
        for (int j = 1; j <= i; j++) {
            System.out.print("*");
        }
        // 第三块：长方形，每一行都是 3 个星
        for (int j = 1; j <= 3; j++) {
            System.out.print("*");
        }
        // 第四块：右上角倒三角，跟第一块是同一个循环
        for (int j = i; j <= 2; j++) {
            System.out.print("*");
        }
        // 右下角那一块是空格，忽略不计
        System.out.println();
    }
    ```

    * 内循环要写四个，代码量明显变多，但不需要找规律，直接生搬硬套。

* > **结论**：图形题不要一上来就找通项。绝大多数复杂图形都能切成「正三角 + 倒三角 + 长方形 + 空格」这四类积木，每一块的内循环都是一个独立的 `for`，唯一的坑是**同一层里多个内循环的变量不能都叫 `i`**，改用 `j`、`k`（或者改完记得 `Shift + F6`），否则改一个就把另一个也改了。

### 九九乘法表

* **先把形状打出来**

    * 忽略内容只看形状，九九乘法表跟直角三角形一模一样，是九行九列。外循环 `for (int i = 1; i <= 9; i++)` 决定行数，内循环 `for (int j = 1; j <= i; j++)` 决定列数，先在循环体里不管三七二十一打印一个星。

    ```java
    for (int i = 1; i <= 9; i++) {
        for (int j = 1; j <= i; j++) {
            System.out.print("*");
        }
        System.out.println();   // 每一行打完，另起一行
    }
    ```

* **再推导每一格的内容**

    * 三个数字分别是乘数、被乘数、乘积，其中前两个都从 1~9 变化，整个循环里符合的正是 `i` 与 `j`。

    ```java
    for (int i = 1; i <= 9; i++) {
        for (int j = 1; j <= i; j++) {
            System.out.print(j + "*" + i + "=" + (i * j) + "\t");
        }
        System.out.println();
    }
    ```

    * 三个细节：变量要挪到双引号外面，不然打出来的是字面量；`i * j` 外面的括号可以删掉，因为计算时先算乘除再算加减；按 `Ctrl + Alt + L` 格式化代码。

    * 一开始写成 `i * j` 打出来第二行是 `2*1`、`2*2`，跟想要的 `1*2`、`2*2` 不一致，把 `i` 和 `j` 的位置换一下即可。

* **对齐：加空格救不了**

    * 后面加 4 个空格确实能分开，但乘积有的是一位数有的是两位数，后面就没法对齐了；改用制表符 `\t` 就能上下对齐。

### 制表符的对齐规则

* **制表符**

    * > **定义**：制表符的书写格式是 `\t`，可以理解成一个长度可变的大空格，作用是在打印表格类数据时让上下对齐。

    * 表格例子：

    ```java
    System.out.println("name\tage\tgender");
    System.out.println("张三\t\t23\t男");
    System.out.println("李四\t\t24\t女");
    ```

    * 只按空格间隔不会对齐；换成制表符后，`name` 后面一个制表符顶不过「张三」「李四」这两个名字的宽度，所以名字后面各要加两个 `\t` 才对齐。觉得间距小还可以再加两个。

* **真正的规则**

    * 制表符在打印时**不会去观察上一行的数据**，跟表头关系不大；它真正的作用是在**前面的字符后面补 1~4 个空格，让整体长度凑成四的整数倍**。也有编译器补 1~8 个空格凑成八的整数倍，IDEA 遵守的是前一种规则。

    * 「整体」指**前面的字符加上制表符本身**，与后面的内容无关：

    ```text
    标尺：12345678901234567890

    --\t--     前面 2 个字符，制表符本身算第 3 个
               → 补 2 个空格，凑成 4
               实际：--␣␣--

    ---\t---   前面 3 个字符，制表符本身算第 4 个
               → 补 1 个空格，凑成 4
               实际：---␣

    ----\t---- 前面 4 个字符，已经凑成 4 的整数倍
               → 补 4 个空格，凑成 8
               实际：----␣␣␣␣
    ```

    * 第三个是重点：前面已经是四的整数倍，规则写的是补 **1~4** 个空格，**没有零**，所以只能补四个。

* > **提示**：千万不要把 `\t` 理解成「到不了边界就原地停下」。它宁可让这一列变宽一倍，也一定会往前走至少一格，这正是它能让不同位数的列自动对齐的原因。

* **回头验证九九乘法表**

    * `1*1=1` 前面一共 5 个字符，凑成四的整数倍补 3 个空格就够，凑成 8；`2*5=10` 因为「10」多了一位，制表符补 2 个空格凑成 8。补的空格不一样，后面就直接对齐了。

## 数组入门

* **数组**

    * > **定义**：数组是一个容器，可以用来存储同种数据类型的多个值。以后要存储很多相同类型的数据时就可以用数组。

    * 动机来自变量的局限：记录 100 个游戏名就得定义 100 个变量，变量干不了的事数组能干。

    * 「同种数据类型」不能理解得太死，Java 里有隐式转换，取值范围小的赋值给取值范围大的可以，`double` 类型的数组里存整数会自动转成小数；不过一般来讲数组规定什么类型就存什么类型，不会正面硬刚。

* **要学的四个知识点**

    | 知识点 | 学什么 | 为什么现在要学 |
    | :--- | :--- | :--- |
    | 静态初始化 | 把数组定义出来，再存储一些数据 | 这是最基础的创建方式，先把「容器里能放东西」这件事跑通 |
    | 元素的访问 | 如何获取数组里面的数据，如何修改数组里面的数据 | 光存不用没有意义，得能取得到、改得动 |
    | 数组的遍历 | 获取数组里面所有的元素 | 有了访问，才有办法把所有元素过一遍 |
    | 动态初始化 | 创建数组时先给默认值，等知道要存什么数据了再修改 | 有的时候创建数组时根本不知道要存什么 |

    * 动态初始化必须单独学，是因为创建数组时常常还不知道里面要存什么数据，比如用来存键盘录入的五个整数，定义数组时还不知道具体值，这时不能用静态初始化。

    * 后面还会继续学数组的常见问题、写大量算法真题，最后站在内存角度深入分析数组的完整结构。
