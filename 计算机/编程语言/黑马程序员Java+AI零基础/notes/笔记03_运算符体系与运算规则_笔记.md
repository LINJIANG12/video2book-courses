# 运算符体系与运算规则

## 算术运算与数值精度

### 五个算术运算符

* **算术运算符（arithmetic operator）**
    * > **定义**：拿数据做加减乘除和取余的运算符，Java 一共五个：`+`、`-`、`*`、`/`、`%`。
    * `%` 就是「获取余数」，用法与数学里的取余完全一致。
    * 除法的斜杠必须敲成正斜杠 `/`，写成反斜杠 `\` 是错的，会直接标红。
    * 同类型数据参与运算，结果仍是该类型：`int` 加 `int` 得 `int`，`double` 加 `double` 得 `double`。

* **整数计算的实测结果**
    * 取 `a = 10`、`b = 3`，逐个跑五个运算符。

    | 表达式 | 运行结果 | 说明 |
    | :--- | :--- | :--- |
    | `a + b` | 13 | 与数学一致 |
    | `a - b` | 7 | 与数学一致 |
    | `a * b` | 30 | 与数学一致 |
    | `a / b` | 3 | 小数部分被丢弃 |
    | `a % b` | 1 | 10÷3 余数就是 1 |

* > **提示**：做带算法色彩的题目卡壳时，先让工具只给思路、不要直接生成代码——自己没思路时生成的代码看不懂，也不知道对不对。

### 整数相除只取商

* **整数相除（integer division）**
    * > **结论**：整数相除，结果还是整数，取的就是**商**，余数那部分根本不考虑。
    * `10 / 3` 在程序里得 `3`，而不是数学上的 3.3333……
    * 除法算式里的每一个数字都是整数时，结论同样成立。
    * 这条规则是把多位数拆成个位、十位、百位的前提。

### 小数参与计算的精度损失

* **小数计算的不精确现象**
    * `10.0 / 3.0` 除不尽，程序给的是 `3.3333333333333335`。
    * 换成 `1.1` 与 `1.01` 做四则，连加减乘也全飘：`1.1 + 1.01` 应为 `2.11`，程序给 `2.1100000000000003`；`1.1 - 1.01` 得 `0.09000000000000008`；`1.1 / 1.01` 得 `1.0891089108910892`。
    * > **结论**：小数直接参与计算，结果是有可能不精确的。
    * > **易错点**：这不是某一门语言的毛病，而是所有编程语言共有的现象——计算机用二进制存小数，十进制里的 0.1 在二进制中根本写不出来，只能用一串「无限接近但不等于」的二进制去逼近。
    * 实际开发中要做精确运算，改用 `BigDecimal`。

## 数值拆分与时间换算

### 位拆分公式

* **数位拆分（digit extraction）**
    * 个位、十位、百位、千位都可以用同一条套路拿到：以 10 为底，先除去掉低位，再对 10 取余。

    | 要拆的位 | 表达式 |
    | :--- | :--- |
    | 个位 | `number % 10` |
    | 十位 | `number / 10 % 10` |
    | 百位 | `number / 100 % 10` |
    | 千位 | `number / 1000 % 10` |
    | 万位、十万位、百万位…… | 以此类推，同一个套路 |

    * 拆 `123` 的验算过程：

    ```text
      123  %  10       →  3        余数就是个位
      123  /  10       →  12       整数相除，只剩商
       12  %  10       →  2        余数就是十位
      123  /  100      →  1        商就是百位
    ```

    * 写成公式：$$\text{个位} = n \bmod 10 \qquad \text{十位} = \left\lfloor n / 10 \right\rfloor \bmod 10 \qquad \text{百位} = \left\lfloor n / 100 \right\rfloor \bmod 10$$

    * `number / 10 % 10` 里运算符**从左到右依次计算**，等价于 `(n / 10) % 10`：先取出商，再取这个商的个位。
    * 百位后面再补一个 `% 10` 不会改变结果：123 除以 100 商 1 余 23，整数相除只留 1；`1 % 10` 仍得 1。补上它纯粹是为了让每一行的写法保持统一、更具通用性。

* **拆分三位数的完整写法**

    ```java
    Scanner sc = new Scanner(System.in);
    System.out.println("请输入一个三位数");
    int number = sc.nextInt();

    int ge = number % 10;         // 个位
    int shi = number / 10 % 10;   // 十位
    int bai = number / 100 % 10;  // 百位

    System.out.println("个位是" + ge);
    System.out.println("十位是" + shi);
    System.out.println("百位是" + bai);
    ```

    * 只打印裸数字看不出对应关系，加上「个位是」「十位是」「百位是」这类字符串前缀才能读懂输出。

### 秒数转时分秒

* **时间换算（seconds to h:m:s）**
    * 题目：把给定秒数 `seconds` 转成小时、分钟、秒，总时间不变，且分钟与秒都不超过 59；示例 `3661` → `1 1 1`。
    * 小时：`int hour = seconds / 3600;`
    * 分钟：先剥掉整小时的部分再除以 60 —— `int min = seconds % 3600 / 60;`
    * 秒：`int second = seconds % 60;`
    * > **易错点**：分钟数不能写成 `seconds - 3600` 把 3600 写死。秒数是 3661 时看不出问题，换成 7220 就错——`7220 % 3600` 得 20，正确分钟是 20，而写死的写法算出 `-580`。要减的是「总秒数对 3600 的余数」，不是写死的 3600。
    * 验证：3661 得 1 小时 1 分 1 秒，3662 得 1 小时 1 分 2 秒，7242 得 2 小时 0 分 42 秒。
    * 拼接输出形如 `2小时0分42秒`。

## 类型转换规则

* **类型转换（type conversion）的总纲**
    * > **结论**：类型不一样不能运算，必须转成同类型才能计算。
    * 转换以**取值范围**为标准：范围小的转大的叫「提升」，大的塞进小的必须手动强转。

### 隐式转换

* **隐式转换（implicit conversion / widening）**
    * > **定义**：把取值范围小的类型变成取值范围大的类型，底层实质是**前面补零**。
    * 由 Java 底层自动完成，不需要自己写代码。

    ```text
      byte  的 56（1 字节 = 8 比特位）
      0011 1000

      隐式提升为 int（4 字节 = 32 比特位）：前面补 24 个 0，数值一分不变
      0000 0000 0000 0000 0000 0000 0000 0011 1000
    ```

    * 转 `short` 前面补八个零凑齐 16 比特，转 `int` 补到 32 比特，转 `long` 补到 64 比特。
    * 不同类型的数据参与计算时默认走隐式转换。

* **隐式转换的两步顺序**
    * 第一步：先在参与计算的数据里找有没有 `byte` 或 `short`，有就**不管三七二十一先转成 `int`**。
    * 第二步：再把取值范围小的提升为取值范围大的，变成同类型后再计算。
    * 由此推出两条固定结论：
        * 两个 `byte` 相加，结果**不是 `byte` 而是 `int`**，因为底层实际是两个 `int` 在相加。
        * `byte` 加 `double`：先 `byte → int`，再因 `int` 取值范围小于 `double` 而 `int → double`，最终两个 `double` 相加，结果是 `double`。

* **连续加法的类型演算**
    * 连续相加是**从左到右依次计算**的，必须拆成一步一步看。

    ```java
    byte b = 100;
    short s = 200;
    double d = 20.3;
    double result = b + s + d;   // 运行结果 320.3
    ```

    ```text
      b + s + d
      = (b + s) + d                     连续加，从左到右
      = (int 100 + int 200) + double 20.3
      = int 300 + double 20.3            byte / short 先提升为 int
      = double 300.0 + double 20.3       int 范围小于 double，继续提升
      = double 320.3  →  赋值给 double result
    ```

### 强制转换

* **强制转换（cast / narrowing）**
    * > **定义**：从大类型转成小类型，底层实质是**把前面不要的砍掉**，只留下低位字节。

    ```text
      int 类型的 252645121
      ┌──────────────┬──────────────┬──────────────┬──────────────┐
      │ 0000 1111    │ 0000 1111    │ 0000 1111    │ 0000 0001    │
      └──────────────┴──────────────┴──────────────┴──────────────┘
            丢掉            丢掉            丢掉          保留
      强转成 byte：只留最后一个字节 → 0000 0001 → 变成了数字 1
    ```

    * 2 亿 5 千多万一下变成 1，这就是强转的弊端：**可能导致精度丢失，改变原本的数据**。
    * 正因为有风险，强制转换**不会自动触发**，必须自己手写。
    * 书写格式：在前面加小括号，括号里写要转成的类型。

* **强转一个计算结果**

    ```java
    byte c = (byte) (a + b);
    ```

    * 适用场景：`byte` 加 `byte` 的结果是 `int`，把这个 `int` 赋给 `byte` 变量会报错，只能靠强制转换。
    * > **易错点**：后面那对小括号绝对不能丢。加括号表示强转的是 `a + b` 的**结果**；不写括号，强转的就是变量 `a` 本身，而 `a` 原本就是 `byte`，强转了也没用——一参与运算它照样提升为 `int`，整段代码照样报错。

* **两种改法的取舍**

    ```java
    short s1 = 100;
    short s2 = 200;
    byte result = s1 + s2;   // 编译阶段直接报错
    ```

    * 报错原因：两个 `short` 参与运算都先提升为 `int`，相加结果是 `int`，`int` 塞不进 `byte`。

    | 方案 | 写法 | 运行结果 | 结论 |
    | :--- | :--- | :--- | :--- |
    | 强转 | `byte result = (byte) (s1 + s2);` | 44 | 能跑，但数据已经被改了 |
    | 改类型 | `int result = s1 + s2;` | 300 | 数据完好无损 |

    * 强转方案错在哪：300 的 32 位二进制里被砍掉的三个字节中仍含有一个 `1`，只剩最后那个字节 `0010 1100`，转回十进制正好是 44。
    * > **结论**：实际开发中能不用强制转换就尽量不用，改接收变量的数据类型更稳。

## 字符运算

* **ASCII 码表（American Standard Code for Information Interchange）**
    * > **定义**：一张让每个字符与唯一数字对应的码表；字符参与计算时先查表变成数字再做运算。
    * 大写 `'A'` 对应的数字是 **65**，所以 `char c = 'A'; c + 1` 的结果是 `66`。
    * 字符和数字混算不会报错，因为字符的底层本就是数字。

### 大小写转换

* **字母大小写差值**
    * 码表里同一字母的大写与小写**相差 32**。

    ```text
      'A'  →  65   ┐
                     ├──  相差 32
      'a'  →  97   ┘
    ```

    * 规律：`'A'` 参与运算先变成 `int` 的 65，`65 + 32 = 97`，97 强转回 `char` 就是小写 `'a'`。
    * `'B'` 同理：66 + 32 = 98 → `'b'`。

    ```java
    char c = 'A';
    char cc = (char) (c + 32);
    System.out.println(cc);   // a
    ```

    * 不写 `(char)` 会把 int 结果赋给 char 变量而报错，查码表即可确认结果是哪个字符。

## 字符串运算

* **字符串拼接（string concatenation）**
    * > **结论**：任意数据加字符串，进行的都是**拼接**操作，并产生一个新的字符串。
    * 字符串只有加号，没有减号乘除。
    * 拼接过程同样**从左到右依次计算**，一旦某一步出现字符串，后面全部转为拼接：

    ```text
      10      + 8            →  18          两边都是数字，做加法
      18      + "岁"         →  "18岁"      有字符串参与，走拼接
      "18岁"  + 1            →  "18岁1"     只要有字符串参与就是拼接
      "18岁1" + 2            →  "18岁12"    同上
    ```

    * 所以 `10 + 8 + "岁"` 是 **18 岁**，不是 108 岁。
    * `10 + 8 + "岁" + 1 + 2` 是 **18岁12**。
    * 数值拼接 `123 + "AAA"` 得 `"123AAA"`。
    * 拆分与换算两类题目的输出都可以靠前缀拼接变成可读形式：`"个位是" + ge`、`hour + "小时" + min + "分" + second + "秒"`。

## 自增自减运算符

### 基本形式

* **自增自减运算符（increment / decrement）**
    * > **定义**：`++` 把变量中的值加一，`--` 把变量中的值减一。
    * 写在变量前面叫**先加加**，写在变量后面叫**后加加**；两种写法的基本作用完全一样，都表示把值加一。
    * `a++` 等同于这三行：先取值 → 加一 → 再赋回变量。

    ```java
    int a = 10;
    a++;                  // 等价于 a = a + 1;
    System.out.println(a);   // 11
    ```

    ```text
       a = 10
         │
         ▼
       a++   ──►   先把 a 里的值 10 拿出来
                     │
                     ▼
                  10 + 1 = 11
                     │
                     ▼
                  再把 11 塞回 a 里

       打印 a  →  11
    ```

* **连续自增自减的推演**
    * `int a = 10;` 后接 `a++; a++; a--; a--; a--;`，最终打印结果是 **9**。
    * 逐步：10 → 自增 **11** → 自增 **12** → 减一 **11** → 减一 **10** → 减一 **9**。
    * > **提示**：连续自增自减时把每一行的值念出来，比盯着代码猜靠谱得多。

* > **注意**：先加加、后加加**再参与计算**时的返回值差异不用研究——这种写法在程序里基本没人用，面试不问、项目不用，又晦涩难懂，把基本使用吃透即可。

### 计数用途

* **做计数（counting）**
    * 自增自减最本质的用途：起始值先记 0，碰到目标就 `++` 一次，不碰到就不动。

    ```text
       初始：心里先记 0

       左边第一个 —— 是蜜蜂吗？是  → 心里自增一次 → 1
       第二个     —— 是蜜蜂吗？不是，是一只鸟 → 不变     → 1
       第三个     —— 是蜜蜂吗？是  → 心里自增一次 → 2
       第四个     —— 是蜜蜂吗？是  → 心里自增一次 → 3

       答：三只小蜜蜂
    ```

    * 购物车数量放大也是同一回事：点一次 `[+]` 就是 `number++`，点一次 `[−]` 就是 `number--`，连点两次就是连着两次 `number++;`。

## 赋值运算符

* **赋值运算符（assignment operator）**
    * > **定义**：把等号**右边**的值，赋给等号**左边**的变量。
    * 最常见的是等号直接赋值：`int a = 10;`
    * 扩展写法有五种：`+=`、`-=`、`*=`、`/=`、`%=`（取余等）。
    * 规则统一：**左边和右边运算，结果只赋给左边的变量，右边不受任何影响**。

    ```java
    int a = 10;
    int b = 20;
    a += b;

    System.out.println(a);   // 30
    System.out.println(b);   // 20
    ```

    * `b` 之所以纹丝不动，是因为相加的结果只回到 `a` 身上，`b` 只是被读了一次。
    * `-=`、`*=`、`/=`、`%=` 与 `+=` 规则完全一致。
    * > **易错点**：`a += b` 与 `a = a + b` 对 `a` 而言结果一样，但前者只写一次 `a`，少打几个字，也少一次「万一手滑写错变量名」的机会。

## 关系运算符

### 六个关系运算符

* **关系运算符（relational / comparison operator）**
    * > **定义**：拿左右两边做一个判断，结果只有 `true` 或 `false` 两个布尔值。

    | 符号 | 读作 | 判断什么 |
    | :--- | :--- | :--- |
    | `==` | 等于 | 左右两边是否相等 |
    | `!=` | 不等于 | 左右两边是否不相等 |
    | `>` | 大于 | 左边是否大于右边 |
    | `>=` | 大于等于 | 左边是否大于或等于右边 |
    | `<` | 小于 | 左边是否小于右边 |
    | `<=` | 小于等于 | 左边是否小于或等于右边 |

    * 与数学上的判断含义没有任何区别，只是书写方式必须照敲。
    * > **易错点**：判断两边是否相等要用**两个**等号 `==`；一个等号在 Java 里是**赋值**。
    * > **易错点**：数学里写成的 `≥`、`≤` 在 Java 里不是一个字符，必须分开敲成 `>=` 和 `<=`。

### 布尔结果的接收与整除模板

* **比较结果要用布尔变量接**
    * `boolean result = myHeight >= friendHeight;` —— 比较结果要么 `true` 要么 `false`，要用布尔类型变量接收。

* **整除判断模板**
    * 数学原理：**一个数字的各位数字之和能被 3 整除，这个数字就能被 3 整除**。
    * 步骤：拆出三个数位 → 相加得 `sum` → 拿 `sum` 对 3 取模 → 与零比较。

    ```java
    Scanner sc = new Scanner(System.in);
    System.out.println("请输入一个三位数");
    int number = sc.nextInt();

    int ge = number % 10;
    int shi = number / 10 % 10;
    int bai = number / 100 % 10;
    int sum = ge + shi + bai;

    boolean result = sum % 3 == 0;
    System.out.println(result);
    ```

    * 输入 333 得 `true`，输入 334 得 `false`。
    * > **提示**：`% 3 == 0` 是万能模板——判断被 2 整除写 `% 2 == 0`，被 7 整除写 `% 7 == 0`，记住这一个写法什么整除判断都是它。

## 逻辑运算符

### 三个逻辑运算符

* **逻辑运算符（logical operator）**
    * > **定义**：在多个条件之间表达「同时成立」还是「满足其一」的运算符。

    | 符号 | 名称 | 含义 | 键盘怎么打 |
    | :--- | :--- | :--- | :--- |
    | `&&` | 与（and），「而且」 | 多个条件**同时成立**才符合要求 | `Shift` + 数字 `7` |
    | `\|\|` | 或（or），「或者」 | 多个条件**只要有一个符合**就可以 | `Shift` + `\` |
    * `!` | 非，取反 | `false` 取反变 `true`，`true` 取反变 `false` | 数字 `1` 左边那个 |

    * Java 中**不能连写** `1 < x < 10`，语法是错的，必须先拆成 `x > 1` 与 `x < 10`，再按「同时满足」组合。

### 区间判断与选型

* **两种区间写法的对照**

    ```java
    // ① 在 1~10 之间：两个条件必须同时成立
    boolean result = number > 1 && number < 10;      // 输入 5 → true，输入 20 → false

    // ② 不在 1~10 之间：满足其一即可
    boolean result = number <= 1 || number >= 10;    // 输入 10 → true，输入 5 → false
    ```

    * 画成数轴看第一种：区间两端是 `1` 和 `10`，命中段是 `x > 1` 且 `x < 10`，两个条件缺一不可；第二种命中的是 1 左边和 10 右边两段。
    * > **结论**：题目的要求是**两边同时满足**就用 `&&`；要求**二选其一、多条件只要满足其中一个**就用 `||`。
    * 真实场景对照：登录要用户名和密码**全部正确**，用 `&&`；扫码登录与账号登录**满足一种即可**，用 `||`。

## 短路逻辑运算符

### 触发条件与整体结果

* **短路逻辑运算符（short-circuit operator）**
    * > **定义**：写法与单个 `&&`、`||` 完全一样，区别在于右边有可能压根不执行，用来省掉无意义的那一趟。
    * 单个 `&&` 的效率低：左边已经算出 `false` 时，与运算要的是两边同时成立，整体已经确定为 `false`，右边再算也是白算。
    * 对比示意：

    ```text
      键入 5 → 左边 true → 右边照样执行 → true  → 结果 true     ← 两边都算了，没优化

      键入 1 → 左边 false → 右边还是被执行 → true  → 结果 false ← 右边这一趟白跑了

      键入 1 → 左边 false → 右边直接跳过   →       → 结果 false ← 短路与：省掉这一趟
    ```

    | 写法 | 名称 | 触发条件 | 行为 | 整体结果 |
    | :--- | :--- | :--- | :--- | :--- |
    | `&&` | 短路与 | 左边是 `false`，不成立 | 右边**不再执行** | `false` |
    | `\|\|` | 短路或 | 左边是 `true`，已经成立 | 右边**不再执行** | `true` |

    * 短路与最大的好处：第一个条件已经不成立时，后面那一串判断可以整体不执行。
    * > **结论**：短路逻辑运算符本身就是逻辑运算符，只是其中比较特殊的两种；实际开发里真正高频的是 `&&`、`||` 和取反 `!`，掌握这三个即可。

### 回文数判断

* **回文数（palindrome number）**
    * > **定义**：不管从左往右读还是从右往左读，结果都一样的数字，具有对称性；如 `1221` 是，`1234` 不是（倒着读是 4321）。
    * 落到四位数上就是**第一位等于最后一位、第二位等于倒数第二位**，两组必须**同时成立**，所以用 `&&`。

    ```text
       number = 1 2 2 1
                ↑ ↑ ↑ ↑
                │ │ │ └── 个位  d = number % 10
                │ │ └──── 十位  c = number / 10 % 10
                │ └────── 百位  b = number / 100 % 10
                └──────── 千位  a = number / 1000 % 10

       回文 = ( 千位 a == 个位 d )  &&  ( 百位 b == 十位 c )
                  也要同时成立 ↑
    ```

    * 千位写成 `number / 1000 % 10`，补上 `% 10` 是为了跟其他行保持同一个套路。

    ```java
    boolean result = (qian == ge && bai == shi);
    System.out.println(result);
    ```

    * 输入 1221 得 `true`，输入 1234 得 `false`；也可以不用 `result` 变量，直接把整个表达式写进输出语句。

### 含有 7 判断

* **包含 7 的三条件**
    * 「包含 7」的具体含义是：**个位是 7 或十位是 7**，只要有一个是 7 就算包含。
    * 「7 的倍数」在程序里的体现是：拿这个数对 7 取余，结果是零就是倍数。

    ```java
    int number = 18;

    int ge = number % 10;
    int shi = number / 10 % 10;

    boolean result = (ge == 7 || shi == 7 || number % 7 == 0);
    System.out.println(result);
    ```

    * 题目说「包含 7 **或者**是 7 的倍数」，是三选一，三个条件之间全用 `||`。
    * 实测：71（十位是 7）`true`、17（个位是 7）`true`、21（7 的倍数）`true`、22 `false`。

## 三元运算符

* **三元运算符（ternary operator）**
    * > **定义**：格式为 `关系表达式 ? 表达式1 : 表达式2;`
    * > **规则**：运行时先执行前面的关系表达式（也就是先做判断），结果为 `true` 就执行表达式一，为 `false` 就执行表达式二。
    * 解决的是「想要的是具体值而不是布尔值」的问题：普通比较只能得到 `true`/`false`，三元能把判断直接映射成两个候选答案。
    * 取较大值的两种写法：

    ```java
    int a = 20;
    int b = 10;

    // 方式一：结果赋值给变量
    int max = (a > b ? a : b);

    // 方式二：整体写进输出语句直接打印
    System.out.println(a > b ? a : b);
    ```

    * 三元结果必须再做处理：要么赋值给变量，要么整体写进输出语句，不能单独悬着。
    * 两个数相等时无所谓，给表达式一或表达式二都可以。
    * > **易错点**：表达式一和表达式二的最终结果类型要能赋给接收它的变量——两边都是 `int` 没问题；一边 `int` 一边 `double` 而接收变量是 `int`，得先想清楚到底要哪一个。
    * 两个难点：格式长不好记（可以借工具生成，但要会检查生成结果对不对）；运行规则需要记牢。

## 运算符优先级

* **运算符优先级（operator precedence）**
    * > **结论**：只需要记住一条——**小括号优先于所有**；优先级表当参考用即可。
    * 完整的优先级表不需要背：越靠上的优先级越高，同一行内左边的优先级更高。
    * 想让某一部分先算，就用小括号把它括起来，比背表和临时查表都靠谱。

    ```text
            ↑  越往上的优先级越高
       ────────────────────────────────  优先级表
            同一行内：左边的优先级更高
       ────────────────────────────────
            ↓  越往下的优先级越低
    ```

    * 加了括号后的理解路径：先分别算出每个判断的结果，再看这些结果是否同时成立。

    ```text
       没有括号时：谁先算谁后算，得去查那张表

       加了括号后：

       ( 判断一 )  &&  ( 判断二 )  &&  ( 判断三 )
           │              │               │
           ▼              ▼               ▼
       先算出判断一的结果，再算出判断二、判断三的结果
           │              │               │
           └──────────────┴───────────────┘
                          ▼
                  再看这三个是否同时成立
    ```
