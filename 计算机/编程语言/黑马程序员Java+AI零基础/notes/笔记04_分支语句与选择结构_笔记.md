# 分支语句与选择结构

## 顺序执行与三类分支语句

* **顺序执行（sequential execution）**

    * > **定义**：程序默认的、从上往下依次运行、先来后到的执行流程。

    * 此前写过的代码几乎都属于这一类，只有极少数场景才需要打破它。

    * 只靠顺序执行表达不了"分情况"：登录时若把"登录成功跳转主页"和"登录失败重新登录"顺着写下来，不管账号密码对不对，每次都会先跳转主页再重新登录。

* **判断、选择、循环三类语句**

    * > **定义**：为补上顺序执行表达不了的分支与重复需求而引入的三类流程控制语句。

    * 判断语句：控制某段代码是否执行。

    * 选择语句：把所有选项一一列举出来，按条件任选其一执行。

    * 循环语句：重复执行同一段代码。

* **判断语句（if 语句）**

    * > **定义**：只有满足对应的条件，对应的代码才能执行的语句；因为格式中用到了 `if` 关键字，所以也叫 `if` 语句。

    * 体温测量仪是生活化的使用场景：仪器自动检测体温，超过 38 度才发出语音警告，这个警告并不是每次都出现。

    * 项目里处处都是判断——登录时判断用户名与密码是否正确，支付时判断账户余额是否足够，游戏受到伤害时判断剩余血量是否归零。

    * "小括号 + 大括号"是所有分支与循环语句的公共骨架，`switch`、`for`、`while` 都长这个样子。把 `if` 的结构记住，后面学这些语句就没有压力。

    * > **提示**：细节不必死记，代码出错时知道怎么改就行。

## if 的第一种格式

* **语法格式**

    * > **定义**：小括号里写关系表达式，大括号里写满足条件才执行的语句体。

    ```java
    if (关系表达式) {
        语句体;
    }
    ```

    * 关系表达式就是大于、小于、大于等于、小于等于这类比较，结果为 `true` 才执行大括号里的语句体。

* **执行流程**

    * 先执行小括号里的关系表达式。

    * 结果为 `true`：执行大括号里的语句体，语句体执行完毕后再执行 `if` 下面的其他代码。

    * 结果为 `false`：压根不进入大括号，直接执行 `if` 下面的其他代码。

    ```text
            执行小括号里的关系表达式
                      │
            ┌─────────┴─────────┐
            │                   │
        结果为 true          结果为 false
            │                   │
       执行大括号里的语句体      跳过大括号里的语句体
            │                   │
            └─────────┬─────────┘
                      │
             执行 if 下面的其他代码
    ```

* **体温测量仪案例**

    * 题目要求：定义变量表示人的体温，体温大于等于 38 度就打印语音警告。

    * 体温是小数，数据类型用 `double`，变量名 `bodyTemperature`。

    ```java
    double bodyTemperature = 37.5;

    if (bodyTemperature >= 38) {
        System.out.println("当前体温已经超过了38度");
    }
    ```

    * 取 37.5 时不打印，改成 39 时打印，改成 37 时又消失。

* **游戏血量上下限案例**

    * 题目要求：人物初始最大生命值 200 点，键盘录入受到的伤害 X 与技能恢复的血量 Y；人物不会死亡，最低 1 点血，问最终血量。

    * 直接写 `200 - X + Y` 是错的：伤害超过剩余血量时要托底到 1，恢复超过上限时要压回 200，两头都得判断。

    ```java
    int hp = 200;

    Scanner sc = new Scanner(System.in);
    System.out.println("请输入当前人物受到的伤害");
    int heart = sc.nextInt();

    hp = hp - heart;
    if (hp < 0) {
        hp = 1;
    }
    System.out.println("当前游戏人物的血量是" + hp);

    System.out.println("请输入技能恢复的血量");
    int add = sc.nextInt();

    hp = hp + add;
    if (hp > 200) {
        hp = 200;
    }
    System.out.println("当前游戏人物的血量是" + hp);
    ```

    * 上限那一处只能写 `hp > 200` 不能写 `hp >= 200`：相等时没必要修改，只有严格大于才需要压回上限。

    * 录入伤害 50 后剩余 150，录入恢复 300 后被压回 200。

    * > **易错点**：这段代码还有一个尚未修复的缺陷——伤害录入负数（如 -100）时，血量会变成 300。正确做法是判断录入的伤害是否为正数，为负就让它重复输入，这需要后面学循环才能补上。

## if 语句的四个细节

### 括号、分号与布尔判断写法

* **左大括号的位置**

    * > **定义**：Java 主流约定把左大括号写在上一行末尾，不单独成行。

    * 这种写法叫 **K&R 风格**（紧凑风），名字取自创造 C 语言的 Brian Kernighan（布莱恩·肯尼汉）与 C 语言之父 Dennis Ritchie（丹尼斯·里奇）——两人合著《The C Programming Language》，书中两种风格都用过，各取一个字母就成了 K&R。Java、Go 等多数语言遵守它；Java 采用它是因为 Oracle 官方示例基本都用它，安卓官方的谷歌编码规范以及 Spring 框架也都用它。

    * 左大括号另起一行独占一行的写法叫 **Allman 风格**（折叠风），源自 BSD UNIX 的主要开发者 Al Allman（奥尔曼）。该操作系统对安卓、iOS 影响很大，Windows 也有不少设计灵感来自它。C# 采用这种风格，认为结构更清晰。

    * C 与 C++ 两种风格都在用，取决于个人习惯。

    * 两种写法语法上都没有任何问题，只是不是 Java 的主流。

    ```java
    // K&R 风格
    if (score >= 60) {
        System.out.println("通过");
    }

    // Allman 风格
    if (score >= 60)
    {
        System.out.println("通过");
    }
    ```

* **大括号能否省略**

    * 语句体只有一行时大括号可以省略，语句体直接写在 `if` 后面，效果完全一样。

    * 语法上不写大括号时，距离 `if` 最近的那一行会被当作语句体，紧随其后的行会被当成独立于 `if` 之外的其他代码。

    * 强行省略的效果是：只运行了第二行代码，第一行成了被嵌套进去的语句体。

    ```java
    if (bodyTemperature >= 38)
        System.out.println("第一行代码");
        System.out.println("第二行代码");   // 这一行已经不属于 if 了
    ```

    * > **结论口径**：语句体只有一行，大括号可以省；语句体有多行，大括号必须写上。

* **小括号后面不能加分号**

    * > **易错点**：`if (bodyTemperature >= 38);` 这个分号千万不能加，加上之后 `37 >= 38` 虽然是 `false`，大括号里的代码却照样执行了。

    * 加分号等于切断了判断与语句体之间的联系：`if` 变成一段没有语句体的空判断，大括号则变成一段独立代码块，不再受上面 `if` 控制。

    ```java
    if (bodyTemperature >= 38);          // 这个分号千万不能加
    {
        System.out.println("当前体温已经超过了38度");
    }
    ```

* **判断布尔变量不要只写等号**

    * 两个等号才是判断，一个等号是赋值；`if (b == true)` 一旦漏写成单等号，就把 `true` 赋给了 `b`，小括号里的结果必然为 `true`。

    * 这种代码的运行结果具有欺骗性：变量值为 `true` 时打印"为真"，把变量改成 `false` 再运行，"为真"照样打印，变量里记录的值失去意义。

    * 正确做法是对布尔变量直接判断，把变量名原样写在小括号里。

    ```java
    boolean b = false;

    // 直接把变量写在小括号里
    if (b) {
        System.out.println("为真");
    }
    ```

## if 的第二种格式与嵌套

* **if...else 的语法与流程**

    * > **定义**：在第一种格式的基础上多加一个 `else`，对两种情况作出判断；`else` 可理解为"否则"。

    * 只需要判断单一情况时，第一种格式够用；需要判断两种甚至多种情况时，就得继续往后加分支。

    * 语句体 A 与语句体 B 二选其一执行，绝不会都执行；两边执行完都汇合到 `if` 下面的其他代码。

    ```java
    if (关系表达式) {
        语句体A;
    } else {
        语句体B;
    }
    ```

    ```text
            执行小括号里的关系表达式
                      │
            ┌─────────┴─────────┐
            │                   │
        结果为 true          结果为 false
            │                   │
         执行语句体 A          执行语句体 B
            │                   │
            └─────────┬─────────┘
                      │
             执行 if 下面的其他代码
    ```

* **成绩判断案例**

    * 题目要求：定义一个小数表示考试成绩，大于等于 60 输出"通过"，否则输出"不通过"。

    * 只写这一层判断存在缺陷：把成绩改成 200（异常数据）时仍会输出"通过"，与现实生活不符。

    * 补一层合理性校验即可：现实中的分数应当落在 1 到 100 之间，先卡范围再判是否及格。

    ```java
    double score = 59.9;

    if (score >= 0 && score <= 100) {
        if (score >= 60) {
            System.out.println("通过");
        } else {
            System.out.println("不通过");
        }
    } else {
        System.out.println("不合理");
    }
    ```

* **if 的嵌套**

    * > **定义**：`if` 里面还有其他的 `if`。

    * 把"是否及格"这一段整体挪进"成绩合理"的大括号里，200 会输出"不合理"，59.9 输出"不通过"，80 输出"通过"。

* **外卖优惠券比价案例**

    * 题目要求：两个平台——饱了么全场九折、满 30 减 10；一顿烧烤 50 元，问在哪家下单更划算；价格改为键盘录入时又该怎么写。

    * 第二步不能盲写判断：得先算出两个平台优惠后的价格，才能比较谁更低。饱了么是 `price * 0.9`，满减是 `price - 10`。

    * 满减不是白减的，它有门槛。价格改成 10 元时满减无法使用，所以要在满减计算前先判断 `price >= 30`，否则按原价计算。

    ```java
    double price = 50;

    double price1 = price * 0.9;

    double price2 = 0;
    if (price >= 30) {
        price2 = price - 10;
    } else {
        price2 = price;
    }

    if (price1 < price2) {
        System.out.println("饱了么app最便宜");
    } else {
        System.out.println("满减app最便宜");
    }
    ```

    * 把判断改成键盘录入时，后面所有计算与判断代码一行都不用动，只把 `50` 换成读取即可。

    ```java
    Scanner sc = new Scanner(System.in);
    System.out.println("请输入订单的价格");
    double price = sc.nextDouble();
    ```

    * 录入 100 时饱了么 90、满减 90，两者同价；录入 110 时饱了么 99，判定饱了么更便宜。

* **变量的作用域**

    * > **定义**：变量只在所属的大括号里有效，超出那个大括号范围就不可用。

    * 把 `price2` 定义在 `if` 的大括号内部，后面再拿它比较就会直接报错。

    * 解法是把 `price2` 定义到 `if` 外面，先给一个默认值（这里是 0），在 `if` 内部只修改它记录的值而不重新定义；`price1` 同理，直接由 `price` 赋值而来。

    * 挪到外层之后，`price2` 属于 `main` 后面的大括号，在整个方法范围内都能使用。

## if 的第三种格式与判断链

### 判断链的写法与执行

* **if...else if...else**

    * > **定义**：在第二种格式的基础上加若干 `else if`，用于多条件判断；`else if` 可以写多个，把不同条件分别写进各自的小括号。

    * 执行顺序是从上往下的：先算关系表达式 A，成立就执行语句体 A 并结束整个 `if` 体系；A 不成立看 B，B 成立就执行语句体 B 并结束；全都不成立才执行最后一个 `else` 的语句体。

    * 一句话概括：从上往下依次判断，只要有一个判断成立就执行对应语句体，只有所有判断都不成立才执行 `else`。

    ```text
            if (关系表达式A) ──成立──▶ 语句体A ──┐
                │ 不成立                          │
                ▼                                 │
            else if (关系表达式B) ──成立──▶ 语句体B ─┼──▶ 结束整个 if 体系
                │ 不成立                          │     继续执行下面的代码
                ▼                                 │
            ... （中间可以继续往下排任意多个 else if）│
                │                                 │
                ▼                                 │
            else ──全部不成立时的兜底──▶ else 语句体 ─┘
    ```

* **判断链上的条件可以推出来因而能删**

    * > **定义**：`else if` 判断链上的后一个分支天然继承了前面所有分支"不成立"的前提，凡是能被这个前提推出来的条件都可以放心删掉。

    * 内层的 `price > 0` 可以删：最外层 `price > 0` 不成立时直接走 `else`，代码能走进内层就意味着 `price` 必然大于零。

    * 后面各档的下限也可以删：`price` 为 5 时第一个条件 `price < 10` 就已成立并直接走掉，根本到不了第二个分支；能走到第二个分支就意味着 `price >= 10`，同理 `>= 50`、`>= 100` 均可删，对结果没有任何影响。

    ```java
    if (price > 0) {
        if (price < 10) {
            discountPrice = 0;
        } else if (price < 50) {
            discountPrice = 8;
        } else if (price < 100) {
            discountPrice = 30;
        } else if (price < 200) {
            discountPrice = 50;
        } else {
            discountPrice = 90;
        }
    }
    ```

    * > **注意**：代码没变短之前先别急着删，先讲清楚它为什么能删，这才是优化的依据。

### 判断链的简化与排列顺序

* **语句体只有一行时判断链可以压成一行**

    * 语句体只有一行时大括号可以省略，`else` 的大括号同样可以省，省完之后直接写在一行上，简洁性会有明显提升。

    * 格式化代码的快捷键是 `Ctrl + Alt + L`。

    ```java
    if (price > 0) {
        if (price < 10) discountPrice = 0;
        else if (price < 50) discountPrice = 8;
        else if (price < 100) discountPrice = 30;
        else if (price < 200) discountPrice = 50;
        else discountPrice = 90;
    }
    ```

* **范围重叠时小的写在上面**

    * > **定义**：多个判断的范围存在重叠时，必须把小范围写在上面、大范围写在下面。

    * 等边三角形一定也是等腰三角形，所以等腰的范围大于等边；判断顺序必须是先等边、再等腰。

    * ⚠️ **易错点**：把等腰剪到上面、等边放到下面后，录入 10、10、10 会打印"等腰"，下面的"等边"永远执行不到——上面的大范围把小范围里所有的条件全都拦截了。

    * 这条规则可以直接搬到坐标系位置判断上：原点是其余所有情况的子集，必须第一个判断。

## 区间分档类案例

### 判断嵌套型案例

* **优惠券与会员卡**

    * 题目设定：四张券——满 10 减 8、满 50 减 30、满 100 减 50、满 200 减 90，且同时只能用一张；另有一张全场八折的会员卡；会员卡与优惠券不能同时使用，问最优惠的价格。

    * 两种变量含义：常规写法让 `discountPrice` 记录"使用优惠券之后的价格"；另一种写法把它改成"使用优惠券之后可以少付的钱"，拿优惠券少付的钱与会员卡少付的钱对比。这种写法的好处是省掉了最后统一减一次总价的步骤。

    * 先写伪代码把结构搭好：最外层判断 `price > 0`，因为只有价格大于零时优惠才有意义，否则是价格有误；里层再嵌判断链。

    * > **易错点**：判断条件写的是区间，但用哪张券要看的是门槛。10 到 50 这一档用的不是满 50 减 30，而是满 10 减 8，因为那张券要超过 50 才能减 30。

    | price 区间 | 能用的券 | 可以少付的钱 |
    | :--- | :--- | :--- |
    | $0 < price < 10$ | 一张都用不上，最低门槛是满 10 减 8 | 0 |
    | $10 \le price < 50$ | 满 10 减 8 | 8 |
    | $50 \le price < 100$ | 满 50 减 30 | 30 |
    | $100 \le price < 200$ | 满 100 减 50 | 50 |
    | $price \ge 200$ | 满 200 减 90 | 90 |

    * 会员卡少付的钱是 `price * 0.2` 而不是 `price * 0.8`，因为全场八折只付 80%，省下的是那 20%。

    ```java
    double memberPrice = price * 0.2;

    if (discountPrice > memberPrice) {
        System.out.println("使用优惠券的价格会更低：" + (price - discountPrice));
    } else {
        System.out.println("使用会员卡的价格更低：" + (price - memberPrice));
    }
    ```

    * 判断条件用的是"大于"：一旦 `discountPrice > memberPrice`，说明会员卡省下的更多，所以优惠券方案的实际价格反而更低。

    * 总价 100 时用券更低，只付 50；总价 1000 时会员卡更低，只付 800。

    * > **注意**：打印文案写"优惠的价格是 discountPrice"容易产生歧义，改成"使用优惠券之后可以少付的钱"就没有歧义了。

* **判断三角形**

    * 题目要求：键盘录入任意三个大于零的小数，判断能构成等边三角形、等腰、直角三角形还是无效（不能构成三角形）。

    * 采取 `if` 嵌套：外层先判断是否构成三角形，不构成直接输出"无效三角形"；构成了再依次判断是哪种类型。

    * 录入用 `Scanner` 的 `nextDouble` 接收小数，再复制给 `a`、`b`、`c` 三个变量记录边长。

    ```text
                  if (a + b > c && a + c > b && b + c > a)     ← 三个条件必须同时成立
                  │
             ┌────┴────┐
           不成立       成立
             │           │
             ▼           ▼
      输出"无效三角形"   等边？ ──成立──▶ 等边三角形
                       否则等腰？──成立──▶ 等腰三角形
                       否则直角？──成立──▶ 直角三角形
                       否则      ──────▶ 普通三角形
    ```

    * ⚠️ **易错点**：现实经验可能与代码逻辑相反。边长 5、5、10 确实有一条边满足"两边之和大于第三边"，但它构不成三角形，所以三条件之间必须用"而且"（`&&`）而不是"或者"（`||`），必须同时成立。

    ```java
    if (a + b > c && a + c > b && b + c > a) {
        // 三个条件必须同时成立，才能构成三角形
    }
    ```

    * 分支顺序固定为等边 → 等腰 → 直角 → 普通，原因是等腰的范围覆盖等边，颠倒顺序会让小范围永不被检查。

### 分档计算型案例

* **阶梯电费**

    * 题目设定：用 100 度以内一度 0.5 元；超过 100 度后，100 到 200 之间一度 0.8 元；超过 200 度的部分一度 1.2 元。

    | 用电区间 | 单价 |
    | :--- | :--- |
    | $[0, 100)$ | 一度 0.5 元 |
    | $[100, 200)$ | 一度 0.8 元 |
    | $[200, +\infty)$ | 一度 1.2 元 |

    * ⚠️ **易错点**：超过 100 度并不是全部电量都按八毛计费，只有超出 100 的那部分按新单价，前面已经走过的档位仍按它自己的单价，不跟着涨价。

    * 金额等于前面各档的电量乘以各自单价之后求和。

    * 150 度：$100 \times 0.5 + 50 \times 0.8 = 75$ 元。

    * 300 度：$100 \times 0.5 + 100 \times 0.8 + 100 \times 1.2 = 250$ 元。

    * 结构上与优惠券那道题同源，都是"区间分档 + 每档一个不同的值"。

* **直角坐标系的位置判断**

    * 题目要求：输入 X 与 Y 两个变量表示点的位置，判断它属于原点、第一至第四象限，还是在 X 轴上、在 Y 轴上。

    * 这与前面范围重叠的问题是同一回事，练习时特别注意大小范围共存的情况。

    * 范围最小的是原点（`X` 等于零而且 `Y` 等于零），它是其余所有情况的子集，必须第一个判断。

    * X 轴与 Y 轴上的点是四个象限之外的零头，也要排在四个象限之前或按小范围优先的顺序排好。

    * 结论收口仍是那一条：范围重叠时，小的写在上面，大的写在下面。

    * 顺序为：先判原点，再判 X 轴（`Y` 为零）与 Y 轴（`X` 为零），最后按 `X`、`Y` 的正负组合判四个象限。

## switch 语句的语法与执行流程

* **选择语句（switch 语句）**

    * > **定义**：把所有选择一一列举出来，根据不同的条件任选其一去执行的语句；因格式中用到了 `switch` 关键字而得名。

    * 减肥计划是典型的使用场景：跑步、游泳、慢走、动感单车是选择，星期是条件——周一跑步、周二游泳，依次类推。

    * `switch` 与 `if` 的第三种格式形式上非常类似，区别后面单独说。

    ```java
    switch (表达式) {
        case 值1:
            语句体1;
            break;
        case 值2:
            语句体2;
            break;
        default:
            语句体n;
            break;
    }
    ```

    * 书写细节：`case` 与值之间加一个空格，值后面加一个冒号，下面写对应的语句体和 `break`；这样的 `case` 可以写多个，最后再加一个 `default`。

    * 这个格式不用死记，拿一个案例推导一遍自然就记住了；现在还有 AI 提示格式兜底，更不容易写错。

* **执行流程**

    * 先计算小括号中表达式的值。这里与 `if` 不同：表达式不是判断条件，而是会得到一个具体的结果，比如数字一、数字二、数字三。

    * 拿着这个结果依次跟 `case` 后面的值比较：找到相等的就执行该 `case` 里的语句体，遇到 `break` 就结束整个 `switch`；所有 `case` 都不匹配就执行 `default` 里的语句体，然后结束整个 `switch`。

    ```text
        ┌─ 计算小括号中表达式的值 ──▶ 得到一个具体的结果
        │
        ▼
        拿结果依次跟每个 case 后面的值比较
        │
        ├─ 找到相等的 ──▶ 执行该 case 里的语句体 ──▶ 遇到 break ──▶ 结束整个 switch
        │
        └─ 所有 case 都不匹配 ──▶ 执行 default 里的语句体 ──▶ 结束整个 switch
    ```

* **default 与 else 的对应关系**

    * `switch` 里的 `default` 与 `if` 里的 `else` 非常类似：前者兜住所有 `case` 都不匹配的情况，后者兜住条件为 `false` 的情况。

* **星期减肥计划案例**

    * 第一步先键盘录入星期，`switch` 不用管：`week` 用 `nextInt` 接收。

    * 第二步把所有情况一一罗列，每种情况一个独立的 `case`，共 7 种。

    ```java
    Scanner sc = new Scanner(System.in);
    System.out.println("请输入当前的星期");
    int week = sc.nextInt();

    switch (week) {
        case 1:
            System.out.println("跑步");
            break;
        case 2:
            System.out.println("游泳");
            break;
        case 3:
            System.out.println("慢走");
            break;
        case 4:
            System.out.println("动感单车");
            break;
        case 5:
            System.out.println("拳击");
            break;
        case 6:
            System.out.println("爬山");
            break;
        case 7:
            System.out.println("好好吃一顿");
            break;
        default:
            System.out.println("没有这个星期");
            break;
    }
    ```

    * 录入 11 与所有 `case` 都匹配不上，走 `default` 打印"没有这个星期"；录入 5 匹配 `case 5` 打印"拳击"，随后 `break` 结束整个 `switch`。

    * 搭骨架的效率做法：先写好 `case 1` 加冒号，用 `Ctrl + D` 向下复制成 2 到 7，再加一个 `default`；把 `case 1` 那一段 `Ctrl + C`、`Ctrl + V` 粘贴给其余 `case`，再逐个改执行逻辑。

    * > **提示**：第一次写 `switch` 时先不要用 AI 写，自己敲一遍，手感比什么都重要。

## switch 的取值与标签约束

### 表达式的结果与 case 的取值

* **表达式的结果类型**

    * > **定义**：小括号中表达式的结果表示将要匹配的值，最终结果只能是字符或整数。

    * 整数只允许 `byte`、`short`、`int` 三种类型，不能是 `long`，也不能是小数类型。

    * JDK5 以后可以是枚举，JDK7 以后结果可以是一个字符串。

    * 实验现象：把变量改成 `long` 并给 10 加 `L` 后缀，程序不用运行就直接报错；改成小数 `double` 同样直接报错，鼠标悬停会提示这种写法在 JDK 24 时不被允许。

    * 之所以这样设计，涉及跳转表的问题：跳转表的索引不支持小数，也不支持大的整数。

* **case 后面的值**

    * > **定义**：`case` 后面的值表示要跟表达式进行比较的值，也就是被匹配的值。

    * 这个值只能是编译期就能确定的常量表达式，不能写变量。定义 `int a = 1`、`int b = 2`、`int c = 3` 然后写 `case a` 之类会直接报错，鼠标悬停提示必须要写常量表达式。

    * `case` 后面的值不允许重复。强行写成两个 1，不用运行就会报错，鼠标悬停提示 `duplicate label`（标签重复）。

    * 不允许重复的理由很直接：假设表达式结果是 1，如果允许重复，程序就不知道该跟上面那个 1 匹配还是跟下面那个 1 匹配。

* **break**

    * > **定义**：Java 里的一个关键字，表示中断、结束；一旦执行到 `break`，整个 `switch` 语句就结束。

    * 学到循环时还会再遇到 `break`，那时它的作用同样表示结束。

### default 的位置与省略

* **default**

    * > **定义**：表示所有情况都不匹配时执行的兜底分支，与 `if` 里的 `else` 非常类似。

* **default 的位置任意**

    * `case` 刚才按从小到大一个挨一个书写纯粹是为了看着舒服，语法中根本没有这样的规则：把 4 写在最上面、把最小的写在下面完全合法，运行结果不变。

    * `default` 的位置同样随便写，写在最上面或写在中间都可以，表达式结果为 3 时照样打印星期三，改成 10 则走到 `default`。

    * > **注意**：位置自由是语法给的权力，书写顺序是给人看的规矩。面试手写代码和长期维护的代码还是老老实实 `case` 从小到大、`default` 垫底，别人扫一眼就知道写了什么。

* **default 可以整个省略**

    * `switch` 中的 `default` 可以不写，只是此时若所有 `case` 都不匹配，就没有任何输出结果。

    * > **易错点**：删掉 `default` 之后传进一个谁都不匹配的值，程序不报错、也什么都不输出。"没报错"和"处理了"完全是两码事。

## case 穿透

### 穿透的机理与走法

* **case 穿透**

    * > **定义**：书写时不小心漏掉 `break`，就会触发 case 穿透现象——程序匹配上某个 `case` 执行完语句体后，没见到 `break` 就继续往下执行下一个 `case` 的语句体。

    * 穿透会一直持续到遇见 `break` 或者整个 `switch` 全部执行完为止，`default` 后面的语句体也算在穿透路径之内。

    * 正常情况是匹配、执行语句体、遇 `break` 结束整个 `switch`；异常情况就是这条"匹配上就到此为止"的开关没关掉。

    ```text
           拿表达式的值去和每一个 case 标签比较
                        │
            ┌───────────┴───────────┐
            │                       │
       匹配上了                 一个都没匹配上
            │                       │
       执行 case 里的语句体          从 default 开始执行
            │
       看见 break ──→ 整个 switch 结束
            │
       没看见 break ──→ 继续往下穿，执行下一个 case 的语句体
            │
       （default 后面的语句体也算在内）
            │
       直到遇见 break，或者整个 switch 全部走完，才停
    ```

    * 穿透只认 `break`，不认 `case` 和 `default` 谁写在前面。

    * 把下面所有 `break` 删掉后，`week` 为 1 时会依次打印星期一、星期二、星期三和"没有这个星期"四行。

    | 场景 | 打印结果 |
    | :--- | :--- |
    | `week = 1`，删掉全部 `break` | 星期一、星期二、星期三、没有这个星期 |
    | `week = 3`，删掉全部 `break` | 星期三、没有这个星期 |
    | `default` 挪到中间，`number = 5`，删掉全部 `break` | 没有这个星期、星期二、星期三 |

    * 第三行的走法是：5 与所有 `case` 都匹配不上，从 `default` 开始打印"没有这个星期"，没有 `break` 就继续往下穿透，直到整个 `switch` 走完才停。

* **穿透是知识点而不是错误**

    * > **定义**：当多个 `case` 的语句体重复时，利用穿透可以省掉重复的代码。

    * 朴素写法要为 12 个月各写一个 `case`，1 和 2 重复、3 4 5 重复、6 7 8 重复、9 10 11 重复，代码非常冗长。

    * 穿透写法把语句体相同的 `case` 标签并成一组，只在真正要打印的那一个 `case` 后面保留 `break`。

    ```java
    switch (month) {
        case 1:
        case 2:
        case 12:
            System.out.println("冬季");
            break;
        case 3:
        case 4:
        case 5:
            System.out.println("春季");
            break;
        case 6:
        case 7:
        case 8:
            System.out.println("夏季");
            break;
        case 9:
        case 10:
        case 11:
            System.out.println("秋季");
            break;
        default:
            System.out.println("没有这个季节");
    }
    ```

    * > **注意**：`break` 只能留在有语句体的那一个 `case` 后面；前面光秃秃的 `case 1:` 下面什么都没有，它等着被穿过去，穿过去时什么也不打印，所以不需要 `break`。

    * 走法示例：录入 9，匹配上 `case 9` 后发现没有语句体也没有 `break`，继续往下穿到 10、11 都没有打印，直到有语句体才打印"秋季"，见到 `break` 结束整个 `switch`。

    | case 组 | 输出 |
    | :--- | :--- |
    | 1、2、12 | 冬季 |
    | 3、4、5 | 春季 |
    | 6、7、8 | 夏季 |
    | 9、10、11 | 秋季 |
    | 其余 | `default` 提示"没有这个季节" |

## switch 的新写法

### 版本前提与箭头标签

* **版本前提**

    * > **定义**：`switch` 的新特性在 JDK12 推出的是预览版，JDK14 才是正式版，预览版可以理解成临时版本。

    * 运行这些特性最好保证 JDK 是 14 或 14 以上，JDK12 有点不太保险。

* **箭头标签**

    * 完整格式是把 `case` 后面的冒号去掉，值后面写一个箭头，语句体放进大括号里；这种写法不用写 `break`，并且不会有 `case` 穿透的现象。

    ```java
    int week = 3;
    switch (week) {
        case 1 -> {
            System.out.println("星期一");
        }
        case 2 -> {
            System.out.println("星期二");
        }
        case 3 -> {
            System.out.println("星期三");
        }
        default -> {
            System.out.println("没有这个星期");
        }
    }
    ```

    * 箭头由一个小横杠加一个英文状态下的大于号组成，两者中间不能加空格，加了空格就错了，必须紧挨在一起。

    * `week` 为 5 时不匹配任何 `case`，执行 `default`；改成 3 则匹配 `case 3` 只打印星期三，不会穿透去执行 `default`。

    * 语句体只有一行时大括号可以省略，代码会非常简洁。

    ```java
    switch (week) {
        case 1 -> System.out.println("星期一");
        case 2 -> System.out.println("星期二");
        case 3 -> System.out.println("星期三");
        default -> System.out.println("没有这个星期");
    }
    ```

### 多值 case 与表达式

* **一个 case 写多个值**

    * 箭头写法不触发穿透，多个 `case` 语句体重复时就只能把整套东西重写一遍，于是有了多值写法：把多个值写在一起，值与值之间用逗号隔开。

    ```java
    switch (week) {
        case 1, 2 -> System.out.println("一");
        case 3, 4, 5 -> System.out.println("三");
        case 6, 7, 8 -> System.out.println("二");
        case 9, 10, 11 -> System.out.println("三");
        default -> System.out.println("没有这个星期");
    }
    ```

    * 值本身仍然不允许重复。

* **switch 表达式与 yield**

    * > **定义**：普通 `switch` 只是往控制台打印，如果在它下面还要继续使用运行结果就没有办法操作；这时要把 `switch` 写成表达式——前面用变量接收，大括号内用 `yield` 带出结果，末尾补分号。

    ```java
    int week = 3;
    String name = switch (week) {
        case 1 -> {
            yield "一";
        }
        case 2 -> {
            yield "二";
        }
        case 3 -> {
            yield "三";
        }
        default -> {
            yield "没有这个星期";
        }
    };
    System.out.println(name);
    ```

    * 每个 `case` 与 `default` 都要按这个格式改写；写完后仍会报错，是因为还没在 `switch` 前面拿变量接收、也没在末尾补分号。

    * 语句体只有一行时，大括号可以省略、`yield` 也可以省略，结果直接写在后面。

    ```java
    int week = 3;
    String name = switch (week) {
        case 1 -> "一";
        case 2 -> "二";
        case 3 -> "三";
        default -> "没有这个星期";
    };
    System.out.println(name);
    ```

    * ⚠️ **易错点**：switch 表达式末尾那个分号不能少。普通 `switch` 语句的大括号后面不需要分号，写成表达式之后末尾必须补分号，少了就会出错。

* **用 switch 模拟计算器**

    * 定义 `int a = 10`、`int b = 20`，再定义 `char operator` 表示运算符，比如取 `'*'` 表示拿 a 去乘以 b。

    * 因为要继续使用 `switch` 的运行结果，必须写成表达式形式。

    ```java
    int a = 10;
    int b = 20;
    char operator = '*';

    int result = switch (operator) {
        case '+' -> a + b;
        case '-' -> a - b;
        case '*' -> a * b;
        case '/' -> a / b;
        default -> 0;
    };

    System.out.println(result);
    ```

    * 完整格式下加法分支要先 `int sum = a + b;` 再 `yield sum;`；简化时 `sum` 不用定义，在 `yield` 后面直接写 `a + b`，于是语句体只剩一行，大括号与 `yield` 一起省略。

    * > **注意**：必须补上 `default`，否则 `operator` 会报报错；不是四则运算时直接返回 0。

    * `operator` 为 `'*'` 时，10 乘 20 得 200，赋给 `result` 后可以继续使用。

## if 与 switch 的选型

### 选型依据

* **选型结论**

    * > **定义**：`if` 判断语句更适合对一个范围进行判断，`switch` 选择语句更适用于 `case` 的值是有限个的时候。

    | 你要判断的东西 | 该用谁 | 理由 |
    | :--- | :--- | :--- |
    | 一个范围，比如 1~100 | `if` | `switch` 得写一百个 `case` |
    | 有限个选项，比如月份、季节、星期 | `switch` | 读起来一眼看到结果，运行效率也更高 |

    * 判断一个范围时强行用 `switch`，得写一百个 `case`，既麻烦又写不完。

### 两种写法的对照

* **同一需求两种写法的对照**

    * 月份对应季节这个需求，左边用 `switch`、右边用 `if` 的第三种格式，功能完全相同。

    * `month` 取 11 时，左边一眼就能看到 11 走的是秋季；右边得一个判断一个判断地看，相对更麻烦一些。

    ```java
    // 左边：switch
    int month = 11;
    switch (month) {
        case 1:
        case 2:
        case 12:
            System.out.println("冬季");
            break;
        case 3:
        case 4:
        case 5:
            System.out.println("春季");
            break;
        case 6:
        case 7:
        case 8:
            System.out.println("夏季");
            break;
        case 9:
        case 10:
        case 11:
            System.out.println("秋季");
            break;
        default:
            System.out.println("没有这个季节");
    }

    // 右边：if 的第三种格式
    int month = 11;
    if (month == 1 || month == 2 || month == 12) {
        System.out.println("冬季");
    } else if (month >= 3 && month <= 5) {
        System.out.println("春季");
    } else if (month >= 6 && month <= 8) {
        System.out.println("夏季");
    } else if (month >= 9 && month <= 11) {
        System.out.println("秋季");
    } else {
        System.out.println("没有这个季节");
    }
    ```

* **运行效率的差异**

    * `switch` 拿着表达式的结果跟所有 `case` 匹配，一下子就能定位到结果；`if` 的第三种格式需要从上往下一个一个地找，效率相对偏低。

    * `case` 选项是有限个的时候优先使用 `switch`，理由就是可读性与效率这两条。

* **多少个算有限个**

    * 业内没有固定标准，只要不太多、不影响代码的阅读，基本都是可以的。

* **if 三种格式的适用面**

    | 格式 | 适用于 |
    | :--- | :--- |
    | `if` | 单个条件的判断 |
    | `if...else` | 两个条件的判断 |
    | `if...else if...else` | 多个条件的判断 |

    * 三种格式的区别只在于能判断的条件个数。

## 分支结构的可复述要点

* **if 要记的**

    * 作用只有一个：程序当中用来判断，以后想判断就直接用 `if`。

    * 三种格式：`if`、`if...else`、`if...else if...else`，分别对应单个条件、两个条件、多个条件的判断。

    * 完整执行流程：先执行关系表达式，为 `true` 就执行大括号里的语句体，为 `false` 就不执行，然后继续往下。

    * 四个细节：左大括号写在上一行末尾；语句体只有一行时大括号可省略；小括号后面不能加分号；判断布尔变量时把变量直接写在小括号里。

* **switch 要记的**

    * 作用一句话：把所有选项一一列举出来，根据不同的情况任选其一。

    * 格式与流程：`switch` 小括号大括号，小括号里写一个表达式，大括号里写多个 `case` 加一个 `default`；先算出表达式的值，再拿它跟所有 `case` 匹配，匹配上就执行语句体，全都匹配不上就执行 `default`。

    * 语法细节：表达式结果只能是字符或整数，整数限于 `byte`、`short`、`int`，不能是 `long` 也不能是小数，JDK5 以后可以是枚举，JDK7 以后可以是字符串；`case` 后面只能跟常量表达式，不能跟变量，值也不允许重复；`break` 表示中断结束，用来结束整个 `switch`；`default` 与 `else` 类似，负责所有 `case` 都不匹配的情况。

    * 其他知识点：`case` 与 `default` 没有上下顺序之分，为方便阅读一般 `case` 从小到大、`default` 垫底，`default` 也可以整个省略；漏写 `break` 会引发 case 穿透，这不是错误而是知识点，多个 `case` 语句体重复时正好可以用它减少代码书写；新特性从 JDK12 开始测试、JDK14 正式发布，使用时最好保证 JDK14 及以上。

* **选型收口**

    * 判断一个范围用 `if`；`case` 的个数是有限个的时候优先用 `switch`，可读性与运行效率都更高。

## 其他可复用的算法与分档题

* **卡拉兹函数**

    * 给定正整数 $N$，$N$ 为奇数执行 $3N+1$，$N$ 为偶数执行 $N \div 2$，最终的结果称作"牛妹数"。

    * 这一题是 `if...else` 的直接应用：一个关系表达式同时管两种情况，奇数走语句体 A，偶数走语句体 B，二选一执行，绝不会都执行。

    * 判断奇偶对 2 求余即可。

    * 自测：输入 $1$，$1$ 是奇数，执行 $3 \times 1 + 1 = 4$，牛妹数为 $4$；输入 $2$，$2$ 是偶数，$2 \div 2 = 1$，牛妹数为 $1$。

* **充卡赠送**

    * 充值 1000 赠送 200，充值 2000 赠送 500，充值 3000 赠送 700，以此类推，次卡规则忽略。

    * 充值额度与赠送金额本身就是一档一档往上排的，正面是充值、后面是赠送，是典型的 `else if` 区间分档。

    * 充值额和赠送额同时变化的档位用一条 `else if` 链串起来即可。

    * 余额：充值 1000 到账 1200；充值 2000 到账 2500；充值 3000 到账 3700。

    * > **注意**：判断用的是"大于等于某个门槛"，落在档位边界上时归属哪一档要先跟题目确认清楚，不能自己拍。

* **计算 BMI 并判断体型**

    * 在原本计算 BMI 的基础上，针对不同情况输出偏瘦、正常、偏胖或其他。

    * 这是 `else if` 判断链最典型的用武之地，把体型按 BMI 从小到大排成一串档位即可。

    * "其他"这个兜底分支要放在最后，它就是这条链上的 `else`。

    * > **注意**：分档阈值的长文未说明，不要凭印象写，自己去资料里核对。
