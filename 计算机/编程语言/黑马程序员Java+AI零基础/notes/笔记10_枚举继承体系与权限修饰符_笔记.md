# 枚举、继承体系与权限修饰符

## 枚举项的编译期机制

* **枚举项即对象**

    * > **定义**：枚举类里的每一个枚举项，都是该枚举类的一个对象实例。

    * 对象一律由构造方法创建出来：只要访问到这个枚举类的任意一个枚举项，底层已经把该类全部枚举项对应的对象一次性创建完毕。

    * 验证办法是在构造方法第一行加一句打印，随后访问任意一项——输出里会依次出现全部枚举项的构造痕迹，最后才是本次取到的那一项。

    * 有参构造与无参构造都成立：枚举项写成 `处理中(name)` 走有参构造，改成 `处理中()` 走无参构造，都能正常编译；实际开发中把描述放进字段、用有参构造更常见。

* **枚举项在底层是常量**

    * 每个枚举项底层默认带 `public static final` 三个修饰符，源码里一个不写，编译器也会替源码补上。

    * `public` 权限最大，任意地方都能访问这个枚举项；`static` 表示静态，可以用类名点的方式调用；`final` 表示不可变。

    * 验证方式是用 JDK 自带的 `javap` 反汇编 class 文件，输出里每一个枚举项前都规规矩矩挂着 `public static final`，另外还能看到 `values()` 与 `valueOf(String)` 的签名。

    * > **结论**：写代码时不要手动加这三个关键字，加了属于冗余；它们才是枚举项在字节码里的真实样子。

    * > **易错点**：`javap` 严格说是反汇编，把 class 文件里的字节码摊成可读结构，而不是还原成一份能直接编译的 `.java` 源文件；要看清修饰符和方法签名，它足够用了。

* **枚举类的结构约定**

    * 第一行必须全是枚举项，枚举项之间用逗号隔开，整行以分号结尾。

    * 把 `private String name;` 这类成员写到第一行，程序会直接报错。

    * 枚举项太长可以折行，因为程序认定分号才是这一段的结束；只要末尾能补上分号，折不折行都认。

    * 构造方法必须是 `private`，目的是让外界无法创建本类的对象；不写 `private` 编译器也会补上，IDEA 会把这个关键字显示成灰色并提示省略不写也不报错。

    * 在外部执行 `new OrderState()` 会编译报错，提示枚举类不能创建它的对象；所有对象只能由编译器在类加载时创建，外部毫无插手机会，这就是枚举"单例且不可乱造"的根本原因。

* **编译器赠送的两个方法**

    * `values()`：默认 `static` 修饰，用类名调用，返回本类全部枚举项组成的数组。

    * `valueOf(String)`：默认 `static` 修饰，传入枚举项名字，返回指定的那一个枚举项。

    * 这两个方法源码里一次都没写，但照常可用；遍历时只看向下那几行输出就能确认，六个枚举项全在数组里。

    * > **易错点**：`valueOf` 传的是 `enum` 第一行写的枚举项名字，不是构造方法括号里存的描述字符串；大小写、多一个字少一个字都不行，不匹配时抛 `java.lang.IllegalArgumentException: No enum constant ...`。

## 继承的定义与判定

* **继承（Inheritance）**

    * > **定义**：类与类之间的一种父子关系，父类有的内容子类也有，从而省掉大量重复代码。

    * 面向对象的三大特征是封装、继承、多态；封装是把零散的数据和行为变成一个整体，写 JavaBean 就是封装——成员变量一律 `private` 并配 `get`/`set` 防止非法赋值，再写构造方法以便创建对象时一次性把已知数据给足。

    * 重复的成员变量 `name`、`age` 和成员方法 `eat()` 从 `Student`、`Teacher` 抽到 `Person` 后，两个子类只写自己独有的部分。

    * Java 用关键字 `extends` 建立父子关系：`public class Student extends Person {}`，前面的类叫子类（派生类），后面的类叫父类（基类、超类）；叫法不统一源于不同译者的理解，日常更多用子类、父类。

    * 好处有两个：把多个子类中重复的代码抽取到父类，子类不必重写一遍，提高复用性；子类在父类基础上增加新功能，让子类更强大。

* **使用继承的两个条件**

    * > **结论**：类之间存在相同内容，并且子类是父类中的一种——两个条件必须同时成立才能用继承优化代码，缺一不可。

    * 父类名字要有代表性，不能随便乱起：`Student` 与 `Teacher` 抽成 `Person` 可以，父类叫 `AAA` 就不合理，因为学生是 `AAA` 的一种、老师是 `AAA` 的一种都说不过去。

    * `Manager` 与 `Coder` 抽成 `Employee` 可以，父类叫 `animal` 不行——项目经理和程序员都是员工的一种，咱是人不是牛马。

    * > **易错点**：父类里的内容只代表子类的共性。把"管理奖金"放进父类，就等于宣称项目经理有管理奖金、程序员也有管理奖金；管理奖金是项目经理独有的，必须留在子类里。

    * `Coder` 与 `Phone` 虽然都有 id 和名字，抽成"商品类" `Goods` 语法上能通过、程序不报错，但不符合实际情况——手机是商品的一种说得通，程序员不是商品。此时不该硬凑继承结构，两个类各自独立写就行。

    * > **结论**：实际开发中会有很多条不同的继承结构，不要想着把所有类都塞进同一个继承结构里。

* **画图法设计继承体系**

    * 规则一：从下往上画。先画子类，再把共性往上抽成父类。

    * 规则二：先分类。把相同的子类归为一类，不同的放到外面去。

    * 三个设备的设计过程：`Android` 与 `IOS` 都是手机，归为一类抽成父类 `Phone`（`call()`、`sendMessage()`），`Android` 独有 `nfc()`，`IOS` 是空类；`Phone` 与 `Laptop` 又都是智能设备，再往上一级抽成 `SmartDevice`（`brand`、`price`，没有共有行为），`Laptop` 独有 `coding()`。

    * 把三个设备平铺挂在 `SmartDevice` 下面语法没问题，但 `call()`、`sendMessage()` 在 `Phone` 和 `SmartDevice` 之间重复了一遍，不如分层方案干净。

    * 顺序口诀：画图从下往上，写代码从上往下——先写父类再写子类，否则子类无从继承一个还不存在的类。

    * > **易错点**：`Android`、`IOS` 继承的是 `Phone`，`Laptop` 继承的是 `SmartDevice`；`IOS` 对象调不了 `nfc()`，因为 NFC 是安卓独有的功能，兄弟子类之间是隔离的。

## 继承的特点

* **单继承与多层继承**

    * > **结论**：Java 只支持单继承，不支持多继承，但可以多层继承。

    * 单继承指一个子类只能继承一个父类；不支持多继承指一个子类不能同时继承多个父类。

    * 砍掉多继承的原因：C++ 允许多继承，若父类 A 让子类 `eat()` 吃饭、父类 B 让同一个子类 `eat()` 吃面条，那么创建子类对象调用 `eat()` 时，到底执行哪一个无从判定，Java 为避开这种歧义取消了多继承。

    * 多层继承指子类 A 继承父类 B，父类 B 又继承它自己的父类 C，像现实里的祖孙三代。

    * 直接继承的那个父类叫直接父类，再往上一层的爷爷、太爷爷统称间接父类；Java 里没有"爷爷"这一层概念，否则还得有曾祖父、高祖父、烈祖父一串。

    * 旁支类之间没有任何继承关系：儿子与叔叔即便长得再像，代码里也毫无关系，不能互相使用对方的内容。

* **顶级父类 Object**

    * `Object` 是 Java 已经写好的顶级父类，是所有类的祖宗，每一个类都直接或间接继承于它。

    * 源码里压根没写 `extends` 的类，不是没有爸爸——虚拟机运行时会自动给它加上继承 `Object` 的默认关系；如果这个类本来就有父类，虚拟机不插手。

    * 正因如此，自己没定义过的 `equals()`、`hashCode()` 也能直接调用，它们就是从 `Object` 继承下来的。

    * > **结论**：继承体系顶层的那些类默认继承 `Object`，下面所有的类都是间接继承 `Object`；对任意一个子类而言，它能用直接父类和全部间接父类的内容，但用不了旁支类里的内容。

## 成员变量与就近原则

* **书写规则**

    * > **结论**：把多个子类中相同的属性抽取到父类——"抽取共性"四个字就是全部规则。

    * `Student` 和 `Teacher` 里都有 `name` 和 `age`，既然是共性就该往上抽到 `Person`；抽取完毕后，调用时自动遵守就近原则。

* **就近原则的完整版**

    * > **定义**：谁离我近我就用谁——先在方法内的局部位置找，再在本类成员位置找，再到父类成员位置找，一级一级往上，整个继承体系都没有才报错。

    * 本类没有同名成员时不会立即报错，而是继续往父类找；只有整条继承链上都没有对应的成员变量，这一时刻才报错。

        ```text
          方法里直接写 name
                  |
                  v
          1 方法内的局部位置找 name  有 -> 用它，结束
                  | 没有
                  v
          2 本类的成员位置找 name    有 -> 用它，结束
                  | 没有
                  v
          3 父类的成员位置找 name    有 -> 用它，结束
                  | 没有
                  v
          4 爷爷的成员位置找 name    有 -> 用它，结束
                  | 没有
                  v
          整个继承体系都没有 -> 报错
        ```

    * 父类 `Fu` 有 `name = "父"`，子类 `Zi` 没有自己的 `name` 只有 `show()`，此时直接打印 `name`，运行结果是 `父`。

* **重名时用 this 与 super 点名**

    * `this` 在内存角度表示当前方法调用者的内存地址——谁调用当前方法，`this` 就是它的地址值；在代码角度用于区分局部变量与成员变量，可访问本类的成员变量、成员方法、构造方法。

    * `super` 表示取父类中的内容，可访问父类的成员变量、成员方法、构造方法。

        | 写法 | 从哪儿开始找 | 依次会经过 |
        | :--- | :--- | :--- |
        | `name` | 方法里的局部位置 | 本类成员 → 父类成员 → 爷爷… |
        | `this.name` | 本类的成员位置 | 父类成员 → 爷爷… |
        | `super.name` | 父类的成员位置 | 爷爷… |

    * 父类 `name = "父"`、`address = "南京"`，子类只有 `name = "子"`：要输出"子"有两种写法（`name`、`this.name`）；要输出"父"只有一种写法（`super.name`），因为重名时直接写 `name` 只能拿到子类的那个；`address` 只存在于父类，三种写法（`address`、`this.address`、`super.address`）都能输出"南京"，因为本类根本没这个变量，往上一找就在父类找到了。

    * > **易错点**：不存在 `super.super.name` 这种套娃写法，程序不用运行就直接报错；子类里向上取同名成员变量最多只能访问到父类，爷爷类无法直接访问，`super` 只跨一层。

    * > **提示**：为了省去多文件之间双击切换的麻烦，几个类可以写在同一个文件里；真正的企业级开发仍是一个文件写一个类。

## 成员方法与方法重写

* **成员方法的抽取与调用**

    * 书写规则与成员变量一样：把多个子类中相同的行为抽取到父类，子类里原样删掉即可。

    * 调用的第一种情况是外界创建子类对象再调方法：先到子类找，子类有就用子类的，子类没有再到父类找。

    * 第二种情况是在本类当中调用其他方法：直接写 `eat()`、`drink()`，这与写 `this.eat()`、`this.drink()` 完全等价；也可以写 `super.eat()`、`super.drink()`，这种写法跳过子类，直接到父类里找。

* **方法的重写（Override）**

    * > **定义**：在继承中，子类出现了和父类一模一样的方法声明——修饰符、方法名、参数列表三者完全一致——称子类的这个方法重写了父类的方法。

    * 触发时机只有一个：父类的方法已经不能满足子类的需求。

    * 三代手机的链式继承：第一代只有 `call()`；第二代继承第一代，只新增 `sendMessage()`；第三代继承第二代，把 `call()` 重写成视频通话，再新增 `playGame()`。

        ```java
        public class ThirdGenerationPhone extends SecondGenerationPhone {
            @Override
            public void call() {
                System.out.println("开启视频");
                System.out.println("利用手机进行打电话");
            }

            public void playGame() {
                System.out.println("利用手机玩游戏");
            }
        }
        ```

    * 第三代的 `sendMessage()` 没有任何改动，就不要重写——它在第三代里能调到靠的是继承，不是重写。

    * 写重写不必 `Ctrl+C`、`Ctrl+V` 复制粘贴方法体，IDEA 里按 `Alt+Insert` 选 Override Methods，勾选要重写的方法名回车即可自动生成。

* **Override 注解**

    * 注释是给程序员看的文字性解释，注解是给虚拟机看的；`@Override` 只是一个小标记，告诉虚拟机下面这个方法是重写父类的。

    * 有了这个标记，方法名写错成 `call2`、或者参数列表多写一个形参，程序都不用运行就直接报红色波浪线。

    * > **结论**：`@Override` 的作用是让虚拟机替你检查重写语法有没有写对，写对没问题，写错立刻报错。

* **重写的注意事项**

    * 方法名与参数列表必须与父类完全一致，不一致代码直接报错；父类无参而子类多一个形参、父类有参而子类少写或多写，都会报错。

    * 方法体按实际需求书写：子类要干什么就写什么，需要用到父类逻辑时仍可通过 `super` 调用。

    * `final` 修饰的类是最终类，里面所有方法都不能被重写，而且这个类本身不能被继承。

    * `final` 修饰的方法是最终方法，不能被子类重写；`final` 写在 `public` 前面或后面都可以，一般写在 `public` 后面。

    * `private` 修饰的方法、`static` 修饰的方法都不能被重写：父类的私有方法相当于爸爸的小秘密，儿子不能知道也不能去干；静态方法同样不在子类的继承范围内。

    * 复用父类逻辑有两种处理：父类代码一行都不想用，就把子类方法体完整重写一遍；想在父类结果之上再加业务逻辑，就先用 `super.方法()` 拿到父类结果再二次操作。

        ```java
        public class Phone extends SmartDevice {
            @Override
            public double payments() {
                return super.payments() * 0.9;
            }
        }
        ```

    * 折扣区间：`0 ≤ price < 1000` 不打折；`1000 < price < 5000` 九折；`5000 ≤ price < 10000` 八折；`price ≥ 10000` 七折；`price` 小于 0 返回 `0`。

    * 三个子类都继承 `SmartDevice`，只有 `Phone` 重写 `payments()` 实现折上折（$0.9 \times 0.9 = 0.81$），`Laptop`、`Pad` 没有额外补贴，保持空类即可。

    * 手机赋值 `4999` 最终应付约 `4049.19`，笔记本赋值 `10000` 应付 `7000.0`；小数后面那一长串后缀是浮点数精度问题，保留两位小数的做法留到 `BigDecimal` 详细讲。

## 构造方法与 this、super

* **父类构造方法不能被继承**

    * > **结论**：父类中的构造方法不会被子类继承，只能通过 `super` 关键字调用。

    * 原因不是 Java 禁止继承，而是名字根本对不上：构造方法名必须与类名完全一致，`Person` 的构造方法到了子类里也不可能改名叫 `Student()`，改名就违背了构造方法的命名规则。

* **用 super 调用父类构造方法**

        | 写法 | 小括号里 | 调用的是父类的 |
        | :--- | :--- | :--- |
        | `super()` | 空的 | 无参构造 |
        | `super("张三", 23)` | 有实参 | 带参构造 |

    * 作用同样是在创建对象时给成员变量赋值。

    * > **结论**：属性在哪个类里面就要在哪个类里面赋值；抽到父类的 `name`、`age` 不应该由子类的构造体去赋值，而应通过 `super` 的小括号把实参交给父类的带参构造。

    * 子类带参构造的"全部参数"指的是父类加子类的字段全集：`Student(String name, int age, String grade)` 里前两个交给 `super(name, age)`，`grade` 自己 `this.grade = grade`；`Teacher` 同理也是三个参数而不是只写 `subject`。

    * > **结论**：父类的属性交给父类赋值，子类独有的属性我们自己赋值。

    * > **提示**：IDEA 里 `Alt+Insert` 选 Constructor 生成子类构造时会连弹两个框——先在 `Choose super class constructor` 里勾选父类构造，再勾选本类字段（诸如 `subject`）；生成的带参构造依然是父类加子类的全集，只需把空参构造里的参数删掉。

* **创建对象时的执行顺序**

    * > **结论**：创建对象时先执行父类的构造方法，再执行子类的构造方法。

    * 子类构造体第一行的 `super(...)` 先跑，把父类字段填好；回到子类之后才执行 `this.字段 = 字段` 和后面的语句。

        ```text
        new Student("张三", 23, "一年级")
                |
                v
          进入 Student 的带参构造
          第一行 super("张三", 23)
                |
                v
          Person 的带参构造执行
          this.name = "张三"
          this.age  = 23
          打印：父类的带参构造执行了
                |
                v
          回到 Student 的下一行
          this.grade = "一年级"
          打印：子类student的带参构造执行了
        ```

    * 子类构造方法第一行有一个默认的 `super()`，默认去访问父类的无参构造；不写的话虚拟机会自动加上。

    * > **易错点**：想访问父类的带参构造，`super` 小括号里的实参必须手动写上、不能省；把这行注释掉再运行，执行的是父类的空参构造。

    * 老版本 JDK 中 `super()` 必须写在构造方法第一行；最新 JDK 版本允许把它写到下面，甚至可以先执行子类再执行父类，但这种写法与既有书写习惯出入太大，一般仍把 `super()` 严格放在第一行。

* **this() 调用本类的其他构造**

    * `this(...)` 表示调用本类的其他构造方法，用它可以让对象天生带默认值。

    * 场景：学校里不认识某个同学，一般称呼对方"同学"，于是学生的默认名字定为"同学"、默认年龄定为 18；直接用无参构造创建对象，得到的是 `null` 和 `0`。

    * 写法一：在成员变量的声明处直接给默认值，外层带参构造照常 `this.name = name` 赋值，手动传入的值会覆盖默认值。

    * 写法二：成员位置不写默认值，在空参构造里写 `this("同学", 18);` 把默认值转交给带参构造去赋值。

        ```java
        public class Student {
            String name;
            int age;

            public Student() {
                this("同学", 18);
            }

            public Student(String name, int age) {
                this.name = name;
                this.age = age;
            }
        }
        ```

        | | 写法一：成员位置给默认值 | 写法二：空参构造里 `this(...)` |
        | :--- | :--- | :--- |
        | 默认值写在哪 | 成员变量的声明处 | 空参构造的第一行 |
        | 手动赋值能否覆盖默认值 | 能 | 能 |
        | 多个构造时要注意 | 无影响 | 不能互相调用，必须留一个去调父类 |

    * > **易错点**：一个类里有多个构造方法时，不能用 `this()` 互相调用——你钓我、我钓你没有尽头；一定要预留一个去调用父类的构造方法，否则父类里的共性属性永远赋不上值。

    * > **易错点**：构造方法里写了 `this()` 就不能再写 `super()`，而且虚拟机也不会自动补上 `super()`；这两个只能存在一个，有 `this` 没 `super`，有 `super` 没 `this`。

    * 老版本中 `this()` 只能写在构造方法第一行，新版本去掉了这一限制，但这种写法基本没人用，仍统一写在第一行。

## 继承的底层账本

* **能调用不等于能继承**

    * > **结论**：子类能调用的，不等于子类继承下来了；父类有的子类才有才叫继承，子类拿父类的东西来用只是调用。

    * 拿"钱"比喻继承其实站不住脚：用爸爸的钱，不等于把爸爸的钱复制了一份放进了子类。合适的案例是武学世家——爸爸会武功，儿子是真把武功继承下来了，爸爸那儿有一份，儿子也有一份。

    * 父类里的成员变量可以被子类继承，哪怕用 `private` 私有修饰的也能被继承；只是私有的成员变量没法直接调用，想用得走 `getXxx`、`setXxx`——相当于从父类继承了一个带锁的保险柜，能搬回家但打不开，钥匙就是 get 和 set 方法。

    * 成员方法分四种情况：虚方法能继承能调用；`final` 修饰的最终方法不能被继承但可以被调用；`static` 修饰的静态方法不能被继承但可以被调用；`private` 修饰的私有方法既不能被继承也不能被子类调用。

* **对象在内存里被一分为二**

    * 类加载顺序：加载子类时会发现它有父类，于是先加载父类再加载子类；完整顺序是 `Object` → 父类 → 子类。

    * 对象的内存结构自上而下是对象头（哈希信息、锁信息）、类型指针（指向该类字节码文件的内存地址）、成员变量区。

    * 成员变量区一分为二：左边记从父类继承下来的属性，右边记子类独有的属性，默认初始化为引用类型给 `null`、基本类型给 `0`。

    * 赋值规则是先看子类、再看父类：先在子类里找同名成员，找到就赋值给子类的那个，父类里的不再管；子类没有才给父类继承下来的那个赋值。

        ```java
        class Fu {
            String name;
        }

        class Zi extends Fu {
            String name;                       // 子类又自己声明了一个同名的 name

            public void show() {
                System.out.println(name);      // AAA
                System.out.println(super.name); // null
            }
        }
        ```

    * 上例中 `zi.name = "AAA"` 落到的是子类那个 `name`，父类的 `name` 压根没被碰过，保持默认初始化的 `null`；反过来若子类不声明同名 `name`，这次赋值就落到父类上，父子两个 `name` 拿到的都是 `"AAA"`。

    * > **结论**：成员变量在子类里同名，就是一次遮蔽（也叫隐藏）；这与重写是两回事，而且父类的属性在子类里是真真正正继承下来的，不是简单调用。

    * > **提示**：验证手段是 JDK 自带的内存分析工具。先把测试代码末尾加一段键盘录入，否则程序瞬间跑完、工具什么都看不到；运行后拿到对象的真实内存地址，`jps` 取当前所有运行进程的 id 并记下 `Test` 那个，`jhsdb` 打开 HSDB，`File` → `Attach` 连上该进程 id；`Tools` → `Memory Viewer` 里把对象地址前面补上 `0X`（内存地址是 16 进制）再粘贴，即可看堆里对象的结构；`Tools` → `Inspector` 粘贴字节码文件地址，即可看方法区里的类信息。

    * 字节码信息里 `non static field size` 数出 `4`（父类两个非静态加子类两个），`static field size` 只有 `1`（子类独有的静态变量），因为静态变量在静态区、不随对象走，在对象结构里看不到。

* **虚方法与虚方法表**

    * > **定义**：虚方法就是普通的成员方法，即非 `final`、非 `static`、非 `private` 修饰的方法；判断一个方法是不是虚方法，就看前面有没有那三个修饰符，一个都没有才是。

    * `Object` 里的虚方法一共 5 个：`clone()`、`equals()`、`finalize()`、`hashCode()`、`toString()`；`getClass()`、`notify()`、`notifyAll()` 以及三个重载的 `wait()` 前面都有 `final`，属最终方法，不算虚方法。

    * 虚方法表的传递方式：顶级父类把自己类里所有虚方法的内存地址汇总成一张表传给子类，子类在这张表的基础上再添加自己的虚方法。

        ```text
        +------------------+----------------------------------+
        | Object           | 虚方法 5 个                      |
        +------------------+----------------------------------+
        | Fu（父类）       | 虚方法 6 个（5 + 父秀一）        |
        +------------------+----------------------------------+
        | Zi（子类）       | 虚方法 7 个（6 + 子秀一）        |
        +------------------+----------------------------------+
        ```

    * 调用虚方法时到虚方法表里找对应的内存地址，再把该方法加载到栈里运行。

    * > **结论**：方法重写的本质是替换虚方法表里那个槽位的内存地址；签名相同，重写只把地址换掉，表的长度一动不动。

    * 父类有 `public fuShow1()` 与 `private fuShow2()`、子类有 `public ziShow1()` 时，父类虚方法表 6 个、子类 7 个：子类对象调 `ziShow1`、`fuShow1` 都到子类的虚方法表里找得到。

    * `private` 方法不是虚方法、不在父类的虚方法表里，但在父类中真实存在，查到之后因为权限受限调用失败。

    * > **易错点**：真实的 Java 里调用父类私有方法这行在编译期就直接报错，根本轮不到运行时；按虚方法表的思路推演只是为了讲透"表里没有它、只能往上找、找到了权限又不够"这三层原因。

    * HSDB 里 `v_table_length` 显示子类为 `7`、父类为 `6`、`Object` 为 `5`，逐层 `super_class` 展开就能对上；`Object` 的 `super_class` 值是 `null`，从内存分析工具的角度再次印证 `Object` 是顶级父类。

* **final 与 static 的查找发生在编译期**

    * `final` 修饰的最终方法不能被子类继承，但可以被子类调用；`static` 修饰的静态方法同样不能被继承，但可以被子类调用。

    * 两者的定位都发生在编译期：编译器一级一级遍历整个继承链（子找父、父找爷爷），确定最终要调用的方法在哪个类里，并把这个方法的内存地址记录下来。

    * 用对象调用静态方法时，编译期会把"对象调用"直接改写成"类名调用"。

    * 代价是编译变慢、运行变快；运行期不必再逐级向上查找，直接运行即可。

    * > **结论**：调用静态方法时直接写 `类名.方法名`，写成对象调用会让编译器额外做很多工作，拖慢编译。

    * 设计动机是空间换时间：把开发中最常用的虚方法提前放进表里，用内存空间换取运行效率；多占的几 KB 内存相对 16G、32G 的机器无所谓，运行效率的提升才是显著的。

## 权限修饰符

* **四种权限修饰符**

    * > **定义**：Java 的访问权限修饰符一共有四种，由大到小依次是 `public` ＞ `protected` ＞ （空着不写） ＞ `private`。

        ```text
        public  ＞  protected  ＞  （空着不写）  ＞  private
        ```

    * `private` 权限最小，只能在本类当中访问。

    * `public` 权限最大，在所有的地方都能够使用。

    * 中间还有两个：一个是空着不写，也就是包权限；另一个是 `protected`。

* **权限在继承结构中的体现**

    * 子类重写父类方法时，访问权限必须大于等于父类：把父类的修饰符改成 `protected`、子类也写 `protected` 代码不报错；父类是 `public`、子类却写成 `protected` 就直接报错。

    * 实际开发中重写的方法一般与父类完全保持一致，权限修饰符大于等于、返回值类型小于等于这些死规则只需混个眼熟，知道报错时怎么改就行。

    * `private` 修饰的私有方法既不被继承也不能被调用，权限限制正是它被排除在继承范围之外的原因。

    * 父类里 `private` 修饰的成员变量照样能被子类继承，只是不能直接调用，必须通过 `getXxx`、`setXxx` 方法访问。
