# 方法、参数与 Java 运行机制

## 方法

### 方法的本质

   * **方法（method）**

       * > **定义**：程序当中的独立功能，也是最小的执行单元。

       * "最小执行单元"指方法里的代码要么一行都不执行，一旦执行就从上往下把方法内所有代码全部执行完毕。

       * 求数组最大值、遍历数组打印、判断奇偶这类功能性代码重复书写十几遍就会腻，把它们打包成方法后可以直接调用调用处，重复代码大幅减少。

   * **复用性**

       * 重复代码不必再写一遍，以后用到直接调用已经打包好的方法即可。

   * **可维护性**

       * 代码出问题不必整段成段地排查，定位到出错的方法只改这一处即可。

### 方法之间的位置关系

   * > **易错点**：方法跟方法之间是平级关系，不能互相嵌套定义，不能把 A 方法写在 B 方法里面。

   * > **易错点**：方法不会主动运行，写在文件里只是一段待命代码，必须被调用才会执行。

       * `main` 本身也是方法，自定义的方法要写在 `main` 外面、类的里面。

   ```text
     class MethodDemo {                              ← 类的大括号
         │
         ├─  public static void main(String[] args) {  ← main 本身也是一个方法
         │       ...
         │   }
         │
         └─  public static int getSum(int a, int b) {  ← 自定义的方法，与 main 平级
                 ...
             }
     }
   ```

## 方法的格式

### 完整定义格式

   * **定义格式**

       ```java
       public static 返回值类型 方法名(形参, 形参) {
           方法体;
           return 返回值;
       }
       ```

       * `public`、`static` 暂当固定格式，面向对象章节再展开。

       * 接收数据的变量定义在小括号内部，多个形参之间用逗号隔开，位置一一对应。

       * 方法体是大括号内部的核心业务逻辑。

   * **以求 10 与 20 的和为例**

       ```java
       public static int getSum(int a, int b) {
           int sum = a + b;
           return sum;
       }
       ```

   * > **易错点**：返回值 `sum` 是方法真正运行的结果，返回值类型 `int` 是这个结果的类型，两者必须互相对应；返回的是整数却把返回值类型写成 `String` 就是错的。

### 第一行的三种说明职责

   * | 第一行上的那一块 | 它在告诉别人什么 |
       | :--- | :--- |
       | 方法名 `getSum` | 这个方法是干什么的 |
       | 形参 `int a, int b` | 干这件事需要提供什么 |
       | 返回值类型 `int` | 干完之后会得到什么结果 |

   * 只要看第一行就能猜出方法大致怎么用，根本不需要看方法体里的代码。

### return 关键字

   * **return**

       * > **定义**：只能写在方法里面，不能写在其他任何地方。

       * 第一层含义：结束方法的运行。

       * 第二层含义：把方法的计算结果交给方法的调用处。

   * > **注意**：`return` 返回的不是直接交给左侧变量，而是交给等号的右边，再由赋值运算符把该值赋给左侧变量。

   * 方法内 `return true` 会让方法直接结束，此时方法里的循环不会带着往下走，所以可以提前返回。

### void 与无返回值

   * **void**

       * > **定义**：Java 关键字，表示当前方法没有返回值，即不需要把结果返回给调用处。

       * 只把数据打印到控制台、不需要把结果交给调用处的方法，返回值类型写 `void`。

       * `void` 方法可以完全省略 `return`。

       * > **易错点**：`void` 方法里如果保留了 `return`，那么 `return` 后面不能写具体的数据，它仅表示结束方法。

## 方法的调用

### 调用格式与前提

   * **调用格式**

       * 直接写方法名喊它干活，小括号里交上它干活所需的数据，多个数据之间用逗号隔开。

   * > **易错点**：调用处与定义处的参数必须一一对应，指个数对应且数据类型对应。

       * 定义了两个形参就只能传两个实参，多传或少传都会直接报错。

       * 形参要两个整数，传两个字符串在程序不运行时就已经报错。

   * **使用返回值的两种方式**

       * 赋值给变量后再使用。

       * 直接写进输出语句，由 `println` 把结果打印出来。

       ```java
       int add = getSum(10, 20);
       System.out.println(add);
       System.out.println(getSum(10, 20));
       ```

### 实参与形参

   * **实参（actual parameter）与形参（formal parameter）**

       * > **定义**：调用处小括号里的参数叫实参，方法定义上的参数叫形参。

       * 调用时实参按顺序一一复制给形参，形参拿到值之后方法内的变量才真正有值。

       * 一一对应包含两层含义：个数对应、数据类型对应。

### 调用的执行流程

   ```text
     ┌─────────────────────────────────────────────────┐
     │ main 方法（调用处）                              │
     │     int add = getSum(10, 20);                    │
     └──────────────────────┬──────────────────────────┘
                            │
                            │  ① 实参按顺序一一复制给形参
                            │     10 → a        20 → b
                            ▼
     ┌─────────────────────────────────────────────────┐
     │ getSum 方法（形参：int a, int b）                 │
     │     ② 形参已有值，开始执行核心逻辑               │
     │        sum = a + b = 30                          │
     │     ③ return 结束方法，把 30 交出去              │
     └──────────────────────┬──────────────────────────┘
                            │  return 返回的是「等号的右边」
                            ▼
     ┌─────────────────────────────────────────────────┐
     │ 回到调用处：等号右边接到 30                      │
     │ 再由 = 赋值运算符，把 30 赋值给 add              │
     └─────────────────────────────────────────────────┘
   ```

### 无参方法

   * 方法内部用循环嵌套自己就能完成、什么都不需要外部提供时，小括号里可以空着。

   * 这类方法叫没有参数的方法，调用时实参也是空着的。

   * > **注意**：既没有参数也没有返回值的方法，定义处与调用处的小括号里都不写任何内容。

## 定义方法的三诀窍

### 诀窍一：方法里写什么

   * > **结论**：在大段代码中找出反复使用到的独立功能，把这一段抽成方法，而不是把全部代码搬进去。

   * 诀窍里有两条核心标准：反复使用、独立功能。

### 诀窍二：形参是什么

   * > **结论**：完成这个独立功能需要哪些数据，形参就是哪些数据。

   * > **提示**：想形参之前先确定当前方法要干什么事，再问"干这件事你需要我提供什么"。

   * 什么都不需要就能独立完成，这个方法就是无参的。

### 诀窍三：返回什么

   * > **结论**：看方法的调用处是否要用这个结果继续做事情。

       * 调用处要拿结果继续做判断或运算，就必须返回值，返回值类型写结果的数据类型。

       * 调用处不需要继续使用这个结果，直接定义成 `void`。

### 反例：整段代码塞进方法

   * 把四个参数和全部判断逻辑原样塞进 `compare`，跟没定义方法没有区别。

   * 这样的方法不具通用性，换成比较三个、四个、五个长方形时就完全不能用了。

   * **按三诀窍重写后的标准拆法**

       ```java
       public static double getArea(double length, double width) {
           return length * width;
       }
       ```

       * 调用处分别把 `length1, width1` 与 `length2, width2` 传进去求面积，再继续做 `if` 判断。

## 方法的练习形态

### 判断元素是否存在

   * **去重练习：把内层循环抽成方法**

       ```java
       public static boolean contains(int number, int[] arr) {
           for (int i = 0; i < arr.length; i++) {
               if (arr[i] == number) {
                   return true;
               }
           }
           return false;
       }
       ```

   * 结果只有存在与不存在两种，所以返回值类型写 `boolean`，`true` 表示存在、`false` 表示不存在。

   * 遇到相等的元素可以直接 `return true`，方法一结束循环也跟着结束。

   * > **易错点**：`return false` 不能写在 `else` 里面，必须写在循环外面，"没找到"这个结论只有在所有元素都比完之后才成立。

   * 调用处可以直接把方法写进 `if` 条件判断，省去中间的 `flag` 变量。

### 遍历数组

    ```java
       public static void printArr(int[] arr) {
           System.out.print("[");
           for (int i = 0; i < arr.length; i++) {
               if (i == arr.length - 1) {
                   System.out.print(arr[i]);
               } else {
                   System.out.print(arr[i] + ", ");
               }
           }
           System.out.println("]");
       }
     ```

   * 只需要把数据打印在控制台、不需要把结果交给调用处，所以返回值类型写 `void`，只带一个数组形参。

   * 格式三步：把元素逐个换行改成同一行；循环开始前打左括号、循环结束后打右括号；元素后加逗号空格。

   * > **易错点**：最后一个元素后面不能带逗号空格，靠判断 `i == arr.length - 1` 把最大索引的元素单独拎出来。

### 打印九九乘法表

    ```java
       public static void printMulTable() {
           for (int i = 1; i <= 9; i++) {
               for (int j = 1; j <= i; j++) {
                   System.out.print(j * i + "=" + i * j);
               }
               System.out.println();
           }
       }
     ```

   * 方法里直接写循环嵌套、什么都不需要外部给，所以是既无参也无返回值的方法。

   * 两层循环都写 1~9 先得到 9 行 9 列的长方形。

   * 把内层循环的结束条件改成 `i`，长方形就变成直角三角形。

   * 换行从内层挪到外层，循环体内连续打印不换行。

## 方法重载

### 重载的定义

   * **方法重载（overload）**

       * > **定义**：在同一个类当中定义多个同名方法，这些同名方法具有类似的功能，每个方法必须具有不同的参数类型或不同的参数个数，这些同名方法就构成重载关系。

       * 简单记忆：在同一个类里面，方法名相同、参数不同的方法就是方法的重载。

       * > **注意**：判断重载不需要看返回值，只看方法名和形参两点，返回值根本不参与。

   * 同名方法带来的收益：调用处通过"方法名 + 形参"就能直接找到底使用的是哪一个方法。

### 参数不同的三种形态

   * **个数不同**

       * 你有一个形参、我有两个形参，如 `sum(int a)` 与 `sum(int a, int b)`。

   * **类型不同**

       * 你是 `int`、我是 `double`，如 `sum(int a)` 与 `sum(double a)`。

   * **顺序不同**

       * 你是 `int, double`、我是 `double, int`，如 `sum(int a, double b)` 与 `sum(double a, int b)`。

   * > **结论**：参数个数、参数类型、参数顺序只要有一个不同，都算参数不同。

### 编译器如何选中方法

   * 编译器只认两样东西：方法名 + 形参列表。

    ```text
        同一个类里，三个方法共用一个名字：sum

        ①  sum(int a, int b)               →  return a + b
        ②  sum(int a, int b, int c)        →  return a + b + c
        ③  sum(int a, int b, int c, int d)  →  return a + b + c + d

                         调用 sum(1, 2)
                               │
                               ▼
           编译器只认两样东西：方法名 + 形参列表
                               │
                               ▼
           方法名对得上 sum，形参个数对得上 2
                               │
                               ▼
                  命中 ① ，② ③ 直接被排除
     ```

   * > **结论**：调用时命中的就是形参跟实参一一对应的那个方法。

### 隐式转换带来的歧义

   * Java 存在隐式转换：没有与实参一一对应的方法时，取值范围小的类型会自动提升为取值范围大的类型。

   * > **易错点**：所以方法重载一般不写成参数顺序不同的形式。

    ```text
        实参：a 和 b 都是 int

        想调用 getSum(int, double)   →   把 b 从 int 提升到 double   提升 1 次
        想调用 getSum(double, int)   →   把 a 从 int 提升到 double   提升 1 次

        两个候选都要提升 1 次，谁也不比谁更"优"
             │
             ▼
        编译器不知道该去掉哪一个，只能直接报错
     ```

   * 把 `(int, int)` 注释掉而 `(int, double)`、`(double, int)`、`(double, double)` 都在时，调用 `getSum(a, b)` 且 `a`、`b` 都是 `int` 会直接报错：没有完全匹配的方法，两个候选的提升次数又一样，编译器挑不出来。

   * 只留 `(double, double)` 一个候选时调用恢复正常，运行结果是 `30.0`。

   * 把 `(int, double)` 与 `(double, int)` 中任意一个删掉，代码也不再报错。

### 重载判断示例

   * `test(int a)` 与 `test()` 构成重载关系，形参个数不同。

   * `test(int a)` 与 `test(String s)` 构成重载关系，形参类型不同。

   * `test(int a, double b)` 与 `test(double a, int b)` 构成重载关系，形参顺序不同，但这种写法一般不用。

   * 两个方法名字相同、形参也相同、只有返回值不同，不构成重载，直接属于代码错误，程序会报错。

## Java 运行机制

### 编译与字节码文件

   * **编译**

       * > **定义**：把操作系统看不懂的 Java 代码翻译成能看得懂的内容。

       * 操作系统不管是 Windows 还是 macOS 都只认识 0 和 1，不认识 Java 语言。

       * 编译之后产生一个新文件，后缀名是 `.class`，即 class 文件，也叫字节码文件。

   * **真正运行的是 class 字节码文件**

       * `.java` 文件是给人看的，`.class` 才是给机器看的，操作系统认识的是后者。

   * **完整运行过程**

       * 编写 Java 文件 → 编译产生 class 字节码文件 → 把 class 字节码文件运行在虚拟机里面 → 看到最终效果。

       * 编译这一步由 IDEA 自动保存、自动完成，开发者只负责写代码和看结果两头。

### 虚拟机与跨平台

   * **虚拟机（virtual machine）**

       * class 字节码文件不是运行在操作系统里的，而是运行在 Java 虚拟机当中。

       * 模拟器类比：在 Windows 里装一个安卓手机模拟器，相当于模拟出一部手机，手机游戏就能在电脑上玩，模拟出来的这部手机就是虚拟机。

       * 手机游戏本身不是跨平台的，借助于不同版本的虚拟机才能实现在任意操作系统中运行。

   * **跨平台（cross platform）**

       * > **定义**：可以借助不同版本的虚拟机在任意操作系统中都能运行的特性。

       * 只要给一个安装包，一个程序就能在所有操作系统里运行，大幅降低开发成本。

       * Java 的运行规则与手机游戏完全一致：不是直接运行在操作系统里，而是运行在虚拟机里，代码本身不需要任何改动。

   * **JDK（Java Development Kit）**

       * > **提示**：JDK 全称 Java Development Kit，开发者工具包，是给程序员使用的。

       * 虚拟机不需要单独安装，安装 JDK 时里面就已经包含了虚拟机，针对不同操作系统安装不同版本的 JDK 即可。

### 源码目录与编译目录

   * **`src` 与 `out`**

       ```text
          项目根目录
          │
          ├── src   自己写的所有源代码
          │         src/com.itheima/...             ← 之前写的类都在这儿
          │
          └── out   编译之后生成的代码
                    out/production/com.itheima/...   ← 这里面全是 .class
       ```

   * 同一个类在两个目录里各有一份，`src` 那份是 `.java`，`out` 那份是 `.class`。

   * class 文件是给机器看的，用记事本强行打开全是看不懂的内容。

## 内存

### 内存

   * **内存（memory）**

       * > **定义**：软件在运行的时候用来临时存储数据的空间。

       * 记事本、Word、Excel 敲进去的文字，数据首先会在内存当中临时存储。

       * 只有点击了保存，程序才先到内存中找出这些临时数据，再把它移动到硬盘做永久化存储。

       * > **注意**：没点保存就把软件关掉，再打开数据就没了——未保存的数据全在内存里临时存着，软件一关、内存一清就全丢了。

       * 计算器点 `2 + 7` 时也先把 2 和 7 临时存储到内存，点等于号时才到内存中取出这两个数据交给 CPU 计算。

### 内存地址

   * **内存地址（memory address）**

       * > **定义**：操作系统给内存里每一个小格子的编号，它连续、唯一、不能重复。

       * 操作系统为了更快地查询内存中的数据，把内存以字节为单元划分成很多个小空间，一个小空间就是一个字节。

       * > **注意**：一个字节就是 8 个二进制位，也就是 8 个 0101。

       * 没有地址时获取某个小格子里的数据只能一个一个地查找，跟大海捞针一样慢；有了地址就可以直接定位。

       * > **易错点**：说的是内存地址的位数，不是内存空间的位数；一个地址对应一个字节，地址的取值范围直接决定可寻址的容量上限。

   * **编号规则**

       * 32 位操作系统用 32 位二进制表示地址，最小地址全 0、最大地址全 1，共 $2^{32}$ 个不同地址，最大支持 $2^{32}$ 个字节即 4 G，这正是它被逐渐淘汰的主要原因。

       * 64 位操作系统用 64 位二进制表示地址，共 $2^{64}$ 个地址，理论上支持 $2^{64}$ 字节，换算下来大约是 16 EB（一千六百多万 TB）。

       * > **结论**：到目前为止，世界上还没有一台计算机能达到这么大的内存。

       * | | 32 位操作系统 | 64 位操作系统 |
           | :--- | :--- | :--- |
           | 地址用什么表示 | 32 位二进制 | 64 位二进制 |
           | 地址个数 | $2^{32}$ ≈ 42.9 亿 | $2^{64}$ |
           | 最多能用多少内存 | 4 GB | 约 16 EB |

   * **为什么用 16 进制表述**

       * 直接写成 64 个 0101 太长不好阅读，所以在实际阅读前把 4 个二进制位分为一组转成 16 进制。

       * 八进制由 0~7 组成、逢八进一；16 进制逢 16 进一，每位是 0~9，10~15 不写成"十"这个字，而是写成 A、B、C、D、E、F，最大到 F。

       * 内存地址前面加 `0x` 作为标记，提示后面这一串数字是 16 进制，避免阅读时产生误解。

## Java 内存分区

### 五块区域

   * **Java 虚拟机的内存划分**

       * 每一款软件在运行时都要占据一块内存区域，Java 也不例外；虚拟机运行时占用一块内存空间，为更好地利用它把它分成五个部分。

   * | 区域 | 作用 | 一句话记忆 |
       | :--- | :--- | :--- |
       | 栈内存 | 方法进栈、出栈，存放方法运行时产生的局部变量 | 跟方法有关 |
       | 堆内存 | 存储对象、数组、字符串常量池，所有线程共享 | 跟 `new` 有关 |
       | 方法区 | 存储字节码信息、常量、静态变量 | 存字节码，不运行 |
       | 本地方法栈 | 用来调用本地 native 方法 | 平时用不到 |
       | 程序计数器 | 每个线程独立，记录当前线程执行到哪条字节码指令 | 给 CPU 用的，用不到 |

   * 现阶段只需要记住栈内存、堆内存、方法区三块区域的作用。

### 栈内存

   * **栈内存（stack）**

       * > **结论**：方法被调用的时候进栈执行；方法里面所有代码全部执行完毕，方法会从栈里出去。

       * > **结论**：栈是跟方法有关的。

   * **main 也在栈里**

       * `main` 是方法，只不过不是自己调用的，而是程序启动时由虚拟机自动调用，一旦调用就进栈执行，代码执行完毕就从栈里出去。

       ```text
          栈内存
          ┌──────────────────────────┐
          │  main()                  │  ← 虚拟机调用，进栈
          │    ┌────┐  ┌────┐        │
          │    │ a  │  │ b  │  ┌────┐│
          │    │ 10 │  │ 20 │  │ 30 ││
          │    └────┘  └────┘  └────┘│
          └──────────────────────────┘
       ```

### 堆内存

   * **堆内存（heap）**

       * 所有线程共享，用来存储对象、数组，还有字符串常量池。

       * > **结论**：只要代码里有 `new` 关键字，就一定用到了堆内存。

       * > **结论**：`new` 的作用就是在堆内存当中开辟一个空间。

   * > **易错点**：堆内存中用 `new` 开辟的空间是带有内存地址的，看到 `new` 就要想到"堆里多了一个带地址的小空间"。

### 方法区

   * **方法区（method area）**

       * JDK7 以前由永久代实现，从 JDK8 开始改由元空间实现，从虚拟机内部挪到了本地内存里。

       * 存储字节码信息、常量以及静态变量。

       * > **结论**：字节码信息是存在方法区的，编译完的 class 文件在程序运行时先加载到方法区里临时存储。

   * **方法区存、栈内存跑**

       * 运行 `Test` 类就是把 `Test.class` 加载到内存中并记录类里的所有信息，`main` 方法此时也在内存中。

       * > **易错点**：此时 `main` 方法只是临时存在方法区里，并没有运行；虚拟机调用 `main` 时是把它加载到栈内存里运行的。

       ```text
               方法区（存）                    栈内存（跑）
          ┌──────────────┐        ┌──────────────┐
          │  Test.class  │  调用  │    main()    │
          │  字节码信息  │ ─────► │  局部变量 a  │
          │  （不运行）  │        │ （正在运行） │
          └──────────────┘        └──────────────┘
       ```

## 内存中的执行过程

### 局部变量与内存归属

    ```java
       public static void main(String[] args) {
           int a = 10;
           int b = 20;
           int c = a + b;
           System.out.println(c);
       }
     ```

   * 正确答案是用到了栈和方法区，没有用到堆——这段代码里没有 `new` 关键字，没有 `new` 就用不到堆。

   * 完整执行流程：

       * 程序开始运行时，把相关类的字节码文件加载到方法区，该类所有信息都记录在方法区。

       * 虚拟机自动调用 `main` 方法，`main` 被加载进栈，开始准备执行里面的代码。

       * `int a = 10` 在 `main` 里开辟名为 `a` 的小空间存 10，`int b = 20` 同理开辟第二个小空间。

       * `int c = a + b` 开辟名为 `c` 的小空间，但它的值不是立马就有，要先找到 `a`、`b` 相加得到 30，再复制给 `c`，所以打印出来是 30。

### 基本数据类型的传参

   * **交换没成功的原因**

       * `main` 里的 `a`、`b` 与 `change` 里的形参 `a`、`b` 是各自方法栈帧中的小空间。

       * > **易错点**：两个 `a`、两个 `b` 之间不冲突，因为它们各自在不同的方法当中。

   * **传参的本质**

       * 调用时把 `main` 里的 10 和 20 赋值给 `change` 的形参 `a`、`b`，`change` 交换的是它自己栈帧里的两个变量。

       * `change` 内所有代码执行完毕就出栈，方法内变量随之消失，回到调用处继续执行；此时打印的仍是 `main` 里的 `a`、`b`，结果还是 10 和 20。

   * > **结论**：基本数据类型的变量里记录的是真实的数据，传递的也是真实的数据——我把真实数据给你了，你想怎么改就怎么改，不会影响到我。

   ```text
      栈内存（main）                     栈内存（change）
      ┌────────────────┐                  ┌────────────────┐
      │    main        │                  │    change      │
      │  ┌────┐ ┌────┐ │   实参赋给形参   │  ┌────┐ ┌────┐ │
      │  │ a  │ │ b  │ │  ──────────────► │  │ a  │ │ b  │ │
      │  │ 10 │ │ 20 │ │                  │  │ 10 │ │ 20 │ │
      │  └────┘ └────┘ │                  │  └────┘ └────┘ │
      │  ↑ 没被动过    │                  │  ↑ 交换发生在  │
      └────────────────┘                  └────────────────┘
   ```

### 数组的内存结构

   * **数组是第一种引用数据类型。**

       ```java
       int[] arr = new int[]{1, 2, 3};
       ```

       * 等号左边要把方括号去掉看，它就是定义在方法里的变量，`arr` 定义在栈内存中。

       * 等号右边的完整格式里有 `new`，所以它在堆内存中，`new` 在堆里开辟了一个空间，假设内存地址是 `0x0011`。

       * 数组长度为 3，`new` 出的空间被分成三个小格子，每格都有自己的索引，存着真实数据 1、2、3。

   * **即使写成简写也一定用到堆**

       * 简写格式 `int[] arr = {...}` 省略了 `new`，但完整格式里有 `new`，所以一定会用到堆内存。

       * 任何代码都会用到栈内存和方法区——字节码文件一定进方法区，`main` 被虚拟机调用一定进栈。

       ```text
         栈内存                          堆内存
         ┌──────────┐                     ┌────────────────────────┐
         │   arr    │ ─── 0x0011 ───────► │   0x0011（内存地址）   │
         │          │                     │   ┌────┬────┬────┐     │
         │  0x0011  │                     │   │ 1  │ 2  │ 3  │     │
         │          │                     │   └────┴────┴────┘     │
         └──────────┘                     │      0    1    2       │
                                         └────────────────────────┘
       ```

### 数组的访问、修改与打印

   * > **注意**：`arr` 里记录的不是数据，而是 `0x0011` 这个内存地址。

       * 访问：先找到 `arr`，通过内存地址找到堆里的数组本身，再获取指定索引上的数据。

       * 修改：同样先找到 `arr`，通过内存地址定位到堆里的数组，再修改对应索引上的数据。

   * **直接打印数组**

       ```text
       [I@1b6d3586
        └─┬─ 方括号：我打印的内存地址是一个数组
          └─ @ ：固定的分隔符
            └─ I ：数组元素类型是 int（换成 double，这里就是大写的 D）
              └─ 1b6d3586 ：16 进制表示的内存地址
       ```

   * 直接打印 `arr` 打印出来的是内存地址，不是数组里所有的数据。

   * 每一个人打印出来的内存地址可能都不一样，因为 `new` 出来的小空间在堆内存中的位置不固定。

## 基本数据类型与引用数据类型

### 差别就在变量里存什么

   * | | 基本数据类型 | 引用数据类型 |
       | :--- | :--- | :--- |
       | 变量里存什么 | 真实数据 | 内存地址 |
       | 传参传的是什么 | 真实数据 | 内存地址 |
       | 对方改了以后 | 原变量不受影响 | 原变量跟着变 |
       | 现实类比 | 花自己兜里的钱 | 兜里揣着好基友的家庭住址 |

   * 基本数据类型的变量里存储的是真实数据，引用数据类型里存储的是内存地址。

   * 现实类比：基本数据类型花的是自己兜里的钱；引用数据类型兜里装的是好基友的家庭住址，通过地址找到人，花的是他的钱。

   * 字面意思就是"引用"，拿别人的那一份去用。

### 引用数据类型的传参

   * **记录什么就传递什么**

       * > **易错点**：`change` 接收的是 `main` 中 `arr` 记录的内容，也就是内存地址 `0x0011`，不是数组里的数据。

       * `change` 里的 `arr` 通过传递过来的 `0x0011` 也能找到右边堆里的同一个数组。

   * **一处修改，处处可见**

       * 假如还有另一个变量 `br`，不管 `arr` 还是 `br`，通过内存地址 `0x0011` 都指向同一块空间，其中有一个人修改了空间里的数据，另外一个人再次访问看到的就是修改后的结果。

       * `change` 出栈后形参 `arr` 从内存中消失，但它修改的是堆里的空间，`main` 再次访问拿到的就是交换后的结果。

       ```text
         栈内存                                堆内存
         ┌──────────────┐                      ┌──────────────────────┐
         │ main:arr     │ ─── 0x0011 ────────► │  0x0011              │
         │   0x0011     │                      │   ┌───┬───┬───┐      │
         ├──────────────┤                      │   │ 1 │ 2 │ 3 │      │
         │ change:arr   │ ─── 0x0011 ────────► │   └───┴───┴───┘      │
         │   0x0011     │                      │    0    1    2       │
         └──────────────┘                      └──────────────────────┘
       ```

## 快慢指针移除元素

### 双指针的分工

   * **双指针（快慢指针）**

       * "指针"可以理解为一个变量或一个箭头，默认指向数组中的某个索引，然后不断移动它产生想要的效果。

       * 慢指针 `slow`：当前数据应存入的位置，也就是已经存了几个好数据。

       * 快指针 `fast`：从左往右一个一个地扫，撞见要删的就跳过。

       * 快指针位置的数等于要删的值就舍弃、`slow` 不动；不等于就把这个数存入 `slow` 所指位置，`slow` 与 `fast` 一起前进。

       ```text
         慢指针 slow                    快指针 fast
         ┌────────────────────┐        ┌────────────────────┐
         │ 数据该存到哪个位置 │        │ 从左往右一个一个扫 │
         │ 已经存了几个好数据 │        │ 撞见要删的就跳过   │
         └────────────────────┘        └────────────────────┘
       ```

### 慢指针的两层含义

   * 第一层含义：数字应存入的位置，下一个满足条件的数据应该存在 `slow` 所指的索引里。

   * 第二层含义：当前已经找到的符合要求的数据个数，`slow` 现在指向几索引就说明刚好存了几个好数据。

    ```text
       fast 指向  该位置数据  动作                     之后 slow 指向  已找到
       0         2           舍弃，fast++             0              0 个
       1         2           舍弃，fast++             0              0 个
       2         1           存入 slow 位置，slow++   1              1 个
       3         1           存入 slow 位置，slow++   2              2 个
       4         2           舍弃，fast++             2              2 个
       5         2           舍弃，fast++             2              2 个
       6         3           存入 slow 位置，slow++   3              3 个
       7         3           存入 slow 位置，slow++   4              4 个
       8         3           存入 slow 位置，slow++   5              5 个
       9         3           存入 slow 位置，slow++   6              6 个
       10        —           越界，循环结束           6              6 个
     ```

### 判定依据

   * `slow` 永远指向"下一个有效数据该放的位置"：下标小于 `slow` 的那一段元素已经全部不等于要删的值，且顺序与它们在原数组中出现的顺序完全一致。

   * 下标大于等于 `fast` 的那一段元素还没被检查过。

   * 扫描结束后下标 `[0, slow)` 区间就是整理好的有效数据，`[slow, length)` 区间里残留的都是应该被丢弃的值，整个过程原地修改数组，不需要额外的辅助空间。

### 最终写法

    ```java
       public static void main(String[] args) {
           int[] arr = {0, 1, 2, 2, 3, 0, 4, 2};
           int val = 2;

           int slow = 0;
           int fast = 0;

           while (fast < arr.length) {
               if (arr[fast] != val) {
                   arr[slow] = arr[fast];
                   slow++;
               }
               fast++;
           }

           for (int i = 0; i < slow; i++) {
               System.out.print(arr[i] + " ");
           }
           System.out.println("有效个数：" + slow);
       }
     ```

   * `if` 和 `else` 两边都有 `fast++`，把它提到 `if else` 外面，走哪条分支都会执行；此时 `if` 里就空了，把 `==` 改成 `!=`，把 `else` 里的代码挪进 `if`，删掉 `else`。

   * > **易错点**：输出循环的结束条件不是 `arr.length` 而是 `slow`，真正有效的数据是 `slow` 前面的那一段，按 `arr.length` 输出会把残留的要删的值一起打出来。

   * > **结论**：`fast` 负责整个数组的扫描，`slow` 负责往前压缩有效数据；循环结束时 `slow` 就是保留下来的有效元素个数，输出时只输出前 `slow` 个即可。

   * 示例二的结果是 `0 1 3 0 4`，有效个数 `5`。
