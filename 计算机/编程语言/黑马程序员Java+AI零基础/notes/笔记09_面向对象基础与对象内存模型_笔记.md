# 面向对象基础与对象内存模型

## 类的三种形态

### JavaBean 类与测试类

* **java bean 类**

    * > **定义**：用来描述一类事物的类，它不是程序的主入口。

    * 类中不写 `main` 方法，写了也没用，因为程序不会从那儿启动。

    * 类中可以写属性和行为，行为本质上就是方法，表示这一类事物能干什么。

    * > **结论**：java bean 类里面书写的方法不加 `static`，其他部分跟普通方法一模一样。

### 测试类

* **测试类**

    * > **定义**：带着 `main` 方法的类，承担程序主入口。

    * 测试类负责创建出具体对象、给属性赋值、再调用对象的行为。

    * 写在测试类里、写在 `main` 方法下面的方法需要加 `static`，写在 java bean 类里的方法不加。

* 两者对照

    | 对比项 | java bean 类 | 测试类 |
    | :--- | :--- | :--- |
    | 干什么用 | 描述一类事物 | 写程序主入口、创建对象 |
    | 有没有 `main` 方法 | 没有 | 有 |
    | 里面写什么 | 属性和行为（方法） | 创建对象、给属性赋值、调用行为 |

### 工具类

* **工具类**

    * > **定义**：不是用来描述一类事物的、也没有 `main` 方法，而是帮我们做一些事情的类。

    * 工具类一般以 `Util` 结尾命名，如数组工具类叫 `ArrayUtil`，这样别人看名字就知道它是干什么的。

    * 私有化构造方法，因为创建工具类的对象没有任何意义，不让外界创建对象。

    * 所有方法都定义为静态的，直接用类名调用。

    * > **结论**：方法必须静态的原因是不写静态外面根本没法调用——既没有对象，又不能用类名调用。

* 三类归属

    | 类型 | 有没有 `main` | 干什么用 | 例子 |
    | :--- | :--- | :--- | :--- |
    | java bean 类 | 没有 | 描述一类事物 | `Dog`、`Cat`、`Student`、`Teacher` |
    | 测试类 | 有，程序主入口 | 让程序跑起来 | 测试类 |
    | 工具类 | 没有 | 帮你做一些事情 | `ArrayUtil` |

## private 与数据安全

### 权限修饰符

* **权限修饰符**

    * `private` 修饰成员变量，也能修饰成员方法。

    * > **定义**：成员变量是定义在方法外面、类里面的变量；成员方法是写在类里面的行为方法。

    * 被 `private` 修饰后只能在本类当中访问，外界无法访问。

    * `public` 与 `private` 相反，表示公共的，在所有的类当中都可以使用。

* 修饰符访问范围

    | 修饰符 | 含义 | 访问范围 |
    | :--- | :--- | :--- |
    | `private` | 私有的 | 只能在本类当中访问 |
    | `public` | 公共的 | 在所有的类当中都可以使用 |

### 数据不安全的成因

* 成员变量直接不加修饰符定义时，测试类里可以用点的方式直接访问属性，代码简单，但赋入错误的数据没有任何提示。

* 典型表现：把小狗的年龄赋成负数，因为 `int` 的取值范围包含负数，代码不会报错，但与实际情况不符。

* 在赋值之前判断能不能解决单个对象的问题，但对象一多，每次赋值都要写一次判断，非常麻烦。

* > **易错点** ⚠️：`private` 一加就把外界全堵死了，连正确的值也赋不进去，这显然不是想要的。

### 解决数据安全的两步

* **第一步：私有化成员变量**

    * java bean 类中所有成员变量都用 `private` 修饰，只能在本类当中访问，其他类不能直接使用。

    * 私有化之后，测试类里用对象名直接访问该属性会在编译期直接报错。

* **第二步：为私有化的成员变量提供对应的 get 和 set 方法**

    * `setXxx` 用于赋值，可以在方法体内对传进来的数据做判断过滤——符合要求才正常赋值，不符合要求直接不赋值。

    * `getXxx` 用于对外提供该属性的数据，返回值类型与属性类型一致。

    * 两个方法都用 `public` 修饰，效果是正确的数据赋值成功、错误的数据赋值失败。

* 过滤逻辑的落点

    ```java
    public void setAge(int value) {
        if (value >= 0 && value <= 15) {
            age = value;
        } else {
            System.out.println("当前的" + value + "不在合理范围之内");
        }
    }
    ```

    * 判断写在 `set` 方法内部，被拒绝的赋值完全不触碰成员变量。

    * 走 `else` 分支后，成员变量保持默认初始化值。

### 默认初始化值

* 赋值失败后取到的值

    | 成员变量的类型 | 默认初始化值 |
    | :--- | :--- |
    | 引用数据类型（比如 `String`） | `null` |
    | 整数（`int`） | `0` |
    | 小数（`double`） | `0.0` |

* > **易错点** ⚠️：赋了错误的数据导致没有成功赋值时，属性取到的是默认初始化值，这一规则跟数组一模一样。

### 基于 get 与 set 的相对修改

* 增删属性值的写法

    * 先 `get` 出来、加减运算、再 `set` 回去，而不是把增量直接传给 `set`。

    ```java
    double newWeight = s.getWeight() + 10;
    s.setWeight(newWeight);

    newWeight = s.getWeight() - 3;
    s.setWeight(newWeight);
    ```

    * 直接写 `s.setWeight(s.getAge() + 1)` 这类嵌套写法与「先定义变量再赋值」等价，区别只是少定义一个变量。

    * > **易错点**：`set` 方法是「修改」而不是「累加」，原来是多少不管，只把传入的值变成对象里的最新值。

* 同名类的选择

    * > **易错点** ⚠️：项目里存在多个同名类时，选错了包会导致用错类，要看清包名。

    * 用同一个包里的同名类时，类名上方没有 `import` 导包语句；用到别的包里的同名类时，上方会多出 `import`。

### 字符串中拼接变量

* 需要随对象变化的值要挪到引号外面

    ```java
    public void eat() {
        System.out.println(age + "岁的小" + name + "正在吃骨头");
    }
    ```

    * 往字符串里塞变量时，要么少写一个引号，要么少写一个加号。

    * > **提示**：把变量挪到引号外面时，先选中变量 `Ctrl+X`，光标不动，按两下双引号把光标放到中间，按加号，在两个加号中间 `Ctrl+V`。

## 就近原则与 this 关键字

### 成员变量与局部变量

* **成员变量**

    * 定义在方法外面、类里面的变量，也叫属性。

* **局部变量**

    * 定义在方法里面，或者定义在方法形参（小括号里）的变量。

### 就近原则

* **就近原则**

    * > **定义**：在方法中直接使用变量时的查找顺序——先找方法内的局部变量，有就用它；方法内没有再使用成员变量。

    * 方法中直接写一个变量名时，JVM 先在方法里面找对应的局部变量，方法里压根没有才往上走用成员变量。

    * 变量名离得越近越优先用；同方法的局部变量只隔几行，成员变量隔着一层大括号，自然取局部变量。

    ```java
    public class Student {
        private int age;              // 成员变量

        public void setAge() {
            int age = 18;             // 局部变量
            System.out.println(age);  // 离得近，用局部变量 → 18
        }

        public int getAge() {
            System.out.println(age);  // 方法里没有局部变量 → 用成员变量 age
            return age;
        }
    }
    ```

### this 关键字

* **this 关键字**

    * > **定义**：`this` 的本质是它所在方法的调用者的内存地址值。

    * 在变量前面加 `this.` 前缀，强制使用成员变量，不受就近原则影响。

    * 局部变量与成员变量重名时，右侧不带 `this` 取局部变量（外界传进来的数据），左侧带 `this.` 明确指向对象属性。

    ```java
    public void setAge(int age) {
        age = age;      // 自己赋给自己，对象的属性没被改到
    }

    public void setAge(int age) {
        this.age = age; // 正确：外界数据 → 对象属性
    }
    ```

    * > **结论**：`this` 的作用就是区分成员变量和局部变量；直接写变量名会触发就近原则，加 `this.` 则强制使用成员变量。

    * 同一个方法被不同对象调用时，`this` 记的是不同地址，取到的成员变量自然不同。

    ```text
           栈                                         堆
    +------------------------+     +-----------------------------------+
    | main()                 |     | Student 对象①  @0x0011            |
    |   s1 ────────────►     ├────►|    name = 小诗诗    age = 18       |
    |   s2 ────────────►     │     +-----------------------------------+
    |                        |     | Student 对象②  @0x0022            |
    +------------------------+     |    name = 小丹丹    age = 19       |
    +------------------------+     +-----------------------------------+
    | study()      ← s1 调用 |
    |   this ────────────────┼────────────────────────▲
    |   age = 10（局部变量）  |
    +------------------------+
    ```

    * 方法进栈时会在栈帧里记录调用者的内存地址，这个记录下来的东西就是 `this`。

    * 方法体内先定义局部变量 `age = 10`，打印 `age` 走就近原则仍是 10；打印 `this.age` 顺着记录的地址找到对应对象。

* 形参与字段重名

    * 形参名与字段同名时，`age = name` 形式看起来能编译，但赋的其实是形参传进来的值，因为形参把同名字段遮住了。

    * 换成 `value`、`n` 这类名字读起来清爽，但规范写法是统一用 `this.` 明确指代字段。

    * > **易错点** ⚠️：形参与字段重名而没加 `this.`，相当于把值赋给形参自己，字段仍保持 `null`。

## 构造方法

### 定义与格式

* **构造方法（构造器、构造函数）**

    * > **定义**：与类名同名、无返回值类型、在创建对象时由虚拟机自动调用、用来给成员变量做初始化（第一次赋值）的方法。

    ```java
    修饰符 类名(参数) {
        // 方法体：给成员变量赋值的代码
    }
    ```

### 三个特点

* 方法名必须跟类名完全一致，连大小写都要一致。

* 没有返回值类型，连 `void` 都没有；写的时候在修饰符后面直接就是类名。

* 没有具体的返回值，方法体里不能写 `return`。

### 调用时机

* > **结论**：构造方法不是手动调用的，而是在创建对象的时候由虚拟机自动调用的。

    * 虚拟机根据创建对象时小括号里的参数决定调用哪一个构造方法：小括号空着调空参构造，填了属性值就调带全部参数的构造。

    * 每创建一次对象就调用一次构造方法；一次走空参、一次走带参，两次调用各归各的。

    * > **易错点**：不能拿对象名去手动调构造方法，构造方法只在创建对象的那一刻由虚拟机自动调用。

### 默认构造方法的补充规则

* 压根没写构造方法时，系统会补一个默认的无参构造，所以直接 `new Student()` 不报错。

* 系统不会补带全部参数的构造，`new Student("张三", 23)` 会报错。

* 只要自己写了任意一个构造方法，默认无参构造就没了。

    | 你写了哪些构造 | `new Student()` | `new Student("张三", 23)` |
    | :--- | :--- | :--- |
    | 一个都没写 | 系统补默认无参，能用 | 报错 |
    | 只写带参构造 | 报错 | 能用 |
    | 只写无参构造 | 能用 | 报错 |
    | 两个都写 | 能用 | 能用 |

* 带参构造与无参构造方法名相同、参数不同，属于**方法的重载**，所以构造方法本质上是一个特殊的方法。

* > **结论**：不管用不用、用什么，都手写无参构造和带全部参数的构造这两个。

### 带参构造的赋值

* 构造方法里的赋值靠 `this` 理解：等号右边是传进来的形参，等号左边带 `this.` 指向对象属性。

    ```java
    public Student(String name, int age, String gender, int height) {
        this.name = name;
        this.age = age;
        this.gender = gender;
        this.height = height;
    }
    ```

* 空参构造创建的对象直接取属性，打印出来是 `null`、`0`，因为数据保持默认值。

## JavaBean 类的书写规范

* 类名要见名知意：描述学生就叫 `Student`，描述猫叫 `Cat`，描述小狗叫 `Dog`，不能随便乱写。

* 所有成员变量都要用 `private` 修饰，私有化，不让外界直接访问。

* 针对每一个私有化成员变量，都提供对应的 get 和 set 方法，好处是在 set 里对要赋的值做过滤。

* 额外再写两个构造方法，一个无参、一个带全部参数，创建对象时可以把属性一次性给完。

* 其他行为也写在这个类里，比如学生的学习、吃饭、睡觉，都以方法的形式写在 java bean 里。

* 创建对象的格式是 `类名 对象名 = new 类名();`。

* 即使可以用带全部参数的构造一次性赋值，创建对象时并不知道所有属性时仍要先用无参构造创建，等知道之后再一个一个 set。

### IDEA 快捷键

* 类建好、私有化成员变量敲完后，剩下的成员可以一键生成，快捷键是 `Alt + Insert`。

    | 操作 | 步骤 |
    | :--- | :--- |
    | 生成空参构造 | `Alt + Insert` → 选 `Constructor` → 回车 → 点 `Select None`（或连按两下 `Tab`）→ 回车 |
    | 生成带全部参数的构造 | `Alt + Insert` → 选 `Constructor` → 回车 → `Ctrl + A` 全选 → 回车 |
    | 生成 get 和 set | `Alt + Insert` → 选第四项 `Getter and Setter` → `Ctrl + A` 全选 → 回车 |

* 弹框名字是 `Generate`；生成空参构造时 `Constructor` 默认已勾选 `name`，直接点 OK 生成的是带 `name` 的构造，所以要点 `Select None`，或按两下 `Tab`——第一下取消默认勾选，第二下选中 `Select None`。

* 生成 get 和 set 时别选第二项 `Getter` 或第三项 `Setter`，要选第四项两个一起的。

* > **注意**：`Insert` 键在每个键盘上位置不一样，大概率在退格键上方；按 `Alt + Insert` 没反应时再加上 `Fn` 键，三个一起按。

## 内存模型

### 三块内存区域

* 虚拟机把内存分成五个部分：栈内存、堆内存、方法区、本地方法栈、程序计数器，后两个不需要记忆。

* 栈内存与方法有关，方法被调用进栈执行，方法里代码执行完毕就从栈里出去。

* 堆内存用来存储对象、数组、字符串常量池；只要是通过 `new` 关键字创建的小空间，一定在堆里。

* 方法区用来存储字节码信息，一个类要运行时会把这个类的 class 文件先加载到方法区当中。

### 创建对象的七个动作

* 执行 `Student stu = new Student();` 时虚拟机做的七件事：

    ```text
    ① 加载 class 文件 ──▶ 把 Student 的字节码文件加载到方法区临时存储
                         此时方法区里有了 Student 的全部信息：属性 name、age，行为 study()

    ② 声明局部变量   ──▶ 执行等号左边，给 stu 声明这个局部变量
                         stu 是数据类型，意思是它以后能存 Student 类对象的地址值
                         注意：stu 虽叫对象名，但在内存角度它就是一个变量

    ③ 堆中开辟空间   ──▶ 执行等号右边的 new Student()，在堆里开辟一个小空间
                         堆里每一块空间都有内存地址，假设这块的地址就是 0x0011

    ④ 默认初始化     ──▶ name 这个引用数据类型默认为 null，age 这个 int 默认为 0

    ⑤ 显示初始化     ──▶ 如果在类里定义成员变量时直接赋了值，这一步才生效
                         我们一般不这么写，所以这步可以忽略

    ⑥ 构造方法初始化 ──▶ 调用构造方法给 name、age 赋值
                         用的是空参构造，里面一般不写代码，这步也可以忽略
                         若是用带全部参数的构造创建的对象，这一步属性就有值了

    ⑦ 赋地址值       ──▶ 执行中间的等号，把堆中对象的内存地址 0x0011 复制给左边的 stu
    ```

* 三处赋值是默认初始化、显示初始化、构造方法初始化，顺序即④⑤⑥。

* 走完七步之后的样子：

    ```text
    ┌──────────────────────── 方法区 ─────────────────────────┐
    │  Student.class                                          │
    │  name、age、study() …… 这个类里所有的属性与方法信息      │
    └──────────────────────────────────────────────────────────┘

    ┌──────────────────────── 栈内存 ─────────────────────────┐
    │  main()                                                 │
    │  ┌──────────────────┐                                   │
    │  │ stu : 0x0011     │                                   │
    │  └──────────────────┘                                   │
    └──────────────────────────────────────────────────────────┘

    ┌──────────────────────── 堆内存 ─────────────────────────┐
    │  0x0011                                                 │
    │  ┌──────────────────────────────────┐                  │
    │  │ name : null                      │                  │
    │  │ age  : 0                         │                  │
    │  │ study() 的内存地址                │                  │
    │  └──────────────────────────────────┘                  │
    └──────────────────────────────────────────────────────────┘
    ```

    * 堆里 `0x0011` 那块空间才是平时所说的**对象**，`stu` 从头到尾只是拿着地址的变量。

    * 对象里除了属性，还记着所有成员方法的内存地址，记它是为了用对象调方法时能找到对应的方法。

### 访问属性与调用方法

* 访问属性的查找是两跳

    ```text
    stu（栈内存里的变量）
       │  ① 读出 stu 里记录的内存地址
       ▼
    0x0011（堆内存中的对象）
       │  ② 在对象里找到 name、age
       ▼
    null 和 0
    ```

* 调用的查找是四步

    ```text
    stu.study()
       │
       ├─ ① stu 里记录的是谁的内存地址？→ 0x0011，找到堆中的对象
       │
       ├─ ② 在对象里查有没有 study 这个方法的地址
       │       对象里除了属性，还有成员方法的内存地址
       │       有 → ③ 把 study 方法加载进栈，开始执行里面的代码
       │       没有（比如调用 aaabbb）→ 调用失败
       │
       └─ ④ study 里只有一行输出语句，打印「学生正在学习」
              方法里代码执行完毕，study 从栈里出去
    ```

* > **注意**：变量记录什么，打印就是什么；直接打印 `stu` 打出来的是 `Student` 在内存中的地址，Java 对地址做了优化，打印时前面会加上「包名.类名@」，最后那串才是真正的十六进制内存地址。

### 对象什么时候消失

* 方法都没有了，方法里面的变量也不会存在；`main` 方法从栈里出去，里面的 `stu` 随之消失。

* 变量一消失就没有人再用右边那个对象，对对象也会随之从内存当中消失。

* > **结论**：当没有任何地方在使用这个对象时，对象就会从内存中消失；但方法区里的字节码信息一般不会消失，除非整个虚拟机停掉。

## 对象在方法中的传递

### 传过去的是内存地址

* > **结论**：把一个对象传递给方法，实际传递的是对象的**内存地址**；此时栈里有多个变量指向同一个对象，只要有一个变量修改了对象中的属性，其他变量再次访问拿到的就是修改之后的结果。

    ```text
            栈（main）                        栈（change）              堆
    ┌──────────────────────┐   ┌──────────────────────┐    ┌──────────────────────┐
    │ stu ──► 0x0011       │   │ stu ──► 0x0011       │    │ name = 小丹丹        │
    │                      ├───┤                      ├────►                      │
    │                      │   │                      │    │ age  = 19             │
    └──────────────────────┘   └──────────────────────┘    └──────────────────────┘
    ```

    * 调用方法时变量里面记录的是什么就传递什么，`main` 里的 `stu` 记着 `0x0011`，传进 `change` 的形参 `stu` 记着的也是 `0x0011`。

    * 两个变量指向同一个对象，就像把家庭住址告诉别人，别人到的是同一户人家。

* 执行时序

    ```text
    ① main 执行 Student stu = new Student()  → 堆里造对象，stu = 0x0011
    ② main 打印 stu.name / stu.age          → 小诗诗 / 23
    ③ 调用 change(stu)                       → change 进栈，形参 stu 拿到 0x0011
    ④ change 里改成 小丹丹 / 19              → 改的还是同一个对象
    ⑤ change 出栈，形参 stu 消失             → 对象还在，因为 main 的 stu 还在用
    ⑥ main 再次打印                          → 小丹丹 / 19
    ⑦ main 出栈                              → 没人再用了，对象才消失
    ```

    * 差别就在第⑤步和第⑦步：`change` 出栈后对象不会消失，只要栈里还有变量在用它它就活着，等没人引用了才从内存中消失。

## static 静态成员

### 加不加 static 的标准

* **static**

    * `static` 表示静态，是 Java 里的一个修饰符，可以修饰成员变量和成员方法。

    * 判断标准只有两个字——**共享**：看当前属性是对象独有的，还是所有对象共享的。

    * 对象独有的属性加 `static` 等于宣布全体共用一份值，与实际情况不符。

* 属性判断

    | 属性 | 加 static 吗 | 为什么 |
    | :--- | :--- | :--- |
    | `name` 姓名 | 不加 | 加了就表示所有学生共享同一个名字，全班所有人都叫同一个名字不可能 |
    | `pen` 笔 | 不加 | 所有学生都有自己的笔，不是共享的 |
    | `teacherName` 老师姓名 | 得看业务场景 | 在学校里一个班级共享同一个老师，要加；但如果这老师是家庭私教，一个学生只对一个老师，就不能加 |
    | 水杯 | 不加 | 所有人都用同一个水杯说不过去 |
    | 饮水机 | 加 | 不用的话就是每个学生都有自己的饮水机，不现实 |

* > **结论**：像 `teacherName` 这样的属性到底用不用 `static`，要看具体的业务场景。

### 共享要达成的两个效果

* 不管有多少对象，共享数据的赋值只写一次，写完所有对象用的都是同一个值。

* 任意一个对象修改了共享数据，其他对象再次访问时拿到的就是修改之后的结果。

* 对照实验：把 `teacherName` 的 `static` 删掉再运行，只有被赋值的那一个对象里是「小文老师」，另一个对象访问不到，取到的是默认初始化值 `null`。

### 静态变量的调用方式

* 被 `static` 修饰的成员变量叫**静态变量**。

* 有两种调用方式：用类名调用，或者用对象名调用；推荐用类名。

    ```java
    Student.teacherName = "小文老师";   // 推荐
    stu1.teacherName = "小文老师";     // 不推荐，能用但 IDEA 不给自动提示
    ```

* 第二个对象从没给 `teacherName` 赋过值，取到的却是「小文老师」，正是静态变量被全类共享的结果。

### 静态变量的内存布局

    ```text
             栈                    堆                             方法区
    ┌────────────────────┐  ┌────────────────────────┐  ┌──────────────────┐
    │ main()             │  │ 静态区（Student 类）   │  │ Test.class       │
    │  s1 ─► 0x0011 ─────┼─►│  teacherName = 阿伟    │  │ Student.class    │
    │  s2 ─► 0x0022 ─────┼─►├────────────────────────┤  └──────────────────┘
    │                    │  │ 对象① @0x0011         │
    │                    │  │  name = null          │
    │                    │  │  age  = 0             │
    │                    │  │  ── 静态区地址 ───────┼─┐
    │                    │  ├────────────────────────┤ │
    │                    │  │ 对象② @0x0022         │ │
    │                    │  │  name = null          │ │
    │                    │  │  age  = 0             │ │
    │                    │  │  ── 静态区地址 ───────┼─┼─► 都指向同一个静态区
    └────────────────────┘  └────────────────────────┘ │
    ```

    * 类一被用到，字节码文件就加载到方法区，同时在内存中创建出一个单独存放静态变量的空间，这个空间叫静态区。

    * 静态变量是随着类的加载而加载的，跟对象没有任何关系，优先于对象而存在；此时内存中还没有对象。

    * 堆里每块对象空间存着所有非静态的成员变量，同时还记录静态区的地址，因为代码里也可以通过对象名调用静态变量。

    * 栈与对象出栈消失后，静态区里的变量与方法区里的字节码信息依然存在，除非关掉整个虚拟机。

### 静态变量的三个特点

* 被 `static` 修饰后这个变量就叫静态变量，它被这个类所有的对象共享，内存中其实只有一份，放在静态区里，谁要谁去拿。

* 静态变量属于类的，不属于某一个特定的对象。

* 静态变量随着类的加载而加载，优先于所有对象而存在，只要这个类被使用静态的东西就已经在内存中出现了；对象一定要通过 `new` 执行了才会出现。

* 某个对象改了静态变量，其他对象再访问拿到的就是改后的结果。

### 静态方法

* **静态方法**

    * 被 `static` 修饰的成员方法叫静态方法，多用在测试类和工具类里，在 java bean 类里很少使用。

    * 调用方式跟静态变量一样，类名和对象都能调，一样推荐用类名。

### static 的三条边界

* 静态只能访问静态：静态方法里访问普通成员变量、调用普通成员方法都报错，访问静态变量、调用静态方法都正确。

* 非静态能调用所有：同一个普通成员方法里访问静态与非静态的内容全部正确。

* 静态方法里面没有 `this` 关键字，不能用 `this` 去点调用其他内容。

* 边界的成因

    * 静态的内容随着类的加载先进内存，优先于对象存在，此时不一定有对象，所以静态只能调静态。

    * 非静态的内容出现在内存里，说明类已经加载、静态变量已经加载、对象也创建好了，所以非静态可以调用所有。

    * 调用非静态的成员方法只有一种方式，就是用对象来调，它不能用类名调，所以想调必须先 `new` 一个对象再用对象去调。

    * > **易错点** ⚠️：静态方法里即便已经在调用点前面 `new` 出了对象，也照样调不通——静态方法没有 `this`，不记录调用者的内存地址，它压根不知道该找谁。

* 调用非静态方法时的栈帧

    ```text
       Stack / 栈                     Heap / 堆
    +----------------------+      +-----------------------------+
    |  main()              |      |  Student 对象 (0X0011)      |
    +----------------------+      |    name        = null       |
                |                  |    teacherName = "老王"     |
                | new              +-----------------------------+
                v                            ^
    +----------------------+                |
    |  show() frame         | --- this --->  |  调用者就是它自己      |
    |    this = 0X0011      |                |
    +----------------------+
    ```

## 工具类的写法

* **工具类的三步**

    * 第一步，名字见名知意，如 `ArrayUtil`，工具类一般以 `Util` 结尾。

    * 第二步，私有化构造方法，创建工具类的对象没有意义，写成 `public` 外界就能创建，违反工具类的定位。

    * 第三步，所有方法定义为静态的，直接用类名调用。

* 遍历数组的两种写法

    * 直接打印版

    ```java
    public static void printArr(int[] arr) {
        System.out.print("[");
        for (int i = 0; i < arr.length; i++) {
            if (i == arr.length - 1) {
                System.out.print(arr[i] + "]");
            } else {
                System.out.print(arr[i] + ", ");
            }
        }
        System.out.println();
    }
    ```

    * > **注意**：这里要把 `println` 的 `ln` 去掉，只有打印完最后一个数据的时候才换行。

    * 返回字符串版

    ```java
    public static String printArr(int[] arr) {
        String result = "";
        result += "[";
        for (int i = 0; i < arr.length; i++) {
            if (i == arr.length - 1) {
                result += arr[i] + "]";
            } else {
                result += arr[i] + ", ";
            }
        }
        return result;
    }
    ```

    * 返回版本需要用一个变量接收后打印，返回之后想打印还是做其他操作都随你。

* 求平均值

    ```java
    public static double getAverage(int[] arr) {
        int sum = 0;
        for (int i = 0; i < arr.length; i++) {
            sum += arr[i];
        }
        double avg = sum * 1.0 / arr.length;
        return avg;
    }
    ```

    * > **易错点** ⚠️：整数跟整数相除只能得到整数。数组 `1 2 3 4 7` 的总和是 17，`17 / 5` 的结果是 `3` 而不是 `3.4`，必须让 `sum` 先乘 `1.0` 变成小数再参与计算。

* > **提示**：点一下方法按 `Ctrl + Alt + V` 可以自动生成左边接收该方法结果的变量；按 `Ctrl + Alt + L` 格式化代码。

## main 方法

* **main 方法的每个关键字**

    ```java
    public class Test {
        public static void main(String[] args) {

        }
    }
    ```

    * `public`：访问权限，公共的，权限最大，虚拟机可以在任意地方调用它。

    * `static`：静态，正因为 `main` 方法是静态的，虚拟机调用时可以用类名直接调；也正因为它静态，在测试类下面再写的其他方法也得写成静态的。

    * `void`：表示 `main` 方法没有返回值。

    * `main`：不是关键字，而是方法名，是一个被虚拟机识别的固定名字，写成别的名字虚拟机就不认识了。

    * `String[] args`：字符串类型的数组，用来接收运行参数，暂时用不到。

## final 常量

### 定义与两个特点

* **final**

    * `final` 翻译成中文是最终、不可变，它可以修饰变量、类、方法三类东西；修饰类和修饰方法涉及继承，此处只把修饰变量学透。

* **常量**

    * 用 `final` 修饰完的变量就叫常量，写法是在变量前面直接加 `final`。

    ```java
    public class FinalTest {
        final int NUMBER = 100;

        public static void main(String[] args) {
            System.out.println(NUMBER);        // 100
            System.out.println(NUMBER + 100);  // 200
        }
    }
    ```

    * 常量的使用跟变量一样，可以加减乘除，也可以直接输出打印。

    * 只能被赋值一次，一旦赋值成功就不能再改变里面的数据；试图重新赋值时程序都不用运行，直接报 `cannot assign a value`。

    * 为了跟其他变量区分开，常量的名字一般大写；有多个单词时用下划线隔开。

### 基本数据类型与引用数据类型

* 数据类型分两种：基本数据类型四类八种（`byte`、`short`、`int`、`long`、`float`、`double`、`char`、`boolean`），除此之外都是引用数据类型，比如数组、`Student`、`Teacher`。

* 基本数据类型：变量里记录的是真实的数据，`final` 修饰后不变的是变量里记录的数据本身。

* 引用数据类型：变量里记录的是对象的内存地址，`final` 修饰后不可改变的是这个地址，而对象里面的属性值还是可以改变的。

    ```java
    final Student STU = new Student("张三", 23);

    // STU = new Student();          // 报错：相当于把第二个对象的地址赋给了 STU
    STU.setName("李四");              // OK
    STU.setAge(23);                  // OK
    ```

    ```text
       STU 这个变量（final 修饰的是它本身）
       +------------------+
       |  0X0011          |   <-- 这个内存地址不可再改变
       +------------------+
                |
                v
       +-------------------------------+
       |  Student 对象                  |
       |    name   = "李四"   可以改   |
       |    age    = 23        可以改 |
       +-------------------------------+
    ```

    * > **结论**：`final` 修饰哪个变量，哪个变量里面记录的内容就无法再次改变；基本数据类型变的是数据本身，引用数据类型变的是内存地址。

### 想让属性也不变

* 在属性的前面也加上 `final`，对象里面的属性就不会再变化。

    ```java
    public class Student {
        final String name = "张三";
        final int age = 23;

        public String getName() {
            return name;
        }

        public int getAge() {
            return age;
        }
    }
    ```

    * 加了 `final` 之后 `set` 方法直接报错，与「只能赋值一次」冲突，`set` 方法要删掉。

    * 构造方法同样冲突，IDEA 认为在构造方法里也发生了修改，所以构造方法也要删掉，改成在属性定义处手动写死赋值。

    * > **易错点** ⚠️：`final` 禁止的是再次赋值，不是读取。属性被 `final` 修饰后，照样可以用对象直接点它取值，也可以通过 `get` 方法取值。

### 圆类的写法

* 描述圆的 JavaBean 有一个半径属性和一个圆周率属性，要提供计算面积与周长两个行为。

    ```java
    public class Circle {
        private double radius;
        private static final double PI = 3.14;

        public Circle() {
        }

        public Circle(double radius) {
            this.radius = radius;
        }

        public double getRadius() {
            return radius;
        }

        public void setRadius(double radius) {
            this.radius = radius;
        }

        public static double getPI() {
            return PI;
        }

        public double getArea() {
            return PI * radius * radius;
        }

        public double getLength() {
            return PI * radius * 2;
        }
    }
    ```

    * 圆周率不可能发生变化，所以用 `final` 修饰，并且名字一定要大写成 `PI`。

    * IDEA 生成构造方法时根本不会管 `PI`，生成 get and set 时即使选中 `PI` 也只生成 `get` 方法、不生成 `setPI`，这就是常量「只能赋值一次」最直观的证据。

    * 面积 $S = \pi r^2$，周长 $C = 2\pi r$，方法体里直接写 `return PI * radius * radius;` 和 `return PI * radius * 2;`。

    * > **结论**：`final` 在实际开发中的真正应用场景就是——发现一个数据它是固定的、不能变的，直接用 `final` 修饰它。

## 枚举

### 适用场景

* **枚举（enum）**

    * > **定义**：枚举也是一个特殊的 JavaBean，只不过这个类里面的对象是有限个的。

    * 用普通 JavaBean 创建对象时，创建的个数没有任何限制，可以创建无数个；但有些场景要求对象个数有限、不能多也不能少、不能自己编造，这时 JavaBean 就不合理了。

    * 订单状态只能有 6 个，如果不讲规矩，创建 60 个、600 个甚至 6000 个对象在语法上都是允许的。

* 数量有限的场景

    | 场景 | 有限的状态 |
    | :--- | :--- |
    | 电商订单 | 待支付、处理中、已发货、配送中、已送达、已取消 |
    | 月份 | 一年只有 12 个 |
    | 星期 | 一周只有 7 个 |
    | 游戏职业 | 战士、法师、弓箭手…… |
    | OA 项目会议室预约 | 空闲、已预订、申请中 |
    | 物联网设备监控 | 未开机、已启动、正常、异常 |

* 这些场景的共同点是对象个数有限，所以在这些情况下就得用枚举。

### 定义格式与枚举项

* 枚举里也有属性和行为，定义时不能��� `class`，要用 `enum` 关键字，后面跟枚举类名。

    ```text
    +--------------------------------------------------------------+
    |  enum 枚举名 {                                                |
    |                                                              |
    |      枚举项1(参数), 枚举项2(参数), 枚举项3(参数);             |
    |                                                              |
    |      // 属性                                                 |
    |      // 构造方法（必须私有化）                                |
    |      // 成员方法                                             |
    |  }                                                           |
    +--------------------------------------------------------------+
    ```

* **枚举项**

    * 枚举类对象的专业称呼，每一个枚举项就是当前枚举类的对象。

    * 限定别人能创建多少个对象的做法是：提前把所有对象创建出来，写在枚举类的第一行，对象之间用逗号隔开，最后以分号结尾。

    * 外面使用对象时不需要自己创建，直接调用即可。

    * > **注意**：程序中判断「一行代码」不是以换行为标记，而是以分号为标记；看到分号这个语句才算一行，枚举项写得再长，在编译器眼里也是一行代码。

### 从 JavaBean 改写成枚举

* 先写标准 JavaBean：一个 `name` 属性、空参构造、全参构造、`getName` 和 `setName`。

* 改成枚举一共四刀：

    | 改动 | 具体做法 | 为什么 |
    | :--- | :--- | :--- |
    | 换关键字 | `class` 改成 `enum` | 枚举不是普通类，IDEA 左边图标会变成一个紫色的 E |
    | 写枚举项 | 把创建对象那行 `Ctrl+X`、`Ctrl+V` 粘过来，取对象名作为枚举项、取小括号里的内容作为构造参数，全部写在第一行 | 提前把有限个对象全部创建出来 |
    | 删空参构造 | 删掉空参构造方法 | 统一用有参构造，空参构造没用了 |
    | 私有化有参构造并删 set | 有参构造的修饰符改成 `private`，同时删掉 `setName` | 不让外界创建对象，也不需要再修改属性值 |

* 整理后的标准枚举类

    ```java
    public enum OrderState {
        PAYMENT_PENDING("待支付"),
        PROCESSING("处理中"),
        SHIPPED("已发货"),
        OUT_FOR_DELIVERY("配送中"),
        DELIVERED("已送达"),
        CANCELLED("已取消");

        private String name;

        private OrderState(String name) {
            this.name = name;
        }

        public String getName() {
            return name;
        }
    }
    ```

* > **易错点** ⚠️：最后一个枚举项的后面一定要用分号作为结尾；嫌太长可以折行，也可以每个枚举项单独写一行，编译器只认分号。

* 构造方法写成 `public` 会直接报错，因为它与枚举的设计初衷违背——外界一旦能创建对象，个数就不再有限了。

### 取出枚举项与状态匹配

* > **结论**：所有的枚举项都默认被 `public static final` 修饰，就算没写，虚拟机也会在前面加上。

* 因为有 `public` 和 `static`，可以直接用枚举类的类名取出枚举项。

    ```java
    OrderState o1 = OrderState.PAYMENT_PENDING;

    System.out.println(o1);          // 第一个对象就打印出来了
    System.out.println(o1.getName()); // 待支付

    switch (o1) {
        case PAYMENT_PENDING:
            System.out.println("当前是待支付状态");
            break;
        case PROCESSING:
            System.out.println("当前是处理中状态");
            break;
        // 其余枚举项同理
    }
    ```

* 拿到状态之后可以用 `switch` 拿它与所有枚举项匹配，看当前订单到底是什么状态。

* 企业级项目里的通用做法就是：先获取当前订单的状态，再拿这个状态跟所有状态匹配，用 `if` 还是用 `switch` 看情况。
