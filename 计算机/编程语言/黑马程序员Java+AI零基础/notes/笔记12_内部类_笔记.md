# 内部类

## 内部类的定义与判定

* **内部类（Inner Class）**

    * > **定义**：定义在另一个类的类体内部的类；把被包住的类称为外部类，嵌在里面的称为内部类。

    * 判定规则：内部类表示的事物是外部类的一部分。
    * 判定规则：内部类单独存在没有实际意义，必须依赖外部类才能存在。
    * 只有同时满足这两条才写进外部类内部，"有点关系"的类不能作为判据。

* **汽车与发动机的取舍**

    * 把发动机的品牌、使用年限直接平铺进汽车类不合适：发动机是一个独立个体，与车本身有区别。
    * 把发动机单独抽成一个顶级类也不够：发动机需要依赖车才能存在，单独出现没有实际意义。
    * 写在汽车的类体内部同时满足两点：表示车里面有发动机，且发动机仍是独立个体。
    * 落地形态：外部类 `Car` 持品牌、车龄、颜色三个属性，内部类 `Engine` 持发动机品牌与使用年限。

## 内部类的四种分类

* **四种分类**

    | 分类 | 写在哪里、怎么写 |
    | :--- | :--- |
    | 成员内部类 | 写在成员位置（类中方法外），不加 `static` |
    | 静态内部类 | 写在成员位置，加 `static` 修饰 |
    | 局部内部类 | 写在方法里面 |
    | 匿名内部类 | 没有名字的内部类 |

    * 成员内部类与匿名内部类是主体内容，静态内部类与局部内部类了解形态即可。
    * 匿名内部类是 lambda 表达式的前提，lambda 表达式又是方法引用的前提。

## 成员内部类

* **成员内部类（Member Inner Class）**

    * > **定义**：写在成员位置（类中方法外）、不带 `static` 的内部类，属于外部类的成员之一。

    * 地位与外部类的成员变量、成员方法完全一致，因此同样可以被修饰符修饰。
    * 一旦给它加上 `static`，它就不再是成员内部类，而变成静态内部类。

* **五种修饰符的可见范围**

    | 修饰符 | 能否在外部直接创建成员内部类的对象 |
    | :--- | :--- |
    | `private` | 不能，只能在外部类本类里创建 |
    | 默认 | 只能在同一个包中创建 |
    | `protected` | 本包中 + 其他包的子类中 |
    | `public` | 所有地方都行 |
    | `static` | 此时它不算成员内部类，叫静态内部类 |

    * `private`：外部测试类直接创建对象会报错，只能回到外部类内部创建；与私有成员变量只能在本类访问是同一个道理。
    * 默认权限：同包可直接创建；换到别的包（如另建的 `test` 包）写测试类就报错。
    * `protected`：本包中可用，其他包的子类中可用。
    * `public`：任何地方都能直接创建内部类对象。

* **成员内部类里的静态成员**

    * > **易错点**：成员内部类中 JDK16 以前不允许定义静态变量，JDK16 开始才可以。

    * 把编译语言级别切到 15，`static int a` 立即报红，提示 language level 15 不支持 inner class 中的 static。
    * 切回 SDK default 后错误消失；编译与运行的版本必须小于等于已安装的 JDK 版本。
    * 项目结构面板上方的 `SDK` 表示项目安装的 JDK 版本，下方选项决定用哪个版本编译与运行。
    * 这类细节不必背，报错时知道怎么改即可。

## 获取成员内部类的对象

### 创建格式与推导

* **创建语句**

    * > **结论**：成员内部类的地位与成员变量、成员方法一模一样，所以必须通过外部类的对象去创建。

    ```java
    Outer.Inner oi = new Outer().new Inner();
    ```

    * 等号左边是数据类型：`Inner` 前面加 `Outer.` 限定，表示外部类中的那个内部类。
    * 等号右边的 `new Outer()` 得到外部类对象，它是调用者，负责调用后面那个内部类对象。
    * 等号右边的 `.new Inner()` 才是真正创建出来的内部类对象，其地址值赋给左边的变量。
    * 推导过程与推导"先 `new` 一个 `Outer` 对象、再访问它的成员变量"完全同构；先有外部类对象再点 `new` 的链式写法也成立。
    * 调用侧同样要先拿对象再调方法。

    ```java
    Outer.Inner oi = new Outer().new Inner();
    oi.show();
    ```

* **被 `private` 修饰后的两条出路**

    * > **易错点**：内部类一旦被 `private` 修饰，外界就不能直接创建它的对象。

    * 出路一：在外部类中编写方法，对外提供内部类的对象。

    ```java
    public class Outer {
        private class Inner {
        }

        public Inner getInstance() {
            return new Inner();
        }
    }
    ```

    * 外界先创建外部类对象，再用该对象调用这个方法拿到内部类对象。
    * 左侧类型不能再写 `Outer.Inner`，因为外界根本不知道 `Outer` 里存在私有的 `Inner`。
    * 办法一：用父类类型接收形成多态；`Inner` 没写 `extends` 时默认继承 `Object`。

    ```java
    Outer o = new Outer();
    Object oi = o.getInstance();
    ```

    * 办法二：左侧不用变量接，直接使用方法返回的对象。

### 两种方式的适用与实例

* **选型规则**

    * 内部类被 `private` 修饰时，用"外部类方法对外提供对象"的方式。
    * 内部类被默认、`protected`、`public` 等非私有修饰符修饰时，直接创建对象。
    * 工程实例：`ArrayList` 的内部类 `ITR` 外界拿不到，靠的是外部类提供的 `iterator()` 方法。
    * 该方法返回的类型不是 `ITR`，而是它实现的接口类型，接收方用接口类型接，等同于多态。

    ```java
    public Iterator<E> iterator() {
        return new ITR();
    }
    ```

* **类名里的美元符**

    * Java 在底层用 `$` 区分外部类名与内部类名：`$` 左边是外部类名，右边是内部类名，编译产物形如 `Outer$Inner`。
    * > **易错点**：⚠️ 自己起名时不要用下划线（那是常量的位置）和 `$`（那是内部类的位置），避免与编译器生成的类名撞车。

## 外部类成员变量重名的访问

### 三级作用域

* **同名变量的取用**

    * > **结论**：取外部类成员变量用 `Outer.this.变量名`，取内部类自己的成员变量用 `this.变量名`，直接写变量名触发就近原则，拿到的是局部变量。

    ```java
    public class Outer {
        int a = 10;              // 外部类的成员变量

        class Inner {
            int a = 20;          // 内部类的成员变量

            public void show() {
                int a = 30;      // 局部变量

                System.out.println(Outer.this.a);   // 10 —— 外部类
                System.out.println(this.a);        // 20 —— 内部类
                System.out.println(a);             // 30 —— 局部变量
            }
        }
    }
    ```

    * 没有重名时直接写变量名即可，打印出的就是外部类成员的 `a`。
    * 直接写 `a`：先在本方法内查找，命中局部变量，得 `30`。
    * 写 `this.a`：跳过方法这一层作用域，命中内部类成员变量，得 `20`。
    * 写 `Outer.this.a`：命中外部类成员变量，得 `10`。

* **为什么这里用不了 `super`**

    * > **易错点**：`Inner` 与 `Outer` 之间是包含关系而不是继承关系，继承必须在类后面写 `extends`。

    * `super` 表示父类，外部类并不是内部类的父类。
    * 类比：汽车不是发动机的"爹"，人也不是心脏的"爹"。
    * 正确写法是 `Outer.this.a`，取到的正是外部类的成员变量。

### 内存模型与 `Outer.this` 的含义

* **内存里发生了什么**

    * 外部类与内部类在内存中是两个独立的字节码文件，编译后得到 `Outer.class` 与 `Outer$Inner.class`。
    * 执行 `Outer.Inner oi = new Outer().new Inner();`：`new Outer()` 在堆中创建外部类对象并记录 `a = 10`；`.new Inner()` 再次在堆中开辟内部类对象并记录 `a = 20`。
    * 虚拟机给内部类对象自动加一个隐藏成员变量 `this$0`，类型是外部类且被 `final` 修饰，记录外部类对象的地址值。
    * 左边变量记录的是内部类对象的地址而不是外部类对象的地址——类型写的是 `Outer.Inner`。
    * 用 `oi` 调用 `show()` 时，方法里的 `this` 记录调用者 `oi` 的地址，也就是内部类对象。

    ```text
    堆内存
    ┌────────────────┐      ┌───────────────────────────────────────────┐
    │ 001: Outer     │      │ 002: Inner                               │
    │                │◀─────│                                           │
    │   int a = 10   │      │   int a = 20                              │
    │                │      │   final Outer this$0 ── 记录 001 的地址    │
    └────────────────┘      └───────────────────────────────────────────┘

    栈内存
    ┌───────────────────────────────────────────────────────────────┐
    │ main()                                                         │
    │   Outer.Inner oi = 002         // 只记内部类对象的地址         │
    ├───────────────────────────────────────────────────────────────┤
    │ show()   this = 002             // 方法的调用者是 oi           │
    │   int a = 30                    // 局部变量                    │
    └───────────────────────────────────────────────────────────────┘
    ```

    * 打印 `a`：就近原则在本方法内命中局部变量。
    * 打印 `this.a`：等价于打印内部类对象里的 `a`。
    * 打印 `Outer.this.a`：先通过内部类对象自己的 `this` 找到外部类对象，再取它的 `a`。

* **`Outer.this` 的真实含义**

    * `Outer.this` 就是"获取到了外部类对象的地址值"，用外部类对象去取成员，得到的自然是外部类成员变量的值。
    * 验证思路：让程序停在键盘录入处不退出，先用 `jps` 拿到进程 id，再用内存分析工具连接该进程。
    * 在类的浏览器中输入外部类名，可列出 `Outer` 与 `Outer$Inner` 两个字节码文件。
    * 查看 `Outer$Inner` 的 `fields`：除了自己写的 `private int a`，还有一个虚拟机自动添加的 `final` 成员变量，类型是外部类的全限定名，名字写作 `this$0`，与源码里的 `this` 区分开。
    * 与以往不同的地方就在这一点：内部类对象里多了一个隐藏的 `this`，专门记录外部类对象的地址。

## 静态内部类

* **静态内部类（Static Inner Class）**

    * > **定义**：成员内部类前面加上 `static` 关键字，它本身就是成员内部类的一种。

    * 不写 `static` 就退化成前面那个成员内部类，唯一差别就是这个关键字。

* **只能访问外部类中的静态成员**

    * > **易错点**：静态内部类中只能访问外部类的静态变量和静态方法。

    ```java
    class Outer {
        int a = 10;
        static int b = 20;

        static class Inner {
            public void show() {
                System.out.println(b);   // 静态变量，直接访问，OK

                // System.out.println(a);   // 非静态变量，直接访问，编译报错

                // 想访问 a，就得先造一个外部类的对象出来
                Outer outer = new Outer();
                System.out.println(outer.a);   // 这样才可以
            }

            public static void show2() {
                System.out.println(b);        // 静态方法里访问静态变量，一样可以
                // System.out.println(a);     // 静态方法里访问非静态变量，照样报错
            }
        }
    }
    ```

    * 依据仍是"静态只能访问静态"这条老规矩：在外部类的静态方法里访问非静态成员变量同样不行。
    * 唯一的出路是先创建外部类对象，再用这个对象访问非静态成员。
    * 静态内部类的静态方法与非静态方法受同一条限制约束，`show2()` 里访问 `a` 一样报错。

* **创建对象与调用方法**

    * > **结论**：只要是静态的东西，都可以用「类名 + 点」直接拿到。

    ```java
    class InnerClassDemo4 {
        public static void main(String[] args) {
            // 创建静态内部类的对象
            Outer.Inner oi = new Outer.Inner();

            // 调用里面的非静态方法：必须先有对象，再用对象去调
            oi.show();

            // 调用里面的静态方法：不需要创建对象，类名一路点到底
            Outer.Inner.show2();
        }
    }
    ```

    * 左侧 `Outer.Inner` 是类型名，作用相当于给对象起名字。
    * > **易错点**：⚠️ `new` 的不是 `Outer` 这个对象，`new` 的是 `Outer` 里面 `Inner` 类的对象。
    * 调用非静态方法必须有对象，用 `oi.show()`。
    * 用对象调用静态方法运行时不会出错，但不提倡，IDEA 不给这类提示；规范写法是 `Outer.Inner.show2()`，无需创建对象。

## 局部内部类

### 地位与修饰符

* **局部内部类（Local Class）**

    * > **定义**：定义在方法体内部的类，地位与方法里的局部变量一模一样。

    * 前提是必须先有方法，没有方法就无处书写。
    * 写法上与静态内部类只差一个 `static`，性质上已经完全不同。

* **修饰符跟着局部变量走**

    * > **结论**：能修饰局部变量的修饰符都可以修饰局部内部类，不能修饰局部变量的就一定不能修饰局部内部类。

    * `final` 能修饰局部变量（修饰完就变成常量），因此也能修饰局部内部类。
    * `public`、`protected`、默认访问权限、`private` 只能修饰成员，局部变量接受不了，把它们写在局部内部类前面同样报错。

### 使用规则

* **外界无法直接使用**

    * 外界不能直接使用方法里的局部变量，同理也不能直接使用方法里定义的局部内部类。
    * 对比：`o.a` 里的 `a` 表示成员变量 `a`，并不表示方法里的局部变量 `a`。
    * 用法：只能在方法里面创建局部内部类的对象。

    ```java
    class Outer {
        public void show() {
            int a = 10;

            class Inner {                       // 局部内部类：写在方法里面
                String name;
                int h;

                public void method1() {
                    System.out.println("局部内部类中的method1方法");
                }

                public static void method2() {
                    System.out.println("局部内部类中的method2静态方法");
                }
            }

            // 只能在方法里面创建局部内部类的对象
            Inner i = new Inner();

            // 有了对象，就能访问里面所有的成员
            System.out.println(i.name);         // 默认值 null
            System.out.println(i.h);            // int 类型，默认值 0

            i.method1();                        // 非静态方法，用对象调
            Inner.method2();                    // 静态方法，用类名调
        }
    }
    ```

    * 测试类入口：创建外部类对象，再用对象调用那个方法。

    ```java
    class InnerClassDemo5 {
        public static void main(String[] args) {
            Outer o = new Outer();
            o.show();
        }
    }
    ```

    * 对象里未赋值的成员按类型取默认值：`String` 为 `null`，`int` 为 `0`。

* **可访问的范围**

    * 局部内部类可以直接访问外部类的成员。
    * 局部内部类也可以直接访问定义它的方法里的局部变量。
    * 前面的代码已经演示：方法一进来先定义 `int a = 10`，紧接着定义的内部类方法里可以直接拿到它。
    * 这个形态的实用价值有限，知道它的存在与基本写法即可。

## 匿名内部类

### 动机与格式

* **匿名内部类（Anonymous Class）**

    * > **定义**：没有名字的内部类，写在成员位置或写在局部位置都可以。

    * > **结论**：它的作用是让我们少定义一个 java 文件，仅此而已。

    * 触发场景是继承一个类或实现一个接口、且这个子类或实现类只用一次的时候。
    * 它是 lambda 表达式的前置知识点，这个格式不熟，lambda 就学不明白。

* **先看传统写法的问题**

    * 方法 `goSwimming()` 接收 `Swim` 类型的参数，所以调用它需要传一个 `Swim` 接口的实现类对象。
    * 传统步骤：新建一个类让它实现 `Swim` 并重写抽象方法；测试类中创建它的对象；再把对象传进去。

    ```java
    interface Swim {
        void swim();
    }

    // 单独一个文件里放实现类
    class Student implements Swim {
        @Override
        public void swim() {
            System.out.println("学生正在游泳");
        }
    }
    ```

    ```java
    class Test {
        public static void main(String[] args) {
            Student s = new Student();
            goSwimming(s);
        }

        public static void goSwimming(Swim s) {
            s.swim();
        }
    }
    ```

    * 问题在于这个实现类只用一次，为它单独新建一个文件显得浪费；不要文件、只要里面的代码，匿名内部类由此产生。

* **格式的四个组成部分**

    * > **定义**：格式为 `new 类名或接口名 ( ) { }`，大括号中重写类或接口里的抽象方法。

    ```java
    new Swim() {
        @Override
        public void swim() {
            System.out.println("学生正在游泳");
        }
    }
    ```

    ```text
            new   Swim    ( )   {  @Override public void swim(){ ... }  }
             ④      ②      ─┬─   └────────────── ① ──────────────────────┘
              │      │      │                   │
              │      │      │                   └─ ③ 在大括号里重写接口/类里的抽象方法
              │      │      └─ 构造方法的括号；接口没有构造方法，这里是空的
              │      └─ ② 继承或实现关系：前面写类名→继承，写接口名→实现
              └─ ④ 创建对象：new 的是后面那个没有名字的类，不是接口本身

            整体理解：一个「没有名字的 java 类」的对象
    ```

    * ① 就是后面那个大括号，代表一个没有名字的 java 类；因为它写在别的类里面，所以才是内部类。
    * ② 继承或实现关系：前面写类名就是继承，写接口名就是实现。
    * ③ 重写方法：接口里的抽象方法必须全部重写，不是只写一个；漏掉任何一个立刻报红波浪线，全部写完红波浪线消失。
    * ④ 就是前面的 `new` 关键字。

### 两种写法与使用时机

* **两种写法**

    * 写法一：整个匿名内部类直接写在方法调用的参数位置里。

    ```java
    class Test {
        public static void main(String[] args) {
            goSwimming(new Swim() {
                @Override
                public void swim() {
                    System.out.println("学生正在游泳");
                }
            });
        }

        public static void goSwimming(Swim s) {
            s.swim();
        }
    }
    ```

    * 写法二：赋值给接口类型变量，结尾要加分号，之后用这个引用去调用或传参。
    * 这一行与 `Swim s = new Student();` 同构：实现类对象赋给接口类型，这就是多态。

    ```java
    class Test {
        public static void main(String[] args) {
            Swim s = new Swim() {
                @Override
                public void swim() {
                    System.out.println("学生正在游泳");
                }
            };

            goSwimming(s);
        }

        public static void goSwimming(Swim s) {
            s.swim();
        }
    }
    ```

    * > **易错点**：⚠️ 这个 `new` 创建的不是 `Swim` 接口本身，而是后面那个没有名字的类的对象。

* **使用时机**

    * 判断标准只有一条：子类或实现类只用一次、不想再新建一个 java 文件时才用它。
    * "每次都新建文件"并不意味着永远遇不到它——lambda 表达式在开发中大量使用这种写法。
    * 这个格式至少要默写到不用想，lambda 学起来才轻松。
