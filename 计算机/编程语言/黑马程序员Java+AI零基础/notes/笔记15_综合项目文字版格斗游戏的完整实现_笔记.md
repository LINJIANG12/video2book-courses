# 综合项目：文字版格斗游戏的完整实现

## 项目定位与构成

* **文字版格斗游戏**
    * 纯控制台的回合制文字 RPG，没有画面，全靠控制台输出。
    * 进场第一眼是登录注册页面，给出三个选择：1 登录、2 注册、3 退出。
    * 登录成功之后才启动游戏，角色的名字直接沿用登录时用的那个用户名。
    * 规模是 4 个类 + 2 个界面，连代码带注释约 700 到 800 行。
    * 行数口径有两套：登录注册页面约 260 行（login 方法加 User 类不到 400 行），游戏主界面约 310 行（终稿口径为游戏类约 410 行、登录类约 305 行）。
    * 真正难的不是里面的知识点，而是游戏整体的业务逻辑；知识点谁都会，业务串联起来才是分水岭。

## 需求文档与游戏流程

* **需求文档（Requirements Document）**

* **游戏四大系统**

    | 系统 | 它要解决的问题 |
    | --- | :--- |
    | 角色创建与属性分配 | 我方控制谁、敌人有几个、手上的点数怎么分 |
    | 回合制战斗系统 | 打一下之后发生什么，什么时候算结束 |

    * 胜场累积在代码里只要一个变量，赢一场加一。

* **开局五步**
    * 显示游戏标题（欢迎语里带登录用户名） → 创建玩家角色并分配 20 点属性 → 打印初始属性与技能列表 → 从敌人列表随机取一个 → 进入回合制战斗。
    * 我方三个技能固定：普通攻击、强力一击、生命回复。

## 包结构与启动类

* **包划分**
    * `com.itheima.ui`：页面类，`ui` 就是界面的意思，放 Login 与 FightingGame。
    * `com.itheima.domain`：JavaBean 类。看到 `bean` 或 `domain` 这样的包名，就知道里面装的是 JavaBean。

```java
public class App {

        Login l = new Login();
        l.start();

}
```

    * 为了测游戏部分提速，可以先把登录流程注释掉，直接在 main 里创建 FightingGame 并传一个用户名进去调 gameStart；全部写完再删掉临时代码、放回登录入口。

## 登录注册主页面

* **start 方法的骨架**
    * 页面内容直接从需求文档 `Ctrl+C` / `Ctrl+V` 粘贴，不用自己写。
    * 内容就两块：提示文字 + 用户选择，用 Scanner 录入到 `choose`，再交给 switch 分派。
    * 用 `Ctrl + Alt + T` 给整段选中的代码套一层 `while (true)`——没有循环的话页面只能执行一遍，而登录可能要做两三次、注册要反复注册多个账号。
    * Scanner 声明在循环外面，整个页面共用一个。

* **switch 的箭头写法**
    * `case "1" -> login();` 是 JDK 12 起的新特性。
    * 传统写法后面不写箭头时必须补 `break`，否则会引发 case 穿透。
    * 两种写法不能混用：要么全用箭头，要么全用传统写法。
    * `default` 处理非法输入，提示"再见，或者输入有误，请重新输入"。

* **System.exit(int)**
    * 类名 `System` 里定义的都是与系统相关的方法，`exit` 是 static 的，可以用类名直接调用。
    * 参数写 `0` 表示程序正常停止；写非 0（123、456、789、10 等任何不是 0 的值）表示程序异常终止。
    * 虚拟机一旦停止，里面还有什么方法、循环、代码都不会再往下走。

```java
case "3" -> {
    System.out.println("用户选择了退出操作");
    System.exit(0);
}
```

* **主页面只分发，方法里只放业务**
    * 所有代码挤在一个 switch 里会非常臃肿，出问题也没法改，所以抽出 `login()` 和 `register()` 两个成员方法承接全部业务，switch 里只留一行调用。
    * 退出只有两行代码，可以写在 `case "3"` 里，也可以单独定义方法。

* **登录注册的四条规则**
    * 登录成功之后才去启动游戏。
    * 注册时每个属性都要满足要求，额外一条：密码要输两次，两次一致才算注册成功。
    * 登录的步骤是键盘录用户名、录密码、录验证码，且三者都要符合题目要求。
    * 登录时密码最多重试三次，三次都错则账户直接锁定。

## User 类

* **四个属性**
    * `id`、`username`、`password`、`state`，一个都不能少。
    * `id` 用 `String` 而不是 `Integer`：格式是"黑马"加五个数字，整数装不下。
    * `state` 用 `boolean` 而不是 `int`：只有可用与禁用两个取值，天然是布尔量。
    * 生成空参构造、带全部参数的构造，并为每个私有化成员变量生成 getter/setter；boolean 的 getter 命名为 `isXxx`。

* **属性规则**

    | 属性 | 规则 | 能否由用户设置 |
    | --- | --- | :--- |
    | id | 固定前缀"黑马" + 5 位随机数字 | 否，系统自动生成 |
    | username | 唯一、长度在区间内、只能字母数字且不能纯数字 | 是 |
    | password | 长度在区间内、必须字母加数字的组合 | 是 |
    | state | true 可用、false 禁用 | 密码连错三次自动置 false |

    * 长度区间有两套口径：需求文档最初给出用户名 3~6、密码 6~12；实现阶段最终采用的是用户名 3~16、密码 3~8。
    * 用户名允许纯字母，密码不允许纯字母——两者最容易忽略的差别就在这。

* **id 不能用 Scanner 录入**
    * 用户无法设置 id，由系统在代码里自动生成，所以要用 Random 而不是键盘输入。
    * StringBuilder 先 append "黑马"，Random 循环五次 `nextInt(10)` 把 0~9 的数字逐个追加进去。

```java
public String createId() {
    StringBuilder sb = new StringBuilder();
    sb.append("黑马");
    Random r = new Random();
    for (int i = 0; i < 5; i++) {
        int n = r.nextInt(10);
        sb.append(n);
    }
    return sb.toString();
}
```

    * return 之前必须调 `toString`：sb 是 StringBuilder，不是字符串。
    * 空参构造里写 `this.id = createId()`，创建对象时形参不再接收 id。

* **state 的默认值必须手动改**
    * 成员变量的默认值：byte/short/int/long 是 0，float/double 是 0.0，boolean 是 false。
    * `false` 这个默认值在这里不能用——它表示账户被禁用，刚注册的账户一上来就被禁用不合理；默认必须是 `true`。
    * 有参构造同理，形参只给 username 和 password，id 与 state 在构造里自己生成、自己赋值。

* **用户名的合规判定**

    | 用户名 | 是否合规 | 原因 |
    | --- | --- | :--- |
    | 张三 | 合规 | 字母组成，不是纯数字 |
    | 12345 | 不合规 | 纯数字 |
    | 张3123 | 合规 | 字母 + 数字 |
    | 张3123at | 不合规 | 混进了第三个字符 |

* **密码的合规判定**
    * 字母至少一个、数字至少一个、其他字符一定不能有，所以纯字母的 `abcdefg` 不合规，`abcdefg123` 才合规。
    * 与用户名唯一的差别在数字那一条：用户名数字可以有也可以没有，密码数字至少要有一个。

* **集合的选型与位置**
    * 容器用 `ArrayList<User>` 而不是数组：集合包含数组的所有特点，而且长度可长可短，不需要提前关心长度。
    * 集合必须定义在循环外面。写在循环里的话每次循环都会新建一个集合，注册用一个、登录又用另一个，两边就操作不到同一份数据。
    * 再把集合作为形参传给 register 与 login，保证两边操作的是同一个集合。

## 注册业务

* **注册与登录的分岔**
    * 注册：键盘录入 → 本地校验格式 → 校验唯一 → 封装 User 放进集合 → 提示成功。
    * 登录：键盘录入 → 本地校验格式 → 拿用户名密码去比对 → 存在则成功，不存在则失败。
    * 输入段几乎一样，分岔只发生在最后：注册是往里写，登录是拿出来查。
    * 先写注册——登录需要已有数据；硬要先写登录就得预先往容器里塞测试数据。

* **register 的五步骨架**
    * ① `new User()` 用空参构造先造一个空对象，等会儿往里面填数据。
    * ② new Scanner，负责键盘录入。
    * ③ 校验用户名，通过后 `u.setUsername(username)`。
    * ④ 校验密码，通过后 `u.setPassword(password1)`。
    * ⑤ `list.add(u)` 添加到集合，并提示注册成功。

* **校验的顺序标准**
    * 先验格式、再验唯一：格式校验在本地用代码就能做完不耗时，唯一性要联网查数据库，先简单再难。
    * 先判异常数据、剩下的自然合法：这样才能避免大量 if 嵌套，史山代码就是这么形成的。
    * 用户名的三条校验按长度 → 内容 → 唯一的顺序排。

* **checkLn(int minLen, int maxLen, String str)**
    * 判断字符串长度是否落在指定区间：`str.length() >= minLen && str.length() <= maxLen`。
    * 结果就是一个布尔，直接 return 布尔表达式，不要写成 `if (...) return true; else return false;`。
    * 三个形参：最小长度、最大长度、待判字符串。用户名和密码都要用，所以抽成方法复用。

* **getCount(String userInfo)**
    * 遍历字符串统计字母数、数字数、其他字符数，返回长度为 3 的 int 数组。
    * 下标 0 是字母个数，1 是数字个数，2 是其他字符个数。
    * 判定字符类别直接比较字符区间：`(c >= 'a' && c <= 'z') || (c >= 'A' && c <= 'Z')` 算字母，`c >= '0' && c <= '9'` 算数字，else 算其他。
    * Java 没有返回多个值的语法，要返回多个数据就把它们装进容器再把容器返回。

* **checkUsername 与 checkPassword**

```java
public boolean checkUsername(String username) {
    int[] arr = getCount(username);
    return arr[0] > 0 && arr[1] >= 0 && arr[2] == 0;
}

public boolean checkPassword(String password) {
    int[] arr = getCount(password);
    return arr[0] > 0 && arr[1] > 0 && arr[2] == 0;
}
```

    * 两个方法只有中间那一项不同：数字从"可以有也可以没有"变成"至少一个"。
    * 用户名里 `arr[1] >= 0` 天然成立，对应的正是"数字不是强制要求"。
    * 统计代码能复用、判定条件不能复用，所以只把统计那段抽成 getCount。

* **contains(ArrayList<User> list, String username)**
    * 遍历集合比对用户名，命中立刻 `return true`，循环走完还没找到才 `return false`。
    * 调用处是 `if (contains(list, username))` 直接进 if 提示"当前的用户名已经存在"，不取反——"已存在"本身就是异常数据。
    * 能顺利执行到 setUsername 那一行，意味着长度符合、内容符合、且用户名唯一。

* **三道密码校验**
    * 长度 `checkLn(3, 8, password1)`、内容 `checkPassword(password1)`、两次一致 `!password1.equals(password2)`。
    * 三道都写在 while 循环里，不合格就 `continue` 回到录入，三道全过才 `setPassword` 再 `break`。
    * 长度校验传 password1 或 password2 都可以，反正后面还要判两次是否一致。
    * 先校验内容再校验两次一致，所以提示"密码只能是字母加数字的组合"会先出现。

## 验证码

* **验证码规则**
    * 长度 5；四位大写或小写字母 + 一个数字；同一个字母可以重复出现；数字可以出现在任意位置。
    * `AQAEK` 是合法样例：A 出现两次，数字落在第一个位置上。
    * 字母可重复意味着不需要判重、不需要 Set，直接重复抽四次不会冲突。
    * "数字可以出现在任意位置"最容易被追问，把数字固定拼在末尾虽然能跑通演示，但不满足需求。

* **getCode() 的五步**
    * 建集合装 52 个字母：`for` 循环 26 次，每次 add `(char)('a'+i)` 和 `(char)('A'+i)`。
    * `nextInt(list.size())` 抽 4 个字母，追加进 StringBuilder。
    * `sb.append(r.nextInt(10))` 补一位 0~9 的随机数字。
    * `sb.toString().toCharArray()` 转成字符数组，把最大索引上的字符与随机索引上的字符交换。
    * `new String(arr)` 转回字符串返回。

```java
public static String getCode() {
    ArrayList<Character> list = new ArrayList<>();
    for (int i = 0; i < 26; i++) {
        list.add((char) ('a' + i));
        list.add((char) ('A' + i));
    }
    Random r = new Random();
    StringBuilder sb = new StringBuilder();
    for (int i = 0; i < 4; i++) {
        int index = r.nextInt(list.size());
        char c = list.get(index);
        sb.append(c);
    }
    sb.append(r.nextInt(10));
    char[] arr = sb.toString().toCharArray();
    int index = r.nextInt(arr.length);
    char temp = arr[index];
    arr[index] = arr[arr.length - 1];
    arr[arr.length - 1] = temp;
    return new String(arr);
}
```

* **泛型与装箱**
    * 集合的泛型里不能写 char——泛型参数只能是引用类型，char 是基本数据类型，要存字符必须写包装类 `Character`。
    * add 时可以直接传 char 字面量，Java 会自动装箱成 `Character` 对象，不用手写转换。
    * `nextInt(list.size())` 取的是集合索引，边界是 0~51。

> **易错点**：交换位置时最大索引不要写死成 `4`。写死只在长度固定为 5 时成立，写成 `arr.length - 1` 才在任何长度下都拿得到最大索引。
>
> **易错点**：调 `toCharArray()` 的是 `sb.toString()` 的结果，不是 sb 本身。链式调用写错对象会直接编译报错。

* **调用顺序与比较方式**
    * 先调 getCode() 生成正确验证码并打印出来，再提示用户录入，最后拿两个比较——没有正确的验证码，用户根本不知道该输什么。
    * 比较用 `equalsIgnoreCase`，验证码大小写无所谓，用户手抖打成小写就判失败是很糟的体验。
    * 输错必须既换一个新验证码又让用户重新输入，只换不录或只录不换都不行。
    * 用 `while (true)` 包住这一段，输对 `break`、输错 `continue`，这时 break/continue 的作用域正好就是这个循环。
    * 验证码写完可以作为独立小业务单独成类，验证通过后再整个方法剪切粘贴到登录注册页面里。

## 登录业务

* **登录判断链**
    * 顺序是用户名 → 账号状态 → 验证码 → 密码；前三层都是异常分支，只有最后一层是正常分支。
    * 用户名不存在：提示当前用户名未注册请先注册，`return`。
    * 用户名已存在但被锁定：提示已被禁用请联系客服，`return`。
    * 两个异常都排掉之后才轮到验证码，最后才是密码。
    * 不能照着需求文档的录入顺序先让输密码——账号根本没注册，让用户先输密码再告诉他账号不存在是在耍人玩。

* **findIndex(ArrayList<User> list, String username)**
    * 遍历集合返回用户名所在索引，走完还没找到返回 -1。
    * 与 contains 是一家人：contains 判断在不在，findIndex 判断在第几个。
    * 状态和密码都存在对象里，只知道用户名三个字没用，必须先 `User u = list.get(index)` 拿到整个对象，后续判断全挂在 u 上。
    * 判断状态用 `if (!u.isState())`，少一个叹号逻辑就整个反过来。

* **三种跳转关键字的分工**
    * 不在循环里、要结束整个登录方法让用户回到选择界面，只能用 `return`。
    * `break` 只跳出当前循环、`continue` 只跳过本次迭代，它们都在循环内部用，在登录方法这个位置根本达不到效果。

* **三次机会与锁定**

```java
for (int i = 0; i < 3; i++) {
    System.out.print("请输入密码：");
    String password = sc.nextLine();
    // 这里还要重新走一遍完整的验证码校验
    String rightPassword = u.getPassword();
    if (rightPassword.equals(password)) {
        System.out.println("登录成功，游戏启动");
        break;
    } else {
        System.out.println("登录失败，密码输入错误");
        if (i == 2) {
            u.setState(false);
            System.out.println("当前账号" + username + "已锁定，请联系客服");
            return;
        } else {
            System.out.println("密码错误，你还剩下" + (2 - i) + "次机会");
        }
    }
}
```

    * for 循环要包的范围比想象的大：键盘录入密码和整段验证码校验都要放进去，每一次验密码都得先过一次验证码，这才是验证码存在的意义。
    * 密码比较用 `equals`，大小写必须完全一致；验证码才用 `equalsIgnoreCase`。
    * 剩余次数是 `2 - i` 不是 `3 - i`，因为 i 从 0 开始；`i == 2` 那一轮输错即三次用完，直接 `setState(false)` 锁死并 return。
    * 所谓锁定就是把 state 置为 false，没有别的花活；锁死之后再登录，状态层直接拦下，连密码和验证码都不让碰。

* **代码定位快捷键**
    * `Ctrl + Alt + T`：把选中的语句用 if / 循环包裹。
    * `Ctrl + F12`：列出当前类所有方法，双击跳转。
    * Ctrl + 点击方法名直接跳到定义；`Ctrl + Alt + L` 格式化；`Ctrl + Alt + V` 自动生成左边的变量名。
    * 方法名不知道起什么，AI 插件会按注释自动生成，直接调用就行。

## 角色属性与继承结构

### 属性分析

* **角色名字与属性点**
    * 角色名不需要用户输入，直接就是登录时用的用户名。
    * 属性 = 初始属性 + 分配点数 × 比例；生命值的比例是 10，即一个属性点折算 10 点生命。
    * 20 个初始属性点全部分配到生命值、攻击力、防御力三项。

* **hp 与 maxHp 必须是两个属性**
    * hp 记当前血量，maxHp 记最大血量。
    * 每胜三场加的 30 点加的是上限，不是直接砸到当前血量上。
    * 回血有封顶：当前 150、上限 200 时回 100 点也只能到 200。少了 maxHp 封顶没法写，少了 hp 加血扣血都无从谈起。

* **技能：一个用集合，一个用变量**
    * 我方三个技能用 `ArrayList<String>` 表示，玩家那侧是"技能列表"。
    * 敌方每种只有一个技能，用 `String skill` 变量表示就够，集合纯属浪费。

* **defending 属性**
    * 重装坦克的防御姿态是给自己加的减伤 Buff，不是伤害技能。
    * 怎么知道当前敌人有没有挂上 Buff：给敌人加一个 `boolean defending`，true 表示身上有减伤状态，false 表示没有。

### 继承骨架

```text
                 Character（游戏人物）
    name | hp | maxHp | attack | defense
    isAlive()  heal()  takeDamage()  show()
             /                  \
            /                    \
  HeroCharacter               EnemyCharacter
 skillList : ArrayList<String>   skill : String
   （我方，3 个技能）            defending : boolean
                                （敌方，1 个技能 + 减伤 Buff）
```

* **父类的属性与构造**
    * 五个属性 `name` / `hp` / `maxHp` / `attack` / `defense`，两个子类都能用，所以往上抽。
    * 有参构造只接收一个 hp，同时赋给当前生命和最大生命——人物刚创建时血量是满的，一行 `this.hp = this.maxHp = hp` 搞定。
    * 角色类的成员变量直接写成 public，不逐个生成 getter/setter，调用时直接点出来，写起来简洁。

* **父类的四个行为**

```java
public boolean isAlive() {
    return hp > 0;
}

public void heal(int amount) {
    hp += amount;
    if (hp > maxHp) {
        hp = maxHp;
    }
}

public void takeDamage(int damage) {
    hp -= damage;
    if (hp < 0) {
        hp = 0;
    }
}

public void show() {
    // 打印姓名、当前生命值、攻击力、防御力四行
}
```

    * isAlive 大于零就是存活，打完一边就要用它判断另一边，所以放父类。
    * heal 的形参 amount 表示这次回了多少血，由调用方提供；回完超过上限就截断到上限。
    * takeDamage 减完血如果小于零就强制置零，游戏里人物的血量不可能是负数。
    * show 只展示姓名、当前生命、攻击力、防御力四项，技能和状态不打印；可以给它加 String 返回值，外面直接拼进字符串里一起打印。
    * 回血写在父类是给后面的版本铺路——下一版完全可能出现带回血技能的角色，提前把能力铺好省得改继承结构。

* **EnemyCharacter 重写 takeDamage**

```java
@Override
public void takeDamage(int damage) {
    if (defending) {
        damage = Math.max(1, damage / 2);
    }
    super.takeDamage(damage);
    this.defending = false;
}
```

    * 扣血这段跟父类一模一样，直接 super 调用；子类只负责算出真正要扣的伤害值。
    * 防御姿态只能持续一个回合：这一回合减完伤立刻把标记撤掉，下一回合不好使。
    * 减半后必须套 `Math.max(1, ...)`：攻击 20、防御 40 时原始伤害被压到 1，再除以 2 得 0.5，Java 里整数相除结果还是整数，直接变 0，跟"至少造成 1 点伤害"直接矛盾。

* **HeroCharacter**
    * 独有的只有 `skillList` 技能集合，空参构造里也要 `this.skillList = new ArrayList<>()`，这样以后从外部直接 `add` 技能，不用自己创建集合。

## 创建敌我双方

* **createPlayerCharacter(String username)**
    * 返回值是 `HeroCharacter`：调用方要拿这个对象去和电脑对战，所以结果必须返回出来。
    * 流程是提示创建角色并打印角色名 → 属性分配 → new 出对象 → add 三个技能 → `return player`。
    * 属性多的时候每个形参折行写并加注释。

* **属性分配的两道防线**

    | 键盘录入的值 | 程序判定 | 提示 | 最终生效的值 |
    | --- | --- | --- | --- |
    | 负数 | `input < 0` | 无效的输入，默认分配 0 点 | 0 |
    | 超过剩余点数 | `input > points` | 属性点不足！剩余的属性点已全部分配到这一项 | points |
    | 合法值 | 两个条件都不成立 | 无 | 原样参与扣减 |

    * 键盘录入是能接受负数的，所以负数和超额各要一道防线；两道防线走完才开始真正扣减。
    * `points -= input` 放在两道防线之后，执行到这里说明本轮录入非负且剩余点数足够。

* **三段雷同代码合成一段**
    * `String[] attributes = {"生命值", "攻击力", "防御力"}` 驱动动态提示语，`i=0` 是生命值、`i=1` 是攻击力、`i=2` 是防御力。
    * `int[] values` 记录三项各自分了多少点，循环结束直接 `values[i]` 取值继续往下。
    * 提示串格式要跟需求文档完全一致："剩余点数"后面没有点号，但有右括号，右括号后面还有一个冒号。

```java
for (int i = 0; i < attributes.length; i++) {
    System.out.print("分配点数到" + attributes[i] + "（剩余" + points + "点）：");
    int input = sc.nextInt();
    if (input < 0) {
        System.out.println("无效的输入，默认分配 0 点");
        input = 0;
    }
    if (input > points) {
        System.out.println("属性点不足！剩余的属性点已全部分配到" + attributes[i] + "中");
        input = points;
    }
    points -= input;
    values[i] = input;
}
```

* **创建对象的取值公式**

    | 属性 | 基础值 | 每点加成 | 取值 |
    | --- | --- | --- | --- |
    | 生命值 | 100 | ×10 | `100 + values[0] * 10` |
    | 攻击力 | 10 | ×2 | `10 + values[1] * 2` |
    | 防御力 | 0 | ×1 | `0 + values[2] * 1` |

    * 录 30 点到生命时，20 点会全部归到生命，最终 `100 + 20 × 10 = 300`。
    * 录 10 / 5 / 5 时得到生命 200、攻击 20、防御 5。

* **showSkill()**
    * 在 HeroCharacter 里遍历 skillList 用 StringBuilder 拼接并返回，外部直接 `player.showSkill()` 拼进字符串。
    * 只有不是最后一个元素时才补 `", "`，最后一项后面不加逗号。
    * 属性打印也可以在外部遍历集合自己拼，两种写法都行。

* **敌人列表**
    * `List<EnemyCharacter> enemyList = new ArrayList<>()`，把四个对象逐个 add 进去统一管理。

    | 敌人 | 生命 | 攻击 | 防御 | 技能 |
    | --- | --- | --- | --- | --- |
    | 初级战士 | 80 | 15 | 10 | 猛击 |
    | 敏捷刺客 | 60 | 25 | 5 | 快速攻击 |
    | 重装坦克 | 120 | 10 | 20 | 防御姿态 |
    | 神秘法师 | 70 | 25 | 8 | 火球术 |

## 伤害公式与血条

* **calculateDamage(int attack, int defense)**
    * 公式：受到的伤害 = 攻击力 − 防御力。
    * 最小伤害是 1：攻击 40、防御 50 时差值为负，总不能反过来给敌人回血。
    * 两个形参是 attack 和 defense；不要让 AI 直接生成 `return attack - defense`，要先用变量记录再判断。
    * 普通攻击传玩家攻击与敌人防御；用技能打就先在传参之前把攻击力乘上百分比算好，方法就能算技能伤害了。

* **getHpBar(String name, int hp, int maxHp)**
    * 固定 20 格：满血 20 格全亮、半血前半亮后半换成空格、残血只剩一格——打印的永远是 20 格，空的部分不是删掉而是换成空格。
    * 点亮格数 `int filled = (int) (hp * 1.0 / maxHp * barLength)`。

```java
public String getHpBar(String name, int hp, int maxHp) {
    int barLength = 20;
    int filled = (int) (hp * 1.0 / maxHp * barLength);
    StringBuilder sb = new StringBuilder();
    sb.append(name).append(": [");
    for (int i = 0; i < barLength; i++) {
        if (i < filled) {
            sb.append("■");
        } else {
            sb.append(" ");
        }
    }
    sb.append("] ").append(hp).append("/").append(maxHp).append(" ");
    return sb.toString();
}
```

    * 返回 String，三个形参是名字、当前血量、最大血量；想打印我方传我方数据，想打印敌方传敌方数据，一个方法搞定双方。
    * `append` 返回 `this`，所以可以一路链式追加冒号、左括号、右括号。

> **易错点**：`filled` 的计算必须先给 hp 乘 `1.0`。当前 10、上限 200 时真值是 0.05，不乘 1.0 的话整数相除直接得 0，这一格会打成 0 个方块。

* **技能系数总表**

    | 技能 | 使用者 | 效果 |
    | --- | --- | --- |
    | 普通攻击 | 通用 | 按公式原样计算伤害 |
    | 强力一击 | 我方 | 消耗 10 生命，攻击力 ×1.8 |
    | 生命回复 | 我方 | 消耗 10 生命，随机回复 0~20 |
    | 猛击 | 初级战士 | 伤害 ×1.5 |
    | 快速攻击 | 敏捷刺客 | 伤害 ÷2，打两次并累加 |
    | 防御姿态 | 重装坦克 | 不造成伤害，自身进入减伤 Buff |
    | 火球术 | 神秘法师 | 伤害 ×1.8 |

## 战斗流程的两层循环

* **三个计数器**

```java
int count = 1;   // 记录当前是跟第几个敌人战斗
int wins  = 0;   // 记录当前胜利了几场
int round = 1;   // 记录当前是第几个回合
```

* **内外循环的分工**

    | 循环 | 条件 | 管的是 |
    | --- | --- | --- |
    | 外循环 | `player.isAlive()` | 跟多个敌人依次战斗，一场接一场 |
    | 内循环 | `player.isAlive()` | 跟当前这一个敌人打多少回合 |

    * 依次跟第一个、第二个、第三个敌人打下去，只要玩家生命不为零就一直战斗；游戏里的"第 X 场"提示用的就是 count。

* **内循环的固定顺序**
    * ① 打印第 round 回合提示 + 双方血条。
    * ② 玩家出手，打完判断的是敌人血量——此时挨打的是敌人。
    * ③ 敌人还手，打完判断的是玩家血量——此时挨打的是我。
    * ④ 玩家没死才 `round++` 回内循环顶部。

* **战斗前的属性重置**
    * 每场战斗：敌人最大生命 +10、攻击 +3、防御 +2，这样每场都有"挑战新 Boss"的感觉。
    * 加点从第二场才开始，第一场是默认初始属性。
    * 判断条件两种写法都对：`if (count > 1)` 或 `if (wins != 0)`——赢过一场就已经不是第一场了。
    * 条件满足后遍历敌人集合逐个改属性。

```java
if (count > 1) {
    for (int i = 0; i < enemyList.size(); i++) {
        Character c = enemyList.get(i);
        c.setMaxHp(c.getMaxHp() + 10);
        c.setHp(c.getMaxHp());
        c.setAtk(c.getAtk() + 3);
        c.setDefense(c.getDefense() + 2);
        c.setDefending(false);
    }
}
```

    * `getMaxHp() + 10` 算完再 `setMaxHp` 回去，和 `setMaxHp(getMaxHp() + 10)` 是一回事，其他属性同理。
    * 验证方法：把 wins 改成 1 让条件成立，重装坦克的 120 / 10 / 20 会变成 130 / 13 / 22；验完把 wins 归零、临时的 `System.exit(0)` 删掉。

> **易错点**：改完 `setMaxHp` 一定要把 `setHp` 也跟着改一遍。血量上限涨了人还躺在上一场的老血上，后面结算时的回血比例会全乱套。
>
> **易错点**：`defending` 每场开打前必须清成 false，不然上一场挨打留下的格挡状态会一路带到下一场。

* **随机选择敌人**
    * `r.nextInt(enemyList.size())` 取索引，再 `enemyList.get(index)` 拿到对象，`show()` 打印它的属性。
    * 验证阶段还没写战斗逻辑时，循环会停不下来地抽敌人，加一行 `System.exit(0)` 控制住，验完删掉。

* **两段结算的落点**

    | 代码块 | 写在哪 |
    | --- | --- |
    | 单场战斗结算（回血、成长、是否继续） | 内循环之外、外循环之内 |
    | 最终结算（总胜场、结束语） | 外循环之外 |

    * 结算写进内循环会每回合结算一次，写到外循环之外则整个游戏只结算一次。
    * 内循环的结束点就是单场战斗的结束点。

## 玩家回合

* **playerTurn(HeroCharacter player, EnemyCharacter enemy)**
    * 两个形参：玩家对象和敌方对象，玩家回合就是我打电脑。
    * 打印"你的回合"和 `1.普通攻击  2.强力一击  3.生命回复`，Scanner 录入 `choose`，交给 switch 分派。
    * 写完每个 case 记得补 `break`，否则会 case 穿透。

* **default 写在最上面省代码**
    * 用户录 4、5、6 属于异常输入，处理方式是默认当作普通攻击。
    * `default` 里的语句体跟 `case 1` 完全一致，正好用 case 穿透节约代码：把 `default` 写在最上面并故意不写 `break`，让它向下穿透执行 `case 1` 的语句体，靠那边的 `break` 收住整个 switch。

* **三种行动的落地**

```java
case 1:
    int damage1 = calculateDamage(player.getAtk(), enemy.getDefense());
    System.out.println("你对" + enemy.getName() + "使用了普通攻击，造成了" + damage1 + "点伤害");
    enemy.takeDamage(damage1);
    break;
case 2:
    if (player.getHp() > 10) {
        player.takeDamage(10);
        int damage2 = calculateDamage((int) (player.getAtk() * 1.8), enemy.getDefense());
        System.out.println("消耗了10点生命，你对" + enemy.getName() + "使用了强力一击，造成了" + damage2 + "点伤害");
        enemy.takeDamage(damage2);
        break;
    } else {
        System.out.println("体力不足，攻击失败");
        break;
    }
case 3:
    if (player.getHp() > 10) {
        player.takeDamage(10);
        Random r = new Random();
        int healHP = r.nextInt(21);
        player.heal(healHP);
        System.out.println("消耗了10点生命，你使用了生命回复，恢复了" + healHP + "点生命");
        break;
    } else {
        System.out.println("体力不足，恢复生命失败");
        break;
    }
```

    * 强力一击与生命回复都是先扣 10 点血，判定条件是当前血量大于 10。
    * `nextInt(21)` 取的是 [0, 21) 的整数，正好是 0~20 的随机回复量。
    * 回血直接调 `player.heal(healHP)`，封顶判断交给父类，不用自己重写一遍。
    * 两个 case 的伤害变量不能重名：普通攻击叫 damage1，强力一击叫 damage2。

> **易错点**：百分比相乘的结果是小数，传给 int 类型形参类型不匹配，一定要写 `(int) (player.getAtk() * 1.8)` 强转。

* **打完立刻判定胜负**

```java
if (!enemy.isAlive()) {
    System.out.println("恭喜你，你击败了" + enemy.getName());
    wins++;
    break;
}
```

    * 敌人血量为零就不会再还手了，必须停手；`wins++` 正是"从第二场开始加属性"那个判断的依据。
    * 字符串拼接太复杂就直接交给 AI 生成，把变量换掉即可。

## 敌方回合

* **enemyTurn(enemy, player)**
    * 方法体第一行先把分隔线和敌人名字拼上输出。
    * `String action = "普通攻击"` 作为默认值兜底，不管后面怎么随机先按普攻。
    * `int n = r.nextInt(10)` 取 0~9，0~4 是普通攻击、5~9 是技能攻击，五五开正好对上需求的 50%。
    * 命中技能攻击再去问当前这个敌人是谁：`action = enemy.getSkill()`。
    * 只有五种情况，switch 后面的 default 写不写都行。

* **五个分支的算法**

```java
case "普通攻击":
    int damage1 = calculateDamage(enemy.getAttack(), player.getDefense());
    player.takeDamage(damage1);
    break;
case "猛击":
    int damage2 = (int) (calculateDamage(enemy.getAttack(), player.getDefense()) * 1.5);
    player.takeDamage(damage2);
    break;
case "快速攻击":
    int damage3 = 0;
    for (int i = 0; i < 2; i++) {
        int temp = (int) (calculateDamage(enemy.getAttack(), player.getDefense()) / 2);
        damage3 = damage3 + temp;
    }
    player.takeDamage(damage3);
    break;
case "防御姿态":
    enemy.defending = true;
    break;
case "火球术":
    int damage4 = (int) (calculateDamage(enemy.getAttack(), player.getDefense()) * 1.8);
    player.takeDamage(damage4);
    break;
```

    * 敌方出手传进去的顺序是敌人的攻击、玩家的防御，我方回合正好是反过来的一对，两个方法名像但参数一换方向就整个反了。
    * 快速攻击是 50% 且要打两次：循环外用 `damage3` 做累加器，循环内用临时变量 `temp`，两次结束才是总伤害。
    * 防御姿态不调 `calculateDamage` 也不调 `takeDamage`，只把 `defending` 置为 true；成员变量布尔默认是 false，改成 true 就是当前挂上了这个状态。
    * 提示语不用自己写，需求文档里现成就有，复制粘贴把变量换掉即可。

* **回合收尾**

```java
if (!player.isAlive()) {
    System.out.println(enemy.getName() + "击败了你");
    break;
}
round++;
```

    * 玩家没被击败才 `round++` 进入下一回合；只有敌方或我方有一个人被打败，这个循环才会真正结束。
    * 敌方回合比玩家回合复杂，多出来的复杂度全部来自"不同敌人走不同分支"这个 switch，伤害计算和扣血本身没有任何区别。

> **易错点**：`(int) (伤害 * 1.5)` 里的强转不能省。不强转的话方法返回的 double 赋给 int 变量直接编译不过；就算能过，多出来的那点小数伤害也不会体现在血量上。

## 战斗结算

* **结算的整体位置**
    * 跟单个敌人的战斗结束后，玩家胜利就恢复生命值继续战斗，玩家失败整个游戏停止。
    * 三部分都挂在同一个前提 `if (player.isAlive())` 下面——玩家一旦倒下，回血、成长、继续这三件事统统不该发生。

* **恢复血量 20~40**
    * 两种写法等价：`r.nextInt(20, 41)` 或 `r.nextInt(21) + 20`，后者是 0~20 统一加 20。
    * 上面随机选敌人时已经建过 Random，这里直接复用那个变量，重复声明会报"变量已重复"。

```java
int hp = r.nextInt(21) + 20;
player.heal(hp);
System.out.println("战斗结束了，你恢复了 " + hp + " 点生命值");
```

* **每胜三场提升属性**
    * 触发条件是 `player.isAlive() && wins > 0 && wins % 3 == 0`，`wins % 3 == 0` 就是三的整数倍。

> **易错点**：加的是最大生命 maxHp，不是当前生命 hp。当前生命由结算里的回血那段管。

* **询问是否继续**
    * 提示"请问你是否需要继续下一场战斗（yes/no）"，`sc.nextLine()` 录入 `choose`。

> **易错点**：这里不做 `count++`，每场提示都会是"第一场战斗开始"，因为"你是第 count 场战斗开始"用的正是 count。

## Math 类

* **工具类的书写规则**
    * ① 类名要见名知意；② 构造方法私有化，不让外界创建它的对象；③ 里面的方法都定义成静态的，直接用类名调用。
    * `Math` 完全遵守这三条，构造方法被 private 修饰，写 `Math m = new Math()` 立刻飘红；所有方法都是 static，调用时直接用类名点一下。
    * API 就是 JDK 提供的各种功能的 java 类，已学过 Scanner、Random、String、ArrayList。

* **常见方法**

    | 方法 | 含义 | 结果示例 |
    | --- | --- | --- |
    | abs | 绝对值 | `Math.abs(-10)` → 10 |
    | ceil | 向上取整，进一法 | `Math.ceil(10.11)` → 11.0 |
    | floor | 向下取整，去尾法 | `Math.floor(10.11)` → 10.0 |
    | round | 四舍五入 | `Math.round(11.55)` → 12 |
    | max | 两个数据中的较大值 | `Math.max(10, 20)` → 20 |
    | min | 两个数据中的较小值 | `Math.min(10, 20)` → 10 |
    | pow | a 的 b 次方 | `Math.pow(2, 3)` → 8.0 |
    | sqrt | 平方根 | `Math.sqrt(4)` → 2.0 |
    | cbrt | 立方根 | `Math.cbrt(27)` → 3.0 |
    | random | 随机小数 | 0.0 到 1.0，不含 1.0 |

    * ceil 和 floor 的返回值都是 double，打印出来带 `.0`；名字已经把行为告诉你了——ceil 跟天花板同名向上顶到整数，floor 跟地板同名直接往下掉到整数。
    * max / min 重载了 int、long、float、double，源码内部就是一句三元运算符的比较。
    * random 是空参方法返回 double，不常用；真要随机数还是用 Random。

> **易错点**：`round` 的规则是返回与参数最近的整数；如果有多个，就返回正无穷方向的那个。所以 `Math.round(-10.5)` 是 `-10` 而不是 `-11`，自测四舍五入要避开负数的 .5 临界值。

* **pow 的三种用法**
    * 求幂：`Math.pow(2, 3)`。
    * 开根号：第二参数写 `0.5`，即取 a 的 1/2 次方，`Math.pow(4, 0.5)` → 2.0。
    * 倒数：第二参数写 `-0.5`，即取 a 的 -1/2 次方，`Math.pow(4, -0.5)` → 0.5。
    * 立方根必须写 `1 / 3`，写 0.3 算的是 0.3 次方，根本不是立方根。

    | 需求 | 写法 A | 写法 B |
    | --- | --- | --- |
    | 平方根 | `Math.pow(n, 0.5)` | `Math.sqrt(n)` |
    | 立方根 | `Math.pow(n, 1 / 3)` | `Math.cbrt(n)` |

    * 只想做开方这种特殊操作直接用 sqrt / cbrt；数学计算比较复杂、比如要 -1/2 次方，那就只能用 pow。
    * `Math.random()` 的底层是先创建一个 Random 对象再用它调 `nextDouble`，所以它本质上是包装出来的。

## 算法小题

* **判断质数 isPrime(int number)**
    * 因子是成对出现的，每一对因子里必有一个小于等于平方根，另一个大于等于平方根，没有特殊情况。
    * 所以只需要检查一半区间，判断质数的循环结束条件就是它的平方根。
    * 判 13 用朴素写法要循环 11 次没什么感觉，判 997 要循环 900 多次；改成走到平方根后只要 30 次。

```java
public static boolean isPrime(int number) {
    for (int i = 2; i <= Math.sqrt(number); i++) {
        if (number % i == 0) {
            return false;
        }
    }
    return true;
}
```

> **易错点**：循环条件必须是 `<=` 而不是 `<`。number 是 16 时，中间的平方数 4 本身也得参与判断——`16 % 4 == 0`，它不是质数。

* **自幂数（Armstrong number）**
    * 定义：N 位自然数等于自身各位数字的 N 次幂之和，即 $\sum_{i} d_i^{\,N} = n$，其中 $d_i$ 是第 $i$ 位数字。
    * 三位数 153 满足 $1^3 + 5^3 + 3^3 = 153$；四位数就要求四次方。
    * 难点不是计算过程，而是这个数字是键盘录入的、事先不知道是几位。

```java
Scanner sc = new Scanner(System.in);
System.out.println("请输入一个正整数");
int number = sc.nextInt();

int temp = number;                    // 备份原值
int len = (number + "").length();     // 位数
int sum = 0;

while (number != 0) {
    int lastNumber = number % 10;     // 取最右边的数字
    sum += (int) Math.pow(lastNumber, len);
    number = number / 10;             // 去掉最右边的数字
}

if (sum == temp) {
    System.out.println("当前的数字是一个自幂数");
} else {
    System.out.println("当前的数字不是自幂数");
}
```

    * 位数取法是 `(number + "").length()`——字符串加任意数据类型都做拼接，整数加上一个长度为 0 的空串就变成字符串了；小括号不能省，否则 `.length()` 落不到它身上。
    * 拆位循环条件是 `number != 0`，每次先 `% 10` 取末位、再 `/ 10` 去掉末位，0 就是循环的结束条件。
    * 求和用 `sum += (int) Math.pow(lastNumber, len)`，pow 返回 double，赋给 int 必须强转。

> **易错点**：拆位循环会把 `number` 一路改成 0，最后拿它跟 sum 比较必然不相等——录入 153 会被判成非自幂数。循环变量和被比较的原始数据不能是同一个变量，必须用第三方变量备份原值再比较。

* **写代码的顺序**
    * 写算法题不是从上往下一行一行照着写，而是先写主体思路，发现问题了再回头补。
    * 看到复杂问题先别慌，想到多少写多少，书写过程中遇到问题或缺变量再回头补，思路才更通畅。
    * 测试类里写的方法一定要加 `static`：main 是静态的，静态只能调用静态，非静态还得先 new 出对象再用对象调。
