# 文件操作与 JSON 序列化

## 文件与流

### 文件

* **文件（File）**
    * > **定义**：文件是数据源，是保存数据的地方。

    * 数据库本质也是文件，只是它的文件形式与普通文件不太一样。
    * 可保存的数据形态不限：文本、图片、视频、音频各在其列。
    * 文件操作在程序里的价值是对数据源做增删改查。

### 流

* **流（Stream）**
    * > **定义**：流是数据在数据源（文件）和程序之间经历的路程、路径。

    * 输入流：数据从文件流向程序内存，对应读文件的操作。
    * 输出流：数据从程序内存流回文件，对应写文件的操作。
    * 判定输入流还是输出流，只看数据流向。

    ```text
            输入流：读
       ┌──────────────┐         ┌──────────────┐
       │   数据源     │ ──────► │  程序内存    │
       │   （文件）   │         │  （Go 变量） │
       └──────────────┘         └──────────────┘

            输出流：写
       ┌──────────────┐         ┌──────────────┐
       │   数据源     │ ◄────── │  程序内存    │
       │   （文件）   │         │  （Go 变量） │
       └──────────────┘         └──────────────┘
    ```

## os.File 与打开关闭

### os.File 结构体

* **os.File**
    * > **定义**：`os` 包中的 `File` 结构体，封装了所有文件相关操作，代表一个打开的文件对象。

    * 对文件的一切操作（读、写、定位、同步、关闭）都通过 `File` 结构体及其绑定的方法完成。
    * 获取文件元信息用 `Stat`，它返回 `FileInfo`，可拿到文件大小、修改时间。
    * `Name` 方法返回文件名称。

### os.Open 函数

* **os.Open（name string）**
    * > **定义**：`os` 包提供的普通函数（不是 `File` 的方法），打开一个文件用于读取。

    * 成功返回 `*File` 与 `error`，因此文件在类型上是一个**指针类型**。
    * 实参是文件的路径字符串。
    * 打开失败时返回错误；若此时继续执行关闭，会因参数无效而再次报错。

### File.Close 方法

* **File.Close（f \*File）**
    * > **定义**：关闭文件，关闭后文件不能再用于读写，成功返回 `nil`，失败返回 `error`。

    * 它是绑定在 `File` 结构体**指针**上的方法，必须用文件指针变量调用。
    * 打开与关闭成对出现，读写操作做完后必须关闭。
    * `file` 这个变量有三种叫法：file 对象、file 指针、文件句柄，指的是同一个东西。

### defer 与句柄泄漏

* **defer 关闭文件句柄**
    * `defer file.Close()` 写在打开之后，保证在函数退出前执行关闭。
    * 关闭动作被推迟，不影响 `defer` 之后对文件句柄的正常使用。
    * 忘记关闭文件句柄会造成内存泄漏，代码跑一段时间会越来越慢。

## 读取文件

### 带缓冲读取 bufio.NewReader

* **bufio.NewReader**
    * > **定义**：把已打开的 `file` 包装成带缓冲的 `*bufio.Reader`。

    * `Reader` 内部有一个 buffer，默认缓冲区大小为 **4096** 字节。
    * 带缓冲的意义在于读一部分处理一部分，而不是一次性把整个文件读进内存，适合读取大文件。
    * 需要显式写出 `defer file.Close()`，否则会泄漏文件句柄。

### ReadString 与 io.EOF

* **reader.ReadString（'\n'）**
    * > **定义**：以结束符 `'\n'` 为界把文件内容一行一行读出来，返回 `str` 与 `err`。

    * 循环里用 `if err == io.EOF { break }` 判定读到文件末尾并结束读取。
    * 输出内容用 `fmt.Print(str)`。

    * > **易错点**：不要用 `Println`。`str` 本身已包含读到的换行符，再用 `ln` 会多出一个换行。

    * 输出里出现的额外空行来自源文件本身存在的空行，不是读取错误。

### ioutil.ReadFile 一次性读取

* **ioutil.ReadFile（name）**
    * > **定义**：把整个文件一次性读入内存的函数，返回 `[]byte` 与 `error`。

    * 打开与关闭都被封装在函数内部，调用方不需要显式 `Open` 或 `Close`。
    * 返回的是 byte 切片，直接打印会看到一堆数字，要用 `string(content)` 转成字符串才能看到内容。
    * 读失败时 `error` 不为 `nil`。

    * > **注意**：该方式只适用于文件不大的情况。文件大时应改用带缓冲的 Reader，否则效率很低。

## OpenFile 与打开模式

### 三个参数

* **os.OpenFile**
    * > **定义**：`os` 包中用于写文件的函数，返回文件指针（文件句柄）与 `error`。

    * 第一个参数是文件路径。
    * 第二个参数是 flag，表示打开文件的模式。
    * 第三个参数是文件权限 `FileMode`。

### flag 取值

| 常量 | 含义 |
| :--- | :--- |
| `O_RDONLY` | 只读模式打开，文件只能读不能写 |
| `O_WRONLY` | 只写方式打开，只能往里写不能读取 |
| `O_RDWR` | 读写模式打开，既可读也可写 |
| `O_APPEND` | 追加，写入内容不覆盖原有内容，追加到文件尾部 |
| `O_CREATE` | 创建，文件不存在时创建新文件 |
| `O_SYNC` | 同步 |
| `O_TRUNC` | 打开时清空原有内容 |

    * 几种模式可通过竖杠组合使用。
    * 没有专门创建文件的函数，以 `O_CREATE` 打开时文件不存在会自动创建。
    * 实际开发中常把 `O_CREATE` 与写模式组合使用。

    * > **易错点**：`O_TRUNC` 是唯一会毁掉原有数据的模式，一打开就把文件清空。如果用循环把文件夹里所有文件都这样打开遍历一遍，里面的文件会全部丢失。

### FileMode 权限

* **FileMode**
    * > **注意**：`FileMode` 只在 Linux、Unix 操作系统下有效，在 Windows 下无效，随便写一个值即可（如 `0666`）。

    * 三个占位符分别代表文件所有者、文件所在组的用户、其它组用户的权限。
    * 权限数值：可读 `r` 为 **4**，可写 `w` 为 **2**，可执行 `x` 为 **1**。

### 带缓冲 Writer 写文件

* **bufio.NewWriter**
    * > **定义**：把文件句柄包装成带缓冲的 `*bufio.Writer`，只返回一个参数。

    * 写文件时选用带缓冲的 Writer 以提高效率。
    * `writer.WriteString(str)` 往 Writer 里写字符串，写入内容先进入缓冲区。

    * > **易错点**：每写一句都要带上 `\r\n`，否则所有内容会挤在同一行。

* **writer.Flush**
    * > **定义**：把缓冲区里的数据真正写入底层目标，源码注释为 “Flush writes any buffered data to the underlying io.Writer.”

    * `WriteString` 只是写进缓冲，并没有实际落盘，必须调用 `Flush` 才会真正写入文件。
    * 漏掉 `Flush` 的后果是打开文件看不到任何内容，数据丢失。

### 四种写文件模式对照

| 案例 | 需求 | 打开模式 | 写入内容 |
| :--- | :--- | :--- | :--- |
| 案例一 | 创建新文件 | `O_WRONLY \| O_CREATE` | 五句 hello, gardon |
| 案例二 | 覆盖已存在的文件 | `O_WRONLY \| O_TRUNC` | 十句 你好，尚硅谷 |
| 案例三 | 在原内容后追加 | `O_WRONLY \| O_APPEND` | 十句 ABC, English! |
| 案例四 | 先读出来，再追加 | `O_RDWR \| O_APPEND` | 读出后追加五句 你好，北京 |

    * 四个案例的差别只在打开模式，Writer 的写法完全照抄。
    * 打开文件时 `err != nil` 要打印错误并立即 `return`，不再往下走。

    ```text
                        O_CREATE   O_TRUNC   O_APPEND   O_RDWR
      文件不存在时         创建      ——        ——       ——
      打开已有文件时        ——      先清空    尾部追加   既读又写
      内容会被覆盖吗        否      会！      不会       只在尾部追加
    ```

### 换行符

* **换行符 \r\n**
    * 只写 `\n` 时，用记事本打开不换行，用 EditPlus 打开会换行，因为记事本没有对 `\n` 做完整识别。
    * 有些编辑器认 `\r`，有些认 `\n`，两个一起带上就不会出问题。
    * 写文件代码统一带 `\r\n`，保证记事本和 EditPlus 打开都能看到换行。

## 文件导入与存在性判断

### ioutil 导入文件内容

* **ioutil.ReadFile + ioutil.WriteFile**
    * > **定义**：先把源文件读成 byte 切片，再把这个切片写进目标文件，完成内容导入。

    * `WriteFile` 三个参数依次是：目标文件路径、待写的 byte 切片、文件模式。
    * `ReadFile` 与 `WriteFile` 都隐式地打开和关闭文件，调用方无需管理句柄。
    * `WriteFile` 只返回一个 `error`。

### os.Stat 判断存在性

* **os.Stat（name）**
    * > **定义**：返回描述指定文件对象的 `FileInfo`，据此判断文件或目录是否存在。

| `os.Stat` 返回的 error | 说明 |
| :--- | :--- |
| 为 `nil` | 文件夹和文件存在 |
| `os.IsNotExist` 判定为 `true` | 文件夹不存在 |
| 其他类型 | 不确定是否存在 |

    * 封装成 `PathExists(path string) (bool, error)`：`err == nil` 返回 `true, nil`；`os.IsNotExist(err)` 为真返回 `false, nil`；其他错误原封不动返回。
    * 调用方看布尔值即可判断存在性，兼看 `error` 区分是否属于其它错误。
    * 一般情况下 `Stat` 的错误只源于存在与否，用 `true` 和 `false` 判断通常足够。

### io.Copy 拷贝文件

* **io.Copy（dst Writer，src Reader）**
    * > **定义**：`io` 包提供的拷贝函数，把 `src` 的数据拷贝到 `dst`，返回拷贝的字节数与 `error`。

    * 源文件侧用 `os.Open` 打开，再用 `bufio.NewReader` 得到 Reader。
    * 目标文件侧用 `os.OpenFile(dst, os.O_WRONLY|os.O_CREATE, 0666)` 打开，再用 `bufio.NewWriter` 得到 Writer，并用 `defer dstWriter.Flush()` 保证落盘。
    * 目标文件可能不存在，所以不能用 `os.Open`，必须用带 `O_CREATE` 的 `OpenFile`。
    * 源与目标两个句柄都要 `defer Close`，否则内存泄漏。
    * 因为带缓冲，读一点写一点，可以拷贝大文件。
    * 可拷贝的对象不限于图片，视频、音频等二进制文件同样适用。

    ```text
     源文件 side                                        目标文件 side
    ─────────────                                        ─────────────
     srcFileName                                         dstFileName
          │                                                 ▲
          │ os.Open                                         │ os.OpenFile
          ▼                                                 │ (O_WRONLY|O_CREATE)
      *os.File (srcFile)                                   │
          │ bufio.NewReader                                │ bufio.NewWriter
          ▼                                                 ▼
      *bufio.Reader  ──────── io.Copy(dst, src) ───────►  *bufio.Writer
                                                              │
                                                        Flush + Close
    ```

    * `io.Copy` 内部调用 `copyBuffer`，循环执行“读一段就写一段”，出错时截断并返回错误。

## 字符统计

### 结构体承载计数

* **CharCount 结构体**
    * > **定义**：用四个整型字段承载分类计数，分别是英文、数字、空格、其他字符的个数。

    * 字段为 `ChCount`、`NumCount`、`SpaceCount`、`OtherCount`，都是 `int` 类型。
    * 声明 `var count CharCount` 后各字段默认是零值 `0`，不需要显式初始化。
    * 实现思路：打开文件 → 建带缓冲 reader → 每读一行遍历一次 → 结果存入结构体。

### switch 分流统计

* **逐字符 switch**
    * 字符串本质是 byte 数组，可以 `for _, v := range str` 遍历，比较的是对应 ASCII 码。
    * 落在 `'a'`–`'z'` 或 `'A'`–`'Z'` 区间计入英文，用 `fallthrough` 穿透合并两个分支。
    * 等于 `' '` 或 `'\t'` 计入空格。
    * 落在 `'0'`–`'9'` 区间计入数字。
    * 其余落入 `default`，计入其他字符（中文、特殊字符及 `\r`、`\n` 等不可见字符）。
    * 读取的文件含两处回车换行时，其他字符计数为 4。

    * > **易错点**：`switch v { case v >= 'a' && v <= 'z': }` 编译不通过。带表达式的 `switch` 要求各 case 与 `v` 同类型，而该表达式是布尔类型。要写成无表达式的 `switch`，把它当作 if 分支结构使用。

### 中文与 rune

* **string 转 rune 切片**
    * 按字符串直接统计无法处理中文，可写 `str := []rune(str)` 转成 rune 切片后遍历，从而兼容中文。
    * `for i, v := range str` 遍历时 `v` 的类型是 `rune`，Go 会自动解码 UTF-8，中文已按字符拆开，无需转换。
    * 真正会出问题的是直接按索引访问 `str[i]`，那样拿到的是单个字节。

## 命令行参数

### os.Args

* **os.Args**
    * > **定义**：`os` 包中事先定义好的全局变量，是一个 string 切片，保存命令行的所有参数。

    * 切片第 0 个元素是程序自身的名称，从第 1 个元素开始才是用户传入的参数值。
    * 参数个数用 `len(os.Args)` 获取，遍历切片即可依次取出全部参数。
    * 典型用途：运行时传入配置文件路径、要监听的端口号等动态配置。

    * > **易错点**：参数位置就是一切，顺序写错会把值读到别的下标上，调用方必须严格按顺序传参。

### flag 包

* **flag（命令行参数解析包）**
    * > **定义**：`flag` 包实现了命令行参数的解析，支持 `-u root` 这类带标识的参数形式。

    * 相比 `os.Args`，用标识指定参数后顺序不受约束，可以任意调整位置。
    * 注册参数：`flag.StringVar(&user, "u", "", "用户名，默认为空")`、`flag.IntVar(&port, "port", 3306, "端口号，默认为 3306")`。
    * 第一个参数是引用类型，用于把解析出的值写回变量；第二个是参数标识名；第三个是默认值；第四个是 usage 说明。
    * 命令行未给值时启用默认值，例如未传 `-port` 时端口为 `3306`。
    * 参数标识一旦注册，命令行就必须按该标识书写（如注册 `pwd` 就写 `-pwd`）。

    * > **易错点**：注册完所有 flag 后必须调用 `flag.Parse()` 才开始解析，否则取不到值。它必须在所有 flag 注册完成之后、访问其值之前执行。

## JSON 与序列化

### JSON 与序列化

* **JSON（JavaScript Object Notation）**
    * > **定义**：JSON 全称 JavaScript 对象标记法，是一种轻量级的数据交换格式，2001 年推行使用，如今是主流数据传输格式。

    * 它利于人的阅读和编写，也利于机器的解析和生成，有利于网络传输效率。
    * 经典用法是 key-value，键叫属性，值是对应的具体数据，键值对可无限增加，扩展性好、灵活。
    * 任何一种数据类型都可以转成 JSON 格式，包括字符串、数字、对象、数组，以及 Golang 中的 map 与结构体。

* **序列化（Marshal）**
    * > **定义**：把具有 key-value 结构的数据（结构体、map、切片）转成 JSON 字符串的操作。

    * 网络传输的典型流程是发送方序列化、接收方反序列化后再操作。
    * 基本类型（int、string、float64 等）也能序列化，但没有 key-value 对应关系，意义不大，实际开发中很少用。

### 应用场景

* **场景一 · Web 编程（B/S）**
    * Go Web 服务器不直接把数组返回给浏览器，而是先做 JSON 序列化得到 JSON 字符串再传出去。
    * 浏览器收到 JSON 字符串后先反序列化成数组，再做渲染和 DOM 编程显示。
    * 网络上传递的只有中间那段 JSON 字符串。

    ```text
    【场景一 · Web 编程（B/S）】

      Go Web 服务器                              浏览器
     ┌─────────────────┐                       ┌─────────────────┐
     │  Go 数组         │ ① json.Marshal      │                 │
     │  [北京 上海]     │ ───────────────────► │  JSON 字符串    │
     │                  │                       │                 │
     │                  │                       │ ② 反序列化     │
     │                  │                       │   → 数组        │
     │                  │                       │ ③ 渲染到页面   │
     └─────────────────┘                       └─────────────────┘
          整个网络上传递的，只有中间那段 JSON 字符串
    ```

* **场景二 · 聊天程序（C/S）**
    * 客户端 A 把消息数组序列化成 JSON 字符串发给中转服务器，服务器原封不动地转发给客户端 B。
    * 客户端 B 收到 JSON 字符串后反序列化回数组再显示。
    * 两端都遵守同一格式时转换和通信才好控制，类比于双方都用同一种语言聊天。

    ```text
    【场景二 · 聊天程序（C/S）】

     客户端 A         Go 中转服务器         客户端 B
    ┌─────────┐      ┌────────────┐      ┌─────────┐
    │ 消息数组 │ ①    │            │  ④   │JSON字符串│
    │         ├─────►│  原样中转  ├─────►│         │
    └─────────┘      └────────────┘      └─────────┘
       ② 序列化成 JSON 字符串，两端都遵守这个格式；
          服务器不改内容，只负责转发，客户端 B 再反序列化、显示
    ```

### JSON 格式规则

* **键值对与分隔符**
    * JSON 靠键值对保存数据，描述一个信息时总是“一个键、一个值”。
    * 键名写前面并用双引号包裹，后面用冒号与值分开。
    * 多个键值对之间用逗号间隔。
    * 值有多个时用中括号表示数组；对象有多个时把中括号写到外层再用逗号分隔。

    ```json
    {
    	"name": "tom",
    	"age": 20,
    	"address": ["上海", "北京"]
    }
    ```

    * 可继续追加属性（如 `hobby` 及其数组值），信息描述能力随之增强。
    * `json.cn` 这个站点可以校验 JSON 格式正误（少一个逗号也会被指出），还能转成 XML 格式、保存复制折叠、展开压缩显示。
    * 原则：数组用中括号，键值对用冒号间隔，多个键值对用逗号间隔。

### json.Marshal

* **json.Marshal**
    * > **定义**：`encoding/json` 包中把 `v` 编码为 JSON 的函数，参数是空接口 `interface{}`，返回 `[]byte` 与 `error`。

    * 参数为空接口，因此任何数据类型都能传进去序列化。
    * 返回的是 byte 切片，要看到内容必须 `string(data)` 转换。

    * > **易错点**：直接打印返回值只会看到一堆数字，必须转成 `string` 才能看到 JSON 内容。

* **结构体序列化**
    * 未加 tag 时，结构体字段名直接作为 JSON 的键，字段值作为值，一个不多一个不少。

    ```text
    {"Name":"牛魔王","Age":500,"Birthday":"2011-11-11","Salary":8000,"Skill":"牛魔拳"}
    ```

* **map 序列化**
    * map 的 key 是字符串，值是任意类型 `interface{}`，使用前必须 `make`。
    * map 本身按引用传递，序列化时直接传变量即可，不必再传地址。
    * 序列化结果的键没有固定顺序。

    ```text
    {"address":"火云洞","age":30,"name":"红孩儿"}
    ```

    * > **易错点**：map 的 key 无序，序列化输出的顺序不会与书写顺序一致。但结果本身是正确的，JSON 按 key-value 对应，不依赖顺序。

* **切片序列化**
    * 切片元素为 `map[string]interface{}` 时，序列化结果就是一个对象数组。

    ```text
    [{"address":"北京","age":7,"name":"jacky"},{"address":"墨西哥","age":20,"name":"tom"}]
    ```

    * 因为值是 `interface{}`，某个值本身是数组也可以序列化，它会以中括号分隔呈现。

## tag 与反序列化

### tag 标签

* **结构体 tag**
    * > **定义**：写在结构体字段后面的反引号标签，形式为 `` `json:"字段名"` ``，用于指定序列化后的键名。

    * 适用场景是 Web 接口：客户端（如 jQuery、JavaScript）希望键名统一为小写或自己指定的名字。
    * 写法是反引号 + `json` + 冒号 + 新的字段名，例如 `json:"monster_name"`、`json:"monster_age"`。
    * 只能标了 tag 的字段改名，其余字段仍以字段名为键。

    ```text
    {"monster_name":"牛魔王","monster_age":500,"Birthday":"2011-11-11","Sal":8000,"Skill":"芭蕉扇"}
    ```

    * tag 改名由反射机制实现：序列化时把键从 `Name` 换成 `monster_name`。
    * 需要指定键名时给 struct 加 tag 即可；不加 tag 时键保持原字段名。

    * > **易错点**：tag 必须写在结构体的定义位置，不能写在赋值的地方。

    * > **易错点**：不能把字段名直接写成 `monster_name`。`json.Marshal` 属于另一个包，跨包访问首字母小写的字段属于访问不可导出的字段，会报错；即便改成首字母大写以绕过报错，该字段也会被静默跳过，序列化结果丢失这个字段且不抛异常。
    * 用 tag 是为了同时满足两点：`Marshal` 能访问到该字段，且序列化后的键名按自己指定的名字输出。

### json.Unmarshal

* **json.Unmarshal**
    * > **定义**：把 JSON 字符串反序列化成对应的数据类型，是序列化的逆向操作。

    * 两个参数：第一个是该字符串对应的 byte 切片，第二个是承接结果的结构体变量，按引用传递。
    * 第二个参数必须是引用，否则函数外部的值不会被改变。
    * 反序列化失败返回非 `nil` 的 `error`；成功后可按字段逐个取出。
    * 结构体的声明与定义必须先存在，才能反序列化成该类型；是否保留 tag 与反射不影响这一步。

    ```go
    var monster Monster
    err := json.Unmarshal([]byte(str), &monster)
    ```

* **反序列化 map 与切片**
    * 承接用的 map / 切片类型必须与序列化前的类型保持一致，不能随便改类型。
    * map 与切片在反序列化时都不需要 `make`，`make` 已被封装进 `Unmarshal` 内部，遇到 map 时利用类型断言在函数内部完成空间分配。

    * > **易错点**：JSON 字符串很长时可以换行书写，用一个双引号截断一段再加 `+` 拼接下一段，直接换行会语法出错。

### 两条易翻车的规矩

* **类型一致性**
    * 反序列化后的数据类型必须和序列化前一致；对结构体来说，指的是字段名字和字段类型都要一样。
    * 结构体的类型实际由字段决定，字符串里并不携带它到底是哪个结构体，所以换一个字段完全相同的结构体（如字段一致的另一个结构体）也能正常反序列化。

* **转义处理**
    * 原生形态手写的 JSON 字符串，因为内部含双引号，必须加反斜杠转义，否则语法出错。
    * 通过程序、网络或读取文件获得的 JSON 字符串**不需要**再转义，因为引号在字符串内部已经完成转义处理。
