# 面向对象综合实战：记账与客户管理系统

## 家庭收支记账软件需求

   * **项目定位**

       * 模拟实现一个基于文本界面的家庭记账软件，只做文本界面不做图形界面。

       * 涉及知识点是局部变量、基本数据类型、循环语句、分支判断、输出格式控制以及面向对象编程。

       * 这个项目较小，需求几句话就说完了，不画用例图；设计上只做了界面设计，不涉及架构、数据库和操作系统。

   * **四项功能**

       * 记录家庭的收入。

       * 记录家庭的支出。

       * 打印收支明细表，让收支情况一目了然。

   * **主菜单界面**

         ```text
         -----------------家庭收支记账软件-----------------
                          1 收支明细
                          2 登记收入
                          3 登记支出
                          4 退出软件
         请选择(1-4)：
         ```

       * 选 1 查看收支明细，选 2 登记一笔收入（金额加原因），选 3 登记一笔支出（钱花到哪里去了），选 4 退出。

## 面向过程的记账软件

   * **三步走**

       * 写任何一个功能都是三步：先功能说明，再思路分析，最后代码实现。

       * 功能说明就是讲清这个功能完成一件什么事，一张界面图就够。

   * **主菜单与退出的标志位**

       * 主菜单必须循环显示，输入一个选项后处理完还要再次显示菜单，所以外层是 `for`。

       * 声明 `key` 保存用户输入的选项，声明 `loop` 控制是否退出 `for` 循环。

         ```go
         key := ""
         loop := true

         for {
             fmt.Println("-----------------家庭收支记账软件-----------------")
             fmt.Print("请选择(1-4)：")
             fmt.Scanln(&key)

             switch key {
             case "1":
                 fmt.Println("-----------------当前收支明细记录-----------------")
             case "4":
                 loop = false
             default:
                 fmt.Println("请输入正确的选项..")
             }

             if !loop {
                 break
             }
         }

         fmt.Println("你退出了家庭记账软件的使用...")
         ```

       * > **易错点**：`switch` 里的 `break` 只跳出 `switch`，跳不出 `for` 循环，所以必须用 `loop` 这个标志位来跳出外层循环。

   * **明细与登记收入需要的变量**

       * | 变量 | 作用 | 初值 |
         | --- | :--- | :--- |
         | `balance` | 账户余额 | `10000.0` |
         | `money` | 本次收支金额 | `0.0` |
         | `note` | 本次收支说明 | `""` |
         | `details` | 收支明细详情 | 表头字符串 |

       * `balance` 初值 10000 是从需求反推的：收入 1000 后余额是 11000，说明原本就有 10000 的预留资金。

       * `details` 初值直接给表头，用制表符 `\t` 控制格式：

         ```go
         var details = "收支\t账户金额\t收支金额\t说    明\t\n"
         ```

       * 写到这里先编译，编译器会提示 `balance` 定义了没使用，这是正常的，先注释掉等登记收入做完再打开。

       * 登记收入：提示并接收金额和说明，`balance += money`，然后拼接一行明细：

         ```go
         balance += money
         details += fmt.Sprintf("收入\t%v\t%v\t%v\n", balance, money, note)
         ```

       * 拼接的格式串是固定的「收入」两个字，三个 `%v` 依次对应 `balance`、`money`、`note`。

       * 行尾必须带 `\n`，否则明细不会换行，全挤在一行里。

         ```text
         收支   账户金额   收支金额   说明
         收入   10100      100        发工资了
         收入   13100      3000       中大奖了
         ```

   * **登记支出**

       * 支出比收入多一条判断：余额不满足就不能处理，不能像收入那样直接加。

         ```go
         if money > balance {
             fmt.Println("余额不足")
             break
         }

         balance -= money
         ```

       * > **易错点**：这里的 `break` 只是退出了 `switch`，并没有退出 `for` 循环。

       * 支出金额等于余额是允许的，小于等于零也是不允许的。

       * 其余照抄登记收入那段，把「收入」改成「支出」即可。

## 项目代码的改进

   * **改进一：退出前二次确认**

       * 输 4 时不能马上把 `loop` 改成 `false`，要先问一句「你确定要退出吗」。

       * 必须输入 `y` 或 `n` 才放行，输入别的就一直循环提示。

         ```go
         case "4":
             fmt.Print("你确定要退出吗？y/n\n")
             choice := ""
             for {
                 fmt.Scanln(&choice)
                 if choice == "y" || choice == "n" {
                     break
                 }
                 fmt.Println("你的输入有误，请重新输入")
             }
             if choice == "y" {
                 loop = false
             }
         ```

       * 输 `n` 就什么都不做，`loop` 保持 `true`，主菜单继续打印。

   * **改进二：没有明细时不要只打印一个表头**

       * 定义一个标识符 `flag` 记录是否发生过收支，初始化为 `false`。

       * 成功的收入或成功的支出都把它置成 `true`。

         ```go
         case "1":
             fmt.Println("\n-----------------当前收支明细记录-----------------")
             if flag {
                 fmt.Println(this.details)
             } else {
                 fmt.Println("当前没有收支明细，来一笔吧")
             }
         ```

   * **改进三：余额不足给出提示**

       * 支出时若 `money > balance` 就提示余额不足，直接不处理。

## 改造成面向对象

   * **思路：把全部功能封装进一个结构体**

       * 结构体取名 `FamilyAccount`，把 `key`、`loop`、`balance`、`money`、`note`、`flag`、`details` 全部变成字段。

       * 工程分成两个文件夹，一个是 `main`，一个是 `utils`，工具类代码放在 `utils` 里。

         ```go
         package utils

         type FamilyAccount struct {
             key     string
             loop    bool
             balance float64
             money   float64
             note    string
             flag    bool
             details string
         }
         ```

   * **把功能拆成方法**

       * `MainMenu` 负责循环显示菜单、接收 `key`、`switch` 分派。

       * `showDetails` 打印明细，`income` 处理登记收入，`pay` 处理登记支出，`exit` 处理退出确认。

       * 把原来 `main` 里那一大坨代码拆成这几个方法才是面向对象的写法，否则一个方法写完显得很不专业。

   * **补上 this. 前缀，break 失效**

       * 字段变成结构体成员后，所有使用处都要加 `this.`，包括 `this.key`、`this.loop`、`this.flag`、`this.details`。

       * 接收者名随便起，叫 `this` 或叫别的都行，但所有地方都要和接收者名一致。

       * > **易错点**：拆成方法之后，原先 `switch` 里的 `break` 不能再用了，它已经跳不出调用方的 `switch`，金额不足时直接不处理即可，把 `break` 注释掉。

   * **工厂模式的构造方法**

         ```go
         func NewFamilyAccount() *FamilyAccount {
             return &FamilyAccount{
                 key:     "",
                 loop:    true,
                 balance: 10000.0,
                 money:   0.0,
                 note:    "",
                 flag:    false,
                 details: "收支\t账户金额\t收支金额\t说    明\t\n",
             }
         }
         ```

       * 结构体字段本身没有初始值，所以初始值要在这里返回实例时给全。

       * `flag` 默认 `false`，因为刚启动时还没有一笔收支。

   * **main 里只剩两行**

         ```go
         package main

         import (
             "fmt"
             "go_code/12/familyaccount/utils"
         )

         func main() {
             myFamilyAccount := utils.NewFamilyAccount()
             fmt.Println("这是面向对象的方式完成")
             myFamilyAccount.MainMenu()
         }
         ```

       * `MainMenu` 首字母大写，`showDetails`、`income`、`pay`、`exit` 都是小写，这本身也体现了封装。

       * 思路是：字段封装进结构体，功能绑定成方法，提供一个工厂方法返回实例，`main` 里创建实例再调主菜单。

   * **面向对象带来的两个好处**

       * 代码更清晰。原先所有功能塞在一个 `main` 里，功能一多就没法维护，改成结构体之后改起来也容易。

       * 便于项目分工。五个人写这个项目可以分成好几个结构体，每人写一个，主函数按需调用即可。

   * **课后扩展任务**

       * 增加转账功能，把一个账号的钱转给另一个账号。

       * 增加登录功能，必须输入用户名和密码验证通过才能使用记账软件。

## 客户信息管理系统需求

   * **为什么再写一个项目**

       * 家庭记账软件连数组都没用到，也没有程序结构，重点只是练 `for` 循环和分支判断，业务逻辑简单。

       * 客户信息管理系统要用到切片，比上一个稍微综合一些，难度更大。

   * **四项需求**

       * 模拟实现基于文本界面的客户信息管理软件。

       * 能对客户对象进行插入、修改、删除，并且能用切片实现。

       * 能打印客户明细表。

       * 客户个数不确定，可能 10 个也可能 100 个，所以用切片而不是数组，切片可以动态变化。

   * **界面**

         ```text
         -------------------客户信息管理系统-----------------
                          1 添加客户
                          2 修改客户
                          3 删除客户
                          4 客户列表
                          5 退出软件
         ------------------------------------------------
         ```

       * 添加客户要依次输入姓名、性别、年龄、电话、邮箱，最后提示「添加完成」。

       * 修改客户先选待修改客户的编号，直接回车表示不修改；修改时要把原先信息打印出来逐项改，不改就回车。

       * 删除客户先输入编号，再确认是否真删，输 `y` 才真的删除；编号不存在要提示「无该客户编号」。

       * 客户列表把当前所有客户信息一次性显示出来。

## 程序框架图

   * **定义**

       * > **定义**：程序框架图描述项目里有哪些文件，以及文件和文件之间的调用关系。

       * 软件公司做项目之前要先画它：项目经理或架构师给设计文档和功能模块划分，但每个模块内部的文件不一定给得那么细。

       * 程序员拿到模块后要把它拆开做，画出这个模块有几个文件以及文件之间的调用关系，还要按架构师要求分层。

       * 文件就是类，类就是文件。

   * **三层结构**

       * `customerView.go` 是界面层，负责显示界面、接收用户输入、根据输入调用 Service 完成管理。

       * 界面层虽然能改、能删、能显示，但它自己不真正做，实际是调用下一层完成的。

       * `customerService.go` 是业务处理层，真正执行增删改查并把结果返回给 View，内部持有一个 `Customer` 切片。

       * `customer.go` 是 Model 层，表示一个客户的信息，里面放客户的各个字段。

         ```text
         ┌──────────────────────────────────────────────────────┐
         │  customerView.go            界面层（View）           │
         │  ① 显示界面  ② 接收用户输入  ③ 调用 Service 完成管理 │
         │  自己并不真正做修改/删除/显示，只负责发起和呈现       │
         └───────────────────────┬──────────────────────────────┘
                                 │ 调用；View 持有一个 CustomerService 实例
                                 ▼
         ┌──────────────────────────────────────────────────────┐
         │  customerService.go        业务处理层（Service）     │
         │  增 / 删 / 改 / 显示 —— 真正执行，并把结果返回给 View │
         │  持有一个 Customer 切片                                │
         └───────────────────────┬──────────────────────────────┘
                                 │ 使用；Service 持有一个 Customer 切片
                                 ▼
         ┌──────────────────────────────────────────────────────┐
         │  customer.go               Model 层（表示数据）      │
         │  type Customer struct { Id / Name / Gender / ... }   │
         └──────────────────────────────────────────────────────┘
         ```

       * 三条线是自上而下的单向调用：View 调 Service，Service 用 Model，再由 Service 把结果返回给 View。

   * **分析顺序与编写顺序相反**

       * 分析时是从界面到业务逻辑再到 Model 层。

       * 开发时顺序刚好相反，先写 Model，再写 Service，最后写界面层。

   * **Customer 的字段从界面反推**

         ```go
         type Customer struct {
             Id     int
             Name   string
             Gender string
             Age    int
             Phone  string
             Email  string
         }
         ```

       * 界面上的客户列表要显示编号、姓名、性别、年龄、电话、邮箱六个信息，所以客户至少要有这六个字段。

       * > **提示**：结构体里有哪些字段、有哪些方法，完全由需求分析反推，需求说要显示哪些信息就提取哪些字段。

## 主菜单与退出

   * **目录结构**

       * 工程名叫 `customerManage`，下面建 `view`、`service`、`model` 三个包，分别放界面、业务逻辑和数据。

       * 写的时候从最下面的 `model` 开始往上写比较方便。

   * **model：Customer 与工厂方法**

         ```go
         package model

         type Customer struct {
             Id     int
             Name   string
             Gender string
             Age    int
             Phone  string
             Email  string
         }

         func NewCustomer(id int, name string, gender string,
             age int, phone string, email string) Customer {
             return Customer{
                 Id:     id,
                 Name:   name,
                 Gender: gender,
                 Age:    age,
                 Phone:  phone,
                 Email:  email,
             }
         }
         ```

       * 因为将来要在 `customerService` 里用它，所以工厂方法就定义在 `Customer` 所在的文件里。

       * 参数一多可以换行写，换行时逗号要保留在上一行。

       * > **提示**：报「无效的」字符类错误不要怕，先把内容放到记事本里清一遍去掉格式再粘回来就行，通常是粘贴时带进了特殊字符。

   * **service：先立一个结构体骨架**

         ```go
         package service

         import (
             "go_code/customerManage/model"
         )

         type CustomerService struct {
             customers   []model.Customer
             customerNum int
         }
         ```

       * 要对 `Customer` 做操作，结构体里必须有一个 `Customer` 切片，所有客户信息都存在这。

       * `customerNum` 记录目前有多少个客户、记住最大编号，以后新客户的编号就在它基础上加一。

   * **view：主菜单和退出**

         ```go
         type customerView struct {
             key  string // 接收用户的输入
             loop bool   // 表示是否循环地显示主菜单
         }

         func (this *customerView) mainView() {
             for {
                 fmt.Println("-----------------客户信息管理软件-----------------")
                 fmt.Print("请选择(1-5)：")
                 fmt.Scanln(&this.key)

                 switch this.key {
                 case "1":
                     fmt.Println("添 加 客 户")
                 case "5":
                     this.loop = false
                 default:
                     fmt.Println("你的输入有误，请重新输入...")
                 }

                 if !this.loop {
                     break
                 }
             }

             fmt.Println("你退出了客户关系管理系统...")
         }
         ```

       * 「请选择」用 `fmt.Print` 不带换行，其余用 `Println`。

       * 在主函数里创建实例并调用主菜单，结构体要实例化才能调方法：

         ```go
         func main() {
             customerView := customerView{
                 key:  "",
                 loop: true,
             }
             customerView.mainView()
         }
         ```

       * `package` 打的是 `main`，因为要在这放主函数；结构体名不大写是因为目前只在同一文件里用。

## 显示客户列表

   * **思路分析**

       * 客户信息其实就是切片，「返回客户信息」等价于「返回这个切片」。

       * `CustomerService` 里写 `List` 方法返回切片，`CustomerView` 里写 `list` 方法调 `List` 并打印。

       * View 要调 Service 的方法，View 就必须先持有一个 `CustomerService` 字段，所以 `CustomerService` 还要提供 `NewCustomerService` 返回实例。

   * **service 侧的两个核心方法**

         ```go
         func NewCustomerService() *CustomerService {
             customerService := &CustomerService{}
             customerService.customerNum = 1

             customer := model.NewCustomer(1, "张三", "男", 20, "112", "zhangsan@sohu.com")
             customerService.customers = append(customerService.customers, customer)
             return customerService
         }

         func (this *CustomerService) List() []model.Customer {
             return this.customers
         }
         ```

       * 初始化时先塞一个客户进去，不然运行起来是空列表，还以为代码写错了。

       * `customerNum` 默认给 1，这个字段留着后面分配新客户 ID 用。

       * > **易错点**：`append(切片, 元素)` 的第一个参数就是原来的切片，写成 `append(customerService.customers, customer)` 表示在这个切片基础上增加一个，返回值再赋回去。

       * > **提示**：`model.NewCustomer` 是函数名后面跟参数列表，`model.Customer` 才是类型名，两者只差一对小括号；不写包名报 `undefined`，当类型用报 `is not a type`。

   * **view 侧：先加字段再初始化**

         ```go
         type CustomerView struct {
             customerService *service.CustomerService
         }

         customerView.customerService = service.NewCustomerService()
         ```

       * `CustomerService` 在 `service` 包里，不在当前包，所以要先引包，标准写法是 `*service.CustomerService`。

       * 初始化的是 `customerService` 这一个字段，不是整个结构体；`NewCustomerService` 不需要传参数。

   * **view 侧的 list 方法**

         ```go
         func (this *CustomerView) list() {
             customers := this.customerService.List()

             fmt.Println("---------------------------客户列表---------------------------")

             for i := 0; i < len(customers); i++ {
                 fmt.Println(customers[i].GetInfo())
             }

             fmt.Println("-------------------------客户列表完成-------------------------")
         }
         ```

       * 先取数据、再打表头、遍历打印、最后打表尾，中间可以用 `\n` 拉开距离。

       * 菜单里输入 4 的位置改成 `this.list()` 即可。

   * **把格式化输出封装回 Customer**

         ```go
         func (this Customer) GetInfo() string {
             info := fmt.Sprintf("%v\t%v\t%v\t%v\t%v\t%v",
                 this.Id, this.Name, this.Gender,
                 this.Age, this.Phone, this.Email)
             return info
         }
         ```

       * 六个 `%v\t` 依次对应 ID、姓名、性别、年龄、电话、邮箱。

       * 接收者用值类型 `Customer` 而不是指针，因为只是读字段不需要改，没必要传地址。

       * 一个字段一个字段 `Printf` 也能跑，但六个字段要写六遍，字段一改就得回来改六处，封装成方法才体现价值。

       * > **结论**：有界面层、业务逻辑层、Model 层这种结构，代码的扩展性和可读性才会好；没有分层，程序稍微大一点就立刻看不懂。

## 添加客户

   * **service 侧的 Add**

         ```go
         func (this *CustomerService) Add(customer Customer) bool {
             this.customerNum++
             customer.Id = this.customerNum

             this.customers = append(this.customers, customer)
             return true
         }
         ```

       * 返回 `bool` 表示成功还是失败，一般不会失败所以直接返回 `true`。

       * Customer 实例在 View 层就已经构建好，Service 这一层只要把它塞进切片。

   * **ID 分配规则**

       * > **结论**：确定一条分配 ID 的规则，就是添加的顺序——添加的顺序就是它的 ID。

       * `Customer` 实例是在 View 层构建的，不让用户输入 ID，因为 ID 需要系统分配，就像注册 QQ 号不是自己指定的一样。

       * View 层的 `add` 只接收姓名、性别、年龄、电话、邮箱五项，构造 Customer 用一个不带 ID 的方法：

         ```go
         func NewCustomer2(name string, gender string, age int, phone string, email string) *Customer {
             customer := &Customer{
                 Id:     2,
                 Name:   name,
                 Gender: gender,
                 Age:    age,
                 Phone:  phone,

             return customer
         }
         ```

   * **view 侧的 add**

         func (this *CustomerView) add() {

## 删除客户

   * **两层确认**

       * 先确认「删谁」：提示输入待删除客户的编号，输入 `-1` 或直接回车都表示放弃，直接 `return`。

       * 再确认「真删吗」：输入 `y` 或 `Y` 才真的执行删除。

       * 编号不存在要提示「删除失败，输入的 id 号不存在，请重新输入」。

   * **必须额外写 FindById**

       * > **结论**：`FindById` 要返回的是客户在切片中的下标，因为最终是从切片里把这个客户干掉，不知道下标就没法删除。

       * 客户 ID 和切片下标不一定相等。ID 一直在增长，删掉一个再加新的，ID 会继续往上走。

         ```go
         func (this *CustomerService) FindById(id int) int {
             index := -1
             for i := 0; i < len(this.customers); i++ {
                 if this.customers[i].Id == id {
                     index = i
                     break
                 }
             }
             return index
         }
         ```

       * `index` 初值给 `-1` 表示找不到，找到就改成 `i` 并 `break`，找不到返回 `-1`。

       * > **提示**：用 `-1` 这个哨兵值让「找到」和「没找到」共用一个返回值，不用额外返回 bool 或定义错误变量，Go 里这种写法非常常见。

   * **Delete 与那段切片手术**

         ```go
         func (this *CustomerService) Delete(id int) bool {
             index := this.FindById(id)
             if index == -1 {
                 return false
             }
             this.customers = append(this.customers[:index], this.customers[index+1:]...)
             return true
         }
         ```

         ```text
         原切片:  [ c0 | c1 | c2 | c3 | c4 ]
                               ↑
                             index=2

         this.customers[:index]        → [ c0 | c1 ]        （不含 index）
         this.customers[index+1:]      → [ c3 | c4 ]
         append( 左, 右... )           → [ c0 | c1 | c3 | c4 ]
                                        ↑ c2 被干掉了
         ```

       * 左边截取到 `index` 但不含 `index`，右边从 `index+1` 取到末尾并展开成变参，两个拼起来正好补上被挖掉的洞。

   * **view 侧的 Delete**

         ```go
         func (this *CustomerView) Delete() {
             fmt.Println("删除客户")
             fmt.Print("请选择待删除的客户编号:")
             var id int
             id = -1
             fmt.Scanln(&id)
             if id == -1 {
                 return
             }

             fmt.Print("确认删除，请输入(Y/N):")
             var choice string
             fmt.Scanln(&choice)
             if choice == "y" || choice == "Y" {
                 if this.customerService.Delete(id) {
                     fmt.Println("删除完成")
                 } else {
                     fmt.Println("删除失败，输入的 id 号不存在，请重新输入")
                 }
             }
         }
         ```

       * `id` 默认给 `-1`，回车不改变它，所以 `id == -1` 时直接放弃删除。

       * > **提示**：这里没做输入循环，输的不是 `Y` 或 `N` 就不删除；前面学过用 `for` 循环重输，这个可以自己加进去。

       * 菜单里输入 3 的位置要改成 `this.Delete()`，不调用等于白写。

   * **编号空着是故意的**

       * 删除之后编号空着就空着，这个编号代表曾经被占用过，就不再复用。

       * 除非业务逻辑明确要求，否则不要把后面的客户往前挪来补号，因为编号是唯一标识一个人的标识，改了本人自己都不知道。

       * 比方说学校里的学号，有同学退学了所有人的学号不会跟着变，没有就没有了。

         ```text
         阶段                  Id          切片内容（Id）
         ---------------------------------------------
         刚初始化              1           [1]
         添加汤姆              2           [1, 2]
         再添加 Mary           3           [1, 2, 3]
         删除 2 号汤姆          —           [1, 3]      ← 下标塌陷
         添加史密斯             4           [1, 3, 4]
         ```

       * 删除后 3 号 Mary 的下标从 2 变成 1，但她的 Id 仍是 3；新来的史密斯 Id 是 4，下标却只有 2。

       * 所以 `FindById` 那一次遍历省不掉。

   * **本功能的改动清单**

       * model 层没有变化。

       * service 层增加了 `Delete` 和 `FindById` 两个方法。

       * view 层增加了 `Delete` 方法，并修改菜单分支调用它。

       * 本质是界面层只负责接收 ID、问一句是否真删，真正从切片里把客户干掉的还是 Service。

## 退出确认

   * **只动界面层**

       * 退出确认只涉及界面层，`CustomerService` 和 model 都不需要变化，只改 `customerView.go` 一个文件。

   * **exit 方法**

         ```go
         func (this *CustomerView) exit() {
             for {
                 fmt.Println("确认是否退出(Y/N):")
                 fmt.Scanln(&this.key)
                 if this.key == "Y" || this.key == "y" || this.key == "N" || this.key == "n" {
                     break
                 }
                 fmt.Println("你的输入有误，请重新输入(Y/N):")
             }

             if this.key == "Y" || this.key == "y" {
                 this.loop = false
             }
         }
         ```

       * 复用结构体里已有的 `key` 接收输入，不必再定义新变量。

       * 必须循环，因为输错就直接退出会出问题。

       * 跳出循环时值必然是 Y 或 N，是 Y 就把 `loop` 改成 `false`，是 N 就保持 `true` 继续显示主菜单。

   * **指针这一课又上了一遍**

       * > **结论**：`this` 是 `*CustomerView` 指针，这里改的 `this.loop` 和 `mainView` 里的 `this.loop` 是同一个，因为用的是同一个 `CustomerView` 实例。

       * > **易错点**：如果接收者不是指针类型，方法里改的 `this.loop` 和调用方看到的 `this.loop` 就不是同一个，退出功能会失效。

       * 道理和 Service 用 `*CustomerService` 完全一样，只是这次改的是「要不要继续循环」这个开关。

       * 菜单里输入 5 的位置要改成 `this.exit()`，不调用不好使。

## 修改客户作业

   * **功能说明**

       * 输入 2 提示输入新的客户信息，修改完毕后指定编号的客户带上新信息。

       * **ID 号不能改**，姓名、性别、年龄、电话、邮箱都可以改。

       * 好比银行卡可以改密码但绝对不能改卡号，卡号一改就不是这张卡了；QQ 号是唯一标识，分配后就不能改。

   * **实现路线**

       * 在 `CustomerService` 中新增 `Update` 方法，接收一个**含 ID 的**新 `Customer`，先用 `FindById(id)` 判断该 ID 是否存在。

       * 不存在直接返回 `false`，存在就用新信息替换切片中对应位置的客户，返回 `true`。

       * 在 `CustomerView` 中新增 `Update` 方法：接收用户输入的姓名、性别、年龄、电话、邮箱，构造出一个带 ID 的 `Customer`，再调 Service 的 `Update`。

       * 别忘了最后在菜单分支里把 `this.Update()` 调用上。

       * > **提示**：这条路线里唯一的新东西就是 `FindById` 返回的那个下标，它是把新信息塞回老位置的唯一桥梁；和 `Delete` 同理，Delete 是把它删掉，Update 是把它覆盖。
