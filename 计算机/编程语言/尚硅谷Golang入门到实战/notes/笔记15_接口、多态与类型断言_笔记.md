# 接口、多态与类型断言

## 接口的概念

   * **接口（Interface）**

       * > **定义**：接口是一组不需要实现的方法声明组成的类型，规定一组行为规范，谁来实现都行。

       * 现实里的 USB 插槽就是接口，插上手机还是相机它都不管，统一规则让它能自动识别。

       * Go 里多态主要通过接口实现，离开接口多态讲不明白，所以先讲接口再讲多态。

         ```go
         type Usb interface {
             Start()
             Stop()
         }
         ```

       * 有返回值的方法要把返回值写出来，没返回值就不用写。

   * **接口里只能有方法，不能有变量**

       * `interface` 类型里可以定义一组不需要实现的方法，但**不能包含任何变量**。

       * 别的编程语言接口里可以有常量，Go 的接口一个变量都不允许，写进去就是语法错误。

       * 自定义类型要用的时候再把这些方法写出来，写出来就叫实现。

   * **基本语法**

         ```go
         type 接口名 interface {
             Method1(参数列表) 返回值列表
             Method2(参数列表) 返回值列表
             ...
         }
         ```

       * 这一部分叫函数的签名，实现时的签名必须和接口里的完全一致。

       * 实现有两层含义：把方法的具体内容写出来，并且把接口里所有方法都实现。

## 接口的实现规则

   * **实现了接口就是实现了全部方法**

       * > **定义**：所谓「实现了某接口」，指的就是实现了该接口声明的所有方法，缺一不可。

       * 不能只实现接口里的一个方法就说实现了这个接口。

       * 自定义类型可以是任意的，`Phone` 可以实现，`Camera` 也可以实现。

   * **两条硬规则**

       * 第一条，接口里所有的方法都不能有方法体，多写一句话就是语法错误。

       * 第二条，Go 中不需要显式实现接口，没有 `implements` 这样的关键字。

       * 写 `Phone` 和 `Camera` 时完全不用声明「我在实现 `Usb`」，把方法写了接口就满足了。

       * > **结论**：只要一个变量含有接口类型中的所有方法，这个变量就实现了该接口。

   * **基于方法，而不是基于接口本身**

       * 再定义一个同样含 `Start` 和 `Stop` 的 `Usb2`，`Phone` 和 `Camera` 照样实现了 `Usb2`。

       * 接口叫什么名字它并不关心，只要里面的方法都实现了就算实现。

       * 一个类型因此可以同时实现多个接口，这在显式实现的语言里是做不到的。

       * 接口的方法一旦少实现一个就报错，缺方法时报 `cannot use phone (type Phone) as type Usb2 in value`。

## 接口的使用场景

   * **专家定规范，别人来实现**

       * 造飞机时专家只负责把功能和规格定下来，让别人去实现。

       * 一个结构体方法很多时全交给一个人写不合适，项目经理定义接口，大家分别实现，便于控制进度和规范化开发。

   * **sort 包：接口早就用在你身上**

       * `sort` 包的 `Sort` 接收一个 `Interface`，任何实现了这个接口的类型都能传进去排序。

       * 里面要实现 `Len`、`Less`、`Swap` 三个方法，实现了 `Sort` 就替你把排序做完，怎么排序不用你管。

       * 结构体变量的数组也可以实现这个接口。

## 接口的十条细节

   * **接口本身不能实例化**

       * 接口不能定义变量、不能直接创建实例，空着的接口变量调用方法会报无效地址和空指针。

       * 但它可以指向一个实现了该接口的自定义类型的变量。

         ```go
         type Stu struct {
             Name string
         }

         func (stu Stu) Say() {
             fmt.Println("Stu Say()")
         }

         var stu Stu
         var a AInterface = stu
         a.Say()
         ```

       * 类型没实现方法就赋值会报 `stu does not implement AInterface (missing method Say)`。

   * **任何自定义类型都能实现接口**

       * 只有自定义数据类型才能实现接口，不限于结构体。

         ```go
         type integer int

         func (i integer) Say() {
             fmt.Println("integer Say i =", i)
         }

         var i integer = 10
         var b AInterface = i
         b.Say()
         ```

       * `integer` 的变量间接实现了 `AInterface`，输出 `integer Say i = 10`。

   * **一个自定义类型可以实现多个接口**

       * 一个类型既实现 `AInterface` 的 `Say`，又实现 `BInterface` 的 `Hello`，同一个实例可以赋给两个接口变量。

       * > **易错点**：赋给 `AInterface` 后可以用它调 `Say`，但不能点 `Hello`，接口变量能调哪些方法取决于它的静态类型是哪个接口。

   * **接口中不能有任何变量**

       * 在接口里随便写一个成员，比如 `Name`，保存就报语法错误，不管什么类型都不准放进去。

   * **接口之间也能继承，而且必须全部实现**

       * 一个接口可以继承多个别的接口，嵌进去之后要实现这个接口，就得把被嵌接口的所有方法也全部实现。

         ```go
         type BInterface interface {
             test01()
         }

         type CInterface interface {
             test02()
         }

         type AInterface interface {
             BInterface
             CInterface
             test03()
         }
         ```

       * 用一个 `Student` 把 `test01`、`test02`、`test03` 都实现了，赋值成功。

       * 去掉任何一个方法都会报 `Student does not implement`，缺一不可，这是强制要求。

       * 实现了 `AInterface` 的类型同时也实现了 `BInterface` 和 `CInterface`，但用 `BInterface` 的变量只能调 `test01`，调不了 `test02`。

   * **interface 是引用类型**

       * `interface` 类型默认是指针，是引用类型，没初始化就是 `nil`，直接使用会报错。

       * 把结构体传给接口形参时是按引用方式传过去的，接收的其实是地址。

   * **空接口能接一切**

       * > **定义**：空接口是 `interface{}`，没有任何方法，因此所有类型都实现了空接口。

         ```go
         type T interface {
         }

         var stu Student
         var t T = stu
         var t2 interface{} = stu
         ```

       * 可以把任何一个数据类型的变量赋给空接口，空接口形参能接收任何一种数据类型。

       * `interface{}` 本身也可以直接当类型用，效果与自定义的空接口类型一致。

## 三道判断题

   * **同一个类型赋给两个方法重叠的接口**

       * `AInterface` 有 `test01`、`test02`，`BInterface` 有 `test01`、`test03`，`Student` 三个都实现了。

       * 把 `stu` 分别赋给 `A` 和 `B` 两句都 OK，编译通过。

       * 两个接口里都有 `test01` 也无所谓，`test01` 属于哪个接口根本无所谓，但方法签名必须完全一致。

   * **接口继承后出现重复方法**

       * `CInterface` 同时继承 `AInterface` 和 `BInterface`，而这两个接口里都有 `test01`，代码编译不过。

       * 报错是 `duplicate method test01`，接口里绝对不允许出现相同的方法名。

   * **指针接收者与值变量的匹配**

       * 接口 `Usb` 有方法 `Say`，`Student` 用 `func (this *Student) Say()` 实现，写 `var u Usb = stu` 会报错。

       * 编译器会补一句 `Say method has pointer receiver`，提示应该传什么类型。

       * 改成 `var u Usb = &stu` 就正确了，其余调用不变。

       * > **结论**：接口方法用什么接收者定义，就只能用相应的类型去赋值。值接收者的方法 `T` 和 `*T` 都能满足，指针接收者的方法只有 `*T` 满足。

## 接口编程的经典案例

   * **从 int 切片到结构体切片**

       * `sort.Ints` 直接对 int 切片排序，因为切片是引用类型，不需要加地址，外面立刻跟着变。

       * 结构体切片用 `sort.Sort`，它接收一个 `Interface`，实现 `Len`、`Less`、`Swap` 三个方法就能排。

       * `Sort` 内部调 `data.Len()`，默认走快速排序，快速排序里再用 `Less` 判断、再调 `Swap` 交换。

       * > **结论**：只要自定义类型实现了这三个方法，就能直接交给 `sort.Sort` 排序，不管你是什么类型。

   * **实现三个方法**

         ```go
         type Hero struct {
             Name string
             Age  int
         }

         type HeroSlice []Hero

         func (hs HeroSlice) Len() int {
             return len(hs)
         }

         func (hs HeroSlice) Less(i, j int) bool {
             return hs[i].Age < hs[j].Age
         }

         func (hs HeroSlice) Swap(i, j int) {
             temp := hs[i]
             hs[i] = hs[j]
             hs[j] = temp
         }
         ```

       * 必须声明成切片类型，因为只有切片里才能放多个 `Hero`。

       * 交换要自己写，因为快速排序是通过接口来调 `Swap`，它只管喊，具体怎么换是实现者的事。

       * > **易错点**：接收者必须写成 `func (hs HeroSlice)`，写成 `func hs HeroSlice` 会直接报语法错。

       * 造数据时 `append` 有返回值必须接住再赋回去，`rand.Intn` 在 `math/rand` 包下，别导错包。

       * 注释掉任意一个方法就会报 `HeroSlice does not implement sort.Interface`。

   * **Less 决定排序标准**

       * `Less(i, j)` 的语义是「i 该排在 j 前面就返回 `true`」。

       * 按年龄升序返回 `hs[i].Age < hs[j].Age`，降序把比较号反过来返回 `>`。

       * 换成按姓名排只改这一行，返回 `hs[i].Name < hs[j].Name`。

       * 条件更复杂的排序只要能返回一个布尔值，同样能排。

       * > **结论**：接口编程的思路是把可以放开的部分做成接口留给别人，把最核心的代码握在自己手里。

       * `Less` 放开别人才能告诉你按什么标准排，`Swap` 放开才能适配各种类型，`quickSort` 这种核心算法必须留在内部。

   * **多值交换**

         ```go
         hs[i], hs[j] = hs[j], hs[i]

         i := 10
         j := 20
         i, j = j, i    // i = 20, j = 10
         ```

       * 这行和用临时变量交换完全等价，含义就是「把 j 给 i，把 i 给 j」。

## 接口与继承的比较

   * **接口是对继承的补充**

       * > **定义**：结构体继承另一个结构体就自动拥有对方的字段和方法；想扩展功能又不破坏继承关系，就用实现接口的方式，接口是对继承的补充。

         ```text
                         ┌───────────────────────────┐
                         │   Monkey（老猴子）         │
                         │   字段：Name              │
                         │   方法：climbing()        │
                         └─────────────┬─────────────┘
                                       │  匿名结构体嵌入
                                       │  → 字段与方法自动获得
                         ┌─────────────▼─────────────┐
                         │  LittleMonkey（小猴子）   │
                         └─────────────┬─────────────┘
                                       │  实现接口（不破坏继承）
                       ┌───────────────┴───────────────┐
            implements │                               │ implements
            ┌──────────▼──────────┐     ┌─────────────▼──────────┐
            │  BirdAble           │     │  FishAble              │
            │  Flying()           │     │  Swimming()            │
            └─────────────────────┘     └────────────────────────┘
         ```

       * 横向那条线是继承，小猴子一行代码都不用写就拿到了 `Name` 和 `climbing()`。

       * 纵向那两条线是实现接口，飞翔和游泳是小猴子额外扩展出来的，`Monkey` 一行都没被改。

   * **不能写在 Monkey 上的 Flying**

         ```go
         type BirdAble interface {
             Flying()
         }

         func (this *LittleMonkey) Flying() {
             fmt.Println(this.Name, "通过学习，会飞翔了...")
         }

         type FishAble interface {
             Swimming()
         }

         func (this *LittleMonkey) Swimming() {
             fmt.Println(this.Name, "通过学习，会游泳了...")
         }
         ```

       * 猴子本身不会飞，把 `Flying` 绑到 `Monkey` 上不合理。

       * `climbing` 是小写方法名属于未导出，但它定义在同一个包内，所以完全能用。

   * **继承搞不定的一种需求**

       * 运动员被篮球运动员和足球运动员继承，学生被大学生和中学生继承，现在要求足球运动员和大学生掌握英语。

       * 写在 `运动员` 上会强迫篮球运动员学英语，写在 `学生` 上会强迫中学生学英语。

       * 直接写在子类上虽然满足了需求，但足球运动员和大学生各写一份，规范性没有保证。

       * 定义一个「学习英语的技能」接口让这两类去实现，好处是解耦和规范性都有。

   * **三个对比维度**

       * | 关系维度 | 继承 | 接口 |
         | --- | :--- | :--- |
         | 着重解决 | 复用性、可维护性 | 设计，事先定好规范 |
         | 关系强弱 | is-a，强绑定 | like-a，松散耦合 |
         | 波及范围 | 父结构体加方法，所有子类被迫获得 | 谁实现谁生效，不影响别人 |

       * 继承的价值是复用性和可维护性，被继承的一方加一个方法，改一处全都拥有。

       * 接口的价值在于设计，事先把规范定好，其他自定义类型来实现。

       * 继承满足 is-a，接口满足 like-a，猴子不是鸟但可以像小鸟一样飞翔。

       * 在 `LittleMonkey` 上定义了 `Flying` 却没写任何「正在实现 `BirdAble`」的声明，靠方法签名一致就算实现，所以接口在一定程度上解耦。

## 多态

   * **多态参数**

       * 多态指变量或实例具有多种形态，在 Golang 里多态通过接口实现。

       * 同一个 `usb` 变量传 `Phone` 就呈现 `Phone` 形态，传 `Camera` 就呈现 `Camera` 形态，调用方不需要区分。

         ```text
                   Working(usb Usb)
                          │
           ┌──────────────┴──────────────┐
           │                             │
      usb = Phone{"vivo"}          usb = Camera{"尼康"}
           │                             │
      usb 呈现 Phone 形态         usb 呈现 Camera 形态

      同一个接口变量 usb，不同的实参 → 不同的形态
         ```

   * **多态数组**

       * > **定义**：多态数组就是一个接口类型的数组，里面可以存放实现了该接口的任何结构体变量。

         ```go
         var usbArr [3]Usb

         fmt.Printf("%T %T %T\n", usbArr[0], usbArr[1], usbArr[2])

         usbArr[0] = Phone{"vivo"}
         usbArr[1] = Phone{"小米"}
         usbArr[2] = Camera{"尼康"}
         ```

       * 不用赋值之前三个元素都是 `nil`。

       * 普通数组只能放一种类型，用了接口才能一个数组里放两种结构体。

## 类型断言

   * **基本形式**

       * > **定义**：`b = a.(Point)` 表示判断 `a` 是否指向一个 `Point` 类型的变量，是就转成 `Point` 赋给 `b`，否则报错。

       * 接口是一般类型不知道具体类型，要转成具体类型就需要类型断言。

         ```go
         var a interface{}
         p := Point{1, 2}
         a = p

         var b Point
         b = a       // 编译报错：missing type assertion
         b = a.(Point)
         ```

       * 转换不成功就报错，必须清楚原接口里装的是什么类型才能转回来。

       * > **易错点**：转换不是想怎么转就怎么转，`x` 里装的是 `float32` 却断言成 `float64`，直接 panic。

   * **带检测的类型断言**

       * 断言失败会 panic，程序直接退出，后面的代码执行不了。

       * 用一个布尔变量接收结果，失败也不会崩溃：

         ```go
         var y float64
         y, ok = x.(float64)
         if ok {
             fmt.Println("convert OK")
         } else {
             fmt.Println("转换失败")
         }
         fmt.Println("继续执行")
         ```

       * 更简洁的写法是把断言直接写在 `if` 后面用分号隔开：`if y, ok = x.(float64); ok {`。

       * 布尔变量叫 `ok` 还是 `flag` 都行，`ok` 本身就是布尔类型，写 `if ok == true` 是画蛇添足。

   * **遍历多态数组调用特有方法**

       * `Phone` 有一个接口里没有的特有方法 `Call`，`Camera` 没有。

       * 直接写 `usb.Call()` 不行，编译器报 `usb.Call undefined`；就算把它加进接口也违背了接口只描述共性的原则。

         ```go
         func (c Computer) Working(usb Usb) {
             usb.Start()
             if phone, ok := usb.(Phone); ok {
                 phone.Call()
             }
             usb.Stop()
         }
         ```

       * 是手机就输出「手机开始工作、手机打电话、手机停止工作」，是相机时断言失败跳过 `Call`，不报 panic 也照常运行。

       * 断言语句里的变量名不是必须叫 `phone`，写 `a`、`b` 都行，只是为了好读。

   * **通用类型判断函数**

         ```go
         func TypeJudge(items ...interface{}) {
             for index, x := range items {
                 switch x.(type) {
                 case bool:
                     fmt.Printf("第%v个参数是 bool类型，值是%v\n", index, x)
                 case float32:
                     fmt.Printf("第%v个参数是 float32类型，值是%v\n", index, x)
                 case float64:
                     fmt.Printf("第%v个参数是 float64类型，值是%v\n", index, x)
                 case int, int32, int64:
                     fmt.Printf("第%v个参数是 整数类型，值是%v\n", index, x)
                 case string:
                     fmt.Printf("第%v个参数是 string类型，值是%v\n", index, x)
                 default:
                     fmt.Printf("第%v个参数类型不确定，值是%v\n", index, x)
                 }
             }
         }
         ```

       * 参数用 `...` 表示可变参数，类型是空接口，所以能接任意多个任意类型的实参。

       * 一个 `case` 可以列多个类型，`int, int32, int64` 会一起命中并统一报成整数类型。

       * > **易错点**：`switch x.(type)` 里的 `type` 是关键字固定写法，不是某个类型名，它判断的是「`x` 断言之后到底是什么类型」。

       * > **提示**：每条格式串末尾都要有 `\n`，否则全部打到一行，输出就乱了。

       * 自定义类型也能判断，在 `switch` 里再加 `Student` 和 `*Student` 两个 case 即可，能区分值类型和指针类型。

       * 类型定义写在 `case` 后面也能跑，因为调用时该类型已加载到内存，但把定义写在前面对代码理解更友好。

## 项目开发的六个阶段

   * **六个阶段**

       * 需求分析、设计、代码实现、测试、实施、维护。

       * 实现和测试不是「全部写完再测试」，而是螺旋递增的关系，一轮一轮往上走。

         ```text
         需求分析 ──► 设计 ──► 实现 ──► 测试
                       ▲                 │
                       └──── 螺旋递增 ────┘

            一边写代码，一边测试
            先有单元测试，后面还有集成测试
         ```

       * 维护阶段存在是因为实施之后不敢保证项目绝对没问题，再大的软件也会有 bug 和漏洞补丁。

   * **时间怎么分配**

       * 没有很标准的比例，项目大小决定分配，小项目可能需求分析都没有直接写代码。

       * | 阶段 | 大项目的大致时间占比 |
         | --- | :--- |
         | 需求分析 | 30% |
         | 设计 | 20% |
         | 实现 | 20% |
         | 测试 | 30% |

   * **需求分析**

       * 由需求分析师做，必须懂技术但技术不一定最强，关键是懂业务，一般要到对方公司常驻。

       * 最终产物是需求分析报告，搞清楚对方到底要做成什么样的东西。

   * **设计**

       * 由项目经理或架构师负责，架构要定技术选型、操作系统、框架、数据库，还要考虑服务器集群撑不撑得住。

       * 项目经理还要选人，人选得好坏直接影响项目成绩和个人去留。

       * 最终产物是设计文档，最重要的是各种图和数据库设计，数据库是一个项目的核心。

       * 原型开发要求界面原型必须出来，好处是可以直接跟决策方沟通确认样子和功能。

   * **实现**

       * 由软件工程师承担，就是把画好的各个模块实现出来。

   * **测试**

       * 由软件测试工程师测开发工程师的代码，看好不好用，不好用就打回重写。

       * 测试工程师至少要会黑盒测试、白盒测试和灰盒测试。

       * 黑盒测试必须写出稳定的复现步骤，「点什么再点什么然后出错」才是有效 bug，时有时无的错误最难查。

       * 白盒测试要写代码、懂代码，所以不少测试工程师开始学编程。

   * **实施**

       * 由实施工程师负责，项目上架上线、搭服务器、各种配置。

       * 这类岗位常要出差，对体力有要求。

   * **维护**

       * 一般没有专职人员，由对接人接收用户反馈的问题，再做调试和修改。
