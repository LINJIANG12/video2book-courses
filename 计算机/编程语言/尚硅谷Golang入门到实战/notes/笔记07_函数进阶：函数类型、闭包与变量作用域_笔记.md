# 函数进阶：函数类型、闭包与变量作用域

## 函数本身也是一种数据类型

* **函数赋给变量**

    * > **定义**：在 Go 中函数也是一种数据类型，它的地位和 `int`、`string` 一样，函数本身可以赋给一个变量，该变量就是函数类型的变量。

      ```go
      func getSum(n1 int, n2 int) int {
          return n1 + n2
      }

      func main() {
          a := getSum

          fmt.Printf("%T\n", a)
          fmt.Printf("%T\n", getSum)

          res := a(10, 40)
          fmt.Printf("res = %v\n", res)
      }
      ```

    * `a` 和 `getSum` 打印出来的类型都是这个函数类型，因为已经把 `getSum` 交给了 `a`，两者都指向同一块代码空间。

    * 通过该变量完成调用 `res := a(10, 40)` 与 `res := getSum(10, 40)` 完全等价，结果是 `res = 50`。

    * 这个特性在闭包里还会用到。

* **函数作为形参**

    * > **定义**：函数既然是一种数据类型，在 Go 中函数就可以作为形参并调用。

      ```go
      func myFun(funvar func(int, int) int, number1 int, number2 int) int {
          return funvar(number1, number2)
      }
      ```

    * `funvar func(int, int) int` 表示 `funvar` 的数据类型是一个函数类型，`number1`、`number2` 传两个整型过来。

    * 函数体里直接 `return funvar(number1, number2)`，通过形参来调用它。

    * 调用 `res2 := myFun(getSum, 50, 60)`：把 `getSum` 交给形参 `funvar`，50、60 传给两个整型形参，50 + 60 = 110，所以 `res2` 等于 110。

    * > **易错点** ⚠️：这里不能去掉冒号，否则相当于把返回值直接交给一个尚未定义的 `res2`，会报 `res2` 没有定义；确实要用就先 `var res2 int` 再赋值，但一般直接用类型推导更省事。

* **自定义数据类型**

    * > **定义**：为了简化数据类型的定义，Go 支持自定义数据类型，语法是 `type 自定义数据类型名 数据类型`。

    * 可以理解为给类型取个别名：`type myInt int` 让 `myInt` 等价于 `int`；`type mySum func(int, int) int` 让 `mySum` 等价于一个函数类型。

    * 在 Go 里 `int` 和 `myInt` **不是同一个类型**，Go 从语法上认为它们是两个不同的数据类型。

      ```go
      type myInt int

      var number2 int
      number2 = number1   // 报错：不能把 myInt 直接赋给 int
      number2 = int(number1) // 需要显式转换
      ```

    * > **注意**：转换时依然需要显式转换，不写转换就会出错。

    * 给函数类型起名字可以把冗长的形参声明简化：

      ```go
      type myFunType func(int, int) int

      func myFun(funvar myFunType, number1 int, number2 int) int {
          return funvar(number1, number2)
      }
      ```

    * > **易错点**：`type` 必须提到 `main` 函数外面，至少要提到 `main` 前面；写在 `main` 函数内部，其它地方识别不到，编译器直接报未定义。

* **给返回值命名**

    * > **定义**：Go 语言支持对函数返回值命名，形参位置上直接写 `sum int, sub int` 这样的名字。

      ```go
      func getSumAndSub(n1 int, n2 int) (sum int, sub int) {
          sum = n1 + n2
          sub = n1 - n2
          return
      }
      ```

    * 函数体里写 `sum = n1 + n2` 时不要再写 `:=`，因为名字已经定好，编译器在调用时已经把这两个返回值的创建工作做好了，只是默认为空、默认为 0。

    * 最后直接 `return`，不用再写后面还有 `sum`、`sub`。

    * 这样顺序就无所谓了：`a, b := getSumAndSub(1, 2)` 输出 `a=3 b=-1`，调换内部计算顺序也不影响。

    * > **易错点**：接收用的变量名不要和前面的名字冲突；如果 `a` 之前已经被定义成函数类型，再把返回的 `sum` 交给它就会类型不符，换个名称即可。

* **下划线忽略返回值**

    * > **定义**：下划线 `_` 可以作为**占位符来忽略返回值**，它出现的位置就是返回值的位置——左边不留，右边用 `_` 顶替。

    * 只想取两个返回值中的一个时用 `result3, _ = ...`；两个都不要就直接调用、不接收。

## 可变参数

* **基本写法**

    * > **定义**：Go 中支持可变参数，可以支持 0 到多个参数；写法是 `args ...int`，三个点缺一不可，是固定的写法。

    * 前面的参数名字可以随意，后面是数据类型；要支持 1 到多个参数，就前面写固定参数、后面加可变参数。

    * > **提示**：`args` 本质是一个切片（slice），可以暂时理解成动态数组；访问第几个参数用 `args[index]`，参数名并不固定叫 `args`。

    * 求 1 到多个 `int` 的和：

      ```go
      func sum(n1 int, args ...int) int {
          sum := n1
          for i := 0; i < len(args); i++ {
              sum += args[i]
          }
          return sum
      }
      ```

    * `n1 int` 不是可变参数，一定写在第一位；默认值就是 `n1`，只传一个值时 `n1` 就是整个和。

    * 因为事先不知道传了多少个参数，所以要用 `for` 循环遍历：`len(args)` 拿长度，`args[0]` 取第一个元素，其余依此类推。

    * `sum(10)` 得 10；`sum(10, 0, -1, 90, 10)` 得 109。

    * > **易错点** ⚠️：遍历时 `args[i]` 的 `i` 千万别漏写成 `args[0]`，也别忘了先声明循环变量 `i`，写成了固定的 0 就不再是遍历。

    * 参数名可以改成 `vars` 等等，通常还是按约定俗成取 `args`。

    * 可变参数的数据类型也不限于 `int`，可以是 `string` 或其他。

* **可变参数必须放在最后**

    * 把可变参数写在前面、固定的写在后面是不支持的，会报 `can only use ... with final parameter in list`。

    * > **定义**：Go 中如果一个函数的形参列表中有可变参数，可变参数一定要放在形参列表的最后，否则语法通不过。

* **课堂练习：同类型形参省略与类型不匹配**

    * 形参 `n1, n2 float32` 返回 `float32` 是合法的：同类型形参前面可以都省略，只在最后写一次数据类型。

    * `myFun(a, 1, 2)` 是 OK 的，因为 `a` 的数据类型是 `myFunType`，签名与两个 `int` 形参返回一个 `int` 的函数对得上。

    * `myFun(b, 1, 2)` 则报错，因为 `b` 指向的 `sum2` 是三个 `int` 形参返回一个 `int`，与 `myFunType` 类型不匹配。

    * 错误原因就是**类型不匹配**，不能把这个函数类型赋给这种自定义类型。

* **课堂练习：指针交换两个变量**

    * 题目要求交换 `n1` 和 `n2` 的值，必须用指针接收，否则是值拷贝交换不了外层变量——题面漏写的那两个星号是出题时的疏忽。

      ```go
      func swap(n1 *int, n2 *int) {
          t := *n1
          *n1 = *n2
          *n2 = t
      }

      func main() {
          a := 10
          b := 20
          swap(&a, &b)
          fmt.Printf("a=%v b=%v\n", a, b)
      }
      ```

    * 逻辑是先把 `*n1` 交给临时变量 `t`，再把 `*n2` 交给 `*n1`，最后把 `t` 交给 `*n2`。

    * 形参是指针，所以传递时得传地址；输出要用 `Printf` 才是格式化输出。

    * 运行结果是 `a=20 b=10`，交换成功。

## init 函数

* **定义与执行顺序**

    * > **定义**：每一个源文件中都可以包含一个 `init` 函数，该函数会在 `main` 函数执行之前被 Go 运行框架调用，通常用来做初始化的工作。

    * 一个文件里同时有变量定义、`init` 函数和 `main` 函数时，执行流程是：**先执行变量定义，再执行 `init` 函数，最后执行 `main` 函数**。

      ```go
      var age = test()

      func test() int {
          fmt.Println("test()...")
          return 90
      }

      func init() {
          fmt.Println("init()...")
      }

      func main() {
          fmt.Println("main()...")
          fmt.Println("age=", age)
      }
      ```

      ```text
        ┌──────────────────────────────────┐
        │  源文件中的三样东西               │
        ├──────────────────────────────────┤
        │  var age = test()   ←  变量定义  │  第 1
        │  func init() {...}  ←  init     │  第 2
        │  func main() {...}  ←  main     │  第 3
        └──────────────────────────────────┘
      ```

    * 直接定义变量没有输出不好验证，所以用一个会打印的 `test()` 赋给全局变量 `age`；运行时 `test()` 最先输出，然后是 `init()`，最后是 `main()`，且 `age` 等于 90。

* **在 init 里初始化全局变量**

    * `utils` 包里定义两个全局变量 `Age int` 和 `Name string`，再用 `init` 给它们赋初值，这样 `main.go` 引入包后直接用就已经是初始化好的。

      ```go
      package utils

      var Age int
      var Name string

      func init() {
          Age = 100
          Name = "tom~"
      }
      ```

    * `main` 里 `fmt.Println("age=", utils.Age, "name=", utils.Name)` 打印出 `100` 和 `tom~`，说明引包的过程里它其实已经先初始化了。

    * 变量名首字母必须大写才能在别的包里取到。

    * 在 `utils` 包里也加一句打印可以看到，最先执行的是 `utils` 包里的 `init`，然后是 `test`，然后是 `init`，最后是 `main`——**被引入的包先执行**。

* **跨文件的执行顺序**

    * > **定义**：`main.go` 引入了 `utils.go`，两者都含变量定义和 `init` 函数时，先执行被引入文件的部分，再执行自己的部分。

      ```text
        main.go  引入了  utils.go

        ┌────────────────────────────────────────────┐
        │ 1  被引入文件（utils.go）里的变量定义        │
        │ 2  被引入文件（utils.go）里的 init 函数     │
        │ 3  main.go 里的变量定义                     │
        │ 4  main.go 里的 init 函数                  │
        │ 5  main.go 里的 main 函数                  │
        └────────────────────────────────────────────┘
      ```

    * 如果 `utils.go` 又引入了别的文件，规则一样：先执行那个文件的变量定义和 `init`，再回来执行 `utils` 的变量定义和 `init`，最后执行主函数。

## 匿名函数

* **定义**

    * > **定义**：匿名函数就是没有名字的函数；某个函数只是希望使用一次时可以考虑用匿名函数。

    * > **结论**：匿名函数的使用方式只有两种——定义时直接用，或者赋给一个变量再通过变量调用。

* **定义时就直接调用**

      ```go
      res1 := func (n1 int, n2 int) int {
          return n1 + n2
      }(10, 20)

      fmt.Println("res1=", res1)
      ```

    * 没有函数名，直接写形参和返回值类型；调用方式是直接用括号括起来在后面传参，用变量 `res1` 接收。

    * 前半段 `func (n1 int, n2 int) int { return n1 + n2 }` 是定义，后面的 `(10, 20)` 是调用。

    * 运行结果 `res1 = 30`。

    * > **易错点**：这种方式匿名函数只能调用一次，因为既没给名字也没交给变量，调过之后再想调就没有机会了。

* **赋给一个变量再调用**

      ```go
      a := func (n1 int, n2 int) int {
          return n1 - n2
      }

      res2 := a(10, 30)
      res3 := a(90, 30)
      ```

    * 把匿名函数赋给 `a` 之后，`a` 就是一个函数变量，数据类型是函数类型，可以通过 `a` 反复调用：`res2` 等于 -20，`res3` 等于 60。

    * > **提示**：`a` 不是一个函数名，它就是一个函数变量；虽然写的是赋值语法，但效果上等同于定义了一个函数。

    * 这种方式还有一个价值：一般情况下在 `main` 里面单独定义函数语法通不过，通过这种方式就**可以在一个函数里面再定义一个函数**。

* **全局匿名函数**

    * 把匿名函数赋给一个全局变量，这个匿名函数就称为**全局匿名函数**，可以在整个程序中有效。

      ```go
      var (
          // Fun1 就是一个全局匿名函数
          Fun1 = func (n1 int, n2 int) int {
              return n1 * n2
          }
      )

      func main() {
          res4 := Fun1(4, 9)
          fmt.Println("res4=", res4)
      }
      ```

    * 变量名首字母要大写才在整个程序有效；`res4 := Fun1(4, 9)` 输出 36。

## 闭包

* **闭包的定义与构成**

    * > **定义**：闭包是一个**函数与其相关的引用环境组成的一个整体**，或者说一个实体。

    * 闭包本质上返回的是个函数，但这个函数会用到函数外的一些变量，它们共同组成一个整体，这个整体就是闭包。

* **累加器案例**

      ```go
      func AddUpper() func (int) int {
          var n int = 10
          return func (x int) int {
              n = n + x
              return n
          }
      }

      func main() {
          f := AddUpper()
          fmt.Println(f(1)) // 11
          fmt.Println(f(2)) // 13
          fmt.Println(f(3)) // 16
      }
      ```

    * `AddUpper` 返回的数据类型是 `func(int) int`，也就是返回一个函数。

    * 关键点在于 `var n int = 10`：返回的匿名函数引用到了函数外的 `n`，因此这个匿名函数和 `n` 形成引用关系、共同组成闭包。

    * 反复调用会累加，是因为 `n` 只初始化一次，不会每次进来重新定义。

    * `f(1)` 是 10 + 1 = 11；`f(2)` 不是 12，因为 `n` 已经是 11，11 + 2 = 13；`f(3)` 是 13 + 3 = 16。

    * 可以把返回的函数理解成一个类：这个函数是一个**操作**，而 `n` 相当于它的一个**字段**。

    * > **结论**：分析闭包的关键就是**分析清楚函数返回的那个函数引用到了哪些变量**——函数和它引用到的变量共同构成闭包；引用的环境变量不会每次调用都重新初始化，而是在此基础上不停累加。

    * 把外部变量换成字符串 `str = "hello"`、函数内 `str += x` 同样是这个规律：第一次拼接 `"hello1"`，第二次在原有基础上继续拼。

    * > **易错点**：拼接如果用的是整数，`1` 会被转成 ASCII 码对应的字符，`1` 对应的是一个笑脸；换成 `36` 就对应可见字符 `$`，第一次拼出一个 `$`、第二次两个 `$`、第三次三个 `$`。

* **闭包最佳实践：给文件名补后缀**

    * 需求是写一个函数 `makeSuffix`，参数接收一个文件后缀名（如 `.jpg`），返回一个闭包；调用闭包时传入文件名，没有该后缀就加上，已有该后缀就返回原文件名。判断用 `strings` 包的 `HasSuffix`。

      ```go
      func makeSuffix(suffix string) func(string) string {
          return func(name string) string {
              // 如果没有指定的后缀，则加上；否则按原名字返回
              if !strings.HasSuffix(name, suffix) {
                  return name + suffix
              }
              return name
          }
      }

      func main() {
          f := makeSuffix(".jpg")

          res1 := f("winter")
          fmt.Println("res1=", res1)

          res2 := f("bird.jpg")
          fmt.Println("res2=", res2)
      }
      ```

    * 这一段代码里的闭包是：返回的匿名函数加上它引用到的外层 `suffix` 变量。

    * `f("winter")` 返回 `winter.jpg`；`f("bird.jpg")` 返回 `bird.jpg`，不会重复追加。

    * 如果名字是 `bird.avi`，`.avi` 不是 `.jpg` 的后缀，所以返回 `bird.avi.jpg`。

    * > **易错点**：上面已经声明过一个 `f` 就不要再重复声明，要换名字；`suffix` 这个单词也容易拼错，写完检查一遍。

* **闭包强在哪**

    * 传统写法同样能实现这个功能：

      ```go
      func makeSuffix2(name string, suffix string) string {
          if !strings.HasSuffix(name, suffix) {
              return name + suffix
          }
          return name
      }
      ```

    * 两种方式效果一样，都返回 `winter.jpg` 和 `bird.jpg`；区别在于普通函数每次调用都得把后缀重新传一遍。

    * > **结论**：传统方法每次都要传入后缀名，闭包因为能保留上次引用的值，传入一次就可以反复使用。

    * 普通函数调用一次栈就销毁了，原先的变量也就没有了（除非用全局变量）；闭包能把它引用到的变量保留下来供下次调用接着用，而且不需要全局变量。

## defer

* **为什么需要 defer**

    * > **定义**：`defer` 是延时机制，加上它之后 `defer` 后面的语句会在函数执行完毕过后才执行。

    * 函数中经常需要创建资源，比如打开数据库连接、打开文件句柄、锁；为了在函数执行完毕后及时释放资源，Go 的设计者提供了 `defer` 机制。

* **defer 栈与后进先出**

    * > **定义**：执行到 `defer` 时不会立即执行后面的语句，而是把它压入一个独立的栈（defer 栈），然后继续执行下面的语句。

      ```go
      func sum(n1 int, n2 int) int {
          // 当执行到 defer 时，会先将 defer 后面的语句压入到一个独立的栈中，暂时不执行
          defer fmt.Println("ok1 n1=", n1)
          defer fmt.Println("ok2 n2=", n2)

          res := n1 + n2
          fmt.Println("ok3 res=", res)
          return res
      }

      func main() {
          res := sum(10, 20)
          fmt.Println("res=", res)
      }
      ```

      ```text
         执行 sum(10, 20)
              │
              │  defer fmt.Println("ok1 n1=", n1)   ① 压栈（栈底）
              │  defer fmt.Println("ok2 n2=", n2)   ② 压栈（栈顶）
              │  fmt.Println("ok3 res=", res)       ③ 立刻执行
              │  return res                          ④ 执行完毕后开始出栈
              ▼
         ┌──────────┐   ┌──────────┐   ┌──────────┐
         │ ② ok2    │ → │ ① ok1    │ → │  空       │   后进先出
         │  n2 = 20 │   │  n1 = 10 │   │          │
         └──────────┘   └──────────┘   └──────────┘
              ▼
         回到 main，输出 res= 30
      ```

    * 函数执行完毕后从 defer 栈中依次取出栈顶语句执行，遵守先入后出：先压入的后执行，后压入的先执行。

    * 输出顺序是 `ok3 res= 30`、`ok2 n2= 20`、`ok1 n1= 10`、`res= 30`。

* **压栈时值拷贝同时入栈**

    * 在把语句压入 defer 栈的同时，会把相关的值拷贝一并入栈。

      ```go
      func sum(n1 int, n2 int) int {
          defer fmt.Println("ok1 n1=", n1)
          defer fmt.Println("ok2 n2=", n2)

          n1++
          n2++

          res := n1 + n2
          fmt.Println("ok3 res=", res)
          return res
      }
      ```

    * 加了 `n1++`、`n2++` 之后 `res` 变成 32，输出 `ok3 res= 32`；但 `ok2 n2=` 和 `ok1 n1=` 仍然输出 20 和 10。

    * 因为语句压栈时就把当时的值拷贝一起压了进去，外面 `n1`、`n2` 后续的变化对它没有影响。

    * > **注意**：值拷贝同时入栈这个细节是面试常考点。

* **defer 的使用三步**

    * 创建资源后立即 `defer` 它的关闭操作，比如打开文件句柄后马上 `defer file.Close()`，获取数据库连接后马上 `defer connect.Close()`。

    * > **易错点** ⚠️：不要理解成一旦 `defer` 了这个资源就用不了了；defer 完照样可以继续用这个句柄和连接，函数执行完毕后才会去销毁它。

    * 函数执行完毕后，系统会依次从 defer 栈中取出这些语句、关闭资源。

    * 这套做法的好处是程序员既不会忘记关、也不用操心什么时候关——以前用 PHP、Java 时资源到底该在 service 关、model 关还是在这句话前后关都不好控制，现在统一成"一打开就 defer"就行。

## 参数传递方式

* **两种方式的本质**

    * > **定义**：值传递是在传递参数时做了一次值拷贝；引用传递传的是一个地址。

    * > **结论**：值传递和引用传递本质上都是一样的，传递给函数的**都是变量的一个副本**，只是拷贝过去的副本不一样。

    * 值传递拷的是一个值，比如传了整数 6，函数里就得到一个新的 6。

    * 引用传递（指针传递）拷的是地址这个具体的值，传过去的是地址而不是原值本身的内容。

* **效率差别**

    * 地址拷贝的效率通常更高，因为它拷贝的是一个地址，数据量小，一下就传过去了。

    * 值拷贝的效率取决于被拷贝数据的大小：数据越大效率越低，比如后面要学的结构体内容量很大，用值拷贝会拷贝一个很大的数据；传递它的地址效率就很高。

    * 所以实际开发中想提升效率，往往采用地址拷贝也就是引用传递的方式。

* **类型对照**

    * | 传递方式 | Go 中的类型 |
      | :--- | :--- |
      | **值传递** | 基本数据类型（`int`、`float`、`bool`、`string`）、数组、结构体 |
      | **引用传递** | 指针、切片（slice）、`map`、管道（channel）、`interface` |

    * 引用传递里目前只详细讲了指针，切片、`map`、管道、`interface` 后面再讲。

    * > **结论**：哪些是值传递、哪些是引用传递是一个必须记牢的考点。

* **值类型与引用类型的内存差别**

    * 值类型变量直接存储值，`number = 100` 时变量和值直接关联，取地址得到的就是这个值对应的地址。

    * 引用类型变量存储的是一个地址，这个地址对应的空间才真正存储数据，内存一般在堆上分配。

      ```text
         值类型：number = 100

              ┌───────────┐
              │  number   │ ──────────▶ ┌───────────────┐
              └───────────┘   存储值    │  100          │
                                          └───────────────┘


         引用类型：ref

              ┌───────────┐            ┌───────────────┐    ┌───────────┐
              │   ref     │ ────────▶ │    地址       │───▶│  真正的值 │
              └───────────┘   存储地址  └───────────────┘    └───────────┘
                                    堆上分配的空间

              当没有任何变量引用这个地址时
              → 该地址对应的数据空间成为垃圾
              → 由 GC 回收
      ```

    * 当没有任何变量引用这个地址时，该地址对应的数据空间就成为垃圾，由 GC 回收。

    * 希望把默认的值传递改成引用传递，就把变量的地址传进去。

## 变量作用域

* **局部变量**

    * > **定义**：在函数内部声明或者定义的变量称为局部变量，作用域仅限于函数内部。

    * 不管首字母是大写还是小写，只要在函数内部声明或定义，它就是局部变量。

      ```go
      func test() {
          var age int = 10
          var Name string = "汤姆"
          // age 和 Name 的作用域仅限于 test 函数内部
      }

      func main() {
          // fmt.Println(age)   // 这里用不了，报 undefined: age
      }
      ```

    * 出了这个函数 `age` 和 `Name` 就用不到了，首字母大写也没有用，会直接报 `undefined`。

* **全局变量**

    * > **定义**：在函数外部声明的变量叫全局变量，作用域在整个包都有效；如果首字母大写，作用域在整个程序都有效，别的包也能使用。

      ```go
      var age int = 50       // 首字母小写：本包可用
      var Name string = "jack" // 首字母大写：整个程序可用

      func test() {
          var age int = 10
          var Name string = "汤姆"
          fmt.Println(age)  // 10
          fmt.Println(Name) // 汤姆
      }
      ```

    * 同名的 `age`、实际上是两个不同的变量，因为作用域不一样：`main` 里输出 50 和 `jack`，调用 `test` 输出 10 和 `汤姆`。

    * > **易错点**：小写的全局 `age` 在别的包里用不了，改成小写后访问会报 `cannot refer to unexported name utils.age`；只有首字母大写的全局变量才能被其它包使用，类似于 `public`。

* **代码块里的变量**

    * `for`、`if` 这类控制语句构成代码块，在代码块里定义的变量作用域只在该代码块内生效，出了块就不认了。

      ```go
      for i := 0; i <= 10; i++ {
          fmt.Println("i =", i)
      }
      // fmt.Println("i =", i)  // 报 undefined: i
      ```

    * 循环输出 0 到 10 没问题，但退出循环后再输出 `i` 会报 `undefined: i`。

    * 上下两个 `for` 各定义一个 `i` 也不会报重复定义错误，因为上一个 `i` 出了块就失效了，下面那个是新变量。

    * 如果希望 `for` 块里的变量在循环外也能用，就把定义提到外面、初始化位置改成赋值：

      ```go
      var i int
      for i = 0; i <= 10; i++ {
          fmt.Println("i =", i)
      }
      fmt.Println("i =", i) // for 循环执行完毕后的 i
      ```

    * 必要的话还可以定义到最外面作为全局变量，就看需求；`if` 语句同理。

* **就近原则**

      ```go
      var name string = "汤姆"

      func test01() {
          fmt.Println(name) // 汤姆
      }

      func test02() {
          var name string = "杰克"
          fmt.Println(name) // 杰克
      }
      ```

    * `main` 和 `test01` 内部都没定义 `name`，会找到外面的小写全局变量，输出"汤姆"。

    * `test02` 里定义了同名的局部变量，**不会报错**，编译器采用就近原则，输出"杰克"。

    * 再调用 `test01` 又输出"汤姆"，因为 `test02` 里的改动是局部的，不影响全局变量。

    * 完整输出顺序是：汤姆、汤姆、杰克、汤姆。

    * 如果把 `test02` 里的冒号去掉写成 `name = "杰克"`，同样不报错，但这相当于修改全局变量，后续 `test01` 也会输出"杰克"，结果是汤姆、汤姆、杰克、杰克。

* **函数外不能用 :=**

      ```go
      var age int = 20
      Name := "汤姆"
      ```

    * 第一句没问题，第二句会报 `syntax error: non-declaration statement outside function body`。

    * 因为 `Name := "汤姆"` 等价于两句：

      ```go
      var Name string
      Name = "汤姆"
      ```

    * 函数外声明变量没问题、初始化变量也没问题，但**不能有赋值语句**——赋值语句属于执行语句，只能在函数体内执行，而 `:=` 隐藏了这条赋值语句。

    * > **易错点** ⚠️：这是一个使用陷阱，一定不要在函数体外用 `:=`。

* **把老案例封装成函数**

    * `printPyramid(totalLevel int)`：把打印金字塔的核心代码原样搬进来接收层数；打实心金字塔就把空心判断那段 `if/else` 去掉。

      ```go
      func main() {
          var n int
          fmt.Println("请输入打印金字塔的层数")
          fmt.Scanln(&n)
          printPyramid(n)
      }
      ```

    * `Scanln` 一定要传地址，正是因为传地址外面这个 `n` 才会变化；传的不是地址的话，里面改了外面不改。

    * `printMulti(num int)`：接收 1 到 9 的整数打印对应乘法表，没有返回值。

      ```go
      func main() {
          var number int
          fmt.Println("请输入九九乘法表对应的数")
          fmt.Scanln(&number)
          printMulti(number)
      }
      ```

    * 传 9 打九九乘法表，传 8 就打八八乘法表；基本数据类型直接传值即可。

    * 把功能封装进函数后 `main` 一目了然，比把代码直接堆在 `main` 里更便于阅读和维护。

    * 课后作业是写一个函数对给定的二维数组（如 $3 \times 3$）做转置：

      ```text
      1 2 3        1 4 7
      4 5 6   →    2 5 8
      7 8 9        3 6 9
      ```

    * 转置就是把行列交换：2 和 4 交换、3 和 7 交换、6 和 8 交换，主对角线上的元素刚好对称所以不变。
