# 反射机制

## 反射的入口

### 反射的本质

* **反射（reflection）**
    * > **定义**：反射实现了运行时的反射，可以在运行的时候动态获取变量的各种信息。

    * 能拿到的信息包括变量的类型、类别；如果是结构体实例，还能拿到它的字段、方法等结构体本身的信息。
    * 还能通过反射修改变量的值（变量按引用传递）和调用关联的方法，例如以反射方式调用结构体的方法。
    * 做反射一般会专门写一个函数演示，形参用空接口 `interface{}`，因为可以对任何数据类型做反射。
    * > **结论**：反射的本质是运行时的——运行的那一瞬间能确认值的类型，但**编译阶段无法确认**，所以反过来取值时必须先做类型断言。

* **变量名以 r 打头**
    * 反射相关变量习惯前面写 `r` 以示区别：`rTyp` 是反射意义上的 type，不是传统类型；不看前缀很容易听懵圈。

### reflect.TypeOf

* **reflect.TypeOf（b interface{}）**
    * > **定义**：根据空接口参数返回被反射变量的 `reflect.Type`，`Type` 本质是一个接口。

    * 传基本类型进去时打印出来就是 `int`，但它的真正类型是 `reflect` 的 Type；原有的 `int` 不能调方法，而它可以调。
    * `Name()` 返回该类型在自身包内的类型名，未命名则返回空串。

### reflect.ValueOf

* **reflect.ValueOf（b interface{}）**
    * > **定义**：根据空接口参数返回被反射变量的 `reflect.Value`，它是拿到值之后进一步操作原变量的入口。

    * 直接打印时看起来是原值，其实并不是原来那个值。

    ```go
    rVal := reflect.ValueOf(b)
    n2 := 2 + rVal
    ```

    * 上式会报 `invalid operation: 2 + rVal (mismatched types int and reflect.Value)`，因为 `rVal` 的类型是 `reflect.Value`，与 `int` 不匹配。

    * > **提示**：要真正看到它的类型应该用 `%T`，例如 `fmt.Printf("rVal=%v, type=%T\n", rVal, rVal)` 打出 `reflect.Value`；用 `%v` 只输出底层机制代表的那个值。

    * 拿到 `reflect.Value` 之后，它提供的全部方法都可以用，可以对原变量做各种操作。

### 取值与来回切换

* **取值方法**
    * `reflect.Value` 提供了改变值的系列方法，以及按类型取值的 `Int()`、`Bool()`、`Uint()`、`String()`、`Bytes()`、`Pointer()`。
    * `Int()` 返回 v 持有的符号整数，这才是真正的值，所以加减乘除要这样写：`n := rVal.Int() + 1`。
    * 若传进来的不是 `int` 而是 `float`，用对应的方法或先做断言即可。

* **来回切换链路**
    * > **结论**：变量通过传参交给空接口，空接口通过 `reflect.ValueOf` 拿到 `reflect.Value`，再通过 `rVal.Interface()`（`I` 大写）转回空接口，最后用类型断言转回原来的变量类型。

    ```go
    iv := rVal.Interface()   // 注意 I 是大写
    num2 := iv.(int)
    ```

    * 它们之间的关系可以随意切换，实际开发中会经常用到这条链路。

## 结构体反射与断言

### 取不到字段的坑

* **结构体的取值**
    * 定义 `Student{Name string; Age int}` 并传入反射函数，取回 `iv` 后打印为 `iv={tom 20}, type=main.Student`，内容与类型都对。
    * 但直接写 `iv.Name` 保存就报错——编译器在编译期没法确认 `iv` 是什么类型。

    * > **易错点**：即使打印出来确实指向 `Student`，也不能直接取字段；**从 `interface{}` 取出来的值，编译层面它仍然是 `interface{}`**，必须先断言成对应类型再取值。

* **带 ok 的断言**
    * `stu, ok := iv.(Student)`：能判断是否断言成功，成功就用，失败也不影响后续。
    * 断言成功后从编译层面它就是 `Student`，可以放心地把所有字段遍历出来。

* **更灵活的 switch**
    * 断言本身还可以写成 `switch x.(type)` 的形式，把可能遇到的类型都列进去，封装成一个函数。
    * 之所以强调这个形式，是因为将来传入的可能是 `Monster` 等其它类型，直接断言风险大。

## Type 与 Kind

### Kind 的两条获取路径

* **Kind**
    * > **定义**：`Kind` 是获取变量类别的方法，返回的是一个**常量**。

    * 第一种：`reflect.Value` 上的 `Kind()`，返回 v 持有的分类。
    * 第二种：`reflect.Type` 上的 `Kind()`，`TypeOf` 返回的变量实现了 `Type` 接口。
    * 两个 `Kind` 定位到同一处，值完全相同，所以从 Value 取和从 Type 取都行。

    ```go
    kind1 := rVal.Kind()
    kind2 := rType.Kind()
    ```

### Type 与 Kind 的关系

* **类型与类别**
    * > **结论**：`Type` 是类型，`Kind` 是类别，两者可能相同也可能不同，取决于传进来的是什么变量。

    * 基本数据类型（`string`、`float`、`bool`、`int`）两者相同，因为不存在包这一层。
    * 结构体则不同：`Type` 是 `包名.Student`，`Kind` 是 `struct`。
    * Go 用**包名加结构体名**来区分 Type，所以 `pkg1` 和 `pkg2` 里各有一个 `Student` 不冲突，名字相同但类型不是同一个，类别却都是 `struct`。

    ```text
       包名.Type  ── 唯一标识「你是哪一个」
       目录 pkg1 /  pkg1
            └── Student   ──►  Type = pkg1.Student
       目录 pkg2 /  pkg2
            └── Student   ──►  Type = pkg2.Student
                                 ↑ 同名，但 Type 不是同一个

       基本类型 string / float / bool / int
                         ──►  没有包这一层
                              Type == Kind
    ```

    * > **结论**：`Kind` 只看大类别，`Type` 才带包名。
    * 范畴大小上 `Kind` 的范畴更大——类比“电器”是类别，“冰箱”是类型，冰箱还可以分 500 毫升和一万升。

* **类别常量的比较**
    * `Kind` 的这些常量定义在 `reflect` 包里，使用时写成 `reflect.Struct`。
    * 它本身是常量（底层是数字），所以可以直接用 `!=` 这类比较做判断。

## 常量

### const 的四条规则

* **常量（constant）**
    * 用 `const` 关键字修饰，完整格式是 `const identifier [type] = value`，类型可以写也可以不写。

    * > **易错点**：常量在声明时必须给值，`const tax int` 会报 `const declaration cannot have type without expression`。变量可以不赋值、有默认值 0，但给 0 和不赋值含义不同。

    * 常量一旦定义好就不能修改，赋值会报 `cannot assign to tax`。
    * 常量只能修饰布尔、数值和 `string`，不能修饰切片这类本身要能变的数据类型。

* **必须是编译期确定的值**
    * `const b = 9 / 3` 可以，因为两个操作数都是常量。
    * `var num = 9; const b = num / 3` 报错——编译器认为 `num` 将来可变、值不确定，例如它可能来自控制台输入，那就变成运行期了。
    * `const b = getValue()` 同样报错，因为函数返回值不保证固定。
    * > **结论**：编译器的常量必须在编译时就确定具体值。

### 两种写法与 iota

* **块写法**
    * 简洁写法是小括号里逐行给值：

    ```go
    const (
        a = 1
        b = 2
    )
    ```

* **iota 自增**
    * 更“专业”的写法是首行给 `iota`，后面不写值表示在这个基数上依次加 1：

    ```go
    const (
        a = iota   // 0
        b          // 1
        c          // 2
        d          // 3
    )
    ```

    * `iota` 表示给 `a` 赋一个 0，之后每行加 1，运行结果就是 `0 1 2 3`。
    * 同一行里写多少遍 `iota` 都是同一个值：用逗号写 `c, d = iota, iota` 时 `c` 和 `d` 都是 2，要换一行才继续递增。
    * 遇到新的 `const` 块，`iota` 重新从 0 开始计算，因为它只在这个范围内生效。

### 作用域与访问范围

* **作用域**
    * `const` 定义在函数内部就是局部常量，定义在外面就是全局常量。
    * > **结论**：Go 没有规定常量必须大写，很多语言有这条规矩，Go 没有，写小写同样是规范的。
    * 但常量的访问范围机制和变量完全一样，全局常量同样靠首字母大小写控制访问范围。

## 反射取值的硬要求

* **类型必须匹配**
    * 用反射获取变量的值并返回对应类型，要求数据类型匹配：`x` 是 `int` 就必须先拿到 `reflect.Value` 再取它的值。
    * 结构体没有直接对应的取值方法，因为它对应的 Type 无法确定，**只能先断言再取**。

* **类型对不上的后果**
    * 明知传的是 `int` 却偏要用 `Float()` 取，编译器检测不出来，因为对它来说这些都属于运行期的事情。

    ```text
    panic: reflect: call of reflect.Value.Float on int Value
    ```

    * > **易错点**：这是**运行时的 panic，不是编译错误**，编译器拦不住，等到运行测试时才炸；用反射取回基本类型值之前一定要确认是同一个类型。
    * 想知道它到底是什么类型，就加一个判断先确认类别再取值。

* **课堂练习的固定套路**
    * 对一个 `float64` 变量取三件套（`reflect.Value`、`Type`、`Kind`）再切回 `float64`，各步对应：拿 Value 用 `reflect.ValueOf`；拿 Type 用 `Type()`，拿 Kind 用 `Kind()`；拿具体值用 `Float()`（用 `Int()` 会 panic）；Value 转接口用 `rVal.Interface()`；接口转回用类型断言 `iv.(float64)`。

## 反射改值

### 传值改不到外面

* **传值的无效性**
    * 需求是通过反射修改传入的 `int` 变量。若主函数里写 `reflect01(number)` 传的是值拷贝，里面改什么都不会影响外面的 `number`，没有任何用处。

    * > **易错点**：要用反射改变外部变量的值，必须传地址 `reflect01(&number)`。

* **SetInt 直接报错**
    * 传了地址之后 `rVal := reflect.ValueOf(b)` 拿到的 `Kind` 是 `ptr` 而不是 `int`，因为类型本质上变成了指针类型。
    * 直接调 `rVal.SetInt(20)` 会报 `reflect: reflect.Value.SetInt using unaddressable value`，即使用了一个不可寻址的值。

    ```text
       number  ──┐
                 │  取地址
                 v
       &number ──► reflect.ValueOf(&number)
                          |
                          |  Kind = ptr
                          v
                     rVal.SetInt(20)      ✗  unaddressable value
                          |
                          |  Elem()  ==  解引用 *ptr
                          v
                     rVal.Elem().SetInt(20)   ✓  改的是同一块内存
                          |
                          v
                      number = 20
    ```

* **Elem**
    * > **结论**：`Elem()` 返回 v 持有的接口保管的值，或者 **v 持有的指针指向的值**；后半句是关键。

    * > **结论**：要用 `Set` 系列方法改值，必须先 `Elem()` 拿到那个可寻址的值，写成 `rVal.Elem().SetInt(20)`；漏掉 `Elem()` 就直接报错。

    * 可以简单理解为解引用：`var ptr *int = &num; num2 := *ptr`，底层改变的是同一个数据空间。
    * 后面几个反射应用案例会大量用到 `Elem()`，因为反射的价值就在于直接改变外部变量或结构体的值。
    * 对 `string` 变量调 `SetString` 也是同理：传参改地址，再用 `fs.Elem()` 取回真正指向的数据空间。

* **结构体更麻烦一层**
    * > **易错点**：修改结构体比修改基本类型麻烦，因为要**先拿到它的字段才能改**，字段拿不到就无法修改。

## 遍历字段、方法与标签

### Method 与 Call

* **Method**
    * `reflect.Value` 上的 `Method(i)` 返回 v 所持有的结构体的第 i 个方法，下标从 0 开始。

* **Call**
    * 拿到方法后用 `Call` 真正调用它。
    * > **结论**：`Call` 后面传一个切片，**这个切片必须是 `reflect.Value` 类型的切片**，用于给可能有参数的方法传参；`in` 代表输入，返回的也仍是 `reflect.Value` 切片。

    * 反射主要靠 `Value` 来玩，所以传入类型和返回类型都是它，用这一个类型把所有环节囊括完。

### Monster 案例的骨架

* **被反射的结构体**
    * 定义带 tag 的 `Monster` 结构体，并绑定 `Print`（无参输出自身）、`GetSum`（返回两数之和）、`Set`（接收四个值给自身赋值）三个方法。

    * > **易错点**：`Set` 用的是**值接收者**，改的只是自己的副本，外面的变量一点都不会变；这一点在反射改字段时还会再撞上。

* **先确认类别**
    * 进函数先拿 `typ := reflect.TypeOf(a)`、`val := reflect.ValueOf(a)`、`kd := val.Kind()`。
    * 然后 `if kd != reflect.Struct { fmt.Println("expect struct"); return }`——不是结构体就退出，因为目标是对结构体做遍历。
    * 这也说明反射里可以做类别判断。

* **字段个数与遍历**
    * `num := val.NumField()` 取字段总数，四字段结构体返回 4，加一个字段立刻返回 5。
    * `for i := 0; i < num; i++ { fmt.Printf("Field %d: 值为=%v\n", i, val.Field(i)) }` 逐个打印字段值。

    * > **易错点**：`val.Field(i)` 返回的仍然是一个 `Value`，直接打印能显示值，但**不能对它做加减等任何运算**；可以转成对应类型，用 `switch type` 写法会更完整。

### 标签只能从 Type 上拿

* **取值链路**
    * `typ.Field(i)` 返回的是 `StructField`（`reflect.Type` 的 `Field` 与 `reflect.Value` 的 `Field` 返回类型不同），它里面有一个 `Tag` 字段。
    * `typ.Field(i).Tag` 的类型是 `StructTag`，再点进去有一个 `Get(key)` 方法，`key` 就是结构体标签里写的那个键名，`Get` 才真正返回字符串值。

    ```text
       type Monster struct {
           Name  string `json:"name"`
                  ─────────────  ─────────
                   标签整体         Get() 的 key

       typ.Field(i)                  →  StructField   (一个结构体)
       typ.Field(i).Tag              →  StructTag     (一个结构体)
       typ.Field(i).Tag.Get("json")  →  string    ← 终于拿到值了
    ```

    * > **结论**：获取标签一定要用 `reflect.Type`，不能用 `reflect.Value`。

    * > **易错点**：标签是按 key 读的，写错了 key 就取不到那个值；改成别的名字，其它字段的标签也就一并取不到了。

* **为什么要用 json 这个 key**
    * 这解释了结构体 tag 为什么能让序列化后的键名改名——反射在这中间起了作用，序列化、反序列化内部有一段类似的取标签代码。
    * 序列化时那个标签名是写死的，所以必须写 `json`；自己另写一套序列化时这个 key 是可以改的。

### 方法排序与调用

* **NumMethod**
    * `val.NumMethod()` 取方法个数，三个绑定方法就返回 3。

* **方法按函数名排序**
    * > **结论**：**方法的排序默认按函数名的 ASCII 码大小排序**，与代码里书写的先后无关。

    * 三个方法 `Print`、`GetSum`、`Set` 按首字母 ASCII 排序，`G(71)` < `P(80)` < `S(83)`，因此实际下标是 `GetSum` 为 0、`Print` 为 1、`Set` 为 2。
    * 所以 `val.Method(1)` 取到的是无参的 `Print`，能直接调用；把 `Print` 挪到最后写，调出来的仍然是它。

    ```text
       我写的顺序            Print        GetSum       Set
       首字母 ASCII      P(80)  80   G(71)  71   S(83)  83
                              |         |          |
                           排第二    排第一     排第三
                              |         |          |
       实际下标:                1         0          2

       =>  val.Method(1)  拿到的是  Print  （没有参数，所以能直接调用）
       =>  val.Method(0)  拿到的是  GetSum （需要两个参数）
    ```

    * 理论上存在按函数名获取方法的方式（`MethodByName`），但既然已经知道函数名，反射的意义就不大了，本质上没有区别。

* **带参调用与返回值**
    * 参数按顺序 `append` 进切片，每个元素都要转成 `reflect.Value`，字符串同理。
    * `res := val.Method(0).Call(args)` 调用求和方法，返回的 `res` 同样是切片。
    * 取结果时要知道返回了几个，按顺序取；只返回一个和时 `res[0].Int()` 就是结果。

    * > **易错点**：不确定返回类型时应加类型断言；不加断言虽然也能打印出 50，但类型不一样。

## 反射创建与修改结构体

### 改字段

* **修改结构体字段**
    * > **结论**：与改基本类型唯一的区别就是传入的地方加了一个 `&` 符号（传指针），其余大量使用 `Elem()` 才能真正把字段改过来；改完之后重新打印，原值就变成了新值。

### reflect.New 创建实例

* **创建流程**
    * `typ := reflect.TypeOf(&User{})` 先拿到类型，打印是 `*main.User`。
    * `elem := reflect.New(typ)` 创建一个新的 `Value`，它持有一个指向该 Type 的**新申请的零值指针**；此时还没有数据，但已经指向了一块 `User` 的地址空间。

    ```text
       ①  reflect.New(typ)
             |
             |  elem  :  *User   (Kind = ptr)
             v
       +-------------------------------+
       |   一块刚申请的新内存（零值）    |   UserId : ""
       |   它就是我们的 User 数据空间    |   Nickname : ""
       +-------------------------------+
             ^                    ^
             |                    |
        model = elem.Interface()  |
        .(*User)  ────────────────┘
        model 也指向这一块，两边看到的是同一份数据

       ②  elem = elem.Elem()
             elem 不再是指针，直接指向数据空间

       ③  elem.FieldByName("UserId").SetString("1234")
             |
             v
       +-------------------------------+
       |   UserId : "1234"  ← 写进去了   |
       +-------------------------------+

       ④  再用 model 访问
             model 仍是指针，指向同一块
             => model.UserId 也就是 1234 了
    ```

    * `model := elem.Interface().(*User)` 先转成空接口再用类型断言转回 `User`，此后 `model` 与 `elem` 指向同一块内存，改一边另一边就跟着变。
    * `elem = elem.Elem()` 让 `elem` 不再是指针、直接指向数据空间，这样才能往里赋值；`model` 仍是指针、通过地址访问。

    * > **结论**：只有先 `Elem()` 再赋值才能真正往这块空间里写；写完之后用 `model` 访问同样能看到新值。

### 操作任意结构体

* **FieldByName 通路**
    * 先创建指向 `User` 的指针型变量并用 `reflect.ValueOf` 拿到 `sv`，此时是指针类型。
    * `sv.Elem()` 取到对应的真实 `reflect.Value`，再用 `FieldByName` 找到 `UserId` 等字段并设置值。
    * > **结论**：结构体具体是什么类型并不影响这条通路，任意结构体都能这样操作。

## 反射的意义

* **让人震撼的地方**
    * 平常调结构体方法的固定套路是创建实例再调它的方法；而现在只需要把一个实例传进方法，就能通过反射把所有事情做完。
    * 将来做底层框架时把这套东西放进去就成立：框架可以约定控制器或 Model 的命名规范，然后反射去扫描、找到对应入口函数并调用；不符合规范的则调不起来。
    * > **结论**：测试框架要求用例函数必须以 `Test` 打头，就是靠反射扫描调用的，命名规范与反射机制是配套的。

* **适配器写法**
    * 适配器函数的用途是作为统一的处理函数：形参是空接口加可变参数，传进来的函数按各自需要的参数个数被调用。
    * 反射最大的价值就是自己写框架，写框架时反射必用无疑；写底层代码时会大量用到适配器函数。
