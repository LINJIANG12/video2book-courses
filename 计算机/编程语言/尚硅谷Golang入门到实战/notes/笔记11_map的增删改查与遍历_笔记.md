# map 的增删改查与遍历

## map 的三种使用方式

* **三种写法的对比**

    | 对比项 | 方式一：声明后 make 再赋值 | 方式二：声明时直接 make | 方式三：声明时直接赋值 |
    | :--- | :--- | :--- | :--- |
    | 写法 | 先 `var`，再 `make`，再赋值 | `var cities map[string]string = make(map[string]string)` | `var heroes map[string]string = map[string]string{"hero1": "宋江"}` |
    | make 次数 | 显式一次 | 显式一次 | 语法上没写，底层已经 make 过 |
    | 之后能否继续传统赋值 | 能 | 能 | 能 |
    | 使用建议 | 完整但啰嗦 | 推荐，清晰且不拖泥带水 | 容易搞混 |

* **方式一：先声明，再 make，再赋值**
    * 先声明，声明完 `make`，`make` 完再赋值，是最基本的写法。

* **方式二：声明的时候直接 make**
    * `var cities map[string]string = make(map[string]string)`，大小可以不写取默认值，空间已经 make 好，下面直接赋值。
    * 存放城市信息时可以随便写，不受 make 时给定大小的影响，它会自动增长——这一点与数组不同，数组直接拿来用会越界。
    * > **提示**：这种方式用得比较多，比较灵活，个人一般推荐用它。

* **方式三：声明的时候直接赋值**
    * 写法是 `map[string]string` 后面直接写一对大括号，里面写 key-value；这样连 `make` 都没用到，但底层实际上也已经 make 过空间了。
    * 可以进一步用类型推导写得更简洁：`heroes := map[string]string{"hero1": "宋江", "hero2": "卢俊义", "hero3": "吴用"}`。
    * > **易错点**：大括号里**即使是最后一项也不能少逗号**，少一个逗号就语法过不去，编译器会提示这里期待一个分号之类的。
    * 这种写法做完之后仍然可以用传统方式继续赋值，如 `heroes["hero4"] = "林冲"`。
    * 三种方式将来在别人代码里都可能出现，遇到不认识的写法要能反应过来。

## 嵌套 map：把 value 换成 map

* **需求决定结构**
    * 要求存放三个学生的信息，每个学生有名字和性别。
    * 只存名字时 key 为 string、value 为 string 就够了；但一个学生有两个信息，所以**把 value 换成一个 map** 更合理——外层 string 是学号，内层 map 里放名字和性别。

* **写法与必做的 make**
    * `studentMap := make(map[string]map[string]string)` 建立外层。
    * > **提示**：**只要使用到 map 就一定要 make**，少一次就会报 panic；外层做完还不够，`studentMap["student01"] = make(map[string]string)` 这一步必须再 make 一次，因为值也是 map。
    * 之后就能连续写入 `studentMap["student01"]["name"]`、`["sex"]`、`["address"]` 这样的多层下标。
    * > **易错点**：写第二个学生时**编号一定要改**，不改就把第一个学生的名字冲掉了。
    * 想取出整个第二个学生写 `studentMap["student02"]`，只想取出他的名字写 `studentMap["student02"]["name"]`，取法很灵活。

## 增与改

* **一行代码，两种语义**
    * 写法是「map 名称 + key + 值」，如 `cities["no1"] = "北京"`。
    * key 现在**还没有**就相当于增加，key **已经存在**就相当于修改。
    * 例：`cities["no3"] = "上海"` 之后再执行 `cities["no3"] = "上海~"`，因为 `no3` 已存在，这一句就是修改，输出里 `no3` 变成「上海~」。
    * > **结论**：修改和增加其实主要取决于这个 key 是否存在，同一行代码因为 key 的存在与否，语义完全不同。

## 删：delete 内置函数

* **delete 的定义与行为**
    * > **定义**：`delete` 是内置函数，按指定的键将元素从 map 中删除，第一个参数写 map 名称，第二个写 key。
    * key 存在就删除这一对 key-value；key 不存在相当于不操作，**也不会报错**。
    * 手册里还有一句：如果 `m` 为 nil，`delete` 不进行任何操作，同样不报错。
    * 因为是内置函数，不需要引入任何包，直接 `delete(cities, "no1")` 即可。

* **删除不存在的 key**
    * 故意删一个并不存在的 `no4`，代码里并没有报任何错误，删除之后数据保持原样。

## 清空整个 map

* **Go 没有 clean 方法**
    * 有些编程语言的 map 确实有像 `clean` 这样的方法能一次性删掉所有 key，但 Go 里没有这样一个方法。
    * **方案一**：遍历这个 map 把它们遍历一次，然后逐个删除；这要用到遍历的知识，相对麻烦一点。
    * **方案二**：让这个 map 重新分配一个空间，`cities = make(map[string]string)`；`cities` 指向新的空间后，原先指向的那块数据空间成为垃圾被 GC 回收。
    * > **提示**：方案二肯定比逐一删除效率高而且更简单，推荐使用。

## 查：value, ok := m[key]

* **取值返回两个数据**
    * 直接取一个 key 会返回两个数据：`value` 和结果标志 `ok`。
    * 有这个 key 时 `value` 就是这个值、`ok` 为 `true`；没有时 `value` 是零值、`ok` 为 `false`。
    * 变量名可以随意，写 `findRes` 也行；通过这种方式就能判断到底有没有。

* **另一种判断写法**
    * 除了 `value, ok := m[key]`，还可以直接写 `if m[key] != nil` 判断——有该元素时它不等于 nil，没有就等于 nil。

## map 的遍历

* **必须使用 for-range**
    * > **结论**：map 的遍历必须使用 for-range，不能用普通的 for 循环。
    * 原因在于普通 for 循环拿到的是**下标**，是按数字来的；而 map 的 key 不是数字，它可能是个字符串。
    * 即使 key 是数字，**也不一定是连续的数字**，for 循环那套下标假设照样不成立。

* **单层遍历**
    * 语法是 `for k, v := range cities`，第一个是 key，第二个是 value，输出格式写成 `k=%v v=%v`。

* **双层 for-range 遍历嵌套 map**
    * 值的类型仍是 map 时要遍历两次：外层 `for k1, v1 := range studentMap`，`k1` 是 `student01`、`student02` 这样的值，`v1` 又是一个 map。
    * 内层 `for k2, v2 := range v1` 里 `v2` 才是具体的值——**range 对 `v1` 遍历**，因为 `v1` 本身是个一维的 map。
    * 内层输出前加一个制表符 `\t`，这样就体现出了层级关系。
    * 这种双层 for-range 在做比较复杂的业务逻辑时会经常用到。

* **用 len 统计 key-value 对数**
    * 想知道 map 里有多少对 key-value，用内置函数 `len`，和统计数组长度是同一个函数。
    * 统计 `cities` 得到「有 3 对 key-value」；统计 `studentMap` 返回 2，因为它只有 `student01` 和 `student02` 两个 key，里面的值又是 map 而已。

## map 切片

* **定义与定位**
    * 切片可以理解成动态的数组，而 map 切片（英文 slice of map）可以理解成**动态的 map**——切片元素类型写成 map 之后，map 的个数就能动态变化。
    * 前面可以动态地增加一个 `int`，这里就可以动态地增加一个 map。

* **案例：记录若干妖怪的名字和年龄**
    * 要求用一个 map 记录 monster 的信息（名字和年龄），且**妖怪的个数可以动态增加**：先记录狐狸精，再加玉兔精、牛魔王。
    * 每个妖怪的信息放在一个 map 里，妖怪个数是变化的，所以正好用 map 切片来满足。

* **必须 make 两次**
    * 声明写 `var monsters []map[string]string`，然后 `monsters = make([]map[string]string, 2)`。
    * > **易错点**：**这里要 make 两次**——第一个是切片本身要 make，第二个是切片元素对应的 map 也要 make，缺一次后面就会报错。
    * > **注意**：map 的 value 是 `string`，所以年龄 `500` 必须写成 `"500"`，写成整数是不行的。

* **逐个赋值要先判空**
    * 添加第一个妖怪时先判 `if monsters[0] == nil`，说明还没分配就先给它 make 一个 map 空间，再写 `monsters[0]["name"] = "牛魔王"` 和 `["age"] = "500"`。
    * 第二个妖怪同理写玉兔精、400 岁；此时切片里两个 map 都有信息。

* **超出 make 的容量会报 index out of range**
    * 直接给第三个妖怪赋值会报 `index out of range`。
    * 把 make 写成 3 确实正确，但**事先并不知道将来要放多少个妖怪**：写成 2000 太大浪费，妖怪有 3000 个不够，3001 个又不行，始终没办法满足。

* **正确做法是用 append 三步**
    * 第一步先创建一个 monster 的 map，直接用字面量赋值：`newMonster := map[string]string{"name": "火云邪神", "age": "200"}`。
    * 第二步用 `append` 把它加进切片：`monsters = append(monsters, newMonster)`。
    * 第三步接收结果即可，哪怕只分配了两个空间，需要多少加多少。
    * > **易错点**：不能把 `newMonster` 再赋给它自己，那等于自相矛盾；正确做法是把 `newMonster` 追加到 `monsters` 上，再把结果赋回 `monsters`。
    * 加完三个之后结果是：牛魔王、玉兔精、火云邪神。

## map 的排序

* **Go 没有针对 map key 排序的方法**
    * map 默认是无序的，而且 Go 语言里并没有一个专门针对 map key 进行排序的方法。
    * 其他语言的 map 的 key 要么本身有序，要么有专门的方法，Go 里两者都没有。
    * 示例：`map1` 里依次放入 `map1[10]=100`、`map1[1]=13`、`map1[4]=56`、`map1[8]=90`，第一次输出顺序是 8、1、4、10，再跑一次又变成 1、8、10、4。
    * > **结论**：Go 语言中的 map 默认无序，**也不是按添加顺序存放的**，每次遍历得到的输出都可能很不一样。

* **排序的三步思路**
    * > **结论**：Go 语言中对 map 排序的做法是**先将 key 进行排序，然后根据这个 key 遍历输出**。
    * 第一步把 map 的 key 放入切片。
    * 第二步对这个切片排序。
    * 第三步遍历切片，按 key 输出 map 的值。

* **三步的具体写法**
    * 第一步定义 `var keys []int`，然后 `for k, _ := range map1 { keys = append(keys, k) }`，值不关心直接用 `_` 忽略。
    * 第二步用 `sort.Ints(keys)` 排序，它接受一个切片并**按递增顺序排列**；`sort` 包里还有别的排序方法。
    * > **易错点**：第一次执行会报 undefined，因为**没有引入这个包**，用到它的函数必须 `import "sort"`。
    * 第三步 `for _, k := range keys { fmt.Printf("map1[%v]=%v \n", k, map1[k]) }`，只取切片里的值，把 map 名字和 key 写进去就把对应的值取出来了。
    * 排序后输出稳定为 `map1[1]=13`、`map1[4]=56`、`map1[8]=90`、`map1[10]=100`，再运行一次顺序依旧固定。

* **适用场景**
    * 开发中如果要**按照价格的高低，或者按照学生的编号来输出信息**，就用这种写法：先把 key 遍历出来放进切片，排序后再遍历切片输出对应的值。

## map 的引用类型语义

* **map 是引用类型**
    * map 和切片一样都是引用类型，遵循引用传递机制——用函数接收一个 map 并修改之后，会直接修改原来的 map。
    * 验证：`func modify(map1 map[int]int) { map1[10] = 900 }`，主函数里 `map1[10]` 原本是 1，调用后打印出来变成 900。
    * 结果为 900 就说明底层是引用传递；如果仍是 1 就说明默认是值拷贝。

* **容量满了会自动扩容**
    * `make(map[int]int, 2)` 时只指定了 2 个位置，但实际放入 `map1[10]` 时已经超过 2，**并没有报错**，说明 map 会自动扩容。
    * > **提示**：**这跟切片不一样，切片不可以自动扩容，得用 `append` 才行**；map 能够动态地增长键值对。

## value 用结构体更合适

* **把学生信息从嵌套 map 换成结构体**
    * 前面用嵌套 map 记录学生信息其实并不好管理，用**结构体作为 value** 更合适。
    * 先定义 `type Student struct { Name string; Age int; Address string }`，三个元素分别是名字、年龄（int）和家庭住址。
    * 再声明 `students := make(map[string]Student)`，key 仍用 string 表示学号，值用结构体。
    * 创建学生时直接按位置给值：`student1 := Student{"tom", 18, "北京"}`、`student2 := Student{"mary", 28, "上海"}`，属性简单时不用键值对方式。
    * 之后 `students["no1"] = student1` 放进 map 的值里，输出时 key 为 `no1` 的是 tom、18、北京，为 `no2` 的是 mary、28、上海。
    * > **结论**：这种方式更好，将来结构体的数据可以很轻松地增加组成部分，比如再加一个属性。

* **遍历结构体值**
    * `for k, v := range students` 中 `k` 是学生编号、`v` 是结构体。
    * 用 `v.Name`、`v.Age`、`v.Address` 把结构体的属性逐个取出来，输出层次非常清晰。
    * 实际开发中 value 更多的情况下就是用结构体这种数据类型，保存和管理数据更方便也更灵活。

## modifyUser 课堂练习

* **需求与函数签名**
    * map 的结构是 key 为 string、value 又是一个 map；key 表示用户名，唯一且不可重复。
    * 用户名存在就把密码修改为 `"888888"`，不存在就增加该用户信息，包括昵称和密码。
    * 值里有两对 key-value，就是昵称和密码。
    * 函数写成 `func modifyUser(users map[string]map[string]string, name string)`，接收 map 本身和用户名。

* **判断用户是否存在**
    * 可以写 `val, ok := users[name]` 通过 `ok` 判断，也可以写 `if users[name] != nil`——有该用户就不等于 nil，没有就等于 nil。

* **新增分支必须先 make**
    * > **易错点**：不能一上来就直接往里放东西。「我知道他没有 pwd，直接给 pwd 一个密码行不行？」**不行**——因为这个 name 对应的 map 还没有 make，第一步必须先 `users[name] = make(map[string]string, 2)`。
    * 至于这个 map 至少有几对 key-value，**至少两对**，因为要求有昵称和密码。
    * 昵称按理说应该再传一个参数进来，这里用 `"昵称~" + name` 示意拼接；想做得更好可以再加一个 `nickname string` 参数。

* **验证结果**
    * 先调用 `modifyUser(users, "tom")` 和 `modifyUser(users, "mary")`，得到 tom 的密码是 `888888`、昵称是 `昵称~tom`，mary 的密码是 `888888`、昵称是 `昵称~mary`。
    * 事先手工加一个 smith（密码 `999999`、昵称「小花猫」，值是 map 所以同样要先 make），再调用 `modifyUser(users, "smith")` 会走 **if 分支**：密码变成 `888888`，而**昵称保持小花猫不变**，说明分支判断正确。
    * > **注意**：**map 里面如果值还是个 map，一定要 make 两次**，这是初学 Go 时经常犯的错误。

## 从 map 走向结构体

* **Go 的面向对象不是传统意义上的**
    * Go 语言的面向对象编程跟传统的（比如 Java、.NET）有很大区别，**因为 Go 语言里面没有类、没有 class 的概念**。
    * 它用一个叫做结构体的东西替代了类的概念，**结构体在面向对象里的地位类似于 class**。
    * 学过别的面向对象语言的人要注意，Go 里有很多和以往学的不太一样的地方。

* **养猫问题的引出**
    * 题目是张老太太养了两只猫：一只叫小白、3 岁、白色；一只叫小花、100 岁、花色；用户输入猫名就显示名字、年龄、颜色，输入错了就提示没有养这只猫。
    * 目的正是让人感受到传统方法解决这个问题的缺点，从而引出结构体。

* **方案一：用一堆变量**
    * 两只猫各有名字、年龄、颜色三个属性，需要**定义六个变量**。
    * 养 20 只猫就要定义更多变量；一只猫若还要记录爱好、喜欢的食物或其他特性，就得继续加变量。
    * 定义变量本身已经很吃力，而且**即使找到了这只猫，也很难把它的所有属性通过一个变量取出来**。

* **方案二：用数组**
    * 属性类型不一样：名字和颜色是 `string`，年龄是 `int`，所以只能开三个数组——`catNames [2]string`、`catAges [2]int`、`catColors [2]string`。
    * > **结论**：**找到「小白」这个名字后要找到它的年龄其实很难找到，因为它们都不在同一个数组里。**
    * 用 map 解决也出现同样的问题：**map 的数据类型是单一的**，把名字保存了就不能保存年龄，名字、年龄和其他信息也得分开记录，数据仍然是分开的。

* **传统方法的两点缺陷**
    * 第一，**使用变量或数组都不利于数据的管理和维护**——一只猫的三个属性本来是一个整体，却被分开保存了。
    * 第二，**将来需要对猫的属性进行操作、绑定一个方法时很难做到**，因为数据已经分散开来。
    * 正因为现有技术很难解决，**即使换成 map 也不好处理**，才引出了结构体这个概念。
