# 查找算法与二维数组

## 顺序查找与二分查找的定位

* **两种查找方式的对比**

    | 对比项 | 顺序查找 | 二分查找 |
    | :--- | :--- | :--- |
    | 查找方式 | 按顺序一个一个比对 | 从两头找中间，每次砍掉一半 |
    | 前提条件 | 无 | 数组必须有序 |
    | 效率 | 低，整个数组都得扫一遍 | 高，折半查找 |
    | 是否用到递归 | 否 | 是 |
    | 受排序方向影响 | 否 | 是，决定往左还是往右 |

* **二分查找的硬前提**
    * 二分查找的效率高得多，但它有个硬前提——**数组必须有序**，不是有序的话根本用不了。
    * 要用二分查找就先把数组排序，排完再用。
    * 二分查找用到了递归知识，难度稍大，也经常作为面试题出现。

## 顺序查找

* **案例与三步思路**
    * 数列是白眉鹰王、金毛狮王、紫衫龙王、青翼蝠王，要求从键盘输入一个名称判断数列中有没有，指定用顺序查找。
    * 第一步定义一个字符串数组存放这些信息。
    * 第二步从控制台接收一个名称，`fmt.Scanln(&heroName)` 必须传 `heroName` 的**地址**，这样才能把读到的内容写回变量。
    * 第三步依次比对，发现有就提示相应信息。

* **写法一：在循环里判断是不是最后一个**
    * 循环条件是 `i < len(names)`，匹配时打印并 `break`。
    * 关键在 `else if i == (len(names) - 1)`：`i` 已到达最后一个元素且仍未进入上面的匹配分支，说明没有找到。
    * 查得到时输出形如「找到 金毛狮王，下标为 1」，查不到时输出「没有找到 hello」。

* **写法二：用 -1 当标记（推荐）**
    * 先定义 `index := -1`，找到就把真实下标赋给 `index`，找不到就让它一直保持 -1。
    * 循环里只要匹配就 `index = i` 并 `break`；循环结束后看 `index` 判断结果：还是 -1 说明没找到，不等于 -1 说明一定找到了。
    * 判定可靠的依据是**只有找到的情况下才会进入那条赋值语句**。
    * > **提示**：两种写法任选，开发中更推荐第二种——思路更清晰，找到就 break、顺手把下标存进 `index`，最后统一判断。

* **效率代价**
    * 元素很多时必须把整个数组扫一遍才能确定有没有，所以才有二分查找。

## 二分查找的思路

### 前提与三个下标

* **有序性是全部推理的根基**
    * 二分查找的对象是有序数列，从小到大或从大到小；任务是判断输入的数是否存在并求出下标，没有就提示。
    * > **结论**：如果不是有序数组，上面这套分析根本不成立——中间数大于目标时，无法断定目标一定在那一半。

* **三个下标与三种可能**
    * 用两个不同颜色的箭头表示左右边界：绿色是 `leftIndex`，红色是 `rightIndex`。
    * 待查找的数叫 `findVal`，中间下标 `middle` 等于 `(leftIndex + rightIndex) / 2`。
    * 把中间值与 `findVal` 比较后有三种可能，砍掉其中一半：

    ```text
            0      1     2     3      4      5
          +------+-----+-----+-----+------+------+
          |  1   |  8  | 10  |  89  | 1000 | 1234 |
          +------+-----+-----+-----+------+------+

            ^                              ^
            |                              |
         leftIndex                     rightIndex
           左边界                          右边界
    ```

* **三种可能的处理规则**

    | 比较结果 | 结论 | 新的查找区间 |
    | :--- | :--- | :--- |
    | `array[middle] > findVal` | 目标若存在应在左边 | `leftIndex` 到 `middle - 1` |
    | `array[middle] < findVal` | 目标应在中右边 | `middle + 1` 到 `rightIndex` |
    | 两者相等 | 找到 | 无需继续 |

    * > **易错点**：往左还是往右取决于数组本身的排序方向。现在是**从小到大，中间大就往左找；从大到小则刚好相反**，这一步千万不要搞混。
    * 这套逻辑要周而复始执行，中间值一旦不等于目标就立刻把数组砍成两半——这就是「二分」这个名字的由来。

### 退出条件与递归实现

* **退出条件是 `leftIndex > rightIndex`**
    * 查找过程中左下标一路往右挪、右下标一路往左挪，两个下标越靠越近。
    * 一种极端情况是左右下标**相等**，此时还能再进行一次比较，这已经是最后一次；这一次还不是就说明真的找不到了，因为已经全部扫描过一遍。
    * 再往后一步，左下标就会超过右下标，这个条件一出现就说明真的找不到。

    ```go
    if leftIndex > rightIndex {
        // 说明找不到了，退出递归
    }
    ```

    * 没有分析出这个条件，二分写出来一定是死循环。

* **函数签名与四个参数**
    * `func BinaryFind(arr *[6]int, leftIndex int, rightIndex int, findValue int)`。
    * 数组**用指针接收，这样不用进行值拷贝，效率高很多**。
    * `leftIndex` 和 `rightIndex` 告诉它从左边第几个开始、从右边哪个下标结束，`findValue` 是要查找的那个数。

* **实现的三步顺序**
    * 第一步把 `leftIndex > rightIndex` 的判断写在函数体最前面，成立就打印「找不到」并 `return`。
    * 第二步求中间下标 `mid := (leftIndex + rightIndex) / 2`。
    * 第三步按三种可能分支递归：往左时传 `mid-1` 且 `leftIndex` 保持不变，往右时传 `mid+1` 且 `rightIndex` 保持不变，相等时打印「找到了，下标为 mid」。
    * > **易错点**：`arr` 是指针，`arr[mid]` 取不到元素，**必须先用取值符再取下标**，写成 `(*arr)[mid]`。
    * > **易错点**：递归里的 `return` 一定要写。不写的话即使命中了 `leftIndex > rightIndex` 分支，函数还会往下走，递归停不下来，结果就是死循环。
    * 找不到时 `return` 一层层把它返回回去；找到时打印的下标就是 `mid`。

* **调用方式**
    * 第一个参数要传**地址** `BinaryFind(&arr, ...)`，因为形参接收的是数组指针。
    * 递归调用函数本身时**不用再加 `&`**，指针传给指针当然可以。
    * 左边界传 0，右边界 `len(arr)-1` **一定要减 1**，不减 1 就跑到数组外面去了。

* **验证结果**
    * 查 1000 得到「找到了，下标为 4」，查 1 得到下标 0，查 89（中间的值）也能找到。
    * 查 -6 时数组里没有，正确提示「找不到」。

## 二维数组

### 本质与应用场景

* **二维数组的本质**
    * 二维数组是多维数组里最简单的一种。
    * > **定义**：二维数组就是一维数组里边的元素又是数组；它具有一维数组的形式，只是在一维数组的元素位置上再放一个一维数组。
    * 一维数组的元素是基本数据类型如 `int`、`float`、`string`，二维数组则是把这些元素换成了数组。

* **典型应用场景**
    * 写五子棋游戏时棋盘就是一个二维数组。
    * 基于递归的迷宫小游戏里，迷宫本身就是二维数组，点击「走」后小球沿路径走到终点就说明迷宫走完。
    * 迷宫用到的正是**二维数组加上递归回溯算法**，因为有回溯，小球走到某处还可能退回去一趟。
    * 网络游戏的地图内部也是二维数组。

### 声明、赋值与图形输出

* **声明 `var arr [4][6]int`**
    * `var` 是关键字，数组名是 `arr`；`[4]` 表示这是一个有四个元素的数组。
    * 但每个元素不再是 `int`，**又是一个数组**；这个 4 是「四个元素里每个放的是什么」，放的是一个 6。
    * 即「有一个一维数组可以放四个元素，但每个元素又是一个一维数组」。
    * 写完这行就已经有初始值，全部为 0，直接输出就是四个元素的全零状态。

* **赋值时两层下标都从 0 开始**
    * `arr[1][2] = 1` 表示第二个一维数组里的第三个元素为 1。
    * `arr[2][1] = 2` 表示第三个一维数组里的第一个元素为 2。
    * `arr[2][3] = 3` 表示第三个一维数组里的第四列放 3——第四列写 3，正因为下标从 0 开始编。

* **遍历输出图形**
    * 外层循环 `i` 走行，内层循环 `j` 走列，内层条件是 `j < 6`。
    * 内层输出写成 `fmt.Print(arr[i][j], " ")`，输完一个元素加一个空格。
    * 内层循环走完一个一维数组后用 `fmt.Println()` 换行，因为要求一排一排地输出。
    * 只写外层循环会横向输出并且带中括号，必须再套一层才能把每个元素单独取出来。

### 内存布局

* **空间里存的是两个指针**
    * `array2` 这个变量对应的空间**不直接存放数据**，而是被分成两部分，各存一个指针。
    * 这两个指针分别指向两个一维数组的**首地址**；两个一维数组刚声明完时里面默认值都是 0。
    * 把数据调小是为了便于作图，用两个元素、每个元素三个 `int` 的结构来说明。

    ```text
       array2 变量对应的空间（不存数据，只放两个指针）
       ┌────────────────┬────────────────┐
       │     指针 1     │     指针 2     │
       └────────┬───────┴────────┬───────┘
                │                │
                ▼                ▼
       ┌── 一维数组 1 ───┐  ┌── 一维数组 2 ───┐
       │   0      0     0 │  │   0      10     0 │
       └───────────────────┘  └───────────────────┘
            ↑                          ↑
       &arr2[0]                    &arr2[1]
       = &arr2[0][0]              = &arr2[1][0]

       两块一维数组的首地址相差：3 × 8 = 24 字节
    ```

* **地址差值的规律**
    * `&arr2[0]` 与 `&arr2[1]` 打印出来刚好相差 24 个字节，因为每个元素里有 3 个 `int`，一个 `int` 占 8 字节，跨度就是 3 × 8。
    * `&arr2[0][0]` 与 `&arr2[0]` 完全相同，`&arr2[1][0]` 与 `&arr2[1]` 也完全相同，这就证明了指针确实指向两个一维数组的首地址。
    * 把 `[2][3]` 改成 `[2][2]`，每个一维数组只有两个 `int`，地址相差 16 字节。
    * 再改成 `[2][1]`，地址相差 8 字节。

* **赋值时如何定位**
    * 执行 `arr2[1][1] = 10` 时，先找到 `arr2` 里的第二个元素（也就是 `arr2[1]`）对应的指针，再在下标为 1 的位置改值；下标 1 就是第二个元素。
    * 结果是第一个一维数组仍然是三个 0，第二个变成 0、10、0。

### 声明与初始化的几种写法

* **使用方式一：先声明再赋值**
    * 语法是 `var 数组名 [大小1][大小2]类型`。
    * 第一个大小指二维数组共有多少个元素，第二个大小指里面的各个一维数组各有几个元素。
    * 后面这个大小可以带上也可以省略，省略一样成立。

* **使用方式二：定义时直接初始化**
    * `var arr3 [2][3]int = [2][3]int{{1, 2, 3}, {4, 5, 6}}`，写完之后仍然可以改也可以不改。

* **在此基础上的变体写法**
    * 前面的 sizes 可以省略写成 `[...]`，让编译器根据初值自行推导：`var arr4 [...]int = [2][3]int{{1, 2, 3}, {4, 5, 6}}`。
    * > **注意**：`[...]` 能推导是因为赋初值时已经知道一共赋了几组、每组几个数，**但后面这个大小不能省略**。
    * 前面的类型可以省略，因为后面的值已经把具体数据交给了它：`var arr5 = [2][3]int{{1, 2, 3}, {4, 5, 6}}`。
    * `var` 也可以去掉，但去掉后必须给 `:=`，这就是类型推导：`arr6 := [2][3]int{{1, 2, 3}, {4, 5, 6}}`。

## 二维数组的遍历方式

* **方式一：双层 for 循环**
    * 外层条件写 `i < len(arr3)`，不能用 `len` 之外的东西写死，别人一变就出问题。
    * 内层条件写 `j < len(arr3[i])`，统计的是当前这个 `i` 对应的那一个一维数组里有多少个元素。
    * > **提示**：Go 本身要求每个一维数组的个数是一样的，写 `len(arr3[i])` 而不是写死 5，纯粹是为了代码更健壮。
    * 输出用 `%v` 并跟一个 `\t`，每遍历完一个一维数组就 `fmt.Println()` 换行。

* **方式二：for-range 嵌套**
    * 外层 `for i, v := range arr3`，此时 `v` **不是一个具体元素的值，而是一个一维数组**。
    * 内层 `for j, v2 := range v`，`v2` 才是具体的值。
    * 输出格式化成 `arr3[%v][%v]=%v\t`，`i` 对应第一个中括号、`j` 对应第二个中括号、`v2` 对应元素值。
    * 两种写法遍历结果完全相同：双层 for 得到 `1 2 3`、`4 5 6`，for-range 得到 `arr3[0][0]=1` 一直到 `arr3[1][2]=6`。
    * > **易错点**：第一层只写 `for i, v := range arr3` 而后面又没用到 `i`，会报 `i` 没有使用；暂时不用就先把它打印出来。

## 三个班五名学生的平均分

* **第一步：定义二维数组**
    * `var scores [3][5]float64`，第一个 3 代表三个一维数组，第二个 5 代表每个一维数组里有五个元素即五个成绩，类型是 `float64`。
    * 一维数组在这里已经搞不定，因为区分不出是哪个班的。

* **第二步：循环输入成绩**
    * 外层 `i < len(scores)`，内层 `j < len(scores[i])`。
    * 提示语是 `请输入第%d个班的第%d个学生的成绩` 并传 `i+1`、`j+1`，因为下标从 0 开始但不能说「第 0 个班」。
    * 接收用 `fmt.Scanln(&scores[i][j])`，**别忘了 `&`**，必须传地址。

* **第三步：统计平均分**
    * `sum` 要定义在**班级循环里面、学生循环外面**，这样一轮内层循环下来 `sum` 才是这个班的总分。
    * 内层遍历完一个班级就 `totalSum += sum`，而 `totalSum` 必须定义在最外层；定义到内层会在每次循环时被重新赋值，就没有意义了。
    * > **易错点**：平均分不能写死除以 5，通用写法是 `len(scores[i])`，代表当前这个班级有几个学生。
    * > **易错点**：`scores` 是 `float64` 而 `len()` 返回 `int`，Go 运算时不会隐式转换，必须写成 `sum/float64(len(scores[i]))`，否则报类型不匹配。
    * 所有班级的平均分最后除以 15，因为一共 15 个学生；觉得麻烦也可以再定义一个变量把总人数统计出来。

* **易错点与验证结果**
    * > **易错点**：如果 `fmt.Printf` 的参数一行太长想换行，**换行时要在上面一行留一个逗号**，把逗号拿到下一行去会语法报错。
    * 第 1 个班全输 1 分时总分 5、平均 1；第 2 个班全输 2 分时总分 10、平均 2；第 3 个班全输 3 分时总分 15、平均 3；所有班级总分 30、平均 2。

## 数组与查找的练习清单

* **随机数综合题**
    * 随机生成 10 个 1 到 100 之间的整数，倒序打印，求平均值、最大值和最大值的下标，并查找里面有没有 55 这个数。
    * 用 `rand` 包里的 `Intn` 方法。

* **升序数组插入元素**
    * 往已排好序的升序数组里插入一个元素，最后打印出来仍然是升序的。
    * 数组不可以动态增长，所以要先**创建一个比原先大一个元素的新数组**，按顺序把原数组元素拷贝进去，同时考虑插入的元素该放在哪个位置。

* **二维数组清零与行交换**
    * 定义一个 3 行 4 列的二维数组，逐个从键盘输入值，编写程序将四周的数据清零。
    * 定义一个 4 行 4 列的二维数组，逐个从键盘输入值，然后将第一行和第四行交换、第二行和第三行交换。

* **查找的拓展**
    * 把 1、3、5、7、9 五个奇数保存到数组中并倒序打印。
    * 已知字符串数组保存了 10 个元素，查找里面有没有 `"AA"` 并打印提示信息；**拓展要求是如果数组里有多个 `"AA"`，也要把对应的下标都找出来**——原先的顺序查找找到一个就退出了，这里不能找到一个就跑路。
    * 随机生成 10 个 1 到 100 之间的整数，用冒泡法排序；排完之后用二分查找判断是否有 90 这个数并显示下标，没有就提示找不到。
    * 编写一个函数接收一个含 5 个数的数组，找出最大数、最小数以及对应的下标。
    * 定义一个含 8 个整数的数组，求大于平均值的数的个数和小于平均值的数的个数。

* **跳水比赛题**
    * 8 个评委打分，运动员成绩是去掉一个最高分、去掉一个最低分之后剩下 6 个分数的平均分，国际上也是这么打分的。
    * 用一维数组实现两个功能：找出打分最高的评委和最低的评委是哪两个人；找出最佳评委和最差评委——最佳是打分与最后得分最接近的，最差是相差最大的。

## map 的声明与初始化

* **map 的定义与声明语法**
    * > **定义**：map 是一个 key-value 的数据结构，又称字典或者关联数组，类似于其他编程语言里的集合；通过一个 key 可以找到对应的 value。
    * 官方叫「映射」，本质上就是一个集合。
    * 典型用法是 key 用学生编号、value 用学生名字。
    * 语法是 `var map变量名 map[keytype]valuetype`，中括号里写 key 类型，后面写 value 类型。

* **key 与 value 能用的类型**
    * key 可以是 bool、数字、string、指针、channel（管道），还可以是只包含前面这些类型的接口、结构体和数组。
    * 但用接口、结构体或数组做 key 非常奇怪，实际中 **90%、99% 都用 `int` 或者 `string` 作为 key 的类型**。
    * > **易错点**：`slice`、`map`、`function` **绝对不可以**做 key，官方解释是没法用等号来判断——key-value 将来主要用来判断某个 key 是否存在。
    * value 的可选类型与 key 基本相同；常见做法是数字、`string`，也常用另一个 map 从而构成**多重 map**，用得比较多的是 struct。

* **声明不会分配内存**
    * > **结论**：声明一个 map 不会分配内存，它没法直接用；初始化需要 `make`，分配内存过后才能赋值和使用。
    * 这跟数组完全不一样——数组声明完空间就已经分配好，map 声明完空间是不分配的。
    * `var a map[string]string` 直接打印得到空的 `map[]`；此时给它赋值会 panic：`assignment to entry in nil map`。
    * 好比有个人要去住房子，房子都不存在自然住不进去，这就是报错的来源。
    * `make` 的第一个参数要写上完整的 map 类型（key 类型和 value 类型），后面写分配多大空间，如 `a = make(map[string]string, 10)` 表示可以放 10 对 key-value。

* **key 不能重复、value 可以重复**
    * 同一个 key 再赋值会**覆盖**前面的值：先给 `no1` 写宋江，再给 `no1` 写武松，map 里 `no1` 就变成武松。
    * 值完全可以重复：`no2` 和 `no3` 都写吴用不冲突，因为它们的 key 不一样。
    * 重复时**以最后一个 key-value 为准**。

* **map 是无序的**
    * 每次运行 key 的输出顺序都可能不同，有的语言里的 map 会按 key 排序或按添加顺序排序，Go 里的 map **既不按 key 排序也不按添加顺序排序**。
    * 所以拿到一个 map 想排序还需要另外的排序方法。

* **必须记住的四条**
    * map 在使用前一定要 `make`。
    * key 不能重复，重复则以最后这个 key-value 为准。
    * value 可以重复、可以相同。
    * key-value 是无序的，key 和 value 都无序。

* **make 分配映射的说明**
    * 手册里说内建函数可以分配初始化一个切片或者映射；映射这一条是：初始分配的容量取决于 `size`，但**产生的映射长度为 0**。
    * `size` 可以省略，省略时只会分配一个默认大小的初始值。
