# 函数、包与递归调用

## 为什么需要函数

* **从重复代码说起**

    * 需求是输入两个数再输入一个运算符得到一个结果，运算符决定做加、减、乘还是除。

    * 传统写法直接定义三个变量再用 `switch` 判断：

      ```go
      var n1 float64 = 1.2
      var n2 float64 = 2.3
      var operator byte = '+'
      var res float64

      switch operator {
      case '+':
          res = n1 + n2
      case '-':
          res = n1 - n2
      case '*':
          res = n1 * n2
      case '/':
          res = n1 / n2
      default:
          fmt.Println("操作符号错误")
      }
      fmt.Println("res=", res)
      ```

    * `operator` 是操作符，因为事先不知道是哪一个所以要单独定一个变量，用 `byte` 是因为可以用字符来表示。

    * 这种写法能完成功能，`1.2 + 2.3` 得到 `res = 3.5`，功能上没有问题。

* **传统写法的两个问题**

    * 同一段代码会在程序里多次出现，别处再需要算加减乘除就只能把这一串再复制一遍，导致代码出现冗余。

    * 不利于代码维护：想加一个功能，比如加一个求两数最大值或求模的分支，改了这一处，下面所有复制过的地方都得跟着加一遍。

    * 这两个问题就是必须引出函数的直接原因，函数体现出模块化编程的思想。

* **函数的定义**

    * > **定义**：函数是为完成某一个功能的程序指令的集合，也就是程序语句的集合。

    * Go 中的函数分成两大类：**自定义函数**是自己写的函数；**系统函数**是系统提供的函数，如 `fmt.Println`。

    * 函数由六部分组成：`func` 关键字（不能改）、函数名（一个标识符）、参数列表（也叫形参列表）、返回值类型列表、一对必须有的花括号、函数体。

    * 形参列表表示函数的输入；函数中的语句是为实现某一个功能的代码块。

    * 函数可以有返回值也可以没有；没有返回值就不要写返回类型，直接 `return` 就完了。

    * > **定义**：`return` 有两个作用——返回一个值，以及表示终止这个函数的执行；它在终止的同时把值返回了。

* **自定义函数快速入门**

    * 思路是把这一段功能封装成一个函数，需要时调用即可；函数名 `cal` 是 `calculator` 的简写。

      ```go
      // 自定义函数：计算两个数的加减乘除
      func cal(n1 float64, n2 float64, operator byte) float64 {
          var res float64
          switch operator {
          case '+':
              res = n1 + n2
          case '-':
              res = n1 - n2
          case '*':
              res = n1 * n2
          case '/':
              res = n1 / n2
          default:
              fmt.Println("操作符号错误，没法计算")
          }
          return res
      }
      ```

    * 形参声明时先写形参名称再写类型 `float64`，顺序不能反。

    * 只有一个返回值时括号可以省略，写上也没有问题。

    * 调用时的实参与形参一一对应：`result = cal(5.3, 2.3, '-')` 把 5.3 传给 `n1`、2.3 传给 `n2`、减号传给 `operator`，结果 `result` 等于 3。

    * 直接传具体值很累，可以把调用方自己的变量传进去：`result = cal(n1, n2, operator)` 得到 `result = 3.5`。

    * 再算一组只要一句话：`result = cal(4.5, 6.7, '*')`。

    * 增加功能只需在函数内部加一个 `case '%': res = n1 % n2`，调用方就直接具备了这个功能，维护性非常好。

## 包

* **包要解决的两个问题**

    * 第一个问题是跨文件复用：理论上可以把成百上千个函数都写进 `main.go`，但显然不合适；专门写一个 `utils.go` 存放通用函数、专门写一个 `db.go` 存放数据库操作函数，把函数剪切过去，需要时引入即可。

    * 第二个问题是命名冲突：两个程序员共同开发项目时可能都想定义一个叫 `CAL` 的函数，同一个文件里出现相同函数名会报 `Cal redeclared in this block`（已声明过，不允许再声明）。

    * 分了包之后两个人不在同一个包里，各自都可以叫 `CAL`，靠包来区分。

* **包的本质与三大作用**

    * > **定义**：包的本质就是创建不同的文件夹来存放程序文件；一个包往往对应一个文件夹，这个文件夹下面就是我们的文件。

      ```text
      oa（项目）
      ├── main（包）
      │   └── main.go
      ├── utils（包）
      │   └── utils.go
      └── db（包）
          └── db.go
      ```

    * > **定义**：Go 的每一个文件都属于一个包，Go 语言是以包的形式来管理文件和项目目录结构的。

    * 第一，区分相同名字的函数、变量等标识符——不同包下可以写相同的函数名，变量名也可以相同。

    * 第二，当程序文件很多时可以很好地管理项目，比如分成 `model` 包、`service` 包、`utils` 包。

    * 第三，控制函数、变量的访问范围及作用域。

    * 用到的两个指令：打包指令 `package 包名`（如 `package main`）和引入指令 `import`。

* **打包与引入的写法**

    * 第一步建目录：把 `main.go` 移进 `main` 文件夹成为 `main` 包，再建 `utils` 文件夹并在下面新建 `utils.go`，打包写成 `package utils`。

    * 第二步函数名首字母必须大写，官方术语叫**可导出**，类似其他语言的 `public`；不写大写即使引入 `utils` 包也用不了，编译报 `undefined: cal`。

    * 第三步引入包并按"包名点函数名"调用：

      ```go
      import "go_code/chapter06/function_demo01/utils"

      result = utils.Cal(n1, n2, operator)
      ```

    * 引入路径从 `GOPATH` 的 `src` 下面开始写，但不用写 `src`，因为默认就是从 `src` 下面开始定位。

    * `utils.go` 里自己用了打印，所以它自己也要 `import "fmt"`。

    * 把 `Cal` 写成小写 `cal` 后调用会报 `cannot refer to unexported name utils.cal`——首字母小写代表私有，私有不可跨包访问。

* **包名与文件夹名**

    * 一个包对应一个文件夹，文件的包名通常和所在文件夹名保持一致，一般为小写。

    * > **注意**：Go 语言并没有强制要求包名必须和文件夹名一致——文件夹叫 `utils`、包名叫 `abc` 语法上完全可以。

    * 但一旦引入路径写的是 `utils` 文件夹，调用时就不能再用 `utils` 去调，运行会报 `undefined: utils`，必须写成 `abc`。

      ```text
      文件夹名：utils   →   import ".../utils"
      包名：     abc     →   调用时必须写 abc.函数名()
      ```

    * 写调用时用的是**包名**，`import` 引入的只是**包所在的文件夹**；虽然可以不一致，习惯上还是保持一致。

* **package 与 import 的规矩**

    * 一个文件要使用其它包的函数或变量，必须先引入这个包；引入形式有两种：单独写 `import "包名"`，或者把多个包名写在一块，习惯上按规范写在一起。

    * `package` 打包指令一定放在文件第一行，然后是 `import`，接着才是函数的定义与执行，这跟 Java 一样。

    * 编译器会先从 `GOROOT` 找，但 `GOROOT` 一般不放自己写的包，找不到就从 `GOPATH` 的 `src` 开始找；例如 `GOPATH` 配的是 `D:\go_project`。

    * 这是 Go 的开发规范：通常在该路径下建 `src`，在 `src` 下面再建项目。

    * 包名比较长时 Go 支持取别名，`import util "go_code/chapter06/function_demo01/utils"`；但取完别名后原来的包名就不能再用了，写 `utils` 会报 `undefined: utils`。

    * 要用原来的名字就不要取别名。

## 编译与产物

* **同包不能重名**

    * > **定义**：在同一个包下不能有相同的函数名，否则报重复定义错误；同样也不能有相同的全局变量名。

    * Go 是以包为单位管理函数的，调用时是通过包名去调用的；同一个包下如果有两个相同函数名，编译器根本无法区分调的是哪一个。

    * 在 `utils` 包下的另一个文件 `utils2.go` 里再写一个 `calculate`，即使不在同一个文件，一保存就报 `calculate redeclared`。

* **main 包与可执行文件**

    * > **定义**：要编译成一个可执行文件，需要把包声明为 `main`（即 `package main`），而且 `main` 包只能有一个。

    * 可执行文件其实就是 `main` 函数所在的那个文件。

    * 如果是库文件，包名可以自定义（比如 `utils`）；但只有 `main` 包里面的文件最终才能形成一个可执行文件。

* **go build 与 -o**

    * 真实开发中不可能一直 `go run` 源代码，`go run` 只是讲课方便；实际要生成可执行文件交给服务器或客户使用。

    * 编译时先切换到 `GOPATH` 路径下面，不要在源码目录里编译，然后编译 `main` 包所在的文件夹。

    * `go build gocode/chapter06/funcdemo01/main` 执行完会生成 `main.exe`，大小约 1.9 兆，运行效果与 `go run` 一致；路径从 `src` 下面的项目名称开始写。

    * 指定名字和目录用 `-o`：`go build -o bin/my.exe gocode/chapter06/funcdemo01/main`；`-o` 表示输出，`bin` 目录不存在会自动生成。

    * > **易错点**：不指定名字默认生成 `main.exe`；指定名字和目录要用 `-o`，且路径相对 `GOPATH` 写、不带 `src`。

* **编译时顺手生成的库文件**

    * 编译完成后还会生成一个 `pkg` 文件夹，里面是各包的 `.a` 库文件，例如 `utils.a`。

    * 库文件是二进制码，打开看到的是乱七八糟的内容，用十六进制查看器才打得开，看不到源代码。

    * Go 会把其它包的文件生成 `.a`，开发者可以不交源文件、直接把这个库文件交给对方；对方引进去后看文档就能调用里面的函数，包括写的结构体和变量，再配一份文档即可。

## 函数调用机制

* **内存的三个区域**

    * 程序运行时内存被分成三部分：

      ```text
      ┌──────────────────────────────────────────────────────────┐
      │  代码区（Code）                                          │
      │  存放指令本身，CPU 靠它知道要做加减乘除——好比拍电影得有剧本│
      └──────────────────────────────────────────────────────────┘
      ┌───────────────────────────┐ ┌──────────────────────────┐
      │  栈区（Stack）             │ │  堆区（Heap）            │
      │  ┌─────────────────────┐  │ │  一般来说引用数据类型分配 │
      │  │  main 栈区          │  │ │  在堆区：                │
      │  │    n1 = 10          │  │ │    map、切片 …           │
      │  └──────────┬──────────┘  │ │  Java 里的"对象"也在这   │
      │             │ 传入实参    │ │                          │
      │  ┌──────────▼──────────┐  │ │                          │
      │  │  test 栈区          │  │ │                          │
      │  │    n1 = 10 → 11     │  │ │                          │
      │  └─────────────────────┘  │ │                          │
      └───────────────────────────┘ └──────────────────────────┘
      ```

    * 栈区：函数在调用、执行过程中，基本数据变量分配在栈区。

    * 堆区：引用数据类型一般分配在堆区，比如 `map`、切片；Java 语言里的对象也分配在堆区。

    * 代码区：存放指令本身，CPU 靠它知道要执行什么。

    * > **易错点**：说"一般"是因为 Go 的编译器有**逃逸分析**的特点，不一定所有基本数据类型都分配在栈区；这三个区是**逻辑上的划分**而不是物理上的划分。

* **调用时的三条要点**

    * > **定义**：调用一个函数时，会给该函数**分配一个新的空间**，编译器会处理成和原有的栈空间分界开来。

    * > **定义**：每个函数对应的栈中，它们的数据空间是**独立的**，不会混淆在一起。

    * > **定义**：一个函数调用完毕（执行完毕）后，程序会**回收或者销毁**这个函数对应的栈空间。

    * 典型案例：故意在 `main` 和 `test` 里都叫 `n1`。

      ```go
      func test(n1 int) {
          n1 = n1 + 1
          fmt.Println("test() n1=", n1)
      }

      func main() {
          n1 := 10
          test(n1)
          fmt.Println("main() n1=", n1)
      }
      ```

    * 执行 `n1 := 10` 时栈区里给 `main` 划分一块空间存放 `n1 = 10`；执行 `test(n1)` 时按操作系统机制再开辟一块新的 `test` 空间，并把 10 传进去，所以两个 `n1` 同名但独立，好比 A 教室和 B 教室各有一个叫三毛的人。

    * `test` 里执行 `n1 = n1 + 1` 变成 11，输出 `test() n1= 11`；函数执行完这个空间被编译器回收，回到调用处继续输出，`main` 的 `n1` 仍是 10。

    * 最终输出是 `test() n1= 11` 和 `main() n1= 10`。

    * 传引用类型时例外，`test` 和 `main` 可能指向同一个数据空间。

* **return 把结果带回来**

    * > **定义**：当函数有 `return` 语句时，就是将这个结果返回给调用者——谁调用我，我就返回给谁。

      ```go
      func getSum(n1 int, n2 int) int {
          sum := n1 + n2
          return sum
      }

      func main() {
          sum := getSum(10, 20)
          fmt.Println("getSum里面的 sum=", sum)
          fmt.Println("main sum=", sum)
      }
      ```

    * 两句话完全可以合成 `return n1 + n2`，怎么写看习惯。

    * `return` 前面必须写清返回值类型列表；写漏了会直接编译报错。

    * 两处输出都是 30，因为结果已经返回给调用者，调用处是多少这里也就是多少。

* **返回值的写法**

    * 返回一个值时括号可以不写，写上也可以；Go 开发者习惯不写。

    * 返回多个值时**必须写括号**，多个返回值用逗号间隔。

      ```go
      func getSumAndSub(n1 int, n2 int) (int, int) {
          sum := n1 + n2
          sub := n1 - n2
          return sum, sub
      }
      ```

    * 调用时第一个返回值交给 `res1`、第二个交给 `res2`：`res1, res2 := getSumAndSub(1, 2)` 得到 `res1 = 3`、`res2 = -1`。

    * 只想取其中一个值时，用下划线 `_` 占位忽略另一个：`result3, _ = getSumAndSub(3, 9)`，结果 `result3` 等于 -6。

    * > **结论**：Go 函数支持直接返回多个值，这是其他编程语言没有的；其他语言往往要通过数组来实现多值返回。

## 函数使用细节

* **形参与返回值列表**

    * 形参列表可以是多个的，返回值列表也可以是多个的。

    * 形参列表和返回值列表的数据类型可以是值类型也可以是引用类型，返回类型没有限定：整数、字符串、`map`、数组都可以。

    * 函数命名按已有的命名规范来，**首字母不能是数字**。

    * 函数名首字母大写则该函数可以被本包文件和其他包文件使用；首字母小写只能被本包文件使用，类似于 `private`。

* **函数中的变量是局部的**

    * 函数中声明的变量是局部变量，作用范围只在该函数内，函数外不生效。

      ```go
      func test() {
          // n1 是 test 函数的局部变量，只能在 test 函数中使用
          var n1 int = 10
      }

      func main() {
          // 这里不能使用 n1
      }
      ```

    * 在 `main` 里使用 `test` 的 `n1` 会报 `undefined: n1`。

* **值传递**

    * > **定义**：基本数据类型和数组默认都是**值传递**，即进行值拷贝，在函数内修改不会影响到原来的值。

    * > **注意**：Java 的数组是引用传递，函数内能改到函数外的数组；Go 不是引用传递，讲过 Java 的同学一定要把这个观念倒过来。

      ```go
      func test02(n1 int) {
          n1 = n1 + 10
          fmt.Println("test02() n1 =", n1)
      }

      func main() {
          var num int = 20
          test02(num)
          fmt.Println("main() num =", num)
      }
      ```

    * 运行结果是 `test02() n1 = 30` 和 `main() num = 20`：值拷贝把 `num` 的 20 拷给 `test02` 里的 `n1`，它们是两个不同的变量。

* **传地址**

    * 如果真的希望函数内的变量能修改函数外的变量，可以传入地址，函数内以指针方式操作，效果上类似引用传递。

      ```go
      func test03(n1 *int) {
          *n1 = *n1 + 10
          fmt.Println("test03 中的 n1 = ", *n1)
      }

      func main() {
          var number int = 20
          fmt.Printf("number 的地址 = %v\n", &number)
          test03(&number)
          fmt.Println("main 中的 number = ", number)
      }
      ```

    * 关键只有三处：形参变成指针类型 `*int`，调用时传 `&number`，函数内写 `*n1 = *n1 + 10`。

    * `&` 是取地址符，`*` 是取指针指向那个值的运算符。

    * 运行结果两处都变成 30，因为传的是地址，两者操作的是同一块数据空间。

      ```text
         main 栈                          test03 栈
      ┌──────────────────┐              ┌──────────────────┐
      │ number = 20      │              │ n1  (*int)       │
      │   地址 A         │◄─────────────┤   存的值 = 地址 A │
      └──────────────────┘              └──────────────────┘
              ▲                                  │
              └──────────────────────────────────┘
                   n1 指向 number，两者操作同一块空间

        test03(&number)  →  n1 里装的就是 &number 本身
        *n1 = *n1 + 10   →  直接把 number 那块空间的 20 改成 30
        test03 返回       →  test03 栈销毁，但 number 已经是 30
      ```

    * 就算是一个基本数据类型它也有地址，用 `fmt.Printf("%v\n", &number)` 就能打出来。

    * `n1` 自己也有地址（`&n1`），它是指针类型、本身有存放空间，里面装的才是指向 `number` 的地址，两个地址显然不一样。

* **不支持函数重载**

    * > **定义**：Go 函数里面不支持传统的函数重载。

    * 很多语言里函数名可以相同，只要形参个数或数据类型不同就算不同的函数；Go 里这么写会报 `function test02 redeclared in this block`。

      ```go
      func test02(n1 int) {
      }

      func test02(n1 int, n2 int) {
      }
      ```

    * > **易错点**：Go 认为这两个 `test02` 是同一个函数，报重复定义错误。

    * Go 不需要重载是因为它支持**可变参数**，还有**空接口**，用另外一种形式可以达到同样的效果。

## 递归调用

* **递归的定义**

    * > **定义**：一个函数在函数体内调用了本身，就称为递归调用。

      ```go
      func test(n int) {
          if n > 2 {
              n--
              test(n)
          }
          fmt.Println("n=", n)
      }

      func main() {
          test(4)
      }
    ```

    * 调用函数时按机制会开辟一个新空间，栈的规则是**先入后出**，所以新的空间画在上面。

      ```text
      ┌──────────────────┐
      │    main 栈        │
      │   调用 test(4)   │
      └────────┬─────────┘
               │ 调用
               ▼
      ┌──────────────────┐
      │    test 栈       │   n = 4
      │   n > 2 ?  成立  │
      │   n--  →  n = 3  │
      │   ↓ 打印还没执行 │
      └────────┬─────────┘
               │ test(3)   ← 下面打印语句先不执行
               ▼
      ┌──────────────────┐
      │    test 栈       │   n = 3
      │   n > 2 ?  成立  │
      │   n--  →  n = 2  │
      │   ↓ 打印还没执行 │
      └────────┬─────────┘
               │ test(2)
               ▼
      ┌──────────────────┐
      │    test 栈       │   n = 2
      │   n > 2 ? 不成立 │
      │  ✅ 打印 n = 2    │   ← 最先输出
      └────────┬─────────┘
               │ return（该栈销毁）
               ▼
      ┌──────────────────┐
      │    test 栈       │   n 仍是 2
      │  ✅ 打印 n = 2    │   ← 第二个输出
      └────────┬─────────┘
               │ return（该栈销毁）
               ▼
      ┌──────────────────┐
      │    test 栈       │   n 仍是 3
      │  ✅ 打印 n = 3    │   ← 第三个输出
      └────────┬─────────┘
               │ return（该栈销毁）
               ▼
           main 栈销毁，程序结束
      ```

    * 进入 `test` 栈后，下面代码先不执行，先去执行新开的那个栈；最内层 `n = 2` 不满足条件直接输出，栈销毁后回退的那两层各自打印自己的 `n`。

    * 输出依次是 `n = 2`、`n = 2`、`n = 3`，即 **2 2 3**。

    * > **提示**：第一次跑的时候没有输出结果，是因为没有保存代码；重新保存再执行就是 2 2 3。

* **只改一个 else，结果完全变了**

    * 把打印语句挪进 `else` 分支，其余不变：

      ```go
      func test2(n int) {
          if n > 2 {
              n--
              test2(n)
          } else {
              fmt.Println("n=", n)
          }
      }
      ```

    * 最内层栈 `n = 2` 不满足条件，执行 `else` 输出 `n = 2`；回退的两层都是从 `if` 分支进来的，`if` 与 `else` 互斥，`else` 分支不参与执行，什么都不输出。

    * 最终只输出一行 `n = 2`。

    * 本质差异在于结构变成了 if-else：最上面那个栈直接进入了 `else`，其余栈返回时执行的是 `if` 分支。

* **递归调用的四条铁律**

    * 第一，执行一个函数时就会创建一个新的受保护的独立空间，也就是一个新的函数栈；每调用一次就产生一个新空间，它们之间数据和执行的代码都完全独立。

    * 第二，函数的局部变量是独立的，互相不受影响；名字相同不代表是同一个变量。

    * 第三，递归必须向退出递归的条件逼近，否则就是无限循环、变成死递归。

    * > **易错点**：把 `n--` 去掉，`test(4)` 进去后 `n` 永远是 4、永远大于 2，会无限地往里跑出不来；写成 `n++` 更可怕，值越来越大更出不来。

    * 第四，当一个函数执行完毕或遇到 `return` 时就返回，遵守谁调用就将结果返回给谁；同时该函数本身被销毁、栈空间被释放。

* **递归练习：斐波那契数**

    * 斐波那契数的定义：第一个数是 1，第二个数也是 1，第三个数开始是前面两个数的和。

    * 给定整数 $n$ 求它的斐波那契数，两条分析：当 $n = 1$ 或者 $n = 2$ 时返回 1；当 $n \ge 2$ 时返回前面两个数的和 $f(n-1) + f(n-2)$。

      ```go
      func fbn(n int) int {
          if n == 1 || n == 2 {
              return 1
          } else {
              return fbn(n-1) + fbn(n-2)
          }
      }
      ```

    * > **易错点**：这里的条件写的是等号 `==`，不能手滑写成赋值 `=`。

    * 前提是 $n$ 是一个大于等于 1 的整数；实测 $f(3) = 2$、$f(4) = 3$、$f(5) = 5$、$f(6) = 8$。

* **递归练习：题目直接给表达式的情形**

    * 已知 $f(1) = 3$，当传入 $n$（$n > 1$）时返回 $2 \times f(n-1) + 1$，用递归求出 $f(n)$。

    * 做递归最重要的事情就是拿到这个函数的表达式，题目把表达式给了，直接翻译成递归代码即可。

      ```go
      func f(n int) int {
          if n == 1 {
              return 3
          } else {
              return 2*f(n-1) + 1
          }
      }
      ```

    * 实测 $f(1) = 3$、$f(5) = 63$。

* **递归练习：猴子吃桃子**

    * 猴子第一天吃掉一堆桃子的一半再多吃一个，以后每天都吃一半再多吃一个；第十天想吃的时候（还没吃）发现只有一个桃子，问最初共有多少桃子。

    * 关键转折是从最后一天往前推：第九天的桃子数等于第十天的桃子数加 1、括起来再乘以 2。

    * $$\text{peach}(n) = (\text{peach}(n + 1) + 1) \times 2$$

    * 因为是倒着推，这里是 $n + 1$ 而不是 $n - 1$，写成 $n-1$ 就变成正推了。

      ```go
      func peach(n int) int {
          if n > 10 || n < 1 {
              fmt.Println("输入的天数不对")
              return 0
          }
          if n == 10 {
              return 1
          } else {
              return (peach(n + 1) + 1) * 2
          }
      }
      ```

    * $n$ 的范围要求是 1 到 10 之间，越界时提示"输入的天数不对"并返回 0，表示没有得到正确数量。

    * 实测 $peach(1) = 1534$、$peach(9) = 4$（四个吃一半剩两个再吃一个，正好剩一个）、$peach(10) = 1$。
