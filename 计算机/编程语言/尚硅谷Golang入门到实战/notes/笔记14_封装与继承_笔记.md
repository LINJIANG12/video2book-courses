# 封装与继承

## 抽象

   * **抽象（Abstraction）**

       * > **定义**：一种研究问题的方法，把一类事物共有的属性和行为提取出来，形成可复用的模板。

       * 属性在程序里体现为字段，行为在程序里体现为方法，提取出来的模板就是结构体。

       * 抽象贯穿整个面向对象编程过程，不先垫上这一层，后面只会记住写法，记不住思路。

   * **抽取共有的属性**

       * 不管哪个银行的账号，都要先抽象出它有哪些共有属性。

       * 第一是账号，没有账号银行卡就不存在。

       * 第二是密码，空密码也是密码，这个属性客观存在。

       * 第三是余额，零就是余额，欠钱时负一万也就是余额。

   * **抽取共有的行为**

       * 第一是存款，没有哪张卡不能存款。

       * 第二是取款，能存不能取只是取的人不是你，可能是银行或别的机构。

       * 第三是查询余额，不能查询这套系统跑不起来。

   * **把抽象变成物理模板**

       * 第一步定名字，银行账号的结构体叫 `Account`。

       * 第二步把字段落进去，属性决定字段名和字段类型。

       * 第三步把方法绑上去，因为方法要绑定到类型上，接收者写成指针类型。

## Account 存取查实现

   * **字段定义**

```go
type Account struct {
    AccountNo string
    Pwd       string
    Balance   float64
}
```

   * **Deposit：先校验密码，再校验金额**

```go
func (account *Account) Deposit(money float64, pwd string) {
    if pwd != account.Pwd {
        fmt.Println("你输入的密码不正确")
        return
    }
    if money <= 0 {
        fmt.Println("你输入的金额不正确")
        return
    }
    account.Balance += money
    fmt.Println("存款成功")
}
```

       * 存款也要密码，因为打开 ATM 机存钱之前同样要输密码。

       * 存款不返回值，直接在里面打印一条存款信息。

   * **WithDraw：多一条不能超过余额**

```go
func (account *Account) WithDraw(money float64, pwd string) {
    if pwd != account.Pwd {
        fmt.Println("你输入的密码不正确")
        return
    }
    if money <= 0 || money > account.Balance {
        fmt.Println("你输入的金额不正确")
        return
    }
    account.Balance -= money
    fmt.Println("取款成功")
}
```

       * 取款金额等于余额是允许的，大于余额不行，小于等于零也不行。

   * **Query：只要一个密码**

```go
func (account *Account) Query(pwd string) {
    if pwd != account.Pwd {
        fmt.Println("你输入的密码不正确")
        return
    }
    fmt.Printf("你的账号为 %v，余额为 %v\n", account.AccountNo, account.Balance)
}
```

       * 密码不对就 return，否则把账号和余额一起打出来。

   * **串起一次完整流程**

       * 结构体首字母大写，外部不需要工厂模式，直接创建就能用。

       * 初始余额 100，存 200 变 300，取 150 剩 150。

```text
你的账号为 111111，余额为 100
存款成功
你的账号为 111111，余额为 300
取款成功
你的账号为 111111，余额为 150
```

       * > **易错点**：调用名和函数名不一致会报 `undefined: save money`；密码少打几位同样会走进「输入的密码不正确」分支，这正是校验该有的行为。

## 封装

   * **封装（Encapsulation）**

       * > **定义**：把抽象出来的字段和对字段的操作封装在一起，数据被保护在内部，其他包只能通过被授权的方法操作字段。

       * 比方是对待电视机：调音量只要按遥控器按钮，内部结构不需要用户管理。

       * 好处一是隐藏实现细节，调用者不关心你怎么实现，只要求结果。

       * 好处二是对数据做校验，只有合理才操作，不合理直接拒绝。

       * `Account` 的取款就是典型：没有这个方法，别人可以直接把余额减掉，余额只有一块却取走一万也会通过。

   * **Go 里实现封装的两种方式**

       * 把结构体、字段的首字母改成小写，别的包就不能访问，本包仍然可以。

       * 通过方法和包来实现，必须通过被授权的方法才能操作属性。

   * **四步封装法**

       * 第一步把结构体、字段首字母小写。Go 没有 `private`，**本包依然可以访问**，只是别的包不行。

       * 第二步给结构体所在的包提供一个首字母大写的工厂模式函数，类似构造函数。

       * 第三步提供一个首字母大写的 `Set` 方法，可以在里面加业务逻辑。

       * 第四步提供一个首字母大写的 `Get` 方法，把需要返回的字段返回出去。

```go
func (p *person) SetAge(age int) {
    if age > 0 && age < 150 {
        p.age = age
    } else {
        fmt.Println("年龄范围不正确")
    }
}

func (p *person) GetAge() int {
    return p.age
}
```

       * 必须通过被授权的方法才能操作私有字段。

   * **Go 为什么不强调封装**

       * Go 的面向对象做了大量简化，它认为保证代码准确是程序员自己的责任，没有必要强制封装。

       * Java 里字段一般全部私有，每个属性配一对 Getter/Setter，Go 不要求这么做。

       * 适当使用 Set、Get 不被反对，因为封装本来就是靠这种方式体现的，但不被特别强调。

       * > **提示**：不要总用 Java 的语法特征看待 Go，它连构造函数、`extends`、方法重载都没有。

## 封装案例 person

   * **model 包：小写结构体与工厂方法**

```go
package model

type person struct {
    Name   string
    age    int
    salary float64
}

func NewPerson(name string) *person {
    return &person{
        Name: name,
    }
}
```

       * 结构体名故意写成小写，`Name` 公开，`age` 和 `salary` 不可导出，其他包不能直接访问。

       * 工厂函数只需要接收名字，因为只有 `Name` 是对外公开的。

   * **两组 Set/Get 的取值范围**

```go
func (p *person) SetAge(age int) {
    if age > 0 && age < 150 {
        p.age = age
    } else {
        fmt.Println("年龄范围不正确")
    }
}

func (p *person) GetAge() int {
    return p.age
}

func (p *person) SetSalary(sal float64) {
    if sal >= 3000 && sal <= 30000 {
        p.salary = sal
    } else {
        fmt.Println("薪水范围不正确..")
    }
}

func (p *person) GetSalary() float64 {
    return p.salary
}
```

       * 年龄必须大于 0 且小于 150，合理才放进去，不合理保留原值并提示。

       * 薪水在 3000 到 30000 之间才算合理，低于这个没人来工作，高了也不合理。

   * **main 包：只能通过方法碰私有字段**

```go
func main() {
    p := model.NewPerson("smith")
    p.SetAge(18)
    p.SetSalary(5000)

    fmt.Println(p)
    fmt.Println(p.Name, " age =", p.GetAge(), " sal =", p.GetSalary())
}
```

       * 直接写 `p.age = 18` 会报 `cannot refer to`，不可导出的字段不允许引用。

       * `p.Name` 可以直接操作，因为首字母大写；年龄和薪水必须用 `GetAge`、`GetSalary` 取。

       * 输出是 `&{smith 18 5000}` 和 `smith  age = 18  sal = 5000`。

       * 工程上要建包而不是建文件，只有分成两个包才演示得出封装效果。

       * > **易错点**：字段和方法分散在两个文件里，`model` 包用了 `fmt.Println` 却忘了在 `person.go` 里 import `fmt`，会报 `undefined: fmt`。

## 封装练习 account 与三关校验

   * **构造函数的字段约束**

       * | 字段 | 约束 |
         | --- | :--- |
         | 账号 | 长度必须在 6 到 10 之间 |
         | 余额 | 必须大于 20 |
         | 密码 | 必须为 6 位 |

   * **把三关写进工厂函数**

```go
package model

import "fmt"

type account struct {
    accountNo string
    pwd       string
    balance   float64
}

func NewAccount(accountNo string, pwd string, balance float64) *account {
    if len(accountNo) < 6 || len(accountNo) > 10 {
        fmt.Println("账号长度不对")
        return nil
    }

    if len(pwd) != 6 {
        fmt.Println("密码长度不对")
        return nil
    }

    if balance < 20 {
        fmt.Println("余额数目不对")
        return nil
    }

    return &account{
        accountNo: accountNo,
        pwd:       pwd,
        balance:   balance,
    }
}
```

       * 三关依次判断，任何一关不过就提示一句并返回 `nil`。

       * > **结论**：构造函数返回 `nil` 就把「创建失败」交回给调用方，这是 Go 里很常见的返回约定——成功给值，失败给零值。

   * **主函数先判 nil**

```go
func main() {
    acc := model.NewAccount("建设银行11111", "123456", 40)

    if acc != nil {
        fmt.Println("创建成功", acc)
    } else {
        fmt.Println("创建失败")
    }
}
```

       * 正常情况输出 `创建成功 &{建设银行11111 123456 40}`。

       * 账号改成 4 位会提示「账号长度不对」再「创建失败」；密码改成 000 会提示「密码长度不对」。

       * > **易错点**：报「main.go 里有两个包」这种莫名其妙的问题，九成是 import 路径里的包名拼错了，先去查路径。

   * **还要自己补上的部分**

       * `Set` 方法要带上同一条约束：改账号校验 6 到 10 位，改余额校验大于 20，改密码必须也是 6 位。

       * `Get` 方法把字段值取出来，并在主函数里逐个测试。

## 继承的必要性

   * **冗余是怎么来的**

       * 学生考试系统里，小学生建结构体 `Pupil`，三个字段 `Name`、`Age`、`Score`。

       * 三个方法：`ShowInfo` 显示成绩、`SetScore` 设置分数、`testing` 显示正在考试。

       * 大学生来了，粘贴一份 `Graduate`，三个字段一模一样，`ShowInfo` 和 `SetScore` 也完全一样，只有 `testing` 的输出不同。

       * 为了这一个方法不一样，却写了两份几乎相同的代码；再加高中生还要再粘一份。

       * 要给 `Pupil` 和 `Graduate` 都加「会做算术题」，同样要写两份。

       * > **结论**：没有继承就极有可能出现代码冗余，代码重复导致复用性不强，既不利于维护也不利于扩展。

   * **继承的原理**

       * 把 `Pupil` 和 `Graduate` 里共有的字段和方法提取成一个 `Student`，再让两者嵌入它。

       * 特有的字段和方法可以保留，也可以增加。

```text
     ┌──────────────────────────────┐
     │  Student（抽出来的共有部分） │
     │  ┌──────────┐ ┌───────────┐  │
     │  │ Name     │ │  Age      │  │
     │  └──────────┘ └───────────┘  │
     │  ┌──────────┐ ┌───────────┐  │
     │  │ Score    │ │ ShowInfo()│  │
     │  └──────────┘ └───────────┘  │
     │  ┌──────────────┐ ┌────────┐│
     │  │ SetScore()   │ │testing ││
     │  └──────────────┘ └────────┘│
     └──────────────────────────────┘
          ▲                        ▲
          │ 嵌入 Student          │ 嵌入 Student
          │                        │
 ┌────────┴─────────┐     ┌────────┴─────────┐
 │  Pupil           │     │  Graduate        │
 │  testing() 独有  │     │  testing() 独有  │
 └──────────────────┘     └──────────────────┘
   小学生正在考试中…          大学生正在考试中…
```

   * **Go 里的继承语法**

       * > **结论**：在 Go 里实现继承，就是在结构体里嵌入一个匿名结构体名。

       * Go 不靠 `extends`，而是把被继承结构体的名字直接放进结构体里。

       * Go 一般不把被嵌入的叫父类、把嵌入方叫子类，这是一个很松散的关系。

```go
type Goods struct {
    Name  string
    Price float64
}

type Book struct {
    Goods
    // Book 自己特有的字段可以照常写在这里
}
```

       * 嵌入后 `Book` 就直接拥有 `Goods` 的 `Name` 和 `Price`，以及绑在 `Goods` 上的方法。

## 继承的写法与调用

   * **抽出 Student 并嵌入**

```go
type Student struct {
    Name  string
    Age   int
    Score int
}

func (stu *Student) ShowInfo() {
    fmt.Printf("学生名=%v 年龄=%v 成绩=%v\n", stu.Name, stu.Age, stu.Score)
}

func (stu *Student) SetScore(score int) {
    stu.Score = score
}

type Pupil struct {
    Student
}

func (p *Pupil) testing() {
    fmt.Println("小学生正在考试中...")
}

type Graduate struct {
    Student
}

func (p *Graduate) testing() {
    fmt.Println("大学生正在考试中...")
}
```

       * 匿名结构体就是没有变量名的结构体，通常写法是 `stu Student`，这里不写名字直接嵌进去。

       * 没嵌入 `Student` 的话，`Pupil` 和 `Graduate` 就只剩下自己那一个方法。

   * **最直白的访问写法**

```go
pupil := &Pupil{}
pupil.Student.Name = "tom"
pupil.Student.Age = 8
pupil.testing()
pupil.Student.SetScore(70)
pupil.Student.ShowInfo()
```

       * 先写外层结构体名，点到匿名结构体，再取里面的字段，层级关系很清晰。

       * `testing` 是自己的方法，直接 `pupil.testing()` 调用。

       * 这种写法比传统的 `extends` 松散，但保留了点点点的层级，不容易混淆。

   * **继承带来的两点便利**

       * 代码的复用性提高了。

       * 代码的扩展性和维护性提高了，加一个共同方法只需在 `Student` 上绑一次。

```go
func (stu *Student) GetSum(n1, n2 int) int {
    return n1 + n2
}
```

       * `pupil.Student.GetSum(1, 2)` 得 3，`graduate.Student.GetSum(10, 20)` 得 30。

       * > **易错点**：方法名写成小写却按大写调用编译器不认，Go 区分大小写，方法名首字母大写才是导出的，跨结构体调用要和定义保持一致。

## 嵌入后的三个访问细节

   * **小写字段和方法照样能用**

       * 结构体可以使用嵌套匿名结构体的所有字段和方法，不管首字母是大写还是小写。

```go
type A struct {
    Name string
    age  int
}

func (a *A) SayOk() { fmt.Println("A SayOk", a.Name) }
func (a *A) hello() { fmt.Println("A hello", a.Name) }

type B struct {
    A
}

func main() {
    b := B{}
    b.A.Name = "tom"
    b.A.age = 19
    b.A.SayOk()
    b.A.hello()
}
```

       * Java 里私有的属性在子类里用不了，Go 里不存在这个问题，一旦匿名结构体写进去就能用。

   * **访问可以简化，编译器是这样找的**

       * `b.A.Name` 可以直接简写成 `b.Name`。

       * 先到 `b` 对应的类型里找，有就用自己的；没有就去看嵌入的匿名结构体；还没有就继续往上一层找。

       * 找了一圈都没有就报错，提示该函数或字段没有定义。

```text
b.Name  →  B 自己有吗？──有──► 用 B 的
              │没有
              ▼
        嵌入的 A 有吗？──有──► 用 A 的
              │没有
              ▼
        A 里嵌入的 C 有吗？──有──► 用 C 的
              │没有
              ▼
         报错：未定义
```

   * **同名撞车走就近原则**

       * 结构体和匿名结构体有相同字段或方法时，编译器采用就近访问原则。

       * `b.Name` 找到的是 `B` 自己的 `Name`，不会给 `A` 的 `Name` 赋值。

       * `b.Age` 因为 `B` 本身没有，会找到 `A` 里的 `Age`。

       * `b.SayOk()` 调的是 `B` 自己的方法，输出 `B sayOk jacky`。

       * `b.Hello()` 调的是 `A` 的方法，方法体里的 `a.Name` 访问的是 `A` 实例的 `Name`，没赋值所以输出空串。

       * 要给 `A` 的字段赋值必须带上匿名结构体名，`b.Name = "jacky"` 给 `B` 的字段，`b.A.Name = "scott"` 才给 `A` 的字段。

       * 要调用 `A` 的方法同理，写 `b.A.SayOk()`，输出 `A sayOk scott`。

## 多个匿名结构体与组合

   * **嵌两个匿名结构体，同名必须点名**

       * 两个匿名结构体有相同字段或方法，同时结构体本身没有同名成员，访问时必须指定匿名结构体名，否则编译报错。

```go
type A struct {
    Name string
    Age  int
}

type B struct {
    Name  string
    Score float64
}

type C struct {
    A
    B
}

func main() {
    var c C
    c.Name = "tom"       // 错误：ambiguous selector c.Name
    c.A.Name = "tom"     // 正确
    fmt.Println(c)
}
```

       * 查找时 `C` 里没有 `Name`，转向 `A` 和 `B`，两边都有就不知道该给谁，编译报 `ambiguous selector`。

       * 如果 `C` 自己有一个 `Name` 就不会报错，因为先在 `C` 里就找到了，`A` 和 `B` 不再参与查找。

       * 方法同理，两个匿名结构体都有同名方法时，除非结构体本身有同名方法，否则必须点名区分。

   * **有名结构体就是组合**

       * > **定义**：结构体里嵌套一个有名结构体这种模式叫组合，组合是继承的一种特殊关系，访问时必须带上结构体名字。

```go
type D struct {
    a A
}

func main() {
    var d D
    d.Name = "jack"    // 错误：type D has no field or method Name
    d.a.Name = "jack"  // 正确
    fmt.Println(d)
}
```

       * 有名结构体时编译器只在 `D` 里找，**不会往上找**，所以少了名字就报没有这个字段或方法。

       * 即使 `D` 自己有 `Name` 也不影响这条规则，只是那样写本来就不报错。

       * 组合关系很灵活，甚至可以组合多个 `A`。

## 创建时指定匿名字段的值

   * **按顺序写**

```go
type Goods struct {
    Name  string
    Price float64
}

type Brand struct {
    Name    string
    Address string
}

type TV struct {
    Goods
    Brand
}

tv := TV{
    Goods{Name: "电视机001", Price: 5000.99},
    Brand{Name: "海尔", Address: "山东"},
}
```

       * 这种写法必须按结构体定义时的字段顺序写，定义时名字在第一位这里就得先写名字。

   * **前面写字段名**

```go
tv2 := TV{
    Goods: Goods{
        Name:  "电视机002",
        Price: 6000.99,
    },
    Brand: Brand{
        Name:    "夏普",
        Address: "北京",
    },
}
```

       * 这种写法不依赖字段顺序，把 `Price` 写到名字前面也可以。

       * 每一行末尾都要有逗号，不要漏。

   * **嵌入指针类型**

```go
tv3 := TV{
    &Goods{Name: "电视机003", Price: 7000.99},
    &Brand{Name: "创维", Address: "河南"},
}

fmt.Println((*tv3.Goods).Name, (*tv3.Goods).Price)
fmt.Println((*tv3.Brand).Name, (*tv3.Brand).Address)
```

       * 嵌套匿名结构体的指针类型，这样直接就是地址，效率更高。

       * 直接打印出的是两个地址，取值要先 `(*)` 取出来再用。

       * 指针也可以配合字段名写，`Goods: &Goods{...}` 这样同样能用。

       * > **易错点**：嵌入指针有两处要小心，一是初始化时指针要加 `&`，二是取值时别忘了写 `(*)`；另外类型名一旦写错（比如结构体定义成 `TV2` 却写成 `TV`）编译器立刻报错。

## 匿名字段是基本数据类型

   * **int 也能匿名嵌入**

```go
type Monster struct {
    Name string
    Age  int
}

type E struct {
    Monster
    int
}

func main() {
    var e E
    e.Name = "狐狸精"
    e.Age = 300
    e.int = 20
    fmt.Println("e=", e)
}
```

       * 结构体里可以嵌入基本数据类型，相当于结构体里有一个匿名字段，类型是 `int`。

       * `Monster` 的字段可以简写，全写是 `e.Monster.Name`，因为只有一个 `Name` 所以能省。

   * **匿名字段最多只能有一个**

       * 一个结构体里不能有第二个 `int` 类型的匿名字段，因为无法区分。

       * 需要多个 `int` 字段就必须命名，写成 `n int`，用的时候 `e.n = 40`。

## 多重继承

   * **定义与写法**

       * > **定义**：结构体嵌套了多个匿名结构体，就可以直接访问这些结构体的字段和方法，在 Go 里实现多重继承就是嵌入多个匿名结构体。

       * `TV` 同时嵌入 `Goods` 和 `Brand`，既能用 `Goods` 的属性方法，也能用 `Brand` 的属性方法。

       * 嵌入的匿名结构体有相同字段名或方法名时，访问要通过匿名结构体类型区分，比如 `tv.Goods.Name`。

       * `Price` 只有 `Goods` 有，`Brand` 里没有，所以可以直接写 `tv.Price`。

   * **使用建议**

       * 多重继承很容易把继承关系搞复杂，为了保证代码简洁建议尽量不要使用。

       * 很多编程语言已经把多重继承拿掉了，Go 保留下来是因为设计者本身来自 C 家族，但文档里也说了尽量不要用。
