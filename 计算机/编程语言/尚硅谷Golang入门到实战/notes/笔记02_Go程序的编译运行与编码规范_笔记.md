# Go 程序的编译运行与编码规范

---

## 项目目录与第一个程序

* **源文件后缀**
    * Go 源代码以 `.go` 扩展名结尾
    * 换成别的后缀，编辑器认为这不是 Go 程序就不高亮，`go build test.abc` 直接提示 `unknown`，无法编译

* **目录结构规范**

    ```text
    D:\goproject
    └── src                        ← 源代码目录
        └── gocode
            ├── project01          ← 第一个项目
            │   ├── main           ← 一个文件夹就是一个包
            │   │   └── hello.go
            │   └── 其他包...
            └── project02          ← 第二个项目
                └── main
    ```

    * 从下往上看：`project01` 是项目，`main` 是这个项目里的一个包，`hello.go` 是这个包里的源文件
    * 一个文件夹对应一个包，这是 Go 的管理机制
    * 不这么建也能跑、程序一样执行，但既然有规范，按规范来更正规
    * 项目名不一定叫 `project01`，也可能是 OA、CRM 或一个众筹项目
    * 讲课按章节建目录：每一章节建一个目录，章节里面为每个案例再建一个子文件夹

* **第一个程序的结构**

    ```go
    package main

    import (
    	"fmt"
    )

    func main() {
    	fmt.Println("hello, world")
    }
    ```

    | 代码 | 含义 |
    | :--- | :--- |
    | `package main` | 说明 `hello.go` 这个文件**所在的包**是 `main` |
    | `import "fmt"` | 引入一个名叫 `fmt` 的包，目的是能用它里面的函数 |
    | `func main()` | `func` 是关键字，表示后面是一个函数；`main` 是主函数名，也就是**程序的入口** |
    | `fmt.Println("hello, world")` | 调用 `fmt` 包里的 `Println` 函数，输出这句话 |

    * 整个程序的结构：包名 → 引入包 → `func` 关键字 → 函数名 → 调用包里的一个函数输出内容
    * `fmt` 就是 format 的意思
    * > **易错点**：出不来效果时按顺序对照检查三处——文件后缀是不是 `.go`、`package main` 是不是写了、`fmt` 是不是 import 了，这三处漏掉哪一个都会直接编译报错

## 编译与运行

* **编译**
    * > **定义**：把源代码编译成机器可识别的二进制代码，这就叫编译

* **先编译，再运行**
    * `go build hello.go`，代码有错会提示错误；没问题就多出一个 `hello.exe`，这就是编译得到的二进制可执行文件
    * 然后直接执行 `hello.exe`，回车就输出了内容

* **直接 `go run`**
    * `go run hello.go` 直接执行源码，类似执行一个脚本文件，输出是一样的。
    * 但这种方式明显比直接执行慢：直接跑 `hello.exe` 大概一秒就出来，`go run` 要四秒才输出
    * 原因是源码计算机不能直接执行，`go run` 在底层同样要把源码编译成二进制码，只是这个过程被隐藏在指令里面了。

    ```text
    方式一：先编译，再运行  ── 快
       hello.go ──go build──> hello.exe (Windows) / hello (Linux、Mac)
                              │
                              └── 直接执行 ──> 输出

    方式二：go run        ── 慢
       hello.go ──go run──> [ 编译 ] + [ 运行 ] ──> 输出
                            ^^^^^^^^^^^^^^^^^^^^^^^
                            编译过程被藏在指令里面了
    ```

    * 两条路的输入都是源码，区别在于编译这一步是显式做还是隐式做，所以只从"运行"角度看直接执行可执行文件肯定快
    * 真正的工作和生产环境肯定是先编译再执行，有些老师为了讲课方便才用 `go run`

* **三种关键差别**

    | 对比项 | 先编译再运行 | `go run` |
    | :--- | :--- | :--- |
    | 目标机器要求 | 拷到没装 Go SDK 的机器上照样能跑 | 那台机器上必须也有 Go 开发环境 |
    | 速度 | 快 | 明显更慢 |
    | 体积变化 | Go 源代码只有 1KB，编译过后会变成 1.8 兆（1895 KB） | — |

    * 体积变大是因为编译时会把程序执行所需要的相关文件和资源、依赖的库文件一起打包链接进去

* **可执行文件的后缀**
    * Windows 下生成 `hello.exe`
    * Linux 或 Mac 下生成的是一个二进制码文件，同样可执行，但没有 `.exe` 后缀

    ```text
       hello.go  ──go build──▶  hello.exe     Windows：带 .exe 后缀
       hello.go  ──go build──▶  hello         Linux / Mac：没有 .exe 后缀，
                                                  但同样是二进制码文件，同样可执行
    ```

* **Linux 与 Mac 下运行要加 `./`**

    ```bash
    ./hello
    ```

    * Linux 下开发 Go 和 Windows 目录结构一模一样、编译指令一模一样，就一个地方有区别：运行
    * 不能直接敲 `hello`，必须加一个点，因为点斜杠代表当前目录，告诉系统"从当前这个目录下面去找一个 hello 可执行文件"

## 编译反馈与错误定位

* **指定可执行文件名**
    * `go build -o myhello.exe hello.go` 可以指定生成的可执行文件名，不指定时默认以你编译的那个源文件的名字命名
    * 生成 `myhello.exe` 之后原来那个名字没了，而且它照样能执行
    * > **易错点**：`-o` 后面指定的名字后缀必须是 `.exe`，如果后缀不是 `.exe`，后面是没法执行的。

* **编译时的反馈**
    * 程序没有错误，编译的时候就不会有任何提示，静悄悄的
    * 有错误会在错误的那一行报错，这有助于程序员排错
    * 错误信息主要就两部分：行位置和原因

    ```text
    hello.go:7:8: undefined: fmt.Printnl
    └─ 行位置 ─┘  └─ 原因 ─┘
    ```

    * 报错行号加上那个未定义的名字，程序员看到就能快速把错误调试出来
    * 编译器不会明确告诉你是数字 `1` 和小写字母 `l` 写错了，它没那么智能。
    * > **提示**：一定要学会看错误信息，而且不要怕它，看一眼错误信息这个问题很快就解决了。

## Go 程序开发的七点注意

* **必须以 `.go` 后缀结尾**
    * 这是它的一个硬要求，换后缀既不高亮也编译不过去

* **执行入口是 `main` 函数**
    * 程序最终执行时是从这个 `main` 函数往里面执行的
    * 尽量叫"函数"不要叫"方法"，Go 里方法和函数很像但也有区别

* **严格区分大小写**
    * `println` 的 `n` 不能大写，写成大写立刻报 `undefined`
    * 有些语言不区分大小写，Go 区分

* **语句后面不需要加分号**
    * 因为 Go 语言会在每行后自动加分号，编译器帮你加
    * 加了也能用、保存编译 `go run` 都跑得起来，但显得不专业，有点画蛇添足

* **一行一条语句**
    * Go 编译器是一行一行编译的，把多条语句写在同一行会报语法错误

* **声明了必须用**
    * 定义的变量或 `import` 的包如果没有用到，代码不能编译通过

    ```text
    imported and not used: "fmt"
    ```

    * Java 里 import 了不用最多警告一下，Go 直接让你编译不通过，有几个包没用到就整个跑不过去

    ```go
    var num = 10   // 声明了却没用
    // 报错：num declared and not used
    ```

    * 设计理由是：代码里经常留下张三定义、李四不敢动其实早就不要了的变量和包，它们在编译和运行时会参与，对代码性能造成影响
    * 这是 Thompson 自己在设计时就定下的规则，既体现简洁性也强制风格统一

* **大括号要成对出现，缺一而不可**
    * 所有编程语言都要求，不是 Go 独有的特点，但对初学者容易忘

## 转义字符

* **转义字符（escape char）**
    * 第一个斜杠表示转义：没有斜杠 `t` 就是一个字母 t，有了斜杠 `\t` 就变成了制表符

    | 转义字符 | 含义 | 用途 |
    | :--- | :--- | :--- |
    | `\t` | 制表符 | 排版、对齐 |
    | `\n` | 换行符 | 输出完换到下一行 |
    | `\\` | 反斜杠 | 输出一个真实的反斜杠 |
    | `\"` | 双引号 | 在字符串里输出双引号 |
    | `\r` | 回车 | 回到当前行行首覆盖输出 |

* **`\t` 制表符**

    ```go
    fmt.Println("tom\tjack")
    ```

    * 输出 tom、若干空格、jack；这里没有斜杠就会直接输出一个字母 t
    * `\t` 中的 t 代表 table

* **`\n` 换行符**

    ```go
    fmt.Println("hello\nworld")
    ```

    * 输出 hello 之后换行，再输出 world

* **`\\` 反斜杠**

    ```go
    fmt.Println("D:\\GoWorks\\src\\...")
    ```

    * 直接输出单个斜杠编译器会报错，提示 character escape 有问题，因为它不知道单个斜杠是什么意思
    * 第一个斜杠用来告诉编译器，后面的斜杠当作普通字符输出

* **`\"` 双引号**

    ```go
    fmt.Println("tom说:\"I love you\"")
    ```

    * 希望输出的字符串里带双引号时直接写双引号会导致语法解析错误，使用转义符 `\"` 后运行结果是 `tom说:"I love you"`

* **`\r` 回车**

    ```go
    fmt.Println("天龙八部雪山飞狐\r张飞")
    ```

    * 运行结果是 `张飞八部雪山飞狐`
    * 回车代表先输出前面的内容，回车之后不换行，而是从当前行的最前面顶头开始输出后面的"张飞"，覆盖掉以前的内容
    * `"张飞"`刚好也是两个汉字，就替换掉了"天龙"；写成"张飞厉害"会替换"天龙八部"四个字，再长一点就替换不动了，剩下多出来的字符照样留在后面

* **一个语句输出表格**

    ```go
    fmt.Println("姓名\t年龄\t籍贯\t住址\nJohn\t20\t河北\t北京")
    ```

    * 表头和数据之间的列对齐靠制表符 `\t`，两行之间换行靠 `\n`
    * 题目要求一个 `fmt.Println` 语句，整个"表头 + 换行 + 数据"必须写进同一个字符串字面量里，不能用两个语句分两行输出

* **同一个包里不能有两个 `main` 函数**
    * 两个文件放在同一个文件夹下就属于同一个包，同一个包里有两个 `main` 函数会报 `main redeclared in this block`
    * Go 要求函数是 `main` 函数就必须在 `main` 包里面，所以没有办法靠换包名来解决，只能重新建一个文件夹也就是重新建一个包
    * 把文件挪到新包后如果还提示以前的错误，是因为编译器有点傻，稍微改动一下文件再保存就好了。

## 注释与代码风格

* **注释（comment）**
    * 目的是提高代码的可读性
    * 代码没有注释，一年后、两年后回头看几乎不知道自己当初写的是什么
    * Go 语言 `src` 目录里高手的代码全是注释，源码里 `fmt` 包的一个文件就写着说明这个函数是用来输出格式化输出的注释
    * > **结论**：多写注释这既是技术习惯，也是职业习惯——参加工作以后代码里一行注释都没有，项目经理会觉得你不负责任、没有良好编程习惯

* **行注释**

    ```go
    // 这是注释内容
    ```

    * 基本格式是两个斜杠然后是注释文字
    * 快捷键 `Ctrl + /` 一键注释，再按一次取消注释，想一次性注释多行时特别好用

* **块注释**

    ```go
    /*
    fmt.Println("hello")
    fmt.Println("world")
    */
    ```

    * 语法是 `/*` 开头、`*/` 结尾，中间是注释内容

* **注释的两条使用细节**
    * 一旦被注释了，被注释的文字就不会被 Go 编译器编译执行
    * 块注释里面不允许再嵌套块注释
    * > **易错点** ⚠️：编译器是从第一个 `*/` 就截断的，中间那个 `/*` 已经被当成注释内容吞掉了，下面那个 `*/` 找不到配对的 `/*`，程序立刻报错，下面一堆代码全变成错误

* **尽量用行注释**
    * Go 官方推荐尽量使用行注释来注释整个方法和语句
    * 把 Go 的源代码往下拉会发现注释几乎全是行注释，很少看到块注释

* **缩进和空白**
    * 选中一段文本按 `Tab` 整体向右缩进，按 `Shift + Tab` 整体向左移动

    ```bash
    gofmt main.go
    gofmt -w main.go
    ```

    * `gofmt main.go` 只是把格式化后的内容输出出来，终端里看到的对齐了，但文件本身没有变化
    * `gofmt -w main.go` 才是把格式化后的内容重新写入文件，重新打开该文件看到的就是新的、格式化过的样子
    * > **易错点** ⚠️：这两个指令一定要分清，`-w` 是把格式化结果写回文件的关键

* **运算符两边各加一个空格**

    ```go
    var number = 2 + 4 * 5
    ```

    * Go 的源代码几乎也是这样写的，输个加号它的运算符也是这么带空格的。

* **大括号必须留在函数名那一行**

    ```go
    func main() {

    }
    ```

    * Java、C、PHP 等语言都允许把大括号另起一行，但 Go 里不允许，换成换行的写法会立刻报错，说你没有方法体
    * > **定义**：Go 语言的设计者有一个思想——一个问题尽量只有一个解决方法，有些人喜欢这么写有些人喜欢那么写，搞得好像有两种风格没有标准，Go 不接受这件事，所以干脆强制只能写一种，风格反而统一了。

* **一行不超过 80 个字符**
    * 超了就要用换行来展示，尽量保持代码的优雅性
    * 方法是打一个逗号然后换一行，再接着打一个逗号再换一行，到最后一段用分号收尾再换行

    ```go
    fmt.Println("一句很长的话",   // 逗号，然后换行
        "再接一句",              // 继续逗号，继续换行
        "最后一句")              // 到这里收尾
    ```

    * 跑一下输出还是一整坨，完全没有影响
    * > **提示**：如果你是想**输出的时候**换行，那还得靠转义字符 `\n`，源码里的换行用逗号处理、输出结果里的换行用 `\n` 处理，这两个换行不是一回事

## 官方手册与 API 文档

* **官方网站与 Tour**
    * 官方网站是 golang.org，这个站点经常会被屏蔽掉，一般来讲得先翻一下墙
    * 首页有吉祥物和一段示例代码，点一下 **Run** 它就运行给你看，代码写得乱不要紧，点一下 **Format** 就格式化成漂亮的样子
    * 点进 **Tour** 进入官方手册，一上来就是一句 "hello world"，可以格式化、可以运行
    * > **提示**：Run 的原理是把文本框里的内容发给后台服务器，后台服务器把这段代码执行一遍，再通过 HTTP 协议把结果返回给页面渲染出来，所以你看到的每一次 Run 都是一次真实的编译和执行

* **Tour 手册的定位**
    * 进 Tour 后第一步点"下一步"选简体中文翻译手册，左边有基础、包、变量、函数、方法、接口等一大串目录，相当于整本手册的目录
    * 但它写得非常简单、非常粗犷
    * 适合本来就有编程经验的人，通过这份手册上手会相当快；零基础拿这份手册学起来就吃力

* **Packages 与 API**
    * 官网还有一个入口叫 **Packages**，点进去全是 API，因为 Go 语言是以包的形式来管理函数和文件的。
    * 在搜索框打 `fmt` 直接定位，或者顺着字母顺序找 `f` 打头的那一栏；点进 `fmt` 之后点 **Index**，这里就是这个包里所有的方法
    * > **定义**：API 是 Application Programming Interface 的缩写，叫应用程序编程接口，说得直接一点，它就是 Go 各个包下面的各个函数
    * 文档是用来告诉开发者怎么使用这些标准库的：标准库里面包含哪些方法、该怎么调

* **文档读不懂的三招**
    * 第一招百度翻译，把英文段落复制过去点翻译，虽然不一定百分之百准确，但总比没有好
    * 第二招直接搜，比如打 "fmt Println 的用法"，会告诉你 Golang 里 `Println` 和 `Printf` 的区别
    * 第三招靠自己的脑子
    * > **结论**：查文档这件事不要怕麻烦，要灵活地使用各种工具

* **中文文档与离线文档**
    * 官网文档有两个门槛：要能上网，还要能翻墙
    * 国内有个 **studygolang** 提供中文版 Go 标准库 API 文档，只要能上网就行，不需要翻墙
    * 它会告诉你 `fmt` 包实现了格式化 I/O 函数，类似于 C 的 `printf` 和 `scanf`，这一句话下去学起来压力就小很多
    * 查 `Println` 会告诉你结果写入**标准输出**，并返回**写入的字节数**和遇到的任何错误
    * 连网都上不了可以用离线版 API 文档，有说明、有 index，点任何一个函数都能到位，唯一的缺点是它是英文版的。

* **直接读 Go 源码**
    * Go 语言的特点是各个包的源代码都是可以找到的
    * 安装的 Go SDK 里有个 `src` 目录，`src` 里面有一个文件夹就叫 `fmt`，一个包基本上对应一个文件夹
    * 包里有 `print.go`、`format.go`、`scan.go` 等一堆源文件，每个文件里就有一堆函数定义
    * 在源文件里按 `Ctrl + F` 搜函数名就能找到它的源代码：上面那一行是函数签名，下面函数体里调用的函数可以再往下追
    * 文件里会看到作者署名和年份，2009 年就写出来了

* **包、文件夹、源文件、函数的关系**

    ```text
      包（逻辑概念）        一一对应        文件夹
          fmt         ─────────────────►   src/fmt/
          bytes       ─────────────────►   src/bytes/
                                               │
                         一个包里有一堆源文件，  │  下面若还有文件夹，
                         说明这个包还有子包      │  就是子包
                                               │
                            ┌──────────────────┼──────────────────┐
                            ▼                  ▼                  ▼
                        print.go           format.go           scan.go
                            │
                            │  一个源文件里又有一堆函数
                            ▼
             Println / Printf / Fprintln / Sprintf ...
    ```

    * 一个包对应一堆源文件，不是一对一
    * 包里如果还有新的文件夹，说明这个包下面还有子包，这是允许的
    * 调用方式是**包名 + 函数名**：先 `import` 一个包，然后使用 `包名.函数名` 的形式

    ```go
    fmt.Println("hello")
    ```

    * > **易错点**：调用的时候不是以源文件来调的，而是以包名去调，虽然 `print.go` 里写了 `Println`，但你调用的时候不会写文件名的。
    * 前提是这个文件里第一句话必须是 `package fmt`，必须先在包里声明 `package` 才能用

## DOS 基础与目录操作

* **DOS**
    * > **定义**：DOS 全称叫 Disk Operating System，也就是磁盘操作系统。这是微软最早用的系统，早期比较流行；后来微软出了一个图形界面叫 Windows，Windows 又集成了 DOS

    ```text
            程序员（人）
                 │
                 │  敲入 md test200
                 ▼
       ┌────────────────────┐
       │   DOS 操作终端      │   ← cmd 打开的黑窗口
       └─────────┬──────────┘
                 │  指令
                 ▼
       ┌────────────────────┐
       │   DOS 操作系统      │   ← 真正的核心：解析 md
       └─────────┬──────────┘
                 │  操作
                 ▼
       ┌────────────────────┐
       │   Windows 目录结构  │   ← D 盘、E 盘、F 盘……
       └────────────────────┘
    ```

    * 在 `cmd` 里看到的黑乎乎的窗口并不是真正的 DOS 系统，它只是操作 DOS 的一个终端而已
    * 指令不是直接发给 Windows 目录结构，中间有一层 DOS 操作系统，它接到指令先解析——比如 `md` 代表什么意思——解析完再由它去真正操作目录结构
    * DOS 在这里扮演的是翻译者和执行者，人是操作者

* **目录与文件操作指令**

    | 指令 | 作用 |
    | :--- | :--- |
    | `dir` | 查看当前目录包含的目录以及文件有哪些内容 |
    | `cd /d f:` | 切换到其它盘符，大小写都无所谓 |
    | `md ok200` | 新建目录，md 是 make directory 的简写 |
    | `md ok300 ok400` | 一次创建多个目录，目录名用空格隔开 |
    | `rd ok100` | 删除空目录，rd 是 remove directory |
    | `rd /q /s ok200` | 不带询问地删除目录及其所有子目录 |
    | `rd /s ok300` | 带询问地删除，选 Y 删掉、选 N 不删 |
    | `echo hello > abc.txt` | 新建或追加内容到文件，文件不存在就创建、存在就追加 |
    | `copy abc.txt d:\test200` | 复制文件，保持原文件名 |
    | `copy abc.txt d:\test200\ok.txt` | 复制的同时重新指定文件名 |
    | `move abc.txt f:\` | 移动文件，相当于剪切，后面的文件名写也可以、不写就保持原名 |
    | `del abc2.txt` | 删除文件 |
    | `del *.txt` | 删除所有 `.txt` 后缀的文件 |
    | `cls` | 清屏 |
    | `exit` | 退出 DOS |

    * `rd` 只能删除空目录，删除非空目录会提示"目录不是空的"且没删掉
    * `rd /q /s` 里 `/q` 是 query，表示不用询问的安静模式，`/s` 是层级式地把这个目录以及所有子目录全部删掉
    * > **提示**：不带询问的删除比较危险，因为它没有问就直接删掉了，建议使用带询问的。
    * 文件名可以一个一个手敲，也可以用 `Tab` 键全部补全
    * `cls` 简称"苍老师"，记住这一句就记住了
    * 复制有两种方式：使用原来的文件名，或者重新指定名字，两种任选

* **相对路径与绝对路径**
    * > **定义**：绝对路径是从当前盘的盘符最上面开始定位，也就是从 D 盘、F 盘、C 盘这样的盘符开始一级一级找到需要的目录
    * > **定义**：相对路径是从当前这个位置开始定位，去寻找对应的目录

    ```text
       当前位置：d:\test100

       cd abc100                      相对路径 —— 从"当前位置"往下找一层
            └──▶ d:\test100\abc100

       cd d:\test100\abc100           绝对路径 —— 从 D 盘根开始逐级定位
            └──▶ d:\test100\abc100
    ```

    * 相对路径写成 `cd abc100`，是因为已经在 `test100` 而它下面正好有 `abc100`
    * 绝对路径从 D 盘开始一级一级地找，所以要写成 `cd d:\test100\abc100`
    * > **结论**：目录切换的指令掌握那些就够了，关键是相对路径和绝对路径要搞清楚

* **两个特殊写法**
    * `cd ..` 里的 `..` 就代表回到上一级目录
    * `cd \` 回到它的顶级目录，也就是根目录

## VS Code 的设置与快捷键

* **设置入口与两类设置**
    * 设置入口是文件 → 首选项 → 设置，打开后默认显示的是**默认的用户设置**
    * 设置面板按分类铺开：通用的"通用"设置；"编辑器"里有 82 个设置是最大的一块；往下还有源代码管理、工作台、窗口、文件、Zen 模式、文件资源管理器、搜索、JSON 设置、调试、扩展；语言相关的也有一大堆 Go 语言设置和标签相关配置，再往下是 Git、GitHub 的各种设置
    * 平时用得最多的绝大部分都在"编辑器"这一块

    ```text
    ┌───────────────────────────┬───────────────────────────┐
    │  默认的设置（只读）        │  用户设置（你自己改的）   │
    │  "Editor: Font Size  14"  │  ← 点"编辑"后落到这里    │
    │  灰色的，改不了            │  可以随便改               │
    └───────────────────────────┴───────────────────────────┘
                       ↓
            用户设置会「覆盖」默认设置
    ```

    * 字体大小以像素为单位控制字号，默认就是 14，这个 14 在左边是改不了的。
    * 改法：点它一下"编辑"，这一项会自动挪到右边的用户设置里，把 14 改成 18 保存就生效了。
    * 字体的粗细同样这么改；把右边已经改过的那条删掉再点编辑，会显示"文件设置已无法修改"，重新保存一下就能继续改

* **更新与扩展相关的开关**
    * 扩展的更新：希望后台自动接受 VS Code 的更新就改这里，不想自动更新可以关掉，选项是 `none`
    * 启用 Windows 后台更新：默认是启用的，觉得它老往后台跑可以改成 `false`
    * 扩展本身是否自动更新：默认是 `true`，可以改成 `false` 关掉
    * 扩展建议通知：说明是"如果设置为 `true`，将不再显示扩展建议通知"，默认给的是 `false`，所以第一次用会发现它老弹框提示装扩展

* **控制键入时是否自动显示建议**

    | 取值 | 含义 |
    | :--- | :--- |
    | `other` | 在字符串和注释外启用快速建议 |
    | `comments` | 在注释内启用快速建议 |
    | `strings` | 在字符串内启用快速建议 |

    * 默认值是 `other`，体验有点像以前用 Eclipse，敲一个点就给你提示相关的信息
    * > **易错点**：有些建议你在设置里打开了也不管用，因为你没装相应的扩展，这个配置要配合扩展同时使用才可以。

* **快捷键面板与自定义**
    * 快捷键在文件 → 首选项 → 键盘快捷方式，这边全是它的快捷方式而且可以直接搜索
    * 搜"删除"会列出删除、删除右侧字符、删除行，"删除当前行"对应的快捷键是 `Ctrl + Shift + K`
    * 要改的话点旁边那支**小铅笔**，弹出输入框里输入想用的组合键，按 `Enter` 键就生效
    * > **提示**：一般情况下如果没有特殊需求还是用默认值比较好，只有真的需要或者它的快捷键跟输入法、跟其他软件的快捷键相冲突了再去改

    | 快捷键 | 作用 |
    | :--- | :--- |
    | `Ctrl + Shift + K` | 删除当前行（可自定义） |
    | `Shift + Alt + ↑` / `Shift + Alt + ↓` | 向上／向下复制当前行 |
    | `Alt + /` | 补全代码（快速修复，可自定义） |
    | `Ctrl + /` | 添加注释／取消注释（按一次加，再按一次去） |
    | `Shift + Alt + F` | 格式化文件 |
    | `Shift + Alt + A` | 切换块注释 |
    | `F11` | 切换全屏 |

    * 补全代码在这里面叫"快速修复"，它的默认快捷键不是 `Alt + /` 而是 `Ctrl + Space`，因为 `Ctrl + Space` 刚好是输入法中英文切换的键，所以常被重新定义成 `Alt + /`

* **快捷键按下去没反应的两个原因**
    * 第一种是和输入法冲突。输入法在那一层的优先级更高，敲一个快捷键它先在输入法那边有变化，代码里面不会有变化
    * 第二种是 Go 插件没有装，有些快捷键需要装 Go 插件之后才会生效
    * Go 插件安装方式：在扩展面板里搜 `Go` 点进去，里面有详细信息和一个 `How to use this extension`，安装时会给出相应的步骤
    * > **注意**：有些扩展的安装是要走外网的，因为这些扩展都在国外，国内可能会把某些网关、网站屏蔽掉，连不上网就需要翻墙；不能翻墙就从网上找一些现成的包安装一下
