# 结构体的声明、内存分配与使用细节

## 面向对象的世界观

* **一个程序就是一个世界**
    * 现实世界有什么东西，编程里就有相应的体现：现实里有房子、树、有人、狗，编程里也会有很多对象。
    * > **定义**：Go 里的「结构体对象」就是「结构体类型的变量」，两种叫法一个含义。
    * 之所以既说「创建一个结构体变量」又说「创建一个结构体对象」，本质上都是一个变量，只是这个变量的类型不一样。
    * 编程时不必把程序显得很神秘；程序越复杂越像一个现实社会，做网游、游戏开发时会发现人物的行为和属性与现实非常相似。

* **Go 面向对象编程的五个特点**

    | 特点 | 结论 |
    | :--- | :--- |
    | 支持但纯度不高 | OOP 即面向对象编程；Java 没有全局变量、东西都在对象里，Go 有很多全局变量和全局函数 |
    | 没有 class | 由 `struct` 替代类的地位，与其他语言的类有同等地位 |
    | 简洁 | 拿掉了方法重载、构造函数、析构函数、`this` 指针；继承概念还在但没有 `extends` |
    | 仍有三大特性 | 继承、封装、多态都还在，只是实现方式不同，继承通过匿名字段实现 |
    | 优雅 | 本质是一门面向接口的语言，通过接口关联降低耦合性 |

    * > **易错点**：说「Golang 支持面向对象编程特性」是精准的，不要硬套 Java 那套纯度很高的面向对象说法。
    * 面向对象编程本质上是一种**思想**，不要过度拘泥于形式；因为 Go 跟传统面向对象变化太大，有些同学学起来觉得奇怪，但它确实有这些特性。
    * 有些程序员和书上更喜欢把面向对象编程叫做**面向接口编程**，因为接口是 Go 面向对象里最重要的特点，用得特别多而且非常巧妙，耦合度非常低。

## 结构体与结构体变量

* **一类事物与它的实例**
    * 猫有很多种类——波斯猫、花猫、中华田园猫；它们总会有相同的特征：名字、年龄、颜色，这些叫**字段**或**属性**。
    * 它们也总会有相同的行为——叫、吃东西、睡觉、做算术题，这些行为体现出来就是后面要讲的**方法**。
    * 把这些共同的特征和行为**提取出来**放到一个数据结构、一个数据类型里，这个数据类型就叫做**结构体**，例如 `Cat` 结构体。
    * 有了结构体，就可以通过这个数据类型创建多个变量，也就是多个实例（有些程序员直接叫对象）。

    ```text
          一类事物                 多个具体的个体
       提取共同特征与行为
       得到一种数据类型
      -------------------> Cat (struct) --------> cat1   cat2   cat3
                                                 (变量/实例/对象)
    ```

    * 类比 `int` 也是一种数据类型，它同样可以有很多变量（`a int`、`b int`），`Cat` 结构体是同一样的道理。
    * 这个思路可以拓展：这一类事物到底是什么一类，根据编程需求来定，可以是猫，也可以是人（`Person`）、鱼（`Fish`）、某个工具类。
    * > **易错点**：「创建了一个 `Cat` 结构体变量」和「定义了一个 `Cat` 结构体变量」两种叫法都对，含义一样，不必纠结。
    * > **结论**：结构体是一种自定义的数据类型，它的变量是它的一个具体实例。

* **快速入门：用 Cat 结构体解决养猫问题**
    * 先定义结构体把各个字段统一管理：`type Cat struct { Name string; Age int; Color string; Hobby string }`。
    * 用 `var cat1 Cat` 创建变量，和 `var a int` 是同一个套路，只是类型换成了结构体。
    * 因为结构体是值类型，创建时空间**已经分配**了；没赋值时各字段取自己类型的默认值——`Name`、`Color`、`Hobby` 是空的 `string`（打印时看不见），`Age` 是 `0`。
    * 赋值方式是「变量名点字段名」：`cat1.Name = "小白"`、`cat1.Age = 3`、`cat1.Color = "白色"`、`cat1.Hobby = "吃鱼"`。
    * > **易错点**：字段名写成小写 `cat1.hobby = "吃鱼"` 会报 `undefined`。Go 区分大小写，**字段名大写开头代表公开，小写代表包内私有，赋值和读取必须一致**。
    * > **结论**：面向对象关于结构体的入门代码本质就是两块——**定义结构体**，和**创建并使用结构体变量**。

* **结构体变量在内存中的存在形式**
    * `cat1` 这个变量名**直接指向**存放各字段的数据空间，每个字段都已分配并取各自默认值：

    ```text
    +--------------------- MEMORY ---------------------+
    |                                                    |
    |   cat1  ------>  +---------------------------+   |
    |                   |  Name  : ""              |   |
    |                   +---------------------------+   |
    |                   |  Age   : 0               |   |
    |                   +---------------------------+   |
    |                   |  Color : ""              |   |
    |                   +---------------------------+   |
    |                   |  Hobby : ""              |   |
    |                   +---------------------------+   |
    |                                                    |
    |   &cat1 = cat1 自身的地址                            |
    +----------------------------------------------------+
    ```

    * 结构体变量本身也有地址，用 `&cat1` 加取址符、`%p` 可以打印出来。
    * > **结论**：因为是**直接指向数据空间**（没有先指向一个地址再让地址指向数据空间），所以 `cat1` 是**值类型而不是引用类型**；很多别的语言里结构体不一定是值类型，Go 里就是。
    * 声明结构体变量时数据空间已经有了，没赋值时每种数据类型都有对应的默认值。

## 结构体的声明与字段

* **声明语法**
    * 写成 `type 结构体名称 struct { field1 type; field2 type }`，例如 `type Student struct { Name string; Age int; Score float32 }`。
    * `type` 和 `struct` 是**关键字，不能改**；中间那个标识符是结构体名称，可以按实际情况随便写；大括号里写多少个字段就写多少个，先字段名后字段类型。
    * 字段声明的语法和声明一个普通变量完全一样。

* **可见性：大小写决定作用域**
    * 结构体类型名首字母大写，表示这个类型可以在其他包被使用；小写则私有，只能在本包使用。
    * 字段名首字母大写，表示这个字段的数据可以被其他包引用；小写同样私有。
    * 这与变量的作用域规则是一致的。

* **字段、属性、field 说的是同一件事**
    * 字段有些叫属性，有些书直接叫 `field`，因为 Go 是老外设计的，翻译时叫法不一致；这三个概念几乎可以认为说的是同一件事，授课时统一叫**字段**。

* **字段能装什么**
    * 字段的数据类型可以是**基本数据类型、数组，也可以是引用类型**，几乎我们能用的都可以用。
    * 例如把猫的考试成绩直接定义成一个数组字段（数学、语文等三门成绩），字段本身也可以是二维数组。
    * > **结论**：字段类型只能是三种——基本数据类型、数组、引用类型，几乎没有例外。

* **字段的零值**

    | 字段类型 | 零值 |
    | :--- | :--- |
    | 布尔类型 | `false` |
    | 数值（整型、浮点型） | `0` |
    | 字符串类型 | `""`（空字符串） |
    | 数组类型 | 同元素类型，比如 `[3]int` 是 `0 0 0`，`[3]string` 是三个空字符串 |
    | 指针、slice、map | `nil`，即还没分配空间 |

* **引用类型字段必须先 make**
    * 定义一个含多种字段类型的结构体后直接打印，可以观察到指针、slice、map 三个字段都是 `nil`。
    * 用 `if p1.ptr == nil`、`if p1.slice == nil`、`if p1.map1 == nil` 分别判断，三个都会成立，说明它们都没分配空间。
    * 此时直接写 `p1.slice[0] = 100` 会报 `panic: index out of range`，因为切片还没 `make`。
    * 先执行 `p1.slice = make([]int, 10)` 之后才能正常赋值和使用。
    * 原理是：引用类型字段自己存的**只是一个地址**，`make` 之后它才指向一个具体位置。

    ```text
         p1  ──>  [ Name | Age | scores |  ptr  |  slice  |  map1  ]
                                      nil      nil      nil

                            执行 p1.slice = make([]int, 10) 之后：

                                      |
                                      +──> 0x1111 ──> [ 100, 0, 0, 0, 0, 0, ... ]
    ```

    * > **易错点**：使用切片时一定要先 `make`，不要一上来就直接拿来赋值、直接就建键值对。

* **不同结构体变量的字段相互独立**
    * 一个结构体变量的字段更改不会影响到另外一个，因为**结构体是值类型**。

## 创建结构体实例的四种方式

### 四种方式的对比

* **写法与返回类型**

    | 方式 | 写法示例 | 返回类型 |
    | :--- | :--- | :--- |
    | 一 var 加类型名 | `var person Person` | 结构体变量 |
    | 二 类型推导加大括号 | `p2 := Person{}` 或 `p3 := Person{Name: "Mary", Age: 20}` | 结构体变量 |
    | 三 new | `var p3 *Person = new(Person)` | 结构体指针 |
    | 四 取地址符 | `person := &Person{}` 或 `person := &Person{Name: "Mary", Age: 60}` | 结构体指针 |

* **各方式的要点**
    * 方式二在创建时就已经有了默认值，之后可以整体赋值，也可以写 `p2.Name = "tom"` 这样逐字段赋值。
    * 方式三里 Java 的 `new` 在 Go 中返回的**实际是指向该结构体的指针**，所以 `p3` 是 `*Person`；写成 `var p3 *Person = new(Person)` 更明确。
    * 方式四里 `&Person{}` 得到的同样是结构体指针，括号里可以直接带值；创建时就赋的值不会被后面的再赋值覆盖成默认值。
    * 方式三和方式四返回的都是**结构体指针**，方式一和方式二得到的是结构体变量本身。
    * > **提示**：一般会用方式二，在创建时直接赋值，它直接就是一个结构体而不是指针，开发中用得比较多。

### 结构体指针访问字段

* **标准写法与简写等价**
    * 标准写法是 `(*结构体指针).字段名`，例如 `(*p3).Name = "smith"`、`(*person).Name = "scott"`——先用取值符找到结构体，再点字段。
    * Go 做了简化，也允许写成 `结构体指针.字段名`，例如 `p3.Name = "john"`、`person.Name = "..."`。
    * 原因是 Go 的设计者认为这种写法更符合程序员的使用习惯；**编译器在底层会对 `p3.Name` 自动加上取值运算**，处理成 `(*p3).Name` 的形式，这个转换过程被隐藏到编译器底层，程序员不可见。
    * > **结论**：两种写法等价；标准写法是 `(*p3).字段名`，但 Go 的编译器在底层会对 `p3.字段名` 自动加上取值运算。
    * 别人用取值符的写法时也要理解，那才是真正的用法，只是比较麻烦一点。

## 值拷贝

* **结构体变量互不影响**
    * `monster2 := monster1` 是**值拷贝**：`monster1` 指向自己的数据空间，`monster2` 指向另一块独立空间，两块内容一模一样。

    ```text
         monster1  ──>  [ Name : "牛魔王" | Age : 500 ]      ← 一块独立的数据空间

         monster2  ──>  [ Name : "青牛精" | Age : 500 ]      ← 另一块独立的数据空间
    ```

    * 因此把 `monster2.Name` 改成青牛精之后，`monster1` 仍然是牛魔王。
    * 想让 `monster2` 的改变影响 `monster1`，就要**传地址**——赋一个地址给它，让它也指向同一块空间。
    * > **易错点**：手滑把 `monster` 写成 `Monster` 大小写不一致会直接报「没有定义」。
    * > **结论**：默认的结构体赋值是值拷贝，是值类型。

## 传地址

* **两个名字共享一份数据**
    * 把 `p1` 的**地址**交给 `p2`（`p2 := &p1`）之后，`p2` 是一个结构体指针。
    * 输出 `(*p2).Age` 和 `p2.Age` 都是 `10`。
    * 用 `p2.Name = "汤姆~"` 修改名字后，`p2.Name`、`p1.Name`、`(*p2).Name`、`p1.Name` **四次输出全部是「汤姆~」**。
    * > **结论**：这就是通过一个变量去修改另外一个结构体内容的方法——**传地址**。

* **内存布局：两个地址各自有地址**
    * `p2` 所在的空间里存放的**是一个地址**，这个地址指向的正是 `p1` 这个结构体的数据空间，属于间接引用。

    ```text
       内存

       p2 所在的地址空间                     p1 所在的地址空间
       +---------------------------+         +---------------------------+
       | 存放的内容 = p1 的地址    |         | 存放的内容 =              |
       +---------------------------+         |   Name : "汤姆~"          |
                  |                          |   Age  : 10               |
                  |                          +---------------------------+
                  +------------------------------>  ^
                  |                                  |
                  |
                  +-- 间接引用到 p1 的数据空间 --+
    ```

    * `&p1` 是 `p1` 的地址；`&p2` 是 `p2` 本身的地址；`p2` 是 `p2` 的值，也就是它存放的那个地址。
    * 实测中 **`p2` 的值刚好等于 `&p1`**，证明这个指针存放的地址确实指向 `p1`；同时 `p2` 本身也有地址。
    * 因为它们共享同一份数据空间，所以不管从哪个入口改，访问到的都是同一份数据。

* **`*p2.Age` 这种写法为什么是错的**
    * 和 `(*p2).Age` 唯一的区别是**没有用括号**把 `*p2` 包起来，这样写会报错。
    * > **易错点**：**点运算符的运算级别比取值运算符 `*` 更高**，所以实际执行顺序是先算 `p2.Age`（得到一个具体的 `int` 值），再对这个 `int` 值取星号，类型上直接不成立。
    * 正确做法是用括号包起来写成 `(*p2).Age`，或者干脆去掉星号写成 `p2.Age`。

## 字段在内存中的排布

### 字段连续分布

* **用地址验证连续性**
    * 定义 `Point{x int; y int}` 和 `Rect{leftUp, rightDown Point}`，创建 `r1 := Rect{Point{1, 2}, Point{3, 4}}`。
    * 打印 `&r1.leftUp.x`、`&r1.leftUp.y`、`&r1.rightDown.x`、`&r1.rightDown.y` 四个地址，依次是 40、48、50、58，**每一步刚好相差 8 个字节**。
    * 为什么是加 8 而不是 6 或 5？因为字段类型是 `int`，一个 `int` 在 64 位环境下就是 8 个字节，默认就是 `int64`；第三个是在 48 的基础上再加 8，十进制是 56，十六进制就进位变成 `50`，第四个再加 8 变成 `58`。

    ```text
      r1  ──>  [ x : 1 ][ y : 2 ][ x : 3 ][ y : 4 ]
                addr 40  addr 48  addr 50  addr 58
                       ←8→   ←8→   ←8→
    ```

* **连续分布的好处**
    * 结构体的**所有字段在内存中连续分布**。
    * 第一个好处是取值速度快：底层直接通过地址加减来定位，找到第一个字段后加 8 个字节就找到下一个，操作本身的速度偏快。
    * 这种分布也利于数据查找，高手可以完全通过地址的加减快速取得某个字段的值。

* **连续分布为什么值得记住**
    * 早期在 Linux 下用 C 做服务器时有个获取用户在线状态的功能，最初把每个用户的状态直接存在 MySQL 数据表里，被当时的负责人批评——用户状态变化非常频繁，都存进表里会导致对数据库的操作非常频繁、承压能力很低。
    * 改法是把用户状态直接放在一个结构体里，来一个用户就把 ID 和状态放进去，查找时根据用户编号通过地址加减迅速定位到地址再取出状态，只改了这么一点点，整体性能提升非常大。

### 指针字段的连续性

* **本身连续，指向的未必连续**
    * 定义 `Rect2{leftUp, rightDown *Point}`，创建 `r2 := Rect2{&Point{10, 20}, &Point{30, 40}}`。
    * 打印 `&r2.leftUp` 和 `&r2.rightDown`（取本身的地址，后面不要跟 `x`），得到 `11C0` 和 `11C8`，**本身地址仍然连续、相差 8 个字节**——因为它们的类型底层是 `int*`。
    * 打印它们指向的地址（此时不加 `&`）是 `...090` 和 `...0A0`，`90` 与 `A0` 相差明显，**不保证连续**，每次都可能不一样，要看内存分配和系统当时的分配情况。

    ```text
      r2.leftUp 本身: [ 指向 0x...090 ]  ← 本身连续（相差 8 字节）
      r2.rightDown : [ 指向 0x...0A0 ]

      0x...090  ──>  [ x:10 ][ y:20 ]      ← 与下面那块不保证相邻
      0x...0A0  ──>  [ x:30 ][ y:40 ]
    ```

    * > **结论**：**指针字段本身是连续的，但它本身的内容、也就是它指向的那个地址不一定是连续的**，当然也有可能是连续的，看实际情况。

## 结构体之间的类型转换

* **前提是字段完全相同**
    * 结构体是用户单独定义的类型，和其他类型转换时**需要有完全相同的字段**。
    * 「完全相同」指**字段的名字、个数、类型**三样都必须一致；只要有一项不同，整个就转换不成功。

* **强转的写法与失败示例**
    * 定义 `A{Num int}` 和 `B{Num int}`，直接写 `a = B` 会报 `cannot use b (type B) as type A`。
    * 强转写成 `a = A(b)` 就没有问题，之所以能转正是因为字段的个数、名称、类型都一样。
    * 把 `B` 的字段名改成别的也不行；多出一个 `Name string` 字段同样不行。

## type 重新定义

* **重新定义会造出一个新类型**
    * `type Stu Student` 之后，Go 认为 `Stu` 和 `Student` 是**两个不相同的数据类型**，`stu2 = stu1` 直接赋值会报错。
    * 要写 `stu2 = Stu(stu1)` 强转才行，本质还是因为两个结构体拥有相同的字段。
    * 内置类型也一样：`type integer int` 之后，`integer` 与 `int` 被视为两种不同类型，`var i integer = 10`、`var j int = 20` 时 `j = i` 报错，要写 `j = int(i)`。
    * > **易错点**：很多人会认为重新 `type` 定义后就是同一个数据类型，一般语言会这么处理，但 **Golang 对数据类型的要求非常严谨**，它认为是两个不同的类型。
    * 这个特性保证了写项目时代码的可读性——否则后面的代码会看不懂。

## 结构体 tag

* **tag 的定位**
    * 在结构体的每个字段上还可以写一个标签，叫 tag，**可以通过反射机制获取**。
    * 最常见的使用场景是**序列化和反序列化**。

* **Go 服务器返回数据给浏览器的场景**
    * 服务器拿到一个结构体变量后不可能直接把结构体返回，通常要先做成**字符串**，也就是先**序列化**；通用的字符串格式叫 `json`。
    * 客户端接收字段时并不希望是大写的 `N`，很多客户端更喜欢小写。

* **序列化时踩的两个坑**
    * 序列化用 `encoding/json` 包里的 `Marshal` 方法，`data, err := json.Marshal(monster)` **返回两个值**，一个是 `byte` 字节（也就是 byte 切片），一个是 `error`；不接收 error 就用下划线忽略，需要时判断 `if err != nil`。
    * 拿到 byte 切片后要转成字符串才能看见，用 `string(data)` 转换。
    * **第一个坑**：很多程序员不习惯字段首字母大写，于是把字段改成小写，结果序列化出来是**空串**——因为 `json` 在另一个包里，按作用域原则它访问不到这些小写字段。
    * **第二个坑**：保持大写时序列化出来的字段名是 `Name`、`Age`、`Skill`，客户端并不喜欢这种形式。

* **用 tag 收尾**
    * 写法是一个**反引号**（不是普通引号）加上固定的名字 `json` 和冒号，再写上小写的对外名字：

    ```go
    type Monster struct {
        Name  string `json:"name"`
        Age   int    `json:"age"`
        Skill string `json:"skill"`
    }
    ```

    * 改完之后序列化出来的就是小写的 `name`、`age`、`skill`，既能正常序列化，又保持了与客户端习惯的兼容性。
    * > **结论**：`Marshal` 能把大写字段名换成 tag 里的小写名字，底层用到了**反射**——反射的原理到讲反射时再展开。
