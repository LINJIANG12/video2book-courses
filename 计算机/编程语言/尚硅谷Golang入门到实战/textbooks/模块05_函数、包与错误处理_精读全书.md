## 从一段重复的 switch 代码，看函数为什么必须存在
> 对应块：BLK37 | 覆盖分集：P109-P110 | 块标题（分集名）：《108_尚硅谷_为什么需要函数》

流程控制这块内容我们全部介绍完了。下面打开新章节——**函数、包和错误处理**。

函数是我们这里面特别重要的一个概念，也是编程语言里特别重要的一个概念。而且从这儿开始，就开始有**模块化编程的思想**了。

我还是老规矩，为了让大家听得轻松一点，**由一个问题引出我们为什么需要函数**，尤其是对零基础的同学来说，这特别重要。我前面一定阐述过这个观点：**任何一个新的技术，一定是因为它对以前有一个改进，或者能让效率提升，或者在使用形式上有一个优化，它总是有个原因的。**

### 一个看起来毫无难度的需求

请大家完成这样一个需求：**输入两个数，再输入一个运算符，得到一个结果。** 也就是写一段代码来计算两个数的加减乘除，计算结果应该跟它的运算符有关系。

同学们想，如果这段代码让你们来完成，你们能够完成吗？

肯定你们是能做出来的。因为前面两个数的加减乘除我们是学过的，而且还学过判断语句和 `switch` 语句，这是完全可以做成的。**有了这个需求，我们先不去管函数，先不要管其他东西，我们就用传统的方式来解决，然后我们看一看用我们现有的技术解决会出现什么问题。**

### 传统写法：能跑，但撑不住

新建 `chapter06`，里面建一个文件夹叫 `func_demo`，写一个 `main.go`。老规矩，`package main`、`import "fmt"`、`func main()`。

他说输入两个数，再输入一个运算符，其实就应该有三个变量了。这里我就不从控制台输入了，直接定义三个变量：

```go
var n1 float64 = 1.2
var n2 float64 = 2.3
var operator byte = '+'
var res float64
```

`operator` 这个单词就是操作符的意思。因为运算符可能是加、减、乘、除，在输入的时候不知道是哪一个，所以我们再定一个变量。这个地方我们用 `byte`，因为我们可以用字符来表示。

现在因为这些操作符到底是什么我不知道，所以用 `switch` 来判断：

```go
switch operator {
case '+':
	res = n1 + n2
case '-':
	res = n1 - n2
case '*':
	res = n1 * n2
case '/':
	res = n1 / n2
default:
	fmt.Println("操作符号错误")
}
fmt.Println("res=", res)
```

如果输入的是加号，那我们就等于 `n1 + n2`；是减号就等于 `n1 - n2`，其他依此类推。否则如果这个运算符不对，我们 `default` 一下，给他提示一个信息——你的操作符有误，没法计算。

整个这个 `switch` 走完以后，其实这个结果是不是就已经拿到了？把它输出来，`res` 等于多少。

跑一把：结果是 3.5，完全正确，因为我这是加号嘛，1.2 + 2.3 没问题。假设我把它改成减法，1.2 - 2.3，看结果是多少。当然你后面还可以想一些办法把它格式化输出，比如我就想保留到小数点后多少位，也可以这样处理，后面再说。

不管怎么样，这个结果已经做出来了，是正确的，而且的确比较简单。有些同学说老师这个完成就完成了呗——没问题，是这样子的。**我们先把代码写出去，然后我就要分析一下传统的方法解决有什么缺陷。因为他有缺点，所以说才引出我们使用函数的必要性。**

### 拆穿它：冗余与维护成本

先问大家一个问题：**这段代码写完了以后，你敢不敢保证我们在别的位置就没有这个需求了？**

假设我写了很多很多代码，`main` 函数写到这儿还没执行完，下面还有很多其他的代码。当它写到这儿的时候，它突然又有一个需求——我还要计算两个数的乘法，或者加法、除法。怎么办？

比如这两个数是 `number1` 和 `number2`。那当然有同学说了，好吧，你不是 `number1` 和 `number2` 吗？你定义一个 `number1 float64`，比如这个值假设是 4.5，然后又定义 `number2` 假设是 6.7。然后你要去求它的加减乘除，你把这个 `byte` 值拿过来，重新赋一下值，假设这个地方我想求乘法，给他赋一个乘号。然后怎么办？**把这一串代码复制一下。** 复制下来过后，这个结果不就可以重新算出来了吗？可以啊。

那这个时候你肯定要把它代码改了嘛，或者说老师我再聪明一点，`n1` 和 `n2` 本身这个变量值是什么并不重要，我直接就把 `number1`、`number2` 这样写，`byte` 我重新赋一下值，让它重新算一下，这个值不就得到了吗？

没错，这样思想确实是可以的，确实也是 OK。**但是大家有没有发现，我们这段相同的代码已经出现过两次了。** 等到你再往下面走，它突然又有一个需求，要求两个数的加减乘除，你是不是又把这段代码再重新给我复制一遍？是不是又得复制一遍啊？

> **结论**：问题就已经出现了。这段代码在我们的程序里面有一种可能性，就是会多次出现。那么我们就会出现什么问题呢？这地方就导致我们的代码可能会出现**冗余**，同时**不利于我们代码的维护**。

你比如说我要加一个功能，**减一个功能**——比如我这个 `switch` 我要加一个求两个数最大值的，或者有别的运算符，比如求模，求两个数的模，那你是不是可以在这儿给我加一个？如果他输入的是取模符号，你这儿给我加一下。**你这儿加了过后，是不是意味着下面也通通都要加？你代码维护性是不是也不好？**

所以我们总结出来两个问题：

- 第一，上面这种写法**首先是可以完成功能的**，这个是给它一个肯定，**但是代码可能会出现冗余**，因为在别的地方你也会反复复制；
- 第二，**同时也不利于代码的维护**。比如说我要增减一个功能，也很麻烦。

这两个问题就导致我们不能够这样去写。那怎么办呢？我们要引出的东西就出来了——**就是函数。函数可以解决这个问题。其实函数就体现出模块化编程了。**

这就是我们通过这样一个分析，解决了**为什么需要函数**。

### 什么是函数

> **定义**：**所谓函数是为完成某一个功能的程序指令的集合，或者叫做程序语句的集合，称为函数。** 其实特别简单，就是把一些功能合在一起，我们把它就叫函数。

在 Go 语言中，函数有**自定义函数**，也有**系统函数**。

- **自定义函数**：听其名而知其意，就是说你自己写的函数；
- **系统函数**：就是系统给你提供的函数。

你比如说前面我们用的这些其实就是系统函数。这里的 `fmt.Println`，这个就是一个系统函数。

系统函数很多。我们打开 Go 的源代码——前面我们安装过一个 Go，进到 `go/src` 里面来，随便找一个，比如说我们熟悉的 `fmt`。打开这里面，这里面写的东西其实都是很多很多很多的函数。你看这里，这个是不是就是一个函数？这个是不是又是一个函数？这个还是个**方法**，不好意思，这是个方法，还不是函数。我们找一个函数——这边全都是方法，这边全部都是方法，还不是函数。

那我们打开手册找一个吧，打开官方的 Go 手册，找一个我们前面讲过的 `math` 包。你看这里面，`NaN`——这个就是一个函数；这个也是一个函数，就是判断是不是一个数值、返回一个是否为数值的函数；这边也都是函数，等等等等。**这都是函数，函数很多，这就是系统函数了。**

所以函数就是有两大类：**一种是自己写的函数，一种是系统直接给我们用的函数。**

### 函数长什么样

函数是这样子的：

- `func`——这是个关键字，**这是不能改的**；
- 这里是我们的**函数的名字**，就是一个标识符；
- 这边是我们的**参数列表**，我们也管它叫**形参列表**；
- 这边是**返回值类型列表**，或者叫返回值列表，都可以；
- 里面**带个大括号是必须有的**，这是一对大括号，表示在这里面是我们的**函数体**，里面有我们要执行的语句，而这个执行的语句就是我们要完成的功能——比如一个计算的功能，或者是一个统计的功能等等。

那么这个 `return`，在这里就上场了：

> **提示**：`return` 有两个作用——**第一，它可以返回一个值；第二，它可以表示终止这个函数的执行。** 它在终止的时候给你返回了一个值。

我把它整理成三句话：

- **形参列表**就是表示函数的输入；
- 函数中的语句表示为了实现某一个功能的代码块；
- 函数的返回值，这个函数**可以有返回值，也可以没有**。如果你没有返回值你就不要写，就直接 `return` 就完了。

这就是基本语法，特别简单。

### 快速入门：把那段 switch 装进函数

有了基本语法，我们快速入门：**用函数解决前面的计算问题。** 当这个快速入门讲完，你马上就对函数有一个比较形象的认识，就觉得不抽象了。

它的思想是这样子的：**把这一段功能封装起来，写成一个函数，在需要使用时调用即可。**

函数名叫 `cal`，就是 `calculator` 的简写。参数这边大家想，是不是要输入两个数，还有一个运算符啊？

第一个形参，**注意这个参数叫形参**。形参在写的时候是先写形参的名称，再写类型 `float64`，**注意这个顺序**。第二个我们再接收一个值，`float64`。第三个我们还要接收一个操作符 `operator`，`byte` 类型。

这样我这里面就有三个形参，这个叫形参、形式参数。那么我有返回值吗？我肯定是有返回值的，因为我会计算一个结果嘛，我把这个结果返回来 `float64`。这个就叫返回值列表。因为只有一个，所以说我这地方这个括号可以不写，当然你写上也没有问题。

```go
package main

import "fmt"

// 自定义函数：计算两个数的加减乘除
func cal(n1 float64, n2 float64, operator byte) float64 {
	var res float64
	switch operator {
	case '+':
		res = n1 + n2
	case '-':
		res = n1 - n2
	case '*':
		res = n1 * n2
	case '/':
		res = n1 / n2
	default:
		fmt.Println("操作符号错误，没法计算")
	}
	return res
}

func main() {
	n1 := 1.2
	n2 := 2.3
	var operator byte = '+'

	// 调用函数，用 result 接收返回的结果
	var result float64
	result = cal(n1, n2, operator)
	fmt.Println("result=", result)
}
```

这里面的内容是不是咱们已经写过了呀？我把这段代码复制过来，整个复制一把，然后放到这个函数里面来。它进来过后，这段代码我已经把它放在函数里面去了；然后这个 `res`、`operator` 拿到过后，它就加减乘除，最后把这个结果返回——把这个 `res` 给我返回即可。代码写完了。

#### 调用时到底发生了什么

那在用的时候怎么用呢？非常简单，`result := cal(5.3, 2.3, '-')`，这样我们相当于定义了一个变量，等于这边返回的，把这个粘贴到这里来。

这样用法代表什么意思呢？就是相当于说，你这有一个 5.3，这有一个 2.3，这有一个减号。那么这个时候 **5.3 就传给了 `n1`**，**2.3 就传给了 `n2`**，**这个减号就传给了 `operator`**。

那边就会拿到，拿到过后它下面就可以使用了。你可以理解成好像把 5.3 赋给了 `n1`，把 2.3 赋给了 `n2`，把这个减号赋给了这里的 `operator`。这个 `operator` 拿到过后，下面就可以当做一个变量直接使用了。

跑一下，`result` 等于 3，正确，因为 5.3 减 2.3。

但是这样写法肯定不合理——**你这样老是传一个具体的值很累**。所以说完全可以把这里的 `n1` 写到这来。

这个时候，传的这个 `n1` 就是 1.2，传的这个 `n2` 就是 2.3，传的这个 `operator` 就是加号，一样的。**整个返回的结果应该是 3.5。**

#### 一句话顶一大段

下面的代码你看有多方便了呢？我想计算 4.5、6.7、星号，一句话就够了：

```go
result = cal(4.5, 6.7, '*')
fmt.Println("result=", result)
```

刚才那么大一段代码，用这一个就解决了，是不是？同样如果我再想计算，也是一样的道理，我就不写了。

**原先我们写很多代码，现在其实就是调用一下就可以了。调用一下，结果就拿到了，这多方便。**

而且代码的维护性也会变得很好。为什么？如果我想增加一个取模的功能，那非常简单：

```go
case '%':
	res = n1 % n2
```

我们这个结果怎么返回呢？`res = n1 % n2`，完事。那这样一写的话，相当于说你在这个地方调用的时候，你就可以直接这样做了。**你下面是不是也同样具有这个功能了，所以维护性也非常好。**

这块我们先撤回去，因为我们一般不取模，体会一下它的好处吧。这一个基本函数的快速入门案例我们就讲到这了。大家先体会一下、感受一下，如果可以的话，自己写写代码，自己跑一跑。

但是不管怎么样，我们现在可以这么说：你听完老师讲到这，你可以说我对函数有个基本的了解了，只是细节我们还没抠。所以细节等到下面就要开始来讲解。

## 包：把函数分门别类放好，再互相调用
> 对应块：BLK38 | 覆盖分集：P111-P113 | 块标题（分集名）：《110_尚硅谷_包的引出和使用原理》

刚才我们讲了这个函数，它很好，可以解决我们代码复用性的问题，而且也利于我们代码的维护。**但是，当我们用了函数过后，又带来了一个新的问题。**

### 函数的烦恼：都堆在 main.go 里合适吗

什么问题呢？我们在 `main.go` 里面写了一个函数 `cal`，这是没有问题的。但是大家想一想，**如果这地方写一个函数是可以的，那就意味着将来我可以写很多函数**。今天我写了个 `Cal`，那我接着再写函数、再写函数，函数越来越多，都堆在这个 `main.go` 里面，这合适吗？

这肯定不合适。我们来看这个示意图描述的问题。

#### 麻烦一：想跨文件复用

```text
   ┌───────────────────────────────┐
   │           main.go              │
   │  ┌─────────────────────────┐  │
   │  │ func main() { ... }     │  │
   │  │   └─ 调用 Cal(...)      │  │
   │  └─────────────────────────┘  │
   │  ┌─────────────────────────┐  │
   │  │ func Cal(...) { ... }   │  │
   │  └─────────────────────────┘  │
   └───────────────────────────────┘

   问题：能不能把这些函数挪到别的文件去？
   ┌────────────────┐      ┌──────────────────┐
   │   main.go      │ ───▶ │    utils.go      │
   │  只管调用      │ 引入 │ 只管定义函数      │
   └────────────────┘      └──────────────────┘
```

你们想没想过这样一个需求：这有一个函数，我们接着再写一个函数，再写函数。**我们能把所有的函数都定义到 `main.go` 里面吗？**

从理论上来说这是可以的。再说一遍，从理论上来说是可以的。**但是你想一想，我们一个大项目里面函数可能有成百上千**，你都把这么多函数都写到一个文件里面，你觉得合适吗？显然这是不合适的。

于是乎我们提出一个新的概念、一个新的问题：如何把这些函数写到别的地方，然后再调用？是不是顺理成章就出来了。也就是说，假如我这里有一个新的文件，比如这个文件叫 `utils.go`——**这个文件干什么呢？就是专门用于定义函数的，定义函数让其他文件来调用的。**

你想实现的效果就是：你的很多函数，别全部写在 `main.go` 里面去了，你专门写一个文件或者写很多文件。把这个函数剪切到 `utils.go` 里。然后我在 `main` 方法里边想去用它。怎么用呢？**我引入。只要它支持一种方式，就是引入 `utils.go` 的 `cal` 这个函数就可以了。只要它提供这样一种机制，就是说我想用谁，我就把它引到我相对应的文件里面，我就用它就行了。**

我们可以再写一个文件，假设这个文件专门用来对数据库的操作，叫 `db.go`，那里面又专门定义对数据库操作的函数。这样就好办了——**分门别类地把各个函数写在对应的文件里面**。我要在 `main.go` 里面用 `utils` 里面的 `Cal` 函数，我就引入 `utils`；我想用 `db` 里面的 `AddData` 函数，我又引入 `db`。我一引入过后，那我在这里除了可以调用 `cal` 函数，还可以调用 `AddData` 函数。

#### 麻烦二：两个人的函数撞了名

包还有一个用处：**两个程序员共同开发一个 Go 项目**，这是有可能的，因为项目将来很大，你不可能一个人写，张三李四都有可能去写。

假设有一个程序员叫小明，他希望定义一个函数叫大写的 `CAL`；小强呢也想定义这个函数，**两个程序员还要打架怎么办？** 大家都可能去定义一个相同的函数名。

但是大家都知道，**我们在同一个文件里面是不可以定义相同的函数名的**，如果你有相同的函数名它肯定要报错，因为叫重复定义。比如我们在 `main` 里面再去写一个这样的函数，它是绝对给你报错的。当我一保存，这地方立马报错：

```text
Cal redeclared in this block
```

什么意思？说你这已经声明过了，声明过你还再去声明一个，它是不予允许的。

那刚才这个机制又能解决它。**假设这个 `utils` 是小明写的，假设 `db.go` 是小强写的，那你放心大胆写了，因为你已经不在同一个文件里面了，或者说不在同一个包里面了。** 你这可以叫 `CAL`，我这地方也可以叫 `CAL`。那怎么区分呢？还是用我们的包。

#### 两个需求，一个结论

- **第一个需求**：我们需要在不同的文件里面去写自己的函数并调用——包的作用是让我们**分门别类**，在不同包下面建不同的文件，把函数放到对应的文件里面，然后进行调用。
- **第二个需求**：包还可以进行**项目的管理**。比如我让小明建一个包，让小强建一个包，各自在自己的包下面去写自己的东西，这样也不冲突。

这就是为什么需要包。

### 包的本质就是一个文件夹

讲到这儿我们必须要说一下包的原理了：

> **定义**：**包的本质就是创建不同的文件夹来存放程序文件。** 再具体一点，我们一个包往往对应一个文件夹，而这个文件夹下面就有我们的文件。

打个比方。比如说我这有个项目叫 `oa`，`oa` 下面有一个 `main` 包，`main` 包下面有 `main.go` 文件。那我怎么去实现这种效果呢？

**在 Go 语言里面它是这样规定的：你不同的文件放在不同的包下面就可以。**

```text
oa（项目）
├── main（包）
│   └── main.go
├── utils（包）
│   └── utils.go
└── db（包）
    └── db.go
```

如果我们要建另外一个包，比如刚才画的 `db` 包，那就在 `db` 这个文件夹下面建 `db.go`。这样就把我们的文件分开了。

理解一下：说白了你可以这样理解，**我们一个包往往对应一个文件夹，而这个文件夹下面就有我们的文件**。通过这种方式和这种机制可以实现刚才我们的这种效果。当然它还有很多细节，细节我们在讲后面的时候会逐一给大家展现出来，**但大家一定要知道，包的本质就是一个文件夹。**

### 包的基本概念与三大作用

何为包？

> **定义**：**Go 的每一个文件都属于一个包。** 也就是说 **Go 语言是以包的形式来管理文件和项目目录结构的**。如果你一个文件不属于一个包，这是不可能的。

包的作用有哪些？简单总结一下：

- **第一，区分相同名字的函数、变量等标识符。** 刚才讲过，在不同的包下面，我们的文件可以写相同的函数名，甚至变量名也是可以相同的。
- **第二，当程序文件很多时，可以很好地管理我们的项目。** 我们不可能把所有的文件、把所有的函数都写在一个 `main.go` 里面去，这是不现实的。必须要用一种包的形式把所有的文件分门别类地放好，比如说 `model` 包、`service` 包、`utils` 包等等。
- **第三，包还可以控制函数、变量的访问范围及作用域。** 具体怎么做待会儿再说。

包的具体使用有两个特别重要的指令：**一个是打包指令 `package 包名`**，比如说我们前面写过的 `package main`，这个就是打了一个包，`main` 就是它的包名。**一个是 `import`，引入一个包。**

具体来说：如果我想在 `main.go` 里面用到 `utils` 包下面这个文件的 `SayHello` 函数，怎么用呢？非常简单，就 `import` 写上我要引入的包的路径。引进去过后，调用的时候是 `utils.SayHello()`。

> **注意**：如果你的函数名首字母是小写，还不能这么用——**得用大写的 S 才能调，待会儿我们还要讲这个细节。如果你的函数名首字母是小写，就不能跨包使用。** 这就是体现出包还可以控制我们函数的访问范围。

### 快速入门：一次完整的目录改造

需求是：**将计算的那个函数 `Cal` 定义到 `utils.go` 这个文件里面，将 `utils.go` 放在 `utils` 包里面去。当其他文件需要使用到 `utils.go` 的方法时，可以 `import` 包，就可以使用了。**

目前我的 `function_demo01` 里面只有一个 `main.go`，这显然是不好管理的。我们要实现这个效果，得把 `main.go` 放在一个独立的 `main` 包里面去。

#### 第一步：把目录结构搭起来

首先你可以把 `function_demo01` 理解成是一个项目的名称。我先建一个文件夹叫 `main`，然后将 `main.go` 移到 `main` 文件夹里面去——也就是说现在在 `function_demo01` 这个文件夹下面有个 `main` 包。

然后我们再建一个新的文件夹叫 `utils`，在这个文件夹下面新建一个文件叫 `utils.go`。这个时候我们上来先打包：

```go
package utils
```

这就是打包指令。然后我把 `main.go` 里面的这个方法剪切走，放到 `utils.go` 里面去。

#### 第二步：函数名首字母必须大写

> **注意**：这个时候大家注意，**这个函数的名字首字母就要大写了，C 必须大写。** 为什么要大写？因为如果你不大写的话，即使引入了 `utils` 包，你也用不了这个函数，**因为小写代表私有。**

在 Go 语言里面有一个专业的术语叫做：**该函数可导出**，类似其他编程语言的 `public`。

保存过后显然这个代码一定会报错，它立马会告诉你这个函数没有定义过，报 `undefined: cal`——你这没有定义又没有引入，肯定用不了。

#### 第三步：import 路径与调用

现在我们要引入这个包：

```go
import "go_code/chapter06/function_demo01/utils"
```

引入的时候是从 `GOPATH` 的路径下面的 `src` 开始往下写，**但是不用写 `src`**，因为默认就是从 `src` 下面开始定位的。

在调用的时候是**包名点函数名**：

```go
utils.Cal(...)
```

保存。这边报了个错，因为你在 `utils.go` 文件里面又用了打印，本身也应该引入 `fmt` 包：

```go
import "fmt"
```

`utils.go` 的完整样子：

```go
package utils

import "fmt"

// 该函数可导出，供其他包调用
func Cal(n1 float64, n2 float64, operator byte) float64 {
	var res float64
	switch operator {
	case '+':
		res = n1 + n2
	case '-':
		res = n1 - n2
	case '*':
		res = n1 * n2
	case '/':
		res = n1 / n2
	default:
		fmt.Println("操作符号错误，没法计算")
	}
	return res
}
```

`main.go` 这边调用也得改一下：

```go
package main

import "go_code/chapter06/function_demo01/utils"

func main() {
	n1 := 1.2
	n2 := 2.3
	var operator byte = '+'

	var result float64
	result = utils.Cal(n1, n2, operator)
	fmt.Println("result=", result)
}
```

> **提示**：为了能够让大家感受到确实变化了，我把 `res` 输出后面加一个波浪号。**尽量在代码做了改变过后让输出也有一定的改变**，不然的话到底改没改、生效没生效，心里边还不敢肯定。

#### 顺手解决一个精度问题

终端进入 `main` 目录运行：

```bash
go run main.go
```

结果 `res` 等于 3.5，第二个相乘等于 30 点多——**这个我没有做精度的处理，所以它把精度保存得比较高。** 在输出的时候很简单的就能解决这个问题：如果想保留两位小数，可以写 `%.2f`。

这种写法其实看手册就能看得非常清楚。手册的 format 里写得很清楚：`%.2f` 默认宽度，精度为 2，就是保留小数点两位。如果你要保留小数点三位，一样的；`.3`、.4、.5 也都可以。`9f`、`9.f` 又代表什么意思？是不是很容易理解啊？`9.f` 就代表宽度为 9，精度为 0，就是没有小数点，去掉小数点。

那么老师是怎么知道这样写就可以的呢？**因为我看手册了。** 方法很重要。

#### 顺手验证一下：首字母小写会怎样

假设我把这个 `Cal` 写成小写的 `cal`，这边调的时候也写成 `utils.cal`。这样是不是也写？但是你执行的时候，当我一保存，它马上会提示一个信息：

```text
cannot refer to unexported name utils.cal
```

它是什么意思呢？说我不能指向这个不可导出的函数。`unexported` 就是不可导出嘛。它认为这个函数**根本没定义过**——**因为首字母小写就代表私有，私有的是不可以跨包被访问的。**

这就是我们刚才讲的那一点，**包其实也可以用来做访问范围的控制**，就是这个地方引出来的。

### 包的使用细节

包的使用细节也是很重要的一个知识点。这里一共给大家整理总结了**七个在使用包的时候要注意的细节**，这个视频讲到第五个，剩下的后面再展开。

#### 包名和文件夹名：一致，但不是硬规定

**第一个细节**：在给文件打包的时候，**该包对应一个文件夹**，前面已经讲过了。比如这里的 `utils` 文件夹，对应的包名就是 `utils`。**文件的包名通常和文件所在的文件夹名保持一致，一般为小写。**

但是——**Go 语言里面并没有严格地说你的包名就一定要跟文件夹名保持一致，没有这个规定。** 打个比方，你这文件夹叫 `utils`，包名也可以叫 `abc`，这样用也是没有任何问题的。

**但是，一旦你引入路径写的是 `utils` 文件夹，在调用的时候如果再用 `utils` 去调，就调不起来了**，因为你的包名叫 `abc`。这个时候再去运行它一定会报错，提示 `undefined: utils`，没有这个包，应该写成 `abc`。

```text
文件夹名：utils   →   import ".../utils"
包名：     abc     →   调用时必须写 abc.函数名()
```

所以这个地方写的是**包名**，而 `import` 引入的**只是包所在的那个文件夹**。

虽然可以写成 `abc`，但引用的路径叫 `utils`，包名却叫 `abc`，感觉会很奇怪。**所以一般情况下我们还是保持一致**——虽然语法上没有说一定要保持一致，但是作为开发人员，习惯上一般还是保持一致的，我们还是按照约定俗成的习惯来命名包名。

#### package 和 import 的写法规矩

**第二个细节**：当一个文件要使用其它包的函数或变量时，**需要先引入这个包**。引入的形式有两种：**第一种是直接单写 `import "包名"`，第二种是把这些包名写在一块。** 习惯上我们还是按照标准的规范把它们写在一起。

还有一点：**`package` 打包指令一定要放在文件的第一行，然后才是 `import` 指令，接着才是函数的定义与执行**——这一点跟 Java 是一样的。

引包的时候还要注意：**引包时的路径是从 `GOPATH` 的 `src` 下面开始计算的，不用带 `src`**，因为编译器会自动把 `src` 引入。

在计算机环境变量里面我们配置过 `GOPATH`，比如 `D:\go_project`，它实际上是从该路径下面的 `src` 开始去定位的。**其实它首先会从 `GOROOT` 去找，但 `GOROOT` 一般不会去放我们自己写的包，所以没找到后就会从 `GOPATH` 的 `src` 开始找。**

这也是为什么在创建项目或工程的时候，通常是在该路径下面建 `src`，在 `src` 下面再去建项目。**作为一个 Go 语言的开发规范，大家都应该去遵守。**

#### 首字母大写：跨包的通行证

**第三个细节**：为了让其它包的文件可以访问到本包的函数，**则函数名的首字母需要大写**，类似于其它语言的 `public`，这样才能跨包访问。比如 `utils` 里面的 `Cal` 函数——如果首字母写成小写，别的包是无法访问的。

**如果是一个变量也同理。** 比如在 `utils` 包里面定义一个变量：

```go
var Num1 int = 300
```

需要在 `main` 包里面去使用这个变量，**变量名首字母也必须大写**。如果不写成大写，代表它是私有的，别的包就无法访问。

#### 访问语法：包名.名字

**第四个细节**：在访问其它包的函数或变量时，其语法是 **`包名.函数名`** 或 **`包名.变量名`**。如果变量名首字母大写，其实就是全局变量。

#### 取了别名，原名就作废

**第五个细节**：如果包名比较长，Go 支持给包取一个别名。**需要注意：取完别名过后，原来的包名就不能使用了。**

比如在 `main` 里面原本是用 `utils` 来访问的，现在我给这个包取一个别名，比如取名为 `u` 或者 `ut`：

```go
import util "go_code/chapter06/function_demo01/utils"
```

那这个时候我在用的时候，就应该用这个名字来访问。**当然你这样写了过后，原先这个包名也用不了了。** 我一保存它就提示你没有用过这个 `utils`；你要写 `utils`，它直接告诉你 `undefined: utils`。

**相当于说它这个名字就在这个地方是生效了，你原先这个就用不了了。你要用原先这个，你得怎么办呢？你就不要取别名。**

所以你以后看到别人在引入的路径前面写了一个别的变量，这个就是相当于给这个文件夹所在的包取了一个别名。当然你取了一个别名过后，在这个文件里面去用这个包的变量或函数时，就得用这个名字了。

剩下第六、第七个细节，后面再展开讲。

## 同包不能重名、怎么编译出可执行文件，以及函数调用时内存发生了什么
> 对应块：BLK39 | 覆盖分集：P114-P115 | 块标题（分集名）：《113_尚硅谷_包使用注意事项和库文件(2)》

我们接着把包的注意事项讲完，然后回头把函数再往深处挖一层。

### 同一个包里，函数名不能重样

> **结论**：**在同一个包下，不能有相同的函数名，否则报重复定义错误；同样也不能有相同的全局变量名。**

这是什么意思呢？**Go 语言在管理我们这些函数的时候，它是以包的方式来进行管理的。也就是说，在一个包下面，假设有两个文件，这两个文件就不能有相同的函数名。**

打个比方。比如说在 `utils` 里面你定义了一个 `calculate`，首先肯定在同一个文件里面你不可能再去定义这个相同的函数了——我在这写一个这样的函数，它肯定是要报错的。

而且我告诉大家，刚才大家也看到，我们在 `main` 里面去调一个函数的时候，是通过这个包名去调用的，**大家还有印象吧？它是通过这个包名去调用的。** 那就意味着：**如果你在这个包下面有两个相同的函数名，那在调用的时候，编译器根本无法区分。**

我换一个思路说：老师，假设我在这包下面还有一个文件叫 `utils2.go`——这是个新文件。我们先保存一下，这个时候应该不会报错了。在 `utils2.go` 里面写一个叫 `sayOk` 的函数：

```go
package utils

import "fmt"

func sayOk() {
	fmt.Println("say ok")
}
```

这个是没有问题的，因为你没有重复。但是大家看，`utils2.go` 是在 `utils` 这个包下面。

那么同学们想一想，**如果我在这个文件里面写一个 `func Cal` 这个函数，你们认为可不可以？**

乍看一眼，你感觉应该是可以的，因为这个函数名不在同一个文件嘛。**但是实际上是不允许的。** 为什么不允许？因为大家都在同一个包下面，如果你叫 `calculate`，我也叫 `calculate`，那我在调用的时候，调这个函数名到底调谁？**编译器无法区分，因此这种写法一定是错的。**

一保存它马上提示错误信息：`calculate redeclared`，就是重复声明了，在你的 `utils` 这个文件的第九行，果然是提示信息。

所以我们再次强调：**在同一个包下不能有相同的函数名，当然也不能有相同的全局变量名。** 原因我说清楚了——**因为我们在调用的时候是用包名去点函数名，如果你这个包下面有相同的函数，显然它是无法区分的，从道理上也能够马上说清楚。**

### main 包只能有一个

> **结论**：**如果你要编译成一个可执行的文件，则需要将这个包声明为 `main`，也就是说 `package main`。而且我们的 `main` 包只能有一个。**

我们的可执行文件其实就是哪一个呢？就是 **`main` 函数所在的文件**。

这个是一个语法规范。如果你说的是**库文件**，则包名可以自定义，比如说前面刚才讲的像 `utils`——你这个地方不是 `main` 包，所以这个名字你可以自己来定义。**但是只有 `main` 包里面的这些文件，最终才能形成一个可执行文件。**

### 把源码变成可执行文件

大家看，刚才我们在使用的时候其实一直是用 `go run` 的。**我这样 `go run` 其实并不是一个很规范的使用方式**，纯粹是为了讲课方便。**但是实际上在真实的开发中，我们不可能去 `go run` 一个源代码**，我们是需要把这个源代码生成一个可执行文件，然后交给别人去使用。

思路非常简单：

- **编译的时候，首先切换到项目所在的目录**——不要在源码目录里编译，直接切换到我们的 `GOPATH` 路径下面去编译；
- **编译时需要编译 `main` 包所在的文件夹**，因为这样才能生成一个 `.exe` 文件。当然，如果你是在 Linux 下面，它也是要求在 `main` 包所在的文件夹去编译这个文件夹，才会生成一个可执行文件；
- 项目的组织结构最好按照规范来做——这个路径下面写一个 `src`，`src` 下面写我们的项目名称，项目名称下面才是我们的各个包。

我们演示一下。`cd ..` 一路退到 D 盘的 `go_project` 目录，也就是我们的 `GOPATH` 目录。然后来编译：

```bash
go build gocode/chapter06/funcdemo01/main
```

路径应该从哪里写？刚才我们已经讲过了，**从 `src` 下面的项目名称开始写**。

编译完过后我们看一下，此时此刻就生成了一个 **`main.exe`** 文件。这个文件你看很大，大概 **1.9 兆**——这个就是可执行文件了。我们把这个可执行文件交给需要使用的服务器或者交给我们的客户，那么他就可以运行它了。运行一下 `main.exe`，运行的效果跟原先是一样的。

当然，我们还可以指定自己的名字：

```bash
go build -o bin/my.exe gocode/chapter06/funcdemo01/main
```

`-o` 是什么意思呢？`-o` 代表输出，**输出什么呢？把可执行文件放到当前这个目录下面的 `bin` 目录下面，而且名字叫做 `my.exe`。**

有同学说老师你下面不是没有那个 `bin` 目录吗？**没有 `bin` 目录，它会自动帮我们生成。** 跑一下，此时此刻 `bin` 目录生成了，点进去看果然有个 `my.exe`。这个文件就是可执行文件，就是跟刚才是一样的，只是名字是由你自己指定的。

> **易错点**：不指定名字的话默认生成的是 `main.exe`。指定名字和目录要用 `-o`，而路径是相对 `GOPATH` 写的、不要带 `src`。

### 编译时还会偷偷生成一个库文件

还有一个细节我要再强调最后一点，**这个细节我就不记到笔记里面来了**，大家听我说。

当你编译完了过后，它还会生成一个文件，这个文件一般人没有注意到——**一个 `pkg` 文件夹**。点进去看一下，`chapter06`，进去——一个 `utils.a`。

这个文件我没见过呀。告诉大家，**这是一个库文件**。

什么意思呢？大家知道，我们这个项目本身有两个文件夹：一个是 `main` 包，一个是 `utils` 文件夹，也是 `utils` 这个包。这个包下面有一个 `utils.go` 文件，**当你编译完了过后，它会把这个文件里面的内容直接生成一个 `.a` 这么一个库文件。**

这个文件有什么好处呢？**这个文件你打开是看不到源代码的**——它仍然是个二进制码，一打开全是乱七八糟的东西，得用十六进制查看器才打得开，你是肯定看不懂的。

那它有什么用处呢？**Go 语言它会把你其他包的文件生成一个 `.a` 文件，这个文件你就可以把它当做一个库文件交给对方。** 比如说小明开发了一个工具库，**小明可以不把源文件交给对方，他直接把这个库文件交给小李；小李把这个文件引进去过后，看那个文档，就能够调这里面相应的函数。**

**相当于说是一个库文件。当别人要用的时候，你可以直接把这个库文件交给对方，对方就可以用里面写的函数了，包括你写的结构体、变量都可以用，你再给他出一份文档就 OK。**

关于这七点，我觉得只要你把它们都掌握了其实也够用了，其他东西也不用过多地研究，因为做项目里面我们只要注意到这七点足足都够了。

### 函数调用机制：一个特工小组的比喻

前面我们已经把函数的相互调用——怎么把一个函数放在一个文件里面，然后利用包的机制进行相互调用——说过了。现在我们要对函数做一些比较深入的探讨。

**函数的调用机制可以说是一个非常重要的知识点。如果同学们没有把调用机制搞清楚，那么后边咱们遇到递归、或者用到一些数据结构的东西的时候，大家会比较茫然。**

先找一个比较通俗易懂的方式。这里有拉登，拉登给特工小组下达一个命令说"炸掉白宫"。那么特工小组它能不能把白宫炸掉呢？最终它会返回一个结果给拉登同志。这里边就有一个下达命令、执行——就是我们的特工小组去执行，然后特工小组执行完了过后，会把结果返回给拉登。

**在程序里面我们怎么去理解呢？拉登就变成程序员了。程序员去调用方法，这个方法就是我们要去完成一个功能的一段代码的集合；然后方法执行完毕过后，会返回一个结果给程序员，或者说返回给调用者。**

这是一个比较通俗易懂的理解，**但是它不够深入，也不够本质**。现在我们换另外一种方式，深入到代码里面去，从代码执行的角度来分析函数的调用机制。

### 内存里的三块地方

在程序运行的时候，内存会被分成三个部分：

```text
┌──────────────────────────────────────────────────────────┐
│  代码区（Code）                                          │
│  存放指令本身。我们的 CPU 靠它知道要进行加减乘除        │
│  ——好比拍电影得有剧本                                    │
└──────────────────────────────────────────────────────────┘
┌───────────────────────────┐ ┌──────────────────────────┐
│  栈区（Stack）             │ │  堆区（Heap）            │
│                           │ │                          │
│  ┌─────────────────────┐  │ │  一般来说，引用数据类型   │
│  │  main 栈区          │  │ │  分配在堆区：             │
│  │    n1 = 10          │  │ │    map、切片 …           │
│  └──────────┬──────────┘  │ │  Java 里的"对象"也在这   │
│             │ 传入实参    │ │                          │
│  ┌──────────▼──────────┐  │ │  注意：Go 有逃逸分析，   │
│  │  test 栈区          │  │ │  基本类型也可能落到堆上   │
│  │    n1 = 10 → 11     │  │ │                          │
│  └─────────────────────┘  │ │                          │
└───────────────────────────┘ └──────────────────────────┘
```

- **栈区**一般来讲就是我们的函数在调用过程中、在执行过程中，基本数据变量是分配在栈区的。你可以理解成**基本数据类型一般来说分配到这个栈区**。
- **堆区**：一般来说，我们的**引用数据类型**一般分配在堆区。比如说你比如说 `map`，比如说我们的切片，后面大家用到的这些东西，它一般分配在堆区。你比如说你学过 Java，Java 语言里面的对象一般分配在堆区里面。
- **代码区**：听其名而知其意，我们本身这个代码在执行的过程中，它本身的计算机指令要存取。那我们的 CPU 怎么知道要进行加减乘除呢？就是因为你有代码。比方说刚才老师写的这样一些代码，它总得有个地方存——**你不存代码那计算机怎么知道要执行什么东西呢？这就好比我们人要去拍一个电影，你首先得有剧本吧，你没有剧本你怎么拍电影呢？**

> **易错点**：我这里说"一般"，是因为在 Go 语言里面，它的编译器有一个叫**逃逸分析**的特点，所以**不一定所有的基本数据类型都分配在栈区**。这个是 Go 语言的设计者 Ken Thompson 对编译器做了一个优化，后面加了逃逸分析。另外，老师画的这个区**不是物理上的划分，而是逻辑上的划分**。

### 案例一：两个都叫 n1 的变量

我们用一个最简单的例子：传入一个数，对这个数加一。关键不是说这个操作，而是说**我们在函数这个层面是怎么做的**。

```go
package main

import "fmt"

func test(n1 int) {
	n1 = n1 + 1
	fmt.Println("test() n1=", n1)
}

func main() {
	n1 := 10
	test(n1)
	fmt.Println("main() n1=", n1)
}
```

我在 `main` 里面**故意**也把它命名为 `n1`。为什么呢？**我就是让大家看到两个都有 `n1` 的时候，在底层的代码里面、在内存里面究竟是用一种什么样的机制来进行运算和操作的。** 你们看，这里有 `n1`，这里有 `n1`，这里还有两个 `n1`，大家是不是瞬间懵圈了？没关系，画个图大家马上就明白了。

先不运行，我们从内存的角度来分析，分析完了过后我们再执行。如果执行的结果和我们分析的结果相同，那就说明我们分析到位了。

#### 一张图看懂 n1 = 10 是怎么变出两个 n1 的

首先，当我的代码执行到 `n1 := 10` 的时候，**在栈区里面它会划分一个空间**，我用一个颜色来表示。你可以认为在这个栈区里面划分了一个 `main` 栈区——**这个是我给它取的名字，为了让大家比较容易理解，但实际上并没有说在内存里面真的存在这么一个玩意儿**。你可以理解成在 `main` 函数里面的基本数据类型都会在这里面分配空间。

此刻 `n1` 就分配了一个空间，它等于 10。也就是说第一句话执行完毕过之后，你可以认为在这个大的栈区里面有一个空间，里面有一个 `n1` 的变量，它对应的值是 10。

此时此刻，我们又调用了 `test(n1)`。**注意听这里，这个很重要了：根据我们操作系统的原理和它的机制规定，当一段代码去调用一个函数的时候，它会再开辟一个空间、或者说分配一个空间。** 这个空间还是逻辑的空间，你可以认为在这里又有一个空间，叫 `test` 栈区。

**在真实的内存里面是没有这个 `test` 栈区和 `main` 栈区的区分的**，底层的编译器里它怎么区分呢？它底层会有一种方式来区分这两个栈区的一个分界线。这一块因为涉及到编译原理和编译器的东西，这里就不展开讲述了。**你可以认为这两个数据空间是独立的，但同时都在栈区里面。**

代码跑到 `test(n1)` 这里的时候，它会把这个 `n1` 的值传给了 `test` 里面的这个 `n1`。此时此刻，在 `test` 的栈区里面也会存在一个 `n1`，它的值等于多少呢？**它就等于 `main` 这个 `n1` 里面传过来的这个值，换言之，也等于 10。**

但是同学们可以看到，**这两个 `n1` 虽然名字都叫 `n1`，但其实是独立的。** 这就好比在教室里面，有一个 A 教室，有一个 B 教室——**A 教室里面有个人叫三毛，B 教室也有个人叫三毛，他们名字虽然相同，但是人是不一样的**，一个是女的，一个是男的。

接下来它执行 `n1 = n1 + 1`，相当于说 `n1` 自己加了一把 1，变成 11。然后执行 `fmt.Println`，终端输出：

```text
test() n1= 11
```

**当它执行完这个函数的时候，注意听一个重要点**：`test` 函数执行完毕了，此时此刻编译器会怎么处理？**当它执行完毕过后，如果有返回语句则返回，没有返回语句那么这个就结束了**——执行完了就没了。它又回到原先这个位置，因为你原先是从这儿调用 `test` 的，当它执行完了过后它又回到这边来了。可以认为有一个 CPU 的东西在不停地进行调度。

回到这里过后，**此时此刻这个就消失在人间，没了。谁把它消失的？编译器会回收这个空间，因为你的栈已经没有用了。** 就好像我们用完一个工具，我们再把工具还给别人，那么手上就没有工具了。

当它回到这里来继续往下执行，输出 `main` 里面的 `n1`。**但是同学们注意，`main` 里面的 `n1` 还在呢？这个栈是不是还没死啊？没死。此时此刻这个地方 `n1` 它等于多少呢？等于 10。**

这句话执行完毕后，整个主函数也就执行完毕了。**整个主函数程序完毕过后，整个内存分配给它的、给这个应用程序分配的空间也就全部被回收了。**

所以运行结果就是两句话：

```text
test() n1= 11
main() n1= 10
```

跑一下，结果跟我们分析的完全一致。

> **结论**：这个图上有三句话需要同学们引起重视。
>
> - **第一点**：在调用一个函数时，会给该函数**分配一个新的空间**。编译器会通过自身的方式处理，让这个新的空间和原有的、其他的栈的空间**分界开来**。
> - **第二点**：在**每一个函数对应的栈中，它们的数据空间是独立的**，不会混淆在一起。当然有些同学会说老师如果说这里面有个引用变量呢？如果你传了个引用过去，那这个 `test` 和 `main` 它可能是指向同一个数据空间——这个我们后面再说，属于引用类型的时候再引出的东西。
> - **第三点**：当一个函数调用完毕（或者叫执行完毕）后，程序会**回收或者销毁这个函数对应的栈空间**。

只要记住这三句话，我们在理解函数上面就相对轻松了。

### 案例二：return 把结果带回来

第二个案例：编写一个函数，可以接收两个整数，求出它们的和并返回结果。

```go
package main

import "fmt"

func getSum(n1 int, n2 int) int {
	sum := n1 + n2
	return sum
}

func main() {
	sum := getSum(10, 20)
	fmt.Println("getSum里面的 sum=", sum)
	fmt.Println("main sum=", sum)
}
```

我既然要计算两个数的和，那我必须会有两个数，就是 `n1 int, n2 int`。因为我要把两个数算出来再返回去，因此我有个 `return`。

这两句话其实**完全可以合在一起**写成 `return n1 + n2`，就看你的习惯，无所谓高低。老师为了讲课方便，暂时用上面这种相对代码更清晰的方式。

`return` 怎么理解呢？回想那个图：**当它把这段代码执行完毕以后，如果有 `return` 语句，就会把这个 `return` 返回给调用者。**

> **定义**：**`return` 给谁？当函数有 `return` 语句时，就是将这个结果返回给调用者。也就是说——谁调用我，我就返回给谁。**

那想一想，你这是在这儿调用，我在这儿调用，我就相当于把这个结果返回到这个地方。所以你可以完全认为：10 和 20 放进去，它一加等于 30，那这个地方就应该输出 30。

这里跑起来的时候有个小问题：**我在 `return` 的时候这边少了一个东西，我有一个变量要写一下——这个地方就是要指定你返回的参数列表**，这个地方我要写的 `int` 是返回的参数列表。改好之后执行：

```text
getSum里面的 sum=30
main sum=30
```

**为什么这两个值又相同了呢？** 因为你在这个地方把结果返回给人家了嘛——你那儿是多少，我这儿也就是多少了。

### return 语句的基本语法

基本语法是这样的：`func` 是个关键字；函数名；形参列表——**就是我需要它传什么东西**；返回值类型列表——**你有哪些返回值类型给我写清楚**；然后这块就是语句，就是你这个函数要完成的功能；最后 `return` 语句，把返回的返回值列表给我写清楚，**如果这有多个，用逗号间隔就可以了**。

> **结论**：这里有两个细节需要同学们注意。
>
> - **第一点**：如果返回多个值，在接收的时候，**希望忽略某个返回值，可以用下划线符号 `_` 来表示占位**。
> - **第二点**：如果返回值只有一个，**这个括号可以不写**；但是如果有多个，**必须要写括号**。
>
> 刚才老师这个地方其实是有返回值的，你看这里面就没有写括号，但是你写上也可以——我把它括起来过后再执行，同学们可以看到没有任何毛病，它仍然是可以的。因为只有一个，一般来讲我们出于这种编程的习惯，Go 的开发者一般就不写了，**但是有多个就必须要写了**。

> **提示**：Go 函数中支持返回多个值，这一点其他编程语言是没有的。其他的编程语言里面要返回多个值，往往通过数组来实现这个效果；但在 Go 语言里面，它是可以直接支持返回多个值的。

#### 返回两个值

案例：请编写一个函数，可以计算两个数的和、差，并返回结果。

这时候其实就是要返回几个值了呀？两个值，那这个时候我们就跟刚才的写法要有一点区别了：

```go
package main

import "fmt"

func getSumAndSub(n1 int, n2 int) (int, int) {
	sum := n1 + n2
	sub := n1 - n2
	return sum, sub
}

func main() {
	res1, res2 := getSumAndSub(1, 2)
	fmt.Printf("res1=%v res2=%v\n", res1, res2)

	// 只想取差，不想取和：用下划线占位
	var result3 int
	result3, _ = getSumAndSub(3, 9)
	fmt.Println("result3=", result3)
}
```

我这边都叫 `n1`、`n2`，大家看到**因为他有不同的栈空间**。我要返回两个值，所以说用 `(int, int)` 分开，**这个地方就必须要打括号了**。

调用非常简单：`res1` 逗号 `res2`，等于 `getSumAndSub`，传入 1 和 2。**第一个返回值交给 `res1`，第二个返回值交给 `res2`。** 所以 `res1` 等于和，应该等于 3；`res2` 等于 $1 - 2 = -1$。

执行一下，我们可以看到 `res1 = 3`，而 `res2 = -1`，跟我们分析的完全一样。

#### 只想拿其中一个值怎么办

有个细节要多说一句：**有时候你可能只想要其中的一个值。** 比如说你返回的是一个和 `sum`，还有一个差 `sub`——但是有可能我只要和，不要差；或者只要差，不要和。

这时候就**可以使用下划线来占位，希望忽略某个值**。

如果我只想取差，不想要和：再调用一次，写成 `result3, _ = getSumAndSub(3, 9)`。**大家知道函数可以反复调用**，这个时候语法也没有报错。跑起来，`result3` 就应该等于 **-6**，没毛病。

有些同学问老师，如果我两个都不想要呢？也可以这么调用。**但是这样没有意义**——这样写就等价于调用了不要值嘛。所以我只是说这个说法也可以这样去用。

> **结论**：关于函数的调用机制，我强调的就是这个图很重要，**你一定要把这个图搞得明白一点**。核心就是那三句话——调用时分配新空间；每个函数对应的栈中数据空间是独立的、不会混淆；函数执行完毕后，该函数对应的栈空间就被回收了。

关于函数的调用机制，我就给大家介绍到这里。

## 递归调用：函数在自己体内再调用自己
> 对应块：BLK40 | 覆盖分集：P116 | 块标题（分集名）：《115_尚硅谷_递归调用流程分析》

我们下面来探讨一下函数的递归调用。

**函数的递归调用也是我们在学函数调用的时候一个非常重要的内容**，尤其是后面如果同学们在学的时候会学到一些数据结构——**在数据结构里面，递归就是一个特别重要的知识**。

### 一个只有几行的例子

> **定义**：**什么叫递归调用呢？就是一个函数在函数体内调用了本身，调用了本身，我们就称为递归调用。**

你看这里有一个 `test` 函数，它在这个地方又调用了一个 `test`。**在 `test` 函数里面又调用 `test`，这个我们就称之为递归调用。**

如果它是在函数内调用了别的函数，这个好理解；**调用自己，你会突然发现有点转不过来了，是不是？**

新建一个文件夹 `func_demo03`，新建一个 `main.go`，`package main`、`import "fmt"`，然后给它一个主函数：

```go
package main

import "fmt"

func test(n int) {
	if n > 2 {
		n--
		test(n)
	}
	fmt.Println("n=", n)
}

func main() {
	test(4)
}
```

这段代码非常的简单。这有一个函数叫 `test`，它可以接收一个整数。如果 `n` 大于 2，就 `n--`，然后 `test(n)`。然后我在下面输出 `n` 等于多少。

我在主函数这里调用的时候是这样调用的：`test(4)`。

**现在我想请问输出什么内容？** 如果同学们现在正在听，你可以先暂停视频，先思考一下这个问题。

我们还是老规矩，把这段代码放在 Excel 表里面进行分析。**分析完了过后，我们看看输出的结果跟我们分析的结果是否相同，从而证明我们对递归调用的理解是否一样。**

### 逐帧走一遍栈

因为我们这只涉及到栈，所以老师画的时候稍微画的简单一点，就直接画一个栈就可以了。堆区还有代码区暂且不画，因为我空间有限。这个栈区空间比较大一点，所以我把它往上面挪一下。

代码从主函数开始执行。从 `main` 一执行，就会在栈区里面为我们的主函数开辟一个空间——**主栈**。在里面调用了一个函数叫 `test(4)`。

**根据前面讲的底层原理，当我们的程序去调用一个函数时，就会开辟一个新的空间。** 新的空间我们画在上面，因为**栈的规则是先入后出**。

```text
┌──────────────────┐
│    main 栈        │
│   调用 test(4)   │
└────────┬─────────┘
         │ 调用
         ▼
┌──────────────────┐
│    test 栈       │   n = 4
│   n > 2 ?  成立  │
│   n--  →  n = 3  │
│   ↓ 打印还没执行 │
└────────┬─────────┘
         │ test(3)   ← 下面打印语句先不执行
         ▼
┌──────────────────┐
│    test 栈       │   n = 3
│   n > 2 ?  成立  │
│   n--  →  n = 2  │
│   ↓ 打印还没执行 │
└────────┬─────────┘
         │ test(2)
         ▼
┌──────────────────┐
│    test 栈       │   n = 2
│   n > 2 ?  不成立 │
│  ✅ 打印 n = 2    │   ← 最先输出
└────────┬─────────┘
         │ return（该栈销毁）
         ▼
┌──────────────────┐
│    test 栈       │   n 仍是 2
│  ✅ 打印 n = 2    │   ← 第二个输出
└────────┬─────────┘
         │ return（该栈销毁）
         ▼
┌──────────────────┐
│    test 栈       │   n 仍是 3
│  ✅ 打印 n = 3    │   ← 第三个输出
└────────┬─────────┘
         │ return（该栈销毁）
         ▼
     main 栈销毁，程序结束
```

跟着这张图一步一步走：

`n` 等于 4，执行 `if n > 2`，显然成立，于是进来执行 `n--`，**4 变成 3**。变成 3 过后，它又执行了一个 `test`。**注意：下面还有一个打印语句，现在执行到这儿了，还没有执行到它。**

执行到 `test(3)`，根据我们以前的规则，它继续开辟一个新栈、一个新的独立空间。在这里面 `n` 就应该是 2。

**这个时候，在这个栈里面，下面代码先不执行了，它先去执行上面这个栈的内容。**

同样到这个栈里面，它也有 `if n > 2`。这个时候 `n` 大于 2 还成立吗？不成立了。因为传进去的是 3。$3 > 2$ 成立，于是它执行这个函数里面的 `n--`，**变成 2**。变成 2 过后，它又去调用了一个 `test(2)`。

**下面还有一句话没有执行，下面这句话还等待执行。**

`test(2)` 又开辟一个新栈。在这里面传进来的仍然是 2，`n` 就是 2。**此时此刻 `n` 大于 2 已经不成立了**，所以它就直接执行这个 `fmt` 里面的输出语句——**在这个栈里面这个 `n` 等于多少呢？是不是 `n` 等于 2？所以说在这地方马上就会输出一个 `n = 2`。**

输出 `n = 2` 过后，这个 `test` 栈就执行完毕了。**它返回来，它会返回到这儿来——因为你是从这调进去的嘛，它本身就是从这开始执行调用才开辟的这个新的 test 栈。所以它又回来，回来的时候这个栈就消失了，没了。**

回到这个地方以后，下面这个 `if` 语句还执行吗？**因为他已经进到 `if` 语句里面了，所以他执行完了 `if` 又出来，出来就执行这里面的话。** 这个时候 `n` 还是等于 2，所以说它仍然输出 2。输出完了过后这个栈就执行完毕了，它又回到 `test(3)`。这个也没有了过后，他又回到这儿，回到这个地方执行——因为这个调用完毕，执行到这儿，然后又开始执行下面这句话，`n` 等于多少呢？**是不是 $n = 3$？因为这里还保留着这个 3 这个值。**

$n = 3$ 完了过后，这个栈也就不存在了。最后回到 `test(4)`，整个执行完毕，这个栈也就没有了。

**因此这里面的结果应该是 $n = 2$、$n = 2$、$n = 3$，就 2 2 3。**

> **提示**：第一次跑的时候没有输出结果，为什么？因为**我们没有保存这段代码**。重新保存再执行，效果就是 2 2 3，跟老师分析的结果完全一致。

### 只改一个 else，结果完全变了

第一个案例是一个初步入门，第二个案例我看同学们能不能真正地理解。我们再写一段代码，这段代码就是在上面代码做一个微微的调整，改写成 `test2`。**唯一我就改变了一个位置，叫 `else`，其他我没有做任何变化。**

```go
package main

import "fmt"

func test2(n int) {
	if n > 2 {
		n--
		test2(n)
	} else {
		fmt.Println("n=", n)
	}
}

func main() {
	test2(4)
}
```

**如果我把这段代码的调用改成了这样一种形式，请同学们思考一下输出结果是什么？**

你乍看一眼："老师，上面这段代码调的是 `test`，现在这段代码调的是 `test2`，好像没什么变化呀？" **但是你看，我这有 `else` 了。** 这方就是考验大家有没有真正把这一个函数的调用搞明白。

还是调 `main` 栈，第一次进来传的仍然是 4，$n > 2$ 成立，于是执行 `n--`，**本栈的这个变成 3**。执行完毕 `test2(3)`，把 3 传进去，这边 $n > 2$ 成立，于是又 `n--`，变成 2。

**这变成 2 的时候，这个 $n$ 大家看，$n > 2$ 吗？显然不大于 2，于是它执行它的这个 `else` 语句。**

因为传的是 2，所以它是 2。$2 > 2$ 不成立，于是执行 `else`。**在这个栈里面，这个灰色的部分会输出一个 $n = 2$。** 这个没有毛病，因为你 `n` 就是等于 2，2 不大于 2，所以它输出 `else`。

它执行完毕过后，这个也销毁了。

**那么这个时候，`else` 语句还会执行吗？显然不执行。** 因为你刚才进去的时候是从这个 `if` 里面进去的。**所以这句话是不会输出的**——相当于什么都没有输出，直接就走了。同样，这边也是从 `if` 里面进去的，于是他这里的 `else` 也是不会执行的，因为它是 `else` 的关系。**所以最后结果只有一个：$n = 2$。**

> **结论**：完全不一样。**因为你的语法发生了变化，你的结构是 if-else 结构。** 说白了就是这个地方会输出一个 2，下方什么都不会输出。

执行一下，结果就是 $n = 2$，没有别的，跟老师分析的完全一样。

> **提示**：分析示意图上唯一跟原先的区别，就是因为在这里它的语法是 `else` 的结构，if-else。**其实也就是最上面这个栈它直接进入到 `else` 了**；其他的栈在退回的时候，因为它执行的是 `if` 分支，所以 `else` 这个分支就不执行。
>
> 我为什么把这个图保留下来呢？**保留下来的目的就是希望同学们能够看到这个流程是什么样子的。** 这个图本身在返回的时候，**这个栈其实就已经被销毁了**，但是因为我想让大家看到这个来龙去脉，所以我就没有删除。

### 递归调用的四条铁律

我们总结四句话，这四点特别的重要，希望同学们引起重视。

> **第一句话**：**执行一个函数时就会创建一个新的受保护的独立空间**，也就是我们可以理解成是一个新的函数栈。
>
> 比如刚才画的这个图，`test2` 栈这边也都是 `test2` 栈。**它每调用一次函数，就会产生一个新的空间**。因为它们之间的数据是完全独立的，它们要执行的代码也是完全独立的。

> **第二句话**：**函数的局部变量是独立的，互相不受影响，不会相互影响。**
>
> 比如刚才老师画的这个图，这有一个 `n`，上面这个也叫 `n`，没毛病。**因为它们是相互独立的，不要认为它们是同一个。** 它们名字虽然相同，但是因为它们数据空间是独立的，因此它们的变量其实每一个栈里面都有一个独立的、完全不一样的，只是它们名字刚好都叫 `n`。

> **第三句话**：**递归必须向退出递归的条件逼近，否则就是一个无限循环，变成一个死递归了。**
>
> 这个怎么理解呢？同学们看我的代码里有一个 `n--`，这个特别的重要。**如果说我把这个 `n--` 去掉，会出现一个什么情况？** `test(4)` 进去过后 $n > 2$ 成立，就调 `test(2)`；`test(2)` 又去调，它发现 $n > 2$ 又调，是不是就一直死在里面出不来了？
>
> **为什么呢？因为你的 `n` 永远都是 4，它永远都大于 2，于是它就不停地往里面跑，死在里面了，成了一个无限的调用，这就是死递归。**
>
> 当然你这里也不能写成 `n++`，`n++` 那更可怕，它永远都是大于 2 的，也出不来。**这个地方是特别重要的一点。**

> **第四句话**：**当一个函数执行完毕，或者遇到 `return` 时就会返回，遵守谁调用就将结果返回给谁。** 哪一个人调用，我就把这个结果返回给谁，这个在前面已经阐述过了。同时，**当函数执行完毕或者返回时，该函数本身也会被销毁**——你可以认为是编译器销毁的，也可以认为是系统销毁的，这个无所谓，**这个栈的空间就被释放出来了**。

这四点特别的重要。这以上就是关于递归调用的一个说明和介绍，下面我们就来做一些关于递归调用的案例和课堂练习，加深对递归调用的理解。

### 本讲提到的思考题

#### 思考题一：`test(4)` 输出什么

**题干**：给定 `func test(n int) { if n > 2 { n--; test(n) }; fmt.Println("n=", n) }`，在 `main` 中调用 `test(4)`，问这段代码输出什么内容。

**解析**：`test(4)` 的栈里 `n = 4`，条件成立，`n--` 后为 3，递归调用 `test(3)`；`test(3)` 的栈里 `n = 3`，条件成立，`n--` 后为 2，递归调用 `test(2)`；`test(2)` 的栈里 `n = 2`，条件不成立，直接打印 `n = 2`。该栈销毁回退到 `test(3)` 的栈，执行打印语句，此处 `n` 仍是 2，输出 `n = 2`；再回退到 `test(4)` 的栈，此处 `n` 已被 `n--` 改成 3，输出 `n = 3`。

**答案**：输出依次为 `n= 2`、`n= 2`、`n= 3`，即 **2 2 3**。

#### 思考题二：把 `Println` 挪进 `else` 后输出什么

**题干**：把上面代码改写成 `func test2(n int) { if n > 2 { n--; test2(n) } else { fmt.Println("n=", n) } }`，在 `main` 中调用 `test2(4)`，问输出什么。

**解析**：`test2(4)` 进入后 $n = 4$，条件成立，`n--` 后为 3，递归 `test2(3)`；`test2(3)` 的栈里 $n = 3$，条件成立，`n--` 后为 2，递归 `test2(2)`；`test2(2)` 的栈里 $n = 2$，条件不成立，执行 `else`，输出 `n = 2`。该栈销毁后回退的两层，都是从 `if` 分支进来的，**`else` 分支不再执行**，所以没有任何输出。

**答案**：只输出一行 **n = 2**。与上一题的本质差异在于：上一层是通过 `if` 分支进来的，返回后 `if` 与 `else` 互斥，`else` 那条语句根本不参与执行。

### 斐波那契数：最经典的那一题

第一个练习，斐波那契。它太经典了，经典到几乎成了"递归"二字的代名词。

题目要求很简单：使用递归的方式求出斐波那契数。

**什么是斐波那契数？** 第一个数是 1，第二个数也是 1，第三个数开始是前面两个数的和。第一个和第二个是固定好的——1，1；第三个数就是第一个加第二个；第四个数是它前两个数的和；第五个数、第六个数同样是以此类推。

给你一个整数 $n$，求出它的斐波那契数是多少。

#### 思路怎么落地

两条，一条比一条短：

- 当 $n = 1$ 或者 $n = 2$ 时，返回 1。为什么？因为 $n=1$、$n=2$ 的时候它的斐波那契数就是 1，这已经是我们定义好的起点。
- 当 $n \ge 2$ 时，返回前面两个数的和。说白了就是 $f(n-1) + f(n-2)$——假设 $f$ 就是那个函数的话。

> **易错点**：这里写的是等号 `==`，不能手滑写成赋值 `=`。

#### 代码

```go
func fbn(n int) int {
	if n == 1 || n == 2 {
		return 1
	} else {
		return fbn(n-1) + fbn(n-2)
	}
}
```

`else` 那一支就是分析里的第二条。注意这里我们的前提是 $n$ 是一个大于等于 1 的整数。

#### 验证

测试的时候不要一上来就挑大数，先找几个简单的试：

```go
func main() {
	res := fbn(3)
	fmt.Println("res=", res)
}
```

运行结果 `res= 2`，对的，$1+1=2$。

再测一组：

```go
fmt.Println("res=", fbn(4))
fmt.Println("res=", fbn(5))
fmt.Println("res=", fbn(6))
```

输出是 **2、3、5、8**。完全正确。$f(4)=3$、$f(5)=5$、$f(6)=8$，都对得上。

通过这个练习，斐波那契就被我们用递归的方式完成了。代码非常简单，这就是第一个练习。

### 当题目把算式直接给了你：$f(1)=3$，$f(n)=2f(n-1)+1$

第二个练习难度其实不高，因为它几乎就把答案告诉你了：已知 $f(1) = 3$，当传入一个 $n$（这里 $n$ 肯定大于 1 了）的时候，返回 $2 \times f(n-1) + 1$。用递归的思想编程，求出 $f(n)$ 的值。

这题连分析都省了，人家已经把函数的表达式给你了，你把它翻译成递归调用的代码就 OK 了，几乎没难度。

做递归最重要的事情是什么？**就是要拿到这个函数的表达式。** 现在表达式已经在纸面上了，直接用就完了。

```go
func f(n int) int {
	if n == 1 {
		return 3
	} else {
		return 2*f(n-1) + 1
	}
}
```

$n = 1$ 就 `return 3`；不是 1 就走 `else`，直接把算式拿过来用——`2*f(n-1) + 1` 里面不就已经有一个递归调用了吗？既然有 `return`，前面还有一个返回值列表，只有一个值，所以直接写个 `int` 完事。

测试：

```go
func main() {
	fmt.Println("f(1)=", f(1))
	fmt.Println("f(5)=", f(5))
}
```

跑起来看效果：$f(1) = 3$，$f(5) = 63$。同学们可以自己去试一下，一定是正确的，因为我们完全是按照题的要求来完成的。

### 猴子吃桃子：方向反过来的递归

下面还有一个题，难度也还可以，不是很难，我一开始想让大家自己先想一想，再来讲。这道题是三道里唯一一道需要自己转个弯的。

题目要求：有一堆桃子，猴子第一天吃掉了其中的一半，并再多吃了一个。以后猴子每天都吃其中的一半，然后再多吃一个。到第十天的时候，再想吃的时候（这个时候还没有吃），发现只有一个桃子了。问最初共有多少个桃子？

注意问的是"第一天还没吃的时候"有多少桃子。

#### 关键转折：从最后一天往前推

我们先看题目的要求，找出那句决定性的话：**到第十天想吃的时候，只有一个桃子了。** 于是我们得出结论——第十天只有一个桃子。

问题来了：它第九天有多少个桃子呢？

这是**反过来推**的。我现在不知道第一天有多少个，但我知道最后这一天，也就是第十天有一个桃子。那反过来，第九天有几个？

第九天的桃子数量等于第十天的桃子数量加上一个 1，括起来，再乘以 2。

> 为什么这么说？如果第九天有这么多桃子，第九天它吃的时候先吃掉一半，然后再吃掉一个，不就正好变成第十天的桃子了吗？所以要求前一天的桃子数量，实际上是它下一天桃子数量加 1 乘以 2。

规律找到了：第 $n$ 天的桃子数量，假设用 `peach` 表示，它应该等于下一天的桃子数量加上一个 1，括起来，再乘以 2：

$$\text{peach}(n) = (\text{peach}(n + 1) + 1) \times 2$$

因为它是从最后一天往前推，所以这里是 $n + 1$——**注意这里的 $n+1$，别写顺手写成 $n-1$**，那样就变成正推了。

#### 代码

```go
package main

import (
	"fmt"
)

func peach(n int) int {
	if n > 10 || n < 1 {
		fmt.Println("输入的天数不对")
		return 0
	}
	if n == 10 {
		return 1
	} else {
		return (peach(n + 1) + 1) * 2
	}
}

func main() {
	fmt.Println("第一天的桃子数量是：", peach(1))
}
```

这里 $n$ 的范围是有要求的，它是 1 到 10 之间。如果我们想写得更完整一点，就可以像上面这样：如果 $n > 10$ 或者 $n < 1$，不在这个范围，就直接提示一句"输入的天数不对"，然后返回 0，表示没有得到正确的数量。

运行代码，可以看到第一天桃子数是 **1534** 个。这个猴子还真是挺能吃的，第一天就造了这么多桃子。

再测几个数据验证一下：`peach(10)` 结果是一个桃子；`peach(9)` 就应该是四个桃子——第九天四个桃子，吃了一半剩两个，再吃一个，不就正好剩一个了吗？再输入一个 11，它直接输出"输入的天数不对"，桃子数为 0。

我们真正要求的就是第一天，算出来的结果是 1534。

> **结论**：关于猴子吃桃子用递归来解决的整个分析，包括代码，就介绍到这里。希望同学们不看笔记也能自己做出来，达到这样一个效果才是正确的。

### 函数使用的注意事项和细节（上）：形参、作用域与传参

下面我们再来看一下函数在使用的时候需要注意的事项以及它的一些细节讨论。

要讲的点比较多，我大概总结了有 **13 个点**，所以我们把它分成两个部分展开讲述。前面有一些其实是已经讲过的，这里再系统地过一遍；还有一些没讲到的，我会举一个案例给大家详细介绍。

前三点没有什么可说的，扫一遍就行：

- **第一，函数的形参列表可以是多个的**，返回值列表也可以是多个，返回值可以是多个的。前面我们写过一个函数，让它返回了两个数的和，同时也返回了两个数的差，这就是返回值列表可以为多个的说明。
- **第二，形参列表和返回值列表的数据类型可以是值类型，也可以是引用类型**。返回的类型可以是任意的，没有什么限定：可以是整数，可以是字符串，可以是一个 map，也可以是一个数组。
- **第三，函数的命名规范还是按我们以前说的命名规范来做**，还有一点就是**首字母不能是数字**，这个在讲标识符命名规范的时候已经提过了。

第三点还有一个特别重要的补充：**首字母大写，则该函数可以被本包文件和其他包文件使用**。我们在讲"包的注意事项和细节"的第三点提到过这个概念——为了让其他包文件可以访问到本包的函数，函数名的首字母需要大写，类似于其他语言的 `public`，这样就能跨包了。如果函数的首字母是小写的，则只能被本包文件使用，类似于 `private`。这个案例我就不再举了，前面咱们已经讲过了，再反复说也没有意义；忘的同学打开笔记的第三点，那里做了详细的介绍。

#### 函数中的变量是局部的

第四点：函数中的变量是局部的，函数外不生效。这个我举个例子说明一下。

```go
package main

import "fmt"

func test() {
	// n1是test函数的局部变量，只能在test函数中使用
	var n1 int = 10
}

func main() {
	// 这里不能使用n1，因为n1是test函数的局部变量
	// fmt.Println("n1 =", n1)
}
```

`n1` 的作用范围只能在 `test` 里面，在别的地方用不了。也就是说，如果我们在 `main` 函数里面使用这个 `n1`，是会报错的。

保存过后它提示了一个错误：**undefined: n1**。

> **易错点**：这一条其实在我们前面讲函数调用机制的时候就已经体现出这个特点了，有些同学可以根据原理去推导，不是每一次都要老师讲一遍，但是需要提的时候还是要说。你在 `main` 里用不了 `n1`，这么用肯定要报错。

#### 值传递：函数内改不动外面的值

第五个细节，这个点有点意思：**基本数据类型和数组默认都是值传递，即进行值拷贝，在函数内修改不会影响到原来的值。**

基本数据类型是值传递，这个很好理解。但是有些同学就说了："老师，那个数组不是我们现在还没学吗？那你这先提这个干什么呢？"

因为有些听视频的同学是有编程基础的。在其他的编程语言里面，数组往往都是引用类型的，比如 Java——Java 在传递的时候是引用传递，所以它在函数内是可以修改到函数外的数组的。

> **注意**：在 Go 语言里面，基本数据类型和数组都是值传递，**它不是引用传递**，那么在函数内修改不会影响到原来的值。讲过 Java 的同学一定要把这个观念倒过来。

因为数组大家还没有使用过，所以这个地方我先把这个结论抛给大家，讲到数组的时候我们再举例。先看一个基本数据类型的案例，其实前面已经讲过了，这里再系统地说一遍：

```go
package main

import "fmt"

func test02(n1 int) {
	n1 = n1 + 10
	fmt.Println("test02() n1 =", n1)
}

func main() {
	var num int = 20
	test02(num)
	fmt.Println("main() num =", num)
}
```

我在主函数里面定义了一个变量 `num = 20`，传给了 `test02` 里面的 `n1`。根据前面咱们讲解的函数调用机制而言，会开辟一个新的栈，叫 `test02` 这个栈，里面会有一个新的变量 `n1`，因此这个 `n1` 的变化不会影响到外面——**它们两个是独立的**。

跑起来看一下效果，两个值是完全不一样的：`test02` 里面加了个 10 变成了 30，但是 `main` 函数里面的仍然是 20。所谓值拷贝就是说，它会把 `num` 的 20 拷贝给 `test02` 里面的 `n1`，它们两个是不同的变量；在函数内加 10 改变的是 `test02` 里面的 `n1`，因此对 `num` 没有任何影响。

基本数据类型包括数组，都是以这种值拷贝的方式来进行参数传递的。

#### 传地址：把值传递变成引用效果

第六个细节：**如果我们真的希望函数内的变量能够修改函数外的变量，可以传入地址，函数内以指针的方式来操作变量**，从效果上来看类似于引用传递。

这里我指的是默认以值传递方式的数据类型，比如前面讲的基本数据类型和数组。如果本身就是引用传递，那当然本身就可以直接修改了。

怎么写呢？我把上面的代码做一个修改，写个 `test03`：

```go
package main

import "fmt"

func test03(n1 *int) {
	*n1 = *n1 + 10
	fmt.Println("test03 中的 n1 = ", *n1)
}

func main() {
	var number int = 20
	fmt.Printf("number 的地址 = %v\n", &number)
	test03(&number)
	fmt.Println("main 中的 number = ", number)
}
```

这里的关键就三处：形参变成 `*int`（指针类型），调用时传的是 `&number`（传地址进去），函数内取的时候要写 `*n1 = *n1 + 10`。

> 关于指针的这两个操作符我讲过：一个是**取地址符 `&`**，一个是**取指针指向那个值的运算符 `*`**。

跑起来，两个都变成 30 了——原先一个 30 一个 20，现在都是 30。为什么？因为传的是地址，它们操作的就是同一块数据空间。

##### 一张图说明原理

我把这个原理画一次，后面就不反复画了，姑且只用栈区来示意：

```text
   main 栈                          test03 栈
┌──────────────────┐              ┌──────────────────┐
│ number = 20      │              │ n1  (*int)       │
│   地址 A         │◄─────────────┤   存的值 = 地址 A │
└──────────────────┘              └──────────────────┘
        ▲                                  │
        └──────────────────────────────────┘
             n1 指向 number，两者操作同一块空间

  test03(&number)  →  n1 里装的就是 &number 本身
  *n1 = *n1 + 10   →  直接把 number 那块空间的 20 改成 30
  test03 返回       →  test03 栈销毁，但 number 已经是 30
```

有几个细节值得专门说：

- **就算是一个基本数据类型，它也有地址。** 用 `fmt.Printf("%v
", &number)` 就能把 `number` 的地址打出来看。
- **`n1` 自己也有地址。** 它是指针类型，但它本身也有存放空间，也可以用 `&n1` 打印出来。显然这两个地址肯定是不一样的——一个是 `n1` 自己存放的地方的地址，一个是它里面存的、指向 `number` 的地址。类似于：指针类型 `n1` 有一个空间，这个空间里放了另外一个地址，那个地址指向 `number`。
- **`*n1` 就是访问到那个 20。** 星号代表取值，取谁的值？取它存的这个地址所指向的那个值，那就是 20。加个 10 改变它，就是直接改掉了 `number` 那块空间。

关于执行顺序：进入 `test03` 之后，`*n1` 打印出的是 30（`test03 中的 n1 = 30`）；执行完毕，函数回到 `main` 栈，继续执行那句打印 `number` 的语句——因为它就是个普通的基本数据类型，不需要取值符号，直接输出，而它现在已经是 30 了（`main 中的 number = 30`）。

> 这个图很关键，不是老师自夸。你把它理解透彻了，说白了就是把传值和函数调用机制理解得比前面还透一点。这张图也一并放到笔记里面。

#### Go 不支持传统的函数重载

最后一点，第七点，也是非常重要的一点：**在 Go 函数里面不支持函数的重载。**

为什么要单独提这一句话？因为有很多编程语言是支持函数重载的。那什么叫函数重载？对于初学者可能还没有太多认识，我举个例子：

```go
func test02(n1 int) {
}

func test02(n1 int, n2 int) {
}
```

很多编程语言里面，函数名可以相同，只要形参的个数或者数据类型不同，它就认为这是不同的函数，能区分开。

但是我告诉大家，**这种所谓的重载，在 Go 语言里面是不支持的**。你保存一下，它马上就会报错——**function test02 redeclared in this block**。

> **易错点**：Go 会认为这两个 `test02` 是同一个函数，报一个重复定义的错误。记住一句话就行：Go 语言里面不支持传统的函数重载，这种写法是错的。

为什么 Go 不需要？因为后面我们会讲，Go 语言是支持**可变参数**的，而且它还有一个叫做**空接口**的东西，其实它完全可以达到这种效果。也就是说，Go 语言是用另外一种形式来实现这种函数重载的。

关于第一部分的函数使用细节和注意事项，先给大家介绍到这里，后面我们再说其他的。

### 函数本身就是一个数据类型

先明确第八点：**在 Go 中，函数也是一种数据类型。**

就是说函数本身可以赋给一个变量，该变量就是一个函数类型的变量。Go 函数本身也是一种数据类型，它的地位和我们的 `int`、`string` 是一样的，都是数据类型。

怎么来体现这一点？看个例子。我们写一个函数，就是求两个数的和：

```go
func getSum(n1 int, n2 int) int {
	return n1 + n2
}
```

`n1 int`、`n2 int`，返回一个 `int` 值，非常简单。但是我这里想说的是**函数本身是一种类型**，怎么来体现呢？注意看效果。

假设我这里有一个 `a` 变量，我把 `getSum` 这个函数直接赋给它：

```go
func main() {
	a := getSum

	// 看看它们各自是什么类型
	fmt.Printf("%T\n", a)
	fmt.Printf("%T\n", getSum)

	// 通过变量调用函数
	res := a(10, 40)
	fmt.Printf("res = %v\n", res)
}
```

跑起来：`a` 的数据类型打印出来就是一个函数类型，`getSum` 的类型也是这个——因为它们两个是一样的，你已经把 `getSum` 交给了 `a`，所以它们其实**都指向了同一块代码空间**。

然后我们还能通过该变量实现对函数的调用：

```go
res := a(10, 40)
```

这跟 `res := getSum(10, 40)` 是完全等价的，输出 `res = 50`。

> **结论**：在 Go 里面，函数也是一种数据类型，我们可以把这个函数交给另外一个变量，并且通过该变量来完成调用。这个特性后面还会用到，比如在讲**闭包**的时候，我们还会用到这个特点。

---

### 把函数本身当形参传进去

既然函数是数据类型，那第九点就顺理成章了：**函数既然是一种数据类型，因此在 Go 中，函数可以作为形参，并且调用。**

有点意思了。就是说我们前面的形参数据类型基本上就是基本数据类型，虽然也可能是引用类型，但把函数本身当做一个形参传过去，好像还真没有用过。

这次我们直接在前面这个案例上来玩一把。写一个函数，把函数当形参来接收：

```go
func myFun(funvar func(int, int) int, number1 int, number2 int) int {
	return funvar(number1, number2)
}
```

这里面的要点：

- `funvar func(int, int) int`——`funcvar` 这个形参的数据类型是一个函数类型。我们前面不是把 `getSum` 的类型用 `%T` 打印出来了吗？`funvar` 的数据类型就是它。
- `number1`、`number2` 传两个整型过来。
- 函数体里直接 `return funvar(number1, number2)`。既然我们能把一个函数交给一个变量，那同样也可以把一个函数交给一个形参，通过形参来调用它。

调用的时候：

```go
res2 := myFun(getSum, 50, 60)
fmt.Printf("res2 = %v\n", res2)
```

这个流程大家再想一想：把 `getSum` 这个函数交给了形参 `funvar`，再把 50 和 60 分别传给 `number1` 和 `number2`。此时 `funvar` 就是 `getSum` 这个函数了，调用的时候把这两个值传进去，50 加 60 等于 110，`return` 返回给 `res2`。所以 `res2` 等于 **110**，跟分析完全一样。

> **易错点**：我再多问一句，如果我把那个冒号（`:=`）去掉行不行？不行。因为这样就相当于把返回值直接交给 `res2`，可是 `res2` 你根本没有定义，这样肯定会报错，它会报告 `res2` 没有定义。如果你一定要这么用——有些同学第一次接触 Go 语言，对这个语法不熟悉——你可以先写 `var res2 int`，先定义了，再把值赋给它。但是这样写有点麻烦，所以我一般来讲就直接用类型推导，就完事了。

---

### 自定义数据类型：给类型取个别名

第十个细节：**为了简化数据类型的定义，Go 支持自定义数据类型。**

这一点在很多语言里面是没有的。Go 支持它——其实这个是 C 语言里面的一种语法现象，被它拿过来直接用了，还是比较好的。

它的基本语法是：

```go
type 自定义数据类型名 数据类型
```

你可以理解成好像给它取了一个别名。比如第一个案例 `type myInt int`，这就相当于说 `myInt` 就等价于 `int` 了。同样，我也可以把一个函数类型定义成一个名字，比如 `type mySum func(int, int) int`，这时 `mySum` 就等价于一个函数类型——这个类型不就是你写的这个吗？非常简单。

这个用法我们后面用得是非常多的，尤其是有些同学刚刚接触 Go 语言，还不太清楚这是怎么回事，大家认真听。

#### 一个很怪的点：`myInt` 和 `int` 不是同一个类型

我把这个点专门拎出来说，因为它第一眼看着很不合理。在 Go 语言里面来看，`int` 和 `myInt` **不是同一个类型**——你不能完全把它等价于同一个，Go 认为这两个还是不同的数据类型，一个叫 `myInt`，一个叫 `int`。

这有点怪，但是它确实是这样做的。

看个例子：

```go
type myInt int

func main() {
	var number1 myInt
	number1 = 40
	fmt.Printf("number1 = %v\n", number1)
}
```

跑起来，`number1 = 40` 出来了。但我刚才说了一句话，Go 认为这两个是不同的类型。怎么来证明这个事情呢？可以这样证明：

```go
	var number2 int
	number2 = number1   // 这里会报错
```

保存一下就看到报错了：**不能把 `myInt` 直接赋给 `int`**，因为 Go 认为这两个不是同一个类型。

有些同学可能不理解，说不都是 int 吗？为什么呢？因为 Go 语言从语法上认为它们是两个不同的类型，因此你要把 `number1` 交给 `number2`，就相当于把 `myInt` 这个类型交给了 `int` 这个类型，他认为是不允许的。

那怎么办呢？**转一下就行了**，一样的规矩：

```go
	number2 = int(number1)
```

这里我再强调一下：这里依然需要**显式转换**。一定是要显式转换，否则要出错的。

#### 给函数类型也起个名字

再举一个复杂一点的例子，就是给一个函数类型取个别名，这样将来如果我们要把这个函数作为一个形参，就可以简化这种写法了：

```go
type myFunType func(int, int) int

func myFun(funvar myFunType, number1 int, number2 int) int {
	return funvar(number1, number2)
}
```

你看，原先我们这个写法 `funcvar func(int, int) int` 是不是写得挺长的？现在有这个东西，就可以直接换成 `myFunType`，效果是完全一样的。

> **提示**：这一条老师不讲是不行的。你以后看别人写代码，突然发现 `myFunType` 是个什么玩意儿，一查发现它是这么定义的，你瞬间就蒙圈了对不对？所以咱们既然要当程序员，你其实就是要抠细节。

这里还踩了一个很典型的坑：我一开始把这个 `type` 写在 `main` 函数**里面**了，结果外面根本识别不了——你在 `main` 函数里面定义一个 `type`，别的地方用它，它根本识别不了，编译器直接说这个没有定义过。所以**这个 `type` 必须提到外面去，至少要提到 `main` 前面**才可以有用。

提到最前面之后就没问题了，保存，代码里的红色波浪线没有了，跑起来 `res3 = 1100`（因为传的是 500 和 600），完全正确。

### 给返回值命名

第十一个细节，这个也很有用处：**Go 语言支持对函数返回值命名。**

我们前面有一个函数，要计算两个数的和以及两个数的差，当时我们直接写的是 `int, int`。但有时候有些程序员喜欢直接给返回值命名。

那为什么要有这个功能呢？传统的写法有一个问题：你必须把两个数的顺序搞清楚，不然的话和或者是差可能刚好就求反了。命名之后就不用担心这个了。

```go
func getSumAndSub(n1 int, n2 int) (sum int, sub int) {
	sum = n1 + n2
	sub = n1 - n2
	return
}
```

这里面的语法要注意几处：

- 形参位置上直接写 `sum` 和 `sub`，函数体里就不用再写要返回哪两个值了，这里就是对应的关系。
- 函数体里写 `sum = n1 + n2`——**这个地方就不要再写 `:=` 了**。因为你已经把这个名字定好了，相当于说在调用这个函数的时候，编译器把这两个返回值的创建工作也给你做好了，只是它默认为空、默认为 0。
- `sub = n1 - n2` 同理。
- 最后直接 `return` 就行了，不用再写后面还有 `sub`、还有 `sum`。

**这样做的好处是什么？就是说这个顺序我无所谓了。** 因为 `sum` 和 `sub` 的值算出来是多少就是多少，所以跟它顺序无关了。你把这个顺序调一下，`sub` 还是差、`sum` 还是和；只要你在那边接收的时候按顺序接就可以了。

调用演示：

```go
a, b := getSumAndSub(1, 2)
fmt.Printf("a=%v b=%v\n", a, b)
```

这里我问大家一个问题：`a` 等于多少？`a` 就是你这设计的，返回的第一个是 `sum`，就是两个数的和；第二个是 `sub`。至于你在函数内部怎么算的顺序，我不关心。

跑起来，输出 `a=3 b=-1`，完全正确。

> **易错点**：这里我第一次跑还报错了，报错信息里有"两个值没问题"，但真正的原因是——这个 `a` 我们在前面已经定义过呀！前面那个 `a` 是函数类型，所以它认为你把这个返回的 `sum` 交给 `a`，而 `a` 原本的数据类型是函数类型，这就不对了。**换个名称就行了，不要跟前面的名字产生冲突。**

### 用下划线忽略返回值

第十二个：**使用下划线标识符忽略返回值。** 这一点在前面已然讲过了，所以这块我就不再多说了。

什么意思呢？比如说我这里有两个返回值，一个是 `sum`，一个是 `sub`。那么我在调用这个函数的时候，如果说我只想得到其中一个值，那么另外一个值用下划线来使用就行了。如果我两个都不要，那直接调一下不就完了嘛，就不用接收了。

> **定义**：这个下划线可以作为一个**占位符来忽略返回值**。它出现的位置，就是返回值的位置——左边不留，右边用 `_` 顶替。

### 可变参数：支持 0 到多个，或者 1 到多个

最后一个细节，也是非常重要的一个知识点：**在 Go 中支持可变参数。**

它可以支持 0 到多个参数。比如说我想去求多个数的和，但是这个数有多少个我不知道，可能是两个数，可能是三个数，那这个时候就可以用可变参数来实现这种效果。

写法是 `args ...int`——**三个点，缺一不可，它是一种固定的写法**。前面这个参数名字可以随意，后面是数据类型。

如果要支持 1 到多个参数怎么办呢？那前面这个给它写固定，后面也可以加一个可变参数。

> **提示**：`args` 其实本质是一个**切片**（slice）。但切片大家现在还没有学习，你可以暂时把它理解成就是一个数组，只是切片它是一个动态的数组而已。因为这块还没有讲解，所以这里就是简单地用它一下，后面再讲切片的时候还会再做一个深度的了解。

在访问这个参数，第几个参数的时候，可以用 `args[index]` 来访问。再说一遍，`args` 这个参数是**可以变名的**，不是说固定就一定叫 `args`，也可以是别的名称。

#### 求 1 到多个 int 的和

题目：编写一个函数 `sum`，可以求出 1 到多个 `int` 的和。

```go
func sum(n1 int, args ...int) int {
	sum := n1
	// 遍历 args
	for i := 0; i < len(args); i++ {
		sum += args[i] // args[0] 表示取出切片的第一个元素的值，其它依此类推
	}
	return sum
}
```

逐段看：

- `n1 int` 这个不是可变参数，就一定写在第一位；后面 `args ...int`，一般是这样命名的，但名字可以变，类型是 `int`。
- 因为只有一个返回值，所以我就没有用括号把它括起来了。默认就为 `n1`——假设求的时候只传了一个值，`n1` 就是整个数的和。
- 然后 `for` 循环遍历 `args`。因为你现在不知道它传了多少个参数，就要遍历它了。`len(args)` 拿到它的长度，`i++` 递增。
- 这时我们就累积 `sum += args[i]`。因为从第 0 个开始遍历，`args[0]` 表示取出这个切片里面的第一个元素的值，其他依此类推。

先给它传一个值试试：

```go
res4 := sum(10)
fmt.Println("res4 =", res4)
```

`res4 = 10`，因为你就一个值。再多传几个：

```go
res4 := sum(10, 0, -1, 90, 10)
```

这样算下来应该等于 109。看结果——**有问题**，跟我们想的不一样。看代码是哪里出了问题：我们要对它进行一个遍历，遍历的时候刚才为了演示把这个 0 没有改回去，因为写死了，每次进来访问 0 刚好就是 0。这个应该是变化的，进来一次取第一个，第二次取第二个。把 `args[0]` 改成 `args[i]`，测出来 109，正确。

> **易错点**：写循环的时候，**`args[i]` 的 `i` 千万别漏了写成 `args[0]`**，也别忘了先把循环变量 `i` 声明出来。改过来才是遍历。

前面讲了，`args` 的名字不一定非是 `args`，也可以是别的名字。比如我把它改成 `vars`，其实也是可以的。改完之后再加一个 100，这样应该是 209，正确。所以大家就知道这个可变参数这里名字是可以变的，但通常情况下我们还是取名叫 `args`，按约定俗成的来做就行了。

#### 可变参数必须放在最后

关于可变参数我再补一个细节：顺序我们看看能不能颠倒。

有些编程语言里面它不是这样的，我们来看看，如果我把可变参数写在前面、把不是可变参数写在后面，它支不支持这种写法？

> **不支持**。它直接报错：`can only use ... with final parameter in list`。

也就是说在 Go 语言里面，如果你用可变参数，那么**可变参数一定要放在形参列表里的最后一个**。如果一个函数的形参列表中有可变参数，可变参数需要放在形参列表最后，否则语法是通不过的。

这样子讲完，大家应该对我们的可变参数了解得更明白一点。当然这个地方是 `int`，也可以是 `string`，也可以是其他。

### 三个函数练习题

下面我们来做一些关于函数的练习题，这里我给大家准备了三个题，加深一下对函数的理解。

#### 第一题：这个写法可以

第一题里有一个 `main` 函数，`main` 函数里面调用了一个 `sum(1, 2)`。看 `sum` 的时候，形参我定义的是 `n1, n2 float32`，返回一个 `float32`。

这种用法可不可以？可以。这种用法就是跟以前咱们定义多个变量的用法是一样的：如果 `n1` 和 `n2` 的数据类型是一样的，前面这个其实都可以省略，在最后写上它的数据类型就可以了。也就是说 `n1` 和 `n2` 都为 `float32` 这个数据类型。

答案代码是没有错误的。输出内容是这样的：

- 这里输出 `n1` 的类型是什么——`n1 type = float32`；
- 这里返回 `n1 + n2` 的值，1 和 2 传进去了，算出来是 3，所以 `sum = 3`。

#### 第二题：错在类型不匹配

第二题问的是代码有没有错误，为什么？

先把两个函数交给变量：把 `sum` 这个函数交给了一个 `a` 变量——允许的；把 `sum2` 也交给了一个 `b` 变量，这也可以，没问题吧。然后调用 `myFun(a, 1, 2)`。

第一个地方是 **OK 的**。这个 `a` 呢，它的数据类型是 `myFunType`；`myFunType` 是不是一个自定义类型？是。它是什么类型？就是有两个 `int` 形参、返回一个 `int` 的那种函数类型。而 `a` 其实就是 `sum`，`sum` 的签名刚好和它对得上——两个形参，返回一个 `int`。我这也是两个形参，也返回一个 `int`，所以这是 OK 的。

再来看下面这一个 `myFun(b, 1, 2)`。**这就有问题了。**

因为你 `myFun` 这里接收的是 `myFunType` 这种自定义的数据类型，而它只能接收两个 `int` 的形参、返回一个 `int`。但是你给的这个 `b` 其实是 `sum2`，`sum2` 是什么？它相当于要把 `sum2` 这个函数类型赋给一个叫 `myFunType` 的自定义类型。而 `myFunType` 接收的是两个 `int` 形参返回一个 `int`，你给的却是三个 `int` 形参返回一个 `int`，因此这个是错的。

> **结论**：这句话会报错。错误的原因就是**类型不匹配**——不能把这个函数类型赋给这种自定义类型。这两个类型不匹配。

#### 第三题：用指针交换两个变量

第三题是一个编程题：**请编写一个函数叫 `swap(n1 *int, n2 *int)`，可以交换 n1 和 n2 的值。**

大家想一想，能交换吗？我们这个地方它这个题出得是有点小问题：如果要交换 n1 和 n2 的值，那么这个地方得有个星号。因为你如果不是星号的话，你是值拷贝，那是交换不了的。所以这应该是要有这个星号才对，**应该是出题的时候忘写了这两个星号**。

来，我们一起完成这个题：

```go
func swap(n1 *int, n2 *int) {
	t := *n1
	*n1 = *n2
	*n2 = t
}
```

交换的逻辑是这样的：定义一个临时变量 `t`，先把 `*n1`（也就是 `n1` 这个指针指向的那个值，取值运算）交给它；然后把 `*n2` 的值交给 `*n1`；最后再把 `t` 交给 `*n2`。

先把 `n1` 的值放到 `t`，再把 `n2` 的值交给 `n1`，再把 `t` 交给 `n2`——这就完成了一个交换。

测试：

```go
func main() {
	a := 10
	b := 20
	swap(&a, &b)
	fmt.Printf("a=%v b=%v\n", a, b)
}
```

这里有两处要注意：因为形参是一个指针，所以在传递的时候**得传地址**，那边接收的就是指针。另外输出这一句一定要用 `f`，用 `Printf` 才是格式化输出。

跑起来：`a=20 b=10`。原先的值是 a 等于 10、b 等于 20，现在交换过后 a 等于 20、b 等于 10，正确，交换成功。

> **易错点**：这个地方一定要用指针的形式来传递，因为我们知道基本数据类型它是值传递的，值传递要进行拷贝。如果用的是值传递，你在函数里面交换的时候对外面的变量是没有影响的。所以这里用一个指针来接收这个地址，进行相应的数据交换。

这三个练习题就分享到这里。大家自己最好是敲一遍，不能光看我演示了一遍自己不写一遍，那是不行的。

### init 函数

下面给大家介绍一下 Go 里面的一个叫 `init` 的函数。

`init` 这个函数，大家看这个名字就能猜出来它是干什么的——`init` 就是初始化的意思。

> **定义**：每一个源文件中都可以包含一个 `init` 函数。该函数会在 `main` 函数执行之前被 Go 运行框架调用，也就是说 `init` 会在 `main` 函数前被调用。这个函数通常可以用来做初始化的一些工作。

#### 执行顺序：全局变量 → init → main

第一个细节，注意听：如果一个文件中包含有变量定义（我们这儿说的变量定义往往指的是**全局变量**），又有 `init` 函数，还有 `main` 函数，那么执行的流程是：**先执行变量定义，再执行 `init` 函数，再执行 `main` 函数**。

这块我们要把它好好地给大家聊一下。怎么证明全局变量是最先执行的呢？因为直接定义一个变量是没有输出的，很难看。我们这里先写一个函数来完成初始化：

```go
var age = test()

func test() int {
	fmt.Println("test()...")
	return 90
}

func init() {
	fmt.Println("init()...")
}

func main() {
	fmt.Println("main()...")
	fmt.Println("age=", age)
}
```

如果真的全局变量定义是先执行的，那它就会去调 `test` 函数对不对？这样 `test()...` 这句话就应该先输出，然后输出 `init()...`，最后输出 `main()...`。

请看效果，跑起来：**`test` 函数第一个被执行，`init` 函数第二个执行，`main` 函数第三个执行**；而且 `age` 的确等于 90。跟我们分析完全一样，说明我们分析是正确的。

```text
  ┌──────────────────────────────────┐
  │  源文件中的三样东西               │
  ├──────────────────────────────────┤
  │  var age = test()   ←  变量定义  │  第 1
  │  func init() {...}  ←  init     │  第 2
  │  func main() {...}  ←  main     │  第 3
  └──────────────────────────────────┘
```

所以 Go 程序的源文件里面，它其实是先执行变量定义，再执行 `init` 函数，最后执行 `main` 函数，理解？

这些将来我们都会用得到，在做项目的时候，这些知识点就会发挥巨大的作用。

#### 一个真实场景：在 init 里初始化全局变量

再强调一个细节：`init` 函数最主要的作用是什么？刚才讲过，是完成一些初始化的工作。到底怎么用这个 `init` 函数完成初始化工作呢？我给大家举个案例，做一个应用场景。

比如说现在我有这么一个需求，`main.go` 里面要去用到另外一个包的文件。在这儿新建一个包叫 `utils`，这个包里面有一个文件叫 `utils.go`：

```go
package utils

var Age int
var Name string

func init() {
	Age = 100
	Name = "tom~"
}
```

写这么一两个变量，有一个变量叫 `Age`，是全局的——因为我要在别的地方用，把它定义成全局的；还有一个 `Name`。这两个变量我希望在 `main.go` 里面去用，但是**我在用之前希望它先被初始化**。

怎么做？一般来说可以这样写 `init`，在这里去完成初始化不就完了吗？因为这是两个比较简单的变量，将来有可能是个连接，或者打开一个文件，在函数里面去初始化特别的方便。

在 `main` 里面怎么去用它呢？非常的简单，先引入包：

```go
import "go_code/chapter06/func_init/utils"

func main() {
	fmt.Println("age=", utils.Age, "name=", utils.Name)
}
```

直接说 `Age` 等于多少呢？写出来，那就是 `utils` 包里面的 `Age`；`Name` 也把它取出来。保存一下，没问题。

跑一下，我们可以看到 `Age` 的的确确取出来是 **100**，而 **tom~** 也取出来了。那就说明我们在执行代码的时候，其实是在引包的过程，或者说在调包里面变量的时候，它其实**已经先把它初始化了**——不然肯定它先被初始化，才有可能拿到值。

也可以在这执行一下，看看哪个先被执行。我们在 `utils` 包里也加一句打印，可以看一下谁先执行。大家可以猜一猜，是它先执行呢，还是 `main` 里面的 `init` 先执行？

> 我们可以看到，最先执行的其实是 `utils` 包里面的 `init`。也就是说，**是被引入的包先执行**，然后是 `test`，然后是 `init`，然后是 `main`。

这就是说，我们在 `init` 函数里面经常用来做初始化的工作。

#### 面试题：跨文件的执行顺序

现在还得有个细节了。有同学问："你刚才讲的时候是 `main.go` 引入了 `utils` 里面的 `utils.go` 文件，那么它们之间这个调用顺序到底是什么样子的呢？我有点听蒙圈了。"

这是面试题，最后一点：如果 `main.go` 和 `utils.go` 中都含有变量定义、`init` 函数，那么执行的流程是什么样子的？

大家看一个图就明白了：

```text
  main.go  引入了  utils.go

  ┌────────────────────────────────────────────┐
  │ 1  被引入文件（utils.go）里的变量定义        │
  │ 2  被引入文件（utils.go）里的 init 函数     │
  │ 3  main.go 里的变量定义                     │
  │ 4  main.go 里的 init 函数                  │
  │ 5  main.go 里的 main 函数                  │
  └────────────────────────────────────────────┘
```

当然有同学会问："如果 `utils.go` 又引入了别的文件呢？"比如他又引入了别的文件，一样的：那就先执行这个文件里面的变量定义、这个文件里面的 `init` 函数，然后再回来执行 `utils` 里面的变量定义、`init` 函数，最后再执行主函数里面的。听清楚没有？

这个就是一个重要的面试题，有可能被问到，请大家加深印象。在我们做项目的时候，如果需要涉及到变量定义、`init` 函数和主函数执行流程，大家要搞得非常清楚，不然的话你就会蒙圈了。

## 匿名函数与闭包：把"上次那个变量"记住的写法
> 对应块：BLK44 | 覆盖分集：P124-P126 | 块标题（分集名）：《123_尚硅谷_匿名函数》

现在再给大家介绍一下 Go 函数里面的匿名函数，接着是闭包。这两个东西是连着的——闭包正是匿名函数的一个高级用法。

---

### 匿名函数：没有名字的函数

大家都知道，匿名函数在很多编程语言里面其实都是有的。**所谓匿名函数就是没有名字的函数。**

一般情况下我们的函数都是有名儿的，那什么时候我们会用到没有名字的函数呢？Go 支持匿名函数，如果某个函数只是希望使用一次，就可以考虑使用匿名函数。当然，匿名函数也可以实现多次调用。

> **结论**：匿名函数的使用方式就这么两种——**定义时直接用**，或者**赋给一个变量再通过变量调用**。

#### 定义时就直接调用

新建一个文件，我们看第一种方式：假设有这么一个情况，求两个数的和，使用匿名函数的方式完成。

```go
package main

import (
	"fmt"
)

func main() {
	// 在定义匿名函数时就直接调用，这种方式匿名函数只能调用一次

	// 案例演示：求两个数的和，使用匿名函数的方式完成
	res1 := func (n1 int, n2 int) int {
		return n1 + n2
	}(10, 20)

	fmt.Println("res1=", res1)
}
```

这里面没有函数名，直接写形参 `n1 int, n2 int`，返回一个 `int`。没有函数名怎么调呢？**直接括号括起来，在后面传参就行了**，我们用一个变量 `res1` 来接收。

这里有两层要分清楚：

- **前面这一段是定义**——`func (n1 int, n2 int) int { return n1 + n2 }`；
- **后面传参是调用**——`(10, 20)`。

所以这相当于在定义这个匿名函数的同时就调用了它。10 会给到 `n1`，20 会给到 `n2`，进行计算后把结果返回给 `res1`。

运行一下可以看到 `res1 = 30`。

> **易错点**：这种方式匿名函数**只能调用一次**。因为没有给它名字，也没有把这个匿名函数给一个变量，所以调过了再想调就没有机会了。有时还真有这样的需求——我们并不希望定义一个函数，而是想调一次就完事，这个时候匿名函数就可以用了。

#### 赋给一个变量再调用

再来看第二种方式。求两个数的差，把它交给一个变量 `a`：

```go
	// 将匿名函数 func (n1 int, n2 int) int 赋给变量 a
	// 则 a 的数据类型就是函数变量/函数类型
	// 此时，我们可以通过 a 完成调用
	a := func (n1 int, n2 int) int {
		return n1 - n2
	}

	res2 := a(10, 30)
	fmt.Println("res2=", res2)

	res3 := a(90, 30)
	fmt.Println("res3=", res3)
```

这句话的意思就是将匿名函数赋给了 `a` 这个变量。此刻 `a` 这个变量其实就已经是一个函数了，它是个**函数变量**，`a` 的数据类型就是函数类型。我们可以通过 `a` 完成调用。

调用 `a(10, 30)`，把 10 传给 `n1`，把 30 传给 `n2`，返回的结果赋给 `res2`，此时 `res2` 就等于 **-20**。再调一次 `a(90, 30)`，`res3` 就等于 **60**。

> **提示**：这个时候 `a` 就可以反复调用了。但是大家知道，这个 `a` **可不是函数名**，不能理解成函数名，它就是一个函数变量。

最后这一点挺有价值：一般在 `main` 里面是定义不了函数的，单独定义函数语法通不过；但是通过这种方式，就可以**在一个函数里面再定义一个函数了**。在某些情况下，我们用这种方式也可以完成一些特殊的需求。

#### 全局匿名函数

如果我们将匿名函数赋给一个**全局变量**，那此时此刻，这个匿名函数就称为**全局匿名函数**，可以在整个程序中有效。

```go
package main

import (
	"fmt"
)

var (
	// fun1就是一个全局匿名函数
	Fun1 = func (n1 int, n2 int) int {
		return n1 * n2
	}
)

func main() {
	// 全局匿名函数的使用
	res4 := Fun1(4, 9)
	fmt.Println("res4=", res4)
}
```

因为 `Fun1` 是一个全局变量，把匿名函数交给这个全局变量，此时此刻 `Fun1` 就代表一个全局匿名函数，可以在任何地方使用，在整个程序都是有效的。当然**这个时候变量名首字母要大写才是全局有效**。

调用时用 `res4 := Fun1(4, 9)`，运行输出是 **36**。

在实际开发中，我们用的比较多的相对来说还是第一种方式多一点。以后大家看到这种形式的使用，不要大惊小怪，心里就很坦然了：原来这种写法我见过。在项目里面用到的时候，因为你有这个知识点，就能理解了。

### 闭包是什么：一个函数加上它引用的环境

闭包这个概念听起来会相对高大上一点，有时候也不是那么容易理解，对不对？但是我们在做开发的时候往往还会用到闭包。

> **定义**：所谓闭包就是一个**函数与与其相关的引用环境组成的一个整体**，或者说一个实体。

这里面出现了三个概念。首先是**函数**——闭包它本质返回的是个函数。但是这个函数它会用到函数外的一些变量，然后它们共同组成一个整体，这个整体我们把它叫闭包。

我们直接走案例，运行过后再分析。新建一个文件 `func/demo07`，讲闭包：

```go
package main

import (
	"fmt"
)

func AddUpper() func (int) int {
	var n int = 10
	return func (x int) int {
		n = n + x
		return n
	}
}

func main() {
	f := AddUpper()
	fmt.Println(f(1)) // 11
	fmt.Println(f(2)) // 13
	fmt.Println(f(3)) // 16
}
```

这是一个**累加器**。逐段看：

- `AddUpper` 里面会返回一个这样的类型：函数。这个函数会传一个 `int` 值进来，然后返回一个 `int`。注意看它返回的是什么——返回的**是一个函数**。
- 这里边我先定义了一个变量叫 `n int`，初始化为 10。
- 然后我 `return` 了一个匿名函数 `func(x int) int`，里面做的是 `n = n + x`，然后 `return n`。

怎么用？这里有一个变量来接收 `AddUpper()` 的返回值。它返回的是什么呀？实际上本质就是一个函数，那这个时候我就可以调用它了。

我先看 `f(1)` 返回什么。我在这里传了一个 1，因为它返回的是函数，那这个 1 就会传给 `x`。但是这个 `x` 在里面用的时候，它其实会跟外面这个 `n` 相加，所以相当于 10 加 1 等于 11，返回 11。跑起来确实是 **11**，没问题。

#### 关键问题：为什么第二个是 13 不是 12

但我关键要问的是：假设我写一个 2，这个地方返回什么？大家可以猜一猜，这是关键。

按理说如果按照我们以前的写法，你这写了个 2，那就是 10 加 2 等于 12。**但是不是。**

因为你这个它形成一个闭包过后，这个 `n` 其实就已经是 11 了，所以说这个地方会返回 **13**——它相当于说这个 `n` 已经变成 11 了，11 再加一个 2 不是 13 吗？运行一下，返回的确实是 13。

再写一个 3 呢？是不是相当于这个 13 再加 3 等于 **16** 了？跑起来，完全正确。

#### 把这件事讲透

那为什么会出现这么一个情况呢？我把这个代码好好整理一下，做一个说明和总结，这个很重要，注意听讲。

**第一点**：`AddUpper` 它是一个函数，它返回的数据类型是 `func(int) int`，没问题吧？

**第二点，也是最关键的一点**：到底哪一块是闭包？注意看这段代码——`var n int = 10`。准确的讲，**这个就是闭包**。

它返回的是一个匿名函数，但是这个匿名函数引用到了函数外的 `n`。因此这个匿名函数就和 `n` 形成了一个引用关系，它们共同组成一个整体——**构成了闭包**。所以闭包实际上是：这个匿名函数，加上这个匿名函数引用到的外面那个 `n`，构成的一个闭包。

> **提示**：你可以这样理解——**你可以把这个返回的函数理解成一个类**。这个类里面的概念有些同学没有学过类就有点麻烦了，因为你没学过面向对象。那就先这样听着吧：这个函数实际上是一个**操作**，而我们这个 `n` 相当于它的一个**字段**。函数和它使用到的这个 `n` 共同构成了一个闭包。

**第三点**：为什么反复调用会累加？因为 `n` 是**累加的**，它不会每次进来都给你定义一次——**它只是初始化一次**。所以每调用一次就进行一次累加。第一次是 11，当它调用完了得到 11 过后，其实它下次调的时候这个 `n` 就变成 11 了，而不会再进行一次初始化。

**第四点，也是最后一点，最关键**：我们要搞清楚闭包的关键，就是要**分析清楚函数返回的那个函数，它使用到了或者引用到了哪些变量**。为什么要分析这个清楚呢？因为你分析清楚之后才知道函数和哪些变量构成了闭包——因为函数和它引用到的变量共同构成闭包。

再说的直白一点：这块如果同学们学过面向对象就特别好理解了。如果没有学过面向对象也也很好理解，你就认为**闭包本质就是函数——返回的这个函数和它引用的变量构成一个整体**。当它反复调用的时候，它引用到的这个变量不会每次都初始化，而是不停地累加。

记住这两点就 OK：第一，闭包其实是返回的匿名函数和这个匿名函数用到的函数外的一个变量，它们共同构成一个闭包；第二，在调用的时候，它用到的这个环境变量不是每一次都会被初始化，它用一次就会变化，再用一次就在这个基础上再进行变化。

#### 换个角度再看一次

如果大家真的明白了，稍微改变一下，大家看看能不能马上把这个搞出来。

```go
var str string = "hello"
```

这是一个 `"hello"`。如果我在这里，在这个地方做：

```go
str = str + x
// 或者直接
str += x
```

在这儿用外面这个 `str`，然后输出：

```go
fmt.Println("str =", str)
```

问同学们，当我们第一次调用这个闭包的时候，这个地方会输出什么？是不是 `str` 会等于原先的 `"hello"` 再加上你传进来的 `x`？第一次如果传的是 `1`，那就是 `"hello1"`。

第二次会输出什么呢？是不是在这个基础上？因为刚才讲过了，引用的外部变量只会初始化一次，所以第二次调用的时候，它其实是在原有 `str` 的基础上去拼接。

第三次输出的时候，是不是就在后面又加了一个 `3`？

道理是一样的：返回的这个函数和外面引用的变量共同构成一个闭包；每当你调用这个闭包的时候，这个变量不会再初始化了，而是在原先的基础上进行变化。因为它们是个整体，你可以把它理解成一个类，或者理解成一个对象都可以。

跑起来看效果——**这里会有一个小惊喜**：拼接如果使用的是整数，这个 `1` 会被转成 ASCII 码的一个字符，所以这里显示的就不是数字 `1` 了，而是转成 `1` 对应的 ASCII 码字符。`1` 对应的字符，是个笑脸。打开 ASCII 码表你就明白了。

那我这里写死，你们再看一遍就好办了。我们直接写死，写成一个字符，这样拼接大家可能看得更明白，我就不使用这个 `x` 了。那第一次是 `a`，第二次是两个 `a`，第三次是三个 `a`。

如果一定要让大家理解成数字的话，我可以找一个能够转成对应**可见字符**的，这样更明白。比如 dollar 符，`$` 对应的数值是 36。如果要像刚才那样写的话也可以，那就是拼接 36，36 对应的字符其实就是一个 `$` 符号，这就是可见字符了。刚才那个是不可见字符，所以看得比较乱。

这样的话，应该就是第一个变成 `$`，后面变成两个 `$`，第三个变成三个 `$`，因为它每次都累加一次，是不是？跑一遍看效果，这样分析就完全正确了。

### 闭包最佳实践：给文件名补一个后缀

我们来看一个关于闭包的最佳实践。我这出了一个题，等下会完整地列出来，先跟着我做一遍。

要求很简单：**写一个函数叫 `makeSuffix`，它有一个参数，可以接收一个文件后缀名**，这个后缀名随便写，比如 `.jpg`。**然后它返回一个闭包**。调用这个闭包时可以传入一个文件名：如果该文件名没有指定的后缀，就返回文件名加上 `.jpg`；如果已经有这个后缀了，就返回原文件名。要求是使用闭包的方式完成。

这里有一个提示：我们会用到 `strings` 这个包里面的一个函数叫 `HasSuffix`，它可以判断一个字符串后面有没有一个后缀。

思路是这样的：

1. `func makeSuffix`，传入一个参数 `suffix string`，这是它指定的文件后缀。
2. 它要返回一个闭包，所以我返回的是一个可以接收一个 `string`、然后返回一个 `string` 的函数。形参叫 `name`。
3. 里面做一个判断：如果 `name` 没有指定的后缀名，就加上；否则就按原来的名字返回。

判断 `name` 有没有指定后缀，用的就是 `strings.HasSuffix`，对 `name` 判断有没有 `suffix` 这个后缀。如果没有，它就等于 `false`，就让这个名字拼接上这个后缀；如果有，等于真，就直接把名字返回去。

```go
package main

import (
	"fmt"
	"strings"
)

func makeSuffix(suffix string) func(string) string {
	return func(name string) string {
		// 如果没有指定的后缀，则加上；否则按原名字返回
		if !strings.HasSuffix(name, suffix) {
			return name + suffix
		}
		return name
	}
}

func main() {
	f := makeSuffix(".jpg")

	res1 := f("winter")
	fmt.Println("res1=", res1)

	res2 := f("bird.jpg")
	fmt.Println("res2=", res2)
}
```

> **易错点**：这里我第一次写就踩了个坑——上面已经声明过一个 `f` 了，下面再写一个 `f` 就冲突了，得换个名字叫 `f2`。另外 `suffix` 这个单词也容易拼错。这两处写完检查一遍，代码就没毛病了。

跑起来看效果：传进去的 `winter` 没有带 `.jpg`，返回的时候就把 `.jpg` 给我加上，得到 **`winter.jpg`**。

那假设我这个地方本身有一个叫 `bird.jpg` 的，已有的后缀 `.jpg` 了，它返回的时候会给我再加一个 `.jpg` 吗？**不会了。** 因为我在里面做了这个判断：没有这个后缀才加后缀；已经有 `.jpg` 后缀了，它就按照原来的名字返回，跑一下果然如此，`bird` 后面并没有再追加一个 `.jpg`。

但是如果你的后缀名是别的就不好说了。比如说你是叫 `bird.avi`，这个 `.avi` 对它来说它不是 `.jpg` 的后缀，所以说它会返回 **`bird.avi.jpg`**。

#### 哪一块是闭包

那我们来分析一下这个代码，究竟哪一块是我们的闭包？

它返回的是一个函数，这个函数它用到谁了？它是不是用到这个 `suffix` 了？这个 `suffix` 是不是这个函数外面的一个变量？**因此，这个返回的匿名函数和外面的 `suffix` 构成了一个闭包。**

就这么一个意思。

---

### 闭包到底强在哪

我们体会一下闭包有什么好处。我说两句话。

**第一句**：`makeSuffix` 返回的这个匿名函数和 `makeSuffix` 里面的 `suffix` 这个变量组成了一个闭包。因为返回的这个匿名函数它引用到了 `suffix` 这个变量了。

**第二句**：如果使用传统的方法，我们这个功能其实也可以轻松地实现。当然是可以实现的，没有任何问题。你写一个函数嘛，判断有没有后缀，如果有就原封不动返回，如果没有就加上。你看，这方你写个函数难道完成不了吗？完全可以。

比如说我不用闭包，写成 `makeSuffix2`：

```go
func makeSuffix2(name string, suffix string) string {
	if !strings.HasSuffix(name, suffix) {
		return name + suffix
	}
	return name
}
```

你看，我调用 `makeSuffix2`，把后缀给它带进去，判断一下有没有这个后缀，如果没有就给我加上，有就原封不动返回。**效果一样**，它也返回 `winter.jpg`，也返回 `bird.jpg`。

> **易错点**：这里有个坑我一开始也踩了——`name` 变量没有写进去，函数里就用不上了；而且这个地方要传两个变量进来才对，第一个你要针对哪一个判断，第二个你还要传一个名字。所以必须先 `var name string`，再把 `.jpg` 这个后缀带进去。

但是你们有没有发现这两者有什么不一样？

**如果用闭包的话，我只要传一次这个变量，这个后缀我传一次。** 如果用普通函数的话，其实每次都要传——每次调用都得把这个后缀变量带过去。

> **结论**：所以相对来说，用闭包还是有一点优势的：**后缀名只需传一次**。因为函数是调用一次，它的栈就销毁了，这个后缀不会保留，它就消失了。但是我们这个闭包，它会保留，它每次调用都会把你这个 `suffix` 保留下来。

回到第二句话总结一下：**如果使用传统的方法，也可以轻松实现这个功能，但是传统方法每次都要传入后缀名；而闭包因为可以保留上次引用的某个值，所以我们传入一次就可以反复使用。** 大家仔细体会一下它的好处。

同学们以后在工作中使用闭包的时候，要充分体会它最大的好处：**它可以把它引用到的、那个匿名函数引用到的一些变量保留下来，进行下次调用的时候再接着用。可是函数是不行的，因为函数调用一次，它的栈就销毁了，它原先的变量也就没有了**——除非你用全局变量，是不是？但是我闭包不用全局变量，我也可以搞定这个事。

如果面试官问到你闭包和普通函数的好处，你就想想这个加后缀的例子，总结的那两句经典的话。

### 本讲提到的题目

**题目 · 用闭包写一个后缀补全器**

请编写一个程序，具体要求有这么四点：

1. 编写一个函数叫 `makeSuffix`，它有一个参数，可以接收一个文件后缀名（后缀名随便写，比如 `.jpg`）；
2. `makeSuffix` **返回一个闭包**；
3. 调用这个闭包可以传入一个文件名：如果该文件名没有指定的后缀，则返回文件名加上 `.jpg`；如果已经有这个后缀，则返回原文件名；
4. **要求使用闭包的方式完成**。（提示：`strings` 包里的 `HasSuffix` 可以判断一个字符串后面有没有某个后缀。）

**解析**：闭包部分就是 `makeSuffix` 返回的那个匿名函数，加上它引用到的外层 `suffix` 变量。判断逻辑放在匿名函数里，靠 `!strings.HasSuffix(name, suffix)` 决定是拼接还是原样返回。

**答案**：`makeSuffix(".jpg")` 得到闭包 `f`；`f("winter")` 得 `winter.jpg`，`f("bird.jpg")` 得 `bird.jpg`，`f("bird.avi")` 得 `bird.avi.jpg`。闭包最大的好处是**后缀只需传一次**——普通函数每调一次都得重新传一次后缀。

## defer 与函数参数的传递：延后执行的资源释放，和"其实都是副本"
> 对应块：BLK45 | 覆盖分集：P127-P129 | 块标题（分集名）：《126_尚硅谷_defer的基本使用》

我们再来给大家介绍一下 Go 语言函数里面的一个关键字，叫 `defer`。`defer` 听这个名字，它是一个**延时**的意思。

### 为什么 Go 要多一个 defer

在函数中，程序员经常需要创建资源。这块我们现在还没学创建资源，但是我可以先给大家介绍一下——比如后面我们去打开一个数据库的连接，或者打开一个文件句柄、锁等等，这些都是资源。

**为了在函数执行完毕后及时释放资源，Go 的设计者提供了一个 `defer` 延时机制。** 也就是说，你只要加上一个 `defer`，你的函数在执行完毕过后，它一定会把你指定的资源关闭；或者说，`defer` 后面的语句在函数执行完毕过后它会去执行，就这么一个意思。

在函数里面使用 `defer` 最主要的目的，就是在函数执行完毕后及时释放资源，我们可以用 `defer` 来完成这个功能。

### 快速入门案例：defer 栈与后进先出

我们写一段代码，重点分析这段代码会运行出什么效果：

```go
package main

import "fmt"

func sum(n1 int, n2 int) int {
	// 当执行到 defer 时，会先将 defer 后面的语句压入到一个独立的栈（defer 栈）中，暂时不执行
	defer fmt.Println("ok1 n1=", n1)
	defer fmt.Println("ok2 n2=", n2)

	res := n1 + n2
	fmt.Println("ok3 res=", res)
	return res
}

func main() {
	res := sum(10, 20)
	fmt.Println("res=", res)
}
```

这里有一个主函数，主函数调用了一个 `sum`，`sum` 传了一个 10 和 20 进去，然后返回一个 int 值。这里有一个 `defer` 语句，这里又有一个 `defer` 语句。这边把 n1 和 n2 加起来之后交给了 `res` 变量，然后输出 `ok3`，`res` 等于这个值，然后再把 `res` 返回来。返回值在主函数里面接收，并在主函数里面输出。

**这段案例执行的顺序是这样子的：**

当我们的代码执行到 `defer` 的时候，编译器或者说我们的系统会将 `defer` 后面的语句压入到一个独立的栈中。我们姑且把这个叫做 **defer 栈**，它暂时不会执行。它压完了以后，会继续往下面执行后面的语句。

当函数执行完毕后，再从 defer 栈中取出，**按照先入后出的方式出栈，然后执行**。也就是说，**谁先进去反而后执行**。这两个 `defer` 语句先不会执行；当函数执行完毕后，再从 defer 栈按照先入后出的方式出栈来执行。第一句 `defer` 先入栈，它就后出来；第二句 `defer` 后入栈，它就先出来。

如果画个图的话，这儿有一个 defer 栈。先把第一句压到栈底，然后把第二句压入到它上面。出栈的时候，其实是先把栈顶的弹出来执行。

```text
   执行 sum(10, 20)
        │
        │  defer fmt.Println("ok1 n1=", n1)   ① 压栈（栈底）
        │  defer fmt.Println("ok2 n2=", n2)   ② 压栈（栈顶）
        │  fmt.Println("ok3 res=", res)       ③ 立刻执行
        │  return res                          ④ 执行完毕后开始出栈
        ▼
   ┌──────────┐   ┌──────────┐   ┌──────────┐
   │ ② ok2    │ → │ ① ok1    │ → │  空       │   后进先出
   │  n2 = 20 │   │  n1 = 10 │   │          │
   └──────────┘   └──────────┘   └──────────┘
        ▼
   回到 main，输出 res= 30
```

此时此刻，`res` 等于传进来的 10 加 20，就是 30。于是先执行的是这第一句话：

```text
ok3 res= 30
```

第一句执行完了之后，再执行 `return`。`return` 执行完毕后，函数 `sum` 就相当于执行完毕了。执行完毕后，它就会从 defer 栈里面开始取东西。因为遵循先入后出的方式，后入栈的先出栈，所以第二句输出的是：

```text
ok2 n2= 20
```

紧接着再出栈，第三句输出的就是：

```text
ok1 n1= 10
```

defer 栈全部都执行完毕后，再回到主函数，把这个值返回给 `res`，最后一句执行输出：

```text
res= 30
```

我们在终端运行 `go run main.go` 跑起来，输出结果就是 `ok3 res= 30`、`ok2 n2= 20`、`ok1 n1= 10`、`res= 30`，跟我们的分析完全一样。

> **结论**：`defer` 在这里起的作用，说白了就是**可以把一些在函数执行完毕过后要执行的语句，先压入到 defer 栈中，等到函数执行完毕后再依次执行**。这在资源进行释放的时候经常会这样做，后面我们还会详细说这个事情。主要是要搞清楚原因，也就是 defer 执行的顺序以及它为什么这么执行。

### 值拷贝同时入栈：最容易踩的那个细节

defer 的细节我总结了三点，有些在前面其实已经讲过了，我再系统地给大家过一遍。

当 Go 执行到一个 `defer` 时，**不会立即执行 `defer` 后的语句，而是将 `defer` 后的语句压入到一个栈中**（我为了讲课方便，暂时称该栈为 defer 栈），然后它会继续执行函数下面的语句。

当函数执行完毕后，就从 defer 栈中依次取出栈顶语句执行，**遵守栈先入后出的机制**。也就是说，先被压入栈的那个语句实际上是后执行，反而后压入栈的那个语句是先执行。

**第三点比较重要：在 defer 将语句压入到栈时，也会将相关的值拷贝同时入栈。**

这句话是不是有点不好理解？什么叫同时入栈？就是它在把你后面这个语句压入栈的时候——你后面这不是有 `n1` 和 `n2` 这些值吗？或者说不是 n1、n2，而有可能是一个什么资源也是有可能的——**如果说涉及到值的话，它会将相关的值拷贝同时入栈。**

前面两点我已经说过了，第三点还没有说过，我们把第三点给大家做一个案例。我们还是在刚才的代码上稍微做一下修改，增加两句话：

```go
func sum(n1 int, n2 int) int {
	defer fmt.Println("ok1 n1=", n1)
	defer fmt.Println("ok2 n2=", n2)

	n1++
	n2++

	res := n1 + n2
	fmt.Println("ok3 res=", res)
	return res
}
```

请大家思考一个问题：此时此刻，这个语句的输出顺序是不是还是不会变化的？**没有变化**，因为增加这两句话并不会改变 defer 那个语句输出机制，因此仍然是刚才的 1、2、3、4 顺序，这个没什么可说的。

那么问大家一个问题：当 `n1++` 过了过后，这个时候 `n1` 等于多少了？你传进来的是 10，等它 `++` 过了变 11 了。那这个 `n2` 是不是变成 20 加了一个 1，变成 21 了？那么此时此刻 `res` 等于 11 加 21 等于 32，因此这个地方应该输出 32。

**问题是在这里。** 同学们请思考：`ok2 n2=` 这句话是在 `n2++` 之后才执行的，那么同学们可能会认为这个 `n2` 是不是应该等于 21 啊？因为它在后面执行，理论上说应该这样。但实际上它仍然输出的是 **20**。

为什么这么讲？因为刚才我说的那么一个细节——**defer 将语句放入栈时，同时也会将相应的值拷贝同时入栈**。当它把这句话压入到 defer 栈的时候，其实它把 `n2` 这个值当时是多少，也就已经入栈了。它原先这个 `n2` 是 20，那就把 20 压进去了，同时它把 20 这个值拷贝压到这个栈里面去了。**所以说你外面这个 `n1`、`n2` 的变化对它没有影响。**

跑起来我们可以看到，输出结果确实是：

```text
ok3 res= 32
ok2 n2= 20
ok1 n1= 10
res= 32
```

顺序没有变化，但是值——这两个值会变化；原先入栈的时候值拷贝的还是 20 和 10。

> **注意**：**这个细节经常用来做面试的时候会问到你，所以大家一定要注意这块的使用细节。**

### defer 的最佳实践：打开就 defer，用完不用操心

刚才我们讲到 defer 最主要的价值在于哪里呢？**当函数执行完毕后，可以及时地释放函数创建的资源。** 它主要是这个用处。

来看一段模拟代码——将来我们在后面学数据库连接的时候，可能会去打开一个文件或者连接一个数据库。

```go
// 示意代码，不是真实 API，大家先看结构
file, err := os.Open("a.txt")
if err != nil {
    // 错误处理
}
defer file.Close()        // 打开后立刻 defer 关闭

// 中间该怎么用就怎么用 file，不受影响
```

比如说我们打开了一个文件，我会拿到一个文件的句柄，拿到过后我就可以马上执行 `file.Close()`——马上可以执行，因为有时候你会忘了执行嘛，我用完了过后我马上 defer。

**但是这个 `defer` 它又是在你这个函数执行完毕过后才去关闭的**，所以说你在后面的时候其实还是可以继续用这个 file，还是可以用这个句柄的。但用完了过后你用不用、害怕什么，因为你已经把它压入到 defer 栈了，它一定会帮你关闭，对不对？至于它什么时候去关闭，那就是它的事情，因为函数执行完毕过后它才去关闭。

打开数据库也是一样。打开数据库我们会得到一个数据库的连接，拿到一个数据库连接过后，我们也可以马上 `defer` 把这个连接关掉，然后下面继续用。

> **易错点**：**千万不要理解成一旦 `defer` 了这个连接就用不了，那就完全错了。** 你 defer 完了过后，file 这个句柄可以用；你 defer 完了，connect 连接可以用。上面该怎么用还怎么用。它是什么时候才去执行 defer 呢？就是你的整个函数执行完毕过后，它才去帮你销毁。

你看有些资源关闭的时机特别不好控制。很多代码里面像 PHP、像 Java，有时候这个资源什么时候关闭特别不好处理。那么 Golang 它把这个处理、把这个问题给解决了：**你只要一打开你就 defer，defer 完了你该怎么用就怎么用，用完了过后，最后函数调用完了过后，它才从这个 defer 栈里面把这些资源一个一个给你销毁了。**

这种设计理念还是我觉得用起来比较舒服。因为有些时候你要么就是容易忘记关，要么就是不知道什么时候关，那么我们这个 Golang 的设计者把这个就给你处理好了。

这里面的做法可以总结成三步：

- 在 Golang 编程中的通常做法是：**创建一个资源后**——什么叫创建资源呢？比如打开了一个文件句柄，或者获取了数据库的连接，或者有个锁资源——**可以立即 defer**。defer 的内容比如说是 `file.Close()` 或者是 `connect.Close()`；
- 在 defer 后面**可以继续使用**打开的资源，也就是创建的资源；
- 当这个函数执行完毕后，**系统会依次从 defer 栈中取出这些语句，关闭资源**。

> **结论**：这种设计理念的好处是能够让程序员及时地处理关闭的动作，而且**也不用去关注什么时候关闭了**——函数执行完毕它帮你一个一个销毁。程序员不用再为"在什么时机关闭资源"而烦心了。以前写代码的时候确实就有这个麻烦，只要做过开发的同学就会有这种感受：比如我以前在做 PHP 的时候，有时候就特别麻烦，不知道这个资源是在 service 关闭，还是在 model 中关闭，或者说是在这句话前关闭还是在这句话后关闭，不是特别的容易；容易是这块是在这儿关闭，另外一块代码又在另外一个地方关闭，它总是不统一。**所以这种机制非常简洁，程序员大家就可以统一这样去处理了。**

### 函数参数传递：值传递与引用传递

我们再把函数参数的传递方式做一个系统的回顾。前面已经讲过了，包括值传递以及引用传递，其实都已讲过，这里再系统地说一遍，因为**这个地方是重难点**，同学们在开发的时候也是经常会用到这一个知识点。

在 Go 语言里面，函数参数的传递方式主要有两种。一种我们称之为**值传递**，比如前面我们讲的基本数据类型其实就是值传递。何为值传递？**所谓值传递，就是说在传递参数的时候，它进行了一个值拷贝。** 第二个我们叫**引用传递**，所谓引用传递，其实它传的是一个地址。

#### 本质上都是变量的副本

**实际上，值传递和引用传递的本质都是一样的。** 不管你是值传递还是引用传递，传递给函数的**都是变量的一个副本**。

不同的是：值传递是值拷贝，就是它传的是一个值拷贝。比如你给他传了一个 6，是一个整数，那么传过去给这个函数以后，这个函数也得到一个新的 6，是一个值。

那么如果是引用传递，它是地址的一个拷贝。我们前面讲过的指针，大家还记得吧？如果希望函数内的变量能够修改函数外的变量，我们可以使用引用传递，其实是使用指针传递，传入的是个地址。你在测试代码里面传了一个地址过去，传给指针。我们知道指针它是引用传递类型——但你传地址的时候其实也是进行了一个拷贝，也是传递了一个具体的值过去，**只是这个值它不是这个 20 这个具体的数据的内容了，而是这个地址。**

> **结论**：**传递给函数的都是变量的副本，只是值传递的是值的拷贝，而引用传递的是地址的拷贝。** 本质上其实都是一样的，唯一不一样的就是拷贝过去的那个副本不一样。

#### 效率差在哪：数据量的大小

那么一般来讲，**地址拷贝的效率要高一些**。大家知道这是为什么吗？因为你拷贝的时候就是一个地址嘛，那当然相对来说效率要高了。

比方说我们还是以那个图为例。假设我们这个 number 是一个数，拷贝一个数过去和拷贝一个地址过去，效率肯定是不一样的——**地址它比较小，数据量比较小，一下就传过去了。**

再比如说后面我们学到一个结构体，那结构体它可能是一个内容量很大的结构体。这个时候我们如果把结构体用值拷贝过去，因为结构体默认它也是值拷贝，那这样子就会拷贝一个很大的数，数量就很大了，效率就低；那如果说我们传递的是结构体的一个地址呢，那效率就很高。

所以我们能够看到的区别就是效率的问题：**地址的拷贝效率要高，因为数据量小；而值拷贝取决于拷贝数据的大小，数据越大，效率越低。** 所以在实际开发中，往往如果想提升一下效率，那么我们会使用地址拷贝，也就是使用引用传递的方式来处理。

#### 哪些类型是值传递，哪些是引用传递

我们再回顾一下，值传递和引用传递分别有哪些数据类型？还有印象吗？

| 传递方式 | Go 中的类型 |
| :--- | :--- |
| **值传递** | 基本数据类型（`int`、`float`、`bool`、`string`）、数组、结构体 |
| **引用传递** | 指针、切片（slice）、`map`、管道（channel）、`interface` |

在这里引用传递其实我们只讲了一个指针，像切片、`map`、管道、`interface` 我们还没有讲过，但我先把它放到这个地方，大家有个初步的印象。

> **结论**：**大家记住啊，这是一个考点。** 面试官包括我们实际开发的时候，也会经常用到这个知识点。你要非常清楚地知道哪些是值传递、哪些是引用传递，这样你在做开发的时候才不会迷茫。

#### 值类型和引用类型的内存差别

**值类型默认就是值传递**，它是怎么样子的呢？就是变量直接存储值。比如我们画在内存里，比如 `number = 100`，那这个 `number` 它就直接和这个值关联起来了；就是说这个 `number` 如果取地址的话，这个地址就是你这个值所对应的那个地址。

```text
   值类型：number = 100

        ┌───────────┐
        │  number   │ ──────────▶ ┌───────────────┐
        └───────────┘   存储值    │  100          │
                                    └───────────────┘


   引用类型：ref

        ┌───────────┐            ┌───────────────┐    ┌───────────┐
        │   ref     │ ────────▶ │    地址       │───▶│  真正的值 │
        └───────────┘   存储地址  └───────────────┘    └───────────┘
                          堆上分配的空间

        当没有任何变量引用这个地址时
        → 该地址对应的数据空间成为垃圾
        → 由 GC 回收
```

那如果说你是引用类型的数据，那默认就会是引用传递。这个时候呢**变量存储的是个地址，这个地址对应的空间才真正存储了数据**。内存一般来讲是在堆上分配。当没有任何变量引用这个地址的时候，该地址对应的数据空间就会成为一个垃圾，由 GC 来回收。

**最后，如果希望函数内的变量能够修改函数外的变量，也就是说希望把默认的值传递方式改成引用传递，怎么办呢？传变量的地址就可以了。** 这个我们在前面说过，就不重复了。

关于这个知识点，要求同学们一定要把它记下来。**如果这个地方记不住，你后面做开发的时候一定会比较迷茫。** 这是一个结论性的东西，一定要把它记住。

### 局部变量：出了函数就用不了

**在函数内部声明或者定义的变量，我们把它称之为局部变量。作用域仅限于函数内部。**

注意，我不管你是首字母大写的还是小写的，只要你是在函数内部声明或者定义的，那么它就是局部变量。

新建一个文件夹 `varscope`——变量的范围。我们来看例子：

```go
package main

import "fmt"

func test() {
	var age int = 10
	var Name string = "汤姆"
	// age 和 Name 的作用域仅限于 test 函数内部
}

func main() {
	// fmt.Println(age)   // 这里用不了，报 undefined: age
	// fmt.Println(Name)
}
```

我告诉大家，这个 `age`、这个 `Name`，它们的作用域仅限于 `test` 这个函数内部。**如果出了这个函数，那 `age` 和 `Name` 就用不到了。尽管你首字母大写也没有用，也没有用。**

如果你在这儿用一下，肯定是要报错的：它直接会告诉你这个 `age` 是没有定义过的，`undefined`。

> **结论**：在函数内部定义的或者声明的变量，它的作用域只能在本函数内部，在别的地方用不了。

### 全局变量：首字母大小写决定能走多远

**在函数外部声明的变量，我们就叫全局变量。** 它的作用域在整个包都有效；而且如果首字母是大写的，则作用域在整个程序都有效。

也就是说你在外面写的，不管首字母是大写的还是小写的，在整个包都已经有效了；如果首字母是大写的，那么在整个程序都有效，也就是说在别的包也能使用。

看一个案例：

```go
package main

import "fmt"

var age int = 50    // 首字母小写：本包可用
var Name string = "jack" // 首字母大写：整个程序可用

func test() {
	var age int = 10
	var Name string = "汤姆"
	fmt.Println(age)   // 10
	fmt.Println(Name)  // 汤姆
}

func main() {
	fmt.Println(age)   // 50
	fmt.Println(Name)  // jack
	test()              // 10、汤姆
}
```

注意这两个 `age`——虽然名字一样，但是实际上它们是不同的变量，因为它们的作用域是不一样的。我在 `main` 里输出 `age` 和 `Name`，都不报错，输出的是 **50** 和 **jack**。调用 `test` 函数，输出的是 **10** 和 **汤姆**。

> **易错点**：这里的 `age` 全局变量，你在别的包是用不了的；这个 `Name` 在别的包是可以使用的。

这一点是不是在前面我们讲过的案例里有一个很像的？还回忆一下——讲 `init` 函数的时候，是不是讲过一个类似的案例？`main` 里面我们用到了 `utils` 包里面的 `Age` 和 `utils` 包里面的 `Name`，你凭什么可以用？

**原因就是 `utils` 里面这两个变量是大写的。**

那如果你把它改成小写呢？那我告诉大家，你在这里面就用不了。你把名字改了小写，保存一下——你看已经报错了，它说 `cannot refer to unexported`，就是不可导入的一个值，`utils` 里面的 `age`。因为它小写了，已经用不了了；但是另一个 `Name` 没有报错，这个地方是 OK 的。

你要用的话只能是怎么样呢？**你要把它做成一个首字母大写的。因为只有首字母大写的这种全局变量，它在本包可以用，而且在其他包也可以使用，类似于 `public`。** 我再恢复成大写，一保存马上就提示没有错误了。

请同学们引起重视。我们在写代码的时候一定要把这个搞清楚。

### 代码块里的变量：出了块就不认了

如果一个变量是在一个代码块里边——什么叫代码块？比如说 `for` 这个控制语句，或者是 `if` 控制语句，那么我们就认为这个变量是在代码块。那么**这个变量的作用域就只在该代码块生效，出了这个代码块，不认了。**

这块也是同学们需要注意的，因为有些编程语言里面你在 `for` 这个地方定义的变量它是可以用的，但是在 Go 里面它**不许可**。

```go
for i := 0; i <= 10; i++ {
	fmt.Println("i =", i)
}
```

这个没毛病吧？比较简单，不运行大家都知道肯定是输出 0 到 10。但是同学们注意一个问题：你在这个地方相当于定义了一个 `i`，那你在下面就用不了了。

比如说："老师，我想输出一下当这个 `i` 退出 `for` 循环的时候，这个 `i` 等于多少。"你在这用，它是用不了的，马上就报 `undefined: i`。

为什么？因为你是在这个 `for` 代码块里边定义的，那出了这个 `for` 循环就没用了。

那如果我们在下面再来定义一次，它也不会报重复定义的错误：

```go
for i := 0; i <= 10; i++ {
	fmt.Println("i =", i)
}

for i := 0; i <= 10; i++ {
	fmt.Println("i =", i)
}
```

有些同学说："老师你看，上面有个 `i`，相当于定义了一个 `i` 等于 0，下面怎么又搞了一个 `i` 等于 0，它们不是重复定义吗？"

**没有。** 因为这个 `i` 的作用域只在这个 `for` 代码块，出了这个 `for` 循环它就没用了。所以我在这儿定义一个 `i`，人家认为是新的 `i`。

那有同学问了：如果我就希望 `for` 代码块里面的变量既可以被 `for` 循环使用，也可以被外面的输出语句使用，那又怎么做呢？

很简单，你可以这么干：

```go
var i int
for i = 0; i <= 10; i++ {
	fmt.Println("i =", i)
}
fmt.Println("i =", i) // for 循环执行完毕后的 i
```

注意，我相当于把这个 `i` 写在外面，然后 `for` 的初始化位置就只是一个赋值了。那相当于说这个 `for` 循环里面用的 `i` 是在外面定义的，那它的作用域就是一个局部变量了——大家都知道局部变量是在整个函数体有效，那我再输出这个 `i` 就没有问题了，它就是 `for` 循环处理完毕过后等于多少就是多少。

如果你一定希望代码块里面的变量除了在代码块能用、在别的地方也可以用，那你可以把这个定义到外面去；甚至说定义到最外面去作为一个全局变量也可以。就看你的需求。

这块跟别的编程语言里面还真是有一些区别，所以要强调一下。老师这儿举的例子是 `for` 循环的，`if` 语句也是一个道理，我就不再举例子了，因为这个也并不难。

### 两个作用域练习

同学们注意，如果说你们是在听视频的，可以暂停一下，先自己想一想下面这段代码输出什么内容，然后再听分析。

#### 就近原则：局部遮住全局

第一个，这里有一个全局变量 `name`，首字母是小写的。它首字母小写就意味着它在本包都是可以使用的。

```go
package main

import "fmt"

var name string = "汤姆"

func test01() {
	fmt.Println(name) // 汤姆
}

func test02() {
	var name string = "杰克"
	fmt.Println(name) // 杰克
}

func main() {
	fmt.Println(name) // 汤姆
	test01()          // 汤姆
	test02()          // 杰克
	test01()          // 汤姆
}
```

- `main` 里的 `name` 在函数内没有定义，就去外面找，找到全局变量 `name`，它首字母小写但在本包可用，所以没有问题，输出"汤姆"。
- `test01` 里的 `name` 在本函数也没有定义，那它就直接使用外面的全局变量，因此也输出"汤姆"。
- 紧接着调用 `test02`。**注意看，`test02` 里面它定义了一个 `name`。问题来了：你局部变量有个 `name`，全局变量也有个 `name`，那这会儿会报错吗？先告诉大家，不会报错。**

原因是因为：**当全局变量和局部变量有相同名的时候，它会采用一个就近原则。** 编译器采用就近原则，以你这个为准，那这个地方就会输出"杰克"。

- 紧接着他又输出了 `test01`。**注意听，这个 `test01` 又重新调了一次。** 再调一次，注意听，你这个"杰克"是在 `test02` 里定义过的，因此它的改变并不会影响到全局变量的改变，所以它会再次输出一个"汤姆"。

所以最终结果是：**汤姆、汤姆、杰克、汤姆**。跑一下，输出内容跟分析的是完全一致的。

那我再请同学们思考一个更有意思的：**如果我把 `test02` 里面那个冒号去掉**，也就是写成 `name = "杰克"`，代码会报错吗？**不会报错。** 但是此时此刻输出内容会不会发生变化？

会。你如果说这地方没有冒号，就相当于说把这个"杰克"重新赋给这个全局变量了。也就是说这个时候全局变量的 `name` 是一个"杰克"了。那么这个地方会输出"杰克"，然后当它调用完了过后，`test01` 再去输出 `name` 的时候，这次也会输出"杰克"——因为你在这个地方相当于修改了全局变量的 `name`。

所以这样子运行的结果是：**汤姆、汤姆、杰克、杰克**。跑起来，果然如此。这是一个很有意思的案例，大家好好去想一想。

#### 陷阱：`:=` 写在函数外会报错

第二个案例：

```go
var age int = 20
Name := "汤姆"
```

第一句话应该是 OK 的，没有毛病。但第二句话行不行？

乍看一眼你感觉好像，这个跟上面不是一样吗？**其实这是不一样的。** 这个是在定义的时候就同时赋了值，而 `var age int = 20` 是显式写了类型。

`Name := "汤姆"` 这句话实际上是**等价于两句话**：

```go
var Name string
Name = "汤姆"
```

问题就出在这里。因为我们这个地方——这个定义它是在**函数外**定义的。在函数外你去定义一个变量没有毛病，你去初始化一个变量也没毛病，**但是你不能有赋值语句**。

因为大家都知道赋值语句它是一种**执行语句**，这种执行语句它是要在函数体内才能执行的。因此 `Name := "汤姆"` 等价于这两句话的时候，那这句赋值是不能够在函数外执行的——它**隐藏了一个赋值语句**，而赋值语句是不能够在函数体外执行的。所以这个地方就会报错。

在 VS Code 里一写，保存一下马上提示错误：

```text
syntax error: non-declaration statement outside function body
```

什么意思呢？就是说你这里面有一个不能够放在函数体外的一个语句。哪个语句？就是因为你这边其实隐藏了两条语句：一个是声明，一个是赋值。而这个赋值语句是不允许在外面执行的，所以说这个写法是错的。

> **易错点**：这是一个**使用陷阱**，一定要高度重视。一定不要这么去用。如果你错了的话，你别说老师没有讲过——老师是讲过的。

### 把以前的老案例封装成函数

接下来做几个关于函数的课堂练习题，来实际地把函数应用到一个练习之中去。

我们在前面讲 `for` 循环的时候，写过两个案例：一个是打印金字塔，另一个是打印九九乘法表。但是当时我们**没有用函数**，是纯的面向过程的方式写出来的。

#### 打印金字塔

第一题：**编写一个函数，从终端输入一个整数，打印对应的金字塔。**

这个金字塔的分析我就不多废话了，因为前面讲打印金字塔的时候我们分析得还是比较清晰的——当时用了两个非常经典的技巧：**一个是先死后活，一个是先易后难**。这里就不再重复了。

思路很清晰：将原来写的打印金字塔的案例，使用函数的方式封装起来，在需要打印时直接调用即可。

既然要打金字塔，是不是我得知道层数？于是我先定义一个层数 `totalLevel int`：

```go
func printPyramid(totalLevel int) {
	// 这里就是第五章多重循环控制里那个打印金字塔的核心代码
	// 先死后活、先易后难，原来怎么写这里就怎么写
	// 要打实心金字塔的话，把判断空心位置的那个 if/else 去掉即可
}
```

我这边接收了一个 `totalLevel`，其他地方完全不用改。你要做的就调用它一下——调用 `printPyramid` 这一个函数就可以打印金字塔。

那我们能不能这样做呢？我先给它传一个 9 吧，跑起来，金字塔已经打出来了，而且我这儿打的是**空心金字塔**。那有些同学说我不想打空心金字塔怎么办？还记得怎么做的吗？是不是把处理空心位置的那段 `if/else` 去掉就行了？老师讲过的，**打空心金字塔比打实心金字塔要难**。

好，这块就已经完了。但是人家要求是怎么写的？他说从终端输入一个整数，打印对应的金字塔。我这个是空心的，如果你要跟它保持一致的话，其实很简单，把那个 `if` 去掉就行了，就都打。既然人家说的是打实心，我们也不要多此一举了，就这么写就行。

那现在问题来了：你这是写死的 9，但是人家要求是从终端输入一个整数。那我们处理一下：

```go
func main() {
	var n int
	fmt.Println("请输入打印金字塔的层数")
	fmt.Scanln(&n)
	printPyramid(n)
}
```

大家还记不记得为什么 `Scanln` 一定要传个地址进去？现在理解了吧？**因为你传这个地址进去，那么外面这个 `n` 才会变化。如果你传的不是地址的话，那里面改了你外面不改啊。** 现在是不是对它理解得更清晰了？

跑一下：他说请你输入层数，我输一个 4，是不是打印 4 层？再来，我输一个 8，打印的就是 8 层，可以了。

#### 打印九九乘法表

第二题：**编写一个函数，从终端输入一个整数（1 到 9），打印对应的乘法表。**

思路跟前面几乎是一样：将原来写的打印九九乘法表的案例用函数的方式封装，在需要打印时直接调用即可。

```go
func printMulti(num int) {
	// 这里就是第五章那个九九乘法表的核心代码，原样搬过来即可
}
```

这里接收一个整数 `num` 就可以了，没有返回值——因为打印九九乘法表打出来就完了嘛。

怎么来调用呢？跟前一样，我从控制台或者终端输入一个整数，表示要打印的乘法表对应的数。比如你传的是 9，就是九九乘法表；你传的是 8，那就是相当于八八乘法表了。

```go
func main() {

}
```

这个地方跟前两句话其实是一样的，我就偷一个懒了。注意调用的时候，因为它是基本数据类型，咱们直接传一个值过去就行了。

跑一下：它会让我们输入一个九九乘法表对应的数，我写 9，打一个九九乘法表，完全正确。我改一下，比如说我要打印到 8 就就可以了，不打印到 9，一样的，没问题。

通过这个案例我们可以看到，其实把我们的功能封装到一个函数里面去调用，应该会**更加方便**。我们在做程序开发、做项目的时候，如果能够把一些功能封装到函数中，咱们尽量把它封装到函数中，这样会有利于我们后面的调用，代码看起来也比较简洁——你看这 `main` 干啥？打印个乘法表，一目了然，比原先直接把这个代码写在这儿，应该说更方便我们的阅读和维护，是不是这个意思？

## 字符串常用系统函数（上）：从 len 一路走到 Index

### len 返回的是字节数，不是字符数

第一个需要大家掌握的叫 `len(str)`。

这个函数是一个**内置函数**，也叫内建函数。也就是说它不在一个包里面，它是一个内建的，你直接就可以用，不需要引什么特别的包。

那内建函数在手册里面在哪去查呢？搜一个叫 `builtin`，翻一下——这就是内建的，它不需要你引。里面像 `make`、`len`、`copy`、`delete`、`close`、`panic`、`recover`、`print`，这些都是，直接用就行了。

`len` 是一个内建函数，它返回的是你传进去的这个 `v` 的长度。**这取决于具体类型**——你这个类型是什么，它就按照这个类型来给你把这个长度返回。它最常常用的就是计算字符串或者数组的长度，后面我们还会用到。

```go
package main

import (
	"fmt"
)

func main() {
	str := "hello"
	fmt.Println("str length=", len(str)) // 5

	str2 := "hello北京"
	fmt.Println("str2 length=", len(str2)) // 8
}
```

`"hello"` 的长度是 5，对不对？跑一下确实是 5。

那问题来了：如果你这方有中文会怎么样？我们来看一下，这里有个中文叫"北"，北京的那个"北"。大家猜一猜这边会输出多少？会是 6 吗？**不会是 6。** 输出的是 **8**。

为什么是 8 不是 6 呢？因为我们在前面讲过：**Golang 语言它的编码统统一定是 UTF-8。**

这个 UTF-8 是有具体细节的——字母、数字，还有 ASCII 码里面的东西，说白了就是 ASCII 码的字符。**ASCII 码的字符里面就包含了字母和数字，对不对？这个它占一个字节，注意听，占一个字节。**

> **结论**：**一个汉字占三个字节。** 前面有 5 个字母，再加上一个汉字 3，就 $5 + 3$ 等于 8，就这么来的。

从而说明我们这个 `len` 它其实是**按字节返回的，还是按字符返回的？说明 `len` 它是按字节返回**。如果按字符的话它应该返回 6 了，按字节就应该返回 8。

另外注意，`len` 除了可以统计字符串，它还可以统计数组的大小。

### 遍历带中文的字符串：先转成 rune 切片

第二个函数：**字符串的遍历，同时处理有中文的问题。**

也就是说如果一个字符串里面含有中文，那么我们需要先把它转成一个叫 `rune` 的切片，然后再对这个返回的变量进行一个遍历，这样才不会出现中文乱码。如果你不这样处理，你会发现它是一个乱码。

```go
	str2 := "hello北京"

	for i := 0; i < len(str2); i++ {
		fmt.Printf("字符=%c\n", str2[i])
	}
```

刚学了 `for`、刚学了 `len`，我们就这样写，`%c` 按字符格式化输出。`str2[i]` 就是取出这个 `str2` 里面的第几个元素，从 0 开始编号。

跑一下你会发现，前面 `hello` 这几个都 OK，但是到后面会出现乱码。**因为它是按字节遍历的，你想一个汉字占三个字节，那它肯定就被截断了**，因此这个不行。

那怎么处理呢？就得用刚才那个套路：**先把它转成 `rune` 的一个切片**。

```go
	r := []rune(str2)
	for i := 0; i < len(r); i++ {
		fmt.Printf("字符=%c\n", r[i])
	}
```

`[]rune(str2)` 就是把它转成 `rune` 切片。转完了过后再重新遍历，下面代码就不用变化了。

> **易错点**：这里还有一个坑。如果我写成 `str := []rune(str2)`，它会报错——**因为 `str` 这个名字上面已经定义成字符串了，数据类型已经定下来了**，你一转，转成 `rune` 切片，它就类型不匹配了。那我还是换一个名字吧，比如 `r`，这样就可以了。还有下面循环那里也记得要一起换成 `r`。

跑起来看效果，`hello` 完了过后，"北京"就出来了，不会再有乱码。

所以同学们以后如果要去遍历含有中文的字符串，可以先把它转成一个 `rune` 的切片，然后你就可以正常遍历了。

### 字符串和整数之间的转换

#### 字符串转整数：Atoi 会返回 error

第三个，字符串转整数。

如果我们想把一个字符串转成一个整数，当然前提是这个能够转。**如果它转不成功的话，它这个 `err` 会给你打印出错误**——所以说这个函数还有一个功能：如果转不成功会产生一个 `error`，你可以对 `error` 进行一个判断，这样就更好了。

在手册里怎么找呢？它对应的是 `strconv` 这个包。找到 `strconv` 往下划，搜一个叫 `Atoi`。它传一个字符串，给你转成一个 `int`；但是如果转不成功，它会把这个 `error` 给你打过来，`error` 就会有值。

```go
	n, err := strconv.Atoi("123")
	if err != nil {
		fmt.Println("转换错误，错误的原因是：", err)
	} else {
		fmt.Println("转换的结果是：", n)
	}
```

这里有两个点要讲：

- `err != nil` 就是错误，`nil` 是空值；如果不等于这个空值，那就说明它错误，我可以提示一句话，就是转换错误，错误的原因是什么呢？可以把它打印出来。
- 如果没有错，那这个 `n` 就是值了，`else` 就是转换成功了，把它打出来。这个 `n` 此刻就是个整数了。

跑一下，转换结果是 123，成功了，它转成一个整数了。

那如果我故意给一个不对的呢？比如 `"hello"`——`hello` 能转成一个整数吗？不可能，那这个 `err` 就会出现，它不等于 `nil`，它就会提示一个转换错误：**invalid syntax**，`hello` 转不了，它就报错了。

> **提示**：所以我们有时候可以利用这个特性来干什么事情呢？**对一个数据类型进行一个校验。** 比如说我们在输入的时候要求这个人必须输入一个数字的字符串，他不输怎么办呢？我验证出来了，然后给他相应的提示，不就完事了吗？这也是有用的。

#### 整数转字符串：Itoa 直接转

第四个，**整数转字符串**。

这个它就直接转了，因为你这个整数必定能转成字符串，即使你给的是其他的它也能转成字符串，所以它就没有这个 `err` 这个东西了，就直接转。

```go
	str := strconv.Itoa(12345)
	fmt.Printf("值=%v 类型=%T\n", str, str)
```

把它的值输出来，同时把它的类型也输出来（`%T` 打类型）。跑一下，值是 `12345`，而且类型是 `string` 了，转完了过后它的类型肯定也发生变化了。

### 字符串与字节切片互转

#### 字符串转 byte 切片

第五个，字符串转成一个 byte 切片。

什么时候需要这么做呢？比如说现在有一个字符串，但是有时候我需要把这个字符串写入到一个二进制文件或者一个什么文件，那我要把它转成一个 byte，数据类型才能匹配。

把字符串写到后边，前面用一个 byte 的切片来强转就行了：

```go
	b := []byte("hello")
	fmt.Printf("bytes=%v\n", b)
```

注意这个时候你在输出的时候，它就是按照这个 byte 本身的值输出了。这个输出的是什么呀？输出的就应该是按照对应的 ASCII 码。

跑起来看效果：

```text
104 101 108 108 111
```

这是不是老师以前讲过？这个对应的数字就是编码，它对应谁的编码？就是对应你这个字母的编码，**ASCII 的字母编码**。

#### byte 切片转字符串

第六个，**把 byte 转成字符串**，这个用的也很多。

有些时候我要反过来用，就是说我给你了一个 byte 切片或者是一个数组，我要把它转成一个字符串。因为有时候我想把它按字符串的输出，怎么办呢？很好办，你转一下就行。

```go
	str := string([]byte{97, 98, 99})
	fmt.Printf("str=%v\n", str)
```

这样一做的话，就相当于把 97 转成了一个对应的字符，把 98 转成一个对应的字符，把 99 转成它对应的那个字符，并且组成一个字符串返回给它。

那最后打印出来的就应该是 97 对应的字符、98 对应的字符、99 对应的字符形成一个字符串。跑一下，直接输出字符串了：**`abc`**。

为什么是 `"abc"`？**因为 `'a'` 对应的 ASCII 码的值就是 97，`'b'` 对应 98，`'c'` 对应 99**，就是这个道理。

### 进制转换：FormatInt

第七个，有时候我们需要把一个十进制的数转成二进制或者八进制或者十六进制，有这种需求。如果需要转的话呢，可以用 `strconv` 里面一个叫 `FormatInt` 的这么一个函数来完成。

在文档里很好查：点进去，这地方它让你传一个 `int64` 的 int 值，然后呢这传一个 `base`，这个 `base` 里面就可以写 2、8、16，就转成它对应的值，然后会返回一个字符串。

```go
	str := strconv.FormatInt(123, 2)
	fmt.Printf("123对应的二进制=%v\n", str)

	str = strconv.FormatInt(123, 16)
	fmt.Printf("123对应的十六进制=%v\n", str)
```

跑一下看效果：**123 对应的二进制是 1111011，123 对应的十六进制是 7b。**

有些同学说老师我想把它转成八进制行不行？当然也可以，你把 16 改成 8 就行了。

> **结论**：就是有时候需要转的话，咱们可以用 `strconv` 里面的 `FormatInt` 这一个函数来完成十进制和其他进制的转换，非常的简单。关于转换的原则，前面已经讲过了，这块就不再赘述。

### 查找子串：Contains 与 Count

第八个：**在子串中是否在指定的字符串**，就是查找一个子串是否在指定的字符串中。如果有，返回一个布尔值为真；如果没有，返回一个布尔值为 `false`。

它是在 `strings` 这个包里面，有个叫 `Contains` 的函数。这个函数里面第一个传的是你的这个字符串，第二个传的是子字符串。就是说这句话什么意思呢？就是要去看在这个字符串里边有没有 `"foo"`。

文档里写得清清楚楚：**判断字符 `s` 是否包含子串 `substr`**，如果有返回真，如果没有返回假。

```go
	b := strings.Contains("seafood", "foo")
	fmt.Printf("b=%v\n", b) // true

	b = strings.Contains("seafood", "mary")
	fmt.Printf("b=%v\n", b) // false
```

`"seafood"` 里面有没有 `"foo"`？有啊，所以它应该返回一个真。

那如果我改成 `"mary"` 呢？`"seafood"` 里面有没有 `"mary"`？没有，那它肯定就返回一个 `false`。跑一下确实如此。

> **易错点**：这里我第一次跑的时候报错了——**因为没有引 `strings` 这个包**。用了一个新的包，理论上说你要把它引进去。把 `strings` 引进去过后再来跑就正常了。

第九个：**统计一个字符串中有几个指定的子串**。看一下手册，它还是 `strings` 里面的 `Count`，返回字符串 `s` 中有几个不重复的子串。其实说白了就是看这个字符串里面有几个这样的子串。

```go
	// 统计一个字符串中有几个指定的子串
	var str string = "cheese"
	var count = strings.Count(str, "e")
	fmt.Printf("count=%v\n", count) // 4
```

这个地方会返回一个整数，用 `count` 来接收。`"cheese"` 里面有几个 `e`？1、2、3、4，四个，所以它会返回 **4**。

那我改一下，比如说改成了 `"se"`，`"cheese"` 里面会返回几个？这里只有一个，返回 **1**。那如果一个都没有呢？比方说在这找了一个 `"u"`，里面就没有完全一样的，`count` 就会返回 **0**。

大家可以根据实际情况来使用。有时候会需要这种功能，比如说我们要查找一篇文章，看这一篇文章里面有几个这样的关键词，用一个 `Count` 一下就搞定了，它是有用的。

### 字符串比较：== 与 EqualFold

第十个，这个也是用得非常多的：**如果我们要进行字符串的比较，有两种方式。**

第一种就是两个等号，两个等号是可以来判断两个字符串是否相等的，但是**两个等号在判断的时候是区分字母大小写的**。也就是说，等号要求内容和字母大小写都要相同才是为真。

但是有时候我们在比较的时候不想区分字母的大小写，这时请使用 `strings` 包里面的 `EqualFold` 函数，**这个函数是不区分大小写的**。

```go
	// 不区分大小写的字符串比较(==是区分字母大小写的)
	b := strings.EqualFold("abc", "Abc")
	fmt.Printf("b=%v\n", b) // true

	fmt.Println("结果", "abc" == "Abc") // false
```

我们可以看到 `b` 返回 `true`，因为 `EqualFold` 不区分大小写。但是如果用 `"abc" == "Abc"` 呢？它会返回 `false`，因为两个等号是区分字母大小写的，所以它会返回一个 `false`，除非完全相同。

跑起来，确实是 `false`。这个时候用等号来判断，它认为这两个是不等的，因为它是区分大小写的——一个首字母是小写的 `a`，一个是大写的 `A`，自然就不相同了。

| 写法 | 是否区分大小写 | `"abc"` 与 `"Abc"` 的结果 |
| --- | --- | --- |
| `a == b` | 区分 | `false` |
| `strings.EqualFold(a, b)` | 不区分 | `true` |

这也提醒大家，如果将来做**密码校验**的时候，你要不要区分大小写？如果要区分大小写，就用等号；如果不区分大小写，用 `EqualFold` 就可以。

### 找到子串的位置：Index

这一部分的最后一个：**返回子串在字符串中第一次出现的 index 值，如果没有就返回 -1。**

其实这个有两个用处：第一个，可以去找这个子串在串里面出现的下标；第二个，也可以用它来判断串里面有没有这个子串，因为如果没有的话会返回 -1。这是一举两得的事情。

```go
	// 返回子串在字符串第一次出现的index值，如果没有返回-1
	index := strings.Index("NLT_abc", "abc")
	fmt.Printf("index=%v\n", index) // 4
```

`"abc"` 出现在这个位置，数一下下标：`N` 下标为 0，所以 0、1、2、3、4——`a` 实际上是在第四个下标位置，因为它是从 0 开始算的，所以这个地方会返回 **4**。

那我再问大家一个问题：如果我写一个 `"hello"` 呢？`"hello"` 在 `"NLT_abc"` 里面没有出现，因此会返回 **-1**。**所以你可以通过返回是不是 -1 来决定它是否找到了子串。**

如果假设有多个 `"abc"` 呢？它其实是找到**第一次**出现的位置。有些同学说想找最后一次呢？它一定也有类似的函数，去手册找一下就行了，会有类似 `LastIndex` 的函数，找最后一次出现的。`Index` 是找第一次出现的那个值。

### 替换子串：Replace

第 13 个：**将指定的子串替换成另外一个子串。**

这里面有个函数叫 `Replace`。我们看一下它是什么意思。比如说我这儿有 `go go hello`，那么这个 `go` 就是我想替换的，我想把它替换成 `Go语言`。

那么这个地方后面有个 `n`，这个 `n` 指定你希望替换几个。**如果你写的是 -1，则表示全部替换。**

```go
	str := strings.Replace("go go hello", "go", "北京", 1)
	fmt.Printf("str=%v\n", str) // 北京 go hello

	str = strings.Replace("go go hello", "go", "北京", -1)
	fmt.Printf("str=%v\n", str) // 北京 北京 hello
```

先看 `n` 写 `1` 的情况：把这个 `go` 换成 `北京` 的话，那第一个这个 `go` 就会变成 `北京`，第二个 `go` 就不会变了，它只会变一个。跑起来正是如此。

如果你想全部换，直接写 -1 就可以。你看这边换北京，这边也换成北京了，是不是？如果要换两个，那就写 2。

> **提示**：这个地方实际上**也可以是个变量**。大家不要认为这个地方必须写成一个常量，这里也可以是个变量——比如说我把这个字符串直接放到 `str2` 这个变量里面去，那我也可以把 `str2` 直接放在这个位置来，效果是一样的。

#### 一个关键点：原串不变，返回的是新串

我要强调一点：**替换完了以后，`str2` 有没有变化？**

**`str2` 是不会变化的。** 它是把 `str2` 里面的内容替换完了过后，返回了一个**新串**——`str` 是个新串，那 `str2` 本身并没有发生变化。

大家千万不要认为说我替换完了过后 `str2` 本身也发生变化了，**而是返回了一个替换过后得到的新串。这点请大家一定要搞清楚。**

我们把 `str2` 本身也打印出来验证一下：被替换过后的新串是"北京 北京 hello"，但是原先的那个仍然是 `go go hello`。

### 按分隔符拆分成数组：Split

第 14 个：**按照指定的某个字符进行分割，将一个字符串拆分成字符串数组。**

数组这块虽然我们还没有学，但是大家简单地看一下应该问题也不大。

什么意思呢？比如说我给了一个字符串，但是我我想把这个字符串按照后面指定的字符进行一个拆分，把它拆分成一个新的字符串，这个用的很多。

```go
	str := "hello,world,ok"
	strArr := strings.Split(str, ",")
	fmt.Printf("strArr=%v\n", strArr)
	fmt.Printf("len=%v\n", len(strArr))

	for i := 0; i < len(strArr); i++ {
		fmt.Printf("index=%v value=%v\n", i, strArr[i])
	}
```

这里面不是有 `hello`、`world`、`ok` 吗？但是你看到这有一个逗号，这也有一个逗号，有两个逗号。这个逗号表示什么呢？就是代表**我待会儿要按这个逗号进行拆分**。

拆分完了过后，这有一个 `hello`，这有一个 `world`，这有一个 `ok`——也就是说这个数组就会有**三个元素**。为什么？因为我是按照逗号进行拆分的。

然后这里已经是可以遍历了。我们前面讲过 `len` 这个函数，它可以计算出数组或者字符串的长度，那这块就是一个数组了，它应该等于 3。

跑一下看效果：第一个元素，下标 0 是 `hello`；第二个元素，下标 1 是 `world`；第三个元素，下标 2 是 `ok`。

所以如果将来有一种需求，就是要将一个字符串进行某一种方式的拆分得到一个数组的话，就可以用 `Split`。

> **结论**：这个地方，也就是第三个参数，**也可以是一个字符串的变量**。同样，它**也不会改变这个字符串本身**，而是进行拆分形成一个数组过后得到的一个新的数组。

这一点跟前面讲的 `Replace` 是**一样的道理**：它是得到一个新的。如果真的要改变的话，那一定是传一个引用进去才会被改变，但实际上大家看，传的并不是引用，而是传了一个**值拷贝**。也就是说这个 `Split` 拿到的是它的一个值拷贝，因此它在里面做的变化并不会影响到这个串本身。

### 大小写转换：ToLower 与 ToUpper

第 15 个：**如果我们在进行字符串大小写转换的时候，它也提供了一组方法，一个叫 `ToLower`，一个叫 `ToUpper`。**

比如说我们在进行密码验证的时候，假设我们不区分这个大小写，或者说大小写我们要统一进行验证，你可以先把它们进行一个大小写转换再进行判断，也是用得比较多的。

```go
	str := "goLang Hello"
	str = strings.ToLower(str)
	fmt.Printf("str=%v\n", str) // golang hello

	str = strings.ToUpper(str)
	fmt.Printf("str=%v\n", str) // GOLANG HELLO
```

这里大家看代码，这个字符串里面有小写的字母，也有大写的字母。现在我想把它统一地全部换成小写的。

这里有一个地方大家要注意——**我这次就想彻底地改变它，于是乎我把返回的结果直接交给了这个 `str`**。

那意味着什么？那意味着**这个 `str` 是会被改变的**。我们以前是给的新变量，比如给个 3，那这样子的话呢，`str` 是不会改变的；但是如果说我直接就把返回的结果返回给它，那当然上面这个也发生变化了。

所以全小写之后输出的是 `golang hello`。跑起来，正是全小写了。

当然有些同学说：老师，我要全部把它改成大写又怎么办呢？非常简单，你把 `ToLower` 改成 `ToUpper`，`ToUpper` 就是全部大写。跑一下，输出 `GOLANG HELLO`。

> **易错点**：所以这几个函数的区别大家一定要搞清楚——`Replace` 和 `Split` 你如果把结果交给**一个新变量**，原串是不变的；而这里 `ToLower`/`ToUpper` 如果你把返回值**直接交回原来的变量名**，那原变量就被改变了。**就看你怎么用。**

### 修剪字符串两端的空白与指定字符

#### TrimSpace：去掉左右两边的空格

第 16 个：**将字符串左右两边的空格去掉。**

比方说我这儿有一个字符串，它的左边有一个空格，右边有很多空格。有时候我们在进行字符串处理的时候，我们希望左右两边的空格被拿掉，怎么办呢？我们可以用 `strings` 这个包里面叫 `TrimSpace` 来处理。

```go
	str := "   hello   "
	str = strings.TrimSpace(str)
	fmt.Printf("str=%q\n", str) // "hello"
```

跑一下，两头确实没有了。

但如果说你想看得更细一点——"老师我不知道这边有没有，我看不出来怎么办呢？"——你可以写个 `%q`。写个 `%q` 的话，就看得更清楚了：它用两个双引号给你引起来打印出来，两边都看得更清楚。

#### Trim、TrimLeft、TrimRight：去掉指定的字符

第 17 个：**将字符串左右两边指定的字符串去掉。**

有些时候你是希望去把左右两边指定的字符串去掉，这个时候可以这样写：

```go
	str := " ! hello ! "
	str = strings.Trim(str, " !")
	fmt.Printf("str=%q\n", str) // "hello"
```

大家看这个字符串，我想去掉的是什么呢？我想去掉这个叹号，还想去掉空格——我想把它左右两边的叹号和空格同时去掉。

怎么写呢？**我先写一个空格，代表我要去掉空格；我还想去掉叹号，那我就把这个叹号写到这儿。** 这后面写的东西是什么意思呢？就是我想把左右两边的哪些去掉，我就写上就行了。这就代表我要去掉空格，同时我还要去掉左右两边的叹号。

> **易错点**：**中间的去掉不了。** 注意，你中间有个叹号它是去掉不了，它是去掉左右两边的。

跑一下，左右两边的确实被去掉了，但是中间它没有办法，中间它去不掉。

那如果说我把这个叹号拿掉，也就是只写 `" "`，那这就相当于**只去掉左右两边的空格**，前面这个地方就会被保留。

第 18、19 个：**如果说你只想去掉左边的，你就把 `Trim` 改成 `TrimLeft`；如果你只想去去掉右边的，那你就用 `TrimRight`。**

`TrimLeft` 和 `TrimRight` 和这个几乎是一样的，只是说 `Trim` 是代表把左右两边指定的字符都去掉，而 `TrimLeft` 是去掉左边的，这个是去掉右边的，仅此而已。这个我就不举例了，因为也比较简单。

### 判断前缀与后缀：HasPrefix 与 HasSuffix

最后两个，这两个函数其实我们已经用过一次了——**在讲闭包的时候我曾经用过 `HasSuffix`**。

**`HasPrefix`：`prefix` 就是前缀的意思，判断字符串是否以某个字符串开头。**
**`HasSuffix`：`suffix` 就是后缀的意思，判断字符串是否以指定的字符串结尾。**

如果确实是这样子，就会返回一个 `true`；如果不是，则返回一个 `false`。

```go
	b := strings.HasPrefix("ftp://abc.com", "ftp")
	fmt.Printf("b=%v\n", b) // true

	b = strings.HasPrefix("http://abc.com", "ftp")
	fmt.Printf("b=%v\n", b) // false
```

它判断这个字符串是否是以 `ftp` 打头的。你的的确确是以 `ftp` 打头的，所以它返回一个 `true`；如果我这儿写成了一个 `http`，这个时候就返回一个 `false`。

后缀这个是一样的，老师就不举例了。一个是判断前面是不是以这个打头，而这个是判断你这个字符串是不是以指定的这个字符串结尾，这个我也不举例了，也比较简单。

**关于我们 Golang 里边的字符串函数，我们常用的就是这 21 个**，希望同学们把它掌握。在后边我们写项目的时候，会经常使用到这 21 个常用的字符串函数。

### 时间与日期函数入门

下面给大家介绍一下 Golang 里面的日期和时间相关的函数。大家都知道，我们在编程的时候肯定会用到日期相关的函数。

比如说要去记录下订单的日期，肯定是需要时间函数的；再比如说要去统计某一段代码执行的时间，那么也会用到时间和日期相关的函数。**时间和日期相关的函数用的也是非常普遍的。**

#### 先导包，再认类型

要用 Golang 里面的时间和日期相关的函数，首先需要引入一个包，叫 `time` 包。换言之，**在 Golang 里面时间和日期相关的函数都是放在 `time` 包里面的**。这个包提供了时间的显示和测量用的函数，时间相关的函数几乎都放在这里，非常丰富。

在 Golang 里面有一个类型叫做 `Time` 类型，就是 `time.Time`。它是 `time` 包里面定义的类型，它本身也是一种数据类型，是**专门用于表示时间的**。

#### 获取当前时间：time.Now

我们新建一个包 `time_func`，新建一个文件叫 `main.go`，先打包，引入 `fmt` 包，当然还要引入 `time` 包。

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	now := time.Now()
	fmt.Printf("now=%v now type=%T\n", now, now)
}
```

运行一下，输出是：

```text
2019-05-18 10:14:15.123456789 +0800 CST m=+0.000000001
```

这不太容易看清楚，但是也能看得出来这个时间大概是什么样子的。**但是后面有一堆时区和纳秒数，所以我们在实际用的时候往往会对它进行处理。**

再看类型，刚才得到的 `now` 的类型实际上是 `time.Time`。

> **提示**：`Time` 其实是一个结构体，虽然大家现在还没学结构体。点进手册里能看到它返回的是个结构体，结构体里面有很多的方法：往下看有 `Unix`、`UnixNano`、`Equal`、`Before`、`After`，还有 `Year`、`Month`、`Day`、`Hour`、`Minute`、`Second`。

#### 取年月日时分秒

既然如此，我就用 `now` 相关的方法来获取需要的年月日和时分秒：

```go
	fmt.Printf("年=%v\n", now.Year())
	fmt.Printf("月=%v\n", now.Month())
	fmt.Printf("日=%v\n", now.Day())
	fmt.Printf("时=%v\n", now.Hour())
	fmt.Printf("分=%v\n", now.Minute())
	fmt.Printf("秒=%v\n", now.Second())
```

其他以此类推：月就是 `now.Month()`，日就是 `now.Day()`，时是 `now.Hour()`，分是 `now.Minute()`，秒是 `now.Second()`。

执行一下，可以看到我们拿到了当前的年月日时分秒。但是大家看到这里返回的是英文的 `May`，是 5 月。怎么把英文的 `May` 改成中国人喜欢的数字呢？**非常简单，强转一下就行了**：

```go
	fmt.Printf("月=%v\n", int(now.Month())) // 月=5
```

用一个 `int` 直接给它强转就可以了，这个月份就可以看到是国人喜欢看的那种数字了。

#### 格式化的两种方式

拿到日期信息过后，往往我们在输出的时候不可能这样一行行输出年月日时分秒，往往会给它来一个格式化，一下子就能看出当前是某年某月某日某时某分某秒。

在 Golang 里面格式化日期和时间有两种方式。**方式一比较原始**，直接用 `Printf` 这种方式来输出；如果你想返回字符串，就用 `Sprintf`。`Sprintf` 和 `Printf` 的区别在哪里？**`Sprintf` 就是把字符串拿到，`Printf` 就是直接输出。**

```go
	fmt.Printf("当前年月日 %d-%d-%d %d:%d:%d\n", now.Year(),
		now.Month(), now.Day(), now.Hour(), now.Minute(), now.Second())

	dateStr := fmt.Sprintf("当前年月日 %d-%d-%d %d:%d:%d",
		now.Year(), now.Month(), now.Day(), now.Hour(), now.Minute(), now.Second())
	fmt.Printf("dateStr=%v\n", dateStr)
```

因为这个函数很长，如果不换行，全部写到一行就很痛苦了。那怎么办？咱们允许换行，你这样换一下行就行了。**但换行的时候一定要保证上面有个逗号。**

年月日后面的 `02` 也可以不要，可以保留也可以保留。大家看出来什么意思了吗？我的格式化是：`%d`、`%d`，这不都是整数吗？这都是整数。第一个就对应这个值，`Month` 对应这个值，`Day` 对应这个值，以此类推。最后输出的就是我们中国人比较喜欢看的年月日时分秒。

**当然这个间隔符你可以自己设置**，这边打空格也可以，这边打空格也可以，这个我就不多啰嗦了。但是你这个 `%d` 最好是保持这个样子就行。

如果你不喜欢用这种中划线来间隔，你也可以改成你习惯的，比如说"我就喜欢用空格"，也没有强求。中间就是空格了，就看你的习惯；不过我们国人一般来说还是喜欢有一个中划线把它间隔一下。

那有些同学就说："老师，我们能不能把这个字符串本身拿到呢？"也可以。比如说你打一个 `S`，`S` 过后你会拿到一个字符串，像 `dateStr`，那这样子它是在格式化了过后把这个字符串返回给这个变量，那你就可以用这个变量做相应的处理，比如说保存到数据库里边，或者是做其他的处理。

> **易错点**：这里用的一定是 `Sprintf`，**不能写成 `printf`**——因为你是格式化输出的嘛，所以说你得用那种格式化的方式来处理，不然的话这儿有问题。

第一种方式先放到这里来。实际上说白了就是用了一种这种方式；还有一种方式，就是也有可能是你需要把它处理完了过后，把这个字符串返回给一个变量，然后再在这个变量基础上再进行输出或者是保存。

**方式二就是用 time 给我们提供的一个方法叫 `Format`。**

```go
	timeStr := now.Format("2006-01-02 15:04:05")
	fmt.Printf("timeStr=%v\n", timeStr)
```

`now` 不是 time 类型吗？它里面有一个 `Format` 这个方法，其实是它的一个方法。它里面直接写清楚一个字符串。

**同学们注意，我标红的这一部分是它固定的写法，固定的写法。** 这个有点不太好理解：为什么必须写 `2006/01/02 15:04:05` 呢？它必须这么写，各个数字是固定的。但是**你可以自由组合**：如果说你只想输出年月日，那你就写 `"2006-01-02"`，这个 `01` 就代表月，`02` 就代表日；如果说你只想得到时分秒，你就写 `"15:04:05"` 就行了。

> **结论**：这个 layout 是有讲究的——官方文档里说明了，格式串是**基于一个参考时间**来定义的：**2006 年、1 月、2 日、15 时、04 分、05 秒**。这个 layout 里各个数字**都不重复**，所以它才能区分得开："01" 就是月，"2006" 就是年。你如果只想要月份，写个 `"01"` 就可以了，返回的就是月；你如果只想要年，写个 `"2006"` 就可以了。

所以作为使用者就不要去给它较劲了，那就按它这个用就行了。**反正不管你怎么样子你就必须写这个时间，你不按这个时间写，它就拿不出来。**

> 对应块：BLK49 | 覆盖分集：P137-P139 | 块标题（分集名）：《136_尚硅谷_Go时间和日期函数详解(2)》

编程里用到时间的地方，往往不是"打印一下当前日期"这种展示需求，而是实打实要跑的活儿：让程序歇一会儿、每隔一小段时间轮询一次、统计某个函数到底跑了多久。这一讲把这些场景背后共用的那一批东西收干净——时间常量、Unix 时间戳，再顺带把内置函数里最该早点认识的 `new` 和 `make` 讲在前面。

### 时间常量：为什么不能写 `time.Second / 10`

最常碰到的一个场景就是休眠。Go 里让程序歇一歇用的是 `Sleep`，而 `Sleep` 必须告诉它"歇多久"，这时候就得用到时间常量。

这些常量都是 `time` 包里 `Duration` 这个类型下的常量——`Duration` 表示两个时间点之间经过的时间，常量就挂在它下面：

| 常量 | 对应的时间单位 |
| --- | --- |
| `time.Hour` | 小时 |
| `time.Minute` | 分钟 |
| `time.Second` | 秒 |
| `time.Millisecond` | 毫秒 |
| `time.Microsecond` | 微秒 |
| `time.Nanosecond` | 纳秒 |

它们之间的换算关系是老一套：1 小时 = 60 分钟，1 分钟 = 60 秒，1 秒 = 1000 毫秒，1 毫秒 = 1000 微秒，1 微秒 = 1000 纳秒。所以纳秒是最小的那个单位。

知道了常量怎么用，就拿它来写个小练习：每隔 1 秒打印一个数字，打印到 100 就退出。

```go
var i int = 0
for {
    i++
    fmt.Println(i)
    // 休眠
    time.Sleep(time.Second)
    if i == 100 {
        break
    }
}
```

跑起来就是每隔 1 秒蹦出一个数字。

现在需求变了：改成每隔 0.1 秒打印一个，打印到 100 退出。这里立刻会撞上一个坑——很多人顺手就想写 `time.Sleep(time.Second * 0.1)`，结果编译器直接报错：浮点数不能传给整型参数。

> **易错点**：`time.Second` 是整型常量，`time.Second / 10` 一做除法就变成浮点小数了，而 `Sleep` 要的 `Duration` 是整型，浮点数压根传不进去。这也正是 Go 的设计者为什么要在 `time` 包里摆出这一整套时间常量：需要表达一个时长时，你永远都在挑一个合适的整数单位去乘，而不是拿现成的秒去四则运算。

0.1 秒等于 100 毫秒，换个单位写就顺了：

```go
time.Sleep(100 * time.Millisecond)
```

改掉之后再跑，每 0.1 秒输出一个数字，问题解决。所以这几个常量的用处说到底就一句：让你在程序里精确地拿到指定长度的时间单位，需要多长就挑哪个单位去乘。

### Unix 时间戳与 Unix 纳秒时间戳

时间和日期里还有两个特别要紧的方法：`Unix` 时间戳和 Unix 纳秒时间戳。

`Unix()` 返回的是从 1970 年 1 月 1 日 UTC 那一刻到当前时间经过的**秒数**；`UnixNano()` 返回的是同一段距离，只不过单位换成**纳秒**，所以变化频率更快、更"随机"。

这两个方法都挂在 `time.Time` 类型上，只能通过一个时间对象来调用：

```go
now := time.Now()
fmt.Printf("unix时间戳=%v unix纳秒时间戳=%v\n", now.Unix(), now.UnixNano())
```

运行结果一眼就能看出差别：秒级时间戳是个十来位的整数，纳秒级的那个数大得多，末尾几位每次刷新都在跳。再马上执行一次，秒级的数字也跟着变了，比如从 60 变成 69；纳秒那个变化得更快，因为它本来就是按纳秒在算的。

> **结论**：拿时间戳当随机种子用，是一个非常常见的写法。等我们讲到数学函数 `rand` 的时候会知道，如果不设置随机种子，每次拿到的随机数都是一模一样的；这时候用 Unix 时间戳甚至 Unix 纳秒时间戳来当种子，就能拿到每轮都不同的随机数——因为它自己就在变。做开发时想取随机数字的需求非常多，随手就能想到这招。

### 用时间戳给函数计时

有了 `Unix()`，马上就能干一件很实用的事：统计某个函数执行了多久，判断一段代码的效率到底怎么样。

先看被测函数 `test03`，它的任务是把一个字符串拼接 10 万次：

```go
func test03() {
    str := ""
    for i := 0; i < 100000; i++ {
        str += "hello" + strconv.Itoa(i)
    }
}
```

`strconv.Itoa` 是把一个整数转成字符串的函数，所以这里每循环一次就在 `str` 后面接一段 `"hello"` 加上 `i` 的字符串形式，拼 10 万次。

光调用它是不够的——执行完了，我们并不知道它到底花了多久。做法很简单：**在调用前后各取一次时间戳，相减就是耗时**。

```go
package main

import (
    "fmt"
    "strconv"
    "time"
)

func test03() {
    str := ""
    for i := 0; i < 100000; i++ {
        str += "hello" + strconv.Itoa(i)
    }
}

func main() {
    // 在执行 test03 前，先获取到当前的 unix 时间戳
    start := time.Now().Unix()
    test03()
    end := time.Now().Unix()
    fmt.Printf("执行 test03 耗费时间为 %v 秒\n", end-start)
}
```

`time.Now()` 拿到当前时间对象，再对它调 `Unix()` 拿到秒级时间戳——`start` 是执行前的，`end` 是执行后的。中间的 `test03()` 跑完之后，最后 `end - start` 一减，秒数就出来了。

> **提示**：想要更精准的话，前后都改取 `UnixNano()`，相减得到纳秒数，粒度会细很多。我这里为了直观，就直接用秒级的 `Unix()` 了。

实际跑一下（`cd` 到 `time` 练习目录下 `go run main.go`），10 万次拼接跑完，输出是"执行 test03 耗费时间为 17 秒"。这个数字看着是挺吓人的，但它不是重点——重点是你现在能非常精准地知道一个函数花了多长时间。

这套用法往后能直接迁到别的地方：想判断某个排序方法快不快，想知道一个网络爬虫抓一页内容耗了多少时间，都可以用同样的方式去测。

> **结论**：这一招还有更直接的实用场景——当你是面试官、或者你是项目经理，需要从两三个候选人里挑一个更厉害的，就让他们各写一个函数（排序也好、爬虫也好），然后你用这套计时方式跑一遍，谁写的代码更高效一目了然，直接就给了你一个客观的选人标准。

### 内置函数：目前用得上的 `len` 与 `new`

Golang 的设计者为了编程方便预先造了一批函数，可以直接拿来用，不需要引入任何包，这一整块在手册里就叫 `builtin`。它的函数很多，不过以我们现在的进度，能真正讲透的主要是 `len` 和 `new`。

`len` 我们前面已经讲过了，它用来统计字符串的长度或者数组的大小。这里不再重复。

`new` 是干什么的？手册上对它的描述是：**内建函数 `new` 分配内存，其第一个实参为类型，返回值是指向该类型的新分配的零值的指针。**

这句话念起来确实有点绕。它强调的是"实参是**类型**而非值"——你告诉 `new` 要什么类型，它给你一块装了该类型零值（也就是 0）的空间，再把这块空间的地址以指针的形式给你。后面拆开讲。

### `new` 与普通赋值的内存差异

前面讲过，创建或者给一个 `int`、`float`、字符串赋值，我们基本都是直接赋值：

```go
num1 := 100
fmt.Printf("num1的类型%T num1的值=%v num1的地址=%v\n", num1, num1, &num1)
```

这是最常见的用法：类型是整数，值是 100，地址用 `&num1` 拿。运行结果也印证了这一点——类型是 `int`，值是 `100`，地址是一个十六进制的内存地址。

对应到内存里是这样一块空间：

```text
        num1  (类型 int)
        ┌────────────────────────┐
        │   值 = 100             │
        │   地址 = 0xc000010250  │   ← &num1 就是这个地址
        └───────────┬────────────┘
                    │  变量直接关联到存放数据的那块空间
                    ▼
        ┌────────────────────────┐
        │          100           │
        └────────────────────────┘
```

简单到不能再简单：变量本身就指向存放 100 的那块空间，`&num1` 取到的就是那块空间的地址。

第二种写法就是 `new`：

```go
num2 := new(int)
fmt.Printf("num2的类型%T num2的值=%v num2的地址=%v\n", num2, num2, &num2)
```

运行结果出来：`num2` 的类型是 `*int`，值是一个地址，`&num2` 又是另一个地址。同样画一张图对比：

```text
   num2  (类型 *int)
   ┌──────────────────────────────────────────┐
   │  值  = 0xc000010250  ← 它本身就是地址   │
   │  地址 = 0xc0000160b0  ← &num2           │
   └───────────────────┬──────────────────────┘
                       │ num2 指向这里
                       ▼
       ┌──────────────────────────────────┐
       │  存放的内容 = 0xc000010250        │ ← 也是一个地址
       │  这块空间的地址 = 0xc0000160b0    │
       └───────────────────┬──────────────┘
                           │ 这个地址又指向
                           ▼
       ┌──────────────────────────────────┐
       │              0                   │ ← new 分配的零值
       └──────────────────────────────────┘
```

注意听这里的关键区别：普通赋值是 `num1` **一个**变量直接关联到数据；而 `new` 是**一层一层套下来的**——`num2` 指向一个空间，那个空间里存的又是一个地址，这个地址才真正指向装着 `0` 的那块空间。

所以现在结论就出来了：

- `num2` 的类型是 `*int`，一个指针类型；
- `num2` 的值，是它指向的那个空间的地址；
- `num2` 自己也有地址，因为它本身就是个变量；
- `num2` 指向的最终那块空间里，默认值是 `0`。

> **定义**：`new` 做的事情可以概括成两段——第一，它分配一块空间装上了数值（这里是 `int` 的零值 0）；第二，它再分配一块空间把这个地址放进去，然后让 `num` 指向这块空间。往后无论是别人跟你讨论 `new` 干了什么，还是面试官问你，都能很轻松地答上来。

那 `num2` 指向的值到底是不是 0？打印一下就见分晓：

```go
fmt.Printf("num2指向的值=%v\n", *num2)
```

`*num2` 就是取值运算符，穿过 `num2` 把它指向的值取出来。跑一下，果然输出一个 `0`。何以为证，这不就齐了。

### 通过 `new` 出来的指针修改指向的值

既然拿到了指针，改它指向的值就太简单了。`new` 出来的 `num2` 指向的那个 0，想改成 100，**只要写 `*num2 = 100`** 就行——`*num2` 取出它指向的值，直接赋值 100，等于通过 `num2` 找到了那块空间并且改掉了内容。

改完再运行，指向的值变成 100 了。但是有两点不会变：**这两处地址没有发生变化，`num2` 的类型也没有变化**，它始终还是那个 `*int`。

> **易错点**：地址每次运行都可能不一样，这是正常的。因为你的程序每次执行时，内存的实际情况就在变，系统分配的地址不可能永远固定。`num2` 的值（也就是那个地址）和 `num2` 自身空间的地址，都是由系统分配的，程序员根本没有办法指定——你说"我想让它分配到某个地方"，那是不行的。

### `make`：给引用类型分配内存

`new` 主要是给**值类型**分配内存的，`int`、`float32` 这些用它没问题，后面讲到 `struct` 也可以。

还有另一个操作符 `make`，它同样可以分配内存，但**主要是给引用类型分配**的，比如 `channel`（管道）、`map`、`slice`（切片）。

不过这三个类型我们现在还没讲到，现在硬讲只会一头雾水，所以 `make` 的具体用法留到后面去。这里先把两个概念记住就行：`make` 能分配内存，且它分配的是引用类型的内存。等讲到管道、`map`、切片的时候，我们还会再回来用 `make`。

至于内置函数里其他的——比如 `copy`、`close`、`open`——都是一样的用法：现在用到哪些再讲哪些，到时候自然会遇上。

## Go 的错误处理：defer、panic、recover 与自定义错误
> 对应块：BLK50 | 覆盖分集：P140-P142 | 块标题（分集名）：《139_尚硅谷_Go错误处理机制》

写代码的时候我们总希望它是"顺畅"的：从上到下跑完，出了岔子也能接着往下走。但 Go 默认的做法有点硬——出了岔子直接崩。我们先从一段最朴素的代码说起，看看它到底是怎么崩的，以及我们到底想要什么。

### 一个除以零引出的问题

看这段代码，它做了一个小学数学老师早就交代过不能做的事：除以 0。

```go
package main

import (
    "fmt"
)

func test() {
    num1 := 10
    num2 := 0
    res := num1 / num2
    fmt.Println("res=", res)
}

func main() {
    test()
    fmt.Println("main 中下面的代码...")
}
```

`num1` 是 10，`num2` 是 0，`res := num1 / num2` 等价于 10 除以 0。分母不能为 0，这是小学就定下的规矩，所以这里一定会报错。

新建一个 `error` 文件夹，写一个 `main.go`，`cd` 进去 `go run main.go` 跑一下，结果一目了然：它根本没执行到 `fmt.Println("main 中下面的代码...")` 那一句。运行器报到两处行号，一处是第 9 行，也就是 `res := num1 / num2` 这一句；另一处是第 17 行，也就是调用 `test()` 的那一行。也就是说，从第 17 行进入 `test`，在第 9 行就炸了。

错误原因也直接告诉你了：`integer divide by zero`。而且紧跟着的是一个 `panic`。

> **定义**：`panic` 字面意思是"恐慌"。在 Go 里它代表一种**致命的错误**——一旦触发，程序直接退出，也就是崩溃了，后面所有的代码都不再有机会执行。

所以对这段代码的第一个总结是：**默认情况下发生 panic，程序就退出、就崩溃，没法继续执行了。**

那问题来了——我们是不是真的希望它这样？很多时候我们想要的恰恰相反：

1. 即使这个地方出错了，我仍然希望后面的代码能继续往下执行；
2. 即使错了，能不能告诉我，并且给我一个预警机制？

Go 里其实是有这样的机制的。用好它的错误处理机制，代码执行的效率反而会更好：错了，我保证你"错的就错了"，但下面的代码还能正确跑；同时我一检测到错，还能发一封邮件或者一条短信给管理员，说一句"小心，你服务器后面有代码错误"——那岂不更好。

### Go 为什么不用 try-catch-finally

先说清 Go 处理错误的整体思路。Go 语言追求简洁、优雅，所以**它并不支持传统的 `try-catch-finally` 这种语法**。学过 Java 的同学很熟悉，Java 的错误处理就是 `try-catch-finally` 这一套；但 Go 认为这个并不好，容易造成程序的混乱。

Go 用的是三个关键字：`defer`、`panic` 和 `recover`。

它们怎么配合使用呢？Go 中可以抛出一个 panic 异常——当它发生一个错误的时候，就可以抛出 panic；然后**在 `defer` 中，通过 `recover` 这个内建函数捕获这个异常，再正常处理**。所以这三者往往是结合使用的。

> **定义**：`recover` 是一个内建函数，作用是捕获 panic 异常。`defer` 则负责把这个"善后程序"压入 defer 栈，等到外层函数执行完毕或者发生异常的时候，它会被调用。

### defer 加 recover，让程序不再崩溃

现在拿这段除以零的代码来改。异常发生在 `test` 函数内部（第 9 行），解决办法就是在 `test` 里用 `defer` 加 `recover` 把异常捕获掉：

```go
defer func() {
    err := recover() // recover()内置函数，可以捕获到异常
    if err != nil {  // 说明捕获到错误
        fmt.Println("err=", err)
    }
}()
```

这段是放在 `test()` 函数**开头**的。我们一句一句拆开看。

`defer` 后面跟的是一条语句，也可以是一个函数调用；这里我们直接写一个匿名函数然后调用它——回忆一下，匿名函数的调用就是外层加一对括号，它不需要参数也没有返回值，括起来直接执行就行。

匿名函数体里第一件事：`err := recover()`。`recover` 能拿到一个错误值，我们就把它接到 `err` 上。

第二件事：`if err != nil`。`nil` 是它的零值，所以只要 `err` 不等于 `nil`，就说明确实捕获到了异常或错误，那就把这个错误打印出来。

整个执行流程是这样的：`defer` 把这个函数压进 defer 栈，等 `test` 执行完毕或者发生异常的时候调用它，然后把异常交给 `recover`，`recover` 拿到后我们再判断。

加完这段代码之后，结果和前面完全不一样了。跑一下就能看到：错误信息被打印了出来，然后程序**继续往下走**，`main` 里面的"下面的代码"照样被执行了。

要是这里换成循环，效果会更直观。比如加一个 `time.Sleep` 休眠一秒（用到了就得把 `time` 包引进来），下面的代码就会每隔一秒还在正常执行。

> **结论**：这就相当于对异常或错误进行了捕获并且处理，处理完之后代码可以正常往下执行。至少你的程序不再崩溃了——该怎么走就怎么走。

### 错误处理带来的两个好处

第一个好处很直接：**进行错误处理后，程序不会轻易地挂掉**。

第二个好处更有价值：**如果加入预警代码，可以让程序更加健壮**。

具体怎么落地？注意 `if err != nil` 那个分支——你是不是在这个地方实际上就已经知道错误发生了？那么这里就可以加一段代码，把这个错误信息发送给管理员。

怎么发送？Go 里当然也有支持这种发送信息的机制。我在这里写段伪代码示意一下，比如：发送邮件给某某管理员 `admin@sohu.com`。管理员一看，有信息来了，就知道我们的程序在某个地方已经发生错误了，这时候他就会立即来处理。

跑一下看看，邮件确实给你发出去了，下面还在继续执行。管理员一看到，原来有个错误信息是什么什么样子的，把这个信息给他发过来了，这个程序员或者管理员一看到，赶紧去处理，处理完了不就完事了。

> **结论**：所以在这个位置上，你可以加入预警代码或者相应的提示信息给管理员，这就是健壮性实实在在的来源。前面提到的两种收益——程序不崩溃、下面的代码继续执行，以及捕获到 `err` 之后还能发送信息给管理员——都是同一段代码带来的。

顺带提一个等价写法。有些程序员还喜欢这么写：

```go
defer func() {
    if err := recover(); err != nil { // 说明捕获到错误
        fmt.Println("err=", err)
    }
}()
```

我们以前讲 `if` 的时候说过，`if` 前面是可以带一个语句的，可以先做一个语句。这种写法完全 OK，跑起来效果一模一样。

> **提示**：这两种写法是完全等价的，就看你习惯哪一种。我一般还是习惯把它分开写，这样逻辑上更清晰一点；但合在一起写，你也得会，不然看到别人这么写会懵。

这段代码整体放在哪儿才合适？至少你要知道预警代码或者通知代码应该写在哪个位置——写在 `recover` 判断出错误之后的那个分支里。至于怎么把这个信息发给管理员，那是后面要讲的其他技术了，比如发一封电子邮件，或者说发一个短信给指定的管理员。

别人面试官问你：如果有一个错误发生了，怎么去处理？你得有个方案、有个思路给人家才可以。

### 自定义错误：信息我自己定，要不要退出我说了算

接下来是错误处理里面的自定义错误。我们假设这么一种情况：在 Go 程序里，如果发生了一个错误，我希望这个错误的信息**由我自己来定义**；第二点，我希望发生错误之后，**这个程序就放弃执行**。

为什么会有第二种需求？因为有些错误是致命的。举个例子：读取一个配置文件，如果这个配置文件根本没读取到，那下面的代码执行还有什么意义呢？这种情况下就可以通过自定义错误来完成处理。

这要靠两个东西：

- `errors` 包里面的 `New`，它可以创建一个 `error` 类型的错误值；
- `panic` 这个内置函数，可以直接抛出一个 panic 并退出程序。

写起来是这样：`errors.New("错误说明")`，把你的错误信息写进去，它会返回一个 `error` 类型的值，表示一个错误。

> **定义**：`errors.New` 会返回一个 `error` 类型的值，仅此而已。至于 `panic`，它可以接收一个空接口类型的参数——空接口就是任何一个值都可以传过去作为参数（接口这块我们还没正式讲，先这么记）。它当然就可以接收 `error` 这种类型的变量，把这个错误信息输出出来，并且**退出程序、终止这个程序**，相当于这个程序我就不玩了。

#### 一个读取配置文件的模拟案例

我们现在模拟一个错误。就拿读取配置文件来说：假设有一个函数去读取名为 `config.ini` 的配置文件信息，如果这个文件名不正确，我们就返回一个自定义的错误。

```go
func readConfig(name string) (err error) {
    if name == "config.ini" {
        // 读取...
        return nil
    } else {
        // 返回一个自定义错误
        return errors.New("读取文件错误..")
    }
}
```

返回列表里是可以给变量名称的，所以签名写成 `(err error)`。逻辑很直白：如果 `name` 等于 `config.ini`，我们认为文件名正确，就执行读取操作，然后返回 `nil`——`nil` 就表示没有错误。如果不是这样，你文件名传得不对，那就返回一个自定义的错误，用 `errors` 包里的 `New` 来创建：`errors.New("读取文件错误..")`，这个地方就会返回一个 `error` 类型的数据。既然用到了 `errors` 包，那自然要把 `errors` 包引进来。

那怎么测试呢？再写一个 `test02` 去调用它：

```go
func test02() {
    err := readConfig("config.ini")
    if err != nil {
        // 如果读取文件发生错误，就输出这个错误，并终止程序
        panic(err)
    }
    fmt.Println("test02()继续执行...")
}
```

用一个 `err` 去接收返回值。判断 `err != nil`：如果读取文件发生错误，就输出这个错误并终止程序；否则的话该怎么玩怎么玩，下面 `test02` 后面的代码继续执行。

先看文件名传对的情况。传的是正确的 `config.ini`，`readConfig` 返回 `nil`，判断不成立，不进去，继续执行下面那句。`cd` 到 `error` 目录下 `go run main.go`，输出是 `test02()` 继续执行，`main` 下面的代码也正常执行。

再看传错的情况，把文件名换成 `config2`。它不等于 `config.ini`，就走进 `else` 分支，返回一个 `error` 错误。这个错误返回到调用方，`err` 肯定不等于 `nil` 了，于是触发 `panic`。

> **易错点**：`panic` 一执行，程序就终止了。那么问题来了——程序终止了，`test02` 里"继续执行"那句还会输出吗？肯定不会。`main` 里下面那句同样不会执行，直接退出。

跑一下验证：它在出错的那一行直接抛出了 panic，内容是 `读取文件错误..`，后面的代码全部不执行，错误定位在第 41 行，正是 `panic(err)` 那一行。

这就是自定义错误的用法——**可以把自定义的错误信息输出出来，并且可以选择终止这个程序**。

> **结论**：两套错误处理思路可以对照着记：走 `defer` + `recover` 这条路，是"程序不崩、继续往下跑"；走 `errors.New` + `panic` 这条路，是"错误信息我自己定义，并且我主动终止程序"。什么时候选哪一条，取决于这个错误到底是不是致命的。

### 第六章的收尾

到这里，我们第六章的内容就全部讲完了。这一章主要讲了**函数、包和错误处理**三块。讲完之后，下一次我们就开启新的一章，在讲新章节的时候可能会给大家布置一些作业。

### 本讲提到的题目

光听一耳朵、自己不练一练，学习效果是出不来的，所以这一章课后要求做下面这六道练习。前四道是纯逻辑题，后两道有明确的方法提示。

**循环打印输入月份的天数**。给你一个年、一个月，就告诉我这个月有多少天。月份输得不对，要有相应的错误提示信息。比如输入了 2010 年 31 月，你得告诉对方这个日期有问题。里面肯定要考虑这一年是不是闰年。

**编写一个函数，随机猜数字的游戏**。随机生成 1 到 100 的一个整数，有十次机会。生成之后你来猜：猜中就提示对应信息；两到三次猜中提示一个，四到九次猜中提示一个，最后一次猜中提示一个；一次都没猜中，就提示另一句话。这里会用到你自己的全局变量，还要写一个函数。生成随机整数的方法，我们讲 `switch` 的时候提到过，自己去看一下，这里就不重复了。

**编写一个函数，输出 100 以内所有素数，每行显示五个，并求和**。素数是什么还有印象吗？只能被 1 和它自己整除的数就是素数。要求把 100 以内所有素数每行显示五个输出出来，并且把素数的和求出来。

**编写一个函数，判断是打鱼还是晒网**。中国有句俗话叫"三天打鱼两天晒网"。假设从 1990 年 1 月 1 号开始执行"三天打鱼两天晒网"这个活动，要求你判断以后的某一天——比如说 2001 年 3 月 7 号——这天应该是打鱼还是晒网。

> **提示**：这题给你两点提示。第一，你得先求出输入的这一天距离 1990 年 1 月 1 号到底隔了多少天；第二，把这个天数模一个 5，然后根据模出来的结果判断是打鱼还是晒网。至于取模之后得到什么值算打鱼、什么值算晒网，自己去想一想。

**编写一个小小计算器，要求打印出指定的效果**。也就是说：10 和 5 是固定的，根据输入来输出对应的算式。输入 1，就输出 `10+5=15`；输入 2，就提示另一句，以此类推。

**输出小写的 a 到 z 以及大写的 Z 到 A**。这里有个顺序要求：一侧是 a 到 z，另一侧是 Z 到 A，而且肯定不能用固定的写法，必须使用 `for` 循环。

> **提示**：这题提示大家肯定要用到 ASCII 码的相关处理，也就是加 1 减 1 的那种做法。想清楚怎么用 `for` 循环把小 a 输出到大 z、又把大 Z 输出到小 A，答案就出来了，写个函数处理一下即可。
