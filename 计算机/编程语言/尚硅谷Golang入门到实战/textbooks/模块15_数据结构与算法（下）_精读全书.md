### 插入排序：把思路敲成代码

考察一个人到底代码写得怎么样、算法怎么样，这是最基本功。现在根据刚才的分析，我们就来一步一步写——先搞第一个，再搞第二个，再搞第三个、第四个，你一下就明白是怎么做的了。

打开 VS Code，新建一个文件夹叫 `insertsort`，新建一个文件 `main.go`。老规矩，`package main`，`import` 引入包，先把 `fmt` 引进去，`func main`：

```go
package main

import (
	"fmt"
)

func main() {

}
```

我们就用刚才分析的这个数组，我还是用这个数组比较好写：

```go
	// 5 个元素的 int 数组
	var arr = [5]int{23, 0, 12, 56, 34}
```

现在我们在这里写一个 `InsertSort`，给它一个数组，然后用指针指向 `*[5]int`。

#### 第一次：把第二个元素插到合适的位置

先完成第一次吧。第一次就是给第二个元素找到一个合适的位置并插入。

根据刚才的分析，我们首先先定义两个变量：

- 一个是值，`insertVal` 显然是 `arr[1]`，因为你第二个元素下标为 1；
- 一个是索引，`insertIndex`，**始终是待插入元素的前一个下标**，也就是说现在应该是 $1 - 1$。

```go
	// 插入排序
	func InsertSort(arr *[5]int) {
		// 第一次：给 arr[1] 找位置
		insertVal := arr[1]   // 0
		insertIndex := 1 - 1 // 0
```

找到这个位置过后，我们就开始找位置了，`for` 循环。

```go
		// 逆着走：从有序区的最后面往前找
		for insertIndex >= 0 && arr[insertIndex] < insertVal {
			arr[insertIndex+1] = arr[insertIndex] // 数据后移
			insertIndex--
		}
```

这个地方是逆过来走的。首先我要比较的时候，要保证 `insertIndex` 大于等于 0 才可以——因为你不大于等于 0，我没办法比较了。如果最后它小于 0，说明找不到位置，那就是第一个。

并且还要满足一个什么条件呢？就是你的 `insertIndex` 这个下标的值，因为我们现在是从大到小，它如果比我小，也就是我插入的值比你还大，我就应该继续往前走。大家能理解这个意思吧？因为是从大到小，如果反过来就是从小到大了。**如果插入的值比当前这个还大，说明我应该继续往前走。**

那怎么做呢？就要做后移的动作：`arr[insertIndex + 1] = arr[insertIndex]`。注意，**`insertIndex` 先不要去动它**。加 1 后面这个值等于前面这个值，不就相当于把它覆盖了吗？但是不用担心，因为 `insertVal` 已经被保存下来了。

紧接着往前走一下。移完过后，`insertIndex` 要减减，就是再往前看看。当然如果减减到最后实在找不到，都不大于 0 了，说明是 -1 了——到了最前面都还找不到。

这个循环完了过后，我们就找到位置了，插入：

```go
		// 插入：位置是 insertIndex + 1
		if insertIndex+1 != 1 {
			arr[insertIndex+1] = insertVal
		}
	}
```

为什么要想加 1 呢？你想，就以第一次这个 `0` 为例，它直接比你大，`insertVal` 本来就在前面，加 1 不就刚好在这，相当于不动嘛。所以这个地方要有一个加 1 的动作。

但是这个动作有时候是多余的。什么时候多余呢？假设你比较的这个数刚好就是最小的，那你没有必要比。所以这里还要加一个条件：如果 `insertIndex` 加了一个 1 之后不等于当前这个 1，也就是说 `insertIndex + 1` 不等于最后那个值，说明这个时候要去添加，否则我就不加了——相当于它本身就在原来的位置，你加它干什么呢？

#### 第二次、第三次、第四次：只有下标在变

代码写完了，我们看看代码有没有问题，跑一下。`fmt.Println`，这是第 1 次插入后的结果：

```go
		fmt.Printf("第%d次: %v\n", 1, *arr)
```

`arr` 是指针，为了好看取一个星号，把它解引用打出来。同时我们把主函数里面的原始数组也打印出来，做一个比较。

打起精神，`cd ..`，cd 到 insert 里面去，然后 `go run main.go`，跑起来。

同学们可以看到，原始数组是这样子的。第一次给 `0` 找位置，`0` 本身就是这个位置，所以在原来的位置没有动。**但是你不遍历是不知道的，所以还是比较了一次。** 比较完了过后，相当于这个效率是最高的，比了一次刚好就在最后，比一次就完事了。而且连这个动作都没有做——比较完了过后 `insertIndex` 本身是 0，`0 + 1` 就等于 1，所以连这个动作都没做。

第二次怎么做呢？跟这个逻辑很像：相当于给第三个元素找位置了，那这个地方应该变成 2，变成 `2 - 1`。这个同样，加 1 只要不等于 2 我就要去进行。这个不改，仍然是加 1 就写完了。

当我们运行完毕过后，我们发现第二次插入过后跟我们想象的是一致的。你看这里，给 `12` 找位置，`12` 一找发现 `0` 比你大，`0` 就往后面移一下，再比 `23` 发现没有你大了，位置找到，插到这儿——`23、12、0`，这个就是一个有序的。

其它以此类推。第三次是给我们的第四个元素找位置，那第四个元素下标应该为 3，往前面定一个位置；这个地方只要不等于 3 就可以。再跑一把，效果跟我们想的是一样的——第三次你看这个 `56` 最大，啪啪啪啪都到前面去了，需要全后移。

最后还有最后一次就是 `34`，这是第四次了。第四次相当于给第五个元素找位置。注意，**最后这个元素是要参与找位置的**。第五个元素下标为 4，这个就变成 `4 - 1`，这个变成不等于 4 就可以了。跑起来，第四次插入过后，看这个结果跟我们想的是一样的吗？完全正确——相当于给 `34` 找位置，`34` 刚好比 `23` 要大一点，插到前面去了。

#### 规律出来：整个代码套进一个 for

总共有四次，5 个元素有四次。同学们看，你突然发现这些代码几乎是一样的，**只有一个东西在变化，就是这个值在变化**。既然如此，我们可以把它包起来。我们用一个 `for` 循环把整个代码包起来：

```go
// 插入排序
func InsertSort(arr *[7]int) {
	for i := 1; i < len(arr); i++ {
		insertVal := arr[i]
		insertIndex := i - 1

		for insertIndex >= 0 && arr[insertIndex] < insertVal {
			arr[insertIndex+1] = arr[insertIndex]
			insertIndex--
		}

		if insertIndex+1 != i {
			arr[insertIndex+1] = insertVal
		}
		fmt.Printf("第%d次: %v\n", i, *arr)
	}
}
```

下标显然应该从 **1** 开始走。为什么这次是 1 不是 0 了？你看这又变了。冒泡的时候它是从 0 开始走的，所以每个同学要知道它的含义。

它小于多少次呢？显然是我们的 `len(arr)`。**因为最后是要参与比较的，所以不能再减 1。** 最后元素不参与比较那不行，这里为什么不减 1，道理大家要清楚。然后 `i++`。

现在要改变的值改成 `i`，这个也改成 `i`。这边不需要改；这边加完 1 之后只要不等于 `i` 就可以了。`%d` 我们把它输出来看一下，把 `%v` 输出来。这个 `d` 就应该就是 `i`，刚好和它保持一致。

请看代码，我们发现这个代码应该是没有什么问题。大家可以看到，第一次没有动，第二次把 `12` 定住，最后是正确的。

为了测试这个代码的正确性，我们可以把数组再增加一个。那我增加两个吧：`-1`，再来一个填到中间去，比 55 小一点的，就 55 吧。把 `[7]int` 改成 7 以后，在接收的时候也要改成 7——因为我们这个指针，`size` 也是指针变量的一部分，以前讲过了。

跑一下。大家发现也是没有问题的：看最后一次，`56、55、34、23、12、0、-1`，正确的。所以代码是 OK 的。

> **易错点**：这里有两个 `1` 容易搞混。一是外层 `for i := 1`，为什么从 1 开始——因为第一个元素自己就是有序的，不用插；二是内层 `insertIndex` 的初值 `i - 1`，因为它**始终指向待插入元素的前一个位置**，而不是待插入元素自己。最后一个判断 `insertIndex+1 != i` 也是同一个道理：如果待插入的值本来就该待在原位，就不要再赋值一次。

### 快速排序：两头对撞，中间立一根轴

下面还有一个排序法也是需要大家掌握的，叫快速排序法（Quick Sort）。这个排序法实际上是对冒泡排序的一种改进，**它的思想就会用到递归**。

**基本思想**是这样子的：通过一趟排序，将要排序的数据分割成独立的两部分，其中一部分的所有数据都比另外一部分的所有数据要小。当然如果说是从大到小或者从小到大，不同的情况下比较条件可能发生变化。然后再按此方法对这两部分的数据分别进行快速排序，整个排序过程中可以递归进行，以达到整个数据变成有序序列。

这里画了一个图帮助大家理解。这个图里是以最后一个数作为基准，但不一定每个都是以最后一个数。比如待会儿我们看到的案例，我是以中间这个数作为中轴，也就是以它为基准点来进行分割的。

如果以基准分解，它是怎么分解的呢？它这边是从小到大排，它会先**把比基准小的数扔在基准的左边**。但注意听这句话——**并不是把比基准小的数扔到这边过后这就是有序的，它仍然不是有序的**，它只是只能把比基准小的扔在左边，比基准大的扔在右边。

紧接着再进行分解，又以最后一个数作为基准，也就是轴点，比它小的扔在左边，比它大的扔在右边；然后再把分割好的再以最后一个数作为基准，比它大的分在右边，比它小的分在左边。没有了就不分了，这样就会出来有序序列。同样这边也是一样的道理，**整个过程是一个递归的过程**。

```text
   原始数组：
   [-9 ][ 78 ][ 0 ][ 23 ][ -567 ][ 70 ]
             ↑
          pivot = 0

   一趟扫描之后（只保证"小的在左、大的在右"）：
   [-9 ][ -567 ][ 0 ][ 23 ][  78 ][ 70 ]
             ↑
          pivot 已就位，但左右两边本身还是乱的

   左边递归：[-567][-9]     右边递归：[23][70][78]
   合起来才真正有序
```

这个理解起来就比前面的选择和插入要困难很多了，因为这里面用到了很多递归。我们看看这个代码是怎么实现的。

#### 三个变量：left、right 和一个中轴

根据刚才的思路，待会儿我们做这么一个案例。这里有一个数组，有六个数，要求从小到大排，要求使用快速排序。我们先看一下它大体是怎么实现的，新建一个文件夹叫 `quicksort`，新建一个文件 `main.go`：

```go
package main

import (
	"fmt"
)

func main() {
	var array = [6]int{-9, 78, 0, 23, -567, 70}
```

就这么六个数。我们把这个逻辑讲清楚，**数据设计都是有道理的**，待会儿可以看到效果。

快速排序有这么三个变量：一个是 `left`，表示进行排序的时候数组最左边的下标——当然如果是在往里面分割的时候，就是小块数组的最左边的下标，它是不断在变化的；同样，`right` 表示数组右边的下标；紧接着这个 `array` 就是要进行排序的数组，用的是指针类型。

```go
func QuickSort(left int, right int, array *[6]int) {
	l := left
	r := right
	// pivot 是中轴，也可以叫支点
	pivot := array[(left+right)/2]
	temp := 0
```

`pivot` 是一个中轴，翻译过来叫中轴，也叫支点。以这个地方为中轴开始左右分，也可以认为它是个支点。这个时候我们用的是 `(left + right) / 2`，实际上是把**中间这个数当成一个支点**。`temp` 是个临时变量。

#### l 找大的，r 找小的

```go
	for l < r {
		for array[l] < pivot {
			l++
		}
		for array[r] > pivot {
			r--
		}
```

`for l < r` 代表只要 `l < r` 的情况下，我就不停地去找。`for` 循环结束以后，它的目标是将比 `pivot` 小的数放到左边，比 `pivot` 大的数放到它的右边。

它是怎么放的呢？只要 `l < r` 就一直找，**什么情况算结束呢？`l >= r` 就算结束了，因为它是两头走。**

`for array[l] < pivot { l++ }` 这句话的意思是，先从 `pivot` 的左边找到大于等于 `pivot` 的一个值。只要左边这个数小于它就一直找，`l` 就一直加加，直到找到一个比它大或者等于的数才停下来。

现在可以理解为它有两个指针，一个是左边的指针，一个是右边的指针。现在先找到中间这个值——现在的 `pivot` 是 0。因为最左边是 0，最右边是 5，$(0 + 5) / 2 = 2$，所以中间的值 `pivot` 相当于 0。

它先从左边找到一个大于等于 `pivot` 的值，相当于找到了 `78`。找到 `78` 的目标是希望再从右边找一个比它小的数，然后两者交换。而 `for array[r] > pivot { r-- }` 这边是从 `pivot` 的右边找到一个小于等于 `pivot` 的值。根据我们的情况，应该能领会到这边还有一个指针，要找到一个小于 0 的，显然找到了 `-567`。

```go
		if l >= r {
			break
		}
```

如果 `l >= r`，说明它们已经扫描到中间了，说明已经完成了。如果满足这个条件，说明两头分割的任务已经完成了。针对这一次的分割，表明本次分解任务完成，我就 `break`。

#### 交换、错位一步，然后递归

如果说没有达到这个效果，那就交换：

```go
		temp = array[l]
		array[l] = array[r]
		array[r] = temp

		if array[l] == array[r] {
			l++
			r--
		}
	}
```

这个交换咱们也可以直接写成一句话，这里我用的还是传统的交换方式，大家可以把它改一改。针对我这边来看，其实就是 `78` 和 `-567` 交换。如果是这样的话，这边就变成了 `-567`，而 `-567` 的位置变成了 `78`。它交换之后，已经达到了一个效果：小的移到左边，大的移到右边。

这里做完了没有呢？没有做完，因为后面可能还有数。所以做完之后它又去做了判断：**如果 `pivot` 的值和 `arr[l]` 相等的话，我可以再往前错一步，这里相对做了一个优化。** 如果交换完了之后你会发现它们两个还相等，说明下一次就不要再比较了——相等的这种情况我们也不交换，这里做了一下优化。

整个地方做完了以后，接着再来看 `l` 和 `r`。如果不小于，指针就继续往下面移动，仍然跟我们的临界值进行比较。刚才只交换了一次，后面可能还有第二、第三个数。

整个 `for` 循环结束以后，大家应该想到一件事情：**针对这一次，左右两边已经搞定了。**

如果我不信，我可以把代码注销来看一下。如果我把后面的代码注销，大家可以准确地体会到，我们输出的数组就应该是：`-9、-567、0、23、78、70`。把这个理解了之后，你就知道后面的代码是什么含义了。

我们调用一下快速排序：

```go
	// 调用快速排序
	QuickSort(0, len(array)-1, &array)

	fmt.Println(array)
```

因为左边最早应该是 0，右边最早是它的长度减去 1，下标是 `len - 1`，紧接着把数组本身传进去。因为是引用传递，所以它是可以变化的。

我们来看看整个这样排序完了之后，是不是跟我们想象的分析一样：`78` 和 `-567` 发生交换。`23` 就不交换了，`23` 本身就比 0 大，而且右边也找不到了，就停下来了。把最早的初始数组打印出来，原先最早的时候是这样的，现在 `78` 和 `-567` 已经交换了，第一次就搞定了。

但是你这样搞定没有意义，为什么没有意义呢？因为 0 左边的这个地方仍然不是从小到大；同样，0 右边的这边它也不是从小到大。你还得保证小的数组里面仍然要保持这个规律。

那怎么办呢？最经典的写法就是**一个向左递归**：

```go
	if left < r {
		QuickSort(left, r, array)
	}
	if r < right {
		QuickSort(l, right, array)
	}
```

如果我把向左递归打开，它就能保证 0 左边递归下去就变成有序的。递归条件也是要满足 `left < r`，如果 `left` 传进去不停地变大，大到比 `r` 还大，就不要再走了。

同理，这边是向右递归，保证右边也是一个有序的，因为下去之后还要继续分割。

我们打开看一下，**如果只保证一个向左递归**，把这个打开之后，`0` 这边会变成有序的，但是右边仍然没有动过，因为只往左边进行了递归。处理完了之后，它应该只动了 0 左边，这边就变成了 `-567、-9`，保证了左边是有序的。但是右边没有动，右边仍然保持 `23、78、70`，因为没有向右递归。

我们执行一下代码看分析得对不对。这样处理过之后，它处理完了变成有序的，果然保证了 0 左边是有序的。

同样，右边也是一样的道理。如果我把向右递归打开，那么它右边也是有序的了，两边都是有序的。右边也打开之后看这边：`23、70、78`。原先是 `23、78、70`，现在变成了 `23、70、78`，其实就很简单。

> **易错点**：还有这句话大家要注意，一定要加上：`if l == r { l++; r-- }`。**不加上它有可能是一个死递归。** 为什么呢？因为如果相等你不移动，它一直卡在那个地方动不了，一比较又相等，就卡在那儿了。所以这个地方这句话是非常重要的。如果把这个去掉，你会发现它是一个死循环，会在向左递归的时候发现一个死递归，推不出来——因为没有发生 `l++` 和 `r--`，卡在那儿了。

#### 从 6 个数扩到 9 个数

写完了之后，我们来看看把数据量扩大一点，它是不是还是对的。我们把数据量扩大一点，增加测试数据 `-123`、`90`、`-23` 等，现在一共有 9 个数据，把它扩成 9。运行看代码对不对——没有任何问题，从小到大排序完成。

有些同学说，我不想从小到大，我想从大到小，应该改哪个值呢？其实**关键点就在这个地方，把比较符号改一下就可以了**。因为你是从左边找大的，反过来找就是从左边找一个小于等于它的再交换，只需要把符号改成大于或者小于就可以了，一样的道理。如果这样改的话，就相当于从左边找一个比它大的数再去交换，这时候就应该是从大到小。看结果也是正确的。

## 栈：编译器到底是怎么算出结果的，以及用数组手写一个栈
> 对应块：BLK148 | 覆盖分集：P370-P372 | 块标题（分集名）：《368_尚硅谷_数据结构和算法-栈》

### 我们写死的 7 × 2，和输入框里敲进去的 7 × 2，不是一回事

我个人认为，作为一个程序员来讲，其实都必须对栈有一个了解。

你看我们在做编程的过程中，经常用到加减乘除或者各种运算，对吧？那么我们要**深度地问**大家一句：它的这种运算在我们计算机底层，或者说编译器，它是怎么去处理的？这个问题其实对一个程序员来说应该是有所了解——至少你要了解它的一个基本的运行原理。

我们来看一个实际的需求，引出栈的概念。比如说我给大家输入一个表达式，是这样一个表达式，然后我要求大家点击计算。

注意，也就是说这个计算式是**你从一个输入框输入进去的**，不是像我们在程序里面直接写的。比如如果我这个地方是直接把这个算式放在我们程序里面去，当然同学们都知道这个很容易做出来，比如说我用一个结果来接收——那这个我相信同学们都知道它是可以运行的，对吧？$7 \times 2$ 怎么怎么样，这个都很简单。

但是当它是以一个**字符串**的形式给它传进去的，它是怎么来进行扫描，然后把这个结果得到的呢？这底层就用到了一个栈。

> **结论**：请注意，不是简单地把算式列出来运算——因为我们看到的这个算式是我们在看，**计算机怎么理解这个算式呢？** 也就是说对计算机而言，当你一提交这个算式的时候，它接收到的就是一个字符串。那么字符串怎么去解析，计算机怎么去解析这个字符串从而得到我们想要的结果？这是我们要去讨论的问题。它底层其实说白了，研究到下来就是我们的编译器它是怎么进行加减乘除的这种运算的。好，这里面就引出我们的栈的概念了。

### 三个基本知识点：先入后出，以及栈顶和栈底

有些程序员也把这个栈直接叫**堆栈**，所以说你在网上去搜的话，也会看到有时候堆栈它也叫栈，有时候它是同一个。叫法就是有时候不是特别精准，说栈和堆有什么区别——栈和堆是有区别的，栈和堆是有区别的。但是有时候有些程序员直接就把栈叫堆栈了，我们严格地叫还是叫栈，比较准确一点。它的英文单词叫 **Stack**。

#### 弹夹：往下压，往上打

然后栈它跟前面的队列有一个最大的区别，它是**先入后出**的这么一种数据结构。就是谁先进去，结果反而后出来。

大家可以把它想象成是一个弹夹，小时候小男孩比较喜欢玩的勃克枪、双枪老太婆玩的那个玩意儿，对吧？往下压一颗子弹，再压一颗，再压一颗。打出来的子弹是最后压进去的，它是一下打出来；最后打出来的是最先压进去的，因为它往下面压嘛。栈就是这么一个东西，它是先入后出，先入后出。

> **易错点**：这个先入后出你一定要记住。**待会儿我们在写计算表达式的时候，如果你忘了先入后出，这个结果刚好相反——你在做减法的时候，你刚好是反过来的。** 比如本身是 $5 - 4$，结果你会发现你得出的结果刚好是 $4 - 5$。如果你不把这个记住，你整个这个结果是错的。

#### 限制性线性表：只有一端能动

第二个，栈是一个**限制性线性表**。它的元素插入和删除只在限制表的同一端进行，也就是栈顶。它允许插入和删除的一端为变化端，这个称之为**栈顶**，因此栈顶是一个关键。它总是从栈顶取，也是从栈顶往里面放，它只有一端可以出来。

**栈底是动不了的，栈底是动不了的。** 不跟我们队列，队列有队头和队尾，它这个没有，它就一个栈顶。另外一端为固定的一端，称之为**栈底**。

#### 入栈与出栈的示意图

栈一般我们用什么来做呢？一般是用**数组**来模拟。那么栈顶和栈底在刚开始的时候都为 $-1$，都开始都为 $-1$。这个绿色的代表栈底，红色的代表栈顶。

```text
   空栈：  stack empty
            ↑ top = -1
            ↑ base = -1

   Push 1  [ 1 ]        top 和 base 一起上移一位
            ↑ top = 0
            ↑ base = 0

   Push 2  [ 1 ][ 2 ]   只有 top 再上移一位
            ↑ top = 1      base 钉死在 0

   Push 3  [ 1 ][ 2 ][ 3 ]
                  ↑ top = 2      base 仍然是 0

   Pop     [ 1 ][ 2 ]           从栈顶弹出一个，top 下移一位
                  ↑ top = 1      base 不变
```

那么什么时候这个栈满了呢？就是栈顶到达了我们这个数组的最大的那个下标，就是它的长度减 1 这个下标，就不能再往上面再给了。

有同学说老师，假设我这个栈让它无限地延伸可不可以？也可以。那么你可以用**链表**来做，当然也可以用**切片**来做。假设一般来讲我们这个栈都是有一个限制的。

出栈是怎么出呢？出栈是从这个栈顶弹出去一个，弹出去以后，我们这个栈顶就往下面挪动一位。比如说我从这边弹出去一个 `30`，那么 `30` 被取出以后，栈顶是往下一动一位，栈底不变。

> **结论**：所以判断一个栈是不是空的，就看 `Top == -1`；判断它是不是满的，就看 `Top` 撞没撞到数组的最大下标。这两条待会儿写代码全靠它们。

#### 栈到底用在哪：五个地方

我们再来看栈的应用场景有哪些。什么地方有可能用到我们这个栈的数据结构呢？有这么几个地方：

**第一个是子程序的调用。** 比如我们调用一个函数，它底层是怎么实现的呢？它在跳往一个子程序前，会先将下一个指令的地址先存在这个堆栈里面。它如果不存到那个地方，它不知道以后干完事过后应该回到哪个位置。**直到子程序执行完毕后，再将地址取出，回到原来的程序。** 所以说大家知道这个 `return` 是怎么做的了——它整个函数也有一个栈的概念。这就是为什么以前有同学说为什么那个函数先执行、这个函数后执行：它比如说在跳到另外一个函数之前，先把原来的这个地址先压到这个栈里面，它又开一个新栈开始执行，执行完了过后它回到这个栈底，再把这个地址取出来——哦，我继续应该到哪儿去做。

**第二是处理递归的调用。** 处理递归的时候，它把这个参数、局部变量的数据也压到栈里面去。那么在开一个新栈的时候，再开一个新栈，把新的变量和数据压到新栈里面去，**所以它的数据也是相互独立的。**

**第三是表达式的求值和转换**，比如刚才我们所说的像 $5 \times 4 - 3 + 5$，这个地方也用了栈。待会儿我们就自己来实现这个东西。

**第四是二叉树的遍历。** 前序遍历、中序或者是后序遍历，都会用到这个栈。**第五是图形的深度优先搜索算法**，也会用到栈。这个栈在底层里面玩得很多。

> **注意**：不过我告诉大家，你要写一个非常完整的表达式求值其实是比较麻烦的——比如说你要考虑到小括号，还要考虑到中括号，有些地方还要考虑到大括号，这个难度还是有点大。所以我在这里更多的是把这个栈的基本使用原理告诉大家。我们待会儿实现的表达式在功能上不是特别强大，只能做加减乘除；小括号、大括号我可以交给你们去做，我提一些思想算法在里面。

### 用数组模拟一个栈：结构体怎么定

好了，那有这些东西过后，同学们，我们就来快速地入门。我们用什么做呢？**我们用数组模拟一个栈**，然后把这个栈的哪些讲清楚呢？一个是出栈，一个是入栈，还有一个就是遍历，就是把这个栈给大家打印出来，还有一个打印栈，或者叫输出栈。

新建一个文件夹，还是第 20 章，叫 `stack`，然后我们写一个主文件 `main.go`：

```go
package main

import (
	"errors"
	"fmt"
)

func main() {

}
```

我们这块是用一个数组来模拟栈，当然栈也可以用链表。**链表其实是最灵活的，链表既可以去模拟一个队列，也可以模拟一个栈。** 但是现在我用数组。

既然要用到数组，可能要定义一个结构体。因为栈里面有几个概念：**一个是数组本身，第二个有栈顶，还有一个栈底**。这个地方大家要很清楚知道。

```go
type Stack struct {
	MaxTop int // 表示我们栈最大可以存放的数个数
	Top    int // 表示栈顶
	arr    [5]int // 数组模拟栈
}
```

`MaxTop` 表示我们栈最大可以存放的个数，后面我们都要用它完成很多事情。第二个做栈顶 `Top`，直接表示栈顶。**因为栈底是不变的、是固定的，因此可以直接使用栈顶 `Top` 就可以了**——你只要知道栈顶在哪儿，就知道栈底在哪儿。还有一个就是数组，我们这个数组有多大，现在我定义一个五个元素的数组。

我先初始化一个栈，大家就知道它们之间的关系了：

```go
	stack := &Stack{
		MaxTop: 5, // 最多存放5个数到栈中
		Top:    -1, // 当栈顶为-1时，表示栈为空
	}
```

`MaxTop` 等于 5，因为本身这个数组是 5，所以给它一个 5，表示最多存放 5 个数到栈中。初始化的时候栈里面没有数据，没有数据的话默认 `Top` 为 -1。

### 入栈 Push 和遍历 List

先写一个入栈 `Push`。入栈一般术语就叫 push，推进去。推进去的时候给我推一个值进来 `val int`——因为我这里的数组是用 int 类型的。当然如果说是 float，这里也是 float，以此类推。入栈的时候**可能会产生一个错误，所以我返回一个 error**。

```go
func (this *Stack) Push(val int) (err error) {
	// 先判断栈是否已经满了
	if this.Top == this.MaxTop-1 {
		fmt.Println("stack full")
		return errors.New("stack full")
	}

	this.Top++
	// 放入数据
	this.arr[this.Top] = val
	return
}
```

怎么知道栈已经满了呢？要取决于 `Top` 和 `MaxTop` 之间的关系。如果 `this.Top == this.MaxTop - 1`——因为你想，`Top` 不停地往上长，当它存满的时候，`Top` 应该等于 4。$4 = 5 - 1$，说明栈已经满了，不能再往里面加了，就输出一句话，返回一个错误 `errors.New("stack full")` 就可以了。

如果说没有满，**先让 `Top` 自增 1，再往里面放数据**——顺序不能反。放入数据非常简单，就是 `this.arr[this.Top] = val`，这就成功了。成功过后直接 `return` 就可以了，因为 error 本身是一个命名返回值参数，所以直接 return 就成功了，这就代表入栈成功。

#### 为什么遍历要从栈顶开始

现在我们再来写一个显示或者遍历这个栈。**遍历栈的时候要注意，需要从栈顶开始遍历**，因为取的时候是从栈顶取，所以在打印的时候不能按照以前从 0 开始打印，那是不对的。

```go
func (this *Stack) List() {
	// 先判断栈是否为空
	if this.Top == -1 {
		fmt.Println("stack empty")
		return
	}

	fmt.Println("栈的情况如下：")
	for i := this.Top; i >= 0; i-- {
		fmt.Printf("arr[%d]=%d\n", i, this.arr[i])
	}
}
```

既然遍历栈，先判断这个栈是不是空的。如果栈是空的，肯定没有办法遍历，给它提示一句话就行了。如果 `this.Top == -1`，说明初始化的时候就一直没有往里面加东西，或者说不停地弹出来、弹到没有东西了，因此打出一句话 "stack empty"，直接 return 不走了。

不为空的时候，咱们就从栈顶开始打印。但是**你不能够去直接修改栈的值，不要把栈顶给改了，改了的话你自己都不知道它原先有多大了**。所以这里用一个变量 `i`，先把 `this.Top` 赋给 `i`；只要 `i >= 0`，就可以不停地去显示，然后 `i` 不停地减减。第一个 `%d` 就是 `i`，代表从上往下打；然后值显然就是 `this.arr[i]`。越减越小，只要 `i >= 0` 咱们就可以打，如果不大于等于 0，说明已经遍历完了。**注意 `this.Top` 没有发生改变。**

我们测试一下，入栈：

```go
	stack.Push(1)
	stack.Push(2)
	stack.Push(3)
	stack.Push(4)
	stack.Push(5)

	stack.List()
```

因为一共有五个了，我再显示。显示的话用这个 `stack.List()`。注意听，**待会儿我们要用这个栈完成计算式的运算，所以说前面这个还是很重要的，不能写错了，写错会跑不起来。**

大家看，根据我入栈是先入的 1 2 3 4 5，**打印的时候刚好是反过来打的，是 5 4 3 2 1**。来，`run` 一把：

```bash
cd ..
cd stack
go run main.go
```

看代码，OK。跟我们想象的是一样的，栈的情况如下，栈顶是第五个，第 5，以此类推。

#### 第六个元素：栈满了

那么我们问大家一个小问题：如果说我在这里再去加一个 `6`，它往里面走的时候，这时这个地方它就会阻止。因为 `this.Top` 不停地在自增，加到已经加到 5 了——这时它已经到 4 了，已经等于它了，你就加不进去了。

走，我们看效果。同学们可以看到，我们的第 6 个没有加进去，没有加成功，它这儿报了个**栈满**。原因刚才老师已经分析了：你在加这个元素的时候，其实进到这里面的时候，你这个条件就成立了。因为 `this.Top` 已经等于 4 了，$4 = 5 - 1$，就满了，直接扔出去了。

这个是我们讲的栈的入栈和遍历，这个就叫入栈。关于入栈和遍历，我们先给大家讲到这里。

### 出栈 Pop：先取值，再减 Top

对于栈来说，最重要的一个是入栈，还有一个就是我们所说的出栈。**出栈刚好是反过来的，所以这块函数的签名很像**，因此我把它粘一份。

首先命名为 `Pop`。出栈的时候不需要给我值，因为我是从里面取。**出栈至少应该有两个返回值**：一个，你弹出的数是多少；第二个，有没有错误。

```go
func (this *Stack) Pop() (val int, err error) {
	// 出栈先判断是否为空
	if this.Top == -1 {
		fmt.Println("栈空, stack empty")
		return 0, errors.New("stack empty")
	}

	// 先取值，再减减
	val = this.arr[this.Top]
	this.Top--
	return val, nil
}
```

如果它的栈顶等于了 -1，那么栈已经没有东西了，你不能再取东西了，所以提示一句话叫 println "栈空，stack empty"。一旦栈空的话，这个时候你就 return 一个值，随便返回一个什么值，比如说默认值为 0 就返回一个 0 也可以；然后错误给它返回这样一个错误就行了——因为你在取的时候先判断这个 error 是不是已经有错误了，如果这个 error 有错的话，你就知道这个值肯定也是不对的，也不用再去取它了。

如果它不等于空，那么我们就取值。**取的时候先取再减减，同学们，要先取值再去栈顶减减——先取值，再对这个 `Top` 减减，这点注意顺序。** 怎么取呢？`val` 等于我们的 `this.arr[this.Top]`，把栈顶的值先交给 `val`。

> **易错点**：把值给了过后，怎么体现出弹出来呢？弹出来就是两个概念：第一个，**先让 `this.Top--`**，这样子的话前面的栈顶就取不到了；然后再 return。**如果你不移动，相当于再次取的时候你还取到栈顶，这里大家要特别小心。**

Pop 我们就写完了，我们来测一下，看一下这个效果。我们已经入栈了，先弹一个值出来。出栈的时候，我们这个 `val` 等于 `stack.Pop()`。但是这个地方还不能这样写，因为返回的是两个值，所以这样还不行，还得收一下，把值收一下，`error` 也收一下，假设我不管这个 error。

弹出来过后再显示一下。这个时候第一个弹出来的应该是 5——应该是先入的后出，后入的先出，那应该弹出一个 5，栈顶弹出来了。弹出来过后，这边一显示应该是 4 3 2 1。走一个，看效果：出栈一个 5，再打印 4 3 2 1，这个 5 已经没有了。

我们再出一个栈，把出栈多打几次。出栈完了过后我们再重新打一下，看效果：第一次出了一个 5，显示 4 3 2 1；再出一个 4，显示 3 2 1。如果我出了几次，看会不会报错，这都要测一下。这次我弹了一个，再弹一个，再弹一个，看现在栈的情况是什么样子的。同学们看，这样子的话栈这边还有一个，我再弹一个出来。再弹一个出来的话，这边打印的时候就应该是个空栈了——这个时候栈的情况它直接告诉你空栈，果然是 `stack empty`。

那么在空栈的情况下你再弹一个，注意，这句话就会报错，就会出错了。它会报一个什么错呢？已经弹不出来了。出栈的时候这一个 `stack empty`，再弹不出来东西了。

这说明我们这个栈出栈和入栈都是正确的。现在我已经把出栈和入栈做完了。

> **结论**：关于栈的最核心的三个操作——**入栈 `Push`、出栈 `Pop`、遍历 `List`**——我们就算说完了。讲完这个东西的意义是什么呢？就是我待一会儿就要用这个栈来完成一个计算器，也就是表达式的运算。

### 给你 3 + 2，你敢先算吗

这个栈讲完了过后，你得把它用一下，用到一个实际的场景里面去。用一个什么场景来说呢？我们来举这么一个例子：**用栈实现一个综合的计算器。**

这个计算器我们也分阶段来走。首先第一个，大家一定要**先把它的一个思想整出来，然后再来走代码**——如果说没有这个思想的话，代码写出来过后，同学们也很难理解。

我们就针对一个比较简化的东西，就 $3 + 2 \times 6 - 2$ 我们怎么做？我先把我的思路分析一下。

假设这是一个表达式，这个表达式**我们人是怎么算的呢？** 你们先不用去想机器怎么算，如果你是一个人，你是怎么算的？有人说是先乘除后加减。

对的。你看你说的是先乘除后加减，**你怎么知道先乘哪一个、后加哪一个呢？** 是因为你的眼睛很厉害，一下就把它全部扫描了。

假设我不给你看后面这一半，我就给你看一个 3——你知道对 3 怎么处理吗？你不知道怎么处理。即使我给到你这样一个表达式，我就把前面这个 `3 + 2` 给你了，你敢肯定是先做 `3 + 2` 吗？你不敢肯定。因为你不知道后面运算符的优先级到底高不高。比如说这个表达式我就给你看这一半，请你计算，你能计算吗？你计算不了。因为你不知道 `3 + 2` 是先计算呢，还是干别的活，因为你不知道 2 后面这个运算符的优先级是比加高，还是比加低，甚至是相同的，你不知道。

> **结论**：对人来说，这个算式其实挺容易，一眼就看出来应该怎么算。**但是对计算机来说，它就像一个瞎子一样**，不知道你后面是什么东西。因此，这里面的逻辑就要同学们去设计算法了。

我说一下我的算法。当然，我的算法并不代表所有人的算法，因为每个人都有自己的算法——张三有张三的算法，李四有李四的算法，王五有王五算法。针对这个算式，我是这样来思考的。

### 整个算法：一条扫描线，两个栈

我先设计两个栈。我们知道，进行运算的时候最重要的就是两种特性的符号：**一种是数，一种是运算符**。所以，我把这个叫做数栈，另一个叫做符号栈。当然有些地方叫法可能稍微差异一点。

现在我开始来进行模拟，我是一个电脑。我认为我有一个指针叫 `index`，开始扫描了。第一步，创建两个栈，一个叫做数栈 `numStack`，还有一个叫操作符栈 `operStack`。数栈显然大家很清楚地知道，就是存放数的；`operStack` 是存放操作符的。

再设计第三个，设计一个 `index` 变量，或者你把它理解成是一个指针都可以，初始化给它一个 0。它是用来扫描我们这个表达式的——表达式说白了就是一个字符串。

#### 扫描到 3：数字直接入数栈

`index` 开始扫描。先扫到 3，如果发现它是一个数字，没有甚么可说的，**直接把它入数栈**。

逻辑是：扫描时如果发现是一个数字，则直接入数栈。**因为一个数你不知道后面有什么运算符，得先把它保存起来。** 3 就被放到这个栈里面去了，显然是在栈底。这个时候栈里面有一个 `top` 指向了 3。

```text
   扫描 3        数栈 [3]                 符号栈 []
```

> **注意**：这里数字我们只考虑的是个位数，将来这个数是多位的，还要重新考虑，比如 399，还得考虑拼接的问题，但是**我们先简化**。你在做一个东西的时候，先考虑一个简单的，不要先考虑复杂的——考虑复杂的你一时半会儿思路就阻在那个地方动不了了。

#### 扫描到第一个加号：符号栈空，直接入栈

如果发现是一个运算符，里面的逻辑又分这么几个。

如果发现**当前 `operStack` 是个空栈**，那说明你现在只扫描到一个运算符，后面的数没进去也没法弄，所以符号栈是个空栈，这个运算符就直接入栈。这个没有甚么可说的，直接入栈。

那现在先把加号放进去。

```text
   扫描 +        数栈 [3]                 符号栈 [+]
```

这个也是我们编译器在底层做运算时的原理，听完了对大家理解还是非常有帮助的。

紧接着又扫描到 2。扫描到 2，如果发现是数字直接入数栈，所以 2 也入栈了。2 一旦入栈了，栈顶就指向了 2。

```text
   扫描 2        数栈 [3, 2]              符号栈 [+]
```

#### 扫描到乘号：优先级不够高，不动，先入栈

紧接着扫描到一个星号，实际上就是乘号。发现是一个运算符了，但是 `operStack` 不是一个空栈。这个时候你就要考虑问题了：**你得考虑扫描到的运算符的优先级，跟当前符号栈栈顶的运算符的优先级哪个高、哪个低。**

逻辑应该是这样子的：

- 如果发现当前符号栈 `operStack` **栈顶的运算符的优先级，大于等于当前准备入栈的运算符的优先级**，说明你要赶紧去计算，不计算的话后面就完蛋了；
- **否则**，直接写个"否则"——否则的话，这个运算符就直接入栈。

当然这个逻辑到时还要优化，因为这里面情况还有很多，比如加小括号、大括号、中括号，那是比较麻烦的，待会儿我们说。

那么目前这个情况应该怎么做呢？就要从这个 2 把它弹出来，把 3 弹出来。注意，你弹了两个数出来过后……

不过我这个地方现在还不是一样的情况。**因为星号的运算符它是高于加的，现在还不能弹**——因为目前我当前栈的优先级是低于乘法的，所以说我这个逻辑还不适用于现在这个逻辑，那就是下面这个逻辑了：否则，直接把这个乘号给我入栈进去。

**因为它满足的是"否则"这个条件，跟我上面那个还不一致，所以说我现在应该把乘号入栈。** 入栈的话，应该是这样入栈，入栈这个地方就指向它了。

```text
   扫描 *        栈顶(+) 的优先级 < (*)  →  不算，直接入栈
                 数栈 [3, 2]              符号栈 [+, *]
```

#### 扫描到 6：又是数字，直接入栈

紧接着它继续扫描。扫描到 6，注意，扫描到 6 的时候，它又满足这个条件了。如果发现是个数字，这个没什么可说的，直接入栈。

```text
   扫描 6        数栈 [3, 2, 6]           符号栈 [+, *]
```

#### 扫描到减号：先算，再入栈

紧接着同学们可以看到，现在扫描到减号了。**现在这个情况就满足刚才我们说的那个情况了。** 因为目前我们发现栈顶的这个运算符（`*`）的优先级是大于减法的。

根据刚才说的这个逻辑，因为你是大于等于当前准备入栈的，现在把这个 6 和 2 弹出来。把这个 6 和 2 弹出来，也就是弹一个，再弹一个，大家想象，到时肯定用一个变量来接收。

> **易错点**：注意弹的顺序——**是 2 先弹出来，6 后弹出来**。你说 6 和 2 弹出来过后，紧接着从符号栈把它弹出来，**必须从数栈弹两个**，那么这个星号也弹出来了，它们弹出来进行运算。运算过后等于 12。

等于 12 过后，同学们注意听：把这个 12 重新入到数栈里面去。运算后把结果入栈到这个数栈——你的栈顶再往上面走一下。

栈顶走一下过后，**当前这个符号你还没做处理呢**。所以说这个时候符号仍然入栈，再入这个符号栈。

```text
   扫描 -        栈顶(*) 的优先级 >= (-)  →  弹 2、6，弹 *，算得 12
                 数栈 [3, 12]             符号栈 [+]      （- 还没入栈）
                 再把 - 入栈
                 数栈 [3, 12]             符号栈 [+, -]
```

> **结论**：这两个逻辑是反过来的，而且是 **if-else 的关系**——空栈就直接入栈；栈里面有东西的情况分成第一种和第二种。这样大家看起来就轻松了一点：2、2.2，符号栈不是空栈的时候有这两个逻辑。

那么现在同学们看，你运算完后把 12 入栈了，星号也弹出来了，现在把符号再入符号栈——那现在你符号是什么呢？是减法。所以说这个减法就入到这个位置。入到这个位置的话，因为你现在栈顶是在这儿，所以相当于**把它给覆盖了**。

#### 扫描完毕：把剩下的算干净

走完了以后，又继续扫描，扫描到一个 2。扫描到 2 的话，这个时候它满足扫描是数字，直接入栈。也就是说这个地方直接被覆盖掉了，因为你是栈顶嘛，紧接到这里面去了。

这个时候它再扫描，没了。也就是说它再扫描的时候它发现已经什么都没有了。

那么**最后一个逻辑，第七个逻辑**：如果扫描全部完毕，则应该依次从数栈里面弹出两个数，再从符号栈弹出一个数进行运算。运算一次入数栈，弹一个符号位，弹两个数，结果再入栈；再弹一个符号位，再弹两个数，再运算，再入栈。**最后留在数栈的就是最终的结果。**

如果扫描完毕，就依次从符号栈取出或者叫弹出符号，然后从数栈取出两个数进行运算，运算后的结果入数栈。直到符号栈为空，就结束了。

现在开始弹东西了。**弹一个 2，弹一个 12**。注意弹的时候是后面这个数减去前面这个数：

> **易错点**：一定是**后面这个数对前面这个数操作**。所以你这个时候怎么弹的呢？又弹了一个 2 出来，紧接着弹了一个 12 出来。**但是在这个地方运算的时候，一定是后面这个数对前面这个数操作**——所以说在运算的时候你要这么去：12 减去一个 2。那么这个时候，这个减号也被你弹出来了，结果等于 10。

等于 10 过后，把这个 10 再入栈，相当于把这个给覆盖掉了，栈顶又上去了。栈顶又上去过后，符号栈还有一个加号，紧接着再把 10 和 3 取出来，再把符号取出来——符号取出来过后就是加法。加法完了过后，整个是 13。

```text
   扫描 2        数栈 [3, 12, 2]          符号栈 [+, -]

   ── 扫描结束，符号栈还剩 [+, -]，从栈顶往下弹 ──
                 弹 2、12，弹 -      →   12 - 2 = 10
                 数栈 [3, 10]            符号栈 [+]
                 弹 10、3，弹 +       →   10 + 3 = 13
   最终           数栈 [13]               符号栈 []
```

> **结论**：最后这个结果就是 13，算出来了。这个是整个我们操作的、计算机包括我们人分析算式的一个流程，这是一个算法的流程。大家看能不能理解，好好地想一想。

#### ASCII 码里那四个不连续的数

现在我们给这个栈增加几个方法。第一个，我们要给这个栈增加一个判断一个字符是不是一个运算符的问题。我们这里面**只做加减乘除，取模那些我们先别去玩了**，那个就很复杂。

同学们都很清楚地知道，**单个的字符在本质上其实就是一个整数，它是一个 `byte`**。因此我这儿就偷了一个懒：**我就直接用它对应的 ASCII 码来判断它是不是一个整数**，这就很巧妙地利用了这个特性。因为加法、减法、乘法和除法，它们都对应一个 ASCII 码，ASCII 码其实它的本质就是一个整数。

```go
func (this *Stack) IsOper(val int) bool {
	if val == 42 || val == 43 || val == 45 || val == 47 {
		return true
	} else {
		return false
	}
}
```

给它传一个值进来，比如 `val`，是个 `int`。待会儿我把截过来的肯定要转成一个 `int` 给它。

注意，同学们，这段代码确实要小心一点，写错了调试起来难度很大，写错你自己调错你都不知道怎么去调。我们来查一下 ASCII 码表：它的**乘是 42，加是 43，减是 45，除是 47**。

> **易错点**：注意，这地方特别诡异。以前我自己写完了过后我整了半天，我说这个结果老是错的呢，我发现这个地方错在这。它这个 ASCII 码特别讨厌——一般中文说加减乘除嘛，我们也很少别的顺序，结果它是**乘、加、减、除，一下顺序变了**。第二点大家注意到，**它的这个 ASCII 码不是连在一起的**：一般来说加减乘除连在一起的话，42、43，跳过了一个逗号，然后又跳过了一个点号才是这个乘。有些同学一上来就是很自然地 42、43、44，然后一个 45，最后结果死活都是错的，结果就在这犯了一个巨大的错误——**因为我们人都有惯性思维嘛**，大家都会认为是加减乘除，而且一般都会认为它连在一起的，结果全不对的。

所以注意这个细节：42、43、45 和 47。在这个情况下我们认为它是一个操作符，返回一个 `true`，`else` 返回一个 `false`。当然这边应该有一个返回值叫 `bool` 值。

#### Cal 运算方法：num2 在前，num1 在后

还有一个问题，大家可以看到，待会儿我们还需要一个方法——就是计算。大家看我这反复说"运算后、运算后"，那么这个运算后我们肯定最好也写一个方法，比较好。**你别到时间说每一个都是自己在这儿加减，这肯定不行。**

```go
func (this *Stack) Cal(num1 int, num2 int, oper int) int {
	var res int
	switch oper {
	case 42:
		res = num2 * num1
	case 43:
		res = num2 + num1
	case 45:
		res = num2 - num1
	case 47:
		res = num2 / num1
	default:
		fmt.Println("运算符错误")
		res = 0
	}
	return res
}
```

我们就叫 `Cal` 吧，calculate 就是计算的意思。注意，你给我传两个数进来，再给我传一个运算符就可以了。我们都是用 `int` 来算的，那就用一个很简单的形式——`switch` 语句。

> **易错点**：`case 42` 是乘法，**乘法顺序其实是无所谓的**，所以说这地方你可以写 `num1` 乘以 `num2`，但是**最好不要那么写，还是按顺序来，把 `num2` 写前面去比较安全**。虽然这样写两个相乘无所谓，但是咱们还是按规矩来，**因为我们的栈是先入后出来的**，所以说这样子调整一下。

`case 43` 是加法，`res` 就等于 `num2` 加上一个 `num1`，没问题。`case 45` 是减法——**减法的顺序一定是 `num2` 减 `num1`，否则这个结果是错的**。`case 47` 是除法，`result` 就应该等于 `num2` 除以 `num1`。

如果还有别的，那如果说你不小心给了一个错误的，那么我给它提示一下，`default` 就是你的运算符有问题，就直接提示运算符错误。最后处理完了以后，不要忘了这件事情：`return`，return 我们的 `res`，就完事了。一个地方都不要错。最好再看一下，42、43、45、47，没问题。

#### 优先级方法：乘除为 1，加减为 0

运算的方法写完了，我还缺少一个特别重要的方法，就是优先级。**这个地方就需要同学们动脑筋了。**

你说优先级谁高谁低呢？没办法判断，因为你不知道现在传的是加法、减法，还是除法、乘法，没办法。**你只有一个办法：你给我一个操作符，我给你返回它的优先级。底层都这么干的。** 今天学完了过后，你至少知道我们编译器在底层怎么做加减乘除的，其实还是挺有意思的。

我们可以定：**我认为乘法和除法它的优先级为 1，加法和减法为 0 就可以了。**

> **结论**：注意，这个优先级是**我们定的，是程序员定的，很具有灵活性，没有一个固定的说法**。如果你将来在小括号的优先级更高，那你就把小括号的优先级定为 2，它底层也是这么来做的。因为我的运算符比较少，就加减乘除，所以我这样定义一下。

编写一个方法，返回某个运算符的优先级。`priority`——优先级这个单词用得不太多数。你给我一个操作符就可以了，也是一个 `int` 类型的；我给你返回一个优先级，也是 `int` 类型：

```go
func (this *Stack) Priority(oper int) int {
	var prio int
	if oper == 42 || oper == 47 {
		prio = 1 // 乘、除
	} else if oper == 43 || oper == 45 {
		prio = 0 // 加、减
	} else {
		prio = 0
	}
	return prio
}
```

如果你这个操作符等于乘（乘是 42），或者等于除（除法这个符号是 47），那么我就返回它的优先级为 1。`else if`，如果它的操作符传的是一个 43，或者是 45，那么我认为它就是加或者是减。43 是加，45 是减，确定一下，在这样一种情况下，我们认为它的优先级为 0。

最后一种就是 `else`，我们就认为有错误——`else` 我就不去处理了，默认给它来一个 0。因为这儿还有一个其他情况，比如将来还想设置一些小括号、大括号、中括号，你可以在这个基础上再增加。优先级就写完了。

### 从字符到 int：IsOper 之前必须先跨的一道坎

你判断它是不是一个操作符，不就是调用这个方法吗？但是**你要传进去的是一个 `val int`。问题来了，你怎么把这个字符转成对应的 `int` 值？**

比如说，你现在扫描了一个字符串是加号，那你现在得把这个加号想办法给我转成什么玩意儿？转成 43。这本身就需要大家动脑筋。

如果是 Java 语言，它相对比较简单，它本身就可以通用的，直接往里面一扔就完事。但是 Go 语言里面稍微麻烦一点，要这么做。

首先，它是一个字符串，你先把它转成一个切片。因为我们知道，**字符和 `byte` 是一个对应关系**，因此你先要这么做。我先把它处理一下，`temp`：

```go
ch := exp[index : index+1]
```

我先把它转成一个 `byte` 切片。**也就是说当我转成一个切片的时候，你假说是个加号，其实它已经把你里面这个加号转成那个 `byte` 了。** 然后你要取的是第一个——因为他并不知道你这个 slice 里面有几个，对不对？你要取第一个，因为他还是一个切片。

取完了过后，各位同学，你还要把它转成 `int` 就可以了。这个 `temp` 就是 43，而且它的类型是 `int`。**如果你不转成一个 `int` 的话，它是一个 `byte`，是一个单个 `byte`，你传也传不进去，你还得转。** 这个就拿到 43 了，这就是字符对应的 ASCII 码值。

### 三个方法串起来：符号栈不空时的两条路

我们先处理简单的。大家都知道，如果是一个数的话，我们直接把它扔在数栈里面，还记得吧？也就是说这个时候你直接去找 `numStack`，调用它的一个方法叫 `Push`。因为这个栈我们是测试过的，没毛病，所以直接把它放进去，把这个 `temp` 扔进去就可以了。没有任何问题，因为它已经转换成一个 `int` 值了。

如果说现在应该接着往下走，那么到这里面去了。这里面**如果是符号，又分两个逻辑**——哪两个逻辑呢？刚才我们分析过了。

> **结论**：这个时候你突然发现这个思路是多么的重要。**如果前面老师没有给大家分析这个思路，我就直接写代码，我估计除非你曾经学过，不然的话你不知道我在写什么了。**

第一个逻辑：先判断 `operStack` 是不是空栈。如果是空栈，就直接入栈完事。那我怎么知道它是不是一个空栈呢？非常的简单——**我只需要判断它的 `Top` 是不是等于 -1**：

```go
if operStack.Top == -1 {
	operStack.Push(temp)
}
```

当然你也可以写个方法，我这儿因为没写方法，我就只能这样先写了。`operStack.Top` 它是等于 -1，说明它是个空栈。如果它是一个空栈的话，这个符号直接把这个符号入栈了——把 `temp` 入栈，因为你现在已经把它转成一个整数了。

那么，如果它不是一个空栈的话，又要分逻辑。好，那先判断这个逻辑——**判断当前 `operStack` 栈顶的运算符是不是跟它大**：

#### 栈顶优先级 vs 当前优先级：弹两个数算一次

我们用 `operStack` 调用它的这个优先级方法，先把它优先级取出来。取出栈顶的那个值：

```go
operStack.Priority(operStack.oper[operStack.Top])
```

**这个地方就是取出栈——没有取出，只是看一下，没有弹出来。** 我看看你这个符号栈的栈顶的那个符号，它的优先级是多少。如果说它大于等于当前这个——当前这个也比较好处理，`temp` 是一个数，你已经把这个符号位转成一个整数了，它刚好就可以判断。

那弹数的话，弹两个数。为了配合运算，我们定义需要的变量。先有两个数我是需要的，我先初始化 `num1`、`num2`；同时我们还要拿到一个你弹出来的 `oper`，因为你运算的时候需要一个 `oper`，所以说我把这个 `oper` 也弹出来，也是一个整数。我们都把它做成一个整数。最后还有一个结果，我们也把它用 `result`。**这是我需要的四个变量。**

弹，先从数栈里面弹两个数出来，数栈是 `numStack`。

> **注意**：大家放心，你只要走到这里面，数栈里面一定有东西，不可能没有。**如果没有的话只有一种可能性，你表达式写错了。** 它一定会弹东西出来。

弹出来两个过后，再弹一个运算符。这个运算符要从 `operStack` 弹，一定要把它弹出来、出栈。

> **易错点**：注意，**你这个时候给这个数的顺序一定要是按照这个弹的顺序给**。因为方法里面写的时候是已经把这个顺序颠倒过来了，**如果你这个地方错位了的话，整个结果刚好相反**。我这儿是 `num1`、`num2`，`num1` 是代表先弹出来的数。所以这个地方我们先把先弹出来的当成 `num1`——如果你这个顺序不对也是要出问题的。

#### 弹栈时 Pop 的两个返回值要收掉

```go
num1, _ := numStack.Pop() // 第一个弹出来的
num2, _ := numStack.Pop() // 第二个弹出来的
oper, _ := operStack.Pop()

res := operStack.Cal(num1, num2, oper)
numStack.Push(res)
```

这个 `Pop` 它会返回两个，一个是 `num`，还有一个就是 `error`。那个 `error` 我忽略，我不要。这个也是一样，我忽略。这个就不会再报错了。

算出来过后还有一件事情——**你得把这个 `result` 再重新压入到数栈里面去**，大家不要忘了这件事情。把运算结果要重新入栈到数栈，这个我们在前面已经做过算法分析了：`numStack.Push(result)`。

压进去过后**没有完，还有一件重要的事情：你还得把当前这个符号再入栈**。因为当前符号你还没有处理呢，你只是把原先那个符号栈里面弹出来算了一把，你当前这个还得压进去，不然的话少了一个运算符。它底层就这么做的：

```go
operStack.Push(temp)
```

> **注意**：先把当前这个符号压入，压入哪个栈呢？压入我们的符号栈。

好，这个时候我们已经把这个逻辑处理完了。别忘了，还有一个逻辑，就是如果它这个优先级并不大于准备入栈的——**没有大的话那怎么办呢？不用犹豫，直接把它入栈。** 这里还有一个 `else` 的关系。

#### index 加加，和"最后一位别探头"这件事

但是，但是**这个第七个逻辑没有处理**——就是你整个做完了以后，不是栈里面还留了一些东西吗？那这个时候就要根据刚才的分析，依次从符号栈中取出来。

> **易错点**：你这只取了一个就跑了，**`for` 循环永远是死的**。取了一个、取完一个过后你做完一个处理就跑了，不行，你还得往下继续取、继续扫描。

那么，你怎么样体现出继续扫描这个特点呢？就是那个 `index` 要加加。

> **易错点**：**注意，这个 `index` 加加也很恐怖啊，不能乱加。因为你加的时候有可能已经越界了。**

所以这个时候咱们要像这么去处理一下：**先判断这个 `index` 是不是已经到了最后。** 那你怎么来判断已经到最后了呢？非常的简单——**如果它加一已经等于这个表达式的 `length` 了，说明它这个 `index` 已经在最后这一位了，而且已经处理过了**。整个长度下标是从 0 开始算的，比如说你现在是 4，说明它已经到最后了，那 4 再加 1 等于 5，好，满足。这个就相当于说到最后了，那你就 `break`，不要再玩了。否则 `index++`。

```go
	for index < len(exp) {
		// ... 上面那一大坨逻辑 ...

		if index+1 == len(exp) {
			break
		}
		index++
	}
```

等这个处理完了过后呢，就是这个 `for` 循环处理完毕以后，其实就完成了前面的六——就是前面这个逻辑全部做完了，就剩下最后一件事情了。

### 扫描结束后：把符号栈清干净

如果扫描完毕——因为你 `for` 循环结束了就扫描完毕。**但是你这个运算并没有意味着全部结束，因为后面可能栈里面还有很多数没有处理。**

好，完成这个逻辑呢也是非常简单的一件事情，直接玩一下就行了，`for` 循环。**但是你在弹的时候你要先判断现在这个符号栈是不是已经空了**——你退出的条件是符号栈为空：

```go
	for operStack.Top != -1 {
		num1, _ := numStack.Pop()
		num2, _ := numStack.Pop()
		oper, _ := operStack.Pop()

		res := operStack.Cal(num1, num2, oper)
		numStack.Push(res)
	}
```

如果 `operStack` 的 `Top` 等于 -1，说明它已经空了，你不要再玩了，赶紧走。这是退出条件。

如果说它没有到这个地方呢，把这个逻辑重新走一遍。**但是走的时候呢有一点点变化**：数栈取一个，再取一个，计算，计算完了把它再重新压到数栈里面去——**但是这个没有了**。就是你现在的符号栈只有取，没有往里面压的过程了。

最后，当它退出来的时候，如果你这没有任何毛病，这个栈里面就留下了最后一个结果：

```go
	res, _ := numStack.Pop()
	fmt.Printf("表达式%s，结果=%d\n", exp, res)
```

**它一定是剩最后一个数，没有别的原因，没有别的可能性。**

### 第一次运行就翻车：那个离谱的结果是怎么来的

我保存一下，先看语法有没有毛病。看一下代码有没有毛病——我们发现代码从目前来看没有毛病，但是能不能成功，现在我也得试一下。因为里面代码还是比较多：有一个 `for` 循环，`for` 循环里面有 `if`，`if` 里面还有 `if`，`else` 里面还套了一个 `if else`，这个逻辑已经比较复杂了。OK，那么我们希望一次成功。

把这个再来进行一个运算：**$3 + 2 \times 6 - 2 = 13$，正确。**

为了证明它的正确性呢，我们把这个值稍微改变一下。把这个改成 4——那现在的表达式是 `3+3*6-4`。我们先算一下：$3 \times 6 = 18 + 3 = 21$，$21 - 4 = 17$。看结果——**是 17，是正确的**。

> **易错点**：但是呢，老师要提出一个问题：我们在前面讲的时候，同学们也感觉到有一个问题存在——**比如说我把这地方改成一个 30，那整个就错了**。因为你改成 30 的话，你在这个地方没有做任何处理，你是把一个直接当成一个数字，0 没做处理。这个时候我们看运算结果是什么样子的：$30 + 3 \times 6 - 4 = 14$，显然是说错的。

### 多位数：keepNum 这个变量

好，那么下面呢，我们就准备来解决这个字符串拼接的问题。

处理多位数的思路是这样的：**因为数字里面不可能有操作符，所以"如果扫描是一个操作符"这一整大块不需要做任何变化，这一大块都没毛病。主要的毛病是在这里**，因为你直接把 `ch` 做了处理，这是有问题的。

那怎么办呢？这里要动脑筋。**先设计一个变量，这个变量是专门用来做拼接的**，叫 `keepNum`，它是个字符串。

> **结论**：这个东西就是练习大家的一种思维方式。这个代码能写出来，说实话有些代码你自然就会感觉到并不难了，这个很有用。

**问题在于怎么来决定它下面不是一个数字呢？所以你还得往前面探一位。** 就是每次扫描 `index` 的时候，你再往后面探一位，但是 `index` 不要动——你往前面探一下，看下一位是不是一个运算符，如果它不是运算符那就继续拼接。

**探的时候还有一个危险**：有时候往下面它还能探成功，但是假设已经到最后一位，你再往前面一探就探空了，**探到一个空指针直接报错**。所以探的时候还不能乱探：如果已经到最后了，就别探了，直接把它拼接进去就行了。

```go
var keepNum string

for index < len(exp) {
	ch := exp[index : index+1]

	keepNum += ch // 是数，先拼上

	if index == len(exp)-1 {
		// 已经是最后一位了，别再探头，直接入栈
		val, _ := strconv.Atoi(keepNum)
		numStack.Push(val)
	} else if isOper(int([]byte(exp[index+1:index+2])[0])) {
		// 往后面看一位，是运算符，说明这个数结束了
		val, _ := strconv.Atoi(keepNum)
		numStack.Push(val)
		keepNum = "" // 一定要清空，不然会在原先的基础上继续拼接
	}
	// ...
}
```

如果 `index` 就等于表达式的长度减一——为什么减一呢？因为 `index` 是从 0 开始算的——这个说明已经到屁股后边了，**千万不要再探了**，直接把 `keepNum` 转成一个整数压进去。当然这个 `keepNum` 也不一定就是单位数，它也有可能是多位数。

`else` 逻辑：如果它不到最后一位，那么你可以向 `index` 的后一位探一位。**这个逻辑有点麻烦：`exp[index+1 : index+2]`**——因为你要看后边取，取的切片是 `index+1` 到 `index+2`，我们没动 `index`。这个取出来也是一个字符串；取出来是字符串的话，要把它转成一个 `byte` 切片，改成一个 `byte` 切片过后，再取出它的第 0 个值，取出第 0 个值还要把它转成一个 `int`，看它是不是运算符。

**如果是操作符，说明这个就结束了**——因为你在后面再看一眼它已经是运算符了，你就不需要再去拼接了。做完有一个**特别重要的事情，把这个清空：`keepNum = ""`**。如果你不清空的话，它会在原先的基础继续拼接。

而**拼接的动作在哪里完成呢？** 如果不是运算符，我们就直接拼了：`keepNum += ch`。来了之后是数，先拼接，因为 `keepNum` 原来是空的，就拼一个进去。再来再拼再拼，后面决定是不是再继续拼接还是加进去，取决于下面这个 `if` 逻辑。

我们看看这个代码有没有毛病。现在我已经把它做成了一个 $30 + 3 \times 6 - 4$：现在这个 $30 + 18 = 48$，$48 - 4 = 44$，是正确的，这就没有毛病。

那么我们可以把这个位数再调得大一点，比如调成 $30 + 30 \times 6 - 4$。就是 $30 + 180 = 210$，$210 - 4 = 206$。走——**206 出来，正确的**。那么我们可以把它再做一点运算，比如再减去一个 6，那应该等于 200。正确。

> **结论**：我把这个代码就完成到这，基本上我认为就可以了。因为我们并不是教大家去写一个计算器——要写一个有大括号还有小括号的**完整**代码，我这里有一个资料，算法项目资料里有一个栈实现计算器的完整代码，是 C++ 版的，打开看一下它的源码。这个相对来说完成得比较全一点，它做了好多判断，有三百多行，然后这边还有一个头文件。如果有兴趣的同学可以把这个再看一看，**但是我建议大家也没有必要去看了**，你们只需要把老师讲的这个掌握了就行。

我们讲这个栈的目的为了什么呢？**第一，让大家体验一下运算它的底层是什么运行的；第二，让大家体会到栈的使用场景。** 第一个版本，是要求同学们能够写出来的。

编程的时候，不管你将来做什么编程，**一定先把思路理清楚，然后再写代码**，不然的话可能后边就写懵圈了。当然这也仅仅是韩老师的思路，你也有可能在别的地方看到别人的思路跟老师不一样，那也可以。

#### 它快不是因为"同时在排"

那么我们来分析一下，**为什么快速排序法它会快呢？首先我要告诉大家，千万不要以为你的快速排序法是在同时排，没有同时排。** 因为你们可以看到，它的代码仍然是按照递归的方式走的。也就是说，它其实也是一步一步做的。它进到这里面，往里面不停地追，追完了过后，等它把左边递归完了过后，它才去递归右边的——**并不是像我们想象的是同时在排，没有。**

那为什么它没有同时排，仍然这么快呢？以我们上午讲的那个为例，快速排序法是这样子的：**它先找到中间一个值，然后首先第一点是，它从这边扫描，这边同时也在扫描，扫描的时候两个同时交换。这一下就比以前传统的方法要快很多了。** 找一个，然后两个同时找到，找到过后两个一交换——**光这块，就省很多时间。**

第二个，等到它扫描完了过后，它这一半，这个逻辑又在进行这样子折半。**也就是它的整个比较次数是在每扫描到一个中轴的时候，它是按一半的方式在减少比较的次数，这就很猛。**

> **结论**：像以前的插入排序法，它总是找一个往里面排，找一个。那么它插入一个数，下一次就减少一次的比较。比如我们按选择排序法来说，它是先找 0 到 $n-1$ 最小或者最大数给它填进去，填完一个数过后，它下一次比较的次数**仅仅是减少了一次而已**；等到它再去插入第二个最大或者最小数过后，它下一次比较次数又在减少一次而已。**但是我们快速排序法不是这样子的，它先把这个地方找到过后一移位，移位过后这边折半**——它每次是按一半的方式来减少比较的次数，**所以它递减的速度会很快，效率就会很高。它的根本原因就是减少了比较和交换的次数。**

如果别人跟你讲快速排序法是不是因为同时在排？不是这样子的。如果同时排的话那就更快——如果你有一个能力，让它给我们开协程，把快速排序法结合协程来做，那速度还会提高。

但是有一个问题，因为一个数组它有锁的关系，它要同步，所以应该也很难做到。**四个协程同时去排一个数组，系统里面要对这个数组进行加锁，当有一个协程在操作的时候，可能另外一个协程就操作不了**——但是也不一定，我没去试过。如果有同学有兴趣，可以说把这个数组让几个协程同时来排，看看能不能把它搞定，可以去试一试。

#### 代价：CPU 一路飙到 60

但是，它对程序耗费的资源也是很厉害的，**因为它开了很多的栈。每开一个栈都会吃掉一些资源，所以它耗费资源会比较大**。

待会儿我们打开任务管理器再运行一下，你会发现它的 CPU 还有内存会耗费得比较厉害。**刚才已经噌的一下到了 60，现在基本上维持在 50 左右，CPU 利用得还是很多的，因为它不停地开这个栈。**

但是如果我来用选择排序法，你来看看选择排序法对 CPU 的耗费率。它还是维持在 40 左右、30 左右，**它并不像快速排序法耗费那么厉害，因为它没有开栈。**

这个原因我就给大家分析到这里，大家再去体会一下。要理解快速排序法它快的根本原因，**就是它减少了比较和交换的次数，而且是按除以 2 的倍数递减的。**

## 递归拆开看：一个 n=4 为什么打印出 2、2、3
> 对应块：BLK151 | 覆盖分集：P378-P379 | 块标题（分集名）：《376_尚硅谷_数据结构和算法-递归机制剖析》

### 先看那只走不出迷宫的小老鼠

递归我们前面虽然讲过，但是比较简单，而且没有涉及到回溯。现在我们来看一个相对来说比较复杂一点的、**涉及到回溯的递归**。

迷宫问题，刚才我已经简单地说了——就是有一个小老鼠，它从这个位置开始出发，然后能够到达这个位置。当然**它也有可能到不了**，因为你不知道它是不是一个死路。打个比方，你从这儿能够到达这个位置的前提是，中间它的的确确有一个通道。假设你的迷宫是这样子的，这有一个小圆圈把它堵死了，它是不是就出不来了？所以它也有可能是出不来的。

还有一个最重要的问题是，小老鼠从这个地方出发，它的路径很多。它既可以从这过来，它也可以这样子走，当然还有很多很多选择。**你怎么知道它从哪走呢？哪条路又是最短的呢？** 这就需要我们用递归的方式来解决。所以迷宫问题是一个非常经典的用递归解决的回溯问题。

不过在进迷宫之前——我们已经会用递归了，只是很久没用，有点生疏。我们先把这个机制拆开看一眼，回头再回来解决迷宫。

### 递归到底是什么

**简单地讲，递归就是函数或者是一个方法自己调用自己**，每次调用的时候传入的参数、传入的变量是不一样的。递归有助于编程者解决复杂的问题，同时可以让代码变得比较简洁。它可以解决一些比较复杂的问题，而且代码会变得比较简洁，所以递归在我们的开发中用得还是比较多的。

> **结论**：比如说我们在上一次课讲快速排序的时候，就用到了递归——你明显感觉到它的速度会提升很多。

为什么很多地方都要自己调用自己？因为很多概念在我们现实的问题里面有一种逻辑，就是**很多是自己去调用自己**的。比如说，咱们要去显示一个目录树，它也是自己调用自己；再比如说刚才那个排序，排序也有可能要自己调用自己；还有查找、二分查找，都有这种概念。

### 把递归的机制在栈里重画一遍

当时我们讲快速入门的时候，出了两个问题：**一个是一个打印问题，第二个是一个阶乘问题**，我们都是用递归来做的。借助这个快速入门，我们把递归的机制做一个非常简短的回顾。就以打印数字为例。

当时我们是出了这么一个题，说有一个函数叫 `test`。`test` 可以接收一个 $n$ 值，如果这个 $n$ 大于 2，然后 $n--$，再调用自己——这里就是递归调用。调用完了过后，它进去过后，这个 $n$ 还要继续减减，最后输出这个结果：

```go
package main

import (
	"fmt"
)

func test(n int) {
	if n > 2 {
		n--
		test(n)
	}
	fmt.Println("n=", n)
}

func main() {
	n := 4
	test(n)
}
```

我们来分析一下这段代码到底怎么运行。

#### n=4 的完整旅程

**这里其实就是栈在里面起作用了。** 说这是我们的一个内存，你可以把它理解成就是一个栈。当我们的程序从这里开始执行的时候，刚开始执行的是主函数——你可以理解成在内存里面就有一个栈，栈的空间很大，它刚刚进来的时候有一个栈空间，叫**主栈**。

主栈里面有一个变量 $n = 4$。$n = 4$ 是在这赋值，然后调用 `test(n)`。这个时候它会去**开辟一个新的空间**，这个新的空间我们可以理解成又是一个新的栈，但是它仍然是在大的栈空间里面。它在调用 `test` 的时候，**先对这个现场做一个保存**，让这里面的数据不要跟 `test` 里面的数据混在一起。因为栈是先入后出的，所以它会把调用的函数的新栈压在栈的上面。

```text
   调用方向：主栈 → 栈① → 栈② → 栈③      （栈先入后出，新调用压在上面）

   ┌ 主栈 ┐    ┌ 栈① ┐    ┌ 栈② ┐    ┌ 栈③ ┐
   │ n=4  │ →  │ n=4  │ →  │ n=3  │ →  │ n=2  │
   │      │    │n--→3 │    │n--→2 │    │2 不大于 2│
   └──────┘    └──────┘    └──────┘    └──────┘

   返回方向：栈③ → 栈② → 栈① → 主栈

   栈③：2 不大于 2，进不了 if，直接往下走到 Println   →  输出 n = 2
   栈②：栈③ 结束，栈顶回退到这里，继续往下走到 Println →  输出 n = 2
   栈①：再回退到这里，继续往下走到 Println            →  输出 n = 3
   主栈：没有后续动作，退出
```

我们来一步一步对照着看。

**第一层**：`test(n)` 被调用，开辟新栈，里面又有一个 $n$。因为是值传递，传进来的默认也是一个 4。注意**两个 $n$ 不打架**。于是它判断 `n` 大不大于 2，显然 4 大于 2，于是执行 `n--`。

> **注意**：`$n--$` 是对哪一个 $n$ 减呢？是对这个栈里的 $n$ 减。**待会儿一定要理解，不然迷宫问题理解起来有点吃力。** 这个看起来很简单，但是一旦应用起来你就觉得很麻烦。

这个 4 就变成了 3。变成 3 过后，它又去调用 `test`，于是你又认为它开辟一个新栈，里面又有一个 $n$，此时此刻这个 $n$ 它就应该等于 3。**但是要注意，它现在代码卡在哪儿的？就是这个栈里面的代码还停留在了 `test` 这一行。**

**第二层**：在这个栈里 $n = 3$ 大于 2，于是又进到 `n--`，减的是**栈顶的这个 $n$**，于是这个 $n$ 变成了 2。变成 2 过后，它又去调用这个 `test`——根据函数调用的规则，它又开辟一个新的函数栈。这些基本原理一定要很清楚。

**第三层**：这个地方传过来的 $n$ 的确就是 2，但是是一个新的栈顶的。它又来判断 $n$ 大不大于 2，显然 2 不大于 2，于是它就执行这个栈里面的这段代码——先输出一个 $n$，输出 $n = 2$。输出完了过后，这个栈就执行完毕了。**这个栈执行完毕，我们的栈顶就会往下走**，回退到上一层去。

**回到第二层**：`test` 进去过后它就往下执行，执行到这它又输出这个栈——因为现在这个是栈顶，它就输出这里面的 $n$。显然这个 $n$ 仍然是 2，它又输出 $n = 2$。输出完了过后，这个栈又相当于执行完毕，栈顶又往下面走。它这执行完了过后它又执行这句话，那么这个时候它又把 $n = 3$ 输出出来了。

当它把 $n = 3$ 输出出来过后，它这个栈又执行完毕，它又回退到主栈。主栈里面没有做任何事情，就退出了。

所以结果应该是 $n = 2$，$n = 2$，$n = 3$，**它是这么一个逻辑。这就是递归调用的一个流程。**

保存一下，看效果：2，2，3，没问题，跟我们想的是一样的。

#### 加一个 else，结果为什么只剩一个 2

明白这个道理过后，我再做稍微的一点点改变——**我把这个地方加一个 `else`**：

```go
func test(n int) {
	if n > 2 {
		n--
		test(n)
	} else {
		fmt.Println("n=", n)
	}
}
```

那你唯一的变化就是加了一个 `else`，那结果又是什么样子的呢？好，朋友们，我们来分析一下。

那还是再来分析，因为这里面的东西已经有了。主栈还是在这儿，然后第一次调用的时，你就从这儿开始走。你的 $n$ 是 4，没有进到 `if` 里面，所以往下走到 `else`。因为你这个 $n$ 是不大于 2 的，所以它进到这里面去——**进到这里面去，它肯定是要输出这个 $n$ 等于 2 的**。

**它一旦输出过后呢，它又回退到这个栈，栈顶往下挪动。** 这个时候对于这个栈来说，它是到这儿进到这个 `test` 的。进到这里面去，因为你这个地方已经进入 `if` 了，所以说这个地方是不会输出的——这个不会输出，于是这个栈也结束了。

最后大家想这个地方又是怎么进去的呢？它也是进去的，所以这个呢也不会输出。**最后其实只输出一个 $n$ 等于 2。**

> **结论**：所以大家要明白这两点——**一是数据是独立的，二是他们的代码也是要根据这个实际情况去执行**。因此在加了 `else` 过后，输出的结果应该只有一个栈顶输出的一个 2。跑一下，我们发现的确如此。

还有**阶乘问题、迷宫问题、球和篮子的问题**——比如在昨天布置的 2005 年 Google 编程大赛里面，球和篮子怎么放、把球放在各个篮子里面有多少个情况，哪种情况是需要的，就可以用递归来解决。还有栈，**栈的一些问题也可以用递归来简化**。

总结一下就是两条：**一是递归解决什么问题——只要是涉及到逻辑重复的地方，都可以用到递归，经典的就是各种数学问题；二是将栈解决的问题，可以用递归来进行简化。**

#### 递归用的时候是有一定风险的

打个比方，**为什么在递归中要减减，而不是加加？** 如果把这里写成加加，同学们可以考虑，这个地方就会成为一个死龟，它就不是递归了，变成一直死龟了。这就死在里面了。因为我们递归有一个前提，**它一定要向退出递归的条件逼近**。

#### 四条必须记住的原则

**第一，递归在去调用一个函数或者方法时，它会创建一个新的、受保护的独立空间。** 什么叫受保护的独立空间呢？就是我们刚才老师画的这个图。我们编译器在底层，在去开创一个新的栈空间的时候，它会**保存现场**——它会留一个地址，会记录我到哪儿去了，于是乎它会把这个地址压入到新的栈。等到它执行完了过后，它会从这个地址再重新退回来。所以这点大家要清楚，它会有一个保护的机制，这是编译器底层做的。

**第二，函数的局部变量是独立的，不会互相影响，即使你的变量名相同也不会。** 但是有一点，有些时候你恰恰要用到一个特点——就是你所有的函数用的却是**同一个变量**，也有可能用到。

> **结论**：比如我们前面讲的快速排序，如果是快速排序，你们发现我们在每一个栈里面用的是**同一份数组**的时候，那么这个时候传递的时候就应该传递**引用的方式**——它们每一个栈用的指向的数组是同一个数组，不会是两份。**这次我们解决迷宫问题，就必须传同一份地图过去，否则的话就会出问题。** 所以大家一定要分清楚你的实际情况：**如果你在这个递归里面，每一个栈里面你要引用同一份数据空间，那就得引用；如果你是独立的，比如像 $n$，你认为是每一个地方是不同的变量，那你就用值传递。**

**第三，递归必须向退出递归的条件逼近，否则就是无限循环。** 比如刚才老师写的这个东西，如果没有减减，要么不动，它也是个死龟——因为它进去就退不出来了。你只要看到类似这样一个提示：不停打一句话，在第九行不停地打，像这种情况一般来讲都是出现死循环了。**所以说大家一定要找到这个条件，一定要分析出退出递归的条件。**

> **结论**：那么这个条件是什么呢？**你自己要分析。** 比如待会儿讲的迷宫问题，如果你分析不出来什么时候退出这个递归，你肯定是出不来的——这个小老鼠就在迷宫里面转转转，最后就晕了。**你得分析出来什么时候是找得到，什么时候确实找不到，你都要分析出这个条件，不然的话一定是失败的。这个是程序员自己要分析的，程序员自己必须分析出来。如果你分析不出来，那对不起，你这个肯定是做不了的。**

**第四，当一个函数执行完毕后，或者它遇到 `return` 后，就会返回。它要遵守一个原则：谁调用，就将结果返回给谁。** 同时，函数执行完毕或者返回时，**该函数本身也被系统销毁了**——就是这个空间相当于是被回收了。

## 迷宫回溯：0、1、2、3 四个数字，和一条会自己回头的路
> 对应块：BLK152 | 覆盖分集：P380-P381 | 块标题（分集名）：《378_尚硅谷_数据结构和算法-迷宫回溯问题(1》

我一边写代码，一边说思路，直接走代码。

大家听懂了还是非常有好处的，**不要小看这个案例，其实还是包含很多东西在里面的**。案例看起来好像不是特别复杂，但是它包含的东西还是很多的。

### 先把地图整出来：八行七列

首先第一步，我们先整一个地图出来——因为你没有地图就没办法，所以我们先用一个**二维数组**模拟这个迷宫。为什么是用二维呢？因为行和列刚好。

```go
package main

import (
	"fmt"
)

func main() {
	var myMap [8][7]int
}
```

地图按照刚才老师那个图来说，一共是 1 行、2 行……8 行，1 到 7 列——**8 行 7 列**。我们用 `int` 来表示，因为 `int` 可以用不同的数字来表示不同的情况。比如 0 表示什么、1 表示什么，我们先定一下规则。

#### 四个数字的规则：墙、未探、通路、死路

**第一，如果这个元素的值为 1，就代表一堵墙。** 墙就代表走不了——因为你不设置墙的话，迷宫到处通路，它不知道什么时候停下来，所以一定要设置一个墙。

**第二点，如果这个元素为 0，就代表这个路还没有探过**，它还是还没有走过的一条路，不知道能不能走通。

**第三点，如果这个元素将来变成了 2，就代表它是一个通路**，这条路是可以一直走下去的。最后我们这个地图会形成一个 2 指向的线，这条线就是一条通路。

**还有一点同学们要注意，就是第四点。** 如果将来这个元素……我们走的时候，假设我们这是一个圈，是一个包起来的，它进去过后发现走不了，它就退回来了。你想假设我们将来设计的这里假设是这样写的，有两个圈，然后我在这地方再搞一个框框——假设这个小球到这来了，它发现往这走走不了，它就回退回去了。那么这个小圆圈点，就是叫**死路**，就走过了，插了个旗子在这标了一下说走过，但是走不通。那还得有这样一个标识，这个标识我们设计为 3。

> **结论**：**如果元素的值为 3，就说这曾经走过，但是走不通。** 你得有这个思想在里面，所以这里还是需要动脑筋的，而且很有意思。

#### 先围一圈墙，再打印看看

有了二维数组过后，先把墙给我建起来——因为你首先得把墙初始化。我们现在的墙大家都很清楚地知道它是有规律的：**这一排、下面一排，还有最左边和最右边全是墙。**

所以我先初始化它。**怎么把它设成 1 呢？你不能一个一个设置，一个一个设置太累了。**

```go
// 先把地图的最上和最下设置为1
for i := 0; i < 7; i++ {
	myMap[0][i] = 1
	myMap[7][i] = 1
}
```

7 就代表最后那一排、最下面那一排，当然它也是 `i`，也等于 1。这样就把最上和最下设置好了。

输出地图这个也很简单，`for` 循环一下就可以了。关于二维数组的遍历，我们是学过的：

```go
// 输出地图
for i := 0; i < 8; i++ {
	for j := 0; j < 7; j++ {
		fmt.Print(myMap[i][j], " ")
	}
	fmt.Println()
}
```

打完过后我们就再换一下行。保存一下，来看看现在地图长什么样子——**我打一个点，打一个空格，这样看起来会清楚一点。**

```bash
cd ..
go run main.go
```

跑一下。可以看到，目前我们已经把最上边和最下边已经置为 1 了。我们接着把最左边和最右边也置为 1，因为这样子我们就可以知道它是墙了。

> **注意**：这边发生了一点点变化，相当于是对**行**——那么这边就得写 8 了，这边做一下变化，**列是不变的**：

```go
// 把最左和最右设置为1
for i := 0; i < 8; i++ {
	myMap[i][0] = 1
	myMap[i][6] = 1
}
```

第 0 列，然后这边是第 6 列，这样子置为 1。当然这里有几个点我是重新设置了一下，**会重复设置那四个点，但是无所谓，我也不去判断了**。

执行一把——现在大家可以看到，我已经把最上边、最下边、最左边和最右边全部设为 1 了。中间的 0 就代表是还没有探索过的。现在我们开始继续写，第一步咱们就算是搞定，地图算是做出来了。

### SetWay：三层判断，一次探测

现在我们已然有了地图，下一步我们就开始写函数来完成它。

首先，让小老鼠去找迷宫，**得先把地图给我，而且地图应该是大家都指向同一个地图**。在找的时候肯定要指向同一个地图，所以我写一个函数叫 `SetWay`，或者叫 `FindWay` 都可以，我就叫 `SetWay` 了，就是设置一个点，标线。

首先把地图给我，把地图先拿到 `myMap`。**这个时候地图应该是一个引用型的传进来，不要每次都给一个新的地图复制一份，那就完蛋了。** 还需要什么信息呢？得告诉我你是从哪个地方去找，所以需要给我两个坐标 `i int`、`j` 也来一个 `int`。

> **结论**：代码不多，但是理解起来有点难度。`myMap` 这个代表地图，**每次把地图给我，地图是同一个，始终是同一个，一定要保证始终是同一个地图、在同一个地图上找，因此我这里使用的是引用**。`i` 和 `j` 表示什么呢？表示当前是对哪一个点、哪一个格子进行测试。

现在代码就开始写了。记住我刚才的规则，上来第一句话——

#### 第一层：找到出口了吗——myMap[6][5] == 2

我们现在首先判断，因为我原先讲过，咱们在进行递归的时候**必须要分析出来什么时候算是找到了，或者说算是找不到**。

大家可以想象，因为我刚才讲过，2 代表一个通路。如果在整个查找的过程中，我们发现这个点——就是现在我用箭头标的这个点——等于 2 了，那你一定找到通路了。**肯定就找到通路了，该走了，别再找了。**

```go
func SetWay(myMap *[8][7]int, i int, j int) bool {
	// 规则：如果 myMap[6][5] == 2，说明找到出路了
	if myMap[6][5] == 2 {
		return true
	}
```

为什么是 6 和 5 呢？**这一行就是第七行，第七行从下标来说是 6；这边是第六列，第六列从下标来说是 5。**

为什么我这儿是 2 呢？因为我刚才已经把我的规则说清楚了。**如果我上来突然写个 2 大家可能不理解为什么，因为我定的规则是这样子的——如果你们定的规则不是说 2 表示通路、是 5 表示通路，那就是 5。** 找到了你可以打出一句话，但也可以不打，我就直接 `return`，说明找到了，别再玩了，返回一个真。

> **结论**：这一点是很重要的，**要分析出什么情况下就找到出路了。**

#### 第二层：这个点能探吗——非 0 就是墙

如果你这个 `myMap[6][5]` 不等于 2，说明还要继续找。问题又来了：在找的时候得分析出来它是不是一堵墙。

**因为我们的目标是探测这个点，对这个点进行探测——如果本身这个点它都等于一堵墙了，你还探个啥呀？**

这个地方看起来突然有点蒙的感觉，但是很正常，慢慢就好了：**你要找的时候首先判断能不能进行探测。如果前面都是一堵墙，你就没法探。** 所以先判断，如果这个 `i`、这个 `j` 等于 0，你才能探。

```go
	if myMap[i][j] != 0 {
		// 不等于 0，在初始情况下它只能等于 1，就是一堵墙
		return false
	}
```

如果不等于 0，打个比方，比如说我们上来过后就直接往上探测，做个最极端的案例——小球在这儿，然后直接往上一顶，发现这是一堵墙，那就别探了，不能出这堵墙。所以在这种情况下，**如果不等于 0，它就一定等于 1**。既然是墙的话，就直接告诉它不能走，直接 `return` 一个 `false`。

#### 第三层：先假设它通，再去反证

里面最麻烦了，因为里面涉及到一种关系——**你怎么探测的问题。**

**我的思路是这样子的：我先把它置为 2，我认为它可以通。** 注意这是假设——**假设这点是通路，但是实际上是不是通路我不知道，必须要通过探测才能知道。** 假设它是通的话，我就先将其置为 2。

```go
	// 先假设这个点是可以通的
	myMap[i][j] = 2
```

这里面有很多概念还有思维在里面。我假设它会通，但是实际上是不是通不知道，我要真正探测——**到底能不能通我要玩一把，通不通、是否真的能通需要探测。**

#### 四个方向的 else if，和最后的死路

那我开始怎么探测呢？因为大家想这个策略自然就出来了——既然要探测，在一个点你可以向上走、可以向左走、可以向下走，肯定涉及到策略。那你**必须得告诉我先往哪儿走啊**。有些同学可能说了："老师，我也不知道往哪儿走"，那就随便选一个。那就意味着针对这一个点就有好几种选项了，上下左右进行一个组合，顺序就好多了。可以先上再下，也可以先上再左，那就很多很多了。那么我就假设我的是这样子的。

现在开始探了：

```go
	if SetWay(myMap, i-1, j) {
		return true
	} else if SetWay(myMap, i+1, j) {
		return true
	} else if SetWay(myMap, i, j-1) {
		return true
	} else if SetWay(myMap, i, j+1) {
		return true
	}
```

**向上走**：`i` 减一下 1 就可以了，`j` 不变。如果这条路通了——因为从这个点往前走，注意往上走的时候它会不停地往下走——那我很高兴，说明成功了。到底能不能通你得告诉我，如果通了我就 `return` 一个 `true`。

> **结论**：这里有点不好理解，说实话。**至于这个 `true` 是哪一层返回的不知道，同学们，这点大家要理解。它到底是不是最终返回的？它是不停地往下递归，肯定要把这条路整个走通了才一个 `return true` 返回来的，不要理解成只有一层。** 你要理解到，看到这个代码要理解到它在不停地往下探了——也就是这条路一直是通的，它才不停地返回 `true`。

**向下走**：向下走的话这个地方就应该是加 1。如果向下走走通了，那我很高兴，我就 `return` 一个 `true`。**同学们注意，它向下走到下一层里面又是按照这个逻辑在走的，不是一直向下走。**

**向左**：`i` 不用变化，`j` 向左嘛，那肯定就是减 1。如果向左走能通，也很高兴。

**向右**：`i` 不变，`j` 加 1。

> **结论**：但是这里面只有一个方向能够成功，因为我用的是 `if else if`。**只要进到这里面成功了，它就不会再去探测，只有不成功才去向下走，向下走不成功才会向左走。大家看到这个逻辑，这个代码一点都不能错，错了就完蛋——所以为什么用的是 `else if`。**

当然还有一种可能性，就是上、下、左右都不通。如果都不通，**同学们要注意，这一点就很重要了**。

**如果都没有走通，说明这是一条死路。** 从当前这个点往上走走不通，说明上下左右都不通——是一条死路。你现在好像在一个点，被围起来了。

一旦是死路，同学们应该马上把这个重新置为 3。也就是说你这个假设是错的，**假设一旦是错的，我就把它置成一个 3，并且返回一个 `false`**：

```go
	// 上下左右都不通，说明是一条死路
	myMap[i][j] = 3
	return false
}
```

### 上右下左，这条策略救了两回

现在很简单，同学们，我只需要 `SetWay`。我把一个地图传给它，这个地图就是 `myMap`，但传的时候咱们需要传的是一个地址。我从哪个地方开始进行探测呢？显然是 (1, 1) 这个点——大家看到这个点是我们的出发点。

```go

	// 再输出地图看看
	for i := 0; i < 8; i++ {
		for j := 0; j < 7; j++ {
			fmt.Print(myMap[i][j], " ")
		}
		fmt.Println()
	}
```

这个是探测完毕的地图。**同学们看，我这个地方是有问题的——我们代码是有问题的。全部都置成 2 肯定是不对的。**

大家看到我们现在这个地图其实它走通了，但是它是这样子走的：**向上走，然后回到这儿，又向上走，像这样不停地走。这个策略不好。** 我们换一个策略——**下、右、上、左。**

#### 人为走一遍那张图


现在到这儿来了，小老鼠从这儿先置为 2，**往下走**，先置为 2。**发现这个 2 再往下走走不通——走不通它也不会马上把它置为 3，因为它还要回溯到这个点。** 回到这个点，它又向右，因为下走不通它就向右走，发现右可以走通，非常高兴。

接着它到这点它又向下走，它说怎么又是一堵墙？于是他又回到这点，接着往这边右走，走通了。走到这点它又向下走，走不通，它又回来了——它又回来，这怎么走？

> **结论**：所以说这个点我们应该清楚地看到它是这样子的。**整个这个 2 连起来的应该是这样子的走，就是这样子的一条线。** 好，是这条线。

我们把它打开跟老师分析的对比一下。**走代码，还是有问题——为什么这个地方还是有问题呢？代码真的是有问题。** 再调整一下。

那这样子，我们现在把这个策略也做相应的改变。因为我还是上下左右，我把它改成**下右上左**。来走，下；右，右是这个逻辑——**把这个改一下，就是 `i` 不动，`i` 不动的话是 `j + 1`，对**。这个就改成，这个是下了。然后是上——**上的话就是把 `i` 减掉一个 1，然后 `j` 不变**。然后最后一个就是左边——**左边就是 `i` 是不用变化的，把这个 `j` 减 1**。

同学们，现在这个策略我就变化了，我们再来跑一下。

**这次跟我们想的就完全一样了，跟我们分析的是完全一样的。**

> **结论**：那为什么刚才那是那样一个路径呢？**那样一个路径根本原因就是因为我们那个策略采用得不好。** 你按照那个策略分析出来，应该也是一样的。

## 从一道上机题说起：哈希表凭什么能让查询快起来
> 对应块：BLK153 | 覆盖分集：P382-P383 | 块标题（分集名）：《380_尚硅谷_数据结构和算法-哈希表(散列)1》

数据结构讲到哈希（也叫散列）这一块，我们先不谈定义，先看一个真实需求——它比任何定义都更能说明这个东西为什么存在。

### 一道不许用数据库的上机题

这是 Google 公司的一道经典上机题，考察的正是你知识结构里有没有哈希思想。

题面是这样的：有一个公司，当有新的员工来报到的时候，就要把这个员工的信息加入进来，信息包括 ID、性别、年龄、住址。演示的时候我们只添加 ID 和名字，其他的就不加了。**输入该员工的 ID，要求查询到该员工的所有信息。**

它有四个前提，缺一不可：

| 要求 | 为什么难 |
| --- | --- |
| 不允许使用数据库 | 数据库能查，但你凭什么保证快 |
| 要节省内存 | 不能拿大数组暴力铺 |
| 速度越快越好 | 目标是 O(1) 级别地定位 |
| 原题要求自己设计 | 现成的 Map 之类不让用，考的是原理 |

注意最后一条。如果这题允许你直接 `map[int]*Emp`，那它就不是题了。所以它真正在问的是：**你自己能不能设计一个东西，把数据摊开存放，然后还能按 ID 一步到位地找到它。**

这个题考察的点就是——你会不会哈希表的原理。怎么去存储我们的数据，然后让它的速度更快，这就是哈希的一个实际需求。

### 哈希表到底是个什么东西

散列表，有时候也叫哈希表（Hash Table），是根据关键码值而直接进行访问的数据结构。它通过关键码值映射到表中一个位置来访问记录，以加快查找的速度。

这个"映射函数"就叫散列函数。通过一个散列函数，能够把我们的数据分散到不同的数据存储的位置——有可能是链表，也有可能是数组，我们这里就用链表来做。

```text
             散列函数 HashFun
                    │
      ┌──────────────┼─────────┬──────────┬─────────┐
      ▼             ▼         ▼          ▼         ▼
  ┌───────┐    ┌───────┐ ┌───────┐ ┌───────┐ ┌───────┐
  │ 链表0 │    │ 链表1 │ │ 链表2 │ │ 链表3 │ │ ...   │
  └───────┘    └───────┘ └───────┘ └───────┘ └───────┘
   散开的          分到不同位置，每根链表内部有序
```

这样一存，你手里其实就相当于**自己做出了一个内存数据库**，而且能按你的需求定制。如果你不会这个，肯定只能依赖现成的数据结构，比如 Map、比如切片来用；但有些时候，它必须由你自己来做。

这个结构大体长什么样呢？每一格是一个链表。幻灯片上画的是 **16 根链表**，不同的码值被分散到不同的链表里。而且大家可以观察到，它往里面添加数据的时候，是**按照从小到大的顺序往里面添加的**：

- 0 号链表：第一个是 496，第二个是 896，从小到大
- 1 号链表：存了三个元素，1、337、353，也是从小到大

我们不用 16 根，16 根太多了，先用 7 根。

### 三层结构：哈希表、雇员链表、雇员

要写代码之前必须先把结构想清楚，不然听着会蒙圈，也写不下去。基于 HashTable 的雇员管理系统示意图是这样的：

```text
                         HashTable
                            │
                            ▼
        ┌───────────────────────────────────┐
        │  LinkArr [7]EmpLink   ← 链表数组   │
        └──┬──────────────┬─────────────┬───┘
           ▼              ▼             ▼
      ┌─────────┐   ┌─────────┐  ┌─────────┐
      │Emplink 0│   │Emplink 1│  │Emplink 2│  ... （共 7 个）
      │ Head ●  │   │ Head ●  │  │ Head ● │
      └────┬────┘   └────┬────┘  └────┬────┘
           ▼             ▼             ▼
        7→14→28       8→22→29       15→36→43
       (ID 从小到大)  (ID 从小到大)  (ID 从小到大)
```

三个部件，一层套一层：

**HashTable 的本质是一个链表数组。** 它是一个结构体，里面就一个元素：

```go
LinkArr [7]EmpLink
```

> **提示**：以前我们写的是整型数组、float 数组，这里是**链表数组**——数组的每个元素本身是一条链表。这是这个案例比较"高级"的地方。

**EmpLink 是雇员链表，也是一个结构体**，因为它要挂很多方法。它里面只有一个元素：

```go
Head *Emp
```

也就是一个头指针，实际就存了一个指针而已。

**Emp 是具体的雇员节点**，是个结构体：

```text
Id   int      // 雇员的 ID
Name string   // 雇员的名字
Next *Emp     // 指向下一个节点的指针 ← 特别重要
```

> **易错点**：这里的链表**不带表头**。第一个节点就直接存放雇员数据，不是先有一个空的头节点再挂数据。以前我都是带表头的，这次换一种写法。带表头也行，记住这是**你设计的选择**就行。

### 散列函数：取模定去向

那 ID 到底该放进哪一根链表呢？靠散列函数。我这里取模来决定：

```text
链表编号 = ID % 7
```

举例说明：

- ID = 7，`7 % 7 = 0`，所以进第 0 根链表
- 下一个也进第 0 根链表的是 14（`14 % 7 = 0`），再下一个可能是 28
- ID = 8，`8 % 7 = 1`，所以进第 1 根链表
- 同理 22、29 也进第 1 根链表

注意，**同一根链表里的 ID 不一定是连续的**。比如第 1 根链表里没有 29，而是直接放了个 36，这也是有可能的——因为 `36 % 7 = 1`。它不一定是连续的，但必须保证**从小到大**。

> **结论**：散列函数决定了"去哪儿"，而链表内部的有序性决定了"怎么找"。两个机制配合，才让哈希表既快又可控。

这个散列函数很粗糙，但**水平高的程序员可以写出完全不同的算法**——按 ID 散列、按名字散列、按 ID 加名字散列，都有可能。后面还可以做多级：模完之后下面又是一个节点，再从那儿伸出一根链表，那就是二级链表，模了之后再模。这我暂且不展开，有兴趣的同学可以自己去玩。

### 快在哪：一笔具体的账

先问个问题：**为什么这样就会变快？**

打个比方。现在我有一根链表，里面串了 1000 个雇员。

- **不散列**：单链表只能一个一个往后查。要查 ID 等于 998 的，那就得查 998 次才能找到。
- **散列**：我在存 998 的时候，先算 `998 % 7`，插入的那一刻就已经确定它在哪根链表里了。查的时候，把 998 拿过来，同样取一次模，直接跳到指定的那根链表里去找。

从"一根链表里线性找"变成"七根链表里锁定一根"，理论上就省了六七倍的时间。

```text
不散列： [1]→[2]→[3]→ ... →[996]→[997]→[998]
         要走 998 步

散列：   HashFun(998) = 998 % 7 = 4
         直接跳到第 4 根链表，在其中查
```

如果你原先花 7 秒，现在可能只花 1 秒就找到了。**如果你散列的是 100 个、1000 个呢？** 那显然就更舒服了。

它的价值就在这里：**用空间换时间。** 后面代码里那个 `[7]EmpLink`，你写完了想调整，把 `7` 一改，整个就变大了——写成 70、700、7000 都行，速度肯定杠杠的，因为你有效地利用了空间。

> **结论**：哈希表不是一个什么高深算法，它就是**把一条长链拆成若干条短链，然后用一个便宜的取模运算，把"在哪儿"这个问题一次性算出来**。

### 这套思路真正的用武之地

学东西一定要理解它的价值在什么地方，学起来才带劲儿。如果不明白它有啥用，第一你不想学，第二你都觉得没啥用。但真要用到的时候，你会突然发现：哦，原先讲过的这个东西给我留了点思路，我可以用这个方式去优化。

举一个真实的场景：**维护用户在线状态。**

传统做法是把用户的 ID 和状态直接存数据库，状态一变就去操作数据库。假设同时在线有 1000 万人，你按传统方法操作数据库会有什么后果呢？有一个人状态发生变化，或者有一个人要来读取状态，都只能打数据库——这个量是巨大的，对数据库的冲击很大。

换一个思路。注意我们的瓶颈在于"取用户状态"这个动作。而且——

> **定义**：用户状态不是一个特别重要的数据。它要么离线、在线、繁忙，第一次没更新上，第二次来了再更新上就行了，丢了就丢了，无所谓。它不像我们的存款余额那么重要。

所以像这种**经常操作、但又不特别重要、不是必须入库**的数据，就可以用哈希表来接。

怎么做呢？我做一个结构体，就叫 `user_status`，只设计两个特别简单的字段：

```go
type user_status struct {
	ID    int  // 用户的 ID
	State byte // 0 表示离线，1 表示在线，2 表示繁忙
}
```

把用户直接存进哈希表，散列给他串上 2000 根链表。效果是什么？

- **查询和修改状态**：理论上比以前快 2000 倍
- **并发**：读的话，并发问题都不用考虑。1 万个人读、1000 万个人读都无所谓，速度大大提升，我至少不用去数据库里玩
- **内存**：我们算一下其实并不大

假设 `int` 就算 64 位（最大值），一个用户 ID 占 8 个字节，`byte` 占 1 个字节，一共 9 个字节。存 1000 万个用户：

$$1000\text{万} \times 9\ \text{字节} = 9000\text{万字节} \approx \frac{90000000}{1024 \times 1024}\ \text{MB} \approx 85\ \text{MB}$$

85 兆。这点内存你还差乎？我是很珍惜内存，但那是以前的事情。再乘以 10，能存 1 亿个在线用户，**连 1 个 G 都不到**。

所以这种优化是很有价值的。而且不光是用户状态这个问题，**只要是类似的问题，我们都可以这么玩**。

顺便说一句：散列的键也不一定是 ID。比如我想用名字查，我可以先给名字算一个固定的值，转成一个整数——很多算法都能做到，用名字生成一个唯一的 32 位整数，再取模，连名字都可以查。

> **提示**：如果你不会自己写哈希，全靠 map，这两件事你都做不到。这就是**代码的优化**。

### 动手搭骨架：三个结构体

分析讲完了，现在开始动手。新建一个文件夹叫 `hashtable`，新建 `main.go`：

```go
package main

import (
	"fmt"
)
```

**写代码的顺序很重要**：谁用到了谁、谁又用到谁，关系决定先写谁。这个案例里，是 `HashTable` 用到 `EmpLink`，`EmpLink` 又用到 `Emp`，所以顺序是 `Emp` → `EmpLink` → `HashTable`。

```go
type Emp struct {
	Id   int
	Name string
	Next *Emp
}
```

只写两个字段就够演示了，一个是 ID，一个是名字，其他都不要。但必须有一个指向下一个节点的指针 `Next *Emp`。

```go
type EmpLink struct {
	Head *Emp
}
```

```go
type HashTable struct {
	LinkArr [7]EmpLink
}
```

> **提示**：`LinkArr [7]EmpLink` 这里没用指针，因为反正就 7 个，直接指向它就够了。你要写指针到时候也可以，给它挨个传过来。

方法待定，它们肯定会有方法，待会儿再往里面加。

### 哈希表的插入：先散列，再委派

先完成添加，给 HashTable 编写一个 Insert 方法：

```go
func (this *HashTable) Insert(emp *Emp) {
	// 使用散列函数，确定将该雇员添加到哪个链表
	linkNo := this.HashFun(emp.Id)
	// 使用对应的链表添加
	this.LinkArr[linkNo].Insert(emp)
}
```

逐行拆开看：

- **参数一定要带指针**。不用指针的话，创建过后它会进行值拷贝，更麻烦。
- **第一步必须先确定添加到哪一根链表**。如果你不分，那我这个 HashTable 就没有一点意义，我就是孤零零的一个单链表了，没有任何意义。
- **真正干活的不是 HashTable**。你散列下去之后，到底该用哪个链表去添加，得调出 HashTable 里面的 `EmpLink` 去添加，不能在这儿添加。
- HashTable 在这个地方只做了一件事：**散列，把它散开**。这里将来你还可以加逻辑，把它散到对应的地方去写。

对应的散列方法：

```go
func (this *HashTable) HashFun(id int) int {
	return id % 7 // 得到一个值，就是对应的链表的下标
}
```

我现在是按 ID 散列的，所以我把 ID 给我，我返回给你一个 int，告诉你这个雇员该扔到哪根链表去。

> **易错点**：这一行现在会报错，因为 `EmpLink.Insert` 还没写。没关系，我们马上写。

### 有序插入：双指针 pre 与 cur

现在给 EmpLink 加添加方法。**这里是最难的一个点**，其他都不难：

```go
func (this *EmpLink) Insert(emp *Emp) {
	cur := this.Head
	var pre *Emp = nil

	// 空链表的情况
	if cur == nil {
		this.Head = emp
		return
	}

	// 不是空链表，找位置
	for cur != nil {
		if cur.Id > emp.Id {
			break
		}
		pre = cur
		cur = cur.Next
	}

	// 插入
	pre.Next = emp
	emp.Next = cur
}
```

#### 为什么要 pre

因为要保证插入后**从小到大**，而这是一个**单链表**——单链表没法直接知道自己前面是谁，所以必须准备一个辅助指针 `pre`，**它始终保持在 `cur` 的前面**，两者同步往后走。

`pre` 的类型是 `*Emp`，默认值为 `nil`，是一个孤零零的辅助指针。加的时候需要它帮我在前面把东西插进去。

#### 空链表：最好处理的那种

如果 `cur == nil`，说明这个 head 本身就是 `nil`，说明它是一条空链表。那就简单了，直接让 `this.Head = emp`，完事，`return`。

用 `this.head` 判断也可以，用 `cur` 判断也一样——因为我一开始就是 `cur := this.Head`。

#### 非空链表：找位置

`for` 循环：`cur != nil` 就继续比较。

- 如果 `cur.Id > emp.Id`，说明我们应该插在 `cur` 的前面——也就是 `pre` 的后面、`cur` 的前面。位置找到了，`break` 出去。
- 否则（`cur.Id` 不大于它），就 `pre = cur`、`cur = cur.Next`，两个指针一起往下走，保持同步。

#### 退出之后：两种情况其实是同一种

循环退出来只有两种可能：

- **中途 `break`**：找到了一个比它大的节点，插到中间
- **一路走到 `cur == nil`**：没有任何一个比它大，说明它就是最大的，加到最后面

但**这两种情况可以用同一段代码处理**：

```go
pre.Next = emp
emp.Next = cur
```

如果 `cur == nil`（加到最后），`emp.Next = cur` 等于 `emp.Next = nil`，而 emp 本身后面本来就是空的，写不写无所谓。这两个逻辑可以合在一起，**不要写两份**。

### 三种临界情况，一个漏洞

大家写代码一定要考虑三种情况：**中间、最前面、最后面**。这三个是临界点，也是最容易出问题的地方。我们拿一条 `3 → 6 → 9` 的链表来验。

#### 插到中间：加一个 4

- `cur = this.Head`，`cur` 指向 3；`pre = nil`
- `cur != nil`，比较：`3 > 4`？不成立，于是 `pre = cur`（指向 3），`cur = cur.Next`（指向 6）
- 继续：`cur != nil`，比较：`6 > 4`？成立，`break`
- 退出后 `cur` 不是 nil，执行 `pre.Next = emp`、`emp.Next = cur`

结果：`3 → 4 → 6 → 9`。对的。

#### 加到最后：加一个 12

- 前进：`3 > 12`？不成立，`pre = 3`，`cur = 6`
- `6 > 12`？不成立，`pre = 6`，`cur = 9`
- `9 > 12`？不成立，`pre = 9`，`cur = cur.Next = nil`
- 再判断 `cur != nil`？不成立，循环结束
- 执行 `pre.Next = emp`（9 指向 12），`emp.Next = cur`（12 指向 nil）

结果：`3 → 6 → 9 → 12`。对的。而且注意，**这里的代码和上面那句是一模一样的**，不需要单独写。

#### 空链表

上来 `cur = this.Head` 是空、`pre` 也是空，两个都是"孤魂野鬼，还没地方走"。然后判断 `cur == nil` 成立，让 `this.Head = emp`，`return`。第一个节点就进来了，没问题。

#### 那个"特别不容易找"的漏洞

但是——如果观察力比较强，你可能会发现，我的代码**有一个漏洞**。

假设链表里已经加了 12，紧接着再加一个 ID **比 12 还小**的雇员，会怎么样？

**会把它踢掉。**

为什么？再来一个比较小的，它直接让 `head` 指向这个地方，就跑了——原来已经建好的那条链就断了，链表被破坏掉。

> **易错点**：这是因为循环判断的顺序。当前面的代码只处理了"空链表"和"插到中间/最后"，**没有处理"新来的比 head 还小"这一种插入位置**。`pre` 初始为 `nil`，当 `cur` 的 ID 直接大于 `emp.Id` 时，正确的做法应该是 `this.Head = emp; emp.Next = cur`，而不是 `pre.Next = emp`——此时 `pre` 是 `nil`，`pre.Next = emp` 会直接空指针 panic。
>
> 这个漏洞我先留到这儿，后面再去解决。大家先把"添加"这个最核心的点吃透。

添加就写完了。这是最核心的、也是最难的一个点，讲完了这个点，其实后边的代码可以这么说，**一马平川**——就这个添加麻烦，其他的都简单。

## 哈希表走起来：显示全部，按 ID 查找
> 对应块：BLK154 | 覆盖分集：P384-P385 | 块标题（分集名）：《382_尚硅谷_数据结构和算法-哈希表(散列)3》

上一讲我们把"添加"这个最难的功能写完了。现在先别急着往下走，回头看一眼那段代码——**它还有一点点可优化的地方**。

我们退出 `for` 循环的条件写的是 `cur.Id > emp.Id`。但其实**它等于的时候就可以退出了**，对吧？因为假设刚好有几个相同的，你也没必要非得把这个添加在最后。

如果这个地方想 ID 不唯一，那还要加点判断了。如果说 ID 允许多次重复，那这个代码还要做一些优化——这个地方大家想一想怎么去优化。

> **易错点**：`>` 还是 `>=`，取决于你的业务对"重复 ID"的态度。默认假设 ID 唯一，用 `>` 就够了；一旦允许重复，就得明确"新来的那个覆盖旧的，还是两个都留着"，这会影响后面查找函数的返回值语义。

好，添加就完事了，我们把它放进去。接着往下看：有了添加，现在做一个什么功能呢？我们做一个**显示**——把整个哈希表全部打印出来，看看到底有哪些在里面，看看对不对。

### ShowAll：一次把七根链表全打出来

编写方法，显示哈希表所有的雇员：

```go
func (this *HashTable) ShowAll() {
	// 所有的给我显示出来
	for i := 0; i < len(this.LinkArr); i++ {
		// 遍历链表数组，逐条委派给对应的链表
		this.LinkArr[i].ShowLink(i)
	}
}
```

这段逻辑非常简单，就是一个 `for` 循环。我也不分你是哪一个，我也不是查找，全部给我弄出来。`len(this.LinkArr)` 做大小统计——我不管你有多少根，全部显示出来，`i++`。

有两个细节要注意：

- `this.LinkArr[i].ShowLink()`——**不要调错了，调错到时候是出问题的**。数组下标 `i` 就是第几条链表
- 我这里直接把 `i` 作为参数传进去了。`ShowLink` 传不传参数都行，但传了更方便，因为链表自己并不知道自己是第几条

### ShowLink：显示当前链表的信息

真正干活的是链表自己：

```go
// 显示当前链表的信息
func (this *EmpLink) ShowLink(no int) {
	// 空链表给个提示
	if this.Head == nil {
		fmt.Printf("链表 %d 为空，没有雇员\n", no)
		return
	}

	// 遍历当前的链表，并显示数据
	cur := this.Head
	for cur != nil {
		fmt.Printf("链表 %d 雇员 id=%d 名字=%s -> ", no, cur.Id, cur.Name)
		cur = cur.Next
	}
	fmt.Println() // 换行处理
}
```

几个点值得停下来：

**为什么要传 `no`？** 因为我在 `EmpLink` 里**没有保存自己是第几条链表**，它就是一个纯粹的链表，压根不知道自己的编号。所以只能由调它的人传进来。谁知道编号是多少？显然是 HashTable 在调的时候知道。

**`Head` 一般不去动它。** 遍历的时候我另起一个 `cur` 指向 `this.Head`，把它当成一个"跑路的"辅助指针，只管往前走。

**结尾为什么要 `fmt.Println()`？** 为了好看。下一条链表还要接着打，不换行的话会全挤在一行上。

> **结论**：HashTable 的 `ShowAll` 是一个"数组遍历 + 委派"，逻辑薄得几乎可以忽略；真正有内容的是 `ShowLink` 的空链表判断和游标遍历。这就是分层的舒服之处——上层只管"到哪儿去"，下层才管"怎么办"。

### 按 ID 查找：先定链表，再在里面找

现在来完成查找雇员的功能。用户输入一个 ID，我们就把对应雇员的信息显示出来。

在菜单的 `find` 分支里，先提示"请输入要查找的 id 号"，用 `fmt.Scanln` 接收，然后**把这个 id 传给 HashTable 里面的一个方法**。

#### HashTable.FindById：先散列，再委派

```go
func (this *HashTable) FindById(id int) *Emp {
	// 使用散列函数确定该雇员应该在哪个链表
	linkNo := this.HashFun(id)
	// 调用对应链表的查找方法
	emp := this.LinkArr[linkNo].FindById(id)
	return emp
}
```

要点仍然是老规矩：**先把这个是哪一个链表确定下来。** 因为你的链表很多嘛，先用散列函数算出到底应该到哪个链表去找。**如果这个链表找不到，那就肯定没有了**，别的链表肯定没有——你看，哈希在这地方就体现出它的应用优势了。

返回值方面注意：我们返回一个 **Emp 的指针**。因为整个过程我们都按照引用的方式来处理，这样比较好。

然后我们调用这根链表的 `FindById`，把 id 传进去。真正来找这个雇员的人，还是链表来完成。最后直接 `return` 就 OK 了。

#### EmpLink.FindById：遍历加两个终止条件

```go
// 根据 id 查找对应的雇员
func (this *EmpLink) FindById(id int) *Emp {
	cur := this.Head
	for cur != nil {
		if cur != nil && cur.Id == id {
			return cur
		} else if cur == nil {
			break
		}
		cur = cur.Next
	}
	return nil
}
```

怎么找呢？因为你已经到达了这根链表了，所以用我们的遍历方式就可以搞定——**就是比较而已**。

老规矩做一个辅助指针。不过这时候**不需要 `pre` 了**，因为找到了就找到了，找不到就找不到。所以直接 `cur := this.Head`，开始 `for` 循环。

先做判断，当前节点不等于 nil，我们就继续找；把它写在一起就是"不等于 nil 并且满足一个条件"——当前这个节点的 id 等于你传进来的 id，那就说明找到了。我们假定 ID 是唯一的，在这种条件下就认为找到了，直接 `return` 就完事了。

如果一直找不到呢？那就一直 `cur = cur.Next` 往下探一步。整个 `for` 循环结束都没有一个返回值，那就肯定没找到，直接 `return nil`。

> **易错点**：这里有个坑，**空指针判断不能省**。假设它是一个空链表，`cur` 本身就是空指针。如果你只写 `if cur.Id == id` 就往下走，第一次上来它等于空，你还要去取 `cur.Id`——这本身就是错误，会直接空指针 panic。所以必须再补一个 `cur == nil` 的 `break` 分支。加上了它，我们才能保证代码没有空指针异常。

> **提示**：`else if` 可不可以加？可以。如果这个条件没有成立，假设当前又等于 nil 了，那就在这里 `break` 退出。否则——条件不满足、又不是 nil——就往下再探一步。逻辑写成什么样都可以，**关键是让循环有两个明确的终止出口**：找到（return）、走到头（break）。

#### ShowMe：雇员自己报出自己的信息

拿到指针以后调用方要判断。它等于 nil，说明确实没有这个人，就输出一句"id 等于 X 的雇员不存在"，然后换一行。

如果不等于 nil，说明找到了，我们把信息打出来。但是——因为他本身就是一个雇员，因此在打的时候**干脆我们写一个方法**。而且还得告诉他，**你是在哪一个链表里面**。

所以我们专门写一个方法，直接绑定在 `Emp` 结构体上，让雇员自己报出自己的信息：

```go
func (this *Emp) ShowMe() {
	fmt.Printf("链表 %d 找到该雇员 id=%d 名字=%s\n", this.Id%7, this.Id, this.Name)
}
```

格式跟前面保持一致：链表多少多少，有一个雇员，id 是多少，名字是多少。

它到底是哪一根链表呢？这里就简单一点，**直接用它的 id 模下 7 就可以了**。

如果你想把代码做得稍微复杂一点，也完全可以去调用哈希函数——因为 HashTable 里面有个 `HashFun`，你可以想办法把那个方法返回来。但如果你的散列方法本身比较复杂，就没法简单取模了，那你就得真的想办法去调它。这也说明**散列函数一旦变复杂，这个地方就要跟着变**。

> **提示**：我这里因为已经有一个全局变量 `hashtable` 了，其实也是可以直接用的。但为了简单，就直接取模。

调用方就很简单了：

```go
var employee *Emp
employee = hashtable.FindById(id)
if employee == nil {
	fmt.Printf("id 为 %d 的雇员不存在\n", id)
} else {
	employee.ShowMe()
}
```

## 前序、中序、后序，以及一套让你少打字的工具
> 对应块：BLK155 | 覆盖分集：P386-P388 | 块标题（分集名）：《384_尚硅谷_数据结构和算法-二叉树三种遍历方》

前面我们把链表、哈希表这些"横着长"的结构讲完了，接下来换一个方向：**竖着长的结构**——二叉树。这一块我们重点讲前序、中序、后序这三种遍历。

### 什么是二叉树

我们前面讲的一个节点，只有一个指向下一个节点的指针。但是有些情况下，我们这一个节点可能会有两个指针，甚至有些地方是有三个都有可能。

如果说我们**每一个节点都有一个左指针和一个右指针**，它的下一个节点又有一个左指针和右指针，那么这个我们就把它称作二叉树。

关系可以这样理解：第一层、第二层、第三层、第四层。最上面这个 A，我们把它叫作**根节点**——遍历的时候要从根节点开始。B 下面有两个节点 D 和 E，D 的父节点是 B，B 的父节点是 A；C 是 F 和 G 的父节点，同时是 A 的子节点。父子关系就很明显了。

如果 A、E、F、G 没有子节点，我们就称为**叶节点**。

我们根据这个来构建一棵简单的二叉树，然后拿它来遍历一下。**有时候面试官会问你什么叫前序遍历、什么叫后序遍历、什么叫中序遍历**，他会大概问一下它的含义是什么，所以我们来走一个小案例。

现在这棵二叉树长这样：有一个 Hero 节点，它左边指向一个英雄，这个下面就没有子节点了——我构建得比较简单；它的右节点指向另外一个节点，这个节点的右节点又还有一个林冲：

```text
                  宋江 (No=1)
                 /          \
            吴用 (No=2)     卢俊义 (No=3)
                                  \
                                  林冲 (No=4)
```

要求分别用前序、中序、后序对这棵二叉树进行遍历。一般来说这种是比较简单的，它主要考察点就是**什么是前序、中序、后序**。

### 三种遍历：只差"根节点在第几位"

三种遍历的概念其实就这么一点差别，全在**根节点被输出的位置**上。

| 遍历方式 | 顺序 | 专业词 |
| --- | --- | --- |
| 前序 | 根 → 左子树 → 右子树 | PreOrder |
| 中序 | 左子树 → 根 → 右子树 | Infix |
| 后序 | 左子树 → 右子树 → 根 | PostOrder |

`Order` 在这里面就是遍历的意思。你要给我一个根节点，我就可以搞定它。

我们先构建这棵树。写一个案例，就叫 `binary_tree`，`main.go`：

```go
package main

import (
	"fmt"
)
```

既然我们要去构建一个英雄节点，先写个结构体：

```go
type Hero struct {
	No    int
	Name  string
	Left  *Hero
	Right *Hero
}
```

它有编号，编号用 `int`；有一个名字，名字用 `string` 来表示；然后是指向左边节点的指针和指向右边节点的指针——`Left *Hero`、`Right *Hero`，一左一右。

```go
func main() {
	root := &Hero{No: 1, Name: "宋江"}
	left1 := &Hero{No: 2, Name: "吴用"}
	right1 := &Hero{No: 3, Name: "卢俊义"}
	right2 := &Hero{No: 4, Name: "林冲"}

	root.Left = left1
	root.Right = right1
	right1.Right = right2

	PreOrder(root)
}
```

建节点的时候，它们左右两边的指针默认为空，所以它们之间还没有形成二叉树；然后我们再把关系指过去。`root.Left` 指向 `left1`，`root.Right` 指向 `right1`。林冲是卢俊义右面这个子节点，所以是 `right1.Right = right2`。到这一步，按照要求的二叉树就已经写成了。

### 前序遍历：根、左、右

前序遍历的代码这么简单：

```go
func PreOrder(node *Hero) {
	if node != nil {
		fmt.Printf("no=%d name=%s\n", node.No, node.Name)
		PreOrder(node.Left)
		PreOrder(node.Right)
	}
}
```

就一个判断：只要这个节点不等于 `nil`，我们就输出。编号就是 `node` 里面的 `No`，名字就是 `node` 里面的 `Name`。输完当前节点，紧接着输出它的左子树——把 `PreOrder` 往这一写，再把这个 `node.Left` 给它就可以了；然后再往它的右面去遍历。

注意它在进去的时候是一个**递归的过程**。

那它的输出顺序应该是什么样子呢？我们先在脑子里走一遍：先输出宋江，再输出吴用。吴用再往下面走的时候，吴用下面的左子树没有了，就会**回溯**到上面，又把卢俊义输出出来。卢俊义本身想往左边走，但左边是空的，它又输出林冲。也就是说，如果你下面还有子树，它仍然遵循先打中间再打两边的规则。

所以顺序是：**宋江、吴用、卢俊义、林冲**。

#### 那个特别容易犯的错

我们第一次跑代码就报错了。问题在哪呢？是树没建对吗？不是——**问题在代码这里，我们这个地方没有取子树直接打的**。你往左边打，那应该取一个 `node.Left`；这边往右边走还要 `node.Right` 一下，不然的话确实要死在这儿。

改动之后再跑，效果就跟我们想的一模一样了。因为刚才你没有去访问它左边或者右边的子树，它当然就死在这儿了。

> **易错点**：递归函数里**必须把自己正在处理的那个字段传下去**。写成 `PreOrder(node)` 就成了无限递归，栈会一直涨到爆。这一条记住就够了。

### 加两个节点，再验证一次

光看一棵树不够明显，我再出一题让大家思考。现在假如我在这儿又伸出去两个节点——一个叫 10，一个叫 12：

```text
                  宋江 (No=1)
                 /          \
            吴用 (No=2)     卢俊义 (No=3)
            /       \             \
   node10 (No=10)  node12 (No=12)  林冲 (No=4)
```

如果二叉树是这样，那么它输出的顺序应该是什么样子的呢？

前序遍历：先输出宋江，然后往下走左边的。左边这个地方输出什么呢？吴用。吴用接着往 10 号走，输出 10。输出这个 10 过后，再输出 12，然后再输出卢俊义——**宋江、吴用、10、12、卢俊义、林冲**。

大家要把这个选对，因为这种经常做这种选择题。我快速地验证一下：复制一份，在吴用下面挂两个节点，`node10` 名字叫汤姆，`node12` 名字叫杰克，把它们挂在吴用的左右两边。

运行结果跟我们分析的是一样的：先输出宋江，对的；往左边遍历输出吴用，再往左边遍历输出 10；输出 10 过后下面没有了，它就回溯，回到这个位置接着往吴用的右边这条树打，于是打出 12，这也是正确的；然后宋江的左边这个子树全部打完了，又开始往它的右边打，先打出卢俊义；卢俊义的左边没有，所以就没法打了，然后往卢俊义的右边打出林冲。

**这个顺序跟我们想的是一样的。** 这个呢我们就叫作前序遍历——别人问到你前序遍历是什么意思，你要清楚地告诉他。

### 中序遍历：把根挪到中间

中序遍历是先输出 `root` 的左子树，然后再输出 `root` 节点，最后输出它的右子树。专业的名词叫 **infix**。

怎么做？还是这样判断，**它唯一的变换就在这一点：把它放在了中间**。

我们先不打，自己先推一下。同样把这个根节点传进去：如果是中序遍历，它应该怎么走呢？它**先把这边输出来，所以说宋江先不会打**。它先到这边来，这个呢，对不对？也不对，因为这边还没到底头呢，于是它会打这边，所以它会打出这个 **10**。10 打出来过后，打出这个**吴用**。再往这边跑，打出什么呢？**12**。然后再打出 **1**。

所以这一段是：**10、2、12、1**。右子树那边是同一个道理：进去先打林冲（4），再打卢俊义（3）。合起来就是 `10、2、12、1、4、3`。

跑一下验证——它打出的是 10、2、12、1，跟我们分析的是对的。**中序遍历总是相当于一直往下跑，跑到最左边把它打出来，然后再这样子做。**

### 后序遍历：把根挪到最后

后序遍历概念是一样的：最后打出这个根节点，专业词 **postOrder**。它也是做一个判断，然后把这个地方往后面再挪一下。

顺序我们推一推。后序是**先打左边，再打右边，最后打中间**。

我第一次推的时候有问题，重新确认一遍：

- 宋江这个地方因为是最后才打的，所以它应该最后出来——因为是先把左边全部打完再打右边
- 往下走，**10 是先打的**，没问题，这是第一个
- 打完 10 打的是 **12**，这个分析也是正确的
- 这边做完了过后，再打**吴用（2）**
- 3 打完了过后，宋江还不能打，因为他要把宋江左边的也全部做完才能打。所以往下面走卢俊义，卢俊义还不能打，因为它左边有子节点，所以这个时候应该打出**林冲（4）**，这是第四个
- 打出 4 过后，相当于卢俊义的左右子树全部都打完了，所以说**卢俊义（3）**是第五个
- 第五个打完了过后，相当于宋江的左右子树全部打完了，最后才打出**宋江（1）**，这是第六个

所以完整顺序是：**10、12、2、4、3、1**。

跑一下确认，代码这么写：

```go
func PostOrder(node *Hero) {
	if node != nil {
		PostOrder(node.Left)
		PostOrder(node.Right)
		fmt.Printf("no=%d name=%s\n", node.No, node.Name)
	}
}
```

确实是这样子的。这个就是我们所说的前序、中序、后序遍历。

> **结论**：在面试的时候，如果面试官问到前序、中序、后序遍历它是一个怎么样的顺序，大家能够把这个题给答上来——有可能是个面试题，也可能是一个选择题。**三种遍历的代码几乎一模一样，唯一的差别就是 `fmt.Printf` 那一行放在哪、递归按什么顺序调用。**

> **注意**：安装 VS Code 插件的时候，**要先安装一个 Git，并且配好**。要是没有这个东西，它也是不能成功的，因为**所有的插件都是在这个 Git 上面去安装**。所以你的第一步工作应该是先把 Git 安装好——一步步装下去，只要你看到了类似于 `git version` 的提示，那就说明这个成功了。装好以后还要配一个 Git 的环境变量，配好了过后才可以继续往下走。

VS Code 的 Go 插件有很多，常见的有这么多个。每一个是什么含义倒也不是很关键，**就是把跟 Go 相关的插件都装上就行了**。

#### 装不成功怎么办

现实是：它也会提示有些安装失败。我这个网络环境里能成功安装的没几个，其他都成功不了。

不着急，我有解决办法。

如果你走到这个地方，你会发现到 `src` 目录下面去看，**其实下载几乎都能成功，但是就是没有安装成功**。它经常有这样一个情况：有时候下载成功了，但安装没成功。

那怎么办呢？看我的幻灯片，注意听这句话——

**第一步，切换到 Go 的 src 目录下面。**

你会看到在你的 goproject 下面 `src` 确实存在一个 `github.com`，它现在好多插件其实都已经下载下来了。比如它刚才说 `go-outline` 失败了，但实际上下下来了一些，`go-symbols`、`gorename` 也在。

**第二步，切到 `golang` 里面去，执行一个 `git clone`。**

克隆过后，它会把没有成功的包重新再给你进行下载或者处理。做完以后，会在 `github.com` 的 `golang` 里面多一个 `tools` 目录。

**第三步，把 `tools` 目录下面所有文件拷贝到 `golang.org/x/tools` 目录下面去。**

> **易错点**：我在这儿也踩了坑。执行 `git clone` 的时候它报"不能切换克隆，无效的一个参数"，我怀疑是多粘了一个 `tools`，去掉以后还是不行——**它连多出来的那一个空格都不认**。最后这个克隆要等很久，进度条才 1%、2%，我就不等待了。后面第 8 步、第 9 步你自己照着做就行。

如果成功以后，按步骤做完了，你最后会得到一个文件夹。这个文件夹里边有这些东西：`src` 里面的 `github.com` 就是一个非常完整的插件包，`tools` 里面也是下载完了的完整 tools 包。你要下载一会儿。

整个做完以后，你再打开的时候情况就**完全不一样了**。

> **提示**：如果实在装不上——因为你的网络关系实在装不上——我可以把这个包给你们，你们把你们的项目重新定位到这个上面就可以了。把整个工作做完的包改个名字叫 `project`，然后打开就行。中间有个小坑：有时候这个文件夹正在被访问，因为你有一个 DOS 窗口打开过，它会锁这个文件，所以要先退出来把它改名。

#### 装好之后能干什么

打开这个工作目录，我们写一段代码，看看它能完成哪些事情。比如说现在我要完成一个任务——**对切片排序**。

首先去定义一个切片，比如我有一个 `mySlice`，是一个 `int` 切片，好，有这么多个元素，写完。然后打个 `sort.`——**大家看到，很爽，就全部出来了**。我们知道有一个方法叫 `Ints`，我一回车它自动就把这个包给引进去了。

再打个 `fmt.`，**它又自动地把这个包给你引进去了**。当然这肯定开发速度会稍微快一点。有时候它反应会有点迟钝，多敲一下就好了。

还有两个好处：

**保存时自动格式化。** 假设你的代码写得有点怪、写错了，你一保存它自动给你进行格式化，比如 `Ctrl+S`。以前都是设置过好多次的。

**可以往里面追源代码。** 比如原先我们这个是追不进去的，现在我一点右键，这里边有一个叫"转到定义"，一点——源代码就可以直接追进去了。比如说这里面用到的 `sort`，用的什么方法都可以一步一步追进去，包括我们以前学的快速排序它是怎么做的，都可以往里面追。

**跨文件定位。** 假设你项目里面文件很多，`test.go` 用到别的文件的一个函数，也可以定位。比如我有一个叫 `sayHello` 的函数，假设我的代码离它很远，我一写它就已经出来了，然后我要定位这个函数也很简单，一点，直接按个快捷键，它就可以定位到这儿。**虽然它离得十万八千里，它也能够看到；如果你不在同一个文件，它也能定位。**

好，你回去就按照幻灯片的要求把这个插件装起来。因为到后面讲 Go Web 的时候，我在讲项目，那个项目相对来说肯定要比我们前面讲的聊天程序要稍微大一点。你这代码要是全用那个没有工具的，看起来也很糟糕。

### 快捷键：常用的就那么几个

VS Code 装了这个插件过后，它的快捷键就可以马上用起来了。

先打开"首选项"里有一个叫"键盘快捷方式"，一点——你们可以看到快捷键特别的多，而且可以自定义，太多了。

比如我想看一下删除怎么弄，**直接输入 `delete`**，你就会看到一个叫"删除行"的命令，默认是 `Ctrl + Shift + D`。这是用户的设置，你也可以改——你说你不喜欢它，改成 `Ctrl + Shift + L` 也行，加了一回车，`Ctrl + Shift + L` 就变成删除当前行了。我们试一下，`Ctrl + Shift + L` 一删，没了。

还有什么呢？**向上向下复制**（这个我以前用过的就不再多说了）、**补全代码会自动给你补全**、**添加和取消注释**——整体注释，再按一下就取消。还有很多其他的快捷键。

**格式化**默认是 `Shift + Alt + F`，但现在你都用不着这样做了，因为**保存会自动给你格式化**。

还有很多其他的快捷键，我给到大家一个文档。里面有一个文件叫"VS Code 快捷键大全"，它写得比较详细，基础编辑功能、导航功能、多光标这些，很多。**用到哪个去查一下就行了，也没有必要专门去背**，其实常用的就那么几个。

因为**导包它自动给你导了**，跟 Java 不一样——Java 有很多很多这种方式，它直接是一用马上给你弄进去，一保存格式化了。所以大体上大家需要什么就去用什么就可以了。

### 本讲提到的题目

我出一道选择题，请大家思考：**下面这棵二叉树，用前序、中序、后序三种方式遍历，输出顺序分别是什么？**

```text
                  宋江 (No=1)
                 /          \
            吴用 (No=2)     卢俊义 (No=3)
            /       \             \
   node10 (No=10)  node12 (No=12)  林冲 (No=4)
```

**答案：**

| 遍历 | 顺序 | 编号序列 |
| --- | --- | --- |
| 前序（根左右） | 宋江、吴用、汤姆(10)、杰克(12)、卢俊义、林冲 | 1、2、10、12、3、4 |
| 中序（左根右） | 汤姆(10)、吴用、杰克(12)、宋江、林冲、卢俊义 | 10、2、12、1、4、3 |
| 后序（左右根） | 汤姆(10)、杰克(12)、吴用、林冲、卢俊义、宋江 | 10、12、2、4、3、1 |

**解析依据**在正文里都能找到：前序先打宋江再整棵左子树，10 下面没有了就回溯到吴用右边打 12；中序宋江先不打，跑到最左边先打 10；后序根节点最后打，所以林冲先于卢俊义、卢俊义先于宋江。

**另一个坑：** 写遍历函数的时候，递归调用**一定要传 `node.Left` 和 `node.Right`**，不能只传 `node` 自己，否则会无限递归直到栈溢出。
