## 数组是被逼出来的：养鸡场的六只鸡，和内存里那块连续的空间
> 对应块：BLK51 | 覆盖分集：P143-P145 | 块标题（分集名）：《142_尚硅谷_数组的使用价值》

各位同学，那我们现在开始给大家讲一下 Go 语言核心编程里面的数组和切片。

大家都知道，我们在进行编程的时候，数组这个概念可能有些同学是听过的——就是存放一组数据嘛，也是一种数据类型，它是用来存放多个数据的这么一种数据类型。**但是切片这个概念很多同学没有听过，因为切片是 Go 语言里面特有的一种数据类型**，所以说大家注意一下切片。

讲数组之前，还是老规矩，先说一下为什么我们需要去讲这个数组，由浅入深地引导一下。我们来看一个问题。

### 六个变量能不能解决养鸡场的问题

说有一个养鸡场有 6 只鸡，体重分别为 3 公斤、5 公斤、1 公斤、3.4 公斤、2 公斤，还有一个 50 公斤的。50 公斤的可能是超级大鸡，那就不用管了，可能是这个鸡特别能吃、长得挺胖的。

那么现在的问题是什么呢？**请问 6 只鸡的总体重是多少？平均体重是多少？请编写一个程序。**

这个问题其实难吗？如果说我们用传统的方法来解决，应该说同学们都能做出来。那这个很简单嘛，就是我定义 6 个变量，分别表示 6 只鸡的体重，然后把它们总体重加起来，求平均体重除以一个 6，不就完了吗？

**所以这个问题其实并不难。但是我们用传统方法来解决，会发现会出现一些问题**，肯定有些不爽的地方、对不对？用起来不方便的地方，这时我们就会引出数组这个概念。

不管怎么样，我们先用传统的方法来写一写，看看到底有什么问题。老规矩，新建一个文件夹叫 `chapter07`，在下面新建一个文件夹 `arraydemo01`，在里面新建文件 `main.go`。

**思路分析**：定义 6 个变量分别表示 6 只鸡的体重，然后求出它们的和，然后再求出平均值。非常简单的思路。

```go
package main

import "fmt"

func main() {
	// 用类型推导定义六个变量，分别表示六只鸡的体重
	hen1 := 3
	hen2 := 5
	hen3 := 1
	hen4 := 3.4
	hen5 := 2
	hen6 := 50

	// 求总体重
	totalWeight := hen1 + hen2 + hen3 + hen4 + hen5 + hen6

	// 求平均体重
	avgWeight := totalWeight / 6

	fmt.Printf("总体重=%v 平均体重=%v", totalWeight, avgWeight)
}
```

一保存就出现语法错误了，为什么呀？**他说 `hen4` 不匹配 int 和 float64。** 因为你这里用的是类型推导，`hen1 := 3` 它认为是什么类型？它认为是整型 int；而你这个 `hen4 := 3.4` 又是 float64 的类型，所以说这样子是不行的。怎么办？非常简单，给它这样处理一下就可以了，让它认为都是 `float64`，保存成功。好，这块不会报错了。

跑起来，我们打印出来总体重是 **64.4**，平均体重是这么多。但是大家看到，这个平均体重精确的小数点太多了，不太喜欢。**我们来把它精确到小数点两位就可以了**——你只需要写 `%.2f` 就行了，这样就代表小数点精确到两位。再来跑一下，可以看到此时就保留到 **10.73** 了。

但是问题来了：有些同学会说："老师，你这个地方是输出的时候保留到小数点两位，但是这个值我想把它传给另外一个数的话，这个地方怎么处理呢？"可以这样处理。我们可以把 `Sprintf` 用起来——它是不是用来做格式化的？这样子我们就可以让它直接返回一个值：

```go
avgWeight := fmt.Sprintf("%.2f", totalWeight / 6)
```

这句话的意思就是：**我把这个结果四舍五入保留到小数点两位，然后把格式化之后的值返回来。** 这样子 `avgWeight` 本身就是这个值了，直接输出它的原值就可以了，以后你也可以直接用这个 `avgWeight` 来做其他的操作，是不是？

好，我们用传统的方法就已然完成了。**同学们想，用传统的方法把求鸡的总体重和平均体重完成了过后，大家有什么感想没有？**

别的我就不说了——你看，我们现在是统计 6 只鸡的体重，你定义了 6 个变量，没问题。**但是我要统计 600 只鸡呢？你怎么玩？** 你难道要跑去定义 600 个变量吗？显然，这个时候我们就需要一种新的数据类型来解决这个问题。

你想，Go 语言的设计专家那也不是白吃两碗饭的，人家也是专家级别的，不可能不去解决这样的问题。你说白了，600 只鸡是一个一个地记录好，还是说用一种新的数据把它统一地管理起来好呢？

**有一种数据类型就叫数组。** 数组听这个名字就知道：一组数据，数就是数据，组就是一组嘛，就是把这个数放在一组里面去统一管理。

那传统方法的问题，我们做个说明：

> **结论**：**使用传统的方法不利于数据的管理和维护。** 你想一想，每一只鸡的体重你都用一个变量，肯定不好管理和维护；**也不利于我们程序的编写**，传统方法不够灵活，没有办法处理一些复杂业务。因此，我们就引出了需要学习的一个新的数据类型，就叫数组。**数组就应运而生了，这就是数组的来由。**

### 数组是什么

**数组是可以存放多个同一数据类型的这么一种数据类型。** 也就是说，数组可以存放多个同一数据类型的数据。数组也是一种数据类型。

> **结论**：**在 Go 中数组是值类型。记住了，数组是值类型。** 有很多编程语言里面数组其实是引用类型，但是在 Go 里，注意听这句话——**Go 里边数组是值类型**。因此它的使用是要符合值类型以及值传递的这些特征、特点的，这点大家一定要有清楚认识。

那快速入门最好的方法是什么呢？就是**我们用数组来解决上面养鸡场养鸡的问题**，这样大家马上就能够快速地理解数组在程序里面是怎么使用的。

### 用数组把养鸡场的问题重做一遍

我们干脆就直接在下面写，用数组的方式来解决这个问题。

**第一步，先定义一个数组。** 你不是有六只鸡吗？我定义一个数组——6 个、`float64` 类型：

```go
// 第一步：定义一个数组，可以存放 6 个 float64 型的数据
var hens [6]float64
```

这个 `hens` 就是一个数组，它的数据类型是 float64，里面可以存六个数据。

**第二步，初始化**——给数组的每个元素赋值：

```go
// 第二步：给数组的每个元素赋值，注意下标从 0 开始
hens[0] = 3
hens[1] = 5
hens[2] = 1
hens[3] = 3.4
hens[4] = 2
hens[5] = 50
```

大家看到，**它的下标是从 0 开始计算的**。再说一遍啊，**它的下标是从 0 开始计算的**——上面这个 `hens[0]` 就相当于 hens 数组的第一个元素，它的下标为 0，依此类推，最后一个是 `hens[5]`。

> **易错点**：**最大这一个下标是 5，而没有 6。** 本身有六个数据，你非要去访问 6，那就相当于是说访问第七个数据了，那就越界了。

**第三步，求总体重。** 总体重咱们就不要一个一个去加了，因为**数组可以遍历**，它就很方便嘛：

```go
// 第三步：遍历数组，求总体重
totalWeight2 := 0.0 // 定义一个总体重
for i := 0; i < len(hens); i++ {
	totalWeight2 += hens[i]
}
```

为什么 `totalWeight2` 我定一个 `0.0` 大家知道吗？因为你的这个体重里面本身都是小数，所以我定义一个 `0.0`，**让它的数据类型变成 float64，这样数据类型就统一了**。

> **易错点**：`len` 是一个内置函数，前面我们已经讲过了。

**第四步，求平均体重**：

```go
// 第四步：求平均体重
avgWeight2 := totalWeight2 / float64(len(hens))

fmt.Printf("总体重=%v 平均体重=%v", totalWeight2, avgWeight2)
```

我们看这两次求得体重是不是一样的。同学们看，**两次的方式哪一个更方便？** 是不是这个更方便？

为什么？你看，**如果我增加了一只鸡的体重，这个地方的代码是不用变的**，这个地方也不用变。为什么？大家看我这个 6 还可以写得更灵活：

```go
avgWeight2 := totalWeight2 / float64(len(hens))
```

**用总体重去除以鸡的个数就行了。是不是很灵活？**

#### 一个小插曲：`len(hens)` 为什么还要强转成 float64

保存一下，我们看这里有问题出来了。**哦，大家看怎么会有这个冒号？这个不行啊**，因为你这儿是不是已经有了？你这儿打个冒号不就是类型推导吗？这是不对的，大家不要犯这个错误。

再保存，还有错误。看这个地方属于什么错：`totalWeight` 是一个什么类型？是一个 `float64`；而你写的这个 `len` 是什么类型？是个 `int` 型。那显然不行了。因为我们知道，在 Go 里面它运算的时候，**它的数据类型要保持一致**。

那这个地方好办，我把它转一下，`float64`：

```go
avgWeight2 := totalWeight2 / float64(len(hens))
```

保存一下，没错了。也就是说它转了过后呢，它就变成 6 就变成 6.0 了嘛，这个不影响结果。

> **注意**：**为什么要转啊？** 因为你这个是 float64，而 `len(hens)` 它这里边求出来是个整数，求出来是个整数的话类型不一样，float64 转一下就可以了。
>
> 那有些同学说："老师，你上面为什么写个 6 就可以了？"——好，如果你现在再问这个问题的话，只能证明一件事情：**前面没有认真听讲。**
>
> 我原先就讲过，如果你这儿是一个具体的数，那没问题；但是如果你把这个 6 给一个变量，然后再把变量写到这个位置，**它也会报错**，因为变量它是有数据类型的，而这个 6 呢是个具体的常量值，它是可以除的。同学们记住了啊。

#### 加一只鸡试试：下面的代码一行都不用改

我们来体验一下数组的好处在哪里。**如果我们增加了一只鸡的体重**，比如说只需要改两个地方——把这一个地方改一下，把体重给它加进去，完事。**下面代码不需要做任何变化。**

你看，我就是把这一个地方增加了一下，增加了一只新的鸡的体重。我一跑代码仍然是没问题的。当然这两个值肯定不一样了——总体重发生变化了，平均体重也发生变化了。

**所以说我们可以看到，数组相对来说肯定比我们原先这种单独的定义变量要方便很多，而且可操作。** 你以前在这儿写，加了一个这个东西过后，这个地方要加，这个地方还要改，你改的地方还挺多的；而且你想如果这个变量越来越多越来越多，你写多长啊！

**而我这个地方不需要变化，它一个遍历就全部搞定。**

所以关于这个数组的快速入门，我们做个小结：

> **结论**：**使用数组过后，我们发现数据的可维护性增加了，而且更加灵活、非常容易扩展，代码也更加清晰。** 你看上面传统方法那种方式显得就比较乱了，而这一看就很清晰，很利于代码的维护。

### 数组的定义与内存布局

刚才讲的数组的使用都是面上的东西，没有深入到内存。现在来看一下数组的定义和数组内存布局——**数组在内存里面到底长什么样子，它是怎么分布的。** 这点对于把数组彻底掌握非常重要。

数组定义是这样子的：`var` 关键字、数组名，这边有数组的大小和数据类型。比如说刚才用的：

```go
var a [5]int
```

`a` 就是一个数组的名称，5 代表数组最多存放 5 个数据，int 代表数组能够存放的数据类型是什么。赋初值就是 `a[0]` 代表给第一个元素赋初值，`a[1]` 代表给第二个元素赋初值。前面已经讲过就不再多说。

**这里重点想给大家画一下数组在内存里面的布局图。** 新建一个文件夹 `array_demo02`，新建文件 `main.go`。为了容易画出来，我们定义一个存放 int 类型的数组：

```go
var intArr [3]int
```

这个数组定完之后，**它本身也有默认值**。也就是说这地方不用赋初值，其实已经有默认值了。**当定义完数组后，数组的各个元素已经有默认值了，默认值就是 0。** 我们可以打印给大家看一下：

```go
fmt.Println(intArr)
```

先不给它赋初值，先让大家看到定义过后会是什么样子。执行 `go run main.go`，可以看到这里面有 3 个元素，它们都是 0，也就是 `[0 0 0]`。

当代码执行完 `var intArr [3]int` 这句话过后，在内存里面会出现这么一个东西：有个叫 `intArr` 的变量。因为它是值类型，所以在这个地方会有一个数组，里面存放 3 个数据，这块空间就分配好了，而这个空间里面每一个元素也有了默认的值，就是 0。`intArr` 就指向了这个位置——**因为它是值类型，直接指过去关联上了**。

#### 数组的地址就是首地址，首地址就是第一个元素的地址

能不能看一下 `intArr` 它的地址是什么？可以。**数组名它的地址就是数组的首地址。** 往深了研究一下这句话：

```go
fmt.Printf("intArr 的地址=%p\n", &intArr)
```

用 `%p` 输出，取一下它的地址看是什么东西。可以看到 `intArr` 指向了这个地址，这个地址就是数组的首地址。而且还有一点——**数组的首地址其实就是第一个元素的地址**。

总结一下：

- **数组的地址可以通过数组名来获取**，也就是 `&intArr` 就可以了；
- **数组的第一个元素的地址就是数组的首地址**。

我们证明一下，来看第一个元素的地址，也就是 `&intArr[0]`：

```go
fmt.Printf("intArr[0] 的地址=%p\n", &intArr[0])
```

> **注意**：**如果要取地址的话得加 `&` 符号；如果不加 `&` 符号，就直接把值取出来了。**

看第一个元素的地址是不是跟数组的首地址是一样的——可以看到两个是完全相同的。这个也可以理解，**就像小朋友排队，排在第一个的同学，他既是第一个同学的地址，同时也是整个队列里面的首地址**，完全是这样子的。

#### 元素占多少字节，间距就是多少

再思考一下，打出第二个元素的地址：

```go
fmt.Printf("intArr[1] 的地址=%p\n", &intArr[1])
```

**第二个元素的地址其实就是第一个元素的地址基础上加上这个元素占用的字节数**，也就是加上数组类型占用的字节数。比如说 int 是占 8 个字节，因此可以推出来这个元素一定是前面这个元素加一个 8 就行了。根据这个情况来说，下一个元素就应该是 `0xc04204a0a8`。

**为什么敢这么肯定？因为它是按照连续分布的，而一个元素是一个 int，一个 int 占 8 个字节，所以一定是前面元素加一个 8。**

看效果，完全没问题。上面是 `a0`，这个是 `a8`，就是在基数上加了一个 8；后面依次类推，如果要找下一个地址，在这个基础上再加一个 8。看第三个元素：

```go
fmt.Printf("intArr[2] 的地址=%p\n", &intArr[2])
```

第一个是 `a0`；在 `a8` 的基础上再加一个 8 就是 `b0` 了，**因为它是十六进制的**：$8 + 8 = 16$，十六进制就进位，a 变 b，8 变 0，成了 `b0`。

把这段代码和上面画出来的图放在一起看，内存布局就是这样的：

```text
        ┌──────────┐
        │  intArr  │  变量名（值类型：直接指向数据空间）
        └────┬─────┘
             │ 首地址 = &intArr = &intArr[0]
             ▼
   ┌────────┬────────┬────────┐   每个元素 int 占 8 字节，地址连续
   │  0    │  0    │  0    │
   └────────┴────────┴────────┘
   ...a0        ...a8        ...b0     ← 每次 +8（0x8）

   一改元素的值：
   ┌────────┬────────┬────────┐
   │   10  │   20  │   30  │
   └────────┴────────┴────────┘
   ...a0        ...a8        ...b0     ← 地址一点没变，变的只是值
```

我们也可以改变它，比如我把这个值稍微改变一下：

```go
intArr[0] = 10
intArr[1] = 20
intArr[2] = 30
```

此时此刻我们再去执行，大家看是不是这些地方还是没有变化，但是**值发生变化**。前面是 `0 0 0`，后面是 `10 20 30`。也就是说，**通过这个元素的访问，我们也可以改变各个元素里面具体放的值**。

#### 如果把类型改成 int32 呢

如果把这个改成 `var intArr [3]int32`，思考一下，它们之间的地址是不是还是连续的？而且它们地址之间每个相差几呢？**相差 4，因为 int32 是 4 个字节。**

看一下，彻底把它搞懂：首地址仍然是一样的，但是下一个地址是加了 4，再加一个 4 是 `88`。为什么？因为 int32 每一个元素占的是 4 个字节，所以每个就加一个 4。**理解这个东西，大家一定要注意。**

> **结论**：**数组元素的地址间隔多少取决于数组的类型。** 各个元素的地址大小间隔是依据数组的类型来决定的。比如你是 int 类型的——int 类型其实就是 int64，因为在我这个系统里面操作系统是 64 位的，比如 64 位，它间隔就是 8 个字节；如果你是 int32，它的间隔就是 4 个字节，以此类推。

#### 这张内存图还透露了两件事

这个图一定要深刻地理解。**如果你理解这个图了，我跟大家讲，后面学习的东西相对很轻松。** 因为首先从这个图透露很多信息：

- **第一个，我们可以很明确地看到数组它是什么类型——它是值类型。** 因为如果是引用类型的话，它不会直接指向这个数据空间，而是指向一个地址。但是你看这个图是让名字直接指向数据空间的，说明它是值类型；
- **第二个，我们可以看到它的内存里面每个元素，它的地址是连续分布的，而且每隔多少取决于数组的类型。** 而且怎么去访问各个元素，这也体现出来了。

**通过这个地方还可以看到一个非常重要的特性：数组元素的地址其实是连续的，这也是 Go 语言里面的一个特点。** 有些高手以前做开发时讲过一个方法：**想快速定位一个值，最快的方法就是在这个地址上加——在这个地址上加一个 8，就马上取得下一个元素的地址然后取值，速度是最快的。用地址的方式来取值速度是最快的，但是要找到它的规律。**

## 数组的使用：元素访问、初始化、for-range 与使用细节
> 对应块：BLK52 | 覆盖分集：P146-P148 | 块标题（分集名）：《145_尚硅谷_数组的使用》

数组的内存布局那张图，我们还可以画得更明确一点。你看这个地方我写一个 `int array[0]`，对不对？这个就是我们的第一个元素；第二个元素就是它，下标为 1；第三个元素下标为 2，放到这儿就可以了。它们分别是这样一组对应关系——第一个元素、第二个元素 `int array[1]`、第三个元素 `int array[2]`。这样子画一下就更明确了。

### 访问数组元素的基本语法

在 Go 里访问数组元素，基本语法就是：**数组的名字，然后中括号里面写上下标名**。比如你要访问 `a` 数组的第三个元素，就应该是 `a[2]`——这块刚才已经讲过了。

先来做个快速入门的案例，加深一下认识：**循环输入 5 个成绩，保存到 `float64` 的数组中，并输出这个数组**。我们从终端循环输入。

```go
var score [5]float64

for i := 0; i < len(score); i++ {
    fmt.Printf("请输入第%d个元素的值\n", i+1)
    fmt.Scanln(&score[i])
}

for i := 0; i < len(score); i++ {
    fmt.Printf("score[%d]=%v\n", i, score[i])
}
```

先定义一个数组 `var score [5]float64`，它要存放 5 个成绩，类型是 `float64`。写完过后大家都知道，默认情况下这些元素的值是 0。

然后写 `for` 循环，让它从控制台循环输入值。循环条件直接用 `len(score)`，是不是更灵活一些？每次让它输一个成绩就写一句提示语；因为元素下标为 0 的时候刚好对应第一个元素，所以提示语里写的是 `i + 1`。接收的时候传一个**地址**过去——传 `score[i]` 的地址，把地址传进去就会改变外面数组的值。每次输一个，输到第 5 个的时候循环就退出来了。

最后再遍历一次把数组打印出来：

```bash
请输入第1个元素的值
80
请输入第2个元素的值
90.5
请输入第3个元素的值
70.1
请输入第4个元素的值
45.6
请输入第5个元素的值
89
```

输出的结果依次是 80、90.5、70.1、45.6、89，第五个也都正确。这个案例没有难度了，因为我们刚才已经遍历过数组了。

### 四种初始化数组的方式

除了刚才那种"先定义、再逐个赋值"的方式，Go 还提供了几种在**定义的同时直接初始化**数组的写法，更方便。

第一种，先把类型写好，大括号里填元素：

```go
var arr01 [3]int = [3]int{1, 2, 3}
fmt.Println("arr01=", arr01)
```

第二种，也可以不写类型部分，直接用类型推导：

```go
var arr02 = [3]int{5, 6, 7}
fmt.Println("arr02=", arr02)
```

因为你把值交给 `arr02` 了，它也就知道这个数组是什么样子的。

第三种，中括号里的长度不用写，写 `...` 就行：

```go
var arr03 = [...]int{8, 9, 10}
fmt.Println("arr03=", arr03)
```

> **易错点**：这里的 `...` 是固定写法、规定的写法，三个点不能少一个、不能改，表示让系统自己去判断这个数组到底有多大。

第四种，可以指定元素值的下标：

```go
var arr04 = [...]int{1: 800, 0: 900, 2: 999}
fmt.Println("arr04=", arr04)
```

下标为 1 的元素值等于 800，下标为 0 的元素等于 900，下标为 2 的元素等于 999。输出的时候你会看到，它**并不是按你书写的顺序**给值的：800 属于下标 1，900 属于下标 0，999 属于下标 2。真正输出时先输出 900，再输出 800，再输出 999——因为你已经指定了下标，下标为 0 其实是第一个元素，输出时它会按下标的顺序来。

当然也可以结合类型推导，写成短变量声明：

```go
strArr05 := [...]string{1: "tom", 0: "jack", 2: "mary"}
fmt.Println("strArr05=", strArr05)
```

跑一跑，结果同样是先输出 `jack`，再输出 `tom`，再输出 `mary`，没毛病。

大家以后看到这种写法也不要觉得很奇怪，人家确实可以这样初始化——我在定义的时候同时就给各个元素直接指定值，这是允许的。而且如果你不写这些值，默认都是零值：`int`、`float` 这些是 0，`string` 是空字符串。

### for-range：Go 语言独有的遍历结构

数组遍历主要有两种方式。一种是前面一直在用的**常规遍历**，就是普通 `for` 循环，已经演示过很多次了，这里不再赘述。另一种是 Go 里特有的一种结构，叫 **`for-range`**。

基本语法非常简单：

```go
for index, value := range array01 {
    fmt.Printf("index=%v value=%v\n", index, value)
}
```

`for` 后面先来一个 `index`，第二个是 `value`，中间这个符号叫 `:=`，是类型推导符，相当于定义的同时赋值。再往后的 `range`——为什么叫 for-range，就是因为这有一个 `for`、有一个 `range`，所以 Go 程序员在开发的时候经常就说 for-range 这个结构。最后那个就是你要遍历的数组名称。

关于它有五点要记：

1. **`index` 是数组的下标**。遍历的时候会依照这个顺序依次遍历，先把 `array01` 第一个元素的下标放到这个位置。
2. **`value` 是该下标位置的值**。就是这个 `index` 下标对应的那个值是多少。一个是下标，一个是值。
3. **它们都是仅在 `for` 循环内部可见的局部变量**。这又涉及到变量的作用域了：如果变量是在 `for` 循环这个语句块里面定义的，作用域就只能在这个 `for` 循环的代码块里边，出了这个代码块就不能用了。你不能说我这有一个 `index`、有一个 `value`，然后跑到下面去用，那是用不了的。
4. **不想使用下标，就把下标用一个下划线**。下划线还记得是什么符号吗？是占位符，也叫忽略。我并不关心每个元素的下标是什么，只关心每个元素的值，那就把下标忽略掉。当然你也可以反过来忽略掉 value，看你的需求。
5. **`index` 和 `value` 的名称不是固定的**，程序员可以自行指定。一般我们写成 `index` 和 `value`，显得比较通用；有些程序员就写 `i`、逗号、`v`，这也是完全可以的，没毛病。它们其实就是两个变量名，并不是固定就叫 index 或者 value。

#### 遍历一个英雄数组

新建一个文件夹，就叫 `forrange`，进去写 `main.go`。先定义一个数组 `heroes`，里面放三个元素：

```go
heroes := [3]string{"宋江", "吴用", "卢俊义"}
```

> **提示**：注意这些地方必须要写。中括号里的 `3` 和 `string` 不能少——你不能说你不按规定的写，我瞎写一个试试看，那样代码肯定是报错的，直接编译不过去，语法都错了。你可以觉得繁琐，把类型推导这种写法去掉（写成 `[...]string{...}`），甚至干脆用 `:=` 让编译器自己推，但**不能连中括号里的类型都不要**。

定义完之后我们把它打印出来看看——结果编译果然报错：因为你把数据类型整个没写进去。这样一写就没报错了，但是这种写法是把整个数组按照**首地址**的方式一下打印出来的，我们希望把每一个英雄单独取出来，你还不能用这种方式。

那就用 `for-range` 来遍历。常规方式我就不写了，前面演示过。

```go
for i, v := range heroes {
    fmt.Printf("i=%v v=%v\n", i, v)
}
```

这里 `for` 后面是谁呢？`index` 逗号 `value`——如果你嫌这个烦，也可以简单写成 `i`、逗号、`v`，同样可以。然后是类型推导符 `:=`，再 `range`，`range` 谁呀？`heroes`，最后括起来。

这里要留心一个特别容易搞蒙圈的地方：`i=%v`、`v=%v` 这两个 `%v` 是**格式化的占位符**，而变量名叫 `v` 是你自己给起的名字，这两件事完全是两码事。

`cd` 到 `forrange` 目录里 `go run main.go` 跑一下，结果就出来了：`i` 等于 0、`v` 等于宋江；`i` 等于 1、`v` 等于吴用；`i` 等于 2、`v` 等于卢俊义。也就是说下标为 0 的元素值是宋江，下标为 1 的是吴用，下标为 2 的是卢俊义。

有些同学会问：我能不能用这个遍历的同时，再用传统方式取一下？**语法上当然也可以。** 比如把格式符写成 `%d`，取的时候写 `heroes[i]`，因为这个 `i` 大家都知道就是下标，刚好是下标。跑一下，一样能取出来：第一次 `i` 等于 0、宋江，`heroes[0]` 也等于宋江；第二次 1、吴用；第三次 2、卢俊义。两种方式都行。

不过既然我们已经用了 for-range，**我建议大家就直接用上面那种写法，别两个都去用**。

#### 只想用值，不想用下标

有些时候因为种种原因，你不想用下标，只想用值，那就把下标用下划线占位：

```go
for _, v := range heroes {
    fmt.Printf("元素的值=%v\n", v)
}
```

这相当于说我不关心它的下标，只关心 `heroes` 里面的值。跑一下，宋江、吴用、卢俊义，一样可以取出来。

> **结论**：最后强调一下 `i` 和 `v` 的作用域——它们只在这个 `for` 循环的块里面，离开这个环境你就不能再用了，因为这是变量作用域规定好的。for-range 这种使用方式用的非常多，后边写项目的时候会经常用到。万丈高楼平地起，还是要先把这些基础打扎实，不然后面写项目的时候立马就会懵圈。

### 数组的注意事项和细节

前面我们讲了：为什么需要数组、数组的介绍、快速入门、定义和内存布局——尤其是这个布局，大家一定要非常清晰，只有理解了它，你才能理解数组在内存里边、在底层是以什么形式存在的。然后是数组的使用，重点是访问、那个循环输入成绩的案例，还有四种初始化方式；最后是遍历，常规方式和 for-range。

如果你只是掌握了数组这块知识，可以说工作的百分之七八十基本就能应付了。但还有使用细节和注意事项，我一共给大家整理了将近十点，这一讲先讲前五点。

#### 相同类型，长度固定

第一点：**数组是多个相同类型数据的组合**。注意听这句话：相同类型。如果你定义的是一个 `int` 类型的数组，那它就只能存放 `int`；比如定义为 `int32` 的，就只能存 `int32`，连 `int64` 都存不进去。

第二点：**一个数组一旦声明定义了，其长度是固定的，不能动态变化**。很多别的编程语言也有这个特点——**数组的长度本身就是数据类型的一部分**。这个长度一旦写下来了，你就不能说我给它动态地增长，这是不准许的。

举个例子：

```go
var arr01 [3]int
arr01[0] = 1
arr01[1] = 30
arr01[2] = 1.1
fmt.Println(arr01)
```

`arr01[0] = 1` 可以；`arr01[1] = 30` 也可以；第三个元素给个 `1.1` 就不行了，保存的时候编译直接出错——常量 1.1 不能给这个 integer，数据类型不匹配。既然你定的是 `int`，就不能给它一个小数。

再看长度：

```go
arr01[2] = 90
arr01[3] = 890
```

给它一个整型 90 没问题，但你不能再来一个下标 3。这句一写就变色了，报错是 `invalid array index 3 (out of bounds for 3-element array)`——`out of bounds` 就是越界。为什么？因为你这个地方是三个元素的数组，你却给到了第四个元素。这种代码根本不用去运行，编译都已经错了，运行也没有意义。

> **提示**：这里还要强调一点——假设你这儿是 `int32` 的，你也不能给一个 `int64`。即使同是"int 类型"，它也要区分：我们知道有 `int8`、`int16`、`int32`、`int64`，即使是 int 类型，这里面也要细分。所以哪怕数组定的是 `int32`，你也不能塞一个 `int64` 的变量给它，它一样要分开。

#### 中括号里不写长度，那就不是数组

第二类要注意的地方：有些同学会看到有人这么定义数组——`var arr []int`，中括号里不写大小。

注意，如果在 Go 里面前面这个中括号**没有写大小**，那么 `arr` 其实**不是数组，而是切片（slice）**。切片跟数组的区别是非常大的，因此我在这儿讲解意义就不特别明显，放在后面专门讲，请大家不要着急。

我为什么专门提这一句？因为在很多其他编程语言里面，定义数组的时候前面是不用写大小的，但在 Go 语言里是要写大小的，考虑到有些同学有别的编程语言基础，我专门提一下。

#### 元素类型可以任意，但不能混用

第三点：**数组中的元素可以是任意数据类型，包括值类型和引用类型**。也就是说我现在高亮的这个类型，既可以是基本数据类型，也可以是引用类型。

但我们要说的一句话是：**不能够混用**。什么叫混用？就是你这儿定的是什么类型，那你就只能放这个类型的数据，不能一会儿放 `int`、一会儿放 `float`。其实这一点在前面已经提过了，只是在这儿专门地再系统地罗列出来。

#### 没赋值也有零值

第四点：**数组创建以后，如果你没有赋值，有默认值**，这个我们上一讲已经讲过了。数组定义好了但你没赋值，其实各个元素已经有默认值了，这个默认值就是**零值**。

零值是怎么分配的呢？

- **数值类型的默认全为 0**——不管你是整型系列还是小数（浮点数）系列的，全部为 0；
- **字符串数组默认全为空串**；
- **布尔数组默认就是 `false`**。

举个例子体验一下：

```go
var arr01 [3]float32
var arr02 [3]string
var arr03 [3]bool

fmt.Printf("arr01=%v arr02=%q arr03=%v\n", arr01, arr02, arr03)
```

> **提示**：这里我直接用数组来输出，它就会找到数组的**首地址**，然后把整个数组的数据全部输出出来——这个特点我们前面讲数组内存布局的时候已经说过了。

跑一下：`arr01` 是 `0 0 0`，`arr02` 是空串（空串在终端上看不出来，本来就没东西），`arr03` 是 `false false false`。确实如此。

#### 使用数组的三个步骤

第五点，把数组使用的步骤捋一下：

1. **声明数组并开辟空间**。在你定义数组的时候，这个空间其实就已经给开辟了——数组在做这个工作的时候，你的数据空间就已经分配好了，只是你没赋值而已；没赋值它是零值。
2. **给数组各个元素赋值**。当然有些同学说"老师，我不赋值"——不赋值默认就是零值，默认是零值，默认零值。
3. **使用数组**。使用数组就是通过下标来访问到各个元素，就这样。

## 数组细节的最后几讲：值拷贝、指针传参与两道应用题
> 对应块：BLK53 | 覆盖分集：P149-P150 | 块标题（分集名）：《148_尚硅谷_数组注意事项和细节(2)》

数组的十个注意事项和细节，上一讲收了前五个，这一讲把它们讲完，顺便进入数组的应用案例。

### 下标越界：编译器能骗过去，运行时骗不过

先补一条最容易忘的：**数组的下标是从 0 开始的**。这一点请大家特别注意，对初学者来说很容易忘掉。

举个例子。我定义一个数组 `arr04`，长度是 3，类型是字符串。它能够访问的下标其实是 **0 到 2，没有 3**——因为只有三个元素，所以它的元素就是 0、1、2。你一定要用到 3，会出什么问题？会报越界。

直接写 `arr04[3]` 的话，编译器当场就会报错。但我可以"骗"它一下：定义一个变量 `var index int = 3`，然后用它来访问下标。

```go
var index int = 3
fmt.Println(arr04[index])
```

这样从编译器那一关就混过去了——它发现是个变量，就不检测了。你直接写个 3 它能检测出来，写成变量它就检不出来。但这不代表你没事，**运行的时候就会报越界**。

跑一下，你会看到一个运行时错误，是个 `panic`，报的信息是 `index out of range`。而且它还告诉我们是第 35 行——学会看错误，35 行是哪一行呢？就是我们刚才写的那一行。

> **结论**：以后再看到 `index out of range`，不用怀疑，一定是数组的下标超过了它的范围、不在范围以内。当然也不能是 -1——"老师，我小一点行不行？"也不行，因为它只能是 0、1、2：你的长度就是 3，下标又从 0 开始。

所以记住这一条：**数组下标必须在指定范围内使用，否则报 panic：数组越界。**

### 数组是值类型：传参时会发生值拷贝

第八个细节，也是特别重要的一条：**Go 的数组属于值类型，默认情况下是值传递，因此传参时会进行值拷贝，数组之间不会相互影响。**

也就是说，我们把一个数组传给一个函数时，它其实是把整个数组做了值拷贝。值拷贝就意味着——在函数里面做的改变，并不会影响到外面。

> **提示**：很多编程语言里数组其实是引用类型，但在 Go 语言里，数组非常有意思，它是值类型。这一点请大家一定要高度重视。

#### 值拷贝实验：函数里的改动出不去

先写一个函数：

```go
func test01(arr [3]int) {
    arr[0] = 88
}
```

这里要留心一件事：在 Go 里，**数组类型中的长度是类型的一部分**。再说一遍，在 Go 里面数组的长度是这个数组类型的一部分，因此这个 `3` 必须写清楚。Go 认为 `[3]int` 和 `[4]int` 不是同一种数据类型——这个是一种数据类型，那个又是另外一种数据类型，因为长度不一样。

> **结论**：对于学过其他编程语言的人，这一点是很难接受的；但在 Go 里面它就是这样认为的。所以在定义参数类型的时候，要把长度写上。**你不写上，那它就不是数组，而是切片（slice）**——后面我们还有案例专门证明这个事情。

函数里把 `arr` 的第一个元素改成了 88。现在来测试，主函数里：

```go
var arr [3]int = [3]int{11, 22, 33}
test01(arr)
fmt.Println("main 里面的 arr =", arr)
```

请大家思考一个问题：这个时候输出的是 11、22、33，还是第一个元素已经被改成 88 了？

它是值类型，因此不会相互影响。跑一下，输出结果是 11、22、33，并没有出现 88。

#### 两份拷贝画在内存里

如果画一张内存图来说明，就是这个样子：

```text
    main 栈                            test01 栈
┌───────────────────┐               ┌───────────────────┐
│ arr               │               │ arr               │
│   值拷贝 ─────────┼──────────────►│   值拷贝          │
│   [ 11  22  33 ]  │               │   [ 88  22  33 ]  │
└───────────────────┘               └───────────────────┘
      ↑                                   ↑
   打印的是这份                      函数改的是副本
   始终没变
```

执行到定义数组那句话的时候，内存里、在**栈**里就会出现这么一个情况：这里有一个 `arr` 变量，给的是 11、22、33，这是在 main 函数里的一个栈。

执行到 `test01` 这一句时，它会把 `arr` 传给 `test01`。`test01` 会把这个 `arr` 做一次值拷贝——意味着它会有一个**新的、独立的空间**，在 `test01` 这个栈里面。`test01` 这边会有一份跟 main 栈一模一样的数据，在这里把 `arr[0]` 改成 88。改完，`test01` 调用完毕。

后面那个打印是在 main 栈里执行的，打印的其实是 main 栈里的 `arr`。这个栈没有发生任何变化，因此它仍然是 11、22、33。你这边改变的东西跟我没有影响。

### 用指针传参改变默认行为

那有同学问了：如果我就想在别的函数里去修改原来的数组，在 `test01` 里面改变主函数里的那个，可不可以？

当然可以，用**指针传递**就行。虽然默认是值传递，但如果我们通过引用传递，也就是通过指针方式传递，那也可以成功。

#### 传地址：外面的数组真的被改了

新写一个 `test02`，关键是给参数加一个星号：

```go
func test02(arr *[3]int) {
    (*arr)[0] = 88
}
```

加一个星号，这边 `arr` 就变成了指向数组的一个指针。

那在这个函数里面怎么访问到第一个元素呢？你肯定不能直接 `arr[0]` 这样访问。为什么不能？因为你的 `arr` 已经不是数组了，是指向数组的一个指针。同样，你得先用取值符把它包起来——**`(*arr)[0]`**：先把这个 `arr` 用取值符找到这个数组，然后取下标 0。这个就相当于取到这个数组了，能理解吗？因为 `arr` 本身是个指针，我用一个取值符就找到这个数组了，然后取 0。好，这样就 OK。

主函数这样调：

```go
var arr [3]int = [3]int{11, 22, 33}
test02(&arr)
fmt.Println("main 里面的 arr =", arr)
```

怎么传地址过去还记得吗？`&` 符号，把我们数组的**首地址**传给这个 `arr` 指针。

执行一下，输出的内容就发生了一个变化，变成了 **88、22、33**。那为什么这次会发生变化呢？再画一张图。

```text
    main 栈                              test02 栈
┌───────────────────┐                 ┌───────────────────┐
│ arr               │  传 &arr 首地址 │ arr  (*[3]int)    │
│   首地址 0xc...───┼────────────────►│   值 = 0xc...     │
│  [ 11  22  33 ]   │                 │   自身也有地址    │
│   11 → 88 ◄───────┼──────┐          │   0xd...          │
└───────────────────┘      │          └───────────────────┘
                           └──────────────┘
                        (*arr)[0] = 88  改的是同一块数据
```

读一下这张图。`test02` 一执行，它又会开辟一个独立空间。在这姑且称之为 test02 的栈里面，也会有个 `arr`，但此时此刻它**不是值拷贝**——它拿到的是这个数组的**首地址**。你可以把这个首地址打出来看看，用 `fmt.Printf` 配合 `%p`：

```go
fmt.Printf("arr数组的首地址=%p\n", &arr)
fmt.Printf("arr指针的地址=%p\n", &arr)
```

运行一下确实能拿到，而且这两个地址**肯定是不一样的**——存放数组首地址的那个指针空间，它本身还有一个地址。这个我们以前其实已经分析过了。

把这里说得透一点：`arr` 是一个指针，它自己有一个空间，存放的是"指向原先那个数组的首地址"；同时呢，存放这个地址的空间，它本身还有一个地址。两个是一样的。

然后执行 `(*arr)[0] = 88`：`(*arr)` 直接取到了这个数组的值，下标 0 就找到了 11，给它改成 88。而这个 11 正是 main 栈里那个数组的元素——所以 main 栈里的 `arr[0]` 也变成了 88。执行完毕退回 main，`fmt.Println` 打印的自然就是 88、22、33。

#### 值拷贝和指针传递的开销差多少

显然这种写法比上面麻烦一点，因为你用了一个指针传递。但大家想一想，**哪个效率高？**

指针传递的效率显然要高一点。因为我在拷贝的时候，拷贝的其实只是一个地址——它既然是个地址，数据量是很小的，数据量小当然效率就高了。而值拷贝呢？假设我们这个数组很庞大，比如不是 3 个元素而是 3000 个元素，那你这个值拷贝其实是非常耗费资源的。

> **结论**：因此在使用数组的时候，如果我们就是想去改变外面的数组，那就用指针传递——效率高，而且速度快。

这块我讲得比较透彻，因为涉及到一些原理性的东西。如果这块你还没听明白，那就好好地把这个图再好好地过一过。

### 长度是数组类型的一部分：三个编译案例

第十个细节，也是最后一个：**在 Go 中，长度是数组类型的一部分，在传递函数参数时，需要考虑数组的长度。** 下面有三个案例，看看你觉得会怎么样。

**第一个案例**：主函数里定义一个长度为 3 的数组，然后把它传给 `modify`。但这个函数接收的时候，形参里**没有写长度**。

答案：编译直接错误，通不过。因为数组在传递的时候长度是类型的一部分，你这么写相当于把一个数组给了一个切片（`[]int`），类型根本对不上。

**第二个案例**：同样是数组，这个写了 4，传给形参是 `[3]int` 的函数。同样错。有人说"上面不是已经是一个数组了吗？"——对不起，长度是数据类型的一部分，Go 认为这两个不是同一个类型，所以仍然是编译错误。

**第三个案例**：这边是长度为 3 的 `int` 数组，那边也是长度为 3 的 `int` 数组。编译正确，通过。

我之所以举三个案例，就是想阐述一个很多同学学完别的编程语言不太容易理解的地方：**在 Go 中，长度是数据类型的一部分**。其实我就想阐述这一个观点，但举了三个案例加深大家对它的认识。你们可以自己敲敲这段代码验证一下。

到这里，数组的十个细节就全部讲完了。如果你能把这十个细节都掌握消化掉，那么在使用数组的时候几乎就没有什么拦路虎了，就肯定能够非常正确地使用数组。

### 案例一：把 A 到 Z 装进 byte 数组

掌握细节之后我们来做一些数组的应用案例，加深对数组应用的掌握。只有通过做题，才能真正把语法掌握清楚。这一块我准备了三个题，先做前两个。

第一个题：**创建一个 `byte` 类型的 26 个元素的数组，分别放置 'A' 到 'Z' 这 26 个英文字母，使用 for 循环访问所有元素并打印。**

题里给了一个提示，有没有发现？他说字符的数据运算是按照字母来的，比如我要得到 B 字母，那我是 `'A' + 1` 就可以了。这里利用了**字符可以参与运算**这个特性。也就是说你在放置的时候，不能傻乎乎的一个一个放，那样太慢了；人家要求用 for 循环来放置，而且要求用 for 循环来打印。

分析一下思路，很简单：第一步，声明一个数组 `var myChars [26]byte`；第二步，使用 for 循环，利用字符可以运算的特点来赋值；第三步，用 for 循环把它打印出来。

```go
package main

import "fmt"

func main() {
    var myChars [26]byte
    for i := 0; i < 26; i++ {
        myChars[i] = 'A' + byte(i)
    }
    for i := 0; i < 26; i++ {
        fmt.Printf("%c ", myChars[i])
    }
}
```

注意：**做任何事情，思路是第一位的**。如果思路不清晰，那你写代码肯定要出问题。

先看赋值那一行。`myChars` 下标为 `i` 的时候等于 A 字母加上这个 `i` 就行了。但这样写你们待会儿会发现有个小问题，我先卖个关子，故意起个问号。

现在一保存，马上就发现报错了，红色波浪线出来了。为什么？因为字符在进行运算的时候是 `int` 类型，而 `i` 的类型——注意听——它是一个 `byte` 类型。报错的提示是 `use of 'A' + i (type int) as type byte`：他的意思就是说，你这个 `i` 是一个 byte，相当于运算的时候把它当成 byte；而你那个地方是 int 类型，所以类型不匹配。

怎么办？转一下。Go 语言是强数据类型语言，数据类型不匹配它是不能够进行运算的，把这个 `i` 从 int 转成 byte，再保存，OK 了，代码没毛病。

输出就简单了，用 for 循环，老规矩我偷个懒从上面粘贴拷贝下来：

> **提示**：需要将 `i` 转成 `byte` 类型。输出时因为你是按照字符来输出的，所以格式化要写成 `%c`，这样才是按照字符输出。为了好看，中间我打一个空格。

`cd` 到 `chapter07/array_exercise` 目录下 `go run main.go`，跑一下：输出正是我们要的 26 个字母。第一个题完成。

### 案例二：求数组的最大值及其下标

第二个题要求：**求出一个数组的最大值，并得到对应的下标。**

意思就是：给一个数组，要求把这个数组的最大值导出来，并且把这个最大值对应的下标给我找出来。老规矩，**万事都要从思路开始**。

**第一步**，你首先得有个数组。假设我们叫 `intArr`，里面有五个元素，先初始化一下：`1、-1、9、90、11`。大家看到这里面最大值是 90——但这是人看到的，计算机不知道。

**第二步**，**假定第一个元素就是最大值**。那下标是几呢？下标就是 0，这是我假定的。

**第三步**，让这个假定的最大值分别和后面的数据相比较，如果发现有比它大的，我就交换。从第二个元素开始循环比较，如果发现有更大的数，则交换这个最大值。

> **结论**：也就是说，你认为第一个是最大，但不一定就是最大的；当然它也有可能就是最大的。那怎么办呢？我就让它跟第二个元素开始循环比较，发现有更大的就交换。思路非常清晰。

```go
package main

import "fmt"

func main() {
    intArr := [5]int{1, -1, 9, 90, 11}

    maxVal := intArr[0]
    maxValIndex := 0

    for i := 1; i < len(intArr); i++ {
        if maxVal < intArr[i] {
            maxVal = intArr[i]
            maxValIndex = i
        }
    }

    fmt.Printf("maxVal=%v maxValIndex=%v\n", maxVal, maxValIndex)
}
```

代码里两处要留意：一是开头的类型推导那里少了冒号，少了冒号就用类型推导过去了；二是中间不能少了类型。改完跑一下，`maxVal` 是 90，`maxValIndex` 是 3，成立。

当 for 循环结束以后，`maxVal` 和 `maxValIndex` 就是真实的最大值和它的下标了。

有同学会问：如果我的元素增加了，你这个代码能不能一样地变化？可以。比如我把这个数组换成 6 个元素、其中一个是 9000，那么最大值就应该是 9000，下标应该是 5。改完再跑一遍，完全没问题，说明我们这段代码是正确的。

## 求和求平均、数组反转，以及切片的登场
> 对应块：BLK54 | 覆盖分集：P151-P153 | 块标题（分集名）：《150_尚硅谷_数组应用实例(2)》

### 数组求和与平均值：整数除法那个坑

第一道题：**请求出一个数组的和和它的平均值**，要求用 `for range`。

从题意上来说其实挺简单的，但里面有个细节要和大家聊聊。第一个要求是用 `for range`；第二个是求平均值的时候有个陷阱——如果我们的数组是**整数**数组，整数数组在求平均值的时候本身应该能精确到小数点，但默认情况下它返回的也是整数，那么这个平均值就有可能求错了。

思路很简单：第一步先声明一个数组，偷个懒直接用上面那个 `int` 数组；第二步求出和，用一个变量累加就行；第三步求出平均值。

```go
var intArray2 [5]int = [5]int{1, -1, 9, 90, 12}
var sum int = 0
for _, val := range intArray2 {
    // 累计求和
    sum += val
}

fmt.Printf("sum=%v\n\n", sum)
fmt.Printf("avg=%v\n\n", float64(sum)/float64(len(intArray2)))
```

先看求和。定一个变量 `var sum int = 0` 默认等于 0，然后遍历；要求用 `for range`，第一个下标我不关心，就用下划线忽略掉，第二个是它的值——我现在只关心值，并不关心下标，因此用下划线将下标的返回值忽略了。累加求和用 `+=` 就可以搞定。

求完之后输出来。**注意这里我故意用的是 `int` 数组，待会儿我们注意看求平均值的时候需要注意什么问题。**

一开始数组最后一个元素是 11，运行出来和是 110，平均值 22。110 除以 5 刚好整除，得 22，看着没问题。为了让它出现一个小数，我们把最后一个元素改成 12——从理论上来说应该是 111 除以 5，这必然会有一个小数点。但是跑一下你就会发现，**平均值仍然是 22**。

> **易错点**：为什么？理论上应该是 22.2，但它除下来是 22，显然跟我们要求的平均值不匹配——你把 0.2 舍掉了，舍去的值太大，我们应该需要保留到小数点。问题出在类型上：你的 `sum` 是一个 `int`，而 `len(intArray2)` 也是一个 `int`。根据 Go 语言的运算规则，**当两者都为 `int` 类型的时候，结果也会是 `int`**。

怎么办？非常简单，把数据类型转一下就可以了。那就转成 `float64`——`float64(sum)`。但是**只转前面不行**：前面转了，后面这个不转会报错，因为前面是 `float64`，而后面是 `int`。所以还要把后面这个也转一下：`float64(len(intArray2))`。

再执行一次，保留到小数点了：**22.2**。

这就是我们 Go 语言运算时候的一个规则，大家注意。这一点对学过 Java 或者学过其他编程语言的人来说有点不太适应，但没有办法，Go 语言设计者就是这样设计的：它对数据类型是强制要求转换的。前面讲基础的时候我们知道，**Go 语言的数据类型转换都是显式转换，没有所谓的隐式转换这个规则**。

这道题的考点主要就在这个位置，尤其对学过其他编程语言的人来说有点不太适应，但就得这么去做。

### 数组反转：随机生成五个数字再倒着打印

第二个案例是数组的复杂应用，叫**数组反转**。要求是：随机生成五个数字，并将其反转打印。这个相对复杂一点，是一个复杂的应用。老规矩，先把题放这儿，然后分析思路。

#### rand.Intn 与那个"每次都一样"的坑

**第一步**，随机生成五个数字。在 Go 里用什么方法可以随机生成数呢？要用到一个叫做 `rand.Intn` 的函数。

这个函数在 `math/rand` 包里。点进去看它的说明：返回一个 0 到 n 的随机数，**大于等于 0、小于 n，也就是说 n 取不到**。这个无所谓，那我们就用它。

**第二步**，得到这个数字过后，把这五个数字放进一个数组里，用 `int` 数组就完了。

```go
var array03 [5]int
for i := 0; i < len(array03); i++ {
    array03[i] = rand.Intn(100)
}
fmt.Println("array03=", array03)
```

用到 `rand` 就得引包，我们引的是 `math/rand`。运行一下，确实生成了五个数字，比如 81、87、47、59、81。但紧接着你会发现一个非常奇怪的问题：**当我每次执行的时候，这五个数字都是一样的。**

上面第一次运行是这五个数字，下面再执行还是这五个数字。虽然这五个数字的的确是随机生成的，但每一次都一样，这是为什么呢？

手册里写得很清楚：这里有一个叫做 `Seed` 的东西，它是使用给定的一个 seed 来初始化生成器到一个确定的状态。也就是说，如果你不给它设置一个 seed 值——这个值是 `int64` 类型的——它就有一个默认值。只要这个默认值固定了，它永远都会生成这五个数字。你不管怎么运行，它都是 81、87、47、59、81。

> **结论**：种子一旦不变化，它生成的随机数也是不会变化的。

#### 种子下得不够细还是不随机

那怎么给它一个种子呢？我们突然想到，前面不是学过日期和时间函数吗？如果给它一个当前的秒数，这个问题不就解决了吗？

```go
rand.Seed(time.Now().Unix())
```

大家还知道怎么获取当前 Unix 时间戳吗？应该是 `time.Now().Unix()`，还记得吧。这样一写，是不是就 OK 了？如果报 `undefined time`，那就是忘了引 `time` 包，把包引进来就好了。

跑一下：这次生成的是 61、32、59……再来跑一次，7、51、18、7、58——嗯，这个时候是随机了。

**但我告诉大家，这个方式虽然好、虽然没问题，但还是有一点风险。** 就是如果你在**同一秒**生成随机数的话，生成的还是一样的。因为 Unix 是按照当前的秒数来算的，这个种子如果你在同一秒、同一秒钟内生成了 100 个随机数，那这 100 个随机数都是一样的。因此这个还是不够 OK。

所以我们想到，能不能把这个种子下得更好一点？还记得前面讲日期和时间函数时说过获取纳秒吗？手册里有一个 `UnixNano`，是不是用这个更好一点？因为这个是精确到纳秒的。你知道纳秒，1 秒等于 1000 毫秒，1000 毫秒等于 1000 微秒，1 微秒等于 1000 纳秒。如果用纳秒，那时间肯定分散得比较广。所以我们最好用纳秒。

```go
rand.Seed(time.Now().UnixNano())
```

执行一下，每次生成的都不一样了。

#### 反转的思路：交换长度除以 2 次

有了数组，第三步就是**反转打印**。怎么反转呢？就是你要把最前面的打到后面去，把后面的打到前面去——这个地方就有一点麻烦了。

先举个例子。假设你现在产生的数组是 `44、10、46、35、34` 这样五个数。我们要做的其实非常简单：**把这个数字在打印的时候给它进行一个交换**。让 44 和 34 交换，让 10 和 35 交换，而 46 不变。

大家听我这句话：**倒数第一个和第一个交换，倒数第二个和第二个交换。** 一共交换多少次呢？那第三次刚好只剩中间那一个，自己跟自己交换没有意义嘛。

所以交换的次数刚好是**数组大小除以 2**。五个数字，5 除以 2 等于 2，在 Go 里是取整的，所以只需要交换两次；如果是六个数字，6 除以 2 等于 3，就要交换三次。思路有了没有？

```go
length := len(array03)
for i := 0; i < length/2; i++ {
    temp := array03[length-1-i]
    array03[length-1-i] = array03[i]
    array03[i] = temp
}
```

交换的代码其实非常简单。我们定义一个临时变量 `temp`，默认给 0——它是用来做交换的临时变量。

第一步，先把**倒数第一个的元素保留到 temp** 里。倒数第一个怎么写呢？就是数组的长度 `length` 减 1，再减 `i`。为什么减 1 才是倒数第一个？不减 1 就越界了。然后为什么减 `i`？因为你循环第二次的时候 `i` 就变成 1 了，再一减刚好就是倒数第二个——**你要考虑一个动态的变化**。

第二步，交换完了过后，再把第一个值 `array03[i]` 放到倒数那个位置去。下一次的时候 `i` 就是第二个值了，以此类推。

第三步，再把 `temp` 里的值放过来。

这样子就把倒数第一个交给了第一个；当 `i` 等于 2 的时候，就是把倒数第二个交给了它，以此类推，交换完毕。

做完过后，我们两次都打印，一个是在交换前，一个是在交换后。跑一下：交换前是 `63, 50, 2, 85, 10`，交换后是 `10, 85, 2, 50, 63`——没问题。

> **易错点**：这里要特别小心变量名。如果你针对的是 `array03` 在操作，那么每一处都得写 `array03`；中途手一抖写成别的数组名，你自己就混淆在里面了。我第一次跑出来就是这个问题——交换前后一模一样，因为改的根本不是同一个数组。所以这个代码请大家自己再敲一遍。

#### 把 len 存进变量的小优化

再说一个用得不太舒服的地方：上面这段代码里这个长度，我计算了几次？一次、两次、三次、四次，太麻烦了。如果这样做，程序的效率会有影响。因为 `len` 总归是一个内建函数，内建函数每次去调比较耗费资源——大家都知道，我们调一个函数都会开辟一个对应的独立的数据空间，很耗费资源。

反正这个值都是固定的，那何不把它先算出来，然后做一个变量不就完了吗？

```go
length := len(array03)
```

把 `len` 直接替换掉，换一个、换两个，这个地方也可以换。这样用起来是不是比刚才更清晰了，或者说效率更高了？我先把数组的长度求出来，然后在需要用到长度的地方，直接用这个变量来处理就可以了。

这是一个开发经验技巧——**我为什么要做这个变化呢？就是我希望能够看到的确是输出修改过后的代码**。跑一下仍然是 OK 的：`46, 31, 7, 86, 34` 变成 `34, 86, 7, 31, 46`，完全正确。

老师写完一遍过后，如果你们理解了，我建议自己再敲一遍，这样才能把 Go 的语法、包括数组应用的一些细节真正掌握住。

### 为什么要切片

接下来我们正式进入 slice 切片这个概念。**切片是 Go 语言里面特有的一种数据类型**，大家注意一下，它在使用的时候跟我们数组有什么不一样的地方。

先看一个需求：我们需要一个数组用于保存学生的成绩。这没什么错，定义一个数组来保存学生成绩再正常不过了。但是有一个问题——**学生的个数是不确定的**。一个班有几个学生不确定，可能是三个，也可能是五个，那怎么办？

你用数组吧，好像不太方便。你想想，Go 里面数组大小是固定的：你把数组空间开大了浪费，开小了不够用。

那这个时候 Go 提供的解决方案就是**切片**。通过这个小小的需求，大家大致可以猜得出来，**切片可以简单地理解成一个动态的数组**，但是它跟数组还是有些区别的，后边我们一个一个展开讨论。

> **结论**：当我们需要保存一组数据，但是数据的个数不确定的时候，就可以使用切片。

### 切片基本介绍：五个要点

关于切片的基本概念，我总结了五点。

**第一点，切片的英文叫 `slice`**，这个大家要记住。

**第二点，切片是数组的一个引用。** 大家看到这是什么意思没有？切片既然是数组的一个引用，那么切片必然就是**引用类型**——这点就体现出切片是个引用类型，而且在进行传递的时候，它就自然遵守了引用传递的机制了。引用传递和值传递的区别我们前面已经介绍过，这里就不再赘述。

**第三点，切片的使用跟数组基本上是相似的**，但是肯定有不一样的地方——如果完全相同，那切片就变成数组了。说说类似的地方：比如遍历切片、访问切片的元素，还有求切片的长度都是一样的。但还有些具体不一样的地方，后边会展开讲解。

**第四点，切片的长度是可以变化的。** 这是它跟数组比较大的一个区别。数组的长度一旦固定了是不能变化的，往数组里加的元素超过范围它就会越界。但切片不一样，它的长度可以随着数据的增加而动态地增长。因此我们说切片可以理解成一个可以动态变化的数组——当然，它不完全是个数组。

**第五点，切片的基本定义语法**：

```go
var a []int
```

还是 `var` 关键字，变量名称实际上就是切片名；第二个地方是数据类型，说明这个切片里放什么东西，放 `int` 还是 `float` 还是 `string`。唯一区别就是——**它的中括号里边不需要填长度**，就是一个中括号就行了。写个 5、写个 4 都不需要，一对中括号就表示它是一个切片。

所以 `var a []int` 表示：`a` 是一个切片名，这个切片可以放 `int` 类型的数据，可以放多少个 `int`？不确定，你爱放多少放多少，因为切片本身是可以动态变化的。

### 切片快速入门：intArr[1:3] 到底切出了什么

有了这五点，我们来个切片的快速入门，直接体验一下切片的基本使用。老规矩在 `chapter07` 里新建一个文件夹 `slicedemo/demo01`，新建 `main.go`。

先用第一种方式，定义一个 `int` 数组，大小为 5，初始化为 `1、22、33、66、99` 这五个元素。

然后声明一个切片：

```go
slice := intArr[1:3]
```

这个就是一个切片了。这种写法代表什么意思呢？说明一下：

1. `slice` 就是切片的名称，比较简单。
2. **注意它是"引用"**——`slice` 直接引用到 `intArr` 这个数组，**它自己直接指向它就行了，并没有进行一个值拷贝**。
3. 它引用的是 `intArr` 数组里**起始下标为 1、终止下标为 3（但不包含 3）**的那一段。

这一条有点拗口。起始下标写 1，那从下标为 1 的元素开始，也就是 22；终止下标写 3，下标为 3 是 66，但**不包含下标 3**，所以引用到的其实是 **22 和 33**。

注意，它包含起始的那个下标，不包含终止的那个下标。

我们把它输出来，同时输出它的长度和容量：

```go
slice := intArr[1:3]
fmt.Println("intArr=", intArr, "slice=", slice)
fmt.Println("slice的元素个数=", len(slice), "slice的容量=", cap(slice))
```

长度跟前面求数组长度是一模一样的写法。切片还有一个东西叫**容量**，通过一个内置函数 `cap` 就可以算出来。

> **定义**：所谓容量，就是这个切片目前可以存放的最多元素个数。而这个容量是**可变的**、可以动态变化的——当它容量不够的时候它就会自动增长，再加、再加的时候又不够，它又自动增长。

`cap` 的全写是 `capability`，这个单词就是容量的意思。手册里的说明是：内建函数 `cap` 返回 v 的容量，这取决于具体类型。比如切片的容量就可以通过 `cap` 来计算。

运行一下，结果是这样的：数组 `intArr` 本身没问题；`slice` 的元素是 **22 和 33**，跟我们分析的完全一样；元素个数是 **2**；容量是 **4**。

我说过，它的容量一般是元素个数的两倍，但**不一定**。为什么会是两倍？因为 Go 的设计者认为，你到了 2 之后有可能继续再增加，再增加的话我这个 4 就可以在不用变化的情况下继续放。它的容量不会说你增加一个我给你加一个，而是**预先先给你增加一点，等到你不够的时候再一次性分配一些空间，这样效率就比较高一点**。

如果你的元素越来越多，比如元素到了 33，它的容量可能就不一定是 66 了——因为他觉得你再加一个才 34 个，开这么大容量有点浪费，也有可能是个 1.5 倍的样子。但这个其实我们并不关心：**容量你不用操心，它会随着你元素的增加自动变大。**

另外要提醒的是：**数组没有容量的这个概念**，数组是多大就是多大，它是固定的。

到这里，切片的"为什么需要切片"、基本介绍以及快速入门案例就介绍到这里了。

## 切片的内存布局，以及它的三种使用方式
> 对应块：BLK55 | 覆盖分集：P154-P155 | 块标题（分集名）：《153_尚硅谷_切片的内存布局分析》

快速入门完了之后，我们应该对切片在内存中存在的方式做一个分析——这块非常重要。我们都知道，往往涉及到底层这些原理性的东西都是非常重要的。为了让大家更深入地理解切片，我们画一个图，来分析一下切片在内存里是如何布局的，以及切片和它引用的那个数组之间到底是什么关系。

### 切片在内存里其实只有三块

还是以前面那个案例来说，不搞别的东西了，就根据这个案例来画。

代码从这里开始走：

```go
intArr := [5]int{11, 22, 33, 66, 99}
slice := intArr[1:3]
```

假设这是我们的内存。第一句话执行完——也就是声明数组那一句——大家都知道数组是一个值类型，当它这样声明过后，在我们的内存里就存在一个变量叫 `intArr`，它会指向一个内存空间。

这个空间里有五个元素，我把它画成五个小格子：第一个元素是 11，第二个是 22，第三个是 33，第四个是 66，第五个是 99。因为 `intArr` 是值类型，所以它就**直接**跟这个数组关联，指向我们这个数组。

当我们的数组走到第二句、做了切片以后，内存里又变成什么样了呢？**请注意：切片包含三个非常重要的部分。** 它的本质可以理解成一个数据结构——**结构体（struct）**，这样一写你就明白了。

#### 第一块：指向引用起始元素的那个地址

第一个部分就是一个地址——**指向 22 这个元素的地址**。

为什么是指向 22？因为你这个切片切的是 1 到 3，指向 `intArr` 数组的第二个元素，那第二个元素不就是 22 吗？

这个地址具体是多少？我们可以直接打印出来：

```go
fmt.Printf("intArr[1]的地址=%p\n", &intArr[1])
```

运行一下就看到了。也就是说，在我们的这个 `slice` 的数据结构里面，它的第一个部分就是一个地址，指向它引用的第一个元素——也就是 22 号元素的地址。

#### 用地址证明它确实指向 22

有同学肯定要问：老师，你怎么敢这么肯定 `slice` 里面有一个部分就是指向它的呢？

我可以这样证明——**因为要分析底层，就必须用指针来说话。** 因为 `slice` 的第一个元素就是指向 `intArr` 的第二个元素的，所以我把 `slice` 的第一个元素的地址输出来，你们会发现这两个地址是一样的：

```go
fmt.Printf("intArr[1]的地址=%p slice[0]的地址=%p slice[0]的值=%v\n", &intArr[1], &slice[0], slice[0])
```

跑一下就会发现：`intArr` 的第二个元素的地址和 `slice` 的第一个元素的地址**一模一样**，而且 `slice` 的第一个元素的值就是 22。这就证明了它们之间确实是相同的，这点不用怀疑了吧。

#### 第二、三块：长度与容量

那 `slice` 后面还有两个部分存什么呢？一个是存放这个 `slice` 的**长度**，这个大家都知道，它就是 2；还有一个部分存放 `slice` 的**容量**，capacity 等于 4。

所以在内存底层，`slice` 其实由三个部分构成：**一个是它指向的、或者说引用的那个数组元素的地址；第二个记录了 `slice` 本身的长度；第三个部分记录了 `slice` 容量的大小。**

#### 它其实就是三个字段组成的 struct

经常有人会问：那 `slice` 的数据结构是不是一个结构体啊？其实它已经是个结构体了。如果我们用一个结构体来说的话，`slice` 的结构体长这样：

```go
type slice struct {
    ptr *int   // 指针，指向引用的起始元素
    len int    // 长度
    cap int    // 容量
}
```

它里面至少有三个成员：一个就是 `ptr`，这是个指针，根据实际情况不一样，它指向的指针类型是不一样的；还有一个成员叫 `len`，这是一个 `int` 类型；还有一个就是 `cap`（容量），也是 `int` 类型。你可以理解成 slice 它就是这么一个数据结构。

> **结论**：所以**第一点，`slice` 的确是一个引用类型**——我们总是说它是引用类型，就是因为它引用到了一个地方。第二点，**`slice` 从底层来说其实就是一个 `struct` 结构体**，里面包含三个部分：一个指针、一个切片的长度、一个切片的容量。理解透彻这一点，比原先就透彻得多了。

顺带回答一个常见疑问：`slice` 本身有没有地址？有。`slice` 本身也有一个地址，你完全可以取出来——相当于上面高亮的那块空间本身还有一个空间，因为只有空间才能存放这些数据。只是说它的空间里有一部分是用来存放地址的，这个空间的地址我就不打印出来了。如果你们有兴趣，还可以把 `slice` 本身的地址打出来，它就相当于这个地方。

#### 引用类型的直接后果：改切片就是改数组

那大家问一个问题：如果我通过切片把 33 修改成 34，请问这个数组本身有没有变化？

**必然变化。** 因为它是引用啊。如果你连这块都还没看出来，那我这块就白讲了。

我们可以试一下。`slice[1]` 大家看这张内存图，它相当于找到第一个元素、再找第二个元素，就是找到 33 了——下标为 0 的才是第一个元素，下标为 1 已经是第二个元素了。我把它改成 34：

```go
slice[1] = 34
```

这样一修改过后，是不是就相当于把 33 改成了 34？那数组本身和这个切片取到的值是不是都发生了变化？因为它是引用类型。

不信的同学可以把它再输出一次，跑一下就会看到：**`int` 数组的 33 变成了 34，而 `slice` 本身的元素也变成了 34。**

所以我们说 slice 这个切片的**应用效率其实还是蛮高的**——因为它是引用，它并不是像数组那样做一个值拷贝，注意这个地方的特点。

最后顺一下这个引用的走向：**它引用到哪里取决于你这个地址，而这个地址又是取决于你给的第几个元素**——也就是取决于起始下标给的是第几个。引用到哪里取决于它找到的那个数组引用位置，但这个地址到底是多少，完全取决于你这个起始的下标。

只要把这张图记住了，关于数组和切片的底层就理解到位了。

### 用 make 创建切片

切片一共有三种使用方式，这三种要求同学们都必须掌握：

1. 定义一个切片，让它去**引用一个已经创建好的数组**——就是前面那个 `slice := intArr[1:3]` 的案例，这个已经讲过，就不再举例了；
2. 通过内置函数 **`make`** 来创建切片；
3. 在定义切片的时候**直接指定具体的数据**。

先说第二种。

#### 基本语法与手册里的说明

```go
var 切片名 []type = make([]type, len, [cap])
```

`make` 后面有三个参数要填：第一个参数是切片的类型；第二个是切片的大小，就是它的 `len`；第三个参数是你指定这个切片的容量。

手册里对 `make` 的说明是：**内建函数 `make` 分配并初始化一个类型为切片、映射或通道的对象。** 也就是说，`make` 不但可以创建切片，还可以创建 `map` 或者通道。

下面还写得很清楚：`size` 指定了长度，**该切片的容量等于其长度**；切片支持第二个整型参数用来指定不同的容量。

> **提示**：如果你指定了容量，它必须不小于其长度——容量必须至少大于等于长度。这很好理解：你容量为 2、长度为 3，这怎么可能呢？所以手册上写的 `make([]int, 0, 10)` 是什么意思呢？就是分配一个**长度为 0、容量为 10** 的切片：长度为 0 表示目前里面还没有一个元素，但它的容量现在最多可以放 10 个。

#### 一个必须 make 后才能用的切片

举个完整的例子。我们新建一个 `slice_use` 文件夹，写 `main.go`：

```go
package main

import "fmt"

func main() {
    var slice []float64

    fmt.Println(slice)
}
```

先注意一个细节：**如果你这是一个数组，这样直接定义就可以用了；但如果是切片，你不 `make` 直接用要出问题。对于切片而言，必须 `make` 后才能使用。** 大家说"老师，我这儿定义一个切片，我直接用"——你直接用试试看有什么后果？

运行一下，你会看到什么都没有。**对，因为这是空的，没有任何东西。**

那我们 `make` 一下就不一样了。`make` 的时候先把数据类型写在第一个参数，第二个参数给它分配 `len` 是 5 个大小，容量为 10：

```go
var slice []float64 = make([]float64, 5, 10)
```

再输出一次，你就能看到**有 5 个元素了，而且 5 个元素都为 0**——因为你没给它赋值，默认就是 0。它的容量是 10，但目前因为你没给任何数据，所以这 5 个元素默认都为 0。

修改它一下：

```go
slice[1] = 10
slice[3] = 20
```

`slice[0]` 就是访问到切片的第一个元素，`slice[2]` 就是访问到切片里的第三个元素，运行一下，对应的元素的值就变成 10 和 20 了。

大小和容量也可以输出出来：

```go
fmt.Println("slice 的 size =", len(slice))
fmt.Println("slice 的 cap =", cap(slice))
```

跑起来：**5 是它的大小，10 是它的容量。**

#### make 出来的切片，底层数组对外不可见

那我们来画一下这段代码的内存图：

```text
   变量 slice (struct)
┌────────────────────────────────────────────┐
│ ptr = 0xc000...  ────────────┐              │
│ len  = 5                     │              │
│ cap  = 10                    │              │
└──────────────────────────────┼──────────────┘
                               ▼
   底层数组（对外不可见）
┌────────────────────────────────────────────┐
│  [0]=0    [1]=10   [2]=0   [3]=20   [4]=0   │
└────────────────────────────────────────────┘
   没有任何别的变量指向它
```

它还是指向一个包含 5 个元素的空间，元素分别是 0、10、0、20、0，指向的是第一个元素。

**此时此刻最大的不同在哪里呢？就是不会再有一个数组指向这个地方了。** 前面那个案例里，这块空间既可以通过 `slice` 去操作，也可以通过数组名 `intArr` 去操作；但当我们用 `make` 方式来做的时候，**这块空间的数据只能通过 `slice` 来进行访问**，那个数组对外是不可见的。

> **结论**：也就是说，程序员只能通过 `slice` 去操作它，而不能通过数组名去操作了。你原先那个空间既可以通过切片操作、又可以通过数组操作；而现在我们内部这个数组其实是对外不可见了，只能通过切片在底层维护。

对 `make` 方式做个小结，三点：

1. **通过 `make` 方式创建切片，可以指定切片的大小和容量**；
2. **如果没有给切片的各个元素赋值，那么默认就会使用默认值**：`int` 类型、`float` 这个系列的统统都是 0；数组类型是 `string` 的，默认是空字符串；`bool` 类型的，默认是 `false`；
3. **通过 `make` 方式创建的切片，其对应的底层数组是由 `make` 在底层维护的，对外不可见**，你现在只能通过 `slice` 去访问各个元素。

### 定义时直接指定具体数据

第三种方式：在定义一个切片时，就直接指定具体的数据，原理类似于 `make`。

```go
var strSlice []string = []string{"tom", "jack", "mary"}

fmt.Println("strSlice=", strSlice)
fmt.Println("strSlice size=", len(strSlice))
fmt.Println("strSlice cap=", cap(strSlice))
```

写完了，你爱写多少就写多少。

运行一下，数据就这么多了。它的 size 肯定是 3，这个好理解。那 `cap` 是多少呢？因为你没有指定它的大小、没有给它指定 `cap`，所以它也是等于 3。这个无所谓，我们现在还没有讲细节，还是讲的一些基础的东西；细节的时候我们还会告诉大家这个 `cap` 到底会怎么自动地增长。

> **结论**：为什么要把这三种方式都介绍呢？因为你将来在工作中，这三种方式都有可能用到。后面我们都有项目，基础如果没有打牢，项目理解起来肯定到不了位；没有这些最本质的东西支撑，你写代码肯定到不了位，要么效率比较低下，要么就是自己也不知道为什么这么写。**项目本身并不难，只要把老师讲的这些东西都理解了，看一个项目跟玩似的。** 所以不管是哪个大学，真正好的大学、真正好的公司，别人问的就是你最底层的东西——像百度或者像谷歌，一般来说都是问算法、底层的东西偏多。基础只要牢了，包括后面讲的项目，听起来就是非常轻松的一件事情。

## 切片的细节收尾：两种建法之别、遍历、append 与 copy
> 对应块：BLK56 | 覆盖分集：P156-P159 | 块标题（分集名）：《155_尚硅谷_使用切片的区别分析》

前面我们把切片的内存布局和使用方式讲完了，这一讲把剩下的细节收掉：方式一和方式二到底差在哪、切片怎么遍历、以及 `append` 和 `copy` 这两个内置函数到底在干什么。

### 方式一和方式二的区别：这是个高频面试考点

先把前面讲过的两种使用方式的区别总结一下，因为这是一个**经常用来做面试的考点**——一定会有面试官问你，看你有没有用过、有没有理解这里的区别。

**方式一是直接引用一个数组。** 切片里面有三个部分：第一个部分指向了它所引用数组的第几个元素的地址，后面是长度和 capacity。而方式一还有一个特点：**这个数组是事先存在的，程序员是可见这个数组的。**

**方式二是通过 `make` 来创建切片。** `make` 也会创建一个数组——也就是说 `make` 本身它仍然是创建了一个数组，只不过这个数组是由切片在底层维护的，**这个数组没有名称，程序员是不可见的。**

```text
   方式一：引用已存在的数组

   slice ──┬─ ptr ──► intArr[1] 的地址
           ├─ len = 2
           └─ cap = 4

   intArr (程序员可见，可直接访问)
   [ 11 ][ 22 ][ 33 ][ 66 ][ 99 ]
         ▲
         └── ptr 指这里


   方式二：make 出来的切片

   slice ──┬─ ptr ──► 内部数组的第一个元素地址
           ├─ len = 4
           └─ cap = 4    ← len 与 cap 相同

   [ 0 ][ 0 ][ 0 ][ 0 ]     newArray（无名称，对外不可见）
   ▲
   └── 只有通过 slice 才能取到
```

`make` 一个 `int` 这样的切片，4 是它的 length。这时候它的 length 和 capability 是一样的。里面的指针指向哪里呢？应该是指向第一个元素——因为不存在"切到第几个元素"的问题，默认情况下肯定是指向数组空间的第一个元素。但你要把这个数组元素的地址打出来，**你只能通过 slice 来取**。

> **结论**：所以从这里我们可以看出来它的区别，说白了就两点：**第一，方式一的数组已经存在，程序员可见；第二，方式二是 `make` 帮你创建数组、由底层维护，程序员不可见**，你要访问 `make` 出来的数组里面的元素，只能通过 slice 来访问。

面试官问到你这个问题，你就这么回答：方式一是直接引用数组，数组已经存在，程序员可以通过数组和切片都来访问这个数组；方式二通过 `make` 创建切片，也会创建数组，但这个数组由底层维护、程序员不可见，要访问这里面的数据只能通过切片访问。只要这样回答就可以了。

### 切片遍历：两种写法，结果完全一样

切片遍历有两种方式：**第一种是常规的 `for` 循环遍历；第二种是用 `for-range` 遍历。** 分别举个例子。

老规矩新建一个 `slice_for_range` 文件夹，写 `main.go`。先创建一个数组，然后让切片去引用它：

```go
package main

import "fmt"

func main() {
    var arr [5]int = [...]int{10, 20, 30, 40, 50}
    slice := arr[1:4]
```

`slice` 引用 1 到 4——注意是不包含 4 的，所以它的元素应该是 20、30、40 这三个。

第一种，常规的 `for` 循环：

```go
    for i := 0; i < len(slice); i++ {
        fmt.Printf("slice[%v]=%v ", i, slice[i])
    }
    fmt.Println()
```

`i` 从 0 开始，`i < len(slice)`，然后 `i++`。两个 `%v`：第一个是它的下标，第二个是它的值，值用 `slice[i]` 取。每取一次给它来一个空格。

跑一下，取出来是 **20、30 和 40**，完全正确。

第二种，`for-range`：

```go
    for i, v := range slice {
        fmt.Printf("i=%v v=%v\n", i, v)
    }
```

这个跟以前学的是一样的。`i` 你想要就保留，不想要可以用下划线；值写成 `v` 简单一点；`range` 后面跟 `slice`。每打印一个我们来个换行。

跑一下，两种方式遍历出来的结果是一样的：第一种是 20、30、40；第二种下标为 0 对应的值是 20，下标为 1 对应 30，下标为 2 对应 40，完全没问题。

> **结论**：切片的遍历其实跟数组是一样的，所以这块并没有什么难度，也没有什么特别需要注意的地方。我只强调一点：如果你在遍历切片的时候只想要 `v` 不想要 `i`，那么这个 `i` 可以用个下划线，`v` 也是同样的道理。

### 切片的区间写法与越界

#### 左闭右开，以及三种可以省略的写法

切片初始化的时候，用我们说的第一种方式——让一个切片直接引用一个已经存在的数组——它应该有两个参数：第一个叫 `startIndex`，比如我们前面用的 1；还有一个叫 `endIndex`。

它是**从 `array` 这个数组下标为 `startIndex` 取到下标为 `endIndex` 的元素，但不含最后这一个元素**。这一点前面已经提到过，这里不再举例。

引用的写法有几种可以简写的情况：

- 如果你的起始值 `startIndex` 是 0，`array[0:end]` 可以简写成 **`[:end]`**——前面不写，默认就是 0；
- 如果后面那个是 `len(array)`，也就是你要从这个位置取到这个数组的最后一个——因为大家知道 `len` 是数组的长度，不包含这个数组长度就相当于把整个数组后面全部取光——这种 `array[start:len(array)]` 可以简写成 **`[start:]`**，后面这个不用写了，因为后面这个值默认就是数组的长度；
- 如果你需要有一个切片，把这个数组从第 0 个元素引用到它的最后一个元素，两边都不写就行：直接简写成 **`arr[:]`**。因为默认前面是 0，默认后面是 `len(array)`。

举个实际的例子体会一下：

```go
slice := array[:]
```

从 0 开始取，把整个数组全部取过来——从 0 取到这个数组的最后一个，全部取过来。这时候我们遍历一下看效果，可以看到它把 5 个元素都取出来了。**这种写法你也可以直接简写成 `arr[:]` 这种形式**，很多项目里面就是这样写的，前后两头都使用默认值。

#### 越界还是越界：index out of range

第二点：**切片初始化时仍然不能够越界。** 在用的时候，默认情况下这个切片该怎么用还怎么用，它的使用范围仍然是 0 到指向数组的大小之间；后面我们讲到它可以动态增长，只有动态增长以后，才能去使用后面的数组。

打个比方：`1:4` 这个写法，大家都知道第四个元素其实你没有取到、没有引用到，你就不能这么用。

假设这个切片由 `array[1:4]` 得到，一共有 3 个元素，那么下标 0 可以取到、1 可以取到、2 可以取到，**但你不能取到第三个元素**——如果是下标 3，那就相当于越到 `array` 末尾之后的那个元素了，因为你引用的时候只引用到 `array` 的这一段，根本没有引用到它。

跑一下试试，它仍然会报 `index out of range`，是第 23 行报错。因为你引用的时候没有引用到人家最后这一个，所以这样用肯定要报错。**它默认仍然不能越界，这点请大家注意。**

#### 刚定义还不能用，但可以再切

还有一点：`cap`（capacity）是一个内置函数，用于统计切片的容量，也就是最大可以存放的元素个数，这个前面已经说过了。

另外，**切片定义完毕以后还不能使用**，因为它本身是个空的，需要让它引用到一个元素，或者 `make` 过以后才能使用。你定义完一个切片过后，要么引用到一个数组去，要么 `make` 一个空间来供切片使用，否则它是个空的，没办法用。

那如果切片已经是切片了，还能怎么办？**切片可以继续切片。**

```go
slice2 := slice[1:2]
```

我不从数组切，我直接从切片切。请问这时 `slice2` 是什么东西？它也是个切片。它里面有哪些元素呢？如果这样切，相当于在原先这个切片上再切了一个元素出来——原先 `slice` 的下标 1 切到下标 2，但不包含 2，输出的是 **20**。

我告诉你，`slice2` 也好、`slice` 也好，**其实它们都指向同一个数据空间**。也就是说 `slice2` 改变了，`slice` 也会变化，同时这个数组也会变化——因为它们都是引用类型的。

那如果我把这里改成 `2:4` 呢？那就是在原先 `slice` 的基础上，下标为 2 的再取，取到第 4，切出来的就是 **30、40**。跑一下测一下，果然如此。

我再问大家最后一个问题：如果我把 `slice2` 的第 0 个元素改成 100，请问 `slice` 还有 `array` 对应的这个值变不变？

**也会发生变化。** 也就是说 30 这个值，不管是通过数组来看还是通过 slice 来看，都会变成 100。因为 `array`、`slice` 还有 `slice2` 指向的数据空间是同一个，因此 `slice2` 改变了，其它都会变化。如果你输出 `slice2`、包括 slice、包括我们的数组，对应的 30 全部都变成了 100。

> **结论**：这里要特别体会的一点是：**因为切片是引用类型，所以当一个切片的元素发生变化，会直接影响到它关联的数组以及其他切片的数据变化。** 它们指向的数据空间其实是同一块空间，只是引用的具体位置不一定相同。

### append：动态增长的真正机制

接下来是 `append` 这个内置函数，用得也比较多。还记得前面说过的吗？切片有一个特别重要的功能、特性——**它可以动态地增长**，而这个特性用到的主要函数就是内置函数 `append`。

手册里的说明是：**内建函数 `append` 将元素追加到切片的末尾。** 它还说，如果它有足够的容量，它就会重新分配切片以容纳新的元素；否则就会分配一个新的底层数组。也就是说，**`append` 就可以用来扩容。**

先看一个最简单的：

```go
var slice3 = []int{100, 200, 300}
fmt.Println("slice3", slice3)
```

运行一下，现在这个切片是 100、200、300。那如果我们现在需要在这后面再追加一个 400，怎么做呢？用 `append` 直接给 `slice3` 追加。

当然这个元素的值要跟这个类型保持一致——它是一个 `int` 类型的，你就不能给它追加一个 `float`，那肯定违反了数据类型要匹配的原则。

#### 不接住返回值，等于白干

第一种写法，直接追加：

```go
append(slice3, 400)
```

也可以一次性追加多个，比如 400、500、600：

```go
append(slice3, 400, 500, 600)
```

跑一下，这有问题——它说你没有用过这个。这个是必须接收一下才可以，你不接收不行。

为什么？因为 **`append` 追加完了过后，`slice3` 本身是没有变化的**。它在追加的时候，实际上是内部做了一个分配、创建了个新的数组来追加的，然后在 `slice3` 追加了三个元素过后，**把这个新追加的东西返回出来**。因此你要接收，你不接收的话，`slice3` 还是没有变化。

假设我们用一个新变量来接收：

```go
slice4 := append(slice3, 400, 500, 600)
```

跑一下你会看到：`slice4` 变成 100、200、300、400、500、600；**但是 `slice3` 其实仍然还是前三个元素**。它本身没变化，只是把追加过后的东西重新返回一个结果给新变量。

但是我们其实需要的效果就是要改变 `slice3`，对不对？这样做就没有意义。因此一般情况下，我们直接把这个新的再重新赋给 `slice3`：

```go
slice3 = append(slice3, 400, 500, 600)
```

这样子就对了，`slice3` 就真正相当于扩容了。跑一下，`slice3` 现在就是最新的数据。

> **易错点**：注意这个细节——**`append` 的返回值一定要接住，并且要接回原来的那个切片名**，否则原来的切片一点没变。

#### 追加自己：slice3 = append(slice3, slice3...)

有些同学还看到有人这样用：`append` 后面直接追加一个切片，可不可以？可以。比如我在 `slice3` 这个基础上这样追加：

```go
slice3 = append(slice3, slice3...)
```

这种方式是什么意思呢？就是把切片再追加到这个切片自己身上——通过 `append` 函数，将切片 `slice3` 追加给 `slice3`，相当于自我增长。

那它会变成什么样呢？是不是相当于它原先已经是这些了，再重新复制一份？**12 个元素了**，对不对？跑一下。

效果跟我想的一样：它在自己基础上又追加了一份。注意后面这个 `slice3` 其实也可以是别的切片，追加别的切片也是可以的。我这里故意用相同的切片，就相当于自己追加给自己。

> **提示**：而且这三个点是固定的写法。**后面这个必须是切片，不能是数组**；这三个点必须带上，别把这三个点忘了——这是我们规定的一种写法，大家记住这个细节就行了。

#### append 底层到底干了什么

`append` 用得非常的多，大家一定要把它的底层机制搞清楚搞明白，不然别人稍微问你一下，你就搞不清楚了。

**第一，切片 `append` 操作本质就是对数组扩容**，这个没什么可说的，原先少了你可以增加几个。

**第二，Go 底层会创建一个新的数组**，然后把新数组扩容过后再重新赋给这个新的切片——具体来说，它会**把 slice 原来包含的元素拷贝到新的数组中**。也就是说它会先创建一个新的数组，这个数组的大小就是按照扩容过后的大小来创建；然后再把准备追加切片的内容先拷贝到这个新数组里面去；然后再让这个 slice 重新引用到这个新数组里面去。

**注意，这个 newArray 是在底层维护的，程序员是看不到的。** 它在最底层怎么去进行这个扩容、创建新的数组，我们程序员不用关心。

如果一定要画个图来说的话，我以追加具体元素为例，就以 `append(slice3, 400, 500, 600)` 这句来分析：

```text
  执行之前
     slice3 ──► [ 100 | 200 | 300 ]          len=3, cap=3


  执行之中（append 的四步）
   1) 先创建一个新数组，默认全部填 0
        [ 0 | 0 | 0 | 0 | 0 | 0 ]           newArray，底层维护
   2) 把 slice3 原有的元素拷贝过来
        [ 100 | 200 | 300 | 0 | 0 | 0 ]
   3) 再把新增的元素拷进去
        [ 100 | 200 | 300 | 400 | 500 | 600 ]
   4) 把这块新数组的首地址返回给调用方，len 变成 6


  执行之后
     slice3 ──► [ 100 | 200 | 300 | 400 | 500 | 600 ]
                   ↑
                   └─ 原来的旧数组已没有任何变量引用
                      → 变成垃圾 → 被回收
```

关键就在于**你把返回的这个新数组交给谁**：

- 如果你交给 `slice3`，那这个指针就会直接指向新数组这边去；一旦指向这边，原先 `slice3` 指的那个就没有了，相当于是扩容了一样，`len` 和 `cap` 也都会变成 6；
- 如果你把它交给一个 `slice4`，它就会产生一个新的 `slice4`，让 `slice4` 指向这个新空间。**那样的话 `slice3` 还是 `slice3`，`slice4` 指向一个新的空间。**

所以关键是看你把 `append` 过后返回的这一个数据交给哪个变量。如果你交给 `slice3`，它就指向这边来；如果你交给的是一个新的变量，那新的变量指向它，**原先那个仍然是没有发生任何变化的**。

如果按照我们代码来说，示意图实际上就是没有 `slice4` 的事了，它直接让 `slice3` 指向这个新空间。当然，因为这个旧空间已经没有任何变量引用了，那谁会做这个事情呢？这个空间就变成**垃圾了，就会被回收**——因为没有任何变量引用它，它其实已经用不了了。

### copy：两个独立空间之间的搬运

接下来是切片的拷贝操作，用的是另外一个内置函数叫 `copy`。

举个完整的例子：

```go
package main

import "fmt"

func main() {
    var slice4 []int = []int{1, 2, 3, 4, 5}
    var slice5 []int = make([]int, 10)

    copy(slice5, slice4)

    fmt.Println("slice4=", slice4)
    fmt.Println("slice5=", slice5)
}
```

先看 `slice5`：它是用 `make` 创建的一个切片，大小是 10。我们没有给它值，默认是不是全部都是 0？**一共有 10 个 0。** 打印出来肯定是 `1 2 3 4 5 6 7 8 9` 后面还有一个 0，一共 10 个 0。

然后 `copy(slice5, slice4)` 是什么意思？就是**把 `slice4` 的数据拷贝给 `slice5`**。

注意，原先的 `slice4` 自己是有一个空间的，它是 1、2、3、4、5；`slice5` 也有自己的一个空间。**这两个空间是独立的——你有你的空间，我有我的空间，这两个不打架。**

然后 `copy` 就把 `slice4` 里面的数据拷贝到 `slice5`：它会把 1、2、3、4、5 分别拷贝给对应的位置，那边变成 1、这边变 2、这边变 3、这边变 4、这边变 5。那后面这几个怎么办呢？保留原值就行了——**因为你只有 5 个拷贝给它们，后面还有 5 个没被拷贝到，那就保存原来的值，还是 5 个 0。**

跑一下，结果跟分析的一模一样：`slice4 = [1 2 3 4 5]`，`slice5 = [1 2 3 4 5 0 0 0 0 0]`。

它们是独立的空间。那我问大家一个问题：**我修改 `slice4` 的元素，会对 `slice5` 有没有影响？**

> **结论**：显然是没有变化的，因为它们是独立的空间，它们数据是独立的。这点大家一定要注意，**它们之间的数据空间是独立的**。

对这段代码有几点要整理一下：

1. **在进行拷贝时，要求这两个参数都是切片。** `copy(para1, para2)`，这两个参数的数据类型都必须是切片类型；
2. **按照上面这个案例来说，`slice4` 和 `slice5` 的数据空间是独立的，相互不会影响。** 也就是说如果我把 `slice4[0] = 999`，那么 `slice5[0]` 仍然是 1，并没有发生变化。

注意听这个细节，`slice5[0]` 仍然是 1，我不会受你的影响。

## 切片的最后两处细节，以及 string 为什么也能切片
> 对应块：BLK57 | 覆盖分集：P160-P161 | 块标题（分集名）：《159_尚硅谷_切片注意事项和细节(3)》

切片的注意事项讲到这儿，其实就剩最后两块了：一块是拷贝时的长度问题，一块是引用传递机制。这两块讲完，切片这块就算彻底收尾。收尾之前，我们顺手再把 `string` 和切片的关系也一并捋一遍——因为 `string` 这个类型，本质上就是"不能随便改"的一种切片。

### 拷贝时长度不一致，到底会不会出错

先看一道练习题。这段代码有没有错误？

```go
var a []int = []int{1, 2, 3, 4, 5}
var slice = make([]int, 1)
fmt.Println(slice) // [0]
copy(slice, a)
fmt.Println(slice) // [1]
```

代码是**正确的**，能跑，而且不会报任何错。

`a` 有五个元素，`slice` 只 `make` 了一个，长度是 1。第一次打印时它还没被赋值，所以输出 `[0]`——`make` 的时候大小为 1，又没给它赋值，那个位置当然是零值。

关键在 `copy`。很多同学到这里会紧张：`slice` 只有 1 个位置，`a` 有 5 个，往里拷的时候会不会因为"大小不够"报错？

不会。`copy` 的规矩是——拷过去的空间不够，拷能拷的那些，剩下的直接放弃，**既不报错，也不 panic**。所以 `a` 的第一个元素 `1` 被拷进了 `slice`，第二个元素 `2` 需要两个空间，而 `slice` 只有一个位置，拷不进去，就到此为止。最终 `slice` 输出 `[1]`。

> **结论**：`copy` 无论目标比源大还是比源小，都不会报错。大了会截断，小了会少拷。

这是关于拷贝的第八个细节，也是我们这道练习题的全部内容。千万不要因为长度对不上就怀疑代码写错了，放心去试。

### 引用传递：一次赋值，三方看到同一个数组

接下来是切片的第二个细节：**切片是引用类型**。所以无论是普通的赋值，还是作为参数传给函数，它走的都是引用传递机制。我们分两段代码来看。

#### 两个切片变量共享同一个底层数组

```go
package main

import (
	"fmt"
)

func main() {
	var slice []int
	var arr [5]int = [...]int{1, 2, 3, 4, 5}
	slice = arr[:]
	var slice2 = slice
	slice2[0] = 10

	fmt.Println("slice2=", slice2)
	fmt.Println("slice=", slice)
	fmt.Println("arr=", arr)
}
```

先把脉络理清楚：先声明一个切片 `slice`；再声明一个整型数组 `arr`，有 `1、2、3、4、5` 五个元素；接着用 `slice = arr[:]` 让切片指向这个数组；然后 `var slice2 = slice`，这一步之后 `slice` 和 `slice2` 就都指向了同一个 `arr`。最后通过 `slice2` 把第 0 个元素改成 10。

那么三个打印分别是什么？

```text
slice2=[10 2 3 4 5]
slice=[10 2 3 4 5]
arr=[10 2 3 4 5]
```

**三个全是 `[10 2 3 4 5]`**。因为 `slice` 和 `slice2` 指向的是同一个数组，通过谁去改都是改那一块内存，所以 `arr` 的第一个元素也跟着变成了 10，后面的 2、3、4、5 没人动，还是原样。

新建一个 `slice` 的测试文件夹，新建 `main.go`，把上面这段放进去跑一下，输出跟分析完全一样。

#### 切片作为实参传给函数

第二段是同一个机制的另一个体现：

```go
package main

import (
	"fmt"
)

func test(slice []int) {
	slice[0] = 100
}

func main() {
	var slice = []int{1, 2, 3, 4}
	fmt.Println("slice=", slice)
	test(slice)
	fmt.Println("slice=", slice)
}
```

运行结果：

```text
slice= [1 2 3 4]
slice= [100 2 3 4]
```

调用 `test` 之前先打印一次，是 `1 2 3 4`；调完 `test` 之后再打印一次，变成了 `100 2 3 4`。

原因还是引用传递。`test` 的形参 `slice` 接到的其实是一个地址，它和外层主函数的实参 `slice` 是同一个东西，可以想象成同一块内存空间。里面的切片指着外面那个切片，所以在函数内部做的修改会直接影响实参——这里把 `slice[0]` 改成了 100，外面的实参也就跟着变了。

> **易错点**：形参和实参是两个名字，但当实参是切片时，它们指向的是同一块底层内存。函数内部对元素的修改会"逃逸"出来；但如果函数内部只是给形参重新赋值（`slice = ...`），那改的只是形参自己，外面的实参不受影响。

所以，切片这块要注意的东西就归拢成两条：一条是拷贝时的长度容错，一条是传递时的引用共享。

### string 为什么也能切片

接下来说 `string` 和切片的关系。为什么非要专门讲这个？

因为 **`string` 这个数据类型的底层是一个 byte 数组**。既然是 byte 数组，那它自然就可以进行切片处理操作。我们来看一个例子。

假设现在有这样一个字符串：

```go
str := "hello@atguigu"
```

现在我想把 `@atguigu` 这一块取出来，怎么做？用切片，一行就够：

```go
slice := str[6:]
fmt.Println("slice=", slice)
```

输出就是 `@atguigu`。

为什么是 `6`？来数一数，`hello@atguigu` 里 `@` 是第几个元素——1、2、3、4、5、6，第 6 个是 `o`，那 `@` 就是第 7 个元素。第 7 个元素的下标是 6，下标是从 0 开始的，所以写成 `str[6:]`。

后面为什么可以不写？因为切片里后面采用默认值时，表示"把后面所有的部分全部切过来"，一直到字符串末尾。

> **提示**：字符串下标和切片下标一样是从 **0** 开始的。数元素个数的时候容易多算一位，`@` 是第 7 个字符，它的下标才是 6。

把代码 `cd` 到刚才写的 `stringslice` 目录下，`go run main.go` 跑起来，`@atguigu` 就切出来了。以后想对字符串做截取——从第几个字符到第几个字符——都可以直接用切片的方式来完成。

### string 在内存里长什么样

第二个要看的，是 `string` 和切片在内存中的存在形式。我们拿 `"ABCD"` 这个字符串画个内存示意图。前面切片的内存布局我已经画过好几个了，这个就不从头画了，直接看结论：

```text
     底层 byte 数组（字符串 "ABCD" 的真实存储）
        +------+------+------+------+
   0x0001|  A   |  B   |  C   |  D   |
        +------+------+------+------+
          ^              ^
          |              |
          |              +--- 指向第 2 个元素 B
          |                   len = 2（内容是 B、C）
          +--- 指向首地址 0x0001
                len = 4（内容是 A、B、C、D）

   str   = [ A  B  C  D ]
   slice = [    B  C    ]      // 从第 1 个到第 3 个
```

读这张图：`"ABCD"` 本身就是一个 byte 数组。如果它是一个 `string` 类型的变量，那么它内部同样有一块这样的结构——一个指向 `"ABCD"` 首地址的指针，再加上表示这个数组长度的 `len`。（图上那个 `0x0001` 是我随便写的示意地址，真实地址肯定不是这个值，重点是它指向 byte 数组的开头。）

大家看这个结构眼熟不熟悉？它有指针、有 `len`——这不就是切片的头两个字段吗？

同理，如果有一个切片是从这个 string 的第 1 个到第 3 个取出来的，那它的指针指向的就不再是数组首地址，而是**第二个元素 B 的地址**；因为取的是 B、C 两个，所以 `len` 是 2。它后面还有 `cap`（容量）这一项，只是我这里没写出来，所以图上没画。

> **结论**：字符串的底层是一个 byte 数组，它本质上也是一个切片。正因为它是个切片，所以它也能享受切片的相关操作——上面那个 `str[6:]` 就是这么来的。

### 不可变的 string，和绕开它的三步套路

第三个细节：**`string` 本身是不可变的**。

所以你想通过下标去修改字符串，是要报错的：

```go
str[0] = 'z'
```

保存一下，编辑器立刻报错：`cannot assign to str[0]`——不可以给它赋值，编译不通过。

道理很清楚：`str[0]` 是 `'h'`，你想把它改成 `'z'`，但 `string` 是不可变的，你不能通过找到下标为 0 的位置把这个值改掉。以后要改一个字符串，千万不要这么写，写了就是直接给你报错。

那问题来了：老师，你说 string 不可变，可因为种种原因我就是要改这个字符串，那怎么办？我确实有这种需求，我就是想把 `'h'` 改成 `'z'`，难道就没有别的办法了吗？

有办法。这就说到第四个细节了。注意听，如果需要修改字符串，步骤是这三步：

- **第一步**，先把字符串转换成一个 byte 切片——注意是**切片**，不是数组。也可以转换成 rune 切片。
- **第二步**，修改。因为已经是切片了，所以可以随便改。
- **第三步**，修改完之后，再重新转回字符串。

也就是说它稍微麻烦一点，但没办法，因为字符串本身不可变。在 Go 语言里要改变它，就只能想这个别的招：**先转成切片，改完，再转回去**。

```go
// 我们想把 "hello@atguigu" 改成 "zello@atguigu"
arr1 := []byte(str)
arr1[0] = 'z'
str = string(arr1)
fmt.Println("str=", str)
```

一步一步看套路：先转成一个 byte 切片 `arr1`；这时它已经是切片了，访问到它的第 0 个元素，给它一个值 `'z'`——因为它是 byte 切片，给 `'z'` 没问题；改完之后，通过 `string(arr1)` 再转回字符串，然后输出。

跑起来一看，`str` 变成了 `zello@atguigu`，第一个 `'h'` 变成了 `'z'`。这就完成了。这块用法其实挺多的。

### byte 切片改不了中文，得换成 rune

但上面这个办法，还有一个细节要注意：**它能处理英文和数字，但不能处理中文**。

原因是 byte 是按一个字节来计算的，而一个汉字要占 3 个字节，所以一换成中文就会出问题。

来验证一下。把上面那段代码粘贴过来（为避免跟上面冲突，先把之前那段注销掉），然后把第 0 个元素改成一个中文，比如北京的"北"：

```go
arr1 := []byte(str)
arr1[0] = '北'
```

一保存就直接报错了，根本过不去。为什么？

因为这个汉字的编码是 21271，而 `byte` 的范围大家都知道，只有 0 到 255。你把一个 21271 塞进去，直接就越界了，编译都过不去。

> **提示**：`byte` 是 `uint8` 的别名，只能表示 0–255 的无符号数。中文的 Unicode 码点（比如"北"是 21271）远远超出了这个范围，所以编译期就会拦下来报 `constant 21271 overflows byte`。

那怎么办呢？好办：**把 `[]byte` 换成 `[]rune` 即可**，就这么一点小技巧。

```go
arr1 := []rune(str)
arr1[0] = '北'
str = string(arr1)
fmt.Println("str=", str)
```

为什么 `rune` 就能解决？因为 `rune` 是兼容中文的，它是**按字符来计算**的，一个汉字就是一个 `rune`，所以可以处理、兼容汉字。

保存一下，这次不报错了；执行一下，`'h'` 就变成了"北"。

> **注意**：转换的类型要跟着数据走——要改的是中文，就转 `[]rune`；要处理的是二进制编码，还是得转成 `[]byte`，然后再进行数据的传输或者处理。如果数据里有汉字，在显示的时候用 `rune` 切片。

大家注意听，这个细节一定要小心。整个方案其实就是一句话，大家记牢：

> **结论**：以后要对字符串进行修改或处理，就直接把它转成 `rune` 切片，改完过后再转回去；如果处理的是二进制数据，那就还是转 `byte`。就这么一点小技巧，理解这个意思就行。

## 从斐波那契切片练习，到手写一遍冒泡排序
> 对应块：BLK58 | 覆盖分集：P162-P165 | 块标题（分集名）：《161_尚硅谷_切片的课堂练习》

切片的注意事项讲了那么多遍，今天终于可以做练习题了。做完这道题，切片这块就算彻底收尾；然后我们正式开一个新章节——排序和查找。这一章的重点是**数组的排序和查找**，我们先把排序的基础概念交代清楚，然后把冒泡排序从"想明白"一路推导到"写出来"。

### 用切片把斐波那契装进去

先看课堂练习的题目要求：编写一个函数叫 `fbn`，传一个 `n` 进去，要求完成两个功能——

- 能接收一个 `n`，`int` 类型的；
- 能够将斐波那契的数列放入到切片中。

这里要抠一下字眼：题目说的是"将斐波那契的数列放入到切片中"，也就是说**每一个斐波那契数都要放进这个切片里**，不是只要最后一个。

题目还给了一个提示，说斐波那契数列的形式是：第一个元素为 1，第二个元素为 1，第三个元素为 2，实际上就是前面两个数的和；第四个元素为 3，为什么等于 3？因为前面两个数一个是 1、一个是 2，加起来就是 3；第五个元素为 5，就是 2 + 3；第六个元素为 8，是 3 + 5。

那用什么来做？**用切片最合适**。为什么不能用数组？因为声明数组的时候，数组大小就得当场确定下来；而切片可以在 `make` 的时候传一个变量进去进行空间分配。我们的 `n` 是运行时才知道的，切片天生就能对付这种情况。

#### 思路拆成三步

我们还是老规矩，一边写代码一边分析实现思路。新建一个 `exercise` 文件夹（练习的意思），新建 `main.go`。

**第一步，确定函数签名。** 编写一个叫 `fbn` 的函数，接收一个整数 `int` 参数，这没什么说的。但是斐波那契数列算完要放到一个数列里，是不是让它返回一个切片最合适？所以返回类型是切片。返回什么样的切片类型呢？大家都知道斐波那契的数会越变越大，所以我们给它一个能存放最大数值的类型——`uint64`。

**第二步，确定整体套路。** 题目要求把所有斐波那契都放到切片中，那就用 `for` 循环，一个 for 循环做完，所有斐波那契就都放到了对应位置。但里面有个特例：下标 0 和下标 1 对应的斐波那契数都是 1，这两个比较特殊，要单独提出来写死。

**第三步，确定边界。** 切片先声明、大小就是 `n`，因为你传了 `n`，我就给你 `n` 个斐波那契数。然后 `for i := 2; i < n; i++`——注意是 `i < n`，为什么不是 `i <= n`？因为 `n` 代表的是切片的大小，实际最大的下标是 `n - 1`。循环体就是那一句递推。

#### 代码和验证

```go
package main

import (
	"fmt"
)

/*
编写一个函数 fbn(n int)
要求完成下面的功能：
1) 可以接收一个 n int
2) 能够将斐波那契的数列放到切片中
3) 提示：斐波那契的数列形式：
   fbn[0] = 1, fbn[1] = 1, fbn[2] = 2, fbn[3] = 3, fbn[4] = 5, fbn[5] = 8...
*/

func fbn(n int) []uint64 {
	// 声明一个切片，切片大小就是 n
	fbnSlice := make([]uint64, n)
	// 第一个数和第二个数的斐波那契数是等于 1 的
	fbnSlice[0] = 1
	fbnSlice[1] = 1
	// 通过 for 循环来存放斐波那契数列
	for i := 2; i < n; i++ {
		fbnSlice[i] = fbnSlice[i-1] + fbnSlice[i-2]
	}
	return fbnSlice
}

func main() {
	fbnSlice := fbn(10)
	fmt.Println("fbnSlice=", fbnSlice)
}
```

注意下面这行 `return fbnSlice`：因为切片是引用类型，返回回去的就是我们函数里边计算好的那个东西，没问题。


### 排序到底是什么：内部排序与外部排序

下面正式开一个新章节，叫**排序和查找**，这是第八章。

这一章重点介绍排序和查找。而且要先把范围划清楚：我们说的排序指的是**数组的排序**，查找也是针对数组的查找。

#### 基本概念

所谓排序，是指**将一组数据依指定的顺序排列的过程**。

排序又分成两大类：一类叫内部排序，一类叫外部排序。

**内部排序**，就是将要处理的所有数据都加载到内存中进行排序。它的排序工作不需要借助文件，一次性把所有数据放到内存里面去排就可以了。这种一般来讲数据量都比较小。比如我们常见的交换式排序法、选择排序和插入排序，这些都属于内部排序。

**外部排序**什么时候用？数据量比较大的时候。比如说我们要针对一千亿个数据、一万亿个数据进行排序，一次性加载到内存里加载不了，因为内存不够，这时就往往要借助外部存储来排序。

怎么借助外部存储呢？举一个合并的例子：先调一部分数据，把这一部分数据的顺序排好；再调第二部分数据，再排好；最后把这些排好的数据一次性地输出到文件里面保存起来，这时我们就会用到外部排序。

> **结论**：内部排序和外部排序最大的区别，就是**是不是一次性地把全部数据加载进内存**。内部排序一次性搞定，不需要借助外部存储；外部排序因为数据量过大，往往先加载一部分，排完再加载第二部分，最后合并起来——比如合并排序、直接合并排序法都属于外部排序。

#### 交换式排序，和冒泡的那句定义

编程里面排序的方法非常多。交换排序就属于内部排序，而交换排序里用得比较多的，一个是**冒泡排序**（bubble sort），还有一个是**快速排序**（quick sort）。它们为什么都属于交换排序？因为都是把数据加载进去，然后根据大小不一样来两两比较、交换位置。

冒泡是我们要求重点讲解的，所以今天就介绍这一个。

冒泡排序的基本思想是：通过对待排序序列**从后向前**（从下标较大的元素开始），依次相互比较相邻元素的排序码，**若发现逆序则交换**，使排序码较小的元素逐渐从后部向前移动，然后就像水泡一样向上冒。

因为排序过程中各元素不断接近自己的位置，所以**如果在一趟比较下来没有进行交换，就说明已经有序**。因此要在排序过程中设置一个 `flag` 标志，记录本趟有没有发生过交换，从而减少不必要的比较——这属于优化。

说实话这段定义写得特别不好。你听完之后会觉得"不知道它在说什么"。

所以我不打算硬着头皮往下讲，我们用一个案例把冒泡彻底讲透。

### 五个数走一遍，就知道它在冒什么

来看这个案例：现在有五个数据——**24、69、80、57、13**，我们用冒泡排序法把它们排成**从小到大**的数列。注意是"从小到大"，也就是排好之后第一个元素是最小的，最后一个元素是最大的。

> **提示**：很多同学面试的时候写不出冒泡排序，根本原因不是记不住代码，而是没有把冒泡的**本质规则**掌握到。你去招一个同学让他写冒泡，一层层问下去，最后会发现他是没搞清楚"冒泡到底是怎么玩的"。编程这件事其实一直在做同样的转换——你有一个思路、一个思想，然后把思想转成代码，这叫编程。语法从来不难，难的是思路。

那我们就用 Excel 表把这个规则一格一格画出来，边画边看。

我先在 Excel 上把数组摆出来：

```text
初始状态：  24   69   80   57   13
             ↑    ↑
             绿   蓝     ← 两个指针都从最前面开始
```

冒泡的核心其实就一句话：**经过不断地比较，把最大的数扔到最后面去，然后再找第二大的数放在倒数第二个位置，然后依此类推。**

#### 第一轮：把 80 送到最后

所谓第一轮，也就是我们说的外层排序第一次。

规则是：**让前面的数和后面的数比较，如果前面的数大，则交换。**注意只有"前面的大"才交换，前面不大就什么都不做。

- 第一次比较：`24` 和 `69`。24 不大于 69，不动。
- 第二次比较：`69` 和 `80`。69 不大于 80，不动。
- 第三次比较：`80` 和 `57`。80 大于 57，交换！
- 第四次比较：`80` 和 `13`。80 大于 13，交换！

两个指针每次比较完都往后挪一位。走到最后的时候，蓝色指针已经没必要再往后挪了——因为**经过第一轮的四次比较，80 这个数已经明明白白地定下来了**，它就是最大的数，被送到了最后一位。第一轮比较的结果是：找到了最大的数。

```text
第 1 轮（4 次比较）  24<69 不动 | 69<80 不动 | 80>57 交换 | 80>13 交换
                     24  69  57  13  80     ← 80 就位

第 2 轮（3 次比较）  24<69 不动 | 69>57 交换 | 69>13 交换
                     24  57  13  69  80     ← 69 就位

第 3 轮（2 次比较）  24<57 不动 | 57>13 交换
                     24  13  57  69  80     ← 57 就位

第 4 轮（1 次比较）  24>13 交换
                     13  24  57  69  80     ← 24 就位，全部有序
```

#### 第二轮：把 69 送到倒数第二

第二轮为什么要重新从最前面开始？因为每一轮都是从头扫的。

- 第一次比较：`24` 和 `69`。24 不大于 69，不动。但注意，80 已经定下来了，不再参与比较。
- 第二次比较：`69` 和 `57`。69 大于 57，交换。
- 第三次比较：`69` 和 `13`。69 大于 13，交换。

到这里就没必要再往后比了——因为 80 已经是最大的了，再去比较没有意义。**所以第二轮只进行了三次比较，就把第二大的数确定下来了。**

#### 第三轮和第四轮

第三轮建立在第二轮结束的基础上，又回到最前面开始：

- 第一次比较：`24` 和 `57`。24 不大于 57，不动。
- 第二次比较：`57` 和 `13`。57 大于 13，交换。

此刻已经没必要再往后挪了——69 已经定下来了，再比较很不划算。**第三个最大的数 57 就位了。**

第四轮也只比一次：`24` 和 `13`。24 大于 13，交换。第四个位置确定。至此 13 已经是最后一个了，还有比的必要吗？没有了。

### 从图里把规律捞出来

现在规律已经跃然纸上了。我们把它整理成三条：

> **结论**：五个数据，我们进行了**四轮比较**（外层循环），而且**每一轮的比较次数在逐渐减少**。

- **第一个特点**：外层一共比较了 `arr.length - 1` 轮，**每一轮确定一个数的位置**。
- **第二个特点**：每一轮的比较次数逐渐减少，是 `4、3、2、1` 这样递减。第一次四次，第二次三次，第三次两次，最后一次一次。
- **第三个特点**：**当发现前面的一个数比后面的一个数大的时候，就进行交换。**

说白了就这么一点点东西。有些书上把这个讲得特别复杂，可是如果没有那张图的支撑，我直接把这个抛出来，你们几乎不知道我在说什么。

所以我的建议是：**当我们在遇到比较复杂的问题时，可以适当地把这个东西写一写。**人的思维就是这样——写完了之后还是有点空空荡荡，搞得这东西还没深入到自己的血液里、灵魂里。根本原因是你现在还没有一个形象的思维。等到有一天你再看到这个排序，脑海里面就浮现出刚才那张图——那你恭喜你，整体的思维就很形象了。

我就经常跟同学们聊，做一个东西的时候一定要去想它的结构。比如我们说 HTTP 协议，"啪"一个协议过去了，我脑子里想的是：这边是一种什么形式在发，那边怎么接收，接收完了又做什么处理，最后怎么回来。整条线都很清晰，所以你做东西的时候不会觉得空洞。如果没有这个支撑，你就感觉很虚。不过这个需要咱们多练习。

### 先写里面，再写外面

有同学说，老师，你这个东西我思想有点感觉，但代码真的有点难写。

那我教你第二招。

**你先不要去管第几轮，现在先把第一轮给我写出来。**我只要求你做一件事：把这个数组里面最大的给我排过去。这个只需要一层循环，连双层循环都用不到，应该没问题吧？

我的思想就是这样：

- 第一步，先写一段代码能把最大的数排到最后；
- 然后再写第二段代码，把第二大的数排到倒数第二个位置；
- 然后以此类推。

> **提示**：这个"先里后外"的顺序很反直觉。我们平时看别人的代码，往往是**先写外层，再写里层**；但如果你按这个顺序从零开始想，你会发现思维刚好是卡住的。正确的顺序是**先写里面，再写外面**。有时候计算机的思维跟人的直觉是反的。

写完四轮你就会发现一个规律，然后找到规律，再把它整成一个双层 `for` 循环。这种思想你有了，会受受益无穷。

规则说完，下面就要把刚才做的这件事**翻译成代码**了，这就叫翻译。

### 把重复的四轮套进两层循环

新建章节 `chapter08`，在里面新建 `bubble` 文件夹——`bubble sort` 就是冒泡排序的意思——再新建 `main.go`。前面照旧 `package main`，因为要输出，引入最常用的 `fmt` 包。

数组先定下来，就用刚才那个五元素的：

```go
arr := [5]int{24, 69, 80, 57, 13}
```

然后我们把这个数组传给一个函数来完成排序。函数这样写：

```go
func BubbleSort(arr *[5]int) {
	// 因为数组是值类型，所以在函数里想修改传入的实参，
	// 必须用指针来接收
	fmt.Println("排序前 arr=", *arr)
	...
}
```

这里要停下来想一下。**数组是值类型**，还记得吧？所以如果我们想在函数里面修改外面传进来的实参，是不是应该用指针来接收？所以形参写 `*[5]int`，这就是一个指向数组的指针，传进来的 `arr` 和外面的 `arr` 就是同一个 `arr` 了，这样才能保证你在函数里排序的结果影响到 `main` 里的那个变量。

调用的时候要把地址传进去：

```go
BubbleSort(&arr)
```

先跑一把，看排序前的数组是乱序的。

#### 先只写第一轮

现在要求大家把 80 排在最后一个。**先不要去看第二轮、第三轮**，就看第一轮。第一轮是 4 次比较，刚好是数组大小减 1，而且一个 `for` 循环就够了：

```go
for j := 0; j < 4; j++ {
	temp := 0
	// 让前面的数和后面的数比较，前面的数大则交换
	if (*arr)[j] > (*arr)[j+1] {
		temp = (*arr)[j]
		(*arr)[j] = (*arr)[j+1]
		(*arr)[j+1] = temp
	}
}
```

几个点解释一下。因为形参是指针，所以每次取元素都要做一次**取值运算**：`(*arr)[j]`。交换靠一个临时变量 `temp`，先把这个数交给 `temp`，再把后面的数交给前面这个位置，然后让 `temp` 把原来那个数交给后面这个位置，交换完毕。这个流程前面我们已经讲过好多次了。

写完打印一下：

```go
fmt.Println("第一次排序后 arr=", *arr)
```

跑一下，我们可以看到第一次排序完毕后，80 确确实实放到了最后。

#### 第二、三、四轮只有数字在变

下面该第二轮了。第二轮要把 69 排在倒数第二位，里面进行了三次比较。这段代码有什么写头？**把这个 4 改成 3 就行，里面什么都不用变。**

第三轮，外层第三次，把这个 3 改成 2，里面还是不用变。跑一下，57 已经在它的位置上了。

第四轮，改成 1，里面依然不用变。跑一下：13、24、57、69、80，已经是个有序数列了。

看到了吗？**这四段代码长得几乎一模一样，唯一在变化的就是那个数字：4、3、2、1。**

#### 统统删掉，套进循环里

那我们能不能把这个当做一个循环体，给它套一个循环？

当然可以。而且既然规律已经找到了，这四段代码**统统不要了**——我要它干什么？整个用 `for` 循环表达就完事了。真正的变化在这里：

```go
func BubbleSort(arr *[5]int) {
	// 打印排序前的数组
	fmt.Println("排序前 arr=", *arr)

	// 冒泡排序：外层控制轮数，内层控制每轮的比较次数
	for i := 0; i < len(*arr)-1; i++ {
		temp := 0
		for j := 0; j < len(*arr)-1-i; j++ {
			if (*arr)[j] > (*arr)[j+1] {
				temp = (*arr)[j]
				(*arr)[j] = (*arr)[j+1]
				(*arr)[j+1] = temp
			}
		}
	}

	fmt.Println("排序后 arr=", *arr)
}
```

外层 `i < len(*arr)-1`——大循环一共多少轮？正好是数组长度减 1。每完成一轮，就有一个数就位。

内层 `j < len(*arr)-1-i`——这就是"每一轮比较次数逐渐减少"的代码表达。我们验一下这个减去的 `i` 是怎么起作用的：`i` 第一次进来是 0，`len` 是 5，5 减 1 等于 4，就比 4 次；第二次进来 `i` 变成 1，5 减 1 再减 1 就等于 3；依此类推。**一个 `- i` 就把整个"逐轮递减"的问题解决了。**

> **提示**：其实你哪怕**不写那个 `- i`**，代码也已经是正确的——每次都比 4 次而已，大不了有几轮白比几次，浪费点感情和性能而已，结果照样有序。但既然我们知道了规律，就应该把优化写进去。

完整的主函数：

```go
func main() {
	// 定义一个数组
	arr := [5]int{24, 69, 80, 57, 13}
	// 打印主函数中的数组
	fmt.Println("主函数中的数组 arr=", arr)

	// 将数组的地址传递给函数，完成排序
	BubbleSort(&arr)

	// 函数中排序完成后，再次打印主函数中的数组
	fmt.Println("主函数中的数组 arr=", arr)
}
```

`cd chapter08`，再 `cd bubblesort`，`go run main.go` 跑起来：

```text
排序前 arr= [24 69 80 57 13]
排序后 arr= [13 24 57 69 80]
主函数中的数组 arr= [13 24 57 69 80]
```

排序前是乱序的，排序后是 `13、24、57、69、80`，完全正确。

如果你还听不懂冒泡，那就真的彻底听不懂了。那么问题来了：**如果我要求输出的是从大到小，应该改哪个？**只要把那个大于号改成小于号，就是从大到小排列了。改一下跑一跑，果然如此，然后改回去。

主函数里那两次打印也印证了一件事：你传的是**地址**，是引用传递，所以在函数里面的修改会直接影响外面的变量。前面已经讲过好多遍了，这里再一次得到验证。

## 顺序查找与二分查找：从一个一个比对，到每次砍掉一半
> 对应块：BLK59 | 覆盖分集：P166-P168 | 块标题（分集名）：《165_尚硅谷_顺序查找》

编程过程中我们会经常用到查找这门技术。尤其找工作或者面试的时候，也往往会被问到查找。今天我们把 Go 语言里常用的两种查找方式一次讲透：**顺序查找**和**二分查找**。

先把两者的定位摆出来。顺序查找听其名而知其意，就是按顺序一个一个地比，看数组里有没有你要找的元素；**二分查找的效率要高得多**，但它用到了递归的知识点，而且有个硬前提——**数组必须有序**。不是有序的话，二分查找根本用不了。所以要用二分查找，就先把数组排序，排完再用。

### 顺序查找：给四位鹰王找一个名字

看这个案例要求：有一个数列——**白眉鹰王、金毛狮王、紫衫龙王、青翼蝠王**，要求从键盘输入一个名称，判断数列中有没有这个名称，**要求用顺序查找**。

思路其实非常简单，三步：

- **第一步**，定义一个数组，里面存放这些信息，是**字符串数组**；
- **第二步**，从键盘或控制台接收一个名称；
- **第三步**，依次比对，发现有就提示相应信息。

新建一个 `finddemo` 文件夹，新建 `main.go`，按这个思路走。

```go
package main

import (
	"fmt"
)

func main() {
	// 第一步：定义一个字符串数组
	names := [4]string{"白眉鹰王", "金毛狮王", "紫衫龙王", "青翼蝠王"}

	// 第二步：从控制台接收一个名字
	var heroName = ""
	fmt.Println("请输入要查找的人名：")
	fmt.Scanln(&heroName)
```

第二步里的 `fmt.Scanln(&heroName)` 要注意：因为是要接收用户输入的值，所以必须传 `heroName` 的**地址**（取地址符 `&`），这样才能把读到的内容写回到这个变量里。

#### 第一种写法：在循环里顺手判断"是不是最后一个"

先用第一种方式完成顺序查找：

```go
	for i := 0; i < len(names); i++ {
		if heroName == names[i] {
			fmt.Printf("找到 %v，下标为 %v\n", heroName, i)
			break
		} else if i == (len(names) - 1) {
			fmt.Printf("没有找到 %v\n", heroName)
		}
	}
```

这里的关键是那个 `else if i == (len(names) - 1)`。意思是：**如果 `i` 已经到达了最后一个元素**，而且走到这里仍然没有进到上面那个匹配的 `if` 逻辑里，那就说明——没有找到。

进目录运行 `go run main.go`，输入一个查得到的名字，比如 `金毛狮王`：

```text
请输入要查找的人名：
金毛狮王
找到 金毛狮王，下标为 1
```

再试一个查不到的，比如 `hello`：

```text
没有找到 hello
```

第一种方式就完成了。但是这个写法感觉有点笨笨的。

#### 第二种写法：用一个 -1 当标记

还有第二种方式，一般情况下思路是这样的：**先定义一个下标 `index = -1`**。意思是——我先定义一个下标等于 -1，如果找到了，我就把真实的下标赋给 `index`；如果找不到，`index` 就一直保持 -1 这个值。

```go
	index := -1

	for i := 0; i < len(names); i++ {
		if heroName == names[i] {
			index = i // 将找到的值对应的下标赋给 index
			break
		}
	}

	if index != -1 {
		fmt.Printf("找到 %v，下标为 %v\n", heroName, index)
	} else {
		fmt.Printf("没有找到 %v\n", heroName)
	}
}
```

逻辑在哪里？不停循环比对的时候，**只要找到了就 break 跳出**。那循环结束后，怎么知道到底找到了没有？就看 `index`：

- `index` 还是 -1，说明没找到；
- `index` 不等于 -1，说明一定找到了——因为**只有找到的情况下才会进入那条赋值语句**。

把第一种方式注释掉，测试第二种。输入 `汤姆`：

```text
没有找到 汤姆
```

再输入 `紫衫龙王`：

```text
找到 紫衫龙王，下标为 2
```

下标确实是 2，没错。

> **提示**：这两种方式大家可以任选，但我在开发中**更推荐第二种**，思路更清晰——找到了就 break，顺手把下标存进 `index`，最后统一通过 `index` 判断结果。查找本身并不难，就是找到一个就 OK；难的是下一节的效率问题。

### 顺序查找的代价：整个数组都得扫一遍

大家想一想，这个顺序查找的效率是不是比较低？为什么这么说？假设元素很多，比如 789、111、10、121 这样的一个数字数组，你**是不是得把整个数组扫一遍**才能确定有没有？

所以我们还有第二种查找方式——二分查找。它的思路我们下面详说。

### 二分查找的前提：数组必须有序

二分查找的要求是：**对一个有序数列进行二分查找**。

有序意味着要么从小到大，要么从大到小。任务是输入一个数，看数组里是否存在此数，并且求出下标；没有就提示没有这个数。这套逻辑会**使用到递归**。

还是老规矩，编写一段程序之前先做思路分析。如果不做思路分析，写完代码再看也很难懂。还是用 Excel 表画一下。

我们拿这个数组举例，它现在就是一个**从小到大排列的有序数组**：

```text
        0      1     2     3     4      5
      +------+-----+-----+-----+------+------+
      |  1   |  8  | 10  | 89  | 1000 | 1234 |
      +------+-----+-----+-----+------+------+

        ^                            ^
        |                            |
     green 绿色箭头              red 红色箭头
      leftIndex                   rightIndex
```

二分查找的思路是这样：

- **第一**，首先要保证这是一个有序数组。
- **第二**，它有**两个下标**，我用两个不同颜色的箭头表示。绿色那个叫 `leftIndex`，是左边的下标；红色那个叫 `rightIndex`，是右边的下标。
- **第三**，我们先规定要查找的数叫 `findVal`。二分查找**从两头找中间这个数**：中间的下标 `middle` 等于 `(leftIndex + rightIndex) / 2`。

### 三种可能，决定往哪边砍

找到中间下标之后，让中间下标对应的值和 `findVal` 比较。一比较就有**三种可能**：

- **第一种**：`array[middle]` 大于 `findVal`。
- **第二种**：`array[middle]` 小于 `findVal`。
- **第三种**：相等。

逐个说清楚。

**情况一，中间大于要找的数。** 这说明什么？说明你要找的这个数，**如果存在的话，应该在左边**。因为你是从小到大排的，中间这个数既然比要找的大，那么要找的数只能在它左边。于是就应该向 `leftIndex` 到 `middle - 1` 这个区间去查找。

> **易错点**：往左还是往右，取决于数组本身的排序方向。我们现在是**从小到大**，中间大就往左找；**如果是从大到小，就刚好相反**。这一步千万不要搞混。

**情况二，中间小于要找的数。** 那么要找的数就应该在 `middle + 1` 到 `rightIndex` 这个范围。

**情况三，相等。** 那就恭喜你，找到了。

这个逻辑要**周而复始地执行**。左、中、右三个下标里，中间那个一比较：假设中间值比要找的数大，就让这个标往这边移动，然后中间这个值就移动到这儿来了。**这也就是为什么管它叫"二分"——中间这个数一旦不等于目标，我们马上就把这个数组砍成两半了**，你要找的只可能在这一半，绝不可能在另一半。

打个比方：原先这个地方一共有 6 个数。假设中间这个值算下来是它，如果这个数和要找的数一比不相等，那么这一半直接就被抛弃了。**为什么二分查找速度快？就是因为它折半查找。**

前提还是那句话：**数组必须有序**。如果不是有序数组，我们这套分析根本不成立——就算中间那个数大于要找的值，你也不能说它一定在那一半，因为它是无序的。如果是有序的，我们就可以这么判断。

### 退出递归的条件：leftIndex > rightIndex

还有一个非常重要的分析：**什么时候我们才认为它找不到？**

这一点非常非常重要。如果我们没把这个条件分析出来，我可以负责任地告诉大家：**二分写出来也是个死规，一定会死循环在里面。**

答案就是：**当 `leftIndex > rightIndex` 的时候，说明确实找不到了。**

我们把过程推一遍。查找的过程中，左下标会一路往右挪，右下标会一路往左挪，两个下标**越靠越近**。有一种极端情况是：左右两个下标**相等**了，这时候还能再进行一次比较——这已经是最后一次比较了。如果这一次还不是，那就说明真的找不到了，因为再往走已经全部扫描过一遍了。

再往后一步呢？右边这个指针继续往左跑，左边这个继续往右跑，那就出现一个情况——**左边这个下标比右边这个下标还大了**。这个条件一旦出现，就说明真的找不到了。

所以退出条件就一句话：

```go
if leftIndex > rightIndex {
	// 说明找不到了，退出递归
}
```

能理解这个意思吗？

### 递归实现：把思路翻译成代码

新建文件夹，二分查找有个专业术语叫 `BinaryFind`，所以文件夹就叫这个名字，新建 `main.go`。

先定义数组，直接用我们已有的那个有序数组：

```go
arr := [6]int{1, 8, 10, 89, 1000, 1234}
```

然后写二分查找的函数。参数有这么几个：数组传进来——**老规矩用指针接收，这样就不用进行值拷贝了，效率高很多**；另外你得告诉我这个数组从左边第几个元素开始找、从右边哪个下标结束，所以还要 `leftIndex` 和 `rightIndex`；最后你要查找的那个数也得体现出来，叫 `findValue`。

```go
func BinaryFind(arr *[6]int, leftIndex int, rightIndex int, findValue int) {

}
```

现在按思路一步步往里填。

**第一步，先判断 `leftIndex` 是否大于 `rightIndex`，是就找不到，直接退出。** 这一句要写在函数体的最前面。

**第二步，先找到中间的下标**：

```go
med := (leftIndex + rightIndex) / 2
```

**第三步，根据三种可能分支。** 这里有个细节要提醒：`arr` 是一个指针，所以 `arr[med]` 是取不到元素的，**必须先用取值符再取下标**，写成 `(*arr)[med]`。

完整代码：

```go
package main

import (
	"fmt"
)

func BinaryFind(arr *[6]int, leftIndex int, rightIndex int, findValue int) {
	// 先判断 leftIndex 是否大于 rightIndex
	if leftIndex > rightIndex {
		fmt.Println("找不到")
		return
	}

	// 先找到中间的下标
	mid := (leftIndex + rightIndex) / 2

	if (*arr)[mid] > findValue {
		// 说明我们要查找的数，应该在 leftIndex 到 mid - 1
		BinaryFind(arr, leftIndex, mid-1, findValue)
	} else if (*arr)[mid] < findValue {
		// 说明我们要查找的数，应该在 mid + 1 到 rightIndex
		BinaryFind(arr, mid+1, rightIndex, findValue)
	} else {
		// 找到了
		fmt.Printf("找到了，下标为%v \n", mid)
	}
}

func main() {
	arr := [6]int{1, 8, 10, 89, 1000, 1234}

	BinaryFind(&arr, 0, len(arr)-1, 1000)
}
```

几个地方再拆开说：

- **调用函数本身时不用再加 `&`**。因为 `arr` 本身就是一个指针，你把指针传给指针当然可以。
- **右边界那一侧传 `mid + 1`，右边界 `rightIndex` 保持不变**；左边界那一侧传 `mid - 1`，左边界 `leftIndex` 保持不变。
- **找到时打印的下标就是 `mid`**。
- **找不到时 `return` 就完了**，一层一层把它 return 回去。

#### 跑起来验证

调用 `BinaryFind` 时，第一个参数要传**地址**，因为形参接收的是数组的指针：`BinaryFind(&arr, ...)`。

第二个参数是左边的起始下标 `0`；第三个参数是右边的下标，**这里一定要减 1**——`len(arr)-1`。不减 1 的话就跑到数组外面去了。

`cd binaryfind`，`go run main.go`。第一次跑确实报错了——一个 `undefined`（少了一处类型推导），还有一处把 `mid` 单词拼错了。改完之后：

- 查 **1000**：`找到了，下标为 4`。我们传的第一个数下标就是 4，0、1、2、3、4，正确。
- 查 **1**：`找到了，下标为 0`，正确。
- 查 **89**（一个中间的值）：也找到了。
- 查 **-6**：数组里没有，提示 `找不到`，完全正确。

说明这个代码是 OK 的、是完全正确的。

> **易错点**：递归里的 `return` 一定要写。不写的话，即使命中了 `leftIndex > rightIndex` 这个分支，函数还会往下走，递归就停不下来，结果就是死循环——这正是前面说的"退不出来"的那个坑。

### 查找这块要掌握什么

关于查找，我们就全部介绍完毕了。你们要掌握的就是**顺序查找**和**二分查找**这两个。尤其是二分查找，一定要好好理解，因为里面用到了递归，难度稍微大了一点——而它也经常作为面试题。

关于递归这部分，我在前面是下了大功夫给大家讲的，这块确实有一定技术含量，大家要好好想。

### 二维数组用在哪：棋盘和迷宫

我们接着讲 Golang 里的二维数组。**二维数组是多维数组里最简单的一种**——我们前面讲的数组都是一维数组，现在来看二维数组。

**二维数组的应用场景非常多。** 比如我们写一个五子棋游戏，棋盘其实就是一个二维数组构成的。再比如我以前讲 Java 的时候，带同学们写过一个基于递归的迷宫小游戏，那里也用到了一个二维数组——因为这个迷宫本身就是一个二维数组。

我给大家看我以前写过的那个迷宫小游戏，感受一下。我用 Java 运行一下：

```bash
java MyFrame
```

你们看，这里面就出现一个小迷宫。从这开始到这，就是一个二维数组；里面可以画上一些遮挡物体，把小球挡住，甚至我在这儿也可以再画一个。最终当我点"走"这个按钮的时候，这地方会出现一个小球；小球出现过后，我一点"走"，小球就会从这里最终走到这个位置。也就是说，小球从这里出发，最后到达这个角——**小球到了这儿，就说明迷宫走完了。**

这里面用到的就是**二维数组，加上我们前面讲的递归回溯算法**。你们看，因为这里边用了回溯，所以小球到这个地方的时候可能还会回去一趟。

大家体验一下就可以了。这个小游戏我也会分享给大家。**从这一下你就能感觉到，二维数组的应用场景还是比较多的。** 我们把笔记补一下：二维数组的应用场景，比如做游戏的时候会用到二维数组，你们玩的一些网游，它的地图其实里面就是一个二维数组。

### 快速入门：用二维数组输出一个图形

讲完怎么用之后，我们就按老规矩来一个快速入门，体验一下它的用法。

#### 二维数组是什么

我们直接上一个案例：**请使用二维数组输出下面这个图形。**

这个图形你仔细看——单看一行是不是一个数组？再往下看一行又是一个数组，再下一行又是一个数组。**其实这就是二维数组。所谓二维数组，就是一维数组里边的元素又是数组。**

其实二维数组是在一维数组上扩展的。我们前面学的一维数组，元素就是基本数据类型，比如 `int`、`float`、`string`；但二维数组你可以这样理解——**它具有一维数组的形式，只是一维数组里边的元素又是一个一维数组，从而就构成了二维数组。**

#### 声明：`var arr [4][6]int`

新建一个文件夹 `multiarray`，里面建一个 `main.go`。要做的功能就是用二维数组输出上面那个图形，思路很简单，直接上代码。

第一步，声明一个二维数组：

```go
var arr [4][6]int
```

二维数组怎么声明呢？非常简单。前面还是 `var`，数组名叫 `arr`。你先看这个 `[4]`——**这表示这是一个有四个元素的数组**。但它现在每个元素不是一个 `int` 了，而是什么？**又是一个数组。**

这样理解就很好理解了：这个 4，是"4 这个数组里边的每一个元素放的是什么"？它放的是一个 6——也就是"你可以理解成这有一个一维数组可以放四个元素，但每个元素又是一个一维数组"。这就完事了。

写完这行，这个数组其实**有初始值，全部都为 0**。所以先不赋值，直接输出看看：

```bash
go run main.go
```

一输出一目了然——这是其中第一个元素，这是第二个，这是第三个，这是第四个，是不是符合我们前面定的 `[4]`？**只是它的每一个元素不是一个基本数据类型，而是一个数组。** 你可以理解成，原先的基本数据类型变成了一个数组——这就叫二维数组，一共有四个一维数组，整体构成了一个二维数组。

#### 赋值：下标还是从 0 开始

现在人家要求的图形里，那几个位置要放 1、2、3，其余是 0。怎么找到它们？

要求里说，第二个元素对应的一维数组的第三个元素要为 1。**首先你要看这一组元素是第几个一维数组？** 实际上是第二个——是不是应该写 `1`？现在老师高亮的部分就代表这个一维数组。那它里面的第几个元素呢？第三个元素——是不是写 `2`？

```go
arr[1][2] = 1
```

这就对应 1 这个位置了。

另外两个同理。第三个一维数组的第几个元素放 2？——第二个一维数组里的第一个元素，`arr[2][1] = 2`。

还是第三个一维数组，第四列放 3。**第四列这就应该写 3，因为下标是从 0 开始编的：**

```go
arr[2][3] = 3
```

```go
arr[1][2] = 1
arr[2][1] = 2
arr[2][3] = 3
```

这样写完我们再来执行一遍，请看效果——对应的 1 变了，2、3 变了。**但是人家的输出不是让你横向输出，而是要输出一个图形。**

#### 遍历：外层走行，内层走列

那怎么输出一行一行的图形呢？非常简单，遍历一下。

既然它是一个二维数组，先把每一个一维数组遍历出来——它一共有四个一维数组：

```go
for i := 0; i < 4; i++ {
	// ...
}
```

如果我这样就输出，是不是相当于每一次就把整个一维数组输出来了？大家看，横向就输出出来了——中括号还在。

**但人家说你不要按一维数组的方式输出，要一个一个地把一维数组里面的每个元素也输出出来。** 那是不是意味着我们还需要找到这个一维数组，再对它进行一次遍历，依次取出里面的元素？

因此怎么干呢？非常简单，这个地方你再进行一层遍历：

```go
for i := 0; i < 4; i++ {
	for j := 0; j < 6; j++ {
		fmt.Print(arr[i][j], " ")
	}
	fmt.Println()
}
```

大家都知道每个一维数组里有几个元素？六个元素，那就写 6。

这个时候有两个细节：**输出了 `arr[i][j]`，输完一个过后给它来一个空格；等这个 for 循环走完以后，一个一维数组就遍历完了，然后给它来一个换行符。** 为什么？因为人家要求一排一排地输出，你输完一排再换行。

跑一下就能看到，中括号没有了，也按要求输出了对应的图形。

> **结论**：老师讲课的时候始终在强调——**二维数组的本质就是一个一维数组里面的元素又是一个一维数组。** 你只要理解了这个，下面就不太难理解了，因为它的本质就是在一维数组上扩展了一下而已。

### 内存布局：两个指针，各指向一个一维数组

这一块是一个**重点**。我们只有理解了一个数据类型在内存里面的布局，才能深刻地理解这个数组到底是怎么存在的，应用起来才会得心应手。

我为什么把数据调小了？**因为这样我比较好画。** 如果还按前面这个 4、6，元素太多了，我画起来比较吃力，所以把数据都减小了一下。我们以这个为例，分析它在内存里的布局。

老规矩，打开一个 Excel 表，我们开始画。这是一块内存——

```text
   array2 这个名字对应的内存空间
   ┌────────────────┬────────────────┐
   │     指针 1     │     指针 2     │   ← 这里不直接放数据，只放两个指针
   └────────┬───────┴────────┬───────┘
            │                │
            ▼                ▼
   ┌── 一维数组 1 ───┐  ┌── 一维数组 2 ───┐
   │   0      0     0 │  │   0      10     0 │
   └───────────────────┘  └───────────────────┘
        ↑                          ↑
   &arr2[0]                    &arr2[1]
   = &arr2[0][0]              = &arr2[1][0]

   两块一维数组的首地址相差：3 × 8 = 24 字节
```

先看 `array2` 这句话一旦执行，内存里会出现什么。**首先会有一个 `array2` 这个变量名，它在这个地方会有一个空间对应。这个空间里面存的是什么呢？它并没有直接存放这里面的数据，而是有两个指针。** 它把这个空间分成两个部分，第一个部分是一个指针，指向一个位置；第二个部分又是一个指针。

为什么是两个指针？因为你这个 `array2` 有两个元素，只是每一个元素指向的是一个一维数组——**这两个指针分别指向一个一维数组。**

那它指向哪里呢？第一个指针指向的就是第一个一维数组的**首地址**。第二个指针同理，指向另外一个一维数组的首地址。这两个一维数组刚声明完的时候，里面默认值都为 0，因为你还没有给它赋值。

有同学问："老师，你能把地址给我打出来看一下吗？"没问题。

```go
fmt.Printf("%p %p\n", &arr2[0], &arr2[1])
```

跑出来你会看到两个地址，**而且它们刚好相差 24 个字节**——比如 270 和 288。

**为什么刚好相差 24 个字节？** 因为你每一个元素里有 3 个 `int`，而一个 `int` 是 8 个字节，因此它的跨度刚好是 3 个元素的跨度：**3 乘以 8，不就 24 吗？** 70 加一个 24，刚好就进到 88。

那能不能证明这两个地址确确实实就是上面那两个一维数组的首地址？也能：

```go
fmt.Printf("%p %p\n", &arr2[0][0], &arr2[1][0])
```

第一个一维数组的首地址就是 `&arr2[0][0]`，你会看到这个地址和刚才 `&arr2[0]` 那个**完全相同**；第二个同理，`&arr2[1][0]` 和 `&arr2[1]` 也完全相同。这就证明我们画的这个图是对的。

有些同学说："老师，你给我改一下看看是不是。"**比如我把这个 `[2][3]` 改成 `[2][2]`**，它的一维数组里面每个只有两个 `int`，那就应该相差 16 个字节。跑一下，果然相差 16——在 A0 的基础上加一个 16，A 进一位变成 B，后面变回 0，跟我分析的完全一样。

**再改成 `[2][1]` 试试看**，那就相差 8 个字节，一看就更清楚了。这个是不是改不了？不，能改，只是改成 1 有点太窄了，但在语法上是合法的。

最后再验证一下内存图对不对。**如果我在代码里做一个 `arr2[1][1] = 10`，我改变的是哪一个呢？** 它是这样找的：首先找到 `arr2` 里面的第二个元素的指针，也就是 `arr2[1]`，其实就会找到图里这里；然后找其中下标为 1 的这个元素——是不是就是它？把它改成 10。因为下标为 1 其实就是第二个元素。

再跑一遍，你看输出：**前面第一个一维数组仍然是三个 0；后面这个是 0、10 和 0。** 跟老师分析的完全一致。**我们通过这个分析，就对二维数组理解得比较到位了。**

### 声明与初始化的几种写法

上面那个案例用的是**第一种使用方式：先声明，再赋值**。它的语法你刚才已经见过了：

```go
var 数组名 [大小1][大小2]类型
```

前面这个大小指的是你这个二维数组**共有多少个元素**；第二个大小指的是**里面的各个一维数组各有几个元素**。

比如刚才的案例 `arr [4][6]`，后面这个大小是可以不要的，也可以带上——我刚才就没再加这个中括号了，去掉一样。

**第二种使用方式是直接初始化拿来使用**，也就是我在定义的时候就把值给你初始化好。当然后面也可以再改，也可以不改；不改的话就跟上面那个初值一样：

```go
var arr3 [2][3]int = [2][3]int{{1, 2, 3}, {4, 5, 6}}

println("arr3=", arr3)
```

跑出来跟想象的结果完全一样。没问题。

除此之外还有几种写法，大家了解一下就可以了：

```go
// ① 前面的大小可以省略，写 [...]，让编译器自己推导
var arr4 [...]int = [2][3]int{{1, 2, 3}, {4, 5, 6}}
```

**`[...]` 可以根据你赋初值的时候知道你一共赋了几组、赋了几个数，这样它就能把大小推导出来。但后面这个大小不能省略。** 就好比刚才那个写法，我完全可以把前面这个地方写成 `[...]`。

```go
// ② 前面的类型可以省略，因为后面这个值是什么，它直接就把具体的数据交给它
var arr5 = [2][3]int{{1, 2, 3}, {4, 5, 6}}
```

```go
// ③ var 可以去掉，但去掉之后必须给 :=，这就叫类型推导
arr6 := [2][3]int{{1, 2, 3}, {4, 5, 6}}
```

这个在前面讲基础的时候老师已经全部讲过了，我这儿就不再赘述。大家记住有这么几种写法就行。

## 遍历二维数组、算出三个班的平均分，然后认识 map
> 对应块：BLK61 | 覆盖分集：P171-P174 | 块标题（分集名）：《170_尚硅谷_二维数组遍历方式》

二维数组遍历是二维数组的一个基本使用，我们直接来看案例；顺带把二维数组最典型的一道应用题——按班级统计成绩——完整地走一遍。等数组和查找这块收尾，我们正式打开 Go 语言核心编程的**第九章：map**。

### 二维数组的两种遍历方式

二维数组的遍历仍然是有两种方式：**第一种，使用双层 for 循环来完成遍历；第二种，用 for-range 来完成遍历。** 我分别给大家介绍。

新建一个文件夹，就叫 `traverse`——traverse 在英文里就是遍历的意思。文件叫 `main.go`。既然要遍历二维数组，我们首先得有一个二维数组，这块我们就"偷个懒"，直接用前面那个二维数组。

#### 双层 for 循环

用 for 循环来遍历非常简单：

```go
for i := 0; i < len(arr3); i++ {
	for j := 0; j < len(arr3[i]); j++ {
		fmt.Printf("%v\t", arr3[i][j])
	}
	fmt.Println()
}
```

这里有两个地方要停下来想清楚。

**外层 `i <` 多少？** 这里应该写 2，但你不能写死。写死了，别人一变怎么办？所以这个地方我们用 `len` 来算——`len(arr3)` 得到的就是这个二维数组里面统共有几个元素，当然这个元素肯定是一个一维数组了。这里 `len(arr3)` 就拿到了那个 2。

**内层 `j <` 多少？** 每进来一次，它里面可能有自己不同的元素个数，因为元素有可能是不一样的。所以我们写 `len(arr3[i])`。也就是说，假设第二个元素里面只有两个元素，它也能正确遍历。怎么统计？因为你每进来的这个 `i` 在不停变化，`len(arr3[i])` 就正好统计到当前这个 `i` 对应的那一个一维数组里有多少个元素。

> **提示**：虽然 Go 语法允许写成 `len(arr3[i])` 这种"每行长度可以不同"的写法，但 Go 语言本身要求每个一维数组的个数是一样的，所以我们一般不会去修改它的个数。这里写成 `len(arr3[i])` 而不是写死 5，纯粹是为了代码更健壮。

输出就用 `%v`，为了好看后面跟一个 `\t` 格式化一下，取值就是 `arr3[i][j]`。**每遍历完一个一维数组，就来一个 `fmt.Println()` 换行**，代码就写完了。

`cd` 到 `traverse_array`，`go run main.go` 跑起来，我们可以看到遍历成功了：`1 2 3`，`4 5 6`。第一种方式介绍完毕。

#### for-range 嵌套

下面介绍用 for-range 的方式来遍历，道理也是一样的。

首先，`for i, v := range arr3`——先把它遍历出来。这里有一个值 `v`，**这个地方这个值其实就是里面的一组一维数组**，大家能理解吗？

```go
for i, v := range arr3 {
	for j, v2 := range v {
		fmt.Printf("arr3[%v][%v]=%v\t", i, j, v2)
	}
	fmt.Println()
}
```

这里我强调一个特别容易搞错的点。第一次进行 for-range 的时候，这个 `v` **不是一个具体的元素的值，而是一个一维数组**。你可以把它打印出来看一下，每一步的 `v` 目前来说都是一个一维数组。

顺便说一个小坑：如果我们第一层只写 `for i, v := range arr3`，而后面又没用到 `i`，就会报 `i` 没有使用。如果 `i` 暂时没用，那我们就先用一下它——输出 `i =` 多少、`v =` 多少，也把它输出来，不就完了吗。

跑一个你就看到：`i = 0` 的时候对应一个一维数组，`i = 1` 的时候又对应一个一维数组。但人家可能不想看这种风格，我们换一个风格。

接着对它再进行遍历：`for j, v2 := range v`。这个 `v2` 就是具体的值了，对 `v` 进行 range——因为我们知道 `v` 其实是个一维数组。输出格式化成 `arr3[%v][%v]=%v\t`：这个 `i` 就是它第一个中括号里面的值，`j` 就是第二个中括号里面的值，`v2` 就是这个元素对应的值。

跑一下，我们可以看到：`arr3[0][0]=1 arr3[0][1]=2 arr3[0][2]=3 arr3[1][0]=4 arr3[1][1]=5 arr3[1][2]=6`。跟上面输出的结果其实是一样的，**只是我们遍历的方式不一样了**——上面用的是 for 循环，下面用的是 for-range。

### 案例：三个班五名学生的平均分

来看一个二维数组的应用案例。现在要求定义一个二维数组，用于保存**三个班、每个班五名学生的成绩**，并要求**求出每个班的平均分以及所有班级的平均分**。

一维数组在这里已经搞不定了。你想一想，三个班每个班五个学生，一维数组没办法区分是哪个班的，自然就得用二维数组来完成。

从它给出的图来看，应该是动态地给每个班每个学生赋值，循环地从控制台输入成绩。老规矩，`chapter08` 下面写一个 `exercise`，新建 `main.go`。

**第一步，定义二维数组。** 这个对我们来说没有难度：

```go
var scores [3][5]float64
```

怎么理解这个声明？二维数组说存放三个班、每班五名学生，那首先要有三个一维数组，每个一维数组里有五个元素。**第一个 3 代表我有三个一维数组，第二个 5 代表每一个一维数组里有五个元素，也就是五个成绩**，然后类型是 `float64`。

**第二步，循环地输入成绩。** 那我怎么循环输入呢？肯定要遍历：

```go
for i := 0; i < len(scores); i++ {
	for j := 0; j < len(scores[i]); j++ {
		fmt.Printf("请输入第%d个班的第%d个学生的成绩\n", i+1, j+1)
		fmt.Scanln(&scores[i][j])
	}
}
```

这里有个小细节：因为它的下标是从 0 开始的，但我们不能说"第 0 个班"，所以 `i` 要加个 1，`j` 也一样。提示完了过后我们就接收一下——`fmt.Scanln(&scores[i][j])`，**别忘了 `&`，这是要接收用户输入的值，必须传地址**。

跑一跑，可以看到它会依次提示"请输入第 1 个班第 1 个学生成绩"……全部输完之后，三个班各五个学生的成绩都录进去了。可以把它打印出来看一下。

**第三步，统计平均分。** 这个遍历跟刚才是一样的，只是要重新处理一下。

要统计每个班级的平均分，首先得知道每个班级的总分。怎么知道总分？简单，我定义一个 `sum`，给它个 0.0，**在内层 for 循环遍历这个班级成绩的时候就累加**：

```go
var totalSum float64 = 0.0
for i := 0; i < len(scores); i++ {
	sum := 0.0
	for j := 0; j < len(scores[i]); j++ {
		sum += scores[i][j]
	}
	fmt.Printf("第%d个班的总分为%v，平均分为%v\n", i+1,
		sum,
		sum/float64(len(scores[i])))
	totalSum += sum
}
fmt.Printf("所有班级的总分为%v，平均分为%v\n", totalSum, totalSum/15)
```

几个点一个个拆：

- **`sum` 要定义在内层循环的外面一层**（也就是班级循环里面、学生循环外面），这样一轮内层循环下来，`sum` 才是这个班的总分。
- **平均分不能写死除以 5**。既然要用通用写法，班级的总人数怎么写最合理？就是 `len(scores[i])`，代表当前这个班级有几个学生。
- **这里会报一个"类型不匹配"的错**，原因还是老规矩：`scores` 是 `float64`，而 `len()` 返回的是 `int`。Go 语言在运算时**不会默认进行隐式转换，必须强制转换**——所以写成 `sum/float64(len(scores[i]))`。
- **所有班级的总分 `totalSum` 必须定义在最外层**。你不能定义到内层去，定义到里面它就会在每一次循环的时候被重新赋值，那就没有意义了。内层遍历完一个班级，就赶紧 `totalSum += sum`。等整个双层循环完毕，`totalSum` 就是所有班级的总分。
- **最后除以 15**，因为我们有 15 个学生。我这里偷个懒直接除以 15；如果你觉得麻烦，也可以再定义一个变量把总人数统计出来。

> **易错点**：这一行如果越来越长，想换行处理，**换行的时候要在上面留一个逗号**。逗号留在上一行，这样看起来也比较舒服。如果把逗号拿到下一行去，语法就会报错。

跑起来看结果。我为了简单一点，第 1 个班全输 1 分，第 2 个班全输 2 分，第 3 个班全输 3 分。

第一次跑的时候输出有点不对——班级总分为 1 分，这肯定不对。我们马上就知道问题出在哪了：**少了一个百分号**。把它补上，并且这里是第 `i+1` 个班，这样写才对，不然对不上。

再跑一次：第一个班总分为 5 分（五个学生每人 1 分），平均分 1 分；第二个班总分 10 分，平均分 2 分；第三个班总分 15 分，平均分 3 分；所有班级总分为 30 分，平均分为 2 分。**完全正确。**

- **编写一个函数接收一个数组，该数组有 5 个数，请找出最大数、最小数以及对应的下标。** 前面我们讲过找最大值和它下标的题，这里把它拓展了，最大和最小都要找到。
- **定义一个数组给出 8 个整数，求该数组中大于平均值的数的个数和小于平均值的数的个数，并输出来。**
- **跳水比赛题，这个稍微难一点，有一定难度。** 8 个评委打分，运动员的成绩是 8 个分数去掉一个最高分、去掉一个最低分之后剩下 6 个分数的平均分——国际上打分也是这样子的。用一维数组实现下面两个功能：**一、把打分最高的评委和最低的评委找出来**，是哪两个人打的最高、哪一个人打的最低；**二、找出最佳评委和最差评委**。什么叫最佳评委？就是打分和最后得分最接近的那个评委。最差评委就是打分和最后得分相差最大的——比如说人家最后平均分是 5 分，结果这个人打了 20 分，那明显就是作弊，把这个最差评委也给我挑出来。

十道题就布置到这里。只有这样子，你才能把这个编程语言学到手，才会真正学会编程的思想。大家好好去思考、好好去研究。

### 第九章 map：一个 key 找到对应的 value

现在开始讲 Go 语言核心编程的第九章——**map**。

map 在 Go 语言里其实就是一个数据结构，官方把它叫**映射**，实际上它本质就是一个集合。

> **定义**：map 是一个 **key-value 的数据结构**，又称为字典或者关联数组，类似于其他编程语言里的集合。它通过一个 key 可以找到对应的 value，这在编程中是经常用到的。

在实际开发中 map 用得非常多。比如我要保存一个学生的信息，**key 用学生的编号，value 用学生的名字**，这样就可以非常方便地把学生的信息管理起来。

#### 声明语法，以及 key 和 value 到底能用什么

map 的基本语法非常简单：

```go
var map变量名 map[keytype]valuetype
```

前面是一个关键字 `var`，然后是 map 的变量名，后面这个 `map` 是关键字、固定的。中括号里面写 key 的数据类型，后面写 value 的数据类型。

**key 可以是什么类型？** 在 Go 中 map 的 key 可以有多种数据类型：bool、数字、string、指针、channel（管道），还可以是只包含前面这些类型的接口、结构体和数组，都可以做 key。

但是大家想一想，用这几个做 key 其实非常奇怪，很少有人用接口、结构体或者数组去做 key。通常情况下 key 是什么类型？**通常是 `int` 类型或者 `string` 类型，90%、99% 都是用 int 或者 string 作为 key 的数据类型。**

> **易错点**：`slice`、`map`、还有 `function` 是**绝对不可以**做 key 的。为什么呢？因为官方的解释是——**没法用等号来判断**。言外之意就是说，将来 key-value 主要是用来做判断的，就是你有没有存在这个 key。

**value 可以是什么类型？** 它可以是的数据类型跟 key 基本上是一样的，就不赘述了。通常来说，值是数字，比如整数或浮点数；也可以是 string 类型，用 string 做 value 的类型也非常多；还可以是另一个 map，这样就构成了**多重 map**，这个用得也比较多；用得比较多的是 struct，也就是这个值是一个结构体——结构体我们后面马上就会讲到。

#### 声明 map 不会分配内存

现在来看一个 map 声明的案例：

```go
var a map[string]string
var a map[string]int
var a map[int]string
var a map[string]map[string]string
```

看最后一行：这里有一个 map，它的 key 是 string 类型，它的值又是一个 map，这个 map 里面的 key 是 string，值也是 string。也就是说 **map 其实可以有多重 map**。

这里我要强调一个特别重要的点：

> **结论**：**声明一个 map 是不会分配内存的，它没法用。** 初始化需要 `make`，分配内存过后才能赋值和使用。

这跟数组完全不一样——数组声明完了，它的内存空间其实就已经分配好了；但是 map 声明完了，空间是不会分配的，必须 `make` 之后才能赋值和使用。这一点特别重要。

打开 VS Code，新建 `chapter09` 专门讲 map，里面新建 `mapdemo01`，再新建 `main.go`：

```go
package main

import (
	"fmt"
)

func main() {
	// map 的声明和注意事项
	var a map[string]string
	fmt.Println(a)
}
```

`cd chapter09`，再 `cd mapdemo01`，`go run main.go` 跑起来。我们可以看到输出的是一个空的 `map[]`——因为你还没有做 `make`，所以说它是一个空的，什么都没有。

而且这个时候你给它赋值，它会报错：

```go
a["no1"] = "宋江"
```

这个就是 key，类型是 string，没写错；值也是 string。问题在于——此时此刻这个 map `a` 有没有给它分配空间？**没有。** 所以直接给它赋值，一定会报错。运行一下你就会看到一个 panic：

```text
panic: assignment to entry in nil map
```

也就是说你给一个空 map 赋值了，就报错了，因为你还没有数据空间。

> **提示**：这个错误用一个生活里的比喻特别好理解——就好比有一个人要去住一个房子，但是**这个房子都不存在**，他能直接住得进去吗？没有房子你怎能住得进去呢？所以这就报错了。

那怎么样才能使用呢？**在声明、使用 map 前需要先先 `make`。而 `make` 的作用就是给 map 分配数据空间。**

```go
a = make(map[string]string, 10)
```

注意 `make` 的写法：前面第一个参数要写上 map 的数据类型，把它的 key 类型和 value 类型都写进去；后面写上你给它 make 多大的一个空间，比如 10。这个 10 代表我给它分配了 10 个这样的空间，它可以放 10 对 key-value；当然它还可以动态变化，这个我们后面再说。

这时候再执行一遍，效果就完全不一样了：`map` 里面有个 `no1`，这是它的 key，宋江也出来了。

再给它一个：

```go
a["no2"] = "吴用"
```

现在 map 里应该就有两对 key-value 了。

#### key 不能重复，value 可以重复

我再给大家演示一个现象。如果我又给了一个 `no1`，然后这个地方我写的是武松，请同学们思考：**这里已经有个 no1 了，又给它一个 no1，那么在 map 里面它会怎么处理呢？它会报错呢，还是说它会覆盖呢，还是说它就直接追加一个呢？**

跑起来一看：此时此刻 `no2` 还是吴用，但 `no1` 变成了武松。

也就是说——**key 能不能重复？既然人家叫 key，那 key 就不能重复。key 是关键词的意思，在里面 key 是不可以重复的。你有一个 no1，再给一个 no1，它就把前面这个 no1 给覆盖掉了。**

那值可不可以重复呢？比如我再来写个 `no3`，值我还叫吴用，这个可不可以？

```go
a["no3"] = "吴用"
```

显然是允许的。因为 no2 叫吴用、no3 还叫吴用，这两个吴用肯定不会冲突，因为它们的 key 不一样。跑一下你就能看到：no1 叫武松、no2 叫吴用、no3 也叫吴用。

#### map 是无序的

而且大家有没有发现，在我们每次运行的时候，这个 key 实际上是无序的。这次输出的是 no1 武松排前面，然后是 no3、no2；再跑一遍又变成了 no3、no1、no2。

于是我们得出一个很重要的结论：

> **结论**：**map 并没有像我们想象的那样是有序的，map 其实是一个无序的 key-value 结构。** 很多编程语言里面的 map 是有序的，要么根据 key 来排序，要么根据添加的顺序排序。但是 Go 语言里面的 map 是完全没顺序的——它既不按照 key 来排序，也不按照你添加的顺序排序。

所以这块大家一定要小心。如果后面你拿到一个 map 想要排序，我们还可以讲排序的方法。

### map 声明与使用必须记住的四条

把上面这个案例做个说明，一共四条：

- **第一**，map 在使用前一定要 `make`。
- **第二**，map 的 key 是不能够重复的。如果重复了，则**以最后这个 key-value 为准**——刚才 `no1` 原先是宋江，后来又写了个 `no1` 是武松，那就以最后这个为准。
- **第三**，值是可以重复的。key 不能重复，但 map 的 value 是可以重复、可以相同的。
- **第四**，map 的 key-value 是**无序的**，key 和 value 都是无序的，请大家这块要注意。

最后还有一个关于 `make` 内置函数。手册里是这么说的：内建函数可以分配初始化一个切片或者映射，映射就是我们的 map。看映射这一条：**初始分配的容量取决于这个 size，但产生的映射长度为 0；size 可以省略，这种情况下只会分配一个默认大小的初始值。** 如果你不写，它默认就是一个。

关于 map 的基本介绍和它的声明，就先给同学们介绍到这里。

## map 的三种写法、嵌套结构，以及增删改查
> 对应块：BLK62 | 覆盖分集：P175-P176 | 块标题（分集名）：《174_尚硅谷_map三种用法和应用实例》

map 的使用方式和数组有些相似，但也有不一样的地方。我们总结了一下，**map 的使用方式一共有三种**，我分别给大家介绍一遍。你将来做开发的时候，看到别人用的不是我讲的那种写法，你也应该能有些反应——你不能说"老师讲的就是这种方式，其他方式我不能接受"，那就麻烦了，三种都必须能理解。

先新建文件夹 `chapter09`，里面建一个 `map_use`，再新建 `main.go`。

### 三种使用方式

#### 方式一：先声明，再 make，再赋值

这是前面已经讲过的那种：先声明，声明完了过后 `make`，`make` 完了再赋值。直接拿过来用就没问题，这是第一种方式。

#### 方式二：声明的时候直接 make

第二种方式就是说，在声明的时候直接就 `make` 一个空间，然后下面就可以赋值了。比如我这里要存放很多城市信息：

```go
var cities map[string]string = make(map[string]string)

cities["no1"] = "北京"
cities["no2"] = "天津"
cities["no3"] = "上海"

fmt.Println("cities=", cities)
```

我给它存放什么？key 为 string，值也为 string。大小我不写了，默认就行——这样就已经 make 好空间了，下面直接用。

大家看到没有？**我随便写，并不受它大小的影响，这跟数组不一样，我直接拿来用就行了，它会自动给你增长。**

`cd` 到 `map_use`，`go run main.go` 跑起来：`no1` 是北京、`no2` 是天津、`no3` 是上海，可以的。也就是说我们直接给它 make，然后直接就可以使用，这就是第二种方式。

> **提示**：这种方式用的也比较多，比较灵活，比上面那种感觉要稍微简单一点，不拖泥带水。**我个人一般推荐用第二种。**

#### 方式三：声明的时候直接赋值

第三种方式也有点意思，是在声明的时候直接就赋值。我声明完一个 map 过后，**直接给它值**——这里连 `make` 都没用到，但实际上底层里面它也给你 make 了。

```go
var heroes map[string]string = map[string]string{
	"hero1": "宋江",
	"hero2": "卢俊义",
}

fmt.Println("heroes=", heroes)
```

写法就是 `map[string]string`，然后直接写一对大括号，大括号里写上我们的 key-value 值就可以了。第一个英雄 `hero1`，冒号，写上宋江，逗号；第二个 `hero2`，冒号，卢俊义，好，其他以此类推我就不写那么多了。

不过你也可以说：老师，我就喜欢用类型推导。甚至你还可以写得更简洁：

```go
heroes := map[string]string{
	"hero1": "宋江",
	"hero2": "卢俊义",
	"hero3": "吴用",
}

fmt.Println("heroes=", heroes)
```

这样写更简洁——我直接有个 map，赋给 `heroes` 就完了。对，我们再加一个 `hero3`，排名第三的是吴用，把吴用也排进去。

> **易错点**：这里我保存完跑起来，老是报错——**少了一个逗号**。因为这个 map 即使是最后这一项，你也不能少逗号。语法过不去，编译器会告诉你这里期待一个分号之类的。加上逗号之后一跑，宋江、卢俊义、吴用全都有了。

顺便说一句：**这种写法做完之后，你也可以继续给它加东西。** 相当于在做这个声明的时候它已经给你 make 空间了，所以你在后面仍然可以用传统的方式来给它赋值：

```go
heroes["hero4"] = "林冲"
```

这样写也可以，配合使用，跑一下第四个林冲也出来了。

三种用法希望同学们都能掌握。我的建议是：**一般来讲我喜欢用第二种方式，比较清晰；第三种方式它这个是先赋值，有时候容易搞懵圈。**

### 课堂案例：存放三个学生的名字和性别

接下来是一个应用实例。演示一个 key-value 的案例：**要求存放三个学生信息，每个学生有名字和性别。**

大家思考一下应该怎么做。首先你一定要想，**这个 map 它是一个什么结构比较合理？**

如果这个学生信息只存放一个名字，其实挺简单的，key 为 string、值也为 string 就完事了。但人家说的是一个学生**既有名字、又有性别**，一个学生有两个信息，那怎么做？是不是我们这样设计更合理——**我们把值换成一个 map**。

原先的设计是直接写一个 string，key 是学生的学号，值是学生名字，就完了。现在一个学生有名字还有性别，怎么办？**我们直接再做一个 map，不就解决了吗？**

所以我们把这个值当成一个 map，那就简单了。这个 string 就是学生的学号，这个 map 里面我可以写两个，一个是名字，一个是性别，就完事了。这块是关键。

走代码。我用第二种方式，变量叫 `studentsMap`：

```go
studentMap := make(map[string]map[string]string)

studentMap["student01"] = make(map[string]string)
studentMap["student01"]["name"] = "汤姆"
studentMap["student01"]["sex"] = "男"
studentMap["student01"]["address"] = "北京长安街"

studentMap["student02"] = make(map[string]string)
studentMap["student02"]["name"] = "Mary"
studentMap["student02"]["sex"] = "女"
studentMap["student02"]["address"] = "上海黄浦江"

fmt.Println(studentMap)
```

这里有个地方一定要停下来看清楚：

```go
studentMap["student01"] = make(map[string]string)
```

`student01` 这个 key 是 string，**但它的值是不是一个 map？既然值是 map，那是不是还得 make 一下？** 因为值是 map，我们知道 map 必须先 make 才能用，所以这里马上再 make 一下。它至少要有两个，因为有名字和性别。

> **提示**：**只要使用到 map 就一定要 make**，你不 make 就会报前面讲的 panic 错误，提示不能分配。这句话绝对不能少，少了就会报错。

第一个学生放完之后，名字可以写进去了——第一个学生叫汤姆，性别记录下来是男性。这样通过他的学号就可以把这个学生的信息全部找到，甚至还可以更多。比如还想记录他的地址 address，也可以，比如这个汤姆住在北京长安街。

第二个学生以此类推，是 `student02`；因为第二个学生的值又是一个 map，所以你还要 make 一下。假设名字是 Mary、性别是女的、地址住在上海黄浦江。**编号也要给它改了，如果不改就把名字给冲掉了。**

运行一下，信息完全正确：第一个学生的 key 是 `student01`，里面有一个 map 记录了三个信息；第二个学生的 key 是 `student02`，里面也记录了三个信息。

当然也可以分开取。如果只想取出第二个学生的，把 key 写进去就行：

```go
fmt.Println(studentMap["stu02"])
```

如果想取出第二个学生的名字，也可以：

```go
fmt.Println(studentMap["student02"]["name"])
```

这样就很灵活了。

关于 map 的课堂练习就讲到这里。这里我们用到了一个相对复杂的 map 结构：**key 为 string，而值又是一个 map。**

### 增和改：写一行，看这个 key 在不在

下面讲 map 的增删改查。做项目的过程中必然会用到 map，而对 map 来说最重要的操作就是增加、删除、修改和查询。

**增加和更新**，更新就是修改。它的操作非常简单：前面写上 map 的名称，然后写上一个 key，再给它一个值。

这里会分两种情况：

- 如果这个 key 现在**还没有**，就相当于增加；
- 如果这个 key **已经存在了**，就相当于修改。

这一点我们前面已经体验到了。看案例：

```go
cities["no1"] = "北京"
cities["no2"] = "天津"
cities["no3"] = "上海"

cities["no3"] = "上海~"
```

写完前面三个之后再执行一个 `no3`，把它设置成"上海~"。因为 `no3` 这个 key 已经存在了，所以下面这句就是修改。运行一下你会看到，前面这个 `no3` 是上海，后面这个 `no3` 变成了上海~，说明修改成功。

> **结论**：**修改和增加其实主要取决于你这个 key 是否存在。** 同一行代码，因为 key 的存在与否，语义完全不同。

### 删：delete 内置函数

map 里面的删除用的是内置函数 `delete`。`delete` 的第一个参数写上这个 map 的名称，第二个写上这个 key。

> **定义**：`delete` 是一个**内置函数**，按指定的键将元素从 map 中删除。如果 key 存在，则删除这一对 key-value；如果 key 不存在，相当于不操作，**但是它也不会报错**。手册里还有一句：如果 `m` 为 nil，`delete` 不进行任何操作，同样也不报错。

因为它是内置函数，所以不用去引什么包：

```go
delete(cities, "no1")
fmt.Println("cities=", cities)
```

执行一下你会发现，`no1` 北京已经没有了，说明删除成功。

那如果我再继续删除，故意写一个 `no4`，显然 `no4` 是不存在的。我们可以看到**它在代码里面并没有报任何错误**，删除之后它仍然还是那个样子。

> **注意**：当 `delete` 指定的 key 不存在时，删除就不会操作，**也不会报错**。这一点请大家注意。

### 想一次性清空整个 map

这里有个细节。如果要删除一个 map 所有的 key，有些编程语言里面的 map 确实有像 `clean` 这样的方法，可以一次性把 map 所有的 key 全部删掉。但很遗憾，**Go 里面没有这样一个方法**。

那如果我要把 map 里面所有 key 一次性清空怎么办？有两个办法。

**方案一：遍历这个 key，把它们遍历一次，然后逐个删除。** 这要用到遍历的知识，后面我们讲 map 如何遍历的时候会讲。学完遍历之后你也可以用 for 循环一把，然后用 `delete` 一个一个删。但相对来说，稍微麻烦一点。

**方案二：让这个 map 重新分配一个空间。** 你重新 `make` 一个新的空间，让原来的成为垃圾，让 GC 回收就完事了：

```go
cities = make(map[string]string)
```

你只要这么一执行，相当于这个 `cities` 指向了一个新的空间，那原先它指向的那些数据空间就成为一个垃圾被回收掉了，就扔掉了，让系统回收。跑一下你就会看到这个 `cities` 空了。

> **提示**：这个方案肯定比逐一删除效率要高，而且也比较简单。**如果你想把一个 map 里面所有的 key 全部清空，我推荐你按第二个方案。** 第一个方案因为涉及到遍历，等你学完遍历之后也可以用，但确实没有第二个方法简单。

### 查：value, ok := m[key]

最后是查询。我们想去看看一个 map 里面有没有这个 key，该怎么做呢？其实可以直接去取这个 key：

```go
value, ok := heroes["no1"]

if ok {
	fmt.Printf("有 no1 这个 key，值为%v\n", value)
} else {
	fmt.Println("没有 no1 这个 key")
}
```

取这个 key 它会**返回两个数据**：一个是 `value`，一个是返回的结果。

- 如果确实有这个 key，`value` 就是这个值，`ok` 为 `true`；
- 如果没有，`value` 是零值，`ok` 为 `false`。

变量的名字其实是可以随意的，我这里写的是 `value` 和 `ok`，你写个 `findRes` 也行，这个无所谓。通过这种方式我们就可以判断到底有还是没有。

跑起来试一下。第一次提示"没有 no1 这个 key"——那确实没有，因为我上面不是用 `delete` 把这个 `no1` 已经干掉了嘛。那我换一个，换成 `no2` 跑起来，提示的信息是：**有 `no2` 这个 key，值为天津**，完全正确。

到这里，map 的增加和更新、删除、查找就全部介绍完了。在后面写项目的时候，我们会经常使用到 map 的增删改查操作，请大家注意一下。

## map 的遍历、map 切片，以及给无序的 map 排个队
> 对应块：BLK63 | 覆盖分集：P177-P179 | 块标题（分集名）：《176_尚硅谷_map的遍历》

map 的增删改查讲完了，接下来把三件事一起收掉：**怎么遍历 map、怎么把一堆 map 装进切片动态增长、以及 map 无序了怎么办。**

### 遍历：为什么只能用 for-range

> **结论**：**map 的遍历必须使用 for-range，不能用普通的 for 循环。**

为什么？大家想一想。我们在用 for 循环遍历的时候，拿到的其实是数组的**下标**，它是按一个数字来的，对吧？但是我们知道 map 的 key 不是数字——它不一定是一个 1、2、3 这样的东西，它可能是个字符串。所以说在 map 遍历的时候，咱们只能用 for-range。

新建目录 `map_traverse`，新建 `main.go`。我们用前面那个比较简单的、方式二做的 map（`no1`、`no2`、`no3`）来遍历一下，把它的每一对 key-value 都遍历出来：

```go
for k, v := range cities {
	fmt.Printf("k=%v v=%v\n", k, v)
}
```

第一个是它的 key，第二个是它的值，因为它是键值对，然后 range 一下 `cities`。输出用 `Printf`，格式写成 `k=%v v=%v
`。

`go run main.go` 跑起来：

```text
k=no1 v=北京
k=no2 v=天津
k=no3 v=上海
```

这个时候你用 for 循环肯定做不了——因为 for 循环认为下标都是像 0、1、2、3 这样子的，但我们看到它不是这样子的。

#### 双层 for-range：遍历嵌套的 map

这是一个比较简单的 map。我们再拿一个比较复杂的 map 给大家做案例——还记不记得前面那个练习吗？学生信息，它的值**又是一个 map**。我们把它遍历一遍。

因为它的值又是一个 map，所以我们遍历的时候其实要进行一个**双层遍历**，要 for-range 两次：

```go
for k1, v1 := range studentMap {
	fmt.Println("k1=", k1)
	for k2, v2 := range v1 {
		fmt.Printf("\tk2=%v v2=%v\n", k2, v2)
	}
}
```

这里 `k1` 就是 `student01`、`student02` 这样的值，而 `v1` 又是一个 map，因此我们在里面再进行一次 for-range，那就是 `k2`、`v2`。这个 `v2` 就是具体的名字、性别这些具体的值了——range 对谁进行遍历？对 `v1`。

为了好看，我先在前面把 `k1` 输出出来，然后再把 `k1` 对应的里面的信息——名字、性别、地址——输出出来。**内层的换行之前加一个制表符 `\t`，这样子就有一个层级关系在里面了。**

跑起来你看：

```text
k1= stud01
	k2=name v2=tom
	k2=sex v2=男
	k2=address v2=北京朝阳
k1= stud02
	k2=name v2=mary
	k2=sex v2=女
	k2=address v2=上海浦东
```

信息是不是很准确？第一个 `k1` 是 `student01`，它里面又是一个 map，这个 map 里有三对 key-value：地址、名字、性别；上面那个 `student02` 也是一个 key，下面同样对应三对 key-value。这个层级关系大家应该能看出来。如果我再加一个学生，它同样也会被遍历到。

通过这种方式，我们又演示了一个结构比较复杂的 map 的遍历——**这里用到了双层 for-range**。后边做比较复杂的业务逻辑时，就会用到这种双层 for-range 循环来遍历 map。

### 用 len 统计 map 的长度

想知道一个 map 有多少对 key-value？用内置函数 `len`。这个 `len` 前面我们已经用过了——统计数组长度的时候用的就是它，统计 map 有多少对 key-value 也可以用它：

```go
fmt.Printf("cities 有 %d 对 key-value\n", len(cities))
```

跑一下，输出显示 **cities 有 3 对 key-value**——`no1` 北京是一对，`no2` 天津又是一对。

当然你也可以这样去统计 `studentMap`，也是一样的道理：如果直接统计它有多少对 key-value，它应该返回 2，因为你有一个 `student01`、还有一个 `student02`，只是它里面对应的这个值又是一个 map 而已。

关于 map 的增删改查，到这里就全部介绍完毕了。**尤其要注意：进行 map 遍历的时候要用 for-range，不能使用常规的 for 循环。** 别人问你为什么，你告诉他——因为 map 的 key 不一定是数字，即使是数字也不一定是连续的数字。

### map 切片：把 map 装进切片里

前面我们讲过切片，切片可以存放一组数据，你可以把它理解成是动态的数组。但是 map 也可以对应一个切片——**你可以把它理解成是动态的 map。**

前面我们这样写：

```go
[]int
```

这是个切片，只不过里面放的类型是 `int`。但如果这一个类型不是 `int`，而是 map 了，各位同学，那么这个我们就叫 **map 切片**，英文叫 slice of map。这样使用的话，我们 map 的个数就可以动态地变化了。前面你可以动态地增加一个 int，那我就可以动态地增加一个 map，这就更灵活了。

#### 案例：记录若干个妖怪的名字和年龄

要求：**使用一个 map 来记录 monster 的信息，有名字和年龄。** 也就是说一个 monster 对应一个 map，而且**妖怪的个数是可以动态增加的**——比如我先记录一个狐狸精，然后我又记录一个玉兔精，我还可以再加一个牛魔王。

每个妖怪的信息保存在一个 map 里面，但妖怪的个数是变化的。所以这里我们就会用到 map 切片，因为 map 切片正好满足"map 的个数可以动态增加"这个要求。

新建文件夹 `mapslice`，新建 `main.go`。

**第一步，声明一个 map 切片：**

```go
var monsters []map[string]string
```

对不对？切片是不是前面有一个中括号？然后它的类型就是 `map`，而这个 map 是 `string, string`——因为一个 map 里面存放的是一个妖怪的信息，存放名字和年龄就行了。

**第二步，切片本身也要 make：**

```go
monsters = make([]map[string]string, 2)
```

我预计先放两个妖怪，所以我先写 2。这里要特别提醒大家注意：

> **易错点**：**这里要 make 两次！** 第一个，切片本身要 make；第二个，切片它对应的这个数据类型是 map，也要 make，这样才能使用。因为 map 是要 make，切片本身也是要 make 的。我们这个地方上来过后先要对它进行一个 make，不然的话后面也会报错。

**第三步，添加第一个妖怪。**

```go
if monsters[0] == nil {
	monsters[0] = make(map[string]string, 2)
	monsters[0]["name"] = "牛魔王"
	monsters[0]["age"] = "500"
}
```

如果第一个妖怪它等于 nil，就是说现在还没有分配，我先给它分配一个空间；既然对应一个 map，那我就给它分配一个 map 空间。因为我要存放名字和年龄，就先写个 2。然后往里面放东西：`name` 对应牛魔王，`age` 对应 500 岁。

> **注意**：这里值必须是字符串，所以 `500` 要写成 `"500"`，因为 map 里的 value 是 `string`。写成整数是不行的。

跑一下：第一个 map 里面有名字牛魔王、age 是 500；还有一个 map 为什么是空的？因为我现在还没有往里面放数据。

**第四步，添加第二个妖怪。** 同样的道理：

```go
if monsters[1] == nil {
	monsters[1] = make(map[string]string, 2)
	monsters[1]["name"] = "玉兔精"
	monsters[1]["age"] = "400"
}
```

玉兔精，400 岁。这样一来，我们这个切片里面就有两个妖怪，而且每个妖怪的信息是放在一个 map 里面的。跑一下，后面这个 map 也有信息了。

#### 加第三个就报错了，所以必须用 append

好，问题来了：**假设我们要加第三个妖怪，我这样写还可以吗？** 比如叫狐狸精，300 岁。

同学们想一想，我原先 `make` 的是几个空间？是不是两个呀？但你现在给第三个赋值了，肯定会报一个错误。跑一下你就会看到：

```text
index out of range
```

有些同学就说：老师，那简单嘛，你把这个写成 3 不就完了吗。是的，写成 3 肯定正确，这个你放心。但是——**你并不知道将来人家要放多少个妖怪**，难道你写得很大吗？写得太大是不是浪费空间？

有些同学还会想：我上来就把它整得很大，整到 2000 个行不行？那我问你，假设我妖怪有 3000 个怎么办？写 3000 个？那我要是 3001 个，你又怎么办？**你始终是没办法满足的。**

所以有些时候我们需要它能够动态增加，而不能事先就把 `make` 的空间搞得很大。

**正确的做法是用切片的 `append`**。切片有一个内置函数叫 `append`，它可以动态增长。怎么动态增加？非常简单，三步：

**第一步**，先创建一个 monster 的信息——monster 本身就是一个 map，我们先用最简单的方式直接给它赋值：

```go
newMonster := map[string]string{
	"name": "火云邪神",
	"age":  "200",
}
```

**第二步**，把这个 monster 加到这个切片里面，用 `append`：

```go
monsters = append(monsters, newMonster)
```

**第三步**，接收一下，完事。

```go
newMonster := map[string]string{
	"name": "火云邪神",
	"age":  "200",
}
monsters = append(monsters, newMonster)
```

这里有个地方特别容易写错，我来跑的时候它就报错了：`append` 这儿为什么错了？编译器已经把话说得很清楚了——**你不能把 `newMonster` 再赋给它自己，你这不是自相矛盾吗？** 正确做法是：我把 `newMonster` 追加到 `monsters` 上，把结果再赋给 `monsters`。这样就是在这个基础上追加了一个。

保存一下，没问题了，代码非常清晰。跑起来，你会看到结果就正确了：**第一个 map 是牛魔王，第二个 map 是玉兔精，第三个 map 是火云邪神。**

这样我们就可以通过 map 切片来动态地增加 map 了。将来如果要动态增加，我只要创建一个新的 monster 的 map，然后 `append` 一下就完事了。**哪怕我只给你分配了两个空间，你需要多少我就加多少，这才是正确的做法。**

这块在我们开发中用得比较多，你不要小看这个知识点。如果你没有把 map 切片搞清楚，那么我们就不知道怎么动态地增长 map 这种数据类型。

### map 排序：先排 key，再按 key 输出

最后是 map 的排序。首先要清楚一点：**map 默认是无序的，而且 Go 语言里面并没有一个专门针对 map key 进行排序的方法，确实没有。** 其他编程语言里面，map 的 key 要么是有序的，要么就有专门的方法，但 Go 语言里面没有。

我们举个例子说明这件事。新建文件夹 `map_sort`，新建 `main.go`，先写一个 `map1`：

```go
var map1 = make(map[int]int, 10)
map1[10] = 100
map1[1] = 13
map1[4] = 56
map1[8] = 90

fmt.Println(map1)
```

跑起来，输出的顺序是这样子的：**8、1、4、10**。

我们看这是什么顺序？它并不是按照 key 从小到大，也不是按照从大到小；而添加顺序是 10、1、4、8，它也不是 10、1、4、8。所以这个顺序其实是完全无序的。你再跑一遍，它又可能发生变化，这次变成了 1、8、10、4。

> **结论**：**Go 语言中的 map 默认是无序的，注意它也不是按照添加顺序存放的，每次遍历得到的输出可能很不一样。** 据说 Go 语言的设计者先前是按某个顺序排的，默认有一个顺序，但有相关的程序员提出"这个 map 最好是无序"，所以这个功能就被去掉了。不管怎么样，它就是无序的。

那我们要让它排序怎么办呢？方法在这里：**Go 语言中的排序是先将 key 进行一个排序，然后根据这个 key 遍历输出即可。**

思路就三步：

- **第一步**，先把 map 的 key 放入到切片中。
- **第二步**，对这个切片进行排序。
- **第三步**，遍历切片，然后按照 key 来输出 map 的值。

#### 三步走一遍

**第一步，先定义一个切片**，很简单，就叫 `keys`：

```go
var keys []int
```

大家看到这儿是不是一个切片？这个切片里面是放 `int` 的。

然后我们遍历这个 map，把它的 key 取出来：

```go
for k, _ := range map1 {
	keys = append(keys, k)
}
```

遍历过后这里就会拿到这个 key，我们把这个 key 放进去——这个值我先不用它，直接忽略掉就行了，把它追加到 `keys` 里面。

**第二步，排序。** 排序有一个专门的包叫 `sort`，它有一个方法叫 `Ints`，接受一个切片，**按照递增顺序排列**。当然这个包里还有别的排序方法，很多，我这里用的是递增的方法：

```go
sort.Ints(keys)
fmt.Println(keys)
```

> **易错点**：第一次执行会报错，因为**你没有引入这个包**。用到人家的函数了嘛，得 `import "sort"`。加上之后一执行，可以看到 key 就按照 1、4、8、10 的递增顺序排列了。

**第三步，遍历切片，按照 key 来输出 map 的值。** 遍历切片很简单，一个是 `i` 一个是值；这里面我要的是值——这个值就是我们的 key：

```go
for _, k := range keys {
	fmt.Printf("map1[%v]=%v \n", k, map1[k])
}
```

注意，第一个是它的下标，第二个是它的值，值就是我们的 key。输出格式化成 `map1[k]=值`，把值也取出来——**把 `map1` 写进去，写上它的 key，就把它的值取出来了**。每取一次给它一个换行。

跑起来你就会看到：

```text
map1[1]=13
map1[4]=56
map1[8]=90
map1[10]=100
```

此时此刻它就稳定了。我们再运行一次，这个顺序是稳定的、固定的，按照 key 的递增顺序来输出我们这个 map。

这个就是我们 map 的一个排序处理。

所以，如果同学们将来在做开发的时候有一个业务需求，比如**我们要按照价格的高低，或者按照学生的编号来输出学生信息**，那就要用这种写法：先把它的 key 遍历出来放进一个切片里，然后遍历这个切片把 key 取出来，再输出对应的 map 值。这样就是按照 key 的一种顺序来显示我们这里面的值了。

完整代码：

```go
package main

import (
	"fmt"
	"sort"
)

func main() {
	// map的排序
	var map1 = make(map[int]int, 10)
	map1[10] = 100
	map1[1] = 13
	map1[4] = 56
	map1[8] = 90
	fmt.Println(map1)

	// 如果按照map的key的顺序进行排序输出
	// 1. 先将map的key放入到切片中
	// 2. 对切片排序
	// 3. 遍历切片，然后按照key来输出map的值

	var keys []int
	for k, _ := range map1 {
		keys = append(keys, k)
	}
	// 排序
	sort.Ints(keys)
	fmt.Println(keys)

	for _, k := range keys {
		fmt.Printf("map1[%v]=%v \n", k, map1[k])
	}
}
```

关于 map 遍历、map 切片和 map 排序，就介绍到这里。这三块连起来正好构成了一条完整的线：**先用 for-range 把 map 读出来，需要动态扩充的时候用 map 切片，需要有序输出的时候用 sort 把 key 收进切片。** 后面的项目里这些都会用到。

## map 的使用细节与综合案例，以及结构体为什么必须出场
> 对应块：BLK64 | 覆盖分集：P180-P182 | 块标题（分集名）：《179_尚硅谷_map使用细节和陷阱》

map 的增删改查讲完了，接下来把三件事收尾：**map 的使用细节、一个综合课堂练习，以及——为什么下一个章节必须讲结构体。**

### map 是引用类型

第一点非常重要：**map 是一个引用类型的数据类型。** 既然它是引用类型的，它就要遵循引用传递的机制——如果我们用一个函数来接收一个 map，修改过之后，会直接修改原来的 map。

跟切片一样，切片是引用类型，map 也是引用类型。请大家注意这一点。

我们举个例子来证明这个特点。新建文件夹 `map_details`，新建 `main.go`。先写一个函数：

```go
func modify(map1 map[int]int) {
	// 确保确实有一个 key 为 10，把它改成 900
	map1[10] = 900
}
```

然后在主函数里声明一个 map 并放点东西：

```go
map1 := make(map[int]int, 2)
map1[1] = 90
map1[2] = 88
map1[10] = 1
map1[20] = 2

modify(map1)
fmt.Println(map1)
```

我们观察一下：此时此刻这个 `map1` 里面 key 为 10 的这个元素的值，它是 1 还是 900？

- 如果是 **900**，说明底层的确是引用传递；
- 如果仍然是 **1**，那说明它默认是值拷贝。

`cd map_details`，`go run main.go` 跑起来——**key 为 10 的变成了 900**。这就说明，当我们把这一个 map 传给 `modify` 这个函数过后，它在里面的修改会直接影响到 `main` 里面的 `map1`。

> **结论**：**map 是引用类型。** 这个特点我们通过这个例子就说得非常清楚、非常到位了。

### 容量满了会自动扩容

第二个细节：**map 容量达到后，再想向 map 增加元素，会自动地扩容，并不会发生 panic。**

这一点其实前面已经说过了，我再把它系统地整理到这个位置。还以上面这个案例说话：我在 `make` 的时候故意只写了个 2，默认它最多只有 2 个的位置。但实际上我往这个 map 放数据，放到 `map1[10]` 的时候其实就已经超过 2 了，**但是它仍然没有报错**，跑起来仍然是正确的。

这说明什么？说明我们的 map 确确实实可以自动扩容。

> **提示**：**这跟切片不一样，切片不可以自动扩容，得用 `append` 才行。** map 能够动态地增长键值对。

### map 的 value 更适合用结构体

第三个细节很重要：**map 的 value 经常会使用到结构体，它更适合管理复杂的数据，比我们前面那个 value 用 map 更好。**

还记得前面我们记录学生信息吗？当时我是用一个 map 来记录的。其实**这个并不好，用 map 记录这个学生信息并不好管理**。那用什么比较好呢？**用结构体这个数据类型比较好。**

非常遗憾就是因为我们还没有学习结构体，所以我只能先在这里写一下，让大家体验一把。不要说"老师你还没讲结构体怎么就用结构体了呢"——因为结构体马上就要讲了，而且结构体本身也不是很难的。

我们用 map 的 key 还是学号，然后它的值用结构体来完成。

**第一步，先定义一个学生结构体：**

```go
type Student struct {
	Name    string
	Age     int
	Address string
}
```

大家可能看不太懂的，大家体验一下，我再说一遍，只是体验一下。这里边有三个元素：Name、年龄和 Address。第一个 Name 是名字，string 类型；年龄 Age，用 int 类型；还有一个是家庭住址 Address，string 类型。

**第二步，有了学生结构体过后，声明一个 map：**

```go
students := make(map[string]Student)
```

我待会儿要放很多学生进去。它还是 map，key 我们用 string，但它的值我用的是这个结构体。默认给它来 10 个学生吧，当然你也可以不写。

**第三步，创建两个学生：**

```go
student1 := Student{"tom", 18, "北京"}
student2 := Student{"mary", 28, "上海"}
```

怎么去创建一个学生呢？非常简单，其实就是把这个结构体拿过来，在里面写上它的信息就可以了。因为它比较简单，三种属性直接这样给值就行了，不用键值对的方式给，比较简单。

**第四步，把这两个学生放进 map 的值里：**

```go
students["no1"] = student1
students["no2"] = student2

fmt.Println(students)
```

跑一下你会看到：这个结构体的信息就输出来了，而且很清晰。map 里面 key 为 `no1`，它是个结构体，里面是 tom、18、北京；第二个 key 为 `no2`，是 mary、28、上海。

> **结论**：**这样子是不是更好一点？** 因为你将来这个结构体的数据可以很轻松地增加它的组成部分——比如说再增加一个属性，就很轻松了。

**顺便把遍历也写了：**

```go
for k, v := range students {
	fmt.Printf("学生的编号是 %v \n", k)
	fmt.Printf("学生的名字是 %v \n", v.Name)
	fmt.Printf("学生的年龄是 %v \n", v.Age)
	fmt.Printf("学生的地址是 %v \n", v.Address)
	fmt.Println()
}
```

`k` 就是学生的编号，`v` 就是一个结构体。虽然结构体我们还没正式学，但大部分同学能看出来——**`v.` 就是把这个结构体的属性取出来，或者叫元素取出来都可以。**

跑一下，信息非常清晰：第一个学生的编号是 `no1`，名字、年龄、北京；第二个是 `no2`，名字、年龄、上海。

所以在我们实际开发中，这个 value 更多的情况下是用结构体这种数据类型。大家应该能感受到，**这种方式来保存和管理数据更加方便，也更加灵活。**

### 课堂练习：modifyUser，改密码或者加用户

来看一个 map 的课堂练习。这个练习相对来说综合一点，使用到 map 的各个方面的知识点。我们看一下要求。

首先是 map 的结构：**它的 key 是一个 string，它的值是不是又是一个 map？** 看清楚没有？

- **key 表示用户名，是唯一的，不可以重复。**
- **如果某个用户名存在，则将其密码修改为"888888"；如果不存在，就增加这个用户信息，包括它的昵称和密码。**

从这个要求我们就能判断出来：它的值里边应该有两对 key-value——昵称和密码。

要求你写一个函数叫 `modifyUser`，接收两个参数：一个是这个 map 本身，第二个传一个名字进去，完成上述功能。说白了就是他给你传一个用户名进去，然后你去判断这个 map 里面有没有。如果有，你就把密码改成"888888"；如果没有，就增加这个用户信息。

需求很简单，也涉及不到什么编程思想，按这个套路走就行了。在 `chapter09` 里面新建文件夹 `exercise`，新建 `main.go`。

```go
package main

import (
	"fmt"
)

func modifyUser(users map[string]map[string]string, name string) {
	// 前面我们学过，判断 map 中是否有某个 key，可以这样写：
	// val, ok := users[name]
	// 这里我换一种写法，让大家看得更多一点
	if users[name] != nil {
		// 如果用户名存在，就将密码修改为 888888
		users[name]["pwd"] = "888888"
	} else {
		// 如果用户名不存在，就增加这个用户信息
		// 注意：值是 map，必须先 make
		users[name] = make(map[string]string, 2)
		users[name]["pwd"] = "888888"
		users[name]["nickname"] = "昵称~" + name
	}
}

func main() {
	users := make(map[string]map[string]string, 10)

	modifyUser(users, "tom")
	modifyUser(users, "mary")

	fmt.Println(users)
}
```

这里有两个点要特别讲清楚。

**怎么判断这个 map 里面有没有这个名字？** 前面我们学过一个东西——取出这个值，然后配一个 `ok`：`val, ok := users[name]`，通过 `ok` 就可以判断。上面那个写法是可以的。这里我换一种用法，让大家看得更多一点：`if users[name] != nil`。如果有这个用户，它就不等于 nil；如果没有，就等于 nil。

**新增的时候，第一步必须先 make。** 记住这句话：

> **易错点**：你不能一上来就直接往里面放东西。比如"老师，我知道他没有 pwd，我直接给 pwd 一个密码行不行？"**不行。** 为什么？因为这个名字都还没有，你这样直接用肯定直接报错了——**因为你这个 name 对应的这个 map 是不是还没有 make？** 所以第一步应该先把这个名字对应的 map make 出来。至于这个 map 里至少有几对 key-value？**至少两对**，因为人家说了要有昵称和密码。

至于昵称，按理说这个地方应该再传一个昵称过来，但他没有传，我就示意一下拼一下就行了：`"昵称~" + name`。这是示意代码，如果你想做得更好一点，可以再传一个昵称参数 `nickname string`，这样也可以。

跑起来你就会看到：tom 的密码是"888888"，昵称是"昵称~tom"；第二个人 mary 的密码是"888888"，昵称是"昵称~mary"，完全正确。

**那如果事先已经有这个用户了呢？** 比如我先给他加一个 smith：

```go
users["smith"] = make(map[string]string)
users["smith"]["pwd"] = "999999"
users["smith"]["nickname"] = "小花猫"

modifyUser(users, "smith")

fmt.Println(users)
```

因为 smith 的值对应的是个 map，所以**也得先 make 一下**，你不 make 没法用。再说一遍，一定要理解。

同学们想一想，如果我在这里也把 smith 传进去，进去过后他应该走哪个逻辑？**走 if 那个分支**，所以 smith 的密码就会变成"888888"，同时 **smith 的昵称不会发生变化**，还是小花猫。跑一下你就会看到结果正是这样，说明我们的代码走对了分支——他走的是这个 if 分支，而没有走 else 分支。

到这里，我们就把 map 的各个方面全部介绍完了。后边写项目、写爬虫，包括我们后面写流量统计这个项目的时候，都会用到 map 这样的相关信息。

> **注意**：**尤其是 map 里面如果值还是个 map 的话，一定要搞清楚，要 make 两次。** 这是我们初学 Golang 的时候经常容易犯的错误，请大家一定要重视。

### 下一个话题：为什么必须有结构体

关于 map 就全部讲完了。下一个章节，我们开始介绍 Golang 里面的**面向对象编程**，或者叫做面向接口编程。

先开宗明义把一个点讲清楚：**Go 语言的面向对象编程跟传统的面向对象编程——比如 Java、像 .NET——还是有很大区别的。** 传统意义上说，我们应该把面向对象这个地方引起来。也就是说，Go 语言的面向对象其实不是传统意义上的面向对象编程——**因为在 Go 语言里面没有类的概念，没有 class。它用一个叫做结构体的东西，来替代了类的概念。也就是说，结构体在面向对象里面的地位，类似于 class。**

所以大家在听 Go 语言面向对象编程的时候，要注意它跟传统面向对象里面**相似的地方和不相同的地方**。如果你曾经学过别的面向对象编程语言，那你要注意在 Go 语言里面有很多跟你们以前学的不太一样，注意这个特性。

#### 一个养猫的问题

我们从一个问题引出结构体。张老太太养了两只猫：**一只叫小白，今年 3 岁，白色；还有一只叫小花，今年 100 岁了，花色。** 请编写一个程序，当用户输入小猫名字时，就显示猫猫的名字、年龄、颜色；如果输入小猫名错误，则提示没有养这只猫。

这个题如果交给你，你会怎么完成？有什么思路？

我们现在不是已经学了一段时间 Golang 了吗？那如果这个问题交给你，我相信同学们可能有两种思路：**第一种用单独定义的变量来解决，第二种用数组来解决。** 当然有同学说老师我还可以用 map——你用 map 你试试看，看看到底好不好解决。

我为什么要先用传统的方法来解决？就是因为要让大家感受到：**如果使用传统方法解决，它有什么缺点。从而引出结构体，你就一下秒懂结构体跟别的数据类型有什么不一样的地方，以及结构体有什么好处。**

新建 `chapter10`，在里面建一个 `struct01` 文件夹，新建 `main.go`。我们先用传统的方法来解决这个养猫的问题。

#### 方案一：用一堆变量

第一只猫：

```go
var cat1Name   string = "小白"
var cat1Age    int    = 3
var cat1Color  string = "白色"
```

第二只猫：

```go
var cat2Name   string = "小花"
var cat2Age    int    = 100
var cat2Color  string = "花色"
```

因为你有两只猫，每一只猫都有三个属性：名字、年龄和颜色。为了记录两只猫的信息，**你需要定义六个变量**。

同学们，你们看看现在它的问题是不是已经出现了？如果张老太太是一个养猫比较着迷的老太太，她养的不是两只猫，她养的是 20 只猫，你想你要定义多少个变量？这还不算——一只猫它现在只有名字、年龄和颜色，**假设我还要记录这个猫的爱好、它喜欢吃的食物，或者这只猫的其他特性，你是不是还得变化呀？**

所以你用变量来处理的时候，先不说别的，**你已经发现定义变量就已经很吃力了**。你看下面已经没法写了，确实没办法写了。而且你即使找到这只猫，你要把它的信息取出来也很困难——**因为你没办法通过一个变量来把它的所有属性取出来，根本就做不到。**

#### 方案二：用数组

有些同学说老师，我用数组来解决。可以啊。你想想这个怎么解决。

一只猫猫它的属性类型都不一样：名字是 string，年龄是 int，颜色又是 string。所以你用数组来解决，可能只能这样写——先有一个数组记录猫的名字：

```go
var catNames [2]string = [...]string{"小白", "小花"}
```

然后你又觉得，还有 ages 记录年龄的：

```go
var catAges [2]int = [...]int{3, 100}
```

然后这还有它的颜色：

```go
var catColors [2]string = [...]string{"白色", "花色"}
```

你们琢磨琢磨，下面的代码还能写下去吗？

**你找到小白这个名字，你要找到它的年龄，其实很难找到，因为它们都不在同一个数组里面去。**

**同样，你们用 map 来解决也会出现这个问题。** map 虽然可以记录，名字写一个、年龄写一个，问题是**它的 map 也有类型的问题**——你把名字保存了，就不能保存这个年龄，它数据类型也要一致。名字、年龄还有其他信息也得分开记录，数据仍然是分开的。

#### 传统方法到底差在哪

我们发现现有技术的解决方案至少有下面两点缺陷：

**第一，使用变量或者数组来解决养猫的问题，都不利于数据的管理和维护。** 为什么这么说？一只猫有三个属性——名字、年龄、颜色——其实都是属于一只猫的，但是这里被分开保存了。**它本身是一个整体，却被分开保存，这显然不利于数据的管理和维护。**

**第二，如果将来需要对猫的属性进行操作，也就是说要绑定一个方法，这个地方也很难做到。** 什么叫属性呢？就是刚才所说的名字、年龄、颜色。要去操作它们，数据都已经分散开来了，要去操作是不是很困难？**所谓操作其实就是写绑定方法，这个地方非常不好处理。**

既然通过传统方法，我们说出了"用单独变量和数组不好处理"这种情况，那就自然引出了我们要讲解的技术——**结构体**。结构体就在这里应运而生了。

到底结构体是个什么东西、它有什么特点，我们在下面这个章节为大家详细介绍。在这里我们就把结构体的引出问题讲完了：为什么需要结构体？因为现在的传统技术很难解决，**即使你用 map 也不好处理**——它的数据类型是单一的，不能混着用。如果你用 map 的话，你会发现名字、年龄还有其他信息也得分开记录，数据仍然是分开的。

传统方法不好的问题，一个是**不利于管理和维护**，同时**我们要对它属性进行操作也不好处理**。因此我们就引出了结构体这个概念。
