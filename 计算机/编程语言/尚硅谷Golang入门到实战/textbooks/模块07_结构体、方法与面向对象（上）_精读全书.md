## Go 的面向对象：一个程序就是一个世界
> 对应块：BLK65 | 覆盖分集：P183-P185 | 块标题（分集名）：《182_尚硅谷_Go独树一帜的面向对象特点》

在前面我们说了，用传统方法解决一些问题不好解决，于是引出了结构体的概念。现在要回答一个很关键的问题：**结构体和我们熟悉的面向对象编程，究竟是什么关系？**

### 先把"对象"这两个字说清楚

我曾经讲过一句话：一个程序它就是一个世界。

现实世界有什么东西，在我们编程里面就会有相应的体现。现实生活里有房子、有树、有人、有狗、有小雪人，那么在我们编程里面，它也会有很多对象。在面向对象里，我们把这个称为对象。

但是——**对象其实就是一个变量**，明白吗？它就是一个变量。

所以我讲结构体的时候，有时候会这样阐述："现在我们创建一个结构体变量。"也可能这样说："同学们，我们创建一个结构体对象"，或者直接简称"我们来创建一个对象"。这两种说法、很多种说法，含义其实都是一个意思：说白了就是一个变量，只是这个变量的类型不一样。

一般来讲，在 Go 语言里，如果这个变量是个结构体类型，那么有些程序员会直接把它叫作对象。理解这个意思就行了，不要过多地纠结这个概念。

> **定义**：Go 里的"结构体对象"就是"结构体类型的变量"。两种叫法，一个含义。

> **提示**：编程的时候不要把程序显得很神秘。其实程序写多了、复杂度越高，它就越像一个现实的社会、现实的世界。我有些学生后面去做网游开发、做游戏开发，做着做着自己就发现了——游戏里的那些人物，包括它的行为、它的属性，跟现实生活中非常相似。你只要有这个概念，就会觉得编程也是很好玩的一件事。

### Go 面向对象编程的五个特点

Golang 里面的面向对象编程，跟传统纯度很高的面向对象语言还是有很大区别的。跟 Java、`.NET`，甚至跟 PHP 都有很大区别。如果你曾经学过这些语言，你就会突然感觉到：Golang 其实在面向对象编程里面做了**很多的简化**。

下面的内容都是概念性的东西，听起来可能有点抽象，忍耐一下。因为我必须先把这些概念理清楚，我们才能正式去写代码。

#### 它支持面向对象编程特性，但纯度不高

第一个特点：Golang 也支持面向对象编程。面向对象又叫 OOP，OOP 就是 Object-Oriented Programming。工作以后别人问你"你会 OOP 编程吗"，你别一脸很懵——OOP 就是面向对象编程的简称。

但是它的面向对象跟传统的面向对象有很大区别。为什么有区别？

因为在 Golang 里面它**并不是纯粹**的面向对象编程语言。所以我们经常这样说：**Golang 支持面向对象编程特性**。这个说法是比较准确的。

> **易错点**：Java 的面向对象纯度很高，它没有所谓的全局变量，所有东西都在对象里。而 Go 有很多全局变量的概念，还有全局函数，所以它不是纯度很高的面向对象。说"Golang 支持面向对象编程特性"是精准的，别去硬套 Java 那套。

#### 没有 class，只有 struct

第二点，在 Golang 里面没有传统面向对象里的 `class` 了。

那谁来充当 `class` 的角色呢？是一个叫**结构体**的数据类型，`struct`。它用 `struct` 来替代类的地位。所以我们可以认为，Go 语言的结构体和其他编程语言的类**有同等的地位**。

Golang 正是基于 `struct` 来实现 OOP 特性的。

#### 简洁：拿掉了一堆东西

第三点，Golang 面向对象编程非常简洁。它去掉了传统 OOP 语言的一些特性：

- **继承**：不能说没有继承的概念，它是有的，但是没有 `extends` 这个东西了，而且它的继承跟传统 OOP 继承还有很大区别，后面我们会展开；
- **方法重载**：这个确实拿掉了，Golang 里面没有方法重载的概念；
- **构造函数**：没有；
- **析构函数**：没有；
- **`this` 指针**：没有。

这些统统拿掉了。

那有些同学会跳出来说："我学过 Java，`this` 指针怎么没讲？"

它已经拿掉了，怎么讲啊？是不是？它肯定是用别的方式来实现这种功能的，肯定会有这种体现，只是跟以前的传统方法完全不一样了。注意听这句话。

#### 仍然有继承、封装、多态

第四点，Golang 仍然有面向对象编程的继承、封装和多态特性。它还是有这些特性的，只是实现方式跟其他 OOP 不太一样。

比如继承吧：传统面向对象里，继承是通过 `extends` 关键字实现的；而 Golang 里的继承是通过**匿名字段**实现的。具体怎么做，后面再具体说。

> **结论**：面向对象编程实际上是一种**思想**，不要过度地去拘泥于它的形式。每种语言实现的方式已经有变化了。谁敢说 Golang 没有面向对象编程的思想和特性，那他一定是乱说。只是 Golang 这个家伙出来以后，跟以前传统的面向对象变化得太大了，所以有些同学学起来感觉很奇怪——但它确实还是有这些特性的，只是实现方法不一样了。

#### 优雅：本质上是一门面向接口的语言

第五点，Golang 的 OOP 非常优雅。为什么这么说？

因为 **OOP 本身就是语言类型系统的一部分**。你可以这样理解：Golang 本身就是一种天然支持面向对象的语言。而且它通过**接口关联**可以降低耦合性，这非常灵活。

有些用 Go 用得比较多的程序员、还有一些书上，更喜欢把面向对象编程叫做**面向接口编程**。

为什么这么说？因为接口其实是 Go 语言面向对象编程里面最重要的一个特点。Go 中面向接口编程是非常重要的特性，它好多东西都可以用接口来实现——这一点，它把接口用到了极致，我可以这么讲。Go 里面面向对象的接口用得特别特别多，而且用得非常巧妙，耦合度非常低。这个后面你们会逐渐地感受到。

### 结构体和结构体变量：一类事物与它的实例

上面这五个特点说的东西没有代码，确实抽象，但必须先点题。因为听的人里面有很多是学过 Java、`.NET`、PHP、Python 或者 C++ 的，点过题你心里才有数。

现在我们来看结构体到底是什么东西。我举的例子还是猫。

猫有很多种类：波斯猫、花猫、中华田园猫，各种各样的猫。这些猫总会有相同的特征——名字、年龄、颜色，我们姑且把它叫做字段，或者属性；也总会有相同的行为——猫都会叫、都会吃东西、都会睡觉、都会做算术题等等，这些行为体现出来就是后面要讲的方法。

那么，当把这些共同的特征和行为**提取出来**，放到一个数据结构、一个数据类型里面，我们就把这个数据类型叫做**结构体**——也就是 `Cat` 结构体。

有了结构体，我们就可以通过这个数据类型创建多个变量，也就是多个实例（有些程序员直接叫对象）。

```text
      一类事物                 多个具体的个体
   提取共同特征与行为
   得到一种数据类型
 -------------------> Cat (struct) --------> cat1   cat2   cat3
                                            (变量/实例/对象)
```

怎么理解这个关系？`int` 是不是一种数据类型？但 `int` 可以有很多变量：可以写个 `a int`，`b` 也是个 `int`，对吧？`Cat` 结构体是同一样的道理——我可能是小黄猫、小花猫、小白猫等等。

所以这个关系就是这么来的：**提取形成一个数据类型，这个数据类型叫结构体；然后通过这个结构体创建各个变量。**

这个思路是可以拓展的：这一类事物到底是一类什么事物，要根据你的编程需求来定。可以是猫，也可以是人（`Person`）、鱼（`Fish`）、某个工具类等等。

> **易错点**：创建了一个 `Cat` 结构体变量，还是定义了一个 `Cat` 结构体变量？两种叫法都对，叫法不一样，含义一样，不用纠结。

### 快速入门：用 struct 解决养猫问题

既然对结构体有了认识，那现在就快速入门一个案例。用面向对象的方式、也就是用我们的 `struct` 来解决养猫问题。这时你突然发现，用结构体来解决养猫的问题，**突然变得简单而且高效了**。

打开 VS Code，我们既不用单个变量，也不用数组，现在用结构体。先定义一个 `Cat` 结构体，把 `Cat` 的各个字段信息放入到 `Cat` 结构体进行管理。

```go
type Cat struct {
	Name  string
	Age   int
	Color string
}
```

第一个是名字，字段名叫 `Name`，类型是 `string`；还有一个年龄，`Age`，是 `int` 类型的；还有一个 `Color`，`string`。

大家看，我字段名是用大写开头，说明什么？说明将来这个字段它是可以公开的。还有一个是 Hobby。这几个字段，有大写开头的，也有小写开头的。

大家看，此时此刻你是不是突然发现：**我们有一种数据类型，可以把它的字段统一进行管理，而不再是分散的了**。你刚才那个单独的变量、还有数组，必须是分散的；现在我把这一个猫的所有属性放在一个 `struct` 里面管理，是不是更方便了？

下面接着看。有一只猫叫小花，我们先创建一个 `Cat` 的变量。`Cat` 是个结构体，我怎么创建呢？非常地简单：

```go
var cat1 Cat
```

这样就写完了。这个 `cat1` 是个什么类型？就是 `Cat`。它是不是特别像以前写的 `var a int`？只是你的变量名叫 `a`，它现在叫 `cat1`；你的类型是一个 `int`，现在是一个结构体。实际上这个 `int` 到后面你会发现，它也可以绑定自己的方法——这正是为什么我说 Golang 的面向对象是一种天然的。

有了这个过后就可以用了。注意，当我们定义这个猫过后，其实这个猫的这些字段**已经分配了**，因为它是值类型。你们不相信的话，可以打印出来看一下：

```go
fmt.Println(cat1)
```

我们跑起来看看。大家注意观察，是不是有个 `0` 呢？有些同学说："老师不对啊，你不是有三个属性吗？"

是的，我确实是有三个属性，但是第一个属性其实是一个**空的字符串**，默认值嘛——字符串不给值默认就是个空串，所以你看不见。而这个 `0` 呢，就是那个年龄的默认值。

也就是说：当我们去创建一个结构体变量时，其实它的空间就已然分配了。只是因为你还没有给值、没有给每一个字段赋值，因此默认为空串、默认为 `0`。

> **易错点**：这里是值类型，后面我们还会讲细节，不要着急。

但是我肯定不希望它是默认值，我要给它赋值。赋值的方式很简单，就是变量名点它的字段名就可以了：

```go
cat1.Name = "小白"
cat1.Age = 3
cat1.Color = "白色"
```

它不是一只猫吗？这只猫其中有一个字段叫 `Name`，叫什么名字啊？叫小白。还有一个年龄，3 岁。还有一个 `Color`，白色。写完了。

大家再看一下执行的效果，是不是已经出来了？第一个字段、第二个、第三个都出来了。而且大家有发现，这个时候管理也非常方便——如果想去输出一个猫的信息，只要知道这个结构体的名称，其他的就按照它的字段名来访问就行了。

好，信息就非常清晰了。

我们再往下走一步。假设我们要增加一个字段——猫猫还有一个它喜欢吃的食物，比如 `Hobby`：

```go
type Cat struct {
	Name  string
	Age   int
	Color string
	Hobby string
}
```

那这个地方你固然可以不给它赋值，它也不错，只是默认是个空嘛。这个猫猫的爱好是什么呢？它的爱好是**吃鱼**。

一执行，效果非常有意思——**鱼没有输出来**。为什么？因为我给它的字段名写成了小写：

```go
cat1.hobby = "吃鱼"
fmt.Println("猫猫的爱好是", cat1.hobby)
```

`undefined`。这地方我小写了，那我把它改成大写，改成大写。当然因为 Go 是区分大小写的，这块我必然也要跟着改，不然肯定是要出问题的。

好，都改成大写之后再跑一下。此时此刻，吃的是鱼。完事。

是不是很方便？而且不但可以这样做，还有一个好处——现在还不能讲，就是什么呢？它不但可以给这个猫把属性统一管理，而且还可以给这个猫**绑定方法**。比如我们这个小猫通过学习可以做算术题，还可以给这个类型绑定它的方法。当然，绑定方法除了给这个结构体绑定，给基本数据类型也可以绑定，后面我们还会说这个事情。

总而言之，这种方式肯定是特别利于我们去管理数据、或者字段比较多的这种事物。

> **易错点**：`fmt.Println` 里那个 `undefined` 的报错，根源就是字段名首字母小写。Go 里字段名大写开头代表公开，小写代表包内私有，赋值和读取必须一致。
>
> **结论**：面向对象编程关于结构体的入门代码，本质就是两块——**定义结构体**，和**创建并使用结构体变量**。

### 结构体是类型，结构体变量是它的实例

用完案例，我们来总结一下结构体和结构体变量的区别和联系。

通过前面讲的案例我们可以看出：**结构体实际上是自定义的一种数据类型**，这一点就把它的本质提取出来了。结构体是你自己定义的一个数据类型，它代表的是一类事物，比如猫、比如猫类；而结构体变量、实例是一个具体的、实际的东西，代表一个具体的变量。

前面写的代码里，我们定义了一个结构体，其实它代表的是一类事物，就是猫；但是当我们做了 `var cat1 Cat` 这样一个动作过后，这个 `cat1` 就是一个实实在在的个体了，是一个结构体的变量、具体的对象。

> **结论**：结构体是一种数据类型，它的变量是它的一个具体实例。记住这一条就够了。

### 结构体变量在内存中的布局

下面有一个非常重要的知识点：把结构体的内存布局画一下——结构体变量在内存中是怎么存在的。

这块比较重要，希望你们注意听，这块是个重中之重点。

就以刚才的猫为例。我们这个 `Cat` 结构体，现在在这里创建了一个猫的对象实例，现在我们来看看这个 `cat1` 在内存里面是如何存在的。

当我们执行完 `var cat1 Cat` 这一句话的时候，它在内存里面是这样子存在的：

首先会有一个变量名 `cat1`；这个变量它会指向一个空间；这个空间有几部分呢？它有四个字段，所以说我们要画的话，它在这里面存在有四个部分。

```text
+--------------------- MEMORY ---------------------+
|                                                    |
|   cat1  ------>  +---------------------------+   |
|                   |  Name  : ""              |   |
|                   +---------------------------+   |
|                   |  Age   : 0               |   |
|                   +---------------------------+   |
|                   |  Color : ""              |   |
|                   +---------------------------+   |
|                   |  Hobby : ""              |   |
|                   +---------------------------+   |
|                                                    |
|   &cat1 = cat1 自身的地址                            |
+----------------------------------------------------+
```

读图说明：`cat1` 这个变量名直接**指向了**存放四个字段的数据空间，每个字段都已经分配，并且因为还没有赋值，所以各自取了自己类型的默认值——`Name`、`Color`、`Hobby` 是空的 `string`，`Age` 是 `0`。

它存在的形式跟我们这个结构体本身的数据类型是密切相关的。而且——这个 `cat1` 自己有没有地址呢？**它也有地址。** 虽然它是一个结构体，它有它自己的地址，我们把地址也输出出来给大家看一下：

```go
fmt.Printf("cat1 的地址是 = %p\n", &cat1)
```

既然是地址，那 `cat1` 就用取址符 `&`。我们可以看得出，它本身确实是有一个地址的。

> **结论**：通过这个图你们有没有发现，我画的这个图是**直接让它指向**这的，那说明我们这个 `cat1` 是什么类型的？**是值类型，而不是引用类型。** 这一点希望你们注意区分。因为有很多编程语言里面，它结构体不一定是值类型；但在 Go 里面，它的结构体其实就是一个值类型——因为它是直接指向它的数据空间的，并没有先指向一个地址，再让这个地址去指向一个数据空间。

接着往下看。等它下面做了一个 `cat1.Name` 的时候，它就通过这个 `cat1` 访问到它 `Name` 这个字段，然后给它取了一个名字叫"小白"。然后它又执行了一个 `cat1.Age = 3`，那就把这个变成了 `3`。下面它又把这个 `cat1.Color` 变成"白色"，那就是说这个地方是空字符串就变成了"白色"。紧接着它下面写了一个 `cat1.Hobby = "吃鱼"`，那这个地方就改成了"吃鱼"。

```text
+--------------------- MEMORY ---------------------+
|                                                    |
|   cat1  ------>  +---------------------------+   |
|                   |  Name  : "小白"           |   |
|                   +---------------------------+   |
|                   |  Age   : 3                |   |
|                   +---------------------------+   |
|                   |  Color : "白色"           |   |
|                   +---------------------------+   |
|                   |  Hobby : "吃鱼"           |   |
|                   +---------------------------+   |
|                                                    |
|   &cat1 = cat1 自身的地址                            |
+----------------------------------------------------+
```

执行完这段代码以后，内存就变成"小白"、`3`、"白色"和"吃鱼"了，因为你代码就是这样去执行的。

从这个图我希望你们至少领会到两个结论：**第一点**，当我们声明一个结构体变量时，数据空间已经有了，而且在你没赋值的时候，它每一种数据类型的默认值也给它了；**第二点**，从这个图我们可以看出来，结构体变量、也就是结构体，它是**值类型**。

就这两点。这个图很重要，一定要好好地理解一下。基于这个图，后面我们就会有很多细节展开。

## 结构体怎么声明、字段有哪些细节，以及创建实例的四种方式
> 对应块：BLK66 | 覆盖分集：P186-P187 | 块标题（分集名）：《185_尚硅谷_结构体声明和使用陷阱》

前面其实我们已经用过结构体的声明了。现在把它系统地讲一遍，顺便把字段的概念、你手底下最容易踩的坑，一次性说透。

### 结构体是怎么声明的

它的基本语法就是这样子：

```go
type 结构体名称 struct {
    field1 type
    field2 type
}
```

这里面的 `type` 和 `struct` 是**关键字，不能改**。中间那个标识符就是我们的结构体名称，它可以根据自己的实际情况随便写，比如前面我们写的 `Student`。

大括号里面就可以写上你的字段了——你有多少个字段就写多少个。第一个是字段的名称，第二个是字段的类型。

```go
type Student struct {
    Name  string
    Age   int
    Score float32
}
```

非常简单，前面已经用过很多次了。

> **易错点**：注意大小写。如果这个结构体类型的首字母是大写的（这里是 `S`），那就意味着你定义的这个结构体类型可以在其他包被使用；如果这个字段的名字是大写的，那就意味着你这个字段的数据可以被其他包引用。小写的话就成为私有了，只能在本包使用。这一点跟前面讲变量的作用域是一致的。

### 字段、属性还是 field：说的是同一件事

这一节我要专门把这个概念抛出来讲一下，就是怕同学们在听课或者看书的时候，因为叫法不一样，造成一种混淆的理解。

字段，有些人叫属性；有些书上直接叫 `field`，就是"字段"的意思。因为我们学的 Go 语言其实是老外搞的，所以书在翻译的时候可能就不一样：有些叫字段，有些叫属性，有些干脆叫 `field`。

**这三个概念几乎可以认为说的是同一个事情。**

有些程序员说："你给我加一个字段进去。"有些程序员说："你在这个结构体里面加个属性。"甚至有些英文学得比较好的程序员直接说 "the field 是什么"。

所以在我授课的过程中，干脆我们就统一叫**字段**了。如果不是特别说明，我就直接叫字段。这样大家达成一个统一，听起来就比较轻松一点。

### 字段能装什么：基本类型、数组、引用类型

字段是结构体的一个组成部分。一般来讲，**字段的数据类型可以是基本数据类型，也可以是数组，同时也可以是引用类型**——就是咱们能用的几乎它都可以使用。

比如前面我们写的那个猫结构体，`Name string` 就是一个字段，它里面也可以是数组。打比方说，我写个数组进去：猫它有很多成绩，比如这个猫要考试，它有数学成绩、有语文成绩，那我可以定义一个数组 `scores`。它有三门成绩，这也是可以的。

跑一下你就知道会怎么样。当你还没有赋值的时候——大家应该猜得出来——因为你给它有一个字段是数组，数组是有三个元素的一维数组，它就直接给你分配到这儿了。

当然，有些同学问：如果是二维数组可不可以？当然可以，这个我就不再一个个举例了。

> **结论**：字段类型只能是三种——基本数据类型、数组、引用类型。几乎没有例外。

### 字段的零值，和引用类型必须先 make

下面是字段使用的注意事项和细节，一共四点，我们一个一个来。

**第一点**，字段声明的语法和变量是一样的：先是字段的名，再是字段类型。字段的名字、类型，其实跟声明一个基本变量是一样的。

**第二点**，字段的类型可以是基本类型、数组或引用类型——这块刚才已经说过了。

**第三点**，创建一个结构体变量后，如果没有给字段赋值，那么它都对应一个**零值**，也就是默认值。这个零值分别是什么呢？规则和前面讲的是一样的：

| 字段类型 | 零值 |
| --- | --- |
| 布尔类型 | `false` |
| 数值（整型、浮点型） | `0` |
| 字符串类型 | `""`（空字符串） |
| 数组类型 | 同元素类型，比如 `[3]int` 是 `0 0 0`，`[3]string` 是三个空字符串 |
| 指针、slice、map | `nil`，即还没分配空间 |

重点要说第三点里的最后一行：**如果你的字段是指针、slice 或者 map，它们的零值都是 `nil`——即还没分配空间。你要用的时候，首先要 `make` 才能用。**

我们举个例子，就重点讲清楚指针、slice 和 map 怎么用。因为前面的基本数据类型像布尔、数值、字符串，我们都比较简单。

新建一个文件夹，我们取个叫 `fielddetails`，就是字段的意思。新建一个文件 `main.go`。

```go
type Person struct {
    Name   string
    Age    int
    scores [5]float64
    ptr    *int
    slice  []int
    map1   map[string]string
}
```

两个基本数据类型 `Name`、`Age` 不说了；考试成绩 `scores [5]float64`，他考了有五门课；我认为这里面他还有一个指针 `ptr *int`；再有一个切片 `slice []int`；再定义一个 map `map1 map[string]string`。

现在我想来使用这个东西。我们先定义一个结构体变量：

```go
var p1 Person
```

根据刚才画的图，你们可以想象到是一个什么情况？这前面三个字段是有的，但是因为后面这几个是引用类型，它们**指向别的地址**。而这个时候它们默认这个地方的空间还没有放地址——你可以这么理解：现在它们还没有指向任何一个地址，也就是说它们目前的值其实是 `nil`，你还不能用。

何以证明呢？打印出来看一下：

```go
println(p1)
```

跑起来。我们可以看到：前面有个 `0`（名字是空串看不到），这个是它的成绩；然后有一个 `nil`，这个 `nil` 就是我们那个指针；还有一个也是空的；map 也是空的。是不是跟以前讲的一样？因为它现在没有分配空间，所以实际上这三个都是 `nil`，只是它输出不一样而已。

如果你这样判断的话，也可以得到相同的结果：

```go
if p1.ptr == nil {
    fmt.Println("ok1")
}
```

我们一执行，发现进来了。同样道理，那我把这个 `slice` 也比较一下：

```go
if p1.slice == nil {
    fmt.Println("ok2")
}
```

运行之后 `ok2` 也输出来了，那说明你这个引用类型没有给它分配空间，它也是 `nil`。第三个问题：如果我把这个也取出来，`map1` 的 `ok3` 会不会输出？同学们思考一下——因为你还没 `make`，此时此刻 map 对应的这个值是不是也是 `nil`？你一执行就会发现这个 `ok3` 也输出了。说明这三个都是 `nil`。

那问题来了："老师，那我如果现在就想用它，怎么用呢？"比如说，我现在想在这个 `slice` 里面放些数据进去，可不可以呢？

```go
p1.slice[0] = 100
```

注意听，第 0 个，因为它是切片嘛，它是一个 `int` 类型的，我就给它来一个 100。请问，这个地方会不会报错？

显然会报错。因为你 slice 现在还没有 `make`，你就直接拿来用了。我们在前面讲切片的时候是不是反复强调过一点：**切片必须先 `make` 才能用。** 你可以负责任地告诉大家，你一执行就会报一个错误——`panic: index out of range`，第 38 行，正是这一行。

那你就是要给它赋值怎么办呢？那你得按照以前我们规定的那样去做，首先要 `make`：

```go
p1.slice = make([]int, 10)
```

给它 `make` 一个空间出来，否则的话人家是不会让你用的。数据大小假设为 10。

再跑一下。走，我们发现这个时候代码就没报错了。此时这个 slice 肯定就不等于空了，把它输出来看效果：

```go
p1.slice[0] = 100
fmt.Println(p1)
```

大家看到这里，有变化了。原先在你没有给它 `make` 空间的时候，切片是一个空的；等到你 `make` 了一个 10 的时候，它就变成这个了——因为你给它 `make` 了 10 个，然后第 1 个元素你给它赋了一个 `100`，这样就可以了。

这个原理在示意图里其实已经说清楚了：

```text
     p1  ──>  [ Name | Age | scores |  ptr  |  slice  |  map1  ]
                                  nil      nil      nil

                        执行 p1.slice = make([]int, 10) 之后：

                                  |
                                  +──> 0x1111 ──> [ 100, 0, 0, 0, 0, 0, ... ]
```

读图说明：刚开始的时候，如果它是引用类型，其实都没有指向一个空间；等它 `make` 过了，这边就会指向一个具体的位置，就会引用到一个空间了。它这里存的只是一个**地址**（比如 `0x1111`），地址指向一个真实的空间；那个空间是什么样子，就根据你这个 map 也好、切片也好，自己来做。

> **易错点**：使用切片时一定要先 `make`。再次说明，一定要先 `make` 再使用。不要上来就像刚才那样直接拿来给它赋值、直接拿来就给它建键值对，都不行的。

**第四点**，最后一个细节注意听，也很重要：**不同的结构体变量的字段是相互独立的，互不影响。** 一个结构体变量的字段更改，不会影响到另外一个。

这个我也要严重地说明一下。为什么呢？因为**结构体是值类型**。这点是特别特别重要的，不要把结构体搞成引用类型了。

### 结构体变量之间为什么互不影响

我们来看一个小小案例，大家体验一下。这里已经有 `Person` 了，我们再定义一个别的结构体：

```go
type Monster struct {
    Name string
    Age  int
}
```

这个结构体我们叫 `Monster`，妖怪。妖怪有名字和年龄，我就留两个就行了，简单一点。

我们来定义两个妖怪：

```go
var monster1 Monster
monster1.Name = "牛魔王"
monster1.Age = 500
```

现在我做了这样一个动作，注意听：

```go
monster2 := monster1
```

有个 `monster2`，我把 `monster1` 赋给了它。

那我问大家一个问题：

```go
fmt.Println("monster1 =", monster1)
fmt.Println("monster2 =", monster2)
```

这个时候这两个结构体它们输出的内容是不是相同的？（顺带提醒，写的时候要小心，我一开始就手滑把 `monster` 写成了 `Monster`，大小写不一致直接就报"没有定义"。）

执行一下。我们看到这个结果，它们是相同的，都是牛魔王和 500 岁。但是，我在这做一个动作，请注意观察。我写 `monster2.Name`，我把这个 `monster2` 的名字改成青牛精。

**当我把 `monster2` 的名字改成青牛精过后，请问 `monster1` 有没有影响？**

告诉大家，其实刚才我已经讲过了：因为它们是值类型，也就是说这个 `monster1` 赋给 `monster2` 的时候，其实它是一个**值拷贝**。既然它是一个值拷贝，青牛精的改变并不会影响到牛魔王。

看效果，走一个。我们可以看到，上面这个还是牛魔王，下面是青牛精。那也就说明它们确确实实默认是值拷贝。

为什么呢？为了让大家彻底明白这件事，我还是想画一个示意图，就是 `monster1` 赋给 `monster2`，它在内存里面到底发生什么事情了。不要嫌我麻烦、啰嗦，这个是很重要的。

```text
     monster1  ──>  [ Name : "牛魔王" | Age : 500 ]      ← 一块独立的数据空间

     monster2  ──>  [ Name : "青牛精" | Age : 500 ]      ← 另一块独立的数据空间
```

读图说明：当 `monster1` 创建好过后，它会指向它自己的一个数据空间，里面放着两个字段"牛魔王"和 500 岁。等到执行 `monster2 := monster1` 这一句时，它把整个这个东西**完整地复制了一份**，一模一样地复制了一份，然后创建了一个新变量 `monster2`。这个 `monster2` 跟 `monster1` 是没有关系的，它又指向了它自个儿的空间。所以在内存里边，`monster1` 和 `monster2` 是完全独立的两个数据空间——因此我后面通过 `monster2` 把"牛魔王"改成"青牛精"，肯定不会影响到 `monster1`。

当然有同学说："老师，假设我就是想让 `monster2` 改变会影响 `monster1`，可不可以呢？"

当然也可以。但是这个时候咱们传的就是**地址**了。你传的地址的话，这个就变成一个**指针**了。这个就变成一个指针，你这样用，看，这个时候你直接用它可能会报错，对吧？

这时候它也没报错，这是做了优化了，后面我们再说这个吧，先不把它搅在一起了。如果我们后面想通过 `monster2` 去修改 `monster1`，后面再说。**至少现在呢，我们可以看出来，默认的结构体赋值是值拷贝，是值类型。**

> **结论**：想通过 `monster2` 去改变 `monster1` 也是可以的——你要想办法让 `monster2` 也指向这个空间。怎么让一个结构体赋的是地址呢？其实说白了就是**赋一个地址给它**。我把地址给一个变量，`monster2` 它也就指向同一块空间了。那这个时候你通过 `monster2` 把"牛魔王"改成"青牛精"，`monster1` 也就跟着变化了。但在默认情况下，它是值拷贝。这个图一定要认真理解。

### 创建结构体实例的四种方式

我们来看一下创建结构体变量和访问结构体字段的四种方式。

#### 方式一 var 加类型名

```go
var person Person
```

第一种方式前面我们已经讲过、也已经做过了，所以说这块就不多说了。

#### 方式二 类型推导加大括号

还有一种方式，大家有时候会看到有人这么去用：前面是 `var`，然后是变量名，然后是结构体类型名，然后一对大括号——大括号里面也可以带值。

它也可以这样写，甚至还可以直接这样：

```go
p2 := Person{}
```

注意，当你这样做的时候，其实就已经创建好了，它里面已经有默认值了。我们输出看一下：

```go
fmt.Println(p2)
```

运行一下，是不是它这个时候其实也有默认值了？

当然你这个时候也可以这样赋值：

```go
p2.Name = "tom"
p2.Age = 18
```

那样子就会有新的值进去，就是根据你的赋值情况，它会把值放到相对应的字段里面去——`tom`、18。

甚至有些人在大括号里面直接把值写进去，也是可以的：

```go
p3 := Person{Name: "Mary", Age: 20}
```

我们知道第一个是字符串，就写个 `Mary`，然后 `Age` 直接写个 20。这样就直接在定义这个 `Person` 的时候，把它的字段的值写进去了。运行一下请看效果，直接输出 `Mary` 和 20。

#### 方式三 new

方式三就是 `new`。大家都知道有些程序员是学 Java 的，在 Java 里面创建对象通过关键字是用 `new` 的。在 Go 里面它也支持 `new`，但是 **`new` 出来的实际上是一个指向 `Person` 的一个指针**。

```go
var p3 *Person = new(Person)
```

此时此刻我告诉大家，它就是一个指针。所以有些同学可能看 `p3 := new(Person)` 看不太懂，我就这样写，大家看得更明确点。

如果是指针，我们怎么给它赋值呢？因为这个 `p3` 是一个指针，因此**标准的**给字段赋值的方式应该是这样的：

```go
(*p3).Name = "smith"
(*p3).Age = 30
```

是不是这样子我就找到了——用 `*` 这个取值符先把它 `p3` 的结构体变量找到，然后再点里面的 `Name`。

那输出一下：

```go
fmt.Println(*p3)
```

这样输出过后，就把史密斯的信息输出出来了。史密斯，30，拿到了。

但是这种写法注意听，**这种写法有点啰嗦**。标准的给字段赋值方式确实应该这么写，但是 Go 语言的设计者做了一个简化。他说因为这种写法很多程序员并不习惯，所以为了让程序员用起来比较方便，他做了一个简化，它也等价于这个东西：

```go
p3.Name = "john"
```

这样写也可以。但实际上这种写法其实很难理解，因为你 `p3` 本身是一个**指针**，指针怎么去点这个属性呢？这样写为什么可以成功呢？

原因是这样子的：**Go 的设计者为了程序员使用方便，在底层对这个东西做了一个优化。** 你这写的是 `p3.Name`，但实际上编译器在底层会把这个 `p3` 加上取值运算。也就是说，你写的是这个样子，但底层会把它处理成 `(*p3).Name` 的形式。所以它这样写也不会报错。

比如说我把名字再改一次，改成 John。那我问一下，此时输出的时候是"史密斯"还是 "John"？显然应该是 `John`，因为你先给它赋了一个值，我再重新赋了一个值，相当于把前面这个值覆盖了嘛。运行一下看效果，输出的名字就是 `John`。同样的道理，年龄也可以这样访问，我把它改成 100 岁，那这个时候就应该是 John 100 岁。

那我这里主要是要给大家强调：**标准的写法是 `(*p3).Name`，但是 Go 设计者为了让我们使用方便，也允许写成 `p3.Name`。** 只是我们在写代码的时候可以不用知道这个事情，编译器帮我们做这个工作，底层会做这个处理。

> **提示**：面试官问你的时候，你一定要答得上来说：这两种写法是等价的，标准写法是 `(*p3).字段名`，但 Go 的编译器在底层会对 `p3.字段名` 自动加上取值运算。

#### 方式四 取地址符

第四种方式也可以用取地址符 `&` 来进行这个处理：

```go
person := &Person{}
```

因为大家知道 `person` 已经是一个指针了，所以说标准的访问其字段的方法也应该是这样：

```go
(*person).Name = "scott"
(*person).Age = 88
```

先用一个取值符找到我们的结构体，然后再 `.Name` 给它赋值。我们看看标准写法这样用了过后，能不能输出正确的信息。输出一下这个 `person`，跑一个，没有任何问题。

同理，有人说："老师，那我用这个方法呢？`person.Name` 也可以。"注意听，这些都很重要，不然的话你以后完全看不懂别人写的代码。那我故意这样改一下，然后最后这个结果应该是 `scott~` 和 10，因为相当于把前面这个给覆盖了。运行一下，请看效果。

还有一点我要说一下：**这种写法也可以直接在这个括号里面给它赋值，也是允许的。** 比如说直接给它赋一个值叫 `Mary`，然后给它一个年龄 60：

```go
person := &Person{Name: "Mary", Age: 60}
```

因为你后面又重新赋值了，肯定就把它覆盖了。假设我这儿没有后面那两句改变，那么我在创建的时候直接赋了一个 `Mary` 和 60，请问这时输出什么？还会是空字符串和 0 吗？

显然不会。这时它就会输出 `Mary` 和 60，因为你在创建的时候就直接给它的字段赋值了。跑一下，请看效果，输出的是 `Mary` 和 60。注意这个细节。

#### 四种方式怎么选

四种方法同学们都要掌握。有些同学说："老师，那你喜欢哪一个呢？"

其实就看情况。我一般来讲会用方式二——在创建 `person` 的时候直接赋值，直接给它就完事了，它直接就是一个结构体。但这个时候它是**结构体变量**，不是指针。方式二也是我们在开发中用得比较多的，推荐大家使用方式二。

当然，你将来在做开发的时候到底用哪一种，要根据项目的要求而定。但至少我们要能看得懂，你不能说这种写法我就看不懂了，也是不行的。

### 四种方式的三个使用细节

把它整理一下，前面四种方式：

**第一点**，方式三和方式四返回的其实是**结构体的指针**。前面已经反复强调过了。

**第二点**，结构体指针访问字段的标准方式应该是：

```go
(*结构体指针).字段名
```

比如 `(*person).Name = "tom"`，这是标准的用法。

**第三点**，Go 做了一个简化，它也支持：

```go
结构体指针.字段名
```

你比如刚才讲的这个，其实就是结构体的指针点字段名。那为什么你可以这样用呢？按理说你是不能这样用的——指针怎么去点字段名呢，这是不被允许的。但是这种写法为什么被支持？

原因是：**Go 语言的设计者认为这样更符合程序员使用的习惯。** Go 的编译器在底层里面会对这个 `person.Name` 做一个转换，真正编译的时候也会把这个东西重新加进去，只是这个转换的过程被隐藏到编译器的底层了，我们程序员不可见。

所以别人面试的时候问你"为什么结构体指针点 Name 可以用"，你得告诉他：其实是 Go 的设计者为了方便支持了这个，但底层仍然还是 `(*person).Name` 这种方式在用。

> **结论**：这两种方式都可以用。一般人都会喜欢使用简写这种方式，简单嘛，直接点一下就完了，何必还要写个星号呢。但别人用取值这种方式在用，你也要理解，这才是真正的用法，只是比较麻烦一点。

这四种方式一定要搞清楚。不然的话，以后别人写代码的时候突然写了一个这个东西出来，你立马就懵圈了，看不懂了。而且这种结构体在我们的面向对象里面其实用得非常的多，请大家一定要高度重视。

## 结构体的内存分配机制：值拷贝与传地址
> 对应块：BLK67 | 覆盖分集：P188 | 块标题（分集名）：《187_尚硅谷_结构体内存分配机制》

前面我们已经给大家讲了一些关于结构体在内存里面的布局，对不对？但是还不够深入，还不够深入。因此我们在这里有必要把结构体这种类型在内存里面分配的机制，再做一个系统和深入的讲解。

### 先做个思考题，把值拷贝再回顾一遍

先看一段代码，这里有一个思考题：这段代码大家先思考一下，它会输出什么？来，我们一起来看一下。

```go
type Person struct {
	Name string
	Age  int
}

func main() {
	var p1 Person
	p1.Age = 10
	p1.Name = "小明"

	var p2 = p1

	fmt.Println(p2.Age)

	p2.Name = "汤姆~"

	fmt.Println(p2.Name)
	fmt.Println(p1.Name)
}
```

首先我定义了一个 `Person` 结构体变量，然后我给它赋了一个值，`Age` 这个字段给了一个 10，`Name` 这个字段给了一个小明。然后我把 `p1` 交给了 `p2`。

这句话执行的时候，在内存里面会出现一个什么情况呢？默认会有一个 `p2`，还有一个 `p1`。`p1` 会指向一个数据空间，这个空间里面将会有名字——`p1` 原先指向了一个数据空间，里面有小明，还有一个年龄是 10 岁。当我们把 `p1` 交给 `p2` 的时候，进行一个**值拷贝**——因为我们知道结构体这种数据类型默认它是值拷贝的，因此 `p2` 也会有一个数据空间，`p2` 指向自己的空间。这时它会把小明还有年龄也拷贝过去。

紧接着在这里我输出了 `p2.Age`，请问这时输出什么内容？显然它输出的这个年龄就应该是 `10`，没问题吧？

紧接着我通过 `p2` 这个结构体变量访问到它的属性 `Name`，将小明改成汤姆。这里这个地方修改会不会影响到 `p1`？是不是不会？这个知识点和它的特点在前面我们已经给大家讲过了，对不对？

那这个时候我们输出 `p2.Name` 和 `p1.Name` 分别是多少？同学们想，是不是这个时候 `p2` 的 `Name` 就应该是汤姆~？而 `p1` 它的名字仍然是小明？所以说最后这个结果就应该是**汤姆~ 和小明**。

```text
     p1  ──>  [ Name : "小明"  | Age : 10 ]      ← 修改之前

     p1  ──>  [ Name : "小明"  | Age : 10 ]
     p2  ──>  [ Name : "汤姆~" | Age : 10 ]      ← 改 p2 之后，两块空间完全独立
```

读图说明：`p2 := p1` 复制的是整份数据，两个变量各自拥有一块独立的数据空间，所以改 `p2` 动不了 `p1`。

这段代码其实没有新鲜的东西，跟前面讲过的一致，因此这里我把它简单地说一下就可以了，这相当于把前面讲的一个知识点又做了一个回顾。

> **结论**：我们说变量总是在内存中的——一段代码在运行的过程中，所有的变量都会被加载到内存才能去运行，这个是一个程序运行的基本原则和规则，这个没什么可说的。那么结构体变量在内存中究竟以怎样的一个形式存在？因为它是值类型，所以那个图我们当时在前面已经画过，这里再把它说一下。

有些同学说："老师，你这些不都是讲过的吗？为什么还要讲一次呢？"

原因是**下面会有新的内容**。

### 传地址：两个名字指向同一份数据

我们来看一段新的代码。同学们看一下这段代码会输出什么信息？

```go
func main() {
	var p1 Person
	p1.Age = 10
	p1.Name = "小明"

	p2 := &p1

	fmt.Println((*p2).Age)
	fmt.Println(p2.Age)

	p2.Name = "汤姆~"

	fmt.Println(p2.Name)
	fmt.Println(p1.Name)
	fmt.Println((*p2).Name)
	fmt.Println(p1.Name)
}
```

跟着老师一起做一做。第一个，首先我创建了一个 `p1` 这个结构体变量，然后给它赋了一个值，年龄、名字。然后我做了这样一个动作：大家看到，我把 `p1` 这一个变量的**地址**交给了 `p2`。注意，是赋的地址了，而这边 `p2` 是一个**结构体指针**。

然后呢，我在这里输出了这个 `Age`，我用了一个取值符把这个 `Age` 取出来。好，请问这个地方应该输出什么内容？是不是就是这个 `10`？没问题吧？肯定是等于 10 的。

然后呢，我把这个 `p2` 的年龄也进行一个输出。各位，这个 `p2` 是一个指针，它指向了原先这个 `p1`，那所以说这个地方的年龄，请问是多少？是不是也是 10？因为我们讲过，上面这种写法和下面这种写法在 Golang 里面都支持，因此这个地方也是 10，没有问题吧？

然后呢，我通过 `p2` 去修改这个名字，我把它改成了汤姆~。

紧接着我做了一个动作，我要求输出 `p2.Name` 和 `p1.Name`，请问这个时候会输出什么信息？注意，**这个时候已经是指针了**。既然是指针，所以说 `p2.Name` 和 `p1.Name` 它们应该是同一个值。是什么呢？它们都应该是汤姆~。然后呢，我这里又输出，我用 `(*p2).Name`，其实就等于 `p2.Name`，对不对？然后这儿 `p1.Name`，其实这个仍然是汤姆~，后面这个呢也是汤姆~。

好，我们来试一下是不是跟老师分析的一样。我们写一段测试程序，新建一个文件夹 `exercise`。这里我们打一个 `package main`，然后 `import`，我们把 `fmt` 这个包引入，然后新建一个主函数包起来，执行。

一运行有人说："这块有代码有问题。"他说这个 `Person` 没有定义。好，没关系，我们加一个结构体就行了：

```go
type Person struct {
	Name string
	Age  int
}
```

这样它就不会报错了。我们来运行一下。我们发现地地道确确输出内容跟我们想的是一样的——是不是汤姆~，汤姆~，汤姆~，汤姆~？

> **结论**：这就是通过一个变量去修改另外一个结构体内容的方法——**传地址**。

### 把地址和值打出来，验证这个结论

但是呢，我想通过这个题来讲解的主要是什么？讲这个东西它到底在内存里面是怎么存在的。

好，同学们，打开 Excel 表，我们来画一下内存它是怎么布局的。就针对这段代码，我们说一下它是内存怎么布局的。当我们的代码从这里开始执行的时候，首先执行到这里，第一句话，它创建了一个 `p1`。因此在我们的内存里面，`p1` 这个变量它就会分配一个空间。`p1` 里面有几个字段呢？有 `Name` 和 `Age` 两个字段。`Name` 呢，它的值给成一个小明；然后它这儿还有一个年龄，是 10 岁，这个没有问题。

然后 `p1` 就指向了这个空间。

下面是关键的这句话：**这时我们把 `p1` 的地址交给了指针 `p2`。**

那这时它会在内存里面怎么存在呢？同学们注意听，这是关键，它是这样走的：这时会有一个新的 `p2`。`p2` 会指向什么呢？它已经是一个指针类型了，既然是一个指针类型，它就会指向一个空间。但这个空间里面存的是什么呢？**这个空间里面存的是这个地址**，就是 `p1` 这个结构体的地址。

那 `p1` 这个结构体的地址是多少呢？我们打出来看一下：

```go
fmt.Printf("p1 的地址是 = %p\n", &p1)
fmt.Printf("p2 的地址是 = %p\n", &p2)
fmt.Printf("p2 的值是 = %p\n", p2)
```

我们就发现：`p1` 的地址是它，没问题吧？同时我们发现，**`p2` 的值刚好就等于这个东西**——是不是证明了 `p2` 这个指针存放的地址的的确确就指向 `p1`？

当然了，有同学说："老师，那 `p2` 它本身有没有地址呢？"

肯定也有。它是一个指针，既然是一个指针，所以它本身也会有一个地址，就是 `p2` 本身也有一个地址。而 `p2` 本身的地址，实际上指的是它自己所在的那个空间的位置。

```text
   内存

   p2 所在的地址空间                     p1 所在的地址空间
   +---------------------------+         +---------------------------+
   | 存放的内容 = p1 的地址    |         | 存放的内容 =              |
   +---------------------------+         |   Name : "汤姆~"          |
              |                          |   Age  : 10               |
              |                          +---------------------------+
              +------------------------------>  ^
              |                                  |
              |                                  |
              +-- 间接引用到 p1 的数据空间 --+
```

读图说明：`p2` 是一个指针，它指向了自己所在的空间，而那个空间里存放的**是一个地址**；这个地址指向的正是 `p1` 这个结构体的数据空间。也就是 `p2` 通过"存放地址"这一步，间接引用到了 `p1` 的数据空间，形成这么一种引用关系。

既然这个关系一旦成立，下面的代码就特别好理解了。这两句话不说了：`*p2` 通过取出这个地址，就相当于找到了它的数据空间，再找到这个 `Age`，打印出 10。同样，`p2.Age` 这句话之所以可以这么用，前面老师讲过，这是 Go 的设计者做了一个简化处理——其实标准的写法应该是上面这个写法，但是 Go 设计者为了大家使用方便，它也支持 `p2` 这个指针直接去访问它的字段。

紧接着它做了一个 `p2.Name = "汤姆~"`。同学们想一想，`p2.Name` 其实是通过这个指针、通过这个地址找到了它指向的数据空间，然后找到这里面有个字段叫 `Name`，把这里面的这个值改成了汤姆。

大家想一想，你通过 `p2` 去改变这个东西，显然 `p1` 也就发生变化了。**这个从数据空间可以看出来，因为它们是共享一份数据空间。** 所以说当下边你用 `p2.Name` 或者 `p1.Name` 去访问名字的时候，其实都是汤姆。同样的道理，你用 `(*p2).Name` 去访问名字和 `p1.Name` 也是汤姆。所以最终这个结果就是这么出来的。

> **结论**：这个图特别重要，一定要把这个图理解到位。这个图理解到位了，下面怎么输出、为什么输出这些，大家就非常清晰了。

### `*p2.Age` 这种写法为什么是错的

接着我们再来看下面一个题。下面这个代码说：有一个结构体变量是 `p1`，并且给它两个字段赋了值。然后我把 `p1` 这个地址交给了 `p2` 这个指针。然后他就问：**能不能这样用？`*p2.Age` 能这样用吗？**

它跟原先我们写法唯一的区别就是**没有用括号**。原先的写法是把它包起来的，这 `*p2` 是包起来的，用一个括号包起来，现在它没有包。请问这样用能行吗？

这样用，我先给大家说，这样用肯定是不对的。

为什么说不对呢？因为大家都知道**点运算符的运算级别要高**，对吧？所以它先会执行 `p2.Age`，这个是没问题的。但是你做完了过后你又取了一个星号取值符，所以说这个就错了。

打开我们的笔记。我们在讲运算符的时候，提到了一个运算符的优先级。大家看这里，我们这儿讲到点运算符的运算级别是非常高的，**它比取值运算符星号要高**。因此在进行这个代码执行的时候，它先执行这个点操作，然后再执行星操作。那这样子的话代码肯定是有问题的。

为什么有问题？你想，它先点操作然后再星操作，它本身这样已经取出来一个具体的值了，结果你对一个具体的值再去作一个星号处理，肯定是要报错的。

所以结论是：**不能这样写，代码会报错。** 原因是点运算符优先级比星号、取值符高，所以这样子就会错。如果真的是星运算符级别高，那你这样写就没问题，因为他先对 `p2` 指针进行一个取值再 `.Age`，这个是可以的。但问题是人家点运算符的优先级要比星高，所以你就不能这么去写。

> **易错点**：一定要用括号包起来，一定要用括号包起来才行。要么你就直接把这星号拿掉也可以。以后在面试的时候如果有人这么问你，或者你在写代码的时候千万不要这么去写。

#### 值拷贝下的输出结果

题干：第一段代码中，`p2 := p1` 之后把 `p2.Name` 改成"汤姆~"，最后输出 `p2.Name` 和 `p1.Name` 是什么？

解析：`p2 := p1` 是值拷贝，`p2` 拥有自己独立的数据空间，改 `p2` 动不了 `p1`。

答案：`p2.Name` 输出 `汤姆~`，`p1.Name` 输出 `小明`。

#### 传地址下的输出结果

题干：把 `p2 := &p1`，然后依次输出 `(*p2).Age`、`p2.Age`，再用 `p2.Name = "汤姆~"` 修改名字，最后输出 `p2.Name`、`p1.Name`、`(*p2).Name`、`p1.Name`。

解析：`p2` 存放的是 `p1` 的地址，通过这个地址间接引用到 `p1` 的数据空间，两者**共享同一份数据**。所以不管从哪个入口改，四次输出的都是同一份数据里的值。

答案：`(*p2).Age` 和 `p2.Age` 都输出 `10`；`p2.Name`、`p1.Name`、`(*p2).Name`、`p1.Name` 全部输出 `汤姆~`。

#### `*p2.Age` 能否成立

题干：`p2` 是 `*Person` 类型，能否直接写 `*p2.Age`？

解析：点运算符优先级高于取值运算符 `*`，所以实际执行顺序是"先算 `p2.Age`（得到一个具体的 `int` 值），再对这个 `int` 值取星号"，这在类型上就不成立。

答案：不能，会报错。要写成 `(*p2).Age`，或者干脆去掉星号写成 `p2.Age`。

## 结构体的四个使用细节：连续分布、类型转换、重新定义与 tag
> 对应块：BLK68 | 覆盖分集：P189-P191 | 块标题（分集名）：《188_尚硅谷_结构体使用细节(1)》

各位同学，我们接着来看下一个话题：使用结构体的时候，有哪些事情需要我们注意。一共四个细节，我一个一个讲。

### 字段在内存中是怎么排布的

第一个要给大家讲一下：**结构体的所有字段在内存中是连续分布的。**

这个怎么理解呢？比如说我们这个结构体里面有五个字段，那么这五个字段在内存里面它们的地址——我这里有个图大家瞄一眼。比如说我这里这个结构体里面有四个整数，那么这四个整数你们可以看到它的地址其实是连续分布的。

连续分布有什么好处呢？像有一些编程的高手，他可以完全通过地址的加减——比如说我通过地址增加多少个字节，然后找到下一个数，通过这种方式来快速地获取某一个字段的值，都是可以做到的。同时，它这种分布形式也有利于我们数据的一种查找，速度会比较快。

我们举个例子，让大家认识一下字段在内存中所谓的连续分布是指的什么意思。打开 VS Code，新建一个文件夹 `structdetail`，新建一个文件 `main.go`。

为了看到这个效果，我们需要定义两个结构体。第一个结构体我们叫**点** `Point`，记录一个点的。这个结构体有两个字段，一个字段是 `x`，写成 `int`；一个字段是 `y`，也写成 `int`。然后我们再来定义一个结构体叫做**矩形** `Rect`，它也是一个结构体。这个结构体里面有两个点——矩形的左上角这个点和右下角这个点共同构成了一个矩形。

```go
type Point struct {
	x int
	y int
}

type Rect struct {
	leftUp, rightDown Point
}
```

现在我们定义一个 `Rect` 矩形的结构体变量，看看它在内存里面是怎么分布的：

```go
func main() {
	r1 := Rect{Point{1, 2}, Point{3, 4}}

	fmt.Printf("r1.leftUp.x 地址=%p r1.leftUp.y 地址=%p r1.rightDown.x 地址=%p r1.rightDown.y 地址=%p\n",
		&r1.leftUp.x, &r1.leftUp.y, &r1.rightDown.x, &r1.rightDown.y)
}
```

`r1` 在它的内存里面会有四个整数。怎样来证明它是连续分布的呢？只有一个办法，就是打印它的地址。要输出一个变量的地址要用取址符号 `&`，其他以此类推。

运行一下，我们发现了一个非常有意思的现象：第一个 `x` 的点地址是 `40`，第二个是 `48`，它们刚好**相差 8 个字节**。再看第三个，又相差 8 个字节，变成 `50` 了——加 8 进了一位，16 进制的。第四个就是 `58`。

这说明它们这四个点的的确确在内存里面是连续分布的。

```text
  r1  ──>  [ x : 1 ][ y : 2 ][ x : 3 ][ y : 4 ]
            addr 40  addr 48  addr 50  addr 58
                   ←8→   ←8→   ←8→
```

读图说明：`r1` 直接指向一个结构体，这块空间里有四个字段，值刚好是 1、2、3、4。为什么是加 8 个字节而不是 6 个或者 5 个呢？就是因为它的数据类型刚好是 `int` 类型——一个 `int` 在 64 位环境下就是 8 个字节，它默认就是 `int64`。同样的道理，第三个点的地址又在这个基础上加了一个 8，变成 50 了；第四个点的位置又加了 8。它底细就是按照这个方式连续分布的。

连续分布有什么好处？**第一个好处**是，因为它是连续的，因此它在取这个值的时候，在内存底层肯定是通过地址的加减来找到对应的这个值，因此速度会非常快。结构体的操作本身的速度就偏快，因为它是按照地址来直接进行加减——找到第一个字段的值，找第二个字段在内存里面直接加 8 个字节，一下就找到了。这个特点大家一定要有一个初步印象。

#### 指针字段：本身连续，指向的未必连续

第一个案例说完以后，我们还要再举一个案例。还有一个特性：**如果 `Rect` 里面存的不是具体的值，而是指针的话，它指针里面的内容就不一定是连续的了。**

假设我们还有一个结构体叫 `Rect2`，里面也有这么两个点，一个是左上角，一个是右下角。现在我们又来创建这么一个 `r2`，但是我要把它改成指针。此时此刻这个结构体存的内容不是一个具体的值，而是一个指针类型了。指针本身的内容指向的是个地址，但是指针本身是不是也有地址？`r2` 有两个 `*Point` 类型。

我要下的结论是：**这两个 `*Point` 指针类型，它们本身的地址也是连续的，但是它们指向的地址不一定是连续的。**

```go
type Rect2 struct {
	leftUp, rightDown *Point
}

func main() {
	x := 10
	y := 20
	r2 := Rect2{&Point{10, 20}, &Point{30, 40}}

	fmt.Printf("r2.leftUp 本身的地址=%p r2.rightDown 本身的地址=%p\n",
		&r2.leftUp, &r2.rightDown)
}
```

注意听讲，是**本身的地址**。怎么取？是不是还是取地址符，但是后面不要 `x` 了。

执行一下。同学们有没有发现它的地址仍然也是连续的？这是 `11C0`，这个是 `11C8`，是不是也是八个字节？为什么是八个字节？因为它的类型其实说白了是 `int*`，它底层是 `int*` 这种类型，指向是一个 `int` 类型的指针，说明它也是连续的。

```go
fmt.Printf("r2.leftUp 指向的地址=%p r2.rightDown 指向的地址=%p\n",
	r2.leftUp, r2.rightDown)
```

这个我就不去作测试了，有兴趣的同学可以上去作测试——说"老师我就想把指向的地址打印出来"，也可以，这样写就行。那么指向的地址是不是就不要这个符号了？

跑一下。我们看到它指向的地址是 `...090` 和 `...0A0`。看起来好像也还能看出点规律，但你看这个 `9` 在这个基础之上如果再加一个值的话，`90` 和 `A0` 相差可就比较大了，一看肯定不是连续的。因为 9 到 A 相差很大，它肯定不是相差简简单单的八个字节或者十六个字节。而且每一次可能都不一样，这要根据它的内存情况、要看编译器或者系统当时在运行时是如何分配的。

所以我们做一个结论：**它本身的地址是连续的，但是它本身的内容、也就是它指向的那个地址不一定是连续的。当然也有可能是连续的，就看实际情况了。**

```text
  r2.leftUp 本身: [ 指向 0x...090 ]  ← 本身连续（相差 8 字节）
  r2.rightDown : [ 指向 0x...0A0 ]

  0x...090  ──>  [ x:10 ][ y:20 ]      ← 与下面那块不保证相邻
  0x...0A0  ──>  [ x:30 ][ y:40 ]
```

读图说明：上面那两个存放指针的槽位是紧挨着的，但它们各自指向的两块数据空间落在哪儿，是堆分配器决定的，编译器不保证。

#### 一段亲身经历：为什么这件事值得记住

为什么我要强调这一点？就是因为有一些计算机学者、编程编得比较熟的人，他可以直接通过地址的加减来取得结构体里面的值。

我记得以前我刚刚参加工作的时候，我们做的是一个在 Linux 下面做 C 开发的服务器，这个服务器当时有一个功能就是要去获取用户在线的状态。

当时我因为刚刚参加工作没有经验，那我怎么做的呢？我做得非常简单，我就直接把每个用户的信息、那个状态，直接存在 MySQL 数据表里面去。结果我把这个设计方案拿出来的时候，我们当时这个头——他也是新浪的第一任 CTO——就很苛刻地批评了我。

他说："你这个小伙这样写是不对的。如果你把所有的信息都往数据库里面去存，那么获取用户的状态这个压力会非常大，因为用户的状态变化非常频繁，对不对？他一会儿上线一会儿离线。如果说你放到数据表里边去，大家想一想，你对数据库的操作会非常频繁，因此承压能力是很低的。"

他又想了一个办法，因为当时我们用的是 C 语言，他就把用户的状态直接放在一个结构体里边的。然后来了一个用户，我就把一个用户的 ID 和他状态直接放进去。等到我要查找某一个用户信息的时候，直接通过这个结构体的地址进行一个加——比如说我要根据这个用户的编号，然后迅速地定位它的这个地址，然后把状态取出来。

只做了这么一点点改动，整个性能提升是非常非常大的。

所以那个时候我就发现，有经验的程序员和刚刚入行的程序员，他们写代码质量真的是有差别。这点我希望同学们在写代码的时候多动脑筋。我们就把这个原理告诉大家为什么可以这样做——因为它们在内存里面是连续的。

### 两个结构体之间怎么转换

结构体是用户单独定义的类型，和其他类型进行转换时，**需要有完全相同的字段**。

什么叫"完全相同"呢？注意听这句话，叫完全相同。也就是说它的**名字、它的个数以及它的类型**要完全一致，明白这意思吧？这三样都必须相同。如果这三样有一个不相同，那整个就不会转换成功。

我们走一个案例。因为代码已经有点多了，干脆我们就新建一个文件夹，叫 `structdetails2`，新建一个文件 `main.go`。

```go
type A struct {
	Num int
}

type B struct {
	Num int
}

func main() {
	var a A
	var b B

	fmt.Println(a, b)      // 0  0，两个变量都能正常输出
	a = B                  // 报错：cannot use b (type B) as type A
}
```

`a` 这个变量和 `b` 这个变量，它默认值就是 `0`，所以输出来都是 0，运行没有任何问题。

但现在我要做这么一件事情：我要把 `b` 直接赋给 `a`。我一保存的时候你们会发现它会报错——`cannot use b (type B) as type A`，也就是说你不能把一个叫做 `B` 的数据类型、B 这个结构体交给 `a`。

那有些同学说："老师，能不能强转呢？"可以。我们应该把它转成 `A`，这样强转：

```go
a = A(b)
```

一保存，没问题了，强转是可以的。

那么这个地方有个前提：**你之所以能够把 `b` 这个结构体变量转成 `A` 这种结构体类型，因为什么？因为你的字段是一样的**——字段的个数、名称、类型都一样。

我们再来看第二个，名字不一样行不行？如果我把 `B` 的字段名称改成其它的，你们发现它也不可以。名字不一样也不行，看到没有？还是不行。

不但名字不一样不行，而且如果我们多一个数据类型也不行。假设我这还有一个 `Name string` 字段，你们发现当我一保存它又报错了，又不能转换。

> **结论**：可以转换，但是有一个要求，要求就是结构体的字段要完全一样。所谓要有相同的字段，指的是**字段的个数、字段的名称以及字段的类型**要完全一致。只要有一个不同，整个就转不了。

### type 重新定义会造出一个新类型

第三个细节：结构体进行 `type` 重新定义了。一个结构体可以再次被 `type` 重新定义。比如说我这定义的 `Student` 它是结构体，然后我又定义了一个 `Stu`，它是 `Student`：

```go
type Student struct {
	Name string
	Age  int
}

type Stu Student
```

乍看一眼，你会发现这个 `Stu` 和 `Student` 它其实是同一种结构体，对吧？

但是大家看到，当我这样赋值的时候：

```go
var stu1 Student
var stu2 Stu
stu2 = stu1   // 错误
```

我把 `stu1` 直接赋给 `stu2` 行不行？我告诉大家这个结论：**这样转是不可以的。**

为什么这么说呢？因为 **Golang 认为是新的数据类型**。当用一个 `type` 重新定义了你自己定义的这个结构体之后，Golang 认为 `Stu` 这个类型和 `Student` 这个类型是两个**不相同**的数据类型。因此你直接把这个 `stu1` 交给 `stu2`，这个语法是要报错的。

怎么办呢？你要强转。因为你 `stu2` 是这个类型，因此我把它强转成这个类型：

```go
stu2 = Stu(stu1)
```

这个就 OK 了。其实这点跟我们前面讲的是一样的，因为它相当于说两个结构体它们拥有相同的字段，就 OK 了。

我们再来看这个题。这个地方有一个 `int`，这个 `int` 它本身是不是 Golang 设计者事先就已经给我们定好的一个数据类型？那么如果你用 `type` 也可以给这个 `int` 取个别名，比如说叫 `integer`：

```go
type integer int
```

这是允许的。那么这个时候 `integer` 其实也是一个 `int` 了。那这个时候如果你把 10 交给一个变量 `i`，你把 `i` 变量定义成 `integer`，这也是可以的；这个时候你把 20 交给了一个 `int` 变量 `j`。

同样我问大家一个问题，如果直接把 `i` 赋给 `j` 可不可以？

```go
var i integer = 10
var j int = 20
j = i          // 错误
```

其实这个地方也是不可以的。原因跟刚才一样，因为当你重新 `type` 了一下这个 `int` 过后，它认为 `integer` 这个数据类型和 `int` 这个数据类型是两个不同的数据类型，因此你不可以把 `i` 直接赋给 `j`。

当然，如果你就想把 `i` 赋给 `j`，可以怎么做？强制转换一下就可以了：

```go
j = int(i)
```

因为你的 `j` 已经是一个 `int` 了，所以说你把 `i` 强制转换成 `int`，那么我就赋给它了。

> **易错点**：这个地方是很容易让我们犯糊涂的。因为很多人他会认为，你这 `Student`，我 `Stu` 重新定义一下，按理说它是同一个数据类型，对吧？一般的语言都会这么去处理的。但是 **Golang 它对数据类型的要求是非常严谨的**，它就认为这是两个不同的。甚至你把 `int` 直接 `type` 了一下，它认为 `integer` 和 `int` 也是不同的数据类型。不然的话以后你在写项目的时候，包括我们后面写项目的时候，你就看不懂你的代码了。

### 结构体 tag：序列化时给字段换个对外名字

最后一个需要同学们注意的细节：**在结构体的每个字段上，我们还可以写一个标签，叫 tag。这个标签可以通过反射机制来获取。**

当然了，有同学说："老师，反射机制我们还没有讲。"是的，反射机制现在还没有讲，后面我们会说的，这里我们就说体验一下，体验一下。

#### 场景：Go 服务器怎么把数据返回给浏览器

那这个反射机制常见的使用场景，它是用来做什么呢？它是用来做序列化和反序列化的。

比如说这个 `Monster`，它是个结构体，那么这个结构体大家看到有这么一个需求，需要大家去思考。这个结构体我们名字的 `N`，就是 `Name`，它首字母是大写的 `N`。大家知道我们为什么要把它写成大写的 `N` 吗？就是因为我们有些时候是需要这个 `Monster` 的变量、这个 `Monster` 结构体的变量能够在其他的包去使用。

但是有一个问题，因为这个变量它的首字母大写，**有些程序员他是不习惯的。**

打个比方，这里是我们的服务器——比如说这是一个用 Go 写的服务器。那么 Go 服务器这一头大家注意观察，这地方比如说我们的浏览器，注意听，这是浏览器。当浏览器发一个信息给我们的 Go 服务器过后，Go 它往往会去操作一个数据库；操作完了过后，它会返回一个数据给我们的浏览器。

那么这个时候就存在一个问题：假设这个 Go 它会返回一个结构体变量。我把这个结构体变量返回给客户端的时候，我怎么返回？我不可能把一个结构体本身直接返回，往往是把这个结构体做成一个**字符串**，那么问题就来了——既然你要把它做成一个字符串，那就意味着你要把结构体先**序列化**。

序列化的概念就是：可以把一个变量序列化成一个字符串，然后再返回去，返回给你的客户端，这样子就是一种标准。那么一般来讲，这种字符串有一个现在通用的一种格式叫 `json`，能理解吗？

这种 `json` 往往来说，别人接收这个字段，它并不希望是一个大写的 `N`，因为很多客户端它更喜欢的是返回这个字段名是小写的 `n`。这时我们就可以给我们的结构体加一个 `tag`。

多说无益，我说了半天可能大家也不知道我在说什么，我就举个例子。

#### 序列化踩的两个坑

说现在有这么一个需求，我有一个 `Monster` 结构体。里面有什么字段呢？有名字；有一个年龄 `int`；还有一个 `skill`，它最厉害的武器或者最厉害的攻击技能。

```go
type Monster struct {
	Name  string
	Age   int
	Skill string
}

func main() {
	monster := Monster{"牛魔王", 500, "芭蕉扇"}
}
```

它的需求场景是这样一个事情：我现在有这么一个需求，这是一个客户端；客户端这边还有一个服务器端，这个服务器端就是我们用 Go 语言写的。现在客户端向我们发出了一个请求，发出一个请求过后，Go 语言给它回送了一个信息。

假设服务器这边要返回 `monster` 这个变量的值。有这种可能性吧？你比如说我将来客户端是一个浏览器，我就要浏览一下你当前服务器里面有多少个 `monster` 变量，或者我要看 `monster` 的信息、看学生的信息都有可能嘛。那这个时候你就要返回它的变量——可能是一组变量，我这说是一个是简化了，可能更多的情况是返回一组 `monster` 或者是学生信息。

那么这个时候你不可能把这个变量直接返回去，通常情况下是把这个 `monster` 序列化。序列化其实就是一个字符串，然后再把这个序列化的字符串返回给我们的客户端。客户端拿到这个东西就可以进行处理了。

现在的问题是我们怎么把一个 `monster` 做成一个字符串呢？通常情况下序列化就是序列化成一个 `json` 格式。它有一个专门的包，叫 `json` 包。打开 Go 官方文档，`encoding/json` 里面大家可以看到有一个方法叫 `Marshal`。往下走，这个 `Marshal` 函数，它返回你传进去的一个变量的 `json` 编码。

那既然我们要引这个包，那肯定是 `encoding/json`：

```go
import (
	"encoding/json"
	"fmt"
)
```

将 `monster` 这个变量序列化成一个 `json` 格式的字符串。非常简单，它使用的就是 `json` 这个包里面的一个方法，叫 `Marshal`，然后我们把这个对象传进去，传进去过后它会返回一个字符串。

这里要注意一个细节：**这个方法，它其实会返回两个值**。一个是返回一个 `byte` 字节，另外还会有 `error`。如果你不想接收 `error` 的话，其实这地方我们还要做一个动作（用一个下划线忽略掉）。但是实际上有时候我们往往还是要看一下，因此我们把这个信息做一个判断：

```go
data, err := json.Marshal(monster)
if err != nil {
	fmt.Println("json 处理错误", err)
}
fmt.Println("jsonStr", string(data))
```

如果 `error` 不等于 `nil`，我们就输出一句话，就是"json 处理错误"，把错误信息给打出来就可以了。否则的话，我们就把这个结果输出来。

我们跑起来。大家一看就傻眼了，为什么傻眼了呢？跟你想象的不一样——**它返回的是一个字节，是一个 `byte` 切片**。那你怎么把它转成一个可以看到的字符串呢？是不是在这里我们只需要非常简单地用 `string` 给它转一下就可以了？

```go
fmt.Println("jsonStr", string(data))
```

此时此刻它确确实实就返回了一个字符串。但是大家看，这个就是它的字符串哦——你看这里面，这个字段是不是大写的 `N`？这边也是大写的 `A`，这边是大写的 `S`。

**第一个坑**：很多程序员并不习惯你的字段首字母是大写的。因此我们解决方案的第一种方式，把它改成小写的。

那你看改成小写的会怎么样呢？好，当我们改成小写过后，注意听讲，再一执行，我们傻了眼了。我们发现**返回的是个空串**，好怪啊。

我问同学们想一想，为什么它是空串啊？是不是因为你用这个 `json` 这个包去调了它的 `Marshal` 方法，相当于是别的包，因为这个 `json` 是在另外一个包里面的，是不是这个意思？那相当于就是说**你在别的包里面用到这个 `Monster` 变量了**。但是你的 `Monster` 变量的字段又是什么呀？又是小写的。

那就根据我们前面讲的作用域原则——你在 `json` 这个方法里边是使用不到、或者访问不到这个 `Name`、`Age` 和 `Skill` 的。因此你只能大写，不然的话别人用不了，别人无法给你序列化。

#### 用 tag 收尾

但是问题又来了，它序列化过后它的字母是大写的怎么办呢？好了，现在终于引出我们结构体的这个 `tag` 了。非常简单，你只要这样写就行了。

一个**反引号**，注意是**反引号**啊，反引号完了过后呢，写上你的字段名。`json`，然后 `json:`，然后双引号，我要写成小写 `name`，这样就可以了。同样的道理，下边一样的修改，前面这个 `json`、`json` 这个名字是固定的，然后改成 `age`。

```go
type Monster struct {
	Name  string `json:"name"`
	Age   int    `json:"age"`
	Skill string `json:"skill"`
}
```

注意听，这个在我们实际开发中用的可以说是非常非常多的啊。只是原理我还没有讲，原理呢到反射的时候我们再说，好不好？

当我这样一改动过后，我们再来一执行，请看效果。我们发现跟我们想象的完全一样。大家看这里，原先你的是 `Name`，我现在是小写的；`Age` 变成 `age`，`Skill` 变成 `skill`。好，这样呢，我既能够序列化，同时我能把这个序列化的字符串通过网络返回给客户端，客户端的人呢他也习惯这种用法——因为一般的程序员他就喜欢首字母小写的。这样就能保持一种兼容性。

> **结论**：这就是我们的 struct tag。至于它底层——就是 `Marshal` 这个函数怎么样就能够把你的大写的字段名换成了这里面的名字呢？这个里面用到了**反射**。因为反射我们现在还没讲，所以说现在我只能先放到这个地方。这里底层里面就是我们 `json.Marshal` 函数中，使用到了反射。反射我们后面会详细介绍。

至此，我们结构体里边的四个细节和注意事项就全部给大家讲完了。

## 方法：作用在指定数据类型上的函数
> 对应块：BLK69 | 覆盖分集：P192-P193 | 块标题（分集名）：《191_尚硅谷_方法介绍和使用》

前面我们把结构体的使用注意事项给大家说了一下，下面我们来看方法。

### 方法到底是什么

在某些情况下，我们需要声明、定义一些方法。比如前面我们讲过的 `Person` 这个结构体，它肯定是有一些字段的，对吧？前面只是字段，现在我们需要有**行为**——比如说我们需要人可以说话，人可以跑步，人可以通过学习做算术题，这时我们就需要用到方法了。

注意，**方法和函数很相似，或者说它的使用方法基本上都相同的，但是两个概念还是有所区别的。**

我这里下了一个结论：

> **定义**：Golang 中的方法是作用在指定的数据类型上的。也就是说，我们这个方法是给某一个数据类型绑定的。

因此，**自定义类型都可以有方法**。什么叫自定义类型呢？只要这个类型是你自定义的，通过 `type` 来定义或者声明的，都可以有方法，而不仅仅是 `struct`。明白这意思吧？后边我们会详细说明。

在这里我们至少要明白两点：第一点，方法是跟数据类型相互绑定的；第二点，自定义类型都可以有方法，而不仅仅只是 `struct`。

我们简单地来看几个案例。大家注意观察，它很像函数，非常像函数。但是跟函数不一样的地方——就好像它这就多了一个这个东西，前面多了一个部分，小括号里有 `(n Number)`。那么这是什么意思呢？就说明我们这一个函数，它只能够跟这个 `Number` 相关联。那这个我们就管它叫**方法**了。

所以我们说方法和函数它有很多相似的地方，但是概念上还是有所区别。

### 给 Person 绑一个方法并调用它

我们来看一个案例。`type A`，`A` 这是一个结构体，这个结构体大家看到，我这里写了一个小括号 `(a A)`，这个很关键，`(a A) test()`。那么这就说明什么呢？说明这个 `test` 这个函数只能被 `A` 这种数据类型的变量来调用，那么我们就管它叫什么？叫方法。

或者这样说，我们可以这样说：**`A` 结构体有一个方法叫 `test`**。这样是不是就更清晰了？

我们建一个文件夹，就叫方法了，`methoddemo`，新建一个文件 `main.go`：

```go
type Person struct {
	Name string
}

func (p Person) test() {
	fmt.Println("test() name=", p.Name)
}
```

这个 `p` 相当于它的一个变量名——就是代表是跟这个 `Person` 类型绑定的。到时谁调用我，拷一个副本过来给这个 `p`。然后后边可以写上它的名字，方法的名字。来，我们走一个 `Println`。

那就相当于给 `Person` 类型绑定了一个方法。这个方法干什么呢？输出了它的名字。那我们来用一用。我先来定义一个 `Person` 实例：

```go
func main() {
	var p Person
	p.test()
}
```

大家看到这个地方就叫调用方法。

那我问大家一个问题：如果我现在调用的话，这个 `p` 相当于这个 `p` 调用 `test` 方法，这个 `p` 就会传到哪里去呢？这个 `p` 实例或者叫这个变量，就会在调用的时候传给它。明白这意思吧？就相当于说这个 `p` 在调用的时候，就会把自己的变量传入到这个位置去。有点类似于我们在函数的传参这种感受。

既然如此，那么我们在这输出的时候，因为没有给它赋名字，同学们可以考虑这时会输出什么呀？是不是这个名字是空的？

我们跑起来。确实运行起来了，但是后面没东西，没有名字。因为此时此刻这个 `Name` 等于什么呢？等于空。为什么等于空？因为你没有给这个 `p` 赋任何的名字，没赋值嘛。

那我给它赋一个值：

```go
p.Name = "tom"
```

听，这个很简单，但是很重要。我给它赋一个名字叫 `tom`。相当于说这个时候 `p` 它的字段 `Name` 就有值了。一旦有值，那么我在用它去调用的时候，它把这个 `p` 这个结构体的变量传到这个位置来，那这个时候这里面肯定就会有一个值，这时就会输出 `Name` 等于 `tom`。

我们跑一下，`tom` 就出来了。

### 方法只能通过它绑定的那个类型调用

针对上面这段代码，我做几点总结。

**第一点**，`test` 这个方法和 `Person` 类型绑定。这点刚才已经说过了。

**第二点**要注意到，`test` 既然和这个类型绑定，那也就是说——**你只能通过 `Person` 的这个变量来调用，而不能通过别的方式来调用。** 不能直接调用，也不能使用其他类型的变量来调用。

能理解这个意思吧？那这两点怎么来证明一下呢？

比方说，如果你直接调用 `test`，大家想一想这个 `p` 从何而来？这个 `p` 是谁调进去啊？调不进去。所以这个时候你一执行，它会报 `undefined: test`。所以说不能直接调用。

那你如果用别的类型来调用也不行。比如说你定义一个 `Dog` 这个结构体，`Dog` 这个结构体的变量，你这样调用也不行。它也会告诉你，`Dog` 这个结构体没有一个这样的方法。

我还没执行就已经报错了：`type Dog has no field or method test`，就是 `Dog` 这个类型没有这个字段或者没有这个方法。

> **易错点**：既不能直接调用，也不能够用别的类型来调用。这两种写法都是错的。

### 接收者里的那个名字，是调用者的副本

**第三点**，注意听，这个也很重要，就是这个位置：

```go
func (p Person) test() {
```

这里面这个小 `p`，这个名称——把它标成一个蓝色——它代表的是谁呢？它表示谁调用我，表示哪个 `Person`，注意听，就是表示**哪个 `Person` 变量调用我**。这点很重要。

它表示哪个 `Person` 变量调用，这个 `p` 就表示谁，这个 `p` 就是**它的一个副本**。怎么理解这个东西呢？它这点和那个函数传参是非常相似的，这点和函数传参机制非常相似。

那我问大家一个问题，请思考：如果我在这里边把这个名字改变了——这是肯定可以的，对吧？我把它改成 `Jackie`。那我问大家，当我把它改成 `Jackie` 过后，这个地方会输出什么？是不是它会输出 `Jackie`？肯定嘛，因为你在这儿把人家改变了，你当然输出 `Jackie` 了。

那我再问大家一个问题：如果我在这里继续去输出 `main` 函数里面的 `p.Name`，它等于多少？

我们先来研究一下这个问题。因为刚才老师讲了，这个 `p` 在 `test` 的时候，它是代表它的一个副本，而你本身不是通过指针传的是吧？你不是一个指针。而我们也知道，**结构体它在传参的时候，它默认是值拷贝**。那也就是说，`p` 在调用这个 `test` 的时候，其实它传了一个自己的一份拷贝给这个 `p`。那你里面的改变会影响到 `main` 函数里面这个 `p` 的 `Name` 吗？

显然它是不会的。因此这边会输出什么呢？它会输出 `tom`。因为你这的改变并不会影响我，**除非你传地址**。

我们跑一下看老师分析的到底有没有道理。在 `test` 函数里面是 `Jackie`，在 `main` 这边呢还是 `tom`。这点和我们的函数传参机制是一样的，就不再赘述了。

**第四点**，我们注意：`p` 这个名称是可以随意的，不是固定的。这里的这个值其实相当于是一个**形参**，因此它的变量名字可以随便写，只要你后面这个不改就行了。

比如说我就叫做 `a`。如果我把这个改成 `a`，那下面这个是不是也应该改成 `a` 就可以了？看，我这样运行也完全没有问题。

但是你后面改了类型就不行了——如果你把这个 `Person` 改成别的类型了，那这个方法就跟别的类型绑定了，而不再是跟 `Person` 类型绑定了，能明白吧？

> **提示**：所以说这个名字就是随意，根据你的习惯可以指定。但一般呢，这个名字还是要写一点有意义的，最好不要写 `a`、`b`、`c`、`d`，也不要写 `p`。其实真实的情况下应该写一个小写的 `person`，更严谨一点，更好一点。因为不然的话，叫个 `a` 叫个 `b` 都特别不好。只是我在讲课的时候有可能为了省事就这么写的，但是在我们真实的开发中，最好把形参这个名称也写得有含义一点，这样别人一读就读懂了。这个其实有点像 Java 里面的 `this`，有点类似。

### 四个方法，把形参和返回值都走一遍

我们来看方法的快速入门。现在我这儿举了四个案例，通过这四个案例我们可以加深对方法的理解。

#### 不接参数也不返回值

第一个案例：给 `Person` 结构体添加一个 `speak` 方法，输出"谁谁谁是一个好人"。这个其实是最简单的方法。

大家看到 `Person` 这个结构体是不是已经有了？有了。那我们就来给它增加方法。首先 `func` 关键字写上，括起来。括起来过后，首先我们给它一个名称，就是代表是跟这个 `Person` 类型绑定的。到时谁调用我，拷一个副本过来给这个 `p`。然后名字叫 `speak`。这里面没有传任何的形参，就是说这个方法不接受形参。

```go
func (p Person) speak() {
	fmt.Println(p.Name, "是一个goodman")
}
```

我们来调用一下。直接它是汤姆对不对？`p.speak()` 就完了。同学们想一想，此时此刻这个 `p` 在调用的时候就会代表它了，它也传进去，传一个副本给它，同时 `speak` 就调用。那这时候就输出什么呢？"汤姆是一个好人"。

这个方法是一个最简单的方法，**既没有传形参，也没有返回值**。

#### 不接参数但方法体内可以运算

第二个案例：给 `Person` 添加一个方法叫计算，可以计算从 1 到 1000 的结果。那就意味着我们这个方法体里面也可以做任何的运算，跟函数一样，对不对？

这个案例的作用是要告诉大家，在我们写的方法里面也可以进行各种运算，加减乘除、取模等等都可以，这点和函数一样。

前面是一样的，方法名它叫计算。然后这里边，注意听，他说要进行一个从 1 加到 1000 的结果。那我先定一个结果，里面可以定变量：

```go
func (p Person) jisuan() {
	res := 0
	for i := 1; i <= 1000; i++ {
		res += i
	}
	fmt.Println(p.Name, "计算的结果是=", res)
}
```

写完过后他也没有说要把这个结果返回，那就直接输出。我说谁谁谁计算的结果是：`p.Name` 这个人计算的结果是多少，输出来，那就是 `res`。

其实这个地方你也可以不用输——就是说这个 `p` 你不用也可以，传过来过后没有用也可以。但我这里为了体现出是哪一个人计算的，我把他的名字输出出来了。

我调用一下，直接调 `p.jisuan()`。我们跑一下，发现这个运算结果跟我们想的是一样的，`500500`。因为是 1000 嘛，这个结果是正确的。

#### 接收一个参数

第三个案例：给 `Person` 结构体加一个 `计算2`，该方法可以接收一个参数 `n`，计算从 1 加到 `n` 的。

这点跟前面不一样——就是说从 1 加到多少，这个值是从我们这边输进去的，也就是我们这个方法要接收参数了。

还是老规矩，前面这个部分是一样的，我就复制粘贴下来，这是 2，改了。首先他说可以接收一个数，那这个数其实就是一个参数嘛。那这个参数怎么写呢？大家看，写到这个里面：`(n int)`。

同样他要进行运算，运算的话跟这个几乎是一样的。唯一的改变在哪里？就是这个 1000 改成 `n` 就 OK 了：

```go
func (p Person) jisuan2(n int) {
	res := 0
	for i := 1; i <= n; i++ {
		res += i
	}
	fmt.Println(p.Name, "计算的结果是=", res)
}
```

同学们，我们来看看怎么调用它：`p.jisuan2(10)`。那这个时候，比如说我们让它计算到 1 加到 10，看效果，执行起来。我们可以看到"汤姆计算结果是 55"，因为这个时候这个值是从 1 加到 10 的。同样你也可以改变——说"老师我要加到 20"，可以，这样就可以改变了。

这里我们就演示了一个方法怎么接收一个参数。你要接收多个参数，可以在后面一样地写。

#### 有返回值

第四个方法：给 `Person` 结构体添加一个 `getSum` 方法，可以计算两个数的和，并且返回结果。

注意，这是有个新的东西——**有返回值了**。前面我们举的三个方法其实都没有返回值，现在有返回值了。

包起来过后，我们把方法名改成 `getSum`。这里边他要传两个数，那一个叫 `n1`，一个叫 `n2`，没问题。但是他有一个返回结果，返回结果这个结果写到屁股后边就行了。当然如果你有多个返回值，括起来写就行了。能理解吧？因为这里面我只有一个返回值，因此我就写一个 `int` 就行了。

```go
func (p Person) getSum(n1 int, n2 int) int {
	return n1 + n2
}
```

那这个时候注意听，因为你这个方法这个结果是返回去，而没有在自身的函数体内输出，因此我们在调用的时候得需要有个结果来接收：

```go
res := p.getSum(10, 20)
fmt.Println("res=", res)
```

我们跑一下。我们运算过后，发现它的结果跟我们想象的是一样的，`res=30`。也就是说，你把这个 10 和 20 传给了我们的 `n1` 和 `n2`，然后它运算过后把这个结果返回给这个 `int`，你接收了。

这个地方我们可以看到，我们在这一块、在这个方法里面并没有去使用这个 `p`，它也没有报错，对不对？也就是说这个 `p` 其实你用也可以，不用也行。

> **结论**：方法的调用该怎么调，你就按照你这个方法定义的形式，给它相应的调用形式就可以了。这四个方法走完，我敢说同学们对方法应该有一个更加全面的认识。

## 方法怎么被调用，以及调用时参数是怎么传的
> 对应块：BLK70 | 覆盖分集：P194-P196 | 块标题（分集名）：《193_尚硅谷_方法的调用和传参机制》

我们接着来看一下方法的调用和传参机制。这点很重要。

方法的调用和传参机制，首先说跟函数其实是很相似的，但是不一样的地方也有。不一样的地方在哪里呢？就是**方法调用时，会将调用方法的这个变量——就是谁调用这个方法，它不是一个变量来调用的吗？它会把这个变量也当作实参传递给方法。**

下面我们举例来说明一下。为了把这个东西讲清楚、说明白，我们还是通过以前的老规矩，画图。

### 调用方法时，调用者自己也被传了进去

#### 一个 getSum 的完整执行过程

我们来画出前面 `getSum` 方法的执行过程。前面我们在举例的时候是不是写过一个 `getSum`？这里面传了一个 10 和 20，然后它返回一个结果。

为了把这个东西说得更明白一点，我用变量来传。比如这定义了一个 `n1 = 10`，用类型推导；`n2` 的值给它一个 20。然后这个地方传的时候，我们直接用变量传。

```go
func main() {
	n1 := 10
	n2 := 20

	res := p.getSum(n1, n2)
	fmt.Println("res=", res)
}
```

结果我们先来看看，此时此刻运行的结果仍然是一样的，还是 `res = 30`。

我们来看看这段代码它是怎么执行的。

首先第一句它先执行了 `n1`。大家都知道这段代码是属于 `main` 函数的，这样子的话，`main` 函数有自己独立的一个数据空间，我们把它叫做 **main 栈**。这里有个 main 栈，里面有一个 `n1` 变量了，`n1` 是个基本数据类型，`n1` 指向一个空间，就叫 10。

紧接着，他又执行了下面这句话，叫 `n2`。`n2` 我们可以看到，它又指向一个数据空间，这个空间叫 20。

紧接着，他在这里去调用了 `p.getSum`。注意，调用 `p.getSum`，大家都知道它是先执行等号右面的代码，也就是 `p.getSum`。当它执行 `p.getSum` 的时候，根据我们前面讲的原则，它会生成一个新的独立的数据空间，我们姑且把它叫做 **getSum 栈**。

当它调用这个栈的时候，它会把 `n1` 和 `n2` 传给 `getSum` 这个方法的 `n1` 和 `n2`，那么它会进行一个**值拷贝**。因此在这个栈里面也会有个 `n1`，它的值为 10；同时它还会有一个变量叫 `n2`，它的值为 20。

此时此刻注意听这个关键点：在主函数调用之前，这个 `p` 是不是已经存在了？`p` 肯定已经存在。`p` 是一个 `Person` 结构体，它里面有一个字段叫 `Name`，`Name` 里面有个值 Tom。

**当他 `p.getSum` 的时候，除了把刚才的 `n1` 和 `n2` 进行一个值拷贝之外，同时它也会把主函数里面的 `p` 也当作一个参数传给这边这个 `p`。** 那也就是说，在 `getSum` 这个栈里面，其实也有一份相同的 `p`。但是它们其实是独立的数据空间。

这点就是跟函数调用不一样的地方：因为 `p` 在调用 `getSum` 的时候，它本身这个 `p` 变量也会当作一个形参传给这个 `p`。这个 `p` 接收过后，它也会在这个栈里面生成一个相同的拷贝。因为大家都知道 `p` 它是结构体，结构体是值拷贝。

紧接着它执行了一个 `n1 + n2`。它直接执行了一个 `return`，就是 `n1 + n2`。那 `n1 + n2` 是不是就是 $10 + 20$，于是这个就返回了个 30。

这个 30 会返给谁呢？它把这个值就返回给这个位置了。也就是相当于在我们的主栈里面会有这么一句话，叫 `res := 30` 就来了。最后你这往下继续走，输出 `res =` 什么什么，那么在我们的终端，它就会输出一句话叫 `res = 30`。

```text
  main 栈                              getSum 栈
  +-------------------------------+   +--------------------------------+
  | n1 : 10                       |   | n1 : 10      (值拷贝)          |
  | n2 : 20                       |-->| n2 : 20      (值拷贝)          |
  | p  : [ Name : "tom" ]         |   | p  : [ Name:"tom" ] (值拷贝)  |
  +-------------------------------+   +--------------------------------+
            |                                      |
            |                                      | return n1 + n2  =>  30
            +<-------------------------------------+
            |
            v
      res := 30
      fmt.Println("res=", res)      ==>  res = 30
```

读图说明：`p.getSum` 执行的那一刻，会开出第二个独立的数据空间。`n1`、`n2` 和调用者 `p` **三者全部按值拷贝**进去，所以两个栈里的数据完全一样、也完全无关。

> **结论**：调用方法的时候，其实它也是在不停地进行这个拷贝。如果你是值类型，那就相当于说把这个值就拷贝了一份过去；如果我们是一个引用类型，那大家可以想象，拷贝过来的就是这个地方相当于是一个地址。因为我这块是值，因此我就画的是值。

我们对他做一个简单的说明。**第一点**，我们可以看到，在方法调用的时候，它的机制和函数是一样的——通过一个变量去调用一个方法时，其调用机制和函数几乎是一样的。

**第二点**，不一样的地方是什么呀？就是**调用方法的这个变量也会作为一个形参传递到方法里面去**。

那这个时候就要看你这个变量是什么类型了。要看如果变量是值类型，则进行**值拷贝**；如果变量是引用类型，则进行**地址拷贝**。

#### 再走一遍 area

因为一个案例有的时候可能大家还没有把它彻底地认识清楚，我们再举一个案例。要求是这样的：

1. 先声明一个结构体，这个结构体叫 `Circle`，圆的意思；字段为 `radius`，半径，圆总是有半径的嘛；
2. 声明一个方法叫 `area`，和 `Circle` 进行绑定，并可以返回面积；
3. 画出我们 `area` 执行的过程并加以说明。

我们就针对这个要求来完成相应的代码。新建一个文件夹，方法的练习 `methodexercise`，新建一个 `main.go`。

第一步，他要建一个结构体叫 `Circle`，字段为 `radius`。`radius` 肯定是一个小数了，就半径：

```go
type Circle struct {
	radius float64
}
```

第二步，要声明一个方法和它进行绑定。既然是个方法，我们就 `func`。前面他说跟 `Circle` 绑定的，因此我们前面来做一个 `c`，简单点写。然后名字叫 `area`。有参数吗？没有，他没有说要传什么参数进去，那就不写了。但是他要返回一个面积，面积我们仍然叫 `float64`。

这个时候面积怎么计算呢？面积其实很好计算，就是你这个圆的半径，$\pi r^2$ 嘛。把这个 $\pi$ 先写出来，3.14 吧，乘以它的半径 `c.radius`，再乘一次，乘两次：

```go
func (c Circle) area() float64 {
	return 3.14 * c.radius * c.radius
}

func main() {
	var c Circle
	c.radius = 4.0
	res := c.area()
	fmt.Println("面积是", res)
}
```

执行一下。我们看到这个时候结果跟我们想的是一样的，`50.24`，正确。

现在的重点就是要给大家分析一下，这里面这个过程是怎么样做的，它的流程是什么样子的。老规矩，这次我们稍微画快一点。

首先，代码从这里开始走。它创建了一个 `Circle` 结构体。在 main 栈里面，我们先写到 main，main 栈里面有一个 `c`，`c` 就创建好了。`c` 它是一个结构体，它指向一个结构体，结构体里面有一个字段叫 `radius`，然后里面给了一个值 `4.0`。

紧接着它在这里调用 `c.area()`。`c.area()` 根据我们以前讲的规则，它会创建一个新的独立的数据空间，那么这个空间我们把它姑且叫做 **area 栈**吧。这个栈里面，它也会把它自己复制过来。刚开始的时候是没有的，因为他在传的时候，`c` 这个变量本身也会传到这个地方来，于是在 area 这个栈里面也有一份相同的结构体。

进到这里面，它就执行了个运算。它怎么运算呢？它运算的结果是 3.14 去乘以谁？乘以 `c.radius`。**同学们注意，这个时候 `c.radius` 它是从这里面取的，并不是从 main 栈里面取的。** 虽然值都一样，但是大家一定要搞清楚它是从哪儿取的，千万不要认为是从 main 栈取的。

整个这个结果运算完了过后它就 `return` 了。它 return 到哪里去了呢？这儿不是有一个 `res` 接收了吗？相当于说这个地方它会把这个值计算出来过后返回过来。这个值其实就是等于 50.24，也就是说这个地方就得到了 50.24。

当它返回了过后，其实上面这个空间就销毁了，没有了吧。等到主函数把这句话输出过后，它自己也就执行完毕，连这个也就没有了，内存就全部释放了。

```text
  main 栈                                  area 栈
  +-------------------------------+     +------------------------------+
  | c  ---> [ radius : 4.0 ]      | --> | c  : [ radius : 4.0 ]        |
  +-------------------------------+     +------------------------------+
            |                                       |
            |                    return 3.14 * 4.0 * 4.0  =>  50.24
            +<--------------------------------------+
            |
            v
      res := 50.24
      fmt.Println("面积是", res)   ==>  面积是 50.24
```

读图说明：两个栈里各有一份 `c`，`area` 里的那份和 `main` 里的那份**互不影响**；运算用的是 area 栈里那份 `c` 的 `radius`。

> **易错点**：这个大家看起来是很简单，当做一个项目的时候，如果这个细节、这个本质没有搞清楚，在看别人项目的时候你就会产生各种歧义、拿不定主意。我没有讲这个东西的时候，可能很多同学认为这个 `c` 就是这个 `c`，认为这两个 `c` 是同一个——那麻烦了。

当然，它可不可以变成同一个呢？也可以。如果你把 `Circle` 这个类型改成是个指针，它也一样可以把这个东西通过地址去引用到你 main 栈里面的 `Circle`。但是这个地方它没有用指针，因此它就会进行一个值拷贝。显然这种效率会比较低下，因此后边我们就会去讲，在更多的情况下，其实我们会把这个地方改成指针。

### 方法的声明语法

现在我们再来看一下方法的声明和定义——有些人喜欢把它叫方法的声明，有些程序员喜欢把它叫方法的定义，这个是同一个意思。

我们来看一个完整的方法声明和定义的语法是什么样子的：

```go
func (receiver type) methodName(参数列表) (返回值列表) {
    方法体
    return
}
```

首先这有一个关键字叫 `func`，这个没什么可说的。后面大家看到这一对小括号里面是 `type`，这个地方就是你这个方法要跟哪一个数据类型先绑定。这个 `receiver` 就是这个类型的一个变量，对不对？比如前面我们写的 `p`。这个是方法的名字，方法的名字就根据我们前面讲的标识符的命名规则来写就可以。

这块大家看到是参数列表，其实就有点类似于我们学函数的时候那一个形参列表。大家再看这里，这边是返回值列表。什么叫返回值列表？就是你这一个方法如果有返回值，那么这个返回值列表就可以写到这里。就像我们以前写的，比如说我有两个 `int`、`int`，对吧？甚至我们也可以给它写名字，比如说第一个 `res1`，第二个 `res2`，用这个名字来跟返回的参数列表进行绑定也是可以的。

> **定义**：`receiver type` 表示这个方法是和 `type` 这个类型相绑定的，或者说方法作用在 `type` 这个类型。当然这个 `type` 是什么类型，根据实际情况而定——比如说你这地方绑定的是一个 `Student`，那就是跟 `Student` 绑定的。
>
> **提示**：而且我要多说一句，这个 `type` 不一定是结构体类型，它也可以是普通的那种数据类型定义的一个 `type`。比如说：
>
> ```go
> type integer int
> ```
>
> 那么同学们，你也可以给这个 `integer` 来绑定一个方法，也是可以的。

我们再看第四个。`receiver` 这个就是 `type` 类型的一个变量，或者叫一个实例。因为如果是结构体变量，有些程序员还是比较习惯把它称之为实例。比如说你前面讲的那个 `c`，就是 `Circle` 这一个结构体的变量，或者是 `Circle` 的一个实例，都可以这么说。

然后参数列表表示方法的输入，返回值列表表示返回值，可以是多个，你有多个返回值你可以写到这里。然后方法主体，这个就不多说了，就是你这个方法要完成的一个功能。究竟是完成什么功能，根据你写项目的实际需求来定——比如说是一个计算的功能，也可能是一个连接数据库、往数据库添加数据的一个功能，都有可能。

`return` 语句并不是必须的。如果你这个地方没有 `return`，那么就意味着你这个返回值列表也应该没有。但是注意听，**如果你这有返回值列表，那这一定会有个 `return`**。

### 方法使用的五个细节

关于方法的注意事项和细节的讨论，大概有五点。有些前面老师已经说过了，有些还没有说过。

#### 细节一：结构体是值类型，方法调用时值拷贝

结构体类型是值类型，方法调用时遵守值类型的传递参数及值拷贝。这一点我们在前面画图的时候就已经说过了。

#### 细节二：想改结构体，就绑指针

第二点，我们来看一下。**如果程序员希望在方法中修改结构体变量的值，可以通过结构体指针的方式来处理。而且通常情况下，其实我们更多是跟它的结构体的指针类型绑定。**

为什么呢？因为这样子我们可以提高传输的速度、传输的效率。因为大家都知道，如果你给结构体这个类型绑定，它在传输的时候是进行值拷贝；如果你给结构体指针类型绑定，那么这个时候它仅仅是拷贝一个地址就可以搞定这个事情了。

我们就以刚才讲过的这个 `Circle` 为例。前面不是刚刚讲过这个 circle 吗？这个时候大家看我们绑定的是跟 `Circle` 这个结构体绑定的。但是这种绑定的方式它有一个问题——它会把你传递的这个 `c` 进行一个值拷贝。那这样的话效率比较低。

因此我们更多情况下会这么做：为了提高效率，通常我们和方法绑定的是**结构体的指针类型**。注意听，这块我们写个 `*` 绑定：

```go
func (c *Circle) area2() float64 {
	return 3.14 * c.radius * c.radius
}
```

那这个时候，当我们调用这个方法的时候，其实这个时候传的就是这个 `c` 的一个地址。那我们来调用一下，怎么来写呢？

按理说一个标准的调用方式，其实因为这个时候它本身已经是一个地址了，所以说我们标准的调用方式应该这样写：

```go
var c Circle
c.radius = 5.0

res2 := (&c).area2()
```

为什么？因为你这儿是指针嘛，所以说我传一个地址过去。同样道理，因为这个 `c` 已经是指针了，标准的访问字段方式应该这样写：

```go
(*c).radius
```

这样写才是正确的。我们执行一下，结果是 `78.5`，应该是正确的。

但是我要说一下：**但是 Go 语言的设计者觉得这样调用太麻烦了，所以他在底层的编译器里面做了一个优化。** 编译器会自动地给我们加上一个取地址符号，所以 `c.area2()` 这样写也可以，等价于上面那个写法。同样道理，`c.radius` 它也支持这样写，它也等价于 `(*c).radius`。

这样写了过后我们来运行一下看看对不对呢？为了看到有变化，我把它改成 6。我们看，`c.area2()` 它也是可以的。执行一下，只要面积变化了，就是对的。好，所以说这种写法大家要明白，就是为什么这样可以写。不然的话你去跟别人一讲，"这个地方是个指针，那你为什么可以这样去写呢？为什么跟原先这个类型是一样的呢？"

其实不一样，**它底层做了优化而已，只是在形式上一样，但是机制已经发生了完全的变化。**

为什么这么说呢？我问大家一个问题，如果我在这个方法里面这样写：

```go
c.radius = 10
```

如果我在这里面把 `c.radius` 改成了 10，那我问大家，在这外面这个 `c` 的 `radius` 有没有发生变化？

**会发生变化。** 因为这个地方传的时候，`c.area2()` 因为你这个类型是指针类型，那么这个时候这个 `c` 它拷贝的这个副本其实不再是这个结构体、整个这个结构体，而只是它的一个指针。因此这个 `c` 其实就直接指向了 main 函数里面的 `c`。因此你在方法里边对它进行了修改的话，其实在外面这个地方也会发生变化。

```text
   值接收者（默认）                     指针接收者
   ---------------------------------   ---------------------------------
   main 栈                              main 栈
   +----------------------------+       +----------------------------+
   | c --> [ radius : 6.0 ]     |       | c --> [ radius : 6.0 ]     |
   +----------------------------+       +-------------+--------------+
            |                                       |
            |  值拷贝（两份，互不影响）              | 地址拷贝（同一份）
            v                                       v
   area2 栈                             area2 栈
   +----------------------------+       +----------------------------+
   | c --> [ radius : 6.0 ]     |       | c : (只存一个地址)          |
   +----------------------------+       +----------------------------+
   方法里改 c.radius，外面不变           方法里改 c.radius，外面跟着变
```

读图说明：左边是两套独立的数据；右边 `area2` 栈里只有一个地址，指回了 `main` 栈里的同一块空间。**这就是"形式一样、机制完全不同"的含义。**

> **结论**：这五个点不要小看，有些程序员工作了一年两年，可能都没有把这个搞清楚。尤其是这一点——通常我们是实现结构体指针的方法来做，因为这样的效率会高。同样一个功能，为什么你的程序跑起来那么快而别人的那么慢？就是因为你实现的是结构体指针，人家是直接传一个地址过去就完事了。

#### 细节三：方法也能挂在非结构体的自定义类型上

Golang 中的方法是作用在指定数据类型上的，这一点我们前面已经说过了。**只要是自定义类型都可以有方法，不仅是结构体。** 比如说像 `int`、`float32` 等也可以有自己的方法。

新建一个文件，方法的一个细节 `methoddetails`，新建一个 `main.go`。比如我现在有这么一个自定义的 `integer`：

```go
type integer int
```

我就叫 int。也就是说我给 int 做了一个自定义，`integer` 就是 `int` 的一个别名。那我给它绑定一个方法：

```go
func (i integer) print() {
	fmt.Println("i =", i)
}
```

我就叫 `print`，打印一下它的值。非常简单，一个非常简单的方法。

```go
func main() {
	var i integer
	i = 10
	i.print()
}
```

我运行一下，发现这个时候输出了 `i = 10`，没有任何问题。

**大家不要认为我们的方法一定是跟一个结构体绑定，它也可以是 `int`、`float32` 这种自定义的类型。**

甚至你还可以通过这个方法来修改我们的变量。比如编写一个方法，可以改变一个整数的值、改变 `i` 的值，也可以做到。我们利用指针的方式来做：

```go
func (i *integer) change() {
	*i = *i + 1
}

func main() {
	var i integer
	i = 10
	i.print()

	i.change()
	fmt.Println("i =", i)
}
```

大家知道什么意思吧？就是把这个值取出来加 1 再重新赋给它，相当于改变这个 `i` 本身的值。而且因为它是指针，因此你传过来什么值它就把它自己改了。

我这样用：`i.change()`。因为它是指针，所以这个 `i` 其实和 main 函数里的 `i` 是同一个 `i`——因为这个时候它进行的是**地址拷贝，并不是值拷贝**，所以这里面对 `i` 的修改会直接影响到 main 函数里面的 `i`。

跑起来，你可以看到的确变成了 `11`。这就证明了我们的观点：不一定是结构体，像 `int`、`float` 的自定义类型也可以去绑定方法。

#### 细节四：方法名的首字母决定它能不能被外部调用

方法的访问控制的规则和函数是一样的：**方法名首字母小写，只能在本包访问；方法名的首字母大写，那么就可以在本包或者其他包访问。**

这块我就不再多说了，因为以前我们讲过案例。你要记住，如果 `print` 是小写的，那么 `print` 方法其实只能在这个 main 包里面用，别的地方用不了。如果你把它改成大写的 `Print`，那么这个方法就相当于变成一个公开的方法，在其他包也可以去调用这个类型的 `Print` 方法。

#### 细节五：实现了 String，fmt.Println 就会自动调用它

如果一个类型实现了 `String` 这个方法，那么在 `fmt.Println` 输出的时候，就会默认调用这个变量的 `String` 方法进行输出。

这个也很有用，比如我们在输出日志的时候，或者输出一个结构体的信息，就可以用这种方式来解决，很轻松。以后就不用每次都写那么长的一段代码，直接把它封装到 `String` 方法里面就可以。

我们来做个案例。比如现在有一个结构体叫 `Student`，学生里面有名字 `Name string`，学生还有年龄 `Age int`。

假设我给 `Student` 实现 `String` 方法：

```go
type Student struct {
	Name string
	Age  int
}

func (stu *Student) String() string {
	str := fmt.Sprintf("Name=[%v] Age=[%v]", stu.Name, stu.Age)
	return str
}

func main() {
	stu := Student{
		Name: "tom",
		Age:  20,
	}

	fmt.Println(&stu)
}
```

我传一个 `stu` 变量进来和 `Student` 绑定，最好直接用指针绑定。用指针是因为待会儿就不用每次都传一个副本过来，不划算，所以直接实现它的指针类型就完了。

如果同学们学过 Java 的话，其实就知道 Java 里面也有一个方法叫 `toString`，和这个很相似。

这个时候当我们在输出 `Student` 变量的时候，它就会默认调用这个方法。怎么证明呢？先定义一个 `Student` 变量。大家看到它是一个 `Student` 类型，但是人家方法接收者是指针类型，所以在输出的时候要这样写：

```go
fmt.Println(&stu)
```

**因为人家是指针，所以你传个地址。** 如果你不传地址直接传 `stu`，就相当于把这个结构体的字段和名字按默认方式输出出来，它肯定不会去调 `String` 这个方法。这时它就是按照原先的方式把结构体输出来。

执行一下，效果就不一样了。我们可以看到此时此刻它输出的内容是：`Name=[tom] Age=[20]`。这两个中括号就是我们在程序里面写出来的。

这种方式，如果你实现了 `Student` 类型的 `String` 方法，就会自动调用。如果没实现，输出的就是它的一个地址而已。如果把这个实现了，调用的就是 `String` 方法来完成操作。

### 先做三个：把打印和计算一步步交给方法

#### 打印一个 10×8 的矩形

第一个题说：编写一个结构体，这个结构体的名字就叫 `MethodUtils`。然后编写一个方法——编写一个方法肯定是作用在这个结构体类型上的。方法它说不需要参数，在方法中打印 $10 \times 8$ 的矩形，在 main 方法中调用该函数。

因为它是练习，我们专门放到方法的练习 `methodexercise` 里面，新建一个 `main.go`。

我们先看看它的要求。编写一个结构体，这个结构体的名字人家已经告诉你了，就叫 `MethodUtils`，那就写：

```go
type MethodUtils struct {

}
```

注意听，这个结构体它说有方法，那它没有字段就算了，没有就算了，也可以。因为他在这边没有说给这个结构体什么样的字段，所以没有就算了。没有的话，我们就直接写方法了。

编写方法，给 `MethodUtils` 编写方法。方法的名字他没有说，但是他说了方法不需要参数，在方法中打印 $10 \times 8$ 的一个矩形，在 main 方法中调用。因为它没有参数，也没有返回值，实际上就是完成一个打印的任务，那就好办了：

```go
func (mu MethodUtils) print() {
	for i := 1; i <= 10; i++ {
		for j := 1; j <= 8; j++ {
			fmt.Print("*")
		}
		fmt.Println()
	}
}

func main() {
	var mu MethodUtils
	mu.print()
}
```

首先它跟这个结构体绑定，然后写一个函数的名字叫 `print`。没有参数，没有返回值。打印 $10 \times 8$ 的矩形，两个 `for` 循环就搞定：外层循环循环 10 次，每一次里边打印 8 个星号。直接打一个星号，打完这个星号以后换行，换行的话咱们 `Println` 就可以了。

然后他说在 main 方法里面去调用该函数。调用它的操作也很简单，你首先得有这么一个变量，简单一点。然后我们调用它：`mu.print()`。完事了。

我们运行一下。此时此刻它就打印出来这样一个图形了，对不对？第一题就做完了，简单。

> **结论**：通过这个地方我们可以认识到，**方法其实它对应的结构体也可以没有任何字段。**

#### 把行和列变成参数

第二个题：编写一个方法，提供 `m` 和 `n` 两个参数，方法打印 $m \times n$ 的矩形。这个就是要求大家去练习一下方法中如何接收两个参数。

我把这个拷贝一份，只是里面的内容不一样了。打印矩形，那就 `print2`，有两个参数，`m` 是个 int 型，`n` 是个 int 型。你怎么知道是 `int` 呢？你自己也应该能分析出来，因为 `m` 和 `n` 打矩形，那肯定是行和列，行和列肯定是整数，对不对？

其实我们只需要在前面这个代码里面改一点点就行了，把这个 10 改成 `m`，把这个 8 改成 `n`，完事了：

```go
func (mu MethodUtils) print2(m int, n int) {
	for i := 1; i <= m; i++ {
		for j := 1; j <= n; j++ {
			fmt.Print("*")
		}
		fmt.Println()
	}
}

func main() {
	var mu MethodUtils
	mu.print2(2, 6)
	fmt.Println()

	mu.print2(5, 20)
}
```

跑起来。我们打一个两行六列的。为了能够看到这个区别，我们打一个换行。两行六列，可以的。我们写大一点，比如来一个 5 行 20 列吧。这样看起来效果就比较明显了。

这个题就是再次让大家体验一下，我们一个方法中可以去接收参数是怎么实现的。

#### 再进一步，把面积算出来并返回

第三个题其实也是非常简单：编写一个方法，计算该矩形的面积，可以接收一个长为 `len`、宽为 `width`，将其作为方法的返回值。在 main 方法中调用该函数，并接收返回面积并打印。

这个其实就是在这个基础上又增加了一点——**有返回值**了。

得到一个面积，跟它绑定，还是老规矩：

```go
func (mu MethodUtils) area(len float64, width float64) (float64) {
	return len * width
}

func main() {
	var mu MethodUtils
	res := mu.area(2.5, 8.7)
	fmt.Println("面积为=", res)
}
```

他没说方法名字，我们就自己取一个。一个叫长度 `len`，当然这个长度它也可能有一个小数，所以我们最好是 `float64`——这些数据类型就要你自己来分析了。宽度 `width`，`float64`。返回类型肯定也是一个 `float64`，把它括起来。不过如果返回值只有一个，其实你括或者不括都可以。

面积也非常简单，`return len * width`，完事了。运行一下，我们可以看到结果就有了，`21.75`。

### 再做三个：接收更丰富的参数

我们再来看三个关于方法的课堂练习题。这三个里，我们统一把方法绑到 `MethodUtils` 的**指针类型**上——这样 `mu` 就不会进行值拷贝了。

#### 判断一个数是奇数还是偶数

第一个题：编写一个方法，判断一个数是奇数还是偶数。这个对我们来说应该没有难度。

判断是奇数还是偶数，那么就来一个 `judgeNumber`，判断一个数。既然判断一个数，你是不是应该把这个数传给我？所以有一个 `number int`。判断一个数是奇数还是偶数，我直接在这个函数里面把判断结果输出来就可以了，就没有什么返回值了。

```go
func (mu *MethodUtils) judgeNumber(number int) {
	if number % 2 == 0 {
		fmt.Println(number, "是偶数")
	} else {
		fmt.Println(number, "是奇数")
	}
}

func main() {
	var mu MethodUtils
	mu.judgeNumber(10)
	mu.judgeNumber(11)
}
```

因为这个时候它是指针类型，严格来说我们调用的时候应该先找到它指针这个类型，然后再调用 `judgeNumber`：`(*mu).judgeNumber(10)`。但是实际上大家都知道，编译器底层做了一个优化，所以也可以直接这样写：`mu.judgeNumber(10)`。

我们跑一下，10 是偶数；换一个数，比如说 11，11 是奇数。

#### 行、列和字符都交给调用者

第二个题：根据行列字符，打印对应的行数和列数的字符。比如说行数为 3，列为 2，字符为星号，就打印相对应的效果。

也就是说这个时候我们应该接收三个参数：一个是行，一个是列，还有一个就是打印的字符到底是什么字符。

```go
func (mu *MethodUtils) print3(n int, m int, key string) {
	for i := 1; i <= n; i++ {
		for j := 1; j <= m; j++ {
			fmt.Print(key)
		}
		fmt.Println()
	}
}

func main() {
	var mu MethodUtils
	mu.print3(7, 20, "#")
}
```

做得很灵活了。打印出来的就是我们需要的全部效果。如果想打另外一个符号，比如改成 `@` 符号，执行后就全部变成 `@` 符号了。

#### 给 Calculator 做加减乘除

第三个题：定义一个小小的计算器结构体，叫 `Calculator`，实现加减乘除四个功能。实现的形式有两：一种是分四个方法实现，一种是用一个方法搞定。

**如果分四个方法搞定**，那就分别计算加减乘除就可以了。

```go
type Calculator struct {
	Num1 float64
	Num2 float64
}

func (cal *Calculator) getSum() float64 {
	return cal.Num1 + cal.Num2
}

func (cal *Calculator) getSub() float64 {
	return cal.Num1 - cal.Num2
}
```

其它依此类推。测试的时候，首先还是得先创建一个 `Calculator` 的结构体变量：

```go
func main() {
	var cal Calculator
	cal.Num1 = 1.2
	cal.Num2 = 2.2

	fmt.Printf("sum = %.2f\n", cal.getSum())
	fmt.Printf("sub = %.2f\n", cal.getSub())
}
```

运行后结果是 `3.40` 和 `-1.00`，保留到小数点两位。

**如果你要用一个方法搞定**，肯定要接收两个数，同时还要接收运算符。我们给指针绑定一个方法，叫 `getResult`。这里面我们需要给它传入运算符，或者在结构体里面增加字段，看你的喜好。

传一个 `byte`，比如说它的运算符叫 `operator`。`operator` 是我们操作符的意思，大家查一下这个英文单词叫 operator。我们认为它是一个 `byte` 类型，没问题吧？最后它也返回一个结果，是 `float64`，这个没毛病。

这时候我们要做一个判断了，因为你这个运算符是什么，我要判断过后才能知道。所以说我现在先定一个结果放到这，默认给它一个 0.0。我用 `switch` 语句做判断：

```go
func (cal *Calculator) getResult(operator byte) float64 {
	var res float64
	switch operator {
	case '+':
		res = cal.Num1 + cal.Num2
	case '-':
		res = cal.Num1 - cal.Num2
	case '*':
		res = cal.Num1 * cal.Num2
	case '/':
		res = cal.Num1 / cal.Num2
	default:
		fmt.Println("运算符输入有误")
	}
	return res
}
```

当然它还有一种可能性就是它给的运算符不对，我们来一个 `default`。这地方就是没有取到，那么我们就输出一句话，说你的运算符有问题，`fmt.Println("运算符输入有误")`，输入有误。那如果有误的话，我们还是得给它返回一个值，那这个 `res` 我们就保留原先这个 0.0 就行了——就相当于说这个没有结果，但是我这地方会有一句话输出，他也知道。

那现在我们来调用它一下：

```go
func main() {
	var cal Calculator
	cal.Num1 = 1.2
	cal.Num2 = 2.2

	res := cal.getResult('+')
	fmt.Println("res =", res)
}
```

我们跑一下。我们发现 `res` 等于，还是一样的，`3.4`。因为我这没有格式化，所以说它输出的小数点非常多，这个不去管它了。

加法有了，你把它改成减法，它就按减法运算了，看到没有？`-1.0`，没问题。如果你把它改成乘法，那么这个地方就应该是这两个数相乘的结果，`2.64`。其它依次类推。

这些基本语法大家都要记得住，不要说现在写到这的时候把前面的内容又全部忘掉了，对吧？所以说要多写代码。

## 方法和函数的区别，以及面向对象编程的三部曲
> 对应块：BLK72 | 覆盖分集：P199-P200 | 块标题（分集名）：《198_尚硅谷_方法和函数区别说明》

我们来看一下方法和函数的区别。

我认为方法和函数的区别主要是三个方面。

### 调用方式不一样

第一个就是调用方式不一样。函数的调用方式直接通过函数名，然后传实参就可以了。

方法的调用方式，首先得有一个变量——当然这个变量应该是**和方法绑定的类型的变量**才可以，然后传入实际参数。这个在前面已经说过了。

### 普通函数的参数类型必须严格对应

第二点，对于普通函数，**接收者为值类型的时候，就不能将指针类型的数据传入，反之亦然**。这句话什么意思呢？就是说如果是一个函数，它如果是值类型，你就只能传值类型；它如果是指针类型，你就只能传指针类型。

我们来看一个案例来说话。新建一个文件夹，叫做 `method_vs_function`。

假设现在有一个结构体叫 `Person`：

```go
type Person struct {
	Name string
}

func test01(p Person) {
	fmt.Println(p.Name)
}
```

现在在 main 函数里面定义一个 `Person`：

```go
p := Person{"tom"}
test01(p)
```

因为这里是结构体类型，并不是指针类型，因此传的就是 `p`。运行之后它的结果就是 `tom`，是正确的。但是因为这里写的是 `Person`，你就不能传地址：

```go
test01(&p)      // 报错
```

如果这里有一个函数 `test02`，它是一个指针：

```go
func test02(p *Person) {
	fmt.Println(p.Name)
}
```

它是指针，在调用 `test02` 的时候，就只能传一个地址：

```go
test02(&p)      // 正确，输出 tom
```

传一个地址给指针类型，它跑起来结果也是 tom。但是因为你传 `test02(p)`，它也会报错。

所以这里就有一个严格的规定，即反之亦然：**如果它是指针，你就只能传地址；它如果是值类型，你就只能传值。**

### 但方法不一样：接收者说了算，调用形式说了不算

但是我们要说的是，方法不一样。比如给 `struct` 写一个方法，**接收者为值类型，可以直接用指针类型的变量调用该方法；反过来也是一样，如果接收者是指针类型，也可以用值类型的变量调用。**

给 `Person` 定义两个方法：

```go
func (p Person) test03() {
	p.Name = "jack"
	fmt.Println("test03() =", p.Name)
}
```

这里直接写的是值类型，不是指针类型。在调用的时候，`p.test03()` 肯定是没问题的，输出 jack。但是你会发现，这样调用它也可以：

```go
(&p).test03()
```

给 `p` 取了一个地址，然后调用 `test03` 也可以。为什么呢？因为编译器做了一个优化。**虽然传了一个地址，也能调用 `test03`，但是传进去之后，这个地方仍然是进行了一个值拷贝。**

在 main 函数中打印：

```go
fmt.Println("main() p.Name =", p.Name)
```

用 `p.test03()` 调用，因为是值拷贝，内部修改为 jack 肯定不会影响到外面的 tom，所以输出 tom。

但有些同学不能理解的是：通过 `(&p).test03()` 传了一个地址过去，调用完了之后再次打印，它**仍然还是 tom**。因为这只是形式上穿了一个地址，其实它在这种方式传递的时候，`p` 仍然是一个值拷贝，对外面这个 `p` 仍然是不会生效的。**从形式上看是传入了地址，但是本质仍然是值拷贝，因为方法接收者写的是值类型。** 编译器在做优化的时候，仍然把它改成了值拷贝的形式，语法上又支持这种写法。

同样，反过来也是一样。如果有一个 `test04`，把它改成一个指针类型：

```go
func (p *Person) test04() {
	p.Name = "mary"
	fmt.Println("test04() =", p.Name)
}
```

按照正规的方法来调用，应该这样调：

```go
(&p).test04()      // 因为是指针，所以传一个地址进去
```

调用完了之后，因为它又是指针，所以 `p.Name` 肯定被改掉了，`mary` 就会直接影响到外面的 `p`。

而且它还支持这种写法，直接：

```go
p.test04()         // 等价于 (&p).test04()
```

也可以。这种写法等价于 `(&p).test04()`，底层的编译器给我们做了一个优化处理。说明这样调用的效果跟上面是一样的，仍然会修改外面的值。

```text
  普通函数 test01(p Person)      普通函数 test02(p *Person)
  --------------------------------  --------------------------------
  test01(p)      OK              test02(&p)     OK
  test01(&p)     报错            test02(p)      报错
                                  形参类型与实参类型必须严格对应


  方法 test03 绑 Person（值）      方法 test04 绑 *Person（指针）
  --------------------------------  --------------------------------
  p.test03()     OK 值拷贝         (&p).test04()  OK 地址拷贝
  (&p).test03()  OK 值拷贝！       p.test04()     OK 地址拷贝！
                ↑形式是地址，                       ↑形式是值，
                 本质仍是值拷贝                     本质仍是地址拷贝
  改 p.Name：外面不变              改 p.Name：外面跟着变
```

读图说明：左边两个"调用方式不同但结果相同"，右边两个也是。方法这一栏里，括号里传什么已经不影响结果了——真正决定权在方法定义的地方。

> **结论**：不管形式是什么样，不管调用形式是如何，**真正决定是值拷贝还是地址拷贝，主要是看这个方法是和哪个类型绑定的**。如果是和值类型绑定的，比如我们前面写的这种 `Person`，大家都知道它是值类型，和它绑定的则是值拷贝；如果是和指针类型绑定，比如 `*Person` 这种，则地址拷贝。你不用去看形式到底是哪种方式调用，统统不管，我主要是看它到底是跟哪种类型绑定的，就可以决定这个结果。

这其实也说明了方法和函数的另一个区别：**方法就是它是跟别人绑定的，而函数它并不跟一个类型绑定，它并不跟一个具体的类型绑定，因此你直接调用就可以了。** 但是方法因为它是跟一个类型绑定的，那就必须通过这个类型的一个变量来调用这个方法。

当时 Go 语言设计者主要为了方便，结果这样一设计之后，反而容易让人混淆。这个概念其实很容易懵圈的——因为一般的人会觉得，你这儿不是按地址传了个地址给这个 `p` 吗？那你这个 `p` 就应该指向外面，但是实际上它仍然还是值拷贝。反过来也一样，从形式上看是传入一个值，但是本质上穿的其实是地址拷贝。

**为什么它是地址拷贝呢？其关键的原因主要看 `test04` 里边它跟它绑定的这个类型是什么。**

> **易错点**：大家一定要把这儿搞得很明白，不然的话以后肯定是看不懂别人代码的。给你出个面试题，几乎就倒了——你看就地址，那边一改，问你那边通过这个方法去修改这个 `p`，这个外面的 `p` 有没有修改？**一般来说 90% 以上的人都会说修改了，结果根本就没有修改，因为它本质仍是值拷贝。**

### 面向对象编程的三部曲

下面我们来看几个面向对象编程的应用实例。

首先我们看一下面向对象编程它有一个步骤，它的步骤大概分为三步：

| 步骤 | 做什么 | 要点 |
| --- | --- | --- |
| 第一步 | 声明结构体 | 把结构体的名称确定下来 |
| 第二步 | 编写结构体的字段 | 根据需求，把字段以及字段的类型定下来 |
| 第三步 | 编写结构体的方法 | 它有哪些方法，你把它确定下来 |

这是它的三部曲。

### 案例：把学生信息整理成一句话

那我们来看一个案例，比如这有个学生案例。

他说编写一个 `Student` 的结构体，包含这么一些字段。然后各个字段的类型他也告诉你了。然后他说在结构体中声明一个方法，返回一个 `string` 类型，方法返回信息中包含所有的字段值。说白了，他这个方法就是要把它这个结构体里面的各个字段的信息怎么样，显示出来、返回来。然后在 main 方法中创建这样一个实例，并访问 `say` 方法，并将调用结果打印输出。

对不对？他这个就把一个面向对象编程的一个步骤展示出来了。比如说名称告诉我们了，再比如说他把字段的名字以及类型告诉我们了。如果是我们自己在做开发的时候，那这些信息都要我们自己去分析。然后他告诉你要求写的方法，并且调用。

新建一个文件夹，`oop exercise`，新建一个文件叫 `main.go`。

首先他说编写一个结构体，那么先搞一个结构体下来。它有哪些字段呢？人家已经告诉你了，有这么五个字段：

```go
type Student struct {
	Name   string
	Gender string
	Age    int
	Id     int
	Score  float64
}
```

名字它的类型是 `string`；有一个性别 `gender`，也是 `string`；有一个年龄，是 `int` 类型；有一个 `id`，也是 `int` 类型；还有一个 `score`，成绩是一个 `float64`。

同时他说有一个方法叫 `say`，`say` 这个方法能够返回所有字段的值。好，这个也很简单。现在大家应该能看懂了，为了方便，我们直接把它声明成指针类型——指针类型这样提高我们的开发效率：

```go
func (student *Student) say() string {
	info := fmt.Sprintf("student的信息 name=[%v] gender=[%v] age=[%v] id=[%v] score=[%v]",
		student.Name, student.Gender, student.Age, student.Id, student.Score)
	return info
}
```

没有参数的传入，然后会返回一个字符串，我们就把它格式化，得到一个字符串吧，叫 `info`。学生的信息，好，我们写一个 `name=`，`%v` 一下。然后它的这个 `gender=`，也把它放在一个中括号里边去；然后它还有 `age=`，`id=`，再来一个就是 `score=`。

写完过后我们换一行，因为这行太长了。换行的时候，同学们看到，这逗号保留在上一行——**在给值的时候，每一行都要有逗号，包括最后一行**。

那么写完过后，我们来测试一下。我们先创建一个 `stu` 实例，其实就是一个变量：

```go
func main() {
	var stu = Student{
		Name:   "tom",
		Gender: "male",
		Age:    18,
		Id:     1000,
		Score:  99.98,
	}

	fmt.Println(stu.say())
}
```

我就直接这样写，直接赋值了，我就一次性搞定。名字呢我们叫汤姆，`gender` 是他的性别，性别呢我们叫 `male`。年龄是个整数，比如说 18。他的这个 `id` 它也是个整数，比如 1000。还有呢就是他的成绩，成绩是一个小数，比如他考了 99.98 分。

写完过后呢，我们就要调用它。调用它呢，因为他是一个指针类型的绑定，那么我们其实本身应该去取地址符的，但是呢完全可以直接调用。原因我就不再多说了。

跑起来。大家看学生的信息是这样子的：名字、性别、年龄、ID 和成绩，全部搞定，没问题。

好，这样第一个题我们就完成了。大家看，一个面向对象的一个小案例咱们就做完了。这里面整个这个顺序是：**先定义结构体，确定字段，再写方法，最后调用**。

### 案例：盒子的体积

紧接着我们看下一个案例，这个是盒子案例，同时也是一个面向对象的案例。要求是这样的：

编程创建一个 `Box` 的结构体，在其中声明三个字段，分别表示立方体的长、宽、高；长、宽、高要从终端获取，也就是说长宽高是从终端输入的；声明一个方法获取立方体的体积；最后调用它。

大家都知道立方体的体积它这个公式是怎么算的？还有印象吗？是不是长宽高的乘积？就长乘以宽，再乘以高。

这个因为思路也很简单，我就直接走代码了。首先还是根据我们面向对象编程的一个套路，首先先把这个结构体写出来：

```go
type Box struct {
	len    float64
	width  float64
	height float64
}

func (box *Box) getVolume() float64 {
	return box.len * box.width * box.height
}
```

它是一个 `struct` 类型。他说有三个字段长宽高，那长宽高的类型大家能确定下来吗？肯定都是 `float` 类型，对不对？这里写的时候不需要打逗号。

然后他说写一个方法获取立方体的体积，那没问题。`getVolume`，`volume` 就是得到体积。得到体积的时候，这个地方我们就返回一个值 `float64`。怎么算？非常简单，`box` 上面的这个长宽高，长乘以 `box` 的宽，`box` 点它的高。

然后下面我们就要调用了，测试一下：

```go
func main() {
	box := Box{
		len:    1.1,
		width:  2.0,
		height: 3.0,
	}

	volume := box.getVolume()
	fmt.Printf("体积为 %.2f\n", volume)
}
```

我们可以看到体积呢为这个，但是体积显然这个地方应该格式化一下比较好。我们把它格式化输出，`体积为 %.2f`，这样子呢它就是按照保留小数点的方式给我们输出的，对不对？非常简单，那就是 `6.60`。

题都不难哈，同学们，题都并不难，只是呢把这些东西整理一下。

（顺带提醒：写的时候眼睛放亮一点，`width` 这个单词容易少敲一个字母变成 `dth`，编译器会第一时间指出来。）

### 案例：景区门票

那么这个题做完了过后呢，我们紧接着再来做第三个题，叫景区门票案例。

它是这样子的：说一个景区根据游人的年龄收取不同的价格。比如，年龄大于 18，收费如何；其他情况，免费。请写一个 `Visitor` 结构体，根据年龄段来决定能够购买的门票价格并输出。

好，同学们现在可以先思考一下。这个题大家先思考两分钟，然后再听老师的讲解。**建议大家先写再听。**

名字和年龄呢是通过控制台输入的。而且呢，当输这个 `n` 的时候——大家看到，他输了一个年龄为 `n` 就代表要退出，输入一个姓名为 `n` 就退出程序。大家想想，这个怎么做？是不是咱们应该有个死循环呢？然后呢在这个循环里面来进行判断就可以了。

首先呢他说，这个有个 `Visitor` 结构体，那么我们先来一个 `type Visitor struct`。然后他说这里面有年龄，还有这个名字：

```go
type Visitor struct {
	Name string
	Age  int
}
```

那这个时候呢我们要写一个方法。他说有一个方法能够计算他的门票，好，那我就直接绑定一个方法 `func`，用一个 `Visitor` 指针类型。好，这边我们把它写成小写的，这样以示区别：

```go
func (visitor *Visitor) showPrice() {
	if visitor.Age >= 90 || visitor.Age <= 8 {
		fmt.Println("考虑到安全，不要玩耍")
		return
	}

	if visitor.Age > 18 {
		fmt.Printf("游客的名字为 %v 年龄为 %v 收费 20元\n", visitor.Name, visitor.Age)
	} else {
		fmt.Printf("游客的名字为 %v 年龄为 %v 免费\n", visitor.Name, visitor.Age)
	}
}
```

好，这里面我没有去做过多的判断啊，如果说写得严谨一点，要注意这个年龄进行一个判断。比如说他的年龄总不能总小于 10，一般小孩嘛，儿童我们不让他自己跑，比如说 8 岁，小于 8 岁我们就不让他玩了；比如大于 90 岁，我们也不让他来去游玩。

如果 `visitor.Age` 大于等于 90 岁吧，我们就不让他去一个人去游玩了，因为很危险。或者再加一个，`visitor.Age` 小于等于 8 岁，我们也不让他独自游玩，直接返回就行了——你的年龄太小，年龄太大或者太小，考虑到安全，就不要游玩了。

好，那这个时候下面代码就不走，直接 `return` 就完了。没返回任何东西，因为没有返回值嘛，就直接 `return`，就相当于说不执行了。

那现在呢我们怎么用它呢？测试的时候，同学们，我们首先先创建一个 `visitor`。但是名字呢还有年龄是输入的，所以说咱们要这么去做：

```go
var v Visitor
for {
	fmt.Println("请输入你的名字")
	fmt.Scanln(&v.Name)
	if v.Name == "n" {
		fmt.Println("退出程序")
		break
	}

	fmt.Println("请输入你的年龄")
	fmt.Scanln(&v.Age)

	v.showPrice()
}
```

这个地方呢我就用一个 `for` 循环，死循环在这个地方不停地判断。怎么拿这个值呢？**地址传进去一个地址**，`&v.Name`。然后呢我们让他继续再接收他的年龄，`&v.Age`。

做完了以后，我们就来调用一个方法，调用 `v` 里面的一个方法，叫 `v.showPrice`。

但是呢人家这还有一个要求，他说如果名字为 `n` 就退出程序，所以说这儿还应该加一个判断。如果他输入的这个名字 `Name` 它等于这个 `n` 了，那就意味着这个人想退出不想玩了，那就提示一句话，`fmt.Println`，说"退出程序"，就直接 `break` 到那个 `for` 循环外面。

我们运行一下。比如说我输入了一个名字叫 `Jackie`，年龄给了个 17 岁——它说游客的名字为 `Jackie`，年龄为 17，免费。因为他不到 18 嘛。

我们再输一个名字，比如说这个人的名字叫汤姆，年龄是 40 岁——游客的名字为汤姆，年龄为 40，收费 20 块钱。

假设现在我不想玩了，我就直接输了一个 `n`——退出程序。

对吧？那么我们也可以输一个年龄不正常的年龄，比如说输了一个汤姆，年龄 99 岁——年龄太大了，我们就说考虑到安全，你就不要玩了。然后提示你再重新输入名字，就下一个人嘛。比如说这个人呢叫做史密斯，这个人的年龄呢 19 岁。好，OK。退出，输 `n`。代码没有问题。

好，这就是我们写了一个景区门票的案例，也是通过使用面向对象这种方式来进行开发的。

## 结构体实例的八种写法，以及藏在后面的工厂模式
> 对应块：BLK73 | 覆盖分集：P201-P202 | 块标题（分集名）：《200_尚硅谷_创建struct实例指定字段值》

前面我们已经用过不少"创建结构体变量时直接把值填进去"的写法，但一直没有系统地把它整理出来。今天我就点出来讲清楚：**Golang 在创建结构体实例的时候，可以直接指定字段的值**。这件事有两种方式，每种方式又有四种写法，加起来八种，一定要会。

之所以要专门拎出来讲，是因为不明确说的话，大家总觉得模模糊糊的——明明见过、写过，却说不上来到底有哪几种。今天就一次讲透。

### 方式一：创建结构体本身

先定义一个最简单的结构体，后面所有例子都在它上面做文章：

```go
type Student struct {
	Name string
	Age  int
}
```

然后拿一个独立的案例文件专门练结构体赋值（`struct_assign`），把前面那一段公用代码搬过来，在里面写 `main` 函数。

#### 按字段的顺序直接赋值

最直接的一种：给一个大括号，里面按字段的顺序把值排好。

```go
var stu1 = Student{"小明", 18}
```

注意听，**按这个字段的顺序给它赋值**。第一个值对应第一个字段，第二个值对应第二个字段。上面 `Name` 在前、`Age` 在后，所以"小明"就是名字，18 就是年龄。这一点没什么可商量的，不然就错位了。

第二种是同样的值，只是用类型推导，前面不用写 `var`：

```go
stu2 := Student{"小明~", 20}
```

有同学会担心：我这个值跟字段顺序有时候会匹配不上。因为有些时候你写完了，过后不小心又把这个字段改了一下顺序，那这样写就会很危险——你会把"小明"赋给年龄，代码肯定报错。

来，我们把这种危险直接跑给你看：

```go
stu2 := Student{20, "小明~"}
```

这相当于把 20 给了名字、把"小明"给了 Age。你不用等它跑起来，编辑器已经检测出来了：它会告诉你 `int` 和 `string` 类型不匹配。编译器在类型层面就把你拦住了。

> **易错点**：按位置赋值的写法完全依赖字段的定义顺序。字段顺序一旦调整，所有按位置书写的代码都会错位。好在类型不同的时候编译器会直接报错，字段类型碰巧相同的话，那就只能靠眼睛看了——所以下面这种写法才是真正该用的。

#### 把字段名和字段值写在一起

更简洁、也更明确的一种写法：前面把字段名字也写上。

```go
var stu3 = Student{
	Name: "jacky",
	Age:  20,
}
```

直接告诉它 `Name` 是多少、`Age` 是多少。注意最后那个也有逗号，写的时候别漏。

这样写的好处是什么？**即使 `Student` 定义时字段顺序发生变化，这段代码也是正确的。**因为我明确指定了 `Age` 等于 20，这就不依赖于顺序了。别人读到这段代码，也一眼就知道这个 30 是年龄、名字是 mary。

这里同样可以用类型推导：

```go
stu4 := Student{
	Age:  30,
	Name: "mary",
}
```

我故意把顺序颠倒了一下，先写 `Age` 再写名字，一样没问题。记住这个地方逗号不要忘。

所以方式一的四种写法合起来是：

```go
var stu1 = Student{"小明", 18}                       // var + 按位置
stu2 := Student{"小明~", 20}                          // 推导 + 按位置
var stu3 = Student{Name: "jacky", Age: 20}           // var + 带字段名
stu4 := Student{Age: 30, Name: "mary"}               // 推导 + 带字段名
```

输出：

```go
fmt.Println(stu1, stu2, stu3, stu4)
```

得到 `{小明 18} {小明~ 20} {jacky 20} {mary 30}`，四个都是对的。

写代码的时候如果碰到 `stu4 declared and not used`（声明了未使用），那是编译器在提醒你少写了一次输出，把变量名补上就行。跑 `go run main.go`，值全对。

### 方式二：创建结构体的指针

有些时候我们是希望直接返回一个结构体的指针类型的，这个用的非常多，后面讲工厂模式的时候会用到。

做法非常简单：**前面加个 `&` 符号就行了。**

#### 四种写法和方式一一对应

```go
var stu5 *Student = &Student{"小王", 29}

stu6 := &Student{"小王~", 39}

var stu7 = &Student{
	Name: "小李",
	Age:  49,
}

stu8 := &Student{
	Age:  19,
	Name: "小李~",
}
```

看到规律了吗？方式一的四种写法，前面各加一个 `&`，就变成了方式二的四种写法。带字段名的写法同样不依赖顺序，`stu8` 里我把顺序颠倒过来也没有问题。

顺便说一句，有些人喜欢把类型也写在前面，就是想告诉编译器"我 `stu5` 的类型就是一个指向 Student 结构体的指针"：

```go
var stu5 *Student = &Student{"小王", 29}
```

这样写当然可以。不写也行，因为编译器会自动判断出 `stu5` 就是这么一个指针。

> **易错点**：方式一和方式二**完全不是一回事**。方式一是把结构体本身赋给变量，方式二是把结构体的指针赋给变量。`stu5`、`stu6`、`stu7`、`stu8` 都是指针类型。

#### 为什么"用法一样"却"本质不一样"

我画一下内存里的样子，你就明白差别在哪了：

```text
方式一：变量直接指向数据空间
   stu1 ─────────────────────► [ Name="小明" | Age=18 ]


方式二：变量先存一个地址，再由地址指向数据空间
   stu5 ──► 0xADDR ─────────► [ Name="小王" | Age=29 ]
              ↑
        这里多出来的一层，就是 & 造出来的
```

上面 `stu1` 是直接指向结构体的数据空间，中间没有"地址"这一说。`stu5` 则是先指向一个地址，这个地址再指向结构体的数据空间。

那为什么平时用起来感觉没差别？因为 **Golang 的编译器把 `Student` 和 `*Student` 的字段访问合并处理了**，你去访问字段的时候它会帮你做一层简化。所以在语法层面它俩用起来一样，但本质是不一样的，大家心里要清楚这个区别。

#### 输出里的 & 和取值符号

把 `stu5` 到 `stu8` 一起 `fmt.Println` 出来，你会看到一个现象：

```text
&{小王 29} &{小王~ 39} &{小李 49} &{小李~ 19}
```

值和方式一完全一样，只是**每个前面都多了一个 `&`**。它是在告诉你：这是一个指针，直接打印打出来的是地址。

怎么样把这个地址去掉？非常简单，用一个取值符号 `*`：

```go
fmt.Println(*stu5)
```

`*` 一加，那个地址符就没有了，输出又变回 `{小王 29}`。

这个道理很直白：你本身是指针，`*` 就是把指针指向的那块数据空间整个拿出来。上面那种画法是"先取地址、再拿到它"，而 `*stu5` 是直接一步取到里面的内容。

> **结论**：方式一和方式二，每种方式四种写法，一共八种。这八种一定要会。尤其是方式二，后面学工厂模式会直接用到。

### 工厂模式：Go 没有构造函数，那就自己造一个入口

讲完写法，我们接着往下走一个知识点——工厂模式。

#### 先说明一件事：Go 没有构造函数

**Go 的结构体没有构造函数。**这句话大家注意一下。

我们在别的传统面向对象编程语言里，都知道要获取一个实例是怎么做的：通过构造函数来获取。但 Go 里没有构造函数这个东西。

因为我们知道，Go 的结构体就类似于别的语言里的 class。结构体既然没有构造函数，那我们要怎么获取到一个结构体的实例呢？

**通常我们使用工厂模式来解决这个问题。**换句话说，你可以简单地理解成——工厂模式就相当于是以前构造函数的功能。

#### 一个很现实的需求

来看一个需求。现在有一个结构体，它的声明在 `model` 包里面：

```go
type Student struct {
	Name string
}
```

当然还会有其他字段。注意 `Student` 的首字母现在是大写的。如果首字母是大写，那么在其他包创建 `Student` 的对象实例——比如在 `main` 包里面——我们只要引入这个 `model` 包，就可以直接创建，没有任何问题。

**但是问题来了。**

假设我们把这个 `Student` 的首字母变成小写了呢？你想一想，如果首字母变成小写，那么你在 `main` 包里面就用不了了，就创建不了这个对象实例了，肯定是用不了的。

可是我们通常情况下又都会去用。我们既希望它的名称首字母是小写的（这样才有封装性），同时又希望在别的包能够创建它的实例，那又怎么办呢？

这时候就需要工厂模式来解决。

> **需求归纳**：当结构体定义时首字母是小写，但我们又需要在别的包里创建这个结构体类型的实例时，就需要工厂模式。

#### 案例：跨包创建结构体实例

我们完整地把这个案例搭起来，这块很重要，跟上思路。

项目结构是这样的——新建一个 `factory` 文件夹（工场模式，就叫 factory），下面再建两个包：`main` 和 `model`。

先在 `model` 包里创建文件 `student.go`：

```go
package model

type Student struct {
	Name  string
	Score float64
}
```

比如这个学生有一个考试的成绩，用 `float64`。

现在到 `main` 包里用它。这时候你是不是直接用就行了？没什么麻烦：

```go
package main

import (
	"chapter10/factory/model"
	"fmt"
)

func main() {
	// 创建一个 Student 的实例
	var stu = model.Student{
		Name:  "Tom",
		Score: 78.9,
	}

	fmt.Println(stu.Name, stu.Score)
}
```

顺手就能抓两个常见错误。第一种是**忘了引包**，编译器直接报 `undefined: Student`。第二种的坑更隐蔽：引包路径写成 `chapter10/factory/model` 的时候，斜杠方向写反了，顺序是反的。正确的是从 `src` 目录下面开始引，一级一级写下来：`chapter10` → `factory` → `model`。

引对了之后可能又提示"imported and not used"，那是因为你还没用。"怎么用呢？`model.`"——因为这个结构体是打在 `model` 包里面的，所以要带包名：`model.Student`。

然后 `cd` 到 `factory` 目录，跨包运行要注意路径，得走到 `main` 包里面去：

```bash
go run main/main.go
```

输出是 `Tom 78.9`，跟我们定义的完全一致。

> **结论**：如果 `model` 包里的结构体首字母是**大写**的，引入之后直接使用，没有任何问题。

#### 首字母一改小写，问题就来了

现在把 `model` 包里的 `Student` 改成小写的 `student`。

保存的一瞬间，代码马上报错：

```text
cannot refer to unexported name
```

`unexported` 就是"不可导出"。因为小写的是私有的，你在别的包里根本用不了。这样你就连对象实例都创建不了了——问题很严重。

#### 解决办法：加一个工厂方法

既然 `student` 首字母小写相当于是私有的、只能在 `model` 包里使用，那我们就在 `model` 包里面给它加一个方法，对外暴露一个入口。

我们前面学过方法，这里正好用上。直接写一个方法 `NewStudent`，让它接收两个参数：一个是名字 `n string`，一个是成绩 `s float64`。

返回类型是一个指针 `*student`，因为我们在里面创建完之后直接把指针返回出去：

```go
package model

type student struct {
	Name  string
	Score float64
}

func NewStudent(n string, s float64) *student {
	return &student{
		Name:  n,
		Score: s,
	}
}
```

我在本包使用自己的小写 `student` 是完全没有问题的，所以我直接初始化它，返回出去。

这就相当于：在你这个文件里面创建了一个 `student` 的对象实例，然后把它返回。因为返回的是指针，你可以理解成这块数据空间是放在堆里的、是一个共享的空间，大家都可以用。

回到 `main` 包里用起来就非常方便了：

```go
stu := model.NewStudent("tom~", 88.8)
```

`NewStudent` 本身首字母是大写的，所以你可以直接调用它。**通过工厂模式，我们照样拿到了一个 `student` 的实例。**

#### 怎么把这个实例的值取出来

因为返回的是指针，`stu` 实际上就是 `student` 的指针。直接打印会看到前面带着地址符：

```text
&{tom~ 88.8}
```

想拿到实例本身，用取值符号：

```go
fmt.Println(*stu)
```

这样就把整个实例的地址取出来了。

其他信息也能照样取：

```go
fmt.Println("name=", stu.Name)
fmt.Println("score=", stu.Score)
```

这里我要追问一句：明明 `stu` 是指针，为什么可以直接写 `stu.Name`？

因为**编译器在底层对指针访问字段的时候，会默认在前面加一个取值操作**。标准写法其实是 `(*stu).Name`，但因为编译器做了这层简化处理，我们写 `stu.Name` 也是可以的，没问题。跑起来，名字是 tom，score 是 88.8。

> **结论**：在 `model` 包里增加一个方法（这就是工厂模式），在 `main` 包里通过调用这个方法拿到实例。关键点在于——`stu` 始终是一个指向结构体的指针。

### 小写字段读不到怎么办：给结构体加一个取值方法

这里还有一个问题，我觉得挺严重的，留给大家想一想。

如果 `model` 包里的 `student` 结构体，除了名字以外，还有一个成绩字段。如果我把 `Score` 也改成小写的 `score`，我们还能正常访问吗？

改完之后一保存，错误立刻就来了。

第一种错误是：

```text
has no field or method Score, but does have score
```

它告诉你：没有大写的 `Score` 字段，但确实有一个小写的 `score`。

我们老老实实改成 `stu.score`，错误又变成：

```text
stu.score undefined (cannot refer to unexported field score)
```

`cannot refer to unexported field`——不可导出的字段不允许引用。

**这个问题怎么解决？**其实只要前面那些你听懂了，稍微改一改就知道了。既然 `score` 已经是小写的，那就干脆在 `student` 上面给它绑定一个方法，让这个方法去返回 `score` 就行了。这完全做得到。

如果 `score` 字段首字母小写，则在其他包不可以直接访问，那这时我们可以提供一个方法来解决：

```go
package model

type student struct {
	Name  string
	score float64
}

func NewStudent(n string, s float64) *student {
	return &student{
		Name:  n,
		score: s,
	}
}

// GetScore 对外公开，取出内部私有的 score 字段
func (s *student) GetScore() float64 {
	return s.score
}
```

我问大家一个问题：在这个方法里面，用 `s` 去访问小写的 `score`，可不可以？

当然可以。因为你本身就在 `model` 包里，访问本包的一个字段，哪怕它首字母小写，你也是有权利的。

那 `main` 包这边怎么用？

```go
stu := model.NewStudent("tom~", 98.8)

fmt.Println("name=", stu.Name)
fmt.Println("score=", stu.GetScore())
```

`GetScore` 首字母大写，所以这个方法本身是对外公开的，我就可以通过它这个对外公开的方法，去访问到那个私有的、不可导出的字段。没问题。

> **结论**：这其实就是 Go 里面的一种封装方式。后面我们写代码还会遇到大量类似的写法，大家一定要高度重视。

#### 指针接收者，这里必须再强调一次

这里有个特别重要的知识点，别又滑过去了：`stu` 还是指针。这个指针去调用它的方法，因为我们给这个**指针**绑定了方法。

那么前面讲过的那个问题——传过来的 `s` 到底是值拷贝还是地址拷贝——主要取决于这个参数。它传过来之后，这个 `s` 是不是就是那个 `student`？肯定是它，因为它是指针传递，那就是**地址拷贝**。

所以在方法里面我写 `s.score` 是可以的。

不过实际上，标准写法应该是：

```go
return (*s).score
```

因为它是指针。同理我们没有这么写，是因为底层又做了一次简化处理。

### 本讲提到的题目

#### 题目

如果 `model` 包里 `student` 结构体的 `Score` 字段改成小写的 `score`，我们还能在 `main` 包里正常访问它吗？如果不能，应该怎么解决？

#### 解析

字段名的首字母大小写决定了可见性，这一点跟结构体类型本身的首字母是同一个规则。

`score` 首字母小写，属于包内部私有的标识符。在 Go 里，**标识符的可见性是以包为单位的**：只要代码位于定义它的那个包内部，无论首字母是大写还是小写，都可以直接访问；但跨包访问时，只有首字母大写的标识符才可见。

所以在 `main` 包里直接写 `stu.Score` 会报 `has no field or method Score, but does have score`；改成 `stu.score` 会报 `stu.score undefined (cannot refer to unexported field score)`。两条路都走不通。

解决办法就是在定义它的包内部提供一个对外公开的方法，由这个方法在包内部读出小写字段，再把它返回给外部。这正是前面讲的**封装**的标准做法：`GetScore` 首字母大写因而可以在别处被调用；方法体运行在 `model` 包里，因此可以合法访问 `s.score`。

另外顺带记住方法签名：这里必须用**指针接收者** `func (s *student) GetScore() float64`。因为工厂方法返回的是 `*student`，只有把方法绑在指针上，`stu` 才能调到它；此时 `s` 拿到的是地址拷贝，方法内部对结构体的修改才会作用到原对象上。方法体里的标准写法是 `(*s).score`，写成 `s.score` 是编译器简化后的等价形式。

#### 答案

不能直接访问。解决办法是在 `model` 包内为 `student` 定义一个首字母大写的方法（例如 `GetScore`），由它返回私有的 `score` 字段：

```go
func (s *student) GetScore() float64 {
	return s.score
}
```

然后在 `main` 包中调用 `stu.GetScore()` 即可正常拿到成绩。

## 把 VS Code 调顺手：设置面板与常用快捷键
> 对应块：BLK74 | 覆盖分集：P203 | 块标题（分集名）：《202_尚硅谷_VSCode配置和快捷键》

用了这么一段时间 VS Code，今天我给大家分享一点使用技巧和经验。咱们用这个 IDE 的时候，总会积累出一些经验和技巧。

最典型的痛点是什么？打开 VS Code 之后，有些同学发现字体并不是很大的，它比较小；有时候字体也不是粗体的。怎么看怎么调？我今天就从头到尾捋一遍。

### 设置从哪里进：文件 → 首选项 → 设置

VS Code 跟我们平常用的有些 IDE 不太一样。它的设置入口是：**文件 → 首选项 → 设置**。

打开设置面板，你先搂一眼会发现，这边默认显示的是**默认的用户设置**。想改某个选项，就在这里把它改。

整个设置面板是按分类铺开的：常用的"通用"设置；"编辑器"里有 82 个设置，是最大的一块；往下还有源代码管理、工作台、窗口、文件、Zen 模式、文件资源管理器、搜索，再往下还能直接看 JSON 设置——如果你用 PHP 开发，这里还能设置 PHP 相关的内容；然后是调试、扩展。

设置面板里连语言相关的都有，你看 Go 的配置就更多了，一大堆 Go 语言的设置，标签相关的配置都在里面。再往下面还有 Git、GitHub 里的各种设置，包括合并等等。

我们平时用得最多的，绝大部分都在"编辑器"这一块。所以我们就在这里面找几个比较熟悉的来看。

#### 默认设置和用户设置：为什么点一下"编辑"，它就搬家了

以**字体大小**为例。你往下面拉，能看到它写得很清楚：**以像素为单位控制字号，默认就是 14**。

那问题来了——这个 14 在左边是改不了的。它觉得 14 就是最优的设置。

那怎么改？**你点它一下。**

一点击"编辑"，它就会把这个选项自动地挪到右边来。我再说一遍，你一点击编辑，它会把这个选项放到这一头。

那两头分别是什么？看这个布局你就明白了：

```text
┌───────────────────────────┬───────────────────────────┐
│  默认的设置（只读）        │  用户设置（你自己改的）   │
│  "Editor: Font Size  14"  │  ← 点"编辑"后落到这里    │
│  灰色的，改不了            │  可以随便改               │
└───────────────────────────┴───────────────────────────┘
                   ↓
        用户设置会「覆盖」默认设置
```

右边这一块的作用就是**用户设置**。左边是默认设置，右边是你自己的设置。如果你这边做了一个设置，就相当于"将设置放置此处以覆盖默认设置"。

所以你把 14 改成 18，保存一下，就生效了，就变成 18 了。

#### 字体的粗细也能在这儿改

**字体的粗细**同样可以在这里改。它的取值像正常的 100、200，还是粗体。

这里有一个现象值得说一说：假如你把右边已经改过的这条删掉，再点"编辑"，你会发现它上面写着**"文件设置已无法修改"**。这个不用管它，那是因为设置需要重新保存一下，保存之后就能继续改了。

现在再点编辑，它就会自动把这一项挪到右边来，你就在右边改。同样的道理，**字重、大小这些显示相关的项，都是这么调的**。

#### 更新和扩展的开关

字体之外，最常用的就是更新相关的了。往下面拉，在扩展这一块：

- **扩展的更新**。如果你希望后台自动去接受 VS Code 的更新，可以改这里；如果你不想自动更新，也可以把它关掉。点编辑，选择 `none`，这个更新就被关闭了。
- **启用 Windows 后台更新**。默认是启用的。如果你觉得它老往后台跑、你不舒服，也可以把它改成 `false`，就不自动更新了。
- **扩展本身是否自动更新**。这里默认是 `true`，你可以改成 `false` 关掉它，也可以改回 `true` 打开。我这里是已经改成 `false` 的。
- **扩展建议通知**。它的说明是"如果设置为 `true`，将不再显示扩展建议通知"。默认给你的是 `false`，代表只要有扩展建议的通知，它就会在这儿弹一个框框出来。如果你第一次用 VS Code，会发现它老弹这个框——它是在建议你装点什么扩展。如果你觉得这个烦，把它改成 `true` 就关掉了。我这里是关闭过的。

#### 自动建议：other、comments、strings

再往下，"编辑器"里有一堆"控制键入时是否应自动显示建议"的设置，就是它提不提示你函数名、变量名这些。

它默认值是 `other`，点过来之后会有提示，写得很清楚：

| 取值 | 含义 |
| --- | --- |
| `other` | 在字符串和注释外启用快速建议 |
| `comments` | 在注释内启用快速建议 |
| `strings` | 在字符串内启用快速建议 |

这一块有点像以前用 Eclipse 的那个体验——你敲一个点，它会给你提示相关的信息。

这里我必须给你提个醒：**有些建议，你在设置里打开了也不管用**，因为你没装相应的扩展。即使把开关打开了，它也不提示。为什么？因为这个配置要配合扩展同时使用才可以。

### 快捷键：查得到，也改得了

#### 快捷键面板在哪，怎么改一个

快捷键在哪里看？同样是 **文件 → 首选项 → 键盘快捷方式**，点进去之后，这边全是它的快捷方式，而且**可以直接搜索**。

我们随便找一个来看。比如你搜"删除"，它会列出：删除、删除右侧字符、删除行。你会发现"删除当前行"对应的快捷键是 **`Ctrl + Shift + K`**。

如果你觉得这个快捷键不好用，或者说它跟你的输入法、跟别的软件的快捷键相冲突了，你也可以改。

怎么改？点它旁边那支**小铅笔**，点一下会弹出一个输入框。在这个框框里面，你直接输入你想用的组合键就可以了。

比如我以 `test` 这行代码里的 `time.Now()` 为例，顺手删是很麻烦的。用快捷键，`Ctrl + Shift + K`，一下就删掉了。

那有的同学说：我就是不习惯这个快捷键，怎么办？可以自定义。点开小笔的输入框，我输入我认为更顺手的 `Ctrl + L`，按 `Enter` 键，它就生效了。这时候"删除当前行"的快捷键就变成了 `Ctrl + L`，我保存一下再试，确实删掉了。

**当然，一般情况下如果没有特殊需求，还是用它的默认值比较好。**除非你真的有这个需求，或者它的快捷键跟你的输入法、跟其他软件的快捷键相冲突了，你再去改。没有冲突的话，默认的应该是最好的。所以我还是把它恢复成 `Ctrl + Shift + K`。

#### 常用快捷键

这个面板里东西非常多——复制、调试、折叠、放大、替换、查找、格式化，一大堆。我挑几个你平时用得最多的说一下。

| 快捷键 | 作用 |
| --- | --- |
| `Ctrl + Shift + K` | 删除当前行（可自定义） |
| `Shift + Alt + ↑` / `Shift + Alt + ↓` | 向上／向下复制当前行 |
| `Alt + /` | 补全代码（快速修复，可自定义） |
| `Ctrl + /` | 添加注释／取消注释（按一次加，再按一次去） |
| `Shift + Alt + F` | 格式化文件 |
| `Shift + Alt + A` | 切换块注释 |
| `F11` | 切换全屏 |

逐个演示一下。

**复制当前行**。比如我要复制这一句话，`Shift + Alt + 向下光标`，它就自动往下复制了一份。很简单。

### 快捷键按下去没反应，两个原因

这个我要特别说明一下，因为新手一定会撞上。

#### 第一种：和输入法冲突

VS Code 的快捷键不要和输入法冲突，否则它就不生效——因为输入法在那一层的优先级更高。

**怎么办？改一下就完了。**到快捷键面板里找到"快速修复"那一项，点开，把默认的 `Ctrl + Space` 改成 `Alt + /`，然后就不冲突了。

## 抽象与封装：一个银行账号是怎么抽出来的，又怎么把字段锁起来
> 对应块：BLK75 | 覆盖分集：P204-P206 | 块标题（分集名）：《203_尚硅谷_面向对象编程思想-抽象》

按理说，讲完 VS Code 的使用技巧之后，接下来应该给大家讲面向对象的三大特性——在 Go 语言里面它的继承、封装、多态是怎么实现的。

但在讲三大特性之前，我要先给大家介绍一个东西：**抽象**。

我为什么要先讲它？因为**抽象这种思想是贯穿在整个面向对象编程过程里的**。不先把这一层垫上，后面讲封装、讲继承，你只会记住写法，记不住思路。

### 抽象：它是一种研究问题的方法

什么叫抽象呢？我们在前面定义一个结构体的时候，实际上做的就是一件事——**把一类事物共有的属性和行为提取出来**。

- 属性体现到程序里，就是**字段**；
- 行为体现到程序里，就是**方法**。

当我们把一类事物共有的属性和行为提取出来、形成一个物理模板，这个模板就是我们所说的**结构体**。

这种研究问题的方法，我们称之为**抽象**。

> **定义**：抽象准确地讲是一种研究问题的方法，或者说是一种编程的思维方式——把一类事物共有的属性与行为提取出来，形成可复用的模板。

这个抽象始终贯穿在我们面向对象编程的整个过程里。我们来看它到底是怎么一个过程。

#### 抽取共有的属性

我举一个实在的例子。现在有一个案例摆在面前：有很多的银行账号，1、2、3、4、n。

银行有很多种，民生银行、建行、工行等等。大家想一想，**不管哪个银行的账号，你是不是先要把它抽象出来它有哪些共有的属性？**这就是一种思维方式。

我们来分析。所有的银行账号，有哪些属性？

**第一，应该有账号。**得有账号吧。你没有账号，显然这个银行卡它是不存在的。

**第二，有密码。**有同学说"我这个银行账号没有密码，是空的"——我告诉你，空密码就是你的密码。密码这个属性是客观存在的。

**第三，所有的账号都应该有余额。**有同学说"老师我这个没有余额，余额是零"——零就是你的余额。就算你欠人家的钱，负一万，负一万就是你的余额。

#### 抽取共有的行为

有了字段以后，下面我们抽象出它有哪些行为——这个卡号能做哪些事情？行为体现到程序里就是方法。

**第一，存款。**没有哪一个银行卡是不能存款的。如果不能存款，除非它被临时冻结了还差不多。

**第二，取款。**有些同学说有些账号就是只能存不能取——那只是取的人不是你而已，可能是银行或者别的机构。钱存进去如果取不出来，那还了得。

**第三，查询余额。**你都不能查询，那肯定跑不起来吧。

当然还有很多其他的，我就不分析那么多了。我分析出来的就是银行账号必须的一些功能。

**你看，我把这个抽象过来的一个过程、分析的这个思路，其实就是抽象。**

#### 把抽象变成物理模板

当你把一类事物的属性和行为抽取出来以后，下一步要做的事情就是**把它用代码具体呈现出来**——形成一个物理模板。

这个物理模板到我们这儿，准确地讲就是一个结构体。

我们先建一个文件夹，叫 `chapter11`，在下面新建一个文件叫 `main.go`。打上包名，把公用部分拿过来，然后定义结构体。

**第一步：定名字。**这个账号的结构体，我们叫 `Account`。

**第二步：把字段落进去。**

```go
type Account struct {
	AccountNo string
	Pwd       string
	Balance   float64
}
```

注意听，这一步就是刚才抽象出来的三个属性——`AccountNo` 账号是 `string`，`Pwd` 密码也是 `string`，`Balance` 余额是 `float64`。

**第三步：把方法绑上去。**存款方法名叫 `Deposit`，取款方法名叫 `WithDraw`，查询方法名叫 `Query`。因为方法要绑定到类型上，所以接收者写成 `(account *Account)`。

### 让抽象跑起来：一个能存取查的 Account

#### Deposit：先校验，再入账

存款要传几个信息进去？你至少要告诉我要存多少钱——`money float64`；同时还应该有一个密码——`pwd string`。为什么存款也要密码？你打开 ATM 机存钱，在存款之前其实也是需要密码的。

返回值呢？存款的话我们干脆就不返回了，直接在里面提示它显示一条存款信息。

写的时候有三个要点：

```go
func (account *Account) Deposit(money float64, pwd string) {
	// 先比对密码
	if pwd != account.Pwd {
		fmt.Println("你输入的密码不正确")
		return
	}

	// 再检测存款金额是否正确
	if money <= 0 {
		fmt.Println("你输入的金额不正确")
		return
	}

	// 两个校验都过了，才真正存进去
	account.Balance += money
	fmt.Println("存款成功")
}
```

看这个顺序：既然你要存款，先要看密码；密码对了，再看你要存的钱。如果你存的钱都小于等于零，肯定不能让你走；检测不通过就 `return` 直接退出，不玩了。

最后既然保存完了，就提示一下"存款成功"。

#### WithDraw：多一条"不能超过余额"

取款这个方法其实跟上面很像，照着改一下就行，把名字改成 `WithDraw`——取款的意思。参数一样，`money` 和 `pwd`。

各位同学请思考一个问题：**什么情况下取款金额不正确？**

如果你取的这个钱比你的余额还要多，那肯定不正确。**等于可以**，大于了余额就不行。当然你也不能取小于零的——说我要取零元，取得出来吗？说我要取负一万，取得出来吗？肯定取不出来。

所以这里要加一个判断：

```go
func (account *Account) WithDraw(money float64, pwd string) {
	if pwd != account.Pwd {
		fmt.Println("你输入的密码不正确")
		return
	}

	// 或者：取款金额不能为负，也不能超过余额
	if money <= 0 || money > account.Balance {
		fmt.Println("你输入的金额不正确")
		return
	}

	account.Balance -= money
	fmt.Println("取款成功")
}
```

校验全过了，就把这个钱减掉——取款成功。

#### Query：只要一个密码

查询余额只要传一个密码就可以了。密码不对肯定不让你查，否则就把余额打出来。

```go
func (account *Account) Query(pwd string) {
	if pwd != account.Pwd {
		fmt.Println("你输入的密码不正确")
		return
	}
	fmt.Printf("你的账号为 %v，余额为 %v\n", account.AccountNo, account.Balance)
}
```

大家看这段代码，它把我们刚才整个抽象的东西变成了代码。大家是不是感觉到这是一种思路了？**先是属性、行为，然后定名字，然后写代码。**而且越来越有面向对象的感觉了——我们这个对象其实就是银行卡、就是账号。

#### 跑一遍：100 → 300 → 150

最后测一把。因为结构体首字母是大写的，**这里我们不需要工厂模式，直接创建就行**：

```go
func main() {
	account := &Account{
		AccountNo: "111111",
		Pwd:       "666666",
		Balance:   100,
	}

	account.Query("666666")           // 查一下现在有多少钱
	account.Deposit(200, "666666")    // 存 200
	account.Query("666666")           // 再查
	account.WithDraw(150, "666666")   // 取 150
	account.Query("666666")           // 再查
}
```

密码在开号的时候默认设置为 6 个 6；余额一般来讲银行开卡的时候会让你存 100 块钱，我们就存一个 100。

跑起来的结果是这样的：

```text
你的账号为 111111，余额为 100
存款成功
你的账号为 111111，余额为 300
取款成功
你的账号为 111111，余额为 150
```

刚开账号余额 100，存了 200 变成 300，取了 150 还剩 150，完全正确。

> **易错点**：我第一次跑的时候报了个 `undefined: save money`——我写的调用名是 `save money`，可函数实际叫 `Deposit`。写调用之前先对一遍函数名。密码打错几位（比如打成 5 个 6）也一样会走到"输入的密码不正确"那条分支，这正是校验该有的行为。

### 封装：字段和对字段的操作封装在一起

现在进入面向对象三大特性里的第一个——**封装**，英文叫 encapsulation。

Go 里也有封装、继承、多态这三大特性，只是实现方式跟传统的 OOP 不太一样，因为设计者对它做了一些简化。这一点要提前给大家打个预防针。

#### 什么叫封装

封装的意思就是：**把抽象出来的字段和对字段的操作封装在一起。**

举个例子。比如你有一个字段叫 `salary`（薪水），但是这个薪水你不希望它是公开的，所以你就把这个字段做成私有的——首字母小写。首字母小写过后，你再对这个字段提供一个公开的方法，让别人通过方法去操作它。这就叫封装。

> **定义**：数据被保护在内部，程序的其他包只有通过被授权的操作——也就是我们所说的方法——才能对字段进行操作。这一点和别的编程语言是一样的。

这个概念很好懂，我打个大家天天都在用的比方：**就好比我们对电视机的操作。**

要把音量调大，只要通过遥控器按一下按钮就行了。但是电视机内部的结构，其实并不需要我们去管理。将来我们对字段的操作也一样——只需要调用方法就可以完成，具体的操作由方法帮我们完成，而方法当然是我们自己写的。

#### 封装能带来什么

封装的一大好处是**隐藏实现的细节**，并且**可以对数据做一个验证，保证安全合理**。

举个例子。有个 `age` 字段，人的年龄总是在一个范围的，一般来讲不会超过现在世界上最大年龄的人，大概 130 岁左右。说得宽一点，不会超过 150。那假设有人在编程的时候给这个年龄设置了 200 岁，这就很不合理了。

**我怎么控制这个事情呢？我就可以通过一个方法来对这个数据做验证**，只有在数据合理的情况下，我才把这个值设置进去、才让它修改成功。这时候封装就起到作用了。

大家还记得前面那个 `Account` 吗？你看那段代码其实也体现了封装。**我们在取钱的时候，最终就是要改变它的余额。**如果没有这个函数把这个操作封装起来，别人就可以直接把这个 `balance` 减一下——那可能就不合理了。比如别人要去取钱，他明明余额只有一块钱，结果他要取一万块钱，你就给他取了，肯定不合理。

那怎么办呢？**加一段代码对它进行一个校验。**这就是封装的一个好处。

对别的用户来说，他只要输入一个要取的金额、把密码一输进去，最后我们告诉他取款成功还是没成功就行了。

所以封装的作用可以总结成两条：

- **隐藏实现的细节**——对调用者来说，具体你怎么实现我并不关心，你只要给我实现就行；
- **对数据进行校验**——只有合理我才去操作，不合理我就不给你操作。比如这里你输入的金额不正确、密码不正确，我就退出了。

#### Go 里怎么实现封装

在 Go 里封装主要有这么两种实现方式。

**第一种：把结构体、字段（属性）的首字母小写。**

比如我们想把余额封装起来，就写个小写的 `b`。写了一个小写的 `b`，别的包就不能访问了——当然，本包还是可以访问。

**第二种：通过方法、通过包来实现封装。**

要去操作这个属性，你就必须通过方法。再比如通过包来实现——我让你别的包用不了本包的一些方法和属性，这也能体现出封装。

### Go 实现封装的具体步骤

在 Go 里面封装怎么实现呢？其实还是很简单，主要就那么一种方式，一共四步。

**第一步：把结构体、字段（属性）的首字母小写。**

这里我要特别强调一下，因为这一点跟 Java 不一样，也是很多学过 Java 的同学最不好理解的地方。

Java 有一个 `private`，连本包都不能访问——只有类内部授权才能访问，外面哪儿都用不了。**但是 Go 不是这样。**Go 弱化了这种封装，它的封装程度并不像 Java 或者其他语言那么高，它没有 `private`。

所以你写小写之后——**本包还是可以访问的**。别老想着"我本包里是不是也访问不了"，不是的，可以访问，只是别的包访问不了。

**第二步：给结构体所在的包提供一个工厂模式的函数。**

就是我们前面写的那个。因为你想让别的包来用，那只能给它一个工厂模式写的函数，首字母大写，类似一个构造函数。

**第三步：提供一个首字母大写的 Set 方法。**

为什么要大写 Set？因为你希望别的包来使用它，那就只能提供一个 Set 方法来对字段进行设置。它类似于其他语言的 `public`，因为你首字母大写嘛。

而且——**你在 Set 里面可以加入你的业务逻辑。**比如你要给 `age` 这个字段设一个值，那在 Set 里面就可以加一些判断：如果设置进来的年龄必须在 1 到 150 之间，我才给你设置，否则我就拒绝给你设置这个值。这不就是封装的体现吗？

```go
func (p *person) SetAge(age int) {
	if age > 0 && age < 150 {
		p.age = age
	} else {
		fmt.Println("年龄范围不正确")
	}
}
```

**必须通过我授权的这个方法，才能操作我私有的这个 `age`。**

**第四步：提供一个首字母大写的 Get 方法。**

既然有 Set，那一般就会配一个 Get。Get 方法也是首字母大写。然后把你需要返回的字段返回出去：

```go
func (p *person) GetAge() int {
	return p.age
}
```

因为 `GetAge` 跟这个结构体绑定了，同时首字母又是大写，那我当然就可以去用它了。

#### Go 为什么不强调封装

这一点我要特别给同学们强调：**在 Go 开发中并没有特别强调封装。**

Go 的面向对象本身就是做了很多简化的，所以它并不是特别强调封装这个概念。这点不像 Java——Java 里所有的字段一般来讲都会做成私有的，然后每一个属性都设置一对 Getter/Setter 方法。

**但是 Go 里面它并没有特别强调封装，它认为没这个必要。**

为什么认为没这个必要呢？因为它觉得，你作为一个程序员、开发程序员，**你应该保证你的代码是准确的**。你设这个年龄，你为什么要设置一个 200 岁的年龄？这些事情在编程的时候程序员就应该去控制。

当然了，你适当地用 Set、Get 方法，它也不反对，因为封装本来就是靠这种方式来体现的。**但它并不特别强调这个东西。**

所以我特别提醒学过 Java 的朋友：**不要总是用 Java 的语法特征来看待 Go。**你后面会发现，它连构造函数都没有，它连 `extends` 都没有，它连方法的重载都没有——它做了很多简化。

### 封装快速入门：给 person 加一道门

我们来看一个完整的封装案例，要求是这样的：**不能随便查看人的年龄、工资等隐私，并对输入的年龄进行合理的判断、校验。**

案例的工程结构是这样设计的：创建两个包，一个是 `model` 包，里面放 `person.go`；一个是 `main` 包，里面放 `main.go`，它去调用 `person`。

注意——**建包，不是建文件**。因为只有分成两个包，才能演示出封装的效果。

#### model 包：小写的结构体、工厂方法和两组 Set/Get

在 `model` 包里面新建 `person.go`：

```go
package model

type person struct {
	Name   string
	age    int
	salary float64
}
```

注意听，**`person` 我故意把小写**——因为我想封装。在实际开发中也不一定就要小写，写成大写让别人访问也是可以的。

三个字段里，`Name` 是公开的；`age` 和 `salary` 我故意写成小写，说明这两个是不可导出的，其他包不能直接访问。

接下来，在 `main` 包里现在肯定创建不了 `person` 结构体变量了。怎么办？**写一个工厂模式的函数，相当于构造函数。**

```go
func NewPerson(name string) *person {
	return &person{
		Name: name,
	}
}
```

返回一个指针，把 `Name` 填进去。因为 `Name` 是对外公开的，所以工厂函数只需要接收一个名字。

然后，为了访问 `age` 和 `salary`，我们提供**一对 Set 方法和 Get 方法**。年龄这组：

```go
func (p *person) SetAge(age int) {
	if age > 0 && age < 150 {
		p.age = age
	} else {
		fmt.Println("年龄范围不正确")
		// 给程序员一个默认值，或者保留原值
	}
}

func (p *person) GetAge() int {
	return p.age
}
```

这里我加了一个必要的判断：年龄只能大于 0 且小于 150，合理才放进去；不合理就提示"年龄范围不正确"，不做任何操作。

那你不给它值，`p.age` 默认就是 0；你也可以给个默认值，看你自己的喜好——有些程序员会给个默认值，看你的需求。我这儿保留原值。

薪水这组是一样的思路，只是判断条件换了：

```go
func (p *person) SetSalary(sal float64) {
	if sal >= 3000 && sal <= 30000 {
		p.salary = sal
	} else {
		fmt.Println("薪水范围不正确..")
	}
}

func (p *person) GetSalary() float64 {
	return p.salary
}
```

假设我们认为一个人的薪水至少在 3000 到 30000 之间：太低了就没人来这儿工作了，太高了也不合理。在这个范围内就设置进去，否则提示"薪水范围不正确"，不给它设置，保留原来的值。

#### main 包：只能通过方法去碰私有字段

在 `main` 包里面用它：

```go
package main

import (
	"fmt"

	"go_code/chapter11/encapsulate/model"
)

func main() {
	p := model.NewPerson("smith")
	fmt.Println(p)
}
```

引包的时候从 `src` 这个地方开始引：先写 `go_code`，正斜杠，`chapter11`，然后是 `encapsulate`，最后 `model`。

先跑一遍看看：`smith 0 0` 出来了。名字公开，年龄和薪水是 0。

但是现在你会发现，**你直接去取它的年龄是取不到的。**比如说我想直接给它赋一个年龄：

```go
p.age = 18
```

这样肯定直接报错，编辑器已经告诉你了：`cannot refer to`——不可以引用一个不可导出的字段。

**怎么赋值呢？非常简单，调用我们刚才写的那个方法：**

```go
func main() {
	p := model.NewPerson("smith")

	p.SetAge(18)
	p.SetSalary(5000)

	fmt.Println(p)
	fmt.Println(p.Name, " age =", p.GetAge(), " sal =", p.GetSalary())
}
```

给它来个 18 岁；同样道理，设置薪水也是一样的，比如这个人一个月挣 5000 块钱。

取值也有讲究：`p.Name` 是可以直接操作的，因为 `Name` 首字母大写、在别的包可以使用。**但是年龄不能这样去取，这样取也会报错**，得用 `GetAge`。薪水也一样，得用 `GetSalary`。

跑起来：

```text
&{smith 18 5000}
smith  age = 18  sal = 5000
```

正确。

> **易错点**：这里我踩了一个坑，报的是 `undefined: fmt`，提示位置在 `person.go` 的第 21 行和第 35 行。原因是 `model` 包里的 `SetAge` 和 `SetSalary` 里有 `fmt.Println`，但我**忘了在 `person.go` 里 import `fmt`**。封装案例里字段和方法分散在两个文件里，写完记得回头检查 import 列表。

这就是我们封装的一个快速入门案例。大家可以敲敲代码，把案例写进去就可以了。我给大家一个任务，待会儿这个地方会做一些扩展，也要求同学们在这个基础上把代码写得更完善一点。

## 给 Account 加三道关，再看继承想解决的重复
> 对应块：BLK76 | 覆盖分集：P207-P209 | 块标题（分集名）：《206_尚硅谷_封装课堂练习讲解》

### 练习要求：校验全塞进构造函数

题目的要求是这样的：在 `model` 包里面定义一个 `account` 结构体，然后在 `main` 函数中体会 Go 语言的封装性。

`account` 结构体要求具有这几个字段：

| 字段 | 约束 |
| --- | --- |
| 账号 | 长度必须在 6 到 10 之间 |
| 余额 | 必须大于 20 |
| 密码 | 必须为 6 位 |

并且**通过 Set 方法给 account 字段赋值**，然后在 `main` 函数中测试。

跟前面做的那个 Account 案例相比，这里多出来的东西就是：**对长度、余额、密码的一个校验**。大家先想一想能不能做出来。

#### 先把结构体改成小写

新建一个工程文件夹，就叫 `encap`（encapsulation）下面的 `exercise`，里面建 `main` 和 `model` 两个文件夹。

在 `model` 包里新建 `account.go`。前面抽象那一节我们已经写过一段 Account 的代码，**直接粘过来用就行了，不用反复地写**。但有几处要改，因为这次要做成封装的：

- `account` 全部改成小写；
- `pwd` 字段改成小写；
- `balance` 字段也改成小写。

改完就意味着，这个结构体在别的包已经不能用了。

#### 写一个构造函数，三关全过才放行

那就在 `model` 包里写一个工厂模式的函数，相当于构造函数，`NewAccount`。

传三个参数进来：`accountNo string`、`pwd string`、`balance float64`，返回一个 `*account` 指针。

然后把三道校验加进去。

**第一关：账号长度。**用 `len` 求长度，如果它小于 6 或者大于 10，说明不满足条件，输出一句"账号长度不对"，然后**返回 `nil`**。

`nil` 就是空的意思。对方拿到这个地方一判断，发现是 `nil`，就知道创建失败了。

**第二关：密码长度。**要求 6 位，判断 `len(pwd) != 6`，不满足就提示"密码长度不对"，同样返回 `nil`。

**第三关：余额。**要求大于 20，如果小于 20，就提示"余额数目不对"，返回 `nil`。

三关都闯过了，说明满足条件，就返回真正创建好的这个 `account` 指针，把参数赋给对应字段就行。

```go
package model

import "fmt"

type account struct {
	accountNo string
	pwd       string
	balance   float64
}

func NewAccount(accountNo string, pwd string, balance float64) *account {
	// 第一关：账号长度必须在 6~10 之间
	if len(accountNo) < 6 || len(accountNo) > 10 {
		fmt.Println("账号长度不对")
		return nil
	}

	// 第二关：密码必须是 6 位
	if len(pwd) != 6 {
		fmt.Println("密码长度不对")
		return nil
	}

	// 第三关：余额必须大于 20
	if balance < 20 {
		fmt.Println("余额数目不对")
		return nil
	}

	return &account{
		accountNo: accountNo,
		pwd:       pwd,
		balance:   balance,
	}
}
```

> **结论**：构造函数返回一个 `nil`，就把"创建失败"这件事交回给了调用方。这是 Go 里很常见的一种返回约定——**成功给值，失败给零值**。

### 主函数怎么测：先看 nil，再补 Set/Get

在 `main` 包里新建 `main.go`。引包是从 `src` 这个目录下开始引的，斜杠是正斜杠——**这一块有些同学老是在这犯糊涂**。

### 为什么需要继承：一个学生考试系统写崩了

讲完封装，我们接着来看面向对象编程里的继承。

还是老规矩：**在讲继承之前，先说一下为什么需要继承。**我们去学一个新东西总是有原因的。Golang 的设计者在设计继承的时候，为什么需要有继承？继承能给编程带来什么好处？我们首先要把这个搞清楚。

我这里有一个小问题：**假如我们要去写一个学生考试系统，比如学生会管理系统，这里面有各种各样的学生。**现在有这么一个需求——我们需要记录各种学生考试的成绩。你想一想这个时候你会怎么做？

大家先思考一下，我先把这个问题板书出来。**引出继承的必要性，大家听的时候才会掌握到它的精髓。**

#### 先老老实实写一个小学生

既然是学生考试系统，假设有小学生要考试。小学生我肯定就会建一个结构体叫 `Pupil`：

```go
type Pupil struct {
	Name  string
	Age   int
	Score int
}
```

三个字段：名字、年龄、考分。

既然是小学生要考试，我们认为他有这么几个方法。第一个是显示成绩：

```go
func (p *Pupil) ShowInfo() {
	fmt.Printf("学生名=%v 年龄=%v 成绩=%v\n", p.Name, p.Age, p.Score)
}
```

这里的成绩我都可以直接访问到，所以就不写 getter、setter 了——我就在一个文件里面写，也不去封装它了，**现在因为我是讲继承，就直接公开访问就行**。

第二个是设置分数，考完以后给它设置成绩：

```go
func (p *Pupil) SetScore(score int) {
	// 业务判断：比如成绩是不是在 1 到 100 之间，不能是 -2
	p.Score = score
}
```

这里本来可以做业务判断的，但因为我现在讲继承，这个业务判断我就不写了。

第三个是显示他正在考试的状态：

```go
func (p *Pupil) testing() {
	fmt.Println("小学生正在考试中...")
}
```

这就写完了。试用一下：

```go
func main() {
	pupil := &Pupil{
		Name: "汤姆",
		Age:  10,
	}
	pupil.testing()
	pupil.SetScore(90)
	pupil.ShowInfo()
}
```

输出：

```text
小学生正在考试中...
学生名=汤姆 年龄=10 成绩=90
```

#### 大学生来了：粘贴一份，麻烦就来了

问题在什么地方呢？有小学生考试，当然我们还有大学生要考试，也有研究生这种情况。

**这里至少不能提示"小学生正在考试中"，因为考试的内容不一样。**小学生考的是小学数学，大学生考的是高数。尽管"显示信息"和"设置成绩"我们可以是一样的，但是 `testing` 考的内容不一样。

那这个时候你要做这个开发，只能这么干：**粘贴一份下来。麻烦已经来了。**

```go
type Graduate struct {
	Name  string
	Age   int
	Score int
}

func (p *Graduate) ShowInfo() {
	fmt.Printf("学生名=%v 年龄=%v 成绩=%v\n", p.Name, p.Age, p.Score)
}

func (p *Graduate) SetScore(score int) {
	p.Score = score
}

func (p *Graduate) testing() {
	fmt.Println("大学生正在考试中...")
}
```

名字、年龄、成绩没有变化，就是结构体的名字变了；绑定方法的地方也要变，绑定到 `Graduate` 这个结构体类型的指针上；只有 `testing` 改了一下。

测试一下：

```go
graduate := &Graduate{
	Name: "mary",
	Age:  20,
}
graduate.testing()
graduate.SetScore(90)
graduate.ShowInfo()
```

输出：

```text
大学生正在考试中...
学生名=mary 年龄=20 成绩=90
```

#### 问题出在哪儿：冗余

同学们看看这部分代码，是不是已经出现一些小问题了？

**第一点：**`Pupil` 结构体的三个字段和 `Graduate` 的三个字段，是不是一模一样？——已经冗余了。

**第二点：**`Pupil` 的 `ShowInfo` 和 `SetScore` 两个方法，跟 `Graduate` 的这两个方法是不是完全一样的？

**唯独不一样的就是 `testing` 这一个方法而已。**Pupil 输出的是"小学生正在考试中"，Graduate 输出的是"大学生正在考试中"。

但是**为了这一个方法不一样，我们却写了两份几乎相同的代码。**

而且你想一想，除了大学生，是不是还有其他学生，比如高中生？难道每个都来一份吗？

再说得更远一点。打开我们的源码，你假设要给 `Graduate` 和 `Pupil` 都加一个相同的方法——比如说他们都会做算术题。**你是不是要写两份？**如果我给小学生加一个他可以做算术题的方法，那我要给 `Graduate` 也绑定一个方法。

所以你会发现，这样写**既不利于代码的维护，也不利于功能的扩展**。

> **结论**：没有继承，我们就极有可能出现代码冗余。代码重复了，复用性就不强；复用性不强，就出现冗余。**继承这个知识点就呼之欲出了。**

### 继承的原理：把共有的抽出来，让别人嵌进去

#### 示意图：从两份重复到一份共用

既然有这个问题，Golang 的设计者就提出了一个概念——**继承**，通过继承的方式来解决。

它是怎么思考的呢？我们前面写的这两个结构体，`Pupil` 有自己的字段和方法，`Graduate` 也有自己的字段和方法，但你发现它们有很多是相同的。

继承会这么思考：**干脆把 `Pupil` 和 `Graduate` 里共有的字段和方法提取出来**，比如我写一个 `Student`，把共有的字段、共有的方法提到它里面去。

```text
        ┌──────────────────────────────┐
        │  Student（抽出来的共有部分） │
        │  ┌──────────┐ ┌───────────┐  │
        │  │ Name     │ │  Age      │  │
        │  └──────────┘ └───────────┘  │
        │  ┌──────────┐ ┌───────────┐  │
        │  │ Score    │ │ ShowInfo()│  │
        │  └──────────┘ └───────────┘  │
        │  ┌──────────────┐ ┌────────┐│
        │  │ SetScore()   │ │testing ││
        │  └──────────────┘ └────────┘│
        └──────────────────────────────┘
             ▲                        ▲
             │ 嵌入 Student          │ 嵌入 Student
             │                        │
    ┌────────┴─────────┐     ┌────────┴─────────┐
    │  Pupil           │     │  Graduate        │
    │  testing() 独有  │     │  testing() 独有  │
    └──────────────────┘     └──────────────────┘
      小学生正在考试中…          大学生正在考试中…
```

图里上面那个大盒子就是被抽出来的 `Student`——共有的字段和方法都搬上去了。下面两个小盒子各自保留自己**特有的字段和方法**——`testing` 就是它们唯一不一样的那个方法。

**共有的提到上面去，然后让它们形成继承的关系**：`Pupil` 去继承它，`Graduate` 也去继承 `Student`。

这样 `Student` 里面共有的字段和方法就不用重写了。我只要把共有部分提到 `Student`，然后把它嵌入到 `Pupil` 或者 `Graduate`，那么 `Pupil` 和 `Graduate` 就相当于拥有了 `Student` 里面的字段和方法，我就可以用了。

#### Go 里没有 extends，只有匿名结构体

注意，继承这个概念在很多编程语言里是靠一个关键字完成的，叫 `extends`。

**但是在 Golang 里面，继承并不是靠 `extends`。**为了实现继承效果，它用的是**匿名结构体**——我把 `Student` 这个结构体的名字往这一放就行了。

想让 `Graduate` 去继承 `Student` 里面的字段和方法，也很简单：在 `Graduate` 结构体里面加一个匿名结构体 `Student` 就可以了。

> **结论**：在 Golang 里面，实现继承就是**在你的结构体里面嵌入一个匿名结构体名**。当一个结构体嵌入了另一个匿名结构体，这个结构体就可以直接访问匿名结构体的字段和方法，从而实现了继承的特性。

另外这里还有一点要提前说清楚：**在 Go 里面，一般也不会把 `Student` 叫做父类、把 `Pupil` 叫做子类，它就是一个很松散的关系。**

如果大家学过 Java，也不用老去对比，不要去想 `Student` 是不是父类、`Pupil` 是不是子类。**它就是实现这种特性**——你就认为 Go 里通过嵌入一个匿名结构体就可以实现继承的特性就可以了，不用去把继承关系理得那么清楚。

因为 Go 对面向对象其实是弱化了的，它不希望我们的结构体之间有那么强的封装或者继承关系在里面，**它是一种很松散的关系**。包括后面我们学到接口编程，也能体现出这种特点。

#### 基本语法：Book 也是一种 Goods

我们再来看一下嵌套匿名结构体的基本语法。

假如有一个结构体叫 `Goods`，货物的意思，里面有名字还有价格——我们都知道任何一种商品都会有名字、有价格：

```go
type Goods struct {
	Name  string
	Price float64
}
```

现在我有一个结构体叫 `Book`，我们认为 Book 也是一种商品。那怎么做呢？

**我不想再把名字和价格重新写一遍**，不愿在这里面重新写一个 `Name string`，然后再把价格写一次。直接在里面嵌套一个 `Goods` 匿名结构体就行了——**你不要去给它名字**，这里就嵌套一个匿名结构体 `Goods`。

那么此时此刻，你的 `Book` 结构体就相当于拥有了 `Goods` 里面的 `Name` 和 `Price` 这两个字段。

```go
type Book struct {
	Goods
	// Book 自己特有的字段可以照常写在这里
}
```

当然，如果你把 `Goods` 引入进来，你当然也可以用跟 `Goods` 绑定的方法。

这就是我们所说的基本语法。

### 本讲提到的题目

#### 题目

在 `model` 包中定义一个 `account` 结构体，要求：账号长度在 6 到 10 之间、余额必须大于 20、密码必须为 6 位；通过 Set 方法给字段赋值；在 `main` 函数中测试，并在测试中体会 Go 的封装性。

#### 解析

三条约束都是**数据合法性校验**，它们必须发生在"值进入结构体之前"。所以正确的落点就是构造函数 `NewAccount`：三条都过了才 `return &account{...}`，任何一条不过就打印一句提示并 `return nil`。

返回值设计成 `*account` 而不是 `account`，是为了让"失败"有明确的表达——`nil` 就是空指针，调用方一判断就知道创建失败了。这就是"成功给值、失败给零值"的 Go 式返回约定。

Set 方法这边，思路跟构造函数一模一样：把同一条约束搬进 Set 的方法体里。比如改密码时，别人告诉你新密码，你必须校验它也是 6 位，不满足就拒绝，不修改原值。

#### 答案

正文中已经给出完整实现：`NewAccount` 里三道校验依次判断、失败返回 `nil`；`main` 里用 `if acc != nil` 判断成败。需要你在老师基础上补的是 Set/Get 方法（以及在 `main` 中对它们的调用与测试），这一部分题目明确要求同学独立完成，不替大家写了。

## 继承快速入门，以及三个必须记住的访问细节
> 对应块：BLK77 | 覆盖分集：P210-P211 | 块标题（分集名）：《209_尚硅谷_继承快速入门应用实例》

前面我们知道了继承的基本语法——在结构体里嵌入一个匿名结构体。这一讲我们用继承的方式，把那个学生管理系统改造一遍，然后专门挖一挖嵌入之后访问的三个细节，这三个细节后面写项目的时候都要用到，不然别人写的东西你看不懂。

### 把共有的搬进 Student

非常简单，先抽取出来一个共有的结构体叫 `Student`。**不管你是小学生还是大学生，你们都是学生。**

```go
type Student struct {
	Name  string
	Age   int
	Score int
}
```

这三个字段是 `Pupil` 和 `Graduate` 共有的，我把它"剪走"。剪走了过后，你这块保留也就没啥意思了——都是共有的，我都给你拿走。

那两个结构体原来都有三个方法，`ShowInfo` 和 `SetScore` 是共有的，于是把它们也搬到 `Student` 上，绑定到 `*Student`：

```go
func (stu *Student) ShowInfo() {
	fmt.Printf("学生名=%v 年龄=%v 成绩=%v\n", stu.Name, stu.Age, stu.Score)
}

func (stu *Student) SetScore(score int) {
	stu.Score = score
}
```

搬完之后，`Pupil` 和 `Graduate` 里的这两个方法就可以退出历史舞台了，删掉。

#### testing 留着：它是各自独有的

有些同学会问——这个方法还要不要保留？

注意，`Pupil` 的 `testing` 和 `Graduate` 的 `testing` **它们两个是不一样的**。你看它的内容我们没法合并，只是我这儿写的函数名字刚好一样而已，其实也有可能是不一样的。因为小学生考试的内容跟大学生考试的内容是不一样的。

所以我们就把它放一放，**保留它特有的**。这相当于 `Pupil` 结构体特有的方法，或者叫独有的方法都可以。

为什么保留？你看示意图上就是这么写的：**特有的字段和特有的方法可以保留**，而且**不但可以保留，还可以增加**。同样的道理，`Graduate` 也可以保留它自己那个 `testing`。

#### 嵌入：让它们真的用上 Student

现在这样改完以后，**去使用的方式肯定不一样了**。而且你还少了一件事情——如果你这个地方没有嵌入这个 `Student`，那你的 `Pupil` 其实什么属性都没有，它只有一个方法而已；`Graduate` 也是一样。

那怎么样让 `Pupil` 能够使用到上面的东西呢？非常简单：

```go
type Pupil struct {
	Student // 嵌入了 Student 匿名结构体
}

func (p *Pupil) testing() {
	fmt.Println("小学生正在考试中...")
}

type Graduate struct {
	Student // 嵌入了 Student 匿名结构体
}

func (p *Graduate) testing() {
	fmt.Println("大学生正在考试中...")
}
```

**什么叫匿名结构体？就是这个结构体没有名字，它没有变量名。**我们一般写法是 `stu Student`，有一个字段它的类型是 `Student`；但这里你不需要写，相当于把它嵌进去了。注意，这个地方保留一个匿名的结构体就可以了。

你看代码是不是已经减少了很多？`Pupil` 里面就有一个 `Student` 加一个方法；`Graduate` 也是一个 `Student` 加一个方法，没了。如果你要写高中生，写其他学生，一样可以这样做。

### 嵌入之后怎么用：先走最直白的那种写法

当我们对结构体嵌入了匿名结构体后，**使用方法会发生变化**。

我们先写第一种方式，因为这种方式大家最容易理解，后面还有别的方式。

```go
func main() {
	pupil := &Pupil{}
	pupil.Student.Name = "tom"
	pupil.Student.Age = 8

	pupil.testing()

	pupil.Student.SetScore(70)
	pupil.Student.ShowInfo()
}
```

创建 `Pupil` 的时候给一个引用，把这个指针赋过去。注意想一下，这个时候 `Pupil` 里面其实是空的，什么内容都没有，它的任何一个字段信息都没有，怎么办？给它赋一下值。

**注意听，这里很关键：**`Pupil` 它的匿名结构体名字叫 `Student`，但字段是在 `Student` 里边的。所以我们要用的时候，一种比较简单的方式是这样写——**先写结构体的名称，点到它的匿名结构体，再取到它的字段。**层级关系还是很清晰的。

考试的时候调的是 `testing`，那是它自己的方法，直接 `pupil.testing()` 就能调起来。考完了要设置分数，还是老规矩，找到它的匿名结构体，调用 `SetScore`：

```go
pupil.Student.SetScore(70)
pupil.Student.ShowInfo()
```

跑起来看：

```text
小学生正在考试中...
学生名=tom 年龄=8 成绩=70
```

大学生以此类推：

```go
graduate := &Graduate{}
graduate.Student.Name = "mary"
graduate.Student.Age = 28

graduate.testing()

graduate.Student.SetScore(90)
graduate.Student.ShowInfo()
```

```text
大学生正在考试中...
学生名=mary 年龄=28 成绩=90
```

大家看，**这种继承跟我们传统的继承区别还是蛮大的。**传统的继承就是 `extends`，然后把这个名字一写就完事了。但是它这里很松散。

你们慢慢去体会，它有很多好处。因为大家都知道，学 Java、学别的编程语言的时候，**继承的关系其实是不太容易搞清楚的**。但 Go 的设计者就很简单：**你要用什么，你把它嵌进去就行了**，而且层级关系它仍然给你保留。

既然有一个层级关系，我们就是要访问到哪一层，直接点点点就完了，**不存在什么容易让人混淆的地方**。它尽量让你的代码没有混淆的地方——这是 Go 设计者的一个初衷，让代码看起来更简洁，也更松散。

### 继承到底带来了什么便利

前面其实已经说过了，我再总结一下，就两点：

1. **代码的复用性提高了；**
2. **代码的扩展性、维护性提高了。**

怎么体现出扩展性和维护性提高了呢？非常简单。

比如说我希望给 `Graduate` 和 `Pupil` 增加一个**共同的方法**——它们都可以做算术题。**我只需要在 `Student` 上绑定一个方法就可以用了：**

```go
func (stu *Student) GetSum(n1, n2 int) int {
	return n1 + n2
}
```

传两个 `int` 进去，返回一个结果，`return n1 + n2` 就可以了。

那么当我这样一做完，`Pupil` 和 `Graduate` 就可以马上用这个方法了。**你不需要在每一个 `Pupil`、每一个 `Graduate` 里面再单独写一份，因为它可以共用。**

```go
result := pupil.Student.GetSum(1, 2)
fmt.Println(result)   // 3

result2 := graduate.Student.GetSum(10, 20)
fmt.Println(result2) // 30
```

跑一下，代码没有任何问题，3 和 30。

就这么简单。**扩展起来很方便**——当然你要去掉一个方法也很方便，要增加一个属性也很方便。

顺便说一句，我第一次写这里的时候犯了个小错：我把方法名写成了小写的 `getSum`，调用时按大写去写，编译器当然不认。Go 是区分大小写的，方法名首字母大写才是导出的，跨结构体调用时要跟定义保持一致。

### 深入讨论：三个必须记住的访问细节

关于继承还有几个比较深入的东西。这些细节都比较重要，不然你以后看别人代码也看不懂，自己写代码也很费劲。

#### 一、小写的字段和方法照样能用

第一个：**结构体可以使用嵌套匿名结构体所有的字段和方法。**

注意——**不管首字母是大写的还是小写，字段或方法都可以用。**

这一点跟我们有些编程语言不一样。以 Java 为例，私有的属性在子类里面是用不了的。**但是在 Golang 里面不存在这个问题**——一旦把匿名结构体写进去了，匿名结构体的所有的字段和方法，不管是首字母大写还是小写，都可以使用。

我们写个例子验证一下。新建一个 `details` 文件夹，写一个 `main.go`：

```go
type A struct {
	Name string  // 首字母大写
	age  int      // 首字母小写
}

func (a *A) SayOk() {
	fmt.Println("A SayOk", a.Name)
}

func (a *A) hello() {
	fmt.Println("A hello", a.Name)
}

type B struct {
	A
}

func main() {
	b := B{}

	b.A.Name = "tom"
	b.A.age = 19

	b.A.SayOk()
	b.A.hello()
}
```

字段有一个大写、一个小写；绑定的方法有一个大写、一个小写。跑起来：

```text
A SayOk tom
A hello tom
```

完全没问题。这就证明了一个观点：**你这个结构体可以使用匿名结构体所有的字段和方法，不管你是大写还是小写。**

这点大家都要搞清楚，别到时候被搞蒙圈了。因为我们有些同学学过别的编程语言，知道"私有的东西在外面用不了"——但 Go 里面它不存在这个问题，它可以直接使用。

#### 二、访问可以简化，编译器是这么找的

第二个：**匿名结构体字段访问可以简化。**

你看我上面写的东西：`b.A.Name`、`b.A.age`、`b.A.SayOk()`、`b.A.hello()`，其实**你也可以直接把大写的 `A` 去掉**，也就是说把匿名结构体去掉：

```go
func main() {
	b := B{}

	b.Name = "smith"
	b.age = 20

	b.SayOk()
	b.hello()
}
```

**为什么可以这样用？**

有同学可能会问：`SayOk` 不是跟 `A` 绑定的吗？怎么用 `b` 就可以调用呢？

我再讲一遍：**因为 `b` 变量是 `B` 结构体，它到这里面去找，发现自己没有 `SayOk`；但它发现有个嵌入的结构体，就去看这个 `A` 有没有这个方法。找到了它就去调用。**

**编译器的查找流程是这样的：**

1. 先到 `b` 对应的类型 `B` 里面去找，有没有 `Name` / `SayOk`。有的话直接用 `B` 的；
2. 如果没有，就去看 `b` 中嵌入的匿名结构体 `A` 里有没有；
3. 如果 `A` 里也没有，就看 `A` 里面还有没有嵌入（比如嵌了一个 `C`），依次向上找；
4. 如果都找了一圈都找不到，就报错——它会告诉你这个函数没有定义。

打个比方，我们这个 `A` 里面确确实实有个 `Name`，如果你把这个 `Name` 去掉，肯定要报错的。当然如果你的 `A` 里面又嵌了一个匿名结构体 `C`，那怎么办？这就叫**不停往上找**。

```text
b.Name  →  B 自己有吗？──有──► 用 B 的
              │没有
              ▼
        嵌入的 A 有吗？──有──► 用 A 的
              │没有
              ▼
        A 里嵌入的 C 有吗？──有──► 用 C 的
              │没有
              ▼
           报错：未定义
```

这个流程就是我们后面讲继承层次的时候会再提到的观点，大家先注意。

跑一下看，代码没有任何问题：

```text
A SayOk smith
A hello smith
```

#### 三、同名撞车了，走就近原则

第三个细节：**当结构体和匿名结构体有相同的字段或者方法的时候怎么办？**

注意听，编译器会采用一个叫做**就近访问原则**来进行处理。如果希望访问匿名结构体字段的时候，可以通过匿名结构体来进行区分。

我还是以刚才那个代码为例子。现在我在 `B` 里面**也定义一个 `Name`**，同时给 `B` 这个指针类型**也绑定一个 `SayOk` 方法**——我故意把名字都写成一样的：

```go
type A struct {
	Name string
	Age  int
}

func (a *A) SayOk() {
	fmt.Println("A sayOk", a.Name)
}

func (a *A) Hello() {
	fmt.Println("A Hello", a.Name)
}

type B struct {
	Name string // B 自己也有一个 Name
	A
}

func (b *B) SayOk() {
	fmt.Println("B sayOk", b.Name)
}

func main() {
	b := B{}
	b.Name = "jacky"
	b.Age = 100
	b.SayOk()
	b.Hello()
}
```

这个时候 `b` 里面也有一个 `Name`，会不会冲突呢？**它并不会冲突，它会采用就近原则。**

我们先来分析一下这个时候会输出什么。

先问大家第一个问题：`b.Name` 去找这个 `Name` 的时候，**其实它在自身已经找到一个 `Name` 字段了**，因此它就不会给 `A` 的这个 `Name` 赋值。也就是说，此时此刻这个地方肯定不会报错的。

那么 `b.Age`，因为 `b` 本身没有 `Age`，于是它会找到 `A` 里面的这个 `Age`，给 `A` 的 `Age` 字段赋值，因此这个也是没有错的。

关键的问题在这里来了：**`b.SayOk()` 实际上调用的就是它自身的方法**，它会输出 `B sayOk`。因为你本身有这个方法，它就不往上面去找了。然后它调用的是 `b.Name`——注意听，`b.Name` 是不是就找到自己这个 `Name`？而这个 `Name` 刚好就是刚才赋值的 `jacky`，所以就输出 `B sayOk jacky`。

然后 `Hello` 呢？`b.Hello()` 其实调用的是**父级结构体**的 `Hello`，会输出 `A Hello`。**关键是这个方法里面写的 `a.Name` 到底会输出什么？**

因为这个时候是用 `b` 调进去的，调用的是 `a.Name`。那这个地方到底输出 `jacky` 还是一串空串呢？问题在这儿。

我们跑一下：

```text
B sayOk jacky
A Hello 
```

**是空串。**为什么？

因为如果你真的找的是 `a.Name`，那肯定是空串。调 `b.Hello()` 的时候调用的就是这个 `Hello`，而你这个地方写的就是 `a.Name`，它就会去找**`A` 这个结构体的 `Name`**。这个 `Name` 其实并没有给它赋任何值——因为你调用的正是**嵌入的匿名结构体里面的 `A` 的实例的 `Name`**，但是你并没有给它赋值，所以实际输出的就是空字符串。

那有些同学说："老师，我就要给它赋值怎么办呢？"

**可以这样写。如果你一定要给 `A` 的 `Name` 赋值，你就通过匿名结构体名来做：**

```go
b.Name = "jacky"
b.A.Name = "scott"
```

`b.Name = "jacky"` 给的是 `B` 的 `Name` 字段赋的值；`b.A.Name` 这肯定就是给匿名结构体实例的 `Name` 字段赋的值。给它写一个名字叫 `scott`，这个时候它肯定输出的就是 `scott` 了。

跑一下，果然输出了 `scott`，完全正确。

**方法也一样。**如果你就是想访问 `A` 里面的 `SayOk`，这样写就可以了：

```go
b.A.SayOk()
```

这样肯定没问题，因为你明确告诉它了，我要访问 `A` 里面的 `SayOk`。它输出的就是 `A sayOk`，而里面的 `a.Name` 你已经赋值了，输出的是 `scott`，所以结果是 `A sayOk scott`。跑一下，分析完全正确。

> **结论**：当结构体和匿名结构体有相同的字段或者方法时，编译器会采用**就近原则**进行访问；如果希望访问匿名结构体的字段和方法，可以通过**匿名结构体的名字来区分**，比如 `b.A.Name`、`b.A.SayOk()`。

---

这三点我给大家单独说一下，大家注意：

**第一点**，结构体可以访问嵌套匿名结构体所有的字段和方法，**不管你是首字母大写还是小写**。

**第二点**，匿名结构体字段访问可以简化。但是简化的时候大家要知道它的访问原则——采用就近原则。先到 `b` 对应的结构体里面去找，有就直接访问；没有就往嵌套的匿名结构体里面找；匿名结构体里面还没有，再找上一级；都找不到就报错。

**第三点**，如果我们的结构体和匿名结构体有相同的字段或者方法，编译器会默认采用就近原则。如果你想访问匿名结构体的字段或者方法，就通过匿名结构体的名字来区分。

关于这三个细节我就先介绍到这里。

## 嵌两个结构体、有名结构体、嵌指针：继承剩下那三个细节
> 对应块：BLK78 | 覆盖分集：P212-P213 | 块标题（分集名）：《211_尚硅谷_继承的深入讨论(2)》

我们继续来看继承的深入讨论，接下来是三个需要特别注意的地方。这一块讲完，"嵌多个匿名结构体"这件事就彻底讲透了，顺带把多重继承的概念也正式抛出来。

### 嵌了两个匿名结构体，同名时必须点名

先说一种更普遍的情况：**一个结构体里面嵌入了两个或者多个匿名结构体，这是有可能的。**

比如结构体 `A`、结构体 `B`，两者都被嵌到了结构体 `C` 里面。而且更麻烦的是：`A` 有 `Name` 字段、有 `Age` 字段，`B` 里也有一个 `Name` 字段。

那怎么办？

**如果两个匿名结构体有相同的字段或方法，同时结构体本身没有同名的字段或方法——注意这个前提——那么访问时就必须明确指定匿名结构体的名字，否则编译直接报错。**

再说白一点：`A` 和 `B` 里面都有 `Name`，但是 `C` 没有同名字段或同名方法，在这种情况下你为了区分到底用 `A` 的还是 `B` 的，就必须把匿名结构体的名字带上。

我们写个例子。新建一个文件夹，就叫 `details2`，里面新建 `main.go`：

```go
type A struct {
	Name string
	Age  int
}

type B struct {
	Name  string
	Score float64
}

type C struct {
	A
	B
}
```

`A` 有 `Name string` 和 `Age int`；`B` 也有 `Name string`，还有一个别的字段，比如成绩 `Score float64`；`C` 同时嵌入了 `A` 和 `B`。

现在定义一个 `C` 的变量，试着给它赋值：

```go
func main() {
	var c C
	c.Name = "tom" // 错误：ambiguous selector c.Name
	c.A.Name = "tom"
	fmt.Println(c)
}
```

**为什么 `c.Name = "tom"` 会报错？**

按前面说过的查找顺序走：先到 `C` 里面找 `Name`——`C` 有没有 `Name`？没有。于是它就到嵌入的结构体 `A` 和 `B` 里面去找。

**结果它发现 `A` 有一个 `Name`，`B` 也有一个。**完了——它不知道到底你把这个 `Name` 给 `A` 里面的 `Name` 字段，还是给 `B` 这个结构体的字段呢？于是它编译报错，报的是 `ambiguous selector c.Name`，一个不明确的选择器。

那怎么办？**只能加上 `c.A.Name`**，这样就明确了：我就告诉你我要找 `A` 里面的 `Name`。这样就没问题了。

我再说一个问题：**假设 `C` 里面就有一个 `Name string` 呢？它也不会报错。**

因为如果 `C` 里面本身就有一个 `Name`，这个时候它很清晰——先到 `C` 里面去找，已经找到了；找到了的话，`A` 和 `B` 就不会再去找了，也就不会再发生选择器不确定的问题。

> **结论**：如果 `C` 没有 `Name` 字段，而 `A` 和 `B` 都有 `Name` 字段，这时就必须通过指定匿名结构体的名字来区分。方法也是一样的道理——假设 `A` 有一个方法叫 `sayHello`，`B` 也有一个方法叫 `sayHello`，你直接调 `c.sayHello()`，那也是区分不了的，除非 `C` 本身有一个 `sayHello`。

### 嵌有名结构体就是组合：名字必须带上

第五个要注意的地方是：**如果一个结构体嵌套了一个有名结构体，这种模式我们把它叫做组合。**

一般不把它称之为继承了——**组合是继承的一种特殊关系。**如果是组合关系，那么在访问组合的结构体字段或者方法时，**就必须带上结构体的名字。**

这就叫组合。你甚至可以组合多个 `A`。在 Go 语言里面，继承是非常灵活的。

我们走一下代码。假设有个 `A`，里面有 `Name`、有 `Age`，我嵌套了一个 `A`，同时指定了名字：

```go
type D struct {
	a A
}

func main() {
	var d D
	d.Name = "jack"    // 错误：type D has no field or method Name
	d.a.Name = "jack"  // 必须带上名字
	fmt.Println(d)
}
```

在这个结构体 `D` 里面，我们嵌套了一个 `A`，但它是有名的——相当于在嵌套结构体的时候，给这个结构体有了一个名字，因此我们就说嵌套了一个**有名结构体**。

那如果是有名结构体，要使用就得这样使用。我声明一个 `D` 这种结构体变量，如果像以前那样写 `d.Name = "jack"`，它就报错了，说 `type D has no field or method Name`。

**为什么呢？因为你这个地方不是一个匿名结构体。**那么在检查规则的时候，编译器只在这个 `D` 里面看有没有 `Name`，如果没有——它就直接告诉你 `D` 没有这个字段或方法。**它不会往上找**，明白吧？

所以在 Go 语言里面，**层级关系是很清晰的**。当然如果把字段名去掉，那肯定就对了；但你写上了名字就一定会报错。

那怎么办？就 `d.a.Name`，你就必须把名字带上，这样就可以访问到了。

有同学又要问了：**假设 `D` 里面也有一个 `Name` 呢？**如果 `D` 有一个 `Name`，我这样写肯定不会报错，因为它还是先到 `D` 里面，发现它有，那就没问题了。但是如果你没有，它发现你这个是有名结构体，它也**不会**到 `A` 里面去看有没有 `Name`，直接报错。

> **结论**：如果 `D` 中是一个有名结构体，访问它的字段时就必须带上这个有名结构体的名字。同时这个关系被别人问到，就叫**组合关系**——`D` 和 `A` 组合起来了。

### 创建时直接给匿名字段赋值：有三种写法

第六个：**嵌套匿名结构体后，也可以在创建结构体变量实例时，直接指定各个匿名结构体的字段值。**

这种用法会很多。大家还记不记得，前面写细节的时候我们是怎样给名字赋值的？比如我建一个 `pupil`，建完了过后再给它的 `Name` 和 `Age` 赋值——这个很麻烦。在 Go 语言里面，它也可以直接在创建结构体变量时，直接给各个匿名结构体的字段赋值。

我们来看这个案例。

我有两个结构体：`Goods`，商品，它有 `Name`，也有价格 `Price float64`；还有一个结构体叫 `Brand`，品牌，它也有一个名字，还有一个地址——它是在哪注册的，`Address`。

然后我有一个结构体叫 `TV`，电视机。它把 `Goods` 和 `Brand` 同时放进来了——**也就是说我的 `TV` 电视既是一种商品，同时我也用到了人家的一个品牌。**

```go
type Goods struct {
	Name  string
	Price float64
}

type Brand struct {
	Name    string
	Address string
}

type TV struct {
	Goods
	Brand
}
```

以前我要先创建一个 `TV`，再一点点赋值——这个太慢了，太麻烦了。现在我们可以一次性给它创建起来。

#### 按顺序写

```go
tv := TV{
	Goods{Name: "电视机001", Price: 5000.99},
	Brand{Name: "海尔", Address: "山东"},
}

fmt.Println(tv)
```

跑起来看效果，电视机有了，海尔也有了，可以创建。

**这种写法有个前提：必须按顺序写**，否则肯定要报错。也就是说你在定义 `Goods` 的时候名字写在第一位，那你这里就必须先写 `Name` 再写 `Price`。

#### 带字段名写

有些人喜欢这样写——他说老师我直接把字段名给它写上，也可以。换行，这样看起来更清晰：

```go
tv2 := TV{
	Goods: Goods{
		Name:  "电视机002",
		Price: 6000.99,
	},
	Brand: Brand{
		Name:    "夏普",
		Address: "北京",
	},
}
```

**这样写的好处是，我不依赖于你 `Goods` 的顺序了**，甚至我可以把 `Price` 写到上面去、把名字写在后面都可以。刚才那种写法就必须按顺序，你定义的时候名字写在第一位，这里就必须先写名字。

注意这种写法**不要忘了有一个逗号**。

这两种形式大家都可以任选。

#### 嵌入指针类型

还有一种形式我再多说一句。有些人喜欢这样嵌套，比如我有第二种电视，它直接用这个星号——**嵌套匿名结构体的指针类型**，这样也可以。

就是说我们在嵌套匿名结构体的时候，其实也可以嵌套这个匿名结构体的指针类型。**这样嵌套直接就是指针，返回的就是地址，效率更高。**

```go
tv3 := TV{
	&Goods{Name: "电视机003", Price: 7000.99},
	&Brand{Name: "创维", Address: "河南"},
}
```

那这个怎么取出来呢？

**因为它是指针，直接打印出来的是两个地址**——你本身就是把地址给了人家，人家返回地址也是顺理成章的事。

取出来也很简单：**先把它取出来，然后再使用。**前面应该有一个取值符：

```go
fmt.Println((*tv3.Goods).Name, (*tv3.Goods).Price)
fmt.Println((*tv3.Brand).Name, (*tv3.Brand).Address)
```

这样值就正确了，把电视机和创维、河南取出来了。（当然，编译器对指针字段也做了简化，直接写 `tv3.Goods.Name` 同样能跑通，这里先把取值这一层显式写出来，方便你理解它底下是什么。）

同样，如果你想分行写、想把字段名和值一一对应上，也完全可以：

```go
tv4 := TV{
	Goods: &Goods{
		Name:  "电视机004",
		Price: 9000.99,
	},
	Brand: &Brand{
		Name:    "长虹",
		Address: "四川",
	},
}
```

跑一下，长虹、四川，一样能用。

> **易错点**：这一段我被自己的错误卡了一下——类型定义是 `TV2`，我却写成了 `TV`，编译器立刻报错。嵌入指针那一块第一次写完也要小心两件事：一是**指针要加 `&`**；二是**取值的时候别忘了 `(*)`**。

---

### 匿名字段还能是基本数据类型

接下来看一个课堂练习上的点：**结构体的匿名字段是基本数据类型，它也是可以直接嵌入到结构体里面的。**

在结构体里面其实你也可以嵌入基本数据类型，比如 `int`。这是完全允许的。

```go
type Monster struct {
	Name string
	Age  int
}

type E struct {
	Monster
	int
}
```

如果我们现在把 `Monster` 以匿名结构体的方式嵌进去，这是没问题的。同时我们也可以把基本数据类型作为一个匿名字段放进去——**相当于说在 `E` 里面有一个匿名字段，它是基本数据类型 `int`。**

那怎么去用这个 `int` 呢？

```go
func main() {
	var e E
	e.Name = "狐狸精"
	e.Age = 300
	e.int = 20
	fmt.Println("e=", e)
}
```

`Monster` 的用法前面讲过，直接写 `e.Name` 就可以了——全写应该是 `e.Monster.Name`，但因为只有一个 `Name`，所以可以简写。

**要访问它的匿名基本数据类型字段，直接 `e.int` 就可以了**，给它一个 20，这也是可以的。运行起来看，这个地方仍然可以正确地输出。

再给大家强调一点：**如果这里有一个 `int`，就不能再有相同的 `int` 匿名字段了，因为无法区分。**

如果你一定还要有 `int` 的话，前面就一定要有个名字，比如写一个 `n int`，这样是可以的。给这个 `int` 一个名字，就相当于在 `E` 里面有一个字段名叫 `n`，它的类型是 `int`，这样也可以区分，用的时候就是 `e.n = 40`。输出也是没问题的。

> **结论**：如果一个结构体中有一个 `int` 类型的匿名字段，就**不能有第二个了，最多只能有一个**。如果需要有多个 `int` 类型的字段，则必须给这些字段指定名字。

---

### 多重继承：把概念正式抛出来

最后我们把多重继承这个概念梳理一下。

**多重继承其实前面已经讲过了，只是没有把这个概念抛出来。**我们在讲 `TV` 那个细节的时候，`TV` 里面有两个匿名结构体——说明 `TV` 继承了 `Goods`，同时又继承了 `Brand`。这其实就是一个多重继承的案例。

> **定义**：如果一个 struct 嵌套了多个匿名结构体，那么该结构体可以直接访问嵌套结构体的字段和方法，从而实现了多重继承。在 Go 里面实现多重继承，就是**嵌入多个匿名结构体**。

案例前面已经有了：`TV` 嵌入了 `Goods`，又嵌入了 `Brand`，这就相当于继承了两个。在 `TV` 里面既可以使用 `Goods` 里面的属性和方法，又可以使用 `Brand` 里面的属性和方法，如果有方法也是可以使用的。

这里还有两个细节要再点一下。

**第一点：如果嵌入的匿名结构体有相同的字段名和方法名，在访问时就需要通过匿名结构体类型来区分。**

比如 `Goods` 里面有 `Name`，`Brand` 里面也有 `Name`，那就必须把匿名结构体的名称写出来，通过 `tv.Goods.Name` 去显式区分。如果直接写 `tv.Name`，编译器就无法区分，一定会报错。

但如果 `TV` 去访问价格 `Price`——`Goods` 里面有价格，而 `Brand` 里面没有价格，那就可以直接写 `tv.Price`。因为 `Brand` 里面没有 `Price` 字段，它是**可以区分**的。

**第二点：建议大家尽量不要使用多重继承。**

为了保证代码的简洁性，在我们做 Go 开发的时候，**多重继承很容易把继承关系搞复杂**。很多编程语言里面其实已经把多重继承拿掉了——但 Go 的设计者本身就是 C 语言的设计者，因此把多重继承特性保留了下来，不过在相关文档里面也说了尽量不要使用多重继承。

**当然，更多的还是用上面那几种写法，一般我们是使用上面这种。**

---

好，我们把这一块回顾一下。这里面我们又讲了三个需要注意的地方：

**第一个**，当一个结构体嵌套了多个匿名结构体的时候，如果两个匿名结构体有相同的字段和方法，同时结构体本身没有这个相同字段和方法，你得明确指定结构体的名字，否则编译错误。

**第二个**，如果一个结构体嵌套了一个有名结构体，那么这种模式我们首先要知道它叫组合——组合其实也是继承的一种体现，这点大家要清楚。但是这个时候必须要把这个有名结构体的名称带上，否则它是要报错的。

**第三个**，如果我们去创建这样一个嵌套了匿名结构体的结构体，也可以直接指定匿名结构体的各个字段的值。有三种形式：按顺序写；前面写字段名后面给值；以及有些程序员喜欢直接把类型的指针放到这里去，创建的时候注意它的细节是**要给地址**。

关于继承的细节老师就介绍到这里。大家把这六点掌握好，基本上在我们做开发的时候是足够用的。
