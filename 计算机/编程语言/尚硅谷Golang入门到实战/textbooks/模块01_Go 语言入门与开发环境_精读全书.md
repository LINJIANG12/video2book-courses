### Golang 这个名字，和它的学习方向

Go 后面那个 `lang` 代表 language，Go 语言其实就是 Go language 的简称。因为后面这个词太长，行业里一般就直接叫 Golang。所以别人说"你 Go 语言学得怎么样"，或者说"Golang 又出了个新特性"，说的是同一个意思。

既然要学它，先得弄明白学完能做什么事。学一个语言，目的就是拿它去做开发、做事情，这是个很浅显的道理。Golang 核心编程将来能用在哪，我给你介绍几个方向。

#### 区块链研发工程师

区块链现在闹得沸沸扬扬，也很火。如果你要做区块链研发工程师，就应该学一下 Golang。**因为区块链主流的开发语言就是 Golang。**

区块链说白了就是分布式账本技术，是一种互联网技术。它的核心思想是去中心化，让任何人都可以参与数据库的记录。现在虚拟货币、还有金融这方面用得比较多，很多培训机构陆陆续续都在开区块链的培训，就是因为这是一个方向。谁先走在前面，在它还没完全起来的时候你先走，那你前景就会很光明——做得越早，机会就越多。

#### 服务器端开发

目前服务器端主要用的是什么语言？C、C++ 偏多一点。只要是 C 和 C++ 能做的事情，Go 都可以做，而且做得更好。

为什么？Go 的三个主要设计者里有一个叫 Ken Thompson，C 语言就是他设计的。他既设计了 Go，又设计了 C，而 Go 是后面设计的，所以他在某些方面会把 C 的设计理念优化一下。日志处理、数据打包、文件系统这类活，C 和 C++ 能干的 Go 都能干。比如大家都知道美团，美团后台流量的支撑程序就是用 Go 语言写的。

Go 在这块体现出两个很明显的优势：**一个是数据的处理能力比较强，一个是处理大并发比较强。**现在的网站越来越大，用户量动辄几千万，新浪、搜狐、腾讯这样的站，一个并发下来就是几百万——那你怎么样去处理这么大的并发？Go 语言在这方面非常牛。所以现在在后台做服务器端的，Go 用得比较多。

#### 游戏后台的数据通道

后台游戏开发的时候，有时候也会用到数据通道。打个比方，你玩游戏的时候点一下、用一把刀砍了一个人，为什么跟你一组的队友能立刻看到这个动作？其实后台有一个数据通道在帮你撑着。用 Go 语言做这一块也是非常强的，现在很多游戏软件的后台，尤其是数据通道这块，用 Go 开发得比较多。

#### 分布式云计算

想做分布式云计算方面的工作，Go 也用得比较多。举两个比较经典的案例：一个是盛大云 GrandCloud；另一个是京东——京东后台的消息推送服务以及分布式文件系统，后台全部都是用 Go 语言做的。

把这几条串起来你会发现：光会 Go 语言当然还不能直接干这些活，它是一个核心。你将来做区块链开发，就必须用到、主要就是用 Go；做服务器端或者游戏软件工程师，也可能用到 Go；做分布式云计算，同样可能用到 Go。所以 Go 的应用场景还是比较多的。

说完方向，再说说大家最关心的事——行情。

说明 Go 语言做开发，工资还是比较高的。

但有一点大家要知道：现在做 Java 开发、PHP 开发、.NET 开发、C++ 开发的人已经非常多了，而 **Go 工程师在中国还比较少**。谁先占领这块商机，谁将来就有可能成为这一方面的专家；哪怕只是走在前面一点，机会都会大得多。等到大家都开始学 Go 的时候你再跑来学，就一个字：晚了——因为竞争会很激烈。

你看现在各种编程语言，哪个方向的人才都不缺，但 Go 语言说实话还是一块没有开垦出来的好地。所以听完 Go 的学习方向，你应该感觉到这是一个机会，值得系统地跟着学一把。

### 应用领域，就三块

跟上思路。前面说的是**学习方向**——将来学完可能从事什么工作；这里说的是 **Golang 的应用领域**——它到底能做什么事情。我总结了一下，就三块。

#### 区块链技术的应用

区块链这个技术也叫 BT 技术，它其实是一种分布式账本技术。这块我们简单说一说，因为要等你学完 Golang 之后，才会去学区块链相关的技术。它们的关系是：你学完 Golang 再去学区块链，区块链用的编程语言就是 Golang，或者说主流就是 Golang。

区块链技术的特点就是去中心化、公开透明，每一个人都可以参与数据库的记录——这就是它的几个核心点。当然区块链的应用不是一两句话能讲清楚的，所以先简单罗列在这儿。它的第一个应用领域，就叫区块链技术的应用，做区块链应用开发。

#### 后台的服务应用

除了区块链，Go 还能做服务器端开发。看看它在什么地方被用上了，两个很经典的应用。

第一个是**美团后台流量支撑**。美团是做外卖的，好多人都用，尤其是中午 12 点那会儿，流量不可小看——你想想中国有多少人。美团后台主要要做哪些功能呢？**排序、推荐、搜索**。这几个都是非常耗费运算能力的要求，对数据的运算能力要求很强。第二个是提供**负载均衡、缓存、容错、按条件分流**。这几点又要求做后台的语言有强大的处理大并发的能力。

你看，前面那几点要求语言有很强的计算能力，计算能力不行，响应速度就上不来；后面那几点又要求有大并发能力。美团后台综合了很久，开发团队选来选去，最后选了 Go 语言。这就说明 Go 不是吃素的——这么大的一家公司都在用它做后台流量支撑程序，正好印证了那两条：**计算能力强，大并发能力强。**

第二个例子是一款叫《仙侠道》的游戏，它后台的通信、做数据通道这一块也是用 Go 语言。所以 Go 在后台、后端服务器端的应用，也是非常强悍的。

#### 云计算和云服务

第三个领域非常重要：**云计算和云服务**，现在应用得非常广泛。它要解决什么问题呢？打个比方，盛大云有个叫 CDN 的东西，翻译成中文叫内容分发网络。

什么叫内容分发网络？大家都知道访问一个网站，里面会有很多内容，最经典的就是图片和视频，而这些是耗费流量很大的。如果说你访问网站的时候，网络又恰好很繁忙，这时候要解决的问题就是——**如何让用户就近地、快速地获取到内容**。说得再直白一点，就是怎么让用户访问网站更快。这时就可能要用到 CDN 这个技术。盛大云计算就可以提供这样的服务。说白了，就是要让我们用 Go 语言来建一个 CDN 的网络服务，这样它的云计算能力就凸显出来了。

再看京东。京东是电子商务平台，每天的购买量、用户量都非常庞大，它要做消息推送，要做分布式文件系统，这些地方都要用到云计算技术。云计算谁来做？我们可以选 Go。**京东后台所有的服务全部是用 Go 实现的**，这就说明 Go 的计算能力很强。

综合来看，Go 的第三个应用就是云计算和云服务的后台应用。

### 那只叫 Gopher 的金花鼠

接下来说 Go 之前，先看一个很可爱的小动物。老外很有意思，搞什么东西都喜欢配个吉祥物，而且往往都是一只动物。比如学过 MySQL 的同学知道，MySQL 的吉祥物是一只海豚；学过 Linux 的知道，Linux 的吉祥物是一只小企鹅；学过 PHP 的知道，PHP 的吉祥物是一只大象。

Go 语言也有一个吉祥物。它有时候看着很像个小土豆，有些人喜欢叫它土拨鼠——其实不对，它是一只金花鼠，名字叫 **Gopher**。这个吉祥物是谁设计的？这里分享个小故事：它是 Go 语言的一位设计者罗布·派克（Rob Pike）的妻子画出来的，还给它取名叫 Gopher。所以大家以后看到这个小动物，可别说它是土拨鼠，它是一只很可爱的金花鼠。

### 学这门课，我想跟你约定的几件事

在学 Go 语言的过程中，我有几点希望跟大家达成共识。我怎么讲、你那么去听，一配合，效果就出来了；你要是我这么讲、你偏那么听，效果就不好了。

#### 要高效、要愉快，更要踏实

第一，**要高效而愉快地学习**。高效体现在哪？听完了半天没听懂老师在讲什么，那就成了我的问题；如果我讲好了、讲明白了你还没听懂，那你也得想想自己的原因，是不是没有配合好。所以一定要高效——别学完了 Go 还不知道 Go 是什么。

我希望达到的效果是：**我讲一遍，你基本上就能听个 80%、90%；后面再把作业做一做，Go 语言核心编程基本就能拿下。**争取一个月或者一个半月之内，把 Go 比较常规的语法和用法都学到位。

只有高效了你才会愉快。学东西不能太痛苦，别天天这个听不懂那个听不懂，慢慢就不愉快，不愉快就会放弃——那就不是"从入门到精通"，而是"从入门到放弃了"。所以每一天都要有目标，学完了要达到什么目标，自己心里必须规划一下。不光我计划，你们也要计划。别上来听这个课跟玩一样，"我来接受一下计算机知识普及"。要么就好好学，要么就不学，要学就学到位。

#### 先整体框架，再细节

第二，学 Go 的时候，**先建立整体框架，然后再抠细节**。上来的时候不要把细节扣得太厉害，先把整体框架、这个东西是什么了解了，然后再一步一步往里深入。学东西先整体框架、再细节，这个地方要注意。

#### 培养"用到什么就能快速学起来"的能力

第三，我在讲课的时候会带大家培养一种能力——**用到什么能够快速学习的能力**，这也是实际工作里真正需要的。

我带的学生比较多，后面很多同学会说："老师，我们工作里有个知识点你没讲过。"我说那很正常。如果老师什么都讲过，那怎么可能？你在大学里学了那么多东西，工作里真正用过的有几个？我能保证的是，我们讲过的东西你在工作中 80% 以上都用得上；但毕竟还有 20% 你没接触过——因为你将来的环境我是不知道的，我也不知道你将来在工作中会遇到什么问题。我只能把我们能够讲的细致详尽地讲完，但不可能 100%。

所以听课的时候我会带大家培养这种能力：比如我会带大家看手册；遇到问题我会教你们怎么去调试；遇到一个技术难题，咱们从几个方面下手把它拿下。这里头会有启发的成分，我会告诉你们"这个知识点先暂时不讲，你们能不能先搞定"，然后在下一讲再把答案公布出来。

#### 先 know-how，再 know-why

第四，先 know-how，再 know-why。

这让我想起上大学时清华的一位老师，四五十岁年纪，特别有特点，讲话的时候嘴是歪着的。他跟我们说，我们学的计算机编程是一门**工科**，实践性很强。工科有一个特点：**你不一定把这个东西搞得很明白，但你能做出来。**这跟学数学、学物理不一样。有时候你做出来了，不一定知道为什么。

所以有时候先不要刻意地把每个东西都问一遍为什么。当然问为什么是对的，但也可以是这样：你先做出来，回头再看，哦，原来是这个原因。如果不是这样，我们天天都在想这是为什么、为什么、为什么，却不去做、不动手，那永远不知道为什么。所以做编程先 know-how 再 know-why，这是学工科的一个特点。

#### 软件编程是做中学

第五，软件编程是一门**做中学**的学科，不是会了再做，而是做了才会。所以我会在视频课程里布置作业。

布置作业的时候，希望你们先不要等答案。答案我当然会讲，会告诉你们这个东西怎么解决，但我希望你们在老师没讲这题怎么做之前，先自己做一做。不要看着看着题目不动手，问他为什么不动手，"我不会啊"——道理好像是能讲得通，但我希望你**能写一点思路出来也可以**；虽然不能全部写完，写一部分呢？核心代码实现不了，写段伪代码把思路理一理也可以。

我再强调一点：**是做中学，是在做的过程中学会，而不是会了才做。**这是我们工科的一个特点。

#### 该囫囵吞枣的时候就囫囵吞枣

第六，适当囫囵吞枣。有些时候我们可能对一个知识点没有理解得很到位。比如后面讲指针，它涉及到内存的东西，有可能你理解得不是那么形象。但我告诉你，**你可以适当囫囵吞枣一下**——虽然现在理解得不是很到位，但还要继续往下学、继续做，学到某个位置可能突然就恍然大悟了。

不知道大家有没有这种感受：这就像咱们练武功，前面练的"猴子摘桃"你不知道怎么用，只知道一个招式。等你实战了过后，被人家打了几下，突然发现原先老师傅教的猴子摘桃这一招应该怎么出。有时候就是要适当囫囵吞枣，不要每个地方都抠得很到位。当然你能抠到最到位那是最好的；实在理解不了也不用害怕，囫囵吞枣，然后接着往下学，学着学着突然回头一看就明白了。

#### 琢磨设计者怎么想，而不是"我认为应该怎么做"

第七，学习软件编程是在琢磨别人怎么做，而不是"我认为应该怎么做"。

举个例子。Go 语言里有个 for 循环，它的基本定义是这样写的：

```go
for i := 0; i < 10; i++ {

}
```

这种语法在很多编程语言里是很奇怪的。一般的、几乎所有传统语言都会用一对小括号把它括起来，但 Go 不括。你要问"为什么"，那设计者就觉得这样子更简洁，你上哪说理去？你说我觉得用小括号括起来很好，人家认为这个更好，你要跟人家较什么劲？

再举一个。用 Go 语言输出一个 Hello World，正确写法是这样：

```go
package main

import "fmt"

func main() {
	fmt.Println("Hello World")
}
```

下面这种在很多编程语言里绝对没毛病，是很标准的写法，Java、C 都支持：

```go
package main

import "fmt"

func main()
{
	fmt.Println("Hello World")
}
```

但它放到 Go 里会被认为是错的。**Go 要求把大括号写到上一行**，也就是必须用上面那种行尾风格。原因很简单：Go 默认会在每行末尾给你补一个分号，你把大括号另起一行，等于把函数头和函数体切开了，所以过不了。

> **易错点**：Go 这么设计，是因为它的设计者认为"一个问题最好只有一个解决方案"。他为了强制这门语言保持简洁，不允许你写成另一种风格。记住这条就够用了。

所以有时候你不能老觉得"我认为这样也可以、我认为那样也应该"——你这样想，很多时候就是在跟设计者较劲，我觉得没有必要。他说这么写就这么写就完了。

那我们的重点应该放在什么地方？**应该放在逻辑的处理上，而不是语法的本身。**语法怎么写都无所谓，你让我怎么写我就怎么写；重点是学习编程思想和逻辑处理能力。

以上这些学习方法和心得体会，跟大家共勉。

## 从"为什么"开始学：学习方法、程序本质与 Go 的来路
> 对应块：BLK02 | 覆盖分集：P03-P05 | 块标题（分集名）：《003_尚硅谷_如何学习Golang更高效(2)》

### 讲这门课的方式，和讲师的学法

先说两句题外话，算是我们正式进技术之前的一个交底。

我会尽力把课讲得通俗易懂，其他老师也都是这个风格。但毕竟这是一门语言，Golang 有它自己的难点——它借鉴了很多 C 语言的特点，有结构体，也有指针。指针一上来，难度就摆在那儿了，不可能小。所以我尽量通俗，但有些地方确实还是有难度，需要你们配合。你听课时会觉得挺轻松，可一门技术总归是有门槛的，凡是难的地方、要特别注意的地方，我都会特别强调一下。

这是第一点：尽量通俗易懂，但心里要有个准备。

第二点：我讲课既注重 Go 语言的整个体系，也会兼顾技术细节。**技术细节才是真正决定两个程序员档次的地方。** 你说你会写 Hello World，我也会写，但我写得比你快，写得规范、效率高——差别就在技术细节上。这是老师要重点给你讲的东西。

其实我今天想跟你聊的，是比知识本身更有用的一件事：**怎么快速地掌握一个新技术。** 这个我跟自己带的学员都分享过，他们反馈说特别受用。所以我把它拿出来讲两句——你不但能学到 Go 的知识，还能知道老师是怎么讲一个知识点的，将来你自己学别的技术时也有章法。

### 如何快速吃透一门新技术

我认为学一个新东西，应该按这么几步走。

#### 先问一句：为什么需要它

学新技术无非两个由头。

一是在项目开发中遇到了一个需求，需要解决某个问题——这种最多。二是有别的动机，比如你想跳槽，想学个新技术。

不管是哪个由头，有需求之后，第一个动作不是去翻文档，而是先拿现有技术试一试。

```text
   有需求
     │
     ▼
  现有技术能解决吗？
     ├── 能，且够好 ──────────────▶ 用它，收工
     ├── 能，但不够好 ──▶ 痛点浮出水面 ──▶ 技术缺口
     │                                    │
     └────────────────────────────────────┘
                                          ▼
                              自然引出「新技术」
```

拿页面局部刷新这个老例子。05 年、06 年那会儿，新浪、搜狐这些门户网站都面临同一个问题：早期一个页面一打开，是整个页面连图片一起加载出来的。很多人打开页面只看上面一块，看完就关了，后面加载的内容全白费了——流量浪费、带宽浪费、计算机资源浪费。

这个问题当时是怎么解决的？用传统的 `iframe` 框架。能解决，但不够好。既然传统方案有短板，那"用新技术来解决"这个念头就自然冒出来了：老师告诉你，用 Ajax 技术解决。

你看，这条路径是顺的——需求 → 传统方案能用但不好 → 技术缺口 → 新技术。**学一样新东西，学起来有障碍，往往不是因为它难，而是因为你不知道它是被造出来解决什么的。** 后面讲到函数的时候我也是这么开的场：先让大家看看没有函数有什么不好，你自然就明白函数是被什么逼出来的。这样学起来就没有障碍了，就感觉是顺理成章的事。

#### 原理和基本语法，先别抠细节

知道了为什么学，心理上就觉得这东西有用。接下来要做的是**快速入门**，此刻先不要抠细节。这一阶段要解决两个问题：把原理搞清楚，把基本语法搞清楚。**不要涉及到任何细节问题。**

Ajax 的原理是什么？它其实就是把 DOM、JavaScript 等等结合起来。基本语法也很简单，看一遍就会了。到这一步，入门就算完成了。

#### 一个 Hello World 级的快速入门案例

第三步做完了，第四步是做一个快速入门的案例。这个案例有两个特点：

- 第一个，**要极其简单**，简单到 Hello World 那个级别；
- 第二个，只让你了解这个新技术或知识点的**基本使用方式，不含任何细节**。

如果我来给新同学讲，我会拿一个特别简单的案例让他们看一眼这技术大概长什么样，但不展开细节。讲完，同学们心里就有底了："噢，原来我要学的东西长这样。"原理我知道了，基本语法我知道了，快速入门我也会了，心里就踏实了，感觉有点意思了，也没有压力了。

#### 技术细节才是最耗时间的地方

但各位要注意——如果你只掌握了原理、基本语法和一个简单案例，说实话**你根本没办法解决项目里真正遇到的问题**，因为你跟它还差着一大截。

所以下一个环节就是研究技术细节，也就是该技术的各种"坑"和规矩：

- 怎么使用更规范？
- 有没有什么使用陷阱？
- 使用时要注意什么？

这时候再研究细节，你不会觉得烦，为什么？因为你对它已经有了整体框架认识，学起来是"噢，是这么回事"。

我也实话实说告诉你：**技术细节这一块，是特别考察一个程序员能力的地方**，有经验的程序员和没经验的程序员，在细节上完全不是一个水平。一个刚入行一年的程序员和一个做了十年的程序员，后者对这个技术的细节了解得多得多。

所以我们学 Go 也会碰到同样的问题：讲一个知识点的时候，怎么把这个细节给你讲清楚，让你快速了解使用这个技术的注意事项——这是讲课里特别耗时间的地方。

```text
  为什么要学 ──▶ 原理 ──▶ 基本语法 ──▶ 快速入门 ──▶ 技术细节 ──▶ 回到项目解决问题
   （很便宜）                                        （★ 最耗时、最值钱）
```

这个阶段也是最耗时间的。我给你算一笔账：一个程序员用了一年这个技术，可能了解了 10 个细节；用两年，又多增加了 10 个细节。所以**编程是永无止境的，因为它可以不停地优化**。就算有程序员用 Java 或 Go 用了五年、十年，他也不敢说每个细节都学到手了，因为后面永远还可能有个小问题在等着你。

那为什么有些程序员一个月拿 5000，有些能拿 5 万？根本区别就在这儿。

#### 画一个 T 字型

所以学技术的人要注意：既要有框架感，同时又要能深入进去。学一个技术应该是一种感觉，是**一个 T 字型**。

```text
  ════════════════════════════════════════════════════
       │        │        │        │        │         │     ← 横：体系 / 框架感
  ════════════════════════════════════════════════════   大面都要知道
                     │
                     │
                     │                                   ← 纵：技术细节
                     │                                      越挖越深，永无止境
                     │
                     │
```

横向这一条是大面，整体我都能了解；纵向这一条是要能深入进去，哪里需要深入就往纵向往里扎。程序员有月薪 3000 的，也有 3 万的，区别就在这个 T 的两根竖线上。

我在讲课的时候，基本也就是按这套思路来带每一个知识点、每一个你们要注意的地方。

### 程序到底是什么

方法论讲完了，正式进技术。这一章先补一些编程的基本概念——课程是给零基础同学准备的，如果你有基础，这块可以跳；如果你以前对编程接触不多，那就老老实实按顺序听。

#### 老板指挥不了计算机

先说什么是程序。

所谓程序，就是完成某一个功能的指令的集合。这话听着抽象，我画个图。

想象这里有两个人：一个是老板，一个是老板的女秘书。秘书是老板的雇员，老板可以给她下指令。比如老板连着下了三道指令："把我说的内容记下来"——秘书拿个本就记下来了；"把内容打印出来"——她找台电脑打印；"把内容传真给某某公司"。这两个人就这样通过对话完成了交互。

现在问题来了：**假设老板要把这几件事交给计算机去做，你猜电脑能不能听懂？**

老板对着电脑说"帮我记录下来、打印出来、传真给某公司"——显然现在的计算机听不懂。也许几十年以后可能有这个能力，但现在绝对不行，而且这些话也太复杂了。所以**人直接指挥计算机是做不到的**。

那怎么办？程序就出来了。

```text
  人跟人：   [老板] ──口述──▶ [秘书]                      靠自然语言就能指挥

  人跟机器：[老板] ──口述──▶ [计算机]  ✗ 听不懂

  程序员：  [程序员] ──写源码──▶ [main.go] ──编译──▶ [main.exe] ──▶ [计算机逐条执行]
                                                                    能听懂
```

于是这个角色从老板换成了程序员——也就是你们将来有可能从事的职业。程序员指挥计算机的方式不是说话，而是**编写一段程序**。他先写一份源代码，比如叫 `main.go`：

```go
func main() {
	print("...") // 指令1
	// 指令2
	// 指令3
}
```

`print` 是他发出的第一条指令，后面还有指令二、指令三。这个整体就是一段源代码。

但源码还不能直接交给电脑执行，还差一步——**编译**。把 `main.go` 进行编译处理，会得到一个二进制可执行文件，比如叫 `main.exe`。计算机执行这个 `main.exe`，就把里面的事情做完了。

> **定义**：程序 = 为了让计算机执行某些操作或解决某个问题，而编写的一系列**有序指令的集合**。上面那位老板给秘书下的三句话，是人跟人的交互；换成程序员写给计算机的那一组指令，才是程序。

所以将来我们学编程，学说白了就是学怎么写这一块——写出来，交给电脑执行，完事。电脑可以是 Windows，也可以是 Linux、苹果。发文件、打印文件、上传下载、操作数据库，都是这么来的。

#### 那我们为什么要学 Go

Go 的作用很大，前面已经提过，这里系统地再说一遍。

- **Go 是区块链最主流的编程语言**；
- **Go 是当前最具发展潜力的语言**；
- **Go 是 Google 公司创造的语言**——它是 Google 的一个产品，也是 Google 现在主推的语言。有 Google 推，加上区块链的潮流形势，Go 会越来越火。

国外 Google、CoreOS 这些公司都开始用了；国内也不少了，青云、阿里、小米、京东，都在开始大规模地用 Golang 开发云计算产品。一句话总结：**谁先占领了先机，谁就拥有更多的机会。**

### Go 语言是怎么来的

学一门语言，还是应该简单了解一下它是怎么来的。因为只有知道来龙去脉，你才能知道它会是什么样的语言、有什么特性。行业里人之间互相调侃，也爱拿"Go 是怎么出来的"开玩笑。

#### 三位重量级开发者

先看 Go 语言的核心开发团队有谁——别学了 Go 还不知道它是哪些牛人设计的。

**Ken Thompson。** 大名鼎鼎。Unix 操作系统的最主要设计者就是他。C 语言的主要发明人也是他。1983 年就拿到了计算机行业最高奖图灵奖，98 年又拿到美国国家技术奖——都是世界级的荣誉，他还是美国工程院院士。更牛的是，2000 年他觉得对编程有点厌烦，不干了，去当飞行员；当了几年飞行员之后，又回来继续干这行。而且 B 语言也是他发明的。也就是说 B、C、Go 三门语言，主要发明人都是他。我们学了好几年还没学明白，人家发明一门语言跟玩似的。我还曾经在清华大礼堂远远见过他来做演讲，胡子很长，说得特别好，我一句没听懂——全英文的。

**罗伯·派克（Rob Pike）。** 贝尔实验室的人，也是 Unix 系统开发的主要成员，跟 Thompson 是好朋友，经常一起喝酒吃饭——一聊就干脆搞一个 Go 语言。他还非常厉害：UTF-8 编码主要是他创造的；特别擅长演讲，参加过美国一个特别有名的脱口秀节目，还很受欢迎；是射箭健将，1980 年奥运会上拿过一枚射箭银牌；还是个天文学家，设计了一台伽马望远镜，差一点就被美国航空航天局直接使用了。编程好、身体好、还是天文学家、还擅长演讲——多才多艺。顺便说一句，Go 的金花鼠吉祥物就是他老婆设计的。

**Robert Griesemer。** 谷歌浏览器里的 JavaScript 引擎是他设计出来的，Java 里的 HotSpot 编译器也是他协助设计的。这个人的照片我找了半天没找到，所以课件上没放图，大家知道有这么个人就行。

#### 谷歌为什么要创造 Go

官方说法大致是三点。

**第一，编程语言的发展落后于硬件。** 谷歌是业内赫赫有名的世界级公司，他们认为硬件技术更新很频繁、发展很快，但软件和编程语言跟不上，**不能充分发挥多核、多 CPU 的优势**。说白了就是 CPU 每次只能用到那么一点，10%、20%，我有 8 个核、16 个核却吃不满。他们想设计一款能充分发挥硬件优势的语言。

**第二，软件系统越来越复杂，维护成本越来越高。** 他们认为现有的编程语言有几个劣势：一是编程不够优雅、风格不统一——有人这么写、有人那么写，他觉得这不好；二是计算能力不够；三是处理大并发不够好。当然这是他们的一家之言。想设计出来的语言是：风格统一、计算能力足够强、还能处理大并发，而且非常简洁高效。

**第三，现有的语言各有各的短板。** 像 C、C++ 这种，速度确实非常快，但谷歌认为它们编译速度比较慢，还有内存泄漏的可能；像 Python、PHP 这种脚本语言，开发效率高，但速度又不够快。所以他想找一种**既兼顾编译语言的速度、又拥有脚本语言的开发速度**的语言。

把这三个初衷合起来看，Go 要体现的就是这种风格：把上面这些缺点统统拿下。

#### 发展简史，以及我们用哪个版本

```text
  2007        2009            2015          2017        2018
   │            │               │             │           │
   ▼            ▼               ▼             ▼           ▼
 三位工程师    首发 1.0        1.5 ★         1.8 / 1.9    1.10
 开始设计      11月10日      去掉最后残余     陆续发布    发布
                               的 C 代码
                            （里程碑）
```

这条线里有三个点要记住：

- **2007 年**派克、Thompson、Robert 三个人开始设计这门新语言；
- **2009 年 11 月 10 日发布第一个版本**——这个大家要有印象，不能一点都不懂；
- **2015 年的 1.5 是一个里程碑式版本**，它把最后残余的那部分 C 代码彻底拿掉了。到这时，Go 语言就可以说是"独树一帜"了。

Google 更新 Go 的速度还是蛮快的，2017 年出了 1.8、1.9，2018 年前几个月又发了 1.10。更新这么频繁，说明它的势头确实猛，现在学它对未来的发展也很不错。

那我们讲课用哪个版本？**用 1.9.2。** 没用最新的，是因为 18 年刚出来的版本还不算稳定；1.9 是目前各大公司采用比较多、比较成熟的稳定版。大家记住这个就行。

到这里，关于 Go 的诞生故事、它的来龙去脉和历史原因，就介绍完了。接下来我们正式进 Go 的技术本身。

## 七个特点定江山，再挑一款趁手的工具
> 对应块：BLK03 | 覆盖分集：P06-P09 | 块标题（分集名）：《006_尚硅谷_Go语言的特性和快速体验》

学一门语言，得先知道它是个什么脾气。所以先讲 Go 语言的特点。

但光干讲没意思——你把语言特点一条一条念过去，同学们没有一个直观的认识。所以我们一边讲一边写几个小程序，只写不跑，让大家先感受一下。所以如果你现在零基础，下面这些代码不用太纠结，就当体验一下；等后面真到那一步，我们再细讲。

### Go = C + Python

先给个总纲。**Go 语言既有静态编译语言的安全和性能，又有动态语言开发和维护的高效率。**

什么叫静态编译语言？像 C 语言，速度很快、安全性和性能都强。什么叫动态语言？像 Python，开发效率高。

用一个式子形容最形象：

$$
\text{Go} = \text{C} + \text{Python}
$$

这个描述不算特别精确，但足够说明它的特点：**既有 C 这种静态编译语言的运行速度，又有 Python 这种动态脚本语言的开发效率和好维护性。**这两方面结合得相当完美。

这个总纲一立，下面七条特点就都好理解了。

### Go 语言的七个特点

#### 从 C 继承来的那一套

第一，Go 从 C 语言继承了很多理念：表达式的语法、控制结构、基础数据类型、参数传值，还有**指针**。

大家注意，Go 语言里是有指针的。同时它保留了 C 语言一样的编译执行方式，并且**弱化了指针**——因为指针本来就难，所以 Go 对指针的要求做了点弱化处理。

指针长什么样，举个体验版的例子：

```go
func testPtr(num *int) {
    *num = 20
}
```

函数名里 `Ptr` 是 pointer 的简写。注意 Go 语言的一个写法习惯：**变量写在前面，数据类型写在后头**——`num *int` 就是"num 这个变量，类型是指针，指向 int"。

用起来也很简单：函数接收一个指针，然后用 `*` 符号取得指针所指向的值，再进行赋值。就三行。

#### 包：每个文件都必须归属于一个包

第二，Go 有**包**的概念。包这个概念在很多语言里都有，比如 Java 也有包。Go 引入包，是用来**组织程序结构的**——换句话说，我们后面的项目实际上是以包的形式来管理的。

这一条有个特别重要的话，大家要记住：**Go 语言的每一个文件都要属于一个包，而不能单独存在。**如果一个文件不属于任何包，它是编译不过去的。

举个例子。我新建一个文件 `test.go`，随手写一个函数：

```go
func sayOk() {
    fmt.Println("ok")
}
```

一保存就报错，提示说没有 package。因为 `fmt` 本身是一个包，所以还得 import 一个包，不然同样编译不过去。加上 `package main` 和 `import "fmt"`，这就编译过去了：

```go
package main

import "fmt"

func sayOk() {
    fmt.Println("ok")
}
```

至于具体属于哪个包，按实际情况定。

#### 垃圾回收机制

第三，Go 引入了**垃圾回收机制**。

C 语言里内存回收是要程序员自己管的，这事很麻烦——稍微不注意就内存泄漏，而内存泄漏很快就能把你的内存吃光。做过 C 开发的都知道那是什么滋味。

Go 一边借鉴 C 的东西，一边对它做优化，比如引入垃圾回收。**程序员只关注业务逻辑，不再关注怎么回收内存，直接用就行。**这一条没法举例子，就记住有这么个好东西。

#### 天然的并发

第四，**天然的并发**。这一条特别特别优，我给它标出来。

Go 刚开始设计的时候，就是冲着有效利用多核、多 CPU 去的。而多核多 CPU 最终要落到哪儿？落到**处理大并发**上。Go 在语言层面就直接支持并发，而且实现得特别简单——它引入了一个叫 **goroutine** 的概念，可以非常轻松地实现大并发、高效利用多核。

而且它是基于 **CSP 并发模型**执行的。

> **提示**：关于天然并发你就记一句话就够了：**Go 语言支持大并发做得非常到位，支持上千、上万个并发都属小儿科，它从语言层面就直接支持。**C 语言或者 Java 语言在这方面可能是赶不上 Go 的，后面你用起来会有更直观的感受。当然前提是用得得当。

这一条涉及 goroutine 这个知识点，后面再详细说，先不举例。

#### 管道通信机制 channel

第五，Go 吸收了一个管道通信机制，叫 **channel**。

这个管道要解决什么问题？**解决 goroutine 之间的相互通信问题**，用的就是 channel 这个管道来实现的。

先不举例——很多同学在这里突然来一个"管道"，听起来会懵圈。后面会有专门的章节来讲 channel 到底是什么。

#### 函数可以返回多个值

第六，**函数支持返回多个值**，这个比较好理解。

比方说我写一个函数，让它同时返回两个数的**和**与**差**。传统的编程语言只有一个返回值，要返回两个，你得用数组把它们封装起来再返回。但 Go 直接支持返回多个值：

```go
func getSumAndSub(n1 int, n2 int) (int, int) {
    sum := n1 + n2
    sub := n1 - n2
    return sum, sub
}
```

参数是两个 int，那返回值列表就写两个 int。处理的时候把和求出来、把差求出来，最后 `return sum, sub` 一起返回。

> **提示**：注意这两行里**没有分号**。Go 语句后面不用带分号——其实不是说不带，而是**编译器会自动给你带上分号**，所以你就不要画蛇添足了。

#### 切片和 defer

第七，这是 Go 独有的一些语法现象。

一个是**切片 slice**，可以理解成动态数组，有点像 Java 里的集合概念。

另一个是 **`defer`** 关键字，用于**延时执行**——函数执行完毕之后，再去执行 `defer` 里面的这些语句。它是为了在函数中能够及时、方便地回收资源。

七条就这么多。现在虽然还没逐条展开，但大家多少能体会到 Go 跟别的语言差别在哪。**总结成一句话就是：它既有编译型语言的速度，又有动态开发语言的开发效率。**

也正因为并发处理得非常到位，前面讲的那些后台服务程序、云计算才那么喜欢用 Go。

### 开发工具怎么选

既然要做 Go 开发，就得先挑一款工具。

| 工具 | 特点 |
| --- | --- |
| **Visual Studio Code（VS Code）** | 微软出品，跨苹果、Windows、Linux 三大平台；默认支持 Go 语法高亮，装 Go 插件后有智能提示，还能直接编译运行 |
| **Sublime Text** | 免费，支持语法高亮；但用到一定次数会提示你购买，比较烦人，不买也能继续用 |
| **Vim / Vi** | 非常强大的文本编辑工具，Linux、Unix 下的常客，程序员中使用广泛 |
| **Emacs** | 号称"编辑神器"，不只是编辑工具，还能当集成开发环境，Linux、Unix 环境常用 |
| **Eclipse** | 本身是个平台，装什么插件就能开发什么；装上 GoEclipse 插件就能做 Go 开发 |
| **LiteIDE** | 中国人自己开发的 Go 专用 IDE，免费，网上一搜就能下载 |
| **JetBrains 系** | PhpStorm、WebStorm、PyCharm 都能用来开发 Go，但需要装 Go 插件，而且都是付费产品 |

我们选 **VS Code**。

#### 为什么不一上来就用最智能的 IDE

工具这么多，选哪一款？我的建议是：**先用 VS Code 或 Vim 这种文本工具，等你对 Go 语言有一定了解之后，再换更高级的 IDE。**

原因有两个。

**第一，能更深刻地理解 Go 语言技术，培养代码感。**讲课的时候前期先不给提示，至少前面一段时间，希望同学们不需要提示也能写代码。你不能说我打开一个高级工具，一点，"啪"一堆东西全出来了——这对刚开始学 Go 的同学没有任何好处。因为你连最基本的函数都不会写，哪天面试了会有个麻烦事：**可能连 `println` 这个函数都写不出来，就麻烦了。**

**第二，有利于公司面试。**将来参加工作的时候，有可能人家直接给你一张纸，让你用笔写程序。你以前没手写过最基本的函数，那拿一张纸让你用笔写，你想你写得出来吗？肯定马上就懵圈了。

所以我们刚开始用稍微原始一点的工具，后面再智能一点。

#### 智能提示长什么样

装了 Go 插件之后，打一个 `fmt.`：

```go
fmt.
```

可用的函数马上就全列出来了。现在因为没装插件，所以这里是空的；装上插件一点，马上就有。

### 下载地址：先分清系统，再分清位数

下载地址很简单。浏览器里直接搜"VS Code 下载"，回车，点进 **Download Visual Studio Code** 那一项。

进去之后你会看到 **Windows、Linux、Mac** 三个大选项——先判断你希望在哪个系统下面做开发，这是第一层选择。

第二层是格式和位数。

**Windows**：有 installer 和 zip 两种。installer 是 exe 文件，双击安装；zip 是解压就能用的。你再根据自己的系统是 32 位还是 64 位去选对应的那个。

**Linux**：分好几种格式。`.deb` 是 Ubuntu 用的；`.rpm` 是红帽、Fedora、SUSE 那一类；`.tar.gz` 就是压缩包，解压完直接能用。如果你不清楚 `.tar.gz`，就理解成"一个压缩文件，解压之后即可使用"就行。我自己用的是 64 位的 Ubuntu，所以选的是 64 位那个 `.tar.gz` 版本，解压就能用。32 位的就选另一边。

**Mac**：只有一个版本，没得选。

> **提示**：很多同学会问"我怎么知道自己的系统是 32 位还是 64 位？"有个小技巧：**点开计算机 → 属性 → 系统类型**，这里写着 64 就说明你是 64 位系统，否则就不是。**这一点大家要清楚，不然选错了装上不好使。**

我会分别在 Windows、Linux（选 Ubuntu）和 Mac 上都演示一遍——因为每个同学的系统可能跟我不一样。Linux 用 Ubuntu 没问题，如果你用的是 CentOS 也行。

### Windows 下安装 VS Code

#### 步骤一：把安装文件准备好

先到下载地址选好适合自己系统的版本下载。下载完你会得到一个 `VSCodeSetup` 开头的安装文件——我这里下的是 64 位的那个。你根据自己的需求在 64 位和 32 位之间选，选好以后确认一下自己系统是多少位再点安装程序。

#### 步骤二：双击安装文件

安装其实非常简单，傻瓜式安装就行。双击安装文件以后：

- 点"我接受"，下一步；
- **安装路径**：默认会装到 C 盘，我一般不装 C 盘，我装到 D 盘。这纯粹是个人习惯，我也建议同学们专门找一个目录装。我装在 D 盘的 `programs` 目录下，它默认会帮我创建这个文件夹；如果这个文件夹已经有了，我就写个 `2`，表示这是我第二次安装的版本；
- **这里有一个"添加到 PATH（重启后生效）"，把它勾上。**勾上以后 VS Code 就被加到 PATH 这个环境变量里面去了，可以直接用；
- 然后下一步，等它安装完，点"完成"。

> **易错点**：很多同学这里是先卸载再装的演示。卸载的路径是：控制面板 → 程序和功能 → 输入一个 `M` 过滤（`M` 开头的多半都是微软的产品）→ 找到 Microsoft Visual Studio Code → 卸载 → 它会问要不要删除相关的文件夹，选删除。卸载完记得刷新一下控制面板列表，这样才看不到那一项了。

#### 步骤三：第一次简单使用

安装成功后会弹到这个界面，看到它就说明装好了。

先做个便利性的小操作：我们装的位置是 D 盘下面，找到 Microsoft VS Code 这个文件夹，里面有启动文件，**把它发送到桌面做个快捷方式**，以后双击就能开，非常方便。

真正用起来是这样：

**先建一个专门存放 Go 代码的文件夹**，比如我在 D 盘建一个叫 `gocode` 的。然后在 VS Code 里用"打开文件夹"，选到这个 `gocode`，它就会把这个文件夹当作你的工作区打开。

接下来就可以在里面写程序了。点 New，新建一个 `test.go`，写这么一段：

```go
package main

import "fmt"

func main() {
    fmt.Println("hello")
}
```

`fmt` 就是引入的那个包；顶上那句 `package main` 是把这个文件归属到 main 包。这是能跑起来的最短的一段代码。

> **提示**：用着的时候它老在底下弹那些提示，意思就是"你是不是在拿它做 Go 开发，要不要装点插件、装点包"。我们现在不想装这些，**直接叉掉就行**。叉一次之后就不会再提示了；万一又提示，再叉一次。

到这，Windows 这一块就讲完了。也不难，大家可以自己上手练一练。后面真正做 Go 开发的时候，我们还会反复用这款工具，并且会讲得更细。

再往后就是 Linux 和 Mac 上的安装了。

## 三个系统怎么装 VS Code，以及为什么前期我只用 Windows
> 对应块：BLK04 | 覆盖分集：P10-P11 | 块标题（分集名）：《010_尚硅谷_Linux下VSCode的安装和》

Windows 上装完，接下来把 Linux 和 Mac 也走一遍——有些同学就习惯用 Linux 开发，也有一些程序员、尤其是国外的一些程序员非常喜欢在苹果机下面做 Go 开发。

先把一句话撂在这儿：**你不会 Linux 完全无所谓，不会 Mac 也无所谓。**因为后面我们主要还是在 Windows 下面做开发，你 Windows 会就够了。学 Go 语言不会受任何影响。之所以演示这两个系统，是考虑到确实有同学习惯用它们。你要是不懂 Linux，直接跳过去就行。

### Linux 下安装

#### 环境先说清楚

我这边用的是**虚拟机**装的 Linux，具体是 Ubuntu。有同学会问虚拟机是什么，不懂的可以先看看相关资料，不懂也无所谓——反正后面还是在 Windows 下开发。我这份安装包是 **AMD 64 位**的：AMD 是 CPU 的型号，64 位说明系统是 64 位的。既然你在玩 Linux，那你肯定已经不是初学者了，Linux 怎么玩你肯定是知道的。

#### 步骤一：找到对应的安装包

老规矩，先下载 Linux 版本的 VS Code 安装软件。你的 Linux 是什么版本，就对应下对应版本的安装包。

#### 步骤二：把安装包传到 Ubuntu 里

因为是虚拟机，所以多一个步骤：得把 Windows 这边下载好的安装包**传输到 Ubuntu 系统下面**。

我用的是 **Xftp** 这个软件来做传输。打开 Xftp 5，连接到我的 Ubuntu，它会弹出一个框让我输密码，我输进去之后，它会自动切换到我要的那个目录。

这时候的状态是：**老师的 Windows 系统已经连上了虚拟机里的 Ubuntu。**接下来把 Windows 上的那个 VS Code 安装包上传过去就行——双击进到软件文件夹，选中它，上传。传得很快，一下就过去了。

#### 步骤三和四：拷到 `/opt` 目录下

传过去之后，下一步是解压。不过在 Ubuntu 下做 Go 开发的话，我建议把 VS Code 装到 `/opt` 这个目录下——这是我的个人习惯。当然你不装到这儿也行，大家习惯上都喜欢把软件装到 `/opt` 下面。

怎么拷？打开终端。我先看一下当前目录，能看到刚才传过来的安装软件就在这儿。然后把它拷到 `/opt` 下——

它提示**权限不够**，因为我是一个普通用户。没关系，切换成 root 用户：

```bash
su root
```

输入 root 密码（这个你自己应该是知道的），回车，成功。现在再拷贝就没有问题了，拷贝到 `/opt` 目录下。切到 `/opt` 里 `ls` 一下，就能看到软件已经在那里了。

#### 步骤五和六：切换目录，解压

切换目录用 `cd` 指令：

```bash
cd /opt
```

意思就是切换到 `/opt` 目录下。然后解压：

```bash
tar -zxvf code-stable-x64-1536817294.tar.gz
```

解压完就可以用了。

#### 步骤七：找到可执行文件，运行

`ls` 一下，会看到一个蓝色的文件夹，这就是解压过后的目录。`cd` 进这个目录再 `ls`，你会看到一个绿色的文件——这就是**可执行文件，叫 `code`**，有点类似于我们前面讲的 Windows 下面那个 `Code.exe`。

运行它就是这个指令：

```bash
./code
```

回车之后会有一个"这个不用去管它，一会儿就好了"的提示，等一会儿，蓝色的英文界面就起来了——VS Code 启动成功。

#### 打开工作文件夹，写第一段代码

启动之后用法和 Windows 下是一样的：**打开一个文件夹**，选择你要把 Go 代码放在哪儿。我一般放在 atguigu 这个用户下面，可以放一个 `code` 代码目录；你不喜欢也可以换个路径，比如新建一个 `mycode`、`my` 或者 `go_dev` 这样的目录，点确定，VS Code 就切换到那个文件夹了。

在里面 New 一个 `test.go`，它会提示你"你这个应该装一个 Go 扩展"——因为它发现你写的是 Go 文件。现在我们不管它，直接写：

```go
package main

import "fmt"

func main() {
    fmt.Println("hello")
}
```

Linux 下简单安装和使用 VS Code 就是这个流程。会 Linux 的可以自己玩一把；不会的，跳过去，没关系。

### Mac 下安装

Mac 下更简单，因为它只有一个版本。

#### 步骤一：下载 Mac 版安装包

刚才在下载页面介绍过，苹果系统下的 VS Code **只有一个版本，是一个 zip 文件**。你要做的就是把这个文件解压，然后使用。

#### 步骤二：传到 Mac 系统下

还是老规矩，把安装软件传输到 Mac 里。我的虚拟机上还装了一个苹果系统，是 10.11 版的。有些苹果机太贵了买不起，如果你刚好用的就是苹果机，就可以直接用；没有的话也可以装一个苹果机虚拟机。

传输的原理和 Linux 那边一样。

#### 这里有个坑：Mac 默认不开 SSH

> **易错点**：想把安装包传到 Mac 里，**Mac 系统默认没有启动 SSH 服务，所以必须先启动一下才能远程传文件。**Mac 本身是装了 SSH 服务的，只是默认不开机自动启动。如果你没启动，是没办法把 zip 文件传过来的，会直接提示连不上。

怎么启动？先查一下当前有没有这个服务：

```bash
sudo launchctl list | grep ssh
```

它会让你输密码，输的是你这个用户的密码。查出来有记录，就说明服务是起来的；如果你把服务停了，就查不到这一项。

演示一下把它停掉：

```bash
sudo launchctl unload -w /System/Library/LaunchDaemons/ssh.plist
```

停掉之后再连，就真的连不上了——会提示连接失败。为什么？因为刚才已经把它停了。有些同学第一次用苹果机、没启动过这个服务，就会碰到这种情况。

那要连怎么办？把 `unload` 改成 `load` 就行：

```bash
sudo launchctl load -w /System/Library/LaunchDaemons/ssh.plist
```

回车，启动。再点连接，这次就连接上了。启动之后你也可以用前面那个查询指令再确认一下有没有。

#### 步骤三：解压，得到 .app

启动好 SSH 传进去之后，第三步就是解压，这个非常简单，一句话的事：

```bash
unzip VSCode
```

后面跟的是你下载下来的那个 zip 文件名。解压完你会得到一个 **`.app` 文件，这就是可执行的文件，双击就能打开**。

怎么进到它的图形界面去双击？用过苹果系统的同学非常熟悉：新开一个 Finder 窗口，就看到文件系统了。点我的磁盘 `abc`，里面有个 `用户`，用户下面有 `atguigu`，这里面有一个 VSCode 文件夹，就是刚才解压出来的，双击，VS Code 就起来了。

#### 步骤四：打开文件夹，写一段 Hello World

起来之后我们照样写一段代码。VS Code 总是以一个文件夹的形式来管理工程的，所以新建一个文件夹，还是放在 `abc`、用户、`atguigu` 下面，名字就叫 `gocode`，创建完打开它——VS Code 就会把这个文件夹打开。

然后建一个 `test.go`。它又会提示装 Go 插件，这个我们不需要，删掉那些提示信息就行。写：

```go
package main

import "fmt"

func main() {
    fmt.Println("Hello, World!")
}
```

这就是在苹果机下面开发 Go 程序的一个简单演示。如果你用的是苹果系统，就可以这么玩。

### 三个系统都装完了，为什么前期还是用 Windows

到这里，三个系统的 VS Code 安装和使用就都讲完了。后面还会讲怎么在这三个系统下安装 Go 的 SDK，然后真正做开发。

但有几句话我要先点出来，不然有些同学会有压力，说"老师我 Linux 没学啊，我都不知道，那我压力太大了"。

**前期一段时间，我们还是在 Windows 下面做开发。**原因有两个。

**第一**，很多同学对 Windows 系统更熟悉一些，选它可以减轻大家学习的压力。

**第二**，也是更重要的一点：**你在 Windows 下做 Go 开发、在 Linux 下做 Go 开发、还是在 Mac 下做开发，本质没什么区别，因为基本的核心语法是一样的。**甚至在实际开发中，还有很多人是在 Windows 上把程序写好，然后上传到 Linux 上部署——这种开发形式在实际工作中用得还比较多。

所以我把这个知识点提前给大家点出来，让大家做到心中数，不至于非常迷茫：**我们会讲三个系统下怎么装 VS Code、怎么装 SDK、怎么开发，但前期为了方便以 Windows 为主；等到后期真正开始讲项目、讲区块链的时候，就会用 Linux 了。**

你在 Windows 下开发完了上传到 Linux，其实完全是一样的。

## 有了编辑器还不够：Windows 下把 Go 的 SDK 装上、配好
> 对应块：BLK05 | 覆盖分集：P12 | 块标题（分集名）：《012_尚硅谷_Windows下搭建Go开发环境》

现在我们手里已经有工具了，能写 Go 程序了。那是不是就可以做 Go 开发了呢？**还不行。**

比方说你现在写了一段代码，就叫 `main.go`，很简单的，输出一句话。可这段源代码你**执行不了**。为什么？因为源代码需要先被**编译**，编译成可执行文件，才能被计算机执行。这个环节就需要我们去搭建 Go 语言的开发环境。

打个比方你就明白了：你已经有了一个暴风影音，但你没有要播放的文件，你照样看不了 movies。**光有播放器没用，你得有可执行文件；光有源代码没用，你得有编译它的工具。**

### SDK 是什么

所以我们需要安装一个叫 **SDK** 的东西。

SDK 的全称是 **Software Development Kit**，软件开发工具包。你要去开发 Go 语言、去写 Go 程序，就需要这么一个软件包——就像你要做图得先装一个 PS 软件，你没有这个软件就是做不了活的。

> **定义**：**SDK 是软件开发工具包，里面包含了对应开发语言的各类工具，主要是编译工具和一堆 API。**如果你没有 SDK，你就只能写源代码，写完了也跑不起来。

工作里要是有人问你"Go 语言的 SDK 是什么意思"，你得答得上来：**软件开发工具包。**

所以 Windows 下搭建 Go 开发环境，简单说就是**安装和配置 SDK**。

### 到哪儿去下载

一般来讲都是到 Go 语言的官方网站 `golang.org` 下载。但非常遗憾，因为种种原因，这个网站有可能被和谐掉。**你能翻墙就去官网下；不会翻墙也没关系，国内有一个叫" Golang中国"的网站，去那儿下载也是可以的。**

打开官网你会看到，当前最新版本是 **1.9.2**，也就是我们目前使用的版本。

### 版本怎么选：先看系统，再看位数

很多同学会问："老师，为什么有这么多 SDK 版本啊？"

原因很简单：**Go 语言可能在 Linux 上开发，也可能在苹果上、可能在 Windows 上开发，不同的系统对应不同的 SDK。**你的 Linux 还又分不同的版本、不同的位数。所以选之前要分两层判断。

```text
                     Go SDK 下载列表
                             |
     +---------------+-------+-------+-----------+----------+
     |               |               |           |          |
   Darwin           Unix          Linux      Windows      source
  (苹果机)        (FreeBSD等)   (Ubuntu/CentOS)            (源码包)
     |               |               |           |
  .pkg / .tar.gz   同样两种格式   386 / amd64 / arm   386 / amd64
                                   ↓                 ↓
                              32位 / 64位        .msi / .zip
                              arm 不要下          32位 / 64位
```

读图：**第一层先按操作系统分**（Darwin 就是苹果的操作系统），**第二层按包格式和位数分**。

**位数怎么认？**`386` 代表 32 位，`amd64` 就是 64 位操作系统。这个我不再赘述。

**包格式怎么认？**

- `.pkg` 是图形化安装包，`.tar.gz` 是解压缩就能用的。**推荐大家用 `.tar.gz`。**
- Windows 下的 `.msi` 相当于 `.exe` 那种 setup 形式的安装，`.zip` 是解压即可使用。**我们推荐用 zip。**

**Linux 那边要多说一句：**`386.tar.gz` 对应 32 位系统，`amd64.tar.gz` 对应 64 位系统。旁边的 `arm` 版本**不要去下**——这个 CPU 体质跟我们不一样，下了你也用不了。

**最后的 source 是源码包。**你们愿意的话可以直接下载——Go 语言的源码是直接给用户可以看到的，它是开源的。

所以结论就是：**如果在 Windows 下开发，去 Windows 那块下载；64 位选 64 位的那个 zip 包。**我自己用的就是 `windows-amd64` 64 位的 zip 版本。

### Windows 下安装 SDK

Windows 下的安装主要就是按 32 位还是 64 位来选版本，前面已经讲过了。选好之后有几个注意点。

**第一，安装路径不要带中文，不要有特殊字符，最好就是纯英文。**

**第二，建议装在 D 盘。**当然你不装 D 盘也行，F 盘、E 盘、C 盘都行。我的习惯是装在 D 盘的 `programs` 目录下。

**第三，安装基本是傻瓜式的，解压就能使用，非常简单。**

还有同学问"我怎么知道自己是 32 位还是 64 位"——记得前面讲过吗？在电脑的属性里面看一下系统类型，这个地方要清楚，不然选错了装上不好使。

#### 实操：解压

下载好之后，把这个 zip 粘贴到 D 盘的 `programs` 目录下，然后右键**"提取到当前目录"**，就放在 D 盘下面，等它解压完就行。

它毕竟有 **285MB**，机器慢的话要等一会儿；机器快可能"嗖"一下就过去了，我这个机器性能就稍微差了点。

解压完之后注意两件事：**第一，解压完那个 zip 文件就没用了，可以删掉**——当然保留也行，我是想着省点空间就删了。**第二，解压完你会得到一个 `go` 文件夹，这个 `go` 目录就是 SDK。**

### 打开看看：SDK 目录里都有什么

点进去瞅一眼，跟我说的对不对。

| 目录 | 里面是什么 |
| --- | --- |
| `api` | 一堆 API |
| `bin` | 三个指令：`go.exe`、`godoc.exe`、`gofmt.exe` |
| `doc` | 文档 |
| `src` | **Go 语言的源代码** |

`src` 这个目录比较有意思，以后有兴趣的同学可以去看。**后面讲到后期，为了让大家更深入地理解 Go 的基本原理，我会带大家去看它的源代码，看它的内核是怎么写的。**

#### `bin` 里的三个 exe

`bin` 里只有三个程序，我们重点看第一个：

- **`go.exe`**：Go 的运行和编译器，**这是最重要的一个**。Go 程序写完以后，用它来编译和运行我们的代码。既可以编译成可执行文件，也可以直接用 `go run` 当脚本跑。
- **`godoc.exe`**：用来生成文档的。
- **`gofmt.exe`**：对你的代码进行格式化。

> **提示**：如果你学过 Java，就知道这个 `go.exe` 有点类似于 `java` 和 `javac` 的角色。三个里面，**最主要还是 `go` 这个家伙，后面大家会用得很得多**。

### 测试一下：go version

怎么证明装成功了？得测。

打开 CMD（它严格说不是真正的 DOS，而是一个 shell 操作界面），`cd` 到 SDK 的 `bin` 目录里去：

```cmd
cd D:\programs\go\bin
D:
```

进去以后打一个 `dir`，能看到 `go.exe`。然后执行：

```cmd
go version
```

回车，如果输出是这样：

```text
go version go1.9.2 windows/amd64
```

**看到这个，就说明成功了。**版本是 1.9.2，Windows 下面，AMD CPU 的 64 位操作系统。恭喜你，成了。

如果你没看到这个界面，说明安装还有问题，你就想想是不是哪一步没按要求做——比如路径里有中文？——按步骤重新走一遍就能成功。

### 新问题：换个目录就用不了了

但是呢，装好以后又出现一个新问题。

刚才在 `D:\programs\go\bin` 这个目录下敲 `go version`，是有输出的。但如果我把路径换到别的地方去——我先 `cd ..` 切换到上一级目录，也就是 `go` 这个目录——再执行：

```cmd
cd ..
go version
```

你会发现提示的信息不一样了：

```text
'go' 不是内部或外部命令，也不是可运行的程序或批处理文件。
```

意思是：在这个目录下就不能用 `go` 了。这个太让人郁闷了——**因为将来老师写的源代码不一定放在 `bin` 目录下面，它可能在 C 盘、可能在 F 盘。你不能说我把源代码放到别的盘下面，我就用不了 Go 的编译器，那说不过去吧？**

所以这就引出一个新需求：**要配置环境变量了。**

#### 为什么会这样：Windows 找程序的原理

先搞清楚原因。Windows 执行一个程序时：

1. **先在当前目录下找**有没有这个可执行程序；找不到，
2. **再到环境变量 `Path` 指定的目录里找**；还是找不到，
3. 就报那个"不是内部或外部命令"的错。

所以我们进入 `bin` 目录能运行，出来就找不到了，原因就是这么简单。既然有这个原因，下一步就是配置。

> **定义**：**环境变量的作用，就是把 `go` 所在的路径定义到环境变量中，让系统帮我们去找这个程序，从而在任何目录下都能执行 `go` 指令。**

### 配置环境变量

Go 开发中主要需要配三个环境变量。如果你有 Java 基础，听起来会比较轻松——Java 也要配环境变量；不过我们是针对零基础的，所以讲得细一点。

先说清楚**为什么要配**：因为不配的话，你只能在安装的那个目录下使用，这显然不合理。

#### 进到环境变量配置界面

**计算机 → 属性 → 高级系统设置 → 环境变量。**

进去以后你会看到两块：一块叫**用户变量**，只针对当前用户生效；另一块叫**系统变量**，针对所有用户都生效。显然配到**系统变量**比较好，对所有用户都能用上。

所以步骤是：点属性 → 点高级系统设置 → 点环境变量 → 在系统变量这里编辑。

#### 三个变量分别填什么

| 变量名 | 变量值 | 说明 |
| --- | --- | --- |
| `GOROOT` | Go 的安装路径，比如 `D:\programs\go` | 指定 SDK 安装路径，Go 装在哪儿就填哪儿 |
| `Path` | 在已有值**末尾**加一个分号，然后 `%GOROOT%\bin` | 不新建，点"编辑"追加 |
| `GOPATH` | 你自己的工作目录，比如 `D:\goproject` | Go 项目的工作路径 |

**第一个，新建 `GOROOT`。**变量值直接写 Go 的安装路径。**不能说我写什么你就照抄**——如果你装在 F 盘，照抄 D 盘就找不到了，按自己的实际情况来。

**第二个，配置 `Path`。**注意这里有个区别：**`Path` 这个环境变量系统本身就有了，所以不要新建，要点"编辑"去增加**——人家已经有了，你再去建一个没有道理。点进去，在后面加：一个分号，然后 `%GOROOT%\bin`。

这两个写法代表什么呢？**`%GOROOT%` 是去引用刚才定义的那个 `GOROOT` 变量**——它已经指向 Go 的安装目录了；**`\bin` 表示在后面再加一个 `bin` 路径**——因为实际上的编译程序是在 `bin` 目录下，所以要在后面补上 `\bin`。配好点确定就行。

**第三个，再新建一个叫 `GOPATH`。**它指的是将来 Go 项目放在哪个目录。Go 项目放哪儿也很重要，**这个跟 Java 不一样，Java 没有这个。**你可以先创建一个目录，比如准备放到 D 盘的 `goproject`，以后就把 Go 的项目或工程放进这个目录里。

> **提示**：为什么 `GOPATH` 这么重要？因为**编译器在编译的时候会用到这个路径，它会生成一系列的 `.a` 文件或者 `.exe` 文件**。

这个是**新建**，注意看——系统以前是没有 `GOPATH` 的，它是一个新创建的环境变量。保存一下。

最后**一定要点确定**。不点确定，有些同学整个配完了直接点取消，那不是白忙活了吗。

### 一个必须记住的坑

点完确定，我们回到 `programs` 目录下去执行一下，看能看到不。

一回车——咦，怎么还没看到？是不是配错了？**没有配错。**

原因是：**配完环境变量以后，需要重新打开一次 DOS 终端**，要把原来这个控制台关掉、重新打开，新开一个。

你看我现在在 C 盘下面，不在 D 盘。再执行：

```cmd
go version
```

回车——有了。原来是这样。

> **易错点**：**配置环境变量后必须重新打开一次 DOS 终端**，不然你会发现不生效。这是新手最容易卡住的一个点，记住它能省你半小时。

到此为止，恭喜大家，我们终于把 Go 的开发环境配好了。步骤、原因都写清楚了。大家可以拿点时间跟着步骤自己练一遍，练习过了再接着往下学。

## Linux 和 Mac 上把 Go 的开发环境搭起来
> 对应块：BLK06 | 覆盖分集：P13-P14 | 块标题（分集名）：《013_尚硅谷_Linux下搭建Go开发环境》

Windows 下那一套走完了，我们再来看 Linux 和 Mac。

先把心结解开：**不会 Linux 没关系。**你有两个选择——要么先去学一下，要么直接跳过。因为后面主要还是 Windows 下开发，我演示这两个系统，纯粹是考虑到有些同学比较熟悉 Linux、或者就喜欢在苹果机下面做 Go 开发。

原理性的东西前面都讲过了，所以这次不重复，直接演示怎么装。

### Linux 下安装 SDK

#### 第一件事：先搞清楚你的系统是多少位

安装包有 386 和 64 位两种，下哪个得看你自己。**怎么查？**

打开 Linux 的终端，输入这个指令：

```bash
uname -a
```

看清楚输出：**如果你看到里面有 64，说明你这个 Linux 系统就是 64 位的；如果看不到 64，那一般来说就是 32 位的。**

我这一看是 64 位的，那我就应该选 `.tar.gz` 这个包了——前面讲过为什么选它，因为它一解压就可以使用。

#### 注意事项：路径别折腾

装的时候**不要有中文路径，不要有特殊字符，不要有空格**。

我以前有个学生也是这样：找了半天发现就是个路径的问题，没意思。所以让你别有这个，你就别有这个，不要自己把自己折腾一遍，不划算。

至于装在哪儿，我建议大家放在 **`/opt` 目录**下面。当然不是强制的，但习惯上大家都喜欢把软件装到 `/opt` 下面。

#### 四步曲

```text
  ① 上传           ② 拷贝              ③ 解压             ④ 验证
  安装包 →  Ubuntu   拷到 /opt          tar -zxvf          cd go/bin
  (Xftp 5 传输)     (权限不够就 su root)                   ./go version
      |                 |                   |                  |
      v                 v                   v                  v
  ~/go1.9.2...   /opt/go1.9.2...     /opt/go/bin/go      go version go1.9.2
                                                     linux/amd64
```

读图：从左到右就是安装的全部四步，成功与否以最后一步的版本输出为准。

**第一步：把安装包传到 Ubuntu。**打开 Xftp 5，输密码连上去。我这里有 32 位和 64 位两个包，既然 `uname -a` 查出来是 64 位，就选那个 64 位的传过去。你本身就用 Linux 的话，用别的方式下载就行。

**第二步：把安装包拷贝到 `/opt`。**传过去以后 `ls` 一下，能看到这个 Go 的安装包了。接着拷贝到 `/opt`——它会提示**权限不够**，因为我是一个普通用户。没关系，切换成 root：`su root`，输密码，然后再拷贝，就没问题了。

**第三步：解压。**`cd /opt`，能看到里面有一个压缩包，解压：

```bash
tar -zxvf go...
```

注意**命令和参数之间都有空格**。这个文件比较大，解压会有点慢，等一等。解压完会看到一个新的 `go` 目录。

**第四步：验证。**`cd` 进这个 `go` 目录，`ls` 一下能看到里面有个 `bin`，再 `cd bin`，里面是三个绿色的可执行文件。执行：

```bash
./go version
```

一回车能看到版本信息，**这就证明 Go SDK 已经安装成功了。**

### Linux 下配置环境变量

SDK 装好了，可还是那个老问题——**不配置环境变量，你在别的路径下依然用不了 Go 的指令。**

验证一下就明白了：在 `/opt` 目录里执行 `go version`，它会提示你没安装。**实际上我是装了。**原因跟前面讲的一模一样，我就不重复了。

#### 编辑 `/etc/profile`

Linux 下有个文件叫 `/etc/profile`，它就相当于 Windows 的环境变量配置文件。**在里面加上三个变量就行了**，含义前面都讲过：`GOROOT` 是安装目录，`PATH` 是可执行文件的路径，`GOPATH` 是工作目录。

> **提示**：编辑这个文件**需要 root 权限**。用 `vim` 编辑 `/etc/profile`（vi 和 vim 一样，我用 vim 是因为它有颜色，看起来好看一点）。

里面要写三行，我逐条说清楚。

**第一行，`GOROOT`。**刚才我们是装到 `/opt` 下面的，所以这里就指向 `/opt` 下的 go 目录。

**第二行，`PATH`。**注意这里**千万不要打空格**——有些人在 Linux 下写变量会习惯性加个空格，写上空格就错了，Linux 下面不允许多余空格，不然它不识别。

紧接着要把原先的 `$PATH` 带进来，再在后面写上刚才的 `$GOROOT/bin`。我解释一下这一步：**`$PATH` 代表引入它原先的路径**。如果没有这句 `$PATH`，你等于把以前 PATH 里原有的东西全冲掉了，那肯定不行。所以要把原先的带上，再拼接上——这里的**冒号**就相当于在后面接上一段，把带 `bin` 的路径拼上去，相当于累加了一个路径。

有同学会问："老师，我觉得直接写 `/opt/go` 行不行？"**也可以，但你这样写不是不划算嘛。**你上面已经定义了 `GOROOT`，何必再抄一遍 `/opt/go`？**专业的写法就是直接引用 `$GOROOT`。**

**第三行，`GOPATH`。**我们把它放在 home 下面的 `go_project` 目录，也是一个环境变量的引用——引用用户的 HOME 环境变量，然后接上 `/go_project`，表示将来我的 Go 项目就放在这个目录下面。

写完**一定要保存退出**：

```bash
:wq
```

#### 配完不算完，还得注销

保存完了是不是马上就能用了？**不行。还有一个问题。**

我现在退到上一级目录，在 `/opt` 里写 `go version`，你发现它还是提示找不到。为什么？**因为刚才配的环境变量没有生效，说白了就是系统没有去重新读这个文件。**

怎么办？非常简单——**注销一下。**Ubuntu 里点右上角那个位置有个"注销/登出"，登出过后会让你重新登录一次。**重新登录以后，刚才配的这些东西就都管用了。**

输密码进去，稍等片刻，再打开一个终端输入：

```bash
go version
```

成了。**此时此刻你就可以在任何目录下面使用 SDK 来开发了。**

> **易错点**：**需要注销、重新登录，不需要重启。**有人说需要重启，这是不对的，重新登录一下就行。注销的本质就是让系统去重新读一遍 `/etc/profile`，它就知道里面有新变量了。

关于 Linux 下配置 Go 环境变量就讲到这里。有时间的同学可以花五分钟再过一遍，想一想有没有不清楚的地方。

## 快速入门：一个 hello, world 走通目录、编译和运行
> 对应块：BLK07 | 覆盖分集：P15-P17 | 块标题（分集名）：《015_尚硅谷_Go程序开发和基本结构说明》

环境搭好了，我们来看几个案例，通过案例来学 Go 程序的基本结构和语法现象。

需求很简单：**开发一个 `hello.go` 程序，输出 `hello, world`。**就借这个最经典的程序，把 Go 程序的基本结构看清楚。

### 先把目录结构立起来

在写第一行代码之前，先说开发的一个步骤——**目录结构怎么组织。**程序本身很简单，但目录结构这一步不能糊弄。

Windows 下的开发步骤：第一步，安装 VS Code，这个不说了；第二步，**把 Go 代码写在扩展名为 `.go` 的文件中**。这是约定俗成的，Java 是 `.java` 结尾，C 程序是 `.c` 结尾，Go 就得是 `.go`，大家要遵循这个规范。

那目录怎么排？一般按这种方式：

```text
D:\goproject
└── src                        ← 源代码目录
    └── gocode
        ├── project01          ← 第一个项目
        │   ├── main           ← 一个文件夹就是一个包
        │   │   └── hello.go
        │   └── 其他包...
        └── project02          ← 第二个项目
            └── main
```

读图：**从下往上看——`project01` 是项目，`main` 是这个项目里的一个包，`hello.go` 是这个包里的源文件。**一个文件夹对应一个包，这是 Go 的管理机制。所以我们后面做开发也沿用这种方式。

你不这么建也能跑，程序一样执行，但**既然有规范，按规范来更正规一些。**

具体的操作就是：打开 VS Code，新建一个文件夹叫 `goproject`；在它下面建 `src`；`src` 下面建 `gocode`；`gocode` 下面建 `project01`；再在 `project01` 下面建 `main`。然后在这个目录里新建文件 `hello.go`。

### 这段代码逐行交代

因为这是第一个程序，我讲得细一点，后面就不用重复了。

```go
package main

import (
	"fmt"
)

func main() {
	fmt.Println("hello, world")
}
```

代码不复杂，就那么几行，但每个关键字你都得说得上。

| 代码 | 含义 |
| --- | --- |
| `package main` | 说明 `hello.go` 这个文件**所在的包**是 `main` |
| `import "fmt"` | 引入一个名叫 `fmt` 的包，目的是能用它里面的函数 |
| `func main()` | `func` 是关键字，表示后面是一个函数；`main` 是主函数名，也就是**程序的入口** |
| `fmt.Println("hello, world")` | 调用 `fmt` 包里的 `Println` 函数，输出这句话 |

有几个地方要专门强调。

**第一，`.go` 后缀是约定俗成的**，大家都要这么写。

**第二，`package main` 说的是"这个文件所在的包"。**言外之意是：**Go 程序每一个文件都必须归属于一个包，不能脱离一个包。**这个细节你必须知道。

**第三，`import "fmt"` 的目的是什么？是为了能使用这个包里面的函数。**`fmt` 就是 format 的意思，引入之后就可以用这个包里的函数，比如这里的 `fmt.Println`——`Println` 就是这个包里的一个函数。

**第四，`func main()` 里，`func` 你也不能写全，它是关键字。**它表示后面是一个函数。而 `main` 这个名字是主函数名，是**我们程序的入口**——程序就从 `main` 这地方开始往里执行。

所以整个程序的结构现在应该很清楚了：**包名 → 引入包 → `func` 关键字 → 函数名 → 调用包里的一个函数输出内容。**

### 两种跑起来的方式

写完之后就要跑一把。**先 `cd` 到 `main` 所在的目录**，进 DOS 控制台，`dir` 一看，确实有个 `hello.go`。

**第一种方式：先编译，再运行。**

```cmd
go build hello.go
```

如果代码有错，它会提示错误。这里没发现问题，`dir` 再一看，多了一个 **`hello.exe`**——这就是编译之后得到的二进制可执行文件。然后直接执行它：

```cmd
hello.exe
```

回车，就输出了 `hello, world`。这就叫运行。

**第二种方式：直接 `go run`。**

有些老师在讲课时不编译，直接用 `go run` 执行源码，类似执行一个脚本文件：

```cmd
go run hello.go
```

回车，输出是一样的。但你可以感受一下，**这种方式明显比直接执行慢**。我当时数了一下：直接跑 `hello.exe` 大概一秒就出来了，`go run` 要一秒、两秒、三秒、四秒，四秒才输出 `hello, world`。

**为什么？**因为源码计算机是不能直接执行的。`go run` 在底层同样要把源码编译成二进制码，只是**这个过程被隐藏在指令里面了**。

这两种方式你都可以用，但**真正的工作和生产环境，我们肯定是先编译再执行**。有些老师为了讲课方便才用 `go run`，你别被带偏了。

### Linux 和 Mac：结构一样，跑起来多个 "./"

#### Linux 下开发

Linux 下开发 Go 和 Windows **基本上是一样的**——目录结构一模一样，编译指令一模一样。**就一个地方有区别：运行。**

Linux 下运行可执行文件要用 **`./文件名`** 的方式。你不能直接敲 `hello`，那样执行不好使，必须加一个点：

```bash
./hello
```

**为什么？因为点斜杠代表当前目录**，告诉系统"从当前这个目录下面去找一个 hello 可执行文件"，这样才能执行成功。

流程走一遍：在 VS Code 里打开/新建 `goproject`，照着规范建出 `src` → `go_code` → `project01` → `main`，在 `main` 里写 `hello.go`：

```go
package main

import "fmt"

func main() {
	fmt.Println("hello, go")
}
```

保存。然后打开终端，`ls` 一下找到 `goproject`，进去：

```bash
cd goproject/src/go_code/project01/main
```

`ls` 确认 `hello.go` 在里面。编译：

```bash
go build hello.go
```

代码没问题就编译通过，多出来一个绿色的可执行文件，然后 `./hello` 执行。或者直接 `go run hello.go`，同样能看到输出。

#### Mac 下开发

Mac 下跟 Windows 也基本一样，就是重复一遍：`goproject` → `src` → `go_code` → `project01` → `main` → `hello.go`。

> **提示**：项目名当然不一定叫 `project01`，也可能是 OA、CRM，或者一个众筹项目，看你做什么。

因为我这机器性能内存 CPU 都弱，跑不动两个虚拟机，所以先把 Ubuntu 关掉——`shutdown -h now`——然后再开苹果虚拟机。

代码：

```go
package main

import "fmt"

func main() {
	fmt.Println("hello, atguigu")
}
```

保存、最小化、开终端，进入工作目录，`go build hello.go`，编译成功后 `ls` 看到一个 `hello`，然后：

```bash
./hello
```

输出就出来了。第二种方式 `go run hello.go` 同样可以。

**再说一遍：实际开发环境下肯定先编译再执行，不会用 `go run`，那个只是为了演示方便。**

### 两种执行流程的差别

最后我们把这件事掰开讲清楚，因为**面试的时候面试官有可能问到这个问题。**

```text
方式一：先编译，再运行  ── 快
   hello.go ──go build──> hello.exe (Windows) / hello (Linux、Mac)
                          │
                          └── 直接执行 ──> 输出

方式二：go run        ── 慢
   hello.go ──go run──> [ 编译 ] + [ 运行 ] ──> 输出
                        ^^^^^^^^^^^^^^^^^^^^^^^
                        编译过程被藏在指令里面了
```

读图：两条路的**输入都是源码**，区别在于编译这一步是显式做还是隐式做。所以**只从"运行"角度看，直接执行可执行文件肯定快**，因为它已经是二进制了。

实际开发中还是应该先编译再执行；`go run` 有时候为了快速看一眼源码有没有变化可以试一下，但不会这么用。

具体有三点区别。

**第一，先编译出来的可执行文件，拷到没有 Go 开发环境的机器上照样能跑。**

你会发现编译生成的文件变得比较大：**Go 源代码其实只有 1KB，编译过后会变成 1.8 兆**。1KB 到 1895 KB，大了上千倍。为什么这么大？因为编译的时候会把这个程序执行所需要的相关文件和资源一起打包/链接进去。

所以你把这个可执行文件直接拷到另一台没装 Go SDK 的机器上，它也能运行。我就在控制台里 `cd` 到 D 盘直接执行 `hello.exe`，输出照样是 `hello, world`。

**第二，直接 `go run` 源代码，那台机器上必须也有 Go 开发环境。**

打个比方：我把 `hello.go` 这个源代码交给你，你想用 `go run` 来跑，那你的机器上也得有 Go SDK，否则它跑不起来。

**第三，编译时，编译器会把程序所依赖的库文件包含进可执行文件，所以可执行文件会变大很多。**这就是刚才 1KB 变 1.8 兆的原因——程序依赖的那些库也被链接、编译进去了。

## 编译、运行与 Go 的语法规矩：从可执行文件的名字到转义字符
> 对应块：BLK08 | 覆盖分集：P18-P20 | 块标题（分集名）：《018_尚硅谷_Golang编译运行说明》

### `go build` 可以指定生成的可执行文件名

编译这个概念刚才大家已经听过一遍了——**把源代码编译成机器可识别的二进制代码，这就叫编译**。大家都清楚编译指令。这里再强调一个前面没讲过的点：通过 `go build` 对 `hello.go` 这种源码进行编译，可以指定生成的可执行文件名。

不指定的话，它默认就以你编译的那个源文件的名字命名。但有些时候你不想用这个名字，那就可以指定。我们拿 `hello.go` 来演示。

先教大家一个进入目录的"绝招"，省得每次 `cd` 来回切那么麻烦：**在编辑器里先用鼠标把目标目录选中，然后直接输入 `cmd` 回车，你就已经在那个目录里了。** 你要进哪个目录，就先把哪个目录选中，一敲 `cmd` 就进来了，是不是比每次 `cd` 简单得多？

在这个目录里输入 `dir` 看一眼，现在文件是 `hello.go`。接下来我们想生成一个可执行文件，不叫 `hello.exe`，比如叫 `myhello.exe`：

```bash
go build -o myhello.exe hello.go
```

> **易错点**：`-o` 后面指定的名字，**后缀必须是 `.exe`**。这是它的一个要求，如果后缀不是 `.exe`，后面是没法执行的。

回车之后我们再输入 `dir`，你看，目录下就生成了 `myhello.exe`。原来那个名字没了，现在是这个名字了。而且它照样能执行：

```bash
myhello.exe
```

一样能跑出我们的 Hello World。**记住 `go build -o` 这一个指令就够了。**

### 编译的时候它会给你什么反馈

**程序没有错误，编译的时候就不会有任何提示。** 静悄悄的，不吭声。

**有错误呢？有错误在编译的时候会在错误的那一行报错，这有助于我们程序员排错。** 我故意写错一处给你看——把 `println` 的顺序故意颠倒，写成 `printnl`。这个 `nl` 在这里肉眼看不出来，但函数肯定错了。写错之后保存，编辑器这边其实就已经提示 `undefined` 了。不但这里会提示，编译也会提示。我们把它再编译一次，这次不指定文件名，让它默认就行：

```text
hello.go:7:8: undefined: fmt.Printnl
```

意思是 `hello.go` 在第七行有一个 undefined 的函数 `fmt.Printnl`，说明它没有定义过。所以如果同学们在编译的时候发现有这种错误提示，就应该快速定位咱们代码是在哪里出错了——**报错行号加上那个未定义的名字，程序员看到就能快速把错误调试出来。**

顺带说一句刚才我用的快速复制代码的快捷键：**`Shift + Alt` 加向下箭头是向下复制一行，加向上箭头是向上复制一行**。后面我这里会专门讲，会有一份 VS Code 快捷键大全的资料分享给大家，想快速执行一些命令的，里面都有，后面讲到的时候再好好说一说。

还有一点要注意：**如果在 Linux 下面编译，生成的可执行文件就不是 `.exe` 了。** 在 Linux 或者 Mac 下面生成的是一个二进制码文件，同样也是可以执行的。前面给大家演示 Linux 和 Mac 开发程序的时候已经讲过这个东西了。

```text
   hello.go  ──go build──▶  hello.exe     Windows：带 .exe 后缀
   hello.go  ──go build──▶  hello         Linux / Mac：没有 .exe 后缀，
                                              但同样是二进制码文件，同样可执行
```

### 运行的两种方式

运行有两种方式。

一种是**直接运行生成的可执行文件**，比如 `myhello.exe`。

另一种是**直接通过 `go run` 对源代码文件进行运行**，`go run hello.go`，这样也可以。

两者的区别在前面讲 Go 执行流程的时候已经讲过了，这里就不再多说了。

如果觉得字体比较小，可以调整字体的大小，我顺便简单演示一下怎么调整。VS Code 跟传统的 IDE 工具调整参数还不太一样，感觉有点怪，但适应了就好了。

路径是：**点"文件"，里面有一个"首选项"，点击"设置"**。点进去之后，你会看到它的常用设置全部是以文本的方式列出来的，其中有一个就是改变字体大小。

比如想去修改源码管理，点击之后选项会变到这边来，在这边改了之后，就相当于把设置的值改变了。跟传统的编辑工具有点不一样：以前的传统 IDE 是弹出一个对话框让你选，但是 VS Code 并不是这样。以"控制工作台活动栏是不是可见"这个选项为例，看到这里有一个小笔，点击编辑，点击 `true` 或者 `false`，一改这就改了；再点编辑改回 `false`，又改回来了，它就是这样修改的。如果用惯了传统工具，可能会感觉比较奇怪。

### Go 程序开发需要注意的七点

接下来这块是个重点。对于我们 Go 语言的初学者来说，有些细节、容易疏忽的地方，我要特别地强调一下。我总结了这么几点，大家看一看。

**Go 源代码是以 `.go` 扩展名结尾的。** 有同学问："老师，我如果非要以别的结尾，会有什么后果呢？"我们看一下：新建一个文件叫 `test.abc`，把这段代码复制过去——首先它就已经不变色了，因为编辑器认为你这个不是 Go 程序，所以它不高亮。第二个，你编译也编译不过去：

```bash
go build test.abc
```

它直接提示 `unknown`，说不知道这是什么玩意儿，无法进行编译了。所以这就要求我们**必须以 `.go` 后缀**，这是它的一个硬要求。

**Go 应用程序的执行入口是 `main` 函数。** 这里我特意强调一下：尽量叫"函数"，不要叫"方法"，因为在 Go 里面方法和函数是有区别的，它们很像，但也有区别。程序最终执行的时候，是从这个 `main` 函数往里面执行的，从这个地方开始作为入口。这一点跟我们的 Java 程序、我们的 C 程序是一模一样的。

**Go 语言是严格区分大小写的。** 比方说我们这个地方有一个 `println`，这个 `n` 是小写的，你就不能大写。我故意把它大写一下，大家注意看，这边立刻就标红了，它说 `undefined`，这个函数没有定义过。也就是说它的函数名是区分大小写的。有些语言是不区分的，但 Go 区分。

**Go 方法是由一条一条语句构成的，每个语句后面不需要加分号。** 为什么不需要？因为 Go 语言**会在每行后自动加分号**。这就体现出 Go 程序的设计者认为：既然你每句话都要加分号，那干脆我编译器帮你加，你就不要再加了，体现出它的一种简洁性。你加了也能用，保存、编译、`go run` 它也都能跑，也没什么毛病，但这种方式就显得不专业了。因为 Go 本身默认就会在每个地方给你加一个分号，你又去加一个，有点画蛇添足，没有必要。所以同学们，记住在 Go 语言里面每个语句后面不需要加分号，不需要加，你就别加就行了。

**Go 编译器是一行一行编译的，因此我们一行最好就写一条语句，不能把多条语句写在同一行，否则会报错。** 比方说我们以前写代码，假设有两句话，我们这样写在同一行。如果是在传统的编程语言里面，只要是符合要求的，它也不会报错，对吧？但是在 Go 里，我一保存它就提示语法有问题。就是说咱们一行就写一条语句，不要把多条语句放在一起写。为什么呢？因为 Go 语言就是行行编译的，记住这个规则就行了。

**Go 语言定义的变量或者 `import` 包如果没有用到，代码不能编译通过。** 这一条也是 Go 语言跟很多其他编程语言不一样的地方。如果在 Java 里边，你 import 一个包，引了但没有用到这个包里面的方法或者函数，它最多警告你一下。但是在 Go 语言里面，它认为既然你引了，你又没有用，那我对不起你，你就不能通过，编译就不能通过。

我引了一个 `fmt` 这个格式化包，但是里面一句话都没写，你看它就报错了：

```text
imported and not used: "fmt"
```

说你把这个包引进去了，但是你没有用过，那它就不让你通过。它这个就不是警告了，它直接就让你跑不起来。假设你有两个包、三个包，只要有一个包没有用到，你这个代码就跑不过去。变量也是一样：

```go
var num = 10   // 声明了却没用
// 报错：num declared and not used
```

> **结论**：Go 语言里，你只要声明了东西，就一定要用一下。你不用，它就认为你这是吃饱了没事干，直接不让你过。

因为这个其实也有它的道理，经常做开发的人都有这样一个小毛病：这段代码可能是张三写了一段时间，李四又接着写。张三定义了一些变量或者引了一些包，李四不知道有没有用，就不敢乱动。结果代码里面就留下了一些变量和包，其实早就不要了，但是还保留在程序里面。它们在编译和运行的时候也会参与，所以说会对我们代码的性能造成一定影响。所以 Go 语言的设计者就干脆强制性地要求一句话：**你定义了的或者声明了的东西，那你就必须要用，你不用，我就让你过不去。** 这既体现出它的简洁性，也体现出它强制要求我们风格统一的一个特点。这是 Thompson 他自己在设计的时候就这么设计的。

**大括号要成对出现，缺一而不可。** 这点是我们所有的编程语言都需要的，不管是 Go、PHP、.NET，还是 Java、C，都是一样的，它不是 Go 的一个特点。但是对初学者来说容易忘。你比如说少写一个大括号，这个地方它就会报错，它也会提示你。我把 `fmt` 那个例子先用一下：

```go
fmt.Println("hello")
```

我只要用了一次 `fmt`，它就不会报错了。大家看，假设我的代码有很多行，那么这一对大括号、这个大括号和那个大括号，它要匹配，就是你不能突然少了一个大括号。我们写代码的时候，有时候代码特别长、这个文件代码特别多，那就有可能你会忘掉，忘掉了过后，你的编译就不能通过。

> **提示**：这七条里，"一行一条语句"和"不许声明了不用"这两条是 Go 最特色的，也是新手最容易被编译器卡住的地方；其余几条别的语言也要求，但同样容易疏忽。大家在做开发的时候一定要特别注意我提到的这些点，别写的时候太随意了，后面讲课的过程中我们还会逐渐地加深。

### 转义字符：五个常用的

下面我们继续学习一下 Go 语言里面的转义字符。**为什么要学转义字符呢？因为后面我们用 Go 语言编写程序的时候，会涉及到转义字符的使用。**

转义字符用英文来说就是 escape char。Go 语言常用的转义字符主要有五个：

| 转义字符 | 含义 | 用途 |
| :--- | :--- | :--- |
| `\t` | 制表符 | 排版、对齐 |
| `
` | 换行符 | 输出完换到下一行 |
| `\\` | 反斜杠 | 输出一个真实的反斜杠 |
| `\"` | 双引号 | 在字符串里输出双引号 |
| `\r` | 回车 | 回到当前行行首覆盖输出 |

所谓"转义"是什么意思呢？指的是第一个斜杠表示转义。如果没有这个斜杠，`t` 就是一个字母 t；有了斜杠，`\t` 就变成了制表符——**斜杠代表一种转义**。

先安排一下项目的结构。我们在讲课的时候是按照章节来讲的，比如现在讲的是第二章，就建一个新的文件夹，把它当做一个项目，也就是**每一个章节建一个目录**。在当前工程中新建一个文件夹叫 `chapter02`，在 `chapter02` 里面，我们讲每一个案例，再建一个子文件夹，把我们的文件写到这里面去，这样比较好找。所以我们新建一个文件夹作为转义字符的案例，叫 `escapechar`，然后建立文件 `main.go`。

```go
package main

import "fmt"

func main() {
    // 演示转义字符的使用
    fmt.Println("tom\tjack")
}
```

`fmt` 这个包主要提供格式化、输出、输入的函数。

比如我在这里写了 tom jack，我希望它中间有一个制表符。我们来运行一下，看有这个斜杠和没有这个斜杠区别在什么地方。我们 `cd chapter02/escapechar` 进到目录里，查看一下里面有一个 `main.go`，然后直接运行：

```bash
go run main.go
```

输出的是 tom、若干空格、jack。如果这里没有斜杠，就会直接输出一个字母 t。**带上斜杠就代表转义，`\t` 就代表制表符 table。**

**换行符 `
`。**

```go
fmt.Println("hello\nworld")
```

`
` 代表换行，也就是输出 hello 之后换行，再输出 world。执行之后，确实是在 hello 之后换行输出了 world。

**输出反斜杠 `\\`。** 比方说这里有一个路径：

```go
fmt.Println("D:\\GoWorks\\src\\...")
```

如果直接输出单个斜杠，编译器会报错，提示 character escape 有问题，因为它不知道单个斜杠是什么意思。如果想把斜杠输出出来，因为单个斜杠会被当做转义符，所以需要写两个斜杠：**第一个是转义符，第二个才是真正要输出的路径分隔符。** 加上之后运行，输出的就是单个斜杠——第一个斜杠用来告诉编译器，后面的斜杠当作普通字符输出。

**双引号 `\"`。** 比方说我们假设要输出这样一句话，想把内容用双引号引起来：

```go
fmt.Println("tom说:\"I love you\"")
```

有时候我们希望输出的字符串里面带有双引号，如果直接写双引号，会导致语法解析错误。老规矩，使用转义符 `\"`。运行之后，就会把双引号输出出来：`tom说:"I love you"`。

**回车符 `\r`。**

```go
fmt.Println("天龙八部雪山飞狐\r张飞")
```

运行一下看看效果，输出的内容是：`张飞八部雪山飞狐`。

> **提示**：为什么不是"天龙八部雪山飞狐张飞"呢？原因是**回车代表先输出前面的内容，回车之后不换行，而是从当前行的最前面、顶头开始输出后面的"张飞"，覆盖掉以前的内容。**

在输出张飞的时候，张飞就会在当前行最前面输出，替换掉以前的内容。替换掉谁呢？替换掉"天龙"——因为"张飞"刚好也是两个汉字，就把你替换了，对不对？那如果说是"张飞厉害"，那会怎么样呢？"张飞厉害"就会替换"天龙八部"这四个，因为刚好四个字。再长一点就替换不动了，剩下多出来的字符会照样留在后面。这也就是"替换"的效果。

### 课堂练习：用一句话输出姓名、年龄、籍贯、住址

明白转义字符过后，我们来做一道课堂练习：**请用一句话输出姓名、年龄、籍贯、住址，然后用 John、12、河北、北京。要求是用一个输出语句，一句输出语句，不能给我出多个——我出两个那就不行，我们要一个语句。** 大家先想一想怎么做，给大家五分钟练习时间。

我们直接看代码怎么写。首先我们看"姓名 年龄 籍贯 住址"，这是一句话吧？中间用什么来间隔呀？用我们的制表符 `\t`；然后要换行，用 `
` 就可以了，是不是还是很简单的？我们新建文件 `exec01.go`，写成这样：

```go
fmt.Println("姓名\t年龄\t籍贯\t住址\nJohn\t20\t河北\t北京")
```

首先是姓名，然后 `\t`；年龄，然后 `\t`；籍贯，然后 `\t`；住址。然后不要输出第二句话，马上换行 `
`。然后是 John，再一个 `\t`，年龄，再一个制表符；然后籍贯是河北；再 `\t`，住址是北京。这句话就写完了。

直接运行的时候我们却发现有问题了——你看代码有毛病没有？什么原因？

```text
main redeclared in this block
```

**我在这个文件里面有个 `main`，在这里面又有一个 `main`，这就出问题了。** 因为你现在 `exec01` 和 `main` 都在同一个文件夹下面，其实它是属于同一个包的。你看你是 main 包，这也是一个 main 包，在同一个包下面你有两个 `main` 函数，这就会提示重复定义。

怎么办呢？好办：**遇到这种情况，我们必须要重新来一个包。** 但是在 Go 语言里面它要求，如果你的函数是 `main` 函数，就必须在 `main` 包里面，所以说这个时候我们没有办法——你不能说换一个包，换一个包也不好使。咱们只有**重新建一个文件夹**，也就是重新建一个包。如果你学过 Java 的话，就好比说咱们在同一个包里面不能有重名的，道理是一样的。

所以我们新建一个文件夹叫 `exec`，`package` 这个练习的包，然后把 `exec01.go` 移到这个文件夹里面去。这时候你的 `main.go` 和 `exec01` 这两个文件就不在同一个文件夹下面了，它们所在的包自然也不在同一个包了。虽然都叫 `main`，但这个就不影响了，保存一下就没毛病了。

哎，为什么它还在提示呢？我们来看看这是什么原因。其实这个地方是没有毛病的，保存确实又不报错了。这是因为**编译器有时候它不是想的那么智能**——它好像没感觉到你把文件挪过来了，还把以前那个错误给保留下来。所以你把这个文件稍微改一下、动一下它就能变化了。比如我把这个地方的名字改一下，稍微改动一下再保存，你看这就没错了吧。就这个编译器有时候有点傻，你稍微把这个文件动一动，然后再一保存，它就没毛病了，明白这意思吧？

那我们现在再来运行一下这段代码。切换到 `exec` 目录下 `dir`，我们进到 `package` 里面去，运行 `go run exec01.go`，跑起来。此时此刻我们发现它输出的内容就跟我们想的是一样的了。

### 本讲提到的题目

#### 题目

用**一个** `fmt.Println` 语句，输出下面这样的两行表格效果：第一行是表头"姓名　年龄　籍贯　住址"，第二行是"John　12　河北　北京"。字段之间要求对齐。

#### 解析

表头和数据之间的列要"对齐"，靠的就是制表符 `\t`；两行之间要"换行"，靠的就是 `
`。这两件事在 Go 里都是靠转义字符完成的——制表符 `\t` 会让终端跳到下一个制表位，自然就形成了列的视觉对齐；`
` 让输出从下一行行首继续。

还有一个坑是新手最容易踩的：**不要用两个 `fmt.Println` 分两行输出**。题目明确要求一个语句，那么整个"表头 + 换行 + 数据"必须写进同一个字符串字面量里。

#### 答案

```go
fmt.Println("姓名\t年龄\t籍贯\t住址\nJohn\t20\t河北\t北京")
```

> **注意**：把这个文件放到自己新建的练习包目录（比如 `chapter02/exec`）里去，不要和原来的 `main.go` 放在同一个文件夹，否则会因为同包内重复定义 `main` 函数而报 `main redeclared in this block`。

### 找不到文件：先怀疑文件名和路径

初学 Go 的时候，最先拦住你的往往不是逻辑问题，而是这么一行：

```text
The system cannot find the file specified.
```

系统找不到指定的文件。再往前走一步，当你想去执行一个可执行文件时，它可能反过来告诉你"xx 不是内部或外部命令"。这两条看起来不一样，根子却是同一个：**你的文件名不存在、文件名写错了，或者路径写错了。**

我们现场演示一下。比方说我本来应该是 `go run` 一个 `exec01.go`，手一抖把 `01` 掉了，写成了 `exec.go`。一执行，立刻就是那句经典的 `The system cannot find the file specified.`。

编译也一样。我们先编译：

```bash
go build exec01.go
```

编完之后 `dir` 一下，能看到生成出来的 `.exe` 文件。正常情况下直接运行它就起来了。但只要文件名或者路径写错一个字符，它同样会告诉你"不是内部或外部命令"。碰到这种情况，不用怀疑人生，老老实实去核对文件名和路径。

> **结论**：遇到"找不到文件"或者"不是内部或外部命令"，第一件事是检查文件名和路径，不是检查代码。

### 语法错误：那个把 l 写成 1 的 Println

学编程，尤其是刚学编程的时候，最容易犯的就是语法错误。

最经典的一种，就是 **数字 `1` 和小写字母 `l` 长得太像，分不清楚**。上课的时候我们经常发现有人把 `fmt.Println` 写成：

```go
fmt.Print1n
```

上面那个是小写字母 `l`，下面那个是数字 `1`。就差这一点，编译器可不认。

我们保存一下、编译一下，看看会发生什么。运行之后，编译器会告诉你，Go 的**第 6 行**有个 `undefined`。但是——请注意这个"但是"——它**不会明确告诉你说是 `l` 和 `1` 写错了**，它没那么智能。

> **提示**：如果说编译器真有这么聪明，那我们程序员就没有存在的价值了，对不对？任何一个人都能编程了，它都告诉得这么清楚。正因为它不告诉，这一行才只能由你自己来看。

所以 Go 要求我们必须按照语法规则写代码：忘记了大括号、引号没闭合、单词拼错了，编译器都会给你报语法错误。遇到它，别跳过，别硬着头皮往下写，**一定要试着看懂它报出来的那行错误信息**。

#### 错误信息其实只给了两样东西

很多人一看红字就慌，其实错误信息好读得很，它主要就两部分：

```text
.\main.go:6:2: undefined: fmt.Print1n
└─ 行位置 ─┘  └─ 原因 ─┘
```

前面那个数字很重要，一般来讲它告诉你错误在第几行——**第 6 行错了**；后面那段文字告诉你**为什么错**。就这么两样信息，一般的程序员都能把问题搞定。

把代码改回来，保存，错误就没了，OK。

> **易错点**：一定要学会看错误信息，而且**不要怕**它。看一眼错误信息，这个问题很快就解决了。这是编程过程中特别需要小心和注意的地方。

### 注释：写给一年后的自己，也写给下一个读代码的人

现在我们聊一聊 Go 语言里的注释，也叫 comment。

#### 注释是为了什么

写一段代码、做软件开发的时候，我们往往会配一段文字说明，目的是提高代码的可读性。

有些人的代码写得很长、写了很久。如果这段代码没有注释，等到一年以后、两年以后再回头看，他几乎不知道自己当初写的是什么了。

**注释是一个程序员必须养成的良好编程习惯。** 先把自己的思想通过注释整理出来，再用代码去实现，这本身就是很好的做法；另外一个好处，是让别人看你的代码时能轻松一点。

你可以想象一下，如果每个人都不写注释，那这个问题就严重了。我们去翻 Go 语言的源代码 `src`，随便打开 `fmt` 包里的一个文件看看——高手的代码里全是注释：

```go
// Write is a function to call to emit formatted output to be printed.
```

这句话的意思就是"这是一个函数，用来调用、输出、格式化输出"。你翻源码的时候，人家连这个都写得好好的。所以我们做开发也要养成写注释的习惯，这将来对大家的职业发展也是有好处的——参加工作以后，如果你的代码里一行注释都没有，你的项目经理一看就觉得你这个人不行：要么不负责任，要么根本没有良好的编程习惯，人家就会看不起你，或者对你有意见。

> **结论**：多写一点注释，这既是技术习惯，也是职业习惯。

#### 行注释：两个斜杠

Go 里的注释主要有两种，一种叫**行注释**，一种叫**块注释**（也叫多行注释）。

行注释的基本格式就是写两个斜杠，然后是注释文字：

```go
// 这是注释内容
```

我们拿刚才写的代码来演示。比方说我运行 `main.go`，它会输出六句话（1、2、3、4、5、6）。现在我不想让其中三句执行了，怎么办？直接给它们加上行注释：

```go
// fmt.Println("hello")
// fmt.Println("world")
```

前面加两个斜杠就注释掉了。保存之后再运行，你会发现被注释的那几句已经不生效了，只剩下 Tom、Jacky——注释掉的代码就不工作了。

手一行一行加斜杠太慢，我们有快捷键：**选中这几行，按 `Ctrl + /`，一键注释**。注释完还可以顺手写点说明，比如：

```go
// 这是一个 main 函数，是程序的入口
```

> **提示**：`Ctrl + /` 第一次按是注释，再按一次就是取消注释。想一次性注释多行的时候特别好用，大家注意一下。

#### 块注释：一把注释一大片

块注释的语法是 `/*` 开头，`*/` 结尾，中间是注释内容。上面那几行也可以用块注释一把包住：

```go
/*
fmt.Println("hello")
fmt.Println("world")
*/
```

#### 两条使用细节

**第一，一旦被注释了，被注释的文字就不会被 Go 编译器编译执行**，这句话就不生效了。

**第二，块注释里面不允许再嵌套块注释，不能嵌套。** 这个是重点。

为什么不能嵌套？你可以想象编译器是怎么理解的：`/*` 匹配到**第一个** `*/` 就截断了。中间那个 `/*` 已经被当成注释内容的一部分吞掉了，于是你下面那个 `*/` 就再也找不到配对的 `/*`，程序立刻报错——你会看到下面一堆代码全变成了错误。

> **易错点**：块注释不能嵌套。这一点以后写长代码时特别容易栽跟头，记住它。

### Go 的代码风格：这门语言只给一种写法

要写出规范的代码，有几个地方需要掌握。

#### 尽量用行注释

Go 官方推荐：**尽量使用行注释来注释整个方法和语句**。

我们把 Go 的源代码往下拉一拉就会发现，那些注释几乎全是行注释，很少看到块注释。所以我们也可以借鉴它，尽量用行注释来给代码作注释，这点知道就行。

#### 缩进和空白：Tab、Shift+Tab 与 gofmt -w

第二点，要有正确的缩进和空白。

有些同学代码不缩进，所有东西死死地堵在一起，看着非常不好看。正确的缩进看起来就清楚多了——选中这一段文本按 `Tab`，整体缩进，代码立刻清爽起来。

具体怎么操作？假设某段代码顺序有点乱了：先把它们全部选中，然后按 `Shift + Tab` 整体向左移动；移动到位了以后，再按 `Tab` 整体向右移动。就这样——**按一次 `Tab` 整体向右，按一次 `Shift + Tab` 整体向左**。

不想手动调？有第二招，叫 `gofmt` 命令：

```bash
gofmt main.go
```

执行一下，你会看到终端里打印出来的内容已经不乱了，明显对齐了。但是——**文件本身没有变化**。为什么？因为这样写只是把格式化后的内容**输出**出来，并没有真正写回文件。

要真正写回去，得加上 `-w`：

```bash
gofmt -w main.go
```

这个才是"把格式化后的内容重新写入到文件"。写进去以后我们把文件重新打开一看——对齐了。

> **易错点**：`gofmt main.go` 只是打印结果，`gofmt -w main.go` 才会真正格式化文件。这两个指令一定要分清。
>
> **结论**：`-w` 这个指令可以把格式化后的内容重新写入文件，程序员重新打开该文件时看到的就是新的、格式化过的样子，这才是我们想要的效果。

#### 运算符两边各加一个空格

我们习惯性地在运算符两边各加一个空格。比如要写 $a + 4 \times 5$，加号和乘号两边都要留空格：

```go
var number = 2 + 4 * 5
```

你去翻 Go 的源代码，会发现它几乎也是这样写的——输个加号，它的运算符也是这么带空格的。照着这个习惯写，代码会清晰很多。

#### 大括号必须留在函数名那一行

这条是 Go 语言**不允许**的写法，大家要注意。我们以前学的其他语言——Java、C、PHP 等等——都允许把大括号另起一行，但在 Go 里不允许。

```go
func main() {

}
```

这样写没问题。但你一旦换成换行的写法：

```go
func main()
{

}
```

代码立刻报错——它说你没有方法体。

> **定义**：Go 语言的设计者有一个思想：**一个问题尽量只有一个解决方法**。有些人喜欢这么写，有些人喜欢那么写，结果搞得好像有两种风格、没有标准。Go 不接受这件事，所以干脆强制你只能写一种，你想写另一种，它也不允许。这样风格反而统一了，程序员之间也不用为了"到底该这么写还是那么写"扯皮。

所以这条没什么好犹豫的：**遵守规则就行**。

这也教给我们一种学编程的方式——我们始终是在考虑别人怎么思考，而不是我们自认为应该怎么样。设计者就是这么设计的，我们就照着来。

#### 一行不超过 80 个字符，超了就用逗号换行

Go 语言建议**每一行不要超过 80 个字符**，超了就要用换行来展示，尽量保持代码的优雅性。

比方说我们输出：

```go
fmt.Print("hello world")
```

假设这句话特别长、后面还要一直接下去，你就不要死劲地往后面写——你自己看着都难受，怎么办？换一行。但直接换行还不好使，得换个方式。

方法是：**打一个逗号，然后换一行**；还有就接着再打一个逗号，再换一行；到最后一段用分号收尾，再换行。看一下形式是这样：

```go
fmt.Println("一句很长的话",   // 逗号，然后换行
    "再接一句",              // 继续逗号，继续换行
    "最后一句")              // 到这里收尾
```

这个逗号有点类似于我们以前用 `+` 号把输出内容连在一起的感觉。跑一下，输出还是一整坨，完全没有影响。

> **提示**：如果你是想**输出的时候**换行，那还得靠转义字符 `
`。也就是说：源码里的换行用逗号处理，输出结果里的换行用 `
` 处理。这两个换行不是一回事，别搞混。
>
> **结论**：一行最好不要超过 80 个字符，尽量保持代码的优雅性。

### 一份清单：这一讲真正要记住的东西

Go 开发中常见的问题和解决方法，归纳起来就这么几条：

- **文件名或路径错误**：报错是 `The system cannot find the file specified.`，或"不是内部或外部命令"。改对文件名和路径就行。
- **语法错误**：尤其是数字 `1` 和字母 `l` 分不清。一定要学会看错误信息，不要怕——它给你的就是"第几行"和"什么原因"两样东西。
- **注释**：尽量用行注释；块注释不能嵌套；被注释的代码不参与编译。
- **缩进与空白**：`Tab` 向右、`Shift + Tab` 向左；或者用 `gofmt -w main.go` 真正格式化。
- **运算符两边各加一个空格**。
- **大括号写在函数名的同一行**——Go 只给一种写法，一个问题只有一个解决方法。
- **一行不超过 80 个字符**，用逗号换行；输出换行用 `
`。

把 `Ctrl + /` 记牢了，多写注释，把错误信息看明白，剩下的都是照着写的事情。

### 官网、Tour 与 Packages：官方手册该怎么翻

Golang 的官方网站是 golang.org。这个站点有个现实问题：**经常会被屏蔽掉**。你要看到它，一般来讲得先翻一下墙；不会翻墙的话，那就看不着。

不过这个网站做得其实相当不错。它的首页有吉祥物，还有一段示例代码，你点一下 **Run**，它就运行给你看。也就是说，你既可以看效果，也可以自己改代码，通过这个网站来学 Go。

#### Run 一下你就知道它是怎么跑起来的

点进 **Tour**，进入官方手册，一上来就是一句 "hello world"。这块可以格式化、可以运行。你把"你好世界"改成 `abc`，再点一下 Run，结果就出来了；你也可以拿它做运算，比如：

```go
var number = 1 + 2
```

然后把这个结果输出出来，点 Run，页面上就显示等于 3。代码写得很乱也不要紧，点一下 **Format**，它给你格式化成漂亮的样子。

> **提示**：这背后的原理其实一点都不玄。如果你学过 Web 编程就明白了——**它把文本框里的内容发给后台服务器，后台服务器把这段代码执行一遍，再通过 HTTP 协议把结果返回给页面渲染出来**。所以你看到的每一次 Run，都是一次真实的编译和执行。

用不用得上这地方，取决于你的英语水平。英语足够好的话，你可以在这里面做各种各样的测试，一边试一边学。

#### 手册写得太简略，谁该用它

进 Tour 之后，第一步要点语言：点"下一步"，选**简体中文**，手册就被翻译成中文了；下面再点一次"下一步"，还是选"简体中文"。

进去之后你会看到左边有一大串目录：基础、包、变量、函数，还有方法、接口。比如你想知道包是干什么的，点"包"；想了解函数，点"函数"；想了解接口，点"接口"。这些条目其实就相当于整本手册的目录。

但这个手册有个特点必须说清楚：**它写得非常简单、非常粗犷**。

所以它适合谁？适合**你本来就有编程经验**——你学过别的语言，通过这份手册上手会相当快。如果你是个零基础，拿这份手册学起来就吃力了。

> **结论**：有这份手册总比没有的好，所以我在后面讲课的过程中也会适当地带着大家查一下它。包里、函数、变量这些条目，我们都要讲；有时候我也想让大家看看**官方是怎么定义一个包的**——我就直接把这个手册拉出来。

#### 一路点到 fmt 的 Println

除了 Tour，官网还有一个入口叫 **Packages**，点进去全是 API。

为什么这里全是 API？因为**Go 语言是以包的形式来管理函数和文件的**。所以你在这里可以按字母顺序找到你想了解的那个包。

以 `fmt` 为例：你在搜索框里打 `fmt`，直接定位到这个包；不喜欢搜索的话，也可以顺着字母顺序往下找，`f` 打头的那一栏就有它。点进 `fmt` 之后，再点 **Index**，这里就是这个包里所有的方法。

我们之前用过的 `Println` 就在列表里。点它一下，它就告诉你这个函数是干什么的。**如果你英文足够好，就可以很轻松地学会一个函数怎么用。**

#### 文档读不懂？三招都能救

**第一招，百度翻译。** 把这一段英文复制过去，点翻译，就能看到中文结果。比如 `Println` 那段翻译过来大概是"打印格式使用其操作数的默认格式，并写入标准输出……"。这个翻译肯定不是百分之百准确，但至少给英语不太好的同学提供了那么一点点提示，总比没有好。

**第二招，直接搜。** 干脆一点，直接在搜索框里打 "fmt Println 的用法" 回车。这地方有专门的人在回答——很多中国人也在学 Go，他会告诉你 Golang 里 `Println` 和 `Printf` 的区别，会介绍 `fmt` 的各种用法，而且介绍得非常详细。

**第三招，靠自己的脑子。** 学习的方法很多，只要你善于动脑筋都 OK。

> **结论**：查文档这件事，不要怕麻烦，要**灵活地使用各种工具**。英文好就直接读，英文不好就翻译、再不济就搜——三条路都能到达终点。

### 什么是 API：说白了就是各个包里的函数

有些初学者对 API 这个词不太清楚，我把它说得再直接、再明白一点。

> **定义**：API 是 Application Programming Interface 的缩写，叫**应用程序编程接口**。听起来很高大上，但说得更直接一点——**它就是 Go 各个包下面的各个函数**。

我们前面写程序的时候其实已经用过 API 了，就是 `fmt` 包下面的 `Println`：我们引入了这个包，包里的 `Println` 就是一个函数，这样的函数就可以看成一个 API。它有很多，统称为 API。

这个文档是干什么用的？它是用来**告诉开发者怎么使用这些标准库**——标准库里面包含哪些方法、也就是哪些函数，该怎么调。

因为 Go 提供了大量的标准库，所以谷歌公司也为其提供了相应的 API 文档。

#### 国内的中文文档站

刚才那个文档好是好，但有两个门槛：**第一要能上网，第二要能翻墙**。这就麻烦了。

所以国内还有一个网站，也提供了**中文版**的 Go 标准库 API 文档——**studygolang**，只要能上网就行，不需要翻墙。

用它查 `fmt` 舒服得多。它会告诉你：**`fmt` 包实现了格式化 I/O 函数，类似于 C 的 `printf` 和 `scanf`**。这一句话下去，学起来压力就小很多了——这个包实现了什么、格式化、I/O 函数、又像 C 里的哪两个方法，一目了然。再点进去更漂亮，各个方法的参数和使用都做了中文解释。

比如查 `Println`，它会告诉你：结果会写入**标准输出**（也就是我们的控制台），并返回**写入的字节数**和遇到的任何错误。有了中文解释，学 API 就是事半功倍。

大家可以想想：如果有一天所有编程语言的文档都是中文写的，你学起来该有多方便？现在中文解释给了我们之后，那种"压力突然小很多"的感觉，就是这个道理。

#### 连网都上不了？用离线文档

连网都上不了也不要着急。资料文件夹里有一份我下载好的**离线版本 API 文档**，打开以后同样可以查看各个包的内容，有说明、有 index，点任何一个函数都能到位。唯一的缺点是：**它是英文版的。**

#### Go 的源码是可以直接读的

Go 语言有一个特点：**我们这个包的源代码都是可以找到的。**

我们以 `fmt` 为例，一路找过去：先找到我们安装的 Go SDK（在 Program 下面有个 `go`），进去之后有个 `src`，`src` 里面有一个文件夹就叫 `fmt`。注意——**我们的一个包基本上对应一个文件夹**。

那这个包里的函数在哪儿呢？点进去，里面有很多源代码文件，比如 `print.go`、`format.go`，每个文件里就有一堆函数定义。打开一个源文件，你会看到很长，一千多行，你也不用管它。你会看到作者署名和年份——2009 年就写出来了，是 Go 的作者写的。

那我们关心什么呢？比如我很想知道 `Println` 的源码是怎么写的。怎么办？在这个文件里按 `Ctrl + F` 搜 `Println`，回车往下走，很快就找到了它的源代码：

- 上面那一行是**函数的签名**；
- 下面 `Println` 的函数体里，调用的是 `Fprintln`——你想再深一层，就继续往下追。

学过 Java、学过 C 的同学都可以用这个办法，把标准库的源代码追一遍，这样我们对这些函数的理解会清楚得多。

#### 包、文件夹、源文件、函数的关系

我把三者之间的关系画成一张图，这个图非常有指导意义：

```text
  包（逻辑概念）        一一对应        文件夹
      fmt         ─────────────────►   src/fmt/
      bytes       ─────────────────►   src/bytes/
                                           │
                     一个包里有一堆源文件，  │  下面若还有文件夹，
                     说明这个包还有子包      │  就是子包
                                           │
                        ┌──────────────────┼──────────────────┐
                        ▼                  ▼                  ▼
                    print.go           format.go           scan.go
                        │
                        │  一个源文件里又有一堆函数
                        ▼
         Println / Printf / Fprintln / Sprintf ...
```

几点要理解清楚：

- **包对应文件夹**，这是一一对应的关系。包里可能还会有新的文件夹，那就说明这个包下面还有**子包**，这是允许的。
- **一个包对应一堆源文件**，不是一对一。`fmt` 文件夹里除了 `print.go`、`format.go`，还有 `doc.go`、`scan.go` 等等。
- **每个源文件里又有一堆函数**，比如 `print.go` 里就是一堆函数定义。

那么我们要调用一个函数的时候，是怎么调用的？在 Go 里，方式就是**包名 + 函数名**：

```go
fmt.Println("hello")
```

逻辑是这样的：首先你 `import` 一个包，包名肯定要知道；然后使用包里的函数，其实就是 `包名.函数名` 的形式，这样就能用到它了。

> **易错点**：调用的时候**不是以源文件来调的，而是以包名去调**。虽然 `print.go` 里写了 `Println`，但你调用的时候不会写文件名的。
>
> 另外还有前提：这个文件里第一句话必须是 `package fmt`——**必须先在包里声明 `package`，才能用**。测试文件、没有打包的、用不上的，不用管它。

### 顺带补一块基本功：DOS 到底是个什么

有些同学对 DOS 不太了解，对 Windows 的目录结构也不太了解，所以我们花一点时间，讲一讲在 DOS 下怎么操作我们的目录。

#### DOS 是个什么玩意儿

> **定义**：DOS 全称叫 **Disk Operating System**，也就是磁盘操作系统。这是微软最早用的系统，早期比较流行；后来微软出了一个图形界面叫 Windows，Windows 又集成了 DOS。

DOS 是干什么的？它主要能完成哪些功能？我们画一张图来讲清楚它的基本操作原理。

```text
        程序员（人）
             │
             │  敲入 md test200
             ▼
   ┌────────────────────┐
   │   DOS 操作终端      │   ← cmd 打开的黑窗口
   └─────────┬──────────┘
             │  指令
             ▼
   ┌────────────────────┐
   │   DOS 操作系统      │   ← 真正的核心：解析 md
   └─────────┬──────────┘
             │  操作
             ▼
   ┌────────────────────┐
   │   Windows 目录结构  │   ← D 盘、E 盘、F 盘……
   └────────────────────┘
```

这里有个一定要听清楚的点：**你在 `cmd` 里看到的那个黑乎乎的窗口，并不是真正的 DOS 系统，它只是操作 DOS 的一个终端而已。**

我们人，是通过这个终端来发操作指令的；指令发给谁？**不是直接发给 Windows 目录结构，中间有一层 DOS 操作系统。** 它接到指令以后会先解析——比如 `md` 代表什么意思——解析完了，再由它去真正地操作目录结构。

黑窗口是给程序员用的，是人用的；DOS 系统负责解析，这是核心。理解了这三者的关系，你就明白 DOS 的作用是什么，也明白我们学这些基本操作指令有什么意义。

#### 亲手敲一次 md

光看图没感觉，我们实际干一次。

第一种方式是图形化界面：在 D 盘上直接建一个叫 `test100` 的目录，右键、新建文件夹，完事。

第二种方式是**作为一个程序员，我们希望通过终端来操作**——从这个窗口发一条创建目录的指令，交给 DOS 系统，让它帮我们完成任务。怎么做？非常简单：

```dos
md test200
```

怎么建到 D 盘上去？先看清自己在哪个盘：刚才那个目录看不到，是因为我现在在 C 盘。那就先切到 D 盘，再敲 `md test200`。

看，`test200` 出来了。

什么感受？这个目录是我从终端发出 `md` 指令，DOS 系统解析完 `md` 的含义之后，替我把任务完成的。这就是这张图里三者之间的关系。

#### 先把后面演示用的目录结构搭好

了解了原理，我们来看 DOS 常用的操作指令。不过在那之前，得先有个能演示的地方。

我们现在还不知道具体怎么创建，所以**先用图形化的界面建一个目录结构**，之后再来演示 DOS 命令怎么玩。

我们先设计成这样——D 盘是根：

```text
D:\
├── test100
│   └── abc100
└── test200
    └── ok100
```

也就是：D 盘下面建 `test100` 和 `test200`；在 `test100` 里面再建一个 `abc100`；在 `test200` 里面建一个 `ok100`。这几个目录，就是我们接下来演示各种指令的场地。

> **结论**：DOS 的常用指令，做一个普通程序员，**了解就够了**，不是特别重要的知识点。但了解归了解——你不能说我连看都不看，那也说不过去，对不对？

到这里，关于 Golang 官方编程指南、标准库 API 和 DOS 的基本原理我们就介绍完了。作为一个熟练的 Go 程序员，我们要非常熟悉 API，而且要快速学会一种能力：**通过 API 了解一个函数是怎么使用的、有什么特点、接受什么参数**。这也是我们作为程序员必须掌握的能力，我讲课的时候也会带着大家培养这方面的能力。

## DOS 常用指令实战：目录切换、文件操作，以及相对路径和绝对路径
> 对应块：BLK11 | 覆盖分集：P27-P29 | 块标题（分集名）：《027_尚硅谷_目录操作》

好，接着来玩吧。

现在我已经把这两个我们要用的目录建好了，大家看一下这个目录结构：`test100` 下面有个 `abc100`，`test200` 下面有个 `ok100`。也就是说，目前它已经按照我设计的这种方式展现出来了。目录我用蓝色表示，这样大家看起来一目了然——因为待会儿我们还要去创建文件，对不对？

```text
   D:\
   ├── test100\
   │    └── abc100\        ← 目录
   └── test200\
        └── ok100\
```

现在我们就用这个目录结构来演示 DOS 各个指令的使用。

### 指令到底是怎么跑起来的

第一个要给大家演示的是**查看当前目录**。我们现在进入 DOS 了，我输入 `dir` 回车。

你看，当你输一个 `dir` 指令过后，它就会把当前这个 D 盘所包含的目录和文件给你展现出来。这就是 `dir`：**查看当前目录包含的目录以及文件有哪些内容**。

大家看，你从资源管理器里看到的和从控制台里看到的是一模一样的。这就相当于我们通过这个终端发出一个 `dir` 指令——

```text
   你（操作者）
        │  发出指令  dir
        ▼
   DOS（翻译者 / 执行者）
        │  解析指令，返回内容
        ▼
   终端（把结果呈现出来）
```

简言之就是这样子的：**我发了一个 `dir` 指令，发给 DOS 系统，它就会解析 `dir`，解析完了"哦，你是想去看 D 盘下面所有内容"，然后把内容返回给终端，终端把内容展现出来。** 其实 DOS 在这个地方扮演的是一个翻译者和执行者，而你是一个操作者。这个逻辑大家要搞清楚。说白了就是一个 `dir`，也不难。

### 切换到其它盘符

第二个指令，**切换到其它盘符**。

大家要清楚，目前我们在 D 盘下。此刻我的位置在 D 盘，我现在希望切换到 F 盘去。怎么切过去呢？很简单，注意看指令：

```cmd
cd /d f:
```

大小写都无所谓，回车。此时此刻我已经切换到 F 盘了。如果你用这个指令一查，你会发现你看到的东西就不再是刚才的 D 盘内容，而是 F 盘下面的内容。**这个指令大家要记一下，就是切换到某个盘符。**

### 相对路径与绝对路径

第三个指令是**切换到当前盘的其它目录**。这个地方我要给大家介绍一个概念：**什么叫相对路径，什么叫绝对路径。** 作为一个程序员来说，这两个概念是很重要的，我给大家讲清楚。

我们先回到 D 盘来做演示，因为我对 D 盘这个目录结构比较熟悉。回到 D 盘当然还是用 `d:`，回车。

现在我在 D 盘，我想切换到 `test100` 这个目录，怎么写？

```cmd
cd d:\test100
```

回车，我现在就到 `test100` 来了。

> **定义**：**绝对路径**——从当前盘的盘符最上面开始定位。也就是从 D 盘、F 盘、C 盘这样的盘符开始，一级一级找到需要的目录。刚才我写的 `d:\test100` 就是绝对路径。

那什么叫**相对路径**呢？**相对路径就是从当前这个位置开始定位，去寻找对应的目录。** 我举个例子大家一下就明白了。比如现在我的位置在 `test100`，我想到 `abc100` 这个目录去。

用相对路径就这么写：

```cmd
cd abc100
```

为什么？因为我已经在 `test100` 了，而 `test100` 下面正好有 `abc100`，我直接从当前位置开始定位，"哦，下面有一个 `abc100`"，我就过来了。**这个用的就是相对路径。**

如果我要用绝对路径定位，那我就应该这么写：

```cmd
cd d:\test100\abc100
```

因为我是从 D 盘开始一级一级地找。回车，大家看，是不是也过来了？

```text
   当前位置：d:\test100

   cd abc100                      相对路径 —— 从"当前位置"往下找一层
        └──▶ d:\test100\abc100

   cd d:\test100\abc100           绝对路径 —— 从 D 盘根开始逐级定位
        └──▶ d:\test100\abc100
```

大家看这个有区别没有？因为你现在已经在 `test100` 了，你想到 `abc100`，你直接从当前位置开始定位就行；但是如果是绝对路径，它就从 D 盘开始计算。**这个大家要有一个很准确的认识，尤其对我们初学者来说，要注意绝对路径和相对路径到底是怎么算的。**

### 回到上一级目录和根目录

**切换到上一级目录**非常简单。目前我在 `abc100` 目录，我想上到上一级目录去，一个指令就搞定了：

```cmd
cd ..
```

这个 `..` 就代表回到上一级目录。回车，你看，我回到 `test100` 了。非常简单，我就不再多说了。

**切换到根目录**。什么叫根目录呢？所谓根目录指的就是回到它的顶级目录，顶级目录就叫根目录：

```cmd
cd \
```

回车，你看，就回到 D 盘的根目录了。它的顶级目录就叫根目录。这个也是固定的写法，大家记住就行。

> **结论**：关于目录的切换，大家掌握这些就足够的了。**关键是相对路径和绝对路径要搞清楚。**

### 新建目录

目录操作还有几个需要掌握的，就是新建目录和删除目录，这两个在工作中用得比较多。

先看新建目录。我现在在 D 盘，先切换到 `test200` 去玩一玩。大家知道切换到 `test200` 应该怎么写吗？如果用相对路径的话，是不是直接就是 `test200`？如果用绝对路径的话，就是 `d:\test200`，对不对？

在这个 `test200` 里面，我想再建一个目录叫 `ok200`。非常容易，一句话：

```cmd
md ok200
```

这个 `md` 就代表建目录，翻译成英文就是 make directory，它是它的简写。建好了没有？`dir` 你看，是不是有个 `ok100`，还有个 `ok200`？`test200` 里面是不是有了一个 `ok200`？这就是建一个目录。

有些同学问：想一次性多创建几个目录可不可以？**也可以。** 我再建一个 `ok300` 和 `ok400`：

```cmd
md ok300 ok400
```

一回车，两个目录就出来了。**创建多个目录，把目录名用空格隔开就可以了**，创建三个、四个目录直接往后面写就行了。

### 删除目录

下面我们来演示一下删除目录。这个目录你不需要了，怎么删除呢？

**删除空目录**。比如说 `ok100` 这个目录是个空目录，这个比较好删除：

```cmd
rd ok100
```

这个 `rd` 翻译成英文就是 remove directory，稍微懂一点英文的就知道这什么意思了，就是移除掉、删除掉一个目录。一回车，`ok100` 就没有了。

**但是有一个问题：这个指令只能删除空目录。** 比如说我在 `ok200` 里面建一个文件 `abc`，`ok200` 里面就有内容了。现在我还想用刚才那个指令去删除 `ok200`，请看后果——它提示"目录不是空的"。也就是说，如果用这个指令删除非空目录，它是提示错误的，没删掉。

那怎么办呢？如果我们要删除一个目录以及它下面的子目录和文件，有两种方式。

第一种是**不带询问，直接删**：

```cmd
rd /q /s ok200
```

解释一下这两个参数：`/q` 代表不用询问，安静模式——q 就是 query，查询、询问的意思；`/s` 就是层级式的把这个目录以及所有子目录全部删掉。这是一个固定的写法，`/q` 和 `/s` 带上，回车就删掉了。

第二种是**带询问**，把 `/q` 去掉：

```cmd
rd /s ok300
```

删除的时候它会问你：我要删除 `ok300`，你是真删还是假删？因为删除了过后真的就删掉了，所以这个时候你可以选择。选 `N` 就不会删除，选 `Y` 就删掉了。

> **提示**：有些时候不带询问的删除是比较危险的，因为它没有问就直接删掉了。**建议同学们使用带询问的**；如果你确实确定要删，那当然就可以用不带询问的，根据你的实际需要来选择。

### 新建或追加内容到文件

现在我们接着来介绍 DOS 里面对**文件的操作**。我们刚才讲的是对目录的操作，我们有时候也要对 Windows 的文件进行相应的操作。需要给大家讲解的有这么几个：新建或者追加内容到一个文件里面去；复制或者移动这个文件，说白了就是一个拷贝和剪切的过程；以及删除文件。

**先看新建或追加内容到文件。** 现在有这么一个需求：我想在 `abc100` 里面创建一个文件。

注意听，目前我们在 D 盘的 `test200` 这个目录下，我现在想从这到 `abc100` 目录去，然后去创建文件。

有些同学说我不切换行不行？你不切换也可以操作，但是对于我们初学者来说，直接在这里创建文件也可以，只要把路径写清楚就行。第二种方式是先到 `abc100` 目录再创建也行，两种方式都可以。为了让大家学的东西更深入一点，我现在当前在这里，但是我要把文件创建在那边，你看我怎么创建：

```cmd
echo hello > d:\test100\abc100\abc.txt
```

它的指令是这样子的：`echo`，比如我写一个 `hello`，到哪个目录去呢？到 D 盘下面的 `test100` 目录下面的 `abc100` 下面的 `abc.txt`。

**它的意思就是：我要把 `hello` 这个文本写入到这个文件去。如果这个文件不存在就创建，如果存在那就追加。**

回车之后，我们 `dir` 一下——没有？你看看你现在在哪里，你现在在 `test200`，你当然看不到你创建的这个 `abc.txt` 了。为什么看不到？因为你现在在这儿嘛，除非你先切换到那儿去看。我们现在切过去：

```cmd
cd d:\test100\abc100
```

我还是用绝对路径，大家看起来比较轻松一点。切换了，再 `dir`，大家看这边是不是有一个 `abc.txt` 文件？打开看一下，里面就有我们的 `hello`。成功。

如果我就在这个本目录创建文件是不是更容易呢？当然更容易了：

```cmd
echo @硅谷 > abc2.txt
```

这次我写一个叫做 `@硅谷`，写到一个叫 `abc2.txt` 的文件里去。一回车，又产生一个文件，这个文件里面就是 `@硅谷`。**这两种方式大家都注意学习一下：一种我用的是绝对路径的方式来创建文件，另一种我用的是相对路径的方式来创建我们的文件，两种都 OK。**

### 复制与移动文件

有了文件过后，我们现在再来学习一下怎么用 DOS 指令来**复制或者移动文件**。

先看复制文件。我现在有这么一个需求：想把 `abc.txt` 文件拷贝到 `test200` 目录下面来：

```cmd
copy abc.txt d:\test200
```

拷贝 `abc.txt` 文件，然后到哪里去呢？写个绝对路径，写清楚，把它拷贝到 D 盘下面的 `test200`。回车，复制了。找到我们的 `test200`，是不是有个文件了？而且里面应该是有 `hello` 吧？没问题，这叫做拷贝。

拷贝的时候，你也可以指定文件名。假如我不想再叫 `abc.txt` 了，我想叫 `ok.txt`，行不行？也可以：

```cmd
copy abc.txt d:\test200\ok.txt
```

这就相当于拷贝的时候自己重新命了个名，边拷贝边改名。

这就是拷贝的两种方式：**一种是拷贝的时候使用原来的文件名，一种是拷贝的时候重新指定名字。两种方式大家可以任选。**

还有一种叫做**移动**，移动就是我们所说的剪切。在 `abc100` 里面拷贝完了过后，原先的文件还是有的；但是移动就相当于整个把它剪过去了。现在我想把 `abc.txt` 剪切到 F 盘去：

```cmd
move abc.txt f:\
```

它叫 `move`，然后 `abc.txt` 这个文件，我要把它移动到 F 盘下面去。**后面的这个文件名你写也可以，不写也可以**——不写就保持原先的文件名，写了的话就是剪切的同时改名。回车，移动了一个文件。

此刻我们 `dir`，我们发现 `abc.txt` 已经没有了；在 F 盘下面你看，有一个新的 `abc.txt` 文件，就是你刚才剪过来的。这就是剪切，剪切就是移动的意思。

### 删除文件

还有一个就是删除文件。如果这个文件不想要了，你想把它删除，怎么删除呢？简单，一个指令就搞定了。比方说我想把 `abc2.txt` 删掉：

```cmd
del abc2.txt
```

注意，这个命令可以补全：一种方式是一个一个手敲，特别累而且还容易出错；还有一种方式是用 `Tab` 键全部补全，这样比较快。删掉了，再来看 `dir`，没有了。**这就是删除一个文件：`del` 带上文件名就行了。**

同样这个地方我用的就是相对路径，因为我就直接在这个目录下面删的。如果你用绝对路径也可以写得很清楚，比如我要去删 F 盘的一个文件，我也可以在后面把这个路径写清楚，也能把它删掉。

那如果**删除所有文件**呢？就直接改一个指令：

```cmd
del *.txt
```

它也可以用星号。`del *.txt` 就是说把所有 `.txt` 后缀的文件全部删掉。这个我就不演示了——找不到是因为我目前下面一个文件都没有，所以它提示找不到；如果有的话就会全部删掉。

> **注意**：**不要轻易使用这个指令，一旦删掉过后文件就真的没有了。** 有些同学在用的时候很随意，工作很随意，他就写个星号，结果把文件全都删掉了。删掉过后很多同学说老师怎么回事，我这文件都没有了。如果丢的是重要文件，那我告诉你，你就哭去吧，项目经理没准还会让你卷铺盖卷走人。所以大家一定要小心慎用这个删除。

> **结论**：关于文件的操作，掌握这几个常用的文件操作指令就足足地够了，绝对够了，你也不用再去看什么看不懂的资料。因为 DOS 对我们来说主要用常用的就行，你不用去研究太深，而且实际上用处也不大。

### 清屏与退出

DOS 的常用指令里还有两个用得也比较多：**一个是清屏，一个是退出 DOS。**

比如你看这个屏幕内容很多了，看起来很不舒服，怎么办？`cls`——**简称"苍老师"，你就记这个苍老师一下就记住了**，对不对？你不用记别的，就苍老师就完了。一回车，清屏了，看起来比较舒服。

还有一个就是退出这个 DOS。如果说你玩了一段时间，你觉得我不想玩了——第一种方式是点窗口的叉，很低端是吧？我们作为程序员有一个专门的指令退出，叫 `exit`。退出来了。

这两个指令大家记一下就行，非常简单。虽然简单，咱们也把它记到笔记里面去。

### 本讲提到的题目

#### 题目

综合练习，坦白地说很简单，你只要把刚才讲的内容听明白了、或者听了个大概，就可以做出来：

- 切换到 E 盘；
- 新建一个目录，就叫 `test100`——或者换一个名字吧，叫 `atguigu100`；
- 切换到这个目录；
- 在这个目录里新建 `a`、`b`、`c` 三个目录；
- 切换到 `a` 目录，在里面新建一个 `news.txt` 文件；
- 复制这个文件到 `b` 目录下；
- 最后把它们都删除。

#### 解析

每一步都是把前面讲过的指令按顺序串起来：跨盘符切换用 `cd /d e:`；建目录用 `md`；进目录用 `cd`，想清楚这次是相对路径还是绝对路径；写文件用 `echo ... > news.txt`；复制用 `copy`；删文件用 `del`；删目录用 `rd`。

> **注意**：删目录这一步要注意——如果目录里还有文件，直接 `rd` 是删不掉的，会提示"目录不是空的"，这时候要么先把文件删掉，要么用 `rd /s`。

#### 答案

按顺序敲下面这一串即可（每一条都与上面讲过的指令一一对应）：

```cmd
cd /d e:
md atguigu100
cd atguigu100
md a b c
cd a
echo news > news.txt
copy news.txt ..\b\
cd ..\b
del news.txt
rd /s a
rd /s b
rd /s c
```

这个大家自己去练一练，非常简单。可以这么说，你要是第一次学的话，最多十分钟就可以把它搞定。**好，一定要练啊！** 虽然说大家是在听视频，但是也要有一个学习的态度，既然你要学了，就踏踏实实地学，把这个案例好好地做出来。
