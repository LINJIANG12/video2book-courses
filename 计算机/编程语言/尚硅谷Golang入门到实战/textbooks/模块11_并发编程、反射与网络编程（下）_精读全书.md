## 反射的细节：类型对不上就 panic，改值得先传地址
> 对应块：BLK109 | 覆盖分集：P289-P291 | 块标题（分集名）：《287_尚硅谷_反射的注意事项和细节(1)》

刚才我们讲到了反射的第一个细节，在那里我们引出了 `const` 的内容。今天接着看剩下的几个。

### Type 和 Kind：可能相同，也可能不同

第二个需要注意的地方。有一些不用举例，我直接念一下就可以了：

> **结论**：`Type` 是一个类型，`Kind` 是类别。**`Type` 和 `Kind` 可能相同，也可能不同。**

这个什么意思呢，各位同学？注意听，**它可能是相同的，也可能也不同**——这取决于你传进去的变量，就是你传到这里做反射的变量它是什么类型的。

如果你是一个基本数据类型，比如像 `string`、`float`、`bool`、`int`，那这个时候 `Type` 和 `Kind` 其实是相同的，**因为它们不存在包的问题**。

那如果说你是一个 `Student`，像结构体就不一样了。如果是结构体的话，**它的 `Type` 就是 `包名.Student`，而 `Kind` 就是 `struct`。**

怎么理解这个意思呢？

那就意味着我们 `Student` 这个结构体，**可能是别的包也允许有**。也就是说，在 Go 语言里面，它去区分一个 `Type` 是**包名加上结构体的名称**。

```text
   包名.Type  ── 唯一标识「你是哪一个」
   目录 pkg1 /  pkg1
        └── Student   ──►  Type = pkg1.Student
   目录 pkg2 /  pkg2
        └── Student   ──►  Type = pkg2.Student
                             ↑ 同名，但 Type 不是同一个

   基本类型 string / float / bool / int
                     ──►  没有包这一层
                          Type == Kind
```

那比如说我在 `pkg1` 这个包有个 `Student`，它算是一个 `Type`；**那也有可能我在 `pkg2` 这个包下面也有一个 `Student`，这个是不冲突的。** 因为我们知道在 Go 语言里面，**它是以包名来进行范围的一个区分的**。

你看，相当于说你是 `Student`，我也是 `Student`，**但是我们的类型不是同一个。但是我们的类别都一样，都是结构体。**

> **结论**：**`Kind` 只看大类别，`Type` 才带包名。** 所以两个包里的同名结构体，`Kind` 都是 `struct`，`Type` 却完全不同。传进去的是基本类型时，因为没有包这一层，两者就相等了。

### 取值时的两个硬要求

#### 先在 interface 和 reflect 之间切一刀

第三个细节我们前面已经讲过了，在这过一下就行：**通过反射可以让变量在 `interface` 和 `reflect` 之间进行切换。**

刚才讲的这个案例，不管是基于基本数据类型的还是基于结构体的，其实我一直在讲这个东西——**它们可以随意切换。变量可以交给 `interface`，`interface` 可以转成它，它又可以转回去，它还可以转回去。**

```text
     变量 ──► 空接口 interface{} ──► reflect.Value
       ▲                                │
       └──── 类型断言 ◄── 空接口 ◄── .Interface()
```

#### 数据类型必须匹配

还有一个：**使用反射的方式来获取变量的值，并返回对应的类型，要求数据类型匹配。**

比如说 `x` 是 `int`，我们应该怎么反射呢？**是先拿到它的 `reflect.Value`，再去取它的值，而不能用别的。** 在前面其实已经讲过这个了。

> **结论**：你想要通过反射来获取变量对应的值，**要这么去做**，不能用别的方式。

那反过来，同学们说："老师，假设是一个结构体怎么去取呢？假设我要把它取出一个结构体，怎么去取呢？"

**结构体的话，我们发现这个 `Value` 应该没有直接的结构体，那你只能用断言了。** 我们去看它的 `Value`，因为结构体它对应的 `Type` 类型是无法确定的——你看它里面就没有这种方法。**所以这个时候对于结构体，你先得断言，然后再取才可以。**

那如果类型不匹配会怎么样呢？大家看一个案例。**如果说，你明明传的是一个 `int` 类型，但是你偏偏用 `Float` 去取**，那这个地方就会直接给你报错。

**是编译错误还是运行错误？** 我们看一下。比如我很清楚地知道这个传进去的是 100，我应该用 `Int` 去取，但是我偏偏要用 `Float` 去取。

好，我看编译它有没有检测出来。他说没有用——没有用这个倒不是大问题，我用一下。**大家看一下，我们发现在编译这个层面找不到。**

> **结论**：为什么编译层面检测不出来？因为**对它来说，它现在已经变成了一个这样的类型，你用 `Int` 来取、用 `Float` 来取，都是属于运行时代了。**

所以它在运行的时候才发现：你这个反射它其实持有的是一个 `int` 类型的反射值，但是你要把它转成一个 `Float`，那么错误就会在运行的时候发生。`cd` 到我们刚才写的这个案例，跑一下——报了一个非常经典的错误：

```text
panic: reflect: call of reflect.Value.Float on int Value
```

**非常清晰了，他说你调了一个 `Float`，但是你是给谁用的 `Float`？是个 `int` 这样一个 Value 的，所以他它就报错了。**

> **易错点**：这个错误是**运行时的 panic，不是编译错误**——编译器根本拦不住你，测试时才会炸。**将来你想通过这个 `reflect.Value` 去取回对应的基本数据类型值的话，一定要确认是同一个类型。**

那有同学会说："老师，我怎么来比对它是什么类型呢？"可以这样做——**你可以加一个判断**，加这个判断它到底是什么类型，你可以加一个判断。

**后面我们还会继续说这个事情的，所以这地方不能乱用，这里不能乱用。**

### 用反射改值：得先传地址

第五个需要注意的地方：**通过反射来修改变量的细节。这是一个很重要的细节。**

> **结论**：当我们想使用 `Set` 相关方法来设置的时候，**需要通过对应的指针类型来完成。**

比方说有这么一个需求：**我传了一个 `int` 进去，希望在反射里面把这个 `int` 的值修改过来。**

#### 先想清楚：传值是改不到外面的

新建一个 `reflectdetails` 文件夹，在里面举一个例子。写一个函数，参数是一个空接口：

```go
func reflect01(b interface{}) {
	// 通过反射修改一个 int 类型的变量的值
}
```

主函数里面先按照套路出牌：

```go
func main() {
	var number int = 10
	reflect01(number)
}
```

> **易错点**：大家想，你这样传进去，**显然后面通过 `reflect.ValueOf` 拿到之后，最终不会影响到这里**——因为这相当于是一个**值拷贝**。把这个 `b` 传给它之后，里面的改变并不会影响到外面的 `number`，**没有任何用处**。

所以我们肯定是要传一个地址过去才有用：

```go
reflect01(&number)
```

#### 为什么 SetInt 直接报错

但是当我们传了一个地址过去之后，来看一个问题。我们非常明确地知道，反射的 `reflect.Value` 本身提供了一个方法叫 `SetInt`。我们看看是不是有这个方法——**果然是有 `SetInt` 方法**。那好像通过它就可以改变这个值一样，我们看一下对不对：

```go
rVal := reflect.ValueOf(b)
rVal.SetInt(20)
```

一运行，它就报错了：**`reflect: reflect.Value.SetInt using unaddressable value`**——就是说你使用了一个**不可寻址的值**。

为什么呢？因为你传的是一个地址进去，**这个时候它的类型本质上是一个指针。** 如果把这个类型打印出来，你会发现它其实是一个指针。我们看一下此时此刻 `rVal` 的 `Kind` 是什么：

```go
fmt.Printf("rVal kind=%v\n", rVal.Kind())
```

运行输出，你会发现**它是一个 `ptr`，它的大类别已经不再是基本数据类型了，而是一个指针**。如果传的是值本身，它的 `Kind` 才是 `int`。

既然这样，在这个时候必须传指针进去才能改变外面的值，**那为什么直接用 `SetInt` 会报错呢？**

因为这个地方它的类型**已经不再是值类型，而是一个指针类型了**。因此我们要看有没有一个方法能获取到它指向的值。

#### Elem() 到底做了什么

在这里提供了一个非常重要的方法，**很简单但是很重要，后面会大量用到**，叫 `Elem()`。

我们找到这个方法：**`Elem()` 返回 `v` 持有的接口保管的值，或者是 `v` 持有的指针指向的值。**

> **结论**：**"返回 v 持有的指针指向的值"——这句话很重要。**

原来是它。**这个才是我们真正要去拿到的、能够调用设置方法的值**。也就是说，你只需要这样操作就可以了：

```go
rVal.Elem().SetInt(20)
```

这样就搞定了。这句话到底等价于什么？你可以这样理解：

```go
var num int = 9
var ptr *int = &num
var num2 int = *ptr
```

**你可以简单理解成，这种写法就相当于取到了指针指向的真正的值，然后再调用方法改变它。它在底层改变的时候，其实是改变了同一个数据空间。**

```text
   number  ──┐
             │  取地址
             v
   &number ──► reflect.ValueOf(&number)
                      |
                      |  Kind = ptr
                      v
                 rVal.SetInt(20)      ✗  unaddressable value
                      |
                      |  Elem()  ==  解引用 *ptr
                      v
                 rVal.Elem().SetInt(20)   ✓  改的是同一块内存
                      |
                      v
                  number = 20
```

这样一做，代码就没问题了。执行之后效果就出来了：**`number` 变成了 20。如果没有这句 `Elem()`，就会直接报错。**

> **结论**：这是一个很重要的点，这句话特别重要。**后面我们讲解反射应用的几个案例里面，会大量用到这个 `Elem()`。** 因为我们的反射必须有一种能力：**直接改变外面的结构体或者变量的值——反射的价值就在这里。**

#### 结构体的修改更麻烦一层

同样的道理，如果让你们去改变一个结构体的值，是不是也应该类似这样处理？在老师这个例子的基础上去传一个学生对象，然后把学生的名字改了，你会改吗？**原理是一样的。**

> **易错点**：**但是结构体的改变比这个要稍微麻烦一点**，因为你首先还要拿到它的字段才能改；**如果字段都拿不到，你怎么改？** 所以结构体肯定比普通数据类型要更麻烦一点，后面我们会讲这个案例。

至于怎么理解 `reflect.Value.Elem()` 的含义和原理：刚才我们把这个 `number` 用反射了一下，反射把这个地址传给了 `fn`。**那么这个 `fn` 其实就相当于是一个接口拿到了那个东西**，当然 `fn.Elem().Set` 这个就改变这个 `number`。**`fn.Elem()` 这句话，就等价于把星号取出来，干什么干什么事。** 就这个意思。

#### 反射取 float64 的三件套

**题目**：给你一个变量 `float64`，请你使用反射来获取它的 `reflect.Value`，然后获取对应的 `Type` 和 `Kind`，还有它具体的值，**三点**；并将 `reflect.Value` 转成这个接口，**再将接口转成 `float64`**。

**解析**：这个题跟前面讲的 `reflect_test01` 案例**没有什么区别**——其实说白了就是让你把这个代码自己敲一遍。`reflect_test01` 其实就是完成了这样一个工作，只不过当时做的是传了一个整数 `number` 进去；**这个题的要求是把它做成一个 `float64`，所以没什么需要注意的。**

具体到每一步用什么：

- 拿 `reflect.Value`：`reflect.ValueOf`；
- 拿 `Type`：`Type()`；拿 `Kind`：`Kind()`——这两个是同一个东西，只是入口不同；
- 拿具体值：`Float()`。**这一步为什么能选 `Float()` 而不能选 `Int()`？** 因为前面讲过——**你传的是 `float64`，用错方法编译器不拦你，运行时会直接 panic：`call of reflect.Value.Float on int Value`。** 这就是第四个细节反复强调的那条规矩；
- `reflect.Value` 转接口：`rVal.Interface()`；
- 接口转回 `float64`：类型断言 `iv.(float64)`。

> **结论**：把"取三件套"和"来回切一刀"这两步串起来，这个题就完了。**它考的不是新东西，就是前面那条 `interface ↔ reflect.Value` 的转换链路。**

#### 这段代码为什么编译过了却跑不对

**题目**：有一个 `string` 类型的变量（它最终要改成 `"jack"`），先用 `reflect.ValueOf` 把它包成一个 `fs`，然后直接调 `fs.SetString("jack")`，再打印出来。**这段代码对不对？**

**答案：不对。**

> **解析**：大家动动脑筋看看会输出什么。这句话——把它包成 `Value`——没问题；把它打印出来——也没问题。**但这里传过去的话，你拿到这个 `fs`，它的类型也好、类别也好，它是什么类型的？它是 `string`。**
>
> **然后 `fs.SetString` 这句话会报错，报什么错呢？因为它在这里是要求用一个指针去 `Elem`，然后再调用的，所以这个地方会错的。**

我们验证一下。`cd` 到刚才我们写的 `exercise`，`go run main.go` 跑起来——**它果然报错了，报错的原因跟刚才一样**，那就意味着不能这么用。

那怎么办呢？

> **结论**：修改代码有**两个地方**要调：
>
> 1. **第一个地方，把传入的地方改成一个地址**——原来传的是值本身，现在传 `&` 出来的地址；
> 2. **第二个地方，用 `fs.Elem()` 去取回这个 `string` 真正指向的那一个数据空间**。

这样就可以了。然后这边会输出什么呢？显然会输出 `jack`，因为你通过它把它改动了。我们运行一下——**输出了 `jack`，正确。**

> **结论**：这两道题问的是同一件事。**第一题答案全对，第二题错在"传值还是传地址"。** 判断的口诀就一句：**用 `Set` 系列方法改值，必须先 `Elem()` 拿到那个可寻址的值。**

### 先认识两个方法：Method 和 Call

第一个最佳实践是：**使用反射遍历结构体的字段，调用结构体的方法，并获取结构体的标签值。**

> **注意**：在这个地方其实就解释了我们怎么去获取到结构体的标签。**你们看在写结构体的时候曾经写过 `json` 冒号，它是怎么拿到的，在这里面就可以解释这个问题了。**

要完成这三件事，尤其在调用结构体方法的时候，需要认识两个特别重要的相关方法：**一个叫做 `Method`，一个叫做 `Call`。**

我们来看看这两个方法。**这两个方法都是 `reflect.Value` 类型的方法。**

`Method` 是什么？打开看一下：**`Method` 可以通过 `reflect.Value`，在这个地方填上 `i`，就可以返回反射的 `v` 所持有的结构体的第几个方法。方法的下标 `i` 是从 0 开始的。** 比如说结构体有三个方法，那么第一个方法的下标就为 0，第二个方法的下标就为 1，第三个为 2。这是第一点。

`Call` 是什么意思呢？**获取到这个方法以后，可以调用 `Call` 来真正的调用这个对应的方法。**

> **结论**：`Call` 后面可以传一个切片，**这个切片的类型是 `reflect.Value`**。说白了什么类型都可以往里面放，**但是必须是 `reflect.Value` 这个类型的切片往里面扔。** 因为将来获取的方法可能是有参数的，这个时候我们通过切片往里面传参。

**这两个方法特别重要。**

### 案例：一个叫 Monster 的结构体

第一个应用 `apply01`。在这里建一个文件，我们一句一句地看，哪地方看不懂可以随时问。

包先打上，然后我们需要 import 一些相关的包——首先 `fmt` 包肯定是要有的，还有一个 `reflect` 包肯定也是要有的，这两个大包肯定跑不了。

这里声明定义了一个结构体，`Monster` 结构体：

```go
type Monster struct {
	Name  string `json:"name"`
	Age   int    `json:"monster_age"`
	Score float32
	Sex   string
}
```

这个大家应该能看懂，名字、成绩、性别，这边是它的标签 tag 标签。

紧接着我给 `Monster` 绑定了三个方法。第一个方法 `Print`，输出这个 `Monster` 的值：

```go
func (s Monster) Print() {
	fmt.Println("Print()", s.Name, s.Age, s.Score, s.Sex)
}
```

第二个方法写了一个 `GetSum`，让它可以返回两个数的和：

```go
func (s Monster) GetSum(n1, n2 int) int {
	return n1 + n2
}
```

第三个方法写了一个 `Set`，这个方法可以接收四个值去给 `Monster` 赋值：

```go
func (s Monster) Set(name string, age int, score float32, sex string) {
	s.Name = name
	s.Age = age
	s.Score = score
	s.Sex = sex
}
```

> **易错点**：注意这个 `Set` 用的是**值接收者**。所以它改的只是自己那份副本，**外面的 `a` 一点都不会变。** 这一点等下讲到修改字段的时候你会再撞上。

先看我们的主函数。主函数这个能看懂吗？**这是我们非常熟悉的名字，黄鼠狼精，黄大仙。《盗墓笔记》里的黄皮子坟，专抓黄大仙的。**

```go
func main() {
	var a Monster = Monster{
```

然后大家看这里，**很猛啊，这个地方有点类似于你们学的 Java 里面的那种在底层创建对象**。如果有同学学过 Java，应该看起来似曾相识的感觉。

```go
typ := reflect.TypeOf(&User{})
fmt.Println("typ:", typ)     // *main.User

elem := reflect.New(typ)    // elem 是 *User 的 Value
fmt.Println("elem kind:", elem.Kind())  // ptr
```

**这个 `elem` 还不是一个实例。它是干什么呢？`New` 了一个 `Value` 类型的值，该值持有一个指向 `Type` 的新申请的零值指针。**

> **结论**：**这里面还没有东西——数据还没有。但是它已经指向了一个什么？它其实已经指向了一个 `User` 的一个地址，但是东西没有。**

紧接着我这里输出了两个日志，这个你不用看。**这个就很重要了**：

```go
model := elem.Interface().(*User)
```

大家看这句话是不是能看懂？**这句话是不是我先把它转成一个空接口，再用我们的一个类型断言把它重新转成一个 `User`？**

```text
   ①  reflect.New(typ)
         |
         |  elem  :  *User   (Kind = ptr)
         v
   +-------------------------------+
   |   一块刚申请的新内存（零值）    |   UserId : ""
   |   它就是我们的 User 数据空间    |   Nickname : ""
   +-------------------------------+
         ^                    ^
         |                    |
  model = elem.Interface()  |
  .(*User)  ────────────────┘
  model 也指向这一块，两边看到的是同一份数据

   ②  elem = elem.Elem()
         elem 不再是指针，直接指向数据空间

   ③  elem.FieldByName("UserId").SetString("1234")
         |
         v
   +-------------------------------+
   |   UserId : "1234"  ← 写进去了   |
   +-------------------------------+

   ④  再用 model 访问
         model 仍是指针，指向同一块
         => model.UserId 也就是 1234 了
```

**也就是说这个时候 `model` 和这个 `elem` 其实它们都指向了一个 `User` 的一个地址空间。那这样就意味着如果我改变它，它们两个值都会发生变化。**

> **结论**：**我通过 `elem` 取到了它真正的指向这个值。** 原先是指针——这个是指针，它指向一个真正的空间，这个空间就是我们的 `User` 的一个空间；然后到了这个地方，我 `elem = elem.Elem()`，这个就真正的指向这儿了，这句话就能让它真正指向这个地方的数据空间。**但是 `model` 还是通过地址指向的。**
>
> **为什么这样做呢？因为我们刚才讲了，去修改这个值总是 `Elem()` 然后再做的。**
>
> **只有你这样做才能够去往这里面赋值。** 下面我用这个东西往里面找到它的 `UserId` 并赋了个 1234，相当于说在这里面写了个 1234。紧接着再写个 nickname。

这样做完了以后，在我去用 `model` 访问的时候——**这个 `model` 因为是指针，它取的时候它还是能把这个取出来，所以说 `model` 这地方会把它的一地址打出来。** 如果 `model.Name` 呢，**也把这个值取出来了，因为你这改变了就把它改变了。**

### 你的"hello"并没有直接飞过去

首先我们来看两个实际的应用。

同学们看到在我们的幻灯片里边有一个 QQ，当然迅雷我没写。**比如你看到 QQ、迅雷或者百度网盘的客户端**，你会看到这样子的东西；同时你在实际工作中会看到有些网站。

大家想一个问题：**假设你这有个 QQ 客户端 A，你这有个 QQ 客户端 B。为什么你在 A 地方写了一个"hello"，然后对方就可以收到？**

各位，其实大家应该思考这个问题。你看你经常玩微信、你玩 QQ，**为什么你说了这一句话，或者你发了一张图片，发了之后对方为什么就收到了呢？作为一个程序员，你应该思考这个问题。**

> **易错点**：首先告诉大家，**绝对不是这样过去的。** 可能有些同学认为 A 发了一个东西给了 B，B 发了一个东西给了 A——**那这个就不叫网络编程，这个叫对讲机，直接过来了。**

这个地方一般我们会用服务器，**就是在公网上会有一个服务器。** 数据会怎么跑呢？**它是先把数据发到了这边，然后这边给你一个中转。**

> **结论**：中转的时候方式很多：**有可能是我读完了之后，把这个东西放到数据库里面去，然后你到数据库去取**；**还有一种可能性就是大家在这里建立一个综合的 Socket，不断在内存里边，我直接不落盘，直接就给你传过去，这个实时性就更强，当然难度也更大。**

它大致就这么一个过程。在这个使用过程中，我们就会用到网络编程——**这就叫网络编程。这种网络编程我们一般把它叫做 C/S 的结构。**

#### C/S 和 B/S：网络编程的两大块

除此之外，我们还有一种结构就是 **B/S 结构**。

其实 B/S 结构也是属于网络编程的一个范畴。**因为它的底层——之所以你可以看到这个网站、看到这些图片、看到这些文字——其实底层仍然是靠我们 TCP/IP 这个协议来支撑的，只是它在上面做了一个包装，它变成了一个叫 HTTP 协议。**

> **结论**：这个 HTTP 编程，我们这块要说一下它属于 **Go Web 的一个范畴**。所以我这重点讲的是 TCP 编程。当然你学完 TCP 编程过后，你会对 HTTP、对 Web 编程有一个更深入认识。
>
> **其实它这里面只是变了一样东西——它就变了一个，就是发送的协议发生变化了。** 你原先发的协议是你自定义的协议，等到你学 HTTP 编程的时候，**它发送的协议就是一种标准协议**，就是大家都遵守的那种超文本传输协议。**它底层是一样的，所以说 TCP 还是一个基础。**

### TCP/IP 是每台电脑的必装件

> **结论**：Golang 的主要设计目标之一，就是**面向大规模的后端服务器程序。网络通信这块，是服务器端的程序必不可少也是至关重要的一个部分。**

### 联网的两件硬件

既然是网络编程，我们需要对网络编程有个基础的认识。**这个基础认识我简单过一下就行，照顾一下对网络完全是零认识的同学。**

#### 网卡：没有它你出不去

首先大家都知道，**计算机之间要相互通讯，必须要由最基本的东西：一个是网线，一个是网卡。**

现在物理网卡越来越少了，现在也有很多是无线网卡。**都需要这两个最基本的——有线必须要有网线，如果是无线的，不要网线，无线网卡也可以。**

这是第一个要知道的。**出去必须要有这个卡，你没有卡的话是不让你出去的。**

#### 协议到底是个什么东西

第二个，我们还要明白一下**协议**。

> **定义**：**什么叫协议呢？打个最简单的比方——协议是双方认同的。** 计算机和计算机之间相互去交流的时候，他们需要一种协议。

我举这样一个例子，大家一下就明白了。比如说我打开一个 Excel 文件——**比如我们两个人之间交流，张三和李四交流。** 假设这里有两个人，我们来画个笑脸就行了。假设这个人叫张三、叫 A 吧，然后叫 B，还有一个人叫 B。

**他们之间要相互交流的话，他们必须要有一种东西——大家都认同、都认识、都能识别的东西。**

比如说他是中国人，他也是中国人，**那么他们交流靠什么呢？靠语言。** 我跟你说一句话，你能听得懂我在说什么。同样的道理，B 这个人也可以给 A 说一句话，**那么他要能听懂——人与人之间靠的是语言。**

**问题又来了**：如果 A 和 B 都是中国人，那这个语言就叫中文就行了。**但是有一个问题——如果 A 是一个中国人，B 是一个越南人，越南人不会说中国话，这样子就不能通讯。**

> **结论**：这就好像**语言我们认为叫协议，语言就叫做一种协议。** 但是这个协议下面，语言有中文，当然它也有英文，还有越南语等等。**每种具体的语言，我们把它叫做具体的协议。协议下面有很多种协议，这就叫一个具体的协议。**

有些协议、有些语言是大家公认的；有些语言可能是一个小部落的语言，只有他们自己能用。

这就好像我们以后写编程：**我们有通用的协议，比如说大家都清楚的 HTTP 协议、FTP 协议、HTTPS，还有 SMTP**，这些都是协议，是大家都认同、都认可的。**但还有一种协议就是自定义协议，我们自己定义的协议也可以。** 比如后边我们写东西，我们可能自己去定义协议，在这个基础上我们自定义协议也是有可能的。

> **结论**：**协议是一个很重要的东西。你将来做网络编程，你就要学会自定义协议。**

#### 自己定义一个协议：一个结构体就够了

自定义协议其实也挺简单的，**一般就是一个结构体**。

比如说最简单的协议，我要跟 A 和 B 发生一种关联关系，我就定义一个结构体：

```go
type Message struct {
	Id      int
	Content string
	Time    string
	To      map[string]string
}
```

我们就定好了，我跟双方都是认同的。

**我要给你发个消息，我怎么发这个消息呢？** 首先我告诉你，我会有个 `Id` 号，`Id` 是一个 `int` 类型的。我还要给你发一下**消息的内容**是什么，比如是个 `string`。再比如我还发一个**发送的时间**，我是什么时候发给你的，可能用个 `string` 来记录这个时间。

再比如我这个消息是要发给谁呢？**我要发给张三还是李四，还是群发呢？可能我还有一个接收者——那么接收者可能我这边用的就是一个 `map`。**

> **易错点**：**为什么接收者用 map 呢？可能是一个数组，或者是个 map。** 我告诉你我将来把这个东西发给谁等等，**这样子就可以描述一个完整的 Message。**
>
> 对方拿到过后，他去读取这里面的内容，然后显示。**这种东西就可以自定义了，这就是一个简单的协议的描述。**

### 从七层到四层：OSI 与 TCP/IP

我们这个协议有这么多了，接下来介绍的就是一个重点了：**在我们实际的网络 TCP 这个范畴，我们有哪些协议呢？**

在网络世界里面有一种模型，它叫 **OSI 模型**。**这种模型最早是由美国的一个标准化组织提出来的。** 我们将来要开发一个网络，那么我们需要有这么几层，**一共是七层：应用层、表示层、会话层、传输层、网络层、数据链路层，还有物理层。**

但实际上在真实的环境里面，其实没有这么复杂，**它把这个做了一个简化。简化成几层呢？简化成了应用层、传输层、网络层和链路层。**

有些同学说老师你这样讲我有点听不懂。**因为同学们虽然你们不是专业学网络的，但是我认为了解一些最基本的东西，大家还是要了解的。** 咱们也不去讲过于理论化的东西，**因为太理论化的东西不是一句话两句话能说清楚的，光书都有三本**，而且随着它的发展，有些还在不停地完善。

> **提示**：搞运维的同学应该非常清晰，**搞运维的必须学这个东西，而且学得很透。**

### 一个 hello 从中国走到美国

我就以一个最简单的 QQ 相互通讯的案例来结合看。**比如我通过 QQ 发了一个"Hello"，它是怎么把这个"Hello"传递到 B 的呢？** 我就站在咱们 Go 语言开发者的角度，给大家看一下到底它是怎么做的。**请大家认真听，还是比较有用的——因为你了解这个东西，对你理解程序本身是有帮助的。**

现在有这么一个情况：**这是张三的电脑。张三他有一个好友在遥远的美国，叫李四。张三和李四他们是好友，他们都用 QQ。** 这边是张三的 QQ。两个人上线了，一个是在中国，李四这个人在遥远的美国，在大西洋的彼岸。

现在张三上线了，李四也上线了，他们要说话。**张三有电脑，他的电脑上装的有 TCP/IP 这个协议。**

> **结论**：**TCP/IP 协议其实是一组协议，它简称 TCP/IP，其实它包含的协议很多。** 在电脑里面它分成了这么几层：**第一层是应用层（Application）；第二层我们叫传输层，也叫 TCP 层；第三个是 IP 层，也就是网络层；最后一层叫链路层。**

**链路层下面是什么呢？链路层就直接对应我们的网卡。** 每个电脑要出去，它必须要装有网卡。网卡是一个硬件设备。

#### 往下走：每层各加一个头

**数据开始了。** 张三在 QQ 上说了一句话，他给李四说了一句话叫"Hello"，因为他的好友已经拿到了。

这个"Hello"首先开始往下走。

```text
  张三发出 "Hello"，一层一层往下走，每一层都在前面加一个头

   走到哪一层                        此刻这个包长什么样
   ------------------------------------------------------------------
   起点                              [ "Hello" ]
                                     内容就一个文本包

   应用层  Application          +    [ APP头 | "Hello" ]
                                     APP头：表示我是哪个程序发过来的

   传输层  TCP                 +    [ TCP头 | APP头 | "Hello" ]
                                     保证数据包准确地传送到李四那边去

   网络层  IP                  +    [ IP头 | TCP头 | APP头 | "Hello" ]
                                     IP头要记录两样：我的IP、对方的IP

   链路层                       +    [ 帧头 | IP头 | TCP头 | APP头 | "Hello" | 帧尾 ]
                                     加了帧头帧尾，就"变成一帧数据"
   ------------------------------------------------------------------
   到这里已经变成二进制的东西了，这一帧就是最终发出去的东西
```

**"Hello"经过了应用层，它首先会在这地方加一个 APP 头。** 加 APP 表示什么意思呢？**表示我是哪个程序发过来的。因为对方最后接收的时候，他在解析的时候要知道这是哪一个程序发过来的**，所以它有个 APP 头。

**加完这个 APP 头过后，紧接着继续走传输层。** 经过这个传输层过后，这个地方又会加一个东西，加一个 TCP 头。你看这个数据包在不停地变东西，又加了个 TCP 头。

**加这个 TCP 头有什么用呢？TCP 这一层要保证我将来的数据包准确地传送到李四那边去，它有这样一个责任。每一层有它自己的责任，它的责任就是说我要准确地把这个包发送到李四那边去——叫传输层。**

紧接着还有第三，它又过渡往下继续走，经过了我们的 IP 层。**IP 层过后，在这个基础之上再加一个头，叫 IP 头。**

**为什么要加这个 IP 头呢？因为要记录两样东西：第一个，我的 IP 是多少；第二个，对方的 IP 是多少。** 因为这样子，后面网络才能知道你要把这个包发给哪一个人。

> **结论**：**在网络中你为什么发了一个"hello"能够准确地定位到李四呢？因为我们每一个网络都会有一个自己独一无二的 IP 地址。**
>
> **当然有些同学说了，那假设都在内网里面，IP 不是相同的吗？这是另外一个范畴了，局域网里面还会有别的方法进行解包。我们先不去考虑那么多。**

**拿到 IP 头过后还不能发送，然后再经过我们的链路层。** 经过链路层，要在这个包上面再加两样东西，**一个是帧头、帧尾。这个时候就变成一个帧数据了。** 在前面加一个帧头，还要加一个帧尾。**它加帧头、帧尾的目的，就变成了一帧数据。**

> **易错点**：这个时候这个数据到这其实**已经变成二进制的东西了**，肯定就是一堆二进制东西。
>
> **如果你的代码在这个地方被人截获了怎么办？** 比如你的包在网络某一个地方被人截取，**把这个头改了，那你就被欺骗了，这个包就会发到另外一个地方去。** 比如你说"hello，我的电子密码是多少"——**如果被人截取这个 IP 头，就会把 IP 头改到另外一个地方去，而且会自动把密码给截过来。所以网络世界的风险很高。**

#### 出去：网卡、网关、路由器

有了这个数据过后，**当我们拿到这个地方的时候，这个数据就会交给我们的网卡。**

**交给网卡，网卡做什么事情呢？它也不是闲着的。** 假设你这个网是在局域网，网卡就会对接一些东西，**比如说对接一个网关——因为你也有可能是在一个局域网里边，所以它有网关。**

```text
   张三的电脑（中国）        局域网      骨干网（大量的路由器）      李四的电脑（美国）
   +------------+           +----+      +----+----+----+           +------------+
   |   网卡     | --- 网关 - |    | ----> | 路由|路由|路由 | --- 网关 - |   网卡     |
   +------------+           +----+      +----+----+----+           +------------+
```

**网关出去就是大量的路由器，它有很多路由。** 我们一个包要到对方去，**其实经过了很多路由。当然有多少个路由我们不知道，每个路由也有自己的 IP 地址，叫路由器。**

假设经过了两个路由器到美国，**那么我们这个数据包就在网络里面传输。经过这个路由过后到达了李四。**

李四这边同样有这样的四层数据。**李四的电脑肯定也是在一个网络里边，所以他对方也有一个网关。** 这个数据通过网络一层层地发，**最后到达了李四所在的网关的位置，他就要接收。**

#### 往回走：逐层拆包

传输到这儿的时候，**它就反过来进行一个逆向的处理。**

**经过链路层，到达链路层的时候，这个数据到这儿就会去掉帧头和帧尾。** 然后再经过 IP 层，**继续去掉 IP 头——因为每层都要校验到底是不是给我的。** 把 IP 头去掉就到达这一层，然后继续经过传输层的处理，**传输层再往上走，又把 TCP 头去掉。**

**到达应用层就决定是哪个程序来接收。** 因为你的应用层可能有很多程序，**你有 QQ，可能还有微信，到底由哪个来接收呢？当然里面还有端口。**

再经过应用层把 APP 头去掉，**APP 头去掉过后，最后我们的"hello"就送到了李四的地方，就看到一个"hello"了——它是这么一个过程。**

> **结论**：整个过程是这样来的。当然我画得比较简单，**也没有画得非常具体，里面有很多细节。** 我们在编程的时候大家也可以看到**网络很复杂**，比如你的包在某个路由被人截获了，那你就麻烦了。

### 亲手追一个包：tracert

我们看一下能不能看一下一个数据包整个路由的过程呢？**在 Windows 里面包括 Linux，它有专门的指令可以去追一个包的流向。**

**比如现在我们想去追一个包，`tracert`。`trace` 就是追踪的意思，`rt` 是路由的简称 router。** 现在我们追踪一个包到百度是经过了哪些路由器——走，现在开始追了。

```text
   hop   看到的地址            说明
   -------------------------------------------------------
   1     192.168.4.3           第一个出口，进了内网
   ...   192.168.53.x          还在内网里面跑，不知道跑哪儿去了
   ...   (超时)                路由器不支持/不返回这个指令
   ...   ...
   末    111.13.101.x          快到百度了
   -------------------------------------------------------
   一共大概十来个，12 个，有时候八九个就到了
```

**有些路由器是阻止给你返回这个东西的——按说大家都应该遵循这个规则。** 我首先到了 192.168.4.3，**有些路由器不给你返回信息就会带一个超时。**

> **结论**：**最终你要到哪里去？最终你要到百度的 IP 去。** 我记得以前每追一次全部都看得很清晰，**现在好多路由器都不支持这个了，反不回来。**
>
> **192.168.53，说明目前我们这个包还在内网里面跑**，不知道跑哪儿去了。**但最终它是要到这个 111.13.101。**
>
> **有些地址可能给你伪装了、隐藏了。它可能说本身是一个公网地址，但是我给你返回一个内网地址，你看不到——网络很复杂。**

**这个请求超时不是说你没有过去，而是他不给你响应这个指令，他不返回包给你。** 大概快到了，现在已经在路上了。

**如果你追的是美国的、像亚马逊的网站，它可能经过路由更多。**

最后大概 12 个路由。**也就是说我们这个网站为什么这么复杂？**

> **结论**：**但是我要告诉大家——每一次路径不一定完全相同。** 比如你这次看走的是这 12 个，**可能下次看走的是另外 12 个，都有可能。因为网络是一个非常有意思的现象。**

## IP、端口，以及 Socket 那根线

### 每一台电脑都有一个房间号

先来看 IP 地址。**IP 地址的概念也比较简单——就是每一个因特网上的主机和路由器都有一个 IP，包括网络号和主机号。这是基本知识。在一个网络里面，它有自己的主机。**

IP 现在有 IPv4 和 IPv6 这两种。**那么为什么有这两种呢？** 大家看一下，我查一下我的地址：

```bash
ipconfig
```

**这个指令可以看你的 IP 地址。** 你看我这个地址，它这儿已经有两种地址了，一个是 IPv6，一个是 IPv4。

#### IPv4 为什么会被用光

那怎么会有这两种地址呢？它是这样子的。

最早的时候，我们这个网络只有 IPv4。**为什么叫 IPv4 呢？是因为它是 4 个字节来表示的 IP 地址。**

但是大家要知道，**4 个字节能够表示的 IP 地址非常有限**。即使全部用来表示的话，它最多表示多少个地址呢？就 $2^{32}$ 次方，它最多就这么大。

```text
   IPv4   = 4 字节 = 32 位   →   2^32 = 4 294 967 296

   个、十、百、千、万、十万、百万、千万、亿、十亿  →  才 42 亿

   42 亿个 IP 地址  →  根本不够用
```

> **结论**：**才 42 亿个 IP 地址根本就不够用。** 不够用怎么办呢？后边发现，如果在 200 几几年——**当时说是 2008 年，整个 IP 地址就没有用了，就用光了。**

后边计算机专家就提出来什么概念呢？干脆这样子，我们把它提到 IPv6。**那么 IPv6 过后呢，它的 IP 地址是按 128 位来进行计算的。**

那 128 位意味着什么呢？128 位就意味着——**它上面原先写了个文档说，就意味着如果我们把电脑每一平方米放一台电脑，整个地球都能放满。**

**所以说那个就足足地够用了，所以说做了一个扩展，就这么一个概念。** IP 地址我们就说到这儿。

#### 查自己的 IP：ipconfig

**IP 怎么去查？我用了一个指令，就是 `ipconfig`。这个指令大家必须会——同学们，这是个基本指令，每个同学都要会。**

### 一台电脑有 65535 个耳朵

另外一个同学们必须要理解：**在做网络编程的时候，必须理解一个特别重要的概念叫端口。**

这个端口如果你做过网络编程，当然你很清晰了；如果你没有做过，**你还是仔细听。端口很有用**，有几个基础知识需要给大家讲一下。

#### 端口不是插口，是"谁的门口"

我们首先得这样：**我们这儿说的端口，在网络里面的端口，它不是指物理意义上的端口。** 你不要说"韩老师，我们这儿有个端口，电脑上插口那个"——**跟我们不是一个概念。它是特指 TCP/IP 协议中的端口，是逻辑意义的端口。**

你可以这样比较：**我这里有一台电脑，我这里有一台电脑，这是韩老师的一台电脑。** 电脑上你必然跑了很多的程序。

**你比如说你跑了一个程序是用来做服务器的**，那你这儿运行的一个程序，这是第一个程序，我把它放在这里。**假设你又跑了第二个程序**，比如你自己做了一个服务器。

这两个程序——**第一个程序比如你是跑了一个 Tomcat，你还跑了一个什么呢？你还跑了一个聊天系统的一个服务器。**

> **结论**：那么你跑这个程序过后，**只要是做服务器的，注意听这句话——只要是做服务器的，一定会监听一个端口。这是一个重要的原则。**
>
> 我以前刚刚做开发的时候，我连这些基本知识都不知道。**只要是做服务的程序，都必须监听一个端口。**

那么这个端口你可以这样理解：**就好像你的电脑是一个房间，你将来要跟别的程序交流。** 比如你这里有个客户端——**假设你这里有个客户端程序，这是你的一个客户端。我不管你客户端是什么，张三、李四、王五都无所谓，这是一个客户端。**

那么你这个客户端你要跟它交流。**比如说我们除了 Tomcat，我们还有一个程序，大家都非常熟悉的 MySQL。** 假设你在你的电脑上还跑了一个 MySQL 服务。

**你想一想，我们客户端跟你的电脑服务器进行交流，其本质就是靠刚才老师画的一个图——就是你发送一个数据包给到 Tomcat，或者发送一个数据包给到你的 MySQL。**

**问题来了，你怎么给？你怎么知道这个包要给 Tomcat，这个包要给 MySQL 呢？** 比如你现在有两个数据包，一个是给它的，还有一个数据包是给 MySQL 的，你怎么知道给哪个呢？

> **结论**：**其中一个最重要的东西就是，它有一个端口在监听。** 也就是说 Tomcat 也好、MySQL 也好，包括你的聊天服务器这个也好，**它有一个小端口。**
>
> **你可以理解成是一个人的耳朵。** 它这儿有一个端口，就好像它就像一个人一样长了一个耳朵，我在这儿进行一个监听。**当然这个"监听"这个比喻很形象，其实它就是在这儿等待你来连接——本质上就是等待你的连接，就这么一个东西。**
>
> **每一个只要是做服务的程序，必须监听一个端口，必须监听端口。**

```text
        你的电脑  =  一个房间，IP 地址就是它的房间号
   +--------------------------------------------------------------+
   |                                                              |
   |   +---------------+  +---------------+  +----------------+   |
   |   | Tomcat         |  | MySQL         |  | 聊天服务器      |   |
   |   | 监听 8080  (耳) |  | 监听 3306  (耳) |  | 监听 8888  (耳) |   |
   |   +-------+-------+  +-------+-------+  +--------+-------+   |
   |           |                   |                   |           |
   +-----------|-------------------|-------------------|-----------+
               |                   |                   |
        客户端(随机端口)      客户端(随机端口)      客户端(随机端口)
            1245                  7861                   ...

   端口 = 其他程序和这个服务通讯的通道
   没有端口，就根本没法玩
```

那么这个端口就是我们别的程序跟你进行交互的一个通道。**该端口就是其他的程序和该服务通讯的一个通道。如果你没有这个端口，你根本就没法玩。** 所以为什么有些同学学这个网络编程，他不懂这个基本知识的话，他一直很蒙圈呢？

**这就是端口。** 这就好比说韩老师给你们讲课：**你们每一个人是不是都有两个耳朵？** 说"老师我没有耳朵"——那不可能，如果你没有耳朵的话，那你真应该去医院看一看了。

**那么你有耳朵，韩老师说一句话："哎，今天咱们中午去吃个红烧肉。"你怎么就知道的呢？因为你长了个耳朵，而且你耳朵随时在监听。**

#### 端口分三类

**大家看到，端口就是出这个房间的门。真正的房子只有几个门，但是一个 IP 地址的端口一共有 65535 个，即 $256 \times 256$，当时把那个 0 也算进去了。**

**端口是通过端口号来标记的，端口只有整数，没有小数。**

端口还有几个比较重要的特点：

| 范围 | 名字 | 谁能用 |
| :---: | :--- | :--- |
| 0 | 保留端口 | 不能用 |
| 1 - 1024 | 固定端口，又叫**有名端口** | 某些程序固定使用，**程序员一般不能用** |
| 1025 - 65535 | 动态端口 | **程序员可以编程使用**，可以指定你监听哪个端口 |

**这个固定端口是什么呢？又叫有名端口，即某些程序固定使用，程序员一般不能用。** 打个比方：

- **22** 这个端口一般不让你用；
- **23**，Telnet 用的；
- **21**，FTP 用的；
- **25**，收发电子邮件用的；
- **80**，一般是 IIS 用的；
- 还有一个 **7**，echo 端口。

很多，很多。**这些端口一般来说，程序员如果你要去自己写一个程序、说我写个程序我去监听，你就不能用 1 到 1024 的端口，不能用。**

**1025 到 65535 是动态端口，这些端口程序员可以编程使用，你可以去指定你监听哪个端口。**

> **结论**：**一般来说端口大家用的时候尽量给它大一点——一般来说你至少四万以上。** 这个一般来说不会冲突，一般人不会用四万以上的，**所以说这样子监听的时候就不会报错。**

所以端口的三大分类就是这样：**0 号是保留端口，不能用；1 到 1024 是固定端口，不要去用，名花有主了，不要去抢；你要用的话用 1025 到 65535 的，这个是没有问题的，这个我们叫动态端口。**

### Socket：一根不会主动断开的双向管子

下面为了方便，我们把 TCP Socket 编程就简称为 **Socket 编程**。

**Go 语言的 Socket 中的客户端和服务器的分布应该是这样子的**：将来我们这有一个服务器端，服务器端会跑一个程序，这边是客户端。**客户端可以有多个，都可以跟服务器端进行连接。连接过后，这个线就代表一个连接。**

> **结论**：**这个连接是可以不关闭的，只要你连上了过后，理论上是不会关闭。**
>
> **什么时候关闭呢？第一个，你主动关闭这条线；第二个，就是超时，一直没有数据，它也会在一定时间给你关闭。**
>
> **但我们 TCP 理论上是不关的，它是个长连接。**

**这个跟 HTTP 协议的连接不一样。HTTP 协议一般是连上过后把数据一发就关了；但是我们 TCP 的连接是长连接。**

一旦连接管好了之后，**我们就可以把它理解成是一个管道，就好像一根管子一样。我们可以从这输出数据**——一般是用 `Write`，这边会有 `Write`。我们通过一个连接，拿到这个连接过后调用 `Write`，我可以把数据写上去，这边就可以去读取。

**每个连接它是能够区分开来的，是张三给我发的还是李四发的，客户端是可以区分的。** 怎么区分的呢？就是靠刚才老师画的这个图——**比如说这个是客户端 A 发的，假设有客户端 B，他们之间就是靠本身的一个区分，靠 TCP。**

大家有一个基本的认识，现在我们准备写代码了。

#### 服务端三步，客户端三步

**待会儿我们要实现这么一个效果**：客户端发送信息给服务器端——

| 客户端发什么 | 服务端回什么 |
| :--- | :--- |
| `who are you` | 我是小冰 |
| 你的性别 | 你猜猜看 |
| 你会什么 | 我会讲故事 |
| 你讲个吧 | 从前有座山，没了 |
| 其它 | 你说啥 |

**当然这个客户端可以有很多个，可以起两个、三个、四个、五个都可以。**

> **结论**：**而且我要求同学们将来做完了过后，它这一块内容可以进行自动学习，它可以自己学习。怎么自己学习呢？**
>
> 这些数据——就是客户端发送的东西和服务器端回送的东西——**咱们可以写一个小程序，让这些内容可以通过文件自动添加。这个文件只要往文件里面放一点他们的对话，它自动对话的信息就会增加。**
>
> **这个文件如果你写得再好，可以从网络去抓，自动去更新这个文件，它就在自我学习——这还是很有意思的，就很智能的一个小东西。**

开发流程是这样的。**服务器端先监听端口，这个端口我们把它设置成比如 8888。然后接收客户端的 TCP 连接，建立客户端和服务器端的连接。然后创建一个 goroutine，我们用 goroutine 来处理。**

> **结论**：**为什么要 goroutine 处理呢？因为我们希望这个服务器能够处理多个客户端的请求，所以我们用 goroutine 处理该连接请求。** 通常客户端会发个连接，发送请求包。

客户端这边怎么处理呢？**建立服务器和客户端的连接，发送请求数据，接收服务器端返回的结果数据，关闭连接。** 当然这个地方可以循环地做，**到时我们发送的数据请求，希望通过终端输入。**

#### 每个客户端起一个协程

首先我会开发一个服务器端，这个服务器端我取个名字叫 `server.go`。**这个服务器端要在某一个端口上进行监听，比如放在 8888 这个端口上监听。至于谁来连接，我不管。**

**在 8888 端口上进行监听的时候，假设来了一个 A 客户端，A 客户端的代码我们姑且叫 `client.go`。它发送了一个请求给我们。它发这个请求一定是找到这个端口的。**

**建立请求后，大家可以互相通信，就不是单向的了——它们之间建立了一个相互通信的管道，也就是 Socket。** 一旦连接建立，**客户端可以发数据给服务器端，服务器端也可以回送数据给客户端，数据就在这个管道里面流动。**

A 客户端可以通信，**B 客户端也可以跟它交流。** 假设有另一个 B 客户端，它的代码跟 A 一样，也可以去连接到这个端口。

> **结论**：**具体来说，它们一旦连接，我们希望为不同的客户端起不同的协程来为它们服务。不能让服务器端主线程一直在这为某一个客户端服务，因为这样会造成阻塞。服务器端在运行过程中有一个主线程，不能让这个主线程死掉。**

```text
                     server 主线程
                  listen.Accept()  循环等待
                          |
          +---------------+---------------+
          |                               |
     来了 A 客户端                  来了 B 客户端
          |                               |
   go func(){ 服务 A }           go func(){ 服务 B }()
          |                               |
   连的是 8888 端口               连的还是 8888 端口
   服务的是这条 goroutine        服务的是这条 goroutine

     前台接待：张三来办事 → 让他去 101 房间找某某某
              又来一个客户  → 让他去 102 房间
```

**当发现有一个 A 客户端来的时候，就在这个地方启动一个协程。** 比如这里是上下文 P，在这里为它启动一个协程服务。**真正通信的时候，连接肯定还是连接到 8888，但真正服务的时候是通过协程来服务的。真正为我们进行通信服务时，是通过端口拿到连接，而真正读写数据时，是协程在两者之间交互。**

同理，**B 客户端来了之后，也可以给它开一个协程。这样就形成了一种分支结构——来多少个客户端就可以开不同的协程为它们服务。**

> **结论**：**这样做的好处类似于：现在有很多客户来找服务器，服务器接受请求后，分配一个协程为你服务，双方建立一种通信关系。但连接还是要走这个端口，端口始终是在的。**
>
> **这就好比服务器是个前台接待，张三找到前台说要办事，接待员告诉他去 101 房间找某某某；又来了一个客户要找张经理办事，接待员安排他去 102 房间。**
>
> **这样来多少个客户端都无所谓，全部开启协程处理，这就实现了并发。**

这就是 TCP Socket 的基本原理图与流程分析。有了这个原理图，接下来就可以开始编写代码。

#### net 包里的 Dial、Listen、Accept

#### Accept 循环和 err 的处理

怎么办？好，**这个 `Listener` 里面有一个特别重要的函数叫 `Accept`，这个函数很牛逼。它是干什么呢？它等待你的连接。如果你没有人连接，我会干什么呢？我在这儿卡那儿，等着你——意思就是说"我等你来啊"。如果一个人都不连接，我就一直等。**

所以这个 `Accept` 是代表我等待你的连接。**那我等待连接我应该是个 `for` 循环，对不对？**

```go
defer listen.Close()

for {
	conn, err := listen.Accept()
	if err != nil {
		fmt.Println("Accept err:", err)
	} else {
		fmt.Printf("Accept 成功，conn = %v\n", conn)
	}
}
```

**`Close` 关闭该接口，使任何阻塞 `Accept` 的操作都不再阻塞并返回错误。** 这个呢使用的是 `defer`，只要你这个 `main` 函数不退出，我就不关闭——**所以这个就要及时的、延迟关闭。**

**注意，在这，循环等待。等待谁？等待客户端来连接我。** 反正我就是一直等嘛。

**这个 `Accept` 它会返回什么东西很重要。** 各位，其实我们让它连接，我们最主要的是要拿到一个什么东西呢？**拿到这根线。** 你没有这个线，你没办法通讯。

**所以说我们可以看到这个 `Accept` 刚好就返回了一个这个东西——`Conn`。**

**有了连接就可以写东西，可以读啊、还可以写——那不就是可以读可写了吗？** 就好像我们打电话一样，我可以说话，我可以听。

**还有什么呢？`Close`，因为这也是一种资源。还有呢，我可以拿到本地地址，还可以拿到对方的地址。**

### 拨号：net.Dial 是怎么用的

先看包：

```go
package main

import (
	"fmt"
	"net"
)

func main() {
```

主包，老规矩。既然是做这个东西，`fmt` 包肯定跑不了——你总得输出点东西；`net` 包也跑不了。这两个是最核心的，就不多说了。`func main()` 主函数，一样的，走。

上来第一件事是连接。连接得有一个专门的函数，对吧？查手册，`net` 包里有一个特别重要的函数叫 **Dial**。

```go
conn, err := net.Dial("tcp", "127.0.0.1:8888")
if err != nil {
	fmt.Println("client dial err=", err)
	return
}
fmt.Println("conn 成功=", conn)
}
```

这个函数的签名是这样的：第一个参数写上 `"tcp"`，第二个参数写上你要连接的那个服务端的 **IP 加它的端口**。

> **注意听，一定是服务端的 IP 加端口。**

为什么这么说？因为一个程序，一定是 IP 加端口才能区分你是跟哪一个进行沟通的，你不能光写一个 IP 地址。这一个 IP 地址上面可以跑几万个程序呢，你知道要找哪一个吗？

最后这个地方会返回一个 `Conn`，这就是连接。你的连接和我的连接是对上了，就跟打电话一样——这个连接，你说的话他能听到。然后这儿可以做一个 error，如果它不为空，你可以 handle，就是处理这个 error。如果成功的话，你就可以做你的其他的工作。

代码这么写：`"127.0.0.1"` 是本地地址，这样写更准确一点，兼容性也更好。至于更正式一点的做法——我一会儿会说，这个 IP 地址后面我们要把它做活，要写成一个 `configure.ini`，从文件里读，不能写到程序里写死。写死的话，每个客户端不一定一样，它可能会变化呀，所以说最好从一个配置文件里面读取。

写完 `8888`，这句话的意思就是说，我要连这个服务器上面的 8888 端口上的那个监听程序。

`err != nil` 就说明我们连接失败了，我把这个错误信息打出来——这叫 Dial，客户端的 Dial 函数失败，error 等于错误信息，原因给打出来。**但是如果你连都连不上，这个地方肯定要 `return`**，你自己跟人家连不上，你还干啥？啥事都别干了。

### 顺手看一下：对方到底是谁

`conn` 是一个接口，里面有大量的方法。

有意思的是 `net` 包里还给你准备了另一个东西：`bufio.NewReader`。它可以去创建一个 reader，而这个 reader 它可以接收键盘的输入。以前我们是一个字符一个字符，太慢了，它就一行一行输入。这个地方又给我们提示了一个 `NewReader` 可以去指定一个连接——看到没有？它当然也可以从键盘，很有意思。

`go run client.go` 跑一下，服务器那边会闪一下“等待客户端连接”，客户端这边会打印 `conn 成功=`，这就说明连上了。

那如果说，韩老师，我想在服务器知道是哪一个客户端连到我这儿，行不行？当然可以。客户端连上之后，你就可以拿到对方的 IP。

怎么拿？这个 `conn` 它有一个方法，名字叫 `RemoteAddr()`。它返回的是一个 `Addr`。这个 `Addr` 是个什么玩意儿？先把这个粘过来，看它是个字符串还是什么东西。

点进去看一下——大家可以看到，它是一个接口。既然是接口，调用它的 `String()`，是不是就可以拿到字符串格式的地址？这样我就可以拿到到底是哪一个客户端连到我的了。

我把服务器的 `conn` 打出来看看：

```text

客户端IP=192.168.20.253:51741
```

看，非常清晰了。各位同学看，客户端这边是不是也有端口？而且这个端口是随机分配的。你这边（服务端）端口是固定的四个 8（8888），但是客户端不一样。大家可以再看，我退出再连一次，端口又发生变化了：下一个是 56602。

> **结论**：一次连接 = 服务端的固定监听端口 + 客户端的随机端口。这个客户端端口是 TCP 协议分配的，`RemoteAddr().String()` 一行就能拿到。

```go
	}

	// 如果用户输入 exit，就退出
	line = strings.Trim(line, " \r\n")
	if line == "exit" {
		fmt.Println("客户端退出...")
		break
	}

	// 发送给服务器端，补上换行符
	_, err = conn.Write([]byte(line + "\n"))
	if err != nil {
		fmt.Println("conn.Write err =", err)
	}
}
```

把这部分包裹起来之后，这里有一个问题：你在不停地往服务器端发送，写了一句再发送，现在没法退出。所以我们在这里应该做一个判断，当用户输入的内容是 `exit` 关键字的时候就退出。

问大家一个问题：**如果我直接拿 `line == "exit"` 这样写，对不对？有没有问题？**

哪里写错了？逻辑上这样写是不行的。因为在读取终端输入的时候，字符串本身是带了 `
` 或 `\r
` 的。所以你在比较的时候，应该先把 `line` 进行一个处理，把换行符去掉。大家还记不记得怎么去掉？

非常简单，使用 `strings.Trim`：对 `line` 中的 `\r`、`
` 以及空格进行截取去除，然后再来判断是否等于 `exit`。如果要使用 `strings` 包，我们还需要在上面引入 `strings` 包。

### 去掉换行的代价：得手动补一个

我这样做了之后，同学们想一想，客户端和服务端那边有没有问题？**你在写这边代码的时候，要同时考虑 Server 端。**

运行 Server 端起来，测试客户端。输入 `Hello`、`abc`，可以看到客户端输入后，服务端在循环等待。但是服务端终端老是打印「等待输入」提示很不友好，因为只要客户端不回车，它就一直在等待。所以我们第一件事把 Server 端的这个等待提示信息去掉。

去掉提示信息后重新编译运行。在客户端运行并输入 `hello world`、`北京你好`，这时会发现一个奇怪的现象：**服务端打印为什么没有换行？**

这是因为你在客户端把 `\r
` 去掉了，去掉之后发送给服务器端的数据就没有换行符了。所以我们在向服务端发送写入连接时，需要手动把换行符补上：

```go
_, err := conn.Write([]byte(line + "\n"))
```

这样代码就改好了。重新测试：输入 `hello world`，回车；输入 `北京你好`，回车；输入 `大家好`，回车。

> **易错点**：这两个动作是一对——为了判断 `exit` 你把换行 `Trim` 掉了，那就必须在上行时手动补 `
`，否则服务端 `Print` 出来的内容会全部糊成一行。

### 两个客户端同时在线，协程在扛

现在是一个客户端在交互。如果我再起一个客户端，看服务端能不能同时接收。现在相当于有两个客户端连接到服务端了。大家可以看到，现在有两个客户端处于连接状态。

在第二个客户端运行 `go run client.go`，连接成功，服务端提示又有新的客户端连接上来。在第二个客户端输入 `abc`、`1234567`；在第一个客户端输入 `A 说：大家好`——服务端都能分别接收并打印出来。

这说明我们现在已经完成了两个客户端连接到服务端，由服务端起了两个不同的协程为它们服务。

然后我们在客户端输入 `exit` 退出。**一退出，服务端也能捕获到这个消息并打印退出。** 它是怎么捕获到的呢？是因为客户端断开后，服务端在读取时发现了 `io.EOF`，知道远端主机关闭了连接，进而退出协程。

这就是我们完成的循环输入与退出案例。

### 一次翻车现场：为什么必须 `buf[:n]`

这里有一个细节问题需要提醒大家注意。我曾经在写这个案例的时候犯过一个错误，而且特别不好排查：在服务器端读取时，我当时没有使用读取到的字节数 `n`，而是**直接对整个缓冲区切片进行了转换**。

因为你的缓冲区可能有 1024 字节，如果不按实际读取到的长度 `n` 截取切片，直接转换就会带入多余的空字符或脏数据，引发很多不确定的错误。

那个缓冲区到底有多大？后面有什么内容？不知道。因为他在给你内存里面分配一个 1024 字节的时候，里面前面有没有什么内容不清楚。他切了 1024 个字节，字节里面有可能预先已经有些内容了。

如果你这样写会出现一个什么情况呢？我给大家演示一下。按理说大家可能会觉得也对——不就是读了一些数据，从这个连接里面读了一些数据放到这个 buffer 里面吗？但是没有考虑到这个 buffer 后面的内容可能会导致整个输出会有问题。

我当时就犯了一个错误，我还看了一阵才把它解决的。我先退出，跑一下我们的 server，这块都没毛病。然后运行这个 client 端，这个地方逻辑上面也没问题，它也等待你连接，我说 `hello`。

**然后就出现了一个非常奇怪的现象。**

> **结论**：所以一定要使用 `buf[:n]` 进行切片处理，这个地方一定要特别小心谨慎。

### Redis 是什么：一个「数据结构服务器」

首先，我们看一下 Redis 的基本介绍。

Redis 是一种 NoSQL 数据库，这是一个基本常识。什么叫 NoSQL 数据库呢？它不是传统的这种关系型数据库。我们听到像刚才老说的 MySQL、Oracle，它都是关系型的，它有主键、外键这样一些东西来进行一个关联。那么 Redis 呢，它不是传统的这种关系型，它是一种 NoSQL 数据库。

那么它的官网呢——大家可以去看一下，这是它的官网，里面有下载它的软件。这个我也不多说，因为后面我们直接带大家安装软件就行了。

你看，这里面讲得很多。这个 Redis 现在还是比较火的，现在几乎学 Java 的同学应该都学过 Redis 吧，我估计。这里面它有很多类型，比如字符串、哈希、列表等等，这里面做了一些介绍，什么 list 是干什么的等等，这里面都有一些介绍。

那么第二个要知道的是 Redis 它的**全称**是什么。Redis 的全称是 **Remote Dictionary Server**，就是远程字典服务器。远程字典服务器，翻译得很生硬，其实说白了就是就是一个服务器，里面存数据的。

那么 Redis 性能非常的高，**单机能够达到 15 万个 QPS**。这个 15 万的 QPS 已经很高了，就每秒的读写率很高的这个，15 万已经很高了，至少比一般的这种关系型数据库要高很多，所以它的速度非常快。

它非常的适合做缓存，也可以持久化。它既可以做缓存，又可以持久化，很厉害。也就是说，**它既可以把数据加载到内存，同时也可以定期地把数据直接给你持久化到文件里面去。**

而且它有几个性能：**一个是开源、高性能、分布式**，它也支持分布式。它是**基于内存并支持持久化**，是目前最热的一个数据库之一。

它也叫**数据结构服务器**。为什么管它叫数据结构服务器啊？有道理。因为他支持的数据类型都跟数据结构相关。你比如说最经典的哈希，它支持哈希、哈希表的结构，它支持 list 这个结构，它还支持集合，叫 set。所以说，如果说同学们学过数据结构，听起来就更轻松了。

读图：左边是我们写的 Go 代码（`xx.go`），右边是那个专门用来测试的 `redis-cli`，两者都把指令发给 Redis 服务端的 6379 监听层；监听层把指令交给核心组件去解析、执行，操作的核心对象就是那一大块内存里的数据，处理完还可以落盘到 `dump.rdb` 这样的文件里。

这里要强调一点：只要是服务一定会有监听端口，跑不了，它默认应该是 6379。

那么这个时候呢，我们假设这里有个客户端，比如我们写的一个 `xx.go`，这是我们的 Go 代码，它肯定要连接嘛，它肯定连接到我们这个 Redis 这个服务来了。连接上了过后呢，它在这一边可以发出一些指令。

> **注意这个指令是什么指令呢？待会儿再说，肯定无所谓就是增删改查，只是形式不一样。**

那它把这个指令发给谁呢？它先发给我们这个监听的这个服务。这个核心组件就会去解析你的指令。什么叫解析呢？就是解释一下你的指令，然后它做相应的处理。

#### 内存里到底装着什么

那么主要是处理什么呢？它在这个地方**有一块内存**，注意听，它维护了一块内存。

那这个内存里面有什么呢？说白了就是一堆数据。这数据有什么形式的数据呢？各位同学，最常见的是**字符串**。字符串呢它一般是以 key-value 的形式来保存，当然可以有很多。

还有一种呢就叫**哈希**。这个哈希呢也是一种数据结构，它在这里面有很多的哈希数据，也是大量的数据。待会儿我们再具体说这些数据是什么样子的。

然后还有经典的 **list**。List 呢也是一种数据结构，它的数据呢，它的结构是以 list 形式来维护你这个数据的。

当然这些都是数据，都是它的组织形式而已。数据可以放任何数据，比如说咱们的字符串、int，它反正放在内存里面都是字符串了。

当然还有呢，就是我们的一个 **set**。Set 就是集合。集合这种形式的数据它也能存。

还有一种就是 **zset**，有序，zset，有序的集合，就叫有序集合。当然有序集合呢跟上面唯一的区别就是它是有顺序的。

> **结论**：在这个内存里面它维护的数据形式呢主要就这么五大类。

好，所以说它在这个地方处理的时候，说白了它就往里面扔东西。至于怎么扔、怎么取，就它的事了，它能够去操作我们这里面的东西。当然具体来说就是它这个相应处理会往里面扔或者从里面取。

#### 内存会丢：所以还要落盘

但是它还有一种机制。久了过后呢，因为整个这块都在内存里面，数据都在内存里面，有一个问题——因为你有些数据老在内存呢，你不落盘也很危险。你打个比方吧，我关机了，对吧？你关机了，内存里面数据就没有了，那怎么办呢？

所以它还涉及到持久化的问题。那么它也可以将你的数据真正地给你落库、入库。这个库啊本质是文件。我最好不要画这个东西，画这个大家容易理解错误——它会有文件，它会真正地存到自己的那个文件里面去。这边就是它最后可以保存到的这个文件里面去，一般我们叫 `dump.rdb` 啊等等。然后呢到时候这里面的东西呢可以直接落盘。

好，但是它是落盘了过后它还能读出来，落盘过后它还能读出来。

#### redis-cli 也能连

那有一个问题，说：「老师，我通过这个 Go 程序可以操作 Redis，那我还可以通过什么呢？」还可以通过这个也行，就是这个程序也行。

它也提供了一个专业的工具，就是我们的这个 Redis 开发者呢，他为了让我们学习比较方便、操作比较方便，他也提供了一个专业的一个叫 `redis-cli` 的程序，这个呢也可以去操作我们的这个 Redis 服务器。

也就是说，你在这儿呢也可以直接双击我们的这个程序，它也可以连接到哪里呀？它也可以连接到我们的这个指令区。它可以连上去，这很正常。这跟我们今天上午讲的聊天室一样，**我一个端口当然可以连接多个人了**，它也可以通过这边发送指令去操作、去玩，两个都可以。

当然实际开发中肯定这个用的是最多的，显然这个用得最多，咱们不可能说每次用这个指令去手敲，对吧？这个肯定是个重点。

后面我们重点学的是什么呢？一个是 Go 程序怎么操作，第二个就是这个地方怎么操作。

> **结论**：它们的指令很像，它们指令的形式非常非常像，操作这个指令的形式非常像。所以说我们学完 Go 这边过后，再去看看这里面发出指令，基本上不用学了，只需要我们去稍稍地加载一个 Redis 的第三方插件就可以了。
