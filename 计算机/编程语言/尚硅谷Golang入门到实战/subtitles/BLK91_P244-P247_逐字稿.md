我们接着来看一下文件的基本操作。

首先，先领着大家来初步认识一下文件。在 Go 语言里面，我们要去操作一个文件，首先要先打开一个文件。你既然要对这个文件进行读或者写的操作，或者修改的操作，那你首先应该打开一个文件。在 Go 语言里面，它是怎么样打开一个文件的呢？

大家看这里，`os` 包里面提供了一个 `Open` 函数。这个 `Open` 并没有跟 `File` 直接绑定，它就是 `os` 包里面的一个 `Open` 函数。它干什么呢？`Open` 打开一个文件用于读取。如果操作成功，返回的文件对象可以读取数据。这里面直接给它传一个字符串就可以了，它会返回两个参数：一个是返回一个文件的指针，其实它返回的就是 `File` 这个结构体的一个指针。因此我们可以看到，文件其实是个指针类型。你打开一个文件过后，它返回的是 `File` 这个结构体的一个指针类型。换言之，我们文件准确地讲它是一个指针类型。同时会返回一个 `error`，也就是说如果打开失败，它会返回一个 `error`。

打开一个文件过后，我们还有一个特别重要的操作：当你对文件进行操作完毕以后，比如说读或者写做完了以后，你必须要记住一件事情，要关闭文件。关闭文件是怎么做的呢？在 `File` 这个结构体里面有个 `Close` 方法。`Close` 是关闭这个文件的，它是 `File` 这个结构体指针类型绑定的一个方法。干什么呢？使文件不能用于读写。这个时候如果关闭错误，它会返回一个 `error`；如果成功当然就没有错误了。这两个是我们打开文件和关闭文件最常用的方法。

我们给大家演示一下第一个案例，就是打开文件和关闭文件的一个演示。

首先我们要说一下，它使用的函数和方法是：打开这个文件用的是 `Open` 函数，要很清晰地知道它是干啥的。

它使用的是：
```go
func Open(name string) (file *File, err error)
```
这个 `name` 就是写上你这个文件的路径，就是你打开是哪个地方的文件。然后它返回是一个 `File` 这个结构体的指针类型，同时如果有错误返回一个 `error`。你打开完了过后，其实你后面要用的就是它了，因为通过它就可以对文件进行读操作或者是写操作。这是一个方法。

另外，关闭文件我们用的是 `Close`：
```go
func (f *File) Close() error
```
这就是关闭文件。如果说你这边关闭失败了，那就会返回一个 `error`。注意，这个 `Close` 它是跟 `File` 结构体指针类型绑定的，也就是说你不能直接去用这个 `Close`，你必须是用 `File` 结构体指针这种变量才能调 `Close`。

当函数退出时，要及时的关闭 `file`。怎么做呢？用 `defer`。前面学通过，`defer` 就是说在函数结束之前，它会调用 `defer` 后面的这些代码。写上：
```go
defer file.Close()
```
这样写是最合适的，在函数退出的时候再去调用 `file.Close()`。这样就会避免文件句柄的泄漏。要及时关闭 `file` 句柄，否则会有内存泄漏。这点大家要注意一下。因为 `defer` 是函数退出时才去调用，所以下面还是可以正常使用文件句柄的。关于 `defer` 关键字的运行机制，前面已经讲过，这里就不再反复多说。

文件打开之后，下一步就是创建一个 `Reader`。这个 `Reader` 是带缓冲的，它是一个指针类型。看看这个 `Reader` 是什么样子的。先把函数写出来，在 `bufio` 包里面有一个函数叫 `NewReader`，把 `file` 写进去，这会返回一个 `reader`。

看看这个 `Reader` 是什么，打开文档。在 `bufio` 包里面有一个函数叫 `NewReader`。`NewReader` 会返回一个 `Reader` 指针类型。点开可以看它的源代码：
```go
// NewReaderSize returns a new Reader whose buffer has at least the specified
// size. If the argument io.Reader is already a Reader with large enough
// size, it returns the underlying Reader.
```
这个 `Reader` 是带缓冲的，而且默认缓冲区为 4096 个字节。它是带缓冲的输入，也就是缓冲输入。看源代码，这就是 `Reader` 结构体：
```go
type Reader struct {
    buf          []byte
    rd           io.Reader // reader provided by the client
    r, w         int       // buf read and write positions
    err          error
    lastRuneSize int       // size of last rune read for UnreadRune; -1 means invalid
    lastByte     int       // last byte read for UnreadByte; -1 means invalid
}
```
里面会有缓冲，这个缓冲默认大小是 4096 个字节。默认缓冲区为 4096。

有缓冲有什么好处呢？如果有缓冲，在读取文件的时候并不是一次性把整个文件读到内存，而是读一部分处理一部分，这样可以处理一些比较大的文件。

有了 `reader`，下面就循环读取文件的内容。既然是循环读取，那就是一个 `for` 循环。在这个 `reader` 里面有一个方法叫 `ReadString`：
```go
str, err := reader.ReadString('\n')
```
传入一个结束符 `'\n'`。这句话的意思是，用这个 `reader`——因为 `reader` 已经跟 `file` 文件绑定了，通过 `reader` 去读取文件的内容。读到多少就结束呢？读到一个 `'\n'`。`'\n'` 是换行符的意思，读到一个换行就结束一次。

也就是一行一行地读。文件里面第一句话先读到 `hello, world!`，一换行再读取第二行，循环地读。因为读到一个换行，这个换行符在编辑器里如果打开显示所有字符，可以看到确实有一个换行符，只是平时隐藏起来了。每读到一个换行符就结束。

读取的时候，`reader` 会返回两个变量、两个结果：一个是 `str`（`string`），一个是 `err`（`error`）。读取的内容会放在 `str`，如果在读取过程中产生了错误，会把错误信息放在 `err` 变量。`str` 是它具体的内容，而 `err` 是在读取过程中产生的错误信息。

既然如此，我们就可以来做一个判断：
```go
if err != nil {
    // 错误处理
}
```
有一个错误是 `io.EOF`。如果 `err` 等于了 `io.EOF`，`io.EOF` 表示文件的末尾（End of File）：
```go
if err == io.EOF {
    break
}
```
表示文件的末尾，就应该结束读取，`break` 就行了。`io.EOF` 代表文件的末尾。

如果还没有到文件末尾，就反复读取。读取一行就把这个内容输出，输出内容用：
```go
fmt.Print(str)
```
不要打 `ln`（`Print` 即可），因为 `str` 本身就会把换行符也读进去。如果打一个 `Println` 的话，就会有两个换行。直接把内容输出：`fmt.Print(str)`，这个 `str` 就是从文件里面读到的。

等到不停地读、不停地读，最终读到文件末尾就退出来了。最后输出一句话：“文件读取结束”。

```go
	// 当函数退出时，要及时的关闭file
	defer file.Close() // 要及时关闭file句柄，否则会有内存泄漏

	// 创建一个 *Reader，是带缓冲的
	/*
		const (
			defaultBufSize = 4096 // 默认的缓冲区为4096
		)
	*/
	reader := bufio.NewReader(file)
	// 循环的读取文件的内容
	for {
		str, err := reader.ReadString('\n') // 读到一个换行就结束
		if err == io.EOF { // io.EOF表示文件的末尾
			break
		}
		// 输出内容
		fmt.Print(str)
	}

	fmt.Println("文件读取结束...")
}
```

这里用到了 `io` 包的 `io.EOF` 常量，需要把 `io` 这个包也引进去。代码就没有问题了。等到函数退出的时候，它会去调用 `defer`，把文件句柄进行关闭。这样就相当于把一个文件读取完成了。

下面我们再为大家介绍第二种读取文件的应用方式。

前一种方式是带缓冲的，是一次一次地读入。在 Golang 里面还有一种方式读取文件的内容并显示在终端，在 `ioutil` 包里面有一个方法叫 `ReadFile`，它可以一次性将整个文件读入到内存中，也就是一次搞定。这种方式比较简单、比较直接。

这种方式有一个前提，它比较适用于文件不太大的情况。如果文件比较大，用这种方式就不太好了，如果文件比较大，还是用前面带缓冲的方式。如果你这个文件比较小，咱们就直接用 `ioutil` 包里面的 `ReadFile` 一次性就可以把它读进来了，而且文件也不用打开，因为它把文件的打开和关闭整个操作都封装到 `ReadFile` 函数里面去了，所以看起来比较简洁。

```go
package main

import (
	"fmt"
	"io/ioutil"
)

func main() {
	// 使用 ioutil.ReadFile 一次性将文件读取到位
	file := "d:/test.txt"
	content, err := ioutil.ReadFile(file)
	if err != nil {
		fmt.Printf("read file err=%v", err)
	}
	// 把读取到的内容显示到终端
	fmt.Printf("%v", string(content))
}
```

现在我已经把文件指到了 D 盘下面的 `test.txt` 文件。我们用一个方法就可以搞定了，`ioutil` 包下面有一个函数叫 `ReadFile`，直接把 `file` 放进去就可以了。这个函数会返回两个值，一个是它读取到的内容，我们看一下：在 `io` 下面的 `ioutil` 这个包里面有一个方法叫 `ReadFile`。它传入的形参是文件的名字，实际上就是文件的全路径；它返回的是一个 byte 切片，也就是按字节的形式返回的，同时有个 `error`。如果有错误，error 就不会为 nil。

所以在此处把文件名字写清楚，然后有个 `content`，有个 `err`。这个 `content` 就是 byte 切片。如果 `err != nil` 说明出错了，把错误信息打出来：`read file err=%v`。如果没出错，我们把读取到的内容显示到终端。

直接输出 `content` 的话，大家想一想，这样输出的是什么内容？它实际上输出的是一个切片，是一个 byte 切片，所以你会看到一堆数字，因为 byte 按输出的时候是按数值打印的。

还有一点，如果大家认真观察的话会发现我没有打开这个文件就直接读取了。因为你没有打开，所以你也不用关闭，没有 `Close` 的方式。因为文件的打开和关闭都被封装到 `ReadFile` 函数内部了，因此我们不需要去管理。因为我们没有显式地 open 这个文件，因此也不需要显式地 close 这个文件，因为文件的 open 和 close 被封装到 `ReadFile` 函数内部了，所以这个地方显得就比较简洁。前面我们还写了不少代码，还 defer 了一下，然后循环地去读取，而这个地方直接一个函数就把内容读出来了，输出就完事，显得很简洁。

但是有一个前提：这种方式因为是一次性把整个文件内容读进来，如果文件过大，效率就会很低。因此这种方式只适合文件不太大的情况来使用。所以我们这里没有打开，也没有关闭，不需要显式地关闭。
