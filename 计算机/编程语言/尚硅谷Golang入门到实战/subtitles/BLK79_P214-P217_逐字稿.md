我们来看一下接口的，系统的介绍一下接口的概念和它的基本语法。

interface 这个类型就是接口类型，接口里面可以定义或者叫声明一组方法，这些都是不需要实现的，也就是说我们接口里面的方法都不要去实现。并且 interface 不能包含任何变量，这点大家记住。

我们在学过其他编程语言里面，接口是可以有变量的，或者叫常量。但是在我们 Golang 里面的接口，它是不允许有任何变量的，不管什么变量都不能有。那么到某个自定义类型，比如说结构体 Phone，需要使用的时候，再根据具体情况把这些方法写出来。写出来我们这就叫实现这个方法，就叫实现。特别强调一下，没有任何变量。

第二个，基本语法我们再来系统的说一下。它的基本语法是这样子的：

```go
type 接口名 interface {
    Method1(参数列表) 返回值列表
    Method2(参数列表) 返回值列表
    ...
}
```

`type` 和 `interface` 是关键字。在这里面你可以定义很多的方法，或者叫声明很多方法：方法名、参数列表、返回值列表。当然方法名、参数列表、返回值列表，里面点点点。也就是说在这个接口里面，你的方法可以是多个的。比如说我们在前面 USB 是不是就声明了两个方法，一个是 `Start`，一个是 `Stop`。但是我们这个方法特别简单，没有形参，也没有返回值，对不对？这是可以写多个。

什么叫做实现了接口呢？所谓实现接口有两层含义：第一个就是把这个方法具体的内容写出来；第二个，实现接口还要包含一个东西叫所有方法。你不能说我只把接口里面的这一个方法给它写出来了，我就认为是实现这个接口了，这是不对的。它是把所有的、把这个接口里面所有的方法都实现了，那么我们才叫实现了这个接口。比如这边看：

```go
func (自定义类型) MethodName(参数列表) 返回值列表 {
    // 方法具体实现
}
```

自定义类型可以是任意的，比如说前面我们的 `Phone`，也可以是 `Camera`。自定义类型完全是你自己定义的。A 自定义类型可以去实现这个接口，那么 B 自定义类型也可以去实现这个接口，能理解？这个是方法名、参数，后面是一样的。这部分叫函数的签名，老师现在高亮的部分叫函数的签名。函数的签名要跟它完全保持一致，不能不一样，一定要一样。

这是基本语法。这有几个小结说明：接口里所有的方法都不能有方法体。我给大家举个例子，比如说这里，你不能多写一句话说我来写一点东西在里边，这个就不行。你像这样写的话，它立马给你报错。你看，马上报错，这是语法出错了。它不期望这边有一个什么逗号之类的，也就是说这个方法是不会有方法体的。这是第一点要注意的。

我们接着来看一下接口的注意事项和它的细节说明。

这里我一共总结了有十个细节和注意事项，我们分成两个部分来讲。我们先来看第一部分。

接口本身是不能创建实例的。也就是说，接口它本身不能定义一个变量，你不能直接用接口来创建一个变量。那我给大家举个例子，还以此为例。我干脆新建一个文件，不然都在一个地方就打架了。我新建一个文件叫 interface details。然后我们新建一个文件叫 main.go。前面我们打一个包包过来，共有的代码我们粘一份过来。主函数：

```go
package main
import "fmt"

type AInterface interface {
    Say()
}

func main() {

}
```

现在我假设有一个接口，我有一个 `type AInterface interface`，它的类型就是 interface。然后这里边假设我们有一个方法叫做 `Say()`，就写一个方法就行了。注意，你不能这样去搞一个变量，说写一个变量名叫 a，它的类型叫这个东西：

```go
var a AInterface
a.Say()
```

你这样直接写了过后，其实它是没有什么东西的。实际上这个东西必须有一个变量去指向它才行。所以一般来讲，接口本身不能创建实例，但是它可以指向一个实现了该接口的自定义类型的变量。

那这个怎么理解呢？比如我举个例子。你像这样子去直接调这个 `Say()`，肯定调不起来的。保存一下，运行一下看。切换到接口的 details 目录，然后 go run 一下 main.go，我们看看这边会提示什么信息。大家可以看到直接报错了，提示无效的一个地址，也是个空指针。也就是说，你直接去用这个接口去调它肯定是起不来的，因为这个方法都没实现过。

你要用它怎么用才可以呢？它自己不能实例化，但是它可以指向一个实现了该接口的自定义类型的变量。比方说，我这里有一个结构体叫 Stu：

```go
type Stu struct {
    Name string
}

func (stu Stu) Say() {
    fmt.Println("Stu Say()")
}
```

我让 Stu 来实现这个接口。写一个 `(stu Stu) Say()`，把这个方法写进去，输出一句话，Stu 里面的一个 Say 方法。这个时候它可以这么玩，我先去创建一个 Stu 结构体的变量，然后我把它赋给它：

```go
var stu Stu
var a AInterface = stu
a.Say()
```

这个时候就可以调用起来了。这个是一个结构体变量，而且它实现了 Say 方法。既然它实现了 Say 方法，它就实现了这个接口。于是乎，我把这个变量交给它是可以成功的。然后再通过 a 去调，这个时候它就把 Stu 里面的 Say 方法调起来了。我们来运行看一下效果，发现没问题。

但是有一点，如果说你没有实现这个方法，那是不可以给的。比如我把方法注释了，这样给它就会报错：`cannot use stu (type Stu) as type AInterface in assignment`。为什么呢？`Stu does not implement AInterface`，没有实现这个 A 接口。所以这个特点大家要注意一下。

我们把这个特点整理到笔记里面去：
注意事项第一点：接口本身不能实例化。它本身不能直接去创建一个所谓接口数据类型的变量，因为它的方法是需要别的自定义类型来实现的。但是它可以指向一个实现了该接口的自定义类型的变量。

前提是这个变量对应的类型实现了对应的方法，也就实现了这个接口。

第二点，接口中所有的方法都没有方法体，即都是没有实现的方法。这一点在前面我们已经讲过了，就不再多说。

第三个接口的注意事项：在 Golang 中，一个自定义类型需要将某个接口所有方法实现，我们才说自定义类型实现了这个接口。缺一不可，每一个都要实现。

第四点，一个自定义类型只有实现了某个接口，才能将自定义类型的实例赋给这个接口类型。这其实和第一点说的是同一个问题。

第五点比较重要，经常作为一个面试题：只要是自定义数据类型，都可以实现接口，而不仅仅是结构体类型。我们前面都是用结构体这种类型来实现接口的，但实际上它不一定是结构体。

比如我这里定义了一个类型叫 integer，它是 int 类型的：

```go
type integer int

func (i integer) Say() {
    fmt.Println("integer Say i =", i)
}
```

我也可以对它来实现这个接口。写 `func (i integer) Say()`，实现 Say 方法，打印出 i。此时此刻，integer 这个类型的变量也就实现了这个接口。怎么体现呢？

```go
var i integer = 10
var b AInterface = i
b.Say()
```

我定义了一个变量 `var i integer = 10`，这个时候也可以把它赋给接口。为什么可以？因为 i 对应的类型叫 integer，integer 又实现了 Say 方法，那就间接地实现了 AInterface 这个接口。这个时候通过 b 来调用 Say 方法也是成功的，输出 `integer Say i = 10`。也就是说，普通的高非结构体的自定义类型，其实也可以实现接口。只要把它的方法实现了，就实现了这个接口。

我们来运行一下看效果，发现没问题，输出 `integer Say i = 10`。后边有些程序员会针对某一个自定义的非结构体类型去给它实现接口。
