首先我们来看看Golang的学习方向有哪些。Go后面这个lang代表什么意思？Go语言我们也可以简单地写成Golang，其实它是Go language的一个简称。因为后面这个词太长了，我们在行业里面一般叫Golang，简写Golang。所以别人说Go语言，有些程序员说“你Go语言学得怎么样”，有些说“Golang现在又出了一个新的特性”，同学们都知道说的是同一个意思。

第一个，同学们如果将来想去做区块链的研发工程师，大家都知道区块链现在闹得沸沸扬扬的，也比较火。如果你要从事区块链研发工程师，那么你就应该学一下Golang。为什么？因为区块链主流的开发语言就是Golang。我们学下Golang将来就可以去做区块链研发工程师相应的职位。区块链说白了，其实就是叫做分布式账本技术，它是一种互联网技术。它的核心思想就是去中心化，让认人都可以参与数据库的记录。这是区块链的一个核心。比如现在虚拟货币，还有金融这方面，区块链现在用得就比较多。现在很多培训机构都陆陆续续在做区块链的培训，就是因为这是一个方向。谁先走在前面，在区块链还没有完全起来的时候你先走在前面，那你前景就会很光明，因为你做得越早，机会就越多。

第二个，如果你将来要做服务器端的开发。目前服务器端主要使用的是什么语言呢？C、C++语言偏多一点。只要是C和C++可以做那些事情，Go都可以做，而且做得更好。为什么？因为Go语言本身的设计者有三个主要的设计者，其中有一个设计者叫Ken Thompson。Ken Thompson本身C语言就是他来设计的。他既设计了Go语言，又设计了C语言，而Go语言是后面设计的，所以他其实在某些方面会把C语言的设计理念优化一下。C和C++做的事情Go都可以做，比如处理日志、数据打包、文件系统等等。比如现在大家都知道美团，美团后台流量的支撑、后台流量的程序其实就是用Go语言写的。

Go语言在这块体现出它的一些优势：一个是数据的处理比较厉害；第二个，它处理大并发比较厉害。这也是它的一个优势。现在的网站越来越多，平台越来越大，现在的用户量动辄就是几千万，像新浪、搜狐或者是腾讯，这样的网站有时候一个并发下来就是几百万，那你怎么样去处理大并发呢？Go语言在处理并发上非常的牛。第一个是Go语言数据处理能力很强，第二个是处理大并发也很强。所以现在在后台做服务器端的，Go语言用得比较多。

在后台游戏开发的时候大家都知道，游戏开发有时候也会用到数据通道。打个比方，你们玩游戏的时候，你点一下游戏，用一把刀砍了一个人，为什么另外一个伙伴跟你一组的人能够看到你这个动作呢？其实后台有一个数据通道在帮你支撑。这个时候用Go语言也是非常强的。现在很多游戏软件的后台，尤其是数据通道这块，用Go语言开发也比较多。

再看Go语言还可以做什么。比如你将来想做一下分布式云计算这方面的工作，Go语言也用得比较多。举两个比较经典的案例：第一个是盛大云GrandCloud；还有一个叫京东，京东后台的消息推送服务以及分布式文件系统，它们后台全部都是用Go语言来做的。

总结一下，你会发现Go语言学完了过后，你可以做这几个方面的工作。当然，你光会Go语言还是不能做这些的，它是作为一个核心。你将来做区块链开发，就必须要用到或者主要用到了Go语言；将来做服务器端或者游戏软件工程师，你也可能会用到Go语言；将来做分布式云计算，你也可能用到Go语言。所以Go语言的应用场景还是比较多的。

第二个呢，我在讲课的时候，希望同学们在学 Go 语言的时候，先要建立一个整体的框架，然后再细节。怎么个意思呢？就上来的时候，先不要去把细节扣得太厉害。你首先把整体的一个框架、这个东西是什么了解了，然后再往里面一步一步深入去学习。就说我提的一个观点，学东西的时候，先整体框架，然后再细节。明白我意思吧？这个地方大家要注意一下。

第三点呢，在听课的时候，老师会带大家去学习一种能力。什么能力呢？这个也是实际工作中需要同学们的一种能力，就是要培养用到什么能够快速学习的这个能力，明白我意思吧？因为我带的学生比较多了嘛，后面很多同学说：“老师，我们在工作中的时候，有一个知识点你没有讲过咧。”我说：“那很正常啊，对不对？如果说老师都讲过，这怎么可能呢？你在大学里面学了那么多东西，你说实话，你在工作中用过几个？我能够保证就是我们讲过的东西你在工作中 80% 以上的都能讲得到，但是毕竟还有 20% 你没有接触到，因为你将来的环境我们是不知道的。老韩也不知道你将来在工作中你会遇到什么问题，对不对？我只能说把我们能够讲的细致详尽地讲完，但是毕竟不可能说 100%。”所以大家在听课的时候，老师会带大家去培养这种能力。比如说，我会带大家看手册；比如说，在遇到一个问题的时候，我会教你们怎么去调试；再比如说，遇到一个技术难题，咱们从几个方面下手把它拿下。这是老师要说的这么一点。所以老师在讲的时候会有这种启发的东西在里边，我会告诉你们：“同学们，这个知识点这个地方先暂时不讲，你们能不能先搞定？”然后我在下一讲再给大家把这个答案公布出来，明白意思吧？好，这是老师要说的这个问题。

第四点，我要给大家打个招呼，先 know-how 再 know-why。这个又想起我在上大学的时候，上大学的时候，清华有个特别牛逼的一个老师，年纪大概有四五十岁吧，特别有特点，讲话的时候就是歪着一嘴巴，也不知道为什么。他就跟我们讲，他说我们学的这个计算机编程它是种工科。注意啊，我们计算机它是一种实践性很强的，它属于工科。这个工科有一个什么特点呢？就说你不一定把这个东西搞得很明白，但是你能做出来。这个跟我们去学习数学和学习物理不一样。就说有时候你做出来了，你不一定知道为什么，明白我意思吧？所以说我们在这种时候，有时候先不要刻意地把每个东西都要说为什么、为什么、为什么。当然你问为什么这是对的，但是有时候它是这样子的，你先做出来过后，你回头再一看，哦，原来是这个原因。能理解我的意思吧？如果不这样的话，我们天天都在想这是为什么为什么，但是我们不去动手，不去做出来，好，你永远不知道为什么。明白我的意思吧？所以说我提出一个观点，我们在做编程的时候先 know-how 再 know-why，这是学工科的一个特点。

第四个呢，软件编程是一门做中学的学科。不是会了再做，而是做了才会的一种学科。所以你看，在我的视频课程里面我会布置一些作业。在布置作业的时候，我希望同学们先不要等着老师的答案。当然我会讲这个答案，我会告诉你们这个东西怎么去解决，我会告诉你们的。但是我希望同学们在没有老师讲这题怎么做的时候，你们先自己做一做。不要在这看着看着这个题不动手。你问他为什么不动手，“我不会啊”。是，你这个道理好像是能讲得通，但是我希望同学们你能写一点思路出来也可以。虽然你不能全部写完，你写一部分呢？虽然你不能全部写完，核心代码你不能实现，怎么样呢？你能写段伪代码，把思路理一理也可以啊。所以我再强调一点，是做中学，是做的过程中学学会的，而不是会了才做的。这是我们工科的一个特点，希望同学们注意这个特点。

第六点，适当的囫囵吞枣。怎么个意思呢？同学们注意听我的这句话。就是有些时候，我们可能对这个知识点没有明白得很到位。打个比方，后面这个 Golang 我们会去讲一个指针。讲指针这个地方，说实话它是涉及到内存的东西了，有可能你理解的不是那么的形象，但是呢我告诉大家，你可以适当的囫囵吞枣一下。这种虽然我不是理解得很到位，但是我还要继续往下面学习，我还要继续学，我还要继续地做，可能学到某个位置突然你恍然大悟了。我不知道大家有没有这种感受。这就好像说咱们练武功，前面练的一个猴子摘桃你不知道怎么去用，对不对？你不知道怎么用，只知道一个招式。等到你实战了过后，被人家打了几下过后，你突然发现原先这个老师傅教的猴子摘桃这一招应该怎么去出。所以我给大家讲，有时候要适当的囫囵吞枣一下，不要说每个地方都抠得很到位，明白我的意思吧？当然你能够抠到很到位这是最好的，实在理解不了了也不用很害怕，囫囵吞枣，然后接着往下学，学着学着突然回头再一看，明白了。

第六点，我要大家学习一下，学习软件编程是在琢磨别人怎么做，而不是我认为应该怎么做的。举个例子，我们 Go 语言里面有个这样的东西叫 for 循环。这个 for 循环呢，你看啊，它这个基本定义它是这样写的：

```go
for i := 0; i < 10; i++ {

}
```

同学们看，这种语法在很多编程语言它是觉得很奇怪的。为什么？一般来讲很多语言，几乎传统的语言都会用一个小括号把它括起来，明白？都这样括起来。但是 Go 语言它就不括，它不括。

那你要说：“老师，这是为什么？”那你的设计者他就觉得这样子更简洁，你上哪去说理去？对吧？你说：“我觉得用小括号括起来很好啊。”那我告诉你，人家认为这个更好，你要跟人家较什么劲呢？对不对？所以说我说的不是你认为应该怎么做，而是琢磨这个设计者他是怎么理解的。

你再比如说，在 Go 语言里面这样写是对的。你看这样写，我写一句话啊，我们用 Go 语言来输出一个 Hello World，它就是：

```go
package main

import "fmt"

func main() 
{
    fmt.Println("Hello World")
}
```

你看，这样写在很多编程语言绝对是没毛病的，这有什么毛病？这种写法是很标准的一种写法，很多语言都支持，包括 Java、C。但是我告诉你，这段代码如果你放到 Go 语言里面去，它认为是错的。为什么？因为他这个不能换行，他要求把那个大括号写到上面去。为什么呢？因为他默认会在每个后面给你加个分号。你刚才这样写法在别的语言里面是可以通过的，但是在 Go 语言里面去它就过不了，他就错。为什么呢？因为 Go 语言设计者认为：我就让你有一种风格。他提倡的是什么呢？一个问题最好只有一个解决方案。就是说他为了强制这个语言很简洁，他就不允许你这么去写。你这样写就过不去，你必须用这种行尾风格来进行代码编程。

所以说我说了，有些时候你可能不要老觉得“我认为这个也可以，我认为那个也应该”，你不要这样去认为的话，就是有时候就跟这个设计者较劲了。我个人认为没有必要。他说这么写就这么写就完了嘛，对吧？我们应该把我们的重点放在什么地方呢，各位朋友？我们应该把我们的重点放在逻辑的处理上，而不要把这个重点放在语法的本身，能理解我的意思吧？就语法本身怎么写都无所谓，你让我怎么写我就怎么写。但是呢，我们重点是学习的一种编程思想和逻辑处理。能理解老师说什么意思吧？好，我先简单这么说一下。

好，这是老师说的这个学习方法的几点注意事项吧，跟大家共勉一下。
