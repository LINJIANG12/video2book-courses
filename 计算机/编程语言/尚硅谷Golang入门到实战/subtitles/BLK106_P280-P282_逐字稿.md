使用 select 可以解决从管道取数据的一个阻塞问题。什么意思呢？同学们看，我们前面大家记不记得，我们去从一个管道里面读取东西，我们需要 close 这个管道。如果不 close 这个管道，你在遍历这个管道的时候它会阻塞，而且会发生一个死锁。

但有些情况下，你说：“老师，我不想关闭它，我也希望它能够不阻塞，能够正常的退出行不行呢？”也可以。这时我们会使用到一个关键字叫做 select。我给大家举个例子，这个肯定要写代码的。

所以说这个时候有一个问题就来了：在某些情况下，在实际开发中，有可能我们不好确定什么时候关闭该管道。这个时候我们就不能用传统的方式处理了。那怎么办呢？我们就可以使用 select 这种方式来解决。

我就直接上代码了，传统方法我就不写了，我就不管，我还是要把它遍历出来，我就不管。那怎么办呢？非常的简单，直接看。

上来先来一个死循环，然后咱们写上 select 包起来。它的基本语法是这个样子的：select 包起来过后有 case，然后管道里面的值放到一个 v 里面去。

```go
	// 传统的方法在遍历管道时，如果不关闭会阻塞而导致 deadlock

	// 问题，在实际开发中，可能我们不好确定什么 closure 该管道
	// 可以使用 select 方式可以解决
	// label:
	for {
		select {
		// 注意：这里，如果 intChan 一直没有关闭，不会一直阻塞而导致 deadlock
		// 会自动到下一个 case 匹配
		case v := <-intChan:
			fmt.Printf("从 intChan 读取了数据%d\n", v)
			time.Sleep(time.Second)
		case v := <-stringChan:
			fmt.Printf("从 stringChan 读取了数据%s\n", v)
			time.Sleep(time.Second)
		default:
			fmt.Printf("都取不到了，不玩了\n")
			time.Sleep(time.Second)
			return
			// break label
		}
	}
```

我说一下这个关键点，注意，这边很重要。它是这样子的：这种思路去取一个管道的时候，即使你这个管道关闭，取不到数据了它也不阻塞，它会往下走。

注意，按这种方式，这里如果管道最终都没关闭，一直没有关闭，也不会一直阻塞在这里而导致死锁，不会一直阻塞而死锁。那它会怎么样呢？在这取不到会怎么办呢？注意听，你又没有关闭，我又取不到东西会怎么办呢？在这种情况下，它会自动地到下一个 case 匹配。
