下面来给大家介绍一下 Golang 里面查找是怎么完成的。我们在进行编程过程中，会经常用到查找这样一门技术。尤其是在我们去找工作或者面试的时候，也往往会问到查找这个知识。

在 Golang 里面，我们常用的查找方式有两种：一种我们管它叫顺序查找。所谓顺序查找，其实听其名而知其意，就是按照顺序一个一个地比对，看数组里面有没有你需要查找的这个元素。二分查找相对来说效率要高很多，二分查找其实是用到递归的知识点，在有序数列里面去进行二分查找。也就是说，如果你要用二分查找，它有个前提，该数组是有序的。如果它不是有序的，那么二分查找不能使用。也就是说，你要用二分查找，可以把这个数组先进行排序，排序完了过后，再用二分查找。

现在我们来看一下 Golang 里面的第一个顺序查找，我们来案例演示给大家。我们一起来完成查找的学习。

查找的基本介绍：在 Golang 里面常用的查找有两种，一个是顺序查找，还有一个我们叫它二分查找。

我们看看二分查找怎么完成。

首先，我们把二分查找的要求先给大家看一下。他说：“请对一个有序数列进行二分查找。”也就是说，二分查找有一个前提，就是它是一个有序的。有序就意味着要么是从小到大，要么是从大到小。那么，输入一个数，看数组是否存在此数，并且求出下标；如果没有，就提示没有这个数，会使用到递归。

我们还是老规矩，在去编写一段程序的时候，首先要进行思路分析。我们看看二分查找的思路分析。如果没有思路分析，写出来过后再看不太懂。还是老规矩，用Excel表来画一下。

请大家先看，这里面有一个数组，我们先把它拿过来，就以这个数组为例。

现在二分查找的思路就来了。二分查找的思路是这样子的：第一个，首先要保证是一个有序数组；然后第二步是这样做的：它有两个下标，我用两个不同的箭头来表示，比如绿色箭头表示一个下标，这边又表示另外一个下标。二分查找是怎么做呢？它是从两头找中间这个数。我们姑且把这个下标叫做leftIndex，就是左边的下标；把红色叫做rightIndex。

现在来谈第二个思路。比如我们要查找的数——我们先规定一下，我们要查找的数叫做findVal，就取个名字叫findVal。首先是先找到中间的下标。中间的下标就是leftIndex加rightIndex除以2。中间下标姑且叫middle，它等于(leftIndex + rightIndex) / 2。是不是这就是中间的下标了？

找到然后让中间下标的值和findVal进行比较。它一旦比较就有三种可能：第一种，中间下标对应的值大于findVal；第二种，中间下标对应的值小于findVal；第三种，相等。

这里面就有三种逻辑：
如果array[middle]大于findVal，请问这说明什么？这说明你要查找的这个数，如果存在的话，它应该是在中间下标的哪一边？左边。因为你是从小到大排的。如果说这个条件成立，就应该向leftIndex到middle - 1这个区间进行查找。是这个区间到这个区间进行查找。因为中间这个数大于别人，又是从小到大排列的，所以如果findVal在的话，它也应该是在leftIndex到middle - 1这个范围去找。这个能理解吧？比如说我现在查找的数是8，如果8跟中间这个数进行比较，比如8和19，中间这个数大于8，说明我要查找的8应该是在现在高亮的这个范围。所以你就应该向leftIndex到middle - 1这个范围去查找，是这意思吧？

当然还有一种可能性，就是中间这个数小于findVal。说明你要查找的findVal应该是在哪个范围呢？就应该是在middle + 1到rightIndex这个范围。是这样子吧？在middle + 1到rightIndex的范围。

还有一种可能性，就是找到了：如果你中间这个值刚好等于要查找的数，那就恭喜你，找到了。

这个逻辑，就是要周而复始地执行。中间这个数找到了，一比较，假设有一个箭头表示中间下标，左、中、右有三个。假设中间这个值比你要找的数大，那就让这个标往这边移动，然后中间这个值就移动到这儿来了。是不是这个意思？这也就是为什么管它叫二分呢？中间这个数一旦不是，马上我们就把这个数组砍成两半了，你要查找的话只能是在这一半或者是在这一半。它为什么这么快呢？就是因为它是折半查找。

打个比方，原先这个地方一共有几个数？一共有1、2、3、4、5、6，6个数。假设中间这个值算下来是这个值。如果这个8和中间这个数一比较，不相等，8就应该是在这边。移在这边，我把left往这边移动，中间这个值一加就是这儿。你看，这一下子就把这边这一半直接抛弃了。为什么它二分查找速度快呢？就是这样子的。前提是要求我们这个数组是一个有序数组。如果不是有序数组，我们这个分析就是不对的。如果是无序数组，你就没有办法判断，就算中间这个数大于这个值，你也不能说它一定是在这一半，因为它是无序的；但是如果是有序的话，我们就可以用这个来做，对不对？我把这个还撤回去。

哪种情况？向右边递归，这个箭头往这边移动了，左边下标它一定会往这边移动。它始终是越靠越近、越靠越近，最终有一种可能性就是左和右它们都相等了，还能进行一次比较；如果说我们发现左边比右边还大了，那就说明的确是找不到了。因为最多最后一次比较就是左边的下标和右边的下标相等了，如果还不是这个数，那就说明真的找不到了。因为再往走的话，已经全部扫描了一遍。如果我们左边这个下标和右边这个下标已经指向同一个数了，它还不是，那就意味着右边继续往左边跑，而左边的继续往这边跑，那就出现一个什么情况？左边的下标还比右边的下标还大了。这个条件一旦出现，就说明真的找不到了。它最后一次比较只有一种可能，就是左边下标和右边下标相等，这是最后一次比较；如果还不是，就不要再比较了，肯定是找不到了。能理解这个意思吗？大家想一想是不是这个分析？

```go
package main

import (
	"fmt"
)

func BinaryFind(arr *[6]int, leftIndex int, rightIndex int, findValue int) {
	// 先判断 leftIndex 是否大于 rightIndex
	if leftIndex > rightIndex {
		fmt.Println("找不到")
		return
	}

	// 先找到 中间的下标
	mid := (leftIndex + rightIndex) / 2

	if (*arr)[mid] > findValue {
		// 说明我们要查找的数，应该在 leftIndex 到 mid - 1
		BinaryFind(arr, leftIndex, mid-1, findValue)
	} else if (*arr)[mid] < findValue {
		// 说明我们要查找的数，应该在 mid + 1 到 rightIndex
		BinaryFind(arr, mid+1, rightIndex, findValue)
	} else {
		// 找到了
		fmt.Printf("找到了，下标为%v \n", mid)
	}
}

func main() {
	arr := [6]int{1, 8, 10, 89, 1000, 1234}

	BinaryFind(&arr, 0, len(arr)-1, 1000)
}
```
