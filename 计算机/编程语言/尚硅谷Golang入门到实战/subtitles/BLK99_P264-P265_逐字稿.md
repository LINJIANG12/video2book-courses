在学 goroutine 的时候，我们需要明确这么几个概念：第一个，进程；第二个，线程。

那么进程和线程指的是什么？举个例子，进程就是程序在操作系统中的一次执行过程。这句话说得还是比较经典的。

打个比方，我们前面写了很多的程序，比如说刚才你们的 .exe 文件，比如说前面我们讲的客户关系管理系统，那么你整完了过后，其实它是一个 .exe 的文件。这个并不能叫程序，你可以叫做一个文件，源代码你也叫文件，也可以把这个叫做我们的源码。

进程指的是什么呢？进程是我们去运行了这个东西，我们运行它，让它在内存里面，让操作系统开始执行了，我们把这个叫做一个进程。它是系统进行资源分配和调度的基本单位。最直接的，你们可以看到，在任务管理器里边打开它，这里我们都可以叫做一个一个的进程。这里的进程很多，但有些进程是后台进程，有些进程是前台，就是说它有界面。

下面接着看并发和并行。

可以这样理解：什么叫做并发？什么叫做并行？听其名而知其意，并发是指多线程程序在单核上运行，我们叫做并发。你的 CPU 假设只有一颗，或者说你的程序运行作用在一颗 CPU，我们叫做并发。简单的来讲，这个 CPU 它切换的时间单位是以零点零几秒或者叫几毫秒来切换的。对我们人来说，我们的反应根本就反应不过来，所以对我们来说好像是同时在跑。实际上在一个时间点上，它只是在执行一个任务。就好像你打开一个网页，假设你是单核的，打开了两个视频，你感觉两个视频在同时播放，其实它在一个时间点上实际上只是在执行一个任务上面而已。我说的是单核，如果你是多核那就是另外一回事。所以单核我们把它叫并发，在这个概念叫并发。

当然这个并发的概念跟我们外部的并发不是同一个含义。外部并发是指比如我这里有 CPU，一下子有一万个请求过来，这个时候可能是同时的。我们说的是 goroutine、Go 程序的并发。

那么什么叫做并行呢？它指的是多核上运行，我们叫做并行。那我画个图给大家描述一下示意图的话，应该是这样画的。现在韩老师的电脑上假设有一颗 CPU，CPU1，这个 CPU 上面我跑了有三四个任务，这是任务 1，这是任务 2，这是任务 3。假设我有这么三个任务，它是一个……

也就是说我这一个任务是同时跑在这一颗 CPU 的。大家想一想，如果是这种情况，你们自己琢磨一下，显然在同一个时间点上来说，一个 CPU 不可能在微观世界上既执行 01 又执行 02，这是不可能的。所以这种我们叫做并发。

并发的特点：第一个是多个任务作用在一个 CPU 上。第二点是从微观的角度看，在某一个时间点上，在时间点也就是那一瞬间，其实只有一个任务在执行。当然从宏观上看，从人的角度来看感觉是在同时执行。这个叫并发。

那并行是什么意思呢？并行是这个意思：它能够把这三个任务分配到三颗 CPU 上去做。这就是为什么 Go 语言要这么做，因为现在传统的编程语言，即使有多个任务也是分配在一个 CPU 的，所以有时候多核不能发挥威力。那么 Go 语言能够把所谓的并发转成并行，它这块可以做一个改进。Go 语言支持并行，是 Go 语言重大的一个改进。

它怎么做呢？我还是这么一个任务，但是情况发生了变化。它会这样子改进：因为一个 CPU 的效率太低了，如果假设有三个 CPU，另外两个 CPU 在睡觉，很不划算。那么第一个 CPU 就做这一件事情。然后再来两个 CPU，这儿一个 CPU 2，直接让 CPU 2 去做 task02。假设还有一颗 CPU 3，当然 CPU 一般不会是奇数，一般来说是 4、8、16、32 这样子递增，很少说是三个、五个，这里只是示意一下。让三号 CPU 专门干这件事情，作用在 task03 上去执行。

这个我们把它叫做并行。并行的特点是：多个任务作用在多个 CPU 上。从微观的角度看，在同一个时间点有多个任务在同时执行。注意是同时，不是在切换，它就是真的在同时执行。这样看来，我们并行的速度肯定要比并发快。

关于并发和并行，针对这个图再总结几句话：并发，因为是在一个 CPU，比如有 10 个线程，每个线程执行 10 毫秒，进行轮询操作。其实它是轮询操作，但是 10 毫秒太快了，给我们人的感觉好像都在同时执行。从人的角度来看好像 10 个线程都在运行，但是从微观上看，某一个时间点其实只有一个线程在执行，这个叫并发。反过来，并行因为是在多个 CPU 上，比如有 10 个 CPU，有 10 个线程，每个线程执行 10 毫秒，在各自不同的 CPU 上运行。从人的角度看 10 个线程都在运行，从微观上看也是 10 个。这就是并发和并行。
