这个地方要有对应关系了。虽然确实不是特别好讲，因为这边概念叫得有点混乱，目前来说叫得还比较混乱。你们如果说有兴趣看书，会发现在 Go 语言里面，它的概念没有像传统语言写得那么明确，比如说 C 语言，它叫进程、线程，对吧？它这边多了一个东西叫协程。

为什么有协程呢？它是这样子的。我先说一下历史的原因。

首先大家都知道，原先程序最早最早的时候没有并发和并行的概念，根本就没有，什么多核听都没听过。最早的时候就是一个进程打天下，就干一件事。后面发现进程效率太低了，程序专家、设计专家搞出一个线程。这样我们可以极大地发挥 CPU 的能力，因为硬件发展总是比软件发展快。大家都知道，这点是一个定律，叫摩尔定律什么玩意儿，我忘了。有这么一个定律说法吗？就是硬件发展的比软件发展快。事实也是如此。后面发现进程效率有点低，怎么办呢？就搞出一个线程。

线程这个东西虽然很好，的确解决了很多问题，就是它至少能够做到并发了。但是又来一个新的问题：线程还是比较吃资源。也就是说，它虽然是一个轻量级的进程，但是它仍然也是比较吃资源的。所谓吃资源指的是占用 CPU 和内存还是比较多，因为有些地方还是物理态的，比较笨拙。

于是乎，Go 语言的设计者，就是 Ken Thompson 这帮哥们，他们就想：现在最大的问题就是要解决两个问题。第一个要解决，能不能让我们的 CPU 全部都参与工作？他要解决的第一个问题是：我的 CPU 假如说有八核，我能不能把我的任务全部分配下去，八个同时干？这样就很爽嘛。这是第一件事情。第二件事情，他还在想：你这个线程虽然好，但是还是有点重。于是在底层做了一些优化。他把这个完全做成一种叫做逻辑态的。他做了很多优化的东西，这个有兴趣我们再去分析它的底层。他在算法上做了一些优化，编译器做了一些优化，做成逻辑态。做成逻辑态过后，这个线程就变得更轻巧了，变得更轻了。从它的效率上，占的 CPU，包括吃的内存更小了。因为可以在协程之间能够做到一些资源的共享，其实底层就做优化。做优化可能就是最核心的东西了。那么他就搞了一个什么呢？他说干脆这样子，我提一个新的东西，叫什么呢？叫协程。

我们来看看 MPG 是什么。首先我们分别对 M、P 和 G 做一个介绍。

第一个，M 代表的是操作系统的一个主线程。M 相当于是我们的主线程，你可以这么去理解，就像我们线程是从这里开始执行的。它是一个物理级的线程，所以它比较耗费资源。

P 是什么东西呢？P 你可以认为它是在整个执行过程中的一个上下文环境。什么叫上下文环境呢？这个上下文环境在很多编程语言里面都会有提到。所谓上下文环境你可以简单理解成运行的时候所需要的一些资源，或者当时操作系统的一个状态。你可以这样理解，就好像说我们这有一个 M 主线程，在运行的过程中，比如说在这个位置我们需要开启一个协程，在协程起来的时候需要有一个上下文环境。就好像一个人一样，一个人要生活，得有空气，得有水。人的上下文环境就是你生活的环境，你不能把一个人扔在火星上去，扔在月球上就 game over 了。就好像我们 Golang 起来的时候，它要依赖于当前操作系统的环境，还有没有内存可分配，还有没有 CPU 可分配，这些都可以称之为上下文环境。它是一个相对来说比较抽象的概念，就是它需要的资源和运行当时的一个状态，就这么理解。像人一样，得有空气有水才能生活。

G 就是个协程。协程是指什么意思呢？在创建运行过程中突然在这个地方需要去开启一个协程，那么这个协程可以往这走。这边可以有协程，甚至这个协程还可以形成一个队列。比如运行到这个位置，又需要创建或者开发一个协程，那么这边又算是一个节点或者上下文的一个环境，从这又可以继续开启另外的协程，同样也可以形成一个队列。简单地这么理解。

原来的情况是 M0 这个主线程正在执行 go0 这个协程，另外有三个协程在这里等待。等待的时候如果遇到了 go0 协程被阻塞，比如什么情况下会阻塞一个协程呢？比如读文件或者数据库。因为你读文件的时候不知道要花多少时间，操作系统就会，协程底层就会想：你这个地方读一个文件到底要读多久我不知道。有些同学说读文件不是挺快的吗？读一秒钟读两秒钟不是挺快吗？读一秒钟两秒对计算机来说已经很长了，它认为你在读文件的时候 CPU 有点浪费。所以这个时候它有可能会做这样一件事情，因为你继续去做别的事，CPU 在这处于一个空闲状态，它会怎么办呢？

这个时候就会创建一个叫 M1 的主线程。那也有可能已经从已有的线程池取出 M1，这要根据当时的情况。比如 M0 在运行了，它有可能在它的底层维护了一个线程池。线程池里面也有可能预留了一个 M1，但也可能没有，不知道。这个就跟操作系统底层相关了，如果有，我就把 M1 拿过来唤醒它，让它工作；如果没有，我就创建。这个情况就跟操作系统底层有关系了，跟你的上下文环境有关系。

不管怎么样它有个 M1。它有 M1 干什么事呢？M1 的作用就是说，你原先不是这挂了三个 G 在等待吗？现在我就可以来为你工作了。怎么做呢？并且将等待的三个协程挂到 M1 下面去执行。有些同学可能对这个词不好理解，“挂到”。这是一个比较通俗易懂的讲法，其实说到我们程序底层，说白了可能就是一个链表，也可能是一个队列，数据结构完全可以做。挂到你可以简单的认为让这个 M1 指向一个队列。指向这个队列很简答，因为队列这些东西一般我们……


我们可以创建，然后把这个队列指向给它就行了，就相当于挂到这上面去了。挂到这个 M1 过了后呢，这个 M1 就干什么事呢？它就这样子的，挂到下面过后，它就开始执行。

那么 M0 这个主线程呢，它的 G0 仍然执行原先 G0 的读写。注意，它读写的时候就相当于阻塞了。

那么这样的 MPG 模式有什么好处？总结一下：既可以让 G0 去读它的文件，同时也不会让队列中的其它协程一直阻塞，没有机会执行。

打个比方说，现在有一个餐馆，我们去吃饭。前面有一堆家伙是这样子的，我们排队，有一个厨子正在这儿炒菜。厨子就相当于这个主线程在这炒菜。炒着炒着呢，他本身是给一个客户在炒菜，这个炒菜的时候，突然有件事情来了。他给那家炒菜的时候呢，要给客户 A，假设这是客户 A，这是客户 B、客户 C、客户 D。客户 A 要的菜特别的多，他们这个客户一共点了有 100 个菜。

B 和 C 是我们同学，中午要吃饭，我们只点一个盖饭。这就麻烦很大了，如果我们只为客户 A 服务的话，那么 B 和 C 可能要等到一两点半了，那就吃不了饭了，很麻烦，对吧？

那它有什么机制呢？它有这样一个机制：因为客户 A 要 100 个菜，其中有一道菜是干什么呢？叫红烧熊猫肉，这个时候他得去搞一些——当然吃熊猫肉是违法的——比如说他吃一个海鲜。海鲜在做的时候呢，它有道工序，要先把海鲜比如临时的去洗一下、去泡、发，需要点时间。

在这个去做海鲜的时候，他有点空闲时间了。因为海鲜可能是需要，洗的时候去让他的另外一个助手去洗一洗，或者说要泡一泡，需要点时间，比如说这个海鲜要泡五分钟才能够去煮。这个时候呢，他把这个海鲜一泡，相当于阻塞在这儿了。

但是他有时间了，这个时候他就找正在排队的 B 客户说：“你要什么？”“我要一个鱼香肉丝盖饭。”“我临时就给你炒一份。”炒完了过后，你这个 B 就服务完了，然后这边的海鲜也泡好了，我再回头回来再执行 G0。就有点类似这种感觉。所以说，它这种机制既可以让 G0 进行执行，同时也不会让队列的其它程序一直阻塞，仍然可以并发和并行执行。

我再说一遍，MPG 这个模式咱们要了解的就是几点：

第一点，别人问到这个 MPG，你能够大概知道 M、P、G 是什么东西，这个你得给他答上来，这是第一点。

第二点，你要明白在工作的时候它的模式是：M 代表一个主线程往下执行的时候，这个 P 可以根据实际情况开启一个协程去工作。M 可能有很多，这些 M 既可能是执行在一个 CPU 上，可能是这几个都挂在同一个 CPU 的，也有可能是每一个 M 挂一个 CPU，那个就叫并行，这点要明白。

第三点，同学们要清楚地知道，当有一个协程被阻塞的时候，它有一种来回切换的机制。这种机制既能够保证我们 M 主线程的执行，同时呢也能够让排队的 G 协程得到一种执行的机会。因为这个时间来回切换比较快，所以说你感觉效率很高，有效地利用了我们的 CPU 资源。
