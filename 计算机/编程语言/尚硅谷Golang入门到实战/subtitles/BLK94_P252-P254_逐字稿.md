我们来完成这个事情，首先定义一个结构体，用于保存统计的结果：

```go
type CharCount struct {
	ChCount int // 用于记录英文的个数
	NumCount int // 记录数字的个数
	SpaceCount int // 记录空格的个数
	OtherCount int // 记录其他字符的个数
}
```

有了这个结构体过后，我们接着往下看。首先我们打开一个文件。为了做这个测试，我在 E 盘写一个文件叫 `abc.txt`，在里面写一些字符：`ab123 89 op go`，换行再写一些 `yy 89 hello`。我就做一个这样的测试文件，先把它保存好。

保存好过后，我们现在打开这个文件。怎么打开？用 `os` 里面的函数 `Open`。我们把文件名写一下：

接着我们来创建 reader，这个 reader 是带 buffer 的：

把句柄放进去，它会返回一个 reader。现在开始循环地读取文件内容。

```go

```

用 reader 的 `ReadString` 方法，给它一个终止符 `'\n'`。拿到内容 `str`，同时会有一个 `err`。如果读到最后 `err == io.EOF`，代表读到了文件末尾，就不读了，直接 break 跳出。

这个时候拿到的 `str` 就是我们读到的字符串，我们现在就可以遍历它进行统计：

```go
for _, v := range str {
	switch {
	case v >= 'a' && v <= 'z':
		fallthrough
	case v >= 'A' && v <= 'Z':
		count.ChCount++
	case v == ' ' || v == '\t':
		count.SpaceCount++
	case v >= '0' && v <= '9':
		count.NumCount++
	default:
		count.OtherCount++
	}
}
```

字符串的本质其实是一个 byte 数组，所以是可以遍历的。在比较字符的时候，会比较它们对应的 ASCII 码。如果大于等于 `'a'` 并且小于等于 `'z'`，或者在大写的 `'A'` 到 `'Z'` 之间，利用 `fallthrough` 穿透处理，让 `count.ChCount++`。

如果它是空格或者制表符 `'\t'`，就让 `count.SpaceCount++`。

如果大于等于 `'0'` 并且小于等于 `'9'`，说明是个数字，让 `count.NumCount++`。

如果不属于这些情况，`default` 里面我们就认为它是其他的字符，比如中文或者特殊字符等等，把 `count.OtherCount++` 即可。

经过这一番循环，每读一行我们就去处理一次。

我们来了解一下 Go 里面的命令行参数。

先看一个需求。比如说现在我们希望获取到命令行输入的各种参数，应该如何处理？大家看我这有一个图片。比如说我们去执行一个可执行文件，在这个地方我们可能会在执行这个程序的时候，顺带就传入一些参数，这个是有可能的，对吧？如果我们在这个命令行后边直接带了一些参数进去，比如 tom，还有一个路径，还有一个 88 这个数字。那么我们怎么在程序里边，就是在这个 test.exe 这个程序里面去拿到这几个参数呢？这个是可以的。

怎么拿到？告诉大家，在 os 这个包里面有一个切片叫 Args（arguments），它是一个 string 的切片。这个切片可以存储所有的命令行参数。我们来看一下这个文档。大家看到在 os 这个包里面，它有一个 Variables 变量，变量里面有一个这个东西，大家看到没有？这个变量是它这个包事先已经定义好的一个全局变量，对不对？大家可以看到是个大写的 A，是个全局变量。那它是干什么呢？这个是个 string 切片，它保管了命令行的所有参数。第一个是程序的名字，也就是说这个切片里面的第一个元素，它就是程序的名称；从第二个开始，就是你的参数的值。明白这个意思吧？

那么我们来把这个做一个案例给大家演示一下。我们一起走一走。

我们在做开发的时候，有可能需要从命令行得到一些参数。你比如说我们得到一个配置文件的路径，或者说一个端口号，我们要监听哪个端口，我们希望把这个做得更加灵活一点。这时我们可能是在执行这个程序的时候，在这个命令行里面给它传入了一些动态的参数。那些动态参数我们可以通过 os 包里面的 Args 这个切片来获取。

举例说明。我们来举一个案例：请编写一段代码，获取命令行的各个参数。比如说待会儿我们写一个 test.exe 这个程序，里面有 tom，有文件路径，还有一个数字。这里面其实一共有四个参数，test.exe 是第一个，tom 是第二个，路径是第三个，最后 909 是第四个。第 0 个也就是第一个参数，其实就是这个程序的名称。从第二个元素开始，就是我们后面输入的这些参数的具体的值。

我们来跑一个，给大家演示一下这个题。

新建一个文件夹，把它叫做 argsdemo，就是获取到我们命令行里面的参数。写一个文件 main.go：

```go
package main

import (
	"fmt"
	"os"
)

func main() {
	fmt.Printf("命令行参数有 %v\n", len(os.Args))
	// 遍历 os.Args 切片，就可以得到所有命令行输入的参数值
	for i, v := range os.Args {
		fmt.Printf("args[%v]=%v\n", i, v)
	}
}
```

命令行参数有多少个呢？其实就是这个 os 包里面的 Args 这个切片，我们用 len 取一下。然后我们遍历一下 os.Args 这个切片，就可以得到所有的命令行输入的参数值。for 循环这个可以用 for range，也可以用普通的 for 循环。我用 for range 来处理：i 是下标，v 是值，range os.Args。因为它是一个切片，我们就把它输出出来。i 代表它是第几个参数，如果下标为 0 其实是代表第一个参数，因为切片都是从 0 开始编号的。

我们来看一下 flag 包用来解析命令行参数。

前面的这种方式，同学们已经看到，我们前面用的是 os 下面的 Args 切片来获取参数。这个是没有问题的，但是这种方式有些缺点。大家发现有什么缺点没有？

这个缺点就是这样子的，大家看，如果你将来在去写这个参数的时候顺序写错了，比如说把 tom 写到后面来了，那原先这个 tom 的值就跑到第四个参数去了。这是第一个不太方便的地方。也就是说，你这种方式要严格地按照参数的顺序来编写，有点麻烦。

而且还有一个问题，在实际的开发中，如果同学们用过 MySQL 或者其他的数据库的话，你们都知道 MySQL 在登录的时候往往是这样写的：`-u root -p`，然后比如带一个密码 `123456`，然后 `-h` 我连接哪个主机，然后 `-` 端口比如说 `3306`。在很多程序里面，我们经常会看到这种用法，前面是一个应用程序，后边用一个 `-u` 来指定参数。前面有一个指定参数的标识，后面才是这个参数的值。这种用法在程序里面是经常看到的。

这样子有什么好处呢？好处在于，如果我用指定参数的方式来给参数值的话，顺序就不受约束了。也就是说，`-u root` 可以写在前面，也可以写到后面。因为程序在解析命令的时候，是根据指定的参数来确定到底是什么值。

既然如此，在 Golang 里面也支持这种写法，用 flag 包来解析命令行参数。前面的方式是比较原生态的，对解析参数不是特别方便，特别是带有指定参数形式的命令行。

比如待会儿要求大家写一段程序：`test.exe -u root -pwd root` 等等，要求通过指定的参数，通过 `u` 来获取到我们需要的参数值。我希望通过指定参数来拿到后面真正的参数值。这种用法的参数顺序可以随意。在 Golang 里面通过 flag 包可以支持这种方式，根据指定参数来获取参数的值。
