这里面要先给大家介绍的是什么是程序。有些同学说什么是程序呢？我给大家聊聊这个话题。

所谓程序，其实就是完成某一个功能的指令的集合。那这样子讲可能大家也不是很好理解，就是完成某个功能的指令的集合。这句话听起来比较抽象，那我画一个示意图帮助同学们理解，尤其是帮助零基础的同学理解一下。

我们来看看示意图的讲解，看看什么是程序。为了让大家理解，我们先抛开程序，说一个生活上的东西。比方说这里有一个人，笑脸，这个人是谁呢？是一个老板，公司的老板。然后这边还有一个人，这个人是什么呢？是他的女秘书。老板和秘书大家都知道，秘书是老板的雇员，所以老板可以下达一些指令给这个秘书。老板就下达指令了，老板给秘书下达什么指令呢？

我打个比方，老板分别下了这几个指令。他对秘书说了第一句话，要求秘书记下他说的话的内容，这是他给秘书下的第一个指令。秘书肯定听得懂的。第二个，老板又说，要求她把我说的话、说的内容打印出来。第三又下了一个指令，把内容传真给某某公司。

我们看一下这个生活化的东西大家很好理解，一个人要去指挥另外一个人干事情，他只要把他的要求告诉秘书就可以了。秘书肯定能理解他的话，要秘书记下他说的内容，秘书拿个本就记下来了；记完了过后，又说把这个内容打印出来，秘书找一台电脑就可以把它打印出来；然后又说把内容传真给谁谁谁。这两个人就通过了这种对话的形式完成了一种交互。

现在问题来了，假设老板要把这几个事情交给计算机去做，问题就来了。比方说这里有一台电脑，如果老板这样跟它说话，老板给电脑这样说了几句话，你觉得电脑能理解吗？老板说：“来，帮我把这个记录下来，把内容打印出来，把内容传真给某某某。”你觉得电脑能听得懂他在说什么吗？显然我们现在还没这么智能。也许在几十年以后有可能有这个能力，但现在绝对不可以，至少这些内容太复杂了。所以这个时候人去直接指挥电脑是做不到的。

那怎么来做呢？程序就出来了。因为现在我们要解决的问题就是什么是程序，实际上当程序出来的时候，这个交互就发生变化了。还是有一个人，但这个人不是老板，是谁呢？是我们的程序员，也就是同学们将来有可能从事的职业。你们将来要做的就是程序员。

程序员怎么去指挥电脑呢？他也不能说话，他是这样做的：他编写一段程序去指挥电脑。他怎么指挥呢？他要编写源码。编写程序就是编写源代码。比方说他写了一个源代码叫 `main.go`。他怎么写呢？我写一段伪代码来示意一下：

```go
func main() {
    print("...") // 指令1
    // 指令2
    // 指令3
}
```

他写的第一句话：`print`，这是他发出的第一个指令，指令一；紧接着程序员又写了一个源代码指令二、指令三。

这个时候写的是一段源代码。他这个时候要想去指挥电脑，他不能说程序员在这说话，他写了一段代码，这个代码我们就叫源代码。源代码能不能交给电脑执行呢？还不行，还有一个过程。在我们 Go 程序里面还有一个过程叫编译。在此刻，要把这个源代码进行编译，程序员将 `main.go` 源码进行一个编译处理，就会得到一个可执行文件，这个文件是二进制的。这个文件一般比如说叫 `main.exe`。

他首先得写一段代码，这个代码里面就把它的功能、要做什么事情写清楚了；然后程序员将这个 `main` 编译出来，得到一个可执行的文件，叫做 `main.exe`；电脑就可以去执行这个 `main.exe`，就把这里面的事情做完了。
