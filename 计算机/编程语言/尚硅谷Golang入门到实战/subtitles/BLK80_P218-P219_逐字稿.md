如果你把A和B两个接口都放到C这个接口里面来，相当于是继承了，那问题就比较严重了。为什么说这个问题比较严重？因为A接口和B接口里面都有 `test01`，那就麻烦了。这就相当于在C接口里面有两个 `test01` 方法，继承下来有两个完全相同的 `test01` 方法，还能通得过去吗？肯定编译器直接就给你报错了。

这就意味着我们接口之间不管是什么关系，继承多少次，绝对不允许有相同的方法名。如果你有相同的方法名，那这个地方肯定就过不去的。

你看前面在实现的时候，它们是分开的，分别在不同的接口。而现在搞了一个什么呢？把这一大块拿到这里面去了，又把这一大块拿到这里面去了，那就相当于C里面有两个 `test01`，因此编译器直接报错。

这个编译错误，因为C interface中有两个相同的 `test01` 方法，因此编译器通不过，编译器报错，报重复定义。

如果大家有所怀疑的话，可以把这段代码放过来测试一下。我们写一个 `main.go`，把代码放进去。保存一下，我们可以看到此时此刻它确实报错了。它会报一个什么错误呢？duplicate method，重复定义的方法，重复的方法叫 `test01`。它认为C接口里面有两个 `test01`，所以它报错是重复定义。

大家看第三段代码有没有错误，为什么？

首先这儿定义了一个接口叫 Usb，里面有一个方法 `Say`。这有一个结构体 `Student`。然后大家看到这里，它实现这个 `Say` 方法是用指针类型来实现的，是用 `*Student` 结构体的指针类型来实现的，并不是 `Student` 类型。

加一个星号和不加星号是有区别的。如果你加了星号，就代表是这个类型的指针类型；如果不加星号，才是结构体类型。

紧接着创建了一个 `Student` 结构体变量，然后把这个 `stu` 赋给 `u`。大家觉得行吗？

大家想一想，此时此刻这个 `stu` 是什么类型？是不是它就是 `Student` 类型？而 `Student` 这个类型并没有实现 `Say` 方法，因此这个地方一定会报错。

它会直接告诉你 `Student` 没有实现 Usb 接口。因为 `Say method has pointer receiver`，它自己告诉你应该给它传什么类型，告诉你要怎么改了。

那应该怎么改就成功了呢？其实加个地址就成功了。因为这个 Usb 接口是指针实现的，所以传个指针进去就行了。其它调用没有变化，还是一样的。因为指针按理说调的时候，这样调是可以的，因为本身就是指针去实现这个 `Say` 方法，直接调它没毛病。运行出来的结果也会是正确的。

如果要通过编译，应该这样修改：将代码改成 `var u Usb = &stu`，把这个加个地址就可以了。

	"fmt"

	// 错误写法: var u Usb = stu
