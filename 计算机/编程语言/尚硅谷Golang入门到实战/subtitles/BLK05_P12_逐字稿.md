原因，来分析一下为什么会出现这个原因呢？错误原因是当前执行的程序在当前目录下如果不存在。什么意思？就是你在这儿执行这个 `go version`，那么我们的 Windows 会在这个目录下，也就是说它会默认在这个目录下面去找有没有一个叫 go 的应用程序。如果找不到，它就会到环境变量，它这有个环境变量，我们待会儿再说环境变量怎么配，它会到环境变量里面去看有没有。如果环境变量里面还没有找到这个 go 的话，就会报错误，就会报这个错误，能理解吧？

当前执行的程序在当前目录下如果不存在，Windows 系统会在系统中已有的一个名为 Path 的环境变量指定的目录去查找。如果仍然找不到，就会提示上面的信息。所以各位同学，我们进入到 go 的 bin 目录下可以运行，但是出来就找不到了，就是这个原因。既然有这个原因，下一步我们就来看配置。

我把这个地方给大家补一下笔记，毕竟将来你们看笔记就希望能把这个问题搞定。配置我们的环境变量，为什么要配置？刚才老师已经做了一些基本的说明。为什么要配置呢？就是因为你不配置，你只能在安装的那个目录下使用，这肯定是不合理的。

什么是环境变量？根据 Windows 系统查找可执行程序的原理，可以将 go 所在的路路径定义到环境变量中，让系统帮助我们去找运行的程序。这样在任何目录下都可以执行 go 指令了，我们要的就是这个效果。

为什么需要配置环境变量？你不配的话，只能在当前目录用，这显然不合理。在 Go 开发中需要配置哪些环境变量？如果你有 Java 基础的话，听起来比较轻松了，Java 它也是配环境变量的。我们这个课程是针对零基础的，所以这块都说得比较细致。

在 Go 语言中需要配置哪些环境变量呢？主要有三个环境变量：
第一个，`GOROOT`，要指定 SDK 的安装路径。其实说白了，这边就应该是指定的 D 盘下面的 `program\go`。也就是说这个地方就是你 Go 装在哪里的，你就配置这个东西。
第二个，`Path`，添加 SDK 的 bin 目录，这样它就可以找到 go 执行指令了。
还有一个 `GOPATH`，这个 GOPATH 是你的工作目录，换言之就是将来我们的 Go 项目的工作路径。将来要用 Go 语言去开发项目，项目放在哪个路径下面去，就给配好。

有了这个东西过后，老师就来开始正式地给大家演示。步骤一，先打开环境变量配置的界面。怎么进去呢？点计算机，点属性，计算机属性。点完属性过后，点高级系统设置，再点环境变量。

这个地方有一个叫用户变量，只针对当前用户生效。这还有一个系统变量，针对所有的用户都生效。显然我们把环境变量配置到系统变量会比较好一点，对所有的用户都可以去使用到我们配置的环境变量。第一步，点属性；第二步，点高级系统设置；第三步，点环境变量；第四步，在系统变量这儿进行编辑。

步骤二，就可以配置我们的环境变量了。要配置的是三个环境变量。
新建变量名：`GOROOT`。变量值指定 Go 的安装路径，比如安装在 D 盘下面，直接把路径写到这里来。如果你的 Go 解压包不在这个路径，你要根据自己实际情况来配，不能说老师写什么就照抄，如果你放在 F 盘，照抄就找不到了。

第二个，配 Path。Path 这个环境变量已经有了，就不要新建，而应该点编辑去增加。Path 人家有了，你再去建一个没有道理。点进去，在后面加：一个分号，然后 `%GOROOT%\bin`。

这地方写的是一个分号，然后 `%GOROOT%\bin`。这个地方代表什么意思呢？`%GOROOT%` 代表去引用刚才定义的那个 GOROOT 变量；`\bin` 表示在后面再加一个 bin 路径。Path 这个环境变量不需要再创建了，因为系统本身就有，编辑在后面增加即可，不需要重新创建。

增加 Go 的 bin 目录，在末尾加分号，然后 `%GOROOT%\bin`。`%GOROOT%` 代表去引用或者使用前面定义的变量。前面已经指向了 Go 的安装目录，但是实际上编译程序在 bin 目录下，所以在后面要增加一个 `\bin`。配好之后点确定就可以了。

第三个，再新建一个叫 `GOPATH`。这个 GOPATH 是指将来 Go 项目放在哪个目录下面。Go 项目放在哪个目录下面也很重要，这个跟 Java 不一样，Java 是没有这个的。项目放哪儿去呢？先创建一个目录，比如说以后准备放到 D 盘的 `goproject`，将来准备把 Go 的项目或者工程放在这个目录里去，就把这个路径写进去。将来的 Go 项目就可以放到这个目录下面去了。
