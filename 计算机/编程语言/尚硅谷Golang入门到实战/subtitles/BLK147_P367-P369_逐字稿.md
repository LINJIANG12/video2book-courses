下面还有一个排序法也是需要大家掌握的，叫快速排序法（Quick Sort）。这个排序法实际上是对冒泡排序的一种改进，它的思想就会用到递归。它的基本思想是这样子的：通过一趟排序，将要排序的数据分割成独立的两部分，其中一部分的所有数据都比另外一部分的所有数据要小。当然如果说是从大到小或者从小到大，不同的情况下比较条件可能发生变化。然后再按此方法对这两部分的数据分别进行快速排序，整个排序过程中可以递归进行，以达到整个数据变成有序序列。

这里画了一个图帮助大家理解。这个图还是比较清楚地把关系理清楚了。这个图里是以最后一个数作为基准，但不一定每个都是以最后一个数。比如待会儿我们看到的案例，我是以中间这个数作为中轴，也就是以它为基准点来进行分割的。

如果以基准分解，它是怎么分解的呢？它这边是从小到大排，它会先比基准小的数扔在基准的左边。但是注意听这句话，并不是把比基准小的数扔到这边过后这就是有序的，它仍然不是有序的，它只是只能把比基准小的扔在左边，比基准大的扔在右边。紧接着再进行分解，又以最后一个数作为基准，也就是轴点，比它小的扔在左边，比它大的扔在右边；然后再把分割好的再以最后一个数作为基准，比它大的分在右边，比它小的分在左边。没有了就不分了，这样就会出来有序序列。同样这边也是一样的道理，整个过程是一个递归的过程。

这个理解起来就比前面的选择和插入要困难很多了，因为这里面用到了很多递归。我们看看这个代码是怎么实现的。

我们看一下效果，把最早的初始数组打印出来：

```go

```

原先最早的时候是这样的，现在 78 和 -567 已经交换了，第一次就搞定了。但是你这样搞定没有意义，为什么没有意义呢？因为 0 左边的这个地方仍然不是从小到大；同样，0 右边的这边它也不是从小到大。你还得保证小的数组里面仍然要保持这个规律，那怎么办呢？最经典的写法就是一个向左递归。

如果我把向左递归打开，它就能保证 0 左边递归下去就变成有序的。递归条件也是要满足 `left < r`，如果 `left` 传进去不停地变大，大到比 `r` 还大，就不要再走了。

同理，这边是向右递归，保证右边也是一个有序的。因为下去之后还要继续分割。

我们打开看一下，如果只保证一个向左递归，把这个打开。这个地方也是做了一个处理：如果交换完毕之后 `l` 和 `r` 还相等，那就再错一位，再移动一下：

```go
if l == r {
    l++
    r--
}
```

这次就不要再比较了，再移动一位。

如果我这样打开之后，0 这边会变成有序的，但是右边仍然没有动过，因为只往左边进行了递归。处理完了之后，它应该只动了 0 左边，这边就变成了 -567、-9，保证了左边是有序的。但是右边没有动，右边仍然保持 23、78、70，因为没有向右递归。

我们执行一下代码看分析得对不对。这样处理过之后，它处理完了变成有序的，果然保证了 0 左边是有序的。

同样，右边也是一样的道理。如果我把向右递归打开，那么它右边也是有序的了，两边都是有序的。

右边也打开之后看这边：23、70、78。原先是 23、78、70，现在变成了 23、70、78，其实就很简单。但是如果要一步一步把它分析出来，还是不太好分析的，因为它是递归，画图不好画，这个时候需要一点点想象的能力。

还有这句话大家要注意，一定要加上。不加上它有可能是一个死递归，为什么呢？因为如果相等你不移动，它一直卡在那个地方动不了，一比较又相等，就卡在那儿了。所以这个地方这句话是非常重要的。相等了你不移动，它卡在那儿不动，因为有这样一个条件。所以这个地方是必须加上，如果不加上把这个去掉，你会发现它是一个死循环，会在 56 行出现一个大问题，在向左递归的时候发现一个死递归，推不出来，因为没有发生 `++` 和 `--`，卡在那儿了。
