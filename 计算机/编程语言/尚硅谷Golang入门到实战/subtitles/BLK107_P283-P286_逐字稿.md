首先我们看：反射可以在运行的时候动态地获取变量的各种信息。什么信息呢？比如变量的类型、变量的类别。

类型和类别是有区别的。一般来讲，从英文字母来说，类型叫 Type，类别叫 Kind，是有稍微一点点小区别的。

如果说你的变量是基本数据类型，其实这两者是相同的；如果你这个变量是结构体，类型和类别是不一样的，待会儿我们还要举例，这是第一点。

如果你是结构体的一个实例（当然我们也可以叫变量），还可以获取到结构体本身的信息，比如说它的字段、它的方法等等，这是它的第二个用处。

还有，通过反射我们可以修改变量的值（当然我们用的是变量加引用的传递），还可以调用关联的方法。比如说我通过反射，可以以反射的方式去调用结构体的方法。

反射里面有两个特别重要的类型，一个叫 Type，一个叫 Value。

打开官方手册，我们来看 reflect 包。reflect 包实现了运行时反射，允许程序操作任意类型的对象。经典用法里面说到两个关键点：
一个是它可以调用 `TypeOf` 获取其类型信息，返回 `Type`；
还有调用 `ValueOf` 可以返回一个 `Value` 类型值。

这两个是它最核心的两个值。

如果你点进去，会发现 `Type` 里面的内容很多，它其实是一个接口。它定义了非常多的方法。通过反射获取到 `Type`，你就可以拿到该变量的 Kind、名字、包路径、尺寸、大小、还有长度（Bits）、`Elem`（指的是通过指针获取它对应的值）、Key、Field 拿到它的字段。如果反射的类型是一个结构体，通过这个方法还可以拿到它的字段。同样还可以有其它很多信息，比如它的方法代表第几个、通过名字获取方法等等。

也就是说，第一个最重要的东西出来了：通过反射我们可以获取到这样一个类型，叫 `reflect.Type`。

它是怎么玩的呢？它是通过这个方式，关键的一句话就是这个函数：`reflect.TypeOf()`。注意 `O` 是大写的。它可以接受的类型是任意类型（空接口），把你的变量传进去，通过这里你就拿到了它的类型。

通过这个类型反过来，你又可以反向去操作这个变量。当然操作它是依赖于反射包给你提供了大量的方法。操作的依据就是通过 `Type` 给你提供的一系列方法，这些方法都可以用。返回这个类型肯定把接口的方法都实现了，大量的这些方法你都可以玩。

这是它的一个最基本的道理。把这个基本道理明白了，待会儿讲的时候不至于那么蒙圈，而且觉得很清晰。

除了 `reflect.TypeOf` 可以拿到 `reflect.Type` 接口类型，还有一个非常重要的类型，就是它的 `Value` 类型。

核心的反射过来的东西叫 `Value`，它是通过调用提供的另外一个函数获取到的：`reflect.ValueOf()`。

在文档里可以看到，`ValueOf` 也是一个函数，可以接受任意的数据类型，并且返回一个 `Value`。这个 `Value` 是一个结构体。注意，刚才的 `Type` 是接口，而 `Value` 是结构体。

这个结构体里面包含了很多非常有效的方法，全都是它的方法。如果我们拿到了 `reflect.Value` 类型，就可以调用这些方法去做相应的工作，比如说判断是否有效、判断是不是一个 `nil`。

通过它也可以拿到 Kind。更有意思的是，拿到 `reflect.Value` 还可以拿到 Kind，甚至还可以拿到 Type。通过这个 `Value` 还可以拿到 `Type`，而这个 `Type` 又是那个接口，又绕回去了。这两者之间其实还有一个桥梁关系。

还有很多方法，比如 `Float`，还有 `NumField`（一看就是如果是结构体，就看你有多少个字段），还有 `FieldByIndex`（通过一个索引来获取它的字段，返回的又是一个 Value），还可以通过名字来获取字段。

在反射的过程中，基本的代码形式通常是这样子的。比如这里有一个变量，假设是个结构体：

```go
var stu Student
```

然后这个结构体一般怎么去玩反射呢？一般会把这个结构体传给一个函数，比如这里有个函数叫 `test`：

```go
func test(b interface{})
```

这个 `test` 一般不但可以去反射 Student，也可以反射其它的一些类型。比如既可以反射 Student 这种实例，也可能去反射一个非常简单的 number 类型。这个时候 `test` 函数在接收参数的时候，一般是这样接收的，比如 `b interface{}`。

在实际的工作中，玩反射的时候，通常这个函数是专门用于做反射的，一般会把 Student 这个值传给它，所以这个地方一般来讲是一个空接口类型。在传的时候一般情况是这样子的，这里有一个值，传到这里面去。

紧接着往里面走。拿到接口 `b`，我们真正把它转成 `reflect.Value`，通常情况下是通过一个函数来转的。这里一个重要概念就是：如何将一个空接口 `interface{}` 转成我们需要的类型 `reflect.Value`？

它用的是一个函数。比如转成一个 value，反射的 value，这样写：

```go
rVal := reflect.ValueOf(b)
```

一般来讲是这样做的，调用 `reflect.ValueOf`，然后把 `b` 传进去。所以我们要把 `interface{}` 转成这种类型，一般用的就是这种方式。

那又有一个问题了，如果将来需要把这个类型重新再转回原来的类型，这种情况还比较多，这个时候又怎么做呢？

在实际开发中，先解决一个这样的问题：如何将 `reflect.Value` 这种类型转成空接口类型？这个很有用。因为有时候往往先把它转成空接口，然后再做下一步工作。这时用的是它的一个方法，比如写个叫 `iv`，代表 interface 接口。这个时候是用上面的 `rVal` 提供的方法，它的方法叫 `Interface()`，注意这个 `I` 是大写的：

```go
iv := rVal.Interface()
```

这个地方它又变成一个接口了。也就是说这个时候我们又实现了把反射过后的类型转成空接口类型。打开文档看 Value，真的会有一个 `Interface()` 方法：本方法将返回 v 持有的值，返回是一个接口类型。因为有时候这个接口很有用，可以做类型断言，或者做更广泛的应用。

下一步接着做，第三步。在开发中有时候还会做一个特别重要的功能。因为目标是要把它重新转换回去，下面要完成一件事：如何将 `interface{}` 这种空接口类型，转成原来的变量类型？

这个非常简单，使用类型断言即可。其实只要做这件事就可以了，比如叫做 `v`，表示真正的变量类型：

```go
v := iv.(Student)
```

直接断言。想把它转成原先的 Student，这里就放一个 Student 就可以了。此时此刻这个 `v` 又变成了它，相当于转了一圈回去了。这个我们在做反射的时候会经常用到。

反过来讲，它们之间的关系其实是这样子的：首先做反射，把变量值传给了一个空接口；通过传过来的空接口 `b`，调用 `reflect.ValueOf` 拿到了反射的类型 `reflect.Value`；再如果要继续处理，想把它转回去，先调用 `Interface()` 把反射的 Value 转成空接口，再用空接口断言，又转回去了。

变量通过传递参数交给空接口，空接口通过反射的函数 `ValueOf` 拿到了反射的 Value 类型。通过反射的 Value 类型，可以再返回去变成接口，使用 `v.Interface()`，这个 `I` 是大写的，又转回去；再回到原来的变量类型，使用类型断言。它们之间的关系是可以随意进行切换的，想转到哪儿都可以。
