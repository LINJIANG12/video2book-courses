既然是网络编程，我们需要对网络编程有个基础的认识。这个基础认识我简单过一下就行，照顾一下对网络完全是零认识的同学。

首先大家都知道，计算机之间要相互通讯，必须要由最基本的东西：一个是网线，一个是网卡。现在物理网卡越来越少了，现在也有很多是无线网卡。都需要这两个最基本的，有线必须要有网线，如果是无线的，不要网线，无线网卡也可以。这是第一个要知道的。

第二个，我们还要明白一下协议。什么叫协议呢？打个最简单的比方，协议是双方认同的，计算机和计算机之间相互去交流的时候，他们需要一种协议。我举这样一个例子，大家一下就明白了。

比如说我打开一个 Excel 文件。比如我们两个人之间交流，张三和李四交流。比如这里有两个人，我们来画个笑脸就行了。假设这个人叫张三，叫 A 吧，A 这个人。然后叫 B，还有一个人叫 B。他们之间要相互交流的话，他们必须要有一种东西大家都认同、都认识、都能识别的。比如说他是中国人，他也是中国人，那么他们交流靠什么呢？靠语言。我跟你说一句话，你能听得懂我在说什么。同样的道理，B 这个人也可以给 A 说一句话。那么他要能听懂，人与人之间靠的是语言。这边我给他说话，也是靠的语言。

问题又来了，如果 A 和 B 都是中国人，那这个语言就叫中文就行了。但是有一个问题，如果 A 是一个中国人，B 是一个越南人，越南人不会说中国话，这样子就不能通讯。这就好比语言我们认为叫协议，语言就叫做一种协议。

但是这个协议下面，语言有中文，当然它也有英文，还有越南语等等。每种具体的语言，我们把它叫做具体的协议。协议下面有很多种协议，这就叫一个具体的协议。大致就是这么一种感受。

有些协议、有些语言是大家公认的，有些语言可能是一个小部落的语言，只有他们自己能用。这就好像我们以后写编程，我们有协议，我们有通用的协议，比如说大家都清楚的 HTTP 协议、FTP 协议、HTTPS，还有 SMTP，这些都是协议，是大家都认同、都认可的。但还有一种协议就是自定义协议，我们自己定义的协议也可以。比如后边我们写东西，我们可能自己去定义协议，在这个基础上我们自定义协议也是有可能的。协议是一个很重要的东西，你将来做网络编程，你就要学会自定义协议。

自定义协议其实也挺简单的，一般就是一个结构体。比如说最简单的协议，我要跟 A 和 B 发生一种关联关系，我就定义一个结构体：

```go
type Message struct {
    Id int
    Content string
    Time string
    To map[string]string
}
```

我们就定好了，我跟双方都是认同的。我要给你发个消息，我怎么发这个消息呢？首先我告诉你，我会有个 ID 号，ID 是一个 int 类型的。我还要给你发一下消息的内容是什么，比如是个 string。再比如我还发一个发送的时间，我是什么时候发给你的，可能用个 string 来记录这个时间。再比如我这个消息是要发给谁呢？我要发给张三还是李四，还是群发呢？可能我还有一个接收者，那么接收者可能我这边用的就是一个 map。为什么呢？可能是一个数组，或者是个 map，我告诉你我将来把这个东西发给谁等等。这样子就可以描述一个完整的 Message。对方拿到过后，他去读取这里面的内容，然后显示。这种东西就可以自定义。这就是一个简单的协议的描述。

我们这个协议有这么多了，接下来介绍的就是一个重点了。在我们实际的网络 TCP 这个范畴，我们有哪些协议呢？大家可以看到有这么一个协议。

在网络世界里面有一种模型，它叫 OSI 这种模型。这种模型最早是由美国的一个标准化组织提出来的。我们将来要开发一个网络，那么我们需要有这么几层，一共是七层：应用层、表示层、会话层、传输层、网络层、数据链路层，还有物理层。

但实际上在真实的环境里面，其实没有这么复杂，它把这个做了一个简化。简化成几层呢？简化成了应用层、传输层、网络层和链路层。

有些同学说：老师，你这样讲我有点听不懂，它是什意思？因为同学们虽然你们不是专业学网络的，但是我认为了解一些最基本的东西，大家还是要了解的。咱们也不去讲过于理论化的东西，因为太理论化的东西不是一句话两句话能说清楚的，光书都有三本，而且随着它的发展，有些还在不停地完善。

我就以一个最简单的 QQ 相互通讯的案例，来结合看，比如我通过 QQ 发了一个“Hello”，它是怎么把这个“Hello”信息传递到 B 的呢？搞运维的同学应该非常清晰，搞运维的必须学这个东西，而且学得很透了。那么我就站在咱们 Go 语言开发者角度，给大家看一下到底它是怎么做的。请大家认真听，还是比较有用的。因为你了解这个东西，对你理解程序本身是有帮助的。

我们就以这个为例，来看一个 QQ 相互通讯的案例。我们不讲过于理论的东西，请跟上老师思路。

现在有这么一个情况，比如这是张三的电脑。这边是张三的电脑，张三他有一个好友在遥远的美国，叫李四。张三和李四他们是好友，他们都用 QQ。这边是张三的 QQ。两个人上线了，一个是在中国，李四这个人在遥远的美国，在大西洋的彼岸，美国。

现在有这么一个情况，张三上线了，李四也上线了，他们要说话。张三有电脑，他的电脑上装的有 TCP/IP 这个协议。TCP/IP 协议其实是一组协议，它简称 TCP/IP，其实它包含的协议很多。在电脑里面它分成了这么几层：

第一层是应用层（Application）。
第二层我们叫做传输层，也叫 TCP 层，每个有它自己的作用。
第三层是 IP 层，也就是网络层。
最后一层叫链路层。

链路层下面是什么呢？链路层就直接对应我们的网卡。每个电脑要出去，它必须要装有网卡。网卡是一个硬件设备，这是我们的网卡。

数据开始了。张三在 QQ 上说了一句话，他给李四说了一句话叫“Hello”，因为他的好友已经拿到了。

这个“Hello”首先开始往下走，它先经过第一层。这边是一个文本包，在这个包里面第一次放的是“Hello”。这个“Hello”经过了应用层，它首先会在这地方加一个 APP 头。经过这一层过后，它在前面加了个 APP 头。这边是内容，这边是 APP。加 APP 表示什么意思呢？表示我是哪个程序发过来的。因为对方最后接收的时候，他在解析的时候要知道这是哪一个程序发过来的，所以它有个 APP 头。

加完这个 APP 头过后，紧接着继续走传输层。经过这个传输层过后，这个地方又会加一个东西，加一个 TCP 头。你看这个数据包在不停地变东西，又加了个 TCP 头。加这个 TCP 头有什么用呢？

TCP这一层要保证我将来的数据包准确地传送到李四那边去，它有这样一个责任。每一层有它自己的责任，它的责任就是说我要准确地把这个包发送到李四那边去，叫传输层。

紧接着还有第三，它又过渡往下继续走，经过了我们的IP层。IP层过后，在这个基础之上再加一个头，叫IP头。在这个基础上又加了一个东西，协议的感觉就出来了。

为什么要加这个IP头呢？因为要记录两样东西：第一个，我的IP是多少；第二个，对方的IP是多少。因为这样子，后面网络才能知道你要把这个包发给哪一个人。在网络中你为什么发了一个“hello”能够准确地定位到李四呢？因为我们每一个网络都会有一个自己独一无二的IP地址。当然有些同学说了，那假设都在内网里面，IP不是相同的吗？这是另外一个范畴了，局域网里面还会有别的方法进行解包。我们先不去考虑那么多。

它这里就会记录说我是从哪儿来，我要发给谁，这就拿到一个IP头。拿到IP头过后还不能发送，然后再经过我们的链路层。经过链路层，要在这个包上面再加两样东西，一个是帧头、帧尾。这个时候就变成一个帧数据了。在前面加一个帧头，还要加一个帧尾。它加帧头、帧尾的目的，就变成了一帧数据。

这个时候这个数据到这其实已经变成二进制的东西了，肯定就是一堆二进制东西。如果你的代码在这个地方被人截获了，比如你的包在这被人截获，你刚发出去，在网络中传送这个数据，假设你的数据在网络某一个地方被人截取把这个头改了，那你就被欺骗了，这个包就会发到另外一个地方去。比如你说“hello，我的电子密码是多少”，如果被人截取这个IP头，就会把IP头改到另外一个地方去，而且会自动把密码给截过来。所以网络世界的风险很高。

有了这个数据过后，当我们拿到这个地方的时候，这个数据就会交给我们的网卡。交给网卡，网卡做什么事情呢？它也不是闲着的。假设你这个网是在局域网，网卡就会对接一些东西，比如说对接一个网关。因为你也有可能是在一个局域网里边，所以它有网关。

网关出去就是大量的路由器，它有很多路由。我们一个包要到对方去，其实经过了很多路由。当然有多少个路由我们不知道，每个路由也有自己的IP地址，叫路由器。假设经过了两个路由器到美国，那么我们这个数据包就在网络里面传输。经过这个路由过后到达了李四。

李四这边同样有这样的四层数据。李四的电脑肯定也是在一个网络里边，所以他对方也有一个网关。这个数据通过网络一层层地发，最后到达了李四所在的网关的位置，他就要接收。相当于这个数据就在网络里面传输。

传输到这儿的时候，它就反过来进行一个逆向的处理。比如经过链路层，到达链路层的时候，这个数据到这儿就会去掉帧头和帧尾。然后再经过IP层，继续去掉IP头，因为每层都要校验到底是不是给我的。把IP头去掉就到达这一层，然后继续经过传输层的处理。传输层再往上走，又把TCP头去掉。

到达应用层就决定是哪个程序来接收。因为你的应用层可能有很多程序，你有QQ，可能还有微信，到底由哪个来接收呢？当然里面还有端口。再经过应用层把APP去掉，APP头去掉过后，最后我们的“hello”就送到了李四的地方，就看到一个“hello”了，它是这么一个过程。
