如果是先对源码编译后再执行，Golang 的执行流程如下：

如果说把源代码编译过后再执行，执行流程就是原代码拿到过后，用了一个 `go build` 指令。`go build` 指令会把我们的源代码进行一个编译，编译会形成一个 `.exe` 的可执行文件（如果是 Windows；如果是 Linux 或者是 Mac，后面就没有 `.exe` 后缀了，但仍然是一个可执行文件）。拿到这个可执行文件，就可以对这个可执行文件进行运行。怎么运行呢？比如像 Windows，直接对它执行就可以了，这个就叫运行我们的可执行文件。

如果说是用 `go run` 指令直接来运行一个源代码，它的流程又是怎样的呢？

如果我们是对源码（源代码）直接执行 `go run` 指令：`go run` 源代码，它的执行流程是直接把编译和运行放在一起了。明显会感到这两者谁的速度更快一点呢？如果只是从运行的角度来看，直接执行可执行文件肯定要快，因为这个已经是二进制的了。如果直接 run 的话，其实在底层仍然会把我们的源码编译成二进制再执行，只是把这个过程隐藏起来了。因此可以感觉到，前者执行的速度要快，后者执行速度要慢。

在实际的开发中，还是应该先把它编译成可执行的文件再执行。这种方式在有时候为了快速看一下源代码有没有什么变化，可以去试一下，但实际开发中咱们不会这么去用。

现在我们再来看看这两者区别是什么，简单的聊两句。

说明两种执行流程的方式区别，这也是在面试的时候面试官有可能会问到的一个问题。

总结了有这么三点：

第一点，如果我们先编译成可执行文件，那么我们可以将该可执行文件拷贝到没有 Go 开发环境的机器上，仍然可以运行。如果注意到的话，会发现我们编译生成的这个文件会变得比较大。Go 的源代码其实只有 1KB，可是当我们编译过后，会发现它变成了 1.8 兆。为什么会变这么大呢？这就是因为在编译的时候，其实它也会把这个源代码需要执行的相关的一些文件和资源打包进去，所以它就会变得很大。也就是说，如果把这个文件拷贝到其他的地方，比如拷贝到别的机器上，假设这个机器没有安装 Go 的 SDK，它也是可以运行的。在控制台里面切到 D 盘，直接执行 `hello.exe`，回车，它仍然可以执行，仍然可以执行输出“hello, world”。如果说把 `hello.exe` 直接拷贝到你的另外一台机器上面去，假设那台机器没有装 Go SDK，它也可以运行。就是因为文件变得很大，把相关资源已经一起加载到里面去了，或者链接到里面去了。

第二点，如果我们直接 `go run` 源代码，那么需要在另外一台机器上也必须要有 Go 开发环境才可以。比如把源代码给你了，打个比方，韩老师把 `hello.go` 这个源代码交给了张三，张三想去用 `go run` 来运行，那需要对方也应该有 Go SDK 才可以，否则它是跑不起来的。

第三点，在编译时，编译器会将程序所依赖的库文件包含在可执行文件中，所以可执行文件就会变大了很多。刚才也看到了，原先源代码是 1KB，等到编译过后变成 1.8 兆，变大了很多。1KB 和 1895 相当于变大了 1000 倍。为什么会变大呢？因为程序所依赖的一些库也会被链接和编译进去。
