我们继续来看一下继承的深入讨论的另外一个部分，我们看第四一个。如果说结构体里面嵌入了两个或者多个匿名结构体，这是有可能的，对不对？你比如说看这里，你有结构体 A，这有结构体 B，那么 A 和 B 都被嵌入到了结构体 C 里面，这是有可能的。而且更可悲的是什么呢？就是 A 有 `Name` 字段，还有 `Age` 字段，而 B 里面也有一个 `Name` 字段。

那这样子的话怎么办呢？如果两个匿名结构体都有相同的字段或者方法，同时，结构体本身没有同名的字段和方法。也就是说，你两个匿名结构体有 `Name`，但是 C 里面没有这个 `Name`。再说明白一点，A 和 B 里面有 `Name`，但是 C 没有同名字段或者方法，在这种情况下，在访问时就必须明确指定匿名结构体的名字，否则编译直接报错。

什么意思？如果嵌了两个结构体，这两个结构体有相同的字段或名字，但是 C 却没有同名的字段或名字，那么这个时候，你为了区分到底用 A 的还是用 B 的，就必须把匿名结构体的名字带上，否则编译就会出错。我给大家举个例子，大家看案例。

这一点也是我们在使用的时候需要同学们注意的一个细节。我给大家举个案例，大家看一下。同样我还是在这儿举例吧。干脆我们新写一个文件夹，不然的话文件就越来越多，在这儿就比较混乱。我还是写这个东西，叫做继承的 details2。同样在这里面，我们新建一个文件叫 `main.go`。

现在我们来看看，比如我定义了一个结构体 C。这个时候我要给它赋值，如果我这样写：`c.Name = "tom"`，这个地方就会 error。为什么这个地方会错误呢？因为你在访问 `Name` 的时候，根据原先我们说的访问规则和它的顺序，是不是先到 C 里面去找？C 有没有 `Name`？没有。没有的时候，它就会到嵌入结构体 A 和 B 里面去找。那么它发现 A 有一个，B 也有一个，完了，它不知道到底你把这个 `Name` 给 A 里面的 `Name` 字段，还是给 B 这个结构体的字段呢？于是它就会编译报错。

我们总结一下：如果 C 没有 `Name` 字段，而 A 和 B 有 `Name` 字段，这时就必须通过指定匿名结构体名字来区分。所以 `c.Name` 肯定是行不通的，就会报编译错误。这一点大家注意一下。

在使用的时一定要注意这个细节，否则是不行的。当然方法也是一样的道理，我就没有举例了。方法也是一样的，假设 A 有一个方法叫 `sayHello`，B 也有一个方法叫 `sayHello`，你这直接调用 `c.sayHello()`，那也是区分不了的，除非你 C 本身有一个 `sayHello`。这个规则对方法也是一样的。

这是我们讲的第四一个需要注意的地方。我们看第五个需要注意的地方是什么。

如果一个结构体嵌套了一个有名结构体，这种模式我们把它叫做组合。一般不把它称之为继承了，组合是继承的一种特殊关系。如果是组合关系，那么在访问组合的结构体字段或者方法时，就必须带上结构体的名字。

这就叫组合。你甚至可以组合多个 A。在 Go 语言里面，继承是非常灵活的。假设我这有个 A，里面有 `Name`、有 `Age`，那这个地方我嵌套了一个 A，同时我指定了名字。那这个时候同学们注意听，你这个时候要访问 `Name`，你要访问到 A 里面的 `Name`，就必须把这个名字带上，否则它是访问不成功的。

我们在代码中走一下：


如果是有名结构体的话，要使用就得这样去使用。我在声明了一个 D 这种结构体变量，那么现在我们如果像以前那样写 `d.Name = "jack"`，我们来看看行不行。这时它就报错了，说 `type D has no field or method Name`。为什么呢？因为你这个地方不是一个匿名结构体，那么在检查规则的时候，编译器只在这个 D 里面看有没有 `Name`，如果没有就直接报错了。

也就是说，因为你这个地方不是匿名结构体，它就不会往上找，明白吧？它就直接在 D 里面看有没有这个 `Name`，如果没有它就直接告诉你 D 没有这个字段或方法。所以在 Go 语言里面，层级关系是很清晰的。当然如果把字段名去掉，那肯定就对了，去掉肯定不报错，但是你写上有名字就要报错。

那怎么办呢？就按照老师说的 `d.a.Name`，这样就可以了，你就必须把名字带上了。这样就可以访问到。

当然有同学又说了：假设 D 里面也有一个 `Name` 呢？如果 D 有一个 `Name`，我这样写肯定不会报错，因为它还是先到 D 里面，发现它有，那就没问题了。但是如果你没有，它发现你这个是有名结构体，它也不会到 A 里面去看有没有 `Name`，直接报错。

如果 D 中是一个有名结构体，则访问有名结构体的字段时就必须带上有名结构体的名字，比如这里的 `d.a.Name`。同时这个关系别人问到你，就叫组合关系，D 和 A 组合起来了。

我们接着往下看。现在我们来看几个关于面向对象编程继承的课堂练习。

大家看这里有一个继承的课堂练习题。结构体的匿名字段是基本数据类型，它也是可以直接嵌入到结构体里面的。比如我这里有一个 `type A`，这个 `A` 可以以匿名的方式嵌入到 `struct`，前面讲过了。

在结构体里面其实你也可以嵌入基本数据类型，比如 `int`。如果你嵌入 `int` 这种字段，因为它本身是基本数据类型，它自己是没有字段的，因此在访问的时候就直接通过这个名字，比如 `student.int`，这样就可以了。这种用法在 Golang 里面也是允许的。

我给大家简单演示一下。比如我这里有一个结构体：

```go
type Monster struct {
    Name string
    Age int
}
```

假设我这里还有一个结构体叫做 `E`：

```go
type E struct {
    Monster
    int
}
```

如果我们现在把 `Monster` 以匿名结构体的方式嵌进去，这是没问题的。同时我们也可以把基本数据类型作为一个匿名字段放进去，这种方式也是允许的，就相当于说在 `E` 里面有一个匿名字段，它是基本数据类型 `int`。

这种情况下怎么去用这个 `int` 呢？演示一下匿名字段是基本数据类型的使用：

```go
var e E
e.Name = "狐狸精"
e.Age = 300
e.int = 20
fmt.Println("e=", e)
```

如果是 `Monster` 的用法，前面我们讲过，直接写 `e.Name` 就可以了。这个 `Name` 全写应该是 `e.Monster.Name`，但是因为只有一个 `Name`，所以可以简写。给它取个名字叫做狐狸精，年龄 `e.Age = 300`。

假设这里面要访问它的匿名基本数据类型字段，直接 `e.int` 就可以了，比如给它一个 `20`，这也是可以的。我们输出看一下：运行起来可以看到，这个地方仍然可以正确地输出。

给大家再强调一点：如果这里有一个 `int`，就不能再有相同的 `int` 匿名字段了，因为无法区分。如果你一定还要有 `int` 的话，前面就一定要有个名字，比如写一个 `n int`，这样是可以的。给这个 `int` 一个名字，就相当于在 `E` 里面有一个字段名叫 `n`，它的类型是 `int`，这样也可以区分。用的时候就是 `e.n = 40`。输出也是没问题的。

这里把这种使用方式总结一下：如果一个结构体中有一个 `int` 类型的匿名字段，就不能有第二个了，最多只能有一个。如果需要有多个 `int` 类型的字段，则必须给 `int` 字段指定名字。

接着我们再来看下面的多重继承概念。

多重继承其实在前面已经给大家讲过了，只是没有把这个概念抛出来。我们在讲细节的时候，`TV` 里面有两个匿名结构体，说明 `TV` 继承了 `Goods`，同时又继承了 `Brand`，其实这就是一个多重继承的案例。

把这个概念梳理一下：如果一个 `struct` 嵌套了多个匿名结构体，那么该结构体可以直接访问嵌套结构体的字段和方法，从而实现了多重继承。在 Golang 里面实现多重继承，其实就是嵌入多个匿名结构体。

案例前面已经有了，`TV` 嵌入了 `Goods`，又嵌入了 `Brand`，这就相当于继承了两个。在 `TV` 里面既可以使用 `Goods` 里面的属性和方法，又可以使用 `Brand` 里面的属性和方法，如果有方法也是可以使用的，这就是我们所说的多重继承。

这里还有多重继承的细节需要再点一下：

第一点，如果嵌入的匿名结构体有相同的字段名和方法名，在访问时则需要通过匿名结构体类型来区分。这点在前面其实已经说过了。比如 `Goods` 里面有 `Name`，`Brand` 里面也有 `Name`，那就必须把匿名结构体的名称写出来，通过 `tv.Goods.Name` 去显式区分。如果直接写 `tv.Name`，编译器就无法区分，一定会报错。但如果 `TV` 去访问价格 `Price`，`Goods` 里面有价格，而 `Brand` 里面没有价格，那就可以直接写 `tv.Price`。因为 `Brand` 里面没有 `Price` 字段，它是可以区分的。

第二点，为了保证代码的简洁性，在我们做 Golang 开发的时候，建议大家尽量不要使用多重继承。因为多重继承很容易把继承关系搞复杂，很多编程语言里面其实已经把多重继承拿掉了。但 Golang 的设计者本身就是 C 语言的设计者，因此把多重继承特性保留了下来，但在相关文档里面也说了尽量不要使用多重继承。
