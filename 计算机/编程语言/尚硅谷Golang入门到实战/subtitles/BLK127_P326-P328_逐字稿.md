```go
package model
```

如果我这样写一个 User 结构体，问题就很严重了。为什么这么说呢？因为将来这个 User 一定会被反序列化或者序列化操作，而我们现在往这里面添加的序列化的 User，它的名字是小写的，前面的 key 是小写的，因此你在反序列化的时候根本就不会成功。因此必须把这个 tag 写进去。

为了能够序列化和反序列化成功，我们必须保证用户信息的字符串，也就是 JSON 串的 key，和我们结构体的字段对应的 tag，即 struct 里面的 tag 的名字保持一致，否则就一定会失败。

这个地方写完过后，我先插一句话。这个地方有一个地方我要说清楚。同学们可以看到，服务端这边如果学过 MVC 的同学可能感觉到：是不是少了一层？你看，现在这块是我们的控制层，相当于 MVC 里面的 C；这层是 model 层，相当于 M。那界面上哪去了呢？界面你可以理解成就在 main 里面显示。
