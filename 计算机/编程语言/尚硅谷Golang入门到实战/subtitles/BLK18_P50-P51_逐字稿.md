同学们要注意一下，我们基本数据类型和 string 相互转换的时候，尤其要注意在将 string 转成基本数据类型时，要确保 string 这个类型能够转成有效的数据。

一般来讲，我们把基本数据类型转 string 是比较容易的，比如说把 12 或者是 12.35 转成 string，一般不会出现什么异常或者错误的问题。但是反过来呢，不一定。

比如说，string 转基本数据类型，我们可以把 "123" 转成一个整数，但是我们不能把一个 "hello" 转成一个整数，对不对？如果说你真的给了一个 "hello"，那 Golang 会怎么处理呢？告诉大家，Golang 也不会报错，它直接把它转成一个 0 就完事了，明白吧？

也就是说，Golang 对于不能够成功把一个字符串转成一个有效数据的时候，就把它转成一个默认值。

string 转基本数据类型的注意事项，要确保 string 类型能够转成一个有效数据。案例说明一下，这个数它就能转成一个整数，对吧？但是你要写个 "hello"，你看会有什么下场，演示一下。

比如这里有一个 `str4`，它的值是 "hello"，但是你却硬要把它转成一个 int64 的，我们看看会有什么后果。

```go
n3, _ := strconv.ParseInt(str4, 10, 64)
```

我们输出一下，还是老规矩，把它的类型还有它的值都输出出来看一下。n3 类型是什么，n3 的值又是什么，输出出来看看，跑一把。

我们看到 n3 仍然转成了一个 int64，它确实还是给你转成一个 64 位，但是这个值是 0。为什么呢？原因很简单，没有办法把一个 "hello" 转成一个整数。所以说它把类型还是给你转过来了，但是因为 n3 本身就是 int64，所以它没有改变；而 "hello" 没办法转成一个整数，就给你填了一个默认值进去。那么这个 n3 它就还是原先那个值，就相当于说没有转成功，明白吧？

有人说：老师，假设它原先就有一个值呢？比如说原来就是 11，我们看这个时候 n3 会变成 0 还是保留原来的值？跑起来。我们可以看到，n3 就被转成一个默认的 0 值了。也就是说，它转完了以后发现没有转成功，那么它就会把这个 n3 置成一个 0 值，就是默认值，把它原先的 11 都给拿掉了，能理解这意思吧？

这点请大家注意一下，其它的也是一样的。会默认转成一个 0 值。如果注意听，如果没有转成功，那么这个 n3 就变成了一个默认值。

其它类型也是一样的道理。比如我们要把 string 转成一个 float 型，你也不能把 "hello" 转成一个 float 吧？再比如说 bool 型，我们可以把 "true" 变成一个 bool 值，但是如果给一个 "hello"，就转不成 bool 值。转不了的话它会怎么办呢？它会把这个 bool 转成一个什么值呢？也可以试一下。
