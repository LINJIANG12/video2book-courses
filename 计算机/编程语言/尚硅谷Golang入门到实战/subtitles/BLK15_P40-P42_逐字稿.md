计算机最早的时候，大家都知道，它其实是美国人在用的。最早是美国人用，美国人他用的英文单词也好，他的一些表达的句子也好，其实只需要这么几种字符就够了。也就是说在最初的时候美国人他们用，ASCII 码就足足地够了，听到这意思了吧？但是，随着计算机的普及，不但美国人要用，中国人、日本人，还有像朝鲜人、韩国人，他们也要用计算机了。这时候就出现了一个问题，什么问题呢？就是你这个 ASCII 码表示的这些字符不足以去表示其他国家的文字。你比如说中国，中国的汉字很多，光这 127 个或者这么一点字符不够用的，怎么办呢？

我们的计算机专家就想了一个办法，干脆我们就把这个 ASCII 码表进行一个升级。当然升级过程中真的有好几个编码，比如说还有 GB2312，还有 GBK 编码。最后到了现在，升级到整个计算机编程里面用得最多的就是 UTF-8 编码。你可以这样认为：我们的 UTF-8 编码包含了 ASCII 码，就把它包起来了，把它扩大了。相当于说你有 ASCII 码表，同时我有 UTF-8 这个编码，那么我的 UTF-8 编码包含了你的 ASCII 码，你可以这样简单认为。

所以你会看到，ASCII 码里面这个 `'a'` 是 97，我们来看看在它的 Unicode 码里面，`'a'` 是不是也是 97 呢？来，我输入一个小 `'a'` 查看编码，你会发现它仍然是 97。这说明什么？这说明我们 UTF-8 编码是兼容 ASCII 码的。也就是说我并没有把你的那个编码给你破坏，我兼容你，能理解意思吧？就相当于把它扩大了。扩大的好处是什么呢？扩大的好处就是说，将来你 ASCII 码里面只能保存的是 127 个字符，那么到了 UTF-8 表里面我就扩了，比如说我可以保存“中”，我可以保存“国”，我还可以保存“你”，我还可以保存“好”。这些就是我们的字符，这些字符它也对应一个码值。它的码值是什么呢？比如说“中”，就是这个码，我们可以认为它就是 Unicode 里面的十进制码；“国”就是这个码。

所以说，现在大家是不是多少理解一点 UTF-8 和 ASCII 码的来龙去脉了？最早的时候只有 ASCII 码，但是随着大家使用，发现 ASCII 码能够表示的字符太少了，于是乎大家就想办法去对它进行升级或者增加，这个时候就有一个叫 UTF-8 的编码出现了。当然从 ASCII 码到 UTF-8 编码还经历过很多历程，我们就不讲了。现在通用的 UTF-8 是世界比较通用的，是目前使用得最多的。基本上我们语言里面都是用 UTF-8 这种编码来处理的。

Go 语言字符是用 UTF-8 编码来做的，它还有一个特点：在 UTF-8 里面，它的英文字母是一个字节，它是用一个字节；它的汉字是三个字节来存储的。这是一个基本常识问题，大家要注意一下。这是我说的第三个需要同学们了解的。

第四个，在 Go 中，字符的本质是一个整数，直接输出时是该字符对应的 UTF-8 编码的码值。这个大家也来体验一下，刚才其实我们已经体验过了对吧？你看我输北京的“北”，它就是 21217。

第五个，我们也可以直接给某一个变量赋一个数值，然后按格式化输出 `%c` 的时候，它也可以输出该数值对应的 Unicode 字符，Unicode 字符就是我们所说的 UTF-8 字符。打个比方，大家看到刚才老师不是这儿有一个“国”吗？我把这个复制一下，给大家体验一下，来看一个案例。

比方说，我给一个整数：
```go

```
其实大家都知道 22269 对应的编码是“国”，对吧？也就是说，我如果把这个按照字符输出，它就应该出的是“国”这个字。是不是这样子呢？我们试一下。

```go

```
同学们看效果，看下 c4 是不是输出的“国”。通过这个案例就可以把它认识得更清楚一点。走！我们可以看到，c4 输出的是“国”，完全没问题。

那假如说我输的是 ASCII 码的一个值呢？也一样的。比方说我们找一个 ASCII 码里面的值，`x`。这个 `x` 对应的数字是 120。十六进制大家不要去管它，输一个 120 进去。如果大家知道的话，这应该输出一个什么呀？就输出 `x` 了。它们之间对应关系大家搞通透。你看，我再输出这个，你会看到 c4 输出的是 `x`。明白这意思了吧？其实就是个对应关系，不要把它搞得很复杂的样子。这是我们讲的细节的第五点。

第六点，字符类型是可以进行运算的。因为它的本质就是一个整数，因此它可以进行加法的运算。我给大家举一个例子。这也是个细节，有时候会利用这个特性来完成一些业务逻辑。字符类型可以进行运算，相当于一个整数。运算时是按照码值运算的。比如说这有一个整数：
```go
var n1 = 10 + 'a'
```
大家觉得这个输出多少？因为一旦当做加法来运算，就相当于把 `'a'` 的码值得到然后再运算。大家都知道，10 加多少呢？`'a'` 对应的码值其实是 97。也就是说它相当于是加了一个 97，显然这个结果就应该是 107。能理解？

输出一下：
```go
fmt.Println("n1=", n1)
```
这个时候我是按照数字输出的，没有格式化，所以它应该输出 107。走！我们可以看到，这边输出的是 107，没有任何问题。

所以说，有些时候有些程序员专门利用字符可以运算的特性来完成一些操作。比如说我们想从 `'a'` 得到我们所有的英文字母，我就可以逐一地加 1，不停地加，然后按字符输出，一下就把它全部输出出来了。所以有时候会运用这种特性来完成一些业务逻辑，能理解吧？

后面还有一个幻灯片也是讲字符的，我们一并把它说完了。关于字符类型的本质讨论，老师整理了三点。其实你学到现在，单个的字符存到计算机中，其实它的本质存的是一个整数。它在读取的时候，流程是这样子的：首先存储的时候，它先把这个字符转成码值，找到对应的码值；找到码值过后，把它转成二进制；二进制过后，再存储。反过来读取的时候是怎么读呢？如果按字符输出，它先读的是二进制；二进制找到对应的码值；找到码值过后，把它转成对应的字符；然后读取。它是这么一个流程。

第二点要注意，字符和码值的对应关系是通过字符编码表来决定的，事先规定好的，你不能说你去改它。比如刚才同学们看的这个地方，中国的“中”，它事先就定的是20013，你就不能改了。定好了以后就20013，这是字符编码的时候它就规定好的。

第三点也是一个很重要的点：Go语言的编码都统一用了UTF-8编码。Go语言的编码统一成了UTF-8，非常方便，很统一，再也没有乱码的问题了。如果有同学用过像PHP，或者有同学用过Java的JSP，你们会发现这个中文乱码特别的痛苦，因为它的编码并不是特别统一的，有些地方用的是GBK，有些地方用的是GB2312，有些地方用的是UTF-8。到了Go语言，它的所有的编码都是UTF-8，强制你用UTF-8，这样子的话我们在编程过程中就不会有乱码的问题了，不会出现中文乱码，这是一个好消息。如果同学们以后在做Go开发的时候，你几乎遇不到乱码问题，中文乱码几乎遇不到，所以说这是一个好消息，那么我们也能够体现到Go语言它的这种简洁性。
