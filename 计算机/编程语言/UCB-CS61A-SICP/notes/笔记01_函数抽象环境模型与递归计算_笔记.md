# 函数抽象、环境模型与递归计算

## 表达式求值与执行模型

### 调用表达式与求值树

* **调用表达式（Call Expression）**

    * > **定义**：由一个运算符子表达式与紧随其后包裹在圆括号内、由逗号分隔的零个或多个操作数字表达式构成的复合计算形式。

    * 结构组成：包含一个运算符子表达式（Operator Sub-expression）与任意数量的操作数字表达式（Operand Sub-expressions）。

    * 求值规则：先从左至右依次求值运算符子表达式与所有操作数字表达式；再将运算符求值得到的函数对象应用于操作数求值得到的实参（Arguments）上。

    * 嵌套结构机理：调用表达式的嵌套次序通过表达式树（Expression Tree）由内向外、自底向上隐式驱动计算，子表达式求得的值作为实参向上层节点流动。

    * 树形推演结构：

        ```text
                             mul(...)  --->  208
                            /        \
                           /          \
                          /            \
        add(2, mul(4, 6)) ---> 26       add(3, 5) ---> 8
           /          \                    /     \
          /            \                  /       \
         2        mul(4, 6) ---> 24      3         5
                     /    \
                    /      \
                   4        6
        ```

### 赋值机制与名字绑定

* **赋值语句（Assignment Statement）**

    * > **定义**：将一个或多个名称与一个或多个表达式的即时求值结果建立单向引用的语句。

    * 执行两阶段规则：第一阶段从左至右对等号右侧的所有表达式进行全量求值；第二阶段将求得的确定值从左至右依次绑定到等号左侧的名字上。

    * 重新绑定规则：给既有变量名重新赋值会直接覆盖当前帧中该名字的旧绑定，不影响曾引用该对象的其他别名。

    * 别名机理：函数在 Python 中为一等公民（First-Class Citizens），可作为值赋给变量；给函数赋别名不会产生新函数对象，仅增加对同一内存实体的引用。

    * > **易错点**：⚠️ 赋值语句执行时仅记录右侧表达式计算出的当前数值快照，不建立动态依赖连接；后续修改右侧表达式中涉及的变量时，已赋值的变量绝不会联动更新。

### 纯函数、副作用与控制台输出

* **纯函数（Pure Function）**

    * > **定义**：调用时仅依据传入参数计算并返回确定结果，且不产生任何可被外部观察到的状态改变的函数。

    * 行为准则：相同输入必定产生相同输出，计算逻辑完全封装于封闭边界内部。

* **非纯函数（Non-pure Function）**

    * > **定义**：在计算或返回值之外，会引发外部环境状态变更或与外界发生交互的函数。

    * 副作用（Side Effect）：函数在“接收输入、返回输出”标准闭环之外产生的行为，包括向控制台打印字符（如 `print`）、写入文件等。

    * `print` 与交互式回显规则：`print` 函数执行的副作用是在终端输出字符，其返回值固定为 `None`；交互式解释器对表达式求值为 `None` 的结果执行静默吞没，不予打印。

    * 遗漏 Return 的隐式行为：函数若未包含显式 `return` 语句，或执行流程未触发 `return` 即结束，统一隐式返回 `None`。

    * 嵌套调用副作用时序：多层嵌套调用中，操作数自左向右评估时依次触发各自的副作用，最后才触发外层函数的副作用。

## 控制流与环境模型基础

### 复合语句与分支控制

* **复合语句（Compound Statement）**

    * > **定义**：由一个或多个子句构成的代码组织结构，每个子句包含决定性质的标头（Header）与保持统一缩进的代码套件（Suite）。

    * 套件执行规则：按从上到下的物理顺序逐一执行套件中的每一条语句，中途遇到跳转指令（如 `return`）时立刻中断退出。

* **条件语句（Conditional Statement）**

    * > **定义**：依据布尔表达式的真假状态决定代码分支执行路径的复合语句。

    * 分支规则：以一个 `if` 子句开头，后接零个或多个 `elif` 子句，以零个或一个 `else` 子句结尾；从上至下依次判定标头条件，一旦某标头评估为真值，执行其套件后立即跳过该复合语句所有剩余子句，最多仅有一个分支套件被执行。

    * 布尔上下文（Boolean Context）：条件标头所处的值判定环境，仅区分对象代表真还是假。

    * 真值与假值映射规则：

        | 逻辑类别 | 包含的具体值与对象 |
        | :--- | :--- |
        | **假值（Falsy Values）** | 布尔值 `False`、数字 `0`、空字符串 `""`、空值 `None` |
        | **真值（Truthy Values）** | 除假值之外的任何对象（包括非零整数、非空字符串等） |

### 短路求值与控制流模拟边界

* **短路求值（Short-circuit Evaluation）**

    * > **定义**：逻辑运算符在左侧操作数的值已足以确定整个表达式的布尔结果时，直接跳过右侧操作数求值的机制。

    * 逻辑与（`P and Q`）规则：评估 `P`，若 `P` 为假值则立即返回 `P` 的实际值，彻底跳过 `Q`；若 `P` 为真值，则评估 `Q` 并返回 `Q` 的实际值。

    * 逻辑或（`P or Q`）规则：评估 `P`，若 `P` 为真值则立即返回 `P` 的实际值，彻底跳过 `Q`；若 `P` 为假值，则评估 `Q` 并返回 `Q` 的实际值。

    * 保护机制应用：利用 `and` 在左侧前置合法性检查（如 `x > 0 and sqrt(x) > 10`），或利用 `or` 在左侧前置规避非法计算（如 `n == 0 or 1 / n != 0`）。

* **控制语句不可替代性定理**

    * > **定义**：普通调用表达式无法模拟分支控制语句的语义特性。

    * 本质原因：调用表达式在执行函数体前，必须无条件对括号内所有操作数子表达式完成全量求值；因此用普通函数（如 `if_(c, t, f)`）封装分支时，未选中分支中的非法计算（如负数开方、除以零）必然提前爆发异常。

### while 迭代与状态推进

* **while 循环（while Loop）**

    * > **定义**：在标头条件表达式持续保持为真值的前提下，重复循环执行套件代码的控制结构。

    * 执行周期：第一步评估标头表达式在布尔上下文中的真假；若为假值，跳过套件终止循环；若为真值，执行整个套件，套件执行完毕后无条件回到第一步重新评估标头。

    * > **易错点**：⚠️ 套件完整执行原则：即便循环体执行到中途某行赋值语句时，标头条件在逻辑上已被破坏变假，解释器也绝不会在此刻中途跳出循环；套件内的剩余代码必须严格执行完毕，直到控制流重新回到标头处时才会退出。

### 环境图解构与名字查找规则

* **帧（Frame）**

    * > **定义**：保存变量标识符到值对象单一映射关系的命名空间容器。

    * 命名唯一性约束：在同一个帧内，同一个名字绝不能重复出现，至多只能绑定到一个唯一的值。

* **环境（Environment）**

    * > **定义**：由一系列存在特定父子层级关系的帧组成的有序序列。

    * 环境追溯结构：一个环境的完整链条从指定的起始局部帧开始，沿着父级指针（Parent Pointer）一路单向追溯，最终终止于无父级的全局帧（Global Frame）。

* **名字查找规则（Name Lookup）**

    * > **定义**：解释器在指定环境中解析符号语义的线性遍历检索过程。

    * 检索优先级：从当前环境的第一个活动帧开始顺序搜索；名称将求值为在该环境序列中**最早**找到它的那个帧里所绑定的值；一旦命中立即取值并终止搜索；若遍历到全局帧仍未找到，抛出 `NameError`。

* **同名遮蔽（Shadowing）**

    * > **定义**：内层帧中声明的变量名与外层帧或全局帧中的变量同名时，外层同名实体在当前环境内被阻断访问的现象。

    * 独立性边界：局部帧中的同名遮蔽仅影响以此局部帧为起点构建的环境，不会篡改外层帧中原本绑定的对象实体。

    * 环境图骨架与遮蔽结构：

        ```text
        Global frame
        +-------------+-----------------------+
        | mul         | func mul(...)         |
        | square      | func square(x) [p=G]  |
        +-------------+-----------------------+
               ^                   ^
               | parent=Global     | parent=Global
        +------|------+     +------|------+
        | f1: square  |     | f2: square  |
        +-------------+     +-------------+
        | x: 3        |     | square: 4   | (形参同名遮蔽函数名)
        | Return: 9   |     | Return: 16  |
        +-------------+     +-------------+
        ```

## 高阶函数与过程抽象

### 计算泛化与过程参数化

* **高阶函数（Higher-Order Function，HOF）**

    * > **定义**：接收一个或多个函数作为输入参数，或者输出（返回）一个函数的函数。

    * 数值泛化机理：将计算模式中易变的常量提取为函数参数，收拢重复公式（如将图形面积公式提取为 `area(r, shape_constant)`）。

    * 过程泛化机理：将循环骨架、累加步进等控制结构抽象为通用模板，将每一步的具体计算操作封装为函数形参传入（如通用求和骨架 `summation(n, term)`）。

    * 断言（Assertion）：语句形式为 `assert <布尔表达式>, <错误信息>`；当且仅当条件为假时抛出 `AssertionError` 中断程序，用于防御非法输入。

### 嵌套定义与闭包持久化

* **词法作用域（Lexical Scope）**

    * > **定义**：函数内部可访问的名字范围完全由该函数在源码中被定义时的物理位置决定，而非由该函数被调用的运行时路径决定。

* **函数创建与调用的环境铁律**

    * 创建三步法（`def` / `lambda`）：在内存中创建函数对象并记录签名；将创建该函数时所在的当前执行帧无条件记录为该函数的父级帧（Parent Frame）；在当前活动帧中绑定函数名字。

    * 应用三步法：创建新的活动局部帧；将形参名称绑定至传入的实参；**将该新帧的父级无条件指向被调函数对象所记录的 Parent Frame**；在该新帧引导的环境序列中执行函数体。

    * 状态保持（闭包）机理：内层函数因诞生于外层函数的执行帧中，其函数对象永久引用该外层帧作为父级；即使外层函数调用结束退出，外层帧中的变量绑定仍随内层函数存活而驻留内存，供内层函数后续寻址。

    * > **易错点**：⚠️ 作用域越界反例：在全局帧定义的两个独立函数 `f` 与 `g`，即使在 `f` 的函数体内调用 `g`，`g` 执行时创建的新帧其父级必须是 Global 帧；`g` 绝对无法沿调用栈横向刺穿访问 `f` 的局部变量，违背词法作用域必然抛出 `NameError`。

    * 闭包与作用域链环境图：

        ```text
        Global frame
            make_adder ───► func make_adder(n) [parent=Global]
            add_three  ───► func adder(k)      [parent=f1]
        ------------------------------------------------------------
        f1: make_adder [parent=Global]
            n ────────────► 3
            adder ────────► func adder(k)      [parent=f1]
        ------------------------------------------------------------
        f2: adder [parent=f1]  <--- 继承函数自身 Parent，直接指向 f1
            k ────────────► 4
            Return: 7 (查找 k 命中 f2，查找 n 顺父级命中 f1)
        ```

### 匿名函数与柯里化

* **Lambda 表达式（Lambda Expression）**

    * > **定义**：使用 `lambda` 关键字在表达式层级直接构造无名函数对象的紧凑语法形式。

    * 语法形式：`lambda <形参列表>: <单个返回表达式>`。

    * 结构约束：严禁包含 `return` 关键字，主体只能是单一表达式，不能包含赋值、`while` 或 `for` 等语句。

    * 行为等价与差异对比：

        | 维度 | `square = lambda x: x * x` | `def square(x): return x * x` |
        | :--- | :--- | :--- |
        | **父级帧判定** | 取决于表达式求值时的当前活动帧 | 取决于语句执行时的当前活动帧 |
        | **内在名称（Intrinsic Name）** | 解释器内部与环境图中固定标记为 `<lambda>` | 拥有天然名称字符串（如 `'square'`） |
        | **绑定机理** | 先求得无名函数值，再通过常规赋值绑定给变量 | 创建函数对象的同时，隐式在当前帧完成名字绑定 |

* **柯里化（Currying）**

    * > **定义**：将一个接收多个参数的函数，转换为一系列每个都只接收单个参数且链式返回下一级单参函数的变换技术。

    * 双参数通用柯里化构造式：`curry2 = lambda f: lambda x: lambda y: f(x, y)`。

### 装饰器机理与语法糖

* **装饰器（Decorator）**

    * > **定义**：接收一个函数作为输入、返回一个功能增强后的替代函数的高阶函数。

    * 语法糖等价规则：在函数定义首行上方添加 `@decorator` 声明，在底层语义上与在定义后紧跟赋值语句进行重新绑定完全等价。

    * 形式等价对应：

        | 显式高阶函数赋值写法 | 装饰器语法糖写法 |
        | :--- | :--- |
        | `def square(x): return x * x`<br>`square = trace1(square)` | `@trace1`<br>`def square(x): return x * x` |

### 函数抽象屏障与程序健壮性

* **抽象屏障（Abstraction Barrier）**

    * > **定义**：在系统设计中隔离“功能意图”（What it does）与“具体实现”（How it does it）的逻辑边界。

    * 接口契约边界判定：

        | 考量维度 | 是否属于调用方必须掌握的信息 | 判据与机理 |
        | :--- | :---: | :--- |
        | **参数数量（Arity）** | **必须知道** | 调用方必须传入匹配数量的操作数，否则在运行时直接抛出 `TypeError`。 |
        | **外部行为契约（Behavior）** | **必须知道** | 必须确切知悉函数的输入输出映射效果，以维系上层业务组合的正确性。 |
        | **固有名称（Intrinsic Name）** | **不需要知道** | 仅用于调试显示，外部通过作用域当前绑定的符号引用实体即可正常调用。 |
        | **底层实现细节（Implementation）** | **不需要知道** | 实现无论采用原生算子、内置库还是复杂算法，对外部调用者必须完全透明。 |

* **DRY 原则（Don't Repeat Yourself）**

    * > **定义**：软件工程中消除重复逻辑、将相同的计算结构提取为独立命名组件的核心设计原则。

* **Python 错误类型体系**

    * 语法错误（SyntaxError）：代码在解析器执行前的编译解析阶段被拦截，常见于括号不闭合或冒号缺失。

    * 运行时错误（Runtime Error）：语法符合规范，但在解释器逐行执行期间爆发异常并崩溃（如 `ZeroDivisionError`, `TypeError`）。

    * 逻辑与行为错误（Logical Bug）：程序全程畅通执行未崩溃，但输出的业务数值与正确预期不符。

    * 回溯报告（Traceback）解读法则：最底层提示异常类型与具体计算错误；中间各层指示调用栈的深浅分布与报错语句；报错行号指示解释器首度无法继续运行的“案发现场”，真正的缺陷诱因往往位于调用栈更早期的参数传递或函数定义内部。

## 递归计算机制

### 递归解剖与信仰飞跃

* **递归函数（Recursive Function）**

    * > **定义**：在其函数体内部直接或间接调用了自身的函数。

    * 双核心骨架：

        | 组成部分 | 触发条件 | 核心职责 |
        | :--- | :--- | :--- |
        | **基准情况（Base Case）** | 达到不可再分的最小输入规模 | 直接计算并返回确切值，绝不发起递归调用，充当递归终止的制动刹车。 |
        | **递归情况（Recursive Case）** | 输入规模大于基准条件 | 将原问题拆解，发起调用处理更小规模的子问题，并将子结果组合为原问题解。 |

* **递归的信仰飞跃（Recursive Leap of Faith）**

    * > **定义**：在编写或验证递归函数时，严禁人脑深潜追踪多层递归展开，直接将内层递归调用视作已经正确实现的黑盒抽象的思维范式。

    * 三步验证法：
        1. 验证基准情况：确认边界输入是否能无条件给出符合数学定义的正确解；
        2. 假设递归黑盒成立：严禁脑补展开过程，直接假定下一层递归调用必然产出正确的数学结果；
        3. 验证组合逻辑：基于第二步的正确假设，推导当前层通过合并子问题结果是否能严密推导出原问题的解。

### 递归环境展开与调用栈

* **递归执行机制**

    * 下潜与挂起（Unwinding）：原问题尚未解决前，每次触发递归调用，当前活动帧的后续代码必须原地挂起，系统为新调用开辟全新局部帧。

    * 触底与回溯（Rewinding）：最深层调用命中基准情况并给出初始确定值后，执行权自底向上逆向交还，各层挂起的运算利用接收到的子结果完成计算并依次返回。

    * 变量隔离保障：求值永远发生在当前活动环境（Current Environment）中，多层递归创建的同名局部变量分别密封于各自独立的活动帧内，调用栈的严格出入栈顺序确保了环境查找绝不混淆。

    * 阶乘 `fact(3)` 环境调用栈展开时序：

        ```text
        Step 1: 递归下潜 (Unwinding)
        Global
          └── f1: fact(n=3) ──> 挂起等待计算 3 * fact(2)
                └── f2: fact(n=2) ──> 挂起等待计算 2 * fact(1)
                      └── f3: fact(n=1) ──> 挂起等待计算 1 * fact(0)
                            └── f4: fact(n=0) ──> 命中 Base Case，返回 1

        Step 2: 结果回溯 (Rewinding)
          f4 返回 1 给 f3 ──> f3 计算 1 * 1 = 1 并返回
          f3 返回 1 给 f2 ──> f2 计算 2 * 1 = 2 并返回
          f2 返回 2 给 f1 ──> f1 计算 3 * 2 = 6 并向全局返回
        ```

* **自我引用（Self-Reference）**

    * > **定义**：函数在函数体内通过访问环境链中的自身名称，将函数对象自身作为值向外传递或返回的模式。

    * 链式调用控制：仅返回自身函数实体而不内部直接调用自身的函数（如 `def print_all(x): print(x); return print_all`）不会形成无限递归，其执行深度严格受控于外部书写的链式调用括号个数。

### 相互递归与状态机

* **相互递归（Mutual Recursion）**

    * > **定义**：两个或多个函数在其函数体内彼此交替调用对方构成的递归协作网络。

* **Luhn 算法状态机**

    * > **定义**：用于校验信用卡等标识码合法性的模 10 校验算法。

    * 校验流程：自右向左处理，最右侧第 1 位（校验位）保持原样；从倒数第 2 位起偶数位逐项加倍；加倍结果若大于 9，则将其各位数字相加折叠；最终对所有处理后的位值求和，总和能被 10 整除则卡号合法。

    * 相互递归实现拓扑：函数 `luhn_sum` 剥离末位直接累加，将剩余数位丢给 `luhn_sum_double`；函数 `luhn_sum_double` 剥离末位翻倍折叠后，将剩余数位丢回 `luhn_sum`，以函数交替调用模拟状态切换。

### 迭代与递归的等价转化

* **迭代转递归机械化法则**

    * > **定义**：将显式命令式循环等价重构为声明式递归的过程。

    * 转换准则：
        1. 识别循环变量：找出 `while` 循环中所有随迭代步进而被重新赋值的状态变量；
        2. 映射为递归参数：将所有状态变量提升为辅助递归函数的形参；
        3. 循环条件转基准情况：将循环终止条件翻转为递归的 Base Case 条件，并在命中时返回当前状态累加器；
        4. 循环体更新转实参传递：将循环体内变量的重新计算逻辑，打包为下一次递归调用的实际参数。

    * 累加器模式（Accumulator Pattern）：将中间计算状态作为实参沿着递归调用链单向向下传递，到达递归底部时直接交出累加结果。

## 树递归与分支分治

### 调用时序与级联结构

* **函数调用时序法则**

    * > **定义**：调用表达式在执行时具备同步阻塞特性，当前函数的后续指令必须在被调函数完全返回并移交控制权后方可继续推进。

* **级联函数（Cascade）**

    * > **定义**：在递归调用前后分别排布输出语句，呈现对称镜像计算形态的代码结构。

    * 级联时序结构：递归调用发生之前的语句在由浅入深的下潜阶段顺序执行；递归调用发生之后的语句在由深至浅的回溯阶段逆序执行。

    * 逆向级联生长与收缩法则：
        * 生长阶段（Grow，递增打印）：必须先深入递归处理更小子问题，利用回溯时序后执行打印输出；
        * 收缩阶段（Shrink，递减打印）：必须先执行打印输出，再深入递归调用更小子问题。

### 树递归展开与冗余陷阱

* **树递归（Tree Recursion）**

    * > **定义**：函数体内包含两次或多次对自身的递归调用，导致执行流程分岔展开为调用树形态的递归结构。

    * 执行时序准则：计算机严格遵循自左向右深度优先的次序遍历整棵调用树；必须完全遍历完毕左侧子树的所有分支并彻底返回后，才会启动右侧子树的计算。

    * 重复计算缺陷：朴素树递归（如朴素斐波那契 `fib(n-2) + fib(n-1)`）在分支展开中会以指数级爆炸式重复计算完全相同的重叠子问题（如计算 `fib(5)` 时多次完全重算 `fib(3)` 和 `fib(2)`），导致时间开销剧增。

    * 斐波那契树递归展开拓扑：

        ```text
                                 fib(5)
                             /           \
                       fib(3)             fib(4)
                      /      \           /      \
                  fib(1)    fib(2)    fib(2)    fib(3)
                           /     \   /     \   /     \
                         fib(0) fib(1) ...  ... ...  ...
        ```

### 组合探索与整数分区

* **整数分区（Counting Partitions）**

    * > **定义**：正整数 $n$ 使用不超过 $m$ 的正整数部分进行分割、按升序相加排列的不同组合方案总数。

    * 分治拆解定理：将针对 $(n, m)$ 的解空间严格划分为两个互斥且穷尽的子集合：
        * 至少使用一个零件 $m$：既然已固定选用一个零件 $m$，剩余目标和为 $n - m$，后续允许使用的最大零件依然为 $m$，即转化为子问题 `count_partitions(n - m, m)`；
        * 完全不使用零件 $m$：所有可用零件尺寸必须小于 $m$，即转化为子问题 `count_partitions(n, m - 1)`；
        * 方案总数等于两个互斥子集解之和：`count_partitions(n - m, m) + count_partitions(n, m - 1)`。

    * 分区问题基准情况判定准则：

        | 判定条件 | 返回值 | 语义本质与判定机理 |
        | :--- | :---: | :--- |
        | **$n == 0$** | `1` | 选取的一系列零件总和恰好等于目标值，寻得 1 条完全合法的拆解路径。 |
        | **$n < 0$** | `0` | 前序零件累加超出目标数值，该零件选取路径组合无效，计 0 次。 |
        | **$m == 0$（且 $n > 0$）** | `0` | 已无任何可用正整数零件，无法完成对正整数目标和的填充，计 0 次。 |

## 序列容器与复合数据遍历

### 列表容器与序列运算

* **列表（List）**

    * > **定义**：容纳零个或多个任意类型对象且按固定线性顺序排列的可变内置序列容器。

    * 偏移索引法则：采用从 0 开始的非负整数寻址；索引值在物理底层代表**相对于序列起始位置的偏移量（Offset）**；末尾有效元素索引固定为 `len(s) - 1`。

    * 序列运算符：
        * 加法拼接（`+`）：将两个独立序列连接生成全新的合并序列；
        * 乘法重复（`*`）：将原序列中的元素浅拷贝重复指定整数次。

* **成员关系测试（`in` 运算符）**

    * > **定义**：判定特定元素值是否存在于目标序列中的布尔运算操作。

    * > **易错点**：⚠️ `in` 运算符只进行单层浅层扫描，严格按元素全等匹配。它绝不会自动递归深入到嵌套子列表内部查找标量；亦不会在序列中去搜寻局部的“子序列”。

    * 成员测试边界行为特征：

        | 判定表达式 | 计算结果 | 判定机理 |
        | :--- | :---: | :--- |
        | `'1' in [1, 8, 2, 8]` | `False` | 严格匹配类型与值：字符串 `'1'` 不等于整数 `1`。 |
        | `[1, 8] in [1, 8, 2, 8]` | `False` | `in` 仅寻找独立单个元素，不检索子序列切片。 |
        | `[1, 2] in [[1, 2], 3]` | `True` | 列表 `[1, 2]` 是外层列表的第一层独立元素。 |
        | `1 in [[1, 2], 3]` | `False` | `in` 仅扫描外层顶层元素，不递归深潜嵌套列表内部。 |

### 序列遍历与解析推导

* **for 循环（for Loop）**

    * > **定义**：按照特定顺序逐一迭代可迭代对象中每个元素的控制语句。

    * 执行机理：评估标头 `in` 右侧表达式得到序列；依次取出首个及后续元素直接绑定至指定的循环变量；针对每个绑定执行一次套件；序列耗尽时循环结束。

    * 环境帧约束：执行 `for` 语句不会引入新的执行环境帧，循环变量直接在当前所在的活动帧内完成赋值与重新绑定。

    * 序列解包（Sequence Unpacking）：若序列中的元素本身为等长复合结构，可在 `for` 标头处直接写出多个变量名（如 `for x, y in pairs:`），单步迭代时自动触发多元赋值。

* **Range 序列**

    * > **定义**：表示一段左闭右开连续整数区间的内置不可变序列类型。

    * 区间定义特征：`range(start, end)` 严格包含起始值 `start`，但排除结束值 `end`。

    * 数学属性：序列长度固定为 `end - start`；索引为 $i$ 的元素值严格满足公式 $\text{value} = \text{start} + i$；缺省 `start` 时默认自 $0$ 起步。

    * 惯例：当仅需循环固定频次而无需在套件中引用计数值时，习惯采用单下划线 `_` 作为循环变量名。

* **列表推导式（List Comprehension）**

    * > **定义**：结合映射表达式、序列遍历与可选过滤条件，在一行内直接声明性构造全新列表的复合表达式结构。

    * 语法模板：`[<映射表达式> for <变量名> in <源序列> if <过滤条件>]`。

    * 求值时序：自左向右遍历源序列中的每一项并绑定至变量；若包含 `if` 子句，仅当过滤条件求值为真值时保留该元素；将通过过滤的元素输入映射表达式完成计算；将所有计算结果按遍历顺序收集为新列表并返回。
