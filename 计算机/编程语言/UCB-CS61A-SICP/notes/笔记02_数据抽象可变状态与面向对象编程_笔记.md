# 数据抽象、可变状态与面向对象编程

## 序列容器与分层抽象

### 封闭属性与环境图表示

* **封闭属性（Closure Property）**

    * > **定义**：组合数据的方法所产生的结果，自身可以继续使用完全相同的方法再次进行组合的数学与结构特性。

    * 封闭性使得离散元素能够层层嵌套，构造出表达部分与整体关系的**分层结构（Hierarchical Structure）**。
    * Python 列表（List）满足封闭属性，其内部可无差别容纳整数、布尔值、函数以及其他列表。

* **方框与指针表示法（Box-and-Pointer Notation）**

    * > **定义**：在内存环境模型中透视复合数据拓扑结构的图形化抽象表示法。

    * 容器表现为一行带有从 0 开始的非负整数索引标签的相邻方框序列。
    * **原始值装载规则**：整数、布尔值、`None` 等不可再分的原子原始值（Primitive Value）直接记录在对应索引的方框内部。
    * **复合值装载规则**：嵌套列表、函数对象等复合值（Compound Value）绝对不置于方框内，方框内画出引向独立内存堆对象的单向指针（箭头）。

    ```text
    nested_list
         |
         v
       +---+---+---+
       | * | * | * |
       +---+---+---+
         0   1   2
         |   |   |
         |   |   +--------------------------+
         |   v                              v
         v  +---+ (空列表)                +---+---+
       +---+---+                          | * | * |
       | 1 | 2 |                          +---+---+
       +---+---+                            0   1
         0   1                              |   |
                                            v   v
                                         func  +---+---+---+
                                               | 3 | F | - |
                                               +---+---+---+
                                                 0   1   2
    ```

### 序列切片与高阶聚合

* **序列切片（Slicing）**

    * > **定义**：利用方括号内置冒号语法，以指定索引边界提取序列连续子集的运算符。

    * 语法格式为 `seq[start:end]`，遵循闭开区间 $[start, end)$ 规则，包含起始索引，排除结束索引。
    * 省略 `start` 默认从索引 0 开始；省略 `end` 默认截取至序列末端；两头均省略的 `seq[:]` 截取完整序列。
    * > **易错点**：切片操作在内存中永远分配新方框并创建新列表值副本，原序列不受影响。

* **序列聚合函数（Sequence Aggregation Functions）**

    * > **定义**：接收可迭代序列并将其所有离散项合并归约计算为单一标量值的高阶接口。

    * `sum(iterable, /, start=0)`：按顺序累加元素。可选参数 `start` 决定累加基底。显式指定 `start=[]` 可实现嵌套子列表的单层压平展开（Flattening）；严禁将 `sum` 用于拼接字符串列表。
    * `max(iterable, key=None)` 与 `min(iterable, key=None)`：返回极值元素。当指定 `key=f` 时，按元素经过函数投射后的像值 $f(x)$ 判定大小，最终返回原象元素 $x$ 本身。
    * `all(iterable)` 与 `any(iterable)`：执行全称与存在量词布尔判定。空迭代器输入时，`all` 恒返回 `True`；`0` 与空字符串 `''` 在布尔上下文中判定为假值，其余有效数字与非空字符串判定为真值。

### 文本序列与映射字典

* **字符串（String，str）**

    * > **定义**：用于承载与表达任意文本字符流的不可变序列抽象。

    * 单引号 `'...'` 与双引号 `"..."` 语义完全一致；三引号 `'''...'''` / `"""..."""` 原生支持跨行书写；转义控制符 `\n` 表示物理换行。
    * **行为差异对比**：

        | 维度 | 列表 `list` | 字符串 `str` |
        | :--- | :--- | :--- |
        | **单元素选择** | `[10, 20][0]` 返回整数 `10`（类型转变） | `'Berkeley'[0]` 返回单字符字符串 `'B'`（类型不变） |
        | **成员判定 `in`** | 仅按单元素全等匹配 | 原生支持子序列（连续子字符串）模式匹配 |

* **字典（Dictionary，dict）**

    * > **定义**：通过任意不可变键将输入映射到对应值的键值对（Key-Value Pair）容器。

    * **单向寻址机制**：仅支持基于键检索值 `dict[key]`。若键不存在则抛出 `KeyError`；不支持逆向由值查键，亦不支持通用整数位置物理偏移下标。
    * **序列本质**：字典在迭代上下文中表现为**键的序列**。`for k in d:` 遍历键；`d.values()` 返回只读映射序列 `dict_values`。
    * **键的强约束铁律**：键必须互异，重复赋值直接覆盖旧值；键必须具备不可变性（Immutable），列表与字典属于非散列类型（Unhashable），严禁充当字典的键。
    * **字典推导式（Dictionary Comprehension）**：通用语法 `{key_expr: value_expr for name in iterable if filter_expr}`，通过独立临时帧执行过滤筛选与键值映射装配。

## 数据抽象与层次树结构

### 行为条件与分层抽象屏障

* **数据抽象（Data Abstraction）**

    * > **定义**：通过一组构造器（Constructor）与选择器（Selector）对外界隔离具体存储细节、仅以既定行为规范定义复合数据的方法论。

    * **行为条件（Behavioral Conditions）**：验证数据抽象有效性的代数关系式。对于由分子 $n$ 与分母 $d$ 构成的有理数对象 $x = \text{rational}(n, d)$，其必须满足：
      $$\frac{\text{numer}(x)}{\text{denom}(x)} = \frac{n}{d}$$
    * **抽象屏障（Abstraction Barrier）**：将系统垂直划分为多层契约架构，上层仅依赖相邻下层暴露的语义接口，严禁越级刺探底层容器实现。

    ```text
    +-------------------------------------------------------------+
    |                   使用有理数进行业务计算的程序                  |
    +=============================================================+ <--- 屏障：add_rational, mul_rational
    |                   有理数算术实现层（分子分母代数逻辑）           |
    +=============================================================+ <--- 屏障：rational, numer, denom
    |                   构造器与选择器定义层                         |
    +=============================================================+ <--- 屏障：具体存储表示
    |                   底层实现机制（列表、字典、函数闭包）          |
    +-------------------------------------------------------------+
    ```

    * **屏障防御优势**：在构造器 `rational(n, d)` 内部引入最大公约数（Greatest Common Divisor, GCD）化简除法 $n // g, d // g$ 时，所有上层算术运算与终端打印代码零改动即可实现最简分数自动化维护。
    * > **易错点**：⚠️ 在算术逻辑或业务层绕过选择器直接编写下标索引（如 `x[0]`）或字面量容器组装，将彻底破坏模块封装，底层存储形式迁移时会导致程序大面积崩溃。

### 纯函数数据表示与闭包状态

* **高阶函数闭包数据表示**

    * > **定义**：完全脱离物理容器硬件绑定，纯粹依赖高阶函数调度与父环境帧变量绑定机制构建复合数据对象的实现形式。

    * **函数构造器与选择器协议**：
        ```python
        def rational(n, d):
            def select(name):
                if name == 'n':
                    return n
                elif name == 'd':
                    return d
            return select

        def numer(x):
            return x('n')

        def denom(x):
            return x('d')
        ```
    * **环境图推演机理**：
        1. 调用 `rational(3, 8)` 生成活动帧 `f1`，绑定形参 `n: 3, d: 8`。
        2. 内部函数 `select` 固化其父作用域为 `f1`，该函数对象被返回并绑定至全局变量 `x`。
        3. 调用 `numer(x)` 时触发执行 `x('n')`，生成父作用域指向 `f1` 的局部帧 `f3`。
        4. 变量查找沿环境链逐级回溯至 `f1` 并成功取出 `n = 3`。这证明行为条件得到满足时，函数闭包在语义上等价于数据。

### 树的抽象数据类型与递归计算模式

* **树（Tree）**

    * > **定义**：由一个根标签（Root Label）和一组分支（Branches）构成的层级数据抽象，其中每个分支本身均为一棵合法的树。

    * **双重视角隐喻**：植物隐喻强调递归嵌套自相似性，分支为空的树称为叶子（Leaf）；家谱隐喻强调相对空间拓扑，涵盖根节点（Root Node）、父节点（Parent）、子节点（Child）与兄弟节点（Siblings）。
    * **规范接口构造**：
        ```python
        def tree(label, branches=[]):
            for branch in branches:
                assert is_tree(branch), '分支必须是树'
            return [label] + list(branches)

        def label(t):
            return t[0]

        def branches(t):
            return t[1:]

        def is_leaf(t):
            return not branches(t)
        ```
    * **递归心智模型划分**：
        * **自底向上后序聚合（向上返回）**：依赖子调用返回值在回溯阶段合并。计算叶子节点总量：
          $$\text{count\_leaves}(t) = \begin{cases} 1 & \text{若 } \text{is\_leaf}(t) \\ \sum_{b \in \text{branches}(t)} \text{count\_leaves}(b) & \text{否则} \end{cases}$$
        * **自顶向下前序累加（向下传递）**：将祖先节点累积状态通过形参压入递归调用。如路径和搜索 `print_sums(t, so_far)` 将当前标签叠加进 `so_far` 后向下派发。
    * **双重统计拆分（路径和等于目标值 `count_paths`）**：
        * 路径集严格分解为两类互斥事件之和：终止于当前根节点的路径（判定 $\text{label}(t) == \text{total}$）；穿过根节点继续深入子分支的路径（对各分支递归求解目标差值 $\text{total} - \text{label}(t)$）。

## 可变性机制与局部持久状态

### 对象的变异机理与函数副作用

* **变异（Mutation）**

    * > **定义**：可变对象在其内存物理身份保持不变的前提下，内部数据状态随时间演进而发生原地修改的动态过程。

    * **原地修改操作符**：列表方法 `.pop()`（截断尾部元素）、`.append(x)`（尾部追加单项）、`.extend(L)`（合并序列）；索引赋值 `s[i] = val` 与切片赋值 `s[start:end] = L`。
    * **别名传播规则**：当多个变量绑定到同一个内存对象指针时，对该对象的任意就地变异操作将通过指针引用无差别体现在所有别名变量上。
    * **函数副作用（Side Effect）**：当可变对象作为实参传入函数后，局部帧内形参对该对象发起的变异操作将永久改变外部调用环境下的对象状态。

### 不可变性保护与对象身份同一

* **元组（Tuple，tuple）**

    * > **定义**：一旦创建其内部元素序列的物理引用链条便无法被原地篡改的不可变容器。

    * **语法约束**：定义元组的核心标识符为逗号而非圆括号。单元素元组必须显式追加尾随逗号 `(2,)`；若省略逗号，`(2)` 在语义上解析为带括号优先级的普通整数标量。
    * **浅层不可变边界**：不可变容器仅保证自身槽位的指针值固定不变。若元组内部包含列表等可变复合对象，该列表内部的状态依旧可以被原地变异。
    * **同一性与等价性判定判定准则**：

        | 判定机制 | 运算符 | 语义本质 | 判定条件 |
        | :--- | :--- | :--- | :--- |
        | **内容相等（Equality）** | `==` | 结构值等价 | 两表达式求值结果的包含内容与逻辑拓扑一致 |
        | **身份同一（Identity）** | `is` / `is not` | 物理地址唯一 | 两表达式指向堆内存中完全一致的同一内存实体 |

### 可变默认参数陷阱与元素赋值闭包

* **可变默认参数陷阱**

    * > **易错点**：⚠️ 函数默认参数表达式并非在函数调用时动态求值，而是在解释器执行 `def` 语句创建函数对象时完成求值并永久绑定至该函数实体。
    * 声明 `def f(s=[]):` 会导致多次默认缺省调用共享同一个底层的列表实体，变异操作会跨调用累积，破坏函数的确定性。

* **元素赋值与持久局部状态实现**

    * > **机理**：利用可变单元素列表与对象内部修改绕开 Python 局部作用域变量重绑定规则。

    * **变量作用域冲突**：在内层嵌套函数中直接执行 `balance = balance - amount` 会被解释器标记为当前帧的局部变量赋值，因而在读取时引发未绑定局部变量异常。
    * **元素赋值解法**：在外层创建 `b = [balance]`，在内层调用 `b[0] = b[0] - amount`。`b[0]` 属于**元素赋值（Element Assignment）**，不触发当前执行帧的变量名绑定，解释器沿着父框架指针链查找外层帧捕获该列表，实现原地状态突变与跨调用的记忆持久化。

    ```text
    Global frame
      make_withdraw_list ----> func make_withdraw_list(balance)
      withdraw --------------\
                             |
    f1: make_withdraw_list   |
      balance: 100           |
      b: [ 50 ] <------------+--------\ (withdraw 内部的 b[0] 修改原地修改该对象)
      withdraw -------------> func withdraw(amount) [parent=f1]

    f2: withdraw [parent=f1]
      amount: 25   (读取 f1 中 b[0] 的 100，原地改写为 75)

    f3: withdraw [parent=f1]
      amount: 25   (读取 f1 中 b[0] 的 75，原地改写为 50)
    ```

## 迭代器生成器协议与惰性序列

### 迭代器接口与遍历消费模型

* **迭代器协议（Iterator Protocol）**

    * > **定义**：为顺序数据提供统一单向按需访问支持的一组底层调用接口规范。

    * `iter(iterable)`：接收可迭代对象并生成其对应的独立迭代器。
    * `next(iterator)`：步进检索序列的下一个元素，并将内部光标前移；序列耗尽时抛出 `StopIteration` 异常。
    * **独立光标特性**：针对同一底层容器调用 `iter()` 生成的多个独立迭代器，各自独立维护自身的光标状态，互不干涉。
    * **字典遍历中的结构突变限制**：字典支持键（`.keys()`）、值（`.values()`）、键值对（`.items()`）三重视图迭代器。若在迭代推进过程中对字典执行新增或删除键的操作，底层的哈希表结构变更会导致迭代器失效，下一次调用 `next()` 立即抛出 `RuntimeError`；仅修改已有键的值不破坏迭代状态。

* **可迭代对象与迭代器模型对比**

    | 核心属性 | 可迭代对象（Iterable，如 `range`, `list`） | 迭代器（Iterator，如 `iter(...)` 生成的对象） |
    | :--- | :--- | :--- |
    | **光标状态** | 仅容纳数据集合本身，不持有单次遍历游标 | 内部捆绑光标状态，记录当前所处绝对步进位置 |
    | **可变性质** | 容器本身可为可变或不可变类型 | 自身恒为可变对象，执行 `next()` 必改写内部光标 |
    | **重复遍历** | `for` 循环每次介入均从头完整重播 | 单向单次消费，遍历耗尽后无法复位或重头再来 |

### 惰性序列处理与管道级联

* **惰性计算（Lazy Evaluation）**

    * > **定义**：将具体计算过程推迟至外部实际索取目标结果瞬间才予以执行的求值模型。

    * 内置函数 `map`、`filter`、`zip`、`reversed` 返回的均为迭代器对象，在被显式调用 `next()` 之前，不执行任何具体的数据运算。
    * **管道级联（Pipeline Cascading）**：级联组合 `filter(pred, map(func, seq))` 构建数据加工流水线，各中间阶段仅按需求拉取最小必要数据，杜绝整体内存实例化分配。
    * **回文序列判定边界**：`reversed(s)` 返回单向迭代器，`s == reversed(s)` 因容器与迭代器类型不同恒为 `False`。正确解法为利用生成器比对 `all(a == b for a, b in zip(s, reversed(s)))`，具备短路求值与解耦特性。

### 生成器函数与委托生成

* **生成器函数（Generator Function）**

    * > **定义**：函数体内部包含 `yield` 关键字、在被调用时返回生成器对象的专用函数。

    * **执行流挂起与苏醒**：调用生成器函数时不执行任何函数体语句；首次对生成器调用 `next()` 时，执行至首个 `yield <expr>` 处交出数据并返回，同时**冻结**当前帧的所有局部命名空间绑定及程序计数器（Program Counter, PC）；下次调用 `next()` 时，从挂起点无缝唤醒继续向下执行。
    * **委托生成语法（`yield from`）**：
        * `yield from <iterable>` 自动将当前生成器的控制权全权委托给子迭代器，直到子序列完全耗尽。
        * 递归生成器实现：
            ```python
            def prefixes(s):
                if s:
                    yield from prefixes(s[:-1])
                    yield s

            def substrings(s):
                if s:
                    yield from prefixes(s)
                    yield from substrings(s[1:])
            ```
        * > **易错点**：⚠️ 严禁将递归委托写为 `yield recursive_gen(...)`。若缺少关键字 `from`，语句将交出生成器对象实体本身，而非逐项产出内部元素。
    * **整数分割生成器（`partitions`）**：
        ```python
        def partitions(n, m):
            if n > 0 and m > 0:
                if n == m:
                    yield str(m)
                for p in partitions(n - m, m):
                    yield p + ' + ' + str(m)
                yield from partitions(n, m - 1)
        ```
        相比全量列表递归追加的指数级内存暴涨，生成器模型在探索庞大解空间时，提取前 $k$ 个解具备极低常数级的纳秒级初响应延迟与微量内存占用。

## 面向对象范式与属性分层机制

### 类实例化流程与本地状态封装

* **类（Class）与实例（Instance）**

    * > **定义**：类是定义一类对象共有属性与行为逻辑的模具（在 Python 中属于一级值）；对象则是根据该模具物化生成的具体实例。

    * **两步实例化机理**：
        1. 执行 `obj = Account('John')` 时，系统在堆内存开辟全新的空白实例空间。
        2. 自动调用类内定义的构造方法 `__init__(self, ...)`，新创建的空白对象自动充当首参数绑定到 `self`，其余入参填充后续形参，完成实例属性初始化。
    * **本地状态（Local State）**：各个实例维护专属于自身的实例属性。对某一个对象 `self.balance` 的修改完全限制在该实例的作用域封闭边界内。

### 属性查找链与赋值不对称性

* **属性查找链（Attribute Lookup Chain）**

    * > **规则**：执行 `<expression>.<name>` 时严格遵循由近及远的分层检索链条。

    ```text
    求值 <expression> 获得对象
              │
              ▼
    实例字典中是否存在 <name>？ ──[是]──> 返回其实例属性值
              │
             [否]
              ▼
    所属类字典中是否存在 <name>？
              │
             [是]
              ├─ 是函数 ──> 封装并返回绑定方法（Bound Method）
              └─ 非函数 ──> 直接返回该共享类属性值
              │
             [否]
              ▼
    沿基类继承树向上检索 ──[未找到]──> 抛出 AttributeError 异常
    ```
    * `getattr(obj, name)` 与 `hasattr(obj, name)` 提供针对该检索机制的动态反射。

* **属性赋值的不对称性（Assignment Asymmetry）**

    * > **规则**：带有点号的赋值语句仅针对点号左侧求值出的物理实体产生作用。

    * **实例赋值**：点号左边为实例时（如 `tom_account.interest = 0.08`），操作永远且仅在**实例级别**生效，在其实例字典中新增或修改同名属性，**遮蔽（Shadow）**类属性，绝不回写类对象。
    * **类属性赋值**：点号左边为类名时（如 `Account.interest = 0.04`），操作修改类对象内部属性，所有未定义同名特化属性的实例在后续查找时均感知到此全局更新。已具备特化遮蔽属性的实例不受类属性变更影响。

### 函数与绑定方法的一级对象特性

* **函数（Function） vs 绑定方法（Bound Method）**

    * > **定义**：通过类访问获取的是底层非绑定函数；通过实例访问获取的是与该特定实例绑定的绑定方法。

    * **非绑定函数**：`Account.deposit` 表现为 `<function Account.deposit>`，调用必须手动传入全部形参 `Account.deposit(tom, 100)`。
    * **绑定方法**：`tom.deposit` 表现为 `<bound method Account.deposit of tom>`，已预先将实例 `tom` 固化为第一个实参。调用时只需传入后续参数 `tom.deposit(100)`。
    * **一级值应用**：绑定方法可脱离原对象直接作为独立参数传递给高阶函数，如 `map(a.deposit, range(10))`，通过迭代器按需调用将持续修改闭包实例 `a` 的本地状态。

## 继承层次与对象组合模型

### 类的专业化与基类调用规范

* **继承（Inheritance）**

    * > **定义**：在通用基类（Base Class）的基础上衍生子类（Subclass），共享基类全部属性并在子类中实现专业化（Specialization）特化的机制。

    * **代码复用与单一事实来源（DRY 原则）**：子类仅需声明与基类产生差异的类属性与方法覆盖（Override）。
    * **显式基类调用规范**：
        ```python
        class CheckingAccount(Account):
            withdraw_fee = 1
            interest = 0.01

            def withdraw(self, amount):
                return Account.withdraw(self, amount + self.withdraw_fee)
        ```
        子类重写方法需要复用基类逻辑时，通过 `BaseClass.method(self, ...)` 显式调用。通过类对象访问的方法未绑定实例，必须显式将子类的当前实例 `self` 作为第一参数送入。
    * **特化扩展规范**：在方法内引用属性应统一写为 `self.withdraw_fee` 而非写死类名 `CheckingAccount.withdraw_fee`，确保后续深层继承子类或个别实例动态覆盖手续费属性时能够由动态查找链正确解析。

### 属性查找解析链与多重继承

* **属性继承解析链**

    * > **规则**：继承非数据拷贝，而是动态沿继承链自底向上回溯查找。

    * 实例自身命名空间 $\to$ 实例化所属子类 $\to$ 抽象基类 $\to$ 顶层基类。
    * **多重继承（Multiple Inheritance）**：类声明形如 `class AsSeenOnTVAccount(CheckingAccount, SavingsAccount):`，具备多基类的行为融合。子类属性优先级恒高于所有基类。

* **属性嵌套追踪经典案例推导**

    * 结构定义与绑定序列：
        ```python
        class A:
            c = -1
            def f(self, x): return B(x - 1)

        class B(A):
            n = 4
            def __init__(self, y):
                if y: self.c = self.f(y)
                else: self.c = C(y + 1)

        class C(B):
            def f(self, x): return x

        a = A()
        b = B(1)
        b.n = 5
        ```
    * **追踪解析推论**：
        * 求值 `C(2).n`：`C` 无构造器，回溯执行 `B.__init__(self, 2)`。`self.f` 优先匹配 `C.f`，返回 `2` 绑定至 `self.c`。随后查找 `.n`，实例无、类 `C` 无，沿继承链在类 `B` 中命中类属性 `n = 4`。
        * 求值 `a.c == C.c`：`a.c` 查 `A.c` 得 `-1`；`C.c` 沿继承链向上查 `B`、`A` 得 `-1`。两值均为整数标量，布尔判断为 `True`。
        * 实例 `b = B(1)` 的连续解引用拓扑：
            1. `b` 实例化：`y=1`，执行 `self.f(1)`，查找 `A.f(1)`，返回新实例 $B_0$（此时 `b.c = B(0)`）。
            2. $B_0$ 实例化：`y=0`，执行 `self.c = C(1)`，返回新实例 $C_1$（此时 $B_0.c = C(1)$）。
            3. $C_1$ 实例化：`y=1`，执行 `self.f(1)`，命中 `C.f(1)`，直接返回整数 `1`（此时 $C_1.c = 1$）。
        * 引用链深度：
          $$\begin{aligned} b &\implies \text{实例 } B_0 \\ b.c &\implies \text{实例 } B_0 \\ b.c.c &\implies \text{实例 } C_1 \\ b.c.c.c &\implies \text{整数 } 1 \\ b.c.c.c.c &\implies \text{抛出 AttributeError: 'int' object has no attribute 'c'} \end{aligned}$$
        * 从而 `a.c == b.c` 等价于 `-1 == <B object>`，结果为 `False`；上述表达式中仅 `b.c.c.c` 最终求值为整数。

### 概念模型甄别：继承与组合

* **继承与组合设计准则**

    * > **判定准则**：严格区分系统实体间的语义拓扑关系。

    * **继承表达 `is-a`（是一个）**：子类必须是基类的更特化形态。如支票账户是一种银行账户（`CheckingAccount is an Account`）。
    * **组合表达 `has-a`（拥有）**：一个主体对象将其他独立对象收纳为其属性字段。如银行拥有一组账户（`Bank has-a list of Accounts`）。
    * **组合实现范式**：
        ```python
        class Bank:
            def __init__(self):
                self.accounts = []

            def open(self, holder, amount, kind=Account):
                account = kind(holder)
                account.deposit(amount)
                self.accounts.append(account)
                return account

            def pay_interest(self):
                for a in self.accounts:
                    a.deposit(a.balance * a.interest)
        ```
        组合架构中，类作为一级值传入 `kind` 参数动态物化；分发利息时直接利用多态分派，自动依各账户的真实属性链路结算利息。

## 对象自省、运算符重载与递归数据结构

### 字符串规范双轨制与多态分派

* **字符串表示双轨体系**

    * > **定义**：Python 原生区分面向解释器的内部表达式与面向人类的可读文本表示。

    * **规范表示 `repr(x)`**：面向 Python 解释器。输出理想情况下应满足 $\text{eval}(\text{repr}(x)) == x$。交互式终端 REPL 回显默认使用 `repr`；对无法还原的内部对象输出 `<...>` 代理形式。
    * **友好表示 `str(x)`**：面向人类阅读。`print(x)` 与字符串格式化默认调用 `str`；若类中未实现 `__str__`，系统底层自动回退调用 `__repr__`。
    * **插值求值规则**：格式化字面量 `f'{x}'` 默认调用对象的 `str`；需显示规范格式时必须手动书写 `f'{repr(x)}'`；插槽表达式严格遵循从左到右求值顺序。
    * **安全自省查找协议**：内置函数 `repr(x)` 的核心实现机理为：
      $$\text{repr}(x) \equiv \text{type}(x).\_\_\text{repr}\_\_(x)$$
      解释器**直接绕过实例字典**，强制从对象的类型对象中检索 `__repr__` 函数并将实例显式作为首参数传入，防止实例属性遮蔽底层协议。

### 特殊方法与跨类型算术协作

* **特殊方法（Dunder Methods）与运算符映射**

    * > **定义**：以双下划线开头和结尾的预留名称，用于绑定 Python 内置运算符及内部协议。

    | 运算表达式 | 底层触发机制 | 对应角色 |
    | :--- | :--- | :--- |
    | `a + b` | `type(a).__add__(a, b)` | 主动左加法重载 |
    | `a + b`（左侧返回 `NotImplemented`） | `type(b).__radd__(b, a)` | 协同反向右加法重载 |
    | `bool(obj)` | `type(obj).__bool__(obj)` | 对象的真值上下文裁定 |
    | `float(obj)` | `type(obj).__float__(obj)` | 显式强制浮点转换 |

* **跨类型交互架构设计**

    * **类型分派（Type Dispatching）**：在重载逻辑内部动态判断操作数具体类型并引导至对应运算路径。
    * **类型强制转换（Type Coercion）**：当遇到不兼容类型时（如分数加浮点数），主动将自身转化为通用公共类型（如利用 `__float__` 降级为浮点数加法）。
    * **加法对称性维持**：针对满足交换律的算术系统，在类级别显式绑定 `Ratio.__radd__ = Ratio.__add__`，左操作数为基础类型时自动由右侧类接管执行。

### 链表递归抽象与就地变异算法

* **链表（Linked List，Link）**

    * > **定义**：要么为空（`Link.empty`），要么包含序列首元素 `first` 与指向后继链表的指针 `rest` 的递归组合数据结构。

    * **类结构建模**：
        ```python
        class Link:
            empty = ()
            def __init__(self, first, rest=empty):
                assert rest is Link.empty or isinstance(rest, Link)
                self.first = first
                self.rest = rest
        ```
    * **无副作用函数式流水线**：
        ```python
        def range_link(start, end):
            if start >= end: return Link.empty
            return Link(start, range_link(start + 1, end))

        def map_link(f, s):
            if s is Link.empty: return Link.empty
            return Link(f(s.first), map_link(f, s.rest))

        def filter_link(f, s):
            if s is Link.empty: return Link.empty
            rest = filter_link(f, s.rest)
            return Link(s.first, rest) if f(s.first) else rest
        ```

* **环形链表与变异算法**

    * **环形指针变异拓扑分析**：
        ```python
        s = Link(1, Link(2, Link(3)))
        s.first = 5
        t = s.rest
        t.rest = s
        ```
        指针变异导致节点 2 的 `rest` 重新回指节点 5，形成 $[5 \leftrightarrow 2]$ 双节点死循环。访问链条步进具有以 2 为模的周期律：偶数步回溯至节点 5，奇数步推进至节点 2。表达式 `s.rest.rest.rest.rest.first` 经过 4 次步进，求值精确命中数字 `5`。

    ```text
    变异后的环形链表拓扑：
         s.first = 5
          +---+---+
    s ->  | 5 | * |
          +---+-|-+
            ^   |
            |   v
          +---+-|-+
    t ->  | 2 | * |
          +---+---+
         t.first = 2
    ```

    * **严格递增链表有序插入（值置换法）**：
        ```python
        def add(s, v):
            """向严格升序链表 s 中就地插入值 v 并保持去重排序"""
            assert s is not Link.empty
            if s.first > v:
                s.first, s.rest = v, Link(s.first, s.rest)
            elif s.first < v and s.rest is Link.empty:
                s.rest = Link(v)
            elif s.first < v:
                add(s.rest, v)
            return s
        ```
        当插入值小于表头时，单向链表无法逆向修改外部指针对当前节点的引用，此时采用**原位数值置换法**：将老数据的 `first` 与 `rest` 打包推进新分配的后继节点，当前节点的 `first` 原地更新为新值 $v$，实现在返回值引用不变前提下的链表头就地扩充。

### 树对象的层次建模与外科手术式修剪

* **面向对象树（Tree）建模**

    * 树由标量属性 `self.label` 与装载子树实例的列表 `self.branches` 构成。构造方法内显式调用 `self.branches = list(branches)` 创建浅拷贝，隔离外部列表变异风险。
    * **测度度量函数**：
        * 叶子标签提取：若 `t.is_leaf()` 返回 `[t.label]`，否则遍历分支执行 `extend(leaves(b))` 归并。
        * 树的高度计算：
          $$\text{height}(t) = \begin{cases} 0 & \text{若 } t.\text{is\_leaf}() \\ 1 + \max_{b \in t.\text{branches}} \text{height}(b) & \text{否则} \end{cases}$$

* **树的就地修剪（Pruning）**

    * > **机理**：自顶向下优先在父级阻断连接，避免针对将被废弃的整个子树执行无意义深度遍历。

    * **外科手术式修剪实现**：
        ```python
        def prune(t, n):
            """就地删除树 t 中所有根标签等于 n 的子树拓扑"""
            t.branches = [b for b in t.branches if b.label != n]
            for b in t.branches:
                prune(b, n)
        ```
        步骤一使用列表推导式直接替换当前节点的 `branches` 属性，从指针引用层面瞬间切断并连根拔除根标签命中 $n$ 的直接分支；步骤二递归下沉至幸存下来的分支，对残存更深层的子拓扑执行同等过滤规则。修剪完全基于就地变异，无需显式返回任何对象。
