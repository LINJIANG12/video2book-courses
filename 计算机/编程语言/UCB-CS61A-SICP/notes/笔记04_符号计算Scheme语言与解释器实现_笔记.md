# 符号计算、Scheme语言与解释器实现

## Scheme 语言核心机制与数据抽象

### 表达式与前缀求值模型

* **原始表达式（Primitive Expression）**

    * > **定义**：不可再拆分的语言基础构成单元，包含自我求值字面量与内置过程名称。

    * 数值（如 `2`、`3.3`）与布尔值（`true`、`false` 或 `#t`、`#f`）为自我求值对象，求值结果为其自身。
    * 内置过程符号（如 `+`、`-`、`*`、`/`、`quotient`）在全局环境中绑定到具体的底层操作实现。
    * 无参数单位元规则：加法运算 `(+)` 求值为单位元 `0`；乘法运算 `(*)` 求值为单位元 `1`。
    * 谓词命名惯例：返回布尔值的过程名称通常以问号 `?` 结尾（如 `number?`、`zero?`、`integer?`），问号属于合法标识符字符，非独立语法操作符。

* **组合表达式（Combination）**

    * > **定义**：由圆括号包裹、空格分隔的一组子表达式，采用前缀表示法组织代码。

    * 语法结构为 `(<operator> <operand_1> <operand_2> ... <operand_n>)`，首个子表达式为运算符，后续子表达式为操作数。
    * 标准调用求值规则：自左向右递归求值运算符与所有操作数子表达式，随后将运算符解析出的过程应用于操作数求值结果列表。
    * 语法树不受缩进与换行限制，空格与换行仅起词法标记分隔作用。

### 特殊形式与环境绑定

* **特殊形式（Special Form）**

    * > **定义**：语法表现为括号组合式，但首元素为保留关键字且具备专属求值规约、不遵循标准子表达式预计算规则的表达式。

    * 条件分支 `if`：格式为 `(if <predicate> <consequent> <alternative>)`。首先求值谓词 `<predicate>`，若为真则仅求值并返回 `<consequent>`，若为假则仅求值并返回 `<alternative>`；未选中分支绝不执行。
    * 短路逻辑 `and` 与 `or`：`(and e1 ... en)` 从左至右求值，遇假值立即截断并返回假；`(or e1 ... en)` 遇真值立即截断并返回该真值。
    * 顺序求值 `begin`：按书写顺序依次求值所有子表达式，将最后一个子表达式的计算结果作为整个 `begin` 块的返回值。
    * 多路分支 `cond`：自上而下匹配子句 `(<test> <expr> ...)`，一旦 `<test>` 求值为真即执行该分支表达式并返回结果，跳过后续所有子句；可选 `else` 子句充当兜底默认分支。
    * 局部绑定 `let`：格式为 `(let ((<symbol> <expr>) ...) <body>)`，创建仅在 `<body>` 作用域内有效的局部环境绑定，执行完毕后局部符号注销。

* **绑定与过程抽象（define / lambda）**

    * > **定义**：`define` 用于向当前环境引入符号绑定；`lambda` 用于构造匿名第一类过程对象。

    * 变量定义：`(define <name> <expr>)` 先求值 `<expr>`，再将符号 `<name>` 绑定到所得值并注入当前环境帧。
    * 过程定义语法糖：`(define (<name> <formals>) <body>)` 严格等价于 `(define <name> (lambda (<formals>) <body>))`。
    * 匿名过程：`(lambda (<formals>) <body>)` 创建过程实体，捕获定义时所处的词法环境，调用时以传入实参绑定形参。

### 单向链表与盒式指针模型

* **对与链表（Pair and List）**

    * > **定义**：Scheme 列表底层均为严格由双槽节点通过指针链接构成的单向链表。

    * 节点构造原语 `cons`：分配包含两个指针域的内存单元，分别存放头部元素指针与尾部后继指针。
    * 解构原语 `car` 与 `cdr`：`(car p)` 获取节点左半格元素（当前值）；`(cdr p)` 获取节点右半格后继指针（剩余链表）。
    * 空列表标识：`nil` 或 `'()`，用于标识单链表终端。
    * 嵌套 `cons` 等价性：`(cons 1 (cons 2 nil))` 等价于 `(list 1 2)`。

    ```text
    s = (cons 1 (cons 2 nil))
    s ---> [ . | . ] ---> [ . | / ]
             |              |
             v              v
             1              2
    ```

    * 共享结构机制：若多个链表节点的 `cdr` 或 `car` 指向同一内存单元，终端输出呈现为独立括号序列，但底层保持指针重叠。

    * > **易错点**：⚠️ 终端输出时解释器会自动将单向链表扁平化显示为括号列表 `(1 2)`，隐蔽了分散分配的物理节点特征；`(cdr s)` 得到的是合法链表 `(2)`，而非裸原子 `2`。

### 符号计算与高阶列表规约

* **引用机制（Quote）**

    * > **定义**：阻断解释器对后续表达式求值、将其直接作为字面量数据返回的特殊形式。

    * 语法糖简写：单引号 `'<expr>` 是前缀修饰符，词法解析阶段双向展开为 `(quote <expr>)`。
    * 作用域穿透：引用施加于复合表达式时，递归阻断其内部所有子表达式的求值，保留原始符号与列表结构。
    * 同像性（Homoiconicity）：代码语法结构与内建链表数据结构完全同构，代码能够以列表形式被程序读取、遍历与重构。

* **高阶规约过程（Higher-Order List Procedures）**

    * > **定义**：以过程作为参数或返回值的列表批处理原语。

    * `append`：接收多个列表，将其内部元素按序浅拷贝摊平链接为单个单一列表；区别于 `cons` 将第一个参数整体嵌入表头。
    * `map`：接收单参数过程 $f$ 与列表 $s$，对 $s$ 中每个元素依次独立应用 $f$，汇聚所有返回值构建同构新列表。
    * `filter`：接收判定谓词与列表，剔除求值结果为假值的元素，保留满足条件的元素构建子列表。
    * `apply`：将解包后的列表元素一次性作为实参包传递给目标过程，仅触发单次调用，规约运算形式为 `(apply + '(1 2 3 4))` $\equiv$ `(+ 1 2 3 4)`。

* **偶数和非空子集算法（even-subsets）**

    * 分治数学模型：对于列表首元素 `(car s)`，非空子集分为“不含首元素”、“包含首元素并与后续子集拼接”、“首元素自成单子集”三类。
    * 状态转移逻辑：
        * 若首元素为偶数，拼接后续偶数和子集；单元素自成合法子集。
        * 若首元素为奇数，拼接后续奇数和子集；单元素不能构成偶数和子集。
    * 管道化规约实现：先通过分治递归生成幂集非空子集列表，再利用高阶过程组合校验：

    ```scheme
    (define (nonempty-subsets s)
      (if (null? s)
          nil
          (let ((first (car s))
                (rest (nonempty-subsets (cdr s))))
            (append rest
                    (map (lambda (t) (cons first t)) rest)
                    (list (list first))))))

    (define (even-subsets s)
      (filter (lambda (subset) (even? (apply + subset)))
              (nonempty-subsets s)))
    ```

## 程序解析与计算器求值流水线

### 异常拦截与控制流解耦

* **异常机制（Exception Handling）**

    * > **定义**：向运行环境抛出运行时非预期事件并由上层调用栈定向拦截恢复的非局部控制流设施。

    * 异常触发：使用 `raise <expression>` 语句主动抛出实例，该表达式必须求值为 `BaseException` 的子类或其实例。
    * 常用内建类型：`TypeError`（类型不匹配）、`NameError`（未绑定标识符）、`KeyError`（键缺失）、`RecursionError`（调用栈越界）、`ZeroDivisionError`（除数为零）。
    * 拦截结构：

    ```python
    try:
        <try suite>
    except <ExceptionType> as <name>:
        <except suite>
    ```

    * 关注点分离（Separation of Concerns）：通用算法骨架（如折叠函数 `reduce`）内不编写任何具体业务容错逻辑；调用方组合业务操作时独立包裹 `try...except`，实现遍历机制与异常修复的解耦。

### 语言层次与同像性内部表示

* **语言层次与执行范式**

    * > **定义**：计算机硬件仅能识别固定拓扑电路硬编码的机器语言；高级语言通过编译、解释或二者混合机制映射到底层执行。

    * 编译（Compilation）：全量将源文本转换为目标机器代码或底层二进制指令文件后交付执行。
    * 解释（Interpretation）：直接读取源文本，边解析语义边实时驱动运行时状态机执行。
    * 混合架构：CPython 将 Python 源代码预编译为规整的 Python 3 字节码（Bytecode），由 Python 虚拟机（PVM）逐条解释运行。
    * 领域专用语言（DSL）：面向特定受限逻辑域定制的语言系统，如 Erlang（并发通信与容错调度）、MediaWiki（超链接模板排版）。

* **Pair 与 nil 宿主语言建模**

    * Python 内部使用面向对象结构模拟 Scheme 表达式同像性：

    ```python
    class Pair:
        def __init__(self, first, rest):
            self.first = first
            self.rest = rest

        def __repr__(self):
            return f"Pair({repr(self.first)}, {repr(self.rest)})"

        def __str__(self):
            s = "(" + str(self.first)
            second = self.rest
            while isinstance(second, Pair):
                s += " " + str(second.first)
                second = second.rest
            if second is not nil:
                s += " . " + str(second)
            return s + ")"

    class nil:
        def __repr__(self):
            return "nil"
        def __str__(self):
            return "()"

    nil = nil()
    ```

### 语法解析流水线

* **词法分析（Lexical Analysis / Tokenization）**

    * > **定义**：顺序扫描原始字符流，剔除多余空白符与注释，聚类输出合法原子标记（Token）序列的过程。

    * 状态识别：具备有限字符前瞻能力，能将连续字符 `2` 和 `3` 聚类为单一整数标记 `23`；将带小数点的字符流解析为单一浮点数；遇到紧邻括号 `))` 拆解为两个定界标记。

* **语法分析（Syntactic Analysis）**

    * > **定义**：消费由词法分析器产生的扁平标记流，依据形式文法递归构建层次化表达式树（Pair 链表）。

    * 树递归构建规则（`scheme_read`）：
        * 遇到原子标记（数字或符号）：直接返回基本对象（递归基）。
        * 遇到左括号 `(`：启动递归解析，依次消费后续标记并构造嵌套 `Pair` 链表，直至消费匹配的右括号 `)`。
        * 遇到失配孤立右括号或未闭合左括号：抛出 `SyntaxError`。

    ```text
    原始文本: "(+ 23 (* 4 5.6))"
             │
             ▼ 【词法分析 (tokenize)】
    标记列表: ['(', '+', 23, '(', '*', 4, 5.6, ')', ')']
             │
             ▼ 【语法分析 (scheme_read)】
    表达式树: Pair('+', Pair(23, Pair(Pair('*', Pair(4, Pair(5.6, nil))), nil)))
    ```

### 计算器解释器与集中式容错

* **计算器语言（Calculator）语义规则**

    * 语法树节点类型：纯数字基本表达式直接求值返回；以 `Pair` 组织的调用表达式由运算符和操作数组成。
    * 算术操作规约：
        * 加法 `+`：计算所有参数和，无参数返回 `0`。
        * 乘法 `*`：计算所有参数乘积，无参数返回 `1`。
        * 减法 `-`：必须至少 1 个参数；单参数执行取相反数；多参数用首参数依次减去后续参数。
        * 除法 `/`：必须至少 1 个参数；单参数执行取倒数；多参数用首参数依次除以后续参数；除数为 0 抛出 `ZeroDivisionError`。

* **求值与应用分派器（calc_eval / calc_apply）**

    * `calc_eval` 调度流程：遇到基本数字调用 `simplify` 规约后返回；遇到 `Pair` 递归调用 `calc_eval` 处理 `rest` 中每个操作数子表达式，将运算符与纯数值实参列表传递给 `calc_apply`。
    * `calc_apply` 规约实现：根据符号分发至底层 Python `sum` 或 `reduce` 算子；遇到非法符号抛出 `TypeError`。

* **读取-求值-打印循环（REPL）**

    * > **定义**：周而复始运行提示输入（Prompt）、文本读取（Read）、语法解析（Parse）、树形求值（Eval）、结果输出（Print）的交互式生命周期。

    * 集中式容错模型：在 REPL 外层单一 `try...except` 结构中集中拦截 `(SyntaxError, ValueError, TypeError, ZeroDivisionError)`，输出错误诊断信息并重置提示符，阻止进程异常退出；捕获 `(KeyboardInterrupt, EOFError)` 时正常退出循环。

## 环境模型与通用解释器架构

### Eval-Apply 双核相互递归

* **双核分发机制**

    * > **定义**：由树形分派器 `scheme_eval` 与过程应用器 `scheme_apply` 构成相互递归调用的解释执行闭环。

    ```text
    scheme_eval(expr, env)
       │
       ├─► 自求值对象 (数字, 布尔, nil) ──► 返回自身
       ├─► 符号 (Symbol) ──────────────► env.lookup(symbol)
       ├─► 特殊形式 (if, quote, ...) ──► 专属规约求值分支
       └─► 过程调用表达式 (Combination)
             │
             ├─ 递归调用 scheme_eval 求值操作符与所有操作数
             └─ 将求得的过程与实参包交由 scheme_apply(proc, args)
                   │
                   ├─ 内置基元过程: 直接调用宿主执行逻辑返回
                   └─ 用户定义过程 (LambdaProcedure):
                         │
                         ├─ 1. 开辟新帧 (Parent = proc.env)
                         ├─ 2. 绑定形参与实参
                         └─ 3. 递归反冲: 调用 scheme_eval 求值过程体
    ```

### 帧链结构与作用域查找

* **环境与帧（Environment and Frame）**

    * > **定义**：环境是表示作用域链的单向链表，由一系列按从内向外顺序链接的活动帧（Frame）组成。

    * 帧属性结构：每个 `Frame` 实例维护一个本地符号绑定字典（Bindings），以及一个指向外层父帧（Parent Frame）的指针。
    * 绑定定义 `define(name, value)`：始终且仅在当前活动帧的字典中建立或更新映射关系，绝不污染父帧。
    * 变量查找 `lookup(name)`：首先检索当前帧字典，若命中立即返回；若缺失则顺着父指针递归检索父帧；直至上溯至全局帧依然缺失时，抛出 `unknown identifier` 运行时错误。
    * 变量遮蔽（Shadowing）：内层帧中与外层帧重名的符号绑定会直接阻断向上检索，使外层同名变量在当前环境内被屏蔽。

### 用户定义过程与闭包

* **过程对象结构（LambdaProcedure）**

    * 内部元组属性：
        1. `formals`：形参符号列表。
        2. `body`：未经求值的过程体表达式列表。
        3. `env`：闭包环境指针，**严格固化该过程被创建时解释器所处的环境起始帧**。

* **用户过程应用三步铁律**

    * 第一步（创建帧）：实例化全新 `Frame`，将其父指针显式指向 `LambdaProcedure.env`。
    * 第二步（绑定参数）：按位置次序将形参符号与实参值一一配对，存入新帧的局部绑定字典。
    * 第三步（求值主体）：将新创建的帧作为当前环境，调用 `scheme_eval` 求值过程主体表达式。

### 作用域规则

* **词法作用域与动态作用域判定**

| 作用域机制 | 新帧父指针的决定因子 | 确定时机 | 游离变量解析依赖 | 代表语言 |
| :--- | :--- | :--- | :--- | :--- |
| **词法作用域（Lexical Scope）** | 过程**定义时**所处的词法环境 | 编写代码时静态确定 | 定义点上层的包含块 | Python, Scheme, 现代通用语言 |
| **动态作用域（Dynamic Scope）** | 过程**被调用时**所处的执行环境 | 程序运行时动态决定 | 调用栈当下的最近调用者帧 | 早期 Lisp, 部分 Shell 脚本 |

* **解析行为对照案例**

    ```scheme
    (define (f x) (+ x y))
    (define (g x y) (f (+ x x)))
    (g 3 7)
    ```

    * 词法作用域解析：执行 `(g 3 7)` 开辟帧 $F_1$（$x=3, y=7$，父帧为全局帧 $G$）；计算实参调用 `f` 开辟帧 $F_2$（$x=6$）。依据词法规则，$F_2$ 的父指针指向 `f` 的定义环境全局帧 $G$。$F_2$ 中查找 $y$，在 $F_2$ 与 $G$ 中均未找到，抛出 `Unknown identifier: y`。
    * 动态作用域解析：$F_2$ 的父指针直接挂接在调用点所在帧 $F_1$ 上。$F_2$ 查找 $y$ 缺失后回溯至 $F_1$，命中 $y=7$，求值结果返回 $6 + 7 = 13$。

* **Lisp 1.5 极简公理体系**

    * 核心操作原语：`car`、`cdr`、`cons`、`atom`（原子类型判断）、`eq`（相等判断）。
    * 核心特殊形式：`quote`（代码降维数据）、`cond`（分支控制）。
    * 抽象构造机制：`lambda`。

## 尾调用优化与程序即数据

### 函数式规范与尾递归救赎

* **纯函数式编程核心约束**

    * 纯函数无外部副作用，禁止变量重新赋值（No Reassignment），禁止可变数据类型（No Mutable Data Types）。
    * 引用透明性（Referential Transparency）：任何表达式均可用其对应的求值结果直接替代，不改变程序系统外部行为。

* **尾调用与正确尾递归**

    * > **定义**：如果一个过程调用另一个过程后，调用方除了直接将该调用的返回值作为自身结果返回之外，无需再进行任何附加计算，该调用即为**尾调用（Tail Call）**。

    * 正确尾递归（Proper Tail-Recursion）规范：Scheme 规范强制要求解释器必须在常数调用栈空间 $O(1)$ 内执行尾递归过程。
    * 淘汰中间人机理：执行尾调用时，当前帧历史局部变量已完全失效，解释器直接丢弃或复用当前活动帧，抑制调用栈帧线性堆积。

### 尾上下文判定法则

* **尾上下文（Tail Context）推导规则**

    * 规则 1（函数体）：`lambda`（或过程定义）主体表达式序列中的**最后一个子表达式**处于尾上下文。
    * 规则 2（条件分支）：若外层 `if` 整体处于尾上下文，其结果项（Consequent）和替代项（Alternative）表达式均处于尾上下文。
    * 规则 3（多路分支）：若外层 `cond` 处于尾上下文，所有匹配子句的最后一个子表达式均处于尾上下文。
    * 规则 4（逻辑短路）：若 `and` 或 `or` 处于尾上下文，其最后一个操作数处于尾上下文。
    * 规则 5（复合块）：若 `begin` 处于尾上下文，其内部最后一个子表达式处于尾上下文。

    * > **易错点**：⚠️ `if` 的谓词子表达式 `<predicate>`、加法等调用中的操作数子表达式永远**不处于**尾上下文。即便该操作数内包含调用，调用返回后解释器仍需执行分支决策或外层运算，属于非尾调用。

* **空间消耗实测差异**

    * Python 栈限制：宿主 Python 调用栈深度上限约 1000 帧。未实现尾优化的递归阶乘在递归深度约 673 时因栈空间耗尽抛出 `RecursionError`。
    * Scheme 尾调用消除：引入蹦床机制或迭代求值循环后，尾调用的过程在当前帧原地展开，深度达 10000 仍平稳运行，空间复杂度锁定为 $O(1)$。

### 递归程序常数空间重构

* **经典过程结构尾递归判定分析**

    * 列表求长 `length`：
        * 非尾递归版本：分支返回 `(+ 1 (length (cdr s)))`，加法操作处于尾上下文，但递归调用 `length` 位于操作数位置，返回后需加 1，空间复杂度 $O(n)$。
        * 尾递归重构：引入辅助累加器，替代分支改写为尾调用 `(length-iter (cdr s) (+ n 1))`，空间复杂度 $O(1)$。
    * 包含判定 `contains`：
        * 递归调用 `(contains (cdr s) v)` 处于内层 `if` 替代分支的尾上下文中，直接返回结果，属于严格尾递归。
    * 重复元素判定 `has-repeat`：
        * 主递归调用 `(has-repeat (cdr s))` 处于替代分支尾上下文。
        * 谓词调用 `(contains (cdr s) (car s))` 虽非尾调用，但由于被调用的 `contains` 自身为 $O(1)$ 空间尾递归过程，调用完毕立即回收栈帧，因此 `has-repeat` 整体保持在 $O(1)$ 辅助调用栈深度。
    * 斐波那契数计算 `fib-iter`：
        * 尾部虽然调用 `fib-iter`，但实参表达式包含 `(fib (- k 1))`，在参数求值阶段触发非尾递归树展开，破坏常数空间保证。
    * 序列规约 `reduce` 与映射 `map`：
        * `reduce`：对自身的递归调用处于尾上下文，其是否在常数空间运行取决于实参高阶过程 `procedure` 自身的空间占用。
        * `map`：常规写法因外层挂接 `cons` 节点分配导致非尾调用。常数空间重构方案采用两阶段处理：先通过反向累加器尾递归构建逆序链表，再通过尾递归过程将其完全反转。

### 代码即数据与准引用模板

* **通用计算机模型（Universal Computer）**

    * 解释器接收两组输入：描述机器拓扑的**源代码列表**与被模拟机器处理的**原始数据**。
    * 内部运行求值-应用循环（Eval-Apply Cycle），实现对任意专有目标计算逻辑的模拟。

* **准引用（Quasiquote）与取消引用（Unquote）**

    * 语法标记：反引号 `` ` `` 开启准引用代码模板；逗号 `,` 在模板内部取消引用，强制恢复求值。

| 表达式结构 | 求值结果 | 运行时机理 |
| :--- | :--- | :--- |
| `'(a b)` | `(a b)` | 纯引用，`b` 作为字面符号保留 |
| `'(a (+ b 1))` | `(a (+ b 1))` | 纯引用，内部复合子表达式完全不计算 |
| `` `(a ,(+ b 1)) ``（设 $b=4$） | `(a 5)` | 准引用中嵌入取消引用，`(+ b 1)` 强制求值为 5 填入 |

* **元编程循环合成案例（sum-while）**

    * 借助准引用模板，在原生缺乏循环语句的 Scheme 中动态生成尾递归迭代代码并送入 `eval` 求值：

    ```scheme
    (define (sum-while initial-x condition add-to-total update-x)
      `(begin
         (define (f x total)
           (if ,condition
               (f ,update-x (+ total ,add-to-total))
               total))
         (f ,initial-x 0)))
    ```

## 宏元编程与代码重写

### 宏的本质与二次求值

* **宏（Macro）**

    * > **定义**：在解释器评估之前运行的、以未求值的源代码表达式列表作为输入、生成全新目标代码列表供解释器进行二次求值的转换程序。

    * 宏定义特殊形式：`define-macro`。
    * 执行范式差异：
        * 普通过程：接收**值**，返回**值**。解释器调用前必须强制预先求值所有操作数。
        * 宏：接收**表达式树**，返回**表达式树**。操作数绝不进行预先求值。
    * 代码复刻失效案例（`twice`）：普通过程 `(define (twice expr) (list 'begin expr expr))` 在传入 `(print 2)` 时，操作数提前执行并仅将返回值传入，无法复制副作用；宏定义 `(define-macro (twice expr) (list 'begin expr expr))` 捕获未执行语法树 `'(print 2)`，展开为 `(begin (print 2) (print 2))`，二次求值时触发两次打印。

### 控制流扩展与上下文捕获

* **测试断言宏（check）**

    * 功能目标：条件成立返回 `'passed`；失败时捕获导致失败的**具体源码表达式树**，返回包含原始代码结构的失败日志。
    * 宏构造实现：

    ```scheme
    (define-macro (check expr)
      (list 'if expr ''passed (list 'quote (list 'failed expr))))
    ```

    * 展开语义：对于输入 `(check (> x 0))`（设 $x=-2$），在预处理阶段代码被展开为 `(if (> x 0) 'passed '(failed (> x 0)))`。二次求值使分支命中失败项，输出字面结构 `(failed (> x 0))`，保留源代码上下文。

* **循环控制流宏（for）**

    * 语法重构目标：在 Scheme 中扩展类似指令式循环的语法结构 `(for <sym> <vals> <expr>)`。
    * 语法树映射关系：把用户书写的结构映射重写为高阶函数 `map` 与 `lambda` 构成的闭包表达式。

    ```text
    程序员编写源码: (for   x    '(2 3 4 5)   (* x x))
                          │        │            │
                          ▼        ▼            ▼
    宏展开目标结构: (map (lambda  (x)        (* x x))  '(2 3 4 5))
    ```

    * 宏展开构造实现：

    ```scheme
    ;; 方式一：纯列表装配
    (define-macro (for sym vals expr)
      (list 'map 
            (list 'lambda (list sym) expr) 
            vals))

    ;; 方式二：准引用模板装配
    (define-macro (for sym vals expr)
      `(map (lambda (,sym) ,expr) ,vals))
    ```

    * > **易错点**：⚠️ 构造 `lambda` 形参时，`sym` 必须显式封装在单层列表结构中（`(list sym)` 或 `(,sym)`），不可直接裸置符号，否则违反过程形参表语法规范。

### 非侵入式表达式跟踪

* **动态追踪宏（trace）设计**

    * 机制诉求：在单次表达式执行期间启动对目标递归函数的拦截与调用栈打印，表达式计算完毕后立即将原函数完全还原，消除全局持久状态污染。
    * 控制流编排：通过 `begin` 复合块组织五阶段生命周期：
        1. 备份原过程：`(define original ,op)`
        2. 局部劫持函数符号：`(define ,op (lambda (n) (print (list ',op n)) (original n)))`
        3. 锁存实际调用返回值：`(define result ,expr)`
        4. 还原函数定义：`(define ,op original)`
        5. 产出最终结果：`result`

    ```scheme
    (define-macro (trace expr)
      (let ((op (car expr)))
        `(begin
           (define original ,op)
           (define ,op (lambda (n)
                         (print (list ',op n))
                         (original n)))
           (define result ,expr)
           (define ,op original)
           result)))
    ```

* **跟踪机制对比**

| 属性维度 | Python 装饰器（@trace） | Scheme 宏跟踪器（trace） |
| :--- | :--- | :--- |
| **追踪锚定对象** | **函数定义实体（Function Entity）** | **表达式求值调用（Expression Evaluation）** |
| **生效周期** | 静态、永久侵入式符号修改 | 动态、仅在被包裹表达式生命周期内生效 |
| **现场恢复机制** | 需人工显式编写逆向重新赋值逻辑 | 由宏生成的 `begin` 块在求值尾部自动清理还原 |
