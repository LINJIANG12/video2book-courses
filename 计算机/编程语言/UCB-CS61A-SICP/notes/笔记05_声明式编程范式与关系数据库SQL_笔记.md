# 声明式编程范式与关系数据库SQL

## 声明式编程范式与关系数据模型

* **声明式编程（Declarative Programming）**

    * > **定义**：一种仅向执行环境描述期望计算结果的特征与约束，而不指定具体算法执行步骤的编程范式。

    * 差异机理：命令式编程由程序员逐行编码计算过程与状态转移；声明式编程由解释器或执行引擎自行推导、评估并选择最优计算路径。
    * 运行特征：同一声明式查询语句在面对不同数据规模、分布或索引结构时，底层系统可能动态采用完全相异的物理执行算法。

* **数据库管理系统（Database Management System，DBMS）**

    * > **定义**：负责管理、维护、存储结构化数据并提供声明式查询路径优化与执行引擎的软件基础设施。

    * 核心交互语言为结构化查询语言（Structured Query Language，SQL）。
    * 各商业与开源供应商存在特定语法方言扩展，但核心关系代数语义在各大系统中保持一致。

* **关系表结构（Relation Table Structure）**

    * > **定义**：DBMS 中组织与持久化数据的二维网格数据结构，数学上定义为记录的无序集合。

    * **表（Table）**：记录的集合。
    * **行（Row）**：又称记录（Record），代表现实实体或事件的单个具体实例。
    * **列（Column）**：又称属性（Attribute），代表实体集中所有记录均具备的某种固定特征维度。
    * **列名（Column Name）**：属性维度的字符标识符，属于表结构元数据，非记录数据本身的组成部分。

    ```text
    +-------------+--------------+-----------------+  <-- 列名 (Column Names)
    |  latitude   |  longitude   |      name       |
    +-------------+--------------+-----------------+
    |     38      |     122      |    Berkeley     |  <-- 行 / 记录 (Row / Record)
    |     42      |      71      |    Cambridge    |
    |     45      |      93      |   Minneapolis   |
    +-------------+--------------+-----------------+
    ```

## 数据投影与单表表达式运算

* **查询投影（Projection）与字面值构造**

    * > **定义**：利用 `SELECT` 语句从零创建临时行数据，或从输入表中选取、转换特定列生成输出结果集的运算。

    * 列别名规则：在表达式后添加可选的 `AS 列名` 关键字指定输出列名称；多列描述以逗号分隔，语句以分号结尾。
    * 字面量界定：字面字符串必须使用单引号括起（如 `'Berkeley'`），无引号标识符直接解析为列名或系统关键字。
    * 联合建表（`UNION`）：使用 `UNION` 操作符串联多个单行 `SELECT` 生成多行临时表。
    * 结构一致性约束：`UNION` 两侧的子查询必须包含相同数量的列，且对应位置列的数据类型必须相互兼容。
    * 命名继承规则：`UNION` 产生的结果集列名完全由首个 `SELECT` 语句中的定义决定，后续子句无需重复指定 `AS` 列名。
    * 持久化语法：使用 `CREATE TABLE <表名> AS <SELECT查询>` 将查询得到的结果集固化为持久化存储表。

* **基础查询执行骨架**

    * > **定义**：单表数据提取、筛选、投影与排序的标准子句结构体系。

    * 语法构成：
      ```sql
      SELECT [列描述列表]
      FROM [输入表]
      WHERE [行过滤条件]
      ORDER BY [排序表达式];
      ```
    * 子句职能机制：
        * `FROM`：指定产生输入数据流的源表。
        * `WHERE`：对源表中每一行逐个评估布尔谓词表达式，计算结果非真的行直接丢弃。
        * `SELECT`：对通过过滤保留的行进行属性映射计算与列级投影。
        * `ORDER BY`：在最终生成输出结果前，指定整行记录的排序标量依据（默认升序）。
    * > **易错点**：⚠️ 关系表中出现内容完全相同的物理行属于合法行为。`SELECT` 的逐行过滤与投影机制决定了只要输入表中存在多条满足条件的独立行，输出表中就会产生等量的相同记录。

* **行内标量运算**

    * > **定义**：仅依赖当前单行记录内部的列属性值与常量，计算出派生属性的数学或逻辑表达式。

    * 隔离性规则：所有算术运算（`+`、`-`、`*`、`/`、`%`）及布尔比较（`=`、`!=`、`<>`、`>`、`<`）在执行时完全封闭于当前行空间，行间数据绝对隔离，不可直接跨行求和或对比。
    * 相等判定机制：SQL 查询语境中无变量赋值操作，单个等号 `=` 严格表示数值或字符串的相等性断言。
    * 字典序规则：对字符串类型执行 `>`、`<` 比较时，系统按字符编码的字典序（Alphabetical Order）逐位求值。

* **字符串处理与建模边界**

    * 拼接语法：SQL 标准中使用双竖线操作符 `||` 连接字符串（如 `'hello, ' || 'world'`），不支持加号 `+` 拼接。
    * 数据建模反模式（Anti-pattern）：严禁使用带分隔符的字符串在单个列字段内模拟序列或链表（如 `'2, 3, 4'`）。
    * 关系范式约束：一对多的集合从属关系必须拆分为子从表，每个独立元素作为子表中的一行存储，通过关联键与主表相连。

## 多表关系运算与连接

* **笛卡尔积（Cartesian Product）**

    * > **定义**：在无连接条件约束下，从第一张表中取出每一行与第二张表中的每一行进行全量排列组合所生成的宽表。

    * 计算基数：若表 $A$ 包含 $M$ 条记录，表 $B$ 包含 $N$ 条记录，逗号连接 `FROM A, B` 产生的中间虚表规模严格为 $M \times N$ 行。
    * 关联过滤：在 `WHERE` 子句中显式引入连接谓词（如 `WHERE A.key = B.key`），以笛卡尔积为底座裁撤无语义的无效配对行。

* **表别名（Alias）与自连接（Self-join）**

    * > **定义**：同一张表在 `FROM` 子句中被引用多次，并通过命名空间别名实现自身与自身的笛卡尔积运算。

    * 歧义消除：语法为 `FROM 表名 AS 别名`，后续列引用统一采用点表达式 `别名.列名`。
    * 自连接成对去重规则：在自连接查找同组关联实体对时，过滤条件采用严格不等式 `a.col < b.col`。
    * 严格不等式效用：
        1. 排除实体与自身配对（消除 `a.col = b.col`）。
        2. 强制指定输出对的字典序或数值序，消除镜像重复项（如保留 `(Barack, Clinton)`，自动剔除 `(Clinton, Barack)`）。

    ```text
    parents 表自连接求亲兄弟姐妹逻辑流：
    FROM parents AS a, parents AS b
    WHERE a.parent = b.parent AND a.child < b.child;
    
    [ a.parent == b.parent ]  --> 锁定共同父母
    [ a.child  <  b.child  ]  --> 消除自匹配及无序镜像配对
    ```

* **多表链式连接**

    * 串联扩展：`FROM` 子句后可并列三张或更多数据源表（包含物理表、视图或自连接副本）。
    * 约束闭包：多表串联必须提供足额的等值约束链（例如三表连接至少需要两组维度的键匹配），确保各维度实体信息在投影前语义对齐。

## 多行聚合与分组归约

* **聚合函数（Aggregation Function）**

    * > **定义**：以一组记录的指定属性值序列为输入，经过多对一数学归约，最终输出单一汇总标量值的函数。

    * 核心基础函数：
        * `max(col)`：求多行中该列的最大值。
        * `min(col)`：求多行中该列的最小值。
        * `sum(col)`：求多行中该列的数值累加和。
        * `avg(col)`：求多行中该列的算术平均值。
        * `count(col)` / `count(*)`：统计有效行数。
    * 执行管线：查询引擎先通过 `WHERE` 过滤原始行，再对保留下来的物理行流应用聚合计算。
    * 复合表达式聚合：参数内部支持复合算式（如 `max(legs - weight)`），引擎逐行完成行内标量计算后再行内外部极值规约。
    * 并列独立性：同个 `SELECT` 中并列的不同聚合函数（如 `max(a), min(b)`）分别独立计算，结果值之间不具备行级绑定约束。

* **行数统计与去重聚合（DISTINCT）**

    * `count(*)`：无差别统计通过过滤的全部物理行总数。
    * `count(col)`：仅统计该列值不为 NULL 的有效行总数。
    * `DISTINCT` 修饰：置于聚合函数内部列名前方（如 `count(DISTINCT col)`、`sum(DISTINCT col)`），执行时先剔除该列的重复取值，仅保留唯一值集合参与归约计算。

* **混合聚合列陷阱**

    * > **易错点**：⚠️ 在无 `GROUP BY` 的聚合查询中，严禁在 `SELECT` 列表中混用聚合函数与非聚合普通列（如 `SELECT max(weight), kind FROM animals;`）。虽然 SQLite 等系统在求极值时可能顺带拉取对应行的普通列，但当存在多个相同极值或使用 `avg`/`sum` 时，普通列返回的值在业务上毫无逻辑关联，在多数严格关系型数据库中会直接报语法错误。

* **分组机制（GROUP BY）**

    * > **定义**：依据指定的列、多列组合或标量表达式的求值结果，将过滤后的数据行集切分为互不重叠的子分区，使聚合函数在各子分区内独立执行归约。

    ```text
    原始数据表 animals
    +---------+------+--------+
    | kind    | legs | weight |
    +---------+------+--------+
    | dog     | 4    | 20     |
    | cat     | 4    | 10     |
    | ferret  | 4    | 10     |
    | parrot  | 2    | 6      |
    | penguin | 2    | 10     |
    | t-rex   | 2    | 12000  |
    +---------+------+--------+
                 │
                 │ 按 legs 拆分 (GROUP BY legs)
                 ▼
    ┌─────────────────────────┐      ┌─────────────────────────┐
    │ legs = 4 组             │      │ legs = 2 组             │
    │ dog     (weight: 20)    │      │ parrot  (weight: 6)     │
    │ cat     (weight: 10)    │      │ penguin (weight: 10)    │
    │ ferret  (weight: 10)    │      │ t-rex   (weight: 12000) │
    └─────────────────────────┘      └─────────────────────────┘
                 │                                │
                 │ 独立聚合 (max(weight))           │ 独立聚合 (max(weight))
                 ▼                                ▼
           legs=4, max=20                   legs=2, max=12000
    ```

    * 分组输出行数：输出结果集的行数严格等于 `GROUP BY` 分组键的唯一取值总数。
    * 多列分组：`GROUP BY col1, col2` 按照多列属性的笛卡尔元组联合值划分细粒度分区。
    * 表达式分组：`GROUP BY` 后允许接任意算术运算（如 `GROUP BY weight / legs`），依照行内动态算式的结果等值聚合。

* **分组过滤差异（HAVING 与 WHERE）**

    | 比较维度 | WHERE 子句 | HAVING 子句 |
    | :--- | :--- | :--- |
    | **应用时机** | 分组之前执行 | 分组及组内聚合运算之后执行 |
    | **作用对象** | 输入表中的单条原始物理行 | 聚合完成后的整个分组单元 |
    | **聚合函数支持** | 严禁包含任何聚合函数 | 允许且通常必须包含聚合函数表达式 |
    | **过滤结果** | 剔除不符合行级条件的底层行 | 剔除不满足统计汇总指标的整组数据 |

## 表结构管理与数据变更

* **数据定义语言（Data Definition Language，DDL）**

    * 空表定义语法：
      ```sql
      CREATE TABLE IF NOT EXISTS 表名 (
          列名1 数据类型 列级约束,
          列名2 数据类型 列级约束
      );
      ```
    * `IF NOT EXISTS`：幂等控制标志，若数据库已存在该表则静默跳过创建流程。
    * 列级约束体系：
        * `UNIQUE`：强约束该列全局数值唯一性，写入重复值直接触发冲突异常。
        * `DEFAULT <默认值>`：缺省填充，插入新行时若未显式指定该列，引擎自动赋默认值。
    * 布尔数据表示惯例：SQLite 底层无独立布尔类型，惯例使用整型数值 `1` 代表真（True），整型数值 `0` 代表假（False）。
    * 表结构注销语法：`DROP TABLE [IF EXISTS] 表名;`。若未包含 `IF EXISTS` 条件且目标表不存在，DBMS 直接抛出运行时错误。

* **数据操作语言（Data Manipulation Language，DML）**

    * **行插入（`INSERT INTO`）**：
        * 全列插入：`INSERT INTO 表名 VALUES (val1, val2);`。
        * 部分列插入：`INSERT INTO 表名 (列名) VALUES (val1);`，未列出字段自动回退至 `DEFAULT` 定义或 NULL。
        * 批量查询注入：`INSERT INTO 表名 (列名) SELECT ...`，将子查询产生的数据流整批写入目标表。
    * **行更新（`UPDATE`）**：
        * 语法：`UPDATE 表名 SET 列名 = 新值表达式 WHERE 过滤条件;`。
        * 批量原地修正：对满足 `WHERE` 谓词约束的所有行，同步更新一个或多个指定字段的取值。
    * **行删除（`DELETE`）**：
        * 语法：`DELETE FROM 表名 WHERE 过滤条件;`。
        * 实体清理：依据布尔断言定位行并从物理存储中剔除。
    * > **易错点**：⚠️ 无条件的 `DELETE FROM 表名;` 与 `DROP TABLE 表名;` 存在本质差异。前者仅清空表内的所有行数据，保留表元数据、列定义与约束配置（形成合法空表）；后者将整张表的元定义及其文件数据自数据库字典中彻底抹除。

## 程序宿主交互与并发数据共享

* **Python 数据库连接与游标管理**

    * 原生驱动：Python 标准库内置 `sqlite3` 模块，无需三方依赖直接接管 SQLite 引擎。
    * 核心连接范式：
      ```python
      import sqlite3
      
      # 建立连接：若文件不存在则在磁盘自动创建
      db = sqlite3.connect("data.db")
      
      # 执行 DDL / DML 操作
      db.execute("CREATE TABLE IF NOT EXISTS nums (val);")
      db.execute("INSERT INTO nums VALUES (?);", (10,))
      
      # 显式提交事务
      db.commit()
      
      # 查询并拉取数据
      cursor = db.execute("SELECT * FROM nums;")
      rows = cursor.fetchall()  # 返回由各行元组构成的列表
      ```

* **事务控制与持久化机制**

    * `commit()` 提交约束：在对数据库执行了 `CREATE`、`INSERT`、`UPDATE`、`DELETE` 等状态写操作后，必须显式调用连接对象的 `commit()` 方法。
    * 易失性风险：若未显式调用 `commit()` 提交事务，数据变更仅滞留在进程的内存缓冲区内，Python 进程终结后物理磁盘文件状态不发生永久改变。

* **参数化查询与注入防范**

    * 占位符语法：动态拼装参数时，SQL 模板中必须使用统一占位符 `?`，变量通过第二个参数以元组形态注入（如 `db.execute("INSERT INTO t VALUES (?);", (val,))`）。
    * 安全边界：严禁使用 Python 语言级别的原生字符串格式化（如 `f-string` 或 `%`）拼接 SQL 命令。
    * 底层防护机理：驱动层占位符机制自动对传入参数实施类型转换与敏感字符转义，在词法分析阶段切断恶意构造代码转化为指令的路径，彻底阻断 SQL 注入（SQL Injection）漏洞。

* **多连接跨进程并发共享**

    * 独立生命周期性：DBMS 属于解耦于具体应用程序运行周期的中央持久化状态存储中心。
    * 状态共享机制：多个相互独立的控制台客户端、Python 进程或其它语言宿主环境可并发挂载同一个数据库文件。
    * 实时穿透特性：任一外部连接对表执行的写变更（经 `commit` 固化后），在其他并发连接的独立查询与分组聚合评估中立即可见，实现无进程通信阻隔的跨上下文数据协同操作。
