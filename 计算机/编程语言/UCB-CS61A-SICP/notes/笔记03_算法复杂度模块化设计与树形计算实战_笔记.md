# 算法复杂度、模块化设计与树形计算实战

## 计算复杂度与执行效率

### 树递归开销与调用追踪

* **函数调用计数装饰器（Call Counter Decorator，count）**

    * > **定义**：通过高阶函数为目标函数挂载闭包计数器，用于精确统计目标函数及其递归调用被实际触发的总次数。

    * 机理：定义外层计数变量或函数对象属性 `call_count = 0`，包装函数内部每次执行递增该计数器，随后返回底层函数计算结果。

    ```python
    def count(f):
        def counted(n):
            counted.call_count += 1
            return f(n)
        counted.call_count = 0
        return counted
    ```

    * 数值：对于未记忆化的斐波那契递归 `fib(n)`，计算 `fib(5)` 产生 15 次调用；计算 `fib(30)` 调用次数高达 269 万次（2.69 million 次）。
    * 边界：累计计数为持续叠加；若多次调用同一个包装函数，计数器将在上一次调用的基础上继续累加。

### 记忆化机制与状态缓存

* **记忆化（Memoization，memo）**

    * > **定义**：利用外部哈希表作为缓存层，以空间换取时间，记录已求值输入的映射结果，避免相同子问题的重复计算。

    * 机理：在闭包环境中维护字典 `cache`；调用拦截时检查输入是否命中缓存，未命中则触发底层求值并写入 `cache[n]`，命中则直接返回缓存值。

    ```python
    def memo(f):
        cache = {}
        def memoized(n):
            if n not in cache:
                cache[n] = f(n)
            return cache[n]
        return memoized
    ```

    * 规则：在求值 `fib(30)` 时，底层原始 `fib` 仅执行 31 次（对应参数 0 至 30 各执行一次），而顶层记忆化函数 `memoized` 累计调用 59 次。
    * 剪枝特征：在树展开过程中，右侧子树或重复分支（如 `fib(2)`、`fib(3)`）因命中缓存直接返回，整棵子树被跳过。
    * > **易错点**：⚠️ 记忆化必须严格作用于**纯函数（Pure Functions）**。若函数存在控制台输出、修改全局状态、随机数生成等副作用，记忆化会跳过底层重复调用，导致副作用丢失，破坏程序行为。

### 算法重构与快速幂计算

* **快速幂算法（Fast Exponentiation，exp_fast）**

    * > **定义**：利用偶数幂的可折半性质，将底数自乘与指数减半相结合的分治求幂算法。

    * 数学规则：
      $$b^n = (b^{n/2})^2 \quad (\text{当 } n \text{ 为偶数})$$
      $$b^n = b \cdot b^{n-1} \quad (\text{当 } n \text{ 为奇数})$$
    * 结构分类：尽管函数体包含偶数与奇数两个递归入口，但分支互斥，每次调用仅执行其一，属于**线性递归（Linear Recursion）**而非树递归。

    ```python
    def square(x):
        return x * x

    def exp_fast(b, n):
        if n == 0:
            return 1
        elif n % 2 == 0:
            return square(exp_fast(b, n // 2))
        else:
            return b * exp_fast(b, n - 1)
    ```

    * 性能表现：
        * 朴素乘方 `exp(b, n)` 耗时随 $n$ 呈现严格直线（计算 $2^{100}$ 约 100 微秒，$2^{400}$ 约 400 微秒），输入规模翻倍则耗时翻倍。
        * `exp_fast` 在输入规模每翻一番时，耗时仅增加固定常数（约 0.002 毫秒）；输入扩大 1000 倍（约连续翻倍 10 次）仅需增加约 10 个固定时间步长。
    * 基准测试规则：使用 `timeit` 模块进行时间测量时，由于系统调度与垃圾回收干扰，必须重复多次运行并**取所有耗时的中位数（Median）**。

### 渐近分析与常见增长阶梯队

* **渐近记号边界（Asymptotic Notations）**

    * > **定义**：用于脱离特定硬件架构、量化程序时间开销随输入规模扩展趋势的数学界限体系。

    * 大 $\Theta$（Tight Bound）：紧确界，同时确定渐近的上界与下界常数因子。
    * 大 $O$（Upper Bound）：渐近上界，仅描述运行时间的最坏上限。

| 增长阶 | 记号 | 规模变换递推方程 | 规模翻倍（$n \to 2n$）行为 | 典型场景 |
| :--- | :--- | :--- | :--- | :--- |
| **常数阶** | $\Theta(1)$ | $T(n) = c$ | 运行时间完全不变 | Python 字典按键查值（Dict Key Lookup） |
| **对数阶** | $\Theta(\log n)$ | $T(2n) = T(n) + c$ | 运行时间增加一个固定常数 $c$ | 快速幂算法 `exp_fast` |
| **线性阶** | $\Theta(n)$ | $T(n+1) = T(n) + c$ | 运行时间同步翻倍 | 单重 `for` 循环遍历、朴素乘方 `exp` |
| **二次阶** | $\Theta(n^2)$ | $T(n) \propto n^2$ | 运行时间增加为原来的 4 倍 | 两重循环嵌套、无序列表元素重叠检查 `overlap` |
| **指数阶** | $\Theta(b^n)$ | $T(n+1) \approx b \cdot T(n)$ | 运行时间随规模增加乘上几何因子 | 未记忆化的树递归 `fib` |

### 活动环境与调用栈空间分析

* **活动环境（Active Environments）**

    * > **定义**：在程序执行的某一时刻，必须常驻物理内存中、不可被解释器垃圾回收销毁的执行帧集合。

    * 存在条件：
        1. 正在被求值且尚未返回的函数调用所对应的环境帧；
        2. 任意活动环境内部所引用的函数对象的父环境（如闭包的词法作用域帧）。

* **最大并发帧分析（Maximum Concurrent Frames）**

    * 监测工具：通过 `count_frames` 记录当前打开帧 `open_count` 与历史峰值 `max_count`。

    ```python
    def count_frames(f):
        def counted(n):
            nonlocal open_count, max_count
            open_count += 1
            if open_count > max_count:
                max_count = open_count
            result = f(n)
            open_count -= 1
            return result
        counted.open_count = 0
        counted.max_count = 0
        open_count = 0
        max_count = 0
        return counted
    ```

    * 时空解耦法则：
        * **时间消耗**：取决于整棵计算树中**全部节点的总数量**（所有历史调用的总和）。
        * **空间消耗**：取决于整棵计算树中**从根到叶节点的最大深度**（同一时刻并存的最大活跃帧链）。
    * 数值验证：未记忆化计算 `fib(20)` 时，总调用次数达数万次（时间指数阶 $\Theta(b^n)$），但内存中同一时刻的活动帧峰值 `max_count` 恒等于 20（空间线性阶 $\Theta(n)$）。

## 模块化设计与解耦原则

### 关注点分离架构准则

* **关注点分离（Separation of Concerns，SoC）**

    * > **定义**：将软件划分为若干职责独立的模块，使得每个模块仅处理特定侧面业务逻辑的架构原则。

    * 判定标准：修改某一模块的规则（如计分胜负逻辑），不应导致其他协同模块（如策略、解说）产生任何代码改动。
    * 案例结构：
        * **Hog 掷骰游戏架构**：
            * 游戏模拟器（Simulator）：掌控投骰先后顺序、状态轮转、最终胜负判定。
            * 游戏评论功能（Commentary）：仅接收状态输入，维护历史解说文本，不干预流程。
            * 玩家策略功能（Strategy）：纯决策计算，仅根据当前分值返回掷骰数量。
        * **Ants 昆虫保卫战架构**：
            * 动作函数（Action Functions）：单兵作战行为逻辑（如投叶、蜇人），与外部轮次无关。
            * 地图通道结构（Map & Tunnels）：维护空间坐标与连接拓扑。
            * 模拟引擎（Engine）：统筹全局回合推进、食物消耗结算与基地存亡裁决。

### 性能瓶颈诊断与数据表征改造

* **无序查找导致的二次退化**

    * 机理：在餐厅推荐系统中，计算同时评论过餐厅 $r$ 与 $s$ 的用户重叠数。
    * 朴素低效实现：

    ```python
    def reviewed_both_slow(r, s):
        count = 0
        for u in r['reviewers']:
            if u in s['reviewers']:
                count += 1
        return count
    ```

    * > **易错点**：⚠️ 若 `s['reviewers']` 为普通无序列表，`u in s['reviewers']` 操作的时间复杂度为线性扫描 $O(U_s)$。外层循环遍历 $U_r$ 次，导致整体耗时退化为二次阶 $O(U_r \times U_s)$，面对数百评论的密集节点时产生秒级严重卡顿（如 "cafe" 查询耗时 1.7 秒）。

### 双指针有序序列交集算法

* **双指针求交算法（fast_overlap）**

    * > **定义**：利用输入列表严格递增且去重的先决条件，使用两个步进游标同步向前推进，在线性时间内完成交集大小统计。

    * 前提条件：两个输入列表 $s$ 和 $t$ 必须严格递增排序（Sorted）且不含重复元素。
    * 算法步进规则：
        1. 初始化游标 $i = 0, j = 0, \text{count} = 0$；
        2. 循环条件：$i < \text{len}(s) \land j < \text{len}(t)$，任一游标越界即终止；
        3. 若 $s[i] == t[j]$：命中共有项，$\text{count} \gets \text{count} + 1, i \gets i + 1, j \gets j + 1$；
        4. 若 $s[i] < t[j]$：说明 $s[i]$ 小于 $t$ 列表后续所有项，今后绝无可能匹配，$i \gets i + 1$；
        5. 若 $s[i] > t[j]$：说明 $t[j]$ 处于落后状态，$j \gets j + 1$。
    * 复杂度：每个元素最多访问一次，严格受控于 $O(\text{len}(s) + \text{len}(t))$。
    * 优化实测数据：
        * "cafe" 查询：从 1.7 秒降至 0.7 秒；
        * "Thai" 查询：从 0.7 秒降至 0.5 秒。

```python
def fast_overlap(s, t):
    i, j, count = 0, 0, 0
    while i < len(s) and j < len(t):
        if s[i] == t[j]:
            count += 1
            i += 1
            j += 1
        elif s[i] < t[j]:
            i += 1
        else:
            j += 1
    return count
```

## 复合数据变异与对象原型链

### 列表变异机制与框指针模型

* **追加、扩充与重新绑定**

    * `s.append(t)`：将对象 $t$ 作为一个完整的子元素实体存入 $s$ 末尾；$s$ 内部槽位引出的指针直接指向 $t$ 所指向的值对象。
    * > **易错点**：⚠️ 指针在底层永远指向**堆中的值对象**，绝不直接指向**变量名标签**。后续执行 `t = 0` 仅仅将标签 `t` 重定向，不改变已存储在列表 $s$ 内部的内存引用指针。
    * `s.extend(t)`：遍历集合 $t$，将其所有元素逐个解包并依次追加到 $s$ 的末尾。

* **加法拼接与切片共享**

    * 表达式 `a = s + [t]` 和 `b = a[1:]` 均会申请分配一个全新的外层列表容器对象。
    * 外层容器内部的元素引用指针，全盘继承操作数对应索引位置的对象引用。对共享深层对象的原地修改（如 `b[1][1] = 0`），将同步反映在 `t`、`a[2]` 与 `b[1]` 中。

* **切片赋值的原地变异**

    * 插入与替换：左侧切片 `s[0:0] = t` 在索引 0 处执行原地插入，后续元素自动右移。`s[0:1] = []` 或 `s[0:2] = []` 实施区间剪除。
    * 自引用拓扑：

    ```python
    t = [1, 2, 3]
    t[1:3] = [t]
    ```

    * 切片赋值直接将内部槽位链接至 $t$ 自身，生成无限递归嵌套结构 `[1, [...]]`；继续调用 `t.extend(t)` 产出 `[1, [...], 1, [...]]`。
    * 嵌套切片追加：
      对 `t = [[1, 2], [3, 4]]` 执行 `t[0].append(t[1:2])`，`t[1:2]` 生成包含子列表 `[3, 4]` 的新列表外壳 `[[3, 4]]`，追加后 `t` 呈现为 `[[1, 2, [[3, 4]]], [3, 4]]`。

### 原型继承链与属性覆盖规则

* **属性查找与赋值协议（Attribute Lookup vs Assignment）**

    * 查找顺序（Resolution Order）：
        1. 实例局部字典 `__dict__`；
        2. 实例化对象所属的当前类对象；
        3. 沿类的基类继承树链条自底向上回退。
    * 赋值规则：`<expression>.<name> = <value>` 永远直接且仅作用于点号左侧的运算实体本身，绝不静默穿透到所属类层级。

* **经典继承执行追踪**

```python
class Worker:
    greeting = 'Sir'
    def __init__(self):
        self.elf = Worker
    def work(self):
        return self.greeting + ', I work'
    def __repr__(self):
        return Bourgeoisie.greeting

class Bourgeoisie(Worker):
    greeting = 'Peon'
    def work(self):
        print(Worker.work(self))
        return 'I gather wealth'

jack = Worker()
john = Bourgeoisie()
jack.greeting = 'my man'
```

* 追踪表达式解析：
    * `Worker().work()` $\to$ `'Sir, I work'`。匿名实例无局部属性，回退至 `Worker.greeting = 'Sir'`。
    * `jack` $\to$ `'Peon'`。交互式求值触发 `jack.__repr__()`，该方法直接读取 `Bourgeoisie.greeting`，返回并带单引号呈现 `'Peon'`。
    * `jack.work()` $\to$ `'my man, I work'`。实例属性 `greeting = 'my man'` 拦截了类属性。
    * `john.work()`：执行方法内部 `print(Worker.work(self))`，其中 `self` 为 `john`；`john` 无实例属性，回退至所属类 `Bourgeoisie.greeting`（`'Peon'`），基类方法返回 `'Peon, I work'` 并被无引号打印；最后方法本身返回并带引号呈现 `'I gather wealth'`。
    * `john.elf.work(john)` $\to$ `'Peon, I work'`。`john.elf` 取得 `Worker` 类对象，以普通函数形式调用未绑定函数，传入 `john` 作为显式参数，属性查找命中 `Bourgeoisie.greeting`。

### 序列推导式高阶变换

* **最小绝对值元素的所有索引提取**

    * 逻辑：提取列表中绝对值等于全序列最小绝对值的所有位置索引。

    ```python
    [i for i in range(len(s)) if abs(s[i]) == min(map(abs, s))]
    # 函数式等价实现
    list(filter(lambda i: abs(s[i]) == min(map(abs, s)), range(len(s))))
    ```

* **相邻配对最大和**

    * 错位切片法：利用 `s[:-1]`（去尾）与 `s[1:]`（去头）通过 `zip` 并行压缩成二元对。

    ```python
    max([a + b for a, b in zip(s[:-1], s[1:])])
    # 索引安全截断遍历实现
    max([s[i] + s[i+1] for i in range(len(s) - 1)])
    ```

* **按个位数字归拢字典**

    * 逻辑：提取有效个位数字集合，避免无匹配项引入空键。

    ```python
    last = [x % 10 for x in s]
    {d: [x for x in s if x % 10 == d] for d in range(10) if d in last}
    ```

* **元素无孤立重复性验证**

    * 逻辑：检查序列中每一个元素的出现频次是否均严格大于 1。

    ```python
    min([s.count(x) for x in s]) > 1
    # 局部切片排除法等价实现
    all([s[i] in s[:i] + s[i+1:] for i in range(len(s))])
    ```

### 链表递归与指针重织

* **链表类规格（Link Class Specification）**

```python
class Link:
    empty = ()
    def __init__(self, first, rest=empty):
        assert rest is Link.empty or isinstance(rest, Link)
        self.first = first
        self.rest = rest
```

* **有序性检验（ordered）**

    * 终止基线：若 `s is Link.empty` 或 `s.rest is Link.empty`，恒为 `True`。
    * 递归步：比较当前节点与后继节点键值 `key(s.first) > key(s.rest.first)`，若失序立即短路返回 `False`，否则步进至 `ordered(s.rest, key)`。

* **非破坏性有序合并（merge）**

    * 规则：严禁破坏输入链表原有拓扑，每次比较提取较小者，并通过构造新 `Link` 节点连接递归剩余计算结果。

    ```python
    def merge(s, t):
        if s is Link.empty:
            return t
        elif t is Link.empty:
            return s
        elif s.first <= t.first:
            return Link(s.first, merge(s.rest, t))
        else:
            return Link(t.first, merge(s, t.rest))
    ```

* **原地变异有序合并（merge_in_place）**

    * 规则：严禁调用 `Link` 构造函数分配新内存；通过直接覆写当前胜出头节点的 `rest` 引用槽位，实现对旧节点的原地指针穿针引线。

    ```python
    def merge_in_place(s, t):
        if s is Link.empty:
            return t
        elif t is Link.empty:
            return s
        elif s.first <= t.first:
            s.rest = merge_in_place(s.rest, t)
            return s
        else:
            t.rest = merge_in_place(s, t.rest)
            return t
    ```

## 树形计算与状态流动算法实战

### 层次本质与双向数据流模型

* **树数据流向分类**

    * **自顶向下状态传递（Top-down Passing）**：将祖先链上的全局上下文信息（如路径极值、累积深度）作为参数向子树逐层下发。
    * **自底向上聚合回溯（Bottom-up Aggregation）**：子分支通过返回值向父节点汇聚局部信息（如子树规模、子树后代极值），在当前层组装决策。

### 系统化函数设计六步法

* **示例驱动设计工作流（Six-step Design Process）**

    * 第 1 步：**数据定义（Data Definition）**——明晰实体在运行时的具体数据结构表达方式。
    * 第 2 步：**文档与存根（Signature, Purpose Statement, Stub）**——定义域与值域规格化，编写目的陈述与带有明确命名形参的 `def` 头。
    * 第 3 步：**示例先行（Examples）**——编写代码前，人工构造极端及常规边界输入，手算推演精确预期结果。
    * 第 4 步：**骨架模板（Template）**——勾勒递归控制结构（分流条件、分支递归遍历轮廓）。
    * 第 5 步：**填补实现（Definition）**——结合手算用例逻辑，将变量与状态演化填入骨架。
    * 第 6 步：**全面测试（Tests）**——运行第三步中的测试集实施断言校验。

### 祖先约束与自顶向下状态传递

* **大于所有祖先的节点计数（bigs）**

    * 判定规则：节点值必须严格大于其所有祖先节点；根节点无祖先，该命题逻辑上**空真成立（Vacuously True）**，根节点恒算一个。
    * > **易错点**：⚠️ 严禁仅将当前节点与直接父节点进行局部比较。判定条件等价于：**当前节点的标签严格大于从根出发路径上累积的“最大祖先标签”**。

* **模式对比：自底向上返回值聚合 vs 可变状态累加**

    * 模式一实现（返回值聚合）：

    ```python
    def bigs(t):
        def f(a, x):
            count = 1 if a.label > x else 0
            new_x = a.label if a.label > x else x
            return count + sum([f(b, new_x) for b in a.branches])

        return f(t, t.label - 1)
    ```

    * 模式二实现（外部可变列表累加）：

    ```python
    def bigs_alt(t):
        n = [0]
        def f(a, x):
            if a.label > x:
                n[0] += 1
            for b in a.branches:
                f(b, max(x, a.label))

        f(t, t.label - 1)
        return n[0]
    ```

| 维度 | 模式一：递归返回值聚合 | 模式二：可变容器副作用累加 |
| :--- | :--- | :--- |
| **数据流向** | 自底向上：子节点统计量向父节点回溯汇集 | 自顶向下：纯遍历推进，就地覆写外部容器 |
| **函数职责** | `f` 为纯函数，显式返回子树内部统计结果 | `f` 依靠副作用（Side Effect），返回值无意义 |
| **汇总算子** | 列表推导式配合 `sum([...])` 求和 | `for` 循环遍历直接触发子调用 |
| **初始参数设计** | 传入 `t.label - 1` 确保根节点恒大于初始边界 | 传入 `t.label - 1` 确保根节点初次命中累加 |

### 后代极值汇总与双重职责递归

* **筛选小于所有后代的非叶节点（smalls）**

    * 判定约束：
        1. 节点必须是**非叶子节点**（`not t.is_leaf()`，叶节点直接排除出结果）；
        2. 节点的标签必须严格小于其**所有后代中的最小值**：`t.label < min_descendant`。
    * 辅助函数双重职责：
        * **返回值**：后序遍历计算并返回以当前节点为根的**整棵子树的最小值**（含根自身与所有后代），即 $\min(\text{label}, \text{min\_descendant})$；
        * **副作用**：若非叶节点判定成立，就地将当前树对象 `t` 追加至结果列表。

```python
def smalls(t):
    result = []

    def process(t):
        if t.is_leaf():
            return t.label
        
        min_descendant = min([process(b) for b in t.branches])
        if t.label < min_descendant:
            result.append(t)
            
        return min(t.label, min_descendant)

    process(t)
    return result
```

* 执行规约：通过单次后序遍历，整棵树的每个节点被访问且仅被访问一次，后代极值回传与目标节点过滤在同一递归展开链中同步完成。
