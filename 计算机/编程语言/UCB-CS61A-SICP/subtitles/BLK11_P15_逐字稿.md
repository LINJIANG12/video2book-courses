元组是序列，但它们是不可变的序列，这意味着它们无法被更改。在我继续之前，我要提一下，有些人称这些为元组，而有些人则称之为 tuples。虽然关于这个词的发音没有确立的惯例，但这俩个群体至少可以达成共识，即另一群体一定是错的。我会让你决定你想怎么发音这个词，但我会大多数时候说 tuple，尽管偶尔你可能会听到我说 tuple。

元组是序列值。`(3, 4, 5, 6)` 就是一个元组。看看我们是如何使用圆括号而不是方括号的。其实，为了创建一个元组字面量，你其实不需要那些括号。逗号分隔的任何东西都会被解释为一个元组。很多人总是在它们周围加上括号，只是为了清楚地表达发生了什么。

你可以创建一个空元组，可以在空括号上调用 `tuple`，也可以在列表或者任何序列上调用 `tuple`，它会返回一个与列表内容相同的元组。

那么，如果你想要一个只有一个元素的元组呢？其实是可以的，但语法实在是太糟糕了。在最后加个逗号，如果愿意，也可以用括号括起来。这和数字 2 不同，这是一个包含两个元素的元组，而这只是数字 2。

现在，你可以把元组加在一起，得到更大的元组。你可以用成员运算符判断一个元素是否在元组中。你也可以切片元组。

元组是不可变的值，这意味着可以把它们用作字典中的键。记住，不允许用列表作为字典的键，因为会出现不可散列类型的错误。现在，虽然你可以使用元组，但你不能在其中的某个位置使用一个包含列表的元组。这也会导致错误。

元组是不可变序列，而不可变值实际上有一些好处。其中一个好处是，它们在某种程度上受到突变的保护。如果我有一个 turtle，它是一个序列 `(1, 2, 3)`，然后我调用一个名为 `oops` 的函数，turtle 仍然会是 `(1, 2, 3)`，因为这个序列不能被改变。

数字也是不可变的值，字符串也是。唯一可变的值，也就是能改变的，是列表。所以如果我有这个列表 `turtle = [1, 2, 3]`，然后我调用 `oops`，就像我们之前看到的一样，在这一点上 turtle 里可能有任何东西。

现在，`oops` 不能影响 turtle 并不完全准确。它不能改变这个值，但在下一讲中，我们将看到一个函数可以改变 turtle 这个名字绑定的内容。所以，你有一些保护，但在语言中无法完全防止函数对你当前环境进行更改。

由于名称或对象的更改，表达式的值可能会改变。名称的更改我们已经看了很长时间。如果我有两次相同的表达式 $x + x$ 和 $x + x$，我们可能会得到不同的值，因为名字 $x$ 已经被用来表示其他东西。所以，如果我说 $x = 2$，那么这将是 4。但是如果我说 $x = 3$，那么 $x + x$ 就会是 6。所以，这些都是名字的变化，我们在整个课程中都见过它们。

对象的变异是不同的，但它也可以产生相同的效果，改变表达式的求值结果。所以如果 $x$ 以前是列表 `[1, 2]`，那么 $x + x$ 就会是 `[1, 2, 1, 2]`。但如果我在末尾添加 3，那么对于 $x + x$，我将得到 `[1, 2, 3, 1, 2, 3]`。所以，这是相同表达式可以有不同值的两种不同方式。

对于不可变对象，这个不适用。但这个总是适用。你总是可以改变事物的名称。如果不可变序列包含可变值作为元素，则可能仍然会发生变化。

假设我有一个包含列表的元组。那么我不能改变这个元组。这就是我所说的不变，但我可以在元组内更改列表，所以元组仍然包含相同的内容。其中的列表与以前不同，因为这个列表被更改为一个 4。你看，那就不一样了。

基因变异。我们来谈谈什么是相同，以及什么是改变的意义。

从前，我们从不修改对象。在那些时候，一个复合对象只是其各部分的总和。成为有理数不再仅仅是分子和分母的问题。但是，在变化的存在下，整体仅仅是部分之和的观点已经不再成立。

一个复合数据对象，比如列表，在其构成的元素之外还有一个身份。一个列表，即使我们改变了它的内容，它仍然可能是同一个列表。

所以，如果我把 `a` 绑定到 `[10]`，然后把 `b` 绑定到同一个列表 `a`，这里会发生什么？`a` 被计算为包含 10 的列表，然后 `b` 被绑定到那个列表。`a == b`。如果我在后面追加 20，仍然等于 `b`，因为 `a` 是 `[10, 20]`，而 `b` 也是 `[10, 20]`。`b` 和 `a` 虽然改变了其内容，但仍然绑定到同一个列表。

然而，我们也可能有俩个列表，它们碰巧有相同的内容，但在身份上是不同的。它们不一样。它们可能是相等的。如果我说 `a` 是列表 `[10]`，`b` 是另一个列表 `[10]`，那么 `a == b` 是真的。

到目前为止，没什么太大的区别，但如果我把 20 添加到 `b`，`a` 现在是 `[10]`，`b` 是 `[10, 20]`，这两者不再相等。它们以前是相等的。我们从未重新给 `a` 或 `b` 赋过任何值，所以没有 `a = ...` 或 `b = ...` 的语句。这只是它们碰巧在之前有相同的内容，所以它们是相等的，但它们从未相同过。当一个改变时，另一个没变。

你怎么知道两个东西是……

不相同的。有一种叫做身份运算符的东西，看起来像是这个词 `is`，而 `is` 的反义词叫做 `is not`。

所以如果这两个表达式都求值为相同的对象，那么一个表达式就是另一个表达式。相等就是真的，如果两个表达式的值相等。包含 10 的任何列表都等于包含 10 的其他列表，但它们可能是同一个列表，也可能不是。相同的对象始终是相等的值，但反之则不一定成立。

10 始终等于 10。如果 a 是 10，而 b 是包含 10 的列表，那么……和 b 是相等的，但它们不是同一个列表。当两个东西不相同时，对其中一个的更改不会影响另一个。但是 c 与 b 绑定在一起，意味着 c 实际上就是 b，它们只是同一事物的两个不同名称。所以，如果我从 c 中弹出某个东西，我也从 b 中弹出了它。

但是没有发生任何变化。现在，一个教训，需要注意的是，可变默认参数非常危险。所以，一旦你了解了变异，就必须了解它的风险。在定义函数时，默认参数值是该函数值的一部分，而不是每次调用函数时都生成的。

所以说，假设我定义了一个函数 f，它接受某个序列 s，默认情况下，它取空序列。它的操作是在其中附加 5，然后返回附加 5 后序列 s 的长度。

你调用 f，它使用默认的参数值，这个值是一个空列表，将 5 添加到它，并返回包含 5 的列表的长度。然后你得到 1。如果你再次调用它，你得到 2。如果你再次调用它，你得到 3。

这是因为每次你调用它时，s 将绑定到相同的值。这就是默认参数的工作原理。如果默认参数的值是可变的，并且你在函数中间对其进行了修改，那么这个改变仍然会在下一次调用函数时保留，并且你会得到相同的默认参数值。

看起来相当简单的东西，实际上可能会有奇怪的行为，每次调用该函数时都会有所不同。这绝对是需要注意的事情。在第一次调用中，s 被绑定到一个空列表。然后该列表被改变，以包含三个。下一次我调用 f 时，s 被绑定到同一个列表。该列表再次被改变，以添加另一个 3。第三次，你得到第三个 3。就是那样。这就是为什么我们每次都得到不同的返回值：1，然后 2，然后 3。

可变值可用于定义可变函数。所以，这里有一个行为随时间变化的功能。这就是使它可变的原因。每次调用它，即使使用相同的参数，你都会得到不同的结果。

假设我们想要一个表示具有初始余额为 100 美元的银行账户的函数。然后，我想能够从我的银行账户中提取钱，所以我调用它并传入我想要提取的金额。这里的银行账户是什么？就是代表银行账户的提款功能。当我们提款 25 时，剩下多少？75 美元。参数是提款金额，返回值是剩余余额。如果我再提款 25，那么剩余余额应该是 50。相同金额的第二次提款导致不同的返回值。这是一个可变函数。这不是一个纯函数，因为调用函数会产生一些副作用。

改变的是提现函数的行为。不知何故，这个提现函数代表了一些信息，我们称之为状态，即我们正在提现的银行账户的余额。我们讲这个状态描述为函数本地的，因为我们没有在其他地方写下它。相反，它只是函数的一部分，因此定义了它的行为。

如果我提现 60，而我只剩下 50，我可能会得到一个返回值，比如“你的银行账户里没有足够的美元”。但如果你提现 15，那就没问题，并且它会从 50 中扣除。

这个余额存储在哪？它在提款函数内部，我们使用一个高阶函数 `make_withdraw_list` 来创建这个函数，该函数接受初始余额作为参数。我们存储余额的地方是在提款函数的父框架中的一个列表中，也就是 `make_withdraw_list` 框架中引用的列表。由于这是一个可变列表，我们每次调用提款函数时都可以更改其中包含的值。

所以，你应该从这个例子中体会到的是，我们创建了一个函数，将一些行为和一些数据捆绑在一起。但与以前的例子不同，这里的数据每次调用提款函数时都会发生变化。这只是在我的编程语言中拥有可变值的一个自然结果，也就是说，我可以随着时间的推移改变行为。

那么我们如何实现持久的本地状态呢？这意味着在多次调用 withdraw 时，与 withdraw 函数相关的余额是持久存在的。所以，如果我多次调用它，我正在累积信息。我是用一个可变的值来做的。

这是实现：我定义了 `make_withdraw_list`，它接受初始余额，创建一个包含余额的列表。b 的内容可以改变，因为 b 是一个列表。事实上，即使在取款函数的主体内部，b 的内容也是可以更改的。只要一个函数可以引用这个列表，它就可以修改它。

所以，withdraw 是一个函数，它接受要取款的金额，检查确保有足够的钱。它在哪里进行检查呢？实际上它并不检查余额，余额会保持不变，那是原始的余额。它将检查可变列表 b 的索引 0 的元素。如果金额太大，那么我们就完成了。但如果不行，那我通过赋予一个新值来减少那个数值，那就是新的余额，我可以返回它。

`make_withdraw_list` 返回提款函数，其父框架是 `make_withdraw_list` 框架。其中有一个 b，指向一个包含更新后余额的可变列表，最初是传入的余额，但后来会被扣减掉提款金额。如果我调用提款两次，我总是会使用 `b[0]` 的新值，它是从上一次调用中更新的。

所以，这里的名称在提款定义之外被绑定，但元素赋值通过引用该名称来更改列表，你会得到一个看起来像这样的环境图：`make_withdraw_list` 的余额是 100。它定义了一个 b，是一个列表，最初包含 100，然后定义了一个提款函数，其父框架是 f1，即 `make_withdraw_list` 框架，这意味着提款的主体可以引用这个 b，它还可以更改这个 b。

提现被退回，绑定到名为 withdraw 的名称，然后调用金额 25，检查确保 25 不大于此列表最初的值，即 100。然后重新分配列表的内容为 100 减去 25 得到 75。

withdraw 不会重新分配父级中的任何名称。这实际上并不是赋值的工作方式。赋值语句如 `b = ...` 总是分配到本地框架。这实际上并不严格正确。在 Python 中，有一种使用称为 `nonlocal` 和 `global` 语句的语句来分配到非本地或全局框架的方法。你想了解的话可以看看，但我们这里不使用这些。

相反，我们所做的是指向 b，这个 b 总是相同的，它总是相同的列表。只是列表的内容随时间变化而变化。所以，撤销不会改变这些绑定的内容。相反，它改变的是 b 本身的值。
