环境的工作方式有一个有趣的结果，就是一个函数在其体内可以引用自己的名字。让我们看几个例子。

如果我写一个函数 `print_all`，它接受一些参数并打印它，我可以让它返回 `print_all`。实际上这并不奇怪。当你定义这个函数时，所发生的只是将其体存储起来，等待调用。在调用时，`print_all` 这个名字已经存在，并且已经绑定到一个函数。

所以，如果我 `print_all(1)`，它会打印 1，然后这个表达式将求值为 `print_all` 函数，我可以再次调用它。那个表达式将被评估为 `print_all` 函数，所以我可以再次调用它。

让我们看看会发生什么。`print_all` 被定义了。当我调用 `print_all` 时，注意 `print_all` 已经在全局帧中被绑定。我在第一个参数 1 上调用 `print_all`，1 被打印出来了。在这个环境图中，我们还展示了打印输出。然后函数 `print_all` 被返回，同样的函数。我们通过名称查找它，然后将其返回。返回它意味着它是 `print_all(1)` 的值。所以，这正是在参数 3 上调用的函数。

当我在 3 上调用 `print_all` 时，3 被打印，`print_all` 被返回。现在我又要在 5 上调用它，5 被打印出来，`print_all` 被返回，执行结束。

所以即使这个引用指向自身，因为它们没有调用自己，它不会无限运行。由这个调用表达式来确定 `print_all` 被调用的次数。然后我们看到输出是各个单独调用的参数。

这里是一个稍微复杂一点的例子。我要写一个函数来对迄今为止的所有参数求和。我们将其命名为 `print_sums`。而不会返回 `print_all`，因为 `print_all` 已经不存在了。它将返回一个函数，一个我在 `print_sums` 主体内定义的函数，名为 `next_sum`。它接受一个参数 $y$，并立即对 $x + y$ 调用 `print_sums`。这正是求和发生的地方。所以 $x$ 是到目前为止的总和，$y$ 是下一个数字，而 `print_sums` 只是返回 `next_sum`。

让我们看看它是如何工作的。首先，`print_sums` 被定义，然后在数字 1 上调用。到目前为止的总和是 1，所以这就是打印出的内容。接下来，我们定义一个新函数，并将其作为值返回。我们将在数字 3 上调用它。因此，`next_sum` 刚刚在数字 3 上调用。3 不是一个总和，这只是这里的参数。我们得到总和的地方是，我们将在当前环境中的 $x$——在 f2 的父级框架中——与 $y$ 相加，得到 4。

现在这个 4 会被传递到对 `print_sums` 的另一个调用中。所以，有另一个对 `print_sums` 的调用。这里的参数是 4，这是 1 和 3 的总和。`print_sums` 做了什么呢？它只是打印出它接收到的总和。然后定义一个新函数，那个新函数被返回。

那么，它被返回到哪里了呢？它是 `print_sums(1)(3)` 的值。注意，我们正在返回的函数，它的父函数是 f3，知道目前总和是 4。因此，如果它想计算整个东西的总和，$1 + 3 + 5$，它需要那个 4 以及我即将传入的 5。所以我刚刚调用了 `next_sum` 第二次。请注意，现在我传入的是 5。父级是 f3，其中包含 4，这意味着我可以计算总和 9。

在这里我计算它，$4 + 5$。我将其传递到第三次调用 `print_sums`。`print_sums` 打印出 9，这是 1、3 和 5 的总和。通过在 `print_sums` 中定义一个内部函数，并且这个内部函数返回对 `print_sums` 的调用，我能够在这里使用参数来记忆沿途计算的值。这些值作为参数传入，它们出现在帧内，这是 `next_sum` 局部帧的父帧。在这种情况中，`next_sum` 执行求和操作，而 `print_sums` 只是打印出它得到的任何东西。

所以，这是同样的情形。重要的是要注意各个部分的作用。当你实际有了调用表达式 `print_sums(1)(3)(5)` 时，第一次调用是对 `print_sums` 的调用。但其他两个是传递给 `print_sums` 返回的函数的，这就是 `next_sum` 函数。所以，`next_sum` 函数只是告诉 Python 在下一次调用中要做什么。下一次调用首先得到 3，然后是之后得到 5。所以我们看到，在 `print_sums` 的帧中，我们看到的是 1、4 和 9 的总和。在下一个总和的帧中，我们只看到直接传递的单个参数，这些参数是 3 和 5。

递归函数，这门课程里我最喜欢的话题之一。递归函数就是一个函数，其主体要么直接调用自身，要么间接调用自身。今天我们会看到这两种情况。这意味着有时候当你执行一个函数的主体时，而且它是一个递归函数，可能需要你再次应用同样的函数。

递归不仅出现在计算机科学中，它也出现在艺术、自然和数学中。比如说谢尔宾斯基三角形，被定义为三个不同的谢尔宾斯基三角形：1、2、3。每一个像这个一样的，由三个谢尔宾斯基三角形组成。

作为一个起始例子，我们将对一个数字的各位数求和。2013 是一个数，正整数。

$$2 + 0 + 1 + 3 = 6$$

为什么我们要这么做？数字和有一些有趣性质，比如一个数字能被 9 整除，当且仅当它的数字和也能被 9 整除。而且将数字相加对于检测打字错误非常有用。

这是一张信用卡。信用卡号码的问题在于它们非常长，人们经常输入它们，而人类容易出错。所以，每张信用卡上都有一个被称为校验位的数字。第 16 位数字实际上不是你账号的一部分。相反，它是由所有其他数字计算得出的。而那个的重点就是，如果校验位数字与所有其他数字的计算不匹配，那就表明输入的数字有误，这是一个无效的信用卡号。

校验位数字实际上不只是其他数字的总和。这是稍微复杂一点的东西，我们将在随后的课程中计算，但我们将从数字总和开始，然后再看一下用于计算信用卡校验位的实际算法。

我们要不在使用 `while` 语句的情况下对数字求和。你可能已经能够自己想出如何对数字求和，但是不使用 `while` 语句将需要使用递归。

首先是一个基本模块。我们来定义分割函数。接受一个正整数 $n$，并将其分割成两部分：除了最后一位数字，和最后一位数字。我们将通过整数除法和取 $n$ 除以 10 的余数来实现这一点。让我们写下这个分割函数：

```python
def split(n):
    return n // 10, n % 10
```

我们可以理解它的作用。它将一个数字分解成除了最后一位数字和最后一位数字之外的所有部分。对于 2013，我们得到了 201，然后最后一位是 3。所以如果我能把 201 的数字相加，然后再加 3，那我就得到了 2013 的总和。让我们用代码来写。

为了对 $n$ 的数字求和，如果 $n < 10$，意味着它是个个位数，我们就返回 $n$。数字 7 的各位数和就是 7。否则，我们将 $n$ 分成除了最后一位数和最后一位数以外的所有部分，然后我们将返回从这两部分计算得到的数字和。那总共是多少呢？我们要对除了最后一个数字以外的所有数字求和，然后我们再加上最后一个数字。

对于 2013，这将有 201 和 3。我会把 201 的数字相加，得到 3。再加上 3，我就得到了 6，这就是我要找的答案。这是一个递归函数。为什么呢？因为我从某些数字中调用了一些数字。这真的运行了？那么让我们看看递归函数的解剖，然后我们可以尝试一下。

它的工作方式是，`def` 语句的头部类似于任何其他函数。你只是给函数起个名字和一些形式参数。然后，通常递归函数将以一个检查基本情况的条件语句开始。基本情况是我尝试解决的问题的非常简单的版本。在这种情况中，基本情况是一个非常简单的情况，您只有一个数字，所以总计起来很简单，你只需返回 $n$。所以基本情况在没有递归调用的情况下进行评估。它们通常可以直接计算，比如在这种情况下，只需返回 $n$。

现在，如果我们不在基本情况下，意味着这不是一个非常简单的问题，而是更复杂的情况，其中 $n$ 有多位数字，那么我们将有一个递归情况。递归情况通过递归调用进行评估。我们把要对其数字求和的数字拆分开，然后对一些数字进行递归调用。

现在注意，我们不尝试对 $n$ 的数字求和，相反，我们对比以前更简单的问题的数字进行求和。所以如果我们以 2013 开始，现在我们只有 201 要对其数字求和，这更简单，因为它有更少的数字要求和，使我们更接近基本情况。

在我们继续之前，让我们只是输入它，并确保它确实有效。定义 `sum_digits(n)`：

```python
def sum_digits(n):
    if n < 10:
        return n
    else:
        all_but_last, last = split(n)
        return sum_digits(all_but_last) + last
```

如果 $n < 10$，那是基本情况的测试，我会直接返回 $n$。否则，我将通过调用我的 `split` 函数将 $n$ 分解成两部分，除了最后一位数字，然后是最后一位数字。然后我会返回一些数字。对于简单的问题，就是除了最后一个数字，然后我必须加上最后一个数字。我们可以对 2013 或者任意数字的各个数字求和。

让我们谈谈环境图中的递归。好处在于，环境图对理解递归函数很有用。

我们要看一个新的例子：阶乘函数。它计算 $n$ 的阶乘，即 $n \times (n-1) \times (n-2) \times (n-3) \dots \times 1$。我们将从查看 Python Tutor 本身开始。这是一个实现：

```python
def fact(n):
    if n == 0:
        return 1
    else:
        return n * fact(n - 1)

fact(3)
```

将 $n$ 的阶乘定义为：如果 $n = 0$，我们返回 1。这是阶乘的定义的一部分，即 0 的阶乘是 1。否则，返回 $n \times \text{fact}(n-1)$。这就是我们的递归调用。最后，我们将对 3 调用阶乘，这应该给我们 $3 \times 2 \times 1$，然后我们就完成了。

首先我定义了这个函数，然后我用参数 3 调用它。3 不是 0，所以我计算 $n \times \text{fact}(n-1)$。所以我们需要弄清楚我们正在相乘的这两个数是什么，这涉及计算 $n-1$ 的阶乘，其中 $n-1$ 是 2。所以我再次调用阶乘，这次 $n$ 绑定到 2，因为这是我传入的参数。

然后我再次执行函数体，在这个新的环境中，$n$ 被绑定到 2。2 不等于 0，所以我们再次计算 $n-1$ 的阶乘。但在该环境中，$n-1$ 是数字 1，这意味着我们下一次调用阶乘时 $n$ 绑定的数字不同。

所以，现在我们有一、两、三次阶乘的调用。也许我们还会再来一次。让我们看看，执行 `fact` 体的内容再次。我们执行 `fact`，我们看看 1 是否等于 0，它不是。所以我们必须再次执行此 `return` 语句，这意味着计算 $\text{fact}(n-1)$。在这一步上，$n-1$ 是多少？是 0。所以我们断定计算 $\text{fact}(0)$。

再来一次，我们执行这个函数的主体，看看 0 是否等于 0。确实是，所以我们返回数字 1。现在最终我们有了一个返回值。

现在当我们返回时会发生什么？我们回到我们首次调用这个函数时正在评估的那行，当时 f3 是当前环境的第一个帧，这行是计算 $\text{fact}(n-1)$ 的地方。我们发现的是，在那个框架里，$\text{fact}(1)$ 的结果是 1。

现在我们发现对于这个框架，也有一个返回值是 1，因为 $n$ 是 1，这个求值结果是 1，而 $1 \times 1$ 就是 1。我们将它返回到我们首次调用这个函数时所在的地方。顺便说一句，那是在执行 f2 框架中的 `return` 语句时的中间过程，而那又是在同一个主体内部。而它再一次是在求值我所突出显示的这个表达式，这个表达式现在的返回值是 1。我们将 $n$ 等于 2 乘以 $\text{fact}(n-1)$ 的返回值，而那个返回值是 1。$2 \times 1 = 2$，所以这是我们的返回值。

我们确切地回到了同一个地方，但在一个不同的框架中，回到我们执行原始调用阶乘的 `return` 语句的时候。在这种情况中，我们将 3 乘以我们得到的任何东西，这就是这个返回值。$3 \times 2 = 6$。所以我们得到了 3 的整个返回值。实际上，这是正确的答案。

$$3 \times 2 \times 1 = 6$$

所以在执行的中间某个时候，我们的环境图看起来像这样。在这一点上，我们正在从阶乘的最后一次调用返回，但我们还没有从这些调用中返回。

咱们来分析一下当你调用递归函数时发生的一些情况。同一个函数被多次调用，我们可以看到。一次是从这里调用，有好几个不同的调用是从这里画出的，所以这个是从这里来的。但是所有这些 f2、f3 和 f4 的框架都是从在 `fact` 中调用 `fact` 时产生的。

为了跟踪每次调用中的不同参数，有不同的框架。这就是为什么我们能够多次调用一个函数，每次使用不同的参数，甚至一个参数嵌套在另一个参数里，而计算机不会混淆，因为它采用了这种评估模型，其中我们有不同的框架保存了传入的不同参数值。$n$ 的求值取决于当前的环境是哪一个。由所有这些不同的 $n$，每个对应于对 `fact` 函数的不同调用。这意味着每个包含 $n$ 的表达式可能会根据我所在的环境而求值为不同的结果。

而每次对 `fact` 的调用都解决了比上一次更简单的问题。在这种情况中，因为 $n$ 不断减小，一旦 $n$ 到达 0，那么我们就有一个非常简单的计算，我们只是返回 1。所以当 $n$ 为 0 时，要作的工作比 $n$ 为 1 时要少，而且比 $n$ 为 2 时要少，比 $n$ 为 3 时要少。

现在，我们可以比较迭代和递归的情况。迭代是递归的特殊情况。这是我们的阶乘函数，这就是它的作用。这里是另一种实现，使用 `while` 语句而不是递归：

```python
def fact_iter(n):
    total, k = 1, 1
    while k <= n:
        total, k = total * k, k + 1
    return total
```

所以我可以说，我可以通过跟踪总阶乘和我即将相乘的数字来计算阶乘。只要 $k \le n$，我就将总数更改为总数乘以“下一个”数字，而 $k$ 更改为比之前多 1。当我完成这个 `while` 语句时，总数将绑定到 $n!$。所以 $k$ 是 1，然后是 2，然后是 3，然后是 4，然后我们将它们全部相乘。

使用递归，我们说一些稍微简单的东西。我们说，如果 $n$ 为 0，阶乘 $n$ 的结果是 1；否则，它等于 $n \times \text{fact}(n-1)$。现在，解释这个不仅花费更少的时间，而且从字符数量的角度来看更容易写。也许如果有人看到这个函数，逻辑会更容易理解。所以，有些情况下使用递归确实简化了事情，我觉得这就是其中之一。

现在，与每个实现相对应的数学公式略有不同。因此，迭代版本说我从 $k=1$ 开始，然后一直到 $n$，每次都乘以数字 $k$。这就是我得到 $n!$ 的方法，那个感叹号表示阶乘。

递归定义对应的数学表达式是：

$$n! = \begin{cases} 1 & \text{if } n = 0 \\ n \times (n - 1)! & \text{otherwise} \end{cases}$$

这也是阶乘的正确定义，只是看起来与之前的定义有点不同。所以这个与那个完全对应，这个也对应于这个。但是这里有一些额外的机制用来跟踪总数，并确保我们在每个部分中正确地进行乘法运算，然后在最后返回正确的结果。

现在我们可以通过查看所有涉及的名称，看出事实上迭代与我们最初使用递归定义相比多了一些复杂性。我们有名字 $n$，名字 `total`，名字 $k$，还有名字 `fact_iter`。而在递归中，我们只有两个名字。环境图中的帧负责追踪计算的位置。而在左边，我们必须通过追踪 `total` 和追踪 $k$ 来做到这一点。

那么现在，我们终于要实现 Luhn 算法了。这实际上用于计算信用卡号的校验和。这是来自维基百科的描述：从最右边的数字开始，也就是被检查的数字，从右向左，将每第二个数字的值加倍。如果这个加倍的结果大于 9，那么将乘积的各位数字相加，取所有数字的总和。

那么这是如何工作的呢？好的，我们来计算一下 1 3 8 7 4 3 的 `luhn_sum`。我们通过这样做：将每个数字加在一起，除了每隔一个数字——我已经标记成灰色的，要把它们翻倍。从最右边开始，3 仍然是 3，4 翻倍得 8，7 还是 7，8 翻倍得 16，但由于操作的结果大于 9，所以我们要将 1 和 6 相加得到 7。3 是 3，1 是 2。所以：

$$2 + 3 + 7 + 7 + 8 + 3 = 30$$

而一个有效的信用卡号将始终具有 Luhn sum，这是 10 的倍数。那么有什么意义呢？Luhn sum 的好处是，如果任何一个数字不正确，那么 Luhn sum 将不是 10 的倍数。此外，几乎所有的转位，比如我交换 4 和 7，Luhn 算法会检测出结果，并给出一个不是 10 的倍数的结果。

所以我们写一个函数来计算这个。`n` 的 `luhn_sum`，它和一些数字求和非常相似。如果 $n < 10$，那么我们就返回 $n$。否则，我们会得到最后一位数字。然后，我们会返回某个数加上最后一位数字，但那个数将不是 `luhn_sum`，而是 `luhn_sum_double`。而双倍版本将会做的是，它会将最后一位数字加倍，如果必要的话还会加上它的某些数字，然后再加入那个数字，就像我们之前指定的那样。

好的，所以 `luhn_sum` 只有一个数字时就取最后一位，否则就会进行这个加倍操作。那么让我们计算那个双倍数字。所以我们首先会把 $n$ 分解开，然后我们将计算 `luhn_digit = sum_digits(2 * last)`，即最后一位数字的 2 倍的各位数之和。

现在，如果 $n < 10$，我们就返回 `luhn_digit`。否则，我们将返回除了最后一位数字外的所有数字的 `luhn_sum`，再加上我们计算的那个被加倍的 `luhn_digit`。

```python
def split(n):
    return n // 10, n % 10

def sum_digits(n):
    if n < 10:
        return n
    else:
        all_but_last, last = split(n)
        return sum_digits(all_but_last) + last

def luhn_sum(n):
    if n < 10:
        return n
    else:
        all_but_last, last = split(n)
        return luhn_sum_double(all_but_last) + last

def luhn_sum_double(n):
    all_but_last, last = split(n)
    luhn_digit = sum_digits(2 * last)
    if n < 10:
        return luhn_digit
    else:
        return luhn_sum(all_but_last) + luhn_digit
```

注意，`luhn_sum` 调用 `luhn_sum_double`，而 `luhn_sum_double` 调用 `luhn_sum`。这是相互递归，就是两个函数互相调用的情况。它可以出现在这两个函数中，也可以只在一个函数中出现。这种情况下，我们看到它在两者中都出现了。

好的，所以仅仅是数字 2 的 `luhn_sum` 是 2。但如果我看 32，那么 3 会翻倍变成 6，再加上 2 就是 8。如果我取一个有效的信用卡号的 `luhn_sum`——这是一个有效的 MasterCard 号码，它不起作用，但它在 MasterCard 使用的数字范围内——然后我们会得到一个 `luhn_sum`，它是 10 的倍数，比如 20。所以如果你想在你自己的信用卡上尝试这个，你可以检查确保它有效，方法是确保它的 `luhn_sum` 是 10 的倍数。或者如果那太麻烦，你可以把你的信用卡号发给我，我会帮你检查。

现在，我们来谈谈递归和迭代之间的关系。

有时候你想把一个递归函数转换成迭代的实现方式。这可能有点棘手，因为迭代是递归的一个特殊情况。但对于许多函数来说，转换成迭代实现是直接了当的。我们之前讨论过的例子就是其中之一。所以关键是要弄清楚迭代函数在每次通过 `while` 语句时需要维护的状态。

因此，如果我们看一下之前实现的 `sum_digits` 函数，我们可以看看在每个递归调用中传递了什么以及返回了什么。这些是提示，告诉我们在编写迭代版本时可能需要为其命名的内容。所以传入的是剩下要求和的部分，我们称之为 `n`，作为形式参数；而返回的是部分和，即迄今为止数字的总和。

那么让我们试着写一个迭代版本。定义 `sum_digits_iter`。我们将存储到目前为止的数字和。然后当 $n > 0$ 时，表示还有数字要求和，我们将重新绑定 `n` 和 `last` 到 `n` 的拆分版本，所以 `n` 会变得比之前更小。它将包含分出最后一位数字之外的所有数字，然后 `last` 将包含最后一位数字。然后我们可以更新 `digit_sum`，变成之前加上 `last`。最终，我们将返回数字总和。

```python
def sum_digits_iter(n):
    digit_sum = 0
    while n > 0:
        n, last = split(n)
        digit_sum = digit_sum + last
    return digit_sum
```

所以我们仍然可以求和数字。现在我们可以对数字进行迭代并得到相同的答案。通过检查，我们弄清楚了如何做。原来，将使用 `while` 语句的迭代实现转换为递归实现要简单得多，因为迭代是递归的一种特殊情况。

这就是故事的开头。当你查看一个迭代实现时，你要找的是在不同迭代之间保持的状态，然后将其作为参数传递。这是我们一些数字的迭代实现。在这里，通过 `while` 循环的每次迭代中保持的状态是 `n` 和数字总和，其中数字总和包含到目前为止的部分数字总和。

所以当我们写出相同事物的递归版本时，我们传递的正是那个 `n` 和到目前为止的数字总和。不再有一个 `while` 语句说 $n > 0$，现在我们有一个基本情况，恰恰相反：当 $n = 0$ 时，我们就返回数字和。否则，我们执行与 `while` 语句的主体相同的操作，只是我们将新的 $n$ 值和更新后的数字和作为参数传递给递归调用。

```python
def sum_digits_rec(n, digit_sum):
    if n == 0:
        return digit_sum
    else:
        n, last = split(n)
        return sum_digits_rec(n, digit_sum + last)
```

然后我们对 `n` 进行递归调用 `sum_digits_rec`，其中 `n` 绑定到传入的除最后一位数字外的所有数字，然后数字和加上最后一位就是到目前为止的总和。因此，通过赋值进行的更新变成了递归调用的参数。对于每个迭代实现，这都可以被普遍地完成。
