当我们定义 `original` 时，我们不希望它总是 `fact`，我们希望它是运算符是什么就是什么。我们使用反引号确保运算符得到评估。然后我们重新定义运算符是什么，比如 `fact`，成为一个新的 `lambda`，打印出列表，而不是总是打印 `fact`。我们想要先打印操作符，然后是参数 $n$，而且我们仍然需要在 $n$ 上调用原始的。这是我们生成的代码的一部分。

当我们定义结果时，不是每次调用 `(fact 5)`，我们想要调用表达式是什么就调用什么。那就是，例如 `(fact 5)`。

最后，我们将操作符设置回最初的值，这样如果有人再次调用它，我们不会看到不同的结果。然后我们返回结果。我们关闭 `begin`，关闭定义的宏。

现在我们可以追踪 `(fact 5)`，我们应该看到一个被追踪的版本。现在这个版本有一个问题。让我们看看是什么问题。

我们定义 `fact`，称之为 120。我们构建我们的宏，这是一个追踪宏。当我们将其追踪宏应用于 `(fact 5)` 时，在计算 120 之前，我们打印了一堆东西，看起来不错。但我们并不打印 `(fact 5)`。相反，我们要打印出 `fact` 过程，看起来是这样的。

但我们实际上只想打印出 `fact` 符号。我们可以通过引用该符号来实现。这个符号通常被称为运算符。

因此，如果我们再次运行这个，现在我们看到了我们想要的东西。调用 `(fact 5)` 会给我 120。追踪 `(fact 5)` 给我看发生了什么，并给了我 120。但如果我在那之后调用 `(fact 5)`，一切都恢复正常，因为我回去重新定义了 `fact` 为原始状态。而且好的一点是，这个追踪宏根本不涉及 `fact` 过程。

它只是假设 `expr` 是任何可能是递归的过程的调用表达式，该过程接受一个参数。它必须接受一个参数的原因是我们将这个 `lambda` 定义为一个参数。但你也可以尝试写一个更通用的版本。

现在我们已经实现了与 Python 中看到的相同的关注点分离，但这个版本甚至比 Python 的更好。因为在 Python 中，你必须决定是否始终跟踪 `fact`，这取决于它是否被装饰。而在 Scheme 版本中，我们可以有时调用未追踪的 `(fact 5)`，有时跟踪它，甚至可以切换回去。

真正重要的是我们是否追踪一个表达式，一个调用，而不是永久追踪整个过程，这提供了额外的灵活性。
