波形文件的作用就是直接编码声波的样本。声音是以波的形式传播，波在任何时刻都有振幅。采样的作用是允许我们通过仅记录波在特定时刻的高度或振幅来数字化这个波。这就是这些点所代表的。谢谢维基百科给了这张酷炫的图片。

通常，这些波浪是通过在现实世界中记录声音而创建的。但你也可以根据数学函数从头开始生成波浪。

从函数调用返回意味着结束函数调用并确定调用表达式的值。

所以我们已经看到了返回语句，但我们还没有详细讨论过。
返回语句是为了完成对调用表达式的求值。
当你对用户定义的函数进行调用表达式的求值时，你必须在新的环境中执行该函数的主体，直到达到返回语句或者到达主体的末尾。

所以当你达到像 $f(x)$ 这样的调用表达式，对于某个用户定义的函数 $f$，那就是切换到新的环境的时候了。
现在是执行 $f$ 的主体的时候了。
为什么要这么做呢？
为了弄清楚 $f(x)$ 的值是多少。

当 $f$ 内的 return 语句被执行时，我们切换回之前的环境，即评估 $f(x)$ 的环境。
现在 $f(x)$ 有一个值了。
这个值通常决定了原始表达式中接下来会发生什么。
也许我们正在将 $f(x)$ 的值赋给一个名称，或将其作为参数传递给其他函数。
不管是什么情况，在达到 return 语句时，$f(x)$ 现在有一个值。
而且这个值就是该语句中 return 表达式的值。

在执行函数体时，只有一个 return 语句会被执行。
一旦达到该 return 语句，我们就完成了。

例如，让我们编写一个函数，以反向顺序打印整数 $n$ 的最后几位，直到找到数字 $d$。
假设 $n$ 是非负的。
这是我们正在做的事情的一个例子。
34567 的末尾是从 34567 的末尾开始的所有数字，直到我们达到 5，然后我们就完成了。
我们从 7 开始，然后是 6，然后是 5。我们找到了 5，我们完成了。

要怎么写这个函数呢？
有一种简单的方法就是写一个 while 语句，它会打印所有的数字：7、6、5、4、3。

这里的思路是说，当 $n > 0$ 时，我们把 $n$ 分解成它的最后一位数字和除最后一位数字外的部分，然后打印最后一位数字。
现在我们需要确保当找到 $d$ 时，我们就完成了。
我们可以通过一个包含 return 语句的条件语句来做到这一点。
如果我发现 $d$ 是我们当前查看的 $n$ 片段的最后一位数字，那么我们返回 None，作为结束 while 语句过程的一种方式。

一旦你返回，函数体内的其他代码都不再执行。

让我们看一些在 while 语句块中可能返回的例子。

我要写一个叫 `search` 的函数，这是一个高阶函数。

那么，什么是真值呢？
`True` 是一个真值，或者不为 0 的数字也是真值。
所以我们从 $x = 0$ 开始，只要找到一个使得 $f(x)$ 为真的值就继续尝试。

现在我们来谈谈选择名称的事情。
名称的作用是帮助人们。
所以你选择的名称通常对程序的正确性并不重要，但对于组合或以一种其他人能够阅读的方式编写程序而言，它们确实非常重要。

所以这里有一些指南。
名称应该尽量传达与其绑定的值的含义或目的，这样很容易看出我们为什么创建了这个值，以及我们接下来要对它做什么。

绑定到名称的值的类型，无论是数字还是字符串，最好在函数 docstring 中进行文档记录，而不是绑定到值本身的名称。

而函数名称，我们为定义的函数所取的名称，通常传达它们的效果，比如打印；它们的操作，比如三倍化；或者返回的值，比如一个数字的绝对值。

这些都是给函数取名字的合理方式。

所以这里只是一些建议。
左边的那些不太好。
右边的那些更受欢迎。
不要仅仅因为它是真或假就把某个值命名为 `true_false`，试着说出它应该代表的意思，比如在 Hog 游戏中玩家掷出了一个 1。

在一个较大程序的上下文中，不要只用单个字母，比如 $d$。使用一个完整的名称会更有帮助，比如 dice。

当你在给函数命名时，描述一下那个函数的作用，它的行为是什么，而不仅仅是谁调用它。

我们不想仅仅通过它们的类型来命名值。
所以不是用 `my_int` 来表示某个东西是整数，我们想要说出存储该整数的目的以及它代表什么，比如犬的数量。

最后，有一些名称可能在特定字体下非常难以阅读，比如小写的 l、大写的 I、大写的 O，可能被误认为是数字 1 和 0。
如果你只使用一个字母，像 $k$、$i$ 或者 $n$ 更为典型。

在程序中，我们不必为每个中间值都取个名字，因为我们可以使用复合表达式。

错误有三种形式。

第二种类型是运行时错误。
这些是在你的程序执行时由 Python 解释器检测到的错误。

第三种类型的错误是逻辑或行为错误，在 Python 中根本不会被检测到。
程序在运行，只是做了错误的事情。
检查这些错误的方法是编写测试，并检查这些测试是否正确描述了程序的行为。
