咱们再聊聊高阶函数以及它们是如何与我们一直在示意图中谈论的这些环境互动的。

高阶函数就是一个接受另一个函数作为参数值，或返回一个函数作为返回值，或两者兼有的函数。

好消息来了：其实我们的环境示意图已经处理了高阶函数的情况，也就是说，我教给你的规则已经适用，即使我们传递的是函数而不仅仅是数字。

现在你知道了这个大秘密：我告诉你关于环境和环境示意图的全部原因，就是为了我们能够准确地解释高阶函数是如何工作的。

咱们来演示一下。比如，我写一个叫做 `apply_twice` 的函数：

```python
def apply_twice(f, x):
    return f(f(x))
```

这个函数接受一个函数和一个参数，然后它要做的事情是通过调用 `f(f(x))` 来两次应用那个函数。`apply_twice` 是一个高阶函数，为什么？因为它会接受另一个函数作为参数。

咱们单件创建这样一个函数，比如我们的朋友方块（`square`）怎么样：

```python
def square(x):
    return x * x
```

现在我们要运行 Python，从这个文件开始。这样我们就能算平方了，当然，但我们也可以对数字 3 `apply_twice` 平方函数：

```python
apply_twice(square, 3)
```

这将对其进行一次平方得到 9，再平方得到 81。

注意我使用的语法，我调用了 `apply_twice` 作为接受两个参数的函数，其中一个是 `square` 的值，另一个是 3 的值。这两个参数传递给 `apply_twice` 函数，然后进行两次平方。

让我们看看这个环境图。我首先定义 `apply_twice`，我定义 `square`。注意还没进行平方运算，但现在我要在 `square` 和 2 上调用 `apply_twice`：

```python
apply_twice(square, 2)
```

调用 `apply_twice` 引入了一个新的帧。形式参数 `f` 和 `x` 被绑定到实际参数值，即 `square` 函数和数字 2，在这一点上执行主体。

主体是 `f(f(x))`。为了评估 `f(f(x))`，我首先必须评估运算符 `f` 和操作数表达式 `f(x)`。因此，`f(x)` 需要调用 `f`，目前绑定到 `square`。所以我在数字 2 上调用 `square` 函数，这是 `x` 绑定的值。通过对 2 求平方，最终得到返回值 4。

因此，这里的内部 `f(x)` 评估为 4。然后我要在 4 上调用 `f`。`f` 是什么来着？那是一个平方的函数。所以我在 4 上调用 `square`，它返回 16，最终绑定到名字 `result` 上。16 就是你两次平方 2 得到的结果。

好的，让我们深入了解一下发生了什么。执行完前两个 `def` 语句后，我只有一些绑定到那些函数的函数的名称，我还没给任何一个打电话。

我执行 `apply_twice(square, 2)`，这意味着我搞清楚了 `apply_twice` 是什么，我搞清楚了 `square` 是什么，然后我实际上应用了那个函数到两个参数，即 `square` 函数和数字 2。

应用用户定义的函数包括三个步骤：
1. 创建一个新的框架；
2. 将形式参数 `f` 和 `x` 绑定到参数；
3. 执行主体，这种情况下就是返回 `f(f(x))`。

所以当我在下一步实际应用这个函数时，我得到了这个环境图。我保留了旧的，只是为了让你看到区别。

所以当你应用一个用户定义的函数时，我们创建了一个新的框架。这个叫做 f1，它是为执行 `apply_twice` 函数的主体而创建的。而且，它有形式参数 `f` 和 `x` 绑定到这两个参数：传递进来的参数或者是 `square` 函数和数字 2。这里有 `square` 函数，这里有数字 2，你可以看到那里的绑定。

此刻，我们可以执行 `f(f(x))`。我们怎么搞清楚 `f` 到底是什么意思呢？

这是我们当前的环境，一个本地框架后面跟着全局框架。当我们尝试在当前环境中查找一个名称时，我们首先查看第一个框架；如果那里没有，我们就查看第二个框架，以此类推，直到找到它。但是，`f` 其实在第一个框架里，就在这里。我们看到名称 `f` 是给予将事物平方的函数的名称。这就是实际发生的平方过程。

咱们来聊聊嵌套定义的环境。

上次，我给你演示了下面的例子：我可以创建一个 `make_adder` 函数，它接受一个非正式参数 `n`，它内部创建另一个函数 `adder(k)`，它返回 $k + n$。现在，`make_adder` 函数返回在其体内定义的 `adder` 函数：

```python
def make_adder(n):
    def adder(k):
        return k + n
    return adder
```

所以 `make_adder`，它的作用是创建一个新函数并返回它，它实际上不执行加法。

如果我把这个函数加载到 Python 中，会发生什么？我可以即时创建新的函数。通过调用 `make_adder` 并传入 3，我可以创建一个名为 `add_three` 的函数：

```python
add_three = make_adder(3)
add_three(4)
```

而在函数 `add_three` 中，不知何故有一个被添加的数字 3。我们是如何在一个函数中嵌入数据的呢？

好的，让我们看看环境图，我们会明白到底发生了什么。

这是个例子：我定义了 `make_adder`，它并不执行其主体，它只是定义了一个新函数。然后我调用 `make_adder` 并传入参数 3，这引入了一个带有形式参数 `n` 绑定到参数 3 的新帧。

接下来，我定义了 `adder` 函数，这是 `make_adder` 主体中的第一步。在我定义 `adder` 函数时，我创建了一个新的函数值。然后，我将函数 `adder` 的名称绑定到当前帧中的该值，注意这不是全局帧。所以 `make_adder` 帧及其环境可以访问这个 `adder` 函数，但到目前为止，还没有办法从全局帧引用它。

但一切都在我们返回时发生变化。因此，`return` 语句的作用是将信息从本地帧带回到我们首次调用该函数时的当前帧。所以我们回到了特定的点，我们正在评估这个调用表达式。

所以，当我们返回时，我们将直接回到评估这个的地方，我们正要将其绑定到名称 `add_three`。那么我们要绑定到名称 `add_three` 的返回值是什么？

在这里，这是我们通过弄清楚当前环境中 `adder` 的含义并返回该值得到的这个函数的返回值。这个值就是这个 `adder` 函数。

在下一步中，我立即回到之前的位置，也就是在全局框架中已经评估了 `make_adder(3)`，并且其值是这个函数 `adder`。我使用常规赋值将其绑定到名称 `add_three`。记住，我们可以给同一个函数起多个名字。

好的，现在我们有 `add_three`，这是一个将 3 添加到事物上的函数。它是怎么做到的呢？它的主体只是 $k + n$。

好吧，让我们在 4 上调用 `add_three`，看看会发生什么。我们引入了一个新的框架，其中 `k` 绑定到 4。它的父级实际上是 f1，在这里的框架。所以即使我们从 `make_adder` 返回，我们仍然可以访问它的内容，因为我们创建了其父框架为 `make_adder` 框架的框架，其中包含名称。我马上详细解释一下。

但这里发生的是，我们在以 f2、然后是 f1、最后是全局帧开始的环境中评估表达式 $k + n$。我们发现 $k$ 就是 4，我们发现 $n$ 就是 3，这就是我们得到的数字 7，它绑定到 `result`，然后我们就完成了。

所以，这就是我刚刚给你展示的示例的环境图。让我们稍微谈一下。

这里我们有一个嵌套的 `def` 语句，而且我们还有一些我们以前从未见过的东西：一个函数的父级不是全局帧。所以发生的是，你把函数的父级设置为该函数创建时的当前帧。

那么这个 `adder` 函数是如何被创建的呢？它是 `make_adder` 的主体的一部分。所以 `make_adder` 是当前环境的第一个帧，当这个 `adder` 函数被创建时。这就是为什么它的父级是 f1。

所以当父级是 f1 时，我们调用函数 `adder`，我们把名称复制到新的框架中，我们把形式参数复制并将它们绑定到参数值，我们还将函数的父级复制为框架的父级。

所以这就是为什么我们首先要有函数的父级的解释，这是为了当我们调用这些函数时，我们可以写下框架的正确父级。

现在，我们为什么需要给框架配父母呢？这告诉我们如何找到当前的环境。所以，当我们实际评估 $k + n$ 时，它从加法器框架开始，然后是它的父母 f1，再然后是它的父母全局框架 Global。

我简写为 G，只是为了让所有东西都能在屏幕上显示。如果你把它评估为 Global 也没问题。

好的，现在我们有一个三框架的环境。如果我们在该环境中查找名字 $k$，我们首先看到 $k$ 是 4，然后就完成了。在这个环境中查找变量 $n$，首先查找当前环境的第一个框架，但那里没有 $n$。所以我们必须查看第二个框架，这是第一个框架的父框架，这是 $n$ 被绑定为 3。因此，我们可以得到 $k + n = 4 + 3 = 7$，然后我们就完成了。

关键点是什么？每个用户定义的函数都有一个父框架。在我们看过的所有其他示例中，都是全局帧。但是，当你有一个嵌套的 `def` 语句时，情况就不同了。内部 `def` 将具有外部 `def` 函数调用的框架。函数的父级是其定义或创建时的框架。正如我们所见，每个本地框架都有一个父框架。框架的父级是调用该函数的父级。

这应该解释了我在创建这个加法器框架时在这里做的事情：我复制了它的名称，我还复制了它的复数形式，并将其实参形式绑定到其参数上。你在正确创建这个框架的时候需要的所有信息：加法器的父级 f1，在这个函数值里都在。所以如果你知道你调用的是哪个函数，你就知道怎么正确写下它的框架。

这是一个绘制环境图的小指南，这样你就可以自己画它们，而不用使用 Python Tutor。这真的很有帮助，因为这样你甚至可以理解复杂的例子。

当一个函数被定义时，你总是创建一个看起来像这样的函数值。它的父级是当前的执行框架，这就是为什么当我们创建 `adder` 函数时，我们位于 `make_adder` 框架中的原因。所以我们写下父级是 f1，这是这个框架的标签。

现在，我们不写下 `make_adder`，因为可能有多个不同的被称为 `make_adder` 的框架，但每个都会有一个唯一的标签，所以我们使用那些。我们在当前帧中将名称绑定到函数值，所以，那就是当我们有名字 `adder` 指向这个函数的时候。

当一个函数被调用时，我们创建一个新的帧。所以我们添加一个以被调用函数的名称为标题的本地帧。我们将函数的父级复制到本地帧，然后我们在该本地帧中将形式参数绑定到实参。最后，我们可以在以该本地帧开头的环境中执行函数的主体。

如果我们需要在该环境中查找名称，我们沿着父级一直追溯到全局帧。而我们无论在哪里首次找到该名称，就是我们使用的值。

本地名称：函数的形参具有局部范围。让我给你演示一下这是什么意思。

我们想象一下，试图摆脱这个嵌套定义的过程，而是写两个不同的函数：

```python
def f(x, y):
    return g(x)

def g(a):
    return a + y
```

现在我调用 `f(1, 2)`：

```python
f(1, 2)
```

这将导致一个错误，报错说：全局名字 `y` 未定义（NameError: global name 'y' is not defined）。

现在，它真正想告诉你的是：在 `g` 中，也就是在尝试评估这个返回表达式时，它找不到名字 `y` 的任何值。

这里是一个例子：我们定义了 `f`，我们定义了 `g`。我们调用 `f`，`x` 绑定到 1，`y` 绑定到 2。我们调用 `g`，因为我们正在执行 `f` 的主体。现在，在 `g` 中，`a` 绑定到 1。所以我们有各种名字和值的绑定。在这里，我们看到了那个错误。

为什么会有错误，即使 `y` 就在这里？这是因为这个框架不在当前环境中。这是代码，这是导致错误的时刻。这是我刚刚给您看的框架：当前环境包括这个局部框架，然后是全局框架。

所以，当我们查找名称 `y` 时，我们在这里找，没找到；我们在那里找，没找到。所以我们得到一个错误：`y` 不在全局帧中。

错误：一个环境是一系列帧。通过调用在这里定义的顶层函数创建的环境（在其中没有在 `def` 内的 `def`），由一个本地帧和一个全局帧组成。你不能从这个函数的主体中引用这个 `y`，它是本地的。

现在与我们在 `make_adder` 中看到的进行对比，其中 `adder` 的主体实际上可以引用 `n`，因为它是嵌套的。

我们将以一个大例子结束今天：函数组合。

我要做的是：
定义一个平方函数：
```python
def square(x):
    return x * x
```

我要定义一个三倍函数，它只是返回 3 倍的 $x$：
```python
def triple(x):
    return 3 * x
```

这里有一些简单的函数。但现在，我要定义一个高阶函数，叫做 `compose1`，它接受两个不同的函数，每个函数都接受一个参数：

```python
def compose1(f, g):
    def h(x):
        return f(g(x))
    return h
```

它定义了一个新的函数 `h`，也是在一个参数上，它返回调用 `f` 在调用 `g` 在 $x$ 上的结果。这是将函数 `f` 和 `g` 组合成一个新函数 `h` 的方式，它将返回。

怎么工作呢？我们可以将其实方。我们可以把 5 变成三倍。现在，我们要定义一个新的混合函数叫做 `squiple`，它涉及将 `square` 和 `triple` 组合在一起：

```python
squiple = compose1(square, triple)
```

所以，`squiple` 是一个函数，当我对其调用 5 时，5 首先被三倍，然后再被平方：$15 \times 15 = 225$。

```python
squiple(5)
```

所以 `compose1` 非常通用，它接受任何两个函数并将它们组合在一起。

例如，我们还可以创建 `tripair`，通过将 `triple` 与 `square` 组合而成：

```python
tripair = compose1(triple, square)
```

所以，如果我们 `tripair(5)`，我们得到 75。因为我们平方 5，那就是 25，然后我们再三倍，我们得到 75。

我们甚至可以 `squadd`。什么是 `squadd`？这是通过组合 `square` 和 `make_adder(2)` 而创建的函数。这给了我们一个将 2 加到事物上的函数，这是平方。

如果我想要 `squadd`，比如 3，那么 $3 + 2 = 5$，然后这个平方是 25。

顺便说一下，你可以写一个调用表达式把这一切都做在一起：

```python
compose1(square, make_adder(2))(3)
```

让我们看看这个的环境图。

好的，我们有 `square`，有 `make_adder`，有 `compose1`。我们要调用 `compose1`，它定义了 `adder` 函数并返回它。现在我们把它传给了 `compose1`。`compose1` 把 `f` 绑定到 `square`，`g` 绑定到 `adder`，然后它会定义 `h` 并返回它。

我把所有东西都弄小了，这样它就能放下。那会发生什么？`h` 将调用 `f(g(x))`。`f` 是 `square`。首先，我们需要计算 `g(x)`，这涉及调用 `adder` 函数，其中 $k$ 绑定到 3，$n$ 是 2。所以这给出了一个返回值 5，它被传递到 `square`，返回 25。`h` 的答案是 25。所以，这就是整个表达式给你的东西。

让我们看看那张图片。这就是你刚刚看到的东西，只是我会加点注释。

所以，当我们评估整个调用表达式时，首先我们评估运算符。`compose1` 很容易评估，`square` 很容易评估，但这是一个涉及一些工作的调用表达式：我们对 2 调用了 `make_adder`，结果是一个 `adder` 函数。然后我们对 `square` 和 `make_adder` 调用的结果调用了 `compose1`，结果是这个 `h` 函数。`make_adder` 的返回值，即 `adder` 函数，被作为参数传递给 `compose1`。你可以在这里看到：`compose1` 就在这里，它有一个参数，`g` 是加法函数嘛。

好的，现在我们有 `h` 了，现在我们可以调用 `h`。当我们调用 `h` 时会发生什么？首先我们评估 `f(g(x))`，这涉及评估环境中的 `g(x)`。那么 `f` 是什么？这里；`g` 是什么？它在那；`x` 是什么？它在那。为了得到 `g(x)`，我得调用 `adder`。所以 $k + n$（`adder` 的主体）在这个环境中得到评估，这个环境有三个框架。$k$ 是什么？它在那；$n$ 是什么？就在那。所以，有两个不同的环境，每个环境的长度都是 3，它们一起帮助我们计算数字 25。

Lambda 表达式是评估为函数的表达式。

让我们进行一次演示。我们已经知道，我可以将某个值绑定到一个名字：

```python
x = 10
```

如果我能以相同的语法、一条赋值语句，绑定一个函数到一个名字，这不是挺好的吗？现在，我知道我可以通过在这里有一个评估为函数的东西来将一个名字绑定到一个函数。但如果我想要它是一个以前从未写过的新函数呢？我怎么做？

好吧，有人可能会认为我只需要写下我想要的那个函数的主体：我想让 `square` 成为一个计算 $x \times x$ 的函数。所以，到目前为止，我已经将 $x$ 绑定到 10。那么，`square` 绑定到什么了？它根本不是一个函数，它只是一个数字 100。为什么会这样呢？那是因为我计算了 $x \times x$ 以获取它的值，这就是我绑定给 `square` 的内容。

现在，Lambda 表达式允许你做的，就是实现我们一开始想要的：使用赋值语句，将一个接受某个我们称之为 $x$ 的参数的函数，绑定到名为 `square` 的名称上，并计算 $x \times x$ 作为其返回值：

```python
square = lambda x: x * x
```

现在这次，当我查看 `square` 是什么时，我发现它是一个函数。太好了！那这个函数做什么呢？让我们试一试看：

```python
square(4)
```

搞定了，太棒了！

所以 Lambda 表达式看起来像这样：整个东西都是一个 Lambda 表达式，它用于评估函数。我可以将该函数绑定到一个名称，以便稍后引用；或者我甚至可以在调用表达式中直接应用该函数，其中运算符是 Lambda 表达式，然后我对某个参数调用它：

```python
(lambda x: x * x)(4)
```

让我们看看刚才发生了什么。我写了 `x = 10` 试试，我写了 `square = x * x`。当我拥有那个赋值语句时发生的是，我写下了一个求值为数字的表达式，然后 `square = 100`。但第二次我尝试的时候，那个真正起作用的，我写下了一个求值为函数的表达式。那个 `lambda` 关键字引入了一个新的函数，以 Lambda 表达式的形式。

阅读 Lambda 表达式的方式是将其视为一个带有形式参数 $x$ 的函数，返回 $x \times x$ 的值。所以最终，人们会在你周围开始在非正式的谈话中使用 `lambda` 这个词，但是它们的意思是一个表达式，该表达式会被解释为一个可以以这种方式解释的函数。

重要的是要注意，Lambda 表达式中没有 `return` 关键字。这是表达式句的一个怪癖：你只需要在冒号后直接写下返回表达式，而不需要写 `return` 这个词。这限制了您只能将一个表达式作为您创建的 Lambda 函数的主体。

Lambda 表达式创建函数，但它们总是创建简单的函数，只是评估单个表达式而已。

一旦我完成了这个，我可以平方 4 得到 16，也可以平方任何我想要的书。

在 Python 中，lambda 表达式并不特别常见。用 def 语句更普遍，但总体来说，它们非常重要。在一些编程语言中，它们是完全基础的。在其他很长时间没有它们的编程语言中，它们开始出现，因为人们意识到 lambda 表达式是多么奇妙。

在 Python 中，lambda 表达式不能包含语句，因此，相对于它们的近亲 def 语句，它们有一些限制。只需注意，如果想在函数体内使用 while 语句，就不能使用 lambda，必须使用 def。

还有什么是 lambda 表达式与 def 语句之间的区别呢？让我们搞清楚。面对面的时刻到了。

在左边，我们有 `lambda x: x * x` 绑定到 `square`。在右边，我们有 `square` 的 def 语句版本。它们有什么不同和相同呢？

事实证明，它们几乎完全相同。两者都创建了一个具有相同域、范围和行为的函数。两个函数的父级都是定义它们的框架。创建函数的规则完全相同，无论是使用 lambda 还是使用 def。它们都将该函数绑定到名称 `square`。

它们以非常不同的方式执行此操作。首先创建没有名称的函数，然后在此处的赋值语句将该函数值绑定到名称 `square`，而在 def 语句中，这两件事情都会自动发生。创建一个名为 `square` 的平方函数，所有这一切都是执行 def 语句的副产品。

我们发现了一个区别。只有 def 语句赋予函数一种内在的名称。什么是内在的名称？就是你实际显示函数时看到的名字。如果我输入 `square`，它告诉我这是一个函数。它不叫 square，这与我以前输入 `def square(x): return x * x`，然后查看 `square` 的结果不同。

有一个小地方你会看到不同，那就是当你尝试查看函数值，并且它有一个名称时会发生什么。那被称为函数的内在名称。

现在，它们都以相同的方式用名称 `square` 引用。当你将它们放在表达式中时，所有相同的规则都适用，所以它们几乎是一样的。

但这一个差异确实改变了我们画环境图的方式。这个例子的环境图，包括我定义 `square = lambda x: x * x`，然后我在数字 4 上调用 `square` 的情况，会变成这样。我们把名字 `square` 绑定到函数。我们引入一个新的框架，在其上调用该函数，参数是 4。然后我们得到一个返回值是 16。名字 `square` 出现在这个框架中，这些是我们实际用来评估表达式的名字，这些是重要的。

在这里，我们不写 square，而是写希腊字母 $\lambda$。这意味着，当我调用这个函数并将所有信息复制到一个框架时，lambda 这个名字会一直存在。但这个名字其实也不重要。它只是帮助我们跟踪哪个框架是丰富的。

相比之下，当我定义 `def square(x): return x * x`，然后我调用 `square`，传入数字 4。我们得到了这个熟悉的画面，一个 `square` 被绑定到一个被称为 square 的函数。当我对应像 4 这样的值调用 `square` 时，我会得到一个包含 `square` 的框架。

一个微小的差异，实际上微不足道，但它伴随着这个东西在创建时有一个名字，而 lambda 直到赋值语句完成才有名字。

柯里化，函数柯里化是操作函数的一种方式。在过去的两次讲座中，我已经为你实现了一个 `make_adder`。这已经成为一种传统，所以让我们再做一次。

定义 `make_adder` 接受一个参数 $n$，返回一个接受参数 $k$ 的函数，返回 $n + k$。

注意，我现在使用了 lambda 表达式，而不是定义一个名为 `adder` 的函数，但效果是一样的。

所以，一旦我有了 `make_adder`，我可以编写一个调用表达式，其中运算符本身就是一个调用表达式。`make_adder(2)` 给我返回一个将 2 添加到事物的函数。我把 3 传给那个函数，然后再加 2 得到 5。

所以，我就这样调用 `make_adder`。实际上需要两次调用才能得到一个数字，与之相反的是，我们有一个 `add`，它是一个直接接受两个参数并返回它们和的函数。

现在，`make_adder` 和 `add` 之间是一个普遍的关系。它存在于那些接受一个参数并返回函数的函数，以及接受多个参数并只返回最终答案的函数之间。所以我们可以用代码表达这个普遍的关系。

我会定义一个叫 `curry2` 的函数。2 的意思是我传入的函数接受两个参数。它的作用是定义一个函数 $g$，该函数接受一个参数。定义了一个函数 $h$，它也接受一个参数，不同的参数。实际上，$h$ 的作用是返回对 $x$ 和 $y$ 调用的 $f$。$g$ 返回 $h$，$curry2$ 返回 $g$。

现在，我做了什么呢？我创建了一个名为 `curry2` 的函数，将接受两个参数的函数，比如 `add`，转换为高阶函数，比如 `make_adder`。

这是 `add` 函数。如果我想创建一个等效于 `make_adder` 的函数，我只需要对 `add` 函数进行柯里化。好的，现在我有一个行为类似于 `make_adder` 的东西，这意味着我可以通过在数字 3 上调用 `m` 来创建 `add_three`。现在，我有一个将 3 添加到事物的函数。

可以将 `curry2` 表达为嵌套的 lambda 表达式。这是一个接受 $f$ 的函数，返回一个接受 $x$ 的函数。它返回一个接受 $y$ 的函数，并返回 $f(x, y)$。就像以前一样，我可以将我的新查询应用于 `add`，然后通过高阶函数添加事物。

所以，这是一般的关系。柯里化是将多参数函数转换为一个单参数高阶函数的行为，该函数返回一个接受其余参数的函数。

柯里化不是哈斯凯尔·柯里发现的，而是莫西斯·肖恩芬克尔发现的。后来被哈斯凯尔·柯里重新发现并变得更受欢迎，所以有些人认为它应该叫做肖恩芬克尔化。
