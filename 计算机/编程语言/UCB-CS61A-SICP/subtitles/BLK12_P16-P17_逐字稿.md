## P16 Lecture 16 Iterators-cn

使用迭代器可以隐式地表示顺序数据。

迭代器是许多编程语言中的常见接口，在 Python 中，它们用作访问许多不同容器的元素的一种方式。容器可以提供一个迭代器，迭代器反过来以某种顺序提供对其元素的访问。

内置函数 `iter` 和 `next` 分别创建和推进迭代器。所以，`iter` 接受任何可迭代的东西，这可以是一个容器或你自己创建的东西，它返回可迭代值的元素的迭代器。`next` 是一个内置函数，它返回迭代器中的下一个元素。

假设我有一个容器，一个包含 3、4 和 5 的列表。如果我在列表 $s$ 上调用 `iter`，我会得到一个迭代器 $t$。这个迭代器知道列表的内容，它还有一个标记指示着下一个元素。所以，你可以把迭代器看作是在某个序列中的一个位置。它让你访问该位置及其之后的元素。

如果我在 $t$ 上调用 `next`，我会得到数字 3。由于调用 `next` 的结果，这里的标记会前进，这意味着下一次我调用 `next` 时，我将得到 4 而不是 3。而且由于我已经调用了两次 `next`，我已经前进了两次，现在标记设置为 5。

如果我为同一个容器创建第二个迭代器，那意味着我有了同一列表的第二个标记。所以，$u$ 是一个还没被移动过的迭代器。如果我在 $u$ 上调用 `next`，我会得到数字 3。现在，$t$ 并不因为我创建了 $u$ 就忘记了它的位置。所以如果我问 $t$ 下一个是什么，我会得到数字 5。而且迭代器会移动到最后一个元素，说它已经到了列表的末尾。我仍然可以请求 $u$ 中的元素。所以如果我问 $u$ 下一个是什么，它会说 4。所以，$t$ 和 $u$ 正在迭代相同的值，但在它们即将给你的位置上是独立的。

好的，让我们建立一个比你之前看到的稍微复杂一点的列表。这是一个嵌套列表。如果我要求列表中的下一个值，我会得到一个错误。那不是 `next` 的作用。首先，`next` 期望你已经创建了一个在某个容器的内容上进行迭代的迭代器。在那时，我可以请求 $t$ 的下一个值，这将给我子列表 `[1, 2]`。所以，它只是给我正在迭代的列表的索引 0 处的元素。如果我再次请求下一个 $t$，我会得到一个不同的值。

如果你想要迭代器中的所有值，你可以把它们列出来。现在在这里，你看到我们只得到了剩下的值。我们已经使用了列表 `[1, 2]` 和数字 3。所以，当我构建一个迭代器中剩余内容的列表时，我只得到了数字 4 和 5。现在，如果我在这个时候请求 $t$ 中的下一个元素，我会得到一个错误，一种特殊的错误叫做 StopIteration（停止迭代）。这就是告诉你已经到达末尾的方式，Python 会引发一个 StopIteration 异常。

咱们聊聊字典遍历吧。你可以得到字典内容的多重视图，它们是不同的对象，都可以被遍历。可遍历的值是任何可以传递给内置函数 `iter` 的值，以生成迭代器。而迭代器是从 `iter` 返回的，可以传递给内置的 `next` 函数。所有的迭代器都是可变对象，在调用 `next` 时，它们会变异以指向下一个元素。

字典及其键、值和项都是可遍历的值。所有这些都可以传递给 `iter`，并且生成的迭代器可以传递给 `next`。字典中的项目顺序是它们的添加顺序。这对于最新版本的 Python 是正确的，从 Python 3.6 开始。

然而，在旧版本的 Python 中，字典中的项目以任意顺序显示。因此，字典曾被称为无序的键值对集合。但现在它们是有序的。虽然在编写 Python 代码时，最好记住根据人们用于运行程序的 Python 版本，字典的顺序可能不可靠。但是在我的示例中，我会假设我们使用的是 Python 的最新版本，因此字典将按照构造它们的方式进行排序。所以如果我有一个包含三个键和四个值的字典，1 绑定到 1，2 绑定到 2，3 绑定到 3，然后我添加第四个值，0 绑定到 0，那么我期望迭代键会给我 1、2、3，然后是 0，因为 0 是最后添加的。

这是我如何迭代键的方式。我说我要通过调用 `iter` 函数获得一个迭代器来遍历键。如果你不说 `d.keys()`，而是直接说 `d`，你会得到相同的效果，你迭代键。而这个 $k$ 是一个键的迭代器，这意味着如果我要求下一个，我会得到 1，然后是 2，然后是 3，然后是 0。

如果相反的，我想要遍历字典中的值，我会要求值。这个对象是一个可迭代对象，按照字典构造时的顺序提供对所有值的访问。接下来的值是 1，然后是 2，然后是 3，最后是 0。

最后，我可以请求字典中的项。这些是表示为元组的键值对。第一个是 1，我们在一个包含两个元素的元组中获取键和值，然后是 2，然后是 3，最后是 0。

有许多遍历字典内容的方法，而 Python 设计的方式只有一个字典 $d$，我可以通过请求键的值或项来访问它的不同视图。而且我可以获得其中任何一个的迭代器。

现在，一个有趣的事情要注意的是，如果我有一个字典，而且我已经构建了一个键的迭代器，而且我正在遍历这些键的中间，然后我改变了字典。现在的情况是迭代器无效了。因此，我看到了这个错误，“字典在迭代过程中改变了大小”。它说我不能再使用 $k$ 了，因为在我使用 $k$ 的时候，字典已经被改变了。所以我们的字典现在看起来是这样的。

如果我在遍历键的时候只是改变其中一个键的值，所以这里是 1、2，然后我把 0 改成 5，我可以继续遍历，因为我没有改变字典的形状或结构。我只是改变了其中一个键的值。但如果字典的大小改变了，那么我就不能使用我构建的任何迭代器。相反，我需要创建新的。而且对于键、值或项都是如此。

`for` 语句用于遍历可迭代的值，它们也可以遍历迭代器本身。比如说，我有一个范围是从 3 到 6。这个范围的内容是数字 3、4 和 5。如果我遍历这个范围，我可以看到所有的元素。而且如果我再次遍历，我会再次看到所有的元素，因为我没有改变范围。

迭代器有点不同。所以，如果我从我的范围得到一个迭代器，它在范围中有一个特定的位置，每次我调用 `next` 时都会改变。所以我可以为迭代器的其余元素提出请求。但它不会打印出 3，因为 3 被跳过了。相反，它将只打印出 4 和 5。

现在，`for` 语句也会在迭代器内移动标记，将其推进到序列的末尾。所以我仍然有我的范围。我将构建一个从最开始开始的新范围迭代器。对于 $r$ 中的每个元素，我将打印出来。我把一个范围迭代器传递给 `for` 语句进行处理。现在范围迭代器里什么都没了。如果我再次迭代它，我什么都看不到，因为我已经到达 $r$ 的末尾了。这是在 `for` 语句中使用迭代器的另一个结果。

所以总结一下，如果我在 `for` 语句中使用迭代器，我仍然可以遍历所有元素直到到达末尾。但这会推进迭代器，以至于我不能再次使用它。另一方面，如果我正在使用可迭代对象，比如范围本身，在 `for` 语句中每次使用它时，我可以从头到尾遍历整个内容，而不用担心任何变化。

处理序列和其他可迭代值的大量处理都使用内置函数，这些函数接受一个可迭代值并返回一个迭代器。许多内置的 Python 序列操作返回计算结果的迭代器，以惰性方式计算。惰性计算的意思是只有在被请求时才计算结果。因此，解释器准备计算任何所需的内容，但实际上只有在该值将被使用时才进行计算。

让我给你演示一些例子。有一个叫做 `map` 的函数，它接受另一个函数和一个可迭代对象，并将该函数应用于可迭代对象中的每个元素。但是，它不会立即应用，而是返回一个迭代器。一个迭代器遍历可迭代对象中每个 $x$ 的值的函数。

还有另一个内置函数 `filter`，它接受一个谓词函数和一个可迭代对象。如果 `func(x)` 返回真值，它就遍历 $x$ 和可迭代对象。

`zip` 接受两个可迭代对象，它遍历共同索引的 $(x, y)$ 对。

`reversed` 按照序列中 $x$ 的反向顺序遍历。所有这些都返回迭代器，并且这些迭代器每次调用 `next` 时产生这些值。

如果你想要查看迭代器的全部内容，你可以通过调用 `list`、`tuple` 或 `sorted` 将结果元素放入一个新的容器。`sorted` 函数创建一个包含可迭代对象中所有元素的排序列表。

咱们来演示一下。所以，如果我创建一个列表 `['b', 'c', 'd']`，我可以通过对 `bcd` 中的每个元素调用 `upper` 方法来将它们全部变成大写。通过在 lambda 函数上调用 `map`，计算 `bcd` 中每个元素的大写版本，我也能达到类似的效果。但我得到的不是列表大写的 B、大写的 C、大写的 D，而是一个 map 对象，它是一个迭代器。所以如果我给它起个名字 $m$，然后我可以要求下一个大写字母，它会是 B，然后是 C，然后是 D，然后我们完成了。

现在，这些结果是如何计算的相当有趣。咱们定义一个叫 `double` 的函数，它接受一个 $x$，然后准确地在 $x$ 翻倍的时候打印出来。$x$ 被翻倍了，现在是两倍的 $x$ 了，就是两倍的 $x$。如果我在列表 3、5、7 上映射 `double`，我得到一个映射对象，你注意到什么都没被打印出来。

所以我给这个东西起个名字 $m$，然后我要求 $m$ 中的下一个元素。在那一瞬间，它把 3 翻倍，得到数字 6。直到我要求下一个元素时，它才把 5 翻倍，得到数字 10。最后，如果我在要求之后的下一个元素，它计算得到数字 14。所以这里的重点是，`double` 不会立即应用于 3，然后是 5，然后是 7，而是惰性地应用。只有当我们要求下一个元素时，函数才会被应用并计算结果。

当我调用 `map` 时返回的 map 对象可以传递到另一个序列处理函数中。例如，假设我取从 3 到 7 的范围，我在该范围上映射 `double`，并将其称为 $m$。然后我创建一个过滤函数，该函数以值 $y$ 为参数，并在 $y$ 大于或等于 10 时返回 True。我可以使用 $f$ 过滤 map 对象，并从结果构建新的迭代器。

注意我还没有对任何东西进行加倍。如果我问在从 3 到 7 的范围内，下一个加倍的元素是什么至少是 10，那么它会将 3 加倍以找到结果是 6，这是错误的，根据我们的过滤函数。所以它将 4 加倍得到 8，这也是错误的。然后它将 5 加倍得到 10，而 10 大于或等于 10，因此返回这个值。所以你可以看到它确切地做了它需要做的工作，以便返回加倍值序列中大于或等于 10 的下一个元素。但它没有做比这更多的工作。如果我要求下一个元素，那么它只会将其中一个加倍，找出它是否大于或等于 10，然后将其返回。而且如果我列出 $t$ 的内容，它会发现没有剩下的东西，因为这个范围只有 3、4、5、6，6 加倍是 12，然后我们就完成了。

所以从头开始，如果我想过滤映射双倍到范围 3 到 7 的结果的所有元素，我将得到一个包含值 10 和 12 的迭代器，我可以将它们放入一个列表中。将它们放入列表意味着它将一直运行这个过程，直到我到达末尾的空迭代器，然后返回值 10 和 12。它必须做所有的工作才能达到这一点，它必须将每个数字 3、4、5 和 6 都加倍。

使用这些迭代器来计算详尽的答案是可能的。但是如果你不要求值列表，而是逐个要求元素，那么它们将被懒惰地计算。懒惰计算主要方便，因为它允许你指定如何计算大量的值，但如果你实际上不需要所有这些值，那么你就不必计算它们。

但是，有一些需要小心的地方。例如，如果我创建一个列表，前后相同，然后询问该列表的反向版本，我得到的是一个列表反向迭代器对象。所以仅仅说 $t$ 的反向是否等于 $t$ 将得到 False 的结果。现在，如果我列出反向迭代器的所有内容，那就等于 $t$。但你要避免将列表和迭代器应用于相等性，因为这会得到 False。你需要比较一个列表和一个列表。

咱们谈一谈什么时候会用到迭代器。通过 `next` 处理迭代器，或者通过 `for` 语句或偶尔使用 `iter` 处理可迭代对象的代码，在数据表示方面几乎没有太多的假设。

这意味着从列表更改数据表示方式为元组、映射对象、`dict_keys` 对象或类似对象，都不需要重写任何代码。

这是数据抽象的一个概念。如果你只是把某物当做可迭代的或迭代器，而不用担心它到底是什么，那么当数据的表示方式发生变化时，你的代码仍然能够工作。这意味着其他人更有可能能够在他们的数据上使用你的代码，即使数据有些奇怪的格式。

迭代器还将一个序列和该序列中的位置捆绑在一起，作为一个对象。这在将对象传递给其他函数时非常方便，因为你始终保留着位置。这对于确保（例如）序列的每个元素仅被处理一次非常有用，因为即使你将该序列传递给其他函数，如果它是一个迭代器，调用 `next` 的人正在推进迭代器，对于再次调用 `next` 的任何其他函数也是如此。因此，特定的值只会被 `next` 返回一次。

最后，传递迭代器限制了可以对序列执行的操作，只能请求下一个值。我想这可能很方便，因为你不必担心某个函数改变序列，除了推进迭代器。

生成器是一种特殊类型的迭代器，就像映射对象是一种特殊类型的迭代器。生成器的特殊之处在于它是从生成器函数返回的。

生成器函数看起来像普通函数，这里有个例子。不同之处在于它使用 `yield` 关键字而不是 `return` 来返回值。

```python
def plus_minus(x):
    yield x
    yield -x
```

所以我知道这是一个生成器函数，因为它在某个地方使用了 `yield`。

当我对其调用 `plus_minus(3)` 时，我得到一个生成器对象。这个生成器是一个迭代器，意味着我可以遍历通过 `plus_minus` 产生的值。

```python
t = plus_minus(3)
next(t)
# 3
next(t)
# -3
```

如果我在 `t` 上调用 `next`，我会得到 3。但我可以再次调用 `next(t)` 以获得 -3。所以你可以看到这两个 `yield` 语句都被执行了。

`t` 本身是一个生成器对象，它的工作是帮助迭代调用的函数产生的所有值。

所以生成器函数是一种产生值而不是返回值的函数。普通函数只返回一次，但生成器函数可以多次 `yield`。生成器是在每次调用生成器函数时自动创建的迭代器。

这是我们调用加减并得到一个生成器的调用表达式。当调用生成器函数时，它会返回一个生成器，该生成器会迭代函数的产出。

这里有另一个例子。假设我想返回仅包含偶数的迭代器。我提供整数的起始和结束点，但我想确保我实际上是从大于或等于起始的偶数开始的。

所以下一个偶数是起始加上 0 或 1，这取决于起始是偶数还是奇数。虽然这个偶数小于 $n$，但我将生成它。然后我会将偶数增加 2，得到下一个偶数。

```python
def evens(start, end):
    even = start + (start % 2)
    while even < end:
        yield even
        even += 2
```

所以当我调用 `evens(2, 10)` 时，我得到一个生成器对象，它会给我 2、4、6、8，然后停止迭代，表示我们完成了。如果我列举出一到十之间的所有偶数，它仍然从 2 开始，一直到但不包括 10。

那么这里实际上发生了什么？当我通过调用生成器函数创建一个生成器时，我甚至还没有开始执行这个函数的主体。直到调用 `next` 时，才开始执行主体，而且它会一直执行，直到达到 `yield` 语句。在这一点上，该数字将作为此迭代器中的下一个元素被产生。

而在这种情况下，执行在那个 `yield` 处暂停，但记住函数执行的所有环境，以便下次调用 `next` 时可以继续之前的位置。

所以下一步它将要做的是将 2 添加到 `even`，继续返回 `while` 语句，看到 `even < end`，然后产生下一个偶数。

生成器的强大之处在于您可以设置任何所需的计算，而且该计算将被懒洋洋地执行。所以当有人要求下一个元素时，然后你继续，直到达到下一个 `yield`。但如果没有人要求所有元素，那么你就不必继续计算所有东西。你只需在那里暂停，直到需要下一个值。

生成器函数返回生成器，但在执行过程中，它们经常处理迭代器。而这经常发生，以至于在 2012 年发布的 Python 3.3 中，他们添加了一条新语句：`yield from`。它允许生成器从其他迭代器中产生所有元素。

所以一个 `yield from` 语句从迭代器或可迭代对象中产生所有值。

例如，假设我想定义一个名为 `a` 的函数，然后变成了 `b` 函数，它接受两个可迭代对象或迭代器，并返回第一个中的所有元素，然后是第二个中的所有元素。

我可以这样写：
```python
for x in a:
    yield x
for x in b:
    yield x
```

但有一种更简单的方法，我只需写：
```python
yield from a
yield from b
```
这两者是完全等效的。

所以你可以把 `yield from` 看作是仅仅是写下一个 `for` 语句的简化形式，其中你遍历 `a` 中的所有元素并将它们 `yield` 出来。但它确实允许你避免为这个序列中的每个项目命名，这只是为了清理你的代码。

这里有另一个例子。假设我们想要定义一个从 5 倒数的生成器函数。我可以递归的方式来做。如果 $k > 0$，那么我就 `yield k`，然后通过调用 `yield from countdown(k - 1)` 来 `yield` 所有的值。

```python

        yield k
        yield from countdown(k - 1)
```

所以如果我从 $k$ 开始倒数，如果 $k > 0$，我肯定想先 `yield k`。如果我写错了，只写了 `yield countdown(k - 1)`，我从中得到的迭代器的第二个元素实际上只是另一个迭代器。所以从 3 开始倒数起初是没问题的，但接下来我会得到一个生成器对象，这不是我预期的，我希望得到数字 2。

所以为了得到数字 2 和 1，我必须写一个 `for` 语句并 `yield` 语句中的每个元素。然后如果我倒数，我得到 3，然后 2，然后 1。

要做到这一点的简便方法是，而不是写一个 `for` 语句，我只是写 `yield from countdown(k - 1)`。

我们以一个稍微复杂的例子结束。我可以生成字符串 $s$ 的所有前缀，这里我假设 $s$ 是一个字符串，但实际上可以是任何可迭代对象。如果它不是空的，那么我将生成所有 $s$ 的前缀，但不包括最后一个元素。然后我会生成字符串 $s$ 本身。

def substrings(s):
