咱们看一下这个：
```python

    print('delayed')
    def g():
        return arg
    return g
```
这是一个很常见的模式，你在一个 `def` 语句内部有另一个 `def` 语句。我定义了一个函数 `g`，然后我返回它。发生的情况是，当我调用 `delay` 时，会创建一个新的函数，而这个函数 `g` 的父框架是 `delay` 框架，它是当前环境的第一个框架，当 `g` 被创建或定义时。

这意味着每当我调用 `g` 时，然后 `g` 的主体被执行，并且可以引用在其封闭范围内的名称。这意味着在 `g` 被定义时在 `delay` 框架中绑定的名称。所以这个 `arg` 指的是在定义 `g` 时在 `delay` 中的 `arg`。

所以如果我在 `delay` 上调用 `delay`，然后调用那个，再在 6 上调用那个，然后调用那个：
```python

```
这里发生了什么？记住，这是一个大的调用表达式，所有部分在我们评估整个表达式之前都需要被评估。

我们谈过这个，嵌套 `def` 语句中的名称可以引用它们的封闭范围，因此 `arg` 将有意义。它将意味着我们调用 `delay` 时绑定的内容。`delay` 是一个接受任何参数并返回一个返回该参数的函数的函数。

我们对延迟有了一些概念。让我们简单过一遍，弄清楚调用这个调用表达式到底意味着什么。

这个调用表达式有一个复杂的运算符，就是这整个东西，直到但不包括最后一组括号：

我们必须首先评估这里下划线部分的所有内容，然后我们将在最后一刻将该函数应用于 0 个参数。

那是什么？一个具有复合运算符的调用表达式。现在，我们有了除了这个括号之外的一切，都是我们需要评估的东西：

然后我们将这个应用到数字 6。

我们得到了一个返回 `delay` 函数的函数。顺便说一下，当我在调用 `delay` 时，它会打印出 `'delayed'`。这就是为什么我们有一个打印输出 `'delayed'`。

然后我要调用 `g`，它会给我返回 `delay` 函数。

那么 `print(delay(print)()(4))` 呢？我们必须经历类似的过程。这是调用带参数的打印。这是延迟打印的值，调用它，然后对其进行调用。在我们弄清楚我们要打印什么之前，我们必须弄清楚这个调用表达式评估为什么。

我们将在 `print` 上调用 `delay`，这将打印 `'delayed'` 并给我一个返回 `print` 函数的函数。我调用那个，那挺好的，所以现在我得到了打印函数。我在数字 4 上调用 `print`，然后我看到数字 4。然后整个表达式的值就是 `print(4)` 所求得的值，也就是 `None`。这就是我打印出来的东西，整个表达式的值就是 `None`。

让我们再做一个，练得越多就会越好。所以同样的格式，从 `operator` 模块导入 `add` 和 `mul`，然后定义 `square`。但这里有一个新功能：
```python
def pirate(arg):
    print('matey')
    def plunder(arg):
        return arg
    return plunder
```
定义一个名为 `pirate` 的函数，它打印 `'matey'`，然后定义一个名为 `plunder` 的参数并返回该参数，然后返回 `plunder`。

我们在这里有相同的基本结构，但这是一个具有不同行为的不同函数。并不是因为名称不同，而是因为内部的 `def` 语句的内容。内部的 `def` 语句表示：无论何时调用 `plunder`，我都会返回其参数。这并没有以任何方式延迟，这只是说，我打劫了什么，我立刻就得到了那个东西。`plunder(arg)` 就是 `arg`。

实际上，由于 `plunder` 使用了名为 `arg` 的名称，我们永远无法在封闭的范围内引用此 `arg`，因为查找名称的过程总是在当前环境的第一个框架上进行。如果我们查找名称 `arg`，我们将立即找到它，而不会查找父框架。

如果我们添加 `pirate(arg)(square)(4) + 1` 会发生什么？我们将把这个求值结果添加到数字 1 上。

让我们看看，我们有 `pirate(arg)(square)(4)`。我们要对数字 4 应用某些东西。为了弄清楚那是什么，我们对 `square` 应用某些东西。我们对 `square` 应用的是从调用 `pirate` 对 3 返回的内容。我们的第一个任务是弄清楚 `pirate(3)` 返回什么。

现在正如我所说，名称将被评估为在当前环境的最早框架中绑定到该名称的值。特别是，名称 `arg` 将始终评估为在 `plunder` 框架中绑定到它的值。每当抢劫被调用时，我们就会得到被调用的东西，我们永远也用不到这个参数。

`pirate` 函数的真正作用就是始终返回标示函数或返回传递给它的任何参数的函数。

如果我调用 `pirate(3)`，我得到的是一个函数，它将评估为我传入的任何内容。如果我传入 `square`，那么整个过程就会评估为 `square` 函数。当我把 4 平方时会发生什么？我得到 16。我把那个加到 1 上得到 17。

所以这就是恒等函数。整个式子求值是平方，平方 4 得 16。每次我调用 `pirate` 时都会打印出 `'matey'`，所以这就是为什么这里有 `'matey'`，然后是 17，但整个式子求值为 17。

那么 `pirate(pirate(pirate))(5)(7)` 呢？让我们来看看。

首先，我们要对 7 应用一些东西。无论是什么，我们首先要通过将其他东西应用于 5 来获取它。这个东西是什么？

首先，我们要应用 `pirate`，但我们要将其应用于什么？无论我们通过在 `pirate` 上调用 `pirate` 得到什么，这是我首先要评估的最内层的东西。

调用 `pirate` 函数得到的是恒等函数（identity function）。当然，每次调用 `pirate` 时都会在交互输出中打印出 `'matey'`。所以这给了我一个恒等函数。

我再次调用 `pirate` 函数，这给我另一个恒等函数和另一个 `'matey'`。然后我对其应用于 5，这意味着我得到了数字 5。

到目前为止，我有 `'matey'`、`'matey'`，然后整个运算表达式在这里计算为数字 5。我试图对数字 5 调用 7。5 不是你可以调用的那种东西，你只能调用函数，你不能调用整数。这就是为什么我们会得到一个错误。整个表达式没有值，因为整个表达式评估为错误。

最后一个例子，我想到的我最喜欢的之一：`horse(mask)`。
```python
def horse(mask):
    horse = mask
    def mask(horse):
        return horse
    return horse(mask)

mask = lambda horse: horse(2)
horse(mask)
```
它说：我要 `def horse(mask)`，作为一个函数，该函数将 `horse = mask`，并 `def mask(horse)`，它返回 `horse`。最后，它返回在 `mask` 上调用的 `horse`。

`mask` 到底是什么？`mask` 是一个接受参数 `horse` 并在两者上调用 `horse` 的函数：`mask = lambda horse: horse(2)`。然后我们评估在 `mask` 上的 `horse`。

这里的整个重点是，`horse` 和 `mask` 这两个词在不同的环境中意味着不同的东西。我们必须记住我们在哪里，在每次返回值时返回到哪里，并确保在每个步骤中调用正确的函数。

假设我们有一个绑定到名为 `horse` 的函数的变量，该函数接受 `mask` 作为参数；我们还有一个绑定到在此创建的 lambda 函数的 `mask`，该 lambda 函数接受一个名为 `horse` 的参数。这两者的父级都是全局作用域。

现在，我们在 `mask` 上调用 `horse`，这意味着我们正在使用这个作为参数调用这个函数。调用 `horse` 意味着我们引入一个新的作用域，在这个作用域中我们复制函数的名称。我们给新的作用域贴上标签，并将该函数的形式参数绑定到传入的实际参数。

因此，我们将来自这里的名称 `mask` 赋给传入的参数。我们传入了全局作用域中 `mask` 的值，是这个 lambda 函数。所以，它在这里绑定了 `mask`。现在我们有了 `mask`，表示在当前环境的第一个帧中的这个 lambda 函数。

现在我们执行函数的主体，它说弄清楚 `mask` 的含义并将名字 `horse` 绑定到它上面。赋值语句总是改变当前帧中的某些东西，就是现在这个，所以我们将 `horse` 绑定到当前等于 `mask` 的任何内容。

接下来，我们定义 `mask` 函数。一个 `mask` 函数和一个 `def` 语句有两个不同的步骤：它创建一个新函数，其父级是当前帧；然后，作为第二步，它将名称 `mask` 重新绑定到该函数。这个绑定总是发生在当前帧中。

我们创建一个名为 `mask` 的新函数，参数是 `horse`，父级是 f1，因为我们目前在 f1 中。我们在当前帧中将名称 `mask` 绑定到该函数。现在 `mask` 是这个函数，叫做 `mask`，在这里我们定义的那个函数。在同一帧中，我们不能让相同的名称表示两个不同的东西，得把旧的绑定去掉。现在它没了。

到目前为止，我们做了所有的事情，除了返回语句。它说返回 `horse(mask)`。现在为了做到这一点，我们必须弄清楚 `horse(mask)` 的值是什么。我们必须弄清楚当我们对 `mask` 参数调用 `horse` 函数时会发生什么。

现在是哪个 `horse` 函数和哪个 `mask` 参数呢？我们要记得我们在这一帧，也就是 `horse` 框架。我们正在评估 `horse` 函数，所以我们处于 `horse` 框架中。我们弄清楚当前 `horse` 意味着这个 lambda 函数，而 `mask` 意味着这个 `mask` 函数。

我们用这个作为参数调用 lambda 函数。调用 lambda 函数意味着我们引入一个新框架，该框架名称为 $\lambda$，其父级为全局，因为 lambda 函数的父级是全局的。我们将形式参数 `horse` 绑定到我们传入的参数。

每当我们在该 lambda 函数的主体中使用 `horse` 时，我们会讨论这个：这是我们传入的 lambda 函数，当我们执行它的主体时会发生什么？我们只是返回带有参数 2 的 `horse` 的值：`horse(2)`。

哪个 `horse`？这是当前的帧。这是这个 `horse`，也就是这个函数。我们在参数 2 上调用这个函数，这意味着创建一个新的帧。`mask` 框架有一个父级 f1，因为每当我们调用 `mask` 函数时，这就是父级。它的参数 `horse` 被绑定到 2，就像我说的一样。

`mask` 函数做什么呢？`mask` 函数只是返回 `horse`。`horse` 是 2，所以我们返回 2。

现在我们在哪里返回 2？我们上次调用的是这个 lambda 函数，它试图弄清楚 `horse(2)` 是什么，然后返回那个值。我们刚刚弄清楚，在那个上下文中，`horse(2)` 的值是数字 2。

现在我们需要把它返回。我们把这个数字 2 返回到哪里呢？我们当时正在评估 `horse(mask)` 的主体，我们试图返回调用 `horse(mask)` 时得到的任何东西。现在我们知道那是数字 2。

所以我们可以返回那个，然后就完成了。我们发现，以这种方式称呼 `horse(mask)` 不会引起任何错误。它会生成这种环境，并且评估为数字 2。

那么我怎么样设置 `kept`，让它是所有不是 3 的数字呢？我得一次处理一个数字。也许我会把它加到 `kept` 里，这看起来是合理的。

让我们看看会发生什么。231 和 3 进来了。现在 $n$ 被绑定到 23，最后被绑定到 1，1 不是 3。所以现在 `kept` 不再是 0 了，它是 1。

然后我再次进行，跳过 3，再次进行。第一步，将与持续相关的 2 添加到与 `kept` 相关的 1 上。我应该得到 21，但我没有，我把 2 和 1 加在一起得到了 3。

好吧，所以这是错误的。有问题，因为我需要把 2 和 1 拼在一起，而不是得到 3。

那么，如果我把 `kept` 乘以 10 呢？通过例子看看是否正确。

在这个例子中，`kept` 是 0，`last` 是 1。所以我们得到 `kept = 1`，然后在下一次迭代中，3 我们跳过。下一次迭代，`kept` 仍然是 1，`last` 是 2。这将计算 12，12 不等于 21，这是倒过来的。

这样是不对的，但通过一个例子来做会让你试试。如果最后一个乘以 10 呢？

我们来看看它是否有效。第一次循环，`kept` 是 0，`last` 是 1，所以 `kept` 现在是 10。然后我们再次循环，跳过了 3，`last` 现在是 2，`kept` 是 10，这给了我们 10 加上 20 是 30。

那可不是 21，我得试试别的。我真正想要的是加 20 和 1 得到 21。所以当 `last = 1` 时，我想要乘以 1；当 `last = 2` 时，我想要乘以 10 以得到 20。

我该怎么做呢？然后你得想出一个策略。

那么做的一种方式是将 10 提高到已经在 `kept` 中的数字的幂。这意味着你要追踪 `kept` 中有多少位数字，然后将上一次的结果乘以 10 加上这次的数字。这在这个情况有效。

第一次循环时，上次的结果是 1，数字是 0，现在 `kept` 是 1，很好。下一次循环时是 3，我们跳过它。下一次循环时，`kept` 是 1，上次的结果是 2，数字是 1，这一项是 20，所以我们将 20 和 1 相加得到 21。

成功了。

接下来，检查一个稍微复杂的例子。如果数字是 4 会怎么样呢？那么我们会想要 231，我们想要的是通过得到 $1 + 30 + 200$，我们不再跳过 3 了。

能做到吗？当然。首先是 $1 \times 1$，然后是 $3 \times 10$，最后是 $2 \times 100$。给我 231。

现在有一个创造的时刻把我们带到了这一点：我们必须考虑一个建立数字序列的策略，通过乘以一些 10 的幂。所有这些问题都有一些发明的元素，但如果你从一个合理的结构开始，那么你只是玩弄一些能够完成所有工作的代码，而且你可以通过例子来解决它。

现在一旦你解决了它，确保你返回的是正确的东西。`kept` 真的是 20 或 231，而且确保其他的例子也能工作。所以值得一试，逐步追踪这个较长的例子，确保你没有漏掉重要的情况。

这是实现函数的一种策略。

现在，你可能会想出一个完全不同的解决方案，那也没关系。如果你在这里不知道接下来该做什么，但你想：与其是 21，我每次都除以 10，得到 2.1，然后最后我得弄清楚怎么把 2.1 变回 21。你可以通过乘以 10 来做到这一点。这仅适用于最简单的例子，在一般情况下，你必须乘以 $10^{\text{数字位数}-1}$，以便将小数点移到正确的位置。然后你有一个浮点值，所以你需要将其四舍五入。这样也能解决问题。

装饰器是 Python 的一个特性，利用高阶函数。这就是概念。

我们先从一些普通的函数开始。我们来算个平方，并对从 $k$ 开始以 1 为起点、$n$ 为终点的平方求和：

```python
def square(x):
    return x * x

def sum_squares_up_to(n):
    k = 1
    total = 0
    while k <= n:
        total, k = total + square(k), k + 1
    return total
```

当 $k$ 小于或等于 $n$ 时，将其加到总和中，并改变 $k$。因此，我们将对当前的 $k$ 进行平方，然后将 $k$ 绑定到 $k + 1$。然后我们将返回总和。

所以我们能算 12 的平方，还能计算平方加到 5 的总和，结果是 55。

我跟你说过这个 trace 装饰器。装饰器是指这个东西，看起来像是 `@` 然后是一个名字。当我用它，然后把某个东西平方时，我看到在值返回之前有东西被打印出来。所以这第一行在被调用时被打印出来，另一行在它返回时被打印出来。

让我们实际实现 trace，或者一个更简单的版本。我们要实现一个叫做 `trace1(fn)`，这个函数接收另一个函数。它的作用是返回 `fn` 的一个版本，这个函数在被调用之前会先打印一些东西。而 `fn` 是一个带有一个参数的函数，这就是为什么我们叫它 `trace1` 的原因。

好的，那么会发生什么？我会定义一个被追踪版本的函数，它会在调用此函数时先打印一下参数，然后再打印参数本身。它实际上会返回在 $x$ 上调用 `fn` 的值。然后我们将返回这个被追踪的函数：

```python
def trace1(fn):
    """Return a function equivalent to fn, but that prints its name and input."""
    def traced(x):
        print('Calling', fn, 'on argument', x)
        return fn(x)
    return traced
```

所以，被追踪的函数就像 `fn` 一样，只不过它还会打印一些东西。

现在，我可以用我刚写的 `trace1` 函数注释 square。我们不再使用内置的那个了。这意味着当我计算 12 的平方时，它会说：在参数 12 上调用了平方函数。而且，我可以追踪多个不同的函数。然后，当我求和到 5 的平方时，我可以看到发生的所有工作。

所以我们对参数 5 调​​用了 `sum_squares_up_to` 函数，这涉及对 1、2、3、4 和 5 进行平方运算，然后返回 55。

不错。追踪就是同样的事情。用追踪装饰一个函数，和我在下面写下来的效果完全一样：

```python
square = trace1(square)
```

我会得到相同的行为。

所以，如果你想要一个快捷方式，要将一个函数转换为另一个函数，你可以简单地放一个注解，这称为装饰器。所以，如果我追踪一个函数，那就是所谓的装饰器。你得到的是一个装饰过的函数，并且它绑定到给定函数的名称。这就像我首先定义函数，然后将函数的名称重新绑定到该函数的已追踪版本一样。

为什么不直接用呢？这样多打了点字，而且最好一开始就知道你给函数加了哪些修饰。把它们放在这会更自然一些。但可能最重要的是，这样做是因为并非所有 Python 程序员都理解高阶函数。而对于每个人来说，理解装饰器的魔法都很容易。对你来说可能不是魔法，但对其他人来说可能是。
