## P28 Lecture 30 Calculator-cn

编程语言通常具有一些指示错误或某种异常事件发生的机制，然后有一种处理这些错误并描述下一步操作的机制。在 Python 和许多其他语言中，它们被称为异常。

你可以引发异常以指示发生了异常情况，比如发生了错误。

Python 异常通过一个包含 `raise` 的语句引发，然后有一些表达式，该表达式评估为异常。这个表达式必须评估为一个类或一个实例。该类必须是基本异常的子类，这是内建的某个东西。而实例必须是某种异常类的实例。

异常的构造方式与其他对象相同。因此有不同的类，其中许多是内建的，如类型错误（TypeError）和名称错误（NameError）。然后，构建特定类型的错误只需传入描述发生情况的字符串。所以，这是发生的错误类型，这是具体的细节。

当函数传递了错误的数量或类型的参数时，通常会引发类型错误。名称错误是在找不到名称时引发的，字典中找不到键时引发键错误（KeyError），甚至在递归调用太多时会引发递归错误（RecursionError）。所以所有这些错误类型都是内建的。在某些情况下，这些异常会自动触发，但我们也可以自己触发它们。

让我们来看看。在 Python 中，如果我取 3 的绝对值，这不是一个错误：
```python
>>> abs(3)
3
```
但是如果我取 `'hello'` 的绝对值，就会引发类型错误：
```python
>>> abs('hello')
Traceback (most recent call last):
  ...
TypeError: bad operand type for abs(): 'str'
```
它说类型错误：对于 `str` 是一个错误的操作数类型。

事实证明，我随时都可以引发一个类型错误：
```python
>>> raise TypeError
Traceback (most recent call last):
  ...
TypeError
```
现在，这种类型错误没有描述。但是如果我引发一个带有一些消息的类型错误，比如说非常糟糕的主意：
```python
>>> raise TypeError('Very bad idea')
Traceback (most recent call last):
  ...
TypeError: Very bad idea
```
那么这就是我在消息中看到的内容。

因此，我可以编写自己的函数叫做 `double(x)`。如果 `x` 是一个字符串，那么我可能想引发一个类型错误，而且我可以随心所欲地描述它：`double` 函数仅接受数字或其他什么的。然后我会返回两倍的 `x`：
```python
def double(x):
    if isinstance(x, str):
        raise TypeError('double only takes numbers')
    return 2 * x
```
我为什么要写这样的东西呢？在 Python 中，两次 `'hello'` 确实有效，但是如果我希望我的 `double` 函数实现对字符串不起作用，那么我可以：
```python
>>> double(4)
8
```
它也能正常工作。但是当我将 `'hello'` 加倍时，它就不起作用了。它说 `double` 只接受数字：
```python
>>> double('hello')
Traceback (most recent call last):
  ...
TypeError: double only takes numbers
```

自动引发的其他错误包括名称错误、键错误和递归错误。例如，当我调用 `f` 时，它调用 `f`，它又调用 `f`，一直到达递归错误，因为我有太多递归调用。

异常有类型的原因，既是为了在看到错误消息时帮助描述发生了什么，也是为了在语言中创建处理异常并继续运行程序的能力。

默认情况下，如果发生异常，程序会停止，显示错误消息，回溯。然后由程序员决定下一步要做什么，改变程序并重新运行。但也许多你想写一个在错误发生后仍然继续运行的程序，而实现这一点的方法是使用 `try` 语句来处理异常。

`try` 语句包含 `try` 和一些代码块，可以是任何你想要的东西。然后与 `try` 配对的是一个 `except` 行，你甚至可以有多个 `except` 行。而且 `except` 描述了这个 `try` 语句处理的特定类别的异常。你甚至可以给异常本身起个名字，然后有一个 suite，这是一块代码，描述了当这种错误发生时该怎么办：
```python
try:
    <try suite>
except <ExceptionType> as <name>:
    <except suite>
```

`try` 语句的工作方式是首先执行 `try suite`。如果没有错误，就结束了。但是如果在执行 `try suite` 的过程中引发了异常，并且没有其他处理方式，如果异常的类继承自这里描述的异常类，那么就会执行接受代码块，程序不一定会停止。

如果接受代码块只是说，打印一个错误消息但继续运行，那就会发生这样的情况。这个名称的作用是为异常对象取个名字，有时候这很有用，因为你可以打印它。

异常处理可以阻止程序终止。例如，如果尝试将 1 除以 0，但是你接受了如果发生零除错误，你不想让程序停止，你只是想打印出正在处理零除错误并将 `x` 赋值为 0。然后 `x` 将绑定到 0，尽管此行出现在程序中的此行之后导致零除错误：
```python
>>> try:
...     x = 1 / 0
... except ZeroDivisionError as e:
...     print('handling a', type(e))
...     x = 0
handling a <class 'ZeroDivisionError'>
>>> x
0
```
这是因为这个打印调用，而这个赋值是因为 `x = 0`。而且我们从未看到任何类型的多行回溯，因为异常已处理。

让我们试试另一个例子。这是反转，这是一个接受 `x` 的函数，它计算结果即 $1 / x$：
```python
def invert(x):
    result = 1 / x
    print('Never printed if x is 0')
    return result
```
现在，如果 `x` 是 0，那么此行永远不会被打印，因为它永远不会走到那一步。然后让它返回结果。

这个程序没问题：
```python
>>> invert(2)
Never printed if x is 0
0.5
```
我可以倒置 2 得到 0.5。而且这个被打印是因为 `x` 是 2，而不是 0。但是如果我倒置 0，就会引发异常。这个从未被处理过，而且这一行从未被打印过。

但我可以编写另一个函数 `invert_safe`。`invert_safe` 的作用是获取 `x`，然后尝试对其进行反转。它将尝试返回反转 `x` 的结果。但是在存在零除错误的情况下，我们将为该错误命名为 `e`，而我们将简单地返回 `e` 的字符串版本：
```python
def invert_safe(x):
    try:
        return invert(x)
    except ZeroDivisionError as e:
        return str(e)
```
用 `invert`，如果我说 `a = invert(2)`，那么 `a` 就被定义了。但如果我说 `b = invert(0)`，那么 `b` 根本没有被赋值。但是 `invert_safe` 是不同的。如果我说：
```python
>>> a = invert_safe(2)
Never printed if x is 0
>>> a
0.5
```
那么就绑定到了 0.5。如果我说：
```python
>>> b = invert_safe(0)
```
那么没有显示任何错误。相反，`b` 被赋值为字符串 `'division by zero'`。

为什么会发生这种情况呢？这就是代码所说的。它说尝试反转 `x`，如果因为发生零除错误而无法成功，那么反转安全在程序停止之前不应该将错误冒泡上来。相反，它应该在这里处理该错误并返回一个字符串。如果不是返回该字符串，而是返回数字 0 的话，那么我们会得到完全不同的行为：`a` 将绑定到 0.5，而 `b` 将绑定到数字 0，因为这正是在反转不成功的情况下反转安全返回的内容。

这就是异常的工作原理。在处理来自用户或互联网的输入时，异常非常有用，可能格式不正确或属性不正确。因此可能会发生错误，但你可能不希望程序立即停止。你可能希望它只是打印出错误并继续执行，或者使用默认值，就像在这种情况下一样。

让我们看一个使用异常处理的例子。这是一个重要的高阶函数，叫做 `reduce`。`reduce` 的作用是将整个值序列减少为一个单一的值。

这里是 `reduce` 函数的描述：在 `itertools` 模块中有一个内建版本的 `reduce`，但我们也可以自己编写。它接受一个函数、一个序列和一个初始值，并使用该函数逐对地组合序列的元素，该函数接受两个参数，从初始值开始。例如，如果我们使用乘法对 2、4 和 8 进行 `reduce`，初始值为 1，那就相当于将 1 乘以 2，然后将该结果乘以 4，然后将该结果乘以 8，得到 64。

所以 `f` 是一个两个参数的函数。`s` 是一系列的值，它们都可以作为函数 `f` 的第二个参数。一个初始值必须是一个可以作为第一个参数的值。最后的限制是函数 `f` 的返回值也必须能够作为 `f` 的第一个参数。因为当你调用 `f` 时，你将把那个值直接传递给另一个对 `f` 的调用。

如果我们用初始值 2，从 1、2、3、4 开始减少 `pow`，会发生的是我们将 2 提升到一个逐渐变大的幂。我们开始：通过将 2 提升到 1 的幂，得到 2。然后我们将这个 2 提升到 2 的幂，得到 4。然后我们将 4 提升到 3 次方，得到 64。然后 64 的 4 次方突然变成了一个非常大的数。这就是减少的意义：仅通过将 2 提升到 1 次方，然后将结果提升到 2 次方，然后将结果提升到 3 次方，然后将结果提升到 4 次方，我们最终会得到 16777216。

让我们实现这个函数。`reduce` 接受一个函数 `f`、一个序列 `s` 和一个初始值。关键是使用函数 `f` 组合序列 `s` 的元素，从初始值开始。

我们看的例子是减少使用 2、4 和 8，从数字 1 开始：
```python
>>> from operator import mul, add
>>> reduce(mul, [2, 4, 8], 1)
64
```
这应该给我们 64。

或者例如，我们可以减少使用 `add`，1、2、3 和 4，从 0 开始：
```python
>>> reduce(add, [1, 2, 3, 4], 0)
10
```
这将给我们 10。

从操作符导入 `add` 和 `mul`。我能想到的最简单的实现是说，对于 `s` 中的 `x`，`initial = f(initial, x)`，然后我们返回 `initial`：
```python
def reduce(f, s, initial):
    for x in s:
        initial = f(initial, x)
    return initial
```
这通过了文档测试。

我们也可以递归地编写这个。比如我们会写：
```python
def reduce(f, s, initial):
    if not s:
        return initial
    else:
        first, rest = s[0], s[1:]
        return reduce(f, rest, f(initial, first))
```
如果 `not s`，这样它就是空的，然后我们就返回初始值，没有更多的工作要做了。否则，我们得到 `s` 的第一个值和剩余部分，然后我们返回调用 `f` 在 `s` 的剩余部分上的 `reduce` 的结果，然后更新初始值为 `f` 在初始值和第一个值上的结果。这也通过了我们的文档测试。

那么我们如何使用 `reduce`？比如，我们想写一个叫做 `divide_all` 的函数，它接受一个分子和一系列的分母，然后将分子除以所有的分母。这其实就是 `reduce`。我们使用一个除法函数对所有的分母进行 `reduce`，从分子开始：
```python
from operator import truediv

def divide_all(n, ds):
    try:
        return reduce(truediv, ds, n)
    except ZeroDivisionError:
        return float('inf')
```
所以我们可以将 1024 作为我们的分子，调用 `divide_all` 除以 2、4 和 8：
```python
>>> divide_all(1024, [2, 4, 8])
16.0
```
结果将是 16。这就是当你除以所有这些数时剩下的部分。

现在，如果在中间有一个 0 呢？这就是一个零除法错误。假设这不是我们想要做的分割全部，我们想要它计算除以所有数的结果，但是如果出现零除错误，我们希望返回无穷大。这就是在 Python 中获得无穷大的方式：`float('inf')`。

因此，在我们的新实现中，在这种情况下，我们得到 `inf` 或无穷大，但我们仍然得到 16。使用这种方式进行错误处理的优势是，我们的 `reduce` 实现不需要知道任何关于零除错误的信息。相反，我们编写一个函数，在这个函数中，我们知道我们正在用另一个可能引发零除错误的函数调用 `reduce`。所以是这个函数知道传递到 `reduce` 中的内容并处理错误。

因此，我们创建了关注点的分离：`divide_all` 知道如何进行除法，`reduce` 知道如何进行减少，但 `reduce` 不知道除法的具体操作或导致的错误。`divide_all` 实际上不需要知道如何组合元素，它只需要知道需要调用 `reduce`。
