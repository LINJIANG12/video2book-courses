记忆化是加速程序运行时间的一种非常有用的技术。这是一个简单的思路：只需记住以前计算过的结果。因此，当需要再次使用它们的值时不必重新计算，只需将它们保留下来。

这里有另一个装饰器，它被称为 `memo`。它接受一个可能需要一些时间来计算的函数，但我们还保留了该函数返回的值的缓存。在 `f` 的记忆版本中，我们首先检查并查看传入的参数是否在缓存中。如果不在缓存中，那么我们将添加它到缓存中，这意味着我们在键 $n$ 和返回值 `f(n)` 之间建立了映射。现在，我们实际上必须调用最初传入的函数 `f`，以计算这个返回值。但一旦它在缓存中，我们就永远不会再次计算它。相反，我们将只返回已经在缓存中的返回值。一旦我返回了这个函数的记忆版本，我将自动获得内置的缓存功能。

我们保持一个字典，其中键是参数，值是 `f` 的返回值。而且，这个记忆化函数的行为与 `f` 相同，如果 `f` 是一个纯函数的话。如果是一个非纯函数，那么我们并不每次调用 `memoized` 都实际调用 `f`，所以它可能有不同的行为。所以，这是需要注意的一点。你只能真正的记忆化纯函数，并期望它们的行为保持不变。

让我们看看当我们使用 `memo` 来加速 `fib` 时会发生什么。

```python
def memo(f):
    cache = {}
    def memoized(n):
        if n not in cache:
            cache[n] = f(n)
        return cache[n]
    return memoized
```

那么 59 又是怎么回事呢？好的，让我们看看发生了什么。这是我们的树形递归过程。我们要追踪调用 `fib` 函数的实际次数，调用带有记忆功能的 `fib` 函数并在缓存中找到结果的次数，以及我们完全跳过的次数。肯定有很多次我们完全跳过，因为我们的调用比以前少得多。

所以我们调用 `fib(5)`，它调用 `fib(3)`，它又调用 `fib(1)`，`fib(1)` 返回 1。这是对 `fib` 函数的实际调用。同样，对 `fib(0)` 的调用也是如此。但是下一次调用 `fib(1)` 时，我们只是从缓存中获取已经计算过的值。所以这不算做对基础 `fib` 函数的调用，但却算作对记忆化版本的调用。`fib(2)` 返回，然后 `fib(3)` 返回。接下来发生的事情是，我们调用 `fib(4)`，它调用了 `fib(2)`。而 `fib(2)` 已经在缓存中，这意味着我们可以跳过对 `fib(0)` 和 `fib(1)` 的这些调用。它们根本不会发生。这是因为这种结构是从我们之前已经做过的内容中重复出现的。所以我们立即找到了 `fib(2)`。当我们调用 `fib(3)` 时，我们也立即找到了结果，跳过这些递归调用。所以，通过 `fib(2)` 和 `fib(3)`，我们最终可以从 `fib(4)` 返回，然后从 `fib(5)` 返回。

所以你可以看到，对于每个 $n$ 的值，`fib` 只被调用一次。对于许多 $n$ 的值，`fib` 的记忆化版本会第二次调用以完成计算。但是 `fib(4)` 从不第二次调用，`fib(5)` 也是如此。

让我们看一个我们可以用两种不同的方式定义的函数的例子，其中一种比另一种更有效。

在 Python 中，乘方是内置的。我可以把一个数字的幂提高到另一个数字的幂。但让我们递归地编写一个乘方函数。我们的目标是使得再乘一次方，让我们将指数加倍。

这是一个不符合这个目标的实现：

```python
def exp(b, n):
    if n == 0:
        return 1
    else:
        return b * exp(b, n - 1)
```

这表示，如果 $n$ 为 0，则将 $b$ 提高到 $n$ 次方返回 1；否则，将 $b$ 的 $n$ 次方减 1 乘以 $b$。这是一个正确的定义，但如果我把 $n$ 加倍，我就必须进行两倍的乘法，因为每次我进行递归调用时，我只是将 $n$ 减少 1。而这个函数的实现对应着 $b^n$ 的以下数学定义，但这不是 $b^n$ 的唯一数学定义。

这里有另一个更复杂，但额外的复杂性也将为我们带来额外的效率。这表示，如果 $n$ 为 0，则 $b^n$ 为 1，然后对于 $n$ 是偶数或奇数，有两种不同的情况。如果 $n$ 是偶数，那么我可以将 $b$ 的一半 $n$ 次方，并对结果进行平方。所以如果 $n$ 是 16，我将 $b$ 提升到 8 次方，然后我将 $b^8$ 平方，得到 $b^{16}$。如果 $n$ 是奇数，那么我使用之前的定义。

这是一个实现：

```python
def exp_fast(b, n):
    if n == 0:
        return 1
    elif n % 2 == 0:
        return square(exp_fast(b, n // 2))
    else:
        return b * exp_fast(b, n - 1)
```

这是指数计算的更高效版本，具有两种不同的递归情况，取决于 $n$ 是否为偶数。在这种情况下，你将结果提升到 $b^{n/2}$ 次方，我知道 $n$ 是偶数，所以整除运算将给我精确的结果。如果 $n$ 是奇数，那么我使用我的旧定义。这不是一棵树递归的函数。虽然在函数体中我看到两个对 `exp` 的不同调用，但只有其中一个被调用。所以，这是线性递归的一个实例。有时问题的规模减半，这意味着多做一次乘法，在这种情况下，通过调用 `square`，让我们处理的问题规模加倍。

以这种方式运行多次效率不高，所以我写了一些代码，使用内置的 `timeit` 模块运行多次，可以重复调用某个东西。在这种情况下，我们将计算执行某行代码所需的时间中位数。这就是结果：$2^{200}$ 需要不到半毫秒；$2^{400}$ 需要不到 1 毫秒。这看起来像一条直线。我们用来描述这个的术语是线性的。在这个实现下，计算 $2^n$ 所需的时间是与 $n$ 呈线性关系的。现在有点颠簸，因为在计算机内部发生了各种有趣的事情。但是，即使与直线有轻微偏差，我们仍然使用“线性”这个词来描述出现的总体趋势。

当你绘制计算某物所需时间与输入大小的函数关系图时，这是一个快速的定义。我们可以画同样的图，我们会看到总体数字要小得多。对于 1600，不是花费 4 毫秒，而是仅需 0.04 毫秒。另外，曲线的形状也不同。这种形状被称为对数。从 200 变到 400 的差异，在这种情况下，大约只有 0.002。那么，从 400 到 800 有什么区别呢？那是另外的 0.002。从 800 变到 1600 又是另外的 0.002。每次我们把输入翻倍，都只需要恒定量的额外工作。这是因为我们在 $n$ 上进行递归调用，而 $n$ 的大小减为一半。这就是所谓的对数时间。

所以总结一下，一个线性时间函数对于每一个更大的 $n$ 需要多一单位的工作，这意味着将输入加倍会使时间加倍，而 1000 倍的输入需要 1000 倍的时间。1024 是 $2^{10}$。对数时间要好得多：将输入加倍只会使时间增加一些常数，而且输入增加 1000 倍，时间就会增加 10 倍的那个常数。所以，做 1000 倍的工作，只要花 10 倍的时间。

这些术语——线性和对数，用来描述时间随输入大小变化的一般形状，即使路上有波动和颠簸。对于诸如线性、常数、二次等术语，都有精确的数学定义。这些定义很有用，因为它们使你能够证明函数的属性，而无需在特定示例上运行这些函数，这是计算理论的一个重要组成部分。

现在，这不是本课程的主题，但它在伯克利的未来课程中得到了广泛覆盖，也是计算机科学课程的标准组成部分。与其告诉你所有的定义，你可以自己查找，我将向你展示与这些定义相关的标准符号，因为它们使用得如此普遍，如果你以前从未见过，可能会让你感到惊讶。

对于这些常见的增长量级：指数、二次、线性、对数和常量。描述每个增长量级最典型的方式，要么用大 $\Theta$ 符号，要么用大 $O$ 符号。

大 $\Theta$ 符号看起来是这样的，每个增长量级都有不同的表达方式。二次增长是 $n$ 的大 $\Theta$（$\Theta(n^2)$），而线性增长是 $n$ 的大 $\Theta$（$\Theta(n)$）。计算机科学家真的会到处说大 $\Theta$。对数是 $\log n$（$\Theta(\log n)$），而常量是个棘手的问题，你会写成大 $\Theta$ 的 $1$（$\Theta(1)$），最常见的就是这样。那 $n$ 呢？增加 $n$ 并不会影响常量增长函数的时间，所以你根本不需要把 $n$ 放在那。

另一种常见的符号是大 $O$ 符号，比大 $\Theta$ 符号更好玩。表达式看起来是一样的，大 $\Theta$ 的 $b^n$（$\Theta(b^n)$）或者大 $O$ 的 $b^n$（$O(b^n)$）。它们实际上有稍微不同的含义。大 $O$ 描述了函数运行所需时间的上限，这就想说最多是二次方的。而这个则表示对时间的下限和上限都有要求，既要求最多是二次方的时间，又要求至少是二次方的时间。

为了有效地使用这种数学符号，你必须对你所描述的内容非常精确。在问题中，$n$ 是什么？如果 $n$ 只是输入的数字，那么事情就很简单。但是 $n$ 可能是输入序列的长度，这意味着有许多长度相同的序列。那么，你是在描述长度为 $n$ 的序列在最坏情况下或最好情况下需要多长时间，还是在平均情况下跨所有不同长度为 $n$ 的序列？如果你要证明关于函数的性质，那就是你想要具体说明的事情。

而所有这些将在后面的课程中变得重要。但我认为在这门课程中，重要的是要认识到一个函数完成所需时间的不同一般增长模式。最常见的是我在这里向你展示的这五种。当人们讨论对数增长时，有时他们不说对数增长，相反，他们说大 $\Theta$ 对数 $n$ 或大 $O$ 对数 $n$。

计算函数结果所需时间的增长顺序是一个通用类别，即该函数所处的类别，例如线性或对数。使用线性时间的两个函数在计算相同输入的结果时可能不会花费完全相同的时间，但它们的缩放方式相同。它们的缩放曲线的一般形状都是一条线。而对数函数都具有相同的特征对数形状，还有其他形状。

二次时间描述的是一个处理线性输入中所有元素对或长度为 $n$ 的序列中所有值对的函数。例如，这是一个计算 $A$ 中的元素与 $B$ 中的元素重叠的函数，通过遍历 $A$ 和 $B$ 中的每个元素，并检查它们是否相同：

```python
def overlap(a, b):
    count = 0
    for item in a:
        for other in b:
            if item == other:
                count += 1
    return count
```

当它们相同时，它会增加一个计数，并在最后返回计数。所以 3、5、7、6 和 4、5、6、5 之间的重叠是 3，因为 5、5 是相同的，5、5 也是相同的，6、6 也是相同的。

为了计算这个结果，`overlap` 比较 $A$ 中的一个元素和 $B$ 中的一个元素的所有配对。基于输入长度，这是二次的工作量。这里输入长度是 4，比较的数量是 $4 \times 4$，即 16。处理长度为 4 与长度为 3 所需的额外工作量是这整行。因此，如果将输入大小与计算结果所需时间进行比较，你会得到一个二次形状。

当我们传入范围从 20 到 200 的 $n$ 并计算返回结果所需的中位数时间时，发生了什么？75 花费 2 毫秒，而 150 花费近 8 毫秒，曲线以熟悉的抛物线向上倾斜。

另一种上升的增长顺序是指数时间。在这里情况更糟。树递归函数可能需要指数时间，因为未记忆的 `fib` 函数必须多做 60% 的工作，仅仅为了计算比先前的 $n$ 大一个的 $n$。计算 `fib(2)` 仅需要这么多的工作，`fib(3)` 需要所有这额外的工作，`fib(4)` 需要在 `fib(3)` 的基础上增加所有这额外的工作，而 `fib(5)` 不仅需要计算 `fib(4)`，还需要计算所有这额外的工作，假设我们不进行记忆。因此，像这样没有记忆的树递归函数将需要所谓的指数时间。

因此，指数增长非常缓慢；二次增长缓慢但常见；线性增长非常普遍；对数增长很强大，可以很好地应对非常大的输入；而常数增长是最好的。

这种情况发生在输入大小对时间没有影响的情况下。例如在 Python 中，字典中元素的数量不影响按键查找值所需的时间。它是如何工作的是后续课程的一个主题，但通过键找到值是 Python 字典的一个重要属性，因为这是一个常数时间操作。

每个类别都可以用一个简单的方程来描述，我们已经写下了。处理大小为 $n+1$ 的输入所需的时间，以处理大小为 $n$ 的输入的时间为基础，使用一些常数 $a$ 和 $b$ 来解释运行某些内容需要多长时间的细节，我们在谈论输入大小的一般形状时正在忽略这些细节。

因此，对于指数增长，计算大小为 $n+1$ 的输入结果所需的时间大致为 $a \cdot b^{n+1}$。相对于输入大小为 $n$ 时所需时间的指数增长，需要额外的乘法因子 $b$。所以这就是指数增长的关键特征：增加输入大小为 $n+1$ 会将时间乘以某个常数。常数越大，情况越糟糕，但基本上对于任何常数都相当糟糕。

二次增长并不那么慢。二次增长表示，对于大小为 $n+1$ 的输入，为了计算结果，需要类似于 $a \cdot (n+1)^2$。这除了计算大小为 $n$ 的结果所需的时间外，还需要额外的加法项。增加时间要比乘以时间好，但问题仍然是二次增长的问题，仅仅是从 $n$ 到 $n+1$ 所需的增量是一个取决于 $n$ 的项。所以增加 $n$ 会将时间增加 $n$ 倍的一个常数。

对于规模为 $n+1$ 的问题，线性增长需要 $n+1$ 倍的某些步骤。与解决规模为 $n$ 的相同问题相比，这只是一个不依赖于 $n$ 的附加因素。增加 $n$ 会以一个常数倍增时间。

对数增长是那种在真正大的 $n$ 下才会发生的。在这里，我们写出计算结果为 $n+n$ 或 $2n$ 时所需时间的表达式，是某个常数乘以 $2n$ 的对数。与仅计算 $n$ 时所需的时间相比，这只是增加了一些常数。因此，将 $n$ 加倍只会以一个常数倍增时间。

如果有可能通过记忆化重新实现某个函数，以将其增长阶从指数级改为线性，或者从线性改为对数，正如我们对指数运算所做的那样，这可以显著改变程序的速度，以及程序可以处理的问题的规模，而不会让人感觉像是花费了很长时间。

程序执行时消耗的另一个资源是空间，或者说内存。这是你需要担心的事情。空间的消耗是由值占用的，所以长列表占用的空间比短列表多，但它也被帧占用。你需要知道由于程序中同时进行的不同函数调用而存在的帧的数量，而这涉及一些新概念。

我们需要跟踪的新概念是在评估期间我们需要保留哪些环境帧，哪些可以放弃。这就是故事的全部：在任何时刻，都有一组被称为活动环境的东西。在这些活动环境中的值和帧会消耗内存或空间。用于其他值和帧的任何内存，不在活动环境中，都可以被回收利用。而且，当 Python 解释器知道不再需要某些信息时，它会自动回收之前使用的空间。

哪些是这些活动环境呢？活动环境就是当前正在评估的任何函数调用，也就是说，我们调用了它，但它还没有返回。

还有另一种情况，要少得多，就是一个函数的父环境存在于一个活动环境中。这种情况发生在你再另一个函数内定义了一个函数，因此它的父框架不是全局框架，而是其他一些框架。只要你需要那个函数，你还需要它的父框架以及父环境中的所有其他框架。

幸运的是，Python Tutor 可以为我们可视化显示哪些框架是活动的。这是我们计算斐波那契数的 `fib` 的定义，第六个数字。还有一个设置，我会给你看的，它说不要显示已退出的函数。这样，它实际上会删除已经返回的任何框架。

所以，当我们调用 `fib(6)` 时，显然它还没有返回，因为我们还有一些工作要做。这将涉及调用 `fib(4)`，在我们尝试完成 `fib(6)` 之前必须完成。而 `fib(4)` 的完成涉及调用 `fib(2)`。因此，所有这些都是同时活跃的帧。`fib(2)` 调用 `fib(0)`。`fib(0)` 实际上会返回。一旦它返回，它就不再是活跃的。所以，它就会消失。

然后，我们用一个框架替换了它，称为 `fib(1)`。注意，我们有 f1、f2 和 f3。我们创建了 f4，但后来将其删除，因为我们不再需要它。现在我们到了 f5。

如果我们继续这个过程，我们会发现一旦计算完 `fib(2)`，就会移除 `fib(2)` 框架。现在我们有了 `fib(3)` 框架，这是计算 `fib(4)` 的另一部分。这样继续一段时间。最终，`fib(4)` 帧完全消失了。我们只剩下原始的 f1 帧，因为我们还没有计算完 `fib(6)`。我们有为计算 `fib(5)` 创建的 f11 帧。它做了一些工作。最终，它被删除了。`fib(6)` 最终可以返回值 8，然后就没有更多工作要做了。

在我们的代码中，我们还可以看到使用了多少帧。让我们定义一个称为 `count_frames` 的高阶函数，该函数接受一些 `f`，并定义一个计数版本，该版本接受一个参数 `n`：

```python
def count_frames(f):
    def counted(n):
        nonlocal open_count, max_count
        open_count += 1
        if open_count > max_count:
            max_count = open_count
        result = f(n)
        open_count -= 1
        return result
    open_count = 0
    max_count = 0
    return counted
```

它的作用是增加打开帧的计数。它还将跟踪任何时候打开帧的最大数量。如果打开计数实际上更大，那么 `max_count`，我们可以将 `max_count` 更改为 `open_count`。现在我们将通过在 `n` 上调用 `f` 来获得返回值。现在是关闭此帧的时候了，这仅仅意味着从 `open_count` 中减去 1。然后，我们可以返回结果。打开计数从 0 开始，最大计数也从 0 开始，我们可以返回计数函数。

如果我们快速定义 `fib`，我们已经知道它进行了许多递归调用，但我们不知道任何给定时间有多少个打开的框架，或者最大打开框架的数量是多少。我们可以通过对 `fib` 调用 `count_frames`，并在某个数字上调用 `fib` 来弄清楚这一点，例如 20。它计算了第 20 个斐波那契数，`fib.open_count` 应该是 0，因为我们已经从我们做过的每个对 `fib` 的调用中返回了。但 `max_count` 会告诉我们一次打开的最大框架数量。答案是 20。

这就是这个函数使用了多少空间的指示。它不需要一次打开 6000 帧，只需要一点。

现在我们怎么能理解为什么数字出来是 20 呢？好吧，这是我们用来计算 `fib(5)` 的树形过程。假设我们已经完成了所有这些工作，我们仍然需要做所有这些工作，并且我们即将从对 `fib(1)` 的调用中返回。我们可以弄清楚哪些调用有一个活动的环境。是这个、这个、这个和这个，还没有返回。

左边的那些已经被调用并返回了，所以这些真实用的任何内存都可以被回收。然后在这一块，这些还没有被调用过，所以我们不需要担心那个。

因此，真的最大打开数量是在这棵树中找到的最长链，这种情况下从 Fib 5 到 4 到 3 到 2 到 1 的长度为 5。
