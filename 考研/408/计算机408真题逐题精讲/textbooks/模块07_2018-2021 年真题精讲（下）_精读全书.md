## 2020 年组成原理串讲：机器字长、补码、小端与中断
> 对应块：BLK48 | 覆盖分集：P124 | 块标题（分集名）：《20年（12-22）计算机组成原理。》

这一串题是 2020 年统考真题里组成原理这一部分，一道紧挨着一道。看上去全是"背过就会"的判断题——部件位数跟机器字长有没有关系、CPI 等于几、总线带宽怎么算——可真要在考场上两分钟一道地拿分，靠的不是背了多少，而是每个概念卡得够不够死。这一遍按题号往下过，凡是容易串的地方就多说两句。

### 机器字长管的是谁

第一问：下列给出这些部件，它的位数一定与机器字长相同的是？

先把定义摆出来。机器字长，是指计算机进行一次定点整数运算所能处理的二进制数据的位数。定义里"定点整数"这四个字是要命的——它直接决定了机器字长和浮点数之间没有任何关系。所以第一刀下去，浮点寄存器就被排除了：浮点寄存器里存的是 IEEE 754 格式，它跟定点数的存储方式完全不是一回事，跟字长无关。

> **定义**：机器字长 = 计算机进行一次定点整数运算所能处理的二进制数据的位数。只管定点整数，不管浮点。

剩下三个逐个看。

先看 ALU。ALU 就是算术逻辑运算单元，是运算器最核心的部件。为什么它的位数一定等于机器字长？因为你想处理二进制数据，就得把数据送进运算器里去算，而 ALU 有两个输入端 A 和 B，数据就是这么从 A、B 灌进去的。既然一次能处理的位数就是字长，那 A、B 的位数当然得跟字长一样。

数据流是这样的：

```text
     ┌──────────────────┐
     │   通用寄存器组   │   位数 = 机器字长
     │   x1   x2   x3   │
     └────────┬─────────┘
              │ 待运算数据送进来
              ▼
     ┌──────────────────┐
     │ ALU 的 A、B 两端 │   位数 = 机器字长
     └────────┬─────────┘
              ▼
           运算结果
```

读完这张图就明白了：数据从通用寄存器出来，经 ALU 的 A、B 两端进去，出来的是运算结果。两个端口的位数既然是字长，寄存器为了喂得上这个端口，长度自然也就是字长。ALU 直接操作通用寄存器里的数据，中间不经过别的部件，所以通用寄存器的位数与机器字长一致。

反过来说，指令寄存器 IR 就不一定了。IR 里存的是指令，而指令内容的长度我们叫**指令字长**，指令字长和机器字长之间没有等价关系，它是由指令的长度决定的。更根本的原因是：指令内容不需要 ALU 去算，它会被直接送进译码器去译码。数据走 ALU，指令走译码器——两条路，分开算。

所以答案是 ①③（ALU、通用寄存器），选 B。

### 同一个机器数，两种读法

上一问其实留了个伏笔：字长只管定点整数。现在来一道直接把两套表示体系摞在一起、让你二选一的。

已知有符号整数用补码表示，float 型数据用 IEEE 754 标准表示，假定变量 X 的类型只可能是 int 或者是 float。当 X 的机器数是 C8000000H 的时候，X 的值可能表示什么？

这道题的分量在于：题干已经把类型卡死了，只有 int 和 float 两种可能，而这两种表示对同一个机器数的解释完全不同。你先得判断走哪条路，再算。

先走 int 这条。补码转真值，最土的办法是绕道原码：符号位不动，数值位取反，末位加一。

```text
机器数(补码) ： 1 100 1000 0000 0000 0000 0000 0000
数值位取反    ： 0 011 0111 1111 1111 1111 1111 1111
末位加 1      ： 0 011 1000 0000 0000 0000 0000 0000   ← 原码的绝对值
```

绝对值是 0x38000000，二进制 0011 1000 0000…，也就是 $2^{29} + 2^{28} + 2^{27}$。把 $2^{27}$ 提出来，$2^{27}\times(4+2+1) = 2^{27}\times 7$，再带上前面的负号：

$$X = -7 \times 2^{27}$$

这就是 A 选项。

还有一条更省事、也更快的方法：补码最高位那个 1 的权值是 $-2^{31}$，别当成 $+2^{31}$；剩下各位按普通二进制权值加。这一串 1 特别少，正是这种办法的用武之地：

$$X = -2^{31} + 2^{30} + 2^{27} = 2^{27}\times(-16 + 8 + 1) = -7\times 2^{27}$$

两条路结果完全一样，考场上随便挑一条顺手的就行。

现在换 float。还是那个 C8000000H，还是那个最高位的 1——它照样表示负数。改按 IEEE 754 单精度拆成三段看：

```text
  0xC8000000 = 1100 1000 0000 0000 0000 0000 0000 0000

    1        |  1001 0000  |  000 0000 0000 0000 0000 000
    符号位       阶码 8 位          尾数 23 位（全 0）
```

阶码域是 1001 0000，等于 $128 + 16 = 144$。注意阶码里存的是偏置值，要求真值还得把 127 减掉：$144 - 127 = 17$，也就是 $2^{17}$。尾数全是 0，说明小数部分只有隐藏的那一位 1，也就是纯 $1.0$。

$$X = -1 \times 1.0 \times 2^{17} = -2^{17}$$

选项里根本没有 $-2^{17}$，所以 B、C、D 全错，只有 A 成立。

> **易错点**：同一个十六进制数换个类型就换个人。补码的最高位权是 $-2^{31}$ 不是 $+2^{31}$；IEEE 754 的阶码是偏置值，求真值一定要减 127。这两处各扣一分，就够把一道选择题送走。

### 结构体的边界对齐与小端摆放

第三题是存储布局的综合题：按字节编址、采用小端方式的 32 位计算机中，按边界对齐方式为 C 语言结构体变量 A 分配存储空间。结构体里有 `short x1`（占 2 字节）和 `int x2`（占 4 字节），A 的首地址是 2020F100H，成员变量 X2 的机器数为 12340000H，问 34H 所在存储单元的地址。

这种题别急着算，先把数据按地址摊开。

```text
   地址            存放内容
  ──────────────────────────────────────────────
   2020F100H       x1 的高字节   ┐
   2020F101H       x1 的低字节   ┘  short 占 2 字节
   2020F102H       填充（空）    ┐
   2020F103H       填充（空）    ┘  不是 4 的倍数，放不下 int
   2020F104H       00H           ┐
   2020F105H       00H           │  x2 = 12340000H
   2020F106H       34H           │  小端：高有效字节 12H 落最高地址
   2020F107H       12H           ┘
```

先看上半截。首地址 F100H 和 F101H 正好装得下 2 字节的 x1。下一个成员是 int x2，占 4 字节，按边界对齐它的首地址必须是 4 的倍数；F102H 不是，F103H 也不是，所以这两个字节只能是填充，x2 只能从 F104H 开始，连续占 F104H、F105H、F106H、F107H 四个字节。

再拿下半截。x2 的机器数是 12340000H，最高有效字节是 12H。小端存放，高有效字节放高地址——这看着反直觉，其实是这类题最爱设的陷阱。既然 12H 落在最高地址 F107H，顺着低位往低位地址方向推下去：F106H 是 34H，F105H 是 00H，F104H 是 00H。

题目问 34H 所在存储单元的地址，就是 F106H，写完整是 2020F106H，选 D。

> **易错点**：小端的定义只有一句话——低位字节放低位地址。所以按字节拆的时候，先把机器数从高有效字节到低有效字节列成一列，再从高地址往低地址往里填，绝不会错。边界对齐那条线是另一回事：它管的是"从哪儿开始放"，不是"谁放高位"。

### TLB 和 Cache，三对一错

下一题快问快答：下列关于 TLB 和 Cache 的叙述中错误的是。

- **命中率与程序的局部性有关**——对。它俩都是照着程序的局部性原理设计的。TLB 属于页表中的一个部分，经常访问的页放进快表，程序局部性好，TLB 就命中了，不用再去访问主存；Cache 是存储的副本，局部性好，访问都落在 Cache 里，命中率当然也高。
- **缺失后都要去访问主存**——对。TLB 缺失后要去访问页表，而页表在主存里；Cache 缺失后要去访问主存，从主存里把数据取回来。
- **缺失处理都可以由硬件去进行实现**——对。Cache 缺失之后全部由硬件实现；TLB 缺失既可以由硬件处理，也可以由软件处理。
- **都由 DRAM 存储器去组成**——错。

错在哪儿？因为它们都是高速缓冲存储器，受速度的限制，容量要比主存、比页表小得多，所以只能用 SRAM。SRAM 的特点就是高速，这是它相对 DRAM 的优势所在。

所以选 D。

> **提示**：DRAM 管容量，SRAM 管速度。判断一个部件用什么存储器，先问它是被"求快"还是被"求大"——被求快就往 SRAM 上靠，被求大就只能 DRAM。

### 16 位指令下的直接寻址范围

某计算机采用 16 位定长指令字，操作码的位数和寻址方式的位数是固定的，指令系统有 48 条指令，支持直接、间接、立即、相对四种寻址方式。在单地址指令当中，直接寻址方式可寻址的范围是……

三步走。

第一步抠操作码。48 条指令，操作码要满足 $48 \le 2^n$。$2^5 = 32$ 不够，$2^6 = 64$ 够，只能是 6 位。

第二步抠寻址方式位。四种寻址方式，需要 2 位，$2^2 = 4$，一位不多一位不少。

第三步是剩下多少给形式地址。题目问的是单地址指令，只有一个地址码，所以形式地址 = $16 - 6 - 2 = 8$ 位。

```text
   ┌──────────┬──────────┬──────────┐
   │ 操作码   │ 寻址方式 │ 形式地址 │
   │   6 位   │   2 位   │   8 位   │
   └──────────┴──────────┴──────────┘
```

如果采用的是直接寻址，这 8 位表示的就是主存地址，也就是操作数的有效地址。而地址一定是大于等于 0 的，所以这 8 位得当成无符号数看：$0 \sim 255$。

选 A。

> **易错点**：这里"8 位直接寻址"是按无符号数解释的。地址域永远不给负数，看到地址就要条件反射想到无符号。

### CPI 等于 1 的处理器

下列给出处理器类型当中，理想情况下 CPI 等于 1 的是：

- **单周期 CPU**——等于 1。它的定义就是一条指令执行的时钟周期需要一个。
- **多周期 CPU**——大于 1。不管是复杂指令还是简单指令，都可以分成多个段，每段所需要的时钟周期肯定大于等于 1，所有段加起来，CPI 必然大于 1。
- **基本流水线**——等于 1。题目说的是理想情况，标准流水线 CPU 每隔一个时钟周期就可以输出一个指令的结果。
- **超标量流水线**——小于 1。它一个时钟周期可以并行执行多条指令。

所以答案是 ①③，选 B。

### 自陷为什么算内中断

接下来是一道关于自陷的题，找叙述错误的那一项。

"自陷是通过陷阱指令预先设定的一类外部中断事件"——这句就错在"外部"两个字。

自陷是程序自己用一条专门的陷阱指令主动引发的，它属于内中断，也就是异常，而不是外部中断。所以 A 错，选 A。

剩下三条都是对的：自陷可以用来实现程序调试时的断点设置和单步跟踪，这是它一个很典型的应用；自陷发生后 CPU 会转去执行操作系统内核中相应的程序，因为异常要交给内核去处理；处理完成后返回到陷阱指令的下一条指令继续执行。

> **提示**：区分内外的标准只有一条——这件事是不是 CPU 执行当前指令时自己产生的。自陷、缺页、除零，CPU 自己一脚踩出来，都是内中断；定时器到点、网络来包、外部设备敲门，CPU 坐在那儿等着，是外中断。

### QPI 总线带宽里的乘二

下一道是总线。QPI 是一个点对点的全双工同步串行总线。

先把参数理一遍。全双工的意思是一个总线可以同时接收和发送信息，两个方向同时传输。每个方向传输 20 位，这 20 位包含 16 位的数据（两个字节）加 4 位的校验位。所以每个 QPI 数据包有 80 位的信息，分两个时钟周期传送，每个时钟周期可以传送两次。

于是带宽就是：

$$\text{总线带宽} = \text{每秒传送次数} \times \text{一次的数据量}$$

每秒传送次数：时钟频率 2.4 GHz 意味着一秒内时钟周期个数是 2.4G，一个时钟周期可以传递两次，所以是 $2.4\text{G} \times 2$。

一次的数据量：一个方向 2 字节，全双工两个方向同时传，所以后面再乘 2。

$$2.4\text{G} \times 2 \times 2\text{B} \times 2 = 19.2\ \text{GB/s}$$

选 C。

这道题算是比较简单的，因为公式直接给你了，代进去就行。但真正要记住的是：考试万一没给公式该怎么求。带宽无非等于总线工作频率（也就是每秒传送次数）乘上它一次可以传输的数据量。工作频率就是时钟频率；一次能传多少数据量，先按一个方向算——这里是 2 字节——再乘方向数，两个方向同时传，就再乘二。这一步就是前面那个公式的来历。

> **易错点**：看到"全双工"就要警惕那个乘二。这道题如果只盯着"80 位分两个周期传"，会算出 40 位每周期、5 字节每周期，漏掉了"每周期传两次"和"两个方向"这两层。给了公式就老老实实代公式，没给公式就按"频率 × 每次数据量"这两步走，绝不会错。

### 外部事件与外部中断，连着两道

中断这块连着两题，放一起看。

第一题：下列事件中属于外部事件的是。

- **缺页**——属于异常，是内中断，直接排除。
- **定时器到达**——是外部事件。时间一到就发出中断请求。
- **网络数据包到达**——是外部事件。这个数据包是什么、什么时候到，CPU 事先并不知道，它任何时刻都可能发生，而它到达之后就可以去发出中断请求。

所以答案是 ②③。

如果你对后两个拿不准，就用排除法：缺页属于异常，这一点人人都知道，A 排掉；剩下的 B、C、D 三个选项里只有③④ 说得通，二、三一选就出来了。大家平时碰见不会的题，也要去找窍门——怎么用最少的判断换来确定的答案，这本身就是一种能力。

第二题：外部中断包括不可屏蔽中断和可屏蔽中断，下列关于外部中断的叙述中错误的是。

- **CPU 处于关中断状态的时候，也能去响应不可屏蔽中断请求**——对。不可屏蔽中断是不受中断标志位 IF 影响的，即使在关中断的情况下也能被响应；而 IF 位影响的是可屏蔽中断，你可以控制 CPU 什么时候能去响应它、什么时候能看见它。
- **一旦可屏蔽中断请求信号有效，CPU 就立即去响应**——错。响应的条件有三个：

```text
   可屏蔽中断被响应的条件（三条必须同时满足）
     ① 当前执行的指令已经执行结束
     ② 有相应的中断请求送到 CPU
     ③ CPU 处于开中断状态（中断允许标志 IF = 1）
```

  "信号有效"只是第 ② 条，① 和 ③ 没满足照样不响应，所以绝不可能"立即"。而且第 ③ 条开中断状态是针对可屏蔽中断来说的。
- **不可屏蔽中断优先级比可屏蔽中断高**——对，不可屏蔽的事情本来就急。
- **可通过中断屏蔽字改变可屏蔽中断处理优先级**——对，中断屏蔽技术就是干这个的。

所以错的是 B。

### 周期挪用的 DMA 到底挪走了什么

最后一题是 I/O。某设备采用周期挪用的 DMA 方式进行输入输出，每次 DMA 传送的数据块大小为 512 字节，相应的 I/O 接口中有一个 32 位数据缓冲寄存器。对于数据输入的过程，下列描述中错误的是：

- **每准备好 32 位的数据，DMA 控制器就发出一次总线请求**——对。数据缓冲寄存器准备好了，说明 I/O 设备这边数据到位，它就要向 DMA 控制器发出请求，然后 DMA 控制器再向总线仲裁器或 CPU 去发出总线请求。
- **相对于 CPU，DMA 控制器总线使用权的优先级更高**——对。DMA 如果申请总线，你不及时把使用权给它，它就会存在数据丢失的可能，后果非常严重。
- **在整个数据块传送的过程中，CPU 不可以访问主存储器**——错。
- **数据块传送结束的时候，会产生 DMA 传送结束的中断请求**——对，在后处理阶段发出中断请求，让 CPU 去进行处理。

C 错在把"周期挪用"当成了"独占总线"。题目明明说的是周期挪用方式。

```text
   时间  ─────────────────────────────────────────────▶
   CPU   [访存][访存][让出][访存][访存][让出][访存]
   DMA               [借用一个总线周期][再借一个]
```

CPU 原本在访问主存，DMA 提出申请要去总线的时候，它只是挪用了一个总线周期去传送一次数据，接下来马上就把使用权还给 CPU。等它下一个数据准备好了，又会向 CPU 申请一次总线使用权，于是又挪用一个总线周期。所以在整个数据块传送的过程中，CPU 照样可以访问主存。

> **易错点**："周期挪用"和"独占"只差一个字，含义差得很远。挪用是插空拿走一个总线周期就还回去；独占（比如让 CPU 暂停访存的突发传送方式）才是整个数据块期间不让你碰主存。看到"周期挪用"四个字，脑子里就该冒出上面那行时间轴。

### 操作系统：从共享文件到临界区

#### 多个进程共享同一个文件，哪张表里只有一份

题干：若多个进程共享同一个文件 F，则下列叙述中正确的是。

- A 各进程只能用读的方式打开文件 F
- B 系统打开文件表中仅有一个表项包含 F 的属性
- C 各进程的用户打开文件表中关于 F 的表项内容相同
- D 进程关闭 F 的时候，系统删除 F 在系统打开文件表中的表项

**A 错。** 一个文件能读还是能写，取决于进程本身的操作权限，不是"多进程共享"这件事规定了大家只能读。

**B 对。** 系统打开文件表里记录的，是系统中所有"已打开文件"的信息。多个进程共享同一个 F，这份文件信息在系统里只有一份，落在系统打开文件表中；而每个进程的**用户打开文件表**，是靠一个指针指过去、返回文件描述符的。

```text
  进程 P1 的用户打开文件表        进程 P2 的用户打开文件表
  +----------------------+        +----------------------+
  |  fd = 3              |        |  fd = 5              |
  |  read ptr = 0        |        |  read ptr = 128      |
  +----------+-----------+        +----------+-----------+
           | 指针                           | 指针
           +-------------------------------+
                           |
                           v
    +-----------------------------------------------+
    |     系统打开文件表：关于 F 只有这一项            |
    |   存放 F 的属性：大小、权限、存储位置、时间      |
    +-----------------------------------------------+
    进程 P3 的用户打开文件表同理，同样指向上面这一项
```

读图：三个进程各自的用户打开文件表项内容都不一样，但都通过指针指向系统打开文件表里唯一的那一项——这就是 B 正确、C 错误的全部理由。

**C 错。** 用户打开文件表里关于 F 的表项内容**不相同**，因为这部分内容属于每个进程自己：文件描述符不一样，读写指针的位置也不一样。为什么要这么设计？就是为了让多个进程能独立地管理和访问同一个文件，彼此之间不需要做任何同步。

**D 错。** 某个进程 close 掉 F，不等于系统立刻就能把 F 的表项删掉。得先看还有没有别的进程正在访问这个文件——只有访问它的进程数等于 0 了，才能真正删除。

> **易错点**："系统打开文件表只有一项"和"用户打开文件表也相同"是两码事。多进程共享 = 系统中只有一份文件信息，不等于每个进程各有一份完整表项。

#### 索引分配为什么能同时拿下随机访问和长度可变

题干：下列选项中，支持文件长度可变、随机访问的磁盘存储空间分配方式是（　）。

- A 索引分配
- B 链接分配
- C 连续分配
- D 动态分区分配

**A 为什么对？** 索引块里存的就是所有的盘块号。要访问文件的第 i 个块，直接把那个盘块号从索引块里取出来，落到磁盘上对应位置就行——这就是**随机访问**。至于**长度可变**：文件长一块，我就往索引块里再写一个盘块号，完事；块数没超过一个索引块时，索引块本身甚至都不用改。

**B 链接分配**：默认是隐式链接，就是那种一个一个顺着链串起来的形式。访问必须按链的顺序一个一个走，顺序访问可以，**随机访问不行**。文件长度倒是可变的。

**C 连续分配**：随机访问没问题（起始位置加偏移就能算出目标块），但它要求文件占一整块连续空间，文件一长就得整体搬家，**不适合长度可变的文件**。

**D 动态分区分配**：它管的是存储当中存储单元的分配，说的是内存那一块；而我们这里问的是**磁盘**存储空间分配，概念对不上，排除。

> **结论**：四个选项里，索引分配是把"随机访问"和"长度可变"同时拿到的那个——因为盘块号被**显式地列在索引块里**了，它天生就是可扩展的。

#### 中断这件事，硬件和操作系统各干哪一段

题干：下列与中断相关的操作中，由操作系统完成的是（　）。

- 1 保存被中断程序的断点
- 2 提供中断服务
- 3 初始化中断向量表
- 4 保存中断屏蔽字

**1 是硬件干的。** 断点指的就是 PC，也就是程序计数器。发生中断时，PC 的值必须由硬件在响应中断的那一刻自动压栈——操作系统是在这之后才知道出事了。所以 1 排除。

**2 是操作系统的。** 提供中断服务，指的就是执行中断服务程序，这套服务由操作系统内核提供。

**3 初始化中断向量表——这个也是操作系统的**，而且是操作系统初始化阶段就得做完的事。为什么必须放在初始化里？我们顺着往下想：计算机刚通电的时候，内存里面是没有任何表格的；而操作系统它初始化的过程当中，**完全可能产生中断**——从开机那一瞬间起，随时都有可能来中断。如果这时候还没有中断向量表，中断一来你根本无从处理，系统直接崩。所以只能在操作系统初始化的这段时间，先把中断向量表建好，后面发生中断才有的查、有的跳。后面讲到操作系统初始化的具体步骤时，我会把这块展开，这里大家只要记住"它由操作系统完成、且在初始化阶段完成"就够了。

**4 保存中断屏蔽字，也是操作系统的。** 它属于保护现场：除了通用寄存器之外，中断屏蔽字同样需要被保存。

所以 2、3、4 都对，选 D。

> **提示**：这一类题目问"哪些归硬件、哪些归操作系统"，判断标准就一条——**这一步是不是必须由硬件在响应瞬间自动完成**。断点（PC）的保存是硬件的，因为中断来的那一刻软件还没拿到控制权；其余三项都是软件可以做的。

#### 多级反馈队列，调度前要先定哪几件事

题干：下列与进程调度有关的因素中，在设计多级反馈队列调度算法时应该考虑的是（　）。

- 1 就绪队列的优先级
- 2 就绪队列的数量
- 3 各就绪队列的调度算法
- 4 进程在就绪队列间迁移的条件

把多级反馈队列的图摊开来看，这四件事一件都跑不掉。

**1 优先级。** 每一个就绪队列的优先级都是不一样的，上面高、下面低，不然"多级"就毫无意义。既然优先级不一样，那优先级怎么设置就必须考虑。

**2 队列数量。** 到底分几级？这个数量要定下来。

**3 各就绪队列的调度算法。** 不同的队列完全可以采用不同的调度算法，它的时间片设置也可以不一样——通常是越往下时间片越长。

**4 队列间迁移的条件。** 一个进程在某个队列里用完了自己的时间片，是直接降到下一级？降的条件怎么设？它会直接影响一个进程在各级队列里执行的总时长。

1、2、3、4 全都要考虑，选 D。

#### 银行家算法：一步步把安全序列走出来

题干：某系统中有 A、B 两类资源，各 6 个。T 时刻各进程的资源分配和需求情况如下表，要求求出安全检测的结果，也就是存不存在安全序列。

表里每一行，**前面是已经分配出去的，后面是它的总需求量**。所以"还差多少"要用总量减去已分配：

| 进程 | 已分配 A | 已分配 B | 总需求 A | 总需求 B | 还需 A | 还需 B |
| --- | --- | --- | --- | --- | --- | --- |
| P1 | 2 | 3 | 4 | 4 | 2 | 1 |
| P2 | 2 | 1 | 3 | 1 | 1 | 0 |
| P3 | 1 | 2 | 3 | 4 | 2 | 2 |

- P1：4-2 = 2，4-3 = 1
- P2：3-2 = 1，1-1 = 0
- P3：3-1 = 2，4-2 = 2

再看系统手里还剩多少：A 总共 6 个，已经分出去 2+2+1 = 5 个，**还剩 A 一个**；B 总共 6 个，已经分出去 3+1+2 = 6 个，**还剩 B 零个**。所以当前可用量是 **(1, 0)**。

现在只有一个 A 可分配，谁的剩余需求能被满足？P2 的还需是 (1, 0)，正好卡上。**第一个选 P2。**

P2 执行完，把它已经占的资源释放出来：可用量变成 (1+2, 0+1) = **(3, 1)**。

接下来可以分配给谁？P1 的还需是 (2, 1)，(3, 1) 够。**第二个选 P1。**

P1 执行完，把它已分配的资源再加回来：可用量变成 (3+2, 1+3) = **(5, 4)**。

P3 的还需是 (2, 2)，(5, 4) 够。**第三个选 P3。**

三个进程都能依次拿到资源并跑完，说明系统存在安全序列：**P2 → P1 → P3**，答案选 B。

> **易错点**：安全序列不是"能排出来一个"就算完，它的意义在于——按这个顺序执行，每个进程要的资源都一定拿得到，所以系统不会陷入死锁。而且第一个选谁不是随便挑的，必须是**当前可用量能满足其剩余需求**的那一个；本题一开始只有 A 剩 1 个，所以那个还需 B 为 0 的 P2 才是突破口。

#### 请求分页的平均访存时间，被谁拖住

题干：下列因素中，影响请求分页系统有效平均访问时间的是（　）。

- 1 缺页率
- 2 磁盘读写时间
- 3 内存访问时间
- 4 执行缺页处理程序的 CPU 时间

**1 缺页率——会影响。** 缺页率越高，说明页面不在主存当中的概率越大，那就越频繁地要从外存把页面调入内存。这个调入的过程非常耗时，缺页率越高，你额外要付的缺页处理开销就越大。

**2 磁盘读写时间——会影响。** 一旦发生缺页，页面从外存读进内存，走的就是磁盘。磁盘读写时间越长，平均访存时间一定越长。

**3 内存访问时间——会影响。** 它本身就是访存时间。而且要注意，我们做地址转换时每次都要访问页表，页表在内存里；拿到物理地址再去访问数据，数据也在内存里——两次访存都摊在这上面。

**4 执行缺页处理程序的 CPU 时间——会影响。** 缺页处理程序跑得越久，平均访存时间就越长。

四项全对，选 D。

> **结论**：把四个角度分开看就清楚了——**缺页率**决定"要额外处理多少次"，**磁盘读写时间**和 **CPU 处理时间**决定"每次处理要花多久"，**内存访问时间**决定"基础的那一趟有多慢"。这四条任何一条变坏，平均访存时间都会被拖长。

#### 父子进程之间，哪些话不成立

题干：下列关于父进程和子进程的叙述中，错误的是（　）。

- A 父进程和子进程可以并发执行
- B 父进程与子进程共享虚拟地址空间
- C 父进程和子进程有不同的进程控制块
- D 父进程与子进程不能同时使用同一临界资源

**A 对。** 它俩是两个独立的进程。就批处理系统来说，多道程序并发执行本来就是操作系统的基本特征。

**B 错。** 这就是本题要的答案。我们前面一再强调：父进程和子进程是两个**独立进程**，有各自**独立的虚拟地址空间**，是**不能共享**的。

**C 对。** 两个进程自然就有两个不同的 PCB，PCB 里记录的资源信息也可能不一样。

**D 对。** 对于临界资源的访问必须保证互斥。父进程和子进程作为两个进程，在访问同一临界资源时只能互斥访问，同一时间段内只能分配给其中一个。

所以错误的是 B。

> **易错点**：B 说"共享虚拟地址空间"，D 说"不能同时使用同一临界资源"——这两句听起来矛盾，其实说的完全是两码事。**地址空间各自独立**是进程的定义使然；**临界资源互斥**是临界区机制的要求。地址空间独立，不代表两进程没有共同的资源可用。

#### 设备独立性：换了设备要不要改程序

题干：对于具有设备独立性的系统，下列叙述中错误的是（　）。

- A 可以使用文件名访问物理设备
- B 用户程序使用逻辑设备名访问物理设备
- C 需要建立逻辑设备与物理设备之间映射关系
- D 更换物理设备后，必须修改该设备的应用程序

先说清楚设备独立性到底独立了什么：具有设备独立性，我手里的**文件名其实就相当于一个逻辑设备名**；系统可以把这个逻辑设备名转换成物理设备名，然后才去和物理设备打交道，用户程序完全不需要直接和底层的驱动程序交互。

- **A 对**：文件名在设备独立性的系统当中就是这样一个逻辑名称。
- **B 对**：正因为有设备独立性、有了这样的映射机制，逻辑设备名才能直接转换成物理设备名。
- **C 对**：这套映射关系，就是设备独立性本身要建立的东西。
- **D 错**：既然我提供了逻辑设备名和物理设备名之间的映射，那么更换物理设备之后，**我只需要更新它们之间的映射关系**就可以了，完全不需要去更改访问这个设备的应用程序。

这就是 D 错的地方，也是本题的答案。

> **结论**：设备独立性的价值在于——它让应用程序只认逻辑设备名，把"程序对具体设备的依赖"压缩成了**一张映射表**。所以换硬件时改表，不改程序。

#### 64 字节的目录项，能撑起多少文件

题干：某文件系统的目录由文件名和索引节点号构成，如果每个目录项的长度是 64 字节，其中 4 字节存放索引节点号、60 字节存放文件名，文件名由小写英文字母构成，则该文件系统能创建的文件数量上限是多少。

先看目录项的构成：前 60 个字节是文件名，后 4 个字节是索引节点号。

**真正的瓶颈在索引节点号这一头。** 索引节点号指向的就是索引节点，这个号能有多大，就决定了系统里能有多少个索引节点。它占 4 个字节，也就是 32 位，所以索引节点总数最多是 $2^{32}$ 个。而一个文件对应一个索引节点去存放它的元数据，所以文件数量的上限也就是 $2^{32}$ 个。

答案选 B。

> **提示**：这类题的关键永远是**找那个位数最少、编号空间最小的东西**。目录项 64 字节看着很大，但真正决定文件数量上限的，是里面那个 4 字节的索引节点号。

#### 临界区四条准则，哪条不是必须的

题干：下列准则中，实现临界区互斥机制必须遵守的是（　）。

- 1 两个进程不能同时进入临界区
- 2 允许进程访问空闲的资源
- 3 进程进入临界区的时间是有限的
- 4 不能进入临界区的处于就绪态的进程立即放弃 CPU

逐条对上号：

**1 忙则等待。** 当一个进程进入临界区时，另一个不能同时进，必须对临界区保持互斥的访问。这就是互斥机制的本职。

**2 空闲让进。** 当临界资源空闲的时候，必须允许进程进入访问，不然资源就白白闲着了。

**3 有限等待。** 进程进入临界区的时间是有限的——它提出了进入请求，就不能在无限期地等下去。

**4 让权等待。** 进不去临界区的就绪态进程**立即放弃 CPU**——这一条是**不必要的**。正确的要求只有第 3 条的"有限等待"：它最终能进得去就行；至于是让出 CPU 干等着，还是继续占着 CPU 空转，准则并没有硬性规定。所以忙等的做法同样能满足前三条。

所以 1、2、3 必须遵守，4 不必须，答案选 C。

> **易错点**：临界区这四条准则是有强弱之分的。忙则等待、空闲让进、有限等待，是任何互斥机制都必须满足的**必要条件**；让权等待是一个更强、更"文明"的要求，**不满足它不代表你的互斥机制有问题**。这一条是本题最常被多选进去的坑。

### 计算机网络：协议、虚电路、时延与 DNS

#### 协议三要素：图上画的是时序

第 33 题考协议三要素。先把老底翻出来：**语法、语义、时序**。

题目给的是一张交互图：发送方先发给接收方一个数据报，接收方对它进行确认之后，发送方再发送一个。这跟三次握手的样子很像。它表达的是什么？**我必须接收到你的确认帧，才能发送下一个数据帧。**

所以它描述的正是信息发送的**顺序**，答案落在**时序**上。

那么语法和语义分别指什么呢？我们可以从学英语的经验里迁移过来：

- **语法**。学语法的时候，主语、谓语这些成分告诉你一句话该怎么说、该怎么构造；通过学语法，我们能知道当前要怎么去说这个句子。同理，一个协议里的语法部分，描述的就是**我们交流数据信息时的格式**——数据报由哪几个字段组成、每个字段多少位、顺序怎么排。
- **语义**。语义是当前这句话**表达的含义**。比如我们发送 HTTP 报文的时候，里面的**格式**问题就是语法；而这个报文要表达的**意思**——要获取什么，或者要从哪台主机、哪个页面上获取信息——就是语义。

三要素，每个都要知道它的含义，题目给了信息要会选。

> **结论**：**语法管格式，语义管含义，时序管顺序。** 凡是题目里出现"顺序、先后、先……才……"这类描述，就是时序。

这块内容在我们真题中不止出现过一次，大家要把它理解透。

#### 虚电路和数据报，差别到底在哪

第 34 题单独把虚电路拎出来考，而虚电路和数据报本来就是对着干的两个东西，放在一起对比才看得清。

题目问的是**错误**的是哪一个：A 可以确保数据分组按序到达，B 需要为每条虚电路预分配带宽，C 建立虚电路时需要进行路由选择。

**先说 A 错在哪。** 数据报服务是**一定无序**的：它把每一个分组都当成独立的一包，面朝路由器就随机选择一条路线。既然在整个网络中每个分组走的路线不同、花费的时间也不同，那么到达接收方的顺序也一定不同。**对数据报服务来说，它一定是无序的，没办法保证按顺序到达。**

虚电路就不一样。**虚电路和数据报唯一的区分点，就是它"有连接"**——而这个连接是**逻辑上的连接**，并不是说物理上拉了一条线路。

连接建立的过程是这样的：虚电路最开始的那个分组，也就是路由分组，从出发点到我们的终点，沿途通过路由选择**选定一条固定的路径**，为之后的分组把这条路径开辟出来。这条路径就是它所谓的"连接"。此后每一个分组只需要携带 D 选项里说的那个 **VCI（虚电路号）**，中间设备根据这个识别号就知道它当前只走这一条路就行了。线路是固定的，所以分组的顺序也就是固定的。

**再说 B 错在哪，这是本题的答案。** 我刚才特意强调了：它是**逻辑连接、非物理连接**。逻辑连接的意思是——我们在众多线路中选一条，作为我们接下来所有分组的走向，而不是在起始点和终点之间专门为这两方通信建立一条独占的信道。而"**带宽**"这个词通常都是和链路绑定的，是你当前这条链路上有指定的带宽。所以"为每条虚电路预分配带宽"这句话翻译过来就是"为每条虚电路分配一条物理链路"——那不就变成物理连接了吗？既然是逻辑连接，就没有为它预分配带宽这一说。B 错，排除。

**C 是对的。** 什么时候进行路由选择？就是刚才说的第一个分组——它为后面所有的分组开辟整条线路，也就是建立虚电路的时候，需要进行路由选择。连接一旦建好，之后每一个分组都不需要了，只需要依据虚电路号进行数据分组的转发。

| | 虚电路 | 数据报 |
| --- | --- | --- |
| 连接 | 面向连接（逻辑连接） | 无连接 |
| 顺序 | 按序传输 | 不保证顺序 |
| 路由选择 | 仅建立时做一次 | 每个分组都要做 |
| 转发依据 | 虚电路号 VCI | 完整目的地址 |

> **结论**：虚电路的"有连接"，指的是**第一个分组把后续分组的路径固定下来**；它的软肋也在这里——只要这条线路上有一个路由器、或者某一部分网络瘫痪了，你的整条线路就得重新连接，相当于报废了。而数据报服务不是这样，它可以绕开瘫痪的路由器，走其他线路。

#### 冲突域与广播域，怎么数

第 35 题要在一个网络拓扑里数出冲突域和广播域的个数。

这三种设备，我们讲设备的时候反复强调过好几遍，从高层往低层这么记：

| 设备 | 分割冲突域 | 分割广播域 |
| --- | --- | --- |
| 路由器 | 可以 | 可以 |
| 交换机 | 可以 | 不可以 |
| 集线器 | 不可以 | 不可以 |

回到图里：中间那个是路由器，两边各挂一台交换机（方块上带好几个箭头的），交换机下面那个方块带一个箭头的，是集线器。

**广播域**：只有路由器能分割。图中除了路由器以外的设备都不分割广播域，所以只能由这个路由器把网络分成两块，**广播域 = 2 个**。

**冲突域**：集线器什么都不分割，先把它排除，剩下看交换机。记住一句口诀——**交换机的一个接口，就是一个冲突域**。图中两台交换机上，连接着主机的接口一共有 4 个，所以 **冲突域 = 4 个**。

> **易错点**：有同学会问，交换机连到路由器的那段点对点链路，为什么不算一个冲突域？我们回到冲突域这个概念本身：冲突域实际上是指在**当前的这条链路上**连接的所有主机之间会冲突，也就是你当前一条主机发送信息，可能会和另外一条主机发生冲突，**在所在的这个范围内**才叫冲突域。而这道题里，那条点对点的链路上并没有主机挂着，所以它并不能称为一个冲突域。**有主机挂载的那个接口，才叫做一个冲突域。**

所以答案是 4 个冲突域、2 个广播域，选 C。

> **结论**：**广播域只有路由器能分，冲突域路由器和交换机都能分。** 再顺带记一句：如果路由器的某一个接口下面还连着多个主机，那一部分网络本身又是一个冲突域，同时也是另一个广播域。

#### 停止等待协议的信道利用率

第 36 题：采用停止等待协议，甲向乙主机发送数据，数据帧和确认帧长度告诉我们了，数据传输速率是 10 kbps，单向传播延迟是 200 ms，问最大的信道利用率。

对停止等待协议来说，它只能在一个发送周期内发送一个数据帧，所以就算帧再大，它也大不了 100%。信道利用率的公式是：

$$
U = \frac{T_d}{T_a + T_d + 2T_p}
$$

分母这一长串就是：**一个发送周期 = 发数据帧的时延 $T_d$ + 等确认帧回来的往返时延 $2T_p$ + 回发确认帧的时延 $T_a$**。也就是总共我们发送数据帧、它在线路上传播、发送确认帧、确认帧再在线路上传播这一整段。

本题数据帧和确认帧长度相同，所以 $T_a = T_d$，算起来就等于 $2T_d + 2T_p$。

> **易错点**：算 $T_a$ 和 $T_d$ 的时候，一定不要忘了**把字节转化成比特**，别拿 1000 直接去除。

$$
T_d = T_a = \frac{1000 \times 8}{10^4} = \frac{8000}{10000} = 0.8\ \text{s}
$$

单向传播 200 ms，两个方向加起来就是 400 ms = 0.4 s，所以

$$
U = \frac{0.8}{0.8 + 0.8 + 0.4} = \frac{0.8}{2} = 0.4 = 40\%
$$

答案选 D。

> **提示**：信道利用率的公式一定要记住——**发送时间 ÷（发送时间 + RTT + ACK 的发送时间）**。另外，计算过程中尽量让它保持简洁，不要把分数带入到分数中，那样不太好算。本题虽然没有涉及，但有一些题目大家千万不要给自己添加困难。

#### 里的帧间间隔，谁最长

第 37 题考 IEEE 802.11 无线局域网。使用 CSMA/CA 的过程中，题目问的是主机或 AP 在发送帧前所等待的帧间间隔中，最长的是哪一个。

无线局域网中避免冲突的方式就是 CSMA/CA，它用**帧间间隔**来把冲突挡在门外。题图上有 4 个 IFS（这个图比较小，大家可以看一下自己试卷上的图），按 1、2、3、4 的顺序排列。

CSMA/CA 发送帧的套路是这样的：

- **第一个帧**发送之前，无论它是使用了信道预约的 RTS、还是用了 CTS、还是根本没有使用信道预约而直接发送数据帧，它都需要等待 **DIFS** 的时间。
- **除了第一个以外的所有其他帧**，发送之前都只需要等待 **SIFS** 的时间。

```text
   IFS1        IFS2      IFS3      IFS4
   (DIFS)      (SIFS)    (SIFS)    (SIFS)
      |          |          |          |
  ==\=|======|=|=====|===|=|=====|===|=|===========  数据流
  数据帧     确认帧    下一帧    确认帧
      ^          ^          ^          ^
      |          |          |          |
   第一个帧   后续帧都要等 SIFS（更短，抢在别人插话之前）
```

读图：紧跟第一个数据帧之前的那个间隔最长（DIFS），后面所有的帧都只等 SIFS。

既然 DIFS 和 SIFS 的大小肯定是 **DIFS 大于 SIFS**，那么最长的自然就是我们的 IFS1。

答案选 A。

> **结论**：DIFS > SIFS；**第一个帧前等 DIFS，后续帧前等 SIFS**。这道题是纯记忆题，知道 CSMA/CA 的发送流程就能做出来。

#### 拥塞窗口从 8KB 涨到 32KB，最长要多久

第 38 题：甲和乙之间建立了一个 TCP 连接，往返时延 2 ms，已知在不出现拥塞的前提下，拥塞窗口从 8 KB 增长到 32 KB 所需的最长时间是多少。

看到"**最大分段**"这四个字，脑子里就该跳出一个词：**本题考虑的是拥塞控制**。

这里有个坑：题目没有明确说 8 KB 和 32 KB 到底处于慢开始阶段还是拥塞避免阶段。怎么办？抓住那句关键信息——"**最长时间**"。这四个字就是解题的钥匙：

- 如果走的是**慢开始**：8 KB 涨到 16 KB，16 KB 涨到 32 KB，翻倍，只要经历 **2 个 RTT** 就完事了。
- 如果走的是**拥塞避免**：8 涨到 9、9 涨到 10、10 涨到 11……一直加 1 涨到 32 KB，**每涨 1 个就经历 1 个 RTT**。

要取最长，当然是取后者——当它从 8 到 32 的过程中**一直处于拥塞避免阶段**时，经历的时间最长。

中间有多少个间隔呢？$32 - 8 = 24$，所以是 24 个 RTT：

$$
(32 - 8) \times 2\ \text{ms} = 24 \times 2\ \text{ms} = 48\ \text{ms}
$$

答案选 D。

> **易错点**：算出 24 个 RTT 之后，**不要忘了每个 RTT 是 2 ms**，别只写个 24 就选 C 了。另外，这类"问最短或最长"的题目我们之前也遇到过——**问最短就是全程慢开始（翻倍），问最长就是全程拥塞避免（每次加 1）**；所以题目没给阶段信息时，就用"最短/最长"这两个字去反推它属于哪一阶段。

#### SYN 1000、FIN 5001，中间发过多少字节

第 39 题：甲和乙建立 TCP 连接时，甲发送的 SYN 的序号是 1000；断开连接的时候，甲发送给乙的 FIN 的序号是 5001。在没有任何重传的情况下，问甲向乙已经发送的字节数是多少。

先把两个序号的含义摆清楚，这是第一步：

- **SYN 消耗一个序号**。所以甲发送的**第一个数据字节**，序号是 $1000 + 1 = 1001$。
- **FIN 也消耗一个序号**。FIN 的序号是 5001，也就是说它**前面**那个数据字节是 5000，也就是**最后一个数据字节的序号是 5000**。

于是中间这段应用层数据的字节数就是**尾减首再加一**：

$$
5000 - 1001 + 1 = 4000
$$

> **提示**：还有另一种更省事的算法——**直接用两个"接下来要发的序号"相减，不用加一**。拿 FIN 的序号 5001 减 SYN 之后的 1001：$5001 - 1001 = 4000$。两种算法的区别就在于要不要 +1，别搞混。

所以我们得到的应用层数据字节数就是 4000，答案选 C。

> **结论**：TCP 里凡是问"已知数据的首字节和尾字节，问发送了多少字节"，一律**尾巴减首再加一**；如果给的是各自"下一个要发的序号"，那就直接相减。**SYN 和 FIN 各消耗一个序号**，这是整个计算的起点。

#### DNS 递归与迭代，最短 20ms、最长 50ms

第 40 题是这一块最综合的一题。题目设定：某网络的本地域名服务器**只提供递归查询**，其他域名服务器**只提供迭代查询**；局域网内主机访问 Internet 上各服务器的往返时间均为 10 ms，忽略其他各种时间。问主机通过超链接请求一个 web 页，从点击链接开始到浏览器接收到页面为止，所需的最短和最长时间是多少。

先把两个词理顺，这个理顺了题目就做完了：

- **递归查询**。我们就想到数据结构里的函数递归——一层一层往下的，并且会一层一层地把结果返回来。**本地域名服务器**就是这样：我们的主机向本地域名服务器查询时，接下来的任务都要交给本地域名服务器，它去一层层地问、一层层地拿回答案，最后交到主机手上。
- **迭代查询**。本地域名服务器向其他域名服务器查询时，它会**等待来自对方的一个确认**，然后自己再发下一个请求、再等下一个确认——**所有的请求都由本地域名服务器自己发出**，而不是让对方替它查到底。

> **易错点**：题目说的是"局域网内主机访问 **Internet 上**各服务器的往返时间均为 10 ms"，重点在"Internet 上"这个限定上。也就是说，主机向本地域名服务器发请求的那一跳，题目并没有给时间，所以**忽略不计**。这个措辞很坑，读题的时候一定要圈出来。

#### 最短时间

首先我们可以认为：当前本地域名服务器中有缓存，或者主机自身有缓存——也就是 `www.abc.com` 这个域名对应的 IP 我们可以直接获取，不需要去向 Internet 中的域名服务器请求。

接下来看 HTTP：题目并没有明确说我们用的是哪个 HTTP 版本，那我们不去纠结这个，只按最省的方式算：第 1 个 RTT 用于两次握手，第 3 次握手用来请求数据，第 4 次用于接收数据。假设这个页面在此时已经完全接收了，并且它是**纯文本**的，没有任何图像、链接之类的东西，不需要再次请求。

所以这时候 RTT 一共是两个：

$$
T_{\min} = 2 \times 10 = 20\ \text{ms}
$$

#### 最长时间

最长时间就是我们当前**没有缓存**的情况，那就得去查询这个域名对应的 IP。

首先主机向本地域名服务器发送请求，**这个时间是忽略不计的**。然后本地域名服务器一层一层往下问：

```text
   主机 H       本地域名服务器        根 DNS       .com DNS      abc.com 权威
     |                |                |             |              |
     |--- 递归查询 -->|                |             |              |  (忽略)
     |                |--- 迭代请求 -->|             |              |  RTT 1
     |                |<-- .com 位置 --|             |              |
     |                |                |--- 迭代请求 ------------> |  RTT 2
     |                |<-- 权威服务器位置 ------------|              |
     |                |                |             |--- 迭代请求 -> |  RTT 3
     |                |<--- www.abc.com 的 IP --------------------  |
     |<-- 返回 IP -----|                |             |              |
     |                                                                  |
     |  ====== TCP 三次握手 ========== 1 个 RTT ======================  |
     |  ====== 请求 + 接收页面 ========= 1 个 RTT ======================  |
```

读图：上方 3 个 RTT 走完 DNS，下方 2 个 RTT 走 HTTP，一共 5 个 RTT。

- 本地域名服务器先向**根域名服务器**请求，根域名服务器告诉它 `.com` 顶级域名服务器的位置——**1 个 RTT**；
- 然后它根据根告诉的信息，去请求 `.com` 域名服务器，`.com` 告诉它 `abc.com` 权威服务器的位置——**第 2 个 RTT**；
- 然后去请求 `abc.com`，这个时候它返回回来的信息，其实就**包括了 `www.abc.com` 的 IP 地址**——**第 3 个 RTT**。

这样 3 个 RTT 就把域名对应的 IP 拿到了。接下来它仍然会经历同样的 2 个 RTT，去请求和接收 web 页。

$$
T_{\max} = (3 + 2) \times 10 = 50\ \text{ms}
$$

答案选 D。

这一题把 HTTP 访问、DNS、TCP 连接和信息数据传输全都串起来了，算是比较综合的题目。这里如果再复杂一点，它可以这样问：当前这个 web 页的大小告诉我们，最大段长 MSS 等于 1 KB，然后它的文本页是 2 KB——那就可能还要考虑到 TCP 的拥塞控制。但这道题目没有涉及这些条件，所以大家要**适当地看题目给了什么信息、没给什么信息，考虑什么、不考虑什么**。

### 三个有序集合的最小距离

第 41 题转到数据结构，是个代码题。

题干先交代清楚：统考真题给了一个"三元组"，所谓三元组其实就是一个元素，它由三个数字组成，并且三个都是整数——这就说明这一个数据元素是由三个 int 类型的整数组成的。他们三个数之间的距离是这样计算的，就是两两差的绝对值加起来。题目要求：给定三个非空整数集合 S1、S2、S3，都按升序分别存储在三个数组中，设计一个**尽可能高效**的算法，计算并输出所有可能的三元组 (a, b, c)（a 属于 S1、b 属于 S2、c 属于 S3）的最小距离。

> **提示**：注意"**尽可能高效**"这个措辞——它并没有说时间还是空间，那就意味着**时间和空间都尽量低**，两个维度一起考虑。

#### 先把 D 算清楚

拿到一个三元组，$d$ 怎么算？就是把 a、b、c 之间的**两两绝对差全部加起来**。这个式子看起来很复杂，但如果高中的知识没忘，你会立刻发现它可以化简。

在数轴上，$|a-b|$ 就是 a 和 b 之间的距离，不管 a 大还是 b 大，相减的绝对值一定是它们在坐标轴上那一段。我们现在还不知道 a、b、c 谁大谁小，先假设是 $b < a < c$：

```text
     b -------- a -------- c
     |   |a-b|     |a-c|   |
     |         |b-c|       |
```

读图：上面一行是三个数在数轴上的位置，中间一行标出 $|a-b|$ 与 $|a-c|$ 两段，最下面一行是横跨 b 到 c 的 $|b-c|$。

因为 $|a-b| + |a-c| = |b-c|$，所以

$$
d = |a-b| + |a-c| + |b-c| = 2 \times (|b-c|) = 2 \times (\max - \min)
$$

虽然我列举的时候是 c 最大、b 最小，但也有可能是 c 最小、a 最大——无论它们是哪一个，我们能够确定的结论都一样：

> **结论**：**最终的这个 $d$，其实是三个数中最大值减去最小值的两倍。** 也就是说，d 的大小只由三个数中的最大值和最小值决定。

#### 三重循环：能想出来，也能拿一半分

最直观的思路是什么？**简单选择**。我们维持一个 min 值，让它一开始是一个尽量大的数，比如 1 万，然后每次找到不同的 (a, b, c) 去计算这个 $d$ 值；如果 $d$ 小于 min，就让 min 等于 $d$。这样当你算完所有可能的三元组之后，min 里一定存的就是最小距离。这个就是简单选择的思路。

那"所有可能的三元组"要怎么枚举？$d$ 是由 a、b、c 算出来的，而 a、b、c 位于 S1、S2、S3 中，那自然就能想到去**遍历**它们三个。既然是遍历，那必然选用的就是**三重 for 循环**：外层 i 从 0 到 S1 的长度，依次往里嵌套，第二层是关于 S2 的指针，第三层是 S3。（真的做题的时候，S1、S2、S3 会作为参数传进来，比如 m、n、k 这样的长度。）每次把 S1[i]、S2[j]、S3[k] 用公式算出 $d$，再拿这个 $d$ 和我们的 min 做比较：如果 d 小于 min，就让 min 等于 d。最终当三层 for 循环全部结束，min 就是最小值了。

这个其实是一种**暴力解法**。不过这个暴力解法相信大家都能够想到，因为我们从"求最小值"中就可以知道，必然是要列举出全部的 $d$ 的可能值，才能找到最小值。$d$ 是由 (a,b,c) 计算的，而所有的 (a,b,c) 的组合既然存在于这三个集合中，那我们就用三层 for 循环把所有可能的组合都列出来。

它的**时间复杂度是 $O(n^3)$**（三个集合长度不严格相等，但大致认为是立方级别的就可以了），**空间复杂度是 $O(1)$**。

这时间复杂度非常高，我们理想的是 $O(n)$。

> **提示**：这个暴力解法大家都能想到，**大概能够拿一半的分数**。因为"从所有取值中取最小值"这个想法是对的，$O(n^3)$ 的枚举方式不对。所以先把暴力写出来、把它讲清楚，是拿到那半分的好办法。

#### 三个指针：把 O(n^3) 压成 O(n)

那这道题到底该怎么解决？还是刚才说的那个启发——**用三个指针**。之前那道真题"三个序列找公共元素"，就是三个指针分别遍历这三个序列，让较小的（不是最大值的）那两个序列的指针往后移，这样就能遍历到公共元素。

那道题是找公共元素，这道题是找距离的最小值。骨架可以照搬，但关键是要**分析清楚这个距离和 a、b、c 的取值到底有什么样的关系**。

有了前面那一节的化简，答案就出来了：**d 由最大值和最小值决定，而我们想让它变小。**

**所以我们把问题变成了：在三个数中找到那个最小的值，让它的指针往后移动。** 为什么？一旦最小值往前移动了，max - min 就缩短了，d 就更小了。而因为每个数组都是升序的，它一旦往后移动了，那就代表着它指到的值只可能增大；一旦它增大了，$d$ 的值就会变小。

```text
   S1:  -2   0   3   7  11  ...   <- 指针 i
   S2:   1   4   6   9  12  ...   <- 指针 j
   S3:   5   8  10  13  15  ...   <- 指针 k

   每轮做三件事：
     1) 算出 d = 2 * (三个数中的 max - min)，与 dmin 比较后更新
     2) 找出三个指针所指元素中的最小值
     3) 只把"最小值"那一根指针后移一位
   结束条件：其中任意一根指针走到末尾
```

读图：三根指针各自在三个升序数组上单调向前滑动，每一轮只推进当前最小值所在的那一根，这样 min 只会增大而另外两路不动，得到的 d 就只会越来越小。

正确性也很直观：整个遍历过程是在升序序列中进行的，它只会让最小值增大，而那两个非最小值不动，所以移动过程中找到的值只会比前面的更小，而不会更大——这样我们就能够找到所要的最小距离了。

#### 代码怎么写

先把这个 $d$ 的计算拆成一个独立的函数，把整个程序分块儿，这样比较好看。

绝对值可以直接用数学库里的 `abs`（传入一个数字，返回它的绝对值）；如果不想直接用，自己写一个也完全可以：

```c
int myabs(int x) {
    if (x < 0)
        return -x;
    else
        return x;
}

/* 计算三元组的距离：两两差的绝对值之和 */
int calculateD(int a, int b, int c) {
    return myabs(a - b) + myabs(b - c) + myabs(c - a);
}
```

> **提示**：写成 `myabs(a-b) + myabs(b-c) + myabs(c-a)` 这种循环形式，和题目定义的 `|a-b| + |a-c| + |b-c|` 完全等价——三对数两两取绝对差，集合本来就一样。写代码的时候，其实就是把题目给的公式变成我们的 C 语言。

这个小函数完成以后，再来考虑主函数。它想让我们输出最小距离，所以我们把求出来的 dmin 直接返回出去，调用方打印即可。传入的必然是三个序列，它们是非空整数集合，所以直接把数组传进来就行；但因为是数组，**光靠数组名拿不到长度**，所以要在参数里继续传入它们的长度，假设是 m、n、p。

```c
int minTriple(int S1[], int S2[], int S3[], int m, int n, int p) {
    int i = 0, j = 0, k = 0;   /* 三根指针 */
    int dmin = 10000;          /* 先给 D 的最小值设一个比较大的初值 */

    /* 三个指针都不能到达尾巴 */
    while (i < m && j < n && k < p) {

        /* 先算出当前这三个数的距离 */
        int d = calculateD(S1[i], S2[j], S3[k]);
        if (d < dmin)
            dmin = d;          /* 保证 dmin 永远是当前最小值 */

        /* 找出三个数中的最小值，把对应指针后移 */
        if (mymin3(S1[i], S2[j], S3[k]) == S1[i])
            i++;
        else if (mymin3(S1[i], S2[j], S3[k]) == S2[j])
            j++;
        else
            k++;                /* 剩下的一个必然就是 S3 的 */
    }

    return dmin;               /* 返回找到的最小距离 */
}
```

逐段看几个关键点：

- **循环条件是 `i < m && j < n && k < p`**。只要有一根指针到达了末尾，我们就不往下再计算了——因为它已经到头了，没法再继续往下走，此时 dmin 就是我们想要的答案。
- **每一轮先算 d、再更新 dmin，最后才移指针**，顺序不能乱。
- **取三个数中最小值的函数**可以定义成 `int mymin3(int a, int b, int c)`，用一个 `return` 加叠加的三目运算符就能计算出来。这个我就不给大家完整写了，因为前面有一个真题已经展示过如何取三个数中的最大值，大家可以借用那个写法来练习一下怎么取三个数中的最小值。
- 移动完指针，就回到循环开头，重新计算新的 $d$、再更新 dmin，这样整个逻辑就闭环了。

**复杂度**：它把整个序列都可能会遍历到，**时间复杂度是 $O(n)$**，并不会像暴力解法那样不断重复地遍历；也没有用到任何额外的辅助空间，**空间复杂度是 $O(1)$**。很明显，相对于暴力解法来说这就是比较优秀的解法了——暴力大概能拿一半的分，而更优一点的解法如果解对了就可以打满分。

#### 和"三个序列找公共元素"放一起记

20 年的这道考题，其实是可以由我们在题目讲解部分那道"三个序列找公共元素"的真题启发而来的——**它们都是三个指针同时遍历**，这样就能大大减少时间复杂度。

在这个过程中，我们要学会迁移的是这个思路框架：

1. 分析题目想让我们找到的结果**是怎么计算的**；
2. 分析这个结果**随着各个指针的变化会怎么变**；
3. 据此决定**指针来去怎么移，才能保证不遗漏地获取到所有可能的、他要的那个结果**。

所以这两道题的区别，就是"**到底移动指针是怎么移的**"这一件事，而剩下的部分除了计算公式不同，思路都是一模一样的。

建议大家把 20 年的这道考题和题目讲解的第三题放在一起记忆，做成笔记上的对照，**分析它们的共同之处，感受一下它们的思想到底有什么不同**。

### 从"前缀特性"四个字认出哈夫曼编码

> **定义**：如果任意字符的编码都不是其他字符编码的前缀，称这种编码具有前缀特性。

题干甩过来的是一整套条件：字符集大于两个字符、不等长编码、每个字符的编码均是二进制的 0、1 序列、最长为 $L$、具有前缀特性。还没翻到问题，这几句描述其实都在暗示——这道题考的就是哈夫曼编码。

怎么认出来的？就两条。第一，前缀特性，这概念我们学哈夫曼编码的时候就被定义过；第二，它给了一个字符集，还给集合里每个字符都编了码——给字符集里的每个字符都做编码，这正是哈夫曼编码干的事。

既然是哈夫曼编码，咱们就把哈夫曼编码的知识点代入进去。

#### 括号一：哪种数据结构能存这套编码

第一问问的是：以保存上述具有前缀特性的不等长编码，数据结构有什么呢。

我们学过的数据结构就那么几个。线性表（含栈、队列这两种特殊线性表）先排掉；串是用来存字符的，这里也不对；剩下就是树。

> **结论**：使用树形结构（二叉树）来保存这套编码。

这里有个答题上的小讲究：只写一个"树"字，显得太单薄，毕竟是十分题。你可以多说一点——用一棵二叉树保存字符集中每个字符的编码；每个字符的编码，对应的就是从根节点到叶节点这条路径上的每条边，每条边代表一个位，字符存放在该路径的叶节点处。这样要取出某个字符的编码，从根开始遍历到叶节点，把沿途的边拼起来就够了。

#### 括号二：从 01 串到字符串怎么译码

第二问：基于你设计的数据结构，简述从 01 串到字符串的译码过程。

有的同学读到这里是懵的：为什么要从 01 串翻译？什么样的 01 串翻译成什么样的字符串？所以得先把哈夫曼编码的使用场景补上，不然这一问答出来是空的。

所谓 01 串（也叫比特串），就是把一段信息里的每个字符一个一个换成它的编码，再连起来。比如当前这个文本里有多个 A、多个 B，每个字符都有自己的编码——A 的编码是 110，B 的编码是 01，那么 "ABAB" 编码之后就是 110 01 110 01 连成的比特串。至于每个字符该分多长的编码，那是编码阶段根据字符出现的频次（权值）构造哈夫曼树时定下来的事。

译码，就是把这条路走回来：

```text
比特串 = 110 01 110 01
从根节点开始，约定左 0 右 1，逐位从左到右扫描：

  110 → 右、右、左 → 到叶节点 → 输出 A
  01  → 左、右     → 到叶节点 → 输出 B
  110 → 右、右、左 → 到叶节点 → 输出 A
  01  → 左、右     → 到叶节点 → 输出 B

译出：ABAB
```

一句话概括：**从根开始，按比特位左 0 右 1 往下走；走到叶节点，就输出该节点保存的字符；然后回到根，接着读下一段。** 标准答案也是这么写的——从左到右扫描 01 串，每一位从根开始，根据当前位沿左或右下移，直到移到叶节点为止，输出叶节点保存的字符，不断重复这个过程，译码就结束了。

> **易错点**：光背下"左 0 右 1、遇叶即停"这条规则，答案写出来是空的。规则必须落在"一段文本被逐字符替换成编码再连起来"这个场景上，阅卷的人才认得出你真的懂哈夫曼编码。

#### 括号三：怎么判断一套编码有没有前缀特性

第三问：简述判断一个字符集的不等长编码是否具有前缀特性的过程。题干给了字符集及其对应的编码，问的是判定方法。

这一问最容易踩的坑，是上来就写"构造哈夫曼树，能构造出来就具有前缀特性"。这样写是错的——**当前根本没有哈夫曼树**。我们是要自己现场构造一棵二叉树，再看这套编码能不能长成一棵"所有字符都落在叶节点上"的树。

所以答题的第一句必须先把判定逻辑交代清楚：我要构造一棵二叉树，遍历当前字符集，一边遍历一边判断它能否构成一棵哈夫曼树；若能构成，则该编码具有前缀特性。注意，这个问题跟前两问是分开的——前两问是"树已经有了，怎么用它"，这一问是"树还没有，该不该有"。

过程可以这样描述：依次读入每个编码，为它建立一条从根出发的路径。扫描编码的每一位，根据当前位是 0 还是 1，决定沿左还是沿右下移；遇到空指针就创建新节点，让空指针指向新节点，继续往下移。

在这个过程中会撞到三种情况：

| 撞到什么 | 说明什么 | 判定 |
| --- | --- | --- |
| 位数还没走完，就走到了叶节点 | 叶节点下面没有孩子，说明这个编码是别的编码的前缀 | 不满足前缀特性 |
| 编码全部位走完，却一个节点都没创建 | 路径全是现成的，说明它只是别人的前缀 | 不满足前缀特性 |
| 编码全部位走完，并且创建了新节点 | 新路径顺利落地 | 通过，继续验证下一个编码 |

直到所有编码都验证成功，才能说这个编码具有前缀特性。

举个具体的例子。字符 A 的编码是 110：从根出发，读到第一个 1，就生成一个节点，边上存 1；再来一个 1，再生成一个节点，挂在右孩子上；再来一个 0，作为它的左孩子。此时这个叶节点就记作 A。

```text
把 A = 110 插进树里（从根出发，1 走右，1 再走右，0 走左）

  root
    └── 1 ──> n1
              └── 1 ──> n2
                        └── 0 ──> 叶节点(A)

再把 B = 01 插进去（0 走左，1 走右）

  root
    └── 0 ──> 叶节点(B)
    └── 1 ──> n1 ──1──> n2 ──0──> 叶节点(A)
```

> **提示**：这里其实可以不真的把 A 这个字符存进去，只遍历路径就够了。因为前缀特性的定义就是"任何一个字符的编码都不是其他字符编码的前缀"，重点不在叶节点上写着什么字母，而在于后面字符的构建会不会经过这个叶节点。

那么什么样的情况算失败？两个：

- 后面某个字符的编码走到这个叶节点，还要再往下建节点——比如出现了 1100 或者 1101，那显然不对；
- 某个编码本身就是 11，走完两位停下时落在了非叶节点上，也不对——因为 11 是 110 的一部分。

这两种情况都不行。再看 B 的编码是 01：第一位是 0，在左分支上创建一个节点；第二位是 1，在它的右边再创建一个节点，落成一个叶节点，就是 B。

补充两个细节：新建节点时，一定要保证你新建的位置是空的，也就是只在空指针上建；除了根节点以外，后面每条编码的路径都不应该再撞到叶节点，一撞到就说明不对。

这道题只要求简述，并没有让我们写代码，所以上面这一段话就是全部答案了。第三问的描述明显比前两问长，不是谁偏心——判定过程本身的情况就比较多。

再交代两句答题心态：这类题主要考的是算法的选择和描述，描述清晰一点，把自己的想法写出来就行；核心是你得掌握哈夫曼编码，然后用学过的这些数据结构去思考问题。

### 43 题：没有乘法指令，乘法是怎么算出来的

题目给了两个 C 语言的函数，都是实现 $x \times y$，区别只有一处：第一个函数里 $x$、$y$ 都是无符号数，返回的 $x \times y$ 自然也是无符号数的结果；第二个函数里两个数都是 `int` 类型，也就是有符号数，返回的 $x \times y$ 也是有符号数的结果。整道题就围绕这个差别往下问。

> **前提**：某计算机 M 中的 ALU 只能进行加减运算和逻辑运算。

#### 没有乘法指令，靠加、减、位移凑出乘法

第一问：如果 M 的指令系统中没有乘法指令，但有加法、减法和位移指令，那么在 M 上也能实现上述两个函数的乘法运算，为什么？

这个问法翻译一下就是：乘法指令能不能用加减和位移拼出来？要答这题，就得知道计算机里的乘法究竟是怎么实现的。这里以 **Booth 算法**为例，讲一下乘法运算器的实现步骤。

先看运算电路：被乘数放在寄存器 $X$，乘数放在寄存器 $Y$，另外还有一个乘积寄存器 $P$，初始为 0。

> **提示**：为什么要单独配一个乘积寄存器？$X$ 和 $Y$ 都是 32 位，32 位乘 32 位的结果是可能超出 32 位的。所以要额外配一个 64 位的寄存器存最终乘积；顺带地，乘法计算过程中产生的部分积也先存在它里面。

```text
+----------------------------------------------+
|  被乘数寄存器 X（32 位）                     |
+----------------------------------------------+
|  乘数寄存器 Y（32 位），附加位 y_i=0         |
+----------------------------------------------+
|  乘积寄存器 P（64 位），累放部分积           |
                      |
                      v
+----------------------------------------------+
|  ALU + 移位器（只能做加减运算和逻辑运算）    |
+----------------------------------------------+
                      |  加 X / 加 -X 的补码 / 加 0
                      +------> 写回 P，整体右移一位
                      |
                      v
+----------------------------------------------+
|  控制逻辑：比较附加位 y_i 与 Y 的末位 y_i-1  |
                      |
                      v
+----------------------------------------------+
|  计数器：循环次数 = 乘数寄存器 Y 的位数      |
+----------------------------------------------+
```

Booth 算法会在乘数寄存器后面附加一位 $y_i$，初值为 0。运算过程中，控制逻辑看的是**附加位 $y_i$ 与乘数寄存器 $Y$ 末位 $y_{i-1}$ 的差值**，据此决定这一轮往部分积上加什么：

| $y_i - y_{i-1}$ | 本轮操作 |
| --- | --- |
| $0$ | 部分积加 0 |
| $1$ | 部分积加 $X$ 的补码 |
| $-1$ | 部分积加 $-X$ 的补码 |

$-X$ 的补码就相当于实现了减 $X$，所以 ALU 只需要会加减就够了。

控制逻辑干两件事：一是控制这一轮到底是加被乘数、减被乘数，还是加 0；二是控制移位——加减完之后整体右移一位，再去看附加位和 $Y$ 末位的差值，进入下一轮。

整个过程要循环多少轮？由控制逻辑里的计数器说了算，**计数器与乘数寄存器 $Y$ 的位数一致**——$Y$ 有多少位，就加多少次、右移多少次。

所以答案很直接：把这段加加减减加移位的过程放进一个循环的代码段里，靠循环反复控制多次加法和右移，乘法就出来了。哪怕 ALU 只会加减和逻辑运算，一条乘法指令要干的事它也能干完。

> **提示**：想看乘除运算电路更细的、一步一步带例子的实现步骤，可以去听 B 站上关于乘除运算电路的精讲，那个讲得更细。这里只针对做题，大致了解步骤就够了。

#### 控制逻辑：管次数，也管这一轮是加还是移

第二问：若 M 的指令系统中有乘法指令，用 ALU、移位器、寄存器以及相应的控制逻辑来实现这条乘法指令时，控制逻辑的作用是什么？

前面的电路已经讲过了，答案就是两件事：

1. **控制循环次数**。控制逻辑里的计数器，决定加法和移位操作一共要做多少次；
2. **控制每一步的操作**。决定这一轮是做加法还是做移位。减法不必单独支持——把被乘数求补就等价于减，所以让 ALU 只做加减和逻辑运算就够了。

前两问只要了解过这个电路，都算是简单的。

#### 阵列乘法器：进位改道，一个周期算完

第三问给了三种情况：没有乘法指令、用 ALU 和移位器实现乘法指令、用阵列乘法器实现乘法指令。问的是：对无符号数来说，乘法指令在哪种情况下执行时间最长，哪种最短。

先比 1 和 2。两者的执行阶段都是一堆加法加移位，时间上没有很大差别，**差别全在取指阶段**：

- 情况 1 没有乘法指令，一次乘法得拆成 $n$ 次加法指令 + $n$ 次移位指令，一共 $2n$ 条指令，就得取指 $2n$ 次；
- 情况 2 有乘法指令，从指令的角度看就只有一条，取指一次就够了。

所以情况 1 肯定比情况 2 慢。

再看情况 3，先弄清楚阵列乘法器是什么。它是一个 4 位乘 4 位的结构：HA 是半加器，FA 是全加器。半加器负责把 $A_1B_1$、$A_0B_1$ 这些乘积项两两加起来，和输出到下面；全加器除了本位之外，还得把上一位的进位一起加进来，再把结果送下去。

串起来就是这样：

```text
普通阵列乘法器：进位必须逐级往下传

   第 1 行   HA ──┐
                  └──> 第 2 行  FA ──┐
                                     └──> 第 3 行  FA ──> S3

   每一行都得等上一行的进位到达，运算才能往下走


改进的阵列乘法器：进位一路送到最后一行

   第 1 行   HA ─────────────────────┐
   第 2 行   FA ─────────────────────┼──> 第 3 行  FA ──> S3
   第 3 行   FA ─────────────────────┘

   这一列反正都要加进位，直接送到最后一层求和，
   整行的加法单元互不等待，可以完全并行地算
```

可以看到，乘法时各个部分的计算本来是可以并行进行的，只是进位这一环需要等前一位的结果。改进之后进位改道，全加器不再需要等待上一行的计算结果，**每一行都能并行执行**，效率就提上来了。

结论也就出来了：阵列乘法器是专门用来执行乘法运算的硬件电路，由多个全加器和半加器组成，**一个时钟周期就能完成一次乘法**。而前两种情况都只有一个 ALU，每做一次加法都要占用它，移位还得靠移位器，都得多个时钟周期才能算完。

> **结论**：对无符号数而言，执行时间最长的是"没有乘法指令"的情况，最短的是"用阵列乘法器实现乘法指令"的情况。

#### 2n 位乘积截成 n 位：谁溢出，谁不溢出

第四问：$n$ 位整数乘法指令可以保存 $2n$ 位的乘积，当仅取低 $n$ 位作为乘积时，其结果可能会发生溢出。已知 $n = 32$，$x = 2^{31} - 1$，$y = 2$，问带符号整数乘法指令和无符号整数乘法指令得到 $x \times 2$ 的 $2n$ 位乘积是什么。

先把这个数算出来。带符号与无符号在乘法这一层算出来的，是同一个值：

$$x \times y = (2^{31} - 1) \times 2 = 2^{32} - 2$$

$2^{32} - 1$ 就是 32 个全 1，二进制后 32 位全 1，写成十六进制正好占 4 个字节，是 `FFFF FFFF`；再减 1，最后这个 F 变成 E：

$$2^{32} - 2 = \texttt{FFFF\ FFFE}$$

所以不管带符号还是无符号，最终得到的 64 位乘积都是 `FFFF FFFE`，两者完全一样。

接下来才是关键——此时这两个函数返回的结果，是否发生溢出？

**无符号：没有溢出。** 后 32 位就是 `FFFF FFFE`，每一位都在有效的数值位范围内，能被完整表示出来，所以对无符号运算来说不溢出。

**有符号：溢出了。** 它的最高位是 F，而在有符号解释下，这个最高位是**符号位**。可被截断保留下来的低 32 位里，它被当成了数值位——本该在这里表示的 $2^{31}$ 就没有了，需要靠它减出来。所以有符号版本得到的数，和真实的 $2n$ 位乘积完全不是一回事：按补码求真值，`FFFF FFFE` 取反加 1 得 -2，而真实值是 $2^{32} - 2$，差了十万八千里——这就是溢出导致的结果不一致。

> **易错点**：无符号不溢出、有符号溢出，根源不是"有符号数范围小所以更容易溢出"，而是**截断保留下来的低 $n$ 位，在有符号解释下最高位变成了符号位**。同一个 bit 串被重新赋予了完全不同的含义。

那么溢出到底怎么判断？

**无符号乘法：看高 $n$ 位不全为 0。** 无符号数的高 $n$ 位全都是数值位，只要其中有某一位为 1，就说明真实结果超出了 $n$ 位能表示的范围，把高 $n$ 位截掉之后得到的值必然和真实值不一样。

**有符号乘法（这是第四问之外额外拓展的）：看高 $n$ 位是否与低 $n$ 位的符号位一致。** 从 $n$ 位扩展到 $2n$ 位时，为了让数值大小不变，必须做符号扩展——符号位是 1（负数）时，高 $n$ 位应该全填 1；符号位是 0 时，高 $n$ 位应该全填 0。所以一旦高 $n$ 位与低 $n$ 位的符号位不一致，就说明发生了溢出。

拿本题的例子对照：它的符号位是 1，但高 $n$ 位全是 0，跟符号位不一致，溢出。

### 44 题：八路组相联 Cache 的字段与缺失

题目给的设定：存储地址 32 位，按字节编址；指令 Cache 和数据 Cache 与主存之间均采用**八路组相联映射**；采用**只写策略**和 **LRU 替换算法**；主存块大小 64 字节，Cache 数据区容量 32KB。

先把地址结构算出来，这是后面所有问的地基。Cache 行数 = 数据区容量 ÷ 块大小 = $32\text{KB} / 64\text{B} = 2^9$ 行；每组 8 行，所以组数 = $2^9 / 8 = 2^6 = 64$ 组。组相联映射的地址结构是"标记 + 组号 + 块内地址"：块内地址由 64B 且按字节编址决定，占 6 位；组号由 64 组决定，占 6 位；剩下 32 - 6 - 6 = 20 位，就是标记。

```text
+--------+-----------+------------+
|  tag   |   组号    |  块内地址  |
|  20 位 |    6 位   |    6 位    |
+--------+-----------+------------+
```

#### 行里塞了什么：标记 20 位、LRU 3 位、没有脏位

第一问：Cache 每行中标记、LRU 各占几位？是否有修改位？

**标记 20 位**，上面已经算出来了。

**LRU 位 3 位**。为什么只看组内的行数？因为在组相联映射里，地址中的组号是确定的，映射到哪一组是硬件定死的。一旦确定到这一组，如果组已经满了（一共 8 行），就要从这 8 行里挑一行替换——而挑哪一行，正是由 LRU 决定的。所以位数 = $\log_2 8 = 3$。

**没有修改位**。修改位是为写回（写回法）配套的：脏位为 1 时，只有这一行被替换出去的时候，才对主存做写操作。而本题用的是**只写策略**——对 Cache 写的时候，同时对主存也做写操作，主存始终是最新的，根本不需要判断这一行有没有被动过。

> **易错点**：只写策略和写回策略一定要分清。只有写回才需要脏位，只写不需要。这两句话在考卷上就差一个字，分数却是两问的分。

#### 1024 个 int 元素散进 64 组，只缺 64 次

第二问给的程序段是一个 for 循环，$k$ 从 0 循环到 1024（取不到 1024，所以实际是 0~1023），循环体是 $S[k] = S[k] \times 2$ —— 一次读数组、一次写数组，循环下来对数组一共访问 2 次。已知 $S$ 和 $k$ 都是 `int` 型（各占 4 字节），$k$ 分配在寄存器中，数组 $S$ 在存储器中的起始地址是 `008000C0H`。问：这段程序执行过程中，访问数组 $S$ 的 Cache 缺失次数。

一开始 Cache 是空的，所以要数的就是从头到尾缺了几次。这题的关键不在"怎么数缺失"，而在**先把数组元素的落位规律摸清楚**。

先把起始地址拆成二进制。`008000C0H` 是 32 位：`0000 0000 1000 0000 0000 0000 1100 0000`。按 20 / 6 / 6 切完之后：块内地址是最低 6 位 `000000`，正好是 0，说明数组可以从这一块的开头放起；中间的组号 6 位是 `000011`，也就是 3，所以 $S_0$ 被映射到**第 3 组**。

一个 Cache 行 64 字节，一个 `int` 4 字节，所以一行装得下 $64 / 4 = 16$ 个数组元素。于是：

| 组号 | 放在该行里的数组元素 |
| --- | --- |
| 第 3 组 | $S_0 \sim S_{15}$ |
| 第 4 组 | $S_{16} \sim S_{31}$ |
| 第 5 组 | $S_{32} \sim S_{47}$ |
| … | … |
| 第 63 组 | $S_{960} \sim S_{975}$ |
| 第 0 组 | $S_{976} \sim S_{991}$ |
| 第 1 组 | $S_{992} \sim S_{1007}$ |
| 第 2 组 | $S_{1008} \sim S_{1023}$ |

一共 64 组，每组正好放满 16 个元素，$64 \times 16 = 1024$，一点不多一点不少——正好把整个数组铺满，**不存在任何替换**。

接下来才是访问过程：

- 访问 $S_0$：缺失，把 $S_0 \sim S_{15}$ 这一整块调入第 3 组。随后赋值 $S_0$ 时命中；
- 再访问 $S_1 \sim S_{15}$：读命中，写也命中；
- 所以这 16 个元素只缺了 1 次；
- 后面每一组都是同样的剧本：访问 $S_{16}$ 缺失（把 $S_{16} \sim S_{31}$ 调入第 4 组），之后的 $S_{17} \sim S_{31}$ 读、写全命中，这 16 个元素也只缺 1 次；
- 一直走到最后一组：访问 $S_{1008}$ 缺失，$S_{1009} \sim S_{1023}$ 全命中。

每一组都是"只有访问本组第一个数组元素时缺失，其余读写全命中"，一共 64 组。

> **结论**：访问数组 $S$ 的 Cache 缺失次数为 **64 次**。

这类题的做法是固定的：先把数组元素分组，看 Cache 行里能放多少元素，再把映射关系对到具体的组上，最后才数缺失。中间还必须考虑一件事——所有数组元素在 Cache 里放不放得下、会不会发生替换。本题是 1024 个元素正好每组放一个行，不存在替换；换一组参数、换一个循环顺序，答案就未必是 64 了。

命中率就不用再单独算了：因为每一行的命中情况完全一样，每 16 个元素缺 1 次，整体命中率也就是这个数。

#### 缺失之后，数据到底从主存取还是从 Cache 取

第三问：如果 CPU 最开始的操作是读取存储单元 `00010003H` 中的指令，简要说明从 Cache 中访问该指令的过程，包括 Cache 缺失处理的过程。

给了物理地址，那就按组相联的访存流程一步步走：

**第一步，确定落在哪一组。** 把 `00010003H` 展成二进制，取地址中的组号字段。这里算出来的组号是 0，所以要到第 0 组去找当前的 Cache 块。

**第二步，比较标记，判断是否命中。** 把这个地址的 20 位标记，与第 0 组中各行的标记字段逐一比较。因为一开始 Cache 是空的，所有行的标记都不可能与之相等，**不命中**。

**第三步，做缺失处理。** 不命中就要去访问主存，按这个存储单元的地址从主存读出对应的块；然后更新 Cache，把这个主存块调入组号为 0 的第 0 组中任意一行。这一步有两个细节必须写上：

- 更新该 Cache 行的标记字段，并把**有效位置为 1**——下次访问能不能命中，看的就是标记加有效位，漏了有效位就等于没命中；
- 因为用的是 LRU 替换算法，还要相应修改该行的 LRU 位。

**第四步，取数据。** 然后按块内地址把数据取出来送出去。

第四步有两种写法，考试要注意：

- 2020 年标准答案给的是**需要从 Cache 中获取数据**，也就是从当前这一行里按块内地址把数据取出来；
- 而在现代计算机体系结构中，**可以直接从主存中获取数据**——在访问主存、把数据块调入 Cache 的同时，数据就已经取出来了，更新 Cache 和取数据是同时进行的，不用再回头访问一次 Cache。

现在一般采用后一种写法，但遇到老题（比如 20 年这道）要注意标准答案给的是从 Cache 取。

> **提示**：这两种写法的差别，本质上是在问"Cache 不命中时，数据到底应该从哪里取"。考试按现在的写法答一般没问题，但心里得清楚标准答案是怎么写的。

## 2020 年真题串讲：PV 同步、页表地址转换与 NAT
> 对应块：BLK51 | 覆盖分集：P131-P133 | 块标题（分集名）：《20年（45）操作系统-pv题》

2020 年这三道统考真题是挨着走的：先一道操作系统，用 PV 操作写同步；紧接一道操作系统，二级页表的地址转换；最后一道计算机网络，NAT。我们一道一道来。

这道 PV 题考的就是我们同步关系里 PV 操作的一个写法。它相对我们前面学的互斥同步那种题型来说更简单——不用去争资源，也不用绕临界区，就是把题目描述的"谁在谁之后"老老实实翻译成信号量和 P、V 操作。

### PV 写同步：一条前驱边配一个信号量

#### 读题：五个操作，四条边

题目给了 A、B、C、D、E 五个操作，对应的就是五个进程。约束只有两句话：操作 C 必须在 A 和 B 都完成之后进行；操作 E 必须在 C 和 D 都完成之后执行。

这两句话看着简单，但你在纸上画的时候小心点——它不是一棵树，它有汇合。A 和 B 都要汇到 C，C 和 D 又都要汇到 E。

```text
      ┌── A ──┐
      │       │
      ├── B ──┼──► C ──┐
      │       │        │
      └───────┘        ├──► E
                       │
      └──── D ─────────┘
```

数一数，有向边一共 4 条：A→C、B→C、C→E、D→E。

没有前驱的进程是 A、B、D，它们随时可以开跑；有前驱的 C 和 E，必须等自己的前驱全部到位。

#### 落笔：先写没有前驱的进程

同步关系用的信号量，**个数就等于前驱图里有向边的条数**。这儿是 4 条边，所以我们设 4 个信号量。

命名上我给大家一个习惯：信号量的字母，尽量和这条边的前驱、后继保持字母表上的顺序一致。A→C 这条边就记作 $S_{AC}$，B→C 记作 $S_{BC}$，C→E 记作 $S_{CE}$，D→E 记作 $S_{DE}$。这样你写 PV 的时候，顺着字母就能找到该 P 哪个、该 V 哪个，特别方便，也不容易写错。

> **易错点**：这 4 个信号量的初值全是 0。别按互斥那套的手感随手甩个 1 上去——同步信号量的初值就是 0，因为一开始谁也没把谁 V 起来。

定完信号量就可以写 5 个进程各自的 PV 序列了。从哪个进程开始写呢？从没有前驱的节点开始，也就是 A、B、D。

A 没有前驱，它的动作可以直接执行。执行完之后要干嘛？A 完成后要给它后面连着的这条边去产生信号量，也就是给 C 提供一张"我 A 已经好了"的凭证。所以 A 这一行的写序是：先把自己的动作做完，再 V 掉出边——它压根没有 P，只有 V。写的时候你甚至可以把 A 这个动作本身用省略号表示，说"正在做某个不可分割的动作"也可以，也可以老老实实写出它的微操作，都能拿分。同理 B 也是一样的路数。

D 也一样：D 没有前驱，V 一下 $S_{DE}$，任务完成。

那就剩 C 和 E 了。C 需要申请 A 和 B 提供的凭证，所以它一上来先 P：先 $P(S_{AC})$、$P(S_{BC})$，两个都拿到之后，才能执行动作 C；C 执行完，它又是 E 的前驱，所以再 V 一个 $S_{CE}$。

E 是终点，任务最重：它要等 C 和 D 两个前驱，所以先 $P(S_{CE})$、$P(S_{DE})$，都 P 到了，再执行动作 E。

整套答案就是这 5 行：

```text
进程 A：  完成动作A;                V(S_AC);
进程 B：  完成动作B;                V(S_BC);
进程 C：  P(S_AC);  P(S_BC);  完成动作C;   V(S_CE);
进程 D：  完成动作D;                V(S_DE);
进程 E：  P(S_CE);  P(S_DE);  完成动作E;
```

> **结论**：同步关系写 PV 就一句话——**找到前驱线段先 P，执行完自己的动作，后继线段后 V**。A、D 是只有 V 没有 P 的（它们没有前驱），E 是只有 P 没有 V 的（它们没有后继）。

#### 收口：五步流程与两条铁律

我们把这个流程拎出来，这就是你拿到任何一道同步 PV 题之后的固定动作：

1. **画前驱图**。把题目里每一句"谁必须在谁之后"翻译成一条有向边，别脑补题目没说的依赖。
2. **定信号量**。个数等于有向边的条数，命名尽量和这条边的前驱、后继字母一致。
3. **定初值**。同步信号量初值一律 0。
4. **找头节点**。没有前驱的进程先写，它们的动作可以直接执行，V 掉自己后继的那条边。
5. **顺着边往下推**。走到哪个进程，就看它的入边有哪几条，先逐个 P 完这些边对应的信号量，再执行动作，最后 V 掉它的出边。

再来看一遍标准答案，它跟我们的推导是一模一样的：先画前驱图，4 条有向边所以设 4 个同步信号量、初值全 0；A、B、D 三个无前驱节点直接执行动作，完成后分别 V 出 $S_{AC}$、$S_{BC}$、$S_{DE}$；C 先 P 掉 $S_{AC}$ 和 $S_{BC}$ 这两条入边，执行完动作 C 后 V 出 $S_{CE}$；E 先 P 掉 $S_{CE}$ 和 $S_{DE}$，再执行动作 E。

> **易错点**：写单个进程时是**先 P 后 V**——先申请前驱的凭证，做完动作再 V 给后继。但把时间轴拉长看每一个信号量本身，它一定是**先 V 后 P**：前驱 V 在前，后继 P 在后，这个顺序反了就直接死锁。还有一个特别容易丢的就是信号量本身，中间的 $S_{CE}$、$S_{DE}$ 一个都不能漏，一定要严格按前驱后继关系写。

这套东西你一定要掌握。因为考试里只要考同步关系考 PV 操作，我们就必须把分拿满。它比同步互斥关系的分析简单太多了，是三种考察方式里最容易的一种，非常容易拿满分。所以整个流程你一定要练到不用想。

### 二级页表：所有小问都是"基址加偏移量"

我们接着往下看 20 年第 46 题，这是一道二级的地址转换综合题。我先把题读一下：

某 32 位系统采用基于二级页表的请求分页存储管理方式，按字节编址，页目录项和页表项的长度均为 4B。已知某 C 程序中定义了一个 1024 行乘 1024 列的数组 A，数组元素占 4B，数组 A 在虚拟地址空间中的起始地址为 10800000H；该程序运行时，其进程的页目录基址为 00201000H。问题围绕数组元素 A[1][2] 展开。

#### 数组元素的虚拟地址

第一小问：数组元素 A[1][2] 的虚拟地址是什么。

这个最简单。因为每个数组元素占 4 字节，题目又给了数组的起始虚拟地址，所以只要**用起始地址加上偏移量**就行了。前提是数组元素在虚拟地址空间中一定是连续存放的——数组在逻辑上本来就是连续的嘛，虚拟地址空间对应的正是逻辑结构，所以我们才能用这种"加偏移量"的机制来算。

起始虚拟地址我们写出来：10800000H。那偏移量怎么算？就是先算出偏移了多少个元素。

数组一行 1024 个元素。A[1][2]，前面的元素有：完整的一行 1024 个，再加上第 0 行和第 1 行里排在它前面的那 2 个，一共 1026 个元素。乘以每个元素 4 字节：

$$
\text{偏移量} = (1 \times 1024 + 2) \times 4 = 1026 \times 4 = 4104 = 2^{12} + 8 = 1000\text{H} + 8 = 1008\text{H}
$$

基址加上偏移量：

$$
10800000\text{H} + 1008\text{H} = \boxed{10801008\text{H}}
$$

> **提示**：$1024 \times 4 = 4096 = 2^{12}$，这不是巧合——一行元素正好占满 $2^{12}$ 字节，也就是整整一页。这一点第三小问要用到，先记着。

#### 拆成页目录号和页号

第二小问：在虚拟地址的基础上，给出该地址对应的页目录号和页号。

这就更简单了。第一小问的虚拟地址我们已经算出来了，题目又把虚拟地址的结构给出来了，无非就是从虚拟地址里把高 10 位的页目录号、中间 10 位的页号挑出来。低 12 位是页内偏移，不用管。

我们把虚拟地址写成 32 位的样子，然后按 10、10、12 三段切开：

```text
                     10801008H
   ┌──────────────┬──────────────┬──────────────┐
   │    页目录号    │     页号      │    页内偏移   │
   │     10 位     │     10 位    │     12 位    │
   └──────────────┴──────────────┴──────────────┘
        042H            001H           008H
```

怎么切出来的？除掉低 12 位不用管，我们就看高 20 位。**从右往左第一个 16 进制位是 8**，它写成二进制是 `1000`：低两位二进制 `00` 归到低 10 位里、高两位二进制 `10` 归到高 10 位里。

- **页号（低 10 位）**：手上是 2 位二进制 `00`，高位补两个 0，得到 `0000000001`，也就是 **001H**。
- **页目录号（高 10 位）**：把 `1` 和 `0` 这两位 16 进制拆成二进制，是 `0001 0000`；再把 `8` 拆出来的 `10` 接到最前面，一共 10 位二进制 `0001000010`。四位四位来看就是 `0010 0010`，高位再补两个 0 —— `0010` 是 2，`0010` 也是 2 —— 得到 **042H**。

#### 两次查表，两个物理地址

第三小问：对应的页目录项的物理地址是什么。

这实际上考的就是二级页表里做地址转换的过程。每个进程都有一个对应的页目录基址寄存器，从这个寄存器里拿到的是**物理地址**。拿到页目录基址之后，我们从虚拟地址里把页目录号切出来——页目录号相当于一个数组的下标，还得再乘上数组元素的大小。这一点和我们第一小问算偏移量的逻辑是一样的。

所以页目录项的物理地址 = 页目录基址 + 页目录号 × 每个页目录项的大小。基址题目已经给了，00201000H。每个页目录项 4B，系统按字节编址，直接乘 4：

$$
042\text{H} \times 4 = 108\text{H}
$$

这里要注意进位：十六进制里 $2 \times 4 = 8$ 原样保留，$4 \times 4 = 16$ 已经满 16，要向高一位进 1，所以结果是 `0108` 进位后的 `108`。加上基址：

$$
00201000\text{H} + 108\text{H} = \boxed{00201108\text{H}}
$$

第四小问：若该目录项中存放的页框号为 00301H，问数组元素 A[1][2] 所在页对应的页表项的物理地址是什么。

在二级页表的请求分页里，我们要查**两次表**（TLB 未命中，或者压根没设 TLB 的情况下）。

第一次查表就是第三小问：根据页目录基址和页目录号，找到对应的页目录项——页目录项里存放的就是二级页表的页框号，也就是题目给的 00301H。物理地址的高位就是页框号本身，低 12 位是页内偏移。所以把 00301H 补上低 12 位 `000H`，就得到二级页表在物理地址空间中的起始地址：**00301000H**。

第二次查表又是"基址加偏移量"，逻辑和第三小问一模一样，只不过把页目录号换成页号、再乘上每个页表项的大小。页号我们在第二小问已经算出来了，是 001H，页表项大小也是 4B：

$$
001\text{H} \times 4 = 004\text{H}\quad（不需要进位，直接写 4）
$$

$$
00301000\text{H} + 004\text{H} = \boxed{00301004\text{H}}
$$

> **定义**：二级页表下"缺页/TLB 未命中"的完整访问路径是：CPU 给出虚拟地址 → 用页目录号查一级页表得到二级页表的物理基址 → 用页号查二级页表得到物理页框号 → 与页内偏移拼成物理地址。第一小问的数组连续性、第四小问的查表过程，用的都是这条路径。

#### 连续性：虚拟连续，物理离散

第二小问（题目原第二问）：数组 A 在虚拟地址空间中所占的区域是否必须连续？在物理地址空间中所占的区域是否必须连续？

第一个答案是**必须连续**。因为数组 A 在逻辑结构上本来就是连续的，而虚拟地址空间对应的正是逻辑结构，所以它在虚拟地址空间里必须连续——这也正是我们第一小问能够"基址加偏移量"直接算的前提。

第二个答案是**不必连续**。把虚拟地址空间换成物理地址空间以后，情况就变了：对于请求分页这种虚拟存储管理方式，逻辑上连续的数据在虚拟地址空间里是连续的，但在物理地址空间里是离散的，或者说是可以离散存储的。页表中相邻的两个表项，它们映射到的物理页框在物理内存中并不一定挨着。

```text
   页表（虚拟顺序，连续）        物理内存（离散放置）
   ┌────┬────┬────┬────┐
   │ v0 │ v1 │ v2 │ v3 │      ┌────┐            ┌────┐   ┌────┐
   └─┬──┴─┬──┴─┬──┴─┬──┘      │ p7 │            │ p2 │   │ p9 │
     │    │    │    │          └────┘            └────┘   └────┘
     ▼    ▼    ▼    ▼
   ┌───┐┌───┐┌───┐┌───┐          连续的虚拟页  →  离散的物理页框
   │   ││   ││   ││   │
   │ p7││ p2││ p9││ p5│      正是这种离散性，让虚拟存储管理方式
   └───┘└───┘└───┘└───┘      能够提高内存的利用率
```

> **结论**：逻辑连续 → 虚拟连续 → 物理离散。这正是虚拟存储管理的意义所在。

#### 按行还是按列：局部性的胜负

第三小问：已知数组 A 是按行优先方式存放的，如果对数组 A 分别按行遍历和按列遍历，哪一种遍历方式的局部性更好？

先把两个概念掰开。**时间局部性**，是指当前访问过的元素，在将来一小段时间内又会被再次访问。**空间局部性**，是指对某个地址单元访问过之后，附近的元素在将来一段时间内又会被连续访问。这两个的区别就在"再次访问同一个"还是"访问它旁边"。

这道题能答，靠的是第一小问算出来的一个巧合：每行 1024 个元素，每个元素 4B，所以一行正好是 $1024 \times 4 = 4096 = 2^{12}$ 字节。而页内偏移正好是 12 位，也就是一页的大小是 $2^{12}$ 字节。**所以，一行正好占一页。**

一行占一页，立刻就推出了关键结论：同一列上的元素，比如 A[0][1] 和 A[1][1]，恰好落在不同的页里。虽然这些不同的页在逻辑上、在虚拟页号上是相邻的，但我们在第二问已经分析过了——虚拟上相邻的页映射到物理上完全可能不挨着。

所以结论很清楚：**按行遍历的局部性更好**。因为我们是按页访问的，一次就能把一页里的一整行全部取出来；按行访问的话，不远的连续时间之内我们就能访问到下一个元素，缓存这一页直接接着用。要是按列访问，虚拟上是相邻的，物理上却不相邻，每换一个元素就得跳到另一个物理页去，页表项要重新查、TLB 也要重新装，局部性就差得多了。

你可以发现，第三小问和第二小问其实是咬合在一起的：正因为数组在逻辑上连续，所以它在虚拟地址空间里必须连续；也正因为采用虚拟存储管理方式，相邻的逻辑页映射到物理页可以离散——这才有了按行、按列局部性的差别。

### NAT 转换：谁在换地址，换的是源还是目的

接下来是 20 年第 47 题，计算机网络的大题。

#### 这张转换表属于哪台路由器

题目给的网络是这样的：

```text
                          ┌──────────┐
                          │ Internet │
                          └────┬─────┘
                               │
                              R1        校园网与外网的唯一出口
                          ┌────┴─────┐
                 203.10.2.6          203.10.2.2
                      │                  │
                     R3                 R2
              ┌───────┴──────┐   ┌───────┴────────┐
              │    局域网一    │   │     局域网二     │
              │  S1、H2、H3   │   │  H1、Web 服务器 │
              └──────────────┘   └────────────────┘
```

先认路：Internet 肯定不属于我们的局域网，它就是外网。R1 两边连着线路，沿着这两个接口往下看能看见 R2 和 R3——两个局域网各通过 R3、R2 与外界相连，中间再由 R1 接到外面的 Internet。S1、S2 这种小方块是交换机。

题目说：局域网采用静态 IP 配置，各路由器接口和 IP 地址如图；并且给出了 **NAT 转换表**的结构——外网的 IP 和端口、内网的 IP 和端口。

NAT 主要关注的是 IP 地址的转换，NAT 里的另一种方式叫 **NAPT**，多一个 P，就是题目里说的端口。

现在的问题是：**图上哪个路由器有 NAT 功能？候选是 R3 和 R2。**

判断的第一步是私有地址。私有 IP 地址的范围我们回忆一下：192.168.0.0 到 192.168.255.255。所以无论是 H1、H2、H3 这三台主机，还是 Web 服务器，用的都是私有地址，也就是转换表里说的"内网地址"。那 R2 和 R3 就都得做转换。

但我们还要看第二点：这个转换表里**带了一个端口号**。我们学习 NAT 的时候提过，端口号是有范围的，而端口号的性质要分两类对象来看：

- **服务器端**有固定的熟知端口号。比如 FTP，它的数据连接和控制连接对应的端口号是 20 和 21；HTTP 是 80。一个固定的应用层协议，在它作为服务器的那一端，一定有自己的固定端口。
- **客户端**的端口号是随机的。当前这个进程要通信，哪几个端口号空着，它就用哪几个，所以客户机这一侧的端口是不固定的。

再看图上的角色。右侧由 R3 连接的局域网一里，除了 S1 这个交换机，就是 H2 和 H3 这两台主机。主机在客户机—服务器模型中，**只能充当客户机**，端口号不确定，转换表里那对端口根本填不出来。再看由 R2 连接的局域网二，里面除了 H1，还有一台 Web 服务器——这就有个端口号固定的角色了。

所以结论就出来了：**这个 NAT 转换表一定是 R2 路由器的转换表。**

> **提示**：看到题目给的是"IP + 端口"这种成对的转换表，先去找服务器。服务器有熟知端口，客户机端口随机——只有服务器那一侧才能写出确定的端口号。

#### 三段链路上的源地址与目的地址

第一小问：为了使 H2 和 H3 能够访问 Web 服务器，Web 服务器使用的默认端口号是多少？需要进行什么样的配置，给出具体配置。

默认端口号就是 80，这个没什么好想的。真正的工作量在"配置"上。我们不妨从第二小问倒着推——第二小问问的是：H2 主动访问 Web 服务器，把请求报文封装在 IP 数据报中发送，那么发送时的源 IP 和目的 IP 分别是多少。我们现在正好在做第一问之前，一起来看第二问。

先把链路分好。题目里这整条路径一共三段链路：

```text
   局域网一          局域网之间的链路          局域网二
 ┌─────────┐      ┌──────────────────┐      ┌─────────────┐
 │  H2     │ ──①──▶│   R3  ──②──▶ R2  │──③──▶│ Web 服务器   │
 │  客户端  │      │            出口  │      │   服务器      │
 └─────────┘      └──────────────────┘      └─────────────┘
```

有一点一定要先说清楚：在 H2 所在的局域网中，能代表"这个网络对外说话"的 IP 是 R3 的 IP；在 Web 服务器所在的局域网中，能代表这个网络的是 R2 的 IP。

**第一段链路，H2 → R3。** 源 IP 一定是 H2 自己的私有地址 192.168.1.2。那目的 IP 呢？这里最容易错。H2 访问的是**其他网络**里的服务器，所以目的 IP 一定不能用 Web 服务器的私有地址，而要用**本网络中对外的那个公有 IP**，也就是 R2 的 203.10.2.2。为什么不能直接用私有地址？因为 H2 和 Web 服务器的私有地址是相同的，源 IP 和目的 IP 一样，路由器根本无法识别这个报文到底要去哪里。

**第二段链路，R3 转发出去。** 源 IP 换成了 R3 对外的公有地址 203.10.2.6，目的 IP 还是 203.10.2.2——当前这个私有 IP 永远不能作为外部网络中的目的 IP 存在。

**第三段链路，R2 转发给 Web 服务器。** 源 IP 依旧是 203.10.2.6，不动。目的 IP 换成最终目标 Web 服务器的私有地址 192.168.1.2。R2 转发出去的时候，我们不在乎源 IP 是从哪儿来的，在乎的是这个包最终要放到哪里。

汇总成表：

| 链路 | 源 IP | 目的 IP | 谁动的 |
| --- | --- | --- | --- |
| ① H2 → R3 | 192.168.1.2（H2） | 203.10.2.2（R2） | R2 尚未动作，用本网络的公有 IP 作目的 |
| ② R3 → R2 | 203.10.2.6（R3） | 203.10.2.2（R2） | R3 改**源 IP**：私有 → 公有 |
| ③ R2 → Web 服务器 | 203.10.2.6（R3） | 192.168.1.2（Web 服务器） | R2 改**目的 IP**：公有 → 私有 |

> **定义**：NAT 路由器转发出去的报文，改变的是源 IP **或**目的 IP，"或"这个字很关键——它只动一个，不会把源和目的全改了。所以你分析一条路径上的报文时，就看它此刻"站在谁的立场上"：站在 R3 的立场上就把源换成 R3 的公有地址，站在 R2 的立场上就把目的换成 Web 服务器的私有地址。

#### 转换表里那一条该怎么填

回到第一小问的"具体配置"，其实答案就藏在这三段链路里。

先看 R3 这边：H2 发出的数据，目的 IP 在经过 R3 转换之后是不动的，动的只是源——从私有地址 192.168.1.2 变成了公有地址 203.10.2.6。这个信息天然要记在 **R3** 的表里：私有地址 192.168.1.2 对应公有地址 203.10.2.6。（而 H2 的私有地址经过 R3 之后会变成哪个公有地址，R3 自己当然是知道的。）

再看 R2 这边：来的时候目的地址就是自己，R2 必须记录下来"我这个公有地址收到包以后，该转发给哪个私有地址"。那就查题目给的 NAT 转换表：

| 外网 IP 和端口 | 内网 IP 和端口 |
| --- | --- |
| 203.10.2.2:80 | 192.168.1.2:80 |

外网地址就是 R2 自己的 203.10.2.2；端口呢，用 HTTP 就是 80；对应的内网地址就是 Web 服务器的 192.168.1.2，端口同样是 80。有了这条记录，第二段链路到第三段链路之间，R2 就可以直接把公有地址还原成对应的私有地址，把包送到 Web 服务器手上。

> **结论**：这道题的第一问、第二问是同一件事的两面。第一问要你写的 NAT 转换表条目，正是第二问里 R2 在第二段到第三段链路之间所做的那次转换。**R3 记的是"我的私有地址换成哪个公有地址"，R2 记的是"我这个公有地址要还原成哪个私有地址"**，两边各记一份，一条通路才闭合。

这道题主要考的就是 NAT 功能。我们之前学 NAT 的时候，包括教材上给的那个图，讲的都是"私有网络中的 H2 与 Internet 中某个主机或服务器通信"，只关注报文从 R3 出去、再回来时地址怎么变。而这道题给的是 **H2 去访问另一个私有网络中的服务器**，中间多了一层 NAT 的接力转换。把这条路径走通之后，大家对 NAT 的功能认识就会深一层。

### 带头结点的单循环链表删首元，坑在尾指针上

题目给的条件很典型：头指针 $H$ 指向一个**带头结点的非空单循环链表**，$P$ 是尾指针，$Q$ 是临时指针，现在要删除这个链表的第一个元素，问正确的语句序列。

先把当前的样子画出来。带头结点，意味着 $H$ 指向的是**头结点本身**，不是首元结点；所以要删的"第一个元素"是 $H$ 的后继：

```text
 H
 │
 ▼
[head] ──next──→ (*)[1] ──→ [2] ──→ [3]
  ▲                ▲                    │
  │                └── 要删的就是它      │
  │                                     │
  └─────────────────────────────────────┘
        P 指向 [3]（尾结点）
```

因为是**单循环**链表，最后一个节点的指针要指回头结点，这一条闭合的回路是后面所有麻烦的根源。

#### 核心操作其实只有三步

要摘掉打勾的那个节点，逻辑上就三件事：先让临时指针抓住它，再让 $H$ 绕过它，最后释放它的内存。

```c
Q = H->next;          // ① Q 抓住首元结点
H->next = Q->next;    // ② 首元结点从链表上摘下来
free(Q);              // ③ 释放
```

> **易错点**：第一步绝对不能省，也不能挪位置。$Q$ 的作用就是在"节点还在链表上"的时候先把它按住。你要是先改了 $H$ 的指针再去赋值 $Q$，那 $Q$ 抓到的就已经是原来打勾节点的**后继**了——$H$ 的 next 一变，$Q$ 读到的就是下一个节点，最后 `free(Q)` 释放的是错的那块内存。第一个选项栽的就是这个：它在删除之后才去给 $Q$ 赋值。

#### 选项里那个 if 从哪来的

扫一圈选项你会发现，除了第一个选项，其他几个都长得差不多，但都带着一个 `if`。这里我们千万不能因为"我没发现需要 if"就直接把没 if 的选项划掉——**有可能是我们考虑不周**。

回头看题目条件：我们刚才一直没用到 $P$。为什么用不到？因为前面推的是**一般情况**。特殊情况是：链表里只剩一个元素节点的时候，这个节点同时是首元结点和尾结点，也就是 $P$ 指着的那个：

```text
 H
 │
 ▼
[head] ──next──→ [1]
  ▲                │
  └────────────────┘
        P 指向 [1]（它既是首元结点也是尾结点）
```

这时候按前面那三步走：`Q` 抓住了唯一的节点，$H$ 的 next 重新指回头结点，节点被 free 掉了。可是 $P$ 还指着那块已经被释放的内存——**尾指针悬空了**。而一个"空的带头结点单循环链表"，它的 $P$ 应该是指回头结点的，不是空指针。所以必须补一刀：

```c
Q = H->next;
H->next = Q->next;
if (P == Q) P = H;    // 唯一元素结点被删，尾指针要退回头结点
free(Q);
```

顺序也有讲究：$P$ 的安置必须在 `free` **之前**完成，先把人安顿好，再拆房子。

所以正确的语句序列是 D——它满足"在 $Q$ 被释放之前，先把 $P$ 安置好"，而安置的动作就是 `P = H`。

> **结论**：无论是链队列的出队，还是这种带头结点链表（尤其是循环链表）的删除操作，**尾指针的特殊处理一定要想到**。判断方法就一句话：被删的这个节点，会不会正好是尾结点？

#### 选择题比大题好做的原因

这道题其实还藏着一条方法论。我们一开始没想到 $P$，是因为没往特殊情况上想；但选项里白纸黑字给了 `if`，那**选项本身就是提示**。

做题的正当姿势是：发现一个自己没写出来的判断语句，就回头去翻题设条件——这个 $P$ 到底是什么？它在什么特殊情况下才被触发？答案是"被删结点是尾结点"。这比闷头硬推高效得多。

> **易错点**：这里说的不包含"不带头结点"的链表。题目明写了带头结点，无头结点结构的空表表示、$P$ 为空这些约定一概不适用，别自己往上加戏。

### 由这道题引申：链队列的出队真的只关队头吗

顺着上一题往下追一层。链队列里，出队就是从头指针那里做删除，入队就是往尾指针那里做插入。常见的一句话结论是"**出队只与队头指针有关，入队只与队尾指针有关**"。

前半句其实不严谨。上一题已经替我们准备了反例：链队列同样有头指针和尾指针两个变量，当出队的元素**恰好就是队尾指针 P 指向的那个节点**时（队列里只剩一个元素），你必须先处理 $P$——把尾指针退回头结点——再从队头指针那里做删除。

这类"某某操作只与某个指针有关"的描述，在真题里出现过不止一次。看到它，第一反应就该是去举一个"最极端的队列状态"反例，而不是直接背下来。

### 输入受限双端队列：先画出队列状态再判

第二题考受限双端队列。题设是：一端仅能入队，假设是左端；另一端既能入又能出。这种结构换个名字就是我们书里说的**输入受限双端队列**——只有一端能输出，两端都能输入。

现在入队顺序是 $1,2,3,4,5$，问下面哪个出队序列是不可能的。假定从右端出。

这一题没有捷径，唯一的办法就是**把每个选项在队列中的状态画出来**，倒着推能不能靠"入队顺序 + 两端输入"拼出来。规律其实就一句：

> **判定规则**：任何一个时刻要入队的元素，它必须落在当前已入队元素的**最左端或最右端**——绝不可能插进队列中间。

拿这个规则逐个过一遍。

**A 选项 $5,4,3,1,2$**，倒推：1 入队；2 从 1 的左边入队；3 从 1 的右边入队；4 从 3 的右边入队；5 从 4 的右边入队。队列状态是 $[2,1,3,4,5]$，从右端依次取出正好 $5,4,3,1,2$。成立。

**B 选项 $5,3,1,2,4$**：1 入队；2 从左边；3 从 1 的右边；4 从 2 的左边；5 从 3 的右边。得到 $[4,2,1,3,5]$，右端出队为 $5,3,1,2,4$。成立。

**C 选项 $4,2,1,3,5$**：1 入队；2 从右边；3 从左边；4 从右边；5 从左边。得到 $[5,3,1,2,4]$，右端出队为 $4,2,1,3,5$。成立。

**D 选项 $4,1,3,2,5$**：1 入队之后，2 只能紧挨着 1——要么左边要么右边，绝无其他位置。可 3 是 1 之后才入队的，它要么落在 1 右边、2 左边，**不可能插进 1 和 2 中间**。而目标序列要求 1 和 2 之间夹着一个 3。矛盾。

所以不可能的出队序列是 D。

> **提示**：这类双端队列题，选项里给的答案是"在选项中给大家的一个贴士"——**画简图**。把队列的中间状态画出来，倒着还原入队过程，比在脑子里空推快得多。

### 二维数组压缩存储：地址指的是"前面"的位置

第三题是二维数组的压缩存储。C 语言里二维数组在存储上就是一维数组，题目按**行优先**存放，每个元素占一个存储单元，给出 $A[0][0]$ 的地址是 100、$A[3][3]$ 的地址是 220，问 $A[5][5]$ 的地址。

题目并没有直接告诉我们这个数组有多少行多少列——**两个地址信息已经足够反推出来**。

#### 先反推行长

设一行有 $X$ 个元素。按行优先数一数 $A[0][0]$ 到 $A[3][3]$ 之间一共有多少个元素：

- 第 0、1、2 三行，每行 $X$ 个，共 $3X$ 个；
- 第 3 行里，$A[3][3]$ 前面有第 0、1、2 列三个元素，即 $+3$。

所以 $A[3][3]$ 前面共有 $3X+3$ 个元素，每个占一个存储单元：

$$220 - 100 = 3X + 3 \;\Rightarrow\; 3X = 117 \;\Rightarrow\; X = 39$$

一行 39 个元素。

> **易错点**：这里为什么是 **220 减 100** 而不是把 $A[3][3]$ 本身加上去？记住存储地址的定义——它指的是**这个元素所占存储单元前面的那个位置**，不包含元素自己。$A[0][0]$ 站在第 0 号位置，$A[3][3]$ 站在第 $3X+3$ 号位置，两地址之差就是夹在中间、包括 $A[0][0]$ 在内的那些存储单元数。

#### 再算 $A[5][5]$

- 第 0 到第 4 行：$5X = 5 \times 39 = 195$ 个；
- 第 5 行里 $A[5][5]$ 前面有 5 个。

$A[5][5]$ 前面共 $195+5=200$ 个元素，换成存储单元数还是 200，最后别忘了**加上 $A[0][0]$ 的首地址 100**：

$$200 \times 1 + 100 = 300$$

答案选 B。

> **易错点**：如果选项里有 200 这么个数，一定会有大批人选错——就是忘了加首地址。另外有些选项是把 $A[3][3]$ 自己给算进去才得到 6 开头的数，算之前务必再问一句"这个地址包不包括我自己"。

#### 这套套路在 408 里是通用的

不只是二维数组，特殊矩阵的对称矩阵、三对角矩阵的压缩存储，题目形式千变万化，解法都是同一套：

- **第一步**：求当前元素在矩阵中**前面**有多少个元素；
- **第二步**：看你要求的一维数组下标是**从 0 还是从 1 开始**——从 0 开始时，下标值就等于前面元素的个数；从 1 开始要把这个数加 1。

把这两条记住，这一类题目就没什么可担心的了。

### 森林与二叉树互转：数一数最右分支

第四题给了森林对应的二叉树的**先序和中序**遍历序列，问这棵森林里有几棵树。

二叉树的遍历大家都很熟：**任何一个遍历序列加上中序序列，就能唯一确定二叉树的形态**。形态出来了，再反推回森林。这一题真正想考的是最后那一步，所以我们在还原二叉树的时候顺手留个心眼。

#### 先把二叉树搭出来

- 先序序列的第一个元素一定是**根**。这里根是 $A$。
- 拿着根去中序序列里划一刀，根左边是左子树、右边是右子树；同时在先序序列里也划出对应范围。
- 进左子树：先序里左子树的第一个点 $B$ 一定是左子树的根，也就是 $A$ 的左孩子。$D$ 是左子树里的另一个节点，到中序里一看，$D$ 在 $B$ 的右边，说明 $D$ 是 $B$ 的**右孩子**。
- 左子树画完，进右子树：先序里右子树范围的第一个节点是 $C$，所以 $A$ 的右孩子是 $C$。中序里 $C$ 的左右两边分别是它的左右子树，右子树只有一个节点 $F$，所以 $C$ 的右孩子是 $F$。
- 再看 $C$ 的左子树：先序里是 $E$、$G$，$E$ 在前，所以 $C$ 的左孩子是 $E$；中序里 $G$ 在 $E$ 的右边，说明 $G$ 是 $E$ 的右孩子。

```text
        A
       / \
      B   C
       \ / \
        D E  F
           \
            G
```

#### 直接数棵数，不用还原

现在可以不还原森林，直接回答问题。**树转森林要把右孩子指针全砍掉**，砍掉之后 $A$ 的兄弟就都站出来了——也就是所谓"左孩子右兄弟"表示法：$A$ 的兄弟就是 $C$ 和 $F$ 这两个。

所以这棵森林一共有 **3 棵树**。选项 C。

> **提示**：学得好的同学一眼就能看出来——**二叉树里最右边的那条分支上有几个节点，就有几棵树**。这条分支是 $A \to C \to F$，三个节点，三棵树。

#### 真的还原一遍森林

如果没做对，我们就把整棵二叉树老老实实地还原成森林，感受一下上面那句话。规则就一条：**左孩子直接变成第一个孩子，右孩子全部砍掉、变成右兄弟**。

- 所有的左孩子，在森林里都是"当前结点的第一个孩子"。所以 $B$ 一定是 $A$ 的一个孩子；$E$ 一定是 $C$ 的一个孩子。
- 右孩子指针全部砍掉：$A$ 的右孩子 $C$、$C$ 的右孩子 $F$、$B$ 的右孩子 $D$、$E$ 的右孩子 $G$，这四条右指针都要叉掉，砍完就变成了它们原来那个结点的兄弟。
- 砍掉 $A \to C \to F$ 这条链之后：$D$ 和 $B$ 是兄弟，所以 $B$ 和 $D$ 一起认 $A$ 做双亲；$E$ 认 $C$ 做双亲，$G$ 和 $E$ 是兄弟所以也认 $C$；剩下 $F$ 自己成树。

```text
    A                森林里有 3 棵树：
  ┌─┼─┐              第 1 棵根是 A
  B D C        F     第 2 棵根是 C
      │              第 3 棵根是 F
      E
      │
      G
```

A 画完这一片，右边还剩两个结点，那就是另外两棵树。**森林与二叉树之间的转换，一定要练到形成肌肉记忆**，这是 408 的高频考点。

### 哈夫曼树：WPL 一定要数路径

第五题给了一棵二叉树，它有五个叶节点，并且权值已经给了，问最小的带权路径长度是多少。

先做个判断题：**不看考点提示，你能从题干判断出这考的是哈夫曼树吗？**

能。哈夫曼树的定义就是"**带权路径长度最小的树**"。题面里"带权路径长度""最小""叶节点""权值"四个词一凑齐，答案就该跳出来。而且人家还贴心地把权值排好序了，那就更好办，直接按哈夫曼的两条规矩来：**每次取最小的两个节点合并，新节点放回集合继续参与比较**。

```text
10 + 12  = 22     把 22 放回集合
16 + 21  = 37     把 37 放回集合
22 + 30  = 52
37 + 52  = 89
```

拼出来的树大致是这样（方框是原本就有权值的叶节点，圆圈是我们构造出来的父节点）：

```text
                         (89)
                       /      \
                   (37)       (52)
                  /   \      /   \
               [16] [21]   [30]  (22)
                                /   \
                             [10]  [12]
```

$$\mathrm{WPL} = 16 \times 2 + 21 \times 2 + 30 \times 2 + 10 \times 3 + 12 \times 3 = 32+42+60+30+36 = 200$$

答案选 B。

也可以偷懒：把所有合并过程产生的中间权值直接加起来，$22+37+52+89=200$，这是哈夫曼树的一个经典性质。

> **易错点**：**一定要数路径条数，绝不能看图**。你随手画哈夫曼树画出来往往是个 Y 形，视觉上会觉得"这四个点好像在同一层"，从而把 $16$、$21$、$30$ 的路径都当成 3——这样一算就全错。路径长度的定义是"从根到这个叶节点中间有多少条边"，是数出来的，不是看出来的。顺带说，解析里的图把方框叶节点和圆形父节点区分开，也是为了让你后面算 WPL、写编码时能一眼分清哪些是原始节点、哪些是你自己造出来的。

> **提示**：还有一个更根本的问题——如果你只会**构造**哈夫曼树，却不知道它的**定义**，那看到这道题你根本判断不出考的是什么。所以概念和构造，两个都得拿下来。

### 平衡二叉树的 RL 双旋

第六题给了一棵平衡二叉树，往里面放入关键字 23，问根中的关键字是什么。

看到"平衡二叉树"四个字其实就等于给了提示：**一定有平衡因子失衡了，一定要去调整**。平衡二叉树首先是一棵二叉排序树，构造过程必须遵循左小右大；不管是二叉排序树还是平衡二叉树的插入，**第一步都是先查找插入位置**。

23 比 20 大 → 往 20 的右子树走；右子树的根是 30，23 比 30 小 → 找 30 的左子树；左孩子是 25，23 比 25 小 → 插到 25 的左边。

```text
        20
       /  \
      16   30
          /  \
         25   40
        /
       23
```

#### 找最小不平衡子树的根

从 23 开始一层一层往上看，谁**最先失衡**（平衡因子绝对值大于 1）谁就是根：

- 25：左高 1、右高 0，平衡因子 1，稳；
- 30：左高 1、右高 1，平衡因子 1，稳；
- 20：左高 1、右高 3，平衡因子 $1-3=-2$，绝对值大于 1，失衡了。

所以**最小不平衡子树的根是 20**，接下来只需要调整以 20 为根的这棵子树。

#### 判断旋转类型

23 位于 20 的**右孩子的左子树**上，右左，简称 **RL**。

> **提示**：双旋的顺序是铁律——**第一个旋转针对子树（小范围），第二个旋转针对大树（大范围）**。也就是先小后大，RL 就是先右旋后左旋。

#### 第一步：对以 30 为根的小树右旋

30 这条分支上，$30 \to 40$ 比左边的长，所以往下带一带，**让 25 上去**。这个旋转的过程是：30 和 40 顺下来，25 上位，23 仍然留在 25 的左边。左小右大的性质没有被破坏。

```text
        20
       /  \
      16   25
           /  \
          23   30
                \
                 40
```

#### 第二步：对以 20 为根的大树左旋

右边那条斜分支比左边长，所以要让根下来、让右边的上去，**20 一定要下来，16 顺下来，25 上位**。原本在右分支上的 30 和 40 **不要动**。

```text
         25
        /  \
      20    30
     /  \     \
    16   23    40
```

#### 剩下的 23 怎么办

看仔细：$20$ 下移之后占掉了 23 原来的位置，23 就无处可去了。这时候唯一的线索还是"左小右大"——**23 必须待在 25 的左边**。23 的右孩子现在是 20，而 23 比 20 大，所以 20 挂到 23 的右边正好。

右平衡和左小右大都没被破坏，最终根中的关键字是 **25**，选 D。

> **提示**：其实在确定"最小不平衡子树根是 20、旋转类型是 RL、25 是这条路径上唯一要上位的中枢节点"这几步之后，答案 25 就已经能推出来了。但**最好还是把双旋完整地转一遍**——你转得顺不顺、能不能一次转对，才是真正要练的东西。

旋转这个动作本身确实不好理解，多练就是了。真题里这道题本身算简单，可你要是做的时候需要在 25 和 26 之间纠结一下，就说明你的旋转还欠火候。

### 拓扑序列个数：什么时候才是唯一的

第七题给一个有向图，问拓扑有序序列的个数是多少。

这一题对大家的要求有两层：**一是会生成拓扑序列，二是能完整地数出所有拓扑序列的个数**。第一步是熟路：反复找入度为零的点，输出它，然后把它**以及所有从它出发的弧**一起删掉，再回去重新找。

找零入度点时有个偷懒办法：**只关注每个节点身边有没有箭头指向它**。

看图：$B$、$C$、$D$、$E$、$F$ 身边都有箭头，只有 $A$ 身边没有。所以第一个输出的只能是 $A$，**没有第二种可能**。

删掉 $A$ 和它的出弧之后，$C$、$D$、$E$、$F$ 仍然都有入边，只有 $B$ 的入度归零了，所以 $A$ 之后直接输出 $B$，还是**没有第二种可能**。

再删掉 $B$ 及其出弧，剩下的弧是 $D \to E$、$D \to F$、$E \to F$ 这三条。此时入度为零的点**依然只有一个**，输出 $D$；再输出 $E$；最后输出 $F$。

| 步骤 | 当前入度为零的点 | 动作 |
|---|---|---|
| 一 | 只有 $A$ | 输出 $A$，删 $A$ 及它的两条出弧 |
| 二 | 只有 $B$ | 输出 $B$，删 $B$ 及其出弧 |
| 三 | 唯一（$D$） | 输出 $D$，删 $D$ 及 $D \to E$、$D \to F$ |
| 四 | 唯一（$E$） | 输出 $E$，删 $E$ 及 $E \to F$ |
| 五 | 唯一（$F$） | 输出 $F$，序列结束 |

> **结论**：整个过程中**每一步的零入度点都只有一个**，没有任何一步出现分叉，所以这个有向图的拓扑序列是**唯一的**，个数为 1。选 A。

这里还牵出一个对真题的呼应：**2024 年那道代码题**问的就是"如何设计算法判断一个给定有向图是否只有一个拓扑序列"。知道什么情况下才唯一（每轮扫描零入度点都恰好一个），反过来你就知道那道算法题该怎么写了。

### 迪杰斯特拉：题目问的是第几步的数组

第八题考迪杰斯特拉算法，这道题大家的疑问特别多——**不是不会算，而是看不明白题目问的是什么**。

题目说：起点是顶点 1，"找到第二条最短路径之后的 DISS 数组"更新成什么。

先把 DISS 初始化成从顶点 1 直达各顶点的弧上权值：

| DISS[2] | DISS[3] | DISS[4] | DISS[5] |
|---|---|---|---|
| 26 | 3 | $\infty$ | 6 |

（1→2 有弧权 26，1→3 有弧权 3，1→4 没有弧，1→5 有弧权 6）

然后按迪杰斯特拉的流程走：

**先找最小值**。当前数组里的最小值是顶点 3 的 3，所以第一条最短路径（$1 \to 3$）就求出来了，$D[3]=3$ 定下来。

**再更新**。定了 $D[3]$ 之后，要用顶点 3 去看能不能把别的顶点变得更短：3 到 2 有一条权值 22 的弧，$3+22=25 < 26$，所以 $D[2]$ 更新为 25；3 到 4、3 到 5 都没有弧，这两处保持原值。

**再找第二条**。此时数组里的最小值变成了顶点 5 的 6，第二条最短路径（$1 \to 5$）求出来了，$D[5]=6$ 定下来。

**再更新**。用顶点 5 去更新其余顶点：

- 5 → 2 有一条权值 15 的弧，$6+15=21 < 25$，所以 $D[2]$ 更新为 21；
- 5 → 4 有一条权值 8 的弧，$6+8=14 < \infty$，所以 $D[4]$ 从 $\infty$ 变成 14；
- 顶点 3 不动，值还是 3。

| 阶段 | $D[2]$ | $D[3]$ | $D[4]$ | $D[5]$ |
|---|---|---|---|---|
| 初始化（直达弧） | 26 | 3 | $\infty$ | 6 |
| 找到第一条（顶点 3）后用它更新 | 25 | 3 | $\infty$ | 6 |
| 找到第二条（顶点 5）后用它更新 | **21** | **3** | **14** | **6** |

最终数组是 $21, 3, 14, 6$，选 C。

> **易错点**：这道题做不对的原因，几乎从来不是算法不会，而是**太关注"最终求解过程"，把算法的步骤顺序给忘了**。你脑子里想的是"从 1 到各点最短路径是多少"，但题目问的是"执行到第几步时的中间状态"。迪杰斯特拉的骨架是**"先找一个、再更新、再找下一个、再更新"**，节奏是一拍一拍的。

这里也说明为什么必须回去翻教材：做完题之后不停地回顾概念定义和算法的官方描述流程，才能把知识学透。像"我会了，但不知道他问我的是哪一步的数组"这种麻烦，说到底就是**基础没打牢**。

### 三阶 B 树：先算关键字范围，再数节点

第九题给一棵三阶 B 树，$M=3$，高度为 3，题目还额外告诉你第二层一共有四个关键字，问这棵 B 树最多有多少个节点。

这种"给高度和关键字情况、让你数节点"的题目，套路跟前几年（包括 25 年那道）都差不多。**最基本的一步，是先快速算出 $M$ 阶 B 树中一个节点的关键字范围**：

$$\text{非根节点：}\ \lceil M/2 \rceil - 1 \ \sim\ M-1 \qquad \text{根节点：}\ 1 \ \sim\ M-1$$

$M=3$ 时，$\lceil 1.5 \rceil - 1 = 2-1 = 1$，$M-1=2$，所以**非根节点的关键字范围是 $1 \sim 2$**。根节点是 $1 \sim 2$，这一题里两者一样。

现在问**节点数最多**，那就让根节点取满——两个关键字。有 $k$ 个关键字的节点有 $k+1$ 个孩子，所以**第二层固定是 3 个节点**。

注意题目说的是**高度为 3**，也就是根算第一层。能确定层数和节点数的是前两层；第三层有几个节点，取决于**第二层的关键字个数**——而题目已经告诉我们了：第二层总共 4 个关键字。

4 个关键字分到 3 个节点里，每个节点 1~2 个，怎么分？只能是 $1+1+2$。没有别的可能——你不可能分出 $1+3+0$，因为每个节点都必须在 $1 \sim 2$ 范围内。

```text
关键字个数 k :  1    2
孩子个数 k+1:   2    3
```

而**不管 4 个关键字按哪种顺序分配，$1+1+2$、$1+2+1$、$2+1+1$ 算出来的孩子总数都是一样的**。我们求的是节点数不是形态数，所以顺序无关：

$$1\ (\text{根}) + 3\ (\text{第二层}) + \big[(1+1)+(1+1)+(2+1)\big]\ (\text{第三层}) = 1+3+7 = 11$$

答案选 A。

> **提示**：别嫌我啰嗦——**根节点与非根节点的关键字范围，每次都要快速算一遍**。这个 $\lceil M/2\rceil-1$ 只有在反复重复中才能在考场上瞬间反应过来，然后才谈得上"根据已知条件不断去凑"。

### 基数排序：第一趟之后 372 的前后是谁

第十题考基数排序，21 年只考了它。这类题目出现得少，**掌握住基数排序的过程就行**。

题给的序列最高三位，用**低位优先（LSD）**排成升序，问第一趟分配和收集之后，372 之前和之后紧邻的元素分别是多少。

原序列是：

```text
93, 946, 372, 151, 301, 485, 236, 327, 146, 13, 892
```

低位优先就是从**个位**开始排。基数是十进制，所以准备 0~9 这十个桶；分配的时候**一定要标记好元素的先后顺序**——收集是**按原相对顺序**进行的，比如 146 一定排在 946 后面，因为它本来就在 946 后面。

| 桶（按个位） | 收集到的元素（保持原相对顺序） |
|---|---|
| 1 | 151, 301 |
| 2 | 372, 892 |
| 3 | 93, 13 |
| 5 | 485 |
| 6 | 946, 236, 146 |
| 7 | 327 |

从 0 到 9 从上往下收集，第一趟的结果是：

```text
151, 301, 372, 892, 93, 13, 485, 946, 236, 146, 327
```

所以 372 前面紧邻的是 **301**，后面紧邻的是 **892**。选 C。

#### 一个能省时间的巧办法

完整走一遍当然最保险，但如果我问的是第二趟，就只能老老实实全排了；第一趟其实是有窍门的。**别去排，直接看 372 的个位**：

- 372 个位是 2。排在它**前面**的元素，个位只可能是 **1**（个位为 1 的会先被全部收集完），或者是在**原序列中位于 372 之前、个位也是 2** 的那个数。所以 A、B、D 这类前缀对不上的选项可以一口气排掉。
- 排在它**后面**的元素，个位只能是"原序列中位于 372 之后的个位为 2 的数"，或者"个位为 3 的数"（因为个位 2 收完紧接着就收 3）。

进一步定位：原序列里 **372 之前没有任何个位为 2 的数**，所以它前面只能是最靠后的那个个位为 1 的元素——就是 **301**（所有个位为 1 的都先收完，最后一个是 301）。而 372 后面确实有个位为 2 的 **892**，所以后面就是 892，**轮不到 93**。

答案依然是 C。这种方式更省时，因为可以直接对着当前序列的状态看。当然你觉得全排更保稳，那就全排，两种都行。

### 大根堆：一边插一边调

第十一题是把若干关键字**依次插入到初始为空的大根堆**中，问最终得到的堆是什么。

这题和我们平时学的"建堆 / 调整"过程不一样，得先把心态摆正：

> **易错点**：**既然是"插入到大根堆中"，就不可能是一口气全插完再去调整**，而是一个一个插进去，哪一步破坏了堆性质就调整哪一步。这种题跟"先建好堆再调整"的常规套路完全不同，要根据题目灵活变通。

插入过程一定是一个线性序列，我们一个一个来（序列是 $6,9,1,5,8,4,7$）：

- **插 6**：堆为空，6 直接作为根。`6`
- **插 9**：进 6 的左孩子位置。9 > 6，违反大根堆性质 → 9 与 6 交换。`9 6`
- **插 1**：进 6 的右孩子位置。1 < 6，满足。`9 6 1`
- **插 5**：进 6 的左孩子位置（层序的下一个空位）。5 < 6，满足。`9 6 1 5`
- **插 8**：父结点是 6，8 > 6 违反 → **6 和 8 交换**；8 再和 9 比，9 更大，满足，停。`9 8 1 5 6`
- **插 4**：父结点是 1，4 > 1 违反 → **4 和 1 交换**；4 再和 9 比，9 更大，满足。`9 8 4 5 6 1`
- **插 7**：父结点是 4，7 > 4 违反 → **7 和 4 交换**；7 和 9 比，9 更大，满足。`9 8 7 5 6 1 4`

| 插入 | 上浮过程 | 调整后的层序 |
|---|---|---|
| 6 | 空堆，作为根 | 6 |
| 9 | 与 6 交换 | 9 6 |
| 1 | 无需调整 | 9 6 1 |
| 5 | 无需调整 | 9 6 1 5 |
| 8 | 与 6 交换，再与 9 比较后停 | 9 8 1 5 6 |
| 4 | 与 1 交换，再与 9 比较后停 | 9 8 4 5 6 1 |
| 7 | 与 4 交换 | 9 8 7 5 6 1 4 |

最终的大根堆是 **9 8 7 5 6 1 4**，选 B。

> **提示**：一定要把"哪些是原叶结点、哪些是构造出来的"分清楚，习惯上用方框和圆形区分，这样后面算 WPL、写编码、做其他延伸时都能一眼认出节点属于哪一类。

### 这一年的排序题说明了什么

可以看到，21 年的排序部分**没有出现"两种排序之间的比较"**这种综合题型，而是分别单独考了基数排序和大根堆。

但别因此放松。我之前就说过，**排序不止会考一道两道题**，凡是出现综合性题目的地方，就需要你把所有排序算法都备注齐全。越到后期，越要回过头去把第八章的全部内容重新过一遍——**排序这一章是需要反复背诵和记忆的**，它的分量在整个数据结构里是越来越重的。

### 本讲提到的题目

#### 在平衡二叉树那棵树里，把新插入的节点换成 26

那道 AVL 题的树是这样的：

```text
        20
       /  \
      16   30
          /  \
         25   40
           \
            26
```

26 是新插入的节点，要让它重新平衡，步骤是什么？

**解析**：26 > 20，所以先往 20 的右子树走；26 < 30，往 30 的左子树走；26 > 25，所以落在 25 的右边。最小不平衡子树的根**仍然是 20**（25、30 的平衡因子还是 1，20 是 $1-3=-2$），26 依然位于 20 的右孩子的左子树上，**旋转类型不变，还是 LR 双旋**。

**答案**：先对以 20 为中心的大范围子树做右旋，再对以 20 为根的做左旋。25 肯定要上来，30 下来，40 也下来；26 比 25 大、比 30 小，所以它最好的位置是挂在 **30 的左边**（也就是 25 的右孩子）。最后 25 上升成为根：

```text
         25
        /  \
      20    30
     /  \     \
    16   26    40
```

有意思的是，右旋那一步比上一次顺多了：上一次的 23 多少有点阻碍 20 的旋转，而 26 恰好把 25 的位置让了出来，所以做左旋时可以直接把 20 放到下面，25 自然就上去了。

> **提示**：你整体的操作思路永远是"把这样的子树旋成那样的形状"，不管它下面的分支拐到哪里。

#### 如果那道三阶 B 树的题问的是"形态个数"

原题是问节点个数最多是多少。如果把问题换成"**这棵 B 树可能有几种形态**"呢？

**解析**：第二层 3 个节点、总共 4 个关键字、每节点关键字范围 1~2。第二层的 4 个关键字只有一种分法：$1+1+2$。而这个 $1+1+2$ 在三个节点上的排列方式不止一种，分别是 **112、121、211**，每种排列对应一棵形态不同的 B 树。

**答案**：3 种。

> **提示**：25 年出的那道题考的就是形态个数，只是条件没有 21 年这道给得这么齐。所以"求节点数"和"求形态数"是两种问法，前者只管加和、顺序无关，后者才需要把每一种排列都数出来。做完 21 年这道，顺手把 25 年那道也想想。

这一讲把 2021 年统考的第 12 题到第 40 题完整过一遍。题目跨度不小，组成原理、操作系统、计算机网络三门都考到了，但真正吃力的不是知识点本身，而是「题目给的条件到底要我算什么」——很多同学读完题干都不知道从哪儿下手。所以这一讲我会把每道题「为什么这么想」的来路都讲出来，而不只是报一个答案。

先从一道看着最唬人的题开始。

### Flops 与量纲：P 到底代表多少

2017 年公布的全球超级计算机 Top500 排名里，我国神威·太湖之光蝉联第一，它的浮点运算速度是 93.0146 PFlops。题目问这个运算速度是多少。

看着吓人，其实就是个量纲转换。93.0146 PFlops 意思是每秒完成 $93.0146 \times 10^{15}$ 次浮点运算。

这里有个**特别容易踩的坑**：K、M、G、T 这一串前缀，到底该按二的十次方还是十的三次方递增？答案是不统一，**看描述的是什么量**。

| 描述对象 | 每级递增 | 前几个 |
| :--- | :--- | :--- |
| 存储容量、文件大小、长度 | $2^{10}$ | K=1K，M=1M，G=1G，T=1T，P=1P |
| 运算速度、频率 | $10^{3}$ | K=$10^3$，M=$10^6$，G=$10^9$，T=$10^{12}$，P=$10^{15}$ |

神威太湖之光是**速度**，所以走十的三次方那一列。于是

$$
93.0146 \times 10^{15} \approx 9.3 \times 10^{16}
$$

选项里给的是 9.3 开头，后面直接写成「亿亿次」——因为 $10^{16} = 10^8 \times 10^8$，正好是两个亿。答案选 **D**。

> **提示**：看到 Flops、Hz、bps 这类速度单位，就老老实实按 $10^3$ 换；看到 KB、MB、GB 这类容量单位，就按 $2^{10}$ 换。记混了会差出 8 倍以上。

### 补码比大小：三种做法，从繁琐到省事

已知带符号整数用补码表示，X、Y、Z 的机器数分别是 FFFDH、FFDFH、07FFH。问：无符号和有符号两种解释下各是什么大小关系？

#### 先看无符号：无符号数没有符号位，位序即大小

无符号数里最高位也是数值位，位权照算，所以越靠前的 1 越值钱。举个最直观的例子：

```text
1100  = 12
1000  =  8
       ^ 靠前的 1 权重是 8，靠后的是 4
```

回到本题：X=FFFDH 前面的 F 是全一，十六进制一位四个一，FF 一共十二个一；Y=FFDFH 前面的 F 只有八个一，后面就断了。Z=07FFH 最高位是零（7 就是 0111）。所以

$$X > Y > Z$$

无符号条件下，选 **A**。

#### 有符号：先把补码还原成真值

补码转真值不用绕弯子，**符号位不变，数值位取反加一**，得到原码，符号位为 1 就是负数。

X = FFFDH = 1111 1111 1111 1101，符号位不动、数值位取反加一：

```text
补码   1111 1111 1111 1101
取反   1111 1111 1111 0010
加一   1111 1111 1111 0011   ->  -3
```

Y = FFDFH 同理，数值位取反得 ...0000，加一得 ...0001，绝对值是 33，带符号是 $-33$。

Z = 07FFH 符号位是零，正数，直接算：$0\times2^{15} + 127 = 127$……把中间的 0 展开算完整是 $2047$。

$$Z > X > Y$$

答案还是 **D**。

#### 直接比补码：负数的判断要反过来

其实不还原成真值也能比。关键在于：**原码里负数是「数值位越靠前的 1 越多、数越小」，补码里恰好反过来**。

为什么反过来？因为求补要做一次「取反加一」，取反把靠前的 1 全搬到靠后去了，于是补码里负数变成了「1 越靠前、数越大」。本题 X 的 1 集中在靠前位置，Y 的 1 集中在靠后位置，所以 $X > Y$，与还原真值的结论一致。

> **易错点**：这一条只对**负数**成立。两个正数比较时，补码和原码的判断方向是相同的（都是靠前的大）。所以「补码比较靠前的 1 越多越大」这句话不能不分正负就往上套。

#### 换码比较：最省事的一种

还有第三种方法，也是我更推荐平时用的：**把补码换成绩码（移码）再比**。

为什么换码之后就能直接比？因为移码是在真值上加了一个偏置 $2^{n-1}$，把整个负区间平移到非负区间去了。八位补码的范围是 $-128 \sim 127$，加上 128 就变成 $0 \sim 255$——**正负数被拉到了同一侧**，大小顺序完全不变，于是位序判断就重新变得有效。

移码的算法也简单：**补码的符号位取反**。

```text
X = FFFD  ->  7FFD
Y = FFDF  ->  7FDF
Z = 07FF  ->  FFFC
             ^^^^ 全 1，数值最大
```

FFFCH 最大，7FFDH 次之，7FDFH 最小，所以 $Z > X > Y$。

> **结论**：三种做法都能选到 D。考试时挑你顺手的用就行，我个人最推荐换码比较，因为它既不用还原真值、也不会搞反正负号的方向。

### 哪些小数能被 IEEE 754 精确表示

题目问下列数值中**不能用 IEEE 754 浮点格式精确表示**的是哪个。

浮点格式是二进制科学计数法，能精确表示的前提是：这个数的有效数字能写成有限位的二进制小数。哪些不能？只要**小数部分是 5 的因子**就一定有无穷展开。

逐个看：

- **1.2**：整数部分 1 没问题（藏在隐藏位里），但 0.2 转二进制是 $0.001100110011\ldots$ 无限循环。$2^{-1}=0.5$、$2^{-2}=0.25$、$2^{-3}=0.125$，0.2 没法由它们有限组合出来。**选 A**。
- **1.25**：$= 1.01_2 = 1.01 \times 2^0$，尾数 01 直接放进有效数字位，符号位为正。精确。
- **2**：$= 1.0 \times 2^1$，隐藏位置 1，尾数 0.0，阶码为 1。精确。
- **2.5**：$= 10.1_2 = 1.01 \times 2^1$。精确。

答案 **A**。

> **提示**：平时要攒一点二进制小数的「手感」。0.2、0.7 这类都转不干净；0.25、0.125、0.5、0.625 这类都是 2 的负幂组合，干净。

### 从存储总线宽度倒推 RAM 区容量

某机存储总线有 24 位地址线、32 位数据线，按字编制，**字长为 4 个字节**。问若地址范围为 RAM 区，需要多少片 512K×8 位的 RAM 芯片。

#### 存储单元个数

先看地址范围能编址多少个存储单元。地址从 00000H 到 3FFFFFFFH，个数是**末地址减首地址再加一**：

$$
\text{3FFFFFFF}_{\text{H}} - \text{00000}_{\text{H}} + 1 = \text{400000}_{\text{H}} = 2^{22}
$$

减零其实等于不做操作，加一才是关键，别漏。

#### RAM 区总容量

一个存储单元占多少位？按字编制，字长 4 字节 = 32 位，所以一个存储单元就是 32 位。于是

$$
2^{22} \times 32\ \text{位} = 2^{22} \times 4\ \text{字节} = 2^{24}\ \text{字节} = 16\ \text{MB}
$$

> **易错点**：题目给的是 32 位**数据线**，但同时给了「字长为 4 字节」和「按字编制」，这三条是一致的——按字编制下一个存储单元就是一个字，32 位。如果题目改成按字节编制，那一个存储单元就只有 8 位，算法完全不同。

#### 拆成字扩展与位扩展

要凑出 16MB，用的是 512K×8 位的芯片，容量是 $512\text{K} \times 1\ \text{字节} = 2^{19}$ 字节。

```text
总需求 16 MB
  |
  |-- 字扩展：16 MB / 512K = 2^24 / 2^19 = 2^5 = 8 组
  |
  `-- 位扩展：4 字节 / 1 字节 = 4 片（拼成 32 位字长）
```

这里我习惯用「先约掉单位再看幂次」的办法：把 16MB 写成 $2^{24}$、512K 写成 $2^{19}$，$24 - 19 = 5$ 就是字扩展的组数；4 字节除以 1 字节得到 4，这是位扩展、片内并联的片数。

$4 \times 8 = 32$ 片，答案 **C**。

### Cache 行长：tag、脏位、有效位一个都不能少

主存地址 32 位、按字节编址，Cache 数据区 32KB，主存块 32 字节，直接映射、写回策略，问 Cache 行的位数至少是多少。

> **注意题干问的是「行」**，也就是一行里装多少位。所以**不用乘行数**，这题不算总容量。

一行 = 数据区 + 标记区。

#### 数据区

一个 Cache 块就是一个主存块，32 字节，即 $32 \times 8 = 256$ 位。

#### 行号占多少位

行数 = 数据区总大小 ÷ 每行数据区大小 $= 32\text{KB} / 32\text{B} = 1024 = 2^{10}$，所以行号 10 位。

#### 块内地址占多少位

主存块 32 字节，按字节编址，所以块内地址 $\log_2 32 = 5$ 位。

#### tag 位数

直接映射下主存地址的构成是：

```text
 31                    21 20        10 9      5 4        0
+------------------------+-----------+---------+----------+
|         tag            |   行号    | 块内地址 |  字节偏移  |
|         17 位          |   10 位   |   5 位   |   (同块内)|
+------------------------+-----------+---------+----------+
        32 - 10 - 5 = 17
```

$\text{tag} = 32 - 10 - 5 = 17$ 位。

#### 标记区还要额外两位

| 字段 | 位数 | 为什么必须有 |
| :--- | :--- | :--- |
| tag | 17 | 主存块地址的高位，区分同一行里的不同主存块 |
| 有效位 | 1 | 标识这一行当前是否装过有效数据 |
| 脏位 | 1 | **写回策略**下，主存块已被修改、尚未写回内存 |

直接映射没有替换位——块的位置是地址唯一决定的，冲突了只能直接覆盖，不需要「要不要换掉原来那块」的判断位。

标记区共 $17 + 1 + 1 = 19$ 位，一行总计

$$
256 + 19 = 275\ \text{位}
$$

答案 **A**。

> **易错点**：替换位只在 Cache 满时才起作用，直接映射根本用不上，所以**不能加**。反过来，若题目换成全相联或组相联且没指定替换算法，才需要讨论替换位；而组相联还要在 tag 里把组号剥掉。

### 哪些寄存器对汇编程序员可见

题目列了四个寄存器，问哪些对汇编程序员可见。

- **指令寄存器（IR）**：存放当前正在执行的指令，由硬件取指自动装载，程序不可见。
- **微指令寄存器**：在控制器内部，微程序控制器从控制存储器取出微指令后送进这里，程序不可见。
- **基址寄存器**：可见。它通常就是从通用寄存器里划出来当基址用的，汇编指令能直接访问。
- **状态条件寄存器（标志寄存器）**：可见。执行条件转移指令时，就是靠它里面的零标志、进位标志、溢出标志、符号标志来判断要不要转移。

所以选第三、四，答案 **D**。

> **提示**：判断标准就一条——**能不能被指令显式读写**。IR 和微指令寄存器是控制器内部的「流水线」部件，不给程序员碰。

### 数据通路与总线：两道概念判断题

#### 数据通路的错误叙述

- **A** 数据通路包含 ALU 等组合逻辑元件。组合逻辑的输出只与当前输入有关、与历史状态无关，ALU 正属于此列。**正确**。
- **B** 数据通路包含寄存器等时序逻辑元件。寄存器有记忆功能，输出与过去状态有关，属时序逻辑。**正确**。
- **C** 数据通路不包含用于异常事件检测及响应的电路。**错误**。指令执行过程中随时可能出现异常和中断，检测与响应它们的电路必然属于数据通路的一部分——除了控制单元，数据通路里的东西都归它管。
- **D** 数据流动的路径由控制信号控制。控制信号驱动数据在通路中流动，从而完成指令执行。**正确**。

错误的是 **C**。

#### 总线的错误叙述

- **A** 总线是两个或多个部件之间进行数据交换的传输介质。这是定义，**正确**。
- **B** 同步总线由时钟信号定时，时钟频率不一定等于工作频率。**正确**。一个时钟周期里能传两次数据，工作频率就是时钟频率的两倍，两者本来就不必相等。
- **C** 异步总线由握手信号定时，**一次握手过程完成一位数据的交换**。**错误**。一次握手传的是**一个数据块**，不是一位。传一位也太少，效率根本没意义。
- **D** 突发传送的总线事务可以在总线上连续传送多个数据。**正确**。突发方式只送一次首地址，后面连续送数据。

错误的是 **C**。

### I/O 接口：先认名字再判断

题目问下列选项中不属于 I/O 接口的是哪个。这题很多人没见过「I/O 接口」这个说法，我们就从名字本身推。

- **磁盘驱动器**：这是**存储设备**。它确实参与 I/O，但它存的是数据，硬件身份是外存，不属于接口。
- **打印机适配器**：名字里就有「适配」。不同厂家的打印机在数据格式、传输方式、管理方式上都不一样，需要一个适配器把它们统一成 CPU 能接受的形式，让 CPU 用同一种方式跟任何打印机打交道。这正是 I/O 接口的职能。**正确**。
- **设备控制器**：I/O 接口还有一个别称就叫设备控制器。不同的网络操作方式不同，计算机要跟网络交互，同样需要控制器来协调管理双方的信息传输。**正确**。
- **可编程中断控制器**：也是控制器。它管理和处理中断信号，不同中断源的优先级不同，由它统一裁决后再和 CPU 交互。**正确**。

不属于的是 **A**。

> **结论**：I/O 接口的本质是「**屏蔽差异、统一接口**」——把各种各样、五花八门的设备或网络，在 CPU 看来都变成统一的样子。

### 异常与中断：谁要重执行当前指令

异常事件在**当前指令执行过程中**检测，中断请求在**当前指令执行后**检测。题目问：下列事件中，处理程序执行后必须回到当前指令重新执行的是哪个。

- **系统调用**：本质上是一条指令（陷阱指令），属于异常范畴。处理完成后要返回**下一条指令**继续。排除。
- **缺页**：要访问的页不在内存，得从外存调进来，调入完成后必须**重新执行这条访存指令**，否则这次访问就没有结果。**正确**。
- **DMA 传送结束**：结束后发起的是中断请求，中断处理完返回**下一条指令**。排除。
- **打印机缺纸**：外中断，返回**下一条指令**。排除。

答案 **B**。

> **结论**：判断口诀——**异常靠指令自己触发，重执行；中断靠外部事件打断，接下一条**。凡是「这条指令没拿到结果」的场合，就得回去重来。

### 多重中断系统：CPU 什么时候能响应中断

题目问多重中断系统中关于 CPU 响应中断的错误叙述。

- **A** 仅在用户态下 CPU 才能检测和响应中断。**错误**。中断服务程序本身就是操作系统的一部分，在内核态运行。在多重中断系统里，执行中断服务程序的前后必须开关中断，因此完全可以在内核态下响应优先级更高的中断。
- **B** CPU 只有在检测到中断请求后才会进入中断响应周期（题目原句表述有误，正确说法是：进入中断响应周期的必要条件之一是有中断请求）。**正确**。
- **C** 进入中断响应周期时 CPU 一定处于中断允许（开中断）状态。**正确**。题目限定了多重中断系统——既然要响应更高优先级的中断，进入响应周期时必然是开中断的，否则更高优先级的请求也进不来。
- **D** 若 CPU 检测到中断请求信号，则一定存在未屏蔽的中断源请求信号。**正确**。被屏蔽掉的中断请求 CPU 是看不见的。

错误的是 **A**。

### 特权指令：trap 不在其中

题目问只能在内核态执行的指令是哪个。

- **trap 指令**：它在**用户态**执行，执行完之后才引起状态转换、进入内核态。这一点前面已经考过很多次了，是易错重灾区。
- **I/O 指令**：属于特权指令，负责控制 CPU 与 I/O 设备之间的数据传输交互，**只有内核态能执行**。**正确**。
- **数据传送指令**：普通指令，寄存器之间赋值这类最基本的操作，用户程序随便用。
- **设置断点指令**：调试用的，在软件里写一段设置断点的程序即可，在用户态执行。

答案 **B**。

> **易错点**：trap 指令是「在用户态执行、执行完才进内核」，而 I/O 指令是「本身特权、只能在内核态执行」。两者一字之差，方向完全相反，别记混。

### 创建新进程必须做哪两步

- **申请一个空白 PCB**：必须的，没有 PCB 就没有落脚点。
- **初始化 PCB**：必须的，把状态信息、处理机信息都初始化好。
- **设置进程状态为执行态**：**不需要**。刚创建的进程根本没有 CPU，得先进入**就绪队列**排队，等后续进程调度时把处理机分配给它，才转成执行态。
- （第四项按题目原文同样属于非必需。）

所以答案是**一、二**，对应 **B**。

> **提示**：进程刚出生是就绪态，不是运行态。运行态只能由调度程序赋予。

### 时间片轮转需要用到哪些内核设施

分时系统实现时间片轮转调度，需要：① 进程控制块；② 时钟中断处理程序；③ 进程就绪队列；④ 进程阻塞队列。

- **① PCB**：需要，而且很容易被忽略。PCB 里存着本进程已经执行了多长时间，轮转调度每跑完一轮都要更新它，用剩余时间片来判断要不要切换进程。
- **② 时钟中断处理程序**：需要。时间片什么时候到？靠时钟中断来触发。
- **③ 就绪队列**：需要。时间片到了要切换进程，旧进程从**运行态转到就绪态**，得放回就绪队列。
- **④ 阻塞队列**：用不到。这里发生的是运行态到就绪态的转换，不是到阻塞态。

所以答案是 1、2、3，选 **C**。

### 最短寻道优先：只能一节一节算

磁盘有 200 磁道，磁头当前在 184 号，用户请求的磁道号依次是 184、182、187、176、199，用最短寻道优先（SSTF）调度，求磁头移动距离。

SSTF 的特点是**每次都去当前磁道号最近的待访问磁道**，移动距离既不是持续递增也不是持续递减，所以只能一段一段算。

按这个规则，访问顺序是：184（原地）→ 182 → 187 → 176 → 199。

```text
184 -> 182   移动  2
182 -> 187   移动  5
187 -> 176   移动 11
176 -> 199   移动 23
                -----
                合计 41
```

答案 **C**（41 磁道）。

### 哪些事件会引起进程调度

四个选项逐一判断：

- **① 中断处理结束之后**：之前进程是因为缺某些资源而发起 I/O 阻塞的，现在 I/O 完成了、资源到手，它就能进就绪态了。如果此刻 CPU 正好空闲，就可以调度它。**会**引起调度。
- **② 进程阻塞**：进程原本是运行态，转入阻塞态时会**主动释放 CPU**。CPU 空出来了，就绪队列里任何进程都有机会被调度上去。**会**。
- **③ 进程执行结束**：进入终止态，要释放它占用的所有资源，其中就包括处理机。**会**。
- **④ 进程时间片用完**：时间片用完就要调下一个进程接着跑一个时间片。这本来就是调度的直接触发条件。**会**。

四个都正确，答案 **D**。

### 请求分页 + 改进型 CLOCK：一个真实的置换过程

某请求分页系统页大小 4KB、按字节编址，给进程 P 分配了两个固定页框，采用改进型 CLOCK 置换算法。访问虚拟地址 02A01H，问变换后的物理地址。

#### 拆页号与页内地址

页大小 4KB = $2^{12}$ 字节，所以**页内地址 12 位**。把 02A01H 的低 12 位切出来：

```text
 02A01H
  ^^^^  低 12 位 -> 页内地址 A01H
  ^^    高位     -> 页号     02H
```

页号 2。查页表，页号 2 对应那一项的**存在位为 0**，说明这一页不在内存——**发生缺页**。

#### 改进型 CLOCK 怎么挑牺牲者

两个页框的位状态是「一个 (1,0)、一个 (1,1)」（依次为访问位、修改位），内存已满，必须置换。

改进型 CLOCK 的规则是：先找**访问位为 0 且修改位为 0** 的页直接换出；找不到就找**访问位为 0、修改位为 1** 的换出。关键在于，**找的过程本身会把访问位置 0**。

于是两轮扫描是这样走的：

| 轮次 | 页框 1 | 页框 2 | 结果 |
| :--- | :--- | :--- | :--- |
| 初始 | 访问位 1 / 修改位 0 | 访问位 1 / 修改位 1 | 两页都不满足「0/0」 |
| 第 1 轮扫描 | 顺手置 0 → 0/0 | 顺手置 0 → 0/1 | 都命中不了「0/0」，但访问位已清零 |
| 第 2 轮扫描 | 0/0 命中 | — | 换出页框 1 |

所以被淘汰的页框是 **60H**，被换入的新页号是 2，页表项更新为页框号 60H。

#### 拼出物理地址

物理地址 = 新的页框号 + 原页内地址：

$$
\text{60H} \mathbin{+\!\!|} \text{A01H} \Rightarrow \boxed{\text{60A01H}}
$$

答案 **C**。

### 二级页表：页表基址寄存器里存的是什么

二级页表里查地址，第一步是查**页目录表**，而页目录表的入口地址就存在页表基址寄存器里，再配合逻辑地址中的**页目录号**才能定位到某个页目录项。

所以它存的是**页目录表的起始地址**。页目录表也可以叫**一级页表**。

而且既然页表本身存放在主存中，这个地址只能是**物理地址**。

答案 **B**。

> **易错点**：页表基址寄存器 ≠ 页表基址。基址寄存器里放的是「这张表的地址」，不是「这张表里的某一项的地址」。

### 删除文件时内核不必做的事

某目录下有文件 file1，删除 file1 时内核**不必**完成的工作是：

**A．删除 file1 的快捷方式。** 快捷方式本质上是**符号链接**，里面存的是 file1 的路径。删除原文件时，系统**不会主动**去删这个快捷方式——它只是一个指向失效路径的普通文件。只有等你下次双击它、访问那个路径发现无效时，才会提示并清理。

所以内核**不必**在删除原文件时一并删掉快捷方式，**不必**做的是 **A**。

> **提示**：符号链接的生命周期与目标文件解耦，这是它和硬链接最大的区别之一。

### 死锁：资源总数至少 N+1

N 个进程，每个进程都需要使用某类临界资源 2 个，求系统不发生死锁时这类资源总数至少是多少。

想最极端的情况：每个进程都分到 2−1 = 1 个资源，那么所有进程都在等那最后一个，谁都跑不动——**死锁**。

所以要留出余量：让某个进程能凑齐 2 个先跑完，跑完后资源释放，又能分给别的进程，死锁就被解开了。

$$
N \times (2 - 1) + 1 = N + 1
$$

答案 **C**。

> **结论**：这类题的通用做法是「每进程需求 $k$ 个、且每进程最多拿 $k-1$ 个」的临界点，再加 1 打破僵局。

### 哪些操作通过系统调用完成

- **A 页置换**：属于操作系统的内存管理机制，页面满了才从外存调入，是操作系统内核提供的服务，**在内核态执行**，不需要用户程序通过系统调用去请求。
- **B 进程调度**：决定把处理机分给哪个进程，同样是内核自己的服务，**不需要系统调用**。
- **C 创建新进程**：Linux 里用 `fork` 函数创建，**这就是一次系统调用**。**正确**。
- **D 生成随机整数**：C 语言里的 `rand` 是**库函数**，库函数是在用户态执行的，不涉及系统调用。

答案 **C**。

> **结论**：内核自己内部完成的事（缺页置换、进程调度、异常处理）都不算系统调用；用户程序要请求内核服务（`fork`、`open`、`read`、`write`）才算。

### TCP/IP 模型：谁挨着传输层

第 33 题问 TCP/IP 模型中由传输层相邻的**下一层**实现的主要功能。

TCP/IP 四层模型自下而上是：网际层 → 网络层 → 传输层 → 应用层。传输层的下一层就是**网络层**。

```text
  应用层   (OSI 的表示层 + 会话层 + 应用层 合在一起)
  传输层   端到端
  网络层   节点到节点 / 路由选择        <-- 传输层的下一层
  网际层   (五层模型里的物理层 + 数据链路层)
```

选项里的「会话管理」属于应用层（OSI 会话层的功能），「端到端」是传输层的，「节点到节点」在五层模型里是数据链路层、在 TCP/IP 里是网际层，都不是网络层。网络层的标志性功能是**路由选择**。

答案 **B**。

> **提示**：这一题考的就是各层功能的归属，哪一层做什么必须背到不用想。

### 差分曼彻斯特编码：看边界，跳变是零

第 34 题给一段波形，问差分曼彻斯特编码的位串。

差分曼彻斯特的规则是看**每个比特周期的边界处**：

- 边界处**发生跳变** → 该比特是 **0**
- 边界处**不跳变** → 该比特是 **1**

```text
位序      1    2    3    4    5    6    7    8
边界      ?   跳变  不跳变 跳变  跳变  不跳变  不跳变 跳变
比特      ?    0     1     0     0     1      1      0
```

第一个比特有个固有问题：它的边界在波形最左边，我们不知道它**前面**的信号是什么，所以无法判断跳没跳变。

> **结论**：差分曼彻斯特**永远确定不了第一个比特**，直接把它丢掉，看第二个到最后一个。得到 `01100110`，据此选 **A**。

### 变长子网划分：画棵树最快

第 35 题：某 IP 网络划分成三个子网，其中一个是 `10/26`，问下列哪个**不可能**是另外两个子网之一。

划分子网只有两个硬性要求：**不重叠**（不出现重复 IP）、**全覆盖**（不留空隙）。我习惯直接画树判断：

```text
8 位地址空间的划分树（按前缀逐层二分）
 1        0
 |        |
 +-- 0/25 ...          1/2
     |    |
   0/26  10/26(题给)
```

**A 选项（`0/25`）可以**：`0/25` + `10/26` + `11/26` 三个前缀恰好把 `/24` 的 8 位空间切得整整齐齐，互不重叠、完全覆盖。网络号就是 `/24`。**C 选项（`11/26`）因此也可以**。

**B 选项（`00/26`）不行**：它比 `0/25` 还小一号，落在一大片已经用 `0/25` 覆盖的范围里。题干说「另外两个子网」，而 `10/26` 已经用掉一个名额，剩下的名额要同时覆盖被 `00/26` 挖掉的那块和 `10/26` 右侧的空缺——一块子网做不到。**B 不可能**。

**D 选项（`110/27` 或 `111/27`）可以**：关键在于题目**没有告诉我们这个 IP 网络的网络号到底多长**。如果网络号取 `/25`（即 `192.168.9.128/25`），那么在 `/25` 内部做覆盖就容易得多——`10/26` 加上剩下两片 `110/27`、`111/27` 恰好把 `/25` 铺满。

> **提示**：这种变长子网划分，我建议**画树**，比在脑子里算区间快得多。也可以像答案解析那样，直接把每个选项的**包含 IP 范围**写出来，然后检查「不重叠 + 全覆盖」两条是否同时满足。

### IP 分片：片偏移以 8 字节为单位

某路由器向 MTU=800 字节的链路转发一个总长 1580 字节的 IP 数据报，首部 20 字节，要求每个分片尽可能大，问第二个分片的总长度和 MF 字段。

#### 第一片能装多少数据

MTU 800 意味着整个 IP 数据报总长必须小于 800，首部占 20，所以数据部分最大 $800 - 20 = 780$ 字节。

原始数据部分是 $1580 - 20 = 1560$ 字节。

看起来 780 和 780 正好一半，但**不行**。

#### 卡点：片偏移必须能表示

片偏移字段以 **8 字节**为单位。要让第二片的片偏移可表示，第一片的数据部分长度就**必须是 8 的整数倍**。

$780 \div 8 = 97.5$，余 4，所以向下取到 8 的整数倍：$780 - 4 = 776$ 字节。

#### 结果：其实要分三片

| 分片 | 数据部分 | 总长度（含 20 字节首部） | MF |
| :--- | :--- | :--- | :--- |
| 第 1 片 | 776 | 796 | 1 |
| 第 2 片 | 776 | 796 | **1** |
| 第 3 片 | $1560 - 776 - 776 = 8$ | 28 | 0 |

注意 $1560 - 776 = 784 > 780$，说明**装不下第二片**，必须分三个。

MF 是 more fragment，「后面还有没有更多分片」。总共三个分片，第二个后面还有，所以 **MF=1**。

答案 **B**（总长度 796，MF=1）。

> **易错点**：如果本题只分成两片，第二个分片就是最后一片，MF 应该是 0，答案就变成 A 了。分片题一定要先确定**分几片**，再谈 MF。
>
> 另外，片偏移的数值是「相对原数据报的字节位置 ÷ 8」。第二、三片的偏移分别是 $776 \div 8 = 97$ 和 $1552 \div 8 = 194$。

### 距离向量路由：加的不是 1，是题给的数

第 37 题：网络中所有路由器采用距离向量路由算法，E 与邻居 A/B/C/D 的直接链路距离给定，E 收到邻居的距离向量，问 E 到各目的网络的最短距离。

距离向量算法的本质是：**把邻居报过来的距离，加上自己到该邻居的直接链路距离，再对所有邻居取最小值**。

> **易错点**：学 RIP 时我们习惯「加一」，那是因为 RIP 把每经过一个路由器视为距离加一。本题给了**特定的链路距离数值**，就不能再加一，要老老实实加本题给的那个数。

逐个网络算：

| 目的网络 | 经 A | 经 B | 经 C | 经 D | 最小值 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| net1 | 9 | 33 | 32 | 28 | **9**（经 A） |
| net2 | 24 | 45 | 40 | 34 | **24**（经 A） |
| net3 | 32 | 28 | 28 | 42 | **28**（经 B 或 C） |
| net4 | 44 | 40 | 20 | 30 | **20**（经 C） |

所以答案是 9、24、28、20，选 **D**。

> **结论**：别把距离向量算法局限在 RIP 这一个协议里。它要表达的意思就是「邻居的视角 + 我这一跳」。

### TCP 四次挥手：主动方停在 TIME_WAIT

第 38 题：客户端先发 FIN 请求断开，收到服务器的 FIN 并发出 ACK 后，客户端进入什么状态。

主动发起断开的一方和被动方的状态要分开记。主动方的流程是：

```text
客户端(主动关闭)                          服务器(被动关闭)
  |  发 FIN  ------------------>        |  进入 CLOSE_WAIT
  |  进入 FIN_WAIT_1                     |
  |  <------------------  发 FIN + ACK    |
  |  发 ACK  ------------------>        |  进入 LAST_ACK
  |  进入 FIN_WAIT_2                     |
  |  <------------------  发 ACK          |
  |  进入 TIME_WAIT                       |  进入 CLOSED
  |  （等待 2 倍 MSL 后）                  |
  |  进入 CLOSED                         |
```

题目问的是「收到 FIN 并且发送过 ACK 之后」，答案是 **TIME_WAIT**，选 **B**。

> **易错点**：TIME_WAIT 等的是**两倍 MSL**。很多题会问「客户端从进入 CLOSED 状态要多久」，那答案不是 MSL，而是 RTT 加上 TIME_WAIT 的 2MSL。而**服务器**从收到最后一个 ACK 就直接进 CLOSED 了，不用等。

### 传输效率：效率看的是有效载荷占比

第 39 题：12 字节的应用层数据分别经 UDP 和 TCP 传输，最大传输效率是多少。

题目问的是**效率**，那就跟传输时间无关，只看**有效数据占封装后总长度的比例**。

**UDP**：首部固定 8 字节，

$$
\text{效率} = \frac{12}{8 + 12} = \frac{12}{20} = 60\%
$$

**TCP**：问的是**最大**效率，那就不能算可变首部（选项部分），只按固定 20 字节算，

$$
\text{效率} = \frac{12}{20 + 12} = \frac{12}{32} = \frac{3}{8} = 37.5\%
$$

答案 **B**。

> **结论**：这类题唯一的门槛就是记住 UDP 首部 8 字节、TCP 固定首部 20 字节。记住常数，题目就变成一步算术。

### 发送窗口：已发未确认的部分不算还能发的

第 40 题：甲发出 SEQ=501、携带 200 字节数据的段；T1 时刻收到乙的段，其中 SEQ=601、ACK=501、接收窗口 500 字节。问甲在未收到新的确认段前，还能继续向乙发送的数据范围是多少。

先把已有数据理清楚：

```text
甲已发送:  501 ......... 700   (SEQ=501, 长度 200)
乙的确认:  ACK=501  ->  501~700 已收到，但窗口还要往右开
乙的接收窗口: 500 字节
```

注意：**接收窗口 500 字节**是乙当前愿意再收的量，它意味着甲接下来能发送的**总范围**（已发未确认 + 新发）是一个 500 字节的区间。

- 501~700 这一段是**已发送但未确认**的，它仍占在窗口里，不能重复发，所以先把 A、B 这类「再发一次已发过的」排除。
- 窗口右端落在 $701 + 500 - 1 = 1200$，但可发范围只有 500 字节，而 501~700 已经占掉 200 字节，所以**新发的部分只有 300 字节**，即 701~1000。

答案 **C**。

> **易错点**：不能因为要发 801 就不发 701——TCP 是**按序字节流**，不可能跳过 701~800 直接发后面的。哪怕此时拥塞窗口可能比 500 更小（发送窗口取二者较小值），起点也一定从 701 开始，本题选项里没有更小的，所以选 C。

## 两道 2021 年 408 真题：读懂一段排序程序，读懂一条机器指令
> 对应块：BLK54 | 覆盖分集：P138-P140 | 块标题（分集名）：《21年（41）数据结构-代码题》

### 上来先自己跑一遍，这题到底在问什么

2021 年 41 题扔给我们一段代码，不给注释，也不告诉我们它想干什么，就问三个问题：跑完之后数组 B 里是什么；元素之间的比较次数是多少；这个算法稳不稳定，不稳定就改造成稳定的。

这道题对读程序有困难的同学是真的不友好。很多人一看到 `if (A[i] < A[j])` 就开始使劲猜——猜这是什么排序，猜它稳不稳，猜它跟哪本教材上的算法长得像。猜着猜着就掉坑里了。我一直觉得 408 里最容易被低估的就是这一类题：它根本不考你会不会写排序，它考你愿不愿意老老实实把十几行代码一行一行跑完。

所以别猜，跑一遍。

我把 41 题跑完再讲 43 题。43 题是道计组大题，看着跟排序八竿子打不着，但它俩其实是同一件事：都是给你一段"看起来像天书一样的东西"，然后逼你把它拆开、拆到每一个数字都对得上号。

### 先把这段代码读成一句话

```c
void CompareCountSort(int A[], int B[], int N)
{
    int i, j, *count;
    count = (int *)malloc(N * sizeof(int));
    for (i = 0; i < N; i++)
        count[i] = 0;                  // count 先清零
    for (i = 0; i < N - 1; i++)       // 外层：i 取 0 ~ N-2
        for (j = i + 1; j < N; j++)   // 内层：j 取 i+1 ~ N-1
            if (A[i] < A[j])
                count[j]++;
            else
                count[i]++;
    for (i = 0; i < N; i++)           // count 当下标，把 A 搬进 B
        B[count[i]] = A[i];
}
```

先交代变量。传进来的是 A、B 两个数组和 N。A 的内容题目给了；B 的长度也是 6，内容我们不知道；N 就是 A 的长度，取 6。三个辅助变量 `i`、`j`、`count`，其中 `count` 是指针类型的，在下面 malloc 了 N 个整数的空间，所以它本身也是一个数组，长度 N；内容一开始我们什么都不知道，然后第一个 for 循环把它全部清零。

真正干活的只有中间那两层 for 循环。外层 `i` 从 0 到 N-1，内层 `j` 从 i+1 到 N-1，内层每一次都会走到 `if (A[i] < A[j])` 这一句，不是 `if` 就是 `else`，没有别的出口。

那 `count` 到底在记什么？我们直接拿题目给的 A 演算。取 `i = 0`，A[0] 是 25，内层 j 依次取 1~5：

- j=1，A[1]=10，25 < 10 不成立 → 走 else，`count[0]++` → 1
- j=2，A[2]=25，25 < 25 不成立 → else，`count[0]++` → 2
- j=3，A[3]=10 → else → 3
- j=4，A[4]=11 → else → 4
- j=5，A[5]=19 → else → 5

一层内层循环走完，count[0] = 5，这里的 5 就是「25 后面有五个数都小于等于它」。再换成 i=1，A[1]=10：

- j=2，A[2]=25，10 < 25 成立 → 走 `if`，加的是 `count[2]`
- j=3，A[3]=10，10 < 10 不成立 → else，加的是 `count[1]`
- j=4，A[4]=11 → if，加的是 `count[4]`
- j=5，A[5]=19 → if，加的是 `count[5]`

看出来了吗？A[2]=25 明明在 A[1]=10 的左边、比它大得多，可是 `count[2]` 照样加了一。这说明 count 不是"右边有多少比我小"一句话能概括的，它是两头都记的：

$$\text{count}[i] \;=\; \#\{j<i \mid A[j]<A[i]\} \;+\; \#\{j>i \mid A[j]\le A[i]\}$$

左边比我小的，右边比我小的，再加上**右边跟我相等的**，全记到我头上。

> **定义**：`count[i]` 就是 A[i] 在「小于等于」这个尺度下的名次（从 0 开始数），相等的元素只会被算进排在前面那一个的 count 里。

整趟算下来：

| i | A[i] | 左边比它小的 | 右边比它小的 | 右边和它相等的 | count[i] |
|---|---|---|---|---|---|
| 0 | 25 | — | 10、10、11、19 | 25 | 5 |
| 1 | 10 | — | — | 10 | 1 |
| 2 | 25 | 10 | 10、11、19 | — | 4 |
| 3 | 10 | — | — | — | 0 |
| 4 | 11 | 10、10 | — | — | 2 |
| 5 | 19 | 10、10、11 | — | — | 3 |

所以 `count = {5, 1, 4, 0, 2, 3}`。

#### 括号一：跑一遍，B 里躺的是升序

最后一个 for 循环干的事是 `B[count[i]] = A[i]`——把 count[i] 直接当下标用。于是：

| i | A[i] | count[i] | 落到 B 的哪一格 | B 的值 |
|---|---|---|---|---|
| 0 | 25 | 5 | B[5] | 25 |
| 1 | 10 | 1 | B[1] | 10 |
| 2 | 25 | 4 | B[4] | 25 |
| 3 | 10 | 0 | B[0] | 10 |
| 4 | 11 | 2 | B[2] | 11 |
| 5 | 19 | 3 | B[3] | 19 |

按位置重新排一遍：

$$B=\{\,10,\ 10,\ 11,\ 19,\ 25,\ 25\,\}$$

所以括号一的答案是：**把 A 升序排列，结果放进 B**。

这里可以顺手提炼一句非常好用的话：`count` 是「小于等于名次」，`B[count[i]] = A[i]` 就是把每个元素搬到它该在的格子里——这本质上是一次计数排序。

> **提示**：别一认出"计数排序"这个名就开始背它的稳定性结论。就盯着 `B[count[i]] = A[i]` 这一行反推：count[i] 越大的元素，就排在 B 的越后面。等号一旦换了边，两个相等的元素谁拿到的 count 更大，答案自己就冒出来了。

#### 括号二：比较次数是一个求和式

先划边界。变量声明、`malloc`、第一个清零的 for、最后一个搬数的 for，这四块**都不含任何元素之间的比较**。整个函数里只有一句在比较，就是 `if (A[i] < A[j])`；而且每一次进入双层循环的循环体，必定会走 `if` 或者 `else`，必定比较一次。

所以比较次数 = 双层循环体的执行次数。

外层 i 取 0~N-2；固定 i 时内层 j 从 i+1 到 N-1，个数是 $N-i-1$：

| i | j 的范围 | 内层次数 |
|---|---|---|
| 0 | 1 ~ N-1 | N-1 |
| 1 | 2 ~ N-1 | N-2 |
| 2 | 3 ~ N-1 | N-3 |
| … | … | … |
| N-2 | N-1 ~ N-1 | 1 |

这就是我们时间复杂度那套的老套路了——把不含 i 的那部分提出来，对 i 求和：

$$\sum_{i=0}^{N-2}(N-1-i)\;=\;(N-1)(N-1)-\frac{(0+N-2)(N-1)}{2}\;=\;\frac{N(N-1)}{2}$$

前头为什么要减掉那个东西？因为求和的每一项 $N-1-i$ 里已经把 i 提出来了，剩下一个 1 也跟着 i 一起提走了，所以要减掉一个 $\sum i$。i 的取值个数是 0~N-2，一共 N-1 个；$\sum_{i=0}^{N-2}i$ 用二分法首尾项相加再乘个数除以 2，套进去就出来了。

> **结论**：比较次数 $=\dfrac{N(N-1)}{2}$，就是从 N 个里挑 2 个的组合数。代回题目给的 N = 6，是 15 次。

这个式子就是括号二的全部答案。写答题卡的时候，把「比较次数由 i 和 j 的取值范围决定」这句话先说清楚，再把求和式摆上去，最后落到 $\frac{N(N-1)}{2}$——这一问就齐了。过程比结果重要，结果算对了但过程糊弄过去是要扣分的。

#### 括号三：稳定性只看相等元素的先后

稳不稳定这件事，只看**关键字相等的数据元素，相对位置有没有被改掉**。

A 里有 0 号位的 25 和 2 号位的 25，一模一样，记住这个。跑完以后 B[5]=25 是 0 号位的 25 搬过去的，B[4]=25 是 2 号位的 25 搬过去的。也就是说，原来在前面的那个 25，跑完跑到后面去了——**不稳定**。

那稳定性是被哪一步毁掉的？回到双层循环。整个算法里跟"等于"有关系的，就只有一个地方，就是那个 `if / else` 的分叉：`A[i] < A[j]` 成立走 if，不成立（也就是 ≥）走 else。**相等的情况，统统被 else 接走了。**

> **易错点**：这就是"排序算法不稳定"的唯一来源。相等的元素被塞进了"我比你大"那一支，于是靠前的那个反而拿到了更大的 count，跑到后面去了。

改法也就一处：把 `if` 里的 `<` 改成 `<=`，让相等的情况走 `if` 那一支。

```c
            if (A[i] <= A[j])          // 原来是 <
                count[j]++;
            else
                count[i]++;
```

改完是什么效果？再看一遍那两个 25：

- i=0，A[0]=25：j=3、4、5 时 `25 <= x` 不成立，走 else，`count[0]` 加 4 次；j=2 时 `25 <= 25` **成立**，走 if，加到了 `count[2]` 头上。所以 **count[0] = 4**。
- i=1，A[1]=10：j=3 时 `10 <= 10` 成立，走 if，加的是 `count[3]`，不是 `count[1]`。所以 **count[1] = 0**，而且全程序再没有别的地方会给它加。
- i=2，A[2]=25：j=3~5 全部走 else，加 3 次；再被 A[1] 和 A[0] 各加一次。所以 **count[2] = 5**。

新的 count 变成 `{4, 0, 5, 1, 2, 3}`。再搬进 B：0 号位的 25 落在 B[4]，2 号位的 25 落在 B[5]。**靠前的那个 25 还在前面**，B 依旧是 `{10, 10, 11, 19, 25, 25}`，一点没乱。稳定。

> **结论**：把 `if (A[i] < A[j])` 改成 `if (A[i] <= A[j])`，算法就变成稳定的。

真到考场里，只要你已经定位到"是哪一步在处理相等的情况"，把它挪到另一条分支上，就一定能改出稳定的结果——因为整个程序再没有第二处碰"等于"了。我们上面这一整段验证，其实只是给大家吃颗定心丸，证明它真的稳定，不是嘴上说说。

### 计组那道大题：一台字长 16 位、按字节编制的机器

41 题跑完了，换个方向看 43 题。题面给的东西很少，就几句话：计算机 M 的机器字长 16 位，按字节编制；连接 CPU 和主存的系统总线里，地址线 20 位、数据线 8 位；指令是 16 位定长的；指令格式给了 R、I、J 三种。

```text
        +------------------------+
        |          CPU           |
        |                        |
        |  MAR        MDR        |
        +-------+----------+-----+
                |          |
       address bus (20)  data bus (8)
                |          |
                +----------+
                           |
                           v
                     +-----------+
                     |   MEM     |  主存，按字节编制
                     +-----------+
```

这张图就是第一问的钥匙。MAR 只跟地址线打交道，它装的就是主存地址，所以 MAR 的位数跟地址线一致；MDR 只跟数据线打交道，它装的就是从主存搬回来的数据，所以 MDR 的位数跟数据线一致；IR 装的是指令，而指令是 16 位定长的，所以 IR 是 16 位。

三种指令格式也在题面里排着：

| 格式 | 字段划分（高位 → 低位） | 说明 |
|---|---|---|
| R 型 | `000`(6) + rs(2) + rt(2) + rd(2) + op(4) | 高 6 位恒为 000；rs、rt 做 op 指定的运算，结果送 rd |
| I 型 | op(6) + rs(2) + rt(2) + imm(6) | 高 6 位是操作码；低 6 位是立即数；题面说它涵盖 ALU 运算、转移、访存三类操作 |
| J 型 | op(6) + target(10) | 高 6 位是操作码；target 直接送 PC，决定下一条指令地址 |

先别急着答，把几个"字长"分清楚，不然第一个小问就容易填错格子。

#### 别把三个"字长"搞混

| 名词 | 指什么 | 这道题里是多少 |
|---|---|---|
| 机器字长 | CPU 一次能处理的二进制位数，等于 ALU 宽度、通用寄存器位数 | 16 位 |
| 指令字长 | 一条指令的长度 | 16 位（定长，占 2 个字节） |
| 存储字长 | 一个存储单元的长度 | 按字节编制 → 1 个字节 |

这道题里机器字长和指令字长都是 16 位，存储字长却是 1 个字节——三条线各走各的：机器字长定住了 ALU 和寄存器的宽度，指令字长定住了 IR 的宽度和一条指令占几个字节，编址方式定住了存储字长。它们完全可以不一样，就等着你在某个小问里用错。

#### 第一问：ALU 宽度、存储空间、寄存器位宽

**ALU 宽度 = 16 位。** ALU 的宽度就是它做算术逻辑运算时一次能处理的最大位数，它一般就等于机器字长。题目白纸黑字给了机器字长 16 位，照抄就行。

**可寻址存储空间 = $2^{20}$ 字节。** 存储容量等于存储空间大小，也就是「主存地址范围 × 存储字长」。地址范围由地址线位数决定，20 位 → $2^{20}$ 个地址；按字节编制，存储字长是 1 个字节。所以：

$$\text{存储空间} = 2^{20} \times 1\text{B} = 2^{20}\text{B} = 1\text{MB}$$

> **提示**：这里算的是**地址空间**，也就是能编址的范围，不等于实际装了多少物理内存。题目问的是"可寻址存储空间"，答 $2^{20}$ 字节就够，别去纠结这台机器里到底插了几 GB。

**IR = 16 位，MAR = 20 位，MDR = 8 位。** IR 存当前正在执行的指令，指令 16 位定长，所以 16 位；MAR 接地址线，20 位；MDR 接数据线，8 位。这两个数前面那张图已经交代过一遍了。

#### 第二问：操作码能编多少种，通用寄存器有几个

操作码能编几种，取决于题面给它留了几位。

**R 型**：高 6 位恒为 `000`，真正的操作码是低 4 位，所以 $2^4 = 16$ 种。

**I 型和 J 型**：两者的操作码都在高 6 位，各有 $2^6 = 64$ 种。但有两点必须想到，不然这题就白做了：第一，I 型和 J 型是两种不同的格式，高 6 位是它们共同的命名空间，操作码绝不能撞车；第二，R 型已经把 `000000` 这个组合拿走了。所以 I 型 + J 型合起来只有

$$2^6 - 1 = 63 \text{ 种}$$

**通用寄存器最多 4 个。** 题面里 rs、rt、rd 都是 2 位，2 位能编出 $2^2 = 4$ 种取值，编号 0~3。

> **易错点**：这里最容易翻车的地方是——R 型明明出现了**三个**通用寄存器编号字段，有人就顺手 4 + 4 + 4 = 12。绝对不行。rs、rt、rd 是三个独立的**编号**，不是三组寄存器；它们完全可以指向同一个寄存器（rs 用 0、rt 用 1、rd 用 2，合法得很），它们划出来的范围都是 0~3，是同一批寄存器。求寄存器个数只能取一个字段的位宽，绝不能把三个字段加起来。

#### 第三问：01B2H 和 01B3H，拆开看

现在给指令编号了：op 为 `0010` 时表示带符号整数减法，op 为 `0011` 时表示带符号整数乘法。已知 R1 = B052H，R2 = 0008H，R3 = 0020H，问 01B2H 和 01B3H 执行完 R3 里是什么，以及会不会溢出。

**先拆 01B2H。** 16 位定长指令字，先化成二进制，再去跟三种格式对：

```text
  01B2H  ->  0000 0001 1011 0010

  按 R 型重新分组：
           000000 | 01 | 10 | 11 | 0010
            高6位   rs   rt   rd   op
```

高 6 位是 `000000`，R 型，稳了。op = `0010` → 带符号整数减法；rs = `01` → R1；rt = `10` → R2；rd = `11` → R3。

所以 **`01B2H` 的功能是 $(R1)-(R2)\to R3$**，也就是 B052H 减 0008H。列个 16 进制竖式：末尾 2 减 8 不够减，向前借一位，借成 16，$16-8=8$，再加上原来的 2 得 A；前一位的 5 借走 1 变成 4。结果是：

$$R3=\text{B052H}-\text{0008H}=\text{B04AH}$$

**再拆 01B3H。** 只有最后一位不同：

```text
  01B3H  ->  0000 0001 1011 0011

  按 R 型重新分组：
           000000 | 01 | 10 | 11 | 0011
            高6位   rs   rt   rd   op
```

还是 R 型，还是 R1 op R2 → R3，只是 op 变成了 `0011` → 带符号整数乘法。所以 **`01B3H` 的功能是 $(R1)\times(R2)\to R3$**，也就是 B052H 乘 0008H。

**这里千万别真去列竖式做二进制乘法。** 0008H = $2^3$，乘一个 2 的整数次幂，那就是左移三位：

```text
  B052H << 3
  = 1011 0000 0101 0010 000
  = 101 |1000 0010 1001 0000
        ----------------
        1000 0010 1001 0000  =  0x8290H
```

通用寄存器的长度跟机器字长相等，都是 16 位，所以竖线左边那 3 个高位的 `101` 直接被截掉，只剩下 0x8290H 存进寄存器。

**溢出吗？溢出了。** 真实的乘积是 $101\ 1000\ 0010\ 1001\ 0000$，也就是 0x58290H，已经 17 位了，第 17 位的权是 $2^{16}$。这一位真实存在，而机器只有 16 位，硬生生被截掉了。截完剩下的 0x8290H 最高位是 1，代表负数——可真实乘积明明是正数。真值和机器里的值已经不是一个东西，这就是溢出。

> **结论**：判断算术左移是否溢出的标准判据是——**被移出去的那些位，只要有一位和结果的符号位不相等，就是溢出**；全相等才不溢出。
>
> 这里移出去的是 `101`，结果符号位是 `1`，那个 `0` 和它不一致，所以溢出。

#### 第四问与第五问：偏移量扩展与无条件转移

**第四问：I 型指令的偏移量是带符号整数，地址计算时应当符号扩展。**

先把两个词掰开：

| | 针对谁 | 高位怎么补 |
|---|---|---|
| 零扩展 | 无符号数 | 直接补 0 |
| 符号扩展 | 有符号数 | 复制符号位 |

题目明确说了这个偏移量是**带符号**整数，那没得选，符号扩展。

> **易错点**：零扩展不是"高位补零"这么简单——补完零之后，这个数在无符号意义下数值不变，可一旦被当成有符号数去解释，值就变了。所以带符号的偏移量千万别用零扩展。

**第五问：无条件转移指令只能采用 J 型格式。**

理由很硬：转移的本质是要拿到目标地址，而 R 型和 I 型的功能里压根没有改 PC 这一件事——R 型是 rs op rt → rd，I 型是高 6 位操作码 + rs + rt + 立即数，干的都是运算和访存。只有 J 型格式里有那个 target 字段，它直接送进 PC，PC 的新值就定了，下一条指令从哪儿取自然也就定了。

答题的时候光写"J 型"是不够的，**一定要补上这句理由**：J 型格式能把 target 写入 PC，从而修改下一条指令的地址。

## 2021 年 408 大题串讲：TLB、信号量、引导流程与交换表

2021 年这套大题，一上来就横跨了四个科目：组成原理的分页加 TLB，操作系统的信号量互斥，操作系统的引导流程，还有一道纯计网。我们之前也说过，408 每年的大题都考得比较综合，要么整个流程全给你走一遍，要么掐头去尾只考前半段或者后半段。所以学完一门科目不要只盯着常考的那几个点，网络的数据交换过程也好、系统的引导过程也好，从头到尾任何一环都要能讲通。今天这四道题就正好把"讲得通"这件事又检验了一遍。

### 分页地址怎么拆：12 位页内地址，18 位虚页号

先看 44 题。条件一摞上来：

> 假设计算机 M 的主存地址是 24 位，按字节编制；采用分页存储管理，虚拟地址 30 位，页大小 4KB；TLB 采用二路组相联，LRU 替换策略，一共 8 组。

第一问问得很直接：虚拟地址中哪几位表示虚页号，哪几位表示页内地址？

这个在读题的时候其实已经顺手做完了。页大小 4KB，编制单位是一个字节，所以页内地址的位宽就是 $\log_2 4\text{KB}$：

$$
\text{页内地址位宽} = \log_2(4\text{KB}) = \log_2(2^{12}) = 12\ \text{位}
$$

> **结论**：虚拟地址 = 虚页号 + 页内地址。页内地址占低 12 位，虚页号就是 $30 - 12 = 18$ 位。

这里记牢一条：**页内地址的位宽只由页大小和编制单位决定，跟虚拟地址有多长完全无关**。后面第四问改虚拟地址位数的时候，这一句话能直接省掉一半的活。

第二问加了一层：已知访问 TLB 时，虚页号的高位部分用作 TLB 标记，低位部分用作 TLB 组号，问哪几位是标记、哪几位是组号。

虚页号一共 18 位，拆成"标记 + 组号"两块。组号这一块看 TLB 的组织方式：二路组相联、一共 8 组，而 $8 = 2^3$，所以组号需要 3 位来指。

$$
\text{TLB 组号位宽} = \log_2 8 = 3\ \text{位}
$$

$$
\text{TLB 标记位宽} = 18 - 3 = 15\ \text{位}
$$

> **结论**：虚页号的低 3 位是 TLB 组号，高 15 位是 TLB 标记。

顺带把容量也算出来：二路组相联就是一组里有两行，一共 8 组，$2 \times 8 = 16$ 行。

```text
30 位虚拟地址
+------------------+-------------------+
|   虚页号 18 位   |   页内地址 12 位  |
+------------------+-------------------+

虚页号再拆成两块（低位定组，高位比标记）：
+------------------------+--------------+
|    TLB 标记 15 位      |  TLB 组号 3 位 |
+------------------------+--------------+
```

读图要点：TLB 总共 16 行，但它的"地址位"只有 18 位，因为组号 3 位是由 TLB 自身的组织方式（8 组）决定的，不是由虚拟地址决定的。

### TLB 里的替换：LRU 把虚页号 4 挤了出去

第三问开始动真格了：TLB 初始时为空，访问的虚页号依次给出，问哪一个虚页号对应的 TLB 表项被替换，并说明理由。

别一上来就模拟整张表。这个题给了"二路组相联、8 组、LRU"三个条件，已经把路子给你了：

- 组内是 2 路，所以每组能装 2 个页；
- 组号是 3 位，说明 8 组是等分的，那么**哪个虚页号落到哪一组，直接对 8 取模**；
- LRU 只在**组内**挑要淘汰的那个，跨组互不相干。

所以本题里我们只需要看组号，标记那 15 位完全不用管。挨个取模：

| 访问次序 | 虚页号 | $\text{虚页号} \bmod 8$（组号） | 这一步发生了什么 |
|---|---|---|---|
| 1 | 10 | 2 | 组 2 是空的，装入 10 |
| 2 | 12 | 4 | 组 4 是空的，装入 12 |
| 3 | 16 | 0 | 组 0 是空的，装入 16 |
| 4 | 7 | 7 | 组 7 是空的，装入 7 |
| 5 | 26 | 2 | 组 2 已有 10，还剩一路，装入 26 |
| 6 | 4 | 4 | 组 4 已有 12，还剩一路，装入 4 |
| 7 | 12 | 4 | 组 4 里已经有 12，**命中，不动表** |
| 8 | 20 | 4 | 组 4 已满，必须淘汰一个 |

一共有两件事要分清楚：**第 7 次访问 12 是命中**，命中不触发替换；**真正触发替换的是第 8 次访问 20**。

到第 8 步我们才用上 LRU。此时组 4 里躺着 12 和 4：

- 4 是在第 6 次被访问的，12 是在第 7 次被访问的；
- 最近最少被访问的那个是 4。

```text
组号:    0      1        2         3        4          5      6      7
        [ 16 ]  [  ]   [ 10 | 26 ] [  ]   [ 12 | 4 ]  [  ]  [  ]  [ 7 ]
                                          ^
                                          第 8 次访问 20 时落在这一组，
                                          12 刚在第 7 次被访问过，
                                          LRU 淘汰掉 4，装入 20
```

读图要点：其余 7 个组在这一整串访问里始终是空的，只有组 2、组 4、组 0、组 7 被用到；冲突只发生在组 4 这一处。

> **结论**：被替换掉的是虚页号 **4** 对应的 TLB 表项，因为它所在组的另一个表项 12 刚被访问过，而 4 是组内最近最少被访问的。

> **易错点**：这类题最容易犯的错，是把"访问序列"当成一条线去推每一步的访问时间戳，而不是先按组切分、再在组内比时间。组间互不影响，LRU 的作用域只在组内那两路。

### 虚拟地址加宽到 32 位，TLB 标记要多长 2 位

第四问：把 M 中虚拟地址的位数增加到 32 位，TLB 表项的位数增加多少位？

这类"改了参数问影响"的题，套路是固定的——**把地址的组成结构画清楚，然后看改的是哪一块，剩下的块哪些跟着动、哪些不动**。

先看现状：

```text
30 位虚拟地址
+---------------------+------------------+
|   虚页号 18 位      |   页内地址 12 位 |
+---------------------+------------------+
              |
              +-- 再拆
   +---------------------+-------------+
   |   TLB 标记 15 位    |  组号 3 位  |
   +---------------------+-------------+

改成 32 位之后：
+---------------------+-------------+------------------+
|   TLB 标记 17 位    |  组号 3 位  |   页内地址 12 位 |
+---------------------+-------------+------------------+
      +2 位            不变            不变
```

一行行来：

1. **页内地址不变**，还是 12 位。页大小没变，4KB 就是 4KB，编制单位还是字节，跟虚拟地址总长八竿子打不着。
2. **虚页号变长**：$32 - 12 = 20$ 位，比原来多了 2 位。
3. **组号不变**：还是 8 组，二路组相联也没动，$8 = 2^3$，组号照样 3 位。
4. **标记补上差额**：$20 - 3 = 17$ 位，比原来多 2 位。

> **结论**：TLB 表项的位数（这里指标记位宽）增加 **2 位**。

你只需要把整个地址表示的组成关系理清，然后根据增加的位数一步一步往下推就行了——**变化的只有虚页号，虚页号里变化的只有标记，因为组号是被 TLB 的组织方式钉死的。**

### wait 和 signal 为什么必须互斥访问 S

45 题换到操作系统，属于"题型三"的一种考法：**先给你方法和功能描述，再让你回答几个问题**。这里的背景是整型信号量 S：

- **wait 操作**（就是 P 操作）负责申请资源。只有资源够用，也就是 S 大于 0 的时候，才能申请成功，所以它要先判断 S 是否小于等于 0，如果是，就一直判断下去；如果 S 大于 0，就把 S 减一。
- **signal 操作**（就是 V 操作）负责释放资源。资源释放出来了，信号量就得加一。

第一问：为什么 wait 和 signal 操作对信号量 S 的访问必须是互斥进行的？

理由就摆在操作本身里：wait 要对 S **减一**，signal 要对 S **加一**，而 S 是被这两个操作共享着的。多个进程同时去访问 S，就意味着对 S 同时做读和写。而 S 是我们前面反复强调的**临界资源**，共享资源上的读写当然得互斥执行。

一句话概括：**S 被多个进程共享，会发生读-写冲突，所以必须互斥访问。**

### 方法一错在哪：关中断把循环锁死了

题里给了两种"用开关中断指令实现信号量操作互斥"的方法，我们先看方法一。

方法一的设计意图很清楚：既然要互斥，那就把关中断和开中断包在 wait、signal 里面。

```text
方法一 wait(S)                        方法一 signal(S)
  关中断                                 关中断
  while (S <= 0) ;                      S = S + 1
  S = S - 1                              开中断
  开中断
```

signal 是没问题的：关中断、加一、开中断，一气呵成，不会卡。

问题出在 wait。请注意这个 while 的位置——**它被关中断整段圈在了里面**。设想一下：如果申请的时候 S 就是小于等于 0，会发生什么？

```text
本进程：关中断 -> 卡在 while(S<=0) 里出不来
其他进程：进不来（中断关着），没人能执行 signal 把 S 加 1
     ↓
  S 永远 <= 0  ->  while 永远成立  ->  死循环
```

关中断期间其他进程根本没法访问 S（它本来就是临界资源），也就没人能把它加上去。S 一直小于等于零，while 一直成立，这个进程就再也出不来了。

> **结论**：方法一**错误**。wait 中在关中断状态下执行 `while (S <= 0)`，一旦 S 持续小于等于零，由于中断关闭其他进程无法执行 signal 修改 S，进程将陷入死循环。

再看方法二。它同样定义了整型信号量 S，wait 的做法变成：

```text
方法二 wait(S)
  while (1) {
      关中断
      if (S > 0) {
          S = S - 1
          开中断
          return
      } else {
          开中断          <-- 关键就在这一句
      }
  }

方法二 signal(S)
  关中断
  S = S + 1
  开中断
```

方法二的 signal 跟方法一完全一样。差别全在 wait 里面那个 while 循环中补了一句**开中断**：即使 S 小于等于零，判断完也把中断打开再出去转一圈。

这样别的进程就能进来访问 S、执行 signal 把资源释放掉。别的进程一改，S 就有可能变成大于零了，下一轮判断成立，wait 顺利脱身。

> **结论**：方法二**正确**。它让出了中断，其他进程可以修改 S，while 循环不会锁死。

> **提示**：这一对方法要放在一起记，差别就一句话——**死循环里要不要开中断**。凡是用"忙等"等待资源的地方，中断必须放开，否则你等的那个释放动作永远等不到。

### 用户程序用不了开关中断指令

第三问：用户程序能否使用开关中断指令实现临界区的互斥？

这里有个词要特别留心，题目问的是**用户程序**。开关中断指令属于**特权指令**，特权指令不能在用户态下运行。

> **结论**：用户程序**不能**用开关中断指令来实现临界区的互斥，因为开关中断指令是特权指令，只能在内核态执行。

> **易错点**：这道题它不仅仅考 P/V 操作，还把它和前面章节的"特权指令只能在核心态执行"串起来了。大家要记住这一条：**开关中断指令不能在用户态下运行**。

### 一块新盘到手要经过的四道工序

46 题是一道概念分析题，题干给的信息量很大，我们一段一段拆。

某计算机用硬盘作为启动盘，硬盘的**第一个扇区**（记为 0 号扇区）存放主引导记录 MBR，它包含两样东西：**磁盘引导程序**和**该磁盘的分区表**。而每一个分区的第一个扇区里，还存着一个**分区引导程序**，作用是引导保存在该分区的操作系统。

这里先补一个背景，磁盘出厂之后如果还没有做扇区划分，就要先做**低级格式化（物理格式化）**，过程就是划分扇区；扇区划分完毕之后才能对磁盘进行**分区**，分区就是我们熟悉的 C 盘、D 盘、E 盘这样的**逻辑磁盘**；具体某个逻辑盘包含多少个扇区、容量是多少，对用户来说是透明的。在分区的基础上，再做**高级格式化（逻辑格式化）**，在高级格式化中为每个分区建立**文件系统**和**根目录**；有了文件系统，才能做文件存储，才能把数据持久化。

于是题干里那句"磁盘的引导程序用于选择要引导哪个分区的操作系统"，其实还告诉我们一件事：**操作系统本身是软件程序，它是被安装在一个逻辑盘上的**。逻辑盘经过高级格式化有了文件系统，我们才能把操作系统当成一个文件持久化到磁盘里。

而"这个磁盘具体分了哪几个分区、每个分区多大、起始位置在哪里"，正是记录在主引导记录里的**分区表**中的。

题目还说了系统采用**多阶段引导**方式，除了总的磁盘引导程序和每个分区上的分区引导程序之外，还需要执行 RAM 中的引导程序。这里补一句：ROM 是主存中的只读部分，RAM 和 ROM 一个断电丢失、一个断电不丢，正因为 ROM 断电不丢，我们才会把 BIOS（基本输入输出系统）存放在 ROM 里面，使得计算机一通电就能够执行 BIOS 中的代码。

现在看第一问：系统启动过程中，操作系统初始化程序、分区引导程序、ROM 中的引导程序、磁盘引导程序，它们的执行顺序是什么？

```text
通电
 |
 v
[ROM 中的引导程序（BIOS）]      断电不丢，一上电就能跑
 |   通过它找到用于引导操作系统的外设
 |   题目给定启动盘 = 硬盘
 v
[磁盘引导程序（MBR，0 号扇区）]  读分区表 -> 挑出装操作系统的那个分区
 |
 v
[分区引导程序]                  把操作系统的一部分先读入内存
 |
 v
[操作系统初始化程序]            逐步读入完整操作系统，CPU 开始执行 OS 代码
```

读图要点：前三段都是"一段引导程序读出下一段"，最后一段才是操作系统自己上场。

为什么顺序是这样？因为只有读到 MBR 的分区表，我们才知道这个磁盘分了哪几个逻辑分区、操作系统装在哪个分区里；只有知道装在哪个分区，才谈得上去读那个分区的引导程序；只有把操作系统的一部分读进内存，才能继续把完整的操作系统读进来，最后才由操作系统跑自己的初始化程序。初始化完成后，计算机就能正常运行了。

> **结论**：ROM 中的引导程序 → 磁盘引导程序 → 分区引导程序 → 操作系统初始化程序。

### 制作启动盘：物理格式化、分区、逻辑格式化、安装

第二问：把一个磁盘制作为启动盘，需要完成操作系统安装、磁盘物理格式化、逻辑格式化以及磁盘分区，这四个操作的正确顺序是什么？

这个我们在读题干的时候就已经顺手捋过了，直接写出来：

```text
出厂 / 新买的盘：一块空白介质，上面连扇区划分都没有
      |
      v
[1. 物理格式化（低级格式化）]  划分扇区
      |
      v
[2. 磁盘分区]                  得到 C 盘 / D 盘 / E 盘 这样的逻辑盘
      |
      v
[3. 逻辑格式化（高级格式化）]  逻辑编号 + 建文件系统、建根目录
      |
      v
[4. 安装操作系统]              OS 本身也是一堆数据，作为文件存进文件系统
```

为什么是这个顺序，一步一步看：

1. 没有扇区划分，你连存储单元都谈不上，所以必须先做物理格式化；
2. 有了扇区划分，才能在这个基础上对磁盘做逻辑上的分区；
3. 有了逻辑盘，才能对其做高级格式化；在高级格式化过程中实际上已经建立了操作系统的**基础**——文件系统和根目录；
4. 有了这个基础，才能把操作系统（它本质上就是一部分数据、一堆程序代码）持久化到磁盘里，作为一个文件让文件系统存下来。

**没有文件系统，你连"把操作系统存成一个文件"这件事都做不到**——这就是为什么安装操作系统必须排在最后。

第三问：磁盘扇区的划分和文件系统根目录的建立，分别是在第二问中的哪个操作里完成的？

答案前面已经分析过了，直接落：

| 要完成的事 | 在哪个操作里做 |
|---|---|
| 磁盘扇区的划分 | 物理格式化（低级格式化） |
| 文件系统根目录的建立 | 分区之后的逻辑格式化（高级格式化） |

顺便把逻辑格式化里具体干的活也记下来：它会对磁盘中的每一个扇区进行逻辑上的编号；然后对每一个逻辑盘（也就是分区）建立它的引导记录，这个我们在题干里已经看过了；再根据该分区采用了什么文件系统，给它建立对应的数据结构，比如文件分配表、文件目录表和数据区等。

> **结论**：这道题是中等难度偏上的概念分析题。难点在于操作系统的引导这一块概念链条比较长，大家可能不太熟悉，需要多加记忆；而且引导又和磁盘的物理格式化、逻辑格式化、分区绑在一起，一定要把整个流程梳理完。

再把两条线合起来看一遍：**盘被制造出来 → 扇区划分 → 逻辑分区 → 高级格式化（逻辑编号、建立文件系统）→ 有了文件系统才能把文件存进磁盘（对数据进行持久化）→ 到这里才可以把操作系统安装到磁盘；而操作系统装好之后，每次开机又要完整地走一遍引导流程，从磁盘把操作系统一步步读入内存开始执行。**

### 从域名到 HTTP：DNS 与逐层封装

47 题是一道计算机网络大题。网络结构给的是：H1、H2 和 Web 服务器 S 通过路由器 R 与网络（互联网）相连，各接口的域名服务器以及对应的 IP 和 MAC 地址都给了。前提条件是：**在 $T_0$ 时刻，H1 的 ARP 表和 S 的交换表都是空的**。$T_0$ 时刻 H1 用浏览器通过域名请求访问 Web 服务器，到 $T_1$ 时刻，S 收到了封装 HTTP 请求报文的以太网帧。题目还特意说：假设从 $T_0$ 到 $T_1$ 之间，没有发生任何与这次访问无关的网络通信。

第一问：从 $T_0$ 到 $T_1$，H1 除了 HTTP 之外，还运行了哪个应用层协议？

先把这段时间里发生的事理一遍。你拿到一个域名地址要去访问，最开始是不知道 IP 的，对吧？在真正去请求对应的 IP 之前，第一件事就是把**域名解析成 IP**。题目已经明说了缓存为空，所以只能实打实地发一次解析请求——这就是 **DNS 协议**。

所以顺序是：先 DNS 解析出 IP，再建立 TCP 连接，然后用 HTTP 发送请求数据。传输层还涉及 TCP 协议，但题目问的是**应用层**协议，答案就只有一个：

> **结论**：DNS 协议。

> **提示**：这里顺便记两条常考的搭配——**DNS 本身使用的是 UDP 协议，HTTP 协议使用的是 TCP 协议**。

接着一个小问：这个应用层报文是通过哪些协议逐层封装的？

```text
应用层     DNS 请求报文
              |  交给 UDP
传输层     UDP 数据报
              |  交给 IP
网络层     IP 数据报
              |  交给数据链路层协议
数据链路层  以太网帧（以太网中用 CSMA/CD 做随机访问控制）
```

读图要点：描述封装顺序时，从上往下念一遍，DNS → UDP → IP → 以太网帧。要用的话可以把 CSMA/CD 也写上，因为在以太网中它就是那个随机访问控制的方法，把这个过程描述清楚、封装顺序写出来是最保险的。

### 交换表的三条记录：两次 ARP 学到了什么

第三小问问的是：如果 S 的交换表结构是"MAC 地址和端口"这样的形式，那么在 $T_1$ 时刻 S 的交换表内容是什么？

这题看着吓人，其实只要把 $T_0$ 到 $T_1$ 这段路重走一遍，答案就在路上。

H1 要发 DNS 请求，第一步得先拿到**本地域名服务器的 MAC 地址**（DNS 请求是发给本地域名服务器的）。而 ARP 协议干的就是"把 IP 地址翻译成 MAC 地址"这件事，那怎么通过 ARP 拿到 MAC？就得先发一个 ARP 请求报文。

H1 此时并不知道本地域名服务器的 MAC，所以它发出的 ARP **请求报文的目的 MAC 是全 1**，是一个广播帧。H2、本地域名服务器、路由器 R 的接口全都在同一个以太网里，这个广播帧人人都收得到。

帧过到 S 的时候，S 虽然收到的只是一个广播帧，但它会**自学习**：把帧的**源 MAC 地址**和进来的端口记下来。于是记下第一条——$00\text{-}11\text{-}22\text{-}33\text{-}44\text{-}CC$ 对应**端口 4**（这就是 H1）。以后谁的帧目的 MAC 是 H1，S 就知道从 4 号口转发出去。

```text
T0 H1 --ARP 请求(广播: 问本地域名服务器的 MAC)--> 整个局域网
      S 自学习: 00-11-22-33-44-CC  -> 端口 4        [记录 1]

   本地域名服务器 --ARP 响应(单播)--> H1
      S 自学习: 本地域名服务器的 MAC -> 端口 1        [记录 2]
      (单播，因为本地域名服务器知道 H1 的 IP 和 MAC)

T0 H1 --DNS 请求(单播)--> 本地域名服务器
      (拿到 Web 服务器的 IP；本地域名服务器如何再向别的域名服务器查询，不用管)

   H1 拿到 Web 服务器的 IP，算一下：不在同一个网络中(图中是由 R 相连)
   -> 只能发给自己的默认网关，那网关的 MAC 是谁？再做一次 ARP

T0 H1 --ARP 请求(广播: 问默认网关的 MAC)--> 整个局域网
      S 自学习: 00-AA-…(R 的接口 MAC)  -> 端口 2   [记录 3]

   默认网关 --ARP 响应(单播)--> H1
      H1 拿到网关 MAC，把 DNS 请求发给网关，由 R 转发出去
      (这一段往后 S 不再参与)
```

读图要点：**交换表的每一条记录，都由一个"从某个接口进来的帧"触发，只看源 MAC。** 记录 1 和记录 3 来自广播请求帧，记录 2 来自域名服务器发回来的单播响应帧。

所以 $T_1$ 时刻 S 的交换表是：

| 目的 MAC 地址 | 端口 | 这条是怎么学到的 |
|---|---|---|
| $00\text{-}11\text{-}22\text{-}33\text{-}44\text{-}CC$ | 4 | H1 发出的第一个 ARP 请求广播帧的源地址 |
| 本地域名服务器的 MAC 地址 | 1 | 本地域名服务器回给 H1 的 ARP 响应帧的源地址 |
| $00\text{-}AA\text{-}\dots$（路由器 R 接口） | 2 | 默认网关回给 H1 的第二个 ARP 响应帧的源地址 |

> **结论**：整个过程里凡是经过 S 的，只有和 **ARP 有关**的帧。DNS 请求是单播、后续由 R 转发的数据帧都只是从 S 上"过"一下（S 会照常查表转发，但不会因此学到新东西——因为那些帧的源 MAC 它都早就记过了）。所以表里一共只有三条记录。

再强调一遍这个链条：知道了域名之后要访问，过程中先需要 DNS 请求；而在发 DNS 请求之前，我们还得先拿到本地域名服务器的 MAC，所以需要 ARP；拿到 IP 之后，因为不在同一网络，还要再 ARP 一次拿默认网关的 MAC。**凡是经过 ARP 的部分才跟 S 有关**，别的都不相干。

> **提示**：标准答案里的文字描述比较长，容易写乱。大家可以简练一点——只要把"哪一条是通过什么样的报文学来的"说清楚，最后给出正确的地址表、体现出一个逐渐完成的转发过程即可；如果大段文字看起来不太明了，就分条分段去写。

### H2 至少收到两个广播帧

最后一小问：从 $T_0$ 到 $T_1$，H2 至少会接收到几个与这次 Web 访问有关的帧？

这个第二小问的结论理顺了，第三小问就好答。我们数一遍 H1 发出的广播帧：

1. **第一个 ARP 请求帧**，问本地域名服务器的 MAC。它是广播，整个局域网内部都能收到，H2 和 R 的接口自然也收得到。
2. **本地域名服务器发出的 ARP 响应帧**——单播，H2 收不到。
3. 拿到 DNS 应答、得到 Web 服务器的 IP 之后，**第二个 ARP 请求帧**，问默认网关的 MAC。它仍然是广播，H2 还是收得到。
4. **默认网关发回的 ARP 响应帧**——单播，H2 收不到。
5. 之后 H1 已知默认网关，把报文直接发给路由器，由 R 转发出去。这之后所有的过程都不涉及以太网中的广播了，H2 再也收不到任何东西。

```text
局域网内流动的帧                 H2 能不能收到
--------------------------------  ----------------
H1 -> 本地域名服务器  ARP 请求(广播)   能   [1]
本地域名服务器 -> H1  ARP 响应(单播)  不能
H1 -> 本地域名服务器  DNS 请求(单播)  不能
H1 -> 默认网关       ARP 请求(广播)   能   [2]
默认网关 -> H1       ARP 响应(单播)   不能
H1 -> R -> 互联网     后续数据/控制帧  不能 (已不在这个局域网里)
```

读图要点：只要目的 MAC 是全 1，局域网内谁都能收到；一旦单播给了具体的人，别的主机就只能干看着。

> **结论**：H2 至少接收到 **2 个**帧，都是**封装 ARP 请求报文的以太网帧**，其目的 MAC 地址为全 1。

### 本讲提到的题目

这一讲通篇在讲的就是 2021 年统考的四道大题，题干与条件都按当时读题的原样写在这里，解析与答案依据在上文对应小节。

**2021 年 44 题（计算机组成原理）**
题干：计算机 M 主存地址 24 位，按字节编制，采用分页存储管理，虚拟地址 30 位，页大小 4KB；TLB 采用二路组相联、LRU 替换策略，共 8 组；访问 TLB 时虚页号高位作标记、低位作组号；TLB 初始为空，给定一串访问的虚页号。
① 虚拟地址中哪几位是虚页号、哪几位是页内地址；② 哪几位是 TLB 标记、哪几位是 TLB 组号；③ 哪一个虚页号对应的 TLB 表项被替换，说明理由；④ 若虚拟地址位数增加到 32 位，TLB 表项位数增加多少位。
答案：① 页内地址 12 位（低 12 位），虚页号 18 位（高 18 位）；② 低 3 位为组号（8 组），高 15 位为标记；③ 被替换的是虚页号 4，所在组另一表项 12 刚被访问过，4 为组内 LRU；④ 增加 2 位（标记由 15 位增至 17 位，组号与页内地址均不变）。解析见"分页地址怎么拆""TLB 里的替换""虚拟地址加宽到 32 位"。

**2021 年 45 题（操作系统，信号量）**
题干：给出整型信号量 S 的 wait 与 signal 操作的功能描述，以及用开关中断指令实现信号量操作互斥的两种方法。
① 为什么 wait 和 signal 对 S 的访问必须互斥进行；② 两种方法是否正确，不正确请说明理由；③ 用户程序能否用开关中断指令实现临界区互斥。
答案：① S 是被两操作共享的临界资源，会产生读-写冲突，必须互斥；② 方法一错误——关中断状态下执行 `while (S <= 0)`，S 若持续小于等于零则其他进程无法执行 signal 改变 S，陷入死循环；方法二正确——循环中补了开中断，其他进程可修改 S；③ 不能，开关中断指令是特权指令，不能在用户态执行。解析见"wait 和 signal 为什么必须互斥访问 S""方法一错在哪""用户程序用不了开关中断指令"。

**2021 年 46 题（操作系统，引导与磁盘）**
题干：某计算机用硬盘作为启动盘，0 号扇区存放主引导记录（含磁盘引导程序与分区表）；每个分区第一个扇区存放分区引导程序，用于引导保存在该分区的操作系统；系统采用多阶段引导方式。
① ROM 中引导程序、磁盘引导程序、分区引导程序、操作系统初始化程序的执行顺序；② 将磁盘制作成启动盘时，操作系统安装、物理格式化、逻辑格式化、磁盘分区四者的正确顺序；③ 扇区划分与文件系统根目录的建立分别属于②中的哪个操作。
答案：① ROM 中引导程序（BIOS）→ 磁盘引导程序 → 分区引导程序 → 操作系统初始化程序；② 物理格式化 → 磁盘分区 → 逻辑格式化 → 安装操作系统；③ 扇区划分在物理格式化中完成，文件系统根目录在分区之后的逻辑格式化中建立。解析见"一块新盘到手要经过的四道工序""制作启动盘"。

**2021 年 47 题（计算机网络）**
题干：H1、H2 与 Web 服务器 S 经路由器 R 与网络相连，各接口、域名服务器的 IP 与 MAC 已知；$T_0$ 时刻 H1 的 ARP 表与 S 的交换表均为空，$T_0$ 时刻 H1 通过域名用浏览器访问 Web 服务器，$T_1$ 时刻 S 收到封装 HTTP 请求报文的以太网帧，$T_0$ 到 $T_1$ 之间无其他无关通信。
① $T_0$ 到 $T_1$ 之间 H1 除 HTTP 外还运行了哪个应用层协议；② 该应用层报文经哪些协议逐层封装；③ 若 S 交换表结构为 MAC 地址与端口，$T_1$ 时刻表内容是什么；④ $T_0$ 到 $T_1$ 之间 H2 至少接收到几个与该次访问有关的帧，帧的目的 MAC 地址是什么。
答案：① DNS（DNS 跑在 UDP 上，HTTP 跑在 TCP 上）；② 应用层 DNS → 传输层 UDP → 网络层 IP → 数据链路层以太网帧（可补 CSMA/CD）；③ 三条记录，见上文交换表；④ 2 个，均为封装 ARP 请求报文的以太网帧，目的 MAC 为全 1。解析见"从域名到 HTTP""交换表的三条记录""H2 至少收到两个广播帧"。

### 这一块的落点

回头看这四道题，共同点很明显：**都要求你把一个完整过程从头到尾讲通，而不是记住几个孤立结论**。44 题考的是从虚拟地址拆分到 TLB 表项替换的一条链；46 题考的是从出厂裸盘到装上操作系统、再到每次开机引导的完整生命周期；47 题考的是从输入域名到发出 HTTP 请求这段"网络连接数据传输的前半段"。

所以每一年真题的大题都会比较综合，可能考察整个流程，可能是前半段，也可能是后半段。学完计算机网络这门科目以后，就把整个网络体系结构、数据交换的任何环节都搞清楚，综合大题对大家来说就没有什么大的问题——除非它考的是一些你压根没复习过的知识点。
