# 排序算法与排序过程分析

排序这件事，是数据结构里最"实"的一块。为什么说实？因为别的结构你得先理解它长什么样，排序不用——你从小学起就在排座位、排成绩、排扑克，脑子里早就有一份直觉了。难的不是排，是**排得快、排得省、并且能讲清楚每一趟排完变成什么样**。

我们这一篇就死死咬住这三件事。第一，算法原理与性质；第二，过程分析——给你一个中间状态，怎么倒推出它是哪一个算法；第三，常考的排序改造——把 partition 改一改，让它只求第 $k$ 小；把归并段的长度拉开，让磁盘少转几圈。

---

## 排序这件事，先把三件事问清楚

任何一道排序题，题干再绕，最后都在问三件事：**有多快**（时间复杂度）、**占多少地方**（空间复杂度）、**会不会把相等元素的先后顺序搞乱**（稳定性）。这三件事答完，排序题的分数基本就拿住了。

### 内部排序与外排序：分界线画在内存上

内存在排序进行的过程中要同时装下"待排的全部数据"和"算法要用的辅助空间"，这就是**内部排序**。我们平时说的九种排序法，全是内部排序。

一旦数据太多、内存装不下，就得把数据放在磁盘这类外存上做，这就是**外部排序**。外部排序的瓶颈不在 CPU，在 I/O——磁盘一次寻道一次读，随机读贵得离谱。所以外部排序的全部设计哲学只有一句话：

> **结论**：外排序的一切努力，都是为了让磁盘的 I/O 次数尽可能少。

> **提示**：怎么减少 I/O？两条路——减少趟数，或者加长每一趟的量。置换选择排序走的是第二条。

### 稳定性到底在说什么

稳不稳定，只看一件事：**关键字相等的数据元素，排完之后相对次序有没有被改掉**。

举个最小的例子：`{ 5₁, 5₂, 3 }` 里的两个 5（用下标区分）。排完如果还是 `5₁` 在前、`5₂` 在后，稳定；如果变成 `5₂, 5₁, 3`，那 5 的内部次序被翻了，不稳定。

**稳定有什么用？** 排序只是手段，目的是把整个记录按主关键字排好、然后按次关键字接着排。如果第一次排序是稳定的，第二次排序就不会破坏第一次的结果。多关键字排序、基数排序、以及外部排序里的多路归并，全靠这一点才成立。

### 三大类方法怎么分家

按"怎么把元素挪到它该去的位置"分，内部排序归成三大类：

- **插入类**：拿一个元素出来，往前面那段有序序列里**找位置插进去**。代表：直接插入、折半插入、希尔。
- **交换类**：不合适的两个元素**直接换位置**，一直换到整齐。代表：冒泡、快速。
- **选择类**：每一趟**先在未排序部分里把极值挑出来**，再送到未排序部分的最前端或最末端。代表：简单选择、堆排序。

再往外还有两个"家族"通常单列：**归并排序**（两段有序合成一段）和**基数排序**（按位分配）。这两个严格说也能算作插入/交换的变体，但特征太鲜明，考试里一般单独成节。

## 插入类：把有序的小段越滚越大

插入类的共同骨架只有一句话：**前 $i$ 个元素已经有序，把第 $i+1$ 个元素插进这个有序小段里。** 三种算法的区别，全部集中在"往哪里插、怎么找位置"上。

### 直接插入排序

第 $i$ 趟：从 $A[0..i-1]$ 里找出比 $A[i]$ 大的那些元素，一个一个往后挪一格，腾出位置，再把 $A[i]$ 放进去。

```text
  原始:  [ 49  38  65  97  76  13  27  49 ]

  第 1 趟，把 38 插进 [49]：
          49 小于 38? 否 → 38 往前挪
          49 38 | 65  97  76  13  27  49      [49,38] 已就位

  第 2 趟，把 65 插进 [49,38]：
          49 38 都比 65 小 → 不挪，插到末尾
          49 38 65 | 97  76  13  27  49      [49,38,65] 已就位

  第 3 趟，把 97 插进 [49,38,65]：
          49 38 65 都比 97 小 → 插到末尾
          49 38 65 97 | 76  13  27  49

  第 4 趟，把 76 插进 [49,38,65,97]：
          97 > 76 → 97 后移
          65 < 76 → 停下
          49 38 65 76 97 | 13  27  49        ← 注意 76 没有越过 65
```

第 4 趟是精华：**一趟插入的元素，落点在它所有相等元素之后**。这就是直接插入稳定的全部原因——它只在"严格大于"时才往后挪。

第 $i$ 趟最多比较 $i$ 次、最多移动 $i$ 次，所以总比较、总移动都是 $\sum_{i=1}^{n-1} i$：

$$\text{比较} = \text{移动} = \frac{n(n-1)}{2}$$

> **结论**：直接插入的时间复杂度 **最好 $O(n)$**（原序列已有序，每趟比一次就停）、**最坏 $O(n^2)$**（完全逆序，每趟都比满）、**平均 $O(n^2)$**，**空间 $O(1)$**，**稳定**。

### 折半插入排序

折半插入的想法很直接：既然要插入的位置一定落在有序段里，那"一个个往前挪"固然要 $O(i)$ 次比较，可**比较**本身是可以二分的——用折半查找定位出插入点，再把后面整段搬过去。

于是折半插入把两件事拆开了：

- **比较次数**：每趟折半查找，$O(\log i)$ 次，总共 $O(n\log n)$，这是它唯一的改进；
- **移动次数**：定位到了还得把元素一个个挪开，这一步一步都省不掉，还是 $i$ 次，总共 $O(n^2)$。

> **结论**：折半插入的**时间复杂度仍然是 $O(n^2)$**，因为决定时间的移动次数没降下来；**空间 $O(1)$**；**稳定**。

> **易错点**：折半插入稳定吗？稳定。它折半出来的插入点一定落在所有相等元素的**后面**，跟直接插入的落点完全一样。谁要是因为"它用了二分"就觉得它和直接插入不一样，那是把比较方式和插入位置搞混了。

### 希尔排序：分组插入的增量游戏

希尔排序的思路像什么呢？像你手洗一副乱了的扑克牌，一张一张地对太慢，于是先按 3 张一组、3 张一组地捋顺，再按 2 张一组捋顺，最后 1 张 1 张地对。前面的粗排把"大老粗"问题解决了，后面的细排就快了。

具体做法：选一个**增量序列** $d_1, d_2, \dots, d_k$（最后一个必须是 1）。对每一个增量 $d$：

1. 把下标按间隔 $d$ 分成若干组，下标同余于 $d$ 的元素是一组；
2. **对每一组做一次直接插入排序**。

```text
  原始: [ 5  4  3  2  1 ]        增量 d = 2

  分组（同余即同组）：
      组 A: 下标 0,2,4 →  5, 3, 1     插入排序后 → 1, 3, 5
      组 B: 下标 1,3   →  4, 2         插入排序后 → 2, 4

  写回原位置：
      位置:  0  1  2  3  4
      元素:  1  2  3  4  5           ← 一趟（d=2）之后

  再看 d = 1：整个序列作为一组做直接插入
      1 2 3 4 5 已经是升序，一趟走完就彻底有序
```

希尔排序的时间复杂度**取决于增量序列**，没有干净的公式。常见的几条增量序列：

| 增量序列 | 说明 |
| --- | --- |
| 希尔特选 $n/2, n/4, \dots, 1$ | 最常用，每趟减半 |
| Knuth $3h+1$ | 增量之间跳得更大，实测更快 |
| 素数序列 | 用质数当增量 |
| 最后一趟为 1 | 共同点：增量必须归到 1，否则就停在半成品上了 |

> **结论**：希尔排序**时间**介于 $O(n^{1.3})$ 到 $O(n^2)$ 之间（增量选得好就靠近前者），**空间 $O(1)$**，**不稳定**。

> **易错点**：为什么希尔不稳定？因为一趟分组插入里，跨组的相等元素照样可能被调换先后。举个最小的例子：序列 `[ 5, 5, 5 ]`，增量 $d=2$ 时组 A 是 `5, 5`，看着没动；但只要有一个 5 从另一组被挪到前面，就乱了。记住一句话就够了——**只要一趟排序里可能跨越"相等"这个判断去搬动元素，它就不稳定**。

## 交换类：让不合适的两个数换地方

交换类的共同骨架是：**反复比较两个位置上的元素，不合适就换。** 差别在于"比哪两个"和"换到什么时候停"。

### 快速排序

快排的思想一句话就能说清：**选一个基准，把数组一分为二——左边全比它小，右边全比它大。然后只对左右两半递归。**

关键在于它只关心"左小右大"这件事，**完全不管每一半内部是不是有序**。这是它 $O(n\log n)$ 的来源：每一趟划分的代价是线性的，但区间长度按几何级数缩小。

一趟划分最经典的做法叫"挖坑法"：

```text
  用 low / high 两个指针夹住当前区间，pivot 存着基准值

  初始：把区间第一个元素 A[low] 取出来存进 pivot
        从 low+1 到 high 的这段区间里，元素被"挖"出了一个坑

     ┌───────────────────────────────┐
     │  pivot                         │
     │    ↓                           │
     │  [坑] ?  ?  ?  ?  ?  ?  ?  ?  ↑ 从 high 往左扫
     │   low                        high
     └───────────────────────────────┘

  ① 从 high 往左扫，找比 pivot 小的（A[high] < pivot），找到就把它填进 low 的坑
     —— 坑从 low 移到了 high
  ② 从 low 往右扫，找比 pivot 大的（A[low] > pivot），找到就把它填进 high 的坑
     —— 坑又从 high 移回 low
  ③ 两个指针相遇时，把 pivot 填进这个坑，分家完成

  相遇点就是基准的最终下标 pivot_pos
  区间 [low, pivot_pos-1] 全部 ≤ pivot
  区间 [pivot_pos+1, high] 全部 ≥ pivot
```

```c
/* 一趟划分：让 [low,high] 分成两半，返回基准元素的最终下标 */
int Partition(int A[], int low, int high)
{
    int pivot = A[low];                       /* 基准先"挖"出来 */

    while (low < high) {
        while (low < high && A[high] >= pivot) high--;   /* 从右往左找小的 */
        A[low] = A[high];                     /* 找到就填坑，坑移到 high */
        while (low < high && A[low] <= pivot) low++;      /* 从左往右找大的 */
        A[high] = A[low];                     /* 填坑，坑移回 low */
    }
    A[low] = pivot;                            /* 相遇，基准归位 */
    return low;
}

void QuickSort(int A[], int low, int high)
{
    if (low >= high) return;                   /* 递归出口 */
    int pos = Partition(A, low, high);
    QuickSort(A, low, pos - 1);
    QuickSort(A, pos + 1, high);
}
```

> **结论**：快排**最好与平均 $O(n\log n)$**（每次都恰好对半分），**最坏 $O(n^2)$**（每次都选到极值，一趟只剥掉一个元素），**空间平均 $O(\log n)$、最坏 $O(n)$**（递归栈），**不稳定**。

> **易错点**：快排的空间复杂度为什么不是 $O(1)$？很多人看到"原地划分"就写 $O(1)$。划分本身确实只用常数个临时变量，但**递归调用要压栈**，递归深度就是空间。平均 $O(\log n)$、最坏 $O(n)$。这就是为什么做那道"找未出现的最小正整数"的题时，用排序的解法空间是 $O(\log n)$ 而不是 $O(1)$——那 $O(\log n)$ 恰恰是快排的递归栈。

> **易错点**：快排最坏 $O(n^2)$ 的触发条件是"每次选到的基准都是当前区间的极值"。实践中的标准处理是**三数取中**（取区间首、中、尾三个，取中间那个做基准），把概率极大的最坏情况压下去。考研选择题问"怎么改进快排"，标准答案就是它。

### 冒泡排序

冒泡排序的图像最直观：**一趟从后往前（或从前往后）扫，相邻两个比较，大的一定往后冒。** 冒完一趟，序列的一端一定是当前最值，然后把这端"冻结"，下一趟少扫一个。

改良版：设一个标志位 `flag`。一趟下来如果没有发生任何交换，说明序列已经有序，直接收工。这一改让"原序列已有序"的情况从 $O(n^2)$ 变成 $O(n)$。

```c
void BubbleSort(int A[], int n)
{
    for (int i = 0; i < n - 1; i++) {
        int flag = 0;                      /* 本趟有没有换过 */
        for (int j = 0; j < n - 1 - i; j++) {
            if (A[j] > A[j + 1]) {         /* 严格大于才换 —— 稳定的来源 */
                int t = A[j]; A[j] = A[j + 1]; A[j + 1] = t;
                flag = 1;
            }
        }
        if (flag == 0) break;              /* 一趟没换过，已排好 */
    }
}
```

> **结论**：冒泡**最好 $O(n)$**（带 `flag`，原序列已有序）、**最坏与平均 $O(n^2)$**，**空间 $O(1)$**，**稳定**。

### 归并排序与"只走一半的归并"

归并排序的思路是**反向**的：它不追求一趟排好，而是把两个已经有序的小段合成一段更大的有序段。段的长度逐层翻倍：$2 \to 4 \to 8 \to \dots$，所以趟数是 $\log n$，每趟代价 $O(n)$，总共 $O(n\log n)$。

```c
/* 把 A[low..mid] 与 A[mid+1..high] 合成一段有序，写进 temp */
void Merge(int A[], int low, int mid, int high, int temp[])
{
    int i = low, j = mid + 1, k = low;
    while (i <= mid && j <= high) {
        if (A[i] <= A[j]) temp[k++] = A[i++];   /* 相等取左边 —— 稳定 */
        else               temp[k++] = A[j++];
    }
    while (i <= mid)  temp[k++] = A[i++];
    while (j <= high) temp[k++] = A[j++];
    for (int t = low; t <= high; t++) A[t] = temp[t];
}

void MergeSort(int A[], int low, int high, int temp[])
{
    if (low >= high) return;
    int mid = low + (high - low) / 2;
    MergeSort(A, low, mid, temp);
    MergeSort(A, mid + 1, high, temp);
    Merge(A, low, mid, high, temp);
}
```

> **结论**：归并**时间 $O(n\log n)$**（最好、最坏、平均三者相同），**空间 $O(n)$**（辅助数组），**稳定**。

**这里有一个特别值得抠的点**：归并过程其实**可以在中途停下来**。

那道"求两个升序序列的中位数"的题，看上去是排序题，其实根本不用排。两个序列都升序、长度都是 $L$，那中位数就是它们合并后序列的第 $L$ 个元素。既然只想拿第 $L$ 个，那**走 $L$ 步就收工**，何必走完 $2L$ 步？

```c
/* 解法一：老老实实归并，造一个 2N 的辅助数组 */
int MedianByMerge(int S1[], int S2[], int n)
{
    int *c = (int *)malloc(2 * n * sizeof(int));
    int i = 0, j = 0, k = 0;
    while (i < n && j < n) {
        if (S1[i] < S2[j]) c[k++] = S1[i++];
        else               c[k++] = S2[j++];
    }
    while (i < n) c[k++] = S1[i++];
    while (j < n) c[k++] = S2[j++];
    return c[n - 1];                      /* 第 L 个元素 */
}

/* 解法二：双指针只走 L 步，省掉 O(N) 辅助空间 */
int MedianByPointer(int S1[], int S2[], int n)
{
    int i = 0, j = 0, count = 1;
    while (count < n) {                   /* 数满 L 个就收工 */
        if (S1[i] < S2[j]) i++;
        else               j++;
        count++;
    }
    return S1[i] < S2[j] ? S1[i] : S2[j];  /* 一定要取小的那个 */
}
```

```text
  走了够 L 步、count 停在 L 时的现场：

  S1:  ...   6   8   ?  20
                        ^  i 指向 20
  S2:  11   ...  ...  ...  ...
       ^
       j 指向 11

  取小者 -> 11，正好是合并后第 L 个元素
```

> **提示**：为什么答案**一定**取小的那一个？因为你没法确定剩下的数据是不是都比那个大的数小。既然剩下 $L$ 个数全都 ≥ 大者，那大者必然是合并序列里最大的元素之一，最不可能当中位数。所以答案只能是小的那一个。

这个例子的教学价值在于：**归并是一个可以按需截断的过程**。只要你知道答案落在第几位，就可以只算到第几位。这在考场上是能救命的——同样的题，能想到这一层，复杂度直接降一档。

## 选择类：每一趟把极值钉死

选择类的共同骨架：**第 $i$ 趟，在还没排好的后缀里挑出最值，直接送到后缀的最前端（升序）或最末端（降序）。** 它的好处是**比较次数跟原始排列完全无关**，坏处是搬动的次数少得可怜。

### 简单选择排序

第 $i$ 趟在 `A[i..n-1]` 里找出最小值，和 `A[i]` 交换。第 $i$ 趟比 $n-i$ 次，总比较次数固定：

$$\sum_{i=1}^{n-1}(n-i) = \frac{n(n-1)}{2}$$

不管原序列长什么样，**比较次数永远是 $n(n-1)/2$**。这是所有排序里最"死板"的一个。

```c
void SelectSort(int A[], int n)
{
    for (int i = 0; i < n - 1; i++) {
        int min = i;                        /* 假设 i 处最小 */
        for (int j = i + 1; j < n; j++)
            if (A[j] < A[min]) min = j;    /* 严格小于才换 —— 稳定的来源 */
        if (min != i) {
            int t = A[i]; A[i] = A[min]; A[min] = t;
        }
    }
}
```

> **结论**：简单选择**最好、最坏、平均全是 $O(n^2)$**，**空间 $O(1)$**，**稳定**。交换次数最多 $n-1$ 次、最少 0 次。

### 堆排序

堆排序是"选择类里唯一不平方"的。它的立足点是：**建一个堆，就能 O(1) 拿到当前最值。**

大顶堆的定义：一棵完全二叉树，且**每个结点都不小于它的两个孩子**。于是根结点就是整个堆的最大值。

```text
  大顶堆（用完全二叉树的数组表示，下标从 0 开始）

          49
         /  \
       38    65
      / \    / \
    13  27  97  76

  数组: [ 49, 38, 65, 13, 27, 97, 76 ]
         0   1   2   3   4   5   6

  结点 i 的左孩子 = 2i+1，右孩子 = 2i+2，父结点 = (i-1)/2
  —— 完全二叉树没有空洞，这就是能用数组存的根本原因
```

堆排序的两个动作：

1. **建堆**：从最后一个非叶结点（下标 $n/2 - 1$）开始，往上逐个做"下沉调整"，总共 $O(n)$。注意是从下往上，不是从上往下。
2. **反复取顶**：把堆顶（当前最大）换到当前堆的末尾，堆的长度减一，在剩下的堆里重新下沉调整。共 $n-1$ 次，每次 $O(\log n)$。

```text
  一趟"取堆顶"之后长什么样：

  原堆（数组表示，最后一位是末尾待定区）：
        [ 49  38  65  13  27  97  76 ]
         ▲
        堆顶 = 最大值 49

  ① 交换堆顶与末尾：
        [ 76  38  65  13  27  97  49 ]
                                 └── 49 被钉死在它该在的位置，再也不动

  ② 有效堆区少一个（末尾 49 退出堆），下标 0 重新下沉调整：
        [ 76  38  65  13  27  97 ]      ← 49 已经归位，不再参与任何比较
         ▲
        新堆顶 = 次大值 76

  规律：你能在过程里反复看到"一个元素被一次性送到末尾、之后再也不动"，
        这是堆排序最醒目的指纹。
```

```c
void SiftDown(int A[], int i, int n)       /* 在 A[0..n-1] 里把 A[i] 下沉到位 */
{
    while (2 * i + 1 < n) {                /* 左孩子还在 */
        int child = 2 * i + 1;
        if (child + 1 < n && A[child + 1] > A[child]) child++;  /* 挑大的那个 */
        if (A[i] >= A[child]) break;       /* 堆序已满足，停 */
        int t = A[i]; A[i] = A[child]; A[child] = t;
        i = child;
    }
}

void HeapSort(int A[], int n)
{
    for (int i = n / 2 - 1; i >= 0; i--) SiftDown(A, i, n);   /* 建大顶堆 */
    for (int k = n - 1; k > 0; k--) {
        int t = A[0]; A[0] = A[k]; A[k] = t;   /* 堆顶送末尾，永久归位 */
        SiftDown(A, 0, k);                     /* 在缩小的堆里重建 */
    }
}
```

> **结论**：堆排序**最好、最坏、平均全是 $O(n\log n)$**（这是它最漂亮的地方——三种情况一个数），**空间 $O(1)$**，**不稳定**。

> **易错点**：堆排序不稳定，同样死在"只有严格比较、没有留位置给相等元素"上。调整路径上一路往大的方向走，遇到相等就停了——**相等元素之间谁在前谁在后，完全由它们在堆里的初始相对位置决定，而建堆已经把那个顺序打乱了**。

## 九个算法摆在一张纸上

现在把话都收回来，做一张总表。这张表建议直接背下来——选择题、填空题、大题的"分析"问，全靠它。

### 性质对照表

| 类别 | 算法 | 最好 | 平均 | 最坏 | 空间 | 稳定 | 关键特征 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 插入类 | 直接插入 | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 稳定 | 插入点在相等元素之后 |
| 插入类 | 折半插入 | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 稳定 | 减比较不减移动，过程与直接插入完全一致 |
| 插入类 | 希尔排序 | $O(n)$ | $O(n^{1.3})$ | $O(n^2)$ | $O(1)$ | **不稳定** | 分组插入，靠增量序列提速 |
| 交换类 | 冒泡排序 | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 稳定 | 带 `flag` 可提前退出 |
| 交换类 | 快速排序 | $O(n\log n)$ | $O(n\log n)$ | $O(n^2)$ | $O(\log n)$ | **不稳定** | 只管分家，不管内部有序 |
| 归并类 | 归并排序 | $O(n\log n)$ | $O(n\log n)$ | $O(n\log n)$ | $O(n)$ | 稳定 | 段长逐层翻倍，$\log n$ 趟 |
| 选择类 | 简单选择 | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 稳定 | 比较次数恒为 $n(n-1)/2$ |
| 选择类 | 堆排序 | $O(n\log n)$ | $O(n\log n)$ | $O(n\log n)$ | $O(1)$ | **不稳定** | 建堆 $O(n)$，取顶 $O(\log n)$ |
| 分配类 | 基数排序 | $O(d(n+r))$ | $O(d(n+r))$ | $O(d(n+r))$ | $O(r)$ | 稳定 | $d$ 趟，每趟按位分配 |
| 分配类 | 计数排序 | $O(n+k)$ | $O(n+k)$ | $O(n+k)$ | $O(k)$ | 稳定 | 不比较，直接算名次 |

> **提示**：这张表里我最希望你盯住三行。第一行和"简单选择"那行，**稳定性是"稳定"**；第二行和"快排""堆排序"那两行，**不稳定**。判稳定的唯一标准只有一条：**相等元素是否有机会被放到对方前面去**。

### 移动次数与交换次数，千万别混

这是排序分析里最容易翻车的一笔账。**一次交换，不是一次移动，而是三次移动。**

```text
  交换 A[i] 和 A[j]，实际发生的三次数据搬运：

      ① A[i] ──► 临时变量        （借出来）
      ② A[j] ──► A[i]           （顶上去）
      ③ 临时变量 ──► A[j]       （送回来）

      = 3 次移动 / 每做 1 次交换
```

所以**比较次数**、**移动次数**、**交换次数**是三个不同的量，算出来再往一起凑的时候记得乘 3。

| 算法 | 最好情况 | 最坏情况 | 移动次数怎么来的 |
| --- | --- | --- | --- |
| 直接插入 | $O(n)$ 比较、**0 次移动** | $n(n-1)/2$ 比较、$n(n-1)/2$ 次移动 | 最坏时每个元素都要往前挪满 |
| 冒泡 | $O(n)$ 比较、0 次交换 | $n(n-1)/2$ 次交换 | 交换 $\times 3$，即移动 $3\cdot\frac{n(n-1)}{2}$ |
| 简单选择 | 比较恒 $\frac{n(n-1)}{2}$ | 同左 | 交换最多 $n-1$ 次 → 移动最多 $3(n-1)$ |
| 快速排序 | $O(n\log n)$ | $O(n^2)$ | 一趟里每交换一次算 3 次移动，交换次数约为比较次数的一半 |
| 堆排序 | $O(n\log n)$ | $O(n\log n)$ | 每次取顶 1 次交换 + 下沉时逐层交换 |

> **易错点**：直接插入排序"最好情况 0 次移动"这句话一定要背准。已有序的时候，每一趟只做一次比较就发现不用挪，元素一个都没动过。但**比较次数是 $n-1$ 次**，不是 0。有人顺手把比较次数也写成 0，那就错得一塌糊涂了。

> **提示**：还有一个特别值得强调的对比——**简单选择和冒泡的比较次数完全一样**（都是 $n(n-1)/2$），但冒泡在有序情况下能提前退出，简单选择不能。所以"简单选择排序性能最稳定"说的是它**对初始排列不敏感**，而不是它快。

### 复杂度里最容易报错的几笔账

- **"$n\log n$"到底是谁的**：快排、归并、堆排序。三者里只有堆排序是**最好最坏都是 $n\log n$**；快排最坏掉回 $n^2$；归并必须开 $O(n)$ 辅助空间。
- **"$O(1)$ 空间"都有谁**：直接插入、折半插入、希尔、冒泡、简单选择、堆排序。这六个。快排是 $O(\log n)$，归并是 $O(n)$，基数排序是 $O(r)$。
- **建堆是 $O(n)$ 不是 $O(n\log n)$**：很多人在这里写 $n\log n$，因为"调整一次是 $\log n$，一共 $n$ 次"。错。建堆是**自底向上**的，高度为 $h$ 的结点有约 $n/2^{h+1}$ 个、每个调整 $O(h)$，加总收敛到 $O(n)$。反过来，从上往下自顶向下建堆才是 $O(n\log n)$。
- **折半插入的比较次数是 $O(n\log n)$，但时间还是 $O(n^2)$**：原因上面讲过——移动没降。

## 只给两趟结果，怎么反推它是哪一种

这是排序题里最见功夫的一类：题干只给"初始序列"和"前两趟排序后的序列"，问"它是哪种排序算法"。你不能靠猜，但**绝对有排除法**。

### 排除法的总思路

拿到一个中间状态，别急着认领算法，先做三件事：

1. **数一数相对位置被打乱的程度**。元素移动幅度很小（都在原位附近挪一格）→ 多半是插入类或冒泡；元素被甩得很远 → 多半是快排、归并、基数。
2. **找"有序片段"**。看结果里有没有一段明显有序的前缀、或者两两成对有序的分组——不同的算法留下的痕迹完全不同。
3. **从最不可能的开始排**。一次划掉两三个，剩下的就是它。

### 各算法的"指纹"

| 算法 | 它在中间结果上留下的痕迹 | 一句话判据 |
| --- | --- | --- |
| 基数排序 | 按某一位（个位、十位……）**分段聚集**，段内乱、段间按该位递增 | **低位优先**——先排低位，才会出现"个位相同的一堆挨在一起" |
| 归并排序 | 每趟结束都有一段**长度翻倍的有序前缀**（2、4、8……） | 归并痕迹：能看出前 $k$ 个是从两段源序列归并来的 |
| 直接插入 / 折半插入 | 元素只在**已排好区与待排区的交界处**移动，整体位移很小 | 前缀几乎全有序，只在末尾一小段被打乱 |
| **折半插入 ≡ 直接插入** | 两者的**每一趟中间结果完全相同** | 折半只改了"怎么比较"，没改"插到哪"，所以过程一模一样 |
| 希尔排序 | 按某个间隔 $d$ 分组后，**每组内部都有序** | **增量分组**——每隔 $d$ 取一个，构成一个非降序列 |
| 冒泡排序 | 每趟有一个极值被推到**一端并冻结**，且相邻成对的元素普遍已有序 | 逐步"两头冒泡"，有序区从两端向中间长 |
| 快速排序 | 一趟之后出现**分界线**：左边一堆比右边一堆小，但两边内部各自是乱的 | 典型的"分家不排序" |
| 堆排序 | 反复看到"某个元素被一次性送到末尾，之后再没动过"，且有效堆区逐次缩短 | 有效区间顶端缩小的过程 + 每次把区间的极值钉死在末位 |

> **结论**：这八条指纹里，考试最常用的其实只有四条——**基数排序看低位优先、归并排序看有序前缀是否翻倍、希尔排序看增量分组、快排看分界线**。剩下的四条用来兜底。

### 折半插入等同直接插入：一条必须记死的结论

把这条单独拎出来，因为它是"由结果反推算法"里唯一一个**反推不出、只能靠别的方式区分**的情形。

**折半插入排序和直接插入排序的每一趟结果完全相同。** 原因很硬：它们都把新元素插到"它应当在的位置"，而这个位置是唯一的；折半插入只是**用更快的方式找到**它，找到之后做的事（把后面元素后移、把它放进去）和直接插入一字不差。

> **提示**：所以题目如果问"这两趟结果可能由哪种排序产生"，折半插入和直接插入**都算对**，两个都写上。反过来，如果要区分这两者，只能从**比较次数**下手：折半插入的比较次数是 $O(n\log n)$，直接插入是 $O(n^2)$。

### 从两趟结果反推希尔排序的增量

这是指纹里最需要动脑的一条，因为它不是"认出来"，而是"算出来"。

**第一趟的结果，能直接告诉你第一趟的增量。** 道理很简单：希尔排序对某个增量 $d$ 做的工作，就是把"下标间隔为 $d$ 的元素"分组做插入排序。所以——

> **结论**：拿第一趟后的结果，从左往右每隔 2 个取一组、每隔 3 个取一组…… 那个能让**所有组都非降序**的最小间隔，就是第一趟的增量 $d_1$。

用一道完整的过程题来走：

```text
  初始序列：      6  5  4  3  2  1
  第一趟后：      2  1  4  3  6  5
  第二趟后：      1  2  3  4  5  6
```

**第一步，验第一趟。** 把 `2 1 4 3 6 5` 按间隔 $d$ 分组，看哪个 $d$ 能让每组内部都非降：

```text
  试 d = 2：
      组 0（下标 0,2,4）：2, 4, 6     ← 非降 ✓
      组 1（下标 1,3,5）：1, 3, 5     ← 非降 ✓
      ⇒ d1 = 2，认得出来

  试 d = 3：
      组 0（0,3）：2, 3               ← 非降 ✓
      组 1（1,4）：1, 6               ← 非降 ✓
      组 2（2,5）：4, 5               ← 非降 ✓
      ⇒ d = 3 也成立？但 d=2 更小，说明真实增量取最小的那个：d1 = 2
```

**第二步，验第二趟。** 第二趟结果 `1 2 3 4 5 6` 已经全有序，按间隔 1 分组只有一个组，必然非降，所以 $d_2 = 1$。

**第三步，验增量序列合法性。** 得到 $d_1 = 2, d_2 = 1$，正好是经典的**希尔增量**（每趟减半，$d_{i+1} = d_i / 2$）。

```text
  完整的手工模拟：

  初始          6  5  4  3  2  1

  第一趟 d=2：
      组 A（下标 0,2,4）= 6, 4, 2  →  插入排序 →  1, 3, 5
      组 B（下标 1,3  ）= 5, 3     →  插入排序 →  2, 4
      写回：              1  2  3  4  5  6

  第二趟 d=1：整个序列一组做直接插入
      原序列已升序，一趟走完：      1  2  3  4  5  6
```

**第四步，检验它不是别的算法。** 这个过程有两个疑点要排掉：

- `6 5 4 3 2 1` 第一趟变 `2 1 4 3 6 5`，元素位移挺大（6 从头跑到第 5 位），插入类"只在末尾小范围挪"的画像不符合 → 排除直接插入、折半插入、冒泡。
- 结果里既没有明显的"分界线"（前 3 个都小于后 3 个），也没有有序前缀 → 排除快排、归并。
- 每次都看到某些元素被甩到远处又不"归位" → 排除堆排序、选择类。
- 剩下唯一能解释的就是**分组插入**，$d=2$。

> **易错点**：反推增量时，**"$d$ 能让每组有序"是必要条件，但可能同时有多个 $d$ 满足**（比如上例里 $d=3$ 也成立）。规则是取**最小**的那个。而且要综合所有趟次：把每一趟算出的最小可行增量排成一列，看它们能不能拼成一条合法的增量序列（末位必须是 1）。拼不出来，说明这个过程不是希尔。

## 计数排序：一段能把名次算出来的程序

排序题里有一类，压根不考你会不会写快排，而是甩一段**不带注释的代码**给你，问三个问题：跑完结果是什么、比较次数多少、稳定吗、怎么改造成稳定的。

```c
void CompareCountSort(int A[], int B[], int N)
{
    int i, j, *count;
    count = (int *)malloc(N * sizeof(int));
    for (i = 0; i < N; i++)
        count[i] = 0;                  /* count 先清零 */
    for (i = 0; i < N - 1; i++)       /* 外层：i 取 0 ~ N-2 */
        for (j = i + 1; j < N; j++)   /* 内层：j 取 i+1 ~ N-1 */
            if (A[i] < A[j])
                count[j]++;
            else
                count[i]++;
    for (i = 0; i < N; i++)
        B[count[i]] = A[i];           /* count 当下标，把 A 搬进 B */
}
```

先别管它叫什么名字，**老老实实一行一行跑**。很多同学一看到 `if (A[i] < A[j])` 就开始猜这是什么算法——猜着猜着就掉坑里了。

### count[i] 的真正含义

`count[i]` 记的**不是"右边有多少个数比我小"**这么一句话。真的是两头都记：

$$\text{count}[i] \;=\; \#\{j<i \mid A[j]<A[i]\} \;+\; \#\{j>i \mid A[j]\le A[i]\}$$

左边比我小的、右边比我小的，再加上**右边跟我相等的**，全记到我头上。

> **定义**：`count[i]` 就是 $A[i]$ 在"小于等于"这个尺度下的**名次**（从 0 开始数）。相等的元素只会被算进排在前面那一个的 `count` 里。

用题目给的 $A = (25, 10, 25, 10, 11, 19)$ 完整走一遍：

| i | $A[i]$ | 左边比它小的 | 右边比它小的 | 右边和它相等的 | $count[i]$ |
| --- | --- | --- | --- | --- | --- |
| 0 | 25 | — | 10、10、11、19 | 25 | 5 |
| 1 | 10 | — | — | 10 | 1 |
| 2 | 25 | 10 | 10、11、19 | — | 4 |
| 3 | 10 | — | — | — | 0 |
| 4 | 11 | 10、10 | — | — | 2 |
| 5 | 19 | 10、10、11 | — | — | 3 |

所以 $count = \{5,\,1,\,4,\,0,\,2,\,3\}$。最后一行 `B[count[i]] = A[i]` 把每个元素搬到它该在的格子里：

| i | $A[i]$ | $count[i]$ | 落到 $B$ 的哪一格 | $B$ 的值 |
| --- | --- | --- | --- | --- |
| 0 | 25 | 5 | $B[5]$ | 25 |
| 1 | 10 | 1 | $B[1]$ | 10 |
| 2 | 25 | 4 | $B[4]$ | 25 |
| 3 | 10 | 0 | $B[0]$ | 10 |
| 4 | 11 | 2 | $B[2]$ | 11 |
| 5 | 19 | 3 | $B[3]$ | 19 |

按位置重排：

$$B=\{\,10,\ 10,\ 11,\ 19,\ 25,\ 25\,\}$$

> **提示**：`count` 是"小于等于名次"，`B[count[i]] = A[i]` 就是把每个元素搬到它该在的格子里——这本质上是一次**计数排序**。别一认出这个名字就开始背它的稳定性结论，盯着 `B[count[i]] = A[i]` 反推：$count[i]$ 越大的元素排得越靠后。等号站在哪一边，两个相等元素的先后答案就自己冒出来了。

### 比较次数为什么是 $N(N-1)/2$

这道题问的"比较次数"，不是什么都能算。先**划边界**：变量声明、`malloc`、第一个清零循环、最后一个搬数循环——这四块**都不含任何元素之间的比较**。整个函数里只有 `if (A[i] < A[j])` 这一句在做比较，而且每次进入双层循环的循环体，必定走 `if` 或 `else`，必定比较一次。

所以比较次数 = 双层循环体的执行次数。外层 $i$ 取 $0 \sim N-2$，固定 $i$ 时内层 $j$ 从 $i+1$ 到 $N-1$，个数是 $N-i-1$：

| $i$ | $j$ 的范围 | 内层次数 |
| --- | --- | --- |
| 0 | $1 \sim N-1$ | $N-1$ |
| 1 | $2 \sim N-1$ | $N-2$ |
| 2 | $3 \sim N-1$ | $N-3$ |
| $\dots$ | $\dots$ | $\dots$ |
| $N-2$ | $N-1 \sim N-1$ | $1$ |

$$\sum_{i=0}^{N-2}(N-1-i)\;=\;(N-1)^2-\frac{(0+N-2)(N-1)}{2}\;=\;\frac{N(N-1)}{2}$$

> **结论**：比较次数 $=\dfrac{N(N-1)}{2}$，就是从 $N$ 个里挑 2 个的组合数。代 $N=6$ 是 15 次。

> **提示**：这一问的**过程比结果重要**。答题时先说清"比较次数由 $i$ 和 $j$ 的取值范围决定"，再摆求和式，最后落到 $\frac{N(N-1)}{2}$——三步齐了才算完。结果算对了但过程糊弄过去，是要扣分的。

### 稳定性只看相等元素的先后

$A$ 里有 0 号位的 25 和 2 号位的 25，一模一样。跑完 $B[5]$ 是 0 号位那个搬过去的、$B[4]$ 是 2 号位搬过去的——**原来在前面的那个 25，跑完跑到后面去了。不稳定。**

那稳定性是被哪一步毁掉的？回到双层循环。整个算法里跟"等于"有关系的，**只有一个地方**，就是那个 `if / else` 的分叉：`A[i] < A[j]` 成立走 `if`，不成立（也就是 $\ge$）走 `else`。相等的情况，统统被 `else` 接走了。

> **易错点**：这就是"排序算法不稳定"的唯一来源。相等的元素被塞进了"我比你大"那一支，于是靠前的那个反而拿到了更大的 `count`，跑到后面去了。

改法也就一处：把 `if` 里的 `<` 改成 `<=`，让相等的情况走 `if` 那一支。

```c
            if (A[i] <= A[j])          /* 原来是 < */
                count[j]++;
            else
                count[i]++;
```

改完再看那两个 25：

- $i=0$，$A[0]=25$：$j=3,4,5$ 时 `25 <= x` 不成立，走 `else`，`count[0]` 加 4 次；$j=2$ 时 `25 <= 25` **成立**，走 `if`，加到了 `count[2]` 头上。所以 $count[0] = 4$。
- $i=1$，$A[1]=10$：$j=3$ 时 `10 <= 10` 成立，走 `if`，加的是 `count[3]`，不是 `count[1]`。所以 $count[1] = 0$，而且全程序再没有别的地方会给它加。
- $i=2$，$A[2]=25$：$j=3\sim5$ 全部走 `else`，加 3 次；再被 $A[1]$ 和 $A[0]$ 各加一次。所以 $count[2] = 5$。

新的 $count = \{4,\,0,\,5,\,1,\,2,\,3\}$。0 号位的 25 落在 $B[4]$，2 号位的 25 落在 $B[5]$——**靠前的那个 25 还在前面**，$B$ 依旧是 $\{10,\,10,\,11,\,19,\,25,\,25\}$，一点没乱。稳定。

> **结论**：把 `if (A[i] < A[j])` 改成 `if (A[i] <= A[j])`，算法就变成稳定的。

> **提示**：真到考场里，只要你已经定位到"是哪一步在处理相等的情况"，把它挪到另一条分支上，就一定能改出稳定的结果——因为整个程序再没有第二处碰"等于"了。上面的验证只是吃颗定心丸，证明它真的稳定，不是嘴上说说。

### 排序，还是不排序

最后提醒一个**选型意识**。同样一道题——"找出数组中未出现的最小正整数，题目要求时间尽可能高效、空间没有要求"——你有两个选择：

**路线一：开一个辅助数组做标记。** 先把答案范围框死在 $1 \sim N+1$（$N$ 个数不可能把 $N+2$ 个正整数全占满），开 $N+1$ 个格子的 $B$，令 $B[i]=1$ 表示值 $i+1$ 出现过，负数跳过、非正数不管，扫完 $A$ 再从前往后扫 $B$，第一个 0 就是答案。时间 $O(n)$，空间 $O(n)$。

```text
  A = { -5,  3,  2,  3 }，N = 4，B 有 5 个位置

  A[0] = -5   负数，跳过          B: 0 0 0 0 0
  A[1] =  3   B[3-1] = B[2] 置 1 B: 0 0 1 0 0
  A[2] =  2   B[2-1] = B[1] 置 1 B: 0 1 1 0 0
  A[3] =  3   B[2] 已经是 1，不动 B: 0 1 1 0 0

  从前往后扫 B，第一个 0 在下标 0 → 返回 下标+1 = 1
  （若一路都是 1，说明 1~N 全出现过 → 返回 N+1）
```

**路线二：先排序再扫。** 用 `miss` 变量从 1 开始试探，遇到负数 `continue` 跳过，遇到与 `miss` 不等的正数就立刻返回它，相等就 `miss++`。时间 $O(n\log n)$。

```c
int findMissPositiveSort(int A[], int n)
{
    QuickSort(A, 0, n - 1);            /* 前提：必须先有序 */
    int miss = 1;
    for (int i = 0; i < n; i++) {
        if (A[i] < 0) continue;        /* 负数不处理 */
        if (A[i] != miss) return miss; /* miss 就是最小未出现的 */
        miss++;
    }
    return miss;
}
```

两条路都能拿分，但你得知道它们各自的代价：

| 路线 | 时间 | 空间 | 前提 |
| --- | --- | --- | --- |
| 辅助数组 | $O(n)$ | $O(n)$ | 必须先想明白答案落在 $1 \sim N+1$ |
| 排序 + 扫 | $O(n\log n)$ | $O(\log n)$ | 数组必须先有序；那 $\log n$ 是快排的递归栈 |

> **结论**：这道题**首选辅助数组路线**。因为题目只要求"时间尽可能高效"、对空间没有要求，那 $O(n)$ 的时间就是天花板；而排序路线光排序就 $O(n\log n)$，还捎带一个 $O(\log n)$ 的递归栈。

> **提示**：`continue` 和 `break` 千万别混。`continue` 是**进入下一次迭代**——本次循环下面的代码全不执行，直接 `i++`；`break` 是**跳出离它最近的那一层循环**。这里"这个数我不想处理"用 `continue`，"我要跳出循环去做处理"用 `break`。

## 置换选择排序：给归并段把长度拉开

外排序里，最先碰到的一个问题是：**初始归并段怎么生成？**

最朴素的做法是：把内存工作区读满，把这批输出掉，工作区空了再读满下一批。这样生成的初始归并段，**长度都是一样的**。

### 为什么外排序要跟磁盘 I/O 死磕

因为归并段个数直接等于后面**多路归并的趟数**，而每一趟都要把全部数据从磁盘读进来、写回磁盘去。段数越多，I/O 次数越多。

而待排序文件的总大小是固定的，所以：

> **结论**：在文件总大小固定的前提下，**每个初始归并段越长，段数就越少，I/O 次数就越少**。置换选择排序就是冲着这个去的。

### 置换选择排序的四步规矩

工作区能装 $M$ 条记录。规则说白了就四步：

1. 先从文件读 $M$ 条记录，把工作区填满；
2. 在工作区里挑关键字**最小**的那条，输出到当前归并段；
3. 每输出一条就腾出一个空位，**立刻**从文件补读一条新的进来；
4. 在工作区里挑"比刚输出那条大、并且是其中最小的"那条，输出出去。

重复第 4 步，直到工作区里再也找不到比刚输出记录更大的了——这时输出一个**归并段结束符**，换下一段重新开始。

> **提示**：为什么一定要挑"比刚输出的大"？**归并段必须有序**。第 1 步既然挑的是 37，同一段里后面挑的数就必须比 37 大，否则这一段本身就是乱的，后面的多路归并根本无从做起。

真正决定长短的是第 3 步：**输出和补读是同时发生的**，工作区始终保持 $M$ 条满载。补进来的新记录如果刚好比刚输出的那条大，立刻就能接着输出，出料口永远不堵；如果比它小，就被压在箱底，这一轮轮不到它，只能等下一段了。

```text
  为什么要"输出即补读"？画一下这个工作区

      时刻 t                     时刻 t+1（输出 37，同时补读 14）
      ┌───┬───┬───┬───┐         ┌───┬───┬───┬───┐
      │   │   │37 │   │   ──┐   │14 │   │   │   │   ← 37 走了，坑立刻补上
      │   │   │   │   │     │   └───┴───┴───┴───┘
      └───┴───┴───┴───┘         出料口一个都没堵

  补进来的 14 比刚输出的 37 小 → 压在箱底，这一轮排不到它
  补进来的如果比 37 大 → 立刻又能输出，段就变长了

  「输出即补读」= 段长的机制来源
```

### 逐次走一遍：十九条记录、四格工作区

19 条记录：51、94、37、92、14、63、15、99、48、56、23、60、31、17、43、8、90、166、100；$M=4$。

**第一段：37、51、63、92、94、99**

| 补读记录 | 工作区内容 | 输出 |
| --- | --- | --- |
| 51 94 37 92 | { 37  51  92  94 } | 37 |
| 14 | { 14  51  92  94 } | 51 |
| 63 | { 14  63  92  94 } | 63 |
| 15 | { 14  15  92  94 } | 92 |
| 99 | { 14  15  94  99 } | 94 |
| 48 | { 14  15  48  99 } | 99 |
| 56 | { 14  15  48  56 } | **段结束** |

注意第 3、4 行：输出 63 之后补进来的 15 比 63 小，被压了下去；输出 92 之后补进来的 99 更大，马上接上输出。同一批补读，**有的马上用、有的要等下一段**——初始归并段的长短就是这么拉开差距的。

输出 99 之后补读 56，工作区变成 $\{14, 15, 48, 56\}$，没有任何一条比 99 大，本段结束，长度 6。

**第二段：14、15、23、31、48、56、60、90、166**

这一段从工作区里剩下的 $\{14, 15, 48, 56\}$ 开始，一口气输出 9 条，是三段里最长的。

| 输出 | 补读 | 补读后的工作区 |
| --- | --- | --- |
| 14 | 23 | { 15  23  48  56 } |
| 15 | 60 | { 23  48  56  60 } |
| 23 | 31 | { 31  48  56  60 } |
| 31 | 17 | { 17  48  56  60 } |
| 48 | 43 | { 17  43  56  60 } |
| 56 | 8 | {  8  17  43  60 } |
| 60 | 90 | {  8  17  43  90 } |
| 90 | 166 | {  8  17  43 166 } |
| 166 | 100 | {  8  17  43 100 }　**无 > 166，本段结束** |

关键看输出 31 那一行：补读进来的 17 比 31 小，被压住，于是下一次只能输出 48。再看最后两行：输出 90 补进 166、输出 166 补进 100，工作区里 $\{8, 17, 43, 100\}$ 全都比 166 小，本段结束，长度 9。

**第三段：8、17、43、100**

到这儿 19 条记录已经全部读进过文件了，工作区里剩下 $\{8, 17, 43, 100\}$，后面再没有记录可补。于是只能一路按"比上一个大"往外排：$8 \to 17 \to 43 \to 100$，排空收工，长度 4。

| 初始归并段 | 内容 | 长度 |
| --- | --- | --- |
| $R_1$ | 37、51、63、92、94、99 | 6 |
| $R_2$ | 14、15、23、31、48、56、60、90、166 | 9 |
| $R_3$ | 8、17、43、100 | 4 |

$6 + 9 + 4 = 19$，一条不落。

> **提示**：这个过程写起来很长，考场上**完全可以不写步骤**，只写"共生成三个初始归并段，分别是……"就行——标准答案的书写量就是这么处理的，试卷未必放得下全程。第一问答对，一般能拿一半的分。

### 第一段最长 $N$、最短 $M$

换成一问抽象的：对任意 $N \gg M > 0$，问**第一个**初始归并段长度的最大值和最小值。

**最大值是 $N$。** 极端情形就是**关键字整体递增**：工作区里挑出最小的输出掉，补进来的更大，立刻接着输出，一条不落地全排进这一段，长度就能做到 $N$。

**最小值是 $M$。** 这里要先排除掉"长度可能为 1"的想法。第一步输出的一定是工作区里最小的那一条，这一点没法绕——哪怕文件后面全是 1、2、3，你也绝不可能在工作区里挑出一个 100 来先输出。既然第一条已经出去了，工作区里另外 $M-1$ 条就全都比它大，它们迟早都得输出，所以长度**至少是 $M$**。而如果文件里已经没有记录可补读（这 $M$ 条就是全部剩余记录），长度就正好等于 $M$。

> **结论**：第一个初始归并段的长度**最长 $N$，最短 $M$**。

> **提示**：这一问的答案只跟 $N$ 和 $M$ 有关，那解题套路就很固定——先问自己"这个长度唯一吗"，不唯一就说明是个区间；再去找边界条件：最大要取到 $N$ 需要什么前提（递增），最小能不能再往下压（举反例，举不出来就定了）。**想极端例子比硬算要快得多。**

### 外部排序的完整流程

把整条链串一下，外排序一共三大步：

```text
  待排序文件（磁盘，N 条记录，内存只装得下 M 条，N >> M）

      │
      ▼
  ① 生成初始归并段
      朴素法：读满一批输出一批      → 每段长度 M，段数 N/M
      置换选择：输出即补读          → 每段长度在 M ~ N 之间，段数明显更少
      │
      ▼
  ② 多路归并（通常用败者树选最小）
      k 个初始归并段 → k 路归并，扫描一遍取一遍
      段数 k 就是归并趟数，k 越小越好
      │
      ▼
  ③ 最后一趟：把剩下的记录直接输出，再把已经有序的段写回磁盘
      最终得到一个完全有序的文件
```

> **结论**：外排序里所有的"优化"，回头看只有两个方向——**把段造长（少造几段）**、**归并时少路几趟**。置换选择解决第一个，败者树解决第二个。

> **提示**：这里头的因果链一定要连着记：初始归并段**长短不一**（置换选择）→ 段数少 → 多路归并的**趟数少** → **磁盘 I/O 次数少**。三步全是为了同一个目的服务的。

## 集合划分：把 partition 改造成第 $k$ 小

排序还有一个高频变形：**给你一个集合，让你把它分成两半，但两半各有什么要求。** 这道题是已知 $N$ 个正整数构成的集合 $A$，要求划分成两个不相交的子集 $A_1$、$A_2$，元素个数分别是 $N_1$、$N_2$，元素和分别是 $S_1$、$S_2$，要求设计一个**尽可能高效**的划分算法。

### 两个条件怎么拆开读

条件写法看着绕，拆开就两条：

- $|N_1 - N_2|$ **最小**。绝对值最小就是 0，所以 $N_1 = N_2$。$N$ 是偶数就正好对半分成 $N/2$；$N$ 是奇数的话两者必然差 1，用 $\lfloor N/2 \rfloor$ 和 $\lfloor N/2 \rfloor + 1$ 也能凑出来。
- $|S_1 - S_2|$ **最大**。既然要划分，$S_1$ 要最大、$S_2$ 要最小，那不就是让 $A_1$ 取最大的那 $\lfloor N/2 \rfloor$ 个元素、$A_2$ 取后面那 $\lfloor N/2 \rfloor$ 个吗。虽然带绝对值，排成从小到大一样能实现。

这一步想不出来，多半是对条件分析不到位。它其实隐含得很直接：**个数差最小必然是 0，0 就代表两半相等；和的差最大，那必然是一边拿最大的几个、一边拿最小的几个。**

### 解法一：排序 + 去重 + 分割

三步，顺序不能乱：**排序 → 去重 → 分割。**

```c
/* 返回 S2 - S1：题目没规定输出形式，把两边的和报出来就够了 */
int setPartition(int A[], int n)
{
    QuickSort(A, 0, n - 1);              /* ① 排序 */

    /* ② 去重：i 指向"已保留的不重复元素"的末尾，j 是工作指针 */
    int i = 0, remove = 0;
    for (int j = 1; j < n; j++) {
        if (A[j] != A[i]) {              /* 与已保留的最后一个比较，不等就保留 */
            i++;
            A[i] = A[j];
        } else {
            remove++;                    /* 相等就是重复，记一笔 */
        }
    }
    n = n - remove;                      /* 数组真实长度变了，后面全用新的 n */

    /* ③ 在中点处切一刀 */
    int mid = n / 2;                     /* 不能整除时取靠前的那一侧 */
    int N1 = 0, N2 = 0, S1 = 0, S2 = 0;
    for (int k = 0; k <= mid; k++)  { S1 += A[k]; N1++; }
    for (int k = mid + 1; k < n; k++) { S2 += A[k]; N2++; }
    return S2 - S1;
}
```

几个实现细节值得抠一下：

- **$j$ 绝对不能从 0 开始**。第 0 个元素前面什么都没有可比，它一定要被保留下来，所以工作指针从下标 1 出发。
- **比较对象是 `A[j]` 和 `A[i]`**。$i$ 始终是"已保留序列的最后一个位置"，初始 $j=1, i=0$，比的就是 0 位和 1 位。
- **`n = n - remove` 一定要做**。题目没要求不能改 $A$，改了之后取中点、划分的范围全都得跟着走。
- 题目里出现了 $N_1$、$N_2$、$S_1$、$S_2$，放置的时候顺手一起累加记录，该有的信息就都有了。
- **别拿"我直接调用 `QuickSort`"就交卷**——快排是这道题最重要的一步，你得把它写出来，不然谁也不知道你到底会不会。

> **易错点**：去重这一步绝对不能省。$A_1$ 和 $A_2$ 要求**不相交**，不相交意味着没有公共元素、同一个数值不能同时出现在两个子集里。如果直接拿一个含重复元素的数组排序后对半分，一个重复值就可能同时落到两边去，去重之后才是真正的"集合划分"。

时间复杂度 $O(n\log n)$，空间复杂度是快排的递归栈 $O(\log n)$。

### 解法二：借 partition 折半收缩

这道题真正有意思的地方在这儿——**用快排的 `partition` 思想，比"把整个序列排完序"优秀得多。**

先想清楚 `partition` 干什么：拿一个基准 $X$，把数据分成"比 $X$ 小的一部分"和"比 $X$ 大的一部分"。而这道题要求的是"前 $\lfloor N/2 \rfloor$ 个大的在前、后 $\lfloor N/2 \rfloor$ 个小的在后"，它**不要求每一块内部有序**！没有这个要求，就能把排序里一大堆步骤全省掉——只要前面那块里每个元素都比后面那块小就完全 OK。而这恰好就是 `partition` 干的事。

所以我们要找的，其实是**第 $\lfloor N/2 \rfloor$ 小的元素**。

```text
n = 8，找第 4 小的元素

轮 1   基准 = A[0]
       区间 [0 .. 7] ──partition──►  pivot 落在下标 1   （1 < 4）
       ⇒ 第 4 小只可能在右边，只在 [2 .. 7] 里继续

轮 2   基准 = 右半段里再挑一个
       区间 [2 .. 7] ──partition──►  pivot 落在下标 5   （5 > 4）
       ⇒ 第 4 小只可能在左边，只在 [2 .. 4] 里继续

轮 3   区间 [2 .. 4] ──partition──►  pivot 落在下标 4   （4 = 4）→ 停
```

规则就两条，全靠 pivot 的最终落点说话：

- 落点 `low` **小于** $\lfloor N/2 \rfloor$：要找的偏右，下一轮只在 `[low+1, high]` 里再做一次 `partition`；
- 落点 `low` **大于** $\lfloor N/2 \rfloor$：要找的偏左，下一轮只在 `[low, low-1]` 里再做。

而快排在这之后是要**递归**下去把两边都排好的，我们不想排序，只要找到中间那个基准元素就够了。所以这里用一个 `while` 循环来代替递归——是**用一个循环改造整个 `QuickSort` 的外层，而不是只用一次 `partition`**。

```c
/* 用 while 代替递归改造 QuickSort 外层：只求第 n/2 小的元素，不做全排序 */
int setPartition2(int A[], int n)
{
    int low = 0, high = n - 1;
    int new_low = 0, new_high = n - 1;   /* 下一轮的区间端点 */
    int flag = 0;                        /* 1 = 已找到 */

    while (flag == 0) {
        low = new_low;                   /* 把上一轮存下来的区间端点取回来 */
        high = new_high;

        int pivot = A[low];              /* 临时变量把基准存住 */
        while (low < high) {
            while (low < high && A[high] > pivot) high--;
            A[low] = A[high];            /* high 找比基准小的，挪到 low 位置 */
            while (low < high && A[low] < pivot) low++;
            A[high] = A[low];            /* low 找比基准大的，挪回 high 位置 */
        }
        A[low] = pivot;                  /* 相遇，基准归位 */

        if (low == n / 2) {
            flag = 1;                    /* 落在中间，划分完成 */
        } else if (low < n / 2) {
            new_low = low + 1;           /* 目标在右边 */
            new_high = high;
        } else {
            new_low = low;
            new_high = low - 1;          /* low == high，目标在左边 */
        }
    }
    /* 走到这里，A 的前 n/2 个就是最大的那 n/2 个 */
}
```

`new_low` / `new_high` 这两个变量是**必须**的。函数主体里算的全是当前轮的 `low` / `high`，而下一轮要换一套端点，又不能直接把当前轮的值覆盖掉（它们还是判断依据），所以得先把新端点存到外面，等循环回来再赋给 `low` / `high`。

> **提示**：官方答案里会出现 `low0` 和 `high0`（排版容易被看成 `l_0`、`h_0`），看到这个不要疑惑——它们和这里的 `new_low` / `new_high` 作用完全一样，保存的都是"下一轮的区间端点"。

每轮把范围砍掉一半，这和折半查找的思路一模一样，只是我们不用全排序，只排出我们需要的那一个部分。时间复杂度比较依赖序列的状态：如果每次选到的基准都靠边，到达中间位置可能还需要 $O(n)$ 级别。所以题面问**平均**时间复杂度时可以写成 $O(n\log n)$。

> **易错点**：解法二**做不到去重**。它没有遍历所有元素，所以没法一边划一边判重复。真要同时满足"不相交"和"高效"，只能走解法一那条"先排序、再去重、再分割"的 $O(n\log n)$ 路线——这也是这道题最终该走的路子。在"不遍历所有数组去找基准元素"这个前提下，是做不到一边找一边去重的。

### 推广到第 $k$ 小

这个思路的通用版本是：**给定一个序列，找出其中第 $k$ 小的元素。**

上面的题只是把 $k$ 固定在了中点上；一旦 $k$ 换成 1、2、3…… 任何值，思路一字不改：

```text
  区间 [low, high]，基准落点 p

      p == k   →  找到，A[p] 就是第 k 小，结束
      p <  k   →  目标偏右，区间收到 [p+1, high]
      p >  k   →  目标偏左，区间收到 [low, p-1]

  外层用 while 代替递归，每轮区间砍掉一半
```

求**第 $k$ 大**元素同理，把比较方向反过来即可。最终答案就是划分结束后位于下标 $k$ 的那个元素。

> **结论**：**快排 partition 的本质是"每轮把一个元素钉到最终位置上"**。快排用递归把这件事做 $n$ 遍，得到完整排序；快速选择只用 `while` 做它一次，就得到第 $k$ 小。差别只在"递归 vs 循环"这一个字符上。

```c
/* 直接插入排序 */
void InsertSort(int A[], int n)
{
    for (int i = 1; i < n; i++) {
        int tmp = A[i];                  /* 把待插入的元素"挖"出来 */
        int j = i - 1;
        while (j >= 0 && A[j] > tmp) {   /* 严格大于才挪 —— 稳定的来源 */
            A[j + 1] = A[j];
            j--;
        }
        A[j + 1] = tmp;
    }
}

/* 折半插入排序：比较折半，移动照旧。结果与直接插入完全一致 */
void BinaryInsertSort(int A[], int n)
{
    for (int i = 1; i < n; i++) {
        int tmp = A[i];
        int low = 0, high = i - 1;
        while (low <= high) {            /* 在 A[0..i-1] 里折半找插入点 */
            int mid = low + (high - low) / 2;
            if (A[mid] > tmp) high = mid - 1;
            else              low = mid + 1;
        }
        for (int j = i - 1; j >= low; j--)
            A[j + 1] = A[j];             /* 位置找到了，搬还是要搬 */
        A[low] = tmp;
    }
}

/* 希尔排序 */
void ShellSort(int A[], int n)
{
    for (int d = n / 2; d >= 1; d /= 2) {
        for (int i = d; i < n; i++) {
            int tmp = A[i];
            int j = i - d;
            while (j >= 0 && A[j] > tmp) {
                A[j + d] = A[j];
                j -= d;
            }
            A[j + d] = tmp;
        }
    }
}
```

```c
/* 冒泡排序（带 flag 提前退出） */
void BubbleSort(int A[], int n)
{
    for (int i = 0; i < n - 1; i++) {
        int flag = 0;
        for (int j = 0; j < n - 1 - i; j++) {
            if (A[j] > A[j + 1]) {
                int t = A[j]; A[j] = A[j + 1]; A[j + 1] = t;
                flag = 1;
            }
        }
        if (flag == 0) break;
    }
}

/* 三数取中：把首、中、尾的中位数放到区间首位，压住快排的最坏情况 */
int MedianOfThree(int A[], int low, int high)
{
    int mid = low + (high - low) / 2;
    if (A[low] > A[mid]) { int t = A[low]; A[low] = A[mid]; A[mid] = t; }
    if (A[low] > A[high]) { int t = A[low]; A[low] = A[high]; A[high] = t; }
    if (A[mid] > A[high]) { int t = A[mid]; A[mid] = A[high]; A[high] = t; }
    return A[mid];
}

/* 快速排序：Partition + 递归 */
int Partition(int A[], int low, int high)
{
    int pivot = A[low];
    while (low < high) {
        while (low < high && A[high] >= pivot) high--;
        A[low] = A[high];
        while (low < high && A[low] <= pivot) low++;
        A[high] = A[low];
    }
    A[low] = pivot;
    return low;
}

void QuickSort(int A[], int low, int high)
{
    if (low >= high) return;
    int pos = Partition(A, low, high);
    QuickSort(A, low, pos - 1);
    QuickSort(A, pos + 1, high);
}

/* 快排的数组版本，封装一下省得每次写区间 */
void QuickSortEx(int A[], int n) { if (n > 1) QuickSort(A, 0, n - 1); }
```

```c
/* 简单选择排序 */
void SelectSort(int A[], int n)
{
    for (int i = 0; i < n - 1; i++) {
        int min = i;
        for (int j = i + 1; j < n; j++)
            if (A[j] < A[min]) min = j;
        if (min != i) { int t = A[i]; A[i] = A[min]; A[min] = t; }
    }
}

/* 下沉调整：把 A[i] 沿大孩子方向往下放 */
void SiftDown(int A[], int i, int n)
{
    while (2 * i + 1 < n) {
        int child = 2 * i + 1;
        if (child + 1 < n && A[child + 1] > A[child]) child++;
        if (A[i] >= A[child]) break;
        int t = A[i]; A[i] = A[child]; A[child] = t;
        i = child;
    }
}

/* 堆排序 */
void HeapSort(int A[], int n)
{
    for (int i = n / 2 - 1; i >= 0; i--) SiftDown(A, i, n);   /* 建大顶堆 */
    for (int k = n - 1; k > 0; k--) {
        int t = A[0]; A[0] = A[k]; A[k] = t;
        SiftDown(A, 0, k);
    }
}
```

```c
/* 归并排序：辅助数组按需申请 */
void MergeSort(int A[], int n)
{
    int *temp = (int *)malloc(n * sizeof(int));
    for (int width = 1; width < n; width *= 2) {   /* 段长逐层翻倍 */
        for (int lo = 0; lo + width < n; lo += 2 * width) {
            int mid = lo + width - 1;
            int hi = lo + 2 * width - 1;
            if (hi > n - 1) hi = n - 1;
            int i = lo, j = mid + 1, k = lo;
            while (i <= mid && j <= hi) {
                if (A[i] <= A[j]) temp[k++] = A[i++];   /* 相等取左，稳定 */
                else               temp[k++] = A[j++];
            }
            while (i <= mid)  temp[k++] = A[i++];
            while (j <= hi)   temp[k++] = A[j++];
            for (int t = lo; t <= hi; t++) A[t] = temp[t];
        }
    }
    free(temp);
}

/* 计数排序：不稳定版（<），改 <= 即稳定 */
void CountSort(int A[], int B[], int N)
{
    int *count = (int *)malloc(N * sizeof(int));
    for (int i = 0; i < N; i++) count[i] = 0;
    for (int i = 0; i < N - 1; i++)
        for (int j = i + 1; j < N; j++) {
            if (A[i] <= A[j]) count[j]++;      /* 改成 < 就变成不稳定 */
            else              count[i]++;
        }
    for (int i = 0; i < N; i++)
        B[count[i]] = A[i];
    free(count);
}
```

## 把这一篇收成几句可以背的话

1. **九种内部排序，六个 $O(1)$ 空间**（直接插入、折半插入、希尔、冒泡、简单选择、堆），**快排 $O(\log n)$、归并 $O(n)$、基数 $O(r)$**。
2. **稳定的判据只有一条**：相等元素有没有可能落到对方前面去。稳定的是直接插入、折半插入、冒泡、简单选择、归并、基数、计数；不稳定的是希尔、快排、堆排序。
3. **一次交换 = 三次移动**。比较、移动、交换是三个数，别混着写。
4. **折半插入和直接插入的过程完全一样**，只有比较次数不同（$O(n\log n)$ vs $O(n^2)$）。
5. **由两趟结果反推算法**：基数看低位优先、归并看有序前缀翻倍、希尔看增量分组、快排看分界线；最后拿增量序列能不能拼成一条合法的（末位为 1）来定案。
6. **置换选择排序**：输出即补读，归并段长短不一；**第一个段最长 $N$、最短 $M$**；段数少 → 归并趟数少 → 磁盘 I/O 少。
7. **集合划分**：排序 + 去重 + 分割才满足"不相交"；借 `partition` 只求第 $\lfloor N/2 \rfloor$ 小更快，但做不到去重。外层把递归换成 `while`，就成了快速选择。
