# 树与二叉树的结构与应用

树这一块在 408 里的位置很特殊：它不像排序那样年年考算法，也不像图那样年年考算法复杂度。它考的是**性质**——你能不能把一条性质立刻翻译成一个数字；它考的是**形态**——给你一个残缺的信息，你能不能反推出整棵树的骨架；它考的是**编码**——它跟信息论、跟实际工程贴得最近。

所以复习树，别一上来就背定义。把历年真题翻一遍，你会发现真正反复出现的就那么几个动作：列一条等式、把树补成满的、还原遍历序列、算路径条数、把权值往里塞。每一个动作背后都立着一条性质，性质不熟，动作就做不出来。

我们按知识点横着梳理一遍，每一节都是「判定方法 → 计算公式 → 解题套路 → 易错点」这个顺序。年份用括注标出来，是告诉你这个点被考过几次、你该花多少力气。

## 树与二叉树的基本性质

### 结点数、边数与度数的关系

这是整棵章节的地基，后面所有的计数题都从它出发。

> **定义**：树的结点数等于所有结点度数之和加一。记结点总数为 $n$，结点 $v$ 的度为 $d(v)$，则

$$n = 1 + \sum_v d(v) \qquad\text{等价于}\qquad n - 1 = \sum_v d(v) = \text{总边数}$$

> **结论**：叶结点就是度为 $0$ 的结点。问叶结点个数之所以好算，正是因为它的度是 0，在等式右边不出现，只能出现在左边——这样才构成一元一次方程。

为什么是这个式子？换个角度理解更好记：每个结点都是靠一根边挂上来的，唯独根不是靠边进来的，所以边永远比结点少一个。

真题里它以三种面貌出现：

- **10 年**：给一棵度为 4 的树，度为 4 的结点 20 个、度为 3 的 10 个、度为 2 的 1 个、度为 1 的 10 个，求叶结点个数。列式 $n = 20\times4 + 10\times3 + 1\times2 + 10\times1 + 1 = 123$，再减去已知的 $41$ 个结点，得 $n_0 = 82$。
- **16 年**：把定义换成「正则 $K$ 叉树」——除叶结点外每个结点都有 $K$ 个孩子。$M$ 个非叶结点撑起的叶结点数是 $M(K-1)+1$。
- **16 年、22 年**：反过来问，$244$ 个结点的三叉树高度至少是多少。这就要满 $M$ 叉树的公式。

```text
  一棵有 5 个结点的树：

         o           <- 根，有 2 个孩子，度 = 2
        / \
       o   o         <- 两个中间结点，各有 1 个孩子，度 = 1
      /     \
     o       o       <- 两个叶结点，度 = 0

  度数和 = 2 + 1 + 1 + 0 + 0 = 4
  边数   = 4
  结点数 = 4 + 1 = 5   ✓
```

> **易错点**：「度为 4 的树」**不是**说每个结点的度都等于 4。它的意思是：树中至少存在一个度为 4 的结点，且所有结点的度都不超过 4。这个坑 10 年直接挖过。

### 森林：棵数就是结点数减边数

16 年那道 15 条边 25 个点的题，答案是 10 棵树。推法就是把上面的等式对每棵树列一遍再相加：

$$n_1 + n_2 + \cdots + n_x = e_1 + e_2 + \cdots + e_x + x \quad\Longrightarrow\quad 25 = 15 + x \quad\Longrightarrow\quad x = 10$$

> **结论**：一棵森林的结点数减边数，等于森林中树的棵数。理解上：树比边多出来的那一个「1」，每一棵树各贡献一次，而森林有多少棵树就有多少个根没有边拴着。

### 二叉树：叶结点数 = 度为 2 的结点数 + 1

把上面的式子在二叉树上移项，就得到这一条几乎是必考的结论。

> **定义**：二叉树中度为 0、1、2 的结点数分别记 $n_0, n_1, n_2$。

$$n = n_0 + n_1 + n_2 = n_1 + 2n_2 + 1 \quad\Longrightarrow\quad \boxed{n_0 = n_2 + 1}$$

> **结论**：$n_0 = n_2 + 1$，和 $n_1$ 完全无关。

> **易错点**：这条式子来自「总结点数 = 总度数 + 1」，而二叉树总度数 $= n_1 + 2n_2$。你如果想验证，就自己拿一棵最小的二叉树代进去：根带两个孩子，$n_0 = 2$、$n_2 = 1$，$2 = 1 + 1$，成立。

### 满 $M$ 叉树的结点数与高度的上下界

这是 16 年和 22 年共同考的公式，务必现场能推。

> **定义**：高度为 $h$ 的满 $M$ 叉树，第 $i$ 层结点数是 $M^{i-1}$，总结点数是等比数列求和。

$$\text{满} M \text{ 叉树、} h \text{ 层} = 1 + M + M^2 + \cdots + M^{h-1} = \frac{M^{h} - 1}{M - 1}$$

二叉树是 $M=2$ 的特例：$\dfrac{2^h-1}{2-1} = 2^h - 1$。

反过来，**给定结点数求高度的上下界**（22 年 244 个结点、16 年 $H$ 层上下界）：

| 问法 | 结论 | 做法 |
| --- | --- | --- |
| 结点数已定，求高度的**最小**值 | 尽量把它长成满的 | 找一个最小的 $h$ 使 $\frac{M^h-1}{M-1} \ge$ 给定结点数 |
| 高度已定，求结点的**最**少 | 长成单支树再补足正则性 | 根 1 个 + 每层 $K$ 个实心结点 |
| 高度已定，求结点的**最**多 | 满 $M$ 叉树 | 直接套 $\frac{M^h-1}{M-1}$ |

16 年那道「高度为 $H$ 的正则 $K$ 叉树」：

```text
             ●              第 1 层：根，1 个结点
           / | \
          ●  ●  ●           第 2 层：K 个结点，只有最左边那个继续往下
         / |
        ● ● ●              第 3 层：K 个结点
        ⋮
        ⋮                  一直这样挂到第 H 层

  结点数 = 1（根） + K × (H - 1)
```

$$\text{最多} = \frac{K^{H}-1}{K-1}, \qquad \text{最少} = K(H-1)+1$$

> **易错点**：最少的那种，画图时容易只画一条链然后忘了「正则」这个约束。记住：链上除了最后一个结点，其余每个结点都必须再挂上 $K-1$ 个孩子——实心的那个孩子要留着，剩下 $K-1$ 个位置补兄弟结点。少了这一步，结点数就少算了。

## 完全二叉树：特征、性质与数字敏感度

完全二叉树是考频最高的特殊形态。16 年 42 题、09 年选择题、11 年选择题、18 年选择题、25 年选择题都拿它出过手。

### 形态特征：从满二叉树右侧往前抠

> **定义**：完全二叉树是「能塞满就塞满，只允许在最后一层从右往左挖掉若干结点」的二叉树。做层序编号（从 1 开始）之后，它和对应的满二叉树编号一一对应，中间不会出现空位。

```text
  满二叉树编号：              完全二叉树编号（抠掉最后 3 个）：

              1                            1
           /     \                      /     \
          2       3                    2       3
        /  \     /  \                /  \     /
       4    5   6    7              4    5   6

  完全二叉树的关键性质：除了最后一层，前 h-1 层都是满的
```

> **结论**：完全二叉树中度为 1 的结点数**要么 0、要么 1**，不可能更多。25 年那道题问「完全二叉树不存在度为 1 的结点」，直接错——它存在，而且只有最后面那一个结点可能是。

### 叶结点的奇偶公式

> **结论**：完全二叉树总结点数为 $N$ 时

$$\text{叶结点数} = \begin{cases}\dfrac{N+1}{2}, & N \text{ 为奇数}\\[6pt] \dfrac{N}{2}, & N \text{ 为偶数}\end{cases}$$

推导链条要能默写出来：从树的性质 $n = 1 + \sum d$ 出发，$N = n_0+n_1+n_2$ 且 $N = n_1+2n_2+1$，移项得 $n_0 = n_2+1$，于是 $N = 2n_0 + n_1 - 1$。$n_1$ 只能 0 或 1，于是 $n_1=0$ 时 $N=2n_0-1$（奇数，$n_0=\frac{N+1}{2}$），$n_1=1$ 时 $N=2n_0$（偶数，$n_0=\frac N2$）。

11 年那道 768 个结点的题：768 是偶数，落第二种情况，$n_0 = 384$。

> **提示**：可以背结论，但一定要知道它从哪来。这条推导链把「普通二叉树性质」和「完全二叉树特殊性质」串起来了，是整章最值得推一遍的地方。

### 叶结点只在最后一层或倒数第二层

这条是「最多多少个结点」类题目的入口。

> **结论**：完全二叉树的叶结点只可能出现在**最后一层**（此时它是满二叉树）或**最后两层**。

**高频题型：已知第 $k$ 层有 $m$ 个叶结点，求总结点数最多是多少**（09 年考过，第 6 层 8 个叶结点）。

套路固定：

1. 问「最多」就取最大的高度——第 $k+1$ 层存在，第 $k$ 层是倒数第二层。
2. 第 $k$ 层共有 $2^{k-1}$ 个结点（$k=6$ 就是 32 个），其中 $m$ 个是叶结点，剩下 $2^{k-1}-m$ 个是非叶结点。
3. 非叶结点每个带两个孩子，全都落在第 $k+1$ 层。
4. 前 $k$ 层是满二叉树，结点数 $2^k - 1$。

```text
  L7  ############################        48
  L6  ################################    32   = 2^5，其中 8 个是叶结点
  L5  ################                16   = 2^4
  ...
  L1  #                                   1

  第六层的叶节点        : 8
  第六层的非叶节点      : 32 - 8 = 24   （每个都带 2 个孩子）
  第七层的节点数        : 24 × 2 = 48
  总节点数              : (2^6 - 1) + 48 = 63 + 48 = 111
```

> **易错点**：第 $k+1$ 层的结点数有两个可能：$2(2^{k-1}-m)$ 和 $2(2^{k-1}-m)-1$。少一个的那个情形是：倒数第 $k$ 层最右边的那个非叶结点只有一个左孩子。题目问「最多」取大的那个，问「最少」才取小的那个。09 年问的正是「最多」。

### 叶结点同层 ⇒ 直接是满二叉树

18 年那道题：一棵非空完全二叉树，所有叶结点在同一层，且每个非叶结点都有两个孩子，问总结点数。

> **结论**：条件已经多余了。只要「完全二叉树的叶结点全在同一层」，它就必然是满二叉树——完全二叉树一旦出现两层都有叶结点的情况，就说明最后一层没填满，叶结点就不齐。

设叶结点 $k$ 个、高度 $h$：$2^{h-1} = k$，总结点数 $2^h - 1 = 2k - 1$。

> **提示**：这类题能不能秒解，完全取决于两件事：能不能把「完全二叉树」这几个字推成「满二叉树」，以及满二叉树那两个公式（$2^h-1$、第 $i$ 层 $2^{i-1}$）是不是张口就来。两个都能，解题过程就是空的；公式不熟，这道题会做得很痛苦。

## 二叉树的四种遍历

### 三种深度优先 + 一种广度优先

> **定义**：以根为 $N$、左子树为 $L$、右子树为 $R$：

| 名称 | 访问顺序 | 根的位置 |
| --- | --- | --- |
| 先序（前根） | $N \to L \to R$ | 第一个 |
| 中序 | $L \to N \to R$ | 中间 |
| 后序（后根） | $L \to R \to N$ | 最后一个 |
| 层序（广度） | 按层从左到右 | 第一个 |

09 年还考过一道题：题目给了 N（根）、L（左子树）、R（右子树）的自定义遍历顺序问是哪一种。答案是 RNL——右在前、左在后。

> **易错点**：真题会给你**我们没教过的遍历方式**。这时候不要跟教材较劲，也不要怀疑题目出错了。观察序列里根出现在哪、左右子树谁在前，把它归到「N 的位置 + 左右次序」这两件事上，就能定下来。09 年那题的四棵子树都是 RNL。

### 遍历序列能推出什么性质

这一块的选择题特别爱挖「给定两个序列的关系，反推树的结构」。

**先序与后序相反**（11 年考过）：

> **结论**：先序序列与后序序列完全相反 $\iff$ 这棵树是一棵**单支树**（每个结点都没有左子树，或者每个结点都没有右子树）。

推法：如果左右子树同时存在，因为左永远在前、右永远在后，两个序列取到的区域不可能相反。剩下的可能只有两种：「根—左—左子树」（全体无右子树）和「右子树—右—根」（全体无左子树）。

单支树的中序序列有什么特征？

> **结论**：根永远处在当前子树序列的**一端**——要么最左端，要么最右端。判断时逐层往下看：根在一端 → 这层过；剩下的子序列再取根，还得在一端。

**先序与中序相同**（17 年考过）：

> **结论**：先序 = 中序 $\iff$ 每个非叶结点都**只有右子树**。

理由很干净：在先序里左子树排在根**后面**，在中序里左子树排在根**前面**，方向完全相反。所以只要某个结点有左子树，序列就不可能相同；把所有左子树去掉，就相等了。

```text
   先序 == 中序  <=>  每一层都只剩右孩子

          R
           \
            R
             \
              R
               \
                R

   先序: R R R R R R
   中序: R R R R R R
```

> **提示**：先中相同、先后相同、中后相同，以及它们两两相反，这六种情况都要会推。推法是统一的：把两个序列并排写出来，看哪一段没能符合相同或相反，然后推断出这棵树的共同特征。

### 由遍历序列还原二叉树

**核心结论：先序 + 中序、后序 + 中序、层序 + 中序，任意一对都能唯一确定一棵二叉树。**

> **结论**：只有中序能起到「定边界」的作用。因为只有中序能告诉你左右子树各占多少个结点，从而在另一个序列里把范围切开。

**为什么必须是中序？** 举 12 年那道题就懂了：只给先序和后序，根能确定（先序第一个 = 后序最后一个），紧跟根的 $E$ 一定是根的孩子（先序里是左子树的根，后序里是右子树的根，两边都指向「根的孩子」这个结论），但**左右定不了**——剩下那些结点有可能全落在 $E$ 的右子树，也可能分到 $E$ 的左子树和根的右子树里去。分界线画不出来，形态就不唯一。

**但是有两个例外情形要记住：**

- **给了树形，就等于给了中序**。17 年那道题给了树形 + 后序序列，结论是「树形本身就扮演了中序序列的角色」，照样能还原。
- **有树形 + 任意一个序列**，理论上都能还原；后序配合「根在最后」这个特性，还原起来尤其顺手（23 年考过）。

**还原的标准流程**（后序为例）：

1. 后序最后一个是根。
2. 根之前那一段（如果只够一棵子树）就是右子树，它的前一个元素就是右子树的根；更一般地，利用树形或中序确定左右各多少个。
3. 对每一段子树递归重复。

```text
  给定后序序列   D  B  C  A
  配树形：

        A
       / \
      B   C
       \
        D

  还原步骤：
  ① 最后一个是 A  -> A 是根
  ② A 只有右子树（C）-> 根往前第一个是 C，C 是右孩子
  ③ 剩下 D B 这一段是左子树的后序 -> 段尾 B 是 A 的左孩子
  ④ D 是 B 的唯一孩子，且 D 出现在 B 之前 -> D 是 B 的右孩子
```

> **提示**：考场上**不要一上来就完整还原**。先看已知的那个序列能排掉哪些选项——后序找根、先序找根，中序找分界——能排两三个就直接选了，剩下时间再回头练基本功。

### 层序遍历与二叉树的宽度

层序就是「一层一层、从左到右」，实现上是队列。14 年那道算 WPL 的题就借用了这个骨架：不传 `deep` 参数，改成用一个局部变量记层数，`for` 循环每处理完一层就加一。

> **易错点**：层序遍历不是深度优先的代名词。图上的 BFS 和树的层序是同一件事：第 0 层是起点，第 1 层是起点的全部邻接点，以此类推。13 年那道题有个选项给了 A→B→C→D 这种一条道走到黑的序列，那是 DFS，不是 BFS。

## 线索二叉树

### 线索化：把空指针利用起来

$n$ 个结点的二叉链表中，有 $2n$ 个指针域，其中只有 $n-1$ 个指向孩子，剩下 $n+1$ 个是空的。把这些空指针改成指向遍历序列里的前驱和后继，就得到了线索二叉树。

> **定义**：中序线索二叉树中，结点 $p$ 的**左指针**在它没有左孩子时指向它的**中序前驱**，**右指针**在它没有右孩子时指向它的**中序后继**。`ltag` / `rtag` 就是用来区分「这条指针是孩子还是线索」的标志位（0 表示孩子，1 表示线索）。

```text
  为什么要线索：一棵只有根和左孩子的单支二叉树

        A
       /
      B

  B 的左右指针都空着；中序序列是 B A，
  所以 B 的右线索该指向 A —— 这条信息本来就在遍历顺序里，白扔了可惜
```

### 解题套路：四步走

线索二叉树的题目几乎都是同一个流程（10 年、13 年各考过一次）：

```text
  第一步：问的是哪边的线索？
          左线索 = 前驱，右线索 = 后继

  第二步：确认这个结点有没有孩子
          有孩子的那一侧，指针就是孩子、不是线索，不参与判断
          两边都没有（叶结点）则两条都是线索

  第三步：确定是哪一种遍历
          中序线索看中序，后序线索看后序
          —— 这一步决定了要去算哪一个序列的前驱/后继

  第四步：老老实实把那个序列排出来，读答案
```

**10 年那道后序线索二叉树**，树是 $A$ 为根、$B$、$C$ 为孩子、$D$ 是 $B$ 的右孩子：

```text
        A
       / \
      B   C
       \
        D

  postorder:  D B C A
```

后序序列排出来是 $D\,B\,C\,A$。然后逐个结点挂线：

```text
  D : left  -> NULL     (没有前驱)
      right -> B        (后序后继)
  B : left  -> D        (孩子)
      right -> D        (线索，指向后序前驱)
  C : left  -> B        (线索，后序前驱)
      right -> A        (线索，后序后继)
  A : left  -> B        (孩子)
      right -> C        (孩子)
```

> **易错点**：$B$ 有左孩子 $D$，所以 $B$ 的**左指针是指向孩子的实线、不是线索**；只有它没孩子的那一侧才挂线。$B$ 的后继是 $C$，但它没有右孩子，所以右指针改挂成线索、指向它的**后序前驱** $D$。这一处是最容易画错的地方。

### 后序线索的右线索指向双亲

13 年那道题是个典型的直接问法：$X$ 是叶结点且有左兄弟 $Y$，问 $X$ 的右线索指向谁。

```text
            A
           / \
          B   C
         / \
        D   X
         \
          E

   中序序列：D  E  B  X  A  C
```

$X$ 是叶结点，两条线索都成立，所以答案就是 $X$ 在中序序列中的前驱和后继：前驱是 $B$，后继是 $A$。中序题的答案是左右两个。

如果题目改成**后序**线索，答案就换成双亲结点了。原因是：后序是「左、右、根」，$X$ 作为双亲的右子树被访问完，下一个访问的就是双亲本身。而左兄弟 $Y$ 在后序里永远排在 $X$ 前面，不可能是后继。

> **结论**：后序线索二叉树中，任一叶结点的右线索都指向它的**双亲结点**。这个结论可以直接背，因为它的证明只有一句话：后序访问完一棵子树，下一个必然是这棵子树的根。

### 线索树省掉了头指针

普通二叉树要有头指针才能遍历整棵树（否则会漏掉最后一个结点），线索二叉树不需要——因为最后一个结点的右线索指向头结点，首尾自环了。

> **提示**：还有一个高频问法是「线索二叉树能不能在 $O(1)$ 时间内求前驱后继」。答案是分情况：中序线索下，若该结点有右孩子，则后继就是右子树中最左下的结点；后序线索下则更麻烦，因为后序线索**没法顺着往下走**，求前驱后继通常仍要借助栈或从根重新遍历。这一点问过 23 年网络题的复合场景，记住结论就行。

## 哈夫曼树与哈夫曼编码

这是树这一块跟工程贴得最近的部分，17 年、18 年、20 年、21 年、22 年、23 年、25 年全考过，形式包括选择题、代码题、应用题。

### 构造过程：只有一句话

> **定义**：WPL（带权路径长度）最小的二叉树就是**哈夫曼树**，也叫最优二叉树。

> **结论**：构造方法只有一句——**每次从当前权值集合中挑出最小的两个，合并成它们的和，再放回集合里**，重复到只剩一个为止。

```text
  权值 10 12 16 21 30

  10 + 12  = 22     集合变为：16 21 22 30
  16 + 21  = 37     集合变为：22 30 37
  22 + 30  = 52     集合变为：37 52
  37 + 52  = 89     完成

                         (89)
                       /      \
                   (37)       (52)
                  /   \      /   \
               [16] [21]   [30]  (22)
                                /   \
                             [10]  [12]
```

### 判定与性质

从构造过程能直接推出一堆结论，选择题基本都在这些描述里绕圈子。

| 说法 | 判定 | 依据 |
| --- | --- | --- |
| 哈夫曼树是（某棵）完全二叉树 | **错** | 形态不唯一，1/2/3/4 能构出不相同的树 |
| 哈夫曼树中没有度为 1 的结点 | **对** | 每个父结点都由两个结点合并而来，度必为 2 |
| 权值最小的两个结点一定是兄弟 | **有前提才对** | 前提是「权值均不相同」；权值有并列时不成立 |
| 非叶结点权值不小于它下面一层任意结点 | **对** | 父结点权值 = 两个孩子之和，自下而上单调不减 |
| 待编码字符全部是叶子 | **对** | 前缀特性要求它不能成为别的编码的前缀 |
| $N$ 个字符编码，总结点数是 $2N-1$ | **对** | $N$ 个叶结点 + $N-1$ 个分支结点（19 年考过，$2N-1=115 \Rightarrow N=58$）|

> **易错点**：「权值最小的两个是兄弟」这条千万别记成无条件成立。权值是 1、1、1、2、3、4 时，三个 1 并列最小，挑哪两个合并有多种可能，挑出来的那两个未必是兄弟。这道坑 10 年挖过。

> **易错点**：题面用「可能」二字的地方，不要拿自己构造的结果去对答案（18 年）。哈夫曼树形态不唯一（权值有并列时）、编码左 0 右 1 还是左 1 右 0 也没规定，所以「可能是某编码」只能**去找必然成立的特征**：频次大的字符编码长度不可能长（先按长度排）、频次最小且权值互异的两个字符必然是兄弟（从根到它们的路径除最后一位完全相同）。

### WPL 一定要数路径条数

> **定义**：叶结点的带权路径长度 = 该叶结点的路径长度 × 权值；整棵树的 WPL = 所有叶结点的带权路径长度之和。非叶结点不参与求和。

$$\text{WPL} = 16\times2 + 21\times2 + 30\times2 + 10\times3 + 12\times3 = 32+42+60+30+36 = 200$$

还有一个等价的算法：

> **结论**：WPL 等于**所有分支结点的权值之和**。上面那棵树就是 $22+37+52+89 = 200$，与逐个叶结点算的结果一致。

两种算法的来历都是同一个：把「叶子权值 × 路径长度」的乘法展开成加法，一个权值被乘几次就加几次。12 年那道最佳归并树用的就是第二种算法。

> **易错点**：**一定要数路径条数，绝不能靠看图。** 随手画的哈夫曼树往往是个 Y 形，视觉上会觉得「这几个点好像在同一层」，路径就数错了。路径长度的定义是从根到该叶结点中间的**边数**——根自己作为叶结点时路径是 0，不贡献任何东西。

### 加权平均编码长度（23 年）

> **定义**：加权平均长度 $=\sum \dfrac{\text{该字符频次}}{\text{总频次}} \times \text{该字符的编码长度}$。

这跟 WPL 不是一回事。WPL 是权值乘路径长度的**绝对和**；加权平均长度还要除以总频次，做了一次概率化。

23 年那道题六个字符频次是 $3,4,5,6,8,10$，总频次 36，构造出的哈夫曼树里频次 8 和 10 的两个编码长 2，其余四个编码长 3：

$$3\times\left(\tfrac{3}{36}+\tfrac{4}{36}+\tfrac{5}{36}+\tfrac{6}{36}\right) + 2\times\left(\tfrac{8}{36}+\tfrac{10}{36}\right) = 1.5 + 1 = 2.5$$

> **提示**：画哈夫曼树时给结点区分形状——叶结点画方框、中间生成的父结点画圆圈，或者一个画一个不画。树画到后面全是圆圈，谁是谁根本分不清，WPL 和编码长度就都算不对了。

### 前缀特性与译码（20 年、17 年）

> **定义**：如果任意字符的编码都不是其他字符编码的前缀，称这种编码具有前缀特性（前缀编码）。哈夫曼编码天生满足这个性质。

**译码**（20 年考过三问中的一问）：约定左 0 右 1，从根开始逐位扫描比特串，每一位按 0 左移、1 右移，**走到叶结点就输出该叶结点保存的字符，然后回到根**继续读下一段。

```text
比特串 = 110 01 110 01
从根节点开始，约定左 0 右 1，逐位从左到右扫描：

  110 → 右、右、左 → 到叶节点 → 输出 A
  01  → 左、右     → 到叶节点 → 输出 B
  110 → 右、右、左 → 到叶节点 → 输出 A
  01  → 左、右     → 到叶节点 → 输出 B

译出：ABAB
```

**判定一套给定编码是否具有前缀特性**（20 年最难的一问）：注意，这里是「树还没有，该不该有」，不是「树已经有了怎么用」。所以**不能**写「构造哈夫曼树，能构造出来就具有前缀特性」——当前根本没有哈夫曼树。

正确做法是**现场构造一棵二叉树**，然后看这套编码能不能长成一棵「所有字符都落在叶结点上」的树：

1. 依次读入每个编码，为它建立一条从根出发的路径。
2. 扫描每一位，按当前位是 0 还是 1 决定沿左还是沿右下移；遇到空指针就创建新节点。
3. 途中会撞到三种情况之一。

| 撞到什么 | 说明什么 | 判定 |
| --- | --- | --- |
| 位数没走完就走到了叶结点 | 这个编码是别的编码的前缀 | 不满足前缀特性 |
| 编码全部位走完，却一个节点都没创建 | 路径全是现成的，它只是别人的前缀 | 不满足 |
| 编码全部位走完，并创建了新结点 | 新路径顺利落地 | 通过，继续验证下一个 |

```text
把 A = 110 插进树里（从根出发，1 走右，1 再走右，0 走左）

  root
    └── 1 ──> n1
              └── 1 ──> n2
                        └── 0 ──> 叶节点(A)

再把 B = 01 插进去（0 走左，1 走右）

  root
    ├── 0 ──> n2' ──1──> 叶节点(B)
    └── 1 ──> n1 ──1──> n2 ──0──> 叶节点(A)
```

> **提示**：这里可以不真的把字符存进叶结点，只遍历路径就够了。因为前缀特性的定义是「任何编码都不是别的编码的前缀」，重点不在叶结点上写着什么字母，而在于**后面字符的构建会不会经过这个叶结点**。

> **易错点**：只背下「左 0 右 1、遇叶即停」这条规则，答案写出来是空的。规则必须落在「一段文本被逐字符替换成编码再连起来」这个场景上，阅卷的人才认得出你真的懂编码这回事。

### 哈夫曼树与最佳归并树

13 年、19 年、12 年都把这两个知识点放在一起考。它们关键词相同——WPL 最小——但约束不同。

> **结论**：哈夫曼树是**二叉**的，构造时两两合并，一定能构出来；**最佳归并树**是 $K$ 叉的，构造时有硬性要求，结点数不够必须补虚结点。

最佳归并树的虚结点公式（19 年考过：120 个初始归并段、12 路归并、补几个虚段）：

$$u = (M-1) \bmod (K-1), \qquad \text{虚段个数} = K - u - 1$$

代入：$(120-1) \bmod 11 = 119 \bmod 11 = 9$，虚段 $= 12-9-1 = 2$。

13 年那道三叉树 WPL 最小也是同一套：6 个叶结点、$(6-1)\bmod(3-1) = 5\bmod 2 = 1 \ne 0$，补一个权值为 0 的虚结点，然后按三叉规矩每次取最小三个合并。

```text
第一趟：0 + 2 + 3 = 5
第二趟：4 + 5 + 5 = 14      （两个 5：一个原始权值，一个是刚生成的）
第三趟：6 + 7 + 14 = 27     ← 根

WPL = (6+7)×1 + (4+5)×2 + (0+2+3)×3 = 13 + 18 + 15 = 46
```

> **提示**：外排序里的「归并段个数越少 I/O 次数越少」和哈夫曼是同一个思路的两条路——要么减少段数，要么加长每一段。12 年那道「六张有序表五次两两合并求最小比较次数」也是：把元素个数当权值构造哈夫曼树，每次构造就是一次归并。

## 树的表示与存储

### 树转二叉树：左孩子、右兄弟

这是整章最需要练到肌肉记忆的一条规则，没有之一（09 年、11 年、16 年、21 年、13 年全考过）。

> **结论**：树/森林转二叉树用**左孩子—右兄弟**表示法——森林中某结点的**第一个孩子**转成二叉树的**左孩子**，它的**右兄弟**转成二叉树的**右孩子**。

```text
  森林                                二叉树

   A          B──C                      A
   │                                    │
   D          D──E                      B     C
                                            │
                                            D     E

读图：森林里兄弟之间靠"谁在左边"来定先后（B 在 C 左边、D 在 E 左边）。
转成二叉树后，挨着父节点的第一个兄弟（B、D）变成左孩子，
后面的兄弟（C、E）就变成了它前一个兄弟的右孩子。
```

转回去的规则就一条：**左孩子直接变成第一个孩子，右孩子指针全部砍掉、变成右兄弟**。

```text
  还原：              森林里有 3 棵树：
    A                 第 1 棵根是 A
  ┌─┼─┐               第 2 棵根是 C
  B D C        F      第 3 棵根是 F
      │
      E
      │
      G
```

> **结论**：二叉树里**最右边那条分支上有几个结点，森林里就有几棵树**（21 年考过，$A \to C \to F$ 三个结点，三棵树）。一眼看穿的办法。

> **易错点**：森林里**没有左右之分**。判断谁是「第一个孩子」靠的是**顺序**（谁排在前面），不是左右。画森林的时候别因为习惯把小的画左边、大的画右边，那会误导自己。

### 遍历对应关系

> **结论**：树/森林的遍历与对应二叉树的遍历只有两条对应关系：

| 树 / 森林的遍历 | 对应二叉树的遍历 |
| --- | --- |
| 先根（先序）遍历 | 先序遍历 |
| 后根（后序）遍历 | 中序遍历 |

原理就藏在规则里：树的后序是「先访问所有孩子，再访问根」，转换之后这一坨孩子正好整体落在二叉树中序的「左子树」位置上——左子树里把各个孩子的后序走完，根排中间，右兄弟链排最后。这就是中序。

> **提示**：反向用法也要会——给了森林的先序和后根遍历，求二叉树的后序：先把它们看成对应二叉树的**先序和中序**，用这两个序列还原二叉树，再求它的后序。

### 一个必会的计数结论

11 年那道题：2011 个结点、116 个叶结点的树，转成二叉树后没有右孩子的结点有多少个。

二叉树的右孩子对应树里的右兄弟，所以问题变成「树中没有右兄弟的结点有多少个」。规律很干净：**任何一组孩子中，一定恰好产生一个没有右兄弟的结点，就是最右边那个。**

分支结点数 $= 2011 - 116 = 1895$，它们贡献 1895 个。但**根结点要单独加 1**——根不作为「孩子」参与上面那个统计，而它自己确实也没有右兄弟（要是有兄弟，那就不止一棵树了）。

> **结论**：树中无右兄弟的结点数 $=$ 分支结点数 $+$ 1。森林的情况也是加 1：不管森林里有几棵树，只有**最右边那棵树的根**没有右兄弟。

> **易错点**：加的那 1 就是这道题的全部陷阱所在。11 年直接把「只算 1895」当成答案，漏掉了根。

### 二叉树的链式存储

> **定义**：二叉链表结点含数据域和两个孩子指针。

```c
typedef struct BiTNode {
    int weight;                    /* 数据域；题目若只说权值，就写权值 */
    struct BiTNode *lchild, *rchild;
} BiNode, *BiTree;
```

> **提示**：定义别名这一步不是为了好看。`BiNode` 是结构体类型，`BiTree` 是它的指针类型，函数签名写起来干净，递归调用也不用每次都写 `struct BiTNode *`。而且**结构体的名字要提前定下来**——如果题目后面还要你给数据类型，先把名字敲定能省很多事。

### 二叉树的顺序存储

25 年选择题考过（此前从未以这个形态考过），22 年那道大题也是顺序存储。

> **定义**：二叉树的顺序存储按**完全二叉树的层序编号**来放。编号从 1 开始时，下标 $k$ 的结点左孩子是 $2k$、右孩子是 $2k+1$；下标从 0 开始时，左孩子是 $2k+1$、右孩子是 $2k+2$。

```text
完全二叉树的层序编号（从 1 开始）：

              1
           /     \
          2       3
        /   \   /   \
       4     5 6     7
```

非完全二叉树就必须**补全成完全二叉树**，不存在的结点位用一个标记（比如 -1 或 #）占位。

> **易错点**：**空结点下面不可能再有孩子。** 25 年那道题四个选项里，只有 D 是在空结点下面还挂了孩子，一眼就被否掉。另外，做题时可以用一个小技巧：按 A、D、B、C 的顺序验证——前面三个都对上了，D 为了保准还是画一遍，说不定第一个就发现它是错的那个。

顺序存储的代价也要知道：只适合**完全二叉树**。非完全二叉树补全之后空位会占掉大量空间，链式存储更合适。

## 树的遍历应用题套路

这一节是把前面的知识点组装成解题动作。历年大题基本都落在下面这几类。

### 递归是第一选择

> **结论**：14 年、17 年、22 年这三道二叉树大题，答案全都可以用递归实现。这个规律非常明显。拿到任何一道二叉树题，先想递归；递归实现不了再考虑非递归。

```c
/* 14 年：求二叉树的带权路径长度 WPL，deep 初值为 0 */
int WPL(BiTree root, int deep)
{
    if (root == NULL)
        return 0;

    /* 叶结点：路径长度 × 权值 */
    if (root->lchild == NULL && root->rchild == NULL)
        return root->weight * deep;

    int left  = WPL(root->lchild,  deep + 1);
    int right = WPL(root->rchild, deep + 1);
    return left + right;
}
```

14 年这道题里藏着两个坑，都在代码里体现了：

- **后序递归**而不是先序。因为要先把叶结点的值算出来、再加起来，必须先取到值。
- **路径 $\ne$ 层次**。根在第 1 层，但它的路径是 0，所以 `deep` 传的是**层次减一**，初值为 0。

```text
            (1)                 level 1, deep = 0
           /   \
         (2)   (3)               level 2, deep = 1
               |
             (5)                 level 3, deep = 2

  路径 = 层次 − 1，所以 (5) 的路径是 2、贡献 5×2
```

> **提示**：`deep` 是值传递、是每层的局部变量，所以递归回溯时它自然就减回去了，不用额外写还原语句。

### 二叉排序树判定：先想中序升序

22 年那道「判定顺序存储的二叉树是否为二叉搜索树」，两种解法都值得掌握。

> **结论**：二叉排序树的中序遍历序列是一个**升序序列**。反过来说，中序不是严格递增的，就一定不是二叉排序树。

> **易错点**：最经典的误区是「当前节点比左孩子大、比右孩子小，每个节点都符合就行」。这是错的——BST 要求的是**左子树上的所有结点都比根小、右子树上的所有结点都比根大**，不是只看父子两个。

**中序守门槛**（推荐）：保留一个变量记录「已遍历过的最大值」，当前值必须严格大于它。

```c
typedef struct {
    int data[MAXSIZE];   /* 顺序存储；不存在的节点用 -1 占位 */
    int num;             /* 实际元素个数 */
} SqBTree;

bool IsBST(SqBTree *T, int k, int *value)
{
    if (T->data[k] == -1)           /* 空子树当然算一棵合法的二叉搜索树 */
        return true;

    if (!IsBST(T, 2 * k + 1, value))  /* 左子树不满足，整体就不满足 */
        return false;

    if (T->data[k] <= *value)         /* 中序序列必须严格递增 */
        return false;
    *value = T->data[k];              /* 成为新的"前驱" */

    if (!IsBST(T, 2 * k + 2, value))
        return false;

    return true;
}
```

> **易错点**：条件是 `<=` 不是 `<`。二叉排序树不允许重复关键字，等于前驱同样不合法。很多人写顺手就把含重复值的树放过去了。传 `int *` 而不是 `int`，是为了让它在递归过程中不断更新、不随回溯还原。

**先序划区间**（另一条路）：存 `minValue` 和 `maxValue` 作为当前结点应处的开区间边界，当前结点是左子树的最大值（传作 `maxValue`）、是右子树的最小值（传作 `minValue`）。

```c
bool IsBST2(SqBTree *T, int k, int minValue, int maxValue)
{
    if (T->data[k] == -1)
        return true;

    if (T->data[k] <= minValue || T->data[k] >= maxValue)
        return false;

    return IsBST2(T, 2 * k + 1, minValue, T->data[k])   /* 当前节点是左子树的最大值 */
        && IsBST2(T, 2 * k + 2, T->data[k], maxValue); /* 当前节点是右子树的最小值 */
}
```

> **提示**：第三种非递归做法（多开两个辅助数组、从后往前反层次遍历）空间开销大、思路绕，不推荐。前两种递归足够应付真题。

### 二叉排序树的删除与再插入

19 年、13 年都从「删掉再插回来」这个动作出过错题。关键是**二叉排序树删除后不需要调整，平衡二叉树需要**。

> **结论**：二叉排序树的删除只有三种情形——删叶结点直接删；删只有一个孩子的非叶结点，让孩子顶上；删左右孩子都有的非叶结点，让前驱或后继顶替。而**插入永远是把它插成叶结点**。

所以把 $V$ 删掉再插回来：$V$ 若是叶结点，$T_1 = T_3$；$V$ 若不是叶结点，它只能插在叶位置，$T_1 \ne T_3$。

换成**平衡二叉树**结论就完全变了：插入和删除都要调整，所以无论 $V$ 是不是叶结点，$T_1$ 和 $T_3$ 都**可能相同也可能不同**，不存在任何一种「一定」的情况。

| | 二叉排序树 | 平衡二叉树 |
| --- | --- | --- |
| 是否调整 | 不需要 | 插入、删除都要 |
| 删的是叶结点 $V$ | 插回原位，$T_1 = T_3$ | 可能相同，也可能不同 |
| 删的是非叶结点 $V$ | 插进去必落叶位且不调整，$T_1 \ne T_3$ | 可能相同，也可能不同 |

> **易错点**：看到「删除后再插入同一个结点」就条件反射答「相同」——那是二叉排序树的答案。看到「平衡」两个字要有心理准备：它的形态变化太多，没有必然。

### 树与表达式的对应

中缀表达式树把运算表达式的结构直接变成树形：运算符作分支结点，操作数作叶结点，**先计算的写在最下面、根是最后计算的**。

> **结论**：中缀表达式树做**后序遍历**，得到的就是后缀表达式（逆波兰式）；做**中序遍历**并加上括号，得到的就是带括号的中缀表达式。17 年那道「后缀表达式求值」用的两个栈，本质上就是在手工模拟这棵树的求值。

25 年考过「链式二叉树的根保存的是最先计算的运算符」这个说法——错。根是最后计算的，最先计算的在最底层。11 年那道「用有向无环图描述表达式，问顶点个数至少多少」是同一件事的复用版：原理跟中缀表达式树一样，区别在于重复的子表达式可以共用结点，所以要**合并重复**才得到最小值。

### 哈夫曼编码长度：只数分支就够

25 年那道题给了 7 个字符的频次 $2,3,4,5,6,10,11$，问编码长度 $\ge 3$ 的字符个数。

> **结论**：不需要真的把编码写出来。**一个分支就代表一个编码位**，所以只要数从根到目标叶结点的分支数（也就是路径长度）。

构造时的合并过程和结果：

```text
                              41
                        /           \
                      19             22
                    /    \         /    \
                   9     10       11     11
                 /   \           /   \
                4     5         5     6      <- 这里的 5、6 是编码节点
                    /  \
                   2    3

  待编码的叶节点（编码节点）：2  3  4  5  6  10  11
  中途生成的内部父节点：       5(2+3)、9(4+5)、11(5+6)、19、22、41

  路径长度为 2 的：10、11（一个）
  路径长度为 3 的：2、3、4、5、6（五个）  → 编码长度 >= 3 的有 5 个
```

> **提示**：频次大的字符一定待在比较靠上的地方——这是一个廉价的排除依据。频次最大的那个（比如 11），编码长度几乎不可能超过 2，先用它砍掉一批选项。

### 序列与树的相互反推套路

这一类在选择题里出现得最多，把三套动作固化下来：

**动作一：由序列关系推树形。** 先序和中序相同 → 只剩右孩子；先序和后序相反 → 单支树。推理方式统一：把两个序列并排写出，看哪一段的位置关系冲突，就说明树形必须做某种删减。

**动作二：由序列还原树形。** 中序定边界，另两个序列定根；后序找根、先序找根。中序的角色是提供「左右各多少个」这一信息，缺了它就切不开。

**动作三：由局部信息反推，不必完整还原。** 比如 23 年那道「后序序列求先序」，只需要两条：先序第一个是根（排掉含 $C$、$D$ 的选项），$A$ 只有右孩子所以 $C$ 一定落在先序的最后一个位置（再排掉含 $B$ 的选项），剩一个就选完了。整棵树甚至不用画。

> **提示**：完整还原是练基本功用的，做题时是提速用的。两件事都别丢：先看能不能靠已知信息排掉两三个选项，把答案选出来；选完之后**回头把整棵树完整还原一遍、每个序列都读一遍**，基本功就是这么长出来的。

## 一份临场自检清单

进考场之前，把下面这些在脑子里过一遍。每一项都是「看到什么 → 立刻想到什么」。

```text
看到"结点数 + 度"        -> n = 1 + Σd(v)，叶结点度为 0 出现在左边
看到"森林 / 几棵树"       -> 棵数 = 结点数 − 边数
看到"各种度的结点个数"      -> 一元方程，唯一未知量是 n0
看到"K 叉 / M 叉 + 高度"   -> (M^h − 1)/(M−1) 与 M(h−1)+1
看到"完全二叉树 + N 求叶"  -> 偶数 N/2，奇数 (N+1)/2
看到"第 k 层有 m 个叶，求最多" -> (2^k − 1) + 2(2^{k−1} − m)
看到"叶结点同层"           -> 满二叉树，总节点 2k − 1
看到"先序 + 后序，无中序"   -> 只能定"根的孩子"，左右定不了
看到"给定树形 + 某序列"    -> 树形等价于中序，照常还原
看到"线索指向谁"           -> 前驱还是后继 → 有没有孩子 → 哪种遍历 → 排序列
看到"后序 + 右线索"        -> 叶结点的右线索 = 双亲
看到"前缀特性"            -> 前缀编码 / 哈夫曼编码，问判定就现场建树
看到"WPL 最小"            -> 哈夫曼树；非二叉就是最佳归并树
看到"权值不唯一 / 可能"     -> 不去对答案，去找必然成立的特征
看到"森林 ↔ 二叉树"       -> 左孩子、右兄弟；最右分支几层就有几棵树
看到"树 ↔ 二叉树遍历"      -> 先根↔先序，后根↔中序
看到"是不是二叉排序树"     -> 中序是否严格递增（<= 就不合法）
看到"最优归并树虚段"       -> (M−1) mod (K−1)，虚段 = K − u − 1
```

最后三句提醒，是这一章最值钱的部分：

- **性质比算法重要。** 树的真题里，超过一半是「列式子 + 化简」，根本不需要设计算法。16 年那道正则 $K$ 叉树 8 分，一行公式就给满了。
- **推导链要能默写。** 从 $n = 1+\sum d$ 一路推到完全二叉树叶结点的奇偶公式，这条链你自己推过一次，考场上就调得出来；只背结论，考到变形题就懵。
- **「不唯一」是这一章的高频陷阱。** 哈夫曼编码、哈夫曼树形态、定长编码树的补虚结点、平衡二叉树的删插结果，凡是题面出现「可能」「某种」的地方，答案都只能从**必然成立的性质**里找，千万别拿自己算的结果去套选项。
