# 图的存储、遍历与应用

图是数据结构里最"活"的一种结构。树有根、有父子、方向单一，走法就那么一条；图不行——顶点可以连到任何顶点，边有方向有无方向，权值有高有低。正因为自由度大，图的问题才特别需要套路：题目千变万化，落到纸上永远只是那几个算法在跑。

这一篇我们把这些算法摊开。每一个都回答三个问题：**它解决什么问题、怎么判定、算得快不快**。掌握这三条，题目里再长的描述你也能一眼认出它要什么。

---

## 图的基本性质：顶点数与边数

凡是给了一张图让你算点什么，第一反应先别急着画图，先把顶点数 $n$ 和边数 $e$ 这两个"体量指标"捋清楚。后面所有的复杂度、所有的边界判断，都从这两个数出发。

### 无向图的度数性质

无向图里，每个顶点的度等于**和它相连的边的条数**。整个图所有顶点的度之和，等于边数的两倍：

$$\sum_{i=1}^{n} \deg(v_i) = 2e$$

> **结论**：无向图中所有顶点的度数之和恒等于边数的两倍。这条式子看着废话，但在让你数"总共有多少个度"或者判断某串度数是否合法时，它是唯一可靠的验算手段。

> **提示**：$2e$ 必是偶数。如果题目给了一串度数让你判断能不能构成无向图，先把总和加起来——奇数直接否掉，连图都不用画。

### 边数的上下界

$n$ 个顶点的无向图，边数有硬上界：任意两个顶点之间最多连一条边，所以

$$e \le \frac{n(n-1)}{2}$$

等号取到时就是**无向完全图**，也就是把每对顶点都连一遍。

有向图因为边分方向，$u \to v$ 和 $v \to u$ 可以同时存在，上界翻倍：

$$e \le n(n-1)$$

另一头是下界。**连通图**至少要 $n-1$ 条边，这正是树的定义——一棵生成树就是恰好 $n-1$ 条边、连通的生成子图。树上再挂任何一条边，必然成环。

> **易错点**：$n-1$ 这个数只对**连通**图成立。非连通图的下界是 $n-c$，其中 $c$ 是连通分量个数。题目里只要冒出"不连通"三个字，就别再拿 $n-1$ 去算。

### 有向图的入度与出度

有向图里每个顶点被拆成两个视角：箭头进来的叫**入度**，箭头出去的叫**出度**。入度为 0 的顶点在拓扑排序里是"无依赖"，出度为 0 的顶点在工程图里是"可以开工"。

> **结论**：有向图里 $\sum \text{入度} = \sum \text{出度} = e$。注意这里**没有那个 2**——有向的每条边只给它的一端贡献一个出度、给另一端贡献一个入度，算两遍但不是同一个量。

### 边的特殊性质

无向图有"每对顶点至多一条边"的前提，但**实际考试里必须警惕自环和重边**。一旦题目没说明"无自环、无重边"，就要意识到边数上界那套是按简单图算的。读题时先确认一句：图是不是简单图。

## 图的存储结构

要算东西总得先把图放进内存。图的存储只有两种基本套路，考研里**几乎所有的图算法都默认建了邻接表**，所以这两个必须闭着眼都能画出来。

### 邻接矩阵

用一个 $n \times n$ 的二维数组，$A[i][j]$ 表示顶点 $i$ 到顶点 $j$ 的信息：有权图存权值，无权图存 1（无边则 0 或 $\infty$）。

```text
        v1  v2  v3  v4
   v1 [  0   3   ∞   7 ]
   v2 [  3   0   9   ∞ ]
   v3 [  ∞   9   0   2 ]
   v4 [  7   ∞   2   0 ]
         ↑ 对角线恒为 0，权值和自身到自身无关
```

它的对称性是无向图最醒目的标志：$A[i][j] = A[j][i]$，矩阵关于主对角线对称。有向图就不对称了，上下三角可以完全不同——这也是区分两种存储的直观抓手。

> **结论**：邻接矩阵的空间复杂度是 $O(n^2)$，与边数**完全无关**。哪怕图里只有 $n-1$ 条边、稀疏得可怜，你照样要开 $n^2$ 个格子。这是它最大的原罪。

判断 $u$ 与 $v$ 是否相邻，只需要查 $A[u][v]$，这是 $O(1)$ 的，矩阵的强项就在这儿。

### 邻接表

把每个顶点挂一张自己的小表，只记它真正的邻居。常见实现是**边集数组 + 邻接表索引**：

```text
顶点下标:  0      1      2      3
         [头0]   [头1]   [头2]   [头3]   ← 每张表的表头指针
           ↓       ↓       ↓       ↓
邻接结点: (1,3)─→(3,7)─→NULL
              ↓
         (0,3)─→(2,9)─→NULL
              ↓
         (1,9)─→(3,2)─→NULL
              ↓
         (0,7)─→(2,2)─→NULL

无向图中每条边出现两次：(u,v) 挂在 u 的表里，(v,u) 挂在 v 的表里
```

> **结论**：邻接表的空间复杂度是 $O(n+e)$。$n$ 个表头占 $O(n)$，$2e$（无向图）或 $e$（有向图）个边结点占 $O(e)$。图越稀疏，它越省；图稠密到 $e = O(n^2)$ 时，它和矩阵一个量级。

代价是**查 $u$、$v$ 是否相邻变成了 $O(\deg(u))$**——得把 $u$ 的整张表扫一遍才敢说没有。这就是空间和时间的经典跷跷板：矩阵拿空间换查询，邻接表拿查询换空间。

### 两种存储的对照

| 对比项 | 邻接矩阵 | 邻接表 |
| :--- | :---: | :---: |
| 空间复杂度 | $O(n^2)$，与边数无关 | $O(n+e)$，与边数线性相关 |
| 判定 $u,v$ 是否相邻 | $O(1)$ | $O(\deg(u))$ |
| 求顶点 $u$ 的度 | $O(n)$，数一行 | $O(\deg(u))$，数它自己的表 |
| 遍历所有顶点 | $O(n^2)$ | $O(n+e)$ |
| 存储有向图 | 天然支持，矩阵不必对称 | 支持，$u$ 表里只存 $u$ 的出边 |
| 存储无向图 | 矩阵对称 | **每条边存两遍** |
| 典型适用场景 | 稠密图、需要频繁问"两点相邻吗" | 稀疏图、一切图算法 |

> **提示**：考研选择题最爱让你算"用邻接表存储需要多少个结点"。无向图是 $n + 2e$（$n$ 个表头 + $2e$ 个边结点），有向图是 $n + e$。第一问"用第几种存储"，八成是无向图，答 $2e$ 的那套；要是题目特意强调"有向图"，那就是 $e$。

## 图的遍历

连通图有千千万万种走法，但只要你想"系统地看遍每个顶点且不重复"，路线只有两条：一条钻到底，一条排队推进。

### 深度优先搜索 DFS

深度优先的精髓是一个 **visited 数组**加一个**递归（或栈）**。从起点出发，标记，点它的邻居，邻居还没访问过就立刻钻进去，钻不动了再回头退一步。

```text
无向图（边：0-1, 0-2, 1-3, 2-3, 3-4），从 0 开始 DFS

入栈/入栈序:  0 → 1 → 3 → 4 → 2
                │   │   │   │   └── 4 退回来发现 2 还没访问，再钻 2
                │   │   │   └────── 在 3 处找到 4
                │   │   └────────── 从 1 钻到 3
                │   └────────────── 0 的下一个未访问邻居是 1
                └────────────────── 起点

visited:  0    1    2    3    4
            ✓    ✓    ✓    ✓    ✓
```

> **结论**：DFS 的访问序列**唯一由起点和邻接表里顶点的排列顺序决定**。邻接表里邻居的存放顺序换了，遍历序列就变。所以"从顶点 0 出发，邻接表为 (1,2), (0,3), (1,4), (2,0) 这样的顺序"这类题目，答案必须严格按给定顺序推——**别自作主张排序**。

DFS 的副产品比它的序列本身还重要：在无向图里跑 DFS 时，**如果遇到一个已经被访问过的、且不是你的父节点的邻居，说明你撞上了一条回边，图里有环**。这是后面环判定的标准武器。

### 广度优先搜索 BFS

BFS 不钻牛角尖。它拿一个队列：从起点标记、入队，然后反复"出队一个、把它所有未访问的邻居标记并入队"。

```text
同一个图，从 0 开始 BFS

队列演化：
   [0]              出队 0
    ↓ 入队 1,2
   [1 2]            出队 1
    ↓ 入队 3
   [1 2 3]          出队 2（3 已在队里，不再入队）
    ↓ 无新邻居
   [2 3]            出队 3
    ↓ 入队 4
   [2 3 4]          出队 4
    ↓
   [3 4]
   [4]
   []

访问序:  0 → 1 → 2 → 3 → 4        ← 按"距离起点的层数"一层层铺开
```

> **结论**：BFS 的访问序是**按到起点的距离从近到远**的。第 $k$ 层 = 到起点距离恰好为 $k$ 的顶点。BFS 首次访问某顶点时记录的距离就是**最短跳数**——记住这一句，它是"无权图最短路径"最省事的解法：跑一次 BFS，距离数组就是答案，不用像 Dijkstra 那样一轮轮松弛。

> **易错点**：BFS 的"入队时标记"，不是"出队时标记"。必须是**入队的那一刻**就置 visited 为真。放到出队再标记，同一个顶点会被多个前驱重复入队，队列规模失控，序列直接错。

### DFS 与 BFS 的对照

| 对比项 | 深度优先搜索 | 广度优先搜索 |
| :--- | :---: | :---: |
| 核心结构 | 递归 / 栈 | 队列 |
| 访问序列特征 | 一条路钻到底，再回头 | 一层一层铺开 |
| 与距离的关系 | 访问序**不**对应最短距离 | 访问序**就是**最短跳数 |
| 空间开销 | $O(n)$（递归栈） | $O(n)$（队列） |
| 常见用途 | 连通分量、环判定、拓扑排序 | 无权图最短路、层次遍历 |
| 是否有确定的下一站 | 看栈顶还有没有未访问的邻居 | 看队头 |

时间复杂度两者一样，而且**取决于存储结构**：

$$\text{邻接矩阵}: O(n^2) \qquad \text{邻接表}: O(n+e)$$

邻接表下每个顶点只入栈/入队一次，每条边被检查常数次，所以是线性的。用邻接矩阵的话，光扫空那 $n^2$ 个格子就已经是 $O(n^2)$ 了，跟图稠不稠密无关。

> **结论**：考研问"深度优先遍历的时间复杂度"，**不指定存储结构就答 $O(n^2)$** 是最稳的；指定了邻接表才答 $O(n+e)$。反过来，邻接矩阵下 BFS 也逃不掉 $O(n^2)$。

## 最小生成树

现在进到应用题。最小生成树要解决的是：**连通无向带权图，怎么挑 $n-1$ 条边把图连起来，还要让权值总和最小**。

"权值和最小"这个最小值本身是唯一的，但**凑出这个最小值的边集未必唯一**——这个区别是后来一连串小问的起点，先记住。

先看两个前提条件，缺一个结论都不成立：

> **定义**：生成树是包含图中全部 $n$ 个顶点、且连通无环的子图。它一定恰好有 $n-1$ 条边。最小生成树（MST）是所有生成树中**边权之和最小**的那一棵。

> **结论**：MST 有两个性质被反复用到。第一，**最小权值边一定在 MST 中**（前提是权值互不相同）。第二，**若某边 $(u,v)$ 是所有能连接 $u$、$v$ 两个不同连通分量的边中最小的，那它一定在 MST 中**。这两条是 Kruskal 和 Prim 能成立的根，也是判断"某条边必选/必不选"的唯一依据。

### Kruskal：按边权全局排序

思路朴素到近乎机械：**把所有边按权值从小到大排一遍，然后依次尝试加入，只要不形成环就收**。

判环靠并查集——这是 Kruskal 的灵魂。加入边 $(u,v)$ 前，看 $u$ 和 $v$ 是不是已经在同一个集合里；在同一个就说明连通了，加进去就成环，扔掉。

```text
已选边: { (A,D) }
分量:   { A D } { B } { C } { E }

待检边   检查        判定
────────────────────────────────────────
CB(4)   C,B 不同分量  ✅ 收下
DE(4)   D,E 不同分量  ✅ 收下
AE(5)   A,E 同在 {A D E}  ❌ 成环，丢
CE(5)   C,E 不同分量  ✅ 收下
AB(6)   A,B 同在 {A B C D E}  ❌ 成环，丢
CD(6)   同分量        ❌ 成环，丢
────────────────────────────────────────
共收 3 条... 还差 1 条？

别急—— 数一遍集合：{A B C D E} 已经连成一坨，
四个顶点  A D C B 加 E 通过 DE 连上，共 5 点 4 边，正好生成树
最终 MST = { AD(4), DE(4), CE(5), CB(4) }，权值和 = 17
```

> **结论**：Kruskal 的复杂度 $O(e\log e)$，瓶颈在**排序**。因此它天生适合**边稀疏**的图。

### Prim：从一个点长出去

Prim 换了个角度：它不看全局的边，而是**盯住已经长进树里的那一个点集**，每次从"一端在集合内、一端在集合外"的边里挑权值最小的。

```text
集合 V = { A }

第 1 步  候选边：AB(6) AD(4) AE(5)      最小 AD(4)
         ────────────────────────────────────────
         V = { A D }
              ──A──D──

第 2 步  候选边：AB(6) AE(5) DE(4) DC(6)  最小 DE(4)
         ────────────────────────────────────────
         V = { A D E }
              ──A──D──E

第 3 步  候选边：AB(6) CD(6) CE(5) AE(5)  ✗ AE 排除（两端都在集合内）
                                                 最小 CE(5)
         ────────────────────────────────────────
         V = { A D E C }
                  ──A──D──E──C

第 4 步  候选边：AB(6) CD(6) CB(4)        最小 CB(4)
         ────────────────────────────────────────
         V = { A B C D E }   5 点 4 边 ✅
              ──B──C──E──D──A

MST = { AD(4), DE(4), CE(5), CB(4) }，权值和 = 17
```

Prim 跑完得到的这棵树，和上面 Kruskal 跑出来的是**同一棵**。这不奇怪——它们都求最小生成树，最小生成树本来就该是唯一的（在这个例子上确实唯一，后面会说）。

### 走 Prim 时最要命的一步

上面第 3 步是整道题的生死线，我们专门停下来讲。

选完 $DE$ 之后，集合里是 $\{A, D, E\}$。这时候 $AE$ 的权值是 5，**在候选边里排得很靠前**——但它绝对不能加。为什么？因为 $A$ 和 $E$ **都已经在集合内**了，再加一条把集合内两点连起来的边，图上立刻出现环 $A \to D \to E \to A$。

> **结论**：一条边能被选中，必须**同时**满足两条：① 它的两个端点里**恰好有一个**在当前集合中（一个在内一个在外）；② 在所有满足①的边里权值最小。第一条管不死就选不成，第二条管选出的是哪一条。

"恰好有一个"这四个字，一个字都不能含糊。**两个都在外的边**同样不能选——这正是第 3 步里我们没选 $CB(4)$ 的原因：$C$ 和 $B$ 当时都不在集合中，够不着。哪怕 $CB$ 的权值 4 是全图最小的、明明排在候选表最前面，也只能干看着。

> **易错点**：这是 Prim 最常见的两种翻车姿势。**第一种**，看到权值小的边就想加，忘了检查它会不会成环——典型表现是把 $AE$ 加进去。**第二种**，被"全图最小边"的顺序误导，以为每步都该从全图最小的边里挑。正确的口径永远是"**当前合法的边里最小的那个**"，不是"全图最小的那个"。合法性优先于最优性。

> **提示**：如果题目让从某个指定顶点开始，就老老实实从那个点起步——**Prim 的起点会换出一棵不同的树**。题目只说"用普里姆算法"而没指定起点时，任选一点都可以，MST 本身不会因此算错（前提是唯一）。

### Prim 与 Kruskal 的对照

| 对比项 | Prim | Kruskal |
| :--- | :---: | :---: |
| 思想 | 从点出发，一点一点把树长大 | 从边出发，把边一条条捡进来 |
| 选择依据 | 跨集合的边中权值最小 | 全图剩余边中权值最小且不成环 |
| 判环手段 | 检查端点是否一内一外 | 并查集查是否同分量 |
| 复杂度 | $O(e\log n)$（堆优化），稠密图 $O(n^2)$ | $O(e\log e)$ |
| 更适合 | **稠密图**（边多，选边瓶颈小） | **稀疏图**（边少，排序才是主要开销） |
| 中途可换起点吗 | 换起点会得到不同的树 | 与起点无关，答案只由边权决定 |
| 中途可否暂停/分块 | 不可，是一个连续过程 | 可，处理完一个连通分量再处理下一个 |

> **结论**：**Prim 是"点"的算法，Kruskal 是"边"的算法**。稠密图用 Prim（边排序的开销太大），稀疏图用 Kruskal（Kruskal 的排序代价小）。这个选择判断在考研里几乎每年都以"用哪个算法更快"的形式出现。

### MST 的唯一性

这是最小生成树最容易被追问的一串小问，我们一次讲透。

判定方法非常朴素：**把整个选边过程重走一遍，看有没有哪一步冒出了"这两条边我选哪条都行"的情况**。如果每一步都是被迫唯一选择的，那 MST 就唯一；如果有某一步存在并列，说明存在另一棵同样最优的树。

回到刚才那个 $A$ 到 $E$、五条边七条边的例子：从 $A$ 出发选 $AD$，再选 $DE$，再选 $CE$，最后选 $CB$——整条路线上**每一步都没有出现可选的替代**，所以这棵 MST 是**唯一的**。

> **结论**：**若图中所有边的权值都不相同，则最小生成树唯一。** 道理很直白：权值都不同，权值和最小的那个边集就没有第二种凑法。

> **易错点**：这条命题**不能反推**。"MST 唯一 ⟹ 边权均不相同"是**错的**。刚才那个图就是活生生的反例：边权里有**三个 4 分组对等权边**（$AD$、$DE$、$CB$ 都是 4）、两个 5（$AE$、$CE$）、两个 6（$AB$、$CD$），可它的 MST 依然唯一。推不回去的箭，就别硬往回射。

什么情况下会**不唯一**？当图里存在**权值相同的边**，且选这些等权边时**选哪条都能达到同样的最优值**，就会长出不同的最小生成树。

> **提示**：这类题一定要**用生成过程去反推唯一性**，而不是盯着边权表下结论。边权表只能告诉你"可能不唯一"，真正的判据是"构造过程中有没有出现并列选择"。这两步之间的落差，就是这道题设的坑。

### 顺带记住的一圈结论

考完算法本身，题目还很喜欢追着问一圈相关结论，样样都得记住：

- 最小生成树的边权之和最小，但**边数固定是 $n-1$**，不会因为"更便宜的边"就多选。
- 有 $n$ 个顶点的图，MST 的权值和**不唯一**的情况只在有等权边且选择存在歧义时出现。
- **Dijkstra 算法不适用于带负权的图**；带负权回路的图连最短路径都**不存在定义**。这一点几乎必然被塞进应用题的某个小问里。
- 算法的具体实现步骤别只盯着"怎么写"，**结论那一圈一起记**，因为应用题的小问经常跳到性质上去。

## 最短路径

最短路径和最小生成树是两类问题，**别混**。最小生成树要的是"把所有点都连起来且总权最小"，最短路径要的是"从 $s$ 到 $t$ 走得最短"。后者只关心一对顶点，路径上不一定经过所有点。

> **提示**：这个区别一句话能说清——**MST 里每条边都是必需的（砍掉就断开），最短路径里有些边是多余的**。一棵 MST 恰好 $n-1$ 条边，而 $s$ 到 $t$ 的最短路可能只用 2 条。

### Dijkstra：单源，权值非负

从一个源点出发，反复做两件事：① 在所有**还没确定最短距离**的顶点里挑一个距离最小的，② 用它去**松弛**邻居。

"松弛"的含义要掰开：假设 $u$ 是刚定下来的点，对它的每个邻居 $v$，看

$$dist[v] > dist[u] + w(u,v)$$

成立的话就把 $dist[v]$ 改成 $dist[u] + w(u,v)$。

```text
源点 A，各边：AD=4 AE=5 AB=6 DE=4 CE=5 CB=4 CD=6

初始   dist:  A=0   B=∞   C=∞   D=∞   E=∞
        prev:  全空

轮 1  未确定中最小：A(0)
       松弛 → D=0+4=4, E=0+5=5, B=0+6=6
        dist:  A=0   B=6   C=∞   D=4   E=5

轮 2  未确定中最小：D(4)
       松弛 → E=4+4=8 (不优于 5，放弃), C=4+6=10
        dist:  A=0   B=6   C=10  D=4   E=5

轮 3  未确定中最小：E(5)
       松弛 → C=5+5=10 (等于 10，任意取一即可)
        dist:  A=0   B=6   C=10  D=4   E=5

轮 4  未确定中最小：B(6)
       松弛 → C=6+4=10
        dist:  A=0   B=6   C=10  D=4   E=5

轮 5  未确定中最小：C(10)
        dist:  A=0   B=6   C=10  D=4   E=5   全部确定

结论  A→D = 4,  A→E = 5,  A→B = 6,  A→C = 10
```

> **结论**：Dijkstra 的复杂度，邻接矩阵下是 $O(n^2)$，邻接表 + 优先队列是 $O((n+e)\log n)$。核心机制是"每次选最小的那个"+"松弛"，两个动作反复 $n$ 轮。

> **结论**：**Dijkstra 不能处理负权边。** 因为它一旦把某个顶点的距离定下来就不再改动，如果那条路径是靠一条负权边走出来的，后面出现的更短路径就被错过了。带负权但无负权回路的图，应该用 Bellman-Ford；带负权回路的图，最短路径无定义。

> **提示**：**权值全为 1 的无权图**是最省事的一种 Dijkstra——这时它退化成 BFS，跑一遍 BFS 得到的距离数组就是最短路。题目给了无权图就直接 BFS，别去搭 Dijkstra 的架子。

### Floyd：全源，三重循环

Floyd 换了个完全不同的思路：做**中转点枚举**。$n$ 个点排好队当"中转站"，一个一个放行，每次问一句"经过这个中转站会不会更短"。

状态转移方程是全篇最该背下来的一行：

$$dist[i][j] = \min\big(dist[i][j],\ dist[i][k] + dist[k][j]\big)$$

```c
/* Floyd：三重循环，最外层必须是中转点 k */
for (int k = 0; k < n; k++)          // ← 中转点必须在最外层！
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            if (dist[i][k] + dist[k][j] < dist[i][j])
                dist[i][j] = dist[i][k] + dist[k][j];
```

> **易错点**：三重循环的顺序**必须是 $k \to i \to j$**，$k$ 必须在最外层。写成 $i \to j \to k$ 语法完全合法、结果也"看着有输出"，但语义全错——那样等于不允许"连续经过多个中转点"，只能中转一次。写完顺手检查一遍循环头，这地方编译器不会帮你抓。

> **结论**：Floyd 的复杂度是 $O(n^3)$，空间 $O(n^2)$。它能正确处理**负权边**（只要没有负权回路），一次跑完全源最短路，这是它相对 Dijkstra 的核心优势。

> **结论**：**如果图中存在负权回路，对角线 $dist[i][i]$ 会变成负数**。这是个非常好用的检测手段：跑完 Floyd，凡是 $dist[i][i] < 0$ 的点，说明它在负权回路里，最短路径无定义。碰到"判断负权回路"的小问就用这招。

### Dijkstra 与 Floyd 的对照

| 对比项 | Dijkstra | Floyd |
| :--- | :---: | :---: |
| 解决范围 | **单源**最短路径 | **全源**最短路径 |
| 核心机制 | 选最小 + 松弛 | 枚举中转点 |
| 核心状态 | `dist[v]`，一维 | `dist[i][j]`，二维 |
| 时间复杂度 | $O(n^2)$ 或 $O((n+e)\log n)$ | $O(n^3)$ |
| 空间复杂度 | $O(n)$ | $O(n^2)$ |
| 负权边 | **不支持** | 支持（无负权回路时） |
| 负权回路检测 | 不适用 | 查 $dist[i][i] < 0$ |
| 适合的图规模 | 大图 | 顶点数少、稠密图 |

> **提示**：选型一句话——**题目给了一个源点就 Dijkstra，给了"任意两点之间"就 Floyd**。顶点少（几十个以内）且要求全源时，Floyd 写起来还更短更好拿分，因为它不需要维护前驱数组。

## 有向无环图与拓扑排序

拓扑排序是有向图的独门功夫。它要回答的是：**一组任务有先后依赖，能不能排出一个合法的执行顺序**。

> **定义**：拓扑排序是把**有向无环图（DAG）**的顶点排成一个线性序列，使得对任意一条有向边 $u \to v$，$u$ 在序列中都排在 $v$ 前面。它存在的**唯一前提是图无环**——有环的图排不出来。

标准做法简单得不像话：数每个顶点的**入度**，把所有入度为 0 的顶点丢进队列，然后循环"取队头、输出、把它每条出边指向的邻居入度减一、减到 0 就入队"。

```text
工程依赖：课程 ←(先修) 教材、习题；教材 ← 习题

入度表：  教材=1  习题=2  课程=0

队列: [课程]
输出: 课程
       ↓ 课程出边 → 教材(1→0, 入队)、习题(2→1)
队列: [教材]
输出: 教材
       ↓ 教材出边 → 习题(1→0, 入队)
队列: [习题]
输出: 习题

拓扑序: 课程 → 教材 → 习题     ✅ 每条边的起点都在终点前面
```

> **结论**：**入度为 0 的顶点可以立即开工**。拓扑序的实质就是把"依赖图"里的先后约束解成一个顺序——AOV 网（顶点代表活动、边代表先后关系）的标准解法。

> **结论**：算法的时间复杂度是 $O(n+e)$，每个顶点入队出队各一次，每条边被松弛一次。这是所有图算法里最线性的一个，务必记住。

> **易错点**：**题目若没说图是 DAG，就先判环**。有环的话拓扑排序根本不存在，硬排出来的序列一定违反某条边的约束。AOV 网绝大多数情况是无环的（否则工程根本无法开工），但考研会故意在某一问里让你说明"若存在环该怎么办"——答案就是**判定有环，然后报告无法排序**。

> **提示**：拓扑序**一般不唯一**。只要有多个入度为 0 的顶点同时在队列里，谁先谁后都对。题目若没指定规则，任选一个合法序即可，但**一定要检查自己的输出是否真的满足所有边的约束**。

## 环的判定

判定图里有没有环，看起来是个小问，实际上有三四种实现路径，考试里会挨个问过来。

### 无向图判环：DFS 回边

跑一遍 DFS，记住每个顶点的**父节点**。访问一个顶点时如果发现某个邻居**已经被访问过、而且不是自己的父节点**——那就是一条回边，图里有环。

> **易错点**：**必须排除父节点**。无向图里你沿着边 $u \to v$ 走过去，回过头 $v \to u$ 这条边照样在邻接表里，不排除的话会误报。正确做法是把父节点参数一路传下去。**如果这题是有向图，父节点这个概念就不成立了**——有向图的判环靠的是三色标记或者拓扑排序。

### 无向图判环：边数速判

$n$ 个顶点、$e$ 条边的无向连通图：

$$e > n - 1 \;\Longrightarrow\; \text{有环}$$

反过来 $e = n-1$ 且连通，那就是一棵**树**，天然无环。这个结论在选择题里经常直接用。

> **易错点**：$e > n - 1$ 只能说明"有环"，不能反过来用"无环推出 $e \le n-1$"之外的东西。**非连通图不适用这个判定**——森林里 $e$ 本来就小于 $n-1$，公式的适用前提是"连通"。

### 有向图判环：拓扑排序与三色标记

最省事的是直接跑拓扑排序：**如果输出的顶点数少于 $n$，就说明有顶点卡在环里没被输出，图中存在环**。跑得干净利落（输出了全部 $n$ 个）就说明无环。

另一种标准三色标记法：

- **白**：从未访问过；
- **灰**：在当前递归路径上（递归栈里）；
- **黑**：已经彻底访问完，它的出边都处理过了。

DFS 走进一个**灰色**顶点，说明你绕回到了当前路径上的某个点，**成环**；走进黑色或白色顶点都没事。

```text
白 → 灰 → 黑        正常的深入过程（DFS 前进）
       ↑
       └── 撞见灰色 = 撞见自己 = 环

A(白) → B(灰) → C(灰) → D(白) → ... → 又摸回 B(灰)  ⟹  B→C→D→…→B 成环
```

> **提示**：三色法的价值在于它**能顺带把环上的顶点揪出来**。如果小问要求"指出环上的所有顶点"，只有三色法（或 DFS 回溯时记栈）做得到，单纯数边数是数不出来的。

## 图的应用题解题套路

最后把散落各处的套路收拢成一张作战图。拿到一道图的应用题，按这个顺序过一遍。

### 读题先抓四样东西

**抓存储**。题目给的是邻接矩阵、邻接表，还是边集？这一条直接决定后面所有算法的复杂度表达。

**抓类型**。有向还是无向？带权还是无权？连通还是不连通？有没有说"无自环无重边"？**这四个问题不问清楚，答案可能整个错掉**。

**抓问题**。问的是遍历序列、最小生成树、最短路径、还是拓扑序？题目里出现的关键词（"最小权值""最短""先后顺序""是否存在"）就是算法选型的直接线索。

**抓规模**。顶点数是几十还是几千？这决定你写过程描述还是写伪代码，也决定复杂度该按哪个版本答。

### 算法选型对照表

| 题目问的是 | 首选算法 | 关键判定/公式 | 复杂度 |
| :--- | :---: | :---: | :---: |
| 遍历序列（按给定邻接表顺序） | DFS 或 BFS | 严格按邻接表排列顺序推 | $O(n+e)$（邻接表） |
| 无权图两点最少跳数 | BFS | 首次访问时的层数即最短跳数 | $O(n+e)$ |
| 最小生成树（稠密） | Prim | 跨集合边中权值最小，端点须一内一外 | $O(n^2)$ |
| 最小生成树（稀疏） | Kruskal | 全局最小且不成环，用并查集判环 | $O(e\log e)$ |
| 单源最短路（权非负） | Dijkstra | 选最小 + 松弛 | $O(n^2)$ |
| 全源最短路 / 有负权边 | Floyd | $dist[i][j] = \min(dist[i][j],\, dist[i][k]+dist[k][j])$ | $O(n^3)$ |
| 任务先后排序 | 拓扑排序 | 反复取入度为 0 的顶点 | $O(n+e)$ |
| 有无环 | 边数速判 / 三色 DFS | $e > n-1$（连通无向）/ 撞见灰色 | $O(n^2)$ |

### 书写规范：这几步漏一个就扣分

**先写答案，再写过程。** 第一行直接落下最终结论或最终数字，后面再补推导。阅卷的第一眼找的就是这个。

**过程该写还得写。** Prim 选边的每一步、Dijkstra 每轮的松弛结果、拓扑排序每步出队的是谁——**只给一棵画好的树，阅卷人看不出你的选边顺序，就没法判断过程分**。

**代码要能自洽。** 用到 Floyd 就把 `k` 放最外层，用到并查集就把 `find` 写全。别写一句"调用 QuickSort"就交卷——**你调用了它，就等于要证明你会写它**。

**性质小问单独成段。** "MST 是否唯一""Dijkstra 适不适用于负权""最短路径是否存在"，这类小问答案都很短，但**必须明确写"是/否"再给理由**，光给理由不写结论会丢分。

> **结论**：图的应用题，几乎没有"想不到"的问题，只有"没对号入座"的失分。判断题识别错算法、计算题漏写一步过程、性质题不敢下结论——把这三个坑填平，图这一章的分就稳了。

> **提示**：临场再补一句。图的题最容易慌，而慌的根源是**没先算 $n$ 和 $e$**。拿到图先数顶点数和边数，这两个数一旦在手心，后面每个算法要跑几轮、占多大空间、会不会超时，全都有数了。稳住图，先数点。
