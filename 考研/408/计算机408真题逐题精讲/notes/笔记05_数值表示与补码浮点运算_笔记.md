# 数值表示与补码浮点运算

这一块是组成原理里最"考得多、又不给面子"的区域。真题从不给你一个新概念，它给的是一串十六进制、一条 C 语言赋值、一个结构体成员，问你这个位串是什么意思。

好消息是：这块的高频点高度集中。原码反码补码移码换算、补码溢出判定、IEEE 754 拆解、大小端与结构体对齐，这几件事在 09 年、10 年、19 年、20 年、22 年、25 年的真题里反复出现，换的只是外壳。

我们按知识体系走，不按年份。

---

## 四种编码：原码、反码、补码、移码

先把最根本的东西立住：真值是你脑子里的那个带正负号的数，机器数是它落在定长二进制位串上的样子。两者之间要靠一套编码规则挂钩，这套规则就是下面四种。

### 原码

> **定义**：最高位是符号位（0 表示正，1 表示负），其余各位直接表示绝对值的二进制。

以 8 位为例，$-5$ 的原码是 `10000101`，$+5$ 的原码是 `00000101`，$+0$ 是 `00000000`，$-0$ 是 `10000000`。

原码的致命伤是**有两个零**，而且加减法要做一堆条件判断，硬件很麻烦。所以计算机实际不用原码，只用它做中间表示。

### 反码

> **定义**：正数的反码和原码完全相同；负数的反码是它原码的**数值位按位取反**（符号位不动）。

```text
  +5  原码 00000101  ->  反码 00000101     （正数不变）
  -5  原码 10000101  ->  反码 11111010     （数值位取反，符号位仍为 1）
```

反码比原码强在哪儿？加减法可以统一做了：加法就是按位加，产生的进位丢掉；减法就是加对方的反码。反码的代价是**仍然有两个零**：`00000000` 和 `11111111`。

> **易错点**：反码的两个零分别读作 $+0$ 和 $-0$。判断某位串是不是反码下的零，标准是"全 0 或者全 1"，不是"最高位为 1"。全 1 在原码里是一个合法的负数，在补码里才变成 $-1$。

### 补码

> **定义**：正数的补码和原码相同；负数的补码是其反码**末位加 1**。也可用权值式直接算。

$$[x]_{\text{补}} = \begin{cases} x, & x \ge 0 \\ 2^n + x, & x < 0 \end{cases}$$

位串转换过程就是这三行，一定要在草稿上写出来，不要靠脑子"看反了加一"：

```text
  以 8 位、-5 为例

  原码：1 0000101          符号位 1，数值位是 5 的二进制 0000101
  取反：1 1111010          符号位不动，数值位逐位取反
  加一：1 1111011          末位加 1（有进位就继续往前进）

  验算：[x]补 = 2^8 + x = 256 - 5 = 251 = 11111011 ✓
```

补码是计算机里唯一真正在用的整数编码。理由有三：只有**一个**零；加减法统一成加法，且能直接判符号；位串的大小顺序和真值大小顺序一致（下面讲比较时会兑现这一点）。

> **结论**：补码比原码多表示一个数。多出来的那个是位串 `1000...0`，它的值是 $-2^{n-1}$。原码的最小值是 $-(2^{n-1}-1)$，补码的最小值是 $-2^{n-1}$——就是全 1 和全 0 那一头，两种编码在这处正好差 1。

22 年那道问 32 位补码能表示的整数范围，答案就是 $[-2^{31},\ 2^{31}-1]$。这个考过不止一次，记住那个"补出来的差 1"就不会错。

### 移码

> **定义**：移码是把真值在 $n+1$ 位（含一位符号位）的补码的**符号位取反**得到的位串。真值 $x$ 的移码等于 $x + 2^n$。

移码的构造有个特别省事的路子：先把 $[x]$补写出来，然后把最左边那一位 0/1 翻一下。

```text
  8 位数值位（不含符号位），取 4 位示例

  x = +5    补码 0 0101   ->  移码 1 0101   （= 16 + 5 = 21）
  x = -3    补码 1 1101   ->  移码 0 1101   （= 16 - 3 = 13）
  x =  0    补码 0 0000   ->  移码 1 0000   （= 16）
```

移码只有一个零，也是 $16$ 这一串 1 0000。它存在的意义有两个：一是让浮点数里的阶码免掉符号判断（阶码永远非负），二是**让移码位串的大小顺序直接等于真值大小顺序**，这个性质在比较里极好用。

### 四种编码的互化与特权位串

原码、反码、补码、移码之间的转换关系值得单列一张表背下来：

| 编码 | 正数 | 负数 | 零的个数 | n 位真值范围 |
| :--- | :--- | :--- | :--- | :--- |
| 原码 | 与原码同 | 符号位置 1，其余为绝对值 | 2 个 | $-(2^{n-1}-1) \sim 2^{n-1}-1$ |
| 反码 | 与原码同 | 数值位取反 | 2 个 | $-(2^{n-1}-1) \sim 2^{n-1}-1$ |
| 补码 | 与原码同 | 数值位取反加 1 | 1 个 | $-2^{n-1} \sim 2^{n-1}-1$ |
| 移码 | 补码符号位取反 | 补码符号位取反 | 1 个 | $-2^{n} \sim 2^{n}-1$（含一位符号位） |

另外要记住几串"特权位串"——它们在别的编码里是合法数字，在补码里被征用去做特殊用途：

```text
  补码 1 1000...0   = 机器零（真值 0，是唯一的零）
  补码 1 0000...0   = -2^(n-1)，补码比原码多出来的那个数
  补码 0 0000...0   = +0，与机器零同值
  移码 1 0000...0   = 真值 0
```

> **易错点**：看到 `1111...1` 别急着说它是 $-1$。$-1$ 只是**补码**下的结论；在原码里全 1 是 $-127$（8 位），在反码里全 1 是 $-0$，在移码里全 1 是 $+127$。编码一变，位串的含义就全变。

## 补码运算与溢出判定

### 补码加减法统一成加法

不管题目写的是加还是减，一律翻译成"补码直接相加"。减法尤其要当心：`X - Y` 要写成 `X + (-Y)`，而 $-Y$ 的补码是把 $Y$ 的补码**各位取反、末位加一**。

25 年那道就是这个套路：8 位字长，$X = $ `A3H`，$Y = $ `75H`，求 $X - Y$ 和 OF 标志。

```text
  第一步：求 -Y 的补码（Y 的补码取反加一）
      Y   = 01110101   (75H)
      取反 = 10001010
      +1  = 10001011   ← 这就是 -Y 的补码

  第二步：与 X 的补码直接相加
      X      = 10100011   (A3H)
    + -Y     = 10001011
    ---------------
      1 00101110          最高位那个进位直接舍去

  结果位串 = 00101110 = 32+8+4+2 = 46
```

真值那边验一下：$X = -128+32+2+1 = -93$，$Y = 64+32+8+4+1 = 109$，真实差是 $-202$，早就出了 8 位补码的范围。所以那串 `00101110` 代表的 46 是**回绕出来的错值**，不是真实的 $X - Y$。

> **易错点**：如果选项里有一项写的是"溢出"，那才是正确答案。溢出的时候算出来的那串二进制根本不代表一个真实结果——这是这类题最爱设的坑。

### 溢出的三种判据

判溢出只有一条根本原则：**真实结果超出了 $n$ 位补码的范围 $-2^{n-1} \sim 2^{n-1}-1$，就是溢出。** 三种判据只是这个原则的三种实现。

**单符号位法**：两个同号数相加，结果符号位和它们不同 → 溢出。

**双符号位法（变形补码）**：把符号位复制一份用 `00`/`11` 表示正负。两个符号位不同就是溢出。

```text
  00 + 00 -> 00   正常正数
  11 + 11 -> 11   正常负数
  00 + 11 -> ？？  两数异号相加，绝不会溢出
  00 + 00 -> 01   正溢出   ← 尾数溢出，要右规
  11 + 11 -> 10   负溢出   ← 尾数溢出，要右规
```

这里有个必须分清的岔路口：双符号位出现 `01`/`10` 之后，你要判断是**尾数溢出**（阶码还能再加 1，做右规就行）还是**阶码本身溢出**（阶码已经顶到最大，没救了）。09 年那道双符号位浮点加法就栽在这个岔路口上。

**符号位进位异或法**：

$$OF = C_{n-1} \oplus C_n$$

其中 $C_{n-1}$ 是符号位产生的进位，$C_n$ 是最高数值位产生的进位。25 年那道里，符号位进位是 1、最高数值位没进位是 0，于是 $OF = 1 \oplus 0 = 1$，溢出。

> **提示**：进位法里最容易混的是 $C_{n-1}$ 和 $C_n$ 谁是谁。记法：$C_{n-1}$ 是符号位的进位（符号位在最顶上，对应最高位下标 $n-1$），$C_n$ 是它下面那一位数值位的进位。两个都进或都不进都不溢出，一进一出才溢出。

### 判断溢出前，先把补码转成真值

10 年那道问四个 8 位补码相乘哪个溢出，四个选项全是乘法。硬算二进制乘法太慢，正确的做法是**先转真值，再用真值算**：

| 寄存器 | 补码 | 转真值的过程 | 真值 |
| --- | --- | --- | --- |
| R1 | FEH = 1111 1110 | 取反得 0000 0001，末位加一得 0000 0010 | $-2$ |
| R2 | F2H = 1111 0010 | 取反得 0000 1101，末位加一得 0000 1110 | $-(8+4+2)=-14$ |
| R3 | 90H = 1001 0000 | 最高位后面 1 很少，权值法：$-2^7+2^4$ | $-128+16=-112$ |
| R4 | F8H = 1111 1000 | 取反得 0000 0111，末位加一得 0000 1000 | $-8$ |

代进去比一比：$(-2)(-14)=28$、$(-14)(-112)=1568$、$(-2)(-8)=16$、$(-14)(-8)=112$，只有 1568 越界。

> **提示**：补码转真值不止"取反加一"这一条路。位串里 **1 的个数很少**的时候，直接按权值加减更快——最高位那个 1 的权值是 $-2^{n-1}$ 而不是 $+2^{n-1}$，这是补码权值法的全部秘密。

### 能用真值算就用真值算

09 年第 12 题是 $X = 127$（`int`）、$Y = -9$（`short`），求 $Z = X + Y$。按位串硬凑竖式当然能算出来，但有一个一秒出答案的路子：

```text
  路线一：按位串走（标准流程）

  X = 127 = 2^7 - 1 = 七个 1，正数
      int，32 位  ->  0000007FH

  Y = -9，short，16 位
      原码   = 1000 0000 0000 1001
      取反   = 0111 1111 1111 0110
      末位+1 = 0111 1111 1111 0111  =  FFF7H

  Y 要参与 32 位运算 -> 符号扩展 -> FFFFFFF7H

      0000 007F
    + FFFF FFF7
    --------------
   1  0000 0076      最高位进位直接舍去
      ->  00000076H = 118
```

但更快的路线是：既然题目给的是真值，直接 $127 + (-9) = 118$，$118 = 7 \times 16 + 6$，所以十六进制是 `76H`。答案一样。

> **结论**：竖式是用来**验证**的，不是用来**出发**的。题目问结果的数值就用真值算，只有题目明确问位串时才去凑竖式。

### 长度扩展与类型转换的顺序

`int` 和 `short` 混在一起算，第一件事永远是长度对齐。规则只有两条：

- **无符号数扩展**：在高位补 **0**。
- **有符号数（补码）扩展**：符号位是 0 就补 **0**，符号位是 1 就补 **1**（符号扩展）。

25 年那道把这套流程和"有符号转无符号"叠在一起考：

```text
  已知：32 位机器上，short si = -32767，转成 unsigned int ui

  第一步：写 -32767 的 16 位原码
      32767 = 2^15 - 1 = 十五个 1
      1 111111111111111

  第二步：转补码（符号位不动，数值位取反加一）
      1 100000000000001

  第三步：short -> int 做符号扩展（符号位是 1，前面补 16 个 1）
      11111111111111111000000000000001

  第四步：有符号 -> 无符号，去掉最高位按无符号重新解释
      这一串 32 位现在被当成 0 ~ 2^32-1 里的一个数来看
```

第四步是最容易算错的一步——你很可能会顺手去把每一位权值加起来，那样又慢又容易错。正确打法是转成"全 1 减掉一个小数"：

```text
      11111111111111111111111111111111     全 1，值 = 2^32 - 1
    - 00000000000000000000000000000010     只有第 1 位是 1（先符号扩展补了 16 个 1，原来的最低位 1 被挤到第 1 位）
    = 11111111111111111111111111111101

    等价写法：
    X = (2^32 - 1) - (2^15 - 2) = 2^32 - 2^15 + 1 = 4294934529
```

> **结论**：两次转换同时存在时，顺序是**先 short → int 长度扩展，再有符号 → 无符号重新解释**。反过来算，答案就是另一个数。

19 年那道是同一件事的另一个切面：`unsigned short` 的 $65535$ 转成 `short`。$65535 = 2^{16}-1$ 就是十六个 1，同一个 bit 串，最高位含义一变：

```text
  unsigned short 视角（看不到符号位）
      1111 1111 1111 1111  =  2^16 - 1  =  65535

  转成 short，最高位现在变成符号位
      机器数(补码)  1 1111 1111 1111 1111
      数值位取反    1 0000 0000 0000 0000
      末位加一      1 0000 0000 0000 0001
      原码          -  0 0000 0000 0001  =  -1
```

> **结论**：无符号转有符号，**机器数一个比特都不用改**，改的是"怎么解释这个比特串"。所以 $65535$ 转 `short` 是 $-1$，$4294967295$ 转 `int` 也是 $-1$。

### 一个机器数，两种读法

20 年那道把两套表示体系摞在一起：已知有符号整数用补码、`float` 用 IEEE 754，当 $X$ 的机器数是 `C8000000H` 时 $X$ 可能是什么。题干把类型卡成只有 `int` 或 `float` 两种，所以必须先判断走哪条路。

```text
  0xC8000000 = 1100 1000 0000 0000 0000 0000 0000 0000

  走 int 这条路（补码）
      机器数(补码) ： 1 100 1000 0000 0000 0000 0000 0000
      数值位取反    ： 0 011 0111 1111 1111 1111 1111 1111
      末位加 1      ： 0 011 1000 0000 0000 0000 0000 0000
      权值法更快    ： -2^31 + 2^30 + 2^27 = 2^27 × (-16+8+1) = -7 × 2^27

  走 float 这条路（IEEE 754 单精度）
      0xC8000000 = 1100 1000 0000 0000 0000 0000 0000 0000

        1        |  1001 0000  |  000 0000 0000 0000 0000 000
        符号位      阶码 8 位         尾数 23 位（全 0）

      阶码域 = 128+16 = 144，偏置 127 ->  真实阶值 = 144-127 = 17
      尾数全 0 -> 小数部分只剩隐藏的那一位 1 -> 纯 1.0
      X = -1 × 1.0 × 2^17 = -2^17
```

> **易错点**：两处各扣一分就够把整道题送走——补码最高位的权是 $-2^{31}$ 不是 $+2^{31}$；IEEE 754 的阶码域存的是**偏置值**，求真值一定要减 127。

## 大小比较：三种比较法与无符号陷阱

"补码为什么能直接比大小"，这是这一块最值得单独立一节的知识点。

### 原码比较法

最原始的办法：先比符号位，符号位不同则符号位为 1 的那个更小；符号位相同再比数值位。

这就是人读十进制数的思路——先看正负号，再比绝对值。硬件上要两轮比较，而且正负两路要分别设计，因此原码比大小很麻烦。

### 补码比较法

> **结论**：把补码位串当作**无符号二进制数**直接比较，得到的顺序和真值大小顺序**完全一致**。

为什么能成立？两件事凑在一起：

- 所有**非负数**的补码最高位是 0，位串值落在 $0 \sim 2^{n-1}-1$，全都小于任何负数的位串值；
- 所有**负数**的补码最高位是 1，位串值落在 $2^{n-1} \sim 2^{n}-1$。而负数的补码等于 $2^n + x$，$x$ 越负位串值越大。

负数这一半正是关键的直觉翻转：$-2$ 存成 `11111110`，$-1$ 存成 `11111111`，**越小的负数，位串反而越大**——因为它离模 $2^n$ 更远。

```text
  真值 -3 → 补码 11111101
  真值 -2 → 补码 11111110
  真值 -1 → 补码 11111111
  真值  0 → 补码 00000000
  真值  1 → 补码 00000001

  把这些位串当无符号数看：253 < 254 < 255 < 0 ... 等等，255 与 0 一比，
  无符号规则下 0 < 255，说明 0 排在所有负数之后 —— 顺序正好是
  -3 < -2 < -1 < 0 < 1   ✓
```

所以补码比大小根本不需要判符号位，一条无符号比较通路就够了。这是补码相对于原码最大的硬件优势之一。

### 移码比较法

> **结论**：移码位串的大小顺序与真值大小顺序**也完全一致**，直接比较即可，**而且连符号位都不用看**。

原因在移码的定义里：$x \mapsto x + 2^n$。加的是一个固定的正偏置，所以真值的大小顺序原封不动地保留在了位串里。19 年那道大端基址寻址里，地址用补码表示、算完还得判符号；换成移码就能省掉这一步。

移码比较法在浮点硬件里用得极多——阶码、浮点数的绝对值大小比较，基本都靠移码。

### 无符号与有符号混比的陷阱

同一串比特，当无符号看和当有符号看，结果可能天差地别。这两种比较必须分道扬镳：

| 比较类型 | 判据 | 易错点 |
| :--- | :--- | :--- |
| 无符号数之间 | 直接按无符号比，最高位的权是 $+2^{n-1}$ | 别顺手判符号位 |
| 补码（有符号）之间 | 直接按无符号比，顺序自动正确 | 别按绝对值想 |
| 无符号 vs 有符号 | **必须先统一类型**（都转成有符号，或都转成无符号） | 混着比是重灾区 |

真实案例：19 年那道 `unsigned short` 的 $65535$ 转成 `short` 得到 $-1$——这就是"同一位串、两种解释"的典型。同一类事情在 C 语言里到处都是，`char` 到底是有符号还是无符号、`size_t` 和 `int` 比大小，都栽在这条线上。

> **提示**：无符号转有符号，**位串不变、解释变**；有符号转无符号，也是**位串不变、按 $0 \sim 2^n-1$ 重新解释**。两次类型转换同时出现时，先扩展长度，再改解释，这个顺序在 25 年那道里直接决定答案。

### 长串 1 的求和技巧

补码转无符号真值时，常常会遇到一长串 1。硬按位权一个一个加，考场上又慢又容易错。

> **结论**：**一个由 $n$ 个 1 组成的无符号数，值就是 $2^n - 1$。**

掌握这一条，上面 25 年那道 $-32767$ 转 `unsigned int` 就是三步：先写成"32 个全 1 减去一个只有第 1 位为 1 的数"，被减的那个数等于"十五个 1 再减 1"，于是

$$X = (2^{32}-1) - (2^{15}-2) = 2^{32} - 2^{15} + 1 = 4294934529$$

这套"转成全 1 的形式再相减"的打法，是所有"长串 1 求真值"题目的通用解法。

## IEEE 754 浮点格式

### 字段划分

单精度 32 位、双精度 64 位，结构完全一样，只是把阶码和尾数各加宽。

```text
  单精度（32 位）                        双精度（64 位）

   31      23                0           63     52             0
  +--------+------------------+         +-----+----------------+--+
  | 符号位  |   阶码（8 位）   |  尾数   | 符号 |  阶码（11 位）  |尾|
  |  1 位   |   偏置 127      |  23 位  | 1 位 |  偏置 1023      |52|
  +--------+------------------+         +-----+----------------+--+

   隐含的 1 不占位 —— 尾数域存的是小数点之后的部分，
   规格化数的小数点后第一位恒为 1，所以隐藏掉了。
```

单精度的真实值公式：

$$X = (-1)^S \times (1.M)_2 \times 2^{E-127}$$

双精度的偏置是 1023，不是 127。

### 真值转机器数

22 年那道：把 $-0.4375$ 转成 IEEE 754 单精度的十六进制表示。

```text
  第一步：转二进制（按 2 的负次幂从大到小试）
      0.4375 达不到 0.5   -> 2^-1 位 = 0
      够 0.25            -> 2^-2 位 = 1，剩 0.1875
      够 0.125           -> 2^-3 位 = 1，剩 0.0625
      正好 0.0625        -> 2^-4 位 = 1，减完归零
      => 0.4375 = 0.0111 (2)

  第二步：规格化，把小数点挪到最高位 1 之前
      -0.4375 = -0.0111 (2) = -1.11 (2) × 2^(-2)

  第三步：符号位
      真值为负 -> S = 1

  第四步：阶码加偏置
      真实阶值 -2  +  偏置 127  =  125  =  01111101

  第五步：尾数取小数点之后的部分，去掉隐藏的最高位 1
      规格化尾数是 1.11，去掉那个 1 剩 110，后面补 0 到 23 位

  三段拼起来：
      符号位     阶码(8 位)        尾数(23 位)
         1     |   01111101   |   11000000000000000000000

      1 0111 1101 1100 0000 0000 0000 0000 0000  =  BEE00000H
```

### 机器数转真值

25 年那道：`float` 型变量 $X$ 的机器数是 `47300000H`，求 $X$。

```text
  十六进制摊成二进制
      0100 0111 0011 0000 0000 0000 0000 0000

      S         阶码(8)          尾数(23)
      |
      0       10001110          0110000...
              尾数隐含最高位的 1 -> 有效尾数是 1.011 (2)

  符号位 S = 0 -> 正数
  阶码域 = 128 + 8 + 4 + 2 = 142，真实阶值 E = 142 - 127 = 15
  尾数：1.011 (2) = 1 + 1/4 + 1/8 = 1.375

  X = +1.011 (2) × 2^15 = 1.375 × 2^15 = 45056
```

> **易错点**：单精度偏置是 127，双精度才是 1023；尾数前面那个隐藏的 1 千万别漏——漏了答案直接差一倍。

### 精确表示范围：哪些数表示不了

这是这一块最该横向记住的一条主线。IEEE 754 的浮点数是**能精确表示一部分数、不能精确表示另一部分数**的，不是所有数都能塞进去。

核心事实：单精度尾数域 23 位，加上隐藏的 1，一共 **24 位有效数字**。

由此可以推出三条判据：

| 判据 | 结论 |
| :--- | :--- |
| 能被**精确表示的连续整数** | $-2^{24} \sim 2^{24}$，也就是 $\pm 16777216$ |
| 大于 $2^{24}$ 的整数 | **不能精确表示**，误差随数值增大而放大 |
| 十进制有限小数（0.1、0.2、0.3） | **不能精确表示**，因为它们的二进制展开是无限循环小数 |
| 任何需要超过 24 位有效二进制位的数 | 不能精确表示，只能舍入 |

双精度的对应数字是 53 位有效数字，精确表示的连续整数范围是 $\pm 2^{53}$。

规格化单精度浮点数的表示范围大致是：最小非零正数约 $2^{-126}$，最大约 $3.4 \times 10^{38}$。

10 年那道把"不能精确表示"演绎到了极致：`(float)(D + F) - D == F`，其中 $D = 1.5 \times 10^{100}$、$F = 1.56780 \times 10^3$。

浮点数加减**必须先对阶**，而这两个数差了一百个数量级。对阶时小阶的尾数要右移，往十进制算是 97 位，二进制里要移的位数还更多。移完之后 `float` 那 23 位有效数字**全被移出去了**，等于什么都不剩，也就是归零。于是 `(float)(D+F)` 就是 $D$，加零还是 $D$，$D - D = 0$，而右边 $F = 1567.8$，$0 \ne 1567.8$。

这道题真正的陷阱是：很多人顺手把括号去掉，看成"double 减 double、float 等于 float"，然后判它真。**判断成败的依据是对阶，不是类型宽度。**

> **结论**：10 年那道题里为真的是"int → float → int"和"float → double → float"两条。前者不会溢出（`float` 范围远大于 `int`），10 位二进制完全放得下 785，24 位有效位不会丢精度；后者是类型提升，范围更大精度更高，再转回来自然一模一样。而"float → int → float"这条假在小数上：1567.8 变 1567，小数点后面那 0.8 就永久没了。

### 规格化与特殊值

规格化的意思是：**尾数的小数点后第一位必须是 1**。这样才能保证表示精度不浪费，也才能把隐藏位的假设坐实。

用双符号位写出来很直观：

```text
  正规格化：00.1xxx...   符号位 00，最高位是 1
  负规格化：11.0xxx...   符号位 11，最高位是 0

  （补码下负数的规格化形态和正数相反，
    符号位与最高数值位必须"不同"才叫规格化）
```

阶码全 0 和全 1 被保留下来做特殊用途：

| 阶码域 | 尾数域 | 含义 |
| :--- | :--- | :--- |
| 全 0 | 全 0 | 真值 0（机器零） |
| 全 0 | 非 0 | **非规格化数**，阶值按 $-126$ 处理 |
| 全 1 | 全 0 | 无穷大 |
| 全 1 | 非 0 | NaN |

> **易错点**：非规格化数（尾数最高位不是 1）表示的数精度很差，只在阶码下溢时用来兜底。判断一个浮点数是不是规格化，看尾数最高位就够，不需要看阶码。

### 浮点加减：对阶、右规与阶码上溢

09 年那道双符号位浮点加法是这一块最经典的陷阱题：阶码和尾数均用补码表示，位数分别是 5 位和 7 位（各含 2 位符号位），$X = 2^7 \times \frac{29}{32}$，$Y = 2^5 \times \frac{58}{64}$，求 $X + Y$。

先把两个数规格化：

```text
  29/32 = 0.11101 (2)     58/64 = 0.11101 (2)     （两者真值相同，阶码不同）

  X = 2^7 × 0.11101        阶码 00111   尾数 00 11101
  Y = 2^5 × 0.11101        阶码 00101   尾数 00 11101
```

对阶——**小阶向大阶看齐**，阶码小的那个尾数右移：

```text
  X 的阶码是 7，Y 的阶码是 5 -> Y 向 X 对齐

  Y 阶码 00101 + 2 = 00111
  Y 尾数 00 11101 右移 2 位 -> 00 00111     （移出的低位舍弃）

  对阶后：X = 2^7 × 0.11101     Y = 2^7 × 0.00111
```

尾数相加，用双符号位看溢出：

```text
      00 11101          X 尾数
    + 00 00111          Y 对阶后
    ------------
      01 00100          符号位变成 01 -> 尾数溢出，必须右规
```

右规：尾数右移一位，阶码加 1。

```text
  尾数 01 00100 -> 右移一位 -> 00 10010
  阶码 00111   -> 加 1     -> 01000        ← 双符号位变成 01，阶码上溢！
```

所以最终结果：**阶码上溢**，这次加法溢出了。

> **易错点**：双符号位的两个符号位一旦不同（`01` 或 `10`），就代表溢出。这时候必须分清是**尾数溢出**（还能右规、阶码加 1）还是**阶码本身溢出**（阶码已经顶到双符号位下的最大值，再加 1 就没救了）。09 年这道属于后者——右规那一步的阶码加 1，正好把 `00111` 顶成了 `01000`。

对阶这一步本身也有代价：**永远会有精度损失**，因为小阶数的低位在右移时被直接丢掉了。所以浮点加减是"不精确"的运算，误差主要就来自这里。

## 机器字长与部件位数

### 定义

> **定义**：机器字长是指计算机进行一次**定点整数运算**所能处理的二进制数据的位数。

定义里"定点整数"这四个字是要命的——它直接说明机器字长**和浮点数之间没有任何关系**。

### 谁等于机器字长

**通用寄存器组**和 **ALU**：数据从通用寄存器出来，经 ALU 的 A、B 两端进去，出来的是运算结果。既然一次能处理的位数就是字长，ALU 的两个端口就得跟字长一样；寄存器为了喂得上这个端口，长度自然也是字长。

```text
     ┌──────────────────┐
     │   通用寄存器组   │   位数 = 机器字长
     │   x1   x2   x3   │
     └────────┬─────────┘
              │ 待运算数据送进来
              ▼
     ┌──────────────────┐
     │ ALU 的 A、B 两端 │   位数 = 机器字长
     └────────┬─────────┘
              ▼
           运算结果
```

### 谁不等于机器字长

**指令寄存器 IR**：它存的是指令，指令内容的长度叫**指令字长**。指令字长和机器字长之间没有等价关系，它由指令的长度决定。更根本的原因是，指令不需要 ALU 去算，它会被直接送进译码器去译码——**数据走 ALU，指令走译码器，两条路分开算**。

**浮点寄存器**：里面存的是 IEEE 754 格式，跟定点数的存储方式完全不是一回事，跟字长无关。

> **提示**：这个判断题的口诀是：**凡是需要参与运算的，位数跟字长一致；凡是只负责存指令或存浮点格式的，与字长无关。**

## 数据的存储布局：大小端与边界对齐

这一块 19 年、20 年、25 年各考了一道，全部是"给一个结构体或一个机器数，问某个字节落在哪个地址"。套路完全一样，只是换了外壳。

### 大端与小端

> **定义**：**大端**把最高有效字节放低地址；**小端**把最低有效字节放低地址。

```text
  32 位机器数 12 34 56 78H（字节编址）

  大端（高位字节在低地址）
   +---------+---------+---------+---------+
   |  地址 n |  地址n+1| 地址n+2| 地址n+3|
   +---------+---------+---------+---------+
   |   12H   |   34H   |   56H   |   78H   |
   +---------+---------+---------+---------+
    高有效字节                            低有效字节

  小端（低位字节在低地址）
   +---------+---------+---------+---------+
   |  地址 n |  地址n+1| 地址n+2| 地址n+3|
   +---------+---------+---------+---------+
   |   78H   |   56H   |   34H   |   12H   |
   +---------+---------+---------+---------+
    低有效字节                            高有效字节
```

> **易错点**：小端的定义只有一句话——**低位字节放低位地址**。看图觉得"高有效字节放高地址"特别反直觉，这正是这类题最爱设的陷阱。

### 大端还要叠加符号扩展和地址计算

19 年那道把大端和基址寻址、符号扩展串在一起：某机采用**大端**按字节编址，某指令操作数的机器数是 `1234FF00H`，采用**基址寻址**，地址用补码表示，基址寄存器内容是 `F0000000H`，形式地址是 `FF12H`，问操作数**最低有效字节**所在地址。

**第一步：求有效地址。** 形式地址 `FF12H` 是用补码表示的，也就是说它是个**负数**。做加法位数必须对齐，所以先把 16 位补码符号扩展到 32 位：

```text
  基址寄存器   F0000000H
  形式地址     FF12H  ->  符号扩展  ->  FFFFFF12H
                F0000000H
              + FFFFFF12H
              ----------------
                EFFFFF12H   （最高位进位丢弃）

  首地址 EA = EFFFFF12H
```

**第二步：按大端排字节。** 大端的规矩是最高有效字节放低地址。

```text
  机器数 1234FF00H，从高到低是 12、34、FF、00

  +-------------+---------+---------+-------------+
  | 地址         | 地址    | 地址    | 地址        |
  +-------------+---------+---------+-------------+
  | EFFFFF12H   |EFFFFFF13H|EFFFFF14H|EFFFFF15H   |
  +-------------+---------+---------+-------------+
  |    12H      |   34H   |   FFH   |    00H      |
  +-------------+---------+---------+-------------+
   最高有效字节                             最低有效字节
```

所以最低有效字节在 `EFFFFF15H`。

> **易错点**：这道题两处都容易翻车。一是忘记符号扩展，直接拿 `F0000000H + FF12H` 算，结果差了一整个 16 位；是大端小端记反——换成小端的话，最低有效字节反而就落在首地址 EA 上。

### 边界对齐与填充

> **定义**：边界对齐要求每个成员变量从**自己大小的整数倍地址**开始存放。放不下时插入**填充字节**（padding）把它顶到下一个合法地址。

20 年那道：32 位机器按字节编址、采用小端，结构体里有 `short x1`（2 字节）和 `int x2`（4 字节），A 的首地址是 `2020F100H`，$x_2$ 的机器数是 `12340000H`，问 `34H` 所在的存储单元地址。

先把数据按地址摊开：

```text
   地址            存放内容
  ──────────────────────────────────────────────
   2020F100H       x1 的高字节   ┐
   2020F101H       x1 的低字节   ┘  short 占 2 字节
   2020F102H       填充（空）    ┐
   2020F103H       填充（空）    ┘  不是 4 的倍数，放不下 int
   2020F104H       00H           ┐
   2020F105H       00H           │  x2 = 12340000H
   2020F106H       34H           │  小端：高有效字节 12H 落最高地址
   2020F107H       12H           ┘
```

`F102H` 和 `F103H` 都不是 4 的倍数，int 放不下，只能填充；$x_2$ 只能从 `F104H` 开始。小端存放，高有效字节 `12H` 落在最高地址 `F107H`，顺低位往低位地址方向推下去：`F106H` 是 `34H`。

所以答案是 `2020F106H`。

> **结论**：边界对齐管的是"**从哪儿开始放**"，小端大端管的是"**谁放高位**"。这是两条独立的规矩，答题时分开处理，绝不能混。

### 结构体大小与数组步长

25 年那道更进一步，问的是**结构体数组**里某个字节的地址：32 位计算机按字节编址、小端方式，结构体成员依次是 `int id`（4 字节）、`char name[10]`（10 字节）、`int salary`（4 字节），数组 `apply` 有 200 个元素，`apply[0]` 首地址 `0000A0B0H`，`apply[1]` 的 `id` 机器数是 `12345678H`，求 `56H` 所在地址。

先画一个元素的骨架：

```text
  +--------------+--------------------+---------+------------------+
  | id (int, 4B) | name (char[10],10B)| 填充2B  | salary (int, 4B) |
  +--------------+--------------------+---------+------------------+
   ^A0B0H         ^A0B4H               ^A0BEH   ^A0C0H        ^A0C3H
```

排布过程：

- `id` 占 `A0B0 ~ A0B3`；
- `name` 占 10 个字节，从 `A0B4` 排到 `A0BD`，一格都不能少；
- 下一个地址是 `A0BE`，$0xBE = 190$ 不是 4 的倍数；`A0BF` 也不行。所以这两格只能**填充**；
- `salary` 落到 `A0C0 ~ A0C3`。

| 地址 | 存放内容 |
| --- | --- |
| A0B0 ~ A0B3 | `apply[0].id` |
| A0B4 ~ A0BD | `apply[0].name`（10 字节） |
| A0BE、A0BF | 填充 |
| A0C0 ~ A0C3 | `apply[0].salary` |

**算结构体总大小**，这一步决定下一个元素从哪开始：

```text
  id       贡献  4 字节
  name     贡献 10 字节，但为了让 salary 对齐被塞进 2 字节填充 -> 这一段实际占 12
  salary   贡献  4 字节

  结构体大小 = 4 + 12 + 4 = 20 (B)

  20 既是最大成员 name[10] 的 10 的倍数，
      也是最大对齐量 4 的倍数 -> 正好收尾，无需尾部填充

  apply[1] 首地址 = A0B0H + 20 = 0000A0C4H
```

> **结论**：因为它是**结构体数组**，每个元素都是一个结构体，所以**一个元素的大小就是一个结构体的大小**，20 字节。下一个元素对齐着接在后面。

`apply[1].id` 从 `A0C4` 开始占 4 格。小端低位字节放低地址：

```text
  +---------+---------+---------+---------+
  | A0C4H   | A0C5H   | A0C6H   | A0C7H   |
  +---------+---------+---------+---------+
  |  78H    |  56H    |  34H    |  12H    |
  +---------+---------+---------+---------+
    低有效                       高有效字节
```

所以 `56H` 在 `0000A0C5H`。

> **结论**：结构体大小 $=$ 各成员大小之和 $+$ 中间填充 $+$ 尾部填充。一个结构体数组的步长就等于单个结构体的大小——这是数组题和布局题合起来考时的固定套路。
