# 内存管理与连续分配

## 内存管理的四大功能

* **内存管理（Memory Management）**

    * > **定义**：操作系统作为系统资源管理者，对内存这种资源进行分配、回收、扩充、转换与保护的管理工作。

    * 内存空间的**分配与回收**：进程投入运行需先放入内存；内存中有的区域已分配、有的空闲，要决定新进程放在哪个位置，进程结束后回收其占用的空间。

    * 内存空间的**扩充**：实际内存不够所有进程使用时，提供从逻辑上扩充内存空间的技术，把物理上很小的内存逻辑扩充为很大的内存——这是操作系统**虚拟性**的体现。典型现象：4GB 内存能运行大小超过 60GB 的游戏。

    * **地址转换**：把逻辑地址转换为物理地址（地址重定位）。

    * **内存保护**：保证各进程在各自的存储空间内运行、互不干扰。

* **逻辑地址与物理地址**

    * > **定义**：程序员写程序时只需关注指令和数据的逻辑地址；逻辑地址到物理地址的转换由操作系统负责，使程序员不必关心底层硬件细节。

## 地址转换的三种装入方式

| 装入方式 | 转换时机 | 谁来完成 | 使用时期 |
| :--- | :--- | :--- | :--- |
| 绝对装入 | 编译时产生绝对地址 | 编译器 | 单道程序阶段（尚无操作系统） |
| 可重定位装入（静态重定位） | 装入时 | 装入程序（属于操作系统） | 早期的多道批处理系统 |
| 动态运行时装入（动态重定位） | 运行时 | 需要重定位寄存器的硬件支持 | 现代操作系统 |

* **绝对装入**

    * 编译时就产生绝对地址，或程序员直接写绝对地址。

    * 单道程序阶段尚未产生操作系统，这种"转换"由编译器完成，不归操作系统管。

* **可重定位装入（静态重定位）**

    * 装入时把逻辑地址转换为物理地址，由装入程序（操作系统的一部分）完成。

* **动态运行时装入（动态重定位）**

    * 运行时才把逻辑地址转换为物理地址，一般需要硬件**重定位寄存器**的支持；现代操作系统采用的方式，页式、段式存储大量使用。

    * 操作系统实现地址转换只用可重定位装入和动态运行时装入两种方式。

## 内存保护

* **内存保护（Memory Protection）**

    * > **定义**：保证各个进程在各自的存储空间内运行、互不干扰——进程只能访问自己那块内存空间，不能访问操作系统的内存区域，也不能修改其他进程的数据。

* **上下限寄存器方案**

    * 在 CPU 中设置一对**上限寄存器**和**下限寄存器**，分别存放进程内存空间的上限与下限。

    * 指令要访问某个内存单元时，CPU 拿目标地址与上下限比较，只有落在两者之间才允许访问。

* **重定位寄存器 + 界地址寄存器方案**

    * **重定位寄存器**又称**基址寄存器**，存放进程的起始**物理**地址；**界地址寄存器**又称**限长寄存器**，存放进程的最大**逻辑**地址。

    * 访问流程：先拿逻辑地址与界地址寄存器中的最大逻辑地址比较，超过即抛出**越界异常**；未越界则将逻辑地址与重定位寄存器中的起始物理地址相加，得到最终物理地址。例：起始物理地址 100、最大逻辑地址 179，访问逻辑地址 80 得到物理地址 80 + 100 = 180。

    * > **易错点**：重定位寄存器（基址寄存器）存的是起始**物理**地址，界地址寄存器（限长寄存器）存的是最大**逻辑**地址，两者存的内容不要搞混；两个别名也可能出现在考题里。

## 进程的内存映像

* **进程内存映像 / 虚拟地址空间**

    * > **定义**：一个进程运行时在内存中的布局。以 32 位系统为例，每个进程拥有 4GB 虚拟地址空间（$2^{32} = 4$GB），范围 0x00000000 ~ 0xFFFFFFFF。

    * 高地址的 1GB 是**内核区**：存放操作系统内核数据（进程的 PCB、页表）与内核代码（如进程调度代码）；普通程序只能访问用户区数据，不能直接访问内核区。

* **用户区布局（自低地址向高地址）**

    * **保留区**：不使用。

    * **只读代码与只读数据**：存放编译链接后得到的机器指令，运行时只能读不能写；`const` 修饰的**常变量**值在运行中不可改变，也存储在这片区域。

    * **读写数据区**：存放全局变量（定义在函数之外）和 `static` 修饰的静态变量，可读可写。

    * **堆（heap）**：凡用 `malloc` / `free` 处理的数据都存放在堆区；大小可动态增减。32 位系统中堆最多到 0x40000000，堆加上三片数据区域总共只有 1GB，所以能 malloc 多少取决于下面两片数据区域的大小。

    * **共享库的存储映射区**：存放系统提供的库函数的指令代码（如 `printf`）；用的库函数越多，这片区域越大、越向上增长。

    * **用户栈**：存放所有与函数调用相关的数据（每层函数的局部变量、调用参数、上一层函数的信息）；调用层数越多越向下增长。

    * 只读区、读写数据区在**进程启动时即可确定大小，且整个运行期间固定不变**；堆与栈动态增减，两者之间的空闲部分是它们各自的增长空间——堆向上增长、栈向下增长。

    ```text
    0xFFFFFFFF ┌─────────────────────────────┐
               │ 内核区（1GB）                 │
               │ PCB、页表、内核代码            │
    0xC0000000 ├─────────────────────────────┤
               │ 用户栈：函数调用信息、局部变量   │
               │        ↓ 调用层数越多越向下长   │
               │      （空闲，是栈的增长空间）    │
               │ 共享库存储映射区：库函数代码     │
               │        ↑ 用的库函数越多越向上长 │
               │      （空闲，是堆的增长空间）    │
    0x40000000 ├─────────────────────────────┤
               │ 堆：malloc/free 处理的数据     │
               ├─────────────────────────────┤
               │ 读写数据区：全局变量、静态变量   │
               ├─────────────────────────────┤
               │ 只读代码与只读数据：指令、const │
               ├─────────────────────────────┤
               │ 保留区（不使用）               │
    0x00000000 └─────────────────────────────┘
    ```

* **宏常量不占内存**

    * > **易错点**：宏定义的常量不会在内存中分配专门的存储空间——预编译阶段编译器把宏名替换为字面值，该值被隐含到程序指令当中（类似立即数寻址）；只有 `const` 定义的常变量才存储到只读数据区。

    * > **提示**：典型考察形式是给出一段 C 语言代码，问某个变量存储在内存映像的哪一片区域。

## 覆盖技术

* **覆盖技术（Overlay）**

    * > **定义**：解决**程序大小超过物理内存总和**问题的技术——把程序分成多个段，常用的段常驻内存，不常用的段只在需要时调入；属于从逻辑上扩充内存的手段。

    * 适用背景：早期计算机内存很小（如早期个人计算机只支持 1MB 内存），无法装下上百 MB 的程序。

    * 内存划分为**固定区**与若干**覆盖区**：常用段放固定区，调入后不再调出，直到运行结束；不常用段放覆盖区，需要时调入、用不到时调出。

* **覆盖区大小的确定**

    * 覆盖区大小按**共享该覆盖区的各段中的最大者**确定。

    * 例：程序 X 中 A（8KB，含 main）依次调用 B（8KB）与 C（10KB）——依次调用意味着 B、C 不可能同时被访问，可共享一个覆盖区，大小取 10KB；B 调用 D（12KB），C 依次调用 E（10KB）、F（4KB），D、E、F 也不可能同时使用，共享另一个覆盖区，大小取 12KB。

    ```text
                 A（8KB，含 main）
                /              \
           B（8KB）          C（10KB）
             |               /     \
          D（12KB）      E（10KB）  F（4KB）

    固定区   8KB   → 常驻 A，调入后不再调出
    覆盖区 0  10KB  → 需要谁调入谁（B 或 C）
    覆盖区 1  12KB  → 需要谁调入谁（D 或 E 或 F）
    ```

    * 上例不用覆盖需 52KB（8+8+10+12+10+4）内存，采用覆盖后只需 30KB（8+10+12），从逻辑上看物理内存被拓展了。

* **缺点**

    * 程序的调用结构操作系统不知道，必须由程序员**显式声明**，操作系统再根据声明的覆盖结构完成自动覆盖——**对用户不透明，增加用户编程负担**。

    * 现在已很少使用，一般只用于早期的操作系统。

## 交换技术

* **交换技术（Swapping，又称对换技术）**

    * > **定义**：内存空间紧张时，把内存中某些进程的数据暂时**换出**到外存，把外存中已具备运行条件的进程**换入**内存；进程在内存与磁盘之间动态调度，同样在逻辑上扩充了内存空间。

    * **中级调度**（也叫**内存调度**）就是为交换技术服务的调度策略：负责选择一个处于外存的进程、把它换入内存。

    * 进程被换出后，PCB 保留在内存中并插入**挂起队列**；PCB 中记录了进程数据在外存的存放位置，操作系统据此管理换出的进程——所谓"换出进程"并不是把所有数据全部调到外存。

    * 换出外存等待的进程处于**挂起态**，进一步分为**就绪挂起**（原本处于就绪态）与**阻塞挂起**（原本处于阻塞态）；引入后形成进程的**七状态模型**。

* **对换区的位置：文件区与对换区**

    * 具有对换功能的操作系统一般把磁盘分为**文件区**与**对换区**；被换出的进程数据存放在**对换区**。

    | 区域 | 用途 | 追求目标 | 分配方式 |
    | :--- | :--- | :--- | :--- |
    | 文件区 | 存放文件 | 存储空间的利用率 | 离散分配 |
    | 对换区 | 存放被换出的进程数据 | 换入换出的速度 | 连续分配 |

    * 对换区空间通常只占磁盘很小一部分，但换入换出速度直接影响各进程并发执行的速度；**对换区的 I/O 速度比文件区更快**，换出放对换区、换入也从对换区换回。

* **交换的时机**

    * 一般发生在许多进程运行、**内存吃紧**时，换出一些进程腾空内存，直到系统负荷明显降低再暂停。

    * 例：许多进程频繁发生**缺页**说明内存不够用，可换出进程；缺页率明显下降即系统负荷降低，暂停换出。

* **换出哪些进程**

    * 优先换出**阻塞态**进程——就绪态进程随时可投入运行，阻塞态进程即使留在内存也暂时运行不了。

    * 优先换出**优先级低**的进程。

    * 但每次都换出低优先级进程，可能导致其刚调入内存很快又被换出，造成低优先级进程的**饥饿**；有的系统因此考虑进程在内存中的**驻留时间**，驻留太短的暂时不换出。

    * PCB 常驻内存、不会被换出。

## 覆盖与交换的区别

* 覆盖是在**同一个程序（进程）内部**进行的：腾地方的是同一程序内不可能同时访问的程序段。

* 交换是在**不同进程（作业）之间**进行的：暂时运行不到的进程调出外存，紧急的进程优先放回内存。

* > **提示**：覆盖与交换一般只在选择题中考察。需要记忆的要点：固定区的程序段运行中不会被调出，覆盖区的程序段运行中可能按需调入调出；覆盖技术的缺点（对用户不透明、增加编程负担）常作为选项出现。

## 连续分配方式

* **连续分配 / 非连续分配**

    * > **定义**：连续分配指系统为用户进程分配的**必须是一个连续的内存空间**；非连续分配下为用户进程分配的内存空间可以是离散的。这是贯穿内存管理章节的分界线。

    * 连续分配分三种：单一连续分配、固定分区分配、动态分区分配。

## 单一连续分配

* **单一连续分配**

    * > **定义**：把内存分为**系统区**（存放操作系统数据）和**用户区**（存放用户程序数据），同一时刻只能有一道用户程序、不支持多道程序并发的最朴素分配方式。

    * 用户程序独占整个用户区：程序再小，用户区其他空闲部分也不分给别的程序。

* **优点**

    * 实现简单，**无外部碎片**。

    * **不一定需要内存保护**——只跑一个用户程序，它出问题只影响自己；早期个人操作系统、微软的 DOS 就没有采用内存保护（只是"不一定"，有的系统也会设越界检查）。

* **缺点**

    * 只适用于**单用户、单任务**的操作系统，不支持多道程序并发。

    * 产生**内部碎片**：分给进程但没用上的部分（程序很小、用户区很大时尤其严重），**存储器利用率很低**。

## 固定分区分配

* **固定分区分配（Fixed Partitioning）**

    * > **定义**：把用户区划分成若干**固定大小**的分区，每个分区只能装入一道作业——**最早的可支持多道程序的内存管理方式**。

    * 分为**分区大小相等**与**分区大小不等**两种策略。

* **分区大小相等**

    * 把用户区切成若干大小相同的固定分区（如每区 10MB）。

    * 缺乏灵活性：小进程也要占一个大了许多的分区；大进程所有分区都装不下，只能靠覆盖技术逻辑拓展分区——但覆盖会增加系统开销。

    * 在现代仍有广泛用途：如钢铁厂 $n$ 个相同的炼钢炉，把内存分成 $n$ 个等大分区、放入 $n$ 个相同的控制程序并发控制各炉，这种场景非常合适。

* **分区大小不等**

    * 灵活性增加：小进程分小分区、大进程分大分区。

    * 划分依据：先估计系统里大作业、小作业各占多少，按比例划分——**多个小分区、适量的中等分区、少量的大分区**。

* **分区说明表**

    * 操作系统用**分区说明表**记录各分区：每个表项对应一个分区，记录分区大小、起始地址、是否已分配的状态。

    * 用户程序装入时，操作系统检索该表，找到一个大小满足需求且未分配的分区，分配后把对应表项状态改为"已分配"。

* **优缺点**

    * 优点：实现不复杂，**无外部碎片**。

    * 缺点：程序太大、没有任何分区能装下时只能靠覆盖技术，降低性能；产生**内部碎片**（程序要 10MB、被装进 12MB 的分区，多出的 2MB 即内部碎片），内存利用率不高。

## 动态分区分配

* **动态分区分配（又称可变分区分配）**

    * > **定义**：不预先划分内存，在**进程装入内存时才根据进程大小动态建立分区**，每个分区大小正好适合进程需要；内存分区的**大小和数目都是可变的**。

    * 例：内存 64MB，系统区 8MB、用户区 56MB；进程一占 20MB、进程二占 14MB、进程三占 18MB，剩 4MB 空闲分区。

    ```text
    64MB 内存（系统区 8MB + 用户区 56MB）
    +------------+--------------+--------------+--------------+--------+
    |   系统区    |    进程一     |    进程二     |    进程三     |  空闲   |
    |    8MB     |     20MB     |     14MB     |     18MB     |  4MB   |
    +------------+--------------+--------------+--------------+--------+
    ```

* **核心三问题**

    * 用什么**数据结构**记录内存使用情况。

    * 多个空闲分区都能满足需求时，把**哪个分区**分给进程——动态分区分配算法。

    * 如何进行分区的**分配与回收**（如回收的分区是否与相邻分区合并）。

* **空闲分区表与空闲分区链**

    * **空闲分区表**：每个表项记录一个空闲分区的大小、起始地址等信息；没出现在表里的分区就是已分配出去的。

    * **空闲分区链**：在每个分区的**起始部分和末尾部分**分别设置指向前一个、后一个空闲分区的指针，以类似链表的方式链接；分区大小、起始地址、结尾地址等信息统一放在分区起始部分。

* **分配操作（以空闲分区表为例，链的操作类似）**

    * 空闲分区比申请空间大：从该分区中摘出一部分分配，分区数量不变，只修改对应表项的**分区大小和起始地址**。

    * 空闲分区恰好等于申请空间：整个分区分出去，空闲分区数量减一，**删除**对应表项（用空闲分区链则删对应链节点）。

* **回收操作的四种情况**

    | 回收区与空闲分区的关系 | 处理方式 |
    | :--- | :--- |
    | 仅后面有相邻空闲分区 | 与后邻分区合二为一，更新该表项的大小和起始地址 |
    | 仅前面有相邻空闲分区 | 与前邻分区合二为一，更新对应表项 |
    | 前后都有相邻空闲分区 | 三块合并为一块，空闲分区数减一，更新相应表项信息 |
    | 前后都没有相邻空闲分区 | 新增一个空闲分区表表项 |

    * 本质一句话：**回收内存分区时，只要发现有空闲分区相邻，就必须把相邻的空闲分区全部合并**（四种情况在真题中出现过，记住这条本质即可）。

    * 空闲分区表一般按**起始地址先后**排列，但不绝对——具体怎么排通常由所采用的动态分区分配算法决定（有时从大到小方便、有时从小到大、有时按起始地址）。

## 内部碎片与外部碎片

* **内部碎片（Internal Fragmentation）**

    * > **定义**：分配给某个进程的内存区域中**没有被用上**的部分——前提是"分配给了这个进程、但它没有用上"。

* **外部碎片（External Fragmentation）**

    * > **定义**：内存中某些空闲分区**由于太小而难以利用**——各进程需要的是一整片连续内存，空闲分区太小的话任何一个都满足不了进程需求。

    * 产生过程：进程一（20MB）、二（14MB）、三（18MB）依次进入后剩 4MB 空闲；进程二换出空出 14MB，进程四到达占 4MB 剩 10MB；进程一换出空出 20MB，进程二换回占走 14MB 剩 6MB。此时进程一想换回，内存中 6MB、10MB、4MB 的空闲区间没有一个能满足它。

    * 要害：空闲区间总和 $6 + 10 + 4 = 20$MB，**总量满足进程一需求**，只是不连续——这种"暂时没分配给任何进程、却因太小没法用"的空闲分区就是外部碎片。

* **紧凑技术（拼凑/紧凑/拼接技术）**

    * > **定义**：把内存中各个进程挪位、全部攒到一起，挪出一块更大的连续空闲区间，以解决外部碎片问题。

    * 整套流程依靠**换入换出技术**与**中级调度**配合实现。

    * 三种装入方式中**动态重定位**最方便实现进程在内存中移动，紧凑技术采用动态重定位；紧凑后需修改各进程的起始地址，该信息存放在进程的 **PCB** 中，进程上 CPU 运行前把起始地址放入**重定位寄存器**（基址寄存器）。

* **各分配方式的碎片情况**

    * 单一连续分配与固定分区分配都**不会产生外部碎片**——这两种方式下不会出现"没被分配出去、又因太小无法利用"的空闲区间；它们的碎片都是**内部碎片**。

    * > **易错点**：这个知识点常在选择题里考，不能死记硬背，必须理解各分配方式的规则后自己分析有没有内部碎片、有没有外部碎片；紧凑技术也曾作为选择题选项考察。

## 首次适应算法

* **首次适应（First Fit）**

    * > **定义**：空闲分区按**地址递增**次序排列，每次从**低地址（链头）**开始查找，找到**第一个**能满足大小的空闲分区进行分配。

    * 例：进程要 15MB，从链头找到第一个 20MB 分区，摘出 15MB 剩 5MB，修改对应节点的分区大小、起始地址；再来一个进程要 8MB，仍从链头查起，第一个分区不满足、第二个 10MB 分区满足，摘 8MB 剩 2MB。

* **特点**

    * 算法开销小：分配/回收后分区大小变化，只要保持地址递增就**不需要重新排序**。

    * 缺点：每次都从链头查起，**低地址部分**会留下很多小的难利用的碎片，且每次查找都要经过它们，**增加查找开销**。

    * 但这一规则也隐含优点：只要低地址有更小的分区能满足需求就优先用掉低地址小分区，**高地址的大分区更有可能被保留**——隐含了一点最佳适应的优点。

## 最佳适应算法

* **最佳适应（Best Fit）**

    * > **定义**：空闲分区按**容量递增**次序排列，每次从链头查找，找到**第一个**能满足大小的分区——按容量递增排序后，第一个能满足的分区一定是"能满足的里面最小的"，由此优先使用更小的空闲区间，保住大片连续空间给大进程。

    * 动机：动态分区分配是连续分配，必须给进程一整片连续区域；为保证大进程到来时有**大片的连续空间**可用，应尽可能留下大片空闲区间。

    * 例：空闲分区 4MB、10MB、20MB 按容量递增链接；进程要 9MB，摘自 10MB 分区剩 1MB——这 1MB 比链头 4MB 还小，**必须对整条空闲分区链重新排序**把 1MB 挪到链头；再来进程要 3MB，从链头 4MB 摘 3MB 剩 1MB，更新后链仍递增，不需重排。

* **缺点**

    * 每次都选**最小的**能满足的分区，留下**越来越多很小、很难利用的内存块**——如两个 1MB 碎片，若所有进程都要 2MB 以上，这些碎片就难以利用。

    * 会产生**很多外部碎片**。

    * 算法开销大：为保证容量递增排列，常需对整个空闲分区链重新排序。

## 最坏适应算法

* **最坏适应（Worst Fit）**

    * > **定义**：与最佳适应相反——每次分配**优先使用最大的**连续空闲区，使分配后剩余部分不会太小；空闲分区按**容量递减**次序排列，每次顺序查找取第一个满足要求的分区。

    * 由于递减排列，**链头第一个分区一定能满足要求**——第一个都满足不了，后面更小的肯定也不满足。

    * 例：空闲分区 20MB、14MB 递减排列；进程要 3MB，摘自 20MB 剩 17MB；再来要 9MB，摘自 17MB 剩 8MB；更新后链变为 14MB、8MB，不再是递减排列，需**重新排序**恢复容量递减。

* **缺点**

    * 解决了最佳适应碎片多的问题，却制造了新问题：每次选最大分区，大分区被不断切割成小分区——之后若来了一个 20MB 的大进程，就没有连续大分区可用，大进程**无处安放**。

    * 算法开销大：常需重排链表。

## 邻近适应算法

* **邻近适应（Next Fit）**

    * > **定义**：为解决首次适应的问题而提出——空闲分区按**地址递增**排列（可排成**循环链表**方便从头接尾检索），每次从**上一次查找结束的位置**开始往后查找，找到第一个大小满足的空闲分区。

    * 动机：首次适应每次从链头查，低地址小碎片拖慢每次查找、增加开销；从上次结束位置继续查可绕开这个问题。

    * 例：空闲分区按地址递增排成循环链表（4MB、6MB、1MB、10MB）；进程要 5MB，从链头查，4MB 不满足、6MB 满足，摘 5MB 剩 1MB；再来进程要 5MB，从上次位置继续，1MB 不满足、10MB 满足，摘 5MB 剩 5MB——换成首次适应则要从链头一路查到 10MB，邻近适应只查了两次。

* **特点**

    * 算法开销小：与首次适应一样只要求地址递增排列，分区大小变化后**不需要重新排序**——这是它和首次适应比最佳、最坏适应好的地方。

    * 缺点：低地址、高地址的分区被使用的概率相同，与首次适应相比**高地址的大分区更有可能被用掉、被切成小分区**，大进程到来时可能没有连续空闲分区可分——隐含了一点最坏适应的缺点。

    * > **易错点**：邻近适应并不是就比首次适应优秀很多——它换来的是大分区被更快用掉的新问题。

## 四种算法对比

| 算法 | 空闲分区排列 | 每次查找起点 | 算法开销 | 主要问题 |
| :--- | :--- | :--- | :--- | :--- |
| 首次适应 | 地址递增 | 链头 | 小 | 低地址端积累小碎片、增加查找开销，但综合效果最好 |
| 最佳适应 | 容量递增 | 链头 | 大，常需重排链表 | 留下大量难以利用的外部碎片 |
| 最坏适应 | 容量递减 | 链头 | 大，常需重排链表 | 大分区不断被切小，大进程无处安放 |
| 邻近适应 | 地址递增（循环链表） | 上次结束位置 | 小 | 高地址大分区更可能被用掉，隐含最坏适应的缺点 |

* "算法开销"指的是：为保证空闲分区按规定次序排列，最佳、最坏适应可能**经常对整个空闲分区链重新排序**，开销大；首次、邻近适应不需要重排，开销小。

* 四种算法当中，**首次适应算法的综合效果最好**。

* > **提示**：这一部分很容易作为选择题考察，甚至可能出大题；理解了各算法的核心思想，排列方式、优点、缺点都能自行推导，再通过课后习题动手巩固。
