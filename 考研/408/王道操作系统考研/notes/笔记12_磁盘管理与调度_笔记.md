# 磁盘管理与调度

## 磁盘读写时间组成

* **寻道时间（Seek Time）**

    * > **定义**：把磁头移动到指定磁道所花的时间，$T_s = s + m \times n$。

    * $s$ 是启动磁头臂的时间，$m$ 是磁头每跨越一条磁道的时间，$n$ 是跨越的磁道数。

    * 典型数值：每移动一个磁道约 0.2ms，磁臂启动时间约 2ms。

* **延迟时间（Rotational Delay）**

    * > **定义**：通过旋转磁盘，把目标扇区转到磁头下面所需的时间。

    * 设磁盘转速为 $r$ 转/秒，转一圈需 $\frac{1}{r}$；定位到目标扇区平均只需转半圈：

    $$T_{延迟} = \frac{1}{r} \times \frac{1}{2} = \frac{1}{2r}$$

    * 机械硬盘典型转速：5400 转/分钟或 7200 转/分钟；转速越高，延迟时间越小，读写越快。

* **传输时间（Transfer Time）**

    * > **定义**：从磁盘读出或向磁盘写入数据本身所经历的时间。

    * 设转速为 $r$ 转/秒、每磁道存放 $n$ 字节、本次读写 $b$ 字节，则数据分布在 $\frac{b}{n}$ 条磁道上，每读写一条磁道耗时一圈：

    $$T_{传输} = \frac{1}{r} \times \frac{b}{n} = \frac{b}{rn}$$

* **总时间**

    $$T = T_s + T_{延迟} + T_{传输}$$

    * 延迟时间与传输时间都与转速 $r$ 线性相关，但转速是硬盘的固有硬件属性，操作系统无法用软件优化这两部分时间。

    * 操作系统唯一能影响的是**寻道时间**——不同磁盘调度算法会让寻道时间产生巨大差异。

## 先来先服务（FCFS）

* **先来先服务（First Come First Served，FCFS）**

    * > **定义**：根据进程请求访问磁盘的先后顺序进行调度，谁先来就先服务谁。

    * 例：磁头初始在 100 号磁道，请求队列按到达顺序为 55, 58, 39, 18, 90, 160, 150, 38, 184，则磁头依次访问：

    ```text
    100 → 55 → 58 → 39 → 18 → 90 → 160 → 150 → 38 → 184
    ```

    * 总移动道数 498，平均寻找长度 $498 \div 9 = 55.3$ 个磁道。

    * 优点：公平；请求访问的磁道比较集中时性能还算可以。

    * 缺点：大量进程竞争使用磁盘且请求的磁道很分散时性能很差，性能上**近似于随机调度算法**。

---

## 最短寻找时间优先（SSTF）

* **最短寻找时间优先（Shortest Seek Time First，SSTF）**

    * > **定义**：优先处理此时与当前磁头离得最近的那个磁道，保证每一次寻道时间都最短。

    * 同一例子（磁头在 100 号）：先响应最近的 90 号，再依次 58、55、39、38、18，随后最近请求变为 150 号，又向右依次 150、160、184：

    ```text
    100 → 90 → 58 → 55 → 39 → 38 → 18 → 150 → 160 → 184
    ```

    * 总移动道数 $82 + 166 = 248$，平均寻找长度 $248 \div 9 = 27.5$ 个磁道，比 FCFS 的 55.3 少一大半。

    * > **易错点** ⚠️：SSTF 只能保证“每一次”寻道时间最短，并不能保证“总体”寻道时间最短——与贪心算法同一思想，只选眼前最优，总体未必最优。

* **饥饿现象**

    * 磁头处理到 18 号时若又来 38 号请求，处理完 38 号又来 18 号请求……只要 18、38 号磁道的请求源源不断到来，磁头就会一直循环为它们服务，150、160、184 号的请求长期得不到处理——发生饥饿。

    * 根因：磁头可能在一个小区域内来来回回移动，只要这个小区域内有源源不断的请求，它就一直被困在里面，跳不出去为其他区域的请求服务。

## 扫描算法（SCAN）与 LOOK

* **扫描算法（SCAN，电梯算法）**

    * > **定义**：只有磁头移动到最外侧磁道才可以往内侧移动，只有移动到最内侧磁道才可以往外移动；移动方式像电梯，故也叫电梯算法。

    * 补充条件：磁道号 0～200，磁头初始 100 号、正向磁道号增大的方向移动：

    ```text
    向右：100 → 150 → 160 → 184 → 200（右边没请求也必须走到最外侧）
    向左：200 → 90 → 58 → 55 → 39 → 38 → 18
    ```

    * 总移动道数 $100 + 182 = 282$，平均寻找长度 $282 \div 9 = 31.3$ 个磁道。

    * 优点：磁头总会扫过每一个区域，**不会产生饥饿**；比 FCFS 好很多，虽然比 SSTF 的 27.5 略差。

    * 缺点一：必须到最边上的磁道才能改变方向——处理完 184 号后右边已没有请求，磁头完全可以立即回头，没必要空跑到 200 号。

    * 缺点二：对各位置磁道的**响应频率不平均**——刚处理完 90 号，90 号下一次被服务要等磁头走到最右再折返，等待时间很长；而 184 号靠近边缘，磁头到边上马上折返就能再次服务它。

* **LOOK 算法**

    * > **定义**：在扫描算法基础上加一条策略——若磁头移动方向上已没有别的请求，就立即改变移动方向；一边移动一边“观察”（look）前方还有没有请求。

    * 同一例子：

    ```text
    向右：100 → 150 → 160 → 184（前方没请求，立即掉头）
    向左：184 → 90 → 58 → 55 → 39 → 38 → 18
    ```

    * 总移动道数 $(184-100) + (184-18) = 250$，平均寻找长度 27.5 个磁道，比 SCAN 的 31.3 进一步缩短。

## 循环扫描（C-SCAN）与 C-LOOK

* **循环扫描算法（C-SCAN）**

    * > **定义**：只有磁头朝某一个特定方向移动时才处理磁道访问请求；返回起点的过程中直接快速移动到起始端，不进行任何请求处理。

    * 同一例子：

    ```text
    向右：100 → 150 → 160 → 184 → 200
    返回：200 ⇢ 0（快速返回，不处理任何请求）
    再向右：0 → 18 → 38 → 39 → 55 → 58 → 90
    ```

    * 总移动道数 $100 + 200 + 90 = 390$，平均寻找长度 $390 \div 9 = 43.3$ 个磁道。

    * 频率均匀的原理：刚服务过 150 号，下一次响应它要等磁头慢慢移到最右、回到起点、再扫回来——对任何位置的磁道流程都一样，每个磁道的响应频率都很平均，这正是 C-SCAN 的卖点。

    * 缺点：与 SCAN 类似，必须到最边上的磁道才能改变方向；且返回时直接回到 0 号，可 0 号此时并没有请求，其实只需返回到最靠左的有请求的位置（18 号）。

* **C-LOOK 算法**

    * > **定义**：若磁头移动方向上已没有任何访问请求，就立即让磁头返回，且只需返回到有磁道访问请求的位置即可。

    * 同一例子：

    ```text
    向右：100 → 150 → 160 → 184（前方没请求，立即返回）
    返回：184 ⇢ 18（直接回到最靠左的请求处，不空跑）
    再向右：18 → 38 → 39 → 55 → 58 → 90
    ```

    * 总移动道数 $84 + 166 + 72 = 322$，平均寻找长度降为 35.8 个磁道，寻道时间进一步缩短。

## 六种调度算法对比

* **同一例题（磁头初始 100 号、9 个请求）的成绩单**

| 算法 | 磁头移动总道数 | 平均寻找长度 | 一句话点评 |
| :--- | ---: | ---: | :--- |
| FCFS | 498 | 55.3 | 公平，但请求分散时近似随机调度 |
| SSTF | 248 | 27.5 | 每步最优但总体未必最优，可能饥饿 |
| SCAN | 282 | 31.3 | 不饥饿，但须到边缘才掉头、响应频率不均 |
| LOOK | 250 | 27.5 | SCAN 的改良：前方没请求就掉头 |
| C-SCAN | 390 | 43.3 | 各磁道响应频率均匀，返回不干活 |
| C-LOOK | 322 | 35.8 | C-SCAN 的改良：不空跑边缘、直接回到请求处 |

* **三条复习主线**

    * SSTF 可能导致饥饿，且只保证眼前最优、不保证总体最优。

    * SCAN 与改良版 LOOK、C-SCAN 与改良版 C-LOOK，是两组“规定版 vs 灵活版”。

    * 磁头是否必须走到最边缘，是区分这两组的关键。

* > **提示**：做题时若题目没有特别说明，题目中所指的 SCAN 算法其实就是 LOOK 算法，所指的 C-SCAN 其实就是 C-LOOK——磁头并不一定非要移动到最外侧磁道，移动方向上没有别的请求了就可以立即改变方向。

## 交替编号

* **交替编号**

    * > **定义**：让逻辑上相邻的扇区在物理上间隔一定的距离，以减少延迟时间。

    * 物理前提：磁头读完一个扇区之后需要一小段时间处理，这段时间里不能接着读下一个扇区；而磁盘又在不停旋转。

    * 不采用时的问题：逻辑相邻的 2、3、4 号扇区物理上也相邻，读完 2 号后磁头做处理的间隙里 3 号已从磁头下方划过——想读 3 号只能等磁盘再转一整圈；连续读入这几个扇区就要多转好几圈，延迟时间特别长。

    * 采用后：0 号扇区之后隔一个扇区的位置才编成 1 号，以此类推；读完 2 号的间隙里 3 号尚未到达磁头下方，磁头做好准备后 3 号划过时被顺利读入。

    * > **结论**：交替编号让磁头的“处理间隙”正好落在两个逻辑相邻扇区之间，省下多转一整圈的时间，可大幅度减少延迟时间。

## 磁盘地址结构与错位命名

* **磁盘物理地址**

    * 磁盘物理地址分为**柱面号、盘面号、扇区号**三个部分，顺序不能颠倒。

    * 示例磁盘：8 条磁道（8 个柱面）需 3 个二进制位，4 个盘面需 2 位，每磁道 8 个扇区需 3 位。

* **柱面号排在盘面号前面的原因**

    * 若盘面号在前：连续读“盘面 0、柱面 0、扇区 0～7”（两圈读完）之后，下一个地址柱面号变了——必须启动磁头臂、移动磁头，这是实打实的机械运动，耗时较高。

    * 若柱面号在前：连续读“柱面 0、盘面 0、扇区 0～7”之后，下一个地址只是盘面号变了、柱面没变——磁头位置不用动，只需电子切换激活 1 号盘面对应的磁头（每个盘面各有一个磁头），不需要再启动磁头臂。

    * > **结论**：柱面号放在盘面号之前，读地址连续的磁盘块时不需要在柱面之间移动磁头，只需切换激活的磁头，减少磁头移动消耗的时间——本质还是让磁头少跑路。

    * > **易错点** ⚠️：这个知识点容易被忽略，选择题中很可能作为陷阱考察。

* **错位命名**

    * > **定义**：让相邻盘面的扇区编号错开，以减少切换盘面继续读时的延迟时间。

    * 前提：所有盘面连在一起同轴旋转，同步转动。

    * 不采用时的问题：0 号盘面 0 号扇区的正下方恰好是 1 号盘面的 0 号扇区；连续读到 0 号盘面最后一个扇区时，由于同步旋转，1 号盘面的 0 号扇区也正好转到自己磁头下方——可磁头刚读完一个扇区正需处理时间，于是它划过去了，想读只能再等一整圈。

    * 采用后：0 号盘面 0 号扇区正下方改成对应 1 号盘面的 7 号扇区，1 号盘面编号整体错开一个位置；磁头利用间隙做好准备之后，1 号盘面的 0 号扇区才第一次划过磁头下方，一次顺利读入。

    * 与交替编号的共同原理：磁头读完一个扇区后需要一段时间准备才能继续读下一个扇区；把编号排布与这个间隙配合起来，延迟时间就省下来了。

## 固态硬盘（SSD）的结构

* **固态硬盘（Solid State Disk，SSD）**

    * > **定义**：基于闪存技术存储数据的硬盘，闪存属于一种电可擦除的 ROM（EEPROM），U 盘采用的也是闪存。

    * 机械硬盘靠盘面上的磁性物质记录二进制 0 和 1；固态硬盘则是一块块存储数据的黑色芯片。

    * 组成：**闪存翻译层** + 由多个闪存芯片组成的**存储介质**。

    ```text
                I/O 总线
                   │  逻辑块号（逻辑地址）
                   ▼
            ┌────────────┐
            │  闪存翻译层  │ ← 负责逻辑地址 → 物理地址的翻译
            └────────────┘
                   │
          ┌────────┼────────┐
          ▼        ▼        ▼
      ┌──────┐ ┌──────┐ ┌──────┐
      │闪存芯片│ │闪存芯片│ │闪存芯片│ ...
      └──────┘ └──────┘ └──────┘
    ```

    * 系统通过 I/O 总线把逻辑块号发给 SSD，经闪存翻译层翻译映射到具体物理地址——闪存翻译层做的就是地址变换工作。

    * 该考点同时进入计组与操作系统的考研大纲，最有可能以选择题考察；其中读写性能特性和磨损均衡技术是操作系统大纲明确要求掌握的。

---

## 固态硬盘的读写特性

* **块与页**

    * 一块闪存芯片由若干个块（block）组成，块大小约 16KB～512KB；每个块进一步拆解为一个个页（page），页大小约 512B～4KB。

    * 系统对固态硬盘的**读写以页为单位**：逻辑块存放在固态硬盘里时，对应的是固态硬盘的一个**页**而不是一个块。

    * 固态硬盘的一个页相当于磁盘的一个扇区；一个块可理解为相当于磁盘的一个磁道——一个磁道包含多个扇区，一个块也包含多个页。

    * 擦除以**块**为单位：一个块被擦干净之后，其中每个页都可以被写一次、被读无限次。

    * > **易错点** ⚠️：“块”和“页”这些术语在其他地方也出现过且含义不同，记住“SSD 读写按页、逻辑块对应页”。

* **读快、写慢**

    * 一个页已写入数据后，再往这一页写新数据是不被允许的；想重写必须先把这一整块擦除。

    * 写一页新数据时，SSD 会先把该块中其他页的数据复制到另一个已擦干净的块的对应位置，再写入新数据，最后把原块整个擦除——保证其他页的数据不丢失。

    * 数据迁移后，闪存翻译层会把涉及的逻辑块号重新映射到新位置、舍弃原有映射；一个逻辑地址对应的实际物理位置是可能变化的，但映射关系始终被修改正确，上层感觉不到。

    * > **结论**：SSD 读速度通常很快，写速度比读慢得多——因为写操作可能引起擦除动作以及数据迁移动作。

* **随机访问**

    * SSD 支持随机访问：给定一个逻辑地址（逻辑块号），闪存翻译层可以通过**电路**迅速定位到对应的物理地址。

    * 机械硬盘定位要移动磁臂、旋转磁盘，全是机械操作；要访问的物理地址离磁臂当前位置远就得移动磁臂，等待时间长——访问不同地址所需时间各不相同。

    * SSD 访问任何一个地址，所需要花的时间都是相同的。

## 固态硬盘与机械硬盘的对比

| 特性 | 机械硬盘 | 固态硬盘 |
| :--- | :--- | :--- |
| 读写速度 | 受寻道时间、旋转延迟影响，较慢 | 电路控制，读写更快 |
| 随机访问 | 移动磁臂＋旋转磁盘定位，不同地址耗时不同 | 电路直接定位，访问任何地址耗时相同 |
| 噪音 | 盘片要转、磁臂要动，夜里能听见转动声音 | 就是一块电路板，安静无噪音 |
| 抗震耐摔 | 机械部件容易坏 | 没有机械部件，电路板焊死了很难坏 |
| 能耗 | 更费电 | 能耗更低 |
| 价格 | 便宜 | 更贵 |
| 寿命 | 扇区不会因为写得次数多而坏掉 | 块被擦除次数太多会坏（如擦约 1 万次后不能再用） |

## 磨损均衡技术

* **磨损均衡（Wear Leveling）**

    * > **定义**：把擦除平均地分布在各个块上，以提升固态硬盘的使用寿命。

    * 背景：一个块被反复擦除约 1 万次之后就不能再使用；机械硬盘的扇区则不会因为写得太多而坏。

    * 实现依据：闪存翻译层可以把逻辑块号映射到任何一个地方，物理位置可变——发现某个块被擦除次数已经很多、已经“老了”，接下来就把数据迁移过去、写到更新的块里。

* **动态磨损均衡**

    * 每一次写入数据时，SSD 优先选择**累计擦除次数更少的新块**来写。

    * 依据：无论写到哪个位置，闪存翻译层都能把逻辑地址映射正确，写到新块更好。

* **静态磨损均衡**

    * SSD 在**后台**监测哪些块经常被读、哪些块经常被写。

    * 对读多写少的数据（如下载到本地只读不写的电影），把它迁移到更老的、寿命更短的块里去——因为读操作并不损耗块的寿命，写操作才可能引发擦除，每擦除一次块的寿命就减一。

    * 效果：让老块承担“只读”的任务，让更新、寿命更充足的块承担写操作更多的任务。
