# IO管理与设备

## I/O 设备的概念与分类

   * **I/O 设备（Input/Output Device，外部设备）**

       * > **定义**：把数据输入到计算机、或接收计算机输出数据的外部硬件设备。

       * 输入过程是把设备准备好的数据**读入**计算机；输出过程是把计算机准备好的数据**写出**到输出设备上。
       * 典型例子：键盘、鼠标是输入型设备；显示器是输出型设备；移动硬盘、U 盘既可输入又可输出。
       * Unix 把外部设备抽象成一种**特殊的文件**：`write` 操作即输出，`read` 操作即输入，用户用读写文件的方式操作外设。

   * **按使用特性分类**

       * **人机交互类外设**：鼠标、键盘、打印机，数据传输速度慢，以字节或几十字节为单位传输。
       * **存储设备**：移动硬盘、光盘，用来存放数据，传输速度一般较快。
       * **网络通信设备**：调制解调器（"猫"）、路由器，速度介于前两者之间——比人机交互类快、比存储类慢。

   * **按传输速率分类**

       | 类别 | 大致速率 | 典型例子 |
       | :---: | :---: | :--- |
       | 低速设备 | 每秒几个到几百个字节 | 鼠标、键盘 |
       | 中速设备 | 每秒数千至上万个字节 | 激光打印机 |
       | 高速设备 | 每秒数千字节甚至更快 | 移动硬盘 |

       * 高中低速没有明确界限划分，这个分类基本不作为考点，有印象即可。

   * **块设备（Block Device）**

       * > **定义**：与计算机以"块"为基本单位进行数据交换的设备，如磁盘、移动硬盘。

       * 传输速率比较高；**可寻址**——可以随机地读写任意一块。

   * **字符设备（Character Device）**

       * > **定义**：以字符或字节为基本传输单位的设备，如鼠标、键盘。

       * 传输速度一般比较慢；**不可寻址**；输入输出时一般采用**中断驱动**的 I/O 控制方式。
       * 块设备与字符设备最本质的区别是与计算机交换数据的**基本单位**（块 vs 字符），其次是可寻址性差异——这是分类里必须抓牢的主轴。

## I/O 控制器

   * **I/O 控制器（Device Controller，设备控制器）**

       * > **定义**：I/O 设备的电子部件（一般是一块印刷电路板），是 CPU 与设备机械部件之间的中介，实现 CPU 对 I/O 设备的控制。

       * I/O 设备由**机械部件**（执行具体 I/O 操作的实体结构）和**电子部件**（控制器）组成。
       * CPU 无法直接控制设备的机械部件，必须通过电子部件间接控制。
       * 一个 I/O 控制器可能对应**多个设备接口**、控制多个设备，因此需要给设备编号（地址），CPU 发 I/O 命令时要指明操作哪个设备。

   * **控制器的四项功能与对应寄存器**

       * **接收和识别 CPU 命令**：由**控制寄存器**存放 CPU 发出的命令与参数（如读写多少字节），控制器据此确定要执行的操作。
       * **向 CPU 报告设备状态**：由**状态寄存器**记录设备忙碌、空闲或故障，CPU 读取它判断状态（如可规定 1 忙碌、0 空闲，复杂状态用更多二进制位）。
       * **实现数据交换**：由**数据寄存器**暂存数据——输出时暂存 CPU 发来的数据再传给设备，输入时暂存设备送来的数据等 CPU 取走。
       * **地址识别**：像给内存编址一样给各寄存器编地址，控制器根据 CPU 提供的地址判断要操作哪个寄存器；由于一个控制器可能管多个设备，数据、控制、状态寄存器都各有**多个**。

   * **控制器的三个组成部分**

```text
        ┌────────────────── I/O 控制器 ──────────────────┐
 ┌────┐ │ ┌───────────┐  ┌─────────┐  ┌─────────────┐  │ ┌────────────┐
 │CPU │═╪═│CPU与控制器 │═│ I/O逻辑 │══│ 控制器与设备  │ ═╪═│ 设备的      │
 └────┘ │ │   接口     │  └─────────┘  │    接口      │  │ │ 机械部件    │
        │ └───────────┘               └─────────────┘  │ └────────────┘
        │  数据线/地址线/      命令翻译、      数据线/    │
        │  控制线             地址译码        控制线      │
        └────────────────────────────────────────────────┘
```

       * 左侧 **CPU 与控制器的接口**完成 CPU 和控制器间的通信：CPU 经控制线发 I/O 指令、地址线指明目标设备、数据总线读写数据寄存器，参数进控制寄存器。
       * 中间 **I/O 逻辑**负责接收识别 CPU 命令、地址译码，并把命令翻译成设备能懂的命令发给设备；还把各设备状态写入状态寄存器供 CPU 读取。
       * 右侧 **控制器与设备的接口**完成控制器和设备间的通信：传送数据、反馈设备状态、按命令对设备发出控制命令。

   * **寄存器编址的两种方式**

       | 方式 | 编址方法 | 特点 |
       | :--- | :--- | :--- |
       | 内存映像 I/O | 寄存器占用内存地址的一段，与内存**统一编址**、共用一个地址空间 | 不需要专门指令，用对内存单元操作的相同指令即可存取寄存器 |
       | 寄存器独立编址 | 采用 I/O 专用地址，寄存器与内存是**两个独立体系** | 需要专门的存取指令，且指令还要指明操作的是哪个控制器 |

       * 选择题可能把控制器三组成加一个错误选项让你选"错误的那个"，控制器组成与主要功能都要有印象。

## 四种 I/O 控制方式

分析每种方式盯住五个问题：完成一次读写的**流程**、CPU 的**干预频率**、**数据传送单位**、**数据流向**、**优缺点**。发展主线是尽量减少 CPU 对 I/O 过程的干预，把 CPU 从 I/O 控制事务中解脱出来。

   * **程序直接控制方式**

       * > **定义**：CPU 通过执行循环检查程序不断**轮询**设备状态来完成 I/O 的最早控制方式。

       * 流程（以读为例）：CPU 发读指令 → 控制器启动设备并置状态为**未就绪** → CPU 不断轮询状态寄存器 → 设备备好数据放入数据寄存器并置状态**已就绪** → CPU 轮询发现就绪后从数据寄存器读出数据到 **CPU 寄存器**，再**转存到内存**。
       * 数据先到 CPU 寄存器再写内存的原因：变量存放在内存中，`scanf` 读入的键盘数据最终要放内存单元，`printf` 输出也是从内存取数据经 CPU 送设备。
       * CPU 干预频率**极高**：I/O 开始前后要介入，**等待过程中也要不断轮询**；传送单位是**一个字**；数据流向为设备 → CPU 寄存器 → 内存。
       * 优点：实现简单，纯软件方式即可实现。
       * 缺点：CPU 与 I/O 设备只能**串行**工作，CPU 发出指令后长期**盲等**，双方利用率都低。

   * **中断驱动方式**

       * > **定义**：引入中断机构，CPU 发出 I/O 指令后转去执行别的进程，由 I/O 完成后的中断信号通知 CPU 介入的控制方式。

       * 流程：CPU 发 I/O 指令后把等待 I/O 的进程**阻塞**、切换到别的进程 → I/O 完成后控制器发**中断信号** → CPU 在**每个指令周期末尾**检查到中断，执行对应**中断处理程序**，从控制器读出一个字到 CPU 寄存器再写入内存 → 恢复之前被阻塞的进程（或让它继续在就绪队列等待）。
       * CPU 干预频率：每次 I/O **开始前发一条指令、结束后处理一次中断**；传送单位仍为**一个字**；数据流向与程序直接控制相同（必须经 CPU 中转）。
       * 优点：CPU 与 I/O 设备**并行工作**，双方利用率明显提升。
       * 缺点：每次中断只传一个字，大量数据要发生**大量中断**，每次中断处理都要付出保存/恢复进程运行环境的时间代价，中断太频繁会降低系统性能。

   * **DMA 方式（Direct Memory Access，直接存储器存取）**

       * > **定义**：数据在 DMA 控制器控制下**直接在设备与内存之间传送、不经过 CPU**，以块为单位的 I/O 控制方式，主要用于**块设备**。

       * 相比中断驱动的三点进化：传送单位由字变为**块**；数据流向不再经过 CPU；CPU 仅在传送一个或多个数据块的**开始和结束**时干预。
       * 流程：CPU 发读写一个块的指令并指明数据量、内存存放位置、设备上存放位置 → DMA 控制器完成整个任务 → 完成后向 CPU 发中断。
       * DMA 控制器由 **CPU 与控制器的接口、I/O 控制逻辑、块设备与控制器的接口**三部分组成，接口寄存器有：

       | 寄存器 | 作用 |
       | :---: | :--- |
       | DR（数据寄存器） | 暂存设备↔内存间的中转数据 |
       | MAR（内存地址寄存器） | 指明数据在内存中的存放/读取位置 |
       | DC（数据计数器） | 记录还需读/写的剩余字节数 |
       | CR（命令/状态寄存器） | 存放 CPU 发来的命令参数与设备状态 |

       * 系统总线把 DMA 控制器和内存**直接连在一起**，二者可直接读写，不经过 CPU。
       * > **易错点**：DMA 控制器并不是一次直接读入一整块塞进内存——它仍是一个字一个字地读入，每个字先暂存 DR 再写入内存，靠逐字传送最终完成一整块。

       * 缺点：CPU 每发一条指令只能读/写**一个或多个连续的数据块**，且块读入内存后必须连续存放；要读写多个离散块需发出多条 I/O 指令。

   * **通道控制方式**

       * > **定义**：由一种叫通道的硬件（可理解为"弱鸡版 CPU"）识别并执行通道程序，独立完成一组数据块传送的控制方式。

       * 通道能识别的指令单一、没有自己的内存，需与 CPU 共享主机内存。
       * 流程：CPU 发 I/O 指令，指明**通道程序**在内存的位置和目标设备 → CPU 切换到其他进程 → 通道从内存读取通道程序（一系列通道指令的集合，相当于**任务清单**，指令中指明读写数据量、内存位置、外存位置等）→ 通道按程序逐步完成 I/O → 完成后向 CPU 发一次中断。
       * CPU 干预频率**极低**：一次扔给通道一批任务，一组数据块读写完成后才中断一次；传送单位是**一组数据块**；数据流向与 DMA 类似（设备 ↔ 内存直达）。
       * 优点：CPU、通道、I/O 设备可以**并行**工作，资源利用率特别高；缺点：实现复杂，需要专门的**通道硬件**支持。
       * 层级关系：**一个通道可控制多个 I/O 控制器，一个 I/O 控制器又可控制多个设备**。

   * **四种方式横向对比**

       | 控制方式 | CPU 干预频率 | 数据传送单位 | 数据流向 | 主要优点 | 主要缺点 |
       | :--- | :--- | :--- | :--- | :--- | :--- |
       | 程序直接控制 | 极高，不断轮询 | 字 | 设备 → CPU 寄存器 → 内存 | 实现简单，纯软件即可 | CPU 与 I/O 串行、盲等，双方利用率低 |
       | 中断驱动 | 每次 I/O 开始前、结束后各一次 | 字 | 设备 → CPU 寄存器 → 内存 | CPU 与设备并行，利用率明显提升 | 频繁中断消耗 CPU 时间，数据仍须经过 CPU |
       | DMA | 一块（或多块连续块）传送的开始和结束 | 块 | 设备 ↔ 内存直达 | 干预更少、传输效率进一步提升 | 只能读写连续块，离散块需多条指令 |
       | 通道 | 极低，一组块完成后中断一次 | 一组数据块 | 设备 ↔ 内存直达 | CPU、通道、设备并行，资源利用率特别高 | 实现复杂，需专门通道硬件 |

       * 每一阶段的优点都是解决了上一阶段留下的最大缺点；选择题常考各方式的流程、干预频率与传送单位。

## I/O 软件的层次结构

```text
┌────────────────────────────┐
│       用户层软件            │ ← 内核之外，用户态可实现
├────────────────────────────┤
│       设备独立性软件         │
│       设备驱动程序           │ ← I/O 核心子系统（内核部分）
│       中断处理程序           │
├────────────────────────────┤
│   I/O 硬件（机械部件+电子部件）│
└────────────────────────────┘
```

   * **分层规则**

       * 越靠上层越接近用户，越靠下层越接近硬件；每层使用下一层的功能，并向上层提供服务。
       * 用户发出 I/O 请求时由**上至下**层层处理，最后交给 I/O 硬件执行实际操作；硬件完成发出 I/O 应答（中断信号）后由**下至上**层层处理，最后返回用户。
       * 下三层（设备独立性软件、设备驱动程序、中断处理程序）属于操作系统内核，合称 **I/O 核心子系统**。

   * **用户层软件**

       * > **定义**：最接近用户的层次，提供简单易用的交互接口，一般为与 I/O 相关的**库函数**。

       * `printf("hello world")` 由用户层软件处理，最终被翻译成等价的 `write` 系统调用并填入参数，请求操作系统提供服务——因为只有操作系统才有操作硬件的权利。
       * Windows API 就是用户层软件提供的库函数接口：系统调用太低级，需进一步封装。

   * **设备独立性软件（设备无关性软件）**

       * > **定义**：实现基本上与设备硬件特性无关功能的层次，负责处理系统调用，因此也被称为"系统调用处理层"。

       * 六项功能：向上层提供统一的调用接口（如 `read`、`write`）；**设备保护**；**差错处理**；**设备分配与回收**；**数据缓冲区管理**（缓冲区用来屏蔽设备间数据交换单位大小和传输速度的差异）；**建立逻辑设备名到物理设备名的映射**并根据设备类型选择调用相应驱动程序。
       * 它不能直接操纵硬件，必须调用厂家提供的设备驱动程序完成对硬件的具体控制。

   * **逻辑设备表（LUT，Logical Unit Table）**

       * > **定义**：记录逻辑设备名到物理设备名映射关系、以及对应设备驱动程序入口地址的表。

       * 逻辑设备名是用户请求使用设备时提供的名字（用户看到的设备名，如"打印机一"）；操作系统必须知道它对应哪台物理设备。
       * 两种管理方式：**整个系统只设一张 LUT**——不同用户用相同逻辑设备名会导致映射紊乱，只适合单用户操作系统；**为每个用户设一张 LUT**——不同用户的逻辑设备名可以重复、可映射到不同物理设备，适合多用户操作系统。
       * 这两种方式类似文件管理中**单级目录与两级目录**的区别：单级目录下不同用户文件名不允许相同，两级目录下可以相同。

   * **设备驱动程序**

       * > **定义**：设备厂家出厂时提供的、针对该设备硬件特性的程序；CPU 执行它即可完成对该设备控制器的控制（如设置寄存器、检查状态寄存器）。

       * 为什么必须有：不同型号设备的内部电子部件可能完全不同（如佳能打印机两个数据寄存器、状态 0 为空闲，惠普可能只一个数据寄存器、状态 1 为空闲），操作系统不可能了解所有设备的内部细节。
       * 各类型的设备驱动程序在系统中一般以**独立进程**的方式运行存在。
       * 设备第一次插上电脑时自动安装的驱动程序就是厂家提供的。

   * **中断处理程序**

       * > **定义**：硬件完成 I/O 操作发出中断信号后，根据中断信号类型找到并执行的处理程序，是 I/O 应答的入口。

       * 流程：从设备控制器读出设备状态、判断这次 I/O 是否正常结束——正常结束则从控制器的数据寄存器读出一个字的数据，经 CPU 放到内存缓冲区；非正常结束（如硬件故障）则根据异常原因做相应处理。
       * 数据处理由下至上层层进行：中断处理程序 → 设备驱动程序 → 设备独立性软件 → 用户。
       * 判断功能归属的关键：**设备驱动程序和中断处理程序直接和硬件打交道**，涉及硬件细节的操作由这两层完成；其余功能基本由设备独立性软件完成。

## I/O 应用程序接口

上层应用无法用一个统一的系统调用接口操作所有类型设备——块设备可寻址、读写需指明地址和字节数，字符设备（如键盘）不可寻址、只能一次读一个字符，所需系统调用参数各不相同。接口是依据这种设备的特性来定义的。

   | 设备类型 | 系统调用 | 地址参数 | 读写单位 |
   | :---: | :--- | :---: | :--- |
   | 字符设备 | `get` / `put` | 无 | 一个字符 |
   | 块设备 | `seek` + `read` / `write` | 有 | 多个字节 |
   | 网络设备 | `socket` / `bind` / `connect` + `read` / `write` | 由 IP + 端口定位 | 数据包 |

   * **字符设备接口**：`get` 从指定字符设备读出一个字符，`put` 往指定字符设备写一个字符；因为字符设备没有地址概念，不需要地址参数。

   * **块设备接口**：先用 `seek` 把读写指针放到磁盘某个地址，再用 `read` / `write` 从指针所指位置往后读/写若干单位的数据，每次读写多个字节。

   * **网络设备接口（网络套接字接口）**

       * 网卡（网络控制器）会收到发给不同应用的数据包，需要区分——通过套接字绑定不同端口实现：网卡根据数据包里的端口信息把包放到对应的套接字对象上。
       * `socket`：创建一个网络套接字，需指明使用的网络协议（TCP 或 UDP），返回一个描述符（可理解为指向套接字的指针，也可理解为申请一片用于收发数据的内核存储空间）。
       * `bind`：把套接字绑定到本地某一个端口上；IP 定位主机，端口号映射到主机中的某个应用程序。
       * `connect`：把套接字连接到远程的某台主机上（传入对方 IP 与端口号，建立应用层连接）。
       * 套接字初始化完毕后，用 `read` / `write` 对套接字进行读写：发送方 `write` 时设备独立性软件把用户区数据复制到套接字对应的内核缓冲区，再由驱动程序输出到网络设备；接收方网卡发中断，中断处理程序把数据搬进对应端口的内核缓冲区，接收进程 `read` 取走。
       * 通过「主机 IP + 套接字绑定的端口」可以找到全世界任何一个套接字对象；同一主机上不同进程各申请套接字、绑定不同端口即可并发通信。

   * **阻塞 I/O 与非阻塞 I/O**

       * **阻塞 I/O**：发出 I/O 系统调用后进程转为阻塞态等待 I/O 完成——如从键盘 `get` 读字符，键盘不输入进程就无法往下执行。
       * **非阻塞 I/O**：系统调用可迅速返回、进程无需阻塞——如向磁盘 `write`，设备独立性软件迅速把数据复制到内核后系统调用即返回，内核慢慢把数据写回磁盘，用户进程继续执行。

   * **设备驱动程序接口**

       * 不同厂商的驱动程序若接口不统一（同名函数参数个数不同），设备独立性软件就得频繁修改内核代码来适配，显然不科学。
       * 因此操作系统统一标准，要求厂商按规定的统一标准（函数名、参数个数与类型等）开发驱动程序——所以同一设备厂商要为 Mac、Windows 等不同操作系统分别开发驱动。
       * > **结论**：驱动程序层需要向上层的设备独立性软件提供一个统一标准的接口。

## I/O 核心子系统的功能布局

   * **功能与层次的对应**

       * I/O 核心子系统 = 设备独立性软件 + 设备驱动程序 + 中断处理程序这三层内核部分，其功能即这三层实现的功能。
       * 考研重点功能：**I/O 调度、设备保护、假脱机技术（SPOOLing）、设备分配与回收、缓冲区管理**。
       * 归属：假脱机（SPOOLing）一般在**用户层**实现——它需要使用磁盘的设备独立性软件层的服务；I/O 调度、设备保护、设备分配与回收、缓冲区管理都在**设备独立性软件**层实现。列出的功能没有一个直接与硬件相关，因此都不由驱动/中断层负责。

   * **I/O 调度**

       * > **定义**：用某一种算法确定一个好的顺序来处理各个 I/O 请求，思想与处理机调度类似。

       * 磁盘调度本身就是 I/O 调度问题（磁盘也是 I/O 设备）；打印机等设备同样可采用先来先服务、优先级、短任务优先等算法确定调度顺序。
       * 做题方式：根据题目给出的算法名，结合已学调度算法思想分析。

   * **设备保护**

       * Unix 把设备看作**特殊的文件**，为各设备建立相应的 FCB（文件控制块）。
       * 用户访问设备时，系统根据该设备对应的 FCB 判断用户是否有相应访问权限——设备保护本质上就是文件保护做的事情。

## 脱机技术与假脱机（SPOOLing）

   * **脱机技术**

       * > **定义**：脱离主机的控制来进行输入/输出操作的技术，用磁带作为高速中转存储。

       * 背景：手工阶段 CPU 直接与速度极慢的纸带机交互，输入输出时 CPU 迁就慢速设备，暴露严重的**速度矛盾**。
       * 输入方向：纸带机 → 外围控制机 → 磁带（比纸带机快得多）→ CPU 直接从磁带读取；输出方向：主机 → 磁带 → 纸带机。
       * 好处：缓解 I/O 设备与 CPU 的速度矛盾；实现**预输入**与**缓输出**——CPU 忙碌时可先把数据预输入到磁带，纸带机忙碌时 CPU 可先把数据输出到磁带，两边各忙各的。

   * **假脱机技术（SPOOLing）**

       * > **定义**：用软件的方式模拟实现脱机技术的技术，一般在用户层实现。

       * 组成（与脱机部件一一对应）：

       | 脱机技术（磁带时代） | 假脱机技术（软件模拟） |
       | :--- | :--- |
       | 脱机输入用的磁带 | 磁盘上的**输入井**（收容输入设备输入的 I/O 数据） |
       | 脱机输出用的磁带 | 磁盘上的**输出井**（收容用户进程输出的数据） |
       | 外围控制机（输入侧） | **输入进程** |
       | 外围控制机（输出侧） | **输出进程** |
       | （无对应物） | 内存中的**输入/输出缓冲区**（数据中转站） |

       * 数据流动：模拟脱机输入为「输入设备 → 输入进程 → 输入缓冲区（内存）→ 输入井（磁盘）→ 用户进程」；模拟脱机输出为「用户进程 → 输出井（磁盘）→ 输出缓冲区（内存）→ 输出进程 → 输出设备」。
       * 输入进程、输出进程需要与用户进程**并发地执行**。
       * > **易错点**：SPOOLing 技术必须依赖**多道程序技术**的支持——没有并发就不存在输入/输出进程与用户进程同时推进。

   * **共享打印机：SPOOLing 的经典应用**

       * **独占式设备**：一段时间内只能满足一个进程请求、串行使用的设备（如打印机——同时处理多个请求会导致打印输出相互混杂）；**共享设备**：允许多进程"同时"（宏观同时、微观可能交替）使用的设备。
       * 打印机本为独占式设备；采用 SPOOLing 后，多个用户提出打印请求时系统**先答应请求**，但不直接分配打印机，而是由**假脱机管理进程**为每个用户进程：在磁盘输出井中申请一个空闲缓冲区（磁盘缓冲区，非内存），存入要打印的数据；再申请一张空白**打印请求表**（本质是打印任务的说明书），填入打印参数、说明数据存放在哪个缓冲区。
       * 打印请求表挂到**脱机文件队列**（打印任务队列）上；**输出进程**从队头取出任务，按表指示从输出井缓冲区读数据到内存输出缓冲区，再输出到打印机；任务完成后删除该表，打印机空闲就继续处理下一个任务。
       * 每个进程请求时都在输出井中分到自己的缓冲区，相当于被分配了一个**逻辑上的设备**，各进程感觉自己独占一台打印机。
       * > **结论**：SPOOLing 可以把一台物理设备虚拟成逻辑上的多台设备，把独占式设备改造成共享设备。

## 设备分配与回收

   * **设备分配要考虑的三个因素**

       * **设备的固有属性**：**独占设备**（一个时间段内只能分配给一个进程，如打印机）、**共享设备**（可同时分配给多个进程，宏观共享、微观可能交替使用，如磁盘）、**虚拟设备**（用 SPOOLing 把独占设备改造成的虚拟共享设备，如共享打印机）。
       * **设备的分配算法**：先来先服务、优先级高者优先、短任务优先等。
       * **设备分配中的安全性**：见下表。

       | 分配方式 | 做法 | 优点 | 缺点 |
       | :--- | :--- | :--- | :--- |
       | 安全分配方式 | 分配设备后就把进程阻塞，直到它释放该 I/O 设备才唤醒 | 破坏"请求和保持"条件，**不会死锁** | 进程的 CPU 与 I/O 设备只能串行工作，资源利用率低、进程执行效率低 |
       | 不安全分配方式 | 分到设备后不阻塞、继续执行，还可发出更多新 I/O 请求，直到某一请求得不到满足才阻塞 | 计算任务与 I/O 任务可并行，效率高 | 不安全，**可能死锁** |

       * 安全分配下一个时间段内每个进程只能使用一个设备；不安全分配下一个进程可同时使用多个设备。
       * 不安全分配方式可用**死锁避免（银行家算法）**避免系统进入不安全状态。

   * **静态分配与动态分配**

       * **静态分配**：进程运行前就分配它所需的全部资源，运行结束后才归还；资源不能完全满足则进程暂不能投入运行。它破坏了"请求和保持"条件，不会死锁。
       * **动态分配**：进程在运行过程中动态申请设备资源，不是一开始就得到全部资源。

   * **设备分配中的四张数据结构表**

       * 结构关系：**一个通道可控制多个控制器，一个控制器可控制多个设备**，呈树形；一个系统中可能有多个通道。控制设备要找到其控制器、控制控制器要找到其通道，所以数据结构必须表示这种**从属关系**。
       * **设备控制表（DCT）**：系统为**每一个设备**配置，字段包括设备类型、设备标识符（物理设备名，唯一 ID）、设备状态（忙/闲/故障）、指向控制器表的指针、重复执行次数或时间（I/O 失败会重试多次，多次仍失败才认为这次 I/O 失败）、设备队列的队首指针（指向由等待该设备的进程 PCB 组成的队列）。
       * **控制器控制表（COCT）**：每个设备控制器一张，字段包括控制器标识符、控制器状态、指向通道表的指针、等待该控制器的进程队列的队首与队尾指针。
       * **通道控制表（CHCT）**：每个通道一张，字段包括通道标识符、通道状态、与通道连接的控制器表首指针（据此找到该通道控制的**所有**控制器的信息）、等待该通道的进程队列的队首与队尾指针。
       * **系统设备表（SDT）**：记录**系统中全部设备**的情况，每个设备一个表目，记录设备类型、设备标识符、该设备的 DCT、驱动程序入口地址；用户按设备名请求设备时，操作系统从 SDT 中找到指定设备。
       * 四张表不需死记：设备/控制器/通道三张表对应树形从属关系，且每种资源都有等待队列指针——资源暂时分配不出去就把进程 PCB 插入相应等待队列。

   * **设备分配的完整流程**

```text
进程提供【物理设备名】作为系统调用参数
   │
   ▼ 查系统设备表 SDT（逐表目比对设备标识符）
得到该设备的 DCT，检查设备状态
   │ 忙 → 进程挂到设备的等待队列；空闲 → 分配设备
   ▼ 按 DCT 中"指向控制器表的指针"找到 COCT
检查控制器状态
   │ 忙 → 挂到控制器的阻塞队列；空闲 → 分配控制器
   ▼ 按 COCT 中"指向通道表的指针"找到 CHCT
检查通道状态
   │ 忙 → 挂到通道的阻塞队列；空闲 → 分配通道
   ▼
设备 + 控制器 + 通道 都分配成功 → 启动 I/O 设备开始数据传送
```

       * > **结论**：只有**设备、控制器、通道**三者都分配成功，这次设备分配才算成功，才可以启动 I/O 设备。

   * **逻辑设备名与物理设备名映射**

       * 用**物理设备名**请求分配的两个缺点：编程绑定具体设备，物理设备一更换、之前写的程序就无法运行；进程请求的设备忙碌时，即使系统还有**同类型空闲设备**也必须阻塞等待，设备利用率不高。
       * 解决方式：用户编程时用**逻辑设备名**（即指明设备类型，如"打印机"），操作系统负责逻辑设备名到物理设备名的转换——根据 SDT 中记录的设备类型，找到**指定类型的、空闲的**设备分配；只有该类型设备全部忙碌才阻塞进程。
       * 分配成功后，操作系统在 **LUT** 中新增表项（记录逻辑设备名到物理设备名的映射及驱动程序入口地址）；后续按 DCT → COCT → CHCT 分配控制器与通道。
       * 细节：只有进程**第一次**用某逻辑设备名申请设备时才查 SDT；之后再以相同逻辑设备名请求时，直接查 **LUT** 找到对应物理设备与驱动程序。
       * LUT 两种设置方式：整个系统一张（逻辑设备名不允许重复，适合单用户操作系统）；每个用户一张（不同用户逻辑设备名可重复，适合多用户操作系统）。

   * **设备回收**

       * 设备回收就是把分配时改动的那些数据结构再改回来，不需要专门展开。

## 缓冲区管理

   * **缓冲区（Buffer）**

       * > **定义**：一个存储区域，可以由专门的硬件寄存器组成，也可以由内存来充当。

       * 硬件缓冲区成本高、容量小，典型例子是快表（联想寄存器）——访问频率极高，用高成本硬件方案值得；一般情况下更多用**内存作为缓冲区**，设备独立性软件层的"缓冲区管理"管理的就是内存缓冲区。
       * 作用机理：输出时 CPU 快速把数据冲入缓冲区后转去干别的，I/O 设备慢慢取走；输入时设备慢慢放入缓冲区，充满后 CPU 快速取走。
       * 四个好处：**缓和 CPU 与 I/O 设备速度不匹配的矛盾**；**减少 CPU 的中断频率、放宽 CPU 对中断响应时间的限制**（没有缓冲区时字符设备每传一个字符就中断 CPU 一次，有缓冲区时只在数据充满/取空缓冲区时才中断）；**解决数据粒度不匹配的问题**（输出进程每次生成一整块、设备每次只能输出一个字符，由缓冲区居中转换）；**提高 CPU 与 I/O 设备之间的并行性**。

   * **缓冲区的"死规矩"**

       * > **结论**：缓冲区不空时不能往里冲入数据、只能从中传出数据；缓冲区为空时可以往里冲入数据，但必须**充满**之后才能传出数据。

       * 即"充满才能取、取空才能放"，没有第三种状态；所有耗时分析都建立在这条规矩上。

   * **单缓冲：平均处理一块数据的耗时**

       * 操作系统在内存中为用户进程分配**一个**缓冲区，大小与一块数据相等。三个时间参数：
       * **T**：块设备产生一块数据、输入到缓冲区所耗时间；**M**：把缓冲区中的数据传送到用户进程工作区所耗时间；**C**：用户进程处理这一块数据所耗时间（默认工作区刚好放下一块数据，处理完即腾空）。
       * 分析技巧：**假定一个初始状态，分析下一次到达相同状态需要多久**——这段时间就是平均处理一块数据的时间。单缓冲一般假设初始状态为**工作区满、缓冲区空**。
       * $T > C$ 时：CPU 处理完（耗时 $C$）后缓冲区未满，须等到 $T$ 时刻充满再传送 $M$，一轮耗时 $T + M$；$C > T$ 时：缓冲区 $T$ 时刻充满但工作区没腾空，须等到 $C$ 时刻才传送 $M$，一轮耗时 $C + M$。
       * > **结论**：单缓冲下每处理一块数据平均耗时 $M + \max(C, T)$。

   * **双缓冲：平均处理一块数据的耗时**

       * 分配**两个**大小各为一块的缓冲区；初始状态假设为**工作区空、一个缓冲区满、另一个空**。
       * $T > C + M$ 时：传送 $M$、处理 $C$ 完成后（$C+M$ 时刻）另一缓冲区尚未充满，等到 $T$ 时刻回到初始状态，一轮耗时 $T$——输入完全跟得上，每来一块处理一块。
       * $T < C + M$ 时：两缓冲区交替充放、流水线运转，设备忙个不停；此时很难再等到与初始状态完全一致的时刻，"等初始状态重现"技巧不好使，改用甘特图分析。
       * > **结论**：双缓冲下每处理一块数据平均耗时 $\max(C + M, T)$。

       * 真正要求会算的只有单缓冲与双缓冲这两个式子；循环缓冲与缓冲池只需理解原理。

   * **通信中的单缓冲与双缓冲**

       * 两台主机通信也可采用缓冲策略：各配**单缓冲**时，发送方充满才能发、接收方取空才能回发，任一时刻**只能单向传输**。
       * 各配**双缓冲**（一个发送、一个接收）可实现同一时刻的**双向传输**。

   * **循环缓冲区**

       * > **定义**：由多个大小相等的缓冲区连成的循环队列。

       * **in 指针**指向下一个可冲入数据的**空**缓冲区，**out 指针**指向下一个可取出数据的**满**缓冲区；in 所指缓冲区充满后前移，out 所指缓冲区取空后前移，两指针在环上你追我赶，生产与消费持续运转。

   * **缓冲池**

       * > **定义**：由一系列缓冲区组成的池子，需要使用或归还缓冲区时对池中缓冲区统一操作。

       * 缓冲区按使用状况分**三个队列**：空缓冲队列、输入队列（装满输入数据）、输出队列（装满输出数据）。
       * 按功能设**四种工作缓冲区**：收容输入、提取输入、收容输出、提取输出。

       | 操作 | 从哪取 | 做什么 | 用完挂回哪 |
       | :--- | :--- | :--- | :--- |
       | 收容输入 | 空缓冲队列队头 | 充入设备输入的数据 | 充满 → 输入队列队尾 |
       | 提取输入 | 输入队列队头 | 数据传送到计算进程的工作区 | 取空 → 空缓冲队列队尾 |
       | 收容输出 | 空缓冲队列队头 | 充入计算进程要输出的数据 | 充满 → 输出队列队尾 |
       | 提取输出 | 输出队列队头 | 数据取走输出到 I/O 设备 | 取空 → 空缓冲队列队尾 |

       * 四种操作模式完全一致：**从某个队列的队头取、往某个队列的队尾挂**，缓冲区周而复始循环利用。

## 磁盘的结构与物理地址

   * **磁盘的组成**

       * 磁盘表面由磁性物质组成，用来记录二进制数据；拆开硬盘里圆圆的东西是**盘片**，读数据需**磁头臂**（磁臂）带动**磁头**移动到相应位置。
       * 一个盘面划分为一条条**磁道**（实际数量成千上万条）；每个磁道再划分为一个个**扇区**，一小片扇区就是一个**磁盘块**；**每个扇区存放的数据量都相同**（如每扇区 1 KB），扇区可编号（0 号、1 号……）；磁盘中间的马达带动磁盘旋转。
       * > **易错点**：每个扇区数据量相同，而最内侧扇区面积最小，所以**最内侧扇区的数据密度最大**——这个推论常被拿来做文章。

   * **读/写一个扇区的步骤**

       * 第一步**磁头定位**：磁头臂带动磁头移动到目标扇区所在的磁道（移动只有往里、往外两个方向）。
       * 第二步**磁盘旋转**：马达带动磁盘转，目标扇区从磁头下面划过时完成读/写。
       * 磁头移动要耗费时间——这一物理直觉是磁盘调度算法的基础。

   * **盘面、柱面与物理地址**

       * 磁盘由多个盘片**垒起来**，每个盘面有专门读取它的磁头，盘面可编号；有的磁盘一个盘片正面、背面各算一个盘面。
       * **所有磁头统一连在同一个磁臂上，只能共进退**——一个磁头往里移动，其他磁头必然跟着往里移动。
       * **柱面**：各盘面上相对位置相同（同一半径）的那一圈圈磁道组成的集合。

       * 物理地址为三元组：

       $$(柱面号，盘面号，扇区号)$$

       * 柱面号定位磁道（磁臂移到哪一圈）、盘面号选择哪个盘面（激活该盘面的磁头）、扇区号选择磁道上哪个扇区。文件物理结构中的"几号盘块"即可转换成这种地址形式。

   * **磁盘的分类**

       * **活动头磁盘**：磁臂来回伸缩带动磁头定位到指定磁道，**每个盘面只需一个磁头**；**固定头磁盘**：磁头不可移动，**每一个磁道都对应一个磁头**，读哪条磁道只需激活对应磁头，无需移动。
       * 按盘片是否可更换分为**可换盘磁盘**与**固定盘磁盘**。
       * > **易错点**：固定头磁盘是**每个磁道一个磁头**，移动头磁盘是**每个盘面一个磁头**——这一对非常可能在选择题里考。

## 磁盘初始化、引导块与坏块

   * **磁盘初始化的三个步骤**

       * **低级格式化（物理格式化）**：划分扇区。每个扇区分为**头、数据区域、尾**三部分，数据区域大小相同（如 512 B）；头尾用于存放**链接指针**（链式文件的块间指针放这里，不占数据区）和**管理扇区所需的数据结构**（如扇区校验码，奇偶校验、循环冗余校验码可放头尾，检查数据是否出错、提高可靠性）。
       * **磁盘分区**：把磁盘逻辑上分区，每个分区由若干**相邻的柱面**组成（即 C 盘、D 盘、E 盘）。
       * **逻辑格式化**：**创建文件系统**——建立根目录的目录文件，初始化存储空间管理用的数据结构（位示图、空闲分区表等在此建立）。
       * 连起来记：**低级格式化（划扇区）→ 磁盘分区（分 C、D、E 盘）→ 逻辑格式化（建文件系统）**。

   * **引导块**

       * > **定义**：磁盘上存放**完整自举程序**的固定区域，也叫启动块、启动分区。

       * 开机需要执行**初始化程序（自举程序）**完成 CPU、内存、寄存器等硬件初始化；传统做法把自举程序整个放 ROM（只读存储器，出厂写入、集成在主板上），问题是 ROM 数据无法更改、**更新很不方便**。
       * 现代方案拆成两半：ROM 只存放很小的**自举装入程序**（简单到保证不出错、永不更改）；**完整的自举程序**存放在磁盘的引导块上，位置固定。开机流程：执行 ROM 中的自举装入程序 → 由它从磁盘引导块读出完整自举程序 → 执行自举程序完成初始化。自举程序需要更新时只需重写引导块中的数据。
       * 拥有启动分区（引导块）的逻辑磁盘称为**启动磁盘（系统磁盘）**，平时熟悉的 C 盘就是系统磁盘。

   * **坏块管理**

       * > **定义**：坏块是坏了的、无法正常使用的扇区，属于**硬件故障**，操作系统无法用软件方式修复，只能标记出来防止误用。

       * **简单磁盘**：在**逻辑格式化**时标明哪些块是坏块（如在 FAT 文件分配表上标注），OS 管理存储空间时读 FAT 即可绕开——坏块对操作系统**不透明**。
       * **复杂磁盘**：磁盘内部的**磁盘控制器**维护一个**坏块链表**（出厂前的检查在低级格式化时初始化坏块链），并保留一些**好的备用扇区**；OS 想使用坏块时，磁盘控制器在硬件层拿备用块顶替（也称**扇区备用**）——整个过程对操作系统**透明**。
       * > **易错点**：两种方案的关键区别在"透明"二字——简单磁盘由 OS 借 FAT 标注，坏块对 OS **不透明**；复杂磁盘由磁盘控制器硬件层顶替，坏块对 OS **透明**。
