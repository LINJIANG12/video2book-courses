# 文件系统：结构与实现

## 逻辑结构与物理结构的分工

* **逻辑结构（logical structure）**

    * > **定义**：用户视角下，文件内部的数据应该怎样组织起来。

    * 与数据结构中"线性表"的分工同理：用户看到的是有先后顺序的元素序列，这是逻辑结构；至于底层用顺序表还是链表实现，是物理结构的事。

* **物理结构（physical structure）**

    * > **定义**：操作系统视角下，文件的数据应该怎样存放在外存中，又称文件分配方式。

    * 同一个逻辑结构可以配不同的物理实现；文件操作的具体实现与两者都有关。

* **逻辑结构与物理结构各司其职**

    * 用户看来，自己创建的文件占用一整片连续的逻辑地址空间，访问数据只需指明逻辑地址。

    * 操作系统根本不知道、也不需要关心文件的逻辑结构；它只负责把文件拆成一个个与磁盘块等大的逻辑块存放，并在用户提供逻辑地址后，将其转换为"物理块号 + 块内偏移量"。

    * 无论采用哪种分配方式，只要用户给出逻辑地址，操作系统总能完成这个转换——物理结构对用户不可知，也不需要关心。

## 无结构文件与有结构文件

* **无结构文件（流式文件）**

    * > **定义**：一连串的二进制流或字符流，没有明显的结构特性。

    * Windows 的 `.txt` 文件是最典型的例子；谈不上逻辑结构问题，不用展开讨论。

* **有结构文件（记录式文件）**

    * > **定义**：由一组相似的记录组成，每条记录又由若干数据项组成，最直观的例子是数据库表。

    * 每条记录一般可拿出一个数据项作为**关键字（key）**，用于唯一识别不同的记录，充当记录的 id。

* **定长记录**

    * 每条记录长度相同，且每个数据项在记录中所处的位置相同。

    * 例：学号 32 字节 + 姓名 32 字节 + 性别 4 字节 + 专业 60 字节，每条记录总长固定 128 字节。

* **可变长记录**

    * 每条记录长度不固定，是生活当中最常见的一类有结构文件。

    * 根因：类似"特长"这种字段，有的记录内容很多、有的几乎没有，给所有记录分配巨大的固定空间会导致存储空间利用率低到无法接受；而"专业"这类字段几个字就能描述，固定分配 60 字节浪费并不明显。

## 顺序文件

* **顺序文件（sequential file）**

    * > **定义**：有结构文件中，记录一个接一个地顺序排列的逻辑结构。

    * 记录可以是定长的也可以是可变长的；物理上既可以**顺序存储**（逻辑相邻物理也相邻，类似顺序表），也可以**链式存储**（逻辑相邻物理不一定相邻，类似链表）。

* **串结构**

    * 记录之间的顺序与关键字无关，一般按存入时间的先后来决定。

* **顺序结构**

    * 记录必须按关键字的顺序排列。

* **能否随机存取（已知起始地址，快速定位第 $i$ 个记录）**

    * 链式存储：无论定长还是可变长、串结构还是顺序结构，都不能随机存取——各记录存储位置离散、无规律，无法直接算出地址，只能从第一个记录依次往后找。

    * 顺序存储 + 可变长记录：仍不能随机存取——每条记录前要额外存长度字段（设 1 字节），第 $i$ 条记录的地址是前 $i$ 条记录长度之和再加上 $i$ 个长度字节，而各记录长度无规律可循，只能从第一条开始数。

    * 顺序存储 + 定长记录（每条长 $L$）：能随机存取——第 $i$ 号记录的逻辑地址直接算 $i \times L$。

    * > **易错点**：顺序存储不等于能随机存取，"顺序存储 + 可变长记录"这一档最容易混——记录长度不定就没有可算的规律。

* **能否按关键字快速检索**

    * 串结构：记录顺序与关键字无关，只能从头依次遍历。

    * 定长记录 + 顺序结构（记录按关键字有序）：可以用**折半查找**快速定位。

* **增删记录**

    * 顺序存储的顺序文件增删记录和顺序表一样困难；若用串结构，不需要保证按关键字排序，新增记录直接插到文件末尾即可，相对简单。

    * 实际系统中为减少磁盘 I/O，一般管理一个**日志文件**，先把对各记录的修改记在日志里，每隔较长时间（如每小时、每 10 分钟）统一合并到外存文件数据中；此点考试不考。

* > **注意**：考题里说"顺序文件"，默认指物理上采用顺序存储的顺序文件，不需要考虑链式存储的情况。

## 索引文件

* **索引文件（index file）**

    * > **定义**：为文件建立一张索引表，索引表的每个表项对应文件的一条记录，借助表项间接定位记录的逻辑结构。

    * 提出动机：可变长记录的顺序文件找第 $i$ 个记录必须先顺序查完前 $i-1$ 个，而现实中很多场景必须用可变长记录——索引文件让可变长记录的文件也能"间接"实现随机访问。

* **索引表的关键性质**

    * 文件的记录在物理上**不需要连续存放**，但索引表的各表项在物理上**需要连续存放**。

    * 每个表项**大小相等**（如索引号、长度、指针各 4 字节，一个表项固定 12 字节），因此索引表本身就是一种**定长记录的顺序文件**——支持随机访问，可快速定位第 $i$ 条记录对应的表项，再顺指针取记录。

    * 若把关键字作为索引号内容并按关键字顺序排列索引表，还能支持**折半查找**，检索速度大幅提升。

    * 增加记录要同步增加表项，删除记录要同步删掉表项。

* **应用与扩展**

    * 主要用于**对信息处理的及时性要求很高**的场合。

    * 除关键字外，还可用别的数据项作为索引号，为同一个文件建**多张索引表**：如学生表既按"学号"建一张，也按"姓名"建一张，两个维度都能快速检索；SQL 的一条建索引语句完成的就是这个功能。

* **索引文件的缺点**

    * 每条记录对应一个表项，表项较大时索引表自身占很大空间：如每条记录平均 8 字节而每个表项 32 字节，索引表长度是文件内容本身的 4 倍，存储空间利用率太低。

## 索引顺序文件

* **索引顺序文件（indexed sequential file）**

    * > **定义**：索引文件与顺序文件思想的结合——同样建索引表，但不给每条记录建表项，而是把记录分组，每组对应一个索引项，索引项记录分组名和分组存放位置。

    * 每个分组本身又是一个顺序文件。

    * 索引项**不需要按关键字顺序排列**（串结构），新表项插入更方便——所以索引表是**定长记录的串结构顺序文件**。

    * 分组后索引表项大大减少，实现索引表"瘦身"。

* **平均查找次数的计算**

    * 不分组：$10^4$ 个记录按关键字顺序检索，平均查 $\frac{10000}{2}=5000$ 个记录。

    * 一级分组（$10^4$ 条，分 100 组、每组 100 条）：查索引表平均 50 次 + 组内平均 50 次 = **100 次**。

    * 一级分组（$10^6$ 条，分 1000 组、每组 1000 条）：平均 $500+500=1000$ 次。

    * 两级索引（$10^6$ 条：100 张低级索引表、每张 100 项、每组 100 条记录）：顶级索引平均 50 次 + 低级索引平均 50 次 + 组内平均 50 次 = **150 次**。

    * > **易错点**：套路是"每顺序查一张定长表平均查表长的一半，各层一半相加即总次数"。分组数与组内记录数的配比直接决定平均查找次数，$10^4$ 一级分组是 $50+50=100$，$10^6$ 一级分组是 $500+500=1000$，改成两级索引才压到 $50\times3=150$。

## 文件目录与 FCB

* **文件控制块（File Control Block，FCB）**

    * > **定义**：存放文件名、物理地址等文件相关控制信息的数据结构，每个文件都对应一个 FCB。

    * 包含三类信息：文件的基本信息（文件名、物理地址、逻辑结构、物理结构等）、存取控制信息（是否可读、可写等）、使用信息（建立时间、上次修改时间等）；文件的各种属性都可放进其 FCB。

    * 其中**最重要的是文件名和文件的物理地址**——FCB 最重要的作用是实现按名存取，即建立"文件名 → 物理地址"的映射。

* **文件目录 / 目录项 / 目录文件**

    * > **定义**：FCB 的有序集合组成**文件目录**；一个 FCB 就是一个**文件目录项**；存放目录的文件叫**目录文件**，它本身是一种有结构的记录式文件——目录也是一种特殊的文件。

    * 打开一个文件夹时，系统查询上级目录文件，找到该目录对应的目录项，再按目录项记录的存放位置把目录文件数据从外存读入。

* **目录要支持的操作**

    * **搜索**：按文件名搜索目录找到对应目录项，是按名存取的基础。

    * **创建文件**：在所属目录中增加一个目录项。

    * **删除文件**：除删除文件数据本身，还要删掉目录里对应的目录项。

    * **显示目录**：列出该级下有哪些文件、目录，可顺带显示文件属性。

    * **修改目录项**：文件属性变化时同步修改，如重命名要改目录项里的文件名信息。

* **按名存取**

    * > **定义**：用户按文件的名字来操作文件，由目录结构支持。

    * 分层的目录结构让文件组织清晰、易于查找；打开文件函数把路径名作参数，系统顺路径一层层往下找到目标文件。

## 目录结构的演进

* 每一种目录结构都是为了**解决上一种遗留的最主要问题**：单级不能重名 → 两级不能分类 → 树形不能共享 → 无环图补上共享。

### 单级目录

* 全系统只建立**一张目录表**，每个文件占一个目录项。

* 支持按名存取；但目录项以文件名区分，**不允许文件重名**——创建文件必须先检查重名，不重名才允许建立并插入 FCB。

* 多用户机器上不同用户的文件名极易撞车，**不适用于多用户操作系统**。

### 两级目录

* 分两级：第一级**主文件目录（Master File Directory，MFD）**记录用户名及对应用户文件目录的存放位置；第二级**用户文件目录（User File Directory，UFD）**由该用户文件的 FCB 组成。

* 不同用户的文件放在各自 UFD 下，**允许不同用户的文件重名**。

* 可实现**访问限制**：user1 访问 user2 的 UFD 时，系统验证用户名不匹配即拒绝。

* 缺点：用户没办法给自己的文件**分类**。

### 树形目录

* **多级目录结构**又称**树形目录结构**，是现代操作系统常用的目录结构：每个目录下可有更低一级目录，也可有普通文件；**不同目录下的文件允许重名**。

* 访问文件用**路径名**作标识符，各级目录间用 `/` 隔开；**从根目录出发的路径称为绝对路径**。

* **每往下一级查询，都必须启动一次磁盘 I/O**，把下一级目录文件从外存调入内存——例：绝对路径 根目录 → 照片 → 201508 → 自拍.jpg 需要 3 次读盘。

* **当前目录与相对路径**：用户常连续访问同一目录里的多个文件，把已调入内存的目录文件设为当前目录，之后**从当前目录出发**的路径叫**相对路径**——省掉前面各级目录的读盘，同样定位自拍.jpg 只需 1 次读盘，访问效率提升。

* 优点：方便文件分类、层次清晰、便于管理和保护；缺点：**不便于实现文件共享**（常考选择题）。

### 无环图目录

* 在树形结构基础上增加一些**指向同一个节点的有向边**，使目录结构成为有向无环图。

* 方便实现多用户间的文件共享，且可以**用不同的文件名指向同一个文件**（user1 的 `demo` 与 user2 的 `mydemo` 是同一份数据）；共享文件之外还可以共享目录（目录本身也是特殊文件）。

* **共享计数器**：每个共享节点设一个计数器，记录当前有几个用户共享该节点；某用户删除时系统只删该用户的目录项并让计数器减 1，文件实际内容不删；**只有计数器减到 0** 才真正删除共享文件。

* > **易错点**：共享与复制完全不是一回事——复制的副本是两个不同文件，改副本不影响原文件；共享的两个名字指向同一份数据，任何一方修改另一方立刻可见。

| 目录结构 | 关键特征 | 解决了什么问题 | 遗留的主要缺点 |
|:---|:---|:---|:---|
| 单级目录 | 全系统一张目录表 | 实现按名存取 | 不允许文件重名，不适用多用户 |
| 两级目录 | MFD + UFD | 不同用户文件可重名，可做访问限制 | 用户无法给自己的文件分类 |
| 树形目录 | 多级层次，用路径名定位 | 文件可分类、层次清晰、便于管理保护 | 不便于实现文件共享 |
| 无环图目录 | 树形 + 指向同一节点的有向边 | 方便多用户间文件共享 | 删除要靠共享计数器管理 |

## 索引节点

* **索引节点（index node）**

    * > **定义**：对 FCB 的改进——按文件名检索目录时真正用到的只有文件名，把除文件名外的其他信息（文件类型、物理位置等）挪到索引节点中，每个文件有唯一的索引节点。

    * 目录项瘦身为"文件名 + 指向索引节点的指针"，目录表占用空间大幅缩小。

* **目录项变小为何加快检索（一笔账）**

    * 改造前：FCB 64 字节、磁盘块 1KB，每块放 16 个目录项；640 个目录项占 40 个磁盘块，平均查 320 个目录项需 20 个磁盘块，平均**启动磁盘 20 次**。

    * 改造后：目录项 = 文件名 14 字节 + 指针 2 字节共 16 字节，每块放 64 个目录项；同样平均查 320 个目录项只需 5 个磁盘块，即 **5 次启动磁盘**。

    * 因果链：目录项变小 → 每个磁盘块装得下更多目录项 → 平均检索范围跨越的磁盘块数变少 → 启动磁盘次数变少 → 检索速度提升。I/O 是最耗时的环节，每一环都要能自己推出来。

* **磁盘索引节点与内存索引节点**

    * 存放在外存中的索引节点叫**磁盘索引节点**。

    * 调入内存后叫**内存索引节点**，需增加信息：文件是否被修改过、当前有几个进程正在访问它等。

## 文件的物理结构与逻辑地址

* **磁盘块（物理块）**

    * > **定义**：磁盘被划分成的一个个大小相等的存储单元，并统一编号（0 号块、1 号块……）。

    * 很多操作系统中磁盘块大小设置得与内存页面大小相同——内存与外存的数据交换以块为单位，两边等大时交换很方便。

* **文件块与文件逻辑地址**

    * 文件的逻辑地址空间被划分成一个个大小相等的**文件块**，类比内存管理中进程逻辑空间被划分为页面。

    * > **定义**：文件逻辑地址 =（逻辑块号，块内地址），与"逻辑地址 =（页号，页内地址）"思路完全对应。

    * 例：物理块 1KB，1MB 的文件分为 1K 个块，逻辑块号为 0 到 1023。

* **操作系统的职责**

    * 各逻辑块实际存放到磁盘的什么位置，**用户不可知**；操作系统负责把用户提供的逻辑块号转换为物理块号（块内地址不需要转换）。

    * > **核心问题**：怎么把**逻辑块号**映射为**物理块号**——每种分配方式本质上都在回答这个问题。

## 连续分配

* **连续分配（continuous allocation）**

    * > **定义**：要求每个文件在磁盘上占用一组连续的块，逻辑相邻的块物理上也相邻且保持相对顺序。

    * FCB 中需记录两个属性：**起始块号**与**长度**（占用的块数）。

* **地址转换**

    * $$\text{物理块号} = \text{起始块号} + \text{逻辑块号}$$

    * 例：文件起始块号 4，访问逻辑块 2 → 物理块 $4+2=6$；转换前还需**验证逻辑块号是否合法**（是否超过文件实际长度）。

* **优点**

    * **支持顺序访问和直接访问（随机访问）**：访问逻辑块 2 无需先访问其他块，直接算出物理位置——这是连续分配最大的优点。区分：顺序访问必须先依次访问逻辑块 0、1 才到 2；直接访问可直接定位。

    * **顺序读写速度最快**：读物理相邻的块时磁头移动距离最短，两块距离越远磁头移动时间越长，故连续分配的文件顺序读取各块时读写时间最短。

* **缺点**

    * **文件拓展很不方便**：文件后面的相邻块可能已被别的文件占用，拓展不得不把整个文件的数据迁移到另一片有足够连续空闲块的区域，迁移开销很大。

    * **产生难以利用的磁盘碎片，存储空间利用率低**：离散空闲块总数够但没有连续的几块时，无法给新文件分配空间；类似内存管理的外部碎片，可用**紧凑**解决，但移动大量磁盘块内容的时间代价很大。

## 隐式链接

* **隐式链接（implicit linking）**

    * > **定义**：链接分配的一种——采取离散分配思想，为文件分配离散磁盘块，各块内拿出一定空间存放指向下一块的链接指针（最后一个块没有指针），指针对用户透明。

    * 链接分配允许离散分配磁盘块，用指针把块串联起来，分为隐式链接和显式链接两种。

    * FCB 中需记录**起始块号**和**结束块号**。

* **地址转换与访问**

    * 访问逻辑块 $i$ 必须先读入起始块（0 号逻辑块）——只有读入后才能知道其中"指向下一块的指针"，才能依次调入后续块。

    * 想访问 $i$ 号逻辑块，必须**依次读入 0 到 $i-1$ 号逻辑块**，总共需要 $i+1$ 次磁盘 I/O 操作。

* **优缺点**

    * 只支持**顺序访问**、不支持随机访问，**查找效率很低**；每块还要耗费少量空间存链接指针。

    * 优点：文件拓展很方便——随便找一个空闲块挂到链尾，再修改 FCB 中的结束块号即可；**不会产生碎片问题，外存利用率很高**。

## 显式链接（FAT）

* **文件分配表（File Allocation Table，FAT）**

    * > **定义**：显式链接方式中，把链接各物理块的指针显式集中存放在的一张表中——磁盘有多少个块，表中就有多少个表项。

    * 每个表项记录该块的"下一块"块号；文件最后一个块的表项记特殊值 $-1$ 表示文件结尾。

    * FCB（目录项）中只需记录文件的**起始块号**。

* **组织方式**

    * **一个磁盘仅设一张 FAT**，所有文件各盘块的先后顺序统一记录其中（例：文件 AAA 依次占 2、5、0、1 号块，FCB 记起始块号 2，FAT 中 2→5、5→0、0→1、1→−1）。

    * FAT 各表项物理上**连续存储**且**长度相同**（如"下一块"用 4 字节表示，则"物理块号"字段可**隐含**，按表项位置即可推知块号）。

    * **开机时 FAT 读入内存并一直常驻内存**——因此**查 FAT 不需要读磁盘**。

* **地址转换与特点**

    * 访问逻辑块 $i$：由 FCB 得起始块号后，直接在内存中逐级查 FAT 表项即可定位，**不需要依次访问前面的块，也不需要读磁盘**。

    * 因此**既支持顺序访问也支持随机访问**，相比隐式链接访问速度快很多；同样不产生外部碎片、文件拓展方便。

    * 缺点：**FAT 需要占用一定的存储空间**。

* > **易错点**：题目只说"链接分配的文件"而未指明显式还是隐式时，**默认指隐式链接**。

* > **对比**：显式链接的 FAT 是一个磁盘一张；索引分配的索引表是每个文件一张。

## 索引分配

* **索引分配（index allocation）**

    * > **定义**：允许为文件分配离散的磁盘块，并为**每一个文件**建立一张**索引表**，记录文件各个逻辑块对应的物理块。

    * 功能类似内存管理中的**页表**：页表建立逻辑页面 → 物理页框的映射，索引表建立文件逻辑块 → 物理块的映射。

* **索引块与数据块**

    * **索引块**：磁盘中用于存放索引表的那个磁盘块。

    * **数据块**：用于存放文件实际数据的磁盘块。

    * 采用索引分配的文件，FCB 中记录**自己的索引块号**——据索引块号找到索引表，再查各逻辑块对应的物理块号。

* **表项定长与逻辑块号隐含**

    * 每个表项用固定字节表示物理块号：磁盘总容量 1TB（$2^{40}$ 字节）、磁盘块 1KB，则共 $2^{30}$ 个磁盘块，30 个二进制位即可表示块号，4 字节（32 位）足够——每个表项占 4 字节。

    * 表项定长后，索引表中的"逻辑块号"可**隐含**：知道索引表起始位置，就能按逻辑块号直接算出对应表项的位置——与通过逻辑页号定位页表项的方式一模一样。

* **地址转换与优缺点**

    * 访问逻辑块 $i$：FCB 中取索引块号 → 从索引块读出索引表 → 按逻辑块号查表得物理块号；**不需要顺序访问前面的块，支持随机访问**。

    * 文件拓展容易：随便找一个空闲块，在索引表中增加相应表项即可。

    * 缺点：**索引表需要占用一定的存储空间**。

## 索引表太大：三种解决方案

* 问题背景：磁盘块 1KB、索引表项 4 字节时，一个磁盘块只能存 $1K \div 4 = 256$ 个索引项；文件超过 256 块则索引表一个磁盘块装不下。解决方案：**链接方案、多层索引、混合索引**。

### 链接方案

* 为文件的索引表分配**多个索引块**，每个索引块存 256 个索引项并用一定空间存**指向下一个索引块的指针**，串联起来；FCB 只记录**第一个索引块**的块号。

* 致命低效：想查第 256 号逻辑块必须先读入第一个索引块才能拿到第二个索引块的块号，再读入第二个索引块。

* 例：文件 64MB（$256\times256$ KB）占 $256\times256$ 个块，需 256 个索引块链起来；访问**最后一个逻辑块**必须先依次读入前面所有索引块——光是地址转换就可能需要 **200 多次读磁盘操作**，这是链接方案的最大问题。

### 多层索引

* **多层索引（multi-level index）**

    * > **定义**：建立多层的索引表，第一层索引块指向第二层索引块，文件很大时还可建第三层、第四层——原理类似多级页表。

    * FCB 中只需记录**顶级索引表**所在的索引块号。

* **文件最大长度的计算**

    * 前提条件要抠死：采用多级索引结构时，**各层索引表的大小不能超过一个磁盘块**。

    * 两层索引（每块 256 项、数据块 1KB）：文件最大长度 $256 \times 256 \times 1\text{KB} = 64\text{MB}$。

    * 三层索引：最大长度 $256 \times 256 \times 256 \times 1\text{KB} = 16\text{GB}$。

* **读磁盘次数**

    * 访问 1026 号逻辑块（两层索引）：$1026 \div 256 = 4$ 定位到 4 号二级索引表（由一级索引表 4 号索引项查得其位置）；$1026 \bmod 256 = 2$ 定位该二级表的 2 号表项得物理块号。

    * 全程 3 次读磁盘：第一次读一级索引表、第二次读对应二级索引表、第三次读目标数据块。

    * > **结论**：采用 K 层索引结构且**顶级索引表尚未调入内存**时，访问一个数据块共需 **K+1 次读磁盘操作**。

    * 遗留问题：文件很小（如数据只有 1KB）时，两层索引下读这 1KB 仍需 3 次读盘——引出混合索引。

### 混合索引

* **混合索引（multi-hybrid index）**

    * > **定义**：多种索引分配方式的结合——顶级索引表中同时包含直接地址索引、一级间接索引和二级间接索引。

    * **直接地址索引**（如 8 个）：索引项**直接指向数据块**，对应 8 个数据块。

    * **一级间接索引**：指向一个**单层索引表**，该表各索引项分别指向数据块，最多 256 个数据块。

    * **二级间接索引**：指向一个**两层索引表**，第二层索引表的各表项再分别指向数据块，最多 $256\times256=65536$ 个数据块。

* **文件最大长度**

    * $$8 + 256 + 65536 = 65800 \text{ 个块} = 65800\text{KB}$$

* **读磁盘次数（假设顶级索引表未读入内存）**

    * 0～7 号逻辑块（直接地址）：读顶级索引表 + 读数据块 = **2 次**。

    * 8～263 号逻辑块（一级间接）：顶级索引表 + 一级索引表 + 数据块 = **3 次**。

    * 二级间接覆盖范围：顶级索引表 + 各级索引表 + 数据块 = **4 次**。

    * 好处：**小文件只需较少的读磁盘次数**——而计算机中小文件是更多的，这就是混合索引的价值。

* > **易错点**：索引分配的两条必会——①根据多层索引或混合索引结构**计算文件最大长度**，关键条件是"各级索引表最大不能超过一个块"；②**分析访问某数据块的读磁盘次数**，特别注意题目是否说明**顶级索引块已调入内存**——有无这一条件答案完全不同。

## 逻辑结构与物理结构的辨析

* **用户视角与操作系统视角的同一个文件**

    * 用户用 C 语言向文件写入的每个字符各占 1 字节，用户看来文件占用一整片连续的逻辑地址空间，`fseek` 可把读写指针指向任意想读写的位置。

    * 操作系统眼里整个文件只是一堆二进制数据，按磁盘块大小（如 1KB）切成逻辑块 0、1、2、3……再用连续分配、链接分配或索引分配存进磁盘；`fgetc` 这类库函数底层调用 `read` 系统调用，系统把逻辑地址转换为"逻辑块号 + 块内偏移量"再转成物理块号。

* **顺序文件的用户实现**

    * 定义结构体（如 `int id` 4 字节 + `char name[30]` + `char major[30]`，每条记录 64 字节），用 `fwrite` 按 `sizeof(struct StudentInfo) × N` 写入 N 条记录；读第 5 号记录时 `fseek` 定位到偏移 $5\times\text{sizeof(struct StudentInfo)}$ 处再 `fread` 一条——这是**顺序存储**。

    * 链式存储由用户自己设计：在结构体里增加 `next` 字段指向下一个学生记录的存放位置（如 0 号学生的 `next` 填 3，表示 1 号学生存在数组下标 3 处）。顺序存储可直接算出第 $i$ 条记录地址，链式存储只能从第一条顺着指针往后找——差别与顺序表、链表完全一致。

* **链式存储 ≠ 链接分配**

    * 逻辑结构里的链式存储：链接的是**文件内部的一条条记录**，由**文件主（用户）**自己设计，链接信息用户关心、操作系统不管。

    * 物理结构里的链接分配：链接的是**拆分后的一个个逻辑块**，由**操作系统**建立，链接信息操作系统关心、用户不用管。

    * | 对比 | 逻辑结构：链式存储 | 物理结构：链接分配 |
      |:---|:---|:---|
      | "链"的对象 | 文件内部的一条条记录 | 拆分后的一个个逻辑块 |
      | 谁来设计、建立 | 文件主（用户）自己 | 操作系统 |
      | 谁需要关心链接信息 | 用户关心，操作系统不管 | 操作系统关心，用户不用管 |

* **索引文件 ≠ 索引分配**

    * 逻辑结构里的索引文件：索引表由**文件主（用户）**自己建立，映射关系是**记录的关键字 → 记录的逻辑地址**。

    * 物理结构里的索引分配：索引表由**操作系统**建立，映射关系是**逻辑块号 → 物理块号**。

    * | 对比 | 逻辑结构：索引文件 | 物理结构：索引分配 |
      |:---|:---|:---|
      | 索引表谁建立 | 文件主（用户）自己 | 操作系统 |
      | 索引表记录什么 | 记录的关键字 → 记录的逻辑地址 | 逻辑块号 → 物理块号 |

## 文件存储空间管理概述

* 磁盘管理的两件事：对**非空闲磁盘块**的管理即文件物理结构（文件分配方式）；对**空闲磁盘块**的管理即文件存储空间管理。

* 学习每种管理方法抓三个角度：①用什么数据结构**记录和组织**空闲磁盘块；②**怎么分配**；③**怎么回收**。

* **文件卷（逻辑卷、逻辑盘、逻辑磁盘）**

    * > **定义**：物理磁盘划分出的逻辑磁盘，即常见的 C 盘、D 盘、E 盘，文件存放在各个文件卷里。

    * 文件卷初始化时进一步划分为**目录区**和**文件区**：目录区存放文件目录、FCB、索引节点，以及空闲表、位示图等用于存储空间管理的数据结构；文件区存放普通文件数据。

    * 平常是把一个物理磁盘划分成多个逻辑磁盘；支持超大型文件的操作系统可以把**多个物理磁盘合并成一个逻辑磁盘（文件卷）**。

## 空闲表法

* **空闲表**

    * > **定义**：记录每一个空闲区间的起始盘块号与空闲盘块数的表，与内存管理动态分区分配中的空闲表极其类似。

    * 一般适用于文件的物理结构为**连续分配**的场景。

* **怎么分配**

    * 为文件分配**连续**的存储空间，可采用**首次适应、最佳适应、最坏适应**算法决定分配哪个空闲区间。

    * 例：请求 3 块，首次适应依次检查表项，找到第一个能满足的空闲区间（10～14 号块，共 5 块），摘出 10、11、12 分配，并把表项改写为起始块号 13、空闲块数 2。最佳适应找能满足要求且**最小**的空闲区间，最坏适应找**最大**的连续空闲区间。

* **怎么回收**

    * 与动态分区分配类似，注意**表项合并**的四种情况：前后都无相邻空闲区 → 新增一个表项；前后都是空闲区 → 合并成一个空闲区，表项数**减一**；仅前面是空闲区 → 表项数不变；仅后面是空闲区 → 表项数不变。

    * 例：回收 15、16、17 号块且前后都有空闲区时，把两个表项合二为一（起始块号 13、连续 8 块）。

## 空闲链表法

* **空闲盘块链**

    * > **定义**：以盘块为单位组成一条空闲链，每个空闲盘块中存储指向下一个空闲盘块的指针。

    * 系统保存链头和链尾指针。分配 K 个盘块：从链头依次摘下 K 块并修改链头指针；回收：把盘块依次挂到链尾并修改链尾指针。

    * 一般适用于**离散分配**的物理结构；分配时只能从链头一个一个地摘，为文件分配多个盘块时可能需要重复多次操作。

* **空闲盘区链**

    * > **定义**：以盘区为单位组成一条空闲链，盘区是若干**连续**空闲盘块组成的区域，每个盘区的第一个盘块里记录本盘区长度 + 指向下一盘区的指针。

    * 分配：采用首次适应、最佳适应等算法从链头检索大小合适的盘区；找不到合适的**连续**空闲块时，也可把不同盘区的盘块同时分配给一个文件（如需 6 块而无连续 6 块，可给一个 3 块盘区 + 另一个 3 块盘区）。

    * 回收：与空闲表法类似，注意回收区与空闲盘区的**合并**；无相邻空闲盘区时作为单独盘区挂到链尾。

    * > **提示**：空闲盘区链既适用于离散分配也适用于连续分配；比空闲盘块链更适合给一个文件分配多个盘块——盘块链只能一个一个摘，盘区链可以一次摘出一大片连续区间。

## 位示图法

* **位示图（bitmap）**

    * > **定义**：用一个个二进制位分别对应各个盘块是否已分配（如 0 代表空闲、1 代表已分配），一般存储成一系列连续的字。

    * 考试最常考的存储空间管理方法。

* **字号、位号与盘块号的换算**

    * 用**字号**与**位号**组成的二元组定位某一个二进制位（如字长 16 位，一行就是一个字）。

    * 设字长为 $N$，从 0 开始编号时，字号 $i$、位号 $j$ 对应的盘块号：

      $$b = N \times i + j$$

      验证：字长 16，字号 0 位号 1 → 盘块 1；字号 1 位号 10 → 盘块 26。

    * 反推：字号 $i = \lfloor b / N \rfloor$，位号 $j = b \bmod N$。例：盘块 13 → 字号 0 位号 13；盘块 31 → 字号 1 位号 15。

    * > **提示**：本例是盘块号、字号、位号都从 0 开始的算法；教材上有的是都从 1 开始的版本。不管哪种起始约定，都要能自己推导出来，不需要死记硬背。

* **怎么分配**

    * 文件需要 K 个块时，顺序扫描位示图，找到 K 个 0（空闲），算出对应盘块号分配，并把相应位置 1。

* **怎么回收**

    * 根据盘块号算出字号、位号，找到相应二进制位并置 0。

* **适用范围**

    * 连续分配和离散分配都适用：连续分配要求扫描时找到**连续**的 K 个 0，离散分配则不要求连续。

* > **易错点**：做题先盯两个条件——①盘块号、字号、位号从 0 还是从 1 开始；②0 和 1 哪个代表空闲（本例 0 空闲 1 已分配，题目完全可以反过来规定）。

## 成组链接法

* **成组链接法（grouped linking）**

    * > **定义**：UNIX 采用的空闲磁盘块管理方法，对空闲块**分组**管理，适合大型文件系统——空闲表和空闲链表在大型文件系统中可能很长很大。

* **超级块（super block）**

    * 文件卷目录区中专门设置的一个磁盘块；**系统启动时读入内存**，并始终保持内存与外存中超级块数据一致。

    * 记录**下一组**空闲盘块的数量及这些盘块的盘块号，充当**链头**——永远保持着指向下一个分组的信息。

* **分组结构**

    * 每个分组的**第一个磁盘块**里记录**下一组**空闲盘块的数量和各盘块号，由此逐组链接到全部空闲盘块。

    * **倒数第二个分组**的第一个盘块里记特殊值 **1**，表示再下一个分组已是最后一个分组——找到值为 1 的节点即知之后没有更多分组。

    * 每个分组的盘块号**并不要求连续**；每组盘块数有**上限**（例中 100 个），且**最后一个分组的盘块数比其他分组少一块**（原因正是那个值为 1 的特殊节点）。

* **怎么分配**

    * 分配 1 个块：检查内存中超级块的"下一组空闲盘块数"是否够（不读磁盘），把该分组"最后"的那个盘块分配出去，从超级块中删掉它的盘块号并把计数减一（例：100 块的第一组分出 201 号块后剩 99）。

    * 分配整组（如要 100 块而第一组恰有 100 块）：**把整组分配出去之前，必须先把其中保存的指向下一分组的链接信息复制到超级块**——否则下一组的链接信息随该块被分配而断掉。要更多块时逐组照此处理。

* **怎么回收**（设每组上限 100 块）

    * 第一个分组**还没满**：把回收块的盘块号放进超级块，计数加一（99 → 100）。

    * 第一个分组**已满**：把超级块中的内容**复制到新回收的块中**，让该块作为**新分组**并拥有指向下一分组的链接指针；再修改超级块指向这个新分组（计数 1、盘块号为新回收块）。

* > **提示**：成组链接法规则复杂、不便文字描述，很难作为考题考察；但理解了分配与回收的过程，考到也能做出来。

## 文件的基本操作

### create 与 delete

* **create 系统调用**

    * > **定义**：创建文件时发起的系统调用，处理流程是——①在外存中找到并分配文件申请的磁盘空间；②在文件存放路径对应的目录表中插入该文件的目录项。

    * 需要的参数：**外存空间大小**（如一个 1KB 盘块）、**存放路径**、**文件名**；Windows 右键新建文本文档时这些参数由系统自动填好。

    * 分配存储空间的具体做法取决于所用的空闲块管理策略（空闲表法、空闲链表法、位示图法、成组链接法等）；插入的目录项要包含文件名、存放位置等信息。

* **delete 系统调用**

    * > **定义**：删除文件时发起的系统调用，处理流程与创建相反——①按存放路径找到目录表；②按文件名找到目录项，据此回收文件占用的磁盘块；③删除目录表中的目录项。

    * 参数：文件的**存放路径**、**文件名**；回收磁盘块同样按不同空闲块管理策略做不同处理。

### open 与两种打开文件表

* **open 系统调用**

    * > **定义**：对文件操作前先"打开"文件的系统调用，处理流程是——①按路径找到目录表，根据目录项**检查用户的操作权限**；②检查通过后把该文件的**目录项复制到内存中的打开文件表**。

    * 参数：**存放路径**、**文件名**、**操作类型**（只读还是读写等）；访问权限信息记录在目录项中，无权限则拒绝打开、终止处理。

    * 把目录项复制到打开文件表的意义：文件信息已在内存，之后按打开文件表编号即可找到文件的一切信息，**不需要每次查文件都重新访问目录**，大幅提升访问速度。

* **系统的打开文件表**

    * 整个系统**只有一张**，记录所有正在被进程使用的文件的信息。

    * 特有字段**打开计数器**：记录该文件此时已被几个进程打开（两个进程打开同一文件则为 2）。

    * 用途示例：Windows 删除被记事本进程打开的 txt 时提示"暂时无法删除"——系统先查系统打开文件表，发现文件正被使用便拒绝删除。

* **进程的打开文件表**

    * 每个进程**各有一张**，只记录自己此时打开了哪些文件，表项中有指向系统表表项的索引号。

    * 特有字段一：**读写指针**——该进程对文件读写进行到的位置，各进程进度不同，故必须放在进程表中。

    * 特有字段二：**访问权限**——该进程打开文件时申请的访问类型（如只读），之后尝试越权写操作会被系统据此拒绝。

### close、read 与 write

* **close 系统调用**

    * > **定义**：关闭文件时发起的系统调用，处理流程是——①删除进程打开文件表中对应表项，回收分配给该文件的内存缓冲区等资源；②将系统打开文件表中对应表项的**打开计数器减一**，计数器减到零才删除系统表中的表项。

    * 计数器仍大于零说明文件还被其他进程使用，系统表表项暂时不能删除——与硬链接共享的链接计数思路如出一辙。

* **read 系统调用**

    * 参数：读**哪一个文件**（只需指明它在进程打开文件表中的编号）、读入**多少数据**、读入的数据放在**内存什么位置**。

    * 操作系统根据打开文件表中**读指针**所指向的外存地址，读入指定大小的数据放到指定内存区域。

* **write 系统调用**

    * 参数与 read 对应：写哪个文件（打开文件表序号）、写回多少数据、数据在内存的位置；操作系统从指定内存区域读出数据，写到**写指针**所指向的外存区域。

* > **易错点**：**打开文件并不会把文件数据读入内存**，只是把文件的目录项复制到内存的打开文件表；只有**读文件**时文件数据才真正从外存读入内存——这是最容易混淆、也最容易在选择题里考的一点。

* **文件描述符（file descriptor）**

    * > **定义**：系统返回给用户的打开文件表**索引号**，有的教材也称文件描述符，考试中出现过该术语。

    * 之后用户根据索引号查询打开文件表直接操作文件，不再需要每次查询目录；**读写文件时不需要再提供文件名、文件路径**，只提供文件描述符即可。

## 文件共享

* **共享与复制的区别**

    * > **定义**：共享意味着系统中**只有一份文件数据**，任一用户修改，其他用户都能看到变化；复制则是各用户各有一份数据，互不影响。

* **硬链接（基于索引节点的共享方式）**

    * > **定义**：让不同用户的目录项指向同一个文件的索引节点，从而共享同一份数据。

    * 前提是索引节点的"瘦身"策略：目录项只含文件名和指向索引节点的指针，物理地址等属性都在索引节点中。

    * 索引节点中设置**链接计数（count）**，表示当前链接到该索引节点的用户目录项个数；第二个用户的目录项也指向它时 count 加一。

    * 不同用户给同一文件起的名字可以不同（User1 的 `aaa`、User2 的 `bbb` 指向同一索引节点）。

    * **删除细节**：某用户删除文件时，系统只删除该用户目录中的目录项（断开链接）并把 count 减一；**只有 count 减到零**才真正删除文件数据和索引节点；count 大于零时绝不能直接删数据，否则其他用户的链接会变成悬空指针。

* **软链接（基于符号链的共享方式）**

    * > **定义**：新建一个特殊的 **Link 型文件**，其内容记录被共享文件的**存放路径**，操作系统按该路径逐层检索目录找到并访问共享文件。

    * 软链接并不把自己的目录项指向目标文件的索引节点，而是通过路径间接访问；类似 Windows 的**快捷方式**——桌面快捷方式就是一种 Link 型文件，双击时系统按其中记录的路径一层层查找，最终定位到启动程序。

    * **删除共享文件的后果**：目标文件和索引节点可直接删除（count 减到零即可删）；此后再访问 Link 型文件，按路径已查不到目标目录项，**软链接失效**（对应 Windows 提示"快捷方式所指向的项目已经删除"），但 **Link 型文件本身依然存在**。

    * **速度**：软链接每访问一次都要按路径逐层查询目录，伴随磁盘 I/O；硬链接的目录项直达索引节点——**软链接访问速度比硬链接更慢**。

* **两种共享方式对比**

    * | 对比项 | 硬链接（基于索引节点） | 软链接（基于符号链） |
      |:---|:---|:---|
      | 共享结构 | 多个用户的目录项直接指向同一个索引节点 | 新建 Link 型文件，内容是共享文件的存放路径 |
      | 允许的文件名 | 各用户的目录项可以使用不同的文件名 | Link 型文件名字随意，类比快捷方式 |
      | 删除共享文件 | count 减一，count 为零才真正删除文件数据和索引节点 | 文件可直接删除；Link 型文件仍在，但按路径查找失败（链接失效） |
      | 访问速度 | 快（目录项直达索引节点） | 慢（每次访问都要按路径逐层检索目录，伴随磁盘 I/O） |
