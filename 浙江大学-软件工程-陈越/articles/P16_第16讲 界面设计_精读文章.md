# 第16讲 界面设计：以用户为中心的交互准则

## 一、交互本质与用户认知

用户界面（User Interface，UI）是用户接触软件的窗口，也是一切用户怨气的出口。当用户用得不顺手、用得不舒服，骂名绝大多数都指向界面，甚至因为界面太糟而牵连硬件一起挨骂。界面之所以"首当其冲"，是因为它处在用户与系统之间唯一的交界处——用户能感知到的软件，就是界面本身。

### 1.1 UI 不是美工

很多人把界面设计等同于"美工"，这是一个根本性的误解。在 Web 应用等场景里，美观确实占很大比重，但 UI 的本质偏技术而非艺术。一个值得追求的界面，首先要在功能与交互上正确、高效、不易出错，美观只是锦上添花。

什么样的人能成为好的界面设计者？需要兼具以下几类知识背景：

- **人机交互（HCI）的基本技术**：理解交互的原理与手段；
- **用户心理学**：知道用户如何感知、记忆、形成习惯、在何时犯错；
- **理解程序员的世界与系统架构**：能看懂程序如何组织，知道哪些限制是真实的、哪些限制只是实现偷懒；
- **一点美工与审美**：不需要亲自会画，但要有品味、会挑元素，借助现成工具也能拼出清爽漂亮的界面。

实际选型上，与其找一个纯美工，再配一个纯技术，不如找一个"懂技术又有美感"的人。技术素养保证他不至于因为自己的实现方便而强迫用户多点一步，审美素养保证结果不丑。

### 1.2 用户习惯是一种下意识的本能

界面设计有一条底层事实必须时刻记住：用户在用你的系统之前，早就在用别的方式工作——纸质的表格、人工的流程、旧的系统。人的操作习惯一旦形成，就变成下意识动作。只要稍微疲劳、稍微走神，强大的旧习惯就会回来。这意味着界面设计不是"教用户新习惯"，而是"尽量贴合他已经有的习惯"，从而降低出错概率。

## 二、三大黄金设计原则（The Golden Rules）

界面设计有三条放之四海皆准的黄金法则，所有具体机制都从它们派生。

| 原则 | 英文 | 核心意图 |
| --- | --- | --- |
| 把用户置于掌控之中 | Place the user in control | 用户能按意图操作，且不会被设计坑去犯错 |
| 降低用户的记忆负担 | Reduce the user's memory load | 用户不必死记路径与状态，系统替他记 |
| 保持界面一致 | Make the interface consistent | 操作方式、视觉风格遵循习惯与整体统一 |

### 2.1 原则一：把用户置于掌控之中（Place the user in control）

这一原则的字面翻译虽是"把用户牢牢掌握在控制中"，但其准确含义是：用户所点的东西，应当与他想点的东西一致；你不想让他搞乱的东西，就根本不给他搞乱的机会。它包含若干互相支撑的机制。

**（1）定义交互模式，不强迫用户做无意义或不期望的动作**

要点是两句话：*不要给他犯错误的机会*，以及*用最少的步骤做到他想做的事*。

- 设计交互时，不能因为程序实现的原因，逼用户多走一步无意义的操作。例如"只能让你在这多点一下才能进下一页"——偶尔一次用户可忍，天天让用户多点一次，他会爆发，因为那明显是软件的愚蠢。
- 更要防止"不小心点一下就闯大祸"。如果一个普通用户随手一点就把整个系统弄崩溃，错不在用户，而在软件工程师、在 UI 设计。好的设计应当从交互上消灭这类灾难路径。

**（2）提供灵活的交互方式（Provide for flexible interaction）**

这一条与第一点互补：既要防止用户犯错、不给他多余动作，又不能走到另一个极端——剥夺他习惯的输入方式。

一个真实的反面教材：一款外汇交易软件升级后，原本用键盘大键盘输入交易数字，升级后大键盘失效，屏幕上只弹出一个仅含数字和小数点的小键盘。原因在于旧版客户经常往输入框里乱敲无关字符，设计者一怒之下封死了键盘。结果是老用户（如长辈）完全不会用了——因为他们习惯敲键盘，新界面却逼他用鼠标点小键盘。灵活交互意味着应当保留多种可行输入途径，而不是用"防错"的名义砍掉用户已有的能力。

**（3）建立有意义的默认值（Establish meaningful defaults）**

同样是那款外汇软件，账号选择用了下拉框，但默认值竟然是空。问题在于：如果有多个账号，本可以统计使用频次、把最常用的账号设为默认；如果只有一个人用，账号就应当自动成为默认。这样至少省掉用户一次操作。默认值空着，等于把本可代劳的事推回给用户，是细节上的懒政。

**（4）视觉布局基于真实世界隐喻（The visual layout should be based on a real-world metaphor）**

如果你的软件替代了原本用纸、用人完成的流程，电子界面应当尽量复刻原有实物。比如"无纸办公"把纸质表格变成电子表格，电子表格的字段位置、顺序最好和原纸张表格一致。

这条原则的分量，由一起真实事故可见：某人去银行存钱，事后查账发现多出一笔天文数字般的金额，他老实上报，银行一查，是柜员把身份证号码敲进了"存款金额"栏。可能的原因就是——电子表单里"存款金额"框的位置，被放在了柜员习惯填身份证号码的地方。工作时全神贯注不会错，但只要一疲劳、一走神，强大的旧习惯就回来，字段错位便酿成差错。所以做电子流程前，应先调查用户在没有你系统之前怎么工作，让新流程最大限度贴合其手工习惯。

**（5）渐进式披露信息（Disclose information in a progressive fashion）**

不要把所有细节"唰"一下全摊在一个界面上吓晕用户，而应分层展开。真正做到位很有学问：一个界面一次展示多少条目（宽度）、每个菜单下拉多深（深度），都是需要权衡的设计参数。信息要随用户深入操作而逐步呈现。

### 2.2 原则二：降低用户的记忆负担（Reduce the user's memory load）

用户不应被迫记住"我刚才访问了哪里""我现在在哪""下一步去哪"。支撑这一原则的机制包括：

- **导航条**：做得充分有导航性，让用户随时知道自己身处何处、能去哪里；
- **帮助文档/提示**：在他想用某功能时，提示他可以在哪里用；
- **撤销（Undo）**：虽常被归入"宽容用户、允许后悔"，本质上也是系统在替用户记住上一步状态，便于回退。

核心思路是：凡是可以由系统代记的上下文，就不要压给用户的大脑。

### 2.3 原则三：保持界面一致（Make the interface consistent）

"一致"至少有三层含义，由内到外。

**（1）软件内部整体风格一致**

一个软件可能由多个小组分头开发，但最终成品不能是七拼八凑。一个验收中的反面案例：几个小组的模块始终合不到一起，便做了一个"假的界面外壳"应付——前台统一壳子，点按钮就拉起某个组的 .exe，打开该组自己的界面；点另一个按钮又起另一组的界面，彼此风格、布局毫无关联。更致命的是后台数据库没合并：在 A 组界面录入的数据，用 B 组界面查不出来。这种"壳一致、里不一致"的东西，在正经软件里绝不允许。无论多少人协作，软件必须呈现统一的整体形象。

**（2）让当前任务处于有意义的情境中（Allow the user to put the current task into a meaningful context）**

用户在 Windows 下常同时开很多窗口：上网、聊 QQ、写论文、做 PPT、开 Word、开 Excel。要在数十个窗口里快速找回目标，依赖底部任务栏——每开一个窗口就有一个图标。图标设计本身有学问：靠视觉即可辨识归属。例如 Word 图标通常是蓝色、PowerPoint 是橘红色、Excel 是绿色，用户扫一眼就能定位要找的窗口。一致性在这里表现为"随时可定位、可回到情境"。

**（3）跨产品家族保持一致（Maintain consistency across a family of applications）**

不止单个软件内部要一致，一个厂商的一系列产品（产品家族）风格也要一致。为何要强调这一点？不一致又怎样？这是本讲的讨论题，见下文。

## 三、设计评估与一致性的价值讨论

关于"跨产品家族一致性"，可分解为三项思考任务：

1. 举出一个**具体的产品系列**例子；
2. 分析它的哪些特征体现了 consistency（一致的风格、一致的操作逻辑、一致的视觉语言）；
3. 说明这么做有什么**好处**、为什么需要这条原则。

论证方向（基于前述原理推导）：家族一致降低用户的学习迁移成本——在一个产品里学会的操作，到同家族另一产品可直接复用；统一的视觉与交互语言建立品牌识别与信任感；一致的报错、一致的导引减少跨产品时的认知错乱。反之，家族内风格割裂，等于让用户每换一个产品都从零学起，既增加出错率，也稀释品牌。

界面设计的"评估"并不只是上线后看，而应贯穿设计：是否把用户置于掌控中？是否减少了记忆负担？是否从内到外保持一致？可用前文那些机制逐条对照，像"外汇软件封死键盘""银行字段错位""假界面外壳"这类事故，都是违背原则后付出的真实代价。

## 四、收尾警示：你以为的意思，未必是客户的意思

用一则漫画收束，它点出一个常被忽视的界面风险：用户对你写的词，理解可能和你完全不同。

漫画里有人打电话："My computer doesn't work. The hard drive crashed. What do I do?"（电脑坏了，硬盘崩了，怎么办？）对方问："Did you back up?" 英语里 back up 原意是"往后退、撤"（像要爆炸时喊 Back up），于是电话那头"哗"地一退："要炸了吗？"

back up 在软件语境是"备份"，但用户的日常词汇里它是"后退/撤离"。这则笑话的严肃教训是：你在界面上写的任何你"以为"是某意思的词，必须确认客户的理解和你是同一回事。词汇歧义、隐喻错位，都会让精心设计的界面在对的地点、对的按钮上，触发完全错的理解。

## 五、随堂自测

**题 1：** 某软件为防用户误填，在升级后取消了键盘输入，只允许鼠标点屏幕小键盘。这违反了哪条黄金原则下的哪一机制？为什么？

> **解析与答案：** 违反了"把用户置于掌控之中（Place the user in control）"下的"提供灵活的交互方式（Provide for flexible interaction）"。该机制要求保留多种可行的输入途径，与第一点"不强迫用户做不期望的动作"互补；用"防错"为名砍掉用户既有的键盘输入能力，走向了过度限制，剥夺了习惯性操作，反而让用户（尤其老用户）无法正常使用。依据见 2.1 节机制（2）。

**题 2：** 银行柜员把身份证号码敲进"存款金额"栏，源于电子表单字段位置与原纸质单据不同。这主要说明哪条设计原则没被遵守？应如何避免？

> **解析与答案：** 违反了"视觉布局基于真实世界隐喻（real-world metaphor）"——电子流程应最大限度贴合用户此前手工作业/纸质流程的习惯与字段位置。避免方法：设计前先调查用户在没有系统前如何工作，使电子表单的字段布局、顺序与原实物一致，从而在其疲劳走神时旧习惯仍指向正确字段。依据见 2.1 节机制（4）。

**题 3：** 一个软件由三个小组分头开发，验收时用一个统一外壳包住，点按钮分别拉起各组自己的 .exe 与界面，且后台数据库未合并。这种做法违背了"一致性"的哪一层含义？危害性是什么？

> **解析与答案：** 违背了"软件内部整体风格一致"这一层（Make the interface consistent 的第一层含义）。它是"假界面外壳"：视觉上统一、实则各组界面互不相干，且后台数据未合并——在 A 组界面录入的数据无法用 B 组界面查出。危害是数据割裂、体验破碎、无法作为统一产品交付。依据见 2.3 节（1）。
