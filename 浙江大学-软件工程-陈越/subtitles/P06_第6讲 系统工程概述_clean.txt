然后 sorting 的这一块呢又分成一个是读 sensor 的，一个是控制手臂的，控制分转发器的。就是，有专门描述硬件的这么一个结构、这么一个图，来告诉你我硬件它是几块组成的。**[03:12 - 04:24] 活动图（Activity Diagram）**然后还有一个图呢叫 Activity Diagram。

是描述动作的，活动。那图的特点，就是规矩，一个呢，开始点是一个黑疙瘩表示，黑的圆饼，这是开始；，圆饼外头套一个圆圈，表示结束。所有的每一个动作都写在这么一个框里面。然后用箭头表示它发生的顺序。粗的黑线表示时间线。在时间点上，这两件事情同时开始。就它走到了时间点，然后在时间点上这两件事情同时开始。那呢表示一个“或”的关系：或者 barcode 是对的，或者是读错了（invalid），会有两种情况。

然后等等怎么样。那么这两件事情，这三件事情等齐了在这一个点，然后开始执行下一步。这就是 Activity Diagram 大概是这么样的一个规矩，它来描述你系统动态执行的过程。**[04:24 - 04:46] 类图（Class Diagram）回顾**呢，大家在学 C++ 吧？在学吗？（学生答：学过了）学过了？

OK，所以那你应该很容易理解，就是描述一个 class。就描述一个 class，然后基本上它就三块：上面是名字，然后中间是 attributes，下面是它的 methods，或者叫 operations。后来用得着就好了。**[04:46 - 07:16] 用例图（Use Case Diagram）**那还有一个呢，就是 use case。

Use case 在很久以前，它叫 user scenarios。User scenarios 翻译过来叫“用户脚本”。用户脚本是什么？就是像你导演写电影剧本一样，就是每一个分镜头是怎么走的。你用户从一开始启动，然后进入一个什么样的情景，我就开始用软件；然后他第一步做什么，第二步做什么，他是怎么用的一个流程。

当然，脚本可以很复杂。因为你中间是有一些判断的，它可能有分支，行动有分支。那你搞清楚它的所有的分支，你都要描述清楚的话，那它有好多脚本，它不是一个脚本能写完的，对吧？它执行到这一步的时候，我可以有三个选项，那于是你对应每一个选项你都要一个、下面一个脚本要写下去。所以呢，以前都是用文字描述的。那大家都知道大多数人来说，看一大篇的文字是很痛苦的，然后也不会很认真的看。

所以呢，它后面把它简化一下，做成一个图形的方式。那大家看图呢会稍微容易一点，理解起来容易一点。那例子呢，还是刚才流水线的例子。这是非常简单的、第一层次的 use case diagram。那他就说我 operator，系统的 operator 进来以后，他可以直接在面板上做哪几件事情。对着，就是他有这么几件事情是直接做的。

然后你要更细化地分析和设计阶段的时候，图可以有好几层。就比如说 request barcode，然后它后面还需要调用哪些功能去完成功能；然后它后面调用的功能还要调用其他的动能？它就可以一层地深下去。但是呢，基本上它是给了你一个，你如果用 UML 的话，它给了你这么一个工具，你可以用图——半图形、半文字的形式，把它的几个、就整个执行的流程给它画清楚，不是像以前完全用文字去描述。

那呢就是一个 use case diagram。**[07:16 - 07:58] 下周课程预告与 TA 答疑提醒**这些工具都是我们后面要用到的。下一次课开始，后面用两周的时间真的开始教大家——还没有到、远没有到编码阶段，就你怎么收集整理需求。那我很偏兴听到昨天你们的 TA 哥跟我说，他已经收到不少骚扰了，哈。
