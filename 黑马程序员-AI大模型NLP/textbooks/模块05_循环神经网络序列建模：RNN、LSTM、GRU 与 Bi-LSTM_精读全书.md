## Day03-03.RNN模型简介(了解)

### 从这一讲开始，进入 NLP 的核心章节

接下来要讲的是 RNN 及其变体，也就是 LSTM 和 GRU。从这个章节开始，才算真正进入 NLP 的核心部分：这三个模型的原理和应用，都是本阶段的重中之重，需要投入比前面更多的精力。

学完这三个模型，我们做一个全球人名分类器的案例；紧接着上整个阶段最重要的内容——注意力机制，这个一定要多花心思；注意力机制讲完，再做 sequence-to-sequence 的英译法案例，这一章就暂告一段落。再往下一章，就该讲 Transformer 了。所以这一章你可以理解为给下一章做铺垫的。

这一讲先看第一部分：RNN 模型简介。概念、作用、分类这些，了解即可；**结构特点需要掌握**。

### RNN 的三层结构与循环的含义

RNN 全称 Recurrent Neural Network，中文叫循环神经网络（recurrent neural network，RNN）。它在深度学习部分已经简单介绍过，当时梳理的三层是：**词嵌入层（embedding layer）、循环网络层（recurrent layer）、输出层**。

三层各干什么，先复习一遍。

第一个问题：词嵌入层的作用是什么？把文本转成词向量。说白了就是把文本转成数值——大模型底层只认识数字，它不认识你的语言。

第二个问题：循环网络层干什么？就是 RNN 里面那一层，它是**基于上一时刻的隐藏状态和本次的输入，得到本次的隐藏状态以及本次的输出**。还记得当时让大家背的那 12 个参数吗？一共 12 个：传出两个、返回两个，而每一次传参都带三个参数，$3 \times 4 = 12$。

> **提示**：想翻旧账的话，这些内容都在深度学习随堂资料 day07 的图片里。当时那张图和我们这一讲画的 RNN 图解是同一件事，12 个参数的图就在里面。

那么，既然词嵌入层已经把文本变成了数值，为什么下一层叫**循环**网络层？循环体现在哪儿？

> **定义**：循环网络层的「循环」，指的是这一层实质上只有一个神经元，而它**上一次的输出会作为下一次的输入**，如此反复执行。

就一个神经元，反复地做同一件事，所以叫循环。这也是整个 RNN 的立身之本。

### 时间步展开：h 与 y 的传递链

下面把 RNN 沿时间步展开，看成一个平铺的网络结构。

```text
   h0 --> [ 循环单元 ] --> h1 --> [ 循环单元 ] --> h2 --> [ 循环单元 ] --> h3
          ^        |               ^        |               ^        |
          |        v               |        v               |        v
         x1       y1              x2       y2              x3       y3
```

上图是同一套参数在时间上反复复用：每个时间步都吃一份新的输入和一个上一时刻的隐藏状态，吐出新的隐藏状态和该步的输出。

> **易错点**：图上横着画了三个、五个方块，但这里**不是三个、五个神经元，而是一个神经元在重复执行**。

对着这张图把数据流走一遍。第一次输入记作 $x_1$；在它之前还有一个 $h_0$，$h_0$ 是**上一时刻的隐藏状态**，用来记录历史信息。基于 $h_0$ 和 $x_1$ 得到 $h_1$；如果需要输出，再基于 $h_1$ 得到 $y_1$。下一步拿 $y_1$ 作为输入，结合 $h_1$ 得到 $h_2$；基于 $h_2$ 得到 $y_2$。再往下，$y_2$ 和 $h_2$ 得到 $h_3$，$h_3$ 再得到 $y_3$，依次往后走。

把中间的算式摊开就是：

$$
h_t = \sigma(W_{hh}h_{t-1} + W_{xh}x_t + b_h)
$$

$$
y_t = \text{softmax}(W_{hy}h_t + b_y)
$$

也就是说，$h_1$ 由「$x_1$ 加权求和、$h_0$ 加权求和，再过激活函数」得到；$h_2$ 同样由 $y_1$ 与 $h_1$ 加权求和后过激活函数得到，$y_2$ 再从 $h_2$ 来。**循环就是这么解读的**。

于是 RNN 网络结构的特点可以收成这么几条：由输入层、隐藏层、输出层组成——说得更确切些，输入层之后是隐藏层，隐藏层往下再分成两部分，一部分是词嵌入层，另一部分是循环网络层，最后给出输出层；并且**上一时间步的输出作为下一时间步的输入**，也就是上一步的 $y_1$ 成为这一步的输入。

### 每个时间步的两个输入与两个输出

把 RNN 的参数账算清楚，只要数每个时间步有几个输入、几个输出。

每个时间步的输入有两个：

| 输入 | 说明 |
| --- | --- |
| 数据端的输入 | 当前这一步的输入数据，如 $x_1$ |
| 隐藏层的输入 | 上一时刻的隐藏状态，如 $h_0$ |

每个时间步的输出也有两个：

| 输出 | 说明 |
| --- | --- |
| 数据端的输出 | 当前这一步的数据输出，如 $y_1$ |
| 隐藏层的输出 | 当前这一步的隐藏状态，如 $h_1$ |

每个时间步的两进两出各自都带三个参数，四个 $3$ 加起来正好是 $3 \times 4 = 12$ 个参数——这就是前面反复提到的 12 个参数的来历，一会儿真正调用模型时传的就是它们。

### RNN 的作用与序列数据

RNN 的作用，第一条是**能够连续性地输入序列数据**：因为它是循环的，一个一个往里扔就行了。

第二条是**提取特征**：人类的语言、语音特别适合用 RNN 处理。原因在于语言和语音都是**序列数据**——下一个字对上一个字有依赖，你必须从前往后一个一个传、一个一个解析，所以它天然适合用 RNN 来做。

> **定义**：序列数据指后面的数据对前面的数据有依赖，这样的数据才叫序列。

RNN 模型广泛用于 NLP 的各种领域和任务：文本分类（判断这篇文章属于体育类、财经类还是新闻类）、情感分析（好评还是差评）、意图识别等等。

#### 意图识别：判断用户到底想干什么

意图识别后面会专门讲案例，因为面试会问。它要解决的问题是：用户进来了，他要做什么。

拿招商银行的 App 举例。打开之后里面有个「小招」助手，你点开小招助手，还没做任何输入，它就会问「小主您是要干嘛呀」——存钱、理财、买基金，上面摆着一排选项。它要在你开口之前判断你可能要做什么，然后基于这个判断给出相应决断，这就是意图识别。

我们后面做案例也要做这件事：未来用户来输问题查数据时，我们要判断用户输的是专业领域的问题还是通用知识的问题，从而决定走不同的模型。

#### 一个例子走完整条链路

以「what time is it」这句话为例。第一步先分词；然后注意，**RNN 是一个时间步输入一个词，每次只收一个单词**——这正是它被称为循环神经网络的原因。

```text
what   time   is   it
  |      |     |    |
  v      v     v    v
 h0 ->  h1 -> h2 -> h3 -> h4 -> h5
  |      |     |    |     |     |
  v      v     v    v     v     v
 O1     O2    O3   O4    O5
(time)  (is)  (it)  ...
```

上图是这句话的处理时序：每个词依次喂进去，隐藏状态一路往右传，右上角写出该步应有的输出。

对着图看一遍：第二步是把 `what` 输给 RNN 产生 $O_1$，下一次 $O_1$ 就作为本次的输入；同时最开始还有一个 $h_0$，$h_1$ 是基于 `what` 和 $h_0$ 算出来的，基于 $h_1$ 又能算出 $O_1$。按这个节奏，`time` 扔进去，结合 $h_1$ 算出 $h_2$，这一步的 $O_2$ 位置应该是 `is`；再往下 `is` 进去算出 $h_3$，对应位置是 `it`，依此类推。

这条链的关键在于**隐藏状态的记忆**：

> **结论**：神经元循环的次数越靠后，它记住的状态就越多——之前发生过的事情会被一路记下来。

课上的类比是看电视剧。假设一共 40 集，你看到第二集，脑子里只有第一集的剧情，因为第二集还没看完；等你看到第三集，脑子里就有了第一集和第二集的剧情，再结合第三集继续往下；看到第四集时，前三集的剧情你都已经知道了。RNN 的隐藏状态就是这个「越往后知道的越多」的过程。

重复到所有词处理完，最后拿到的是最终隐藏层输出的 $O_5$，它用来解析用户意图。如果意图识别是 18 个分类，18 分类属于二分类还是多分类？多分类。那该用哪个损失函数？**Softmax**：它把输出映射成 18 个分类各自的概率，取概率最高的那一个作为最终结果。$O_5$ 经过 Softmax 转成概率，就能判断用户到底属于 18 个分类中的哪一个。这些任务用 RNN 都能做，也正是循环网络存在的意义。

### 两条必须记住的结论

关于 RNN 的简单介绍，收成两句话：

> **结论**：第一，RNN 主要处理序列数据；第二，RNN 由输入层、隐藏层、输出层组成，其中隐藏层主要分为词嵌入层和循环网络层。

第二句特别值得停一下。单看输入、隐藏、输出这三层，你会发现它像极了人工神经网络（artificial neural network，ANN）。而隐藏层里放什么，决定了它变成谁：如果里面是一个卷积、一个池化，那就是 CNN；如果里面是一个词嵌入层、一个循环网络层，那就是 RNN。所以不管是 C 还是 R，**它们的底层都是依赖 ANN 的**——这一层关系理清了，前面深度学习的内容就和这里接上了。

## Day03-04.RNN的分类介绍(掌握)
> 对应分集：P39 | 原始标题：《Day03-04.RNN的分类介绍(掌握)》

### 这一讲要背下来的两个角度

RNN 模型的分类主要有两个角度：**按输入和输出的角度划分**，以及**按内部结构划分**。这一讲的内容是要记到本子上的，被问到「说一下 RNN 的分类」时，必须把这两个方向都说清楚。

先说清楚为什么强调这一点。如果你上来只答「N vs N、N vs 1、1 vs N、N vs M」，那这个回答是没有意义的——那只是第一个角度底下的一种分法，漏掉了整个内部结构那一半。

### 输入输出角度：四种形态

输入输出角度要回答的问题很朴素：**输入几个，输出几个？**

#### N vs N：输入 N 个，输出 N 个

你给我五个，我给你五个；你给我六个，我给你六个。输入和输出个数对齐。这种形态适用于**写诗、写对联这类固定场景的表达**。

为什么是这两件事？因为诗本身就是对仗工整的。四言、七言绝句，字数格律都定死了：「孤山寺北贾亭西，水面初平云脚低」，上下句字数一致；「床前明月光，疑是地上霜。举头望明月，低头思故乡」，也是整齐的句式。输入多长、输出就多长，正好对上 N vs N。

幻灯片上对它的描述是：RNN 的基础形态，生成的输入和输出等长，例如生成等长度的诗句。

#### N vs 1：输入 N 个，输出 1 个

我给你一堆的句子，你最后告诉我它是好评还是差评——这就是**情感分类**。换成意图识别的说法：我用了一堆字去描述我的问题，你最后识别出「原来你要做理财」，输入是一整句话、输出是一个标签，同样是 N vs 1。

幻灯片上的描述是：输入的是一个序列、也就是一句话，输出是一个单独的值，适用于文本分类——给你一堆文本，最后告诉我它属于什么类，是经济类、体育类还是新闻类文章，意图识别也可以用它来做。

#### vs N：输入 1 个，输出 N 个

这就是**看图说话**：我给你一张图片，你解析解析这张图里有哪些内容，基于这张图帮我提取出更多文字信息。给你一个，你生成一堆。

#### N vs M：输入 N 个，输出 M 个

翻译、语音转换、文本生成、摘要都属于这一类。**N 个进、M 个出，而且 M 和 N 不相等**——这是它和 N vs N 最本质的区别。

课上举的例子很能说明问题。有个英语老师在讲课时翻了一句很文艺的话：「君之所向，吾意所往。」对应到英文，她给出的翻译是：

```text
You go, I go.
```

中文这边是八个字，英文那边只有四个单词，个数完全不对齐。这正是 N vs M 的典型形态。

那么四种形态里，**哪一种玩得最多？**答案是 N vs M。之前说过我们会接触至少三个 800 行以上的代码案例，其中就包括后面要做的 sequence-to-sequence 英译法案例，那个案例就是 N vs M。英译法案例是必须掌握的，所以 N vs M 很重要。

#### 编码器与解码器：N vs M 的结构与那个 C

N vs M 的展开图，现在先建立一个整体印象就行，细节等英译法案例再细讲。

```text
   编码器（左半程）                解码器（右半程）

   h0     h1     h2 ...           s0     s1     s2 ...
   ^      ^      ^                ^      ^      ^
   |      |      |                |      |      |
  x1     x2     x3              中间语义 C 传过来
```

上图是经典编码器—解码器（encoder-decoder）结构：左边一串隐藏状态负责把输入序列读成一份语义表示，右边一串负责把它展开成目标序列，中间那份表示就是 $C$。

- 左边这一堆动作，可以理解为我们所说的**编码器**；
- 右边这一堆，可以理解为**解码器**；
- 中间那个 $C$ 叫**中间语义编码张量 $C$**，也叫中间语义张量。

再往这个结构上延伸、延伸，它就成了 Transformer。现在看不懂 $C$ 是什么意思完全正常，英译法案例里会详细讲。

顺便把学习节奏说明白：我们先把 RNN、LSTM、GRU 的原理和代码都学了，然后做全球人名分类案例，之后讲注意力机制，讲完再做英译法案例——这一章就全部结束，接着开 Transformer。这个顺序是安排好的，英译法案例会放慢节奏讲，因为那个案例确实不好掌握。

### 内部结构角度：五种模型

第二个大类不按输入输出分了，按**内部结构**分。这是本讲要着重聊的部分。

#### 传统 RNN

传统 RNN 就是我们前面说的那一套：由输入层、隐藏层、输出层组成，其中隐藏层里一个是**词嵌入层**，一个是**循环网络层**。

#### LSTM：从层变成门

LSTM 直接告诉你，它就不是上面那个意思了。它是**门**：遗忘门、输入门、细胞状态、输出门。

> **提示**：这一串名词第一次听全是新词，一个都不认识，这很正常。你现在只需要知道「LSTM 内部由这些门和细胞状态组成」，每个门具体干什么，等原理部分再展开。

#### Bi-LSTM 与 Bi-GRU：双向的意思

`Bi-` 这个前缀就是 binary、那个「二」的意思。之前讲 N-gram 时，2-gram 就叫 Bi-gram，所以 `Bi-` 在这里表示**双向**：`Bi-LSTM` 就是双向 LSTM，`Bi-GRU` 就是双向 GRU。

双向怎么做的？一句话从前向后做一遍，再从后往前做一遍，然后把两次结果合并。

拿「我爱你」来想：先拿「我爱你」做一遍 LSTM，再拿「你爱我」做一遍 LSTM，把两个结果合并，就是最终结果。

为什么要双向？因为不管是从前往后还是从后往前，都能更好地理解语义——两个方向的信息互为补充。但它带来的弊端是**运算量会增加**，这一点是必然的。也正因为这样，实际开发中除非必要，一般不会选双向的那两个。

#### GRU：用更少的门做更多的事

GRU 的思路是：LSTM 门太多了。所以在保证效率的前提下，尽量减少门的操作，只留两个——**重置门**和**更新门**，就完事了。

把这句话说得更准确一点：GRU 是基于 LSTM 做的一个优化，核心意思是**用最少的资源做更多的事情**。

于是内部结构角度的五个模型可以并列摆开：

| 模型 | 内部结构要点 |
| --- | --- |
| 传统 RNN | 输入层、隐藏层（词嵌入层 + 循环网络层）、输出层 |
| LSTM | 遗忘门、输入门、细胞状态、输出门 |
| GRU | 重置门、更新门 |
| Bi-LSTM | 双向 LSTM：正向一遍、反向一遍，结果合并 |
| Bi-GRU | 双向 GRU：正向一遍、反向一遍，结果合并 |

> **结论**：未来实际开发中用得最多的是 LSTM。虽然摆出来是五个模型，但双向的除非必要一般不选，剩下三个里，LSTM 相对用得更多。

为什么是 LSTM，原理部分会解释。

### 从输入输出角度延伸出去的三个场景

把输入输出这条线再走一遍，顺手把每个场景落到具体业务上。

**N vs N**：输入 N 个、输出 N 个，用在写诗这种对仗工整的场合，生成等长度的诗句。

**N vs 1**：输入 N 个，最后只要一个结果，用来做情感分析、意图识别。输入是序列，输出是单独的值，适用于文本分类——判断这段文本属于经济类、体育类还是新闻类文章，意图识别也走这条路。

**1 vs N**：看图说话，把图片生成文字，给你一张图，你基于它提取出更多文字信息。

**N vs M**：输入 N 个、输出 M 个。中文八个字对英文四个词，「君之所向，吾意所往」对 `You go, I go`，个数不必相等。翻译就是它的主战场，后面那个 800 行以上的英译法案例讲的就是这个操作。

### 本讲提到的题目

这一讲在讲完分类后留了一道单项选择题：**循环神经网络为什么要叫循环？**

- A. 因为 RNN 循环网络也属于深度网络
- B. 因为它有输入、输出以及隐藏
- C. 因为它可以支持文本序列
- D. 上一个的输出作为下一个的输入

**答案：D。**

**解析**：循环的含义落在数据流上——网络里上一次的输出会作为下一次的输入，同一个单元反复执行，所以叫循环。A 项说的「属于深度网络」是所有深层网络的共性，不构成循环的理由；B 项的三层结构描述的是组成，ANN 也有这三层；C 项说它支持文本序列，那是它适合处理序列数据的能力表现，而不是「循环」这个名字的由来。只有 D 项直接对应循环网络层的运行方式。

## Day03-05.RNN的模型结构(理解)
> 对应分集：P40 | 原始标题：《Day03-05.RNN的模型结构(理解)》

接下来要讲的是传统 RNN（Recurrent Neural Network，循环神经网络）的内部结构、它的 API 参数，还有它的优缺点。这一节的要求说得很清楚：能说出 RNN 的内部结构，能掌握它的 API 参数，能了解它的优缺点，就够了。

我先把话说在前面——这一节的图会很多，而且今天要画的图不止这一张，所以你得花点心思跟着我的思路走，别走神。图一旦看懂了，后面写代码就是照着图把数填进去。

### RNN 内部结构：两个输入、两个输出

先看 RNN 的内部结构长什么样。

这张图上花花绿绿的一堆——黄色的、粉色的、各种箭头和圆点——第一次看确实容易懵。但先别管颜色，我们把图上最下面那段文字介绍读一遍：**每个时间步有两个输入，这两个输入会融合到一起，经过一系列运算，再得到输出**。这不就是我们之前一直在说的那个动作吗？

具体到符号：

- $x_t$ 代表**本次的输入**；
- $h_{t-1}$ 代表**上一时刻的隐藏状态**；

这两个输入进去，得到两样东西：

- $h_t$，**本次的隐藏状态**；
- 以及本次的输出。

> **定义**：RNN 的一个时间步，本质就是一个"二进二出"的运算单元——拿本时刻的输入 $x_t$ 和上一时刻的隐藏状态 $h_{t-1}$，算出本时刻的隐藏状态 $h_t$ 和本时刻的输出。

这里肯定有人要举手：本次的隐藏状态有了，那本次的输出呢？图上怎么没画出来？

别急，你回想一下我们前面讲过的分类：RNN 按照输入输出划分，是有 **N vs 1** 这一种的——输入 N 个，只输出一个。那我只要最后那一个 $y$ 是不是就够了？所以图上没有把每个时间步的输出都画出来，这不用纠结。

### 图例解读：五种符号各代表什么

把图放大之后，上面的符号得逐个认。一共五类，我一个个说。

#### Neural Network Layer：神经网络层

`Neural Network Layer`。`Neural Network` 就是神经网络，`Layer` 就是层，所以这哥们儿叫**神经网络层**。图上它用黄色的圆角块表示。

#### Pointwise Operation：逐点运算

`Pointwise Operation`。`Point` 是点，`wise` 是逐个的"逐"，合起来就是**逐点运算**。

那什么叫逐点运算？简单来讲，你就把它理解成点乘或者矩阵乘法，就是这种运算。

#### Vector Transfer：向量传输

`Vector Transfer`。`Vector` 是向量，`Transfer` 是传输，所以它是**向量传输**，管的是数据从一个位置流到另一个位置。

#### 连接与复制：合并和分裂

剩下两个动作符号是一对：

- 那个把两路数据并到一起的符号，叫**连接**，你可以理解为合并，把两个合成一个，二合一；
- `Copy` 就是**复制**，复制相当于一变二，一份数据分给两个地方用。

先把这张图的骨架画出来，你就知道这些符号各自待在什么位置了：

```text
                       输出序列 y_1        y_2              y_3
                          ^                ^                ^
                          |                |                |
         +--------+   +--------+       +--------+       +--------+
   x_1 ->| 连接   |-->| tanh   |--+--->| tanh   |--+--->| tanh   |--> ...
         +--------+   +--------+  |    +--------+  |    +--------+
              ^           ^       |        ^       |        ^
              |           |       |        |       |        |
             x_1        h_0 ------+       h_1 -----+       h_2
                     (Copy 分给下一时间步)

  图例：
    连接        两路输入合成一路（合并）
    tanh        激活函数所在的神经网络层
    箭头         向量传输（Vector Transfer）
    圆点/星号    逐点运算（Pointwise Operation）
    Copy         一路复制成两路
```

读图说明：每一个时间步里，本时刻输入 $x_t$ 与上一时刻隐藏状态 $h_{t-1}$ 先在"连接"处合并成一路向量，送进 tanh 神经网络层做一次运算，出来的就是本时刻的隐藏状态 $h_t$；$h_t$ 一方面向上成为本时刻的输出，另一方面被 Copy 复制一份，传给下一个时间步。

### 图上各变量的角色

把符号认全了，再回头认变量，一个一个对号入座。

$x_t$ 不用说，充当的是**本次的输入**。

$h_{t-1}$ 也不用说，它充当的是**上一时间步的隐藏状态**，你也可以叫上一时刻的隐藏状态，随你怎么叫，自己能看明白就行。

$h_t$ 呢？$h_t$ 就是**本次的隐藏状态**。

画面上中间那个 tanh，颜色是黄色的，黄色在我们的图例里代表神经网络层——所以它就是一个**激活函数神经网络层**。它的计算公式前面已经看过了，我们下面单独说它。

### 激活函数 tanh 与两个公式的差别

先讲流程。RNN 内部结构的运算顺序是这样的：上一时刻的隐藏状态 $h_{t-1}$ 和本次的输入 $x_t$，先经过一次**加权求和**，把结果送进 **tanh 激活函数**处理一下，然后继续往下传递就可以了。

> **结论**：RNN 内部结构 = 先加权求和，再做激活函数，增加非线性元素。

那 tanh 在这里的作用是什么？往上翻一页看激活函数的作用——**把一个值映射成一个非线性的结果**。所以激活函数的作用就是用来给模型增加非线性部分的。这一点记牢，后面讲 LSTM、GRU 的时候，门控里面用的还是这套东西。

好，接下来是个更容易被问到的点：工业界到底是怎么做的？

#### 学术界论文里的写法

如果是学术界的论文，RNN 的论文里是这么写的：$x_t$ 和 $h_{t-1}$ **共用一个权重矩阵** $W$。

$$h_t = \tanh\left(W \cdot [h_{t-1},\ x_t]\right)$$

也就是先把 $h_{t-1}$ 和 $x_t$ 拼成一个长向量，再拿同一个 $W$ 去乘这一个拼接后的向量，最后过 tanh。一次乘法把两路输入一起算完，所以权重矩阵只有一个。

#### 工业界框架底层的写法

但是在工业界，比如说 PyTorch 这种框架，它底层实现的时候是**各算各的**：你的输入 $x_t$ 有它自己的权重 $W_{xh}$，你的历史状态 $h_{t-1}$ 也有历史状态的权重 $W_{hh}$。

$$h_t = \tanh\left(W_{xh} x_t + W_{hh} h_{t-1} + b\right)$$

先把两路分开做加权求和，两个结果相加，外边再套一个激活函数。

这两种方式本质上是一样的，都是"先加权求和，外面加一个激活函数"，一模一样。你要非说区别，那还真有一个——**运算量的不同**。哪一个运算量更大？是 PyTorch 这种写法更大一些。

有人不服："你说是什么就是什么，我不信。"行，我让你心服口服。

打开 PyCharm，随便写一行：

```python
import torch.nn as nn
```

这什么意思？这不就是导入神经网络嘛。你的 RNN 是哪个 API，还记得吗？是 `nn.RNN`。

不用传参，按住 `Ctrl` 别松手，鼠标左键点进去看源码，往上扒拉到最上面。看着，屏幕上是不是 `class RNN`？是不是 RNN 这个类？然后你把它的 `maths` 念一遍——它底层的数学公式就在那儿。你会发现源码里的公式和讲义下面那个公式是一样的：先算的是 $x_t$，也就是本次输入；再来的那项是 $h_{t-1}$，也就是上一时刻的隐藏状态。

> **结论**：工业界用的是"两个权重矩阵各自乘、再加起来"的写法，论文里写的是"拼起来共用一个权重矩阵"的写法。两者严格来讲没什么区别，非要说区别，就是 PyTorch 那套写法的运算量要多一些，仅此而已。

所以讲义上的公式和底层实现的公式，不能说谁对谁错，只不过**参数量的多与少是核心**——这种底层运算的参数量，比论文里那套要稍微多一些。

#### 参数形状怎么对得上

既然讲到了两套公式，顺手把矩阵的形状核对一遍，你才能真正看出"运算量多在哪"。

设输入维度（词向量维度）为 $d$、隐藏层维度为 $h$：

| 写法 | 权重参数 | 形状 | 参与乘法次数 |
| --- | --- | --- | --- |
| 论文写法 | $W$ | $(h,\ h+d)$ | 一次（向量长度 $h+d$） |
| PyTorch 写法 | $W_{xh}$ | $(h,\ d)$ | 一次（向量长度 $d$） |
| PyTorch 写法 | $W_{hh}$ | $(h,\ h)$ | 一次（向量长度 $h$） |

> **提示**：论文写法里那个 $(h,\ h+d)$ 的乘法，等价于把 $W_{hh}$ 与 $W_{xh}$ 并排成一个矩阵再乘一个拼接向量。分成两个矩阵之后，乘法的总元素数没有变少，但多了一路相加、多了一份偏置，框架还为此区分了两组参数，所以实际运算量与参数量都会略多一点。这就是"运算量更多"的来源。

### RNN 作为"层"该怎么调用

图上还有一个东西没写。把刚才的源码截图拉过来，把中间看不懂的那一堆删掉，只留一行：`class RNN`，`maths = ...`。这一行的意思就是——它是 **PyTorch 框架底层源码的计算公式**。

既然它是底层的计算公式，那就说明 `nn.RNN` 天生就替我们把刚说的那套加权求和 + 激活实现好了。所以我们不需要自己写那个 $\tanh$，直接拿它当**层**来用就行。

这一点从调用方式上能直接看出来。你要用 RNN，第一步是创建层对象：

```python
rnn = nn.RNN(输入维度, 隐藏层维度, 隐藏层层数)
```

这个 `rnn` 就是你创建出来的**层对象**；你后面调用的时候，用的就是这个对象，`rnn` 小括号里传参数。

那传什么参数？两个输入。把小写的 `rnn` 摆在这儿，把刚才图上的符号对号入座摆进去：

```text
   output ,  h_n  =  rnn (  x  ,  h_{t-1}  )
     |         |            |        |
     |         |            |        +-- 第二路输入：上一时间步的隐藏状态 h_{t-1}
     |         |            +----------- 第一路输入：本次的输入 x
     |         +------------------------ 第二路输出：本次的隐藏状态 h_t
     +---------------------------------- 第一路输出：本次的输出
```

读图说明：图上画的是数据流，落到代码里就是这一行调用；图上的两路输入（$x_t$ 与 $h_{t-1}$）对应括号里的两个实参，图上的两路输出（本次输出与本次隐藏状态）对应等号左边的两个返回值。

到这里，RNN 内部结构这一块就聊完了。这是最基础的关于 RNN 内部结构的介绍，下一节我们去看它的 API——那 12 个参数到底怎么填，它们和刚才图上的输入输出维度是怎么一一定死的，我们下一节展开。至于传统 RNN 的优缺点，我肯定现在不给你写：代码还一行没动呢，上来先把优缺点念一遍，跟听天书没区别；等我们把代码做完，最后再来分析，才比较合适。

## Day03-06.RNN代码_基础版(掌握)
> 对应分集：P41 | 原始标题：《Day03-06.RNN代码_基础版(掌握)》

接下来要讲的是 RNN 的 API（应用程序接口，Application Programming Interface），也就是我们平时说的那套调用参数。前面看图看了半天，这一节我们把它落到代码上：模型怎么建、数据怎么造、隐藏状态怎么初始化、结果打印出来应该是什么形状。

先说一个我在课上反复强调的原则：**这几个数字不是背下来的，是推出来的**。你把三四个参数定死，剩下所有张量的形状就全被定死了。下面我们就一步步推。

### RNN 的 API 参数与形状依赖关系

大家还记得 RNN 的 API 是怎么写的吗？往这看。

我们拿一组具体数字来说：`5`、`6`、`1`。

这个 `5` 是谁？是**输入维度**，也就是词向量维度。这个 `6` 是谁？是**输出维度**，也就是隐藏层维度。这个 `1` 是谁？是**隐藏层的层数**，就是你需要几层隐藏层。

先把这几个位置记清楚，然后我们来看它们是怎么"锁死"后面所有东西的。

`5` 和 `6` 一定了，什么就定了？输入的东西就定了：输入的词向量维度定了，输出的向量维度也定了。你看，这不就是刚才说的 `128` 跟上面的 `256` 的关系吗？这里只是换成了 `5` 和 `6`。输入输出一定，那输入 $X$ 这个玩意儿就定了。

然后还有谁定了？输出维度那个 `6`，就是 `hidden_size`（隐藏层维度），它一定，那一堆 `6` 是不是就全定了？

> **结论**：`input_size` 和 `hidden_size` 是两个"源头参数"。它们一定，词向量的宽度、输出向量的宽度、隐藏状态的宽度就全都跟着定了；剩下的只有"批次有多大、一批几个句子、句子多长"这几个跟数据组织方式有关的量需要你自己给。

#### 数据形状的约定：三个数谁先谁后

讲义上有个写法叫"数据 3、1、5"，意思就是**三个批次，每个批次一个单词，每个单词 5 个特征**。

> **易错点**：他想写的是 `3 1 5`，但你一会儿真动手写的时候，必须是"这个是 3、这个是 1、这个是 5"——顺序不能换。三个批次，每个批次几个单词？一个单词。

所以写的时候你要这么去做：三个批次，每个批次一个单词。

那反过来写行不行？你要是写成 `3 1`，那就变成了**一个批次、三个单词**——含义完全变了。

> **提示**：PyTorch 的 RNN 接收的输入张量形状是 `(seq_len, batch_size, input_size)`，也就是"句子长度、批次大小、词向量维度"这个顺序。判断某个数字代表什么，永远去看它落在哪个位置，而不是凭感觉。

#### 九组主参数与辅助参数

这一节里有九组参数，分主参数和辅助参数。严格说加起来是 12 个参数。

这组我们以前该讲的都讲过了，不墨迹。你看：

- 第一个是 `5 6 1`。谁是 5？输入那边是 5。谁是 6？上面输出是 6。这个 `1` 是隐藏层的层数，层数是 1。
- 层数是 1，说明上面那个"层数"的位置就是 1。层数定了，这个也定了。
- 剩下的是 `1 3 5`。`1 3 5` 是什么意思？三个批次，每个批次一个单词。所以批次是 3。
- 批次是 3 知道了，那批次位置是不是就是 3？还有隐藏状态里的批次也是 3，这几个全知道了。
- 还有一个 `1`，这个 `1` 是什么？是**句子的长度**。句子长度知道了，对应位置也知道了。
- 现在就剩谁了？`hidden_size`。刚才那个 `6`，`hidden_size` 就是这个 `6`。`6` 知道了，剩下的也全知道了。

于是最终输出结果就两样，形状都是 `1 3 6`：

```text
   nn.RNN(input_size=5, hidden_size=6, num_layers=1)
        |
        |   输入 x       : (seq_len=1, batch=3, input_size=5)   -> 1 3 5
        |   隐藏状态 h_0 : (num_layers=1, batch=3, hidden=6)   -> 1 3 6
        v
   返回值 output : (seq_len=1, batch=3, hidden=6)               -> 1 3 6
   返回值 h_n    : (num_layers=1, batch=3, hidden=6)            -> 1 3 6
```

读图说明：左边是把 `5 6 1` 交给 `nn.RNN`，下面三行是它要求的输入形状和吐出来的两路结果形状；`1 3 5` 喂进去，`1 3 6` 出来两次，一次是 `output`，一次是 `h_n`。

这里的参数你别晕，以前深度学习课都写过。看懂这张推导表，下面写代码就是把数往里填。

### RNN 任务的输入输出分类

在动手之前，先把这张"分类表"填完，因为后面很多任务选什么模型，靠的就是这张表。

RNN 按照**输入和输出**划分，一共四类。

#### N vs N

输入 N 个、输出 N 个。这个最适合做什么？最起码是**对联**，或者**诗词**。

比如四言、七字的绝句。也有些诗词或者诗歌不一样，你看"枯藤老树昏鸦，小桥流水人家，古道西风瘦马，夕阳西下"，你看，这个格式就不一样了，最后接的是"断肠人在天涯"。所以还有一类就叫小令。输入输出个数相等，但结构上会有变化。

#### N vs 1

输入 N 个，输出一个。它适合做什么？**文本分类**。再具体点：**情感分析**、**文本分类**、**意图识别**，等等。

#### vs N

输入一个，输出 N 个。这就是我们说的**生成类**任务，还有一个典型的叫**看图说话**。

你看现在的大模型其实有点像这个——你问他一个问题，他给你生成一堆。

#### N vs M

一般就是 **sequence to sequence（序列到序列，Seq2Seq）**，句子到句子，比如说**机器翻译**。

> **结论**：N vs M 这一种用得最多。听清楚，我说的是用得最多，所以到时候你要花心思好好把它看看。

#### 按内部结构划分

按照**内部结构**来分，有四类：

| 结构 | 组成/机理 |
| --- | --- |
| 传统 RNN | 输入层、隐藏层、词嵌入层 |
| LSTM（长短期记忆网络） | 各种门 |
| Bi-LSTM（双向 LSTM） | 针对语料从前到后做一次，再从后到前做一次，两个结果拼接 |
| GRU（门控循环单元） | 重置门、更新门 |
| Bi-GRU（双向 GRU） | 同 Bi-LSTM，双向后拼接 |

其中双向的那类，机理说清楚就是一句话：**针对语料，从前往后做一次，再从后往前做一次，然后两个结果拼接**。这就是双向 LSTM 和双向 GRU。

> **提示**：你要是想玩 LSTM 和 GRU，光知道这几个名字还不够，还有一个事你得先知道——传统 RNN 的优缺点。这一节我肯定不给你写，你知道为啥吗？我们代码什么都还没做呢，上来呼一顿把优缺点先讲完，你得做完了最后再去分析才比较合适。我最后给你写。

#### 第一步：创建 RNN 模型

第一个操作，创建 RNN 模型：

```python
    # 1. 创建 RNN 模型
    rnn = nn.RNN(input_size=5, hidden_size=6, num_layers=1)
```

有同学问：非得是 `5 6 1` 吗？你换一个呗，无所谓。

- 参 1 是 `input_size`，对外的说法是输入的神经元数，其实就是**词向量维度**，也就是**输入维度**；
- 参 2 是 `hidden_size`，是**隐藏层维度**，其实就是**输出维度**；
- 参 3 是 `num_layers`，是**隐藏层的层数**。

那这里边现在哪个是能换的？三个都能换。你只要清楚它们各自对后面哪个张量负责就行。

`5 6 1` 的含义完整说一遍：词向量维度是 5，输入维度是 5；输出向量维度是 6，`hidden_size` 是 6，隐藏层的维度也是 6；隐藏层层数是 1。

所以 `5 6 1` 能告诉我们的信息到这儿就为止了，剩下的要从数据形状里去拿。

#### 第二步：准备输入数据

第二个参数组：你想玩这个东西，它要几个输入来着？它要俩——**本次的输入**和**上次的隐藏状态**。那你得准备这俩。

先准备本次的输入，就是那个 $X$：

```python
    # 2. 准备输入数据：即本次的输入
    x = torch.randn(1, 3, 5)   # (sequence_len, batch_size, input_size)
```

`torch.randn` 里面三个数怎么写？最后肯定是个 5，不用说了。前边谁逗号谁？`1 3 5`。

`1 3 5` 什么意思？

- 参 1 是 `sequence_len`，**句子长度**，用英语说是 s-e-q-u-e-n-c-e，`sequence_len`；
- 参 2 是 `batch_size`，**批次大小**；
- 参 3 其实不叫输入维度，它叫**词向量维度**，即输入维度 `input_size`。

那么 `1 3` 到底是什么意思？`batch` 的大小是 3，说明**一批三个句子**；`1` 说明**每个句子的长度是 1**。合起来就是：我现在每批三个句子，每个句子的长度是 1。

> **易错点**：这里的第三个 `5` 必须和第一步 `nn.RNN(input_size=5, ...)` 里的 `5` 对得上；第二个 `3` 必须和下一步 `h_0` 里的 `3` 对得上。任意一处对不上，PyTorch 会在运行时直接报形状不匹配的错。

#### 第三步：初始化隐藏状态

第三个参数组是隐藏状态。这个 `h` 叫 `h_{t-1}`，也就是上一时间步的隐藏状态；但你不能真写成 `h_{t-1}`，我们写成 `h_0` 就行了：

```python
    # 3. 初始化隐藏状态：即上一时间步的隐藏状态
    h_0 = torch.randn(1, 3, 6)   # (num_layers, batch_size, hidden_size)
```

`h_0` 得多少？`1 3 6`。这三个数是怎么来的？

- 参 1 = 1，是**隐藏层的层数**，也就是 `num_layers`；
- 参 2 = 3，是**批次大小**；
- 参 3 = 6，是**隐藏层的维度**，也就是输出的那个维度：你输出是 6，它隐藏层就是 6。

看出来了吗？这批数是**基于前面锁出来的**：你写了 `1 3`，`batch` 是 3 就定了；`batch` 是 3 定了，隐藏状态里的批次也得是 3。

> **结论**：`h_0` 的三个数全部是"继承"来的，没有一个是新定的——层数来自模型参数，批次来自输入数据，隐藏维度来自 `hidden_size`。所以这一行不需要思考，照着前面填。

#### 第四步：调用模型

第四个参数组还是解释一下，就是模型调用：

```python
    # 4. 调用 RNN 模型
    output, h_n = rnn(x, h_0)
```

等号左边是两路输出：`output` 是**本次的输出**，`h_n`（本来该叫 $h_t$，我这里写成 `h_n`）是**本次的隐藏状态**。

等号右边括号里写的，就是**本次的输入，加上上一时刻的隐藏状态**。小写的 `rnn` 是第三步创建出来的那个层对象，不是类，别写成 `nn.RNN(x, h_0)`。

最后一步，打印结果：

### output 与 h_n 的关系：为什么两者数值相同

接下来是一件让人"哇"一下的事——打印出来的 `hidden` 你发现它是谁？

`hidden` 是不是隐藏状态那个操作？你看上面又没有在别的地方定义过 `hidden`，我们绑的就是 `h_n`。所以 `hidden` 代表的是**本次的隐藏状态**。

那 `output` 是什么？`output` 是**本次的输出**。

然后你会发现一件事：**你的隐藏状态其实记录的就是本次输出的最后一个值。**

先别急着下结论，我们推一下"为什么"。现在 `output` 是 `1 3 6`，也就是只有 1 个时间步。那有没有可能本次输出 20 组值或者 30 组值呢？当然有这种情况。那如果变成 `10 3 6` 或者 `20 3 6`，这个 `3 6` 的组数是不是就非常多了？

而**本次的隐藏状态只记录你的最后一组 `3 6`**——只记录最后一组，因为它是最终的。

所以就有了你看到的那个现象：上面 `output` 的内容和下面 `h_n` 的内容是一样的。这是**取巧的一种情况**——当 `seq_len = 1`、`num_layers = 1` 的时候，`h_n` 恰好就等于 `output` 的那唯一一组。下一节我们把句子长度改成 20，这个巧合就会破掉，你会看到 `output` 变成 `20 3 6`，而 `h_n` 仍然是 `1 3 6`。

到这里，关于 RNN 的 API 演示就先讲完了，这还是比较简单的。完整的基础版代码如下：

```python
import torch
import torch.nn as nn


# TODO 1 定义函数：演示 RNN 的基础版代码
def demo_rnn_base():
    # 1. 创建 RNN 模型：词向量维度 5，隐藏层维度 6，隐藏层层数 1
    rnn = nn.RNN(input_size=5, hidden_size=6, num_layers=1)

    # 2. 准备输入数据：即本次的输入 x
    x = torch.randn(1, 3, 5)          # (sequence_len, batch_size, input_size)

    # 3. 初始化隐藏状态：即上一时间步的隐藏状态 h_0
    h_0 = torch.randn(1, 3, 6)        # (num_layers, batch_size, hidden_size)

    # 4. 调用 RNN 模型
    output, h_n = rnn(x, h_0)

    # 5. 打印结果
    print("output:", output, output.shape)
    print("h_n:", h_n, h_n.shape)
    print("RNN模型:", rnn)


if __name__ == '__main__':
    # TODO 4 测试代码
    print("=" * 30, "RNN 基础版", "=" * 30)
    demo_rnn_base()
```

逐段对一下：`nn.RNN` 那三个参数决定了"模型这一侧"的所有宽度；`x` 的三个数里，最后一个必须与 `input_size` 相等，中间那个决定批次数；`h_0` 的三个数里，第一个是层数，第二个必须与 `x` 的批次数相等，第三个必须与 `hidden_size` 相等；调用后拿到的 `output` 形状是"句子长度 × 批次 × 隐藏维度"，`h_n` 的形状是"层数 × 批次 × 隐藏维度"。

## Day03-07.RNN代码_修改句子长度(理解)
> 对应分集：P42 | 原始标题：《Day03-07.RNN代码_修改句子长度(理解)》

刚才我们已经完成了 RNN 的基础搭建，代码跑通了，形状也打印出来验证过了。那接下来做一件事：**修改它输入数据的长度**。

比如讲义上这个位置，把那个 `1` 改成了 `11`。`11` 是谁？`11` 就是把 `input` 那个位置——`input` 是谁？是 `x`——相当于把 `x` 里第一个位置上的 `1` 改成了 `11`。你把这改成 `11` 了，上面那个句子长度的位置也改成 `11`，其他的都不变。能跟上我的思路吗？

**无论改谁，你看这里边的参数就行了。**

### 复制基础版代码与新增第二个函数

我们来做修改。把上面那段代码 `Ctrl+C` 全选，直接 `Ctrl+V` 贴下来——我贴我自己的代码，没意见吧。

贴到下面之后，这个函数叫第二个函数，名字就叫"演示修改 RNN 模型的句子长度"。

名字也不用跟原来一样。原来那个叫 `base`，我们就换个名字：s-e-q-u-e-n-c-e，`sequence`，后面再写上 `len` 就可以了。所以函数名就是 `demo_rnn_sequence_len`。

新函数里改哪一处？就改 `x` 的第一个位置。

这里我改的是 `20`。有同学说课件上是 `11`——你管我呢，爱改多少改多少。我把 `input` 那个位置，也就是 `x` 这个位置，从这里的 `1` 改成了 `20`。

### 一处改、一处跟：哪些参数必须同步修改

改完 `x` 之后我先问你个问题：我把 `1` 改成 `20` 了，那还有哪个地方要改？

**上面那个句子长度的位置是不是也要改？** 对，就这两处。

那除了它俩以外，其他地方动吗？**不动。** 批次还是 3，词向量维度还是 5，隐藏状态 `h_0` 也还是 `1 3 6`，一个数都不用碰。

```python
# TODO 2 定义函数：演示修改 RNN 模型的句子长度
def demo_rnn_sequence_len():
    # 1. 创建 RNN 模型：参数完全不变
    rnn = nn.RNN(input_size=5, hidden_size=6, num_layers=1)

    # 2. 准备输入数据：句子长度由 1 改为 20
    x = torch.randn(20, 3, 5)         # (sequence_len=20, batch_size=3, input_size=5)

    # 3. 初始化隐藏状态：与句子长度无关，保持 1 3 6
    h_0 = torch.randn(1, 3, 6)        # (num_layers, batch_size, hidden_size)

    # 4. 调用 RNN 模型
    output, h_n = rnn(x, h_0)

    # 5. 打印结果
    print("output:", output.shape)
    print("h_n:", h_n.shape)
    print("RNN模型:", rnn)
```

> **易错点**：`h_0` 的第一个维度是隐藏层层数，不是句子长度。句子长度改到 20，`h_0` 依然是 `1 3 6`——这一点最容易顺手改错。

### 形状推导：output 与 h_n 各自变成什么

改完之后，两个返回值的形状马上就能推出来。

`output` 打印出来是多少？它是不是就变成 `20 3 6` 了——因为 `output` 的第一维跟的就是句子长度。

那 `h_n` 呢？`h_n` 输出的还是 `1 3 6`。而且这个 `1 3 6` 肯定是 `20 3 6` 里面的什么？**最后一个。**

一句话总结这次的改动：

> **结论**：句子长度只影响 `output` 的第一个维度；`h_n` 的形状由"层数 × 批次 × 隐藏维度"决定，与句子长度无关。所以 `seq_len` 从 1 改成 20 之后，`output` 是 `20 3 6`，`h_n` 仍是 `1 3 6`，且 `h_n` 就是 `output` 里的最后一行。

### 运行验证与科学计数法下的数值对比

接下来我们试试。把下面原来那个基础版的测试调用注释掉，换成新的测试：

```python

    # demo_rnn_base()

    print("=" * 30, "修改句子长度", "=" * 30)
    demo_rnn_sequence_len()
```

右键执行。先看打印结果——打印内容太多了，不看，直接看它的维度。

请问是不是我们刚才所说的？来，瞅着看：第一个叫 `20 3 6`，是左边这个；右边这个是个多少呢？念一下，是不是个 `1 3 6`？

看到了吧。而且这个 `1 3 6`，你会发现里面整个内容都是 `3.67...e-...` 这样、`0.84...` 这样——其实你会发现它和后面那个值是一样的，**只不过它用的是科学计数法**。

> **提示**：张量里数字很多的时候，PyTorch 打印会自动改用科学计数法（形如 `3.67e-01`）来压缩显示宽度。数值本身没有变，`h_n` 和 `output` 最后一行仍然是同一组数，别被显示格式骗了。

所以到这里，还是那句话：你的隐藏状态记录的其实就是你上述输出状态的**最后一级**。这里 `1 3 6` 记录的就是 `20 3 6` 里面的**最后一组数据**。

```text
   x : (20, 3, 5)                                    seq_len 1 -> 20
        |
        v
   nn.RNN(input_size=5, hidden_size=6, num_layers=1)
        |
        +--> output : (20, 3, 6)   <-- 第 0..19 时间步的隐藏状态全存着
        |
        +--> h_n    : ( 1, 3, 6)   ==  output[-1]  <-- 只留最后一个时间步

   形状对照（改动前 -> 改动后）：
       x       ( 1, 3, 5) -> (20, 3, 5)
       output  ( 1, 3, 6) -> (20, 3, 6)
       h_0     ( 1, 3, 6) -> ( 1, 3, 6)   不变
       h_n     ( 1, 3, 6) -> ( 1, 3, 6)   不变，等于 output 最后一行
```

读图说明：句子长度只让 `x` 与 `output` 的第一个维度一起变长，`h_0` 与 `h_n` 完全不受影响；`h_n` 始终等于 `output` 最后一个时间步的那一组数。

### 模板化改参：改哪个参数就换哪个元素

这个位置修改的是它输入的一个**长度**。那我想说的其实是另一句话：

无论是现在在这里边我去修改了哪一个参数，你看上面有变量名，还有变量的值——**无论我修改谁呢，你是不是把那对应的元素做一个变换，是不是就可以了？**

> **结论**：这一节的代码是一份"模板"。模型参数在一处（`nn.RNN` 的三个实参），输入形状在一处（`x`），隐藏状态形状在一处（`h_0`），输出形状由它们推出来。以后你要调批次、调词向量维度、调隐藏层维度，都是同样的动作——找到那个数所在的位置，改它，然后顺着依赖关系把该跟着改的改掉，其他都一样。

这就是修改 RNN 句子长度的全部内容，这份代码我们就先聊到这。

## Day03-08.RNN代码_修改隐藏层及总结(理解)
> 对应分集：P43 | 原始标题：《Day03-08.RNN代码_修改隐藏层及总结(理解)》

上一节我们把句子的长度改了，参数图跟着动了一格。这一节换个地方动：把隐藏层的层数从 1 改成 2。事情看起来比改句长还简单，只有一个数字变了，但恰恰是这一个数字，让不少人复制粘贴代码的时候漏改了一处，程序跑起来才报形状错误。

### 隐藏层层数改动牵连的形状参数

一开始的时候，隐藏层的层数我们一直写的是 1。现在把它从 `1` 改成 `2`，你告诉我谁变了？

是不是后边这个隐藏层的层数要变？还有别的吗？没了。只有它变了。那它变了之后，跟着变的是什么？是 `h_0` 这个位置的形状——它会从 `[1, 2, 128]` 变成 `[2, 2, 128]`。其他地方照常依旧，该是什么还是什么。

我们把参数图摆在旁边，一边改代码一边对照。这一讲的图里，`h_0` 的位置画得很清楚，它和隐藏层的层数是绑在一起的。

> **提示**：真正会出错的不是"改哪个数"，而是"改了数以后忘了改形状"。这两件事在图上永远是成对出现的，图上标了，代码里就得贴。

#### 定义变量与配置隐藏层层数

这一步的操作和上一节改句长时是一模一样的：先定义变量，再传递参数，只是这次传的是隐藏层的层数。

```python
# 配置参数 - 本批样本 2 条，句子长度 1，每个词的向量维度 128，隐藏层神经元个数 256
batch_size = 2      # 每一个批次给模型喂 2 条样本
seq_len    = 1      # 每一条样本的句子长度（时间步数）
input_size = 128    # 每个词的词向量维度
hidden_size = 256    # 隐藏层神经元个数（也就是隐藏状态的维度）
num_layers = 2      # 隐藏层的层数：从 1 改成 2，本节的唯一改动
```

对应的画布是"图 3"，内容就是把"定义变量 + 贴函数"再走一遍，函数换成 `nn.RNN`，而这次要改的变量名叫 `num_layers`——隐藏层的层数。变量名写全一点更好认：`hidden_layers`。

这里我想说一句话：你现在把这个图往这一摆，我觉得无论我改哪一个数，你都知道我在修改谁，而它一改，其他参数也应该相应地发生变化。这就是我要说的点。

这张图里的参数是我们一开始一个一个标上去的。所以我希望你们做一件事：这个图你能背下来最好；背不下来，就把它收藏一下。万一哪一天需要写到参数了，你直接把这张图打开，往里面把参数一填，就知道结果是啥样了。

```python
import torch
import torch.nn as nn

rnn = nn.RNN(input_size=128, hidden_size=256, num_layers=num_layers, batch_first=False)
```

### 隐藏层层数修改后的形状推演

参数都摆好了，两个样本、句子长度 1、词向量 128 维、隐藏层神经元 256 个、隐藏层 2 层。

先看输入：

```python
x  = torch.randn(seq_len, batch_size, input_size)      # [1, 2, 128]
h0 = torch.randn(num_layers, batch_size, hidden_size)  # [2, 2, 256]
```

**这一次改完，`h_0` 这个位置必须换成 `[2, 2, 256]`。** 我们刚才写的还是 `[1, 2, 256]`，层数改成 2 了，`h_0` 却不跟着改，就直接错了。形状错了后面全崩。

再看输出：

```python
output, hn = rnn(x, h0)
print(output.shape)   # torch.Size([1, 2, 256])
print(hn.shape)       # torch.Size([2, 2, 256])
```

先看形状，一个一个念一遍。`output` 是不是还是 `[1, 2, 256]`？是。`hn` 呢？是不是 `[2, 2, 256]`？是，因为两层，第一维就是 2。

那 `nn.RNN` 自己打印出来的结果长什么样？一层的时候它默认把层数省略了，你看不见那个 1；两层的时候，它就会给你显示一个 2：

```text
RNN(128, 256, num_layers=2)
```

> **易错点**：`h_0` 是**入参**，`h_n` 是**返回值**，两者形状规格相同（都是 `[num_layers, batch_size, hidden_size]`），但改层数时容易只顾着写参数、忘了把喂进去的 `h_0` 一起改。复制粘贴的场景下，这是最高频的漏改点。

顺手把整条链上的形状对一遍，就不会漏：

| 变量 | 含义 | 形状 | 是否随 `num_layers` 变化 |
| --- | --- | --- | --- |
| `x` | 本次输入 | `[1, 2, 128]` | 否 |
| `h_0` | 初始隐藏状态（入参） | `[2, 2, 256]` | **是** |
| `output` | 每个时间步的输出 | `[1, 2, 256]` | 否 |
| `h_n` | 最后一层的隐藏状态（返回） | `[2, 2, 256]` | **是** |

对照读一遍：输入 `x` 与 `output` 不受层数影响；两个隐藏状态的位置由层数决定第一维。

再对上参数的总账：`input_size` 是 128，`hidden_size` 是 256，`num_layers` 是 2，`batch_size` 是 2，`seq_len` 是 1。

> **结论**：无论以后在图上改谁，都要记住它的参数就这 12 个——`nn.RNN` 的 9 个入参，加上它返回的 `output`、`h_n` 以及贯穿全程的 `x`。无论你改谁，对应的位置发生改变，代码就不会错。

### 隐藏层最后一层与输出层的关系

改完之后再看一眼 `output` 和 `hn`，你会发现一件事：`hn` 的最后一层，记录的就是 `output` 那一层的结果。

```text
output: [1, 2, 256]   <- 每个时间步的输出
hn:     [2, 2, 256]   <- 第 0 层是隐藏层 1 的结果
                         第 1 层是隐藏层 2 的结果，与 output 一致
```

于是有人就要疑惑了："我有两层隐藏层，为什么 `hidden` 只记录最后一个？那中间那一层是干啥的？"

它是**过渡**的。不是记录上一次，是过渡。什么意思？往下看图。

先把话说在前面：两层这种操作，实际开发中一般是不做设置的。但既然设置了，它的底层图解你就得能想清楚。

时间步展开以后是这样的：第一个时间步、第二个时间步、第三个时间步，每一步都是"本次的输入 + 上次的隐藏状态"，得到本次的隐藏状态和本次的输出。

```text
只有一层时（时间步展开）：

  x1        x2        x3
   |         |         |
   v         v         v
 [H1] ---> [H1] ---> [H1]        每步都是：本次输入 + 上次隐藏状态
   |         |         |
   v         v         v
  y1        y2        y3
```

现在把层数改成 2。输入 `x` 先经过隐藏层 1，再经过隐藏层 2。所以隐藏层 1 其实就是一个过渡，隐藏层 2 才是我们最终的结果。

```text
两层时（同一时间步内部纵向加深）：

        x （本次输入）
        |
        v
  [隐藏层 1]  <- 中间结果，过渡用
        |
        v
  [隐藏层 2]  <- 最终结果，与 output 一致
        |
        v
        y （本次输出）
```

这就解释了你刚才看到的现象：隐藏层 1 的结果是下面那一层，隐藏层 2 的结果是上面那一层，再往上就对接输出那一坨了。

那如果是三层、四层、五层呢？就是 `x` 在这里算一层、算两层、算三层，最后算到 `y`。区别在哪？运算量肯定增加了。层数增加，你可以学到更多特征信息——算力增加了，效果可能相对来讲会好那么一点。

#### 换一个角度：把纵向加深看成一摞前馈网络

这个图你要是看不懂，就把它转一下。把每一层的含义标出来：这是输入层，这是隐藏层 1，这是隐藏层 2，这是隐藏层 3，这是输出层。

```text
转成"垂直摆放"再看：

   输入层
     |
   隐藏层 1        <- 等于在中间插了一个隐藏层
     |
   隐藏层 2
     |
   隐藏层 3
     |
   输出层
```

转成这样以后，你用 ANN（人工神经网络，Artificial Neural Network）来解释就通了：ANN 是输入、一个隐藏层，然后直接对接输出。而现在的动作，相当于在中间又加了几个隐藏层——输入到隐藏到隐藏到隐藏，才到输出。

实在要说，它就是把数据本来"从 `x` 直接算到 `y`"的这个动作，改成了"`x` 先算到中间，再往上算一步到 `y`"，中间插进去了几层。

但实际开发中，一般不会加这个层数。你加了也要记住一句话：**最后一层等价于你输出的那个结果**。

> **易错点**：`h_n` 里只保留每一层在**最后一个时间步**的隐藏状态，中间时间步的历史并不在里面；需要全部时间步时取 `output`。这也是下一节讲长序列问题时最容易被误解的地方。

### RNN 的优缺点与梯度连乘

把 RNN 的总结落地。先说优点，一共三条：

| 优点 | 具体说法 | 为什么 |
| --- | --- | --- |
| 内部结构简单 | 结构本身很简单 | 里面就是一个加权求和，再扔一个激活函数处理，就完事了 |
| 计算资源要求低 | 对资源消耗相对较小 | 同上，运算量小，所以对算力不挑 |
| 短序列任务表现好 | 短序列任务上性能与效果都优异 | 依赖链短，上一时刻的隐藏状态足够承载 |

还有一条对比：RNN 的变体 LSTM、GRU，参数总量比 RNN 少很多。这句话反过来也说明一件事——RNN 内部结构简单，一会儿它的变型 LSTM 和 GRU 的内部结构就不简单了。

再说缺点，两条，但根子是同一个。**在什么任务上不行？** 长序列。什么叫短序列？就是你句子的长度不能太多、不能太长。一个句子的长度是 100 个词或者 200 个词，这种长序列它就干不了了。

为什么？因为长序列经过反向传播的时候要去更新参数，数据量太多，反向传播时容易出现梯度消失或者爆炸的问题。

至于"长序列文本特征提取效果差"，原因也很直接：你总是用上一时刻的隐藏状态往下接，用那个 `h0`、`h1`、`h2` 一路往后传，越往后你的 `h` 里面记录的信息就越多。你能记 5 个词，你能记 500 个词吗？你能记 5000 个词吗？一个 `h` 怎么可能记那么多信息。

> **提示**：这个道理用一句话就能验证——让你用一句话去形容自己从小到现在的人生经历，你怎么可能通过一句话把人生总结下来？就算硬说，也只能说一句"历经磨难"，意义就不大了。RNN 处理短序列比较好，但要处理长序列、想通过上一时刻的隐藏状态去记住所有信息，这个压力太大了。

梯度为什么会消失、为什么会爆炸？想个最简单的例子：

```text
梯度连乘：0.5  ×  0.5  ×  0.5  ×  ...   ->  迅速趋近于 0     （梯度消失）
梯度连乘：1.1  ×  1.1  ×  1.1  ×  ...   ->  迅速变得极大     （梯度爆炸）
```

一直乘下去，0.5 很快就会非常非常接近 0；换成 1.1，一会儿值就超级超级大，有可能爆炸。

> **结论**：RNN 的优点就是更适合计算资源低的场景、更适合短序列任务；缺点就是长序列任务不太适合。正因为不适合处理长序列文本，而处理长文本的需求又确实存在，所以才有它的变形——LSTM 与 GRU。

把这段写进笔记的时候，正好补上前面留的那个空：

- **优点**：内部结构简单；资源消耗相对较小；适合处理短序列文本。
- **缺点**：处理长序列数据时，反向传播结合梯度连乘，过大或过小的 $w$ 值会导致梯度爆炸或梯度消失。

### RNN 的内部结构、数学公式与 API 参数

#### 内部结构、输入输出与变量含义

RNN 的内部结构由输入层、隐藏层和输出层组成。

写代码的时候记住一句话：RNN 是**两个输入对应两个输出**。两个输入是本次的输入和上一时刻的隐藏状态，两者融合到一起，再经过特定处理，得到本次的隐藏状态和本次的输出。

```text
        h0（上一时刻隐藏状态）
              |
              v
  x（本次输入） -> [融合 + 特定处理] -> hn（本次隐藏状态）
                                          |
                                          v
                                    output（本次输出）
```

变量名的对应关系理清：

- `input` 是本次输入；
- `output` 是本次输出；
- `h0` 是上一时刻的隐藏状态；
- `hn` 是本次的隐藏状态。

> **易错点**：`h_0` 是**喂进去的初始状态**，`h_n` 是**返回的末状态**，名字只差一个字母，方向正好相反。位置写反了，形状可能碰巧对得上，数值却完全是错的。

#### 数学公式：学术写法与工程写法

RNN 模型的数学公式有什么好讲的？看两个写法：

$$h_t = \tanh(W \cdot [h_{t-1}, x_t] + b)$$

这是把本次输入和上一时刻隐藏状态拼在一起，用一组权重做完加权求和，再过一个 `tanh`。

$$h_t = \tanh(W_{xh} \cdot x_t + W_{hh} \cdot h_{t-1} + b)$$

这是把两部分分开各乘一组权重再相加，同样过 `tanh`。

学术里那个 $W$ 权重就是一个；业界的公式里是两个。第一个算的是本次输入的贡献，后边那个算的是上一时刻隐藏状态的贡献,把两个加权求和的结果做合并，最后通过 `tanh` 做激活处理。

本质上来讲这两个写法没有什么区别。非要聊区别，就是下面这个写法比上面那个参数的计算要多一些，仅此而已。

#### API 参数与两道概念题

`nn.RNN` 的 API 有 9 个参数。这 9 个参数分别是谁？其实准确地说不是 9 个，一共是 12 个。

那 9 个说的是输入侧：`input`（也就是 `x`），还有一个是 `h_0`。它没有算返回的。你把返回的那一堆——`output`、`h_n`，再加上全程都在的 `x`——一起加上，就变成 12 个参数了。要注意这一点，它们都在这张图里。

> **结论**：第 9 个参数的位置上放的是 `h_0`，而返回侧还有 `output` 与 `h_n`。参数数是 12 而不是 9，差别就在"入参"和"返回值"这两侧要不要一起算。

最后是这一节的两道概念题，把答案记牢。

**当 RNN 模型隐藏层为 2 时，隐藏层 `hn` 和 `output` 的结果各自有什么特点？**

隐藏层的最后一个结果，跟输出层的最后一个结果保持一致。也就是说，`output` 的输出结果和最后一个隐藏层的结果是一致的。为什么是最后一个？因为顺序是输入、隐藏层 1、隐藏层 2、隐藏层 3、输出——最后一个隐藏层和输出层是挨着的。一般来讲隐藏层直接写几个？直接一个，一般不多写，除非必要。

**RNN 写代码时，输入和输出的对应关系是什么？**

两个输入对应两个输出：输入是上一时刻的隐藏状态和本次的输入，输出是本次的隐藏状态和本次的输出。

## Day03-09.LSTM模型_原理图解(上)_理解
> 对应分集：P44 | 原始标题：《Day03-09.LSTM模型_原理图解(上)_理解》

接下来要详细讲的是 LSTM 模型。这种模型相较于 RNN，最直观的变化是内部结构不一样了：承载这个结构的不再单纯是输入层、隐藏状态和输出层，而是**门**——三个门加一个状态。哪三个门？遗忘门、输入门、输出门，再加一个细胞状态，一共四部分。

### LSTM 的定义与作用

`LSTM` 这个单词要记一下：Long Short-Term Memory，叫**长短时记忆结构**。

它是传统 RNN 的一个变体。和经典的 RNN 相比，它能**有效捕捉长序列之间的语义关联**。"语义"这两个字很重要。同时，它**缓解梯度消失或者梯度爆炸**。

> **提示**：注意这里用的是"缓解"，不是"解决"。它没有从根上百分之百解决梯度消失或爆炸这件事，只是让发生的概率更小了一点，但依然有可能存在。

结构上，它同样由输入层、隐藏层、输出层组成。但每个时间步有三个输入：本时刻的输入、上一时刻的细胞状态、上一时刻的隐藏状态；相应地有三个输出：本次的细胞状态、本次的隐藏状态，以及本次的输出。`C` 代表细胞状态（cell），`H` 代表隐藏状态（hidden）。内部是三个门加一个状态，遗忘、输入、输出加细胞状态，一共四个组成部分。

看一眼图就知道这哥们儿相当复杂——从颜色上就看出来了。想想刚才的 RNN，它里边就几个？就一个 `tanh`。这里边几个？四个。所以它比 RNN 要复杂得多。

> **记忆锚点**：2018 到 2020 这两年去找工作，LSTM 这个模型是要**手推**的——接下来这张图你得给别人手绘出来，告诉他是怎么算的，每个公式都是什么意思，每个都要讲清楚。但现在已经 2025 年了，不再要求手推 LSTM 了。现在手推什么？手推 Transformer。为什么 18 到 20 年要手推 LSTM？因为 BERT 那个模型其实就是从 2018 年开始火的，但那时候还没有火到今天这个程度，它也需要一定的时间。

### 四组运算的公式速览

先把四组运算的构成过一遍，知道每一项叫什么，再往下谈直觉。

遗忘门：

$$f_t = \sigma(W_f \cdot [h_{t-1}, x_t] + b_f)$$

$\sigma$ 是小写的 sigma，就是 sigmoid。括号里是加权求和，外面是激活函数处理，这就是遗忘门的门值。门值出来以后，乘上任意时刻的细胞状态即可。

输入门：

$$i_t = \sigma(W_i \cdot [h_{t-1}, x_t] + b_i)$$

同样的结构：上一时间步的隐藏状态和本次的输入拼在一起，与权重 $W_i$ 做矩阵运算，再经过 sigmoid 激活，把结果压到 0 到 1 的区间，算作输入门。

细胞状态与候选记忆、输出门则各有一组类似形式的运算，形式一致，只是门不同、下标不同。

单看这两页公式，一会儿你就看懵了。所以我先一步一步解释这个动作到底是怎么回事，你要好好听——这张图它不是特别好画，东西非常多。

### 结构图上三个门与细胞状态的圈定

在展开画图之前，先把图上哪一坨是哪一坨圈出来，后面读图就不会迷路。

按讲师圈图的位置顺序，一共圈四坨：

- 最左边那一坨：**遗忘门**；
- 中间那一坨：**输入门**；
- 上面那一坨（从左边的乘号一路延伸到后面）：**细胞状态**；
- 最后那一坨：**输出门**。

颜色可以这样分：门各一种颜色，细胞状态单独一种。圈完之后，我们把图复制一份、拉到旁边做个对照，和上面那张 RNN 的参数图摆在一起——很像，正好能一一对上。

> **易错点**：图上标了颜色不等于记住了位置。判断哪个门看的是它的**连线走向**：遗忘门管的是"往细胞状态上乘一个系数"，输入门管的是"往细胞状态上加新东西"，输出门管的是"从细胞状态里挑出一部分往外送"。

习惯养成之后，就进入正题——把每个门的**作用、类比、图中公式、结论**四件事依次写清楚。

### 遗忘门的作用与门值

遗忘门的作用是：通过当前的输入和上一时刻的隐藏状态，决定记忆细胞里的哪些信息可以丢掉。

在图上，`x`（当前输入）有一路进到遗忘门，另外还有一路箭头上边过来，那是上一时刻的隐藏状态。两个信息合起来做判断，输出的是"丢多少"。

举个日记本的例子：你记日记的时候，发现昨天记的是天气预报。对今天的事来说天气预报这点事没用，那就把它从长期记忆本中划掉——这个长期记忆本你可以理解为细胞状态。划掉，不要了。遗忘门干的就是这个动作。

#### 门值公式与保留、遗忘的判断

遗忘门的公式关键在门值的写法：

$$f_t = \sigma(W_f \cdot [h_{t-1}, x_t] + b_f)$$

一步步拆开念：门值等于激活函数括号里的内容；括号里是 $W_f$（权重矩阵）乘以中括号里的一项，中括号里是上一时刻隐藏状态和本次输入 `x_t`；最后再加上一个 $b_f$，也就是偏置。

> **提示**：偏置这一项在某些实现里直接不考虑，也不影响理解主流程。

公式下面还有一组 $f_t \times C_{t-1}$，那不是门值本身——$f_t$ 才是门值，而门值再乘上一次的细胞状态，是"怎么用这个门值"的下一步动作。

> **结论**：门值是一个数值，它会得到一个介于 0 和 1 之间的结果。
>
> - 门值**接近 1**：说明这一挑旧记忆有用，要**保留**下来。
> - 门值**接近 0**：说明要**忘掉**这一挑旧记忆。

理解这个结论有个特别直观的方式：把门想象成一个真实的门缝。

```text
门开得大（门值 -> 1）：        门半掩着（门值 -> 0.5）：      门堵死（门值 = 0）：

   |‾‾‾‾‾‾‾|                     |‾‾\                          |‾‾‾‾‾‾‾|
   |       |  <- 往里挤           |   \  <- 效率大幅下降          |       |  <- 谁也进不来
   |       |     进去的最多        |    \                         |       |
   |_______|                     |_____\                        |_______|
```

门值决定的就是这个门开多大。门开得越大，能过滤进来的信息越多；门关到 0，谁也进不来。忘掉昨天不开心的事情，就是把那些数据的门缝收窄到接近 0。

### 输入门的作用、类比与两个公式

遗忘门讲完，接下来是输入门。

输入门的作用是：同样是**通过当前的输入和上一时刻的隐藏状态**，决定**哪些新信息需要放进记忆细胞**。

同样的入口、同样的两个来源，区别在它管的方向：记忆细胞里那些旧的，由遗忘门决定丢哪些；这次冒出来的新的，由输入门决定记哪些。

#### 类比：把当天发生的大事记进长期记忆本

比方说你今天遇到一件大事。什么算大事？你过生日，女朋友送你一辆法拉利——这事重要，那就把它记到长期记忆本里。记进去以后，你会永远记得在多少多少岁生日的时候，女朋友送了你什么。

输入门干的就是"判断重不重要，重要就写进长期记忆本"这个动作。

#### 门值公式与候选记忆

输入门这一坨其实主要是两个动作，因此需要两个公式。

第一个公式就是门值本身：

$$i_t = \sigma(W_i \cdot [h_{t-1}, x_t] + b_i)$$

它和遗忘门的门值公式形式**完全一样**——都是"门值等于激活函数，权重乘以等等等等，加偏置"。所以写笔记的时候，根本不需要把字母写全，我只需要写"门值"三个字就够了。为什么？因为下一个门的门值公式可以直接复制粘贴拿过来用，一个字都不用改。

> **提示**：门值公式的四件套——激活函数、权重矩阵、上一时刻隐藏状态与本次输入的拼接、偏置——对遗忘门、输入门、输出门完全一致。记住一个，三个都记住。

第二个公式是**候选记忆**：

$$\tilde{C}_t = \tanh(W_C \cdot [h_{t-1}, x_t] + b_C)$$

候选记忆是什么？是**生成可能要存的新信息**。注意"可能"这两个字——它还没有真正去更新，只是临时记一下。

为什么要有这么一个临时的地方？你可以理解为**排练**。马上要过年了，过年那天是直播，但你觉得这帮演员前期有没有去舞台上做过排练？不可能当天直接上台就表演，前期肯定排练了很多很多回。所以候选记忆就是排练这个动作，最终才真正推进去。要是瞄了一眼觉得重要就直接推进去，后面就没有余地了。

所以最后一步是：**门值乘以候选记忆**。门值越大，存进去的越多；门值越小，真正落地的新信息就越少。

### 细胞状态的存储作用与更新方式

中间这个叫记忆细胞，也叫细胞状态（cell）。写代码的时候，我们就用 `C` 表示这个细胞，用 `H` 表示隐藏状态，这些变量名要知道来路。

它其实就是那个长期记忆本，作用是**存储关键信息**。

你长这么大，人生中总有些转折点：高中选文科还是理科、大学选学校选专业、怎么来到了这里——这些都是转折点。其中最重要的那些，你会把它们作为记忆留下来。细胞状态的特点就是**能跨很多时间步传递**。

对比一下就明白了。传统 RNN 为什么无法处理长文本？因为它记以前的信息记得太多了——**不管是重要的还是不重要的，它都记**。这就像你脑子里把从出生第一天到现在的所有事情事无巨细全记下来，那你的脑子这会儿得炸。

> **提示**：检验这件事有个很简单的例子。你还能记清楚一年前的今天吃了什么饭吗？大多记不住。为什么腊八这天有人能记住？因为今天是腊八，传统上早上要喝粥。哪天要是普通日子，比如六月初六、6 月 13 号，本身对你没什么特殊意义，那你上一年做的什么、前两年做的什么，基本是记不住的。**能被想起来的东西，都是因为对你关键。** 这就是细胞状态只存关键信息、并且能跨很多时间步传递的原因。

那么这些关键信息是怎么被筛出来的？靠的就是下面这一行更新公式。

$$C_t = f_t \cdot C_{t-1} + i_t \cdot \tilde{C}_t$$

念完这一行，两个前面"没用上"的公式就对上了：$f_t \cdot C_{t-1}$ 是遗忘门门值乘以前面的旧记忆细胞状态，$i_t \cdot \tilde{C}_t$ 是输入门门值乘以候选记忆。之前留着的两块，到这里正好用上。

- 第一项管的是旧信息："以前的信息每次往后传的时候，我再忘掉一些"。
- 第二项管的是新信息："新的信息我再挑重点往里边加一些"。

为什么必须这么筛？因为不能全存，全存就扯淡了，哪能存那么多。

> **结论**：细胞状态靠"旧记忆筛一遍 + 新记忆挑一挑"来解决长序列记忆问题——只记录核心信息，传递的时候就不用传那么多。

旧记忆为什么会变得不重要？想想你自己：上初中或者高中谈的那个对象，在当时记录你们之间的事记得还是很清晰的，甚至刻骨铭心，要么是他伤你最深，要么是你伤他最深；等到年纪再大一点，结完婚有了小孩，再回忆以前的事，可能都不一定想得起来了。当时觉得很重要的事，随着时间推移可能也就无所谓了。遗忘门门值干的正是这件事。

这也解释了为什么 LSTM 值得那几个科学家那么琢磨——原理这么一思考，确实能想得通，确实可以这样写、这样做。至于他们当时究竟是怎么考虑到这件事的，那就很好奇了。

### 输出门决定传递哪些记忆

最后一步是输出门。事总得往前走：过了今天还有明天，过了明天还有后天。所以输出门决定的是**输出哪些记忆**。

它的作用多了一个输入源：不只是本次的输入和上一时刻的隐藏状态，还要看**更新后的记忆细胞**——因为要输出的内容正是从更新完的细胞状态里挑的。

类比很简单：你给朋友讲今天发生的事。你会从长期记忆本里挑重要的讲。"昨天有人送了我一辆法拉利"这种事你会讲；"早上吃了面包"这种事相对来讲没那么重要，暂时不说。

### 大白话整体流程与管家四步

公式和结构都摆完了，把整件事用大白话串一遍。

把 LSTM 想象成一个小房间。里面有**三个门**，门就是开关；还有一个**记忆细胞**，也就是 `cell`。

三个门分别是遗忘门、输入门、输出门，它们控制信息的**进、出、留**。记忆细胞专门存重要的信息，相当于你们家那本记账用的长期记事本——买菜买奶茶这种几块钱的小支出可能就不记了，超过 500 的、超过 1000 的大项支出才记一记：到月底翻一翻，哪些是必要的，哪些其实可以舍弃。

整体流程就像**管家整理记忆**。其实你脑子里就有个管家在帮你整理记忆，只不过你不知道而已。很久以前的记忆，你不去回想，它就被封存起来；突然想到某个场景，那段封存的记忆就像潮水一样涌现出来——比如你的初恋已经三四年没见了，某天在门口打饭的时候突然看见他，那些记忆一下就涌了出来。

这位管家的四步工作：

- **遗忘门负责筛选旧记忆**，说白了就是丢垃圾——决定以前的东西忘多少，哪些忘掉、哪些保留。注意：遗忘门里存的是**旧的信息**。
- **输入门负责筛选新信息**，可以理解为"新宝贝"——结合当下正在发生的新事，把该记的挑出来。输入门里存的是**新的信息**。这和上一节讲 RNN 的那个操作是同一个道理：上一时刻的隐藏状态与当前的输入，跟历史状态的关系是一样的。
- **记忆细胞负责更新长期记事本**，长期保存关键信息，可以理解为永久存，这事这辈子都不会忘。旧记忆删一些留一些，新记忆也删一些留一些，把筛过的旧的与新的都更新到这个长期小本本里。
- **输出门负责挑重点讲**，筛选要传递的记忆，把长期记忆本里的重点挑出来，交给下一个管家。就像月嫂离职、管家离职要跟新接手的人交接——你会把每行代码具体全部教给他吗？不会。你会把大概要做的事讲一遍：第一、第二、第三、第四要做什么。

```text
                     +---------------------+
   旧信息 ---------> |      遗忘门         | ---- 忘掉哪一挑旧记忆
   （上一时刻         +---------------------+
    隐藏状态）                  |
                                v
                     +---------------------+
                     |   细胞状态（长期）   |  旧的筛一遍 + 新的挑一挑
                     |   记忆本 / 记事本    |
                     +---------------------+
                                ^
   新信息 ---------> +---------------------+
   （本次输入）       |      输入门         | ---- 哪一挑新信息要写进来
                     +---------------------+
                                |
                                v
                     +---------------------+
                     |      输出门         | ---- 挑重点，交给下一个管家
                     +---------------------+
                                |
                                v
                        本次隐藏状态 h_t
```

读图方式：左边两股信息（上为上一时刻隐藏状态、下为本次输入）先进两个门去筛，筛完在中间的细胞状态里做一次"旧减新增"的更新，最后由输出门从更新后的细胞状态里挑出本次要往外传的那部分。

一句话收束整个流程：**旧的记忆删一些留一些，新的记忆删一些留一些，把这些旧的和新的更新到长期小本本里边；然后从这个小本本里再找一部分信息，输出给下一个管家。**

流程讲到这里，下一步就该把每个公式具体是干什么的逐条对上了。

## Day03-10.LSTM模型_原理图解(下)_理解
> 对应分集：P45 | 原始标题：《Day03-10.LSTM模型_原理图解(下)_理解》

前面我们从核心和整体流程上把 LSTM 过了一遍：三门一状态、管家整理记忆、旧的删一些留一些、新的也删一些留一些。但流程归流程，真正落到公式上还没写。这一节就把遗忘门、输入门、记忆细胞、输出门这四步的公式逐条对上去，看每一步到底在算什么。

### 遗忘门的作用、公式与门值含义

一上来第一个区域就是遗忘门。

它的作用是：通过**当前的输入**和**上一时刻的隐藏状态**，决定记忆细胞里的哪些信息可以丢掉。

看图上箭头：`x`（当前输入）有一路进到遗忘门；上边还有一路箭头过来，那是上一时刻的隐藏状态一路往后走传下来的。两个信息合在一起做判断，判断的对象就是记忆细胞里的内容——哪些可以丢。

举个例子：你记日记的时候，发现昨天记的是天气预报。对今天的事来说，这玩意儿没用，那就把它从长期记忆本（也就是你的细胞状态）里划掉，不要了。

#### 门值公式的逐项拆解

遗忘门的公式是：

$$f_t = \sigma(W_f \cdot [h_{t-1}, x_t] + b_f)$$

跟着思路把它念一遍：门值等于激活函数，括号里是 $W_f$ 乘以中括号里的一项，中括号里是 $h_{t-1}$（上一时刻隐藏状态）和 $x_t$（本次输入），最后加上 $b_f$，也就是偏置。

> **提示**：偏置这一项有时候其实可以不考虑，不影响理解主流程。

公式下面还有一组 $f_t \times C_{t-1}$。这一组**不是门值**：$f_t$ 才是门值，门值再乘上一次的细胞状态，是"拿到门值之后怎么用"的动作。这里先记下来，等到讲记忆细胞更新的时候会正式用上。

> **结论**：门值是一个数值，落在 0 到 1 之间。
>
> - 门值**接近 1** → 这一挑**旧记忆**有用，**保留**。
> - 门值**接近 0** → 这一挑旧记忆**忘掉**。

#### 门值大小的直观含义

公式看着抽象，换个实物就清楚了：把它当成一扇真实的门。

```text
门开得足（门值 -> 1）：        虚掩着（门值约 0.5）：         堵死（门值 = 0）：

   |‾‾‾‾‾‾‾‾|                    |‾‾\                          |‾‾‾‾‾‾‾‾|
   |        |                    |   \                         |        |
   |        |  <- 进去的最多       |    \  <- 效率大幅下降         |        |  <- 谁也进不来
   |________|                    |_____\                        |________|
```

门值决定的是门开多大——门开得越大，能过滤进来的信息越多；门越小，能进来的越少；门堵死变成 0，谁也进不来。遗忘门就是靠这个数值来调整"过滤掉多少旧信息"。

### 输入门的作用、门值与候选记忆

遗忘门讲完，接着讲输入门。它主要是两个动作。

输入门的作用是：同样是通过当前的输入和上一时刻的隐藏状态，决定**哪些新信息需要放进记忆细胞**。

换句话说，上面那个门管的是"丢掉哪些旧的"，这个门管的是"记住哪些新的"。

类比一下：你今天遇到一件大事。什么算大事？比如过生日，女朋友送你一辆法拉利——判断这事重要，就把它记到长期记忆本里。于是你会永远记得，在自己多少多少岁生日的时候，女朋友送了你什么。

#### 门值公式与遗忘门同形

输入门的第一个公式是：

$$i_t = \sigma(W_i \cdot [h_{t-1}, x_t] + b_i)$$

你会发现它的内容和上面一模一样——门值等于激活函数，权重乘以等等等等，加偏置。

所以这里有个很实用的结论：写笔记的时候根本不用把字母写全，只写"门值"两个字就够了。为什么不说这是遗忘门的门值、那是输入门的门值？因为下一个门的门值公式可以直接复制粘贴拿过来用，一个字都不用改。

> **易错点**：门值公式的四件套——激活函数、权重矩阵、$h_{t-1}$ 与 $x_t$ 的拼接、偏置——对三个门完全同构，区别只在权重矩阵的下标（$W_f$ / $W_i$ / $W_o$）与偏置的下标。三个门用的激活函数都是 sigmoid，因为门值要被压到 0 到 1 之间才能当"开合程度"用。

#### 候选记忆的生成与激活函数选择

第二个公式是候选记忆：

$$\tilde{C}_t = \tanh(W_C \cdot [h_{t-1}, x_t] + b_C)$$

念一遍：激活函数处理之后，得到的是候选记忆——**生成可能要存的新信息**。

注意"可能"两个字，它还没有真正去更新，只是临时记一下。为什么要绕这么一道？可以理解为**容错**。

> **提示**：这个道理跟过年晚会很像。过年那天是直播，但你觉得这帮演员前期有没有去那个舞台上做过任何排练？不可能的，前期肯定排练了很多很多回。所以候选记忆就是排练这个动作，最终才会推进去。要是瞄了一眼觉得重要就直接推进去，那后面就没有余地了。

最后一步动作是**门值乘以候选记忆**：

$$i_t \cdot \tilde{C}_t$$

门值越大，真正存进去的越多；门值越小，落地的新信息越少——这一项的物理含义就是"候选记忆里哪些是要真正存进去的"。

> **易错点**：候选记忆用的是 `tanh`，门值用的是 `sigmoid`。这不是随手选的：门值必须落在 0 到 1 之间才能表示"放多少进来"，而候选记忆是一个内容值，用 `tanh` 可以取正也可以取负，表示"往记忆里加什么、减什么"。两个激活函数的取值区间不同，作用也不同。

### 记忆细胞的存储作用与更新公式

第三个是记忆细胞，也叫细胞状态。写代码的时候用 `C` 来表示这个细胞，用 `H` 来表示隐藏状态，这两个变量名要知道来路。

它其实就是那个**长期记忆本**，作用是**存储关键信息**。

你长这么大，人生中总有些转折点：高中选文科还是理科、大学选学校选专业、最后怎么来到这里。这些都可以理解为人生中的转折点，其中有些对你更重要，可以作为记忆留下来。它的关键特点是**能跨很多时间步传递**。

这也正是它能解决长序列记忆问题的原因：**我只记录那些核心的信息，这样在传递的时候就不用传那么多**。

> **提示**：对比一下前面 RNN 为什么处理不了长文本——它记以前的信息记得太多了，不管是重要的还是不重要的它都记。如果你脑子里把从出生第一天到现在事无巨细全记下来，这会儿脑子得炸。你还能记清楚一年前的今天吃的什么饭吗？大多记不住。为什么腊八有人能记住？因为腊八有喝粥的传统，这个日子有特殊意义；换成六月初六、6 月 13 号这种普通日子，前两年那天做了什么，基本是记不住的。**它对你有特殊意义，你才记得住。**

那么这些关键信息是怎么筛出来的？靠的就是下面这行更新公式。

$$C_t = f_t \cdot C_{t-1} + i_t \cdot \tilde{C}_t$$

这个公式为什么叫"更新方式"？因为公式左边是新的细胞状态，右边两项分别是旧的和新的：

- $f_t \cdot C_{t-1}$：**遗忘门门值 × 旧记忆细胞状态**。也就是旧的信息往后传的时候，再忘掉一些。
- $i_t \cdot \tilde{C}_t$：**输入门门值 × 候选记忆**。也就是新的信息挑重点再加一些进来。

前面那两组"看起来没用上"的运算（$f_t \times C_{t-1}$、$i_t \times \tilde{C}_t$）到这里正好全部对上——之前没展开，是因为它们真正展开的位置就在这一行。

> **结论**：细胞状态靠"旧记忆筛一遍、新记忆挑一挑"来解决长序列记忆问题。不能全存，全存就是扯淡，哪能存那么多。

旧记忆为什么会变得不重要？想想自己：上初中或高中时谈的那个对象，当时记录你们之间的事记得还是比较清晰的，甚至刻骨铭心；等到年纪再大一点，结完婚有了小孩，再回忆以前的事，可能都不一定想得起来了，甚至初恋是谁都记不起来。当时觉得很重要的事，随着时间推移也就无所谓了——所以每次往后传的时候，都要用遗忘门门值再筛一遍。

### 输出门与本次隐藏状态的计算

最后一步是输出门。事总得往前走：过了今天还有明天，过了后天还有大后天。

输出门的作用多了**第三个输入源**：除了本次的输入和上一时刻的隐藏状态，还要看**更新后的记忆细胞**。因为要往外送的内容，正是从更新后的细胞状态里挑的。

它决定的事情是：**输出哪些信息**。

类比很直接：你给朋友讲今天发生的事，你会从长期记忆本里挑重要的讲。"昨天有人送了我一辆法拉利"这种事要讲；"早上吃了面包"这种相对来讲没那么重要，暂时不说。

#### 门值公式

$$o_t = \sigma(W_o \cdot [h_{t-1}, x_t] + b_o)$$

还是那套门值公式，只不过下标换成输出门的权重与偏置。$o$ 就是 output 那个单词的首字母。

本次隐藏状态则用它去调制更新后的细胞状态：

$$h_t = o_t \cdot \tanh(C_t)$$

念一遍：本次隐藏状态等于**输出门门值乘以 `tanh` 激活函数处理后的新的记忆细胞状态**——括号里处理的就是 $C_t$，也就是刚才更新完的那个新记忆细胞状态。

#### 为什么每次都一定有本次隐藏状态

这里要接上前面 RNN 讲过的模型分类：按输入输出的对应关系分为 N vs N、N vs 1、1 vs N、N vs M。

拿 N vs 1 来讲：给你 N 个输入、只输出一个结果，那就只需要最后一次输出。也就是说，**不一定每次都有 Y，但 100% 每次都有本次的隐藏状态**。

```text
                 +-----------------------------+
   x_t  -------> |           遗忘门            | <------- h_{t-1}
   h_{t-1} ----> |  f_t = sigmoid(Wf·[h,x]+bf) |
                 +-----------------------------+
                                 |
                                 v
                 +-----------------------------+
   x_t  -------> |           输入门            | <------- h_{t-1}
   h_{t-1} ----> |  i_t = sigmoid(Wi·[h,x]+bi) |
                 +-----------------------------+
                                 |
                                 v
                 +-----------------------------+
                 |          细胞状态           |
                 |  C_t = f_t·C_{t-1} + i_t·C~t|
                 +-----------------------------+
                                 |
                                 v
                 +-----------------------------+
   x_t  -------> |           输出门            | <------- h_{t-1}
   h_{t-1} ----> |  o_t = sigmoid(Wo·[h,x]+bo) |
                 |  h_t = o_t · tanh(C_t)      |
                 +-----------------------------+
                                 |
                                 v
                          h_t（本次隐藏状态）
```

读图方式：三个门的门值都由同一组输入（本次输入 `x_t` 与上一时刻隐藏状态 `h_{t-1}`）算出；两个门值在细胞状态那一行汇合完成"旧减新增"的更新；输出门再拿更新后的 $C_t$ 去生成本次隐藏状态 $h_t$。

这就是各个公式到底是什么意思。

## Day03-11.Bi-LSTM模型_介绍(理解)
> 对应分集：P46 | 原始标题：《Day03-11.Bi-LSTM模型_介绍(理解)》

接下来讲双向 Bi-LSTM。什么叫双向？就两句话。

第一，它**没有改变 LSTM 本身的任何结构**——还是遗忘门、输入门、细胞状态、输出门，还是三门加一状态，一点没动。第二，它做两次。

有人会问：那它跟之前有啥区别？区别就在这个「两次」上：`我爱中国` 这句话，你先切词，切成几个词？我、爱、中国，三个。然后从左到右做一次 LSTM，从右到左再做一次 LSTM，把两次得到的张量结果**拼接**起来。讲完了。

> **结论**：Bi-LSTM 不新增任何门、任何状态，它只是把同一个 LSTM 正反各跑一遍，再把两个方向的输出拼在一起，让每个位置的表示同时看到左边和右边的信息。代价是计算量翻倍。

### 两次传递的方向与顺序

既然结构不动，那全部的理解难点就落在「两次分别是怎么传的」上。我用一个例子把它钉死。

假设序列是 `我爱中国`，切完词是 `我`、`爱`、`中国`。上面一条通路从左往右走，依次传入 `我`、`爱`、`中国`，走一步出一个隐藏状态，最后得到三个位置的隐藏状态。

那下面这条通路呢？**反着传**。

反着传的意思是：第一次先传 `中国`，得到一个状态，记作 `R0`——`R` 是 right，右的意思，`R0` 就是反向通路的第 0 个输出。传完 `中国` 再传谁？传 `爱`。再传一个 `我`，得到 `R2`。

这里必须先把一个最容易记反的地方说清楚，不然一会儿拼不起来。

有人一看「从右往左」，脑子里就自动摆成 `中国爱我`：`中国` 就是我原来位置 0 的输入，`我` 是我原来位置 2 的输入。**不对**。

从右往左传，传的第一组是 `中国`，第二个是 `爱`，第三个是 `我`；但这三个词各自落在哪个位置上，是**不动的**。`我` 始终在位置 0，`爱` 在位置 1，`中国` 在位置 2。反向通路改变的只是**传参的顺序**，不是词的顺序。

```text
文本（位置固定）:   [ 0:我 ]      [ 1:爱 ]      [ 2:中国 ]

正向通路  L→R:      我      ──►   爱      ──►   中国
                    L0            L1            L2

反向通路  R→L:      我      ◄──   爱      ◄──   中国
                    R2            R1            R0
                    ▲             ▲             ▲
              先传中国,再传爱,最后一个才传我（传参顺序相反）

最终输出 = 同位置拼接:
  位置0  我    =  concat(L0, R2)    ← 必须都是「针对我」处理后的结果
  位置1  爱    =  concat(L1, R1)
  位置2  中国  =  concat(L2, R0)
```

读图说明：两条通路共用同一套词、同一套位置编号，唯一不同的是喂进去的先后次序；拼接发生在**同一个位置**上，位置 0 拿到的必须是「正向看 `我` 得到的 L0」和「反向看 `我` 得到的 R2」。

> **易错点**：反向通路的 `R0` 对应的是序列**最后**那个词。所以如果你把反向输出按 `R0、R1、R2` 的顺序直接贴到位置 `0、1、2` 上，就变成了「中国」和「我」对齐——那这个拼接就彻底没有意义了，等于白做一次。

### 位置对齐与输出向量拼接

把顺序摆对之后，剩下的就是一次拼接动作。

正向在位置 0 得到的向量是 `L0`，反向在同一个位置 0 得到的向量是 `R2`。这两个向量的「出身」是一样的——都是针对 `我` 这个词算出来的表示，一个从左边看它，一个从右边看它。把它们拼起来，才叫有意义。

拼接的结果长度是两个向量长度之和。举个具体数字：如果单向输出的维度是 3，那么位置 0 的最终输出就是「你的 3」拼上「我的 3」，变成 6。三个位置都是这么干：

- 位置 0：`concat(L0, R2)`，长度为 3 + 3 = 6；
- 位置 1：`concat(L1, R1)`，长度为 3 + 3 = 6；
- 位置 2：`concat(L2, R0)`，长度为 3 + 3 = 6。

> **定义**：Bi-LSTM 在时刻 $t$ 的输出是正向隐状态与反向隐状态的拼接

$$h_t = \left[ \overrightarrow{h_t} \; ; \; \overleftarrow{h_t} \right]$$

其维度为 $2 \times \text{hidden\_size}$。

这么一来，每个位置的输出向量同时包含了它左边所有的信息和右边所有的信息，也就有了完整的上下文视角。这正是 Bi-LSTM 比单向 LSTM 更强大的地方。

对应的弊端也很明确：**双向的参数和计算复杂度都会随之增加一倍**，因为你实实在在做了两次。

> **提示**：这里的「一倍」是指参数量与浮点运算量相对于同样 `hidden_size` 的单向 LSTM 翻番——反方向的 LSTM 有自己独立的一套权重矩阵，不与正向共享。

### 双向的代价与适用判断

参数和计算量翻倍这件事，换个角度看其实是「多买了一套权重」。正向通路和反向通路各有自己的 $W_f, W_i, W_o, W_c$ 那一套矩阵，把参数相加，再乘上迭代轮数，训练成本自然就上去了。

所以它并不是无脑上双向就一定更好。要不要做双向，取决于任务本身能不能看到完整句子：

| 判断依据 | 适合双向 | 只适合单向 |
| --- | --- | --- |
| 输入是否一次性给全 | 整句已经拿到手，左右都能看 | 数据是流式到来，未来还没发生 |
| 典型任务 | 文本分类、命名实体识别、句子级情感分析 | 语言模型逐词预测、实时流式标注 |
| 代价 | 参数与算力翻倍 | 省一半算力，但看不到右文 |

一句话，双向的前提是「右边的信息本来就存在，只是你刚才没去看」。如果右边的东西还没出现，那就没有第二遍可做。

### 关于方向的两个混淆点

讲到这里，还有两处容易绕晕的地方，我一次说清。

第一处是**从右往左的文本顺序**。有些人习惯在反向通路下面也标一句「我爱中国」，这其实也是对的。为什么？因为文本本来就是 `我`、`爱`、`中国`，只不过这一次不是从左往右读，而是从右往左读。所以你得**倒着传**：传 `中国`、传 `爱`、传 `我`。顺序不变，方向变了。

> **结论**：文本顺序永远不变，变的只是传入的先后。你要是把词的顺序也调了，那就完蛋了——`中国`、`爱`、`我` 一挪位置，一会儿拼接时中国跟中国就对不上，这一步就白做了。

第二处是**为什么要拼在同一位置**。你可以反过来想：如果位置 0 放的是正向看 `我` 的结果，而它对面放的是反向看 `中国` 的结果，那拼出来的向量描述的是两个不同的词，后面的分类、标注拿它做决策就是在用错误的信息。

所以判断标准只有一条：拼接的两半，必须都是**针对同一个词处理后的结果**。这一点不标清楚，光看图很容易晕。

> **提示**：想看清更细的动作，可以把这段说明连同「BiLSTM、两次传递」一起丢给豆包这类助手，让它把这两次传递逐步展开给你看。不要去纠结书上那些符号，把两次传递动作各走一遍，比读十遍定义都管用。

### 本讲提到的题目

课上留了一道选择题：下列 LSTM 的调用写法，ABCD 哪一行错了、为什么错？

按本讲的调用规则，传入 `H0` 与 `C0` 时必须**以元组的形式包裹成第二个位置参数**：`lstm(input, (H0, C0))`。

**答案：D 错。** 因为 D 没有加小括号，把 `H0` 和 `C0` 当成两个独立的参数传了进去。`nn.LSTM` 只需要两个位置参数（输入张量、隐状态元组），你给它三个，数量对不上，直接报名称错误。这就是「必须以元组形式包裹」这句话的直接后果。

## Day03-12.LSTM模型_代码实现(掌握)
> 对应分集：P47 | 原始标题：《Day03-12.LSTM模型_代码实现(掌握)》

接下来讲 LSTM 的 API。你会发现 LSTM 的 API 较之于传统的 RNN，就多了一个东西——多了一个 `C0`。

`C0` 跟隐藏状态是一模一样的：维度一样、形状一样、传的位置也一样。以前我们是不是「本次的输入 + 上次的隐藏状态」就够了？现在除了上次的隐藏状态，还得把上次的**记忆细胞**一起传进来；它返回给你的，也是本次的隐藏状态和本次更新后的记忆细胞。就这一步，其他都一模一样。

> **结论**：从 `nn.RNN` 换到 `nn.LSTM`，模型构建的参数签名完全不变，变的只有前向调用——输入要带上 `(h0, c0)` 这个元组，返回值多一个细胞状态。原理讲了一整讲，落到 API 上只多这一个 `C0`。

### 本讲的案例与工程准备

我们新建一个脚本文件，名字叫 `LSTM模型_LSTM的API演示`，案例内容就是「演示 LSTM 的入门代码」。写之前先把 LSTM 的简介摆在前面：它叫长短时记忆结构（Long Short-Term Memory），解决的是传统 RNN 的一个弊端——**处理长序列数据效果差**。

注意这句话的措辞：不是不能处理，是**效果差**。

我打个比方。我让你算一组数：$13 \times 26 + 28$，再除以 2，再加几乘几、除几……算完我最后问你结果等于几，你张嘴就给我来个 3。它不是不会算，它是算得不准——那这有什么用？长序列上的 RNN 就是这样，前面的信息它能碰到，但等到用的时候已经记混了。

组成还是那句老话：**三门一状态**。遗忘门、输入门、细胞状态、输出门。这里先把优缺点一起写掉。

**优点**：

1. 能解决长时依赖问题，也就是长数据依赖；
2. 缓解梯度消失和梯度爆炸，相对来讲训练更稳定；
3. 能抓取更复杂的特征。

**缺点**：

1. 计算慢，消耗资源大。怎么看这一条？传统 RNN 里边就一个黄框（神经网络），这玩意儿里边几个黄框？1、2、3、4——四个。黄框越多，消耗的资源肯定越大。顺便剧透一句：一会儿要讲的 GRU 是不是也四个？不是，它把这四个合成仨。
2. 调参相对较难，因为参数太多。
3. 可解释性稍差。RNN 更好解释一点——上次的隐藏状态加上本次输入，直接得到结果；LSTM 中间还夹着细胞状态，内部怎么工作的虽然后面都会解释，但较之 RNN，相对来讲可解释性是要差一些的。

### LSTM 构造函数与四个参数

先导包，`torch` 肯定要，再 `import torch.nn as nn`，这是免不了的。

然后定义函数 `LSTM_demo()`，函数体第一句话一定是实例化——创建 LSTM 模型对象：

```python
import torch
import torch.nn as nn


def LSTM_demo():
    # 1. 创建 LSTM 模型对象
    lstm = nn.LSTM(input_size=561, hidden_size=135, num_layers=236, bidirectional=False)

    # 2. 构建输入张量：(序列长度, 批次大小, 词向量维度)
    input = torch.randn(4, 3, 5)

    # 3. 初始化隐藏状态 h0 与细胞状态 c0
    h0 = torch.randn(1, 3, 6)
    c0 = torch.randn(1, 3, 6)

    # 4. 模型计算：写法 1 —— 手动传入 (h0, c0)
    output, (hn, cn) = lstm(input, (h0, c0))

    # 5. 打印结果
    print('output:', output, output.shape)
    print('hn:', hn, hn.shape)
    print('cn:', cn, cn.shape)
```

四个参数一个个对着看。

第一个 `input_size`，是词向量的维度，也就是输入的维度。这个数我为什么写 561？561 你们不认识吗？《士兵突击》里边有个人就叫 561，所以我这个数就是拿他的名字写的，特别好记。你写多少都行，这里只要求「跟你的词向量维度对得上」。

第二个 `hidden_size`，是隐藏层的维度，其实就是输出的维度。

第三个 `num_layers`，是 LSTM 隐藏层的层数。

第四个 `bidirectional`，是否双向。写 `False` 就是单向；写 `True` 就是双向，会帮你多算一次。

> **易错点**：`bidirectional=True` 之后，`hn` 和 `cn` 的第一维不再是 `num_layers`，而是 `num_layers * 2`——因为它要把两个方向的最终状态都还给你。上面这套形状推导是在单向前提下做的。

### 输入张量与隐状态形状推导

第二步构建输入张量 `torch.randn(4, 3, 5)`。这三个数分别是什么？

- 参 1 是**句子长度**，`sequence_length`，也就是时间步数，写 4；
- 参 2 是**批次大小**，`batch_size`，写 3；
- 参 3 是词向量的维度，也就是 `input_size` 那个位置。

> **提示**：文档里管参 3 叫「词向量维度」，但在具体网络里，它对应的就是每一个时间步喂进去的特征长度，理解成「输入维度」更不容易绕。只有参 3 和构造函数里的 `input_size` 对上，这一步才不会报错。

第三步初始化隐藏状态和细胞状态。`h0` 写 `torch.randn(1, 3, 6)`，这三个数又是怎么来的？

- 参 1 是 LSTM 的层数，也就是 `num_layers`。上面我们把它设成了 1，这里就写 1。
- 参 2 是批次大小，跟上面保持一致，是 3。
- 参 3 是隐藏层的维度，也就是输出维度，上面 `hidden_size` 是 6，这里就写 6。

所以才是 `1 3 6`。**`c0` 跟 `h0` 完全一样**，一模一样地写一份 `torch.randn(1, 3, 6)`。

```text
input  : (4, 3, 5)   = (序列长度, 批次大小, 输入维度)     ← input_size 要等于 5 才不报错
h0     : (1, 3, 6)   = (层数,     批次大小, 隐藏维度)
c0     : (1, 3, 6)   = 与 h0 完全一致
                │
                ▼  lstm(input, (h0, c0))
output : (4, 3, 6)   = 每个时间步的输出（隐藏状态）
hn     : (1, 3, 6)   = 最后一个时间步的隐藏状态
cn     : (1, 3, 6)   = 最后一个时间步的细胞状态
```

读图说明：输入和隐状态除了「时间步」这一维，其余两维（批次、特征维度）都严格对齐；输出的 `output` 保留了全部时间步，而 `hn`、`cn` 只留最后一个时间步。

### 前向调用的两种写法与元组包裹

第四步是模型计算，有两种写法。

**写法 1**：手动传入 `h0` 和 `c0`。

```python
    # 4. 模型计算：写法 1 —— 手动传入 (h0, c0)
    output, (hn, cn) = lstm(input, (h0, c0))
```

**写法 2**：不传 `h0` 和 `c0`。

```python
    # 4. 模型计算：写法 2 —— 不传，由底层自动生成全零隐状态
    output, (hn, cn) = lstm(input)
```

先说写法 1 的参数与返回值，一个个解释。

实参列表：

- 参 1 是 `input`，本次的输入张量；
- 参 2 是 `(h0, c0)`，**隐藏状态和细胞状态的元组形式**。

返回值：

- 返回值 1 是 `output`，本次的输出结果，形状 `(4, 3, 6)`；
- 返回值 2 是一个二元组 `(hn, cn)`，分别是**最后一个时间步**的隐藏状态和细胞状态，形状都是 `(1, 3, 6)`。

为什么强调「最后一个时间步」？因为 `output` 里边装的是每个时间步的输出，而最后那个时间步的结果，是把前面所有信息都滚过一遍之后得到的状态。所以它和最终的隐藏状态必然是同一个东西。

> **易错点**：`(h0, c0)` 必须整体当作一个参数传进去，小括号不能少。少了它，`lstm` 收到的就不是两个位置参数，而是三个：`input`、`h0`、`c0`——参数个数对不上，直接报错。接收返回值时也一样，`output, (hn, cn) = ...` 这一行的小括号是解包用的，同样不能省。两侧都不加，也一样不 OK。

这个「元组包裹」的规矩跟我们前面用的 RNN 是一个思路：把「上一时刻的隐状态内容」作为一个整体递进去。想通了这一层，就会发现原理讲得再多，API 上真的只多一个 `C0`。

### 实测输出与不传隐状态的行为

右键跑写法 1，输出是：

```text
output: 4 3 6
hn:     1 3 6
cn:     1 3 6
```

把三行形状对着看：`output` 是 `4 3 6`，`hn` 和 `cn` 都是 `1 3 6`。

这里有一个必须自己动手验证一遍的现象：`output` 里**最后一个时间步**的输出，跟下面返回的 `hn` 是一模一样的。因为 `hn` 定义上就是最后一步的隐藏状态，两者本来就该相等。而 `cn` 不一样——记忆细胞里记的信息更多，它很可能挑重点去做记忆，所以不必等于 `output` 的最后一步。

接下来换成写法 2 做对比：接收方式不变，但调用里不写 `h0`、`c0`，直接 `lstm(input)`。先猜一下会怎样——报错？不报错。

不报错就说明底层替我们生成了一个隐状态。生成的是什么？**全零**的 `h0` 和 `c0`。跑出来的形状依旧是 `4 3 6`、`1 3 6`、`1 3 6`，数值上跟手动传的版本也一致（因为 `randn` 的初始值和全零在第一步的效果差别被后续计算迅速覆盖掉了）。

> **定义**：`h0` 是上一时刻的隐藏状态，`c0` 是上一时刻的细胞状态。序列的第一个时间步没有「上一时刻」，所以不传时底层自动创建一个全零的初始状态来占位。

这也就解释了为什么写法 2 可以省略。不过课上我留着写法 1 反复演示，就是因为元组包裹这个坑必须踩过一遍才记得住。顺便演示三种错误写法：

```python
    lstm(input, h0, c0)             # 错：变成三个位置参数
    output, hn, cn = lstm(input)    # 错：返回值解包没按 (hn, cn) 的嵌套结构
    output, hn, cn = lstm(input, h0, c0)   # 错：都不加小括号，照样不 OK
```

写法对不对，就看你是不是老老实实以元组的形式把两个状态包在一起。

### 结构原理回顾与优缺点对比

再往下看一眼它的结构总结。LSTM 就是三门一状态：遗忘、输入、输出三个门，加一个细胞状态。它能更好地捕捉长序列之间的语义关联，缓解梯度消失或爆炸。三个门的分工是这样：

- **遗忘门**决定对以前的信息忘记多少；
- **输入门**决定对新的信息记住多少；
- **细胞状态**是长期记忆本，负责记录大事件；
- **输出门**决定把细胞状态里的哪些信息往外传递。

说白了，LSTM 全称 long short-term memory，与其叫「长短时记忆结构」，不如直接理解成**有选择性的记忆**：某些内容你记了很久，但到下一个时间步它不再重要了，那就被你舍弃掉，这就是「长短时」。

幻灯片上对优缺点的表述也值得记一下：优点是能有效缓解长序列上出现的梯度爆炸或消失问题——**注意只是缓解，不能完全解决**，但在长序列这块比传统 RNN 要好。缺点是内部结构相对复杂，算力要求比 RNN 多，所以在同等算力下训练效率比 RNN 要慢。

我拿车给你比一下：这车性能很牛，但它费油。同样 40 升油，省油的车能跑得更远一点；你这车费油，能跑的路程就短一点。那怎么办？要用 LSTM，就把算力提上去，算力那都不叫事。这就跟买车一样——买十万块车的人会经常算油耗，买几百万车的人虽然油耗很高，但他们不在乎这个油耗。

> **结论**：LSTM 的价值在于「长序列上比 RNN 准」，代价是「同样算力下比 RNN 慢」。这不是设计缺陷，而是用算力换记忆能力的等价交换。

### 本讲提到的题目

课上留了一道选择题：LSTM 的几种调用写法列出 A、B、C、D 四行，问哪一行错了、为什么错。**答案：D 错，D 错在没有加小括号。**

依据就在前面讲的调用规则里：`nn.LSTM` 的位置参数只有两个——输入张量和隐状态元组。D 把 `h0`、`c0` 拆开写成两个独立参数，模型收到的就是三个位置参数，它不认识第三个，直接报错。要么传两个（`input` 加上包好的 `(h0, c0)`），要么传一个（只给 `input`）——就是不能传三个。

## Day03-13.GRU模型_原理图解(掌握)
> 对应分集：P48 | 原始标题：《Day03-13.GRU模型_原理图解(掌握)》

接下来讲 GRU 模型。同样从四个点讲起：介绍、内部结构、API、优缺点。

在正式讲之前要先说一句话：**为什么会有 GRU？** 原因就是为了解决 LSTM 内部结构复杂的问题，于是才有了它。

我问你个问题：LSTM 里的神经网络，就是那些黄框，有几个？四个。那我再问：如果我能把它从四个压缩成三个，甚至压缩成两个，算不算成功？如果功能给你类似的，那当然算成功。

所以我们把它从四个压缩成了三个——不是两个，是三个。这就是 GRU。

> **结论**：GRU 的定位非常清楚，它就是奔着「简化 LSTM 的内部结构」去的：功能对标 LSTM，结构比 LSTM 简单，但比 RNN 复杂。

### 门控循环单元的概念与结构特点

GRU 被称为**门控循环单元结构**。把它拆开看：第一个词 `Gated`，门控；第二个词 `Recurrent`，循环；第三个词 `Unit`，单元。所以叫门控循环单元结构。

它是传统 RNN 的变体，同 LSTM 一样能够有效捕捉长序列之间的语义关联，缓解梯度消失和梯度爆炸。有人可能会嘀咕：等会儿，这功能不就是 LSTM 的功能吗？没错，功能是一样的，区别在于——它比 LSTM 简单，比 RNN 复杂。

RNN 里边的黄框有几个？就一个。顺着这个想下去，其实有个很自然的推演：如果哪天出现一种架构，也是「一个神经网络」就能把事全搞定，那以后还学 LSTM、GRU 吗？学还是要学，但可能就不会花这么长时间了，三四分钟带过，大概念叨一下是啥玩意，了解一下就完事，直接快速刷过，学最新的。一定是这样。

> **提示**：RNN → LSTM → GRU 这条线，本质是「在记忆能力和结构复杂度之间反复找平衡」。GRU 是往「更轻」的方向走了一步，这也是它在工业界仍然常见的原因。

### 三个层与两个门

从结构上看，GRU 里边的层有几个？三个：输入层、隐藏层、输出层。

你要这么说的话，它是不是又回到了 RNN 那个状态？确实是。所以同 RNN 一样，每个时间步有两个输入，每个时间步也有两个输出。

```text
GRU 整体结构（与 RNN 同构，内部换成两个门）

   输入层            隐藏层（门控）              输出层
  ┌───────┐        ┌───────────────┐        ┌───────┐
  │  x_t  │───────►│  重置门  R_t  │───────►│  h_t  │
  └───────┘        │  更新门  Z_t  │        └───────┘
                   └───────────────┘
                          ▲
                   ┌──────┴──────┐
                   │  h_{t-1}    │  上一时刻隐藏状态（这里同时承担记忆的角色）
                   └─────────────┘
```

读图说明：每个时间步吃进「上一时刻隐藏状态」和「本次输入」两样东西，产出「本次隐藏状态」一样东西——和 RNN 完全一样的输入输出形式，只是中间多了一道门控调节。

它内部只出两个门：一个叫**更新门**，一个叫**重置门**。

我们先把公式摆在纸面上，$R_t$ 是重置门，$Z_t$ 是更新门：

$$R_t = \sigma(W_r \cdot [h_{t-1}, x_t])$$

$$Z_t = \sigma(W_z \cdot [h_{t-1}, x_t])$$

看一下这两个式子的构造：最外边还是 $\sigma$，也就是 sigmoid 激活函数；括号里边是权重矩阵乘上「上一时刻隐藏状态」和「本次的输入」的拼接。$h_{t-1}$ 是上一时刻隐藏层的状态，$x_t$ 是本次的输入。

有没有发现思路是一样的？连符号习惯都没换。真正的差别落到候选状态和最终融合上：

$$\tilde{h}_t = \tanh(W \cdot [R_t \odot h_{t-1}, x_t])$$

$$h_t = (1 - Z_t) \odot h_{t-1} + Z_t \odot \tilde{h}_t$$

那个 $\tilde{h}_t$ 是**候选隐藏状态**，$h_t$ 是最终的隐藏状态。

> **为什么 GRU 没有细胞状态？** 玩 LSTM 的时候它多了一个细胞状态，也就是记忆细胞。写代码的时候你会发现，记忆细胞和隐藏状态的形状、维度长得一模一样。所以有人做了一个尝试：把这两者合并。于是 GRU 里就不再有「细胞状态」这个概念了——它已经被合进了隐藏状态。所以那个候选隐藏状态，其实等价于 LSTM 里的候选记忆细胞；而最终的 $h_t$，等价于 LSTM 里的 $C_t$，也就是最终的记忆细胞，只不过它同时承担了对外输出的职责。

### 隐藏状态承担记忆角色

先说这个隐藏状态。它是存**关键信息**的，相当于上面那张图里说的「记忆本」，也就是长期记忆本，跟 LSTM 的细胞状态是同一个角色，但比它更简单。

这「更简单」到底简单在哪？用记账打个比方。

LSTM 那套，相当于你们家每个月**手动记账**：拿个本子，在纸上写你的支出、收入各是多少。你想算某一项支出合计，本子可不会帮你自动算——你还得自己掏计算器再算一遍。

GRU 这个隐藏状态就好比现在的**记账 App**：你消费了什么，甚至可以跟你的某些软件关联，你花了多少钱、对方商铺属于什么类型，它自动帮你记账，帮你把这个月的交通出行花了多少、吃住花了多少、买衣服花了多少、交际花了多少、其他支出花了多少统计得清清楚楚。

这就是「更智能一些」的含义：手动记账和自动记账都能把账记下来，但后者在你需要的时候直接给你结果。所以它不是把记忆扔了，而是把记忆的载体和对外输出的载体合成了一件事。

### 重置门与更新门的公式与结论

#### 重置门

**重置门决定要不要擦除旧记忆。** 它有点像 LSTM 里面的遗忘门。

数值结论上：重置门门值接近 1，表示旧记忆保留、接着用；接近 0，表示少保留旧记忆、多加新记忆，相当于把记忆清洗一遍。

公式就是前面的 $R_t$：

$$R_t = \sigma(W_r \cdot [h_{t-1}, x_t])$$

> **提示**：这里外边一律写 sigmoid，不用纠结「为什么不是 tanh」——门是拿来当「开关/比例」用的，取值落在 $(0, 1)$ 才好当权重用；tanh 的输出范围是 $[-1, 1]$，更适合拿去当候选内容。

#### 更新门

**更新门决定新旧记忆怎么融合**——保留多少新的、保留多少旧的，也就是这个比例是多少。

这不就跟家庭财政支出一样吗？固定的资金存下来多少，拿多少钱去做理财。比如说拿家庭总收入的 30% 去做理财，剩下的当什么什么基金。结婚前你月光其实还可以，结婚以后就不能再月光了，万一小孩有个什么情况，你总不可能满世界借钱去。

数值结论上：更新门门值越接近 1，越少保留旧记忆、越多加入新记忆；越接近 0，越多保留旧记忆、越少添加新记忆。

公式是前面的 $Z_t$：

$$Z_t = \sigma(W_z \cdot [h_{t-1}, x_t])$$

> **易错点**：重置门和更新门的结论方向看一眼容易记反。抓一个锚点就不会错——**更新门 $Z_t$ 是「新的权重」**，它出现在 $Z_t \cdot \tilde{h}_t$ 这一项上，所以 $Z_t$ 越接近 1 就越偏新东西；重置门 $R_t$ 作用在旧记忆上，$R_t$ 越接近 1 就越把旧记忆原样留下。

#### 候选隐藏状态

**候选隐藏状态是生成新记忆候选。** 它有点像 LSTM 里面的候选记忆，是同一个角色。

它的公式里有两处要看清：

$$\tilde{h}_t = \tanh(W \cdot [R_t \odot h_{t-1}, x_t])$$

用大白话说这个式子：先把旧记忆用重置门筛选一遍——$R_t$ 乘上 $h_{t-1}$，就相当于按比例保留旧记忆；然后把它和新的信息 $x_t$ 混合到一起；最后通过一个 tanh 激活函数，把数值压缩到 $\tanh$ 的范围 $(-1, 1)$ 之内，生成新记忆候选。

#### 最终隐藏状态

**最终隐藏状态就是最终的记忆状态**，它完成两件事：新旧记忆融合，然后定稿存储——定稿了就不再动。

公式与大白话解释：

$$h_t = (1 - Z_t) \odot h_{t-1} + Z_t \odot \tilde{h}_t$$

最终融合后的新记忆，等于「$1$ 减去更新门门值」乘上一次的隐藏状态（也就是 LSTM 里那个记忆细胞的位置），再加上「更新门门值」乘上新记忆候选。

说白了，就是更新门决定了将来要更多之前的旧信息，还是更多现在的新信息；融合之后得到的 $h_t$，就是要往下传递的新记忆。

它其实可以理解为 LSTM 里的 $C_t$——因为记忆细胞和隐藏状态的动作、形状基本上都一样，所以在这里直接合二为一了。

接着看边界值：$Z_t$ 接近 1，少保留旧的、多加新的；$Z_t$ 接近 0，多保留旧的、少添加新的。极端一点，$Z_t = 0$ 就说明这次不更新，完全用以前的；$Z_t = 1$ 就是完全更新，之前的东西一概不要。

```text
GRU 单个时间步的数据流

  h_{t-1} ──┬──► R_t = sigmoid(W_r * [h_{t-1}, x_t])
            │            │
            │            ▼
            │      R_t (*) h_{t-1} ──┐
            │                        ├──► tanh ──► h_t 候选 ──┐
  x_t  ─────┴──► Z_t = sigmoid(W_z * [h_{t-1}, x_t])          │
                                                              ▼
  h_{t-1} ─────────────────────► (1 - Z_t) (*) h_{t-1} ──► 加权求和 ──► h_t
  h_t 候选 ─────────────────────►      Z_t  (*) h_t 候选 ──┘

  说明：重置门先把旧记忆筛一遍，拼上本次输入后过 tanh 得到新记忆候选；
        更新门同时充当两个互补权重，(1 - Z_t) 走旧记忆，Z_t 走新候选，相加得到 h_t。
```

读图说明：两条分支并行计算门值——重置门先去筛旧记忆、拼上新输入、过 tanh 得到候选；更新门则作为一对互补权重 $(1 - Z_t)$ 与 $Z_t$，把「旧记忆」和「新候选」按比例加起来，得到这一时刻的 $h_t$。

### GRU 与 LSTM 的对比

为什么要 GRU？一句话：简化。

LSTM 靠**三个门加记忆细胞**解决长序列的记忆问题，但结构复杂、计算慢。GRU 想的是：能不能简化结构，同时保留「智能记忆」的功能？所谓智能记忆，就是选择性的记忆。

它把 LSTM 的**部分门做了合并**，合并之后变成了更轻量的「记忆管家」。更轻量是什么意思？说白了就是消耗资源少，消耗资源少你自然就训练快。而且关键是——快了之后，那个核心问题的解决能力还在。要是光快、问题没解决，那其实也没太大用。

所以 GRU 的核心就是：**两个门加一个隐藏状态**。其实这个隐藏状态话都不用写——RNN 的时候它本来就一定有。所以真正要记的就是**两个门**。

| 对比项 | LSTM | GRU |
| --- | --- | --- |
| 门的数量 | 三门（遗忘门、输入门、输出门）+ 细胞状态 | 两门（重置门、更新门） |
| 记忆载体 | 隐藏状态 + 细胞状态，两份 | 只有隐藏状态，合二为一 |
| 结构复杂度 | 复杂，训练慢 | 更简单，参数更少，训练更快 |
| 长序列能力 | 能捕捉长序列语义关联，缓解梯度消失/爆炸 | 同样能捕捉、同样只缓解 |
| 资源消耗 | 大（四个神经网络结构） | 更轻量（三个） |

> **结论**：GRU 用「少一个门 + 去掉独立的细胞状态」换来更小的参数量和更快的训练速度，而长序列上的记忆能力基本保住。

### API 与前向写法

翻到 API 那一页，你会惊喜地发现一件事：GRU 的写法跟 RNN 的写法**一模一样**，区别只有一个——把你那个 `RNN` 换成 `GRU`，参数都不带变的。

```python
import torch
import torch.nn as nn

// 与 RNN 的唯一区别：类名从 nn.RNN 换成 nn.GRU
gru = nn.GRU(input_size=561, hidden_size=135, num_layers=236)
```

三个参数一一对应：输入维度、隐藏层维度、隐藏层层数——以前 RNN 是怎么写的，现在就怎么写。前向调用也一样，每个时间步两个输入（上一时刻隐状态 + 本次输入），两个输出（本次输出 + 本次隐状态）：

```python
output, hn = gru(input, h0)   # 注意：没有 c0 了
```

> **提示**：调用 GRU 千万别再顺手补一个 `c0`。GRU 没有细胞状态，它只要一个隐状态——这也是「记忆和输出合二为一」在 API 上的直接体现。

## Day03-14.GRU模型_代码演示(掌握)
> 对应分集：P49 | 原始标题：《Day03-14.GRU模型_代码演示(掌握)》

### 改一个类名就算学会 GRU 了吗

先把话说在前面：把 GRU 跑起来，真的只有一处改动。上一节写 RNN 的时候我们写的是 `nn.RNN`，现在换成 `nn.GRU`，其他一行都不用动。

但如果你以为这样就能下课，那就想得太简单了。代码能跑不等于你会写——该写的注释还是得写，该解释的参数还是得解释，该背下来的结构还是得背下来。所以这一节我们要做的事有两件：一是把 GRU 的简介原样写成笔记，二是完整写一遍 GRU 的调用代码，并且每一步都说得清为什么。

### GRU 是什么：四个词拆开看

先把名字拆开。**门控循环单元（Gated Recurrent Unit，GRU）**，四个词一一对应：

| 中文 | 英文 | 词性 |
| --- | --- | --- |
| 门控 | gated | 有门 |
| 循环 | recurrent | 沿时间步复用同一套参数 |
| 单元 | unit | 一个基本计算块 |

它的定位可以这样记住：一个简化版的智能管家——既能像长短期记忆网络（Long Short-Term Memory，LSTM）那样处理长序列信息，计算上又更简单、更节省资源。具体"简化"在哪里？从四个层换成了三个层。

核心设计思路只有两个门：**重置门（reset gate）** 与 **更新门（update gate）**。你可以把它理解为在 LSTM 的基础上，把部分门做了合并。

> **结论**：RNN → LSTM → GRU 这条线不是"越新越强"，而是"越新越会舍"。GRU 拿掉的是一个门，换来的是更少的计算量。

### 优缺点：它站在一个很尴尬的位置

写笔记的时候优缺点必须连着写，因为这一节的全部价值就在这个"尴尬"上。

优点两条：

1. 和 LSTM 一样，能捕捉长序列的语义关联，并且**有效缓解**梯度消失与梯度爆炸问题。注意措辞，是"缓解"，不是"彻底解决"——这一点后面讲缺点时还会再出现一次。
2. 关于长序列的处理效果优于传统的 RNN；计算复杂度比 LSTM 要小。

> **易错点**：笔记上写优点时，"缓解"两个字千万不要写成"解决"。写错了，后面缺点那一条就自相矛盾了。

尴尬在哪里？长序列效果它比传统 RNN 好，但比 LSTM 弱——如果它比 LSTM 又简单、效果又好，那 LSTM 就没有存在意义了，我们也不用再学 LSTM 了。所以效果上一定是：**LSTM 最好，GRU 次之，RNN 再次之**。计算复杂度上它比 LSTM 小，但比传统 RNN 复杂，同样卡在中间。

缺点也是两条：

1. 不能完全解决梯度消失和爆炸问题；
2. 和 RNN 一样不能并行计算。

第二条才是真正的要害。它意味着在**数据量与模型体量逐步增大**的未来，RNN 系架构会成为关键瓶颈。那后来是怎么解决的？就是 Transformer 那套架构——用注意力机制让它能并行计算，再加上各种工程改良，大模型才像雨后春笋一样冒出来。

顺手把这条技术史的因果链记住：人工智能的起点很早，1950 年图灵就提出了图灵测试，1956 年是公认的人工智能元年，一路算到今天七十来年，可 AI 真正火起来只是近几年的事。原因不是想法突然变好了，而是三项条件同时成熟了：

> **结论**：人工智能 = 数据 + 算法 + 算力，三项的顺序不能变。

### 代码实现：五步走

写代码之前先把思路说清楚，就是我们一直用的那套五步法：

1. 创建 GRU 模型对象；
2. 创建本次输入的数据；
3. 创建初始隐藏状态 $h_0$；
4. 把数据送进模型执行，拿到 `output` 与 `hn`；
5. 打印结果。

```python
# 演示 GRU 代码
import torch
import torch.nn as nn


def gru_demo():
    # 1. 创建 GRU 模型对象
    gru = nn.GRU(input_size=6, hidden_size=5, num_layers=1)
    # 2. 创建输入数据 (seq_len, batch_size, input_size)
    inputs = torch.randn(3, 2, 6)
    # 3. 创建初始隐藏状态 (num_layers, batch_size, hidden_size)
    h0 = torch.zeros(1, 2, 5)
    # 4. 运行 GRU 模型
    output, hn = gru(inputs, h0)
    # 5. 输出结果
    print('GRU 模型 output:', output.shape, output)
    print('GRU 模型 hn:', hn.shape, hn)


if __name__ == '__main__':
    gru_demo()
```

把这段和上一节的 RNN 代码摆在一起看，唯一的区别就是构造函数那一行的类名。所以如果哪次赶时间，复制上一段再改一个名字，代码照样跑得起来。

### 三个参数与两个张量形状

构造 `nn.GRU` 时真正要记住的是三个位置参数：

| 位置 | 参数名 | 含义 | 说明 |
| --- | --- | --- | --- |
| 1 | `input_size` | 输入特征维度 | 实际上就是词向量维度 |
| 2 | `hidden_size` | 隐藏层维度 | 实际上就是输出维度，`output` 最后一维等于它 |
| 3 | `num_layers` | 层数 | 不写时默认是 1 |

参数名如果一时想不起来，不要硬猜，直接把光标放到 `nn.GRU` 上按住 `Ctrl` 点进去，翻到 `__init__`，里面 `input_size`、`hidden_size`、`num_layers` 写得清清楚楚，默认值 `1` 也在那儿。自己翻一次源码，比背十遍都牢。

两个张量的形状必须分清，因为顺序和 RNN 完全一致：

- 输入 `inputs` 的形状是 `(sequence_length, batch_size, input_size)`，也就是 `(序列长度, 批次大小, 输入特征维度)`；
- 初始隐藏状态 `h0` 的形状是 `(num_layers, batch_size, hidden_size)`，也就是 `(层数, 批次大小, 隐藏层维度)`。

> **易错点**：输入张量三个维度里，第一个是序列长度，第二个才是批次大小——不是批次在前。初始隐藏状态的第一个维度是层数，不是序列长度。这两个张量混了，报错信息会很难读。

第一维取值很自由：`h0` 的第一个维度写层数，这里层数是 1，所以写 `1`；写成别的数值也能跑，但要对得上 `num_layers` 的语义。真正卡死的只有最后一维——输入最后一维必须等于 `input_size`，`h0` 最后一维必须等于 `hidden_size`。

### 形状校验：拿上一节的图去核对

代码跑通之后，我们要做一件很多同学会跳过的动作：**回头核对形状**。这里用的数据和上一节 RNN 演示时是同一条思路：`inputs` 给的是 `(3, 2, 6)`，`h0` 给的是 `(1, 2, 5)`，那么

- `output` 应该是 `(3, 2, 5)`：序列长度和批次大小照抄，最后一维换成隐藏层维度；
- `hn` 应该是 `(1, 2, 5)`：层数、批次大小、隐藏层维度。

还有一个更容易被忽略的一致关系：

> **结论**：`output` 的最后一维、`output` 最后一步的隐藏状态、以及 `hn` 的最后一维，三者是同一个数值。也就是说，`hn` 就是把 `output` 里最后一个时间步、最后一层的那份隐藏状态单独拎了出来。

之所以能一眼判断，是因为脑子里得一直挂着那张 "12 个 / 30 个" 的维度示意图。图在脑子里，形状根本不用猜；图不在，就只能靠试。

### 优缺点回顾与总结

GRU 与 LSTM 作用相同：捕捉长序列语义关联、缓解梯度消失与爆炸，效果优于传统 RNN，计算复杂度小于 LSTM；缺点是不能完全解决梯度消失与爆炸，且不能并行运行，体量一大就是瓶颈。

不能并行这件事有个很直观的类比：食堂打饭只有一个窗口，一个人在里面打，早高峰全挤在同一时刻；如果有两个或三个窗口同时开，效率立刻不一样。现在校区里的人数如果乘以十倍，窗口还是那一个，队伍就排不动了。序列模型非要按时间步一个一个算，就是这个"单窗口"。

最后收束到结构上：GRU 的模型结构就两个门，一个重置门、一个更新门。三个门的工作原理在 LSTM 那节的图上已经画清楚了，一定要回头去看图，光看文字没有用。

### 本讲提到的题目

**题 1（单选）**：自然语言处理中，通常哪种循环网络在处理长序列时效果最好？

- A. RNN
- B. LSTM
- C. GRU

答案：**B**。题目只问长序列效果，没有带资源、速度这些约束条件，那一定是 LSTM 最好。完整排序是：LSTM 最好，GRU 次之，传统 RNN 最后。

**题 2（多选）**：下列哪些使用了门控机制？

- A. RNN
- B. LSTM
- C. GRU

答案：**BC**。GRU 全称是 gated recurrent unit，名字里就带着"门控"；LSTM 里有输入门、输出门、遗忘门，也是门控结构。传统 RNN 里没有门，它只有输入层、隐藏层、输出层的划分，"输入层"不是"输入门"，不要把这两个词混为一谈——这是本题最大的陷阱。

**题 3（多选）**：LSTM 里面有哪几种门？

- A. 输入门
- B. 输出门
- C. 遗忘门
- D. 记忆门

答案：**ABC**。LSTM 是"三门一状态"：输入门、输出门、遗忘门，再加上一个记忆细胞（细胞状态）。记忆细胞不是门，它是一个与隐藏状态量级相近的矩阵，负责沿时间步搬运信息，所以没有"记忆门"这个说法——"记忆"这两个字就是用来误导的。写笔记时把"三门一状态"这五个字标出来，这一题不会错第二遍。
