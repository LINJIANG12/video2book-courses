# 无注意力 GRU 解码器的结构与形状推导

编码器那一段收工之后，轮到右边了。这一节要拿下的，是解码器的第一个版本——不带注意力机制的那个。

先提醒一句：解码器这张图上并没有标出每个参数到底是谁对谁，所以别指望照抄，得我们自己把每个位置的名字、每个形状的含义写上去。后面才是具体的代码实现，这一节要做的就是把思路和形状推清楚。

## 图上的颜色约定与输入

先把颜色的约定捡回来，看图的时候靠它分辨"这是数据还是层"：

- 橙色（前面几讲里我一直说成黄色那一片）：向量，也就是张量；
- 蓝色：网络层，也就是神经网络层；
- 绿色：新出现的这一类，是运算/激活这些处理动作。

进图的入口有两个：

- `input`：本次的输入；
- `previous_hidden`：上一时刻的隐藏状态。这个隐藏状态是编码器那边传过来的，还是别的来源，都无所谓——它和 GRU 里的隐藏状态是同一种东西。

> **定义**：这里的"无注意力"指的是解码器只从编码器拿一个固定的中间语义向量 $C$（就是编码器最后一个时间步的隐藏状态），每生成一个法语词都看这同一个 $C$，不存在逐位置变化的 $C_1, C_2, C_3 \dots$。

## 本次输入的形状：为什么是 1×1

关键的问题来了：`input` 进来的时候应该是几个？

> **结论**：解码器的 `input` 是 `(1, 1)`——1 批次、1 个词。

为什么不是 `(1, 6)` 这种整句？因为解码器是**一次只处理一个时间步、只吃一个词**的：它拿"上一个词 + 上一时刻隐藏状态"算"下一个词"，然后把算出来的词当输入再算下一个，一个词一个词地滚下去。整句是一步一步喂进去的，不是一口气塞进去。

## 词嵌入层

`(1, 1)` 进来先过词嵌入层（embedding层）。这个层我们前面说过很多次了：它把索引转成词向量。

进去是 `(1, 1)`，出来必然带上词向量维度：`(1, 1, 256)`。词向量是 256 维，所以形状就在最后一维多出个 256——每个词用 256 个数字表示。

## ReLU 激活

词嵌入之后是一个 `ReLU`（Rectified Linear Unit，修正线性单元）激活函数。

设问一下：激活函数会不会改变形状？不会。`ReLU` 是逐元素做值的映射（把负数压成 0、正数原样保留），它改的是数值，不是结构。所以这里走到哪一步形状都不动：进 `(1, 1, 256)`，出还是 `(1, 1, 256)`。

## 与上一时刻隐藏状态的合并

另一条支路是 `previous_hidden`，形状 `(1, 1, 256)`——1 层、1 批、256 维。

它和当前这一步的表示一起送进 GRU。两个 `(1, 1, 256)` 合起来处理，出来的 `hidden` 依然是 `(1, 1, 256)`：编码器那边也一样，隐藏状态的三个维度由层数、批次、隐藏层维度决定，跟句长没关系，所以它恒定不变。

输出的 `out` 同样还是 `(1, 1, 256)`。

> **易错点**：`out` 是**本次的输出**，不是输入；上面那个 `input` 才是本次的输入。这两个名字在同一张图上，看错一个整条链就串了。

```text
无注意力解码器单步数据流（括号内为形状）：

  input (1, 1)                 previous_hidden (1, 1, 256)
      |                                  |
      v                                  |
  [ nn.Embedding ]  蓝色：网络层          |
      |                                  |
      v                                  |
  out (1, 1, 256)  橙色：向量             |
      |                                  |
      v                                  |
  [ ReLU ]          绿色：激活，形状不变   |
      |                                  |
      v                                  |
  out (1, 1, 256)                        |
      |                                  |
      +---------------> [ nn.GRU ] <------+
                            |
              +-------------+-------------+
              |                           |
              v                           v
        out (1, 1, 256)            hidden (1, 1, 256)
              |
              v
        [ softmax ]  映射成概率
              |
              v
        法语词表 4345 维上的概率分布 -> 取概率最高的那个词
```

读图说明：解码器一个时间步只吃一个词，词先过嵌入层升到 256 维，过激活函数保持形状不变，再和上一时刻的隐藏状态一起送进 GRU；GRU 输出的 256 维向量经 `softmax` 映射成法语词表上的概率分布，概率最高的那个词就是这一步生成的结果，同时新的隐藏状态往下传。

## softmax 与输出词表

最后一个问题是：`out` 是 `(1, 1, 256)`，经过 `softmax` 之后会变成多少？

`softmax` 的职责是**把数值映射成概率**。所以它把 256 维的表示投射到词表维度上，得到的是 4345 维——法语词表的大小。

> **易错点**：这里容易顺手写 2803。2803 是**英语**单词的数量，也就是编码器侧词表的规模；解码器要产出的是**法语**，法语词表是 4345。数字别背错，345 没有别的数——就是 4345。

于是这一步的含义就清楚了：把刚才那个 256 维的词表示，映射成"在 4345 个法语词里，每个词有多大概率"这样的分布。

最终 `output` 输出的是什么？**一个词**——4345 个词里的某一个。我们并不知道是哪一个，所以取的是这里面概率最高的那个词。概率最高的那一个，就是这一步生成的那个词。

## 这一版解码器的定位

把整条链串一遍：输入一个词 → 词嵌入层转成 256 维词向量 → `ReLU` 激活 → 与上一时刻隐藏状态一起进 GRU → 得到本次输出和新的隐藏状态 → `softmax` 映射到 4345 个法语词上的概率 → 取概率最高的词。

也就是说，解码器靠着 GRU 这一套处理，一步步把法语词生成出来。

> **结论**：这一版解码器记作"无 attention（无注意力）"版本。它和后面要做的注意力版本只差一件事——上下文向量的取法：无注意力版全程只用编码器传过来的那一个隐藏状态；注意力版则会逐位置拿到 $C_1, C_2, C_3 \dots$。

接下来写代码的时候，参数的流转和形状的变换就完全按这张图来：每个环节的输入形状、输出形状、谁是层谁是张量，图上都已经标死了。
