# 掩码张量的可视化与自回归可见性

前面几节我们一直在跟矩阵较劲：上三角、下三角、`torch.tril`、`torch.triu`，一个 0、一个 1 来回翻。有位同学看完之后直说了一句：「老师，我看不懂这里边啥意思。」

看不懂是正常的。矩阵本身只是一堆 0 和 1，光盯着数字看，看不出它跟「生成一句话」有什么关系。所以这一节不推导、不写复杂逻辑，我们只做一件事：**把那个 0/1 矩阵画成一张图，用眼睛去看它到底挡住了什么、放行了什么。**

---

## 1 配色规则与两种看法

先把我用的配色约定说清楚，这张图只有两种颜色：

| 颜色 | 取值 | 含义 |
| --- | --- | --- |
| 黄色 | 1 | 被遮盖，看不见 |
| 紫色 | 0 | 不遮挡，能看见 |

> **定义**：掩码张量（mask tensor）是一个与注意力分数矩阵同形状的 0/1 矩阵，用 1 表示该位置被遮盖、0 表示该位置可见。它的作用是在计算注意力权重之前，把不该被看到的位置直接从分数上抹掉。

拿着这张图，有两种读法，两种都要会：

```text
        列 = 我能看到的位置
        ┌───────────────────────────┐
 行 =   │  1 1 1 1 1                │   第 0 个词
 当前写 │  0 1 1 1 1                │   第 1 个词
 的位置 │  0 0 1 1 1                │   第 2 个词
        │  0 0 0 1 1                │   第 3 个词
        │  0 0 0 0 1                │   第 4 个词
        └───────────────────────────┘
             0 = 可见（紫色）    1 = 遮盖（黄色）
```

- **纵着看**：竖着选一行，这一行代表「我现在正在写第几个词」，也就是当前位置；
- **横着看**：横着扫这一行，看的是「站在这个位置上，我能看到哪几个位置」。

我先带你把这句话落到图上。生成第一个词的时候，我在第一行横向看过去，**全是黄色，我这一排啥都看不见**。生成第二个词的时候再横着看，前一个词是紫色的、我能知道，后面的词全是黄色、我一个都不知道。再往下的每一行都是同一个动作。

那么生成最后一个词呢？前面全知道，只有它自己那一个位置是黄色。

> **结论**：这张图的规律一句话就能说完——**在预测当前位置的时候，后面是什么你全部不知道，前面是什么你全部知道。** 这句话就是自注意力在解码器里必须遮住未来位置的全部理由。

## 2 画图的三行代码

现在切进 PyCharm，在原本的测试文件里往下加一段。先新建一个函数，名字写 `demo03_test_mask`，注释写「TODO 3：掩码张量的可视化」。

动手之前先回答我一个问题：刚才我们看的这张图，是二维的还是三维的？

你再数一数那几个中括号就明白了。前面 `demo02` 里出来的那个结果，一堆中括号套着，是三维的；而这个掩码矩阵，只有两层中括号，**是二维的**。

二维这件事很关键，因为它决定了绘图接口怎么传参：既然是二维的，那么 x、y 两个维度就够了，我们不需要做任何降维操作，把矩阵本体丢进去就行。

```python
def demo03_test_mask():
    # 1. 造画布，尺寸 5x5
    plt.figure(figsize=(5, 5))

    # 2. 直接画矩阵
    plt.imshow(subsequent_mask(5))

    # 3. 显示
    plt.show()
```

三行，没有一行需要解释算法。

`plt.figure(figsize=(5, 5))` 是造一块画布，`figsize` 决定画布多大，这里给的是 5 乘 5 英寸。`plt.imshow(...)` 是把一个二维数组按「矩阵」的方式渲染成图像，每个元素对应一个色块。`plt.show()` 把图画出来。

> **提示**：`plt.imshow()` 期望收到的是一份二维数据。上面这段代码里我并没有先把矩阵算出来存成变量再传进去，而是把生成掩码的那个函数调用直接写在括号里——因为这个函数返回的本来就是一个二维张量，形状是 `(5, 5)`，正好是 `imshow` 要的东西。

## 3 让矩阵变大一点

把上面这段跑一遍，你会看到一个 5×5 的色块图。它是对的，但不够好看，因为格子太少，规律虽然看得出来，却不够「具体」。

所以我要改一个地方：把传进去的那个 `size` 从 5 改成 20。

```python
plt.imshow(subsequent_mask(20))
```

这一改，矩阵就从 5 乘 5 变成了 20 乘 20。行数、列数都变多，每个色块变小，**图案变细、变密，同时也变得更清楚**——因为一个 20×20 的矩阵里，黄色区域的边界走向是连续铺开的，一眼就能看出它是一条斜着的分界线。

上面那个 5×5 的图还像是在数格子，这个 20×20 的图才是真正能看出形状的那一张。课件上用的就是这个尺寸。

## 4 逐步读图：每一行能看到什么

图放大之后，我们一行一行过一遍。约定不变：横着是「我能看到哪几个位置」，竖着是「我现在写的是第几个词」。

**第 0 行**（生成第 0 个词）：横向整行全黄。这是最反直觉的一行——连它自己在内，它谁也看不见，因为在这个位置上还没有任何「过去」可供参考。

**第 1 行**（生成第 1 个词）：横向只有最左边一个格子是紫的，其余全黄。第 0 个词我看到了，第 1 个词自己、以及后面所有的词，都看不到。

**第 2 行、第 3 行**：同样的动作往前推——前面的词我都知道，后面的词我不知道。紫色区域的宽度一行比一行宽，每次多出一个。

**第 4 行**（生成最后一个词）：横向看过去，前面全是紫色，只有它自己那一格是黄的。

```text
生成第 0 个词   [黄][黄][黄][黄][黄]     前无历史，什么都看不到
生成第 1 个词   [紫][黄][黄][黄][黄]     只看得到第 0 个词
生成第 2 个词   [紫][紫][黄][黄][黄]     看得到第 0、1 个词
生成第 3 个词   [紫][紫][紫][黄][黄]     看得到第 0、1、2 个词
生成第 4 个词   [紫][紫][紫][紫][黄]     前面全看得到，自己那一格仍遮住
```

读图：竖着是「我在写第几个词」，横着是「这个位置上哪些词对我是可见的」。黄色区域整体是一个上三角——它的上边界每往下一行就右移一格，所以行号越大，可用的历史越长，紫色区域越宽。

> **易错点**：不要把它读成「第 0 行是第一个词的信息」。纵向的索引是**当前正在生成的位置**，横向的位置才是**被参考的历史**。同一张图横读与竖读的含义不同，横读是「能看哪些位置」，竖读是「现在写的是哪个位置」。

我讲到这里你可能会有个疑问：图里被遮住的位置，到底是被谁遮住的？答案是——**遮住的部分是你自己赋予含义的**。掩码张量只负责表达「这里遮、那里不遮」，遮住之后在那个位置上权重接近 0、从而看不见对应的信息，这套动作要靠后面 `masked_fill` 那一套函数去落实。这一节我们只把「遮哪儿」看清楚，「怎么遮」是下一节的事。

> **结论**：掩码张量的可视化本质上就是一次矩阵渲染：造画布、`imshow` 这份二维掩码、`show`。它的价值不在代码，而在于把「未来不可见」这条抽象规则变成一张能直接看的图。
