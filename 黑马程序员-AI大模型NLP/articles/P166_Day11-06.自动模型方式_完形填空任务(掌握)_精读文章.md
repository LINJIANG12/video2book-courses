# 用 AutoModelForMaskedLM 做中文完形填空：掩码语言建模的输入构造与结果还原

先把上一段留下的尾巴收掉。特征提取任务里返回的那几个键，我们已经逐个点名过：`token_type_ids` 是段落标记，`0` 代表第一个句子、`1` 代表第二个句子；一个分类输入长这样 —— 前面 `[CLS]`，中间第一句，后面跟 `[SEP]`，再跟第二句，最后再收一个 `[SEP]`。这里有一个特别容易被误读的地方：如果第二句比较短、被填充到了固定长度，那么第二句的 `token_type_ids` 又全是 `0` 了。那这些 `0` 是第二个句子吗？不是，它们是填充位。再往后如果出现 `0`、`1` 交替，那才是第三句、第四句的段落标记。

`last_hidden_state` 是最后一层隐藏层的输出，形状 `1 × 37 × 768`。`pooler_output` 是池化结果，做法是对最后一层隐藏层先做一次线性变换，再取平均池化 —— 出现"平均池化"这个词，基本就说明它服务的场景是分类，后面接别的任务时还要再加工。特征提取这一块就聊到这儿。

接下来换任务。下面这个动作叫**完形填空**，它还有一个正式名字：**掩码语言建模（Masked Language Modeling，MLM）**。名字听起来唬人，做的事其实和上一节一样——给模型一个带掩码的句子，让它把那个空填上。差别只在：上一节我们只关心隐藏层长什么样，这一节我们要的是它填出来的那个词。

## 1 任务切换与 AutoModelForMaskedLM 的选择

写代码之前先做一个小的工程调整。前面无论写分词器还是写模型，模型路径都要写两遍：加载分词器写一次，加载模型再写一次。哪天要换模型，上面一处、下面一处，漏改一处就报错。所以我们把模型名提成一个变量，在文件最上面记一次，下面都用它。

```python
# 第 0 步：定义变量记录模型名，避免路径重复书写
model_name = r"C:\software\develop\src\talk\chinese-bert-wwm"
```

模型名定好，接着按老节奏走：加载分词器、加载模型、文本转向量、喂给模型拿输出、取结果。

但这里有个必须停一下的地方：**完形填空该用哪一个 `AutoModel`？**

```python
from transformers import AutoTokenizer, AutoModelForMaskedLM
import torch

# 第 1 步：加载分词器
my_tokenizer = AutoTokenizer.from_pretrained(model_name)

# 第 2 步：加载模型
my_model = AutoModelForMaskedLM.from_pretrained(model_name)
```

> **易错点**：这里不能再写 `AutoModel`。用 `AutoModel` 加载，模型顶部没有那个"输出到词表维度"的预测头，跑起来会直接告诉你拿不到 `logits`。

`AutoModelForMaskedLM` 里的 `MaskedLM` 念全就是掩码语言建模，掩码语言指的就是我们刚才那个 `mask` 的位置。它和上一节 `AutoModel` 的唯一区别，就是多了顶上那一层按词表打分的预测头。

> **提示**：`encode` 和 `encode_plus` 本质上是同一件事的简写与完整版。`encode_plus` 是增强编码，参数给得更全，可以少写一些手工处理，别把两者当成两种不同机制。

## 2 输入构造与三个键的取值

文本转向量这一步，把要填空的那句话写进去。目标句子是"我 想 明 天 去 `[MASK]` 家 吃 饭"，掩码位置填上 `[MASK]`（对应的 token 文本是 `mask`）。

```python
# 第 3 步：文本转向量
inputs = my_tokenizer.encode_plus(
    "我想明天去mask家吃饭",
    return_tensors="pt"
)
print(inputs)
```

`return_tensors="pt"` 的意思是直接返回 PyTorch 张量，不然你还得自己把一列整数包装成张量。

第一次打印这堆结果，谁都会晕——满屏数字，谁是谁完全对不上号。所以我们逐个键拆开看，顺序就是回传字典里的顺序。

**先看 `input_ids`。** 把上面那句话按词表切好、映射成索引，得到的是：

```text
101, 2769, 2682, 2523, 1217, 103, 1716, 1391, 1928, 102
```

头部的 `101` 是 `[CLS]`，尾部的 `102` 是 `[SEP]`。中间那段就是我们写的每一个字按词表查出来的索引。

这里有一个必须问清楚的问题：**`mask` 在这里是一个 token，还是会被切成六个 token？**

答案是**一个**。`[MASK]` 是词表里的一个独立特殊符号，它对应的索引是 `103`。你往回看那串数字，`103` 就夹在"去"和"家"之间。如果它是六个字符拼成的，这串数字会多出五位，长度立刻对不上。

> **提示**：看索引和词表对不上号时，先数长度，再数位置。你按 human 的习惯从 1 开始数，而词表索引是从 0 开始的，所以你要找的那个字在词表文件里的行号，永远比索引大 1。这一步最容易让人怀疑"是不是我模型加载错了"。

**再看 `token_type_ids`。** 这里全是 `0`：这是一句话，一个整体。如果后面出现 `1`，那才说明后面那段是第二个句子。原因也很直白——我们写 `encode_plus` 的时候没有传 `max_length`、`padding`、`truncation` 这些参数，所以这里没有任何填充位。

**最后看 `attention_mask`。** 它全是 `1`，含义是"这个位置是真实值"；如果是 `0`，含义就是"这个位置是掩码位、填充位"。因为这次没有填充，所以全为 `1`。

| 键名 | 本讲取值特征 | 含义 |
| --- | --- | --- |
| `input_ids` | `101 ... 103 ... 102` | 文本按词表转成的索引序列，`101` 为 `[CLS]`、`102` 为 `[SEP]`、`103` 为 `[MASK]` |
| `token_type_ids` | 全 `0` | 段落标记，`0` 表示第一句，`1` 表示第二句；本讲只有一句话，故全 `0` |
| `attention_mask` | 全 `1` | `1` 为真实值，`0` 为掩码/填充位；本讲未做填充，故全 `1` |

## 3 模型推理与输出中的 logits

参数处理完，接下来给模型喂数据、取输出。这一步有几个细节值得单独说，因为它们决定了代码能不能跑通。

```python
# 第 4 步：给模型喂数据，获取输出
my_model.eval()                                  # 切到评估模式
output = my_model(**inputs)                      # 每个键按参数名具体赋值
print(output.logits.shape)                       # 查看 logits 的形状
```

`**inputs` 的作用，是把字典里的每个键当成关键字参数传进去：`input_ids` 传给 `input_ids`，`token_type_ids` 传给 `token_type_ids`，`attention_mask` 传给 `attention_mask`。不写这一步就得手动逐个传。

> **易错点**：跑推理之前记得 `my_model.eval()`。这一步把模型切到评估模式，`Dropout` 之类的层不再随机丢弃，同一句输入每次跑出来的结果才是稳定的。

`output` 里第一个该看的是 `last_hidden_state`，这个我们已经认识了。除此之外还有 `hidden_states` 等等，都可以往上扒拉看，但这次我们的目标不是它们。

关键在 `logits`。先看形状：

```text
torch.Size([1, 11, 21128])
```

这三个维度怎么理解？第一个 `1` 是批大小——一次给了一个句子。中间那个 `11` 是我们这个句子的长度：`[CLS]`、八个字、`[MASK]`、`[SEP]`，一共 11 个位置。最后那个 `21128` 是词表大小，也就是"这个位置上，词表里每一个 token 各自的分数"。

所以这串形状可以读成一句话：**11 个位置，每个位置都给出词表里两万多个词各自的概率**。

> **结论**：`logits` 的形状是 `[batch_size, sequence_length, vocab_size]`。完形填空要做的全部事情，就是在这个三维张量里，先定位到掩码那一行，再在那一行上取最大值的下标。

掩码在哪个位置？数一遍：索引 `0` 是 `[CLS]`，`1` 到 `5` 依次是"我 想 明 天 去"，第 `6` 位正是 `[MASK]`。

顺带提一个观察：虽然我们只留了一个空，但模型其实**把 11 个位置全部预测了一遍**，每个位置都有自己那 21128 个分数。我们只是去它里面挑掩码那一位而已。

## 4 预测结果的定位与还原

定位分两步：先在掩码位置取最大分数的索引，再把这个索引翻译回字。

```python
# 第 5 步：在掩码位置取概率最高的 token 索引
mask_predict_index = torch.argmax(output.logits[0, 6], dim=-1).item()
print(f"mask 位置的索引：{mask_predict_index}")
```

`output.logits[0, 6]` 这一串下标的读法是：取第 `0` 个批次、第 `6` 个位置，也就是掩码那一行；`torch.argmax` 在这一行 21128 个分数里找最大值所在的位置；`.item()` 把张量里的标量取成 Python 数字，打印出来才干净。

这次得到的是 `872`。

> **提示**：拿到索引之后，不要去猜它对应哪个字。索引是给模型用的，字是给人看的，中间那一步转换必须交给分词器。

翻译这一步得用分词器，而不是模型。模型只负责告诉你"我认为是第 872 号"，分词器负责把编号还原成字：

```python
# 第 6 步：把索引还原成字
print(my_tokenizer.convert_ids_to_tokens(mask_predict_index))
```

`convert_ids_to_tokens` 就是那个"翻译函数"，把 id 转成 token 文本。跑出来是"你"。

顺手验一下：去词表文件里找 872 这一行。前面我们数的时候说过，索引从 0 开始、行号从 1 开始，所以索引 872 对应的是词表里的第 873 行 —— 那里就是一个"你"字。

## 5 完整流程与关键改动点

把整件事串起来看，整个完形填空的链路是：

```text
模型名变量
   └─ AutoTokenizer.from_pretrained  ── 分词器对象
   └─ AutoModelForMaskedLM.from_pretrained ── 带掩码预测头的模型
                     │
   文本 "我想明天去mask家吃饭"
                     │
              encode_plus(..., return_tensors="pt")
                     │
        inputs: input_ids / token_type_ids / attention_mask
                     │
           my_model.eval() → output = my_model(**inputs)
                     │
        output.logits 形状 [1, 11, 21128]
                     │
   logits[0, 掩码位置] → torch.argmax → 索引 872
                     │
   my_tokenizer.convert_ids_to_tokens(872) → "你"
```

读图说明：左边是输入构造，中间是模型前向，右边是从三维 `logits` 里定位掩码行并还原成字，整条链路上只有两次"翻译"——一次是文本进模型前按词表转索引，一次是索引出模型后按词表转回字。

跑通这次任务，真正需要留意的只有三件事：

1. 模型名提成变量，加载分词器和加载模型都读同一个变量，换模型只改一处；
2. 加载模型必须用 `AutoModelForMaskedLM`，用 `AutoModel` 拿不到 `logits`；
3. `logits` 是三维的，先按 `[批次, 位置]` 取到掩码那一行，再在词表维度上取最大值。
