# 英译法案例的单批次训练：从编码、注意力解码到反向传播的完整一次迭代

教师强制这种训练技巧已经聊完了，一句话概括它的动作：强制干预。因为我们知道真实结果，所以解码器每次把真实结果当作输入的一部分，而不是拿模型自己的预测结果——预测一旦错了一步，基于错误答案往后接着预测，后面有可能全错。

接下来该看具体的训练过程了。真正动手之前，先看一眼这次和以往不一样的地方。

## 训练函数为什么要拆成两个

以往写代码，是把训练函数直接一遍全写下来。这次要分开，写两个。

- 第一个函数是**单批次的训练动作**，即一批次怎么训；
- 第二个函数才把整个分轮分批次训练写出来。

原因很实在：现在单批次训练的代码比较多，写完大概三四十行。你要是把这段代码揉进分轮分批次里，整个函数会非常长，一百多行，看起来就费劲了。所以拆开——**只做一批**。

而我们又知道，这份数据一批其实就一条数据。一个批次一条样本，这是后面所有形状推导的基准。

把上面的函数折叠起来看，它的位置是 `TODO 11`、`TODO 12` 这一段。

> **提示**：这一节里的代码只练真正有用的部分。凡是名字带 `demo`、`test` 的测试代码，你一个都不用练。能保证编码器没有任何问题，你测它干嘛？能保证解码器没有任何问题，你测它干嘛？所以那四个函数里，真正有用的是编码器和解码器这两个；剩下的都是测试，你如果不能保证自己写的代码没问题，那就一步一步测。

本轮要掌握的是：内部迭代训练函数、模型训练函数，以及损失曲线分析——也就是最后要画一下损失曲线。

## 单批次训练函数的参数

先把模型训练参数定义好，一共五个。

| 参数名 | 取值 | 含义 |
| --- | --- | --- |
| `my_lr` | `1e-4` | 学习率 |
| `epochs` | `5` | 训练轮数，至少也要跑三轮、五轮、十轮这个量级 |
| `teacher_forcing_ratio` | `0.5` | 教师强制的比例 |
| `print_interval` | `1000` | 打印信息的间隔，每训练 1000 条往控制台打印一次 |
| `plot_interval` | `100` | 绘图的间隔，每训练 100 条画一次图 |

`teacher_forcing_ratio` 这个值是 0.5 的含义要记准：一会儿会生成一个随机数，随机数比它小（小于这个阈值）就触发教师强制，比它大就不触发。所以 0.5 就是**有一半的概率会用上教师强制**。

> **易错点**：打印间隔和绘图间隔的作用域是分开的。打印是往控制台上打，1000 条一打印；绘图是画损失曲线时每 100 条画一次。两个数不要互相代入。

## 单批次训练函数的作用与入参

函数的任务范围，用一句话卡住：**完成一个样本从编码、到解码、到反向传播、到优化参数这一整条链路。**

函数签名收八个入参：

```python
def train_iterators(x, y, my_encoder_rnn, my_attn_decoder_rnn,
                    my_adam_encoder, my_adam_decoder, my_cross_entropy_loss):
    pass
```

逐个说清它们的身份：

- `x`：输入序列，形状为 `(batch_size, sequence_length)`。因为批次一直是 1，所以实际就是 `(1, 16)` 或 `(1, 18)` 这种——句子有多少个词，第二位就是多少。
- `y`：目标序列，即要翻译出来的法语句子，形状同样是 `(batch_size, sequence_length)`。
- `my_encoder_rnn`：编码器对象。
- `my_attn_decoder_rnn`：解码器对象，注意这里用的是**带注意力**的那个解码器。
- `my_adam_encoder` / `my_adam_decoder`：编码器优化器、解码器优化器。
- `my_cross_entropy_loss`：损失函数。

函数注释按这个口径写：实现单批次训练，完成一个样本从编码、解码到反向传播、再到优化参数的过程。

## 编码阶段

第一步，编码阶段：把输入的序列转换为上下文向量。

初始隐藏状态要先算出来：

```python
encoder_hidden = my_encoder_rnn.init_hidden()
```

然后做编码器的前向传播，把本次输入 `x` 和上一次的隐藏状态一起丢进去：

```python
encoder_outputs, encoder_hidden = my_encoder_rnn(x, encoder_hidden)
```

拿回来的两个东西：本次的隐藏状态和本次的输出。隐藏状态是一根链子末端的取值，输出是每个时间步的结果序列。

## 解码参数准备

解码这边的准备工作分四小步，一步都不能省，因为解码器的每次调用都要吃齐这几样东西。

### 构建用于注意力计算的输出张量

```python
encoder_outputs_c = torch.zeros(max_length, my_encoder.hidden_size)
```

这一步是要拿到形状 `(10, 256)` 的张量。`10` 是参与注意力计算的固定长度，`256` 是隐藏层维度。

这里有个必须解释清楚的疑问：为什么这里是 10，而上一步算出来的 `encoder_outputs` 可能只有 6 个位置？

因为句子长度不固定。你上面的那个长度可能是 `(6, 256)`——只有 6 个单词，不够 10 个。那不够 10 个怎么办？把实际的编码器输出**复刻**进去，把长度固定成 10：

```python
for index in range(x.shape[1]):
    encoder_outputs_c[index] = encoder_outputs[0][index]
```

`x.shape[1]` 拿到的就是那个“6”。循环按实际词数把有效位置填进去，剩下的位置保持全零。

> **结论**：注意力计算需要的是一份长度固定的编码器输出，所以先造一个 `(10, 256)` 的全零张量，再把实际长度的那几步复刻进去——这就是“固定为固定长度的向量”这个动作的写法。

### 解码器初始隐藏状态

```python
decoder_hidden = encoder_hidden
```

这行代码要读懂它背后的图，否则会觉得莫名其妙。跟着图走：编码器最后一步的隐藏状态，直接当成解码器的第一个隐藏状态。换句话说，解码器这边的 $s_0$ 就等于编码器那边的 $h_3$。

> **提示**：`encoder_hidden` 拿到的是编码器**最后一次**的隐藏状态，不是第一次。所以 `decoder_hidden = encoder_hidden` 这件事，含义是“编码器的最后一个隐藏状态，就是解码器的第一个隐藏状态”。做案例要上下通篇来回看，只看一段会懵。

它的形状是 `(1, 1, 256)`。

### 解码器初始输入

```python
input_y = torch.tensor([[SOS_token]], device=device)
```

这是解码器的第一次输入。它不是 `welcome`，不是任何真实单词，而是起始标记。这里要特别注意：图上标的可能是 `GO`，但你不能真的写 `GO`。因为我们最开始约定的特殊标记是 `SOS` 和 `EOS`，所以这里的 `SOS_token` 就相当于图上那个 `GO`，它构成解码器第一次调用所需要的内容。

形状是 `(1, 1)`——`[[SOS_token]]` 两层中括号，本来就是二维。

> **易错点**：张量必须迁移到指定设备。这里要写 `device=device`。只要是张量就得迁到指定设备，这样张量才能在指定设备上玩；没迁移，一会儿运算的时候就会报错，告诉你这个张量没有移动上来，用不了。

### 三样齐了，第一次解码就能发生

到这里，`decoder_hidden` 有了，说明 $s_0$ 有了；`input_y` 有了，说明那个 `GO` 有了。它俩往 GRU 里一传，第一次的输出就出来了。第一次的输出有了，下一次拿它当输入，再结合上一时刻的隐藏状态，就能得到第二次的结果，往后一环扣一环传下去。

## 目标序列长度与教师强制判定

解码循环开始前还有两件事。

```python
my_loss = 0.0
y_len = y.shape[1]
```

`y_len` 是要生成的法语句子的长度。不用去调 `len(y)`——形状里本来就有这个数，直接 `y.shape[1]` 取出来就行，能少调函数就少调函数。假设这句法语有 9 个词，那 `y_len` 就是 9，后面的循环就是 `range(9)`。

接着做教师强制的触发判定：

```python
use_teacher_forcing = True if random.random() < teacher_forcing_ratio else False
```

随机生成一个 0 到 1 之间的值，小于阈值就返回 `True`，大于等于阈值就返回 `False`。

这个判定有一个非常重要的性质，必须讲透：**它并不知道你这一步错没错**。它不是说“我精准地知道第三步错了，所以我就在第三步干预你”——它做不到这个。它只知道这次干不干预、下次干不干预，每一次都是独立按概率抽签。

那会不会出现这种情况：我这次预测错了，但这次没抽到干预？会。有没有可能第一次错没干预，第二次错立马就抽中干预？完全可能。所以这个机制防的是“越错越离谱”，不是“一次都不许错”。

> **提示**：阈值如果设成 1，因为随机数落在 0 到 1 之间，就意味着**永远都用**教师强制。真想把错误彻底堵住，就把它写成 1；反过来，你甚至可以不写这个随机判定，直接用与不用两条分支把代码摆出来。

## 教师强制分支

`if use_teacher_forcing` 走这里，说明使用教师强制：**用真实标签作为下一步的输入**。循环长度是 `y_len`。

```python
if use_teacher_forcing:
    for i in range(y_len):
        output_y, decoder_hidden, attention_weights = my_attn_decoder_rnn(
            input_y, decoder_hidden, encoder_outputs_c)

        target_y = y[0][i].view(1)
        my_loss += my_cross_entropy_loss(output_y, target_y)

        input_y = y[0][i].view(1, -1)
```

### 解码器的前向传播与形状

解码器的前向传播，就是把入参按位对齐地扔进去：

```python
output_y, decoder_hidden, attention_weights = my_attn_decoder_rnn(
    input_y, decoder_hidden, encoder_outputs_c)
```

这一步的入参与出参形状必须张口就能报出来，因为它是整张网络形状表的核心：

- 输入 `input_y`：`(1, 1)`
- 输入 `decoder_hidden`：`(1, 1, 256)`
- 输入 `encoder_outputs_c`：`(10, 256)`
- 输出 `output_y`：`(1, 4345)`
- 输出 `decoder_hidden`：`(1, 1, 256)`
- 输出 `attention_weights`：`(1, 10)`

`4345` 是法语词表大小，注意力权重压成 `(1, 10)`，正好对应 10 个被看的源位置。

### 当前时间步的真实标签

```python
target_y = y[0][i].view(1)
```

`y` 是二维的，`y[0]` 拿到里面那个一维列表，再传一个 `i`，就取到一维列表里的第 `i` 个元素——假设取到的是 119。

但直接拿 119 不行，它是一个标量值，后面没法参与运算。要把它转成张量，用 `view(1)` 转成一维，形状就是 `[119]` 这种。

### 累加损失

```python
my_loss += my_cross_entropy_loss(output_y, target_y)
```

`my_cross_entropy_loss` 就是函数外面传进来的那个损失函数参数，这里直接当交叉熵来用。扔进去的两个东西：`output_y` 是刚才前向传播返回的结果，`target_y` 是这一步的真实标签。

> **提示**：`target_y` 用 `view(1)` 而不是 `view(1, -1)`，是因为这里要的是一维形状 `[119]`，好和 `output_y` 那二维的一批概率做比对。到了下一小步要用它当输入时，才需要再升成二维——同一个标签，在两个不同的用途下要摆成两种形状，这是最容易写错的地方。

### 下一个时间步的输入

```python
input_y = y[0][i].view(1, -1)
```

走教师强制分支，下一个时间步的输入直接使用真实标签。注意这里取的是 `y[0][i]`，也就是 119 本身，不是 `i + 1`——因为本次要预测的是下一位，而喂进去的是这一位已经发生过的真值。

`view(1, -1)` 把它变成 `(1, 1)` 这种形状，形状一回到 `(1, 1)`，就正好对上图上 $Q$ 的位置。

> **易错点**：`view(1)` 是一维，`view(1, -1)` 是二维，这两个千万不能混。前者用于算损失，后者用于当前馈输入，写反了形状就对不上。

## 非教师强制分支

`else` 与 `if use_teacher_forcing` 对应，走这里说明不使用教师强制：**使用上一步的预测结果作为下一步的输入**。

```python
else:
    for i in range(y_len):
        output_y, decoder_hidden, attention_weights = my_attn_decoder_rnn(
            input_y, decoder_hidden, encoder_outputs_c)

        target_y = y[0][i].view(1)
        my_loss += my_cross_entropy_loss(output_y, target_y)

        top_v, top_i = output_y.topk(1)
        if top_i.squeeze().item() == EOS_token:
            break
        input_y = top_i.detach()
```

前两小步和教师强制分支完全一样：解码器前向传播，取当前时间步的真实标签（损失照样要用真实标签来算，只是输入换了来源），累加损失。

不一样的是后面这两步。

### 取概率最高的词

```python
top_v, top_i = output_y.topk(1)
```

获取预测的下一个词，也就是概率最高的那个词的索引和概率。`topk(1)` 拿到的就是第一名的值和它的索引。

### 遇到结束标记就停止

```python
if top_i.squeeze().item() == EOS_token:
    break
```

如果预测到了句子的结束标记，就停止预测，不再往后生成了。`squeeze()` 把多余维度去掉，`item()` 取出那个标量值，再和 `EOS_token` 比对。

### 把预测词接成下一次输入

```python
input_y = top_i.detach()
```

走到这里才说明：没有预测到结束标记，那就把预测出来的词作为下一个时间步的输入。

> **易错点**：这里必须加 `detach()`。因为要反向传播，而这一步的输入来自模型自己的预测，不能让这条“预测接预测”的链条把梯度一路往回穿，所以要把它从计算图上摘下来。形状和上面的 `input_y` 一样，都是 `(1, 1)`——区别只在于一个是真实值，一个是预测值。

## 反向传播与参数更新

两条分支的 `if / else` 折叠起来，里面的东西只做了一件事：把下一次时间步的输入准备好。分支之外，就是第五步——反向传播和参数更新。

```python
my_adam_encoder.zero_grad()
my_adam_decoder.zero_grad()

my_loss.backward()

my_adam_encoder.step()
my_adam_decoder.step()
```

梯度清零要清两个：编码器的优化器和解码器的优化器，一个都不能漏。然后 `my_loss.backward()` 做反向传播。最后两步是参数更新：`encoder` 更新一次，`decoder` 再更新一次，因为这两个子网络各自有自己的优化器。

> **提示**：清零、反向、更新这三件事的顺序不能颠倒。梯度是累加的，不清零就会把上一步的残留带进来。

## 返回平均损失

第六步，返回平均损失：

```python
return my_loss.item() / y_len
```

`my_loss` 里累加的是这条样本在这个批次里的全部损失，`.item()` 把它取成标量，再除以 `y_len` 得到每个时间步的平均损失。

到这里，单批次训练就写完了。下一个函数要做的才是分轮分批次——写两层 `for`，外层控制轮数、内层控制每轮的批次数，然后把这个函数调进去就结束了。

> **结论**：单批次的训练就已经这么麻烦，所以更要把它单独抽成函数；跟多轮多批次写在一起，函数就没法看了。

## 单批次训练的整体流程

把六个步骤串起来，一次单批次训练从入参到返回值走的就是这条路：

```text
x, y, 编码器, 带注意力解码器, 两个优化器, 交叉熵损失
        │
        ▼
[1] 编码阶段
    encoder_hidden = 编码器.init_hidden()
    encoder_outputs, encoder_hidden = 编码器(x, encoder_hidden)
        │
        ▼
[2] 解码参数准备
    2.1 构建注意力用的输出张量 (10, 256)，复刻实际长度
    2.2 encoder_outputs_c 填实际步
    2.3 decoder_hidden = encoder_hidden          -> s0
    2.4 input_y = [[SOS_token]]，device=device    -> GO
        │
        ▼
[3] my_loss = 0.0 ; y_len = y.shape[1]
        │
        ▼
[4] use_teacher_forcing = 随机数 < ratio
        │
        ├── True  ──► 每个时间步：前向传播 -> 取真实标签 -> 累加损失
        │              -> input_y = 真实标签(view(1,-1))
        │
        └── False ──► 每个时间步：前向传播 -> 取真实标签 -> 累加损失
                       -> topk(1) 取最高概率词
                       -> 命中 EOS 则 break
                       -> 否则 input_y = 预测词.detach()
        │
        ▼
[5] 两个优化器 zero_grad -> loss.backward -> 两个优化器 step
        │
        ▼
[6] return my_loss.item() / y_len
```

读图说明：第 1、2 步只做一次，把解码器需要的隐藏状态、起始输入和源端张量准备齐；第 4 步是每个时间步都要重复的核心循环，两条分支只在“下一步输入从哪来”上不同；第 5、6 步在整条样本跑完后执行一次。
