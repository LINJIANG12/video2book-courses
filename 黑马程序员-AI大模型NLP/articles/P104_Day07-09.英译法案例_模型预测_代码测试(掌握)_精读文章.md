# 加载已训练模型做翻译测试与效果评估

上一讲把评估函数写完了，但当时它还调不动——手边没有模型对象，也没有参数可喂。这一讲就是给它接上电源：把磁盘上训练好的编码器、解码器参数读回来，喂几句英文进去，看看它到底翻成什么样。

这活儿说白了就三步：加载模型、准备样本、逐样本翻译。输出是**三行**——原始英文、真实法语、我生成的法语。是骡子是马，拉出来遛遛。

## 模型路径与迁移学习的由来

第一个动作是把两个模型的文件路径定下来。

```python
# 1. 模型路径：model 目录下训练时保存的参数文件（编码器 + 带注意力的解码器）
path1 = "./model/my_encoder_rnn.pth"
path2 = "./model/my_attention_decoder_rnn_5.pth"
```

`path1` 是编码器：选 `my_encoder_rnn`。`path2` 是解码器：选带 `_5` 的那个，也就是**第 5 轮训练结束时保存的参数**。为什么挑最后一轮？因为轮数越往后，效果一般越好。当然这里有个前提——我们的训练数据里一共 6 万多条句子，每一轮却只训练了 3000 条，所以第 5 轮的 `_5` 也只是"在这 3000 条上练了 5 遍"的成果。

顺着这个路径，讲一件很多人好奇的事。

假设有个 `.pth` 文件，是我跑了 6 个小时、把 6 万条句子跑满 10 轮（一共 60 万次）训出来的。我把这个文件直接拷给你，你那儿能不能拿来就用？

能。**这就叫迁移学习**——拿着别人已经训练好的模型直接拿过来用，简单到就这一个动作。这也是后面章节要专门讲的内容，等我们讲完 Transformer 那个框架，接着学的就是迁移学习。

## 测试函数与两个模型的加载

函数名就叫 `demo_test_seq2seq_evaluate`，表示"Seq2Seq 模型的演示测试"。

```python
def demo_test_seq2seq_evaluate():
    # 1. 获取数据加载器对象
    my_dataloader = get_data_loader()

    # 2. 加载编码器模型
    my_encoder_rnn = EncoderRNN(input_size=english_word_n, hidden_size=256).to(device)
    my_encoder_rnn.load_state_dict(
        torch.load(path1, map_location=device, weights_only=True)
    )
    print("编码器模型架构：", my_encoder_rnn)

    # 3. 加载解码器模型
    my_attn_decoder_rnn = AttnDecoderRNN(
        output_size=french_word_n, hidden_size=256
    ).to(device)
    my_attn_decoder_rnn.load_state_dict(
        torch.load(path2, map_location=device, weights_only=True)
    )
    print("解码器模型架构：", my_attn_decoder_rnn)
```

加载这件事分两小步，顺序不能反：**先造一个结构相同的空对象，再把参数灌进去**。

先 `.to(device)` 把对象搬到 GPU，再 `load_state_dict` 把参数读进来。解码器这边写的 `french_word_n` 就是法语词表大小——4345 个法语词，这是解码器每个时间步要从中挑一个的那个类别数。

### map_location 与 weights_only

`torch.load(path1, map_location=device, weights_only=True)` 这一行里，第一次见到的人基本都会一脸懵。分开说。

> **定义**：`map_location` 决定读回来的参数放到哪个设备上。

正常配对应该是"用 GPU 训练就用 GPU 预测、用 CPU 训练就用 CPU 预测"。麻烦在于：**如果训练时用的是 GPU，你现在想用 CPU 加载它去跑，是会报错的**。代码看起来一样，但底层不一样——底层怎么不一样就得去问写框架架构师了。要跨设备，就靠 `map_location`。

所以加了 `map_location=device` 之后，设备**不挑**，方向也可以是反的：GPU 训练 → CPU 预测可以，CPU 训练 → GPU 预测也可以。不加就得老老实实设备配对，否则报错。

> **提示**：`weights_only=True` 表示只加载模型的**权重参数**，忽略保存文件里其他那些东西。这样一来读的是参数本身，不去执行任何附带内容，加载更安全、也更快。

两个 `print` 也不是摆设。打印出来的就是模型的层级结构：

```text
编码器 EncoderRNN：
  embedding      <- 词嵌入层
  gru            <- GRU 层

带注意力的解码器 AttnDecoderRNN：
  embedding      <- 词嵌入层
  attn           <- 注意力层
  bmm / attention_bmm   <- 注意力里的矩阵乘法
  dropout        <- 随机失活
  gru            <- GRU 层
  out            <- 输出层
  softmax        <- 输出概率
```

读图说明：这两段打印结果就是后面那张整体流程图的"骨架"，每一层都在里面挂着。脑子里装不下这张结构图，代码里那些维度转换就根本没法推——光流程本身就已经够绕，何况还有各种维度变换。

## 自定义测试样本

样本格式是"英文句子 + `\t` + 法语句子"，一对一行。

```python
    # 4. 自定义测试样本
    my_sample_pairs = [
        ["I am the spokesman of this organization",
         "Je suis le porte-parole de cette organisation"],
        ["I am thinking of buying a new umbrella",
         "Je pense acheter un nouveau parasol"],
        ["he swims very fast", "Il nage très vite"],
    ]
    print("自定义测试样本：", my_sample_pairs)
```

准备个三组就差不多了。

有人会问：样本是不是不该从训练集里抠，而应该从外面另找新的？其实都行，随你。但有一条硬约束——**你自己写的英文句子，里面每个词都必须在那 2803 个英语词里存在**，否则词表里查不到，模型也不认识它。所以我这里图省事就直接从训练数据里抠了几条。

抠的时候原始样本是"英文 TAB 法语"连成一整串的形式，从 TAB 那儿切一下——TAB 左边是英语句子，右边是真实法语句子。切完之后**每一对都要用单引号包成两个字符串，逗号隔开**，凑成一行一对的两元素列表，格式才对得上后面 `pair[0]`、`pair[1]` 的取法。

## 逐样本翻译

```python
    # 5. 对每个样本进行翻译
    for index, pair in enumerate(my_sample_pairs):
```

`enumerate` 出来的是下标加元素。下标默认从 0 开始：第 0 个样本、第 1 个、第 2 个。这个下标在这段代码里其实没被用到，后面打印的时候我另外用 `pair` 去取句子。

`pair` 装的就是一整个"英文 + 法语"的句子对，所以 `pair[0]` 是**英语句子**、`pair[1]` 是**真实的法语句子**。后面三步就写在这个循环体里。

## 文本数值化

```python
        # 5.1 文本数值化：英文句子 -> 索引序列
        temp_x = [english_word2index[word] for word in pair[0].split(" ")]
        temp_x.append(EOS_token)                       # 给句子添加结束标记
        tensor_x = torch.tensor(temp_x, dtype=torch.long, device=device).view(1, -1)
```

`pair[0].split(" ")` 按空格切，把句子切成一个个单词；拿每个词去 `english_word2index` 里查它排第几，就成了索引序列。这里用的是 `word2index` 而不是 `index2word`——现在要的是"从词找索引"，方向别搞反。

切完之后**必须补一个结束标记 `EOS`**，代表这句话到此为止。

接着用 `torch.tensor` 把它包成 `long` 型张量，搬到设备上，再来一个 `.view(1, -1)`。

> **提示**：`view(1, -1)` 是在外面又加一层维度，把原来的一维索引列表变成"$1 \times N$"的二维张量。原来句子的形状是 `[10, 30, ...]` 这种一维序列，加完这一层才是模型能吃的批次形式。

## 模型预测与结果还原

```python
        # 5.2 模型预测
        decoded_words, attentions = evaluate_seq2seq(
            tensor_x, my_encoder_rnn, my_attn_decoder_rnn
        )

        # 5.3 把翻译结果转成句子格式
        output_sentence = " ".join(decoded_words)
```

到这里该 `evaluate_seq2seq` 出场了。它要的第一个参数是 `tensor_x`——这就是前面为什么要费劲把句子包成张量；另外两个是编码器和解码器对象。返回的 `decoded_words` 是**一个词一个词的列表**，所以最后用空格 `join` 把它连起来，才算是能读的句子。

## 实测结果与误差归因

跑出来什么效果？说实话，别抱太大希望——原因只有一个：**训练太少了**。

先看几个对得上的：

| 原始英语 | 模型生成的法语 | 参考含义 | 评价 |
| --- | --- | --- | --- |
| `I am the spokesman of this organization` | 关于机构发言人的那句 | 我是这个机构的发言人 | 意思接近 |
| `I am thinking of buying a new umbrella` | `Je pense acheter un nouveau parasol` | 我正在考虑买把遮阳伞 | 基本正确 |
| `he swims very fast` | `Il nage très` | 他游泳的速度很快 | 相当准 |

也有彻底跑偏的。有一条生成出了"我正在洗澡"这种和原句毫不相干的内容，还有一条生成出"我是纳尔维克的一个儿子"这样莫名其妙的句子——这就是**完全废了**。

为什么？回到训练那一步。训练函数里写了这么一句：

```python
if i > 3000:
    break
```

也就是说，6 万多条句子，**只训练了 3000 条**，比例大概是 $\frac{3000}{63000} \approx \frac{1}{21}$。才跑了这么点数据，结果不准是正常的。

想让效果变好，操作也很简单：

1. 把训练函数里那个 `if i > 3000: break` 判断**注释掉或删掉**，这样每一轮都能吃满 6 万条数据；
2. 把训练轮数从 5 改成 10——其实 10 轮都算少，改成 100 也行；
3. 但轮数一上去，算力就顶不住了，跑起来要很久很久。

时间上是这么一笔账：CPU 上训完一轮大概 **50 分钟**，10 轮就是 **500 分钟**，差不多 **9 个小时左右**。所以最实际的做法是——**晚上睡觉前把训练这个函数跑起来，第二天早上模型就跑完了**，拿它再做预测，结果会比现在准很多很多。误差依然会有，但比现在这个效果好得多得多。

## 数据、算法与算力

为什么这事儿最后卡在机器上？因为人工智能就是三样东西：

```text
人工智能 = 数据 + 算法 + 算力
              |        |        |
              |        |        +-- 显卡：A100 80G / H100 80G，一张就 20 万
              |        +----------- 代码逻辑：编码器 + 带注意力的解码器，已经写完
              +-------------------- 6 万多条英法句子对，已经有了
```

读图说明：数据我们手上有 6 万多条英法句子对，算法这套编码解码的代码逻辑也写完了，**差的就只有算力这一项**。给我一块 A100 80G 或者 H100 80G，动不动就跑一轮，结果自然精准得多。

现实里为什么普通人不做这件事，就在这个"20 万一张"上。有些公司、科研机构，包括证券类机构，会配两块甚至三块这种显卡给团队用。也见过这样的团队：需要什么就跟公司说，别给公司省钱，要开会员、要买设备都批——那这种情况下，直接跟公司提一块 H100 80G 就完了。

不过在练手阶段，我们没必要纠结这个。**先把 3000 条改掉、把轮数加上去、让它通宵跑一遍**，看到效果变好，这个案例的教学目的就已经达到了。
