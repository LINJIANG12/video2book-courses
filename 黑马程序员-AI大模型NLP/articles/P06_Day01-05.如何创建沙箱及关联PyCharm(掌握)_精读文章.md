# 文本处理的基本方法与运行环境：分词、jieba 与 Conda 沙箱关联 PyCharm

要动手做文本处理，摆在面前的是两件事：一件是知识上的——分词怎么做、什么算有价值的文本信息；另一件是环境上的——包往哪儿装、项目跟哪个解释器绑。很多人把第二件当成杂事跳过，结果第一件越做越别扭。这一讲把两件一起办掉：先讲分词、命名实体识别和词性标注的定义和作用，再用创建 `nlp_base` 沙箱、关联 PyCharm 这条完整链路，把跑代码的地方准备好。

## 分词的定义与中文为什么必须分词

分词的介绍只有一句定义，但这句话要拆开看。

> **定义**：分词是把连续的字序列按照一定的规范重新组合成词序列的过程。

"一定的规范"是什么？说白了就是两个字：**语法**——主谓宾、定状补那一套。

分词的作用也是一句话：词是语言语义理解的最小单位，是人类理解文本语言的基础。还记得那六个字吗？字、词、句、段、篇、章。这是中文的天然层级，而 AI 要解决 NLP 领域的高阶任务——自动问答、机器翻译、文本生成——分词就是重要的基础环节。

回到大模型为什么火这个老问题上：一是它能理解我们说的话，二是它生成的内容符合人类的用语习惯。这两件事追到最底下，都要求先把一句话切成机器能逐个处理的最小单位。

那为什么中文要分词，英语却不用？

> **结论**：因为英语天然带空格，单词与单词之间有空格作**分界符**；中文没有明显的分界符，所以中文必须自己切。

看一个具体的句子：

> 传智教育是一家上市公司，旗下有黑马程序员品牌，我是在黑马这里学习人工智能的。

切词之后就变成：传智、教育、是、一家、上市公司、逗号、旗下、有……一路切下去。注意连标点也会被切成独立的一项。

## token 与不同模型的计费口径

这里要记一句话：**切词后分词的每个结果，等于一个 token**。

你对这个词应该有体感——玩大模型的时候，账号里是不是会送一些免费 token？要留意的是，不同模型的 token 计算方式不一样：有的模型可能两个字算一个 token，有的三个字算一个，有的四个字母算一个，有的五个或六个字母算一个。

拿阿里的模型举例：后面做项目要调用千问系列的模型，它有一个千问 Max（对应通义千问 Max）和一个 Plus。同一句话交给这两个模型，它们算 token 的方式也不一样。为什么？因为其中一个模型的结果更精简，另一个更大众化。而那种更精简的模型，将来的收费标准会稍微高一些。

> **提示**：分词的结果等于一个 token，先这么简单理解就够了；但要知道"同一个词在不同模型里可能不是同一个 token 数"这件事，它直接决定你调 API 花多少钱。

## jieba 分词工具与它的能力边界

既然要对中文分词，那怎么分？这里有一个流行的分词工具叫结巴。

> **定义**：jieba 是一个 Python 实现的分词库，对中文有很强的分词能力；它的愿景是做最好的 Python 中文分词组件。

除了 jieba，还有别的选择。这些不用去网上一个个翻，先认识几个名字就够：

| 工具 | 出品方 / 定位 | 特点 |
| --- | --- | --- |
| `jieba` | Python 实现的中文分词库 | 我们要用的就是它 |
| `SnowNLP` | 基于概率算法 | 中文自然语言处理工具包，也能分词 |
| `LTP` | 哈工大 | 适用于复杂的自然语言处理任务 |
| `THULAC` | 清华 | 一看名字就知道是清华出品 |
| `ik` 分词器 | Elasticsearch（ES）生态 | 搜索引擎场景用得多 |

这一堆做到两个字就够了——**了解**。开拓一下眼界、知道有谁，回头见到了不慌，就算达标。

那 jieba 自己有哪些作用？

- **支持多种分词模式**：精确模式、全模式、搜索引擎模式。精确模式就是以前用过的那套，对应 `lcut` 那个函数。三种模式的区别后面重点讲。
- **支持中文繁体分词**。繁体谁用得多？港澳台地区一般用得多一些——那也得能分。
- **支持用户自定义词典**。刚才切词的时候，它把"传智教育"和"黑马程序员"这两组词都切开了。但我想让它们各自成为一个词，怎么办？自己写个词典，以后词典中出现过的词，切词的时候尽量放在一起。

用大白话解释自定义词典：**有规则我就参考你的规则，你没规则，那就按我的规则走**。

装它需要一条命令：`pip install jieba`。三种分词模式的区别，实质上就是分词的**颗粒度**不同。

## 从装包到建沙箱：为什么不能一套 base 走天下

到这里就有个岔路了。以前的课早就玩过 jieba，早就装好了。按老流程，我现在应该打开 PyCharm 建个工程，然后哐哐写代码就完事——但这次我不这么做，我要额外讲一个内容。

因为 jieba 是第三方包，第一件事是把它装起来，而**以前那个环境不要再用了**。将来你到公司，很多情况下干的第一件事就是创建自己的沙箱，也就是创建自己的虚拟环境。

以前大家装包可能都在 `base` 里边，一直装一直装。但 NLP 这部分不一样：后面要部署 GPU 环境，如果把 GPU 那套装到你的 `base` 里，CPU 这套就用不了了，到手还得再折腾。所以现在就要开始按用途分家：

- `nlp_base`：NLP 基础环境，当它是 **CPU** 用的；
- `nlp_base2`：当它是 **GPU** 用的，后面配 GPU 时再讲。

> **易错点**：装完 Anaconda 会自带一个 `base` 环境，很多人的想法是"我一套 base 走天下"。不现实——有些项目对同一个包的版本要求不一样，全塞进 base 迟早撞车。所以第一件事就是分环境。至于沙箱存在哪个位置，其实无所谓。

## 沙箱的创建、激活与环境列表

打开方式：找到你的 Anaconda，右键选择 **Prompt**，以管理员身份运行。进去以后第一行显示的默认内容，就是 `base` 这个沙箱。

第一条命令是查看所有沙箱：

```shell
conda env list
```

其中 `env` 指的是 environment，环境的意思。执行之后能看到我这台机器上的几个：

| 沙箱名 | 用途 |
| --- | --- |
| `base` | Anaconda 自带的默认环境 |
| `nlp_base` | NLP 基础环境（CPU） |
| `nlp_base2` | NLP 环境（GPU） |
| `idol_rag` | 后面 RAG 项目要用的包所在环境 |
| `llm_env` | 大模型基础的环境 |

上课时我会在这几个之间切换：想用 CPU 就切 `nlp_base`，想用 GPU 就切 `nlp_base2`。

创建沙箱的基础命令形态是：

```shell
conda create -n 沙箱名
```

但别这么干。这么装会给你装**最新的** Python 版本。先看两件事：

```shell
python -V
conda -V
```

我这里的 `python -V` 是 3.12，`conda -V` 是 25 的版本。如果你的 conda 是 21、22、23 的，就有点旧了，至少升到 23 或 24 会好一些；跟我一样用 25 也行。

那如果我直接 `conda create -n 沙箱名`，Python 是不是就给我干到 3.12 了？干到 3.12，你后续的包就得按这个版本走。所以推荐一个相对稳定的版本：

```shell
conda create -n nlp_base python=3.10
```

> **提示**：建议使用 Python 3.10。注意两个等号和一处的区别——**在环境里指定 Python 版本时用一个等号**（`python=3.10`），而在 `pip install` 指定包版本时用**两个等号**（`jieba==0.42.1`），这是两套不同的写法。

接下来是一个必须停下来想清楚的细节。如果 `nlp_base` 这个环境已经存在，你敲回车创建同名环境时，它会提示：

```text
a conda environment already exists at ...
```

它在问你要不要 remove。这个时候要是写个 `y`，完蛋——它会把那个环境里已经装过的**所有包全部干掉，一个不留**。那后面带你玩所有动作，都得一个一个重新装，上课就变成这个状态：`pip install` 完，"你们等会儿啊，等我两分钟装完再上课"。这么干就没有意义了。

所以正确答案是敲 `n`：取消，不干这个动作。

还有一处命名上的坑。如果沙箱名我写成中文，你信不信一会儿有人装环境的时候，能把那几个中文原样抄上去？咱班我相信没这人，但这套课将来会传到哪里我不知道，真有个小白照着抄，那就出事了。所以统一改成下划线的英文：`nlp_base`。你要觉得不好区分，写成 `nlp_base_cpu` 也行，随你。

创建完要等一会儿——装 Python 3.10 得联网下东西。装好之后切换沙箱：

```shell
conda activate nlp_base
```

> **定义**：`conda activate` 后面的参数是要进入的沙箱名，作用是切换沙箱，说成"激活"也对。

清屏命令是 `cls`。

## 沙箱里的包管理：pip list 与 jieba 安装

切换过去之后，这个沙箱就算搞完了。看看它里边有哪些包：

```shell
pip list
```

你会看到里边很少——因为很多东西都还没装。我这台机器上装的包比较多，那是我一路装过来的。以后上课要是啥也不干，就干一件事"`pip install`，你等会儿让我装个包，咱们再讲课"，那就不 OK 了。这些包后面都要慢慢装，我可以把自己这个环境下的所有版本导出来成一个文件给你，那是后面的事。

现在先在这个环境里看 jieba。jieba 对版本要求其实不大。如果想装成跟我一样的版本，先看版本怎么看：

```shell
pip list | findstr jieba
```

正常要做的动作是安装：

```shell
pip install jieba
```

要装指定版本就写两个等号：

```shell
pip install jieba==0.42.1
```

如果你装的版本太新导致玩不了，就参考 `0.42.1` 这个版本；正常情况下是不需要指定版本的。

## 在 PyCharm 中创建工程并关联沙箱

沙箱建好了、切换成功了、jieba 也装好了，接下来是：在 PyCharm 里创建项目 `nlp_base_project`，然后**关联上述的 `nlp_base` 沙箱**。因为这是新环境，必须重新关联一次，否则 PyCharm 用的还是旧解释器。

**第一步，建工程。** 打开 PyCharm，选择 **New Project**。命名沿用以前的习惯：以前叫 ML、DL，现在就按方向命名，这次叫 `nlp_base`，也就是 NLP 基础 project；工程位置换成 `day01`。后面也是一样，day1、day2、day3、day4 一天天往下排。

**第二步，添加解释器。** 在建工程的界面里点开 Python 那个位置，往下走。我这里会显示以前关联过的沙箱，但新沙箱不在列表里——所以点 **Add Interpreter**，再选 **Add Local Interpreter**（添加本地的解释器）。

**第三步，选 Conda 并加载环境。** 点开之后选择 **Conda**，右侧有个 **Load Environments**，点一下它。它会去加载你的 conda 环境，界面上显示 `getting list of conda environments`。加载完之后，刚才的环境就全出来了：`nlp_base2`、`idol_rag`，还有新装的 `nlp_base`。选中 `nlp_base`，点 **OK**。

这里有个我踩给你看的坑。我一点 OK，出现 `please wait`，然后它给我长出来一个 `nlp_base (2)`。为什么？因为这个环境我配过，它又给我来了一遍。**你第一次做不会出现这个 2**——你建完就只有一个 `nlp_base`。所以我用它就行。

**第四步，删掉多余项。** 多出来的那个 2 虽然不难受，但得教你怎么删：

1. 左上角 **File** → **Settings**；
2. 选择 **Project** → **Python Interpreter**；
3. 把环境列表拉到最后，点 **Show All**，所有环境都在这里；
4. 选中 `nlp_base (2)`，点**减号**删除；
5. 删完记得点 **OK**，界面回到解释器设置后再点一次 **Apply**，然后 **OK**。

第一次配置的时候它会处理一会儿——因为沙箱过来以后，有些包和依赖要进到 PyCharm 里。配置完成后，当前这个 `day01` 工程使用的 Python Interpreter 就是 `nlp_base`。

**第五步，以后怎么切环境。** 还要像刚才那样 File → Settings → Python Interpreter 一层层点吗？不用了。

```text
                  PyCharm 右下角解释器切换
   +--------------------------------------------------+
   |  day01  [ nlp_base v ]   <- 点它，所有沙箱列在这里   |
   |                             选谁就切到谁            |
   +--------------------------------------------------+
                 |                       |
                 v                       v
            nlp_base                 nlp_base2
            （CPU）                   （GPU）
```

读图：工程右下角显示的 `nlp_base` 就是当前解释器，点开这个位置就能在 `nlp_base` 与 `nlp_base2` 之间切换——想玩 CPU 点 `nlp_base`，想玩 GPU 点 `nlp_base2`。

> **注意**：别在这个下拉里乱点。你呼呼乱点，PyCharm 就得在后台不断地更新、不断地更新，白等时间。

到这一步，创建沙箱以及关联 PyCharm 的动作就走完了。接下来我会用结巴分词给大家演示具体怎么做。
