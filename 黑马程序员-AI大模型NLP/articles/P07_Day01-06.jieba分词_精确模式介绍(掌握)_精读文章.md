# jieba 分词库概览与精确模式实战

jieba 的分词模式不是一个，是一串：精确、全、搜索引擎，另外它还支持中文繁体，还允许你塞一份用户自定义词典进去。这几件事我们得逐个拆开看，先从"分词到底在干什么"入手，把精确模式从讲义上的两行字，一直落到 PyCharm 里能跑起来、能打出结果的那几十行代码。

## 分词的本质与常见分词包

先把最底层那句话钉死：分词的过程，等于找到分界符的过程。中文不像英文那样自带空格，`I love NLP` 天然分成三段，而"传智教育是一家上市公司"是一整串字符，机器看不出边界在哪。所谓分词，就是去找出这些边界所在的字符位置——找到了分界符，词就切出来了。切出来的每一个结果，都叫一个 token。

> **定义**：分词（word segmentation）就是为连续文本确定词语边界的过程；每一个切分结果称为一个 token。jieba 的思路就是给句子找出分界符，把词与词切开。

常见的分词包有这么几个，我按它们的来路说一遍。

jieba（结巴）是我们这门课的主角，它支持精确模式、全模式、搜索引擎模式，能处理繁体字符，还支持用户自定义词典。

IK 分词器（IK Analyzer）多用在 Elasticsearch（ES）里。ES 是搜索引擎方向用得很多的组件，而它的检索底层依赖的是 Lucene。聊 Lucene 就得聊到一个人——Hadoop 之父道格·卡丁（Doug Cutting）。注意，是 Hadoop 之父，大数据领域的那位，不是大模型领域。他最早是做 Java 出身的，后来写了一个爬虫框架，就是 Lucene；当时他遇到的问题是：爬到了海量数据，该怎么存、怎么快速检索，后面才引出 Hadoop 那一摊事。我之前就是玩大数据的，所以从前讲课也要讲他。

还有 SnowNLP，它是基于概率算法的中文自然语言处理工具包。以及 pyltp，这是哈工大的；还有 THU 系列，一看名字就知道是清华的。

> **提示**：这些包你感兴趣的话可以去搜一搜它们底层是怎么实现的。但无论哪一家，本质上是同一件事——找分界符。找到分界符，才谈得上去做后续的文本处理。

## jieba 的三种能力与三种分词模式

jieba 的作用，可以列成三条：

- A：支持多种分词模式；
- B：支持中文繁体分词；
- C：支持用户自定义词典。

第二条和第三条没太多好讲的，重点是第一条。三种分词模式各自的定位是这样的：

| 模式 | 做法 | 适用场景 | 关键参数 |
| --- | --- | --- | --- |
| 精确模式 | 试图把句子最精确地切开 | 文本分析 | `cut_all=False`（默认） |
| 全模式 | 把句子中所有能成词的词语都扫描出来，速度非常快，但不能消除歧义，切出来的词不一定符合使用习惯 | 用得比较少 | `cut_all=True` |
| 搜索引擎模式 | 在精确模式的基础上，对长词再次切分 | 搜索引擎分词 | `cut_all=False` 且换函数 |

先看搜索引擎模式为什么要"对长词再次切分"，因为它想提高的是**召回率**。

> **定义**：召回率（recall）指真实为正例的样本中，被预测为正例的那部分所占的比例。

这里跟混淆矩阵对一下就很清楚：竖着算是精确率，横着算是召回率。所以召回率的分母是"真实正例"，分子是"真实正例中被预测为正例的那部分"——它衡量的是"该找的找回来了多少"。提高召回率，就意味着原来匹配不上、被漏掉的文档，现在能被匹配上了，这正是搜索引擎要的东西。

这三种模式如果只记一句话，那就是：它们实际上是**分词粒度**不同。

> **易错点**：粒度只有粗和细两档，中间没有"中粒度"。拿"软件工程"举例：切出来是 `软件工程` 一个整体，这叫粗粒度；切出来是 `软件`、`工程` 两个词，这叫细粒度。有人会问那"中粒度"是不是 `软件`+`工程`？不是——`软件`+`工程` 就是细粒度。真要再有更细的一档，那就得切成 `软`、`件`、`工`、`程`，可那样切根本没有意义：`软` 不一定是软件，`件` 也不一定能指软件，`工` 还可能是工业。切到这一步，歧义不是被消除，而是被放大了，后面的分析也没法做。这也正好解释了全模式"不能消除歧义"的毛病。

## 精确模式的第一版代码

新建脚本文件 `DM01_jieba分词`，把"演示 jieba 分词库的应用"这个案例骨架搭起来，然后按编号往下填：

- `TODO 1`：定义函数，演示 jieba 精确分词模式（适用于文本分析）；
- `TODO 2`、`TODO 3`……中间的编号先空着，后面一个一个补；
- `TODO 6`：测试代码。

```python
# TODO 1 定义函数, 演示 jieba 精确分词模式, 适用于文本分析
def demo01():
    # 1 定义待分词的文本内容
    content = "传智教育是一家上市公司"

    # 2 使用 jieba 进行精确模式分词(也是默认模式), 参数 cut_all=False 即为精确模式
    result1 = jieba.cut(content, cut_all=False)
    print(f"result1: {result1}")

    # 3 从生成器对象中获取所有的分词结果
    # 3.1 思路一: next 函数逐个获取下一个元素
    print(next(result1))
    print(next(result1))
    print("-" * 10)
    # 3.2 思路二: 遍历方式从生成器中获取元素
    for item in result1:
        print(item)

    # 4 需求: 要一个列表
    # 4.1 思路一: 把生成器转成列表
    list1 = list(result1)
    print(f"list1: {list1}")
    # 4.2 思路二: 切词时直接返回 list —— 语法糖
    list2 = jieba.lcut(content, cut_all=False)
    print(f"list2: {list2}")
```

`content` 这句话可以随便换，写成"今天天气很好，适合敲代码"一样能跑；我为了省时间，直接把讲义上的"传智教育是一家上市公司"拿过来了。

### `cut` 与 `cut_all` 参数的位置

按住 Ctrl 点进 `jieba.cut`，你会看到它最终落到 `dt.cut`，进去之后有一堆函数在告诉你这个操作怎么用，其中就包括 `cut_all` 这个参数。精确模式是 jieba 的**默认模式**，写 `cut_all=False` 是把它显式写出来——一会儿讲全模式，那个参数就变成 `True` 了。

### `cut` 返回的是生成器对象

`result1` 拿到手的不是列表，是一个生成器对象（generator object）。它的好处是节省内存：词不是一次性全算出来堆在内存里，而是你要一个才给一个。

代价也很明确：**生成器只能遍历一次**。口说无凭，先打印一下：

```python
print(f"result1: {result1}")
```

运行之后出现一行 `generator object`，看到 generator 这个词，就是生成器，没问题。

> **提示**：运行时控制台会先输出 `Prefix dict has been built successfully`，还会带上耗时，比如 0.6 秒。这不是报错，是日志——jieba 第一次分词要先把词典的前缀树构建起来，构建成功才继续分词。

## 从生成器里把词取出来

### 思路一：`next` 逐个取

```python
print(next(result1))
print(next(result1))
print("-" * 10)
```

`next` 每次往下取一个元素，两句一跑，"传智"、"教育"就出来了。但你要我 `next` `next` `next` 一个个拿完整句词，那实在没那个工夫，所以才有遍历。

### 思路二：`for` 遍历

```python
for item in result1:
    print(item)
```

`for` 的底层调用的就是上面那一堆 `next`，所以它和 `next` 是同一套机制在往后走。为了保证上面的 `next` 和下面的 `for` 是连着的，中间我打了个 `-` 号的分割线，打完再遍历——你可以把单横线换成等号那种更华丽的分割线，效果一样。

现在关键问题来了：**分割线下面的 `for`，开头还会不会有"传智教育"？**

答案是没有。因为生成器只能遍历一次。把生成器想成一个游标指针：一开始拿到它，指针停在第一个词的**前面**；你 `next` 一次，指针往下走一格，所以第二次 `next` 拿到的就是"教育"；等 `for` 上来接的时候，它接着指针的位置往后走，于是切出来的是"是"、"一家"、"上市公司"这些。

```text
生成器游标推进示意(以 "传智教育是一家上市公司" 为例)

  [开始]  指针位置: 传智 | 教育 是 一家 上市公司
  next 1 → 取到"传智"   指针: 传智 | 教育 是 一家 上市公司
  next 2 → 取到"教育"   指针: 传智 教育 | 是 一家 上市公司
  for   → 依次取到"是"、"一家"、"上市公司"
  [结束]  指针位置: 所有词之后, 再 next 拿不到数据
```

读图说明：指针只会单向右移，取过的词不会回头再给；遍历结束后指针停在所有词的后面。

## 生成器转列表与 `lcut` 语法糖

需求变成"我要一个列表"，形式是 `[词1, 词2, 词3]`。两个思路。

思路一是把生成器转成列表：

```python
list1 = list(result1)
print(f"list1: {list1}")
```

先说结论：**这么写是空的**。为什么？因为指针已经跑到所有词的后面了，生成器被榨干了。

要想让它有数据，就得把上面那段 `next` 和 `for` 注释掉，再运行，列表就有内容了。但这样太别扭——为了拿个列表，还得先把手写的遍历注释掉。

于是有了思路二：切词时直接返回列表，也就是语法糖：

```python
list2 = jieba.lcut(content, cut_all=False)
print(f"list2: {list2}")
```

看这行的写法：函数名还是原来那个 `cut`，只是前面多了一个 `l`——`cut` 变 `lcut`，返回的就是 list。参数还是 `content` 加 `False`。

> **结论**：`jieba.lcut(...)` 就是 `list(jieba.cut(...))` 的语法糖。它底层干的就是上面那一堆事：切词、遍历、收集成列表一次给你。以后只想要列表，直接写 `lcut`。

再运行一次，会发现 `list1` 依旧没结果，`list2` 有。原因不冲突：此时遍历那一段是打开的，`list1` 的指针早跑到末尾了；而 `list2` 是**重新切了一次**，自然拿到完整的词表。

到这里，打印出来的 `list2` 就是精确模式的分词结果。它是默认模式，也是做文本分析要用的模式。

## 完整脚本

把上面的片段按编号拼起来，就是这个脚本最终的样子：

```python
import jieba


# TODO 1 定义函数, 演示 jieba 精确分词模式, 适用于文本分析
def demo01():
    # 1 定义待分词的文本内容
    content = "传智教育是一家上市公司"

    # 2 使用 jieba 进行精确模式分词, cut_all=False 即精确模式(默认)
    result1 = jieba.cut(content, cut_all=False)
    print(f"result1: {result1}")          # 生成器对象

    # 3 从生成器对象中获取所有的分词结果
    # 3.1 思路一: next 逐个获取下一个元素
    print(next(result1))
    print(next(result1))
    print("=" * 10)
    # 3.2 思路二: 遍历方式获取元素
    for item in result1:
        print(item)

    # 4 要列表怎么办
    # 4.1 思路一: 生成器转列表(指针已到末尾, 结果为空)
    list1 = list(result1)
    print(f"list1: {list1}")
    # 4.2 思路二: 切词时直接返回 list(语法糖)
    list2 = jieba.lcut(content, cut_all=False)
    print(f"list2: {list2}")


# TODO 6 测试代码
if __name__ == '__main__':
    # 测试 jieba 精确模式分词
    demo01()
```
