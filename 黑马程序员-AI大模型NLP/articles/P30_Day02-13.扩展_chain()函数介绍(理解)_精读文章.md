# chain 函数：把多份词表拼成一条流并去重统计

需求 2 是统计训练集和测试集里不同单词的个数。数词之前，得先把所有词攒到一起——训练集是一份词表，测试集又是一份词表，我们要的是"所有句子里的所有词"，然后去重、再数个数。这一讲要用的函数叫 `chain`。

先去 PyCharm 里把架子搭出来：demo4，需求 2 这一段，注释写清楚——演示 `chain` 函数的用法。然后准备导包。

```python
# 需求2：演示 chain 函数的用法
from itertools import chain
import jieba
```

`chain` 在标准库 `itertools` 里，不用装任何东西；`jieba` 后面做中文分词要用。

---

## 1 用两个数字列表试手感

### 1.1 先看参数怎么给

`chain` 的用法得先用最简单的数据试出来，别一上来就拿真语料。先定义两个列表：

```python
list1 = [1, 2, 3]
list2 = [2, 3, 4]
```

`chain` 接收的就是这两个可迭代对象，把它们**串成一条流**：

```python
result = chain(list1, list2)
print(result)
```

### 1.2 惰性：不立刻迭代、只在实际取元素时才取

跑这一行，你会看到打印出来的是一个迭代器对象，而不是 `1 2 3 2 3 4`。这就是 `chain` 的第一个关键性质。

> **定义**：`chain` 是惰性的（lazy）——它不会立刻迭代，只是把"接下来要依次吐出哪些元素"这件事记下来，真正的取元素动作推迟到你实际遍历它的时候。因此它节省内存：不需要一次性把所有元素都生成出来放在内存里。

这条性质在语料上意义很大。如果你有一万条句子、分词之后是几十万个词，先拼成一个完整的大列表再处理，中间就会多出几十万个字符串的内存占用；用 `chain` 拼成流，边遍历边产出，中间不落地。

> **提示**：把 `print(result)` 换成 `for w in result: ...` 也一样，真正开始取元素的时刻就是你开始遍历的那一刻，不是 `chain(...)` 被调用的那一刻。

### 1.3 迭代器耗尽后不能再遍历第二次

接着试一个很容易踩的坑：把这条流从头到尾遍历一遍，然后再遍历一遍。

```python
result = chain(list1, list2)

# 第一次遍历：正常取到所有元素
for x in result:
    print(x)          # 1 2 3 2 3 4

# 第二次遍历：什么都不会输出
for x in result:
    print(x)          # 空
```

第二次什么都没有。原因是**迭代器内部的元素已经被取完了**——迭代器是有状态的，取一个少一个，取空之后再问它要，它给不出任何东西，而且不会报错，只是安静地什么都不输出。

> **易错点**：这种现象在调试时特别隐蔽。如果你先 `print(list(result))` 打了一眼结果，后面再拿 `result` 去做别的处理，就会得到一个空结果，然后你会以为是前面的环节出错了。迭代器只能消费一次。

### 1.4 转成列表看结果，以及 chain 与 extend 的区别

要看到真东西，用 `list()` 转一下：

```python
result = chain(list1, list2)
print(list(result))     # [1, 2, 3, 2, 3, 4]
```

两个列表的元素被首尾相接成了一条：`1 2 3` 后面接上 `2 3 4`。注意 `list2` 里的 `2` 和 `3` 与 `list1` 里的是重复值，`chain` 不管重复，它只负责拼接。

这件事用列表自带的 `extend` 也能做：

```python
list1.extend(list2)
print(list1)            # [1, 2, 3, 2, 3, 4]
```

结果看起来一样，但性质完全不同：

| 对比项 | `chain(list1, list2)` | `list1.extend(list2)` |
| --- | --- | --- |
| 是否修改原对象 | 不改动 `list1`、`list2` | **原地修改** `list1` |
| 结果要不要落地 | 惰性，只在遍历时才产出元素 | 立刻把元素全部塞进 `list1` |
| 内存占用 | 不需要新建一个完整的大列表 | 目标列表会增长到合并后的规模 |
| 返回值 | 一个迭代器，要 `list()` 才能看 | `None`，结果就在 `list1` 里 |
| 能不能接多个来源 | 可以，`chain(a, b, c, ...)` 一起串 | 一次只能 `extend` 一个 |

> **易错点**：`extend` 是原地操作，跑完之后 `list1` 就变了。如果你的后续逻辑还要用原始的 `list1`，用 `extend` 就把原数据毁掉了——这种情况必须用 `chain`。

还有一个更关键的区别：`extend` 只在两个列表的**元素同层**时才能得到想要的效果；而我们的真实数据是"每条句子分完词之后各是一个词列表"，是一层嵌套结构。把嵌套结构拍平，`extend` 得靠循环，`chain` 是天然为此设计的。

## 2 换成真实句子试

### 2.1 把两个列表换成两条句子

数字列表只是试手感，现在换成真正要处理的东西——中文句子。把两个列表重新定义成两条句子：

```python
list1 = ['今天天气很好']
list2 = ['今天天气很热']
```

这里要注意：句子本身是**没分过词**的整串文字，`chain` 拼的是"可迭代对象里的元素"，如果直接把两个句子丢进去，它拼出来的是两个整句，不是词。所以下一步必须先把句子分词。

### 2.2 分词：map 配 jieba.lcut

分词用 `jieba`。把分词函数作用到每一条句子上，还是那套已经用熟的 `map`：

```python
temp = map(lambda x: jieba.lcut(x), list1)
```

`jieba.lcut` 把一条句子切成词列表，`map` 把它作用到 `list1` 的每一个元素上。这一步跑完，`temp` 不是词列表，而是**词列表的列表**——每一条句子变成一个内部的词列表，外层还套着一层。这正是"嵌套"的来源。

```text
list1 = ['今天天气很好']
            │  jieba.lcut
            ▼
        [['今天', '天气', '很', '好']]      ← 外层一层，里层是词
                └──────── 这一层才是我们要的词 ────────┘
```

读图说明：`map` 之后得到的是"每个句子一个词列表"的两层结构，只有把外层这层剥掉，才能得到所有词连成的一整条。

### 2.3 星号解包：把词列表逐个摊开当参数

把外层剥掉用的就是星号 `*`。先看它单独怎么用：

```python
temp = [['今天', '天气', '很', '好'], ['今天', '天气', '很', '热']]
result = chain(*temp)
print(list(result))
# ['今天', '天气', '很', '好', '今天', '天气', '很', '热']
```

> **定义**：`*` 叫打包/解包操作符。写在实参位置时，它把一个可迭代对象**展开成一个个独立的参数**传进去。

也就是说，`chain(*temp)` 等价于：

```python
chain(['今天', '天气', '很', '好'], ['今天', '天气', '很', '热'])
```

`temp` 里的两个词列表，被 `*` 摊成了 `chain` 的两个位置参数。`chain` 再把它们首尾相接——嵌套就这么被拍平成了一层。这一步是这讲真正的关键点：`chain` 负责串，`*` 负责展开，两者合起来才叫"拍平嵌套列表"。

### 2.4 去重：set 的作用

拍平之后还有一件事：我们要统计的是**不同单词**的个数，而"今天""天气""很"在两条句子里都出现了。去重交给 `set`：

```python
result = set(chain(*temp))
print(result)
# {'今天', '天气', '很', '好', '热'}
```

集合天然去重，重复的"今天""天气""很"只留一个。到这里，`result` 里装的就是这批句子里出现过的所有不重复的词——对它取 `len`，就是要的那个"不同单词的个数"。

## 3 一行写完：set(chain(*map(lambda x: jieba.lcut(x), list1)))

上面四步其实可以压成一行：

```python
result = set(chain(*map(lambda x: jieba.lcut(x), list1)))
```

从里往外读这一行，每一层都在干一件单独好懂的事：

```text
set( chain( * map( lambda x: jieba.lcut(x),  list1 ) ) )
 │      │    │    │                              │
 │      │    │    │                              └─ 原始句子集合
 │      │    │    └─ 分词：每条句子 → 词列表（产生嵌套）
 │      │    └─ 解包：把词列表摊成 chain 的多个参数
 │      └─ 串接：把摊开的词列表首尾相接成一条流（惰性）
 └─ 去重：只留下不重复的词
```

读图说明：四个动作各自独立，`map` 制造嵌套、`*` 解开嵌套、`chain` 串成流、`set` 去重，顺序不能乱——`*` 必须贴在 `map` 的结果上，`set` 必须包在最外层。

回看这个需求本身："统计训练集和测试集里不同单词的个数"。这句话里的每个字都落到了这一行上：训练集和测试集就是 `chain` 的两个（或更多个）来源，不同单词就是 `set`，个数就是最后那个 `len`。所以这一行不是炫技，它就是这个需求最直接的写法。

> **提示**：`chain(*map(...))` 这种写法只有在来源个数已知、且都已经在内存里时才方便用 `*` 展开。如果来源数量很大、或者是流式产出、或者嵌套层数不确定，就别用 `*`，改用 `chain.from_iterable(可迭代对象)`——它同样拍平一层，但不需要先把所有子列表解包成参数，惰性保持得更彻底。

到这里需求 2 的准备工作就绪了：所有句子的词被拼成了一条流，重复的词被滤掉，剩下的就是词表。下一讲就用它来统计词频。
