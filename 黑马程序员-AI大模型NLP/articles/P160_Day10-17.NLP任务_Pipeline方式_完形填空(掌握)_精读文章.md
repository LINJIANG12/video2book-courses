# Pipeline 完形填空实战：遮蔽语言建模只填一个空

第三个 Pipeline 任务叫**完形填空**，它还有一个更正式的名字——**遮蔽语言建模任务（Masked Language Modeling，MLM）**，是 BERT 类模型预训练时用的那个子任务。用一句话说清楚它干什么：句子里挖掉一个空，让模型把可能填进去的字全部列出来，并且给出各自的概率。中文场景里最顺手的例子就是「我想明天去 [MASK] 家吃饭」。

## 任务名与模型：fill-mask 配 chinese-bert-wwm

在 Pipeline 里，这个任务的任务名固定写作 `fill-mask`，对应中文的「完形填空」。模型这边我换成了 `chinese-bert-wwm`，也就是哈工大讯飞那个全词遮蔽（Whole Word Masking）的 BERT。

换模型这件事每次都会有人问：「你怎么一个任务换一个模型，我怎么知道哪个任务该用哪个模型？」答案不是靠猜，也不是靠一个个试，而是去模型社区的任务导航里查。

打开魔搭社区（ModelScope）首页，左侧的导航已经按大类把任务列好了：热门任务、多模态、自然语言处理、语音……你要玩的任务一定在其中之一。点进对应任务，右边列出的就是属于这个任务的模型，再在里面搜关键词即可。

> **提示**：魔搭只是我举的例子。咱们这套代码用的是 Hugging Face 的 Transformers，所以模型就得到 Hugging Face 去下；如果你用魔搭社区的库，那代码是另外一套——点进模型页会看到一段测试代码，导包导的是 `modelscope`，那是它自己的接口。两边本质一样，但**导包和下载来源必须配套**，混着用一定跑不通。

## 三行代码的骨架：只有中间两处会变

写 Pipeline 有个规律你很快就会发现：你现在做的每个任务，代码都只有三行。最后一行输出固定不变，中间只是换任务名、换模型，以及换掉那句待处理的句子，其他全都一模一样。

```python
from transformers import pipeline

# 1. 创建 pipeline 对象：任务名 fill-mask + 本地中文 BERT 模型目录
pipe = pipeline(task="fill-mask", model=r"chinese-bert-wwm 的本地目录")

# 2. 代入带占位符的句子
result = pipe("我想明天去[MASK]家吃饭")

# 3. 输出
print(result)
```

模型路径我习惯用本地目录。怎么拿到它？对着模型文件夹右键，选「打开文件所在位置」，往上一级，选中 `chinese-bert-wwm` 这个目录，把它整条路径拉过来填进 `model` 参数就行。占位符那边要记住：中间那个空用的不是下划线之类的东西，就是方括号包起来的大写单词 `[MASK]`，而且**区分大小写**。

## 一次只能填一个空

这里有一条必须记牢的规则，也是最容易晕的地方：

> **易错点**：`fill-mask` 一次只能预测**一个** `[MASK]`。不是「一个字」，而是「一个 mask」——句子里有几个 `[MASK]`，一次调用只解决其中一个。

如果句子里有多个空要填，不能指望它一次全给你，必须**用循环**：先预测第一个 `[MASK]`，把概率最高的结果回填进句子，再基于回填后的新句子预测第二个、第三个，一路往后推。这就是标准的逐个补全流程。

```python
text = "我[MASK]你，你[MASK]我"

# 第一轮：只解第一个 [MASK]
step1 = pipe(text)
best1 = step1[0]["token_str"]
text = text.replace("[MASK]", best1, 1)

# 第二轮：基于第一次的结果继续
step2 = pipe(text)
best2 = step2[0]["token_str"]
text = text.replace("[MASK]", best2, 1)

print(text)
```

嫌麻烦？嫌麻烦就别用它，后面还有别的大模型能一次处理多个空。但就这套 Pipeline 而言，眼下只能这么做。

## 默认返回概率最高的五个候选

把 `我想明天去[MASK]家吃饭` 丢进去执行，返回的不是一个答案，而是按概率从高到低排好的**五个**候选：

| 排名 | 预测填入的字 | 拼回来的句子 |
| --- | --- | --- |
| 1 | 她 | 我想明天去她家吃饭 |
| 2 | 你 | 我想明天去你家吃饭 |
| 3 | 他 | 我想明天去他家吃饭 |
| 4 | 我 | 我想明天去我家吃饭 |
| 5 | 您 | 我想明天去您家吃饭 |

> **结论**：`fill-mask` 默认返回概率最高的前五个结果，不是一个。这五个字全部来自模型的词表（vocabulary），词表里没有的字，它绝不会输出。

看结果的时候还遇到个小插曲：候选里不止中文，还冒出来几条日文 —— 片假名 `スノー`（雪），以及 `しています`（正在做）。有人当场念了一遍，查完发现读作「しています」，意思就是「正在做某事」，属于日语动词的进行时。这事说明一个点：这个中文模型的词表里同时收了中文、日文和特殊符号，所以预测出来的候选不一定都是汉字，看到非中文字符不用慌，它同样是词表里检索出来的合法 token。

跑起来时控制台会先刷出一大堆提示，比如 `BertForMaskLM` 开头的、以及 `If you are on ... owner of ...` 之类的英文。这些是**日志，不是报错**。其中一条说的是「你正在用 GPU 环境，但没设置 device 参数」，所以这次推理实际还跑在 CPU 上——听它的提醒，把设备参数补上就行。

## 结果里的 token：从词表第几行来

返回结果里除了 `token_str`，还有一个 `token` 字段，是个整数。它是什么？直接打开模型目录下的 `vocab.txt` 就懂了。

上面结果里排第二的「你」，对应的 token 是 872。去 `vocab.txt` 里数一下：这个「你」字在第 873 行上，而它的索引却是 872。

> **结论**：词表里的**行号是从 1 数**的，而 token 索引是**从 0 开始数的**，所以「第 873 行」对应的索引正好是 872。这个差 1 不是 bug，是数数方式不同。

看懂这一条，你再看其他几个预测字，就能自己拿 token 编号去词表里核对位置了——每个预测结果都是从同一张词表里检索出来的。
