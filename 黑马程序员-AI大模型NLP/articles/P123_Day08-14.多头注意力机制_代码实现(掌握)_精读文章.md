# 多头注意力机制的 PyTorch 代码实现：克隆函数与前向传播

结构图聊完了，接下来把这张图写成能跑的代码。这段代码本身并不算深——浅显，直接自己写就行，写完再看测试。

先把要写的东西列出来。有两个待办：一个是定义克隆函数，一个是实现多头注意力机制这个类。

## 1 克隆函数：一次定义，N 份实例

先说第一个：定义一个克隆函数，用来把指定的模块克隆 N 次，返回一个包含 N 个相同模块的列表。

### 1.1 为什么需要这个函数

多头是什么？多头就是：我只要写一次，把它复制 7 次，剩下的内容就都过来了。

这个套路不止用在这一处。回想一下编码器：编码器是由 6 个编码器层组成的。我们只需要写好一个编码器层，再把它复制 5 份，整个编码器就齐了。所以写一个通用的克隆函数，后面到处都用得上。

### 1.2 实现

先在文件里把 `copy` 包导进来，然后写函数。

```python
import copy


def clones(module, N):
    """创建 N 个相同的模块，返回一个列表

    :param module: 要被克隆的模块
    :param N: 克隆的次数
    :return: 具有 N 个相同模块的列表
    """
    return nn.ModuleList([copy.deepcopy(module) for _ in range(N)])
```

外层用 `nn.ModuleList` 把结果包成模型列表，列表推导式里循环 `N` 次，每次做一次 `copy.deepcopy`。

这里有两个细节值得停一下。

第一，循环变量为什么写成下划线 `_`？因为循环体里根本不需要那个 0 到 N-1 的数字，我只要「做 N 次」这个动作本身。既然用不上，就别给它起名字。

第二，为什么必须是深拷贝（`deepcopy`），而不是浅拷贝？深拷贝让每个模块拥有**独立的参数**。如果只是浅拷贝，N 份模块会共享同一套参数，你以为你复制了 8 个头，实际上它们永远是同一个头——多头就白做了。

> **易错点**：`copy.deepcopy` 这一句就是克隆函数的核心动作。只用 `copy.copy` 或者直接放同一个对象进列表，得到的 N 个模块参数是共享的，8 个头会退化成 1 个头。

## 2 多头注意力类的初始化

第二个待办是定义 `MultiHeadedAttention` 类，它才是实现多头注意力机制的地方。核心就一句话：把词向量维度分成 N 个头，并行计算小维度的注意力，从而增强模型的表达能力。

类名照惯例用缩写，把 `Attention` 缩成 `attn`：

```python
class MultiHeadedAttention(nn.Module):
    def __init__(self, d_model, head, dropout=0.1):
        super(MultiHeadedAttention, self).__init__()
```

参数一共三个：

| 参数 | 示例值 | 含义 |
| --- | --- | --- |
| `d_model` | 512 | 词向量维度，也就是分头前那条 512 维 |
| `head` | 8 | 头数，要分成几个头 |
| `dropout` | 0.1 | 随机失活概率 |

`__init__` 里一共要做六件事，一件一件来。

### 2.1 用 assert 保证能整除

第一件事是分头动作的前提检查——确保 `d_model` 能被 `head` 整除。

```python
        assert d_model % head == 0
```

这行代码在说什么？先看它怎么工作。

写 `assert 10 % 2 == 5`，10 除以 2 得 5，条件成立，程序继续往下走，不会报错。写成 `assert 10 % 2 == 3`，条件不成立，报错，程序就停在这儿，不往下走了。要是写成 `10 / 0`，那是直接报错，同样不会往下走。

> **结论**：`assert` 的含义是——只有它后面的条件成立，代码才会继续向下执行；条件不成立就报错中断。

放回我们的场景：512 维和 8 个头取余等于 0，说明能整除，`assert` 通过，代码继续。这正好把分头的合法性锁死在入口处。

另外注意这里是**整除**。`d_model` 除 `head`，得到的是整数结果，不是带小数的除法结果。

### 2.2 计算每个头的词嵌入维度

第二件事，算出每个头分到多少维：

```python
        self.d_k = d_model // head
```

512 除以 8 等于 64，所以 `self.d_k = 64`。

到这里，「8 个头」和「64 维」这一对就配好了——`head` 是 8，`d_k` 是 64，两个数合起来还原成 512。这和结构图上 `2 4 8 64` 那个形状是一一对应的。

### 2.3 定义四个线性层

第三件事，定义四个 `nn.Linear`，仍然用 `d_model` 到 `d_model`：

```python
        self.linears = clones(nn.Linear(d_model, d_model), 4)
```

为什么是四个？数一下结构图就够了：Q 一个、K 一个、V 一个，最后输出还有一个。前三个负责 Q、K、V 的投影（也就是映射），最后一个负责输出——输出谁？输出多头注意力机制的结果。

那我会不会老老实实写四遍 `nn.Linear(512, 512)`？

不会。这时候第一个待办就派上用场了：`clones` 要一个 `module`、一个 `N`，`module` 就是 `nn.Linear(d_model, d_model)`，`N` 就是 4。一句话替掉四段重复代码。

### 2.4 随机失活层与注意力权重容器

第四件事，定义随机失活层，把概率传进去：

```python
        self.dropout = nn.Dropout(p=dropout)
```

第五件事，准备一个用来保存注意力权重的变量，供可视化使用。现在还没有值，先给 `None`：

```python
        self.attn = None
```

所有注意力权重最后都会赋值到这个属性上，所以先占个位就行。

### 2.5 初始化小结

```python
class MultiHeadedAttention(nn.Module):
    def __init__(self, d_model, head, dropout=0.1):
        super(MultiHeadedAttention, self).__init__()
        assert d_model % head == 0                 # 确保能整除
        self.d_k = d_model // head                 # 每个头的词嵌入维度，512 // 8 = 64
        self.head = head                           # 头数
        self.linears = clones(nn.Linear(d_model, d_model), 4)   # Q、K、V、输出 四条投影
        self.dropout = nn.Dropout(p=dropout)       # 随机失活层
        self.attn = None                           # 保存注意力权重，用于可视化
```

## 3 前向传播的整体流程

`__init__` 把零件备好，`forward` 负责把它们按顺序串成多头注意力的计算流程。

```python
    def forward(self, query, key, value, mask=None):
```

进来先看掩码。

### 3.1 掩码的形状处理

```python
        if mask is not None:
            mask = mask.unsqueeze(0)
```

掩码不为空时给它升一维。为什么要升？因为 Q、K、V 的形状是 `batch_size × seq_len × d_model`，而掩码在批量这一维上可以只写 1，靠广播自动铺满整个 batch。

```text
        mask                    mask.unsqueeze(0)
        seq_len × seq_len   →   1 × seq_len × seq_len
                                       ↑
                                  这一维写 1，靠广播适配 batch
```

读图：掩码本来只描述「哪些位置能看、哪些位置不能看」的一张二维表，升维后在最前面补一个长度为 1 的批量维，就能和 `batch_size × seq_len × d_model` 的数据自动对齐。

### 3.2 取出 batch_size

```python
        batch_size = query.size(0)
```

`query.size(0)` 拿的就是形状里的第一个数。形状是 `2 4 512`，那么取出来的就是 2。后面 `view` 要用到它。

### 3.3 Q、K、V 线性变换与分头

接下来是这一讲真正要吃透的一段。把三个线性层和 Q、K、V 绑在一起，用 `zip` 成对遍历：

```python
        Q, K, V = [
            model(x).view(batch_size, -1, self.head, self.d_k).transpose(1, 2)
            for model, x in zip(self.linears, (query, key, value))
        ]
```

这一段写成一行确实有点密，拆成三层看就清楚了。

第一层，`model` 是谁？是 `self.linears` 里前三个线性层。`zip` 就是把两个可迭代对象按位置配对：`self.linears` 和 `(query, key, value)` 拼起来，于是 `(query, key, value)` 依次配上三个 Linear，各自投影出 512 维的词向量表示。

第二层，`.view(batch_size, -1, self.head, self.d_k)`。`view` 的作用是把输入张量重新排成 `batch_size × seq_len × head × d_k` 这个形状——`seq_len` 用 `-1` 让 PyTorch 自己算，`head` 是 8，`d_k` 是 64。于是 `2 4 512` 变成了：

```text
        2 × 4 × 512        （batch × seq_len × d_model）
             │
             │ view(batch_size, -1, head, d_k)
             ▼
        2 × 4 × 8 × 64     （batch × seq_len × head × d_k）
```

读图：`512` 这一维被拆成 `8 × 64` 两维，`8` 是头数，`64` 是每个头分到的维度，其余维度不动。

第三层，`.transpose(1, 2)`。这一步交换第 1 维和第 2 维的位置：

```text
        2 × 4 × 8 × 64     （batch × seq_len × head × d_k）
             │
             │ transpose(1, 2)
             ▼
        2 × 8 × 4 × 64     （batch × head × seq_len × d_k）
```

读图：`seq_len` 和 `head` 这两维对调，把头提到 `seq_len` 前面。于是每一个头都能完整地看到这 4 个词各自 64 维的信息，而不是「4 个词各切一小块」那种碎法。

> **提示**：`view` 和 `transpose` 这两步合起来，才是结构图上那个「分头」动作的完整实现——`view` 负责拆维度，`transpose` 负责把拆出来的头摆到合适的位置。

### 3.4 算注意力并保存权重

```python
        x, self.attn = attention(Q, K, V, mask=mask, dropout=self.dropout)
```

把 Q、K、V、掩码、丢包层交给注意力函数，一次拿到两个东西：多头注意力的输出 `x`，以及注意力权重 `self.attn`。

这里的形状账：Q、K、V 都是 `2 8 4 64`，算完之后注意力输出 `x` 还是 `2 8 4 64`；而权重矩阵的形状是 `2 8 4 4`——最后一个 4 表示 4 个词之间的关联，每个词对 4 个词分别有多大的关注度。

```text
        输入 Q K V          2 × 8 × 4 × 64
                                 │
                        缩放点积注意力
                                 │
              ┌──────────────────┴──────────────────┐
              ▼                                     ▼
        输出 x  2 × 8 × 4 × 64              权重 attn  2 × 8 × 4 × 4
        （每个头 64 维的结果）              （4 个词两两之间的关联）
```

读图：一次注意力计算同时产出结果和权重，结果继续往后传，权重存进 `self.attn` 留给可视化用。

### 3.5 多头结果拼接

现在手上是 `2 8 4 64`，该把 8 个头拼回去了。拼接要先把形状转回来：

```python
        x = x.transpose(1, 2).contiguous().view(batch_size, -1, self.head * self.d_k)
```

三步走：

1. `transpose(1, 2)`：把 `head` 和 `seq_len` 换回来，`2 8 4 64` 变成 `2 4 8 64`；
2. `contiguous()`：让张量在内存里变成连续存放；
3. `view(batch_size, -1, head * d_k)`：把 `8` 和 `64` 两维合并，`2 4 8 64` 变成 `2 4 512`。`head * d_k` 就是 `8 × 64 = 512`。

> **易错点**：`transpose` 只换维度顺序，不改变数据在内存里的排布，所以它后面直接跟 `view` 是有风险的。`contiguous()` 这一步不能省——先把数据按新的维度顺序整理成连续的一块，`view` 才能安全地重新划分形状。

```text
        注意力输出        2 × 8 × 4 × 64      （batch × head × seq_len × d_k）
              │
              │ transpose(1, 2)
              ▼
                          2 × 4 × 8 × 64      （batch × seq_len × head × d_k）
              │
              │ contiguous() 把数据整理成连续
              ▼
              │
              │ view(batch_size, -1, head * d_k)
              ▼
        拼接结果          2 × 4 × 512         （8 × 64 = 512，回到词向量维度）
```

读图：先换维度顺序、再整理内存、最后合并特征维，三步做完，8 个头的输出重新变回每个词 512 维的样子。

### 3.6 最后一个线性层输出结果

形状已经是 `2 4 512` 了，最后一步就是过输出线性层：

```python
        return self.linears[-1](x)
```

`self.linears` 里有四个线性层，`-1` 取的就是最后一个——它专门负责输出。前三个已经在分头那一步用掉了，这一个把拼接好的结果投影成最终输出。

到这儿，多头注意力机制的代码就写完了。回头看整条链路：克隆函数省掉了四段重复的 `nn.Linear`，`view` 加分头、`transpose` 摆位、注意力计算、`transpose` 加 `contiguous` 加 `view` 合并、最后一个线性层收尾——结构图上画的每一个方块，在代码里都能找到对应的一行。代码本身挺顺畅，主要就是把刚才那张图用代码模拟出来。
