# 基于 GRU 的 Seq2Seq 编码器构建

先把这一讲要落地的位置说清楚：我们现在啃的是 Seq2Seq（Sequence to Sequence，序列到序列）这个架构。既然是 Seq2Seq，那就意味着你不可能只做一半——左边的编码器要做，右边的解码器也得做，而且解码器还要做两个版本：一个不带注意力机制的，一个带注意力机制的。

所以光"构建模型"这件事，函数至少有三个。其实不是三个，是五个：编码器一个、无注意力解码器一个、带注意力解码器一个，写完还都得测——测试代码又是两个函数。我们一步一步来。

## 模型清单与本节任务

先把要交付的东西列出来，免得写着写着迷路。整个英译法案例里，模型侧一共五个函数：

| 序号 | 要写的东西 | 说明 |
| --- | --- | --- |
| 1 | 编码器 | 基于 GRU，本节要写的 |
| 2 | 无注意力（attention）解码器 | 注意力的第一个对照版本，只带一个上下文向量 $C$ |
| 3 | 带注意力解码器 | 对应 $C_1, C_2, C_3 \dots$ 逐位置变化的上下文向量 |
| 4 | 编码器测试 | 写完编码器立刻验证能不能跑通 |
| 5 | 解码器测试 | 同上 |

这一讲只做第 1 件：基于 GRU 的编码器。做完就先停，别急着往解码器冲——编码器能不能拼起来还没验过呢。

## 编码器的输入与输出

编码器这张图我不再另画一遍，因为我们前一天已经在桌面上画过了，重画一遍没有意义——把那张图打开，对着看就行。对着图，先用眼睛扫一遍：这里面应该有哪些东西？

- `input`：本次的输入。
- `previous_hidden`：上一时刻的隐藏状态。
- 中间是一个很眼熟的角色：词嵌入层（embedding层）。
- 然后是 GRU，它给出 `output`（本次的输出）和 `hidden`（本次的隐藏状态）。

设问一下：你本次输入的，肯定得是一个单词吧？把单词交给 GRU，GRU 就吐出一个输出。而这一套东西——`input` 进来、过一个词嵌入层、再进 RNN/GRU 出 `output` 和 `hidden`——跟我们前面讲 RNN 时玩的操作是不是一模一样？是。所以这一节真的不算难，`so easy`，不难受。

图里的颜色分工也要认准，它对应代码里的两类东西：

- 橙色（也就是黄色那一片）：张量。
- 蓝色：网络层。具体就是 `nn.Embedding` 和 `nn.GRU` 这两个。

```text
   input（单词索引）        previous_hidden
        |                        |
        v                        |
   +-------------+               |
   | nn.Embedding|  <- 蓝色：网络层
   +-------------+               |
        |                        |
        v                        v
   [ 词向量张量 ]  --------->  +-----------+
     橙色：张量                |  nn.GRU   |  <- 蓝色：网络层
                               +-----------+
                                 |       |
                                 v       v
                              output   hidden
                             （本次输出）（本次隐藏状态）
```

读图说明：橙色节点是数据（张量），蓝色方块是带有可学习参数的神经网络层；一行英文单词索引先被词嵌入层翻成词向量，再和上一时刻的隐藏状态一起送进 GRU，得到本次的输出与新的隐藏状态。

> **定义**：编码器（encoder）在这里就是一个"把整句源语言压成一个定长语义表示"的网络模块。在这个例子里，它的输出 `output` 是每个时间步的隐藏状态堆叠，`hidden` 是最后一个时间步的隐藏状态，也是后面要交给解码器的那个"中间语义向量"的载体。

### EncoderRNN 类的三步骨架

按代码推进的顺序，先定类名：`EncoderRNN`，继承 `nn.Module`。这个类的骨架就三步：

1. `__init__`：初始化两个东西——词嵌入层和 GRU 层。
2. `forward`：前向传播。
3. 初始化隐藏状态（`initHidden`）。

> **易错点**：为什么是两层网络而不是四层五层？因为左边这个编码器里就只有两个层要实例化。看到"层"字先问一句"谁的层"，别条件反射地凑数。

### init 里的两个层与三类参数

`__init__` 要接收 `input_size` 和 `hidden_size` 两个入参。

`input_size` 是编码器**词嵌入层的输入维度，也就是词汇表的大小**。这个词表大小我们前面已经算出来了——2803（英语侧词表）。别看到 2803 这个数字就以为是随便写的，它就是英文单词（严格说是词元）的总数。

`hidden_size` 是**隐藏层的维度**，128、256 都行，这里我们定 256。

> **提示**：`hidden_size` 和"层数"是两个东西。第 1 个参传 256，意思是"每个词用 256 个数字表示"；后面 GRU 的第 1 个参也传 256，意思是"输入特征维度是 256"；而层数是 `num_layers`，这里等于 1。数值一样，含义不一样——这是最容易混的地方。

`__init__` 里按顺序做四件事：

```python
import torch
import torch.nn as nn


class EncoderRNN(nn.Module):
    def __init__(self, input_size, hidden_size):
        # 初始化父类成员
        super(EncoderRNN, self).__init__()
        # 保存输入参数
        self.input_size = input_size   # 词嵌入层的输入维度，即词汇表的大小
        self.hidden_size = hidden_size  # 隐藏层维度 / 词嵌入维度

        # 词嵌入层：把单词索引转成词向量
        self.embedding = nn.Embedding(input_size, hidden_size)

        # GRU 层：输入特征维度 256，隐藏层维度 256
        self.gru = nn.GRU(hidden_size, hidden_size, batch_first=True)
```

四步分别是：`super()` 初始化父类成员；把 `input_size`、`hidden_size` 保存到 `self` 上；实例化 `nn.Embedding(input_size, hidden_size)`；实例化 `nn.GRU(hidden_size, hidden_size, batch_first=True)`。

`nn.Embedding` 的两个参数，意思完全不同：第 1 个是查表的总行数，也就是词汇表大小 2803；第 2 个是每一行有多少个数字，也就是词向量维度 256。查完表之后，一个编号就变成 256 个浮点数。

`nn.GRU` 的第 1 个参是输入的特征维度，我们喂进去的是 256 维词向量，所以传 `hidden_size`；第 2 个参是隐藏层维度，也传 `hidden_size`。这两个 256 数值相同但含义不同——前者描述"进来的东西有多宽"，后者描述"记住的状态有多宽"。

### batch_first 与三维批数据格式

`batch_first=True` 的作用是**把批次维度设为第 1 个维度**，即数据格式为 `(batch_size, sequence_len, hidden_size)`。

不加 `batch_first=True` 时，PyTorch 默认的格式是 `(sequence_len, batch_size, hidden_size)`——句子长度在前、批次在后。加了之后，批次大小跑到最前面。

举个数就明白了：形状 `(2, 3, 256)` 的意思是"我给你两个句子，每个句子有三个单词，每个单词用 256 维词向量表示"。如果是 `(3, 5, 256)`，就是"三句话，每句话 5 个词，每词 256 维"。先批次、再句子、再词向量——顺序记住，后面所有形状推断都靠它。

### forward 的两步与形状推算

`forward` 要传两个东西进来：本次输入和上一时刻的隐藏状态。参数名写成什么随你，`x` 也行，`input`/`hidden` 也行，但心里得清楚谁是谁——不会的话就把当初讲 RNN 时那张 12 个参数的图调出来，刻在脑子里，写代码时逐参对照。

- `input`：输入的单词索引序列，`(batch_size, sequence_len)`。比如之前见过的 `(1, 6)`：一个句子、句子里有 6 个单词。
- `hidden`：初始的隐藏状态，形状 `(num_layers, batch_size, hidden_size)`,这里就是 `(1, 1, 256)`：1 层、1 批、256 维。

第一步，过词嵌入层：

```python
    def forward(self, input, hidden):
        # 1. 词嵌入层：将单词索引序列转换为词向量
        output = self.embedding(input)   # (1, 6) -> (1, 6, 256)
        # 2. GRU 层处理，返回 GRU 层输出与最终隐藏状态
        output, hidden = self.gru(output, hidden)
        return output, hidden
```

`self.embedding(input)` 把 `(1, 6)` 的形状变成 `(1, 6, 256)`：6 个编号，每个编号换成 256 个数字。这是形状上唯一一次"升维"。

第二步交给 GRU。这里两个参数别搞混：`hidden` 是上面传进来的；`output` 要特别注意——它指的是上面 `embedding` 那个 `output`，也就是词向量张量，不是别的东西。所以 GRU 的两个入参是"本时刻的词向量"和"上一时刻的隐藏状态"。

出来之后把结果重新赋给 `output` 和 `hidden`，等于用旧 `output` 和旧 `hidden` 算出新的 `output` 和新的 `hidden`，省得外面再单独访问一次。这个写法跟前面讲 RNN 时完全一致。

**形状结算**（还是拿 `(1, 6)` 举例）：

| 张量 | 形状 | 含义 |
| --- | --- | --- |
| `input` | `(1, 6)` | 一个句子，6 个单词索引 |
| embedding 输出（即 GRU 的输入） | `(1, 6, 256)` | 6 个词向量，每个 256 维 |
| GRU 输出 `output` | `(1, 6, 256)` | 每个时间步一个 256 维输出 |
| GRU 隐藏状态 `hidden` | `(1, 1, 256)` | 1 层、1 批、256 维 |

> **结论**：`output` 的序列长度跟着输入句子的长度走，`hidden` 永远钉在 `(num_layers, batch_size, hidden_size)`。前面是"随句长变"，后面是"被参数定死"——记住这一条，后面看打印结果时就不会自己吓自己。

### 初始化隐藏状态

第三个动作是初始化隐藏状态，也就是把一开始那个 $h_0$ 技术性地初始化一下。

要造的是全零张量，形状 `(num_layers, batch_size, hidden_size)`，这里即 `(1, 1, 256)`。另外还要处理设备问题：`device` 的意思是把你这个张量迁移到 CUDA 环境里去。如果整个模型在 CPU 上跑，这一步用默认设备就是对的；要用 GPU，初始隐藏状态也必须跟模型在同一块卡上。

```python
    def initHidden(self, batch_size, device):
        # 初始化隐藏状态 h0：形状 (num_layers, batch_size, hidden_size) = (1, 1, 256)
        return torch.zeros(1, batch_size, self.hidden_size, device=device)
```

> **易错点**：初始隐藏状态造在 CPU 上、模型搬到 GPU 上，是最典型的"形状全对但一跑就报设备不一致"的错误。谁造张量，谁负责指定 `device`。

到这里，编码器的三个动作齐了：初始化网络层、前向传播、初始化隐藏状态。图 6 这一步——"构建基于 GRU 的编码器"——交付完毕。
