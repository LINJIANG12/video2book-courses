# 自注意力机制的代码实现与测试

自注意力机制的计算公式我们前面是专门讲过的，一句话就能写完：

$$\text{Attention}(Q,K,V) = \text{softmax}\!\left(\frac{QK^{\mathsf{T}}}{\sqrt{d_k}}\right)V$$

一个 softmax，里面先点积、再缩放，最后乘 $V$。无论是编码器还是解码器，中间那一块标着 multi-head attention 的结构，都建立在这个公式上。

那么写代码有什么难的？拿到 `512`，把 `matrix_qk` 那一堆套进去就行。真正会卡住你的只有一行——`masked_fill`。这一个函数我们上一节刚补齐，现在把注意力机制的代码真正写出来。

---

## 1 函数签名与四种输入的形状约定

回到 `demo02` 里面，接着往下写第四个动作：**定义函数，完成注意力机制的计算**。

```python
def attention(query, key, value, mask=None, dropout=None):
    """自定义函数，模拟注意力机制的计算"""
```

五个形参：`query`、`key`、`value` 是必须给的，`mask` 和 `dropout` 默认都是 `None`。

先看前三个的形状约定。

**查询向量（query，Q）**，形状通常是 `[batch_size, sequence_len, d_model]`，也就是批次、句子长度、词向量维度。

**键向量（key，K）**，形状和上面一样。

**值向量（value，V）**，形状也和上面一样。

> **定义**：自注意力机制（self-attention）中 $Q$、$K$、$V$ 三者**来自同一个输入**，是由同一份词向量分别经三套线性变换得到的，所以在实现里它们三个相等。

**掩码向量（mask）**，形状一般和 `scores` 匹配。`scores` 是 $Q$ 和 $K$ 算完之后的那个匹配分矩阵，掩码要盖的就是这份分数里的某些位置——盖 0 的位置还是盖 1 的位置，取决于我们传给 `masked_fill` 的布尔条件是什么。

> **提示**：有同学问「到底 0 是盖上还是 1 是盖上」，这个不用纠结，你自己说了算，想盖几就盖几。掩码的含义由你写的条件决定，不由函数决定。

`dropout` 就是随机失活，作用是防止过拟合，默认给 `None` 表示不做。

---

## 2 缩放因子 dk 的取法

第一个动作，定义查询向量的特征维度：

```python
dk = query.size(-1)
```

`query.size(-1)` 取的是最后一维的长度。上面说 `query` 的形状是「批次、句子长度、词向量维度」，所以最后一维就是词向量维度，也就是 $d_k$。

举个具体例子看得更清楚：假设 `query` 的形状是 `(2, 4, 512)`。

- 每批 2 句话；
- 每句话 4 个单词；
- 每个单词的维度是 512。

那么 `dk` 就是 `512`。

$d_k$ 这个量我们前面说过——**它管的是缩放**，而它本身的值就是词向量维度。忘了这一条的话，后面除以 $\sqrt{d_k}$ 那一步就没法解释了。

---

## 3 原始注意力分数的计算

第二个动作，计算原始注意力分数，也就是公式里的

$$\frac{QK^{\mathsf{T}}}{\sqrt{d_k}}$$

```python
scores = torch.matmul(query, key.transpose(-2, -1)) / math.sqrt(dk)
```

这里有两个函数要说明。

`torch.matmul` 是矩阵乘法，对应公式里的 $QK^{\mathsf{T}}$。

`key.transpose(-2, -1)` 是转置。`-2` 指的是倒数第二个维度，`-1` 是倒数第一个维度，写下这两个参数，意思就是**把最后两个维度交换**。

交换的过程是这样的：`key` 原来是 `(2, 4, 512)`，交换之后变成 `(2, 512, 4)`。而 `query` 是 `(2, 4, 512)`，两者相乘时，前者的 512 与后者的 512 做内积，结果的后两维就是「前者第二维 4」×「后者第三维 4」，也就是 $4 \times 4$。

> **提示**：为什么写成 `-2, -1` 而不是 `1, 2`？你写 `1, 2` 也能跑，但万一将来传进来的张量是二维的、或者维数不是三维，就会错误地交换到别的维度。倒着数，最后两个维度永远是「序列长度」和「维度」这两个，安全。

除号后面是 `math.sqrt(dk)`，开平方根，把 `dk` 丢进去就行，得到的就是 $\sqrt{d_k}$。注意这里是 `math.sqrt` 而不是张量的方法，因为 $d_k$ 是一个 Python 整数。

> **易错点**：转置必须在 `key` 上做，不能对 `query` 做。公式要的是 $QK^{\mathsf{T}}$，转置的是 $K$。写反了形状对不上，会直接报维度不匹配的错。

## 4 掩码处理与两类注意力的合并

第三个动作，掩码处理，两个字：**可选**。

```python
if mask is not None:
    scores = scores.masked_fill(mask == 0, -1e9)
```

先把 `masked_fill` 的规则复述一遍：给一个布尔条件，把条件为真的位置上的元素替换成第三个参数给的值。上一节我们用它处理过随机矩阵，这里处理的换成了刚算出来的 `scores`——匹配分算完了，跟那份「3 行 5 列」的测试数据是同一个位置上的事。

现在回答一个必然会冒出来的疑问：**编码器里根本没有掩码动作，你为什么要在这个函数里加掩码？**

因为我把三种注意力写成同一个函数了。编码器的注意力、解码器的注意力（带掩码的那种）、以及解码器的另一种注意力，**本质上一模一样，只多了「掩还是不掩」这一个差别**。所以我把 `mask` 传进来：

- 默认 `mask` 是 `None`，说明不做掩码，这就是一个普通的注意力机制；
- 想模拟带掩码的版本，把 `mask` 往里一丢，这段代码立刻变成带掩码的注意力。

这就叫通用版代码。当然，你也可以设计成两个函数，一个带掩码一个不带——那样写是对的、也可以，但结构上会显得冗余。**所以编码器里用不到掩码、掩码是解码器的事，而我在这里也把它写上，原因就是把两者合二为一。**

`mask == 0` 这个条件的意思是：把 `scores` 里被遮挡的位置设为负无穷——说「负无穷」听着吓人，实际就是**一个极小值**，比如我们写的 `-1e9`。

为什么用极小值、而不用真正的 0？因为后面紧跟着一个 softmax：

$$p = \text{softmax}\left(\frac{QK^{\mathsf{T}}}{\sqrt{d_k}}\right)$$

softmax 是归一化，把一串分数变成一串和为 1 的权重。被替换成极小值的那些位置，经过 softmax 之后**权重会被压到接近 0**。

那为什么要让权重接近 0？

因为注意力最终要把权重乘回 $V$：权重要是 0，$0 \times V$ 就等于 0，$V$ 那一坨信息就整个消失了。**我看不见 $V$ 是什么，就等于我没看见那个词。**

```text
   scores  ──masked_fill──>  遮挡位置 = -1e9
                                    │
                                    v
                              softmax(dim=-1)
                                    │
                                    v
                       遮挡位置权重 ≈ 0  ──× V──>  那部分信息被抹掉
```

读图：掩码不是在最后一步砍掉结果，而是在 softmax 之前把分数压到极小，让 softmax 自己把权重推到接近 0，再借「0 乘任何数都是 0」把对应位置的信息清干净。

这对应的正是**解码器里「不能看未来位置」的需求**：生成第三个词的时候，我只让你看到第一个、第二个词，第三个及其以后全都不让你看。

## 5 注意力权重与随机失活

第四个动作，计算注意力权重：

```python
p_attn = F.softmax(scores, dim=-1)
```

`scores` 只是拿到了中间那一堆——掩码也好、不掩也好，都还停在「分数」这一步。接下来把它交给 softmax。

`dim=-1` 的意思是**在最后一个维度上做归一化**，让每个 query 位置的权重总和为 1。

这个「最后一个维度」到底是哪一维，值得对一遍。`scores` 的维度经过上一步的转置与相乘之后，已经从「批次、句子长度、词向量维度」变成了「批次、词向量维度、词的个数」——它的最后两维是 $\text{sequence\_len}=4$ 和 $4$。所以 softmax 是在「词」这个角度上做归一化。

举个例子就清楚了：一句话有 4 个词，我们是在这 4 个词上算出各自的概率，也就是「将来这几个词各自的权重是多少」。

第五个动作，随机失活：

```python
if dropout is not None:
    p_attn = dropout(p_attn)
```

注意这里跟掩码是一样的，**也是可选**，做不做都行。

判据还是那个：一开始我把 `dropout` 设成了 `None`，意味着这时候的注意力就是一个普通的 QKV 计算。Q、K、V 这三个是你必须给的；后面这两个给不给，看需求——不给就不处理，给了就处理。

---

## 6 最终输出与返回值的两种用途

第六个动作，计算最终的注意力输出，也就是**权重加权求和**。

```python
return torch.matmul(p_attn, value), p_attn
```

softmax 做完了，把那个结果乘以 $V$，公式就整个算完了。`p_attn` 是 softmax 之后的那一堆概率，它乘 `value`，得到的就是注意力输出。

但返回两个值：

**第一个是注意力输出**，也就是加权求和之后的最终信息，可以理解为融合信息。

**第二个是注意力权重**，也就是 $p$ 那一份权重矩阵，它的用途是可视化，或者说调试。

那如果我不需要可视化注意力权重呢？那就把第二个返回值去掉，只返回融合信息就好。

> **结论**：`attention()` 把「缩放点积注意力」写成了一份通用实现——$Q$、$K$、$V$ 必须给，`mask` 与 `dropout` 可选；掩码在 softmax 之前把不该看的位置压成极小值，`dropout` 在权重上加随机失活，最后用权重乘 $V$ 输出结果，并附带返回权重供观察。

## 7 测试函数：复用位置编码的结果

注意力写完了，接着顺手把测试也写完。

定义 `use_attn()` 函数。第一件事是**获取数据**——先想清楚，你跑到这一层了，要交给注意力的是什么信息。

答案是我们前面处理过的结果：位置编码处理后的结果，也就是词嵌入层结果加上位置编码结果。那么，这个结果要不要从头再算一遍？

**不用。** 我们在 `demo01_input` 里已经把 position 测过了，在 `demo02` 里也做过自己的测试——我把 `(2, 4, 512)` 的词向量加上位置编码，最后返回的形状还是 `(2, 4, 512)`，而且那个函数最后 `return position_x` 返回的就是这份结果。既然如此，把那份代码拿过来用就行。

```python
from demo02 import *

position_x = position(...)
```

关于导包方式还有一个必须弄清楚的差别：

- `import demo02`：调用里面的东西要写模块名，`demo02.position(...)`；
- `from demo02 import *`：直接把里面的函数名引入当前命名空间，`position(...)` 就能用，不需要再写模块名。

第二种写法在这里的好处很明显——**一环套一环，后面只需要做一次简单的调用，不需要把前面算过的东西重复做一遍。**

第二件事，构造 Q、K、V。因为是自注意力机制，**$Q$、$K$、$V$ 都用同一个向量**：

```python
query = key = value = position_x
```

也就是说，这里进来的是位置编码处理后的 `(2, 4, 512)`，$Q$、$K$、$V$ 三者一模一样。初始的时候它们就是相同的。

第三件事，先做一次**没有掩码**的调用：

```python
result1, p_attn = attention(query, key, value)
print(result1, result1.shape)
print(p_attn, p_attn.shape)
```

`mask` 和 `dropout` 都不传，就是默认的 `None`。

输出值就不看了，一堆数字没什么意义，**我们主要看形状**。

注意力输出的形状，猜一下：它是跟 $V$ 乘过的，$V$ 的形状是「批大小、句子长度、词向量维度」，所以输出必然是 `(2, 4, 512)`。

注意力权重的形状是 `(2, 4, 4)`。

`(2, 4, 4)` 里最后的那个 4，是因为**你只有四个词**。这份权重表示的是**每个词对其他词的权重**：生成第一个词的时候，这四个词各自对我有多大影响；生成第二个词的时候，这四个词对我的影响；以此类推。

## 8 带掩码的调用与结果对比

第四件事，构造一个全 0 的掩码向量，看看效果。

先把上面那次调用注释掉，改成带掩码的调用：

```python
mask = torch.zeros(2, 4, 4)

result2, p_attn2 = attention(query, key, value, mask)
print(result2.shape, p_attn2.shape)
print(p_attn * 10)
print(p_attn2 * 10)
```

掩码的形状必须是 `(2, 4, 4)`——因为 `p_attn` 的形状是 `(2, 4, 4)`，你得跟它一样，位置才能对上号。

先看形状：`result2` 的形状跟 `result1` 一模一样，都是 `(2, 4, 512)`；`p_attn2` 的形状也还是 `(2, 4, 4)`。**形状一样，但里面的内容变了。**

为了把内容看清楚，我把两次的权重都乘以 10 再打印。看这次全 0 掩码下的权重：掩码之后，每个位置上的值变成了 `0.25`——因为四个词的位置差不多都被压平了，剩下的权重均分下来就是 $1/4$。

再看没有掩码的那一份：第一行是 `1 0 0 0`，第二行是 `0 1 0 0` 这样一路下去——生成某个词的时候，对第一个词的依赖最高、对第二个词依赖最高，依次对应下去。这就是「注意力权重」在掩码前后的样子：掩码前是 `1 0 0 0` 这样分明的分布，掩码后被压成 `0.25` 那样均分的值。

顺便把 `result1` 和 `result2` 也一起打出来看：`result1` 里你看到的是一堆小数，处理痕迹不明显；而有掩码的那一份，`target size` 同样是 `(2, 4, 4)`。注意，**`(2, 4, 4)` 这个尺寸是无掩码和有掩码两份权重共有的**——掩码不改形状，只改数值。有掩码的这份在处理完之后，看起来可能并不像你预期的那样「变成 0」，因为我们替换进去的是 `-1e9`，它会变成一个非常非常小的值，而不是干净的 0。

输出值实在太多、太零碎，这里就不再逐个打印了，等后面真正带进模型里的时候再看整体效果。**这一段主要看形状：`2 4 512`、`2 4 512`，形状都是一样的。**

而放进总结图里对比就更清楚了：`(2, 4, 512)` 那一份是没有用 mask 处理的注意力分布；下面那份权重分布，是改用 mask 处理之后的注意力分布——这里的 mask 是一个全 0 矩阵，处理后你会发现那些本来各不相同的值**已经变得一样了**，这就说明掩码处理确实生效了。

## 本讲提到的题目

**题目**：阅读这段程序，简单说明 `(2, 4, 4)` 的含义。

**解析**：这个形状要从一次矩阵乘法看起。`(2, 4, 512)` 与 `(2, 512, 4)` 相乘，两个矩阵相乘之后的形状取「前者的行」与「后者的列」，也就是 `(2, 4, 4)`。

`(2, 4, 4)` 里，第一个 2 是**两个句子**；第二个 4 是**每个句子有四个单词**；第三个 4 是**每生成一个单词时，其他单词对我的权重分布**。

拿两个句子举例：「我爱中国」「我爱武汉」。这两个句子就是 2。第一句占一个 $1 \times 4 \times 4$，第二句再占一个 $1 \times 4 \times 4$，拼起来正好是 $2 \times 4 \times 4$。

再看单句内部。以「我爱中国」为例，第一行取「我」这个字，「我」和这四个字——我、爱、中、国——的关系，就是 $1 \times 1 \times 4$；下一个换成「爱」这个字，「爱」和这四个字的权重还是一个 $1 \times 1 \times 4$。把这一句里所有的 $1 \times 1 \times 4$ 组合起来，就是 $1 \times 4 \times 4$；两句话自然就是 $2 \times 4 \times 4$。

**答案**：`(2, 4, 4)` 表示两句话、每句话四个单词，每个单词与其他四个单词之间的权重分布，也就是依赖关系。
