# 文本数据分析：标签数量分布的可视化统计

文本预处理讲到这儿，进入下半部分了：文本的数据分析、文本的特征处理，还有文本的数据增强。还记得那句话吗——**对文本做处理之前的第一个动作，就是先做一遍文本的数据分析**，看看数据的分布情况，再决定下一步具体怎么动手。下面的顺序就是按这个逻辑来的：先看标签分布、句子长度分布、词频和词云，再讲特征处理里的 n-gram 和文本长度规范，最后是数据增强里的回译增强。这一讲只落在第一块，而且**只查看、不做处理**。

## 文本预处理的下半部分

先把下半部分的路线交代清楚，后面几讲都挂在这三条线上。

第一块是**文本数据分析**，要看四样东西：标签数量的分布、句子长度的分布、单词总数与词频、关键词词云。

第二块是**文本特征处理**，代表性的是 n-gram 这一族特征，比如 1-gram、2-gram、3-gram 等等；还有文本长度规范。长度规范怎么定？比如上面做完句子长度分布，发现长度大多在 50 左右，那就可以拿 50 当固定长度——**超过 50 的截断，不够 50 的补齐**。

第三块是**文本数据增强**，典型手段叫回译增强。数据量不够的时候，用多方翻译再翻回来的方式造数据：一条中文样本先翻成法语，再翻成德语，再翻成葡萄牙语这类小语种，最后翻回中文。翻回来你会发现意思比较相近，可用的话术却不一样了——数据量就这么加上去了。

## 数据分析的作用与两类常见问题

文本语料的数据分析能干什么？一句话：**帮我们理解数据语料，快速检查出语料中可能存在的问题**，并且指导模型训练过程中一些超参的选择。举两个最直接的例子：标签 $y$ 的分布是否均匀？特征 $x$ 里面有没有噪声数据？

把常见问题归归类，大体两大类：

| 问题类型 | 具体表现 | 处理方向 |
| --- | --- | --- |
| 数据质量类 | 错别字、语法错误、重复内容、缺失值、噪声数据 | 清洗、去重、修正 |
| 分布不均衡类 | 标签分布不均；句子长度分布异常 | 数据增强或删减；截断或补齐 |

句子长度为什么也算问题？因为它两头都难受：**过短没有意义**，一两个字的句子分析起来本身就有歧义；**过长又难处理**。所以正确的做法是找一个折中——看看句子整体集中在多长，长的截断、短的补齐。

针对这些问题，分析方式也有三个，一会儿全都写进同一个 demo 里：

- 标签的数量分布：画柱状图，看各个类别分别有多少个；
- 句子的长度分布：柱状图、直方图、密度图都可以；
- 词频统计与关键词词云：也是绘制出来的。

整条链路想一想其实很清楚：

```text
文本语料 ──► 数据分析（只查看，不处理）
                 │
                 ├─ 标签数量分布 ──► 均衡还是不均衡 ──► 增强 / 删减
                 ├─ 句子长度分布 ──► 集中在多长   ──► 截断 / 补齐
                 └─ 词频与词云   ──► 关键词是谁   ──► 决定后续特征动作
                 │
                 ▼
            指导模型训练的超参选择
```

读图说明：分析环节只负责"看出来"，不负责"改数据"；每一种图表都要落到一个能执行的结论上——比例不均衡就调整数据，长度有集中区间就定固定长度。

## 中文酒店评论语料：0 是差评，1 是好评

我们用的数据集是**中文酒店评论语料**，属于二分类的中文情感分析语料：要么好评，要么差评。那 0 是好还是坏？直接给答案：**1 是积极的（好评），0 是消极的（差评）**。

有人会问，我怎么知道哪个是好评？看内容自己分析。看这几条：

- "早餐不好服务不到位，晚餐无……条件不好，餐厅部分……"——看着全是吐槽，那肯定是差评，对应 0；
- "去的时候酒店大厅和餐厅在装修，本来该享受的也没享受到……"——但最后跟了一句"前台服务人员态度挺好的"，这条给的是好评；
- "有很长时间没来新奥大厦住了，以前……网络不好……其他还好"——先吐槽几点，末尾说其他还好，这条也当好评论处理。

现在很多 App 处理好评差评是怎么做的？靠打星。你给它夸得天花乱坠，只要那个星你选的是一星，它照样把你归到差评里。所以基于文本内容做模型分析，这件事的意义就出来了——**它比单纯数星星可靠得多**，这也是我们做 NLP 要解决的问题。

数据文件是 `train.tsv`，里面两列：**第一列是评论内容（特征），第二列是评论的状态，也就是标签**。训练集之外还有验证集，标签口径一致。放到项目里就是 `data` 目录下那三个 tsv 文件，全部拷过去。

## 正负样本比例为什么要盯住 1:1

实际开发中，训练深度学习模型解决分类问题，一般需要把**正负样本比例维持在 1:1**。

为什么要说这个？打个班里的比方。假定班里 50 个男生、45 个女生，虽然没有达到精确的 1:1，但这个比例已经非常非常接近了，这种情况拿去做分类就比较好处理。可要是 70 多个男生、女生只有个位数，那就已经严重失衡了。

那失衡怎么办？想一想上一段叫过的动作——**数据增强，或者删减**。要么再去"招一些女学生"，要么从男生里挑七个、八个出来，让数量跟女生基本持平，再做分析。

回到我们的数据：训练集和验证集里，正负样本都**稍有**不平衡，可以做一下数据比例的调整。但注意用词，是微调，不是大调——这个比例其实已经非常接近 1:1 了。

## csv 与 tsv：只差一个分隔符

在写读数据的代码之前，先补一个很小的知识点：tsv 文件。csv 大家见得多，tsv 可能没碰过，其实它就是分隔符的问题。

拿一张小表演示一下，内容是姓名、年龄、性别，三行数据：

```text
name,age,gender
乔峰,38,男
虚竹,28,男
段誉,18,男
```

问一个问题：这个文件的分隔符是谁？是逗号。所以把它存成 `.csv`，双击打开就是整齐的三列。

那把它改成 `.tsv` 呢？打开一看完蛋了——**全挤成一列**。为什么？因为 **tsv 认的分隔符是 `\t`（Tab 键），它不认识逗号**。想让 tsv 也显示成三列，就得把里面的逗号全部换成 Tab 键（用记事本打开，批量替换一下最省事）。

所以结论就一句：

> **结论**：csv 与 tsv 的区别只有分隔符——**csv 用逗号分隔，tsv 用 `\t` 分隔**，其他用法一模一样。

这份酒店评论数据就是 tsv 格式，打开以后你会发现它不是用空格隔开的，而是 `\t`：第一个是句子（也就是特征），后边第二个是 `label`（标签，0 差评、1 好评，说消极积极也行）。

## 读取训练集与验证集

读数据用 `pandas`。这里有个坑：**没有 `read_tsv` 这个函数**。因为 csv 和 tsv 只差一个分隔符，官方在写文件读取的时候统一都用 csv 那套，靠一个参数把分隔符换掉就行：

```python
train_data = pd.read_csv('./data/train.tsv', sep='\t')
dev_data = pd.read_csv('./data/dev.tsv', sep='\t')
```

`read_csv` 的第二个参数就是**列分隔符**：csv 文件用逗号（默认值），tsv 文件就用 `\t`，所以必须显式写出来。

读进来先看一眼前几条：

```python
print(train_data.head())
```

`head()` 是查看前几条数据，默认给 5 条。跑出来就是 0 到 4 这五条：先是句子内容，后边跟着它的标签。看到"早餐不好……三里三地"这些内容，心里就有数了。确认没问题，把这行 `print` 注释掉。

## 计数柱状图：统计标签分布

现在统计训练集里标签 0（负样本）和标签 1（正样本）各有多少个，用计数柱状图：

```python
def dm01():
    sns.countplot(x='label', data=train_data, hue='label', legend=False)
    plt.title('train_label')
    plt.show()
```

四个参数逐个交代：

- `x='label'`：x 轴的标签；
- `data=train_data`：数据集，从训练集里出数据；
- `hue='label'`：用于分组的分类变量，也就是**按 label 分组**，0 一组、1 一组；
- `legend=False`：是否显示图例，它默认为 `True`，这里关掉。

然后是设置标题 `plt.title('train_label')`，最后 `plt.show()` 把图画出来。跑一下，出来的就是标题为 `train_label` 的计数柱状图，两边柱子高度差不多齐平——这就是前面判断"正负样本稍有不平衡"的依据。

同一个函数顺手把验证集也统计一遍，写法只改数据源：`x='label'`、`data=dev_data`、`hue='label'`、`legend=False`，标题、布局、`show` 照旧。

图出来之后有个现象值得问一句：为什么这里 0 和 1 的颜色不一样？为什么差评是蓝色、好评是红色？——**靠的就是 `hue`**。`hue` 的作用就是分组，按 label 分成 0 和 1 两组，不同组给不同颜色。颜色不是我们手动指定的，是分组分出来的。

## 绘图风格与紧凑布局

讲义上还带了一个可选动作：设置 538 风格。

```python
plt.style.use('fivethirtyeight')
```

538 风格是一种具有现代感的可视化风格。但**不做也行**，讲义上有，我就把它写一下。

它到底值不值？自己动手比一比最快：先加上这一行跑一次，截图；再把它注释掉跑一次，截图；两张图对着看。你会发现加上 538 之后背景变灰了，字体和图的大小也稍微不一样，至于哪个好看——每个人有每个人的审美，你觉得下面那张顺眼，就把上面那行注释掉，无所谓的。

不过 538 风格确实有个副作用要处理：**它把 x 轴的 label 吃掉了一半**。默认风格下没被吃掉，538 风格下被吃掉一部分。这时候就轮到之前讲过的**紧凑布局**上场：

```python
plt.tight_layout()
```

加上 `tight_layout()`，被挤压的坐标轴标签就露出来了，整体观感也整齐。它属于可选项，所以我看代码里都把它放到后边——需要的时候再补上。
