# Word Embedding 获取词向量：从分词到词嵌入层

关于文本张量的表示方法，我们到这里已经讲完了：稀疏的有 one-hot 这种词向量表示法，稠密的有 Word2Vec、Word Embedding 这些词向量表示法。那接下来要做一件事——把文本张量可视化出来，绘制一个 PCA 主成分分析的图解。

先说清需求。有这样两个句子：

- `传智教育是一家上市公司，旗下有黑马程序员品牌`
- `我在黑马这里学习人工智能`

要做的事是三步：对这两句话分词，把每个词转成张量（也就是词向量的形式），再把这些词绘制出来。绘制出来干什么？回答一个很具体的问题——"黑马"这个词和"品牌"这个词，距离是多少？相似度是多少？哪个词跟哪个词比较接近？所以整个案例的流程是：先把两个句子切词，切完以后把两个句子的词合并并去重，再去重后得到 20 个单词并做编号。

案例最终做出来的效果，就是可视化界面中间那一堆点：`上市公司`、`爱`……它们就是刚才切完词得到的那 20 个词。我点一下"黑马"，界面上就会出现 `nearest points`（近邻的点），它会告诉你哪个词跟你的距离大概是多少，比如"这里"跟你的距离、`一家` 跟你的距离。这个图就是 TensorBoard 可视化，本质上是一个 PCA 主成分分析的图解，里面还能做很多其他设置。

import torch

## 文本分词处理

第一步，定义变量记录待处理的文本。两个句子我不打算手敲——练打字磨手指头没必要，直接粘贴：

```python
sentence1 = '传智教育是一家上市公司，旗下有黑马程序员品牌'
sentence2 = '我在黑马这里学习人工智能'
```

第二步，把两个句子封装成列表，因为后面要整体处理：

```python
sentences = [sentence1, sentence2]
```

第三步，使用 jieba 分词。定义变量 `word_list` 记录分词后的数据，即词语列表，然后遍历句子列表，把每个句子的分词结果添进去：

```python
word_list = []
for sentence in sentences:
    word_list.append(jieba.lcut(sentence))
print('分词结果：', word_list)
```

这里是 `append` 而不是 `extend`，这一点必须分清楚。

> **易错点**：如果写成 `extend`，两个句子的词会被摊平混在一起，句子边界就没了；用 `append` 是把每个句子的分词结果整体作为一个元素加进去，得到的是嵌套的两层结构。

结果形状是这样的：

```text
[ [句1的词1, 句1的词2, 句1的词3, ...],
  [句2的词1, 句2的词2, 句2的词3, ...] ]
```

打印出来核对一下：这是两个句子切完以后所有的词，一共 20 个。20 个词里，第一句占一部分，第二句占一部分。两个句子允许有重复的词——比如第二个句子里有"我"，第一个句子里也有"我"，这个没问题，去重是在下一步统一做的。

## 构建词汇映射与文本数值化

第四步，构建词汇表，进行文本数值化。说白了，就是把词换成一个编号。

初始化词汇映射器：

```python
my_tokenizer = Tokenizer()
```

有了它以后要做一个拟合动作：`fit_on_texts`。这一步统计词频并构建词汇表。注意这里往里扔的必须是 `word_list`，不是 `sentences`。

```python
my_tokenizer.fit_on_texts(word_list)
print('word_index 映射关系：', my_tokenizer.word_index)
```

> **易错点**：把原始句子 `sentences` 交给 `fit_on_texts`，构建出来的词表不是按词切的，映射关系就不对了。要扔的是已经分好词的 `word_list`。

查看映射关系，得到的是一个"词 → 编号"的字典。核对一下数量：这里一共 20 个词。如果上一步扔错了对象，这个字典的规模立刻就不对，所以这一步的输出值得看一眼。

获取去重后所有词汇的列表：

```python
my_token_list = list(my_tokenizer.word_index.values())
```

`word_index` 是字典形式：要所有的键就用 `keys`，要所有的值就用 `values`。换言之，这里拿到的是 1、2、3……一直到 20 这一串编号。它的外层类型是 `dict_values`，里面装的确实是列表形式的值，所以可以在外面再包一层 `list`。

接着做这一步的关键动作——把分词后的文本转成数字序列：

```python
sequence = my_tokenizer.texts_to_sequences(word_list)
print('文本转成数字序列：', sequence)
```

原来的句子是中文，现在用编号来表示它。"传智"是几号就写几，"教育"是几号就写几，逐词对应。第一句的词全部换成编号是一行，第二句是一行——因为 `texts_to_sequences` 的入参是嵌套的句子列表，所以输出也是嵌套的。两个句子里重复出现的"我"会共用同一个编号，这正是我们要的效果：同一个词在任何句子里，都对应同一个编号。

## 创建词嵌入层

到这一步才轮到词嵌入层。它要做的事是：把文本（即词对应的编号）转成词向量。

回忆一下我们在 RNN 里说过的那句话——词嵌入层没法直接把文本转成词向量，它得先把文本对应的那个编号转成词向量。这就是为什么前面要多做那两步：先切词，再把每个词转成数字。现在，一个数字终于可以喂给它了。

创建词嵌入层对象：

```python
embed = nn.Embedding(num_embeddings=len(my_token_list), embedding_dim=8)
```

两个参数的含义：

- 参数一 `num_embeddings`：词汇表的大小，即唯一词的个数。这里写 `len(my_token_list)`，不要写死 20——万一词表变了呢？
- 参数二 `embedding_dim`：词向量的维度，这里取 8，即每个词用 8 个数字来表示。

查看词嵌入层的权重参数，它就是词向量本身：

```python
print(embed.weight.data)
print(embed.weight.data.shape)
```

形状是 $20 \times 8$。为什么？一共 20 个词，每个词用 8 个数字表示，所以是 $20 \times 8$。矩阵的每一行对应一个编号的词，这一行的 8 个数就是那个词的词向量——这个权重矩阵本身就充当了一张"编号 → 词向量"的查找表，喂给它一个编号，它就还你一行 8 维的向量。

```text
文本处理链路

分词后的中文文本
      |
      | 1. jieba.lcut 切词 + append 装进 word_list
      v
[ [句1词...], [句2词...] ]          嵌套词列表
      |
      | 2. Tokenizer.fit_on_texts(word_list)
      v
词 -> 编号 的映射字典（20 个词）
      |
      | 3. word_index.values() -> my_token_list（1..20）
      | 4. texts_to_sequences      -> 数字序列
      v
[[4, 5, 1, ...], [3, ..., ...]]     纯编号的文本
      |
      | 5. nn.Embedding(num_embeddings=20, embedding_dim=8)
      v
embed.weight.data  ->  20 x 8 的词向量矩阵
```

读图说明：链路前四步都在把"中文文本"一步步降级成"编号序列"，第五步才用编号去查词嵌入层的权重矩阵，取出每个词的向量。

跑一下看权重矩阵：第一行 8 个数是第一个词的词向量，第二行是第二个词的，第三行是第三个词的，一共 20 行。

到这里 Word Embedding 就实现了。不过还有一步别忘了——写到这儿，跟以前做 RNN 案例有什么区别？没有任何区别，这不就是 RNN 那个词嵌入层的动作吗？
