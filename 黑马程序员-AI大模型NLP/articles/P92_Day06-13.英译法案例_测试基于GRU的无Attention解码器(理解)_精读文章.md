# 无注意力 GRU 解码器的测试：形状校对与逐词解码

无注意力版的 GRU 解码器代码写完了，接下来要做的事只有一件：把它跑起来，看看它到底吐出来什么。测试不是为了"证明代码是对的"，而是为了**把每一层的形状都亲眼看一遍**——看懂了形状，你才知道中间语义张量 `c` 是怎么算出来的，也才知道后面加注意力的时候该往哪儿插。

---

## 测试函数的分步骨架

先给函数体一个骨架，剩下的都往里填：

```python
def demo_test_decoder():
    # 1. 获取数据集加载器
    mydataloader = get_dataloader()

    # 2. 初始化编码器模型，并移动到 GPU
    # 3. 初始化解码器模型，并移动到 GPU
    # 4. 打印模型结构
    # 5. 完整的编码与解码流程测试
```

> **易错点**：我这里测的是**解码器**，为什么第二步却要先初始化**编码器**？因为中间语义张量 `c` 是由编码器生成的——你得先把编码器那一趟跑完，才能拿着 `c` 走后边的解码器。测右边，就得先把左边造出来。

另外记住 `.to(device)` 的写法：不要先创建对象、下一行再写 `my_encoder = my_encoder.to(device)`。**在对象创建表达式的末尾直接接上 `.to(device)`** 就够了。

## 编码器与解码器的初始化

```python
input_size = English_words_n                  # 2803，英文词汇表大小

my_encoder_gru = EncoderRNN(input_size, hidden_size).to(device)

my_decoder_gru = DecoderRNN(French_words_n, hidden_size).to(device)
```

编码器吃的是英文词表大小 2803，因为英译法的**左边是英文**；解码器吃的是法语词汇表大小 4345，因为**右边是法语**。两个模型的隐藏层维度都是 256 —— 这一项必须对齐，否则 `c` 交到解码器手里形状就对不上。

> **提示**：如果换成 CPU 环境，`.to(device)` 这行可以不管；只要是 GPU 环境，这一行是必须写的。

---

## 打印模型结构：编码器为什么没有输出层

保险起见先把两个模型都 `print` 出来。编码器打印出来的三层是这样的：

| 层 | 维度 | 含义 |
| --- | --- | --- |
| `embedding` | 2803, 256 | 英文词汇表 2803 个词，每个词转成 256 维词向量 |
| `gru` | 256, 256 | 前一个 256 是输入维度（词向量维度），后一个 256 是输出维度（隐藏层维度） |

一眼就能看出：编码器**只有词嵌入和 GRU 两层，没有 `out` 那层**。这正是它和传统 RNN 用法不一样的地方——传统写法里 GRU 后面还要挂一个线性层做输出，这里**不挂**。

为什么不挂？因为编码器处理完的结果就是"中间语义张量 `c`"，它是往后**交给解码器继续干活**的，不是拿来做最终预测的。一旦挂上输出层，就直接出结果了，那 `c` 也就不再是原汁原味的隐藏信息了。

```text
编码器（EncoderRNN）
    输入 x (1, seq_len)
      │
      ▼
    embedding(2803 → 256)
      │
      ▼
    gru(256 → 256)          ← 到此为止，没有 out 层
      │
      ▼
    原样返回：c
```

读图说明：编码器只有词嵌入和 GRU 两个动作，中间不做任何降维或线性变换，GRU 算出来的结果原模原样交出去，这就是中间语义张量 `c`。

解码器打印出来是三层：

| 层 | 维度 | 含义 |
| --- | --- | --- |
| `embedding` | 4345, 256 | 法语词汇表 4345 个词，每个词转成 256 维 |
| `gru` | 256, 256 | 与编码器相同 |
| `out` | 256, 4345 | 把 256 维词向量映射成 4345 个法语词的概率 |

`out` 那句的含义是：**把预测到的那个词的 256 维词向量，映射成 4345 个词各自的概率**，然后从这个概率里挑最大的一个作为最终结果。

> **提示**：打印出来的维度里，`2803` 是英文单词总数（英文词汇表大小），`256` 是每个单词用多少维来表示，也就是词向量维度。GRU 那两个 `256` 分别对应"输入维度"和"输出维度"，后者其实就是隐藏层维度。如果你觉得 256 和 256 长得太像容易看晕，那就把隐藏层维度换成 512 或 128——两个数不一样了，后面往下写就清爽很多。

---

## 隐藏状态就是一切：解码器只用一层线性层的原因

看解码器结构时会撞上一个问题：GRU 后面为什么不接 `output` 输出那一步，直接上 `out` 线性层？

因为**隐藏状态里已经装着接下来要生成的那个词的全部信息**。回忆一下 RNN 的两步机理：

$$\text{本次隐藏状态} = \tanh(W \cdot [\text{上次隐藏状态}, \text{本次输入}] + b)$$

$$\text{本次输出} = \text{softmax}(W_o \cdot \text{本次隐藏状态} + b_o)$$

写公式的时候看着是一步到位、一口气全给你，但**底层其实是先算本次隐藏状态、再算本次输出这两个动作**。所以顺序永远是：

```text
s0（初始隐藏状态）
   │  + welcome（本次输入）
   ▼
  s1 ──────────► 输出 welcome
   │  + to（本次输入）
   ▼
  s2 ──────────► 输出 to
   │  + beijing（本次输入）
   ▼
  s3 ──────────► 输出 beijing
```

读图说明：先由上次隐藏状态和本次输入算出本次隐藏状态，再由本次隐藏状态算出本次输出。有了 `s1` 就能算 `welcome`，有了 `s2` 就能算 `to`，有了 `s3` 就能算 `beijing`——这就是"基于隐藏状态预测词"的来历。

> **注意**：真正调用这一层的时候，框架永远让你写成"把本次输入和上次隐藏状态一起传进去"，它一次把本次隐藏状态和本次输出都还给你。底层那两个动作是分开算的，但接口上它是合一的，这一点不用跟它较劲。

所以解码器的逻辑就顺下来了：GRU 交出的隐藏状态 → `out` 映射成 4345 维 → 4345 个法语单词的概率 → 挑概率最大的那一个，就是本次预测结果。这和结构图上"1×4345 转成概率、得到 一个词"完全对应。

## 完整的编码与解码流程

前面的模型只是"造出来了"，还没干活。接下来走一遍完整流程，分四步。

### 从加载器里取一个批次

```python
for i, (x, y) in enumerate(mydataloader):
    print(f"输入的数据信息（英语句子）：{x.shape}")
    print(f"输入的数据信息（法语句子）：{y.shape}")
```

一个批次的样本就是一条数据——相当于从样本集里随机扒一条过来：**左边英文，右边法文**。这里只打印 `shape` 不打印内容，内容打出来信息量太大、看着难受；只看形状，一眼就能看出配对关系：

- `x.shape = (1, 6)`，`y.shape = (1, 7)`：六个英文词，生成七个法文词；
- `x.shape = (1, 9)`，`y.shape = (1, 10)`：九个英文词，生成十个法文词。

打印完记得 `break`，不然会把整个数据集刷满屏。

### 编码过程：把英文句子压成中间语义张量 c

```python
h0 = my_encoder_gru.initHidden(x.size(0), device)

encoder_output, encoder_c = my_encoder_gru(x, h0)

print(f"编码器输出 c：{encoder_c.shape}")
```

先调 `initHidden()` 拿到初始隐藏状态 `h0`，再做编码器前向传播，得到的输出就是**中间语义张量 `c`**。

为什么编码器的输出可以直接当 `c` 用？因为它这一趟只做了词嵌入和 GRU，**没有 `out` 层做降维**，交出来的就是 GRU 处理后的原始信息，没有任何加工。

这一步的形状是可以直接推出来的。`x` 是 `(1, 6)`，所以：

```text
x (1, 6)  ──embedding──►  (1, 6, 256)  ──gru──►  (1, 6, 256)  ──►  c
```

读图说明：`(1, 6)` 经过词嵌入变成 `(1, 6, 256)`；GRU 保持形状不变，输出的 `c` 就是 `(1, 6, 256)`。如果 `x` 是 `(1, 9)`，`c` 就是 `(1, 9, 256)`；`(1, 7)` 对应 `(1, 7, 256)`。

这 6 个 256 维向量里装的是什么？**每个英文单词的词向量形式，以及 GRU 处理后的语义关联与隐藏状态信息，全都在里面**。这就是它被称为"语义张量"的原因。

### 最后一个时间步的隐藏状态

真正交给解码器的，是 `c` 里面最后一个时间步的信息：

```python
print(encoder_c[0][-1].shape)
```

`encoder_c` 是 `(1, 6, 256)`，逐层剥：

- `[0]` 取第一个样本，形状变成 `(6, 256)`——六个时间步，每步 256 维；
- `[-1]` 取最后一个时间步，形状变成 `(256,)`。

> **结论**：这 `(6, 256)` 里记录的是 $h_0, h_1, h_2, \dots$ 依次递推的结果，而最后那一个 256 维向量就是最终的隐藏状态——**它已经包含了前面所有时间步的信息**。所以后面解码只需要这一个向量。

### 逐词解码：把隐藏状态解成法语句子

解码是**逐个字符（逐词）生成**的，走不了捷径：

```python
for i in range(y.shape[1]):
    temp = y[0][i].view(1, -1)
    output, hidden = my_decoder_gru(temp, hidden)
    print(output.shape)
```

`range(y.shape[1])` 里的 `y.shape[1]`：`y` 的形状是 `(1, 7)`，取下标 1 就是 **7**，也就是目标句子的长度。所以 `i` 从 0 到 6 走一遍。

这一步为什么必须显式控制长度？因为如果没人告诉它"这句话一共七个词"，它可能会一路往下生成到 `(1, 10)`、`(1, 100)` 停不下来。**我把长度告诉它，它一个词一个词帮我生成**，就这么简单。

`y[0][i]` 是取出整批中第一个样本的第 `i` 个词的索引，比如第一次是 `y[0][0]`，第二次是 `y[0][1]`。取出来的东西是一个**标量**，形状是 `()`。而解码器要求输入至少是二维的，所以后面接 `.view(1, -1)`：`1` 是一行，`-1` 是列数由框架自己算——反正就一个数，转完就是 `(1, 1)`。

```text
y (1, 7)
   │  y[0][i]        取出第 i 个词的索引
   ▼
标量 123
   │  .view(1, -1)   匹配 embedding 的输入要求
   ▼
(1, 1)  ──►  [123]
```

读图说明：从 `(1, 7)` 里按下标取出一个词的索引，得到一个标量；再用 `view(1, -1)` 把它变成 `(1, 1)` 的二维张量，这个形状正是解码器 `embedding` 层要的输入。

于是循环就长这样：第一次把 `123` 送进去，算出第一个预测；第二次 `i` 变成 1，把 `297` 送进去，算出第二个预测；再下一次把 `126` 送进去……每一步都拿到那一时刻的输出，最后把整个句子的每个词都覆盖到。

### 解码器前向传播与打印

```python
output, hidden = my_decoder_gru(temp, hidden)
print(output.shape)
```

前向传播为什么必须写？因为上面刚把词索引转成 `(1, 1)`，正处在结构图上"进入解码器"的位置，不算它等什么呢。

这里有个必须注意到的地方：**`hidden` 不是随便给的，它就是编码器的输出**。往上翻，这个 `hidden` 是编码器前向传播交出来的那一个——也就是上面的 `s0` 其实等于编码器算出的最终隐藏状态。这正是为什么要先用编码器初始化一遍：**解码器的起点，用的是编码器的终点**。

打印输出时，`output.size()` 和 `output.shape` 拿到的东西一模一样，两种写法没有区别。为了好读可以多打几个换行：

```python
print(f"预测第{i + 1}个法语单词的概率分布：{output.shape}\n\n")
```

注意下标写的是 `i + 1` 而不是 `i`，因为 `i` 是从 0 开始的，而我们要数的是"第几个法语词"。这样打出来的是形状，不是概率值本身——**单词量太大，只打形状就够看清结构了**。

## 跑出来的结果怎么读

随便找一组打印结果，比如英文 7 个词、法文 8 个词的那一组：

- `output` 的形状是 `(1, 1, 4345)`，也就是该时间步对所有 4345 个法语单词的一个概率分布；
- 循环跑了 8 次，就对应法语句子第 1 个词、第 2 个词……第 8 个词各自的概率分布；
- 在每一个 `(1, 4345)` 里挑概率最大的那个词，就是该位置的预测结果。

这就是完整的预测动作：**在这个概率分布里找到最大的那一个，再去 4345 个法语词汇表里把对应的词取出来，拼起来就是生成的句子**。

> **结论**：说明句子有几个单词，就让它生成几个单词——长度是我定的，不让它自己任性发挥。

## 这次测试真正验证了什么

到这里模型的训练和预测其实都通了：预测就是从概率分布里取最大、查词表、拼接句子。

但别忘了，**这才只是测试，还没训练**。只做这一步还不能叫人工智能——那叫人工智障。

不过测试本身已经完成了它的使命：**编码器和解码器这套代码能测通，说明两个模型的形状、接口与数据流全都没有问题**，可以放心进入下一步——在同一个解码器上加注意力机制，再重写一遍。唯一要记住的是：现在这一版，是**没有注意力**的解码器。
