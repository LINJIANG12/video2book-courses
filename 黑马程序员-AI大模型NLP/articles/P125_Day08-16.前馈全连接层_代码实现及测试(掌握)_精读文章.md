# 前馈全连接层的搭建与测试：两次线性变换里的升维与降维

这一块内容本身的代码量很小——两个线性层，一个先升维、一个再降维。但它的设计意图值得掰开讲，因为为什么要升维、为什么升完必须激活、为什么不能一口气从 2048 直接压回 512，这几个问题的答案决定了你到底是在“背代码”还是在“懂架构”。

先把结论放这儿：前馈全连接层干的事，用四个字就能说完——**强化特征**。

## 升维再降维的直观类比

这个结构做的事，是把词向量维度从 512 拉高到高维，比如 1024、2048、4096、8192 都是常见取值，然后再压缩回 512。

怎么理解这件事？假设我们现在都只坐在教室里单纯地学这些知识点。明天我预约了阿里的参观团，后天预约了字节的，接下来一周我们一天去一个大厂，去感受一天，看看将来真正到了岗位上要做的是哪些事。等参观一周之后再坐回这个教室，你还是你，但是你的**阅历和眼界**不一样了，你对这个行业会开始有自己清晰的认知。

前馈全连接做的就是这个事情。

再换个例子。前段时间我儿子有点厌学，我就带他去我们那边的一些大学看。他一进大学就叫：“哇，这个学校好大！这个操场比我们学校都要大！”因为幼儿园不会把园区建得特别大——小孩跑起来不好管理。看完了我就问他，将来想来这儿上学吗？他说想。我说那你得好好学习。

你经历过“高维”，再往下来做，就像那句老话：**由俭入奢易，由奢入俭难**。先让你升维，再让你降维，中间你就学到了更多的信息。

## 为什么要加这两层网络

作用写在明面上：注意力机制可能对复杂过程的拟合程度不够，所以加两层网络来做补充。

但马上有个问题——**为什么是两层？为什么不做三层、四层？**

说实话，这还是一句话：**实验试出来的**。这话听着不太过瘾，但架构里的超参选择很多时候就是这么定下来的。

正式的名字叫 `Position-wise Feed Forward`，里面就两个全连接层。`d_model` 是多少大家心里都有数：512。那 `d_ff` 呢，一般要比 512 大。**你如果做得比 512 小，那就别做这个事了**，一般是要大的。

> **定义**：前馈全连接层（Position-wise Feed Forward Network，FFN）是紧跟在注意力子层之后的两层全连接网络，第一层把 `d_model` 升到 `d_ff`，第二层再降回 `d_model`，逐位置对特征做强化。

## 与架构图的对应关系

回头去看那张 Transformer 架构图，把代码和图对起来看，认知会不一样——今天晚上你们把代码和这张图结合着再走一遍。

前馈全连接在这张图里的位置，是对**每个位置的词向量单独强化特征**。注意 `Position-wise` 这四个字，它说的就是“逐位置”：每个位置各干各的，位置之间不交互。图上的这一块和代码里的 `PositionwiseFeedForward` 就是同一个东西。

## 初始化函数的三个参数

到 `TODO 9`，第一步先写初始化函数。`__init__` 里需要三个东西：

| 参数 | 取值示例 | 含义 |
| --- | --- | --- |
| `d_model` | `512` | 输入数据的词向量维度 |
| `d_ff` | `2048` | 前馈全连接维度，需要比 `d_model` 大 |
| `dropout` | `0.1` | 随机失活比例 |

类名不用写得那么复杂，直接叫 `PositionwiseFeedForward`，继承 `nn.Module`：

```python
class PositionwiseFeedForward(nn.Module):
    """前馈全连接层：先升维，再降维，对特征做强化"""

    def __init__(self, d_model, d_ff, dropout=0.1):
        # 第一步：初始化父类
        super().__init__()
        # 第二步：定义第一个全连接层，512 维 -> 2048 维
        self.linear1 = nn.Linear(d_model, d_ff)
        # 第三步：定义第二个全连接层，2048 维 -> 512 维
        self.linear2 = nn.Linear(d_ff, d_model)
        # 第四步：随机失活
        self.dropout = nn.Dropout(p=dropout)
```

四个动作按顺序落下来：

1. 初始化父类：`super().__init__()`；
2. 定义第一个全连接层，输入维度是 `d_model`，输出维度是 `d_ff`，也就是 512 维变成 2048 维；
3. 定义第二个全连接层，从 2048 再变回 512；
4. 定义随机失活。

> **注意**：第三步的顺序是先第二个全连接层、再 dropout，别在中间插队。就这一升一降，它其实已经学到了很多信息。

## 前向传播的四个动作

前向传播实现的流程同样简短，`x` 扔进去：

```python
    def forward(self, x):
        # 1. 第一个全连接层升维：512 -> 2048
        x = self.linear1(x)
        # 2. 通过激活函数处理，再随机失活
        x = self.dropout(F.relu(x))
        # 3. 第二个全连接层降维：2048 -> 512
        x = self.linear2(x)
        # 4. 返回结果
        return x
```

第一个动作 `x = self.linear1(x)` 之后，512 维的 `x` 已经变成了 2048 维。

第二个动作要做两件事，而且**顺序不能反**：先通过激活函数，再做随机失活。

ReLU 会对负值做什么？它只考虑正值——把负值变成 0，保留正数。于是它给这一层带来的是**非线性**能力。

```python
x = self.dropout(F.relu(x))
```

先激活、再失活，就这一行。写成先 `dropout` 再 `relu` 不是这个设计的意思：这里要的是“激活后的特征做正则化”。

第三个动作是第二个全连接层，映射回 `d_model` 的维度，`x = self.linear2(x)`。第四个动作返回结果。

> **易错点**：不能升到 2048 之后立刻从 2048 变回 512。那等于做了一个大的线性计算，中间没有任何非线性介入，学不到太多信息。正确顺序是**升维 → 激活 → 随机失活 → 压缩**，四步都走到，才能反向映射回 512 维。

## 测试函数的五个动作

`TODO 9` 写完，`TODO 10` 是测试前馈全连接层。测试函数的名字不写 `d_model` 相关的字段，直接叫 `use_ff`——`ff` 就是 FeedForward 的缩写，因为后面别的地方还要用这个前馈处理后的结果。

五个动作：

```python
def use_ff():
    # 1. 获取多头注意力层的结果，形状 [2, 4, 512]
    attn_x = use_multihead_attention()
    # 2. 创建前馈全连接层对象
    my_ff = PositionwiseFeedForward(512, 2048)
    # 3. 把多头结果送进去处理
    result = my_ff(attn_x)
    # 4. 打印输出形状
    print('前馈全连接层', result.shape)
    # 5. 返回结果
    return result
```

第一个动作不是上来创建对象，而是先**取多头注意力的结果**。这个结果是谁给的？就是上一步写好的 `use_multihead_attention()`，它交出来的形状是 `[2, 4, 512]`。

第二个动作创建对象：`PositionwiseFeedForward(512, 2048)`，两个数字分别对应 `d_model` 和 `d_ff`。

第三个动作把多头结果交给它处理，第四个动作打印形状，第五个动作返回。打印出来的形状必定还是 `[2, 4, 512]`——和前馈全连接的输入形状一致，符合预期就可以。

### 组件级测试带来的灵活性

第五个动作为什么要返回结果？因为后续再用的时候直接调这个函数就行，前面那一堆带着位置编码、掩码的计算全都不用重写。

这样做下来，每个组件都有自己独立的测试入口：词嵌入一个、位置编码一个、多头注意力一个、前馈全连接一个。**想从哪个节点切入，就调对应的函数往后走**，这就是灵活。

如果你感兴趣，可以多做一件事：把处理前后的内容都打印出来。你会发现前馈输出的那个 512 和它上面那个输入的 512，数字肯定不一样了——不一样就说明它学到信息了。至于具体学到了哪些信息、为什么这个 `[2, 4, 512]` 在预测时比输入效果更好，这个问题得问科学家。我们要做的是用代码把架构模拟出来，每块各是什么、各干什么。

## 与后续组件和面试的关系

跑完这一块，回头看整个 Transformer，架构图上绝大多数模型用的都是它的**解码器**：解码器主生成，编码器主理解。左边这一类任务叫自然语言理解（Natural Language Understanding，NLU），右边这一类叫自然语言生成（Natural Language Generation，NLG）。这部分后面再展开。

面试的时候这块的价值在哪？**你要能讲出来，注意不是写出来。** 每个组件干的是什么事、架构往下是怎么分的，你不需要现场写代码，但得用自己的话给别人讲清楚。你要是在架构这块扎得深，哪怕大模型应用或者别的方向稍微欠缺一点，公司里也是 OK 的，因为你能很快上手。

而且现在很多活确实是点点点：比如 ChatGLM、DeepSpeed 这类，给你一些成品，你在上面点一点就出效果。但它的底层怎么做？就是这个玩意儿。今天市场上你在用的模型——豆包、DeepSeek、Kimi、ChatGPT 等等——底层全是 Transformer，而且用的绝大多数是 Transformer 里面的解码器。

所以代码写了这么多，晚上把形状这些好好看看。第一件事是**用自己的话讲一遍**，而不是上来就抠代码。
