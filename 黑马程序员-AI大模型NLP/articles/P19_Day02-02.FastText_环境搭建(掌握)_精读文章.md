# FastText 工具包的环境搭建与训练数据准备

CBOW 和 Skip-gram 的原理我们已经推完了。原理懂了，下一步就躲不开一个问题：**这玩意儿用什么代码跑出来**？总不能自己从零手写一个 Word2vec——那是另一门课的量。

所以这一讲的定位很明确：动手之前先把"工具"和"数据"两样东西备齐。工具是 `fastText`，数据是一个 680 兆的英文维基语料。环境搭完，后面写代码就是水到渠成的事。

## 1 为什么是 FastText

先看工具。`fastText` 是一个训练工具包，它能直接生成 Word2vec 的词向量形式。

它由 Facebook 开源，一共两个作用：

- 训练词向量（word vector）；
- 文本分类（text classification）。

我们现在只用它的**词向量**功能。文本分类先放着——到了后面迁移学习那部分，还会拿它来做文本分类相关的活。也就是说这个包后面还得反复用，所以你得在自己那个沙箱里把它装好，装法下面讲。

## 2 词向量训练的四步流程

再往下就是 Word2vec 训练词向量的步骤。这一步我先把话说死：**这个是要求背下来的**。

一共四步：

1. 获取训练数据；
2. 词向量的训练、保存、加载和查看；
3. 模型效果的检验；
4. 模型超参数的设定。

来，告诉我一共几步？四步。接下来我会给你们写**四个函数**，分别对应这四步操作。记住这个结构，后面写代码时你一眼就知道每个 `demo` 函数是在干第几步。

先做第一步，没跑：**获取训练数据**。

## 3 训练数据：英文维基语料与 fil9

我们的数据来源于维基百科。取的是英文维基百科的一部分网页信息，原始压缩包 300 兆左右；解压开来接近一个 G，**确切地说，是 680 兆**。

先说个量级概念。以我这台电脑（不含 GPU 的普通配置）来处理，100 兆大概要 4 分钟左右。那 680 兆呢？算一下就得接近**半个小时**。

问题就来了：我把代码一写，右键运行，然后咱们半个小时什么都干不了——这就没意思了。所以我已经对这个文件做了处理，一会儿给你们看。

先说数据说明里那句话：**预处理后的数据为 `root/data/fil9`**。

预处理到底做了哪些事？其实就一件：底层用**正则**把每个单词都切出来，然后单词与单词之间**用空格隔开**。就这些。

> **结论**：你要做的只有一件事——直接用预处理之后的 `fil9`。前面从压缩包一路切词的活，不用你再做一遍。

说明书里后面那一堆 Linux 命令（查看前 80 个字符、跑预处理脚本等等）都是可选项，感兴趣可以看，不感兴趣就跳过。拿 `fil9` 来玩就行，它同样是 680 兆。

## 4 数据集的拆分：一个 680 兆 + 七个分片

原始语料长这样：

```text
data/
├── fil9                   680 兆，原始全量语料（单词之间以空格分隔）
├── 0502_ad                100 兆  ← A 组
├── 0502_bd                100 兆  ← B 组
├── 0502_ce                100 兆  ← C 组
├── 0502_df                100 兆  ← D 组
├── 0502_eg                100 兆  ← E 组
├── 0502_fh                100 兆  ← F 组
└── 0502_gj                 80 兆  ← 收尾的零头
```

读图说明：上面是原始的整份语料，下面是按 100 兆一段切出来的分片，最后一片是 80 兆的零头；七个分片合起来才等于 `fil9`。

命名里的 `0502` 是日期标签，后面的字母是用来做组次标记的。六个 100 兆加一个 80 兆，正好是 680 兆。

数据文件的位置也交代清楚：在发给大家的资料里有一个「数据集」目录，里面有个「文本张量」，双击打开，第一个就是 `fil9`。

> **提示**：`fil9` 我不建议你直接拿它开跑。它 680 兆，跑一轮下来时间成本高；做演示和调参，用 100 兆的分片足够了，效果差异在入门阶段看不出来。

## 8 两条路径与隐藏层权重矩阵

把 Word2vec 两条路径并排画出来，后面看代码时脑子里就有图：

```text
                 one-hot 输入
                      |
        +-------------+-------------+
        |                           |
     CBOW 路径                  Skip-gram 路径
        |                           |
   上下文若干词                  中间目标词
        |                           |
        v                           v
   预测中间目标词              预测上下文若干词
        \                           /
         \                         /
          +-----------+-----------+
                      |
                      v
            隐藏层权重矩阵 W（dim 维）
                      |
                      v
         W 的每一列 = 一个单词的 Word2vec 词向量
```

读图说明：两条路径方向正好相反——CBOW 用上下文推中间词，Skip-gram 用中间词推上下文；但它们的落点是同一个：**隐藏层的权重矩阵**，这个矩阵的每一列就是一个词的向量。

这一点特别值得记牢。不管以后换哪种训练方式、换哪个工具包，最终我们拿的都是那个矩阵。

## 9 fastText 的安装

现在缺的就是包本身。安装分三步走。

**第一步：进环境。** 在终端里激活沙箱：

```bash
conda activate nlp_base
```

**第二步：先试直装。**

```bash
pip install fasttext
```

**第三步：装不上就换编译版。**

```bash
pip install fasttext-wheel
```

我要提醒你一句：**`pip install fasttext` 你大概率会报错**——不只你会报错，我这里也一样。

为什么？`fasttext` 这个包带 C++ 源码，安装时要现场编译，而编译依赖你的**系统**和**编译器版本**。有的 Anaconda 环境会顺手帮你把编译做掉，那直装就成功；有的环境不帮你编译，那你敲回车就是一片红。

直装报错时，换上 `fasttext-wheel` 这条命令即可——它是**预编译（wheel）版本**，不用你本地编译，装起来干脆利落。

> **结论**：上面两条命令记成一句话——**直装优先，报错换 wheel 版**。

验证一下装没装好，顺便看版本：

```bash
pip list | findstr fasttext
```

我这边的版本号是 **0.9.2**，你们可以参考一下，不必强求完全一致。

> **提示**：`fasttext-wheel` 这个名字里的 `wheel` 指的是 Python 的预编译二进制分发格式,不是车轮。带 C++/Cython 扩展的包常常同时提供源码包和 wheel 包，装不上源码包时换 wheel 包是通用解法。

## 10 开发者与工具谱系

补一个人物背景，知道工具从哪来，用起来会有底。

Word2vec 的作者是**托马斯·米科洛夫（Tomáš Mikolov）**。这个人相当能打：Word2vec 是他发明的，**RNN**（循环神经网络）有他，**`fastText` 整个工具包也是他写的**。

一个人身上挂着三样东西：一种词向量方法、一类序列网络结构、一个工程工具包。所以后面你在看词向量、看序列模型、看词向量工具的时候，反复撞见同一个名字是正常的。

## 11 数据管线与时间成本

最后把整条链路串起来看一眼，你就知道每一步为什么会这么设计：

```text
  英文维基原始网页信息（压缩包约 300 兆）
              |
              v
        解压 + 正则切词（单词之间补空格）
              |
              v
       官方预处理产物 fil9（约 680 兆）
              |
              +---------------------+
              |                     |
              v                     v
   直接用于训练（全量）      拆成 7 个分片
   本机约需半小时           6×100 兆 + 1×80 兆
              |                     |
              v                     v
        全量训练，效果更好      演示 / 调参用，迭代快
```

读图说明：同一份 `fil9` 有两条用法——要么整份丢进去慢慢训（效果上限更高），要么用分片快速试（开发效率更高）。入门阶段用分片，等代码和参数都调顺了，再换全量跑一次拿最终结果。

时间账再算一遍你就明白为什么要有分片：**100 兆 ≈ 4 分钟，680 兆 ≈ 半个小时**。而 `fastText` 跑一轮的耗时还会随你的机器配置浮动。所以别拿 680 兆当"跑通没跑通"的试验品——那太贵了。
