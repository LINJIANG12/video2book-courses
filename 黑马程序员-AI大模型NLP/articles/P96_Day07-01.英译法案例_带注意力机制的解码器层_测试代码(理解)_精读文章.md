# 带注意力机制的解码器：测试代码与维度联动

到目前为止，带注意力机制的解码器已经搭出来了，接下来就是把它跑一遍、测一遍。写这个解码器的时候，建议大家一直对着那张图看，包括图里标的每一次维度转换——这样玩起来会清晰很多。测试代码的整体套路还是熟悉的四件事：封装数据集、建数据加载器，然后实例化编码模型，最后做测试。

这里面有个问题一定有人会问：**怎么又用上编码器了？** 原因很简单——解码器要用编码器的输出，才能拿到那个中间语义张量 $c$。所以测试流程里，编码器必须重新实例化一份，跟着一起跑。

测试代码最后会有一个 `break`，意思是只测一批就够了，不用把整个数据集跑完。

## 数据加载器与模型初始化

先定义测试函数：

```python
def dm_test_attn_decoder():
    # 1. 获取数据加载器对象
    my_dataloader = get_dataloader()
```

接下来是模型初始化阶段。既然是 seq2seq 架构，第一个动作一定是创建编码器对象：

```python
    # 2.1 创建编码器对象
    my_encoder = EncoderRNN(english_n, 256).to(device)
```

参 1 是英语词汇表大小——这个数字要背下来，是 **2803**；参 2 是隐藏层维度 256。

> **注意**：`.to(device)` 是把模型移动到指定设备上，这行代码**必须写**。如果你只是在下边把运行环境切成 GPU（比如 `nlp-base-2`），而模型没有 `.to(device)`，执行的时候是会报错的。切环境和搬模型是两件事，别混成一件。

2.2 创建解码器对象：

```python
    # 2.2 创建解码器对象
    my_decoder = AttnDecoderRNN(french_n, 256, dropout_p=0.1, max_len=10).to(device)
```

参 1 是法语句子词汇表大小 **4345**，参 2 是隐藏层维度 256——**两个模型的隐藏层维度必须一样**，因为编码器最后一个时间步的隐藏状态要直接当解码器的初始隐藏状态用。

## 取一个样本与编码过程

第三个动作是模型推理，其实就是走一遍前向。先从数据加载器里拿一个样本，用 `for i, (x, y) in enumerate(my_dataloader)` 来遍历——这个函数在数据加载里用得实在太多了。

拿到样本以后，先打印输入信息看看：

```python
    # 3.1 从数据加载器中获取一个样本
    for i, (x, y) in enumerate(my_dataloader):
        # 3.2 打印输入信息
        print(f'英语句子: {x}, shape: {x.shape}')
        print(f'法语句子: {y}, shape: {y.shape}')
```

句子最长也就十个单词，因为我们限定了句子长度，所以打出来不会特别长。但要注意：从加载器里拿出来的不是单词本身，而是**单词对应的编号**。

跑一下看结果，只关心最后两行。当前用的设备是 `cuda`，说明跑在 GPU 环境上；想切 CPU 就把环境换成 `nlp-base`，内容完全一样，无所谓。

打出来的英语句子形状是 `[1, 8]`——八个词，这些编号来自 2803 个英语单词表中每个单词的索引。法语句子也是 `[1, 8]`，而这些编号的范围是 4345，因为那是法语词表的长度。

接着做编码过程：

```python
        # 3.3 编码过程
        hidden = my_encoder.initHidden()
        encoder_output, hidden = my_encoder(x, hidden)
```

编码器底层就是一个 GRU：把本次的输入 `x` 和上一次的隐藏状态 `hidden` 丢进去，返回本次的隐藏状态和本次的输出。

两个返回值的含义分清楚：

- `encoder_output` 是**所有时间步**的输出，所以它保留了序列长度这一维，形状是 `[1, 8, 256]`；
- `hidden` 是**最后一个时间步**的隐藏状态，形状是 `[1, 1, 256]`。

这跟前面不带注意力的版本完全一样，没有新东西。

## 编码器输出的固定长度张量

3.4 是准备编码器的输出，供注意力机制使用：

```python
        # 3.4 准备编码器输出（后续用于注意力机制）
        encoder_output_c = torch.zeros(max_len, my_encoder.hidden_size, device=device)
```

先想清楚形状。刚才拿到的 `x` 是 `torch.Size([1, 8])`，法语句子是 `[1, 8]`。那有没有可能出现上面是 `[1, 6]`、下面是 `[1, 8]` 的情况？**有**，六个英语单词配八个法语单词，这很正常。既然真实长度不固定，那我们就要把它统一整成 `[1, 10]`——10 就是 `max_len`。

所以这里 `torch.zeros` 造的是一个形状为 `[10, 256]` 的固定大小张量：`max_len` 是 10，`my_encoder.hidden_size` 是 256，`device=device` 把它放到同一个设备上。

> **定义**：这个张量的作用是**存储编码器输出**，并且尺寸固定。它是全零的——这一点后面很关键，因为「零」正好可以当填充位。

### 固定张量为什么不和图上的 `[1, 6, 256]` 冲突

有人会盯住形状不放：编码器输出明明是 `[1, 6, 256]`，这里怎么就成了 `[10, 256]`？不冲突。

编码器出来的是 `[1, 6, 256]`（假设我只说六个单词），这是**真实**的；而我们建的这个是 `[10, 256]`，这是**我们要的**。把真实的那一份填进这个固定容器里，容器就是 `[10, 256]`。

现在就能回答那个「为什么要升维」的问题了：正因为这个容器是二维的 `[10, 256]`，送到解码器那边去做 `bmm` 时必须是三维，所以前面代码里才会有一个升维动作，把它变成 `[1, 10, 256]`。这两个地方是上下联动的，单看一处确实容易晕。

### 复制与截断补齐

3.5 把编码器的实际输出复制进这个固定张量：

```python
        # 3.5 将编码器实际输出复制到固定大小的张量中
        for index in range(encoder_output.shape[1]):
            encoder_output_c[index] = encoder_output[0, index]
```

`encoder_output.shape[1]` 拿到的就是这个 6（真实句子长度），`range(6)` 让 `index` 从 0 走到 5。往里填的时候，左边写 `encoder_output_c[index]`——取到的是第 `index` 行那 256 个位置；右边写 `encoder_output[0, index]`——先 `[0]` 摘掉批次维，再取第 `index` 个时间步的 256 维向量。

> **提示**：编码器的输出既要留着当容器里填的料，又要当后面解码器要用的 V，所以我把这两个名字分开写：`encoder_output_c` 是那个固定长度的容器，`encoder_output` 是编码器刚吐出来的真实输出。名字分开了，形状就不会看串。

这个动作的妙处在于，它一次把两件事都做完了：

- **截断**：真实长度超过 10，也只往前 10 个位置复制，多出来的直接不要；
- **补齐**：真实长度不到 10，后面那些位置保持着 `torch.zeros` 留下的 0，天然就是填充。

> **结论**：在上面创建一个固定长度 `[10, 256]` 的张量，其实等价于已经把截断和补齐一起做掉了——剩下的只是把你的数据复制进去。

那这个位置有没有用到之前讲的文本张量处理里那套截断补齐的思路和函数？其实并没有调用那个 `padding` 之类的函数。我想说的是：**思维有了，接下来就是做题的时候把这个技巧、这个思维用上去**。不一定非得用别人底层的源码，你自己把它模拟出来、达到想要的效果就行。学代码一定要灵活，千万不要死记硬背。

## 解码器过程与逐词翻译

3.6 是解码过程：把隐藏状态解码成法语句子。这里有一条硬要求——**必须逐词翻译**。

法语句子长度是 8，那就遍历八次，一个词一个词地让模型预测。它不可能一下子把整句吐出来；如果真让它一次预测整句，就会出现「真实长度是 8、预测出来是 6 或者 10」这种收不回来的情况。

### 遍历目标句子的时间步

3.6.1 是遍历目标句子的每个时间步，说白了就是遍历它的长度：

```python
        # 3.6 解码器过程
        for i in range(y.shape[1]):
```

`y` 的形状是 `[1, 8]`，我要的不是 `[1, 8]`，而是那个 8，所以写 `y.shape[1]`，把 8 拿到手。

### 提取当前时间步的目标词索引

3.6.2 提取当前时间步的目标词索引：

```python
            temp = y[0][i].view(1, -1)
```

`y[0]` 先摘掉批次维，拿到那八个词；再 `[i]` 取第 `i` 个。举例来说，如果这一句的编号序列是 `[1595, 992, ...]`，那么 `i=0` 拿到的就是 1595。但这时候它只是一个孤零零的 1595，没有用——所以要 `view` 一下把它转成规范的二维形状。

`view(1, -1)` 的意思是：转成一行，能排多少列就排多少列。这里就变成 `[1, 1]`。

> **易错点**：`view(1)` 和 `view(-1)` 出来的都是一维张量，只有写成 `view(1, -1)` 才是二维。解码器的输入要的是二维的 `[1, 1]`，别在这儿写漏一个参数。

### 执行解码器前向传播

3.6.3 执行解码器的前向传播：

```python
            output, hidden, attn_weights = my_decoder(temp, hidden, encoder_output_c)
```

把三个输出一次接住。这里的三个实参正好对应前面说的 Q、K、V：

| 实参 | 传入内容 | 角色 | 形状 |
| --- | --- | --- | --- |
| `temp` | 当前时间步的输入词索引 | Q | `[1, 1]` |
| `hidden` | 上一个时间步的隐藏状态 | K | `[1, 1, 256]` |
| `encoder_output_c` | 编码器所有时间步的输出 | V | `[1, 10, 256]` |

`temp` 是「临时的」——这八个单词一个一个一直在变，这会儿是 1595，下次就变成 992，所以它是那个不断变化的查询。

`encoder_output_c` 虽然我们按真实长度讲它是 `[1, 6, 256]`，但它进到解码器里一定会变成 `[1, 10, 256]`，跟图里画的完全对上。

三个返回值也要逐个说清：

- `output`：当前时间步的输出概率分布，形状 `[1, 4345]`；
- `hidden`：当前时间步的隐藏状态，形状 `[1, 1, 256]`；
- `attn_weights`：当前时间步的注意力权重分布，形状 `[1, 10]`。

> **提示**：写注意力版解码器的时候我说过一句话——正常的前向传播返回 `output` 和 `hidden` 两个就够了，数据到这一步本来就是完整的。但因为我们后面要画注意力权重分布图，所以在 `forward` 里多返回了一份权重，这里接收的时候就得用三个变量来接。如果不做可视化，这一项可以不返回。

### 打印结果

3.6.4 打印结果：

```python
            print(f'解码 output.shape: {output.shape}')
            print(f'解码 hidden.shape: {hidden.shape}')
            print(f'解码 attn_weights.shape: {attn_weights.shape}')
            # 只看一个词
            break
```

三个形状分别是什么其实早就标在图上了：`output` 是 `[1, 4345]`，`hidden` 是 `[1, 1, 256]`，`attn_weights` 是 `[1, 10]`。

那个 `break` 是加在最里面这个 `for` 里的，意思是只看一个词。但注意——**外面还有一层 `for`**，那层才是遍历每一个样本的。所以如果你把 `break` 放在内层，只是每个样本都只看第一个词；想让整个循环只跑一个样本，就得把这个 `break` 挪到外层去。

改完之后再跑一遍，就能看到「只看一个句子样本」的效果。打印的时候顺手加个换行分隔，看起来清楚些。

## 输出形状的含义

跑通以后盯着结果看，有一件事要解释清楚：我输入的是 `[1, 8]`，输出的也是 `[1, 8]`，那 `[1, 4345]` 是什么意思？

- `[1, 4345]` 是对**当前这一个词**在法语词表上的概率分布。真实的下一个词可能是 119，但预测的结果是在 4345 个编号里挑概率最大的那个；接下来要算损失，就是拿它和真实编号比。
- `[1, 10]` 是在生成**这一个词**的时候，对上面那 10 个源端词的权重考虑——也就是那八个英语单词（加上补齐位）各自占多少分量。

换个词再问一遍：这个 `[1, 4345]` 是预测哪个词的概率？假设是 297，那它就是在生成 297 这个词。那么生成 297 的时候，对上面那十个位置，权重分布又是另一份 `[1, 10]`——和生成 119 那份不一样。

往后每一个词都是这样：**每生成一个新词，就有一份新的 `[1, 10]` 权重**。注意力机制就是这样一步步加进去的。

## 测试代码全貌

把整段测试代码按步骤合起来：

```python
def dm_test_attn_decoder():
    # 1. 获取数据加载器对象
    my_dataloader = get_dataloader()
    # 2.1 创建编码器对象
    my_encoder = EncoderRNN(english_n, 256).to(device)
    # 2.2 创建解码器对象
    my_decoder = AttnDecoderRNN(french_n, 256, dropout_p=0.1, max_len=10).to(device)
    # 3. 模型推理
    for i, (x, y) in enumerate(my_dataloader):
        # 3.1 取一个样本并打印输入信息
        print(f'英语句子: {x}, shape: {x.shape}')
        print(f'法语句子: {y}, shape: {y.shape}')
        # 3.2 编码过程
        hidden = my_encoder.initHidden()
        output, hidden = my_encoder(x, hidden)
        # 3.3 准备固定大小的编码器输出张量
        encoder_output_c = torch.zeros(max_len, my_encoder.hidden_size, device=device)
        # 3.4 复制实际输出，顺带完成截断与补齐
        for index in range(encoder_output.shape[1]):
            encoder_output_c[index] = encoder_output[0, index]
        # 3.5 解码器过程：逐词翻译
        for i in range(y.shape[1]):
            temp = y[0][i].view(1, -1)
            output, hidden, attn_weights = my_decoder(temp, hidden, encoder_output_c)
            print(f'解码 output.shape: {output.shape}')
            print(f'解码 hidden.shape: {hidden.shape}')
            print(f'解码 attn_weights.shape: {attn_weights.shape}')
            break
        # 只看一个样本就退出外层循环
        break
```

## 形状串联

把整条测试链路上的形状变化排成一张图，对照着看，每一步的维度就有出处了：

```text
x                      [1, 8]        英语词索引
  |
  v
encoder_output         [1, 8, 256]   所有时间步的输出
encoder_hidden         [1, 1, 256]   最后一个时间步的隐藏状态
  |
  v
encoder_output_c       [10, 256]     固定容器，多出的位置由 0 填充
  |
  v  送入解码器后升维
                       [1, 10, 256]
  |
  +------------------------+
  |                        |
temp  [1, 1]  ------------> Q
hidden [1, 1, 256] -------> K
encoder_output_c ---------> V
  |                        |
  v                        v
output      [1, 4345]   attn_weights   [1, 10]
hidden      [1, 1, 256]
```

读图说明：编码器的输出先被搬进固定长度的 `[10, 256]` 容器，进解码器时升成 `[1, 10, 256]` 充当 V；每一步的 `temp` 当 Q、`hidden` 当 K，三者一起算出当前词的概率分布与对源端 10 个位置的注意力权重。

> **结论**：解码器的输出概率分布是 `[1, 4345]`，隐藏状态是 `[1, 1, 256]`，注意力权重是 `[1, 10]`。三者的第一维始终是批次，真正变化的只有最后一个维度——而那个维度，正是「法语词表大小」与「源端最大长度」这两件不同的事。

到这里，带注意力机制的解码器就测试完了。
