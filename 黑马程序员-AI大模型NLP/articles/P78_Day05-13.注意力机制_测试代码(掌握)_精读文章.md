## 1 测试代码的四个动作

测试代码是一个新的 `todo2`，放在 `main` 里。整体分四步：先做参数设置，再创建随机输入张量，然后实例化自定义的注意力机制模块并测试它，最后输出结果。

```python
def main():
    # 1. 实例化参数设置
    query_size = 32
    key_size = 32
    value_size1 = 32
    value_size2 = 64
    output_size = 32
```

这五个数字就是刚才那一堆尺寸参数，含义和前面完全一致，直接照搬过来。

## 2 三个输入张量的形状

第二步是创建随机输入张量，用 `torch.rand` 生成。Q、K、V 三者的形状不一样，这是这一步的关键。

```python
    # 2. 创建随机输入张量
    q = torch.rand(1, 1, query_size)                  # 查询张量
    k = torch.rand(1, 1, key_size)                    # 键张量
    v = torch.rand(1, value_size1, value_size2)       # 值张量
```

Q 的形状是 `(1, 1, 32)`，三个维度依次读作**批次、序列、特征**：一批、一个、32 维。

K 的形状同样是 `(1, 1, 32)`，三个维度的读法和 Q 一样——批次、序列、特征。

V 就不一样了，它的形状是 `(1, 32, 64)`，对应 `(1, value_size1, value_size2)`，三个维度读作**批次、单词数、词向量维度**：一批、32 个单词、每个单词 64 维。

> **提示**：V 的中间维是单词数而不是序列，这不是笔误。Q 和 K 的中间维描述的是「一个」查询/键的位置，而 V 要对 32 个单词逐个给出内容，所以它中间那一维必须是单词数 32。也正因为 32 个单词要用权重逐个相乘，注意力权重的个数才必须是 32。

## 3 实例化、前向计算与结果输出

第三步实例化模块并把三个张量喂进去，拿到两个返回值。

第四步输出结果，前面加一条华丽的分割线，万一上面还有别的打印语句，隔开看得清楚。

这里第一个打印看的是 `output.shape`，也就是形状；后面才把内容打出来。

## 4 结果的形状与权重含义

跑起来之后到这儿就结束了。先看上面那一坨组成的输出，你会发现注意力结果表示的形状是 `(1, 1, 32)`。这个就是**增强以后的内容**——以前那个 Q 不够强大，只有它本身那一个张量，现在增强后就是 `(1, 1, 32)`。

下一个打印是注意力权重分布，一共 `(1, 32)`。为什么是 1 × 32？

> **结论**：因为一共有 32 个单词，注意力权重就有 32 个分量，这 32 个分量要分别和 32 个单词相乘，才能得到最终结果。

那么权重分布到底分布成什么样？把这些数加起来——32 个数相加，结果其实应该是 1。这正是 softmax 归一化的意义：加总为 1 之后，我就能看出更应该侧重关注哪个词。

```text
output            : (1, 1, 32)  增强后的 Q，记录对各词的关注结果
attention_weights : (1, 32)     32 个注意力分配概率，总和为 1
```

上面这张图就是这次打印出来的两样东西各自的含义：一个是增强后的查询表示，一个是分给 32 个单词的注意力概率。

> **易错点**：课件上写的注意力权重是 `(1, 10)`，因为我们把单词数从 10 个改成了 32 个，所以这里才是 `(1, 32)`。这个细节要跟着参数走，别把课件上的 10 照抄进自己的结果里。

想亲自确认「加起来是 1」这件事，加一行求和就够了：

```python
    # 验证注意力权重分布：32 个分量加总为 1
    print("attention_weights.sum():", attention_weights.sum())
```

这行打印出来的结果应该很接近 1，误差只来自浮点精度。权重归一化之后，`(1, 32)` 这 32 个数就不再是原始得分，而是一份分配方案：哪个词分到的数大，后面的加权求和里那个词的内容就占的比重大。

换句话说，增强后的 Q 之所以「更强大」，不是因为它变得更多了，恰恰是因为它变少了——它把 32 个单词的信息按权重压缩进 32 维，权重小的词几乎被丢掉，权重大的词留下来。这也是注意力机制的本意：不是平均地看所有词，而是有选择地看。
