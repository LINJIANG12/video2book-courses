# 编码器层测试：掩码张量的构建与层内对象结构打印

编码器层的代码写完了，接下来该验证它。这一节的活儿其实很轻：准备数据、初始化多头注意力、初始化前馈全连接、往编码器层里传参，然后跑一次看结果。真正值得停下来琢磨的是两个地方——`forward` 里那个 `mask` 到底要不要给、给什么形状；以及把 `encoder_layer` 这个对象整个打印出来之后，我们能不能从它的结构里读出「两个子层、四个线性层、两个线性层」这些数字。

## 测试流程与准备数据

新建一个测试脚本，函数就叫 `use_encoder_layer`。全程六个动作：准备数据、实例化两个子层对象、创建编码器层对象、构建掩码张量、执行前向传播、打印结果。

第一步是准备数据，用的还是位置编码层处理后的那份数据——也就是整张结构图上那个绿色的点，正好是编码器层的入口位置。

```python
def use_encoder_layer():
    """测试编码器层的流程"""

    # 1. 准备数据：位置编码层处理后的数据
    x = use_position()
```

它是几维的？这问题我这回都不想写了，还是那个例子：`[batch_size, seq_len, d_model]`，也就是 `[2, 4, 512]`。写成 `[30, 10, ...]` 之类的没有意义，最终取决于你实际传进去的是什么——批次、句长、词嵌入维度，三项对上就行。

## 创建两个子层对象

编码器层需要两个对象当参数，所以要先把它们造出来。先建多头注意力：

```python
    # 2.1 多头注意力对象
    multi_head = MultiHeadedAttention(d_model=512, head=8)
```

写这一行最容易卡在「里面参数叫什么名」。两种办法确认：一是把光标放到 `MultiHeadedAttention` 上按 `Ctrl+Q` 看建议，它会给出参数提示；二是鼠标悬停在类名上别动，等两秒左右弹框，里面就直接写着两个参数——`d_model` 和 `head`。词嵌入维度是 `512`，头数是 `8`。

接着建前馈全连接：

```python
    # 2.2 前馈全连接对象
    feed_forward = FeedForward(d_model=512, d_ff=2048)
```

`d_ff` 这个参数的意思是把特征升维升到多少。前馈全连接层干的活就是强化特征：从原始维度 `512` 升到一个更大的维度，`2048`、`1024` 等等都行，只要比 `d_model` 大就可以；升上去之后再降回 `512`。所以我们这里写 `512 → 2048`。

> **易错点**：前馈全连接只需要传两个参数，不是三个。有人会把「升维」和「降维」当成两个参数分别传，实际上一升一降都由同一个 `d_ff` 决定——进去是 `d_model`，中间是 `d_ff`，出来还是 `d_model`。拿不准就把鼠标放上去悬浮两秒，提示里写得清清楚楚。

## 创建编码器层对象

两个子层对象有了，交给编码器层：

```python
    # 3. 创建编码器层对象
    encoder_layer = EncoderLayer(
        d_model=512, self_attn=multi_head, feed_forward=feed_forward
    )
```

把光标停在 `EncoderLayer` 上静止两秒，会弹出一串提示。这里的提示框有时候显示不全，看着像是「只有两个参数」，其实不止——真正完整的一份参数说明就在我们自己写的类里，就是那段中文文档说明，那是我自己加的注释，位置就在 `EncoderLayer` 的 `__init__` 上面。

所以最可靠的确认方式是按住 `Ctrl` 点进 `EncoderLayer` 看一遍：

| 参数 | 传什么 | 我们的写法 |
| --- | --- | --- |
| `d_model` | 词嵌入维度 | `512` |
| `self_attn` | 多头注意力对象 | `multi_head` |
| `feed_forward` | 前馈全连接对象 | `feed_forward` |

三个参数都是必填，`dropout` 有默认值不用写。到这里编码器层对象就搭好了。

## 构建掩码张量

下面这件事很容易被漏掉：编码器层执行的时候，`forward` 不只是要一个 `x`，它还要一个 `mask`。

编码器本身用不到掩码，那为什么参数里必须有它？看 `forward` 的签名就明白了：

```python
    def forward(self, x, mask):
```

这是为了和解码器层保持同一套接口。既然要给，那就得造一个出来：

```python
    # 4. 构建掩码张量
    mask = torch.zeros(8, 4, 4)
```

形状这里要看清楚：多头注意力是多头的，所以掩码要能对应到每个头上，写成 `[8, 4, 4]`——`8` 是头数，后面 `4, 4` 是句长乘句长。如果只写 `[2, 4, 4]` 就会和头数对不上，或者语义上落错位置。

这里的重点是**先有掩码再前向传播**：`mask` 必须在调用 `forward` 之前准备好，顺序颠倒就会直接报参数缺失。

> **提示**：若只想验证编码器层的形状与流程，掩码给全零张量即可——全零意味着「任何位置都不屏蔽」，对编码器来说这是最朴素也最合适的取值。掩码真正发挥作用要到解码器那部分。

## 执行前向传播与打印结果

```python
    # 5. 执行编码器层前向传播
    output = encoder_layer(x, mask)

    # 6. 打印结果
    print("编码器层输出形状:", output.shape)
    print("编码器层输出内容的第1批前2个单词的前5维:", output[:1, :2, :5])
```

调用时把光标停在 `encoder_layer` 上不松，弹框会告诉你这个对象是谁、有哪些子模块，顺手确认一遍你传的是不是同一个东西。

`output` 这个量代表数据已经走到了编码器层的出口。回到那张结构图上看：红色的点（第一个子层的输出）进来，经过前馈全连接这一圈，出去就是绿色的点。红色进、绿色出，一次编码器层的处理就完成了。

输出形状必定是 `[2, 4, 512]`。batch 是 `2`，句长是 `4`，词嵌入维度是 `512`；编码器层不改变形状，进什么样出什么样。

## 切片观察输出内容

只打印形状其实看不到东西，所以再切一刀看看里面：

```python
    print("-" * 50)
    print("编码器层输出内容的第1批前2个单词的前5维:", output[:1, :2, :5])
```

`[:1, :2, :5]` 就是三个维度上各切一刀，含义拆开是：

| 切片 | 对应维度 | 含义 |
| --- | --- | --- |
| `:1` | `batch_size` | 从 0 开始到 1 结束、包 0 不包 1，即第 1 批 |
| `:2` | `seq_len` | 第 1 批里前 2 个单词 |
| `:5` | `d_model` | 每个单词 512 维中的前 5 维 |

连起来读就是一句话：第 1 批、前两个单词、每个单词的前 5 个特征。每个单词总共有 `512` 维，全打出来看不过来，所以只看前 5 维探个样子。

跑完看到的就是两行数，一行是第 1 个单词的前 5 维，一行是第 2 个单词的前 5 维。

## 打印编码器层对象的结构

还想更彻底地看清这一层里装了什么，有个很刺激的招：把 `encoder_layer` 这个对象本身打出来。

```python
    print("编码器层对象:\n", encoder_layer)
```

打出来的就是一整个嵌套结构，横着读下来，每一项都对得上我们写过的代码：

```text
EncoderLayer(
  (self_attn): MultiHeadedAttention(...)
  (feed_forward): FeedForward(...)
  (sublayer): ModuleList(
    (0-1): 2 x SublayerConnection(
      (norm): LayerNorm(...)
      (dropout): Dropout(p=0.1, inplace=False)
    )
  )
)
```

逐块对照一下：

- `self_attn` 是一个整体，就是多头注意力子层里的那个多头注意力组件，对应我们刚才传进去的 `multi_head`；
- `feed_forward` 也是一个整体，就是前馈全连接子层里的组件；
- `sublayer` 是一个 `ModuleList`，里面写着 `0-1`、`2 x SublayerConnection`——意思是这里有**两个子层对象**，因为 `2 × SublayerConnection`。每个子里装着 `norm`（层规范化）和 `dropout`（随机失活，连同概率 `0.1`）。

看这个对象的时候，先看大框架再看里面：`self_attn` 圈一个整体，`feed_forward` 圈一个整体，`sublayer` 那个 `ModuleList` 圈一个整体，三个大块各归各位，再去细看 `LayerNorm` 和 `Dropout` 这些零件。

## 从对象结构读出网络层数

再把注意力放到 `self_attn` 里面那一层：

```text
MultiHeadedAttention(
  (linears): ModuleList(
    (0-3): 4 x Linear(...)
  )
  (attn): Attention(...)
  (dropout): Dropout(p=0.1, inplace=False)
)
```

`0-3`、`4 x Linear` —— 多头注意力子层里有**四个线性层**。每个头做注意力时 Q、K、V 各需要一个线性层，这是三个；多头的多个头算完之后要把结果合并回一个，还需要一个线性层，加起来四个。你忘了就问自己一句：当时讲多头机制时那个「吃火锅」的比方，把特征切成细丝分给不同的头去处理，切之前要投影、切完要合并，投影和合并用的都是全连接层——三路投影加一路合并，四个。

再看前馈全连接：

```text
FeedForward(
  (linear1): Linear(in_features=512, out_features=2048, ...)
  (linear2): Linear(in_features=2048, out_features=512, ...)
  (dropout): Dropout(p=0.1, inplace=False)
)
```

**两个线性层**：一个是升维，从 `512` 升到 `2048`；另一个是降维，从 `2048` 降回 `512`。一升一降之间做非线性变换，特征就被强化了一遍——这就是前馈全连接在这一层里的全部职责。

汇总一下这一层里到底有几层网络：

| 子层 | 内部线性层数 | 作用 |
| --- | --- | --- |
| 多头注意力子层 | 4 | Q、K、V 三路投影 + 多头结果合并 |
| 前馈全连接子层 | 2 | `512 → 2048` 升维、`2048 → 512` 降维 |

> **结论**：一个编码器层 = 两个子层；多头注意力子层里有 4 个线性层，前馈全连接子层里有 2 个线性层。这些数字不需要背，把对象打印出来，结构自己会告诉你——而且打出来的每一项都能指回你亲手写过的代码，指针指到哪，哪就是它的定义。

把对象打印出来这件事，比单看形状有价值得多：形状只回答「通了没有」，对象结构回答的是「里面是什么」。以后往上拼编码器、解码器的时候，凡是怀疑某一层内部少装了东西，都可以用同样的办法先打印再判断。
