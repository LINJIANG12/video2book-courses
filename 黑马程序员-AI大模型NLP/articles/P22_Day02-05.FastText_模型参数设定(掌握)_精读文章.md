# FastText 词向量训练的超参设定

到目前为止，词向量的第一波操作就差最后一个动作了：模型的参数设定。我们从一开始写的那段训练代码，有个默认行为一直藏着没露脸——`train_unsupervised` 在训练的时候，底层默认用的始终是 skip-gram。可我要用 CBOW 怎么办？我想让词向量的维度多一点怎么办？训练轮数、学习率、线程数这一堆又要从哪儿改？这就得把参数一个一个摆到台面上来。

这一讲要干的事其实很朴素：把"直接默认开训"换成"手动把参数写清楚"，再对比一下两次执行的速度差，看清这些参数到底在影响什么。

## 从默认开训到手动设定参数

先回顾第一版的写法，它是直接开始训练的：

```python
my_model = fasttext.train_unsupervised('./data/5万行2ed.txt')
```

这一句里除了数据路径，什么都没有。模型用什么模式、词向量多少维、跑几轮、几个线程，全部交给底层默认值决定。做基线验证可以，想控制训练过程就不行了。

所以第一个动作是把这段注释掉，第二个动作叫超参设定——说白了就是手动调整参数。`train_unsupervised` 点进去往下拉，参数面板一大串。这里不必每个都讲：很多参数在课程里根本用不到，真需要的时候自己查文档就行，讲一遍也记不完。我们只玩常用的那几个：`input`、`model`、`dim`、`epoch`、`lr`、`thread`。

```python
my_model = fasttext.train_unsupervised(
    input='./data/5万行2ed.txt',
    model='cbow',
    dim=50,
    epoch=1,
    lr=0.01,
    thread=10,
)
my_model.save_model('./data/new.bin')
print('训练完毕，模型保存成功')
```

写完这段再去和第一版比一比：除了多出这几行超参，其余一模一样，连保存动作和提示语都没变。这就是这一讲的全部改动量。

`train_unsupervised` 的参数面板里当然不止这六个，但没必要每一个都讲一遍——很多参数目前的案例用不到，以后真用到了自己查文档就行，讲一遍也记不完。这六个是必须先弄明白的：

| 参数 | 作用 | 默认值 / 本讲取值 |
| --- | --- | --- |
| `input` | 训练数据的路径 | 无默认可用值，指定为 `./data/5万行2ed.txt` |
| `model` | 词向量模型模式 | 默认 `skip-gram`，本讲改为 `cbow` |
| `dim` | 词向量的维度 | 默认 100，本讲取 50 |
| `epoch` | 训练轮数 | 本讲取 1（不写走更大值） |
| `lr` | 学习率 | 本讲取 0.01 |
| `thread` | 线程数 | 默认 `multiprocessing.cpu_count() - 1`，本讲取 10 |

## 六个常用参数的含义

### `input`：训练数据的路径

`input` 给的是本次训练要吃的语料文件，即数据集的训练数据路径。我们用的是切分好的 `./data/5万行2ed.txt`。这个参数不能省，因为默认值不是我们的数据——不显式指定，你训练的就是别人的语料。

> **提示**：路径里的 `./` 表示相对当前运行目录，实际写的时候按自己的工程结构调整，只要指到那份语料上就行。

### `model`：词向量模型的训练模式

`model` 往下看，默认值就是 skip-gram。这里我们不用默认，改成 CBOW：`model='cbow'`。

> **定义**：`model` 决定用哪种模式训练词向量，取值是 `cbow` 或 `skip-gram`；CBOW 基于两边预测中间，skip-gram 基于中间预测两边。

### `dim`：词向量的维度

`dim` 是每个词用多少个数字来表示，默认 100。500 太大了，我设 50；你想换自己换。

> **注意**：维度不是越大越好。它直接决定权重矩阵的大小和训练开销，先跑通就用小维度。

### `epoch`：训练轮数

`epoch` 默认 5，在这里就是训练轮数。课上我们设成 1，也就是只跑一轮。

为什么不干脆写 1000？因为这份语料是 5 万行，跑 5 轮大概两分钟；跑 1000 轮你今天就不用上课了，坐在这儿一直跑它就得了。所以这里是"能调，但你得看时间成本"——你想改自己改，我只是告诉你这玩意儿可以调。

### `lr`：学习率

`lr` 是学习率，课上设 0.01。它管的是每次反向传播更新权重时的步子迈多大：步子太大容易在最优解附近来回跳，步子太小训练慢。

### `thread`：线程数

`thread` 是训练用的线程数，课上设 10。这个参数要特别说一句：点进去看它的默认值，写的是 `multiprocessing.cpu_count() - 1`，也就是"你的 CPU 有多少个核就减 1"，留一个核给系统和其他进程。

在我的机器上是八核十六线程，所以 `cpu_count()` 给 16，默认值就是 15。也就是说，默认值本身已经把机器吃得很满了。但要注意机器和机器不一样：换一台核心数少的机器，这个默认值会跟着变小，训练速度也就不一样。正因如此，填这个参数时不要照着机器的线程数往上加——100 太多了，给 10 其实已经很多很多了。

## 训练流程的五个动作

到这儿 Word2Vec 这一套其实就写完了，把顺序记牢：

| 序号 | 动作 | 说明 |
| --- | --- | --- |
| 1 | 获取训练数据 | 使用 fil9 数据集 |
| 2 | 词向量的训练与保存 | 直接默认参数训练，或手动设定超参后再训练 |
| 3 | 加载与查看 | `load_model` 载入，看模型里有什么 |
| 4 | 效果检验 | 找近义词 |
| 5 | 超参设定 | 即本讲的手动参数版本 |

```text
获取训练数据(fil9)
      |
      v
词向量训练 +-- 分支 A：默认参数直接训练
      |     +-- 分支 B：手动设定超参后训练
      v
   save_model 保存
      |
      v
   load_model 加载 -> 查看 -> get_nearest_neighbors 找近义词
      |
      v
  超参设定(本讲)：换回分支 B 重训，对比耗时与效果
```

读图说明：分支 A 和分支 B 的区别只在训练那一步写不写参数，后面的保存、加载、查看、找近义词完全相同。

## 一轮训练的速度与代价

最后一个动作是把超参版测试一遍：`run` 一下，很快就结束，比之前默认参数那次快得多。

对比一下两次训练的同一条时间线：

```text
默认参数训练：   ... 训练 5 轮（约 2 分钟） ... -> 保存 -> 加载 -> 找近义词
手动超参训练：   ... 训练 1 轮（约 20 秒内） ... -> 保存 -> 加载 -> 找近义词
                       ^ 差别只在 epoch，其余流程完全相同
```

读图说明：流程一步没少，唯一被改小的是轮数，耗时就按轮数等比例地掉下来。

为什么快了？因为这次只训练了一轮。默认 5 轮跑两分钟，1 轮自然就是这个量级；你要写 1000 轮，那就不是快慢的问题，是今天什么也别干了。

代价也马上能看到：用这份只训了一轮的新模型去找近义词，效果不会有上面那个好——训练的轮数太少了。所以参数设定这一段真正要记住的不是"填什么值最小"，而是"每个值在拿什么换什么"：轮数、维度、线程数都是用时间换质量（或者反过来）。你要有时间，就可以多跑一会儿。
