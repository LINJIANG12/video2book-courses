# 普通 Encoder-Decoder 框架：句子到句子的通用处理模型

要理解注意力机制到底加了什么，得先看清"没加"的时候长什么样。这一讲就是把普通编码解码器框架拆开看一遍：它怎么把一句话变成另一句话、中间那个语义向量 $C$ 承担了什么、解码器为什么还要拿到历史信息。把这一层摸清楚，后面加入注意力才知道变的是哪一处。

## 最朴素的形态：编码器给出 C，解码器拿 C 生成输出

先看框架图。左边是编码器（Encoder），你输入一堆 $X$，经过它处理得到一个中间语义向量 $C$；然后拿着这个 $C$ 进解码器（Decoder），在解码器里生成一些单词。

有人会问：这里一定是单词吗？一定是汉译英吗？会不会是英译汉、英译法、汉译俄？都可以。这只是取了一个例子而已，流程本身跟具体是哪种语言没关系。

> **定义**：上图可以看作**一个句子生成另一个句子的通用处理模型**，也就是 sequence to sequence（序列到序列，Seq2Seq），句子到句子。

所谓"句子对儿"，就是两句话成对出现。我们的目标是给定输入的 source，期待通过 Encoder-Decoder 生成 target——你给我一个 source，这是数据源；我希望得到 target，这是我的目标。

$source$ 和 $target$ 可以是**同一种语言**，也可以是**两种不同的语言**。你知道这中间的区别吗？

> **结论**：如果两边语言一样，这个任务叫**文本生成**——你现在看大模型，丢给它一个中文，它给你生成中文，这就是文本生成。如果两边语言不一样，这个动作叫**文本翻译**。但底层架构是一样的。学得越往后越会发现，知识点其实都是相通的。

$source$ 和 $target$ 分别由各自的单词组成：左边是 $X_1$、$X_2$……，右边是 $Y_1$、$Y_2$……。

## 注意力这件事，人脑早就在做了

顺着图往下走之前，先做一个小实验，它也解释了注意力机制的来由。

快速看一眼图，就 5 秒：1、2、3、4、5，好了。你看到了什么？"锦江饭店"。那边有个什么？你记住那个电话号码了吗？图里有几辆车，记住了吗？这里边有几个人？

怎么可能一下子全记住。正常情况你的第一眼应该只看到"锦江饭店"。

> **结论**：这就是注意力机制。人的视觉、人的大脑经过数万年的训练，早就做到这件事了——**自动忽略那些不想看的信息**。你现在看图、看知识点也是同样的道理，会自动忽略那些你不想看的部分。

## 注意力机制的分类

注意力机制的分类和实现，这里提一嘴就够，因为暂时不讲。它分三类：

**软注意力（Soft Attention）**：给每个输入项分配的权重落在 $0$ 到 $1$ 之间。关联度再小，它也有一个值，不会是硬邦邦的 0，这叫"软"。前面举的那种例子，我们一直在玩的就是软注意力机制。

**硬注意力（Hard Attention）**：对每个输入项的权重分配**非 0 即 1**。跟我有关联就是 1，但关照度是多少无所谓，只要有关联就是 1；跟我关联很小很小，就把你标成 0。

**自注意力机制（Self-Attention）**：对每个输入项分配的权重取决于输入项之间的**相互作用**，就是根据需求往里边传。

> **提示**：以后用得最多的一定是自注意力，这一点先记住，后面会专门讲。

## 解码器为什么还需要"之前生成的历史"

再回到普通的编码解码框架，把几个名词落到具体位置上。

Encoder 顾名思义，是对输入句子进行编码，把输入句子通过**非线性变换**得到一个中间语义向量 $C$。等会儿，什么叫非线性变换？你可以把它理解成一个激活函数。那这个 $f$ 具体当什么用？——把 $f$ 当作 **GRU** 就行。GRU 层本身就是加权求和加激活函数那一套东西，通过 GRU 处理，最后得到 $C$。

解码器的任务，是根据 $C$ **和之前生成的历史**来预测 $Y_i$。这里就有一个问题：预测 $Y_i$ 为什么会飞来 $Y_1$、$Y_2$、$Y_{i-1}$？

原因很简单：你想预测第十个词，前九个词你总得知道吧。那怎么知道前九个词是谁？看看 $C$ 记住的是什么——$C$ 记住的是左边这一堆输入词的全部信息。再看状态：$S_2$ 记住的是什么呢？$S_2$ 是 `Welcome to`，也就是已经生成出来的那两个词。所以你生成"北京"的时候，不仅需要 $C$（代表左边这一堆输入），还需要 $S_2$（代表 `Welcome to`）。

所以"想要知道前面的词"，就是**根据隐藏状态来获取**的。本次的输入和隐藏状态，共同得到本次的输出。

> **结论**：上图展示的框架，**没有体现注意力机制**。你可以把它理解为一个**注意力不集中的模型**：预测第一个词 $Y_1$ 时，我只要中间语义向量 $C$——因为我是第一个词，我不需要关心前面有什么；预测第二个词时，我不仅需要 $C$，还需要记住前一个词是谁的隐藏状态；预测第三个词就要 $C$、$Y_1$、$Y_2$；预测第十个词就是 $C$、$Y_1$ 到 $Y_9$。

按这个规律往下排，$Y_1$、$Y_2$、$Y_3$ 各自用到的东西是这样的：

```text
预测目标        用到的信息
---------------------------------------------
Y1              C                 （第一个词，前面没有历史）
Y2              C + Y1
Y3              C + Y1 + Y2
...
Yi              C + Y1 + ... + Y(i-1)
```

读图说明：每一个 $Y_i$ 都从同一个 $C$ 里取输入信息，差别只在于额外带上了多少历史输出词；横向看过去，$C$ 从头到尾没有变过。

## 从普通框架到注意力框架，只差 C 的下标

这一讲是一个过渡。现在再回头看这个模型，它比之前画的模型更简单：编码器得到 $C$，解码器用 $C$ 加历史生成输出。

再说一遍关键的那句：**不加注意力机制，这几个 $Y$ 用的中间语义向量 $C$ 是一模一样的。**

换成加注意力的版本，先扫一眼差别在哪：它变成了 $C_1$、$C_2$、$C_3$，大家已经不一样了。这就是加入注意力以后的效果。至于 $C_1$、$C_2$、$C_3$ 具体怎么算出来，是下一步的事。

> **易错点**：$C_1$、$C_2$、$C_3$ 不一样，不是因为输入的词变了，输入自始至终是同一句 source。变了的是**每一步在输入各位置上分派的权重**，权重不同，加权合成出来的总信息包就不同。
