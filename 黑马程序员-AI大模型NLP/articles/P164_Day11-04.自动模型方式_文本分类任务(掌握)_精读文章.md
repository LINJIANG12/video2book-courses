# 自动模型方式做文本分类：分词器、张量转换与推理输出

管道方式我们把六个 NLP 任务都跑通了，写完只剩下一个感觉：真省事。但也正因为太省事，问题就来了——那条 push 进去的数据，中间被做了什么我们完全不知道。

句子的长度我能自己把控吗？前面讲文本预处理的时候，截断、补齐这些操作我都能做，但换成 pipeline，这些活我插不上手：把数据丢给模型，它直接出结果，中间干了什么我看不见。我想做点 DIY，也做不了。

解决办法就是换第二种语法：自动模型（Auto）。所有以 `auto` 开头的 API 都属于这种方式，它的定位就是比管道方式更具体一点——多出来的那些“加功”的活，我们自己来干。

## 1 从管道方式到自动模型：多出来的那几步

先把两边的步骤摆在一起看，差别立刻清楚：

| 环节 | 管道方式 | 自动模型方式 |
| --- | --- | --- |
| 加载分词器 | 底层自动完成 | 第一步，自己写 |
| 加载模型 | 第一步，`pipeline()` 一次搞定 | 第二步，自己写 |
| 文本转张量 | 底层自动完成 | 第三步（还分两种思路），自己写 |
| 推理与输出 | 底层整理成可读结果 | 第四步自己调，输出自己解析 |

> **结论**：管道方式“上来就找模型”，自动模型方式“先找分词器，再找模型，然后自己把文本转成张量，最后才喂给模型”。中间多出来的那两层，正是我们想 DIY 时唯一能下手的地方。

## 2 三个 Auto 类与导包

先把包导进来。自动模型方式的导包看着多，其实非常好记。

```python
import torch
from transformers import AutoConfig, AutoModel, AutoTokenizer
```

`torch` 就是 PyTorch 深度学习框架，里面定义了张量计算、自动求导（自动微分）这些东西。后面三个类，记法很简单：`auto` 敲下去，编辑器提示里全是它们。

- `AutoConfig`：自动配置模型参数。每个模型都有自己的 `config`，里面就是它的各项配置参数，这个类负责把配置自动读出来。
- `AutoModel`：自动加载模型，可以理解成一个通用的模型加载类，专门帮你加载 Hugging Face 里各种模型。
- `AutoTokenizer`：自动加载“和模型匹配的”分词器，也就是一个通用的分词器加载类。

分词器存在的理由是：模型没法直接处理一大坨长文本，它需要先切词；而不同语种的切词习惯不一样，中文怎么切、英文怎么切都有各自的规则。你可以把 Tokenizer 类比成以前用的结巴分词器（类比可以，但别把它当成同一件事），它的本职就是分词。

光有这三个类还不够——它们只能把模型加载进来，没法让模型去完成具体任务。所以还要再导一组带任务头的类：

```python
from transformers import AutoModelForSequenceClassification
from transformers import AutoModelForMaskedLM, AutoModelForQuestionAnswering
from transformers import AutoModelForSeq2SeqLM, AutoModelForTokenClassification
```

> **提示**：`AutoModel` 和 `AutoModelForXxx` 走的是“同一个名字在不同类里重名的函数”这种设计（比如它们都提供 `from_pretrained`），目的就是方便开发者调用。用的时候要清楚自己调的是分词器的还是模型的——名字一样，对象不同。

## 3 六个任务对应的模型头

`AutoModelForXxx` 后面的那个单词，就是“任务头”。任务决定了要哪个头，而头的名字基本可以从任务名推出来：

| 任务 | 模型类 | 说明 |
| --- | --- | --- |
| 文本分类 | `AutoModelForSequenceClassification` | sequence 指文段，这里的分类就是在文段上做分类 |
| 特征提取 | `AutoModelForMaskedLM` | 即掩码语言建模，特征抽取在这里对应的是“掩码”这条线 |
| 问答 | `AutoModelForQuestionAnswering` | question + answering，问答 |
| 文本摘要 | `AutoModelForSeq2SeqLM` | 序列到序列建模，摘要就是典型的序列到序列 |
| 命名实体识别 | `AutoModelForTokenClassification` | token 级别的分类，具体到字 |

命名实体识别为什么归到 `TokenClassification`？因为它的标注能拆到每一个字上——像“北京天安门”会被标成 `B I I I I`，粒度是 token，比整句分类细得多。这就是“token 级分类”的含义。

> **提示**：有一个 `from rich import print` 的输出美化写法，作用是让打印出来的格式更好看一点。但效果并不明显——处理超长文本或特殊格式时它才会帮你做点自动换行之类的处理，而在 PyCharm 里该换行的地方它本来就帮你换了。写不写都行，不想写删掉即可。

## 5 文本分类的五步实现

### 5.1 第一步：加载分词器

第一步是加载分词器（Tokenizer）。它是把文本转成模型可接受输入格式的对象。

```python
my_tokenizer = AutoTokenizer.from_pretrained(r"Chinese_sentiment模型路径")
```

用“小社会”来理解这个设计：模型是老大，我们直接去找老大，老大不认识我们、不接见。那怎么办？先找老大的秘书——分词器。秘书知道老大的习惯，由秘书把我们的问题翻译成老大能吸收的方式。

所以第一步就是把模型配套的秘书找过来，`from_pretrained` 里写的就是这个模型匹配的分词器路径（这里用的是情感分类模型）。

### 5.2 第二步：加载模型

第二步才是加载模型，这回轮到任务头出场：

```python
my_model = AutoModelForSequenceClassification.from_pretrained(r"Chinese_sentiment模型路径")
```

管道方式是第一步就干这件事，现在不行了：必须先有秘书，再请出老大。分词器和模型用的是同名函数 `from_pretrained`，这一点要分清楚。

### 5.3 第三步：文本转张量

先定义待处理的文本：

```python
message = "人生该如何起步"
```

文本转张量有两种思路，下面分开写。

### 5.4 思路一：直接返回二维张量

```python
tensor1 = my_tokenizer(
    text=message,
    return_tensors="pt",
    padding="max_length",
    truncation=True,
    max_length=5,
)
```

这里的参数一个一个说：

- `text`：带编码的文本，也就是要处理的这句话。
- `return_tensors`：返回张量的类型，默认 `None`。可选值有 `pt`（PyTorch 张量）、`tf`、`np`（NumPy）。这里写 `pt`，返回的就是二维张量。
- `padding="max_length"`：填充方式，可以理解为“是否填充”。写 `max_length` 就是一律补到指定长度——比如最大长度是 50，不够 50 的就直接补到 50。
- `truncation=True`：是否截断。填充和截断这一对，在这里全都有了。
- `max_length`：指定输入的最大长度。

> **易错点**：只要用 PyTorch 框架，底层流转的东西就都得是张量。所以“把文本转成张量”这件事必须由训练好这套流程的分词器来做——秘书干的活，别指望模型自己接。

跑完看一下返回值的类型和形状，会发现它带着 `input_ids`、`attention_mask` 这些键，是一个字典式的结构，里面的张量是二维的。还有一个细节值得注意：我输入的是 `人生该如何起步` 七个字，可结果里只留下了 5 个 token——这就是 `max_length=5` 加 `truncation=True` 生效的结果，超出的部分被截掉了。

### 5.5 思路二：不加 `pt`，手动转张量

思路二是不写 `return_tensors`，但补上一个编码动作：

```python
message_list = my_tokenizer.encode(
    text=message,
    padding="max_length",
    truncation=True,
    max_length=5,
)
```

加上 `encode` 之后，打印出来的东西就干净了——纯粹的一串编号，没有前面那一套啰嗦的字典包装。但它的类型是列表，不是张量。

> **易错点**：模型要的是二维张量，你手里是一个列表，这个列表直接传进模型是处理不了的。所以要手动把它转成二维张量：

```python
tensor2 = torch.tensor([message_list])
```

用中括号把列表再包一层，就升成了二维。

### 5.6 两种思路的对比与取舍

| 思路 | 写法 | 返回物 | 后续动作 |
| --- | --- | --- | --- |
| 思路一 | 带 `return_tensors="pt"` | 二维张量（带字典包装） | 直接可用 |
| 思路二 | 不加 `pt`（用 `encode`） | 一维列表 | 需 `torch.tensor([...])` 手动升维 |

把两种方式的打印结果上下对齐看，内容完全一样——同样的一串编号，同样的形状。既然结果一样，以后就用带 `pt` 的那种，省一步手写。

> **提示**：`padding="max_length"` 会把每一条都补到 `max_length`，所以上面两个句子的张量长度一致，都是 30。批量送入模型时，长度必须对齐，这正是管道方式里我们控制不了、而现在能自己控制的那一环。

## 6 第四步：推理

推理分两步：

```python
my_model.eval()
result = my_model(tensor1)
```

`eval` 在这里是 evaluate，做预测、进入评估模式（也叫推理模式）的意思。它的好处是关闭 Dropout、随机失活这些只在训练时使用的层——现在是预测，训练特有的层一律不用。

传 `tensor1` 还是 `tensor2` 都行，因为前面已经核对过，两者内容一模一样。

## 7 第五步：输出格式

输出这边也分两种写法：

```python
result = my_model(tensor1)                                  # 默认返回字典
result2 = my_model(tensor1, return_dict=False)              # 返回元组
```

- 默认情况下，`result` 是一个包含模型输出的字典，类型是 `SequenceClassifierOutput`，里面是 `loss=...`、`logits=...` 这样一排键值对。
- 加上 `return_dict=False`，返回的就是元组。元组里当前只有一个张量对象，写成小括号加逗号的形式。

两种写法拿到的东西对不上：字典那种结构键值分明，但一眼看下去不太好懂；元组那种拎出来就是裸数据，当列表读也行，但对不上字段名。想弄清楚里面装了什么，两种都要打出来看看。

模型吐出来的是 `logits`，也就是每个类别一个分数。情感分类要的是一条结论，所以在 `logits` 上取最大值对应的下标即可：

```python
import torch

logits = result.logits                      # 形状 (1, num_labels)
pred_id = torch.argmax(logits, dim=-1).item()
print(pred_id, logits)
```

> **提示**：`logits` 是未经归一化的打分，形状是 `(1, num_labels)`——一条样本、每个类别一个分数。类别下标与“好评/差评”这类标签文字的对应关系，取决于该模型自己的配置，因此先看下标、再按模型说明把它翻译成标签，是最稳的做法。

## 8 整条链路的复盘

把这一讲的四个步骤串起来看，就是下面这条链路：

```text
文本 "人生该如何起步"
   |
   v
[1] AutoTokenizer.from_pretrained(...)      找秘书：分词器
   |
   v
[2] AutoModelForSequenceClassification
        .from_pretrained(...)               找老大：带任务头的模型
   |
   v
[3] 秘书处理文本：分词 + 补/截 + 转张量
        return_tensors="pt" ------------> 二维张量（一步到位）
        不加 pt ------------------------> 一维列表 --torch.tensor([...])--> 二维张量
   |
   v
[4] my_model.eval()  关闭 Dropout 等训练专用层
    my_model(tensor) 前向推理
   |
   v
[5] 返回值：return_dict=True -> 字典 SequenceClassifierOutput
            return_dict=False -> 元组（括号里就一个张量）
   |
   v
   logits --argmax--> 类别下标 --按模型标签--> 分类结论
```

读图说明：第 1、2 步是“找人”，第 3 步是“秘书把我们的问题翻译成老大认识的格式”，第 4 步才是老大出面干活，第 5 步把结果整理成我们要的形式。

> **结论**：自动模型方式一共四步（再加打印输出）——找秘书、找老大、准备数据、送进去推理。以后所有任务都按这个骨架走：换的只是 `AutoModelForXxx` 那一个任务头，以及各任务对输出的解读方式。
