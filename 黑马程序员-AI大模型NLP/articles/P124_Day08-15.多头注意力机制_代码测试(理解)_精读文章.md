# 多头注意力机制的代码测试：从函数改名到掩码批次数对齐

多头注意力机制的代码已经写完了，接下来就是把它跑起来看一眼。测试这部分本身不复杂，但它中间会撞上一个特别典型的报错——掩码第一维到底该传几。这个报错把我们前面写的 `view`、`transpose`、头数、批次这些看起来各自独立的东西一次性串到了一起，值得单独拿出来说透。

先把测试动作按顺序摆出来：创建多头注意力层的对象、拿位置编码处理后的结果、把同一个变量同时当作 Q K V、造一个掩码张量、把数据送进层里、打印输出形状、把结果返回出去。七个动作，其中第五个之前还夹了一次“改名”，我们从头说。

## 测试函数的命名统一

写测试时我一开始用的是 `use_attn` 这样的名字，改成 `use_multihead_attention` 更贴切——它就是多头注意力。但在动这个测试函数之前，有一件更让人难受的事要先处理。

你看代码里满屏都是 `demo02`、`demo02`、`demo02`：拿位置编码结果调它，后面所有动作也都调它。这种名字读到第三遍就不知道自己在读什么了。所以我把函数名改一下，统一命名，后面所有调用点跟着一起统一。

要改的为什么是 `demo02` 而不是 `demo01`？因为 `demo01` 是词嵌入的测试函数，词嵌入在位置编码这个函数内部已经被调用过一次了，测试链路上不需要再单独去调它，这个名字留着不动也不影响阅读。真正需要改的是做位置编码测试的那个 `demo02`，改成 `use_position`——`use` 就是“使用”，一眼看出它是给后面步骤供给位置编码结果的。

改名的代价是有两处必须同步：

- 定义处改成 `use_position`；
- 调用处也要从 `demo02` 换成 `use_position`。

调用处漏改会怎样？不用一行一行去扒、也不用全局检索。编辑器会把这处直接标红，把红色那一段点开双击，它会告诉你“这个函数不存在”，并且提示它原来对应的是哪个位置。照着红色提示把它从 `demo02` 改成 `use_position`，红色消失，改名就完成了。

> **提示**：如果你懒得改名，后面全用 `demo02` 一路写下去也能跑通，效果完全一样。改名只是为了让这段代码读起来舒服。

## 测试步骤的七个动作

### 第一步：创建多头注意力层对象

第一个动作是创建多头注意力层的对象。注意它是一个**层对象**，不是一次函数调用，所以这样写：

```python
my_attention = MultiHead(512, 8)
```

两个参数就是上面写好的那一堆：`512` 是词向量维度 `d_model`，`8` 是头数 `head`。

### 第二步：获取位置编码处理后的结果

第二个动作是拿位置编码处理后的结果，也就是刚刚改名后的那个函数：

```python
position_x = use_position()
```

`position_x` 是什么？它是**词嵌入结果再叠加上位置编码**之后的产物。这一点决定了下一步 Q K V 从哪里来。

### 第三步：Q、K、V 取同一个变量

因为是自注意力机制，Q、K、V 三者来自同一个源，所以这一行没有任何悬念：

```python
Q = K = V = position_x
```

有人会犹豫要不要在这里再写一次 `512`、`8` 这类参数。不用。词嵌入和位置编码处理完之后，这个内容本身就是既当 Q、又当 K、又当 V 的那份数据。写成 `Q = K = V = my_attention` 是错的——`my_attention` 是层对象，不是数据。

### 第四步：创建掩码张量

第四个动作是创建掩码张量。用不用都可以，这里为了对齐真实流程，我们造一个：

```python
mask = create_mask(batch_size=8, seq_len=4)
```

掩码的形状按定义是 `batch_size, seq_len, seq_len`，`seq_len` 取 4，那就应该是 `8 4 4`。这里先按下不表，第五步之后会专门回去讲这个 `8` 是怎么来的。

### 第五步到第七步：送入模型、打印、返回

第五个动作把数据送给模型，拿多头注意力的结果：

```python
result = my_attention(Q, K, V, mask)
```

第六个动作打印输出形状，检查它和输入形状是否一致：

```python
print('多头注意力层', result.shape)
```

输入是 `[2, 4, 512]`，那么输出也应当是 `[2, 4, 512]`——多头注意力只做特征层面的重组，不改形状。跑通以后控制台应该打出这个形状。

第七个动作是返回多头注意力结果：

```python
return result
```

为什么非要返回？因为后面残差连接、规范化层、前馈全连接都要用到这个结果。返回之后，后面用的时候直接调这一个函数，前面那一整串（位置编码、Q K V、掩码、送入模型）都不用重写。

> **结论**：组件里每一层我们都写了带返回值的测试函数——词嵌入、位置编码、多头注意力、前馈全连接各有各的入口。想从哪个节点切入，就调对应函数往后走。这样用起来灵活得多。

改完这一版，最后一块测试代码就注释掉，换新的测试函数调一次，右上角右键运行。

## 掩码第一维对不上时出现的报错

### 报错现场

先按上一步的写法跑，我们保证打印出来的结果还是 `2 4 4` 相关的形状。这时会跳出一个错：某个 `int` 类型没有 `transpose` 这个操作。

顺着报错点进去，问题还是出在刚才那个 `x` 的位置上——`transpose` 写错了地方。

### 先修 transpose 的位置

我们要的是：先把 `x` 变形，再交换维度。所以 `transpose` 必须写在 `view` 之后：

```python
x = x.view(batch_size, seq_len, self.head, self.d_k).transpose(1, 2)
```

拆开看形状怎么走的：`view` 先把 `(2, 4, 8, 64)` 这类四维摆好，随后 `transpose(1, 2)` 把第 1 位和第 2 位对调——原来的第 1 位是 4（句长），第 2 位是 8（头数），对调之后就是 `8, 4`，合起来得到 `(2, 8, 4, 64)`。

> **提示**：写代码出错不要慌，先看它下面报的是什么错，再顺着错去改。不出错是不太现实的，真正要练的是出错以后能快速定位——报错会告诉你哪一行爆的，从那一行往里点，一路点到底层，就能看出问题落在哪个维度上。

### 掩码第一维为什么必须是 8

现在回到掩码。我把 `create_mask` 里的 `batch_size` 从 `8` 改成 `2`（`2 4 4`），结果又报错：

```text
The size of tensor a (8) must match the size of tensor b (2)
```

它必须和另一个张量匹配，匹配的对象是注意力计算里的这一句：

```python
scores = scores.masked_fill(mask == 0, -1e9)
```

报错会直接告诉你它在哪一行、哪个函数里爆发，点进去再往下点，就落到 `masked_fill_` 这个底层调用上。

原因很简单：这里已经把头拆成了 **8 个头**，`scores` 的第一维经过 `view + transpose` 之后不再是最初的批次数 2，而是 8。所以掩码第一维也得跟着是 8，必须写 `8 4 4`，不能写 `2 4 4`。

再往层里面看，还能看到一条印证：掩码不为空时，它立刻做掩码处理，紧接着取批次时写的是

```python
batch_size = query.size(0)
```

也就是说，批次数是**从头拆完之后那个张量里现取的**，取出来就是 8。这就解释了为什么这个掩码的第一维必须和头数对齐。

```text
输入 x                          掩码 mask
  (2, 4, 512)                     (8, 4, 4)
      |                               |
      | view(batch, seq, head, d_k)   |
      v                               |
  (2, 4, 8, 64)                       |
      | transpose(1, 2)               |
      v                               |
  (2, 8, 4, 64)  --- Q/K/V ---------> |
      |                               |
      | 注意力打分 scores (2, 8, 4, 4)|
      |                               |
      +---- masked_fill(mask == 0) <--+
                    |
                    v
        第一维必须是 8，即头数
```

读图说明：多头注意力在内部把批与头压到了同一维（第一维 = 2 与 8 合并后的结果），所以对 `scores` 做 `masked_fill` 时，掩码的第一维必须等于头数 8，写 2 就会在维度匹配上直接报错。

> **注意**：这里掩码第一维用 8，是这个多头实现里张量排布方式决定的，不能反过来把它当成“掩码第一维永远等于头数”的通用规则。真要讲统一，只能讲一件事——掩码的每一维都得和被作用的那张张量对上。

## contiguous 与 view 的适用条件

看代码的时候会注意到一个细节：在调用 `view` 之前，为什么要先做 `contiguous`？

因为 `view` 只能处理**连续张量**。什么叫连续张量？就是你在控制台打印出来的元素顺序，和在内存里存储的顺序完全一致——两者一致，就是连续的；内存中的排布和控制台打印出来的不一致，就是不连续的。

`contiguous()` 的作用，就是把不连续张量变成连续张量。判断一个张量连不连续，用的函数是 `is_contiguous()`。这两个东西在深度学习第一、第二天写张量操作的代码时都练过，忘了就回去搂一眼那份代码。

再看 `view` 和 `transpose` 的分工：两者都在动维度，但 `view` 可以一次处理多个维度，`transpose` 一次只能交换两个维度。这是之前学过的内容，不用重写。

## 掩码与自注意力机制的要点收敛

上三角和下三角的特点很好理解：上三角是有值的位置落在对角线上方，下三角是有值的位置落在对角线下方。

那下三角是怎么把未来信息挡住的？靠 `masked_fill_` 这个函数往数据里填——凡是掩码在 0 或 1 的位置，就按条件去掩。

> **易错点**：不要背死“0 表示能看见、1 表示看不见”。完全可以是 0 看不见、1 能看见，到底哪种，取决于你写在 `masked_fill_` 里的判断条件是 `mask == 0` 还是 `mask == 1`。条件写哪边，哪边就被遮住。这里做掩码的根本目的只有一个：防止偷看未来的信息。

自注意力机制的实现流程，前面已经从头走过一遍，核心是那个公式：

$$ \text{Attention}(Q,K,V) = \text{softmax}\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V $$

一步都不能少：先拿 $Q$ 乘 $K$ 的**转置**，再除以 $\sqrt{d_k}$（$d_k$ 就是每个头的维度，取维度再开平方），这一步算出匹配分；然后对匹配分做 softmax，得到归一化的权重；最后拿权重乘 $V$。

> **易错点**：这里最容易漏两处——忘记对 $K$ 取转置，或者漏掉除以 $\sqrt{d_k}$ 的缩放。少了转置维度对不上，少了缩放分数会过大。

自注意力产出的 `2 4 4` 是什么意思？一批是两个句子，每个句子有四个词，`4 4` 就是**当前这个词对包括自己在内的四个词的依赖权重**。第一批 2 个句子各一张这样的权重表，就是 `2 4 4`。

最后收一句多头：多头很简单，就是在一个 `head` 上做拆分。以前是**一个人管 512 维**，现在变成**八个人管 512 维**，每人只管 64 维，最后把八个人的结果汇总起来。
