# RNN 隐藏层层数的修改、形状推演与优缺点归纳

上一节我们把句子的长度改了，参数图跟着动了一格。这一节换个地方动：把隐藏层的层数从 1 改成 2。事情看起来比改句长还简单，只有一个数字变了，但恰恰是这一个数字，让不少人复制粘贴代码的时候漏改了一处，程序跑起来才报形状错误。

## 1. 隐藏层层数改动牵连的形状参数

一开始的时候，隐藏层的层数我们一直写的是 1。现在把它从 `1` 改成 `2`，你告诉我谁变了？

是不是后边这个隐藏层的层数要变？还有别的吗？没了。只有它变了。那它变了之后，跟着变的是什么？是 `h_0` 这个位置的形状——它会从 `[1, 2, 128]` 变成 `[2, 2, 128]`。其他地方照常依旧，该是什么还是什么。

我们把参数图摆在旁边，一边改代码一边对照。这一讲的图里，`h_0` 的位置画得很清楚，它和隐藏层的层数是绑在一起的。

> **提示**：真正会出错的不是"改哪个数"，而是"改了数以后忘了改形状"。这两件事在图上永远是成对出现的，图上标了，代码里就得贴。

### 定义变量与配置隐藏层层数

这一步的操作和上一节改句长时是一模一样的：先定义变量，再传递参数，只是这次传的是隐藏层的层数。

```python
# 配置参数 - 本批样本 2 条，句子长度 1，每个词的向量维度 128，隐藏层神经元个数 256
batch_size = 2      # 每一个批次给模型喂 2 条样本
seq_len    = 1      # 每一条样本的句子长度（时间步数）
input_size = 128    # 每个词的词向量维度
hidden_size = 256    # 隐藏层神经元个数（也就是隐藏状态的维度）
num_layers = 2      # 隐藏层的层数：从 1 改成 2，本节的唯一改动
```

对应的画布是"图 3"，内容就是把"定义变量 + 贴函数"再走一遍，函数换成 `nn.RNN`，而这次要改的变量名叫 `num_layers`——隐藏层的层数。变量名写全一点更好认：`hidden_layers`。

这里我想说一句话：你现在把这个图往这一摆，我觉得无论我改哪一个数，你都知道我在修改谁，而它一改，其他参数也应该相应地发生变化。这就是我要说的点。

这张图里的参数是我们一开始一个一个标上去的。所以我希望你们做一件事：这个图你能背下来最好；背不下来，就把它收藏一下。万一哪一天需要写到参数了，你直接把这张图打开，往里面把参数一填，就知道结果是啥样了。

```python
import torch
import torch.nn as nn

rnn = nn.RNN(input_size=128, hidden_size=256, num_layers=num_layers, batch_first=False)
```

## 2. 隐藏层层数修改后的形状推演

参数都摆好了，两个样本、句子长度 1、词向量 128 维、隐藏层神经元 256 个、隐藏层 2 层。

先看输入：

```python
x  = torch.randn(seq_len, batch_size, input_size)      # [1, 2, 128]
h0 = torch.randn(num_layers, batch_size, hidden_size)  # [2, 2, 256]
```

**这一次改完，`h_0` 这个位置必须换成 `[2, 2, 256]`。** 我们刚才写的还是 `[1, 2, 256]`，层数改成 2 了，`h_0` 却不跟着改，就直接错了。形状错了后面全崩。

再看输出：

```python
output, hn = rnn(x, h0)
print(output.shape)   # torch.Size([1, 2, 256])
print(hn.shape)       # torch.Size([2, 2, 256])
```

先看形状，一个一个念一遍。`output` 是不是还是 `[1, 2, 256]`？是。`hn` 呢？是不是 `[2, 2, 256]`？是，因为两层，第一维就是 2。

那 `nn.RNN` 自己打印出来的结果长什么样？一层的时候它默认把层数省略了，你看不见那个 1；两层的时候，它就会给你显示一个 2：

```text
RNN(128, 256, num_layers=2)
```

> **易错点**：`h_0` 是**入参**，`h_n` 是**返回值**，两者形状规格相同（都是 `[num_layers, batch_size, hidden_size]`），但改层数时容易只顾着写参数、忘了把喂进去的 `h_0` 一起改。复制粘贴的场景下，这是最高频的漏改点。

顺手把整条链上的形状对一遍，就不会漏：

| 变量 | 含义 | 形状 | 是否随 `num_layers` 变化 |
| --- | --- | --- | --- |
| `x` | 本次输入 | `[1, 2, 128]` | 否 |
| `h_0` | 初始隐藏状态（入参） | `[2, 2, 256]` | **是** |
| `output` | 每个时间步的输出 | `[1, 2, 256]` | 否 |
| `h_n` | 最后一层的隐藏状态（返回） | `[2, 2, 256]` | **是** |

对照读一遍：输入 `x` 与 `output` 不受层数影响；两个隐藏状态的位置由层数决定第一维。

再对上参数的总账：`input_size` 是 128，`hidden_size` 是 256，`num_layers` 是 2，`batch_size` 是 2，`seq_len` 是 1。

> **结论**：无论以后在图上改谁，都要记住它的参数就这 12 个——`nn.RNN` 的 9 个入参，加上它返回的 `output`、`h_n` 以及贯穿全程的 `x`。无论你改谁，对应的位置发生改变，代码就不会错。

## 3. 隐藏层最后一层与输出层的关系

改完之后再看一眼 `output` 和 `hn`，你会发现一件事：`hn` 的最后一层，记录的就是 `output` 那一层的结果。

```text
output: [1, 2, 256]   <- 每个时间步的输出
hn:     [2, 2, 256]   <- 第 0 层是隐藏层 1 的结果
                         第 1 层是隐藏层 2 的结果，与 output 一致
```

于是有人就要疑惑了："我有两层隐藏层，为什么 `hidden` 只记录最后一个？那中间那一层是干啥的？"

它是**过渡**的。不是记录上一次，是过渡。什么意思？往下看图。

先把话说在前面：两层这种操作，实际开发中一般是不做设置的。但既然设置了，它的底层图解你就得能想清楚。

时间步展开以后是这样的：第一个时间步、第二个时间步、第三个时间步，每一步都是"本次的输入 + 上次的隐藏状态"，得到本次的隐藏状态和本次的输出。

```text
只有一层时（时间步展开）：

  x1        x2        x3
   |         |         |
   v         v         v
 [H1] ---> [H1] ---> [H1]        每步都是：本次输入 + 上次隐藏状态
   |         |         |
   v         v         v
  y1        y2        y3
```

现在把层数改成 2。输入 `x` 先经过隐藏层 1，再经过隐藏层 2。所以隐藏层 1 其实就是一个过渡，隐藏层 2 才是我们最终的结果。

```text
两层时（同一时间步内部纵向加深）：

        x （本次输入）
        |
        v
  [隐藏层 1]  <- 中间结果，过渡用
        |
        v
  [隐藏层 2]  <- 最终结果，与 output 一致
        |
        v
        y （本次输出）
```

这就解释了你刚才看到的现象：隐藏层 1 的结果是下面那一层，隐藏层 2 的结果是上面那一层，再往上就对接输出那一坨了。

那如果是三层、四层、五层呢？就是 `x` 在这里算一层、算两层、算三层，最后算到 `y`。区别在哪？运算量肯定增加了。层数增加，你可以学到更多特征信息——算力增加了，效果可能相对来讲会好那么一点。

### 换一个角度：把纵向加深看成一摞前馈网络

这个图你要是看不懂，就把它转一下。把每一层的含义标出来：这是输入层，这是隐藏层 1，这是隐藏层 2，这是隐藏层 3，这是输出层。

```text
转成"垂直摆放"再看：

   输入层
     |
   隐藏层 1        <- 等于在中间插了一个隐藏层
     |
   隐藏层 2
     |
   隐藏层 3
     |
   输出层
```

转成这样以后，你用 ANN（人工神经网络，Artificial Neural Network）来解释就通了：ANN 是输入、一个隐藏层，然后直接对接输出。而现在的动作，相当于在中间又加了几个隐藏层——输入到隐藏到隐藏到隐藏，才到输出。

实在要说，它就是把数据本来"从 `x` 直接算到 `y`"的这个动作，改成了"`x` 先算到中间，再往上算一步到 `y`"，中间插进去了几层。

但实际开发中，一般不会加这个层数。你加了也要记住一句话：**最后一层等价于你输出的那个结果**。

> **易错点**：`h_n` 里只保留每一层在**最后一个时间步**的隐藏状态，中间时间步的历史并不在里面；需要全部时间步时取 `output`。这也是下一节讲长序列问题时最容易被误解的地方。

## 4. RNN 的优缺点与梯度连乘

把 RNN 的总结落地。先说优点，一共三条：

| 优点 | 具体说法 | 为什么 |
| --- | --- | --- |
| 内部结构简单 | 结构本身很简单 | 里面就是一个加权求和，再扔一个激活函数处理，就完事了 |
| 计算资源要求低 | 对资源消耗相对较小 | 同上，运算量小，所以对算力不挑 |
| 短序列任务表现好 | 短序列任务上性能与效果都优异 | 依赖链短，上一时刻的隐藏状态足够承载 |

还有一条对比：RNN 的变体 LSTM、GRU，参数总量比 RNN 少很多。这句话反过来也说明一件事——RNN 内部结构简单，一会儿它的变型 LSTM 和 GRU 的内部结构就不简单了。

再说缺点，两条，但根子是同一个。**在什么任务上不行？** 长序列。什么叫短序列？就是你句子的长度不能太多、不能太长。一个句子的长度是 100 个词或者 200 个词，这种长序列它就干不了了。

为什么？因为长序列经过反向传播的时候要去更新参数，数据量太多，反向传播时容易出现梯度消失或者爆炸的问题。

至于"长序列文本特征提取效果差"，原因也很直接：你总是用上一时刻的隐藏状态往下接，用那个 `h0`、`h1`、`h2` 一路往后传，越往后你的 `h` 里面记录的信息就越多。你能记 5 个词，你能记 500 个词吗？你能记 5000 个词吗？一个 `h` 怎么可能记那么多信息。

> **提示**：这个道理用一句话就能验证——让你用一句话去形容自己从小到现在的人生经历，你怎么可能通过一句话把人生总结下来？就算硬说，也只能说一句"历经磨难"，意义就不大了。RNN 处理短序列比较好，但要处理长序列、想通过上一时刻的隐藏状态去记住所有信息，这个压力太大了。

梯度为什么会消失、为什么会爆炸？想个最简单的例子：

```text
梯度连乘：0.5  ×  0.5  ×  0.5  ×  ...   ->  迅速趋近于 0     （梯度消失）
梯度连乘：1.1  ×  1.1  ×  1.1  ×  ...   ->  迅速变得极大     （梯度爆炸）
```

一直乘下去，0.5 很快就会非常非常接近 0；换成 1.1，一会儿值就超级超级大，有可能爆炸。

> **结论**：RNN 的优点就是更适合计算资源低的场景、更适合短序列任务；缺点就是长序列任务不太适合。正因为不适合处理长序列文本，而处理长文本的需求又确实存在，所以才有它的变形——LSTM 与 GRU。

把这段写进笔记的时候，正好补上前面留的那个空：

- **优点**：内部结构简单；资源消耗相对较小；适合处理短序列文本。
- **缺点**：处理长序列数据时，反向传播结合梯度连乘，过大或过小的 $w$ 值会导致梯度爆炸或梯度消失。

## 5. RNN 的内部结构、数学公式与 API 参数

### 内部结构、输入输出与变量含义

RNN 的内部结构由输入层、隐藏层和输出层组成。

写代码的时候记住一句话：RNN 是**两个输入对应两个输出**。两个输入是本次的输入和上一时刻的隐藏状态，两者融合到一起，再经过特定处理，得到本次的隐藏状态和本次的输出。

```text
        h0（上一时刻隐藏状态）
              |
              v
  x（本次输入） -> [融合 + 特定处理] -> hn（本次隐藏状态）
                                          |
                                          v
                                    output（本次输出）
```

变量名的对应关系理清：

- `input` 是本次输入；
- `output` 是本次输出；
- `h0` 是上一时刻的隐藏状态；
- `hn` 是本次的隐藏状态。

> **易错点**：`h_0` 是**喂进去的初始状态**，`h_n` 是**返回的末状态**，名字只差一个字母，方向正好相反。位置写反了，形状可能碰巧对得上，数值却完全是错的。

### 数学公式：学术写法与工程写法

RNN 模型的数学公式有什么好讲的？看两个写法：

$$h_t = \tanh(W \cdot [h_{t-1}, x_t] + b)$$

这是把本次输入和上一时刻隐藏状态拼在一起，用一组权重做完加权求和，再过一个 `tanh`。

$$h_t = \tanh(W_{xh} \cdot x_t + W_{hh} \cdot h_{t-1} + b)$$

这是把两部分分开各乘一组权重再相加，同样过 `tanh`。

学术里那个 $W$ 权重就是一个；业界的公式里是两个。第一个算的是本次输入的贡献，后边那个算的是上一时刻隐藏状态的贡献,把两个加权求和的结果做合并，最后通过 `tanh` 做激活处理。

本质上来讲这两个写法没有什么区别。非要聊区别，就是下面这个写法比上面那个参数的计算要多一些，仅此而已。

### API 参数与两道概念题

`nn.RNN` 的 API 有 9 个参数。这 9 个参数分别是谁？其实准确地说不是 9 个，一共是 12 个。

那 9 个说的是输入侧：`input`（也就是 `x`），还有一个是 `h_0`。它没有算返回的。你把返回的那一堆——`output`、`h_n`，再加上全程都在的 `x`——一起加上，就变成 12 个参数了。要注意这一点，它们都在这张图里。

> **结论**：第 9 个参数的位置上放的是 `h_0`，而返回侧还有 `output` 与 `h_n`。参数数是 12 而不是 9，差别就在"入参"和"返回值"这两侧要不要一起算。

最后是这一节的两道概念题，把答案记牢。

**当 RNN 模型隐藏层为 2 时，隐藏层 `hn` 和 `output` 的结果各自有什么特点？**

隐藏层的最后一个结果，跟输出层的最后一个结果保持一致。也就是说，`output` 的输出结果和最后一个隐藏层的结果是一致的。为什么是最后一个？因为顺序是输入、隐藏层 1、隐藏层 2、隐藏层 3、输出——最后一个隐藏层和输出层是挨着的。一般来讲隐藏层直接写几个？直接一个，一般不多写，除非必要。

**RNN 写代码时，输入和输出的对应关系是什么？**

两个输入对应两个输出：输入是上一时刻的隐藏状态和本次的输入，输出是本次的隐藏状态和本次的输出。
