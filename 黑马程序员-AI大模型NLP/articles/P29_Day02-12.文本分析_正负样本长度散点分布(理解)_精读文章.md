# 正负样本长度散点分布：用 stripplot 定位异常语料

前面我们画的是柱状图和密度图，那两张图回答的是"长度整体集中在哪一段"。但语料审查真正要盯的不是主体，而是**尾巴**——一条长度接近 3500 的评论混在两万条语料里，柱状图只会把它压成几乎看不见的一根针。这一讲换个画法：用散点的形式，把验证集上正负样本的长度分布直接摊开。

先看结果图。上面有一个点明显拉得很高，一眼就能判定它是离群值；把视线收回到密集区，绝大多数数据还是落在 20 到 250 这个区间里，和上一讲的结论对得上。

---

## 1 散点分布图能看出什么

### 1.1 离群点的可见性

散点图（`stripplot`）把**每一条样本**当成一个点画出来：x 轴是标签（0 或 1），y 轴是句子长度。密集区自然形成一条横向的色带，而长度超长的样本会孤零零地飘在色带上方。这就是它的价值——离群点不再是"被压扁的一格计数"，而是一个可以被鼠标指到的点。

所以这一讲的两张图要一起看：

| 图 | 画的是什么 | 主峰/密集区 | 离群点 |
| --- | --- | --- | --- |
| 验证集正负样本长度散点图 | 每条样本一个点，x=label，y=长度 | 集中在 20~250 | 有一个点长度接近 3500 |
| 密度曲线图（上一讲的画法） | 按长度分组的条数/密度 | 同样集中在 20~250 | 尾部被压得几乎看不见 |

> **结论**：通过查看正负样本长度散点图，可以有效定位异常点出现的位置，帮助我们更精准地进行人工语料审核。

### 1.2 人工语料审核要盯住的那个点

上图出现的那个异常点，长度接近 3500。这个必须人工审查。

我当时看到它的第一反应是：我的天呐，你写小作文呢？你说住了一个酒店，这酒店咋你了？你是夸它还是骂它？——问题不在于它夸还是骂，而在于一条这么长的评论，模型很难从里面抽出稳定特征，标注本身也很可能不清楚。

具体做法很简单：把这条长度 3000 多字的评论取出来，做一个判断把它打出来，自己看一眼。

```python
# 伪代码思路：把超长评论单独捞出来人工看
long_review = train_data[train_data['sentence_len'] > 3000]
print(long_review['sentence'])
```

3000 多个字是什么概念？高考作文才给 800 个字——这一条评论顶得上好几篇作文了。

### 1.3 验证集与测试集的分布差异

再往下看，这一讲画的是**验证集**。验证集的分布明显比测试集更均匀、更离散：测试集的点更挤在一条窄带上，验证集则是一条更宽、密度更均匀的带子。

注意这里出现的三个集合名字不要混：训练集用来学参数，验证集用来调超参和做模型选择，测试集用来给最终结论。长度分析要把三个集都过一遍——这一讲专门补上验证集这一张。

## 2 绘制正负样本长度散点分布

### 2.1 代码结构与用到的函数

后边的代码怎么写，别老看我画。整体结构是这样的：

1. 先搭风格（设置绘图风格）；
2. 读取数据；
3. `list` + `map` 那一坨——给数据新增一列长度序列 `sentence_len`；
4. 用 `sns.stripplot` 画散点图。

讲义里这版先是 `sns.regplot`，后来改成了 `stripplot`。这里用的就是 `stripplot`：

```python
sns.stripplot(x='label', y='sentence_len', data=df)
```

### 2.2 每个函数都要逐一实现

需求编号是辅助 3。三步走：

```python
def dm03():
    # 1. 读取训练集和测试集
    train_data = pd.read_csv('./data/train.csv')
    test_data = pd.read_csv('./data/test.csv')

    # 2. 获取长度列：新增 sentence_len
    train_data['sentence_len'] = list(map(lambda x: len(x), train_data['sentence']))
    test_data['sentence_len'] = list(map(lambda x: len(x), test_data['sentence']))
```

第 1 步是一模一样的读取操作，第 2 步就是上面那套 `list` + `map`。注意这里的第 2、3 两个操作分别对应**训练集**和**测试集**的长度序列，两边的列名要一致，画图时才不用改参数。

### 2.3 三个参数的含义

第 4 步就是绘制（也可以叫统计）正负样本长度的散点分布。写法是 `sns.stripplot`，参数依次是：

```python
    # 3. 绘制训练集正负样本长度散点分布
    sns.stripplot(x='label', y='sentence_len', data=train_data)
    plt.title('训练集正负样本长度散点分布')
    plt.show()
```

- **参 1 `x`**：x 轴画什么。这里给 `label`，也就是好评/差评的标签，取值就是 0 和 1 两类；
- **参 2 `y`**：y 轴画什么。这里给长度。所以点的纵坐标就是句子长度；
- **参 3 `data`**：数据集，从这里边去取 `x` 和 `y` 对应的列。

> **易错点**：`train_data` 现在有几列？一开始只有两列——句子和好评差评，这是原始数据；后来新增了一列数据长度，所以现在是**三列**。`x` 和 `y` 指定的列名必须真实存在于这个 DataFrame 里，写错一个字母就是同样的报错：找不到列。

测试集照抄，只把数据来源换掉：

```python
    # 4. 绘制测试集正负样本长度散点分布
    sns.stripplot(x='label', y='sentence_len', data=test_data)
    plt.title('测试集正负样本长度散点分布')
    plt.show()
```

训练集写了，测试集就一模一样，换一下数据集就行。

### 2.4 执行结果与异常值区间

把下面的代码从测试 2 换成测试 3，右键执行"测试正负样本的散点分布"，整张效果图就出来了：还是那个离群值，位置大致就在上面那个位置。x 轴上 0 和 1 两簇点各自成一条带，纵向拉得最长的那一个就是异常样本。

顺势就能定一个处理规则：比如往上大概定个 300，300 以上我全算异常，把它们过滤掉。

```python
# 只保留不是异常点的行：把长于 300 的丢掉
filtered = train_data[train_data['sentence_len'] <= 300]
```

> **注意**：这个 300 不是拍脑袋的定值，前面密度曲线和散点图给出的主体区间是 20~250，300 是留出余量之后的保守上界。规则怎么定，得看你语料尾部到底有多厚。

## 3 用 hue 按分组着色

### 3.1 参数 hue 的含义

想让图更好看一点，或者想让"正负样本"这件事在图上直接可见，可以加 `hue`。当然你也可以按住 Ctrl 点进 `stripplot` 看它底层的源码，`data`、`x`、`y`、`hue` 这些参数都列在那儿。

```python
    sns.stripplot(x='label', y='sentence_len', data=train_data, hue='label')
    plt.title('训练集正负样本长度散点分布（按 hue 分组着色）')
    plt.show()
```

> **定义**：`hue` 是用于分组的字段，即不同组颜色不同。它类似于数据分析里的 `groupby` 那一步的分组，只不过这里分组的结果体现为颜色。

那为什么加了 `hue` 之后颜色会不一样？因为 x 轴上一个是 0、一个是 1，它们属于不同的组，颜色自然不同。

### 3.2 图例与参数增减

注意右上角出现了一个图例。如果连图例都不想要，把 `legend` 这个名字对应的参数置为 `False` 就可以了。

上面这一张我加了 `hue`，下面那一张我就不加，两边对比着看效果。要提醒一句：加了 `hue` 之后效果不一定很明显——因为 x 轴本身已经是 `label` 了，颜色分组和 x 轴分组重复了，视觉上信息量并没有增加。

> **提示**：`hue` 适合用在"x 轴和分组字段不是同一个东西"的时候，比如 x 轴给长度区间、`hue` 给正负标签，这样颜色才真的多带了一层信息。x 轴已经在按 `label` 分了，再加 `hue='label'` 只是把同一件事说了两遍。

## 4 三个集合的长度分布对照

把这一讲和上一讲的图放一起，能读出的整体信息是：

```text
训练集：主体 20~250，尾部有极少数超长样本
验证集：主体 20~250，分布比测试集更均匀、更离散，含一个长度≈3500 的离群点
测试集：主体 20~250，分布比验证集更集中，形状更清晰（数据量更小）
```

三类集合的主体区间是一致的，这说明数据集划分没有引入长度上的偏斜——这是可以直接下结论的地方。不一致才是要注意的信号，那意味着划分方式有问题，或者某个子集里混进了特殊来源的语料。

至于尾部那些点，它们不影响"主体区间在哪"这个判断，但它们决定你要不要花人力去审。长度接近 3500 的评论就这么一条，人工看一眼的成本远低于让模型去硬学一条自己都读不懂的样本。
