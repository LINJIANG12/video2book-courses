# 文本张量表示与 one-hot 编码

大模型在处理文本的时候，是没法直接处理这些词汇的：它底层就是个矩阵运算器，你给它一句人话，它不认识；你得把这些词汇转成数值形式交进去，它才能识别。这个转换出来的数值形式，就是我们后面一直要玩的词向量表示法。

这条路线上有三个方案：`one-hot`、`Word2Vec`、`Word Embedding`。先把它们分成两派记住——`one-hot` 属于稀疏表示法，有这个词就是 1，没有这个词就是 0，词一多就是堆一大堆 0 加一个 1，数据分布离散，所以叫稀疏；`Word2Vec` 和 `Word Embedding` 是稠密向量表示法。这两者之间到底差在哪、具体怎么实现，后面逐个展开。

## 1 这一阶段要拿下的三件事

先把这一阶段的目标摆出来，你就知道精力该往哪儿放。

第一件，搞清楚为什么一定要做文本张量表示。原因很朴素：大模型底层只认数值，不认识我们所谓的文本，所以必须做一次转换。

第二件，掌握 one-hot 编码的实现。这里要提醒一句，讲义上给的是一种稍微复杂点的方案，你还得额外装一个第三方包，而且这个包有点过时了——装上以后能正常用，但你的编辑器会给你报红。所以我另外带你们写一种比它更简单的方案：照讲义写，代码大概二十行；我带你写的话，十行左右就出来了。**两个版本你都要学。**

第三件，`Word2Vec`。它内部又有两种方案：`CBOW`（Continuous Bag-of-Words，连续词袋模式）和 `skip-gram`（跳字模式，也有人叫跳词模式）。这两个必须分清楚：一个是基于两边预测中间，一个是基于中间预测两端。这块开始绕、开始烧脑了，但它的底层本质就是一个矩阵相乘、一个矩阵转换的动作；换成神经元的角度讲，就是一个输入层、一个隐藏层、一个输出层，仅此而已。

在这之前还要先学一个 `Word Embedding`，我们用 `fastText` 去完成这种词嵌入的编码表示方式。

## 2 从"词向量"到"词向量矩阵"

> **定义**：文本张量表示，就是把一段文本用张量表示出来——先切词，再把每个词转成对应的词向量，用词向量的形式来描述文本。它也叫词向量表示法。

词表示成向量，叫词向量；一句话由很多词构成，那合起来就是**词向量矩阵**。为什么？我举个例子你就明白了。

假设一个词我用 5 个数字来表示，那它就是一个一维的矩阵（5 维向量）。假设我有 3 个词，每个词都用 5 个数字表示，那它是不是就变成一个 3 行 5 列的矩阵了？一句话切完词肯定有很多词，那它不就变成词向量矩阵了吗？动作就在这儿。

```text
一个词（5 个数字）:        [0.2, 0.5, 0.1, 0.7, 0.3]        → 5 维向量

三个词（各 5 个数字）:
        [0.2, 0.5, 0.1, 0.7, 0.3]
        [0.9, 0.1, 0.4, 0.2, 0.6]        → 3 行 5 列的词向量矩阵
        [0.3, 0.8, 0.2, 0.5, 0.1]
```

纵向看每一行是一个词的词向量，横向看整块就是一句话的张量表示——**词向量矩阵就是文本张量的落地形态**。它的作用说白了就是把文本表示成张量（矩阵）形式，方便输入到计算机程序中进行运算处理。

### 2.1 用考试成绩代表张三

现实生活里其实早就有这种张量表示法了。

假设张三是学生，语数外、数学、物理、化学、语文、英语这些课的成绩分别是若干个分数。请问，这些成绩能不能代表张三？能。张三考了这么多分，那我就可以用这些分来代表这个张三。

> **提示**：有人会立刻追问——万一出现重复分、相同分的情况呢？有这种概率，肯定有。那怎么办？**尽量别用整数，用小数**。五个小数全都一样的概率就少之又少了。非有人抬杠说概率挺大，那你看彩票就六个数字，全国那么多人买，每天中奖的就那么几个人，买来买去就那么几个数字。概率这东西，落到具体数字上是很小的。

编程里是一模一样的道理，只是把张三换成了词。给定四个数字，你理解为它们分别是数学、物理、化学、语文这些科目的分数；一个词用四个数字来表示，那它就是四维向量。我上面一共有四个词，最终组成的就是一个 4 行 4 列的矩阵，每一行是一个词的词向量形式。前面在 RNN 部分就讲过：**用几个数字来表示这个词，就代表它是几维的向量**。

组合到一起，这个操作就叫词向量矩阵。所以说编程来源于现实生活，又应用到生活中去——这不就是科学家从现实里得到的灵感吗？

## 3 三种常用表示法的定位

NLP 中文本词向量表示的常用方法大体三种：

| 方法 | 表示类型 | 特点 |
| --- | --- | --- |
| one-hot 编码 | 稀疏 | 有就是 1、没有就是 0，词一多就一堆 0 |
| Word2Vec | 稠密 | 内部含 CBOW 与 skip-gram 两种方案 |
| Word Embedding | 稠密 | 用 fastText 完成词嵌入表示 |

这里面有个因果关系要记牢：**正是因为 one-hot 是稀疏的，才有了后续的 Word2Vec 和 Word Embedding 这些稠密表示法**。当然，在 `Word2Vec`、`Word Embedding` 出来之前，`one-hot` 也是常用手段，所以它必须掌握——它的优点就是简单，有就是 1、没有就是 0，这是最直白的思路。

## 4 one-hot 编码的构造规则

> **定义**：`one-hot` 编码（one-hot encoding），也叫独热编码，也叫 01 编码——向量里不是 0 就是 1。它是一种稀疏的词向量表示，是将分类变量转换为数值格式的常用方法，一般用于 AI 任务中处理分类标签 $y$ 的数据。

简单记忆就是：对于一个具有 $n$ 个不同类别的分类，用 $n$ 维向量表示，其中**有一个维度是 1，其他维度全是 0**。

举个例子。一个颜色变量可能取值红、绿、蓝，这是几个值？三个值。有三个不同的类别，就表示为一个三维向量：

- 红色：`1 0 0`
- 绿色：`0 1 0`
- 蓝色：`0 0 1`

为什么红色是 `1 0 0`？因为按红绿蓝的顺序，有红色、没有绿色、没有蓝色，所以是 1、0、0。绿色按同样顺序，没有红、没有蓝，就是 `0 1 0`。

换一批词也一样：改变就是 `1 0 0 0`，要就是 `0 1 0 0`，如何就是 `0 0 1 0`。

> **易错点**：**顺序一变，向量就得跟着变。**你把这几个词的排列顺序调一下，下面每个词对应的 0/1 排列也要全部重排。这个动作一定要盯住，它是后面写代码时最容易出错的地方。

有同学说，我没看出来它有多稀疏啊。那我问你：如果现在给你的文本非常多，切完词以后假定去重后有 100 个词，你告诉我这数据会变成什么样？这就一个 1，后面 99 个 0。你说这玩意儿稀疏吗？相当稀疏。所以才有了后面的 `Word2Vec` 和 `Word Embedding`。

## 5 one-hot 编码的生成流程

先把思路讲清楚，代码稍后一行行写。生成的结果长这样：按顺序排下来，周杰伦是一个 1 后面一堆 0；如果某个词排完序恰好落在第二位，那它就是 `0 1 0 0 0 0` 这一串。

```text
词表顺序（顺序不能变）:  杰伦 / 依迅 / 力宏 / 宗盛 / 羽凡 / 鹿晗
周杰伦 →  1 0 0 0 0 0
第二位 →  0 1 0 0 0 0
```

整件事分四步走，按这个骨架看代码就不会迷路：

```text
准备语料
   ↓
构建词汇映射器（Tokenizer，词汇映射器）
   ↓
赋值为 [0] * len(vocab)：有几个词，这个列表里就有几个 0
   ↓
按词在 word_index 中的索引把对应位置改成 1
```

第三步那个 `0 乘以 len(vocab)` 的说法，含义是列表乘法：你后边是 5，中括号里就是 5 个 0；是 6 就是 6 个 0。

实际用到的包，一个是 `jieba`（结巴分词器，切词必须用它），一个是 `tensorflow`：注意重点，**这个包你得再装一下**。

```bash
pip install tensorflow
```

装完以后，从它里面去导：

```python
from tensorflow.keras.preprocessing.text import Tokenizer
```

这个 `Tokenizer` 就是我们的**词汇映射器**。后面讲迁移学习的时候，`Tokenizer` 这个单词你会经常遇见，这里先提前感受一下它到底在做什么。

> **提示**：`tensorflow` 和 `keras` 这一段，导进来以后你的编辑器会给你报一个红色的波浪线，告诉你这玩意儿不兼容。但是你能正常用，代码能跑通、结果能出来。这一段确实有一丢丢过时了——所谓过时是指 `tensorflow` 这个操作相对用得比较少了。也正是因为它别扭，我一会儿会带你去写一个更简单的版本。

除了 `jieba` 和 `tensorflow`，还需要 `joblib`。因为你是新建的沙箱环境，`joblib` 可能也需要 `pip install` 一下装上去。这个包我们在机器学习部分早就玩过了，它的用途是对象的保存与加载——一会儿把训练好的词汇映射器存下来、再加载回来用，都靠它。

## 6 使用与应用边界

模型保存下来之后，接下来的用法就是 `joblib.load` 把模型加载回来，然后拿它去获取编码。

这里有一个必须注意的边界条件：**你的模型是基于词表里那几个词生成的，所以如果你给它一个词表外的词，它是找不着的**。比如你传一个"狗蛋"进去，它就会报错。

> **结论**：one-hot 编码的模型能力范围，严格等于训练它的那个词表。词表里没有的词，无法编码，直接报错。
