# one-hot 编码的生成与词汇映射器

刚才只是简单介绍了一下 one-hot 编码大概长什么样，接下来我们自己把它实操出来。第一件事肯定是选项目、新建脚本文件，就叫 `DM03`，全名 `DM03_one_hot编码演示`。注意这个脚本里要分别演示两套东西：**复杂版**和**简单版**。跟着我的思路走，该说的还是要说清楚。

先把这一节的介绍补上——文本张量表示，或者说文本张量相关的介绍。

> **定义**：所谓文本张量，就是对文本先做一件事叫**切词**，然后把每个词转成对应的**词向量**，即用词向量的形式来描述文本。这个动作就叫文本张量，也叫词向量表示法。

为什么要这么干？原因很简单：大模型不能直接识别文本，所以你要用数字来标注你的文本，而大模型底层玩的其实就是那些数字矩阵。最早的科学家是怎么做标记的？用 1、0 这样的稀疏标记法。后来发现有弊端，才慢慢在做优化、慢慢在做改进。

作用同样是那句话：模型无法直接解析文本，那就先把它转成文本张量，这其实就是我们所谓的词向量，然后作为模型的输入来进行各种各样的处理。你把一段文本给模型，它玩不了；先转成数值，它就能接手了。

实现方式有三种，快速过一遍：第一种叫 `one-hot` 编码；另外两种叫 `Word2Vec`、`Word Embedding`。`Word2Vec` 里又分 `CBOW` 和 `skip-gram` 两种方案。

## 1 三种表示法的定位与独热编码的构造规则

`one-hot` 编码也叫独热编码，也叫 01 编码——里面不是 0 就是 1。有这个词就用 1 表示，没有这个词就用 0 表示。

| 方法 | 表示类型 | 别名与内部方案 |
| --- | --- | --- |
| one-hot 编码 | 稀疏词向量表示法 | 独热编码、01 编码 |
| Word2Vec | 稠密词向量表示法 | CBOW（连续词袋模式）、skip-gram（跳字／跳词模式） |
| Word Embedding | 稠密词向量表示法 | 词嵌入表示法 |

再往下就是那句关键的话：**列表长度等于……** 我到底应该写几个 0？我到底填几个 0？等于什么？是不是等于词的一个总数？

> **易错点**：这么说不够严谨。应该是**文本切词去重后的总长**。一定要去重，是切词、去重之后的总长。

这里我要考考你的回忆，看你记不记得——之前在讲机器学习的时候，朴素贝叶斯那块做过一个案例，叫情感分析，就是 13 条评论那个案例，那也是我们第一次玩结巴分词器。我们对那 13 条评论先切词，切完以后把那些词去重，再把里边的停用词（像"的"这一类）删掉，最后剩下来三十几个词。

**这个长度就是那么来的**：有这个词你就是 1，没有这个词你就是 0。这样我能保证你的这个词绝对不会出现两个 1 的情况——列表中只有一个 1，其他全是 0，这才叫独热编码。

`embedding` 这个单词你应该熟悉。别光说熟悉，在哪看过？前面讲 RNN 的时候，第一层叫什么层？词嵌入层。那个词嵌入层是谁？不就是这个 `embedding` 吗？搞得跟没学过似的——前面学过的内容该复习还是要复习。

## 5 TensorFlow 的 oneDNN 警告

前面提过，装完 `tensorflow` 以后有报红。此外运行的时候还会看到一段 `oneDNN` 的提示。

你问一句：有强迫症吗？有就处理，没有就不处理。这个 warning 看着难受怎么办？有个操作叫"忽略所有警告"，但你**不能这么干**——这么干可不专业。搞不定这个问题就搞定提这个问题的人？那不行。

它自己在提示里给了方案：设置 `TF_ENABLE_ONEDNN_OPTS`。而且告诉了你，这行要写在导包的**上面**。

```python
import os

os.environ['TF_ENABLE_ONEDNN_OPTS'] = '0'

import jieba
from tensorflow.keras.preprocessing.text import Tokenizer
```

> **提示**：以后你只要看到这种"设置类"的解决方案，动的都是 `os`。`os` 指的是 operating system，就是系统模块——`os.environ` 就是往环境变量里塞东西。前面讲过，这里直接用。

它生成的那句可能不对，怎么办？复制过来，把前面那截拉过来，人家已经告诉你了让你设置成 0，那就写个 0。想理解它到底什么意思，就得去查——这里我直接讲清楚：

- `tensorflow` 使用了英特尔的一个优化库，叫 `oneDNN`，它的作用就是加速器。就像你玩手游的时候手机上装的那个手游加速器，差不多是同一个意思。
- `oneDNN` 之前的原始名字叫 `MKL`，也叫 `MKL-DNN`。
- 它加速的是什么？**CPU 上的深度学习运算**。
- 这个提示就是在告诉你：某些操作使用了自定义的 `oneDNN` 实现，这样的实现可能导致**浮点型计算结果有微小差异**。

**但是不影响绝大多数任务。** 影响的是小数点后五六位那种偏差量级。

那设置成 0 意味着什么？0 是**关闭**它。关闭这个功能之后，可能略微降低 CPU 运算的性能——以前我跑大概 3.2 秒，现在可能跑 3.5 秒或 3.6 秒，会慢一点，但功能该有的都有。

设置完再跑一次，警告就没有了。既然关掉加速会改结果，那"结果"到底长什么样？接着往下看，你会发现一个更要紧的问题。

## 6 逐个词生成编码

### 6.1 循环遍历词表并初始化零向量

```python
    # 5 对每个词进行 one-hot 编码
    for vocab in vocab_s:
        # 5.1 创建长度等于语料库长度的列表, 元素全为 0
        zero_list = [0] * len(vocab_s)
```

先问一个问题：王力宏应该是谁？一个 1，后边一堆 0——那你总得先确定它的长度吧，所以要先创建长度等于语料库长度的列表，列表内元素都是 0，一会儿再换就行。

> **易错点**：这里是 `len(vocab_s)`，**别少写那个 `s`**。写成 `len(vocab)` 它照样能跑，但读出来的长度就变成了单词的字符数，结果就全错了。跑出来你会发现每个都是三个 0，为什么？因为这里边的人名都是三个字儿的——把谁换掉都一样，它跟几个字儿无关，关键是你取的长度对不对。

### 6.2 取索引并减 1

```python
        # 5.2 获取当前词汇在 word_index 中的索引
        idx = my_tokenizer.word_index[vocab] - 1
```

为什么减 1？`Tokenizer` 生成的索引**从 1 开始**，而 Python 列表的下标从 0 开始，所以要把索引整体减 1。

拿周杰伦举例：假设它的序号是 2，2 减 1 是 1，那就把列表里下标为 1 的那个位置改成 1——这就是周杰伦的编码。

### 6.3 把对应位置改成 1

```python
        # 5.3 修改对应位置的元素为 1, 完成 one-hot 编码
        zero_list[idx] = 1
```

真就这么简单：搞一堆 0，然后找找我在里边是哪个位置，找到我的位置改成 1 就完事了。别想复杂了。

### 6.4 打印结果

```python
        # 5.4 打印结果
        print(f'{vocab} 的 one-hot 编码为: {zero_list}')
```

光打这个还不够，你还得把上面那个 `word_index` 也打出来对比着看。中间来一条华丽的分割线，`-` 乘 6，六六大顺：

```python
    print('-' * 6)
```

## 7 每次运行索引都在变，所以要保存模型

跑几遍你就发现问题了：第一次王力宏是第 1 个，所以它是 `100000`；再跑一次，李薇薇变成第 2 个，变成 `010000`。你再玩一次，有可能还是那一个，也可能又变了。

```text
第 1 次运行:  王力宏 → 1 0 0 0 0 0
第 2 次运行:  李薇薇 → 0 1 0 0 0 0
第 3 次运行:  ...顺序又变了
```

> **结论**：索引由 `Tokenizer` 每次生成的顺序决定，**不保存就每次都不一样**。

最终训练完毕、每次都不一样，那你咋办？我就把你这次生成的结果存下来，以后这个代码我就不跑了——那现在的这个结果就是我最终的结果。这就是保存模型的意义。

两行代码，写在 `for` 循环**外面**：

```python
    # 6 保存词汇映射器对象
    joblib.dump(my_tokenizer, './model/onehot_tokenizer.pkl')
    print('模型保存成功')
```

两个问题要注意：

- `./model` 这个文件夹有吗？没有就右键新建一个，建出来一会儿就能往里存了。
- 文件名 `.pkl` 行不行？那叫 `.pth` 是不是也行？**都行**。甚至有的狠人连后缀名都不写。

保存之后再运行，这次就真刀真枪了，是几就是几，不会再变了。

至于后面怎么**使用**——你得把刚才保存的这个模型加载出来，加载出来以后扔个词，它就把码给你了；你要是扔一个词表里没有的词，它找不到，那就报错。很简单。
