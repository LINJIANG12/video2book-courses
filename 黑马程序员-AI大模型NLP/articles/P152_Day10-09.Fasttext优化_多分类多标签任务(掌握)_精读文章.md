# FastText 多标签多分类：ova 损失与阈值截断

先说一个在生产里天天都会遇到的情况：一条数据只有一个特征，但它身上挂着好几个标签。同一个人是男的、是湖北人、是武汉人，这三件事同时对，不是三选一。文本分类里也一样，一篇文章既是"体育"又是"国际"，既属于"科技"又属于"财经"，标签之间并不互斥。

这种题就是我们前面说过的**多标签多分类（multi-label multi-class classification）**，处理思路已经提过一次了——把它拆成多个二分类的问题。这一节就把这句话落成代码：FastText 里管这件事的参数叫 `ova`。

## 从多标签到多个二分类

`ova` 是 one vs all 的缩写，一 vs 所有，也常写成 one vs rest。它把"这句话属于哪几个标签"这个问题，拆成一串"这句话是不是这个标签"的问题。

拿刚才那个例子来说：是不是男的？是不是湖北人？是不是武汉人？每个问题都只要回答"有"或"没有"——有就是有，没有就没有，一个二分类。原本一条带多个标签的数据，就这样被拆成了多个二分类任务。

> **定义**：多标签多分类问题指一条样本可以同时属于多个类别，各类别之间不互斥；工程上通常用 OVA（One-Versus-All）把 $N$ 个标签拆成 $N$ 个独立的二分类问题，每个二分类只判断"有没有这个标签"。

拆开之后，每个二分类的输出都是一句话属于该标签的概率。这一串概率就是后面筛选标签的全部依据。

```text
                    一条样本（一个特征文本）
                              |
        +---------------------+---------------------+
        |                     |                     |
        v                     v                     v
   二分类 #1             二分类 #2             二分类 #3 ... #N
   "是标签1吗"           "是标签2吗"           "是标签3吗"
        |                     |                     |
        v                     v                     v
     p1 = 0.93            p2 = 0.12             p3 = 0.44  ...
        |                     |                     |
        +---------------------+---------------------+
                              |
                              v
              阈值闸门：只留下 p > threshold 的标签
                              |
                              v
              数量截断：从留下的标签里取概率最高的 k 个
```

读图要点：OVA 把一次多标签判定摊成 $N$ 个独立二分类，每个二分类各出一个概率；阈值负责"够不够格留下"，`k` 负责"最多留几个"，两级筛选是串联的。

## ova 训练代码与参数

新起一份代码，`fasttext.train_supervised` 那一行不动，`input` 不动，被换掉的是上面那对 `autotuneValidationFile` 和 `duration`，重新改成手动参数：

```python
model = fasttext.train_supervised(
    input='cooking.train',
    epoch=25,
    lr=0.2,
    wordNgrams=2,
    loss='ova'
)

model.predict('Which baking dish is best to bake a banana bread?', k=3, threshold=0.5)
```

逐项对上：

- `epoch=25`：训练轮数，整个训练集过 25 遍；
- `lr=0.2`：学习率；
- `wordNgrams=2`：词级 n-gram 特征取到二元，也就是把相邻两个词组成的新特征也算进来；
- `loss='ova'`：损失函数选 OVA，这一项是整段代码里唯一决定"多标签多分类"能否生效的开关。

为什么 OVA 这套拆法本质上是逻辑回归？因为它把每个标签都变成一个"是／不是"的二分类判定，而这正是逻辑回归干的事：对每个类别单独拟合一个二分类器，分别算概率。所以 `loss='ova'` 换掉的是损失层的组织方式，其余参数的含义完全没变。

> **易错点**：`loss='ova'` 是多标签多分类的关键，但**不要顺手把别的参数也当成前提**。OVA 只改判定方式，`epoch`、`lr`、`wordNgrams` 该怎么给还是怎么给；另外 OVA 下各个标签是独立二分类，输出的概率不会自动加和为 1，别拿 softmax 的直觉去看它。

## predict 的 k 与 threshold

`model.predict(text, k, threshold)` 三个参数，第 1 个是待预测的样本文本，后两个共同决定"返回哪些标签"：

| 参数 | 含义 | 作用位置 |
| --- | --- | --- |
| 第 1 个位置参数 | 待预测的样本 | 输入 |
| `k` | 期望预测的标签数量 | 阈值筛选之后的截断 |
| `threshold` | 概率阈值，只有大于该值的标签才保留 | 截断之前的筛选 |

`threshold` 是硬门槛：只要概率大于阈值，这个标签才有资格留下来，低于阈值的一律不考虑。`k` 是数量上限：从留下来的候选里取概率最高的前 $k$ 个。两者的顺序不能颠倒——**先拿阈值筛，再拿 `k` 截**，而不是先取前 `k` 个再看阈值。

`k=3` 的意思就是"我众多标签中只要 3 个，哪怕你有 9 个标签，我也只要 3 个"。但它是期望值，不是保证值：**不够就有几个留几个**。万一筛完只剩 1 个，那就返回 1 个，不会硬凑出 3 个来。

## 三次实验：阈值先筛，k 后截

把 `k=3, threshold=0.5` 那次结果拿出来看，返回的标签**只有 1 个**，概率 0.93。明明写了 `k=3`，为什么只给一个？

去打印完整标签表就明白了：这条样本一共有 3 个候选标签，但三个里面只有第一个标签的概率超过 0.5，另外两个都不到。阈值把它们挡在了门外，`k=3` 想截 3 个也没东西可截。

再看一组更彻底的对比，把阈值和 `k` 换掉：

| 设置 | 返回结果 | 说明 |
| --- | --- | --- |
| `k=3, threshold=0.5` | 1 个标签，概率 0.93 | 3 个候选里只有 1 个过 0.5 的线 |
| 放宽阈值后 | 返回 3 个标签 | 阈值一松，被挡住的候选就进来了 |
| `threshold=0.04` | 2 个标签 | 第 3 个标签概率 0.03，比 0.04 小，被筛掉 |
| `k=-1` | 一大堆标签 | 预测所有标签，不做阈值限定 |

`threshold=0.04` 这一组最能说明问题：候选里有 3 个元素，最后只剩 2 个，因为最后一个的概率是 0.03，而 0.03 小于 0.04。它差的不多，但规则就是规则——小于阈值就不要你了。

那留下的这两个还想再缩怎么办？把 `k` 改小就行。比如 `k=1`，就在这两个标签里选概率最高的那一个。

至于 `k=-1`，它的含义是**预测所有标签**，尽可能多地显示，只要沾点边就给你拉出来。跑出来你会发现它把一堆可能沾边的标签全列上了，这种结果没有参考价值。所以实际使用中一般都会加上 `threshold` 做限定，把它筛到合理的范围里，这样才可用。

> **结论**：多标签多分类的完整判定链条是"OVA 拆成多个二分类 → 每个标签算出独立概率 → 阈值筛掉不够格的 → 按 `k` 截取概率最高的若干个"；`k=-1` 表示不截断，等价于把阈值之外的一切都列给你，只适合观察，不适合当结果用。

## 参数取值的落地建议

阈值给多少合适？演示里最后把它调回 0.5——至少得一半以上的概率，才算"这句话是这件事"。

`k` 给多少则看你要的召回程度：要精确就 `k=1`，要看清候选面就 `k=3`。但记住无论 `k` 给多大，最终返回数量永远由阈值和候选数量共同决定，`k` 只是天花板。
