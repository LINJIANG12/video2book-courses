# 英译法案例：无注意力 GRU 解码器的代码实现与维度推导

上一步我们已经把无 Attention 解码器的思路捋完了，思路清楚了，接下来就是把它落到代码上。我先给结论：这个 `DecoderRNN` 里没有一行是新的——词嵌入、GRU、线性层、激活、LogSoftmax，全是我们前面反复用过的老面孔。真正要盯住的只有一件事：**每一个位置上的张量形状是多少，以及为什么必须是这个形状**。形状对了，代码就写完了；形状对不上，模型连跑都跑不起来。

---

## 类的命名与两个构造参数

类名叫 `DecoderRNN`。这里有个很容易被问到的地方：明明是 GRU，为什么名字里还是 `RNN`？因为 GRU 本身就是 RNN 的一类变体架构，构架形式是同一套——**沿着时间步递推、把信息压在隐藏状态里往下传**。所以 `DecoderRNN` 这个名字不算错，它说明的是"这是一个 RNN 家族的解码器"。

`__init__` 只收两个参数：

| 参数 | 含义 | 本案例取值 |
| --- | --- | --- |
| `output_size` | 解码器输出维度，即目标语言（法语）词汇表大小 | 4345 |
| `hidden_size` | 解码器隐藏层维度，即每个词向量的特征数 | 256 |

`hidden_size` 到底是多少，`__init__` 里根本不用猜——后面一定会传 256 进来，这一点和编码器完全一致。

剩下的层按顺序实例化：词嵌入层、GRU、输出线性层。GRU 的两个维度都写 `hidden_size`：

```python
self.gru = nn.GRU(hidden_size, hidden_size)
```

为什么输入 256、输出也 256？因为上一层（词嵌入）交出来的词向量就是 256 维，而这一层要交出去的隐藏状态同样是 256 维，**进来的和出去的维度一致，所以写两次 256**。

`self.out` 是那个负责降维/升维到词表大小的线性层，也就是结构图里标的 `out`；`self.embedding` 就是结构图里的 `embedding` 层。

---

## 各层维度与数据流

先看这张形状推导图。左侧是每一步的**输入**形状，右侧是**输出**形状：

```text
输入 (batch=1, seq_len)                  ← 一个批次一条数据，句子里若干词索引
        │
        ▼
   embedding(4345 → 256)
        │
输出 (1, seq_len, 256)                   ← seq_len 个词，每个词 256 维
        │
        ▼
   gru(256 → 256)  +  上一次隐藏状态 (1, 1, 256)
        │                    │
        ▼                    ▼
   output (1, seq_len, 256)   hidden (1, 1, 256)
        │
        ▼
   out: Linear(256 → 4345)
        │
输出 (1, seq_len, 4345)                  ← 每个位置对 4345 个法语词打分
        │
        ▼
   LogSoftmax(dim=-1) → 取概率最大的那个词 → 一个词
```

读图说明：输入是二维的词索引张量，词嵌入把它变成三维 `(batch, seq_len, hidden)`；GRU 吃这个三维张量，同时收下上一次的隐藏状态，吐出两个东西——每个时间步的输出和最后一步的隐藏状态；线性层把 256 维映射到 4345 维；Softmax 不改变形状，只把值变成概率分布，最后在这个分布里挑概率最高的一个词作为结果。

具体到数值：`seq_len=1` 时，`(1, 1)` → `(1, 1, 256)`；`seq_len=6` 时，`(1, 6)` → `(1, 6, 256)`；`seq_len=7` 时，`(1, 7)` → `(1, 7, 256)`。一句话有几个词，中间那一维就是几。为了讲解省事，后面统一用"一批一条、一条一个词"的 `(1, 1)` 举例。

### out 线性层前后的形状标注

这里有一个必须较真的地方。结构图上把 `out` 线段的输入标成 `(1, 1, 256)`、输出也标成 `(1, 1, 256)`，其实标错了一半。

`(1, 1, 256)` 是 `out` 的**输入**：它是 GRU 处理完之后原样交出来的隐藏信息，形状没变。但 `out` 处理完之后的**输出**，绝对不再是 256——256 维根本映射不出一个词，**Softmax 也不会改变形状，它只管把值变成概率**。所以 `out` 的输出应该是 `(1, 1, 4345)`。

`(1, 1, 4345)` 才是它真正的输出形状，把它写在 `out` 线段的上方才对：上面一行是 `(1, 1, 256)`（输入），下面一行是 `(1, 1, 4345)`（输出）。这 4345 个值就是这个位置上对 4345 个法语单词的打分，进 Softmax 变成概率，挑最大的那个作为预测词。

> **易错点**：全连接层按理只能吃二维输入，但这里传进去的是 `(1, 1, 256)` 三维张量，为什么没报错？PyTorch 会**自动降维**——它把 `(1, 1, 256)` 内部处理成 `(1, 256)` 做矩阵乘法，算完再还原回去。所以你写代码时看到"输入 `(1, 1, 256)`、输出 `(1, 1, 4345)`"不必惊讶，这是框架替你兜住了。

### GRU 的输入与双输出

GRU 那一步，左边是两个进项：本次输入 `(1, 1, 256)`（步内是 `(1, 256)`）和上次隐藏状态 `(1, 1, 256)`。出来也是两个：

- 本次输出（output）：`(1, 1, 256)`；
- 本次隐藏状态（hidden）：`(1, 1, 256)`。

`(1, 1, 256)` 和 `(1, 256)` 在这里其实是同一个东西的两种看法，别被这个区别绕晕。

---

## LogSoftmax 与损失函数的配对

走到线性层下面，会看到一个 `LogSoftmax`。第一反应通常是：为什么不直接 Softmax？

因为多分类交叉熵损失函数本身是拆开的两步：

$$\text{CrossEntropyLoss} = \text{LogSoftmax} + \text{NLLLoss}$$

**如果你的损失直接用 `CrossEntropyLoss`，网络里就根本不需要写这一层**——它内部已经把 log 对数算进去了。

> **结论**：网络里写了 `LogSoftmax`，后面的损失函数就只能用 `NLLLoss`；如果网络里不写、直接输出 logits，后面才用 `CrossEntropyLoss`。两者绝不能同时出现：LogSoftmax 已经求过一次对数，再用 CrossEntropyLoss 会让它**在内部再求一次对数**，结果就不准了。

本案例用的是 `LogSoftmax`，所以后面接 `NLLLoss`。

## 解码器代码的逐步实现

### `__init__` 与父类初始化

第一步照旧初始化父类信息：

```python
super().__init__()
```

第二步保存输入参数：

```python
self.output_size = output_size
self.hidden_size = hidden_size
```

### 词嵌入层

```python
self.embedding = nn.Embedding(output_size, hidden_size)
```

两个参数分别对应：第一个 `output_size`（4345）是词表大小，第二个 `hidden_size`（256）是每个词要转成的向量维度。

这里要重新过一遍输入的 `(1, 1)` 是什么意思：中间这个维度一直是 `batch_size, seq_len`。第一个 1 表示**一批一个句子**；第二个 1 表示**这个句子有一个单词**。写成 `(1, 6)` 就是"一批一个句子，句子六个单词"。所以：

- 给 `(1, 1)`，`embedding` 还给 `(1, 1, 256)`；
- 给 `(1, 6)`，还给 `(1, 6, 256)`。

数据在解码器里长什么样呢？因为翻译是一步吐一个词，解码器每次的输入就是一个词，所以典型形状就是 `(1, 1)` → `(1, 1, 256)`。

### GRU 层与 `batch_first`

```python
self.gru = nn.GRU(hidden_size, hidden_size, batch_first=True)
```

`batch_first=True` 是把批次维度提到最前面的开关。默认情况下（`batch_first=False`），张量排布是"先序列长度、再批次大小、再词向量维度"；打开这个开关之后，批次放到最前面，变成"**批次大小 → 序列长度 → 词向量维度**"。

> **提示**：`(3, 5)` 在 `batch_first=True` 下的含义是"一批三个句子，每个句子长度 5"。这个开关开不开都行，但一旦开了，后面所有打印出来的形状都要按这个顺序读，不然很容易把 `batch` 和 `seq_len` 认反。

### 线性层

```python
self.out = nn.Linear(hidden_size, output_size)
```

输入维度就是上面 GRU 的输出维度 `hidden_size`（256），输出维度就是 `output_size`（4345，从 `__init__` 的第一个参数来的）。这一层干的事，就是把 256 维的词向量映射成 4345 个法语词的打分。

### LogSoftmax 层

```python
self.softmax = nn.LogSoftmax(dim=-1)
```

`dim=-1` 表示在**最后一维**（也就是 4345 那一维）上做归一化，把打分变成对数概率分布。

### 前向传播

```python
def forward(self, input, hidden):
    # 1. 词向量处理
    output = self.embedding(input)

    # 2. ReLU 激活
    output = F.relu(output)

    # 3. GRU 层处理
    output, hidden = self.gru(output, hidden)

    # 4. 线性层与 LogSoftmax 处理
    output = self.softmax(self.out(output))

    # 5. 返回结果
    return output, hidden
```

逐段看。

**词向量处理**：`output = self.embedding(input)`，输入 `(1, 1)`，得到 `(1, 1, 256)`。

**ReLU 激活**：词嵌入后面接一个 ReLU，这一步只是把值过滤一遍，形状不变。

**GRU 处理**：`output, hidden = self.gru(output, hidden)`——这一行和写编码器时一模一样。GRU 输出仍然是三维的 `(1, seq_len, 256)`，隐藏状态还是 `(1, 1, 256)`。

**线性层与 Softmax**：注意这里的写法是 `self.softmax(self.out(output))`，**Softmax 在外面，线性层在里面先跑**。`self.out` 收下 GRU 交出来的三维张量，输出的仍是一个三维张量：

```text
output (1, seq_len, 256)  ─ Linear(256 → 4345) ─►  (1, seq_len, 4345)
```

读图说明：线性层只替换最后一维——把 256 换成 4345，前面两维原样不动。所以 `seq_len=1` 时输入是 `(1, 1, 256)`、出来是 `(1, 1, 4345)`。接着 `LogSoftmax(dim=-1)` 在 4345 这一维上做归一化，把这 4345 个打分变成对数概率，形状不变。

**返回**：`return output, hidden`，把输出和隐藏状态一起交出去。

### 初始化隐藏状态

还差一个初始化隐藏状态的函数：

```python
def initHidden(self, device):
    return torch.zeros(1, 1, self.hidden_size, device=device)
```

`(1, 1, self.hidden_size)` 即 `(1, 1, 256)`，对应"一批一个句子 + 一层 GRU + 256 维隐藏状态"。

> **提示**：写到这儿你可以回头看一眼编码器的代码——把编码器复制下来稍作改动，就是解码器。这两套结构本来就是同一族。真正把它们区分开的，只在于编码器**不接输出层**、只把结果整体往后传；解码器要一层层把结果映射成词。

---

## 解码器写完之后的三步

到这儿模型部分已经攒齐两块：编码器（已经测过）与这个无注意力的 GRU 解码器。

接下来三步是顺着走的。先把刚写好的解码器跑一遍，确认它的形状和输出都对；再把同一个解码器**加上注意力机制**重写一遍；最后对带注意力的版本再做一次测试。

> **结论**：编码器不接输出层、只把 GRU 的结果原样往后交给解码器；解码器在 GRU 之上补一个 `Linear(256 → 4345)` 加 `LogSoftmax`，把隐藏信息变成词表上的概率分布。这就是无注意力编码器—解码器的全部分工。
