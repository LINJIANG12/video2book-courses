## 测试变量与维度常量准备

先别急着实例化对象，第一步是**把要用的量先记下来**。这些量我们前面见过，但这次要用变量名写，不再写裸数字。

```python
input_size = n_letters      # 词向量（one-hot）维度 = 57
n_hidden = 128              # 隐藏状态维度
output_size = category_number  # 输出维度 = 18，国家数量
```

我写成这样，你能不能看懂？我告诉你，这个操作叫**效果同上**：把 `input_size, n_hidden, output_size = 57, 128, 18` 换成这三个变量，计算出来的东西完全一样。

为什么敢这么换？按住 `Ctrl` 不要松手，点上去，`n_letters` 跳过去就是那个 `length`，是不是 57？下面跟它对应的还有一个 `category_number`，是不是就是国家数量 18？

既然能用变量替代，那我写数字还是写变量，你们选哪个？写变量。写变量的好处是**你以后再看到 57 和 18，不用去猜它们是什么**。那三个裸数字就注释掉，留着当对照也行。

`n_hidden = 128`、`output_size = 18` 这两句也别丢了——它们马上就要喂给模型。

## 数据：从 read_data 到 DataLoader

变量有了，第二个操作是加载数据。

为什么要加载数据？回头看看你刚才写的那三个变量——你这个数据是咋来的？`6 57` 是个什么东西？那个"欧阳"是不是你自己随便诌咧搞出来的一个假样本？所以第一步那个是**假的**，验证阶段不能拿它当真数据用。真数据在文件里，得读进来。

那怎么读？有人上来就 `with open`。你要 `with open`，我就把你 open 出去了——你上面写的那个 `read` 是干啥吃的？你写的是不是 `read_data`？它是不是读数据的？

`read_data` 拿的是谁？别往里点开看，还记得吗，它拿的是 `my_list_x` 和 `my_list_y`。这个函数能给你**原始的 x 和 y**，但它给不了你**加载器**。

> **定义**：`read_data` 负责把文本读成两个列表，`Dataset` 负责把列表包成"能被索引的一条一条样本"，`DataLoader` 负责按批次把样本喂给模型。**三件事三种角色，一级一级封装上去**，谁也别越界干活。

所以数据加载这一段是三小步：

```python
# 1.1 读取数据
my_list_x, my_list_y = read_data('name_classification.txt')

# 1.2 构建数据集对象
name_class_dataset = NameClassDataset(my_list_x, my_list_y)

# 1.3 构建数据加载器
my_dataloader = DataLoader(name_class_dataset, batch_size=1, shuffle=True)
```

这里我把一个容易搞错的地方纠正一下：数据集对象的名字是你自己起的。你别照着别人念的 `my_dataset` 写，你刚才亲手写的那一个叫 `name_class_dataset`——人名分类嘛，`name_class`，就用它。

### 为什么 batch_size 只能写 1

到加载器这一步，括号里传三个参数：第一个是数据集对象，第二个是批次大小，第三个是是否打乱。

数据集对象有了，你把它扔进去就行。但扔进去有个问题：**数据加载器是按批次取数据的，你一次拿几批总得告诉我吧**，所以第二个参数必须给。

那 `batch_size` 写几？它有默认值，但默认值不一定是你要的那个。我都放着让你看，你自己选。有人随口说"随便"——**这个批次只能写 1**。

原因就一条：**一个名字和下一个名字，长度不一定一样**。上面这条是 `4 57`，下面那条就是 `6 57`，再下一条是 `9 57`。你没法在一个批次里塞 6 个或 9 个长短不齐的样本，所以先写 1。

第三个参数 `shuffle=True`。它是什么意思？**是不是在这儿打乱顺序抓的**——所以下一次跑，你拿到的第一条数据跟这次不一样，但格式一定一样。

> **提示**：`batch_size=1` 会直接决定后面训练时的整个节奏——两万多条人名就是两万多批，一批一条。这个数字不是随手写的，是被"名字长度可变"这个事实逼出来的。

## 三个模型的实例化

数据准备好，就该创建对象了。第五个操作是模型初始化，三个模型都在这儿建。

```python
my_rnn = my_rnn(input_size, n_hidden, output_size)
my_lstm = my_lstm(input_size, n_hidden, output_size)
my_gru = my_gru(input_size, n_hidden, output_size)
```

这里有个考人的地方：这个位置到底传什么？有人念"57 128 18"——但你注意，上面我们已经用变量接了，所以**这块应该传 `input_size`、`n_hidden`、`output_size` 这三个变量**，别再回头写裸数字。

还有一个更要紧的判断：`my_lstm` 的参数跟 `my_rnn` 一样吗？

**一样。** 这三个模型是同一套入参：输入维度、隐层维度、输出维度。为什么？看它们内部就知道了——三者内部都是"`nn.RNN/nn.LSTM/nn.GRU` 把输入维度映射到隐层维度，再一层 `Linear` 把隐层维度映射到输出维度"。既然两头一样，中间换谁都不影响这个接口。

> **结论**：`my_rnn`、`my_lstm`、`my_gru` 三个类的构造函数签名完全一致，实例化时传的是同一组变量，只有类名不同。

## 模型结构可视化

模型建完，第六个操作是打印一下结构：

```python
print(f'rnn 模型结构:\n{my_rnn}')
print(f'lstm 模型结构:\n{my_lstm}')
print(f'gru 模型结构:\n{my_gru}')
```

> **提示**：`print(f'...')` 里的 `f` 是 Python 的 f-string 前缀，写成 `print F` 是口头的说法，代码里必须是 `print(f'...')`，那个 `f` 是引号**前面**的字母。

打印出来看什么？看三件事：

1. 每一层的名字与输出形状——`57 -> 128` 是循环层，`128 -> 18` 是那层 `Linear`；
2. LSTM 的参数量明显比 RNN 多，因为每一组权重它都要算四个门；
3. 最后那个 `LogSoftmax`，三个模型打印出来是一样的。

往下看打印结果，数据条数都是 20074 条。再看形状：`57 128 128 18`。

这四个数字怎么读？57 是输入那个维度，128 是隐层维度，**接下来我要通过全连接把 128 改成 18**——这个动作就是在 `Linear` 这一层里做的。再往后就是 `LogSoftmax`。

你有没有发现，这三个模型的形状其实是**一模一样**的？

## 测试 RNN 模型

第七个操作是测试上面三个模型，我们从 7.1 开始测 RNN。

```python
for i, (x, y) in enumerate(my_dataloader):
    ...
```

为什么可以 `for` 它？因为它是个加载器，一批一批往外拿。现在 `batch_size=1`，所以**一次拿一条**。这次拿的是哪一条？我也不知道——`shuffle=True` 打乱过了，咱就随机抓一条，比如抓到一个中文名。

```text
my_dataloader  ──►  一条样本 (x, y)
                      x: 张量，形状 (1, L, 57)
                      y: 张量，形状 (1)
```

读图说明：加载器每次只吐出一条样本，`x` 和 `y` 已经是**张量形式**——`x` 是这条人名的字符序列 one-hot，`y` 是它所属国家的编号，后面这两样才算能直接喂给模型。

注意：不是把名字本身直接传进去，而是**已经经过 `Dataset` 处理的张量**。这一点很关键，`Dataset` 里做的编码就是在这一步生效的。

### 打印一条样本

```python
print(f'第{i}条数据, x:{x.shape}, y:{y.shape}')
```

`i` 是编号，也就是第 i 条数据。`x.shape` 是它的形状。

举例：`x` 的形状可能是 `1 4 57`。这三个数字分别是什么？1 是**一批次**，4 说明这条名字有 4 个字符，57 是把每个字符转成 57 维的 one-hot 编码——**整条名字的字符首尾都转完了，所以整体是 (4, 57)**。

`y` 的形状是 `1`，内容是国家编号，比如 `6`。举例来说：如果某个国家在 18 个国家里排第 7，它的编号就是 6，因为**索引从 0 开始**。所以看到 `y` 打印出 `15`，它的意思是"第 16 个国家"。

最后加一个 `break`。`break` 是什么意思？**出来就只玩一次**，以免打印得过多、又看不出什么名堂。

### 实测的形状与 shuffle 的影响

跑一下，屏幕上给的是：

```text
第0条数据, x:(1, 10, 57), y:(1,)
```

`x` 是 10 个 57——说明这条名字有 10 个字符。你去数数那个名字就知道，它肯定是个外国人名，因为咱中国名字没这么长，欧阳才 6 个字符，轩辕也才 8 个。

`y` 是 `1` 的形状、`15` 的内容。这两个数字别混：**形状是 1，编号是 15**。

那再运行一次，结果还一样吗？谁说一样？别忘了，你这儿 `shuffle=True`。这一跑就变成 `1 9 57`、`y` 还是 15——**跟第 15 个国家杠上了**。再换一个，变成 `1 4 57`、`y` 是 2，这回国家换了。

> **结论**：`shuffle=True` 让每次取到的样本不同，但**形状的格式永远固定**——`(1, L, 57)` 和 `(1,)`。这就是我们可以把三个模型塞进同一套循环的前提。

### 前向传播：为什么要传 x[0]

信息都知道了，接下来初始化隐状态，再做前向传播。

```python
hidden = my_rnn.init_hidden()
output, hidden = my_rnn(x[0], hidden)
```

这里有个必须想清楚的细节：`x` 的形状是 `(1, 10, 57)`，你**不能直接把 `x` 传进去**，因为模型内部只接收二维的 `(10, 57)`——还记得吗，模型里已经替你在最前面加了一维批次。

所以要把外面那一层 1 去掉：

```python
x[0]   # 取第一个元素，形状变成 (L, 57)
```

`x[0]` 的意思就是"只要你的第一个元素"，拿到的是 `(10, 57)`。这就等价于之前举例用的 `(4, 57)`，只不过这次长度是 10。

> **易错点**：模型内部做了升维，所以**外面传进去的必须是二维的**。你传三维进去它会直接报错。

然后是输出：

```python
print(f'rnn 输出形状: {output.shape}, 预测结果: {output}')
```

跑起来看结果，`output` 的形状是 `(1, 18)`——18 个国家，每个国家一个对数值。这个 `(1, 18)` 就是**预测结果**。

如果不想让循环打印太多，就在外面套个判断：

```python
if i == 0:
    break
```

只留一条看，够了。

## 输出到国家名的后处理步骤

拿到 `(1, 18)` 之后，接下来要做什么？

**做个 softmax，再做个 argmax**，我就知道它具体是哪个国家了。

为什么？你的 `rnn` 是什么层？**循环网络层**。循环网络层后面还有个输出层，输出层里做两件事：第一件是加权求和，第二件是激活函数。所以到这一步，你的结果里**还少一个 softmax，还少一个 argmax**。

那要不要顺手给加上？不加。

这是测试代码，**它是用来测你的 RNN 能不能跑通**。它能跑到这儿，其实已经跑通了。后面我们是要做模型训练的，在训练的动作上一定会把它加上。测试的目的不是拿到最终预测，而是确认链路是通的。

> **提示**：测试阶段的产出是"能跑到哪一步"，不是"预测对了没有"。把责任分清楚，你才知道出问题时该查哪儿。

## 测试 LSTM 模型

RNN 测完了，接下来该测谁？LSTM。回答我一个问题：改哪些地方？

### 行号定位与三处改动

先看几个位置：

- **385 行附近**：隐状态初始化。这里要变成 `hidden, c = my_lstm.init_hidden()`——**LSTM 返回的是 hidden 和 c 两个值**。
- **388 行附近**：前向传播。这里要把模型换掉，并且在后面加上 `c`。
- 再往后，`print` 里那句也得改，写上 `lstm`。

改的时候别漏了模型对象本身：你上面写的还是 `my_rnn`，那底下这一坨肯定要改成 `my_lstm`，**因为你换的是模型**。

### 为什么不加小括号

这里有个很多人纠结的点：`hidden, c` 要不要写成 `hidden, (hidden, c)` 那种带括号的形式？

**不能加小括号。**

为什么？按住 `Ctrl` 点进 `my_lstm` 的定义看看，它要几个参数？除了 `self` 之外，是要**四个**：`x`、`hidden`、`c`，还有一个 `c` 之后那个参数——但**最后一个参数有默认值**，所以你可以不传，于是**实际传三个参**。

听明白这个区别：**这是我们自己写的 LSTM，不是人家原生的 `nn.LSTM`**。要是用原生的 `nn.LSTM`，那你得按它的要求把状态塞成一个元组；但我们自己写的 `forward(x, hidden, c)` 是三个独立形参，所以直接 `hidden, c` 分开传。

```python
# 7.2 测试 lstm
for i, (x, y) in enumerate(my_dataloader):
    hidden, c = my_lstm.init_hidden()
    output, (hidden, c) = my_lstm(x[0], hidden, c)
    print(f'lstm 输出形状: {output.shape}, 预测结果: {output}')
    if i == 0:
        break
```

### 写完别忘缩进

第一次跑 LSTM 的时候，我犯了个错——不是模型错了，是**这段 `for` 被写到上面那个 `for` 里面去了**。

写在里面会怎样？它会一直给你报错吗？不会。因为外层循环里有个 `break`，外面那一轮早就结束了，**你里面这个 `for` 压根就没执行**。

```text
# 写错的样子
for i, (x, y) in enumerate(my_dataloader):    # 7.1 测试 rnn
    ...
    if i == 0:
        break
    for i, (x, y) in enumerate(my_dataloader):  # 7.2 被塞进了 7.1 里面
        ...                                     # break 之后永远走不到这里
```

所以：**7.2 的 `for` 要跟 7.1 的 `for` 平齐**，是一个并列关系，不是嵌套关系。

纠正后跑一下，LSTM 的输出形状也是 `(1, 18)`——针对的是那条长度为 8 的数据，`(1, 8, 57)` 进去，`(1, 18)` 出来。

## 测试 GRU 模型

7.2 做完，接着写 7.3，直接复制 RNN 那一段，只改两处：

```python
# 7.3 测试 gru
for i, (x, y) in enumerate(my_dataloader):
    hidden = my_gru.init_hidden()
    output, hidden = my_gru(x[0], hidden)
    print(f'gru 输出形状: {output.shape}, 预测结果: {output}')

```

第一处是把 `my_rnn` 改成 `my_gru`；第二处是 `print` 里的文字，别一边改模型一边还在打印"rnn 输出形状"。

顺手把前面打印编号那一坨注释掉——留着它其实没什么用，只留第一组就够了。

写完你会发现一件事：未来你更喜欢写哪种模型？**是不是喜欢写 GRU**。因为 RNN 写完，GRU 一改就行了；而 LSTM 还得加个细胞状态。

### 三个模型的结果对照

跑完把三个结果并排看：

| 模型 | 输入 | 输出形状 | 观测到的结果 |
| --- | --- | --- | --- |
| RNN | `(1, L, 57)`（L 随样本变化） | `(1, 18)` | 每个国家一个对数值 |
| LSTM | `(1, 8, 57)` | `(1, 18)` | 同上 |
| GRU | `(1, L, 57)` | `(1, 18)` | 同上 |

三条都是同一条数据（`4 57` 或 `8 57`，看这次打乱抓到哪条），输出形状完全一致。

那我只要做一件事：针对这个结果，通过一个 `softmax` 处理一下，再 `argmax`，是不是就知道这个名字在这三个模型里分别被预测成哪个国家了？

> **结论**：三个模型的输出**结构完全同构**，只是数值不同。这正是"一套测试骨架能测三个模型"的根本原因——不是我们为了省事硬套，而是它们的接口本来就一样。
