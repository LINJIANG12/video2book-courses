# 从 LSTM 改出 GRU 训练：两处改动、耗时实测与三张图预告

轮到第三个模型了。这次我先干一件事：把上面那份 LSTM 的训练代码整段**注释掉**，再把内容贴到下面来。

为什么不直接删？因为一会儿要对照着看。这次的改法跟上一集完全是同一个套路——复制、粘贴、改，只是改的量更少。

我先交个底：**改两处就够了**。就两处。你要是听完觉得"就这么点"，那说明前面那套你确实吃进去了。

## 1. 两处改动的位置

第一处，模型对象的类名：

```python
my_gru = MyGRU()          # 原来是 my_lstm = MyLSTM()
```

第二处，在 forward 里——把那个多出来的 `c` 去掉，整行就退回到和 RNN 一样的形式：

```python
output, hidden = my_gru(x, hidden)       # 原来是 output, hidden = my_gru(x, (hidden, c))
```

为什么 `c` 可以干脆不要？因为 GRU 内部只返回一个隐藏状态，没有细胞状态这个概念。你可以按住 `Ctrl` 点进 `MyGRU` 的定义里去看，它的返回值就是一个——它把那一个记忆状态直接合进了隐藏状态里。所以 `c` 在这里既没有来源，也没有去处，删掉即可。

那个 `c` 是从哪冒出来的？是上一集给 LSTM 加上的。它在 LSTM 的上下文里必须存在，搬到这里就必须消失。

再顺一句：`init_hidden` 那一边也跟着回去。LSTM 需要你同时接收 `hidden, c` 两个值，GRU 只返回一个，就按它只返回一个来接收，把 `c` 去掉即可——传参和接收两头的形状必须一致，这是唯一要守住的规矩。

> **易错点**：变量名我超级建议你们不要改。把 `my_lstm` 改成 `my_gru` 是必须的，因为它指的是**类的实例**；但那种纯粹为了"看起来对"而把变量名一律重命名的做法，会让你后面所有引用都得跟着改，一改就乱。像 `my_rnn` 那样的名字就留着，先让代码跑通。

改完这两处，找一找还有没有别的要动的地方。往下拉到底——`optimizer`、损失、反向传播、统计、打印，全都不用动。这就是两处改动的全部。

## 2. 第一次复制的写法

顺带说清楚我为什么要"注释掉旧的、再贴一份新的"，而不是在原来那份上直接改：这样两三个模型能并排放在一个文件里互相对照，改错了也能一眼看出是改哪一行出的问题。当然文件会变长，PR 上看着不优雅，但这是**学习阶段的正确做法**——你要的是把三套结构的差异看在眼里，而不是让文件好看。

## 3. 训练与耗时实测

改完名字，继续复制一份训练入口：

```python
train_gru()               # 原来是 train_lstm()
```

然后跑。轮数还是一轮，输出仍是每 2000 个样本打一次，一路走到 6000。

这次跑出来是 **82 秒**。

| 模型 | 实测单轮耗时 |
| --- | --- |
| RNN | 51 秒 |
| LSTM | 52 秒 |
| GRU | 82 秒 |

看到这个数你可能觉得不太对——GRU 是三者里结构最简单的门控模型，凭什么比 LSTM 还慢？

> **结论**：这个 82 秒不用当真。它跟你电脑当下运行的环境和资源直接相关，只值一个参考。我自己之前跑的时候大概是：RNN 51 秒、第三个模型 60 多秒、这一个 55 秒左右。同一段代码换个时刻跑，数就变了。

## 4. 想测准该怎么测

让这个数字有参考性，办法只有一个：**别跑一轮**。把训练轮数改成 100 轮、200 轮，或者干脆 1000 轮，然后拿总耗时去算平均——跑得越多，平均值越稳。

一次不能做英雄。你总得多跑几次，看你最终的结果就行了。这一点跟上一集测 LSTM 时说的是同一件事：单轮数字只说明"这次机器忙不忙"，多轮平均才说明"这个模型重不重"。

## 5. 损失曲线的走向

看训练日志之前，先用一个更直观的指标判断模型有没有在学：**损失有没有一直在往下走**。

这次看到的趋势是**一路垂直下降**：1.4 → 1.3 → 1.2 → 1.3。中间那一下回升很正常，整体趋势确实在降。降得是慢了点，但方向是对的，损失越小说明拟合得越准。

## 6. 训练部分到此结束

GRU 的训练做完，三个模型的训练就全齐了：

- `train_rnn`
- `train_lstm`
- `train_gru`

从写第一份训练代码到现在，感受应该很明显：**第一个训练代码写了接近 40 分钟，后边这两个加起来可能不到 4 分钟**。原因就是思路完全一样——数据怎么进、状态怎么传、损失怎么算、参数怎么更新，这套骨架是共用的，换的只是模型本身。

> **结论**：编程只有第一次做是难的。第一遍做完，后面再写都更简单。

有个小提示跟这个感受有关：RNN 那份训练代码在文件里出现了三次左右。如果你想让三个模型的训练条件完全一致，可以只留动作 2 和动作 3，把多余的那份右键删掉；不删也行，先留着不影响结果。

## 7. 把三个模型从头再跑一遍

训练代码写完了，接下来要出三张图。但在动手画图之前，有件事得先做：

**把所有模型全部清掉，一个都不留，让它们三个从头再来一遍。**

因为只有在同一轮、同一台机器、同一批资源下跑出来的三组数据，放在一张图上对比才有意义。前面那些跑过一半、中断过的状态不能混进来。

```text
清空全部模型状态 ──▶ 重新训练 RNN ──▶ 重新训练 LSTM ──▶ 重新训练 GRU
      │                                                      │
      └──────────────── 三组指标同一条件产出 ─────────────────┘
                              │
                              ▼
                 损失列表 / 总耗时 / 准确率 三组数据到手
```

这一遍预计三分钟左右，比单跑一个模型长，但它是画图前必须付的时间成本。跑完之后，三个模型各自的损失列表、训练总耗时、准确率就都是"同一把尺子量出来的"了。

## 8. 三张图分别画什么

在跑的同时把要画的东西说清楚，一共三张：

1. **损失下降情况对比图**。看三条损失曲线谁降得最快，也就是谁收敛得最快。
2. **准确率对比图**。看三个模型最终谁分类分得准。
3. **用时对比图**。看三个模型各自花多长时间，用图表的方式横向比。

按原理推，这三张图的形状应该是：**RNN 最低、LSTM 最高、GRU 夹在中间**。这个预期是有来源的——LSTM 内部结构最复杂（四组运算），GRU 简化到三组，RNN 只有一组。

三张图一出来，"这仨模型到底该用哪个"这个问题就不用嘴上争了，图会给答案。
