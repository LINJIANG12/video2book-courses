# 注意力机制的计算流程与 PyTorch 实现

聊完了 `bmm` 函数，接下来我们做一个案例：通过一个 Seq2Seq 去完成翻译任务。翻译是什么、单词是什么、查询张量怎么怎么样，这一堆我就不再重复了。写代码之前先把课件里的任务描述贴过来，然后我带你从头写一遍。

## 1 任务描述与计算链条

任务描述是这样的：已知 Q、K、V，V 是内容——32 个单词，每个单词 64 个特征；K 是对应这 32 个单词的索引；Q 是查询张量。我们的任务是输入查询张量 Q，通过注意力机制计算出 Q 的注意力权重分布，得到 Q 和这 32 个单词的相似度，最终把 Q 的结果表示出来：由一个普通的 Q 升级为一个更强大的 Q。

> **易错点**：一会儿到底拿 Q 和谁算相似度？有人张口就答 Q 和 V——你扯淡呢。是 **Q 和 K 算相似度**，算完相似度再乘以 V。那乘以 V 的时候用什么函数？`bmm`，就是刚刚讲过的那一个。

第三个注意事项：查询张量 Q 查询的目标是谁，谁就是查询张量。例如 Q 是来查询单字「我」的，那么 `self.Q` 就是我的查询张量。

```text
        查询张量 Q (1,1,32)
              |
              |  与每个 K 比对 -> 相似度得分
              v
   K (1,32,32) -------> attn_weights (1,32)   注意力权重分布
                              |
                              |  归一化后作为权重
                              v
   V (1,32,64) -------> attn_applied (1,1,64)  加权后的内容
                              |
              Q 与加权内容拼接 (1,1,96)
                              |
                              v
                  线性层降维 -> output (1,1,32)  增强后的 Q
```

这张图就是整个前向传播的走向：Q 先跟 K 算相关性、转成概率，再拿概率去乘 V，最后把原始 Q 和加权后的 V 拼起来降维，输出那个「增强过的 Q」。

## 2 三种注意力规则与炒土豆丝

在动手写类之前，回顾一下刚才说的三种注意力计算方式。

- 第一种：`linear` 里边是 Q、K，两者做线性计算后比分，外边套 `Softmax`，再乘以 V；
- 第二种：`Softmax` 里边包着 `linear`，`linear` 外边包 `tanh`，再外边包一个 `sum`；
- 第三种：上边先做点乘（点积），下边再除以缩放系数。

不管用哪一种规则，核心都一样：**算 Q 和 K 的相关性，把相关性转成概率，再用概率乘以 V，挑出重点信息**。区别只有两处：算相关性的方式不同（拼接可以算，点积也可以算），中间处理不同（有的加线性变换，有的加 `tanh` 激活）。

> **结论**：所有注意力规则都是「先算相关、转概率、概率乘 V」，差别只落在算相关性的方式和中间处理上，其余部分完全相同。

这个道理打个大白话的比方——炒土豆丝。有些人先放醋，有些人后放醋，但目的都是做出好吃的土豆丝。顺便吐槽一下，那位师傅切土豆丝的刀工还有待改进，切得有点厚，真该切细一点，炒出来才好吃。当然这就不纠结了，就跟有人吃香菜有人不吃一样，无所谓的。

## 3 自定义注意力模块的结构设计

本质上来讲，这就是一个神经网络，我们给它起名 `MyAttn`，然后按搭网络的思路分析。

第一步是初始化参数。以前 `forward` 里边只传一个 `x` 就行了，现在用的是 Q、K、V，所以这个位置不能只传一个，你要传 Q，还要传 K，还要传 V。

那 `__init__` 前面要写什么参数？`query_size`、`key_size`、`value_size1`、`value_size2`、`output_size`。后两个什么意思，一会儿解释。

```text
MyAttn
 ├── __init__：五个尺寸参数 + 两个线性层
 │     ├── self.attn          : Linear(query_size + key_size, value_size1)
 │     └── self.attn_combine  : Linear(query_size + value_size2, output_size)
 └── forward(Q, K, V)：算权重 + 算输出
```

这张图就是模块的骨架：初始化里放五个尺寸和两个线性层，前向传播里算权重和输出，别的都在细节里。

## 4 五个尺寸参数的含义

先看这几个参数到底量的是什么。你现在拿 Tom 这个词去查，Tom 在底层肯定不是两个汉字，它得用词向量的形式表示，所以「用几个数字表示一个词」就是**查询张量的维度（query_size）**。

- `query_size`：查询张量的维度，也就是 Q 用多少个数字表示；
- `key_size`：键张量的维度。Q 要拿着去和每一个 K 做运算，所以 K 也得有维度；
- `value_size1`：值张量的序列长度，即编码器里一共有多少个单词；
- `value_size2`：值张量的维度，也就是词向量的维度。

举个例子，我这里一共 3 个单词，每个单词用 64 个数字表示，那么 `value_size1 = 3`、`value_size2 = 64`，V 的形状就是 `3 × 64`。前面那个是**多少个单词**，后面那个是**每个单词用多少个数表示**。

`output_size` 不用我说你也应该会了，它是输出张量的维度。

具体到本讲的代码里：查询张量一共 32 个单词，每个单词 64 个特征，所以 `query_size = 32`、`key_size = 32`、`value_size1 = 32`、`value_size2 = 64`、`output_size = 32`。

> **易错点**：有人看到 64 个特征就想把 `query_size` 写成 64——一共有多少个单词啊？32 个，你哪鼓捣出 64 的。`query_size` 是查询张量的维度，它要跟那 32 个词逐一比对，所以这里是 32。

## 5 两个线性层与维度计算

第三步是注意力计算层：**将 Q 和 K 拼接后映射到与值序列相同的维度**。输入是 Q 的 32 加 K 的 32，等于 64 维，输出维度是 32。也就是说，我现在用 64 个数字来表示你，但最后还是会把你输出成 32 再往后做。

```python
self.attn = nn.Linear(self.query_size + self.key_size, self.value_size1)
```

这里输出维度用的是 `value_size1`——因为算出来的注意力权重，最后是要和 32 个单词一一对应相乘的。

第四步是注意力融合层：**将原始的 Q 和注意力加权后的 V 拼接，融合后映射到输出维度**。

```python
self.attn_combine = nn.Linear(self.query_size + self.value_size2, self.output_size)
```

Q 是 32，加权后的 V 是 64，加起来 96，但最后的输出维度还是 32。这个 `attn_combine` 其实就是权重 $W$。

## 6 前向传播与逐层维度变化

接下来写 `forward`，传进来三个参数：Q、K、V。我把整段写完再回头解释它，因为这块不看图是真的会晕。

```python
    def forward(self, Q, K, V):
        """前向传播, 计算注意力权重和输出"""
        # 1.1 拼接 Q 和 K  -> (1, 32) 与 (1, 32) 拼成 (1, 64)
        qk_cat = torch.cat((Q[0], K[0]), dim=-1)

        # 1.2 通过线性层, 计算注意力得分  (1, 64) -> (1, 32)
        attn_scores = self.attn(qk_cat)

        # 1.3 用 softmax 归一化, 得到注意力权重分布  (1, 32)
        attn_weights = F.softmax(attn_scores, dim=-1)

        # 2.1 扩展注意力权重维度, 以匹配 V 的批次维度  (1, 32) -> (1, 1, 32)
        attn_weights_expanded = attn_weights.unsqueeze(0)

        # 2.2 使用 bmm 执行批量矩阵乘法  (1, 1, 32) @ (1, 32, 64) -> (1, 1, 64)
        attn_applied = torch.bmm(attn_weights_expanded, V)

        # 3.1 拼接原始 Q 与注意力加权后的 V  (1, 1, 32) 与 (1, 1, 64) 拼成 (1, 1, 96)
        output_cat = torch.cat((Q, attn_applied), dim=-1)

        # 3.2 通过线性层降维到输出维度  (1, 1, 96) -> (1, 1, 32)
        output = self.attn_combine(output_cat)

        # 3.3 返回注意力结果表示与注意力权重分布
        return output, attn_weights
```

逐段看维度。Q 的形状是 `(1, query_size)` 也就是 `(1, 32)`，K 是 `(1, key_size)` 也就是 `(1, 32)`，V 是 `(1, value_size1, value_size2)` 也就是 `(1, 32, 64)`。

第一步拼接 Q 和 K。为什么是 Q 的 `[0]` 和 K 的 `[0]`？因为要送进线性层的是二维的 `(1, 32)`，把最外面那个批次维先取掉，拼完就是 `(1, 64)`。

第二步过线性层，`(1, 64)` 进去，输出 `value_size1` 那么多个得分，即 `(1, 32)`——这 32 个数就是 Q 和 32 个单词之间的原始得分。

第三步 `F.softmax(..., dim=-1)` 把得分归一化成概率分布，形状还是 `(1, 32)`。这也是开头导包时 `import torch.nn.functional as F` 的用处，就是为了这个 `F.softmax`。

第四步 `unsqueeze(0)` 扩展注意力权重的维度，从 `(1, 32)` 变成 `(1, 1, 32)`，目的是让它的批次维和 V 对齐，能去做 `bmm`。

第五步 `torch.bmm`：`(1, 1, 32)` 乘 `(1, 32, 64)`。按批量矩阵乘法算，中间的 `32` 与 `32` 消掉，得到 `(1, 1, 64)`——这就是注意力加权之后的 V。注意这里两个张量都是三维的，正是 `bmm` 的用武之地。

第六步拼接 Q 和加权后的 V：`(1, 1, 32)` 和 `(1, 1, 64)` 在最后一维拼起来，变成 `(1, 1, 96)`。

第七步过 `attn_combine`，`(1, 1, 96)` 降维成 `(1, 1, 32)`。所以最终输出 `output` 的形状是 `(1, 1, 32)`，`attn_weights` 的形状是 `(1, 32)`。

| 步骤 | 操作 | 输入形状 | 输出形状 |
| --- | --- | --- | --- |
| 1.1 | 拼接 Q 与 K | `(1,32)`、`(1,32)` | `(1,64)` |
| 1.2 | 过注意力线性层 | `(1,64)` | `(1,32)` |
| 1.3 | softmax 归一化 | `(1,32)` | `(1,32)` |
| 2.1 | `unsqueeze(0)` 扩展维度 | `(1,32)` | `(1,1,32)` |
| 2.2 | `bmm` 加权 V | `(1,1,32)`、`(1,32,64)` | `(1,1,64)` |
| 3.1 | 拼接 Q 与加权 V | `(1,1,32)`、`(1,1,64)` | `(1,1,96)` |
| 3.2 | 线性层降维 | `(1,1,96)` | `(1,1,32)` |

> **提示**：`dim=-1` 在这段代码里出现了两次，含义并不相同。拼接时 `dim=-1` 表示在最后一个维度上首尾相接；softmax 时 `dim=-1` 表示在最后一个维度上做归一化，所以 32 个得分加起来是 1。改错了维度，权重就不成分布了。
