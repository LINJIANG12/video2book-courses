# 从 RNN 训练代码改出 LSTM 训练：四处改动与耗时实测

RNN 那一套训练代码刚刚跑通，接下来就该轮到 LSTM 了。这次不新建文件、不从头写，而是把 `train_rnn` 整段复制过来，只改必须改的地方。

为什么这么干？因为真正的重点不是"会不会写第二个训练函数"，而是**你到底懂不懂 LSTM 和 RNN 的差别落在哪一行**。如果你光会照着 RNN 抄，LSTM 你抄不出来；反过来，如果你能把它改明白，说明你不仅能改过去，还能改回来——这才叫真的听懂了。

我先说一个判断：这次改动一共只有四个地方，其中三个在 forward 里，一个在调用处。剩下那几十行——损失、反向传播、统计、打印——**一行都不用动**。

## 1. 训练函数的复制与命名

操作本身很朴素：到 `train_rnn` 上面 `Ctrl C`，粘到下面 `Ctrl V`，然后把函数名换掉。

```python
def train_lstm():        # 原来是 train_rnn()
    ...
```

训练本体保持不变。这跟后面要做的 GRU 训练是同一套路数：把上面那段直接复制、粘过去、换一下就能出来，非常简单。

## 2. 实例化模型

模型对象的创建要换掉，把 `MyRNN` 换成 `MyLSTM`——这是 `MyLSTM` 这个类第一次真正被用起来。

```python
my_lstm = MyLSTM()       # 原来是 my_rnn = MyRNN()
```

> **易错点**：这里换的是**类名**，不是"给变量重新起个名字"。变量名本身叫 `my_lstm` 或者继续叫 `my_rnn` 都行，它只是一个引用；真正决定用的是哪个模型的是等号右边那个类。

## 3. 隐状态初始化与 `c` 的出现

接下来是这一讲第一个真正的知识点。原来的初始化是这样：

```python
hidden = my_rnn.init_hidden(batch_size)
```

这里就不能直接照抄了，也不能靠"后面总会有 hidden 可用"混过去——`hidden` 是从上面这行来的，上面没给，后面就没有。而且更要命的是，RNN 的 `init_hidden` 返回的是一个张量，LSTM 的返回的是**两个**：隐藏状态和细胞状态。只接一个，直接报错。

所以正确的接法是同时接收两个值：

```python
hidden, c = my_lstm.init_hidden(batch_size)
```

> **提示**：如果第 2 步里你顺手把变量名从 `my_rnn` 改成了 `my_lstm`，那么这里也必须跟着调成 `my_lstm`，否则就是拿 LSTM 的初始化去配 RNN 的对象。我一般不建议改那个变量名，改一处要跟着改一串，不改反而省事——但前提是你心里清楚它现在指的是哪个模型。

## 4. 前向调用时 `c` 的传参方式

LSTM 的前向要接收 `(hidden, c)` 这一对。写法是在原来的 `hidden` 后面**加一个逗号，再加一个 `c`**：

```python
output, hidden = my_lstm(x, hidden, c)       # 错：c 被当成第三个位置参数
output, hidden = my_lstm(x, (hidden, c))     # 对：整体作为一个参数传入
```

后面那个接收用的 `hidden` 不用改名，但整对状态的传参必须用括号括起来，逗号 `c` 是写在括号里面的。

为什么不加括号就报错？因为这个 `MyLSTM` 的 `forward` 是我们自己写的，签名里只认两个参数：输入张量和状态元组。你把它写成三个独立参数，参数个数对不上，自然报错。这一点在 LSTM 的 API 那节讲过——**要是用框架自带的 `nn.LSTM`，它本来就按元组收，不会给你这个机会犯错；自己写的类就得自己盯着括号**。

## 5. 调用模型处的类名

最后还有一处，藏在 loss 计算那一段附近——调用模型、把输出喂给损失函数的那一行：

```python
output = my_lstm(x)              # 原来是 my_rnn(x)
loss = my_loss(output, y)
```

就是这一句里模型对象的引用要换掉。除此之外：

- `my_loss` 不动——损失函数和模型无关；
- 反向传播不动——优化器、`zero_grad()`、`backward()`、`step()` 这四步是通用的；
- 统计那一堆不动——统计的是 loss 和准确率，跟用哪个模型统计没关系。

到这里四处就全改完了。真的就这么多。

## 6. 训练一轮的耗时实测

改完之后没法立刻看出对错，得跑一遍。跑之前先确认一件事：训练轮数是不是已经从 3 改成 1 了。之前为了快，已经把轮数压到了一轮，所以这次只会训练一轮。

启动之后输出是每 2000 个样本打印一次：2000、4000、6000，一屏一屏往下走。我最关心的是总耗时。

> **结论**：这一轮 LSTM 跑了 **52 秒**，而 RNN 那轮是 **51 秒**，只慢了 1 秒——比预想中"慢很多"要接近得多。

按内部结构来推，本来该是这样的排序：

| 模型 | 内部结构复杂度 | 预期训练耗时 |
| --- | --- | --- |
| LSTM | 最高（四组运算） | 最长 |
| GRU | 居中（三组运算） | 居中 |
| RNN | 最低（一组运算） | 最短 |

LSTM 内部结构是最复杂的，所以理论上它应该最慢，GRU 应该介于两者之间。可实际上第一次跑出来只差 1 秒，这就不太对得上。

## 7. 单轮耗时为什么不可靠

这里有个很多人会踩的坑。我提示一下：RNN 第一次跑是 51 秒，后来再跑，我记得跑出过一个 **161 秒**——那是 3 轮的总时间。拿 161 除以 3，每轮接近 54 秒，**比 52 秒还长**。

同一个模型、同一份数据，为什么时间会飘？因为它跟你电脑当下跑着多少东西、占了多少资源直接相关。你一边编译、一边放着网页、一边开着聊天窗口，训练就慢；机器闲下来，训练就快。

> **结论**：只跑一轮测出来的耗时，参考价值有限。想让它有参考性，就把轮数提上去——**改成 100 轮、200 轮甚至 1000 轮，然后算总时长**。跑得越多，平均下来的一次耗时越稳。

具体怎么测才靠谱，三条：

1. 先把手头能关的软件、能停的服务全关掉，**只留 PyCharm 这一个**；
2. 用多轮训练的总耗时去除以轮数，而不是拿单轮的时间当结论；
3. 只做一次，别反复跑——你多跑几次也会发现数字不一样，因为它本来就不是一个稳定量。

单次跑出来的数字，最后就是"仅供参考"四个字。
