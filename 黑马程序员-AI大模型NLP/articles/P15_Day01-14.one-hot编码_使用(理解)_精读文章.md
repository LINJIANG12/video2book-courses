# one-hot 编码的加载与使用

生成那一节做完，模型已经存到磁盘上了。接下来要讲的，是怎么把这个模型用起来——通过 `joblib.load` 把刚才保存的模型加载下来，然后去获取它的编码。

先切回 PyCharm，把刚才那段代码折叠了，往下接着写。`demo 02` 这个位置就是使用环节，叫 `demo 02 use one-hot` 也行，你要嫌那名字看着难受，就把 `demo 02` 删掉，直接叫 `use one-hot`，后面再加个后缀，都行。这个随你，不用纠结。

## 1 为什么模型要存下来再加载

先说清楚这件事的动机，否则你只会觉得"多此一举"。

上一节反复跑那段生成代码，你会发现同一批词跑出来的编号每次都不一样。原因在于编号是词汇映射器当场生成的，程序一重启、映射器一重建，它就跟上次不是同一个排列了。而编码本身强依赖编号：编号变了，同一个词的 0/1 位置就跟着变，昨天的编码今天就用不了。

所以生成和使用必须拆成两段脚本：

```text
DM03 (生成)                          使用 (加载)
  构建语料 → 训练词汇映射器              joblib.load 读回映射器
       ↓                                    ↓
  逐个词生成 one-hot 编码              对任意词查编号 → 生成编码
       ↓
  joblib.dump 把映射器序列化落盘  ────────┘  顺序从此固定, 反复运行不再变
```

> **结论**：**稳定性不是靠代码保证的，是靠"把结果冻结下来"保证的**。映射器一存下来，"我是第几个"这件事就被写死了，后面不管查几回都不变。

## 2 加载词汇映射器

第一个动作不用想，肯定是加载训练好的东西——**词汇映射器**：

```python
import joblib

my_tokenizer = joblib.load('./model/onehot_tokenizer.pkl')
```

`joblib.load` 里填的就是我们保存模型时的那个路径。上一步 `joblib.dump` 存下去的是什么对象，这一步原样拿回来的就是什么对象——拿回来以后它跟当初刚训练完的映射器没有区别，可以直接查编号。

## 3 打印 word_index 字典

第二个动作是打印加载到的词汇映射器里的 `word_index`，查看**词汇和索引的对应关系**：

```python
print(my_tokenizer.word_index)
```

这就是"单词 → 索引"的那个字典。把它打出来，你才能知道某个词到底是第几个，也才能理解后面零向量里那个 1 为什么落在那个位置。

右键运行，结果无论你玩多少回，它肯定都是固定的：

```text
运行第 1 次:  {'王力宏': 1, '李薇薇': 2, '成龙': 3, ...}
运行第 2 次:  {'王力宏': 1, '李薇薇': 2, '成龙': 3, ...}
```

为什么？因为我们已经把这个模型保存下来了——你要是不保存，每次它都可能不一样。

> **提示**：这里那句"每次都不一样"，说的是**重新训练**的那种玩法。上一节在生成脚本上反复右键，每次都在 `fit_on_texts` 里重建一遍映射关系，所以编号来回变；而现在这一行是把存好的字典原样读回来，读两次得到的就是同一份内容。**决定编号的从来不是这次运行，而是当初落盘的那一次。**

跑出来就是"谁是老六"的问题了——你看，微微排在第六位。行，就先到这儿，一会儿换一下就行。

## 4 对指定词汇编码

接下来这个操作，就是对**指定词汇**进行 one-hot 编码。整个流程还是那几步，只是零向量的长度换了来源。

### 4.1 选定待编码的词

```python
token = '常微微'
```

变量名你可以叫 `token`，也可以叫 `vocab`，随你。甩一个词进去就行——就选微微吧。

### 4.2 创建等长的零列表

```python
zero_list = [0] * len(my_tokenizer.word_index)
```

> **易错点**：这里的长度**不再是语料库长度，而是"词汇和索引字典"的长度**——也就是上边那个字典有几对键值，就造几个 0。

你告诉我，这个字典现在一共有几对？六对。那你现在就有几个 0？六个 0。这个数是现成的，不用回头数原始语料——只要字典在手，位数就是确定的。

### 4.3 取索引并减 1

```python
idx = my_tokenizer.word_index[token] - 1
```

获取指定词汇在 `word_index` 中的索引，因为是**从 1 开始编号的，所以要减 1**，换成列表下标。

> **易错点**：编号从 1 起、下标从 0 起，中间差的就是这一下。漏掉减 1，1 号词的 1 会落到 2 号位上，整张表整体错位一格，而且不报错——这种错误最难发现。

### 4.4 把对应位置改成 1 并打印

```python
zero_list[idx] = 1
print(f'{token} 的 one-hot 编码为: {zero_list}')
```

到这里就结束了。所以你会发现，这段代码跟生成那段代码的区别在于：刚才你要先**创建一个词汇映射器**，创建完毕之后才去生成编码，最后把词汇映射器保存下来。

> **结论**：生成那一步，本质上做的是**把词汇的顺序映射出来**这一件事。顺序一旦存好，后续无论你查几回，数值都不会变——常龙是 5 就永远是 5，微微是 6 就永远是 6。

## 5 索引减 1 的验证

跑一下验证。找一个词看它在字典里排第几：假设它在这里边是 3，那减 1 之后对应下标 2，结果是 `0 0 1 0 0 0`，后面那一堆还是 0。

```text
字典中编号为 3  →  idx = 3 - 1 = 2  →  0 0 1 0 0 0
```

换成自己再试一次也行，结果一样。这个动作你多跑几次就能确认：**只要字典不变，同一个词每次拿到的编码一定相同**。

## 6 词表外的词与封闭词表

再换个词试试。这次换成我自己的本名——写着写着你会发现，这名字看着好陌生，虽然是我的本名，但现在好多场合都不念这个了。

然后它就报错了。报什么错？它会说**在这里边找不到这个词**，因为刚才训练的那个字典里没有这个词。

> **易错点**：`word_index` 里的键只包含训练语料里出现过的词。传一个词表外的词进去，`word_index[token]` 直接抛 `KeyError`，编码无从谈起。

这就是 one-hot 最硬的边界：**它的词汇表是封闭的**。模型能表达什么，完全取决于当初喂进去的那几个词。你给它一个从没见过的词，它既不会猜、也不会近似，只会告诉你找不到。
