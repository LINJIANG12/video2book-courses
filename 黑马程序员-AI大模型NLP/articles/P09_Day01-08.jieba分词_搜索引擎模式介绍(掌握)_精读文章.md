# jieba 搜索引擎模式与召回率

`demo02` 那堆代码复制过来，把函数名改成 `demo03`，`cut` 换成 `cut_for_search`，代码就已经能跑了。但你可能会看懵：为什么就换个函数，它就能干搜索引擎的活？"在精确模式基础上对长词再次切分""提高召回率"这两句话到底在说什么？这一讲不急着写代码，先用两个场景加一个真实应用，把这套机制讲透，再回过头收代码。

## 搜索引擎模式在做什么

用注释把这套规则记在函数上面：

```python
'''
3 定义函数, 演示 jieba 搜索引擎模式分词
  适用于搜索引擎分词, 以及文本匹配
  做法: 在精确模式分词的基础之上, 对长词再次切分, 提高召回率
'''
```

> **定义**：搜索引擎模式（search engine mode）先在精确模式下切一遍词，再对其中较长的词做二次切分，让更短的子词也能被命中，从而提高召回率（recall）。

三引号这种写法可以当注释用，也可以当字符串处理；这里我拿它当注释。

## 场景一：搜"程序员"时能被匹配到的文档

场景一：用户在搜索引擎里输入一个词——`程序员`。

假设你现在在百度里搜"程序员"。如果搜出来的结果只会和"程序员"这三个字严格相关，那你搜到什么就是什么。但实际情况是，你最后搜出来的内容里，除了和"程序员"直接相关的，还会匹配到 `程序`，甚至匹配到 `员`。为什么会往下发散？

因为不同分词模式下，"什么文档算命中"的定义不一样：

- 精确模式：只能匹配**完整包含** `程序员` 这三个字的文档。也就是说，它只能帮你把完整包含这三个字的文档找出来；
- 搜索引擎模式：不仅能匹配包含 `程序员` 的文档，还能匹配包含 `程序` 的文档，也能匹配包含 `员` 的文档。

文档命中范围因此变大，**召回率就上去了**。

> **结论**：为什么引擎模式能提高召回率？因为被匹配到的文档变多了——原来因为写得不完整、用了简写而漏掉的文档，现在都能被找回来，预测到的数据更全、更"准"，命中的集合自然变大。

## 场景二：搜"黑马程序"与电商搜索

场景二：用户搜 `黑马程序`。

精确模式下，能匹配的只能是 `黑马` 和 `程序`，它匹配不了 `员`——因为库里没有"员"这个独立词的命中依据。而在搜索引擎模式下，它有可能直接给你匹配到 `黑马程序员` 这一整条。

这个场景在哪儿见得最多？**电商搜索**，这是用得最多的场景。

举个例子：某个商品的标题是 `苹果手机保护套`，但用户搜索的时候只打了三个字——`苹果套`。

先问一句：精确模式能匹配吗？`苹果套`，那是什么套？没有这个词。我们来看看精确模式为什么会失效：用户输入的 `苹果套` 会被切分成 `苹果`、`保护套` 这类词（顶多再延伸一个 `手机`），而商品标题 `苹果手机保护套` 切出来的是 `苹果`、`手机`、`保护套` 这套完整的词。用户的词和标题里的词对不上，所以这个商品你根本搜不出来。

换成搜索引擎模式，能不能匹配？能。它的分词会给到 `苹果`、`手机`、`保护`，甚至可能有 `保护套`，甚至还有可能落到一个字 `套`。这一回，用户输入的 `苹果套` 切出来的 `苹果` 和 `套`，就能和标题里的 `苹果`、`套` 对上，商品就被推荐出去了。

```text
同一商品标题在两种模式下的匹配路径

  商品标题: 苹果手机保护套
  用户输入: 苹果套

  精确模式:
      标题词 -> 苹果 / 手机 / 保护套
      输入词 -> 苹果 / 保护套(类)
      交集   -> 苹果 之外对不齐, 匹配失败(搜不出来)

  搜索引擎模式:
      标题词 -> 苹果 / 手机 / 保护 / 保护套 / 套
      输入词 -> 苹果 / 套
      交集   -> 苹果 + 套 命中, 推荐成功
```

读图说明：搜索引擎模式把长词 `保护套` 再次切开，多出来的 `保护`、`套` 这些碎片让用户的不完整输入有了落点，召回率因此提高。

于是你会看到一种很"智能"的现象：话还没说完、词都没打全，程序却知道你想表达什么。其实背后没什么玄机，就是对长词再切了一次。

## 从 `demo02` 改造出 `demo03`

把 `demo02` 整段 Ctrl+C 复制过来，改叫 `demo03`，展开以后逐项改。

第一句"定义待分词的文本内容"不变。

第二个操作要改措辞：不再是"全模式分词"，而是"搜索引擎模式分词"。

> **易错点**：因为是从 `demo02` 复制过来的，里面写着"全模式分词"这几个字，你稍微不留神就会把它留下。这里的默认模式是精确模式，不是全模式，所以这几个字必须删掉。复制粘贴的弊端就在这儿——容易产生这种残留式的歧义。

接下来是关键的两处替换：

1. 它**不是** `cut_all` 的开关。这个函数要换成 `cut_for_search`——切割是为搜索服务的；
2. 参数里**没有** `cut_all` 了，直接把句子给它就行。

```python
    # 2 使用 jieba 进行搜索引擎模式分词, 函数为 cut_for_search
    result3 = jieba.cut_for_search(content)
    print(f"result3: {result3}")          # 生成器对象
```

后面取数据的部分一模一样。打印出来的 `result3` 依旧是一个生成器对象，地址值不必管。

## 数据获取与 `lcut_for_search`

从生成器里取数据：`next` 逐个取、`for` 遍历，照旧。转列表的两个思路也照旧：

- 思路一，把上面的生成器转成列表——这次肯定还是空的，因为上面的遍历已经把它跑完了；
- 思路二，切词时直接返回列表，也就是语法糖。写法上，`lcut` 后面再带上 `for_search`：

```python
    # 4.2 思路二: 切词时直接返回 list(语法糖)
    list2 = jieba.lcut_for_search(content)
    print(f"list2: {list2}")
```

> **提示**：`cut` 与 `lcut` 的关系在这里同样成立——前面加一个 `l`（list），返回的就是列表。既然搜索引擎模式的切词函数是 `cut_for_search`，那它的列表版本就是 `lcut_for_search`。

## 三种模式的结果对比

每次跑完都靠眼睛在控制台里扫，一行一行去对"这里是谁、那里是谁"，太费劲。所以干脆在代码里把三种模式的结果一起打出来比。

`list2` 那句话先写清楚它是什么模式：

```python
    print("搜索引擎模式分词: ", list2)

    # 5 拓展: 打印精确模式分词与全模式分词的结果, 便于与搜索引擎模式分词对比
    list3 = jieba.lcut(content, cut_all=False)   # 精确模式
    list4 = jieba.lcut(content, cut_all=True)    # 全模式
    print("精确模式分词: ", list3)
    print("全模式分词: ", list4)
```

`list3` 用 `lcut` 配 `cut_all=False`，那就是精确模式；`list4` 配 `cut_all=True`，那就是全模式。

原来那行 `cut_all` 相关的语句要删掉——因为 `cut_for_search` 不接受这个参数。

跑起来，把打印结果拉长一点对比，能看出三者的层次差异：

- 最上面的是搜索引擎模式；
- 中间的是精确模式，切到完整的词为止；
- 下面的是全模式，切得比上面两个都多——但搜索引擎模式不会有很多重复项。

具体看"传智教育"，搜索引擎模式就**没有**切出 `传智` 这两个字，因为它单独看是有歧义的：`智` 可能是智慧、智能、智力等等，组合太多了，所以不往下切。

三种切词方式到这里讲完，最后归到一句话上：

> **结论**：三种分词模式最终的区别就是切词的**粒度**不一样。精确模式粒度较粗、语义完整；全模式粒度最细、碎片最多但带歧义；搜索引擎模式在精确模式的长词上再做一次切分，用更细的碎片换取更高的召回率。函数本身很简单，真正要掌握的是"苹果套"这类例子里它到底解决什么问题。

## 完整脚本

```python
import jieba


# TODO 3 定义函数, 演示 jieba 搜索引擎模式分词, 适用于搜索引擎分词与文本匹配
def demo03():
    # 1 定义待分词的文本内容
    content = "传智教育是一家上市公司"

    # 2 使用 jieba 进行搜索引擎模式分词, 函数为 cut_for_search(无 cut_all 参数)
    result3 = jieba.cut_for_search(content)
    print(f"result3: {result3}")          # 生成器对象

    # 3 从生成器对象中获取所有的分词结果
    for item in result3:
        print(item)

    # 4 要列表
    # 4.1 思路一: 生成器转列表(指针已到末尾, 结果为空)
    list1 = list(result3)
    print(f"list1: {list1}")
    # 4.2 思路二: 切词时直接返回 list(语法糖)
    list2 = jieba.lcut_for_search(content)
    print("搜索引擎模式分词: ", list2)

    # 5 拓展: 与精确模式、全模式分词结果对比
    list3 = jieba.lcut(content, cut_all=False)
    list4 = jieba.lcut(content, cut_all=True)
    print("精确模式分词: ", list3)
    print("全模式分词: ", list4)


# TODO 6 测试代码
if __name__ == '__main__':
    # 测试 jieba 搜索引擎模式分词
    demo03()
```
