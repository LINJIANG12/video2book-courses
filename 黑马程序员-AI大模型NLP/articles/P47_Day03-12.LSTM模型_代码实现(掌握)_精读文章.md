# LSTM 的 API 用法与隐状态元组传参

接下来讲 LSTM 的 API。你会发现 LSTM 的 API 较之于传统的 RNN，就多了一个东西——多了一个 `C0`。

`C0` 跟隐藏状态是一模一样的：维度一样、形状一样、传的位置也一样。以前我们是不是「本次的输入 + 上次的隐藏状态」就够了？现在除了上次的隐藏状态，还得把上次的**记忆细胞**一起传进来；它返回给你的，也是本次的隐藏状态和本次更新后的记忆细胞。就这一步，其他都一模一样。

> **结论**：从 `nn.RNN` 换到 `nn.LSTM`，模型构建的参数签名完全不变，变的只有前向调用——输入要带上 `(h0, c0)` 这个元组，返回值多一个细胞状态。原理讲了一整讲，落到 API 上只多这一个 `C0`。

## 本讲的案例与工程准备

我们新建一个脚本文件，名字叫 `LSTM模型_LSTM的API演示`，案例内容就是「演示 LSTM 的入门代码」。写之前先把 LSTM 的简介摆在前面：它叫长短时记忆结构（Long Short-Term Memory），解决的是传统 RNN 的一个弊端——**处理长序列数据效果差**。

注意这句话的措辞：不是不能处理，是**效果差**。

我打个比方。我让你算一组数：$13 \times 26 + 28$，再除以 2，再加几乘几、除几……算完我最后问你结果等于几，你张嘴就给我来个 3。它不是不会算，它是算得不准——那这有什么用？长序列上的 RNN 就是这样，前面的信息它能碰到，但等到用的时候已经记混了。

组成还是那句老话：**三门一状态**。遗忘门、输入门、细胞状态、输出门。这里先把优缺点一起写掉。

**优点**：

1. 能解决长时依赖问题，也就是长数据依赖；
2. 缓解梯度消失和梯度爆炸，相对来讲训练更稳定；
3. 能抓取更复杂的特征。

**缺点**：

1. 计算慢，消耗资源大。怎么看这一条？传统 RNN 里边就一个黄框（神经网络），这玩意儿里边几个黄框？1、2、3、4——四个。黄框越多，消耗的资源肯定越大。顺便剧透一句：一会儿要讲的 GRU 是不是也四个？不是，它把这四个合成仨。
2. 调参相对较难，因为参数太多。
3. 可解释性稍差。RNN 更好解释一点——上次的隐藏状态加上本次输入，直接得到结果；LSTM 中间还夹着细胞状态，内部怎么工作的虽然后面都会解释，但较之 RNN，相对来讲可解释性是要差一些的。

## LSTM 构造函数与四个参数

先导包，`torch` 肯定要，再 `import torch.nn as nn`，这是免不了的。

然后定义函数 `LSTM_demo()`，函数体第一句话一定是实例化——创建 LSTM 模型对象：

```python
import torch
import torch.nn as nn


def LSTM_demo():
    # 1. 创建 LSTM 模型对象
    lstm = nn.LSTM(input_size=561, hidden_size=135, num_layers=236, bidirectional=False)

    # 2. 构建输入张量：(序列长度, 批次大小, 词向量维度)
    input = torch.randn(4, 3, 5)

    # 3. 初始化隐藏状态 h0 与细胞状态 c0
    h0 = torch.randn(1, 3, 6)
    c0 = torch.randn(1, 3, 6)

    # 4. 模型计算：写法 1 —— 手动传入 (h0, c0)
    output, (hn, cn) = lstm(input, (h0, c0))

    # 5. 打印结果
    print('output:', output, output.shape)
    print('hn:', hn, hn.shape)
    print('cn:', cn, cn.shape)
```

四个参数一个个对着看。

第一个 `input_size`，是词向量的维度，也就是输入的维度。这个数我为什么写 561？561 你们不认识吗？《士兵突击》里边有个人就叫 561，所以我这个数就是拿他的名字写的，特别好记。你写多少都行，这里只要求「跟你的词向量维度对得上」。

第二个 `hidden_size`，是隐藏层的维度，其实就是输出的维度。

第三个 `num_layers`，是 LSTM 隐藏层的层数。

第四个 `bidirectional`，是否双向。写 `False` 就是单向；写 `True` 就是双向，会帮你多算一次。

> **易错点**：`bidirectional=True` 之后，`hn` 和 `cn` 的第一维不再是 `num_layers`，而是 `num_layers * 2`——因为它要把两个方向的最终状态都还给你。上面这套形状推导是在单向前提下做的。

## 输入张量与隐状态形状推导

第二步构建输入张量 `torch.randn(4, 3, 5)`。这三个数分别是什么？

- 参 1 是**句子长度**，`sequence_length`，也就是时间步数，写 4；
- 参 2 是**批次大小**，`batch_size`，写 3；
- 参 3 是词向量的维度，也就是 `input_size` 那个位置。

> **提示**：文档里管参 3 叫「词向量维度」，但在具体网络里，它对应的就是每一个时间步喂进去的特征长度，理解成「输入维度」更不容易绕。只有参 3 和构造函数里的 `input_size` 对上，这一步才不会报错。

第三步初始化隐藏状态和细胞状态。`h0` 写 `torch.randn(1, 3, 6)`，这三个数又是怎么来的？

- 参 1 是 LSTM 的层数，也就是 `num_layers`。上面我们把它设成了 1，这里就写 1。
- 参 2 是批次大小，跟上面保持一致，是 3。
- 参 3 是隐藏层的维度，也就是输出维度，上面 `hidden_size` 是 6，这里就写 6。

所以才是 `1 3 6`。**`c0` 跟 `h0` 完全一样**，一模一样地写一份 `torch.randn(1, 3, 6)`。

```text
input  : (4, 3, 5)   = (序列长度, 批次大小, 输入维度)     ← input_size 要等于 5 才不报错
h0     : (1, 3, 6)   = (层数,     批次大小, 隐藏维度)
c0     : (1, 3, 6)   = 与 h0 完全一致
                │
                ▼  lstm(input, (h0, c0))
output : (4, 3, 6)   = 每个时间步的输出（隐藏状态）
hn     : (1, 3, 6)   = 最后一个时间步的隐藏状态
cn     : (1, 3, 6)   = 最后一个时间步的细胞状态
```

读图说明：输入和隐状态除了「时间步」这一维，其余两维（批次、特征维度）都严格对齐；输出的 `output` 保留了全部时间步，而 `hn`、`cn` 只留最后一个时间步。

## 前向调用的两种写法与元组包裹

第四步是模型计算，有两种写法。

**写法 1**：手动传入 `h0` 和 `c0`。

```python
    # 4. 模型计算：写法 1 —— 手动传入 (h0, c0)
    output, (hn, cn) = lstm(input, (h0, c0))
```

**写法 2**：不传 `h0` 和 `c0`。

```python
    # 4. 模型计算：写法 2 —— 不传，由底层自动生成全零隐状态
    output, (hn, cn) = lstm(input)
```

先说写法 1 的参数与返回值，一个个解释。

实参列表：

- 参 1 是 `input`，本次的输入张量；
- 参 2 是 `(h0, c0)`，**隐藏状态和细胞状态的元组形式**。

返回值：

- 返回值 1 是 `output`，本次的输出结果，形状 `(4, 3, 6)`；
- 返回值 2 是一个二元组 `(hn, cn)`，分别是**最后一个时间步**的隐藏状态和细胞状态，形状都是 `(1, 3, 6)`。

为什么强调「最后一个时间步」？因为 `output` 里边装的是每个时间步的输出，而最后那个时间步的结果，是把前面所有信息都滚过一遍之后得到的状态。所以它和最终的隐藏状态必然是同一个东西。

> **易错点**：`(h0, c0)` 必须整体当作一个参数传进去，小括号不能少。少了它，`lstm` 收到的就不是两个位置参数，而是三个：`input`、`h0`、`c0`——参数个数对不上，直接报错。接收返回值时也一样，`output, (hn, cn) = ...` 这一行的小括号是解包用的，同样不能省。两侧都不加，也一样不 OK。

这个「元组包裹」的规矩跟我们前面用的 RNN 是一个思路：把「上一时刻的隐状态内容」作为一个整体递进去。想通了这一层，就会发现原理讲得再多，API 上真的只多一个 `C0`。

## 实测输出与不传隐状态的行为

右键跑写法 1，输出是：

```text
output: 4 3 6
hn:     1 3 6
cn:     1 3 6
```

把三行形状对着看：`output` 是 `4 3 6`，`hn` 和 `cn` 都是 `1 3 6`。

这里有一个必须自己动手验证一遍的现象：`output` 里**最后一个时间步**的输出，跟下面返回的 `hn` 是一模一样的。因为 `hn` 定义上就是最后一步的隐藏状态，两者本来就该相等。而 `cn` 不一样——记忆细胞里记的信息更多，它很可能挑重点去做记忆，所以不必等于 `output` 的最后一步。

接下来换成写法 2 做对比：接收方式不变，但调用里不写 `h0`、`c0`，直接 `lstm(input)`。先猜一下会怎样——报错？不报错。

不报错就说明底层替我们生成了一个隐状态。生成的是什么？**全零**的 `h0` 和 `c0`。跑出来的形状依旧是 `4 3 6`、`1 3 6`、`1 3 6`，数值上跟手动传的版本也一致（因为 `randn` 的初始值和全零在第一步的效果差别被后续计算迅速覆盖掉了）。

> **定义**：`h0` 是上一时刻的隐藏状态，`c0` 是上一时刻的细胞状态。序列的第一个时间步没有「上一时刻」，所以不传时底层自动创建一个全零的初始状态来占位。

这也就解释了为什么写法 2 可以省略。不过课上我留着写法 1 反复演示，就是因为元组包裹这个坑必须踩过一遍才记得住。顺便演示三种错误写法：

```python
    lstm(input, h0, c0)             # 错：变成三个位置参数
    output, hn, cn = lstm(input)    # 错：返回值解包没按 (hn, cn) 的嵌套结构
    output, hn, cn = lstm(input, h0, c0)   # 错：都不加小括号，照样不 OK
```

写法对不对，就看你是不是老老实实以元组的形式把两个状态包在一起。

## 结构原理回顾与优缺点对比

再往下看一眼它的结构总结。LSTM 就是三门一状态：遗忘、输入、输出三个门，加一个细胞状态。它能更好地捕捉长序列之间的语义关联，缓解梯度消失或爆炸。三个门的分工是这样：

- **遗忘门**决定对以前的信息忘记多少；
- **输入门**决定对新的信息记住多少；
- **细胞状态**是长期记忆本，负责记录大事件；
- **输出门**决定把细胞状态里的哪些信息往外传递。

说白了，LSTM 全称 long short-term memory，与其叫「长短时记忆结构」，不如直接理解成**有选择性的记忆**：某些内容你记了很久，但到下一个时间步它不再重要了，那就被你舍弃掉，这就是「长短时」。

幻灯片上对优缺点的表述也值得记一下：优点是能有效缓解长序列上出现的梯度爆炸或消失问题——**注意只是缓解，不能完全解决**，但在长序列这块比传统 RNN 要好。缺点是内部结构相对复杂，算力要求比 RNN 多，所以在同等算力下训练效率比 RNN 要慢。

我拿车给你比一下：这车性能很牛，但它费油。同样 40 升油，省油的车能跑得更远一点；你这车费油，能跑的路程就短一点。那怎么办？要用 LSTM，就把算力提上去，算力那都不叫事。这就跟买车一样——买十万块车的人会经常算油耗，买几百万车的人虽然油耗很高，但他们不在乎这个油耗。

> **结论**：LSTM 的价值在于「长序列上比 RNN 准」，代价是「同样算力下比 RNN 慢」。这不是设计缺陷，而是用算力换记忆能力的等价交换。

## 本讲提到的题目

课上留了一道选择题：LSTM 的几种调用写法列出 A、B、C、D 四行，问哪一行错了、为什么错。**答案：D 错，D 错在没有加小括号。**

依据就在前面讲的调用规则里：`nn.LSTM` 的位置参数只有两个——输入张量和隐状态元组。D 把 `h0`、`c0` 拆开写成两个独立参数，模型收到的就是三个位置参数，它不认识第三个，直接报错。要么传两个（`input` 加上包好的 `(h0, c0)`），要么传一个（只给 `input`）——就是不能传三个。
