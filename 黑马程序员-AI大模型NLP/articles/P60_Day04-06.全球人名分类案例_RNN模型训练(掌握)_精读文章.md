## 训练函数的三个子任务与数据准备

先在代码里写下 TODO 8，标上"模型训练"。它下面分三个子项：8.1 RNN 模型训练、8.2 LSTM 模型训练、8.3 GRU 模型训练。不管用这三个里面的谁，开头都得有同一个动作——**定义变量**，记录学习率，还有训练的轮数。

数据准备这一步已经写过八百回了：读数据、封装 `Dataset`、封装 `DataLoader`，三小步一路封装上去。

```python
def my_train_rnn():
    # 1. 数据准备
    # 1.1 读取数据
    my_list_x, my_list_y = read_data('name_classification.txt')
    # 1.2 构建数据集对象
    name_class_dataset = NameClassDataset(my_list_x, my_list_y)
    # 1.3 构建数据加载器
    train_loader = DataLoader(name_class_dataset, batch_size=1, shuffle=True)
```

这里不需要再讲道理，只需要注意一件事——**每一次训练都要重新建一个加载器，不要跨轮次复用**（原因在后面讲外层循环时再说）。

## 模型与优化器

### 模型参数

```python
input_size, n_hidden, output_size = n_letters, 128, category_number
```

来解释解释：`n_letters` 是输入维度，也就是**字符表大小**，等于 57；`n_hidden` 是隐层维度，128；`output_size` 是输出维度，也就是**国家数量**，18。

### 损失函数与优化器

```python
criterion = nn.NLLLoss()
optimizer = optim.Adam(my_rnn.parameters(), lr=my_lr)
```

`criterion` 就是 `nn.NLLLoss`。**如果你用了 `CrossEntropyLoss`，那它就等于 `NLLLoss` 加 `LogSoftmax`**——所以你就知道上面模型里为什么写 `LogSoftmax` 了：这两处是配套的，改一处就必须改另一处。这个细节要特别注意。

优化器这边，按 `Ctrl` 往上看一眼导包的地方：上面是不是已经写了 `import torch.optim as optim`？已经导过了，所以这里直接 `optim.Adam` 就行，不用再写 `torch.optim`。里面第一个参数传模型的参数 `my_rnn.parameters()`，第二个参数传学习率。

### 训练参数初始化

```python
start_time = time.time()      # 训练开始的时刻
total_loss = 0.0              # 已训练样本的损失和
total_loss_list = []          # 每 100 个样本的平均损失列表
total_iter_num = 0            # 已训练的样本数
total_acc_num = 0             # 已训练样本中预测准确的总数
total_acc_list = []           # 每 100 个样本的平均准确率列表
```

这几个变量的分工要说清：

- `total_iter_num` 记录已训练的样本数；
- `total_loss` 是损失和，每一条都往里累加；
- `total_loss_list` 是每 100 个样本求一次平均损失存进去的列表——**这个损失值应该是逐步往下降还是往上升？** 应该往下降，损失应该是越来越少的；
- `total_acc_num` 是已训练样本里预测正确的总数。

> **提示**：`total_loss_list` 和 `total_acc_list` 不是给自己看的，它们是**画图用的数据源**。这一点决定了后面第 6 步那个"优化"为什么值得做。

## 训练过程：外层轮数、内层批次

### 外层循环与轮数打印

```python
for epoch in range(epochs):
    print(f'\n开始第 {epoch + 1}/{epochs} 轮训练')
```

`epochs` 是 1，所以 `epoch` 能取到的值只有 0。那为什么还要写 `epoch + 1`？

`epoch` 此时的值是 0，加 1 变成 1，后边就是"第 1/1 轮"。如果 `epochs` 写成 5，你看到的就是 1/5、2/5、3/5、4/5、5/5——**做五轮，第一轮、第二轮、第三轮**，一眼就知道进度。现在我们只训练一轮，所以没办法，输出只能是一个 1/1。

### 每轮新建加载器

在外层循环里再建一次加载器，**关键在于打乱**：

```python
for epoch in range(epochs):
    ...
    train_loader = DataLoader(name_class_dataset, batch_size=1, shuffle=True)
```

上面那个加载器只是针对某一轮取的，所以每一轮都重新创建一次带 `shuffle=True` 的加载器：**把封装好的数据在这里重新打乱一遍**。这样每一轮拿到的批次顺序都不同，模型不至于一直按同一个顺序看数据。

### 内层循环与 tqdm 进度条

```python
    total_iter_num = 0
    for i, (x, y) in enumerate(tqdm(train_loader)):
```

`train_loader` 里一共有多少条数据？20074 条。批次是 1，所以**一共有 20074 批**。

把 `train_loader` 直接包进 `tqdm` 里就行——它会在外面套一层进度条，训练过程就能以进度条的形式看到进度，不用干等。

```text
第 1/1 轮  开始
[==============>          ]  53%  10640/20074  [00:26<00:23,  402.5it/s]
                          ↑                     ↑
                     当前进度条           tqdm 自动统计的速率与剩余时间
```

读图说明：`tqdm` 只负责显示，不参与计算；它包在 `train_loader` 外面，所以"迭代次数"就等于"已训练的批次数"，也就是"已训练的样本数"。

> **易错点**：外层的 `for` 分的是**轮**，内层的 `for` 分的是**每轮的批次**。这两个 `for` 是嵌套关系，别写反了——外层写轮，里层写批次。

### 前向传播的输入维度处理

```python
        output, hidden = my_rnn(x[0], hidden)
```

别忘了咱刚才测过：这里传进去得是 `x[0]`。

为什么？因为 **`x` 本身是三维的**——形状是 `(1, L, 57)`，外面那个 1 是批次，`L` 是这个名字的长度，57 是字符序号编码。你要把外面那个 1 去掉，所以写 `x[0]`。

要是你不会，就想一想之前测 `my_rnn` 的时候：测试的时候传 input 是写死的，但统一测数据的时候，你传的就是一个 `x[0]`。**这个动作我们已经玩过了。**

还有 `hidden`：

```python
        hidden = my_rnn.init_hidden()
```

它就在 `my_rnn` 里面。这个动作的意思就是——**基于本次输入和本次隐藏状态，得到本次的输出和本次的隐藏状态**。

### 损失与三剑客

```python
        loss = criterion(output, y)
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
```

`criterion(output, y)`：`output` 是算出来的结果，`y` 是真实标签。然后三剑客照旧：梯度清零、反向传播、参数更新。

### 统计：样本数与累积损失

```python
        total_loss += loss.item()
        total_iter_num += 1
```

样本数为什么要加 1？**因为一批次就代表一个样本。** 批次是 1，所以每循环一次，样本数正好加 1。

下面是把这一批次的损失累加进 `total_loss`。这两句合起来，就为后面算平均损失准备好了分子和分母。

### 预测正确数统计

```python
        pred = torch.argmax(output, dim=1).item()
        total_acc_num += 1 if pred == y else 0
```

先看 `pred`：`torch.argmax` 是不是找最大值的索引？针对你的 `output` 找一下最大值，最后 `.item()` 取出来——**在 18 个数里面最大的那个数的索引，就是你预测的国家编号**。

再看累计：加等的这一句怎么理解？

```python
1 if pred == y else 0
```

**如果预测值跟真实值一样，就返回 1（说明预测对了），否则返回 0。** 累加进 `total_acc_num` 里。

所以等整个程序都跑完了，`total_acc_num` 里面记录的就是**预测正确的样本数**。那预测正确的除以总的，是不是就是你的准确率？

> **定义**：准确率的计算是 $\text{acc} = \dfrac{\text{预测正确的样本数}}{\text{总样本数}}$。这就是那两个累加变量存在的意义。

### 每 100 步：平均损失与平均准确率

```python
        if total_iter_num % 100 == 0:
            avg_loss = total_loss / total_iter_num
            total_loss_list.append(avg_loss)
```

看这句判断：`total_iter_num` 跟 100 取余等于 0，说明"100 过去了"。

先问一个问题：总数除以 100 算是平均损失吗？**不算。** 平均损失是**总损失除以总样本数**——分子是 `total_loss`，分母是 `total_iter_num`（那个每训练一个样本就加 1 的计数器），不是 100。

然后把它存进列表：`total_loss_list` 就是我们上面定义好的那个容器。

## 每 2000 步：日志、保存与收尾

### 平均准确率

```python
            avg_acc = total_acc_num / total_iter_num
            total_acc_list.append(avg_acc)
```

损失算完了，还有个准确率没算。准确率就是**预测正确的除以总样本数**，算完也添加到准确率列表里。这两句跟上面那两句是同一个套路，只是换了一组变量。

### 打印日志

```python
        if total_iter_num % 2000 == 0:
            avg_loss = total_loss / total_iter_num
            avg_acc = total_acc_num / total_iter_num
            end_time = time.time()
            print(f'轮次: {epoch + 1}, 训练样本数: {total_iter_num}, '
                  f'平均损失: {avg_loss:.4f}, 耗时: {end_time - start_time:.1f}s, '
                  f'准确率: {avg_acc:.4f}')
```

每 2000 步打印一次日志，"2000 步"指的是**2000 个样本打印一次日志**。

怎么判断？跟 2000 取余等于 0，说明能整除。整除的时候要做两件事：**先把平均损失算出来**（不算怎么打印？），再算平均准确率，最后算一下当前时刻，打印`轮次 / 样本数 / 平均损失 / 耗时 / 准确率`。

格式上给几个控制符：`.4f` 是保留四位小数，`.1f` 是一位。

> **提示**：两个取模判断是不同频率的两件事——**每 100 步记录一次指标（进列表，供画图），每 2000 步打印一次日志（进控制台，供人看）**。指标要密、日志要疏，这是很实用的一条经验。

### 一轮结束：保存模型

```python
    # 4.10 一轮训练结束，保存模型
    torch.save(my_rnn.state_dict(), f'./model/my_rnn_027_{epoch}.pth')
```

把上面那个内层 `for` 折叠起来，走到这里就说明**一轮训练完毕了**。

那接下来干嘛？**保存模型。**

有人会问：你一轮训练完了就保存一次？对，我一共保存——比如我训练 20 轮，我可能就保存 20 个。**为什么我要做这件事？**

假设你要训练 10 轮，我刚才说过，训练一轮大概一分钟，那 10 轮可能就是 10 分钟。假设你训练到 9 分 30 秒，马上就要训练完了，之前都是 OK 的，**但就最后一次训练的时候崩了**。那你之前这 9 分半就算无用功，你是不是又要从头做一次？

实际开发中你知道训练一个模型可能要好几周甚至好几个月。如果它一直不备份——执行执行执行，好不容易在那等了两个月，马上要成功了，**噔，网络断开连接**——好，所有的东西全丢完了。那你性命，程序猿把电脑砸了的心可能都有。哪有那时间等你？

所以说我们可以粗暴一点：**先保存了再说。**

`torch.save` 里面写谁？写 `my_rnn.state_dict()`，就是它的那些参数。存到哪儿？`./model` 下面。

问你们一句：你们下面有 `model` 这个文件夹吗？**没有。所以先把 `model` 建出来。** 文件名建议带上能认出是哪次运行的信息，比如：

```python
torch.save(my_rnn.state_dict(), f'./model/my_rnn_027_{epoch}.pth')
```

后缀 `.pth` 可以，`.pkl` 也行，随你。这里大括号里是 `epoch`，所以第一轮、第二轮、第三轮……各存一个文件。假设我要训练 10 轮，最后一轮崩了，它最起码第九轮的结果是合格的，**你下一次就不用再从头去跑了**。

### 收尾：统计与返回

外层的 `for` 走完，训练就结束了。剩下的工作是统计返回结果。

```python
    total_time = int(time.time() - start_time)
    print(f'训练完成，训练总耗时: {total_time}s，共训练样本数: {total_iter_num}')
    return total_loss_list, total_time, total_acc_list
```

`total_time` 是用结束时刻减去最开始记下的 `time.time()`。打印那句里，总耗时和总样本数是重点，前面都有。

到此，训练函数写完了。

## 三处代码优化

写完之后，还有三处可以优化，我一并说清楚——**其中有些我留给你们自己做**。

### 优化一：让数据准备返回加载器

把数据准备那一坨（读数据 + `Dataset` + `DataLoader`）单独收成一个函数，返回数据加载器。这样训练、测试、预测都能复用同一份数据准备代码，不用每次复制三行。

### 优化二：换掉 softmax

不要在模型里写 `LogSoftmax`，直接在损失函数这一处用 `nn.CrossEntropyLoss`。前面说过，`CrossEntropyLoss` 就等于 `NLLLoss` 加 `LogSoftmax`，所以换成它以后，**上面那句 `self.softmax` 就不用写了**，代码更简单。这两处必须同时改，这就是"细节要注意"的含义。

### 优化三：把返回的三个值存到文件里

现在 `return` 出来的是三个值：损失列表、训练总耗时、准确率列表。正常来讲我们应该是返回一个值吧？但这里得返回三个，因为后面画图三样都要用。

**这三值是怎么来的？是你训练完毕才能得到的。** 那这三值可以再做一件事——**存到文件中**。

存到文件里有什么好处？**未来我用的时候，直接拿就行了。**

为什么这件事很重要？因为一会儿我们会**可视化三个模型的训练结果**。如果你没有存，那以后要用这三个结果时，它就**会把这个函数又给你执行一遍**——也就是说，每次想看结果，都得等模型重新训练一次。

> **易错点**：`total_loss_list` 和 `total_acc_list` 不落盘，代价不是"多写几行代码"，而是**每次画图都要重跑一遍训练**。把结果写进文件，未来直接从文件加载，就省掉了整个训练过程。

这三处优化你待会儿可以自己动手做一做，我上面的代码里也没写，是留给你的。

**第二件：损失是不是在往下掉。**

你从 1.53 看到 1.2、1.17、1.19，然后 1.0 几——**损失是不是一直在往下降**？这就是模型在学。同时准确率在往上走。

这就是那个 2000 取余判断在起作用：2000 条训练一下、打一条日志，2000 条训练一下、再打一条。

## 训练结果的落盘与断点续训

跑完你还会发现一件事：我一共保存了三个模型。

为什么是三个？因为第一次跑完了，第二次跑完了，**第三次运行的时候崩了**。

崩了就崩了，崩了说明一件事——**说明你第三次运行的时候出问题了**。那我们就直接做一件事：**把第二次那个模型的参数直接加载进去**，让它当初始模型，往后接着训练就行了。

这样做比以往的好处在哪？你以往是所有的轮数全训练完才保存。假设我训练完一共需要 30 分钟，在第 29 分 30 秒的时候噔，报了个错，导致前边所有的内容都没有保存上——你这半小时就做白废工了。

你要知道，像有的公司训练模型，它训练两个月，**光电费可能都得几百万**。好家伙，你把模型一跑撒手不管了，这两个月在那摸鱼呢。结果两个月之后老大问你："那个数据总该出来了吧？模型差不多了吧？"你跟老大说："嗯差不多了，等会吧，还有 10 分钟就能看到结果了。"老大陪你站在那儿倒计时：5、4、3——噔，报了个错。好，结果啥玩意儿也没了。你不在那儿扯呢吗？

所以正常来讲，**咱以前做是为了简单，最后保存一次；正常应该是每次都保存，这样会好一点**。但你要是觉得太繁琐、太占空间，那你可以三轮保存一下，或者五轮保存一下，是不是都可以？

所以一会儿三个模型里，我们用哪个当起点的模型？**用第三次那个肯定会好一点**，因为它离训练终点最近。当然我就不每个都训练三轮了，成本太高，我就训练一轮——一会儿你挑哪个都行。

## 三个模型的关系

RNN 这一套走完，LSTM 和 GRU 就是把这次的代码复制过去，换模型对象和调用方式：

| 模型 | 主体循环要不要改 | 需要改动的地方 |
| --- | --- | --- |
| RNN | —— | 已经示范完成 |
| LSTM | 不改 | 模型对象换 `my_lstm`；前向传播处返回值多接一个 `c` |
| GRU | 不改 | 模型对象换 `my_gru`，其余与 RNN 完全一致 |

> **结论**：训练流程是"与模型无关"的骨架——数据准备、损失与优化器、统计口径、日志频率、保存策略，三个模型完全共用。真正跟模型绑定的只有两行代码。

最后再说一遍要求：绘图的代码你不用写，但**上面这个训练过程你得自己做**——三个模型的训练都要写出来，最后把三张图绘制出来做对比。RNN 我们就先聊到这个地方。
