# 中文文本分类的 pipeline 实现：环境准备、模型筛选与情感分析案例

"你的库里面有 transformers 这个包吗？"

我问这句话的意思是——不用去查，肯定没有。所以这一讲的第一件事不是写代码，是先把这个包装上。装完才轮到今天真正的主角：用 pipeline 这种方式，几行代码跑通第一个 NLP 任务。

我们这一路都在围绕三种调用方式打转：管道、自动模型、具体模型。这一讲先把管道方式落地。

## 1 开工前的三件事

第一件，把共享资料里的预训练模型先同步下载下来并解压，一共六个模型，对应六个任务。这件事我前面已经让你们做过了。

第二件，安装 `transformers` 模块。第三件，安装 `datasets` 模块。两条命令，一条都不能少：

```bash
pip install transformers
pip install datasets
```

`datasets` 这个包看名字就能猜出来——数据集。`transformers` 负责加载模型，`datasets` 负责把数据弄进来，这两件事都得用，所以两个包都得装。

资料里可能还写了 `git clone` 那一套。那是 Linux 环境下的部署方式，跟我们没关系，直接跳过不看。

> **注意**：GPU 环境和 CPU 环境都装一遍。你在沙箱里切到 `nlp-base2` 这类 GPU 环境时，如果两个环境只装了一个，代码会在解释器那里直接报找不到模块，跟模型没关系，纯粹是包的锅。所以别装错环境。

## 2 三种调用方式的区别与选择

先把三种方式的定位再说一遍，因为它决定了你后面拿哪套代码去改。

管道方式给初学者用——几行代码就能出结果，代价是它替你做主的那些细节你插不上手。具体模型给大佬用——自由度拉满，什么都能改，也什么都得自己管。中间那个自动模型，是给"既想换不同模型，又不想太操心"的人用的。

拿饭店做比方：管道方式是去饭店直接点餐，端上来就是成品；自动模型是买预制菜，简单加工一下就能吃；具体模型是自己买原材料下厨。

> **提示**：这三条路不是"哪条更高级"的关系，而是"谁来做决定"的关系。饭店你也得找对——找不对，那就是把预制菜做成成品端给你吃，你以为省心，其实只是把选择权交出去了而已。

## 3 pipeline 支持的六类任务

pipeline 这一种写法，我们要过六个任务。数一下：文本分类、特征提取、完形填空、阅读理解、文本摘要，还有 NER。

| 任务 | 干什么 | 要求 |
| --- | --- | --- |
| 文本分类 | 给整段文本判一个类别，比如星级好评还是差评 | 掌握 |
| 特征提取 | 只返回文本的特征，要和其他模型配合使用 | 掌握 |
| 完形填空 | 把文本里被挖掉的词补回来 | 掌握 |
| 阅读理解 | 依据给定的文本回答问题 | 了解 |
| 文本摘要 | 把长文本压缩成摘要 | 了解 |
| 命名实体识别（NER） | 从文本里找出人名、地名、机构名 | 了解 |

`NER` 是命名实体识别。什么叫命名实体识别？"我爱北京天安门，天安门上太阳升"——你从这句话里去找哪些是人名、哪些是地名、哪些是公司名，这个动作就叫命名实体识别。

顺带把一个容易和它混的概念也理一下：词性标注（POS）标的是名词、动词这一类词性，NER 标的是实体类别，两个东西标的对象不一样。

掌握前三，了解后三。当然最好六个都会——精力不够的话，就按前三后三这个优先级来。

再算一遍账：三个任务一组乘三种写法，本来是 18 个案例。但具体模型和自动模型差不多，所以我讲 6、6、1，一共 13 个。这一讲只碰管道这一组的第一个。

## 4 本地模型的准备与路径规范

六个模型对应六个任务，解压之后大概有九个 G。这么大的东西放哪儿，是有讲究的。

我自己的做法是把它放在 C 盘的 `software` 目录下，不往项目里贴。原因很实在：明天我可能就要新建一个 day11 的目录，你要是把九个 G 的模型塞进项目目录，等于每天都要重新搬一遍；它太占资源了，太大了，所以我干脆不贴进项目。

> **易错点**：路径必须合法。什么叫合法？不能出现中文、空格、特殊符号。模型目录一旦落在这种路径下，加载的时候就会出问题，而且报错信息通常不会直接告诉你"是中文路径的锅"。所以模型目录一律用纯英文、无空格的名字。

那绝对路径是怎么拿的？很多人第一反应是右键找"复制文件路径"，我自己的做法是：选中这个文件夹，右键，点属性，里面有个"安全"选项卡，安全里有个"对象名称"，从那儿把路径拷出来。用 Ctrl+C、Ctrl+V 也行，但要注意 Windows 的路径分隔符是反斜杠，直接粘进 Python 字符串里会被当成转义字符，所以前面加个 `r` 写成原始字符串：

```python
model_path = r"C:\software\chinese_sentiment"   # 换成你自己解压出来的路径
```

要么就写相对路径，比如 `./model/chinese_sentiment`，前提还是那个前提——路径合法。

## 5 文本分类案例：代码与逐段解析

在 `demo10` 目录下新建一个脚本，文件名就叫 `transformers`。这个脚本要实现的是用 transformers 库完成 NLP 常见的六个任务，而库本身有三种写法：管道方式、自动模型、具体模型，三种我们都要学。

### 5.1 导包

```python
import torch
import numpy as np
from transformers import pipeline
```

这三个包没有一个需要我多讲。`torch` 干什么不用说了；`np` 是后面处理数据用的；关键是第三行——`from transformers import pipeline`。注意是 `pipeline`，没有 `s`，不要写成 `pipelines`。

`pipeline` 是 transformers 这个库提供的高级接口，作用是可以快速调用预训练模型，完成常见的 NLP 任务。记住"高级接口"这四个字，它解释了为什么它能几行代码干活：麻烦的部分被封在接口后面了。

### 5.2 创建 pipeline 对象：两个参数

第一个任务，情感分类。函数名就叫 `demo01_text_classification`。

```python
def demo01_text_classification():
    # 参一：任务类型；参二：模型路径
    my_model = pipeline(
        task="sentiment_analysis",
        model=r"C:\software\chinese_sentiment",
    )
```

参一是任务类型。这里填的是 `sentiment_analysis`，也就是情感分析。这个单词是固定写法，不能换——写成别的，接口就不认这个任务。

参二是指定模型的路径。我用的是本地路径，你也可以用相对路径，但路径要合法，规则和上一节说的一样：不能出现中文、空格、特殊符号。

> **易错点**：任务名里的分隔符要看清。`sentiment_analysis` 用的是下划线，而有些任务名用的是中划线（也就是减号）。这两个不是一个字符，写错了就是找不到任务，跟模型没关系。

### 5.3 输入文本与打印结果

模型已经有了，接下来是直接把文本丢进去。

```python
    output = my_model("我爱北京天安门，天安门上太阳升")
    print(f"output: {output}")
```

就这两句。拿到 `my_model` 这个对象之后，把文本当参数传给它，就出结果了——你以为呢，就是这么简单。

它是中文模型，所以拿中文句子去问它。整段函数体一共三行：创建对象、输入文本、打印结果。

```text
   input text
       |
       v
   +--------------------------------------+
   |  pipeline(task, model)               |
   +--------------------------------------+
       |
       v
   [{'label': 'STAR_5', 'score': 0.98...}]
       |
       +--> label 取概率最高的那一档
```

读图说明：文本进来，经过 pipeline 对象，出去的是一个带 `label` 和 `score` 的字典列表，不需要我们再做任何后处理。

> **提示**：运行时控制台可能会刷出一段信息，说它没检索到 GPU、实际走的是 CPU。那是日志，不是警告，更不是报错——只要你切进去的环境里没配好对应的算力，它就会自动兜底到 CPU，所以你会感觉跑得慢。

### 5.4 结果解读与极致压缩

输出里的 `label` 是标签，`STAR_5` 就是五星好评，后面那个 `score` 是分数。

这个分数你可以直接理解成概率：五星好评的概率是多少，四星好评的概率是多少，三星好评的概率是多少，最后选概率最高的那一个返回给你。

那我能不能写得再极致一点？当然能。`output` 是那一堆返回值，`my_model` 是这个对象，那就把上面的一坨直接往里面一扔，在它屁股后面跟个小括号，把文本塞进去，一行搞定：

```python
print(pipeline(task="sentiment_analysis", model=r"C:\software\chinese_sentiment")("我爱北京天安门，天安门上太阳升"))
```

函数不要了，`main` 也不要了。我刚才说"几行代码就能完成一个 NLP 任务"，说的就是这个。我要写六个任务，所以还是老老实实拆成六个函数；只做一件事的话，一行就够。

## 6 模型检索与在线筛选

代码里的模型从哪来？以 Hugging Face 为例，路径是这样的：先进网站，点 `Models`；进去以后在左侧选任务，选中 `text classification`，也就是文本分类；然后在搜索框里输入 `chinese`，它就会把做中文文本分类的模型筛出来。

但直接点进去下模型有个弊端：你得先下载下来才能用。万一下了半天，用起来发现它根本不是我想要的效果，那时间不就白花了？

所以这个网站支持在线测试。点进模型页面以后，里面有个输入文本的地方，你把文本填进去，点一下 `Compute`，它下面立刻给你出结果。旁边还有 `Use in Transformers`，点开可以查看这个预训练模型的下载地址。

> **结论**：先在线测，确认是你要的效果再下载；不是你要的效果就不下。这个顺序能省掉大量无用的下载时间。

我这边演示不了 Hugging Face，因为它要搭梯子，我这里没开，网站刷不出来。那就用魔搭社区看一遍——魔搭是所有人都能玩的。先点模型库，按任务往下找：刚才做的是文本分类，那就在自然语言这一栏里点文本分类。一点进去模型就变了，多了很多；在搜索框里输入 `chinese`，`bert-base-chinese` 直接就出来了。敲回车，接着就是一堆跟中文相关的模型：fasttext 中文的、电商的、中文满意度的、Struct 的中文分类、孪生信息文本分类的七分类、情绪分类、辱骂风险识别、意图识别……

我随便挑一个没玩过的试试，就挑意图识别。点进去可以在线体验，输入"你好，阿里巴巴"，然后等结果。你会看到它调用的写法是 `from modelscope.pipelines`，而不是我们写代码时用的 `from transformers import pipeline`——因为魔搭社区自己写了一个类似 transformers 的库，接口长得像，但不是同一个。

> **提示**：在线体验慢，跟你的电脑没关系，你是在用别人的算力帮你干活。同样的任务，人家给你排队、给你出结果，已经不错了。

## 7 批量推理与迁移学习

有人会问：以前我们做酒店评论，动辄几十条、几百条、几千条，这个 pipeline 一次只处理一句话，能行吗？

那怕啥。写个 `for` 循环，在里面一遍遍地调，把结果打出来就行了。

这个动作有个正规名字，叫迁移学习：拿着别人预训练好的模型，来完成我们自己的任务。

而这个流程里真正决定成败的只有一件事——你模型找没找对。效果达不到预期怎么办？换一个模型。但不能盲目地在网上乱下，先用在线测试筛一遍，测出来达到效果了再下。

## 本讲提到的题目

**题干**：上面这段代码能不能做到极致压缩——只用一个 `print`、一行写完？

**答案**：能。

**解析**：`my_model` 本身就是一个 `pipeline` 对象，`output` 只是它调用的返回值。所以把创建对象的表达式整体挪到调用的位置上，在它后面直接跟一对小括号、把小括号里的文本传进去，就得到了

```python
print(pipeline(task="sentiment_analysis", model=r"C:\software\chinese_sentiment")("我爱北京天安门，天安门上太阳升"))
```

原来的 `output` 变量、外层函数，甚至 `main` 入口都可以不要。之所以最后还是拆成六个函数写，不是因为不能压，而是因为这一讲要跑六个任务，需要保留可读的结构。
