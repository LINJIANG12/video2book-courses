# 用 AutoModelForSeq2SeqLM 做文本摘要：从 inputs 直接喂给 generate 到 decode 出可读结果

这一节的周期和前面几个任务思路是同一个：定义模型名、加载分词器和模型、处理输入、让模型预测、把预测结果转成能读的文字。所以流程本身不用重新讲一遍，真正值得看的是这条链路上的两个"转换"动作 —— 输入端怎么把英文文本交给分词器，输出端怎么把一串编号变成人话。

任务本身先说清楚：**文本摘要（Text Summarization）** 就是输入一段文本，输出这段文本的概况或简短说明。我们这次输入的是笔记里那段介绍 BERT 模型预训练方法的英文材料。

## 1 模型与分词器的加载

第一步，定义输入文本。

```python
from transformers import AutoTokenizer, AutoModelForSeq2SeqLM
import torch

# 第 1 步：定义输入文本（一段关于 BERT 预训练方法的英文介绍）
text = "..."   # 内容取自笔记里的英文材料，整段贴进来
```

第二步，记录模型名并加载对象。这次用的是 BART：

```python
# 第 2 步：定义变量记录模型名
model_name = r"C:\software\develop\src\talk\bart-large-cnn"

# 第 3 步：加载分词器对象和模型对象
my_tokenizer = AutoTokenizer.from_pretrained(model_name)
my_model = AutoModelForSeq2SeqLM.from_pretrained(model_name)
```

这里加载模型用的类是 `AutoModelForSeq2SeqLM`。摘要属于序列到序列的任务，输入一条序列、输出另一条序列，所以入口要选 `Seq2SeqLM` 这一支，而不是前面完形填空、阅读理解用的那几支。

## 2 输入端：英文文本为何可以直接交给分词器

第四步，把输入文本转成模型可接受的格式。

```python
# 第 4 步：将输入文本转成模型可接受的输入格式
inputs = my_tokenizer(text, return_tensors="pt")
print(inputs)
```

这一步是这一节最容易被质疑的地方：前面几个任务写成 `encode_plus(...)`，这里怎么就直接 `my_tokenizer(text)` 了？

> **提示**：因为我们这里处理的是**纯英文**文本，不需要额外做编码那一步，所以可以直接把文本交给分词器。这是一个小技巧，不是随意的简写。

那要是记不住什么时候该用哪个呢？记不住就去官网转一圈。官网的模型页里通常带着测试用例和 API 示例，打开看一眼，照着它的调用方式写就行。

`return_tensors="pt"` 这一句的作用是返回 PyTorch 张量。注意这里的张量是**二维**的，外层带批次维度。

## 3 推理端：generate 与 input_ids 的单独传入

第五步，把输入喂给模型拿预测结果。分两小步：

```python
# 第 5 步：喂给模型，获取预测结果
my_model.eval()                                  # 5.1 切换到评估模式
outputs = my_model.generate(inputs["input_ids"]) # 5.2 模型预测
print(outputs)
```

这里有一个刻意的取舍：`inputs` 里不止一个键，但我们**只传 `input_ids` 一个**。

```python
# 错误写法示意：把整个 inputs 都铺开传进去
outputs = my_model.generate(**inputs)
```

后者会把 `input_ids`、`attention_mask` 全都传进去，而对我们这次要演示的东西来说，多传的参数是不需要的。所以只取 `inputs["input_ids"]`，明确地只传这一个。这也是 `inputs` 用字典存的原因 —— 想取哪个键，就取哪个键。

## 4 输出端：从 convert_ids_to_tokens 到 decode

第六步，把预测结果打印出来，也就是把文本摘要转成可读的形式。这里的动作分两层，先看第一层。

```python
# 第 6 步：打印预测结果
print(my_tokenizer.convert_ids_to_tokens(outputs[0]))
```

`outputs` 是一个二维张量，外层是批次。`outputs[0]` 取的就是里面那一行编号，也就是模型生成的答案的编号序列。

`convert_ids_to_tokens` 这个操作前面见过，它的能力边界很清楚：**只能把 id 还原成 token**。跑出来你会看到一串带着特殊标记的东西 —— 这就是它给我们的输出，但你确实看不懂。

那就得再往下解码一层：

```python
print("".join([my_tokenizer.decode(g, skip_special_tokens=True,
                                  clean_up_tokenization_spaces=True,
                                  tokenization_spaces=True)
               for g in outputs]))
```

逐个参数解释：

| 参数 | 取值 | 含义 |
| --- | --- | --- |
| `skip_special_tokens` | `True` | 跳过特殊标记，即去掉 token 前后的特殊字符 |
| `clean_up_tokenization_spaces` | `True` | 是否清理分词遗留的空格 |
| `tokenization_spaces` | `True` | 是否保留原始分词的空格 |

`for g in outputs` 里的 `g` 就是 `outputs` 里的每一个数值序列。对它逐个 `decode`，再把结果拼起来，上面那串看不懂的编号就变成了可读的摘要。

把 `skip_special_tokens` 从 `True` 改成 `False`，输出里立刻会多出 `<s>` 这样的标记。这正好说明这个参数在干什么：不做处理的话，词与词之间多余的空格、以及这一堆特殊标记，都会给你留在结果里。

> **易错点**：`convert_ids_to_tokens` 出来的是 token，不是给人读的句子。到这一步必须再走一次 `decode`，否则你打印出来的永远是那串编号。

## 5 完整流程与 decode 参数对照

```text
text（一段关于 BERT 预训练方法的英文介绍）
        │
model_name → AutoTokenizer.from_pretrained        → my_tokenizer
           → AutoModelForSeq2SeqLM.from_pretrained → my_model
        │
my_tokenizer(text, return_tensors="pt")  → inputs（含 input_ids 等键）
        │
my_model.eval() → my_model.generate(inputs["input_ids"])
        │
outputs（生成的编号序列）
        │
convert_ids_to_tokens(outputs[0])   ← 只到 token，读不懂
        │
my_tokenizer.decode(g, skip_special_tokens=True,
                    clean_up_tokenization_spaces=True,
                    tokenization_spaces=True)
        │
可读的摘要文本
```

读图说明：整条链路只有一处真正的"生成"动作 —— `generate`，其余全是格式转换：进去之前把文本转成编号，出来之后把编号转回文本。真正决定输出好不好读的，是最后那次 `decode` 的三个布尔参数。

整节走下来就这么几件事：先定义模型，再定义分词器和模型对象，然后处理输入、让模型生成预测，最后做一次转换把结果落到可读文本上。

## 6 BPE 与这一节里两种转换的分工

最后补一句需要稍微费点脑子的扩展。分词器内部是怎么切词的？这里涉及一个算法叫 **BPE（Byte-Pair Encoding，字节对编码）**，本质就是切词。

这件事为什么值得单独记住：**GPT 底层用的就是 BPE 切词**。

也正因为底层的切词单位不一定是"一个完整的词"，所以 id 和文字之间才需要两次不同的转换，各管一段：

| 转换方法 | 方向 | 用途 |
| --- | --- | --- |
| `convert_ids_to_tokens` | id → token | 把编号还原成 token 文本，中间产物，人不易读 |
| `decode` | id → 可读字符串 | 连跳过特殊标记、清理空格一起做完，输出给人看 |

> **结论**：`convert_ids_to_tokens` 是中间步骤，`decode` 才是终点。做摘要、做生成类任务时，能直接用 `decode` 就别停在 `convert_ids_to_tokens`。
