# 词向量的取出与 TensorBoard 投影可视化

词向量已经拿到手了，接下来要对它做一件事：可视化。不过先把丑话说在前面，这一讲的内容是分两半的——**上面那一坨"怎么拿到 word embedding、怎么把每个词的词向量取出来"，是要求掌握的；后面那一堆接 TensorBoard 做可视化界面的操作，了解就行**。所以下面按这个分量来读：前半段要能自己默写出来，后半段知道流程、能把它跑起来就够了。

## 把词向量矩阵交给 TensorBoard

第一件事是造一个写入器。TensorBoard 那个对象本质上就是个写入器，专门负责把我们要看的数据写进日志目录，目录由 `log_dir` 指定，这里给 `./runs`：

```python
from torch.utils.tensorboard import SummaryWriter

my_summary = SummaryWriter(log_dir='./runs')
```

马上有人要问：现在当前目录底下有 `runs` 这个文件夹吗？没有。那要不要自己先建一个？不用，它会自动帮你创建，你的记录写到这儿就行了。

写入器有了，第二个动作是**把词向量和它对应的词语一起添加进去**，靠的方法是 `add_embedding`：

```python
my_summary.add_embedding(embed.weight.data, my_token_list)
```

这个方法就两个参数，含义必须说清楚：

> **定义**：`add_embedding(词向量矩阵, 词语列表)`。第一个参数是词向量矩阵，形状是 `(20, 8)`——**20 个词，每个词用 8 个数字表示，也就是每个词是 8 维**；第二个参数是对应的词语列表，作用是用来**标注投影图上的每一个点**。

第二个参数为什么非得给？因为一会儿那个界面上会出现很多很多小点，光有点你根本不知道谁是谁。那 20 个点指的就是 `my_token_list` 里那 20 个词——它就是前面从分词结果里取出来的那 20 个词。点有了标签，图才读得懂。

最后一步收尾，把写入器关掉：

```python
my_summary.close()
```

> **提示**：这三步（创建写入器 → `add_embedding` → `close`）属于"了解"级别的内容，把它当成标准流程记住即可。真正要掌握的是上一节拿到 `word embedding` 词向量矩阵的那套动作，以及下面这一段逐词取向量。

## 遍历索引取出每个单词的词向量

现在换个角度：我不看整张矩阵，我想一个一个词地看，每个词自己的词向量到底长什么样。做法非常直接，用一个 `for` 循环：

```python
for index in range(len(my_tokenizer.word_index)):
    print('-' * 10, f'当前索引 {index}', '-' * 10)
    temp_vector = embed(torch.tensor(index))
    print(f'词向量: {temp_vector}')
```

`range` 里的长度为什么写成 `len(my_tokenizer.word_index)`？前面打印过 `my_tokenizer.word_index`，它就是一个字典，里面**正好 20 组键值对**，所以 `len` 出来就是 20。你想省事也可以直接写死 20，或者干脆用 `my_token_list` 的长度——刚才取 `my_token_list` 的时候它也是 20 个词，这几个写法都对。

> **提示**：`range(20)` 给的是 0 到 19，一共 20 个数，**包左不包右**。

这个 `index` 怎么变成词向量的？看这一句：

```python
temp_vector = embed(torch.tensor(index))
```

把当前的 `index` 用 `torch.tensor` 包成一个张量丢进 `embed`，它就把对应的词向量取回来了。循环里我还加了一条 `'-' * 10` 的分割线打印，目的纯粹是**跟上面那一段输出隔开**，观察起来清爽一点。

跑一下，从分割线往下看：这是第一个词的词向量，这是第二个词的……**数一数，1、2、3、4、5、6、7、8，正好 8 个数**。所以每个词的词向量全在这里边，一共 20 个词，每个词 8 维，跟上面那个 `(20, 8)` 完全对得上。

## 索引反查单词：index_word 与那个加 1

光有向量不够，我还好奇：**当前这个索引，对应的是哪个单词**？逆着查回去就行：

```python
word = my_tokenizer.index_word[index + 1]
```

这里有两个点必须讲透，不然这一段必晕。

第一个点：`tokenizer` 这个词汇映射器**不只有单向映射，它是双向的**。

| 属性 | 键（key） | 值（value） | 方向 |
| --- | --- | --- | --- |
| `word_index` | 单词 | 索引 | 单词 → 编号 |
| `index_word` | 索引 | 单词 | 编号 → 单词 |

`word_index` 是单词做键、索引做值，所以叫 word to index；`index_word` 正好反过来，索引做键、单词做值，所以叫 index word。这两个它都有——这正是我们要用这样一个 `tokenizer` 的原因：它既能把你句子里的词映射成编号，也能基于编号**反向映射回词**。

第二个点就是那句 `+ 1`。

> **易错点**：`index_word` 里面的编号是**从 1 开始**的，而你 `for` 循环里 `range` 出来的索引是**从 0 开始**的。两边起点不一样，所以取的时候必须加 1，写成 `index + 1` 才对得上。

这个操作你以前没见过，所以别急着背，直接把两个字典打印出来对着看一遍，一眼就明白了：`word_index` 是"词 → 号"，`index_word` 是"号 → 词"，同一批词同一批号，只是摆的方向相反。

## 张量转 NumPy 之前先 detach

把单词和词向量一起打出来：

```python
print(f'单词: {word}  词向量: {temp_vector.detach().numpy()}')
```

`temp_vector` 直接打印出来是个张量形式，看着不直观，习惯上转成 NumPy 数组。但这里**不能直接 `.numpy()`**：

> **易错点**：这个张量在参与计算的时候，底层经过了反向传播、带着自动微分的信息，直接转 NumPy 有可能报错。正确写法是先 `.detach()` 把它从计算图里摘出来，再 `.numpy()`。

跑起来之后控制台里就能看到结果了，比如"是"这个词，它的词向量是这么一串；"黑马"这个词，词向量是这么一串；"我"、"传智"……20 个词挨个排下来，每个都跟着 8 个数字。

## 启动 TensorBoard 看投影图

代码写完了，控制台里只有一行行数字，那个可视化界面在哪儿？它在 TensorBoard 里，按下面四步走就能打开。

第一步，进到 `nlp_base` 这个沙箱。要么从 Anaconda 那边选进去，要么在 PyCharm 的终端里直接敲：

```bash
conda activate nlp_base
```

第二步，切到**有 runs 文件夹的那个目录**。你的 `runs` 不在 day01 里，它在 day02 这个项目下，所以先回上一级、再进 day02：

```bash
cd ..
cd day02
```

第三步，运行这条命令：

```bash
tensorboard --logdir runs --host 0.0.0.0
```

`--logdir` 后面跟的日志路径就是刚才那个 `runs`；`--host` 后面写四个 0 就行，**注意 host 后面没有等号**。

第四步，用本地地址访问：

```text
http://localhost:6006
```

端口号看它给你的那个 6006。为什么不点它打印出来的那个链接？因为 `--host` 写的是 `0.0.0.0`，它给出的 URL 里带的就是 `0.0.0.0`，你直接点开是看不懂的，把主机名换成 `localhost` 或者 `127.0.0.1` 就对了。

> **注意**：第一次打开大概率看到 "No dashboards are active for the current data set"，这不是出错了，它正在做映射。稍微等个一两分钟，刷新一下，图就出来了。心急吃不了热豆腐，别刚敲完回车就判定"没数据"。

要关掉它的时候，`Ctrl+C` 就行。这种后台服务的开和关都得等一会儿，别急着反复敲。

## 投影图里能读到什么

图出来之后就是一片花花绿绿的点，看着很炫。说句实话，这属于"不明觉厉"——不明白，但是觉得很厉害。**它本质是一张 PCA 主成分分析图**，感兴趣可以自己去搜 `PCA` 主成分分析看看是什么东西。

这个界面里的每一件事都对应我们上面写的代码：

- 左上角写着 **points 20、dimension 8**——一共 20 个单词，每个单词是 8 维，跟 `add_embedding` 第一个参数的形状一模一样；
- 随手点一个点，比如 12，底下立刻列出**除它以外剩下 19 个点到它的距离**，也就是这些词跟"12 号词"的相似度；
- 光标在点上移动的时候，这些距离一直在变，因为它每次都按当前这个点重新算；
- 换个点，比如 20、比如 5，列出来的就是"其他点到它"的距离；
- 想让它转起来看整体分布，去左上角点 `reset`（重置）；
- 想找某个点，比如记得有个 3，就去搜索框里输入 `3`，它会把 3 和 13 这些含 3 的点一起高亮出来。

所以这个界面干的事就一句话：**帮你算词与词之间的距离、相似度**。随便点一个样本，它到其他词的距离关系就在这儿给你摊开看。

## 从句子到投影图的完整流程

把这一讲前面所有动作串一遍，就是下面这条链路：

```text
两个句子
   │  放进一个列表
   ▼
jieba 分词 ──► 得到 20 个单词
   │
   ▼
tokenizer 词汇映射器 ──► 建立 词 → 索引 的映射字典
   │                    （word embedding 只认编号，不认文本）
   ▼
把句子里的文本全部替换成索引
   │
   ▼
Embedding 层 ──► 词向量矩阵 (20, 8)
   │
   ▼
add_embedding(词向量矩阵, 词语列表) ──► 写入 ./runs
   │
   ▼
tensorboard --logdir runs --host 0.0.0.0
   │
   ▼
http://localhost:6006  ──► PCA 投影图，观察词向量的相似性
```

读图说明：文本先要变数字、再变张量，然后才能生成词向量；词向量矩阵和词语列表一起交给 `SummaryWriter` 对象写进 `runs` 目录，最后通过 web 地址把 PCA 投影图调出来看相似性。

记住这条链路里最关键的那一环：**word embedding 只能把编号映射成词向量，它映射不了文本**。所以中间必须有那个"构建词和索引映射关系"的字典，跳过它后面全断。

## 本讲提到的题目

**题干**：有一批伪样本，给定一个张量

$$my\_tensor = \begin{bmatrix} 1 & 2 & 3 & 4 \\ 4 & 5 & 6 & 20 \end{bmatrix}$$

现在要把它喂给一个词嵌入层（要求 100 个词、每个词 256 维）。请问：`my_tensor` 本身的形状是多少？经过这个词嵌入层处理之后，形状又变成多少？

**解析**：

先看 `my_tensor`，它就是中括号套中括号，第一行 `1 2 3 4`，第二行 `4 5 6 20`，所以它是二维的，形状是 `(2, 4)`——2 行 4 列。

再看词嵌入层要什么：100 个词、每个词 256 维。这一层的作用是**把你里边的每一个索引映射成一个 256 维的向量**。`my_tensor` 的形状是 `(2, 4)`，那么它会逐元素替换：每一行、每一列上那一个位置，都变成 256 个数。所以处理后的形状是：

$$(2,\ 4,\ 256)$$

**答案**：`my_tensor` 是 `(2, 4)`，处理完之后是 `(2, 4, 256)`。

代码写出来是这样（直接跑这段会报错，原因在下面）：

```python
import torch
import torch.nn as nn


def dm02():
    my_tensor = torch.tensor([[1, 2, 3, 4], [4, 5, 6, 20]])
    print(my_tensor.shape)          # torch.Size([2, 4])

    my_embed = nn.Embedding(100, 256)
    my_tensor_embed = my_embed(my_tensor)
    print(my_tensor_embed.shape)    # torch.Size([2, 4, 256])


if __name__ == '__main__':
    dm02()
```

> **易错点**：这段代码直接照抄跑会报错，因为 `torch` 和 `torch.nn as nn` 都没导包。导包动作要写在函数**外面**，也就是文件最上面那个位置，然后再跑。
