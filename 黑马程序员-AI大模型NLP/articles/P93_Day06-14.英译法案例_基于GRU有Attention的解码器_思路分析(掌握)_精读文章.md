# 带注意力机制 GRU 解码器的结构分析与张量形状推导

无注意力的解码器我们已经写完也测通了。现在把同一个解码器**加上注意力机制**重讲一遍。这一讲的落点还是思路：先把结构图上每条线、每个张量的形状都标注清楚，代码只是照图抄一遍。所以这一篇的重点不在"怎么写"，而在"**为什么每条线的形状必须长这样**"。

先把无注意力版和带注意力版的结构图并排放在一起看，你能一眼看出差别就在中间那几根新增的线上。

---

## 从无注意力版到带注意力版

无注意力版和带注意力版都是 sequence to sequence（序列到序列）架构，也就是"句子到句子"的架构。两者的编码器完全相同，差别全部落在解码器内部。

上图是无注意力版，下图是带注意力版。带注意力版多出来的动作是：把解码器的本次输入 `Q` 和编码器的输出 `K` 做拼接、算权重、再拿权重去乘 `V`，最后把结果和 `Q` 融合一遍。这就是注意力的全部。

顺带留个记录：前面测试无注意力解码器那一版的打印结果也值得留着，回头对着看会很省事——它给出了每一层的真实维度，是后面推形状的参照系。

---

## Q、K、V 各自是谁、形状多大

有注意力机制，就必然有 Q、K、V 三个角色。三者的分工是：

- **Q（Query，查询）**：查询的问题，就是解码器本次的输入；
- **K（Key，键）**：被查询的对象，来自编码器的输出；
- **V（Value，值）**：与 K 一一对应的内容，同样来自编码器的输出。

> **结论**：Q 一定是"你输入进来的那个东西"。你要拿一个查询去问别的位置，输入自然就是 Q。所以三个张量里第一个就是 Q。

形状方面：

| 角色 | 形状 | 含义 |
| --- | --- | --- |
| Q | `(1, 1)` → `(1, 256)` | 解码器本次输入的那一个词 |
| K | `(1, 10, 256)` | 编码器输出，10 个位置、每位置 256 维 |
| V | `(1, 10, 256)` | 与 K 同形状 |

`Q` 为什么是 `(1, 1)`？因为它就是从目标句子里取出的**一个标量**，再用 `view(1, -1)` 转成一行一列的形状。`K` 和 `V` 为什么中间的维度是 10 而不是 6、7、9 或 13？这是本讲最关键的一个坑，下面单独讲。

---

## 从词嵌入到注意力计算

带注意力版解码器的前半段，和无注意力版几乎一样：词嵌入层把输入的标量转成词向量，接着过一个 **dropout 层**做随机失活，然后进注意力计算。

```text
      Q (1, 1)                        K (1, 10, 256)
         │                                   │
         ▼                                   │
   embedding(4345 → 256)                     │
         │                                   │
         ▼                                   │
      dropout                                │
         │                                   │
         ▼                                   │
   embedded (1, 256)                         │
         │                                   │
         └───────────────┬───────────────────┘
                         ▼
                       attn
                         │
                         ▼
                    (1, 1, 10)      ← 权重分布
```

读图说明：Q 从 `(1, 1)` 出发，经词嵌入变成 `(1, 256)`，再经 dropout 排出过拟合；K 保持 `(1, 10, 256)` 原样进入注意力；两者在 `attn` 处汇合，算出一个长度 10 的权重分布。

### 注意力计算的运算规则

注意力的运算顺序是固定的四步：

$$\text{attn\_weights} = \text{Softmax}\big(\text{Linear}([Q; K])\big)$$

$$\text{attn\_applied} = \mathbf{bmm}\big(\text{attn\_weights},\ V\big)$$

用文字说就是：**Q 和 K 先做拼接，外面套一个 Linear，最外层再套一个 Softmax，最后拿这个结果去乘 V**。所以只要看到拼接，就意味着形状要在这一维上翻倍：`(1, 256)` 和 `(1, 10, 256)` 拼起来，出现的是 `512`。

### 拼接后的形状与 Linear 的转换

拼接动作落在 `attn` 这一步。它的本质是：**把 Q 和 K 拼接后的结果做一次全连接层变换**。

```text
 Q (1, 256)  ─┐
              ├─ 拼接 ─► (1, 10, 512) ─ Linear ─► (1, 10, 1) ─ Softmax ─► (1, 10)
 K (1, 10, 256)┘
```

读图说明：Q 在 10 个位置上被复制展开，和 K 逐位置拼接成 `(1, 10, 512)`；Linear 把 512 压成 1，得到每个位置的打分 `(1, 10, 1)`；Softmax 把打分归一化成权重 `(1, 10)`。

这里会看到 `(1, 1, 512)` 这样的中间形状——它出现的原因就是 Q 和 K 在拼接，说明这两条线并到了一起。

接着是 Softmax。Softmax 的作用是把值**压成概率**：这里就是要算出对每个词的注意力概率。概率分布在几个词上？本来是你的 6 个词，但这里写的是 10 个——**因为要统一长度**。

> **注意**：Softmax 之后还会经过一个激活函数，形状不变、只改变值，所以还是 `(1, 10)`；后面乘的那个权重是常量，算完形状也还是 `(1, 10)`。

这 10 个位置上的权重到底在表达什么？它表达的是：**生成这个 Q 的时候，我分别有多依赖编码器的第 1 个词、第 2 个词……第 10 个词**。是更依赖第一个，还是第二个，还是第三个——权重大的位置，就是这次生成主要参考的位置。

---

## 最大长度 10：补齐与截断

为什么是 10 而不是 6？因为**一开始就设定了句子的最大长度是 10**。这就是那个"定义了却一直没用"的变量，到这一步终于用上了。

```text
英文句子长度       进入注意力前统一为
     6      ──►        10
     7      ──►        10
     9      ──►        10
    13      ──►        10（截断）
```

读图说明：不管原始句子是 6 个词、7 个词还是 13 个词，到这里统统变成 10。不够的用 0 补齐，超出的截断——专业名称叫**截断和补齐**。

**为什么必须统一？** 因为如果它是 `(1, 6)`、`(1, 7)`、`(1, 9)` 这样一直变，下面那几层的矩阵乘法就没法与它配合，整个计算根本进行不下去。只有长度固定为 10，后面的运算才能统一算。

于是 Q 侧的中间表示也要跟着对齐：原来 `(1, 6, 256)` 的编码器输出，到这一步要变成 `(1, 10, 256)`。即使原始句子是 13 个词，到这里也还是 10。

> **易错点**：`(1, 6, 256)` 变 `(1, 10, 256)` 这一步**不经过任何线性层**，形状是直接改写出来的，得由你在代码里显式做到。不做这一步，`(1, 10)` 的权重就没法和 `(1, 6, 256)` 相乘。

---

## 注意力权重与 V 的相乘

`bmm` 是批量矩阵乘法。现在两边的形状是 `(1, 10, 256)`（V）和 `(1, 10)`（权重），这两个形状还不能直接乘，需要先把权重调整好——就是前面说的、把编码器输出的形状改成 `(1, 10, 256)`，让两者对齐。

对齐之后相乘：

$$\text{attn\_applied} = \mathbf{bmm}(\text{weights},\ V)$$

形状是 `(1, 1, 10)` 与 `(1, 10, 256)` 相乘 → `(1, 1, 256)`。

`(1, 1, 256)` 就是加权求和之后的结果——按注意力权重把 10 个位置的 256 维向量混合成一个 256 维向量。

---

## 注意力结果与 Q 的融合

`attn_applied` 拿到 `(1, 1, 256)` 之后，还有一步融合：**把第一步算出来的结果和 Q 再做一次拼接**。

为什么还要拼 Q？因为注意力算出来的是"从编码器那边取回来的信息"，而 Q 是"我现在要生成什么"的原始诉求。把两者拼在一起，模型才能同时看到"我问的什么"和"我取回了什么"。

```text
 attn_applied (1, 1, 256) ─┐
                            ├─ 拼接 ─► (1, 1, 512) ─ Linear ─► (1, 1, 256)
 Q (1, 1, 256) ─────────────┘
```

读图说明：`attn_applied` 和 Q 在最后一维上拼接成 `(1, 1, 512)`，再经过 `attn_combine` 的 Linear 重新换回 `(1, 1, 256)`。

拼接之后是 `(1, 1, 512)`，但这个 512 维**和后面的层没法接**——后面的 GRU 只吃 256 维。所以要用 `attn_combine` 把它换回 256 维。

> **提示**：只要是神经网络层，就能改变形状——它的本职就是"一个输入、一个输出"，形状变换本来就是它的工作。而激活函数（比如 ReLU）只改值、不改形状。这个区别在推算形状时非常有用：看到形状变了，往回找**一层神经网络**；看到形状没变，那多半是激活函数。

所以 `attn_combine` 这一步干的事很清楚：**按注意力计算步骤来看，第一步是拼接（Q 与 K 拼、算出 attn_weights），第二步则是把 Q 与第一步的计算结果拼接，再经历 Linear 做线性转换**，把 `(1, 1, 512)` 转成 `(1, 1, 256)`。

---

## 汇入 GRU 与输出层

融合之后的 `(1, 1, 256)` 进 GRU。GRU 那条线是从解码器的隐藏状态过来的，形状也是 `(1, 1, 256)`。

GRU 处理完会返回两个东西：**本次的隐藏状态和本次的输出**。这两者形状都是 `(1, 1, 256)`。

```text
 attn_combine (1, 1, 256) ──┐
                             ├──► gru(512 → 256) ──► output  (1, 1, 256)
 隐藏状态 (1, 1, 256) ───────┘                   └──► hidden  (1, 1, 256)
                                                          │
                                                          ▼
                                                 out: Linear(256 → 4345)
                                                          │
                                                          ▼
                                                    (1, 4345)
                                                          │
                                                          ▼
                                          代表预测每一个法文单词的概率
```

读图说明：`attn_combine` 的输出和隐藏状态一起进 GRU，GRU 同时返回本次输出和本次隐藏状态；输出经过 `out` 线性层从 256 维映射到 4345 维，这 4345 个值分别代表**预测每一个法文单词的概率**，取其中最大的那个就是本次预测出的词。

`out` 输出的形状是 `(1, 4345)`——这一步在无注意力版里也出现过，是同一个输出层。

---

## 整张结构图的完整数据流

把所有动作按代码执行顺序串起来，就是下面这一趟：

```text
 Q (1, 1)
    │
    ▼
 embedding(4345 → 256)
    │
    ▼
 dropout
    │
    ▼
 (1, 256)  ─────────────────────────┐   ← Q 侧
                                    │
 K (1, 10, 256) ─ 展成 (1, 10, 256) ┤
                                    ▼
                          attn：拼接 → Linear → Softmax
                                    │
                                    ▼
                              (1, 10) 权重
                                    │
                        bmm(权重, V (1, 10, 256))
                                    │
                                    ▼
                            (1, 1, 256)  attn_applied
                                    │
                     ┌──────────────┘
                     ▼
      与 Q (1, 256) 拼接 → (1, 1, 512)
                     │
                     ▼
       attn_combine：Linear(512 → 256)
                     │
                     ▼
              (1, 1, 256) ──┐
                             ├──► gru(512 → 256) ──► (1, 1, 256)
       隐藏状态 (1, 1, 256) ─┘
                             │
                             ▼
                  out: Linear(256 → 4345)
                             │
                             ▼
                        (1, 4345) 概率
                             │
                             ▼
                     取概率最大的一个词
```

读图说明：整条链路上，形状变换只发生在三个地方——注意力里的两次拼接加 Linear、`attn_combine` 的 Linear、`out` 的 Linear；其余位置（dropout、ReLU、Softmax）形状一律不变。

按代码顺序数，这条链路上有四个核心动作：

1. 词嵌入层：把标量形式的词索引转成 `(1, 256)` 的词向量；
2. 注意力计算：Q 与 K 拼接、Linear、Softmax，得到权重，再与 V 相乘；
3. `attn_combine`：第一步的计算结果与 Q 拼接，再经 Linear 换回 256 维；
4. GRU 后面的 `out`：把 256 维映射成 4345 个法文单词的概率。

> **结论**：`embedding` 做词嵌入，中间的 `attn` 与 `attn_combine` 把"编码器信息"按权重取回来并融合进本次输入，`out` 负责输出每个法文单词的概率——这三件事分工清楚，形状就一定是上面这样，不会变。
