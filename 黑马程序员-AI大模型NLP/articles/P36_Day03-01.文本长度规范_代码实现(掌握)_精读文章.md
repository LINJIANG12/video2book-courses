# 文本长度规范：序列截断与补齐的两种实现

先看一个再常见不过的场景。这一批我送 8 句话进模型，也就是 8 个样本，结果第一句长度 10、第二句 13、第三句 9、第四句 11……你要这么玩就没得意思了：后边根本没法生成对应的矩阵，我们的维度没有办法去写。模型要的是一块规规整整的矩形，而不是一排长短不一的木条。

所以批量数据在喂给模型之前，必须先把长度统一起来。这个过程就是**文本长度规范**：假定长度定为 10，超过 10 的做截取，不够 10 的做补齐。这两个动作都有专业名词，别用错：

> **定义**：把超长文本裁到目标长度的操作叫**截断**；把不足目标长度的文本填到目标长度的操作叫**补齐**。补齐时一般默认补 0。

思路就这么简单，关键在代码怎么写。我们在 PyCharm 里新建 `demo03` 项目，解释器选一直用的 `nlp-base` 环境，再新建脚本 `demo01`，案例名叫"演示文本长度规范案例"。写代码之前，先把这段解释注释在文件头上：

```python
'''
文本长度规范解释：
1. 概述：一般模型的输入需要等尺寸大小的矩阵，
   所以需要对超长文本做截断，对不足文本做补齐，这就是文本长度规范。
2. 实现方式：
   方式一：第三方包 tensorflow.keras.preprocessing 里的 sequence
   方式二：纯 Python 代码实现
'''
```

两个方式我都写一遍。用 keras 那个包的时候会刷出一堆警告，看着烦；那我不借你这个工具，只用 Python 自己做，能不能做出来？也能。

## 1. 目标长度 cut_len 的确定依据

第一个变量就是截断和补齐的长度参数：

```python
cut_len = 10
```

为什么整 10，不整 20？这不是拍脑袋定的。回想之前讲文本数据分析时那个句子长度分布的案例——先去看看你的语料库里句子长度大概集中在什么水平，再据此设定这个值。

> **提示**：`cut_len` 是超参数，不是随手写的魔法数字。定大了浪费计算、稀释有效信息，定小了会把长句子的后半段直接切掉。实际开发中一定要根据语料库的句子长度分布来自行设定。

配套的数据也要准备。下面这两组数字你可以理解成"文本切完词以后，每个词对应的索引"：

```python
x_train = [
    [1, 2, 3, 5, 32, 55, 63, ...],   # 长度大于 10，需要截断
    [2, 32, 1, 2, 3]                 # 长度不足 10，需要补齐
]
```

第一句话的长度大于 10 个词，所以要截断；第二句话不够 10 个词，所以要补齐。你自己编数据完全可以，但为了保证效果明显，准备的句子里**最好既有大于 10 的，也有小于 10 的**——至于谁在前面谁在后面，无所谓，翻个顺序照样跑。

## 2. 方式一：sequence.pad_sequences

### 2.1 导包与函数实现

第三方包的方式只需要一个 API：

```python
from tensorflow.keras.preprocessing import sequence


def padding(x_train):
    return sequence.pad_sequences(x_train, maxlen=cut_len)
```

这里先不搭理编辑器报出的那一批警告，把功能写完再说。有同学会问：参数里是不是还有别的词？有，`truncating` 和 `padding` 这两个，控制截断和补齐到底从哪一头下手。我先用默认值把结果跑出来，再换值对比。

### 2.2 四个参数：文本张量、最大长度、截断策略、填充策略

按位置一个个认：

| 位置 | 参数 | 含义 |
| --- | --- | --- |
| 参 1 | 位置参数 | 待处理的文本张量（这里是 `x_train`） |
| 参 2 | `maxlen` | 最大长度，也就是截断与补齐的目标长度 |
| 参 3 | `truncating` | 截断策略，默认 `pre` |
| 参 4 | `padding` | 填充策略，默认 `pre` |

参 3 的取值就两个单词，含义完全对称：

| 取值 | 截断策略 `truncating` | 填充策略 `padding` |
| --- | --- | --- |
| `pre`（默认） | 从序列前端截掉多余元素，保留尾部 `maxlen` 个 | 0 补在序列前端 |
| `post` | 从序列后端截掉多余元素，保留最前 `maxlen` 个 | 0 补在序列后端 |

> **易错点**：`truncating='pre'` 不是"保留前 10 个"，而是"从前端把多余的截掉"，结果是把后面 10 个留下来。这一点刚接触时容易绕：你想留前面那几个，恰恰要把后端的截断——那对应的取值是 `post`，不是 `pre`。

记不住就按这个办法记：`pre` 管的是前面，多了就删、少了就填；`post` 管的是后面，多了就删、少了就填。一句话，方式而已。

### 2.3 默认值验证与 pre/post 实测对比

先写测试代码：定义变量记录文本信息、调用函数接住结果、打印处理后的内容。

```python
if __name__ == '__main__':
    result = padding(x_train)
    print(f'result: {result}')
```

第一次运行时我先什么都不传，让两个策略都用默认值，看看截断到底截的是哪一头：

```text
超长样本（长度 > cut_len，truncating='pre'）
  [ 1  2  3 ... 前端这些被截掉 ... ] [ 尾部保留 10 个，从后面的 5 开始 ]

不足样本（长度 < cut_len，padding='pre'）
  [ 0  0  0 ... 0 ] [ 原始元素 2 32 1 2 3 ]
```

读图说明：默认策略下，第一个样本从序列前端截下去，保留下来的尾部从后面的 `5` 开始；第二个样本因为不够 10 个，在前端补了若干个 0，所以打印出来的开头是一串 0。

把这两种默认效果记下来，然后我把 `truncating` 和 `padding` 都显式写成 `pre` 再跑一次——数字完全一样。这就验证了 `pre` 确实是默认值，不写和写 `pre` 等价。

接着把这两个参数都换成 `post`：

```python
def padding(x_train):
    return sequence.pad_sequences(x_train, maxlen=cut_len,
                                  truncating='post', padding='post')
```

再跑一遍，结果就反过来了：第一个样本变成了 `1 2 3 ... 一直到 32` 这一段，也就是把后面的内容截掉了；第二个样本则是在后面补 0。所以选择哪种策略，取决于你认为一句话的哪一头更值钱——如果句子开头是主谓宾主体、结尾是修饰补充，保留前面 `post` 更合适；反过来就选 `pre`。

### 2.4 运行日志的压制

用 `tensorflow.keras` 时控制台会被警告刷满，看着难受就压掉它。在导入之前设置环境变量即可：


这个变量控制 TensorFlow 输出日志的级别，值越大过滤得越狠，设到 `3` 之后那些提示与警告就不再往外刷了。

## 3. 方式二：纯 Python 实现

不借助任何第三方 API，只用 Python 的基础语法把截断和补齐做出来。函数的骨架是五步：初始化列表、遍历语料库、处理超长文本、处理不足文本、返回处理后的列表。

```python
def padding_custom(x_train):
    list1 = []
    for value in x_train:
        ...
    return list1
```

`list1 = []` 就是初始化一个空列表，用来装处理完的结果。`for value in x_train` 是遍历语料库取出每一个句子——注意它是**一个句子一个句子单独传进来**处理的，不是整批一起进来。

### 3.1 超长文本的截断

如果句子的长度大于 `cut_len`，说明它超长了，要截断，然后再把截出来的结果追加进列表：

```python
        if len(value) > cut_len:
            list1.append(value[:cut_len])
```

`value[:cut_len]` 是什么？它是从左边界取到 `cut_len`，从 0 开始、到 `cut_len` 结束，包含 0 不包含 `cut_len`，也就是索引 0 到 9，正好 10 个元素——前 10 个就拿到了。

> **提示**：要前 10 个写 `[:cut_len]`，要后 10 个就写 `[len(value) - cut_len:]`。两种写法随你自己选，我习惯保留前 10 个，看起来更好处理一些。但**别把 10 写死在切片里**，这个长度来自上面的 `cut_len`，把它拉过来用，改一个参数就全变。

### 3.2 不足文本的补齐

能走到 `else` 的分支，说明上面的 `if` 没进去，也就是这个句子的长度不比 `cut_len` 大——要么刚好等于 10，要么小于 10，反正不可能超长，所以不用再判断了。

接下来先算清楚要补几个 0：

```python
        else:
            padding_len = cut_len - len(value)
```

`padding_len = cut_len - len(value)`。如果句子本身正好 10 个词，$10-10=0$，一个 0 都不用填；如果句子只有 3 个词，$10-3=7$，那就得补 7 个 0。量算出来之后，把补齐的结果也追加进列表：

```python
            list1.append(value + [0] * padding_len)
```

这一行我故意留着点名让人说。答案就是 `[0] * padding_len`：你当然可以手写 `[0, 0, 0, 0, 0]`，但有的句子要补 5 个、有的要补 6 个、有的要补 7 个，具体几个事先不知道，所以必须用乘法让 0 的个数由 `padding_len` 决定。

把五步合起来，纯 Python 版本就是这样：

```python
def padding_custom(x_train):
    list1 = []
    for value in x_train:
        # 超长文本：截断，保留前 cut_len 个元素
        if len(value) > cut_len:
            list1.append(value[:cut_len])
        # 不足文本：计算需要补齐 0 的数量并补齐
        else:
            padding_len = cut_len - len(value)
            list1.append(value + [0] * padding_len)
    return list1
```

### 3.3 两个版本的运行结果对照

把测试代码里的调用换成自己写的这个函数，再跑一遍：

```python
if __name__ == '__main__':
    result = padding_custom(x_train)
    print(f'result: {result}')
```

结果和第三方包的版本能对上：第一个样本被截断，截断的位置落在后面那个 `32` 附近，前端多出来的部分没了；第二个样本 `2 32 1 2 3` 后面补了一串 0。

```text
方式一  sequence.pad_sequences（默认 pre / pre）
  超长： [ 1 2 3 ... 前端被截掉 ... ][ 尾部 10 个 ]
  不足： [ 0 0 0 0 0 ][ 原始元素 2 32 1 2 3 ]

方式一  truncating='post', padding='post'
  超长： [ 前 10 个 ][ ... 后端被截掉 ... ]
  不足： [ 原始元素 2 32 1 2 3 ][ 0 0 0 0 0 ]

方式二  padding_custom（切片 [:cut_len] 截断 + 后端补 0）
  超长： [ 前 cut_len 个 ]
  不足： [ 原始元素 ][ 0 ... 0 ]   共 padding_len 个
```

读图说明：两个版本做的事情完全一致，差别只在"从哪一头截、往哪一头补"这个策略选择上——而这个选择两种实现都留给你自己定，想换方向，把切片 `[:cut_len]` 换成 `[len(value) - cut_len:]`、把 `[0] * padding_len` 挪到前面拼接即可。用第三方包就是一行 API，用纯 Python 也就七八行，掌握之后没有取舍负担。

## 4. zip 函数的行为验证

写 n-gram 时用到了 `zip`，这里顺手把它的行为再看清楚一遍。给它两个等长的列表：

```python
a = [1, 2, 3]
b = [4, 5, 6]

print(zip(a, b))
print(list(zip(a, b)))
```

`zip(a, b)` 做的事情就是上下做拼接，但它返回的是一个对象，直接打印看到的是这个对象本身，看不到内容。想看到里面的东西，用 `list()` 转一下再打印，得到的就是列表套元组：

```text
[(1, 4), (2, 5), (3, 6)]
```

读图说明：`zip` 按位置把两个列表的元素配成对，第一个列表的第 1 个配第二个列表的第 1 个，依此类推——这正是 n-gram 里"上下错位列表一组就拼出 n 元组"的原理所在。文本长度规范和 n-gram 特征这两块就此收尾，它们一个是把长度对齐，一个是把相邻词打包，都是喂给模型之前的准备工作。
