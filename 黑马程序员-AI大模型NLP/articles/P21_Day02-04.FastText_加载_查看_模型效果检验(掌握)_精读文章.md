# FastText 模型的加载、词向量查看与效果检验

模型训完了、也存成 `.bin` 了。可它在硬盘上躺着，我还没验证过它到底学到东西没有。

这一讲要解决的就是这个：**把模型读回来、看看某个词的向量长什么样、再让它自己回答"谁和谁意思接近"**。最后这一问，就是检验模型效果的方式。

有意思的是，"检验"这件事居然可以很主观——我给你一个词，你把它的近义词列给我，列得越准，模型就越好。没有考试卷，只有参照物。

## 1 三个接口与四步流程的位置

先看这一讲要用到的三样东西，它们都是 `fastText` 提供的：

| 接口 | 作用 |
| --- | --- |
| `load_model` | 加载模型 |
| `get_word_vector` | 拿到某一个词的词向量，属于"查看" |
| `get_nearest_neighbors` | 拿一个词的近邻单词 |

回到我们的四步流程，这一讲补的是**第二步的"加载和查看"**和**第三步的"模型效果检验"**。

```text
  训练阶段产出: model/xxx.bin
                  |
                  v
          load_model 读回内存
                  |
        +---------+---------+
        |                   |
        v                   v
 get_word_vector     get_nearest_neighbors
 （看单个词的向量）    （看词的近邻 → 检验效果）
        |                   |
        v                   v
  100 维 numpy 数组     列表套元组：(相似度, 近义词)
```

读图说明：三个接口分两层——`load_model` 负责把模型从磁盘搬进内存，另外两个都建立在"模型已在内存"这个前提上；一个看单点，一个看邻域。

## 2 近邻单词与 KNN 的渊源

`get_nearest_neighbors` 这个名字，两个单词拆开看：`nearest` 是最近的，`neighbors` 是邻居——**最近的邻居**。

机器学习里我们学过一个 **KNN（K-Nearest Neighbors，K 近邻算法）**，那两个 `NN` 就是这两个单词。名字撞在一起不是巧合：思路是同一个思路，都是拿"和它靠得最近的几个样本"来说明一个点。

检查单词向量质量的一种简单方法，就是**查看它的近邻单词**。

> **结论**：具体做法是——给你一个词，让模型把它的近义词列出来；我们再**主观判断**这些近邻词和目标词之间的相关性，以此评估模型好不好。找得越准，模型效果越好。

注意"简单"和"主观"这两个词。这不是一个精确指标，但对词向量来说足够管用——一个词的邻居合不合理，人一眼就能判断。

## 3 加载模型并获取单个词的词向量

切到 PyCharm，第一个函数叫 `demo02`，名字用 `get_word_vector`，也就是"词向量"。

第一步是**加载预训练好的 `fastText` 模型**，也就是刚才训练并保存出来的那一份：

```python
import fastText


def demo02_get_word_vector():
    # 1. 加载预训练好的 fastText 模型
    model = fastText.load_model('./model/0502_fil9.bin')
    # 2. 获取单个词的词向量表示
    result = model.get_word_vector('the')
    # 3. 打印结果
    print(type(result), result.shape)
    print(result)


if __name__ == '__main__':
    demo02_get_word_vector()
```

第二步里取哪个词？

> **易错点**：不能在这儿写一个中文词。为什么？因为刚才训练时喂进去的数据**全是英文单词**，词表里只有英文。取词得从语料里已有的词里挑——比如 `the`。

第三步打印结果。先打印类型和形状：

```text
<class 'numpy.ndarray'> (100,)
```

**它是 `numpy` 的 `ndarray` 数组**，形状是 `(100,)`。

为什么是 100？回想一下看源码那一步——默认参数的 `dim` 就是 **100 维**。所以这里一定是 100。100 维的意思我们前面说过：**用 100 个数字来表示 `the` 这一个词**。

那这 100 个数字到底长什么样？把 `result` 直接打印出来就是它的**具体值**，也就是这个词的词向量。

> **提示**：`type()` 和 `.shape` 这两个打印不要省。它们确认了两件重要的事——返回的是 `numpy` 数组而不是列表，维度是 100 而不是别的数。写代码时先确认形状，后面接别的方法就不会踩维度错。

## 4 用中文词取向量会发生什么

这里有个特别值得试的动作：把 `the` 换成一个中文词——比如说你自己的名字——再右键运行一次。

你会发现：**它照样给你生成向量**。输出里能看到生成出来的类别信息，下面还是一个 100 维、100 个数字的结果。

为什么训练时全是英文，喂中文也能出数？因为模型会**去适配**你给的这个输入，把它映射到它自己的表示空间里，然后照样吐出一个 100 维向量。

但**能生成不等于有意义**。将来你拿这个词去查近义词，结果就不一定准了。

> **结论**：中文词能拿到向量，但向量质量没有保证——因为它的语义从来没在训练语料里出现过。想让中文词也准，得用中文语料重新训练。

顺手把话题拉回来：演示还是用英文单词 `the`。这个函数测试完就切回去。

## 5 当前模型是 Skip-gram 还是 CBOW

写到这里，可以问一个很有价值的问题：**你现在看到的这个词向量，是 Skip-gram 出来的，还是 CBOW 出来的**？

答案是 **Skip-gram**。

为什么？因为刚才训练时我们什么参数都没写，而 `train_unsupervised` 的默认 `model` 就是 `skipgram`。你用的是默认值，拿到的自然就是 Skip-gram 训出来的向量。

想改成 CBOW 就得手动指定参数——那是下一步的事，这一讲先不碰。

## 6 查找近义词与返回格式

同一个脚本里再写一个函数，注释写清楚它的职责：**定义函数，实现查看单词的相似度**。说白了就是**找它的近义词**，再看看模型效果怎么样——这就是所谓"模型效果检验"。

```python
def demo03_get_similarity():
    # 1. 加载预训练好的 fastText 模型
    model = fastText.load_model('./model/0502_fil9.bin')
    # 2. 查找某个单词的近义词
    result = model.get_nearest_neighbors('dog')
    # 3. 打印结果
    print(result)


if __name__ == '__main__':
    demo03_get_similarity()
```

第一步和刚才完全一样，先加载模型。第二步换词：这次不用 `the`，用 **`dog`**——一条有近义词可查的实词。

`get_nearest_neighbors` 有几个行为要记住：

- **默认返回 10 个**近邻；
- 用途是检验模型的**语义理解能力**；
- **返回格式是"列表套元组"**：每个元组里，**第一个是相似度分数，第二个是近义词**，然后一组一组往后排。

```text
[(0.78, 'dogs'), (0.71, 'sheepdog'), (0.66, 'breed'), ...]
   ↑      ↑
 相似度  近义词        ← 成对出现，一共 10 组
```

读图说明：外层是一个列表，长度默认 10；每个元素是 `(相似度分数, 近义词)` 的元组，分数越大表示两个词在向量空间里越接近。

## 7 dog 的近邻结果分析

跑出来数一数：一组、两组、三组……一直到十组，正好 10 个。

结果里能看到这些**真实**的近邻词：

| 近义词 | 说明 |
| --- | --- |
| `dogs` | `dog` 的复数形式，形态最近 |
| `sheepdog` | 牧羊犬，真的是一种狗 |
| （比熊犬一类的词） | 也是一种犬种 |
| `breed lover` | 直译是"繁殖之爱"，实际指的是一种犬种名 |
| `breeds` | 繁殖、品种相关的词 |

> **结论**：前面这几个词找得**确实还不错**——`dogs` 是形近，`sheepdog`、比熊犬是同一类动物，`breed(s)` 是犬类语料里高频共现的词。这说明模型确实学到了"狗"这个概念附近的语义区域。

有个小技巧可以顺手用上：把不认识的近义词丢到**有道翻译**里查一下。词典翻译对这类专有名词覆盖得不够全，翻译出来会有点欠缺，但基本能帮你确认它到底指什么。

## 8 换中文词查近邻的结果

再做一个动作：换个人的名字进去试试。

结果**肯定不准**。原因和前面一样——训练用的是纯英文语料，你输中文它就只能硬适配。跑出来的近邻词会是一些不知所云的组合，甚至可能生成了不太好看的词。

> **提示**：想确认这一点，就把这些单词统一丢到翻译工具里看一眼。你会发现它们和输入的中文人名毫无关系。反过来说，前面输入英文单词时近邻质量明显更好——这本身就是一次对照实验。

对照下来的判断是：**给英文单词时近邻质量明显更好，说明模型训练的结果还不错**。

那想让效果更进一步怎么办？很简单——**训练时别用分片，用上面那个全量数据集**。词表更大、共现统计更充分，学出来的语义空间就更细。

## 9 效果检验与超参设定的衔接

到这里，四步流程已经走了三步：

1. 获取训练数据 ✔
2. 训练、保存、加载、查看 ✔
3. 模型效果检验 ✔
4. 模型超参数设定 ← 下一步

回头看会发现一件事：**从头到尾，超参我们一个都没写过**，全程在用模型默认值。

> **结论**：默认它训练 **5 轮**。那我能不能训 10 轮、20 轮？**训练轮数变多，模型效果通常也会变好**——道理和"多读几遍记得更牢"一样。学习率、维度、模型模式（`skipgram` 还是 `cbow`）也都是同一个逻辑。

这些参数就是最后一节要玩的：把默认值一个个换成我们指定的值，看看训练过程和质量各有什么变化。
