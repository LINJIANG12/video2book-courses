# 句子长度分布统计与 map() 函数用法扩展

接下来讲句子长度分布的统计。先把原始句子翻出来看一眼：有的句子非常非常长，从这一头到那一头，整个句子还没结束；有的又非常非常短，就那么几个字，句子就完了。那问题来了——**实际开发中，句子长度到底该设成多少？设得非常长，还是设得非常短？** 其实两头都不合适。

## 句子长度应该取多长

句子长度不是拍脑袋定的，要看数据自己说话：**看看绝大多数的句子都集中在哪个长度，就拿它做截断的长度**。

打个班里的比方。班里几十个学生，每个人的年龄都不一样，那你要拿哪个年龄代表我们班比较均衡的情况？当然是看绝大多数的学生年龄集中在多少。句子长度定长是同一个道理——不看极端的那几条，看主流的区间。

所以第一个动作是**训练集句子长度分布**：给它画一张柱状图。然后同样的数据再画一张**训练集的密度曲线图**；验证集那边也一样，一张柱状图、一张密度图。加起来四张图：训练集柱状图、训练集密度图、验证集柱状图、验证集密度图。

看完这两组图，结论就是一句话：从训练集和验证集的长度分布来看，句子的长度范围大多处在 **20** 往后的一个区间里——绝大多数数据都集中在那一段。这个区间就是我们后面定固定长度的依据。

## 截断与补齐

长度定下来之后，两个动作就跟着来了。若模型对输入数据的长度有要求，就需要对句子做**截断**和**补齐**：

- **截断**：你超出了我设计的长度，多出来的部分砍掉；
- **补齐**：你没达到我想要的长度，少的补上。

> **定义**：截断处理过长的句子，补齐处理过短的句子，两者配合，把所有句子统一到同一个固定长度。

补齐用什么补？一般用 **0** 填充。举个例子：我把长度设成 10，而你现在这条句子只有 8 的长度，那缺的那两个位置就拿 0 去填，填满 10 为止。

## 新增长度列与四张分布图

代码这一段的骨架是这样的：

- 上来先设置 538 风格（`FiveThirtyEight`），跟上一节一样；
- 接着读数据，训练集和验证集照旧读进来；
- **新增一列长度**，这一列等于把某种"求长度"的操作作用到句子上；
- 然后用新加的这列数据，绘制数据长度分布的柱状图，再绘制密度曲线图。

真正有点门槛的就是第三步——**"新增一列长度"这个动作靠 `map` 完成**。而 `map` 这个函数，不是每个人都用过。所以下面先撇开长度统计，把 `map` 单独讲透；这里讲不清楚，后面那行代码就是照抄。

> **提示**：后面统计长度还会用到 `chain`、`zip` 这类工具，它们在迭代器那一族里是同一挂的；这一讲先把 `map` 说明白。

## 需求：把函数作用到列表的每个元素上

先写一个被作用的函数。需求很简单：**接收一个参数，返回它加 2 的结果**。

```python
def fn(x):
    return x + 2
```

有人要问：为什么是加 2？乘 2 行不行？平方行不行？随你，这只是个演示用的函数，返回什么都可以，重点是它**只有一个参数**。

再定义第二个函数，用来演示 `map` 的用法——把上面这个 `fn` 函数作用到列表中的每一个元素上：

```python
def dm01_map():
    result = map(fn, [1, 2, 3, 4, 5])
    print(result)
```

看这一行 `map(fn, [1, 2, 3, 4, 5])`：后面是个列表，前面是个函数，`map` 站在中间把两者对起来。那它会得到什么？按直觉猜，应该是每个元素加 2，也就是 `3 4 5 6 7`。

先别急着下结论，跑一下 `print(result)`，出来的是这样：

```text
<map object at 0x...>
```

**不是一个列表，是一个 `map` 对象。**

> **结论**：`map` 函数返回的是一个**迭代器对象**，此时**并未实际执行运算**。也就是说，`fn` 这个函数还没有跟列表里的元素相加过。

## map 返回的迭代器与被推迟的计算

为什么会这样？把流程摊开看就明白了：

```text
map(fn, [1, 2, 3, 4, 5])
     │              │
     │              └── 可迭代对象：逐个取出元素
     └── 函数：每取出一个元素，就对它调用一次
                    │
                    ▼
              map 对象（迭代器）
              此刻还没有任何计算发生
                    │
        遍历 / 转成 list 的时候才逐次调用 fn
                    ▼
              3  4  5  6  7
```

读图说明：`map` 只是把"函数"和"可迭代对象"这两样东西**打包**成一个迭代器；真正的加法发生在你从迭代器里往外取元素的那一刻。理解这一点，后面所有的"为什么打印出来是对象"就都不奇怪了。

## 迭代器只能遍历一次

既然要遍历才计算，那就遍历它——第一次遍历 `map` 对象：

```python
for i in result:
    print(i)
```

依次输出 `3 4 5 6 7`，跟猜想一致。中间可以插一条分割线把两次输出隔开：

```python
print('-' * 10)
```

然后是关键的第二遍。第二次尝试遍历同一个 `map` 对象：

```python
print(list(result))
```

输出的是一个**空**。

> **易错点**：**迭代器只迭代一次**。第一遍遍历的时候元素已经被取走了，你再去这个迭代器里拿元素，里面已经没有了。所以第二次拿到的是空的。

到这儿 `map` 的意思就完全清楚了：**它把函数作用到列表中的每个元素上，只有后续遍历、从里面拿元素的时候才真正计算；你直接打印，打印到的仅仅是一个对象。**

## 用 lambda 表达式写同一个函数

上面那个 `fn` 有个特点：**函数体只有一行**。函数体只有一行的时候，没必要单独 `def` 一个函数，用 `lambda` 表达式就能实现相同的功能：

```python
result2 = map(lambda x: x + 2, [10, 20, 30])
```

对着看就很清楚：**`lambda x: x + 2` 这一堆，代表的就是上面那个 `fn`**，后面的列表跟上面是一样的作用。这里顺手把元素换成了 `10 20 30`，不影响理解。

再看结果：

```python
print(result2)          # 还是一个 map 对象
print(list(result2))    # [12, 22, 32]
```

`result2` 打印出来**它还是一个对象**——因为 `map` 的行为没有任何变化，换的只是函数写法。要拿到结果，就得在外面套一层 `list`：

> **结论**：`map` + `list` 是一对。把函数作用到列表里的每个元素上，得到一个迭代器，最后用 `list` 把它封装成列表。

写着写着容易形成肌肉记忆，习惯性地直接在打印时就加上 `list`；加在输出的时候加、还是加在赋值的时候加，都行，效果一样。

## map 在句子长度统计中的作用

回到开头那个"新增一列长度"。为什么这里非得用 `map`？因为这件事的本质就是一句话：

> **结论**：把函数作用到每个句子上，**把句子的内容转换成长度**，最后用 `list` 封装成列表。

一个句子进来，出去的是它的长度；一批句子进来，出去的就是一批长度。至于那个函数是谁——可以是 `len`，可以是 `lambda` 写的自定义规则，只要它的输入是一条句子、输出是一个数字就行。

所以长度统计这条线是这样的：先有原始句子 → 用 `map` 把每条句子换算成长度 → 得到一列长度 → 拿这一列去画柱状图和密度曲线图 → 从图上读出绝大多数句子集中在哪个区间 → 定下固定长度 → 对长句截断、对短句用 0 补齐。

如果一上来不写这些铺垫的测试代码，直接把 `map` 塞进业务代码里，看半天只会一脸懵。所以问一句"这个东西用过没有"很重要：没学过就先写个 demo 把它讲明白，学过了就直接进案例。
