# 双向 LSTM 的双向传递与结果拼接

接下来讲双向 Bi-LSTM。什么叫双向？就两句话。

第一，它**没有改变 LSTM 本身的任何结构**——还是遗忘门、输入门、细胞状态、输出门，还是三门加一状态，一点没动。第二，它做两次。

有人会问：那它跟之前有啥区别？区别就在这个「两次」上：`我爱中国` 这句话，你先切词，切成几个词？我、爱、中国，三个。然后从左到右做一次 LSTM，从右到左再做一次 LSTM，把两次得到的张量结果**拼接**起来。讲完了。

> **结论**：Bi-LSTM 不新增任何门、任何状态，它只是把同一个 LSTM 正反各跑一遍，再把两个方向的输出拼在一起，让每个位置的表示同时看到左边和右边的信息。代价是计算量翻倍。

## 两次传递的方向与顺序

既然结构不动，那全部的理解难点就落在「两次分别是怎么传的」上。我用一个例子把它钉死。

假设序列是 `我爱中国`，切完词是 `我`、`爱`、`中国`。上面一条通路从左往右走，依次传入 `我`、`爱`、`中国`，走一步出一个隐藏状态，最后得到三个位置的隐藏状态。

那下面这条通路呢？**反着传**。

反着传的意思是：第一次先传 `中国`，得到一个状态，记作 `R0`——`R` 是 right，右的意思，`R0` 就是反向通路的第 0 个输出。传完 `中国` 再传谁？传 `爱`。再传一个 `我`，得到 `R2`。

这里必须先把一个最容易记反的地方说清楚，不然一会儿拼不起来。

有人一看「从右往左」，脑子里就自动摆成 `中国爱我`：`中国` 就是我原来位置 0 的输入，`我` 是我原来位置 2 的输入。**不对**。

从右往左传，传的第一组是 `中国`，第二个是 `爱`，第三个是 `我`；但这三个词各自落在哪个位置上，是**不动的**。`我` 始终在位置 0，`爱` 在位置 1，`中国` 在位置 2。反向通路改变的只是**传参的顺序**，不是词的顺序。

```text
文本（位置固定）:   [ 0:我 ]      [ 1:爱 ]      [ 2:中国 ]

正向通路  L→R:      我      ──►   爱      ──►   中国
                    L0            L1            L2

反向通路  R→L:      我      ◄──   爱      ◄──   中国
                    R2            R1            R0
                    ▲             ▲             ▲
              先传中国,再传爱,最后一个才传我（传参顺序相反）

最终输出 = 同位置拼接:
  位置0  我    =  concat(L0, R2)    ← 必须都是「针对我」处理后的结果
  位置1  爱    =  concat(L1, R1)
  位置2  中国  =  concat(L2, R0)
```

读图说明：两条通路共用同一套词、同一套位置编号，唯一不同的是喂进去的先后次序；拼接发生在**同一个位置**上，位置 0 拿到的必须是「正向看 `我` 得到的 L0」和「反向看 `我` 得到的 R2」。

> **易错点**：反向通路的 `R0` 对应的是序列**最后**那个词。所以如果你把反向输出按 `R0、R1、R2` 的顺序直接贴到位置 `0、1、2` 上，就变成了「中国」和「我」对齐——那这个拼接就彻底没有意义了，等于白做一次。

## 位置对齐与输出向量拼接

把顺序摆对之后，剩下的就是一次拼接动作。

正向在位置 0 得到的向量是 `L0`，反向在同一个位置 0 得到的向量是 `R2`。这两个向量的「出身」是一样的——都是针对 `我` 这个词算出来的表示，一个从左边看它，一个从右边看它。把它们拼起来，才叫有意义。

拼接的结果长度是两个向量长度之和。举个具体数字：如果单向输出的维度是 3，那么位置 0 的最终输出就是「你的 3」拼上「我的 3」，变成 6。三个位置都是这么干：

- 位置 0：`concat(L0, R2)`，长度为 3 + 3 = 6；
- 位置 1：`concat(L1, R1)`，长度为 3 + 3 = 6；
- 位置 2：`concat(L2, R0)`，长度为 3 + 3 = 6。

> **定义**：Bi-LSTM 在时刻 $t$ 的输出是正向隐状态与反向隐状态的拼接

$$h_t = \left[ \overrightarrow{h_t} \; ; \; \overleftarrow{h_t} \right]$$

其维度为 $2 \times \text{hidden\_size}$。

这么一来，每个位置的输出向量同时包含了它左边所有的信息和右边所有的信息，也就有了完整的上下文视角。这正是 Bi-LSTM 比单向 LSTM 更强大的地方。

对应的弊端也很明确：**双向的参数和计算复杂度都会随之增加一倍**，因为你实实在在做了两次。

> **提示**：这里的「一倍」是指参数量与浮点运算量相对于同样 `hidden_size` 的单向 LSTM 翻番——反方向的 LSTM 有自己独立的一套权重矩阵，不与正向共享。

## 双向的代价与适用判断

参数和计算量翻倍这件事，换个角度看其实是「多买了一套权重」。正向通路和反向通路各有自己的 $W_f, W_i, W_o, W_c$ 那一套矩阵，把参数相加，再乘上迭代轮数，训练成本自然就上去了。

所以它并不是无脑上双向就一定更好。要不要做双向，取决于任务本身能不能看到完整句子：

| 判断依据 | 适合双向 | 只适合单向 |
| --- | --- | --- |
| 输入是否一次性给全 | 整句已经拿到手，左右都能看 | 数据是流式到来，未来还没发生 |
| 典型任务 | 文本分类、命名实体识别、句子级情感分析 | 语言模型逐词预测、实时流式标注 |
| 代价 | 参数与算力翻倍 | 省一半算力，但看不到右文 |

一句话，双向的前提是「右边的信息本来就存在，只是你刚才没去看」。如果右边的东西还没出现，那就没有第二遍可做。

## 关于方向的两个混淆点

讲到这里，还有两处容易绕晕的地方，我一次说清。

第一处是**从右往左的文本顺序**。有些人习惯在反向通路下面也标一句「我爱中国」，这其实也是对的。为什么？因为文本本来就是 `我`、`爱`、`中国`，只不过这一次不是从左往右读，而是从右往左读。所以你得**倒着传**：传 `中国`、传 `爱`、传 `我`。顺序不变，方向变了。

> **结论**：文本顺序永远不变，变的只是传入的先后。你要是把词的顺序也调了，那就完蛋了——`中国`、`爱`、`我` 一挪位置，一会儿拼接时中国跟中国就对不上，这一步就白做了。

第二处是**为什么要拼在同一位置**。你可以反过来想：如果位置 0 放的是正向看 `我` 的结果，而它对面放的是反向看 `中国` 的结果，那拼出来的向量描述的是两个不同的词，后面的分类、标注拿它做决策就是在用错误的信息。

所以判断标准只有一条：拼接的两半，必须都是**针对同一个词处理后的结果**。这一点不标清楚，光看图很容易晕。

> **提示**：想看清更细的动作，可以把这段说明连同「BiLSTM、两次传递」一起丢给豆包这类助手，让它把这两次传递逐步展开给你看。不要去纠结书上那些符号，把两次传递动作各走一遍，比读十遍定义都管用。

## 本讲提到的题目

课上留了一道选择题：下列 LSTM 的调用写法，ABCD 哪一行错了、为什么错？

按本讲的调用规则，传入 `H0` 与 `C0` 时必须**以元组的形式包裹成第二个位置参数**：`lstm(input, (H0, C0))`。

**答案：D 错。** 因为 D 没有加小括号，把 `H0` 和 `C0` 当成两个独立的参数传了进去。`nn.LSTM` 只需要两个位置参数（输入张量、隐状态元组），你给它三个，数量对不上，直接报名称错误。这就是「必须以元组形式包裹」这句话的直接后果。
