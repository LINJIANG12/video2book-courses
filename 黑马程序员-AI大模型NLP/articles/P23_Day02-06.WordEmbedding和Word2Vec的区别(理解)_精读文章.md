# Word Embedding 与 Word2Vec 的词向量差异

Word2Vec 这种词向量编码方式我们已经玩完了，接下来要看的是 Word Embedding——词嵌入。它跟 Word2Vec 是什么关系？是同一件事的两个名字，还是两种不同的做法？

这一讲要把这个概念掰开：既要搞清楚它在广义和狭义上分别指什么，也要把它和刚学完的 Word2Vec 摆在一起对比。而对比的结果，最后会浓缩成两句大白话，我希望你听完就能复述出来。

## 词嵌入的广义与狭义

词嵌入是通过一定的方式把词汇映射到指定的维度，一般是更高维度的空间。它有两层解释。

> **定义**：广义的 Word Embedding 指所有稠密词向量表示法。像我们之前讲的 Word2Vec，它就属于 Word Embedding 的一种；使用浅层网络可以实现，使用深层网络也可以。

> **定义**：狭义的 Word Embedding 指深度神经网络中的嵌入层。回想一下 RNN 由哪几层组成——第一层是词嵌入层，第二层是循环网络层，第三层是输出层。这里说的就是这个词嵌入层。

这个 `nn.Embedding` 的代码你熟不熟？`nn` 指 Neural Network，神经网络；里面 `num_embeddings` 是多少个单词，`embedding_dim` 是多少维度。前面写 20 个单词、后面写 8，就是每个单词用 8 个数字来表示，最终形状是一个 $20 \times 8$ 的矩阵。

```python
import torch.nn as nn

# 20 个单词，每个单词用 8 维向量表示
embed = nn.Embedding(num_embeddings=20, embedding_dim=8)
print(embed.weight.data.shape)   # torch.Size([20, 8])
```

这段 `nn.Embedding` 我们在讲 RNN 的时候就写过，所以这里不再重复造一遍——等会儿做案例时直接把它带进去用。

## 静态词向量与动态词向量

两者有相同点，也有不同点。

相同点是：无论是 Word2Vec 还是 Word Embedding，它们都是词向量的一种手段和方式。

不同点是这样三条：Word2Vec 产生词向量后，某一个词的词向量就固定下来了，是**静态**的；而 `nn.Embedding` 层产生的词向量，因为词嵌入是整个网络的一部分，权重参数会在训练中更新，是**动态**的。另外，Word2Vec 一般需要两步——先拿到词向量，再给神经网络；`nn.Embedding` 一步直接用就行。

| 对比项 | Word2Vec | Word Embedding（`nn.Embedding` 层） |
| --- | --- | --- |
| 词向量性质 | 静态，一旦训练完就固定 | 动态，随网络训练一起更新 |
| 使用步数 | 两步：先拿词向量，再交给网络 | 一步：直接作为网络的一层使用 |
| 是否单独训练 | 单独训练一个词向量模型 | 不单独训练，是网络内部的层 |
| 训练与保存 | 必须先训练并保存才能用 | 无需单独保存词向量 |

## 核心逻辑：两套大白话

动态和静态听懂了，但"为什么要分两步、一步"可能还没落地。我用大白话给你解释。

Word2Vec 的核心逻辑是：先单独训练好词向量，再拿这些向量去做模型任务。简单记忆就是——**先办证，后干活**。

想干这件事？不好意思，你先把证办了；办完这个事你就能干。不办证，这个事你就干不了——哪怕你能力够，没这证也不行。这就是 Word2Vec：你想做词向量相关的活儿，得先用 fastText 把模型训练出来、保存下来，然后才能用。这也是为什么上一讲的流程里，第一步必须先训练。

`nn.Embedding` 的核心逻辑正相反：它不单独训练词向量，而是把**创建词向量**和**训练模型**合成一步，一起做。大白话就是——**边办证，边干活**。

还是用开车打比方（不聊别的，只说证这件事）：上面那种是先去把证办了，然后才能开车；这个是一边办着证一边就开着车。

```text
Word2Vec：   训练词向量模型 -> 保存 -> 加载模型 -> 做下游任务
             [ 办证 ] ----------------------> [ 干活 ]

Word Embedding：  词嵌入层直接放进网络，随网络一起训练
             [ 办证 + 干活 合成一步 ]

判断口诀：先办证后干活 = Word2Vec；
          边办证边干活 = nn.Embedding（RNN 的词嵌入层）
```

读图说明：上面这条链是串行的两段，中间必须落一次盘才能进下一步；下面这条链只有一段，词向量就是在训练模型的过程中顺便长出来的。

## 问答回顾：两种模式、三大件与 API

概念讲完，接下来是当堂提问，问题挺多的，我们一起过一遍。

**Word2Vec 有哪两种训练模式？** CBOW 和 Skip-gram。CBOW 基于两边预测中间，Skip-gram 基于中间预测两边。

**CBOW 的原理是什么？** 本质是一个神经网络，有输入层、隐藏层和输出层。整体动作跟前面讲过的一样：先前向传播算出预测，拿预测和真实值经过损失函数算损失，得到梯度，再经过反向传播更新。最终我们要的是**隐藏层的权重矩阵**，因为其中的每一列对应一个单词的词向量。

**Skip-gram 呢？** 基于中间预测两边，最终用的还是隐藏层的权重矩阵，底层同样是神经网络，流程也是前向传播 → 损失函数 → 反向传播更新。这里顺带记一下深度学习的三大要素：前向传播、损失函数、反向传播。最终拿到的权重矩阵，不是输入层的，也不是输出层的，而是**隐藏层的**。

**这两种模式代码怎么写？** 用 fastText 工具包，设置参数即可。它的默认模式是 skip-gram，可以改成 CBOW。

**Word Embedding 的极简理解？** 两个词：广义和狭义。广义上只要是稠密向量表示法，全属于 Word Embedding；狭义上指 RNN 的那个词嵌入层——我们做 AI 歌词生成器时用的就是它。

**两者有何异同？** 相同点都是稠密向量表示法，都能把文本转成数值。不同点是 Word2Vec 得先把模型训练出来才能做事，所以是先办证后干活；Word Embedding 是一个词嵌入层，上来直接玩，边干活边训练模型，它就一步。

**fastText 这一套的步骤和相关 API？** 获取数据这步不说了，剩下的：训练用 `fasttext.train_unsupervised`，保存用 `save_model`，加载用 `load_model`，查看用 `get_word_vector`（它是获取你的词向量）。

```python
import fasttext

# 训练
model = fasttext.train_unsupervised('./data/fil9')
# 保存
model.save_model('./data/fil9.bin')
# 加载
model = fasttext.load_model('./data/fil9.bin')
# 查看某个词的词向量
print(model.get_word_vector('the'))
```

**超参设定设了哪几个？** 先是 `input` 关联数据集，再是 `model` 指定模式（CBOW 或 Skip-gram），然后是学习率 `lr`、维度 `dim`（用几个数字表示一个词）、轮数 `epoch`、线程数 `thread`。大体就是这些，后面还有很多参数，感兴趣的可以自己看。

**模型效果检验的函数叫什么？** `get_nearest_neighbors`。机器学习里的 KNN，那俩 NN 就是 nearest neighbors，近邻。模型效果检验最粗暴、最直观的方式，就是我给你一个词，你帮我找它的近义词——找得越精准，说明模型效果越好。

## CBOW 与 Skip-gram 的计算效率取舍

CBOW 的计算相对简单，计算要快一些；Skip-gram 要基于中间预测两端，两次计算，运算量更大。所以在大规模语料下，从计算效率入手做优化，CBOW 会更合适。

课外材料里有一段 CBOW 与 Skip-gram 的对比，其中"CBOW 在训练数据较大的情况下往往表现较好，特别是在低/高频词上"这一句，正确写法是**高频词**，需要把那个字改过来。

材料自己的表述是：CBOW 相对来讲更简单，尤其在高频词上会更好一点。原因是它可以把多个词向量做平均，减少了模型复杂度；而 Skip-gram 在处理低频词时往往更有优势。

> **注意**：判断到底选哪一种，要看两件事——你的数据集特性是高（或低）频词为主，以及你的计算机计算资源。如果计算资源非常富裕，可以考虑 Skip-gram，因为它对算力的要求更大，运算量更大。

## 用大模型给图解做交叉复核

画 CBOW 图解的时候，我在图上标的"高频/低频"和材料里的说法对着干，这就得较真。

做法是别只问一个模型：先用通义问一遍"Word2Vec 的 CBOW 和 Skip-gram 模式哪个更适合处理高频词和低频词"，再换 DeepSeek 问一遍，元宝、Kimi 也可以加上，三四个模型基本够用。几个模型都给出同一个结论后，再回头把材料里那个字改掉——图上的标记本身是对的，材料里那句是错的。

顺带说一个我一直用的习惯：图审。

自己画完一张图之后，我会先截图发给 AI，用这样的提示词：

```text
我是一名 IT 讲师，上述是我绘制的一张 CBOW 图解。
请从专业性、阅读性、知识传递性等角度，帮我分析这张图绘制得如何，
如果有不足的地方，也可以给出一些修改建议。
```

它会回一段评价：核心思路清晰、前向传播那部分怎么怎么样、权重矩阵的命名和维度（比如 $5 \times 3$ 这种）要留意、隐藏层那里是**先相加再算均值**（我图上只标了"相加"），另外 Softmax 可以补充说明。

它还会附一份优化后的版本：主标题怎么写、副标题"训练流程"放哪儿、左侧标什么、右侧标什么，照着再画一遍，再发给它或换一个模型复核。一轮一轮下来，这张图就越来越准了。

> **提示**：这套复核流程的价值在于把画图这件事变成可复用的自检动作，但别把它当主线——我们是为了讲清这门课，图做得再花，跑题就跑题了。

## 本讲提到的题目

讲完概念紧接着做了四道选择题。

**第 1 题：CBOW 和 Skip-gram 都是 Word2Vec 的两种方式，它们的区别主要在于？**

答案是选 A：上下文和当前单词之间的预测关系——CBOW 基于上下文预测中间词，Skip-gram 基于中间词预测上下文。

**第 2 题：哪一种模型在处理大语料时更有优势？**

答案是选 A，CBOW。判断依据在"大语料"三个字上：大语料要考虑处理速度更快、效率更高，而 CBOW 计算相对简单、计算更快，所以在大量语料的情况下表现更好。Skip-gram 相对复杂——它要基于中间预测两端，生成两次、计算两次，运算量更大。既然题干说的是大规模语料，就要从计算效率入手做优化，所以选 CBOW。

**第 3 题：在 Word2Vec 里，窗口大小决定了模型考虑什么的范围？**

答案是上下文的范围。窗口设成 3，就是基于第 1 个和第 3 个词预测第 2 个词；设成 5，就是基于第 1、2 个和第 4、5 个词预测第 3 个词。一般取奇数，比如设成 7，就是基于前 3 个和后 3 个词预测中间那个词——参考几个词，就是这个意思。

**第 4 题：对于模型未见的单词，可以使用什么方法来生成它们的词向量表示？**

这题其实有歧义：如果那个词特别生僻，直接忽略（A）也是一种选择。但题目问的是"用什么方法来生成词向量"，要生成，就只能选 C——使用最接近的已知单词的向量。

这个思路和前面找近义词是同一件事：如果当前这个单词模型不认识，那就去找它的近义词。当时用模型演示时，我传进去一个中文名字，而那批训练语料全是英文单词，它照样能生成词向量——原因就是用近义词的向量顶上了。所以未见词的建议答案是最接近的那个近义词的词向量（3C）。
