Transformer 的输入部分，要讲的是 `input embedding`（文本嵌入层）和 `positional encoding`（位置编码层）。这一讲先把效果立起来：**能说出文本嵌入层的作用并掌握它的实现，能说出位置编码层的作用并掌握它的代码实现。**

先动手的是文本嵌入层，代码落在一个叫 `dm01_input.py` 的文件里。为什么是这个名字、为什么要这么命名，后面有一大段要专门交代——这次写的文件是要给别人调用的，不是写完就扔。

## 输入部分的构成

输入部分包括两块：`Input Embedding`，也就是输入的词嵌入层；还有 `Output Embedding`，输出的词嵌入层。

拿之前的英译法案例来说，数据源里每一行数据都包含两部分：一个是已知的英语句子，一个是已知的法语句子。英语句子走这一路，法语句子走另一路。所以完整的输入部分是这样四样东西：

- **原文本嵌入层**——指的是英语句子；
- **原文本的位置编码**；
- **目标文本嵌入层**——指的是法语句子；
- **目标文本的位置编码**。

## 词嵌入层的作用

文本嵌入层就是这个 `embedding`，它做的事情是**把文本转成词向量**。

> **定义**：词嵌入层就是把文本数据转成词向量形式，也就是把你的数据转成数值形式。

为什么非得转？因为**模型没办法直接处理文本数据，它的底层玩的全是数字**。转成数值之后，我们希望这些数值能在高维空间里捕捉到词汇之间的**语义关联**——说白了，词与词之间的关联，就是数值与数值之间的关联。

## 词嵌入层的定义

```python
class Embedding(nn.Module):
    """模拟词嵌入层"""

    def __init__(self, vocab_size, d_model):
        super().__init__()
        self.vocab_size = vocab_size
        self.d_model = d_model
        self.embed = nn.Embedding(vocab_size, d_model)

    def forward(self, x):
        return self.embed(x) * math.sqrt(self.d_model)
```

### 初始化函数的两个参数

第一步是初始化函数，也就是 `def __init__(self, ...)`，里面要两个参数：`vocab_size` 和 `d_model`。

这里说一句要紧的话：因为这个类后面还要被应用——在二号、三号或者别的文件里要调用——所以类名、连形参名，你最好都跟我保持一致。不然格式一样、名字不一样，传到后面参数你会感觉怪怪的。这份代码写起来差不多接近 1000 行：做英译法的时候在一个脚本里写了接近 800 行，这次是分开写的，大概七八个文件，每个文件二三百行、平均下来 100 多行，写下来就是 1000 加。变量名不统一，后面写起来就很麻烦。

- **`vocab_size`**：词汇表大小，也就是词典库里单词的个数。例如刚才讲的，英语那边是多少个词？**8003**；法语那边是多少？**4345**。就这意思。
- **`d_model`**：词嵌入的维度，也就是**你用几个数字来表示一个词**。

### 函数体内的三步

进来先写第一步：**初始化父类信息**。既然继承 `nn.Module`，那里面有两个函数是必做的，一个是 `__init__`，一个是 `forward`。所以第一件事是初始化父类，写法就是 `super().__init__()`，结束。

第二步是**定义变量、接收参数**，把上面两个参数接住：

```python
        self.vocab_size = vocab_size
        self.d_model = d_model
```

注意 `d_model` 是我们的维度。

第三步是**定义词嵌入层，把单词索引映射为词向量**：

```python
        self.embed = nn.Embedding(vocab_size, d_model)
```

写到这里我要问一句：我们的 `embedding` 跟 `nn` 里面那个 `embedding` 有什么关系？**没关系。** 这就是所谓的**挂羊头卖狗肉**——看着是你自己的 `embedding`，其实底层调的还是人家的。

> **提示**：词向量以前讲过三种手段。第一种是 `one-hot`；第二种是 `word2vec`，它往下又分 `CBOW`（连续词袋，用两端预测中间）和 `Skip-gram`（跳词，用中间预测两端）；第三种就是 `word embedding`。做 `word2vec` 的时候我们用的是 `fasttext` 这个库，第一个案例用的是 `one-hot`，后面要么用 `word2vec`，要么一直在用 `word embedding`。

但 `word embedding` **没法把你的文本直接转成词向量**。它转的是**你的词对应的那个编号、那个索引**。所以你必须先构建一个语料库：单词对应哪个索引，叫 `word to index`；为了好查找，一般还会有一个 `index to word`，就是根据索引反查单词。

举个例子：有一个句子叫「欢迎来武汉」，一会儿我要把它解析成什么？`0` 对应「欢迎」——这一步是 `index to word`，根据索引去查单词；`1` 是「来」，`2` 是「武汉」。接下来还要做一件事：把索引 `0`、`1`、`2` 转成词向量形式。所以顺序是——**先基于文本构建词表，再把索引转成词向量**。它只能这么干，没法把词直接转，这就是 `word embedding`。

### 前向传播与缩放

再往下就一个操作了，不需要别的：前向传播函数。

```python
    def forward(self, x):
        return self.embed(x) * math.sqrt(self.d_model)
```

`self` 加上一个待处理的 `x` 就够了。我这里只有一个 `embed`、没有别的代码，那怎么转？`self.embed(x)`，多简单。但写完以后**一般还会在后面乘个东西**——`math.sqrt(self.d_model)`。

先看前面那一半。如果只写 `self.embed(x)` 扔进去，那就是经典的挂羊头卖狗肉、所谓的嵌套：看着好像是你自己的 `embedding`，底层调的其实还是人家自带的 `word embedding`。

再看乘的这一半。它的完整作用是：把输入的单词索引映射为词向量，**并乘以 $\sqrt{d_{model}}$ 进行缩放**。

缩放的目的是**平衡梯度，避免梯度消失或者梯度爆炸**。为什么乘一个根号就能解决？`d_model` 是维度，假设它是四维——四维就是用四个数字来表示你。对它开平方，根号 4 等于 2，就这么一个操作。它防止的是你生成的数太小了，或者太大了。

> **易错点**：有些资料把这一步注释成「与位置编码特征相加」，这个说法不对。`forward` 里乘的是 `math.sqrt(self.d_model)`，做的是**缩放**，目的是保持量纲一致——量纲一致就是单位一致，这样它后面和位置编码的结果才能在同一尺度上叠加，而不是互相淹没。

到这里词嵌入层就定义完了：就是一个 `embedding`，里面自己搞一个 `Embedding` 类就够了。

## 索引越界的报错

跑一下看结果，会看到 `IndexError` 之类的报错。为什么报错？非常简单：**一共 1000 个词，那么最大的索引是多少？999。**

所以刚才随手写的 500、3060 这些，只要超过 1000 就会报错。把 3060 改成 306、再配 509，就没问题了。

> **易错点**：`nn.Embedding` 的合法索引范围是 $[0, \text{vocab\_size} - 1]$，1000 个词意味着索引最大 999，不能超 1000。

改完再看输出，就转成了这样的东西：`512`、`512`、`512` 一串数字——这是第一个句子里那四个单词各自对应的 512 维词向量；后面接着是第二个句子里四个单词对应的维度。所以形状是 `2 4 512`。

```text
   x  : (2, 4)          ← 2 个句子 × 每句 4 个词（存的是单词索引）
        │
        ▼
   self.embed(x)        ← nn.Embedding：索引 → 词向量，(2, 4) → (2, 4, 512)
        │
        ▼
   × math.sqrt(d_model) ← 缩放，保持量纲一致
        │
        ▼
   result : (2, 4, 512) ← 每条数据都是一个 512 维向量
```

读图说明：整个前向传播只有两步——先把索引查成词向量，再乘上 $\sqrt{d_{model}}$ 做缩放，形状从 `(2, 4)` 变成 `(2, 4, 512)`。

到这里，自定义代码模拟词嵌入层就完成了。看起来好像调用的是我们自己的词嵌入层——创建对象那一步也确实是自己写的类——但底层调用的其实还是人家的 `nn.Embedding`，我们做的只是这一层封装。
