## 1. n-gram 的概述、分类与目的

> **定义**：n-gram 是连续判断出来的 n 个词（或 n 个字）所组成的片段，把这些连续片段当作一种特征来使用，它属于小词组特征。

它存在的理由只有一个：帮我们分析文本语义。单个词翻来覆去就那么多信息，把连续几个词当成一个整体打包进去，计算机才更容易抓住词与词的搭配关系，最终要拿到的就是"文本语义"这四个字。

按 n 的取值，它分三类：

| 名称 | 别名 | 切分方式 |
| --- | --- | --- |
| unigram | 1-gram | 把每个词（或字）单独拆出来 |
| bigram | 2-gram | 找连续两个词的组合 |
| trigram | 3-gram | 找连续三个词的组合 |

> **提示**：1-gram 在实战里不用专门实现。jieba 分词切完的结果本身就是 1-gram，每个词都是独立的个体。所以实际开发中 n 一般取 2 或者 3 就够了。

## 3. 生成 n-gram 特征的三个步骤

函数体拆开就是三步：滑动窗口切片、`zip` 组合、集合去重。

### 3.1 滑动窗口切片：sliced_lists

第一个动作是通过滑动窗口获取 n-gram 特征，也就是把原列表按不同的起点切成好几份、错位摆好：

```python
# 通过滑动窗口获取 n-gram 特征
sliced_lists = [input_list[i:] for i in range(n_gram_range)]
```

这里 `range(n_gram_range)` 展开就是 `range(2)`，`i` 只能取 0 和 1，于是得到两份长短不同的切片：

```text
input_list = [1, 3, 2, 1, 3, 2, 1, 5, 3]

i = 0  ->  [1, 3, 2, 1, 3, 2, 1, 5, 3]
i = 1  ->     [3, 2, 1, 3, 2, 1, 5, 3]
```

读图说明：`i = 0` 时切出的是完整列表，`i = 1` 时切出的是"去掉第一个元素"的列表，两者上下错开一位——这就是滑动窗口，错位的位置决定了一会儿能拼出几元组。

### 3.2 zip 与解包：组合成 n-gram 元组

拿到两份错位列表之后，用 `zip` 把它们上下对齐地组合起来：

```python
# 使用 zip 函数对切片列表进行组合
n_gram_tuples = zip(*sliced_lists)
```

关键在 `*`。它是解包：把 `sliced_lists` 这个整体拆成两个独立的列表，分别当作两个参数传给 `zip`，等价于 `zip(list1, list2)`。`zip` 会把同一列上的元素配成一对：

```text
   1   3   2   1   3   2   1   5
   3   2   1   3   2   1   5   3
   |   |   |   |   |   |   |   |
   v   v   v   v   v   v   v   v
 (1,3)(3,2)(2,1)(1,3)(3,2)(2,1)(1,5)(5,3)
```

读图说明：上下两行同一列的元素被绑成一个元组，一共 8 列，所以 `zip` 出来 8 个 2-gram 元组。这里不需要 `map`，`zip` 已经把活干完了。

### 3.3 集合去重：保证结果唯一

第三步把结果转成集合，用 `set` 做去重封装：

```python
# 转换为集合去重，保证结果唯一
return set(n_gram_tuples)
```

为什么一定要套 `set`？看一眼上面那 8 个元组就明白了：因为原数据里 `1 3 2` 这一段重复出现了几次，`(1, 3)`、`(3, 2)`、`(2, 1)` 这几组在结果里各出现了两遍。不套 `set`，打印出来就是 8 个元组；套上 `set`，同样的组合只保留一份，结果收敛到 5 个。用不用集合虽然在本例里看起来差别不大，但它的意义是**保证结果唯一**——将来语料里出现重复片段时，特征不会被重复计数。

完整的实现放在一起是这样：

```python
# 案例：n-gram 特征
# 1. 定义变量：记录 n-gram 中 n 的取值
n_gram_range = 2


# 2. 定义函数：生成 n-gram 特征
def create_n_gram(input_list):
    # 通过滑动窗口获取 n-gram 特征
    sliced_lists = [input_list[i:] for i in range(n_gram_range)]
    # 使用 zip 函数对切片列表进行组合
    n_gram_tuples = zip(*sliced_lists)
    # 转换为集合去重，保证结果唯一
    return set(n_gram_tuples)


# 3. 测试代码
input_list = [1, 3, 2, 1, 3, 2, 1, 5, 3]
result = create_n_gram(input_list)
print(result)
```

## 4. 运行结果解读与 3-gram 的改法

右键跑起来，控制台打印出来的是：

```text
{(2, 1), (1, 5), (5, 3), (3, 2), (1, 3)}
```

有人会问：为什么第一个蹦出来的是 `2 1`？因为这个结果是个集合，集合本身无序，每台机器、每次运行给出的排列顺序都可能不一样——顺序不代表任何含义，你只要确认这五组齐了就行：

- `(2, 1)` 对应原序列中间那一段的 `2` 和 `1`；
- `(1, 5)` 对应 `1` 和 `5` 的相邻组合；
- `(5, 3)` 对应 `5` 和 `3` 的相邻组合；
- `(3, 2)`、`(1, 3)` 同样是相邻两元素拼出来的。

五组正好覆盖了原序列里所有"相邻两元素的组合种类"，一个不多一个不少。

那么如果让你写 3-gram，你会不会做？做法一模一样：把 `n_gram_range` 的 2 换成 3，`range(3)` 就会取到 `i = 0, 1, 2`，切出三份彼此错开一位的列表，`zip` 之后每一列拼出来的是三元组：

```text
input_list = [1, 3, 2, 1, 3, 2, 1, 5, 3]

i = 0  ->  [1, 3, 2, 1, 3, 2, 1, 5, 3]
i = 1  ->     [3, 2, 1, 3, 2, 1, 5, 3]
i = 2  ->        [2, 1, 3, 2, 1, 5, 3]

   1   3   2   1   3   2   1
   3   2   1   3   2   1   5
   2   1   3   2   1   5   3
   |   |   |   |   |   |   |
   v   v   v   v   v   v   v
(1,3,2)(3,2,1)(2,1,3)(1,3,2)(3,2,1)(2,1,5)(1,5,3)
```

读图说明：三元组就是每一列纵向读下来的三个元素，比如第一列是 `(1, 3, 2)`、最后一列是 `(1, 5, 3)`；切片方式、`zip` 组合方式都不变，只是窗口从两层变成三层。这里同样能看出原始结果里存在重复（`(1,3,2)` 与 `(3,2,1)` 各出现了两次），套上 `set` 之后这些重复会被合并掉，剩下 5 个互不相同的三元组。

> **结论**：n-gram 的 n 越大，被保留下来的就是越长的搭配片段，词汇表的维度也会随之增长；2 和 3 是实战里最常用的两档，写法只差一个数字。

> **结论**：n-gram 的代码实现，本质就是"把同一份数据按不同起点切几次得到错位列表，再用 `zip` 把上下元素一组一组配起来"。听上去挺唬人，实际就是一个 `zip` 函数加一次集合去重——它的目的就一句话：让计算机能更好地理解文本语义。
