# 语料词汇统计：用 chain 数清训练集与测试集有多少个不重复的词

`chain` 这个函数刚讲完用法，接下来就该让它上场干活了。这一讲要做的动作叫**词汇统计**——数一数我们的训练集和测试集里，到底有多少个不同的词。

为什么这件事值得单独写一段代码？因为词表规模（vocabulary size）是后面所有环节的地基：词向量矩阵要开多大、词表要不要裁剪、有多少低频词会被判成 `<unk>`，全都看这个数字。所以别把它当成一个"顺便打印一下"的动作。

不过先说清楚一件事：这一段代码不是从头敲的，是**挪过来的**。我们前面板书写步骤的时候，第 4 步被暂时放到了一边，现在把它挪回它该在的位置，顺便把里面那个"4"拆掉——用的时候我再给你写。

## 步骤 4 要干什么：先定函数再填内容

第 4 步的原始描述是"定义函数"。定义来干什么？

获取训练集和测试集的**词汇总数**。这里立刻要回答一个关键问题：

> **定义**：这里说的"词汇总数"，是去重之后的词表规模，而不是语料里出现过的词次总数。也就是说，一个词在语料里出现一万次，在词表里只算一个。

答案就一个字：去重。

函数名定为 `get_word_count`。你也可以不写 `word`，写成 `vocab` 也行，词汇那个单词就是 `vocab`，随便你。我们这里用 `word_count`。

按老规矩，先把骨架搭出来，函数体里先放一个 `pass`，把注释写上"4，测试"，然后把它挪到该待的位置。

## 两步走：先拆句子，再去重

第一行注释写好以后，我开始写第二步。有同学张嘴就是"获取"，我直接怼回去：还获取呢，获个锤子，直接统计训练集的词汇总数。

那怎么写？

```python
train_vocab = set(chain(*map(lambda x: jieba.lcut(x), train_data['sentence'])))
```

写到这儿有人会问：`len` 呢？`len` 哪去了？

**这里最容易搞错的就是这一点**：不要一上来就写 `len(train_vocab)` 然后顺手把它塞进函数体的中间。我们先把去重后的词表拿到手，`len` 留到打印的时候再加。

至于这行代码为什么长这样——非常简单，就是把前面那个两句话的例子拿过来，照着抄，只改一个地方。

区别在哪里？前面那个例子里，`list1` 里装的是"两句话"。现在我不需要两句话，我要的是训练集里**所有的句子**。剩下代码不一样吗？一模一样，抄就完了。（抄都抄不明白，那我真要怼你了。）

拆开看这三层：

| 环节 | 写法 | 干了什么 |
| --- | --- | --- |
| 遍历 | `map(lambda x: jieba.lcut(x), train_data['sentence'])` | 把 `sentence` 这一列的每一个句子都切词，得到一个"切好的词列表"组成的迭代器 |
| 打散合并 | `chain(*...)` | 把每个句子的词列表拆开，首尾相接拼成一个长序列 |
| 去重 | `set(...)` | 把长序列里重复出现的词压掉，只留不同词汇 |

关键在中间那一步的 `*`。`map` 之后我们手里是这种形状：`[['早餐', '不好'], ['前台', '态度', '很好'], ...]`，是一个嵌套结构；`*` 把它解包成一个个列表交给 `chain`，`chain` 再把它们串成一条：`'早餐', '不好', '前台', '态度', ...`。没有这个星号，`chain` 就会把整个嵌套结构当成一个元素，结果完全不是我们要的东西。

```text
train_data['sentence']
        |
        |  map(lambda x: jieba.lcut(x))
        v
[['早餐','不好'], ['前台','态度','很好'], ...]     嵌套的词列表
        |
        |  chain(* ...)   星号解包 -> 逐个列表交给 chain
        v
('早餐','不好','前台','态度','很好', ...)          一条拉直的长序列
        |
        |  set(...)  去重
        v
{'早餐','不好','前台','态度','很好', ...}          词表
```

读图顺序就是数据从一列句子变成一张词表的全过程：先按句子切词，再用星号解包拉直，最后用 `set` 去重。

## 打印与 len 的位置

拿到词表以后打印：

```python
print('训练集共包含不同词汇总数为：', len(train_vocab))
```

有同学说：`len` 应该写在上边那行去重的语句里，也就是 `train_vocab = len(set(chain(...)))`。也可以，我偏不。

**为什么我没把 `len` 写上去？**其实写哪儿都行，无所谓。但写在上面有一个弊端：那个变量从此就只是一个数字了，你只能拿长度。万一我想用里面的不同词汇去做点别的事呢？比如生成索引、做点别的处理，你就做不了了。

放在下面就更灵活：你要长度，我随时加一个 `len`；你要拿着这些不同词汇去生成词向量或者别的什么，`train_vocab` 这个变量本身就能直接上手用。

> **提示**：两种写法结果一样，区别在变量里留的是"词表"还是"词表大小"。留词表更经得住后续折腾，代价是多打三个字符。你说老师我偏要把 `len` 写上边，那无所谓，可以的。

## 测试集照抄，注意变量名和数据列

测试集这一段，有同学上来就写：

```python
len(set(lcut(...)))
```

切怎么拼我都不知道，你想让我给你拼？这行先放着，看正确写法：

```python
dev_vocab = set(chain(*map(lambda x: jieba.lcut(x), dev_data['sentence'])))
```

两点注意：

- 变量名：上面是 `train_data`，这里是 `dev_data`，那我们词表就叫 `dev_vocab`，配套。
- 取列：`dev_data['sentence']`，注意是 `sentence` 这一列，别写成别的。

把这两段合起来，第 4 步的完整函数长这样：

```python
def get_word_count(train_data, dev_data):
    # 1. 统计训练集的词汇总数（去重后的词表规模）
    train_vocab = set(chain(*map(lambda x: jieba.lcut(x), train_data['sentence'])))
    # 2. 统计测试集的词汇总数
    dev_vocab = set(chain(*map(lambda x: jieba.lcut(x), dev_data['sentence'])))

    print('训练集共包含不同词汇总数为：', len(train_vocab))
    print('测试集共包含不同词汇总数为：', len(dev_vocab))
```

运行一下，两个数字就出来了。本身应该是今天最难理解的一些代码，你们都能默写出来，我觉得你们很棒。但写的时候一定要**梳理清其中的每一项都做了什么事**——以后这种链式写法会非常非常多，你要是不熟，光写这里面的组合，这代码自己从头写是不是得写半天？

```python
import jieba
from itertools import chain

# 第 3 步：词性标注、命名实体识别（本节之前已完成）
```

`chain` 取自 `itertools`——就是"链子、链条"，它做的事就是把多个可迭代对象一扣一扣接成一条长链。

## 判断与取舍：哪一步真正需要动脑

回头看，这一节从头到尾一共三个动作，只有第一个动作需要想：

1. **切词**：`jieba.lcut` 把句子切成词，这一步前面已经会了；
2. **拉直**：`chain(*map(...))` 把"一句一个列表"变成"一串词"，关键就是那个星号；
3. **去重**：`set` 把重复词压掉，得到词表。

剩下全是重复劳动：训练集、测试集写两遍，只是把 `train_data` 换成 `dev_data`。所以真正要背下来的不是这两行代码，而是**"要给一批句子做同一件事，就 map 出去；结果是嵌套的，就用星号交给 chain 拉直"**这个组合套路。你以后遇到的清洗、过滤、拼接，十有八九还是它。
