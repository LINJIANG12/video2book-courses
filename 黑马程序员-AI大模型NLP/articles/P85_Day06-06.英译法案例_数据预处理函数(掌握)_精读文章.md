## 读取原始文件并一次性取出所有行

函数的第一个动作是"读取原始文件数据"。用 `with open` 语法打开文件，路径不要重新敲一遍——上面我们已经用变量把那个目录存下来了，把它拉过来就行，这样以后换数据集只改一个地方。

```python
    # 1.1 打开文件，使用 with open 语法读取
    with open(data_dir + 'eng-fra.txt', 'r', encoding='utf-8') as src:
        # 1.2 一次性读取所有行
        lines = src.readlines()
```

`'r'` 是读模式，`encoding='utf-8'` 不能省，`as src` 拿到文件对象，`readlines()` 一次性把每一行读成一个列表元素。

现在有个问题：**一次性读所有行的格式长什么样？** 我猜你不知道。你大概会说"第一行、第二行、第三行"，然后呢？最后会多一个 `\n`。这玩意儿你可能以前玩得少，所以我说了不算，我们调出来看。

先测一下这个函数：

```python
# 测试数据预处理函数
lines = my_get_data()
print(lines[:5])
```

六万多条数据，控制台打印不完，所以在最上面看不到列表最外层的那个中括号，但你能看到每条末尾的换行符号。所以要加切片 `[:5]`——六万多条你哪看得完。

打出来是这样：每一行是「英文句子 + `\t` + 法文句子 + `\n`」。中间那个 `\t` 就是一会儿要切的那一刀，末尾那个 `\n` 是每一行自带的。这两件事后面都要用上，所以先记住了。

> **提示**：`readlines()` 保留行尾的换行符，这不是多余的 `\n` 而是事实——`open()` 默认按行切分时，行尾符号属于这一行。所以只要用 `readlines()`，就一定要意识到"最后多了一个 `\n`"，无论后面是 `strip()` 还是 `split('\t')`，都要把它算进处理链路里。

## 按制表符切分双语句子对

第一个动作（读取原始文件）到此结束。接下来第二个动作：**清洗文本并构建双语句子对**。

句子对或叫句子数，都是同一个东西。我直接写成一个嵌套的推导式，你看能不能听懂：

```python
    # 2. 清洗文本并构建双语句子对
    my_pairs = [
        [normalize_string(s) for s in line.split('\t')]
        for line in lines
    ]
```

先看外面一层：`for line in lines`，`line` 就是你的一行数据，这没问题。里面又来一个 `for s in line.split('\t')`——**注意，这可不是嵌套**，有人会说这是嵌套，差得远。它的意思是：这一行数据在 `\t` 那里切一刀，`\t` 在中间，所以左边是英文、右边是法文；`s` 拿到的是其中一个句子，先拿到英文，遍历完再拿到法文。

然后最外层那个方括号的位置很关键：我要是在 `s` 前面不加东西，那结果就是从这行里把每个句子提取出来；但我还在前面又套了一层中括号，所以每个 `s` 都被 `normalize_string(s)` 处理一遍再作为一个元素收进去。

于是 `my_pairs` 就是**列表嵌套列表**：外层每个元素是一条句子对，内层每个元素是处理过的一个句子，内层长度恒为 2——索引 `0` 是英文，索引 `1` 是法文。

现在把注释写下来：

```python
    # 2.1 for line in lines：获取每一行数据
    #     例如：I'm tired.\tJe suis fatigué.\n
    # 2.2 for s in line.split('\t')：每行数据按 \t 切割
    #     即 [I'm tired. , Je suis fatigué.\n]
    #     再对每个句子调用 normalize_string 做清洗，
    #     清洗后标点前面会带上空格，为后面按空格切词做好准备
```

`normalize_string` 就是上一个函数写好的那套正则替换。它把每个句子里该规整的都规整了，包括一个重要后果：**标点前面一定会带空格**。这一点到第 6 步按空格切词的时候会救你一次，先记住。

顺手确认句子总对数：

```python
print(len(my_pairs))   # 63594
```

六万三千五百九十四对，和原始数据的行数一致——每行一条句子对，没有漏也没有多。

## 数据探查

句子对拿到了，但不能一条都不看。**数据探查**就是查看部分样本数据，看看我的数据大概长什么样，方便下一步处理。

```python
    # 3.1 打印前 5 条双语句子对，直观查看数据格式
    print('前 5 条双语句子对:', my_pairs[:5])

    # 3.2 打印第 7000 条双语句子对，查看特定位置的数据
    print('第 7000 条英文:', my_pairs[7000][0])
    print('第 7000 条法文:', my_pairs[7000][1])
```

3.1 是为了看格式；3.2 是往后跳着抽查，看中间那一段有没有出问题。有人会问这一步有什么意义？没什么特别的意义，就是往后跳一跳，看看数据有没有坏。

`7000` 这个数字没有任何特殊含义，你可以换成七万，前提是得有那么多条。索引本身也是随意的：你要是纠结"第 7000 条"的索引应该是 `6999`，就写 `6999`，无所谓。

但这里有个写法上的坑：

> **易错点**：`my_pairs[7000]` 拿到的是**一整条句子对**（左英文、右法文），而我们要的是句子。所以要在后面再跟一个中括号：写 `0` 取出英文句子，写 `1` 取出法文句子。少写这一层，你看到的就是个长度 2 的列表。

## 英语词汇表与法语词汇表的初始化

第 4 步开始进入正题：**初始化英语词汇表**。

在这个文件里，英语单词和法语单词成千上万，接下来要把它们整合到一起。怎么整合？

```python
    # 4.1 创建单词到索引的字典映射
    #     预先放入特殊标记：SOS 句子开始索引为 0，EOS 句子结束索引为 1
    english_word_to_index = {
        SOS_token: 0,
        EOS_token: 1
    }

    # 4.2 初始化英语词汇表大小计数器，初值为 2（已包含 SOS 和 EOS）
    english_word_n = 2
```

`english_word_to_index` 的键是单词，值是索引。字典里一开始就放两个特殊标记：`SOS`（Start Of Sentence，句子开始）索引 `0`，`EOS`（End Of Sentence，句子结束）索引 `1`。

**为什么是 2 而不是 0 起步？** 因为上面那两个特殊标记是没有对应单词的，它们是我们人为往字典里加进去的；计数器是用来数"英语词汇表里一共有多少个单词"的，现在里面已经躺着两个了，所以从 2 开始记。

> **提示**：这里有两种写法——索引位置直接写 `0` 和 `1`，或者写 `SOS_token` 和 `EOS_token`。两种写法完全等价，因为上面已经把 `SOS_token` 定义成 `0`、`EOS_token` 定义成 `1` 了。**实际开发我一定写下面这种带变量名的**，因为专业。你可能会问同事看不懂怎么办？你要相信，能和我成为同事的能力不会特别差，他看得懂。

第 5 步把同样的事在法语侧再做一遍，只把 `english` 换成 `french`：

```python
    # 5. 初始化法语词汇表和词汇表大小计数器
    french_word_to_index = {
        SOS_token: 0,
        EOS_token: 1
    }
    french_word_n = 2
```

到这里词汇表有了、大小也有了，接下来就是"每往里边加一个英语单词，计数器加 1；每加一个法语单词，计数器也加 1"。词汇表就这么自己长出来了。

## 英语词汇表的构建：遍历句子对、按空格切词、分配索引

第 6 步是这一讲最烧脑的地方，跟紧。

```python
    # 6.1 遍历所有双语句子对
    for pair in my_pairs:
        # 6.2 英语句子按空格切割成单词列表，再遍历每个单词
        for word in pair[0].split(' '):
            # 6.3 检查单词是否已在词汇表中，不存在则分配新索引
            if word not in english_word_to_index:
                english_word_to_index[word] = english_word_n
                english_word_n += 1
```

先说 `pair` 的数据格式：`[英文句子, 法文句子]`，长度就是 2，所以 `pair[0]` 是英语，`pair[1]` 是法语。

6.2 问的是"英语句子按什么切割"——**按空格**。你可能会注意到切出来的点号前面也带空格，那要么是原文自带，要么是 `normalize_string` 处理过以后一定带上。这样切的好处是绝对不会出现 `you!` 这种粘在一起的记号：一定是 `you` 一个、`!` 一个，两个独立的词元。

6.3 是这一段的核心：`if word not in english_word_to_index`，这个单词没在我的字典里，就给它分配一个新索引。新索引值等于**当前词汇表的大小**。

为什么可以这么算？来看这条链子。字典现在刚好有 2 个元素（`SOS`、`EOS`），新来的单词该拿 `2`——配上。字典有 5 个元素时，索引是 `0` 到 `4`，新来的刚好该拿 `5`——又配上。一句话：**新索引 = 字典当前长度**。所以直接写 `english_word_n`，不用另算一遍。

分配完别忘了那个小细节：计数器加 1，变成 3，下次再来新词它的索引就是 3。

> **易错点**：`if` 这个判断绝对不能省。字典的键是唯一的，如果同一个词前面已经登记过，你后面又给它 `[word] = 新索引`，那就把老索引覆盖掉了。同一个词拿到两个不同的编号，词表和索引的对应关系就崩了。

第 6 步和第 6.4 步是并列的：法语侧一模一样，只是 `pair[0]` 换成 `pair[1]`，`english_word_to_index` 换成 `french_word_to_index`，计数器换成 `french_word_n`。

```python
        # 6.4 法语句子按空格切割成单词列表，再遍历每个单词
        for word in pair[1].split(' '):
            if word not in french_word_to_index:
                french_word_to_index[word] = french_word_n
                french_word_n += 1
```

## 反向映射表的构建

第 7 步：**构建反向映射表**。先问一句，刚才建的是什么到什么的映射？单词到索引——单词是键，索引是值。那反向就是索引到单词。

```python
    # 7.1 英语词汇表反向映射：索引 -> 单词
    english_index_to_word = {v: k for k, v in english_word_to_index.items()}

    # 7.2 法语词汇表反向映射：索引 -> 单词
    french_index_to_word = {v: k for k, v in french_word_to_index.items()}
```

写法简单到离谱：遍历刚才那个字典拿到 `k` 和 `v`，把顺序换过来就行。为什么非要这一份反向的？因为将来模型算出来的是编号，你得有办法拿编号把原词找回来。

```text
   原始语料文本
        |
        v
   normalize_string 清洗（标点前补空格）
        |
        v
   [英文句子, 法文句子]   句子对，内层长度 2
        |
        +--> pair[0].split(' ') --> 英文词元 --> english_word_to_index --> 索引
        |
        +--> pair[1].split(' ') --> 法文词元 --> french_word_to_index  --> 索引
                                                    |
                                                    v
                                        english/french_index_to_word
                                              （反向查回原词）
```

读图说明：清洗之后的句子对往两个方向分流，英文走英语词表、法文走法语词表各拿到一个整数编号，而反向映射表负责把编号再翻译回原词，两条路互为逆运算。

## 词汇表统计与函数的返回结构

第 8 步打印词汇表统计信息：

```python

    print('英语词汇表大小:', english_word_n)   # 2803
    print('法语词汇表大小:', french_word_n)    # 4345
```

这两个数字什么意思？六万多个句子里，一共只出现了 2803 个不同的英语单词、4345 个不同的法语单词。这也顺带说明为什么要用字典去重——如果不去重，六万多句里同一个词会被登记无数次。

> **提示**：这里用 `english_word_n` 和用 `len(english_word_to_index)` 得到的值是一样的，因为计数器就是跟着字典长度同步长起来的。两种都可以，但一定要保证二者一致，否则说明加词的时候漏了加一。

第 9 步，最后一步，返回构建好的数据结构：

```python

```

一共七样东西：英语单词到索引的映射、英语索引到单词的反向映射、英语词汇表大小、法语单词到索引的映射、法语索引到单词的反向映射、法语词汇表大小、双语句子对。
