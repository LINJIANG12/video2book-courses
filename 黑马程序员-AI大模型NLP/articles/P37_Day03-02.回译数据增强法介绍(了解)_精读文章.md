# 回译数据增强：用翻译接口把一句话变成一堆语料

## 数据不够用的时候怎么办

假设你手上只有一句话：「你今天真好看」。老板让你训一个模型，数据集就这么一行。这时候你只有两条路：要么去标注更多数据，要么想办法把这一句话变成十句话。

回译数据增强法是后一条路上的常规手法。它的名字听起来拗口，做起来却简单得有点不像技巧：把中文翻成外语，再把外语翻回中文，得到的就是「意思差不多、话术不一样」的新句子；把新句子塞进原始数据集，数据量就上去了。

这一讲我们先把它了解清楚就够了，不写代码演示。原因很直接：传统做法要调翻译接口，课件里用的是有道翻译，而这个公用接口已经被封掉了，现在你打开会直接提示页面无法访问。

> **提示**：接口封了不代表这条路断了。想自己动手，就去有道的开发平台（智云 AI 开放平台）注册账号、做登录，在产品服务里找「大模型翻译」「文本翻译」这类能力，开通后拿一个 API key 就能用；如果只是少量玩一玩，往账号里充一点钱也够。后续到了大模型阶段，我们更省事——直接让通义的千问 Plus、千问 Max 这类模型帮我们翻译，连接口协议都不用对。

## 回译数据增强法的定义与原理

> **定义**：文本回译数据增强法（back-translation data augmentation），指把文本翻译成另一种语言，再翻译回原语言，用「语义相近、表述不同」的新语料扩充原始数据集，从而实现数据增强。

剥掉这层术语，它其实就两句话：

- 数据增强指的是什么？增加你的数据量；
- 怎么增强？中文翻出去，再翻回来。

先看一个最容易想通的例子：中文「你今天真好看」，翻成英文，再翻回中文，这句话的意思会变吗？大概率不会。因为汉语和英语都是大语种，这两者之间来回翻译，意思非常接近——翻过去翻回来，你拿到的几乎是同一句话，增强不出什么新东西。

所以关键在于**中间那几种语言要换掉**。而选语言的原则就一条：**一般选择小语种**。

为什么是小语种？因为汉英这种大语种互译，出入太小，回来还是原句。换成小语种之后，翻译链路里多了模型「转述」的空间，回到原语言时，你拿到的就是意思相近、但话术陌生的句子——这正是我们想要的语料。

哪些算小语种？阿尔巴尼亚语、斯瓦希里语、毛里求斯当地的语言、阿拉伯语等等，这些都可以拿来当中转站。

```text
中文原句
   |
   +--> 目标语言 A（小语种）--> 目标语言 B --> 目标语言 C
   |                                              |
   +----------------------------------------------+
                       |
                 回译回中文
                       |
            意思相近、表述不同的新语料
```

上图是回译增强的基本链路：原句先翻出去，可以经过一种或几种中间语言，最后一定要回到原语言；带回来的那句话才是新增语料。

## 优势、问题与边界

回译法的优势，按课上给的两条记就行：**操作简单**，**获取新语料的质量高**。质量高是因为译文的意思和原句非常接近，不会引入风马牛不相及的内容，同时内容表述又确实不同，等于给数据集加了「同义换说法」的样本。

它的问题是：**短文本回译中，新语料和原语料可能存在很高的重复率，并不能有效增大特征空间**。

> **易错点**：这条限制只对**短文本**成立，别把它当成回译法的通病。

拿「我爱你」来想就明白了。三个字，翻译链路里模型没有多少改写的余地，绕一圈回来还是「我爱你」或者「我爱着你」这种程度的差别，重复率自然高。反过来，文本越长，回译增强法生成的新数据就越好——长句里有更多可以被重新组织的成分，回来的表述才会真正拉开差距。

高重复率怎么破？办法是**连续多次的多语言翻译**，例如：

```text
中文 -> 韩语 -> 日语 -> 英语 -> 中文
```

注意这条链上一共翻了几次：中到韩、韩到日、日到英、英到中，是四次翻译、三个中间语种。课上给的经验值是**中间语言一般不超过三个**。

> **结论**：中间语种控制在三个以内。更多的翻译次数会带来两个坏处——效率低下，以及语义失真。

为什么强调上限？这就要请出「三人成虎」这个成语了。三人成虎说的不是三个人凑一起变成老虎，它说的正是谣言：一句话被反复转述，越传越走样，最后没人记得原话是什么，所谓「人言可畏」「谣言止于智者」都是这个意思。回译链路每多一环，就多一次这种走样，翻到第四第五种语言，回来的句子可能已经偏离原意了。

## 用豆包走一遍完整流程

接口封了，但我们并不需要为此写代码才能看到效果。打开豆包，把流程用提示词说清楚就行。

先给它一句话，加上双引号：

```text
"你今天
真的
好好看啊，
哎什么，真的是。"
```

然后写我们的翻译指令：

```text
请帮我先翻译成英文，再翻译成韩文，再翻译成毛里求斯语，再翻译成阿尔巴尼亚语，
最后再翻译成中文。
然后注意，翻译后的文本不能和原文一模一样，但是核心意思不变。
```

这里插一个问题：同一个模型，为什么有些人用起来很顺手，有些人觉得不好用？区别在下面写的这段提示词上。也正因为这个差别，才出现了一个岗位——**提示词工程师（Prompt Engineer）**，主要工作就是写提示词、做模板，然后把模板交给 AI 算法工程师去批量生成数据。

课程里那个真实例子值得记住：25 年第一个班，北京 237 班有个女孩子做的就是 Prompt 提示词方向，回校区玩的时候被问到薪资，她比划了一个「二」一个「五」，人家说运气好。这个岗位正常 15K 起，赶上风口可能高很多。顺着这个话往下想一层：大厂里随便拉一个程序员出来，能力都值月薪三万五万吗？不是的。有些时候不是人很厉害，而是那个平台很厉害。

回来说豆包的输出。英文、韩文、阿尔巴尼亚语我们不会念，但最后那一步的中文结果很清楚：

```text
你今天的模样也太惊艳了吧。
```

和原句「你今天真好看」意思接近，但表述已经换了一套，这就是回译增强的成品。

再直白一点，我们把提示词换成扩充指令：

```text
"你今天真好看"，
请帮我将上面的一段话扩充为十段话，或者说十句话，然后听好了，核心意思不变。
```

于是就从一个句子得到了一批句子：

- 你今天真好看，整个人状态显得特别亮眼，一眼看过去让人特别舒服；
- 不得不说你今天真好看，不管是神态、穿搭，或者别样的气质；
- 认真说你今天真好看；
- 你今天真好看，简简单单；
- 真心觉得你今天真好看；
- 忍不住想说……

语料数目实实在在地变多了，而语义没有跑偏。

> **结论**：回译数据增强法就是通过多轮翻译、最后回译回原语言，用来增加数据量的一种手段。执行时不必限定豆包，换成通义、星火，或其它大模型都能做同样的事。

## 文本特征处理与长度规范

到这一讲的最后，把文本特征处理这条线快速串一遍——它和回译增强是一套东西里的不同环节。

> **定义**：文本特征处理是给文本增加普适性的一类预处理操作，常用方法有 n-gram、文本长度规范、本文要讲的文本数据增强。

**n-gram** 的做法是把连续几个词当作一个整体来处理。实现上用一个函数搞定：把词序列错位组合起来，也就是用 `zip` 配合星号展开做错位，再用 `range` 控制截取到几元，最后用 `set` 把结果拼成唯一的词表。写成代码就是这样一个结构：

```python
def create_ngram_set(input_list, n):
    return set(zip(*[input_list[i:] for i in range(n)]))
```

这段代码里，`input_list[i:] for i in range(n)` 生成 $n$ 条互相错位的词序列，`zip(*...)` 把它们按位置对齐、每次取出 $n$ 个相邻词组成一个元组，`set` 负责去重——同一组连续词只留一份。

**文本长度规范**解决的是模型对输入长度的要求。模型不接受参差不齐的输入：有的句子长度是 13，有的是 6，这种情况不被允许，必须统一。

具体做法是自定义一个统一长度，然后**超长的截断，不够的补齐**。这里有两个需要你自己把控的决策点：从前面截还是从后面截，往前面补还是往后面补。课上的说法是结合自己的实际业务情况来定——这几句关键信息在句首还是句尾，决定了你该砍哪一头。

## 本讲提到的题目

这一讲在总结文本特征处理时提出了一组需要回答的问题，整理如下。

**题 1** 文本特征处理的概念是什么？常用的方法有哪些？

答：文本特征处理指给文本增加普适性的预处理操作。常用方法有三类：`n-gram`（把连续几个词作为一个整体）、文本长度规范（把所有句子长度统一）、文本数据增强（扩充语料）。

**题 2** 添加 n-gram 如何实现？

答：通过一个函数完成——用 `zip` 配合星号展开做错位组合，用 `range` 截取到 $n$ 元，最后用 `set` 拼成唯一的词。

**题 3** 文本长度规范的作用是什么？

答：因为模型对输入数据有长度要求，长度必须统一。做法是自定义统一长度，超过的截断、不足的补齐；截断与补齐的方向要结合业务实际来确定。

**题 4** 文本数据增强的作用是什么？通过回译数据增强法能带来什么，好处与坏处分别是什么？

答：作用是增加语料，通过回译数据增强法可以增加语料的数目。好处是操作简单；坏处是短文本容易重复，且翻译次数多了语料容易失真。

**题 5** 数据量非常充裕的时候，还需要用文本数据增强吗？

答：不需要。
