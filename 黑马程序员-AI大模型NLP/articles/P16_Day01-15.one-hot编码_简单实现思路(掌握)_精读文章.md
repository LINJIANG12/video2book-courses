# One-Hot 编码的手工实现：从词表到索引映射

前面我们一直借 `Tokenizer` 去生成索引、生成编码，那个过程能用，但绕：要禁用 `1D-CNN`，要设置这个那个，还得装包，一堆配置层层叠上去。这一节我把这套东西拆掉——不装第三方包，自己搭一份词典出来，只用最朴素的手段把 One-Hot 编码算出来。做法简单到什么程度？词典是几行代码，编码是四步循环，跑完的结果还跟 `Tokenizer` 那边完全一致。

## 准备语料库

第一个动作永远是准备。语料库就是我们前面已经切好词的那些内容，变量名沿用 `vocabs`：

```python
vocabs = ['微微', '周杰伦', '晴天', '稻香', '七里香']
```

这份数据是前面代码里跑出来的切词结果，直接搬过来即可。这一步没有任何花活，但它决定了后面所有东西的规模——词表里有几个词，待会儿那个全 0 列表就得有多长。

## 构建词汇到索引的映射

第二个动作，构建词汇到索引的映射关系。说穿了就是一个字典，名字起成 `word_to_index`：

```python
word_to_index = {vocab: i for i, vocab in enumerate(vocabs)}
print(word_to_index)
```

这里要问一句：既然前面用 `Tokenizer` 也生成索引，为什么还要自己动手？因为 `Tokenizer` 的底层怎么给你编这个号，我们其实不知道，而且它的编号每次生成都可能不一样。可如果只是"给每个词加个编号"这活，我自己就能干——往后边加个数据不就行了。

写法上有一个关键判断：**谁是键、谁是值**。词是键，索引是值，所以字典里是 `vocab: i` 这个方向，不是 `i: vocab`。

`enumerate` 的作用是同时拿到下标和元素。`enumerate(vocabs)` 第 0 次给出 `0` 和 `'微微'`，第 1 次给出 `1` 和 `'周杰伦'`，以此类推；`i` 是编号，`vocab` 是词，写进字典就是"词 → 编号"。

> **易错点**：不要为了"让编号从 1 开始好看一点"而写成 `i + 1`。位置本身就是编号，直接从 0 对位即可；你在映射表里加了 1，后面取用的时候还得减回来，纯属给自己挖坑。

字典还有个性质值得提前记住：它的遍历顺序跟插入顺序一致。也就是说，只要 `vocabs` 的排列不变，这套编号跑多少次都是同一份结果，稳定可复现。

## 对每个词做 One-Hot 编码

第三个动作，对词表里的每个词生成它的 One-Hot 向量，四步：

### 初始化全 0 列表

列表长度等于语料库长度，也就是词表里的词数：

```python
zero_list = [0] * len(vocabs)
```

这和前面讲过的做法一样——先造一个全是 0 的列表，长度跟词表对齐。

### 查当前词的索引

拿词去刚才那张表里查编号：

```python
index = word_to_index[vocab]
```

> **提示**：索引从 0 开始，所以这里不需要做任何加减。前面那步不加 1，这一步自然就不用减 1。

### 把对应位置改成 1

```python
zero_list[index] = 1
```

到这一步，编码就算完成了：找到这个词自己的位置，把那个位置改成 1，其余位置原封不动。

### 打印结果

```python
print(vocab, zero_list)
```

完整跑一遍：

```python
# 1. 准备语料库：切词并去重后的词表
vocabs = ['微微', '周杰伦', '晴天', '稻香', '七里香']

# 2. 构建词到索引的映射关系（词是键，索引是值）
word_to_index = {vocab: i for i, vocab in enumerate(vocabs)}
print(word_to_index)

# 3. 对每个词进行 One-Hot 编码
for vocab in vocabs:
    zero_list = [0] * len(vocabs)      # 3.1 初始化全 0 列表，长度 = 词表长度
    index = word_to_index[vocab]       # 3.2 查当前词的索引
    zero_list[index] = 1               # 3.3 把对应位置的元素改为 1
    print(vocab, zero_list)            # 3.4 打印结果
```

输出就两种样子：`'微微'` 排在第 0 位，得到 `[1, 0, 0, 0, 0]`；`'周杰伦'` 排在第 1 位，得到 `[0, 1, 0, 0, 0]`；后面的词依次往后错一位。每个词的向量长度都是 5，因为词表就是 5 个词。

这里有个非常关键的对照：整个过程用没用结巴分词？没用。用没用 `joblib`？没用。用没用 `Tokenizer`？也没用。最朴素的手段就能把这段代码写完，你要真把这个版本玩熟，我个人觉得这一个就够用了。

## 词汇表的顺序与手工调整

既然索引就是位置，那么"谁排第几"直接决定编码结果。这一点其实挺好用。

假设 `'微微'` 当前在第 0 位、编码是 `[1, 0, 0, 0, 0]`，而我们希望它拿第 6 号位置，怎么改？改词表顺序、或者直接改映射表里那个数字都行——手工把 `'微微'` 的编号设成 6，它就落到位了。没有玄学，就是"号码 → 位置"的对应关系。

那什么时候没必要手工折腾？数据量非常大、而且映射关系每次都要固定下来、又想让它有些变化的时候，就可以把上面那个 `Tokenizer` 拿回来，用它反过来做一层约束。工具是为需求服务的，不是反过来。

## 优缺点与稀疏性问题

One-Hot 的优缺点都很干净，值得一次记牢。

> **定义**：One-Hot 编码（One-Hot Encoding），也叫独热编码、0-1 编码。它的表示形式是把分类变量转换为数字模式——有这个词的位置标记为 1，没有的位置标记为 0。

**优点是操作简单、容易理解。** 说白了就是搞一个全是 0 的列表，找到你的位置，把那个位置改成 1，其余位置不变，这就是 One-Hot 编码。

**缺点有两条，第二条是致命的。**

第一条，它完全割裂了词与词之间的联系。`'微微'` 是 `[1, 0, 0, 0, 0]`，`'周杰伦'` 是 `[0, 1, 0, 0, 0]`，除了 1 的位置不同，两个向量之间再找不出任何可比较的信息，词与词的关系被彻底切断了。

第二条，大语料下每个向量的长度过大，占用大量内存，而且极其稀疏。词表有 100 个词，一个词的向量就是 1 个 1 加 99 个 0；词表有 10 万个词，就是 1 个 1 加 99999 个 0。

> **易错点**：别以为 0 不占空间。那 99999 个 0 照样要存进内存，向量长度一上去，内存和计算量跟着一起上去。

所以它属于**稀疏词向量表示（sparse representation）**。

| 维度 | One-Hot 编码 |
| --- | --- |
| 向量长度 | 等于词表大小 |
| 每行非零元素 | 恰好 1 个 |
| 词间语义关系 | 完全割裂 |
| 大词表表现 | 长度爆炸、极度稀疏、内存开销大 |
| 实现难度 | 一个全 0 列表加一次下标赋值 |

这张表里最后一行正是它的优点，前三行正是它的代价。

## 走向稠密向量

抛砖是为了引玉。既然病根是"稀疏"和"割裂"，那解法也就明摆着了：你是稀疏的，那我就找一对不稀疏的、稠密的向量来表示词。

于是就有了接下来要学的东西——**稠密向量表示法**，也就是 **Word2Vec** 和 **Word Embedding（词嵌入）**。它既能把词与词之间的联系保留下来，又不会像 One-Hot 那样把内存白白吃掉。

> **结论**：One-Hot 的价值在于"把文本变成模型能吃的数值"这件事本身，而不是它作为词向量的质量。它解决了"从无到有"，稠密向量解决"从有到好"。

从整体流程看，这一步的位置很清楚：先分词去重，再构建映射，然后编码成向量，向量质量不够好，就换更高级的表示法。

```text
原始文本
   |
   v
分词 + 去重  -->  词表 vocabs
   |
   v
构建 word_to_index（词 -> 编号）
   |
   v
逐词生成 One-Hot 向量（长度 = 词表大小，仅一位为 1）
   |
   v
稀疏且割裂  -->  改用稠密向量表示（Word2Vec / Word Embedding）
```

读图说明：One-Hot 处在"文本张量化"的最后一步，它的输出直接决定下游模型能拿到什么；图上最后那个箭头，就是下一讲要展开的内容。

## 本讲提到的题目

**第 1 题（单选）**：One-Hot 编码中，对应一个有 $n$ 个不同类别的分类变量，编码后的向量维度是多少？

- A. $n$
- B. $n - 1$
- C. $n + 1$
- D. 固定为 2

> **答案**：A。解析：One-Hot 的向量长度等于词表（类别）的个数——5 个词，向量的长度就是 5；10 个词，长度就是 10。每个词占一个位置，位置总数就是类别总数。

**第 2 题（单选）**：什么时候会发生维度爆炸？

- A. 分类变量取值较少时
- B. 分类变量取值较多时
- C. 分类变量连续取值时
- D. 分类变量取值固定时

> **答案**：B。解析：维度爆炸指的是向量维度随类别数量一起膨胀。设想有 10 万个词，一个词的向量就是 1 个 1 加 99999 个 0，模型根本没法训练。类别越多，向量越长，维度爆炸越严重，所以选 B。
