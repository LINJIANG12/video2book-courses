## 1. 文本张量表示的方法谱系

> **一句话主旨**：说明为什么必须把文本转成数值，并给出稀疏与稠密两条表示路线的划分与各自定位。

### 1.1 文本张量的定义与落地形态

* **文本张量表示（text tensor，词向量表示法）**
    * > 定义：先对文本**切词**，再把每个词转成对应的**词向量**，用词向量的形式来描述文本。
    * 动因：模型底层是矩阵运算器，无法直接解析文本，必须先转成数值才能作为输入。
    * 一个词用 $k$ 个数字表示，它就是 $k$ 维向量；一句话的多个词向量按行堆叠，得到 **词向量矩阵**，这就是文本张量的落地形态。
    * 例：3 个词、每词 5 个数字，堆成 $3 \times 5$ 的词向量矩阵。
    * 作用：把文本表示成张量（矩阵）形式，方便输入计算机程序运算处理。
    * > 来源: P13, P14

### 1.2 稀疏表示法与稠密表示法

* **稀疏词向量表示（sparse representation）与 one-hot**
    * `one-hot` 编码是稀疏表示法：有这个词就是 1，没有就是 0，词一多就是一大堆 0 加一个 1，数据分布离散。
    * `one-hot` 的优点就是简单，有就是 1、没有就是 0，这是最直白的思路。
    * > 来源: P13, P16

* **稠密词向量表示（dense representation）**
    * `Word2Vec` 与 `Word Embedding` 都属于稠密向量表示法。
    * 因果顺序：**正因为 one-hot 是稀疏的，才有了后续的 Word2Vec 与 Word Embedding 这些稠密表示法**。
    * 分工：one-hot 解决「从无到有」，稠密向量解决「从有到好」。
    * > 来源: P13, P16

### 1.3 三种表示法的定位

* **三种表示法的定位**
    * 文本张量表示在整体流程里的位置：先分词去重得到词表，再构建映射，然后编码成向量；向量质量不够好，就换更高级的表示法。
    * > 来源: P13, P14

| 方法 | 表示类型 | 别名与内部方案 |
| :--- | :--- | :--- |
| one-hot 编码 | 稀疏词向量表示法 | 独热编码、01 编码 |
| Word2Vec | 稠密词向量表示法 | CBOW（连续词袋模式）、skip-gram（跳字／跳词模式） |
| Word Embedding | 稠密词向量表示法 | 词嵌入表示法，用 fastText 完成 |

## 2. one-hot 编码的构造与边界

> **一句话主旨**：给出 one-hot 向量的构造规则、长度来源、顺序敏感性与封闭词表四条硬边界，并列出它的代价。

### 2.1 构造规则与长度口径

* **one-hot 编码（one-hot encoding，独热编码 / 01 编码）**
    * > 定义：一种稀疏的词向量表示，把分类变量转换为数值格式，一般用于 AI 任务中处理分类标签 $y$ 的数据。
    * 构造规则：对于具有 $n$ 个不同类别的分类，用 $n$ 维向量表示，其中**有一个维度是 1，其他维度全是 0**。
    * 例（红绿蓝按此顺序）：红色 `1 0 0`、绿色 `0 1 0`、蓝色 `0 0 1`；换成词也一样：改变 `1 0 0 0`、要 `0 1 0 0`、如何 `0 0 1 0`。
    * 列表长度（向量维度）等于**文本切词去重后的总长**，不是词的总数；一定要去重，是切词、去重之后的总长。
    * 这样能保证列表中只有一个 1，其他全是 0，绝不会出现两个 1。
    * > 易错点：顺序一变，向量就得跟着变。词的排列顺序一调，每个词对应的 0/1 排列也要全部重排，这是写代码时最容易出错的地方。
    * > 来源: P13, P14

### 2.2 封闭词表边界

* **封闭词表边界**
    * `word_index` 的键只包含训练语料里出现过的词；传入词表外的词，`word_index[token]` 直接抛 `KeyError`，编码无从谈起。
    * 模型能力范围严格等于训练它的那个词表：词表里没有的词，既不会猜也不会近似，只会告诉你找不到。
    * > 来源: P13, P15

### 2.3 优缺点与稀疏代价

* **优缺点与稀疏代价**
    * 优点：操作简单、容易理解——搞一个全是 0 的列表，找到自己的位置改成 1，其余不变。
    * 缺点一：完全割裂词与词之间的联系。`微微` 是 `[1,0,0,0,0]`、`周杰伦` 是 `[0,1,0,0,0]`，除 1 的位置不同外再无任何可比较信息。
    * 缺点二（致命）：大语料下向量长度过大、占用大量内存且极其稀疏。词表 100 个词 → 1 个 1 加 99 个 0；词表 10 万个词 → 1 个 1 加 99999 个 0。
    * > 易错点：别以为 0 不占空间，那 99999 个 0 照样要存进内存，向量长度一上去，内存与计算量跟着一起上去。
    * > 来源: P16

| 维度 | One-Hot 编码 |
| :--- | :--- |
| 向量长度 | 等于词表大小 |
| 每行非零元素 | 恰好 1 个 |
| 词间语义关系 | 完全割裂 |
| 大词表表现 | 长度爆炸、极度稀疏、内存开销大 |
| 实现难度 | 一个全 0 列表加一次下标赋值 |

## 3. one-hot 的两套实现

> **一句话主旨**：给出依赖第三方词汇映射器的完整实现路径与索引易变问题，以及不依赖任何第三方包的纯 Python 等价实现。

### 3.1 依赖与导包

* **依赖与导包**
    * 切词用 `jieba`（结巴分词器）；对象保存与加载用 `joblib`；索引映射用 `Tokenizer`。
    * `pip install tensorflow==2.19.0`，版本最好保持一致；`conda search tensorflow` 可查可用版本，最新已到 `2.20`，且分 CPU 版与 GPU 版两种情况，先装 CPU 版。
    * 导入方式：`from tensorflow.keras.preprocessing.text import Tokenizer`。
    * 导包后编辑器会在 `keras` 一行报红，**不影响使用**。
    * > 来源: P13, P14

### 3.2 词汇映射器与索引减 1

* **Tokenizer（词汇映射器）**
    * > 定义：把词映射成编号的工具，`fit_on_texts` 在语料上学习映射关系，`word_index` 给出「词 → 索引」字典。
    * 实现步骤四步：准备语料 → 实例化并 `fit_on_texts` → 建全 0 列表 `[0] * len(...)` → 按索引把对应位置改成 1。
    * 索引由 `Tokenizer` 生成的顺序决定，**从 1 开始编号**；Python 列表下标从 0 开始，所以取索引后要减 1。
    * 例：某词序号为 2，减 1 得 1，把下标 1 的位置改成 1。
    * `word_index` 会基于喂进去的数据做一次排列，不保证与你写的语料顺序一致。
    * > 易错点：零向量长度写成了 `len(vocab)` 而不是 `len(vocab_s)` 也能跑，但读出来的是单词的字符数，结果全错——典型表现是每个向量都是三个 0，因为人名都是三个字。它跟词有几个字无关，关键是你取的长度对不对。
    * > 易错点：`Tokenizer` 生成的编号从 1 起、列表下标从 0 起，漏掉减 1，1 号词的 1 会落到 2 号位上，整张表整体错位一格，而且不报错。
    * > 来源: P14, P15

### 3.3 索引稳定性与模型落盘

* **索引稳定性：不保存就每次都不一样**
    * 每次重新运行生成脚本，都在 `fit_on_texts` 里重建一遍映射关系，同一批词跑出来的编号每次都不一样：第一次王力宏是 `100000`，再跑一次李薇薇变成 `010000`。
    * 编号变了，同一个词的 0/1 位置就跟着变，昨天的编码今天用不了，所以生成与使用必须拆成两段脚本。
    * 稳定性靠**把结果冻结下来**保证：`joblib.dump(my_tokenizer, './model/onehot_tokenizer.pkl')` 写在 `for` 循环外面。
    * 后缀 `.pkl` 行不行、`.pth` 行不行——都行，甚至不写后缀名也行；`./model` 目录不存在要自己先建。
    * 使用侧三行：`joblib.load` 读回映射器 → 打印 `word_index` → 对指定词建零列表、查索引减 1、改 1 并打印。
    * 使用侧零向量长度不再取语料长度，而是**「词 → 索引」字典的长度**：字典有几对键值就造几个 0。
    * > 来源: P14, P15

### 3.4 纯 Python 简易版实现

* **纯 Python 简易版实现**
    * 语料：`vocabs = ['微微', '周杰伦', '晴天', '稻香', '七里香']`。
    * 建映射：`word_to_index = {vocab: i for i, vocab in enumerate(vocabs)}`——**词是键、索引是值**；`enumerate` 同时给出下标与元素。
    * 四步出码：`zero_list = [0] * len(vocabs)` → `index = word_to_index[vocab]` → `zero_list[index] = 1` → 打印。
    * 输出：`'微微'` 在第 0 位得 `[1,0,0,0,0]`，`'周杰伦'` 在第 1 位得 `[0,1,0,0,0]`，每词向量长度都是 5。
    * 整个过程不用 `jieba`、不用 `joblib`、不用 `Tokenizer`；字典遍历顺序与插入顺序一致，只要 `vocabs` 排列不变，编号跑多少次都稳定可复现。
    * > 易错点：不要为了让编号从 1 开始好看而写成 `i + 1`；位置本身就是编号，直接从 0 对位。映射表里加了 1，取用时还得减回来。
    * 要改某个词的位置，改词表顺序或直接改映射表里的数字即可；数据量非常大、映射关系要固定又想要点变化时，再把 `Tokenizer` 拿回来用。

    ```python
    # 1. 准备语料库：切词并去重后的词表
    vocabs = ['微微', '周杰伦', '晴天', '稻香', '七里香']

    # 2. 构建词到索引的映射关系（词是键，索引是值）
    word_to_index = {vocab: i for i, vocab in enumerate(vocabs)}
    print(word_to_index)

    # 3. 对每个词进行 One-Hot 编码
    for vocab in vocabs:
        zero_list = [0] * len(vocabs)      # 3.1 初始化全 0 列表，长度 = 词表长度
        index = word_to_index[vocab]       # 3.2 查当前词的索引
        zero_list[index] = 1               # 3.3 把对应位置的元素改为 1
        print(vocab, zero_list)            # 3.4 打印结果
    ```

    * > 来源: P16

## 4. Word2Vec 原理与两种模式

> **一句话主旨**：给出 Word2Vec 用隐藏层权重矩阵充当词向量的核心结论，并区分 CBOW 与 Skip-Gram 的输入输出方向、样本切法与适用词频。

### 4.1 隐藏层权重矩阵与维度口径

* **Word2Vec**
    * > 定义：把单词转化为词向量的 NLP 技术，用深度学习的网络权重参数表示向量。
    * 词向量的唯一交付物是**隐藏层的权重矩阵**：训练时两个权重矩阵都在更新，最后拿出来当词向量的只有隐藏层那一个；输出层那个矩阵的作用是算预测值，它只是个过渡。
    * 隐藏层权重矩阵形状为 $d \times V$：**有几个词就有几列，用几维就有几行**，每一列就是一个词的词向量。
    * 例：5 个词、隐藏层 3 个神经元 → 隐藏层权重矩阵 $3 \times 5$，5 列依次对应 5 个词的词向量；改成 6 维则是 $6 \times 5$；语料从 5 个词涨到 6 个则是列在变。
    * 维度即隐藏层神经元个数，是**超参数**，写 3 就是三维、写 6 就是六维；输入层与输出层的神经元个数由词表决定，是定死的。
    * 偏置项 $b$ 在推导里不写、不考虑。
    * > 易错点：隐藏层写 3 个神经元，藏的是「词向量用几维表示」；输入层写 5 个神经元，藏的是「词表里有几个词」。前者可以随便定，后者由数据决定。
    * > 来源: P17, P18

### 4.2 无监督语料构造监督任务

* **无监督语料构造有监督任务**
    * > 定义：不额外标注，只用滑动窗口从原句里切出「输入 → 目标」配对，让语言模型在语料内部完成自监督。
    * 做法：一次取固定数量的连续词，用前 $k$ 个当输入、下一个词当目标；窗口往后移一格，目标也跟着往后移一格，标签就从语料里自己长出来了。
    * 这是 Word2Vec 不需要人工标注、又能跑起来的直接原因。
    * > 来源: P17

### 4.3 CBOW：基于两端预测中间

* **CBOW（Continuous Bag-of-Words，连续词袋模式）**
    * 基于两端预测中间：把上下文词的词向量**相加**（也可以求平均）作为上下文的表示，再通过神经网络做预测。
    * 训练样本切法：窗口一次拿三个词，左右两个当输入、中间那个当输出。语料 `Hope can set you free` 切成三个样本——`Hope、set → can`，`can、you → set`，`set、free → you`。
    * 样本数取决于窗口如何滑动，不取决于词的多少。
    * 单向数据流：输入层 5 个特征 → 隐藏层压成 3 个特征（$3 \times 5$ 权重矩阵，每个神经元 5 个权重、三个神经元共 15 个）→ 输出层 $5 \times 3$ 变回 5 个位置打分。
    * 输出层 5 个神经元是多分类问题，要经过 **Softmax** 得到每个词的预测概率，算完这一步它已经不再是权重，而是预测值。
    * 矩阵乘法的实际效果：`Hope` 的 One-Hot 只有第 1 位是 1，乘出来就是把隐藏层权重矩阵的**第 1 列**原样取出，后四列因为乘 0 全部消掉。
    * 一次迭代闭环：前向传播算预测值 → 与真实值算损失 → 反向传播 → 更新两个权重矩阵；重复至所有语料遍历完成。
    * 适合**高频词**。
    * > 来源: P17, P18

### 4.4 Skip-Gram：基于中间预测两端

* **Skip-Gram（跳字模式 / 跳词模式）**
    * 基于中间预测两端：把当前单词的词向量作为输入，通过神经网络去预测周围词。
    * 隐藏层结果要与**两个 $5 \times 3$ 的输出权重矩阵**分别做运算，得到两个预测值——上面那份负责前一个词、下面那份负责后一个词；两份矩阵只在参数值上不同，形状、语义、计算方式完全一样。
    * 一个中心词对应两个上下文词，就有两个预测、两个真实、**两个损失**；合成总损失可以求和、也可以求平均，选一个即可。
    * 反向传播先更新输出层的两个权重矩阵，再往前更新隐藏层那个 $3 \times 5$ 的矩阵；最终取用的仍是隐藏层矩阵。
    * 例：语料 `hope can set you free`，`set` 当输入，两侧的 `hope` 与 `free` 是目标；中心词 `can` 的 One-Hot 为 `0 1 0 0 0`，与 $3 \times 5$ 矩阵相乘取的是**第 2 列**。
    * 适合**低频词**。
    * > 易错点：不要凭词本身判断它是输入还是输出。判断依据只有一个——在 CBOW 里中间那个词是目标，在 Skip-Gram 里中间那个词是输入、两侧的词才是目标。
    * > 来源: P18

### 4.5 两种模式的对比与选型

* **两种模式的对比与选型**
    * CBOW 计算相对简单、计算要快一些；Skip-Gram 要基于中间预测两端，两次计算，运算量更大。大规模语料下从计算效率入手优化，CBOW 更合适。
    * 判断选哪一种看两件事：数据集特性是高（或低）频词为主，以及计算机计算资源。算力非常富裕时才考虑 Skip-Gram。
    * > 来源: P17, P18, P23

| 对比项 | CBOW | Skip-Gram |
| :--- | :--- | :--- |
| 输入 | 上下文（两端） | 中心词（中间） |
| 输出 | 中心词 | 上下文（两端） |
| 输出层权重矩阵份数 | 一份 | 两份 |
| 损失份数 | 一份 | 两份（求和或求平均） |
| 适用词频 | 高频词 | 低频词 |
| 最终取用 | 隐藏层权重矩阵 | 隐藏层权重矩阵 |

* **两条路径的公共落点**

    ```text
                     one-hot 输入
                          |
            +-------------+-------------+
            |                           |
         CBOW 路径                  Skip-gram 路径
            |                           |
       上下文若干词                  中间目标词
            v                           v
       预测中间目标词              预测上下文若干词
            \                           /
             +-----------+-----------+
                         v
                隐藏层权重矩阵 W（dim 维）
                         |
                         v
             W 的每一列 = 一个单词的 Word2vec 词向量
    ```

    * > 来源: P19

## 5. fastText 四步流程

> **一句话主旨**：把 fastText 训练词向量的四步串成一条可执行链路，给出每步的接口、默认参数、日志字段与时间成本。

### 5.1 工具包定位与四步流程

* **fastText 工具包**
    * > 定义：Facebook 开源的训练工具包，直接生成 Word2vec 形式的词向量，两个作用——训练词向量与文本分类。
    * 由**托马斯·米科洛夫（Tomáš Mikolov）**开发；Word2vec 由他发明，RNN 有他，`fastText` 整个工具包也是他写的。
    * 本阶段只用它的词向量功能；文本分类留到后面的迁移学习部分。
    * 四步流程（要求背下来）：获取训练数据 → 词向量的训练、保存、加载和查看 → 模型效果检验 → 模型超参数设定。
    * > 来源: P19

### 5.2 训练数据与语料选型

* **训练数据与工程准备**
    * 数据来自英文维基百科的一部分网页信息，原始压缩包约 300 兆，解压后 **680 兆**，文件名为 `fil9`，词与词之间用空格隔开。
    * 预处理做的就是一件事：底层用**正则**把每个单词切出来，单词与单词之间用空格隔开；直接用预处理之后的 `fil9`，切词的活不用再做一遍。
    * 官方同时提供 7 个分片：`0502_ad`、`0502_bd`、`0502_ce`、`0502_df`、`0502_eg`、`0502_fh` 各 100 兆，`0502_gj` 80 兆；六个 100 兆加一个 80 兆正好等于 680 兆，`0502` 是日期标签。
    * 时间账：100 兆约 4 分钟，680 兆接近**半个小时**；fastText 实际训练 100 兆约两分钟，用 680 兆要围绕这个时长**乘 4 到乘 6**。
    * > 易错点：别想着把七个分片全拷进去——七个分片合起来本来就等于 `fil9`，拷两遍纯属浪费硬盘和时间。
    * 查看分片内容：拖进 PyCharm 双击打开，会显示 `the file is too large` / `read-only mode`，只显示一部分；**不要用本地记事本去开**，文件太大大概率直接卡死。
    * > 来源: P19, P20

### 5.3 fastText 的安装

* **安装**
    * 三步：`conda activate nlp_base` → `pip install fasttext` → 装不上换 `pip install fasttext-wheel`。
    * `fasttext` 包带 C++ 源码，安装时要现场编译，编译依赖**系统**与**编译器版本**：有的 Anaconda 环境顺手帮你把编译做掉，有的不帮，那就一片红。
    * 记成一句话：**直装优先，报错换 wheel 版**（预编译分发格式，不用本地编译）。
    * 验证与版本：`pip list | findstr fasttext`，参考版本号 **0.9.2**，不必强求完全一致。
    * > 来源: P19

### 5.4 训练与保存

* **训练与保存**
    * 导包 `import fastText`（包名首字母小写 `f`、中间大写 `T`，与 `pip` 安装时写的 `fasttext` 大小写不一样，但都能装能导）。
    * 最简调用：`my_model = fastText.train_unsupervised('./data/0502_ad')`，一行即训练完。
    * 保存：`my_model.save_model('./model/0502_fil9.bin')`，存成**二进制文件**、扩展名 `.bin`；模型不存 `data` 目录，文件名里带上数据集名便于溯源。
    * `model` 目录要提前右键新建，否则 `save_model` 找不到落盘位置。
    * `train_unsupervised` 返回的模型先存在于内存里，必须再显式调一次 `save_model` 才会在硬盘上留下 `.bin`。
    * > 易错点：`model=`、`lr=`、`dim=` 之类的参数全删掉，一个都不写——这一步就是用最原始的默认参数把流程跑通。
    * > 来源: P20

### 5.5 默认参数取值

* **默认参数取值**
    * 源码里看默认值：按住 `Ctrl` 点 `train_unsupervised` 跳进实现，找到 `unsupervised_default` 变量；按住 `Ctrl` 再点它，会跳到定义它的那一行（定义位置在 551 行附近，跳转跟的是符号定义处而非引用处，所以会落到 439 行）。
    * 关键四项：`model=skipgram`、`lr=0.05`、`dim=100`、`epoch=5`。
    * `dim=100` 的意思是**用 100 个数字来表示一个词**；维度越高能塞进去的语义信息越多，但训练与存储开销也越大。
    * > 来源: P20

### 5.6 训练日志字段

* **训练日志字段**

    ```text
    Read 19M words
    Number of words: 43589
    Number of labels: 0
    Progress:   4.5%  words/sec/thread:  50234  lr: 0.047965  avg.loss: 2.1417  ETA: 0:01:23
    ```

    * `Read 19M words`：读取的单词总数，约 1900 万；`Number of words` 是**去重之后**的词表大小（4 万多个不同单词），不是总词数。
    * `Number of labels: 0`：标签数量为 0，说明这次是**无监督训练**；无监督任务里没有标签可预测，Word2vec 的 CBOW 与 Skip-gram 就属于这一类。一旦标签数不为 0，那就是在做分类，属于有监督。
    * `lr` 不是恒定的：一开始是 `0.05`，随训练推进慢慢衰减，日志里看到的是衰减后的当前值。
    * `avg.loss` 是平均损失，判断模型学得好不好主要看它，正常训练时它应随进度稳步下降；长时间不降或上下乱跳，通常意味着学习率偏大或数据有问题。
    * `words/sec/thread` 是每个线程每秒处理的单词数，这个数**仅供参考**。
    * `ETA` 是预计完成时间。
    * > 来源: P20

### 5.7 加载与查看

* **加载与查看**
    * `model = fastText.load_model('./model/0502_fil9.bin')`。
    * `model.get_word_vector('the')` 返回 `<class 'numpy.ndarray'> (100,)`；是 100 维因为默认 `dim=100`。
    * > 易错点：不能在这里写中文词。训练时喂进去的数据全是英文单词，词表里只有英文，取词要从语料里已有的词里挑。
    * `type()` 与 `.shape` 两个打印不要省：它们确认了返回的是 numpy 数组而不是列表、维度是 100 而不是别的数。
    * > 来源: P21

### 5.8 模型效果检验

* **模型效果检验**
    * 检验方式：给一个词，让模型把它的近义词列出来，再**主观判断**这些近邻词与目标词的相关性；找得越准，模型效果越好。`nearest` 是最近的、`neighbors` 是邻居，与机器学习里的 KNN（K-Nearest Neighbors，K 近邻算法）同源。
    * `model.get_nearest_neighbors('dog')`：**默认返回 10 个**近邻，用途是检验模型的语义理解能力。
    * 返回格式是**列表套元组**，每组里第一个是相似度分数、第二个是近义词：`[(0.78, 'dogs'), (0.71, 'sheepdog'), (0.66, 'breed'), ...]`。
    * `dog` 的近邻里出现 `dogs`（复数形式、形态最近）、`sheepdog`（牧羊犬）、比熊犬一类犬种、`breed lover`、`breeds`（犬类语料里高频共现的词），说明模型确实学到了「狗」概念附近的语义区域。
    * 当前拿到的是 **Skip-gram** 训出来的向量——训练时什么参数都没写，默认 `model` 就是 `skipgram`；想改成 CBOW 要手动指定参数。
    * > 来源: P21

### 5.9 六个常用超参数

* **六个常用超参数**
    * 用法：把默认开训换成手动把参数写清楚。只玩 `input`、`model`、`dim`、`epoch`、`lr`、`thread` 这六个，其余参数用不到时自查文档。
    * `input` 给本次训练要吃的语料路径，**不能省**——默认值不是我们的数据，不显式指定你训练的就是别人的语料。
    * `thread` 默认是 `multiprocessing.cpu_count() - 1`，即「CPU 有多少核就减 1」，留一个核给系统和其他进程；八核十六线程的机器上 `cpu_count()` 给 16，默认值就是 15。填这个参数不要照着线程数往上加，给 10 已经很多很多了。
    * 参数值的取舍是**拿时间换质量**（或者反过来）：轮数、维度、线程数都是如此。
    * > 注意：`dim` 不是越大越好，它直接决定权重矩阵的大小和训练开销，先跑通就用小维度。
    * > 来源: P22

    ```python
    my_model = fasttext.train_unsupervised(
        input='./data/5万行2ed.txt',
        model='cbow',
        dim=50,
        epoch=1,
        lr=0.01,
        thread=10,
    )
    my_model.save_model('./data/new.bin')
    print('训练完毕，模型保存成功')
    ```

| 参数 | 作用 | 默认值 / 讲中取值 |
| :--- | :--- | :--- |
| `input` | 训练数据的路径 | 无默认可用值，指定为 `./data/5万行2ed.txt` |
| `model` | 词向量模型模式，取值 `cbow` 或 `skip-gram` | 默认 `skip-gram`，改为 `cbow` |
| `dim` | 词向量的维度 | 默认 100，取 50 |
| `epoch` | 训练轮数 | 默认 5，取 1 |
| `lr` | 学习率 | 默认 0.05，取 0.01 |
| `thread` | 线程数 | 默认 `multiprocessing.cpu_count() - 1`，取 10 |

* 1 轮训练耗时约 20 秒内，5 轮约 2 分钟，耗时按轮数等比例变化；只训 1 轮的模型找近义词效果不如默认那次——训练轮数太少。

### 5.10 五步执行时间线与接口清单

* **五步执行时间线与接口清单**

    ```text
    获取训练数据(fil9)
          |
          v
    词向量训练 +-- 分支 A：默认参数直接训练
          |     +-- 分支 B：手动设定超参后训练
          v
       save_model 保存
          |
          v
       load_model 加载 -> 查看 -> get_nearest_neighbors 找近义词
          |
          v
       超参设定：换回分支 B 重训，对比耗时与效果
    ```

    * 接口：训练 `fasttext.train_unsupervised`、保存 `save_model`、加载 `load_model`、查看 `get_word_vector`、近邻 `get_nearest_neighbors`。

## 6. Word Embedding 与 nn.Embedding

> **一句话主旨**：厘清词嵌入的广义与狭义两层含义，给出它与 Word2Vec 在静态/动态上的差别，并落到 nn.Embedding 与可视化链路。

### 6.1 广义与狭义两层解释

* **Word Embedding（词嵌入）**
    * > 定义（广义）：所有稠密词向量表示法。Word2Vec 就属于 Word Embedding 的一种；用浅层网络可以实现，用深层网络也可以。
    * > 定义（狭义）：深度神经网络中的**嵌入层**。RNN 由三层组成——第一层词嵌入层、第二层循环网络层、第三层输出层，这里说的就是第一层。
    * 极简理解就两个词：广义、狭义。
    * > 来源: P23

### 6.2 静态词向量与动态词向量

* **静态与动态词向量**
    * 相同点：无论是 Word2Vec 还是 Word Embedding，都是词向量的一种手段和方式，都能把文本转成数值。
    * 不同点：Word2Vec 产生词向量后某个词的词向量就固定下来，是**静态**的；`nn.Embedding` 层产生的词向量随网络训练一起更新，是**动态**的。
    * 步数不同：Word2Vec 一般需要两步——先拿到词向量，再给神经网络；`nn.Embedding` 一步直接用。
    * 记忆口诀：**先办证后干活 = Word2Vec；边办证边干活 = nn.Embedding**。
    * > 来源: P23

| 对比项 | Word2Vec | Word Embedding（`nn.Embedding` 层） |
| :--- | :--- | :--- |
| 词向量性质 | 静态，一旦训练完就固定 | 动态，随网络训练一起更新 |
| 使用步数 | 两步：先拿词向量，再交给网络 | 一步：直接作为网络的一层使用 |
| 是否单独训练 | 单独训练一个词向量模型 | 不单独训练，是网络内部的层 |
| 训练与保存 | 必须先训练并保存才能用 | 无需单独保存词向量 |

### 6.3 词嵌入层与文本数值化链路

* **nn.Embedding（词嵌入层）**
    * 两个参数：`num_embeddings` 是词汇表大小（唯一词的个数，写 `len(my_token_list)`，不要写死 20）；`embedding_dim` 是词向量维度（取 8 即每个词用 8 个数字表示）。
    * 权重矩阵形状 = `num_embeddings × embedding_dim`，例 `nn.Embedding(20, 8)` 得 $20 \times 8$；矩阵的每一行对应一个编号的词，这一行的 8 个数就是那个词的词向量——权重矩阵本身就是一张「编号 → 词向量」的查找表。
    * 嵌入层**不能直接把文本转成词向量**，它得先把文本对应的编号转成词向量；所以必须先切词、再把每个词转成数字。
    * 编号来源：`my_tokenizer.fit_on_texts(word_list)`（统计词频并构建词汇表，**必须扔分好词的 `word_list`**）→ `list(my_tokenizer.word_index.values())` 拿到 1…20 的编号 → `my_tokenizer.texts_to_sequences(word_list)` 把文本转成数字序列。
    * > 易错点：分词结果装进 `word_list` 要用 `append` 而不是 `extend`——用 `extend` 两个句子的词会被摊平混在一起，句子边界就没了。
    * > 易错点：把原始句子 `sentences` 交给 `fit_on_texts`，构建出来的词表不是按词切的，映射关系就不对了。
    * > 来源: P24

### 6.4 文本到词向量的处理链路

* **文本到词向量的处理链路**

    ```text
    分词后的中文文本
          |  1. jieba.lcut 切词 + append 装进 word_list
          v
    [ [句1词...], [句2词...] ]          嵌套词列表
          |  2. Tokenizer.fit_on_texts(word_list)
          v
    词 -> 编号 的映射字典（20 个词）
          |  3. word_index.values() -> my_token_list（1..20）
          |  4. texts_to_sequences      -> 数字序列
          v
    [[4, 5, 1, ...], [3, ..., ...]]     纯编号的文本
          |  5. nn.Embedding(num_embeddings=20, embedding_dim=8)
          v
    embed.weight.data  ->  20 x 8 的词向量矩阵
    ```

    * > 来源: P24

### 6.5 逐词取向量与索引反查

* **逐词取向量与索引反查**
    * 逐词取：`for index in range(len(my_tokenizer.word_index))`，循环里 `temp_vector = embed(torch.tensor(index))`——把 index 用 `torch.tensor` 包成张量丢进 `embed` 就把对应词向量取回来。
    * `range(20)` 给的是 0 到 19 共 20 个数，**包左不包右**。
    * 反查词：`word = my_tokenizer.index_word[index + 1]`——`word_index` 是「单词 → 索引」，`index_word` 是「索引 → 单词」，词汇映射器不只有单向映射，它是**双向**的。
    * > 易错点：`index_word` 里的编号从 1 开始，而 `range` 出来的索引从 0 开始，两边起点不一样，取的时候必须写成 `index + 1`。
    * > 易错点：张量转 NumPy 不能直接 `.numpy()`，它参与计算时经过了反向传播、带着自动微分信息，可能报错；要先 `.detach()` 把它从计算图里摘出来再 `.numpy()`。
    * > 来源: P25

### 6.6 词嵌入层的形状变换

* **嵌入层的形状变换**
    * 输入张量形状 `(2, 4)`，喂给 100 个词、每词 256 维的嵌入层后形状变成 `(2, 4, 256)`：每一行、每一列上那一个索引位置都变成一个 256 维向量。
    * > 易错点：示例代码直接照抄会报错，因为 `import torch` 和 `import torch.nn as nn` 都没写；导包动作要写在函数外面。
    * > 来源: P25

### 6.7 TensorBoard 可视化链路

* **TensorBoard 可视化链路**
    * 三步标准流程：`SummaryWriter(log_dir='./runs')` 创建写入器 → `add_embedding(embed.weight.data, my_token_list)` → `close()`。

### 6.8 中文词与未见词的处理

* **中文词与未见词的处理**
    * 用纯英文语料训好的模型喂中文词，**照样能生成向量**：模型会去适配输入，把它映射到自己的表示空间里，照样吐出 100 维向量。
    * 但**能生成不等于有意义**——它的语义从来没在训练语料里出现过，拿它去查近义词结果就不一定准；想让中文词也准，得用中文语料重新训练。
    * 未见词的词向量生成建议：使用最接近的已知单词（近义词）的词向量顶上。
    * 想进一步提升效果：训练时别用分片，用全量的 `fil9`——词表更大、共现统计更充分，学出来的语义空间更细。

### 6.9 窗口大小的含义

* **窗口大小**
    * 窗口大小决定模型考虑**上下文的范围**。窗口设成 3，就是基于第 1 个和第 3 个词预测第 2 个词；设成 5，就是基于第 1、2 个和第 4、5 个词预测第 3 个词；一般取**奇数**，设成 7 就是基于前 3 个和后 3 个词预测中间那个词。
    * > 来源: P23

## 7. 文本数据分析（标签与长度）

> **一句话主旨**：给出「处理之前先做查看」的分析顺序，落到标签分布、句子长度分布与离群点定位三类统计动作上。

### 7.1 数据分析的定位与两类常见问题

* **文本数据分析的定位**
    * 对文本做处理之前的第一个动作，就是先做一遍文本的数据分析，看数据的分布情况，再决定下一步具体怎么动手。
    * 作用：帮我们理解数据语料、快速检查出语料中可能存在的问题，并且**指导模型训练过程中一些超参的选择**。两个最直接的例子是标签 $y$ 的分布是否均匀、特征 $x$ 里有没有噪声数据。
    * 分析环节只负责「看出来」，不负责「改数据」；每一种图表都要落到一个能执行的结论上。
    * 下半部分的路线：文本数据分析（标签数量的分布、句子长度的分布、单词总数与词频、关键词词云）→ 文本特征处理（n-gram、文本长度规范）→ 文本数据增强（回译增强）。
    * 面试谈资的顺序骨架：**先做查看，再做处理**——先看标签分布、句子长度分布、词频、词云，再决定怎么做处理。
    * > 来源: P26, P32

| 问题类型 | 具体表现 | 处理方向 |
| :--- | :--- | :--- |
| 数据质量类 | 错别字、语法错误、重复内容、缺失值、噪声数据 | 清洗、去重、修正 |
| 分布不均衡类 | 标签分布不均；句子长度分布异常 | 数据增强或删减；截断或补齐 |

### 7.2 中文酒店评论语料与标签口径

* **中文酒店评论语料与标签口径**
    * 数据集是中文酒店评论语料，属于二分类中文情感分析语料：**1 是积极的（好评），0 是消极的（差评）**。
    * 判断靠看内容：通篇吐槽的是 0；先吐槽、末尾跟一句「前台服务人员态度挺好的」的，标的是 1；先吐槽几点、末尾说「其他还好」的也当好评论处理。
    * 基于文本内容做模型分析比单纯数星星可靠得多——App 打星时你夸得天花乱坠只要选一星照样归到差评里，这是 NLP 要解决的问题。
    * 数据文件 `train.tsv` 两列：第一列是评论内容（特征），第二列是评论状态（标签）；训练集之外还有验证集，标签口径一致。
    * 实际开发中训练深度学习模型解决分类问题，一般需要把**正负样本比例维持在 1:1**；本数据训练集与验证集的正负样本都**稍有**不平衡，可以微调比例，不是大调。
    * > 来源: P26

### 7.3 csv 与 tsv 的分隔符差别

* **csv 与 tsv**
    * > 结论：csv 与 tsv 的区别只有分隔符——**csv 用逗号分隔，tsv 用 `\t`（Tab 键）分隔**，其他用法一模一样。
    * tsv 认的分隔符是 `\t`，它不认识逗号；把以逗号分隔的文件改存成 `.tsv`，打开会全挤成一列。
    * 读取时**没有 `read_tsv` 这个函数**，官方统一用 csv 那套，靠一个参数换掉分隔符：`pd.read_csv('./data/train.tsv', sep='\t')`。
    * `head()` 查看前几条数据，默认给 5 条。
    * > 来源: P26

### 7.4 标签数量分布

* **标签数量分布**
    * 画计数柱状图看各个类别分别有多少个，训练集、验证集各一张。
    * `sns.countplot(x='label', data=train_data, hue='label', legend=False)`：`x` 是 x 轴标签，`data` 是数据源，`hue` 用于分组的分类变量（按 label 分成 0 一组、1 一组），`legend` 默认 `True`，这里关掉。
    * 图上 0 与 1 颜色不同、差评蓝色好评红色，靠的就是 `hue`——颜色不是手动指定的，是分组分出来的。

### 7.5 句子长度分布

* **句子长度分布**
    * 长度不是拍脑袋定的：**看绝大多数的句子都集中在哪个长度，就拿它做截断的长度**。
    * 统计对象是训练集与测试集各自的句子长度，两者都要做；句子长度指一条样本在**按字符切分**意义下的长度，即把整条句子当字符串用 `len()` 求出的字符个数。
    * 一组图对应一个数据集，四个图为一轮：计数柱状图（每个长度值/区间上有多少条句子）+ 密度曲线图（长度取值的整体分布形状、峰值落在哪），训练集与测试集各一张。
    * 实现：新增长度列用 `list(map(lambda x: len(x), train_data['sentence']))`，第二套等价写法是 `train_data['sentence'].apply(lambda x: len(x))`，两者跑出来的内容完全一致。
    * 计数柱状图：`sns.countplot(x='sentence_len', data=train_data)`；`plt.xticks([])` 括号里给**空列表**就是隐藏 x 轴刻度值，不给值它就按默认刻度画。
    * 密度曲线图的新版写法：`sns.histplot(x='sentence_len', data=train_data, kde=True)`——`hist` 负责画直方图，`kde=True` 负责把核密度曲线（Kernel Density Estimation，KDE）画在旁边。
    * 旧版 `sns.displot` 已过时，照抄只给一条很淡的线，分布看得不明显；部分电脑照写会报警告，那是 matplotlib 版本问题。
    * 结论：**绝大多数句子的长度落在 20 到 250 这个区间**；`20` 与 `250` 就是后面截断与补齐可以直接拿来用的区间边界——短于 20 的补，长于 250 的截。

    * > 提示：柱状图的一根柱子对应一个**离散的取值**，直方图的一根柱子对应一个**连续区间**。句子长度是连续量，按区间读才不容易看花眼。
    * 四个图连起来看，测试集的分布比训练集更清晰——训练集样本多，每个长度上的句子数被摊薄，柱子显得参差。

## 8. 词汇统计与高频词云

> **一句话主旨**：用 chain 把多份词表拍平成一条流并去重，得到词表规模，再配合词性过滤与 WordCloud 画出正负样本的高频形容词词云。

### 8.1 映射函数 map

* **map()**
    * > 定义：`map(函数, 可迭代对象)` 把函数作用到可迭代对象的每个元素上，返回一个**迭代器对象**。
    * 返回的是 `<map object at 0x...>`，此时**并未实际执行运算**；`map` 只是把「函数」和「可迭代对象」打包成一个迭代器，真正的计算发生在你从迭代器里往外取元素的那一刻。
    * `map` + `list` 是一对：要拿到结果就在外面套一层 `list`；加在输出处还是赋值处都行，效果一样。
    * 对一串句子用 `list(map(lambda x: len(x), df['sentence']))`，就是「把句子的内容转换成长度」。
    * 函数体只有一行时没必要单独 `def`，用 `lambda` 表达式即可：`map(lambda x: x + 2, [10, 20, 30])` 与 `map(fn, ...)` 中的 `fn` 等价。
    * > 易错点：**迭代器只迭代一次**。第一遍 `for` 遍历时元素已被取走，第二遍 `print(list(result))` 得到空。调试时特别隐蔽——先打了一眼结果，后面再拿它做别的处理就会得到空结果，然后误以为前面的环节出错。
    * > 来源: P27

### 8.2 链式拼接 chain 及其与 extend 的差别

* **chain()**
    * > 定义：`itertools.chain` 把多个可迭代对象**串成一条流**，它是惰性的（lazy）——不立刻迭代，只把「接下来依次吐出哪些元素」记下来，因此节省内存。
    * 语料上的意义：一万条句子分词后是几十万个词，先拼成完整大列表再处理会多出几十万个字符串的内存占用；用 `chain` 拼成流则边遍历边产出，中间不落地。
    * 迭代器有状态、取一个少一个，遍历一遍后再遍历什么都不输出，而且**不会报错**。
    * `chain` 不管重复，只负责拼接；`list(chain([1,2,3], [2,3,4]))` 得 `[1, 2, 3, 2, 3, 4]`。
    * > 易错点：`extend` 是原地操作，跑完之后原列表就变了；后续逻辑还要用原始列表时会把原数据毁掉，这种情况必须用 `chain`。
    * > 提示：来源数量很大、流式产出或嵌套层数不确定时别用 `*`，改用 `chain.from_iterable(可迭代对象)`——同样拍平一层，惰性保持得更彻底。
    * > 来源: P30

| 对比项 | `chain(list1, list2)` | `list1.extend(list2)` |
| :--- | :--- | :--- |
| 是否修改原对象 | 不改动 `list1`、`list2` | **原地修改** `list1` |
| 结果要不要落地 | 惰性，只在遍历时才产出元素 | 立刻把元素全部塞进 `list1` |
| 内存占用 | 不需要新建一个完整的大列表 | 目标列表会增长到合并后的规模 |
| 返回值 | 一个迭代器，要 `list()` 才能看 | `None`，结果就在 `list1` 里 |
| 能不能接多个来源 | 可以，`chain(a, b, c, ...)` 一起串 | 一次只能 `extend` 一个 |

### 8.3 星号操作符与嵌套拍平

* **星号 `*`（打包/解包操作符）**
    * > 定义：写在实参位置时，它把一个可迭代对象**展开成一个个独立的参数**传进去。
    * `chain(*temp)` 等价于 `chain(['今天','天气','很','好'], ['今天','天气','很','热'])`——`temp` 里的两个词列表被摊成 `chain` 的两个位置参数，嵌套就这么被拍平成一层。
    * `map(lambda x: jieba.lcut(x), list1)` 之后得到的是**词列表的列表**（两层结构），只有剥掉外层才能得到连成一整条的词流。
    * 一行写法：`set(chain(*map(lambda x: jieba.lcut(x), list1)))`。四个动作各自独立——`map` 制造嵌套、`*` 解开嵌套、`chain` 串成流、`set` 去重，顺序不能乱。
    * > 来源: P30

    ```text
    set( chain( * map( lambda x: jieba.lcut(x),  list1 ) ) )
     |      |    |    |                              |
     |      |    |    |                              +-- 原始句子集合
     |      |    |    +-- 分词：每条句子 -> 词列表（产生嵌套）
     |      |    +-- 解包：把词列表摊成 chain 的多个参数
     |      +-- 串接：把摊开的词列表首尾相接成一条流（惰性）
     +-- 去重：只留下不重复的词
    ```

### 8.4 词汇统计与词表规模

* **词汇统计（词表规模）**
    * > 定义：这里的「词汇总数」是**去重之后的词表规模**，不是语料里出现过的词次总数——一个词在语料里出现一万次，在词表里只算一个。
    * 词表规模是后面所有环节的地基：词向量矩阵要开多大、词表要不要裁剪、有多少低频词会被判成 `<unk>`，全都看这个数字。
    * 写法：`train_vocab = set(chain(*map(lambda x: jieba.lcut(x), train_data['sentence'])))`，验证集把 `train_data` 换成 `dev_data`、取列仍是 `sentence`。
    * 拆开看三层：切词（`jieba.lcut` 把句子切成词）、拉直（`chain(*...)` 把每个句子的词列表拆开首尾相接）、去重（`set(...)` 压掉重复词）。
    * `len` 的位置：写在打印处而不是去重那行。写在上面变量就只是一个数字，只能拿长度；留下词表本身则随时能加 `len`，也能拿这些不同词汇去做生成索引等别的事。
    * 背诵重点不是这两行代码，而是**「要给一批句子做同一件事就 map 出去；结果是嵌套的，就用星号交给 chain 拉直」**这个组合套路——以后遇到的清洗、过滤、拼接十有八九还是它。
    * > 来源: P30, P31

### 8.5 高频形容词词云的绘制

* **高频形容词词云**
    * 要点是先做词性标注（POS）再交给 `wordcloud` 统计作图；要名词或动词的词云做法完全一样，只改 `get_a_list` 里那一个字符：形容词 `'a'`、名词 `'n'`、动词 `'v'`。
    * `get_a_list(text)`：用 `psg.lcut(text)` 切分并遍历，`val` 是 `pair` 对象，`.flag` 拿词性、`.word` 拿词；判断 `val.flag == 'a'` 就把词 `append` 进列表。注意它**一次只处理一句话**，不是一整个数据集。
    * 例：`早餐不好` 打印出 `早餐/n`、`不好/d`——`早餐` 是名词，`不好` 是副词，所以都不是形容词。
    * `get_word_cloud(keywords_list)` 四步：实例化 `WordCloud(font_path='./data/simhei.ttf', max_words=100, background_color='white')` → `' '.join(keywords_list)` 转成空格分隔字符串 → `word_cloud.generate(keywords_str)` → `plt.figure()`、`plt.imshow(word_cloud, interpolation='bilinear')`、`plt.axis('off')`、`plt.show()`。
    * `max_words=100` 就是这张词云里最多只显示 100 个词；有 200 个不同词时按出现次数排序取前 100——所谓「高频」就是这么来的。
    * 词云要的输入格式是「空格分隔的字符串」而不是列表，这不是我们定的格式，是它要的格式。
    * > 易错点：不指定中文字体路径，图上一排方块什么都看不见。
    * `interpolation='bilinear'` 管的是图像显示的平滑方式（双线性插值）；词横着摆还是斜着摆由 `WordCloud` 内部的排布参数决定，要调的是排布参数而不是插值方式。
    * 业务函数按场景拆分四块：训练集正样本（`label == 1`）、训练集负样本（`label == 0`）、测试集正样本、测试集负样本；筛选写法 `train_data[train_data['label'] == 1]['sentence']` 是先布尔筛选拿到整张子表，再取 `sentence` 一列。
    * 合并形容词列表的骨架与词汇统计一模一样：`chain(*map(lambda x: get_a_list(x), p_train_data))`。
    * > 易错点：`chain(*map(...))` 得到的是一个**对象**，直接 `print` 只看到对象地址，要看数据得用 `list()` 或 `set()` 转一下。
    * 实测词云：正样本出现「少、舒服、干净、好、不错、方便」；负样本「差、一般、不满意、最差、很小」，差评里「差」字最多。
    * > 易错点：评论数据里出现模棱两可的词是**普遍现象**，不是标注错误。正样本词云里出现「遗憾」「不足」、负样本里出现「豪华」「不错」都属正常——同一条评论前半句差评口吻、后半句好评，整条仍标注为 1。
    * 可疑词去查带这些词的句子，看是标记错了还是识别错了，做人工核实；确属大量明显不当的词，要么把带这些词的句子过滤掉，要么把词用星号遮蔽。
    * > 注意：词云这一步**没有做敏感词过滤**，数据里有什么它就老老实实显示什么。
    * 这一段代码可以直接当成**模板**：以后换一份数据要做同样的探查，把数据集一改、代码往里一套就行。
    * > 来源: P32

### 8.6 柱状图与直方图的区别

* **柱状图与直方图的区别**
    * > 定义：柱状图统计的是**离散取值的个数**（A 出现了多少次、B 出现了多少次）；直方图统计的是**区间（范围）里的个数**（20 到 30 之间有多少个、30 到 40 之间有多少个）。
    * 句子长度是连续量，所以要用直方图；样本类别是离散量，所以要用计数柱状图。
    * > 来源: P32

## 9. 文本特征处理

> **一句话主旨**：给出「把相邻词打包」与「把长度对齐」两类喂模型前的准备工作，以及计算两段文本相似度的通用链路。

### 9.1 文本特征处理的定位

* **文本特征处理**
    * > 定义：给文本增加**普适性**的一类预处理操作，让模型更有效地处理数据、提高性能指标；常用方法有 n-gram、文本长度规范、文本数据增强。
    * > 来源: P33, P37

### 9.2 n-gram 的定义、分类与量级边界

* **n-gram（n 元语法 / 小词组特征）**
    * > 定义：n-gram 是连续判断出来的 n 个词（或 n 个字）所组成的片段，把这些连续片段当作一种特征来使用。
    * 存在的理由只有一个：帮我们分析文本语义——单个词翻来覆去就那么多信息，把连续几个词当成一个整体打包进去，计算机才更容易抓住词与词的搭配关系。
    * 原始序列 `1 2 3 4 5`：1-gram 是 `1 2 3 4 5` 共 5 项；2-gram 在其上多出 `1 2`、`2 3`、`3 4`、`4 5` 四组；3-gram 再多出 `1 2 3`、`2 3 4`、`3 4 5` 三组——每提高一阶，就用滑动窗口往后挪一位、多取一个词拼成新特征。
    * 2-gram 的相邻组合在词表里分到的是**新编号**（例：`1000` 代表「是谁 敲动」相邻出现、`1001` 代表「敲动 我心」），它已经是一个独立特征，跟 `1`、`34`、`21` 这些单词编号不在一个层面上。
    * > 结论：实际开发中 n 最多最多到 3；大多数场景加一个 2-gram（bigram）就已经相当不错了。
    * n 不能整得特别大：有的句子切完以后可能都没有 10 个词，n 大于句子长度时一个这样的特征都取不出来，那之前的切词也就没意义了。
    * 1-gram 在实战里不用专门实现，jieba 分词切完的结果本身就是 1-gram，每个词都是独立个体。
    * > 结论：n 越大，保留下来的就是越长的搭配片段，词汇表的维度也会随之增长；2 和 3 是实战里最常用的两档，写法只差一个数字。
    * > 来源: P33, P34, P37

| n | 名称 | 别名 | 说明 |
| :--- | :--- | :--- | :--- |
| 1 | uni-gram | 1-gram | 把每个词（或字）单独拆出来 |
| 2 | bi-gram | 2-gram | 找连续两个词的组合 |
| 3 | tri-gram | 3-gram | 找连续三个词的组合 |

### 9.3 生成 n-gram 特征的三个步骤

* **生成 n-gram 特征的三个步骤**

    ```python
    # 案例：n-gram 特征
    n_gram_range = 2

    def create_n_gram(input_list):
        # 通过滑动窗口获取 n-gram 特征
        sliced_lists = [input_list[i:] for i in range(n_gram_range)]
        # 使用 zip 函数对切片列表进行组合
        n_gram_tuples = zip(*sliced_lists)
        # 转换为集合去重，保证结果唯一
        return set(n_gram_tuples)

    input_list = [1, 3, 2, 1, 3, 2, 1, 5, 3]
    result = create_n_gram(input_list)
    print(result)
    ```

    * 滑动窗口切片：`range(2)` 取 `i = 0` 和 `i = 1`，得到「完整列表」与「去掉第一个元素」两份**彼此错开一位**的切片。
    * `zip` 组合：`zip(*sliced_lists)` 把上下两行**同一列**的元素绑成一个元组，一共 8 列，得到 8 个 2-gram 元组。
    * 集合去重：原数据里 `1 3 2` 重复出现，`(1,3)`、`(3,2)`、`(2,1)` 各出现两遍；不套 `set` 打印 8 个元组，套上 `set` 收敛到 5 个——意义是**保证结果唯一**，将来语料出现重复片段时特征不会被重复计数。
    * 运行结果 `{(2, 1), (1, 5), (5, 3), (3, 2), (1, 3)}`：集合本身**无序**，每台机器、每次运行给出的排列顺序都可能不一样，顺序不代表任何含义，确认这五组齐了即可。
    * 写 3-gram 的做法一模一样：把 `n_gram_range` 的 2 换成 3，`range(3)` 取到 `i = 0, 1, 2`，切出三份彼此错开一位的列表，`zip` 后每一列拼出三元组；同样存在重复（`(1,3,2)` 与 `(3,2,1)` 各出现两次），套 `set` 后剩 5 个互不相同的三元组。
    * > 结论：n-gram 的代码实现本质就是「把同一份数据按不同起点切几次得到错位列表，再用 zip 把上下元素一组一组配起来」，就是一个 `zip` 函数加一次集合去重。
    * 一行实现：`def create_ngram_set(input_list, n): return set(zip(*[input_list[i:] for i in range(n)]))`。
    * > 来源: P34, P37

### 9.4 zip 按位置配对与解包差异

* **zip()**
    * > 注意：`zip` 是「打包」，它**不是**解压。
    * 功能是**合并迭代对象**——能遍历的容器类型（列表、元组、字典、字符串）它都能合。
    * 按位置两两配对：`zip([1,2,3,4,5,6], [2,3,4])` 得 `[(1, 2), (2, 3), (3, 4)]`，**以短的那个为准**（类似木桶效应），多余的 4、5、6 被丢弃。
    * 直接打印 `zip(...)` 看到的是一个对象，要 `list()` 转一下才能看到内容。
    * 星号解包决定结果形状：`zip(list3)` 把嵌套列表当成**一个**可迭代对象，结果是元组套列表 `([1, 2, 3], [2, 3, 4], [3, 4, 5])`；`zip(*list3)` 把 `list3` 拆成**三个**参数，按位置竖着配对得 `[(1, 2, 3), (2, 3, 4), (3, 4, 5)]`。
    * > 易错点：`zip` 的结果是**元组**组成的列表。不加星号时外面那层是元组、里面是列表；加了星号、配对成功之后，每一组都是元组。想一眼看出差别就 `list()` 一下再打印。
    * > 来源: P33, P34, P36

### 9.5 文本相似度计算的通用链路

* **文本相似度计算**
    * > 结论（通用答法）：针对两段文本先切词；切词之后去重合并，得到一份统一的词汇表；再按词汇表统计每个词（以及每类 n-gram）在这段文本里出现的频次；这份频次就是它的词向量；最后计算两个词向量之间的距离，欧氏距离、闵氏距离这一类都可以。
    * 四步：各自切词 → 合并去重得到顺序固定、两段文本共用的词汇表 → 按词汇表统计词频得到各自的词频向量 → 计算两个向量的距离。
    * > 易错点：这份词汇表的顺序**一旦生成就不能再变**。它是后面向量的维度顺序，两句话的维度必须一一对应，否则算差值就是在拿「我」减「你」。
    * 欧氏距离：**对应维度差值平方和开平方根**。
    * 例（1-gram，5 维词表「我 你 是 黑马 人」）：文本 1「我 是 黑马 人 我」的词频向量 `(2,0,1,1,1)`，文本 2「你 是 黑马」的词频向量 `(0,1,1,1,0)`，差值 `2 -1 0 0 1`，平方 `4 1 0 0 1`，$2^2+(-1)^2+0^2+0^2+1^2=6$，欧氏距离 $\sqrt{6}\approx 2.449$。
    * 例（2-gram）：词表扩到 10 维（原 5 个 1-gram 加 5 个 2-gram），差值平方和 $4+1+1+1+1+1=10$，$\sqrt{10}\approx 3.162$；其中「是黑马」两句话都有、差值为 0，说明这个组合是两段文本共享的特征。
    * > 提示：1-gram 下的 $\sqrt{6}$ 与 2-gram 下的 $\sqrt{10}$ **不能直接横向比大小**，因为两个距离是在两套不同的特征空间里算出来的（一套 5 维、一套 10 维）。要比较相似度，两段文本必须用同一份词汇表、同一套度量。
    * 加了 n-gram 之后多出来的维度正是「词与相邻词的搭配」；1-gram 只统计单个词出现几次，搭配信息被丢掉了。这套做法不需要额外训练模型，全靠统计。
    * > 来源: P35

$\text{欧氏距离：}\quad d(A,B)=\sqrt{\sum_{i=1}^{n}(a_i-b_i)^2}$

* 常用距离度量：欧氏距离是必须会的；余弦相似度后面讲大模型还会用到；杰卡德距离了解含义即可。索引空间里的计算对象是两段文本的**词频向量**，不是原始文本。

| 度量 | 说明 |
| :--- | :--- |
| 欧氏距离 | 对应维度差值平方和开平方根，两段文本的词频向量需共用同一份词汇表、同一套度量 |
| 曼哈顿距离（城市街区距离） | 有自己的计算规则，可以自行了解 |
| 闵氏距离 | 与欧氏距离同属一类，换参数即可覆盖不同距离形式 |
| 杰卡德距离（Jaccard） | 本质是共同特征占总特征的占比 |
| 余弦相似度（Cosine Similarity） | 后面讲大模型时还会专门讲 |

### 9.6 文本长度规范与目标长度

* **文本长度规范**
    * > 定义：把超长文本裁到目标长度的操作叫**截断**；把不足目标长度的文本填到目标长度的操作叫**补齐**，补齐时一般默认补 0。
    * 动因：模型的输入需要**等尺寸大小的矩阵**，一批样本长度 10、13、9、11 参差不齐，后边根本没法生成对应的矩阵、维度没法写。
    * 目标长度 `cut_len` 的确定依据：看语料库句子长度分布集中在什么水平再据此设定，比如主体落在 50 左右就拿 50 当固定长度。
    * > 提示：`cut_len` 是超参数，不是随手写的魔法数字。定大了浪费计算、稀释有效信息；定小了会把长句子的后半段直接切掉。
    * > 来源: P33, P35, P36

### 9.7 方式一：sequence.pad_sequences

* **方式一：sequence.pad_sequences**

    ```python
    from tensorflow.keras.preprocessing import sequence

    def padding(x_train):
        return sequence.pad_sequences(x_train, maxlen=cut_len)
    ```

    * 四个参数：位置参数是待处理的文本张量；`maxlen` 是最大长度（截断与补齐的目标长度）；`truncating` 是截断策略，默认 `pre`；`padding` 是填充策略，默认 `pre`。
    * 取值的含义完全对称：`truncating='pre'` 从序列**前端**截掉多余元素、保留尾部 `maxlen` 个；`truncating='post'` 从**后端**截掉、保留最前 `maxlen` 个；`padding='pre'` 把 0 补在序列**前端**，`padding='post'` 把 0 补在序列**后端**。
    * > 易错点：`truncating='pre'` 不是「保留前 10 个」，而是「从前端把多余的截掉」，结果是把后面 10 个留下来。你想留前面那几个，恰恰要把后端的截断——那对应的取值是 `post`，不是 `pre`。
    * 记法：`pre` 管的是前面，多了就删、少了就填；`post` 管的是后面，多了就删、少了就填。
    * 默认值验证：把 `truncating` 与 `padding` 都显式写成 `pre` 再跑一次，数字完全一样，说明不写与写 `pre` 等价。
    * 换成 `post` 后结果反过来：第一个样本变成 `1 2 3 ... 一直到 32` 这一段（后面被截掉），第二个样本在后面补 0。选择哪种策略取决于你认为一句话的哪一头更值钱——句首是主谓宾主体、句尾是修饰补充，就保留前面（`post`）。
    * 日志压制：导入之前设置 `os.environ['TF_CPP_MIN_LOG_LEVEL'] = '3'`，值越大过滤得越狠。
    * > 来源: P36

### 9.8 方式二：纯 Python 实现

* **方式二：纯 Python 实现**

    ```python
    def padding_custom(x_train):
        list1 = []
        for value in x_train:
            # 超长文本：截断，保留前 cut_len 个元素
            if len(value) > cut_len:
                list1.append(value[:cut_len])
            # 不足文本：计算需要补齐 0 的数量并补齐
            else:
                padding_len = cut_len - len(value)
                list1.append(value + [0] * padding_len)
        return list1
    ```

    * 五步骨架：初始化空列表 → 遍历语料库（**一个句子一个句子单独传进来处理**）→ 处理超长文本 → 处理不足文本 → 返回处理后的列表。
    * `value[:cut_len]` 从左边界取到 `cut_len`，从 0 开始、包含 0 不包含 `cut_len`，正好 10 个元素；要后 10 个就写 `[len(value) - cut_len:]`。
    * > 提示：别把 10 写死在切片里，这个长度来自 `cut_len`，把它拉过来用，改一个参数就全变。
    * 补齐数量 `padding_len = cut_len - len(value)`：句子正好 10 个词时 $10-10=0$，一个 0 都不用填；只有 3 个词时 $10-3=7$，补 7 个 0。
    * 补齐 0 的个数必须用乘法 `[0] * padding_len` 让 `padding_len` 决定——有的句子补 5 个、有的补 6 个、有的补 7 个，事先不知道。
    * 两个版本做的事情完全一致，差别只在「从哪一头截、往哪一头补」这个策略选择上；用第三方包就是一行 API，用纯 Python 也就七八行。
    * > 来源: P36

    ```text
    方式一  sequence.pad_sequences（默认 pre / pre）
      超长： [ 1 2 3 ... 前端被截掉 ... ][ 尾部 10 个 ]
      不足： [ 0 0 0 0 0 ][ 原始元素 2 32 1 2 3 ]

    方式一  truncating='post', padding='post'
      超长： [ 前 10 个 ][ ... 后端被截掉 ... ]
      不足： [ 原始元素 2 32 1 2 3 ][ 0 0 0 0 0 ]

    方式二  padding_custom（切片 [:cut_len] 截断 + 后端补 0）
      超长： [ 前 cut_len 个 ]
      不足： [ 原始元素 ][ 0 ... 0 ]   共 padding_len 个
    ```

## 10. 文本数据增强

> **一句话主旨**：给出数据量不足时的回译增强做法、选中间语种的原则与次数上限，以及短文本重复率问题的边界。

### 10.1 定义与中间语种选型

* **文本回译数据增强法（back-translation data augmentation）**
    * > 定义：把文本翻译成另一种语言、再翻译回原语言，用「语义相近、表述不同」的新语料扩充原始数据集，从而实现数据增强。
    * 它其实就两句话：数据增强指的是**增加你的数据量**；怎么增强——中文翻出去、再翻回来。
    * 链路：原句先翻出去，可以经过一种或几种中间语言，最后一定要回到原语言；带回来的那句话才是新增语料。
    * 选中间语言的原则就一条：**一般选择小语种**（阿尔巴尼亚语、斯瓦希里语、毛里求斯当地的语言、阿拉伯语等都可以拿来当中转站）。
    * 为什么是小语种：汉英这种大语种互译出入太小，翻过去翻回来几乎是同一句话，增强不出新东西；换成小语种后链路里多了模型「转述」的空间，回到原语言时才是意思相近、话术陌生的句子。
    * 优势两条：**操作简单**、**获取新语料的质量高**——译文意思与原句非常接近、不会引入风马牛不相及的内容，表述又确实不同，等于给数据集加了「同义换说法」的样本。
    * > 易错点：短文本回译中，新语料和原语料可能存在很高的重复率，并不能有效增大特征空间——这条限制只对**短文本**成立，别把它当成回译法的通病。文本越长，回译生成的新数据越好。
    * 高重复率的破解办法是**连续多次的多语言翻译**，例如中 → 韩 → 日 → 英 → 中：一共翻了四次、三个中间语种。
    * > 结论：中间语种控制在**三个以内**。更多的翻译次数会带来两个坏处——效率低下、语义失真（每多一环就多一次走样）。
    * 边界：数据量非常充裕的时候，不需要用文本数据增强。
    * > 来源: P37

    ```text
    中文原句
       |
       +--> 目标语言 A（小语种）--> 目标语言 B --> 目标语言 C
       |                                              |
       +----------------------------------------------+
                           |
                     回译回中文
                           |
                意思相近、表述不同的新语料
    ```

### 10.2 无代码验证与小语种提示词

* **无代码验证与小语种提示词**
    * 传统做法要调翻译接口，课件里用的有道翻译公用接口已被封掉，现在打开会提示页面无法访问；要自己动手，可去有道的开发平台（智云 AI 开放平台）注册、登录，在产品服务里找「大模型翻译」「文本翻译」这类能力，开通后拿一个 API key；只是少量玩一玩，往账号里充一点钱也够。
    * 大模型阶段更省事：直接让通义的千问 Plus、千问 Max 这类模型帮我们翻译，连接口协议都不用对；换成豆包、星火或其它大模型都能做同样的事。
    * 提示词要点：说明翻译链路（如中 → 英 → 韩 → 毛里求斯语 → 阿尔巴尼亚语 → 中），并强调「翻译后的文本不能和原文一模一样，但是核心意思不变」。
    * 实测输出：原句「你今天真好看」经多语回译后得到「你今天的模样也太惊艳了吧」——意思接近、表述已换了一套。
    * 同一模型有人用起来顺手有人觉得不好用，区别就在提示词上；也因此出现了**提示词工程师（Prompt Engineer）**这一岗位，主要工作是写提示词、做模板，再把模板交给 AI 算法工程师去批量生成数据。
    * 另一种直白做法是直接下扩充指令（把一句话扩充为十句话、核心意思不变），实测得到的句子包括「你今天真好看，整个人状态显得特别亮眼，一眼看过去让人特别舒服」「不得不说你今天真好看，不管是神态、穿搭，或者别样的气质」等，语料数目实实在在变多而语义没有跑偏。
    * 数据不够用时只有两条路：要么去标注更多数据，要么想办法把这一句话变成十句话；回译增强走的是后一条。
