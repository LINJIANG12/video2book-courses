# 生成式软件工程导论与智能体开发范式

## 计算机能力日用化的主线

* **从 PC 到 ChatGPT 的演进**

    * 1975 年出现第一台 PC 机 Altair 8800。

    * 互联网把所有人连了起来；早期的 ICQ（I seek you）让用户能随机添加世界另一端的人，腾讯的山寨版先叫 OICQ、后来才改成 QQ。

    * 移动互联网的普及极快：一夜之间，所有菜场卖菜的人都有了支付宝和微信两个二维码。

    * 2022 年 ChatGPT 出现，AI 成为人类历史上增长最快的产品。

    * 这条历史主线是把昂贵的能力变成日用品。

* **两种时代焦虑**

    * 第一种：作业和考试全交给 AI，每门课看起来都很好，可四年下来什么都没学会，一毕业就被 AI 取代。

    * 第二种：把中学里听老师话的习惯延续到大学，每堂课都认真听、每次作业都认真做，毕业时确实学会了点什么，但学会的东西 AI 都会做。

    * 焦虑来自「AI 替我上大学」的闭环：老师用豆包出题，学生用豆包做作业，整个闭环过程里只有学生没有受到训练。

* **简历作为区分信号**

    * 一份「非常完美」的简历若只有 CCF 期刊列表上面的论文、accepted 与若干在投，没有任何额外的信息，就是一份零分简历。

    * 零分的原因是没有一个 GitHub 链接、没有一个个人的主页、没有一天的 preprint，别人无法验证，也无法与之区分。

    * > **提示**：「在投」的论文在读者眼里几乎等于没有——看不到的东西，别人无法验证，也不会为之加分。

    * 当所有人都是「一大堆实习、一大堆奖项、一大堆论文、一大堆在投」时，简历之间已经无法区分；最终检验大学阶段的是投出去的那份简历能不能带你到下一个更大的平台。

## 课程定位与人的优势

* **生成式软件工程（Generative Software Engineering）**

    * > **定义**：它是一门软件工程课，要解决的是怎么样让软件不失败、怎么样造出一个软件来。

    * 课程要做的事，是试着帮大家建立驾驭人工智能的能力。

* **人在 AI 时代的两类优势**

    * 信息差：你拥有别人不知道的信息，才能做别人做不到的事；校园里拥有一份别人都没有的往年试卷、社会上其他不便言说的信息差，都属于此类。

    * 大学真正教你的是怎么样成为一个更好的人——能够驾驭别人驾驭不了的东西。

    * 人现在唯一的功能，就是带着 AI 做 AI 现在做不到的事情；一旦没有这个能力，就立即已经被淘汰。

* **课程运行规则**

    * 可以不来上课：知识有更高效的呈现方式，不用到课、不用看直播，把时间放到实践上。

    * 禁止古法编程：手写每一行、靠刷题过关那一套在这门课不作数；体制的改变自上而下传导会很慢，先撕开一个小口子。

    * token 自费：自己去充，尽量在夜里这类谷时用；夜里 DeepSeek 比较便宜，白天上课正好是峰时。

    * 考核只分通过 / 不通过，不用分数排出高低：同一个任务让 Claude 3.5 Sonnet 做，就是比 DeepSeek-V3 Flash 做得又快又好，模型不同质量天然不同，打分谈不上公平。

    * 建议每个同学去 DeepSeek 充 100 块；除幻灯片生成用一个更聪明的模型外，课程所有演示——幻灯片、lecture 里的东西、生成的 assets——全部使用 DeepSeek-V3 Flash，即一个足够便宜、但智能相对有一些的模型。

* **上课即演出与课程的数字永生**

    * 上课被理解为一种表演：教师是演员，要调动大家的情绪，按照预先设定好的剧本去做一场演出；课后 review 今天的表演，把即兴的、不完美的部分重新整理。

    * 讲义 markdown 是唯一的事实源（source of truth），图片、幻灯片等一切其余产物都是 AIGC。

    * 流程：从写好的 markdown 讲义里选中一段 snippet，由 agent 扩写成 markdown slides，最后在浏览器渲染播放；幻灯片里紫色的部分是模型添油加醋补上的内容。

    * 数字永生：把上课的录像（这次表演）重新回到 code 上，切片整理成一个程序；这个程序可以定制成任何人想要的样子，并可由全世界的人维护。

    ```text
    markdown 讲义（source of truth，课前自己写）
          │  选中一段 snippet
          ▼
       agent 扩写
          │
          ▼
    markdown slides ──────▶ 浏览器渲染（按 F5 播放）
          ▲                        │
          │                        ▼
    AIGC 生成的图片与素材      紫色部分＝模型添油加醋补上的内容
    ```

* **多模型协作与算力换智力**

    * make-slides skill 从一个写好的 markdown 演讲稿出发，让模型添油加醋去做点有趣的事情。

    * 「AI 梗同学」skill 生成三个 sub-agent 并赋予它们不同的 personality，它们在相互隔离的上下文中工作，最后主 agent 回来汇总。

    * 用算力换智力：付出更多的算力，就能得到更多的智力。

    * 提示词换过好几个版本、每一个版本都重新生成一次，最后让另外一个别的模型做 reviewer 来盲评，挑出相对质量最高的那一版。

## 大语言模型与智能体机理

* **大语言模型（Large Language Model，LLM）**

    * > **定义**：大语言模型是一个学到的概率分布；你给它一段很长的文本（可以是一本书，也可以是图像），它不断地预测下一个 token 的概率，每次输出可以理解成一个字符、一个字符地往外蹦。

    * 与概率统计课上抛硬币的题目没有任何区别：抛了六次硬币加起来是多少，问某一次抛出某个面的概率是多少。

    * 在书后面追加一句「能不能帮我总结一下这本书？」，模型就会继续预测下一个 token。

    * 模型很大、见过了世界上所有的东西，训练它很难，这是 frontier lab 之所以牛的原因。

    * 从使用者视角不需要任何关于大语言模型的内部知识，打开 DeepSeek 的网页或 API 问它「什么是大语言模型、我怎么样体验它」即可。

* **从预测下一个 token 到智能体（Agent）**

    * > **定义**：agent 就是那个语言模型；让它输出一个特殊 token 表示「能不能调用一个 bash 程序」，程序运行以后结果重新送回到 agent loop 里，agent 就可以自主运行。

    * 触发条件：模型可以输出越来越长的文本、也接受越来越长的上下文；先有了推理的模型，然后有了 coding 的、ReAct 式的 agent。

    * 机理：模型输出的是文本，其中一种特殊的文本被解释成「去执行一个命令」，命令的输出又变回上下文的一部分，整个循环就能自己转起来。

    * 效果：给一个比较复杂的任务，它不断尝试、改错了就换一种方法再试，最后把任务完成。

    * 终端与系统配置（sway 窗口管理器、现代终端、`ls` 自动换成 eza、`find` 自动换成 fd）都可以只用一个 prompt 交给 agent 配好。

    ```text
            任务 / 对话上下文
                  │
                  ▼
         大语言模型（预测下一个 token）
                  │
         ┌────────┴─────────┐
         │                  │
      普通 token        特殊 token：请调用工具
         │                  │
         ▼                  ▼
     继续输出文本       bash 等程序执行
                            │
                            ▼
                      执行结果送回 loop
    ```

* **模型能力的跃迁**

    * 2023 年 GPT-4 时代，被要求用朴素的语言打一个合适的比方，帮五岁的孩子理解什么是扫描电子显微镜。

    * GPT-4 的比方：闭着眼想知道山的形状，就对着那座山扔球、扔石头——有的方向穿过去了，有的方向弹回来、能听到声音，于是像 ray tracing 一样可以推测出山的形状；这个比方经查资料确认是对的，今天的模型因为有 reasoning，解释得更好。

    * 一个 prompt 可以给 GCC、LLVM 找到 150 个 bug；同样的工作放在今天就是一句话的事情，不需要再做任何为模型做的特别调整。

* **尚未释放的能力**

    * next-token prediction 是一个效率很低的模型。

    * diffusion 类型的语言模型从一个随机的噪声开始，像 diffuse 图片一样一点一点生成很长的文本，过程像人做梦——在梦境当中一点一点把一个东西想得、看得越来越清楚。

    * 未来的可能性包括 diffusion 类型的语言模型，以及不再 predict next token、而是可以把上下文回过头去改、随时把一个很长的文章裁短。

    * AI research 界大家都在赌模型会持续突破，摩尔定律还在；无法预测哪一条路线、哪一种模型会胜出，但可以预见这个世界肯定会变得非常不一样。

## 使用智能体的最小原则

* **两条最小原则**

    * 第一，现在就开使用。

    * 第二，随时问它。

    * 用配置文件（如 `agents.md`）告诉 agent 它是什么；agent 之所以知道某门课，来自仓库 `agents.md` 的配置，这部分是临时得知的。

    * 再往上，其实是你的想象力限制了你的 agent 的上限。

    * > **易错点**：⚠️ 如果只会说「帮我把这个作业做了」，说明用 agent 的方式还没有被解锁。

* **整套系统由 AI 配置的案例**

    * U 盘装 Linux：让 agent 去 `mirrors.nju.edu.cn` 找一个 Debian 13 的镜像装到 U 盘上，确保这个 U 盘可以启动，然后用模拟器验证。

    * 点睛之笔是「用模拟器验证」这一句：agent 装完之后真的在 QEMU 里面启动、看到登录界面并确认登录成功，再按指定的用户名与密码创建用户，验证完成才交付。

    * tile-based 的窗口管理器与终端、Neovim 的现代配置全部用自然语言完成，没有看过任何一眼配置文件。

    * 不会用就问：让模型读系统当前的设置、生成一份「我要做各种事情该怎么办」的文档，例如 Super 加 Enter 打开 terminal、Super 加 D 打开 app launcher。

* **学习顺序的改变**

    * 现在的学习方式是先用好它、先把东西搞出来，再回头去复盘、理解，效率比从零开始一点一点搭积木要高很多。

    * agent 彻底颠覆了「学习曲线太陡、不想用」的瓶颈：改配置文件一改就出错的痛苦被消解，它不仅能改，还能事无巨细地解释为什么要这样改。

    * 危险在于你的理解可能和那个更好的理解会有差距，这一点目前未知。

    * > **提示**：谁掌握了 AI agent，谁就掌握了暴增的学习效率。

## 智能体日常实践

### 事务与个人助理

* **邮件与附件处理**

    * skill 里存有历史上回过的所有邮件，收到一封邮件会自动把它变成已读状态，然后自动用本人的口吻写好回复的草稿。

    * 除那些简单的、routine 性质的东西可以直接用它的回复以外，大部分时候还得人工去改，但至少得到了 AI 的 draft。

    * 收到发票时会把发票自动保存到一个指定的归档位置，这些都是写好的 instructions。

* **待办与通知闭环**

    * 在手机备忘录里加一条「帮我把今天的发票打印出来」，点 Go 就 commit，于是多了一个 todo 项。

    * 后台处理完成后重新给出一个推送通知，通知经过 Reminders 送到手表，手表提示「打印完了」。

    * 前提是放心的事情才交给它处理；这个流程比 Telegram 聊天框要好。

### 读书与读论文

* **读书的流程**

    * 为做每一页 slides，先让模型做两件事：回看人类的历史，在与内容相关的案例里找有没有 lessons、有没有能得到启发和印证的重要案例；再根据所讲的东西去找相关工作，并且 prefer 那些 well-recognized、high-impact 的结果。

    * 附加要求包括 Thinking in First Principles；通过随机性抽卡、讨论、产生分歧的观点，再由主 agent 把分歧的观点送回去讨论，直到收敛，形成一个「算力换智力」的 loop。

    * 提及的书：Fred Brooks 的 The Mythical Man-Month（man-month 指人力，标题其实是「人力神话」，更贴切应叫《人月鬼话》）；John Ousterhout 的 The Philosophy of Software Design（非常紧凑，里面有很多真正的软件工程的智慧）。

* **读论文的流程**

    * 把人类已有的知识视为已知固定，把这篇论文里新的、最少的那部分剥离出来，一篇 12 页的论文基本上就没剩下多少，会变得非常非常短。

    * 仍然读论文，方式是拿着论文的原文、总结、分层次的总结跟模型 chat 讨论。

### 视频与信息消化

* **长视频的图文时间轴**

    * 给一个 BV 号即可，把视频总结成一个自动的图文时间轴，整理过的文本质量比字幕的质量要高一些。

    * 截图密度按帧间隔决定：两帧图片之间的间隔大到一定程度就截图，从而得到这个视频所有的 ground truth。

    * 「AI 梗同学」带着本人的记忆上线，知道哪些东西对自己是 trivial 的并直接去掉，于是可以在几分钟的时间里面看完一个两个小时的视频。

    * > **注意**：如果是纯娱乐的视频，就不要用 AI 读了。

### 现场排障

* **USB 设备断开与恢复**

    * 直播时 USB 摄像头卡住，原因是采集卡的 USB 断开了。

    * 用一个 prompt 让 agent 先查看系统的 USB 设备情况、找出设备，再说「我的 USB 有问题，能不能 reconnect」。

    * 使用的模型是 DeepSeek-V3 Flash，它用出了一些前所未见的 Linux 命令。

### 学习效率的量级差距

* **效率差距与竞争**

    * 在 AI agent 的时代，会用 agent 学习的人和不会用 agent 学习的人，学习效率的差距是 10 倍、100 倍。

    * 竞争力问题回到简历：如果所有人的简历都是一样的，就要想那个没有给你看到的、学习效率是你 100 倍的人，他的简历会长什么样。

## 智能体生态

### 复用定律与插件

* **复用定律**

    * > **定义**：如果有一件事情它是合理的，并且你想做，那么 100% 一定也有别人会想做。

    * Pre-AI 的时代，开源社区多多少少会公开一些脚本来干这件事，到 GitHub 上把它拉下来就可以做自己的事。

    * AI 时代，复用别人的能力变得前所未有的轻松：可以往 Skill Hub 上面发一个 skill，也可以在 Pi 的插件生态里找到一个插件。

    * > **提示**：普通人下一步应该做的，是用插件把浏览器管控起来、用插件把电脑管控起来。

### 浏览器作为可管控对象

* **浏览器（Chrome）与 Chrome DevTools**

    * 浏览器是人类软件工程史上的奇迹之一：看起来就是个显示网页的浏览器，实际上非常复杂，代码量甚至远超操作系统内核——因为它要和用户打交道，有大量的图形栈、显示相关的东西与性能优化。

    * 它为开发者专门留了一个接口，叫 Chrome DevTools，按 F12 打开。

    * 能做的事：删掉页面上很讨厌的某个东西；在 console 上看到网站嵌入的招聘广告；看到 HTTP 的头；把一个请求 copy as curl，带着浏览器的 Cookie、带着所有的状态，用 `curl` 在浏览器外面去请求、拿到列表。

    * 这些都是 Pre-LLM 时代开发者做的事情；LLM 时代的变化是普通人也可以享受到 Chrome DevTools 所有厉害的地方。

* **在浏览器里运行 Android 应用**

    * 前提：Android 应用可以用 Java 写，Java 或 Kotlin 都编译到 Java 虚拟机，于是可以在 OpenJDK 上运行一个 Android app。

    * 做法：把界面上所有按钮的 bounding box（坐标）都算出来、上面的文本也知道，不走 Android 底层的渲染，直接在浏览器里面画出来。

    * 效果：在 Chrome 里看到一个计算器，每一个按钮都在、上面的字也是对的，点它计算器的状态就变了，相当于在本机执行一个 Android app。

### 从翻车到沉淀脚本

* **教务系统的自动化尝试**

    * 教务系统是一个软件工程非常反面的例子。

    * 在 Pi 里说「帮我打开浏览器」，这个浏览器是属于 Pi 的；此时教学周历是空的。

    * 指令是「帮我用随便什么 AI slop 填写，不要看任何东西」；强调「不要看任何东西」是因为如果它知道当前目录是这门课的 repo，它就会去读 lecture notes。

    * DeepSeek-V3-Flash 没有听指令，还是去干了那个事；换成 Claude，它会知道。

    * > **提示**：真正值得看的不是「它翻车了」，而是它翻车以后怎么回来——它会不断地反思自己做的这件事合不合理，然后找到应该怎么办；一开始尝试用注入事件的方式发现不行，后来发现点鼠标是可以的，看起来在翻车，其实是它在试错。

* **从会话到确定性脚本**

    * 走通过一次以后，这个 session 里面的东西会留下来，可以把它沉淀成确定性的脚本。

    * 它可以形成记忆：这条路应该怎么走，什么能成功，什么会失败。

    * 它也可以把走过的这些网页全部变成脚本，于是得到一个自动选课抢课的系统。

### 生态临界点：组合与飞轮

* **管道、组合与复用**

    * Unix 的 philosophy 之所以能成立，靠的就是管道，它实现了所有程序的自由组合和无限复用，1+1 是可以大于 2 的。

    * 从上下文里提取记忆和脚本的能力、浏览器的 skill、在网页上怎么浏览的 skill，它们可以加在一起、互相调用。

    * 这些东西的互相组合，可以成百倍成千倍地放大个人的能力。

* **信息处理的飞轮**

    * 信息源包括 AI 早报（有 RSS、有推送源）、B 站的推送、arXiv 的推送、Hacker News 的推送。

    * 这些信息源各做一次沉淀，变成 skill 或者脚本，进入一个信息处理的系统：大量的信息源进入处理系统，处理系统最终产生有用的知识。

    ```text
    AI 早报(RSS) ─┐
    B 站推送      ├──► 各沉淀为一个 skill / 脚本 ──► 处理系统 ──► 有用的知识
    arXiv 推送    │                                      ▲              │
    Hacker News  ─┘                                      └── 不断调整工作流 ┘
    ```

    * 图里每一段都是自然语言的 skill，一行代码都不用写；它们可以复用，工作流不断被调整，就不断产生对你有用的知识。

### 现象级产品与自我进化

* **现象级产品的惊喜与局限**

    * OpenClaw 和 Hermes 是现象级的产品，能给人很大的惊喜，比如自我进化的能力。

    * 作者并不惊艳，尤其讨厌它去组织 memory：它有它的提示词，会把我并不想让它记住的东西记住，我想让它记住的东西它不记；更倾向调用自己的流程，把该记的东西写到自己的数据库里。

    * 自我进化的玩法：录屏一天，让 AI 自动改你的流程，问它「我这一天干了这些事，你觉得我还有没有提升空间」，在初学者的阶段提升空间很大。

    * 一旦模型过了那个临界点，一个人比 AI 多的就那么一点点，等那一点点也被 AI 取代了以后，人也就被消灭了。

## 计算机科学视角下的能力边界

### 复用形式的分野

* **需求编译与复用判断**

    * 一般人很容易提出一个需求，而这个需求 agent 可能做不好、做不了；或者他不知道该怎样 prompt 这个 agent，才能让它确定性地、快速地完成。

    * 作为 Computer Science 从业人员，非常清楚编程的能力界限在哪里。

    * 关键判断是怎么把需求编译成可以复用的东西——什么应该以代码的形式复用，什么应该以 skill 的形式复用。

    * > **提示**：如果只是用 agent 说「帮我把操作系统的作业做了」，那真是太小看它了。

### 改卷统分流水线

* **改卷统分流水线**

    * 由头：改完卷子要统分，一般交给助教用计算器 `12+13+14+15+16` 加一遍、再仔细核一遍。

    * 基本做法：先 vibe code 让它出脚本、出测试，测试流完之后一口气把它跑完。

    * 第一阶段：办公桌上有一个从顶向下的摄像头，拍到试卷的一个固定位置并先调好；按一个回车拍一张照，回头 offline 用千问识别姓名、学号、每一个小分，往一个文本文件里写一行；一张卷子按一个回车，没摆好就调整一下再来。

    * 第二阶段按反序，仍然按回车键但左右手换了：左手按回车、右手拿笔；按回车后它用语音播报谁谁谁的学号是多少多少、把每一个小分都报出来，一边报一边人工检查；检查过没问题，才把它报的那个最终分数抄写到卷面上。

    * 收尾：抄写卷面 → 教务处 Excel 模板 → 上传 → 抽样复核 → 提交。

    * 环境：本地有一个 27B 的千问，有 Ollama 可以用。

    * > **易错点**：⚠️ 这条流水线的关键不在识别，而在「我没有让大模型做加法」——总分是脚本 eval 出来的，所以它不会错，不会因为大语言模型的幻觉算错；OCR 只负责把每个小分读进来，读错的部分由人工核对。让模型去算总分，是这类任务里最容易翻车的地方。

    ```text
     顶向下摄像头（固定取景）
            │  ↵ 回车
            ▼
      拍一张照 ──► 本地 27B 千问离线 OCR ──► 姓名 / 学号 / 每个小分 ──► 文本文件（一张一行）
                                                                            │  ↵ 回车（反序）
                                                                            ▼
                                         语音播报：学号 + 各小分 + 脚本算出的合计
                                                                            │  人工逐项核对
                                                                            ▼
                                       抄写卷面 ──► 教务处 Excel 模板 ──► 上传 ──► 抽样复核 ──► 提交
    ```

* **人与 AI 共建的现状**

    * 一般人做不到这一点：哪怕对着最好的模型说「我现在改了 140 张卷子，小分都已经写上去了，我要统分，帮我实现它」，也到不了这么一个快速收敛的方案。

    * 现在还需要人和 AI 共建，但可以赌有一天 AI 的能力能够强到感知一切，然后帮人做一个完美的东西。

## 系统边界与规约驱动开发

### 被管控机器的通道设计

* **数据外泄通道（示例产品）**

    * 场景设定：在金融公司里数据可以带进去、出不来，插一个 U 盘可以把 Word 或 Excel 拷进去，但没有任何文件可以拷出来；机器做了管控，不能执行任何不信任的程序，也不能显示任何不信任的网页，唯一能做的是在远处用远程桌面悄悄摄屏。

    * 往外的通道——二维码动画：把任何一个文件的内容编码进二维码，内容是 `Hello world` 时二维码随内容变化，扫出来是 `0001` 加上 Base64 编码的字符串；很长的字符串可以编码成带帧号的二维码动画，按住 F9 逐帧刷新、循环播放，只要偷偷摄屏把每一帧都拍到，就把数据偷走了。

    * > **注意**：这个过程用的全部是完全合法的东西——它就是一个 Excel 文件，里面全部是 Excel 公式，而且是 2019 之前的 Excel 都兼容的公式；合法的东西组合起来，就是一个数据外泄的通道。

    * 往里的通道——抖鼠标：在上下维度抖鼠标就是 0，往左右维度抖鼠标就是 1，用远程桌面连进去就可以往里面传输数据。

    * 组合效果：只要有一个远程桌面，就等于在内部做了一个虚拟网卡，可以把远程桌面变成虚拟网卡，然后和它连起来。

    * 所需知识：上过操作系统、上过计算机网络，知道这里面需要的组件是什么，就可以把它 vibe coding 出来。

    ```text
     抖鼠标（上下=0 / 左右=1）
            │  远程桌面会话
            ▼
       ┌──────────────────────────┐
       │   被管控的内网机器        │
       │   仅渲染可见内容          │
       └──────────────────────────┘
            │  Excel 公式逐帧生成的二维码动画
            ▼
          屏幕 ──► 外部悄悄摄屏，录下每一帧 ──► 重组文件
    ```

### 一般人手上的三类能力

* **学习、操作与生成**

    * 学习：看书、做总结，然后实现一个信息处理的闭环。

    * 操作：用 computer-use、browser-use 去做任何平时日常里做的事情。

    * 生成：因为 Everything is code，可以用 AI 生成你能看到的所有东西——视频、论文。

    * 从 bit 到 atoms：1-Fab 项目用一句自然语言让 3D 打印机打印一个东西出来，真的东西也是 code、也是 Python 代码，生成的是 Python 代码。

    * AI 的能力只会变强，不会变弱；剩下的问题是它什么时候来，以及我们应该怎么面对它。

### 产品是系统性工程

* **系统性失败**

    * LLM 之前的老梗：「idea 都有了，我们是商学院的」「idea 都有了，就差一个程序员了，我们去挣一个亿吧」「ABCD 轮也都有了，就差一个天使投资人了」——真没有那么简单。

    * AI 也能设计前端、也能做后端、也能做交互、也能做运营，它看过世界上所有的书、什么都知道；但你要做一个外卖网站，整个流程上面任何一个环节做不好，产品都是直接暴毙的。

    * 用二维码 Excel 工具做实验让 AI 去做，AI 生成了完全不可维护的代码。

    * 某选课系统难用，而学校每年都会花巨额的钱让公司维护这份代码。

    * 苏州校区字段案例：设计需求的时候没有想到学校竟然还有「校区」这个东西，数据库里就没有这个字段；突然有一天产品经理说「我们两个校区选课要分开」，于是 AI 回去洗版；虽然能改，但还是很容易失败——这是非常典型的软件工程的失败。

### 需求歧义与最小可行

* **二维码 Excel 工具的暴毙过程**

    * 需求非常明确：要一个 QRCode 的 `.xlsx`，只使用 Excel 2019 兼容的公式，把输入的任意一个字符串先用 Base64 编码，然后转成 QRCode 动画。

    * 开始让 AI 做的时候，这个任务经常做到一半停下来问；被告知不要问之后，AI 对这个需求的理解仍然是不妥当的。

    * GPT-5.6 说得对，是因为它看到了完整的课件；但它没有被告知作者是怎么做的，于是认为「AI 容易在小的 corner case 上犯错」，希望做一个对任意的 $s$ 都满足正确性的东西。

    * > **易错点**：⚠️ 把「输入的任意一个字符串先做 Base64」误读成「要对任意 $s$ 都正确」，于是去做一个大而全的实现，第一秒就被带歪，方向从一开始就错了。软件工程的第一步，不要扩大，做最简单的东西，不会失败。

    * 需求原话「把输入的任意一个字符串先用 Base64 编码」意味着输出必须随输入变化，而不是把某一次输入的结果写死在文件里；一份硬编码的 Base64 放在那儿，功能上立即就不成立了。

* **多模型受控实验**

    * 第一个版本是带着 AI 做 vibe coding 做的，所以做得比较顺利；之后直接把这个 specification 告诉 AI，让几个模型各自去做。

    | 模型 | 过程 | 结果 |
    | :--- | :--- | :--- |
    | GPT-5.6 | 看到完整课件，仍把需求理解成「对任意 $s$ 都正确」 | 第一秒就被带歪，方向从一开始就错了 |
    | AI TR-5.3 | 第一次思考了 25 分钟，然后疯狂输出，写了超过 32k output token，直接把 Claude Code 干爆（超过默认 output 限制被截断），再继续跑；全程没有监管，一共跑了 6 个小时 | 是对的；它在 long horizon 任务上确实做得很好 |
    | DeepSeek-V3-Pro | 晚上放着跑，第二天早上看，它已经没有办法遵循指令了 | 给的 Base64 是硬编码的——它用 Python 算了一个 Base64，明显不符合指令 |

    * 把这几件事放在一起看，说的其实是同一件事：AI 能做的东西很多，但「它能做」和「它能被组织成一个不会暴毙的产品」之间，隔着的正是软件工程——先不扩大，先做最简单的、不会失败的那一版；把需求说到不产生歧义，并且说清楚边界在哪里。
