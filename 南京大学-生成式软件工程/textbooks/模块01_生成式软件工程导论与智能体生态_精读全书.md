## 人的唯一功能：带着 AI 做 AI 做不到的事
> 对应块：BLK01 | 覆盖分集：P01上 | 块标题（分集名）：《欢迎来到未来（上）》

我按了一下 F5，浏览器弹出来，课就正式开始了。今天我们站在一个非常重要的交叉路口上——你们是 computer science 的同学，我们不妨从你们刚进学校的这个时间点往回看，看一看计算机发展的历史。

### 站在交叉路口：从 PC 到 ChatGPT

计算机发展的历史上经历过很多次非常重要的变革，我觉得其中最主要的一条主线，是把昂贵的能力变成日用品。

1975 年我们有了第一台 PC 机 Altair 8800。配的那张图也是 AI 生成的，你能看出非常明显的 AI 味儿，而且应该还不是一个特别强的模型。我说过我上课是跟大家比较松散的讨论和交流，之后我还会把课程重新切片、再整理一次。

从 PC 到互联网，互联网把所有人连了起来。我至今都记得——你们没有经历过那个时代。我那个时候大概小学快毕业，装了一个软件叫 ICQ，就是 I seek you 的那三个字母。那时候腾讯的山寨版还叫 OICQ，后来才改成 QQ。你可以随机地加一个世界另一端的人，加到的基本就是 native speaker，他一下子发一大段英语、打得非常快，你完全无法理解他在说什么，因为那个时候我们刚学一点点英语，只会 Hello、Good morning。

从互联网到移动互联网，我印象特别深：一夜之间，所有菜场卖菜的人都有了支付宝和微信两个二维码。在很短的时间里，它一直在改变我们生活的方式。

然后到 2022 年，ChatGPT 出来，AI 成了人类历史上增长最快的产品。

> **结论**：站在这样一个人类命运的交叉路口上，该学什么、该怎么学，都需要好好想一下。正是在这样的背景下，我决定开一门 vibe coding 的课。

### “AI 替我上大学”：两种焦虑，和一份零分简历

大家有一个说法叫“AI 替我上大学”，我觉得这个说法很对。你想嘛：老师用豆包出题，学生用豆包做作业，整个闭环过程里，只有学生没有受到训练。

现在 vibe coding 很厉害，作业可以直接丢给 AI。操作系统课的作业曾经折磨过大家，大家在痛苦的折磨中获得提升——现在不要了，你直接把作业的链接丢到 Codex 里就行，连复制粘贴的步骤都不需要。你甚至可以连链接都不给，直接说“操作系统课第八个实验，帮我实现一下”，这就结束了。

所以在这样的时代，我们到底还应不应该学编程这些东西？答案肯定是既应该也不应该：有些能力你还是需要的，但应该怎么做，我们不知道。所以我看到的其实是大家都在一种非常焦虑的状态里。

| 焦虑 | 处境 |
| :--- | :--- |
| 第一种 | 作业和考试全交给 AI，每门课看起来都很好，可四年下来什么都没学会，一毕业就被 AI 取代 |
| 第二种 | 把中学里听老师话的习惯延续到大学：每堂课都认真听、每次作业都认真做，毕业时确实学会了点什么，但学会的东西 AI 都会做 |

还有一种更让人迷茫的情形，落在你自己身上就是保研。你们投了很多简历，我也收到过很多这样的简历，我觉得非常糟糕。

我先说这份简历是怎么来的：全部都是 AI 做的，我没有干涉任何事。我只是告诉它这里有一份简历、我要在上课的时候展示一下、需要把个人信息去掉，它就把那些字符替换成了 Unicode 的方块——你复制粘贴出来会看到一个黑色的方块字符。隐私是隐掉了。

然后你得到一份“非常完美”的简历：CCF 期刊列表上面的论文、accepted，还有若干在投。当然大家都说“在投”等于不存在，因为你看不到它。

> **提示**：“在投”的论文在读者眼里几乎等于没有——看不到的东西，别人无法验证，也不会为之加分。

但这对我来说是一份零分的简历。因为它里面没有任何额外的信息：没有一个 GitHub 链接，没有一个个人的主页，没有一天的 preprint。我不知道这位同学发生了什么，但对我来说这样一份简历非常非常糟糕。更糟糕的是我收到过无数份这样的简历，而你们的简历多多少少也长成这个样子。这时候你会发现，你和你的竞争者已经无法区分了：所有人都是我有一大堆实习、一大堆奖项、一大堆论文、一大堆在投。那是什么能让你从这些简历里脱颖而出？

好消息是，我希望用这一门课来缓解一下大家这样的焦虑情绪，更多的是带大家还原一种快乐——vibe coding 的快乐。我在 vibe coding 里得到了很多快乐，而在这个快乐里你们又能一定程度上理解软件工程是怎么工作的，能做出一些有趣的东西，也能让你的简历更好看。顺便说一句，对我来说你有一篇发表的论文可能反而是个减分项，但对很多人来说也许不是。

### 这门课讲什么：让软件不失败，以及人还剩什么优势

这门课的题目叫“生成式软件工程”，所以它其实是一门软件工程课。软件工程做的事情很简单：怎么样让软件不失败，怎么样造出一个软件来。

我们经常听说，你们作为人，和 AI 比优势在哪里？你可以坐牢，AI 不能。这是个玩笑，但顺着它往下想，大学里面能教你的、或者说你大学毕业时能拥有的能力，比较重要的第一个是信息差。

信息差是人类社会要进步就必然存在的东西：你拥有别人不知道的信息，你才能做别人做不到的事。所以在学校里多多少少也会有这种恶性竞争——比如你拥有一份往年试卷，别人都没有，那你就可以在竞争当中胜出。这是你们身边的一种信息差，当然还有很多别的、不方便说的信息差，在社会上也广泛存在。

除了信息差以外，你作为个人的优势是你可以坐牢。但大学真正教你的，是怎么样成为一个更好的人：你能够驾驭别人驾驭不了的东西。你在大学毕业的时候可以说，我是一个更好的人，我有一个别人没有的能力。

> **定义**：这门课要做的事，就是试着帮大家建立驾驭人工智能的能力。

### 这门课怎么上：一场演出，和它的数字永生

我希望这门课用一个案例为主的、比较松散的组织方式。如果你有兴趣来跟我讨论、想来 challenge 我，说“你这个地方做得不对”，那欢迎大家来线下。如果你是听课型的同学，希望从这门课里获取知识，那我完全建议你既不用到课，也不用看直播。

我今年想做一个非常有趣的尝试。你看到这是我的 slides：左边是我上课之前写好的讲义，按 F5 就能播放。写讲义的意思是，我会先想好今天上课大概在什么时间讲什么、举什么样的例子——相当于我要先约束好 AI 该做什么。而按 F5 播放出来的 slides，和那份 markdown 是有点不一样的：幻灯片里紫色的部分，是 GPT-5.6o 给我添油加醋加上去的。

我为此有一个 skill，叫 make-slides：从一个我写好的 markdown 演讲稿出发，让它添油加醋去做点有趣的事情。比如我还有一个类似“AI 梗同学”的 skill，我会让它生成三个 sub-agent，给它们赋予不同的 personality。这个非常有效果：有的 agent 会干这个，有的会干那个，它们在相互隔离的上下文里工作，最后我的主 agent 回来汇总。这样我就可以用算力换智力——我付出更多的算力，就能得到更多的智力。

提示词我换过好几个版本，每一个版本都重新生成一次，最后再让另外一个别的模型做 reviewer 来盲评，看哪一版生成的 slides 质量比较高，然后挑出相对质量最高的那一版。幻灯片里的图片全部都是生成的。

```text
markdown 讲义（source of truth，课前我自己写）
      │  选中一段 snippet
      ▼
   agent 扩写
      │
      ▼
markdown slides ──────▶ 浏览器渲染（按 F5 播放）
      ▲                        │
      │                        ▼
AIGC 生成的图片与素材      紫色部分＝模型添油加醋补上的内容
```

这张图就是整套流程：markdown 是唯一的事实源，其余的一切——图片、幻灯片——都是 AIGC；agent 把选中的片段扩写成 markdown slides，最后在浏览器里渲染出来。

我希望探索的是一条能真正改变整个大学讲课方式的路径。如果你们是来学习的，那更高效的方法是什么？我作为一个上课的人，应该思考的是怎么样把知识以更好的方式呈现给大家。

我的答案是：上课是一种表演。我是一个演员，要调动大家的情绪，上课的时候跟大家交流，按照我预先设定好的剧本去做一场演出。演出完了以后，我要做一件很重要的事——review 我今天的表演。我今天举的这个例子可能不是特别恰当，回过头来我可能想到另外一个案例，大家能够更加感同身受。你在上课的时候有一部分是即兴的，而即兴意味着其实不完美。课后我会把这门课的录像切片、重新整理成片段。

我是从 contents as code 来的，everything is code。我就可以把上课的录像——这次表演——重新回到 code 上，把它变得更丰富。这样我就实现了一门课程的数字永生。

我希望的是用切片的方式得到一个“完美版本”：比如今天要讲生成式软件工程，它的要点是什么、逻辑是什么、第一节课应该怎么上，沉淀成一个程序。这个程序现在也许由我维护；也许有一天我不维护了、操作系统课我不上了，我就把操作系统课在 B 站的录像整理成这样的切片，然后可以由全世界的人来维护它。你想要一个什么样的操作系统课，就可以把它定制成什么样子。这不就把所有大学教课的方式给颠覆了吗？我觉得这是一条可能实现的路，所以我会在这门课上做一个比较新的尝试，也欢迎大家随时给我反馈。

### 课程的组织方式与几条 policy

我希望重新找回同学们心中那种“上课耽误学习”的感觉。虽然你们可能还是要去上课，但我推荐大家第一个可以不要上课——你可以把时间花在这门课上的实践里。我后面有很多真正实践的案例，会带着大家做，让你们知道在 AI 的时代，你们学习的方式变了，你们工作的方式也变了，可以尽快适应这个非常有趣的时代。

| policy | 具体做法 | 我的理由 |
| :--- | :--- | :--- |
| 可以不来上课 | 不用到课、不用看直播，把时间放到实践上 | 知识有更高效的呈现方式，我要找的就是那条路 |
| 禁止古法编程 | 手写每一行、靠刷题过关那一套，在这门课不作数 | 体制的改变自上而下传导会很慢，我想先撕开一个小口子 |
| token 自费 | 自己去充，尽量在夜里这类谷时用 | 算力开销自己承担，但费用其实是可控的 |
| 通过 / 不通过 | 只区分通过与否，不用分数排出高低 | 模型不同质量天然不同，打分谈不上公平 |

#### 允许不来上课，禁止古法编程

我相信你们个个都是古法编程的好手，因为你们要考试，马上要保研、要机试了。机试就是把你往小黑屋里一关，你看过我以前出的题，然后就吓尿了，赶快再去 LeetCode 上刷一刷。

但我觉得总有一天这个事情会改变的。从上而下传导不会那么快——你要改变一个体制很难，但我非常想撕开一个小小的口子。

#### token 自费：用足够便宜、但有点智能的模型

本来我是想去拉一些 token 赞助的。但当我看到选课学生的数量的时候，我就想还是算了，也没有必要再去拉着脸去要好多好多的 token，比较麻烦。

首先我有一个个人观点：如果你们手上没有付费 token，那应该立即退学。在硅谷有一种 token-maxing 的玩法，就是死命地烧 token，但你们没有必要那样。

我这门课上所有的演示——除了幻灯片生成我用一个更聪明的模型、因为它能给我更好的质量以外——你看到的幻灯片、lecture 里面的东西、生成的那些 assets，全部都是 DeepSeek-V3 Flash。也就是说，这门课我会用一个足够便宜、但智能相对有一些的模型，带大家把这些事情完成。

我也知道大家都是夜猫子，都是 computer science 的学生，喜欢在夜里工作。而夜里 DeepSeek 是比较便宜的。所以我建议大家在谷时用：白天你们要上课，那正好是峰时；等你们回去做作业的时候，就是谷时了。token 非常重要，每个同学去 DeepSeek 充 100 块，这个还 OK。如果实在 token 有困难的同学，可以联系我，我们一起想个办法。

#### 考核只分通过与不通过

还有一个很重要的 policy：我希望用一个“通过或者不通过”来 evaluate 这门课。我在申请这门课的时候，考核方式填的就是通过和不通过。但根据教务的反馈，专业选修课一般不会做成这样，一般来说是像形势与政策那样的课才是通过与不通过。

原因是我们现在还不知道评判标准是什么。你可能用了更好的模型，就能有更好的质量：同一个任务，你让 Claude 3.5 Sonnet 来做，就是比 DeepSeek-V3 Flash 做得又快又好，没办法。我们也没有办法限制大家用什么样的模型，那怎么评判？尤其是这样一门做 project 的课。

我大概会有一些建议的项目：比如我回头会更新课程网站，告诉大家你可以实现一个自己的 email 管理系统，然后可以回我的 email——我会用一个指定邮箱给你发邮件，你把邮件给我回回来。你可以 vibe coding 一个这样的服务，跑在你宿舍一台一直常开的小电脑上，这就是一个比较不错的实验。有的同学可能会做得复杂一点，有的简单一点。我会用我的邮箱去跟大家发邮件通信。

#### 最终检验你的是那份简历

到底什么叫做好、什么叫不好、到底该给多少分？我觉得在这个时代，分数已经变得不那么重要了，而真正重要的是你最后找工作、或者保研的那一刻，投出去的那份简历上有什么东西。

对你们来说其实就只有那一个考试。当然比较糟糕的是，为了能够走到那一刻，你还需要有一个比较好的 GPA，还得去 reward hacking，还得去 overfit 那个考试的题目。但最终检验你大学阶段的，是交出去的那份简历能不能带你到下一个更大的平台——你敢不敢给 DeepSeek 投简历？他们的那个 bar 还是比较高的。

所以我希望在这门课上，大家最后能在简历里写：我在生成式软件工程里面实现了 A、B、C、D、E，后面跟着很多链接，每一个东西都做得非常漂亮，每一个你都能说清自己完成了设计、实现，以及它里面了不起的地方是什么。

最终有可能的是，如果每个人的电脑上都给装一个监控，那我就知道你大学四年干的所有事情，然后我的 AI 就可以评判你度过了一个怎么样的大学四年。这当然是非常恐怖的一件事：你摸的每一条鱼、你看的每一部不想让别人知道的小电影，都在你的电脑上发生，所以它都知道。我们不知道人类社会什么时候会演进到那个程度，但保持 open，这是我们的 policy。

好，课程开了一个头，接下来进入技术性的内容。

### 大语言模型就是一个概率分布

我先讲一讲大语言模型。我今天不讲什么叫大语言模型——大语言模型就是一个概率分布，跟你们在概率统计课程上学的那个抛硬币的题目没有任何区别：抛了六次硬币，加起来是多少，然后问你某一次抛出某个面的概率是多少。这类题你们在概率课上都做过。

> **定义**：大语言模型是一个学到的概率分布。你给它一段很长的文本——可以是一本书，也可以是图像——它不断地预测下一个 token 的概率；每次输出，你可以理解成一个字符、一个字符地往外蹦。

具体地说，你给它一本书，书到最后就结束了，但你可以在这本书的后面再写几个字，比如“能不能帮我总结一下这本书？”接下来大语言模型就会不断地预测下一个 token 的概率。这个模型很大，它见过了世界上所有的东西，训练它很难——这就是为什么现在 frontier lab 这么牛。

但这门课是站在使用者的视角上：你们只要知道存在一个东西叫大语言模型，打开 DeepSeek 的网页或者 API，问它“什么是大语言模型、我怎么样体验它”，它就会告诉你——你现在就在体验大语言模型。

所以你不需要任何关于大语言模型的知识。

### 第一次被 AI 按在地上打

我第一次被大语言模型按在地上打，是 2023 年、GPT-4 的时代，让我给五岁的孩子解释什么是扫描电子显微镜。

那个时候我们在玩 prompt engineering，我的 prompt 大概是：我希望用朴素的语言打一个合适的比方，帮助他理解这件事。有一天我在给我五岁的孩子讲一个故事，讲着讲着讲到了扫描电子显微镜，然后我讲不下去了。GPT-4 给了我一个比方：

你现在有一座山，这座山的形状你看不到——你闭着眼，你看不到它，但你又想知道那座山是什么形状，那怎么办呢？你就对着那座山扔球、扔石头。闭着眼睛扔：有的时候石头对着这个方向就穿过去了；对这个方向扔，石头会弹回来，弹回来你能听到声音。于是通过哪些地方穿过去了、哪些地方没有穿过去，就像 ray tracing 一样，你就可以推测出那座山的形状。

小朋友大概听懂了——当然他也不可能百分之百听懂，但那个比方让我觉得非常震惊。首先，它得有这个知识；第二，我后来还特意去查了资料，它这个比方打得是对的。而今天 GPT-5.6o 给了更严谨的答案，而且它因为有 reasoning，解释得更好。

GPT-4 的时代，我就用这个模型去生成奇怪的东西：一个 prompt 可以给 GCC、LLVM 找到 150 个 bug。而这个工作放在今天 GPT-5.6o 的时代，就是一句话的事情——真的一句话，不需要再做任何为 GPT 做的特别调整。

### 从预测下一个 token 到 agent

从 GPT 开始，随着大家发现模型可以输出越来越长的文本、也接受越来越长的上下文，agent 就出现了：先有了推理的模型，然后有了 coding 的、ReAct 式的 agent。

agent 是什么？就是刚才那个语言模型。它可以输出下一个 token，那我就可以让它输出一个特殊的 token，说“能不能调用一个 bash 程序？”这个 bash 程序会运行，运行以后结果会重新送回到这个 agent loop 里。这样 agent 就可以自主运行了：你给它一个比较复杂的任务，它可以不断地尝试、尝试、尝试。

```text
        任务 / 对话上下文
              │
              ▼
     大语言模型（预测下一个 token）
              │
     ┌────────┴─────────┐
     │                  │
  普通 token        特殊 token：请调用工具
     │                  │
     ▼                  ▼
 继续输出文本       bash 等程序执行
                        │
                        ▼
                  执行结果送回 loop
```

也就是说，模型输出的是文本，但其中一种特殊的文本被解释成“去执行一个命令”，命令的输出又变回上下文的一部分，于是整个循环就能自己转起来了。

我自己也是做了一些配置的。你们看到我配置了一个 sway 的窗口管理器，它为课堂展示做了优化：对比度比较高，而且我把顶栏之类的东西全都去掉了，这样你们上课的时候可以看得更清楚。

你们都喜欢用 top 这个命令来查看系统里的进程，如果不做定制，你看到的就是一个比较土的 top；但我这里有一个更 fancy 的 top，你能看到 OBS 还在浪费我的算力、内存还有多少，都是这样。我把终端也配置成了相对现代的样子：你们刚才有没有注意到一个细节——我敲 ls 的时候，其实调的不是 ls，它自动把 ls 换成了 eza；我要 find 的时候，它也自动帮我换成了 fd，fd 的行为和 find 稍微有点不一样。你看 ls 的输出里还挺 fancy 的：这是一个目录、这是一个 markdown、这是一个 Makefile，还有这些特殊显示的效果。

所有这些配置，我都是用 agent 配的。我只有一个 prompt：你能不能帮我把现在的命令行终端、包括我的系统 sway，都配置成这个现代的样子、比较好用的样子。结束了。DeepSeek-V3 Flash，没有更好的模型。

所以在今天，有了 ReAct 这种类型的 agent 以后，它就不停地去改、改错了就换一种方法再试，最后把任务完成。去年我上操作系统课的时候，那个 agent 还不怎么能用，各种出错，任务完成不了它就停下来了；但到今年我上操作系统课的时候，这个 agent 就非常非常能用了。到现在，你看到 agent 产品爆发，铺天盖地都是广告，像 WorkBuddy、豆包的 agent 就是这种 ReAct 类型的 agent。

### Agent 的能力还远远没有被释放出来

这个故事其实远远没有结束。今天你们已经感受到 agent 非常强了，但我个人认为，agent 的能力还远远没有被释放出来。

next-token prediction 其实是一个效率很低的模型。比如这里有一个 diffusion model，我可以让它“write a AI slop novel”，你看看它的过程：它从一个随机的噪声开始，就像 diffuse 图片一样，一点一点、一点一点，最后生成了一个很长的东西。它可以生成很长的一段文本，就像人做梦一样——在梦境当中，你一点一点把一个东西想得、看得越来越清楚。

我们还有很多未来的可能性：diffusion 类型的语言模型；甚至我不是 predict next token，而是可以把上下文回过头去改，随时把一个很长的文章裁短。这些都是今天很多人在研究的东西。

现在的模型已经非常强了。如果三个月以后又有一个新的突破，模型变得更强；一年以后模型又突破了、又变得更强——整个 AI research 大家都在赌这件事情要发生，摩尔定律还在。那我现在很难想，未来会变成什么样子。我没办法预测未来到底哪一条路线会胜出、哪一种模型会胜出，但你可以预见的是：这个世界肯定会变得非常不一样。

而在这个世界上我们应该怎么办，是每一个同学都值得好好考虑一下的问题。

好，吓唬人的事情说完了，我们可以吸一口气，来讲讲实际操作。

### 用 agent 的两个最小原则

这仍然是我站着普通人的视角来科普。我先假设你其实不会用 agent——除了“帮我把这个作业做了”以外。从我上个学期改大家期末考试题的感觉看：我期末考试最后考了一道，“如果你要用 agent 给我的课出一份期末考试的卷子，应该怎么办”，我发现大家用 agent 的方式可能正好需要我来稍微解锁一下。

首先，你们是 AI-native 的一代人，要知道：给它一个合适的指令，它就可以把这个指令完成。我在课上选的是 Pi。你只要跟它说就可以了，并且你可以写一些配置文件，比如 `agents.md`。

你可以问它：你是谁？它会说它是生成式软件工程的教学辅助 agent。那你再问它：你不是就是个模型吗？为什么还知道生成式软件工程？它回答的时候你会看到——它之所以知道这门课，是这个仓库 `agents.md` 的配置，这部分是临时得知的。

> **结论**：使用 agent 的第一个原则，现在就开使用；第二个原则，随时问它。这是最小的两条原则。

再往上，其实是你的想象力限制了你的 agent 的上限。所以正好一会儿课间的时候大家可以想一想：你们用 agent 做过的最酷的一件事情是什么？

### 想象力是上限：我的整套系统都是 AI 配的

我的第一个例子，就是我今天上课的这个系统。刚才我给大家展示了，也说了：所有的配置、安装都是由 AI 完成的。

我要在一个 U 盘上装 Linux 操作系统——这一直以来是我上操作系统课的一个特色，我会带一个 U 盘，里面装一个 Linux，可以直接插在教室的电脑上就启动。有一年的操作系统课上，我把那台电脑的硬盘给抹掉了，抹掉以后下一个上课的老师就把它叫成业务事故了。我用这件事来展示操作系统的原理——装机是个很痛苦的事情。

我曾经是装机仙人：这里有一个知乎链接，是 pre-LLM 的时代，2021 年 7 月，我各种定制系统。装机仙人现在已经被 AI 彻底取代了，因为我只用了一句话：

去 `mirrors.nju.edu.cn` 上找一个 Debian 13 的镜像，把它装到我的 U 盘上，这个时候 U 盘插在里面，然后确保这个 U 盘可以启动，然后用模拟器验证。

点睛之笔就是“用模拟器验证”这一句。它就装完了——当然我是有 knowledge 的，所以我知道它是怎么完成这个安装的。它装完之后，真的在 QEMU 里面启动，看到了那个登录界面，告诉我确实是可以登录了、它登录成功了。我告诉它我要创建一个用户、用户名是什么、密码是什么，它全部都做好，验证完成再交给我。

然后我就启动了 U 盘里的镜像，说我要装一个 tile-based 的 window manager。你看我现在的操作是很顺滑的：比如我按 Windows 加回车，它就产生了一个新的窗口在右边；和你们用窗口的方式不太一样，当然我也可以按 Windows 加空格把它挪出来。

不会用怎么办？你可能在 B 站的直播间里看到有人用的东西很酷，但自己不会用。我直接让 DeepSeek-V3 Flash 给我生成了一个文档：你能不能看一下我系统现在的设置，我要做各种事情该怎么办？它告诉我：Super 加 Enter 打开 terminal，Super 加 D 打开一个 app launcher。于是比如我按 Windows 加 D，就可以打开 OBS 或者 Chromium browser。

所有的文档，包括你看到的终端、Neovim 的现代配置，我没有看过任何一眼配置文件，所有的一切都是用自然语言完成的。我只是让它交付——我要什么，你帮我再检查一下，就全部都完成了。

而我作为一个教 computer science 的人，记得我大四的时候——可能跟你们一样大的时候——正在看 Intel 那几千页的 CPU specification，去看每一个 CPU 的 feature 是干什么用的。然后我突然觉得，在这个时间点，有一个人可以跟我沟通，他把这些东西全看了、都懂、能做对。而我现在需要做的，是解锁它的能力。

> **结论**：今天我们学习知识的方式变了。你更多的时候需要知道它能做什么，感知到它能做到什么程度，然后带着它去做一件更大的、它做不到的事情。人现在唯一的功能，就是带着 AI 做 AI 现在做不到的事情。一旦你没有这个能力，你就立即已经被淘汰了。所以没有 token 就可以立即退学，这是我自己的观点。

### 学习方式变了：先把东西搞出来，再回头复盘

agent 彻底颠覆了计算机科学里那个“学习曲线太陡、不想用”的瓶颈。

你想想你们都配置过那个漂亮的终端吧？因为 B 站上面那些人用的终端花里胡哨的，你就想搞一个。搞一个以后，你改一点点它就给你出错，改个 `.zshrc` 一改就出错、一改就出错，非常痛苦。

有了 agent 就一点都不痛苦：它不仅可以给你改，还能事无巨细地解释为什么要这样改。你有什么新的想法，它就说好好好，还给你提供情绪价值。我前两天在小红书上发了一个贴说，为什么 token 比学生好用？因为它可以骂，它不会还嘴。我肯定不能骂学生，但是我可以骂这个 agent。

> **结论**：谁掌握了 AI agent，谁就掌握了暴增的学习效率。

但学习的顺序变了。你现在的学习方式是：先用好它，先把东西搞出来，再回头去复盘、理解。这个效率会比你从零开始一点一点搭积木要高很多。

这里面有一个危险：你的理解可能和那个更好的理解会有差距。We don't know，我们不知道。但这是一个非常不一样的事情。

### 我的 agent 日常：邮件、读书、读论文、刷 B 站

#### 收发邮件与日常事务

我有一个自己的 skill——它在我数据库里有我历史上回过的所有邮件。所以每当我收到一封邮件，它会自动把它变成已读状态，然后自动帮我写好回复的草稿，用我的口吻。

虽然我现在觉得它做得还不够好：除了那些简单的、routine 性质的东西可以直接用它的回复以外，大部分时候我还得去改。但是我得到了 AI 的 draft。

它还会处理重要的东西：比如邮件里面有附件，如果我收到一张发票，它就会把发票自动保存到一个指定的归档位置——当然这都是我写好的 instructions。

我还可以做一件事：像你们用 OpenClaw 或者 Hermes 那样，但我用的是自己 Apple 的 Reminders。我可以打开手机的备忘录，加一条“帮我把今天的发票打印出来”。我在一个叫 bot 的地方，你看现在是空的，我加上一条“把我收到的上一个发票打印出来”。我只要点 Go，它就 commit，我就多了一个 todo 项，就跟你们在 Telegram 里跟自己的 bot 聊天是一样的。然后只要等就行了：它在后台处理，弄好以后会重新给我一个推送通知，这个通知会经过 Reminders 送到我的手表上，手表就告诉我：打印完了。

我所有的日常事务都可以交给它处理，前提是我放心的事情。我觉得这比 Telegram 聊天框要好。而且这个流程会不断地进步——在 OpenClaw 之前我就这样做了。我觉得 OpenClaw 或者 Hermes 不是个人 agent 产品的终极形态，这个产品还可以做得更好，所以未来还有很多空间。

#### 读书与读论文

你们还在读书吗？还看书吗？你们还看论文吗？看论文痛苦吗？

我是一个很喜欢看书的人，我在你们这么大的时候，每年教科书就要看几十本，还会看很多闲书。但我今天已经不看书了。不过为了上这门生成式软件工程的课，我又买了一些，也带了几本来——这些都是我读书的时候仔细看过、甚至看过不止一遍的书。

一本是 Fred Brooks 的 The Mythical Man-Month。这个标题起得非常有误导性：首先什么叫人月？你想到的是那个人和月亮吗——每到月亮出来就会变成狼人？这是个 joke。man-month 很好理解，就是指人力，所以是“人力神话”。而“神话”这个词也不对：你们想到神话是什么？盘古开天地，是那种美好的东西。所以这本书其实应该叫《人月鬼话》——人月是一个鬼话。

还有一本是 John Ousterhout 的 The Philosophy of Software Design，这本书非常紧凑，感觉比我当年看的英文版还要紧凑一些，里面有很多真正的软件工程的智慧，非常好。

我重温了一下当年读书的感觉，读了第一章。读完第一章以后，agent 启动。

我是怎么读书的呢？我比 GPT-4.6 做的要更好一点。在我的 skill 里，为了做每一页 slides，我都会让 GPT-4.6 先去做两件事：第一，回看人类的历史，在和我这些内容相关的案例里，有没有一些 lessons、一些重要的案例能够得到启发和印证；第二，根据我讲的东西去找一些相关工作，不仅是在 computer science 里，而且我会让它 prefer 那些 well-recognized、high-impact 的结果——这是因为我上课，所以我希望跟大家讲经典的东西。还有 Thinking in First Principles 这样的要求。在我的“AI 梗同学”里面，我有更多这样的 personality。

然后还有随机性会抽卡，抽完以后它们会讨论，它们会有分歧的观点；讨论之后我的主 agent 会再把分歧的观点送回去讨论，直到收敛为止。所以我有了一个算力换智力的 loop，这样就可以用它去审稿那些论文。

我读论文的方式也很明确：你从人类已有的知识开始——假设人类已有的所有东西都已经固定下来、都是已知的——然后把这篇论文里新的、最少的那部分剥离出来。这样一篇 12 页的论文基本上就没剩下多少了，会变得非常非常短。所以我现在读论文的效率非常高。而且我会跟它 chat：拿着论文的原文、拿着总结、拿着分层次的总结，跟它讨论。我仍然是读论文的，我不是那种只看微信公众号学习的人。

这里插一句：我的发票已经打印好了，我收到一条通知叫“发票已打印”，我等会儿回到打印机上拿走就行。所以它可以干任何事——literally，我那台电脑能做的事情所有都能干。如果我有时间的话，如果大学倒闭了，我就弄一个机械手，让它能做更多的事情；现在还做不到，但至少可以操纵我的打印机。

#### 用 B 站的方式

我不仅用 AI 读书、读论文，我还用 AI 上 B 站。当然如果你是纯娱乐，要看一个华强买瓜的衍生视频，那就不要用 AI 读了。

我是怎么读的呢？给我一个 BV 号就行。比如我上学期的课程，给一个 BV 号，一个小时 27 分钟。一般来说我会读 podcast，比如 ByteTalk 又发了一个它的软件工程实践——其实我觉得它也挺神棍的，有些经验可能不太完全适合我们的课程。然后我会把它总结成一个自动的图文时间轴。

你看这是整理过的文本，质量还是可以的，比字幕的质量要高一些。这就是全文。图文版的图片会稍微少一些；实际上我截图的密度会更大，当我两帧图片之间的间隔大到一定程度的时候我就会截图。这样我就得到了这个视频所有的 ground truth。

这个时候 AI 梗同学就可以上线了：它会去为我消化这一个多小时的视频。因为它有我的记忆，它知道哪些东西对我来说是 trivial 的——比如这里面所有的东西我都非常清楚，那我就不需要看它，去掉。于是我就可以在几分钟的时间里面看完一个两个小时的视频，而且我基本上确信，我还是很好地知道了那里面不一样的东西。

> **结论**：在 AI agent 的时代，会用 agent 学习的人和不会用 agent 学习的人，学习效率的差距是 10 倍、100 倍。

那么你们坐在这儿，怎么和一个学习效率 10 倍、100 倍的人竞争？这就回到我一开始的那个问题：那份简历。如果所有人的简历都是一样的，那你接下来要想——那个没有给你看到的、学习效率是你 100 倍的人，他的简历会长什么样？

这是一件非常可怕的事情。而更可怕的还在下一节课，所以我们课间休息一会儿。你们可以想一想，因为我还没有公开我下面的内容，还要给大家留一点惊喜。下节课我再来讲更可怕的、比刚才更可怕的。

你们总觉得我神棍，说“人类完了”，但我就是这样想的。而且我非常确信，世界上肯定有人做得比我更好。因为我属于一个上有老下有小的人，我没办法：比如上个学期我为了上操作系统课就花去很多时间，那些时间本来如果不上课，我就可以用来探索我应该怎么搞。

### 课间现场排障：让 agent 修好断掉的 USB

我们回来。刚才有一个非常好的案例：在直播的时候，我的 USB 摄像头卡了。

教室里面的情况大概是这样：这里有一个采集卡，视频采集卡从网络或者别的什么过来，因为这边还有好几台机器。我不知道为什么学校里面用了一个成本那么大的方案，我觉得我可能用 500 到 1000 块就能把整个问题解决掉，但那是一个成本很高的方案，而且它有一个采集卡进来。问题在于那个采集卡的 USB 断开了：所以大家看到我用左边这个摄像头挥挥手它是在动的，但 USB 就断掉了，不知道为什么会断掉。

断掉以后，我刚才立即让 agent 修了一下。这就是一个 prompt：我先看看系统的 USB 设备的情况、找出设备，然后说我的 USB 有问题，能不能 reconnect。

这是 DeepSeek-V3 Flash，它用了你们前所未见的 Linux 命令——其中有些我其实有概念，但我也不知道它具体是怎么工作的。

## 从白板 Pi 到软件工程：agent 生态与它的能力边界

### 白板 Pi 之外：agent 是一个生态系统

先说一句：刚才展示的那些东西，还不是 AI 真正的形态。作为一个普通人，你拿到的不过是一个白板的 Pi，什么也没有。你在 Pi 的官方网站上把它装下来，配一个 DeepSeek-V3-Flash 的 API key，你立即就可以得到刚才所有的那些东西。多么可怕的一件事。

但是 agent 远不止于此。agent 拥有一个完整的生态系统。

这里有一条我一直挂在嘴边的计算机科学的定律：

> **结论**：如果有一件事情它是合理的，并且你想做，那么 100% 一定也有别人会想做。

在 Pre-AI 的时代，开源社区多多少少就会公开一些脚本来干这件事，"我今天又发布了一个新脚本，可以干那件事"，你到 GitHub 上把它拉下来，就可以做自己的事。到了 AI 时代，复用别人的能力变得前所未有的轻松：我可以往 Skill Hub 上面发一个 skill，你也可以在 Pi 的插件生态里找到一个插件。

所以你们应该想到，下一步作为一个普通人，你应该做什么？**应该用插件把浏览器管控起来，用插件把电脑管控起来。**

### 浏览器：人类软件工程史上的奇迹之一

浏览器是一个非常好的工程产品，我们用的是 Chrome。它可以说是人类软件工程史上的奇迹之一。它看起来就是个浏览器，显示网页的，但实际上非常复杂，代码量甚至远超操作系统内核——因为它要和用户打交道，它有大量的图形栈、显示相关的东西、性能优化等等。为了开发者，它专门留了一个接口，叫 Chrome DevTools。

你们应该是用过的。打开 Chromium，按 F12：

- 你很讨厌页面上某个东西？删掉它，它就没有了；
- 网站一般会在这个 console 上面嵌入招聘广告，你们上 B 站按 F12 应该也发现过；
- 在这里你能看到很多信息，比如 HTTP 的头；
- 你还可以把一个请求 copy as curl，把它的命令 copy 出来。这样你就能带着浏览器的 Cookie、带着所有的状态，用 `curl` 在浏览器外面去请求，拿到你要的列表。

这些都是 Pre-LLM 时代开发者做的事情。但在 LLM 时代，变了：**普通人也可以享受到 Chrome DevTools 所有厉害的地方。**

我记得 2020 年的时候，我们做过一个非常疯狂的 project。大家都知道的：Android 应用可以用 Java 写，那我们假设是一个 Java 的应用，Java 或者 Kotlin 都编译到 Java 虚拟机，于是我们可以在 OpenJDK 上运行一个 Android app。运行它的时候，把界面上所有按钮的 bounding box，也就是它的坐标都算出来，上面的文本也知道，但是我不走 Android 底层的渲染，我直接在浏览器里面画出来——你可以在 Chrome 里看到一个计算器，每一个按钮都在，上面的字也是对的，你点它，计算器的状态就变了。我可以在本机执行一个 Android app。非常非常 powerful 的工具。

不过今天我不想讲这个。

### 先从最讨厌的东西下手：教务系统

你们都很讨厌教务系统吧？我也很讨厌。教务系统是一个软件工程非常反面的例子，这个一会儿还会讲到。

我在 Pi 里说"帮我打开浏览器"——注意，这个浏览器是属于 Pi 的。我的教学周历是空的，而我很讨厌动不动就叫我们填东西，所以这时候豆包输入法的含金量又提升了：我在做这些日常任务的时候，会按一个键打开它，跟它对话。当然在我的 Linux 上没有豆包输入法，语音输入也没配置，会有点麻烦。

于是我对它说：**帮我用随便什么 AI slop 填写，不要看任何东西。** 为什么要强调"不要看任何东西"？因为如果它知道现在这个目录是这门课的 repo，它就会去读我的 lecture notes，我不要这样。

结果它不听指令，还是去干那个事了。这就是 DeepSeek-V3-Flash 的麻烦。如果换成 Claude，它会知道。翻车也是经常有的，模型其实还在不断的能力增长中，如果我用最一线的模型，它会做得更好。我用 Flash 还有一个原因：它在课上会更快。

> **提示**：这里真正值得看的，不是"它翻车了"，而是它翻车以后怎么回来。它会不断地反思自己做的这件事合不合理，然后找到应该怎么办——一开始尝试用注入事件的方式，发现不行，后来发现点鼠标是可以的。看起来在翻车，其实是它在试错。

它已经开始可以帮我填 AI slop 了，我完全可以不值守。那么，能力真正的边界在哪里？

当它走通过一次以后，这个 session 里面的东西会留下来，我可以把它**沉淀成确定性的脚本**。它可以形成记忆——这条路应该怎么走，什么能成功，什么会失败。它也可以把走过的这些网页全部变成脚本，于是你就得到了一个自动选课抢课的系统。

这是多么恐怖的一件事：你不需要有任何的知识。

### 生态的临界点：管道、组合与飞轮

你们会觉得，好吧，这又是一个很 fancy 的案例，今天讲了好多：我可以这样用、这样用、这样用，每一个都很厉害。但这其实是一整个生态。

我是教操作系统的。操作系统上面的应用程序，Unix 的 philosophy 之所以能成立，靠的就是那个**管道**：它实现了所有程序的自由组合和无限复用,1+1 是可以大于 2 的。我刚才说的那些东西也一样——从一个上下文里提取记忆和脚本的能力、我那个浏览器的 skill、我又有一个"在网页上怎么浏览"的 skill，它们是可以加在一起、互相调用的。

所以现在这个 AI agent 的生态，其实已经达到了一个临界点。马上你就会看到，这些东西的互相组合，可以成百倍成千倍地放大个人的能力。

对一个一般人来说，他能做什么？他可以找到世界上各种各样的信息源：你订阅过那种每天早上刷牙时听一下的 AI 早报吗？它也是 AI 生成的，但它有 RSS，有推送源；再加上 B 站的推送、arXiv 的推送、Hacker News 的推送。这些东西我都可以做一次沉淀，变成 skill 或者脚本，它们就进入一个信息处理的系统：我有大量的信息源，信息源进入处理系统，处理系统最终产生有用的知识。

```text
AI 早报(RSS) ─┐
B 站推送      ├──► 各沉淀为一个 skill / 脚本 ──► 处理系统 ──► 有用的知识
arXiv 推送    │                                      ▲              │
Hacker News  ─┘                                      └── 不断调整工作流 ┘
```

图里每一段都是自然语言的 skill，一行代码都不用写；它们可以复用，你会不断地调整这个工作流，它就会不断地产生对你有用的知识。你的飞轮就转起来了。

然后你再想一想：一个拥有这样一个飞轮的人，和没有飞轮的人比，这是一件多么可怕的事情。

### 为什么 OpenClaw 和 Hermes 是现象级的产品

这时候你就能理解，为什么 OpenClaw 和 Hermes 是一个现象级的产品，为什么它们能给人这么大的惊喜——比如自我进化的能力。

作为一个 CS professional，我其实并不惊艳，尤其我挺讨厌它去组织 memory：它有它的提示词，它会把我并不想让它记住的东西记住，我想让它记住的东西它不记。所以我更多的时候是调用我自己的流程，把该记的东西写到我的数据库里，让 AI 去做那些事。

但也许有一天——因为现在产品还不够成熟，模型可能还不够强——当模型过了那个临界点，我一个人比 AI 多的就那么一点点，等那一点点也被 AI 取代了以后，我也就被消灭了。

在这个意义上，你能想到很多更有趣的事。比如录屏：你录屏一天，让 AI 自动改你的流程。你就问 AI："我这一天干了这些事，你觉得我还有没有提升空间？"很有可能还有，尤其是在初学者的阶段，提升空间很大。

所以你们是有出路的那一代——你们这代人在 AI native 的环境下长大。像我现在已经被迫要处理很多事务性的事情，我已经没有这个机会了。

我很难理解，为什么有些"旧人类"、有些老登，还要心安理得地每天去做那些重复的事情。可能他们只是从公众号上读消息——而公众号的消息，和真正第一手用过的人的感受，是很不一样的。这个时代来了，所以我们需要认真思考这个问题。

### 换一个视角：念计算机的人怎么用它

这是普通人的视角。接下来是我作为一个 Computer Science 从业人员的视角。

如果你们只是用 agent、用 CodeX 说"帮我把操作系统的作业做了"，那你们真是太小看它了。我们是 Computer Science 的人，我们非常清楚**编程的能力界限在哪里**。

一般人很容易提出一个需求，而这个需求 agent 可能做不好、做不了；或者他不知道该怎样 prompt 这个 agent，才能让它确定性地、快速地完成。我们知道的是：怎么把需求编译成可以复用的东西——**什么应该以代码的形式复用，什么应该以 skill 的形式复用。**

### 一条改卷子的流水线

举个例子。我改卷子，改完以后要统分。一般来说这个任务是给助教的："助教，你去把这个分加了吧。"然后助教就掏出一个计算器，`12+13+14+15+16`，再仔细核一遍。我觉得我对我的学生太好了，这样也不行。

今天我尝试了这样一条流水线。基本做法是先 vibe code 让它出脚本、出测试，测试流完之后一口气把它跑完。流程是这样的：

我在办公桌上有一个从顶向下的摄像头，拍到试卷的一个固定位置，我把它先调好。调好以后，我按一个回车，它就拍一张照；拍完照，它回头去 offline 用千问识别这个姓名、学号、每一个小分，然后往一个文本文件里写一行。所以我是一张卷子按一个回车、一张卷子按一个回车，两只手都没闲下来。如果这张卷子没摆好，我就调整一下再来。

第一阶段完了以后，第二阶段按反序，还是回车键，但这时候左右手换了：我左手按回车，右手拿笔。按回车以后，它用语音播报——谁谁谁的学号是多少多少，然后把每一个小分都报出来，`11+12+13+14+15`，它一边报我一边检查，因为 OCR 会有错。我不信任它，我要对我班上的每一个同学负责。检查过没问题，我才把它报的那个最终分数抄写到卷面上。

```text
 顶向下摄像头（固定取景）
        │  ↵ 回车
        ▼
  拍一张照 ──► 本地 27B 千问离线 OCR ──► 姓名 / 学号 / 每个小分 ──► 文本文件（一张一行）
                                                                        │  ↵ 回车（反序）
                                                                        ▼
                                     语音播报：学号 + 各小分 + 脚本算出的合计
                                                                        │  人工逐项核对
                                                                        ▼
                                   抄写卷面 ──► 教务处 Excel 模板 ──► 上传 ──► 抽样复核 ──► 提交
```

> **易错点**：这条流水线的关键不在识别，而在"我没有让大模型做加法"。总分是脚本 eval 出来的，所以它不会错，不会因为大语言模型的幻觉算错；OCR 只负责把每个小分读进来，读错的部分由我人工核对。让模型去算总分，是这类任务里最容易翻车的地方。

配一个豆包输入法会更好。而因为我是一个 CS professional，我知道边界在哪里：我知道我的本地有一个 27B 的千问，有 Ollama 可以用，我知道应该用这样的流程——一个最舒服的流程，去减轻我和 agent 之间同步的代价。

一般人做不到这一点。你可以回头试一下：哪怕你对着最好的模型说"我现在改了 140 张卷子，改好了，小分都已经写上去了，我要统分，帮我实现它"，也到不了这么一个快速收敛的方案。

所以有些时候，现在还需要人和 AI 共建。但我也赌：有一天 AI 的能力能够强到它感知我的一切，然后帮我做一个完美的东西。

### 一个小软件工程产品：把数据从被管控的机器里送出来

那我们就回到软件工程的话题，毕竟这是生成式软件工程。我们来做一个小产品。

由头是这样的：大概一个星期前，我们在群里闲聊，说"机器被管控了很讨厌"。假设你现在在一个金融公司里，这个公司的数据是可以带进去的，但是出不来的：你插一个 U 盘，可以把一个 Word 或者 Excel 拷进去，拷进去以后它就进去了，但是没有任何文件可以拷出来。机器做了管控，它不能执行任何不信任的程序，不能显示任何不信任的网页。你唯一能做的，是在远处用远程桌面悄悄摄屏。现在你想把一个很大的文件偷出来，你怎么办？

这是 Computer Science 的人才会想到的事情。我做了这样一个程序，可以叫它程序。这是一个典型的软件工程任务。

**往外的通道：二维码动画。** 这是一个二维码，我可以把任何一个文件的内容编码进去。比如现在文件的内容就是 `Hello world`，我改一下，这个二维码就变了，你扫出来是一个 Base64 编码的字符串——它是 `0001` 加上 Base64 编码的字符串。它也可以是一个非常非常长的字符串：一个很长的 Hello world，我就可以把它编码成一段二维码的动画，这里还有一个帧号。这时候我按住 F9 刷新，一帧一帧地过，就是一个二维码动画。也就是说，你只要偷偷摄屏，把每一帧都拍到——它是循环播放的——你就把这里的数据偷走了。

> **注意**：这个过程用的全部是完全合法的东西。它就是一个 Excel 文件，里面全部是 Excel 公式，而且是 2019 之前的 Excel 都兼容的公式。合法的东西组合起来，就是一个数据外泄的通道。

**往里的通道：抖鼠标。** 如果能在那个机器里面装 exe——当然一般是不行的——你可以用抖鼠标的方式：在上下维度抖鼠标就是 0，往左右维度抖鼠标就是 1。你用远程桌面连进去，就可以往里面传输数据；往外送数据用二维码动画。这样你只要有一个远程桌面，就等于在内部做了一个虚拟网卡：你可以把远程桌面变成虚拟网卡，然后和它连起来。

```text
 抖鼠标（上下=0 / 左右=1）
        │  远程桌面会话
        ▼
   ┌──────────────────────────┐
   │   被管控的内网机器        │
   │   仅渲染可见内容          │
   └──────────────────────────┘
        │  Excel 公式逐帧生成的二维码动画
        ▼
      屏幕 ──► 外部悄悄摄屏，录下每一帧 ──► 重组文件
```

作为 Computer Science 的学生，你上过操作系统、上过计算机网络，你知道这里面需要的组件是什么，你就可以把它 vibe coding 出来。AI agent 可以做到，可以做到。

这个二维码 Excel 就是我刚才用 AI 生成的。你的想象力限制了你能做什么。

### 一般人现在手上已经有的东西

总结一下，作为一般人，你可以：

- 学习，看书，做总结，然后实现一个上面那样的信息处理的闭环；
- 操作：用 computer-use、browser-use 去做任何你平时日常里做的事情；
- 生成：因为 **Everything is code**，我可以用 AI 生成你能看到的所有东西——视频、论文。

我在和一个同学做一个叫 1-Fab 的项目：用一句自然语言，3D 打印机可以打印一个东西出来。真的东西也是 code，也是 Python 代码，生成的是 Python 代码，所以能够实现从 bit 到 atoms。这个未来已经来了。

AI 的能力只会变强，不会变弱。那么下一个问题就是：它什么时候来，以及我们应该怎么面对它。

### AI 很强，但产品是系统性的工程

面对它，就进入了生成式软件工程最重要的内容。

刚才我们建立了一个思路，我三观尽毁了，时代的车轮已经压过来了，别急。AI 也不是完全完美的。

在 LLM 之前的时代就有一个老梗："idea 都有了，我们是商学院的"——不知道你们商学院的同学有没有跟你们说过这个——"idea 都有了，就差一个程序员了，我们去挣一个亿吧。"然后还有："ABCD 轮也都有了，就差一个天使投资人了。"没有人投资我们。真没有那么简单。

AI 首先很强，我展示了 AI 可以做什么。**但产品是一个系统性的工程。** 你要做一个外卖网站，你要做前端、后端、交互、运营，整个流程上面任何一个环节做不好，产品都是直接暴毙的。虽然 AI 都能做——它也能设计前端，也能做后端，也能做交互，也能做运营，它看过世界上所有的书，它什么都知道——但如果你组织得不好，也是立即就暴毙。

实际上，我的 QRgen.xlsx，我做了一个实验让 AI 去做，AI 生成了完全不可维护的代码。再看 1.nju.edu.cn，难用吗？难用，史中史。而每年学校都会花巨额的钱，让公司维护这份代码。

为什么？我在用 browser-use 的时候稍微 hack 了一下这个系统，发现里面有一些隐藏的字段，比如你能看到一个学生的校区。在苏州校区建成之前，这个系统里面是不需要这个字段的。为了兼容苏州校区：你们写过软件的人都知道，你在设计需求的时候，没有想到学校竟然还有"校区"这个东西，数据库里就没有这个字段；突然有一天，产品经理说"我们两个校区选课要分开"，于是 AI 回去洗版。虽然能改，但还是很容易失败——这就是非常典型的软件工程的失败。

### QRgen 是怎么暴毙的

这个需求非常明确：我要一个 QRCode 的 `.xlsx`，只使用 Excel 2019 兼容的公式，把输入的任意一个字符串先用 Base64 编码，然后转成 QRCode 动画，每一帧是什么什么什么。

开始让 AI 做的时候，我发现这个任务经常做到一半停下来问我。我说不要，这很容易失败，你不要问我了。

但很遗憾，AI 对这个需求的理解是不妥当的。我说清楚了，我确实就是要这个东西，可这是 GPT-5.6——GPT-5.6 依然误解了我到底要一个什么东西。

GPT-5.6 说得对，是因为它看到了我完整的课件；但我没有告诉它我是怎么做的，所以它认为"AI 哪里容易犯错呢？AI 容易在小的 corner case 上犯错"，于是它第一秒钟就被带歪了：它希望做一个对任意的 $s$ 都满足正确性的东西。

> **结论**：软件工程的第一步，不要扩大，做最简单的东西，不会失败。

它没有理解这一点。

后来我做了一个受控的实验。第一个版本是我带着 AI 做 vibe coding 做的，所以做得比较顺利；之后我直接把这个 specification 告诉 AI，让几个模型各自去做：

| 模型 | 过程 | 结果 |
| :--- | :--- | :--- |
| GPT-5.6 | 看到完整课件，仍把需求理解成"对任意 $s$ 都正确" | 第一秒就被带歪，方向从一开始就错了 |
| AI TR-5.3 | 第一次思考了 25 分钟，然后疯狂输出，写了超过 32k output token，直接把 Claude Code 干爆（超过默认 output 限制被截断），再继续跑；我全程没有监管，一共跑了 6 个小时 | 是对的；它在 long horizon 任务上确实做得很好 |
| DeepSeek-V3-Pro | 晚上放着跑，第二天早上看，它已经没有办法遵循指令了 | 给的 Base64 是硬编码的——它用 Python 算了一个 Base64，明显不符合"把输入的任意字符串先做 Base64 编码"这条指令 |

需求的原话是"把输入的任意一个字符串先用 Base64 编码"：输出必须随输入变化，而不是把某一次输入的结果写死在文件里。一份硬编码的 Base64 放在那儿，功能上立即就不成立了。

把这几件事放在一起看，说的其实是同一件事：AI 能做的东西很多，但"它能做"和"它能被组织成一个不会暴毙的产品"之间，隔着的正是软件工程——先不扩大，先做最简单的、不会失败的那一版；把需求说到不产生歧义，并且说清楚边界在哪里。
