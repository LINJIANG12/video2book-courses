# 105-CSS3 动画：逐帧动画原理与 steps() 仿手机 360 逐帧动效实战

在前面的内容中，我们学习了 CSS3 动画的基础属性和复合写法，并且大家接触到的速度曲线大多是补间动画（如 `linear` 匀速、`ease` 缓动、贝塞尔曲线等）。浏览器会自动帮我们计算两帧之间的平滑过渡值。

但在实际商业前端开发中，有一种非常独特且极具表现力的动效形态——**逐帧动画（Frame-by-Frame Animation）**。比如游戏角色的奔跑跳跃、大厂 App 的加载 loading、以及各类科技感官网的炫酷交互。

本讲我们将深入拆解逐帧动画的底层运行机制，掌握关键函数 `steps()` 的用法，并手把手带大家实现一个高频商业案例：**仿手机 360 官网经典精灵图逐帧动效**。

---

## 1. 什么是逐帧动画？生活中的翻书小人

很多小伙伴小时候可能都玩过这样一个游戏：

拿出一本厚厚的课本或笔记本，在第一页右下角画一个小人（站立姿势）；翻到第二页，在相同位置画一个小人（抬腿姿势）；第三页、第四页、第五页……每一页上的小人都画出连续微变的不同动作。

画完之后，用大拇指按住书页边缘快速翻动（俗称“手翻书”）：

```text
       翻书小人动效类比
第1页       第2页       第3页       第4页
[小人站立]  [小人抬右脚] [小人迈步]  [小人抬左脚]
   │           │           │           │
   └───────────┴─────┬─────┴───────────┘
                     ▼ 快速翻动
           呈现连贯的奔跑动画效果！
```

当翻动速度达到一定频率时，人眼由于**视觉暂留效应**，就会看到这个小人如同活过来一样在书角飞快奔跑！

这正是电影、动画以及前端**逐帧动画**的核心本质：**跳过中间平滑渐变的过渡状态，一帧一帧瞬时切换画面**。

在实际网页场景中，比如手机 360 的官方网站，盾牌上下浮动、周围光效闪烁、核心部件逐步展开等复杂动画，如果单纯用几何变换去画会极其复杂，而使用逐帧动画配合设计师切好的“精灵图（Sprite）”，就能以极高还原度和轻量级代码完美呈现。

## 2. 核心语法：`steps()` 步数函数

在 CSS `animation` 属性中，决定动画按何种节奏执行的正是速度曲线（Timing Function）。

以往我们使用的补间动画语法：
```css
/* 补间动画：从 A 点平滑滑向 B 点 */
animation: move 1s ease infinite;
```
如果用补间动画去移动包含多个动作的精灵图，画面就会像幻灯片飞速拖动一样“哧溜”一下拉过去，整张图都在眼前飞晃，完全失去逐帧跳跃的意义。

为了实现瞬时断点切换，CSS3 专门提供了一个步进函数：**`steps(n)`**。

```css
/* 逐帧动画标准语法 */
animation: 动画名称 持续时间 steps(步数) 循环模式;
```

### 参数解析：
- **`steps(n)`**：小括号中的数字 `n` 代表完成整段动画所需要的**步数（断点个数）**；
- **步数如何确定**：你的精灵图横向一共包含了几个动作状态，这里就填数字几。如果有 10 个小人动作，就填 `steps(10)`；如果有 25 帧状态，就填 `steps(25)`。

## 3. 逐帧动画底层运行原理

逐帧动画在 CSS 中究竟是怎么动起来的？请记住它的黄金三要素：

1. **一个视口盒子（Box）**：尺寸严格等于**单帧小图**的宽高；
2. **一张超宽精灵图（Sprite Sheet）**：把连续的动作帧水平横向排成一整排，作为盒子的 `background-image`；
3. **背景位置的阶梯位移（`background-position`）**：通过 `@keyframes` 改变 `background-position-x`，配合 `steps(n)` 让背景图从右向左“一步一跳”地平移。

```text
视口盒子与精灵图位移示意
+--------------+  <- 盒子固定大小 (548px × 513px)，overflow 之外不可见
|   帧 1 画面  | [ 帧 2 ] [ 帧 3 ] [ ... ] [ 帧 25 ] (超长精灵图向左位移)
+--------------+
       ◄────────── background-position: -13700px (向左步进位移)
```

因为用户只能透过固定尺寸的视口盒子看到当前露出的那一帧，随着背景图按照固定的步长（单帧宽度）一格一格向左闪现，视觉上就呈现出了连贯的动态画面。

## 4. 仿手机 360 逐帧动效实战开发

接下来我们通过真实参数，完整复现手机 360 官网的逐帧核心案例。

### 4.1 素材与尺寸数据准备
在开工前，一定要先找设计团队对接清楚两个关键尺寸：
- **视口盒子尺寸**：单帧画面的实际宽高，本案例中盒子为宽 `548px`、高 `513px`；
- **整张精灵图尺寸**：宽 `13700px`、高 `513px`，横向一共容纳了 **25 个小状态帧**；
- **状态帧步数**：`13700 / 548 = 25`，因此 `steps(25)`。

> **核心避坑细节（图片缩放问题）**：
> 有时设计师导出的精灵图原图高度可能是 `668px`，如果直接当作背景图引入，与我们设置的 `513px` 盒子尺寸不匹配，会导致上下露白或错位。
> 此时必须通过 `background-size` 强制将背景图的高缩放为 `513px`，对应的宽度等比缩放为 `13700px`：
> ```css
> background-size: 13700px 513px;
> ```

---

### 4.2 结构搭建与样式编码

下面是完整的实战代码：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>仿手机360官网逐帧动画</title>
  <style>
    * {
      margin: 0;
      padding: 0;
      box-sizing: border-box;
    }

    /* 1. 撑满视口并设置深色星空科技感背景 */
    html, body {
      width: 100%;
      height: 100%;
    }

    body {
      background: #000 url("images/bg.jpg") no-repeat center center / cover;
      display: flex;
      justify-content: center;
      align-items: center;
      overflow: hidden;
    }

    /* 2. 动效视口容器：严格等于单帧宽 548px，高 513px */
    .box {
      width: 548px;
      height: 513px;
      /* 引入精灵长图，靠左靠上对齐，禁止平铺 */
      background: url("images/sprite.png") no-repeat left top;
      /* 等比缩放到标准高度 513px，总宽 13700px */
      background-size: 13700px 513px;
      
      /* 4. 调用动画：1秒完成一轮，分25步走完，无限循环播放 */
      animation: playSprite 1s steps(25) infinite;
    }

    /* 3. 定义关键帧动画：背景水平向左平移整张图的总宽度 */
    @keyframes playSprite {
      0% {
        background-position: 0 0;
      }
      100% {
        /* 移动整张图片的宽度：负值代表向左位移 */
        background-position: -13700px 0;
      }
    }
  </style>
</head>
<body>
  <!-- 视口容器 -->
  <div class="box"></div>
</body>
</html>
```

## 5. 逐帧动画 vs GIF 动图：为什么不直接放 GIF？

看到这里，肯定有同学会问：“老师，既然都是多张图连贯播放，我直接让设计师导出一个 GIF 图，或者一个 WebP 动图放上去，不也是一行 `<img>` 就搞定了吗？为什么要费劲写精灵图和 `steps()`？”

这是一个非常高频的面试与架构选型问题：

| 维度 | GIF 动图 | CSS3 `steps()` 逐帧动画 |
| :--- | :--- | :--- |
| **色彩与透明度** | 仅支持 256 色，半透明边缘有严重白边或毛边锯齿 | 采用 32 位 PNG 精灵图，完美支持 Alpha 半透明通道，边缘极其细腻 |
| **播放与速度可控性** | **不可控**。动图生成后播放速率固定，无法通过前端动态调节快慢 | **极度灵活**。修改动画时长（如从 `1s` 改为 `3s` 慢放，或 `0.5s` 快进），甚至由 JS 动态响应控制 |
| **交互与状态控制** | 无法精准暂停、反向播放或跳转到指定帧 | 可配合 `animation-play-state: paused` 实现悬停暂停，配合伪类自由交互 |
| **加载性能** | 动态帧体积大，首屏不易做合并加载 | 多动作帧整合成单张 Sprite，极大减少 HTTP 请求次数 |

通过 CSS3 逐帧动画，我们把动效的**控制权完全掌握在了前端手中**：需要慢速播放只需改写为 `animation: playSprite 3s steps(25) infinite;`，需要极速冲击只需改写为 `0.5s`，非常强大。

---

## 6. 核心避坑要点与总结

1. **步数必须精准**：`steps(n)` 中的步数必须与精灵图包含的实际帧数严格一致。如果精灵图只有 25 帧，你写了 `steps(26)`，每一帧停留的位置就会发生偏移错位；
2. **位移距离为负值**：背景图移动的方向与视口相反，要想看到右侧的下一帧，背景必须向左拉动，因此在 100% 关键帧中写 `-13700px`（负的精灵图总宽度）；
3. **盒模型尺寸锁定**：视口盒子宽高必须与单帧切图尺寸严丝合缝，必要时显式声明 `background-size` 避免高分屏或未裁切图片尺寸溢出。
