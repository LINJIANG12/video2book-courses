# 物理像素与 CSS 像素以及设计稿设置

上一讲我们把视口标签加上，页面在手机上站直了。但紧接着就有同学问我：老师你说 iPhone 宽度 375，可网上都说 iPhone 是 750 分辨率，到底谁在说谎？问得好，今天这一讲就是来断这个案的。断完这个案，你们就明白设计稿为什么按 375 出，量出来的尺寸为什么要除以二。

---

## 1. 物理像素与 CSS 像素的划分

### 1.1 物理像素的硬件含义

物理像素（物理像素，physical pixel）是屏幕硬件上真实存在的发光点，出厂就定死了，谁也改不了。iPhone 6 的屏幕横向有 750 个发光点，它的物理分辨率宽度就是 750。这就好比你家地板砖，砖是早就铺好的，一块就是一块。

### 1.2 CSS 像素的软件含义

CSS 像素（CSS 像素，CSS pixel）是我们写代码时用的逻辑单位。你写 `width: 375px`，浏览器排版时用的是 375 个逻辑格子。还是地板砖的比方：CSS 像素是你拿尺子量的"我要铺多宽"，物理像素是实际铺下去用了多少块砖。

在一台标准 PC 显示器上，一个逻辑格子正好对应一个发光点，1 比 1，谁也不欠谁。但在手机上，为了把画面做细腻，厂商往同样大小的屏幕里塞了更多发光点，一个逻辑格子底下压着 2 个甚至 3 个发光点。于是就有了这个公式：

$$DPR = 物理像素 / CSS 像素$$

设备像素比（设备像素比，DPR）等于物理像素除以 CSS 像素。iPhone 6 横向 750 个发光点对应 375 个逻辑格子，DPR 就是 2，也就是传说中的二倍屏（比如 iPhone 6 / 7 / 8）。Plus 系列横向 1242 个发光点对应 414 个逻辑格子，DPR 是 3，叫三倍屏。

```text
二倍屏下一个 CSS 像素的构成（侧视示意）

CSS 像素（逻辑 1 格）：
+-----------+
|           |
+-----------+
由 2 x 2 = 4 个物理像素拼成：
+-----+-----+
| 发光 | 发光 |
+-----+-----+
| 发光 | 发光 |
+-----+-----+
```

读图说明：二倍屏上你写的 1 像素宽，实际由 4 个硬件发光点渲染，所以画面比 PC 细腻得多。

> **定义**：物理像素是屏幕硬件的发光点数，CSS 像素是浏览器排版用的逻辑单位，设备像素比是前者除以后者的比值，描述了一块屏幕的细腻程度。

## 2. 高清屏下的图片与边框处理

### 2.1 二倍图与三倍图

明白了 DPR，图片模糊的问题就破案了。你们有没有遇到过：同一张图在电脑上好好的，到手机上就发虚？原因就是你给了一张 100 发光点的小图，手机却要拿 200 个发光点去显示它，一个点掰成四个用，不糊才怪。

解法就是二倍图（比如 200 像素的图显示在 100 像素的盒子里）：准备比显示尺寸大 DPR 倍的图片。显示 100 逻辑像素宽的图片，就准备 200 物理像素宽的图；三倍屏就准备 300 的。宁可大图小用，不可小图大用，多出来的像素只会让画面更锐，不会浪费。

### 2.2 一像素边框的发虚问题

同理，你写的 `1px` 边框在二倍屏上实际占 2 个发光点，看着比 PC 上粗一圈。极致的做法是用媒体查询或者 `transform: scale(0.5)` 把线压细，但现阶段你们记住原理就行：不是你的代码写错了，是屏幕细腻了。等后面做项目遇到视觉稿里的"一像素线"，自然就知道该上二倍图的思路了。

## 3. 设计稿尺寸的选定与测量换算

### 3.1 为什么按 375 出设计稿

好，终极问题来了：设计师给我们出图，到底按 750 出还是按 375 出？答案是：设计稿按 750 物理像素画（因为作图软件里画的是发光点），我们前端按 375 逻辑像素写（因为代码里用的是 CSS 像素）。同一张稿子，两种读法，中间差一个 DPR 等于 2。

为什么偏偏是 375？因为 iPhone 6 / 7 / 8 这一代机型存量最大，375 是移动端最主流的逻辑宽度。以它为基准，往小兼容 320，往大兼容 414 和 430，偏差都不大。设计师说"这稿是 750 的"，你们心里自动翻译成"按 375 写"，这就是行话。

### 3.2 量出数值除以二

落到实操就一句话：从 750 设计稿上量出多少像素，代码里写一半。量出来按钮宽 200，就写 `width: 100px`；量出来字号 32，就写 `font-size: 16px`。图片呢？切图时按原尺寸切（200 的图直接用），显示时收进 100 的盒子，二倍图自然成立，一举两得。

> **易错点**：最常见的翻车是拿 750 的数值直接写进代码，页面在手机上大一倍，还满屏找 bug。每次从设计稿量完，先问自己一句：除以二了吗？养成这个肌肉记忆，能躲掉一半以上的移动端返工。

> **结论**：物理像素是砖，CSS 像素是尺，DPR 是换算率，375 是尺码基准。下一讲我们解决最后一个问题：页面宽度从 320 到 430 来回变，写死的 375 像素迟早不够用，怎么让页面自己跟着屏幕伸缩？答案就是 vw 适配（vw 适配）加自动换算插件。
