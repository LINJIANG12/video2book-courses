# HTML 文本格式化标签与专业注释规范

在日常网页开发与电商浏览中，我们随处可见各种各样的特殊文本排版：为了突出核心数据或警示信息，文字被加粗显示；商城的降价促销专区，原价 `2499` 元被画上一道横线划掉，旁边醒目地标注着现价 `2099` 元；点击某些超链接前，文字下方带着一条下划线；又或者某些专有名词被设为倾斜排版。

这些在页面中用来强调、修饰特定文字的标记，在 HTML 中统称为**强调与重要性标签**（也常称作文本格式化标签）。与此同时，为了让我们编写的代码条理清晰、便于维护与团队协作，HTML 还提供了一套特殊的**注释机制**。

这一讲我们就把这两套在日常开发中高频使用的标签彻底讲透，建立起现代前端规范的标签选型与代码注释习惯。

---

## 1. 强调与重要性标签的分类与语义化选型

HTML 中实现文字加粗、倾斜、下划线和删除线，其实提供了两套完全不同的标签。很多初学者在刚接触时会非常困惑：明明两套标签在浏览器里渲染出来的视觉效果一模一样，为什么规范里要定义两套？我们在实际开发中到底该用哪一套？

我们先通过下表建立系统认知：

| 文本效果 | 推荐使用（语义化标签，HTML5 规范） | 了解即可（传统非语义标签，不推荐） | 核心语义含义 |
| :--- | :--- | :--- | :--- |
| **加粗** | `<strong>` | `<b>` (Bold) | 内容具有极高重要性、严肃性或紧急性 |
| **倾斜** | `<em>` (Emphasis) | `<i>` (Italic) | 内容具有重音强调（改变句子语调） |
| **下划线** | `<ins>` (Inserted) | `<u>` (Underline) | 文档中插入、新增的文本说明 |
| **删除线** | `<del>` (Deleted) | `<s>` / `<strike>` (Strikethrough) | 文档中已废弃、删除或不再生效的信息（如划掉原价） |

```text
HTML 文本格式化标签选型逻辑拓扑
├── 语义化标签组（现代工业标准 · 强烈推荐）
│   ├── strong ──> 视觉加粗 + 强化重要性语义（SEO / 屏幕朗读优先）
│   ├── em     ──> 视觉倾斜 + 语调重音强调
│   ├── ins    ──> 视觉下划线 + 标记文档新插入内容
│   └── del    ──> 视觉删除线 + 标记无效/过期/原价信息
└── 纯视觉标签组（传统旧写法 · 仅作兼容了解）
    ├── b  ──> 仅视觉加粗，无任何语义权重
    ├── i  ──> 仅视觉倾斜，无语义（现代常借用为字体图标载体）
    ├── u  ──> 仅视觉下划线，易与 a 链接混淆
    └── s  ──> 仅视觉划线，无语义
```
*图 1：文本格式化标签选型与语义权重拓扑图*

### 1.1 语义化标签组（第一组 · 强烈推荐）

我们在开发中务必优先使用带有明确语义的第一组标签。这不仅关乎浏览器的样式呈现，更关乎搜索引擎爬虫（SEO）对页面权重的判定，以及视障群体依赖的无障碍屏幕朗读器对内容的正确解读。

#### 1.1.1 加粗标签：`<strong>`
`strong` 在英文中表示“强壮的、强烈的”。当一段文字包含关键结论、关键数值或风险警告时，使用 `<strong>` 包裹，能让浏览器赋予其加粗字重，同时告知搜索引擎“这是本段的核心关键点”：

```html
<p>
  为了确保您的账户资产安全，请<strong>切勿向任何人透露短信验证码</strong>！
</p>
```

#### 1.1.2 倾斜标签：`<em>`
`em` 是 Emphasis（强调）的缩写。在语言学中，对某个词加重语气会导致整句话的表达重心发生改变。`<em>` 标签在视觉上呈现斜体效果，在语音朗读时会带有升调或重音提示：

```html
<p>
  我们这里讨论的是<em>规范标准</em>，而不是某些浏览器的非标准私有实现。
</p>
```

#### 1.1.3 下划线标签：`<ins>`
`ins` 是 Inserted（插入、追加）的缩写，常用于合同变更、修订记录或标记特定说明。它默认在文字底部渲染一条实线下划线：

```html
<p>
  本协议于 2025 年进行了最新修订，<ins>新增了关于 AI 衍生版权的保护条款</ins>。
</p>
```

> **注意**：在网页设计中，带有下划线的文字极易被用户误认为是可点击的超链接（`<a>` 标签）。因此在实际业务中，下划线样式尽量通过 CSS 谨慎控制，避免引起交互歧义。

#### 1.1.4 删除线标签：`<del>`
`del` 是 Deleted（已删除）的缩写。最经典的工业落地场景就是电商平台的“原价划线促销”。通过删除线直观展现价格折让，激发消费者的购买欲：

```html
<p>
  新款全无线降噪耳机：限时抢购价 ¥2099，原价 <del>¥2499</del>！
</p>
```

### 1.2 传统非语义标签组（第二组 · 了解即可）

第二组标签包括 `<b>`（Bold 加粗）、`<i>`（Italic 倾斜）、`<u>`（Underline 下划线）以及 `<s>`（Strike 删除线）。

这些是早期 HTML 规范为了控制视觉排版而引入的“老式标签”。它们有一个致命的硬伤：**没有任何语义内涵**。在现代 Web 标准“结构（HTML）与样式（CSS）分离”的原则下，这组标签已经不再被提倡用于正文强调。

> **提示**：虽然现代开发不建议用 `<i>` 呈现正文倾斜，但在前端工程中，`<i>` 标签因其书写极短（仅一个字母），经常被工业界约定俗成地借用为第三方字体图标（如 Font Awesome、Iconfont）的容器标签（例如 `<i class="icon-search"></i>`）。遇到这种场景大家不必意外，但对于正文文本强调，必须毫不动摇地使用 `<strong>` 和 `<em>`。

## 2. HTML 注释标签与工程规范

编写代码是写给机器执行的，更是写给人阅读和维护的。随着页面规模的扩大，结构会变得越来越庞大复杂。如果通篇只有标签堆砌，过上一两个月回头看，你自己都可能会困惑：“这块结构是干什么的？这段代码为什么要这么写？”

HTML 提供了**注释标签（Comments）**，用来在代码中记录说明信息。

### 2.1 注释的基本语法与规范写法

HTML 注释使用尖括号、感叹号与双短横线组合包裹：

```html
<!-- 这里是单行注释内容 -->

<!--
  这里是多行注释内容
  可以跨越多行书写更详尽的业务逻辑说明
-->
```

#### 2.1.1 两个短横线后的空格规范
请大家养成一个细致且专业的编码习惯：**在 `<!--` 之后、以及 `-->` 之前，各保留一个半角空格**。

```html
<!-- 推荐：两端保留空格，整洁规范，符合专业工程标准 -->
<!-- 导航栏区域开始 -->

<!--不推荐：内容紧贴短横线，视觉挤压严重-->
<!--导航栏区域开始-->
```

我们要做到专业（Professional），这种代码素养就是从日常每一个空格的敲击中积累起来的。

#### 2.1.2 快捷键操作
在主流现代化编辑器（如 Trae、VS Code 等）中，不需要手动手敲尖括号和感叹号：
- 选中任意单行或多行代码；
- 直接按下快捷键：`Ctrl + /`（Mac 系统下为 `Cmd + /`）；
- 编辑器会自动为选中的代码行添加或解除注释包裹。

### 2.2 注释的核心特性与应用场景

注释具有两个极其重要的技术特征：
1. **浏览器完全静默忽略**：浏览器内核解析 HTML DOM 树时，会忽略注释节点在页面上的渲染。注释内容绝对不会呈现在用户的网页可视界面中。
2. **源码完全公开透明**：注释虽然不在界面中渲染，但它仍然包含在由服务端传输到客户端的 HTML 文本中。任何用户只需在浏览器中点击右键 -> **查看网页源代码（View Page Source）**，就能一字不漏地看到所有 HTML 注释！

基于这两大特征，注释在日常前端研发中承担三类核心工作：

```text
HTML 注释三大核心工程场景
├── 1. 结构划分与目录导航（如：<!-- 头部 Banner 模块开始 -->）
├── 2. 临时禁用代码排错（保留可疑代码片段，避免直接删除导致丢失）
└── 3. 跨开发者留言与逻辑备忘（说明特定写法的初衷或待办 TODO）
```
*图 2：HTML 注释的三大核心工程场景*

#### 场景一：页面模块划分
在一个动辄上千行的复杂页面中，通过注释划定结构边界，可以极大提升代码的可读性与排查效率：

```html
<!-- ==================== 顶部导航栏模块 (NavBar) 开始 ==================== -->
<nav>
  <!-- 导航具体代码 -->
</nav>
<!-- ==================== 顶部导航栏模块 (NavBar) 结束 ==================== -->

<!-- ==================== 主体内容区域 (Main Container) 开始 ==================== -->
<main>
  <!-- 核心展示区域 -->
</main>
<!-- ==================== 主体内容区域 (Main Container) 结束 ==================== -->
```

#### 场景二：代码调试与临时屏蔽
排查页面渲染异常或测试不同方案时，先不要盲目删除原有代码，而是用 `Ctrl + /` 临时注释屏蔽。等测试验证通过后，再决定保留还是清除。

#### 场景三：避免失误的“程序员留言”轶事与职业戒律
既然注释在客户端源码中完全可见，我们在写注释时就必须保持克制与严谨，绝不能把注释当成个人私密日记本或者宣泄情绪的垃圾桶。

曾经发生过一个真实的案例：某商业网站在出现业务暴雷故障后，有技术人员打开该网站并右键查看网页源代码，赫然在 HTML 注释里看到了前任离职员工留下的告诫留言：
> “这家公司没有年终奖呀，兄弟，别指望了，也别来了啊，我都准备辞职了。另外，这个项目有很多意外的 Bug，你坚持不了多久的。Goodbye, sayonara！”

这在行业里成了一个广为流传的笑谈：*“得罪谁也千万别得罪程序员！”* 老板和普通用户虽然在页面渲染层看不到这些字句，但凡是懂一点前端的人，只要右键查看源码，所有怨言与内部隐私全都会公之于众。

这给我们敲响了职业警钟：**公网环境上线的生产代码注释，严禁包含公司内网地址、个人情绪发泄、敏感账号密码与未经授权的内部信息**。

此外，平时写注释也是为了救赎日后的自己。很多人项目赶工期写了大量结构，两周后再看自己写的代码，第一反应往往是：“这是谁写的屎山代码？”仔细一看 Git 提交记录，原来是自己写的！如果当初随手加上了两行清晰的结构注释，就能在数秒内迅速回忆起当时的架构思路。

## 3. 综合实战演练：商品促销模块结构搭建

结合本讲学习的带有语义的强调标签与专业注释规范，我们完整编写一个真实的商品促销卡片结构片段：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>商品特惠专区</title>
</head>
<body>

  <!-- ==================== 限时特惠商品模块开始 ==================== -->
  <section>
    <h2>旗舰智能降噪耳机 - 特惠首发</h2>
    
    <!-- 商品核心卖点说明：使用 strong 强化核心性能参数 -->
    <p>
      配置说明：搭载全新双核主动降噪芯片，深度可达 <strong>48dB</strong>，续航时间长达 <strong>40小时</strong>。
    </p>

    <!-- 促销价格说明：使用 del 划掉原价，突出让利幅度 -->
    <p>
      官方指导价：<del>¥2499</del> 元<br>
      首发专享价：<strong>¥2099</strong> 元
    </p>

    <!-- 售后保障补充说明：使用 ins 标注服务政策升级 -->
    <p>
      服务承诺：全国联保，<ins>首发期间免费赠送一年碎屏与进水延长保修服务</ins>。
    </p>
    
    <!-- 注意事项：使用 em 强调特殊限制条款 -->
    <p>
      提示：每位注册用户<em>仅限购买 1 台</em>，多拍将自动取消订单。
    </p>
  </section>
  <!-- ==================== 限时特惠商品模块结束 ==================== -->

</body>
</html>
```

在浏览器中运行上述代码，我们可以清晰地观察到：
- `48dB` 与 `40小时`、`¥2099` 呈现视觉加粗，凸显参数与到手价的绝对吸引力；
- 原价 `¥2499` 被整齐地划上一条删除线，与现价形成鲜明反差；
- 延保服务下方带有清晰的下划线标记；
- 限购提示中的“仅限购买 1 台”呈现倾斜效果；
- 所有的模块起始注释完美守护了代码的组织层次，且不会对前台页面造成任何视觉干扰。

## 本讲小结与下节预告

本讲我们系统学习了 HTML 中两类最为核心的高频辅助标签：
1. **强调与重要性标签**：必须建立“语义第一”的选型准则，全面拥抱 `<strong>`、`<em>`、`<ins>` 与 `<del>`，摒弃陈旧的非语义化标签 `<b>`、`<i>`、`<u>`、`<s>`；
2. **注释标签**：熟练掌握 `<!-- 内容 -->` 的语法结构、快捷键 `Ctrl + /` 以及两端留白空格的专业素养，深刻理解注释对前台不可见但源码可见的底层特征，规范化管理项目代码。

在今天的练习中，细心的同学可能已经发现：为什么我们写在页面里的 `<p>` 段落总是自己独占整整一行，而 `<strong>`、`<em>` 哪怕写在不同的行里，渲染出来却能在同一行并排显示？这背后涉及 HTML 最为底层的一套运行基石——**元素分类（块级元素与行内元素）**。下一讲，我们就来揭开元素分类的底层面纱，同时为大家带来一段特别的“歌曲彩蛋”，我们下节课不见不散！
