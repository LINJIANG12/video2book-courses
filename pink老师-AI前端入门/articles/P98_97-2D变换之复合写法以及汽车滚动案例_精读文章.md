# 2D 变换复合写法执行机制与问界汽车滚动案例实战

在前端动画与微交互开发中，单一方向的平移、单纯的角度旋转或者孤立的缩放，往往只能实现非常生硬的初级效果。真实世界里的物理运动几乎都是复合叠加的：投掷出去的飞镖一边向前飞一边高速自转，滑梯上的皮球一边向下滚动一边自身翻滚，道路上飞驰的汽车车身整体位移的同时轮胎在高速运转。

当我们尝试在 CSS3 中同时为同一个元素赋予“既平移又旋转”的效果时，很多初学者写出的第一行代码就直接报错或者样式诡异失效。这一讲我们就来彻底击穿 2D 变换的复合写法（Multiple Transforms），搞懂它背后极其关键的执行顺序机理，并以问界 M8 汽车滚动的经典交互效果为实战案例，把图层定位、运动同步与贝塞尔平滑过渡完整跑通。

---

## 1. 2D 变换复合写法与层叠覆盖陷阱

### 1.1 多个变换并存的需求与层叠覆盖现象

我们在前几讲分别拆解了平移 `translate()`、旋转 `rotate()`、缩放 `scale()` 以及倾斜 `skew()`。当遇到复合运动场景时，不少同学最直觉的写法就是一行行往下罗列：

```css
/* 典型错误示范：分行书写多个 transform */
.box:hover img {
  transform: rotate(360deg);
  transform: translateX(600px);
}
```

把这段代码放到浏览器中运行，你会发现一个让人崩溃的现象：图片根本没有发生任何旋转，它直挺挺地向右平移了 `600px`，旋转效果荡然无存！编辑器甚至当场给你标了警告或提示属性被重写。

> **易错点**：这是 CSS 基础规范中不可逾越的底层法则——**属性层叠性（Cascading）**。在同一个 CSS 规则集中，如果对同一个属性名称（此处为 `transform`）进行了多次声明，后面的声明会无情地将前面的声明彻底覆盖掉。浏览器只会采纳最后解析到的那一行 `transform: translateX(600px);`，前面的 `rotate(360deg)` 相当于完全没写。

如果你想在一个元素上同时呈现多种变换特征，绝对不能分行单独写，必须采用复合书写规范。

---

### 1.2 复合写法的语法规范与空格分隔约定

CSS 为 `transform` 提供了原生的复合声明语法：允许在一个 `transform` 属性后面罗列多个变换函数，函数与函数之间**严格使用单个空格隔开**，不能使用逗号，也不能使用分号截断。

```css
/* 语法骨架 */
selector {
  transform: 变换函数A 变换函数B 变换函数C ...;
}
```

例如，让一个元素既发生平移、又进行缩放、还伴随旋转：

```css
.demo {
  transform: translate(100px, 50px) scale(1.2) rotate(45deg);
}
```

```text
transform 复合属性声明结构
┌───────────┐   ┌────────────────────────────────────────────────────────┐
│ transform │ : │ translate(100px, 50px)   scale(1.2)   rotate(45deg)    │ ;
└───────────┘   └────────────────────────────────────────────────────────┘
                       ▲                     ▲
                   空格分隔              空格分隔 (严禁使用逗号)
```
*图 1：transform 复合声明中的空格分隔规范*

虽然掌握了这个语法结构，但复合写法中藏着一个决定成败的致命细节：书写这几个变换函数的**先后顺序**。

## 2. 复合写法的执行顺序与坐标系相对运动

### 2.1 从右向左的执行链条与几何原理解析

在日常认知中，我们阅读代码习惯于从左到右阅读，但在 CSS 的渲染管线中，`transform` 列表中罗列的函数在计算变换矩阵时，遵循的是**从右到左（从后向前）**的执行逻辑。

> **结论**：在 `transform: 函数A 函数B 函数C;` 结构中，浏览器最先执行的是最右侧的 `函数C`，接着执行 `函数B`，最后才执行最左侧的 `函数A`。

为什么这个顺序会导致截然相反的视觉效果？关键在于：**变换函数会改变当前元素的本地坐标系（Local Coordinate System）**！

```text
顺序对比 A：先平移后旋转（书写顺序：rotate 在左，translate 在右）
代码：transform: rotate(360deg) translateX(600px);

   执行阶段 1 (最右侧 translate)          执行阶段 2 (最左侧 rotate)
   ┌───┐                                 ┌───┐
   │ A │ ──────── 平移 600px ─────────►  │ A │ (物体已远离坐标原点)
   └───┘                                 └───┘
     ▲                                     │
  坐标原点                               围绕原点画大圈甩动！
                                           ▼
                                     ┌───────────┐
                                     │  甩出屏幕 │
                                     └───────────┘
----------------------------------------------------------------------
顺序对比 B：先自转后平移（书写顺序：translate 在左，rotate 在右）
代码：transform: translateX(600px) rotate(360deg);

   执行阶段 1 (最右侧 rotate)             执行阶段 2 (最左侧 translate)
   ┌───┐                                               ┌───┐
   │ A │ (原地自转 360deg) ───────── 平移 600px ──────►│ A │ (边滚边走)
   └───┘                                               └───┘
     ▲                                                   ▲
  坐标原点                                            目标终点
```
*图 2：变换顺序对物体运动轨迹与坐标系参照的根本影响*

1. **错误情况（`transform: rotate(360deg) translateX(600px);`）**：
   - 依据从右向左的法则，先执行 `translateX(600px)`，元素先脱离原点沿 X 轴平移了 600 像素；
   - 随后执行 `rotate(360deg)`，由于旋转的默认基准点是元素自身的几何中心，但此时在复合矩阵的相对变换下，旋转动作会产生剧烈的偏心位移，元素在运动过程中绕出了一个巨大的弧线，像流星甩尾一样飞出去再拐回来，完全脱离了平直行进的轨道。
2. **正确情况（`transform: translateX(600px) rotate(360deg);`）**：
   - 依据从右向左的法则，先执行 `rotate(360deg)`，车轮以自身几何中心为基准原地自转；
   - 紧接着执行 `translateX(600px)`，自转的物体整体沿着水平 X 轴平稳向前位移；
   - 最终呈现给用户的视觉反馈就是自然、平滑的“向前滚动”。

---

### 2.2 汽车轮胎运动的顺序判定与调试法则

现实生活中我们说“车轮转着往前走”，转动是车轮的内部动作，往前位移是整体的宏观动作。

| 书写顺序 | 内部执行时序 | 视觉运动轨迹 | 适用业务场景 |
| :--- | :--- | :--- | :--- |
| **`translate(...) rotate(...)`** | **先自转，再平移** | 原地转动同时沿轨道水平平移（平滑滚动） | 滚动的轮胎、滚落的足球、自转的金币 |
| **`rotate(...) translate(...)`** | **先平移，再自转** | 绕远处原点画圆弧摆动（大半径公转甩动） | 雷达指针扫描、钟表摆锤晃动、行星公转 |

> **提示**：在实际项目编码中，如果你一时记混了书写顺序，不必陷入死记硬背的焦虑。只要你在浏览器中发现元素不是平直滚动，而是“突然甩出一道大弧线再跑回来”，立刻反应过来：**函数顺序写反了**！立即把 `translate` 与 `rotate` 的位置对调一下，效果便会恢复正常。

## 3. 问界 M8 汽车滚动案例综合实战

接下来我们把刚才推导的复合变换规律，运用到高质感的真实案例中。我们模拟类似问界 M8 汽车官网的展示交互：当鼠标悬停在视口展示区时，整辆汽车从屏幕右侧平滑驶向左侧，前后两个轮毂同步高速滚动入场。

### 3.1 页面 DOM 结构设计与子绝父相嵌套关系

在动手写 CSS 之前，必须先理清 DOM 结构的层级关系。许多初学者容易犯一个结构性错误：把大盒子、车身图片、两个轮胎图片全都放在同一层级：

```html
<!-- 不推荐的平铺结构：车身与车轮难以统一位移 -->
<div class="box">
  <img src="car.png" class="car">
  <img src="wheel.png" class="wheel-left">
  <img src="wheel.png" class="wheel-right">
</div>
```

如果采用这种平铺结构，当汽车前进时，你必须分别控制车身、左轮、右轮三个独立元素的平移数值，稍微计算偏差就会发生“车身开走了、轮胎落在原地”或者“轮胎跑得比车还快”的脱节灾难。

正规的工业级解决方案是采用**容器包裹法**，构建“车体复合组件”：

```html
<!-- 标准工程结构：子绝父相，将车轮绑定在车身容器内部 -->
<div class="box">
  <!-- car 容器作为车身整体，统领车架与两个轮子 -->
  <div class="car">
    <img src="car.png" alt="汽车车身" class="car-body">
    <img src="wheel.png" alt="前车轮" class="wheel wheel-left">
    <img src="wheel.png" alt="后车轮" class="wheel wheel-right">
  </div>
</div>
```

```text
DOM 树及定位继承拓扑图
┌──────────────────────────────────────────────┐
│ .box (大视口盒子，作为展台轨道)                │
│                                              │
│      ┌────────────────────────────────┐      │
│      │ .car (车身主容器，相对定位/绝对定位)│      │
│      │                                │      │
│      │   ┌────────────────────────┐   │      │
│      │   │ <img> 车身外壳底图      │   │      │
│      │   └────────────────────────┘   │      │
│      │      ┌─────────┐   ┌─────────┐ │      │
│      │      │左轮绝对定│   │右轮绝对定│ │      │
│      │      └─────────┘   └─────────┘ │      │
│      └────────────────────────────────┘      │
└──────────────────────────────────────────────┘
```
*图 3：车身与车轮的组件化容器嵌套与定位拓扑*

通过将车轮定位在 `.car` 容器内部：
1. **车体运动解耦**：当汽车前进时，只需让父级 `.car` 盒子做 `translateX` 平移，两个车轮自然而然随着车身整体前进；
2. **车轮职责单一**：两个车轮只需要原地做绝对定位锁在底盘凹槽内，并在动画触发时专门负责 `rotate` 旋转即可，免去了繁重冗余的位移同步计算。

### 3.2 测量定位与垂直居中状态的保留

在车身内部，我们需要借助设计稿精准测量出两个轮子相对于车身左上角的偏移坐标。假设测量得出车轮尺寸为宽高等比例圆形，其垂直距离车身顶部固定为 `top: 75px`（依据实际素材量取），左车轮距离车身左侧约 `left: 80px`，右车轮距离左侧约 `left: 360px`（或以 `right` 定位）。

在定位车身父容器时，这里埋伏了一个极其高频的**重大易错陷阱**：

```css
/* 初始状态：车身垂直居中定位在轨道右侧 */
.car {
  position: absolute;
  right: 0;
  top: 50%;
  transform: translateY(-50%); /* 利用平移实现垂直绝对居中 */
  width: 500px;
}
```

注意：车身为了在 `.box` 轨道中保持垂直居中，在初始状态下已经使用了一个 `transform: translateY(-50%)`。

当鼠标悬停要求车身向左行驶 `600px` 时，不少人会这么写：

```css
/* 错误写法：直接覆写 transform */
.box:hover .car {
  transform: translateX(-600px);
}
```

一旦这么写，悬停瞬间整个汽车会猛地往下一跌！因为你只写了 `translateX(-600px)`，直接把初始声明里的 `translateY(-50%)` 给彻底冲刷掉了，垂直居中瞬间失效！

> **注意**：在动画伪类或状态类中修改 `transform` 时，**必须完整保留原有的基准变换函数**。正确的写法必须把垂直居中的补偿位移带上：

```css
/* 正确写法：在保持垂直居中的同时进行水平位移 */
.box:hover .car {
  transform: translateX(-600px) translateY(-50%);
}
```

### 3.3 动画同步与贝塞尔曲线平滑过渡

当汽车自右向左驶入时（X 轴负方向位移），车轮应当朝着什么方向转动？
用手势模拟一下：汽车向左开，车轮上沿向前倾倒滚向左侧，这是典型的**逆时针旋转**。逆时针对应的角度必须是**负角度**（如 `-360deg` 或 `-720deg`）。如果写成正的 `360deg`，车轮就会顺时针疯狂倒转，整辆车看起来就像在冰面上违背物理定律打滑漂移！

同时，车身的平移过渡时间与车轮的旋转过渡时间必须保持**严格完全一致**：

```css
/* 车身平移过渡配置 */
.car {
  transition: transform 3s cubic-bezier(0.25, 0.1, 0.25, 1);
}

/* 车轮旋转过渡配置 */
.wheel {
  transition: transform 3s cubic-bezier(0.25, 0.1, 0.25, 1);
}
```

如果车身设为 `3s`，而车轮设为 `2s`，车轮转了两秒停下了，汽车还在往前滑行，视觉上立即穿帮。

关于动画的缓动曲线，采用默认的 `ease` 虽然可用，但 pink 老师特别提到，想要还原类似华为官网、高端电动车发布会的那种极具高级感的加速起步再平稳减速进站的效果，可以提取官网精调的 `cubic-bezier(0.25, 0.1, 0.25, 1)` 三次贝塞尔曲线参数，赋予机械运动优雅的物理阻尼感。

### 3.5 核心技巧总结与工程反思

回顾整个汽车滚动案例的实现链路，我们可以梳理出处理复合运动的黄金三原则：
1. **多重变换不换行**：在一个 `transform` 声明中聚合书写，空格隔开；
2. **运动顺序看右侧**：执行顺序从右向左；滚动类物体遵循“先写平移，再写旋转”的代码书写顺序；
3. **复合嵌套胜平铺**：复杂的协同运动必须优先通过 DOM 容器进行“宏观位移”与“局部自转”的结构分工，将多轴复杂度降维成简单变换。
