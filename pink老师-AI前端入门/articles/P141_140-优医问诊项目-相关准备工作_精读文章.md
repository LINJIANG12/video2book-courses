# 优医问诊移动端项目开工与工程准备

从 PC 端的小兔鲜一路学到这里，你们有没有发现一个问题：之前不管是 1240px 的版心还是固定宽度的楼层，页面都是放在大屏幕浏览器里看的。可你们每天真正花时间最多的地方，是手里这块不到 7 英寸的手机屏幕。从这一讲开始，我们要换一个战场，做一个真正的手机端项目——优医问诊。

为什么偏偏选一个问诊项目？你们想想，电商、新闻、后台管理，市面上教程里的 demo 遍地都是，可医疗问诊这种带头部渐变、图标导航、选项卡切换、底部固定栏的 App 形态，才是移动端最典型、最能串起所有知识点的形态。把它拿下，vw 适配、弹性布局、粘性定位这些东西就全活了。

我先把丑话说在前面：移动端项目和 PC 端最大的区别，不在标签怎么写，而在开工前的准备。准备工作偷懒一分钟，后面量尺寸、转单位的时候就要还十倍的债。这一讲我们不写一行业务代码，就把地基打牢。

---

## 1. 项目全景与 375px 设计稿基准

### 1.1 首页模块划分

优医问诊首页看着东西不少，其实拆开就是自上而下五个大块，顺序是固定的：头部问诊区、图标导航区、轮播横幅区、问诊选项卡区、底部固定切换栏。记住这个顺序，后面每一讲就是按这个顺序一块一块往下啃。

```text
优医问诊首页自顶向下骨架
+------------------------------------------+
| 1. home-header 头部  (渐变绿 + 搜索框)    |
+------------------------------------------+
| 2. nav 导航       (两行,每行 5 个入口)   |
+------------------------------------------+
| 3. banner 横幅    (轮播图)                |
+------------------------------------------+
| 4. tabs 问诊选项卡 (极速问诊 / 预约门诊)  |
+------------------------------------------+
| 5. tabbar 底部固定栏 (首页 / 问诊 / 我的) |
+------------------------------------------+
```

读图说明：五个大盒子自顶向下依次排列，先有这个总览，后面写代码才不会写到一半不知道自己在哪。

### 1.2 设计稿宽度与 vw 换算关系

我们拿到的设计稿宽度是 `375px`，这不是随便定的。iPhone 6/7/8 以来的逻辑分辨率宽度就是 375，国内绝大多数移动端设计稿都以它为基准。上一讲装的 px 转 vw 插件，配置里的视口宽度同样要写 375，两边对上了，转换才有意义。

> **定义**：视口宽度（viewport width）为 `375px` 时，换算关系是 `1px = 100 / 375 vw ≈ 0.2667vw`。量出多少像素，除以 3.75，就是多少 vw。

你们一定要把这个除数记死：量出 `37.5px` 就是 `10vw`，量出 `12px` 就是 `3.2vw`。后面检查插件转换结果对不对，就靠心算这一笔账。

## 2. 目录结构与基础文件搭建

### 2.1 文件夹划分

在本地新建项目根目录，里面只放四样东西，多一样都是累赘：

```text
优医问诊项目目录结构
youyiwenzhen/
  |-- index.html          首页骨架
  |-- css/
  |     |-- base.css      初始化 + 通用样式
  |     `-- index.css     首页各模块样式
  |-- images/             静态修饰图 (logo、图标、装饰背景)
  `-- uploads/            业务图 (医生头像、轮播图、商品图)
```

读图说明：`images/` 放的是页面皮肤，换多少次医生都不会变；`uploads/` 放的是业务数据，随时会被替换。沿用小兔鲜那套隔离思想，分类标准一点没变。

### 2.2 视口标签与初始化样式

`index.html` 的头部，先把移动端三件套写齐：字符集、视口标签、标题。视口标签上一讲讲过，这里直接用：

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no">
<link rel="stylesheet" href="./css/base.css">
<link rel="stylesheet" href="./css/index.css">
```

`base.css` 里要干三件事：清除默认边距、统一盒模型为 `border-box`、设置默认字体和 body 背景色。移动端页面底色一般是浅灰，比如 `#f6f7f9`，各模块的白色卡片压在上面才有层次。

```css
* {
  margin: 0;
  padding: 0;
  box-sizing: border-box;
}
body {
  font-family: "PingFang SC", "Microsoft YaHei", sans-serif;
  background-color: #f6f7f9;
  font-size: 14px;
  color: #333;
}
li {
  list-style: none;
}
a {
  text-decoration: none;
  color: inherit;
}
img {
  vertical-align: middle;
}
```

> **提示**：`box-sizing: border-box` 在移动端是保命设置。vw 单位下盒子宽度本来就算得紧，再让 padding 往外撑，375 的稿子在 320 的小屏机上必溢出。

### 2.3 素材拷贝与路径检查

把配套素材里的图标、轮播图、医生头像分别拷进 `images/` 和 `uploads/`。拷完先别急着写代码，在浏览器里打开 `index.html`，随手写一个 `img` 标签把每张图引用一遍，确认路径全通。路径问题越早暴露越好，等写到导航栏第二行才发现图裂了，回头查路径能查到怀疑人生。

## 3. px 转 vw 插件配置确认

上一讲装的插件，这一讲要亲手验证它真的在干活。打开插件设置，确认视口宽度（viewport width）填的是 `375`，单位精度保留 4 位小数就够了。

验证方法很土但很有效：在 `index.css` 里随手写一行 `width: 37.5px;` 保存，看它是不是自动变成 `width: 10vw;`。是，说明配置正确；不是，回去检查是不是只在 `css` 文件夹下生效、是不是把基准宽度填成了 750。

> **易错点**：设计稿是 375，插件基准就必须是 375。填成 750，转换出来的数值会小一半，页面在手机上看起来整体缩水一圈，新手十个有九个栽在这里。
