# 登录页开工与 rem 工程准备

首页那套 vw 方案跑通之后，你们心里是不是犯嘀咕：既然 vw 这么省事，为什么还要学 rem？问得好。我直接给你们答案：工作中老项目一大半是 rem 写的，你去改别人的代码，看不懂 rem 就只能干瞪眼。而且只会一种适配，出门面试人家问你移动端有几种方案，你说只有一种，底气立刻少一半。

所以我们单开一个新页面——优医问诊登录页，专门拿它练 rem。为什么非要新开一个页面，不直接在首页上改？你们想想，首页的 vw 插件是按 `375` 视口宽度转单位的，rem 这套要换插件、换基准、换脚本，两套混在一个页面里，单位一打架，查错能查到哭。新开一个 `login.html`，旧账新账分开算，这是工程习惯，记住这一条就够了。

这一讲我们不写一行登录的业务代码，就干三件事：看清登录页长什么样，把目录和基础文件搭好，把 px 转 rem 的插件调通。

---

## 1. 登录页全景与 375px 设计稿基准

### 1.1 四个模块自顶向下排列

登录页比首页简单得多，自上而下就四个大块，顺序固定：顶部导航条、头部品牌区、表单区、第三方登录区。后面四讲就是按这个顺序一块一块啃，这一讲先把总览刻进脑子。

```text
优医问诊登录页自顶向下骨架
+------------------------------------------+
| 1. navbar 顶部导航 (返回 + 标题)          |
+------------------------------------------+
| 2. header 头部品牌 (logo + 宣传语)        |
+------------------------------------------+
| 3. form 表单区 (手机 + 验证码 + 登录按钮) |
+------------------------------------------+
| 4. 第三方登录 (微信 / QQ 快捷入口)        |
+------------------------------------------+
```

读图说明：四个盒子自顶向下依次排列，登录页没有底部固定栏，表单就是页面的绝对主角。

### 1.2 设计稿宽度与 rem 换算关系

设计稿还是 `375px`，这一点和首页一模一样，iPhone 6/7/8 以来的逻辑分辨率宽度就是 375，稿子不用换，换的是尺子。

> **定义**：根字号（root font-size）为 rem 方案的尺子，默认按屏幕宽度十等分，`375px` 宽的屏幕对应根字号 `37.5px`，换算关系是 `1rem = 37.5px`。

你们一定要把这个除数记死：量出 `37.5px` 就是 `1rem`，量出 `44px` 就是 `1.1733rem`，量出 `16px` 就是 `0.4267rem`。后面检查插件转换结果对不对，就靠心算这一笔账。

vw 和 rem 到底差在哪？我给你们摆一张表，一次看明白：

| 对比项 | vw 方案（首页用过） | rem 方案（本页用） |
| :-- | :-- | :-- |
| --- | --- | --- |
| 尺子是谁 | 视口宽度本身 | `html` 的 `font-size` |
| 自适应靠什么 | 浏览器原生计算 | 一段 JS 按屏宽改根字号 |
| 写代码时 | 直接量多少写多少 | 靠插件把 px 转 rem |
| 老项目占比 | 新项目多 | 存量项目多，必须会 |

> **结论**：新页面练新方案，老本事不丢，新本事到手，两种适配你们就全拿下了。

## 2. 目录结构与基础文件搭建

### 2.1 文件夹与文件划分

在原来的项目根目录里接着干，不另起炉灶。只新增两个文件，多一个都是累赘：

```text
优医问诊项目目录结构（登录页新增部分）
youyiwenzhen/
  |-- index.html          首页（vw 方案，不动它）
  |-- login.html          登录页骨架（本讲新建）
  |-- css/
  |     |-- base.css      初始化 + 通用样式（复用）
  |     |-- index.css     首页样式（不动它）
  |     `-- login.css     登录页样式（本讲新建）
  |-- js/
  |     `-- flexible.js   rem 根字号脚本（本讲引入）
  |-- images/             静态修饰图
  `-- uploads/            业务图
```

读图说明：`login.html` 配 `login.css`，和首页那一对彻底隔离；`flexible.js` 是 rem 方案的心脏，专门负责按屏幕宽度改根字号。

### 2.2 视口标签与 flexible 脚本引入

`login.html` 的头部，先把三样东西写齐：视口标签、初始化样式、flexible 脚本。顺序不能乱，脚本一定要在样式之前执行，否则页面会先按默认字号闪一下，再突然缩放，那一下闪屏看着特别廉价。

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no">
<script src="./js/flexible.js"></script>
<link rel="stylesheet" href="./css/base.css">
<link rel="stylesheet" href="./css/login.css">
```

你们注意，`maximum-scale=1.0` 配 `user-scalable=no` 是什么意思？就是不让用户双指缩放页面。登录页的输入框一聚焦，某些安卓机会自动放大页面，整个表单被顶得错位，加上这一对，页面就钉死了。

> **易错点**：`flexible.js` 一定要用配套版本，别随手从网上拷一个旧版。旧版默认按 `750` 稿子十等分，根字号基准对不上，后面所有 rem 全错半拍。

### 2.3 flexible 的工作原理

有人问我，这段 JS 到底干了什么？我一句话讲透：它监听屏幕宽度，除以 10，把结果写到 `html` 的 `font-size` 上。

```js
// flexible 核心逻辑示意（简化版）
function setRootFontSize() {
  var width = document.documentElement.clientWidth;
  document.documentElement.style.fontSize = width / 10 + 'px';
}
setRootFontSize();
window.addEventListener('resize', setRootFontSize);
```

屏幕 `375px` 宽，根字号就是 `37.5px`；屏幕变成 `414px`，根字号跟着变成 `41.4px`。页面里所有 rem 都是相对根字号的，根一动，全页跟着等比缩放，这就是 rem 自适应的全部秘密。

```text
rem 等比缩放示意图
屏宽 375px              屏宽 414px
html:37.5px             html:41.4px
   |                       |
   v                       v
1rem=37.5px             1rem=41.4px
盒子宽 10rem            盒子宽还是 10rem
= 375px                 = 414px（等比放大）
```

读图说明：代码里永远只写 `10rem`，屏幕变大变小，实际像素自动跟着走，这就是一套代码适配所有手机的原理。

## 3. px 转 rem 插件配置确认

手写 rem 换算能把人逼疯，`44px` 除以 `37.5` 等于多少？`1.173333`，谁愿意天天按计算器。所以和 vw 那一讲一样，我们靠插件干这个脏活。

打开插件设置，把基准值（root value）填成 `37.5`。为什么是 37.5 不是 75？你们想想，根字号在 375 屏下就是 `37.5px`，`1rem = 37.5px`，基准必须和它一致。填成 75，转换出来的数值会小一半，页面在手机上整体缩水一圈。

验证方法很土但很有效：在 `login.css` 里随手写一行 `width: 37.5px;` 保存，看它是不是自动变成 `width: 1rem;`。是，说明配置正确；不是，回去检查两件事：一是插件是不是只对 `css` 文件夹生效，二是基准值到底填了多少。

> **提示**：`base.css` 里 `box-sizing: border-box` 那一行，登录页同样保命。rem 单位下输入框宽度本来就算得紧，再让边框往外撑，375 的稿子在 320 的小屏机上必溢出。
