# 盒子视觉工程：背景复合属性与全屏视差滚动实战

在上一讲中，我们系统学习了 CSS 背景属性群（`background`）的各个核心成员，包括背景图片引入、平铺方式、定位坐标、尺寸缩放以及固定依附性。

大家在课后动手实操练习时，普遍反馈并提出了两个非常高频且极具代表性的技术疑问：
1. **定位失控疑问**：为什么给背景图片设置了 `background-attachment: fixed` 之后，原本写好的 `background-position: center center` 居中定位突然“失效”了，图片没有在它所在的盒子里居中，反而跑到屏幕中间去了？
2. **书写冗长疑问**：每次给盒子设置背景，都要单独写背景颜色、背景图片、是否平铺、定位坐标、缩放尺寸、是否固定……动辄写满五六行，CSS 能不能像 `font` 属性那样支持一行搞定的复合简写？

这两个问题问得非常精准，正好切中了背景系统在企业级开发中的核心实战痛点。

本讲我们就以这两个核心问题为切入点，首先彻底拆解 `fixed` 固定的底层坐标参照机制与 `background` 复合简写规则；随后，我们将综合运用这套背景控制体系，手把手实现一个极具视觉冲击力的企业级特效——**全屏沉浸式视差滚动（Parallax Scrolling）**！

## 1. 疑难辨析：`background-attachment: fixed` 的定位参照系

### 1.1 常见认知误区：图片为何脱离了盒子中心？

很多同学在写代码时会遇到这样一个看似奇怪的现象：

```css
.banner {
  width: 600px;
  height: 300px;
  background-image: url("./images/bg.jpg");
  background-repeat: no-repeat;
  background-position: center center; /* 期望：在 600×300 的盒子内部居中 */
  background-attachment: fixed;        /* 一旦加上固定属性，图片立刻跑偏！ */
}
```

保存刷新浏览器后，大家会惊讶地发现：**图片根本没有在 `.banner` 这个盒子里水平垂直居中**，而是直接跑到了整个浏览器可视窗口的中央；当我们在页面中滚动或缩放窗口时，图片的位置表现得完全不受 `.banner` 盒子约束。

> **易错点**：初学者常常误以为 `background-position` 永远是以“当前所在的元素盒子”为参考基准进行坐标定位的。一旦启用了 `background-attachment: fixed`，这个前提假设就会彻底被推翻。

### 1.2 视口（Viewport）机制与坐标切换原理

要搞明白为什么会出现这种现象，必须深入理解浏览器的**视口（Viewport）**概念。

> **定义**：视口（Viewport）指的是当前浏览器窗口中**能够直接看到网页内容的可视矩形区域**。它不包含浏览器的地址栏、书签栏、底部状态栏，也不受整个网页文档流总高度的限制，其尺寸由当前浏览器窗口的大小实时决定。

```text
普通背景与固定背景（fixed）的定位参照基准对比

【普通模式：background-attachment: scroll（默认值）】
┌──────────────────────────────────────────────┐
│ 浏览器可视视口 (Viewport)                    │
│                                              │
│   ┌────────────────────────┐                 │
│   │ .banner 元素盒子       │                 │
│   │   ┌────────────────┐   │                 │
│   │   │  背景图片      │   │ ──> 以盒子自身为原点
│   │   │  (居中对齐)    │   │     center center 相对盒子居中
│   │   └────────────────┘   │                 │
│   └────────────────────────┘                 │
└──────────────────────────────────────────────┘

【固定模式：background-attachment: fixed】
┌──────────────────────────────────────────────┐
│ 浏览器可视视口 (Viewport)                    │
│                                              │
│   ┌────────────────────────┐                 │
│   │ .banner 盒子 (视窗孔径)│                 │
│   │    [仅露出局部画卷]    │                 │
│   └────────────────────────┘                 │
│               ┌────────────────┐             │
│               │ 背景图片       │ ────────────┼──> 参照系突变为整个视口！
│               │ (视口居中)     │             │     center center 相对视口居中
│               └────────────────┘             │
└──────────────────────────────────────────────┘
```
*图 1：普通模式与固定模式下背景定位参照系的物理转移*

当我们将 `background-attachment` 属性设置为 `fixed` 时，浏览器底层发生了两处关键质变：
1. **参考坐标系转移**：背景图片的定位基准不再是当前元素的 `padding-box`，而是**直接与浏览器的可视视口（Viewport）绑定**。此时设置的 `background-position: center center`，其真实含义是**让图片在当前视口的水平中心和垂直中心对齐**；
2. **透视窗（Window）效应**：当前元素盒子此时退化成了一个**“透明观察窗”**。只有当这个盒子在页面滚动过程中移动到与背景图片相重叠的位置时，我们才能透过这个“窗口”窥见底层的背景图；一旦盒子滚出该区域，背景图就看不到了，但背景图本身始终静止钉在视口的指定坐标上。

**实机验证与动态特性**：
- **拖拽缩放浏览器窗口**：当你用鼠标拖动缩小或放大浏览器视口时，如果背景设置了 `fixed` 和 `center center`，你会看到背景图片会实时跟随视口尺寸的重算而重新寻找视口正中心；
- **页面纵向滚动**：滚动条上下滚动时，页面里的 HTML 文字、边框、盒子本身在上下平移，但由于图片相对于视口是固定的，图片在屏幕上的像素坐标分毫不动。

## 2. 语法提效：背景复合简写（`background`）

### 2.1 复合写法的属性聚合规则

在实际业务开发中，如果每一个背景细节都要单独写一行独立属性，样式表会变得极为冗长繁琐：

```css
/* 繁琐冗长的分拆写法 */
.box {
  background-color: pink;
  background-image: url("./images/hero.jpg");
  background-repeat: no-repeat;
  background-position: center center;
  background-size: 300px;
  background-attachment: fixed;
}
```

CSS 提供了属性聚合能力，我们可以直接使用单一的复合属性名 **`background`**（注意不要加任何后缀横线），将上述六大子属性一次性写在一行声明中，各个属性值之间使用**单个空格**隔开：

```css
/* 优雅高效的单行复合写法 */
.box {
  background: pink url("./images/hero.jpg") no-repeat center center / 300px fixed;
}
```

> **提示**：在 `background` 复合写法中，各个属性值通常**没有严格的前后书写顺序要求**。你可以把底色写在最前，也可以把图片放后面，或者把固定属性 `fixed` 提至前列，浏览器解析引擎均能正常识别其类型。

### 2.2 核心硬性约束：`position / size` 必须用斜杠分隔

尽管大部分背景属性的先后顺序完全自由，但规范对**定位坐标（`position`）与尺寸缩放（`size`）**作出了极具约束力的特殊语法规定：

> **核心规则**：在 `background` 复合属性中，若同时书写背景定位（`background-position`）与背景尺寸（`background-size`），**必须使用正斜杠 `/` 进行分隔，且顺序必须严格为 `position / size`**。

```text
background 复合写法中 position 与 size 的语法绑定槽位
┌────────────────────────────────────────────────────────┐
│  background: [color] [image] [repeat] [attachment]     │
│              [position] / [size] ;                     │
└───────────────────────┬───────────┬────────────────────┘
                        │           │
                 先写定位坐标   后写缩放尺寸
                 (水平 垂直)     (宽度 高度)
```
*图 2：复合属性中必须使用斜杠严密绑定的 position/size 结构*

**为什么 W3C 必须强制规定使用正斜杠 `/`？**
因为 `background-position` 和 `background-size` 都可以接受诸如 `center`、百分比（如 `50% 50%`）或长度值（如 `100px 200px`）作为参数。如果允许连续裸写两个或四个数值，浏览器内核在进行词法解析时根本无法界定哪些数值代表起始偏移量、哪些数值代表缩放目标尺寸。斜杠的存在是消除语法歧义的唯一法定分界符。

| 语法书写示例 | 是否合法 | 浏览器解析行为 |
| :--- | :--- | :--- |
| `background: url(a.jpg) no-repeat center center / cover;` | 合法 | 水平垂直居中，等比例缩放覆盖盒子，格式标准 |
| `background: url(a.jpg) no-repeat 0 0 / 200px 100px;` | 合法 | 从左上角开始，尺寸强制缩放为 200×100px |
| `background: url(a.jpg) no-repeat center center cover;` | **非法** | 缺少斜杠，整条 `background` 声明直接失效罢工 |
| `background: url(a.jpg) no-repeat cover / center center;`| **非法** | 顺序倒置（写成了 size / position），样式解析失败 |

> **易错点**：千万不要写出漏掉斜杠的写法。很多同学在编码时自信地敲上 `center center 300px`，结果页面背景死活渲染不出来。计算机程序的规则极为严密，该加斜杠的地方必须严格写上。

## 3. 综合实战：全屏沉浸式视差滚动案例

### 3.1 视差滚动（Parallax Scrolling）的美学原理

在现代网页视觉设计中，**视差滚动（Parallax Scrolling）**是一种让多层背景以不同速度移动、甚至让背景静止而内容滚动的交互技术，能够营造出极强的三维纵深感与电影画卷般的叙事质感。

在本实战案例中，我们设计了一个具有四重境界的唯美画卷页面。整个页面由四个全屏大屏依次拼接而成，每一屏呈现一段富有诗意的心境文字与对应主题的壮丽风光：
- **第一屏【落日夕阳】**：“生活，总是非常的忙碌。但是有时候，我们也需要静下心来，去看看落日的夕阳……”
- **第二屏【山水湖色】**：“去看看山水湖色……”
- **第三屏【广阔蓝海】**：“去看看广阔蓝海……”
- **第四屏【白雪蓝天】**：“去看看白雪蓝天。当我们看完之后，我们有时候也会发现，生活原来也是如此的美好。”

### 3.2 布局基石：`html, body` 100% 高度穿透

在开始编写具体页面前，我们需要攻克一个极易被忽略的底层布局机制——**高度穿透问题**。

如果我们希望页面中的每一个 `<section>` 都能精准占满用户当前的整个屏幕，最直观的写法是给它设置 `width: 100%; height: 100%;`。但是，如果你直接这么写，会发现高度设置完全不起作用！

> **核心原理**：在标准文档流中，普通块级元素的百分比高度（`height: 100%`）是**严格基于其直接父元素的高度计算**的。而 `body` 和 `html` 在默认情况下属于内容自适应元素——**页面里有多少内容，它们就仅有多高**！如果父级高度为 0 或未显式定义，子级声明的百分比高度就失去了计算基准，因而彻底失效。

因此，在实现全屏分屏滚动之前，必须显式声明如下基础全局样式：

```css
* {
  margin: 0;
  padding: 0;
  box-sizing: border-box; /* 怪异盒模型：内边距与边框不再向外撑大盒子 */
}

html,
body {
  width: 100%;
  height: 100%; /* 关键：打通视口高度基准链条，使根节点铺满屏幕可视区 */
}
```

1. **`box-sizing: border-box`**：保证后续在内容容器中增加 `padding` 内边距时，盒子的实际占用空间始终受控，绝不会把全屏容器挤爆；
2. **`html, body { width: 100%; height: 100%; }`**：将网页根标签 `<html>` 和承载体 `<body>` 的宽高直接锚定为当前视口的 100%，自此后代容器声明的 `height: 100%` 才能合法生效。

### 3.3 骨架与排版设计

每一屏在结构上保持高度对称与复用，由一个大外层容器包裹上下两个核心部件：
1. **上部感悟文字区（`.content`）**：全宽、固定占高、衬有半透明磨砂黑底色（`rgba(0, 0, 0, 0.5)`），内部承载优美的抒情段落；
2. **下部核心主题标题（`<h2>`）**：大字号、细字重、优雅的字间距（`letter-spacing`），通过外边距推移至视野焦点。

### 3.5 关键样式剖析与现代工程实践

在上述实战代码中，有几个非常精巧的工程技巧值得大家反复揣摩：

1. **复合写法与 `fixed` 的强强联合**：
   在 `.section1` 到 `.section4` 中，我们仅用了一行代码：
   `background: url(...) no-repeat center center / cover fixed;`
   - `url(...)` 负责载入高清壁纸；
   - `no-repeat` 杜绝小图重复排布；
   - `center center` 保证图片以视觉核心居中；
   - `/ cover` 确保图片等比例自动缩放铺满全屏，无视显示器分辨率差异；
   - **`fixed` 则是画龙点睛之笔**：让这四张大图直接钉在视口底层。当你向下滚动网页时，上一个 `section` 带着它的文字移出屏幕，下一个 `section` 像幕布一样拉开，露出的正是属于它的那张被固定好的底图，无缝呈现电影切镜般的视差滚动！

2. **AI 工具辅助提效的心智模型**：
   在编写这种结构高度重复的页面时，不需要一行一行机械手敲。我们在真实开发中遵循“**打好头样，AI 快速扩产**”的原则：
   - 精心打磨好第一屏（`section1`）的 HTML 骨架与 CSS 样式模板；
   - 在编辑器中敲下注释或打出 `section2` 时，借助 AI 代码补全工具（如 Copilot / AI 助手）一键接受推断出的后续三屏结构；
   - 开发者只需把核心精力聚焦在校验背景图片路径和文案细节的准确性上，开发效率成倍提升。

## 4. 知识沉淀与要点自查表

为了方便大家巩固复习，我们将本讲涉及的背景复合属性规则与视差滚动关键要点汇总如下：

| 知识维度 | 核心语法 / 结论 | 关键防坑要点 |
| :--- | :--- | :--- |
| **`fixed` 定位参照** | `background-attachment: fixed` | 背景图片不再以自身盒子为基准，而是**以视口（Viewport）为基准**定位。 |
| **复合属性声明** | `background: [属性值]...` | 属性名无短横杠后缀；属性值以单个空格隔开，顺序通常可任意颠倒。 |
| **斜杠法宝** | `position / size` | 当同时书写定位和尺寸时，**必须用正斜杠 `/` 隔开**，顺序不可倒置。 |
| **高度穿透规则** | `html, body { width: 100%; height: 100%; }` | 普通块级元素百分比高度依赖父级；根节点必须显式设高，后代全屏才能生效。 |
| **视差滚动核心** | `fixed` 结合全屏卡片 | 盒子随页面正常滚动，背景固定在视口底层不动，借由盒子充当“移动透视窗”。 |
