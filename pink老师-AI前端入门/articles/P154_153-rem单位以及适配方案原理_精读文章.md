# rem 单位与等比适配的原理

`vw` 是拿视口直接当尺子，`rem` 是换一把思路：我不直接量视口，我先定一个根字号，再让全站跟着根字号一起缩放。你们听起来绕，其实淘宝、京东移动端用了快十年，原理吃透了，任何设计稿你们都能接。

## 1. em 与 rem 的参照差异

> **定义**：相对根元素字号单位（Root Em，`rem`）是以文档根元素 `html` 的 `font-size` 为基准的相对单位，`1rem` 等于根字号的像素值。

它和 `em` 就差一个字母，坑的全在这一个字母上。我画个对比你们就不会混了：

```text
em: 一层套一层, 越乘越大
body(16px) -> p(2em=32px) -> span(2em=64px)

rem: 只认根, 永远只乘一次
html(16px) -> 任何地方 2rem = 32px
```

读图说明：`em` 的基准是父元素，会逐层累乘；`rem` 的基准永远是根元素，全站统一。

```css
html {
  font-size: 16px;
}
.card {
  width: 10rem; /* 10 x 16 = 160px */
  font-size: 0.875rem; /* 0.875 x 16 = 14px */
}
```

浏览器默认根字号就是 16 像素，所以不设置时 `1rem` 等于 16 像素。你们以后看到 `0.875rem` 别慌，除以 16 就是 14 像素，这都是同一回事。

> **易错点**：改了父级字号，`em` 全跟着变，`rem` 纹丝不动。新手用 `em` 做卡片，嵌套三层字大得离谱，就是累乘闹的。做整站适配一律用 `rem`，把 `em` 留给首行缩进这种局部小活。

## 2. 等比缩放的推导过程

适配的核心诉求就一句话：设计稿 750 宽的屏和手机 375 宽的屏，同一个按钮看起来比例一致。`rem` 方案分两步走。

第一步，按设计稿定一把尺子。假设设计稿宽 750，我人为定 Breite 划分份数，比如分成 10 份，每份 75 像素，那就让 375 宽的手机根字号是 37.5 像素，750 宽的屏根字号是 75 像素。公式是：

$$根字号 = 视口宽 / 划分份数$$

第二步，全站尺寸都用 `rem` 写。设计稿上一个 150 像素宽的按钮，除以 75 得到 `2rem`，写死 `2rem`。手机 375 下根字号 37.5，`2rem` 算出来 75 像素，正好是设计稿的一半，比例完全一致。

```text
设计稿 750px (根字号 75px)    手机 375px (根字号 37.5px)
+------------------+          +--------+
| 按钮 150px=2rem  |  等比     | 2rem   |
|                  | ------> | =75px  |
+------------------+  缩放     +--------+
```

读图说明：`rem` 数值写死，根字号跟着视口变，最终像素自动等比缩放。

| 对比项 | vw 方案 | rem 方案 |
| :--- | :--- | :--- |
| 基准 | 视口本身 | 根字号 |
| 换算 | `px / 视口宽 x 100vw` | `px / 根字号 rem` |
| 适配手段 | 无需脚本 | 需脚本或媒体查询改根字号 |
| 适用场景 | 纯移动端新项目 | 需兼容老机型、老项目 |

你们问我哪个好？我跟你们说实话，新项目我直接上 `vw`，简单。可你们进公司接的八成是老项目，全站 `rem`，你不会 `rem` 连尺寸都看不懂。所以原理必须吃透，下一讲我就带你们亲手实现一遍，再配好自动换算插件。
