# font 复合简写、CSS 继承性机制与《登高》综合案例终极完善

在前面的学习中，我们把字体的颜色、字号、粗细、风格、行高以及对齐方式全部拆解开来逐个攻克。但是，当大家打开京东、小米、腾讯等一线大厂的网页，通过开发者工具审查 `body` 时，往往会看到一行非常奇特的 CSS 声明：

```css
/* 京东与小米官网 body 样式的真实工业级写法 */
body {
    font: 14px/1.5 "Helvetica Neue", Helvetica, Arial, "Microsoft Yahei", sans-serif;
}
```

有的同学看到这里会产生巨大的疑惑：“老师，为什么 `font` 后面既没有跟 `-size` 也没有跟 `-family`？为什么中间还有一个斜杠 `/`？为什么能把这么多属性揉在一行里？”

这一讲，我们不仅要揭开 **`font` 复合简写属性** 的神秘面纱，还将正式迈入 CSS 最核心的三大基石特性之一——**继承性（Inheritance）**，最后利用这两大核心武器，将我们此前遗留的杜甫《登高》综合案例打磨至工业级像素完美状态！

## 1. font 复合简写属性的严谨语法与约束铁律

在 CSS 中，为了避免一遍又一遍地写 `font-style`、`font-weight`、`font-size`、`line-height`、`font-family` 这一长串冗长代码，规范允许我们将这些属性合并到单单一项 `font` 属性中进行复合简写。

### 1.1 完整的书写次序规范

复合简写绝不是把几个值随意乱丢，它有着如同数学公式般极其严谨的书写次序：

```text
font 复合简写属性的标准展开模型
┌────────────────────────────────────────────────────────────────────────┐
│ font: [font-style] [font-weight] font-size / line-height  font-family; │
│        字体风格     字体粗细     字体大小  /   行高        字体族       │
└────────────────────────────────────────────────────────────────────────┘
```
*图 1：font 复合简写从左到右的标准次序模型*

如果完整写出，它的标准形态如下：
```css
/* 完整形态的 font 复合写法 */
.full-font {
    font: italic 700 16px/1.5 宋体;
}
/* 等价于依次展开为：
   font-style: italic;
   font-weight: 700;
   font-size: 16px;
   line-height: 1.5;
   font-family: 宋体;
*/
```

### 1.2 两大不可违背的绝对铁律

在编写 `font` 简写时，必须时刻警惕两条不可违背的底层约束：

> **铁律一：必须严格遵循书写顺序**！
> 属性的前后次序绝不可颠倒交换。你不能把加粗的 `700` 挪到最后，也不能把字体族扔到最前面。顺序一旦错乱，整个 `font` 声明在浏览器中会直接被当成非法语法而彻底失效！

> **铁律二：font-size 和 font-family 缺一不可**！
> 在这几个属性中，前置的 `font-style`、`font-weight` 以及斜杠后的 `/line-height` 都可以按需省略（省略时自动取默认值），**但 `font-size`（字号）和 `font-family`（字体族）是两个绝对的核心主干，必须同时存在，缺一个都不行**！

#### 极简正确示范：
```css
/* 正确：省略了倾斜、粗细和行高，保留了字号与字体族 */
.valid-font {
    font: 14px 宋体;
}

/* 正确：带行高的工业级标准写法 */
.standard-font {
    font: 14px/1.5 "Microsoft YaHei";
}
```

#### 典型错误反例：
```css
/* 错误：只写了字号，缺少 font-family，整句完全失效！ */
.invalid-font-1 {
    font: 14px; 
}

/* 错误：颠倒了粗细与字体族的位置，解析失败！ */
.invalid-font-2 {
    font: 16px 宋体 700; 
}
```

## 2. CSS 继承性机制深度解析（Inheritance）

在现实生活中有一句俗话：“龙生龙，凤生凤，老鼠的儿子会打洞”。孩子天生会继承父亲的某些特征，这在生物学上叫遗传。

在 CSS 世界中，同样存在着一套极其优雅的遗传机制——**继承性（Inheritance）**。

> **定义**：**子元素会自动继承父元素所具备的某些特定 CSS 样式属性**，无需开发者在子元素上做重复书写。

### 2.1 哪些属性能继承？哪些绝不能继承？

很多初学者容易误以为“父亲的所有样式，子元素都会全盘照收”，这是致命的误解。

```text
CSS 继承性分类图谱
┌────────────────────────────────────────────────────────┐
│                   CSS 属性继承性划分谱系                 │
└────────────┬─────────────────────────────┬─────────────┘
             │                             │
             ▼                             ▼
┌──────────────────────────┐  ┌──────────────────────────┐
│   【可以被继承的属性】    │  │   【绝不会被继承的属性】  │
│  - 绝大多数文本与字体样式 │  │  - 绝大多数盒模型几何特征 │
│  - color                 │  │  - width / height        │
│  - font-* (size, weight) │  │  - margin / padding      │
│  - line-height           │  │  - border                │
│  - text-align            │  │  - background            │
│  - text-indent           │  │  - display               │
└──────────────────────────┘  └──────────────────────────┘
```
*图 2：可继承的文本属性与不可继承的盒模型几何属性划分*

- **可以继承的属性**：主要集中在**文本修饰与字体渲染类**属性，例如 `color`、`font-size`、`font-weight`、`font-family`、`line-height`、`text-align` 等。
  - *设计意图*：一个文章容器既然定好了字体和字号，里面的每一段文字理所当然应该遵从该风格，这极大地减少了冗余代码。
- **绝不会继承的属性**：主要集中在**盒模型几何尺寸与物理边界类**属性，例如 `width`、`height`、`margin`、`padding`、`border`、`background` 等。
  - *生活类比*：父亲有一套 120 平米的房子，肚围 100 厘米，孩子生下来不可能自身也自带一套房子或者长着 100 厘米的肚子。容器盒子的几何空间属于个体私有属性，绝不会发生遗传。

### 2.2 继承冲突与叛逆子元素的“就近原则”

如果父元素设置了文字颜色是红色（`color: red;`），而子元素内部又独立声明了文字颜色是粉色（`color: pink;`），那么子元素到底呈现什么颜色？

> **核心判定**：**就近原则（自我优先）**！
> 继承来的样式永远处于从属地位。当子元素自身通过选择器显式定义了样式时，子元素会执行属于自己的独立设定，父级样式被就地覆盖。这就好比父亲希望孩子穿西装，但叛逆期孩子自己换上了运动服，最终展现的一定是运动服。

```html
<!-- 继承与自我覆盖实操结构 -->
<div class="father">
    我是父亲的红色文字
    <p class="son">我是儿子的粉色文字</p>
</div>
```

```css
.father {
    color: red; /* 父亲设为红色 */
    font-size: 20px; /* 父亲设为 20px */
}

.son {
    color: pink; /* 儿子自己声明了粉色，优先执行粉色！但 font-size 仍继承 20px */
}
```

### 2.3 必须警惕的反常态例外：不听话的 `<a>` 与 `<h>` 标签

在实际项目中，有两个原生 HTML 标签极其“傲慢”，它们天然对父级的某些继承属性视而不见：

1. **`<a>` 标签不继承父级的 `color`**：
   无论你在父级 `<div>` 或 `body` 上把 `color` 设成多么显眼的颜色，`<a>` 标签依旧固执地显示浏览器内置的默认蓝色（未访问）或紫色（已访问）。
   *原因*：浏览器用户代理样式表（User Agent Stylesheet）内部给 `<a>` 标签直接绑定了自带的默认颜色规则。由于“自身样式优先级绝对高于继承样式”，父级的颜色被强制切断。要想改链接颜色，必须**单独用选择器命中 `a` 标签设置**。
2. **`<h1> ~ <h6>` 标签不继承父级的 `font-size` 与 `font-weight`**：
   同理，标题标签拥有浏览器赋予的独立字号体系与默认加粗权重，它不会默默承袭父级指定的统一字号，必须在 CSS 中显式进行单独覆盖。

### 2.4 开发者工具审查继承链条

打开 Chrome 或 Edge 开发者工具，右键“检查”一个子元素。在右侧的 Styles 样式面板中向下拉，你会看到清晰的分类：
- 上半部分是当前元素自身命中的 CSS 规则；
- 下半部分会出现名为 **`Inherited from <element>`（继承自某元素）** 的专属面板。
- 如果某项属性呈现为黑色，说明成功完成继承并正在生效；如果带有删除划线，说明已被当前子元素自身更具体的规则就近覆盖失效。

## 3. 《登高》综合案例终极完善实战

现在，我们掌握了文字样式、文本布局、`font` 复合简写以及继承机制的全套武器。回到我们在 P31 中搭建的杜甫《登高》综合案例，针对当时留下的排版缺陷展开终极修复。

### 3.1 改造痛点分析与解耦难题

在原有的页面骨架中：
- 容器 `.content` 下有介绍段落 `<p>`、古诗模块容器 `.shi`（内含标题 `<h5>`、朝代作者 `<p>`、诗句内容 `<p>`）、以及赏析段落 `<p>`。

我们需要达成的视觉指标如下：
1. **常规文章段落**：行高拉开至 `27px`，首行空两格（`text-indent: 2em;`），文字两端对齐（`text-align: justify;`）；
2. **古诗区块**：古诗标题和全诗每一句需要**水平居中对齐**，且字体需加粗以展现古朴庄重；
3. **关键技术冲突**：
   如果我们在 CSS 中贪图省事直接写：
   ```css
   /* 灾难性错误写法：后代选择器 */
   .content p {
       text-indent: 2em;
       text-align: justify;
   }
   ```
   由于后代选择器会无限穿透向下搜寻，这句代码不仅会作用于常规段落，还会**无情击穿古诗模块内部的诗句 `<p>`**！
   古诗“风急天高猿啸哀”本来要求优雅居中，一旦被强制加上 `text-indent: 2em` 和 `justify`，诗句就会发生严重的局部偏移，排版毁于一旦！

### 3.2 破解法宝：子代选择器（>）精准分离

解决这个难题的钥匙，正是我们在前面学过的**子代选择器（`>`）**！

```text
子代选择器在嵌套结构中的精准命中逻辑
.content （白底内容卡片容器）
  ├── > p （亲儿子：杜甫生平简介段落） ────────► [命中：应用首行缩进与两端对齐]
  ├── > .shi （亲儿子：古诗模块容器）
  │      ├── h5 （孙子：登高标题）
  │      ├── p  （孙子：唐·杜甫）       ───────► [未命中：不受亲儿子缩进规则干扰]
  │      └── p  （孙子：风急天高...）   ───────► [未命中：由 .shi 独立接管居中加粗]
  └── > p （亲儿子：登高赏析文本段落） ────────► [命中：应用首行缩进与两端对齐]
```
*图 3：子代选择器精准限定命中层级，隔离内层诗句*

我们只需使用 `.content > p`：
- 它只选中 `.content` 的**直接亲儿子 `<p>`**（即背景介绍段落和赏析段落），为其施加缩进与两端对齐；
- 嵌套在 `.shi` 内部的诗句属于“孙子代”，完美避开此规则！
- 接着，我们充分利用**继承性**，在 `.shi` 容器上直接声明 `text-align: center;`，其内部的 `<h5>` 和 `<p>` 顺理成章、毫不费力地全盘继承居中对齐！

### 3.3 落地完整 CSS 代码实战

```css
/* 登高赏析页面 - 样式终极完善版本 */

/* 1. 全局样式重置与 body 字体复合简写 */
* {
    margin: 0;
    padding: 0;
}

body {
    /* 采用工业级 font 简写：基准字号 14px，行高 1.5 倍，无衬线字体族 */
    font: 14px/1.5 "Microsoft YaHei", sans-serif;
    color: #333333;
}

/* 2. 外部主容器与卡片容器 */
.box {
    width: 677px;
    background-color: #f0f7fe;
    margin: 0 auto;
}

.content {
    width: 610px;
    background-color: #ffffff;
    margin: 0 auto;
    padding: 20px;
}

/* 3. 精准控制常规正文段落（仅限亲儿子，避免污染诗句） */
.content > p {
    line-height: 27px;
    text-indent: 2em;
    text-align: justify;
}

/* 4. 古诗模块：利用继承性实现优雅统揽 */
.shi {
    /* 利用继承性，父级设置居中，内部 h5 和所有诗句 p 自动继承居中 */
    text-align: center;
    /* 统一指定诗歌行高，增强透气感 */
    line-height: 27px;
    /* 诗歌整体适当加粗 */
    font-weight: 700;
}

/* 5. 标题标签独立覆写字号 */
.shi h5 {
    /* 覆盖 h5 原生字号，指定为更协调的 18px */
    font-size: 18px;
}
```

在上面的最终重构代码中：
1. `body` 运用了简洁的 `font` 复合简写；
2. 文章大面积段落的颜色和字体族依赖 `body` 顺滑继承；
3. 古诗区块使用子代选择器解耦了缩进冲突，并利用 `.shi` 的 `text-align: center` 让内部标题与诗句一键继承居中；
4. 针对不顺从的 `h5` 单独重置尺寸。

页面在视觉上彻底告别了粗糙的原型感，呈现出工整严谨、层次分明的高品质商业质感。

## 4. 本讲核心技术全貌总结

| 技术要点 | 核心机理与语法规范 | 工业级最佳实践 / 避坑指南 |
| :--- | :--- | :--- |
| **`font` 复合简写** | `font: [style] [weight] size[/line-height] family;` | **书写次序绝不可颠倒**；`size` 与 `family` 属必填主干，缺一不可 |
| **CSS 继承性** | 子元素自动沿用父元素的特定样式 | 仅文本字体类样式（`color`、`font-*`、`line-height`）可继承；盒子几何尺寸绝不继承 |
| **继承优先级** | 子元素自身的显式声明优先于继承属性 | 遇到 `<a>`（颜色）与 `<h>`（字号）等内置强样式的标签，必须显式书写选择器进行针对性覆盖 |
| **子代解耦实战** | 使用 `父 > 子` 隔断深层孙子节点 | 在图文混排、嵌套段落中，防止通用段落样式（缩进、两端对齐）穿透污染特定功能区块 |
