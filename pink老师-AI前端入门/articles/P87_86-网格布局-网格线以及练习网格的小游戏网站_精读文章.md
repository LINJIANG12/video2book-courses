# 网格线系统与项目跨行跨列排布规范

以前我们使用网格布局划分轨道时，每个子盒子规规矩矩地各自呆在一个单元格里，大小完全均等。但在实际的商业项目开发中，这种纯粹均等的分块往往无法满足复杂的视觉层级需求。大家打开 B站（Bilibili）首页就能看到，顶部的推荐视频流里，第一个视频卡片的面积非常大，它不仅比其他卡片宽，而且比其他卡片高，横跨了整整两列、两行，而右侧和下方的其他视频卡片则继续保持单单元格排列。

这种“打破均等、部分项目占满多个网格”的视觉结构，到底该如何通过 Grid 优雅实现？答案就是利用网格布局的核心底层支架——**网格线（Grid Lines）**。

---

## 1. 网格线的基本概念与坐标编号规则

我们在创建网格容器、声明网格轨道（Grid Tracks）的瞬间，网格线就已经在浏览器渲染引擎中被自动绘制出来了。在浏览器的开发者工具中开启 Grid 调试遮罩层，就能清晰看到这些贯穿整个网格的虚拟刻度线。

### 1.1 网格线的生成机制与方向划分

网格线是构成网格结构的水平与垂直分割线。它们紧贴网格轨道的边缘，用来界定每个网格单元格的坐标位置。网格线在方向上严格分为两组：

1. **列网格线（Column Grid Lines）**：垂直方向的线条，从左至右依次排列，用于界定列轨道的左右边界。
2. **行网格线（Row Grid Lines）**：水平方向的线条，从上至下依次排列，用于界定行轨道的上下边界。

```text
       列线 1      列线 2      列线 3      列线 4
         |           |           |           |
行线 1 --+-----------+-----------+-----------+--
         |  单元格   |  单元格   |  单元格   |
行线 2 --+-----------+-----------+-----------+--
         |  单元格   |  单元格   |  单元格   |
行线 3 --+-----------+-----------+-----------+--
         |  单元格   |  单元格   |  单元格   |
行线 4 --+-----------+-----------+-----------+--
```

> **说明**：上图展示了一个典型的 3 列 3 行网格。可以看到，网格线的存在为网格内的每一个子项目提供了精确的坐标定位参照。

### 1.2 行线与列线的 N+1 编号推导法则

理解网格线，最关键的一点是掌握它的编号规则。很多初学者经常把“单元格序号”与“网格线序号”混为一谈，导致代码定位出现偏移。

> **定义**：网格线的编号默认从正整数 `1` 开始，从左到右、从上到下单调递增。若网格划分为 $N$ 列，则对应存在 $N + 1$ 根列网格线；若划分为 $M$ 行，则对应存在 $M + 1$ 根行网格线。

为了建立直观的数学直觉，我们来看具体的对应关系：

| 网格轨道划分 | 对应网格线总数 | 网格线正向编号序列 |
| :--- | :--- | :--- |
| 1 列（1 Column） | 2 根列线 | 1, 2 |
| 3 列（3 Columns） | 4 根列线 | 1, 2, 3, 4 |
| 5 列（5 Columns） | 6 根列线 | 1, 2, 3, 4, 5, 6 |
| 3 行（3 Rows） | 4 根行线 | 1, 2, 3, 4 |
| $K$ 行/列 | $K + 1$ 根线 | $1, 2, \dots, K + 1$ |

> **易错点**：网格线编号绝不是从 `0` 开始的！这是 CSS 规范与很多编程语言索引最大的差异之一。第 1 个单元格的左边界是第 1 根列线，右边界是第 2 根列线。

## 2. 项目跨越单元格的属性语法与配置模式

当我们要让一个子盒子在网格中合并多个单元格时，本质上就是告诉浏览器：“让这个盒子从第几根网格线开始，延伸到第几根网格线结束”。在 CSS Grid 中，有两种标准的声明方式。

### 2.1 基于显式起止线编号的定义方式

第一种语法直接在属性中使用斜杠 `/` 分隔起始线与结束线的编号：

```css
/* 跨列设置 */
grid-column: <起始列线编号> / <结束列线编号>;

/* 跨行设置 */
grid-row: <起始行线编号> / <结束行线编号>;
```

例如，我们希望一个子项目水平方向占据第 1 列和第 2 列，垂直方向占据第 1 行和第 2 行：

```css
.item {
  /* 水平从第 1 根列线开始，穿过第 2 根，延伸到第 3 根列线结束 */
  grid-column: 1 / 3;
  /* 垂直从第 1 根行线开始，穿过第 2 根，延伸到第 3 根行线结束 */
  grid-row: 1 / 3;
}
```

此时，该元素在水平方向跨越了 2 列（$3 - 1 = 2$），垂直方向跨越了 2 行（$3 - 1 = 2$），最终独占 $2 \times 2 = 4$ 个基础单元格的空间。

### 2.2 基于 span 跨越数量的相对跨越语法

在实际开发中，如果网格列数很多，逐一去数结束线是第几号线往往容易算错。CSS 提供了更加符合直觉的相对跨度关键字 `span`：

```css
/* 语法形式 */
grid-column: <起始列线编号> / span <跨越的单元格数量>;
grid-row: <起始行线编号> / span <跨越的单元格数量>;
```

使用 `span` 关键字改写上述案例：

```css
.item {
  /* 从第 1 根列线开始，向右跨越 2 个单元格 */
  grid-column: 1 / span 2;
  /* 从第 1 根行线开始，向下跨越 2 个单元格 */
  grid-row: 1 / span 2;
}
```

这里的 `span 2` 表达的是“跨度为 2 个格子”，读者不需要心算结束线到底是第 3 根还是第 4 根。这两种写法在浏览器渲染效果上完全等价，大家可以根据团队规范或心智负担自由选择。

### 2.3 属性作用域与宿主元素约束

这里有一个极其关键的规则，必须反复敲黑板强调：

> **重要**：`grid-column` 与 `grid-row` 是**网格项目属性（Grid Item Properties）**，必须直接书写在需要发生形变的**子元素**选择器内，绝对不能写在网格父容器（Grid Container）上！
> 父容器只负责通过 `grid-template-columns` 等属性划分轨道，它自己并不需要在网格里占据位置。

## 3. B站首页复合推荐卡片布局实战推导

为了将上述知识转化为生产力，我们来完整还原 B站首页经典的视频推荐流卡片结构。

```text
+-----------------------+-----------+-----------+-----------+
|                       |  卡片 2   |  卡片 3   |  卡片 4   |
|      主推荐卡片       +-----------+-----------+-----------+
|     (跨 2列 2行)      |  卡片 5   |  卡片 6   |  卡片 7   |
+-----------+-----------+-----------+-----------+-----------+
|  卡片 8   |  卡片 9   |  卡片 10  |  卡片 11  |  卡片 12  |
+-----------+-----------+-----------+-----------+-----------+
```

> **说明**：推荐流首项为一个大尺寸的主推荐卡片，右侧为两排常规卡片，下方为一排横贯全宽的常规卡片。

### 3.1 页面网格行列划分决策

在写代码之前，第一步必须在脑海里对布局进行严密的行列解构。请问：这个区域到底应该划分成几行、几列？

判断网格划分时，**切记不要只看顶部大卡片，必须看最密集、最小细分单元所在的区域**。我们观察布局底部，可以整整齐齐地排下 5 个常规卡片；纵向观察右侧，共有 3 排常规卡片的高度。因此，底层网格的客观物理结构是：**5 列、3 行**。

容器结构与基础样式搭建如下：

```html
<div class="box">
  <div class="item">1</div>
  <div class="item">2</div>
  <div class="item">3</div>
  <div class="item">4</div>
  <div class="item">5</div>
  <div class="item">6</div>
  <div class="item">7</div>
  <div class="item">8</div>
  <div class="item">9</div>
  <div class="item">10</div>
  <div class="item">11</div>
  <div class="item">12</div>
</div>
```

```css
.box {
  /* 设置版心最大宽度与居中 */
  max-width: 1200px;
  margin: 100px auto;
  /* 激活网格布局 */
  display: grid;
  /* 划分 5 列，每列均分 1fr 弹性宽度 */
  grid-template-columns: repeat(5, 1fr);
  /* 单元格之间的横纵间隙统一为 10px */
  gap: 10px;
}

.box .item {
  background-color: pink;
  /* 常规子盒子给一个默认高度 */
  height: 120px;
}
```

### 3.2 跨行跨列样式实现与固定高度失效陷阱

现在我们要让第 1 个子元素独占 2 列、2 行。我们选中第一个子项：

```css
.box .item:first-child {
  /* 水平方向：从第 1 根线延伸到第 3 根线（跨 2 列） */
  grid-column: 1 / 3;
  /* 垂直方向：从第 1 根线延伸到第 3 根线（跨 2 行） */
  grid-row: 1 / 3;
  /* 关键修复点：解除固定高度限制 */
  height: auto;
}
```

这里有一个极易踩坑的细节：
当我们给所有 `.item` 统一设置了 `height: 120px` 时，第一个大盒子虽然在网格分配上占据了 2 行的轨道空间（高度应为 $120px \times 2 + 10px = 250px$），但由于 CSS 盒模型的具体高度声明（`height: 120px`）具有强约束，导致大盒子虽然占了坑，高度却依然被截断在 120px，下方留出一大片空白！

> **易错点**：当子元素进行跨行合并（`grid-row`）时，务必将该子元素的 `height` 重置为 `auto`（或通过内部图片/内容自然撑开），使盒子的视觉高度能自动填满跨行后的完整网格区域。

### 3.3 响应式等比缩放机理与源码佐证

当我们在浏览器中拖动窗口改变宽度时，由于列宽使用了 `1fr` 弹性单位，整个网格会随之平滑压缩或扩张。不仅右侧的小卡片会自适应缩放，左上角跨越两列的大卡片也会严格保持与小卡片呈 $2:1$ 的宽度比例进行联动收缩。

我们在真实 B站首页的推荐流卡片上右键点击“检查”，审查其计算样式，可以看到官方团队同样在首个卡片容器上应用了如下核心规则：

```css
/* 真实商业网页中的源码应用 */
.feed-card:first-child {
  grid-column: 1 / 3;
  grid-row: 1 / 3;
}
```

这充分证明，网格线是大型商业网站构建非对称卡片流的标准现代方案。

## 4. 网格线分写属性与 Grid Garden 逻辑演练

为了帮助学习者建立牢固的网格坐标肌肉记忆，技术社区推出了专门针对网格练习的闯关交互网站（如 Grid Garden，网格花园）。在游戏中，玩家需要通过编写 CSS Grid 规则控制水流（water）覆盖土地上的胡萝卜（carrot）。

### 4.1 独立控制起止位置的分写属性

在前面的实战中，我们使用的是复合简写属性 `grid-column`。在 CSS 规范中，它实际上是由两个分写属性合并而来的：

1. **`grid-column-start`**：定义项目在水平方向开始于哪一根网格线。
2. **`grid-column-end`**：定义项目在水平方向结束于哪一根网格线。

同理，垂直方向对应的分写属性为 `grid-row-start` 与 `grid-row-end`。它们之间的对应关系如下：

$$
\text{grid-column: } \langle\text{start}\rangle \text{ / } \langle\text{end}\rangle \iff \begin{cases} \text{grid-column-start: } \langle\text{start}\rangle; \\ \text{grid-column-end: } \langle\text{end}\rangle; \end{cases}
$$

### 4.2 关卡实战推导与坐标控制演练

我们以该练习网站的前 5 个核心关卡为例，推导网格线属性的运作逻辑：

#### 第 1 关：定位起始位置

- **场景描述**：默认网格为 5 列 5 行。当前水流位于第 1 列，目标胡萝卜位于第 3 列。
- **逻辑推导**：水流只需要从第 3 根网格线开始流出即可覆盖目标。
- **解题代码**：
  ```css
  #garden {
    display: grid;
    grid-template-columns: 20% 20% 20% 20% 20%;
    grid-template-rows: 20% 20% 20% 20% 20%;
  }
  #water {
    grid-column-start: 3;
  }
  ```

#### 第 2 关：延伸至末列起始点

- **场景描述**：胡萝卜生长在最右侧的第 5 列。
- **逻辑推导**：第 5 列的左侧边界就是第 5 根列网格线。
- **解题代码**：
  ```css
  #water {
    grid-column-start: 5;
  }
  ```

#### 第 3 关：控制结束网格线以浇灌连续目标

- **场景描述**：水流默认从第 1 根网格线开始流出，需要向右连续浇灌位于第 1、2、3 列的连续胡萝卜。
- **逻辑推导**：水流从线 1 出发，要覆盖到第 3 个格子的右侧边缘。第 3 个单元格的右侧边缘正是第 4 根网格线。
- **解题代码**：
  ```css
  #water {
    grid-column-end: 4;
  }
  ```

#### 第 4 关：反向约束结束边界

- **场景描述**：水流起始线被固定在第 5 根线，向左扩展浇水，目标是覆盖第 2、3、4、5 列。
- **逻辑推导**：水流向左延伸时，其左边界需要收拢在第 2 根列网格线处。
- **解题代码**：
  ```css
  #water {
    grid-column-end: 2;
  }
  ```

#### 第 5 关：整行全覆盖

- **场景描述**：水流从第 1 根线出发，需要横向浇满整整一行（包含全部 5 颗胡萝卜）。
- **逻辑推导**：5 个单元格对应的最右边界线编号为 $5 + 1 = 6$。若覆盖前 4 颗，则结束于线 5。
- **解题代码**：
  ```css
  #water {
    grid-column-end: 5;
  }
  ```

通过网格游戏与真实网站卡片布局的相互印证，我们可以确信：网格线是精确操控二维空间布局的标尺。掌握了网格线编号与跨行跨列语法，面对任何复杂的非均等栅格设计，都能做到游刃有余。
