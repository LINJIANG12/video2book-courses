# 35-分组选择器和链接伪类选择器

在前面的课程中，我们已经学习了基础选择器（标签、类、id、通配符）以及关系选择器（后代、子代、兄弟）。但在实际做项目的过程中，大家很快就会发现一个让人抓狂的问题：很多不同的标签，它们要实现的样式效果明明是一模一样的，难道我们每一个都要单独写一遍吗？

不仅如此，平时大家在逛淘宝、京东或者新浪新闻的时候，鼠标移到一个链接上，文字瞬间变色或者冒出一条下划线；或者点过的新闻标题颜色变暗变灰，告诉你“这条你已经读过了”——这种根据元素的不同交互状态去改变样式的魔法，又是怎么做到的？

这一讲我们就把 CSS 中大幅精简代码的利器——**分组选择器（并集选择器）**，以及网页交互灵魂所在的**链接伪类选择器**彻底学透！

---

## 1. 分组选择器（并集选择器）

### 1.1 语法定义与核心作用

所谓**分组选择器**，在很多教材和前端规范里也被称作**并集选择器**，指的就是：**将不同的选择器组合在一起，给它们集体声明相同的 CSS 样式**。

在书写语法上，分组选择器使用英文逗号 `,` 来分隔各个选择器。逗号在逻辑上就是“和”的意思。

```text
分组选择器（并集选择器）语法结构示意图
┌─────────────────────────────────────────────────────────────┐
│  选择器1,  选择器2,  选择器3 {                                │
│      共同属性: 属性值;                                        │
│  }                                                          │
│                                                             │
│  解读：选择器1 和 选择器2 和 选择器3，都具备大括号内的样式规则   │
└─────────────────────────────────────────────────────────────┘
```

它的核心使用场景非常明确：**如果页面中有多个元素具有相同的样式规则，完全没有必要分散开来各自写一套，直接组合在一起集体声明，不仅省时省力，还能大幅精简代码体积，维护起来极其方便。**

### 1.2 小米产品卡片案例场景解析

我们来看一个实际开发中的经典场景——小米官网的产品列表卡片。

在每一个产品卡片下方，通常有一行产品的**主标题**（通常用 `<h3>` 或带有 `.title` 类的标签制作），在标题下方紧跟着一行浅灰色的**产品功能介绍**（通常用 `<p>` 或带有 `.desc` 类的标签制作）。

在设计规范中，这两段文字往往有共同的要求：
1. 文字全部居中对齐；
2. 如果文字太长超出了卡片宽度，不能换行把卡片撑破，而必须把多余的内容截断并显示省略号（`...`）。

实现单行文本溢出省略号通常需要三句固定的样式代码：强制不换行、溢出隐藏、溢出显示省略号。如果我们分开给标题和介绍各写一份，代码就会变成下面这样：

```css
/* 繁琐冗余的写法：分开写两套一模一样的代码 */
.product .title {
    text-align: center;
    white-space: nowrap;
    overflow: hidden;
    text-overflow: ellipsis;
}

.product .desc {
    text-align: center;
    white-space: nowrap;
    overflow: hidden;
    text-overflow: ellipsis;
}
```

大家看，这样写整整占用了 12 行代码，里面有 8 行核心属性是完全一模一样的克隆复制。如果页面上类似的地方多了，你的 CSS 文件很快就会变得又臭又长。

借助分组选择器，我们只要在中间加一个英文逗号，就能把它们合并成一组：

```css
/* 优雅精炼的写法：使用分组选择器集体声明 */
.product .title,
.product .desc {
    text-align: center;
    white-space: nowrap;
    overflow: hidden;
    text-overflow: ellipsis;
}
```

一行逗号，直接砍掉了一半的重复代码！两组选择器各自匹配对应的 HTML 元素，但共享同一块样式大括号。

### 1.3 《登高》综合案例代码重构

大家还记得我们前面做过的《登高》千古第一绝句的综合案例吗？

那年我们还年轻，刚刚接触 CSS，在给白色内容盒子 `.content` 设置内部排版时，提出了这样一个需求：
- 盒子内部插入的唐诗配图（`img`），宽度要占满白盒子的 100%；
- 盒子内部插入的朗诵音视频（`video`），宽度同样也要占满白盒子的 100%。

当时因为我们还没学分组选择器，只能老老实实写了两遍：

```css
/* 重构前：初学时的青涩写法 */
.content img {
    width: 100%;
}

.content video {
    width: 100%;
}
```

现在学会了分组选择器，直接动手对它进行现代化重构：

```css
/* 重构后：利用分组选择器合并后代选择器 */
.content img,
.content video {
    width: 100%;
}
```

保存刷新，页面效果丝毫不差，而你的代码已经从初学者级别蜕变成了规范高效的工业级代码！

### 1.4 分组选择器的书写规范与避坑要点

在编写分组选择器时，有两点至关重要的规范大家必须牢记在心：

> **规范**：**选择器列表建议垂直换行书写**。虽然在 CSS 语法中写成一行 `.content img, .content video { ... }` 浏览器完全能解析，但在企业级项目协作中，当选择器较长或并列项多于 2 个时，强烈建议每个选择器独占一行，逗号紧随其后。这样不仅代码结构清晰易读，而且在 Git 提交比对代码差异时一目了然。

> **易错点**：**复合选择器分组时，父级上下文绝不能省略**！
> 很多初学者写并集选择器时容易偷懒，觉得前面写了 `.content img`，后面只写一个逗号加 `video` 就行了，写成了：
> ```css
> /* 致命错误写法：后一个选择器遗漏了父级前缀 */
> .content img, video {
>     width: 100%;
> }
> ```
> 这样写的意思是：“`.content` 盒子内部的图片，以及**全页面所有的视频**全部宽度 100%”。逗号隔开的每一个选择器都是独立的语法单元，浏览器解析时绝不会自动继承逗号前面的父级修饰。必须老老实实写全 `.content img, .content video`。

## 2. 伪类选择器概览

### 2.1 什么是伪类？

搞定了分组选择器，接下来我们要攻克 CSS 里极具动态魅力的一个家族——**伪类选择器（Pseudo-classes）**。

在解释它之前，我们先辨析一个符号特征：
- 基础的**类选择器**，前面用的是**一个英文实心点**，例如 `.box`；
- 而**伪类选择器**，使用的是**英文冒号 `:`** 来进行修饰，例如 `:hover`。

冒号有两个点，所以它不是真正的类，而是一个“虚假的类”（伪类）。那它“伪”在哪里？

平时我们写 `.nav`，是我们在 HTML 结构里白纸黑字写下了 `class="nav"`，这个类是静态写死的；但伪类不同，**它不是选中某种 HTML 标签本身，而是专门用来选中元素的某种“特定状态”或者“特定的结构位置”**。

```text
类选择器 vs 伪类选择器
┌───────────────────┬────────────────────────────────────────────────────────┐
│ 选择器类别        │ 核心特征与表现                                         │
├───────────────────┼────────────────────────────────────────────────────────┤
│ 类选择器 (.class) │ 静态选择：由 HTML 中的 class 属性显式声明，固化在 DOM 中   │
├───────────────────┼────────────────────────────────────────────────────────┤
│ 伪类选择器 (:state)│ 动态选择：根据用户的交互行为、浏览状态或 DOM 结构位置动态激活│
└───────────────────┴────────────────────────────────────────────────────────┘
```

### 2.2 伪类选择器的三大常见分类

在整个 CSS 体系中，伪类选择器主要分为以下三大支柱：

1. **用户交互/状态伪类**：根据用户与网页发生的即时动作来触发。比如鼠标悬停（`:hover`）、表单输入框获取光标焦点（`:focus`）等；
2. **结构伪类**：根据元素在父容器中的排布次序与结构位置来选取。比如选取父元素下的“第一个孩子”（`:first-child`）、“最后一个孩子”（`:last-child`）、“第 n 个孩子”（`:nth-child(n)`）等；
3. **表单伪类**：针对表单控件专属状态的选择器。比如被禁用的输入框（`:disabled`）、被选中的复选框或单选框（`:checked`）等。

本节课我们首先把状态伪类中最经典、面试与实战出现频率最高的**链接伪类选择器**讲明白。

## 3. 链接伪类选择器（LVHA）

### 3.1 链接的四种状态

超链接标签 `<a>` 是网页中交互性最强的元素。一个链接在它的生命周期里，可能会经历以下四种不同的状态，CSS 为每一种状态都提供了一个专属的伪类选择器：

| 伪类选择器 | 对应交互状态 | 触发时机与技术含义 |
| :--- | :--- | :--- |
| `a:link` | 未访问状态（Unvisited） | 链接从来没有被当前浏览器点击访问过时的默认展示样式 |
| `a:visited` | 已访问状态（Visited） | 用户曾经点击浏览过该链接目标地址后的展示样式 |
| `a:hover` | 鼠标悬停状态（Hover） | 用户的鼠标指针移动并停留在链接上方时的即时样式 |
| `a:active` | 激活/点击状态（Active） | 鼠标左键在链接上按下、但**尚未抬起松开**那一瞬间的样式 |

```text
用户与链接交互的状态变迁轨迹
┌──────────────┐   用户点击访问后    ┌─────────────────┐
│   a:link     │ ─────────────────> │   a:visited     │
│ (初始未访问)  │                    │  (历史已访问)    │
└──────┬───────┘                    └────────┬────────┘
       │                                     │
       │           鼠标指针移入               │
       └──────────────┬──────────────────────┘
                      │
                      ▼
               ┌──────────────┐
               │   a:hover    │ (悬停提示：变色/下划线)
               └──────┬───────┘
                      │ 鼠标按下不松
                      ▼
               ┌──────────────┐
               │   a:active   │ (激活按下：变暗/位移反馈)
               └──────────────┘
```

### 3.2 链接伪类的声明顺序规则与机理

这四个链接伪类如果同时写在样式表里，**它们的书写先后顺序有着极其严苛的要求**，绝对不能随心所欲乱写！

> **核心规则**：四个伪类的书写顺序必须严格遵守：
> **`link` $\rightarrow$ `visited` $\rightarrow$ `hover` $\rightarrow$ `active`**

#### 记忆口诀：LV 包包好（LVHA）

四字母的首字母分别是 **L**、**V**、**H**、**A**。
怎么记呢？大家平时有没有买过或者听说过法国的奢侈品牌 **LV**？
LV 包包好不好？**好（HA）**！
把它们连起来读：**LV 好（LV HA）**！
按照这个口诀，你这辈子都不会把链接伪类的书写顺序搞混。

```text
链接伪类顺序口诀：
L (link)     ──> 未访问
V (visited)  ──> 已访问
H (hover)    ──> 鼠标悬停
A (active)   ──> 激活按下
```

#### 颠倒顺序会发生什么？（底层层叠机理）

有的同学可能会问：“老师，我就叛逆一下，我偏要不按你的顺序写，我把 `hover` 写到最前面去，会怎么样？”

我们现场做个实验：

```css
/* 错误示范：顺序颠倒，将 hover 置于最顶端 */
a:hover {
    color: red;
}

a:link {
    color: blue;
}

a:visited {
    color: green;
}

a:active {
    color: orange;
}
```

当我们把代码改成这样后保存，回到浏览器把鼠标放到链接上——你会惊讶地发现：**链接根本不会变成红色！它依然死死保持着蓝色（或者绿色）！**

为什么？因为在 CSS 中，**具有相同优先级的选择器，后面写的样式会覆盖掉前面写的样式**。
当鼠标悬停在链接上时，这个链接**既处于 hover 状态，同时它本质上依然是一个未访问（link）或已访问（visited）的链接**！两个状态同时满足，但你的 `a:link` 和 `a:visited` 写在 `a:hover` 的下面，后面的颜色直接把前面的红色给覆盖干掉了。

同理，如果你把 `active` 写在 `hover` 的前面，当你用鼠标按住链接不放时，因为鼠标指针同时依然停在链接上方，`hover` 写在后面就会把 `active` 按下的效果覆盖掉。

所以，遵循 **LVHA（LV好）** 原则是底层层叠权重与交互逻辑决定的硬性规律，千万不要调皮颠倒。

## 4. 链接伪类代码实操与 DevTools 调试技巧

### 4.1 四种状态完整代码演练

我们在 HTML 中放入三个测试链接，演示四种状态的完整变化：

```html
<a href="https://www.deepseek12345.com">DeepSeek新入口</a>
<a href="#">产品介绍</a>
<a href="#">联系方式</a>
```

在 CSS 中依次注入四种样式：

```css
/* 1. 未访问过的链接：黑色，无下划线 */
a:link {
    color: #333;
    text-decoration: none;
}

/* 2. 访问过的链接：橙色 */
a:visited {
    color: orange;
}

/* 3. 鼠标悬停在链接上：变成红色，并增加下划线 */
a:hover {
    color: red;
    text-decoration: underline;
}

/* 4. 鼠标按下尚未松开：变成蓝色 */
a:active {
    color: blue;
}
```

保存刷新预览：
1. 页面刚打开时，`DeepSeek新入口` 这个网址我们从未访问过，它规规矩矩呈现为 `#333` 纯黑色，下划线被成功清空；
2. 鼠标移入文字上方，文字瞬间亮起醒目的红色，底下刷地浮现出下划线；
3. 鼠标左键用力按住不松手，文字立刻变成深蓝色；松开鼠标，页面触发跳转；
4. 当我们退回该页面后，因为刚才已经成功访问过该网址，链接颜色稳稳转变为橙色，提示用户此前已经浏览过该页面。

> **提示**：如果在测试 `visited` 时，你点击了 `href="#"` 的空链接，你会发现页面中所有同为 `href="#"` 的链接全部一起变成了已访问颜色。因为浏览器记录访问历史是依据目标 URL 判断的，它们的目标地址完全一样，所以会同步生效。

### 4.2 浏览器开发者工具强制状态（Force state）

平时在开发网页排查 bug 时，大家会遇到一个让人头疼的问题：`:hover` 和 `:active` 是动态状态，只有当鼠标移上去或者按住时才会短暂出现；一旦鼠标挪开回到审查元素面板，样式规则立刻就消失了，根本没办法在面板里修改参数进行调试。

怎么才能让浏览器把动态的 `:hover` 状态**死死定住**供我们检查呢？这里教大家一个前端工程师必备的 DevTools 调试技巧：

```text
浏览器调试动态伪类技巧步骤：
1. 按 F12 打开开发者工具，点击左上角箭头图标（或 Ctrl+Shift+C）选中页面中的 a 链接；
2. 在 Elements（元素）面板对应的 <a> 节点上点击鼠标右键；
3. 在弹出的右键菜单中找到 "Force state"（强制状态）；
4. 在二级菜单中勾选 ":hover"（或 ":active" / ":focus"）。
```

此时元素标签左侧会出现一个小圆点标记，页面上的链接就会被强制锁定在 `:hover` 状态下！你可以气定神闲地在右侧 Styles 面板中查看所有生效的 hover 样式规则，实时调整颜色、字体与阴影。

调试完毕后，只需再次取消勾选，就能恢复正常交互逻辑。

## 5. 真实企业级项目中的主流实战写法

我们在前面花了很大篇幅把 LVHA 四个状态讲解得清清楚楚，但在真实的前端工程实践中，难道每一个链接我们都要写满四套规则吗？

答案是：**几乎不需要！**

除了专业的新闻资讯类网站（如新浪新闻、网易新闻）为了照顾读者阅读进度，会针对看过的资讯保留 `:visited` 变暗效果外，绝大多数企业官网、电商平台（淘宝、京东、小米）为了保持页面视觉的高级感与统一性，通常**只保留两种最关键的状态**：

```text
工业级超链接样式标配两步法：
┌────────────────────────────────────────────────────────┐
│  第 1 步：用 a 标签基础选择器，统一定义默认状态的外观     │
│          （指定基准字色，去除默认丑陋的下划线）           │
│                                                        │
│  第 2 步：用 a:hover 单独定义鼠标经过时的视觉反馈         │
│          （变高亮色、微动效或补上下划线）                 │
└────────────────────────────────────────────────────────┘
```

### 5.1 淘宝与京东风格写法对比

我们来看两大电商巨头的通用做法：

#### 方案 A：默认无下划线，悬停加下划线（淘宝风格）

```css
/* 基础默认状态：所有超链接无下划线，字色继承或指定 */
a {
    color: #333;
    text-decoration: none;
}

/* 鼠标悬停交互：文字变主题红，并显现下划线 */
a:hover {
    color: #f40;
    text-decoration: underline;
}
```

#### 方案 B：默认无下划线，悬停只变色不加下划线（京东/小米风格）

很多现代扁平化与极简风格网站不喜欢下划线带来的视觉割裂感，更倾向于仅通过色值跃迁来传递交互响应：

```css
/* 基础默认状态：深灰色，无下划线 */
a {
    color: #666;
    text-decoration: none;
}

/* 鼠标悬停交互：文字跃迁为高亮品牌红，依然保持无下划线 */
a:hover {
    color: #e1251b;
}
```

在日常开发中，直接书写 `a` 和 `a:hover` 不仅写法极其精炼，而且避免了 `a:link` 和 `a:visited` 带来的样式层叠优先级困扰。大家在今后完成各类项目大作业或商业外包时，牢牢握住这一套组合拳就足够应对 95% 以上的业务场景。

## 6. 核心要点归纳与下节预告

在本讲中，我们完成了选择器能力的又一次关键升级：

1. **分组选择器（并集选择器）**：
   - 核心符号为英文逗号 `,`，表示逻辑上的“和”；
   - 适用场景为多个元素具有完全相同的样式规则；
   - 书写时建议垂直排布换行，且后代选择器参与分组时必须写全每一个选择器的完整层级前缀。
2. **链接伪类选择器**：
   - 包含未访问（`:link`）、已访问（`:visited`）、悬停（`:hover`）和激活（`:active`）四种交互形态；
   - 必须严格按照 **LVHA（LV好）** 的次序书写，否则层叠机制会导致悬停或激活样式失效；
   - 掌握了 Chrome 开发者工具通过 `Force state` 强制锁定伪类状态的高效排错技巧；
   - 明确了真实工程开发中以 `a` + `a:hover` 为核心的主流轻量实践方案。

鼠标停留在链接上变色只是伪类家族的冰山一角。那如果鼠标悬停在一个普通的 `<div>` 盒子上、一张图片上或者一个按钮上，能不能也产生这种神奇的视觉跃迁？当用户的鼠标点击表单输入框获取光标时，输入框周围亮起的那一圈漂亮的光晕又是怎么实现的？
