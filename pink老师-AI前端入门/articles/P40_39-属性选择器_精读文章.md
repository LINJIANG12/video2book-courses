# 39-属性选择器

大家在日常浏览 B站（Bilibili）、小米商城或者苹果官网时，如果按下 `F12` 审查元素，经常会在大厂的 CSS 样式表里看到这样一类长相非常特殊的选择器：

比如 `[class*="icon-"]`、`input[type="password"]`、或者 `a[href^="https"]`。很多初学者看到那一对方括号 `[...]` 就直挠头：“老师，这是什么新奇的高级语法？我们平时写样式不都是打个点写类名（`.nav`、`.item`）吗？为什么大厂的样式表里到处都是带中括号的选择器？”

其实，这就是现代前端开发中极其重要、极其优雅的**属性选择器（Attribute Selectors）**！

它的最大杀伤力在于：**不需要我们给每一个 HTML 标签都苦哈哈地手动添加自定义类名（class），而是直接根据标签身上自带的原生属性或自定义属性，以及这些属性的具体取值，进行极其精准的定位或模式匹配**。今天我们就把属性选择器的五大核心形态与三大工业级场景彻底讲深讲透！

---

## 1. 为什么属性选择器是开发利器？

### 1.1 避免类名泛滥（Class Pollution）

在大型项目或复杂表单中，页面上可能同时存在几十个 `<input>` 标签：有的是单行文本框（`type="text"`），有的是密码框（`type="password"`），有的是单选按钮（`type="radio"`），还有的是提交按钮（`type="submit"`）。

如果我们想把所有的文本框和密码框的外轮廓线去掉，按照传统做法，你必须手动去 HTML 里给它们每一个都补上 `class="txt-input"`；
而有了属性选择器，我们一行代码即可降维打击：

```css
/* 无需在 HTML 中额外起类名，直接根据 type 属性精准匹配！ */
input[type="text"],
input[type="password"] {
    outline: none; /* 清除点击时的默认外轮廓蓝框 */
}
```

```text
属性选择器定位原理
┌─────────────────────────────────┐
│        目标 HTML 元素            │
│  <input type="password" ...>    │
└────────────────┬────────────────┘
                 │ 浏览器检测属性名与属性值
                 ▼
┌─────────────────────────────────┐
│     input[type="password"]      │ <── 仅当属性名完全对齐且值匹配时命中！
└─────────────────────────────────┘
```

### 1.2 跨场景三大商业级舞台

1. **表单差异化控制**：精准区分不同功能的输入控件；
2. **图标字体库（IconFont）统一声明**：阿里巴巴矢量图标库、FontAwesome 等，全网统一采用包含匹配模式；
3. **国际化语言适配（i18n）**：根据网页根标签的 `lang` 属性自动切换西文或亚洲文字体。

## 2. 属性选择器的五大核心语法形态

属性选择器的核心标识符就是**中括号 `[...]`**。根据匹配精度的不同，在 CSS 中被严密划分为五大派系：

### 2.1 属性存在匹配——`[attr]`

语法形式：

```css
E[attr] {
    /* 样式规则 */
}
```

- **匹配机理**：只要元素 `E` **拥有该属性**，不论该属性的具体值是什么，通通被选中；如果该元素根本没有这个属性，则直接排除。
- **生动比喻**：“只要你身上带着身份证，不管你叫张三还是李四，全部放行！”

#### 代码实战：

假设页面上有 5 个超链接，其中后 4 个都带有 `class` 属性，只有第 1 个没有：

```html
<a href="#">第一个链接（无 class）</a>
<a href="#" class="font">第二个链接</a>
<a href="#" class="font14">第三个链接</a>
<a href="#" class="font16">第四个链接</a>
<a href="#" class="font-bold">第五个链接</a>
```

```css
/* 选中所有具有 class 属性的 a 标签，文字标红 */
a[class] {
    color: red;
}
```

> **效果**：除了第 1 个链接外，其余 4 个链接文字瞬间全部标红。因为它们都持有 `class` 这个属性。

### 2.2 属性值完全等值匹配——`[attr="val"]`

语法形式：

```css
E[attr="val"] {
    /* 样式规则 */
}
```

- **匹配机理**：**绝对精准匹配**。要求元素的属性值必须与 `val` **一模一样、完完全全相等**，多一个字母、少一个空格、大小写不一致都绝对不匹配。
- **生动比喻**：“实名制精准对号入座，差一个标点符号都不认！”

#### 代码实战：

```css
/* 只有 class 完全等于 "font" 的链接才会被选中 */
a[class="font"] {
    color: red;
}
```

> **效果**：在刚才的 5 个链接中，只有第 2 个链接被精准命中！第 3 个 `font14` 和第 4 个 `font16` 虽然包含 `font`，但因不是绝对相等，全部被无情过滤。

### 2.3 前缀匹配——`[attr^="val"]`

语法形式：

```css
E[attr^="val"] {
    /* 样式规则 */
}
```

- **符号记忆**：**`^` 是正则表达式中极其经典的“行首/开头”定位符**。
- **匹配机理**：匹配属性值以 `val` **作为开头的元素**。不管后面跟着什么后缀，只要开头对得上，全部入选！

#### 代码实战：

```css
/* 选取所有 class 以 "font" 开头的 a 标签 */
a[class^="font"] {
    color: red;
}
```

> **推导分析**：
> - `class="font"`：以 `font` 开头，命中；
> - `class="font14"`：以 `font` 开头，命中；
> - `class="font16"`：以 `font` 开头，命中；
> - `class="font-bold"`：以 `font` 开头，命中。
> 第 2、3、4、5 个链接全数被选中！

### 2.4 后缀匹配——`[attr$="val"]`

语法形式：

```css
E[attr$="val"] {
    /* 样式规则 */
}
```

- **符号记忆**：**`$` 是正则表达式中经典的“行尾/结尾”标识符**（可以联想美元符号收尾）。
- **匹配机理**：匹配属性值以 `val` **作为结尾的元素**。

#### 关键避坑指南（粉哥独家提醒）：

很多同学在写后缀匹配时容易想当然地写：

```css
/* 错误示范：在 CSS 中类名不能以纯数字裸露命名或直接进行非规范匹配 */
a[class$="14"] { ... } /* 极易因类名非法或转义问题导致失效 */
```

在标准的 HTML/CSS 规范中，类名通常应当是语义化的英文或带有前缀的字符组。我们应该规范地定义为 `t14` 或 `size14`：

```html
<a href="#" class="font-t14">字号14</a>
```

```css
/* 正确写法：匹配以 "t14" 结尾的属性值 */
a[class$="t14"] {
    color: red;
}
```

### 2.5 包含匹配——`[attr*="val"]`

语法形式：

```css
E[attr*="val"] {
    /* 样式规则 */
}
```

- **符号记忆**：**`*`（星号）在计算机世界里永远代表通用通配符**。
- **匹配机理**：只要属性值中**包含 `val` 子字符串**（无论它在开头、结尾还是居中），该元素就会被无条件命中！

#### 与完全等值匹配的震撼对比：

```css
/* [1] 完全等值：要求整串完全等于 font */
a[class="font"] { ... }   /* 只能命中 class="font" 单一节点 */

/* [2] 包含匹配：只要含有 font 即可 */
a[class*="font"] { ... }  /* font、my-font、font14、icon-font-small 全部命中！ */
```

## 3. 属性选择器速查矩阵

| 选择器语法 | 符号含义 | 判定逻辑 | 匹配成功案例（针对 `class`） |
| :--- | :--- | :--- | :--- |
| `E[attr]` | 存在属性 | 包含该属性即可 | `class="box"`、`class="btn"` |
| `E[attr="val"]` | 完全相等 | 属性值完全等于 `val` | 仅 `class="val"` 能命中 |
| `E[attr^="val"]` | 开头匹配 | 属性值以 `val` 开头 | `class="val-box"`、`class="val12"` |
| `E[attr$="val"]` | 结尾匹配 | 属性值以 `val` 结尾 | `class="box-val"`、`class="btn_val"` |
| `E[attr*="val"]` | 包含匹配 | 属性值中包含 `val` 字符串 | `class="my-val-item"`、`class="val"` |

## 4. 工业级三大落地实战案例

### 4.1 表单原生黑边框与高亮轮廓线的精准清除

在编写表单页面时，浏览器默认会在用户点击输入框时套上一圈黑黑的或者蓝色的轮廓线（`outline`），非常影响页面质感：

```html
<!-- 表单结构 -->
<form>
    <input type="text" placeholder="请输入用户名">
    <input type="password" placeholder="请输入密码">
    <input type="checkbox"> 记住我
    <input type="submit" value="登录">
</form>
```

如果我们直接写 `input { outline: none; }`，会把所有类型的 input 全局一刀切，甚至可能影响到某些提交按钮或复选框的无障碍焦点。

通过**并集选择器与属性选择器的绝妙配合**，我们可以做到手术刀般精准的局部治理：

```css
/* 仅针对单行文本框与密码框，精准清除原生外轮廓线与设置统一边框 */
input[type="text"],
input[type="password"] {
    outline: none;             /* 拔除点击时的黑蓝轮廓线 */
    border: 1px solid #e0e0e0; /* 换上优雅的一像素浅灰边框 */
    height: 36px;
    padding: 0 10px;
    border-radius: 4px;
}
```

### 4.2 阿里矢量图标库（IconFont）的统一初始化

在大型项目中，我们会用到上百个小图标（如搜索、购物车、用户、返回）。如果你看过阿里巴巴矢量图标库生成的 CSS 源码，你会惊奇地发现它的初始化规则正是利用了包含属性选择器：

```css
/* 无论你用的是 icon-user, icon-cart 还是 icon-search，一行全部搞定！ */
[class*="icon-"] {
    font-family: "iconfont" !important;
    font-size: 16px;
    font-style: normal;
    -webkit-font-smoothing: antialiased;
}
```

> **架构优势**：再也不需要每个图标写一遍 `font-family`，只要你的类名里包含 `icon-`，图标字体环境就会自动就绪！

### 4.3 国际化多语言（i18n）自适应排版

在支持多国语言的全球化产品中（如出海电商或国际版官网），不同国家的文字在视觉审美上的字体偏好截然不同：中文偏好“微软雅黑 / 苹方”，英文偏好“Arial / Helvetica”，而日语偏好“游黑体 / Meiryo”。

前端工程师可以直接利用 HTML 的 `lang` 属性进行全局自动化字体注入：

```html
<html lang="en"> <!-- 当前为英文环境 -->
```

```css
/* 自动侦测语言属性，无缝切换最适配的字体族！ */
[lang="en"] {
    font-family: Arial, Helvetica, sans-serif;
}

[lang="ja"] {
    font-family: "Meiryo", "Yu Gothic", sans-serif;
}

[lang="zh-CN"] {
    font-family: "PingFang SC", "Microsoft YaHei", sans-serif;
}
```

这就是属性选择器的魅力所在——**以最少的代码，最轻的侵入性，撬动最强大的样式匹配能力**！
