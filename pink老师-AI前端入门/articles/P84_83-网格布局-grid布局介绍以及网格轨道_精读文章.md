# 二维网格体系与轨道几何：CSS Grid 核心概念与基础轨道划分精解

我们在前面的课程中，已经非常深入地学习了 Flex 弹性盒布局。

Flex 布局好不好用？非常好用！在处理单行导航栏、两端对齐、水平垂直居中等场景时，Flex 堪称神器。

但是，不知道同学们还记不记得，当年我们带着大家用 Flex 做京东和淘宝的商品列表、做多行多列且带响应式的卡片墙时，过程有多么折腾：

当时我就跟同学们说过：“大家别急，那是当年我们还年轻！后面我们会学习一种专门用来搞定多行多列、真正划时代的布局利器——**Grid 网格布局**！”

从这一讲开始，我们就正式跨入现代 CSS 最强大的二维排版世界！

## 1. Grid 布局的本质：二维排版与技术选型定位

### 1.1 一维布局（Flexbox）与二维布局（Grid）的物理模型对比

> **定义**：CSS Grid（网格布局），是一种将网页容器划分为由“行（Row）”与“列（Column）”构成的二维网格系统的排版模型。开发者可以通过行与列的精准坐标，直接控制子元素在页面中的位置与占据尺寸。

我们先来把 Grid 和前面学过的 Flex 做一个本质层面的对比：

```text
一维布局 (Flexbox) 与 二维布局 (Grid) 拓扑形态对比

【Flexbox：一维线性流】
主轴方向单一（只能沿 X 轴或 Y 轴线性排布）：
┌────────┬────────┬────────┐
│ Item 1 │ Item 2 │ Item 3 │  ───> 沿单一主轴排布
└────────┴────────┴────────┘
换行后形成独立行，各行内部的子项尺寸彼此独立，无法跨行严格对齐列网格。

【Grid：二维正交网格】
行轴与列轴双向强约束（同时控制水平与垂直空间）：
      列轨道 1   列轨道 2   列轨道 3
    ┌──────────┬──────────┬──────────┐
行 1 │ 单元格   │ 单元格   │ 单元格   │
    ├──────────┼──────────┼──────────┤
行 2 │ 单元格   │ 单元格   │ 单元格   │
    ├──────────┼──────────┼──────────┤
行 3 │ 单元格   │ 单元格   │ 单元格   │
    └──────────┴──────────┴──────────┘
所有的子项都受控于全局正交的网格骨架，纵横对齐绝对严丝合缝！
```
*图 1：Flexbox 线性排布与 Grid 正交网格结构对比*

Flex 属于**一维布局**（One-Dimensional Layout）。它在处理元素时，只能沿着某一条主轴进行排列。即便你设置了换行，每一行实际上都是一个独立的弹性容器，第二行的元素根本感知不到第一行元素对应的上下边界。

而 Grid 是真正意义上的**二维布局**（Two-Dimensional Layout）。它允许我们同时在水平方向（列）和垂直方向（行）绘制网格。子元素被精准安置在行列交叉形成的“网格单元”之中。

### 1.2 淘汰论辨析：Flex 与 Grid 的工业级选型法则

讲到这里，很多同学脑子里冒出的第一个疑问就是：“老师，既然 Grid 这么强大，它是不是要把 Flex 给彻底淘汰掉了？”

答案非常明确：**绝对不是！**

在现代商业级 Web 项目中，成熟的架构永远是 **Flex 与 Grid 协同混用、各取所长**：

```text
现代前端工业级页面排版分工模型

┌──────────────────────────────────────────────────────────┐
│ 页面顶层大骨架（Grid 掌舵）                              │
│ ┌──────────────────────────────────────────────────────┐ │
│ │ 顶部 Header (内部分为：Logo / 搜索框 / 用户头像)      │ │
│ │ └─> 单行水平对齐，直接使用 Flexbox！                 │ │
│ ├───────────────────────┬──────────────────────────────┤ │
│ │ 侧边栏 Aside          │ 主内容区 Main                │ │
│ │                       │ ┌──────┬──────┬──────┬──────┐ │ │
│ │                       │ │ 卡片 │ 卡片 │ 卡片 │ 卡片 │ │ │
│ │                       │ ├──────┼──────┼──────┼──────┤ │ │
│ │                       │ │ 卡片 │ 卡片 │ 卡片 │ 卡片 │ │ │
│ │                       │ └──────┴──────┴──────┴──────┘ │ │
│ │                       │ └─> 多行多列卡片墙，使用 Grid│ │
│ └───────────────────────┴──────────────────────────────┘ │
└──────────────────────────────────────────────────────────┘
```
*图 2：外层骨架多行多列使用 Grid、局部内层单行排布使用 Flexbox 的混合架构*

我们来看真实的商业级案例：
- **哔哩哔哩（B 站）首页**：页面顶部的导航模块，左边是频道标签、中间是搜索框、右边是大会员和投稿按钮，这种典型的单行居中或两端对齐，官方直接采用 Flex 布局；而往下看，视频推荐流的多行多列卡片墙，乃至首屏的大图轮播与右侧小图推荐矩阵，B 站官方全部采用 Grid 布局来实现！
- **蔚来汽车（NIO）官网**、**阿里巴巴矢量图标库（Iconfont）**：这些高度追求视觉统一与响应式折叠的现代化站点，商品展示墙无一例外都是 Grid 网格布局的天下。

我们把两者的技术选型界限总结为一张清单：

| 选型评估维度 | Flexbox 弹性盒布局 | Grid 网格布局 |
| :--- | :--- | :--- |
| **空间维度** | 一维空间（单行或单列线性排列） | 二维空间（行与列同时受控） |
| **排版驱动方式** | **内容驱动**（Content-First）：由子项内容撑开尺寸，灵活分配 | **骨架驱动**（Layout-First）：先规划好网格轨道，再向单元格注入内容 |
| **跨行跨列能力** | 跨行极难对齐，无法轻松实现某个子项横跨两行两列 | 具备极其强大的单元格合并能力（跨行、跨列原生支持） |
| **黄金应用场景** | 导航栏菜单、表单输入框与按钮横排、弹窗居中、标签栏 | 电商商品墙、多媒体瀑布卡片流、仪表盘（Dashboard）、报表排版 |

> **核心结论**：**单行单列找 Flex，多行多列找 Grid！** 两者绝非替代关系，而是现代前端开发者必须双修的双子星。

## 2. 网格布局的核心术语与抽象结构

网格布局就像盖高楼，先要搭建好钢筋混凝土框架，再往房间里搬家具。在动手写 CSS 之前，必须先吃透这几个底层核心概念：

```text
Grid 布局四大核心物理结构示意图

   网格线 1       网格线 2       网格线 3       网格线 4
      │              │              │              │
      ▼              ▼              ▼              ▼
──1── ┌──────────────┬──────────────┬──────────────┐
      │              │              │              │ ◄── 行轨道 1
      │   单元格 1   │   单元格 2   │   单元格 3   │
──2── ├──────────────┼──────────────┼──────────────┤
      │              │  [网格项目]  │              │ ◄── 行轨道 2
      │   单元格 4   │   Item 5     │   单元格 6   │
──3── ├──────────────┼──────────────┼──────────────┤
      │              │              │              │ ◄── 行轨道 3
      │   单元格 7   │   单元格 8   │   单元格 9   │
──4── └──────────────┴──────────────┴──────────────┘
      ▲              ▲              ▲
      │              │              │
    列轨道 1        列轨道 2       列轨道 3
```
*图 3：网格容器、行/列轨道、网格线与网格项目拓扑结构图*

1. **网格容器（Grid Container）**：
   应用了 `display: grid` 或 `display: inline-grid` 的最外层父元素。它是所有网格体系的宿主，负责划定网格轨道的整体尺寸和对齐方式；
2. **网格项目（Grid Item）**：
   网格容器的**直接子元素**（Direct Children）。这些子元素就像一个个住户，会被自动或手动塞进网格单元格中；
   > **注意**：只有直接子代才是 Grid Item，孙子代元素默认不属于网格项目，它们依旧遵循常规文档流（除非对子元素再次开启嵌套网格）。
3. **网格轨道（Grid Track）**：
   两条相邻网格线之间的空间。**水平方向的轨道叫做“行轨道（Row Track）”，垂直方向的轨道叫做“列轨道（Column Track）”**。它是我们在 CSS 中真正声明宽高的物理对象；
4. **网格单元格（Grid Cell）**：
   单行轨道与单列轨道交叉重叠出的最小矩形空间（例如上图中行 1 与列 1 围成的区域），也就是我们常说的“九宫格里的每一个格子”；
5. **网格线（Grid Line）**：
   划分轨道的虚拟分割线。如果有 $N$ 列，就会存在 $N+1$ 条垂直网格线；如果有 $M$ 行，就会存在 $M+1$ 条水平网格线。网格线在后续的单元格跨行跨列合并中起决定性作用。

## 3. 网格轨道的声明与基础代码实操

### 3.1 激活网格容器：`display: grid`

与 Flex 布局完全相同，使用 Grid 布局的第一步，是把父盒子声明为网格容器：

```css
/* 块级网格容器（最常用） */
.container {
  display: grid;
}

/* 行内网格容器（容器自身表现为行内块） */
.inline-container {
  display: inline-grid;
}
```

> **易错点**：给父容器设置了 `display: grid` 之后，页面**不会像 Flex 那样立刻把所有子元素排成一行**！
> 为什么？
> 因为当父容器开启 `display: flex` 时，默认主轴是水平从左向右（`flex-direction: row`），所有子元素被强行挤进单行；
> 而开启 `display: grid` 时，浏览器默认只创建了 **1 条列轨道**，因此子元素依然遵循块级垂直流，自上而下竖向排列，并且宽度默认占满容器。

### 3.2 显式轨道划分：`grid-template-columns` 与 `grid-template-rows`

想要让网格真正成型，我们必须在容器中画好网格轨道。这就要依靠 Grid 最核心的一对属性：

```css
/* 声明列轨道：决定网格有多少列，以及每列的宽度 */
grid-template-columns: <轨道尺寸1> <轨道尺寸2> ... <轨道尺寸N>;

/* 声明行轨道：决定网格有多少行，以及每行的高度 */
grid-template-rows: <轨道尺寸1> <轨道尺寸2> ... <轨道尺寸N>;
```

> **轨道数量判定铁律**：**属性值后面写了几个参数（以空格隔开），就代表创建了几条轨道！参数的具体数值，就是该轨道的物理尺寸。**

#### 案例 1：构建一个标准的 300px × 300px 九宫格

我们现在通过一段最严谨的原生代码，在浏览器中实操画出一个三行三列的标准九宫格：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>CSS Grid 九宫格基础演示</title>
  <style>
    /* 1. 父容器（网格容器） */
    .box {
      width: 300px;
      height: 300px;
      border: 2px solid #333;
      margin: 50px auto;

      /* 开启网格布局 */
      display: grid;

      /* 创建 3 条列轨道，每列宽 100px */
      grid-template-columns: 100px 100px 100px;

      /* 创建 3 条行轨道，每行高 100px */
      grid-template-rows: 100px 100px 100px;
    }

    /* 2. 子元素（网格项目） */
    .box div {
      background-color: #ffb6c1;
      border: 1px solid #fff;
      font-size: 20px;
      font-weight: bold;
      color: #333;

      /* 便于观察文字：使用 flex 让数字在单元格中居中 */
      display: flex;
      justify-content: center;
      align-items: center;
    }
  </style>
</head>
<body>
  <div class="box">
    <div>1</div>
    <div>2</div>
    <div>3</div>
    <div>4</div>
    <div>5</div>
    <div>6</div>
    <div>7</div>
    <div>8</div>
    <div>9</div>
  </div>
</body>
</html>
```

代码逻辑解析：
1. `grid-template-columns: 100px 100px 100px;`：我们在属性后传入了 3 个 `100px`，用空格隔开。浏览器立即在垂直方向切出 3 条宽度为 100px 的列轨道；
2. `grid-template-rows: 100px 100px 100px;`：同理，水平方向切出 3 条高度为 100px 的行轨道；
3. 子元素排列规则：9 个 `<div>` 子元素无需声明浮动或宽度，浏览器会默认按照“先行后列”的顺序，从第 1 行第 1 列开始，依次自动填入 1 到 9 号单元格；
4. 尺寸拉伸机制：子元素 `div` 并没有指定固定宽高，但你会发现它们每个都严丝合缝地占满了对应的 $100\text{px} \times 100\text{px}$ 单元格，这就是网格项目的默认自适应特性。

## 4. 轨道在容器内的分布对齐（对齐与留白管理）

在实际页面布局中，经常会遇到这样一种物理状态：**网格轨道所占据的总尺寸，小于外层网格容器的整体尺寸**。

比如，我们的父容器宽度是 `320px`，但声明的 3 列轨道加起来是 $100\text{px} \times 3 = 300\text{px}$，此时容器右侧就会多出整整 `20px` 的多余空白。

怎样让这些网格轨道在容器内部优雅地分布？比如像 Flex 那样实现“两端对齐”或“居中对齐”？

Grid 直接复用了我们非常熟悉的两个对齐属性，但注意——**这里对齐的是“整个网格轨道”，而不是子元素里面的文字**！

### 4.1 列轨道的水平分布：`justify-content`

`justify-content` 控制的是**所有列轨道在容器水平方向上的空间分配方式**：

```css
.box {
  display: grid;
  grid-template-columns: 100px 100px 100px;
  /* 列轨道在水平方向两端对齐 */
  justify-content: space-between;
}
```

常用取值及其行为模型：
- `start`（默认值）：所有列轨道靠左紧密对齐，多余空白留在右侧；
- `end`：所有列轨道靠右对齐，多余空白留在左侧；
- `center`：所有列轨道打包居中，空白均匀分配在容器两侧；
- `space-between`：两端对齐。第一列紧贴左边缘，最后一列紧贴右边缘，剩余空间均匀切分作为列与列之间的间隙；
- `space-around`：每个列轨道两侧分配均等边距，两端留白是中间间距的一半；
- `space-evenly`：所有列轨道之间以及与容器边框之间的距离完全相等。

### 4.2 行轨道的垂直分布：`align-content`

`align-content` 控制的是**所有行轨道在容器垂直高度方向上的空间分配方式**：

```css
.box {
  display: grid;
  grid-template-rows: 100px 100px 100px;
  /* 行轨道在垂直方向两端对齐 */
  align-content: space-between;
}
```

其取值规则与 `justify-content` 完全一致（`start`, `end`, `center`, `space-between`, `space-around`, `space-evenly`），专门用于解决容器高度大于行轨道总高度时的纵向留白排版。

## 5. 商业实战推导：淘宝商品卡片流（动态行数模式）

学完上述基础语法，有的同学立刻就会抛出一个极其尖锐的工程问题：
“老师，九宫格固定 9 个盒子，所以我写了 3 行 3 列。但在真实的淘宝、京东项目里，后台返回的商品数据可能一会儿是 10 个，一会儿是 20 个，甚至上百个！
我怎么可能提前知道会有多少行？我的 `grid-template-rows` 到底该怎么写？”

这是一个极高水平的疑问。接下来我们推导出一种在商业开发中极其核心的排版范式：**固定列轨道，释放行轨道（动态行模式）**！

### 5.1 业务诉求与设计方案

假设我们要仿照淘宝首页构建一个“热门推荐”卡片墙：
1. 页面版心宽度为 `1000px`，要求横向严格划分为 **6 列**；
2. 商品数量由后端接口动态返回，行数完全不固定；
3. 每个商品卡片的高度由内容自然撑开，或者给子元素统一设置固定高度。

针对这种业务，我们的策略非常优雅：
> **核心推导**：**在容器上仅显式声明列轨道 `grid-template-columns`，坚决不写 `grid-template-rows`！**
> 当未定义行轨道时，Grid 引擎会自动开启“隐式轨道（Implicit Grid）”机制：只要子元素超出了当前行的承载上限，浏览器就会自动创建新行，新行的高度将完全由子元素的高度自动撑起！

### 5.2 淘宝多行多列实操完整代码

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>仿淘宝多行多列商品瀑布流</title>
  <style>
    /* 容器：版心宽度 1000px，水平居中 */
    .content {
      width: 1000px;
      margin: 30px auto;
      border: 1px solid red;

      /* 1. 开启网格布局 */
      display: grid;

      /* 2. 严格指定 6 列轨道（每列宽 160px，共 960px） */
      grid-template-columns: 160px 160px 160px 160px 160px 160px;

      /* 3. 剩余 40px 空白两端对齐，列之间自然生成等分缝隙 */
      justify-content: space-between;

      /* 4. 注意：此处绝不声明 grid-template-rows！行数由子元素无限向下自然延伸 */
    }

    /* 子项目：商品卡片 */
    .content div {
      height: 130px;
      background-color: #ffc0cb;
      margin-bottom: 8px; /* 通过外边距拉开上下行间距 */

      /* 样式美化 */
      border-radius: 6px;
      display: flex;
      justify-content: center;
      align-items: center;
      font-size: 16px;
      font-weight: bold;
      color: #333;
    }
  </style>
</head>
<body>
  <div class="content">

    <div>商品 04</div>
    <div>商品 05</div>

    <div>商品 07</div>
    <div>商品 08</div>
    <div>商品 09</div>
    <div>商品 10</div>
```

### 5.3 运行结果与原声验证

打开浏览器观察效果：
1. **自动排版**：前 6 个子元素排在第 1 行，第 7 个子元素自动折入第 2 行，第 13 个子元素折入第 3 行……无论你在 HTML 中粘贴 20 个、50 个还是 100 个子盒子，它们都会严格沿着这 6 条列轨道整齐排布；
2. **两端对齐生效**：由于设置了 `justify-content: space-between;`，总宽 960px 的 6 条列轨道完美贴合容器左右两端，中间自动生出了 5 处均等的呼吸留白；
3. **摆脱 Flex 束缚**：回想用 Flex 实现同样效果时，我们必须给子元素计算精确的百分比、计算 margin 的负值偏移、处理换行后的间距……而在 Grid 面前，仅仅两三行核心代码，复杂的商业多行多列排版便直接告破！

## 本讲核心回顾与思维导图

```text
网格布局起步思维导图

CSS Grid 基础
 ├── 核心定位：二维网格系统（正交行列双轴强约束），适合多行多列多卡片墙
 ├── 容器激活：display: grid (块级) / display: inline-grid (行内)
 ├── 轨道声明：
 │    ├── 列轨道：grid-template-columns (参数个数=列数，数值=列宽)
 │    └── 行轨道：grid-template-rows (参数个数=行数，数值=行高)
 ├── 轨道分布：
 │    ├── justify-content：列轨道水平分布 (start / end / center / space-between 等)
 │    └── align-content：行轨道垂直分布
 └── 商业法则：固定列数、不写行轨道，借助隐式网格实现无限商品流排版
```
