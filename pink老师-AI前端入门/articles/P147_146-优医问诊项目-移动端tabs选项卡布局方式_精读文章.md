# 移动端 Tabs 选项卡的三种布局方式

上一讲我们把 `.tabs-head` 的骨架搭出来了，一排 `a` 往那一放，问题马上就来了：在 375 宽的设计稿里塞五六个科室还行，塞十几个怎么办？挤成一团还是能滑？你们做移动端选项卡，逃不过这道选择题。我这一讲就把三种做法一次讲透，你们以后看到任何 App 的横向选项卡，都能一眼看穿它用的是哪一套。

## 1. 三种布局方式的对比选型

先给结论，再讲写法。横向选项卡（Tabs）在移动端的布局就三种，你们按“数量固不固定”来选：

| 布局方式 | 核心写法 | 适用场景 | 短板 |
| :--- | :--- | :--- | :--- |
| 弹性均分 | 弹性盒子（Flexible Box，`display: flex`）+ 子项 `flex: 1` | 数量固定、一般 3～5 个，如“关注 / 推荐 / 儿科” | 数量一多就被压扁，字都叠在一起 |
| 定宽横向滚动 | 子项定宽 + 父级 `overflow-x: auto` | 数量不固定、 coupons 科室很多，需要左右滑动 | 要处理滚动条隐藏，低端机滑起来略生硬 |
| 等分加滚动兜底 | `flex` 均分打底，超出后允许滚动 | 又想均分好看、又怕以后加栏目 | 代码稍多，新手容易把两套属性写冲突 |

我们这个优医问诊的切换栏，科室数量是会长的，今天四个，明天可能八个，所以我直接选第二种：定宽加横向滚动。这也是你们以后最常用的移动端选项卡写法，记住它。

## 2. 定宽横向滚动的具体写法

思路一句话：父级不换行、允许横向滚动，子级定宽不收缩。字符画把这个关系画出来：

```text
视口 (375px, 只显示一部分)
+----------------------------------+
| [关注] [推荐] [儿科] [内科] | ...> |  -->  overflow-x: auto
+----------------------------------+
   子项 flex: none / width 固定, 不被压缩
```

读图说明：视口像一个小窗口，里边是一条长长的横向长条，手指左右滑看到更多栏目。

代码：

```html
<div class="tabs-head">
  <a class="active" href="#">关注</a>
  <a href="#">推荐</a>
  <a href="#">儿科</a>
  <a href="#">内科</a>
  <a href="#">外科</a>
  <a href="#">皮肤科</a>
</div>
```

```css
.tabs-head {
  display: flex;
  overflow-x: auto;
  padding: 0 11px;
  background-color: #fff;
}
.tabs-head a {
  flex: none;
  padding: 10px 8px;
  font-size: 14px;
  color: #333;
}
.tabs-head a.active {
  color: #16c2a3;
  font-weight: 700;
}
```

> **易错点**：只写 `display: flex` 不写 `flex: none`，子项会被弹性盒子强行压缩，六个栏目挤在一屏里，字全叠了。移动端横向滚动列表，子项一定要“不伸不缩”，这一条给我记住。

> **提示**：滚动条（Scrollbar）在手机模拟器里会露出来一条灰线，很丑。补一句隐藏滚动条的写法即可，标准写法配合私有前缀一起写，兼容性最稳：

```css
.tabs-head::-webkit-scrollbar {
  display: none;
}
.tabs-head {
  scrollbar-width: none;
}
```

## 3. 选中指示线的定位做法

光变颜色还不够，设计稿里选中项底下还有一条小绿线（Indicator）。做法也是固定的：给 `a` 加相对定位（Relative Position），用伪元素（Pseudo-element）`::after` 画线。

```css
.tabs-head a.active {
  position: relative;
}
.tabs-head a.active::after {
  content: "";
  position: absolute;
  left: 50%;
  bottom: 4px;
  width: 24px;
  height: 3px;
  background-color: #16c2a3;
  border-radius: 2px;
  transform: translateX(-50%);
}
```

你们看，`left: 50%` 配 `transform: translateX(-50%)`，这就是居中标线的万能公式，不管文字两个字还是三个字，线永远居中。千万不要用固定 `left: 10px` 去凑，换个栏目字数就歪了。

> **结论**：移动端选项卡先看数量。数量固定就均分，数量会长就定宽加滚动。我们这个项目用滚动方案，你们把 `flex: none`、`overflow-x: auto`、隐藏滚动条、伪元素指示线这四件套背下来，以后任何 App 的横滑导航都能直接默写。
