## 1. 什么是 HTML？从定义到本质机理

### 1.1 HTML 的官方定义与拆解

**HTML** 的全称是 **H**yper**T**ext **M**arkup **L**anguage，中文官方译名为**超文本标记语言**。我们把这个名字拆解开来，它的本质一目了然：

```text
HTML 超文本标记语言全景拆解：
├── 超文本 (HyperText)
│   ├── 超越了传统纯文本的限制：不仅能排版文字，更能容纳图片、音频、视频、超链接等丰富多媒体
│   └── 超级链接能力：可以通过链接从一个网页无缝跳转到全球任意一个网页
└── 标记语言 (Markup Language)
    ├── 由一系列带有特殊含义的“标记符号”（即尖括号标签）组成
    └── 核心使命：告诉浏览器当前这块内容到底是个标题、是个段落、还是一张图片
```

> **核心认知**：
> HTML 不是 C 语言、Java 或 Python 那种具有复杂算法逻辑、循环分支的“编程语言”，它是一门**标记语言**。
> 学习 HTML，本质上**没有任何高深的数学门槛，就是学习如何使用不同的“标签”来准确描述网页的各个构件**！

### 1.2 标记、标签与元素：一物多名

在开发文档和日常交流中，你会听到大家交替使用三个词汇：**标记（Markup）**、**标签（Tag）**、**元素（Element）**。
很多零基础同学常常被绕晕，其实它们指的就是同一回事：
- 就像大家在生活里叫我“pink 老师”，或者开玩笑叫我“刘德华”，不管叫什么，指向的都是我这个人；
- 在 HTML 里，带尖括号的标记叫 `<h1>` 标签，它连同里面的文字合在一起，也叫 `<h1>` 标题元素。大家在平时交流中不必纠结称谓，理解它就是网页构件即可。

### 1.3 大小写书写规范

在 HTML 标准规范中，标签对英文字母的大小写是**不敏感**的。也就是说，你写 `<H1>标题</H1>`、`<h1>标题</h1>`，甚至 `<h1 >标题</H1>`，浏览器都能正常解析渲染。

> **行业铁律告诫**：
> 虽然大写不报错，但现代前端开发规范（包括 W3C 官方标准及各大厂代码规范）**强制要求统一使用纯小写字母**（如 `<h1>`、`<p>`、`<div>`）！小写代码更加整洁、易读，能杜绝不必要的拼写隐患。

## 2. 标签的结构特征与分类规范

在 HTML 中，标签的外形极其鲜明：**永远由左尖括号 `<` 和右尖括号 `>` 包裹**。按照形态，它们被清晰地划分为两大家族。

### 2.1 双标签（Double Tags）——绝大多数主力

HTML 中 95% 以上的标签都是**双标签**。它由成对出现的两部分组成：
1. **开始标签（Opening Tag）**：如 `<h1>`，标志着该结构的起始；
2. **结束标签（Closing Tag）**：如 `</h1>`，在标签名称前带有一个**英文正斜杠 `/`**，标志着该结构的终结；
3. **标签内容（Content）**：包裹在开始标签与结束标签之间的文字或子元素。

```text
双标签标准解剖图：
    开始标签                 结束标签
    ┌──┴──┐                 ┌──┴──┐
    < h1  >  千古第一绝句登高  < / h1 >
    └──┬──┘  ───────┬───────  └──┬──┘
    左尖括号         内容      带有斜杠的闭合标签
```

> **pink 老师的生动比喻**：
> 双标签就像过日子，男男女女成双成对、有始有终，两个人一起把日子过得红红火火。只有被这两人前后“包裹”住的内容，才会享受到该标签所赋予的格式与语义！

### 2.2 单标签（Single Tags）——少数特例

有成双成对的，自然就有独来独往的“单身汉”。HTML 中有极少数特殊的标签不需要包裹文字内容，自身独立成型，称为**单标签**（也叫空元素 Empty Elements）：
- 典型代表：**`<hr>`**（Horizontal Rule，水平分隔线标签）；
- 单标签不需要配对的 `</hr>`，敲出来就能直接在页面上画出一条贯穿左右的横线；
- 单标签在整个 HTML 中屈指可数，一只手的手指头就能数得过来。后面遇到了我会单独提醒大家，其余没特殊说明的，一律默认是双标签！

### 2.3 综合小演练：搭建刘德华个人简况卡片

光看不练假把式。我们利用刚刚学到的知识，写一个简易的人物介绍卡片：

```html
<!-- 1. 一级标题：用 h1 双标签包裹 -->
<h1>影帝刘德华个人介绍</h1>

<!-- 2. 分隔横线：单身狗单标签 hr，独来独往，直接画出分割线 -->
<hr>

<!-- 3. 正文段落：用 p 双标签包裹 -->
<p>
  刘德华（Andy Lau），1961年9月出生于中国香港，华语影视男演员、歌手、制片人、作词人。
  大中华区影坛与乐坛的常青树，深受海内外华人观众的喜爱。
</p>
```

在 Trae 中保存后，右侧浏览器立刻呈现出结构分明的图景：顶上一行加粗特大的标题、中间一条清晰平整的细线、下方一段工整的叙述段落。
如果把这些标签全部去掉、裸写文字，页面就会变成黏糊糊的一团。**标签的本质，就是赋予内容准确的组织形态！**

## 3. HTML 文档标准骨架逐行全解剖

现在我们回过头来，认真审视在 Trae 中输入英文感叹号 `!` 所生成的那一整套默认骨架代码。每一行代码究竟是干什么的？为什么大厂网页都必须这么写？

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Document</title>
</head>
<body>

</body>
</html>
```

我们自顶向下逐行扒开它的核心机理：

### 3.1 `<!DOCTYPE html>`：文档类型声明

- **定义**：这不是 HTML 标签，而是一句**文档类型声明（Document Type Declaration）**；
- **核心作用**：郑重告知浏览器：“我当前编写的这份网页，是严格按照最新的 **HTML5** 标准规范来书写的，请用你最标准、最先进的现代渲染管线来解析呈现，绝不要退回到老旧怪异模式！”；
- **历史渊源**：在古老的 HTML4 或 XHTML 时代，这行声明极其冗长、臭不可闻（带一长串 W3C 的 DTD 网址链接）；而到了 HTML5，大道至简，仅用 `<!DOCTYPE html>` 八个字符即成标准定式。不可遗漏，保持在文档第一行即可。

### 3.2 `<html lang="en">`：根元素与全局语言标识

- **根元素（Root Element）**：`<html>` 是整张网页中层级最高、体积最大的最外层标签。所有的头部、身体、脚本、样式，**都必须且只能被包裹在 `<html>` 与 `</html>` 之间**；
- **`lang` 属性**：`lang` 即 language（语言）。它告诉浏览器和搜索引擎，当前网页的主要语种是什么：
  - 默认生成的 `lang="en"` 代表英文（English）；
  - 如果你做的是中文网站，**强烈建议手动修改为 `lang="zh-CN"`**（代表中华人民共和国简体中文）。
  - **为什么修改？** 如果页面大量是中文，却顶着 `lang="en"` 的标识，Chrome 浏览器常常会弹出一个烦人的弹窗：“检测到英文页面，是否为您翻译成中文？”；改成 `zh-CN` 就能彻底避免该误判，并且能辅助国内百度、搜狗等搜索引擎更好地抓取与收录页面（参考 Bilibili、京东官网的源代码，全部配置为 `lang="zh-CN"`）。

### 3.3 `<head>`：头部元素（元数据控制中心）

- **头部元素**：`<head>` 标签中包裹的内容，是整张网页的“脑垂体”和“幕后中枢”，它承载的是**网页的元数据（Metadata）**；
- **显示特性**：**写在 `<head>` 里面的绝大多数标签内容，都不会直接在浏览器网页可视白色区域中显示出来**。它们主要是给浏览器内核、搜索引擎爬虫、解析机器人等机器程序读取的。

#### 3.3.1 `<meta charset="UTF-8">`：字符编码集（防乱码护身符）
- **属性拆解**：`char` 是字符（Character），`set` 是集合，合起来叫**字符编码集**；
- **UTF-8 的威力**：UTF-8 是目前全球互联网通用的万国码标准，它囊括了全球几乎所有国家和民族的语言字符（中文、日文、韩文、英文、希腊文、数学符号等）；
- **避坑预警**：如果不写这一行，一旦浏览器采用了不同的本地字符集（如 GBK 或 ISO-8859-1）来解码中文，网页上就会瞬间暴露出满屏类似“æ–‡å­—ä¹±ç 码”的天书乱码！**这一行是绝对不可删除的核心配置。**

#### 3.3.2 `<meta name="viewport" content="...">`：移动端视口适配
- 这是专为智能手机、平板等移动设备量身定制的视口标签；
- 它强制将移动端网页的视口宽度与设备的物理屏幕宽度保持 1:1 等宽映射，防止手机浏览器默认将 PC 端大页面强行缩成蚂蚁字。我们在第六篇移动端专栏中会深度展开，初学阶段默认保留即可。

#### 3.3.3 `<title>Document</title>`：网页选项卡标题
- 这是 `<head>` 中唯一一个具有直观“视觉呈现”的标签；
- **呈现位置**：它不会出现在网页正文里，而是**直接呈现在 Chrome 浏览器最顶部的选项卡标签页上**！
- **实战验证**：把 `Document` 修改为“黑马程序员官方网站”，按下 `Ctrl + S` 保存，看浏览器标签页，立刻变为了对应的汉字标题。在搜索引擎检索结果中，展示给用户的那个可点击的蓝色大标题，也是由此标签提取的。

### 3.4 `<body>`：网页的主体躯干

- 如果说 `<head>` 是幕后运筹帷幄的参谋，`<body>` 就是台前冲锋陷阵的将军；
- **唯一准则**：**我们希望用户在浏览器页面中肉眼看到的一切内容**——所有的标题、文字、图片、超链接、表格、表单、视频、音频，**全部必须写在 `<body>` 与 `</body>` 之间**！

## 4. 小猪佩奇（Peppa Pig）人体拓扑结构模型

为了让大家建立起牢不可破的骨架空间感知，我自创了一套**“小猪佩奇（人体）解剖模型”**。大家只要记住这只小猪，这一辈子都不可能把 HTML 骨架写错：

```text
HTML 文档骨架与小猪佩奇结构对照图：
=============================================================================
  <!DOCTYPE html>                (标准出厂说明书，声明这只小猪符合 2025 规范)
-----------------------------------------------------------------------------
  <html lang="zh-CN">            (整只小猪佩奇的完整形态，统揽全局)
  │
  ├── <head>                     (小猪佩奇的头部：负责思想、参数与元数据)
  │   │
  │   ├── <meta ...>             (大脑内部神经：UTF-8 字符集与视口规则，外部不可见)
  │   └── <title>黑马官网</title> (小猪的眼睛：长在最头顶，朝外看着浏览器的标签栏！)
  │
  └── <body>                     (小猪佩奇的身体躯干：所有的血肉实质内容都在这里)
      │
      ├── <h1>标题文字</h1>      (身体上的衣服与装饰)
      ├── <p>段落内容</p>        (身体上的肌肉与器官)
      └── <img src="..."/>       (身体佩戴的手表与配饰)
=============================================================================
```
*图 1：HTML 骨架与小猪佩奇解剖模型映射拓扑*

> **严重易错点告诫**：
> 有很多同学粗心大意，把一篇文章的正文段落、大图片写到了 `<head>` 标签里面！
> 按照我们的模型，你这就是**把心肝脾肺肾硬生生塞进了小猪的脑壳子里**，不仅结构彻底错乱，还会引发浏览器解析异常和 SEO 严重惩罚。
> 记住口诀：**元数据进 head，肉眼内容全进 body！**

## 5. 本讲小结与助教猪爸爸复盘

学到这里，大家对 HTML 的骨骼体系已经有了全面透彻的认知。我们继续请出助教“猪爸爸”，梳理本讲的三大灵魂拷问：

1. **第一问：什么是 HTML？它的核心是学什么？**
   - 答：超文本标记语言。它不是逻辑编程语言，核心就是掌握各种各样语义标签的含义与用法。
2. **第二问：双标签与单标签的核心区别是什么？**
   - 答：双标签成对出现，有开始、有结束（带正斜杠 `/`）、包裹内容（如 `<h1>`、`<p>`）；单标签独来独往，不需要结束标签，用于独立效果（如水平线 `<hr>`）。
3. **第三问：HTML 骨架由哪些核心部件构成？各管什么？**
   - 答：`<!DOCTYPE html>` 声明标准规范；`<html>` 是根元素；`<head>` 管元数据（`meta charset="UTF-8"` 防乱码，`<title>` 负责标签页标题）；`<body>` 管页面所有的实际可视内容。
