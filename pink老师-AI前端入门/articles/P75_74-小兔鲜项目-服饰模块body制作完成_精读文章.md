## 1. 主体双栏架构划分与 Flex 布局策略

### 1.1 左右两大区块的 HTML 语义选型

观察设计稿，主体内容横向明显切分为左右两大部分：
1. **左侧大图推荐展位**：点击后直接跳转至特定品牌或活动专题页，因此最优雅的结构是一个独立的超链接 `<a>`，内部嵌套一张图片，赋予类名 `.body-left`；
2. **右侧商品卡片列表**：由 8 个具有相同结构与样式的商品卡片组成，因此语义上应当使用无序列表 `<ul>`，赋予类名 `.body-right`，内部容纳 8 个 `<li>` 列表项。

```html
<!-- 服饰模块主体开始制作 -->
<div class="body">
  <!-- 左侧大卡片：整卡可跳转 -->
  <a href="#" class="body-left">
    <img src="./uploads/clothes-left.png" alt="服饰精选推荐">
  </a>
  <!-- 右侧 8 个商品小卡片列表 -->
  <ul class="body-right">
    <!-- 后续填充 8 个 li -->
  </ul>
</div>
```

### 1.2 外层容器的两端对齐与尺寸设定

为了让左边的大海报紧贴左侧，右边的商品列表紧贴右侧，我们给父级容器 `.body` 开启 Flex 布局，并声明两端贴边分散对齐：

```css
/* 服饰主体外层容器 */
.clothes .body {
  display: flex;
  justify-content: space-between;
}
```

这里不需要硬编码 `.body` 的宽度，因为它处在 `.clothes.w` 版心内部，默认继承了版心满宽 `1240px`。

### 1.3 Flex 项目的尺寸声明新特性：`a` 标签免转块特性

在设计稿中测得：左侧大盒子的物理宽度为 **`248px`**，高度为 **`610px`**。

很多细心的同学立刻举手发问：
“pink 老师，左边的盒子是一个超链接 `<a>`，属于行内元素，前面不是刚讲过行内元素不能直接写 `width` 和 `height` 吗？这里为什么不需要加 `display: block;` 也能直接生效？”

这是一个极其关键的高频考点：
> **核心定理：Flex 项目自动块级化（Flex Items Blockification）**：
> 一旦一个父元素声明了 `display: flex;`，其所有的**直接子元素**都会自动变成 **Flex 项目（Flex Item）**。在 CSS 规范中，处于 Flex 项目上下文中的行内元素（如 `<a>`、`<span>` 等），其表现形式等同于块级元素，可以直接设置 `width`、`height`、`padding` 以及 `margin`，完全无需手动书写 `display: block`！

因此，左侧样式极其简洁干脆：
```css
/* 左侧大图展位：作为 flex 项目直接拥有尺寸 */
.clothes .body .body-left {
  width: 248px;
  height: 610px;
}

.clothes .body .body-left img {
  width: 100%;
  height: 100%;
}
```

## 2. 右侧商品网格的尺寸推导与 `flex-wrap` 自动换行

### 2.1 网格尺寸精确数学验算

右侧整体容器由 8 个商品卡片构成，呈 2 行 4 列分布。在动手写样式之前，我们必须先做一道精准的数学计算：
1. 单个商品卡片 `<li>` 的宽度经设计稿量取为 **`242px`**，高度为 **`305px`**；
2. 一行排布 4 个卡片，右侧总宽度：
   $$W_{\text{right}} = 242\text{px} \times 4 = 968\text{px}$$
3. 2 行卡片累计高度：
   $$H_{\text{right}} = 305\text{px} \times 2 = 610\text{px}$$
4. 左右两栏总宽度验算：
   $$W_{\text{total}} = 248\text{px} (\text{左侧}) + 968\text{px} (\text{右侧}) = 1216\text{px}$$
   加上左右两栏之间的自然间隙，完美贴合 `1240px` 全局版心！

```css
/* 右侧商品网格大容器 */
.clothes .body .body-right {
  width: 968px;
  height: 610px;
  /* 辅助背景色，调试完毕后移除 */
  /* background-color: pink; */
}
```

### 2.2 破解 Flex 默认单行挤压：`flex-wrap: wrap`

当我们在 `ul.body-right` 内部放置 8 个 `<li>` 时，如果不做任何特殊配置，直接开启 `display: flex;`，会发生什么？

浏览器中的所有 8 个卡片会被强行“塞进同一行”，每个盒子的实际宽度被硬生生挤扁到原来的二分之一！
因为在 Flex 规范中，默认属性值是 **`flex-wrap: nowrap;`（不换行）**。子项目宁可被压缩尺寸，也绝不跨到第二行。

为了让商品卡片按照每行 4 个自然折叠成两行，我们必须显式开启**多行折叠模式**：
```css
.clothes .body .body-right {
  display: flex;
  flex-wrap: wrap;
  width: 968px;
  height: 610px;
}
```
声明了 `flex-wrap: wrap;` 之后，前 4 个卡片刚好占满 `242px × 4 = 968px` 的第一行空间；第 5 个卡片排不下，浏览器会自动将其推入第二行首位，严丝合缝地排列成两排！

## 3. 单个商品卡片（`li`）的内部构建与内边距下沉居中技巧

### 3.1 卡片内部骨架设计

每个商品卡片不仅要好看，更要支持“整卡可点击”。因此在 `<li>` 内部，我们用一个超链接 `<a>` 将所有内容完整打包。
卡片垂直方向包含五个层级：
1. 商品主图：`<img>`（尺寸规格为 `200px × 180px`）；
2. 商品主标题：`<h3>` 或 `<h3 class="title">`（字号 `16px`，上外边距拉开呼吸感）；
3. 属性标签与尺码：`<p>`（文本说明，如“尺码 / 个性配饰”）；
4. 系列小标题：`<p>`（补充描述，如“新款服饰”）；
5. 商品价格：`<p class="price">`（醒目的主色调价格，前置人民币符号 `¥`）。

```html
<li>
  <a href="#">
    <!-- 1. 商品缩略图 -->
    <img src="./uploads/clothes-1.png" alt="商品预览">
    <!-- 2. 商品标题 -->
    <h3 class="title">男士透气网面轻便跑步鞋</h3>
    <!-- 3. 属性规格 -->
    <p>尺码齐全 / 柔软减震</p>
    <!-- 4. 系列归属 -->
    <p>新款运动服饰</p>
    <!-- 5. 销售价格 -->
    <p class="price"><small>¥</small>719.00</p>
  </a>
</li>
```

### 3.2 卡片内边距的精妙控制：图片自然居中与可点击边界

仔细观察设计稿：单个 `li` 的物理宽度是 `242px`，而内部展示的商品图片宽度是 `200px`。
这多出来的 `42px` 空间去了哪里？

设计稿给出了极为规范的处理：
- 上内边距：`padding-top: 10px;`（让内容与卡片顶边留出间距）；
- 左右内边距：各分 `21px`（即 `21px + 200px + 21px = 242px`）；
- 下内边距：`padding-bottom: 0;`。

```text
单体卡片盒模型与内边距分配图解
┌────────────────────────────────────────────────────────┐
│ li (总宽 242px, 总高 305px, box-sizing: border-box)     │
│  padding: 10px 21px 0;                                 │
│ ┌────────────────────────────────────────────────────┐ │
│ │ a (display: block; width: 100%; height: 100%;)     │ │
│ │ ┌────────────────────────────────────────────────┐ │ │
│ │ │ img (定宽 200px, 定高 180px, 自然居中)           │ │ │
│ │ └────────────────────────────────────────────────┘ │ │
│ │ h3.title (字号 16px, margin-top: 10px;)            │ │
│ │ p (规格属性, 行高 19px)                            │ │
│ │ p (新款描述, 行高 19px)                            │ │
│ │ p.price (字号 22px, 主题红, margin-top: 12px;)     │ │
│ └────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────┘
```
*图 2：单体卡片盒模型与内边距分配图解*

```css
/* 单个商品卡片盒子 */
.clothes .body-right li {
  width: 242px;
  height: 305px;
  padding: 10px 21px 0;
  /* 辅助背景色，观察尺寸，校验后移除 */
  /* background-color: skyblue; */
}
```

> **设计细节深度推导**：
> 为什么要给 `li` 设置内边距，而不是让内部的 `a` 或 `img` 去写 `margin: 0 auto;`？
> 1. **约束点击热区**：`li` 的内边距属于内容区之外的透明边缘，鼠标悬停在卡片最外围微小的缝隙时，不会误触发卡片下方的超链接响应；只有当光标进入实际的内容载体（`a` 标签）时，手型指针与点击交互才被激活；
> 2. **图片精准约束**：由于全局开启了 `box-sizing: border-box;`，`li` 内部的内容可用宽度正好被压缩至 `242 - 21 × 2 = 200px`，内部的图片直接充满可用宽度，天然居中，省去了给内部每样元素单独写居中对齐的繁琐操作。

### 3.3 内部 `a` 标签转块与图片尺寸限定

在 `li` 内部的 `a` 标签：
由于 `a` 是 `li` 的直接子元素，但 `li` **并不是 Flex 容器**（`li` 采用的是普通文档流布局），因此这里的 `a` 标签不能自动获得块级特性，必须显式声明 `display: block;` 才能撑满 `100%` 宽高！

```css
/* a 标签撑满整个卡片内容区 */
.clothes .body-right li a {
  display: block;
  width: 100%;
  height: 100%;
  text-align: left; /* 文本靠左排布 */
}

/* 严格限定图片物理边界，防止意外尺寸破坏布局 */
.clothes .body-right li img {
  width: 200px;
  height: 180px;
}
```

### 3.4 文本排版、行高与价格微调

卡片下方的文字信息排版要层次分明、张弛有度：
1. **标题样式**：
   使用 `<h3>` 保证语义层级，重置字号为 `16px`，并添加 `margin-top: 10px;` 让文字远离图片；
2. **描述文本**：
   中间两行描述段落字号保持 `14px`，将行高微调为 `19px`（`line-height: 19px;`），既不显得松散，也不会彼此粘连；文字颜色设置为次级灰（`#666` 或 `#999`）；
3. **价格样式**：
   价格是电商卡片的绝对主角。字号加大至 `22px`，颜色采用小兔鲜的标志性价格红（`#cf4444`），并增加 `margin-top: 12px;` 沉底展示；
   前面的货币符号 `¥` 用 `<small>` 标签包裹，重置字号为 `16px`，形成“符号小、数值大”的专业电商排版质感。

```css
/* 标题 */
.clothes .body-right li .title {
  margin-top: 10px;
  font-size: 16px;
  color: #333;
}

/* 描述文本行高微调 */
.clothes .body-right li p {
  line-height: 19px;
  font-size: 14px;
  color: #999;
}

/* 价格 */
.clothes .body-right li .price {
  margin-top: 12px;
  font-size: 22px;
  color: #cf4444;
}

/* 人民币符号缩小 */
.clothes .body-right li .price small {
  font-size: 16px;
}
```

## 4. 全局单行文本溢出省略工具类（`.ellipsis`）解耦

在实际商业开发中，商品标题的长度是不可控的——后台管理员录入的标题可能只有两三个字，也可能有三四十个字。如果遇到超长标题，文字会在卡片内自动折行，瞬间将整个卡片的高度撑高，导致右侧所有卡片严重错位乱套！

因此，商品标题必须具备**单行文本溢出显示省略号**的能力。

### 4.1 核心三件套原理复习

实现单行省略必须同时满足三个 CSS 属性，缺一不可：
1. `white-space: nowrap;`：强制文本在一行内显示，绝不自动折行；
2. `overflow: hidden;`：将超出父级盒子边界的内容全部截断隐藏；
3. `text-overflow: ellipsis;`：指示浏览器在被截断的文本末尾自动追加省略号（`...`）。

### 4.2 为什么必须提取为公共工具类？

在小兔鲜项目中，不仅服饰模块的商品标题需要省略号，生鲜模块、最新专题、导航菜单以及侧边栏列表都需要这个效果。
如果我们每一个选择器底下都重复抄写这三句代码，样式表将充斥着大量冗余代码，维护成本极高。

遵循现代前端 **DRY（Don't Repeat Yourself）** 原则，我们在全局公共样式表（`base.css` 或 `common.css`）的工具库区域，独立提取封装一个原子类名：

```css
/* ==========================================================================
   全局通用工具类：单行文本溢出省略号
   ========================================================================== */
.ellipsis {
  white-space: nowrap;
  overflow: hidden;
  text-overflow: ellipsis;
}
```

### 4.3 工具类在 HTML 中的多类名组合应用

在 HTML 模板中，任何需要防溢出保护的文本标签，直接追加该类名即可：

```html
<!-- 标题叠加 .ellipsis 原子类 -->
<h3 class="title ellipsis">男士透气网面轻便跑步鞋 超轻缓震专业马拉松训练鞋</h3>
```

无论是 8 个卡片还是后续的专题新闻，只要挂上 `.ellipsis`，文本超出部分便会自动优雅呈现为 `...`，再也无需担心版面被脏数据撑爆。

> **提示**：
> 在现阶段静态开发中，我们通过手动复制 8 个 `<li>` 并替换 `clothes-1.png` 到 `clothes-8.png` 完成版面拼装。到了 JavaScript 和 Vue/React 实战阶段，这一整块商品列表只需保留一个 `<li>` 作为模板，通过向后端接口发起异步请求获取 JSON 数据，使用一个 `v-for` 循环即可完成自动化渲染！
