在上一讲中，我们顺利完成了页面最顶部的快捷导航（`.shortcut`）模块。很多同学做完之后迫不及待地往下看，发现紧接着就是整个网站最显眼、最核心的面门——**Header 头部区域**。

从左侧醒目的品牌 Logo，到中间的分类导航栏，再到右侧的搜索框和购物车，这一整块区域把电商网站最关键的导购入口全部囊括在内。

```text
Header 头部大区四大功能盒子空间排布
┌─────────────────────────────────────────────────────────────────────────────┐
│ .header.w (1240px 居中, 高 132px, display: flex; space-between; center)      │
│ ┌──────────────┐ ┌────────────────────┐ ┌──────────────┐ ┌──────────────┐ │
│ │ 1. logo      │ │ 2. nav             │ │ 3. search    │ │ 4. cart      │ │
│ │ (200×88)     │ │ (分类主导航列表)   │ │ (搜索框容器) │ │ (购物车容器) │ │
│ └──────────────┘ └────────────────────┘ └──────────────┘ └──────────────┘ │
└─────────────────────────────────────────────────────────────────────────────┘
```
*图 1：小兔鲜首页 Header 头部大区四大功能盒子空间排布*

很多初学者看到这个区域，第一反应是：“不就是排排坐放几个标签嘛，随便丢几个 `div` 和 `img` 浮动或者弹性盒一下不就完了？”

绝非如此简单！尤其是最左侧小小的 Logo，在工业级大型商业网站中，绝不是直接丢一个 `<img>` 标签就能交差的。它的背后隐藏着极其严苛的 **SEO 搜索引擎权重优化**、**无障碍访问规范** 以及 **CSS 文本隐形技术**。

这一讲，我就带着大家先把 Header 大区的整体骨架搭建起来，再把 Logo 模块这一整套“大厂级标准制作套路”从头到尾彻底推导清楚。

## 1. Header 头部大区布局规划与盒模型测算

### 1.1 页面骨架定位与双类名 `.header.w` 设定

首先观察设计稿，Header 区域依然是小兔鲜首页的主体内容部分，因此它必须受到全站通用版心的约束：
1. **水平居中**：必须包裹版心类名 `.w`（全局宽度 `1240px`，并通过 `margin: 0 auto;` 保证页面在宽屏显示器下水平居中）；
2. **专属类名**：同时具有专属的结构类名 `.header`，用来承载头部特有的高度与弹性排版特性。

在设计稿上通过测量工具（快捷键 `F3` 辅助量取尺寸）可以精确测出：Header 大区的高度正好是 **`132px`**。

在 HTML 结构中，我们直接给外层容器赋予双类名：
```html
<!-- 头部区域制作 -->
<div class="header w">
  <!-- 四大子盒子 -->
</div>
```

在 CSS 中，我们在书写结构性样式时，养成良好的调试习惯——先给一个临时背景色（比如 `background-color: pink;`），直观观察盒子的高度与居中效果是否正确生效：

```css
/* 头部区域外层容器 */
.header {
  height: 132px;
  /* 辅助观察背景色，骨架校验完毕后移除 */
  /* background-color: pink; */
}
```

> **易错点**：
> 很多同学在写 CSS 选择器时，会写成 `.header .w`（中间带空格），这表示查找 `.header` 内部后代名为 `.w` 的子元素；而我们的 HTML 写法是 `<div class="header w">`，同一个标签同时拥有两个类名，如果要在选择器中同时指定，必须紧贴连写为 `.header.w`，或者直接分别写 `.header` 与 `.w`。我们在 `base.css` 中已经全局声明了 `.w { width: 1240px; margin: 0 auto; }`，因此在样式表中直接书写 `.header` 设定高度即可，双类名会自动叠加生效。

### 1.2 四大子盒子解构与 Flex 布局策略

剖析 Header 大区的内部构成，由左至右横向排列着四个并列子单元：
1. **品牌标识**：`.logo`（展示小兔鲜品牌图腾，兼具首页跳转与全站最高权重）；
2. **全局主导航**：`.nav`（展示各级分类导航链接，内部使用 `ul > li > a` 列表）；
3. **全局搜索模块**：`.search`（输入框及搜索触发按钮）；
4. **购物车模块**：`.cart`（购物车快捷入口及商品计数微标）。

既然这四个盒子水平排成一行，且左端靠齐 Logo、右端紧贴购物车，垂直方向又都处于盒子正中间，那么最优解必然是 **Flex 弹性盒布局**：

```text
Header 弹性容器主轴与交叉轴对齐推导
主轴方向（水平）：justify-content: space-between (首尾靠边，中间两盒子自动分配间隙)
交叉轴方向（垂直）：align-items: center (四个高矮不一的子盒子在 132px 高度内垂直居中)
┌────────────────────────────────────────────────────────────────────────┐
│ .header.w (display: flex; justify-content: space-between; align-items: center)
│                                                                        │
│  [ .logo ]          [ .nav ]              [ .search ]      [ .cart ]   │
│  ← 靠最左                                                    靠最右 →  │
└────────────────────────────────────────────────────────────────────────┘
```
*图 2：Header 弹性容器主轴与交叉轴对齐推导*

主轴采用 `justify-content: space-between;`，交叉轴采用 `align-items: center;`，我们不必去计算每个盒子之间复杂的内外边距，浏览器会自动平整地完成两端贴边与垂直对齐。

### 1.3 为什么 Search 与 Cart 必须使用独立容器？

很多同学可能会好奇：
“搜索框里面不就是一个 `<input>` 吗？购物车不就是一个超链接 `<a>` 吗？为什么非要给它们各自套一个 `<div class="search">` 和 `<div class="cart">` 呢？”

这里体现的是**架构前瞻性**：
- 在搜索框 `.search` 内部，除了输入框之外，右侧还有一个放大镜图标（字体图标）；
- 在购物车 `.cart` 内部，除了购物车图标和文字外，右上角还有一个红色的圆形气泡数字“2”（角标，用来动态展示加购数量）；
- 这两个小挂件在后续制作中，都需要依赖**绝对定位（`position: absolute`）**精准定死在各自的角落，而绝对定位必须依赖父级设置**相对定位（`position: relative`，即‘子绝父相’）**。

虽然我们这一讲还没有深入展开定位系统，但结构先行——必须提前为它们准备好独立的父级容器盒子，留待后续定位使用。

```html
<!-- Header 骨架结构初步搭建 -->
<div class="header w">
  <!-- 1. Logo 品牌区 -->
  <div class="logo">1</div>
  <!-- 2. 主导航区 -->
  <ul class="nav">2</ul>
  <!-- 3. 搜索框区域 -->
  <div class="search">3</div>
  <!-- 4. 购物车区域 -->
  <div class="cart">4</div>
</div>
```

```css
/* Header 弹性盒容器定义 */
.header {
  display: flex;
  justify-content: space-between;
  align-items: center;
  height: 132px;
}
```

保存并预览页面，你会看到 1、2、3、4 四个数字稳稳当当地在一行两端贴边分散排列，并且在 132 像素的高度内处于正中央。骨架搭建完毕，我们立刻进入本讲最关键的核心部分——**Logo 区域的深度打磨**。

## 2. 电商级 Logo 模块工程化规范与 SEO 深度解密

我们在设计稿中选中 Logo 测量其物理尺寸，尺寸为：**宽 `200px`，高 `88px`**。

如果仅仅为了“把图片显示出来”，新手通常会直接写：
```html
<!-- 业余初学者写法：极不推荐 -->
<div class="logo">
  <a href="index.html"><img src="./images/logo.png" alt="小兔鲜"></a>
</div>
```
这样写在视觉上没有任何破绽，但在正规大厂的前端评审中会被直接打回。为什么？因为商业站点的 Logo 承载着极其关键的 SEO 职责。

### 2.1 商业站点 Logo 的三大核心诉求

我们以淘宝网、京东等一线电商平台作为行业参照：打开淘宝网首页，按下 `F12` 审查其左上角 Logo 元素，你会惊讶地发现它的 DOM 结构如下：
- 外层是一个带有明确类名的容器；
- 紧接着嵌套了一个 `<h1>` 标签；
- `<h1>` 里面嵌套了一个超链接 `<a>`；
- `<a>` 标签里面书写了纯文本“淘宝网”；
- 页面上展示的不是 `<img>`，而是把图片作为 `<a>` 标签的 `background-image` 背景图引入；
- 并且表面上根本看不到文字“淘宝网”，文字被神奇地“藏”起来了！

```text
电商级 Logo 标准 DOM 树与样式分层
┌────────────────────────────────────────────────────────────┐
│ .logo (定宽 200px, 定高 88px)                              │
│ └── h1 (继承 100% 宽高, 赋予页面最高级别 SEO 权重)          │
│     └── a[href="index.html"][title="小兔鲜儿"]             │
│         ├── CSS: display: block; 宽高 100%                 │
│         ├── CSS: background: url(...) no-repeat; (展示图)   │
│         ├── CSS: text-indent: -9999px; overflow: hidden;   │
│         └── HTML: 纯文本 "小兔鲜儿" (供搜索引擎抓取)        │
└────────────────────────────────────────────────────────────┘
```
*图 3：电商级 Logo 标准 DOM 树与样式分层*

之所以采用如此繁复的套路，是为了完美兼顾三件事：
1. **提升全站搜索权重（SEO Optimization）**：
   `<h1>` 标签在 HTML 语义中代表页面中权重最高的一级标题。一个页面中通常**只能出现一次 `<h1>`**。搜索引擎爬虫（蜘蛛）抓取网页时，首先会关注 `<h1>` 里的内容。将全站最核心的品牌词包裹在 `<h1>` 中，能最大程度提升核心关键词在搜索引擎中的排名权重。
2. **保证交互可点击性（User Interaction）**：
   在任何成熟的网页上，点击 Logo 必须能够无缝刷新或跳转回到网站首页。因此，内部必须嵌套一个指向首页入口（`index.html`）的 `<a>` 标签，并且还要配置 `title` 属性，鼠标悬停时弹出友好提示文本。
3. **兼顾视觉展示与机器理解（Accessibility & Image Replacement）**：
   搜索引擎爬虫和盲人阅读器并不具备人类肉眼识别图像细节的能力，它们只能“读懂文本”。直接引入图片，即使带了 `alt`，其权重和信息可信度也远不如标签内部实打实的文字节点。因此，必须把品牌名称“小兔鲜儿”写在标签体内，但为了保证视觉设计师精心设计的 Logo 图案不被文字遮挡破坏，又必须在 CSS 中将该文字“完全隐藏”。

### 2.2 标准 HTML 语义结构的推导

根据上述原则，我们规范写出 Logo 的三层嵌套结构：

```html
<!-- 规范标准的 Logo 结构制作 -->
<div class="logo">
  <h1>
    <a href="index.html" title="小兔鲜儿">小兔鲜儿</a>
  </h1>
</div>
```

这里每一个标签都有不可替代的使命：
- `.logo`：负责在 Flex 布局中占据固定的空间坑位；
- `<h1>`：负责向搜索引擎声明最高等级的标题权重；
- `<a>`：负责提供可点击超链接，并作为视觉背景图与隐形文字的载体。

### 2.3 经典文本隐形术：`text-indent` 与 `overflow: hidden`

现在最棘手的问题来了：
我们在 `<a>` 内部写入了“小兔鲜儿”四个字，如果直接添加背景图，文字会重叠在图片上，造成严重的视觉混乱。如何把文字“变没”，却依然留在 HTML 源码里让搜索引擎爬虫抓到？

很多初学者的第一想法是：给文本设置 `display: none;` 或者 `visibility: hidden;`。
> **警告**：
> 绝对严禁使用 `display: none` 来隐藏 Logo 文字！主流搜索引擎（如百度、谷歌）的防作弊反垃圾算法非常健全，一旦检测到 `<h1>` 内部的内容被声明为 `display: none`，系统会判定该网站在恶意堆砌关键词欺骗搜索引擎，直接给予严重的“降权”甚至“K站（拔毛封禁）”处罚！

行业中流传最广、最安全稳定的大厂经典方案是 **首行缩进负值裁剪法**（Image Replacement）：

#### 第一步：让文字产生极大的负缩进
我们学习过文本属性 `text-indent`，它表示首行缩进。
- 给正值（如 `text-indent: 50px;`），文字往右挪动；
- 给负值（如 `text-indent: -9999px;` 或 `-999px`），文字就会以第一行基准线为起点，疯狂地向屏幕左外侧“暴走”！

文字向左跑得足够远，早就脱离了父级盒子的显示范围。

#### 第二步：溢出裁剪彻底销毁视觉痕迹
在文字跑出去之后，父级盒子设置 `overflow: hidden;`（超出隐藏）。
超出盒子物理边界的所有内容，在屏幕渲染视口中被直接裁剪隐形。用户在界面上哪怕把屏幕缩放到极致，也绝对看不到这四个字；但在页面 DOM 树和源码流中，“小兔鲜儿”真实存在且可被解析。

```text
首行负缩进与裁剪运行机理
┌──────────────────────────────────────┐  屏幕可见视口
│                                      │
│  [已跑出屏幕左侧]   .logo 物理显示区域 │
│  "小兔鲜儿" ←←←←   ┌───────────────┐ │
│  text-indent:       │               │ │
│  -9999px            │ 背景 Logo 图  │ │
│  (完全跑出边界)      │               │ │
│  overflow: hidden   └───────────────┘ │
│  将边界外的文字截断                   │
└──────────────────────────────────────┘
```
*图 4：首行负缩进与裁剪运行机理示意*

### 2.4 行内元素尺寸生效陷阱：`<a>` 的模式转换

我们已经明确了 Logo 容器的宽高为 `200px × 88px`。
那么内部的 `<h1>` 和 `<a>` 应该怎么写尺寸？

```css
/* 容器定宽高 */
.header .logo {
  width: 200px;
  height: 88px;
  /* background-color: skyblue; */
}

/* h1 继承填满父级 */
.header .logo h1 {
  width: 100%;
  height: 100%;
}
```

紧接着是内部的 `<a>` 标签。大家必须警惕一个极其常见的坑点：
`<a>` 属于行内元素（`inline`）。行内元素默认是**无法直接设置宽度和高度**的！如果你不转换显示模式，给 `a` 写 `width: 100%; height: 100%;`，它根本不会生效，尺寸完全由文字撑开；一旦你再加 `text-indent: -9999px` 把文字抽走，`<a>` 标签的高度瞬间崩塌为 0，你挂在 `<a>` 身上的背景图根本无法展示出来！

因此，必须把 `<a>` 转换为块级元素：
```css
.header .logo h1 a {
  display: block;
  width: 100%;
  height: 100%;
}
```
经过 `display: block;` 转换后，`<a>` 的物理边界完美等同于父级 200×88 的完整矩形，整块区域都具备了点击响应能力。

### 2.5 相对路径查找陷阱：CSS 模块化中的跨级引用

最后，我们将切好的透明背景图片挂载到 `<a>` 标签上：
```css
background: url(../images/logo.png) no-repeat;
```

> **易错点**：
> 这里的图片路径是无数初学者的重灾区！
> 很多同学写成 `url(./images/logo.png)` 或者 `url(images/logo.png)`，结果图片就是出不来。
> **请务必搞清楚代码的物理宿主位置**：
> - 我们的 CSS 代码是写在 `css/common.css`（或 `index.css`）文件里的，它的当前路径起点位于 `css/` 目录内部；
> - 而图片资源文件是存放在项目根目录下的 `images/`（或 `uploads/`）目录中的；
> - 想要从 `css/` 内部找到 `images/`，第一步必须是 **`../`（跳出当前 css 目录，回到项目根目录）**，第二步才是进入 `images/logo.png`！
> 这就是我们在基础篇反复强调“点点杠（`../`）上一级”的实战价值。

## 3. Header 骨架与 Logo 优化完整代码集成与调试核验

### 3.1 HTML 结构清单

将以上所有推导逻辑归拢，Header 区域现阶段的规范 HTML 结构如下：

```html
<!-- 头部区域 header 制作 -->
<div class="header w">
  <!-- 1. Logo 品牌区（严格遵循大厂 SEO 标准） -->
  <div class="logo">
    <h1>
      <a href="index.html" title="小兔鲜儿">小兔鲜儿</a>
    </h1>
  </div>

  <!-- 2. 全局主导航区（下一讲继续填充子项） -->
  <ul class="nav">
    <!-- 后续填充首页、生鲜、美食等导航 li -->
  </ul>

  <!-- 3. 搜索框区域（预留绝对定位父级容器） -->
  <div class="search">
    <!-- 后续填充 input 及字体图标 -->
  </div>

  <!-- 4. 购物车区域（预留角标定位父级容器） -->
  <div class="cart">
    <!-- 后续填充购物车超链接与数量徽标 -->
  </div>
</div>
```

### 3.2 CSS 样式表完整实现

在样式表（`common.css`）中，我们编写如下精细化控制代码：

```css
/* ==========================================================================
   头部 Header 模块样式定义
   ========================================================================== */

/* 1. Header 外层大盒子（版心居中由 .w 保证） */
.header {
  display: flex;
  justify-content: space-between;
  align-items: center;
  height: 132px;
}

/* 2. Logo 区域定宽定高 */
.header .logo {
  width: 200px;
  height: 88px;
}

/* 3. h1 充满父级，继承标准宽高 */
.header .logo h1 {
  width: 100%;
  height: 100%;
}

/* 4. a 标签核心样式：转块、占满、背景挂图、文字负缩进与超出裁剪 */
.header .logo h1 a {
  display: block;
  width: 100%;
  height: 100%;
  /* 挂载背景图：不平铺、居中对齐或左对齐 */
  background: url(../images/logo.png) no-repeat;
  /* 经典文本隐形术：首行负缩进走得很远，超出部分一刀切 */
  text-indent: -9999px;
  overflow: hidden;
}
```

### 3.3 浏览器端检查工具验证与细节自查

完成上述编码后，在浏览器中进行三项关键技术核验：
1. **背景与点击热区核验**：
   打开 Chrome 开发者工具（`F12`），鼠标悬停在 `.logo a` 上，查看浏览器高亮区域是否严丝合缝地覆盖 `200px × 88px` 的矩形；点击 Logo 任意有效区域，浏览器地址栏应正确跳转或刷新为 `index.html`；
2. **Tooltip 提示验证**：
   将鼠标悬停在 Logo 上静止保持 1 秒，观察是否弹出操作系统原生的“小兔鲜儿”悬停气泡提示框（由 `title` 属性驱动）；
3. **DOM 与抓取审查**：
   在 Elements 面板中检查，文字节点“小兔鲜儿”完完整整地停留在 `<h1>` 和 `<a>` 体内，但在界面上没有丝毫文字露头破坏背景图的美感。
