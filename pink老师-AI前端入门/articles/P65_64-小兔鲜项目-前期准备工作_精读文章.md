# 小兔鲜电商项目架构设计与前期工程准备

学了那么久的 HTML5、CSS3 和弹性布局（Flexbox），很多同学平时跟着写一个个几十像素的小 demo 感觉都会了，但一到真实企业开发场景面对一个完整的工业级电商网站，脑子里往往一片空白：图片该怎么存？样式表写在一个文件里还是分开？设计稿怎么量才不会量偏？第一行代码究竟先写什么？

从小兔鲜（Fresh-Rabbit）这个典型的大型电商网站开始，我们要把前面学过的所有布局知识串联起来实战打通。就像当年做小米、京东商城一样，从零搭建一个结构严谨、可维护、符合企业一线开发标准的完整商业页面。

在敲下任何实际业务结构之前，必须先把项目的基础设施与工程规范彻底理顺。前期准备工作做得越扎实，后面写代码就会越顺畅，绝不会出现改个背景颜色全站样式跟着崩塌的惨剧。

## 1. 电商项目骨架拆解与设计稿测量技巧

### 1.1 页面全景模块与“自上而下”布局法则
小兔鲜是一个典型的 B2C 现代综合电商网站。打开设计稿，我们一眼望去内容繁多，有各种导航、分类、轮播图、促销专区和商品瀑布流。

面对复杂的大型页面，布局的核心思维永远是**大盒子套小盒子，自顶向下切大块，再逐步深入扣细节**：

```text
小兔鲜电商首页自顶向下骨架拓扑
┌────────────────────────────────────────────────────────┐
│ 1. 快捷导航模块（shortcut）：黑色通栏，登录/注册/订单...  │
├────────────────────────────────────────────────────────┤
│ 2. 网站头部模块（header）：Logo、全站主导航、搜索、购物车 │
├────────────────────────────────────────────────────────┤
│ 3. 核心首屏模块（banner / category）：轮播大图 + 左侧分类│
├────────────────────────────────────────────────────────┤
│ 4. 新鲜好物模块（goods / new）：新鲜好物展示卡片列表   │
├────────────────────────────────────────────────────────┤
│ 5. 人气推荐模块（goods / popular）：热销爆款推荐卡片   │
├────────────────────────────────────────────────────────┤
│ 6. 更多产品业务楼层（生鲜/服饰/居家专区...）           │
├────────────────────────────────────────────────────────┤
│ 7. 网站底部模块（footer）：服务保障、版权声明、备案信息 │
└────────────────────────────────────────────────────────┘
```
*图 1：小兔鲜首页自顶向下宏观大盒子结构图*

我们先从最外层的轮廓入手：先排快捷导航，再排头部，再排主体，最后排底部。一个大盒子一个大盒子顺次往里填。

### 1.2 工业级设计稿标注与快捷键测量技巧
在正规公司里，UI 美工/视觉设计师交付的通常是一个在线协同标注链接（例如蓝湖、MasterGo、即时设计或 Figma）。为了保障大家的离线练习，我们在配套素材包中准备了与线上完全一致的本地设计稿标注系统（双击打开素材中的 `index.html` 即可启动）。

设计稿标注系统与普通网页完全不同，掌握以下三个核心操作，测算效率能提升数倍：
1. **元素属性即时提取**：鼠标单击设计稿中的任何文字（如“生鲜”），右侧侧边栏会立即显示其精确的字体系列、字号大小（如 `font-size: 16px`）、色值（如 `#333333`），甚至还会附带一部分现成的 CSS 代码。
2. **两点间距精准测量**：鼠标先单击选定一个起始元素（如“首页”导航项），然后将鼠标悬停在另一个目标元素（如“生鲜”导航项）上方，系统就会自动在两者之间拉出一条带有标注数字的辅助线（例如两者间距为 `47px`）。
3. **视图缩放与抓手拖拽快捷键**：
   - `Ctrl + 鼠标滚轮`：快速放大与缩小画布视图。测算小边框、1px 细线或者小圆点时，必须滚轮放大到 200% 以上，才能避免测出肉眼像素误差；
   - `按住空格键（Space）`：鼠标指针会瞬间变成小手抓手状态，此时按住鼠标左键即可平滑拖动整个设计稿，想看哪里就拖到哪里。

## 2. 项目目录规范与工程化资源分类

很多初学者写代码习惯随心所欲，把 HTML、CSS、图片全丢在一个文件夹里，图片名字全叫 `1.jpg`、`2.png`、`未命名.png`。这种做法在真实商业项目中是绝对不允许的。企业级项目讲究模块化与资产分类隔离。

### 2.1 根目录与 `favicon.ico` 站点图标专用规范
我们在本地新建一个根目录文件夹 `小兔鲜项目/`。在这个项目根目录下，必须直接放置一个名为 `favicon.ico` 的文件。

> **易错点**：**`favicon.ico` 严禁丢进 `images/` 图片文件夹，必须直接放在网站根目录！**
> 很多初学者一看图标是图片，就顺手扔进了 `images/` 里，这是极其不规范的。`favicon.ico`（Favorites Icon）是浏览器标签页标题左侧显示的网站专属标识（比如打开京东，标签栏有个红白相间的小狗头图标；打开小兔鲜，是一个粉白相间的小兔子图标）。现代浏览器在加载任何网页时，默认都会优先在网站根路径 `/favicon.ico` 自动寻址抓取。把它直接放根目录下，既符合浏览器默认嗅探协议，也符合前端标准部署约定。

### 2.2 静态修饰图 `images/` 与业务商品图 `uploads/` 的物理隔离
我们必须在项目根目录中建立两个独立的图片文件夹，很多刚入门的同学经常分不清它们的边界：

| 文件夹名 | 中文语义 | 存放内容与生命周期 | 典型素材示例 |
| :--- | :--- | :--- | :--- |
| **`images/`** | 网站静态修饰图 | **不经常发生变动的、属于页面皮肤结构的静态资源**。哪怕网站没有一件在售商品，这些图也必须存在。 | 网站 Logo、雪碧精灵图、固定装饰背景底纹、App下载二维码小图标等 |
| **`uploads/`** | 业务商品数据图 | **高频变动、随时由商家或后台上传的商品图片**。是纯粹的业务数据，随上架下架随时增删。 | 生鲜苹果照片、衣服鞋帽模特图、商品详情页多角度展示图、促销瀑布流卡片图 |

```text
电商网站图片资产隔离架构
网站资源根目录
  ├── images/ ──────────► [静态皮肤结构] Logo、图标、精灵图、固定底纹（永久静态）
  └── uploads/ ─────────► [动态商品数据] 水果、蔬菜、肉类、服饰实拍（动态更新）
```
*图 2：静态结构图与业务数据图物理隔离架构示意图*

将两者彻底隔开，一方面是因为后端上线时，`uploads/` 目录往往需要挂载到单独的 CDN 存储对象（如阿里云 OSS、腾讯云 COS），而 `images/` 则是跟随前端代码包一同版本发布；另一方面，在日常维护中替换一张商品图绝不会意外覆盖网站的结构 Logo。

### 2.3 字体图标库 `iconfont/` 集成
在现代 Web 页面中，像手机图标、放大镜、购物车、下拉小箭头等轻量级符号，已经全面摒弃了切碎图或 GIF 的老旧做法，统一采用**字体图标（Icon Font）**。我们在素材中集成了阿里巴巴矢量图标库导出的 `iconfont/` 资源包，包含了字体图标 CSS 及预览演示页面。

### 2.4 CSS 样式模块化三层架构
页面样式代码动辄成千上万行，如果全挤在 HTML 页面的 `<style>` 标签或单个 CSS 文件中，代码会变得冗长混乱、难以排查，且多个页面间无法复用。

小兔鲜项目采用外部样式表（External Style Sheet），并将 CSS 拆分为三层职责清晰的独立文件：
1. **`base.css`（基础初始化层）**：重置浏览器默认行为，清除内外边距缝隙，抹平不同浏览器渲染差异，提供全站最通用的全局默认排版规则。
2. **`common.css`（公共模块样式层）**：存放多个页面高度公用的模块样式。例如不管用户浏览首页、生鲜页、还是商品详情页，**顶部的快捷导航、网站头部 Header 以及底部的 Footer 永远是一模一样的**。把它们提取到 `common.css`，一份代码全站复用，后续修改电话或链接只需改动一次，全站同步生效。
3. **`index.css`（当前页面独有样式层）**：只存放当前 `index.html` 首页独有的板块样式（如首页的大轮播图、新鲜好物展示卡等）。

## 3. 样式初始化底座与公共版心定义

### 3.1 `base.css` 初始化样式深度解析
在素材中的 `css/base.css` 已经为我们准备好了标准的重置规则，我们必须清楚每一行代码背后的工程推导：

```css
/* 1. 清除浏览器默认内外边距，统一切换为怪异/边框盒模型 */
* {
    margin: 0;
    padding: 0;
    box-sizing: border-box;
}

/* 2. body 基础文字排版底座 */
body {
    font-size: 16px;
    font-family: -apple-system, BlinkMacSystemFont, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "WenQuanYi Micro Hei", sans-serif;
    color: #333;
    background-color: #fff;
}

/* 3. 列表标签重置：清除无序与有序列表前面的小圆点或序号 */
ul, ol, li {
    list-style: none;
}

/* 4. 倾斜标签重置：让 em、i 默认不倾斜，专为存放字体图标或修饰符做准备 */
em, i {
    font-style: normal;
}

/* 5. 链接重置：清除默认下划线，统一步调颜色为深灰，杜绝浏览器默认诡异蓝紫变色 */
a {
    text-decoration: none;
    color: #333;
}

/* 6. 图像标签重置：消除图片底部的幽灵空白缝隙 */
img {
    vertical-align: middle;
}

/* 7. 表单与输入框重置：清空默认边框与聚焦蓝色外轮廓线 */
input {
    border: none;
    outline: none;
    color: #333;
}

/* 8. 标题标签重置：清空 h1 ~ h6 默认加粗与外边距，让设计稿统一接管 */
h1, h2, h3, h4, h5, h6 {
    font-weight: 400;
}
```

> **提示**：这里 `img { vertical-align: middle; }` 非常关键！图片默认是行内块级元素，默认与基线（baseline）对齐，因此图片底部会留出 3~5px 的诡异空白缝隙。将其基线对齐模式改为 `middle` 或 `top`，就能彻底消除这个幽灵白边。

### 3.2 `common.css` 全局版心 `.w` 封装与推导
打开小兔鲜的设计稿，仔细测量会发现：中间内容并不是撑满屏幕的，而是两边留白、中间居中。

我们测量出小兔鲜的内容核心区域宽度为 **1240px**。这个容纳核心内容、水平居中对齐的容器，在前端行业中被形象地称为**版心（Container / Wrapper）**。

在 `common.css` 中，我们参照京东等大厂的经典命名习惯，封装一个超高频复用的公共类名 `.w`（Width 的缩写）：

```css
/* common.css 中定义的全局版心容器 */
.w {
    width: 1240px;
    margin: 0 auto;
}
```

> **结论**：在后续开发中，页面里只要哪一个模块（如头部、导航、商品推荐区）需要保持 1240px 居中，直接在 HTML 标签上使用多类名机制追加一个 `w`（例如 `<div class="header w">`），它就会自动水平居中，根本不需要在每个业务选择器里重复书写 `width` 和 `margin: 0 auto`！

## 4. HTML 入口文件搭建与外部资源引入戒律

在编辑器中新建 `index.html`，输入 `!` 生成 HTML5 标准骨架，网页标题修改为 `小兔鲜儿 - 新鲜、惠民、快捷！`。

### 4.1 编辑器分屏对照编码实操
在 Trae 或 VSCode 编辑器中，我们右键点击 `common.css` 选择“向右拆分（Split Right）”，让屏幕左侧显示 HTML 骨架，右侧显示 CSS 样式表。

这样我们在左边写标签、给类名，右边直接量设计稿写属性，视线不需要在多个标签页之间频繁跳跃，写代码既流畅又不会漏样式。

### 4.2 外部资源引入时序戒律
在 `index.html` 的 `<head>` 标签内，引入外部图标与样式的顺序有极其严苛的规则，绝不能随意颠倒：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>小兔鲜儿 - 新鲜、惠民、快捷！</title>

    <!-- 1. 优先引入网站标签页图标 favicon.ico -->
    <link rel="shortcut icon" href="./favicon.ico" type="image/x-icon">

    <!-- 2. 引入字体图标库样式（必须在自定义 CSS 之前引入） -->
    <link rel="stylesheet" href="./iconfont/iconfont.css">

    <!-- 3. 引入基础初始化样式表 base.css -->
    <link rel="stylesheet" href="./css/base.css">

    <!-- 4. 引入全站公共样式表 common.css（头部、底部与版心） -->
    <link rel="stylesheet" href="./css/common.css">

    <!-- 5. 引入当前首页专属业务样式表 index.css -->
    <link rel="stylesheet" href="./css/index.css">
</head>
<body>
    <!-- 版心验证测试节点 -->
    <div class="w">123</div>
</body>
</html>
```

```text
外部样式资源层叠依赖加载链
 ┌─────────────────────────┐
 │ 1. iconfont.css (字体库) │ ───► 提供底层图标矢量字形字库
 └────────────┬────────────┘
              ▼
 ┌─────────────────────────┐
 │ 2. base.css (重置层)     │ ───► 抹平浏览器标签默认差异，清空内外边距
 └────────────┬────────────┘
              ▼
 ┌─────────────────────────┐
 │ 3. common.css (公共层)   │ ───► 定义全站通用版心 .w、头部与底部框架
 └────────────┬────────────┘
              ▼
 ┌─────────────────────────┐
 │ 4. index.css (专属层)    │ ───► 覆盖与定义当前页面独特的业务组件外观
 └─────────────────────────┘
```
*图 3：外部样式层叠依赖加载流向图*

> **核心戒律**：
> 1. **字体图标库必须置于自定义 CSS 之前**：因为我们在 `common.css` 或 `index.css` 中需要使用微调类名覆盖字体图标的大小或间距，根据 CSS 后面覆盖前面的层叠优先级原则，底座字库必须先入场。
> 2. **`base.css` 必须早于 `common.css` 早于 `index.css`**：必须先执行基础标签的全局格式化，再由公共样式构建通用骨骼，最后才由页面专属样式渲染个性化细节。顺序若倒置，页面业务细节极易被全局重置规则意外冲刷洗掉。

保存后在浏览器中右键运行 `index.html`，看到文字 “123” 已经在 1240px 的中央区域水平居中显示，且默认字体为 16px、深灰色，说明我们的整个项目底座与模块化体系已经全部加载成功，准备就绪！
