# CSS 文本布局全解：对齐、首行缩进、字间距与行高深度推导

在搞定字体的颜色、大小、粗细与装饰之后，文字的“单兵素养”已经达标。但如果在实际网页中把它们往页面上一放，你立刻就会发现新的问题接踵而至：段落顶格没有空格、长篇新闻右侧参差不齐、字与字挤得喘不过气、或者一个固定高度的按钮里文字死活居不了中。

这就是文本样式的第二大板块要解决的问题——**文本布局（Text Layout）**。

文本布局的核心使命，是**掌控文字在宿主盒子容器中的排版分布与呼吸节奏**。本讲我们将深入剖析四大核心属性：水平对齐（`text-align`）、首行缩进（`text-indent`）、字符间距（`letter-spacing`）与行高计算（`line-height`）。

```text
文本布局四大属性空间作用维度
┌─────────────────────────────────────────────────────────┐
│ 容器（Box）                                              │
│  ┌───────────────────────────────────────────────────┐  │
│  │ text-indent: 2em;                                 │  │
│  │ ──► [首行缩进两个字]                                │  │
│  │                                                   │  │

│  │ 字 [间距] 符 [间距] 间 [间距] 距                     │  │
```

## 1. 文本水平对齐（text-align）

`text-align` 属性用于设置块级容器内部行内内容（文本、行内标签、行内块等）的水平对齐方式。

### 1.1 两大前置铁律

在调用 `text-align` 时，必须时刻警惕两条不可违背的底层约束：
1. **仅对块级元素生效**：行内元素（如普通的 `<span>`、`<strong>`）自身宽度完全由内容撑开，没有属于自己的独立排版空间，给它设置 `text-align` 毫无意义。必须将其设置在包裹文本的块级容器（如 `<div>`、`<p>`、`<h1>` 等）上；
2. **仅控制水平方向**：它只管左右水平排布，**绝对无法实现任何垂直方向的对齐**。

### 1.2 四大取值与商业排版实践

| 取值 | 对齐效果 | 工业实战应用场景 |
| :--- | :--- | :--- |
| `left` | **左对齐（浏览器默认值）** | 中英文日常阅读最习惯的流向，从左往右 |
| `right` | **右对齐** | 价格标注、表格数值对齐、表单右侧标签提示文案 |
| `center` | **水平居中对齐** | 文章主副标题、弹出层提示语、卡片按钮文字 |
| `justify` | **两端对齐** | **商业新闻与长文段落首选**，消除段落右侧锯齿凹凸 |

```css
/* 水平对齐语法示范 */
.align-center {
    text-align: center; /* 文本在块级容器内水平居中 */
}

.align-right {
    text-align: right; /* 文本靠右侧对齐 */
}

.article-p {
    text-align: justify; /* 长文本段落两端齐平 */
}
```

### 1.3 商业实战推导：为什么长篇新闻必须用 text-align: justify？

很多同学在做新闻咨询类页面时会发现一个现象：一段新闻文字，左侧排得整整齐齐，但右侧却犬牙交错、参差不齐。有的行末尾空着两三个字的位置，有的行又紧紧贴边。

这是因为中文在遇到英文单词、标点符号时，浏览器默认为了防止标点溢出或英文截断，会强制将长单词或标点提前折行，导致右侧出现大块不规则的空白“空洞”。

我们以腾讯体育新闻的正文排版为例：审查其段落 `<p>` 的样式，前端工程师统一配置了 `text-align: justify;`。
浏览器在渲染 `justify` 时，会自动计算当前行剩余的空白像素，并将其**微量均匀地分摊到每一个汉字之间**，迫使每一行的最右端都如同用尺子裁切过一样严丝合缝。整个段落瞬间变得沉稳端庄、视觉极度工整。

## 2. 首行缩进（text-indent）

在中文出版规范中，每一个自然段的第一行都要求向前缩进两个汉字的距离，俗称“段首空两格”。在 CSS 中，这一效果由 `text-indent` 负责实现。

### 2.1 长度单位大辨析：px vs em

`text-indent` 后面可以跟长度数值。初学者最容易犯的一个经验主义错误，就是顺手敲上绝对单位 `px`：

```css
/* 危险且不具备响应能力的写法 */
p {
    text-indent: 32px; /* 假设字号是 16px，空 32px 刚好两个字 */
}
```

> **易错点**：为什么严禁在首行缩进中写死 `px`？
> 假设当前段落字号是 `16px`，缩进 `32px` 看起来刚好是两个汉字。但如果之后由于设计规范变更，或者在手机端适配时字号被改成了 `20px`，那么 `32px` 的缩进在 `20px` 的字体下就只能缩进 1.6 个字，段首文字会卡在一个非常尴尬的半字位置上，排版彻底破相！

为了解决这个问题，CSS 专门提供了针对排版的**相对长度单位——`em`**：
- **`em` 的核心定义**：`1em` 等于**当前元素自身所设定的 `font-size` 的大小**；如果当前元素没有设置字号，则等于从父级继承过来的字号大小。
  - 若当前段落字号为 `16px`，则 `1em = 16px`，`2em = 32px`；
  - 若字号放大到 `24px`，则 `1em = 24px`，`2em = 48px`。

```text
em 相对单位弹性伸缩示意图
┌─────────────────────────────────────────────────────────┐
│ 当 font-size: 16px 时:                                  │
│ ┌──────────────┐                                        │
│ │ 16px │ 16px  │ 两个字的空间（总计 32px）                │
│ └──────────────┘                                        │
│ ◄──── 2em ────►                                         │
│                                                         │
│ 当 font-size: 20px 时:                                  │
│ ┌──────────────────┐                                    │
│ │  20px  │  20px   │ 两个字的空间（总计 40px，自适应放大） │
│ └──────────────────┘                                    │
│ ◄────── 2em ──────►                                     │
└─────────────────────────────────────────────────────────┘
```
*图 2：2em 无论在何种字号下都能精准锁定两个字符的宽度*

> **行业黄金铁律**：在中文排版中，首行空两格**必须永远、无条件地写为 `text-indent: 2em;`**！不管字号如何变幻，`2em` 永远不多不少刚好空出两个字的位置。

同样需要谨记：`text-indent` 也只对**块级元素**生效。如果你把它写在 `<span>`、`<strong>` 等行内元素上，浏览器完全视若无睹。

## 3. 字符间距控制（letter-spacing）

`letter-spacing` 用于调节文本中每一个字符（汉字、英文字母、数字）之间的水平间隙。

### 3.1 语法规则与取值范围

```css
/* 字符间距的基本语法 */
.nav-item {
    letter-spacing: 2px; /* 每个文字之间拉开 2px 呼吸感 */
}
```

- **正数取值**：数值越大，文字之间散得越开；
- **负数取值**：数值为负时，字与字之间会向内挤压。如果负得太多（比如 `-5px`），文字会彻底叠合在一起变成黑乎乎的“印章重影”，在常规布局中必须慎用；
- **适用性**：与前两者不同，`letter-spacing` **无论对块级元素还是行内元素均能完美生效**。

### 3.2 商业实操：B站导航栏的透气感秘籍

我们打开哔哩哔哩（Bilibili）官网首页，观察顶部的“番剧”、“国创”、“综艺”、“动画”等栏目导航链接。
如果文字紧紧挨在一起，短字词会显得非常局促局促。B站前端在样式表里对导航文本设置了：
```css
/* B站顶部导航文本呼吸感实操写法 */
.bili-nav-link {
    letter-spacing: 2px;
}
```
通过 Chrome 开发者工具中的样式面板，把光标定在 `2px` 上，按下键盘上的 `↑` 和 `↓` 箭头，你可以实时看到字间距在 1px、2px、3px 之间平滑微调。这种细节正是大厂产品视觉上“看起来更高级、不拥挤”的关键所在。

## 4. 行高计算模型与单行文本垂直居中神技（line-height）

如果说文本样式里哪一个属性承载着最多的几何原理与开发技巧，那非 `line-height` 莫属。

### 4.1 行高的底层物理构成

在 CSS 中，每一行文字所占据的垂直高度并不单纯由字号决定。浏览器在渲染文字时，会在字体的上方和下方自动填充看不见的空白间隙：

$$\text{行高（line-height）} = \text{字号（font-size）} + \text{上间距（Half-leading）} + \text{下间距（Half-leading）}$$

其中，上间距和下间距在物理上始终保持**严格等比、绝对均分**。

```text
行高（line-height）垂直空间解构图
┌──────────────────────────────────────────────┐ ───┐
│              空白上间距 (Half-leading)        │   │
│ ┌──────────────────────────────────────────┐ │   │
│ │   中 文 字 体 基 准 尺 寸 (font-size)      │ │   ├─ 行高 (line-height)
│ └──────────────────────────────────────────┘ │   │
│              空白下间距 (Half-leading)        │   │
└──────────────────────────────────────────────┘ ───┘
```
*图 3：行高由字号与其上下均分的空白半行距构成*

### 4.2 行高的取值形式与经典翻车事故

`line-height` 支持两种主流赋值方式：

1. **带像素单位的数值**：
   例如 `line-height: 26px;`。直接锁死每一行文本的物理高度为 26 像素。
2. **不带单位的纯数字（倍数关系）**：
   例如 `line-height: 1.5;`。这代表当前行高为**当前元素自身字号的 1.5 倍**。
   若当前字号为 `16px`，则实际生效行高为 $16 \times 1.5 = 24\text{px}$。

> **易错点：千万别漏写单位引发翻车**！
> 在课堂上常有同学跑来求救：“pink老师，我明明只写了 `line-height: 26;` 想让行高变成 26 像素，为什么页面上所有文字一下子被撑得彼此相距几十厘米，整个布局彻底爆炸了？”
> **原因就在于丢了 `px` 单位**！你写 `line-height: 26;`，浏览器不会当成 26px，而是当成了 **26 倍**！在 16px 字号下，实际行高被暴力撑到了 $16 \times 26 = 416\text{px}$！因此请大家牢记：**要么老老实实加单位写成 `26px`，要么写合理的小数倍率如 `1.5`、`1.8`**。

### 4.3 核心神技：单行文本在容器内垂直居中的数学推导

在日常开发中，我们做导航条、按钮、提示框时，设计师总是要求文字不仅要在盒子里水平居中，还必须**垂直居中**。

很多新手翻遍 CSS 文档想找一个叫 `vertical-align: center` 的属性，结果发现根本不起作用（`vertical-align` 只能用于行内块或表格单元格）。那么，让普通块级盒子内的文字垂直居中的行业标准解法是什么？

> **前端黄金公式**：**让行高等于盒子高度（`line-height: height;`）**！

#### 原理深度数学推导：
假设我们有一个高度为 `50px` 的容器盒子（`height: 50px;`），里面有一句字号为 `16px` 的单行文本：
1. 当我们给文字设置 `line-height: 50px;` 时，文字自身的物理尺寸依然是 `16px`；
2. 剩余的空白垂直空间为：$50\text{px} - 16\text{px} = 34\text{px}$；
3. 根据行高的底层物理模型，这 34px 会被上下**绝对对半分摊**：
   - 上半间距分配：$34\text{px} / 2 = 17\text{px}$；
   - 下半间距分配：$34\text{px} / 2 = 17\text{px}$；
4. 文字在 17px 上间距的推动下，正好被推到了容器高度的正中央！

```css
/* 单行文本完美垂直水平居中的经典范例 */
.button {
    width: 120px;
    height: 50px;
    background-color: pink;
    
    /* 1. 水平居中 */
    text-align: center;
    /* 2. 垂直居中：行高严格等于盒子高度 */
    line-height: 50px;
}
```

```text
行高等于盒高实现单行文字垂直居中推导
┌──────────────────────────────────────────────┐ ───┐
│ 上间距 = (50px - 16px) / 2 = 17px            │   │
│ ┌──────────────────────────────────────────┐ │   │
│ │               文 本 居 中                │ │   ├─ 盒高 50px = 行高 50px
│ └──────────────────────────────────────────┘ │   │
│ 下间距 = (50px - 16px) / 2 = 17px            │   │
└──────────────────────────────────────────────┘ ───┘
```
*图 4：上下间距均分机制把单行文本精准锁定在盒子垂直中线上*

> **核心警告与边界条件**：
> 这个技巧**有且仅能应用于单行文本**！
> 如果盒子里的文字过长折行成了两行，由于行高是 50px，两行文字总高度就变成了 100px，第二行文字会直接狼狈地掉出盒子下边界！遇到多行文本垂直居中，需要依靠后续章节我们要精讲的内边距（`padding`）或弹性盒（`flex`）来解决。

## 5. 文本布局四大属性实战对比全貌

| CSS 属性 | 作用对象与适用限制 | 推荐取值规范 | 核心业务场景与技术收益 |
| :--- | :--- | :--- | :--- |
| `text-align` | **仅限块级容器**；仅控制水平方向 | `center`、`right`、`justify` | 标题与按钮居中；新闻长文用 `justify` 消除右侧参差不齐 |
| `text-indent` | **仅限块级容器**；控制段首空隙 | **固定写为 `2em`** | 永远使用相对单位 `2em`，自适应任何字号完成中文段首空两格 |
| `letter-spacing` | **块级与行内通用**；控制字符间隔 | `2px`、`4px` | 提升短语与导航链接的呼吸感；严禁使用过大负值避免重叠 |
| `line-height` | 控制单行基准高度与多行间距 | `26px` 或 `1.5`（严禁漏写单位） | 优化长文行距提升可读性；**令 `line-height = height` 实现单行文本垂直居中** |
