# 3D 空间位移机制与 transform-style 子元素立体空间保留

我们在上一讲成功实现了两面翻转的卡片盒子。很多同学做完之后非常兴奋，但把玩了一会儿又会觉得：卡片虽然在三维空间里翻转，可卡片上面的文字和标题依然死死贴在卡片的平面上，看起来就像是在一张纸的正面和反面印了字，缺乏那种未来科技感、电影大片般的**全息悬浮立体视差（3D Parallax）**。

如果我们想让卡片在翻转的同时，正面和背面的文字像浮雕一样**从卡片表面悬浮凸出、飘在卡片前方**，应该怎么做？这就需要引入 CSS 3D 体系中两大至关重要的技术基石：**3D 位移（`translate3d` / `translateZ`）**，以及彻底解锁多层级三维世界的终极开关——**开启子元素 3D 空间（`transform-style: preserve-3d`）**。

---

## 1. 3D 位移原理与 GPU 硬件加速机制

### 1.1 2D 平移向 3D 空间维度的跃迁

我们在前面的章节学过 2D 平移：`translateX(x)` 控制水平左右位移，`translateY(y)` 控制垂直上下位移。而在 3D 变换中，我们引入了垂直穿透屏幕平面的第三个维度——**Z 轴**。

在 CSS 中，3D 位移有两种核心语法：

1. **多轴复合位移**：`transform: translate3d(x, y, z);`
2. **单一 Z 轴位移**：`transform: translateZ(z);`

```text
3D 空间坐标轴位移方向
                    Y 轴 (负方向：向上)
                         ▲
                         │
                         │
                         │
 ────────────────────────┼────────────────────────► X 轴 (正方向：水平向右)
 (X 负方向：向左)        │
                         │
                         │
                         ▼
                    Y 轴 (正方向：向下)

        ⊙ Z 轴正方向 (从屏幕内部穿透出来，笔直冲向我们的眼睛！)
```
*图 1：网页 3D 坐标系三轴空间位移方向基准*

---

### 1.2 translate3d(x, y, z) 语法规范与大厂硬件加速实践

`translate3d` 能够同时接收三个方向的位移量：

```css
/* 语法结构：三个参数缺一不可 */
transform: translate3d(x, y, z);
```

> **注意**：`translate3d` **必须严格传递 3 个参数**，如果某一个轴没有位移，必须显式补 `0`（例如 `0` 或 `0px`），绝不能省略参数，否则整条样式将被视为语法错误而直接作废！

在实际前端工程开发中，即便是只在水平或垂直方向做微小的位移，以小米、苹果为代表的大型商业网站也往往优先采用 `translate3d` 写法，例如：

```css
/* 小米官网等主流电商卡片 hover 浮动效果典型写法 */
.product-card:hover {
  /* X 轴不动，Y 轴向上平移 2px，Z 轴不动 */
  transform: translate3d(0, -2px, 0);
}
```

很多同学可能会疑惑：明明只动了 Y 轴，写 `translateY(-2px)` 不就够了吗？为什么要大费周章写 `translate3d(0, -2px, 0)`？

> **结论**：**`translate3d` 可以强制开启浏览器的 GPU 硬件加速（Hardware Acceleration）**！
> 
> 当浏览器解析到 `3d` 系列函数时，会将该元素提升为一个独立的合成层（Compositing Layer），直接调用显卡 GPU 的纹理管线进行光栅化与矩阵运算，从而完全绕过 CPU 繁重的重排（Reflow）与重绘（Repaint），大幅消除微交互中的掉帧与卡顿，让动效达到极致的 60fps / 120fps 丝滑流畅度。

### 1.3 translateZ(z) 的物理几何意义与中指指向法则

如果我们在业务中只需要沿着 Z 轴移动元素，可以直接使用独立的 `translateZ(z)` 函数。

如何判断 `translateZ` 的位移方向？依然请伸出你们的**左手**！
在左手三维坐标系定则中：
- 大拇指指向水平向右（X 轴正向）；
- 食指指向垂直向下（Y 轴正向）；
- **中指自然向前平伸指向前方（直冲我们眼睛的方向），就是 Z 轴的正方向**！

```text
左手三维轴向姿态定则
           食指 (垂直朝下) ───► Y 轴正向
           大拇指 (水平朝右) ──► X 轴正向
           中指 (直冲眼睛) ───► Z 轴正向
```
*图 2：左手定则中指定向 Z 轴正方向*

> **推导结论**：
> - `translateZ(60px)`（正值）：元素**沿着 Z 轴向前走，脱离屏幕平面直奔我们眼前扑来**；在父级 `perspective` 透视的作用下，由于“近大”，元素在视觉上会明显放大，呈现强烈的凸起悬浮感；
> - `translateZ(-60px)`（负值）：元素**向屏幕深处后退**，远离我们的视线；在透视作用下，由于“远小”，元素会逐渐缩减收敛。

需要特别强调的是：**`translateZ` 要想在肉眼上看出近大远小的缩放形变，其所有祖先容器中必须至少有一层开启了 `perspective` 透视**。如果没有透视，平行投影下的正向位移在正视角度下是无法感知到大小变化的。

## 2. 悬浮全息字效果引出的压平渲染困境

掌握了 `translateZ` 之后，我们立刻在上一讲的两面翻转盒子基础上做一次效果升级：
我们不仅要让卡片翻转，还要让卡片正面的标题 `<h3>17岁 刘德华</h3>` 和背面的歌词段落 `<p>` 向前凸出来，浮在卡片表面上方 `60px` 处！

### 2.1 尝试给文字添加 translateZ

按照直觉，我们直接给正面的标题文字加上 Z 轴平移：

```css
/* 尝试让正面文字向前浮动 60px */
.box .front h3 {
  transform: translateZ(60px);
}
```

为了看得更清楚，我们把翻转过渡时间临时调慢到 6 秒（`transition: all 6s;`），然后打开浏览器刷新测试。

此时，令所有人意想不到的诡异现象出现了：
**鼠标悬停翻转时，文字根本没有凸出来！它依然死死贴在卡片的粉色底板上，随着卡片一起像一张平整的硬纸板一样转过去，完全没有任何立体悬浮的厚度！**

明明写了 `translateZ(60px)`，父级 `.box` 也设置了 `perspective: 1000px;`，为什么 Z 轴位移完全失效了？

---

### 2.2 浏览器的扁平化渲染机制（transform-style: flat）

这是因为触碰到了 CSS 3D 渲染管线中最根本的默认规则：**扁平化压平机制（Flattening）**。

在 CSS 规范中，任何一个元素如果在 3D 空间中被施加了变换（比如旋转或者位移），它的子元素在默认状态下**并不能直接继承该父元素的三维立体坐标空间**。

> **易错点**：浏览器对所有元素的 `transform-style` 属性预设的默认值是 **`flat`（扁平）**！
> 
> `flat` 的字面意思就是“压平”。浏览器在渲染父元素时，会把父元素内部所有的子节点无论在 3D 空间里做了多少位移，通通强制投影、拍扁在父元素自身的 2D 平面上，然后再把这个被拍扁的 2D 平面当作一张画卷放到外层空间里去翻转。这就导致文字在三维层面上被“降维打击”压平了，自然无法悬浮在空中。

```text
默认 flat 模式与 preserve-3d 模式渲染差异对比

【模式 A：默认 flat (扁平化压平)】
           .front (父级自身在三维旋转)
          ┌───────────────────────┐
          │  h3 (虽然设置了 Z+60) │
          │  但在渲染时被强制拍平 │ ◄── 降维打击，无立体厚度
          │  在同一个 2D 画布上   │
          └───────────────────────┘

--------------------------------------------------------------

【模式 B：开启 preserve-3d (保留三维空间)】
                   h3 (凸出悬浮图层，Z = 60px)
                 ┌─────────────┐
                 │ 17岁 刘德华 │  ▲
                 └─────────────┘  │  
                     │ 空间纵深   │ 悬浮间距 60px
                     ▼            │
          ┌───────────────────────┴┐
          │ .front (卡片底板图层)  │
          └────────────────────────┘
```
*图 3：flat 扁平化压平与 preserve-3d 真实立体多图层渲染的空间几何区别*

## 3. 开启子元素 3D 空间：transform-style: preserve-3d

想要打破浏览器的扁平化压制，让子元素在三维空间中自由舒展、悬浮分离，必须显式声明 `transform-style` 属性。

### 3.1 transform-style 属性规范

> **定义**：`transform-style` 属性用于指定**当前元素的子元素是在三维空间中保留立体呈现，还是在平面中扁平化渲染**。

它包含两个取值：
- `flat`（默认值）：子元素不保留 3D 空间，被拍平在父元素的 2D 平面上；
- `preserve-3d`：**开启并保留子元素的 3D 空间立体层级**。

---

### 3.2 致命技术陷阱：“加给亲爸爸”法则

知道要用 `preserve-3d` 很容易，但 90% 的初学者在写代码时依然会写错：**到底把 `transform-style: preserve-3d;` 加给谁？**

很多同学顺手就把 `transform-style: preserve-3d;` 加在外层最外面的大容器 `.box` 上，然后刷新发现：文字依然没凸出来，依然是贴在卡片上的！

> **核心原则**：**`transform-style: preserve-3d;` 必须严格加给发生 3D 悬浮元素的“亲爸爸”（直接父元素）！**

我们来看一下当前的 DOM 亲缘树状结构：

```text
DOM 树亲缘继承脉络
       .box (外层大舞台，提供全局透视 perspective)
         │
         ├──► .front (正面的“亲爸爸”) ──► 必须挂载 transform-style: preserve-3d !
         │       │
         │       └──► h3 / p (要悬浮凸出的亲儿子)
         │
         └──► .back (背面的“亲爸爸”)  ──► 必须挂载 transform-style: preserve-3d !
                 │
                 └──► h3 / p (要悬浮凸出的亲儿子)
```
*图 4：transform-style 的亲缘作用域与亲爸爸挂载层级*

文字元素（`h3` 和 `p`）的直接父容器是 `.front` 和 `.back`，而不是最外面的 `.box`！
如果只在 `.box` 上开启了 3D 空间，受惠的仅仅是它的直接子元素（`.front` 和 `.back`）；但如果 `.front` 和 `.back` 自身没有开启 `preserve-3d`，它们内部的子节点依然会被 `.front` 和 `.back` 各自无情地拍扁在自己的平面上！

因此，我们必须把这行声明挂载到亲爸爸身上：

```css
/* 给两个子盒子（文字的亲爸爸）开启子元素 3D 空间 */
.box .front,
.box .back {
  /* 核心命令：开启并保留亲儿子的 3D 空间立体呈现 */
  transform-style: preserve-3d;
}
```

加上这行代码之后，再刷新页面测试：
奇迹出现了！卡片正面的文字标题瞬间像凌空浮雕一样，笔直地拔地而起，悬停在卡片前方 `60px` 的虚空中；当鼠标移上去卡片翻滚时，文字与卡片底板以不同的视角速率产生震撼的**全息视差漂移**，极其逼真、极富科技感！

## 4. 3D 悬浮文字的空间穿透与二次背面隐藏

然而，当我们仔细观察整个翻转过程时，又会发现一个新的穿帮漏洞：

**当卡片翻转到背面时，正面凸出的文字因为悬浮在 `Z = 60px` 的高处，卡片底面虽然转过去了，但文字却从卡片背后“穿透”露了出来，白白悬在画面上！**

为什么会这样？
因为我们在上一讲中，只给卡片底板 `.front` 和 `.back` 声明了 `backface-visibility: hidden;`，而里面的标题 `h3` 自身是一个独立的 3D 图层，它并没有设置背面隐藏！当整个复合体翻转过去时，悬空的文字背面对着屏幕，由于默认是 `visible`，自然就赤裸裸地暴露在视野里了。

> **解决方案**：不仅外层盒子要设置背面隐藏，**内部悬浮的文本图元也必须同步声明 `backface-visibility: hidden;`**！

```css
/* 内部文字同样开启背面隐藏，防止翻转到背面时穿透露馅 */
.box .front h3,
.box .back h3,
.box .back p {
  backface-visibility: hidden;
}
```

加上之后，当卡片翻转超过 90 度时，卡片底板与悬浮文字同步被渲染器剔除，视觉穿帮彻底消除！

## 6. CSS 3D 核心属性配合关系全景剖析

至此，我们已经把 CSS3 中全部的核心 3D 特性串联成了一套坚固的知识网络。为了让大家建立清晰的空间认知拓扑，我们将这组核心属性的层级归属与职能清单整理如下：

| 属性名称 | 挂载对象 | 核心作用与底层机理 | 缺省或书写错误后果 |
| :--- | :--- | :--- | :--- |
| **`perspective`** | 外层舞台容器（如 `.box`） | 确立模拟人眼视距，构建近大远小的 3D 投影舞台 | 整个场景退化为正交平行投影，无立体景深感 |
| **`transform: rotateY/X`** | 旋转图层（如 `.front / .back`） | 驱动元素绕指定物理轴线偏转角度，实现翻转翻面 | 无法产生空间角度变化 |
| **`transform: translateZ/3d`** | 悬浮子图层（如 `h3 / p`） | 控制图元在垂直屏幕深度方向的位移；`3d` 强制 GPU 加速 | 文字或图元无法产生悬浮距离，永远贴在底面 |
| **`transform-style: preserve-3d`** | **悬浮图元的直接父级（亲爸爸）** | 打破浏览器的扁平化压制，保留子元素的 3D 独立坐标层级 | 子元素的三维位移被强制拍扁在 2D 平面，立体感崩溃 |
| **`backface-visibility: hidden`** | **所有需要防穿透的旋转图元及内容** | 元素旋转角超过 90° 进入背面时，硬件光栅化自动剔除 | 翻转后背面文字镜面穿透，正反两面重叠混乱 |

---

### 7.1 练习题目：翻转卡片案例（练习案例 01）

- **练习目标**：脱离本文的代码照抄模式，独立完成一个包含前后翻转、视差悬浮、阴影拟真的 3D 翻转卡片组件。
- **技术验收标准**：
  1. 卡片具有合理的视距设定（推荐 `perspective: 1000px`）；
  2. 运用左手法则正确处理正反两面的初始角度与悬停旋转角度（正面到 `-180deg`，背面从 `180deg` 回到 `0deg`）；
  3. 卡片内至少包含一层大标题和一层说明文本，分别设置不同深度的 `translateZ`（如 `50px` 和 `30px`），形成阶梯式全息视差；
  4. 严格遵守“亲爸爸挂载法则”，在正确图层上声明 `transform-style: preserve-3d`；
  5. 翻转过程中无文字镜面穿透或内容遮挡穿帮，动画过渡流畅细腻。
