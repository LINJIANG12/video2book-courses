第五篇我们玩的是动效，玩得很爽，但我得问你们一个扎心的问题：你们做的页面，到底有多少人是在电脑上看的？看看你们自己，一天摸手机几个小时，开电脑几个小时？数据早就说明白了，移动端流量早就超过 PC 端了。所以第六篇我们换战场，专门啃移动端开发。开篇我先带你们看这一篇最后要交出的东西，再从最底层的视口（视口，viewport）标签讲起。

---

### 1. 第六篇案例演示与学习路线

#### 1.1 优医问诊移动端项目演示

第六篇我们要完整做一个真实的移动端项目：优医问诊。你们现在看这个成品：顶部是 fixed 吸顶的导航栏，中间是问诊医生列表卡片，底部是固定切换栏，整个页面只能上下滑，左右纹丝不动，字号图标在不同手机上看过去大小永远得体。

我为什么选问诊项目当案例？三个理由。第一，它是标准的移动端版式：顶栏加内容加底栏，你们学会这一个，电商、社交、外卖的移动页全是这个骨架；第二，它里面有大量列表、表单、吸顶切换，正好把移动端布局的硬骨头一次啃完；第三，它是真实线上项目的简化版，做完你们简历上就能写一笔。你们跟着我从零做到上线，别跳步，跳一步后面就接不上了。

#### 1.2 移动端与 PC 端开发的差异

同样是写 HTML 和 CSS，移动端和你们之前学的 PC 端有三处根本不同。第一，屏幕宽度不固定：PC 端我们敢写 1200 像素版心居中，移动端从 320 到 430 像素什么宽度都有，写死宽度就是找死，必须用相对单位做适配。第二，没有鼠标悬停：`hover` 在手机上基本失效，交互要靠点击和滑动。第三，也是今天这一讲的核心：手机浏览器里装着一个"视口"系统，不加视口标签，你写的页面在手机上会被缩成一团。

```text
同一段页面在手机上的两种命运

加了视口标签：                      没加视口标签：

+----------+                        +----------+
| 正常排版  | 宽度 = 手机宽度          | 缩略全景 | 宽度 = 980px 被压缩显示
| 字号可读  | 一屏只显示一屏的内容     | 字小如蚁 | 用户只能双指放大硬看
+----------+                        +----------+
```

读图说明：视口标签决定了手机浏览器用多宽的画布来装你的页面，加与不加是天壤之别。

---

### 2. 视口标签的三个视口概念

#### 2.1 布局视口与视觉视口

手机浏览器里其实藏着两个宽度。布局视口（布局视口，layout viewport）是浏览器用来排版的画布宽度，默认 980 像素——这是当年为了让手机能看懂为 PC 设计的网页，硬塞的一个兼容宽度。视觉视口（视觉视口，visual viewport）是用户眼睛实际看到的区域宽度，也就是手机屏幕的 CSS 宽度，比如 375 像素。

没加视口标签时，浏览器按 980 像素排好版，再整体压缩塞进 375 像素的屏幕里，字能看清才怪。你们一定见过这种页面：打开全是密密麻麻的小字，必须双指放大才能看，那就是没写视口标签的 PC 老页面。

#### 2.2 理想视口与 meta 书写

理想视口（理想视口，ideal viewport）就是让布局视口等于设备宽度的状态：浏览器按手机真实宽度排版，一屏显示一屏的内容，字号该多大就多大。请你们把下面这行代码背下来，这是所有移动端页面的开场白：

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0">
```

拆开看：`width=device-width` 让布局视口宽度等于设备宽度；`initial-scale=1.0` 让初始缩放比为 1，不放大也不缩小。这两个值一配，布局视口、视觉视口、理想视口三者合一，页面在手机上就站直了。

> **定义**：视口标签是通过 `meta` 元素声明的视口规则，`width=device-width` 将布局视口设为设备宽度，`initial-scale=1.0` 将初始缩放设为 1，两者配合得到与设备宽度一致的理想视口。

| 参数 | 取值 | 作用 |
| :--- | :--- | :--- |
| `width` | `device-width` | 布局视口等于设备宽度 |
| `initial-scale` | `1.0` | 初始不缩放 |

> **易错点**：这行 `meta` 必须放在 `head` 里，而且是所有移动端页面的标配，新建页面先写它再写别的。很多人页面在手机上发虚变形，查半天样式，最后发现是这行没写，白白浪费一小时，你们不要重蹈覆辙。

---

### 3. 视口标签的验证方法

光会背不行，你们要会验。方法很简单：写一个宽 `100px` 的盒子，不加视口标签用手机模式打开，再加了视口标签打开，对比两次的表现。或者直接看：不加标签时页面整体被缩小，横向能左右晃；加了标签后页面顶满屏幕宽度，横向纹丝不动，纵向正常滚动。

> **结论**：视口标签是移动端的第一块砖，没有它，后面所有的适配单位都立不住。下一讲我们继续往下挖：为什么同样是 375 像素宽，有人说它是 750？物理像素（物理像素，physical pixel）和 CSS 像素到底是什么关系，设计稿又该按什么尺寸出？

## 第 2 章：138-移动端基础知识-物理像素和css像素以及设计稿设置
> 对应分集：P139 | 原始标题：《138-移动端基础知识-物理像素和css像素以及设计稿设置》

上一讲我们把视口标签加上，页面在手机上站直了。但紧接着就有同学问我：老师你说 iPhone 宽度 375，可网上都说 iPhone 是 750 分辨率，到底谁在说谎？问得好，今天这一讲就是来断这个案的。断完这个案，你们就明白设计稿为什么按 375 出，量出来的尺寸为什么要除以二。

---

### 1. 物理像素与 CSS 像素的划分

#### 1.1 物理像素的硬件含义

物理像素（物理像素，physical pixel）是屏幕硬件上真实存在的发光点，出厂就定死了，谁也改不了。iPhone 6 的屏幕横向有 750 个发光点，它的物理分辨率宽度就是 750。这就好比你家地板砖，砖是早就铺好的，一块就是一块。

#### 1.2 CSS 像素的软件含义

CSS 像素（CSS 像素，CSS pixel）是我们写代码时用的逻辑单位。你写 `width: 375px`，浏览器排版时用的是 375 个逻辑格子。还是地板砖的比方：CSS 像素是你拿尺子量的"我要铺多宽"，物理像素是实际铺下去用了多少块砖。

在一台标准 PC 显示器上，一个逻辑格子正好对应一个发光点，1 比 1，谁也不欠谁。但在手机上，为了把画面做细腻，厂商往同样大小的屏幕里塞了更多发光点，一个逻辑格子底下压着 2 个甚至 3 个发光点。于是就有了这个公式：

$$DPR = 物理像素 / CSS 像素$$

设备像素比（设备像素比，DPR）等于物理像素除以 CSS 像素。iPhone 6 横向 750 个发光点对应 375 个逻辑格子，DPR 就是 2，也就是传说中的二倍屏（比如 iPhone 6 / 7 / 8）。Plus 系列横向 1242 个发光点对应 414 个逻辑格子，DPR 是 3，叫三倍屏。

```text
二倍屏下一个 CSS 像素的构成（侧视示意）

CSS 像素（逻辑 1 格）：
+-----------+
|           |
+-----------+
由 2 x 2 = 4 个物理像素拼成：
+-----+-----+
| 发光 | 发光 |
+-----+-----+
| 发光 | 发光 |
+-----+-----+
```

读图说明：二倍屏上你写的 1 像素宽，实际由 4 个硬件发光点渲染，所以画面比 PC 细腻得多。

> **定义**：物理像素是屏幕硬件的发光点数，CSS 像素是浏览器排版用的逻辑单位，设备像素比是前者除以后者的比值，描述了一块屏幕的细腻程度。

---

### 2. 高清屏下的图片与边框处理

#### 2.1 二倍图与三倍图

明白了 DPR，图片模糊的问题就破案了。你们有没有遇到过：同一张图在电脑上好好的，到手机上就发虚？原因就是你给了一张 100 发光点的小图，手机却要拿 200 个发光点去显示它，一个点掰成四个用，不糊才怪。

解法就是二倍图（比如 200 像素的图显示在 100 像素的盒子里）：准备比显示尺寸大 DPR 倍的图片。显示 100 逻辑像素宽的图片，就准备 200 物理像素宽的图；三倍屏就准备 300 的。宁可大图小用，不可小图大用，多出来的像素只会让画面更锐，不会浪费。

#### 2.2 一像素边框的发虚问题

同理，你写的 `1px` 边框在二倍屏上实际占 2 个发光点，看着比 PC 上粗一圈。极致的做法是用媒体查询或者 `transform: scale(0.5)` 把线压细，但现阶段你们记住原理就行：不是你的代码写错了，是屏幕细腻了。等后面做项目遇到视觉稿里的"一像素线"，自然就知道该上二倍图的思路了。

### 3. 设计稿尺寸的选定与测量换算

#### 3.1 为什么按 375 出设计稿

好，终极问题来了：设计师给我们出图，到底按 750 出还是按 375 出？答案是：设计稿按 750 物理像素画（因为作图软件里画的是发光点），我们前端按 375 逻辑像素写（因为代码里用的是 CSS 像素）。同一张稿子，两种读法，中间差一个 DPR 等于 2。

为什么偏偏是 375？因为 iPhone 6 / 7 / 8 这一代机型存量最大，375 是移动端最主流的逻辑宽度。以它为基准，往小兼容 320，往大兼容 414 和 430，偏差都不大。设计师说"这稿是 750 的"，你们心里自动翻译成"按 375 写"，这就是行话。

#### 3.2 量出数值除以二

落到实操就一句话：从 750 设计稿上量出多少像素，代码里写一半。量出来按钮宽 200，就写 `width: 100px`；量出来字号 32，就写 `font-size: 16px`。图片呢？切图时按原尺寸切（200 的图直接用），显示时收进 100 的盒子，二倍图自然成立，一举两得。

> **易错点**：最常见的翻车是拿 750 的数值直接写进代码，页面在手机上大一倍，还满屏找 bug。每次从设计稿量完，先问自己一句：除以二了吗？养成这个肌肉记忆，能躲掉一半以上的移动端返工。

> **结论**：物理像素是砖，CSS 像素是尺，DPR 是换算率，375 是尺码基准。下一讲我们解决最后一个问题：页面宽度从 320 到 430 来回变，写死的 375 像素迟早不够用，怎么让页面自己跟着屏幕伸缩？答案就是 vw 适配（vw 适配）加自动换算插件。

## 第 3 章：139-vw适配单位以及px转换vw插件安装
> 对应分集：P140 | 原始标题：《139-vw适配单位以及px转换vw插件安装》

上一讲我们定下了 375 的尺码基准，但有个问题我一直压着没说：你按 375 写死的页面，放到 320 的小屏上会溢出，放到 430 的大屏上两边露白。难道要给每个宽度各写一套样式？那得写到猴年马月。今天这一讲就把这个结解开：用 vw（视口宽度单位，viewport width）做适配，再装一个插件让 px 自动转 vw，从此量多少写多少，爽到飞起。

---

### 1. vw 适配单位的换算原理

#### 1.1 vw 与 vh 的定义

vw 是把视口宽度切成 100 份，`1vw` 就是视口宽度的 1%。手机宽 375，`1vw` 等于 3.75 像素；手机宽 414，`1vw` 等于 4.14 像素。单位自己跟着屏幕变，这就是适配的命根子。vh（视口高度单位，viewport height）同理，是把视口高度切成 100 份，之前做滚动叠加卡片时 `100vh` 铺满一屏，你们已经用过它了。

> **定义**：视口宽度单位 vw 将视口宽度等分为 100 份，`1vw` 等于视口宽度的 1%，其像素值随视口宽度自动伸缩，是移动端等比适配的核心单位。

#### 1.2 设计稿数值的 vw 换算

换算公式只有一行：

$$目标vw = 设计稿px / 设计稿基准 * 100$$

按 375 基准，稿子上一个 100 像素宽的按钮就是 `100 / 375 * 100 = 26.67vw`。你们品一下这个式子的妙处：分子是稿子上的死数，分母是当前手机的活宽度，手机变宽，算出来的像素值跟着变大，按钮永远占屏幕同样的比例。320 的小屏和 430 的大屏，看到的是同一个等比缩放的页面。

```text
同一按钮在不同宽度手机上的等比表现

375 宽手机：  按钮 26.67vw = 100px   [======按钮======]
320 宽手机：  按钮 26.67vw = 85px    [=====按钮=====]
430 宽手机：  按钮 26.67vw = 115px   [========按钮========]
```

读图说明：vw 数值不变，像素值随屏幕伸缩，按钮占屏比例永远一致。

那高度呢？记住：宽高统一用 vw 算，不要宽用 vw、高用 vh，否则横竖比例一变，图就压扁了。全页面的尺寸都从宽度这一把尺子里量出来，比例永远锁死。

---

### 2. px 转 vw 插件的安装与配置

#### 2.1 为什么必须装插件

道理都懂，但你们算一笔账：一个页面几十个尺寸，每个都要拿计算器按一遍 `px / 375 * 100`，还要保留两位小数，这活人干得了吗？干得了也得疯。所以前端工程里这种机械换算一律交给插件：我们照常写 px，保存时插件自动翻译成 vw。

#### 2.2 插件安装与基准配置

我带你们装的是 VS Code 里的 px 转 vw 插件（扩展市场搜 px to vw 类扩展，或工程化里的 PostCSS 插件 `postcss-px-to-viewport`，两派原理相同）。安装就三步：第一，扩展市场搜名字点安装；第二，进设置把视口基准宽度（viewportWidth）改成 `375`，和我们的设计稿基准对齐；第三，确认转换精度，一般保留 2 到 4 位小数。

```css
/* 你亲手写的： */
.btn {
  width: 100px;
  height: 44px;
  font-size: 16px;
}

/* 保存后插件自动翻译成的： */
.btn {
  width: 26.67vw;
  height: 11.73vw;
  font-size: 4.27vw;
}
```

你们看，注释、属性名原样保留，只有数值被换成了 vw。这就是插件的全部工作：忠实的翻译官，不改你的任何意图。

> **提示**：装完插件第一件事就是检查基准宽度是不是 375。基准配错，比如配成了 750，算出来的 vw 会小一半，页面整体缩水。出了"页面怎么整体小一圈"的问题，先查这个配置，十次有九次是它。

---

### 3. 插件工作流与无需转换的例外

#### 3.1 日常书写流程

配好之后流程极顺：从 750 设计稿量出数值，除以二得到 CSS 像素，照常写 px，保存，插件自动转 vw，你们连计算器都不用打开。边框 `1px` 这种极细的值，插件一般有最小转换阈值（比如 1 像素以下不转），正好把发丝线保下来，误打误撞还办了件好事。

#### 3.2 不需要转换的场景

有两个东西不要进 vw。第一，`font-size` 在部分方案里会用固定值保底，但按我们这套全 vw 方案，字号跟着转是没问题的，照转就行；第二，`border` 的 1 像素线和圆角里的极小值，靠阈值拦下来就行，不用手动干预。记住原则：插件是默认全转、阈值保底，你们只管写，特殊的再单独处理。

| 写法对象 | 处理方式 | 原因 |
| :--- | :--- | :--- |
| 宽高、间距、字号 | 自动转 vw | 需要跟随屏幕伸缩 |
| `1px` 边框线 | 阈值保留不转 | 发丝线转完会糊 |
| `transform` 位移 | 按需决定 | 与布局伸缩无关时可不转 |

> **易错点**：插件只认你写的 px 数值，如果你忘了先除以二，把 750 稿上的 200 直接写进去，插件会忠实地翻译成一个大一倍的 vw，页面照样撑爆。插件是翻译官，不是质检员，除以二这一步永远是你们自己的责任。

> **结论**：vw 解决"怎么伸缩"，插件解决"谁来算"。到这一讲，移动端的地基彻底打完了：视口标签摆正画布，375 定死尺码，vw 加插件实现全屏适配。下一讲我们直接开工，用这套装备从零盖起优医问诊项目，准备好你们的编辑器。

### 2. 渐变背景与标题行样式

#### 2.1 绿色线性渐变铺底

渐变用线性渐变（linear-gradient），方向自上而下，从亮绿过渡到深绿。写的时候先写 px，插件会自动转 vw，这就是上一讲配环境的意义——我们只管按设计稿量，单位的事交给工具：

```css
.home-header {
  background: linear-gradient(180deg, #2edf9e 0%, #22c484 100%);
  padding: 15px 12px 30px;
}
```

> **结论**：移动端头部的渐变一定写在容器上，而不是每行内容各写一段。只有容器持有完整渐变，标题行和搜索框压在上面，色彩过渡才是连贯的一整片。

#### 2.2 标题行弹性布局

标题行是典型的左右两端对齐：左边标题，右边图标。弹性布局（flexbox）一行搞定，主轴两端对齐、交叉轴居中：

```css
.home-header .title {
  display: flex;
  justify-content: space-between;
  align-items: center;
}
.home-header .title h1 {
  font-size: 20px;
  color: #fff;
  font-weight: 600;
}
.home-header .title .msg {
  width: 24px;
  height: 24px;
  background: url(../images/msg.png) no-repeat center / contain;
}
```

你们看，标题是白色压在绿底上，对比足够，字号 `20px` 在 375 的稿子里正好压得住场。消息图标固定 `24px` 见方，背景图用 `contain` 完整呈现，图标再小也不会被裁掉一半。

> **提示**：背景图简写 `center / contain` 里的斜杠不能丢，斜杠前面是位置，后面是尺寸。丢了斜杠，浏览器会把 `contain` 当成重复方式解析，图直接没了。

搜索框是一个白色圆角长条，里面左边是放大镜图标，右边是灰色提示字。结构上图标和文字是左右关系，同样用 flex，交叉轴居中，文字颜色用浅灰，和白色底拉开一点距离就够了：

```css
.home-header .search {

  align-items: center;
  height: 38px;
  margin-top: 12px;
  padding: 0 14px;
  background-color: #fff;
  border-radius: 19px;

.home-header .search i {
  width: 16px;
  height: 16px;

.home-header .search span {
  margin-left: 8px;

}
```

圆角取高度的一半（`38px` 高配 `19px` 圆角），长条两端就是标准的胶囊形。这个"高度一半即胶囊"的结论，移动端搜索框、按钮、标签页通用，记住一条，处处能用。

## 第 6 章：142-优医问诊项目-头部区域制作完成以及转换vw
> 对应分集：P143 | 原始标题：《142-优医问诊项目-头部区域制作完成以及转换vw》

上一讲我们把 `home-header` 的骨架立起来了：渐变容器、标题行、搜索框，三样都有了。但你们把页面往设计稿上一叠就会发现，还差一口气——搜索框里的放大镜和文字好像没对齐，头部底部那截绿还露得太多。这一讲我们先把这两处细节收掉，然后干一件大事：亲眼看着插件把整片 px 批量转成 vw。

我知道你们有人手痒，想直接手写 vw。千万别。设计稿量出来是多少 px 就写多少 px，让工具转。人的心算会错，工具不会，而且后面设计稿一改，我们改 px 重存就行，这才是工程化的写法。

### 1. 头部细节收尾

#### 1.1 搜索框内部对齐修正

搜索框里图标 `16px`、文字 `13px`，两者高度不一样，只靠 `align-items: center` 还不够，文字那一侧往往还会偏下半个像素。解决办法是给文字单独设一个行高，让它和图标在同一基线上：

```css
.home-header .search span {
  margin-left: 8px;
  font-size: 13px;
  line-height: 1;
  color: #999;
}
```

> **易错点**：`line-height: 1` 不是偷懒，是精确控制。文字默认行高比字号大一圈，多出来的半行距会把它往下顶。行高锁死为字号本身，文字和图标才能严丝合缝地居中。

#### 1.2 头部底部留白控制

头部底部的绿色不是装饰，是给导航栏"上浮压住"预留的舞台。底部内边距要留得比视觉稿多一点，多出来的部分会被导航栏的白色卡片盖住，形成卡片压在绿底上的层次感：

```css
.home-header {
  background: linear-gradient(180deg, #2edf9e 0%, #22c484 100%);
  padding: 15px 12px 40px;
}
```

底部 `40px` 看着多？别急，下一讲导航栏用负边距往上提，实际露出来的绿就刚刚好。移动端这种"上面留白、下面上浮"的配合，是卡片式布局的常规手法，先留后压，顺序别反。

### 2. px 批量转换为 vw

#### 2.1 转换前后对照

保存文件，插件自动重写所有 px。我们抽几个关键值验算，确认它没偷工减料。换算公式是 `$vw = px ÷ 375 × 100$`：

| 属性 | 转换前 | 转换后 | 心算验证 |
| :--- | :--- | :--- | :--- |
| `:---` | `:---` | `:---` | `:---` |
| 标题字号 | `20px` | `5.3333vw` | `20 ÷ 3.75 = 5.3333` |
| 搜索框高 | `38px` | `10.1333vw` | `38 ÷ 3.75 = 10.1333` |
| 左右内边距 | `12px` | `3.2vw` | `12 ÷ 3.75 = 3.2` |
| 图标尺寸 | `24px` | `6.4vw` | `24 ÷ 3.75 = 6.4` |

```css
/* 插件转换后的 home-header（摘录） */
.home-header {
  background: linear-gradient(180deg, #2edf9e 0%, #22c484 100%);
  padding: 4vw 3.2vw 10.6667vw;
}
.home-header .title h1 {
  font-size: 5.3333vw;
}
```

> **结论**：凡是长度、字号、圆角、边距，插件全转；颜色、渐变角度、背景图路径，插件一概不动。转的是尺寸，不转的是表现，这个边界要清楚。

#### 2.2 哪些值不能转

有两处要手动干预。第一，`1px` 的细边框在某些机型上转成 `0.2667vw` 会被渲染成 0 而消失，这种描边线建议保留 px 或改用 `border` 配合 `transform` 缩放；第二，`line-height: 1` 这种无单位值本来就不用转，插件也不会碰它。转换完通读一遍文件，看到 `0.2667vw` 的边框就要警觉。

```text
导航栏上浮示意 (侧视图)

|                            |
|   home-header (绿底)       |
|............................|
|  +----------------------+  |  <- nav 卡片上浮,
|  |  nav (白色圆角卡片)  |  |     盖住头部底部
```

### 2. 第一行五等分布局

#### 2.1 flex 均分与图标尺寸

一行 5 个入口，最干净的写法是 flex 容器，每个 `li` 占一份。`flex: 1` 让五个格子自动均分，屏幕从 375 缩到 320，每个格子跟着等比变窄，图标和文字永远居中：

```css
.nav-row {
  display: flex;
  padding: 14px 0 10px;
}
.nav-row li {
  flex: 1;
}
.nav-row li a {
  display: flex;
  flex-direction: column;
  align-items: center;
}
.nav-row li img {
  width: 48px;
  height: 48px;
}
.nav-row li p {
  margin-top: 6px;
  font-size: 12px;
  color: #333;
}
```

> **定义**：主轴（main axis）是 flex 容器默认的横向排列方向。这里 `li` 沿主轴一字排开 5 个；`a` 内部把主轴转成纵向（`flex-direction: column`），图标在上、文字在下。两个方向各管一层，互不干扰。

图标 `48px` 是设计稿量出来的，圆角图标自带彩色底，视觉上已经足够醒目。文字 `12px` 是移动端辅助文字的标准字号，再小就看不清了，再大一行五个就挤了。

#### 2.2 间距取舍

你们注意，`li` 之间我没有加 `gap`，也没有加左右 margin。为什么？五个 `flex: 1` 的格子本身就是均分的，格子之间的空隙天然相等。图标在格子里居中，间距自动均匀。移动端这种"等分格子 + 内容居中"的模式，比手动算 margin 省心得多，也永远不会出现最后一个被挤掉下去的惨剧。

### 2. 行间距与卡片收尾

#### 2.1 两行之间的间距归属

两行之间的空隙，正确做法是给第一行加 `margin-bottom`（或者给容器加统一的上下 padding 配合行间距），而不是给第二行加 `margin-top`。理由很实际：将来如果产品说"先上线一行，第二行下个版本再上"，删掉第二行时，第一行的底部间距依然完整，页面不会塌。

```css
.nav {
  margin: -20px 12px 0;
  padding: 14px 0 16px;
  background-color: #fff;
  border-radius: 10px;
  box-shadow: 0 2px 8px rgba(0, 0, 0, 0.06);
}
.nav-row {
  display: flex;
}
.nav-row + .nav-row {
  margin-top: 12px;
}
```

`.nav-row + .nav-row` 这个相邻兄弟选择器很有味道：它只命中"前面还有一行的行"，也就是天然选中第二行及以后。以后加第三行、第四行，间距自动跟上，不用补样式。

#### 2.2 图标对齐的隐形保证

上下两行图标能对齐，不是因为我们算过，而是因为两行的 `li` 都是 `flex: 1` 五等分。格子宽度完全一致，图标又都在格子里居中，对齐是数学上的必然。反过来，如果某一行的图标尺寸写错了，比如第二行写成 `46px`，对齐立刻就破。所以检查方法很简单：两行图标尺寸必须同一个数，`48px` 就是 `48px`，一个都不能差。

```text
导航栏整体完工形态

|  (绿)                                    |
| +--------------------------------------+ |
| | [图] [图] [图] [图] [图]  第一行    | |
| | 在线 预约 名医 药品 健康              | |
| |                                      | |
| | [图] [图] [图] [图] [图]  第二行    | |
| | 体检 疫苗 慢病 报告 资讯              | |
| +--------------------------------------+ |
+------------------------------------------+
```

读图说明：白色卡片内两行各 5 个入口，行间距一致，图标列上下对齐，卡片上浮压住绿底——导航栏至此完工。

## 第 9 章：145-优医问诊项目-banner模块和tabs模块开始
> 对应分集：P146 | 原始标题：《145-优医问诊项目-banner模块和tabs模块开始》

导航栏刚写完，页面往下翻是什么？一张大大的活动横幅（Banner），再往下是一排可以左右滑动的科室选项卡（Tabs）。你们发现没有，移动端首页几乎都是这个套路：导航负责分流，横幅负责吸睛，选项卡负责承接内容。我这一讲就带你们把这两块一次搭起来，结构先行，样式后面再精修。

### 1. Banner 模块的结构与盒子关系

先看横幅这一块，它看着简单，其实最容易把盒子套错。记住我的习惯：凡是带左右留白、带圆角的大图，一律用“外层包裹层（Wrapper）+ 内层图片”两层结构，不要直接给 `img` 加 margin。

```text
+-------------------------------------+
|  .banner (外层, padding 10px 11px)   |
|  +-------------------------------+  |
|  |  a > img (圆角 10px, 宽100%)  |  |
|  +-------------------------------+  |
+-------------------------------------+
```

读图说明：外层 `.banner` 只管留白和占位，内层图片只管撑满和圆角，分工一清楚，后面切不同尺寸的图都不会乱。

结构代码我一般这样写：

```html
<!-- banner 横幅模块 -->
<div class="banner">
  <a href="#">
    <img src="./assets/images/banner.png" alt="优医问诊活动横幅" />
  </a>
</div>
```

你们可能会问，包一层 `a` 干嘛？移动端横幅几乎全是可点击的，直接把锚点（Anchor）写好，后面加跳转链接不用返工。

样式上三行就够：

```css
.banner {
  padding: 10px 11px 0;
}
.banner img {
  width: 100%;
  border-radius: 10px;
  vertical-align: middle;
}
```

> **易错点**：`img` 是行内替换元素，底部默认有一条基线（Baseline）空隙，图片下面会莫名多出几像素白边。加一句 `vertical-align: middle` 就压住了，你们以后看到图片底部漏缝，先想这一句。

> **提示**：这里的 `10px`、`11px` 是设计稿量出来的像素（Pixel，px）值。我们的 `px` 转视口宽度（Viewport Width，vw）插件已经配好，保存时会自动换算成 `vw`，你们照着量、照着写 `px` 就行，不用自己算。

### 2. Tabs 模块的外层骨架搭建

横幅下面就是选项卡。这一块我先只搭“切换栏 + 内容区”的大骨架，细节下两讲再填。你们一定要养成这个节奏：一口气想把所有样式写完，准乱；先把父子关系立住，再逐层细化。

```text
+-------------------------------+
|  .tabs                        |
|  +-------------------------+  |
|  | .tabs-head (切换栏)     |  |
|  |  a.active / a           |  |
|  +-------------------------+  |
|  +-------------------------+  |
|  | .tabs-content (内容区)  |  |
|  |  卡片列表, 下讲再写     |  |
|  +-------------------------+  |
+--------------------------------+
```

读图说明：`.tabs` 是总容器，头和内容是兄弟关系，切换栏只管点选，内容区只管展示卡片。

代码骨架：

```html
<!-- tabs 选项卡模块 -->
<div class="tabs">
  <div class="tabs-head">
    <a class="active" href="#">关注</a>
    <a href="#">推荐</a>
    <a href="#">儿科</a>
    <a href="#">内科</a>
  </div>
  <div class="tabs-content">
    <!-- 卡片内容下一讲填充 -->
  </div>
</div>
```

为什么切换栏用一排 `a` 而不用 `button`？一是移动端选项卡点一下一般也要跳筛选页，锚点语义正合适；二是用链接做切换，后面配合高亮类名（Active Class）写选中态最省事。

> **结论**：这一讲不求好看，只求盒子套对。你们写完对照检查两件事：横幅是不是“外层留白、内层圆角”，选项卡是不是“头和内容平级、链接并排”。这两处对了，后面几讲全是顺水推舟。

## 第 10 章：146-优医问诊项目-移动端tabs选项卡布局方式
> 对应分集：P147 | 原始标题：《146-优医问诊项目-移动端tabs选项卡布局方式》

上一讲我们把 `.tabs-head` 的骨架搭出来了，一排 `a` 往那一放，问题马上就来了：在 375 宽的设计稿里塞五六个科室还行，塞十几个怎么办？挤成一团还是能滑？你们做移动端选项卡，逃不过这道选择题。我这一讲就把三种做法一次讲透，你们以后看到任何 App 的横向选项卡，都能一眼看穿它用的是哪一套。

### 1. 三种布局方式的对比选型

先给结论，再讲写法。横向选项卡（Tabs）在移动端的布局就三种，你们按“数量固不固定”来选：

| 布局方式 | 核心写法 | 适用场景 | 短板 |
| :--- | :--- | :--- | :--- |
| 弹性均分 | 弹性盒子（Flexible Box，`display: flex`）+ 子项 `flex: 1` | 数量固定、一般 3～5 个，如“关注 / 推荐 / 儿科” | 数量一多就被压扁，字都叠在一起 |
| 定宽横向滚动 | 子项定宽 + 父级 `overflow-x: auto` | 数量不固定、 coupons 科室很多，需要左右滑动 | 要处理滚动条隐藏，低端机滑起来略生硬 |
| 等分加滚动兜底 | `flex` 均分打底，超出后允许滚动 | 又想均分好看、又怕以后加栏目 | 代码稍多，新手容易把两套属性写冲突 |

我们这个优医问诊的切换栏，科室数量是会长的，今天四个，明天可能八个，所以我直接选第二种：定宽加横向滚动。这也是你们以后最常用的移动端选项卡写法，记住它。

### 2. 定宽横向滚动的具体写法

思路一句话：父级不换行、允许横向滚动，子级定宽不收缩。字符画把这个关系画出来：

```text
视口 (375px, 只显示一部分)
+----------------------------------+
| [关注] [推荐] [儿科] [内科] | ...> |  -->  overflow-x: auto
+----------------------------------+
   子项 flex: none / width 固定, 不被压缩
```

读图说明：视口像一个小窗口，里边是一条长长的横向长条，手指左右滑看到更多栏目。

代码：

```html
<div class="tabs-head">
  <a class="active" href="#">关注</a>
  <a href="#">推荐</a>
  <a href="#">儿科</a>
  <a href="#">内科</a>
  <a href="#">外科</a>
  <a href="#">皮肤科</a>
</div>
```

```css
.tabs-head {
  display: flex;
  overflow-x: auto;
  padding: 0 11px;
  background-color: #fff;
}
.tabs-head a {
  flex: none;
  padding: 10px 8px;
  font-size: 14px;
  color: #333;
}
.tabs-head a.active {
  color: #16c2a3;
  font-weight: 700;
}
```

> **易错点**：只写 `display: flex` 不写 `flex: none`，子项会被弹性盒子强行压缩，六个栏目挤在一屏里，字全叠了。移动端横向滚动列表，子项一定要“不伸不缩”，这一条给我记住。

> **提示**：滚动条（Scrollbar）在手机模拟器里会露出来一条灰线，很丑。补一句隐藏滚动条的写法即可，标准写法配合私有前缀一起写，兼容性最稳：

```css
.tabs-head::-webkit-scrollbar {
  display: none;
}
.tabs-head {
  scrollbar-width: none;
}
```

### 3. 选中指示线的定位做法

光变颜色还不够，设计稿里选中项底下还有一条小绿线（Indicator）。做法也是固定的：给 `a` 加相对定位（Relative Position），用伪元素（Pseudo-element）`::after` 画线。

```css
.tabs-head a.active {
  position: relative;
}
.tabs-head a.active::after {
  content: "";
  position: absolute;
  left: 50%;
  bottom: 4px;
  width: 24px;
  height: 3px;
  background-color: #16c2a3;
  border-radius: 2px;
  transform: translateX(-50%);
}
```

你们看，`left: 50%` 配 `transform: translateX(-50%)`，这就是居中标线的万能公式，不管文字两个字还是三个字，线永远居中。千万不要用固定 `left: 10px` 去凑，换个栏目字数就歪了。

> **结论**：移动端选项卡先看数量。数量固定就均分，数量会长就定宽加滚动。我们这个项目用滚动方案，你们把 `flex: none`、`overflow-x: auto`、隐藏滚动条、伪元素指示线这四件套背下来，以后任何 App 的横滑导航都能直接默写。

## 第 11 章：147-优医问诊项目-tabs切换内容部分开始
> 对应分集：P148 | 原始标题：《147-优医问诊项目-tabs切换内容部分开始》

切换栏点起来了，底下空着怎么行？你们想想，点“推荐”出来一堆医生卡片，点“儿科”又换一批，这就是选项卡内容区（Tabs Content）要干的事。我这一讲先把内容区的大结构铺好：外面是什么，里面一张卡片拆成哪几块，每块叫什么类名。类名一定位，后面两讲填头部、填底部就都有地方落脚了。

### 1. 内容区与卡片的嵌套关系

先看整体嵌套，很多新手一上来就写医生头像、写名字，结果父级是谁都说不清。我带你们从外往里剥三层：

```text
+-------------------------------------+
| .tabs-content (内容区, 灰底)         |
|  +--- .card (白色卡片, 圆角) ------+|
|  | .card-head (头部: 医生信息)     ||
|  | .card-body (中部: 问诊评价)     ||
|  | .card-foot (底部: 标签+按钮)    ||
|  +--------------------------------+|
|  +--- .card (第二张卡片) ---------+|
+-------------------------------------+
```

读图说明：内容区只负责“灰底 + 列表间距”，卡片只负责“白底圆角 + 内边距”，头部、中部、底部分管各自的信息行。

结构代码：

```html
<div class="tabs-content">
  <div class="card">
    <div class="card-head"><!-- 医生头像姓名, 下讲写 --></div>
    <div class="card-body"><!-- 评分问诊量, 本讲搭架 --></div>
    <div class="card-foot"><!-- 标签价格按钮, 下下讲写 --></div>
  </div>
  <div class="card">
    <!-- 第二位医生, 结构复用 -->
  </div>
</div>
```

> **定义**：卡片（Card）就是“白底圆角的小容器”，移动端列表页几乎全是卡片拼起来的。你们以后看到一屏里好几个长得一样的块，先给它起名叫卡片，再往里拆头、中、尾。

### 2. 内容区底色与卡片间距

设计稿里内容区是浅灰的，卡片是白的，一灰一白才能把卡片托出来。这个反差不能丢：

```css
.tabs-content {
  padding: 10px 11px;
  background-color: #f6f7f9;
}
.card {
  margin-bottom: 10px;
  padding: 15px 12px;
  background-color: #fff;
  border-radius: 10px;
}
```

你们注意，卡片之间的间距我用 `margin-bottom`，卡片内部的留白用 `padding`。外间距和内留白各用各的属性，别混。最后一张卡片多出来的下边距，后面做底部固定栏时再收尾，不用现在纠结。

### 3. 卡片中部的信息行骨架

头部和底部下两讲专门做，我这一讲顺手把最简单的中部搭了：就是“好评率、问诊量”那一行字，外加一句擅长描述。用 `p` 标签写两行即可，别套多余的 `div`。

```html
<div class="card-body">
  <p class="info">好评率 99% · 问诊量 2.3万</p>
  <p class="desc">擅长：儿童感冒、发热、咳嗽等常见病诊治</p>
</div>
```

```css
.card-body .info {
  font-size: 12px;
  color: #999;
}
.card-body .desc {
  margin-top: 6px;
  font-size: 13px;
  color: #333;
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}
```

> **提示**：擅长那行字很长，手机上必须单行省略。`white-space: nowrap`（不换行）+ `overflow: hidden`（溢出隐藏）+ `text-overflow: ellipsis`（省略号）三件套，缺一个都出不来省略号，你们直接背下来。

## 第 12 章：148-优医问诊项目-tabs-content头部制作
> 对应分集：P149 | 原始标题：《148-优医问诊项目-tabs-content头部制作》

卡片架子上一讲焊死了，这一讲我们填最要紧的一块：卡片头部。你们去看任何问诊 App，卡片第一眼就是“医生头像 + 名字 + 职称 + 关注按钮”，这一行要是歪了，用户对整个页面的信任感直接掉一半。所以千万别小看这几十像素，我带你们一行一行把它对齐。

### 1. 头部三段式的盒子划分

头部看着元素多，其实就三段：左边头像，中间姓名职称，右边关注按钮。用弹性盒子（Flexible Box，`display: flex`）一排摆开，中间那段自动撑满：

```text
+--------------------------------------------------+
| [头像]  王医生  主任医师  三甲医院        [+关注] |
|  50px   flex:1 (自动撑满, 垂直居中)       定宽按钮 |
+--------------------------------------------------+
```

读图说明：头像定宽定高，按钮定宽，中间文字区 `flex: 1` 把剩余空间全吃掉，这样换多长的名字都不会把按钮挤掉。

结构：

```html
<div class="card-head">
  <img class="avatar" src="./assets/images/doctor.png" alt="医生头像" />
  <div class="doc-info">
    <h4>王小医 <span>主任医师</span></h4>
    <p>北京协和医院 · 儿科</p>
  </div>
  <a class="follow" href="#">+ 关注</a>
</div>
```

你们看，名字用 `h4`（标题语义），职称和医院用 `p` 和 `span`（说明语义），语义（Semantics）顺手就带上了。不要满屏全用 `div`，搜索引擎（Search Engine Optimization，SEO）和读屏软件都靠这些标签认内容。

### 2. 头像与文字的对齐写法

```css
.card-head {
  display: flex;
  align-items: center;
}
.card-head .avatar {
  width: 50px;
  height: 50px;
  border-radius: 50%;
  object-fit: cover;
}
.doc-info {
  flex: 1;
  margin-left: 10px;
  overflow: hidden;
}
.doc-info h4 {
  font-size: 15px;
  color: #333;
}
.doc-info h4 span {
  margin-left: 6px;
  font-size: 12px;
  font-weight: 400;
  color: #999;
}
.doc-info p {
  margin-top: 4px;
  font-size: 12px;
  color: #999;
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: nowrap;
}
```

这里有三个细节你们一定要抠。第一，头像必须正圆，`border-radius: 50%` 配等宽等高，少一边都不圆；第二，`object-fit: cover` 让长方形原图按比例裁成圆脸，不加这句人物会被拉变形；第三，中间文字区加 `overflow: hidden`，医院名字再长也不会把布局撑爆，而是乖乖省略。

> **易错点**：`align-items: center` 写成 `justify-content: center` 的人最多。记住，主轴（Main Axis）默认是横向，`justify-content` 管横向的左右分布，`align-items` 管交叉轴（Cross Axis）的上下对齐。头像文字上下居中，一定是 `align-items` 的事。

### 3. 右侧关注按钮的做法

```css
.card-head .follow {
  flex: none;
  padding: 6px 12px;
  font-size: 12px;
  color: #16c2a3;
  border: 1px solid #16c2a3;
  border-radius: 15px;
}
```

描边按钮（Outline Button）三要素：文字色、边框色、圆角一次写全。圆角给 `15px` 这种超过高度一半的值，按钮两头就是标准的胶囊形。后面点击变成“已关注”的灰态，我们做交互时再切换类名，结构不用动。

> **结论**：卡片头部就是“头像定尺寸、中间自动撑、按钮不收缩”九个字。你们自查：头像圆不圆、名字职称一行还是两行、医院太长有没有省略、按钮有没有被挤扁。这四处都对，这一讲就算过关，下一讲我们做卡片底部。

## 第 13 章：149-优医问诊项目-tabs-content底部制作

头部把“这是谁”讲清了，底部就要回答“贵不贵、怎么约”。你们看设计稿，卡片最底下永远是三样东西：擅长标签、问诊价格、问诊按钮。这一块我带你们一次做完，做完一张完整的医生卡片就闭环了，直接能拿去复用十几张。

### 1. 底部两行的结构划分

底部我拆成上下两行，上面放标签，下面放价格加按钮。为什么不全塞一行？标签数量不确定，一行会被价格挤乱，分两行最稳：

```text
+----------------------------------------+
| .card-foot                             |
|  .tags: [儿科] [发热] [咳嗽]            |
|  .price-row: ￥39起  图文问诊  [去问诊]  |
```

```html
<div class="card-foot">

    <span>儿科</span>
    <span>发热</span>
```

价格数字用 `em` 包起来，语义上表示强调（Emphasis），样式上正好给它单独放大变色，一举两得。

### 2. 擅长标签的写法

```css
.card-foot .tags {
  display: flex;
  flex-wrap: wrap;

  margin-top: 10px;

.card-foot .tags span {

  color: #16c2a3;
  background-color: #e8f8f5;
```

三个点你们记一下。第一，浅底深字是标签最经典的配色，背景 `#e8f8f5`、文字 `#16c2a3`，同色系一浅一深，看着干净；第二，`flex-wrap: wrap` 允许标签换行，医生擅长十个八个也不会撑破卡片；第三，标签间距用间隙（Gap，`gap`）属性，比挨个写 `margin-right` 省事，最后一个还不会多出一截空隙。

> **提示**：`gap` 是弹性布局和网格布局（Grid）通用的间距属性，行列间距一次搞定。你们以前用 `margin` 凑间距，总要处理最后一个元素的尾巴，从现在起换 `gap`，代码少一半。

价格这里有个小反差：数字又大又红（`#f66`），“起、图文问诊”又小又灰，用户的眼睛会本能地先落在数字上，这就是价格行要的效果。记得把 `em` 默认的斜体用 `font-style: normal` 掰正，不然价格数字斜着很别扭。

## 第 14 章：150-优医问诊项目-切换模块改为粘性定位
> 对应分集：P151 | 原始标题：《150-优医问诊项目-切换模块改为粘性定位》

卡片列表越做越长，我一滑动，顶部的那排切换按钮就被顶没了。你们想想咱们手机上用的 App，哪个不是把关键选项卡吸在顶部，滑到哪都能点？我这一讲就干这一件事：把优医问诊的切换模块从普通文档流改成粘性定位（Sticky Position），让它滑到顶部就吸住。

### 1. 粘性定位的工作机理

> **定义**：粘性定位（`position: sticky`）是相对定位和固定定位的混合体，没到阈值时跟普通盒子一样随页面滚动，滚动到阈值位置就吸住不动，像被磁铁吸住一样。

我给你们画一下它和另外两个定位的区别，你们一下就记住了：

```text
+----------------+------------------+------------------+
| 相对定位     | 粘性定位         | 固定定位         |
| relative     | sticky           | fixed            |
| 不脱标       | 阈值前不脱标     | 完全脱标         |
| 跟着滚走     | 到阈值吸住       | 永远吸住         |
+----------------+------------------+------------------+
```

读图说明：三者占位和跟随行为逐级递进，粘性定位正好卡在中间，既占位置又能吸顶。

为什么这里不用固定定位？固定定位一上来就脱标， tabs 会飘在页面上压住下面的 banner，还得给父级补 `padding-top` 顶回来，多此一举。粘性定位阈值之前还在文档流里占着位置，样式不用大改，一行代码就出效果，这就是我选它的理由。

### 2. 一行代码实现吸顶

结构上切换模块是 `.tabs` 包着一排 `a`，外面是大的 `.content` 容器。改造只动 `.tabs` 自己：

```css
.tabs {
  position: sticky;
  top: 0;
  z-index: 10;
  background-color: #fff;
}
```

三行缺一不可。第一行 `position: sticky` 声明身份；第二行 `top: 0` 是阈值，告诉浏览器滚到距离视口顶部为 0 时开始吸住，你们写成 `top: 10px` 就是距离顶部 10 像素吸住；第三行 `z-index: 10` 是保险，后面的医生卡片滑上来时不能盖住选项卡。

> **易错点**：只写 `position: sticky` 不写 `top` 等于没写，浏览器不知道什么时候吸，必须配一个方向阈值，横向滚动就配 `left`，咱们这种纵向页面一律配 `top`。

背景色也一定要给。你们想想，卡片从选项卡底下穿过去，如果选项卡是透明的，字和字叠在一起糊成一片。我习惯吸顶元素顺手加 `background-color: #fff`，这条你们记住，省得以后返工。

### 3. 粘性失效的两个坑

我当年第一次用粘性定位，怎么写都不吸，查了半天，全是栽在这两个坑里，你们直接避开。

第一个坑，父级加了 `overflow: hidden`。粘性定位是相对于最近的滚动祖先工作的，父级一旦裁剪溢出，浏览器就算不出滚动距离，直接失效。咱们这个项目，`.content` 和 `body` 都不能加 `overflow: hidden`，要清浮动用 `clearfix` 或者弹性布局，别拿 `overflow` 偷懒。

第二个坑，父级高度不够。粘性元素只能在父容器范围内吸，父容器到底了，它就被顶走了。画个示意你们就明白了：

```text
+-- .content (父容器) ---------+
|  .tabs (sticky, top:0)      | <- 滚到这里吸住
|  .card 医生卡1              |
|  .card 医生卡2              |
|  .card 医生卡3              |
+-----------------------------+ <- 父容器结束, tabs 被带走
   页面继续向下滚动
```

读图说明：吸顶只在父容器高度范围内有效，父容器走完，粘性元素跟着走，不会飘到全站。

咱们这个页面，`.content` 里有十几张医生卡片，高度足够长，所以吸顶效果能持续很久。你们以后如果发现吸了一下就掉了，先检查父盒子是不是太矮了。

| 对比项 | 粘性定位 | 固定定位 |
| :--- | :--- | :--- |
| 是否脱标 | 阈值前不脱标 | 始终脱标 |
| 是否需要补间距 | 不需要 | 需要给后面补 `padding` |
| 适用场景 | 选项卡吸顶、表头吸顶 | 底部导航、返回顶部 |

## 第 15 章：151-优医问诊项目-底部固定切换模块制作
> 对应分集：P152 | 原始标题：《151-优医问诊项目-底部固定切换模块制作》

吸顶解决的是往下翻找不到入口，吸底解决的是拇指够不着操作。你们看咱们优医问诊这个首页，最底下那一排首页、问诊、我的，拇指一抬就能够到，这一讲我就带你们把这个底部切换模块做出来，全程固定定位（Fixed Position），滑到哪它都在。

### 1. 底部导航的结构划分

底部导航本质是一个固定条包着三个等分选项，每个选项是图标加文字上下叠放：

```text
+----------------------------------+
| .tabbar (fixed, bottom:0)        |
|  .item    .item    .item         |
| [图标]    [图标]    [图标]        |
|  首页     问诊      我的          |
+----------------------------------+
```

读图说明：外层通栏固定，内层三个选项均分宽度，每个选项内部图标在上、文字在下居中。

```html
<div class="tabbar">
  <a class="item active" href="#">
    <i class="iconfont icon-home"></i>
    <span>首页</span>
  </a>
  <a class="item" href="#">
    <i class="iconfont icon-consult"></i>
    <span>问诊</span>
  </a>
  <a class="item" href="#">
    <i class="iconfont icon-mine"></i>
    <span>我的</span>
  </a>
</div>
```

图标我用字体图标（Iconfont），文字用 `span` 包起来，两个都是行内元素，正好上下排列。选中态给 `active` 类，后面换色就靠它，你们先把钩子留好。

### 2. 固定定位与均分布局

```css
.tabbar {
  position: fixed;
  left: 0;
  bottom: 0;
  width: 100%;
  display: flex;
  background-color: #fff;
  border-top: 1px solid #eee;
  z-index: 20;
}
.tabbar .item {
  flex: 1;
  display: flex;
  flex-direction: column;
  align-items: center;
  padding: 6px 0 8px;
  color: #999;
  font-size: 11px;
}
.tabbar .item i {
  font-size: 22px;
  line-height: 1;
}
.tabbar .item.active {
  color: #16c2a3;
}
```

几点你们跟着我捋。第一，`position: fixed` 加 `bottom: 0` 是吸底的标准写法，再配 `left: 0` 加 `width: 100%` 让它通栏，否则固定盒子宽度会塌成内容宽。第二，`display: flex` 配三个 `flex: 1`，三个选项自动等分，不管以后加到四个五个都不用改宽度。第三，每个 `.item` 自己又是一个纵向弹性盒，`flex-direction: column` 让图标压着文字，`align-items: center` 让它们居中。

> **提示**：固定定位会完全脱离文档流，下面的医生卡片最后一张会被导航条压住一部分。标准解法是给 `body` 或者内容区加 `padding-bottom`，数值跟导航条高度一致，比如导航条 56 像素，就加 `padding-bottom: 56px`。

### 3. 选中态与安全距离

选中态不要整花活，就改颜色。默认灰 `#999`，选中绿 `#16c2a3`，图标和文字一起变，用户一眼就知道自己在哪。你们要是给选中态又加粗又加背景，底部那点高度根本撑不住，反而显乱。

还有一个细节，碰到全面屏手机，底部有个小横条手势区，导航会被系统条顶到。我的习惯是多留一点下内边距，或者直接用环境变量兜底：

```css
.tabbar {
  padding-bottom: constant(safe-area-inset-bottom);
  padding-bottom: env(safe-area-inset-bottom);
}
```

`safe-area-inset-bottom` 是系统告诉你的安全距离（Safe Area），有刘海屏就有值，没刘海就是 0，写上不亏。你们现在先记住有这么个东西，真机调试看到被压住再回来加也来得及。

| 对比项 | 顶部粘性切换 | 底部固定切换 |
| :--- | :--- | :--- |
| 定位方式 | `sticky` 加 `top: 0` | `fixed` 加 `bottom: 0` |
| 是否占位 | 占位 | 脱标，需补 `padding-bottom` |
| 层级建议 | `z-index: 10` | `z-index: 20`，压住内容 |

> **结论**：到这里首页是上面吸一个、下面钉一个，中间内容随便滑，拇指操作一刻不停。你们把这个底栏封装好，后面登录页、我的页直接复用。

## 第 16 章：152-vmin和vmax单位以及使用场景
> 对应分集：P153 | 原始标题：《152-vmin和vmax单位以及使用场景》

`vw`、`vh` 你们已经会了，一个管宽度、一个管高度。可我问你们一个问题：手机竖屏变横屏，哪个方向更短完全反过来了，你的正方形还正吗？这一讲我就给你们补最后两块拼图：视口最小单位（`vmin`）和视口最大单位（`vmax`），专门治这种横竖屏翻转的场景。

### 1. vmin 和 vmax 的取值原理

> **定义**：`vmin` 取视口宽高中较小者的百分之一，`vmax` 取视口宽高中较大者的百分之一。`1vmin` 等于短边百分之一，`1vmax` 等于长边百分之一。

公式很直白：

$$1vmin = min(1vw, 1vh)$$

$$1vmax = max(1vw, 1vh)$$

举个具体数你们就通了。假设手机竖屏是 375 乘 667，那么 `100vw` 是 375，`100vh` 是 667，较小的是宽，所以 `100vmin` 等于 375，`100vmax` 等于 667。把手机一横，变成 667 乘 375，较小者变成高，`100vmin` 自动变成 375，还是短边。你们看，`vmin` 永远跟着短边走，根本不用你们写媒体查询去判断横竖屏。

```text
竖屏 375x667          横屏 667x375
+------+              +------------+
|      | 100vmin=375  |            | 100vmin=375
| 短边 | 100vmax=667  | 短边=高    | 100vmax=667
| 375  |              | 375        |
+------+              +------------+
```

读图说明：无论横竖如何翻转，`vmin` 恒等于短边，`vmax` 恒等于长边。

### 2. 横竖屏通用的正方形与全屏字

先看最经典的需求：做一个不管横竖屏都完整显示的正方形。用 `vw` 写就翻车，竖屏 `width: 80vw` 看着正好，横屏高度不够，直接被裁掉。换成 `vmin` 一行搞定：

```css
.box {
  width: 80vmin;
  height: 80vmin;
  background-color: #16c2a3;
}
```

`80vmin` 就是短边的百分之八十，横竖屏都以短边为基准，正方形永远完整显示。我做启动页的大圆、二维码占位，统统用 `vmin`，闭眼写都不会溢出。

反过来 `vmax` 适合做通吃的大背景。你们想做一张横竖屏都铺满的底图，用 `vmax` 定尺寸，保证长边方向一定铺满，短边方向再配合 `object-fit: cover` 裁一下就行。

还有文字。你们有没有见过横屏时标题小得可怜，竖屏时又大得撑破？用 `vmin` 定字号，字跟着短边走，横竖屏观感完全一致：

```css
.title {
  font-size: 5vmin;
}
```

| 单位 | 基准 | 横竖屏翻转时 | 典型用途 |
| :--- | :--- | :--- | :--- |
| `vw` | 视口宽 | 基准跟着宽度变 | 常规移动端适配 |
| `vh` | 视口高 | 基准跟着高度变 | 首屏高度 |
| `vmin` | 短边 | 恒为短边 | 正方形、字号、圆 |
| `vmax` | 长边 | 恒为长边 | 全屏背景、大装饰 |

> **易错点**：`vmin`、`vmax` 和 `vw`、`vh` 一样都是相对视口，不是相对父元素。有人在小盒子里写 `50vmin`，发现比父盒子还大，就以为单位坏了，其实是参照物搞错了，参照物永远是整个视口。

> **提示**：桌面端拖动浏览器窗口也能实时看到 `vmin` 切换，窄到一定程度，较小者从宽度变成高度，盒子尺寸会跳一下，那不是 bug，正好证明它在跟着短边走。

> **结论**：记住一句话就行：要正、要全、要跟着短边，用 `vmin`；要铺满长边、要气势，用 `vmax`。下一讲我们换一条适配路线，讲讲 `rem` 是怎么靠根字号缩放整站的。

## 第 17 章：153-rem单位以及适配方案原理
> 对应分集：P154 | 原始标题：《153-rem单位以及适配方案原理》

`vw` 是拿视口直接当尺子，`rem` 是换一把思路：我不直接量视口，我先定一个根字号，再让全站跟着根字号一起缩放。你们听起来绕，其实淘宝、京东移动端用了快十年，原理吃透了，任何设计稿你们都能接。

### 1. em 与 rem 的参照差异

> **定义**：相对根元素字号单位（Root Em，`rem`）是以文档根元素 `html` 的 `font-size` 为基准的相对单位，`1rem` 等于根字号的像素值。

它和 `em` 就差一个字母，坑的全在这一个字母上。我画个对比你们就不会混了：

```text
em: 一层套一层, 越乘越大
body(16px) -> p(2em=32px) -> span(2em=64px)

rem: 只认根, 永远只乘一次
html(16px) -> 任何地方 2rem = 32px
```

读图说明：`em` 的基准是父元素，会逐层累乘；`rem` 的基准永远是根元素，全站统一。

```css
html {
  font-size: 16px;
}
.card {
  width: 10rem; /* 10 x 16 = 160px */
  font-size: 0.875rem; /* 0.875 x 16 = 14px */
}
```

浏览器默认根字号就是 16 像素，所以不设置时 `1rem` 等于 16 像素。你们以后看到 `0.875rem` 别慌，除以 16 就是 14 像素，这都是同一回事。

> **易错点**：改了父级字号，`em` 全跟着变，`rem` 纹丝不动。新手用 `em` 做卡片，嵌套三层字大得离谱，就是累乘闹的。做整站适配一律用 `rem`，把 `em` 留给首行缩进这种局部小活。

### 2. 等比缩放的推导过程

适配的核心诉求就一句话：设计稿 750 宽的屏和手机 375 宽的屏，同一个按钮看起来比例一致。`rem` 方案分两步走。

第一步，按设计稿定一把尺子。假设设计稿宽 750，我人为定 Breite 划分份数，比如分成 10 份，每份 75 像素，那就让 375 宽的手机根字号是 37.5 像素，750 宽的屏根字号是 75 像素。公式是：

$$根字号 = 视口宽 / 划分份数$$

第二步，全站尺寸都用 `rem` 写。设计稿上一个 150 像素宽的按钮，除以 75 得到 `2rem`，写死 `2rem`。手机 375 下根字号 37.5，`2rem` 算出来 75 像素，正好是设计稿的一半，比例完全一致。

```text
设计稿 750px (根字号 75px)    手机 375px (根字号 37.5px)
+------------------+          +--------+
| 按钮 150px=2rem  |  等比     | 2rem   |
|                  | ------> | =75px  |
+------------------+  缩放     +--------+
```

读图说明：`rem` 数值写死，根字号跟着视口变，最终像素自动等比缩放。

| 对比项 | vw 方案 | rem 方案 |
| :--- | :--- | :--- |
| 基准 | 视口本身 | 根字号 |
| 换算 | `px / 视口宽 x 100vw` | `px / 根字号 rem` |
| 适配手段 | 无需脚本 | 需脚本或媒体查询改根字号 |
| 适用场景 | 纯移动端新项目 | 需兼容老机型、老项目 |

你们问我哪个好？我跟你们说实话，新项目我直接上 `vw`，简单。可你们进公司接的八成是老项目，全站 `rem`，你不会 `rem` 连尺寸都看不懂。所以原理必须吃透，下一讲我就带你们亲手实现一遍，再配好自动换算插件。

## 第 18 章：154-rem适配方案实现以及插件配置
> 对应分集：P155 | 原始标题：《154-rem适配方案实现以及插件配置》

原理听懂了还不够，手停在键盘上写不出来等于没学。这一讲我们就把 `rem` 适配真正跑起来：先用一小段脚本让根字号跟着视口走，再配好自动换算插件，以后你们量出多少像素，直接写，插件替你们换成 `rem`。

### 1. 动态根字号的脚本写法

上一讲的公式还记得吧，根字号等于视口宽除以份数。咱们设计稿 750，分 10 份，根字号就是视口宽除以 10。375 的手机就是 37.5，414 的手机就是 41.4。用媒体查询（Media Query）一个个断点写能累死，直接一段脚本搞定：

```js
function setRootFont() {
  const width = document.documentElement.clientWidth;
  const fontSize = width / 10;
  document.documentElement.style.fontSize = fontSize + 'px';
}
setRootFont();
window.addEventListener('resize', setRootFont);
```

三件事你们看清。第一，`document.documentElement` 就是 `html` 标签，`clientWidth` 拿到的是视口宽；第二，除以 10 得到根字号，直接写到 `html` 的行内样式；第三，监听窗口变化（Resize）事件，横竖屏一转、窗口一拖，重新算一遍。我习惯页面一进来先调一次，不然首屏会闪一下默认值。

> **提示**：除以几完全是约定，10 是为了好算，750 设计稿下 `1rem` 等于 75 像素，量出 150 除以 75 得 `2rem`，心算都行。你们团队定成 7.5 也行，只要全站统一，比例就不会错。

上限也要封一下。平板、桌面动不动 1200 宽，除以 10 根字号 120，全站大得吓人。我的习惯是封顶，比如超过 750 就按 750 算：

```js
function setRootFont() {
  let width = document.documentElement.clientWidth;
  if (width > 750) width = 750;
  document.documentElement.style.fontSize = width / 10 + 'px';
}
```

### 2. 自动换算插件的配置

```text
手写流程                      插件流程
量出 68px -> 心算             量出 68px -> 照写 px
68 / 75 = 0.9067rem           插件编译成 0.9067rem
手动写 rem                    源码仍是 px, 上线自动换
```

读图说明：插件把换算从人肉挪到编译时，源码可读性不变，产物自动带 `rem`。

我用的是 `postcss-pxtorem`，配合 `lib-flexible` 那套思路也行，原理一样。先装包：

```bash
npm install postcss-pxtorem --save-dev
```

再配 `postcss.config.js`，关键就两个参数：

```js
module.exports = {
  plugins: {
    'postcss-pxtorem': {
      rootValue: 75,
      propList: ['*']
    }
  }
};
```

`rootValue: 75` 必须和脚本里的 750 除以 10 对上，设计稿 750 就是 75，设计稿 375 就是 37.5，这两个数是一对，改一个另一个必须跟着改。`propList: ['*']` 表示所有属性都换，你们要是只想换字号和宽高，就写 `['font-size', 'width', 'height']`。

| 参数 | 含义 | 常用值 |
| :--- | :--- | :--- |
| `rootValue` | `1rem` 对应的像素数 | 750 稿填 75，375 稿填 37.5 |
| `propList` | 哪些属性参与换算 | `['*']` 全换 |
| `selectorBlackList` | 哪些选择器不换 | `['.no-rem']` 排除特定类 |

> **易错点**：行内样式和 `1px` 边框别进换算。`1px` 的细线换成 `rem`，大屏下会粗成 `2px`，丑得很。插件里把 `minPixelValue` 设成 2，或者边框手写 `1px` 并加黑名单，都能保住细线。

配完你们验证一下：源码写 `width: 150px`，编译出来变成 `width: 2rem`，手机 375 下根字号 37.5，算出来 75 像素，正好一半，比例严丝合缝，就可以上线了。

> **结论**：脚本管根字号跟着屏走，插件管像素自动变 `rem`，两件套一配，`rem` 适配就闭环了。下一阶段我们拿这套东西重做登录页，你们会发现量稿、写码、适配一气呵成。

## 第 19 章：155-优医问诊登录页-准备工作
> 对应分集：P156 | 原始标题：《155-优医问诊登录页-准备工作》

首页那套 vw 方案跑通之后，你们心里是不是犯嘀咕：既然 vw 这么省事，为什么还要学 rem？问得好。我直接给你们答案：工作中老项目一大半是 rem 写的，你去改别人的代码，看不懂 rem 就只能干瞪眼。而且只会一种适配，出门面试人家问你移动端有几种方案，你说只有一种，底气立刻少一半。

所以我们单开一个新页面——优医问诊登录页，专门拿它练 rem。为什么非要新开一个页面，不直接在首页上改？你们想想，首页的 vw 插件是按 `375` 视口宽度转单位的，rem 这套要换插件、换基准、换脚本，两套混在一个页面里，单位一打架，查错能查到哭。新开一个 `login.html`，旧账新账分开算，这是工程习惯，记住这一条就够了。

这一讲我们不写一行登录的业务代码，就干三件事：看清登录页长什么样，把目录和基础文件搭好，把 px 转 rem 的插件调通。

### 1. 登录页全景与 375px 设计稿基准

#### 1.1 四个模块自顶向下排列

登录页比首页简单得多，自上而下就四个大块，顺序固定：顶部导航条、头部品牌区、表单区、第三方登录区。后面四讲就是按这个顺序一块一块啃，这一讲先把总览刻进脑子。

```text
优医问诊登录页自顶向下骨架
+------------------------------------------+
| 1. navbar 顶部导航 (返回 + 标题)          |
+------------------------------------------+
| 2. header 头部品牌 (logo + 宣传语)        |
+------------------------------------------+
| 3. form 表单区 (手机 + 验证码 + 登录按钮) |
+------------------------------------------+
| 4. 第三方登录 (微信 / QQ 快捷入口)        |
+------------------------------------------+
```

读图说明：四个盒子自顶向下依次排列，登录页没有底部固定栏，表单就是页面的绝对主角。

#### 1.2 设计稿宽度与 rem 换算关系

设计稿还是 `375px`，这一点和首页一模一样，iPhone 6/7/8 以来的逻辑分辨率宽度就是 375，稿子不用换，换的是尺子。

> **定义**：根字号（root font-size）为 rem 方案的尺子，默认按屏幕宽度十等分，`375px` 宽的屏幕对应根字号 `37.5px`，换算关系是 `1rem = 37.5px`。

你们一定要把这个除数记死：量出 `37.5px` 就是 `1rem`，量出 `44px` 就是 `1.1733rem`，量出 `16px` 就是 `0.4267rem`。后面检查插件转换结果对不对，就靠心算这一笔账。

vw 和 rem 到底差在哪？我给你们摆一张表，一次看明白：

| 对比项 | vw 方案（首页用过） | rem 方案（本页用） |
| :-- | :-- | :-- |
| --- | --- | --- |
| 尺子是谁 | 视口宽度本身 | `html` 的 `font-size` |
| 自适应靠什么 | 浏览器原生计算 | 一段 JS 按屏宽改根字号 |
| 写代码时 | 直接量多少写多少 | 靠插件把 px 转 rem |
| 老项目占比 | 新项目多 | 存量项目多，必须会 |

> **结论**：新页面练新方案，老本事不丢，新本事到手，两种适配你们就全拿下了。

### 2. 目录结构与基础文件搭建

#### 2.1 文件夹与文件划分

在原来的项目根目录里接着干，不另起炉灶。只新增两个文件，多一个都是累赘：

```text
优医问诊项目目录结构（登录页新增部分）
youyiwenzhen/
  |-- index.html          首页（vw 方案，不动它）
  |-- login.html          登录页骨架（本讲新建）
  |-- css/
  |     |-- base.css      初始化 + 通用样式（复用）
  |     |-- index.css     首页样式（不动它）
  |     `-- login.css     登录页样式（本讲新建）
  |-- js/
  |     `-- flexible.js   rem 根字号脚本（本讲引入）
  |-- images/             静态修饰图
  `-- uploads/            业务图
```

读图说明：`login.html` 配 `login.css`，和首页那一对彻底隔离；`flexible.js` 是 rem 方案的心脏，专门负责按屏幕宽度改根字号。

#### 2.2 视口标签与 flexible 脚本引入

`login.html` 的头部，先把三样东西写齐：视口标签、初始化样式、flexible 脚本。顺序不能乱，脚本一定要在样式之前执行，否则页面会先按默认字号闪一下，再突然缩放，那一下闪屏看着特别廉价。

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no">
<script src="./js/flexible.js"></script>
<link rel="stylesheet" href="./css/base.css">
<link rel="stylesheet" href="./css/login.css">
```

你们注意，`maximum-scale=1.0` 配 `user-scalable=no` 是什么意思？就是不让用户双指缩放页面。登录页的输入框一聚焦，某些安卓机会自动放大页面，整个表单被顶得错位，加上这一对，页面就钉死了。

> **易错点**：`flexible.js` 一定要用配套版本，别随手从网上拷一个旧版。旧版默认按 `750` 稿子十等分，根字号基准对不上，后面所有 rem 全错半拍。

#### 2.3 flexible 的工作原理

有人问我，这段 JS 到底干了什么？我一句话讲透：它监听屏幕宽度，除以 10，把结果写到 `html` 的 `font-size` 上。

```js
// flexible 核心逻辑示意（简化版）
function setRootFontSize() {
  var width = document.documentElement.clientWidth;
  document.documentElement.style.fontSize = width / 10 + 'px';
}
setRootFontSize();
window.addEventListener('resize', setRootFontSize);
```

屏幕 `375px` 宽，根字号就是 `37.5px`；屏幕变成 `414px`，根字号跟着变成 `41.4px`。页面里所有 rem 都是相对根字号的，根一动，全页跟着等比缩放，这就是 rem 自适应的全部秘密。

```text
rem 等比缩放示意图
屏宽 375px              屏宽 414px
html:37.5px             html:41.4px
   |                       |
   v                       v
1rem=37.5px             1rem=41.4px
盒子宽 10rem            盒子宽还是 10rem
= 375px                 = 414px（等比放大）
```

读图说明：代码里永远只写 `10rem`，屏幕变大变小，实际像素自动跟着走，这就是一套代码适配所有手机的原理。

### 3. px 转 rem 插件配置确认

手写 rem 换算能把人逼疯，`44px` 除以 `37.5` 等于多少？`1.173333`，谁愿意天天按计算器。所以和 vw 那一讲一样，我们靠插件干这个脏活。

打开插件设置，把基准值（root value）填成 `37.5`。为什么是 37.5 不是 75？你们想想，根字号在 375 屏下就是 `37.5px`，`1rem = 37.5px`，基准必须和它一致。填成 75，转换出来的数值会小一半，页面在手机上整体缩水一圈。

验证方法很土但很有效：在 `login.css` 里随手写一行 `width: 37.5px;` 保存，看它是不是自动变成 `width: 1rem;`。是，说明配置正确；不是，回去检查两件事：一是插件是不是只对 `css` 文件夹生效，二是基准值到底填了多少。

> **提示**：`base.css` 里 `box-sizing: border-box` 那一行，登录页同样保命。rem 单位下输入框宽度本来就算得紧，再让边框往外撑，375 的稿子在 320 的小屏机上必溢出。

登录页四个模块里，顶部这条导航看着最不起眼，可你们千万别小看它。我问你们一个问题：一个登录页的顶部，除了放个标题，还能干什么？答案是三件事：告诉用户我在哪，给用户一条退路，保证在任何手机上高度永远协调。退路就是左上角那个返回箭头，很多人做登录页随手把它丢了，用户一点进来发现回不去，直接关页面走人，转化率就这么没的。

这一讲我们就啃这第一块骨头：`navbar` 顶部导航模块。结构、高度、箭头、标题，四样一次做到位。

### 1. 导航结构与三段式骨架

#### 1.1 左中右三段划分

移动端的顶部导航，万变不离其宗，都是左中右三段：左边放返回，中间放标题，右边留空或者放文字按钮。登录页的右边暂时留空，但位置一定要先占出来，不然标题就没法真正居中。

```text
navbar 三段式骨架
+------------------------------------------+
|  < 返回   |     登录/注册     |   (留空)   |
|  左段     |     中段标题      |   右段占位 |
+------------------------------------------+
```

读图说明：左段和右段等宽，中间标题被两边夹在正中央，这是三段式导航居中的标准做法。

结构代码直接写成三个子盒子，语义清清楚楚：

```html
<nav class="navbar">
  <a href="#" class="navbar-back iconfont icon-fanhui"></a>
  <h1 class="navbar-title">登录/注册</h1>
  <span class="navbar-empty"></span>
</nav>
```

你们看，返回用 `a` 标签，因为它真的是个跳转；标题用 `h1`，一个页面只能有一个 `h1`，登录页的标题就是它；右边用空 `span` 占位，宽度和左边保持一致。

> **定义**：字体图标（iconfont）为把图标做成字体来用的技术，图标本质是文字，可以像文字一样改大小、改颜色，不会失真。

#### 1.2 整体高度与底边分隔

导航高度按设计稿量出来是 `44px`，换算成 rem 就是 `44 / 37.5 = 1.1733rem`。为什么偏偏是 44？你们摸摸自己的手机，原生 App 的顶栏基本都是这个高度，手指点起来最舒服，这是多年沉淀下来的拇指友好尺寸。

```css
.navbar {
  display: flex;
  align-items: center;
  justify-content: space-between;
  height: 1.1733rem;
  padding: 0 0.4rem;
  background-color: #fff;
  border-bottom: 1px solid #f0f0f0;
}
```

`display: flex` 配 `justify-content: space-between`，三段自动散开顶住两边；`align-items: center` 让箭头和标题垂直居中。底下那条 `1px` 的浅灰边框，是导航和内容的分界线，没有它，导航和下面的品牌区会糊在一起。

### 2. 返回箭头与标题样式

#### 2.1 返回箭头做法

返回箭头用字体图标，不用图片。图片要发请求、要管 retina 两倍图，字体图标一个字符就搞定，放大十倍都不虚。

```css
.navbar-back {
  width: 0.64rem;
  font-size: 0.48rem;
  color: #333;
}
```

`font-size: 0.48rem` 换算回去是 `18px`，箭头在这个字号下看起来最精神，大了笨重，小了点不中。宽度给 `0.64rem`（也就是 `24px`），是给手指留的点击面积，图标本身可以小，点击区域必须大，不然用户在地铁上晃着手根本点不中。

> **易错点**：`a` 标签默认有下划线和蓝色，一定要用 `base.css` 里的 `text-decoration: none` 和颜色继承清掉。顶栏上挂一个蓝色带下划线的箭头，一秒回到二十年前的网页。

#### 2.2 中间标题做法

标题字号 `18px`，也就是 `0.48rem`，字重 `500` 左右的中等加粗，颜色 `#333` 深灰。为什么不用纯黑 `#000`？纯黑在白色顶栏上对比太烈，看久了累眼睛，深灰是最耐看的标题色。

```css
.navbar-title {
  font-size: 0.48rem;
  font-weight: 500;
  color: #333;
}
.navbar-empty {
  width: 0.64rem;
}
```

右边这个空 `span` 宽度和左边箭头完全一样，都是 `0.64rem`，左右配重相等，标题自然就坐在正中间。有人偷懒右边不占位，直接给标题加 `margin: 0 auto`，左边多了个箭头，标题看着永远偏右一截，强迫症看了浑身难受。

#### 2.3 rem 数值速查

这一讲出现的 rem 全是按 `37.5` 基准换算的，我给你们列出来，对不上就说明插件配置有问题：

| 部位 | 设计稿 px | rem 换算 |
| :-- | :-- | :-- |
| --- | --- | --- |
| 导航高度 | `44px` | `1.1733rem` |
| 左右内边距 | `15px` | `0.4rem` |
| 箭头字号 | `18px` | `0.48rem` |
| 标题字号 | `18px` | `0.48rem` |
| 点击区宽度 | `24px` | `0.64rem` |

> **提示**：检查插件转得对不对，不用逐个按计算器，记住 `37.5px = 1rem` 这一档，`18px` 不到一半，大约 `0.48rem`，量级对了就八九不离十。

## 第 21 章：157-优医问诊登录页-header模块制作
> 对应分集：P158 | 原始标题：《157-优医问诊登录页-header模块制作》

导航条是给用户指路的，头部区是给页面定调的。你们回想一下自己用过的登录页：有的logo一摆就觉得靠谱，有的一打开就觉得像钓鱼网站，差在哪？差的就是头部这短短一百多像素。logo 大小、主标题字号、宣传语颜色，三样对了，信任感就有了；随便一堆，表单做得再漂亮用户也不敢输手机号。

这一讲我们做第二个大盒子：`header` 头部品牌区。就三样东西：logo 图、主标题、副文案，全部居中，留白给足。

### 1. 头部结构与整体留白

#### 1.1 三件套纵向排列

头部结构简单到一句话：一个盒子，里面自上而下放 logo、主标题、副文案，文字全部居中。

```text
header 头部骨架
+------------------------------------------+
|                                          |
|              [ logo 图片 ]                |
|                                          |
|              优医问诊（主标题）            |
|         专业医生 在线问诊（副文案）        |
|                                          |
+------------------------------------------+
```

读图说明：三样纵向排布，上下留白比内容本身更重要，挤在一起就没有品牌感了。

```html
<header class="header">
  <img src="./images/logo.png" alt="优医问诊" class="header-logo">
  <h2 class="header-title">优医问诊</h2>
  <p class="header-desc">专业医生 在线问诊</p>
</header>
```

`img` 的 `alt` 一定要写，哪怕只是两个字。图片万一没加载出来，至少还有文字顶着，而且读屏软件靠它认图，这是习惯问题。

#### 1.2 上下留白尺寸

头部整体上下内边距，设计稿上量出来顶部 `40px`、底部 `30px`，换算就是 `1.0667rem` 和 `0.8rem`。为什么顶部比底部大？你们想想，导航条下面直接接 logo，留白小了，logo 会顶着导航，喘不过气；底部接着就是表单，留白稍小一点，视线能顺着滑下去。

```css
.header {
  padding: 1.0667rem 0 0.8rem;
  text-align: center;
  background-color: #fff;
}
```

一个 `text-align: center`，里面所有的行内内容和文字全居中，比给每个子元素写 `margin: 0 auto` 省事得多。记住，居中一片文字，永远先想 `text-align`。

> **提示**：头部背景保持白色，和导航条连成一片，登录页上半截就是一张完整的白纸，表单区压在下面才有层次。

### 2. logo 与标题文案样式

#### 2.1 logo 图片尺寸

logo 量出来是 `64px` 见方，也就是 `1.7067rem`。正方形 logo，直接定宽高相等，再加一点圆角，医疗类 App 的图标大多是圆角矩形，看着亲切。

```css
.header-logo {
  width: 1.7067rem;
  height: 1.7067rem;
  border-radius: 0.2667rem;
}
```

`border-radius: 0.2667rem` 换算回去是 `10px`，圆角不大不小，方中带圆。图片记得加 `display: block` 再配 `margin: 0 auto`，或者靠父级的 `text-align: center` 居中也行，两种写法效果一样，选一种坚持到底。

> **易错点**：`img` 是行内替换元素，底下默认有一条小缝隙，那是基线对齐闹的。在 logo 这种独占一行的图上，最好顺手写 `vertical-align: middle` 或者转块级，否则 logo 和标题之间会多出几像素的怪缝，怎么调间距都对不齐。

#### 2.2 主标题与副文案

主标题 `22px`（`0.5867rem`），字重加粗，颜色深灰 `#333`；副文案 `14px`（`0.3733rem`），常规字重，颜色浅灰 `#999`。一大一小、一深一浅，主次关系全靠字号和颜色拉开，不用任何多余装饰。

```css
.header-title {
  margin-top: 0.4rem;
  font-size: 0.5867rem;
  font-weight: 700;
  color: #333;
}
.header-desc {
  margin-top: 0.2133rem;
  font-size: 0.3733rem;
  color: #999;
}
```

主标题离 logo `15px`（`0.4rem`），副文案离主标题 `8px`（`0.2133rem`），间距也是上大下小，和外层留白一个节奏。你们发现没有，好的设计稿里，间距都是有节奏的，不是拍脑袋定的。

| 部位 | 设计稿 px | rem 换算 |
| :-- | :-- | :-- |
| --- | --- | --- |
| 头部上内边距 | `40px` | `1.0667rem` |
| 头部下内边距 | `30px` | `0.8rem` |
| logo 尺寸 | `64px` | `1.7067rem` |
| 主标题字号 | `22px` | `0.5867rem` |
| 副文案字号 | `14px` | `0.3733rem` |

## 第 22 章：158-优医问诊登录页-form表单模块制作上
> 对应分集：P159 | 原始标题：《158-优医问诊登录页-form表单模块制作上》

前面导航和头部都是摆样子的，这一讲开始动真格：表单。你们有没有输过那种难用的验证码登录？输入框小得点不中，获取验证码的按钮藏在角落里，输完手机号还要满屏找下一步。用户在表单上每多花一秒，流失就多一分，所以表单是登录页里最值得抠细节的地方。

这一讲做表单的上半部分：手机号输入框和验证码输入框，外加获取验证码的按钮。登录按钮和协议那是下一讲的事，一次吃不完，咱们分两口吃。

### 1. 表单整体结构与容器留白

#### 1.1 两个输入行纵向排列

表单区就两个输入行：第一行手机号，第二行验证码加按钮。每行都是一条底边框线，这是移动端输入框最经典的做法，不要四边大框，只要一条底线，干净又省地方。

```text
form 表单上半部分骨架
+------------------------------------------+
|  [手机图标]  请输入手机号                 |
|  - - - - - - - - - - - - - - - - - - -  |
|  [锁图标]    请输入验证码  [获取验证码]   |
|  - - - - - - - - - - - - - - - - - - -  |
+------------------------------------------+
```

读图说明：两个输入行纵向排列，各自带一条底边框；第二行内部左右分栏，左边是输入框，右边是文字按钮。

```html
<form class="form">
  <div class="form-item">
    <i class="iconfont icon-shouji"></i>
    <input type="tel" placeholder="请输入手机号" maxlength="11">
  </div>
  <div class="form-item">
    <i class="iconfont icon-suo"></i>
    <input type="text" placeholder="请输入验证码" maxlength="6">
    <a href="#" class="form-code">获取验证码</a>
  </div>
</form>
```

手机号用 `type="tel"`，手机弹出的就是数字键盘；验证码用 `type="text"` 配 `maxlength="6"`，六位码，多一位都进不来。`placeholder` 的文案照着设计稿一字不差地写，这是表单的说明书。

#### 1.2 表单左右留白

表单左右各留 `20px`（`0.5333rem`），上下留 `10px`（`0.2667rem`）。左右留白是给拇指让路的，输入框顶到屏幕边缘，大拇指点起来总觉得要滑出去，留出这 `20px`，手感完全不一样。

```css
.form {
  padding: 0.2667rem 0.5333rem;
  background-color: #fff;
}
```

> **提示**：表单和头部之间不要加外边距断开，保持同一张白底连下来，登录页上半截的整体感就保住了。分段靠留白，不靠底色。

---

### 2. 输入行与验证码按钮样式

#### 2.1 输入行弹性布局

每一行都是图标加输入框的横向组合，用弹性盒（flexbox）一句话摆平：图标定宽，输入框占满剩下所有空间。

```css
.form-item {
  display: flex;
  align-items: center;
  height: 1.3333rem;
  border-bottom: 1px solid #f0f0f0;
}
.form-item .iconfont {
  width: 0.64rem;
  font-size: 0.4267rem;
  color: #ccc;
}
.form-item input {
  flex: 1;
  height: 100%;
  border: 0;
  outline: none;
  font-size: 0.3733rem;
  color: #333;
}
```

行高 `50px`（`1.3333rem`），手指点起来宽敞；图标 `16px`（`0.4267rem`），浅灰 `#ccc`，安安静静做个配角。输入框的 `border: 0` 和 `outline: none` 两行必须写，浏览器默认的输入框边框和聚焦蓝圈，在这种底线风格里是灾难，见一个清一个。

`flex: 1` 是什么意思？就是告诉输入框，图标拿走定宽之后，剩下的宽度全归你。第二行的获取验证码按钮也要占地方，输入框照样自动让位，这就是弹性布局写表单最爽的地方。

> **易错点**：`input` 的默认字号很小，自己不写 `font-size`，iOS 上聚焦时页面会被强制放大。定成 `14px`（`0.3733rem`）以上，就能避开这个坑。

#### 2.2 验证码按钮做法

获取验证码是个描边小按钮，绿色文字配绿色边框，圆角拉满变胶囊形，往输入行右边一挂，整个表单的点睛之笔。

```css
.form-code {
  flex-shrink: 0;
  padding: 0.16rem 0.32rem;
  font-size: 0.32rem;
  color: #16c2a5;
  border: 1px solid #16c2a5;
  border-radius: 0.4267rem;
}
```

`flex-shrink: 0` 是关键，什么意思？弹性布局里空间不够时子元素默认会被压缩，按钮加了这一句，宽度雷打不动，谁都别想挤它。字号 `12px`（`0.32rem`），比输入文字小两档，主次分明。

| 部位 | 设计稿 px | rem 换算 |
| :-- | :-- | :-- |
| --- | --- | --- |
| 输入行高 | `50px` | `1.3333rem` |
| 表单左右留白 | `20px` | `0.5333rem` |
| 输入文字字号 | `14px` | `0.3733rem` |
| 验证码字号 | `12px` | `0.32rem` |

> **定义**：占位文本（placeholder）为输入框空置时显示的浅色提示字，用户一打字就消失，只起说明作用，不参与提交。

## 第 23 章：159-优医问诊登录页-form表单模块制作下
> 对应分集：P160 | 原始标题：《159-优医问诊登录页-form表单模块制作下》

输入框是让用户填东西的，按钮才是让用户下决心的。你们回想一下自己点登录的那一刻：按钮够大、颜色够正、写着明明白白的登录两个字，手指就敢点下去；按钮灰不溜秋缩在角落，旁边还堆着一行小得看不清的协议，心里立刻打鼓。这就是表单下半部分要解决的事：登录大按钮加协议行，一鼓作气把转化完成。

这一讲把表单剩下的两块啃完：全宽登录按钮，和它下面的协议勾选行。

### 1. 登录按钮全宽大按钮做法

#### 1.1 按钮结构与渐变背景

登录按钮直接用 `button` 标签，文案就两个字：登录。宽度撑满表单内容区，高度 `48px`（`1.28rem`），圆角 `24px`（`0.64rem`）正好是高度的一半，一拉就是标准胶囊形。

```text
form 表单下半部分骨架
+------------------------------------------+
|                                          |
|  +------------------------------------+  |
|  |             登 录                  |  |
|  +------------------------------------+  |
|                                          |
|  [o] 已阅读并同意《用户协议》...         |
|                                          |
+------------------------------------------+
```

读图说明：大按钮独占一行撑满宽度，协议行跟在下面，左对齐，和输入框的左边缘对齐。

```html
<button type="submit" class="form-btn">登录</button>
<label class="form-agree">
  <input type="checkbox" checked>
  已阅读并同意《用户协议》《隐私政策》
</label>
```

`type="submit"` 不能丢，它声明这个按钮就是用来提交表单的，回车键也能触发登录，键盘党狂喜。

按钮背景用品牌绿的渐变，从 `#16c2a5` 到 `#0da5a0`，由浅入深。为什么不用纯色？你们看，纯色按钮在白底上像贴上去的纸片，渐变带一点纵深，看着像个能按下去的实体键，用户才有点的欲望。

```css
.form-btn {
  width: 100%;
  height: 1.28rem;
  margin-top: 0.5333rem;
  font-size: 0.4267rem;
  color: #fff;
  border: 0;
  border-radius: 0.64rem;
  background: linear-gradient(to right, #16c2a5, #0da5a0);
}
```

字号 `16px`（`0.4267rem`），白色，按钮离上面的验证码行 `20px`（`0.5333rem`），呼吸感刚好。`border: 0` 把浏览器默认的按钮边框清掉，否则渐变再好看，边上圈一圈灰线全白费。

> **定义**：线性渐变（linear-gradient）为颜色沿一条直线平滑过渡的背景写法，`to right` 表示从左往右，两个色标决定起点和终点颜色。

#### 1.2 按钮按压反馈

按钮光好看不够，还得有手感。加上 `:active` 按压态，手指按下去的瞬间透明度降一点，松手弹回来，用户立刻知道这一按生效了。

```css
.form-btn:active {
  opacity: 0.9;
}
```

就一行代码，体验差一截。没有按压反馈的按钮，按下去心里没底，用户会忍不住连点三下，网络请求发三遍，后端同学半夜被叫起来查重复提交，根子就在你少写的这一行。

### 2. 协议勾选行样式

#### 2.1 复选框与文案排布

协议行是个 `label` 包着原生复选框，点文字就能勾选，不用瞄准那个小方块。复选框保持系统默认样子就行，登录页的重点是按钮，协议框别抢戏。

```css
.form-agree {
  display: flex;
  align-items: center;
  margin-top: 0.32rem;
  font-size: 0.32rem;
  color: #999;
}
.form-agree input {
  margin-right: 0.16rem;
}
```

文案字号 `12px`（`0.32rem`），浅灰 `#999`，和验证码按钮一个量级，摆明了告诉用户：我是次要信息。里面的《用户协议》《隐私政策》用绿色高亮，暗示可以点，这是法务和体验的折中，字必须小，但路必须留。

#### 2.2 rem 数值速查

下半部分出现的 rem，我给你们列出来收尾：

| 部位 | 设计稿 px | rem 换算 |
| :-- | :-- | :-- |
| --- | --- | --- |
| 按钮高度 | `48px` | `1.28rem` |
| 按钮圆角 | `24px` | `0.64rem` |
| 按钮字号 | `16px` | `0.4267rem` |
| 按钮上边距 | `20px` | `0.5333rem` |
| 协议字号 | `12px` | `0.32rem` |

> **易错点**：`label` 里包 `input` 的写法，点文字就能切换勾选，这是原生行为，不用写一行 JS。有人非要把文字放 `label` 外面再用 JS 模拟点击，多此一举，还容易把无障碍语义搞丢。

## 第 24 章：160-优医问诊登录页-第三方登录模块制作
> 对应分集：P161 | 原始标题：《160-优医问诊登录页-第三方登录模块制作》

刚把手机号一键登录和短信验证码那两块做完，页面中间已经挺满了，可你们发现没有，真实 App 的登录页最底下永远还有一行小字加三个圆图标——微信、QQ、微博，不做它，页面就像缺了一块拼图。我一开始也想偷懒跳过，可越看越别扭，今天就花十来分钟，专门把这个第三方登录模块补齐。

---

### 1. 第三方登录模块的页面位置与结构拆解

先想清楚这个模块在整个登录页里待在哪。登录页从上到下是：返回箭头标题区、Logo 与宣传语、登录按钮组、短信登录表单，而第三方登录永远沉底，贴着屏幕底部，和上面的表单拉开一大段距离。

```text
+----------------------------------+
|  <-  登录                        |
|                                  |
|      [  Logo  ]                  |
|     快速问诊 · 权威医生           |
|                                  |
|  [ 手机号一键登录 ]               |
|  [ 短信验证码登录 ]               |
|                                  |
|  ...... 留白 ......               |
|                                  |
|  ------ 第三方登录 ------         |
|                                  |
|   (微)      (Q)      (博)        |
+----------------------------------+
```

读图说明：第三方登录模块由上下两部分组成，上面是一行带左右横线的标题文字，下面是三个横向排列的圆形图标按钮。

落到结构上，我把它包成一个独立的 `div.other`，里面再分两层：标题行 `div.title`，图标行 `div.apps`，图标行里放三个 `a` 标签，每个 `a` 包一张 `img`。

```html
<div class="other">
  <div class="title">第三方登录</div>
  <div class="apps">
    <a href="#"><img src="./images/qq.png" alt="QQ"></a>
    <a href="#"><img src="./images/wechat.png" alt="微信"></a>
    <a href="#"><img src="./images/weibo.png" alt="微博"></a>
  </div>
</div>
```

> **提示**：图标用 `a` 包 `img` 是固定套路。`a` 负责可点击跳转授权页，`img` 只负责显示，将来换成 SVG 精灵图也不用动结构。

### 2. 标题文字与左右横线装饰

#### 2.1 标题行的居中与文字样式

标题行的活儿就一个：让四个字老老实实待在正中间。外层 `.other` 我给了左右 `16px` 的内边距，和上面表单区的对齐线保持一致，标题文字 `14px`，颜色取浅灰 `#999`，`text-align: center` 直接居中。字不能贴着线，我给了它左右各 `12px` 的呼吸空间。

```css
.other {
  padding: 0 16px;
}
.other .title {
  text-align: center;
  font-size: 14px;
  color: #999;
}
```

#### 2.2 横线的两种实现与取舍

横线我特意给你们掰开讲两种做法，因为你们以后天天会遇到。一种是用两个 `span` 画 `1px` 高的背景色块，另一种是用标题的左右边框加伪元素。这一讲我用的是最省事的弹性盒方案：标题行本身设为 `display: flex`，左右各放一条 `i` 线，中间文字 `flex: none` 不伸缩，两条线 `flex: 1` 自动撑满剩余空间。

```css
.other .title {
  display: flex;
  align-items: center;
  gap: 12px;
}
.other .title::before,
.other .title::after {
  content: "";
  flex: 1;
  height: 1px;
  background-color: #e5e5e5;
}
```

你们记住这个结论就行：凡是“中间文字固定、两边线条自适应”的装饰，一律用伪元素加 `flex: 1`，比算百分比宽度省心十倍，而且屏幕变宽变窄线条自己会伸缩。

> **易错点**：伪元素必须写 `content: ""`，哪怕内容为空，一字不写它根本不会渲染出来，这是新手最高频的翻车点。

### 3. 第三方图标按钮的排列与尺寸控制

#### 3.1 图标行的弹性居中排列

三个图标横向一排、整体居中、间距相等，这正是弹性盒（弹性布局，Flexible Box）最拿手的场景。`.apps` 设为 `display: flex`，`justify-content: center` 让整排居中，`gap: 32px` 一把拉开三个图标的距离，比逐个写 `margin` 干净得多。

```css
.other .apps {
  display: flex;
  justify-content: center;
  gap: 32px;
  margin-top: 20px;
}
```

#### 3.2 图标尺寸与圆形效果处理

图标尺寸我定的是 `48px` 见方。`a` 标签本身设 `48px` 宽高，里面的 `img` 设 `width: 100%` 跟着走，这样以后想改成 `56px` 只改一处。图标素材本身是圆底白图，直接放上去就是圆形效果，不需要再写 `border-radius`，但你们要保证三张图风格统一，不然一个圆一个方会很难看。

```css
.other .apps a {
  width: 48px;
  height: 48px;
}
.other .apps a img {
  width: 100%;
  height: 100%;
  display: block;
}
```

> **提示**：`img` 加 `display: block` 是为了干掉图片底部的 3px 空白缝隙。图片默认是行内元素，和基线对齐会多出一截，用块级化一次解决。

| 部件 | 尺寸参数 | 布局手段 |
| :--- | :--- | :--- |
| 标题文字 | `14px`，`#999` | `text-align: center` |
| 左右横线 | 高 `1px`，`#e5e5e5` | 伪元素 `flex: 1` 自适应 |
| 图标按钮 | `48px × 48px` | 父级 `flex` 居中加 `gap: 32px` |

### 4. 模块与页面的间距衔接

最后一个细节是这个模块离上面表单有多远。我直接给 `.other` 加了 `margin-top: 60px`，把它“压”到屏幕下半区。为什么不用绝对定位沉底？因为登录页内容高度本来就不满屏，`margin-top` 撑开的留白在各种机型上都稳定，而绝对定位还要处理键盘弹起把按钮顶飞的问题，得不偿失。

```css
.other {
  margin-top: 60px;
}
```

你们做完一定要在手机模式下前后拖一拖宽度看一眼：标题横线跟着伸缩，三个图标永远居中，这就对了。到这里登录页的全部模块就齐了，下一讲我们处理顶部固定和真机预览，把这个页面真正装进口袋里验证一遍。

## 第 25 章：161-优医问诊登录页-固定顶部以及真机演示效果
> 对应分集：P162 | 原始标题：《161-优医问诊登录页-固定顶部以及真机演示效果》

页面四个模块都写完了，在电脑上拖着看挺像样，可你们有没有想过一个问题：真机上滑起来，顶部的“登录”标题栏会不会跟着滚走？我第一次把这个页面发到手机上看，标题一滚就不见了，体验一下就垮了。所以这一讲干两件事：先把顶部固定住，再把页面装进真手机里实打实验证一遍。

---

### 1. 登录页顶部标题栏的固定处理

#### 1.1 固定定位的脱标补偿

顶部标题栏固定的手段只有一个：固定定位（固定定位，Fixed Positioning），`position: fixed` 加 `top: 0`。但你们一定要记住它带来的副作用——固定定位的元素会脱离标准流，原来它占的那一块高度就塌了，下面的 Logo 会“顶”上去，被标题栏压住半截。

```css
.header {
  position: fixed;
  top: 0;
  left: 0;
  width: 100%;
  height: 44px;
  background-color: #fff;
  z-index: 10;
}
```

补偿的办法同样固定：给紧跟在后面的页面主体加一个和标题栏等高的上内边距。标题栏 `44px` 高，主体就 `padding-top: 44px`，被压住的部分一下就让出来了。

```css
.main {
  padding-top: 44px;
}
```

> **易错点**：`position: fixed` 默认宽度会被内容撑开，一定要补 `width: 100%`，否则标题栏会缩成一小条，这是固定头部最高频的翻车现场。

#### 1.2 固定头部的宽度与层级控制

还有两个参数是顺手必须写的。`left: 0` 保证它贴着屏幕左边缘，不写的话在某些机型上会莫名其妙错位几像素。`z-index: 10` 是让标题栏压在后面滚动内容的上层，不然图片和按钮滚上来会盖住标题字。背景色 `#fff` 也别漏，不写背景，滚动的内容会从半透明的标题底下透出来。

```text
层叠关系侧视图 (z 轴从下往上)
-------------------------------
[ z=10 ]  .header  标题栏 (不透明)
-------------------------------
[ z=0  ]  .main    页面内容 (滚动经过)
-------------------------------
```

读图说明：标题栏层级高于内容层，内容上滑时从标题栏背后经过，被不透明背景遮住。

### 2. 真机预览的环境准备

电脑浏览器里那个手机图标只是模拟，真机验证才是交作业的标准。准备工作就三条，你们对照着做。

```text
真机预览链路拓扑
+----------+    同一 WiFi    +----------+
|  电脑     | <------------> |  手机     |
| Live     |   192.168.x.x  |  浏览器   |
| Server   |   :5500        |  输入地址 |
+----------+                +----------+
```

读图说明：电脑起服务，手机和电脑连同一个局域网，手机浏览器输入电脑的局域网地址加端口即可访问。

第一，电脑和手机连同一个 WiFi，这是大前提，不在同一个局域网后面全白搭。第二，编辑器里的 Live Server 保持启动，端口一般是 `5500`。第三，在电脑上用命令行查出本机局域网地址，Windows 下是 `ipconfig` 看 IPv4 那一行，比如 `192.168.1.6`。

> **提示**：公司或校园网如果开了客户端隔离，手机会打不开电脑地址，这时自己开个手机热点给电脑连，最省事。

### 3. 真机地址拼接与效果检验

地址拼接格式固定：`http://` 加电脑 IP 加冒号加端口加项目路径。比如 `http://192.168.1.6:5500/login.html`，在手机浏览器里敲进去，登录页就出来了。

我在手机上重点验了三处，你们也照着验：

| 检验项 | 合格表现 | 对应代码 |
| :--- | :--- | :--- |
| 顶部标题栏 | 上下滑动始终悬停，不跟随滚动 | `position: fixed; top: 0` |
| 第三方图标行 | 三个图标居中，横线随宽度伸缩 | `flex` 加 `gap` |
| 登录按钮 | 宽度撑满，两侧留白与设计稿一致 | `margin` 加 `border-radius` |

滑动时标题纹丝不动，说明固定生效；把手机横过来看一眼，横线变长、图标依然居中，说明弹性布局在真机上同样自适应。到这一步，这个登录页才算真正闭环。

下一讲我带你们把整个移动端阶段收个尾，到底学了哪几种适配方案、以后做项目先选哪个，一次讲清。

## 第 26 章：162-移动端网页开发总结
> 对应分集：P163 | 原始标题：《162-移动端网页开发总结》

从视口标签写到优医问诊登录页落地，移动端这块一口气学了十几讲，你们现在脑子里可能是散的：视口、flex、rem、vw 好像都会一点，可真要自己开一个新项目，第一步先干什么反而说不清。今天这讲不写新代码，就帮你们把散珠子串成一条线。

---

### 1. 移动端开发的三类适配方案

我带你们做的方案一共三类，先把它们摆在一起，你们立刻就能看清各自的分工。

| 方案 | 核心手段 | 适用场景 |
| :--- | :--- | :--- |
| 流式加弹性布局 | 百分比宽度加弹性盒（弹性布局，Flexible Box） | 结构简单、以单列和均分布局为主的页面，本阶段主力 |
| 相对单位适配 | 根字号（根元素字号，Root em）加媒体查询动态换算 | 需要整体等比缩放的老项目和混合终端页面 |
| 视口单位适配 | 视口宽度（视口宽度，Viewport Width）直接换算 | 新项目轻量适配，一处换算处处生效 |

> **结论**：本阶段所有实战案例统一用第一种，你们先把弹性盒练到闭眼能写，再去碰后两种，心里才有锚点。

### 2. 本阶段的三项核心能力沉淀

#### 2.1 视口标签与触屏基础配置

所有移动端页面的第一行代码都是同一段视口（视口，Viewport）声明。它告诉浏览器：布局视口宽度就等于设备宽度，初始缩放为 1，不允许用户随意缩放把版式撑坏。这行不写，后面写什么都是地基不稳。

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no">
```

#### 2.2 弹性布局为主的排版流水线

我要求你们形成固定的做题顺序：先搭结构分块，再定主轴方向，最后处理对齐和间距。登录页的按钮组、第三方图标行，练的都是这一套。`justify-content` 管主轴，`align-items` 管侧轴，`gap` 管间距，三个属性组合起来，九成移动端布局一次成型。

```text
弹性排版三步流水线
[1 分块]  header / main / other 先划区
   |
[2 定轴]  flex-direction: row / column
   |
[3 对齐]  justify-content + align-items + gap
```

读图说明：任何一块布局都按分块、定轴、对齐三步走，顺序固定，不用来回试错。

#### 2.3 真机验证闭环

从这一阶段起，电脑模拟器通过不算通过，手机浏览器打开正常才算。固定顶部的脱标补偿、图片底部缝隙、横线伸缩，这些问题在模拟器里经常看不出来，一上真机全露馅。以后你们交每个页面前，都走一遍“同 WiFi、查 IP、拼地址、滑一遍”的四步验证。

> **提示**：真机验证时重点滑三次：纵滑看固定头，横竖屏切换看弹性伸缩，双指缩放看视口有没有锁死。

### 3. 下一阶段的学习路线指引

移动端收官之后，我们马上进入第七篇：响应式布局（响应式布局，Responsive Layout）。它和移动端是什么关系？一句话：移动端是专门给手机做一版，响应式是一套代码同时伺候手机、平板和电脑。下一讲我就先带你们看第七篇的案例全貌，再正式开讲媒体查询，你们会发现弹性盒的老本在那边照样能吃上。
