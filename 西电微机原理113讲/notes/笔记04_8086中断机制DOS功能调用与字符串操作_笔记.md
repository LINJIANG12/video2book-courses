# 8086中断机制、DOS功能调用与字符串操作

## 中断源与类型号

### 内部中断

* **内部中断（Internal Interrupt）**

    * > **定义**：由 CPU 内部事件产生、无需外部设备拉出请求线的中断。

    * 8086 的内部中断共有除法出错、单步、断点、溢出和软件中断五类。

* **除法出错中断**

    * CPU 执行除法指令时，若除数为零或商溢出，立即触发该中断。

    * 中断类型号固定为 `0`。

* **单步中断（Single-Step Interrupt）**

    * CPU 每执行完一条指令后检查陷阱标志 `TF`。

    * `TF=1` 时产生类型号为 `1` 的单步中断；`TF=0` 时顺序执行。

* **断点中断（Breakpoint Interrupt）**

    * CPU 执行 `INT 3` 指令时产生断点中断。

    * 中断类型号固定为 `3`，与指令中的类型号一致。

* **溢出中断（Overflow Interrupt）**

    * CPU 执行 `INTO` 指令时检查此前指令留下的溢出标志 `OF`。

    * `OF=1` 时产生类型号为 `4` 的中断；`OF=0` 时继续顺序执行。

    * > **易错点**：`INTO` 不会重新计算溢出，`OF` 来自它前面那条算术指令的执行结果。

* **软件中断（Software Interrupt）**

    * CPU 执行 `INT n` 指令时进入软件中断，中断类型号就是指令中的 $n$。

    * $n$ 的范围为 `00H～FFH`，不能超过 `255`。

* **中断类型号（Interrupt Type Number）**

    * > **定义**：8086 用来识别每个中断源的编号。

    * 类型号范围为 `00H～FFH`，共 `256` 个，因此 8086 最多管理 `256` 级中断。

    * 固定类型号包括：除法出错 `0`、单步 `1`、NMI `2`、断点 `3`、溢出 `4`。

    * > **易错点**：类型号 `2` 不属于 CPU 内部五类中断，它已被外部非可屏蔽中断占用。

### 外部中断入口

* **外部非可屏蔽中断（Non-Maskable Interrupt，NMI）**

    * > **定义**：通过 `NMI` 引脚提出、不能由中断允许标志屏蔽的紧急中断请求。

    * `NMI` 为上升沿有效；一旦出现上升沿，CPU 必须响应。

    * 无论 `IF=0` 还是 `IF=1` 都不影响响应。

    * 中断类型号固定为 `2`。

* **外部可屏蔽中断（Interrupt Request，INTR）**

    * > **定义**：通过 `INTR` 引脚提出、是否响应受中断允许标志控制的中断请求。

    * `INTR` 为高电平有效。

    * 只有 `IF=1` 时 CPU 才响应；`IF=0` 时请求被暂时屏蔽。

    * 外部可屏蔽中断的类型号不由 CPU 固定，而由中断控制电路和用户安排。

## 8259A可屏蔽中断管理

### 请求输入与编程

* **可编程中断控制器（Interrupt Controller，8259A）**

    * > **定义**：8086 外部用于接收、筛选并编码可屏蔽中断请求的接口芯片。

    * 一片 8259A 有 `IR0～IR7` 八个请求输入端和一个连接 CPU `INTR` 的 `INT` 输出端。

    * 外设先向某一路 `IR` 请求，8259A 完成优先级、屏蔽和类型号处理，再向 CPU 的 `INTR` 输出高电平。

    * `D0～D7` 与 CPU 数据总线相连，用户可通过 `OUT` 指令编程。

* **请求信号形式与屏蔽位**

    * 可分别设置 `IR0～IR7` 的请求信号是高电平有效还是低电平有效。

    * 可分别屏蔽或开放八路请求；被屏蔽的一路不会经 `INT` 向 CPU 提出请求。

    * 只有未屏蔽且满足有效电平条件的请求，8259A 才向 `INTR` 发出信号。

* **类型号基址**

    * 用户只需写入 `IR0` 对应的中断类型号，其余七路按输入端次序顺延。

    * 若 `IR0` 的类型号为 `08H`，则 `IR1～IR7` 依次为 `09H～0FH`。

    * > **易错点**：8259A 只向 CPU 提出一个 `INTR` 请求，具体请求来自哪一路及其类型号，要由 8259A 在应答时提供。

### 级联扩展

* **主片与从片**

    * `INT` 直接连接 CPU `INTR` 的 8259A 是主片；`INT` 接主片某一路 `IR` 的 8259A 是从片。

    * 每接入一片从片，都要占用主片的一个输入端，因此每增加一片从片只净增 `7` 个外设请求端。

* **可管理请求数**

    * $N$ 片 8259A 由一片主片和 $N-1$ 片从片组成，共有 $8N$ 个输入端。

    * 扣除被从片占用的 $N-1$ 个主片输入端，可管理外设请求数为：

    $$
    8N-(N-1)=7N+1
    $$

    * 单片管理 `8` 个，两片管理 `15` 个，四片管理 `29` 个，九片管理 `64` 个外部可屏蔽中断源。

### 中断响应握手

* **中断响应信号（Interrupt Acknowledge，INTA）**

    * > **定义**：8086 在响应外部可屏蔽中断时，用来与 8259A 确认请求并取得类型号的握手信号。

    * 第一个宽度为一个时钟周期的负脉冲通知 8259A：CPU 已响应请求。

    * 第二个同样宽度的负脉冲表示 CPU 正在索取类型号，8259A 随即把 $n$ 送上数据总线。

    * CPU 从第二个 `INTA` 脉冲期间取得类型号，再按 $n\times4$ 查找中断向量。

## 中断向量与响应过程

### 响应条件与固定步骤

* **现行指令与响应时机**

    * 内部中断和 NMI 一旦满足条件必须响应，但 CPU 不会中断一条尚未执行完的指令。

    * 外部可屏蔽中断除必须执行完现行指令外，还要求 `IF=1`。

* **硬件保护现场**

    * CPU 按 `PSW`、`CS`、`IP` 的顺序依次压栈，保存状态标志和返回地址。

    * 压栈后栈顶是最后压入的 `IP`，出栈顺序与此相反。

    * CPU 自动保护的只有 `PSW`、`CS`、`IP`；服务程序使用的其他寄存器和内存仍需软件自行保护。

* **清除 `IF` 与 `TF`**

    * 进入服务程序后，CPU 自动将 `IF` 和 `TF` 清零，默认不响应新的可屏蔽中断，也不按单步方式执行。

    * 若服务程序有意允许中断嵌套，应在完成必要现场保护后用 `STI` 重新开放可屏蔽中断。

* **取得中断向量**

    * CPU 取得类型号 $n$ 后，在物理地址 $n\times4$ 处取偏移地址送入 `IP`。

    * 在物理地址 $n\times4+2$ 处取段地址送入 `CS`。

    * 新形成的 `CS:IP` 指向中断服务程序（Interrupt Service Routine，ISR）的第一条指令。

### 中断向量表

* **中断向量（Interrupt Vector）**

    * > **定义**：中断服务程序的入口地址，由 `16` 位段地址 `CS` 和 `16` 位偏移地址 `IP` 组成。

    * 一个中断向量共 `32` 位，即 `4` 个字节。

* **中断向量表（Interrupt Vector Table，IVT）**

    * > **定义**：存放全部 `256` 个中断向量、供 CPU 按类型号查找服务入口的地址表。

    * 表位于 1 MB 存储空间的最低 1 KB，物理地址范围为 `00000H～003FFH`。

    * 类型号 $n$ 对应向量的起始物理地址为 $n\times4$。

    * 例如 `INT 21H` 的向量起点为 `21H×4=84H`：`00084H～00085H` 存 `IP`，`00086H～00087H` 存 `CS`。

* **中断向量的建立**

    * > **定义**：把服务程序入口的 `IP` 和 `CS` 写入向量表对应位置的过程。

    * 使用 $n$ 号中断时，必须把入口偏移写到 $n\times4$，把入口段地址写到 $n\times4+2$。

* **中断返回（Interrupt Return，IRET）**

    * 服务程序末尾执行 `IRET`，依次从栈中恢复 `IP`、`CS`、`PSW`，同时恢复 `SP`。

    * 现场恢复后，控制权交回被中断程序。

## DOS功能调用约定

### 调用接口与参数判读

* **DOS功能调用（DOS Function Call）**

    * > **定义**：把 DOS 已实现的文件、设备、键盘、屏幕和时间等功能封装为子程序，供用户程序通过软件中断调用。

    * 常用入口为 `INT 21H`，功能号通常放在 `AH`，其余入口、出口参数按具体功能规定放入寄存器或内存。

    * 磁盘、文件和设备管理等功能已有系统实现，程序应直接调用而不再重复实现。

    * DOS 调用属于低级功能调用；BIOS 调用属于高级功能调用，两者功能号和参数约定不能混用。

* **调用三阶段**

    * 设置功能号及入口参数。

    * 执行 `INT 21H`。

    * 按规定读取出口参数、状态位或返回码。

* **BIOS功能调用（Basic Input/Output System Call）**

    * 同样通过软件中断进入，功能号放在 `AH`，但 BIOS 与 DOS 有各自的编号和参数约定。

    * 查阅或编写程序时必须先确认中断入口和参数表属于 BIOS 还是 DOS。

### 字符输入与输出

* **01H号功能**

    * 等待用户从键盘输入一个字符，字符 ASCII 码返回到 `AL`。

    * 输入字符会回显到当前光标位置。

    * 无入口参数，等待期间检查 `Ctrl+Break`。

* **07H号功能**

    * 等待用户输入一个字符，返回值仍在 `AL`，但不回显。

    * 无入口参数，检查 `Ctrl+Break`。

* **08H号功能**

    * 等待用户输入一个字符，返回值仍在 `AL`，但不回显。

    * 特殊检查对象是 `Ctrl+C`，不是 `Ctrl+Break`。

    * > **易错点**：`07H` 与 `08H` 都等待且不回显一个字符，但组合键检查对象不同。

* **06H号功能**

    * 同一功能号按 `DL` 内容完成控制台输入或输出。

    * `DL=00H～FEH` 时，把 `DL` 中的字符输出到屏幕。

    * `DL=0FFH` 时检查键盘，不等待按键。

    * 检查键盘时，无键则 `ZF=1` 并立即返回；有键则 `ZF=0`，字符 ASCII 码在 `AL`。

    * 轮询时可在 `ZF=1` 条件下跳回检查；检测到 `1BH` 的 `ESC` 后转入相应分支。

* **02H号功能**

    * 向屏幕输出一个字符，待输出字符的 ASCII 码放在 `DL`，功能号放在 `AH`。

    * 它直接输出寄存器中的字符，不会模拟一次键盘输入动作。

* **05H号功能**

    * 向打印机输出一个字符，待输出字符同样放在 `DL`。

    * 它与 `02H` 的参数位置相同，区别仅在功能号所指向的输出设备。

* **控制字符**

    * 回车 `0DH` 把光标送回本行最左端。

    * 换行 `0AH` 使光标移到下一行。

    * 空格 `20H` 不显示普通字形，但占用字符编码。

    * 完整换行必须连续输出 `0DH` 和 `0AH`，只执行其中一个不等价于回到下一行左端。

### 跳转表多分支

* **跳转表（Jump Table）**

    * > **定义**：把多个目标入口按固定步长连续存放，并通过输入序号计算位移量后取得目标地址的数据结构。

    * 每个目标标号代表完整的段地址和偏移地址；跳转表通常只存同一代码段内各入口的偏移地址。

    * 标号不会因为被命名就自动成为数据，必须用 `DW OFFSET G1` 等方式显式定义表项。

* **数据段跳转表**

    * 每个字表项占 `2` 字节，连续输入 `'1'～'5'` 的表内位移量为 $(n-'1')\times2$。

    * 核心处理先检查 $1\le n\le5$，再计算索引、取得表项首地址并间接跳转。

    ```asm
    CHECK_INPUT:
        MOV  AH, 01H
        INT  21H
        CMP  AL, '1'
        JB   CHECK_INPUT
        CMP  AL, '5'
        JA   CHECK_INPUT
        AND  AL, 0FH
        DEC  AL
        SHL  AL, 1
        CBW
        LEA  BX, TABLE
        ADD  BX, AX
        JMP  WORD PTR [BX]
    ```

    * `LEA BX,TABLE` 取得表首地址，`ADD BX,AX` 按索引定位表项；表在数据段时由 `DS:BX` 提供地址。

    * > **易错点**：范围检查不能省略；输入 `0` 或 `6` 时直接计算会产生下标越界或无符号下溢。

* **代码段跳转表**

    * 表项可以直接存放入口地址，也可以存放一组跳转指令；后者需要先执行表内指令，再到达真正入口。

    * 表在代码段时，间接读取必须由 `CS` 覆盖；省略 `CS:` 会按默认数据段寻址。

    * 若表内短跳转实际编码为 `3` 字节，五个表项的步长为 `3`，索引应按 $(n-'1')\times3$ 计算。

    * 若目标距离过远，汇编器会改用更长的跳转编码；此时必须按实际指令长度确定步长，不能固定套用 `2` 或 `3`。

    * > **易错点**：代码段跳转表存的是入口地址或跳转指令本身，不是跳转指令的地址；表项长度也不能脱离实际编码假定。

## 字符串与缓冲输入

### 字符串输出

* **09H号功能**

    * 向屏幕连续输出一个字符串，功能号为 `AH=09H`。

    * `DS` 指向字符串所在数据段，`BX` 保存首字符在段内的偏移地址。

    * 字符串从 `DS:BX` 开始逐字节送屏，遇到结束符 `$` 时停止；结束符本身不显示。

* **字符串结束标志**

    * `$` 的 ASCII 码为 `24H`，必须真实存在于内存中，不能依赖 09H 自动补入。

    * 缺少 `$` 时 DOS 会继续读取后续内存；把它放在字符串中间会截断输出。

    * `BX` 只表示起点，不表示最大可读长度。

* **段地址装载**

    * `ASSUME DS:DATA` 只是对汇编器的声明，不会自动在运行时把数据段地址装入 `DS`。

    * 若 `DS` 尚未指向字符串所在段，必须执行 `MOV AX,DATA` 和 `MOV DS,AX`；`OFFSET MSG` 只给出段内偏移。

    ```asm
    DATA SEGMENT
        MSG DB 'STRING', 0DH, 0AH, '$'
    DATA ENDS

    CODE SEGMENT
        ASSUME CS:CODE, DS:DATA
    START:
        MOV  AX, DATA
        MOV  DS, AX
        MOV  BX, OFFSET MSG
        MOV  AH, 09H
        INT  21H
    ```

* **字符串中的换行**

    * 09H 不会自动换行；若希望下一段从下一行左端开始，应把 `0DH`、`0AH` 放在 `$` 之前。

    * 多个菜单项应分别定义各自的 `$` 和首地址，每次调用 09H 前把 `BX` 指向对应字符串。

### 整行缓冲输入

* **0AH号功能**

    * 等待用户输入一整行，直到按下回车才结束。

    * `DX` 指向输入缓冲区的第一个字节，执行 `INT 21H` 前功能号放在 `AH=0AH`。

    * 返回后必须按缓冲区中的实际长度处理，不能把整个存储空间都视为有效输入。

* **输入缓冲区结构**

    * 偏移 `0`：程序预先设定的最大输入长度。

    * 偏移 `1`：DOS 回写的实际输入字符数，不包含回车。

    * 偏移 `2` 起：实际输入字符，末尾由 DOS 保存回车字符。

    ```text
    偏移 0    最大长度
    偏移 1    实际长度 N
    偏移 2    字符 0
    …         ……
    偏移 N+1  字符 N-1
    偏移 N+2  回车
    ```

* **缓冲空间分配**

    * 最大长度字段占一个字节，描述符最大可表示到 `FFH`。

    * 按约定，最大长度要把最后的回车计算在内，因此缓冲区至少为“最大长度加两个描述字节”。

    ```asm
    INPUT_BUF DB 20H
               DB ?
               DB 20H DUP(?)
    ```

    * 调用前令 `DS:DX` 指向 `INPUT_BUF` 的首字节，不能直接指向偏移 `2` 的字符区。

* **输入与输出结束符差异**

    * 0AH 以回车结束输入，09H 以 `$` 结束输出；0AH 的返回缓冲区不是天然的 09H 字符串。

    * 最稳妥的做法是把处理结果复制到另一输出缓冲区，再补 `0DH`、`0AH` 和 `$`。

    * 若直接复用输入缓冲区，必须确认实际字符后还有足够空间放置 `$`，不能让输出越界继续读取。

## 字符转换与系统时间

### ASCII数字转换

* **ASCII数字字符**

    * 数字字符 `'0'～'9'` 的编码连续排列，范围为 `30H～39H`。

    * 单个字符转数值时，先减去 `30H`，所得结果才是对应的十进制数字。

* **多位数累进转换**

    * 多位十进制字符不能逐位相减后直接拼接，必须保留并扩展已读前缀。

    $$
    d=ASCII(c)-30H,\qquad R=10R+d
    $$

    ```text
    R = 0
    依次取字符 c
        d = ASCII(c) - 30H
        R = 10 * R + d
    ```

    * 处理 `201` 时依次得到 `2`、`20`、`201`。

    * > **易错点**：键盘输入是字符，排序等运算需要数值；直接对 ASCII 码做算术不会自动得到十进制数。

* **16位转换边界**

    * 转换到 16 位字时仍采用逐位减 `30H`、乘十和相加的算法。

    * 每一步都要检查结果是否超出 16 位范围；溢出时设置程序约定的错误标志，不能把截断后的低位当作正确结果。

* **二进制数到显示字符**

    * 二进制整数转十进制时，可反复除以 `10`、保留余数，再把余数逆序组合。

    * 十进制数字还要加 `30H` 转成可显示字符的 ASCII 码。

    * 二进制到十进制是数值表示转换，十进制数字到 ASCII 是字符编码转换，两步缺一不可。

### 系统时间

* **2CH号功能**

    * 调用 `AH=2CH`、`INT 21H` 可读取系统时间。

    * 返回时 `CH` 保存小时、`CL` 保存分钟、`DH` 保存秒，`DL` 保存夏令时标志。

* **2DH号功能**

    * 设置系统时间时，调用前把小时、分钟、秒分别放入 `CH`、`CL`、`DH`，把夏令时标志放入 `DL`。

    * 返回后必须检查 `AL`：`00H` 表示成功，`FFH` 表示失败。

    ```asm
        MOV  AH, 02DH
        MOV  CH, HOUR
        MOV  CL, MINUTE
        MOV  DH, SECOND
        MOV  DL, DAYLIGHT
        INT  21H
        CMP  AL, 00H
        JE   TIME_SET_OK
        ; AL = FFH：设置失败
    TIME_SET_OK:
    ```

* **二进制编码的十进制数（Binary-Coded Decimal，BCD）**

    * 2CH 返回的时、分、秒字段采用 BCD 形式。

    * 一个字节的高半字节表示十位，低半字节表示个位；设字段为 $b$，其十进制数值为：

    $$
    value=10\times high(b)+low(b)
    $$

    * 显示前要拆出十位和个位，再转换为 ASCII 字符。

    * > **易错点**：设置时间由 2DH 完成并用 `AL` 报告结果；读取时间由 2CH 完成并返回 BCD 字段，两个方向的参数不能放反。

* **动态时间刷新**

    * 动态显示必须形成“定位光标—读取时间—转换数值—转换 ASCII—显示字符—再次读取”的循环。

    * 只读取并显示一次只能得到静态时间，不能完成持续刷新。

    * 刷新频率过低会使字符明显闪动；课堂以约 `40 Hz` 作为经验量级，而非适用于所有显示器的固定标准。

### BIOS屏幕控制

* **显示方式设置**

    * `INT 10H` 的 `AH=00H` 用于设置显示方式，模式值放在 `AL`。

    * `AL=3` 对应 `80` 列、`25` 行的彩色文本模式，共有 $80\times25=2000$ 个字符位置。

    * 模式设置会清理画面，并把光标送回文本区左上角。

    * `2000` 仅是可见字符位置数，不能直接当作包含属性和其他区域的整页显存容量。

* **光标定位**

    * `INT 10H` 的 `AH=02H` 用于设置光标位置。

    * 行号放入 `DH`，列号放入 `DL`；接口坐标从 `0` 开始，25 行对应 `0～24`，80 列对应 `0～79`。

    * > **易错点**：阅读时把左上角称作第 `1` 行、第 `1` 列便于理解，但传给接口的实际坐标仍从 `0` 起算。

* **当前光标处写字符**

    * `INT 10H` 的 `AH=09H` 用于在当前光标位置显示字符。

    * 数值转换完成但未执行实际字符输出，屏幕内容仍不会更新。

* **显示页与显存**

    * 切换显示页与在当前页定位字符是不同操作；程序常选 `0` 页。

    * 80×25 文本区有 `2000` 个字符位置，而一块显示页按整页显存空间理解，容量通常以 `8K` 描述。

    * 显示页号、每页可用容量、显存首地址必须按显示方式对应查表，不能混为同一概念。

## 串操作指令

### 指令类别与隐含地址

* **串传送（Move String，MOVS）**

    * `MOVSB` 每次把源串当前字节送到目的串当前字节。

    * `MOVSW` 每次把源串当前字送到目的串当前字。

* **串比较（Compare String，CMPS）**

    * `CMPSB` 每次比较源串和目的串的一对字节。

    * `CMPSW` 每次比较源串和目的串的一对字。

    * 比较通过减法产生状态标志，但不保存差值，也不改写源、目的数据。

* **串扫描（Scan String，SCAS）**

    * `SCASB` 用 `AL` 与目的串当前字节比较。

    * `SCASW` 用 `AX` 与目的串当前字比较。

* **串装入（Load String，LODS）**

    * `LODSB` 从 `DS:SI` 取字节到 `AL`。

    * `LODSW` 从 `DS:SI` 取字到 `AX`。

* **串存储（Store String，STOS）**

    * `STOSB` 把 `AL` 存到 `ES:DI` 指向的字节单元。

    * `STOSW` 把 `AX` 存到 `ES:DI` 指向的字单元。

* **存储器串的隐含操作数**

    * 存储器到存储器时，源地址由 `DS:SI` 给出，目的地址由 `ES:DI` 给出。

    * 源串可按需要使用段超越前缀，目的串的段地址则固定由 `ES` 提供。

    * 源和目的在同一数据段时，仍要保证 `DS` 与 `ES` 都已正确初始化。

* **寄存器串的隐含操作数**

    * 存储器到寄存器使用 `DS:SI` 和 `AL` 或 `AX`。

    * 寄存器到存储器使用 `AL` 或 `AX` 和 `ES:DI`。

    * `BYTE PTR`、`WORD PTR` 只告诉汇编器按字节或字解释数据，不是额外的传送动作。

* **方向标志（Direction Flag，DF）**

    * `DF=0` 时，`SI`、`DI` 按地址递增方向变化。

    * `DF=1` 时，`SI`、`DI` 按地址递减方向变化。

    * 字节操作每次调整 `1`，字操作每次调整 `2`。

    * `CLD` 执行 `DF=0`，`STD` 执行 `DF=1`；顺序处理通常应显式写 `CLD`，不能依赖初始标志状态。

* **重复计数器 `CX`**

    * `CX` 保存串操作允许处理的单元数。

    * `SI`、`DI` 决定下一次从哪里取或存，`CX` 决定还要处理多少次。

### 重复前缀

* **重复前缀（Repeat Prefix，REP）**

    * `REP` 在 `CX≠0` 时继续执行串传送、串装入、串存储，也可用于串比较。

    * 每次串操作后 `CX` 减 `1`，减到 `0` 时结束。

* **相等重复前缀（REPE、REPZ）**

    * 继续条件是 `CX≠0` 且 `ZF=1`。

    * 比较中当前对应项相等，或扫描中当前单元与目标相等时，才继续执行。

* **不等重复前缀（REPNE、REPNZ）**

    * 继续条件是 `CX≠0` 且 `ZF=0`。

    * 当前比较项不相等时继续，遇到相等项时停止。

* **计数与比较结果的分工**

    * `CX` 只表示还有多少个单元未处理，`ZF` 才表示本次比较或扫描是否相等。

    * > **易错点**：`REPZ` 依赖 `ZF=1` 继续，`REPNZ` 依赖 `ZF=0` 继续，不能把前缀误解为无条件重复固定次数。

### 串传送与重叠搬移

* **串传送初始化**

    * 传送前必须分别准备源偏移 `SI`、目的偏移 `DI`、目的段 `ES`、重复次数 `CX` 和方向 `DF`。

    * `MOVSB` 每次搬一个字节，指针变化 `1`；`MOVSW` 每次搬一个字，指针变化 `2`。

* **重叠区域的方向规则**

    * 源地址低于目的地址时，按地址增大方向搬移，避免尚未读取的源数据被先写入的数据覆盖。

    * 源地址高于目的地址时，按地址减小方向搬移；反向处理时应让两个指针从实际访问的高地址端开始。

    * 程序可用 `CMP SI,DI` 判断：源低走 `CLD`，源高走 `STD`。

    * > **易错点**：方向取决于两个实际地址指针，不取决于两块数据谁更长或谁画在纸面上；不重叠时两种方向都可能得到正确结果。

* **100字节顺序传送**

    * 源串与目的串都在数据段时，把 `DS`、`ES` 指向同一段，将 `BUFF1`、`BUFF2` 的偏移分别送入 `SI`、`DI`，次数送入 `CX`。

    * `CLD` 指定递增方向，`REP MOVSB` 完成 100 个字节的搬移。

    ```asm
        MOV  AX, @DATA
        MOV  DS, AX
        MOV  ES, AX
        LEA  SI, BUFF1
        LEA  DI, BUFF2
        MOV  CX, 100
        CLD
        REP  MOVSB
    ```

    * 每次从 `DS:SI` 取一个字节写入 `ES:DI`，随后 `SI`、`DI` 各加 `1`，`CX` 减 `1`，直到计数归零。

### 串比较与查找

* **串比较标志**

    * `CMPSB`、`CMPSW` 做减法判断，但差值不保存。

    * `ZF=1` 表示本次两个操作数相等，`ZF=0` 表示不相等。

    * 比较后仍按 `DF` 修改 `SI`、`DI`，比较范围由 `CX` 给出。

    * > **易错点**：`CMPSW` 只比较对应字，不会把源串内容传送到目的串；`ZF=1` 也只表示本次对应项相等，不表示计数已经结束。

* **查找相等项**

    * 要在两段数据中找到第一对相等字，应使用 `REPNE CMPSW`：当前项不等时继续，遇到相等时停止。

    * 退出后 `ZF=1` 表示找到；`ZF=0` 表示计数耗尽且最后一项仍不等，按未找到处理。

    * 未找到标记 $-1$ 在 16 位汇编中写作 `0FFFFH`。

    * 比较后 `SI` 已指向匹配字的下一单元，所以匹配字在源缓冲区中的偏移为：

    $$
    SI-OFFSET\ BUFF1-2
    $$

* **检查全部相等**

    * 要判断两个缓冲区的所有对应字是否相同，应使用 `REPE CMPSW`：相等时继续，不等时停止。

    * 退出后 `ZF=1` 表示整个比较范围内没有遇到不等项；`ZF=0` 表示在某个位置发现不同数据。

    * 找相等项时遇等即停用 `REPNE`；要求全部相等时遇等继续用 `REPE`。

### 字符串扫描

* **串扫描比较**

    * `SCASB` 执行 $AL-ES:[DI]$ 的比较，结果只影响标志位，不写回存储器。

    * 扫描前把目标字符放入 `AL`，把目的段放入 `ES`，起始偏移放入 `DI`，范围放入 `CX`，并用 `CLD` 或 `STD` 规定方向。

    * 每次比较后 `DI` 按方向和字节步长自动变化。

* **查找等于目标的字节**

    * 查找等于 `AL` 的字符时使用 `REPE SCASB`，相等时继续，遇到不等字节时停止。

    * 正向扫描找到目标后，`DI` 已指向目标的下一单元，匹配地址为 `ES:(DI-1)`。

    * 退出后 `ZF=1` 表示扫描范围内命中目标；`ZF=0` 表示遇到了不等字节。

    * > **易错点**：正向 `REPE SCASB` 找到目标后的地址不能直接取当前 `DI`；反向扫描时也不能机械地永远减 `1`。

* **查找不等于目标的字节**

    * 查找第一个不等于 `AL` 的字符时改用 `REPNE SCASB`：不等时继续，遇到相等时停止。

    * 退出后 `ZF=1` 表示找到不等字节；`ZF=0` 表示计数耗尽仍未找到。

* **删除命中字符**

    * 删除不是把目标单元清零，而是让后继字符依次前移，填补空出的位置。

    * 同一存储区内前移属于重叠搬移，必须保证后写的数据不覆盖尚未搬走的数据。

    * 也可另建输出缓冲区：扫描时跳过目标字符，只把保留字符复制到新缓冲区，扫描结束后新缓冲区即为删除结果。

### 串装入与串存储

* **串装入与串存储的方向**

    * `LODS` 从 `DS:SI` 取数据到 `AL` 或 `AX`，`STOS` 从 `AL` 或 `AX` 存数据到 `ES:DI`。

    * `LODS` 自动修改 `SI`，`STOS` 自动修改 `DI`；字节步长为 `1`，字步长为 `2`。

    * > **易错点**：`LODS` 只把存储器数据取入寄存器，不直接写入另一存储器区域；寄存器到存储器的任务由 `STOS` 完成。

* **连续取放**

    * 要连续取出或存入 $n$ 个单元，应先把 `CX` 设为 $n$，再使用 `REP` 前缀。

    * 没有 `CX` 给出的边界，CPU 就不知道连续搬运应在何处停止。

* **串行发送与接收**

    * 发送端用 `LODSB` 从 `DS:SI` 取下一个字节到 `AL`，再用 `OUT` 把 `AL` 送入发送缓冲器。

    * 接收端用 `IN` 从接收缓冲器取字节到 `AL`，再用 `STOSB` 写入 `ES:DI` 指向的接收缓冲区。

    * 两条路径都体现连续数据沿地址逐字节取送，接口芯片类型可以不同，但取、存、端口访问的职责不能混淆。

* **重复填充缓冲区**

    * 用 `STOSB` 填满缓冲区时，`AL` 决定写入值，`ES:DI` 决定起点，`CX` 决定数量，`DF` 决定方向。

    * 将 256 个单元全部填入 `55H` 的核心设置如下：

    ```asm
        MOV  AX, DATA
        MOV  ES, AX
        LEA  DI, BUFFER2
        MOV  AL, 55H
        MOV  CX, 256
        CLD
        REP  STOSB
    ```

    * 每次写完后 `DI` 加 `1`、`CX` 减 `1`；结束后 `CX=0`，`DI` 越过缓冲区末尾。

## I/O端口与接口电路

### 端口寻址与总线周期

* **输入输出指令（Input/Output，IN/OUT）**

    * > **定义**：8086 在端口与寄存器之间传送数据的专用指令。

    * `IN` 的方向是端口到寄存器，因此端口地址写在寄存器之后；`OUT` 的方向是寄存器到端口，因此端口地址写在寄存器之前。

    * 设备不能直接占用 CPU 数据线，数据必须经过接口电路和端口。

* **I/O端口地址空间**

    * 8086 的 I/O 操作只用低 `16` 位地址线 `A15～A0` 形成端口地址，地址范围为 `0000H～FFFFH`。

    * 端口空间共有 $2^{16}=64K$ 个地址。

* **直接端口寻址**

    * 端口号在 `00H～FFH` 时，可把 8 位立即数直接写入 `IN` 或 `OUT`。

    * 直接寻址只能表达 `00H～FFH`，不能用一个 8 位立即数访问更大端口号。

* **`DX`间接寻址**

    * `0100H～FFFFH` 的端口必须先把完整地址送入 `DX`，再用 `IN`、`OUT` 访问。

    * `DX` 可覆盖全部 16 位端口空间，因此 `00H～FFH` 也可用 `DX` 间接访问。

    * `DX` 在这里是端口地址寄存器，不使用存储器间接寻址的中括号形式。

    ```asm
        MOV  DX, 8001H
        IN   AL, DX
    ```

    * > **易错点**：正确形式是 `IN AL,DX`，不能写成 `IN AL,[DX]`。

* **字节端口与字端口**

    * 字节传送使用 `AL`，字传送使用 `AX`。

    * 字端口由相邻的两个字节地址组成，并应以偶地址为首；低地址字节与紧接着的高地址字节组成端口字。

* **I/O总线周期**

    * 一般指令通常经历 `T1～T4` 四个时钟状态。

    * `IN`、`OUT` 需要 CPU 与外部端口交换数据，总线周期为 `T1、T2、T3、Tw、T4` 五个状态。

    * 额外等待状态 `Tw` 用于适应外部数据传送比 CPU 内部普通传送更慢的特点。

### 片选与输入端口

* **片选信号（Chip Select，CS#）**

    * > **定义**：用于选中某颗接口芯片的控制信号，一般低电平有效。

    * 地址译码与 `IOR#`、`IOW#` 等读写控制必须共同参与片选判断。

    * 地址信号回答“访问哪个端口”，控制信号回答“是否正在访问端口以及是读还是写”，只译地址不足以完成端口选择。

* **三态输入缓冲器（Three-State Input Buffer）**

    * 八个开关不能直接并接 CPU 数据线，需经八位三态缓冲器，如 74LS244。

    * `OE#=0` 时缓冲器导通，设备状态进入 CPU 的 `D0～D7`。

    * `OE#=1` 时输出呈高阻态，解除设备与数据总线的连接，避免多个设备争用总线。

* **8000H只读端口的完整译码**

    * 端口地址为 `8000H` 时，地址条件为 `A15=1`、`A14～A0=0`。

    * 读取该开关端口还必须同时满足 `IO/M=0` 和 `RD#=0`。

    ```text
    OE# = 0  当且仅当：
        IO/M = 0
    且  RD#  = 0
    且  A15～A0 = 8000H
    其他情况令 OE# = 1
    ```

    * 访问存储器、执行端口写操作或访问其他端口时，任一条件不成立，缓冲器都不能被选中。

* **读取开关状态**

    * 端口 `8001H` 超过直接寻址范围，应令 `DX=8001H` 后执行 `IN AL,DX`。

    * 八个开关分别对应返回字节的 `D0～D7`；示例中的 K0 对应 `D0`，闭合为 `1`，断开为 `0`。

    * `TEST AL,01H` 只按位与并设置标志，不保存结果；`ZF=1` 表示 D0 为 `0`，`ZF=0` 表示 D0 为 `1`。

    ```asm
        MOV  DX, 8001H
        IN   AL, DX
        TEST AL, 01H
        JZ   SW_OPEN
        ; 开关闭合的处理
        JMP  DONE
    SW_OPEN:
        ; 开关断开的处理
    DONE:
    ```

    * `AND AL,01H` 也能产生相同标志判断，但会破坏 `AL`；需要保留读回值时使用 `TEST`。

### 输出端口与锁存

* **八位锁存器（Latch）**

    * 74LS374、74LS373 可看成八个共用 CP 的 D 触发器。

    * `D0～D7` 是数据输入，`Q0～Q7` 是锁存输出；CP 上升沿把总线数据锁存到 Q 端。

    * `OE` 控制输出使能，端口输出电路中可保持常有效。

* **LED驱动与限流**

    * LED 点亮需要电流，不能长期让端口输出端承担全部负载，电流应由电源经限流电阻提供。

    * 采用 5 V 电源、约 10 mA 电流时，理论电阻为：

    $$
    R=\frac{5V}{10mA}=500\Omega
    $$

    * `500Ω` 不是标准标称值，工程上可取接近的 `510Ω` 或 `470Ω`，并保证电流不超过 LED 承受能力。

* **输出端口片选**

    * 输出端口的片选由地址译码信号与写控制 `IOW#` 共同产生；`OUT` 只能选中允许写的输出接口。

    * 写周期中 CPU 先把数据送到数据总线并拉低 `IOW#`，数据在写周期结束时被锁存到 Q 输出端。

* **读状态后驱动输出**

    * 程序先用 `IN` 读取状态到 `AL`，完成判断和数据准备，再用 `OUT DX,AL` 写到输出端口。

    * 输入芯片由读控制选中，输出芯片由写控制选中，相同端口地址不意味着读写两条通路可互换。

    * 两个相邻地址构成 16 位端口时，低地址字节和紧接着的高地址字节合成一个字，寄存器改为 `AX`，指令使用 `IN AX,DX` 或 `OUT DX,AX`。

## 标志处理、等待与延时

### 标志位处理

* **方向与中断控制**

    * `CLD`、`STD` 分别把 `DF` 清零、置位，用于控制串操作地址递增或递减。

    * `CLI`、`STI` 分别控制清除和置位 `IF`，用于禁止或开放外部可屏蔽中断。

* **进位控制（Complement Carry Flag，CLC）**

    * 多字节加法若循环体使用 `ADC`，第一次执行 `ADC` 前必须先用 `CLC` 清零 `CF`。

    * 否则第一次加法会带入上一轮遗留的进位，使结果错误。

### 空操作与延时

* **空操作（No Operation，NOP）**

    * NOP 不改变程序功能，但占用执行时间，常用于 I/O 速度协调和短延时。

    * NOP 的总线周期为 `3` 个时钟状态。

* **单重延时循环**

    * 内层循环由 `NOP` 和 `LOOP` 组成：`CX` 由初值递减，减到零时停止。

    * `LOOP` 的总线周期为 `4` 个时钟状态，因此 `NOP` 与 `LOOP` 合计每圈 `7T`。

    ```asm
    L1:
        NOP
        LOOP L1
    ```

* **二重延时循环**

    * 若单层循环不足，可用 `BX` 控制外层次数，用 `CX` 控制内层时间常数。

    * 内层 `CX` 归零后执行 `DEC BX` 和 `JNZ`，非零时重新启动内层循环。

    * 调节 `BX` 得到较粗的时间档位，调节 `CX` 得到较细的时间档位。

    * 16 位计数器初值为 `0` 时，要递减 `65536` 次才变为零，不能按零次处理。

    * 经常使用的延时程序应封装为带入口参数的子程序，由调用者用 `BX`、`CX` 准备延时量。

### 暂停与等待

* **暂停指令（Halt，HLT）**

    * CPU 执行到 `HLT` 时停止继续取指，可用于调试或让 CPU 等待外部设备。

    * 按下面板 `RESET` 可以退出暂停，但不能继续原程序。

    * 外部也可通过 `NMI` 提出不可屏蔽请求退出；通过 `INTR` 退出时还必须满足 `IF=1`。

    * 中断响应时 CPU 保存现场并执行服务程序，服务程序最后用 `IRET` 恢复现场和继续原程序。

* **等待指令（WAIT）**

    * CPU 每隔 `5` 个时钟状态读取一次外部 `TEST#` 引脚。

    * 设备未就绪时继续等待；读到 `TEST#=0` 时认为设备已经准备就绪，退出等待并继续执行。

    * WAIT 与 HLT 都可实现 CPU 和外设同步，但 WAIT 通过轮询状态引脚判断，HLT 通过硬件复位或中断退出。

## 宏指令

### 定义与调用方式

* **宏指令（Macro Instruction）**

    * > **定义**：用户用宏定义方法命名的一段程序代码；引用宏名时，汇编器把宏体展开到调用位置。

    * 宏名不是 8086 机器指令，CPU 不直接识别宏名；汇编阶段由宏调用替换成实际指令序列。

    * 宏与子程序不同：子程序调用由 CPU 在运行阶段转移，宏调用在汇编阶段展开，不产生相应的运行调用开销。

* **定义位置与顺序**

    * 宏必须先定义、后引用。

    * 宏定义应放在源程序最前部，位于 `STACK SEGMENT`、`DATA SEGMENT` 等段定义之前。

* **定义格式**

    * `MACRO` 左侧写宏名，右侧写可选形参；形参用逗号分隔并置于小括号内。

    * `MACRO` 与 `ENDM` 之间是完成特定功能的宏体。

    * `ENDM` 左侧不写名称，这一点不同于左侧带子程序名的 `PROC/ENDP` 配对。

### 形参实参与助记符连接

* **形式参数与实际参数**

    * `MACRO` 右侧声明形参，引用宏时提供实参；同一位置的实参在汇编时逐个代入宏体。

    * 没有形参时不写括号，宏名后直接使用宏体。

* **连接操作符（Concatenation Operator，&）**

    * 宏体中只写实参无法独立决定的部分，把固定字符与实参用 `&` 连接成完整助记符。

    * 例如移位助记符都以 `S` 开头时，宏体写 `S&DIR REG,CL`，由 `DIR` 补出 `HL`、`HR`、`AL` 或 `AR`。

    * 若形参本身给出完整助记符，则可直接把该形参放在操作符位置，不必再连接。

* **移位宏定义**

    * 宏参数分别代表通用寄存器、移位方向和移位次数；移位次数先送入 `CL`，再按方向移位。

    ```asm
    SHIFT MACRO REG, DIR, N
        MOV  CL, N
        S&DIR REG, CL
    ENDM
    ```

    * 调用 `SHIFT AX,HL,4` 时，汇编结果等效为 `MOV CL,4` 和 `SHL AX,CL` 两条实际指令。
