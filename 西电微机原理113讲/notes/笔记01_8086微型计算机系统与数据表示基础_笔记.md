# 8086微型计算机系统与数据表示基础

## 微型计算机系统与信息链路

* **算术逻辑运算单元（Arithmetic Logic Unit，ALU）**

    * > **定义**：完成算术运算与逻辑运算的功能部件。
    * 算术运算包括加、减、乘、除，逻辑运算包括与、或、非。
    * 运算数据可来自存储器，也可直接来自输入设备。
    * 运算结果可写回存储器，也可送往输出设备。

* **控制器（Control Unit）**

    * > **定义**：根据指令产生控制信号，组织取指、译码、执行及数据流动的功能部件。
    * 控制器决定 ALU 使用什么数据、按什么次序和方式运算。
    * 存储器读写、数据输入输出都要由控制器发出相应命令。

* **早期计算机五大部件**

    * 控制器负责指挥。
    * ALU 负责实际运算。
    * 存储器保存程序和数据。
    * 输入设备向系统送入信息。
    * 输出设备接收系统结果。
    * 控制器贯穿数据传送全过程，ALU 是运算中心。

* **微处理器（Microprocessor，CPU）**

    * 半导体技术把控制器、ALU 等集成到小型芯片中，形成微处理器。
    * CPU 通过数量有限的引脚与外部存储器和 I/O 接口交换信息。
    * CPU 是微型计算机的核心，但 CPU 芯片本身不是一台能够独立工作的完整计算机。
    * 外部世界不能把物理量原样交给 CPU，CPU 只能处理数字信息。

* **微型计算机系统**

    * > **定义**：以微处理器为核心，配置三类系统总线、存储器、I/O 接口、I/O 设备、电源和系统工作程序所形成的完整系统。
    * 存储器和 I/O 接口挂接在系统总线上。
    * ROM 中保存断电不丢失的系统管理程序。
    * 用户程序及其运行数据通常在 RAM 中处理。
    * 缺少总线形成电路、存储器、接口、设备或程序中的任一关键部分，硬件都不足以形成可工作的系统。

* **信息传输总线**

    * > **定义**：传送数据信息、地址信息和控制信息的专用通道。
    * 数据总线（Data Bus，DB）传送读写数据，方向为双向。
    * 地址总线（Address Bus，AB）指出存储器单元或 I/O 接口地址，方向为单向。
    * 控制总线（Control Bus，CB）既传送 CPU 的读、写等命令，也传送设备反馈的状态信息。
    * 地址解决“访问谁”，控制决定“怎样访问”，数据总线完成“传送什么”。
    * CPU 访问存储器时，先由地址总线给出目标地址，再由控制总线发出读或写命令，最后在数据总线上交换数据。

* **引脚复用与系统总线形成电路**

    * 芯片引脚数量有限，同一根引脚可在不同时序阶段承担不同功能。
    * 外部系统总线形成电路按信号时序把复用信号分离为数据总线、地址总线和控制总线。
    * CPU 引脚驱动能力较弱，外部电路还要用锁存器、缓冲器等器件完成分流和系统级驱动。
    * 复用只发生在不同时间片，不表示数据、地址和控制三类信号在同一时刻无规则混传。
    * 数据线数量决定一次传送的位数，地址线数量决定可组合出的地址数量；两种宽度不能混为一谈。

* **从物理世界到 CPU 的输入链路**

    * 温度、压力、速度、角度等物理量先由相应传感器转换为毫伏级电量。
    * 前端调理电路对传感器输出进行放大、滤波，并按 AD 输入量程进行必要的幅度变换。
    * 调理电路可使用 `RC`、`LC`、有源或无源滤波，需要时由 CPU 控制可编程增益放大器。
    * 模数转换器（Analog to Digital，AD）把模拟量转换为数字量，常见输出精度可为 8 位、10 位或 12 位。
    * AD 选型必须同时满足系统所需转换精度和转换速度。
    * CPU 通过控制命令决定 AD 何时开始采样。
    * 实验电路应在输入、输出信号链上预留测试点，避免随意把探头压在器件引脚上。
    * AD 输出的数字量通常先存入存储器，再由 CPU 取数、运算和保存结果。

* **从 CPU 到物理世界的输出链路**

    * CPU 结果若用于控制模拟对象，必须先经数模转换器（Digital to Analog，DA）变为模拟量。
    * DA 输出还要经过后端调理和必要的放大，形成真正用于控制的物理量。
    * 数码管和常用 LCD 等设备可直接接收数字量，不必先转换为模拟量。
    * CPU 数字结果控制模拟对象时，DA 与后端调理不能省略。

* **输入输出接口（Input/Output Interface）**

    * > **定义**：把设备的数据格式、传送方式或信号形式转换成 CPU 和系统总线可用形式的连接电路。
    * 任何 I/O 设备都不能直接与 CPU 通信，必须通过对应接口。
    * 输入方向是“设备 → 接口 → 系统总线 → CPU”，输出方向是“CPU → 系统总线 → 接口 → 设备”。
    * 显卡连接显示设备与系统总线，声卡连接音频设备与系统总线，都是接口承担转换与控制的具体形式。

* **地址线、存储空间与数据宽度**

    * $n$ 根地址线可形成 $2^n$ 种地址组合。
    * 存储器按字节组织时，地址数量就是可访问的字节数量。
    * 8 位数据线传送无符号数的范围为 $0\sim255$，传送有符号数的范围为 $-128\sim127$。
    * 16 位数据线传送无符号数的范围为 $0\sim65535$，传送有符号数的范围为 $-32768\sim32767$。
    * 地址线多少与“一次能搬运多少位”是两个不同问题。

* **只读存储器（Read-Only Memory，ROM）**

    * > **定义**：断电后信息仍能保留的存储器。
    * ROM 适合保存系统管理程序和固定程序。
    * 主板 ROM 中可保存 BIOS 程序，系统加电后 CPU 先读取并执行 BIOS。
    * BIOS 先完成 RAM 自检和主板 I/O 接口初始化，再从外部设备把操作系统读入 RAM。
    * ROM 的写入与运行时的读取是两个不同环节，不能理解为普通程序可随时改写 ROM。
    * 某些 CPU 内部自带 ROM；若容量不足，再通过外部总线扩充。

* **随机存取存储器（Random Access Memory，RAM）**

    * > **定义**：运行时可读可写、但断电后信息会丢失的存储器。
    * CPU 执行程序时产生的数据通常放在 RAM 中，因此 RAM 也称数据存储器。
    * “程序存储器”和“数据存储器”描述的是当前系统中的用途，真正决定读写方式的是器件读写特性和控制信号。
    * 8086 内部没有存储器电路，组成系统时必须把所需存储器挂接到外部总线上。

* **存储器芯片引脚**

    * `A0`、`A1` 等为地址引脚，地址线数量决定可接收的地址码位数。
    * `D0`～`D7` 等为数据引脚，8 位存储器可用 8 条数据线并行传送 8 位数据。
    * 输出允许信号 $\overline{\mathrm{OE}}$ 为低电平时，地址对应单元可以把数据送到数据线。
    * 写允许信号 $\overline{\mathrm{WE}}$ 或 $\overline{\mathrm{WR}}$ 有效时，外部数据才能写入指定单元。
    * 一个地址单元通常存放一个字节，即 8 位；只有 4 位宽的存储器芯片可两片并联组成 8 位单元。

* **指令（Instruction）**

    * > **定义**：按 CPU 规定方式编码、能够同时说明“做什么”和“怎样做”的一组二进制代码。
    * 任意二进制数不会自动成为指令，必须符合 CPU 的编码规则。
    * 指令既可能通过数据信息送入 CPU，又会指挥 CPU 控制存储器或 I/O 端口。
    * 汇编语言用助记符和操作数表达机器指令，例如 `MOV AL, 02H` 表示把 `02H` 送入 `AL`。
    * `MOV` 是指令助记符，`ADD`、`SUB` 等助记符分别提示相应动作。

* **机器语言、汇编语言与程序执行**

    * 机器语言能由 CPU 直接识别，但二进制代码难以设计、记忆和修改。
    * 汇编语言用符号描述机器代码，属于直接面向机器的低级语言。
    * 高级语言中的符号程序经过编译成为机器代码。
    * 汇编语言中的符号程序经过汇编成为机器指令。
    * 汇编后的机器代码还要由专用设备写入程序存储器，系统上电时 CPU 再从存储器中读取并执行。
    * 汇编、写入存储器和运行程序是三个不同环节。

## 8086外部结构与总线控制

* **双列直插式封装（Dual In-line Package，DIP）**

    * 8086 和 8088 都采用 40 引脚双列直插式封装。
    * 封装决定芯片在 PCB 上的安装与引脚连接形式。
    * 8086 内部寄存器、ALU 和片内数据总线均为 16 位，外部数据宽度也是 16 位。
    * 8088 内部仍为 16 位，但外部数据引脚只有 8 位，外部一次最多传送 8 位，因此称为准 16 位微处理器。
    * 8086 与 8088 引脚分布大体对应，但外部数据宽度不同。

* **微处理器外部结构**

    * 数据引脚传送数据，地址引脚输出地址，控制引脚表示读写等操作条件。
    * 三类引脚上的信号构成微处理器总线。
    * CPU 通过微处理器总线与外部存储器交换指令和数据，与 I/O 接口交换信息，并输入输出控制信号。
    * 引脚功能必须结合信号名称、有效电平和时序判断，不能只按引脚所在位置死记。
    * CPU 的直接信息交换对象是存储器电路或 I/O 接口电路，而不是设备本体。

* **地址与数据复用引脚**

    * 8086 对外具有 20 位地址能力，地址范围由 `A0`～`A19` 表示。
    * `AD0`～`AD15` 在不同时间片可承担地址或数据功能，属于复用引脚。
    * 在一个存储器或 I/O 访问周期内，地址阶段由复用引脚送出地址，数据阶段再由同一组引脚传送数据。
    * 引脚名称说明功能类别，实际引脚关系还取决于它何时出现以及有效电平。

* **存储器与 I/O 选择信号 `M/IO`**

    * > **定义**：8086 用来区分存储器访问和 I/O 访问的控制信号。
    * 8086 第 28 脚为 `M/IO`。
    * `M/IO=1` 表示当前总线周期访问存储器。
    * `M/IO=0` 表示当前总线周期访问 I/O 接口。
    * 存储器地址与 I/O 地址可能使用相同数值时，必须由 `M/IO` 区分访问对象。

* **低电平有效的读写信号**

    * 8086 第 29 脚为 $\overline{\mathrm{WR}}$，低电平表示 CPU 正在向外写数据。
    * 8086 第 32 脚为 $\overline{\mathrm{RD}}$，低电平表示 CPU 正在从外部读数据。
    * 信号名称后的横线或 `#` 表示低电平有效。
    * 读和写方向互斥，不可能同时有效。

    | 当前操作 | `M/IO` | `WR#` | `RD#` |
    | :--- | :---: | :---: | :---: |
    | 读存储器 | 高电平 | 高电平 | 低电平 |
    | 写存储器 | 高电平 | 低电平 | 高电平 |
    | 读 I/O 接口 | 低电平 | 高电平 | 低电平 |
    | 写 I/O 接口 | 低电平 | 低电平 | 高电平 |

* **四类控制信号的形成**

    * `M/IO` 先选择存储器空间或 I/O 空间。
    * `WR#`、`RD#` 再选择写方向或读方向。
    * `M/IO=0` 且 $\overline{\mathrm{WR}}=0$ 可形成 I/O 写控制信号。
    * `M/IO=0` 且 $\overline{\mathrm{RD}}=0$ 可形成 I/O 读控制信号。
    * 对存储器控制信号取反后再经与非门组合，可形成存储器读写控制信号。

* **从 CPU 引脚到系统部件**

    * 8086 复用引脚和弱驱动输出先进入系统总线形成电路。
    * 总线形成电路按时序分离出数据总线、地址总线和控制总线。
    * 外部存储器、I/O 接口及其他部件再挂接到三类系统总线上。
    * 先形成总线，再扩展存储器和接口，最后连接 I/O 设备，顺序不能颠倒。

## 数制、码制与数据表示

* **二进制（Binary）**

    * > **定义**：计算机内部表示和处理信息的基本数制，只使用 `0` 和 `1`。
    * 键盘输入通常是十进制，CPU 内部处理结果仍必须用二进制表示。
    * 程序中的十进制、十六进制和负数都由汇编工具翻译为二进制机器形式。
    * 二进制数参加运算前必须先确定字长 $n$。

* **字节型数据与字型数据**

    * 存储器通常按字节组织，一个字节为 8 位。
    * 8 位数据称字节型数据，16 位数据称字型数据。
    * 题目要求 8 位结果时，即使有效数字不足 8 位，也必须把高位补为 0。
    * 位序从右向左递增，最低位为第 0 位，最高位为 $n-1$ 位。

* **8 位位权**

    | 位次 | 第 7 位 | 第 6 位 | 第 5 位 | 第 4 位 | 第 3 位 | 第 2 位 | 第 1 位 | 第 0 位 |
    | :--- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
    | 位权 | 128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 |

* **十进制转二进制**

    * 可用除 2 取余法，也可按位权从大到小逼近。
    * 按权转换时，先判断当前数能否减去最大位权；能减则该位置 1，并从余数中减去该位权，否则置 0。
    * $93=01011101_2$，对应十六进制 `5DH`。
    * 最低位是第 0 位，最高位是第 7 位，位权从右向左增大。
    * 写定长二进制数时不能省略高位补零。

* **二进制转十进制**

    * > **定义**：位置加权法是把每一位数字乘以该位权，再把乘积相加。
    * $01011101_2=0\times2^7+1\times2^6+0\times2^5+1\times2^4+1\times2^3+1\times2^2+0\times2^1+1\times2^0=93$。
    * 最高位为 0 不影响结果，但任何位只要为 1，其位权都必须计入。

* **十六进制（Hexadecimal）**

    * > **定义**：以 16 为基数、用 `0`～`9` 和 `A`～`F` 表示数码的数制。
    * 十六进制每一位对应 4 个二进制位，是二进制的压缩写法。
    * 二进制转十六进制时从右向左每 4 位分组，左端不足 4 位补 0。
    * 十六进制数以 `A`～`F` 开头时，为避免被识别成名称，汇编源程序中应在前面加 `0`，如 `0B3H`、`0F0H`。
    * 数值末尾的 `H` 表明它是十六进制数。

* **十进制逐位累积输入算法**

    * 每读入一个十进制数字，先把原累积值乘以 10，再加上新数字。
    * $$\text{新累积值}=\text{原累积值}\times10+\text{本次输入的数字}$$
    * 输入 `9` 后再输入 `5`，得到 $9\times10+5=95$。
    * CPU 从第一次更新开始执行的仍是二进制运算，结果也按二进制保存。

* **二进制转十进制除 10 取余算法**

    * 把被处理的数反复除以 10，依次得到个位、十位、百位等余数。
    * 商为 0 时停止。
    * 余数产生顺序是从低位到高位，输出时必须反向排列。
    * 式中的 10 仍是程序常数，CPU 并没有因此改用十进制运算电路。
    * 该算法循环结构清楚，适合直接写成程序。

* **二进制转十进制比较法**

    * 先把结果的百位、十位、个位统计值清零。
    * 原数大于等于 100 时，反复让百位加 1，并从原数中减 100。
    * 剩余值大于等于 10 时，反复让十位加 1，并从剩余值中减 10。
    * 最后小于 10 的余数就是个位。
    * 比较法只适用于本长文给出的 8 位无符号数 $0\sim255$ 场景。

* **寄存器（Register）**

    * > **定义**：CPU 内部用于高速暂存数据、地址或状态信息的部件。
    * 参加运算的数据多数存放在外部存储器中，每次经总线取出会增加距离与时间开销。
    * 把常用数据提前放入寄存器，可以缩短 CPU 运算时的数据往返距离。
    * 寄存器数量受芯片体积限制，是运算速度与芯片规模之间的折中。
    * 8086 的主要内部寄存器为 16 位，同时提供 8 位寄存器以适应字节型数据。

* **8086 早期数据寄存器拆分**

    * `AX=AH:AL`，其中 `AH` 为高 8 位，`AL` 为低 8 位。
    * `BX=BH:BL`，其中 `BH` 为高 8 位，`BL` 为低 8 位。
    * `CX=CH:CL`，其中 `CH` 为高 8 位，`CL` 为低 8 位。
    * `DX=DH:DL`，其中 `DH` 为高 8 位，`DL` 为低 8 位。
    * 字节运算选择 8 位部分，字运算选择完整的 16 位寄存器。

* **无符号数（Unsigned Number）**

    * 8 位无符号数范围为 $0\sim255$，十六进制表示为 `00H`～`FFH`。
    * 16 位无符号数范围为 $0\sim65535$，十六进制表示为 `0000H`～`FFFFH`。
    * 无符号数不承担正负号，所有位都参与表示数值。

* **带符号数的最高位**

    * 8 位带符号数的第 7 位是符号位，16 位带符号数的第 15 位是符号位。
    * 最高位为 0 表示正，最高位为 1 表示负。
    * 不能只看到最高位为 1 就判断加法溢出，因为普通负数的补码最高位本来也为 1。

* **原码（Sign-Magnitude）**

    * > **定义**：最高位表示符号，其余位表示数值绝对值的机器数表示法。
    * 8 位 `+3` 的原码为 `00000011B`，即 `03H`。
    * 8 位 `-3` 的原码为 `10000011B`，即 `83H`。
    * 原码有正零 `00000000B` 和负零 `10000000B` 两种零表示。

* **补码（Two's Complement）**

    * > **定义**：正数补码等于自身，负数补码为 $2^n+x$ 的机器数表示法。
    * $$[x]_{\text{补}}=\begin{cases}x,&x\ge0\\2^n+x,&x<0\end{cases}$$
    * 正数补码与原码相同。
    * 负数由原码转补码时，符号位保持不变，其余数值位逐位取反，最后最低位加 1。
    * 8 位 `-3` 的原码为 `10000011`，低七位取反为 `11111100`，末位加 1 得 `11111101`，即 `FDH`。
    * 补码只有唯一的零，8 位零表示为 `00H`。
    * 汇编器可把源程序中的负数直接翻译为补码，不必由程序员手工求机器码。

* **带符号数范围**

    * 8 位补码表示范围为 $-128\sim127$。
    * 16 位补码表示范围为 $-32768\sim32767$。
    * 判断范围前必须先确认题目问的是有符号数还是无符号数，以及字长是 8 位还是 16 位。

* **补码加法**

    * $$[x+y]_{\text{补}}=([x]_{\text{补}}+[y]_{\text{补}})\bmod2^n$$
    * 补码加法可直接由二进制加法器完成，但机器只保留低 $n$ 位。
    * 8 位 $53+31=84$ 可用 `0101 0100` 正确表示。
    * 8 位 $53+91=144$ 超过最大正数 127，低 8 位得到 `1001 0000`，必须检查溢出后才能解释结果。
    * 补码加法只保证低 $n$ 位位模式正确，结果是否越出可表示范围还要检查溢出标志。

* **补码加法溢出判定**

    * 检查进入最高符号位的进位和离开最高符号位的进位。
    * 两个进位都发生或都不发生，表示没有溢出。
    * 只有一个进位发生、另一个不发生，表示发生溢出。
    * 同号数相加却得到异号结果时，溢出标志置 1。
    * 最高位单独为 1 不能作为溢出判据。

* **补码减法与取补**

    * $$[x-y]_{\text{补}}=[x]_{\text{补}}-[y]_{\text{补}}=[x]_{\text{补}}+[-y]_{\text{补}}$$
    * 已知 $[y]_{\text{补}}$ 时，$[-y]_{\text{补}}=\overline{[y]_{\text{补}}}+1\pmod{2^n}$。
    * “各位取反、末位加一”称为取补、变补或求补。
    * 把减法改写为加上被减数的补码，可以复用加法器并简化 ALU。
    * 两个补码数相加或相减后，留下的低 $n$ 位仍是结果补码。
    * 需要真值时必须再求补还原，不能把补码位模式直接当成十进制值。

## 运算指令、状态标志与BCD调整

* **汇编运算指令格式**

    * 运算指令的一般形式为 `ADD dst, src`、`SUB dst, src`。
    * 逗号左侧是目的操作数 `dst`，右侧是源操作数 `src`。
    * 结果总是写回目的操作数。
    * `(AL)` 表示 `AL` 中保存的内容，而不是寄存器符号本身。

* **二进制加法规则**

    * `0+0=0`，不进位。
    * `0+1=1`，不进位。
    * `1+0=1`，不进位。
    * `1+1=0`，向高位进 1。
    * 97 与 89 的 8 位二进制分别为 `01100001` 和 `01011001`，相加结果为 `10111010`。

* **逻辑指令（Logical Instruction）**

    * 逻辑运算对两个数的每一位分别判断，与数值大小无关。
    * `AND dst, src`：只有 `1 AND 1=1` 时结果为 1，常用于把掩码选中的位清零。
    * `OR dst, src`：只有 `0 OR 0=0` 时结果为 1，常用于把掩码选中的位置 1。
    * `XOR dst, src`：相同得 0、不同得 1，常用于翻转掩码选中的位。
    * `NOT dst`：对唯一操作数的全部位取反，结果仍写回目的操作数。
    * `AND`、`OR`、`XOR` 会影响部分状态标志，`NOT` 不影响 PSW 中的任何状态标志。

* **逻辑掩码规则**

    * 清零指定位：掩码中待清零位写 0，其余位写 1，再执行 `AND`。
    * 置一指定位：掩码中待置一位写 1，其余位写 0，再执行 `OR`。
    * 取反指定位：掩码中待翻转位写 1，其余位写 0，再执行 `XOR`。
    * `AND AX, 0F0H` 用 `1111 0000B` 清零 `AX` 低四位。
    * `OR BX, 0FH` 用 `0000 1111B` 置位 `BX` 低四位。
    * `XOR AL, 0F0H` 用 `1111 0000B` 翻转 `AL` 高四位，同时保持低四位不变。

* **处理器状态字（Processor Status Word，PSW）**

    * > **定义**：CPU 内部用于记录运算结果状态及部分运行控制状态的寄存器。
    * PSW 宽度与处理器字长对应，8 位处理器对应 8 位 PSW，16 位处理器对应 16 位 PSW。
    * 8086 的 PSW 为 16 位，其中有 9 位有效位，另外 7 位未使用。
    * 9 位有效位分为 6 位状态标志和 3 位控制标志。
    * 运算先产生结果，结果再产生状态，程序最后根据状态选择分支。
    * 设计条件分支时，应先确定所需状态，再安排能产生该状态的运算，最后测试标志并跳转。

* **六个状态标志**

    | 标志 | 名称与位数 | 观察对象 | 置 1 条件 |
    | :--- | :--- | :--- | :--- |
    | `OF` | 溢出标志 | 有符号补码结果 | 同号数相加却得到异号结果 |
    | `SF` | 符号标志 | 结果最高位 | 结果第 7 位或第 15 位为 1 |
    | `CF` | 进位标志 | 最高位之外 | 最高位向前进位，或减法发生借位 |
    | `ZF` | 零标志 | 整个结果 | 结果为 0 |
    | `PF` | 奇偶标志 | 结果低 8 位 | 低 8 位中 1 的个数为偶数 |
    | `AF` | 辅助进位标志 | 第 3 位到第 4 位 | 第 3 位向第 4 位进位 |

* **溢出与进位的区别**

    * `OF` 判断补码有符号结果是否越出可表示范围，更适合带符号运算。
    * `CF` 记录最高位之外的进位或借位，更适合判断无符号数范围。
    * 最高位产生进位不等于补码溢出。
    * 进位成立而 `OF=0`、进位不成立而 `OF=1` 都可能出现。
    * 不能用最高位是 0 还是 1 代替溢出判断。

* **奇偶标志与串行校验**

    * `PF` 只检查结果低 8 位中 1 的个数，不检查 16 位结果的完整位数。
    * 串行通信逐位发送数据，可把第 7 位作为奇偶校验位。
    * 偶校验时，发送端选择校验位，使数据位与校验位中 1 的总数为偶数。
    * 接收端按同一规则检查，不符合约定说明传输发生错误。

* **辅助进位与半字节**

    * `AF` 观察 $b_3\rightarrow b_4$，不是判断整个字节是否溢出。
    * 二进制低 4 位到 16 才进位，十进制一位到 10 就要进位。
    * BCD 运算需要知道低 4 位是否超过 9，因此必须保留 `AF`。

* **8421BCD码（Binary-Coded Decimal，BCD）**

    * > **定义**：用 4 位二进制表示一个十进制数字，且位权保持为 $8、4、2、1$ 的编码。
    * 4 位二进制有 16 个状态，只取其中前 10 个表示十进制 $0\sim9$。
    * 每个码字的位权之和等于对应十进制数字。
    * `0101` 的位权和为 $4+1=5$，`1001` 的位权和为 $8+1=9$。
    * 十进制 53 的组合 BCD 为 `0101 0011`，即 `53H`。

* **组合BCD与分离BCD**

    * 组合 BCD 又称压缩 BCD，一个字节高 4 位放十位，低 4 位放个位。
    * 分离 BCD 中每个十进制数字独占一个字节，不用的高 4 位通常置 0。
    * 十进制 53 的分离 BCD 分别为 `0000 0101` 和 `0000 0011`。
    * 无论位模式被解释为普通十六进制还是 BCD，CPU 内部都只执行二进制运算。
    * BCD 是程序员赋予位模式的解释方式，不会改变 ALU 的加法电路。

* **BCD调整的原因与调整指令**

    * BCD 运算先由 CPU 按二进制规则算出位模式，再由程序员或调整指令修正为正确 BCD 结果。
    * 组合 BCD 加法使用无操作数的 `DAA`，调整对象固定为 `AL`。
    * 分离 BCD 加法使用 `AAA`。
    * 乘法和除法只处理分离 BCD。
    * BCD 调整属于算术运算指令类别，不是独立于算术运算之外的一类指令。
    * 任何 BCD 运算都要遵循“先运算、后调整”的顺序。

* **组合BCD的加 6 调整**

    * $3+8=11$ 在十进制中应进 1，但二进制低半字节只得到 `1011`，尚未到 16 因而没有进位。
    * 二进制和十进制的进位边界相差 $16-10=6$，所以需要加 `06H` 补偿缺失的十进制进位。
    * `53H+28H` 先得到 `7BH`，再加 `06H` 得 `81H`，对应十进制 81。
    * 低半字节大于 9，或 `AF=1` 时，加 `06H`。
    * 调整后再检查高半字节是否大于 9，或 `CF=1`；成立则加 `60H`。
    * `53H+28H` 调整后的 `81H` 高半字节不超过 9，且没有最高位之外进位，因此不再调整。

* **美国信息交换标准代码（American Standard Code for Information Interchange，ASCII）**

    * > **定义**：计算机中表示字符的编码，机器中以二进制位模式保存。
    * 数字字符 `'0'`～`'9'` 的编码为 `30H`～`39H`。
    * 大写字符 `'A'`～`'F'` 的编码为 `41H`～`46H`。
    * 小写字符 `'a'`～`'f'` 的编码为 `61H`～`66H`。
    * ASCII 原为 7 位编码，放入 8 位字节时最高位补 0。
    * 源程序中的 `'0'` 是字符，不是可直接参加算术的数值 0。

* **字符与数值的转换**

    * 键盘输入数字字符，CPU 得到的是字符编码。
    * 屏幕显示数值前，必须先把数值转换为对应字符编码。
    * 数字字符 `'0'`～`'9'` 转数值 $0\sim9$ 可减去 `30H`。
    * 数字字符也可与 `0FH`，清除高四位、保留数值低四位。
    * 大写 `'A'`～`'F'` 转数值 $10\sim15$ 可减去 `37H`。
    * 数值 $0\sim9$ 转数字字符分别加 `30H`。
    * 数值 $10\sim15$ 转大写 `'A'`～`'F'` 分别加 `37H`。

* **英文字母大小写转换**

    * 大写 `'A'`～`'Z'` 的编码为 `41H`～`5AH`，小写 `'a'`～`'z'` 的编码为 `61H`～`7AH`。
    * 对应大小写字符只有第 5 位不同，其余位相同。
    * `AND AL, 0DFH` 把第 5 位清零，可把字母统一转成大写。
    * `OR AL, 20H` 把第 5 位置 1，可把字母统一转成小写。
    * 这种方法不需要先判断字符当前属于大写还是小写。

## CPU内部结构与寄存器

* **CPU内部四类基本功能部件**

    * 算术逻辑单元 ALU 负责执行运算。
    * 寄存器负责暂存数据、地址和状态。
    * 控制器负责取指、暂存、译码和形成控制命令。
    * I/O 控制逻辑负责对 I/O 端口实施控制。

* **数据寄存器与地址寄存器**

    * 数据寄存器专门暂存数据。
    * 地址寄存器提供存储器读写的段内地址。
    * 地址寄存器在不需要提供地址时也可以暂存数据。
    * 16 位地址寄存器既能保存 16 位地址，也能保存 16 位数据。

* **取指、译码与执行**

    * 程序计数器或指令指针给出指令地址，控制器发出读命令。
    * 取回的指令代码先进入指令寄存器暂存。
    * 指令译码器分析“做什么”和“怎样做”。
    * 涉及存储器或 I/O 端口时，译码结果通知控制逻辑产生相应总线控制信号。
    * 一般微处理器中的指令寄存器为 8 位，只能暂存一个字节，不能据此断定整条指令只有一个字节。
    * 指令还可能带有后续操作码、立即数、位移量或偏移地址。
    * 指令执行完成后，程序计数器或指令指针按整条指令占用的字节数增加，再取下一条指令。

* **总线接口单元（Bus Interface Unit，BIU）**

    * > **定义**：8086 中负责与外部存储器和 I/O 端口交换信息的内部单元。
    * BIU 负责取指、形成物理地址和发出总线控制信号。
    * BIU 中包含段寄存器、指令指针 IP、地址产生逻辑和总线控制逻辑。
    * BIU 在指令队列尚未装满且 EU 不占用总线时持续取指。

* **执行单元（Execution Unit，EU）**

    * > **定义**：8086 中负责指令译码与执行的内部单元。
    * EU 的核心包括 ALU 和通用寄存器组。
    * EU 决定当前指令做什么、怎样执行。
    * EU 需要访问存储器或 I/O 端口时，会请求 BIU 让出外部总线。

* **指令队列寄存器（Instruction Queue Register）**

    * > **定义**：8086 内部由 6 个字节组成、按先进先出原则暂存已取回指令的队列。
    * 8088 的指令队列为 4 字节，8086 为 6 字节。
    * BIU 持续把指令字节送入队列，EU 从队首取指、译码和执行。
    * 取指与执行可以并行，8086 由此克服传统微处理器串行取指、串行执行的效率问题。
    * 8086 指令系统中最长指令为 5 字节，队列按指令字节依次形成，不能把“取回一条指令”理解为一次必然填满 6 字节。
    * BIU 停止取指的原因有队列已满或 EU 需要使用总线。
    * EU 停止工作的条件是指令队列已经为空。

* **8086十四个16位寄存器**

    * 4 个数据寄存器是 `AX`、`BX`、`CX`、`DX`。
    * 4 个地址指针和变址寄存器是 `SP`、`BP`、`SI`、`DI`。
    * 4 个段寄存器是 `CS`、`DS`、`ES`、`SS`。
    * 2 个控制寄存器是 `IP`、`PSW`。
    * 4 个数据寄存器都可拆分为两个独立寻址的 8 位寄存器，共形成 8 个 8 位通用寄存器。

* **累加器 `AX`**

    * `AX` 是 16 位累加器，高、低字节分别为 `AH`、`AL`。
    * 涉及运算尤其是自运算时，目的操作数优先选择 `AX`。
    * 字节运算通常选择 `AL`。
    * `MOV AL, 97` 可汇编为机器字节 `B0H 61H`，其中 `B0H` 是操作码，`61H` 是数值 `97` 的机器表示。

* **基址寄存器 `BX`**

    * `BX` 是 16 位数据寄存器，高、低字节分别为 `BH`、`BL`。
    * `BX` 可提供存储器间接寻址的 16 位段内偏移地址。
    * `[BX]` 默认使用数据段 `DS`。
    * `BX` 也可以在不需要提供地址时作为普通数据寄存器。

* **计数器 `CX`**

    * `CX` 是 16 位计数器，高、低字节分别为 `CH`、`CL`。
    * 循环次数通常初始化到 `CX`，每循环一次减 1，减到 0 时结束。
    * 8086 中专用的计数循环指令配合 `CX` 使用，换成其他寄存器需要额外编写代码。

* **数据寄存器 `DX`**

    * `DX` 是 16 位数据寄存器，高、低字节分别为 `DH`、`DL`。
    * I/O 操作中可用 `DX` 暂存 16 位数据。
    * 8086 的 `IN`、`OUT` 指令采用寄存器间接寻址时，端口地址放在 `DX` 中。

* **堆栈指针 `SP` 与基址指针 `BP`**

    * `SP` 给出 `PUSH`、`POP` 操作的段内栈顶偏移地址，默认段为 `SS`。
    * `BP` 可以像 `BX` 一样提供存储器间接寻址的段内偏移地址。
    * `BX` 默认使用 `DS`，`BP` 默认使用 `SS`。
    * 同样使用 `[0002H]` 时，使用 `BX` 访问数据段，使用 `BP` 访问堆栈段。
    * 确实需要用 `BP` 访问数据段时，应加段超越前缀显式指定段。

* **源变址寄存器 `SI` 与目的变址寄存器 `DI`**

    * `SI` 是源变址寄存器，`DI` 是目的变址寄存器。
    * `SI`、`DI` 都可提供 16 位地址，使用方括号时默认对应 `DS`。
    * 字符串操作的源串位于 `DS:SI`。
    * 字符串操作的目的串固定位于 `ES:DI`。
    * 每次字符串传送后，`SI` 和 `DI` 按字节或字的数据长度自动增加或减少。
    * “变”指地址随每次元素传送自动变化；使用普通数据传送指令时，`SI`、`DI` 不会自动改变。

* **段超越前缀（Segment Override Prefix）**

    * 段超越前缀也称段前缀，用于改变指令的默认逻辑段。
    * 普通 `BX`、`SI`、`DI` 间接寻址默认使用 `DS`。
    * `BP` 间接寻址默认使用 `SS`。
    * 加段超越前缀后，汇编得到的指令代码增加 1 字节。

* **四个段寄存器**

    * `CS` 是代码段寄存器，保存代码段段值。
    * `DS` 是数据段寄存器，保存数据段段值。
    * `ES` 是附加数据段寄存器，保存附加数据段段值。
    * `SS` 是堆栈段寄存器，保存堆栈段段值。
    * 段寄存器保存的是段值，不是已经左移 4 位后的段基址。
    * 程序通常需要自行初始化 `DS`、`ES`、`SS`。
    * `CS` 的赋值由操作系统或程序装入过程完成，用户程序不能把 `CS` 当作目的操作数写入。

* **指令指针 `IP`**

    * `IP` 是 16 位指令指针寄存器，等效于一般处理器中的程序计数器 PC。
    * `CS` 指出代码段在哪一段，`IP` 指出当前指令在该段中的位置。
    * 取指令的逻辑地址固定为 `CS:IP`。
    * 程序运行时不能把 `IP` 当作普通目的操作数任意写入。

## 控制标志、堆栈与分段寻址

* **方向控制标志 `DF`**

    * `DF` 控制字符串操作中 `SI`、`DI` 自动变化的方向。
    * `DF=0` 时，`SI`、`DI` 按地址增大方向变化，字节操作加 1，字操作加 2。
    * `DF=1` 时，`SI`、`DI` 按地址减小方向变化，字节操作减 1，字操作减 2。
    * 正向传送时 `SI`、`DI` 初始化到串首单元，反向传送时初始化到串末单元。
    * `CLD` 使 `DF` 清零，`STD` 使 `DF` 置 1；复位时 `DF` 自动清零。

* **中断（Interrupt）**

    * > **定义**：CPU 执行用户程序时，因特殊事件暂停当前程序，转去执行服务子程序，服务结束后返回断点继续执行的过程。
    * CPU 内部提出的中断属于内部中断，不能由外部屏蔽。
    * 外部设备提出的请求属于外部中断。
    * 8086 的 `NMI` 是不可屏蔽中断请求，CPU 必须响应。
    * 8086 的 `INTR` 是可屏蔽中断请求，是否响应受 `IF` 控制。

* **中断允许标志 `IF`**

    * `IF` 控制 CPU 是否响应外部可屏蔽中断。
    * `IF=0` 表示关闭可屏蔽中断，外部请求不响应。
    * `IF=1` 表示允许 CPU 在收到 `INTR` 请求后转入服务程序。
    * `CLI` 使 `IF` 清零，`STI` 使 `IF` 置 1；复位时 `IF` 自动清零。

* **陷阱标志 `TF`**

    * `TF` 控制单步执行和单步调试。
    * `TF=1` 时，CPU 每执行完一条指令就产生一次陷阱中断。
    * `TF` 位于 PSW 第 8 位，复位时自动清零。
    * 8086 没有专用的 `TF` 置位、清零指令。
    * 修改 `TF` 可先把 `FLAGS` 压栈并弹出到 `AX`，按位修改后再压回 `FLAGS`。
    * 置 `TF` 可执行 `OR AX, 0100H`，清 `TF` 可执行 `AND AX, 0FBFFH`。
    * `PUSH FLAGS`、`POP AX`、按位操作、`PUSH AX`、`POP FLAGS` 构成“取出 PSW → 修改 → 写回 PSW”的通用方法。

* **堆栈（Stack）**

    * > **定义**：按先进后出原则组织的一段存储器区域。
    * 8086 堆栈位于 CPU 外部存储器中，程序需在存储器空间内定义栈区。
    * `PUSH` 把数据压入堆栈，`POP` 把最后压入的数据弹出。
    * 8086 堆栈按字操作，每次压入或弹出一个 16 位字。
    * 复杂程序可用堆栈暂存暂时不用的寄存器内容，弥补内部寄存器数量有限的问题。

* **堆栈指针 `SP` 的入栈与出栈规则**

    * 初始化后，`SP` 指向栈底加 1 处的空字单元。
    * `PUSH` 时先执行 `SP←SP-2`，再把一个字写入新栈顶。
    * `POP` 时先从当前 `SP` 指向的单元读出一个字，再执行 `SP←SP+2`。
    * 每压入或弹出一个字，`SP` 都移动 2 个字节。
    * 固定位置是初始化建立的栈底，移动位置是由 `SP` 指示的活动栈顶。
    * 先压入的数据必须先弹出，后压入的数据必须先恢复。
    * 每次 `PUSH` 都应有对应的 `POP`，使 `SP` 最终回到初始位置。

* **堆栈的字内字节排列**

    * 压入 `AX` 时，`AL` 写入低地址，`AH` 写入高地址。
    * 压入 `BX` 时，`BL` 写入低地址，`BH` 写入高地址。
    * 压栈前先减小 `SP`，因此新字单元位于先前栈顶的低地址方向。

* **堆栈余量与失衡**

    * 连续 `PUSH` 会使 `SP` 向低地址移动，`POP` 过多会使 `SP` 越过堆栈另一端。
    * `SP` 越出已定义堆栈区域称为堆栈失衡，可能导致系统死机，只能依靠复位恢复。
    * 堆栈区应按实际需要定义，并预留约 30% 富余量，以容纳后续局部数据、调用层次和程序修改。

* **分段寻址的由来**

    * 8086 有 20 位地址线，可表示 $2^{20}$ 字节的 1 MB 外部存储器空间。
    * `BX`、`BP`、`SI`、`DI`、`SP` 等内部地址相关寄存器只有 16 位，只能直接表示 $2^{16}$ 字节的 64 KB 范围。
    * 8086 用 16 位段值和 16 位偏移地址共同描述 20 位物理地址，而不把地址寄存器直接扩充为 20 位。
    * 段值负责指明逻辑段，偏移地址负责指明段内具体位置。

* **逻辑段边界与重叠**

    * 一个逻辑段最大为 64 KB，但实际程序可以只定义所需长度。
    * 逻辑段起始物理地址必须能被 16 整除。
    * 1 MB 空间共有 $2^{16}=64\text{ K}$ 个不同段起始位置。
    * 相邻段起点只相隔 16 字节，而每段最长 64 KB，因此理论段范围会大量重叠。
    * 一个物理单元可以同时落在多个逻辑段范围内，逻辑段不是把内存切成互不重叠的固定小盒子。
    * 汇编程序装入实际程序时会寻找可用空间并对齐各段边界，不会随意让各段互相覆盖。

* **逻辑地址与物理地址**

    * > **定义**：逻辑地址使用 `S:EA` 表示，其中 `S` 为 16 位段值，`EA` 为 16 位段内偏移地址。
    * 段基址为 $S\times16$，不是直接等于 `S`。
    * 20 位物理地址计算公式为 $$PA=S\times16+EA=(S\ll4)+EA$$。
    * 逻辑地址 `0001H:0010H` 与 `0000H:0020H` 的物理地址都为 `00020H`。
    * 逻辑地址可以不同，但一个已确定物理存储单元的物理地址始终唯一。
    * 汇编程序和 DEBUG 中显示的地址首先是逻辑地址，不应直接当作已经形成的物理地址。

* **取指令地址形成**

    * 取指令时，`CS` 提供代码段段值，`IP` 提供代码段内偏移地址。
    * $$PA=CS\times16+IP$$
    * 条件转移只改变 `IP` 时，仍在当前代码段内取指。
    * 远转移或调用另一代码段中的子程序时，`CS` 与 `IP` 同时改变。

* **一般数据操作地址形成**

    * 一般数据操作由段寄存器或段超越前缀提供段地址，由寻址方式计算 `EA`。
    * `BX`、`SI`、`DI` 间接寻址默认使用 `DS`。
    * `BP` 间接寻址默认使用 `SS`。
    * `EA=BX` 对应 `[BX]`，`EA=BX+DISP` 对应 `[BX+DISP]`。
    * `EA=BP` 对应 `[BP]`，`EA=BP+DISP` 对应 `[BP+DISP]`。
    * 物理地址统一由 `PA=段值×16+EA` 得到。

* **堆栈操作地址形成**

    * `PUSH` 时，`SS` 提供段值，先计算新偏移 `SP-2`。
    * 入栈物理地址为 $$PA=SS\times16+(SP-2)$$。
    * `POP` 时先用当前 `SP` 形成地址 $$PA=SS\times16+SP$$，读出后再令 `SP←SP+2`。
    * 压栈时低字节写低地址，高字节写高地址。

* **字符串操作地址形成**

    * 源串段地址默认来自 `DS`，偏移地址由 `SI` 提供。
    * 目的串段地址固定来自 `ES`，偏移地址由 `DI` 提供。
    * `SI` 的源地址和 `DI` 的目的地址分别形成两条同时存在的地址通路。

    | 操作类型 | 段地址 | 段内有效地址 `EA` | 必须掌握的规则 |
    | :--- | :--- | :--- | :--- |
    | 取指令 | `CS` | `IP` | 固定为 `CS:IP` |
    | 堆栈入栈 | `SS` | `SP-2` | 先让 `SP` 减 2 |
    | 堆栈出栈 | `SS` | `SP` | 先按 `SP` 取数，再让 `SP` 加 2 |
    | 一般数据操作 | 默认 `DS` 或 `SS` | 由寻址方式确定 | `BX/SI/DI` 默认 `DS`，`BP` 默认 `SS` |
    | 字符串源操作数 | 默认 `DS` | `SI` | 源串为 `DS:SI` |
    | 字符串目的操作数 | 固定 `ES` | `DI` | 目的串为 `ES:DI` |

## 存储器格式、对准访问与I/O接口

* **定义伪指令**

    * `DB` 是 Define Byte，用于定义字节型数据，每个数据占 1 字节。
    * `DW` 是 Define Word，用于定义字型数据，每个数据占 2 字节。
    * `DD` 是 Define Double word，用于定义双字型数据，每个数据占 4 字节。
    * 伪指令告诉汇编程序怎样定义和存放数据，不要求 CPU 执行。
    * `ADD`、`PUSH`、`POP` 等是指令，描述 CPU 要执行的动作。
    * 数据定义在哪个逻辑段中，段地址就由相应段寄存器提供。

* **字节型数据存放**

    * 一个字节型数据占用一个字节地址单元。
    * 连续定义的字节型数据按偏移地址加 1 依次存放。
    * `DB 12H, 0CH, -12` 占用三个连续地址单元。
    * `-12` 的原码为 `0000 1100`，符号位不变、低七位取反、末位加 1，补码为 `F4H`。

* **字型数据存放**

    * 一个字型数据由两个相邻字节单元组成，占 2 字节。
    * 连续定义的字型数据按偏移地址加 2 依次存放。
    * 字的起始地址由低地址处的字节单元决定。
    * 字中第 0 字节存放在最低地址，第 1 字节存放在随后一个较高地址。
    * 对数值 `5678H` 写内存时，低地址存 `78H`，高地址存 `56H`。
    * `DB` 每项推进 1 字节，`DW` 每项推进 2 字节，两个偏移推进量不能混淆。

* **双字型数据存放**

    * 一个双字型数据包含 4 个字节，由两个相邻字组成。
    * 四个字节按第 0、1、2、3 字节从低地址到高地址依次存放。
    * `DD` 定义的不是一个独立的新存储实体，而是当前地址开始的连续 4 个字节。

* **数据总线与字节地址奇偶性**

    * 8086 的 16 位数据总线分为 `D0～D7` 和 `D8～D15` 两组。
    * 偶地址字节使用 `D0～D7` 传送。
    * 奇地址字节使用 `D8～D15` 传送。
    * CPU 根据地址奇偶性自动选择相应数据线，程序不需要手工指定。

* **对准字单元（Aligned Word）**

    * > **定义**：起始地址能被 2 整除的字单元。
    * 偶地址是 `0` 端、`2` 端、`4` 端等。
    * 对准字的低字节在偶地址，经 `D0～D7` 传送。
    * 对准字的高字节在奇地址，经 `D8～D15` 传送。
    * 两个字节可在同一总线周期内并行传送，因此 16 位字读写用 1 个总线周期。

* **未对准字单元（Unaligned Word）**

    * > **定义**：起始地址不能被 2 整除的字单元。
    * 奇地址是 `1` 端、`3` 端、`5` 端等。
    * 未对准字的低字节位于奇地址，只能使用 `D8～D15`。
    * 高字节位于随后偶地址，只能使用 `D0～D7`。
    * 两个字节不能在同一总线周期内进入各自正确的数据线，因此需要 2 个总线周期。
    * “对准访问快一倍”只指字数据在总线上的传送时间，不表示包含取指、运算和循环的整段程序都快一倍。

    | 字起始地址 | 对准情况 | 低字节数据通路 | 高字节数据通路 | 总线周期数 |
    | :---: | :--- | :--- | :--- | ---: |
    | `0006H` | 对准 | `D0～D7` | `D8～D15` | 1 |
    | `0003H` | 未对准 | 第 1 周期用 `D8～D15` | 第 2 周期用 `D0～D7` | 2 |

* **对准访问的程序设计**

    * 频繁按字读写的变量应尽量从偶地址开始。
    * `BX=0006H` 时，`MOV WORD PTR [BX], AX` 访问 `DS:0006H` 的对准字。
    * `SI=0003H` 时，`MOV WORD PTR [SI], AX` 访问 `DS:0003H` 的未对准字，需要两个总线周期。

* **8086存储器地址空间**

    * 8086 的 `A0`～`A19` 共 20 根地址线全部用于外部存储器寻址。
    * 每个地址对应一个字节单元，地址空间为 $$2^{20}=1\,048\,576\text{ 字节}=1\text{ MB}$$。
    * 8086 的 I/O 端口只使用其中 16 位地址，理论空间为 $2^{16}$ 个端口地址，即 64 K 字节。

* **8086与IBM PC的I/O地址空间**

    * 8086/8088 理论上有 16 位 I/O 地址空间，即 `0000H`～`FFFFH`。
    * IBM PC 实际只用 `A0`～`A9` 共 10 根线为 I/O 编址，以简化地址译码电路。
    * IBM PC 实际 I/O 空间为 $2^{10}$ 个地址，即 `000H`～`3FFH`，共 1 K 字节。
    * `000H`～`1FFH` 分配给主板 I/O。
    * `200H`～`3FFH` 分配给插件板 I/O。
    * 实际分配插件地址时必须避开系统中已被占用的地址。
    * 64 K 是处理器理论 I/O 空间，1 K 是 IBM PC 实际采用的空间，两者不能混淆。

* **I/O端口（I/O Port）**

    * > **定义**：I/O 接口中供 CPU 与设备交换某一种信息的寄存器或通道。
    * 每个端口至少应分配一个端口地址，常见情况是一个端口使用一个地址。
    * 一个设备端口也可能占用一段连续地址，但整段都应保留，不能只占起点后又把后续地址分给其他端口。
    * CPU 通过系统总线访问端口地址，再由接口把信息送往设备。

* **状态端口、数据端口与命令端口**

    * 状态输入端口把“设备是否准备好”等状态信息送给 CPU。
    * 数据端口传送 CPU 输出或设备输入的实际数据。
    * 命令输出端口把动作、时序或联络信号送给设备。
    * 一个端口只承担一种信息任务，可避免把状态误当数据或把命令混入数据。

* **握手（Handshaking）**

    * > **定义**：CPU 与设备双方确认何时可以交换数据、一次交换是否完成的联络过程。
    * CPU 先读取状态端口，设备未准备好时继续查询。
    * 设备准备好后，CPU 才向数据输出端口送出数据。
    * 输出端口先锁存数据，CPU 再通过命令端口通知“数据有效”。
    * 设备收到通知后取走数据。
    * 数据总线上有数据不等于设备已经知道何时取数，锁存和握手用于保证时序。

* **输入端口与三态输出**

    * > **定义**：三态输出可以呈现高电平、低电平和高阻态。
    * 高阻态表示输出端暂时不主动驱动数据总线。
    * 高阻态不是输出 0，输出 0 仍然是在驱动总线。
    * CPU 选中某输入端口时，该端口驱动数据总线。
    * 未选中时，输入端口必须进入高阻态，把总线让给其他部件。
    * 多个输出同时驱动同一根数据线会产生总线竞争，严重时会损坏器件。
    * 74LS244 是单向缓冲器，74LS245 是双向缓冲器，可帮助接口控制方向、使能和总线隔离。

* **输出端口与锁存**

    * 输出端口被写入后，数据必须保持到设备取走为止。
    * CPU 速度可能远高于打印机等设备，不能让输出数据只短暂出现在总线上。
    * 锁存寄存器使输出数据不随 CPU 下一次总线操作立即消失。
    * 8 位输出锁存可使用带 8 个输入和 8 个输出的 74LS373 一类器件。
    * 数据写入并锁定后，还要用命令或联络信号通知设备取走。

* **I/O接口地址译码**

    * 每个 I/O 接口都要分配地址，CPU 对接口的读写实质上是对其地址读写。
    * 地址译码器把地址线和 I/O 有效控制信号组合为接口选通信号。
    * 只有地址吻合且当前确实执行 I/O 操作时，相应接口才被选中。
    * 不能只看到地址线上出现 `1001` 就断言要选 I/O 接口，还必须同时检查 I/O 有效控制信号。
    * 选通信号再与读写控制配合，决定数据传送方向。

* **I/O直接寻址与间接寻址**

    * 直接寻址在指令中直接给出端口地址。
    * 寄存器间接寻址把端口地址放在 `DX` 中，再由 `IN`、`OUT` 访问。
    * `MOV DX, 2000H` 中的 `2000H` 是端口地址，不是待输出数据。
    * 输出端口的数据源可以是 `AL` 或 `AX` 等数据寄存器中的内容。

* **输出端口指令示例**

```asm
MOV DX, 2000H
OUT DX, AL
```

    * `DX` 保存端口地址，`AL` 保存真正输出的数据。
    * `OUT` 属于 I/O 独立寻址的专用指令，不等同于普通存储器写指令。

* **统一编制（Memory-Mapped I/O）**

    * > **定义**：把存储器和 I/O 端口放入同一个地址空间统一编址。
    * 一个地址在同一编址中要么表示存储单元，要么表示 I/O 端口寄存器。
    * I/O 端口可使用存储器读写指令和存储器寻址方式，程序编写方便、寻址灵活。
    * 缺点是 I/O 端口会占用存储器地址，端口越多，可用存储器地址越少。
    * MCS-51 系列采用 I/O 统一编址。

* **独立编制（Isolated I/O）**

    * > **定义**：存储器地址空间与 I/O 地址空间分开，两者互不占用。
    * 8086 采用独立编址，使用 20 位存储器地址和 16 位 I/O 地址。
    * 存储器操作与 I/O 操作使用不同指令。
    * 8086 的 I/O 端口只有直接寻址和 `DX` 寄存器间接寻址两类。
    * 独立编址不占存储器空间，但 I/O 指令和寻址方式需要单独记忆，程序灵活性低于统一编址。
    * 相同数值可以同时出现在两类地址中，由 `M/IO` 区分当前访问空间。

    | 比较项目 | 统一编制 | 独立编制 |
    | :--- | :--- | :--- |
    | 地址空间 | 存储器与 I/O 共用 | 存储器与 I/O 分开 |
    | 一个地址的含义 | 只能是存储单元或 I/O 端口之一 | 由 `M/IO` 决定所属空间 |
    | I/O 指令 | 可使用存储器操作指令 | 使用专门 I/O 指令 |
    | 地址空间代价 | I/O 占用存储器地址 | I/O 不占存储器地址 |
    | 程序特点 | 编写方便、寻址灵活 | 指令与寻址方式需分别掌握 |

* **直接寻址与间接寻址**

    * 直接寻址在指令中直接给出目标单元地址，例如 `MOV [2000H], AL`。
    * 间接寻址先由寄存器保存实际地址，例如 `MOV BX, 2000H` 后执行 `MOV [BX], AL`。
    * 中括号表示存储单元，`[BX]` 的内容从 `BX` 取得。
    * 读写存储器都先根据寻址方式得到有效地址，再执行读或写。
    * 寻址方式越多，程序定位数据越灵活；它与地址线数量决定的地址空间大小是不同概念。
