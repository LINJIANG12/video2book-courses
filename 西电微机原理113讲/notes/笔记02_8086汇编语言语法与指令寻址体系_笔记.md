# 8086汇编语言语法与指令寻址体系

## 指令、语言与汇编链

### 指令与机器语言

* **指令（Instruction）**

    * > **定义**：CPU 能够识别、并能据以完成某种操作的二进制代码。

    * 某一型号 CPU 能够识别的全部指令的集合，称为该型号 CPU 的**指令系统**。

    * 8086、8051、MSP430 等不同型号的 CPU 具有各自的指令系统；即使都由二进制代码组成，也不等于认识同一种代码。

* **机器语言（Machine Language）**

    * > **定义**：直接采用 CPU 指令代码编写程序的语言，也叫指令代码语言；用这种语言写出的程序称为机器语言程序。

    * 机器语言程序送入计算机后可以由 CPU 直接执行，不需要翻译或编译。

    * 程序员必须记住代码及其功能，程序的阅读、扩充和维护都较困难。

    * > **易错点**：机器语言不是“更神秘的语言”，而是直接采用 CPU 指令代码的语言。

### 汇编、汇编程序与反汇编

* **汇编语言（Assembly Language）**

    * > **定义**：用符号和数字表示机器指令的语言。

    * 用户使用汇编语言编写的程序称为汇编语言程序，也称汇编语言源程序。

    * 例如 `MOV AL, 12H` 汇编后得到 `B0H 12H`。

* **汇编（Assemble）**

    * 源程序不能直接交给 8086 执行，必须先翻译成机器语言程序。

    ```text
    汇编语言源程序
          │
          │ 汇编
          ▼
    机器语言程序（目标码）
          │
          │ 装入并执行
          ▼
    CPU
    ```

* **MASM**

    * 常用汇编程序是 MASM；本课建议使用 5.0 以上版本。

    * MASM 传统上常在 DOS 环境下使用，也可以在 Windows 环境下使用；集成汇编环境同样可以使用。

* **反汇编（Disassemble）**

    * 与汇编方向相反，把机器码翻译回便于阅读的指令形式称为反汇编。

    * 汇编是“源程序走向机器码”，反汇编是“机器码重新显示为指令”。

### 源程序、目标文件与链接

* **源程序（.asm）**

    * 汇编源程序由文本形式的语句组成，经过 MASM 汇编后产生目标文件。

* **目标文件（.obj）**

    * `.obj` 中已经含有目标码，但还不是 PC 能直接执行的最终文件。

    * 代码在存储器中的地址尚未在链接阶段最终确定；规模较大的程序还要与其他目标模块、库代码组合，各段地址和布局由链接过程统一安排。

* **链接（LINK）**

    * 链接程序把 `.obj` 文件连接起来，形成 `.exe` 可执行文件；`.com` 也是常见形式。

    * DOS 装入程序把可执行代码放入内存，CPU 才能执行这些代码。

* **完整转换链**

    ```text
    .asm 源程序
         │  MASM 汇编
         ▼
    .obj 目标文件
         │  LINK 链接
         ▼
    .exe 可执行文件（也可采用 .com 形式）
         │  装入内存
         ▼
    内存中的机器码
         │  反汇编
         ▼
    可阅读的指令形式
    ```

* **DEBUG 与反汇编观察**

    * 可执行文件装入内存后呈现为机器码，可在 DEBUG 一类调试环境中反汇编，使内存中的二进制代码重新显示为指令形式。

    * 8086 环境的取指位置与 `CS`、`IP` 共同确定；把某段机器码与其反汇编结果对应起来，才能把源程序中的一行和 CPU 执行到的机器码对上。

### 三类语句

* **指令语句**

    * > **定义**：CPU 能执行，或汇编后能翻译成机器指令代码的语句。

    * `MOV AL, 12H`、`POP AX` 属于指令语句，最终变成 CPU 执行时取到的机器码。

    * 8086 指令长度不固定；不考虑段前缀时，最短为 1 字节，最长可达 5 字节。

    ```asm
    MOV AL, 12H    ; 汇编后为 B0H 12H
    POP AX          ; 汇编后为 58H
    ```

* **伪指令语句**

    * > **定义**：8086 指令系统中没有、CPU 也不能执行，而由汇编程序处理的语句。

    * `DB`、`DW` 等伪指令向汇编程序说明怎样定义数据或分配存储空间，不产生指令代码。

    ```asm
    BETA1 DB 12H
    BETA2 DW ?
    ```

    * `DB` 定义字节型数据，`DW` 定义字型数据；`?` 表示值暂不确定，用于预留稍后写入结果的单元。

    * > **易错点**：`DB`、`DW` 在汇编时完成数据定义或空间分配，不是 CPU 临时执行的指令，目标文件中不会因此凭空多出相应指令代码。

* **宏指令语句**

    * > **定义**：8086 本身没有、由用户定义并交由汇编程序处理的新语句；定义后可在程序中引用。

    * 宏指令类似先定义函数再在其他位置调用，但能用不等于它是 8086 硬件天然认识的指令。

### 语句的组成

* **四项结构**

    * 一条汇编语句最多由名称、助记符、操作数和注释四部分组成，并不要求四项齐全。

    * 名称根据用途可以表现为变量名或标号名。

* **变量名**

    * 变量名给数据存储单元起名，程序访问该单元时不必到处硬写物理地址。

    * `BETA1 DB 12H` 中，`BETA1` 是变量名；`MOV AL, BETA1` 按字节读取，`MOV AX, BETA2` 按字读取。

    * 变量名通常以字母开头；名称应便于记忆，无意义地拖长只会增加阅读负担。

* **标号名**

    * 标号给代码地址起名，程序分支时可以用 `NEXT` 等符号表示目标指令的位置。

    * 标号写在目标指令前并以冒号结尾，例如：

    ```asm
    NEXT:
    ```

    * 分号之后的标点符号不属于跳转目标，结尾冒号是标号写法的一部分。

* **助记符与操作数**

    * 助记符说明语句要完成什么操作，如 `MOV` 表示数据传送、`ADD` 表示相加、`JZ` 表示结果为零时跳转。

    * 操作数说明数据从哪里来、到哪里去，或参与什么运算。

* **注释**

    * 注释从分号 `;` 开始，不属于语句执行内容，可以解释变量、数据或跳转目的。

    ```asm
    BETA1 DB 12H                 ; 定义一个内容为 12H 的字节单元
    ```

## 汇编语句中的常量与表达式

### 数值与字符常数

* **十六进制数**

    * 十六进制数以 `H` 结尾，例如 `B0H`；后缀用于告诉汇编程序数的基数为 16。

* **二进制数**

    * 二进制数用大写 `B` 结尾，例如 `10110001B`；不能把结尾随意写成小写 `b`。

* **十进制数**

    * 十进制数可直接写 `20`，也可用 `D` 后缀明确写成 `20D`。

* **字符常数**

    * 字符常数写在单引号中，如 `'A'`；汇编时转换为对应的 ASCII 码。

    * 不加 `T` 字符时大小写不分；MASM 把单引号内容按大写处理，`'a'` 与 `'A'` 的码值相同。

    * 要指定小写时使用大写 `T` 前缀，例如 `DB 'tA'`。

* **字符串常数**

    * 字符串常数写在双引号中，如 `"ABC"`，用于定义字符串。

    * `DB "AC"` 最多放两个字符；两个字符需要两个字，写成 `DW "AC"`。

    * `DD` 后的双引号串可以长到内存放得下为止，不超过 64K；`DB "string"` 不能汇编通过。

* **问号**

    * `?` 只出现在定义数据、暂不给出确定值的场合，表示未确定或未初始化，而不是 0。

    * 程序运行并把结果写入后，该单元才有实际内容。

### 汇编时求值的表达式

* **算术表达式（Arithmetic Expression）**

    * > **定义**：由加、减、乘、除、`MOD` 等组成、由汇编程序在生成目标码时先求出结果的表达式。

    * `5 + 2 × 3` 按括号优先、乘除优先于加减的通常规则计算，汇编结果为 11 的二进制形式。

    * 算术表达式可以出现在 `DB` 等数据定义语句中，CPU 执行该语句时不会再次计算这个式子。

    * 除法取商，`MOD` 取余：20 除以 3 的商是 6，20 对 3 取模的余数是 2。

    * 汇编器内部最终以二进制形式表示数值，十六进制和十进制只是表示形式。

* **逻辑表达式（Logical Expression）**

    * 8086 汇编语法允许与、或、异或、非等逻辑表达式。

    * 同一 `AND` 文字在指令中可以是 CPU 执行的操作助记符，在操作数中也可以是逻辑表达式运算符。

    ```asm
    AND AL, 21H AND 0FH
    ```

    * 第一个 `AND` 是指令，第二个 `AND` 是由汇编程序先计算的表达式；生成机器码时表达式已经被处理。

* **关系表达式（Relational Expression）**

    * 关系表达式用于比较两个值；成立时结果按全 1 处理，不成立时结果按全 0 处理。

    * `MOV AX, 5 LT 3` 装入 `0000H`；改为 `3 LT 5` 时装入 `FFFFH`。

* **表达式求值时点**

    * 算术、逻辑、关系表达式的共同本质是汇编时求值；不能因为出现操作符就默认由 CPU 运行时计算。

## 标号与变量

### 标号及其属性

* **标号（Label）**

    * > **定义**：加在指令语句左边、以冒号结尾，用来标识该指令语句地址的符号。

    * 标号一经定义，就可以通过属性表达式取得其属性。

    ```asm
    NEXT:   JMP NEXT
    ```

* **标号的地址属性**

    * 标号的第一个属性是指令所在单元的 16 位地址；指令地址为 `1500H` 时，`NEXT` 的值为 `1500H`。

    * `NEXT` 表示指令所在存储单元的地址，不是指令本身，也不是指令中的操作数。

* **标号的偏移属性**

    * `OFFSET` 取得标号对应的 16 位段内偏移地址。

    ```asm
    MOV BX, OFFSET NEXT
    ```

    * `NEXT` 与 `OFFSET NEXT` 有关联但不能混为一谈；8086 逻辑地址的偏移部分为 16 位量。

    * > **易错点**：`MOV BL, OFFSET NEXT` 会发生 16 位偏移地址与 8 位目标操作数不匹配。

* **标号的类型属性**

    * 标号类型由转移指令与目标标号的位置关系决定。

    | 转移情况 | 标号类型 | 8086 类型属性值 |
    | :--- | :--- | ---: |
    | 转移指令与目标标号在同一代码段 | 段内（近）转移 | `-1` |
    | 转移指令与目标标号不在同一代码段 | 段间（远）转移 | `-2` |

    * MASM 源程序通常用 `NEAR`、`FAR` 表达段内或段间属性；实际设计中常用的是 `OFFSET`，专门获取类型属性通常没有实际意义。

### 变量定义伪指令

* **变量（Variable）**

    * > **定义**：给存储器中一组数据单元起的名字；变量名通常以字母开头。

    * 变量与标号都以名称指向存储器，但标号指向指令语句，变量指向数据。

    * 变量所在单元的内容可以在程序运行中反复改变；常量一旦被汇编程序确定，在表达式中的值就是常数，不能改写成寄存器。

* **三种常用定义伪指令**

    | 伪指令 | 定义的数据类型 | 占用长度 |
    | :--- | :--- | :---: |
    | `DB` | 字节型数据 | 1 字节 |
    | `DW` | 字型数据 | 2 字节 |
    | `DD` | 双字型数据 | 4 字节 |

    * 变量通常定义在数据段中。

    ```asm
    DATA SEGMENT
        BETA1  DB  12H
        BETA2  DB  4D12H
        BETA3  DW  1234H
        BETA4  DW  0012H
    DATA ENDS
    ```

* **地址分配顺序**

    * 变量名定义语句的排列顺序就是内存分配的地址顺序；MASM 从数据段偏移 `0000H` 起按定义顺序分配。

    | 变量 | 起始偏移 | 存储内容 | 下一变量偏移 |
    | :--- | ---: | :--- | ---: |
    | `B1` | `0000H` | `12H` | `0001H` |
    | `W1` | `0001H` | `34H 12H` | `0003H` |
    | `D1` | `0003H` | `78H 56H 34H 12H` | `0007H` |
    | `W2` | `0007H` | `12H 00H` | `0009H` |

    * `DB` 使下一个地址加 1，`DW` 加 2，`DD` 加 4。

    * `DW` 和 `DD` 按低字节在低地址、高字节在高地址存放；例如 `W1` 的 `1234H` 在内存中是 `34H 12H`。

### 变量属性

* **变量地址**

    * 变量名可以取得变量所在存储单元的 16 位地址；例如 `BETA1` 从 `1500H` 开始，其地址就是 `1500H`。

* **变量偏移地址**

    * `OFFSET 变量名` 取得变量所在存储单元的 16 位段内偏移地址。

    ```asm
    MOV BX, OFFSET BETA1
    MOV AL, [BX]
    ```

    * `BX` 保存地址，`[BX]` 据此找到单元；`BX` 中的值是地址，`AL` 中的值才是数据。

    * 取变量偏移地址通常用于配合后续间接寻址，因而适合送入 `BX`、`BP`、`SI`、`DI` 等 16 位寄存器。

    * > **易错点**：`MOV AL, OFFSET BETA1` 会产生 16 位偏移地址与 8 位目标操作数不匹配。

* **变量类型属性**

    * 变量类型反映所占字节数：

    | 定义方式 | 数据类型 | 类型属性值 |
    | :--- | :--- | ---: |
    | `DB` | 字节型 | `1` |
    | `DW` | 字型 | `2` |
    | `DD` | 双字型 | `4` |

    * MASM 根据定义伪指令确定类型属性，并把它预先替换为常数。

* **变量长度属性**

    * `LENGTH 变量名` 取得变量对应的元素数；`SIZE 变量名` 取得变量所占的总字节数。

    * 对 `BETA1 DW 1234H`，`LENGTH BETA1` 为 1，表示一个字节型元素；`SIZE BETA1` 为 2，表示总长 2 字节。

    * 变量大小等于单元类型乘以变量长度：

    $$
    \operatorname{size} = \operatorname{unit\ type} \times \operatorname{length}
    $$

    * 例如 `DB 4 DUP 5` 的大小为 4，`DW 3 DUP 0` 的大小为 6。

* **偏移、组距与位移**

    * 偏移地址给出第一个变量单元在内存中的位置；组距是相邻变量单元之间的字节数，等于一个单元的类型大小。

    * 位移是变量单元地址与变量首地址之间的差；第一个单元位移为 0，第二个为一个组距，依次类推。

    * 偏移地址给出起点，组距给出相邻单元的步长，位移给出从变量首地址要移动的距离。

### `DUP` 重复操作符

* **基本形式**

    * `DUP` 的语法是“重复次数 `DUP` 单个数据”，用于定义多个相同数据或预留多个存储单元。

    ```asm
    VAR1    DB  4 DUP 5
    VAR2    DW  3 DUP 0
    ```

    * `VAR1` 用 `DB` 重复 4 次，占 4 字节；`VAR2` 用 `DW` 重复 3 次，占 $3\times2=6$ 字节。

* **重复值与未初始化空间**

    * `DUP` 告诉 MASM 重复多少次；具体数或字符会按该值填满单元。

    * `?` 表示未初始化、值随机；`00H` 表示显式清零。

    * > **易错点**：`?` 不是 0，`00H` 才是 0；“没给值”和“给了零”不能混为一谈。

* **嵌套定义**

    * `DUP` 后可以嵌套，用于重复一整组数据。

    ```asm
    BUFF    DB  8 DUP (5 DUP 05H, 10 DUP 0F0H)
    ```

    * 每个缓冲区有 5 个 `05H` 和 10 个 `0F0H`，共 15 字节；8 个缓冲区共 120 字节。

    * `0F0H` 是十进制 240 的十六进制写法，前面的零不能省略。

    * 嵌套语法虽然允许，实际中大量重复内容通常写成循环更合适。

### `EQU`、`PTR` 与位置计数器

* **常量定义 `EQU`**

    * 常量符号可以用 `EQU` 定义，并能参与数据定义表达式。

    ```asm
    K   EQU 56AH
    B   DB  K+2
    ```

    * 汇编程序先计算 `K+2`，再按 `DB` 定义的字节存放结果；`K` 改值后，表达式会按新值重新计算。

* **`PTR` 属性操作符（Pointer）**

    * `PTR` 是表达式中的属性临时修改操作符，只在当前语句中生效，不改变变量原来的定义。

    * 变量 `B1` 由 `DW` 定义，却要在一条指令中按字节使用时，可以写：

    ```asm
    MOV AL, BYTE PTR B1
    ```

    * `BYTE PTR B1` 让 `B1` 在本条语句中按字节处理，低字节送入 `AL`；离开本语句后 `B1` 仍是字变量。

    * 反向把字节变量按字读取，可写 `MOV AX, WORD PTR B1`。

    * 对 `[010H]` 或 `[SI]` 这类没有变量类型信息的地址表达式，也可用 `PTR` 临时指定类型：

    ```asm
    MOV BYTE PTR [010H], 10H
    ```

    * `PTR` 的作用是给纯表达式或变量指定本次操作所需的类型，不会修改内存数据。

* **位置计数器 `$`**

    * `$` 引用 MASM 位置计数器的当前值；位置计数器是 16 位偏移量，用来跟踪当前待汇编指令或数据项的起始偏移地址。

    * 取变量地址或变量偏移使用变量名或 `OFFSET 变量名`；取当前汇编位置使用 `$`。

    ```asm
    DATA SEGMENT
        B1  DB  12H
    B   DW  B1, $
    DATA ENDS
    ```

    * `B1` 是变量名并取得其对应单元地址；`$` 表示该数据项开始汇编时在当前逻辑段中的位置。

    * > **注意**：不能在缺少伪指令定义依据时把 `$` 等同于“下一个可用地址”；它究竟表示何种起始偏移或相对值，要看所在伪指令的使用方式。

## 8086 指令分类与通用语法

### 指令的十三类功能

* **功能分类**

    | 类别 | 功能 | 代表指令 |
    | :--- | :--- | :--- |
    | 数据传送类 | 在寄存器、存储器等位置之间传送数据 | `MOV`、`LEA` |
    | 算术运算类 | 加、减、乘、除及十进制调整等运算 | `ADD`、`ADC` |
    | 逻辑运算类 | 按位进行逻辑运算 | `AND`、`OR`、`XOR`、`NOT` |
    | 位操作类 | 将操作数左移或右移一位或若干位 | 左移、右移指令 |
    | 标志位操作类 | 直接设置或清除标志位 | `CLC`、`STC`、`CMC`、`CLD`、`STD`、`CLI`、`STI` |
    | 转移类 | 控制程序转移 | `JZ`、`JMP` |
    | 循环控制类 | 控制循环 | `LOOP` |
    | 子程序调用与返回类 | 调用子程序并返回 | `CALL`、`RET` |
    | 中断调用与返回类 | 发出软件中断并返回 | `INT` |
    | 字符串操作类 | 字符串传送、比较等 | `MOVS` |
    | 输入输出类 | 对 I/O 端口读写 | `IN`、`OUT` |
    | 其他指令 | 前面各类不能涵盖的指令 | —— |
    | 宏指令 | 用户用宏定义方法自定义的新指令 | —— |

* **转移类与子程序调用**

    * 条件转移受条件控制，如 `JZ`；无条件转移不受条件控制，如 `JMP`。

    * `CALL` 本质上属于无条件转移，用于进入子程序；`RET` 负责返回。

### 操作数位置与限制

* **立即数（Immediate）**

    * 立即寻址中的操作数在指令中以常数形式立即给出，如：

    ```asm
    MOV AX, 1234H
    ```

    * 立即数可以作为源操作数送给寄存器或存储器，但不能作为目的操作数。

* **寄存器操作数**

    * 寄存器寻址表示操作数在某个寄存器中。

    ```asm
    MOV AX, BX
    MOV AL, CL
    ```

    * 寄存器之间传送数据时，源、目的类型必须一致；16 位 `AX` 不能与 8 位 `CL` 直接配对。

* **目的操作数限制**

    * 目的操作数必须是能够接收和保存结果的寄存器或存储器单元，立即数不能充当目的操作数。

    * 源、目的只要有一方类型明确，双方类型就随之确定；双方都不明确时，汇编无法通过。

* **`CS`、`IP` 限制**

    * `CS`、`IP` 在指令允许的场合可以作为源操作数，但不能作为普通用户指令的目的操作数。

    * 程序装入时由操作系统建立初始 `CS:IP`，执行期间由转移指令改变执行位置。

### 存储器寻址的定义与分类

* **寻址方式（Addressing Mode）**

    * > **定义**：求操作数所在位置或所在存储单元地址的方式。

    * 操作数在存储器中时，需要用寻址方式求其有效地址；立即给出的常数也归入寻址方式。

    * 数据寻址用于求取参与指令操作的数据地址；转移地址寻址用于求取程序转移的目的地址。

    * 段内转移只需得到目的地的 16 位偏移地址并送入 `IP`；段间转移还要得到目的地的 16 位段地址并送入 `CS`。

* **八种数据寻址方式**

    * 8086 指令系统给出八种数据寻址方式；存储器操作数涉及的五类有效地址形式是直接、寄存器间接、寄存器相对、基址变址、基址变址相对寻址。

    * 不能把 `BX` 与 `SI` 相加另造为“寄存器加寄存器”寻址方式；它属于基址变址寻址。

    * 寄存器与立即数相加属于寄存器相对寻址。

* **通用语法检查**

    * 先检查指令共性规则，再检查本类指令的附加限制。

    * 存储器地址表达式合法，不代表整条指令合法；还必须检查源、目的方向、操作数类型和特殊寄存器限制。

* **存储器之间不能直接操作**

    * 存储器操作数可以作为源或目的，但两个存储器单元不能直接传送或运算，数据必须经过通用寄存器中转。

    ```text
    源存储单元 ──读取──> 通用寄存器 ──写入──> 目的存储单元
    ```

    * `PUSH`、`POP` 必须按字操作；串操作中 `DS`、`ES` 的角色由指令规定，源操作数不能写成立即数。

## 存储器数据寻址

### 直接寻址

* **直接寻址（Direct Addressing）**

    * > **定义**：操作数所在单元的有效地址由指令直接给出。

    ```asm
    MOV AL, [2000H]
    ```

    * `[2000H]` 指出存储单元，`AL` 决定按字节操作；没有段超越前缀时默认段为 `DS`。

    * 变量名也可以直接表示其对应存储单元：

    ```asm
    MOV AL, DATA1
    ```

    * 将偏移地址写成 `2000H` 或用变量名 `DATA1` 表达地址，本质上都属于直接寻址；只有把 `BX`、`SI`、`DI` 等地址寄存器放进方括号，才是寄存器间接寻址。

* **类型来自另一端**

    * 地址表达式只说明“到哪里取”，不必然说明“取一个字节还是一个字”；操作数类型由寄存器等另一端或 `PTR` 明确。

* **两存储单元不能直接搬运**

    ```asm
    MOV AL, DATA1
    MOV DATA2, AL
    ```

    * 第一条从 `DATA1` 读取一个字节到 `AL`，第二条把 `AL` 写进 `DATA2`；寄存器是中转站。

    * > **易错点**：方括号里出现两个地址，并不表示 CPU 能在两个存储单元之间直接搭一条传送通道。

### 寄存器间接寻址

* **寄存器间接寻址（Register Indirect Addressing）**

    * > **定义**：先把 16 位有效地址放入地址寄存器，再由该寄存器找到存储器操作数。

    * 能直接提供有效地址的寄存器只有 `BX`、`SI`、`DI`；`BP` 不能用于寄存器间接寻址。

    ```asm
    MOV BX, OFFSET DATA1
    MOV AL, [BX]
    ```

    * `BX` 保存 `DATA1` 的 16 位有效地址，`[BX]` 据此读取一个字节到 `AL`。

    * `SI`、`DI` 也可以提供有效地址：

    ```asm
    MOV AL, [SI]
    MOV AL, [DI]
    ```

    * `BX`、`SI`、`DI` 形成的地址默认按 `DS` 段解释。

* **地址与数据分开**

    * `[BX]`、`[SI]`、`[DI]` 方括号中的寄存器内容是地址；寄存器接收到的内容才可能是数据。

    * `[BX]` 单独只说明地址，不说明操作数宽度；另一端为 `AL` 或 `AX` 时类型由寄存器确定，另一端类型不明确时需要 `PTR`。

* **寄存器间接仍需寄存器中转**

    ```asm
    MOV AL, [SI]
    MOV [BX], AL
    ```

    * `SI` 找到源单元，CPU 读出字节送入 `AL`；`BX` 找到目的单元，再把 `AL` 写入目的单元。

    * 寄存器间接解决“地址由谁提供”，不取消两个存储器操作数之间需要寄存器中转的规则。

### 寄存器相对寻址

* **寄存器相对寻址（Register Relative Addressing）**

    * > **定义**：有效地址由一个基址寄存器内容与相对位移量相加得到。

    $$
    EA = R_{base} + disp
    $$

    * 基址寄存器可以是 `BX`、`BP`、`SI`、`DI`；相对位移量可以是 8 位或 16 位。

    ```asm
    MOV [BP], AL
    MOV AL, [BP - 2]
    MOV [BX+3], AL
    ```

* **默认段**

    * 常量相对位移量时，默认段由基址寄存器决定：`BP` 对应 `SS`，`BX`、`SI`、`DI` 对应 `DS`。

    * 物理地址由段基址和有效地址形成：

    $$
    PA = S \times 16 + EA
    $$

    * `MOV [BP], AL` 中位移量为 0，但由于仍是“基址寄存器 + 位移”结构，属于寄存器相对寻址而非寄存器间接寻址。

    * > **易错点**：方括号中只有 `BP` 不代表寄存器间接寻址；位移量为零时仍属于寄存器相对寻址。

* **相对位移范围**

    * 8 位位移量范围为 $-128\le disp\le127$；16 位位移量范围为 $-32768\le disp\le32767$。

    * 位移量可以为正或为负；负值表示向相反方向移动，不能把相对位移理解为只能向后寻找。

* **位移量来自变量**

    * 变量作为相对量时，使用变量中存放的 16 位内容，而不是变量所在单元的地址：

    $$
    EA = R_{base} + (\text{变量内容})
    $$

    * 变量定义在哪个段，最终取数就要追踪该变量所在段；不能只根据 `BX` 或 `BP` 机械套用默认段。

### 基址变址与复合寻址

* **基址变址寻址（Based Indexed Addressing）**

    * > **定义**：有效地址由基址寄存器内容与变址寄存器内容相加得到。

    ```asm
    MOV AL, [BX+SI]
    MOV AL, [BX+SI+4]
    ```

    * 基本形式为：

    $$
    EA = [BX] + [SI]
    $$

    * `BX` 提供数据块基准，`SI` 提供块内位置；两个寄存器都不变时，适合遍历连续数据。

* **基址变址的默认段**

    * 常量位移量时，基址寄存器决定默认段：`BX` 基址通常用 `DS`，`BP` 基址通常用 `SS`；`SI` 或 `DI` 的出现不改变由基址决定段地址的规则。

    * 例如 `[BX+SI]` 的物理地址为：

    $$
    PA = [DS] \times 16 + [BX] + [SI]
    $$

* **变址相对寻址**

    * 只有 `SI` 或 `DI` 参与，再加位移量时，有效地址为：

    $$
    EA = [SI] + d \quad\text{或}\quad EA = [DI] + d
    $$

    * `SI`、`DI` 对应的段地址为 `DS`；段地址只看变址寄存器，不看后面的位移量。

    * 变量名不能像运行时寄存器那样直接参与指令中的位移量算术；`SI + 1` 可以，`D2 + 1` 不可以。

* **基址变址相对寻址**

    * `BX`、`SI` 再加一个固定位移量时：

    $$
    EA = [BX] + [SI] + d
    $$

    * 三部分分别表示数据块基准、块内相对位置和固定偏移。

* **连续单元遍历**

    ```asm
    XOR AL, AL
    XOR SI, SI
    MOV CX, 10
    NEXT:
        MOV BYTE PTR [BX+SI], AL
        INC SI
        LOOP NEXT
    ```

    * `SI` 依次为 0 到 9，清除从 `BX + 0` 到 `BX + 9` 的 10 个字节；`LOOP` 每执行一次使 `CX` 减 1，减到 0 时结束。

    * 循环结束后 `SI` 已增加 10，实际地址为 `[BX] + 10`，不是永久保存着最后一个单元编号 9。

* **不同寻址形式的等价性**

    * 同一个目标单元可以用寄存器相对、基址变址、变址相对、基址变址相对或基址相对等形式表示；选择最容易保持程序思路的形式即可。

### 隐含寻址

* **隐含寻址（Implied Addressing）**

    * > **定义**：指令中没有显式写出某些操作数，但 CPU 根据指令约定知道其位置。

    * `PUSH AX` 没有写出目的地址，CPU 仍按约定先使 `SP` 减 2，再把 `AX` 写入 `SS` 指向的新栈顶。

    ```text
    执行前：SP ── 指向原栈顶
                 ↓
    第一步：SP ← SP - 2
    第二步：[SS:SP] ← AX
    ```

    * 字符串操作指令的源、目的位置也由指令本身规定。

    * > **易错点**：操作数没有写在指令字符中，不等于 CPU 不知道它，也不等于操作数不存在。

## 段内间接转移

### 段内转移与直接寻址

* **段内转移（Intrasegment Transfer）**

    * 程序不离开当前代码段时称为段内转移；`CS` 不变，只改变 `IP`。

    * 段间转移则同时改变 `CS` 和 `IP`，进入另一个代码段。

* **段内直接寻址**

    ```asm
    JMP L1
    L1:
        ; 转移目的地
    ```

    * 源程序把目的标号 `L1` 直接写在指令中；汇编程序在汇编时找到 `L1` 并计算目标位置。

    * 从 CPU 执行原理看，8086 写进机器指令的是相对于当前 `IP` 的位移量，不是目的地的绝对地址。

* **短转移与近转移**

    * 短转移使用 8 位有符号相对位移量，汇编后由 1 字节操作码和 1 字节位移量组成，总长 2 字节。

    * 短转移以当前 `IP` 为基准，向前不超过 127 字节，向后不超过 128 字节。

    $$
    IP_{目标} = IP_{当前} + sign\_extend(disp8)
    $$

    * 近转移使用 16 位相对位移量，汇编后由 1 字节操作码和 2 字节位移量组成，总长 3 字节。

    $$
    IP_{目标} = IP_{当前} + disp16
    $$

    * 16 位有符号位移范围为 $-32768$ 到 $+32767$。

    * “段内直接”说的是源程序书写形式，“段内相对”说的是 CPU 用当前 `IP` 加位移量计算目标地址的原理。

### 条件转移与范围

* **条件转移（Conditional Transfer）**

    * 8086 条件转移指令只能进行段内转移，采用段内短转移形式。

    * 条件转移以当前 `IP` 为基准，范围为 $-128$ 到 $+127$；汇编后由 1 字节操作码和 1 字节位移量组成。

    ```asm
    JZ L1
    ```

    * 目标在范围内时可以直接使用 `JZ`；超出范围时，汇编程序会报告转移地址超限。

* **远距离搭桥**

    * 条件目标太远时，可先跳到近处的中间标号，再由 `JMP` 完成第二段转移：

    ```asm
    JZ NEAR_LABEL
    JMP FAR_LABEL

    NEAR_LABEL:
        JMP FAR_LABEL
    ```

    * 条件成立时执行两段转移，条件不成立时两次转移都不执行；不能用超范围 `JZ` 直接完成远距离转移。

* **当前 `IP` 的计算**

    * 条件转移要加的是指令结束后的当前 `IP`，不是该转移指令的起始地址。

    * 若 `IP=0100H`，`JZ L1` 的 8 位补码位移量为 `FDH=-3`，且 `JZ` 为双字节指令，则计算基准为 `0102H`：

    $$
    0102H + (-3) = 00FFH
    $$

### 寄存器与存储器中的目标偏移

* **寄存器间接段内转移**

    ```asm
    MOV BX, OFFSET L2
    JMP BX
    ```

    * `JMP BX` 把 `BX` 中的 16 位内容送入 `IP`；`CS` 不变，新的 `CS:IP` 指向目标指令。

    * 寄存器中保存的是目的偏移地址，不再作为普通数据使用。

* **存储器间接段内转移**

    ```asm
    L2 DW ?

    MOV BX, OFFSET L2
    JMP WORD PTR [BX]
    ```

    * `BX` 先找到保存目的偏移地址的内存单元；`JMP WORD PTR [BX]` 从该单元读出 16 位字并送入 `IP`。

    * 这里有两个“间接”层次：`BX` 找到指针单元，内存单元中的字再成为新的 `IP`。

    * 即使保存指针的单元通过直接寻址找到，也不能因此把整条转移称为段内直接转移；判断关键是目标偏移地址是否先从内存取出再送入 `IP`。

* **段内间接寻址的定义与链路**

    * > **定义**：目的地的 `IP` 不直接出现在指令中，而是先通过间接方式取得，再送入 `IP` 的寻址方式。

    * 保存目的偏移地址的单元可以用直接、寄存器间接、寄存器相对、基址变址或基址变址相对等方式定位。

    * 完整链路是：先算指针单元有效地址，再读出一个字，把该字作为新 `IP`。

    * > **易错点**：“如何找到指针单元”和“指针单元里装的是什么”是两个问题；前者由普通寻址方法解决，后者决定指令属于段内间接转移。

### 转移桥与查表

* **等间隔目标计算位移**

    * 目标指令以固定间隔 2 字节排列时，输入值 `AL=1、2、3` 对应的相对位移为：

    | `AL` | 计算 | 相对位移 |
    | :--- | :--- | ---: |
    | 1 | $(1-1)\times2$ | 0 |
    | 2 | $(2-1)\times2$ | 2 |
    | 3 | $(3-1)\times2$ | 4 |

    * 统一计算为：

    $$
    d=(AL-1)\times2
    $$

    * 以第一个目标的偏移地址为基准：

    $$
    BX=\operatorname{OFFSET}(L1)+(AL-1)\times2
    $$

    * 最后用一条公共的内存间接转移到达计算位置：

    ```asm
    JMP WORD PTR [BX]
    ```

    * 多个目标共用一条转移通道，分支越多时不必逐项顺序比较。

* **查表法**

    * 目标地址没有简单规律时，可以把所有目的偏移地址预先放入表中，由输入值决定表项位置，再从表中取出目标地址。

    * 目标等间隔时用输入值直接算位移；目标地址没有简单规律时查表。

## 数据传送类指令

### 数据传送总骨架

* **七种类别**

    | 类别 | 代表指令 | 核心作用 |
    | :--- | :--- | :--- |
    | 传送 | `MOV` | 把源操作数内容送给目的操作数 |
    | 取有效地址 | `LEA` | 把存储器操作数的有效地址送给寄存器 |
    | 取地址指针 | `LES`、`LDS` | 同时取得偏移地址和段地址 |
    | 标志传送 | `LAHF`、`SAHF`、`PUSHF`、`POPF` | 在 `FLAGS`、`AH` 和堆栈之间传送标志 |
    | 数据交换 | `XCHG` | 交换两个操作数内容 |
    | 字节转换 | `XLAT` | 按 `AL` 给出的索引查字节表 |
    | 堆栈操作 | `PUSH`、`POP` | 在寄存器和内存之间进行堆栈传送 |

* **六条通用规则**

    * 源操作数与目的操作数各司其职，不能随意交换角色。

    * 源与目的的类型必须一致，不能一个按字节、另一个按字处理。

    * 操作数的寻址方式和类型必须明确，不能让汇编器猜测。

    * `DS`、`ES`、`SS` 作目的操作数时，源操作数不能是立即数。

    * `CS`、`IP` 不能作为传送的目的操作数。

    * 同一条指令中不能让两个存储器操作数直接参加传送。

* **目的可接收、源可提供、宽度一致**

    * 目的位置必须真的能接收，源位置必须真的能提供，而且两边必须按同一数据宽度解释。

### `MOV` 与 `LEA`

* **`MOV`（Move）**

    * 格式为：

    ```asm
    MOV DST, SRC
    ```

    * `MOV` 把源操作数内容送入目的操作数；源位置的内容传送后仍保留，目的位置得到一份内容。

    * 只要类型一致、寻址方式合法且用途允许，就可以在寄存器、存储器和立即数等位置之间传送内容。

* **`LEA`（Load Effective Address）**

    * 格式为：

    ```asm
    LEA r16, mem
    ```

    * 目的操作数是 16 位寄存器，源操作数采用存储器寻址方式；CPU 按寻址方式算出有效地址，再把地址送入目的寄存器。

    ```asm
    LEA BX, BETA1             ; BX 得到 BETA1 的有效地址
    MOV BX, WORD PTR [BETA1]  ; BX 得到 BETA1 单元中的字
    ```

    * `LEA` 取“门牌号”，`MOV` 取单元中存储的字；地址寄存器不能使用段寄存器或 `IP` 承载。

    * 源程序中需要表达标号对应的地址常量时可用 `OFFSET`；需要 CPU 根据存储器寻址方式计算有效地址时使用 `LEA`。

* **段寄存器初始化**

    * 立即数不能直接作 `DS`、`ES`、`SS` 的目的操作数。

    ```asm
    MOV AX, 1500H
    MOV DS, AX
    ```

    * 给 `DS`、`ES`、`SS` 初始化至少需要先让立即数进入通用寄存器，再由通用寄存器送入段寄存器两条指令。

### `LES`、`LDS` 与完整指针

* **`LES`（Load Extra Segment）**

    * 格式为 `LES r16, mem32`，从 32 位指针单元中取出一个 16 位偏移地址送入指定通用寄存器，把第二个字送入 `ES`。

* **`LDS`（Load Data Segment）**

    * 格式为 `LDS r16, mem32`，从 32 位指针单元中取出一个 16 位偏移地址送入指定通用寄存器，把第二个字送入 `DS`。

* **指针的内存布局**

    ```text
    低地址
      ├── 第一个字：所指向对象的 16 位偏移地址
      └── 第二个字：所指向对象的 16 位段地址
    高地址
    ```

    * `LES`、`LDS` 取回的是对象的完整地址，不是对象本身；偏移地址定位段内位置，段地址选中段，两半共同组成完整指针。

### 标志传送与 `XCHG`

* **`LAHF`、`SAHF`**

    * `LAHF` 把 `FLAGS` 低 8 位送入 `AH`，只改变 `AH`，不改 `FLAGS`。

    * `SAHF` 把 `AH` 的 8 位内容写入 `FLAGS` 低 8 位，会改变低 8 位标志。

* **`PUSHF`、`POPF`**

    * `PUSHF` 把 `FLAGS` 压入堆栈，读取标志而不改 `FLAGS`。

    * `POPF` 从堆栈弹出一个字送入 `FLAGS`，直接改变标志。

    * `SAHF` 只能处理 `FLAGS` 低 8 位，像 `OF` 这样的高 8 位标志不能靠它改变；可借规定会影响 `OF` 的运算指令改变，例如逻辑运算会清 `OF`。

    * > **易错点**：“传送类大多不影响标志”不能推广为“所有标志传送类指令都不影响”；`SAHF`、`POPF` 会写回 `FLAGS`。

* **`XCHG`（Exchange）**

    * 格式为：

    ```asm
    XCHG DST, SRC
    ```

    * 执行后目的和源各自拿到对方原来的内容，不是单向复制。

    * `AX` 参与交换时，汇编器可能采用更紧凑的机器码编码，但功能仍是两个字互换。

    * 两个操作数都不能是立即数，不能让两个存储器操作数直接交换，段寄存器不能参加，操作数类型必须一致。

### `XLAT` 与堆栈操作

* **`XLAT`（Translate Byte）**

    * `XLAT` 也可写 `XLATB`，没有显式操作数，固定以 `AL` 为索引、`BX` 为表基准。

    $$
    AL \leftarrow DS:[BX+AL]
    $$

    * `BX` 指向转换表，源字节在 `AL` 中形成表内偏移，CPU 取出对应字节并写回 `AL`。

    ```asm
    LEA BX, TABLE
    MOV AL, 4
    XLAT
    ```

    * 若表中对应项为 `34H`，执行后 `AL=34H`；`XLAT` 的本质是以 `BX` 为基准、`AL` 为索引的查表转换。

* **`PUSH` 与 `POP`**

    * `PUSH` 把一个 16 位操作数压入堆栈，`POP` 把栈顶 16 位内容弹出并送入目的操作数。

    * 操作数必须是 16 位寄存器或 16 位存储器，不能使用立即数，也不能按字节处理。

    * `1234H` 这样的数值不能直接放入 `PUSH`、`POP` 的操作数位置，因为它没有对应的寄存器或内存位置。

    * 堆栈操作除遵守数据传送类通用规则外，还必须满足按字操作。

## 算术运算与状态标志

### 六个状态标志

* **算术运算的共同规则**

    * 运算指令会把结果信息写入状态标志；结果本身保存在目的操作数中，状态标志供条件转移使用。

    * 段寄存器不能参加算术运算。

* **状态标志含义**

    | 标志 | 含义 |
    | :--- | :--- |
    | `CF` | 无符号运算的进位或借位信息 |
    | `ZF` | 结果为零时为 `1`，非零时为 `0` |
    | `SF` | 结果最高位为 `1` 时为 `1` |
    | `PF` | 结果低八位中 `1` 的个数为偶数时为 `1` |
    | `OF` | 有符号运算发生溢出时为 `1` |
    | `AF` | 半字节进位或借位信息，主要供 BCD 调整使用 |

    * 六个标志会根据本次运算结果更新，但每个标志最终是 0 还是 1 取决于实际结果。

### 加法指令

* **`ADD`（Add）**

    * 双操作数指令：

    $$
    DEST \leftarrow DEST + SRC
    $$

    * 目的内容与源内容相加，结果送回目的原位置；目的不能是立即数。

    * `ADD` 根据结果更新 `CF`、`ZF`、`SF`、`PF`、`OF`、`AF` 六个状态标志。

* **`ADC`（Add with Carry）**

    * 双操作数指令，在普通加法上再加原 `CF`：

    $$
    DEST \leftarrow DEST + SRC + CF
    $$

    * 结果送回目的位置，并按最终结果更新六个状态标志。

    * 多字加法从低位向高位进行时，低位产生的进位由 `ADC` 接到高位运算中。

* **`INC`（Increment）**

    * 单操作数指令 `INC DEST`，把目的内容加一并送回原位置；目的可为寄存器或存储器，不能是立即数。

    * `INC` 更新 `ZF`、`SF`、`PF`、`OF`、`AF`，但 `CF` 保持原值不变。

    * “保持原值”不是清零：执行前 `CF=1`，执行后仍为 1；执行前为 0，执行后仍为 0。

### 双字加法

* **低位字与高位字**

    * 双字变量按低地址放低字、高地址放高字；例如 `VAR_A DD 00127654H` 的低字为 `7654H`，高字为 `0012H`。

    * `VAR_A=00127654H`、`VAR_B=00049821H`、`VAR_C DD ?` 时，先计算低字再计算高字：

    ```asm
        LEA SI, VAR_A
        MOV AX, [SI]
        ADD AX, [SI+4]
        MOV WORD PTR [VAR_C], AX

        MOV AX, [SI+2]
        ADC AX, [SI+6]
        MOV WORD PTR [VAR_C+2], AX
    ```

    * 低字计算为 $7654H+9821H=0E75H$，产生进位 `CF=1`；高字用 `ADC`：

    $$
    0012H+0004H+1=0017H
    $$

    * 最终 `VAR_C=00170E75H`。

    * `VAR_C` 是 `DD` 定义的 4 字节变量，而 `AX` 为 16 位，必须用 `WORD PTR` 明确本次只处理一个字。

    * 这里的代码只是数据定义和运算片段，不是已经包含数据段、代码段和结束过程的完整可执行程序。

### 减法与取负

* **`SUB`（Subtract）**

    * 双操作数指令：

    $$
    DEST \leftarrow DEST - SRC
    $$

    * 目的内容减去源内容，差送回目的原位置，并更新六个状态标志。

* **`SBB`（Subtract with Borrow）**

    * 双操作数指令，在普通减法中再减去原 `CF`：

    $$
    DEST \leftarrow DEST - SRC - CF
    $$

    * 多字减法从低位向高位进行时，低位产生的借位由 `SBB` 接到高位。

* **`DEC`（Decrement）**

    * 单操作数指令 `DEC DEST`，把目的内容减一并送回原位置；目的不能是立即数。

    * `DEC` 更新除 `CF` 以外的 `ZF`、`SF`、`PF`、`OF`、`AF`，`CF` 保持原值。

* **`NEG`（Negate）**

    * 单操作数指令：

    $$
    DEST \leftarrow 0-DEST
    $$

    * 运算结果送回目的位置，并更新六个状态标志；用补码的相反数关系完成取负。

### `CMP` 与比较流程

* **`CMP`（Compare）**

    * > **定义**：功能上进行一次减法，但不把差送回目的操作数；只通过状态标志留下比较结果。

    * 适合比较大小、相等关系和产生条件，同时不破坏参加比较的原始数据。

    ```text
    alpha, beta
         │
         ▼
    CMP or arithmetic
         │
         ▼
    status flags
         │
         ▼
    Jcc condition
       ┌───┴───┐
     true    false
       │       │
      path A path B
    ```

    * `CMP` 不决定跳转路径；条件转移指令负责测试标志并决定走向。

* **单个标志与条件转移**

    | 被测标志 | 条件成立时的含义 | 条件转移指令 |
    | :--- | :--- | :--- |
    | `CF=1` | 有进位或借位 | `JB` / `JC` |
    | `CF=0` | 无进位或借位 | `JAE` / `JNC` |
    | `SF=1` | 结果为负 | `JS` |
    | `SF=0` | 结果不为负 | `JNS` |
    | `ZF=1` | 结果为零 | `JZ` / `JE` |
    | `ZF=0` | 结果不为零 | `JNZ` / `JNE` |
    | `PF=1` | 结果低八位中 `1` 的个数为偶数 | `JPE` |
    | `PF=0` | 结果低八位中 `1` 的个数为奇数 | `JPO` |
    | `OF=1` | 有符号结果发生溢出 | `JO` |
    | `OF=0` | 有符号结果未发生溢出 | `JNO` |

    * 相等关系常用 `E` 助记符表示，`JZ` 也可写 `JE`；不相等常用 `JNZ` 或 `JNE`。

    * 条件转移目标用标号表示，标号放在目标代码处。

### 无符号与有符号比较

* **比较方向**

    * `CMP ALPHA, BETA` 的实际运算是 `ALPHA-BETA`，不是先求绝对值再判断大小。

* **无符号比较**

    | 关系 | 标志条件 | 常用转移指令 |
    | :--- | :--- | :--- |
    | `ALPHA=BETA` | `ZF=1` | `JE` / `JZ` |
    | `ALPHA≠BETA` | `ZF=0` | `JNE` / `JNZ` |
    | `ALPHA<BETA` | `CF=1` | `JB` / `JC` |
    | `ALPHA≥BETA` | `CF=0` | `JAE` / `JNC` |
    | `ALPHA>BETA` | `CF=0` 且 `ZF=0` | `JA` / `JNBE` |
    | `ALPHA≤BETA` | `CF=1` 或 `ZF=1` | `JBE` / `JNA` |

    * `A` 表示高于或不低于，`B` 表示低于，`E` 表示等于，`NE` 表示不等于；`JB` 与 `JAE`、`JBE` 与 `JA` 互为反面。

* **有符号比较**

    | 关系 | 标志条件 | 常用转移指令 |
    | :--- | :--- | :--- |
    | `ALPHA<BETA` | `SF≠OF` | `JL` / `JNGE` |
    | `ALPHA≤BETA` | `ZF=1` 或 `SF≠OF` | `JLE` / `JNG` |
    | `ALPHA>BETA` | `ZF=0` 且 `SF=OF` | `JG` / `JNLE` |
    | `ALPHA≥BETA` | `SF=OF` | `JGE` / `JNL` |

    * 有符号比较的大小关系使用 `G`、`L` 体系；`JL` 的条件是 $SF\oplus OF=1$，不能只看 `CF`。

    * > **易错点**：设计分支时先判断参加比较的数是无符号数还是有符号数，再选择 `A`、`B` 或 `G`、`L` 体系。

## 乘除法与程序设计

### 程序设计三步

* **分析、流程、指令**

    * 程序设计先分析题目并提出解决方法，再把算法写成流程，最后选择相应指令。

    * 标准流程图中开始框和结束框用椭圆，判断框用菱形，运算或数据处理框用矩形；跨区域连接可用相同字母的小圆圈表示同一连接点。

* **16 位带符号数绝对值**

    * 绝对值算法为：

    $$
    |x|=
    \begin{cases}
    x, & x\geq 0\\
    -x, & x<0
    \end{cases}
    $$

    * 数据段中的 16 位带符号数用 `DW` 定义：

    ```asm
    BUFF    DW      ?
    ```

    * 功能代码片段为：

    ```asm
        MOV     AX, BUFF
        CMP     AX, 0
        JNS     DONE
        NEG     AX
        MOV     BUFF, AX
    DONE:
    ```

    * `CMP AX, 0` 只设置比较标志，不保存相减结果；`JNS` 在 `SF=0` 时直接结束，因为非负数的绝对值就是原数。

    * 原数为负时，`NEG AX` 执行 $0-AX$ 得到 $-x$，再写回 `BUFF`。

* **流程图对应关系**

    * 先用 `MOV AX, BUFF` 读取数据，用 `CMP AX, 0` 判断符号，再按条件决定是否执行 `NEG AX` 和 `MOV BUFF, AX`。

    * 这里的片段不是带完整段结构和结束过程的完整程序。

### 无符号乘法

* **`MUL`（Unsigned Multiply）**

    * 显式给出的原操作数是乘数，被乘数隐含在累加器中；原操作数不能使用立即数。

* **8 位无符号乘法**

    * `AL` 中放 8 位被乘数，显式原操作数为 8 位，完整 16 位乘积放在 `AX`，`AH` 为高 8 位、`AL` 为低 8 位。

    ```text
    AL × 8 位原操作数 → AX
                      AH：高 8 位
                      AL：低 8 位
    ```

    * 判断乘积是否超出 8 位范围看 `AH`；`AH=0` 时 `CF=0、OF=0`，否则 `CF=1、OF=1`。

* **16 位无符号乘法**

    * `AX` 中放 16 位被乘数，显式原操作数为 16 位，完整 32 位乘积放在 `DX:AX`，高 16 位在 `DX`，低 16 位在 `AX`。

    ```text
    AX × 16 位原操作数 → DX:AX
                         高 16 位在 DX
                         低 16 位在 AX
    ```

    * 判断完整乘积是否装得下看 `DX`；`DX=0` 时 `CF=0、OF=0`，否则 `CF=1、OF=1`。

### 有符号乘法

* **`IMUL`（Signed Multiply）**

    * 被乘数与乘数都按带符号数解释，存放位置和乘积宽度由操作数类型决定。

* **8 位有符号乘法**

    * `AL` 中放隐含的 8 位被乘数，完整 16 位结果放在 `AX`。

    * 判断高位是否只是符号扩展时看 `AH` 是否等于 `AL` 的符号扩展：正数时 `AH` 全 0，负数时 `AH` 全 1。

* **16 位有符号乘法**

    * `AX` 中放隐含的 16 位被乘数，完整结果放在 `DX:AX`。

    * 判断 `DX` 是否为 `AX` 的符号扩展：结果为正时 `DX` 可全 0，结果为负时 `DX` 可全 1。

* **乘法标志与类型对照**

    | 类别 | 被乘数及位置 | 显式乘数 | 完整乘积 | `CF=0` 且 `OF=0` 的条件 |
    | :--- | :--- | :--- | :--- | :--- |
    | 8 位无符号乘法 | `AL` | 8 位原操作数 | `AX` | `AH=0` |
    | 16 位无符号乘法 | `AX` | 16 位原操作数 | `DX:AX` | `DX=0` |
    | 8 位有符号乘法 | `AL` | 8 位原操作数 | `AX` | `AH` 是 `AL` 的符号扩展 |
    | 16 位有符号乘法 | `AX` | 16 位原操作数 | `DX:AX` | `DX` 是 `AX` 的符号扩展 |

    * `MUL`、`IMUL` 执行后能够确定的是 `CF`、`OF`，其余状态标志没有定义。

    * “没有影响”表示标志保持原值，“没有定义”表示执行后状态不确定；两者不能互换。

    * > **易错点**：无符号乘法看高半部分是否为 0，有符号乘法看高半部分是否为低半部分的符号扩展。

### 无符号除法

* **`DIV`（Unsigned Divide）**

    * 被除数隐含，除数由原操作数给出；除数不能为 0。

* **8 位无符号除法**

    * 16 位被除数放在 `AX`，8 位原操作数是除数；商放入 `AL`，余数放入 `AH`。

    ```text
    AX：16 位被除数
             │
             ▼
        除以 8 位原操作数
           ┌────┴────┐
           ▼         ▼
        AL：商      AH：余数
    ```

* **16 位无符号除法**

    * 32 位被除数放在 `DX:AX`，高 16 位在 `DX`、低 16 位在 `AX`；16 位原操作数是除数。

    * 相除后，16 位商放入 `AX`，16 位余数放入 `DX`。

    ```text
    DX:AX：32 位被除数
              │
              ▼
         除以 16 位原操作数
            ┌────┴────┐
            ▼         ▼
         AX：商      DX：余数
    ```

* **除法前后位置变化**

    * 8 位除法前从 `AX` 读取 16 位被除数；执行后商回到 `AL`，余数进入 `AH`，不能混用执行前后的寄存器内容。

### 有符号除法与余数符号

* **`IDIV`（Signed Divide）**

    * 有符号除法的被除数、商、余数寄存器位置与 `DIV` 相同，但所有数按带符号数解释。

    * 商的符号由被除数与除数共同决定；余数非零时，符号与被除数一致。

    | 被除数 | 除数 | 商 | 余数 |
    | :--- | :--- | :--- | :--- |
    | 正 | 正 | 正 | 正 |
    | 正 | 负 | 负 | 正 |
    | 负 | 正 | 负 | 负 |
    | 负 | 负 | 正 | 负 |

    * 实际余数为 0 时，余数直接记为 0。

    * `DIV`、`IDIV` 执行后六个状态标志都没有定义，执行后不能依靠状态标志判断除法结果。

* **除数与状态标志**

    * 除数不能为 0；例如保存 10 到 `CL` 后执行 `DIV CL`，`CL` 才是合法的 8 位原操作数。

    * > **易错点**：`CMP` 设置的条件标志可以供判断使用，但 `DIV` 或 `IDIV` 执行后不能把运算结果和状态标志混在一起讨论。

### 二进制数转换为 BCD

* **输入、输出与空间**

    * 题目要求把 `BUFF1` 中的 8 位无符号二进制数转换为十进制 BCD，并从 `BUFF2` 开始按 3 个字节存放。

    * 8 位无符号数范围是 $0\sim255$，十进制结果最多 3 位，因此需要 3 个输出单元。

    ```asm
    BUFF1   DB      ?
    BUFF2   DB      3 DUP (?)
    ```

* **厨师取余法**

    * 反复除以 10、逐次取余：第一次余数是个位，第二次余数是十位，第三次商是百位。

    ```text
    第一次：N  ÷ 10  →  商 Q1，余数 个位
    第二次：Q1 ÷ 10  →  商 Q2，余数 十位
    第三次：Q2 ÷ 10  →  商 百位，余数 0
    ```

    * 余数最先得到，因此个位存最低地址，十位存中间地址，百位存最高地址：

    ```text
    低地址                                      高地址
      │                                          │
      ▼                                          ▼
    BUFF2       BUFF2+1        BUFF2+2
     个位数        十位数          百位数
    ```

* **连续 8 位除法**

    * `DIV CL` 以整个 `AX` 作为 16 位被除数；输入进入 `AL` 后必须先清零 `AH`。

    ```asm
        MOV     AL, BUFF1
        MOV     AH, 0
        MOV     CL, 10

        DIV     CL
        MOV     BUFF2, AH

        MOV     AH, 0
        DIV     CL
        MOV     BUFF2+1, AH

        MOV     AH, 0
        DIV     CL
        MOV     BUFF2+2, AL
    ```

    * 第一次 `DIV CL` 后，`AL` 是中间商、`AH` 是个位数；下一轮必须先清零 `AH`，只保留 `AL` 中的商再除以 10。

    * 第三次除法后，商就是百位，因此把 `AL` 写入 `BUFF2+2`，不再取 `AH` 中的余数。

    * 每轮都是 8 位除以 8 位，必须检查被除数高 8 位；`CL` 中的除数 10 保持不变。

    * 得到的寄存器数字仍是二进制数，存入结果区后才是题目要求的 BCD 表示。

    * 如果要送到显示器，还需先把 BCD 数字转换为对应 ASCII 字符，再通过操作系统提供的功能输出；键盘输入也可由操作系统功能取得。

## 符号扩展与 BCD 调整

### 符号扩展

* **符号扩展（Sign Extension）**

    * 符号扩展用于把较窄的带符号数扩展到更宽的表示，方法是低位保留原数据、高位复制符号位。

    * 符号扩展把位数对上；BCD 调整则把 CPU 得到的二进制结果调整为十进制 BCD 表示，两者处理对象不同。

* **`CBW`（Convert Byte to Word）**

    * > **定义**：把 `AL` 中的 8 位带符号数扩展为 `AX` 中的 16 位带符号数。

    * `AX` 低 8 位保留原 `AL`，`AH` 全部复制 `AL` 的符号位。

    ```text
    AL :  [ s | d6 d5 d4 d3 d2 d1 d0 ]
    AX :  [ s | s  | d6 d5 d4 d3 d2 d1 d0 ]
    ```

* **`CWD`（Convert Word to Doubleword）**

    * > **定义**：把 `AX` 中的 16 位带符号数扩展为 `DX:AX` 中的 32 位带符号数。

    * `AX` 保留原值，`DX` 复制 `AX` 的符号位。

    ```text
    AX    :  [ s | d14 d13 ... d1 d0 ]
    DX:AX :  [ s | s  | d14 d13 ... d1 d0 ]
    ```

* **符号扩展的标志影响**

    * `CBW`、`CWD` 都不影响状态标志。

    * `CBW` 只能处理 `AL`，不能凭空从内存扩展 `C`；必须先 `MOV AL, C`，再执行 `CBW`。

* **混合位宽算式**

    * 对 $y=a\times b+c-18$，其中 `a、b、c` 为 8 位带符号数，`y` 为 16 位字型结果：

    ```asm
    DATA SEGMENT
        A DB ?
        B DB ?
        C DB ?
        Y DW ?
    DATA ENDS

    CODE SEGMENT
        ASSUME CS:CODE, DS:DATA

        MOV AL, A
        IMUL B
        MOV BX, AX

        MOV AL, C
        CBW
        ADD AX, BX
        SUB AX, 18
        MOV Y, AX
    CODE ENDS
    ```

    * `a×b` 产生 16 位乘积并保存在 `AX`；`c` 只有 8 位，先送入 `AL` 并用 `CBW` 扩展到 `AX`，再与保存于 `BX` 的乘积相加。

    * 反复出现的常数或表达式可用 `EQU` 定义，例如 `CONST EQU 18`，之后写 `SUB AX, CONST`。

### BCD 表示与调整对应

* **组合 BCD 与分离 BCD**

    * 组合 BCD 把十进制位紧凑放在一个字节的高、低四位中；分离 BCD 把每个十进制位单独放在一个字节的低四位中。

    * CPU 执行加、减、乘、除时只把操作数当作二进制数，不会自动理解 BCD 的十进制定位规则，因此运算后需要 BCD 调整指令。

* **调整指令对应关系**

    | 运算 | 组合 BCD | 分离 BCD |
    | :--- | :--- | :--- |
    | 加法 | `DAA` | `AAA` |
    | 减法 | `DAS` | `AAS` |
    | 乘法 | 不采用 | `AAM` |
    | 除法 | 不采用 | `AAD` |

    * 加法、减法和乘法都是先进行普通运算，再对结果进行调整；除法必须先调整被除数，再进行除法。

    * 调整指令的对象和顺序不能混用；乘法和除法调整只采用分离 BCD。

### 加法与减法调整

* **组合 BCD 加法 `DAA`**

    ```asm
    MOV AL, 56H
    ADD AL, 73H
    DAA
    ```

    * `ADD` 得到 `C9H`；`DAA` 检查高低四位是否合法，低位 9 不需加 6，高位 `C` 超过 9，需要加 `60H`：

    $$
    C9H+60H=0129H
    $$

    * 低 8 位留下 `AL=29H`，进位进入 `CF=1`；正确的十进制 129 需要结合 `CF` 读取。

* **分离 BCD 加法 `AAA`**

    ```asm
    MOV AL, 04H
    ADD AL, 08H
    AAA
    ```

    * `ADD` 得到 `0CH`；`AAA` 检查低四位 `C` 超过 9，先加 6 得到 `12H` 并置 `AF=1`，再把高四位清零、保留低四位 2，最后把 `AF` 传送到 `AH`，得到 `AX=0102H`，表示十进制 12。

    * 普通十进制加法通常优先采用较简单的组合 BCD `DAA`。

* **组合 BCD 减法 `DAS`**

    ```asm
    MOV AL, 31H
    SUB AL, 87H
    DAS
    ```

    * `SUB` 得到 `AAH` 并产生借位 `CF=1`；`DAS` 对低四位和高四位各减去 6 调整，调整后 `AL=44H`、`CF=1`。

    * $31-87=-56$，`44H` 必须结合借位标志解释，不能把 `44H` 单独当作正的 44。

    * > **易错点**：组合 BCD 减法读取结果时不能只看 `AL`，必须把 `CF` 表示的借位考虑进去。

* **分离 BCD 减法 `AAS`**

    * `AAS` 用于分离 BCD 减法结果调整，针对 `AL` 中的分离 BCD 结果，并按十位、个位和借位关系处理。

    * `DAS` 对应组合 BCD 减法，`AAS` 对应分离 BCD 减法，二者不能混用。

### 乘法与除法调整

* **乘法先乘后调 `AAM`**

    ```asm
    MOV AL, 07H
    MOV BL, 08H
    MUL BL
    AAM
    ```

    * `MUL BL` 先做二进制乘法，得到 `AX=0038H`；`AAM` 再把乘积按十进制调整，商放入 `AH`、余数放入 `AL`。

    * 十进制 56 的商为 5、余数为 6，因此：

    ```text
    AX = 0506H
    AH = 05H（十位）
    AL = 06H（个位）
    ```

    * 乘法 BCD 顺序是先 `MUL` 后 `AAM`；`AAM` 会影响相应状态标志，但首先应掌握运算顺序和结果位置。

* **除法先调后算 `AAD`**

    ```asm
    MOV AX, 0207H
    MOV BL, 04H
    AAD
    DIV BL
    ```

    * 分离 BCD 的十进制 27 用 `0207H` 表示；`AAD` 在除法前按：

    $$
    AX=AH\times10+AL
    $$

    * `0207H → 2×10+7=27 → 001BH`，然后才能执行 `DIV BL`。

    * 商放在 `AL`，余数放在 `AH`；27 除以 4 的结果为 `AL=06H`、`AH=03H`，即 `AX=0306H`。

    * > **易错点**：除法 BCD 运算必须先 `AAD` 再 `DIV`；加法、减法和乘法都是先运算后调整。

## 逻辑运算指令

### `AND`、`OR`、`XOR`

* **按位逻辑运算**

    * `AND`、`OR`、`XOR` 都是双操作数指令：

    ```asm
    AND DST, SRC
    OR  DST, SRC
    XOR DST, SRC
    ```

    * CPU 对两个操作数逐位进行逻辑运算，结果写回目的操作数；目的操作数原内容被结果替换。

    * `OR` 和 `XOR` 与 `AND` 一样可以按字节或字处理。

* **标志处理**

    * `AND`、`OR`、`XOR` 执行后：`CF` 自动清零，`OF` 自动清零，`AF` 没有定义，`SF`、`ZF`、`PF` 根据逻辑结果正常设置。

    * > **易错点**：`AF` 在这些指令后是“没有定义”，不是“保持原值”；`CF`、`OF` 则确实被清零。

### `TEST` 与 `NOT`

* **`TEST`（Test）**

    * 双操作数指令，内部按位与的效果类似 `AND`，根据结果设置标志，但不把结果写回目的操作数。

    * `TEST` 适合测试某些位而不破坏原数据；执行后 `CF`、`OF` 自动清零，`AF` 没有定义，`SF`、`ZF`、`PF` 正常设置。

    | 指令 | 是否写回结果 | 目的操作数是否保留 | 主要用途 |
    | :--- | :--- | :--- | :--- |
    | `AND` | 是 | 否，被结果替换 | 按位与并保存结果 |
    | `TEST` | 否 | 是 | 只测试条件，不破坏数据 |

* **`NOT`（Bitwise Complement）**

    * 单操作数指令：

    ```asm
    NOT DEST
    ```

    * CPU 对目的操作数按位取反，结果写回目的操作数；`NOT` 不影响状态标志。

* **逻辑指令的核心区分**

    * `AND`、`OR`、`XOR` 保存运算结果；`TEST` 只测试并设置标志；`NOT` 按位取反且不改变状态标志。

## 综合规则速查

### 数据位置与指令语法

* **先定位再检查**

    * 先看操作数是否在存储器中，再看有效地址由指令直接给出、由地址寄存器单独给出，还是由基址与位移等成分相加得到；最后检查类型、方向和特殊寄存器限制。

* **地址与类型分离**

    * 有效地址表达式合法，只完成了地址计算；操作数类型不明确或源、目的类型不一致，指令仍然不合法。

    * 立即数只能做源操作数；`CS`、`IP` 不能作普通目的操作数；两个存储器单元不能直接传送或运算。

* **类型明确**

    * 寄存器如 `AL`、`AX` 自带类型；`[BX]`、`[SI]` 只提供地址信息，不自动说明操作数宽度。

    * 类型不明确或类型冲突时，使用 `PTR` 临时指定当前语句中的类型。

### 地址计算的判断顺序

* **存储器寻址骨架**

    | 形式 | 有效地址 |
    | :--- | :--- |
    | 直接寻址 | 指令直接给出的地址 |
    | 寄存器间接寻址 | `BX`、`SI` 或 `DI` 单独提供的地址 |
    | 寄存器相对寻址 | `BX`、`BP`、`SI` 或 `DI` + 位移量 |
    | 基址变址寻址 | 基址寄存器 + 变址寄存器 |
    | 基址变址相对寻址 | 基址寄存器 + 变址寄存器 + 位移量 |

* **默认段与物理地址**

    * 常量位移量时，`BP` 基址默认对应 `SS`，`BX`、`SI`、`DI` 相关形式默认对应 `DS`。

    * 变量作为位移量时，还要追踪变量定义所在段，不能只看地址寄存器名称。

    * 物理地址的基本形成式为：

    $$
    PA=S\times16+EA
    $$

### 算术、符号扩展与 BCD

* **算术结果与条件**

    * 算术指令把结果写回目的操作数，同时更新相应状态标志；`CMP` 只设置比较标志，不写回差。

    * `INC`、`DEC` 保持 `CF` 原值；`AND`、`OR`、`XOR`、`TEST` 清零 `CF` 和 `OF`，而 `NOT` 不影响状态标志。

* **宽度转换**

    * 混合 8 位和 16 位带符号运算时，先把窄操作数送入相应隐含寄存器，再用 `CBW` 或 `CWD` 扩展。

* **BCD 调整顺序**

    * 组合 BCD 加、减用 `DAA`、`DAS`；分离 BCD 加、减用 `AAA`、`AAS`；分离 BCD 乘、除用 `AAM`、`AAD`。

    * 加、减、乘先运算后调整；除法先 `AAD` 后 `DIV`。

    * 组合 BCD 减法结果必须结合 `CF` 解释，分离 BCD 调整还要关注十位、个位和借位的存放关系。
