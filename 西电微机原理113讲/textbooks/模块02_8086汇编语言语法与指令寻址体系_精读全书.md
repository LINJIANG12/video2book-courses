## 从机器指令到汇编语句：读懂 8086 指令系统的入口
> 对应块：BLK12 | 覆盖分集：P24-P25 | 块标题（分集名）：《24》

一条 `MOV AL, 12H` 写出来像一句简短的话，汇编以后却变成了 `B0H 12H` 这样的机器码。CPU 到底认前者还是后者？8086 的指令系统又是怎样把源程序变成 CPU 能执行的东西？学习具体指令之前，我们先把这条转换链上的概念、工具和语句规则全部对齐。

### 先把指令、语言和工具分清

#### 指令、指令系统与机器语言

> **定义**：指令是 CPU 能够识别、并能据以完成某种操作的二进制代码；某一型号 CPU 能够识别的全部指令的集合，称为该型号 CPU 的指令系统。

不同型号的 CPU，指令系统不同。8086 有 8086 的指令系统，8051 单片机有 8051 的指令系统，MSP430 也有自己的指令系统。型号变了，CPU 能直接认识的指令就可能随之改变。当然，它们最终都由二进制代码组成，但“都由二进制组成”不等于“认识同一种二进制代码”。

如果直接用 CPU 能认识的指令代码编写程序，这种语言就是**机器语言**，它也叫**指令代码语言**；写出来的程序则叫机器语言程序。

机器语言最直接的好处只有一个：程序送入计算机后，CPU 可以直接执行，不需要翻译，也不需要编译。因为它从一开始就是 CPU 认识的代码。

> **易错点**：机器语言并不是“更神秘的语言”，而是直接采用 CPU 指令代码的语言。

它的缺点也同样明显。程序员必须记住 CPU 认识哪些代码、每串代码又代表什么功能。即使费了很大力气把程序编出来、调试好，过一段时间再读，连作者自己都可能不理解；等程序要扩充功能或维护时，复杂程度只会继续增加。机器语言难以驾驭，正是汇编语言出现的原因。

#### 汇编、汇编程序与反汇编

汇编语言不再要求程序员直接面对一串抽象的机器码，而是给指令换上容易记忆的符号和数字。例如，`MOV AL, 12H` 表达了“把数值送入 AL”的意思，8086 汇编后却得到 `B0H 12H`。这种用符号表示机器指令的语言，就是汇编语言。

> **定义**：用户使用汇编语言编写的程序，称为汇编语言程序，也称汇编语言源程序。

源程序不能直接交给 8086 执行。CPU 执行前，必须先把它翻译成机器语言程序。这个翻译过程叫**汇编**。

```text
汇编语言源程序
      │
      │ 汇编
      ▼
机器语言程序（目标码）
      │
      │ 装入并执行
      ▼
      CPU
```

常用汇编程序是 **MASM**。它可以从网上或其他软件来源获得，安装也不像许多工具那样复杂，通常直接放置即可使用。本课建议使用 5.0 以上版本；集成汇编环境当然也能使用。MASM 传统上常在 DOS 环境下使用，在 Windows 环境下同样可以使用。

与汇编方向相反，把机器码翻译回便于阅读的指令形式，称为**反汇编**。汇编是“源程序走向机器码”，反汇编则是“机器码重新显示为指令”，一定要把方向记反。

### 一段程序怎样走到 CPU 面前

#### 源程序、目标文件与链接

单看一条指令，汇编关系很清楚；放到完整程序里，中间还会多出一个目标文件，也多出一次链接。完整路径可以画成：

```text
.asm 源程序
     │  MASM 汇编
     ▼
.obj 目标文件
     │  LINK 链接
     ▼
.exe 可执行文件（也可采用 .com 形式）
     │  装入内存
     ▼
内存中的机器码
     │  反汇编
     ▼
可阅读的指令形式
```

读图时要抓住三件事：MASM 把汇编源程序翻译成目标码；链接程序把目标文件组织成最终可执行文件；装入内存后，还可以用反汇编观察机器码对应的指令。

汇编生成的 `.obj` 文件中虽然已经含有目标码，但它还不是 PC 能直接执行的最终文件。代码在存储器中的地址还没有在链接阶段最终确定；如果程序规模较大，还要与其他目标模块、库代码组合，各段地址和布局必须由链接过程统一安排，所以目标文件不能直接交给 CPU 执行。

链接程序把 `.obj` 文件连接起来，形成 `.exe` 这样的可执行文件，`.com` 也是常见形式。DOS 装入程序最终把可执行代码放入内存，CPU 才有机会执行这些代码。

#### Debug 与反汇编

可执行文件装入内存后，呈现出来的是机器码。为了看清其中某一段究竟对应什么指令，可以在 DEBUG 一类调试环境中进行反汇编，让内存里的二进制代码重新以指令形式显示出来。这既能帮助定位程序中的指令，也为理解汇编过程提供了最直接的观察窗口。

调试界面中的地址也不能孤零零地看。在 8086 环境下，CPU 取指与 `CS`、`IP` 共同确定的代码位置有关。我们看到某段机器码被装入内存，又看到它被反汇编成指令，才能把“源程序里写的一行”和“CPU 最终执行到的机器码”真正对上。

### 汇编源程序中有三类语句

8086 汇编语言程序里的语句可以分成三类。最容易混淆的，是“CPU 能不能执行”和“汇编程序要不要处理”并不是同一个判断标准。

| 语句种类 | 由谁处理 | 作用 |
| --- | --- | --- |
| 指令语句 | CPU 执行 | 汇编后产生机器指令代码 |
| 伪指令语句 | 汇编程序处理 | 告诉汇编程序怎样定义、分配或组织数据，不产生指令代码 |
| 宏指令语句 | 用户定义、汇编程序处理 | 8086 本身没有这条语句，定义后可在程序中引用 |

#### 指令语句

凡是 CPU 能执行、或者汇编后能翻译成机器指令代码的语句，都称为**指令语句**。`MOV AL, 12H`、`POP AX` 都属于这一类。它们最终会变成 CPU 执行时真正取到的机器码。

8086 的指令并不是固定长度：最短可以只有一个字节；若不考虑段前缀，最长可以达到 5 个字节。

```asm
MOV AL, 12H    ; 汇编后为 B0H 12H
POP AX          ; 汇编后为 58H
```

左边是符号化、便于阅读的汇编指令，右边才是 CPU 认识的目标码。调试时看到的十六进制内容，应当能够与源程序中的指令对应起来。

#### 伪指令语句

`DB`、`DW` 这样的语句，8086 的指令系统中并没有，CPU 也不能执行。它们属于伪指令，只向汇编程序说明“现在应当怎样定义数据或分配存储空间”。

例如：

```asm
BETA1 DB 12H
BETA2 DW ?
```

`DB` 表示在相应位置定义字节型数据，`BETA1` 可以放一个字节；`DW` 表示定义字型数据，所以给 `BETA2` 分配一个字的空间。问号表示这个单元的值暂不确定，常用于预留一个稍后写入结果的存储位置。

> **易错点**：`DB`、`DW` 是在汇编时完成数据定义或空间分配，不是让 CPU 临时执行的一条指令。汇编后的目标文件中不会因此凭空多出相应的指令代码。

#### 宏指令语句

宏指令语句同样不是 8086 原生具备的指令，而是用户自己开发、定义的一条新语句。定义之后，就可以在后面的程序设计中引用它。

它很像 C 语言中的函数：先定义一个函数，再在其他位置调用它。宏指令具体怎样定义，留到指令系统后半部分再讲；这里先把概念摆正——它能用，不等于它是 8086 硬件天然认识的指令。

### 一条语句最多由四部分组成

一条汇编语句不一定四项齐全，但最多可以由四部分组成：**名称、助记符、操作数和注释**。名称还可以根据用途表现为变量名或标号名。

#### 给数据单元起名字

如果程序直接使用某个存储单元的地址，设计和阅读都会很麻烦。老师用同学“学号”和“姓名”的关系作比喻：每个人的学号确实像一个地址，但日常联系时，大家更愿意按姓名来称呼。把地址符号化，就是给存储单元也起一个容易记的名字。

例如 `BETA1 DB 12H` 中，左边的 `BETA1` 就是一个变量名，它使程序不必到处硬写该单元的地址。需要读取这个字节时，可以写 `MOV AL, BETA1`；需要按字读取 `BETA2` 中的内容时，可以写 `MOV AX, BETA2`。

这里要分清两件事：左边的符号表示**存储单元**，指令执行时读入或写出的则是该单元中的**数据**。符号化并没有把数据值本身抹掉，只是让程序员不必总盯着物理地址。

变量名属于汇编语言中的名称，通常要以字母开头。名字虽然可以有一定长度，但无意义地拖长只会增加阅读负担。我们没有理由为了显示程序“写得很长”，给自己制造维护麻烦。

#### 给代码地址也起名字

程序分支时，跳转目标是一条指令的地址。这个地址在编写程序时未必能立刻算出来，也不该让程序员反复手工计算，所以同样可以符号化。

例如，在执行加法后根据结果是否为零决定是否跳转时，可以把目标写成 `NEXT`，到目标指令处再写 `NEXT:`。分号之外的标点符号不属于跳转目标本身，结尾的冒号是标号写法的一部分。`NEXT` 表示目标指令在存储器中的位置；执行到这里后，程序也可以顺着标号继续向后执行。

变量名与标号名看起来都是名称，作用却不相同：变量名帮助我们访问数据单元，标号名帮助我们表示代码地址。两者共同体现的都是一件事——**把难以直接操作的地址或单元变成可记忆、可引用的符号**。

#### 助记符、操作数与注释

助记符说明这条语句要做什么，例如 `MOV` 表示数据传送，`ADD` 表示相加，`JZ` 表示结果为零时跳转。操作数说明数据从哪里来、到哪里去，或者参与什么运算。

注释从分号 `;` 开始。注释不属于语句的执行内容，却能解释变量、数据或跳转的目的。像下面这样一句，就可以同时看出助记符、操作数和注释：

`BETA1 DB 12H                 ; 定义一个内容为 12H 的字节单元`

一句普通数据定义语句中，左侧的 `BETA1` 是名称，`DB` 是助记符，`12H` 是操作数，分号后是注释。并不是每条语句都需要四项，但排查语句结构时，就按这四个位置逐一核对。

### 常数有哪些写法

汇编程序中的数值必须带上足够的标记，不能只靠“看起来像什么”来猜。常用写法如下：

| 形式 | 示例 | 说明 |
| --- | --- | --- |
| 十六进制数 | `B0H` | 以 `H` 结尾 |
| 二进制数 | `10110001B` | 以大写 `B` 结尾，不能把结尾随意写成小写 `b` |
| 十进制数 | `20` 或 `20D` | `D` 后缀可以明确标出十进制 |
| 字符常数 | `'A'` | 汇编时转换为对应的 ASCII 码 |
| 字符串常数 | `"ABC"` | 写在双引号中，用于定义字符串 |

十六进制后缀 `H` 很重要：它告诉汇编程序，这个数的基数是 16。二进制数后面的 `B` 用来表示二进制，十进制的 `D` 则用来排除其他进制的可能。

单引号中的 `'A'` 是一个字符，汇编程序在处理这条语句时把它换成相应字符代码，所以它在数据定义中仍然可以表示一个数值。问号则只出现在“定义数据、暂不给出确定值”的场合。它表达的是未确定或未初始化，而不是 0；等程序运行并把结果写进去以后，这个单元才有实际内容。

### 表达式由谁计算

表达式看起来像数学算式，但必须先问一句：**谁来计算？** 在汇编语言中，有的表达式由汇编程序在生成目标码时计算，有的表达式则由 CPU 执行指令时计算。把这两种情况混在一起，最容易把“编译期求值”和“运行期执行”弄反。

#### 算术表达式在汇编时求值

以 `5 + 2 × 3` 为例，汇编程序在汇编这条语句时就会先计算它的值，CPU 执行该语句时不会再次替我们计算这个式子。括号优先、乘除优先于加减，计算规律与通常的算术规则一致。

因此，算术表达式可以出现在数据定义语句中。假如把 `5 + 2 × 3` 作为 `DB` 的操作数，汇编程序会先算得十进制 11，再以二进制形式放入目标码。写源程序时看到的是算式，最终进入文件或内存的却是计算结果。

常用算术操作包括加、减、乘、除和 `MOD`。除法取商，`MOD` 取余。例如，20 除以 3，商是 6；而 20 对 3 取模，结果就是余数 2。计算器中的数最终都以二进制形式表示，十六进制、十进制只是人习惯采用的表示形式。

> **结论**：算术表达式的值是汇编数据，由汇编程序在汇编过程中计算，不是 CPU 执行该语句时再计算。

#### 逻辑表达式有“指令”和“运算符”两重身份

8086 汇编语法还允许与、或、异或、非等逻辑表达式。真正容易搞错的地方，是同一种 `AND` 文字，在一个位置表示指令助记符，在另一个位置表示表达式运算符。

例如在 `AND AL, 21H AND 0FH` 中，第一个 `AND` 是 CPU 将来执行的指令；操作数里的第二个 `AND` 属于逻辑表达式，要先由汇编程序计算。生成机器码时，汇编程序已经把这个表达式处理完毕，CPU 收到的是操作数计算后的结果。

这种写法在语法上允许，但实际程序设计中使用得不多。我们不能因为不常用就不认识，更不能看到 `AND` 就不判断它到底是在让 CPU 做按位与，还是让汇编程序计算一个表达式。

#### 关系表达式用全零和全一表示真假

关系表达式用来比较两个值。关系成立时，表达式结果按全 1 处理；关系不成立时，结果按全 0 处理。

例如，在 `MOV AX, 5 LT 3` 中，汇编程序判断 5 是否小于 3。条件不成立，装入 AX 的就是 `0000H`；如果改为 3 小于 5，条件成立，装入 AX 的就是全 1，也就是 `FFFFH`。

逻辑表达式和关系表达式在实际程序设计中都不常直接使用，但语法允许，而且“汇编时求值”的本质与算术表达式相同。到这里一定要记住：不要看到表达式里有操作符，就默认它们一定在 CPU 执行时计算。

本块最后还点到了**属性表达式**，它才是实际程序设计中更常用的一类表达。后续再继续展开；先把最关键的分界线立住：表达式到底由汇编程序求值，还是由 CPU 执行，是读懂每条语句时必须先判断的问题。

## 标号与变量：让地址、类型和位置能够被程序使用
> 对应块：BLK13 | 覆盖分集：P26 | 块标题（分集名）：《26》

一给标号加上冒号，它就不只是一个供人阅读的名称了；一条指令有了名字，汇编程序便可以知道它位于什么地址、具有什么转移属性。到了变量这里，名字又和存放的数据绑在一起，于是我们不仅能访问数据本身，还能取它的地址、取它的类型、取它的长度。

这里最容易搞错的地方是：**一个名字放在源程序里，最终却对应机器中的地址、字节数和常量。** 标号与变量正是把“程序员写出来的名字”和“汇编后真正落到存储器里的内容”连接起来的两类对象。先把这件事想通，后面的属性表达式才不会只是几条需要死记的语法。

### 标号为何一出现就具有属性

我们先看一条普通的转移指令，例如：

```asm
NEXT:   JMP NEXT
```

`NEXT:` 写在指令左边，以冒号结尾；`NEXT` 就是这条指令的标号。汇编程序把标号和它后面那条指令的位置联系起来，汇编时便能自动确定这条指令的目的地址。

> **定义**：标号是加在指令语句左边的符号，以冒号结尾，用来标识该指令语句的地址。标号一经定义，就能够通过属性表达式取得它的属性。

一个标号具有三个属性。

#### 指令所在单元的地址

第一个属性，是该标号所标识的指令在存储器中对应的 **16 位地址**。如果指令地址为 `1500H`，表达式 `NEXT` 的值就是 `1500H`。

前面已经强调过地址与内容不能混为一谈：`NEXT` 并不是指令本身，也不是指令中的操作数，而是这条指令所在存储单元的地址。程序执行到这里时，地址便有了确定的值。

#### 指令的段内偏移地址

第二个属性，是该标号所标识指令的 **16 位段内偏移地址**，用属性操作符 `OFFSET` 取得。

```asm
MOV BX, OFFSET NEXT
```

这里的意思很明确：把 `NEXT` 所标识指令的 16 位段内偏移地址送入 `BX`。

> **易错点**：`NEXT` 取得的是标号对应的 16 位地址，而 `OFFSET NEXT` 取得的是 16 位段内偏移地址。两者有关联，却不能混为一谈。写成 `MOV BL, OFFSET NEXT` 才是类型不匹配，因为 `BL` 只能接收 8 位数据，而偏移地址是 16 位。

为什么偏移地址一定是 16 位？8086 逻辑地址中的偏移部分就是一个 16 位量，所以由属性表达式得到的段内偏移地址不能把它改成 8 位来接收。

#### 标号的类型属性

第三个属性是类型。标号的类型由转移指令与转移目的地的位置关系决定。

| 转移情况 | 标号类型 | 8086 对应的类型值 |
| :--- | :--- | :--- |
| 转移指令与目标标号在同一代码段 | 段内（近）转移 | `-1` |
| 转移指令与目标标号不在同一代码段 | 段间（远）转移 | `-2` |

因此，`OFFSET` 取得偏移地址，而类型属性只能从 `8086` 汇编语言规定的 `-1` 或 `-2` 中选择。8086 汇编语言把这些值称为标号的**类型属性值**；在 MASM 源程序里，一般使用 `NEAR`、`FAR` 来表达标号的段内或段间属性。

> **注意**：在实际的 8086 汇编语言程序设计中，专门获取标号的类型属性通常没有实际意义。我们真正经常使用的是 `OFFSET`，也就是取得标号对应的段内偏移地址。

### 变量与变量定义伪指令

再把目光转到变量。

变量和标号一样，也是给存储器中的一组单元起名字；不同之处在于，标号指向指令语句，而变量指向数据。变量名称的书写规则与标号相同，例如以字母开头。

我们为什么把“变量”叫变量？汇编程序每汇编一次，这个名字所对应的数据就可能改变，所以它不是一块永远不变的单元，而是一个有名字、可反复读写的存储位置。

8086 汇编语言程序设计中最需要掌握的是三个变量定义伪指令。

| 伪指令 | 定义的数据类型 | 占用长度 |
| :--- | :--- | :--- |
| `DB` | 字节型数据 | 1 字节 |
| `DW` | 字型数据 | 2 字节 |
| `DD` | 双字型数据 | 4 字节 |

> **结论**：本讲后面程序设计时，重点掌握 `DB`、`DW`、`DD`。变量通常定义在数据段中。

下面这段代码先把几个常用变量定义出来，后面就可以用它们观察地址、偏移、类型和长度是怎样落在存储单元中的：

```asm
DATA SEGMENT
    BETA1  DB  12H
    BETA2  DB  4D12H
    BETA3  DW  1234H
    BETA4  DW  0012H
    DATA ENDS
```

`BETA1` 被定义在数据段起始处，汇编时该单元的地址取 `1500H`；如果给程序换一个起始地址，变量对应的地址也可能随之改变。名称仍然还是 `BETA1`，但它所落到的存储单元变了，这正是“变量”有别于普通常量名的直观体现。

> **提示**：常量一旦被汇编程序确定，它在表达式中的值就是一个常数。比如 `1234H` 是立即数，不能把它改写成寄存器；想修改数据，必须让程序重新给它赋一个值。

### 变量定义后具有哪些属性

一个变量定义完成后，同样具有自己的属性。

#### 变量对应单元的地址

第一个属性，是该变量所在存储单元的 **16 位地址**。例如 `BETA1` 从 `1500H` 开始，它对应的地址就是 `1500H`。这个地址可以用 `BETA1` 取得。

#### 变量对应单元的段内偏移地址

第二个属性，是该变量所在存储单元的 **16 位段内偏移地址**，用 `OFFSET` 取得：

```asm
MOV BX, OFFSET BETA1
```

这条指令把 `BETA1` 对应存储单元的 16 位段内偏移地址送入 `BX`。若要按地址访问其中的数据，就可以再借寄存器间接寻址来使用这个偏移值。

```asm
MOV AL, [BX]
```

`BX` 保存 `BETA1` 的段内偏移地址，`[BX]` 再据此找到该变量所在单元，读取其中的数据。

> **易错点**：取变量偏移地址的常见目的，是配合后续间接寻址访问数据，通常要送入 16 位寄存器。因此，`BX`、`BP`、`SI`、`DI` 这类 16 位寄存器适合接收它。`MOV AX, OFFSET BETA1` 语法成立，但在实际程序中，如果寄存器位置足够，通常直接使用 `AX` 即可；写成 `MOV AL, OFFSET BETA1` 则会产生 16 位偏移地址与 8 位目标操作数不匹配的问题。

#### 变量的类型属性

第三个属性是类型，它反映变量所占的字节数。8086 汇编语言为类型属性规定了相应常量值。

| 变量定义方式 | 数据类型 | 类型属性值 |
| :--- | :--- | :---: |
| `DB` | 字节型 | `1` |
| `DW` | 字型 | `2` |
| `DD` | 双字型 | `4` |

例如，若 `BETA1` 是由 `DB` 定义的字节型变量，那么它的类型属性值就是 `1`；若变量由 `DW` 定义，则类型属性值为 `2`；由 `DD` 定义，则为 `4`。

> **提示**：MASM 在汇编时，会根据变量定义伪指令确定 `BETA1 TYPE` 的值，并预先把它替换为一个常数。知道具体替换值并不重要，重要的是类型属性必须与数据实际占用的字节数一致。

#### 变量的长度属性

第四个属性是长度属性，用来描述变量所占单元的大小。`LENGTH` 操作符和 `SIZE` 操作符都与这个属性有关。

- `LENGTH BETA1` 取得变量对应的元素数。
- `SIZE BETA1` 取得变量所占的总字节数。

例如，对于一个 `BETA1 DW 1234H`：

- `LENGTH BETA1` 的值为 `1`，表示有 1 个字型元素。
- `SIZE BETA1` 的值为 `2`，表示该变量总长 2 字节。

```asm
BETA1  DW  1234H
COUNT  DB  4

COUNT  EQU 2
M1     DW  BETA1, COUNT
```

若 `BETA1` 指向一个双字型数据，再结合 `COUNT`，则：

$$
\operatorname{SIZE} = 1 \times 4 + 2 = 6\text{ 字节}
$$

`LENGTH` 与 `SIZE` 的结果不同，正是因为前者描述“几个元素”，后者描述“总共占多少字节”。

### 汇编后怎样给变量分配地址

现在假设有如下变量定义：

```asm
DATA SEGMENT
    B1  DB  12H
    W1  DW  1234H
    D1  DD  12345678H
    W2  DW  0012H
    DATA ENDS
```

假如题目规定 `B1` 的地址是 `1500H`，那么按变量定义顺序，汇编程序分配的存储布局是：

| 变量 | 起始偏移 | 存储内容 | 下一变量偏移 |
| :--- | :---: | :--- | ---: |
| `B1` | `0000H` | `12H` | `0001H` |
| `W1` | `0001H` | `34H 12H` | `0003H` |
| `D1` | `0003H` | `78H 56H 34H 12H` | `0007H` |
| `W2` | `0007H` | `12H 00H` | `0009H` |

从图中可以看出，`DB` 定义一个字节，地址加 1；`DW` 定义一个字，地址加 2；`DD` 定义一个双字，地址加 4。

### 位置计数器怎样跟踪当前地址

> **易错点**：这里最容易混淆的是逻辑地址、物理地址和偏移地址。题目直接给出的 `1500H` 应当按它实际承担的角色理解；如果它是首地址，而不是“每个变量自己的偏移地址”，就应该结合所在逻辑段和“段基址加偏移”的规则来计算，不能把它直接当成每个变量都从 `1500H` 开始。

MASM 汇编程序通过 `$` 来引用“位置计数器当前值”。位置计数器是一个 16 位偏移量，用来跟踪**当前这条待汇编的指令或数据项的起始偏移地址**。

这里有一个必须分清的差别：

- 取某个变量的地址或偏移地址：使用该变量名，或者使用 `OFFSET` 加变量名。
- 取当前汇编位置的偏移地址：使用 `$`。

如果 $ 本身是 16 位量，那么“它是一个 16 位的偏移量”与“它已经被赋值为某个具体数值”并不是同一件事。它表达的是位置关系；具体数值，要由汇编程序在汇编到这个语句时计算出来。

```asm
DATA SEGMENT
    B1  DB  12H
B   DW  B1, $
    DATA ENDS
```

在这里，`B DW B1, $` 仍然没有成为 `BETA2 DW 0012H` 或 `BETA2 DW 0012H`：

- `B1` 是变量名，取得其对应存储单元的地址。
- `$` 是位置计数器，表示该数据项开始汇编时在当前逻辑段中的位置。

所以这里不能直接把它算成 `BETA2` 的初值。`$` 并不是一个会自动跟着 `B1` 的内容值改变的“下一个空闲地址”变量，它究竟表示起始偏移、相对地址，还是在程序段内使用时的某个相对值，要看它所在的具体伪指令如何使用它。

> **结论**：不要在没有伪指令定义依据的情况下，擅自把 `$` 等同一个“下一个可用地址”。本讲没有给出足够条件去确定一个具体数值，这里保留应有的谨慎。

### 把标号和变量的属性放在一起看

| 对象 | 指向什么 | 地址属性 | 偏移属性 | 类型依据 |
| :--- | :--- | :--- | :--- | :--- |
| 标号 | 指令语句 | 指令所在单元的 16 位地址 | `OFFSET 标号` | 段内或段间 |
| 变量 | 数据单元 | 变量所在单元的 16 位地址 | `OFFSET 变量` | `DB`、`DW`、`DD` 等定义 |

无论对象是标号还是变量，偏移地址的宽度都是 16 位。真正随着对象、定义方式和访问目的变化的是：它指向指令还是数据，它占 1、2、4 个乃至更多字节，以及取到偏移以后，是直接使用数值，还是把它作为间接寻址的基础。

标号和变量这两个对象，一端连着“指令地址”，另一端连着“数据地址”。只要沿着这条线把地址、偏移、类型和长度串起来，汇编语言中那些看似孤立的指令，就都只是在用不同方式访问名称背后的存储信息。

### 定义语句里的常量、字符与字符串

先回到 `DUP` 之前的那些基本规则。定义语句里允许引用常量符号，常量本身也是可以用表达式参与运算的。

#### 常量符号可以参与表达式

假设有一个数值常量：

```asm
K   EQU 56AH
```

后面就可以写 `DB K+2` 这样的定义。汇编程序不会去猜 `K+2` 是什么意思，它会先把表达式算出来：`56AH + 2 = 58AH`，再把结果按 `DB` 定义的字节存下去。等一会儿常量的值换成 `56H`，同一个 `K+2` 表达式算出来就是 `56H + 2 = 58H`。你可以把加二、移位这些运算写在表达式里，汇编程序会先算出结果，再按结果的位数放进 `DB` 所定义的字节里。

这里最关键的一点：**变量名定义语句的排列顺序就是内存分配的地址顺序。** MASM 拿着这些定义，从数据段的偏移 `0000H` 起一项一项往下排。

#### 字符与字符串

字符用一对单引号括起来。`DB 'A'` 不存字母本身，而是存字母 `A` 的 ASCII 码 `41H`；同理 `DB 'C'` 存 `43H`，`DB 'S'` 存 `53H`，`DB 'B'` 存 `42H`。落进内存里的就是这些 ASCII 码。

不加 `T` 字符时，大小写不分。MASM 把单引号里的内容按大写处理，所以 `DB 'a'` 和 `DB 'A'` 存的码值一样，都是 `41H`。要指定小写，得写成 `DB 'tA'` 这样的形式——注意是大写的 `T`。

#### 字符串的长度限制

字符串用一对双引号括起来。`DB "AC"` 最多只能放两个字，因为 `DB` 定义的是字节，一个字节只能放一个字符。两个字符就需要两个字，所以要写成 `DW "AC"`。

`DD "ABC"` 可以写多长的字符串呢？只要这串字符放进内存放得下，就可以。`DW` 后面放双引号串最多两个字，`DD` 后面就不受这个限制了，64K 都放得下。这是 8086 汇编语言规定的，没有为什么，必须这么用。

> **易错点**：`DB` 双引号串最多两个字；`DD` 后面的双引号串可以长到内存放得下为止（不超过 64K）。写 `DB "string"` 汇编不过。

### 变量定义的三种形式与地址推进

变量名定义语句的核心功能是实现数据定义。MASM 后面拿着这些定义去给变量分配内存，地址从数据段起始处开始，一项一项往下排。

#### DB 定义字节变量

`DB` 定义字节变量，占 1 个字节：

```asm
V1  DB 56H
```

假设它排在偏移 `0000H` 之后，第一个地址是 `0001H`，那 V1 就落在 `0001H`，内存单元里放 `56H`。偏移地址是跟着前面定义往下排的，常量的值变了，V1 的地址并不改变。

#### DW 定义字变量

`DW` 定义字变量，占 2 个字节，低字节在低地址、高字节在高地址：

```asm
V2  DW 9CH
```

`9CH` 只有 1 个字节，MASM 会把高字节补上 `00H`。所以在数据段里是低地址放 `9CH`、紧接着的高地址放 `00H`；写 `09CH` 效果一样。写 `ABH` 放到高字节位置时，前面那个零可以省掉，但要是 MASM 把它当成一个字节看，得到的值就错了。

#### DD 定义双字变量

`DD` 定义双字变量，占 4 个字节：

```asm
V3  DD 9CH
```

`9CH` 放在最低地址的单元里，高字节放 `00H`，剩下的两个字节全是 `00H`。这就是为什么 `DB 0ACH` 和 `DB 'AC'` 是一回事——`0A` 是高位置的零，`0C` 才是真正要存的字符。

> **易错点**：前面定义的变量占几个字节，下一个变量的偏移地址就往后推几个字节：DB 推 1、DW 推 2、DD 推 4。这是硬规矩。

```text
偏移地址    0000H  0001H  0002H  0003H  0004H  0005H  0006H
           ┌──────┬──────┬──────┬──────┬──────┬──────┬──────┐
V1 DB 56H  │      │ 56H  │      │      │      │      │      │
V2 DW 9CH  │      │      │ 9CH  │ 00H  │      │      │      │
V3 DD 9CH  │      │      │      │      │ 9CH  │ 00H  │ 00H  │
           └──────┴──────┴──────┴──────┴──────┴──────┴──────┘
```

读图说明：`DB` 占 1 个字节，紧接的 `DW` 占 2 个字节，再紧接的 `DD` 占 4 个字节；`DW` 和 `DD` 都是低字节放低地址、高字节补 `00H` 放高地址。

### DUP 重复操作符

在实际的数据定义里，定义一个字节的变量、定义十个字节的变量，往往是 `+` 操作符加不上的——`+` 只会加出算术表达式，加不出存储空间。`DUP` 重复操作符就是为这个来的。

#### 基本写法

`DUP` 的语法是"重复次数 `DUP` 单个数据"：

```asm
VAR1    DB  4 DUP 5
VAR2    DW  3 DUP 0
```

左边的数字是重复次数，汇编程序会把这一个数据重复填满左边的次数。`VAR1` 用 `DB` 重复 4 次，占 4 个字节；`VAR2` 用 `DW` 重复 3 次，占 $3\times 2=6$ 个字节。下一个变量的偏移地址就在这个数的基础上再往后推。

`DUP` 后面括号里写的是"单个数据"——可以是具体的数、字符，也可以是 `?`。写具体值就按这个值填满；写 `?` 就表示这个单元的值是随机的、没有初始化。问号就是让 MASM 保留这块空间，不给它赋一个确定的值。写 `00H` 则是正常操作：显式把这些单元清零。

所以至少要分清三个东西：

- `DUP` 告诉 MASM 这条语句重复多少次；
- `?` 表示未初始化，值是随机的；
- `00H` 表示显式清零。

> **易错点**：`?` 不是零，是"随机"；`00H` 才是零。写代码的时候别把"没给值"和"给了零"混为一谈。

#### DUP 可以嵌套

课后第一题（教材 P87 第 4 题）让定义 8 个缓冲区：每个缓冲区保存 5 个字节的 `05H`，再保存 10 个字节的 240，也就是 `0F0H`（十进制 240 转成十六进制是 `0F0H`，是 `0F0H`，不是 `F0H`，前面那个零不能省）。

每个缓冲区 15 个字节，8 个缓冲区就是 $8\times 15=120$ 个字节。嵌套写法是：

```asm
BUFF    DB  8 DUP (5 DUP 05H, 10 DUP 0F0H)
```

这一句里的 `8 DUP` 把整个括号重复 8 次，每次括号里又有两个 `DUP`：先放 5 个 `05H`，再放 10 个 `0F0H`。不用嵌套的话，也可以把每个缓冲区的 15 个字节一个个列出来，再用 `8 DUP` 把这 15 个值整体重复 8 次。

`DUP` 操作符后面可以嵌套，这是允许的。标准答案就是这么写的。但实际应用当中，这类"保留这么多同样内容"的需求，通常写成循环更合适，而不是用 `DUP` 展开成一大串。

> **提示**：`DUP` 嵌套是语法允许的，但实际应用当中非常常用的是循环，而不是把 `DUP` 展到一长串定义上。

### 变量的五项属性

讲完 `DUP` 之后还有一个概念先补上，3.1 节的最后一块拼图。变量定义语句所定义的变量具有下列五个属性：长度、大小、组距、位移、偏移地址。前两个是定义语句本身就能算出来的，后三个要结合偏移地址一起看。

#### 长度与大小

> **定义**：变量的**长度**属性，是指变量名定义语句中所定义的变量个数。8086 汇编语言规定：如果定义语句中出现了 `DUP` 重复操作符，那么左边的重复字数就是这一条定义语句中所定义的变量个数；如果没有 `DUP`，则只定义了一个变量，长度等于 1。

比如 `DB 4 DUP 5`：左边写了重复次数 4，所以定义了 4 个变量，长度等于 4。如果是 `DB 5H`，那这条定义语句只定义了一个变量，长度等于 1。

> **定义**：变量的**大小**属性，是指变量名定义语句中所定义的所有变量所占的总字节数。变量的大小属性等于该变量的类型乘以该变量的长度。

$$\text{size} = \text{unit type} \times \text{length}$$

如果用 `DB` 定义，每单元占 1 个字节；如果用 `DW` 定义，每单元占 2 个字节；如果用 `DD` 定义，每单元占 4 个字节。`DB 4 DUP 5` 的大小就是 4 乘 1 等于 4；`DW 3 DUP 0` 的大小就是 3 乘 2 等于 6。

#### 偏移地址、组距与位移

偏移地址是最后一个属性，已经在前面的分配表里算过：变量名定义语句里每个变量在内存中的偏移地址，MASM 按定义顺序从 `0000H` 起往下排，DB 推 1、DW 推 2、DD 推 4。

组距就是两个相邻变量单元在内存里隔开的字节数，也就是定义语句中一个单元的类型所占的字节数：DB 定义的变量组距是 1，DW 定义的变量组距是 2，DD 定义的变量组距是 4。

位移就是一个变量单元的地址与该变量首地址之间的差。对第一个变量单元来说位移是 0，对第二个单元来说位移是一个组距，依此类推。这三个属性——偏移地址、组距、位移——是把变量定义和后续寻址连起来的桥梁：偏移地址给出第一个单元在哪里，组距给出往哪里跳，位移给出要跳多远。

3.1 节的五个属性操作符到这里就讲完了，再加一个表达式里的 `PTR` 操作符。

### PTR 属性操作符

`PTR` 操作符就是我们讲表达式时讲过的那个属性操作符，可以把它理解成表达式里的"临时类型修改操作符"。

#### 为什么要临时改类型

假设变量 `B1` 是字变量（`DW` 定义），而你想在一条指令里按字节去获取它，源操作数和目的操作数的类型不一致，MASM 汇编时会认为语法错误、给退出来。

`PTR` 就是在指令语句中把 `B1` 临时转化成字节变量来用：

```asm
MOV  AL, BYTE PTR B1
```

这条指令的意思是：把 `B1` 当作字节变量看待，把它的低字节取到 `AL` 里。`PTR` 前面必须留一个空格——`BYTE PTR` 是一体的强制类型转换写法。

#### 临时两个字很关键

汇编程序处理完这条语句以后，脱离这条语句，`B1` 仍然是字变量。`PTR` 只在这条语句里临时把它修改成字节变量来用；出了这条语句，它还是原来定义的类型，内存里的数据也一个字节都没动。这就是为什么它叫"临时修改操作符"。

反过来也一样：我在一个字节型变量上想按字去取，就写 `MOV AX, WORD PTR B1`。

#### PTR 的第二个用途：给纯表达式指定类型

还有一种情况比上面更常见：指令里的操作数是 `[010H]` 或者 `[SI]` 这样一个地址表达式，它本身只是一个地址，不是前面定义过的变量名。MASM 拿到这样的表达式，判断不出它是字节、字还是双字——因为没有任何类型信息可以参考。这时候整个操作类型就不能确定，汇编时不知道该按一个字节处理还是按一个字处理，就会停下来报错。

要让它明确，就得用 `PTR`：

```asm
MOV  BYTE PTR [010H], 10H
```

`BYTE PTR [010H]` 告诉汇编程序，括号里找到的这个 DS 单元是一个字节单元，把 `10H` 写进这个单元。`BYTE PTR` 明确说"第二阶形式找到的单元是字节型的"，`PTR` 把类型钉死，汇编才能通过。

在实际应用当中，这种"操作数类型需要临时指定"的情况非常多，`PTR` 用得非常广泛。记住一句话：PTR 临时修改操作符，只在当前这条语句里生效。

### 8086 指令的十三大类

3.2 节讲 8086 指令系统当中指令的分类。指令多，按功能分成 13 类，每一类里有好多条。

| 类别 | 功能 | 课堂上见过的指令 |
| :--- | :--- | :--- |
| 数据传送类 | 在寄存器、存储器等位置之间传送数据 | `MOV` |
| 算术运算类 | 加、减、乘、除等运算 | `ADD`、`ADC` |
| 逻辑运算类 | 按位进行逻辑运算 | `AND`、`OR`、`XOR`、`NOT` |
| 位操作类 | 把操作数左移或右移一位或若干位 | 左移、右移指令 |
| 标志位操作类 | 直接设置或清除标志位 | `CLC`、`STC`、`CMC`、`CLD`、`STD`、`CLI`、`STI` |
| 转移类 | 控制程序转移 | 条件转移 `JZ`、无条件 `JMP` |
| 循环控制类 | 控制循环 | `LOOP` |
| 子程序调用与返回类 | 调用子程序并返回 | `CALL`、`RET` |
| 中断调用与返回类 | 发出软件中断并返回 | `INT` |
| 字符串操作类 | 字符串的传送、比较等 | `MOVS` |
| 输入输出类 | 对 I/O 端口读写 | `IN`、`OUT` |
| 其他指令 | 前面这些类没能涵盖的指令 | —— |
| 宏指令 | 8086 指令系统本身没有、用户用宏定义方法自己定义的新指令 | —— |

> **注意**：转移类又分两种。条件转移要受某一个条件的控制，比如 `JZ`；无条件转移不受条件控制，比如 `JMP`。子程序调用 `CALL` 本质上也属于无条件转移——像 C 语言里把某一段程序单独定义成子程序，需要时调进去，调用完再返回。

3.3 到 3.16 节就按类来学。但在那之前，教材为了叙述方便，规定了统一的记号：目的操作数用 `DST` 描述，源操作数用 `SRC` 描述，寄存器用 `REG` 描述操作数，求存储单元的有效地址或段内偏移地址用 `EA` 描述，寻址方式用 `S` 描述。书上列得很清楚，这部分自己看一遍就行，我不一一去数了。

### 寻址方式：把操作数的位置算出来

接下来是 3.3 节，数据与转移地址的寻址方式。这一节不背，记住一句话就够了：

> **定义**：寻址方式就是求操作数所在位置或所在存储单元地址的方式。

大多数情况下，指令中出现的操作数都在寄存器当中。当然，如果操作数在存储器里，存储器的有效地址怎么求得？要用一种方法来求得，这种方法就是寻址方式。还有一些情况下，指令中的操作数不在寄存器里，而是一个立即给出的常数——这个也归在寻址方式当中。

再往下分：如果求得的操作数 `OPR` 可以作为数据，用作指令操作的数；也可以作为程序要实现转移的转移地址。寻址方式因此分成两大类：

- 第一大类，是关于取数据的寻址方式；
- 第二大类，是关于转移目的地址的寻址方式。

关于转移地址的求法：如果是段内转移，只要得到转移目的地的 16 位偏移地址，给 `IP` 即可；如果是段间转移，除了偏移地址，还得得到目的地的 16 位段地址，给 `CS`。这两类放在后面讲。

### 数据寻址方式：立即寻址与寄存器寻址

8086 指令系统一共给出了八种数据寻址方式，我们先看前两种。

#### 立即寻址

立即寻址指的是要寻找的这个操作数，在指令中以立即给出的、以常数的形式给出的。比如：

```asm
MOV  AX, 1234H
```

`AX` 是目的操作数，`1234H` 是源操作数。对于源操作数而言，数据就在指令中立即给出，这就是立即寻址。`AX` 是寄存器寻址，下一节再说。

马上要记住这个概念：指令中的源操作数和目的操作数，谁和谁之间都能传送数据。操作数可能的位置只有四种——立即数、通用寄存器、存储器、段寄存器。立即数可以发送给通用寄存器，存储器单元也可以通过立即数去写，但立即数不能作目的操作数。把立即数写进目的操作数的那个位置，语法就错了。**立即数只能做源操作数。**

#### 寄存器寻址

寄存器寻址指的是要寻找的操作数在某个寄存器里。

```asm
MOV  AX, BX
```

这条指令把 `BX` 的内容传送到 `AX` 里。源操作数是寄存器寻址（在 `BX` 寄存器中），目的操作数也是寄存器寻址（传送到 `AX` 寄存器）。两个通用寄存器之间可以互相传送数据。

但当源和目的都是寄存器寻址时，要注意类型一致：

```asm
MOV  AL, CL
```

源是 8 位寄存器、目的也是 8 位寄存器，语法正确。但如果 16 位的 `AX` 配 8 位的 `CL`，操作类型不一致，MASM 会认为语法错误。

> **结论**：源操作数和目的操作数只要有一方类型明确，双方就都明确；双方都不明确，类型就不明确，汇编通不过。

#### 方括号里只有地址：类型要自己指定

立即数可以传送给存储器单元，例如：

```asm
MOV  [0200H], 56H
```

`[0200H]` 是目的操作数，中括号里的 `0200H` 是偏移地址，段地址取默认的 DS。源操作数是立即寻址。但这条指令有个问题：中括号里只给了一个地址，没有说这个地址上的单元是字节、字还是双字。类型不明确，语法错。

如果这个单元是一个字单元，就得用 `PTR` 明确类型：

```asm
MOV  WORD PTR [0200H], 56H
```

`WORD PTR` 告诉汇编程序，偏移地址 `0200H` 找到的单元是一个字单元，把 `56H` 送进去。类型一明确，语法就正确了。

这里顺便记一条 `LEA` 的用法：想直接把存储单元的地址取到寄存器里，用 `LEA AX, [0200H]`，把变量名写在中括号里即可，汇编程序就知道那是地址。

#### 段寄存器初始化的两步走

如果想给 `DS`、`ES` 或 `SS` 赋值，不能直接用立即数：

```asm
MOV  DS, 1500H      ; 语法错误
```

立即数只能做源操作数，不能直接送给段寄存器。怎么办？按图上箭头的路线，先让立即数送给一个通用寄存器，再由通用寄存器送给段寄存器：

```asm
MOV  AX, 1500H
MOV  DS, AX
```

用 `AX` 作中介过渡一下，这两条指令的源和目的都是寄存器寻址。

> **结论**：当 `DS`、`ES`、`SS` 这三个段寄存器作目的操作数时，源操作数不能是立即数。给这三个段寄存器初始化，至少需要两条指令。

### 本讲提到的题目

#### 缓冲区定义

题目要求：在缓冲区里保存 8 个缓冲区，每个缓冲区保存 5 个字节的 `05H`，再保存 10 个字节的 240。

240 转成十六进制是 `0F0H`。每个缓冲区共 15 个字节，8 个缓冲区共 120 个字节。

解析：`DUP` 后面可以嵌套。`8 DUP` 把整个括号重复 8 次，括号内先用 `5 DUP 05H` 放 5 个 `05H`，再用 `10 DUP 0F0H` 放 10 个 `0F0H`。写 `0F0H` 时前面那个零不能省，否则值就变了。

答案：

```asm
BUFF    DB  8 DUP (5 DUP 05H, 10 DUP 0F0H)
```

## 存储器寻址：把地址算出来，再检查语法
> 对应块：BLK15 | 覆盖分集：P29-P30 | 块标题（分集名）：《29》

想把一个值直接写进 `CS`，行不行？不行。这不是数值算错了，而是 `CS` 的身份不允许你这样用：程序装入内存并启动时，由操作系统建立初始的 `CS:IP`；程序执行期间，转移指令负责改变转移位置。`CS` 只能跟着 `IP` 一起改变，`IP` 也会因转移指令而改变。我们自己的普通传送指令，不能强行把它们改掉。

这一下就把寻址部分最容易混淆的两条线分开了：

- **地址怎么求出来**：操作数在存储器哪个单元；
- **操作数怎么使用**：这个操作数是什么类型，能否直接送到目的位置。

地址算对了，指令仍可能因类型不明确、源与目的类型不一致而报错；类型写对了，地址表达式也仍可能不合法。写存储器操作数时，必须把这两条线一起检查。

### 通用语法先立规矩

8086 指令的语法不是各类指令各自为政。后面学到的每一类传送、运算、堆栈指令，都有共同的语法限制；某一类指令还可能附加自己的限制。

> **结论**：先通过通用语法检查，再检查本类指令的个性规则。

#### 目的操作数不能是立即数

指令的基本方向是“源操作数 → 目的操作数”。立即数只是一个写在指令中的数值，它不是寄存器，也不是存储器单元，因此不能充当目的操作数。

> **易错点**：看到“左边是要写到哪里去的”，就必须先问一句：这个位置允许被指令直接修改吗？

#### 源、目的操作数必须类型一致，而且类型要明确

`AL` 是 8 位寄存器，`AX` 是 16 位寄存器；`DB` 定义的是一个字节单元，`DW` 定义的才是一个字单元。让 16 位的 `AX` 直接对应一个字节单元，类型就对不上。

寄存器间接寻址还有一层容易忽略的问题：`[BX]` 能说明地址，却没有说明这个单元里的操作数究竟是字节还是字。如果另一端没有替你把类型说清楚，就必须用 `PTR` 明确指定。

> **提示**：看指令时要养成左右对照的习惯。`AL`、`AX` 会直接带来类型；`[BX]`、`[SI]` 只负责给出地址，不会自动告诉你操作数宽度。

#### `CS`、`IP` 不能作目的操作数

`CS`、`IP` 可以在指令允许的场合作为源操作数使用，却不能像通用寄存器那样被普通用户指令随意改写。它们的改变由操作系统建立初始值、由转移指令改变执行位置。

因此，看到试图直接给 `CS` 或 `IP` 赋值的指令，不必再检查地址计算，第一层就可以判定：语法不允许。

#### 串操作与堆栈操作还有附加限制

串传送中，`DS`、`ES` 所扮演的角色由指令本身规定，不能把它们当作任意通用寄存器替换；源操作数也不能写成立即数。

堆栈的 `PUSH`、`POP` 则必须按字操作。这是堆栈操作类指令自己的语法个性规则。也就是说不只要满足前面那些共性规则，还要满足“按字操作”这一条。

两个存储器单元之间也不能直接传送或运算。数据必须先经过一个通用寄存器过渡：

```text
源存储单元 ──读取──> 通用寄存器 ──写入──> 目的存储单元
```

### 五种存储器寻址先把骨架立住

当操作数在存储器中时，我们真正要回答的问题是：**操作数所在单元的 16 位有效地址，也就是偏移地址，怎样求出来？**

8086 的存储器寻址方式一共五种：

| 寻址方式 | 有效地址的组成 | 关键点 |
| :--- | :--- | :--- |
| 直接寻址 | 指令直接给出的地址 | 地址直接写在指令中 |
| 寄存器间接寻址 | 地址寄存器 | 用寄存器保存有效地址 |
| 寄存器相对寻址 | 基址寄存器 + 相对位移量 | 适合在某个地址附近取数 |
| 基址变址寻址 | 基址寄存器 + 变址寄存器 | 两部分相加得到有效地址 |
| 基址变址相对寻址 | 基址寄存器 + 变址寄存器 + 相对位移量 | 三部分相加得到有效地址 |

后面要重点展开的是前三种。不能随手把两个地址寄存器相加，就宣称存在“寄存器加寄存器”的独立寻址方式；例如把 `BX` 与 `SI` 相加，在 8086 的语法里应当归入“基址变址寻址”，而不能再自造一种寻址方式。寄存器与立即数相加，则属于寄存器相对寻址。

### 直接寻址：地址直接写在指令里

直接寻址的核心只有一句话：**操作数所在单元的有效地址，由指令直接给出。**

例如：

```asm
MOV AL, [2000H]
```

这条指令要做的事，是从当前默认数据段内、偏移地址为 `2000H` 的存储单元取出一个字节，送进 `AL`。

- `[2000H]` 负责指出操作数所在单元；
- `AL` 决定这次操作按字节进行。

没有段超越前缀时，这里的段地址默认取 `DS`，所以有效地址就是 `2000H`。

但只看地址还不够。我们还必须判断另一个操作数究竟是字节还是字。只知道“有一个存储单元”，并不能自动推出它的类型；类型要从另一端看。

```text
源操作数                         目的操作数
[2000H]  ──读取一个字节────────>  AL

有效地址：2000H
默认段：DS
操作数宽度：由 AL 确定为 1 字节
```

### 用变量名写地址

实际编程时，我们很少总把 `2000H` 这样的数值地址硬写出来。数据段中定义好的变量，本身就带有段地址和偏移地址属性，程序里可以直接用变量名表示它对应的存储单元。

假设数据段中已经用 `DB` 定义了 `DATA1`，那么：

```asm
MOV AL, DATA1
```

和直接写出偏移地址，本质上是同一回事：操作数仍使用直接寻址，只是把地址写成了 `DATA1`。这里不需要再加方括号，因为汇编语言已经知道 `DATA1` 是一个符号化的地址。

这一步一定要分清：把偏移地址写成 `2000H`，和把一个变量名写在操作数位置，都属于直接寻址；把 `BX`、`SI`、`DI` 当成方括号中的地址寄存器，才是寄存器间接寻址。语法形式变了，地址是怎样得到的也必须跟着判断，不能只凭“这是存储器操作数”来猜。

### 两个存储单元不能直接搬运

我们很容易顺手写出一条看似顺理成章的指令：

```asm
MOV [DATA2], [DATA1]
```

它想把 `DATA1` 单元中的数据直接送到 `DATA2` 单元。地址表达式的形式没有明显问题，错在数据传输方向：**8086 不允许两个存储器单元直接传送数据。**

存储器操作数可以作为源，也可以作为目的，但一条普通传送指令的另一个操作数必须能够由 CPU 承接。这里的数据必须先读进通用寄存器，再从寄存器写回目的存储单元。

如果两个变量都按字节操作，应当拆成两步：

```asm
MOV AL, DATA1
MOV DATA2, AL
```

读图就很清楚：第一条从 `DATA1` 读出一个字节到 `AL`；第二条再把 `AL` 中的一个字节写进 `DATA2`。寄存器在这里是中转站。

> **易错点**：方括号里出现两个地址，并不表示 CPU 就能在两个存储单元之间搭一条直连通道。存储器之间必须经过寄存器。

如果换成加法、与运算等指令，道理也一样：两个存储器单元不能直接作为运算的双方参与操作，仍要先经过通用寄存器。

### 类型不一致时，用 `PTR` 临时改写属性

假设 `DATA1` 是用 `DB` 定义的字节变量，而 `AX` 是 16 位寄存器。直接写：

```asm
MOV DATA1, AX
```

源是字，目的却是字节，类型不一致，语法错误。解决办法是用 `PTR` 告诉汇编程序：在**当前这条指令里**，把 `DATA1` 临时按字处理。

```asm
MOV WORD PTR DATA1, AX
```

`WORD PTR` 并没有把变量本来的定义改掉。离开这条语句以后，`DATA1` 仍然是字节变量。这里的 `PTR` 只是一个属性临时修改操作符，只在它出现的语句中起作用。

> **结论**：类型不明确时，可以临时指定；类型已经冲突时，也要先让两边按同一种宽度对应。不要误以为 `PTR` 修改了变量定义本身。

### 寄存器间接寻址：先把地址放进寄存器

直接寻址把地址写在指令中。寄存器间接寻址换了一种办法：**先把有效地址放进某个 16 位地址寄存器，再用这个寄存器找到操作数。**

8086 中，可以直接提供有效地址的寄存器只有三个：

- `BX`
- `SI`
- `DI`

注意，这里没有 `BP`。`BP` 不能用于寄存器间接寻址，这一点和寄存器相对寻址不同，后面会专门指出。

假设 `DATA1` 在数据段中，可以先取得它的偏移地址，再装入 `BX`：

```asm
MOV BX, OFFSET DATA1
MOV AL, [BX]
```

第一条指令执行后，`BX` 中保存的是 `DATA1` 对应单元的 16 位有效地址。第二条指令不再把地址数值直接写出来，而是把 `BX` 的内容当成有效地址，从该单元取一个字节送给 `AL`。

```text
DATA1 的 OFFSET
        │
        ▼
       BX ──提供16位有效地址──> [BX] 所在存储单元
                                      │
                                      └──读取1字节──> AL
```

这时：

- `BX` 的内容是一个**地址**；
- `AL` 的内容才是一个**数据**。

把这两者混淆，最容易把“地址是什么”和“这个地址里放着什么”搅在一起。

不限于 `BX`。`SI`、`DI` 同样能提供寄存器间接寻址所需的地址：

```asm
MOV AL, [SI]
```

或者：

```asm
MOV AL, [DI]
```

它们的共同规则是：寄存器中保存操作数所在单元的 16 位有效地址；默认情况下，这三个寄存器形成的地址都按 `DS` 段解释。也就是说，使用 `BX`、`SI` 或 `DI` 做寄存器间接寻址时，段地址默认来自 `DS`。

### `[BX]` 给出了地址，却没有保证操作数类型

寄存器间接寻址还有一个特别容易漏掉的问题：`[BX]` 能告诉我们“去哪个单元取数”，却不能单独告诉我们“取一个字节还是取一个字”。

如果另一端是 `AL` 或 `AX`，类型已经由寄存器确定；如果另一端是立即数，或目的端仍然是存储器，就必须检查类型是否明确。不能因为寻址方式合法，就忽略操作数宽度。

```text
[BX] = 地址信息
AL   = 字节类型
AX   = 字类型
```

因此，当一条指令采用寄存器间接寻址，而另一端没有明确操作数类型时，就要用 `PTR` 把字节或字说清楚。这里的判断顺序不能反：先确定有效地址从 `BX`、`SI` 或 `DI` 来，再检查这个有效地址对应的操作数宽度。

### 寄存器间接寻址也不能让两个存储单元直连

同样不能写：

```asm
MOV [BX], [SI]
```

虽然 `BX` 和 `SI` 都能提供地址，但这两个方括号指向的是两个存储单元，不是两个可独立存放并中转数据的寄存器。前面已经总结过：两个存储器单元之间不能直接传送数据。

如果按字节操作，要让 `AL` 过渡：

```asm
MOV AL, [SI]
MOV [BX], AL
```

第一条用 `SI` 提供源单元地址，把一个字节读进 `AL`；第二条用 `BX` 提供目的单元地址，再把 `AL` 中的字节写进去。

读法是：

1. `SI` 找到源存储单元；
2. CPU 把该单元的一个字节送入 `AL`；
3. `BX` 找到目的存储单元；
4. CPU 把 `AL` 中的字节写入目的单元。

寄存器间接寻址解决的是“地址由谁提供”，并没有取消“两个存储器操作数之间需要寄存器中转”这条规则。

### 寄存器相对寻址：基址加一个位移

寄存器相对寻址把地址分成两部分：一部分放在基址寄存器中，另一部分是相对位移量 `disp`。`disp` 可以是 8 位，也可以是 16 位。

$$
EA = R_{base} + disp
$$

其中，基址寄存器可以使用：

- `BX`
- `BP`
- `SI`
- `DI`

这里又出现 `BP`，而且 `BP` 与另外三个寄存器一起作为基址寄存器使用。它为什么能在寄存器相对寻址中出现，却不能用于寄存器间接寻址？关键就在于相对寻址不要求寄存器单独装下整个有效地址。`BP` 只需贡献有效地址的一部分，再与位移量相加。

#### 默认段要随基址寄存器判断

当相对位移量是常数时，求得偏移地址所使用的默认段，由基址寄存器决定：

- 基址寄存器是 `BP` 时，默认段是 `SS`；
- 基址寄存器是 `BX`、`SI` 或 `DI` 时，默认段是 `DS`。

这一点一定要形成条件反射。看到 `BP` 做基址寄存器，先想到 `SS`；看到其余三个，才按 `DS` 处理。

#### 用 `BP` 访问一个字节单元

```asm
MOV [BP], AL
```

这条指令要把 `AL` 中的一个字节写入一个存储单元。目的单元的地址由 `BP` 的内容和相对位移量 `0` 共同给出：

$$
EA = BP + 0
$$

它使用的是寄存器相对寻址，不是寄存器间接寻址。虽然方括号里只写了 `BP`，但汇编后的指令编码中仍然存在位移量 `0`，这个零就是相对位移量。

> **易错点**：写成 `[BP]` 并不自动等于寄存器间接寻址。只要采用“基址寄存器 + 相对位移量”的结构，即使位移量是零，也仍然属于寄存器相对寻址。

### 相对位移把目标单元放在基址附近

假设已经让 `BX` 指向一组数据的起始偏移地址，现在要把 `AL` 写到起始单元之后第三个字节的存储位置，可以写：

```asm
MOV [BX+3], AL
```

这里没有把目标地址重新完整算出来，而是让 `BX` 指向一个基准，再加上相对位移量 `3`：

```text
BX ───────┐
          ├──> 有效地址 = BX + 3 ──> 目标存储单元
disp = 3 ─┘
```

由于基址寄存器是 `BX`，默认段按 `DS` 处理。最终写入哪个地址，取决于 `BX` 当时的值；而 `AL` 中的一个字节就是待写数据。

相对寻址适合表达“相对于某个基准位置的数据”。`BX` 负责基准，位移量负责说明目标离基准有多远。

### 两种书写格式，汇编结果相同

相对位移量也可以移到方括号里的基址寄存器前面：

```asm
MOV 3[BX], AL
```

它和下面的写法功能相同：

```asm
MOV [BX+3], AL
```

两种写法只改变书写位置，不改变有效地址的计算结果：

$$
EA = BX + 3
$$

相对位移量为正数且位于基址寄存器后面时，中括号里的加号可以省略，因此还可以写：

```asm
MOV [BX+3], AL
```

实际编程中，选一种自己读着顺、含义清楚的格式即可。关键不是背几种表面写法，而是无论它出现在中括号前后，都能立刻还原出“基址寄存器 + 相对位移量”。

### 位移范围看它有没有符号

寄存器相对寻址中的相对位移量可以按 8 位或 16 位书写。

使用 8 位位移量时，范围为：

$$
-128 \le disp \le 127
$$

它既能向高地址方向移动，也能向低地址方向移动；负位移量就是从基址位置向前减去相应的距离。

使用 16 位位移量时，范围为：

$$
-32768 \le disp \le 32767
$$

下界是 `-32768`，不是 `-32769`；上界是 `32767`。这里一定要把端点写准。

> **提示**：正向地址与反向地址都允许。不要把“相对位移”误解为只能往后找；负数表示向相反方向移动。

### 相对位移量也可以来自变量

前面说的是相对位移量为常数的情形。如果相对位移量不是一个写死的数值，而是一个 16 位变量呢？

这时，取该变量中的 16 位内容作为相对位移量，再与基址寄存器相加：

$$
EA = R_{base} + (变量内容)
$$

也就是说，变量名在方括号里不是“变量的地址”。寄存器相对寻址中作为相对量使用的是变量的**内容**，不是把变量所在单元的地址再加进去。

这一点很关键：

```text
BX              保存基准地址
变量内容         提供相对位移
两者相加         得到操作数所在单元的有效地址
```

而且，段地址不能只凭 `BX` 或 `BP` 的名称草率确定。由于位移量来自变量，最终要到哪个段取数，还要看这个变量定义在哪个数据段。变量定义在 `ES` 段，就按 `ES` 解释；定义在 `SS` 段，就按 `SS` 解释；定义在 `DS` 段，才按 `DS` 解释。

因此，常数位移量时可以依据基址寄存器直接判断默认段；位移量由变量给出时，还必须追踪变量定义在哪个段。看到寄存器就机械套默认段，这里会出错。

### 把三种寻址连起来判断

前面详细展开的直接寻址、寄存器间接寻址和寄存器相对寻址，可以放回同一张判断图里：

```text
操作数在存储器
      │
      ├── 地址直接写在指令中 ─────────> 直接寻址
      │
      ├── BX / SI / DI 单独保存地址 ──> 寄存器间接寻址
      │
      └── 基址寄存器 + 相对位移量 ─────> 寄存器相对寻址
                                         ↑
                            BX / BP / SI / DI 均可作基址

算完地址后继续检查
      │
      ├── 源、目的类型是否一致？
      ├── 存储器操作数类型是否明确？
      ├── 是否错误地让两个存储单元直接操作？
      ├── 是否把 CS / IP 当成目的操作数？
      └── PUSH / POP 是否满足按字操作？
```

这张图最重要的不是背名称，而是把判断顺序固定下来。

先看操作数是否在存储器中；再看有效地址究竟由指令直接给出、由地址寄存器单独给出，还是由基址寄存器与相对位移量相加得到；最后回头检查操作数类型和指令自身的语法限制。

> **易错点**：地址表达式合法，不代表整条指令合法。有效地址能求出来，只完成了第一步；操作数类型、源目的方向和特殊寄存器限制，任何一项不满足，指令仍然是错的。

把这条判断链掌握住，后面的基址变址、基址变址相对寻址虽然也要继续学，但它们并不是另起炉灶：仍然是先拆有效地址的组成，再检查类型与语法。只要不再把“地址寄存器”“操作数”和“目的位置”混为一谈，存储器寻址就没有想象中神秘。

> **承前启后**：上一节讲完「存储器寻址：把地址算出来，再检查语法」，下一节接着讲「从保护 SP 到段内跳转：8086 的复合寻址与转移地址」。

## 从保护 SP 到段内跳转：8086 的复合寻址与转移地址
> 对应块：BLK16 | 覆盖分集：P31-P32 | 块标题（分集名）：《31》

栈里明明已经放进了 `AX`，为什么不直接 `POP`，偏偏还要绕一个弯，用 `BP` 把它找出来？

原因就卡在四个字上：**不能破坏 SP**。栈顶位置是由 `SP` 指着的，通常的取数指令只要一执行，就会顺手改变 `SP`。如果既有数据要取，又要求 `SP` 回到原来的位置，那就得请出另一种寄存器，让它在不动 `SP` 的情况下找到同一个存储单元。

这个例子正好把寄存器相对寻址最重要的一条规则带了出来：**`BP` 出现在存储器操作数中时，默认使用 `SS` 段**。下面我们就把这条规则和几种常用复合寻址方式连起来，再顺着“转移地址”走到段内直接寻址与段内间接寻址。

### 不动 SP，把 AX 从栈里取出来

先看这个要求：

```asm
push ax
push bx
push cx
pop dx
```

前三条指令依次把 `AX`、`BX`、`CX` 压入栈中。最后一条 `pop dx` 固然能把栈顶的 `CX` 送到 `DX`，但它同时会修改 `SP`。现在要求取到 `AX`，同时还不能破坏 `BX` 和 `SP`，就不能再靠普通的出栈动作去取。

设最初的 `SP` 值为 $S$，并按 8086 压栈规则画成下面这样：

```text
地址        内容
S           原栈顶加 1
S - 2       AX
S - 4       BX
S - 6       CX
```

三次 `push` 完成后，真正的栈顶是 $S-6$，而 `AX` 仍留在 $S-2$。关键已经摆在这里了：**数据的位置没有变，变的是指针的意思。** 只要另找一个寄存器记住 $S$，就可以从另一个入口找到 `AX`。

若允许改用 `BP`，最简单的办法是在压栈前执行：

```asm
mov  bp, sp
```

此后，`BP` 中保存的是最初的 $S$，而 `AX` 所在单元相对 `BP` 的位移量就是 $-2$。所以要把它送到 `DX`，可以写成：

```asm
mov  dx, word ptr [bp - 2]
```

这里没有 `pop`，`SP` 自然不会因为这次取数而变化。

如果 `BP` 本身也不许破坏，就在使用前把它保护起来，最后再恢复：

```asm
push bp
mov  bp, sp
push ax
push bx
push cx
mov  dx, word ptr [bp - 2]
pop  bp
```

此时先把原 `BP` 压入栈中，再让 `BP` 记住当前位置。读完 `AX` 并送入 `DX` 后，`pop bp` 恢复原 `BP`，`SP` 也回到最初的值；`BX` 则始终没有被这条路径改写。

> **结论**：`push` 确实会保存原寄存器的内容，但不要因此误以为 `pop` 可以随便用。只要执行形式要求移动 `SP`，就可能破坏“`SP` 保持原值”这个条件。`BP` 相对寻址的价值，恰好在于它能从 `SS` 段中找到栈数据，而不靠 `SP` 的增减完成取数。

> **易错点**：这里默认在栈段操作，所以方括号中写 `BP` 时使用 `SS`。如果换成 `BX`，默认段就是 `DS`，不能把两个寄存器的默认段混在一起。

### 寄存器相对寻址：先看方括号里的寄存器

寄存器相对寻址的形式，是在寄存器后加一个位移量，例如：

```asm
mov al, [bp - 2]
mov al, [bx + 4]
```

方括号中的地址不直接写死，而是由“寄存器内容 + 位移量”形成。有效地址为：

$$
EA = R + d
$$

其中 $R$ 是方括号中寄存器的内容，$d$ 是指令给出的位移量。把有效地址放回所属的段中，物理地址就是：

$$
PA = S \times 16 + EA
$$

真正需要先判断的不是地址算式，而是默认段：

| 参与寻址的寄存器 | 默认段寄存器 |
| :--- | :--- |
| `BX` | `DS` |
| `SI` | `DS` |
| `DI` | `DS` |
| `BP` | `SS` |

这条规则可以理解为 8086 在指令编码中给出的约定。`BX`、`SI`、`DI` 出现时，CPU 会从 `DS` 取得段基址；`BP` 出现时，则从 `SS` 取得段基址。

> **易错点**：寄存器相对寻址作为目的操作数时，类型必须明确。`AL` 是一个字节，`DX` 是一个字，读出的存储单元究竟是字节还是字，不能靠猜。只有寄存器和目的操作数已经明确时，存储器操作数的大小才可能随指令一起确定；遇到类型不能自然确定的情况，就要显式写明。

### 基址变址寻址：把 BX 和 SI 加起来

只看一个寄存器还不够，程序里经常要在一个数据块的第 0、1、2……个单元之间移动。这时可以把两个寄存器的内容相加：

```asm
mov al, [bx + si]
```

它的有效地址为：

$$
EA = [BX] + [SI]
$$

物理地址为：

$$
PA = [DS] \times 16 + [BX] + [SI]
$$

这里可以把 `BX` 理解为一个数据块的基准地址，把 `SI` 理解为相对这个基准的位移量。于是，`BX` 不动，`SI` 每增加 1，实际存储单元就向后移动一个字节；若操作数是字，相应地向后移动两个字节。

例如定义了几个字变量，并把 `BX` 指向其中某个数据单元的偏移地址。要取这个单元的内容送给 `AL`，可以先把 `SI` 清零：

```asm
xor  si, si
mov  al, [bx + si]
```

现在地址就是 `BX + 0 + SI`，也就是原来选定的那个单元。

默认段主要由**基址寄存器**决定。`BX` 是这里的基址寄存器，所以使用 `DS`；即便操作数中还有 `SI`，也不能因为 `SI` 默认属于 `DS` 就去“猜”段——这一步看的是 `BX`。

### 用循环把连续十个字节清零

接下来把问题扩大一点：`BX` 已经指向一个数据块的首地址，要把从这里开始的连续十个字节全部清零。

先把清零用的 `AL` 和当前位移量 `SI` 清零，再设置循环次数：

```asm
xor  al, al
xor  si, si
mov  cx, 10
```

循环体只做三件事：

```asm
next:
    mov  byte ptr [bx + si], al
    inc  si
    loop  next
```

整个程序可以连起来看：

```asm
xor  al, al
xor  si, si
mov  cx, 10
next:
    mov  byte ptr [bx + si], al
    inc  si
    loop  next
```

地址形成过程是：

```text
第 1 次：EA = BX + SI，SI = 0
第 2 次：EA = BX + SI，SI = 1
第 3 次：EA = BX + SI，SI = 2
...
第 10 次：EA = BX + SI，SI = 9
```

`loop` 每执行一次都会让 `CX` 减 1；减到 0 时结束循环。因此，十次循环正好清除 `BX + 0` 到 `BX + 9` 这十个字节。

循环结束后，`SI` 不会莫名其妙地停在最后一个单元上。它已经增加了 10，所以实际地址是：

$$
EA = [BX] + 10
$$

这里的“10”不是 `SI` 中永久写好的值，而是十次 `inc si` 累加出来的结果。实际程序设计中，让 `SI` 自增、让 `BX` 指向数据块起点，再配合循环去访问连续单元，是非常常见的写法。

> **结论**：`BX + SI` 的妙处，不只是两个数相加，而是 `BX` 管“这一块从哪里开始”，`SI` 管“这一次从块中的第几个位置出发”。一个负责定位，一个负责遍历。

### 变址相对寻址：让 SI 带着一个固定偏移量走

只有 `SI` 或 `DI` 参与，再加上一个位移量，就是变址相对寻址：

```asm
mov  al, [si + 4]
```

有效地址为：

$$
EA = [SI] + 4
$$

相对基准还可以换成 `DI`：

$$
EA = [DI] + d
$$

在这种寻址方式中，段地址只看变址寄存器，不看后面的位移量。`SI`、`DI` 对应 `DS`，所以 `SI + 4` 的含义就是 `DS` 段中、以 `SI` 为基准再偏移 4 个字节的单元。

如果把直接符号换成变量，情况就要小心。例如 `D2` 是一个字变量：

```asm
mov  al, D2
```

这里是在把 `D2` 所表示的**内容**直接送入 `AL`；而下面的写法才是在通过 `D2` 找到那个存储单元：

```asm
mov  al, [D2]
```

若想访问它后面的单元，不能把 `D2` 当作可以随指令执行而变化的常量来加：

```asm
mov  al, D2 + 1
```

8086 汇编语法不允许在指令的地址表达式中放一个运行时变量。变量在指令中不能被“算”成操作数或位移量。

> **易错点**：变量名可以直接表示一段数据，也可以借助寄存器间接表示地址，但不能在运行时直接参与指令中位移量的算术。像 `SI + 1` 可以，因为 `SI` 在 8086 的寻址结构中有明确位置；`D2 + 1` 不行，因为 `D2` 只是一个存储单元的符号。

### 基址变址相对寻址：BX、SI 再加一个常量

把三种成分放在一起，就得到基址变址相对寻址：

```asm
mov  al, [bx + si + 4]
```

它的有效地址是：

$$
EA = [BX] + [SI] + d
$$

三部分各司其职：

- `BX` 给出数据块的基准；
- `SI` 给出数据块内的相对位置；
- 位移量 $d$ 再补上一个固定偏移。

例如，仍要清除从 `BX` 所指位置开始的连续十个字节，地址中的常量部分可以写成 `0`：

```asm
xor  al, al
xor  si, si
mov  cx, 10
next:
    mov  byte ptr [bx + si + 0], al
    inc  si
    loop  next
```

地址仍然是 `BX + 0 + SI` 到 `BX + 0 + 9`，结果与前面的 `BX + SI` 完全相同。也可以把常量改成 `1`、`2` 等，只要配合相应的 `SI` 初值，最终仍能落到同一批单元。

**同一条转移数据的指令，不代表只有唯一的地址表达式。** 同一个目标单元，可以用寄存器相对、基址变址、变址相对、基址变址相对或基址相对中的某一种形式找到。实际写程序时，哪一种最容易保持你的思路，就用哪一种；没有必要为了形式统一，强行把所有数据访问都改成同一个样子。

> **注意**：指令系统提供的寻址方式越多，程序访问数据的手段就越灵活。五组常用形式不是互相排斥的“备选项清单”，而是可以服务于同一个目标的多种写法。

### 同一个地址，写法不同，段地址怎样定

到这里，最容易混起来的就是“哪个寄存器决定段”。规则并不复杂，关键是分清**常量位移量**和**变量位移量**。

当位移量是常数时，段地址由基址寄存器决定：

- `BX + d` 使用 `DS`；
- `BP + d` 使用 `SS`；
- `BX + SI + d`、`BP + SI + d` 仍分别由 `BX`、`BP` 决定；
- `SI + d`、`DI + d` 使用 `DS`。

当位移量本身是变量时，情况就不同了。变量要先从它自己所在的段中取出 16 位内容，再参与地址计算，因此应以这个变量所在段为准。

例如 `D2` 定义在数据段中，若指令把它作为位移量使用，就不能再只盯着 `BX` 或 `BP` 默认对应的段；要看 `D2` 的段属性。它所在段的段基址参与计算，`D2` 自己的内容则成为地址的一部分。

可以把地址形成过程画成：

```text
基址寄存器内容 ─┐
                ├─ 相加 ─ 有效地址 EA ─┐
变址寄存器内容 ─┤                        ├─ 段基址 × 16 ─ 物理地址
                │                        │
位移量 d        ┘                        段来自默认约定或变量定义
```

读这张图时，只问两个问题：地址的三个数从哪里来；这个地址属于哪个段。寄存器相对寻址和基址变址寻址中，常量位移量只改变偏移地址，不改变段基址。变量位移量则不然，段地址要跟着变量定义去找。

### 隐含寻址：指令里没写，不代表 CPU 不知道

`push ax` 的指令中只明确写出了 `AX`，可目的操作数在哪里？

CPU 执行时并不会因为指令表面没写目标地址就停下来。它知道每条 `push` 都遵循同一套约定：先让 `SP` 减 2，再把 `AX` 写到 `SS` 指向的新栈顶。于是，这个目的操作数就是由指令本身隐含规定的。

```text
执行前：SP ── 指向原栈顶
             ↓
第一步：SP ← SP - 2
第二步：[SS:SP] ← AX
```

这种“指令中没有写出操作数，但 CPU 仍知道它在哪里”的方式，称为隐含寻址。它与前面按地址形成方式分类的寻址并不冲突：前面解决“明确写出的操作数去哪里找”，隐含寻址解决“某些操作数根本不必写出来”。

`push` 的目的地址就是典型例子。字符串操作指令也属于这一类：指令执行时，源操作数和目的操作数的位置由指令本身规定，不需要再在每条指令中逐一写明。

> **易错点**：操作数没有写在指令字符中，不等于 CPU 不知道它，更不等于操作数不存在。8086 的指令编码本来就允许把某些操作数位置作为固定规则藏起来。

### 段内转移：CS 不变，只要把 IP 算出来

数据操作数讲清楚之后，再看第二大类问题：程序怎样实现转移。

分支程序要转移，循环程序也要转移。所谓转移地址的寻址方式，核心问题只有一个：

> 目的地的偏移地址是多少？这个数最终怎样送进 `IP`？

转移地址又分两大类。程序不离开当前代码段，叫段内转移；从当前代码段跳到另一个代码段，叫段间转移。段内转移时，`CS` 不变，只有 `IP` 改变。因此，只要找到目的地的偏移地址，再把它装入 `IP`，转移就实现了。

```text
段内转移
段基址：CS ─────────────────────── 保持不变
偏移地址：IP ── 改变 ── 目的指令在当前代码段中的偏移

段间转移
CS：改变 ────────────────────── 换到另一个代码段
IP：改变 ────────────────────── 落到新代码段中的目标指令
```

段内转移的第一种方式是直接寻址。假设程序要跳到标号 `L1`：

```asm
jmp  L1

L1:
    ; 转移目的地
```

程序员一开始并不知道 `L1` 的实际地址，所以用标号表示目的地。汇编时，汇编程序会找到 `L1`，再把 `jmp L1` 翻译成 CPU 能执行的形式。

单看这条源程序，似乎是“直接给出了目的地址”；可从汇编后的机器指令看，8086 实际写进去的是**相对位移量**。这个“直接”是从源程序的书写形式说的，“相对”是从 CPU 的执行原理说的。

### 短转移与近转移：汇编程序填进去的不是一个绝对地址

假设 `IP` 顺序执行完这条转移指令后，本来会指向下一条指令。这个位置叫当前 `IP`。转移时，需要从当前 `IP` 再移动一段距离：

$$
IP_{目标} = IP_{当前} + 位移量
$$

位移量可以为正，也可以为负。正数表示向高地址方向转移，负数表示反向转移；负数在指令中用补码表示。

短转移采用 8 位有符号位移量：

```asm
jmp  short  L1
```

`short` 的意思是：以当前 `IP` 为基准，向前不超过 127 个字节，向后不超过 128 个字节。汇编后，位移量占一个字节，指令总共两个字节：

```text
短转移指令
+---------+------------------+
| 1 字节  |     1 字节       |
| 操作码  | 8 位相对位移量   |
+---------+------------------+
```

当前 `IP` 指向的是下一条指令，所以只有操作码已经取出，目标地址的计算是：

$$
IP_{目标} = IP_{当前} + sign\_extend(disp8)
$$

近转移使用 16 位相对位移量：

```asm
jmp  L1
```

```text
近转移指令
+---------+--------------------+
| 1 字节  |       2 字节       |
| 操作码  | 16 位相对位移量    |
+---------+--------------------+
```

对应关系是：

$$
IP_{目标} = IP_{当前} + disp16
$$

16 位有符号位移范围为 $-32768$ 到 $+32767$。汇编后，指令共三个字节；CPU 取出两字节位移量，把它加到当前 `IP` 上，就把 `IP` 改成了目的指令的偏移地址。

> **结论**：段内直接寻址站在汇编语言的书写角度，是把目的标号直接写在指令里；站在 CPU 的执行角度，是给当前 `IP` 加一个 8 位或 16 位相对位移量。因此，有些教材也把同一种方式称为“段内相对寻址”。“直接”说的是写法，“相对”说的是原理。

### 条件转移：范围更窄，越界就搭一座桥

8086 的条件转移指令只能在段内转移，不能完成段间转移。它们的转移范围以当前 `IP` 为基准，只能是：

$$
-128 \sim +127
$$

因此，条件转移指令属于短转移，汇编后由一个字节操作码和一个字节位移量组成。

```asm
jz   L1
```

如果 `L1` 就在这个范围内，`jz` 可以直接跳过去；如果目标距离超出 $-128 \sim +127$，汇编程序会报错，提示转移地址范围超限。汇编器能把两边的距离算出来，所以这种错误在屏幕上非常明确，不需要等程序运行后才暴露。

目标太远而又必须完成转移时，可以在中间搭一个跳转点：

```asm
jz   near_label
jmp  far_label

near_label:
    jmp  far_label
```

条件成立时，先跳到距离当前指令很近的 `near_label`，再由 `JMP` 完成第二段转移。条件不成立时，两次转移都不执行。

> **注意**：所有条件转移指令的寻址方式都受段内相对转移这一套限制。想跳得远，可以借 `JMP` 搭桥，但不能把 `JZ` 本身写出超出一个字节所能表示的范围。

### 段内间接寻址：先取到一个数，再拿它当 IP

段内直接寻址还有一个对照面，就是段内间接寻址。

直接寻址里，目的标号已经写在 `JMP` 后面；间接寻址里，目的偏移地址没有直接出现在指令中，而是先把一个位置找到，再从那个位置取出目标偏移值。

这和前面讲过的寄存器间接寻址是同一个思路。例如方括号中的 `BX` 不再表示“`BX` 寄存器的内容就是目的偏移”，而是：

```text
[BX]
  │
  └─ 表示一个存放目标偏移地址的存储单元
          │
          └─ 取出其中的 16 位值 ── 送入 IP
```

数据寻址中的寄存器间接，是“先找到操作数在哪里，再从那里取数”；转移寻址中的段内间接，则是“先找到目的偏移地址在哪里，再从那里取出新的 `IP`”。前面的知识没有换掉，只是应用对象从普通数据变成了转移目的地。

> **定义**：段内间接寻址，是转移目的地的 `IP` 不直接出现在指令中，而是先通过间接方式取得，再送入 `IP` 的寻址方式。由于 `CS` 不变，取出的只是新代码段内的偏移地址。

### 本讲提到的题目

#### 不破坏 BX 和 SP，把 AX 送到 DX

设 CPU 依次执行：

```asm
push ax
push bx
push cx
```

现在要把原先压入的 `AX` 送到 `DX`，但不能破坏 `BX` 和 `SP`，也不能使用普通的 `pop` 完成取数。

**解析**：`push` 已使 `SP` 连续减小，后入栈的 `CX` 位于栈顶，`AX` 则位于更低的地址。题目要绕开“随 `SP` 取数”的限制，因此应改用 `BP` 相对寻址，让 `BP` 保存一个可用的基准，再从 `SS` 段读取 `AX`。

一种保护 `BP` 和 `SP` 的完整写法是：

```asm
push bp
mov  bp, sp
push ax
push bx
push cx
mov  dx, word ptr [bp - 2]
pop  bp
```

**答案**：`DX` 得到的正是最初压入的 `AX`。`BX` 始终保持原值；结尾的 `pop bp` 恢复原 `BP`，同时使 `SP` 回到题目开始时的值。

#### `JZ` 指令执行后，IP 是多少

设：

- `IP = 0100H`；
- `JZ L1` 中给出的 8 位位移量为 `FDH`；
- 求这条指令执行后的 `IP`。

**解析**：`FDH` 作为 8 位补码表示的相对位移量，其值是 $-3$。`JZ` 是一条双字节指令，所以 CPU 取出操作码和位移量后，当前 `IP` 已经是原地址加 2：

```text
0100H  ── JZ 的操作码
0101H  ── 8 位位移量 FDH
0102H  ── CPU 计算目的 IP 时的当前 IP

0102H + (-3) = 00FFH
```

**答案**：

$$
\boxed{IP = 00FFH}
$$

这题真正考的只有一句话：**条件转移要加的是指令结束后的当前 `IP`，不是这条转移指令自己的起始地址；而补码位移量必须先还原成负数。**

## 段内间接转移与数据传送指令
> 对应块：BLK17 | 覆盖分集：P33-P34 | 块标题（分集名）：《33》

我们先从一个很容易绕进去的问题开始：程序明明已经知道要跳到哪里，为什么不直接跳，还要先把“目的地的偏移地址”从寄存器或内存单元里取出来，再交给 `IP`？

这里的关键不是地址算没算对，而是**CPU 怎样取得这个偏移地址**。偏移地址可以直接放在 `BX` 里，也可以先存进一个内存变量；还可以利用若干目标指令等间隔排列这一事实，直接算出目标地址。把这几条路连起来，后面的查表法和多分支转移就都顺了。

### 段内间接转移：先把目标地址取出来

#### 地址放进 BX，直接交给 IP

假设目的地是 `L2`，可以把 `L2` 的偏移地址送给 `BX`：

```asm
MOV BX, OFFSET L2
JMP BX
```

`JMP BX` 执行时，CPU 把 `BX` 中的 16 位内容送到 `IP`。这个内容不再当普通数据使用，而是**下一条要执行的指令的偏移地址**。`CS` 不变，于是 `CS:IP` 立即指向新的位置，完成一次段内转移。

这里要抓住一个很容易忽略的差别：

```text
BX 中的 16 位数
        │
        └─ 不是普通数据，而是新的 IP
                     │
                     └─ 与原 CS 组成 CS:IP
```

> **结论**：寄存器间接用于转移时，寄存器装的是目的偏移地址；取出的数直接改变 `IP`。

#### 地址放进变量，CPU 再从内存取出

还有一种做法：程序段在 `CS` 段中，目的地偏移地址则作为变量存放在数据段。例如在数据段定义一个字变量 `L2`，再用 `L2` 这个标号找到它：

```asm
L2 DW ?

MOV BX, OFFSET L2
JMP WORD PTR [BX]
```

这一次，过程多了一层：

```text
DS 中的 L2 单元
        │
        │ 按有效地址找到该单元
        ▼
读出一个 16 位字
        │
        │ 这个字不是数据，而是目的偏移地址
        ▼
送给 IP，完成段内转移
```

这里必须分清两个“间接”：

- `BX` 用来寻找保存偏移地址的那个内存单元，这是**找到指针的寻址过程**；
- 内存单元里的字最后被送给 `IP`，这是**段内间接转移的实质**。

即使这个指针变量是用直接寻址方式找到的，也不能因此把整条转移叫作“段内直接转移”。判断重点落在结果从哪里来：目标偏移地址不是直接写在指令里，而是先从内存中取出，再交给 `IP`，所以它仍然是段内间接转移。

> **易错点**：`MOV BX, OFFSET L2` 把偏移地址交给寄存器；`JMP WORD PTR [BX]` 再把这个偏移地址从内存送给 `IP`。两条指令合起来完成转移，但不能只盯着 `MOV` 前面那个 `OFFSET` 就把后半条算成直接转移。

#### 怎样找到保存偏移地址的单元

现在问题又向前推进一步：既然 `[BX]` 中可以放保存目的偏移地址的内存单元地址，那么 `[BX]` 里的那个地址又该怎样得到？

答案仍然回到普通存储器操作数的寻址方法。直接方式可以找到，寄存器相关的方式也可以找到；使用 `BX` 加上位移，或者用基址、变址组合，同样可以定位这个单元。按这里的归纳，共有五种办法可以选择。

不管采用哪一种，处理链条都不变：

1. 先算出保存目的偏移地址的内存单元的有效地址；
2. 从该单元读出一个字；
3. 不把它当普通数据使用，而把它作为转移目的地的偏移地址；
4. 用这个字修改 `IP`。

`[BX]` 只是最常见、最直观的写法。换成基于 `SI` 加位移等方式，得到的仍然可能是“寄存器间接寻址方式下的段内间接转移”。答题时若只问这条指令的寻址方式，写“段内间接寻址”已经抓住了主干；若要求说完整，再指出它以哪个寄存器为基础，以及是否带了位移。

> **结论**：不要把“如何找到指针单元”和“指针单元里装的是什么”混为一谈。前者由普通寻址方法解决，后者决定了这条指令为什么属于段内间接转移。

### 给多个分支搭一座转移桥

#### 顺序判断为什么不够快

接下来换一个更贴近实际的问题。程序里有三个目的地：

- `AL = 1` 时跳到 `L1`；
- `AL = 2` 时跳到 `L2`；
- `AL = 3` 时跳到 `L3`；
- 都不是时，按顺序继续执行。

最直观的办法是依次判断：

```text
判断 AL 是否等于 1？是 → L1，否 → 继续
判断 AL 是否等于 2？是 → L2，否 → 继续
判断 AL 是否等于 3？是 → L3，否 → 继续
```

三个分支时还能看过去。若有二十个分支，就要一路比较到第二十项。越靠后的目标，比较次数越多，效率当然不高。

这里真正想说明的是：**段内间接转移并不只是绕一条路，它能用来搭一座“转移桥”，让多个分支共用同一条转移通道。**

#### 用目标间距直接算位移

这里的例子把几个短转移指令等间隔摆好，并利用它们的长度来计算目标间距。假定相邻目标之间相隔 2 字节，那么 `AL` 分别为 1、2、3 时，所需位移恰好是：

| `AL` | 计算 | 相对位移 |
| --- | --- | ---: |
| 1 | $(1-1)\times 2$ | 0 |
| 2 | $(2-1)\times 2$ | 2 |
| 3 | $(3-1)\times 2$ | 4 |

关键计算可以统一写成：

$$
d=(AL-1)\times 2
$$

再以第一个目标的偏移地址为基准：

$$
BX=\operatorname{OFFSET}(L1)+(AL-1)\times 2
$$

最后通过同一条内存间接转移到达计算出的位置：

```asm
JMP WORD PTR [BX]
```

整个过程可以画成一座桥：

```text
AL 的取值
   │
   ├── 1 ── 计算得到 0 ──┐
   ├── 2 ── 计算得到 2 ──┼── 加上 L1 的基准偏移
   └── 3 ── 计算得到 4 ──┘             │
                                      ▼
                               BX 指向目的指令
                                      │
                                      ▼
                               JMP WORD PTR [BX]
```

先把 `AL` 减一，再乘二；把所得位移加到第一个目标的偏移地址上；最后用 `JMP WORD PTR [BX]` 转到目的位置。这个例子还专门避开对 `AX` 的占用，说明实现时可以选择合适的寄存器来完成中间计算，不必拘泥于某一条固定写法。

> **结论**：当多个目标按固定间距排列时，可以由输入值直接算出目标偏移，不必为每个分支逐次比较。

不管 `AL` 是 1、2、3，还是更多合法值，公共的运算和转移通道都相同。这样做，分支越多，原先“从前到后逐项判断”的负担就被消掉了，执行效率自然提高。

#### 还可以查转移地址表

另一种办法，是把所有目的偏移地址预先放进一张表，让 `AL` 的值决定表中的位置，再从表中取出目标地址。

这两种办法解决的是同一个问题：

- 目标本身等间隔时，用输入值直接算位移；
- 目标地址彼此没有简单规律时，用输入值查表。

所以，段内间接转移在实际的程序设计中并非没有应用场合。今天写的小程序简单，直接转移或相对转移够用了；分支一多、地址排布可以组织时，查表和“转移桥”的价值就显出来了。

### 数据传送类指令的总骨架

讲完转移，接着进入数据传送类指令。书中的表把这一类指令归为七种：

| 类别 | 代表指令 | 核心作用 |
| --- | --- | --- |
| 传送 | `MOV` | 把源操作数的内容送给目的操作数 |
| 取有效地址 | `LEA` | 把操作数的有效地址送给寄存器 |
| 取地址指针 | `LES`、`LDS` | 同时取得偏移地址和段地址 |
| 标志传送 | `LAHF`、`SAHF`、`PUSHF`、`POPF` | 在 `FLAGS`、`AH` 和堆栈之间传送标志 |
| 数据交换 | `XCHG` | 交换两个操作数的内容 |
| 字节转换 | `XLAT` | 按 `AL` 给出的索引查字节表 |
| 堆栈操作 | `PUSH`、`POP` | 在寄存器和内存之间进行堆栈传送 |

这七类看着名称很多，核心却反复围绕三件事：**搬内容、取地址、换内容**。真正写程序时，先看清指令究竟把什么交给谁，再去套操作数格式。

#### 数据传送共有的六条语法规则

数据传送类指令大多同时受下面六条规则约束：

1. 源操作数和目的操作数各司其职，不能随意交换角色。
2. 源与目的的类型必须一致，不能一个按字节处理，另一个按字处理。
3. 操作数的寻址方式必须明确，不能让汇编器猜。
4. 当 `DS`、`ES`、`SS` 作为目的操作数时，源操作数不能是立即数。
5. `CS` 和 `IP` 不能作为传送的目的操作数。
6. 不允许在同一条指令中让两个存储器操作数直接参加传送。

这几条不是零散禁令，而是一条共同思路：**目的位置必须真的能接收，源位置必须真的能提供，而且两边必须按同一种数据宽度解释。** 每写一条 `MOV` 或其他传送指令，都先拿这六条检查一遍，比记零散例外可靠得多。

#### 标志不能一刀切地记

多数纯数据传送指令只搬运数据，不做算术运算，所以不会主动改变六个状态标志。但不能把它粗暴地推广成“所有传送类指令都不影响标志”，因为标志传送类必须单独看。

| 指令 | 实际动作 | 对 `FLAGS` 的影响 |
| --- | --- | --- |
| `LAHF` | 把 `FLAGS` 低 8 位送入 `AH` | 只改 `AH`，不改 `FLAGS` |
| `SAHF` | 把 `AH` 写入 `FLAGS` 低 8 位 | 改变低 8 位标志 |
| `PUSHF` | 把 `FLAGS` 压入堆栈 | 读取标志，不改 `FLAGS` |
| `POPF` | 从堆栈弹出的字送入 `FLAGS` | 直接改变标志 |

8086 没有专门用来随意清零、置位的通用标志传送指令。尤其像 `OF` 这样位于 `FLAGS` 高 8 位的标志，`AH` 根本够不着，不能靠 `SAHF` 处理。只能借规定会影响 `OF` 的运算指令来改变它，例如逻辑运算会清 `OF`。

> **易错点**：“传送类大多不影响标志”不等于“标志传送类全都不影响”。尤其看到 `SAHF`、`POPF` 时，要把“是否写回 `FLAGS`”单独判断。

### 七类数据传送指令各做什么

#### MOV：搬的是内容

`MOV` 的格式很简单：

```asm
MOV DST, SRC
```

它把源操作数指明的内容送入目的操作数。源内容在传送后仍保留在自己的位置，目的位置得到一份内容。它不是为了“拉回”某个值，也不是让源和目的互相顶替；只记住“复制并送过去”这一件事就够了。

`MOV` 是最通用的数据传送指令。只要操作数类型一致、寻址方式合法、用途允许，就可以用它把寄存器、内存单元或立即数中的内容送到另一个目的位置。

#### LEA：取的是地址

`LEA` 的格式是：

```asm
LEA r16, mem
```

目的操作数是一个 16 位寄存器，源操作数采用存储器寻址方式。CPU 按该寻址方式算出有效地址，再把这个地址送给目的寄存器。

例如，`BX` 指向数据段中的 `BETA1`：

```asm
LEA BX, BETA1
```

执行后，`BX` 得到的是 `BETA1` 的有效地址，不是 `BETA1` 单元里存放的数据。

这一点要和按字读取该单元的 `MOV` 分开：

```asm
LEA BX, BETA1             ; BX 得到 BETA1 的有效地址
MOV BX, WORD PTR [BETA1]  ; BX 得到 BETA1 单元中的字
```

一条取“门牌号”，一条取“房间里放的东西”，结果当然不能混。

承载地址时，目的寄存器应选 16 位寄存器，并优先使用适合保存地址的通用寄存器，不要使用段寄存器或 `IP`。

源程序里若只是要表达某个标号对应的地址常量，可以直接用 `OFFSET` 表达式；需要由 CPU 根据某种存储器寻址方式算出有效地址时，则使用 `LEA`。两者都能得到地址，但一个偏向源程序中的地址表达，一个明确要求 CPU 执行地址计算。

#### LES 与 LDS：取回完整指针

取地址指针的指令有两条：

```asm
LES r16, mem32
LDS r16, mem32
```

`mem32` 指向一个 32 位指针，其内存布局是：

```text
低地址
  ├── 第一个字：所指向对象的 16 位偏移地址
  └── 第二个字：所指向对象的 16 位段地址
高地址
```

执行后：

- `LES` 把第一个字送入指定的 16 位通用寄存器，把第二个字送入 `ES`；
- `LDS` 把第一个字送入指定的 16 位通用寄存器，把第二个字送入 `DS`。

例如，一个双字指针单元中保存了变量 `X` 的偏移地址和段地址。`LES` 装入指针后，通用寄存器里就有了 `X` 的偏移地址，`ES` 里就有了 `X` 的段地址，再按这个地址就能找到 `X` 的内容。

这组指令不常用，但一定要理解它们取回的不是对象本身，而是对象的完整地址。偏移地址负责单元在段内的位置，段地址负责先选中哪一个段；两半拼起来，才是一个完整指针。

#### 标志传送：搬运的就是标志本身

`LAHF` 的名字可以把 `F` 理解成 `FLAGS`：它从 16 位的 `FLAGS` 中取出低 8 位，送入 8 位的 `AH`。

`SAHF` 方向相反：把 `AH` 中的 8 位内容写入 `FLAGS` 的低 8 位。

`PUSHF` 与 `POPF` 则借助堆栈：

- `PUSHF` 把 `FLAGS` 压入堆栈；
- `POPF` 从堆栈弹出一个字并送入 `FLAGS`。

所以要分别记住方向：寄存器到 `AH` 是 `LAHF`，`AH` 回写标志是 `SAHF`；`FLAGS` 进堆栈是 `PUSHF`，堆栈回填标志是 `POPF`。

#### XCHG：把两个位置的内容对调

`XCHG` 的作用不是简单复制，而是交换：

```asm
XCHG DST, SRC
```

执行以后，目的操作数和源操作数各自拿到对方原来的内容。例如：

```asm
XCHG AX, BX
XCHG AL, [BX+3]
XCHG DH, BL
```

`AX` 参与交换时，还要留意汇编器采用的紧凑编码形式。功能没有变，仍是两个字互换，但指令机器码可能更短。

交换指令除遵守前面六条通用规则外，还多了自己的限制：

- 两个操作数都不能是立即数，因为立即数没有可供交换的存放位置；
- 不能让两个存储器操作数直接交换；
- 段寄存器不能参加这种交换；
- 两个操作数必须按相同类型处理，不能交换一个字和半个字。

> **结论**：`XCHG` 比普通传送多了一条“源与目的不能同为存储器”的限制。只要坚持“交换发生在两个真实可写的操作位置之间”，语法就不会写错。

#### XLAT：把索引变成另一个字节

8086 的字节转换指令写作 `XLAT`，也可以写成 `XLATB`。它没有显式操作数，固定使用 `AL` 作索引、`BX` 作表的基准：

$$
AL \leftarrow DS:[BX+AL]
$$

整个过程是查表转换：

```text
             BX 指向转换表
                    │
AL 保存源字节 ──────►│  相加形成表内偏移
                    │
                    ▼
             取出对应字节
                    │
                    ▼
              写回 AL
```

例如，表中安排数字字符 `0` 到 `9` 的编码分别与字母字符对应，并让某个表项把数字 `4` 映射为字符 `'4'`。先把转换表的起始偏移地址送入 `BX`，再让 `AL = 4`，执行：

```asm
LEA BX, TABLE
MOV AL, 4
XLAT
```

执行后，`AL` 不再是数值 `4`，而是转换后的字符编码；表内若存的是 `34H`，结果就是 `AL = 34H`。

这类表还可以把更多数值关系预先排好。若要完成“四字符数字到对应字符”的转换，只要这个“四”是前面某个运算的结果，就把结果放入 `AL`，让转换表负责后面的对应关系。

`XLAT` 的价值正在于**把规则的查找交给表**。凡是需要按一串离散编码做对应转换的地方，都应该马上想到查表法。指令名称虽然叫“字节转换”，本质却是以 `BX` 为基准、以 `AL` 为索引的一次查表。

#### PUSH 与 POP：按栈的方式存取

堆栈操作常见的是 `PUSH` 和 `POP`；`PUSHF` 与 `POPF` 则利用同样的方式传送 `FLAGS`。

`PUSH` 把一个 16 位操作数压入堆栈，`POP` 把堆栈顶部的 16 位内容弹出并送入目的操作数。它们的操作数必须是 16 位寄存器或 16 位存储器，不能使用立即数，也不能按字节处理。

所以，像 `1234H` 这样的数值不能直接写进 `PUSH` 或 `POP` 的操作数位置。它只是一个数值，还没有对应的寄存器或内存位置。要让程序明确表示压入或取出哪个位置，就必须给出合法的 16 位寄存器或存储器操作数。

除这条特殊规则外，它们仍要遵守数据传送类的共同语法规则。看到堆栈指令时，最先检查三件事：**是不是字操作、是不是寄存器或内存、有没有误塞立即数。**

### 别只停在会解释指令

这一段里真正容易忘掉的，不是某一条指令的格式，而是它们在程序里的位置：`LEA` 用在需要有效地址的地方，查表法用在一组离散编码的对应转换中，段内间接转移用在多分支需要提高效率的地方，`XCHG` 和 `PUSH`、`POP` 则解决寄存器之间的倒换与暂存。

但光学书、本子记几条结论，不等于真的会写程序。围绕这门课安排的实验课要做，课外还要留出时间做大量实践活动。尤其 `LEA`、`XLAT` 和转移桥这类技巧，不亲手写过一遭，很容易只会用自己的话解释，看到代码还是认不出来。

## 算术运算指令：结果、状态标志与条件分支
> 对应块：BLK18 | 覆盖分集：P35-P36 | 块标题（分集名）：《35》

前面把 8086 的传送类指令讲完了，接下来进入算术运算类。加法、减法、乘法和除法，以及 BCD 调整指令，都归在这一类里。现在先把加法和减法这条线走通。

学这一类指令，先别急着背助记符。一定要抓住两条规矩：

- **CPU 执行运算指令后，会根据运算结果影响六个状态标志，或者影响其中的某些标志。**
- **段寄存器不能参加算术运算。**

这两条不只适用于加法和减法，后面讲逻辑运算时也一样。运算结果本身可以从目的操作数中读出来，状态标志则把“结果等于零还是非零”“是否发生进位或借位”“有没有溢出”等信息留下来，供条件转移使用。

六个常用状态标志可以这样理解：

| 标志 | 含义 |
| --- | --- |
| `CF` | 无符号运算的进位或借位信息 |
| `ZF` | 结果为零时为 `1`，非零时为 `0` |
| `SF` | 结果最高位为 `1` 时为 `1` |
| `PF` | 结果低八位中 `1` 的个数为偶数时为 `1` |
| `OF` | 有符号运算发生溢出时为 `1` |
| `AF` | 半字节进位或借位信息，主要供 BCD 调整使用 |

> **提示**：不要把“CPU 会设置六个状态标志”理解成六个标志每次都会变成 `1`。它说的是这六个标志都会依据本次结果被更新，而每个标志最终取 `0` 还是 `1`，要看实际运算结果。

### 加法指令：ADD、ADC 与 INC

8086 中与普通加法直接相关的指令有三条：`ADD` 做不带进位加法，`ADC` 做带进位加法，`INC` 把一个操作数加一。它们用途相近，但参与运算的数和受影响的标志并不完全一样。

#### ADD：把两个操作数直接相加

`ADD` 是双操作数指令，功能可以写成：

$$
\text{DEST} \leftarrow \text{DEST} + \text{SRC}
$$

目的操作数和源操作数的内容相加，结果送回目的操作数原来的位置。目的操作数不能是立即数，因为它不仅要作为输入，还要接收结果。

`ADD` 完成后，`CF`、`ZF`、`SF`、`PF`、`OF` 和 `AF` 六个状态标志都会根据结果更新。这里一定要记住：算出来的“和”不只保存在目的操作数中，CPU 还会同时把判断这个“和”所需的信息写入状态标志。

#### ADC：把上一级进位一起加进来

`ADC` 也是双操作数指令，不过它比普通加法多算一个进位标志：

$$
\text{DEST} \leftarrow \text{DEST} + \text{SRC} + CF
$$

也就是说，目的操作数、源操作数和原来的 `CF` 三者相加，结果仍送回目的操作数，并根据最终结果更新六个状态标志。

为什么需要 `ADC`？一个 8 位数不够表示结果时，可以把更大的数拆成若干个字，从低位向高位逐字相加。低位产生的进位不是丢掉，而是由 `ADC` 接到高位的运算中。没有 `ADC`，多字加法在低位产生进位后就会断掉。

#### INC：只给一个操作数加一

`INC` 是单操作数指令：

```asm
INC DEST
```

它把目的操作数中的内容加一，再把结果送回同一位置。目的操作数可以是寄存器，也可以是存储器单元，但不能是立即数。

`INC` 会根据结果更新除 `CF` 以外的五个状态标志，也就是 `ZF`、`SF`、`PF`、`OF` 和 `AF`。**`CF` 保持原值不变。**

“保持原值不变”不是把 `CF` 清零。如果执行前 `CF=1`，执行后仍然是 `1`；如果执行前 `CF=0`，执行后仍然是 `0`。这一点在后面的 `DEC` 以及条件转移中还会再遇到。

### 双字相加：低位先算，再让进位接上

假设存储器中从低地址开始连续存放两个双字变量 `A` 和 `B`，每个变量占 4 个字节，共 8 个字节：

```asm
VAR_A    DD 00127654H
VAR_B    DD 00049821H
VAR_C    DD ?
```

要求计算 `C=A+B`，结果 `C` 也要占 4 个字节；如果还要保留整个双字运算最终产生的最高位进位，还要另设一个单元接收它。

8086 在存储器中按低地址、高地址依次存放一个字的低字节和高字节，因此这 8 个字节可以按下面的偏移理解：

| 偏移 | 内容 | 读出的字 |
| --- | --- | --- |
| `0` | `A` 的低字节 | `7654H` |
| `2` | `A` 的高字节 | `0012H` |
| `4` | `B` 的低字节 | `9821H` |
| `6` | `B` 的高字节 | `0004H` |

低地址放的是各双字的低字，所以先算低字，再算高字。我们先用 `SI` 取 `VAR_A` 的有效地址，也就是它的偏移地址，然后用存储器寻址访问连续的字：

```asm
; 数据段中定义变量
VAR_A    DD 00127654H
VAR_B    DD 00049821H
VAR_C    DD ?

; 代码段中的运算片段
        LEA     SI, VAR_A

        MOV     AX, [SI]
        ADD     AX, [SI+4]
        MOV     WORD PTR [VAR_C], AX

        MOV     AX, [SI+2]
        ADC     AX, [SI+6]
        MOV     WORD PTR [VAR_C+2], AX
```

先看低字。`[SI]` 读出 `A` 的低字 `7654H`，`[SI+4]` 读出 `B` 的低字 `9821H`，所以：

$$
7654H + 9821H = 0E75H
$$

同时最高位产生了进位，因而 `CF=1`。这个低字结果送入 `VAR_C` 的低字位置。

这里有一个很容易搞错的地方：`VAR_C` 是用 `DD` 定义的双字变量，而 `AX` 只有 16 位。若直接写：

```asm
MOV VAR_C, AX
```

就与“把双字存储器变量和 16 位寄存器配对”发生冲突。必须明确告诉汇编程序，这次只处理其中的一个字，也就是使用 `WORD PTR`。

再看高字。`[SI+2]` 读出 `A` 的高字 `0012H`，`[SI+6]` 读出 `B` 的高字 `0004H`。此时不能再用普通 `ADD`，因为低字已经产生了进位，所以使用 `ADC`：

$$
0012H + 0004H + 1 = 0017H
$$

把 `0017H` 写入 `VAR_C` 的高字位置，最终得到：

```text
VAR_C = 00170E75H
```

这段程序把 `SI` 保持在 `VAR_A` 的起始偏移，再用 `[SI]`、`[SI+2]`、`[SI+4]` 和 `[SI+6]` 访问各个字。换成其他能够找到这些单元的存储器寻址方式也可以解题，不一定非要用这种写法。

> **注意**：这里只给出了题目所需的数据定义和代码段中的运算片段，不是完整的 8086 汇编程序。数据段、代码段以及程序结束部分还没有展开，不能把这段片段直接当成一个完整可执行程序。

### 减法指令：SUB、SBB 与 DEC

与加法对应，8086 中继续看 `SUB`、`SBB` 和 `DEC`。它们的共同点是从目的操作数中减去源操作数，区别在于是否把借位算进去，以及是否只做减一。

一对操作数必须采用一致的操作类型。只要一方的类型明确，另一方的类型也就随之确定，不能把不同宽度的操作数随意配在一起。

#### SUB：不带借位减法

`SUB` 的功能是：

$$
\text{DEST} \leftarrow \text{DEST} - \text{SRC}
$$

它用目的操作数指明的内容减去源操作数指明的内容，把差送回目的操作数原来的位置，并根据差更新六个状态标志。它与不带进位的 `ADD` 正好对应。

#### SBB：把借位一起减掉

`SBB` 比 `SUB` 多减一个 `CF`：

$$
\text{DEST} \leftarrow \text{DEST} - \text{SRC} - CF
$$

也就是目的操作数减去源操作数，再减去原来的借位标志，结果送回目的操作数，并更新六个状态标志。

`SBB` 的用途与 `ADC` 对应：多字减法从低位向高位进行时，如果低位向高位借了 `1`，高位必须把这个借位继续算进去，否则整个多字结果就会错。

#### DEC：只给一个操作数减一

`DEC` 是单操作数指令：

```asm
DEC DEST
```

它把目的操作数减一，差送回原位置。目的操作数同样不能是立即数。

`DEC` 与 `INC` 的标志规则正好对应：它根据结果更新除 `CF` 以外的五个状态标志，`CF` 保持原值不变。

### INC 与 DEC 的进位标志陷阱

有一道考试题专门考过这个问题：假设 `AL=FFH`，而且执行前 `CF=0`，CPU 执行 `INC AL` 后，`AL` 和 `CF` 分别是什么？

这道题不用打草稿，一打草稿反而容易把 `CF` 想复杂。`AL` 原来全是 `1`，加一后只能留下 `00H`，所以 `AL=00H`；结果为零，因此 `ZF=1`。但 `INC` 明明不影响 `CF`，所以 `CF` 仍然等于执行前的 `0`。

最容易犯的错误，是看到“全 `1` 加一”就顺手把 `CF` 写成 `1`。可 `INC` 的规定不是“根据进位更新 `CF`”，而是**保留 `CF` 的原值**。`DEC` 也是如此。看到“没影响”，就直接想成“清零”，同样是错的。

### CMP：只留下差产生的条件

`CMP` 是比较指令，功能上相当于做一次减法：

$$
\text{DEST} - \text{SRC}
$$

但它与 `SUB` 有一个关键区别：**差算出来以后不送回目的操作数，也不改变参与比较的原始数据。** 比较结果只通过六个状态标志留下来。

所以，`CMP` 很适合在分支程序中产生条件。比如要比较两个数谁大、谁小或是否相等，最自然的想法就是先执行一次 `CMP`，再让条件转移指令检查相应标志。`ADD`、`SUB` 等算术指令也能产生某些条件，只是使用算术指令会覆盖目的操作数；如果原数据还要保留，通常就不如 `CMP` 合适。

比较、产生条件、测试条件、决定走向，完整关系是这样的：

```text
 alpha, beta
      |
      v
 CMP or arithmetic
      |
      v
 status flags
      |
      v
 test Jcc condition
      |
  +---+---+
  |       |
 true    false
  |       |
 path A path B
```

读图可以看出，`CMP` 本身不负责跳到哪条路径，它只把运算结果变成标志；后面的条件转移指令才负责测试这些标志，并把程序引向不同的代码位置。

### 单个标志怎样变成条件转移

一次 `CMP` 会更新六个状态标志。`AF` 主要用于 BCD 调整，不作为这里讨论的直接比较条件；其余五个标志都可以单独对应一组条件转移指令。

| 被测标志 | 条件成立时的含义 | 条件转移指令 |
| --- | --- | --- |
| `CF=1` | 有进位或借位 | `JB` / `JC` |
| `CF=0` | 无进位或借位 | `JAE` / `JNC` |
| `SF=1` | 结果为负 | `JS` |
| `SF=0` | 结果不为负 | `JNS` |
| `ZF=1` | 结果为零 | `JZ` / `JE` |
| `ZF=0` | 结果不为零 | `JNZ` / `JNE` |
| `PF=1` | 结果低八位中 `1` 的个数为偶数 | `JPE` |
| `PF=0` | 结果低八位中 `1` 的个数为奇数 | `JPO` |
| `OF=1` | 有符号结果发生溢出 | `JO` |
| `OF=0` | 有符号结果未发生溢出 | `JNO` |

在 8086 汇编语言里，两数相等通常用助记符中的 `E` 表示，所以 `JZ` 也可以写成 `JE`；汇编后得到的指令是一样的。表示两数不相等时，`JNZ` 可以写成 `JNE`。

这些 `Jcc` 指令后面不直接写一个裸地址，而是写目的地的标号。标号放在目标代码处，指令通过标号找到要转移过去的位置。

### 无符号比较：把 A、B 和 E 记清楚

做比较时，目的操作数与源操作数的顺序一定要看清。若写：

```asm
CMP ALPHA, BETA
```

CPU 做的实际运算是 `ALPHA-BETA`，不是先减绝对值来判断大小。对无符号数来说，两个结果之间有相等与不相等的关系；不相等时，存在“哪个高、哪个低”的关系。

| 关系 | 标志条件 | 常用转移指令 |
| --- | --- | --- |
| `ALPHA=BETA` | `ZF=1` | `JE` / `JZ` |
| `ALPHA≠BETA` | `ZF=0` | `JNE` / `JNZ` |
| `ALPHA<BETA` | `CF=1` | `JB` / `JC` |
| `ALPHA≥BETA` | `CF=0` | `JAE` / `JNC` |
| `ALPHA>BETA` | `CF=0` 且 `ZF=0` | `JA` / `JNBE` |
| `ALPHA≤BETA` | `CF=1` 或 `ZF=1` | `JBE` / `JNA` |

为什么 `JB` 的含义是 `ALPHA` 小于 `BETA`？因为 `ALPHA` 减 `BETA` 时如果发生无符号借位，说明原来的 `ALPHA` 装不下这个减法，只能从更小的 `BETA` 那边借。此时 `CF=1`，条件成立，CPU 就转到“低于”路径。

助记符中的字母也正好帮忙记忆：

- `A` 表示高于或不低于，`B` 表示低于，`E` 表示等于，`NE` 表示不等于。
- `JB` 表示低于，`JAE` 表示高于或等于，这两个条件互为反面。
- `JBE` 表示低于或等于，正好是 `JA` 的反面。

不要把“无符号比较”写成数学上绝对值式的“谁大谁小”。对无符号数，助记符强调的是高低关系；对有符号数，才使用大于、小于这套关系。

### 有符号比较：不能只看 CF

如果 `ALPHA` 和 `BETA` 是有符号数，比较顺序仍然是：

```asm
CMP ALPHA, BETA
```

`ALPHA=BETA` 和 `ALPHA≠BETA` 的判断没有变，分别仍看 `ZF=1` 和 `ZF=0`。但判断谁大、谁小时，不能直接沿用无符号数的 `A`、`B` 那套规则，而要用 `G`、`L`：

| 关系 | 标志条件 | 常用转移指令 |
| --- | --- | --- |
| `ALPHA< BETA` | `SF≠OF` | `JL` / `JNGE` |
| `ALPHA≤BETA` | `ZF=1` 或 `SF≠OF` | `JLE` / `JNG` |
| `ALPHA>BETA` | `ZF=0` 且 `SF=OF` | `JG` / `JNLE` |
| `ALPHA≥BETA` | `SF=OF` | `JGE` / `JNL` |

`JL` 为什么不能只看 `CF`？因为对有符号数，执行 `ALPHA-BETA` 后，判断结果是否小于零，要同时考虑结果符号 `SF` 和溢出 `OF`：

- `SF=0` 且 `OF=0`：没有负数，也没有溢出，结果为非负；
- `SF=1` 且 `OF=1`：结果为负，但发生了溢出，真实大小关系不能按表面结果判断；
- `SF≠OF`：结果符号受溢出影响，实际结果是小于。

所以 `JL` 的条件是 `SF⊕OF=1`。从助记符含义看，`JL` 是“小于则转移”；从 CPU 的执行原理看，它实际检查的是 `SF` 和 `OF` 的组合，不是直接比较两个数。

> **易错点**：设计分支程序时，第一步不是先挑 `Jcc`，而是先认清参加比较的数究竟是无符号数还是有符号数。无符号数用 `A`、`B` 体系，有符号数用 `G`、`L` 体系，不能混用。

### 条件转移也有范围

这些条件转移指令都是段内短转移，以当前 `IP` 为基准，负向转移不能超过 `-128` 个字节，正向转移不能超过 `+127` 个字节。

如果目标位置超出了这个范围，条件转移本身无法直接跳到那里，就得想办法借助无条件转移指令过渡。它们都属于段内直接寻址或段内相对寻址，不涉及段间跳转。

### NEG：求操作数的相反数

`NEG` 是单操作数的取负指令，功能是：

$$
\text{DEST} \leftarrow 0-\text{DEST}
$$

运算得到的差仍送回目的操作数，并根据结果更新六个状态标志。

为什么它能取相反数？因为 `0` 减去一个非零二进制数，得到的就是它按补码表示的相反数：

- 原来如果是负数，`0` 减去这个负数，得到对应的正数；
- 原来如果是正数，得到对应负数的补码；
- 原来如果是 `0`，结果仍是 `0`。

所以 `NEG` 适合处理“求相反数”这类场合，而不是简单地再做一次普通减法。

### 本讲提到的题目

#### 双字加法题

在存储器变量 `VAR_A` 开始的连续 8 个字节中，依次存放两个双字数 `A` 和 `B`，每个数占 4 字节。`VAR_A` 的值为 `00127654H`，`VAR_B` 的值为 `00049821H`。另定义双字变量 `VAR_C`，编写程序计算 `C=A+B`。

**答案与解析：**先读两个数的低字，用 `ADD` 得到 `0E75H`；该次运算产生进位。再读两个数的高字，用 `ADC` 把这个进位一起加上，得到高字 `0017H`。最终 `VAR_C=00170E75H`。前面的“双字相加”一节给出了完整的数据定义和代码段运算片段。

#### INC 与 CF 的填空题

执行前 `AL=FFH`、`CF=0`。CPU 执行 `INC AL` 后，`AL` 和 `CF` 分别等于什么？

**答案与解析：**`AL=00H`，`CF=0`，同时 `ZF=1`。`AL` 是 8 位寄存器，`FFH+1` 的低 8 位结果是 `00H`；但 `INC` 不影响 `CF`，所以它保持执行前的 `0`，不能因为发生了“全 `1` 加一”就擅自把 `CF` 写成 `1`。

## 从绝对值到 BCD 转换：8086 算术指令与程序设计
> 对应块：BLK19 | 覆盖分集：P37-P38 | 块标题（分集名）：《37》

先把一道题拿出来：存储器单元 `BUFF` 中有一个 16 位带符号数 $x$，要求求出它的绝对值，并把结果放回原单元。

这道题看上去只是“加个负号”，真正要练的却不是某一条指令，而是完整的程序设计思路。我们怎样判断 $x$ 的正负？怎样把这个判断画成程序流程？算法怎样落到 8086 指令上？数据又该怎样定义？把这些环节连起来，我们才算真正踏进 8086 汇编语言程序设计。

而且，后面乘除法指令的规则非常容易混淆。我们不急着背指令表，先沿着这道题把程序设计的三步走稳，再用同一套办法分析 BCD 转换。

### 先从绝对值题走进程序设计

#### 编程思想先于指令

`BUFF` 中存放的是 16 位带符号数，因此在数据段里要用字变量来定义它。题目的核心算法只有两种情况：

$$
|x|=
\begin{cases}
x, & x\geq 0\\
-x, & x<0
\end{cases}
$$

先别急着翻指令表。程序设计的第一步，是把解决问题的方法想清楚，这里要提出来的思路就是“判断 $x$ 的正负”：当 $x\geq 0$ 时，结果仍是 $x$ 本身；当 $x<0$ 时，要得到 $-x$。

要得到一个数的相反数，只需要做一次减法，也就是用 $0$ 减去 $x$。因此，第二种情况下必须完成“求负”这个操作。到这里，算法已经有了；它还不是代码，却是代码必须遵循的编程思想。

这里要形成一个很牢的习惯：**先分析题目，再提出解决方法，最后才选择指令。** 如果一上来就盯着助记符，很容易只记住几条零散指令，却不知道它们为什么这样连接。

#### 用流程图把判断固定下来

有了算法，第二步是把程序流程画出来。标准程序设计流程图中，开始框和结束框用椭圆，判断框用菱形，运算或数据处理框用矩形。

这道题只需要判断一次符号：

```text
             ╭──────────╮
             │   开始   │
             ╰──────────╯
                  │
                  ▼
         ┌──────────────────┐
         │  MOV AX, BUFF    │
         └──────────────────┘
                  │
                  ▼
         ┌──────────────────┐
         │   CMP AX, 0      │
         └──────────────────┘
                  │
                  ▼
              ◇ SF = 0? ◇
              ╱         ╲
            是           否
            │             │
            │       ┌──────────────────┐
       ╭───────╮      │     NEG AX      │
       │  结束 │      └──────────────────┘
       ╰───────╯              │
                             ▼
                      ┌──────────────────┐
                      │ MOV BUFF, AX     │
                      └──────────────────┘
                             │
                             └───────────→ 结束
```

读图时要抓住两件事。第一，`CMP AX, 0` 做的是一次比较，相当于在内部计算 `AX - 0`，并根据结果设置状态标志。第二，我们只关心结果是否为负，所以接下来判断 `SF`：`SF=0` 表示结果非负，`SF=1` 表示结果为负。条件转移指令就是用来测试条件的。

如果一张纸放不下，要用连接符把流程接起来。连接符通常画成带字母的小圆圈，比如一侧标 `A`，另一侧也标 `A`，表示两处属于同一个连接点。连接符不是可有可无的装饰，而是保证流程图跨区域仍然连续。

> **易错点**：开始和结束不是普通矩形。标准流程图中，开始框、结束框用椭圆；只有运算或处理步骤才用矩形。

#### 把算法换成 8086 指令

`BUFF` 是数据段中的一个 16 位带符号数变量，题目只说明其中存放的初始值未知，所以用问号保留：

```asm
; 数据段中的变量定义片段
BUFF    DW      ?
```

代码段中，用到的功能片段如下：

```asm
        MOV     AX, BUFF
        CMP     AX, 0
        JNS     DONE
        NEG     AX
        MOV     BUFF, AX
DONE:
```

这几条指令与前面的流程一一对应。

先用直接寻址把 `BUFF` 中的 16 位数送入 `AX`。`CMP AX, 0` 比较它与零，得到的条件由标志位承载。`JNS` 在 `SF=0` 时转移，也就是原数非负时直接到达 `DONE`。为什么可以直接结束？因为原数已经在 `BUFF` 中，非负数的绝对值就是它自己，不必再写回去。

只有当原数为负时，程序才不跳转。`NEG AX` 执行 $0-AX$，得到 $-x$；再执行 `MOV BUFF, AX`，把绝对值写回原单元。这样，无论输入是正数、零还是负数，执行结束后 `BUFF` 中都保存 $|x|$。

> **提示**：这里的 `CMP` 不保存相减结果，它只负责设置状态标志。真正产生 $-x$ 的是后面的 `NEG AX`。把“比较”和“求负”混成一件事，程序逻辑就会乱掉。

> **注意**：这里展示的是完成题目功能的数据定义和代码片段，不是已经装配好段结构、设置数据段和退出过程的完整程序。现在先把核心功能写对，完整的程序外壳等相应内容讲过后再补。

### 乘法指令：原操作数宽度决定操作类型

减法指令讲完，算术运算的下一类就是乘法和除法。实际程序设计中，乘除法远不如加法、减法用得多，有些程序甚至一次都用不上，但必须掌握它们的工作规律。

先记住最容易错的一句：**`MUL` 不是“天生就做字乘法”，`IMUL` 也不是只接收某种固定宽度。乘法类型先分无符号与有符号，操作宽度再由原操作数的类型决定。**

无符号乘法用 `MUL`，有符号乘法用 `IMUL`。指令中显式给出的原操作数就是乘数，而被乘数隐含在累加器中。显式操作数可以是寄存器，也可以通过某种存储器寻址方式指出一个操作数，但不能使用立即数。

#### 无符号乘法 MUL

做 8 位无符号乘法时，被乘数隐含在 `AL` 中，指令给出的原操作数也是 8 位。CPU 把二者相乘，完整的 16 位乘积放在 `AX` 中，其中 `AH` 放高 8 位，`AL` 放低 8 位。

```text
AL 中的 8 位被乘数  ×  8 位原操作数  →  AX

                                    AH：高 8 位
                                    AL：低 8 位
```

做 16 位无符号乘法时，被乘数隐含在 `AX` 中，原操作数给出另一个 16 位数。完整乘积有 32 位，不能只放进一个 16 位寄存器，于是高 16 位进入 `DX`，低 16 位留在 `AX`：

```text
AX 中的 16 位被乘数  ×  16 位原操作数  →  DX:AX

                                                  高 16 位在 DX
                                                  低 16 位在 AX
```

因此，无符号乘法只有两种基本规格：8 位乘 8 位得到 `AX`，16 位乘 16 位得到 `DX:AX`。`MUL` 后怎样判断完整乘积是否装得下？对 8 位乘法看 `AH`，对 16 位乘法看 `DX`。

若 `AH` 或 `DX` 中确实有超出低半部分的有效数据，`CF` 和 `OF` 都会置 1，表示高位部分不能丢掉；相应高位为 0 时，`CF` 和 `OF` 都为 0。

#### 有符号乘法 IMUL

有符号乘法用 `IMUL`。被乘数和乘数都按带符号数解释，存放位置仍由操作宽度决定。

8 位 `IMUL` 仍把 `AL` 作为隐含被乘数，把 16 位结果放在 `AX`。但判断高位是否为“多余数据”的方法变了：不能只看 `AH` 是否等于 0，而要看 `AH` 是否恰好是 `AL` 的符号扩展。

若 `AL` 为正，符号扩展要求 `AH` 全为 0；若 `AL` 为负，符号扩展要求 `AH` 全为 1。比如 8 位数的 `-1` 用补码表示为 `FFH`，扩展到 16 位时，低 8 位是 `FFH`，高 8 位也应由 1 扩展为 `FFH`。所以，“高位全为 1”并不等于高位藏着另一个有效乘积，它也可能只是符号扩展。

16 位 `IMUL` 把 `AX` 作为隐含被乘数，完整结果放在 `DX:AX`。此时不能简单要求 `DX=0`；若结果为正，`DX` 可以全为 0，若结果为负，`DX` 可以全为 1。只有当 `DX` 正好是 `AX` 的符号扩展时，才说明它没有额外的有效高位。

`IMUL` 后同样通过 `CF`、`OF` 判断：高位与低半部分符号扩展一致时，两者都为 0；出现额外有效高位时，两者都为 1。

> **易错点**：无符号乘法看“高半部分是不是 0”，有符号乘法看“高半部分是不是低半部分的符号扩展”。这两种判断不能互换。

#### 乘积放不下时，标志位在报警

把四种情况放在一起，隐含操作数和结果位置就更清楚了：

| 类别 | 被乘数及位置 | 显式乘数 | 完整乘积 | `CF=0` 且 `OF=0` 的条件 |
| :--- | :--- | :--- | :--- | :--- |
| 8 位无符号乘法 | `AL` | 8 位原操作数 | `AX` | `AH=0` |
| 16 位无符号乘法 | `AX` | 16 位原操作数 | `DX:AX` | `DX=0` |
| 8 位有符号乘法 | `AL` | 8 位原操作数 | `AX` | `AH` 是 `AL` 的符号扩展 |
| 16 位有符号乘法 | `AX` | 16 位原操作数 | `DX:AX` | `DX` 是 `AX` 的符号扩展 |

`MUL` 和 `IMUL` 执行后，能够确定的是 `CF`、`OF` 两个状态标志，其余状态标志没有定义。

> **定义**：“没有影响”表示该标志在指令执行前后保持原值；“没有定义”表示执行后的状态不确定，不能拿来判断结果。这两种说法不是一回事。

所以，看到乘法的 `CF` 和 `OF` 同时为 1，就不能把高位部分扔掉，必须把完整乘积保留下来。

### 除法指令：商和余数各有位置

#### 无符号除法 DIV

无符号除法用 `DIV`。它和乘法的思路相似：被除数隐含，除数由原操作数给出，操作类型仍由原操作数宽度决定。

做 8 位无符号除法时，16 位被除数放在 `AX` 中，8 位原操作数是除数。CPU 用 `AX` 除以这个 8 位除数，商放入 `AL`，余数放入 `AH`。

```text
             AX：16 位被除数
                      │
                      ▼
             除以 8 位原操作数
                 ┌────┴────┐
                 ▼         ▼
              AL：商      AH：余数
```

做 16 位无符号除法时，被除数需要 32 位：高 16 位放在 `DX`，低 16 位放在 `AX`，两者合起来构成被除数。原操作数给出 16 位除数。相除后，16 位商放入 `AX`，16 位余数放入 `DX`。

```text
DX:AX：32 位被除数
              │
              ▼
       除以 16 位原操作数
          ┌────┴────┐
          ▼         ▼
       AX：商      DX：余数
```

这里一定要分清三个位置：做 8 位除法前，被除数从 `AX` 读取；做完以后，商回到 `AL`，余数进入 `AH`。`AX` 在执行前后承担的角色不同，不能把相除前后的内容混在一起。

除数不能为 0，所以要把除数先送入寄存器。这里用 `CL` 保存 10，正是为了让 `DIV CL` 有一个合法的 8 位原操作数。

#### 有符号除法 IDIV 与余数符号

有符号除法用 `IDIV`，操作数仍分为 8 位和 16 位两种。被除数、商和余数所处的寄存器位置与 `DIV` 相同，区别在于运算按带符号数进行。

把正负组合列开，商的符号由被除数与除数共同决定；余数非零时，其符号与被除数一致：

| 被除数 | 除数 | 商 | 余数 |
| :--- | :--- | :--- | :--- |
| 正 | 正 | 正 | 正 |
| 正 | 负 | 负 | 正 |
| 负 | 正 | 负 | 负 |
| 负 | 负 | 正 | 负 |

这里讨论的是符号，不代表余数一定非零；实际余数等于 0 时，仍应直接记为 0。真正要记住的是：`IDIV` 与 `DIV` 使用相同的结果位置，却按有符号数解释被除数、除数、商和余数。

无论是 `DIV` 还是 `IDIV`，执行后六个状态标志都没有定义。因此，除法指令执行后再去测试状态标志，没有意义。

> **易错点**：`CMP` 设置的条件标志可以帮助程序作判断，但那是比较指令的工作。执行完 `DIV` 或 `IDIV` 以后，不能把运算结果和状态标志混在一起讨论。

### 用除法把二进制数转成 BCD 数

绝对值题让我们熟悉了“分析题目—画流程—写指令”，接下来用同一套方法处理一个更典型的程序设计任务。

题目是：存储器单元 `BUFF1` 中存放一个 8 位无符号二进制数，把它转换为十进制数，并用 BCD 形式依次存放到 `BUFF2` 开始的三个单元中。

这里要抓住三个条件：输入是 8 位无符号数；输出采用 BCD 形式；结果占 3 个字节，并从低地址开始存放。

#### 先分析数值范围和存储空间

8 位无符号数的范围是 $0\sim255$，转换后的十进制数最多有 3 位，因此结果确实需要 3 个字节来存放。

输入只需要 1 个字节，输出需要预留 3 个字节。数据段中的相关定义可以写成：

```asm
; 数据段中的变量定义片段
BUFF1   DB      ?
BUFF2   DB      3 DUP (?)
```

存储次序必须与分析一致：

```text
低地址                                      高地址
  │                                          │
  ▼                                          ▼
BUFF2       BUFF2+1        BUFF2+2
 个位数        十位数          百位数
```

不能把个位数放到最高地址。我们先用除以 10 取余的方法得到个位数，所以第一次余数就写入 `BUFF2`。

#### 厨师取余法：先取个位，再取十位

二进制数转十进制数，最常用的算法之一就是反复除以 10、逐次取余。

设输入为 $N$。第一次用 $N$ 除以 10，商记为 $Q_1$，余数就是十进制个位数；第二次用 $Q_1$ 除以 10，商记为 $Q_2$，余数就是十位数；再对 $Q_2$ 除以 10，此时商就是百位数。

例如，一个数在连续三次除法中得到：

```text
第一次：N  ÷ 10  →  商 Q1，余数 个位
第二次：Q1 ÷ 10  →  商 Q2，余数 十位
第三次：Q2 ÷ 10  →  商 百位，余数 0
```

这就是“厨师取余法”：每做一次，就像厨师从食材中取出一份余数；余数最先得到，所以个位数放在最低地址。

8 位无符号输入最多只有 255，三次除法已经足够：前两次取余，最后一次直接取商。

#### 两个 8 位数相除的安排

因为除数由原操作数给出，而且不能是立即数，所以先令 `CL=10`。输入只有 8 位，而 `DIV CL` 要以整个 `AX` 作为 16 位被除数，所以读入 `AL` 后必须把 `AH` 清零。

第一条 `DIV CL` 执行后，个位数在 `AH` 中，写到 `BUFF2`。接着还要除中间商，但此时的 `AX` 并不是一个干净的 16 位被除数：低位 `AL` 中是商，高位 `AH` 中是上一轮余数。必须再次令 `AH=0`，只保留 `AL` 中的商，才能进行下一次 8 位除法。

完成题目功能的核心代码片段如下：

```asm
        MOV     AL, BUFF1
        MOV     AH, 0
        MOV     CL, 10

        DIV     CL
        MOV     BUFF2, AH

        MOV     AH, 0
        DIV     CL
        MOV     BUFF2+1, AH

        MOV     AH, 0
        DIV     CL
        MOV     BUFF2+2, AL
```

逐段读这段程序，就会发现每一条操作都对应算法中的一步。

第一段把 `BUFF1` 的 8 位输入送入 `AL`，清零 `AH`，使 `AX` 成为完整的 16 位被除数；`CL` 保存除数 10。执行 `DIV CL` 后，`AL` 是中间商，`AH` 是个位数，所以把 `AH` 存入 `BUFF2`。

第二段先执行 `MOV AH, 0`，把上一轮余数清掉，同时保留 `AL` 中的中间商。随后再次执行 `DIV CL`，新的余数就是十位数，把它存入 `BUFF2+1`。

第三段仍然先清零 `AH`，再除以 10。这一次已经取到百位，商的数值直接作为最高位数字，所以不再取 `AH` 中的余数，而是把 `AL` 中的商存入 `BUFF2+2`。

> **提示**：连续做 `8 位 ÷ 8 位` 除法时，每一轮都要检查被除数寄存器的高 8 位是不是有效数据。输入来自 `AL` 时，第一次要清零 `AH`；上一轮的余数又在 `AH` 中时，下一轮也必须先清零。`CL` 中的除数 10 不动。

> **易错点**：每次得到的是“一位十进制数字”，但这个数字装在寄存器里时仍然只是一个二进制数；要让它成为题设要求的 BCD 表示，再存入结果区。

这段程序已经完成了题目要求的核心功能，不过它仍然只是便于我们看清数据流的功能片段，而不是带完整段结构与结束过程的程序。

#### 从 BCD 数字到屏幕字符

实际工程中，还经常要把转换结果送到屏幕上显示。仅仅得到三个 BCD 数字还不够，因为显示器最终需要的是字符。

所以还要先把 BCD 数字转换为对应的 ASCII 字符，再逐个送到屏幕。若参与运算的数据来自键盘，程序同样需要通过操作系统提供的功能取得输入。显示器管理、键盘读取这些设备管理功能，在操作系统中已经做成可供调用的模块；使用 DOS 的相关功能，就可以在屏幕上显示一个字符或一串字符。

因此，这个例子还让我们看到程序设计的两层联系：底层先解决“二进制数怎样转成十进制 BCD 表示”，上层再解决“这些结果怎样转成字符并送到输出设备”。算法、数据表示和设备管理各司其职。

到这里，加法、减法、乘法、除法四类算术运算指令就全部走过了一遍。`BCD` 调整指令此前也已经接触过，后面还要再提一次；接下来则转向逻辑运算以及位操作一类指令。路线很明确：先把程序设计的骨架立起来，再逐步把 8086 指令填进骨架，汇编语言程序设计也就在这一步一步的使用中真正入门。

## 符号扩展与 BCD 调整：算术运算的最后一公里
> 对应块：BLK20 | 覆盖分集：P39-P40 | 块标题（分集名）：《39》

算术运算类指令走到最后，真正容易漏掉的往往不是乘除法本身，而是一个类型不匹配的问题：两个 8 位带符号数相乘，结果到了 16 位；接下来又要加一个 8 位数，这时不能把 8 位结果和 16 位结果硬凑到一起，必须先做符号扩展。符号扩展解决的是“位数不一样”，BCD 调整解决的则是“CPU 只认识二进制，不认识十进制的 BCD 表示”。这两种调整看起来都像是在算完之后补一脚，但它们处理的对象完全不同。

### 符号扩展先把位数对上

8086 指令系统里有两条符号扩展指令：`CBW` 和 `CWD`。它们都不影响状态标志，所以使用它们不会像普通的算术运算那样改变标志位。

#### CBW：把 AL 扩展到 AX

`CBW` 的作用是把 `AL` 中的 8 位带符号数扩展成 `AX` 中的 16 位带符号数。扩展之后，`AX` 的低 8 位仍然是原来的 `AL`，高 8 位 `AH` 全部复制 `AL` 的符号位。

```text
AL :  [ s | d6 d5 d4 d3 d2 d1 d0 ]
AX :  [ s | s  | d6 d5 d4 d3 d2 d1 d0 ]
```

这里的关键不是把 `AH` 随便填成 0，而是复制 `AL` 的符号位。因为原数是带符号数，只有把符号位补到高位，扩展后的数值才和原来的 8 位数保持一致。

#### CWD：把 AX 扩展到 DX:AX

`CWD` 处理的是 16 位数：把 `AX` 中的 16 位带符号数扩展成 `DX:AX` 中的 32 位带符号数。`AX` 保留原值，`DX` 复制 `AX` 的符号位。

```text
AX    :  [ s | d14 d13 ... d1 d0 ]
DX:AX :  [ s | s  | d14 d13 ... d1 d0 ]
```

`CBW` 和 `CWD` 的共同思路很简单：低位保留原数据，高位补符号位。前者处理 `AL → AX`，后者处理 `AX → DX:AX`。`CBW` 虽然属于算术运算类指令，但它本身不改变标志位。

### 把混合类型的算式写出来

现在看一个把符号扩展真正用起来的例子。设

$$
y = a \times b + c - 18
$$

其中 `a`、`b`、`c` 都是字节型的带符号数，`y` 是字型结果。数据段中用 `DB` 定义三个输入变量，用 `DW` 定义结果变量：

```asm
DATA SEGMENT
    A DB ?
    B DB ?
    C DB ?
    Y DW ?
DATA ENDS
```

关键问题出现在 `a × b` 之后。两个字节相乘，结果是 16 位，放在 `AX` 中；而 `c` 只有 8 位。如果直接执行 8 位加法，类型就不一致了。解决的办法是先把 `c` 送入 `AL`，执行 `CBW`，让它变成 16 位数，再和已经保存在 `AX` 中的乘积相加。

核心程序可以这样写：

```asm
CODE SEGMENT
    ASSUME CS:CODE, DS:DATA

    MOV AL, A
    IMUL B
    MOV BX, AX

    MOV AL, C
    CBW
    ADD AX, BX
    SUB AX, 18
    MOV Y, AX

CODE ENDS
```

这段程序的思路要顺着寄存器的变化看。

首先把 `a` 送入 `AL`，使用带符号乘法 `IMUL B`，让 `AL` 与内存单元 `B` 中的 8 位带符号数相乘。乘积是 16 位，存放在 `AX` 中。因为后面还要加 `c`，而 `AX` 还要作为结果寄存器使用，所以先用 `MOV BX, AX` 把乘积保存到 `BX`。

接着把 `c` 送入 `AL`。此时 `AL` 是 8 位数，执行 `CBW` 后，`AL` 的符号位被复制到 `AH`，于是 `AX` 中得到一个 16 位的 `c`。这时 `ADD AX, BX` 就是在相同类型的两个 16 位数之间求和。最后用 `SUB AX, 18` 减去常数，结果仍留在 `AX` 中，再通过 `MOV Y, AX` 保存到字型变量 `Y`。

> **易错点**：`CBW` 只处理 `AL`，不能凭空把内存中的 `C` 扩展。因此必须先把 `C` 送入 `AL`，再执行 `CBW`；不能以为执行一条扩展指令就会自动从数据段取数。

实际程序中，像 `18` 这样的常量或较复杂的表达式，可以用 `EQU` 定义成符号常量。例如：

```asm
CONST EQU 18
```

以后写 `SUB AX, CONST`，就能直接表达“减去 18”这个含义。如果某个复杂表达式在程序里反复出现，也可以先用 `EQU` 把它定义为一个符号常量，再在各处用这个名称代替。这样既减少重复书写，也让算式的意图更清楚。

### BCD 数：CPU 不会替你理解十进制

计算机中可以用 BCD 码表示十进制数，而 BCD 数有两种表示方式：组合 BCD 数和分离 BCD 数。组合 BCD 数把十进制位紧凑地放在一个字节的高、低四位中；分离 BCD 数则把每个十进制位单独放在一个字节的低四位中。

这里的麻烦在于：CPU 执行加、减、乘、除时，并不会自动知道自己正在处理 BCD 数。它会把操作数当成普通二进制数参与运算，所以运算后得到的二进制结果，往往不是我们想要的 BCD 表示。必须再执行相应的 BCD 调整指令，把结果调整为正确的 BCD 形式。

这几类指令可以这样对应起来：

| 运算 | 组合 BCD 数 | 分离 BCD 数 |
| :--- | :--- | :--- |
| 加法 | `DAA` | `AAA` |
| 减法 | `DAS` | `AAS` |
| 乘法 | 不采用 | `AAM` |
| 除法 | 不采用 | `AAD` |

加减法的调整指令都隐含地针对 `AL` 中的结果。乘法和除法则只能使用分离 BCD 数，相应的调整指令是 `AAM` 和 `AAD`。

还要记住调整发生的时机：加法、减法和乘法都是先进行运算，再对结果进行调整；除法反过来，必须先调整被除数，再进行除法运算。这个“先调整还是后调整”是使用 BCD 指令时最容易被忽略的顺序问题。

有些教材会把分离 BCD 数加法调整称为 ASCII 码加法调整，把 `AAA` 称为 ASCII 码调整指令；看到这种说法，实质上仍然是在讲分离 BCD 数的调整。

### 加法调整：DAA 与 AAA

#### 组合 BCD 加法：DAA

先看 `56 + 73` 的组合 BCD 运算。组合 BCD 数中，十进制的 56 用 `56H` 表示，73 用 `73H` 表示。CPU 只把它们当二进制数相加：

```asm
MOV AL, 56H
ADD AL, 73H
DAA
```

`ADD` 执行后，`AL` 得到 `C9H`，但这个值并不是我们想要的十进制 BCD 结果。原因是 CPU 只完成了二进制加法，并没有把 BCD 码的十进制调整规则加入进去。

执行 `DAA` 时，CPU 要检查高低四位的 BCD 码是否合法。这个例子里，低四位的 9 没有超过 9，不需要在低位额外加 6；高四位的 `C` 已经超过 9，需要加上 `60H`。于是：

```text
C9H + 60H = 0129H
```

低 8 位留下 `29H`，进位进入 `CF`，因此调整后 `AL = 29H`，`CF = 1`。

十进制的正确答案是 129。组合 BCD 的低位结果是 29，最前面的进位由 `CF` 携带，所以不能只看 `AL`。如果 `CF` 为 1，就说明本位之外还有一位进位。

#### 分离 BCD 加法：AAA

再看一个分离 BCD 数 `4 + 8` 的例子：

```asm
MOV AL, 04H
ADD AL, 08H
AAA
```

`ADD` 得到 `0CH`。这在二进制中是正确的，但作为分离 BCD 结果还不够合法，因此要执行 `AAA`。

`AAA` 的调整可以分成几步理解。第一步检查 `AL` 的低四位；低四位是 `C`，已经超过 9，所以要加 6，得到 `12H`，并置 `AF = 1`。第二步把高四位清零，低四位保留，于是 `AL = 02H`。第三步把 `AF` 传送到 `AH`，因此 `AH = 01H`，最后：

```text
AX = 0102H
```

这正好表示十进制的 12：十位 1 放在 `AH`，个位 2 放在 `AL`。分离 BCD 数的调整比组合 BCD 复杂，关键就在于它不只调整一个字节，还要把十位和个位分别安排好。

实际工程中，如果只是做普通的十进制加法，通常优先采用组合 BCD 数的 `DAA`，因为它比 `AAA` 简单。

### 减法调整：DAS 与 AAS

#### 组合 BCD 减法：DAS

组合 BCD 数的减法使用 `DAS`。看 `31 - 87` 的例子：

```asm
MOV AL, 31H
SUB AL, 87H
DAS
```

`SUB` 执行后，`AL` 的二进制结果是 `AAH`，同时因为发生了借位，`CF = 1`。这个 `AAH` 不是最终的 BCD 结果，需要用 `DAS` 调整。

调整时，低四位超过 9，需要减去 6；高四位也超过 9，还要继续减去 `60H`。调整之后：

```text
AL = 44H
CF = 1
```

十进制中 `31 - 87 = -56`。所以 `AL` 中的 `44H` 不能理解成正的 44，它要和借位标志结合起来看：`CF = 1` 表示减法向更高位借了位，实际结果是负的 56。

> **结论**：组合 BCD 减法读取结果时，不能只看 `AL`，必须把 `CF` 表示的借位考虑进去。忽略这个借位，就会把一个负数误读成正的余数。

#### 分离 BCD 减法：AAS

如果参加运算的是分离 BCD 数，减法对应的调整指令是 `AAS`。它和 `AAA` 一样，是针对 `AL` 中的分离 BCD 结果进行调整；具体使用时，要根据分离 BCD 的存放形式和运算结果来理解十位、个位以及借位的处理。

分离 BCD 加法在有些教材中被称为 ASCII 码加法，分离 BCD 减法也沿用相应的 ASCII 码叫法。这里先记住指令对应关系，不要把组合 BCD 的 `DAS` 和分离 BCD 的 `AAS` 混在一起。

### 乘法与除法调整：AAM 和 AAD

乘法和除法的 BCD 运算只能使用分离 BCD 数。对应的乘法调整指令是 `AAM`，除法调整指令是 `AAD`。

#### 乘法先乘后调：AAM

以分离 BCD 数 `7 × 8` 为例：

```asm
MOV AL, 07H
MOV BL, 08H
MUL BL
AAM
```

`MUL BL` 执行的是二进制乘法。7 和 8 相乘得到 56，CPU 把它放在 `AX` 中：

```text
AX = 0038H
```

但 `0038H` 是二进制乘积，不是分离 BCD 的十进制结果。执行 `AAM` 后，CPU 对 `AX` 中的乘积进行除 10 的调整，商放入 `AH`，余数放入 `AL`。十进制的 56 除以 10，商是 5，余数是 6，于是得到：

```text
AX = 0506H
```

`AH = 05H` 表示十位，`AL = 06H` 表示个位，结果就是十进制的 56。

所以乘法 BCD 调整的顺序一定要记牢：先用 `MUL` 做二进制乘法，再用 `AAM` 调整。`AAM` 会影响相应状态标志，不过实际应用中通常不必过分纠缠它的标志细节，先把运算顺序和结果位置掌握准确。

#### 除法先调后算：AAD

除法的顺序完全相反。`AAD` 要在除法之前执行，因为它负责先把分离 BCD 被除数调整成 CPU 可以进行二进制除法的形式。

以 `27 ÷ 4` 为例：

```asm
MOV AX, 0207H
MOV BL, 04H
AAD
DIV BL
```

分离 BCD 的十进制的 27 用 `0207H` 表示：`AH` 中是十位 2，`AL` 中是个位 7。`AAD` 的调整原则是：

$$
AX = AH \times 10 + AL
$$

因此：

```text
0207H → 2 × 10 + 7 = 27 → 001BH
```

此时 `AX` 中已经是普通二进制数 27，才能执行 `DIV BL`，用 27 除以 `BL` 中的 4。商和余数的存放位置是：商放在 `AL`，余数放在 `AH`。所以结果是：

```text
AL = 06H
AH = 03H
AX = 0306H
```

也就是商 6、余数 3。

> **易错点**：除法 BCD 运算一定是先 `AAD` 调整，再执行 `DIV`。加法、减法和乘法都是先运算后调整，唯独除法不能照搬这个顺序。

### 逻辑运算的五条指令

算术运算类指令讲完以后，进入逻辑运算类。8086 指令系统中的逻辑运算指令一共有五条：与、或、异或、测试和非。

它们的共同点是按位进行逻辑处理，但结果是否写回目的操作数，以及怎样处理状态标志，并不完全相同。

#### 与、或、异或：结果要写回目的操作数

`AND`、`OR` 和 `XOR` 都是双操作数指令，基本格式是：

```asm
AND 目的操作数, 源操作数
OR   目的操作数, 源操作数
XOR  目的操作数, 源操作数
```

以 `AND` 为例，目的操作数由寻址方式指出，源操作数由另一种寻址方式指出。CPU 对两个操作数逐位进行与运算，所得结果送回目的操作数。也就是说，目的操作数原来的内容被运算结果替换。

`OR` 和 `XOR` 的处理方式相同，只是逐位进行的逻辑运算不同。`OR` 的两个操作数都必须是 8086 所支持的操作数形式，可以按字节或字进行运算；`XOR` 也是把两个操作数逐位异或，再把结果写回目的操作数。

这三条指令的标志处理要特别记清楚：

- `CF` 自动清零；
- `OF` 自动清零；
- `AF` 没有定义；
- `SF`、`ZF`、`PF` 根据逻辑运算结果正常设置。

考试时经常在这个地方设陷阱：执行 `AND`、`OR` 或 `XOR` 后，不能再按照算术运算的习惯去保留 `CF` 和 `OF`，它们就是会被自动清零。`AF` 则不是“保持不变”，而是处于没有定义的状态。

#### TEST：只测试，不保存结果

`TEST` 也是双操作数指令：

```asm
TEST 目的操作数, 源操作数
```

它在内部完成的逻辑效果类似 `AND`，会根据两个操作数按位与之后的结果设置标志，但这个结果不送回目的操作数，目的操作数也不会被破坏。换句话说，`TEST` 关注的是“按位与的结果是什么”，而不是“把结果保存下来”。

因此，`TEST` 很适合完成这样的任务：测试一个数的某一位是 0 还是 1，同时又不能改变原来的数据。和 `AND` 一样，`TEST` 执行后 `CF`、`OF` 自动清零，`AF` 没有定义，`SF`、`ZF`、`PF` 根据结果正常设置。

可以把它和 `AND` 这样区分：

| 指令 | 是否写回结果 | 目的操作数是否保留 | 主要用途 |
| :--- | :--- | :--- | :--- |
| `AND` | 是 | 否，被结果替换 | 按位与并保存结果 |
| `TEST` | 否 | 是 | 只测试条件，不破坏数据 |

#### NOT：按位取反，不影响状态标志

`NOT` 是单操作数指令：

```asm
NOT 目的操作数
```

CPU 对目的操作数按位取反，所得结果仍然写回目的操作数。需要注意，`NOT` 的执行不会影响状态标志；它不像 `AND`、`OR`、`XOR` 和 `TEST` 那样去设置逻辑运算结果标志。

到这里，逻辑运算几条指令的差别就很清楚了：`AND`、`OR`、`XOR` 要保存运算结果，`TEST` 只测试并设置标志，`NOT` 则完成按位取反且不改变状态标志。

### 几条不能忘的规则

BCD 调整和逻辑运算看起来都是“算完之后再处理一下”，但处理顺序不能混在一起。

加法、减法和乘法的 BCD 调整，都是先执行普通运算，再执行调整指令；除法则必须先执行 `AAD`，再执行 `DIV`。这是 BCD 调整最核心的顺序规则。

组合 BCD 减法还要特别注意借位。`DAS` 调整后 `AL` 中的数值必须和 `CF` 一起解释，否则很容易把负数的结果看错。

符号扩展时，先看清楚扩展指令的隐含操作数：`CBW` 处理 `AL`，`CWD` 处理 `AX`。看到 8 位数和 16 位数混用时，先检查类型是否一致，再决定符号位应该补到哪里。

逻辑运算时，记住 `TEST` 和 `AND` 的区别，也记住 `NOT` 不影响状态标志。真正容易出错的，往往不是指令记不熟，而是没有先确认“数据在哪个寄存器、结果要放哪里、调整发生在运算之前还是之后”。
