## 第 1 章：第三章开篇名词解释：从机器语言到 ASM_OBJ_EXE 与三种语句
> 对应分集：P24 | 原始标题：《第三章开篇名词解释：从机器语言到 ASM_OBJ_EXE 与三种语句》

今天到第三章，讲 8086 的指令系统。讲所有指令之前看 3.1 节，汇编语言里要掌握的其他名词概念。今天第一个概念就是名词解释。

### 指令与指令系统

一、什么叫指令？前面建立了：CPU 能认识的一组二进制代码，能告诉 CPU 做什么、如何去做，这种代码称为一条指令。二、指令系统：CPU 能识别的所有指令的集合构成该型号 CPU 的指令系统。不同型号指令系统不同，8086 有它的，8051 单片机有它的，TI 的 `MSP430` 有它的，CPU 能认识的指令不同，但指令都是二进制代码组成。

### 机器语言与汇编语言

第三个概念机器语言：编程序采用机器直接认识的指令代码编写，采用的这种语言就叫机器语言，显然是二进制代码语言，或者叫指令代码语言。用机器语言编写的程序就叫机器语言程序。最大优点：输入计算机后 CPU 直接执行，无需翻译编译，因为用的就是 CPU 直接认识的代码。最大缺点：用户要记忆 CPU 认识哪些代码、每条代表什么功能，编写十分复杂，费好大劲编好调好，过段时间自己都不理解了，功能扩充、维护也复杂。就因为复杂，才引出汇编语言。

汇编语言是符号化语言：把 CPU 认识的一条指令用一组符号和数字替代。比如 CPU 认识 `B0H 12H` 这么一条指令，用符号 `MOV AL, 12H` 代替，把指令符号化了，符号化的语言称为汇编语言。用汇编语言编程肯定比机器语言容易得多。第六个概念汇编语言程序，或者叫源程序，源字可不说。用户用汇编语言写的程序叫源程序，但 CPU 不能直接执行，执行前必须翻译成机器语言程序。

第七个概念汇编，动词：把源程序翻译成机器语言的过程称为汇编。常用翻译工具 `MASM.EXE`，网上找就行，安装不像别的软件那么复杂，直接粘贴就能用，建议 5.0 以上版本，也有集成的可用。`MASM` 一般在 `DOS` 环境用，`Windows` 下也能用。还有反汇编：把机器语言程序翻译回原来汇编语言格式。

### 一段程序的汇编实例

举个例子。组织几条指令写段源程序，代码段的一部分：

```assembly
MOV AL, 12H
ADD AL, 21H
PUSH AX
MOV BL, 0FFH
AND BL, AL
POP AX
```

汇编后：`MOV AL, 12H` 对应 `B0H 12H`；`ADD AL, 21H` 对应 `04H 21H`；`PUSH AX` 对应 `50H` 单字节；`MOV BL, 0FFH` 对应 `B3H FFH`；`AND BL, AL` 对应 `20H C3H`；`POP AX` 对应 `58H`。调试工具里看到的默认十六进制，`H` 不写。8086 指令最短单字节，除掉段前缀最长五字节指令。

左边汇编语言格式，右边机器语言格式，翻译过程叫汇编。翻译后调试程序里能看到指令放在存储器哪个段冒号哪个偏移，段地址肯定是 `CS` 的值，偏移是 `IP` 指向的单元。

汇编后磁盘上形成文件名 `.OBJ` 文件。编辑源程序起名文件名 `.ASM`，后缀必定 `.ASM`；`MASM` 汇编后磁盘上是 `.OBJ` 目标码文件，面向机器、CPU 是目标嘛，能认识的代码文件。但 PC 机上 `.OBJ` 不能执行。汇编时源程序翻译成目标码放存储器，地址是浮动的、不连续的：源程序量大，很难保证存储器有自由空间全放下，要找好多自由空间放进去，地址不连续就不能直接执行。要执行就要连接，用连接程序 `LINK.EXE` 把 `.OBJ` 连接成文件名 `.EXE` 可执行文件。PC 机上 CPU 能直接执行的是 `.EXE` 或 `.COM` 文件。

```text
file.ASM --MASM--> file.OBJ --LINK--> file.EXE --DEBUG装入内存--> 执行/调试
```

`.EXE` 文件可在 `DEBUG` 里调试：程序经 `DEBUG` 装入内存，装的是 `.EXE` 形式的机器语言程序、目标码文件，但地址连续了。装进内存的是二进制代码，用户要看原来程序是什么就要反汇编，用 `DEBUG` 的 `U` 命令一反汇编，屏幕上看到原来的符号指令。`DEBUG` 里把内存二进制文件再翻译回符号的过程叫反汇编。怎么执行上机再讲，要练 `DEBUG` 好多命令。

### 语句的种类

有了这些概念，看 3.1 节一开始第二个概念：8086 汇编语言程序中语句的种类。刚才编的程序，一条一条是不是语句？像这样的语句称为指令语句。什么是指令语句？CPU 能执行的语句称为指令语句，或者说汇编后能翻译成指令代码的语句称为指令语句。

第二种伪指令语句：CPU 不能执行的语句叫伪指令语句，或者说汇编时不能汇编成指令代码、汇编后不产生指令代码的语句。如前面用过的 `DB`，指示告诉汇编程序 `MASM` 汇编时完成的操作：`DB` 告诉汇编程序开始定义字节型数据了，在存储器分配字节型数据，这个操作是 `MASM` 汇编时完成的，不是 CPU 执行程序时完成的，所以叫伪指令语句，像 `DW` 等等。

8086 汇编程序里还有一种语句叫宏指令语句。宏指令语句本身是 8086 指令系统没有的，由用户通过宏定义伪指令开发的新语句，类似 C 语言的函数，前面定义后面引用。具体定义方式第三章后半部分才讲。常用的主要是指令语句和伪指令语句。

## 第 2 章：语句的四部分与常数表达式：变量标号命名与汇编时算值的表达式
> 对应分集：P25 | 原始标题：《语句的四部分与常数表达式：变量标号命名与汇编时算值的表达式》

8086 汇编语言程序语句的种类就三种，常用的主要是指令语句和伪指令语句。第三种宏指令语句本身是 8086 指令系统没有的语句，由用户通过宏定义伪指令定义的，或者说用户开发的新语句。有些语句程序员自己可以开发，工具就是宏定义伪指令。开发了宏指令，后面编程就能引用，类似 C 语言的函数：前面定义函数，下面引用调用，两回事一回事。具体定义方式第三章后半部分才讲。这是 3.1 节一开始要掌握的基本概念。

### 语句最多由四部分组成

下面翻到教材 25 页，3.1.1 汇编语言语句的组成。每种语句由哪几部分组成？一条语句最多四部分。比如数据定义伪指令：

```assembly
DATA1 DB 12H, -12
```

`DB` 叫助记符，后边 `12H, -12` 逗号分隔定义字节型数据，叫操作数，操作数多项之间逗号分隔。助记符一部分，操作数一部分，这就两部分了。

`12H` 存哪个单元？严格说 `DB` 左边要给出单元地址。但实际单元非常多，每个地址都记程序设计极其繁琐，所以把地址符号化。打个比方：每个同学是一个存储单元，学号是地址，人交往全凭学号记忆复杂，起个名字用名字交往就简单了。汇编同理，单元都有地址，直接和地址打交道极其复杂，把用到的单元地址符号化起个符号名称。比如命名 `DATA1`，后面要把 `12H` 读入 `AL` 直接访问 `DATA1`，读后一个数据访问 `DATA1+1`。数据定义伪指令左边起的符号化名称叫变量名，简称变量。

再定义字单元：

```assembly
DATA2 DW ?
```

`DATA2` 是字单元，地址用变量名代替。后面执行：

```assembly
MOV DATA2, AX
```

把 `AX` 内容写入 `DATA2` 地址的字单元。初始没具体数据用问号 `?` 预留空间，打问号实际数据是随机数，开机是多少就是多少，CPU 执行写入指令后才存入目标数据。

变量名、助记符、操作数，操作数后以分号 `;` 开头还能加注释，一条语句最多四部分：名称、助记符、操作数、注释。名称命名规范：凡是名称必须以字母开头，凡是常数必须以 $0 \sim 9$ 开头；名称字符长度不超过 31 个。

### 指令语句中的标号

编程时写指令序列：

```assembly
MOV AX, BX
...
ADD AX, DATA2
JZ  NEXT
```

执行 `ADD AX, DATA2` 结果送回 `AX`，CPU 按结果设置 `ZF` 零标志，再 `JZ` 判断是否为 0：`ZF` 置 1 跳转目标地址，不为 0 顺序执行，典型的条件二分支。`JZ` 后要指定跳转目的地址，具体数字地址无法确定，同样符号化。比如目的指令单元命名 `NEXT`，以冒号结尾，这个名称代表指令在存储器的地址，有段地址有偏移地址，叫标号名，简称标号。不管标号还是变量，凡是名称首字符必须字母开头。`1H` 是数字十六进制常数，`H1` 是名称，就这么个意思。语句四部分就说这么多。

### 常数：数值字符字符串与问号

下面 3.1.2，汇编里的常数及表达式，教材 26 页。常数有几种：

数值常数：十六进制以大写 `H` 结尾；二进制必须大写 `B` 结尾，小写不对，比如 `MOV AL, 10110001B`；十进制结尾可缺省，不缺省用大写 `D`，一般缺省。

字符与字符串常数：单引号括起来的单个字符叫字符常数，比如 `MOV BL, 'A'`，汇编时汇编程序用字符 `ASCII` 码代替，所以也是常数；数据段定义时单引号括起的一串字符叫字符串常数，比如 `STRING DB 'THIS IS ...'`，`STRING` 是变量名。

预留值问号 `?`：数据定义伪指令里用，表明单元数据随机，开机多大就是多大，目的是程序运行期间写入运算结果。这些都叫常数。

| 常数类型 | 写法 | 说明 |
| :--- | :--- | :--- |
| 十六进制 | `12H`、`0FFH` | 大写 `H` 结尾，字母开头前加 $0$ |
| 二进制 | `10110001B` | 必须大写 `B` |
| 十进制 | `12`、`12D` | 一般缺省 |
| 字符 | `'A'` | 汇编时用 `ASCII` 码代替 |
| 字符串 | `'THIS IS ...'` | 数据段定义用 |
| 预留 | `?` | 随机数，运行期写入结果用 |

### 表达式：汇编时算值不是 CPU 算

下面看表达式，教材 27 页。表达式的值是汇编程序汇编过程中计算出来的，不是 CPU 执行指令时计算的！CPU 执行完成的是助记符对应的操作，比如 `MOV` 传送。

算术表达式比如：

```assembly
MOV AL, 5 + 2 * 3
```

操作数项写了算术表达式，汇编程序汇编时先算出值，遵循四则运算：先括号后外边，先乘除后加减，和算术规则一致。也可出现在数据定义伪指令里，比如写 $5 \times 4$，汇编算出 $20$ 即 $14H$ 存入单元，计算机内部数值都用二进制。除法 `/` 取商：$20 / 3 = 6$ 即 $06H$；`MOD` 取余：$20\ \text{MOD}\ 3 = 2$。实际编程允许操作数用算术表达式，但用得不多。表达式里运算符 `+`、`-`、`*`、`/`、`MOD` 叫操作符，参与的数值叫操作数。

逻辑操作表达式与或异或非，比如：

```assembly
AND AL, 21H AND 0FH
```

出现两次 `AND` 要区分：第二个操作数项上的 `21H AND 0FH` 是逻辑表达式，汇编程序汇编时算完；第一个是指令助记符，CPU 执行时才算。两种操作必须分清，逻辑表达式允许出现但很不常用。

第三种关系表达式概念简单，汇编时按关系算出真假值，同样不常用。表达式共同点记住一条：值都是汇编时算好的，CPU 拿到的是现成结果。

## 第 3 章：标号三属性与变量五属性：SEG_OFFSET_TYPE 与存储器分配图
> 对应分集：P26 | 原始标题：《标号三属性与变量五属性：SEG_OFFSET_TYPE 与存储器分配图》

把属性表达式贯穿在这一节讲。到 3.1.3 节，标号、变量及伪指令。标号出现在指令语句左边，以冒号结尾，代表某条指令语句的地址。比如：

```assembly
JNZ NEXT
...
NEXT: MOV AX, BX
```

`NEXT` 指向指令的地址，这就叫标号。在转移目的地指令左边起标号名、以冒号结尾，标号就定义完了。

### 标号三属性与三个操作符

标号一旦定义就具有三个属性，属性概念才能讲下去：段地址属性，该标号对应指令单元的 16 位段地址；段内偏移地址属性，16 位；类型属性。语句里都可以用属性表达式获取它的属性。

获取段地址操作符是 `SEG`，`segment` 缩写；获取偏移属性操作符是 `OFFSET`；获取类型是 `TYPE`。常用的是取 `OFFSET`，比如取 `NEXT` 的偏移：

```assembly
MOV BX, OFFSET NEXT
```

源操作数项上 `OFFSET NEXT` 就叫属性表达式。`NEXT` 的 `OFFSET` 是定义即具有的，属性表达式的值是常数，16 位常数。所以写成 `MOV BL, OFFSET NEXT` 语法就错了，偏移 16 位，`BL` 8 位寄存器类型不一致。取段地址显然写 `SEG NEXT`。

标号类型两种：`NEAR` 近型，`FAR` 远型。转移指令和目的地标号在同一个代码段即 `CS` 段，属于段内转移，近程转移，标号 `TYPE` 属性 8086 赋值为 $-1$。不在同一个代码段叫段间转移，远程转移，从一个代码段跳到另一个去了，`TYPE` 赋 $-2$。取 `TYPE NEXT` 段内转移汇编得出 $-1$，这是 8086 规定。但实际编程取标号类型属性没有意义，记住结论就行。

### 变量定义伪指令与变量五属性

现在看变量，教材 28 页。二、变量及变量定义伪指令。28 页开头给出五种：`DB` 定义字节型变量，数据放变量对应单元，类似定义变量，用 `DB` 定义了单元再用 `MOV` 重写新数据，数据变了所以叫变量；`DW` 定义字型；`DD` 定义双字型；剩下 `DQ` 定义长字型，一个长字 8 字节；`DT` 定义 10 字节型。后两种几乎不用，重点掌握 `DB`、`DW`、`DD` 三个。

一般变量都定义在数据段。比如 `DS` 段：

```assembly
DATA1 DB 12, -12, 12H, '1'
```

`DATA1` 代表 `DB` 定义数据所在单元的地址，符号定位，起名规则和标号一样必须字母开头。`12`、`-12` 讲过，`'1'` 字符常量，变量就定义了。

变量一旦定义具有五大属性：段地址属性，对应单元的段地址；段内偏移属性，对应单元的段内偏移，还叫段内有效地址，用 $EA$ 描述；类型属性，什么类型，`DB` 字节型赋类型值 1，其实类型就是所占字节数，`DW` 字变量占两字节类型等于 2，`DD` 等于 4，记着 `TYPE` 操作符；长度属性；大小属性。

实际编程语句里常出现的是类型和偏移属性。取段地址操作符 `SEG`，偏移 `OFFSET`，类型 `TYPE`，长度 `LENGTH`，大小 `SIZE`。比如：

```assembly
MOV AL, TYPE DATA1
```

`DATA1` 是 `DB` 字节型，类型值 1，汇编时属性表达式用 1 代替，等效 `MOV AL, 1`。取偏移：

```assembly
MOV BX, OFFSET DATA1
```

把 `DATA1` 16 位偏移传给 `BX`，找 `DATA1` 就可以 `BX` 间接寻址。获取偏移肯定送 16 位寄存器，最好选地址寄存器：`BX`、`BP` 两个基址，`SI`、`DI` 两个变址。写 `MOV AX, OFFSET DATA1` 语法对但我认为没意义：取偏移目的是后续间接寻址用，`AX` 不是地址寄存器不能寻址，给它有意义吗？没有。长度和大小属性先不讲，说了还听不懂，一会再说。

| 变量类型 | 定义 | `TYPE` 值 | 含义 |
| :--- | :--- | :--- | :--- |
| 字节型 | `DB` | 1 | 占 1 字节 |
| 字型 | `DW` | 2 | 占 2 字节 |
| 双字型 | `DD` | 4 | 占 4 字节 |

### 存储器数据分配示意图

## 第 4 章：变量定义实战：$ 计数器、字符串定义规则与 LENGTH_SIZE_PTR

`$` 本身也是一个常量，语句里可以引用。比如 `$+2` 是不是算术表达式？加 2 是不是变成 6 了？如果加逗号再给 `56ACH`，逗号给的操作数也是字，因为 `DW` 伪指令。汇编继续往下，这个时候 `$` 是不是增 2 到了 `0006H`？单元段地址变了吗？没变，还是 `1500H`。这个单元放 `56ACH`，`ACH` 低字节写低地址单元，高字节到高地址单元。我写 `ACH` 也可以写 `0ACH`，一样的，但这里不写前导 0 对吗？对的，这里没在语句里，是画存储器示意图。如果 `0ACH` 做数值在语句里出现，字母开头的十六进制高位是不是要加 0？

逗号后跟 `78H` 也是字，汇编使 `$` 再增 2，偏移到 `0008H`。字单元放低字节 `78H`，高字节多少？00，可缺省即 `00H`。`$` 再增 2 到了多少？怎么能到 10？这是十六进制加法！$8+2=A$，就喜欢你们错到这我才有话讲。偏移 `000AH`，段地址依然没变。

### DB 与 DW 定义字符串规则不同

再来 `DB` 定义：

```assembly
beta3 DB 'THIS'
```

变量 `beta3`，单引号 4 个字符。汇编在 `beta3` 单元写入 `'T'` 的 `ASCII` 码。`ASCII` 记不住做作业直接写 `'T'`，概念完全正确，不扣分，尽管单元放的是编码。下一个单元 `$` 加 1 存 `'H'` 的码，再下 `'I'`，再下 `'S'`。逗号后还有字节操作数继续汇编。

再看 `DW` 定义的 `beta4`：

```assembly
beta4 DW 'AB', 'C'
```

`DW` 也能定义字符串，但无论 `DW` 还是 `DD`，定义字符串一对单引号最多只能两个字符，8086 规定的，没有为什么，严格遵守。用 `DB` 定义一对引号可写任意多个，前提不超过 64K，超过逻辑段装不下。`beta4` 偏移多少？A、B、C、D、E，`000EH`，段地址没变同一逻辑段。这个单元放哪个字符的码？`'B'`！遵循低字节低地址，`DW` 字单元低地址放 `'B'` 的码大写 `42H`，下单元放 `41H` 即 `'A'`。板书画不下换行重画，换行写对即可。下一个字单元 `$` 增 2 偏移 `0010H`，放 `'C'` 的码，高位没字符了，`DW` 必须占满字，高位 0 填补 `00H`。

### DD 存地址与 DW 存偏移

数据段继续定义 `beta5`：

```assembly
beta5 DD 9CH
```

双字变量占 4 字节，最低地址放低字节 `9CH`，后面高字节 `00H`、`00H`、`00H`。`beta5` 偏移 `0012H`，汇编完 `$` 增 4 到 `0016H`。

```assembly
beta6 DW beta3
```

字单元放的不再是常量而是变量。汇编在 `beta6` 存 `beta3` 的 16 位偏移 `OFFSET`，`000AH`，低字节 `0AH` 高字节 `00H`。

```assembly
beta7 DD beta3
```

`beta7` 偏移 `0018H`，双字占 4 字节。汇编取 `beta3` 双字属性：先取偏移字属性 2 字节，再取 16 位段地址属性 2 字节，整体当双字。偏移低字节 `0AH` 高字节 `00H`，下个字存段地址低字节 `00H` 高字节 `15H` 对应 `1500H`。汇编完 `$` 增 4：$18H + 4 = 1CH$，偏移变 `001CH`。

> **提示**：`DW 变量名` 存的是该变量的偏移地址，`DD 变量名` 存的是偏移加段地址的完整双字地址（低字偏移、高字段地址）。

### LENGTH 与 SIZE

8086 规定：变量名定义语句只有出现 `DUP` 重复操作符，左边重复次数才是定义的变量个数。比如 `DATA8` 定义 4 个，`LENGTH` 等于 4；`DATA9` 定义 3 个，`LENGTH` 3；没出现 `DUP` 只定义 1 个，`DATA7`、`DATA6` 等 `LENGTH` 都是 1。注意 `DATA2` 有 7 个初始值项，直接定义 7 个变量。

`SIZE` 大小属性：定义语句所有变量占的总字节数。`DATA1` 1 个变量占 1 字节，`SIZE` 1；`DATA9` 3 个变量每个占 2 字节，总 $2 \times 3 = 6$，`SIZE` 6。

$$\text{SIZE} = \text{TYPE} \times \text{LENGTH}$$

### PTR：属性临时修改操作符

教材 30 页 3.1.4 节，五个属性操作符之外还有 `PTR`，27 页说的其他操作符就是它。看直接寻址：

```assembly
MOV AL, DATA1+2
```

读单元数据到 `AL`，若单元存 `F2H`，执行后 `AL` 等于 `F2H`。但写成 `MOV AX, DATA1` 呢？`DATA1` 字节型 8 位，`AX` 16 位字，源目类型不一致，汇编判定语法错误报错退出。

实际经常要在字节单元按字读、字单元按字节读，就要类型强制转换，用 `PTR`：

```assembly
MOV AX, WORD PTR DATA1
```

`WORD PTR` 把 `DATA1` 本条指令临时强制转字变量，执行后 `AX` 得字数据比如 `1202H`。脱离本条语句 `DATA1` 仍是字节型，没永久改变。所以 `PTR` 叫属性临时修改操作符，仅本语句起作用：临时当字 `WORD PTR 变量名`，临时当字节 `BYTE PTR 变量名`。

再看基址寻址：

```assembly
MOV [BX], 10H
```

目的 `[BX]` 是 `DS` 段偏移 `BX` 内容的单元，源 `10H` 常数本身没类型，目的经 `[BX]` 也定不了按字节还是字访问，汇编无法判断把 `10H` 写成字节还是扩展 `0010H` 写成字，类型不明语法错误。必须 `PTR` 明示：`BYTE PTR [BX]` 或 `WORD PTR [BX]`。比如单元是字节单元就改 `MOV BYTE PTR [DI], ...`，真切找到字节单元，语法就对了。

> **结论**：指令里寻址的操作对象类型不明确就用 `PTR` 说明。`PTR` 在实际编程用得非常广泛。这样 3.1 节全讲完了。

## 第 5 章：指令分类与寻址方式开篇：13 类指令、表 3.2 符号与立即数寄存器寻址

从 3.2 节开始涉及的都是 8086 指令系统里的指令，学指令是为汇编程序设计做准备。3.2 节比较简单，翻到 31 页过一下：指令按功能分 13 类，指令多，为便于学习分的类。

### 13 类指令

第一大类数据传送类，每类好多条，前面课堂常用的 `MOV` 比较多，`MOV` 属于通用数据传送指令。第二大类算术运算类，肯定有加减乘除，加法用过 `ADD`、`ADC`。第三大类逻辑运算指令，马上想到至少 4 条，实际 8086 有 5 条，前面第一章讲完基本的与或异或非 4 条。第四大类移位类，把操作数朝左或朝右移一位或若干位。第五大类标志位操作指令，课堂用过的 `CLD` 让 `DF` 清零，`STD` 置 1，`CLI` 让 `IF` 清零，`STI` 置 1，都属这类。第六大类转移类，程序实现转移的一类控制指令，又分两种：条件转移，受条件控制，课堂用过 `JZ`；无条件转移，助记符 `JMP`，子程序调用 `CALL` 等也属无条件转移。第七类循环控制，程序大多循环结构，循环怎么控制，前面用过 `LOOP`。第八种子程序调用与返回，实际也属无条件转移，调用指令 `CALL`，和 C 语言一样，经常出现完成某功能的一段程序事先定义成子程序，需要时 `CALL` 调用，显然无条件转移了。第九类中断调用返回，主要指软件中断，助记符 `INT`，CPU 执行 `INT` 引起内部中断。第十类字符串操作，课堂接触过 `MOVSB`、`MOVSW`。第十一类输入输出，对 I/O 端口读写的指令，输入读 `IN`，输出写 `OUT`。第十二类书上写其它指令，没归入前面的。第十三类宏指令，8086 本身没有，用户宏定义自己开发的新指令。一共 13 类，后面 3.4 节到 3.16 节按类学每条指令功能使用。

学指令前还要掌握知识点。第一个不算知识点，是使用方法表 3.2：后续叙述为方便好多功能用符号缩写，目的操作数 `DST` 描述，源 `SRC`，寄存器 `REG`，操作数 `OPR`，存储单元有效地址即段内偏移用 `EA`，寻址单元段地址属性用 `SEG` 等等，表列很清楚，下去自己看，不一一叙述。

### 寻址方式定义与两大类

今天重点 3.3 节：数据与转移地址的寻址方式。3.4 到 3.6 节按类学每一类指令，掌握每类指令使用首先掌握操作数寻址方式。什么是寻址方式？简单说就是求操作数所在地、所在存储器单元地址的方式、一种方法。大多数情况操作数在存储器单元，单元有效地址怎么求得，用一种方法求，这种方法叫寻址方式。当然还有操作数不在存储器而在寄存器，或者指令立即给出的常数，也归在寻址方式里。

如果求得的操作数 `OPR` 可做数据用，做运算的数据用，也可做程序转移的转移地址用，寻址方式分两大类：第一大类取数据的寻址方式，第二大类转移目的地地址的操作数在哪放着的寻址方式。转移目的地地址求得：段内转移要求目的地 16 位偏移给 `IP`；段间转移除偏移给 `IP` 还要求 16 位段地址给 `CS`。目的地地址怎么求得，要用寻址方式求。今天先看第一大类，寻找数据的寻址方式，8086 一共给出 8 种。

### 立即数寻址与寄存器寻址

第一种立即数寻址：寻找的操作数指令立即给出，以常数形式给出。比如 `MOV AX, 1234H`，逗号右边源操作数，左边目的操作数。源要传到 `AX` 的数据在哪？指令立即给出，这叫立即数寻址。

为大家学寻址时把谁和谁之间能传数据一开始搞清，看 3.4 节 39 页图 3.3。寻找的操作数可能是立即数上面框，也可能右边框通用寄存器，可能左边框某存储器单元，可能下边框某段寄存器，操作数可能的地方只有这四种。图上箭头标谁和谁能传：立即数能传给通用寄存器，也能传给存储器单元，但箭头画回去了没有？没有。说明立即数只能做什么？只能做源操作数。指令里立即数写到目的位置语法就错。

> **规则**：立即数只能做源操作数，不能做目的操作数。

第二种寄存器寻址：寻找的操作数在某寄存器中。比如 `MOV AX, BX`，把 `BX` 内容传 `AX`。源要传的数据在哪？源项明确指出在 `BX` 寄存器，源寻址就是寄存器寻址；反过来传到何方，目的项明确指出 `AX` 寄存器，目的寻址仍然寄存器寻址。这条看到两通用寄存器可互传数据，图上互相传送箭头。但源目都是寄存器寻址，如 `MOV AX, CL`，源 8 位寄存器寻址，目的 16 位寄存器寻址，源目类型不一致语法错。所以目的源都是寄存器寻址一定要类型一致。

> **规则**：源目都是寄存器寻址时类型必须一致。

我讲每种寻址用五角星总结的，都是 3.4 节往后每类每条指令要守的语法共性规则，书写每条指令都要按规则，不按规则语法错，汇编通不过。

图 3.3 再看：立即数除传通用寄存器和存储器单元，再不能给别人了。给段寄存器 `DS`、`ES`、`SS` 赋值怎么办？按箭头走，先传通用寄存器再传段寄存器，用通用寄存器中介过渡。比如 `MOV DS, 1500H`，源是立即数寻址，立即数不能直接传 `DS`，语法错。`DS`、`ES`、`SS` 做目的时源不能是立即数。改一下：

## 第 6 章：存储器寻址五方式与直接寻址：EA 公式、双存储器禁令与 PTR 收尾
> 对应分集：P29 | 原始标题：《存储器寻址五方式与直接寻址：EA 公式、双存储器禁令与 PTR 收尾》

先看指令 `MOV CS, AX`。源目都是寄存器寻址，逻辑上把 `AX` 写 `CS`，但 `CS` 只能读，这条语法错。错因：`CS` 和 `IP` 都不能做目的操作数。用户无权改它俩：初值是程序装入内存启动时操作系统设置的；执行期间改变是 CPU 执行转移指令自动改的，段内转移 `IP` 变，段间转移 `IP` 和 `CS` 都变，不能 `MOV` 强改。所以 `CS`、`IP` 不能做目的，但可以做源。

### 共性规则与个性规则

寄存器寻址和立即数寻址总结出通用语法规则：立即数只能做源；类型要一致；类型要明确；`DS`、`ES`、`SS` 做目的时源不能是立即数寻址；`CS`、`IP` 不能做目的。这些是往后每类每条指令都守的语法共性规则。学具体指令除共性还有自身语法个性规则，比如堆栈 `PUSH`、`POP` 除守上述规则，还必须按字操作，这就是堆栈特有的。

第三种寻址是教材第 3、4、5、6、7 种，统称存储器寻址。概念：操作数 `OPR` 在存储器某单元，取出来必须知道单元地址，段内有效地址 $EA$ 即偏移，由五种方式求得：

1. 直接寻址：指令直接写出单元有效地址。
2. 寄存器间接寻址：寄存器内容求 $EA$，只能 `[BX]`、`[SI]`、`[DI]` 三者之一。
3. 寄存器相对寻址：$EA$ 两部分，地址寄存器 `[BX]`/`[BP]`/`[SI]`/`[DI]` 四者之一，加 8 位或 16 位位移量 $DISP$：

$$EA = (BX/BP/SI/DI) + DISP$$

4. 基址变址寻址：$EA$ 两部分相加，一部分基址 `[BX]` 或 `[BP]`，另一部分变址 `[SI]` 或 `[DI]`：

$$EA = (BX/BP) + (SI/DI)$$

5. 基址变址相对寻址：上面组合再加 $DISP$，三部分之和：

$$EA = (BX/BP) + (SI/DI) + DISP$$

总结：如果操作数在存储器，五种之一都能找到地址。编程序出现"基址加基址"或"变址加变址"就错了，比如 `MOV AX, [SI][DI]`，字面"变址加变址"，8086 没这种方式，语法错。显然 CPU 面向存储器的寻址种类越多，汇编编程越容易。

| 方式 | $EA$ 构成 | 说明 |
| :--- | :--- | :--- |
| 直接 | 指令直接给出 | 数值或变量名 |
| 寄存器间接 | `[BX]`/`[SI]`/`[DI]` | 三者之一 |
| 寄存器相对 | 基址变址之一 $+ DISP$ | 四者之一加 8/16 位位移 |
| 基址变址 | `(BX/BP)+(SI/DI)` | 基址其一加变址其一 |
| 基址变址相对 | `(BX/BP)+(SI/DI)+DISP$ | 三部分之和 |

### 直接寻址：数值形式与变量形式

第一种直接寻址：操作数在存储器某单元，单元段内 16 位有效地址指令直接给出。比如：

```assembly
MOV AL, [2000H]
```

源传目的，单元偏移 `2000H`，段地址默认 `DS`，找到一个单元。字节还是字？看另一方，`AL` 8 位寄存器，所以是字节单元，功能是把字节数据传 `AL`。源寻址就是直接寻址。

实际编程直接寻址不常用数值写法，单元地址都符号化了，符号叫变量。比如 `DS` 段：

```assembly
DATA1 DB 12H
DATA2 DB 34H
```

变量一旦定义具有五个属性，`DATA1`、`DATA2` 具有段地址和偏移属性。代码段想把 `DATA1` 读给 `AL`：

```assembly
MOV AL, DATA1
```

`DATA1` 代表一个地址，源寻址直接寻址，目的寄存器寻址，执行完 `AL` 等于 $12H$。

### 两存储器单元不能直接操作

如果写：

```assembly
MOV DATA2, DATA1
```

源目都是直接寻址，企图一条指令把 `DATA1` 直接传 `DATA2`，不行。图 3.3：存储单元和通用寄存器可互传，存储单元和另一存储单元之间书上画了能传吗？没有！所以语法错。错因：两存储器单元之间不能直接操作。`ADD` 两单元不能直接加，`AND` 不能直接与，总之不能直接操作。想把 `DATA1` 传 `DATA2` 怎么办？先读到通用寄存器过渡：

```assembly
MOV AL, DATA1
MOV DATA2, AL
```

上面源直接寻址、目的寄存器寻址，下面目的存储器直接寻址。中间 `AL` 过渡，两单元传送完成。

还有类型问题。比如 `DATA1` 是 `DB` 字节单元，我以它为地址写字数据：

```assembly
MOV DATA1, AX
```

`AX` 16 位，`DATA1` 字节型，类型不一致违反规则，语法错误。就是想把 `AX` 写到以 `DATA1` 为地址的字单元，用 `PTR` 说明类型：

```assembly
MOV WORD PTR DATA1, AX
```

语法就对了。但 `PTR` 把字节型 `DATA1` 本条语句临时改成 `WORD`，脱离本条 `DATA1` 仍是字节型。所以 `PTR` 叫属性临时修改操作符，只本行起作用。这是直接寻址应用特别注意的问题。下面休息五分钟，再讲其他寻址方式。

## 第 7 章：寄存器间接寻址与寄存器相对寻址
> 对应分集：P30 | 原始标题：《寄存器间接寻址与寄存器相对寻址》

我前面把直接寻址讲完了，今天接着往下走。你们问得最多的那个字覆盖字节的问题，我先把它收个尾，然后把存储器寻址的第二种和第三种一次讲透。

### 直接寻址的字写字节单元覆盖问题

我数据段里定义了两个字节变量：

```assembly
DATA1 DB 12H
DATA2 DB 34H
```

`DATA1`单元原来是`12H`，紧挨着的`DATA2`单元原来是`34H`。这时候我执行：

```assembly
MOV WORD PTR DATA1, AX
```

你们问`DATA2`还在不在。我画一下你们就明白了。`AX`是`16`位，低`8`位是`AL`，高`8`位是`AH`。这条指令是存储器写，而且用`WORD PTR`把`DATA1`临时当成字单元写，字单元以`DATA1`为首地址占两个字节。

写的時候还是老规矩：低字节写进低地址单元，高字节写进高地址单元。写完了，原来`DATA2`单元里的`34H`自然被覆盖了，值变了。但`DATA2`这个字节变量本身还存在，定义并没有消失，变的是它对应单元里的内容。这就是字类型和字节类型打架时一定会发生的事。

> **提示**：类型不一致时，谁覆盖谁只看指令的实际读写宽度，不看变量当初怎么定义的。

### 寄存器间接寻址的三个寄存器

下面看存储器寻址的第二种：寄存器间接寻址（`Indirect Addressing`）。

> **定义**：要找的操作数还在某个存储器单元里，该单元的段内`16`位有效地址`EA`（也就是偏移地址）间接放在一个地址寄存器里。

能间接给地址的只有三个：基址寄存器`BX`、源变址寄存器`SI`、目的变址寄存器`DI`。

前面例子里出现过`BP`，我在这里先把话说死：`BP`不属于间接寻址，间接寻址里没有`BP`。不管用`BX`还是`SI`还是`DI`，寄存器里`16`位的内容就是操作数所在单元的`16`位有效地址，段地址默认都在`DS`段。

### 两条指令把间接寻址走通

还是这组定义：

```assembly
DATA1 DB 12H
DATA2 DB 34H
```

变量名大小写无所谓。图上就是`DATA1`单元`12H`，下一个单元`DATA2`是`34H`。

我想把`DATA1`单元的数据读出来给`AL`，用`BX`间接怎么做。第一步先把偏移地址给`BX`：

```assembly
MOV BX, OFFSET DATA1
```

这条指令源操作数的寻址方式是什么。你们说是直接寻址，都不对，是立即数寻址。为什么。变量一旦定义就有五个属性，我现在取的是`DATA1`的`OFFSET`属性，属性值是个常数，字常数就是立即数。听懂了没有。

这条执行完，`BX`里的值就是那个单元的`16`位有效地址。第二步：

```assembly
MOV AL, [BX]
```

这就是`BX`间接寻址。功能是把`BX`的内容当段内`16`位有效地址，段默认`DS`，找到那个单元。这个单元是字节还是字。不明确，看另一方。另一方是`AL`，说明找到的是字节单元，把它读出来给`AL`。执行完`AL`等于`12H`。

这里用`SI`、`DI`完全一样，换个寄存器名字而已。

### 类型不明确与双存储器错误

再看这条：

```assembly
MOV [BX], 56H
```

源是立即数寻址，目的是寄存器间接寻址。功能是把立即数写进间接找到的单元。立即数没有类型，`[BX]`说明类型了吗。没有。所以这条语法错了，错在类型不明确。

> **易错点**：只要目的操作数用了某种存储器寻址，而源是立即数，类型必须明确，不明确就加`PTR`说明。

再编一组：

```assembly
MOV BX, OFFSET DATA1
MOV SI, OFFSET DATA2
MOV [BX], [SI]
```

源是寄存器间接找到一个单元，目的也是寄存器间接找到另一个单元，想把一个单元的内容直接送到另一个单元。想得美，不行。

为什么。`39`页图`3.8`早就总结了：两存储器单元之间不能直接传送数据。想把`[SI]`单元的数据送到`[BX]`单元，中间必须经过一个通用寄存器过渡。比如按字节操作就改成：

```assembly
MOV AL, [SI]
MOV [BX], AL
```

先读进`AL`，再从`AL`写出去，两条`MOV`才完成两单元之间的数据传送。用`DI`当目的也一样：

```assembly
MOV AL, [SI]
MOV [DI], AL
```

### 寄存器相对寻址的地址算法

再看存储器寻址的第三种：寄存器相对寻址（`Relative Addressing`）。

> **定义**：操作数还在某存储器单元里，该单元的段内`16`位偏移地址由两部分相加得到：一部分在基址或变址寄存器里，另一部分是一个`8`位或`16`位的相对位移量`DISP`。

```text
EA = (BX/BP/SI/DI) + DISP(8/16)
```

读图说明：寄存器给基址，`DISP`给偏量，两者相加才是真正的有效地址。

寄存器可以是`BX`、`BP`、`SI`、`DI`四个，这里把`BP`加回来了。如果`DISP`是常数，段地址看寄存器：用`BX`、`SI`、`DI`任意一个，默认`DS`；用`BP`，默认`SS`。

### `[BP]`为什么只能叫相对寻址

比如：

```assembly
MOV [BP], AL
```

功能是把`AL`写进一个字节单元，这个单元的地址由`BP`相对给，段默认`SS`，段内偏移一部分在`BP`里，另一部分加了个位移量`0`。你们上机验证一下就信了：这条汇编后操作码里藏着一个位移量`0`。所以`[BP]`这种写法只能叫寄存器相对寻址，不能叫寄存器间接寻址。记住这一条就够了。

### 直接寻址与相对寻址找同一个单元

还是`DATA1`放`12H`、`DATA2`放`34H`，我先：

```assembly
MOV BX, OFFSET DATA1
```

让`BX`指向`DATA1`的偏移地址，段默认`DS`。现在我想把`AL`写进`DATA1+3`那个单元。用直接寻址可以写：

```assembly
MOV DATA1+3, AL
```

`+0`、`+1`、`+2`、`+3`数过去，直接给出地址，目的就是直接寻址。

用相对寻址怎么做。我已经让`BX`指向那个基点了，写：

```assembly
MOV [BX+3], AL
```

`+0`、`+1`、`+2`、`+3`，加了个`8`位位移量。`BX`内容加`3`指到那个单元，把`AL`写进去。目的操作数这就是寄存器相对寻址。

位移范围一定要记住：`8`位位移以基点为基准，正方向最多`+127`字节，负方向最多`-128`字节；`16`位位移负方向到`-32768`，正方向到`+32767`。

书写格式还有等效写法：

```assembly
MOV [BX+3], AL
MOV [BX+03H], AL
MOV 3[BX], AL
```

加号放括号里还是放括号外一样，`3[BX]`把位移放左边时加号可以缺省，汇编出来的代码相同。用哪种全看顺手。

### 相对量是变量时的段地址

相对寻址还有一点。比如：

```assembly
MOV BX, 0
MOV AL, 0
MOV DATA1[BX], AL
```

目的地址是寄存器相对给的，但相对量不是常数，是个变量。这时取该变量的`16`位偏移量当相对量：

$$EA = OFFSET(DATA1) + (BX)$$

把`AL`写进这个有效地址对应的单元。

> **结论**：这时段地址不看寄存器了，看变量。变量在哪个段定义的，段基就是哪个段。在`ES`定义就在`ES`，在`SS`定义就在`SS`，在`DS`定义就在`DS`。

## 第 8 章：基址变址寻址与数据寻址收尾
> 对应分集：P31 | 原始标题：《基址变址寻址与数据寻址收尾》

我上次把寄存器相对寻址的概念立住了，今天先把`BP`相对那个最有用的例子做掉，然后把存储器寻址的后两种和数据寻址的收尾一次讲完。

### 用BP相对取栈中数据而不破坏SP

相对量是常数，段看寄存器；相对量是变量，段看变量在哪定义。这个结论先留着，我举个综合题让你们体会`BP`相对为什么默认`SS`。

让`8086`执行：

```assembly
PUSH AX
PUSH BX
PUSH CX
```

栈操作必须按字操作。`PUSH AX`就是`SP`减`2`，栈顶指到新字单元，把`AX`压进去，`AL`在低、`AH`在高。第二条`PUSH BX`，`SP`再减`2`，把`BX`压进去。第三条`PUSH CX`，`SP`再减`2`，栈顶跑到放`CX`的那个字单元。

现在叫你们干什么。把压在最底下那个`AX`的内容取出来放进`DX`，但不能破坏堆栈指针`SP`。

你们先想。能不能`POP`。一`POP`，`SP`就跑了，破坏了，所以不能`POP`。不用`POP`还想把栈底的值读出来，怎么弄。就要用`BP`相对默认`SS`的原理。

我做：

```assembly
PUSH BP
MOV BP, SP
MOV DX, [BP+4]
```

`MOV BP, SP`是寄存器寻址，把`SP`的`16`位值送`BP`，`BP`也指向栈顶了。但这样`BP`破坏了，题目没说能不能破坏`BP`，我假设能破坏；如果`BP`也不能破坏，前面先加一条`PUSH BP`保护起来。

现在以`BP`指的栈顶为基准，向上`+2`、`+4`，`[BP+4]`用寄存器相对寻址正好找到放`AX`的那个字单元。读出来给`DX`，`DX`就等于`AX`，`SP`一点没动。

我为什么说`BP`相对默认`SS`就是为了干这个。有些时候我想从堆栈里取数放数，又不想破坏`SP`，就用`BP`相对。当然实际编程时，也可以在这种寻址左边加段超越前缀去改段，前面讲过。

> **易错点**：寄存器相对做目的、源用立即数时，和间接寻址一样，类型必须明确。

### 基址变址寻址的地址算法

下面看存储器寻址第四种：基址变址寻址（`Based Indexed Addressing`）。

> **定义**：操作数还在某存储器单元里，该单元的段内`16`位有效地址由两部分相加：一部分在基址寄存器`BX`或`BP`里，另一部分在变址寄存器`SI`或`DI`里。

```text
EA = (BX/BP) + (SI/DI)
```

读图说明：基址出一份，变址出一份，相加才是有效地址。

段地址以基址为准，只看基址不看变址：基址用`BX`默认`DS`，基址用`BP`默认`SS`就是堆栈段操作。前面相对寻址里变量优先于寄存器，这里是基址优先，都要分清。

还是这组定义：

```assembly
DATA1 DB 12H
DATA2 DB 34H
```

内存里`DATA1`单元`12H`，下一个`DATA2`单元`34H`，下面还有很多单元不管。我想用基址变址把某个单元取出来给`AL`，先：

```assembly
MOV BX, OFFSET DATA1
```

让`BX`指向基点，再配上`SI`或`DI`的偏量，组合成`[BX+SI]`、`[BX+DI]`、`[BP+SI]`、`[BP+DI]`四种形式。段按基址定，类型看另一方是字节还是字。这就是基址变址的用法，后面做数组、做表格经常用它。

### 字符串操作数的隐含寻址

`8086`的字符串操作指令，源和目的全是隐含寻址（`Implied Addressing`）。比如：

```assembly
MOVSB
MOVSW
```

后面我没写操作数，但`CPU`执行这种串传送知道源串在哪、目的串在哪。源和目的的寻址方式都是隐含寻址，听懂了没有。

### 指令语句中变量不能运算

最后给个概念。比如：

```assembly
MOV AL, DATA1
```

`DATA1`是`DB`字节变量，把对应字节单元的数据送`AL`，字节传送，这是直接寻址。后面加个常数也行：

```assembly
MOV AL, DATA1+1
```

加`1`加`2`常数，还是直接寻址。但后面如果加个变量就不行：

```assembly
MOV AL, DATA1+DATA2
```

加的不是常数是变量，这条出现语法错误。`8086`汇编语法规定的：操作数项不允许变量在指令语句中运算。当然变量在`DW`这类伪指令语句里可以用加法，后面讲应用再说。

这样关于数据的八种寻址方式全部讲完了。难理解难掌握的正是关于存储器的五种，可程序设计天天用它，下去必须熟练复习掌握。

## 第 9 章：段内转移寻址与条件转移范围
> 对应分集：P32 | 原始标题：《段内转移寻址与条件转移范围》

我前面把关于数据的八种寻址方式讲完了，其中和存储器有关的五种要你们下去多做作业多上机。今天看寻址的第二大类：关于转移地址的寻址方式。程序要分支要循环就要转移，转移到目的地的地址是多少，怎么找，这就是转移地址寻址。

### 段内转移与段间转移的分工

转移地址寻址分两种：一种是段内转移，前面提过叫近程转移；一种是段间转移，从一个代码段一下跳到另一个代码段。

先看段内转移。段内转移后只有`IP`变了，`CS`没变。我要找的就是转移目的地的`IP`，也就是偏移地址，找到送`IP`就实现转移。

段内找目的地又有两种：段内直接寻址和段内间接寻址。

### 段内直接寻址的标号写法

段内直接寻址指转移指令中直接给出了转移目的地的地址，但地址用标号描述。你们早就见过标号，我举个例子。

代码段里编到某处，我以无条件转移`JMP`为例。想转到下面某条指令去，那条指令的地址程序员并不知道，用标号代替，假设叫`L1`：

```assembly
JMP L1
...
L1: ...
```

对这条`JMP`而言，指令中直接给出了转移目的地地址，这就是段内直接寻址。理解起来很好理解，难的是原理。

### 汇编时给的是相对位移量

汇编程序对你们写的每一行逐行翻译汇编。汇编到这条`JMP`时，先给一个字节操作码，操作码告诉`CPU`做无条件转移。转到哪去。操作码后面给的不是目的地绝对地址，而是相对位移量。

什么叫相对位移量。`CPU`执行完`JMP L1`如果不转移，顺序执行下来有个`IP`值，这个叫当前`IP`。从当前`IP`到转移目的地之间间隔多少字节，负向转就是负位移，正向转就是正位移。如果转移范围没超出`-128`到`+127`，这个位移就是一个字节`8`位，汇编程序就在操作码后给一个字节相对位移量。

汇编是自上而下逐行汇的。先汇这条`JMP`，往下汇才见到`L1`。负向转时间隔字节数已经能数出来，负数用补码表示位移。如果是正向转，汇这条时还不知道`L1`在哪，但知道是段内转，绝对不会超过`+32767`字节，所以统统按两个字节`16`位位移汇。这就是为什么负向没超`-128`的是双字节指令（`1`操作码+`1`位移），正向转全是三字节指令（`1`操作码+`2`位移），负向超`-128`但没超`-32768`的也是三字节。

你们想省空间，正向转又明确知道不会超`+127`，可以写成：

```assembly
JMP SHORT L1
```

告诉汇编这是`SHORT`短转移。短就是以当前`IP`为基准，负不超`-128`正不超`+127`，比近还近。汇出来双字节，`1`操作码+`8`位位移。

### CPU执行时当前IP加位移

`CPU`执行`JMP`就是执行操作码，就知道要无条件转，转移目的地`IP`等于什么。等于当前`IP`加相对位移量。

双字节和三字节操作码肯定不同。`CPU`执行这条时手里有`IP`，双字节指令`IP+2`就是当前`IP`。紧跟操作码的下个单元取出来，不当操作码用，当位移用，加到当前`IP`上就是目的地`IP`。所以好多教材把段内直接寻址也叫段内相对寻址。相对的概念来自`CPU`执行原理，直接的概念来自语句写法。用起来好用，理论上有难度。

### 条件转移只能段内短转移

`8086`所有条件转移指令只能段内转。无条件`JMP`段内段间都行，条件转移只能段内，且范围以当前`IP`为基准`-128`到`+127`字节。

你们编源程序，条件转的范围超了这个，编译时屏幕告诉你转移范围溢出。肉眼看不见，编译程序能算出来。这时候怎么办。必须转又超范围，就用`JMP`搭桥二级跳：先条件跳到附近目的地`1`，在目的地`1`里再`JMP`到真正目的地。实际应用一定要注意。

还有一点：所有条件转移指令的寻址方式都是段内相对寻址，也就是段内直接寻址。记住这一条。

### 一道只做对寥寥无几的填空题

有一年考试有道题：`8086`执行`JZ L1`，说`IP=0100H`，`DISP=FDH`，问执行后`IP`等于多少。

动动脑筋。`JZ`是条件转，肯定双字节，`1`操作码+`8`位位移。`IP=0100H`是这条指令所在偏移，`0100H`放操作码，`0101H`放位移，跑到`0102H`就是当前`IP`。位移`FDH`是多少。补码，`-3`。计算机带符号数用补码，这是考的第二个点。

所以目的地`IP = 0102H + (-3) = 00FFH`。相当于跳到前面那个单字节指令去了。那年做对的寥寥无几，后来这种抽象题都不敢出了。你们看我出这个题，就是看刚才的概念你们理解几分。

### 段内间接寻址的含义

段内转移第二种：段内间接寻址。

直白说就是转移目的地的`IP`间接在某个地方放着。间接的概念从数据寻址讲到现在应该能理解了。存储器地址用`[BX]`间接，操作数所在单元地址间接在`BX`里，把`BX`读出来才是地址。这里一样，目的`IP`间接放着，取出来送`IP`就转过去了。具体哪些形式能间接，后面讲`JMP`间接时再展开。

## 第 10 章：多分支转移桥与跳转表实现
> 对应分集：P33 | 原始标题：《多分支转移桥与跳转表实现》

我上节把段内直接寻址讲透了，今天先把段内间接寻址回顾一句，然后举个多分支的例子。你们听完就知道间接转移在程序里到底好在哪。

### 段内间接寻址的应用位置

我要找某个单元，单元里放的是转移目的地的偏移地址，从单元里取出偏移送`IP`，不就实现转移了吗。那找这个单元的地址有几种办法。关于存储器的五种寻址任何一种都能找到，听懂了没有。这就是段内间接寻址。

它在实际程序里用得着，但没有段内直接用得广泛，直接用起来也简单。下面这个例子就是间接最漂亮的用法。

### AL等于几就转到哪里去

我编一段程序，不同分支分别是`L1`、`L2`、`L3`。现在叫你们在红粉笔括号那块编一段实现转移：按`AL`的值，若`AL=1`转`L1`，`AL=2`转`L2`，`AL=3`转`L3`，不是`1`、`2`、`3`就顺序下来。能听懂吗。就是在那块测`AL`，等于几跳哪里。

最笨的办法就是测：`AL`等于`1`吗。是跳过去，不是往下；等于`2`吗。是跑过去，不是又下来；再测等于`3`吗。是跑那，不等于下来。我这只有三项，如果给你们二十项呢。等于`19`吗。不是。等于`20`吗。是，找到了。这样一直排下去，顺序比较效率高吗。不高，能实现但效率不高。

我举这个例子就是要你们找一种提高效率的算法。假如从当前`IP`到目的地相对位移没超`-128`到`+127`，超了处理不一样，但这里先不管，重点看段内。

### 用SHORT搭一座转移桥

看我的笨办法行不行。我建一个分支跳转表，也叫转移桥：

```assembly
TABLE: JMP SHORT L1
       JMP SHORT L2
       JMP SHORT L3
```

`AL=1`跳第一条，从这再跳`L1`；`AL=2`跳第二条，再跳`L2`。这里还有什么关系。如果这些`JMP`全是`SHORT`型，全是双字节指令，排开位移是不是按`2`、`2`、`2`递增。

我都提示到这了。当`AL=1`位移`0`，输入`n`时位移和`n`的关系就是：

$$位移 = (n-1) \times 2$$

`n=1`时`(1-1)*2=0`，`n=2`时`(2-1)*2=2`，`n=3`时`(3-1)*2=4`。看懂了没有。

### DEC加ADD算出桥上偏移

前面先对`AL`减`1`，用`DEC`也行`SUB`也行：

```assembly
DEC AL
```

减`1`后要乘`2`，没学移位就用加法，自身相加就是乘`2`，左移一位也行：

```assembly
ADD AL, AL
MOV AH, 0
```

清零是为了扩展用`AX`。然后把桥首地址取出来：

```assembly
MOV BX, OFFSET TABLE
ADD BX, AX
JMP BX
```

`TABLE`标号给`BX`当基地址，加`AX`算出目标跳转指令地址，`JMP BX`段内间接转到桥上对应分支指令。

验证一下。`AL=1`时`AX=(1-1)*2=0`，`BX+0`等于`OFFSET TABLE`，`JMP BX`跳到`JMP SHORT L1`，顺利到`L1`。`AL=2`时`AX=2`，基址加`2`跳到第二条`JMP SHORT L2`，到`L2`。`AL=3`时`AX=4`，跳第三条到`L3`。这就是用`JMP`在这里做转移桥，跳转表。
