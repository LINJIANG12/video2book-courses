## 第 1 章：循环效率优化与子程序定义
> 对应分集：P45 | 原始标题：《循环效率优化与子程序定义》

我上次编的统计`BX`中`1`个数，从头看程序没问题，但最坏情况效率很低。今天把结构变一下，顺手把子程序定义讲了。

### 最坏情况白跑十六遍

假如最坏一开始`BX`全`0`，有没有可能。有。这种`CPU`在这循环`16`遍，花这么多时间最后得`0`，效率低。还有`0000 0000 0000 0010B`，第一遍得`0`第二遍得`1`，后面`14`遍全`0`没统计出结果，效率都低。

### 先判定后工作提前退出

为提效把结构变一下：

```assembly
MOV CX, 16
MOV AX, 0
L2: CMP BX, 0
JE EXIT
SHR BX, 1
JNC L1
INC AX
L1: LOOP L2
EXIT: MOV AH, 4CH
INT 21H
```

`CX`给次数后`CMP BX, 0`先判定，结果`0`相等跳`EXIT`退出，程序结束`INT 21H`。否则`SHR`右移一次，没进位`JNC`跳`L1`，有进位`INC AX`。`L1`处`LOOP`减`1`没到`0`跳`L2`。移位高位补`0`，移后`BX`再和`0`比，为`0`提前退出，效率上来了。

这显然先判定后循环工作，前面是先工作后判定，不一样。实际设计先分析：会不会零次循环或提前退出。有可能为提效用先判定后工作，没有用先工作后判定。但不管哪种，初始化、工作、修改、判定都在，本题出口主要比较判定决定。书`69`页例`3.32`把这功能做成子程序，统计`AX`中`1`个数，题目一样。

### 子程序概念与过程定义

剩下时间讲新知识。`3.11`子程序调用返回和`4.5`子程序设计放一块讲，子程序就完整了。

了解子程序先类比`C`函数。程序经常完成特定功能，每次重写冗余，为结构化把常用功能定义函数，用时调用。汇编一样，把常用特定功能段定义子程序，用时调用指令调用。汇编子程序也叫过程（`Procedure`），定义子程序就是定义过程。

过程定义伪指令`PROC`，格式：

```assembly
过程名 PROC [NEAR/FAR]
...
RET
过程名 ENDP
```

`PROC`左边写子程序名，规则和标号变量段名一致，首字符必须是字母，尽量有含义，比如显示屏幕叫`DISPLAY`好读。右边可选属性类型，后面说。

### NEAR与FAR过程类型

两种。用`PROC`定义的子程序和`CALL`所在同代码段，叫段内子程序，`NEAR`型，可缺省。`CALL`要调的子程序和`CALL`不在同代码段，叫段间调用，子程序段间远程`FAR`型，不能缺省必须写`FAR`。`FAR`肯定`SEGMENT`新代码段里定义。

### 过程体返回与结束伪指令

`PROC`下方具体指令段叫子程序体或过程体。写完写`RET`返回，`CPU`执行回到`CALL`下方紧邻地址。段内直接`RET`，段间远程调用：

```assembly
CALL FAR PTR 子程序名
```

返回严格该`RETF`。实际`RETF`可直接写`RET`，因为汇编自上而下翻译，扫到`PROC`已知过程开始，`PROC`后已指定类型，若`FAR`已记录，汇内部`RET`自动翻`RETF`机器码，所以可直接写`RET`。

写完`ENDP`告诉汇编结束，`ENDP`左边必须写名，且和`PROC`左边完全一致。

子程序定义抓三点：名一致，`PROC`、`ENDP`成对和`SEGMENT`、`ENDS`同，过程名一旦`PROC`定义具备标号三属性：段基`SEG`、偏移`OFFSET`即首条指令地址、类型`NEAR`或`FAR`。过程名等价首条指令标号。

### 主程序调用与模块化代价

实际把反复特定功能定义子程序，含`CALL`那段叫主程序主调，被调叫被调程序。工程即使只用一次也尽量独立子程序，这样模块化：各子程序各管功能，核心由模块搭，主程序初始化后主体基本连续`CALL`下方各模块。

模块化核心是便于维护升级。比如给单位软件交付后运行稳定，生产变了要加功能：非模块化要通读冗长段中间插入，重调易错，新没调通反坏老功能；模块化下方独立新子程序，主流程加一行`CALL`就行，新老不干扰。所以提倡模块化。

代价是费时间。每次调`CALL`保护压栈占周期，`RET`出栈返回也耗时，以时间换清晰维护，整体系统分析这点内部时间没影响，程序尽量模块化。这是子程序定义。

### 段内调用示例

第三个问题子程序调用返回，分近程远程，先看段内。用户程序可没堆栈没数据，但必须代码段。从代码段开始：

```assembly
CODE SEGMENT
ASSUME CS:CODE
START:
; ...主程序
CALL SUB1
```

编到要完成功能，那功能已定义子程序，假设叫`SUB1`就`CALL SUB1`，叫`SUB`加`1`加`2`都行。这种寻址就是段内直接。回想`JMP`转移寻址同样适用`CALL`，`CALL`本质无条件转移。先写到这。

## 第 2 章：段间调用返回与现场保护参数传递
> 对应分集：P46 | 原始标题：《段间调用返回与现场保护参数传递》

我结合`3.11`子程序调用返回和`4.5`子程序设计，重点讲完使用场景、控制指令、定义，剩下调用返回细节、现场保护、参数传递今天收尾。

### 段间调用与返回的堆栈时序

`CPU`执行段间调用远程调用时序和堆栈如下。假设初始栈指针`SP`指初始栈顶：

```text
        +---------------+
        |      ...      |
        +---------------+
 SP --> |  初始栈顶单元  |
        +---------------+
        |               |
```

`CPU`执行段间调用如`CALL FAR Sub1`时分两步。第一步保护断点：`SP`减`2`指向新栈顶，把段寄存器`CS`返回地址压栈；`SP`再减`2`指向下栈顶，把指令指针`IP`返回地址压栈。第二步转移执行：把子程序名`Sub1`段地址送`CS`，偏移送`IP`，`CS:IP`指向子程序入口，转去执行，实现段间调用。

子程序完执行`RETF`远程返回：以当前`SP`为栈顶弹一字送`IP`，`SP`增`2`；以增`2`后`SP`为新栈顶再弹一字送`CS`，`SP`再增`2`。此时`SP`恢复调用前初始位置，`CS`、`IP`指回断点，正确返回。

> **补充**：上面是段间直接寻址，段内段间都可用间接寻址，间接实际较少但要掌握。

### 堆栈平衡与PUSH配对要求

`CPU`远程调用进子程序体执行内部指令时，如果子程序用了堆栈`PUSH`、`POP`，`SP`会跑。当执行到最后返回时，必须`SP`重新指回保存断点`IP`、`CS`的栈顶，才能正确返回。体内破坏`SP`不复原，程序回不去。

> **结论**：子程序用堆栈`PUSH`、`POP`必须严格配对，保证`RET`、`RETF`时堆栈平衡。

### 现场信息的保护与恢复

主程序调子程序前通用寄存器常有重要数据，希望调完保持不变，但子程序运算也要用寄存器，不处理就覆盖破坏。

处理机制就是现场保护恢复：子程序用寄存器前`PUSH`压栈保存，结束`RET`前`POP`逆序出栈恢复。位置两种：在子程序里做，首部压栈末尾出栈；在主程序做，`CALL`前`PUSH`返回后`POP`。实际绝大多数在子程序做。

出栈恢复注意两点：守后进先出，前面`PUSH`后面`POP`必须配对。只有严格配对`SP`不破坏，`RET`才能正确回主程序。

### 子程序参数传递的三种方法

`C`函数调要传入参带回返回值，汇编同样有入口参数出口参数。三种方法：

第一通用寄存器传递。最简单直接高效，局限是数量受限，`8086`一共`14`个寄存器，超了没法用。

第二存储器单元传递。数据段预定义变量单元，`CALL`前把参数写入变量，子程序开头再从单元取入口参数，返回出口同样寄存器或内存都行。比寄存器繁琐，但能传大量参数，突破数量限制。

第三堆栈区传递。堆栈本质同样存储器，可把参数压堆栈，子程序按约定偏移寻址取。用堆栈传要注意`SP`变化。

回顾一下，`3.11`加`4.5`重点讲了：何时划分用子程序，调用`CALL`返回`RET`、`RETF`段内段间，定义`PROC`、`ENDP`规范结构，加上今天的参数三种、保护恢复，子程序就完整了。

## 第 3 章：子程序说明文件、嵌套、递归与可再入性
> 对应分集：P47 | 原始标题：《子程序说明文件、嵌套、递归与可再入性》

如果我编的程序是卖给某个单位的生产软件，别人拿去要用、要改、要扩充，我在子程序前面该留点什么？这就是我们这一讲要先解决的问题：子程序说明文件。然后顺着它，把嵌套、递归、可再入这三个最容易写错的地方一次讲透，最后落到书上例 4.9 偶校验题的题意上。

### 子程序说明文件

我把子程序写在下面，调用的人根本没见过我这段代码，他怎么敢调？靠的就是子程序前面那一段文档，叫子程序说明文件。

> **定义**：子程序说明文件是写在子程序前方的一组注释行，每一行都必须以分号 `;` 开始，说明这段子程序怎么调。

它一般包含六点：

1. 子程序名。写清楚名字，别人才能按名调用。
2. 子程序功能。用文字把这段子程序到底干什么讲清楚。调用者先看功能合不合要求，不合要求后面都不用看了。
3. 入口参数。子程序里要算的东西，需要主程序带进来，什么参数放在 `AX`，什么放在 `CX`，什么放在 `SI`，都要说明。
4. 出口参数。子程序算完，结果放在哪里，主程序到哪里去取。入口和出口参数的传递，不外乎三种方法：寄存器传递、存储单元传递、堆栈传递。
5. 用到的寄存器（用存储单元传递时还要写明用到的存储单元）。这一点很关键。我编的子程序可能做成一个包放在光盘上往外卖，别人买回去要用。如果我的子程序用了 `AX`、`BX`，而用户自己的程序里这几个寄存器的值又不能破坏，用户在 `CALL` 之前就会先把它们 `PUSH` 保护起来。所以写明寄存器，等于告诉用户要做好现场保护。
6. 举例。把调用过程举个例子，用户照着抄就能调。

你们做作业可以不写，但做产品开发，每个子程序前面都要带上。一到五点写清楚了，用户就会调了，所以第六点常常省略，反正你一定会了。我这么说，你们就知道第六点为什么总见不到。

### 子程序嵌套

嵌套的概念一看就清楚：子程序自己又去调别的子程序。

```text
主程序                 SUB1 (PROC NEAR)          SUB2
  |                        |                      |
  |-- CALL SUB1 ---------> |                      |
  |   (IP压栈保护)         |-- CALL SUB2 --------> |
  |                        |   (IP压栈保护)        |-- ... 
  |                        |                      |-- RET -> 回SUB1断点
  |                        |<- RET ---------------|
  |<- RET -----------------|  回主程序断点
```

我在主程序里 `CALL SUB1`，`SUB1` 是段内子程序，直接写名字就是直接寻址。当前 `IP` 压栈保护，流程转到 `SUB1` 里面。`SUB1` 一开始照例要做现场保护。执行到中间，它又 `CALL SUB2`，当前 `IP` 再压栈，转到 `SUB2` 去。`SUB2` 跑完执行 `RET`，从堆栈弹出返回地址给 `IP`，回到 `SUB1` 的断点接着往下跑；`SUB1` 跑完再 `RET`，弹出属于它的返回地址，回到主程序。

这里有两点一定要记住。

第一，嵌套级数原则上不受限，实际上受堆栈限制。就算不算现场保护，光算 `CALL` 一次压一个返回地址，`SP` 就减 2，一直嵌套下去，堆栈就往上长。堆栈空间定义小了，`SP` 就溢出了。所以定义堆栈段时要留够地方。

第二，设计自上而下，调试自下而上。我们设计时是 `SUB1`、`SUB2`、`SUB3` 自上而下拆功能，调试时一定要先调最底层的 `SUB2`，调通了再调上一层，这样上层调下层时，拿到的结果才是对的。不然你都不知道错在上层还是下层。

### 子程序递归

递归就是自己调自己。比如 `SUB2` 还没结束，里面又出现一条 `CALL SUB2`。

你们想想，这时候最怕什么？怕没有出口，写成死循环。所以递归子程序里一定要有条件判断，比如算到某一步产生 `ZF`、`OF` 这些标志，判断一下满足了就退出，一层一层 `RET` 回去。

工程上偶尔会见到递归，但面很窄，我建议你们尽量避免。能用循环、能用嵌套讲清楚的，就不要用递归。

### 子程序可再入性

可再入是什么意思？看这个场景就明白了。

```text
SUBx 执行中 (执行到某条指令)
   |
   | 某事件提中断请求，CPU响应
   v
中断服务子程序
   |-- CALL SUBx (同一个子程序)
   |-- RET (拿到正确结果)
   |
IRET 回到原 SUBx 断点
   |
   v
原 SUBx 继续执行，也能拿到正确结果 -> 可再入
```

我正在执行 `SUBx`，执行到某条指令时，来了一个中断请求。`CPU` 执行完当前这条指令，下一条先不执行了，转去执行中断服务子程序。而中断服务子程序里面，很可能也 `CALL` 了同一个 `SUBx`。如果这样调完能拿到正确结果，中断返回后，原来那个 `SUBx` 继续跑也能拿到正确结果、正确返回，这就叫可再入。

这一块结合书上 3.11 节子程序调用与返回指令和 4.5 节子程序设计技术看，概念就全覆盖了。

### 例 4.9 题意：给缓冲区字符加偶校验

概念讲完，我们看一道题。以后复习就看书上的例子，我讲书上例 4.9。

存储器在 `CPU` 外面，我在程序里定义了数据段，数据段里定义了一个 `BUFFER` 缓冲区，里面放的是字符。题目让你给每个字符加上偶校验。

这里有两个隐含条件。第一，字符是字节型的 `ASCII` 码。第二，题目没说有多少个字符，个数你自己定。书上 119 页第三行用等号定义了 `N=22`，就是 22 个。你们也可以用我上上周讲的方法，`BUFFER DB '...'` 定义一个字符串，再用 `COUNT EQU $ - BUFFER` 算出个数，两种都可以，实际工作中后一种更通用。

什么叫偶校验？`ASCII` 码原则上 7 位表示一个字符，放到按字节组织的存储器里，一个字节 8 位，最高位 `D7` 肯定是 `0`。如果不是 `0`，那肯定不是字符。加上偶校验，就是先数一下这个字节里有几个 `1`：如果是偶数个 `1`，最高位配 `0`；如果是奇数个 `1`，最高位配 `1`，凑成偶数个 `1`。这就叫偶校验，听懂了没有？

解题思想 118 页开头已经写了。118 页一开头先定义堆栈段，段名就叫 `STACK`，组合类型选 `STACK`，类名也给了。里面用 `DW 200 DUP (?)` 定义了 200 个字。堆栈到底定义多大？看实际需求，我以前讲过，要留 30% 左右的富余量，便于以后维护扩充。`STACK ENDS` 就结束了。

> **提示**：书上这里还用 `LABEL` 定义了一个 `TOP` 变量，我就不定义了。原因上次讲过：组合类型已经选了 `STACK`，说明这段就是堆栈段，代码段里就不用再对 `SS` 和 `SP` 初始化了。

## 第 4 章：例4.9偶校验程序的数据段代码段与寄存器传参
> 对应分集：P48 | 原始标题：《例4.9偶校验程序的数据段代码段与寄存器传参》

上节把堆栈段定了，`STACK ENDS` 写完，这节我们接着把数据段、代码段补上。还是例 4.9，`BUFFER` 里一串字符，我要一个一个数里面有几个 `1`，配成偶校验。用寄存器传参，先把框架跑通。

### 数据段定义与字符个数统计

再定义数据段：

```assembly
DATA SEGMENT
    BUFFER DB '...'
    COUNT  EQU $ - BUFFER
DATA ENDS
```

定位类型缺省，本段就缺省了。组合类型是不是 `NONE` 型？本段跟别的模块的任何段都没有关系，就是告诉链接程序，链接时本段就是本段，别跟谁合并。

`BUFFER DB ...` 定义一个字符串，具体是什么字符我就不写了，做题嘛，可以吧？关键是字符个数怎么来。按说要定义一个符号常量 `COUNT`，用 `=`、用 `EQU` 都可以，等于 `$ - BUFFER`。这个表达式的值赋给 `COUNT`，`COUNT` 是不是就是单引号里字符的个数？这讲过了。

### 代码段定义与DS初始化

再定义代码段：

```assembly
CODE SEGMENT
    ASSUME CS:CODE, DS:DATA
    ASSUME SS:STACK
START:
    MOV AX, DATA
    MOV DS, AX
```

代码段一开始是不是要段寻址？`CS` 是 `CODE` 段名指的段，`DS` 是 `DATA` 段名指的段。写不下一行再写一行，`SS` 是 `STACK` 段名指的段。

`START` 是首地址的名字，自己起的，叫 `START` 容易理解一点。有了数据段，代码段一开始肯定先对 `DS` 初始化：

```assembly
    MOV AX, DATA
    MOV DS, AX
```

你们注意，这应该是第三遍了。`MOV AX, DATA` 源操作数是什么寻址？立即寻址。段地址不能直接送 `DS`，先过 `AX` 一下。

### 寄存器传参与CALL SETEVEN

初始化完了，下面要对 `BUFFER` 里每个字节测有几个 `1`，偶数个还是奇数个，从而配偶校验。上节课我们做过没有？做过。上节课测 `BX` 里有多少个 `1`，那是 16 位，这是 8 位，当时用的是移位法。

我把统计工作拿子程序实现。调子程序之前，你得先告诉它：被测字符在哪？有多少个？这都是入口参数。先用寄存器传递：

```assembly
    MOV CX, COUNT
    LEA SI, BUFFER
    CALL SETEVEN
```

`CX` 放个数，`SI` 放缓冲区首地址的偏移地址，段地址在 `DS` 里。看到了没有？这都是在做入口参数准备。准备好了，`CALL SETEVEN`，它就能把每个字符有几个 `1` 统计出来，决定最高位加 `1` 还是加 `0`。

书上这个子程序叫 `SETEVEN`。我在 `CALL` 之前把个数给 `CX`，首地址书上给 `DI` 了，我这给 `SI` 了。一样不一样？用的地址寄存器不一样，设计思想是不是一样的？

假如是段内调用，直接 `PROC` 定义就行。如果是段间子程序，上面还要 `SEGMENT` 再定义一个逻辑段，`SEGMENT` 下面还要 `ASSUME` 告诉汇编程序 `CS` 段地址，然后才能定义子程序。

### SETEVEN现场保护与嵌套结构

```assembly
SETEVEN PROC NEAR
    PUSH AX
    PUSH BX
    PUSH CX
    PUSH SI
    MOV  AL, [SI]
    ...
```

类型 `NEAR`，缺省了。子程序一开始，书上是 `PUSH AX`、`PUSH BX`、`PUSH CX`、`PUSH DI`，把四个寄存器的值压栈保护。我用了 `SI`，那我就 `PUSH SI`。保护的目的，是下面准备用这些寄存器，先把原值保住。

你们还可以在 `SETEVEN` 前面写个子程序说明文件，我刚好把黑板擦了，你们自己写。分号开头，一、子程序名，二、功能，三、入口，四、出口，五、用到的寄存器，写清楚就行。

这个子程序实际上用了嵌套。`MOV AL, [SI]` 是间接寻址，把 `SI` 指的那个单元取到 `AL`。取出来干什么？调下一个子程序去数 `1` 的个数：

```assembly
COUNT_BYTE PROC
    ; 入口参数：AL (被统计字节)
    ; 出口参数：BL (其中1的个数)
    RET
COUNT_BYTE ENDP
```

`COUNT_BYTE` 我就不编了，作用就是统计一个字节里有几个 `1`，入口在 `AL`，出口在 `BL`，用通用寄存器把结果带回来。

都完了，子程序返回，`ENDP`。哪个子程序结束了？`SET_SEG` 就 `RET` 加 `SET_SEG ENDP`。

整个程序结束，代码段才结束：

```assembly
CODE ENDS
END START
```

### 堆栈变化与SP计算

下面看堆栈的变化。

```text
高地址
+------------------+
| 栈底 SS:0        | <- 堆栈段开始
|                  |
|  200字 = 400字节  |
|                  |
+------------------+ <- SP初始位置 (栈底+100H偏移)
|  ... 压栈生长 ... |  向低地址生长
+------------------+
低地址
```

堆栈段从这开始，栈底在 `SS` 偏移 `0` 处。定义了 200 个字，是不是 400 个字节？

$$200 \times 2 = 400\text{字节}$$

初始化以后 `SP` 指的就是栈底加 `100H` 的偏移地址。400 个字节，你就能算出 `SP` 等于多少。能算出来吧？现场保护压一次 `SP` 减 2，恢复弹出一次 `SP` 加 2，先进后出，对上就行。

> **易错点**：`LEA SI, BUFFER` 取的是偏移地址，不是内容；`MOV AL, [SI]` 才是间接寻址取内容。考试最爱在这里绕你们。

## 第 5 章：堆栈传参与BP寻址取参及RET n平栈
> 对应分集：P49 | 原始标题：《堆栈传参与BP寻址取参及RET n平栈》

寄存器传参讲完了，用 `CX` 传个数、`SI` 传首址，简单是简单，可寄存器就那么几个，参数一多就不够用了。这节我们换一种：把缓冲区首址和字符个数压到堆栈里带进去。压进去容易，难的是在子程序里怎么取出来还不把栈搞乱。

### 主程序压栈传参与CALL执行

把缓冲区首址压入堆栈，告诉子程序：“缓冲区首址在这，你去取。”个数也一样压进去。此时 `SP` 指在栈顶。然后执行 `CALL`。

`CPU` 执行 `CALL` 时，先保护返回地址 `IP`：`SP` 减 2，栈顶移到新位置，把下一条指令的偏移地址也就是返回地址压栈。然后流程转到子程序里去。

$$SP \leftarrow SP - 2$$

### 子程序现场保护

进入子程序，先连续压栈保护现场：

```assembly
PUSH AX
PUSH BX
PUSH CX
PUSH SI
```

第一次保 `AX`，第二次保 `BX`，第三次保 `CX`，第四次保 `SI`。`SP` 一路下移，指到当前位置。

### 为什么不能用POP取参

现场保护完了，子程序要干活：统计指定字节有几个 `1`，判断偶奇，配偶校验。要干活就得拿到两个参数：待校验缓冲区的首地址，待校验字符的个数。它们都在堆栈里。

核心问题来了：怎么取？

不能用 `POP` 弹。为什么？`RET` 返回时，`SP` 必须指在保存返回地址 `IP` 的位置，才能弹给 `IP`。你提前 `POP` 把参数弹走了，`SP` 就错位了，`RET` 就回不去了。所以，堆栈传参绝不能用出栈指令取参。

### 引入BP与MOV BP SP

为了解决这个问题，引入基址指针寄存器 `BP`：

```assembly
PUSH BP
MOV  BP, SP
```

子程序里要用 `BP`，不管主程序用没用过，先 `PUSH BP` 保护原值，`SP` 减 2。再执行 `MOV BP, SP`，寄存器寻址，把 `SP` 当前值送给 `BP`。`BP` 就指向了存放原 `BP` 值的那个字单元。

> **定义**：以 `BP` 作基址相对寻址时，默认段寄存器是堆栈段 `SS`。这一点是后面算偏移的依据。

### BP相对寻址提取参数

既不破坏 `SP`，又能拿到参数，靠的就是 `BP` 加位移。堆栈从上往下的布局是这样的：

| 偏移地址 | 存放内容 |
| :--- | :--- |
| `[BP+0EH]` | 字符个数 |
| `[BP+0CH]` | 缓冲区首址 |
| `[BP+0AH]` | 返回地址 `IP` |
| `[BP+08H]` | 保护的 `AX` |
| `[BP+06H]` | 保护的 `BX` |
| `[BP+04H]` | 保护的 `CX` |
| `[BP+02H]` | 保护的 `SI` |
| `[BP+00H]` | 保护的 `BP`，`BP`、`SP` 当前指向处 |

所以取参就两条：

```assembly
MOV SI, [BP+0CH] ; 从堆栈段取出首址给SI
MOV CX, [BP+0EH] ; 从堆栈段取出个数给CX
```

看到了没有？充分利用 `BP` 相对寻址、段地址默认在 `SS`，在子程序开头就把主程序 `CALL` 之前压进去的参数拿到了，`SP` 一动没动。

### 嵌套COUNT_BYTE与寄存器带回

参数拿到，继续往下，调嵌套子程序。教材例 4.9 第 118 页调的 `COUNT_BYTE` 在 120 页，逻辑是：进子程序保护现场，置循环计数 `CX=8`，累加器 `BL` 清零，`AL` 循环移位逐位判断是 `1` 还是 `0` 累到 `BL`，`LOOP` 8 次后 `RET`。结果在 `BL` 里，用通用寄存器 `BL` 把结果带回来。不用 `BL`，用堆栈带回也行，两者皆可。

### 现场恢复与RET返回

快返回了，必须按压栈相反的顺序恢复：

```assembly
POP BP
POP SI
POP CX
POP BX
POP AX
RET
```

`POP BP` 弹给 `BP`，`SP` 加 2，再依次 `POP SI`、`CX`、`BX`、`AX`。弹完 `POP AX`，`SP` 正好回到返回地址 `IP` 处。

> **提示**：往年总有人问，`POP AX` 把栈单元的值送 `AX`，原来单元里的值跑哪去了？物理上还在，只是 `SP` 移走了，那个单元退出了有效栈区，后面压栈直接覆盖旧数据。

此时执行 `RET`，从栈顶弹出返回地址给 `IP`，回到主程序断点。

```text
调用前SP -> [参数个数][首址]
CALL后   -> [参数个数][首址][IP]
保护后   -> [参数个数][首址][IP][AX][BX][CX][SI][BP] <- SP/BP
取参      BP+0CH / BP+0EH (SP不动)
恢复后SP -> [参数个数][首址][IP] <- SP指IP
RET      -> [参数个数][首址]      SP+2
```

### 带参数返回RET 4平栈

问题就出来了。`CPU` 执行 `RET`，把 `SP` 指的栈顶弹一个字给 `IP`，`IP` 回主程序了，`SP` 增 2：

$$SP \leftarrow SP + 2$$

程序看似结束了，`SP` 恢复了没有？没有。因为调用前执行了两次 `PUSH`，`PUSH`、`POP` 该配对，可这里 `POP` 已经没意义了，参数不需要恢复给谁。

哪怕程序结束了，下面还有人用堆栈呢？每次用完 `SP` 都偏 4 个字节，累积下去总有一次溢出，显然不行。必须让 `SP` 回到最初位置。

既然 `POP` 没意义，又必须恢复，直接对 `SP` 修正就行：

```assembly
RET 4
```

`CPU` 执行 `RET 4`：先从栈顶弹一个字给 `IP` 实现返回，本身 `SP` 增 2，在此基础上硬件自动再加 4，丢掉 4 字节参数：

$$SP \leftarrow SP + 2 + 4$$

在增 2 的基础上再增 4，`SP` 就回到调用前了，这就叫堆栈平衡。

## 第 6 章：带参数返回RET n与中断源结构
> 对应分集：P50 | 原始标题：《带参数返回RET n与中断源结构》

`RET 4` 上节讲完了，可我把题变一下你还会吗？段内返回 `RET 4` 执行前后 `SP` 等于多少都会，段间返回 `RET 4` 呢？把这个问题掰清楚，3.11 节就收尾了。然后我们翻到 3.12 节，中断调用与返回，不把第八章拉回来根本看不懂。

### 段内段间RET n与SP变化

`CPU` 执行段内 `RET 4`，`SP` 等于多少？执行后又等于多少？应该会了。反过来，段间 `RET 4` 呢？

段间调用时保护了 `CS` 又保护了 `IP`，返回要恢复 `IP`、恢复 `CS`，本来段间返回 `SP` 就增 4，在此基础上再增一个 4。这就是带参数的 `RET` 返回。

书翻回 3.11 节，69 页上边数第二行：

```assembly
RET n
```

由于 8086 对堆栈按字操作，`n` 肯定是偶数。你来个 `RET 3`、`RET 5`，显然错了。

这样 3.11 节讲完了，严格讲 4.5 节也讲完了。不管哪节，后面给的例题都是课外阅读题。你们要多读程序，程序都读不下去，谈不上编。明白了吧？

### 中断概念与IRET返回流程

3.12 节讲中断调用与返回。要吃透，必须碰第八章。光看 3.12 看不懂，所以我把第八章的知识点拉回来讲。

首先什么叫中断？`CPU` 在执行程序期间，由于某事件发生了，好比执行到某条指令时，一个事件请求 `CPU` 为它服务。`CPU` 如果允许，就暂停执行下一条指令，转到中断服务子程序里去，执行这段程序为那个事件服务。服务完，最后应该有中断返回指令：

```assembly
IRET
```

`CPU` 执行 `IRET`，就能正确回到刚才的中止处，接着原来的程序往下执行。这么一个过程叫中断。

`CPU` 型号不同，响应中断、让 `CS` 和 `IP` 指向中断服务程序入口、找到地址转过去的方法不同，得看具体型号。

### 中断源与NMI INTR引脚

谁引起的中断请求，那个事件源就叫中断源。中断源可以在 `CPU` 内部，也可以在外部。外部中断源要向 `CPU` 请求，必须经过 `CPU` 的某个中断请求输入引脚。

8086 外部中断请求输入引脚有两个：`NMI` 和 `INTR`。

- 经 `NMI` 提出的中断，`CPU` 无条件响应，叫外部非屏蔽中断请求。
- 经 `INTR` 提出的中断，`CPU` 是否响应受中断标志 `IF` 控制。

| 引脚 | 类型 | 响应条件 |
| :--- | :--- | :--- |
| `NMI` | 外部非屏蔽中断 | 无条件响应 |
| `INTR` | 外部可屏蔽中断 | `IF=1` 才响应 |

`IF=1` 叫开中断，`INTR` 的请求就响应；`IF=0` 叫关中断，`INTR` 的请求就不响应。所以 `INTR` 叫可屏蔽，就是受 `IF` 屏蔽的意思。`CPU` 内部任何中断源的请求，都必须响应。

### 除法出错与单步中断

看第八章 8.2 节 241 页图 8.3，8086 中断结构。框内下方画了五个中断源。

第一个叫除法出错中断源。`CPU` 执行 `DIV` 或 `IDIV`，发现除数为 0，或者商溢出，就自动引起。比如字节除法，被除数在 `AX` 16 位，除数 8 位，商在 `AL`，余数在 `AH`。被除数除以除数，商超出 255，`AL` 放不下，这就叫商溢出。除数为 0 或商溢出，`CPU` 在执行除法指令时自己引起中断，这是内部源。

第二个叫单步中断源。讲 `TF` 陷阱标志时提过。`CPU` 执行用户程序，假如执行这条指令时 `TF=1`，这条一执行完，下一条就不执行了，自动引起单步中断。

要全速连续执行用户程序，必须保证：

$$TF = 0$$

`TF=1` 就只能单步，一条一中断。单片机仿真里的全速执行，就是这个意思。

### 溢出中断INTO

第三个是 `INTO`，溢出中断指令。看黑板：

```assembly
ADD AX, BX
INTO
```

`ADD` 执行完影响溢出标志 `OF`，有溢出 `OF=1`，没溢出 `OF=0`。`CPU` 执行 `INTO` 时去检测 `OF`：如果 `OF=1`，下面就不顺序执行了，引起溢出中断，转服务程序，完了 `IRET` 回来；如果 `OF=0`，根本不引起中断，顺着往下跑。所以 `INTO` 是否引起中断，完全受 `OF` 控制，属软件中断源。

### 断点中断INT 3调试方法

第四个叫断点中断源。我让 `CPU` 执行一段用户程序，结果错了，怎么查？肉眼读几遍找不到，就得机器帮你找，这叫调试。

8086 上机用 `DEBUG`。最笨的是单步单步调，程序量大效率太低。能不能分段看？让它跑到这里停，就在这里设断点。

设断点相当于把当前位置的指令临时用 `INT 3` 代替。`3` 是中断类型号，后面讲。`CPU` 连续跑到 `INT 3`，立刻转中断服务子程序。服务程序里把结果输出到屏幕：结果在寄存器就显示寄存器，在内存就显示内存单元，看对不对。看完返回时，必须把原指令换回去，断点消失。再把断点移到下一处，继续跑到下个断点看下一段。

哪段结果错了，错就在那段块内。再从那段开头单步，总能找到。所以调试要把断点调试和单步调试结合起来。

```assembly
INT 3
```

汇编后机器码是：

```text
CCH (单字节)
```

所以断点中断也叫单字节中断，教科书两种叫法一样。

### INT n与DOS功能调用示例

第五个是 `INT n`。其实 `INT 3` 就是 `n=3` 的特例：

$$n = 3$$

每一种中断都编了号，叫中断类型号。调 `DOS` 子程序也是靠 `INT` 软中断。比如调 `DOS`，类型号是 `21H`：

```assembly
INT 21H
```

此时 $$n = 21H$$

`DOS` 内部子程序非常多，调哪个之前，先把功能号送 `AH`。比如：

```assembly
MOV AH, 4CH
INT 21H
```

调 `4CH` 号子程序，结束用户程序，返回 `DOS`。你们原来都用过。

换一种：

```assembly
MOV AH, 01H
INT 21H
```

调 1 号功能，等待按键，从键盘取一个字符。执行到这就不往下走了，一直等，你不按键它一直等，你一按键后面才继续。

外部两个引脚 `NMI`、`INTR` 加上内部五个，概念先梳理清，后面才能讲中断调用与返回指令怎么响应、怎么转到服务程序入口的全过程。

## 第 7 章：中断类型号与中断向量引出
> 对应分集：P51 | 原始标题：《中断类型号与中断向量引出》

上一节把中断的概念和中断源讲了：什么叫中断，内部五个源，外部两个引脚。可 `CPU` 响应时怎么知道是谁在喊它？喊它的那个源对应的服务程序在哪？不解决这两个问题，中断根本转不过去。这一讲就解决第一个：给每个源编个号。

### 内部中断源回顾

任何 `CPU` 的中断源都分两类。内部是 `CPU` 内部某事件引起的，8086 有五个：

- 除法出错中断。执行除法发现除数为 0 或商溢出，自动引起。
- 单步中断。`TF=1` 时执行一条就引起一次陷阱中断。
- 断点中断。执行 `INT 3` 软指令引起。
- 溢出中断。执行 `INTO` 时是否引起受 `OF` 控制，`OF=1` 才引起。`OF` 是前面某条运算指令算出来的。
- `INT n`。执行软中断指令引起，比如 `DOS` 功能调用 `INT 21H`，此时 `n=21H`。

### 中断类型号分配

`CPU` 引起某种中断后，怎么知道是哪个源提的？只有知道了是谁，才能转到它对应的服务程序入口去。为了识别，8086 给每个源分配了一个号码，叫中断类型号。

8086 的类型号从 0 到 255，也就是 `00H` 到 `FFH`，一共 256 个。所以 8086 最多管理 256 级中断。

内部这几个是硬件固定死的：

| 中断源 | 类型号 `n` |
| :--- | :--- |
| 除法出错 | 0 |
| 单步 | 1 |
| `NMI` 非屏蔽（见下） | 2 |
| 断点 `INT 3` | 3 |
| 溢出 `INTO` | 4 |
| 一般软中断 `INT n` | 后面的 `n`，`n` 不可能大于 255 |

哪个源提请求，`CPU` 就知道是几号，知道了几号，后面才能正确转移。怎么转，后面再看。

### 外部NMI与INTR引脚特性

除了内部，还有外部。8086 外部中断源要提请求，必须经过两个引脚之一：`NMI` 和 `INTR`。

```text
外部设备 --上升沿--> NMI (n=2, 不受IF控制)
外部设备 --高电平--> INTR (类型号用户定, 受IF控制)
```

外部经 `NMI` 提请求，对应类型号 `n=2`，硬件固定死。请求信号是上升沿有效，加一个上升沿 `CPU` 就要响应，不管 `IF=0` 还是 `1` 都必须响应，所以叫外部非屏蔽中断请求。

经 `INTR` 提请求，信号必须是高电平有效。是否响应受 `IF` 控制：`IF=1` 开中断、中断允许状态，高电平请求才响应；`IF=0` 关中断、不允许状态，请求就不理睬。所以叫外部可屏蔽中断请求，可屏蔽就是受 `IF` 控制的意思。

### 8259管理与类型号基值

在 8086 系统里，经 `INTR` 提请求对应的类型号不是固定的，硬件没给它分配。类型号由用户定。用户必须在 `CPU` 外面扩一片中断控制器 `8259`（`8259A`），管理外部可屏蔽中断。

一片 `8259` 有 8 个请求输入端 `IR0` 到 `IR7`，每个都能接一个中断源。8 个源先向 `8259` 提，再由 `8259` 的 `INT` 输出向 `CPU` 提。你们把 `8259` 看成一个外设、一个 `I/O` 接口就行：它有 `D0` 到 `D7`，设计电路时跟 `CPU` 低 8 位数据线相连。我们用 `OUT` 指令往它内部命令寄存器写不同命令，就能改变工作方式：

- 设置 `IR0` 到 `IR7` 是上升沿有效还是高电平有效；
- 把哪一级屏蔽掉、哪一级不屏蔽。屏蔽掉的那级，外设再喊，连 `8259` 都不响应，更谈不上 `CPU`。只有未屏蔽的，`8259` 才经 `INT` 输出一个高电平向 `CPU` 提可屏蔽中断。

`CPU` 对这个高电平是否响应，一受 `IF` 控制，二还要知道是 `IR0` 到 `IR7` 里哪一级放过来的。所以要对这 8 个源分配类型号，这个号是用户用 `OUT` 往 `8259` 内部写类型号寄存器定的。写的时候只定 `IR0` 级的就行。比如 `IR0` 定成 `08H`，`IR1` 到 `IR7` 就是 `09H`、`0AH` 顺序下去。`IR0` 对应的这个号叫类型号基值，基值一定，后面随之确定。

### 中断向量与现场保护引出

有了类型号，看第四个概念：中断向量。比如这是你编的主程序，`CPU` 执行到这条指令时，某个源提请求了。如果是内部或非屏蔽，必须响应；如果是可屏蔽，`IF=1` 也必须响应。

请求到来，`CPU` 必须把现行指令执行完才响应，不可能执行一半就跑。执行完，`IP` 是不是指到下一条了？往回返的话，这条指令所在处叫中断现场。

现场里有什么？要想服务完正确返回，就必须保护现场。现场有这条指令的 `IP`，有 `CS`，还有什么？这条指令之前，`CPU` 跑前面的程序可能做过运算，影响了 `PSW` 里的状态标志。一转到服务子程序，服务程序也可能运算，把 `PSW` 破坏了。回来再处理那些标志就错了。所以现场里还应当包含 `PSW` 状态。

服务程序在哪、怎么转过去？这就是中断向量要解决的事，下节接着讲。

> **提示**：类型号是认源的号，向量是找入口的地址。先把号记死：0 除法错，1 单步，2 `NMI`，3 断点，4 溢出，`INTR` 的靠 `8259` 基值往下排。

> 💡 **承前启后**：完成对「中断类型号与中断向量引出」的理解后，下一章我们将深入探讨「中断响应过程与向量表及8259级联」，进一步完善知识图谱体系。

## 第 8 章：中断响应过程与向量表及8259级联
> 对应分集：P52 | 原始标题：《中断响应过程与向量表及8259级联》

上节留了个尾巴：类型号有了，服务程序入口到底怎么找到？这一讲我们把这个链条接上：响应时硬件自动干什么，向量表长什么样，`8259` 的两次握手怎么把号送进来，最后算算级联能管多少级。这都是考试最爱考的。

### 中断响应现场保护

`CPU` 发现有请求且决定响应，第一件事是硬件自动把现场压栈保护起来：标志寄存器 `PSW`（`FLAGS`）状态、返回地址 `CS`、返回地址 `IP` 依次入栈。这一串全是硬件自动做的。

保护完，`CPU` 得想办法拿到中断程序的入口地址。中断程序叫中断服务子程序，简称中断服务程序。服务程序第一条指令同样有 16 位段地址加 16 位偏移地址，所以必须把入口送到 `CS` 和 `IP`，`CS:IP` 一指过去，就跳到服务程序执行了。

### 中断向量与向量表布局

`CPU` 怎么拿到入口？靠中断向量。

> **定义**：中断向量就是中断服务子程序的入口地址，32 位，4 个字节。

8086 规定，1MB 内存最低的 1KB 专门做中断向量表：

```text
00000H +------------------+
       | 0号向量 (4字节)  | 除法错
00004H +------------------+
       | 1号向量 (4字节)  | 单步
00008H +------------------+
       | 2号向量 (4字节)  | NMI
       +------------------+
       | 3号向量          | 断点
       +------------------+
       | ...              |
003FCH +------------------+
       | 255号向量 (4字节)|
00400H +------------------+
```

地址从 `00000H` 到 `003FFH`，1024 个字节，全放向量。一个向量 4 字节，256 级正好：

$$256 \times 4 = 1024\text{B} = 1\text{KB}$$

0 号占最低 4 个，1 号占接着 4 个，往下排，255 号收尾。前几个你们能背出来：0 除法错，1 单步，2 `NMI`，3 断点，往下推。

### 类型号与向量地址映射

比如：

```assembly
MOV AH, 4CH
INT 21H
```

`n=21H`，它的入口一定在向量表某 4 个字节里。类型号 `n` 跟存放首地址满足：

$$\text{首地址} = n \times 4$$

0 号首地址 `0×4=0`，1 号 `1×4=4` 占 4、5、6、7 单元，2 号 `2×4=8` 占 8、9、10、11，往下推。

4 个字节里怎么放？`n×4` 单元放偏移地址 `IP`（低字），`n×4+2` 单元放段地址 `CS`（高字）。

### 向量建立与INT 21H取向量过程

你们要用 `n` 号中断，先得把自己编的服务程序入口偏移和段地址分别写到 `n×4` 和 `n×4+2` 里，这叫中断向量的建立。

`CPU` 执行 `INT 21H` 时：从 `21H×4` 取一个字送 `IP`，再从 `21H×4+2` 取一个字送 `CS`，`CS:IP` 就指向 `21H` 号服务程序入口，开始执行。

服务程序末尾必须安排：

```assembly
IRET
```

`IRET` 把压栈的 `IP`、`CS`、`PSW` 依次出栈，`SP` 每次加 2，现场全恢复，回到断点。服务程序里用到的寄存器、单元，前面 `PUSH` 保，`IRET` 之前 `POP` 恢复，跟普通子程序一个道理。

### 内部与非屏蔽中断响应步骤

`CPU` 怎么响应？先看内部和 `NMI`。类型号 `N` 固定，不受 `IF` 控制，必须响应。

第一步保护现场，`PSW`、`CS`、`IP` 入栈。

第二步清 `IF`、`TF`。教材 71 页下方有步骤。清 `IF`（`IF=0`）干什么？一响应，由于 `IF` 自动清零，`CPU` 执行这个服务程序期间就不会响应外部可屏蔽中断了。如果你允许执行期间还能响应可屏蔽，服务程序一开头就排一条 `STI` 让 `IF=1`。清 `TF`（`TF=0`）干什么？`TF` 是单步陷阱标志，一转过去 `TF=0`，`CPU` 就逐条连续跑，跟单片机全速运行一样。不然 `TF=1`，执行一条又引起单步中断，服务程序里一般不允许这样，所以响应时硬件自动清 `TF`。

第三步取向量。`N` 已知，算 `N×4`，`N×4` 取一字给 `IP`，`N×4+2` 取一字给 `CS`。

第四五步转入服务执行。

### 外部可屏蔽中断响应与两次INTA

响应外部可屏蔽，基本一样，但多了个前提：必须 `IF=1` 开中断。

第一步保护现场一样，第二步 `IF`、`TF` 清零一样，第三步是关键区别：`N` 未知，得先从外部 `8259` 拿号。

你们初始化时给 `IR0` 定了基值，`IR1` 到 `IR7` 随之确定，8 个号已在内部寄存器里。某级没被屏蔽，外设一提，`8259` 把 `INT` 变高，高电平向 `CPU` 提。`CPU` `IF=1` 就要响应，但响应前必须把现行指令执行完。

响应时：

```text
8259 INT(高) ---> CPU INTR
CPU --INTA负脉冲1--> 8259 : 我响应了 (1总线周期)
CPU --INTA负脉冲2--> 8259 : 把号给我
8259 --D0~D7--> CPU : 类型号N
CPU : N*4 取向量 -> CS:IP
```

`CPU` 有 `INTA` 输出，`8259` 有 `INTA` 输入，做电路时连起来。第一个 `INTA` 负脉冲，一个总线周期，告诉 `8259`：你提的我响应了，握手完成。第二个 `INTA` 负脉冲，再一个总线周期，`8259` 知道 `CPU` 在问号，就把那个源对应寄存器里的 `N` 送到数据总线，`CPU` 在发第二个脉冲期间读 `D0` 到 `D7` 拿到 `N`。拿到再 `N×4` 找向量，后面一样。

### 8259单片与级联级数计算

一片 `8259` 管 8 个。初始化只设 `IR0` 基值就行。80286 以前 `PC` 单片工作，只能管 8 个。资料上 `IR0`、`IR1` 给键盘、实时钟、软驱、`COM1`、`COM2` 这些，`IR2` 空出来给扩展槽用户板子提请求。

286 以后两片级联。`INT` 直连 `CPU INTR` 的叫主片，其余叫从片。从片 `INT` 连到主片某个输入，主板上通常连主片 `IR2`。从片 `IR0` 到 `IR7` 来请求，先给主片，主片再经 `INT` 给 `CPU`。两片级联：

$$8 + 8 - 1 = 15\text{级}$$

主片 8 个脚都能挂从片，最多 9 片（1 主 8 从）：

$$8 \times 8 = 64\text{级}$$

考试最爱考这个。例题：在 8086 系统，中断子系统外部由 4 片 `8259` 级联，问共管多少级？4 片是 1 主 3 从，3 从占主片 3 个脚，要扣掉：

$$4 \times 8 - 3 = 29\text{级}$$

括号填 29，填空题 hit 率非常高。

前面中断概念、中断源、类型号、向量、向量表、服务结构、`IRET`、响应过程讲完，3.12 节剩的核心就是系统功能调用。系统主要是 `DOS`，把底层功能编成子程序供你们调，软中断是：

```assembly
INT 21H
```

`BIOS` 的也能调，一般把 `BIOS` 叫低级调用，`DOS` 叫高级调用。涉及磁盘、`I/O`、文件管理，不用自己写底层，直接调表就行。后面第四章大量例程都用 `DOS`、`BIOS`，所以教学重点是 `DOS` 功能调用，兼顾 `BIOS`。
