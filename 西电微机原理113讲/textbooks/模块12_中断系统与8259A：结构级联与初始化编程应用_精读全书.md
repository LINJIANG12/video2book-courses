## 第 1 章：第八章开篇：中断七个概念，考试只考概念不考设计
> 对应分集：P95 | 原始标题：《第八章开篇：中断七个概念，考试只考概念不考设计》

今天讲第八章中断系统。重点掌握`8086`的中断系统，和`8259A`（`8086`外部可屏蔽中断即`INTR`脚的管理）结合。先打预防针：考到第八章基本全在基本概念里，不涉及设计题，都是概念。七个概念，一个一个过。

### 中断：教室里的一堂课

什么叫中断？第三章中断调用返回加`DOS`功能调用讲过，再叙述一遍。整间教室是一片`CPU`，我是`CPU`内部控制器，我在执行程序；你们每位是`CPU`内部一个部件。我讲课期间说一句话就是执行一条指令，我执行中你举手，就是`CPU`内部提了中断请求，我必须响应：这句话说完（本条指令执行完，不能说半截），下句不说了，转去说另一段话（为你服务的中断服务子程序），服务完`IRET`返回刚才断的地方接着说。这就叫中断。教室外有人敲门，也是中断请求，这叫外部中断源。

### 中断源：NMI上升沿，INTR高电平

谁向`CPU`提请求谁就是中断源，分内部和外部。`8086`外部：设备向`NMI`脚以上升沿提非可屏蔽请求，或向`INTR`脚以高电平提可屏蔽请求。

### 中断源识别之一：8086用中断类型号

`CPU`怎么知道谁提的请求、进谁的服务程序？`8086`用中断类型号`n`：每个中断源编`8`位二进制号，`0～255`，所以`CPU`能管`256`级中断。除法错`0`，单步`1`，`NMI`非屏蔽`2`，断点`3`，溢出`4`，`INT 21H`类型号就是`21H`（`INT`后面数字即类型号）。内部中断类型号硬件固定死了，谁请求`CPU`都知道号；`INTR`的可屏蔽请求没固定，外部扩一片`8259`，类型号事先`OUT`初始化进去，响应时`CPU`从`8259`获取。

> **结论**：有类型号就知道是谁，就能进对服务程序。内部号是死的，`INTR`的号是`OUT`进去的。

### 中断源识别之二：51单片机用服务程序查

`MCS-51`外部中断只有`INT0`非、`INT1`非两脚，只能接两个源。四个按键怎么办？每键一脚接地、一脚经上拉电阻接电源，没按全`1`，按下出`0`。四路进与门：无键出`1`，任一按下出`0`（键抖动不消，理想情况），下降沿向`8031`提中断。

这种`CPU`没类型号，进服务程序先读`P1`口（`P1.0～P1.3`设输入接`K0～K3`）：`P1.0=0`吗？`No`下一个；`P1.1=0`吗？`No`；`P1.2=0`吗？`Yes`，就是它按下了，无条件跳对应处理入口。识别靠服务开头编软件查，先测谁谁优先权高——软件排队定优先权。

```text
四按键 ── 与门 ── 下降沿 → 8031中断请求
服务程序：读P1 → P1.0=0? → P1.1=0? → P1.2=0? Yes → 跳K2处理
（先查谁，谁优先权高）
```

读图说明：硬件只管“有人按”，软件逐位查定“谁按”，查序即优先级。

### 优先权：8086硬件编死，8259编程定

`8086`：所有内部中断（除单步）高于外部；外部里`NMI`高于`INTR`；单步最低。硬件编排死了。一片`8259`管`8`个可屏蔽源，谁高谁低用户初始化编程定，所以叫可编程器件。`CPU`型号不同识别法不同，道理各自成套。

### 中断向量与向量表：最低1K，每向量4字节

中断向量就是服务子程序入口地址：`16`位段加`16`位偏移，`32`位。向量表把`1M`空间最低`1024`单元（`0～003FFH`，最低`1K`）拿来全放向量：一个向量占`4`字节，前两字节放段内偏移（`EA`），后一字放段地址。`n=0`在`0～3`单元（除法错入口），`n=1`在`4～7`，一路下去`n=255`在`03FCH～03FFFH`（`C、D、E、F`）。共`256`个向量，`8086`最多管`256`级中断。

| 类型号 | 表中位置 | 内容 |
| :--- | :--- | :--- |
| `n=0`（除法错） | `00000H～00003H` | 偏移（前`2`字节）＋段地址（后`2`字节） |
| `n=1`（单步） | `00004H～00007H` | 同上 |
| … | … | … |
| `n=255` | `003FCH～003FFH` | 同上 |

### 中断过程四步：执行完、保现场、取类型号、清IFTF

主程序加服务程序（末条必`IRET`）。可屏蔽请求响应前提`IF=1`。某条执行中请求来了：本条执行完，下条不执行，停这（断点，现场是`PSW`、断点`CS`、`IP`）。四步：①现行指令执行完；②现场依次压栈保护（回来状态才对）；③外部可屏蔽从`8259`取类型号（内部/`NMI`固定，这步省了）；④清`IF`、`TF`。清`IF`是服务期关中断，不再响应可屏蔽；允许高优先级打断当前服务（中断嵌套），服务开头排`STI`开中断。

> **提示**：断哪回哪靠现场栈，后进先出，`IRET`按反序出栈，`CS:IP`回断点下一条。

## 第 2 章：8259A引脚与级联：响应五步的帽子，主从握手靠CAS
> 对应分集：P96 | 原始标题：《8259A引脚与级联：响应五步的帽子，主从握手靠CAS》

上讲过程四步讲到清`IF`/`TF`。`TF`清零是防单步：`TF=1`执行完一条就单步中断，不允许。第五步：第三步拿到的类型号`N`，`N×4`找向量表首址，首字取给`IP`，下一字给`CS`，`CS:IP`进服务程序。从请求来（`IF=1`开中断）到进服务入口，这五步叫外部可屏蔽中断的响应过程。答题先戴帽子：`IF=1`开中断下，从请求到入口的一系列操作；非屏蔽或内部中断响应，去掉第三步取类型号，其他一样。

出个脑筋急转弯：什么是中断服务子程序？别答“这就是”，话说全：为提请求的中断源（一个事件）服务的那段程序。中断嵌套：服务期间更高优先级请求来，中止当前转去高的，完了`IRET`回来继续；允许嵌套，服务开头排`STI`。

`IRET`恢复：栈顶依次`IP`、`CS`、`PSW`出栈，`CS:IP`回断点接着执行。

### 8259A引脚：28脚，8个IR，端口靠特征位认

第二个问题：中断控制器`8259`及应用，先掌握引脚功能。`28`脚双列直插：

- `IR0～IR7`中断请求输入，外部设备信号进来，一片管`8`个源。
- `D0～D7`双向数据。`CS`非无效高阻，有效二态。`CPU`经它`OUT`写命令、`IN`读状态，写不同命令改工作方式，所以叫可编程器件。
- `WR`非写控制（`OUT`加低），`RD`非读控制（`IN`加低），`CS`非片选（就是存储器讲的片外寻址）。
- `A0`片内寻址：`CS`非`=0`时，`A0=0`的地址可读写，`A0=1`的地址也可读写，对外只有两个端口地址。但内部寄存器不止两个，怎么认？`A0`区分之外，看`OUT`写进来`8`位里的特征位：某位为`0`，或某两位为`00`，就是特征位，靠它识别端口。

### INT与两个INTA非：类型号是第二个脉冲期间取走的

`IR0～IR7`某位有请求且未屏蔽，`8259`经`INT`端高电平发给`CPU`的`INTR`（外部可屏蔽请求输入脚）。`8086`开中断就响应：`CPU`输出，分两个总线周期发两个`INTA`非负脉冲。第一个脉冲`8259`收到，知道请求被响应了；第二个脉冲期间，`8259`把请求源的类型号送`D0～D7`，`CPU`自动从数据线读走。有了`N`，`N×4`找向量，首字`IP`、`+2`字`CS`，进服务。

> **易错点**：`8086`系统`8259`的`D0～D7`必须接系统低`8`位。`CPU`发第二个`INTA`非后自动从低`8`位读类型号，接高`8`位就读错了。

### 缓冲与非缓冲：EN做输出还是SP做输入

`SP`非/`EN`非脚定两种工作方式。缓冲方式：`D0～D7`和系统总线之间加双向缓冲（`245`），防总线负载重。此时该脚做输出`EN`非：对`8259 IN`/`OUT`时自动出低，接`245`的`OE`非，缓冲工作。这方式很少有人用。

非缓冲：数据脚和系统低`8`位直连，该脚做输入`SP`非。早期`IBM PC`（`8088/8086`）单片，`286、386、486`、奔腾到双核两片级联，全是非缓冲。

主从定义：级联时`INT`接到`CPU INTR`的那片叫主片，其余从片。非缓冲下单片或主片，`SP`非接`+5V`；从片`SP`非接`GND`。

### CAS三线握手：主片报代码，从片认领

`CAS0～CAS2`级联线：主片做输出（高位`CAS2`、低位`CAS0`），从片做输入，主片三根拉到从片三根。从片`IR`有请求，先发到主片某个`IR`脚，主片再向`CPU`请求。`CPU`回两个`INTA`非：第一个主从都收到立正；第二个主片从`CAS`输出代码——比如请求从`IR1`来的，输出`001`。所有从片检测代码，谁的`INT`挂在主片`IR1`上谁应答，握上手，该从片把类型号送数据线，`CPU`取走。

```text
从片IR有请求 → 主片某IR → 主片INT → CPU INTR
CPU ──INTA非(1)──→ 主从皆知响应
CPU ──INTA非(2)──→ 主片CAS输出代码(如001=IR1)
                    ↓
              挂IR1的从片应答 → 送类型号上D0~D7 → CPU取走
（主片SP非=+5V；从片SP非=GND；8259 D0~D7接系统低8位）
```

读图说明：请求上行（从→主→`CPU`），代码下行（主→从认领），类型号最后上总线，三步走完一次级联响应。

> **提示**：`CAS`高低位别背反：`CAS2`高、`CAS0`低。主从输出输入方向一句话：代码是主片报的，从片听的。

## 第 3 章：8259级联实例与内部结构：IRR、IMR、ISR与两种结束方式
> 对应分集：P97 | 原始标题：《8259级联实例与内部结构：IRR、IMR、ISR与两种结束方式》

画个图，书上图`8.13`，`IBM PC-AT`机。前面讲`PC-XT`主板`CPU`是`8088`（单片`8259`）；`AT`主板`CPU`是`286`，到`386、486`、奔腾奔二奔三全一样，两片级联。主片`SP`非接`+5V`，从片`SP`非接地，主从先搞清。主从各有`IR0～IR7`，`AT`机做法：从片`INT`级联到主片`IR2`，主片`INT`接`CPU INTR`。主片`CAS2～CAS0`做输出，从片做输入，输出对输入（`CAS2`对`CAS2`一路过去）。`CPU`两`INTA`非负脉冲发到主片`INTA`非，也要接到所有从片`INTA`非去（画不下，我只画一片）。

### 级联通信：主片报010，从片认领送类型号

主片收到第二个`INTA`非：这次请求是谁来的？`IR2`（级联口）来的，就在`CAS2～CAS0`输出`010`（`2`）。后面所有从片收到比对：初始化时我挂在主片谁上？代码相符的那个，从`D0～D7`送中断类型号`n`，`CPU`取走。类型号不是主片送的，是从片送的。读写控制、片选`CS`非、`A0`一样，没画而已。

> **结论**：请求上行从→主→`CPU`，代码下行主→从，类型号从片上总线。`AT`机挂`IR2`所以代码是`010`，挂谁报谁。

### 外部特性学完看内部：图8.7三寄存器加控制逻辑

学引脚是学外部特性，现在看内部组成，图`8.7`，更好理解。先是`IRR`（中断请求寄存器，`8`位）：`IR0～IR7`输入进来，哪个有请求对应位锁存置`1`，很像`373/374`来数就锁。请求有效形式可初始化成高电平或上升沿，一般取上升沿。

`IRR`上头有`IMR`（`8`位屏蔽）：`OUT`写，某位写`1`对应`IR`屏蔽，写`0`未屏蔽。比如第`2`位写`1`其余`0`，`IR2`屏蔽了。只有未屏蔽的请求才能在`IRR`置`1`。

`IRR`的`1`全送优先权分析器，挑最高的，把服务权给它：`ISR`（服务寄存器）对应位置`1`，再`INT`变高请`CPU`。比如单`IR1`请求未屏蔽，分析完它最高，`ISR`第`1`位置`1`。`ISR`置`1`的意思：`8259`对外设算服务上了，`CPU`还没服务呢。`CPU`响应（两脉冲）、取类型号、`n×4`取向量、`CS:IP`进入口执行，`CPU`才算服务上了。`CPU`服不服务还受`IF`控制。

```text
IR0~IR7 ─→ IRR（锁存置1）──→ 优先权分析器 ─→ ISR（选中置1）──→ INT→CPU
              ↑                         （8259已服务，CPU还没）
             IMR（OUT写1屏蔽/0放行）
```

读图说明：请求先过屏蔽门，再比优先级，再登记服务，最后才请`CPU`，四站流水。

### 结束方式：自动的不用，非自动IRET前先OUT

`8259`服务结束两种。自动结束：初始化成自动，收到第二个`INTA`非，送类型号同时把`ISR`置`1`位清零，`8259`对外设服务结束。不用，一般都不用。

常用的是非自动结束（`PC`机`BIOS`初始化就选它）：取类型号时`ISR`不清零，`CPU`转去服务程序执行；服务完`IRET`返回之前，程序里安排向`8259 OUT`写结束命令，告诉它“我马上结束了，你先结束”。命令通知才算完。

### 响应两道闸：8259屏蔽与CPU的IF

一个请求能不能响应，受两个对象控制：`8259`对你屏蔽了吗？`CPU`的`IF`开吗？书上课后两道题：

第一道：请求时该级未屏蔽，但`CPU`关中断（`IF=0`），能响应吗？不能。过会儿`STI`开中断了，刚才的请求呢？能！`IRR`里寄存着呢，跑不掉。

第二道：`8259`把某级屏蔽了，`CPU`开着，能响应吗？不能。`8259`这道闸就把你拦了。

> **结论**：以前讲外部可屏蔽只受`IF`控制，今天起受双控：`8259`屏蔽闸加`CPU`的`IF`闸。

### 控制逻辑：四个ICW从1编号

内部还有控制逻辑，管一堆东西，包含四个`ICW`寄存器（`ICW1～ICW4`，从`1`编号）。`ICW1`写`8`位命令：定单片还是级联，定`IR0～IR7`高电平还是上升沿有效，等等工作方式初始化。`ICW2`写类型号基址：`IR0`对应哪个类型号，后面`IR1～IR7`依次排下去，定一个基址全排好。

### 本讲提到的题目

课后两题：①某级未屏蔽时来请求，`CPU`关中断（`IF=0`），能否响应？（不能。）`STI`开中断后，刚才的请求能否响应？（能，`IRR`锁存着。）②`8259`屏蔽某级，`CPU`开中断，来请求能否响应？（不能，屏蔽闸拦了。）解析：响应双闸——`IMR`屏蔽位与`IF`，见正文`IRR/IMR/ISR`流水。

## 第 4 章：8259A：级联配置、优先级排队与中断响应过程
> 对应分集：P98 | 原始标题：《8259A：级联配置、优先级排队与中断响应过程》

给`ICW3`里面写命令，只是在级联时才用`ICW3`；单片工作时，不要`ICW3`。这一句先立住，后面`ICW1`到`ICW4`的每一位才有地方落脚。这一讲我把上节课剩下的`ICW3`、`ICW4`收尾，把优先级、操作命令字、端口识别、`PC`机上的实际配置一次讲清，最后走一遍`8259A`响应中断的完整过程，下节课接着抠`ICW1`每一位的初始化。

### ICW3：只在级联时用的互相通知

级联时给`ICW3`里面写命令，方向不同，意思完全不同，得分开记。

给主片的`ICW3`写命令，是告诉主片：谁被级联了。哪一位写`1`，就表示该位对应的`IR`输入端被某从片级联了。主片后面最多能级联几个从片？`8`个，正好占满`8`位。

给从片的`ICW3`做初始化，是告诉从片：你的请求输出被级联在主片的哪个输入上了。这是一个通知，约定好，双方才对得上。

### ICW4：定缓冲、结束方式与嵌套形态

`ICW4`（初始化命令字寄存器`4`）一来，就定三件事：`8259`是缓冲工作方式还是非缓冲工作方式；中断结束方式是自动结束还是非自动结束；`IR0`到`IR7`的优先级怎么排列。

优先级先分两种。固定优先级指的就是：`IR0`级优先级最高，`IR1`次之，一路下来`IR7`最低。这样一种固定优先级也称为正常嵌套方式。

还有一种叫循环优先级，它显然不是正常嵌套。假如规定`IR0`级优先级最高，那么当`CPU`对`IR0`级的请求响应后，`IR1`级就变成最高，`IR2`级次之，而`IR0`级就变为最低；当`CPU`对`IR1`级响应后，`IR2`级最高，`IR3`级次之，`IR1`级变为最低。但这需要通过写命令来告诉`8259`，它自己不会转。

> **结论**：一般我们不用循环优先级。我们用的都是非自动结束方式、固定优先级、非缓冲方式，初始化时就要把`8259`定成这样。

`8259`内部还有数据双向缓冲器、读写控制逻辑，那些哪个器件都应该有，不用多说。重点是：在`8259`内部的控制逻辑里面，包含了上面这些全部内容。

### OCW1～OCW3：工作期间随时可写的操作命令

`O`代表操作（`Operation`），`I`代表初始化（`Initialization`）。初始化一开始就要完成，而操作命令字在初始化之后任何时刻都可以写。给操作命令字写不同的命令，可以在`8259`工作期间改变它的工作方式。一般我们不予改变，但三条必须记住：

第一，`OCW1`。给`OCW1`里面写命令，相当于给`IMR`（中断屏蔽寄存器）写命令。要把`IR0`到`IR7`哪一级屏蔽、哪一级不屏蔽，就通过给`OCW1`对应位写`1`、对应位写`0`来完成。

第二，`OCW2`。给`OCW2`写操作命令字，是告诉`8259`中断要结束了，走的是非自动结束方式。在`CPU`执行中断服务程序、到最后`IRET`之前，要给`OCW2`里面写一个命令告诉`8259`：你先结束。

第三，`OCW3`。它是告诉`8259`改变中断屏蔽方式的。一般这个我们不用，在正常嵌套方式的非自动结束方式当中，`OCW3`根本就用不上。

### 两个端口管七个寄存器：地址加特征位

内部`ICW`有`4`个，`OCW`有`3`个，一共`7`个能写的端口，再加上`IRR`、`IMR`、`ISR`三个能读出来的寄存器（读出来能检测谁置`1`了、谁没置`1`）。这么多读写端口，实际只共享了两个端口地址。

用`OUT`指令朝`8259`内部写时，具体写到哪个寄存器，靠两步区分：先看`A0 = 0`还是`A0 = 1`区分一次，再靠`OUT`写进去的`8`位命令中的特征位来识别。这样`8259`就知道这次是给哪个`ICW`写入。也就是通过地址和特征位相结合，找到`OUT`要写入内部的具体端口。

### PC机上的端口分配与BIOS基址

在`PC`机中，主片`8259`分配的`I/O`地址是`20H`和`21H`：`20H`保证`A0 = 0`，`21H`保证`A0 = 1`。从片分配的是`A0H`和`A1H`。

计算机一上电，`BIOS`先做内存自检，随后对主板硬件初始化，完成后才引导操作系统进内存。`BIOS`对主板上`8259`初始化时，把主片的中断类型号基址定成了`08H`：`IR0`对应`08H`，`IR1`就是`09H`，一路排下去。

从片这边，`BIOS`定的基址是`70H`：`IR0`是`70H`，`IR1`是`71H`，`IR7`就是`77H`。

在`IBM PC`系列机中，主片的`IR0`到`IR7`编号为`IRQ0`到`IRQ7`；到了从片，`IR0`对应的是`IRQ8`到`IRQ15`。一共是`16`级，可第`2`级（`IRQ2`）被级联占用了，所以剩下`15`级外部可屏蔽中断。看`PC`资料手册、`ISA`总线说明，就是这样编排的。

### 级联环境下的固定优先级排队

如果主片和从片都初始化成了正常嵌套方式，优先级固定，那排队是什么顺序？`IRQ0`最高，下来是`IRQ1`，再下来是谁？是`IRQ8`！从`IRQ8`下来到`IRQ9`，一直到`IRQ15`，下来才到`IRQ3`，最低是`IRQ7`。

$$IRQ_0 > IRQ_1 > (IRQ_8 \sim IRQ_{15}) > IRQ_3 > IRQ_4 > IRQ_5 > IRQ_6 > IRQ_7$$

> **易错点**：从片整组插在`IRQ1`和`IRQ3`之间，不是从片排在最后。记住`IRQ2`的位置被从片整组吃掉了，`IRQ8`～`IRQ15`的优先级全部高于`IRQ3`。

### 8259A中断响应的完整过程

工作方式其实在讲外部引脚和内部组成时已经叙述得差不多了，这里按顺序走一遍：

```text
中断源 --IR0~IR7(上升沿)--> [8259A] --INT(高)--> CPU.INTR
CPU --INTA非(负脉冲1)--> [8259A] --CAS2~0(主片输出从片地址)-->
CPU --INTA非(负脉冲2)--> [8259A] --D0~D7(类型号n)--> CPU
CPU: 向量地址 = n x 4 --> 取IP/CS --> 转中断服务程序
服务结束前: CPU --EOI--> OCW2 --> ISR清零 --> IRET
```

读图说明：两个`INTA非`负脉冲各花一个总线周期，第一个定级联对象，第二个取类型号，最后`EOI`与`ISR`清零必须配对。

分步拆开：

**1. 请求输入与复位。** 中断源在`IR0`～`IR7`上产生请求，一般初始化成上升沿有效。`8259`通过`INT`向`CPU`的`INTR`提一个高电平请求；`CPU`响应时，通过`INTA非`发两个负脉冲，各花一个总线周期。第二个负脉冲发完，`8259`把中断类型号送到`D0`～`D7`，同时让`INT`输出变低，结束这次请求。

`INT`为什么必须变低？如果正在服务`IR0`期间`INT`还保持高，`IR0`再来一个请求，就会出现同级中断打断同级中断，这是不允许的。我们只允许更高优先级打断正在服务的请求，不允许同级或低优先级打断。`8259`能做到让`INT`变低，这是第一条要注意的。

**2. IRR锁存。** 请求被锁存在中断请求寄存器（`IRR`）中，哪个引脚提的请求，对应位就置`1`，前提是该级未被屏蔽。

**3. 发INT。** 控制逻辑接收请求，向微处理器发`INT`信号。

**4. CPU双脉冲响应。** 微处理器经`INTR`收到信号，进入连续两个`INTA非`负脉冲周期。

**5. 判优并置ISR。** 优先级电路选出最高请求，置中断服务寄存器（`ISR`）对应位。比如`IR0`和`IR3`同时有请求，判优后`IR0`先服务，`ISR`的`D0`位置`1`，表示正在对`IR0`服务；`D0`位清零，就表示对`IR0`的服务结束了。这是以`8259`为对象来说的。

**6. 级联地址与类型码。** 若是主片，在第一个`INTA非`周期把级联地址从`CAS2`～`CAS0`输出。比如`286`以上机子从片`INT`级联到主片`IR2`，主片就该输出`010`。若是单片使用，或者是被`CAS`选中的从片，就在第二个`INTA非`周期把中断类型号送到低`8`位数据线。

**7. CPU取向量。** `8086`从数据线读到类型号`n`，向量地址就是：

$$向量地址 = n \times 4$$

从向量表该地址取一个字给`IP`，再取下一个字给`CS`，`CS:IP`就指向中断服务子程序入口，转去服务。

**8. EOI与IRET。** 服务结束前，中断服务程序要向`8259A`发`EOI`（中断结束命令），前提是初始化成了非自动结束方式。`8259`收到后把`ISR`中正在服务的那一位清零，对外设的服务结束；`CPU`再执行`IRET`，对本次中断的服务彻底结束。

### ICW1初始化：A0与特征位开路

要使用`8259`，必须在主程序一开始做初始化编程，设置工作方式。第一步是对`ICW1`～`ICW4`写命令。

向`ICW1`用`OUT`写初始化命令，首先保证`A0 = 0`，再靠特征位识别。`ICW1`共`8`位（`D0`～`D7`）：高三位（`D7`～`D5`）没用；第`4`位必须写`1`，此位就是特征位——向`A0 = 0`的端口`OUT`写时，`8259`看到第`4`位是`1`，就识别出这是在对`ICW1`初始化。

第`3`位（`LTIM`位）定触发方式：写`0`表示中断请求信号上升沿有效，写`1`表示高电平有效。在`IBM PC`机中选的是`0`，`IR0`～`IR7`全部上升沿有效。下节课接着抠剩下的位。

## 第 5 章：8259A初始化编程：ICW1～ICW4逐位落实
> 对应分集：P99 | 原始标题：《8259A初始化编程：ICW1～ICW4逐位落实》

`ICW1`的高三位没用、第`4`位是特征位、第`3`位定触发方式，这些上节课已经定了。今天接着往下抠剩下的每一位，顺带把`ICW2`、`ICW3`、`ICW4`的初始化一次算清。记的时候别孤立背每一位，跟着`BIOS`在`PC`机上的实际做法走：主片写什么、从片写什么、端口是哪个，全部有来处。

### ICW1第2位：8085留下的历史位

第`2`位，书上给你画了个叉，在`8086`系统中没有用。当年`Intel`生产`8259A`时，配的微处理器是`8085`，是个`8`位机，那时这一位是有用的：在`8085`系统中，中断向量在向量表中占`8`个字节；在`8086`系统中，向量只占`4`个字节。

可`8085`早淘汰不用了，系统全是`80x86`系列，所以这一位就不用了。考试看到它，知道是历史遗留、写`0`即可。

### ICW1第1位：单片还是级联

第`1`位可以写`1`也可以写`0`。写`0`是级联工作，写`1`是单片工作。如果是级联工作，初始化完`ICW1`后面还要初始化`ICW3`；如果是单片工作，就不用初始化`ICW3`了。

### ICW1第0位：要不要初始化ICW4

第`0`位书上给你写死了是`1`。书上没写为什么，我补充一下：写`1`就是要初始化`ICW4`，写`0`就是不初始化`ICW4`。但我们都要初始化`ICW4`，所以书上直接标了个`1`。

### 主片ICW1：11H写入20H端口

不用的位都取`0`：高三位取`0`，第`2`位取`0`，上升沿触发第`3`位取`0`，级联工作第`1`位取`0`，要`ICW4`第`0`位写`1`，再加上第`4`位特征位是`1`，拼出来就是`11H`：

```text
D7 D6 D5 D4 D3 D2 D1 D0
 0  0  0  1  0  0  0  1  = 11H
             ^特征位
```

程序这样写：

```assembly
MOV AL, 11H
OUT 20H, AL
```

`20H`没有超出`255`，目的操作数寻址用的是直接寻址，把`AL`内容写到`20H`端口去。`20H`是主片`8259`的端口地址（`A0 = 0`），第`4`位等于`1`，`8259`就识别出这是写进主片`ICW1`了。`ICW1`收到`11H`，主片就被初始化成中断请求上升沿有效、级联工作。

从片同样要初始化，端口换成`A0 = 0`的从片地址：

```assembly
MOV AL, 11H
OUT 0A0H, AL
```

`BIOS`里面就是这样做的。

### ICW2：只写基址，靠顺序识别

初始化`ICW2`时，`A0`要等于`1`。`ICW2`共`8`位：`D0`、`D1`、`D2`是低三位，`D7`到`D3`是高五位。书上说高五位是中断类型码的高五位：`D5`～`D3`写`000`对应`IR0`的类型码，写`001`对应`IR1`，写到`111`对应`IR7`。

给`8259`的`ICW2`写中断类型号，只需要写中断类型号基址，也就是只给`IR0`定类型号就行了，所以低三位肯定是`000`。

> **提示**：类型号、类型码，号就是码，不分家。读到任一个词，指的都是要送上数据线的那个中断向量编号。

在`IBM PC`机中，主片这样写：

```assembly
MOV AL, 08H
OUT 21H, AL
```

`08H`就是`0 0001 000B`的高五位部分？直接记结论：`AL`取`08H`，`OUT`到`21H`（`A0 = 1`），主片的类型号基址就定了。从片则是：

```assembly
MOV AL, 70H
OUT 0A1H, AL
```

从片基址`70H`，端口`A1H`（前面加`0`写成`0A1H`）。

这里有个关键点：向`A0 = 1`的地址`OUT`写，是没有特征位的。没有特征位怎么办？靠顺序识别：初始化`ICW2`必须紧跟在初始化`ICW1`之后，`8259`靠这个顺序认出这次写的是`ICW2`。

### ICW3：级联才写，主从含义不同

如果是级联工作，必须初始化`ICW3`；单片工作就不用。写`ICW3`时`A0 = 1`，同样靠顺序（`ICW2`写完紧跟着写`ICW3`）。

对主片的`ICW3`（`8`位`D0`～`D7`）：某一位写`1`，表明该位对应的`IR`输入端被某从片级联了。主片后面最多能级联`8`个从片，正好一位管一个。某一位写`0`，表明该位对应的`IR`端未被级联。

对从片的`ICW3`：高五位没用，只用低三位，编码`000`到`111`。如果这三位写的是`010`，说明从片的`INT`输出被级联到主片的`IR2`上了。

在`PC/AT`机中，`BIOS`对主片`ICW3`的初始化是：

```assembly
MOV AL, 04H
OUT 21H, AL
```

`04H`就是第`2`位是`1`、其余全`0`，表明主片的`IR2`被从片级联了。对从片则是：

```assembly
MOV AL, 02H
OUT 0A1H, AL
```

`010B`等于`2`，表明从片的`INT`被级联到主片的`IR2`上去了。两边约定好了，对上了。

> **结论**：我认为这些知识点考试不好考，但在实际工程中非常有用。不管上研究生做科研，还是工作中接到软硬结合的题目、要在计算机上开发系统，只要走中断方式，就要对主板上的`8259`做初始化，或者对自己系统里配的那片`8259`做初始化。

### ICW4：嵌套、缓冲与结束方式

初始化`ICW4`也要保证`A0 = 1`，共`8`位。向`A0 = 1`的端口`OUT`写时，如果`D7`、`D6`、`D5`是`000`，就表明写的是`ICW4`，这是特征位。

`D4`位说明嵌套方式：写`0`是完全嵌套，也就是我说的正常嵌套方式，优先权固定，`IR0`最高、`IR1`次之、`IR7`最低；写`1`是特殊嵌套方式，优先权可以用`OCW`写命令来指定。我们一般都用正常嵌套。

第`0`位写`1`。第`1`位选择中断结束方式：写`0`是非自动中断结束，写`1`是自动中断结束。说的是谁？说的是`8259`。`8259`对中断请求服务结束，意味着`ISR`对应位清零；清零是自动还是非自动，一般选非自动——要在中断服务程序`IRET`结束之前，给`OCW2`写`EOI`命令告诉`8259`中断结束。

中间两位：第`3`位说缓冲方式，第`2`位（`M/S`位）说主片还是从片，两位配合用。第`3`位写`1`（`buffer`位）肯定是缓冲方式；我们用的是非缓冲，所以第`3`位应该写`0`，写成`0X`（`00`或`01`）。书上印了个`1X`，我昨天看怎么看都不对，非缓冲就该是`0X`。

这样一来，`PC`机上主片`ICW4`的初始化就是：

```assembly
MOV AL, 01H
OUT 21H, AL
```

`01H`拆开看：缓冲位`0`（非缓冲）、`M/S`位`0`、结束位`0`（非自动）、嵌套位`0`（正常嵌套）。从片同样：

```assembly
MOV AL, 01H
OUT 0A1H, AL
```

到这里，`ICW1`到`ICW4`四步初始化全部落地，主片四条、从片四条，端口与命令字一一对应。

## 第 6 章：8259A操作命令字与中断应用例题引入
> 对应分集：P100 | 原始标题：《8259A操作命令字与中断应用例题引入》

上节课讲到第八章中断系统及`8259`应用的第二点：可编程中断控制器芯片`8259`。初始化命令字`ICW1`到`ICW4`已经讲完，今天先复习一遍，再看编程的第二点操作命令字，最后进到本章第三点应用，看一道例题。复习不是重复，是把四步的顺序和端口一次焊牢。

### 四步初始化复习：端口与顺序一次焊牢

`ICW1`朝里写初始化命令，必须保证`A0 = 0`，再靠特征位识别。它定两件事：一是`IR0`到`IR7`共`8`个请求输入信号的有效形式，高电平还是上升沿，一般选上升沿；二是这一片`8259`是单片工作还是级联工作。`286`一直到今天的计算机主板用两片`8259`级联，`286`以前的`IBM PC/XT`主板只有一片单片工作。

`ICW1`完了紧接着初始化`ICW2`，紧接着，靠顺序认。`A0`要等于`1`。`ICW2`定`IR0`级的中断类型号基值。

两片以上级联，马上初始化`ICW3`：主片的`ICW3`定的是`IR0`到`IR7`中哪一个输入被后面的从片级联了；从片的`ICW3`是给从片说明你的`INT`输出被级联在主片的`IR`几上。`ICW3`的初始化也靠顺序，`ICW2`之后紧接着写。单片工作就不用`ICW3`了。

`ICW3`完了初始化`ICW4`，`A0 = 1`。它定三件事：嵌套方式（完全嵌套还是特殊嵌套，一般定完全嵌套，也就是正常嵌套，`IR0`最高一路固定下来）；缓冲还是非缓冲（我们都是非缓冲）；中断结束自动还是非自动（我们都是非自动）。我说的我们用的都是什么，指的就是主板上`BIOS`对`8259`的初始化就是那样做的。

### OCW1：屏蔽字寄存器，可读可写

`8259`一旦初始化完，就可以按定的方式工作了。工作期间给`OCW1`到`OCW3`写操作命令字，可以改变工作方式。先看`OCW1`。

朝`OCW1`里`OUT`写，是定`IR0`到`IR7`中哪个输入被屏蔽、哪个未屏蔽：`8`位中某一位写`1`，对应的`IRi`（`i = 0～7`）就被屏蔽；对应位写`0`，对应的`IRi`就未屏蔽。只有未屏蔽的请求输入，`8259`才能响应；只有`8259`能响应的，`CPU`才能响应，一级一级的。

这个寄存器端口也可以`IN`读。读的时候不叫`OCW1`，叫`IMR`。在计算机系统上`IN`读`21H`，读到的就是主片`8259`的`IMR`；看读回每一位是`1`是`0`，就知道`BIOS`一初始化把哪个中断屏蔽了、哪个没屏蔽。

朝`OCW1`里`OUT`写的操作，肯定在`ICW4`初始化完之后就得进行。

### OCW2：非自动结束的EOI通知

`OCW2`共`8`位，我们感兴趣的是第`5`位`EOI`位。朝`OCW2`写操作命令字是向`A0 = 0`的端口写：初始化完成以后，再向`A0 = 0`的端口`OUT`写，写的就是`OCW2`。

在正常嵌套方式下，向`EOI`位写一个`1`，意思就是`CPU`通知`8259`结束中断，通知`8259`结束正在服务的中断。正在服务的那一位`ISR`是不是就清零了？中断服务寄存器在服务期间是置`1`的，清零了，`8259`对中断源的服务就结束了。

上节课讲过两种结束方式：自动结束和非自动结束。非自动结束就是在`CPU`中断服务结束前、执行`IRET`指令前，由`CPU`朝`OCW2`的`EOI`位发一个`1`，通知`8259`先结束，然后自己才执行`IRET`。

主片`8259`的通知程序就是两条：

```assembly
MOV AL, 20H
OUT 20H, AL
```

不用的位取`0`，`EOI`位是`1`，拼出来正是`20H`；`20H`是主片`A0 = 0`的端口。`CPU`执行完这两条，就通知主片结束了。如果是从片，地址改成`A0`的从片端口就行。

`OCW2`其他位的含义，在正常嵌套下我只要求掌握这一种，就不讲了。感兴趣的自己去修：中断结束后还可以指定下一次谁优先级最高，在`OUT`写的时候既结束本次服务、又指定下次最高优先级，算一种循环优先级。明白有这回事就行。

### OCW3：正常嵌套下用不上的屏蔽方式字

向`OCW3`里`OUT`写操作命令字，是改变`8259`的屏蔽方式的。这个我就不讲了，在正常嵌套方式下用不上，感兴趣的自学。

到这里，`8259`怎么编程——初始化编程，加上初始化后工作期间操作命令字的编程，用到哪些讲哪些，已经讲完了。

### 例8.3：中断法取数的硬件摆法

本章最后看一个例题，应用里面的例`8.3`。选哪个例题我想了一下：第七章最后一个例题讲过`A/D`变换器的例程，用`EOC`转换结束信号（开始转换变低，转换完变高，低到高的上升沿）向`8259`请求中断，`CPU`响应后在中断服务程序里把转换结果读走，也是一个思路。今天看书上的例`8.3`。

题目是这样：有一个输入设备，数据准备好放在这里，但没有锁存功能，它会向外部发一个选通信号。我们用户可以这样设计电路：在这里放一个锁存器（`8`位数据就用`8`位锁存器），用这个选通信号把设备准备好的数据一下锁到锁存器输出端。选通信号第二次到来之前，锁存器输出端的数据一直稳定着，这是第一点。

第二点：在这里再设计一个锁存器，利用这个选通信号一到来，使它的`Q`输出原来是低、现在变高，发一个中断请求。书上画得很清楚：一端是正`5`伏，相当于`D`触发器的`D`端，选通信号好比`CP`端；低电平选通的上升沿一来，就把高电平打到`Q`端锁住了，相当于一个`D`触发器。用这个`Q`输出做中断请求信号，送到`8259A`的`IR3`端。

用户还在这里设计一个译码器和一个输入端口（输入缓冲器，用`245`、`244`都能做），分配的地址书上给的是`240H`。译码器对系统地址低`10`根线（`A0`到`A9`）做译码，译出`240H`；`PC`机总线的话`AEN = 0`要参加译码。题目又在这里设计了一个或门：译码器输出的低电平和`IOR非`相或，或出来是低，做这个输入端口的片选（`245`的话接到`E非`端）。`CPU`从这里把锁存的数据取走，走的是`D0`到`D7`。同时这个低电平还作为`D`触发器的`R非`清零端：一次读操作，既取走了数据，又把中断请求清零了，一次中断请求完毕。

题目还说系统在`IBM PC/XT`系统中：只有一片`8259`单片工作，端口就是`20H`和`21H`。要求是：设备把数据准备好放好后，用中断方法把数据取走，取走后传到内存暂存起来；它再次准备好数据，再取走；什么时候不做了？检测键盘有回车就不做了，输入回车字符表示结束。

```text
输入设备 --数据--> [8位锁存器] --D0~D7--> 输入缓冲器(240H) --> CPU
     \--选通信号--> 锁存有效数据      ^
      \--选通信号--> [D触发器Q] --IR3--> 8259A --INT--> CPU
CPU读240H --> 或门(译码+I0R非) --> 片选有效 --> 取数 + 清D触发器(R非)
```

读图说明：数据通路靠`8`位锁存器保持稳定，中断通路靠`D`触发器把一次选通变成持续有效的`IR3`请求，`CPU`读`240H`端口的那个低电平同时完成取数和清请求。

### 本讲提到的题目

**例8.3（题干与做法）**：输入设备备好数据并发出选通信号，经`8`位锁存器与`D`触发器向单片`8259`（`XT`系统，端口`20H/21H`）的`IR3`提中断请求；输入端口地址`240H`（`A0`～`A9`译码，`AEN`参加译码，`IOR非`经或门做片选，用`245/244`做输入缓冲）。要求用中断方法把数据取走暂存内存，设备再备好再取，直至键盘输入回车结束。

做法按题面信息分三块：主程序先对单片`8259`做初始化并开放`IR3`，建立好`IR3`的中断向量；主循环里等待中断、兼查键盘是否为回车；中断服务程序里读`240H`端口取数（读操作同时清`D`触发器），把数据暂存内存后`IRET`返回。完整的初始化与服务程序写法是下一讲的内容。

## 第 7 章：中断法取数程序：从程序骨架到服务返回
> 对应分集：P101 | 原始标题：《中断法取数程序：从程序骨架到服务返回》

例`8.3`的硬件上节课已经摆好了：输入设备备好数据发选通信号，`8`位锁存器锁数据，`D`触发器向`IR3`提请求，`240H`端口读数兼清请求，`XT`系统单片`8259`。今天把程序从头写到尾。记住我的要求：必须用完整的`8086`汇编程序格式写，既满足中断题目的功能，又顺手把汇编程序结构复习一遍。

### 程序骨架与数据段变量

凡涉及中断调用、子程序调用或现场压栈，必须开辟堆栈段。组合类型必须明确写成`stack`，链接程序才认它是系统堆栈段，空间大小按实际需求定：

```assembly
stack segment stack
    ; 空间大小按实际需求定义
stack ends
```

数据段规划三个变量，一个不能少：

```assembly
data segment
    inbuff db 100 dup(?)
    inpoint dw ?
    in_imr  db ?
data ends
```

`inbuff`是输入数据缓冲区，`100`个字节，外设每中断一次读进来的一个数据，按序存在这里。先假定一次任务总共进来的数据不超过`100`个，一般没装满之前用户敲回车就提前结束了。

`inpoint`是字单元，放的是`inbuff`当前待写单元的偏移地址指针。每次往缓冲写数据之前，先从`inpoint`取出目标地址再存。

`in_imr`是字节单元，暂存`8259A`的`IMR`原值。`PC`机启动时`BIOS`已经对主片`8259A`做完初始化，`IMR`里有特定的屏蔽位。我们的应用要改`IMR`，工程规范是：先读出来暂存，改完用新的；程序退出时再把暂存的写回去，恢复系统原状。绝不能盲目全盘覆写。

代码段照规矩来：

```assembly
code segment
    assume cs:code, ds:data, ss:stack
start:
    mov ax, data
    mov ds, ax
```

`8086`不支持立即数直接送段寄存器，必须经`AX`中转，这是死规矩。

### 中断类型号：IRQ3就是0BH

题目把外设挂在`IR3`上，类型号怎么定？主片`8259A`的类型号基值固定`08H`，`IRQ0 = 08H`、`IRQ1 = 09H`、`IRQ2 = 0AH`，所以`IRQ3 = 0BH`。本例的类型号就是`0BH`。

`8086`的中断向量表在内存最底端`00000H`～`003FFH`，共`1024`字节，`256`个向量，每个向量`4`字节（`2`字节偏移`IP`加`2`字节段基址`CS`）。类型号`n`的向量首地址，数学关系是死的：

$$向量偏移 = 4 \times n$$

本例就是`4 × 0BH`。

### 装向量前的现场保护与指针切换

黑板上接着代码段初始化往下写：

```assembly
    push ds
    mov ax, 0
    mov ds, ax
    mov bx, 4 * 0Bh
```

三条各有道理。`push ds`是保护当前数据段：此时`DS`放的是用户`data`段基址，装向量必须把`DS`指向向量表所在的`0000H`段，所以先压栈保护。`mov ax, 0`再`mov ds, ax`，是定位到向量表段，`DS = 0`之后基于数据段的偏移寻址直接落进向量表。

`mov bx, 4 * 0Bh`有个纠偏：起初想用`AX`，不行。`8086`能做寄存器间接寻址的只有`BX`、`BP`、`SI`、`DI`，`AX`不能。所以必须用基址寄存器`BX`存偏移量，后面才能用`[bx]`形式往向量表写入口地址。

### 建向量的方法一：直接写内存

设服务程序入口标号为`ABC`，底层写法是：

```assembly
    mov ax, offset ABC
    mov [bx], ax
    mov ax, seg ABC
    mov [bx+2], ax
```

`4 × n`单元写偏移，`4 × n + 2`单元写段基址。但这组写入横跨多条指令，有临界区问题：只写了偏移、还没写段基址的半就绪状态下来了中断，`CPU`按半残废的向量跳转，直接跑飞。所以写之前必须`CLI`关中断，写完`POP DS`恢复数据段、再`STI`开中断。向量表没彻底建好之前，绝对不允许响应中断。

### 建向量的方法二：DOS 25H功能调用

教材前五行用的是另一条路：向`DOS`请求服务挂向量。`25H`号功能调用，`AH = 25H`是功能号，`AL`是类型号，本例就是：

```assembly
    mov ax, 250BH
```

入口指针这样装：段地址经`AX`中转给`DS`：

```assembly
    mov ax, seg IN_INT
    mov ds, ax
    mov bx, offset IN_INT
    int 21H
```

一条`INT 21H`，委托操作系统内核接管。注意`DOS`调用改了`DS`，所以教材调用完第`6`行重新初始化数据段：

```assembly
    mov ax, data
    mov ds, ax
```

把`DS`重新对回用户数据段。两条路对比：直接写内存是裸机底层控制，`DOS 25H`是走操作系统抽象层。按原理做就行，不必拘泥哪一种。

| 建向量方法 | 控制层级 | 关键动作 | 代价 |
| :--- | :--- | :--- | :--- |
| 直接写内存 | 裸机底层 | `CLI`后写`[BX]`/`[BX+2]`，`POP DS`+`STI` | 自己管临界区，半残向量会跑飞 |
| `DOS 25H`调用 | 操作系统层 | `AX = 250BH`，装`DS`配指针，`INT 21H` | 调用完重装`DS` |

### 指针变量的装载：立即数寻址

```assembly
    mov IN_POINT, offset IN_BUFF
```

汇编里变量经伪指令一定义，在符号表里就内生具备好几个属性（含段属性、偏移属性等）。`OFFSET IN_BUFF`不是运行时动态算的，是汇编链接阶段直接算出来的固定常数，所以源操作数是立即数寻址。这条指令就是把缓冲首地址常数存进`IN_POINT`这个字单元，完成指针初值装载。

### 开IR3：读IMR、改一位、写OCW1

主片`8259A`中`A0 = 1`的端口是`21H`。读这个端口读的是`IMR`，写这个端口写的就是`OCW1`，同一个端口，读和写叫法不同。

硬件上无需重做`ICW1`～`ICW4`：冷启动时`BIOS`已经初始化过主片，用户程序只在现有基础上动`OCW1`。但`BIOS`设的`IMR`原状态未知，不能盲写覆盖，先读出来保护现场：

```assembly
    in al, 21H
    mov IN_IMR, al
```

`AL`的`8`位`D0`～`D7`严格对应`IR0`～`IR7`：位是`1`表示该通道被屏蔽，是`0`表示未屏蔽。要开`IR3`，就是把`D3`清零，其余七位维持原样。保持位与`1`，清零位与`0`，掩码就是`1111 0111B = F7H`：

```assembly
    and al, 0F7H
    out 21H, al
```

一写进去，`OCW1`的第`3`位肯定是`0`，`IR3`未屏蔽，这一点先做到。

### 等待循环：DOS 6号功能查回车

做到这一步，就该等待中断到来。等待用`DOS 6`号功能调用，我在讲`DOS`功能调用时讲过：控制台输入输出，既能从键盘输一个字符，也能向屏幕输出一个字符。输出时`DL`放字符的`ASCII`码；从键盘输入时`DL`放`0FFH`：

```assembly
    mov ah, 06H
    mov dl, 0FFH
    int 21H
```

`6`号功能从键盘读字符但不等待，直接滑下来，输没输入影响`ZF`。书上没测`ZF`，直接测`AL`里有没有输入：没输入肯定不是回车，有输入就看是不是回车：

```assembly
    cmp al, 0DH
    jne W
W:
```

`0DH`就是回车。不相等说明不是回车，跳到`W`标号再读键盘字符再测。`CPU`就一直在这个循环里转：既没按键盘，也没有中断到来，就一直转。转干什么？等待中断。

### 中断服务：取数、暂存、指针加一

一旦中断来了，不管`CPU`在循环体哪条语句上，先把现行指令执行完，保护下一条指令现场，转去服务。服务子程序入口一开始先做信息保护，和子程序调用一样，`AX`、`BX`、`CX`不敢破坏，`PUSH`、`PUSH`、`PUSH`保护起来。

然后取指针：

```assembly
    mov bx, IN_POINT
```

`IN_POINT`里放的是前面装进去的`IN_BUFF`偏移，`BX`现在指向待写单元，段地址在`DS`。接着读端口：

```assembly
    mov dx, 0240H
    in al, dx
```

`240H`给`DX`，读`240`端口。`CPU`做`I/O`读：`240`译码出低电平，低低相或来一个低，这个低电平把数据读到`AL`，同时让触发端清零。读到了，就存起来：

```assembly
    mov [bx], al
    inc bx
    mov IN_POINT, bx
```

`[BX]`间接单元收下数据，下次中断再来的数据该写下一个单元，地址是`BX + 1`，回写`IN_POINT`，下次再从这里取。这就是它的设计思想。

这次中断完了：原来`PUSH`保护的，`POP`、`POP`、`POP`恢复；然后`IRET`中断返回。返回到哪？回到引起中断时断开的地方，又进循环。没按键，或者按的不是回车，下次中断再来，又转进服务程序读数。

> **提示**：`XT`机单片`8259`同样工作在非自动结束方式，按前两讲的规矩，`IRET`之前一般还要向`OCW2`写`EOI`通知`8259`先结束（主片是`MOV AL, 20H` / `OUT 20H, AL`），再执行`IRET`，`ISR`对应位才清零。

### 回车退出与程序收尾

直至按了回车，退出来。按程序设计：

```assembly
    mov ah, 4CH
    int 21H
```

程序结束。如果退出时系统还有别的任务，再加别的任务程序；没有，程序就结束。程序结束的下方，接着是中断服务子程序，写完后代码段撤销：

```assembly
code ends
end START
```

整个程序结束。我这套程序设计和书上不一定一样，每个人有每个人的思路，按原理做就行。

我要强调的是：利用中断方法实现`CPU`与设备之间的通信（就是从外部读数据），在实际工程中经常用到。不会玩中断，根本谈不上你水平怎么样。但是结合中断的应用，考试又不好考，一考全是这样的题，我估计大部分人都糊了。课堂上只是帮你们引进门，工程中大量在用，还要求你们下去加强，这是这一块。
