## 第 1 章：8086的外部结构：从40个引脚看懂三类总线与读写控制
> 对应分集：P13 | 原始标题：《8086的外部结构：从40个引脚看懂三类总线与读写控制》

买到一块CPU芯片，拿到手里我首先看到的是什么？是引脚。想搭系统，我就得从这数量有限的引脚出发，这就是我学任何一款微处理器都要先过的第一关：外部结构长什么样，再进到内部看它怎么干活、程序员又能看到什么。

为什么上来就抓外部结构？我给自己定的学法就是这样：先看外部有多少输入输出引脚、它们怎么分类，再学内部结构，用内部结构把工作原理和编程模型串起来。这一讲就是第二章的开篇，把外部结构从宏观上立住，微观的引脚细节留到第5.3节再抠。

### 外部结构就是数量有限的引脚

> **定义**：微处理器的外部结构表现为数量有限的输入输出引脚，这些引脚构成微处理器级总线。

我手里这块芯片，能和外面打交道的全部家当就是这几十个引脚。CPU正是靠它们，或者说靠微处理器级总线，和外部存储器、外部`I/O`接口传送信息。

传送的信息只有三种：数据信息、地址信息、控制信息。所以引脚按功能分也就是三类：

| 引脚类别 | 传送方向与内容 | 在总线中的对应 |
| :--- | :--- | :--- |
| 数据引脚 | 与外部双向传送数据 | 数据总线（`DB`） |
| 地址引脚 | `CPU`向外部单向输出地址码，用于寻址 | 地址总线（`AB`） |
| 控制引脚 | 输入输出各种控制信号，含电源、地 | 控制总线（`CB`） |

我靠地址总线上的地址来识别：这次读写到底找的是哪个存储器单元，还是哪个`I/O`接口。

### 先看封装：8086为什么是40脚双列直插

做应用之前我先想封装，不然`PCB`（印刷电路板）图都没法画。`8086`、`8088`、`286`用的都是双列直插式封装（`DIP`），和我在数电课上用的`74LS00`与非门、`74LS04`反相器、`74LS161`计数器是一路的东西：芯片两边有引脚。

> **结论**：`8086`与`8088`都是`40`个引脚，双列直插式封装。

现在不少小芯片是扁平封装、四周都有引脚、贴装上去的，但`8086`这个年代就是两边出脚，一共`40`脚。第一脚、第二脚各是什么，`163`页图`5.5`那张引脚图里全画出来了，今天我先不细讲，只拿它当证据看引脚数量和分类。

### 8086是标准16位，8088是准16位

同样`40`个脚，先问世的是`8088`，后来才有`8086`，两者的差别正好把“多少位”这个概念一次讲透。为什么一个叫标准`16`位，一个叫准`16`位？

`8086`的`16`位是里外一致的：内部寄存器`16`位，内部`ALU`（算术逻辑单元）`16`位，部件之间通信的片内总线也是`16`位，和外部存储器、`I/O`之间通信留出的数据引脚同样是`16`根。一次和外面传`16`位，标准`16`位微处理器，当之无愧。

`8088`呢？内部全是`16`位，寄存器、`ALU`、片内总线一点不差，可留给我的外部数据引脚只有`8`根。一次和外部只能传`8`位，里外不对等，所以只能叫准`16`位。

> **易错点**：说几位微处理器，关键看内外是否一致。内部`16`位加外部`16`根数据引脚才是标准`16`位；内部`16`位、外部只给`8`根，就是准`16`位。

### AD0～AD15：地址与数据复用的引脚

看图`5.5`数一数就明白了。第`16`脚是`AD0`（`D0`就是数据第`0`位，`A`是地址的意思），一直到第`2`脚`AD14`、第`39`脚`AD15`，一共`16`根；再加上第`38`～`35`脚的`A16`～`A19`高`4`位地址，地址一共`20`位。

问题来了：`AD0`～`AD15`这`16`个脚，既能做数据脚，又能替`CPU`往外送地址，这不是撞车了吗？对，这就叫复用引脚。

> **提示**：学复用引脚不能只记“它能干两件事”，必须接着问时序：`CPU`执行一条对存储器的读或写指令，总共花一段时间，在这个时间片里，哪个时间片它当地址脚用，哪个时间片它当数据脚用。引脚功能加时序关系，才算真正掌握，详细的时序全放在第五章讲。

```text
+------------+---------------------------+
| 引脚       | 功能                      |
+------------+---------------------------+
| AD0 ~ AD15 | 地址 / 数据复用 (16根)    |
| A16 ~ A19  | 高4位地址 (4根)           |
| 其余引脚   | 控制引脚 (含电源、地)     |
+------------+---------------------------+
```

读图说明：`20`位地址就是`16`根复用线加高`4`位地址线拼出来的，剩下的脚都可以归到控制引脚里。

### 从引脚到系统总线：复用信息要先分离开

教材`12`页图`2.1`画得很直白：左边是`CPU`芯片，从芯片上以总线形式引出数据线、地址线、控制线。那就是把图`5.5`里的数据脚、地址脚挑出来，剩下的全归到控制里，三种线齐了。

```text
              +----------------+
              |   8086 CPU芯片 |
              +---+---+---+----+
                  |   |   |
            数据线 |   |   | 地址线
            (DB)  |   |   | (AB)
                  | 控制线|
                  | (CB)  |
                  |   |   |
     +------------+---+---+------------+
     |            |   |   |            |
  存储器电路   I/O接口电路  I/O设备  电源/系统程序
```

读图说明：`CPU`靠三种线挂存储器、挂`I/O`接口再连`I/O`设备，加上电源、往`ROM`里装好系统程序，就是微型计算机系统。

可图`2.1`只是简单框图，省掉了一步：引脚一出来，第一步要做系统总线形成电路设计。为什么？体积有限，引不出那么多脚，半导体公司只好让部分引脚复用；但实际用的时候，我要数据走专用的数据总线、地址走专用的地址总线，就得按时序把复用脚上的信息分离开。分出真正的系统`DB`、`AB`、`CB`之后，才在上面扩展存储器电路和`I/O`接口电路。

### CPU靠这组引脚干三件事

`13`页第一行最后一句点题：`CPU`的这些引脚信号称为微处理器级总线。靠它们，`CPU`完成三件事。

第一，和外部存储器之间交换信息。交换的有数据，还有指令。指令是什么？就是能告诉`CPU`做什么、怎么做的一组二进制代码，可不是随便一组二进制。比如`MOV AL, 20H`，翻译成指令代码是`B0H 20H`，这两个字节的二进制拼在一起就是一条指令，也就是机器语言里的一条语句，功能就是把`20H`送进`AL`。

第二，和`I/O`设备之间交换信息。严格说，是和设备相连的`I/O`接口电路之间交换。任何`I/O`设备都不能和`CPU`直接通信，必须在设备和系统总线之间设计`I/O`接口电路，`CPU`和设备的交换就变成了`CPU`和对应接口电路的交换。

第三，输入输出必要的信号，也就是控制信号。比如`CPU`执行的正好是一条对存储器的写指令，引脚上就该输出一个写控制信号。

### 两根控制线分清四种读写

再回到`163`页图`5.5`，把控制看具体。第`29`脚`WR#`（`#`表示低电平有效，`WR`就是写），`CPU`往外写数据时它输出低电平；第`32`脚`RD#`同理，是读。可光知道读还是写还不够：是对存储器写，还是对`I/O`写？

`CPU`自己是知道的，因为对存储器读写有专门的读写指令，对`I/O`读写有专门的`I/O`读写指令，执行哪条就知道操作谁。但我做电路的人，看着数据线、地址线上的信息，怎么分辨？就靠第`28`脚`M/IO#`（`M`是`Memory`存储器）。`CPU`执行对存储器操作的指令，在整个指令周期内它输出高电平；执行对`I/O`操作的指令，就输出低电平。

> **定义**：`M/IO#`区分对象（存储器还是`I/O`），`WR#`、`RD#`区分方向（读还是写），两者组合才能唯一确定一次操作。

有了这个关系，我用数电里学的门就能搭出四个控制信号。拿或门来说：`M/IO#`为低、`RD#`为低，两个低一或还是低，这个低输出就肯定意味着`CPU`在对`I/O`读，我把它标成`IOR#`；同样`M/IO#`为低和`WR#`为低相或，输出低就是`CPU`在对`I/O`写，标成`IOW#`。

```text
M/IO# (低=I/O) ---+---[ 或门 ]--- IOR# (低有效: CPU对I/O读)
RD#   (低=读)  ---+

M/IO# (低=I/O) ---+---[ 或门 ]--- IOW# (低有效: CPU对I/O写)
WR#   (低=写)  ---+
```

读图说明：两个低碰在一起或出低，正好对应“选中`I/O`又正好在读/写”的那一刻。

反过来用与非门也行：`M/IO#`取高、`WR#`取高（不够高就加反相器凑），两高相与得高、再反成低，这个低就是`CPU`对存储器写，叫`MEMW#`。同理能搭出存储器读`MEMR#`。门的形式可以换，判断逻辑只有一条：先看`M/IO#`定对象，再看`RD#`、`WR#`定方向，读的时候不可能同时写，写的时候不可能同时读。

## 第 2 章：地址线条数与 I_O 端口：20 根线定出 1MB，打印机例子讲透三类端口
> 对应分集：P14 | 原始标题：《地址线条数与 I_O 端口：20 根线定出 1MB，打印机例子讲透三类端口》

在 8086 里一共有多少根地址线？20 根。从最低位 `A0` 到 `A19`，一共 20 根。这 20 根地址线全部用来给外部存储器提供地址，所以 8086 能寻址的外部存储器空间是 $2^{20}$ 个地址单元。$2^{20}$ 是多少？1 兆。存储器是按字节组织的，每个单元放 8 位二进制信息，第一节课就讲了，所以是 1MB，字节两个字丢掉不行，要说 1M 字节。

### 地址线条数决定寻址空间

好多同学课外玩 51 系列单片机，8051 那种 CPU 有 16 条地址线，能寻址的外部存储器空间是多大？$2^{16} = 65536$。除以 1024，为什么除以 1024？1024 等于 1K，所以是 64K 字节。说话要标准，64K 字节。

把第一节课的结论再回忆起来：CPU 地址引脚条数的多少，或者说一个微处理器系统里地址总线条数的多少，意味着什么？意味着 CPU 能寻址的外部存储器空间的大小。线越多，能找的地方越多，就这么直接。

8086 用 20 位地址线的低 16 条，同时也给外部 I/O 提供地址。所以 8086 能寻址的外部 I/O 地址空间是 $2^{16}$，64K，也是按字节算。那么问题来了：CPU 通过低 16 条地址线输出一个 16 位地址码，你怎么知道它是给 I/O 的地址，还是存储器 20 位地址的低 16 位？你怎么知道？通过那个引脚知道。当那个引脚输出低电平时，这 16 位地址线上的地址肯定是 CPU 给 I/O 的地址。这个概念要搞清楚。

| CPU | 地址线 | 存储器空间 | I/O 空间 |
| :--- | :--- | :--- | :--- |
| 8086 | 20 根（`A0`~`A19`） | $2^{20} = 1M$ 字节 | 低 16 条复用，$2^{16} = 64K$ |
| 8051 | 16 根 | $2^{16} = 64K$ 字节 | — |

### 总线与存储器、I/O 接口的概念

再回到 13 页。上边看了 CPU 通过微处理器级总线完成的功能有 1、2、3，下边还有一句话：总线是用于连接 CPU 与其他部件的一组连线。第一节课我怎么下的定义？用来进行信息传输的通道。通道是不是就是一组连线？和书上讲法一样。后面又说总线从功能上可分为三种：`DB`、`AB`、`CB`，都是前面讲过的，每一种总线传输什么信息、起什么作用，要掌握清楚。

再往下看讲存储器。要求掌握的是计算机中的存储器按字节组织。为什么这里又讲存储器？图 2.1 画方框图把存储器画出来了，所以顺带提一下。这一段讲 I/O 接口，I/O 接口是连接 CPU 与 I/O 设备的控制电路，和我们讲的含义一样：任何 I/O 设备和 CPU 之间都不能直接通信，要通信就必须在二者之间设计连接二者进行通信的那一部分接口电路。

这里边有一句话大家可能看不懂：在 I/O 接口中有一个 I/O 端口寄存器，用来与 CPU 之间做数据交换，计算机也为其分配一个地址，这个地址就叫 I/O 端口地址。是不是引出来端口的概念？什么是端口？I/O 端口实际上就是一个寄存器，这个寄存器用来实现 CPU 和设备之间的信息交换。

### 打印机例子：状态输入端口与三态

为了让大家理解，我举个例子。假如有一个智能设备，并行打印机。CPU 要把打印的数据通过总线、通过接口给打印机，显然二者之间要设计传送信息的接口电路，这就是 I/O 接口电路。

CPU 什么时候把数据给打印机？你不能想给就给，是不是要看设备的状态？线连上了吗？纸装上了吗？它现在是不是正忙着打？这些状态 CPU 必须知道。CPU 不知道，设备自己知道，所以设备要把状态送给接口。在接口里就要设计一个传送状态信息的通道，这个通道就是一个端口，叫状态输入端口。设备把状态送到这个端口，CPU 读这个端口。读就要给它分配地址，CPU 按这个 I/O 端口地址找到它，把数据沿数据总线读回 CPU。

这个状态输入端口是怎么设计的？显然是一个输入缓冲器。平时信息能到输入端但出不来，它的输出端呈第三态，高阻态。当 CPU 要取状态时，按分配的 I/O 端口地址找到它，把这个端口选中，选中信号一到，它的输出端呈二态，和数据总线导通，CPU 把状态取走。当 CPU 不读它时，信号无效，所有输出端都回到第三态。

为什么必须这样？因为它的输出端接到数据总线 `DB` 上，数据总线不只接你一个端口，还接好多端口，还接到存储器芯片上。CPU 和谁操作，才选中谁，选中的芯片和数据总线相连的引脚才处于二态，没选中的都必须是三态。如果不这样，同一条数据总线上同一时刻会出现两个以上的状态，$0$ 和 $1$ 打架了。这种打架叫什么？数电课学的，竞争，总线竞争。

打个比方，双向数据总线 `D0` 位，这边接一个输入端口，那边接另一个输入端口。如果两个端口同时打通，一个输出 $1$，一个输出 $0$，这根线上又有 $1$ 又有 $0$，是不是竞争了？所以设计输入端口，选的器件输出端必须具有三态功能。控制端就是地址译出的选中信号：CPU 操作你的地址时你导通，不操作时处于高阻态，始终保证数据总线上任何时刻最多只有一个状态，这样就不会竞争。

> **结论**：输入端口器件的输出端必须有三态功能，选中时导通二态，未选中时高阻。

一旦发生总线竞争会出现什么问题？轻者系统瘫痪，根本不工作，计算机都启动不起来；重者冒烟，烧了。为什么能烧？从电路上分析：总线竞争时，输出 $1$ 的一端输出电流，输出 $0$ 的一端有倒灌电流，倒灌电流把输出电流往里拉，电流不断增大，增大到一定程度管子就烧了。

### 数据输出端口与命令输出端口：握手

CPU 通过状态输入端口把设备状态读回去了，读回来是编写程序控制的，对状态逐个测试，哪个等于 $1$、哪个等于 $0$，测高低电平，就知道设备准备好了。一旦发现没准备好就继续读、继续测，直到所有状态都准备好，CPU 就可以通过数据线给打印机输出数据了。

输出数据不能走刚才那个通道，必须再设计一个通道，也就是一个端口。CPU 通过数据线把给设备的数据输出给这个端口，由这个端口再给设备。这个端口也有它的地址。输出的是数据，显然叫数据输出端口。

CPU 通过数据输出端口把数据一输出，执行下条指令去了。CPU 很快，设备很慢，它还没反应过来。怎么办？在这个器件的输出端必须具有锁存功能，把数据锁存住，CPU 干别的去，慢设备慢慢响应。锁存器一上电不是 $1$ 就是 $0$，所以没输出有效数据之前，线上也有数据，但是无效的。只有 CPU 把数据通过输出端口锁存住，线上才有有效数据。

有效了，设备怎么知道？CPU 知道，设备不知道，CPU 得告诉设备。这里还要再设计一个端口：命令输出端口。CPU 通过数据线上的某一根线给命令输出端口写个值，好比原来是 $1$，发一个 $0$，这个 $0$ 再送给设备，设备收到这个低电平就说哦数据有效了，有效了就取走。

显然 CPU 和设备之间的数据交换始终是一种握手状态：CPU 怎么知道设备准备好？读取设备状态，查询、测试状态；设备准备好后，CPU 通过数据输出端口输出数据；数据锁存住后，CPU 通过命令输出端口给设备发命令。命令和状态都是握手信号、联络信号。CPU 与智能设备之间的信息交换，简单的工作原理就是这样。

```text
CPU  <--- 状态输入端口 <--- 设备状态 (三态缓冲, 选中导通)
CPU  ---> 数据输出端口 ---> 设备数据 (锁存保持, 等慢设备取走)
CPU  ---> 命令输出端口 ---> 设备命令 (数据有效通知)
```

三个端口分工不同：状态口是输入、要三态；数据口是输出、要锁存；命令口也是输出、发联络信号。把打印机这个例子吃透，端口的概念就立起来了。

## 第 3 章：三种信息三种通道：端口定义与统一编址独立编址之争
> 对应分集：P15 | 原始标题：《三种信息三种通道：端口定义与统一编址独立编址之争》

通过上节那个简单的原理能看到：CPU 通过 I/O 接口和设备相连，接口里面有这么多端口。CPU 和设备之间要传送的信息是不是有三种了：状态、命令、数据。显然通过这个图能明确看到，CPU 与设备之间传送的信息按种类走各自专用的通道，一个通道就是一个端口。端口有输入端口，有输出端口。

### 端口就是传送一种信息的通道

下定义的话：一个 I/O 端口就是用来传送一种信息的通道。传送信息的通道在设计时是不是用寄存器设计的？你看输出要锁存，是不是要用寄存器。1 位可以用 `D` 触发器，`74LS74` 一个芯片里是不是有两个 `D` 触发器；8 位呢，8 个 `D` 触发器，数电课学过一个芯片叫 `74LS373`、`374`、`273`，都是 8 位锁存器。输入端口输出端要具有高阻态第三态，1 位用一个三态门，8 位用 8 个三态门，数电课学过的 `74LS244`、`74LS245`，245 是双向的，244 是单向的，都是数电课学过的。所以第一次课就说学这门课前面要具备数字电路知识。

> **提示**：这门课的硬件设计在第 5 章以后，但 2.1 节讲外部结构就先把端口引出来了。这些数电知识的应用都是硬件设计。

显然一个 I/O 端口就是一个 I/O 寄存器。实际应用中给一个 I/O 端口至少要占用一个 I/O 地址，它占用的这个地址称为 I/O 端口地址，简称端口地址。分配给它的地址显然是 64K 地址空间中的一个。

8086 有 16 条地址线给 I/O 提供地址，如果一个端口占用一个地址，最多能管理 64K 个 I/O 端口。注意我的意思：一个端口至少占用一个 I/O 地址，一般是一个。能听懂吗？打个比方，一个房间至少要分配一个房间号，这话对不对？但你给房间分配门牌号时分配两个行不行？可以。你这房间是 210，我说房间号是 21X，这一位不分配，那这个房间是不是占了 210 到 219 共 10 个门牌号。编程时用了 210，还多出 211 到 219，但这一层楼上再不能有 211 到 219 了，再有就和它重叠了。实际应用中一个 I/O 端口要分配一个 I/O 地址，当然可以重叠分配，但重叠的所有地址再不能给其他端口了。

### 统一编址：把 I/O 当存储器

2.1 节 13 页倒数两三段还有一段话同学们可能看不明白，我解释一下。先看倒数第三段：某些微处理器采用统一的地址空间对存储器和 I/O 端口寻址。抓住统一两个字：存储器和 I/O 端口进行统一的地址编码，一个地址要么对应存储单元，要么对应 I/O 端口寄存器。也就是说这类微处理器对 I/O 端口和存储器的编址采用统一编址：一个地址码给了某存储器单元编码，这个地址码再不能给 I/O；另一个地址码给 I/O 编址了，就再不能给存储器。CPU 把外部存储单元和外部 I/O 端口看成同一件事、同一个对象了，这就叫统一编址。

最大的缺点能想象出来吗？有些地址给 I/O 编址了，这些地址再不能给存储器，对存储器而言空间是不是缩小了？最大缺点就是浪费了存储器地址空间。没有优点就不可能研制，优点是什么？既然统一编址，CPU 操作外部任何一个 I/O 端口时是不是视为一个存储器单元来操作？那就意味着 CPU 对存储器读写操作的所有指令同样适合对 I/O 端口操作，在 I/O 驱动程序设计中程序设计简单。这话拐得太快，我展开说：任何型号的 CPU 对外部存储器操作首先要找到被操作单元的地址，找地址叫寻址方式。CPU 对存储器的寻址方式种类比较多，种类多，同样适合对 I/O 端口的操作，对 I/O 端口操作的程序编写是不是灵活了？换句话说，没有专用的 I/O 操作指令，对存储单元操作的所有指令同样适合 I/O 端口，所以优点是 I/O 驱动程序用汇编语言编写方便灵活。`MCS-51` 系列 CPU，像你们用的 8031、8051，都采用统一编址。

### 独立编址：8086 的选择

对 I/O 端口的编址还有一种方法叫独立编址。看 13 页倒数第二段：大多数微处理器采用两个独立的地址空间。什么意思？存储器地址空间和 I/O 地址空间独立。8086 就是两个独立的地址空间：20 根地址线全部用来给外部存储器编址，低 16 位 `A0` 到 `A15` 同时也对外部 I/O 端口编址，但通过 `M/IO` 信号识别开输出的地址是对存储器的还是对 I/O 的。既然有信号识别，两个空间就独立开了。

独立编址最大的优点正对统一编址的缺点：I/O 并没有占用存储器地址，节约了存储器地址空间。缺点是什么？地址空间独立意味着对存储器读写和对 I/O 端口读写要用不同指令区分，CPU 设计时就要专门设计对 I/O 操作的指令。对程序员而言，既要记对存储器操作的指令，还要记对 I/O 操作的指令，记忆复杂了，相对而言。同时对 I/O 操作指令的寻址方式比较单一：8086 对存储器操作有 5 种寻址方式，对 I/O 操作只有 2 种，程序设计显然没那么灵活，I/O 程序设计不灵活。

| 编址方式 | 代表 | 优点 | 缺点 |
| :--- | :--- | :--- | :--- |
| 统一编址 | `MCS-51` | 所有存储器指令可用于 I/O，程序编写方便灵活 | 浪费存储器地址空间 |
| 独立编址 | 8086 | 节约存储器地址空间 | 需专用 I/O 指令，寻址方式少（2 种对 5 种），记忆多、灵活性差 |

### 直接寻址与间接寻址：找地址的方法越多越灵活

看对存储器操作。假如这是存储器，一个单元一个字节单元，假如这个单元的地址是 `2000H`（8086 其实是 20 位，这里只写 16 位示意）。现在要给这个单元写数据 `0AH`，怎么写？先把数据放到 `AL`：

```assembly
MOV AL, 0AH
MOV [2000H], AL
```

目的是这个单元，写地址就要打上中括号表明是地址。直接写 `2000H` 就是数据，打上中括号才是地址。这条指令把 `AL` 内容写到中括号里地址对应的单元去。现在我要找被写单元的地址，在指令中直接给出了，这种寻址方式就叫直接寻址。

还可以间接给出：

```assembly
MOV AL, 0AH
MOV BX, 2000H
MOV [BX], AL
```

把被操作单元的地址事先存到 `BX` 这个 16 位地址寄存器去，再操作 `MOV [BX], AL`。一打中括号是不是地址？意思是把 `AL` 内容写到目的去，目的单元的地址间接放在 `BX` 里，以 `BX` 内容 2000H 做地址找到这个单元。这条指令里被写单元地址的寻址采用的是间接寻址，同样完成写操作。

意思就是：对存储单元读也好写也好，要操作就要寻找被操作单元的地址，寻找地址叫寻址，寻址的方法越多程序设计越灵活。对 8086 而言，对存储器操作寻址的方式一共 5 种，用哪一种找这个单元都行。

下面看 I/O。假如这边是 I/O，I/O 这边要设连接 I/O 和系统总线的接口电路，假如接口芯片是 `74LS374`，里面 8 个 `D` 触发器，8 个 `D` 输入端 `D0` 到 `D7`，8 个 `Q` 输出端 `Q0` 到 `Q7`。我把 `D0` 接数据总线第 0 位，用 `Q0` 给设备输出数据。设备这样接：通过一个电阻上拉到正 5V 电源，接一个发光二极管。我输出个 $1$ 它是不是亮了，输出 $0$ 是不是灭了，这就是一个设备。

```text
数据总线 D0 ---> [D0  74LS374  Q0] ---> 电阻 ---> +5V
                                              |
                                         发光二极管(设备)
```

输出 $1$ 灯亮、输出 $0$ 灯灭，8 位可以同时输出 8 位。到下一讲我就要用这条指令给这个端口输出数据，让灯亮灭，I/O 程序设计就是这么落地的。

## 第 4 章：从一盏灯到 CPU 内部：OUT 指令与一般微处理器的四大部件
> 对应分集：P16 | 原始标题：《从一盏灯到 CPU 内部：OUT 指令与一般微处理器的四大部件》

上节那个发光二极管的例子还没做完。CPU 要给设备输出数据，是不是要给设备对应的输出端口输出数据？这个端口要分配地址。什么时候能输出？当 `OE` 非是低电平时允许输出，但能不能锁存住还要看 `CP` 端。给 `CP` 端加一个上升沿，在上升沿作用下把数据端的数据咕咚打入 `Q` 端并锁存住。锁存功能刚讲过。假如分配给这个端口的地址是 `2000H`，16 位的，我通过这个端口输出数据让灯亮，8086 的指令就是：

```assembly
MOV AL, 01H
MOV DX, 2000H
OUT DX, AL
```

我想让它亮，输出 $1$，`01H` 就是 $0000\ 0001B$，末位是 $1$，其他高位都是 $0$。把端口地址 2000H 给 `DX`，对 I/O 操作的地址寄存器就是 `DX`。然后 `OUT`，把 `AL` 的内容输出到以 `DX` 内容做地址的端口去。

### 给 I/O 写是 OUT，给存储器写是 MOV

显然，给 I/O 端口的写指令是不是 `OUT`？给存储器写是不是 `MOV`？看到没有，指令不同，说明地址空间不同，它采用的是独立编址。CPU 执行到这条指令时，执行之前输出端那个地址译码是高的，执行期间变低，数据线上数据有效了再变高。由低变高是不是来个上升沿？这个上升沿把数据线上的数据锁存住，一旦锁存住一个 $1$，灯就亮了。

通过这个例子看什么？独立编址中对 I/O 操作有专用指令：对输出端口写是 `OUT`，从输入端口读是 `IN`。8086 的输入输出操作指令简单说就是 `IN`/`OUT`。而对存储器操作是它自己的指令。这就是独立编址的优点：节约了存储器地址空间，I/O 操作有专用指令，占的是 I/O 地址空间，没占存储器地址空间。但是 I/O 操作有了专用指令，书写时要用专用指令写，记忆是不是复杂了？我这里严格讲不是指令复杂了，是指令记忆复杂了，多记几条指令嘛。

而且 8086 对 I/O 操作的 `IN`/`OUT` 指令寻址方式只有两种。我上面用的就是间接寻址：`IN`/`OUT` 的间接寻址寄存器是 `DX`，且不打中括号。存储器操作的间接寻址寄存器有 `BX`、`SI`、`DI` 等等，但要打中括号。都要区别开。

| 对比项 | 存储器操作 | I/O 操作 |
| :--- | :--- | :--- |
| 写/读指令 | `MOV` | `OUT` / `IN` |
| 间接寻址寄存器 | `BX`、`SI`、`DI` 等 | `DX` |
| 中括号 | 打 `[BX]` | 不打，`OUT DX, AL` |
| 寻址方式种数 | 5 种 | 2 种 |

这是 2.1 节后边那两段话引出来的。下面讲微处理机内部结构。刚才讲的是外部结构，现在看内部结构。学内部结构的目的，一是了解微处理器的工作原理，它怎么工作；二是要逐步掌握汇编语言程序设计的编程模型。这门课重点 obviously 看 8086 内部结构，但为了理解 8086，教材 2.2 节先讲只要是微处理机内部都该有的部件，就是一般微处理机的内部结构。

### 一般微处理机内部的四大部件

看 14 页图 2.2。不管什么型号的 CPU，内部必须有这四大部件。第一，`ALU`，必须有，做算术逻辑运算。为了提高运算速度，总希望参加运算的数据不要去外部存储器取，而在 CPU 内部取，因此 CPU 内部必须设计能暂存少量数据的寄存器，书上叫工作寄存器。工作寄存器分两类：一类叫数据寄存器，专门暂存数据，如 8086 的 `AL`；另一类叫地址寄存器，如 `BX`，对存储器读写时被操作单元的地址想间接由寄存器提供，能提供地址的就叫地址寄存器。地址寄存器专门提供地址，但不提供地址时还可以充当通用寄存器暂存数据，16 位地址寄存器是不是能暂存 16 位数据？但数据寄存器只能暂存数据。

第三大部件叫控制器。控制器可以叫中央指挥机关。什么意思？你用户编的程序在外部存储器放着，要让 CPU 执行，控制器就要负责从外部存储器把程序代码取回去，取程序代码叫取指令，取指令由控制器完成。控制器把指令取回去要让 CPU 执行，执行需要时间，执行期间控制器还要负责取下一条指令，但在取下一条之前，刚才取回的指令还没执行完，内部是不是要有个暂存它的部件？叫指令寄存器。取回的指令暂存在指令寄存器里，CPU 怎么知道做什么？要对指令代码译码，指令译码器译码分析，就知道指令让 CPU 做什么、怎么做。这些工作都是控制器完成的，所以叫中央指挥机关。

CPU 还要和外部 I/O 打交道，内部还必须有第四大部件：I/O 控制逻辑，设计能进行 I/O 控制的逻辑电路。不管任何型号的 CPU，内部按大功能分就是这四大部件。`ALU`、工作寄存器理解了，I/O 控制逻辑也理解了，不理解的还在控制器，所以教材对控制器里每个小部件分别解释。

### 控制器六小件与取指执行串行过程

图 2.2 左上角画的是控制器，一下给你画了六大部件。第一大部件叫程序计数器 `PC`，16 位，一般处理器的程序计数器都是 16 位。假如这是外部存储器，用户事先把编的程序不管用什么语言编译翻译成机器代码放在存储器里，这个放程序代码的区域叫代码区。CPU 要从这个区域某个地址单元开始把代码一个字节一个字节取回去，先取一个字节放指令寄存器，再由指令译码器译码分析。

首先让程序计数器通过地址总线给地址引脚输出要取指令单元的地址，同时 CPU 给存储器发一个读操作命令，在读命令作用下，这个地址单元的一个字节代码叫指令代码，沿双向数据总线 `DB` 取回来，放到哪？指令寄存器 `IR`，8 位，一般处理机都是 8 位。寄存到这 CPU 还没执行，程序计数器能往下移取下一条吗？不行，取回来没地方放了。

控制器里有个指令译码器 `ID`，也是 8 位，不断检测指令寄存器里有取回的指令吗？有了就取走放到译码器里，对指令译码分析，就知道这个字节代码让 CPU 做什么、怎么做。如果译出来是对存储器写，就通知下边的控制逻辑部件，在相应的控制引脚发出有效命令，写就发低电平写信号，这条指令就执行完了。执行完了指令寄存器空了，`PC` 自动增加：刚才的指令是双字节就增 2，三字节就增 3，指到准备取下一条指令的单元，再把指令代码取回来放指令寄存器，译码器再译码分析。

举个例子。这个单元放的是 `B0H`，下个单元是 `20H`，双字节指令，前面遇到过，实际上就是 `MOV AL, 20H`，把 20H 传送到 `AL`。程序计数器指到这，把 `B0H` 取回放指令寄存器，译码器一译码就知道哦要把一个字节数据传到 `AL`，而且知道要传的数据就在指令当中。CPU 就在指令代码的下一个地址单元取这个数据，但取回去的是数据不是指令代码，所以不进指令寄存器，直接通过内部数据总线给 `AL`。这条指令才算执行完，`PC` 自动增 2，取下一条去。一条一条取回执行，程序就执行完了。

```text
PC 输出地址 ---> 地址总线 ---> 存储器代码区
存储器指令字节 ---> 数据总线 DB ---> 指令寄存器 IR(8位)
IR ---> 指令译码器 ID(8位) ---> 译码: 做什么 + 怎么做
ID ---> 控制逻辑 ---> 控制引脚发命令(读/写)
数据字节 ---> 内部数据总线 ---> AL (不经过 IR)
PC 自动增量(双字节+2, 三字节+3) ---> 取下一条
```

在这种结构里分析：取指令时它是空的，译码器没指令可执行；取回来译码执行期间，取指令了吗？不能，取回来没地方放。所以这种微处理器是取指令、执行指令，再取下一条、执行下一条，串行下去。CPU 执行效率高吗？不高，特别慢。就是因为这种结构效率不高，Intel 公司才研制了 8086，解决了这个问题。8086 怎么解决的，下一讲看它的内部结构。

## 第 5 章：堆栈与 8086 内部结构：先进后出压弹与 BIU_EU 分工
> 对应分集：P17 | 原始标题：《堆栈与 8086 内部结构：先进后出压弹与 BIU_EU 分工》

先看什么是堆栈，把堆栈的含义搞清楚。要搞清什么叫堆栈，首先理解生活中的栈。生活中有装人的客栈，有装货的库房货栈，是不是？只要是栈，计算机中的栈是用来存放数据的。不管生活中的栈还是计算机里放数据的栈，都符合什么原则？比如教室是一间仓库，我把货一箱一箱往里装，最先搬进来的那箱放到哪了？最底部、最角落。货往外出时，先搬出去的是不是最后搬进来的？最后搬出去的是不是最先搬进来的？所以栈符合先进后出原则。计算机中放数据的堆栈，就是由先进后出原则组织的一段存储器区域。

### 堆栈是一段先进后出的存储器区域

存放堆栈的这段区域在哪？对 8086 而言，在 CPU 外部你设计的存储器里面。存储器最大空间 1M 字节，编程序时就在这 1M 空间里定义一个区间专门做堆栈。堆栈区域多大，程序员按需求定义。

往堆栈里放数据跟放货一样，就是往里压。压数据在 8086 里的助记符是 `PUSH`，取出来是往出弹，`POP`。这是第一点。第二，对 8086 而言堆栈必须按字操作。比如编到这想做堆栈操作了，为什么？CPU 内部暂存数据的寄存器就那么几个，程序复杂了感觉寄存器不够用了，就可以把寄存器里原来的数据 `PUSH` 压到堆栈里，寄存器释放出来暂存别的数据处理，等处理完再 `POP` 弹出来恢复。通过这种办法是不是扩大了寄存器个数？当然还有其他应用。

比如我想把 `AX` 内容压到堆栈里。堆栈必须按字操作，`AX` 是字寄存器，就是对的，`PUSH AL` 就错了。`PUSH AX` 把 `AX` 内容做源压到目的地堆栈去。堆栈区域这么大，压到哪个地址？入栈单元的地址由堆栈指针寄存器 `SP` 提供。定义堆栈区域时这个单元称为栈底，程序初始化以后 `SP` 内容做地址指向栈底加 1 单元的地址。

CPU 执行 `PUSH AX` 完成两步：第一步先把 `SP` 内容减 2 放回 `SP`。减 1 减 2，`SP` 指向这个单元，从这个单元往下空出一个字单元。第二步把 `AX` 16 位压进来。前面提示过规律：一个字存到存储器字单元，低字节存低地址单元，高字节存高地址单元。`AL` 存到这个单元，`AH` 存到高地址单元，这条指令才执行完，这就叫入栈。

同理下面再来 `PUSH BX`，又是这两步：`SP` 减 2 指到新单元，`BL` 写低地址单元，`BH` 写高地址单元。再 `PUSH CX`、`PUSH DX`，每执行一条 `SP` 都减 2。`SP` 现在指的这个单元叫栈顶。明显看到：栈顶是活动的，栈底是固定的。

```text
高地址  +------------------+
        |     栈底(固定)     |
        +------------------+
        |   AX 高字节 AH    |
        +------------------+
        |   AX 低字节 AL    | <-- PUSH AX 后 SP 指向这里
        +------------------+
        |   BX 高字节 BH    |
        +------------------+
        |   BX 低字节 BL    | <-- PUSH BX 后 SP 指向这里(栈顶, 活动)
        +------------------+
低地址  |   (继续 PUSH 向下)  |
        +------------------+
```

> **提示**：字数据的低字节存放在字单元的低地址单元，高字节存放在高地址单元。`PUSH` 是 `SP` 先减 2 再存，栈向低地址方向生长。

### 堆栈溢出与配对原则

程序设计中如果不注意，一直 `PUSH`、`PUSH`，`SP` 一直减，减到头还 `PUSH`，指针跑到堆栈区域外部去了；或者 `POP` 出栈时 `SP` 跑下来了，这两种都叫堆栈溢出。CPU 执行堆栈操作发现 `SP` 溢出就死机了，按任何键都不起作用，只能逼你 `reset`。所以用堆栈就要定义堆栈区域，定义多大？按程序实际需求，且留出 30% 富裕量。工程设计中任何指标都该有 30% 左右富裕量，不光不溢出，还便于程序更新维护。

恢复数据要遵循先进后出：`BX` 后压进去，`POP` 先出。`POP BX` 完成两步：第一，把 `SP` 内容做栈顶地址，从该地址读出一个字弹给目的 `BX`。这个地址对应的字单元是源操作数，`BX` 是目的操作数，指令里是单操作数，源不用写出来但 CPU 知道在哪。第二，`SP` 内容自动增 2，增 2 后的值给 `SP`，`SP` 又跑回去了，这个单元又叫栈顶。继续 `POP AX`，栈顶的字弹给 `AX`，`SP` 增 2，跑到栈底加 1 单元，回到初始化状态，数据恢复完 `SP` 也恢复了。

> **结论**：`PUSH`、`POP` 一定要配上对。只有配上对，程序运行期间才不至于堆栈溢出。

这就是 8086 的堆栈。一要掌握堆栈概念，二要掌握 8086 对堆栈的操作，三要理解堆栈指针寄存器含义。任何微处理器都有堆栈指针 `SP`，8 位机如 `MCS-51` 就是按字节 `PUSH`、`POP`。一般微处理器的第四大部分 I/O 控制逻辑很简单：CPU 要对 I/O 端口操作，内部就设计能操作 I/O 端口的那部分逻辑，前面讲过，这里补充一下。

### 8086 内部结构：BIU 与 EU

2.2 节讲一般微处理器内部结构：取指令、执行指令、再取再执行串行下去，效率很低。为了克服这个矛盾，Intel 先研制 8088，随后生产 8086。先看 8086，内部结构如 15 页图 2.3，图上只画了能说明问题的部件。不管图怎么画，四大部件 `ALU`、工作寄存器、控制器、I/O 控制逻辑仍然存在。

图 2.3 中间有条虚线，把 8086 分成两大部分：虚线右边叫总线接口单元 `BIU`，左边叫执行单元 `EU`。BIU 由什么组成？从上往下是 `CS`、`ES`、`SS`、`DS`、`IP` 这些寄存器。含义简单提一下：`CS` 是代码段寄存器，`C` 就是 `code`；`DS` 数据段寄存器；`ES` 附加数据段寄存器；`SS` 堆栈段寄存器，第一个 `S` 是 `stack`；还有 `IP` 指令指针寄存器，在 8086 里等效于一般微处理器的程序计数器 `PC`。寄存器下一节才细讲。

BIU 第二部分由地址产生与总线控制逻辑组成。举个例子：8086 有 20 根地址线 `A0` 到 `A19` 全部给存储器编址，对存储器不管做什么操作都要 20 位地址才能找到单元。但 `PUSH` 压到哪个单元，地址由 `SP` 提供，`SP` 只有 16 位；上节课 `BX` 间接寻址打中括号，`BX` 也是 16 位，只能提供 16 位地址。用 16 位地址寄存器只能寻址 $2^{16} = 64K$ 个地址，但 8086 能寻址 1M 空间，16 位寄存器寻址不完，怎么办？

Intel 把外部 1M 空间分成许许多多逻辑段管理，一个逻辑段最大 64K 字节，段内用 16 位地址寄存器寻址正好寻址完。寻址到段以外就切换段地址、改变逻辑段。所以 8086 程序设计中找读写单元，先要知道单元在哪个段，段地址谁提供？程序代码在代码段，取指令单元的段地址用 `CS` 提供，段内 16 位地址由 `IP` 提供；堆栈 `PUSH`/`POP` 先找哪个逻辑段，段地址由 `SS` 提供，段内 16 位地址由 `SP` 提供。

因此 8086 里被操作单元的地址由两部分组成：一个段地址，加段内 16 位地址，段最大 64K。编程时给的地址寄存器是 16 位，段地址也用 16 位描述，但外部只有 `A0` 到 `A19` 共 20 位地址线，内部就要经过一种运算，把段地址和段内 16 位地址运算成外部实际单元的 20 位地址。运算单元就在地址产生与总线控制逻辑里面，算出 20 位输出给 `A0` 到 `A19`，找到被操作单元。这些部件都在 `BIU` 里。

> **定义**：8086 的存储器管理按逻辑段进行：段地址（16 位描述）加段内偏移（16 位）经 BIU 内部运算形成 20 位实际地址。一个逻辑段最大 $64K$ 字节。

## 第 6 章：指令队列与 BIU_EU 并行：取指执行两条线与 14 个寄存器开篇
> 对应分集：P18 | 原始标题：《指令队列与 BIU_EU 并行：取指执行两条线与 14 个寄存器开篇》

今天重点讲 `BIU` 下方的结构：指令队列寄存器。它的含义类似 8 位微处理器里的指令寄存器 `IR`。从存储器取回一个字节指令代码放 `IR` 里，早期 8 位机指令寄存器只有 8 位，取回 8 位代码后 CPU 执行完之前不能取下一条，效率低。为解决这个问题，8086 内部设计了 6 个 `IR`，6 个字节组合成指令队列寄存器。从外部存储器取回指令代码直接存入队列，只要 6 字节没装满，`BIU` 就持续取指，效率显著提高。

### 8086 与 8088 只差队列长度

8088 和 8086 内部结构和功能只有一个区别：8088 指令队列是 4 个字节，8086 是 6 个字节。除此之外两款 CPU 内部逻辑 100% 兼容。

| CPU | 指令队列 | 兼容性 |
| :--- | :--- | :--- |
| 8086 | 6 字节 | 内部逻辑 100% 兼容 |
| 8088 | 4 字节 | 内部逻辑 100% 兼容 |

### BIU 取指与 EU 执行并行

`BIU` 的核心职责：从外部存储器代码段取指令代码，存入指令队列。8086 指令长度不一，单字节、双字节、三字节，最长 5 字节，一条指令里要区分操作码和操作数。`BIU` 取出操作码送入队列，6 字节没满就持续取。

`EU` 是执行部件，内部有控制器和指令译码器 `ID`。工作流程：不断检测队列里有没有取回的指令，有就按先进先出 `FIFO` 原则取出来，程序顺序执行，`BIU` 先存的 `EU` 先取。对指令译码分析明确操作内容然后执行。队列不空，`EU` 就连续"取指令—译码—执行"。

```text
外部存储器(代码段) ---> BIU 取指 ---> 指令队列(6字节, FIFO)
                                            |
                                            v
                                    EU 取出 ---> ID 译码 ---> 执行
```

`BIU` 从外部总线取指令，`EU` 从内部队列取指令执行，外部取指和内部执行并行进行，CPU 效率极大提高。这种取指执行并行的流水线机制自 8086 开始，一直沿用到 80186、80286、80386、80486、`Pentium`，后继机功能单元再多、主频再高，这个基本机制始终保留。

为什么 8086 快？车不光要跑得快，路还要修好，取指执行并行加总线高利用率，速度就上来了。

### 时序协同：谁停谁等

从运行状态看：`BIU` 只有队列完全充满才可能空闲暂停，但 `EU` 同步取走执行，队列很难充满；`EU` 只有队列空了才等待，但 `BIU` 持续取指补充，一般也不断空。以加电启动为例：

第 1 个周期，`BIU` 向程序存储器取指，队列为空 `EU` 空闲等待。第 2 个周期，队列未满 `BIU` 继续取下一条，`EU` 取出第 1 周期取回的指令译码执行。第 3 个周期，`BIU` 继续取，`EU` 继续执行。后续周期如果 `EU` 执行的指令要和外部打交道，对存储器或 I/O 端口读写，执行必须占用外部总线，`BIU` 就不能同时取指，产生总线使用权协调问题。

你取指令要用总线，执行指令在内部。`EU` 就通知 `BIU`：我执行这条指令要用总线，你帮我把这条指令执行完。这个周期 `BIU` 不取指了，帮 `EU` 完成操作。所以 `BIU` 什么时候停止取指？两点：队列取满了，或者 `EU` 要用总线了。`EU` 什么时候休息？只有一点：指令队列执行空了。

再看外部总线：这个周期 `BIU` 取指用总线很忙，下个周期取指用总线很忙，再下个周期不取指了但执行的指令要用外部总线，总线也很忙。所以总线一直在忙。取指执行并行提高效率，总线利用率也大大提高。

### 通用寄存器与 14 个寄存器分类

8086 内部除了检测执行指令的控制器，`EU` 里还有这么多寄存器，叫通用寄存器。什么叫通用？编程序就碰到、编程序就要用，叫通用。这些通用寄存器组成汇编程序设计的编程模型，通用寄存器功能和 `BIU` 段寄存器功能 2.4 节才讲，这一节先提一下。`EU` 里还有 `ALU`、`PSW` 等等，图中没画。这一节讲完，有了这些概念 2.4 节就好学了。我说重点掌握，很可能试卷上简答填空出来，但也不一定，内容很多。

下面看 2.4 节：8086 CPU 的寄存器组织。通过图 2.3 看到内部为程序设计设了好多寄存器，一共多少？14 个 16 位寄存器。学程序设计要逐渐背下来，掌握每个的含义用途。按功能分成三类学。

第一大类通用寄存器一共 8 个，图 2.3 左上角标出：`AX`（`AH` 与 `AL` 合并）、`BX`、`CX`、`DX`，加上 `SP`、`BP`、`SI`、`DI`，一共 8 个。又分两小类，第一类数据寄存器 4 个：`AX`、`BX`、`CX`、`DX`，都是 16 位，暂存字类型数据自然想到它们之一。除暂存数据还有各自特殊功能。

`AX` 叫累加器，只有 `AX` 叫累加器。程序里涉及字运算，目的操作数尽量选用 `AX` 充当，运算后大结果也放 `AX`，选 `AX` 比选别的寄存器快。字节运算累加器选 `AL` 或 `AH`，99% 场合选 `AL`，`AL` 是 8 位累加器。

`AX` 16 位可拆两个 8 位：`AL` 低 8 位、`AH` 高 8 位。什么时候用 8 位什么时候用 16 位前面讲过。同理 `BX` 拆 `BL`、`BH`，`CX` 拆 `CL`、`CH`，`DX` 拆 `DL`、`DH`。要用 8 位寄存器显然只有这 8 个。

`BX` 除了暂存 16 位数据，还叫基址寄存器。上节课的例子 `[BX]` 一加中括号内容做地址了，叫基址寄存器。以 `BX` 做基址加中括号间接寻址的单元显然是 `DS` 段的单元，后面举例子。

`CX` 特殊功能叫计数器。程序多有循环结构，循环多少次每循环工作一次，用 `CX` 做计数器减 1 计数。初始化时 `CX` 装循环次数，每循环减 1 到 0 退出。用别的寄存器做计数器也行，但 8086 里只有配合 `CX` 的专用指令，用别的得多写几条指令。

`DX` 在学 I/O 端口之前始终看成 16 位数据寄存器，暂存 16 位数据。但 `IN`、`OUT` 指令里 `DX` 充当 I/O 地址寄存器做间接寻址，不要加中括号，上节课举过例子。这就是四个数据寄存器的作用。

## 第 7 章：地址指针与变址寄存器：BP 和 BX 差一个默认段，SI_DI 的变从串操作来
> 对应分集：P19 | 原始标题：《地址指针与变址寄存器：BP 和 BX 差一个默认段，SI_DI 的变从串操作来》

通用寄存器第二类叫地址指针与变址寄存器，一共四个：地址指针两个，变址两个，全是 16 位。8 位的就那几个，底下讲的全是 16 位。

### SP 与 BP：地址指针寄存器

`SP` 堆栈指针寄存器已经理解了：指示 `PUSH`、`POP` 操作单元的段内 16 位地址，标准术语叫指示段内 16 位偏移地址。偏移两个字先不说，只说段内 16 位地址。堆栈操作的段地址谁提供？`SS`，16 位堆栈段寄存器。

第二个地址指针叫 `BP`，基址指针寄存器，16 位。作用和用 `BX` 做基址寄存器一样，但有区别。举个例子：这片存储器，这个区域定义成堆栈段，逻辑段嘛；那片区域定义成数据段，专门放数据，有字节型有字型。一个逻辑段一开始，这个单元的段地址，堆栈段段地址在 `SS` 里；这个单元相对段开始点向下的位移量叫偏移地址，16 位描述，这个是 0 个位移量、1 个、2 个。位移量 16 位描述，段最大多大？$2^{16} = 64K$。逻辑段开始单元的偏移地址是 0，下一个是 1，再下是 2。数据段这个单元段地址在 `DS`，段内偏移 16 位 `0002`，是不是这个意思？

现在编程序看：

```assembly
MOV BX, 0002H
MOV BP, 0002H
MOV AL, 34H
MOV [BX], AL
MOV [BP], AL
```

`BX` 和 `BP` 值都是 2，都是段内 16 位偏移地址。`MOV [BX], AL` 把 `AL` 写到 `BX` 内容做偏移的单元去，CPU 执行完写到数据段这个单元来了。`MOV [BP], AL` 地址由 `BP` 间接提供，但 `BP` 提供的 16 位偏移 CPU 默认是 `SS` 段的，这条执行完 `34H` 写到堆栈段这个单元来了。听懂没有？`BX` 基址寄存器和 `BP` 基址指针寄存器都能提供 16 位段内偏移，但不在同一个逻辑段：`BX` 默认在数据段，`BP` 默认在堆栈段，特别注意。

当然 `BP` 提供的偏移你认为是给数据段单元写，这条指令就要改：

```assembly
MOV AL, 56H
MOV BP, 0003H
MOV DS:[BP], AL
```

这样写偏移 3 是堆栈段 3 单元，但我要找数据段偏移 3 的单元，就在操作数左边贯穿一个前缀 `DS:` 特别指明。没有指明默认堆栈段。用 `BX` 间接寻址左边同样可以加前缀指明逻辑段。加的这部分叫段前缀，标准术语段超越前缀，简单说段前缀。加了段前缀，汇编时这条指令肯定多一个字节代码叫前缀码。

| 间接寄存器 | 默认段 | 改段方法 |
| :--- | :--- | :--- |
| `[BX]` | `DS` 数据段 | 加段前缀，如 `ES:[BX]` |
| `[BP]` | `SS` 堆栈段 | 加段前缀，如 `DS:[BP]` |
| `[SI]`、`[DI]` | `DS` 数据段 | 加段前缀 |

### SI 与 DI：变的概念来自字符串操作

两个变址寄存器：`SI` 源变址寄存器，`DI` 目的变址寄存器，都是 16 位。不管源目的，只看址是不是地址的意思？所以 `SI`、`DI` 都是地址寄存器。对存储单元读写，用 `BX` 间接能找到，用 `BP` 可以，用 `[SI]`、`[DI]` 中括号也行。但 `BX`、`SI`、`DI` 中括号找到的都是 `DS` 段单元，只有 `[BP]` 默认是 `SS` 段的。

其次还没讲的概念是变。变来自 8086 对字符串的操作。举个例子：这四个单元放 `31H`、`32H`、`33H`、`34H`，`31H` 是什么？字符 `1` 的 `ASCII` 码，也可以看成字节数据。这地方是不是放了字符串 `'1234'`？现在想把字符串搬到别处，字符串传送、移动、搬家，数据块移动，被移动的叫源串，搬到的叫目的串。8086 里用数据传送也能搬家，但为提高串搬家、串搜索、串比较的效率，专门开辟一类指令叫字符串操作指令，第三章 3.13 节专门讲。

用字符串指令搬家规定：源串必须定义在数据段 `DS`，源串首址的段内偏移必须由 `SI` 提供，源字出来了；目的串必须定义在附加数据段 `ES`，目的单元偏移必须由 `DI` 指明，目的出来了。现在差一个变，怎么变？初始化完用这样的指令：

```assembly
MOVSB
```

`MOVS` 的 `S` 是不是 `string`？字符串传送，`MOV` 数据传送，`MOVS` 字符串传送。后边写 `B`（`byte`）一次搬一个字节，写 `W` 一次搬一个字。CPU 执行这条无操作数指令，目的和源都没写，但它知道源指针在这、目的指针在这，自动把 `SI` 指单元内容按字节搬到 `DI` 指单元去，这是第一步。第二步，再往下搬，CPU 自动让 `SI` 和 `DI` 变：按首址往下增大方向加 1，一次一字节加 1，一次一字加 2；原来指末址就自动减。自动加减是不是自动在变？所以字符串操作里用 `SI`、`DI` 做地址指针才叫变址寄存器，变的概念从这来。把 `SI`、`DI` 用在数据传送里不会变，只有字符串操作指令里才自动变。

> **易错点**：`SI` 固定配 `DS` 源串，`DI` 固定配 `ES` 目的串。`[SI]`、`[DI]` 做普通间接寻址默认段都是 `DS`。

### 段寄存器：CS 用户无权写

第一类 8 个讲完。第二大类段寄存器一共四个。`CS` 代码段寄存器，值指明程序代码所在逻辑段的段地址。程序汇编后放存储器里应该有堆栈段、数据段、代码段，字符串操作还有附加数据段。所以 8086 程序设计要建立概念：用汇编符号编写程序就是定义一个逻辑段、再定义一个逻辑段，一个源程序由许许多多逻辑段组成。定义的可能是代码段、数据段、堆栈段，后面先学段怎么定义，有了段定义加那么多指令，还不会编程序？这么看 8086 汇编也不难。任何机型汇编思想都一样，但 51 单片机没有段的概念。

`DS` 数据段寄存器，`ES` 附加数据段寄存器，`SS` 堆栈段寄存器，分别放各自逻辑段的段地址。程序里这些逻辑段都定义用了，代码段一开始要对这些寄存器初始化，使它们指向定义的逻辑段段地址。而 `CS` 的初始值用户不能初始化，由操作系统完成。这句话的意思：考试问 `MOV CS, AX` 语法对吗？错。初始化由操作系统完成意味着用户无权初始化，用户不能给 `CS` 写，更确切说 `CS` 不能做目的操作数，做源读出来是可以的。

```assembly
MOV AX, CS   ; 对：CS 做源读出可以
MOV CS, AX   ; 错：CS 不能做目的操作数
```

## 第 8 章：控制寄存器：IP 与 PSW，DF_IF_TF 三个开关与 TF 置 1 的现场编程
> 对应分集：P20 | 原始标题：《控制寄存器：IP 与 PSW，DF_IF_TF 三个开关与 TF 置 1 的现场编程》

寄存器的第三大类是控制寄存器，一共两个。加上前面的一共几个？14 个。我开始下的定义是不是 14 个？考试出填空：8086 内部共有\_\_\_\_个寄存器，写 14；其中通用寄存器\_\_\_\_，把 8 个背过来。考试就在课堂上，课堂上讲的知识点下课至少消化 75%，听完课大部分理解了，下去稍微复习、作业一做，剩下光娱乐了。带着轻松的姿态学，别把自己搞太累。

### IP 与 CS:IP 不可分家

第一个控制寄存器看 `IP`，指令指针寄存器，16 位。假如有个逻辑段是代码段，CPU 从代码段取指令，要取的那条指令所在单元段地址由 `CS` 提供，偏移地址由 `IP` 提供。所以 `IP` 等效于一般 8 位机里的程序计数器 `PC`。`CS` 冒号 `IP` 是一对，不可分家。刚才说 `CS` 不能做目的，显然 `IP` 也不能做目的。

第二个控制寄存器是 `PSW`，处理器状态字寄存器，前面提到过，也是 16 位。每位布局含义如图 18 页图 2.5。16 位里有用的只有 9 位，7 位没用。有用的 9 位分两类标志：一类状态标志，一类控制标志。

### 状态标志：ALU 运算后结果的状态

状态标志 6 位：`ZF`、`CF`、`PF`、`OF`、`SF` 和 `AF`。下定义：这 6 个状态反映的是 `ALU` 运算后结果的状态，抓住运算后。所以没运算的指令不影响状态标志。`MOV` 指令运算了吗？没运算，执行后不影响这些标志。运算指令执行后什么状态置 1、什么状态清零，前面讲过，下去复习，做作业随时用，不举例子了。设置清零要重点掌握。这几个里除 `AF` 外，剩余 5 个也都是条件分支程序设计中的条件之一。

> **定义**：状态标志反映 `ALU` 运算后结果的状态。无运算就不影响，有运算才置位。

| 标志 | 类别 | 含义 |
| :--- | :--- | :--- |
| `ZF`、`CF`、`PF`、`OF`、`SF`、`AF` | 状态标志（6 位） | `ALU` 运算后结果的状态；除 `AF` 外 5 个可做分支条件 |
| `DF`、`IF`、`TF` | 控制标志（3 位） | 控制 CPU 运行状态 |

### DF：控制串操作 SI/DI 变的方向

控制标志只有 3 位：第九位 `IF`，第八位 `TF`，第十位 `DF`。先看 `DF` 方向控制标志。这三个控制标志都是控制 CPU 运行状态的。

`DF` 程序里可置 1 可清零。计算机一开机 `reset` 复位 `DF` 自动清零。程序里排 `CLD` 无操作数指令，`DF` 清零；排 `STD`，`DF` 置 1。看目录第三章 3.8 节标志位操作指令，61 页表 3.5：`CLC` 让 `CF` 清零，62 页 `CLD` 让 `DF` 清零、`STD` 让 `DF` 置 1。什么意思？看黑板。

方向控制标志用在字符串操作指令里。CPU 执行 `MOVSB` 时如果 `DF` 清零，执行完 `SI` 和 `DI` 自动往增的方向变，字节操作增 1，字操作增 2；如果 `DF` 置 1，传送完自动让 `SI`、`DI` 减，往减少方向变，减 1 减 2 看操作类型。所以 `DF` 控制字符串操作 `SI`、`DI` 变的方向。想按地址增大方向变，`SI`、`DI` 初始化指向源串和目的串首地址；按减小方向变，初始化指向末地址。

### IF：中断允许与 NMI/INTR 两个引脚

`IF` 中断允许标志。要理解先理解什么是中断，中断实际是一种打断。CPU 执行期间打断它现在的程序让它执行另一段程序去。我是 CPU，说一句话执行一条指令，我执行程序期间你突然举手，是不是把我打断了？我就问你想说什么，刚才的程序不执行了，执行这个程序来了，执行的这个叫中断服务子程序。你举手是在 CPU 芯片内部提出来的，叫内部中断；有人敲门是芯片外部提出中断，叫外部中断。

中断就是 CPU 执行用户程序期间，由于某个特殊事件发生，让 CPU 暂时停止正在执行的程序，转去为事件服务，执行中断服务子程序，服务完正确返回刚才中止的地方继续往下执行，这么一个过程叫中断。

任何型号 CPU 外部提出的中断都可以屏蔽，屏蔽了再提我不理睬；标志打开了，一敲门就要理。CPU 内部中断源提出的中断不能屏蔽，必须响应。8086 也不例外，看 5.3 节图 5.5，163 页。外部设备能向 CPU 提外部中断请求的输入引脚有两个：17 脚 `NMI`，`N` 是 `not`，`M` 是屏蔽，`I` 是中断，不能屏蔽的中断输入引脚，叫非屏蔽中断请求信号；18 脚 `INTR`，外部中断请求信号从这进来，从 `INTR` 提出的叫外部可屏蔽中断请求。可屏蔽怎么屏蔽？由 `IF` 控制。`IF` 清零就屏蔽了，通过 `INTR` 提的中断 CPU 不理睬；`IF` 置 1，CPU 开中断、中断允许，通过 `INTR` 提的才响应。

怎么让 `IF` 清零置 1？62 页表：`CLI` 让 `IF` 清零，CPU 关中断，处于外部可屏蔽中断不允许状态；`STI` 让 `IF` 置 1，CPU 开中断。用 8086 做应用要用到外部可屏蔽中断，主程序和中断服务子程序设计里别忘了 `IF` 置 1，CPU 要开中断。

> **提示**：`NMI` 不能屏蔽，`INTR` 受 `IF` 控制。`CLI` 关中断，`STI` 开中断。

### TF：陷阱标志与 DEBUG 单步

最后一个 `TF` 叫陷阱标志，不好理解叫单步标志。一 `reset` 复位开机 `TF` 清零，`TF` 清零 CPU 取一条执行一条连续执行直到程序结束。`TF` 置 1，CPU 执行一条就停止，下头不执行了，引起单步中断、陷阱中断，转去执行陷阱中断服务子程序。`DEBUG` 听过没有？`DEBUG` 里 `T` 单步跟踪命令一条一条执行，每 `T` 回车一次引起一次陷阱中断。汇编后机器代码的调试工具就是 `DEBUG`，这门课学完 `DEBUG` 要会用。

再看 62 页表：`DF` 有清零置 1 指令，`IF` 有，`TF` 有吗？没有。想让 `TF` 置 1 怎么办？讲到今天为止，考试叫你编程序实现 `TF` 置 1 应该会了，不能每个知识点都举例子，例子举到 80 岁举不完，要围绕知识点思维。

`PSW` 在 8086 里也叫 `FLAGS`，取 `F` 标志寄存器意思。按刚学的堆栈有指令 `PUSHF`，把 `FLAGS` 16 位压栈。压栈后 `POP AX` 出栈，通过两条指令 `FLAGS` 和 `AX` 之间数据传送复制过去了，`AX` 每位反映 `FLAGS` 每位。想让 `TF` 置 1，查图 2.5 看 `TF` 在哪一位？第八位，18 页。怎么办？讲过想把某些位置 1、剩余位不变用什么？或，用上了：

```assembly
PUSHF
POP  AX
OR   AX, 0100H
PUSH AX
POPF
```

`AX` 第八位或 $1$、剩余位或 $0$，16 位数就是 `0100H`。或完结果在 `AX`，`PUSH AX` 压栈，`POPF` 复制回来，`TF` 置 1 了。之后程序再执行就是单步了。单步到一定程度想恢复 `TF` 清零，同样的操作，这地方换成与。前面讲的知识点要会用。

> **结论**：`TF` 无专用置 1 指令，用 `PUSHF` 取出、`OR AX, 0100H` 置第八位、`POPF` 送回；清零把或换成与。这是对或运算"某些位置 1"场合的活学活用。

## 第 9 章：存储器与 I_O 地址空间：PC 只用 10 根线与字节字型存放格式
> 对应分集：P21 | 原始标题：《存储器与 I_O 地址空间：PC 只用 10 根线与字节字型存放格式》

今天讲 2.5 节，8086 的存储器和 I/O 组织。先看第一个问题：8086 微机系统里存储器地址空间与数据存放格式。讲地址空间时把 2.5.3 节 I/O 地址空间引出来放在一起讲。

### 存储器 1M 与 I/O 64K

已经知道 8086 有 20 根地址线，`A19` 到 `A0`。前面提过 20 位全部给外部存储器分配地址，所以能寻址的存储器地址空间是 $2^{20} = 1M$ 字节。同时低 16 条也给外部 I/O 端口编址，能寻址的 I/O 地址空间是 $2^{16} = 64K$ 个地址。一个端口传 8 位就是一个字节端口，按字节算 64K 字节。

在 `IBM PC` 机里只用了低 10 根地址线，`A9` 到 `A0` 给 I/O 分配地址。人们认为一个微机系统根本用不了这么多 I/O 地址，如果用 `A0` 到 `A15` 全参加译码，译码电路就复杂了。所以为简化译码设计，PC 机 I/O 地址空间是 $2^{10} = 1K$ 字节，范围 `000H` 到 `3FFH`。3 是两个 1，`FF` 是 8 个 1，一共 10 个 1，$2^{10}$ 就是 1K。

这 1K 又分成两个半 K：`000H` 到 `1FFH` 前 512 字节，`200H` 到 `3FFH` 后 512 字节。PC 机规定前 512 个给主板上的 I/O，后 512 个给插件板上的 I/O。系统里有主板有那么多插卡，主板 I/O 在低半 K，插件板 I/O 用后半 K。你基于 PC 开发产品，硬件做成板子插 PC 总线上去，板上 I/O 地址就要在这个区间找，看说明书，后半 K 里哪个地址被哪个插件板占了就不能用，只能用别人没用过的地址。后续讲译码电路举例时我从理论上讲不考虑这个，你实际应用一定要考虑，分配的地址必须是系统任何部件都没占用的。

| 空间 | 8086 理论 | PC 实际 |
| :--- | :--- | :--- |
| 存储器 | 20 根线，$2^{20} = 1M$ 字节 | — |
| I/O | 低 16 根，$2^{16} = 64K$ | 低 10 根 `A9`~`A0`，$2^{10} = 1K$（`000H`~`3FFH`） |
| 1K 分配 | — | 前 512 主板，后 512 插件板 |

### 伪指令是告诉汇编程序的

第二个问题看数据存放格式。数据在存储器放，存储器按字节组织，一个单元一字节。程序里用到的数据大多数字节型、字型，个别场合双字型，两个字占四字节。什么格式存放？先看字节型。

程序里定义字节数据怎么定义？数据定义在存储器哪个逻辑段？上节课提了逻辑段，数据段。数据段段地址谁提供？`DS`，概念复习一下。实际编程要定义一个数据逻辑段，在里面定义所有数据，有字节型有字型。假如数据段一开始：

```assembly
DATA1 DB 12H, 12, -12
```

`D` 是数据，`B` 字节型，`DB` 是一条伪指令。上一节提的 `MOV`、`ADD`、`PUSH`、`POP` 都是指令，指令是告诉 CPU 做什么的语句。伪指令显然不是让 CPU 执行的，是告诉汇编程序这个编译工具的：源程序要翻译，碰到伪指令就告诉编译程序怎么编译。`DB` 告诉汇编程序定义字节数据。定义在哪个单元？数据段定义的就在数据段，`ES` 段定义就在 `ES` 段，`CS` 段也能定义数据但一般不这么做。段一开始定义的字节数据，段内偏移地址是不是 0？

汇编就是翻译。编译程序在这个偏移 `0000H` 单元放 `12H`，逗号右边还有操作数 12，下一个单元放 `0CH`。没看懂吗？计算机中的数都用二进制表示，讲过没有？汇编程序把 12 一汇编就成二进制 `0CH`。还有一个操作数 -12，这个单元放 `F4H`。什么东西？补码！计算机中带符号数都用补码表示。-12 原码负的 `0001100`，求补码符号位不变、剩余位取反、末位加 1，是不是 `F4H`？

> **结论**：字节型数据一个占一个地址单元，若干字节数据连续顺序存放。十进制 12 汇编成 `0CH`，-12 按补码存成 `F4H`。

### 字型数据：低字节放低地址

字型数据要用字定义伪指令 `DW`，`D` 数据、`W` 字 `Word`。接着刚才的例子，三个字节占了偏移 0、1、2，下一个单元偏移 `0003H`，段地址不变还是 `DS` 提供。从偏移 3 开始定义字数据，这个字由偏移 3 和 4 两个相邻单元组成。3 相对 4 是低，这个是低地址单元，那个是高地址单元。一个字单元里低地址单元的地址称为该字单元的地址，这个字单元地址就是偏移 `0003`，高地址不说。

比如定义 `5678H`。字有低字节高字节，编译程序把低字节 `78H` 存在字单元的低地址单元，高字节 `56H` 存在高地址单元。

```text
偏移 0000H : 12H        (DB 第1个)
偏移 0001H : 0CH        (DB 12)
偏移 0002H : F4H        (DB -12, 补码)
偏移 0003H : 78H  ─┐    (DW 5678H 低字节在低地址)
偏移 0004H : 56H  ─┘    (高字节在高地址, 字单元地址=0003H)
```

低对低、高对高，这个规律前面 `PUSH AX` 讲过，`AL` 进低地址、`AH` 进高地址，前后是同一条规律。双字型四个字节同理按顺序连续放。数据存放格式吃透，往后定义数据、读写数据就不会晕了。

## 第 10 章：对准与未对准：偶地址字存取快一倍与存储器为什么分段
> 对应分集：P22 | 原始标题：《对准与未对准：偶地址字存取快一倍与存储器为什么分段》

接着定义数据。`DB` 是不是又定义一个字节，比如写 -1，偏移 `0005` 单元定义 `FFH`，-1 的补码。再定义一个字 `34A3H`，从偏移 6 开始，这个单元和下一个相邻单元组成字单元，字单元地址偏移 `6H`。低字节 `A3H` 放低地址单元，高字节 `34H` 放高地址单元。

### 对准的字快一倍

我把字数据讲了两种，有区别。什么区别？地址 3 的字单元是不是奇地址？地址 6 的字单元是不是偶地址？字单元地址是偶地址的称为对准的，奇地址的称为未对准的。实际操作中用 `MOV` 给字单元写或读，字操作，对准和未对准速度差一倍：对准的字读写只花一个总线周期，未对准的字读写花两个总线周期。我指的是 8086 系列 CPU。

> **定义**：字单元地址为偶地址称对准，奇地址称未对准。对准字存取 1 个总线周期，未对准 2 个。

为什么？8086 有多少条数据线？16 根，`D0` 到 `D7` 8 根，`D8` 到 `D15` 8 根。`D0` 到 `D7` 叫低 8 位数据线，`D8` 到 `D15` 高 8 位。字节读写传 8 位，单元地址是偶地址走低 8 位，奇地址走高 8 位，有这么个传送规则。

看偶字单元，对准的。举例：

```assembly
MOV BX, 0006H
MOV AX, 3344H
MOV [BX], AX
```

`BX` 基址寄存器放偏移 6，`AX` 放字数据。以 `BX` 间接寻址，`BX` 提供的 16 位偏移是 `DS` 段的，写到 6 单元来。`AX` 是 16 位所以是字单元，如果写 `AL` 找到的就是字节单元了。`AL` 低字节 `44H` 写低地址单元，`AH` 高字节 `33H` 写高地址单元。因为对准，CPU 只花一个总线周期：低地址单元地址是偶地址，低 8 位数据走 `D0` 到 `D7`；高地址单元偏移 7 是奇地址，高 8 位走 `D8` 到 `D15`。两个 8 位沿两组线哗并行写进去，一个周期。

反过来，未对准的：

```assembly
MOV SI, 0003H
MOV AX, 5566H
MOV [SI], AX
```

能打中括号间接的有 `BX`、`BP`、`SI`、`DI`，只有 `[BP]` 默认 `SS` 段，其余默认 `DS` 段。`AL` 低字节 `66H` 写 `SI` 指的 3 单元，3 是奇地址，走高 8 位 `D8` 到 `D15`，花一个总线周期。下个总线周期再把高字节 `55H` 写高地址单元偏移 4，4 是偶地址走低 8 位 `D0` 到 `D7`，又花一个周期。两个周期才写完，和对准的并行一次写完不一样。

```text
对准字(偶地址6):   AL->低地址(偶, D0~D7)  ║  AH->高地址(奇, D8~D15)   1个周期并行
未对准字(奇地址3): AL->低地址(奇, D8~D15) → 周期1, AH->高地址(偶, D0~D7) → 周期2
```

根据这个概念能总结出：程序里数据段定义字数据，经常读写的字尽量定义在偶地址上，提高处理速度。

### 双字 DD 与数据定义伪指令

实际还可能出现双字型，很少。比如定义双字 `783H`，用 `DD`，`D` 是 `data`，第二个 `D` 是 `double`，还是伪指令。双字单元四个字节，汇编把低字节写低地址单元，高字节写高地址单元，空缺补 0。双字存放也遵循低字节低地址、高字节高地址。

通过这个讲解引出数据定义伪指令：字节 `DB`，字 `DW`，双字 `DD`，绝大多数用在数据段定义里。书上第三章 3.1.3 节"变量及伪指令"，27 页，28 页"变量定义伪指令"有 `DB`、`DW`、`DD` 等。变量定义伪指令就是数据定义伪指令，为什么叫变量讲到那再说，不可能一次讲完。

### 存储器为什么分段

第一个概念讲完，第二个概念：存储器的分段与物理地址的形成。第一个问题，存储器为什么分段？上节课答过：8086 有 20 位地址线，能寻址 1M 字节，但寻址用的地址寄存器 `BX`、`BP`、`SI`、`DI` 都是 16 位，只能提供 $2^{16} = 64K$ 字节地址。用 16 位寄存器显然把 1M 寻址不完，为了寻址完，必须把 1M 空间分成许许多多逻辑段管理。用自己语言把概念答出来就行。

第二个，怎么分？提供地址的寄存器都是 16 位，分成的逻辑段最大只能 $2^{16} = 64K$ 字节，最大是 64K，实际用的段多大按需求，用 `DB`、`DW` 定义几个数据、告诉编译程序段结束，段就占几个字节单元。

还有一个原则：1M 空间里从哪个地址开始到哪个地址结束算一个逻辑段？每个逻辑段的起始地址必须能被 16 整除，只有被 16 整除的地址才能做段起始。比如 0 地址能被 16 整除，可以做起始；1 地址不能，就不能做起始。按这个原则理论上 1M 最多分多少段？每隔 16 个单元才有一个被整除，1M 除以 16 等于 64K 个逻辑段。

## 第 11 章：物理地址形成与表 2.1：段地址乘 16 加偏移与各类指令的地址信息
> 对应分集：P23 | 原始标题：《物理地址形成与表 2.1：段地址乘 16 加偏移与各类指令的地址信息》

段地址和段内 16 位地址怎么运算成 20 位？十六进制数朝左移一位相当于乘 16。十进制朝左移一位乘 10，二进制朝左移一位乘 2，十六进制朝左移一位是不是乘 16？再加上该单元的段内偏移地址。段内偏移也叫段内有效地址 `EA`，好多地方写 `EA` 就是有效地址。

### 逻辑地址与物理地址

看例子。某单元逻辑地址 `0001:0010H`，物理地址多少？段地址乘 16 加有效地址：`0001H × 16 + 0010H = 00010H + 0010H = 00020H`。反过来，物理地址 `00020H` 看成段地址 `0000` 的段：`0000 × 16 + 0020H = 00020H`，还是它。所以一个单元看成不同逻辑段，逻辑地址不相等，换算后物理地址唯一。

$$物理地址 = 段地址 \times 16 + 偏移地址(EA)$$

$$0001H \times 16 + 0010H = 00010H + 0010H = 00020H$$

### 取指令：CS 乘 16 加 IP

把书翻到 15 页，看 8086 从外部存储器取指令。`BIU` 里有个加法器 $\sum$。`BIU` 把 `CS` 内容送给加法器乘 16，再把 `IP` 内容送给加法器相加，得到取指令单元的 20 位物理地址，由地址产生与总线控制电路送外部 `A0` 到 `A19` 引脚，从对应单元取回指令。取指令段地址由 `CS` 提供，偏移由 `IP` 提供，它俩一对不可分家，都不能做目的，讲过没有？用户无法更改 `CS` 和 `IP`。

`CS` 的值谁给？操作系统给的。用户程序编译成机器代码存磁盘上，CPU 要执行，操作系统从磁盘找到可执行文件装入内存，装入过程中把程序起始代码单元的段地址给 `CS`，第一条指令的偏移给 `IP`。`CS:IP` 初始化是操作系统装入过程完成的，不是用户。程序执行期间 `IP` 也会变：执行到分支条件满足跳过去了，`IP` 变了，是转移指令执行改变的，不是你写进去的。程序从一个代码段跳到另一个代码段，代码段切换，无条件转移跳过去的，或者 `CALL` 另一个代码段的子程序，段间子程序 `CALL` 执行后 `CS` 和 `IP` 都变了，也不是用户强迫的。

### 数据传送与堆栈的地址形成

数据传送操作，比如 `MOV [BX], AX`，`AX` 16 位字写到 `DS` 段、偏移 `BX` 内容的单元。CPU 执行存储器写，`EU` 通知 `BIU`：我要存储器写了，你把取指暂停，帮我完成读写。`BIU` 把 `DS` 值送 $\sum$ 加法器乘 16，`EU` 把 `BX` 16 位沿内部数据总线传给 `BIU` 送加法器，`DS × 16 + BX` 得到 20 位物理地址，`AX` 内容送数据线，地址送地址线，同时发存储器写命令，数据写进单元。对准的字一个总线周期写完，未对准两个周期。

堆栈操作比如 `PUSH AX`，压到堆栈段单元，20 位物理地址怎么来？`BIU` 把 `SS` 送加法器乘 16，再把 `SP` 减 2 送加法器求和，得到压栈单元 20 位地址送 `A0` 到 `A19`。

### 表 2.1 各类指令的地址信息

回头看 21 页表 2.1，各类指令的地址信息。CPU 取指令代码段地址默认 `CS`，用户能指定吗？不能，`CS` 不能改；偏移由 `IP` 提供，`CS:IP` 一对。考试简答填空：8086 取指令单元地址由\_\_\_\_提供，写 `CS:IP`。

第二行堆栈操作 `PUSH`、`POP`，段地址默认 `SS`，偏移由 `SP` 提供，入栈 `SP` 减 2，出栈完增 2，堆栈必须按字操作。一般数据操作，被读写单元段地址一般默认 `DS`，还可以指定 `CS`、`ES`、`SS`，就是上节课讲的加段超越前缀改变段，没写前缀一律默认。段内偏移按寻址方式确定：`[BX]` 寄存器间接，偏移就是 `BX` 的值；`[BX]+2` 寄存器相对，加 8 位 `DISP`，偏移是 `BX` 内容加位移量之和。寻址方式不同，求偏移的方法不同。倒数第一行用 `[BP]` 做基址，段默认 `SS`，也可加前缀改，`[BP]` 偏移是 `BP` 内容，`[BP]+2` 是二者之和。

倒数第二三行字符串操作，`MOVSB`、`MOVSW`。源串默认 `DS` 段，还可加前缀改，偏移必须 `SI` 提供，`SI` 叫源变址寄存器；目的串段地址必须 `ES` 提供，目的串必须定义在 `ES` 段，不可更改，偏移必须 `DI` 提供，`DI` 目的变址寄存器。往后学指令都要守这张表的规则。

| 操作 | 段地址 | 偏移地址 |
| :--- | :--- | :--- |
| 取指令 | `CS`（不可改） | `IP` |
| 堆栈 `PUSH`/`POP` | `SS` | `SP`（入栈减 2，出栈增 2） |
| 一般数据 | 默认 `DS`，可加段前缀改 `CS`/`ES`/`SS` | 按寻址方式：`[BX]`、位移量之和等 |
| `[BP]` | 默认 `SS`，可加前缀改 | `[BP]` 内容或加位移量 |
| 串操作源 | 默认 `DS`，可加前缀改 | `SI` |
| 串操作目的 | `ES`（不可改） | `DI` |

### 理论重叠与实际不重叠

最后一句话：理论上分段时段与段互相重叠，相邻两段最大间隔 16 字节。有同学想，我编的程序有堆栈段、数据段、代码段，数据段把代码段重叠了，代码不见了？不会。实际汇编时：原程序一开始用段定义方法定义堆栈段，定义完定义数据段，程序用的数据、运行结果要写的单元都用 `DB`、`DW` 空在那，再定义代码段编程序。原程序由这么多逻辑段组成，CPU 能直接执行吗？不能，CPU 不认识 `MOV`，只认识二进制，所以执行前要汇编，汇编程序翻译成机器代码。

汇编时先找存储器自由空间，从头开始，这个单元能被 16 整除吗？不能过，能就从这开始翻译这个段，堆栈段留出来；下面翻译数据段，这个单元能被 16 整除吗？能就做数据段起始，不能一直往下找，最多找 16 次。依次类推，汇编后放存储器的机器代码段与段之间会重叠吗？不会。

还有一点：程序一初始化，`CS` 指向代码段段基址，`DS` 指向数据段，`SS` 指向堆栈段，起始地址高 16 位嘛，复杂还有 `ES`。初始化后这些段寄存器的值对应的段称为当前段，最多几个？4 个。程序运行期间可以改段寄存器值改变当前段。这一章讲完了。
