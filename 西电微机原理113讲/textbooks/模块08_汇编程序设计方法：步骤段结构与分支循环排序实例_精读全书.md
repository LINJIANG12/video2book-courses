### 1 五个步骤：考试爱考的简答题

在本节一开始，首先要掌握的是汇编语言程序设计的步骤。考试中有时会涉及简答题，例如“简述汇编语言程序设计的步骤”。答题时要完整写出以下五个步骤：

1. **第一步：分析题目**。分析问题并提出具体的算法。
2. **第二步：绘制流程图**。根据算法或编程思想画出程序流程图。画流程图时所用的图形符号必须规范。
3. **第三步：编写程序**。根据算法、编程思想以及绘制的流程图，编写具体的源程序代码。
4. **第四步：上机调试**。把编好的程序录入计算机存到磁盘上，源程序文件名必须以 `.ASM` 作扩展名，建立源文件；然后汇编，把汇编语言源程序翻译成机器语言目标文件 `.OBJ`；再链接，链接生成 `.EXE` 可执行文件；最后用 `DEBUG` 等调试工具跟踪调试。
5. **第五步：编写文档**。整理并完成程序设计相关技术文档。

> **提示**：上机调试的详细过程见教材 4.2 节，那一节主要作为课后阅读和实验课上机练习，结合具体题目实践掌握。也就是说，第四步的真功夫在实验课上，这一讲先把架子立住。

### 2 段定义伪指令：SEGMENT 与 ENDS 配对

8086 汇编语言源程序的结构特点是：不同性质的信息要定义在不同的逻辑段里。因此编完的源程序是由多个逻辑段组合成的。段定义伪指令的作用就是定义一个逻辑段，基本格式是：

```assembly
段名  SEGMENT  [定位类型] [组合类型] ['类别']
      ; 段的实体
段名  ENDS
```

`SEGMENT` 指示一个逻辑段定义的开始。汇编程序逐行翻译时，遇到 `SEGMENT` 就知道一个新的逻辑段开始了。

段名写在 `SEGMENT` 左边，和 `SEGMENT` 之间用空格分隔。段名的命名规则和标号名、变量名相同：第一个字符必须是字母；不能用 8086 指令系统的保留字和专用词，比如 `MOV`、`ADD`、`AND` 这些。规范建议是段名要见名知意，让人一看就知道这段放什么：堆栈段建议叫 `STACK`，数据段建议叫 `DATA`、`DATA1`、`DATA2`，代码段建议叫 `CODE`、`CODE1` 或者 `PROGRAM`。

段的实体写在 `SEGMENT` 和 `ENDS` 之间：数据段通常是 `DB`、`DW`、`DD` 等变量定义伪指令开辟的存储单元；代码段是完成特定功能的指令语句；堆栈段通常用 `DB` 或 `DW` 配合 `DUP(?)` 开辟一片连续空间当堆栈用。

`ENDS` 表示这个逻辑段定义结束。`ENDS` 左边同样要写段名，告诉汇编程序结束的是哪一个段。关键规则有三条：

- 第一段结束符是 `ENDS`，而且 `ENDS` 左边的段名要和 `SEGMENT` 左边的段名一致；
- 第二，在实际程序设计中 `SEGMENT` 和 `ENDS` 要配对使用，一个逻辑段从 `SEGMENT` 开始，没有配对就没有结束；
- 第三，段名一旦用 `SEGMENT` 定义，段名本身就具有段地址属性，汇编程序会给它分配一个段地址。严格地讲，段名本身也有偏移地址属性，一个段刚开始，偏移地址就是 $0$。

### 3 定位类型：缺省就是节型

下面看段定义伪指令右边给出的参数，先看第一个：定位类型。

定位类型是告诉汇编程序（比如我们用的 `MASM.EXE`）本逻辑段起始地址的要求。我们在第二章讲分段时说过，一个逻辑段的起始地址必须能被 $16$ 整除。在 8086 汇编里，定位类型共有四种，参考教材第四章 93 页表 4.1。

第一种是页型（`PAGE`）。计算机里 $1$ 页 $= 256$ 字节。如果定位类型选页型，汇编时本段起始地址必须能被 $256$ 整除。要是每个逻辑段都选页型，相邻段之间最大间隔可达 $256$ 个字节，严重浪费存储器空间，所以实际中通常不用。

第二种是节型（`PARA`）。存储单位换算一下：$1$ 字 $= 2$ 字节，$1$ 双字 $= 4$ 字节，$1$ 节 $= 16$ 字节，$1$ 页 $= 256$ 字节，$1\text{KB} = 1024$ 字节。如果定位类型选节型，本段起始地址必须能被 $16$ 整除，相邻段之间最大间隔 $16$ 个字节。编源程序时如果缺省了定位类型，汇编程序默认就是节型。节型是缺省类型，也是 8086 里最常用的定位类型，缺省不写，汇编程序自动按能被 $16$ 整除的地址安排本段起点。

另外两种是字型（`WORD`）和字节型（`BYTE`）。字节型要求起始地址能被 $1$ 整除，也就是任意物理地址都行，相邻段之间没有间隔，最省空间。但实际编程中不可取，因为我们通常要求段的起始偏移地址为 $0$，字节型保证不了这一点，所以实际没人用。字型要求起始地址能被 $2$ 整除，同样保证不了偏移地址为 $0$，也很少选。

| 定位类型 | 起始地址要求 | 相邻段最大间隔 | 实际选用 |
| :--- | :--- | :--- | :--- |
| :--- | :--- | :--- | :--- |
| `PAGE`（页） | 能被 $256$ 整除 | $256$ 字节 | 不用，太浪费 |
| `PARA`（节，缺省） | 能被 $16$ 整除 | $16$ 字节 | 最常用，缺省即此 |
| `WORD`（字） | 能被 $2$ 整除 | $2$ 字节 | 很少用 |
| `BYTE`（字节） | 能被 $1$ 整除 | $0$ | 不用，保证不了偏移地址为 $0$ |

> **结论**：最常用的定位类型是节型。用 `SEGMENT` 定义逻辑段时直接缺省定位类型参数就行，汇编程序自动按节型汇编。

### 4 组合类型：给 LINK 的多模块任务书

接下来看第二个参数：组合类型。组合类型主要用在多模块程序设计当中。

什么是多模块？比如我举个例子。我现在给某个单位开发一个程序，程序量很大、功能很强，靠你一个人，人家一个月后就要交货，你是不是编不完、调不通？那怎么办？是不是要把任务分解？把任务讲清楚、流程讲清楚，然后分解：一部分功能由 A 同志完成，一部分由 B 同志完成，剩下一部分由 C 同志完成。A、B、C 拿到任务回去编写自己的程序，每个人都要定义自己的堆栈段、自己的数据段，编写自己的程序代码。

编完各自调试自己的程序，每个人都调通以后，三个人的程序加在一起，就是最终交付的系统程序。这三个程序汇编后生成的 `.OBJ` 目标码文件，最终要通过 `LINK` 链接程序加在一起链接。`LINK` 是链接程序，能把 `.OBJ` 链接成 `.EXE` 可执行文件。在链接的时候，就要在多模块程序设计当中，通过组合类型告诉 `LINK`：好比把 `A.OBJ`、`B.OBJ`、`C.OBJ` 链接成一个系统程序时，不同模块中同段名、同组合类型的逻辑段该如何链接。组合类型就是干这件事的。

```text
A同志:  STACK段 + DATA段 + CODE段  ──汇编──▶  A.OBJ  ─┐
B同志:  STACK段 + DATA段 + CODE段  ──汇编──▶  B.OBJ  ─┼──LINK──▶ 系统.EXE
C同志:  STACK段 + DATA段 + CODE段  ──汇编──▶  C.OBJ  ─┘
                              ▲
                    组合类型告诉 LINK 同名段如何合并
```

读图说明：三个人各自的同名逻辑段能不能合并、怎么合并，全看组合类型写的是什么，这就是下一讲要展开的内容。

## 第 2 章：堆栈段定义与 SS SP 初始化：左边 STACK 与右边 STACK 不是一回事
> 对应分集：P66 | 原始标题：《堆栈段定义与 SS SP 初始化：左边 STACK 与右边 STACK 不是一回事》

上一讲我们把 A、B、C 三个同志的多模块例子摆出来了：`A.OBJ` 里面有个 `SEGMENT` 定义的堆栈段，`B` 程序和 `C` 程序里面也有各自的堆栈段。那我们链接，把三个 `.OBJ` 链接成一个可执行程序后，堆栈段应该怎么处理？是取三个程序堆栈空间的总和？还是取三个 `.OBJ` 当中谁空间最大取谁？是不是？等等有好多约定，那些约定都是用组合类型来说明的。

那么在组合类型里面，我们这门课按大纲要求，只要求学到单模块程序设计。你编的程序模块和任何模块都不发生关系，你就是你，单模块程序设计。那么在单模块程序设计当中，我要告诉大家的组合类型有两种。

### 1 STACK 型：告诉 LINK 本段就是堆栈段

一种是 `STACK` 型。`STACK` 型告诉链接程序，就告诉 `LINK`：本段为堆栈段。决定死的。比如我编一个：段名叫 `STACK`，`SEGMENT`，组合类型叫 `STACK`，下面来个 `DB 256 DUP(?)`，`STACK ENDS`。哎，我定义了一个堆栈段。

```assembly
STACK  SEGMENT  STACK
       DB  256 DUP(?)
STACK  ENDS
```

大家看，在我定义的这个堆栈段当中，`SEGMENT` 左边的 `STACK` 是段名，`SEGMENT` 右边的 `STACK` 是组合类型。左边这个段名你可以随便起，右边这个是伪指令的保留字，告诉 `LINK` 本段就是堆栈段。

那么这样做有什么好处？在 `MASM 5.0` 以上版本汇编链接时，链接程序知道了堆栈段，系统会做什么？对 `SS` 和 `SP` 初始化。你用户在代码段就不用对 `SS` 和 `SP` 初始化了。但是，如果用 `SEGMENT` 定义堆栈段时，组合类型没有用 `STACK` 说明，那么你在代码段一开始，就要把堆栈段的段地址想办法送给 `SS`，把堆栈段栈底加一的偏移地址想办法送给 `SP`，对 `SS` 和 `SP` 初始化，这要用户在代码段完成。而如果堆栈段的组合类型用 `STACK` 说明了，`SS` 和 `SP` 就不用初始化了，系统会完成的。

| 堆栈段写法 | `SS` 与 `SP` 谁来初始化 | 代码段要不要写初始化 |
| :--- | :--- | :--- |
| :--- | :--- | :--- |
| `STACK SEGMENT STACK`（`MASM 5.0+`） | 系统完成：链接程序知道这是堆栈段，自动装填 | 不用，绝对不要再写 |
| `SEGMENT` 缺省组合类型 | 系统不管，用户自己在代码段完成 | 必须写：段地址送 `SS`，栈底加一的偏移地址送 `SP` |

### 2 NONE 型：我就是我，缺省就是它

还有一个组合类型是 `NONE` 型。如果组合类型选了 `NONE`，它告诉 `LINK`：本逻辑段和任何模块中的任何逻辑段都没有关系。都没有关系，我就是我。所以这种组合类型也属于缺省型，就是说组合类型这项不写了，链接程序就默认本段是 `NONE` 型。

啊，我就讲这两个组合类型。当然组合类型里面还有 `PUBLIC` 型、`MEMORY` 型、`AT` 表达式型等等，我都不讲了。感兴趣的同学参考有关的课外书籍，课堂上不讲。这是组合类型。

再说类别。如果类别这项参数你要写，必须用单引号引起来。但类别这项参数没有任何意义。没有意义还要它干什么？只是告诉程序阅读人员本段信息的种类。比如这个段定义的是数据段，那我在类别写个单引号 `'DATA'`，告诉读程序的人，一看到类别是 `DATA`，就知道本段是数据段。理解了没有？只起这么一个作用，再没有其他意义。

### 3 标准结构：不挨个讲伪指令了，从完整结构里带出来

段定义开始伪指令 `SEGMENT` 和段定义结束伪指令 `ENDS`，这一节 4.1 里面讲到的伪指令还很多，我不要挨个去讲了。我看我的时间，我下面直接给出 8086 汇编语言源程序结构，即完整结构或者叫标准结构，我在结构中引出、带出好多伪指令。我写一个结构你们看：

```assembly
STACK  SEGMENT  STACK
       DB  256 DUP(?)
STACK  ENDS
```

显然我在定义什么段？堆栈段，组合类型就要取 `STACK`。在堆栈段里面，用 `DB` 或者 `DW` 定义一个存储空间做堆栈区。`DB 256 DUP(?)`，堆栈段我定义了 256 个字节，也就是 128 个字的大小。

那么堆栈区要多大？要根据你程序的实际需求，留出 30% 的富裕量来定义堆栈空间。我留富裕量的目的是什么？以便于程序扩充、维护，避免 `SP` 指针溢出。讲堆栈时是不是都提到过？

定义完了，我们来看，我先画一个存储器。你看，定位类型缺省就是节型，汇编程序在自由空间里找第一个能被 $16$ 整除的地址作为本段起点。256 个字节占下来，段内偏移就是 $0000\text{H} \sim 00\text{FFH}$，栈底在 $00\text{FFH}$。

```text
高地址
  ┌──────────────┐
  │  偏移 0100H   │◀── SP 初值指向这里（栈底 + 1）
  ├──────────────┤
  │  偏移 00FFH   │◀── 栈底（最后一个有效单元）
  │     ┆        │
  │  偏移 0001H   │
  ├──────────────┤
  │  偏移 0000H   │◀── 段起点（能被16整除）
  └──────────────┘
低地址      堆栈段（256 字节）
```

读图说明：8086 压栈是先减后存，`PUSH` 先 `SP \leftarrow SP - 2` 再写数据，所以 `SP` 初值必须指向栈底加一，也就是偏移 $256$（`0100H`），第一个压入的字才能完整落在 $[254, 255]$ 单元。你要是把 $255$ 当初值，栈底那个字就没地方完整放了。

> **易错点**：`STACK SEGMENT STACK` 两个 `STACK` 别混为一谈。左边是段名，你改成 `MYSTK SEGMENT STACK` 照样成立；右边是组合类型，少了它，`MASM` 再高版本也不会替你初始化 `SS:SP`。还有，已经声明了 `STACK` 类型，就不要在代码段再写一遍 `MOV SS, AX / MOV SP, 0100H`，那是冗余逻辑。

## 第 3 章：源程序标准结构：从 ASSUME 到 END 的完整走一遍
> 对应分集：P67 | 原始标题：《源程序标准结构：从 ASSUME 到 END 的完整走一遍》

呃，上一节课我们讲第四章 4.1 节汇编语言程序设计基础，从这一节里引出了汇编语言程序的标准结构。我们再复习一下，把这个完整结构从头到尾走一遍。

### 1 数据段：缺省三项，DB DW 照题目摆数据

题目功能里如果涉及到某些数据，数据要定义在数据段。段的定义都是用 `SEGMENT` 伪指令开始定义的。你看，在这个段定义的 `SEGMENT` 伪指令右边，我定位类型缺省了，组合类型也缺省了（本段和其他段都没有关系），类别也缺省了。

```assembly
DATA  SEGMENT
      VAR1  DB  10H
      VAR2  DW  ?
      X_byte  LABEL  BYTE
      X_word  DW  1234H
DATA  ENDS
```

在这个数据段里，根据题目要求用 `DB` 或者 `DW` 定义你的数据，给存储器分配，也就是变量定义。假如 `DB` 定义了个 `VAR1` 变量，这个单元放了 `10H`；假如 `DW` 定义了个 `VAR2` 变量，保留到这；又假如用 `DW` 定义了个变量名叫 `X_word` 的字变量，这个单元定义成 `1234H`。放到这，后边我们再看。数据段定义完了，`ENDS DATA`，你看我这地方空了一行，后边有用。

### 2 ASSUME：只告诉汇编程序，不初始化寄存器

现在我们定义代码段，在代码段编题目完成功能的程序。段名叫 `CODE`。在代码段一开始，要用段寻址伪指令告诉汇编程序，前面用 `SEGMENT` 定义的这些段名，具体哪个段和哪个段寄存器建立关系：

```assembly
CODE  SEGMENT
      ASSUME  CS:CODE, DS:DATA, ES:DATA, SS:STACK
```

比如 `CODE` 段和 `CS` 寄存器建立关系，`DS:DATA` 告诉汇编程序 `DS` 段是 `DATA` 段名指的段，`ES:DATA` 告诉汇编程序 `DATA` 段名指的段也是 `ES` 段，意味着下方程序使用时，数据段和附加数据段是同一个段，`SS:STACK` 建立 `SS` 和堆栈段的关系。

但这种关系只是告诉汇编程序，汇编程序在汇编时承认这种关系，可是 `DS` 寄存器的值并没有指向 `DATA` 段的段地址，也就是说 `DS` 并没有初始化。那么 `DS`、`ES`、`SS` 这几个段寄存器值的初始化，是不是靠用户在下方用 `MOV` 指令来实现？

程序开始要写一个起始地址标号，必须写。起始地址标号名是用户自己起的，我现在叫 `START`，你叫 `MAIN`，叫什么都可以。一开始要用 `MOV` 指令给 `DS`、`ES`、`SS` 初始化：

```assembly
START:  MOV  AX, DATA
        MOV  DS, AX
        MOV  ES, AX
        MOV  AX, STACK
        MOV  SS, AX
        MOV  SP, OFFSET TOP
```

`MOV AX, DATA`，段名写到这，取的是段名具有的什么属性？段地址。把段名具有的段地址给 `AX`，所以这条指令源操作数的寻址方式是立即数寻址。下面再用一条 `MOV` 把 `AX` 传送到 `DS`。`DS` 做目的时源不能为立即数，所以 `DS` 的初始化要用两条 `MOV` 指令实现。

然后 `MOV ES, AX`，对 `ES` 初始化。这个时候 `ES` 的值是不是等于 `DS` 的值？`ES` 段和 `DS` 段同时指向 `DATA` 段。

对 `SS` 初始化：`STACK` 段名具有的段地址给 `AX`，`MOV SS, AX`。还用 `MOV` 对 `SP` 初始化，`SP` 的值应该指向栈底加一单元的偏移地址，栈底加一单元的偏移地址是不是 `TOP` 变量具有的偏移地址？`MOV SP, OFFSET TOP`。对 `SP` 初始化当然还可以用 `LEA` 取有效地址指令：`LEA SP, TOP`。

> **提示**：如果在堆栈段定义时组合类型选了 `STACK`，告诉链接程序本段是堆栈段，那么可执行文件装入内存的过程中，操作系统会对 `SS` 和 `SP` 做初始化。所以实际在代码段，这三条初始化指令可以不要。当然你要放了也行。如果这三条不要了，那条 `LABEL` 定义的 `TOP` 变量是不是也可以不要了？

### 3 LABEL 在数据段：一个单元两种类型

这些初始化做完了，下面编题目要完成功能的程序区。当然如果你的程序是循环结构，循环体前面是不是还有对循环功能的初始化？总之是编程序区。

假如在这个地方我有这么一条指令：

```assembly
MOV  AL, X_word
```

`X_word` 是我们用 `DW` 定义的一个字变量，写到源操作数是直接寻址，直接找到的这个单元是个字单元，但 `AL` 是 8 位的，源和目的类型不一致。以前我们讲的时候，有时需要在一个字变量对应的单元取一个字节，或者在一个字节对应的单元取一个字，用 `PTR` 说明：改成 `BYTE PTR X_word`，把 `X_word` 字变量临时改成字节型，语法上类型一致。

但今天我要讲的是，实际应用中还有另外一种办法。看汇编后在存储器里的效果：`X_word` 字单元里放的是 `34H`、`12H`（`1234H` 按低字节在前存放）。有时我们要对这个字单元做字节处理，把它看成字节单元，假如叫它 `X_byte` 字节变量。那我在 `X_word` 这个变量前方，用 `LABEL` 伪指令定义一个 `X_byte`：

```assembly
X_byte  LABEL  BYTE
X_word  DW    1234H
```

你看用 `LABEL` 定义的 `X_byte` 是字节型的。汇编程序汇编到这一行，`X_byte` 具有了这个单元的段地址和偏移地址属性，类型是字节型，但并没有占用这个存储单元。继续往下汇编到 `X_word`，字变量对应的偏移地址是不是还是这个单元？理解了没有？

所以这样定义以后，下方代码段实际程序设计中，对该单元做字处理用 `X_word`，做字节处理用 `X_byte`，效果和用 `PTR` 说明是一样的。我讲这段的目的，就是讲出 `LABEL` 伪指令在数据段的应用。按字节处理的话，这地方直接写 `X_byte`，类型一致，和刚才的效果一样。

### 4 程序结束：INT 21H 的 4CH 号功能

题目功能实现了，程序就要结束，写出结束语句：

```assembly
MOV  AH, 4CH
INT  21H
```

`INT 21H` 是软件中断指令，后边 `21H` 是中断类型号。`CPU` 执行 `INT 21H`，就是调用 `DOS` 操作系统里面的子程序。`DOS` 把完成每个功能的程序片段都设计成子程序形式，允许用户用 `INT 21H` 调用。调用 `DOS` 当中哪个功能对应的子程序，就要把功能号送给 `AH`，有 `00` 号、`01` 号、`02` 号，我现在是 `4CH` 号。调用 `DOS 4CH` 号功能，完成的是结束用户程序，让指针返回到 `DOS` 操作系统去。`CPU` 执行用户程序是从 `DOS` 操作系统 `CS:IP` 转过来的，用户程序执行完了，`CS:IP` 要返回到 `DOS` 去，靠的就是 `DOS 4CH` 号功能调用。

代码段整个编完了，写 `ENDS`，左边写段名 `CODE`。如果你编的程序在一个代码段，整个程序就编完了。如果你有些功能在另外一个代码段，好比起个 `CODE2` 段，`CODE2 SEGMENT` 又开始了，那么在下方必须用 `ASSUME` 说明 `CS:CODE2`，说此时的 `CS` 段是 `CODE2` 段。`CPU` 要执行到 `CODE2` 段来，按前面讲的远程转移，`JMP FAR PTR` 接个标号就转过来了。

假如就一个代码段，程序编完了，写总汇编结束伪指令 `END`，`END` 右边给出启动地址表达式。启动地址叫 `START`，就写 `END START`；叫 `MAIN`，就写 `END MAIN`。这样做了以后，源程序汇编链接后的 `.EXE` 要执行，`DOS` 装入程序从磁盘找到 `.EXE` 向内存装入的过程中，会把 `END` 后边起始地址表达式 `START` 具有的段地址属性给 `CS`，`START` 具有的偏移地址给 `IP`，程序一装到内存，`CS:IP` 是不是指向了程序的手地（首地址）？从这取指令执行。

## 第 4 章：分支程序设计：先产生条件，再测试条件
> 对应分集：P68 | 原始标题：《分支程序设计：先产生条件，再测试条件》

今天我们利用一节课看第四章汇编语言程序设计。这一章里面，我们看 4.3 节：分支程序设计技术。

### 1 单分支与多分支：结构先认清

在分支程序设计当中，大家要掌握分支程序的结构，主要有单分支结构和多分支结构。

不管哪一种结构，分支程序设计的要点是通过分析题目，抓住分支（一般是条件分支）的条件，即通过判断什么条件来实现分支。这个条件在测试之前，首先要产生条件。

产生条件一般都是用运算指令来产生的，通过某种运算形成标志位：最常用的比较运算指令是 `CMP`，最常用的逻辑运算指令是 `TEST`。当然，有时如果目的操作数被破坏也无所谓，还可以用 `SUB`、`AND`、`ADD` 等指令，都可以通过这类运算产生条件。

产生条件对应的就是 `PSW` 当中 6 个状态标志位。除掉 `AF` 以外，剩余 5 个都是条件之一：`ZF`（零标志）、`SF`（符号标志）、`PF`（奇偶标志）、`OF`（溢出标志）、`CF`（进位标志）。根据具体题目分析，确定用这 5 个条件中的哪一个。

条件产生之后，要去测试条件，也就是判断条件是否成立。测试条件通常用条件转移指令完成：测 `ZF` 有 `JZ`、`JNZ`，测 `SF` 有 `JS`、`JNS`，等等。通过测试，条件成立做一件事，条件不成立转去做另一件事。这就是标准的条件二分支程序，也就是单分支结构。

多分支呢？条件产生之后，有多个条件依次判断：测试条件一成立吗？成立就做第一件事去了；不成立就测条件二；条件二成立就做第二件事；不成立就测条件三……所有分支处理完，汇合做统一的退出处理。

```text
        ┌─产生条件（CMP / TEST / SUB…）─┐
        ▼                                │
   测试条件一成立？                       │
    ┌YES┴NO┐                             │
 做事一    ▼                             │
      测试条件二成立？                    │
       ┌YES┴NO┐                          │
    做事二    ▼                          │
         测试条件三…                      │
              │                          │
              ▼                          ▼
           统一出口 ◀────────────────────┘
```

读图说明：多分支就是一连串“测试—分流”，每条路最后都回到统一出口。

就像我们上机的例 4.39 题：测试按键是否为“1”键？如果是，小写字母变大写；若不是“1”，测试是否为“2”键？如果是，在输入的字符里找出 `ASCII` 码值最大的字符；若不是“2”，继续测试是否为“3”键……这就是典型的多分支。当时针对这种结构，结合例 4.39 的要求，我们引出了利用跳转表实现多分支程序设计的方法。显而易见，在那种情况下用跳转表实现多分支，程序执行效率比较高。

### 2 转移范围：条件转移只有 -128 到 +127

在分支程序设计中要注意：第一个是结构，第二个是转移范围，一定要注意，说的是条件转移范围。对于无条件转移，可以跳到代码段任何地方，甚至段间跳转；对于条件转移，以当前 `IP` 为基准，逆向最多转 $-128$ 个字节，正向最多转 $+127$ 个字节。如果条件转移超出这个范围，想办法用无条件转移指令去搭桥。

第三个要注意的是上机调试：程序上机调试时，必须保证每个分支结果的正确性。你单步调试，一步一步走下来，条件满足（YES），顺利执行完得到了正确结果，你说程序调完了？没有。你必须回去重新跑，跑到条件产生处，上次条件满足，这次让条件不满足，顺着另一条路线走下来，看结果对不对。必须保证每一条分支都被调试覆盖到，每个分支结果都正确，分支程序的调试才算完。

> **结论**：分支程序设计的要点就三条。第一，通过分析题目正确选择分支条件（是 `ZF` 还是 `SF` 等等），条件抓准了，条件转移指令就定了。第二，编写时保证每个分支正确。第三，调试时逐条分支去调试。

### 3 例 4.7 开题：两个递增数组合并成一个

下面看教材例 4.7。题目要求：在 `DATA1` 和 `DATA2` 缓冲区存放两组递增有序的 8 位二进制无符号数，其中前两个字节保存数组长度。编程把它们合并成一个数组，合并后依然递增排列。新数组首地址变量名叫 `DATA`，`DATA` 的前两个字节保存新数组长度。

分析一下：`DATA1` 数组前两个字节放元素个数，元素都是 8 位无符号数。按书上假定，`DATA1` 数据占 10 个字节，前两个字节保存长度，后面 10 个字节数据递增排列；`DATA2` 首地址变量名 `DATA2`，元素字节型，书上假定元素个数 13 个（十六进制 `000DH`），13 个字节连续存放，同样递增排好。

现在要合并成新数组 `DATA`：前两个字节存新数组长度，新数组元素个数显然是两数组之和：

$$10 + 13 = 23 \quad (\text{即 } 0017\text{H})$$

后面存合并后的无符号 8 位数，同样递增。

实现这个算法需要三个指针，三个数组各一个：目标数组 `DATA` 用 `DI`，源数组 `DATA2` 用 `BX`，源数组 `DATA1` 用 `SI`。寻址与段寄存器的对应关系是：`SI` 间接寻址默认段在 `DS`（`DS:SI`），`BX` 间接寻址默认也在 `DS`（`DS:BX`），`DI` 是串操作目的指针，默认段强制在 `ES`（`ES:DI`）。

这样设指针的好处是能配串操作指令：把 `DATA2` 当前元素读到 `AL`，执行 `CMP AL, [SI]`，把 `AL` 和 `DATA1` 中 `SI` 指的当前元素比较。如果 `AL` 小，把 `AL` 写入合并数组，直接用串存储指令 `STOSB`（默认存入 `ES:DI`，`DI` 自动加 1）；如果 `AL` 大，说明 `[SI]` 更小，优先传 `DATA1` 的数据，直接用串传送指令 `MOVSB`（`DS:SI` 传到 `ES:DI`）。这就是解题的核心思路，具体归并流程我们下一讲把 `L1` 到 `L5` 完整走一遍。

## 第 5 章：归并尾部搬运与循环开篇：REP MOVSB 收尾，LOOP 登场
> 对应分集：P69 | 原始标题：《归并尾部搬运与循环开篇：REP MOVSB 收尾，LOOP 登场》

上节课我们把双数组归并的主循环讲完了：`L1` 取数，`L2` 比较，`AL` 大走 `MOVSB`，`AL` 小走 `L3` 的 `STOSB`。今天先把尾部收完，再开新的一节：4.4 循环程序设计。

### 1 L4 与 L5：有一个数组先空了怎么办

归并的过程中，总有一个数组先被搬空。`CX` 是 `DATA1` 的计数器，`DX` 是 `DATA2` 的计数器。`DEC CX` 之后 `JZ L4`，说明 `DATA1` 搬完了，跳 `L4` 去搬 `DATA2` 剩下的；`DEC DX` 之后 `JZ L5`，说明 `DATA2` 搬完了，跳 `L5` 去搬 `DATA1` 剩下的。

`L5` 好办：`DATA2` 全写完了，`DATA1` 还剩 `CX` 个，`SI` 正指着 `DATA1` 没搬的最小元素，`DI` 正指着目标数组末尾，直接一条 `REP MOVSB`，把 `DS:[SI]` 剩下 `CX` 个字节呼呼全搬到 `ES:[DI]` 去，然后 `MOV AH, 4CH / INT 21H` 退出。

`L4` 就要动脑子了，这是黑板上着重推导的地方。进 `L2` 比对时，`AL` 暂存了 `[BX]` 的值；经过若干次 `MOVSB`，`DATA1` 耗尽，`CX` 减到 0，触发 `JZ L4`。这时致命的边界条件是：`AL` 里那个 `DATA2` 元素还没写入目标数组（当时它比 `[SI]` 大），而指针 `BX` 已经递增，指向了 `AL` 之后的一个单元。换句话说，`DATA2` 没搬的数据起点正好落在 `BX - 1` 处。

```assembly
L4:   MOV  SI, BX      ; 把 DATA2 跟踪指针交给串操作源指针
      DEC  SI          ; 核心修正：指针超前了，必须减 1 回退
      MOV  CX, DX      ; DATA2 剩余个数交给串计数器
      REP  MOVSB       ; 批量倾倒到 ES:[DI]
```

> **易错点**：`MOV SI, BX` 后面这条 `DEC SI` 绝对不能漏。漏了，合并数据就丢一个数，尾部还越界读进一个脏字节。记住这个代数关系：$SI = BX - 1$。

```text
L4 现场（DATA1 先空）
  AL  : [ 滞留元素 ]   ← 取出来了，还没存进去
  BX ──▶ 下一个单元    ← 指针已超前
  真正起点 = BX - 1    ← DEC SI 回到这里
  CX = DX              ← 剩余个数（含 AL 里那个）
  REP MOVSB 一次搬完
```

读图说明：`AL` 里滞留一个数，`BX` 超前一位，所以源指针要先接 `BX` 再减 1，个数直接拿 `DX` 来。

### 2 循环控制四指令：LOOP 家族与 JCXZ

那么在第三章讲指令时，循环控制指令我们讲过。8086 里循环控制指令一共四条：`LOOP`（计数循环）、`LOOPZ / LOOPE`（相等、结果为零时循环）、`LOOPNZ / LOOPNE`（不相等、结果不为零时循环）、`JCXZ`（`CX` 为 0 则转移）。这四条都靠判定计数器 `CX` 并自动递减来控制循环。

循环程序通常有两种基本结构。一种是先循环工作、后循环判定：先干一次活再判定，适用于循环次数预先已知的场合，直接 `CX` 减 1 控制。另一种是先循环判定、后循环工作：进循环先检查条件，满足才干活，适用于一开始就可能零次循环、或者中途可能提前退出的场合。为了提高执行效率，可能不循环或需提前结束的场景，优先设计成先判定后工作的结构。

之前举过一个例子：测试 `BX` 寄存器里有几个二进制位是 $1$。思路是移位把 `BX` 往右（或往左）移，每次移出的一位进 `CF`，$CF = 1$ 计数器加 1，$CF = 0$ 不统计。如果用先工作后判定，必须固定循环 16 次；但 `BX` 一开始就等于 0，根本不用循环。所以用先判定结构：一开始 `CMP BX, 0 / JZ EXIT`，为 0 直接退出；不为 0 才移位测 `CF`，统计完 `LOOP` 回去，回去再 `CMP BX, 0`，剩下的位全是 0 就提前退出，不空转。

> **结论**：无论哪种结构，一个完整循环程序一般有五部分：初始化（计数器、指针、工作单元清零）、循环工作体、参数调整（`INC SI`、`INC DI` 改偏移）、出口判定（`LOOP` 减 `CX` 或条件转移）、结果处理（退出后输出，可省）。

### 3 起泡排序引入：五个同学的成绩怎么沉底

前面讲的都是单重循环，4.4 重点是多重循环，以起泡排序法为例。

题目要求：对 8 个学生某门课的成绩排序，由高到低降序。成绩都是无符号数，只比绝对大小。基本思路就是相邻两项两两比较与交换。

为了讲清楚，我不可能把我们班 60 个同学排出来，黑板不够长。我举五个同学，这个班只有五个同学，考完微机课成绩是：70 分、54 分、90 分、67 分、80 分。假设这是存储器，里面放的是分数对应的二进制数，我们按十进制说。

排序由高到低，相邻单元比较：如果上面单元的数相对下面高于或等于，两单元不交换；如果上面低于下面，两单元交换，相当于大泡泡顶上去、小泡泡沉下来。

比如 70 和 54 比，不交换；54 和 90 比，上面低，两单元 `XCHG` 交换。但两内存单元不能直接操作，中间要通过通用寄存器过渡，所以两单元交换需要两条指令完成。一交换，大泡泡顶上去，54 跑下来；54 再和 67 比，67 高，交换；54 再和 80 比，还低，再交换。这一轮循环下来，最后是不是在这一列数里找到最小的数，沉到存储器最末端？小泡泡沉到杯底，大泡泡顶上去。

你看，参加比较的数有 5 个，比较了几遍找到最小数？4 遍。也就是说第一次循环中，$n$ 个数要经过多少次比较把最小的沉到底？

$$n - 1 \text{ 次}$$

> **提示**：条件转移指令的选择，无符号数排序用 `JA` 一类；如果是带符号数排序呢？条件转移该写 `JG` 或者 `JGE`。这个条件要抓住。下一讲我们把起泡排序的完整程序，包括内外循环和退出条件，一次写到位。

## 第 6 章：起泡排序完整程序：CH 管趟数，CL 管次数，BL 管提前退出
> 对应分集：P70 | 原始标题：《起泡排序完整程序：CH 管趟数，CL 管次数，BL 管提前退出》

上节课我们把起泡排序的思路讲完了：相邻两两比较，大泡泡顶上去，小泡泡沉下来，$n$ 个数第一趟比较 $n-1$ 次。今天把完整程序写出来，再讲一个工程优化和考试怎么考。

### 1 题目与寄存器分工：CH、CL、SI 各管一摊

题目要求：对 8 个学生某门课的成绩排序，由高到低降序。成绩都是无符号数，只比绝对大小。数据连续存在缓冲区 `BUFFER1` 开始的单元里。

寄存器分工一开始就定死：外层循环计数器用 `CH`，赋初值 $n-1$；内层循环计数器用 `CL`，每趟开始从 `CH` 动态装载；数据指针用 `SI`，装缓冲区首地址偏移。开始框是什么框？椭圆框！画流程图这细节要注意，起始框必须用椭圆框，不能随手画个矩形。

```assembly
      MOV  CH, N-1         ; 外循环：共 n-1 趟
D:    MOV  CL, CH          ; 内循环次数 = CH（动态缩减）
      MOV  SI, OFFSET BUFFER1
      MOV  BL, 0           ; 交换标志清零，默认本趟有序
C:    MOV  AL, [SI]
      CMP  AL, [SI+1]
      JAE  NOCHANGE        ; 前驱高于等于后继，不交换
      XCHG AL, [SI+1]
      MOV  [SI], AL
      MOV  BL, -1          ; 发生交换，置脏标记 0FFH
NOCHANGE:
      INC  SI
      DEC  CL
      JNZ  C
      CMP  BL, 0
      JE   EXIT            ; 整趟无交换，提前退出
      DEC  CH
      JNZ  D
EXIT: ...
```

为什么外循环是 $n-1$ 趟？每趟内循环必然固化一个极值到最终位置，$n-1$ 趟固化 $n-1$ 个，剩下最后一个自然就在位了，不用再比。第 $k$ 趟剩余 $n-k+1$ 个数，比较 $n-k$ 次，所以内循环次数每趟减 1，用 `CL ← CH` 联动：`CH` 每趟减 1，`CL` 跟着缩。

### 2 交换为什么两条指令：XCHG 配 MOV

`CMP AL, [SI+1]` 之后，降序规则是：`AL` 存放前驱单元内容，前驱高于等于后继不交换，用 `JAE NOCHANGE` 跳过去；前驱低于后继才交换。

> **易错点**：本算法目标是由高到低降序。如果在 `CMP AL, [SI+1]` 后误用 `JBE`，最终排出来就是由低到高升序，方向整个反了。无符号数降序用 `JAE`，带符号数才用 `JG / JGE` 一类，这个条件要抓住。

两个内存单元不能直接对换，中间要过通用寄存器，所以交换是两条指令：`XCHG AL, [SI+1]` 把下个单元换进 `AL`，`MOV [SI], AL` 把原 `AL` 写回当前单元。挖空题最爱在这挖：`XCHG` 后面那条 `MOV [SI], AL` 给你空着。

### 3 BL 交换标志：如果这趟没换过，后面全是白做

固定跑满 $n-1$ 趟有个毛病：如果序列提前有序了，后面几趟是不是白做了？效率就低了。所以引入交换标志 `BL`：每趟内循环开始前 `BL ← 0`；一旦发生交换，`BL ← -1`（机器码 `0FFH`）；一趟结束 `CMP BL, 0`，如果等于 0，说明整趟没换过一个数，全序已成，直接 `JE EXIT` 跳出，不用等 `CH` 减完。

```text
外循环 D (CH = n-1 → 1)
  ├─ 三重重置：CL ← CH；SI ← OFFSET BUFFER1；BL ← 0
  ├─ 内循环 C (CL 次)：取数 → 比较 → 换/不换 → INC SI
  ├─ CMP BL, 0 → =0？提前 EXIT（本趟零交换＝已有序）
  └─ 否则 DEC CH，CH≠0 回 D
```

读图说明：三重重置是每趟的入口动作，缺一个就错：`CL` 不重置次数乱了，`SI` 不重置指针飞了，`BL` 不清零提前退出判据就脏了。

> **结论**：朴素版跑满 $\frac{n(n-1)}{2}$ 次比较；加 `BL` 之后最好情况第一趟 $n-1$ 次比较就退出。寄存器分配也记死：`CH` 管趟数，`CL` 管次数，`SI` 管指针，`BL` 管标志。

### 4 考试怎么考：读程序与挖空

讲师明确说了两种考法。题型 A 是读程序分析功能：卷子上给一整段排序代码，不写注释，让你判定排序算法（认出是起泡排序）、排列方向（由高到低还是由低到高，看比较后的跳转）、参与排序的数据个数（看 `MOV CH, N-1` 处的常数或符号常量）。题型 B 是关键指令横线挖空：交换处的寄存器匹配（`XCHG AL, [SI+1]` 配 `MOV [SI], AL`）、内外循环步进跳转（`DEC CL` 配 `JNZ NEXT1`，`DEC CH` 配 `JNZ NEXT2`）、交换标志检测（`CMP BL, 0` 配 `JE EXIT`）。

另外多说一句，咱们学校研究生入学考试初试复试科目这些年改过几轮，在电路、信号与系统、微机原理与接口技术、模电数电之间变过。但不管怎么变，起泡排序这种双重循环基本功，考法万变不离其宗。
