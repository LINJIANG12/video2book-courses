### [00:10] 一、8255 片选译码电路中的控制信号设计

在 8255 与系统总线接口时，不要忘记在片选译码电路设计中，高位不变地址要参加译码。如果高位不变的地址线全部参加译码，采用的译码方法就是全地址译码；当然也可以采用部分地址译码。到底采用全地址译码还是部分地址译码，要看题目的具体叙述要求。

这里主要要解释的是：在片选译码设计中，控制信号与出来要等于 $0$ 去参加译码。

当该控制信号等于 $0$ 时，表明 CPU 正在对 I/O 端口执行读或写操作。此时只要地址吻合，必然产生有效的片选信号。

如果在 I/O 地址译码设计当中控制信号没有参加译码，会出现什么问题？

举一个例子：假如 CPU 正在对存储器执行读写操作，且读写操作的那组存储器单元的低 16 位地址刚好和我们设计的 I/O 端口地址一致。那么在 CPU 对存储器进行读写操作时，由于地址匹配，I/O 译码器输出也会有效；译码器一有效，8255 的片选端就有效；片选一有效，8255 的 $D_0 \sim D_7$ 数据线就会经过驱动器与系统总线接通。与此同时，系统总线上也连接着正在进行读写操作的存储器芯片的数据线。这样就会造成在 $D_0 \sim D_7$ 数据线上，每根线上同一时刻存在两个驱动源在竞争总线状态。

所以在 I/O 地址译码设计当中，除了地址线要参加译码以外，控制信号也必须参加译码。工程设计中这一点是一定要注意的。

不同系统总线下的控制信号接入规则：
- 如果是 **PC 总线**，需要将 $\text{AEN} = 0$（允许 CPU 访问 I/O，非 DMA 周期）引入参加译码。
- 如果是 **8086 最小方式**，由于 $M/\overline{\text{IO}} = 0$ 代表 I/O 操作，可以直接将 $M/\overline{\text{IO}} = 0$ 作为使能条件参加译码。
- 如果是在 **8088 系统**当中，则是其对应的 $\text{IO}/\overline{\text{M}} = 1$ 信号参加译码。

把这些概念融合起来，就能掌握 8255A 芯片与各种系统总线相连接时的设计要点。

### [04:13] 二、8255A 的逻辑功能等效与应用

本章要掌握的知识点六，也是最后一个知识点，是 **8255A 的应用**。

首先从逻辑本质上理解 8255：
一片 8255 具有三个 8 位数据 I/O 端口：PA 口、PB 口与 PC 口。
- 如果 A、B、C 三个端口都工作在**方式 0 输出**时，其功能就等效于第七章所讲的三片 74LS374 输出锁存器。
- 如果 A、B、C 三个端口都工作在**方式 0 输入**时，其功能就等效于第七章所讲的三片 74LS245 或 74LS244 输入缓冲器。

所以在实际的工程设计当中，8255A 器件的应用十分广泛。

当然，在现代电子技术中，无论是分立的 374、245，还是 8255，都可以直接用 FPGA 进行设计替换。只要掌握了底层硬件的工作原理，就可以使用硬件描述语言在 FPGA 中实现。但要使用 FPGA 设计功能电路，首先必须对原始芯片的功能和工作原理有清晰透彻的理解。

### [00:00] 8255A 端口地址译码与基地址分析

$A_5$ 到 $A_3$（即 $A_5, A_4, A_3$）均为 0。然后 $A_9, A_7$ 经过反相输出，反相输入为 0 时输出得 1，因此对应的地址线上 $A_9 = 1, A_7 = 1$。

$A_2$ 接 8255 的 $A_1$ 引脚，$A_1$ 接到了 $A_0$ 引脚上。这些地址线参加译码来选中基地址。那么对应的端口地址是多少？

高位地址是 $028\text{H}$。接 $A_0 = 1$，$\overline{\text{BHE}} = 0$（说明接在 8086 系统总线的高 8 位数据线上，分配的是奇地址）。

后两位由 $A_2, A_1$ 确定：
- $00$：PA 端口地址；
- $01$：PB 端口地址；
- $10$：PC 端口地址；
- $11$：方式控制寄存器端口地址。

对应的端口地址分别为：
- $0281\text{H}$：PA 端口；
- $0283\text{H}$：PB 端口；
- $0285\text{H}$：PC 端口；
- $0287\text{H}$：方式控制寄存器端口。

显然，$0287\text{H}$ 是 8255 的方式控制寄存器端口地址，$0281\text{H}$ 为 PA 口端口地址，$0283\text{H}$ 为 PB 口端口地址，$0285\text{H}$ 为 PC 口端口地址。地址就分析出来了。

### [01:56] 译码电路与系统总线连接问题剖析

这个译码电路可以看出一点毛病。题目说明是 8086 最小方式。在最小方式下，$M/\overline{\text{IO}} = 0$ 时才能参加译码。这样才能保证片选信号有效时，CPU 正在执行 `IN` 或 `OUT` 操作。当对这四个端口中的任意一个端口执行 `IN`/`OUT` 指令时，片选都有效。

数据总线连接方面，因为分配的是奇地址，所以 8255 的 $D_7 \sim D_0$ 接到了 CPU 的 $D_{15} \sim D_8$（高 8 位数据线）。

题目第 (1) 问要求：设计系统总线与 8255 的连接图。其他连接比较简单，但是在连接图中，8255 与系统总线连接少连了一个 $\text{RESET}$ 复位引脚。假定系统总线提供了上电复位信号，必须把它连接过来，至少应该这样做。如果没有接 $\text{RESET}$，8255 就不会正常工作。8255 只有在上电复位以后，才能进行内部初始化并开始工作。

### [03:50] 开关量读取与 LED 输出控制逻辑

题目接着要求：从一个端口读 8 位开关量，开关量非 0 即 1，外部设备接的就是 8 个开关；然后将读出的开关量从另一个端口输出，用 LED 灯进行指示。

对应逻辑为：读入的是 1，对应的指示灯亮；读入的是 0，对应的指示灯灭。

根据题目设计：
- 输入端口选用 PA 口，接开关量，PA 口应初始化工作在**方式 0 的输入方式**；
- 输出端口选用 PB 口，接 LED 指示灯，PB 口应工作在**方式 0 的输出方式**。

---

### [05:35] 8255A 方式控制字与程序设计

有了这个思路，程序设计非常直接。首先设置工作方式控制字：
- 标志位（最高位 $D_7$）$= 1$；
- A 组方式 0，$D_6 D_5 = 00$；PA 口输入，$D_4 = 1$；
- PC 口高 4 位未用，设为 0（$D_3 = 0$）；
- B 组方式 0，$D_2 = 0$；PB 口输出，$D_1 = 0$；
- PC 口低 4 位未用，设为 0（$D_0 = 0$）；
- 组合得到方式控制字为 $90\text{H}$。

初始化及读入代码如下：

```assembly
; 初始化 8255A
MOV DX, 0287H    ; 指向方式控制寄存器端口
MOV AL, 90H      ; 方式控制字：PA输入，PB输出（方式0）
OUT DX, AL       ; 写入控制字

; 读 PA 口开关量
MOV DX, 0281H    ; 指向 PA 端口
IN  AL, DX       ; 将 PA 口 8 位开关量读入 AL
```

此时 8255 的 PA 口工作在方式 0 输入，PB 口工作在方式 0 输出，工作方式设置完成，并将 PA 口数据读取到了寄存器 `AL` 中。

### [07:15] 输出电路驱动匹配（硬件反相 vs 软件求反）

在书上的电路原理中，PB 口连接的发光二极管阳极接到了 $V_{\text{CC}}$ 电源端。在这种接法下，引脚输出低电平（0）时 LED 导通点亮，输出高电平（1）时 LED 熄灭。

而题目要求输入 1 时灯亮，输入 0 时灯灭。针对这种逻辑相反的情况，有两种解决方案：

#### 方案一：软件取反（书本实现方式）
在数据输出前通过指令执行逻辑求反：

```assembly
NOT AL           ; 将读入的开关量数据求反
MOV DX, 0283H    ; 指向 PB 端口（注：原口述提及0285H实为口误，PB口对应地址为0283H）
OUT DX, AL       ; 输出到 PB 口驱动 LED
```

#### 方案二：硬件加反相器
在 PB 口与发光二极管之间接入硬件反相器。如果硬件加了反相器，软件中的 `NOT AL` 指令就可以省去。

**方案对比：**
- **成本与效率**：加硬件反相器增加了物料成本；不加反相器改用 `NOT` 指令，会占用 CPU 执行时间。
- **驱动与隔离**：增加反相器不仅解决了逻辑反相，还具有驱动放大与电气隔离的作用。

### [08:53] 连续监控与人机交互设计

如果要实现实时监控，使开关量的变动能持续反映到 LED 灯上，程序末尾需要加入无条件跳转循环（`JMP`）结构重新读取并输出。

但是在实际工程应用中，如果仅仅使用简单的无条件死循环，系统将陷入无响应状态（俗称“死机”），CPU 只能在该循环中空转。因此实际工程中必须加入**人机干预程序**（如检测键盘按键中断或轮询退出键），当用户按下特定按键后，程序能够安全退出并返回操作系统。
