### 3.4 数据传送类指令

今天我们课堂时间就过渡到 3.4 节——数据传送类指令。

这一类的指令有哪些？把书翻到 38 页。38 页有一个大括号给我们总结了一下，一共给了七种，这一类有七种指令：
1. 第一种是 `MOV`，这种我们学得差不多了；
2. 第二种是 `LEA`；
3. 第三种是 `LDS`、`LES`，这都是助记符，是取地址指针指令；
4. 第四种是标志传送指令，像 `LAHF`；
5. 第五种是数据交换指令，`XCHG`；
6. 第六种是字节转换指令，`XLAT`；
7. 最后一种是堆栈操作指令，像 `PUSH`、`POP`。有些我们接触了，有些还没接触。

---

[01:23]

我们分类来说。首先，在学这一类指令之前，我们看：

除 `SAHF`（即标志传送指令），除 `SAHF` 还有一个 `POPF`——我在讲控制标志 TF 时应用过 `PUSHF`、`POPF`，把标志寄存器 16 位压栈、出栈——除这两条指令外，剩余的所有传送类指令，CPU 执行后对六个状态标志（状态标志有几个？有六个）均**无影响**。

要抓住“无影响”。也就是说，CPU 执行这类指令只是做了数据传送，并没有做运算，所以执行后不影响状态标志，但这两条指令除外。一开始把这点抓住。

第二点要抓住的是：所有传送类指令在书写时要遵循的语法格式、语法规则，要遵循我们讲关于数据寻址方式时总结的六点。那六点还记得吗？

1. 立即数只能做源操作数；
2. 类型要一致；
3. 类型要明确；
4. 当 DS、ES、SS 这三个段寄存器做目的时，源操作数不能为立即数；
5. CS、IP 不能做目的；
6. 两存储器单元之间不能直接操作。

通过在习题 3.3 里面给大家又说了一个：在指令语句中也不允许两个变量参加运算。这些语法规则在学指令时都要遵循。

#### 一、通用数据传送指令

这类指令的格式是：
```assembly
MOV DST, SRC
```
它完成的功能是把源操作数指明的内容，以某种寻址方式指明的内容，传送到底（目的地址）去。

所谓通用，指的是只要程序设计肯定要用到，这是通用。那么这一类指令怎么用？谁和谁之间怎么传送数据？我们讲关于数据寻址方式时，例子已经很多了，所以第一种就讲完了。

#### 二、取有效地址指令

把书翻到第 41 页，数据传送指令的第二条：取有效地址指令。

* **助记符**：`LEA`
* **指令格式**：
```assembly
LEA reg16, mem
```
这地方要给一个 16 位的寄存器，逗号，后面是五种存储器寻址方式的某一种指明的一个存储器单元（如直接寻址或者寄存器间接寻址等等指明的一个存储器单元）。

这里有五种存储器寻址方式之一指明的一个存储器单元。而 16 位寄存器，用哪一个 16 位寄存器语法都是对的。但是，取的是这个单元的有效地址，即偏移地址（$EA$ 是有效地址）。既然取的是有效地址，并且取出来是要用，那最好把地址取到 `BX`、`BP`、`SI` 或者 `DI` 之一中。

当然取到 `AX`、`CX` 也没错，但是 `AX`、`CX` 不能间接寻址，不能相对寻址。取来地址肯定是要用的，做寄存器间址、寄存器相对、基址变址、或者基址变址且相对寻址都要用。所以目的操作数的 16 位寄存器最好选这四个之一。

这是这条指令的格式。

---

[08:24]

我们看个例子。

比如说，这是一个存储器单元，假如说这是个字节单元，这个字节单元变量名好比说叫 `DATA1`。

我要获取 `DATA1` 单元的偏移地址，前面我们用过：
```assembly
MOV BX, OFFSET DATA1
```
`BX` 的内容就指向了 `DATA1` 单元的偏移地址。

今天学了 `LEA` 指令以后，可以写成：
```assembly
LEA BX, DATA1
```
你看，`LEA` 这条指令是不是把 `DATA1` 变量指的单元的有效地址送给 `BX`？这两条指令完成的功能是完全一样的。

在 `LEA` 这条指令的源操作数部分，采用的是直接寻址，直接寻址找到一个单元，把这个单元的有效地址给 `BX`，并不是把这个单元的内容送过去。

### 8086 汇编语言：标志传送、数据交换与字节转换指令

---

#### [00:00] 标志寄存器传送指令：LAHF 与 SAHF

标志寄存器传送指令一共有两条。

第一条是 **`LAHF`**（Load AH from Flags）。  
这条指令非常简单，其完成的功能是：把标志寄存器 $\text{FLAGS}$（即程序状态字寄存器 $\text{PSW}$）的内容读出来，传送给寄存器 $\text{AH}$。

因为 $\text{AH}$ 是 8 位的，而 $\text{FLAGS}$ 是 16 位的，所以该指令的具体功能是：**将标志寄存器的低 8 位内容读出并送入 $\text{AH}$**。

```assembly
LAHF    ; AH ← FLAGS[7:0]
```

---

#### [00:44] SAHF 指令及对标志位的影响

反过来，还有一条标志传送指令是 **`SAHF`**（Store AH into Flags）。  
`SAHF` 完成的功能是：以 $\text{AH}$ 作为源操作数，传送的目的地是 $\text{FLAGS}$。也就是**将 $\text{AH}$ 的 8 位数据写入到 $\text{FLAGS}$ 的低 8 位**。

```assembly
SAHF    ; FLAGS[7:0] ← AH
```

需要注意的是，这条指令执行后会直接影响标志位。虽然它属于数据传送类指令，但指令执行后改变了标志寄存器的内容，所以之前讲“数据传送指令不影响标志位”时，要除它之外。

---

#### [01:25] 陷阱标志（TF）修改的深入探讨

前面我们讲过，在 8086 指令系统中，没有专门使陷阱标志 $\text{TF}$ 清零或置 1 的指令。当时提到，$\text{TF}$ 的置 1 或清零是采用堆栈操作（如 `PUSHF` 和 `POPF`）来改变的。

那么，能否用 `SAHF` 指令来修改 $\text{TF}$ 呢？  
答案是**不行**。因为 `SAHF` 只能写入 $\text{FLAGS}$ 的低 8 位（即第 $0 \sim 7$ 位），而 $\text{TF}$ 在 $\text{PSW}$ 标志寄存器中处于第 8 位（属于高 8 位）。`SAHF` 写不到高 8 位，所以要想对 $\text{TF}$ 进行置 1 或清零，只能采用堆栈操作的方法。

---

#### [02:26] 数据交换指令：XCHG

数据传送指令的第五类是**数据交换指令**，其助记符是 **`XCHG`**（Exchange）。

##### 1. 指令格式
`XCHG` 为双操作数指令，书写格式如下：
```assembly
XCHG 目的操作数, 源操作数
```

##### 2. 语法限制规则
在应用 `XCHG` 指令时，除了要遵循通用的 6 点语法规则外，还增加了两条特殊限制：
1. **目的操作数和源操作数均不能为立即数**（立即数无法作为被写入的对象，无法进行互换）。
2. **所有段寄存器（CS、DS、SS、ES）均不能参加交换**。

##### 3. 指令功能
将源操作数与目的操作数的内容进行相互交换。

---

#### [04:15] XCHG 指令示例分析

* **寄存器与寄存器交换（16 位）**：
  ```assembly
  XCHG AX, BX
  ```
  该指令语法正确。执行后：$AX \leftarrow (BX)$，$BX \leftarrow (AX)$，实现两个操作数内容的互换。

* **寄存器与存储单元交换**：
  ```assembly
  XCHG AL, [SI + 3]
  ```
  源操作数采用寄存器相对寻址，指向一个字节内存单元。执行后将该内存单元的内容读出给 $\text{AL}$，同时将 $\text{AL}$ 的原值写入该内存单元，实现字节内容的互换，语法正确。

* **高低 8 位寄存器互换**：
  ```assembly
  XCHG BH, BL
  ```
  两个操作数均为 8 位寄存器，类型一致。指令执行后，原来 $\text{BX}$ 寄存器中 16 位数的高 8 位和低 8 位实现互换。

* **错误指令辨析**：
  ```assembly
  XCHG AX, ES    ; 错误！段寄存器不能参与数据交换
  XCHG AX, BL    ; 错误！操作数类型不一致（AX 为 16 位字，BL 为 8 位字节）
  ```
  因此书写指令时必须严格遵循语法规则。

#### [06:33] 字节转换指令（查表指令）：XLAT

数据传送指令的第六类是**字节转换指令**，助记符为 **`XLAT`**（Translate）。

##### 1. 指令格式
```assembly
XLAT
```
指令书写时不需要显式操作数，源操作数和目的操作数均采用隐含寻址。

##### 2. 指令功能
CPU 执行 `XLAT` 指令时：
* 默认在数据段（$\text{DS}$）内；
* 以 $\text{BX}$ 寄存器的内容作为**基地址**；
* 加上 $\text{AL}$ 寄存器的内容作为**相对位移量**；
* 计算有效地址：
  $$EA = (BX) + (AL)$$
* 寻址到该字节存储单元，将单元中的数据读出并送入 $\text{AL}$ 中：
  $$AL \leftarrow DS:[ (BX) + (AL) ]$$

执行后，$\text{AL}$ 原有的数值被表中对应单元的数据替换。因此，8086 指令系统中的 `XLAT` 指令，对比单片机指令系统，也称为**查表指令**。

---

#### [08:22] 查表应用场景：十六进制转 ASCII 码

在数据段（$\text{DS}$）中，我们可以通过 `DB` 伪指令定义一个转换表格。例如将十六进制数转换为对应的 ASCII 码：

* 偏移量 `00H` 存放字符 `'0'` 的 ASCII 码（`30H`）
* 偏移量 `01H` 存放字符 `'1'` 的 ASCII 码（`31H`）
* 偏移量 `02H` 存放字符 `'2'` 的 ASCII 码（`32H`）
* ……
* 偏移量 `09H` 存放字符 `'9'` 的 ASCII 码（`39H`）
* 偏移量 `0AH` 存放字符 `'A'` 的 ASCII 码（`41H`）
* 偏移量 `0BH` 存放字符 `'B'` 的 ASCII 码（`42H`）
* ……
* 偏移量 `0FH` 存放字符 `'F'` 的 ASCII 码（`46H`）

这样就建立好了一个查找表。

---

#### [09:17] 查表程序片段编写

在代码段（$\text{CS}$）中编程调用该表：

```assembly
; 假设需要转换的数值为 4
MOV AL, 04H      ; AL 中存放待转换的数（可以是一个运算结果）

; 获取字符表中该数字对应的 ASCII 码
; 此处需要将表格首地址送入 BX，可以使用 LEA 指令：
LEA BX, TABLE    ; 将转换表的偏移首地址装入 BX 基址寄存器
XLAT             ; 执行查表：AL ← DS:[BX + AL]，此时 AL 转换为字符 '4' 的 ASCII 码 (34H)
```
