# 8086 汇编语言：子程序调用、现场保护与参数传递

### [00:06] 一、段间子程序调用与返回的时序过程

CPU 执行段间子程序调用指令（远程调用）时，整体时序与堆栈操作如下：

假设这是初始的栈指针 $SP$：

```text
       ┌───────────────┐
       │      ...      │
       ├───────────────┤
SP  ──>│  初始栈顶单元  │
       ├───────────────┤
       │               │
```

当 CPU 执行段间子程序调用指令（如 `CALL FAR Sub1`）时：

1. **第一步（保护断点）：**
   - $SP$ 指针减 2（$SP \leftarrow SP - 2$），指向新的栈顶单元，将段寄存器 $CS$ 的返回地址压入堆栈；
   - $SP$ 指针再减 2（$SP \leftarrow SP - 2$），指向下一个栈顶单元，将指令指针寄存器 $IP$ 的返回地址压入堆栈。
   
2. **第二步（转移执行）：**
   - 将子程序名 `Sub1` 所在的段地址送入 $CS$；
   - 将子程序名 `Sub1` 对应的偏移地址送入 $IP$；
   - 此时 $CS:IP$ 指向子程序的入口地址，CPU 转去执行子程序，从而实现了段间子程序调用。

### [01:30] 段间返回（RETF）与堆栈平衡

子程序执行完毕后，执行 `RETF` 指令进行远程返回，CPU 完成以下操作：

1. 以当前 $SP$ 指针的内容作为栈顶地址，在该栈顶弹出一个字送入 $IP$，$SP$ 增 2（$SP \leftarrow SP + 2$）；
2. 以增 2 后的 $SP$ 作为新的栈顶地址，再弹出一个字送入 $CS$，$SP$ 再次增 2（$SP \leftarrow SP + 2$）；
3. 此时 $SP$ 恢复到调用前的初始位置，$CS$ 和 $IP$ 正确指向断点返回地址，完成远程正确返回。

> **补充说明：**  
> 上述推导为**段间直接寻址**方式。子程序的段内调用与段间调用均可采用间接寻址；虽然间接寻址在实际应用中相对较少，但依然需要掌握。

### [02:43] 堆栈指针 SP 的保护与配对要求

在 CPU 执行远程调用进入子程序体、执行内部指令时：
- 如果子程序内部使用了堆栈（执行了 `PUSH` 和 `POP` 操作），会改变 $SP$ 指针的位置；
- 当 CPU 执行到最后的返回指令时，必须确保 $SP$ 指针重新指回保存断点返回地址（$IP$ 与 $CS$）的栈顶位置，才能实现正确返回；
- 若在子程序体内破坏了 $SP$ 指针且未复原，程序将无法正常返回原断点。

**核心准则：** 子程序内如果使用堆栈进行 `PUSH`、`POP` 操作，`PUSH` 与 `POP` 必须严格配对，保证执行 `RET` / `RETF` 时堆栈处于平衡状态。

### [04:06] 二、现场信息的保护与恢复

#### 1. 概念背景
主程序在调用子程序前，通用寄存器中往往存有重要数据，期望在子程序执行完毕后这些数据保持不变。但子程序内部运算也需要使用通用寄存器，如果不做处理就会覆盖破坏原有数据。

#### 2. 处理机制
- **信息的保护（现场保护）：** 在子程序使用寄存器之前，将相关寄存器的内容通过 `PUSH` 指令压入堆栈保存；
- **信息的恢复（现场恢复）：** 在子程序执行结束、`RET` 返回之前，通过 `POP` 指令按逆序将寄存器原值出栈恢复。

#### 3. 实施位置
信息的保护与恢复有两种实现途径：
1. **在子程序中进行**：进入子程序体首部压栈保护，子程序体末尾出栈恢复；
2. **在主程序中进行**：在 `CALL` 指令调用之前 `PUSH` 压栈，在 `RET` 返回后 `POP` 出栈。

在实际程序设计中，绝大多数情况下采用**在子程序中进行**的方式。

### [05:56] 三、子程序间参数的传递方法

正如 C 语言在函数调用时需要向函数传入实参、返回时带回返回值一样，汇编语言子程序调用与返回同样涉及参数传递：
- **入口参数**：调用子程序前传递给子程序作为计算初值的数据；
- **出口参数**：子程序运算结束后返回给主程序调用的结果数据。

参数传递主要有以下三种方式：

#### 1. 用通用寄存器传递参数
- **特点**：实现最为简单、直接，执行效率高；
- **局限性**：可传递的参数数量受限。以 8086 CPU 为例，内部一共只有 14 个寄存器，参数量超出限制时无法继续使用该方式。

#### 2. 用存储器单元（内存）传递参数
- **特点**：在数据段中预先定义变量单元。在 `CALL` 调用前将参数写入变量单元，子程序进入后再从对应的变量单元中读取参数；返回时同理；
- **优缺点**：相对于寄存器传递略显繁琐，但可以传递大量参数，突破寄存器数量的限制。

#### 3. 用堆栈区传递参数
- **特点**：堆栈区本质上同样属于存储器单元，因此也可以利用堆栈段将参数压栈，供子程序按约定偏移寻址提取。

### [09:19] 四、前序教学内容回顾

结合第 3.11 节“子程序调用与返回指令”与第 4.5 节“子程序设计技术”的内容，已重点讲授：
1. **使用场景**：程序设计中在何种情况下应当划分并使用子程序；
2. **控制指令**：子程序的调用（`CALL`）与返回（`RET` / `RETF`）指令，涵盖段内与段间两种情形；
3. **子程序定义**：使用 `PROC` 与 `ENDP` 伪指令规范定义子程序结构。

子程序结束伪指令是 `ENDP`。

第四点我们讲了主程序与子程序之间参数的传递方法，共讲了三种方法：
1. **寄存器传递**：第一种是用寄存器传递。
2. **存储器单元传递**：第二种方法是用存储器单元传递。当用存储器单元传递时，首先要在数据段定义存储器单元；然后在代码段调用程序时，在 `CALL` 调用子程序之前，把传递给子程序的参数都写入到数据段中定义好的变量单元中去，然后再 `CALL` 调用子程序；进入到子程序后，在子程序的一开始，再从那些单元里面去获取参数，这是入口参数的传递。当然，子程序返回（`RET` 返回）时也有出口参数，出口参数的传递同样可以采用寄存器传递，或者采用存储器单元传递。
3. **堆栈传递**：第三种参数传递方法是用堆栈来传递。当用堆栈来传递时，要注意堆栈指针 `SP` 的变化。

[01:38]
最后我们讲了子程序调用时要注意信息的保护与恢复。

信息的保护与恢复一般情况下放在子程序中进行：
* 在子程序一开始，使用 `PUSH` 指令把需要保护的信息（一般情况下是寄存器的内容）进行压栈保护；
* 在 `RET` 返回之前，通过 `POP` 指令出栈恢复。

在出栈恢复时，需要注意两点：
1. 遵循**后进先出**原则；
2. 前面 `PUSH` 压栈保护的信息，在后面 `POP` 出栈恢复时，`PUSH` 和 `POP` 必须配对。

只有 `PUSH` 和 `POP` 严格配对，堆栈指针才不会被破坏；在执行 `RET` 指令时，程序才能够正确地返回到主程序。
