### [00:02] 可视字符、非可视字符与光标回车换行控制

在第一章我给大家讲过，在这门课的上机实践当中，要求大家掌握：
- `'0'` $\sim$ `'9'` 字符
- `'A'` $\sim$ `'Z'`（如果记不全到 `'Z'`，起码掌握 `'A'` $\sim$ `'F'`）的大写及小写字符的 ASCII 码

这几个字符的 ASCII 码称为**可视字符**，在屏幕上能够直接显示出来。

同时，还要掌握一些**非可视字符**，在屏幕上本身并不显示字形，例如：
- **回车字符 (CR)**：ASCII 码为 `0DH`
- **换行字符 (LF)**：ASCII 码为 `0AH`
- **空格字符 (SP)**：ASCII 码为 `20H`

这些都是非可视字符。

我们来看一个实际应用场景：假设这是计算机屏幕，当系统处于 DOS 操作系统界面时，屏幕上可能已经显示了许多信息。显示完成后，光标在末尾闪烁。现在我们希望通过程序控制，将后续要显示的信息输出到**下一行的最左端**。

在显示之前，光标应该先移动到下一行的起始位置。光标如何移动到目标位置？
很多同学会以为直接“回车”就能到下一行——这是**错误**的。

- **回车 (Carriage Return)**：仅将光标移回到**当前行的最左端**。
- **换行 (Line Feed)**：将光标下移到**下一行**（垂直下移，列位置不变）。

因此，必须同时执行**回车**和**换行**，光标才能到达下一行的最左端。

通过 DOS 系统功能调用实现回车的代码如下：
```assembly
MOV AH, 02H     ; 2号功能调用：显示输出
MOV DL, 0DH     ; 0DH 为回车符的 ASCII 码
INT 21H         ; 执行后，光标返回当前行最左端
```

接着进行换行操作：
```assembly
MOV AH, 02H     ; 2号功能调用：显示输出
MOV DL, 0AH     ; 0AH 为换行符的 ASCII 码
INT 21H         ; 执行后，光标下移到下一行
```

回车与换行的先后顺序可以互换，先换行后回车效果是一样的。

在教材第 4.39 题中，我们要实现某些功能，屏幕上经常需要显示菜单或人机交互提示语。当一句话显示完毕后，若要在下一行显示下一句话，就必须执行一次回车换行。因为回车换行是非常常用的代码片段，大家完全可以将其编写为一个**子程序**，当需要光标回车换行时，直接使用 `CALL` 指令调用该子程序即可。

### [03:49] 过程调用与系统功能调用回顾

上一节课我们讲到第 3.12 节“过程调用与返回指令”，并介绍了 3.12.5 节“系统功能调用”。

系统功能调用主要分为两类：
1. **DOS 功能调用**（DOS 高级功能调用）
2. **BIOS 功能调用**（BIOS 低级功能调用）

在上一节课中，我们介绍了以下几个 DOS 功能调用：
- **01H 号功能**、**07H 号功能**、**08H 号功能**：均为等待用户从键盘输入一个字符，但三者在是否有回显、是否响应 `Ctrl+C` 等细节上存在区别。
- **02H 号功能**：向屏幕输出单个字符，待输出字符需预先存放在 `DL` 寄存器中。
- **05H 号功能**：向打印机输出单个字符，待输出字符同样需预先存放在 `DL` 寄存器中。

---

### [05:03] DOS 06H 号功能调用（直接控制台输入/输出）

今天我们接着来看 **06H 号功能调用**，其全称为**直接控制台输入输出**（Direct Console I/O）。

该调用的特点在于：**既能做输入，也能做输出**。
- **输出**：向屏幕输出一个字符。
- **输入**：从键盘读取一个字符。

具体执行输入还是输出，由进入调用前 `DL` 寄存器的取值决定：
1. **输出模式**：若 `DL` 的内容介于 `00H` $\sim$ `FEH` 之间，则执行屏幕输出，输出的字符即为 `DL` 中存放的 ASCII 码字符。
2. **输入模式**：若预先将 `DL` 设置为 `FFH`（即 `MOV DL, 0FFH`），则 06H 号功能转为键盘输入模式。

**06H 号输入功能与 01H、07H、08H 号调用的本质区别**：
01H、07H、08H 号功能在没有按键输入时会**挂起等待**；而 06H 号功能做输入时具有**非阻塞特性——不等待！**

---

### [06:33] 06H 号功能的非阻塞键盘检测机制

在程序设计中，使用 DOS 06H 号功能的主要目的就是为了**非阻塞地检测键盘输入**。

当设置 `DL = 0FFH` 并执行 `INT 21H` 时，CPU 会瞬间检测当前键盘缓冲区是否有按键按下，随后无论是否有按键，程序都会立即向下继续执行。

既然程序不等待并直接返回，我们如何判断是否有按键按下？
系统通过**零标志位 $ZF$ (Zero Flag)** 返回状态：
- **若无按键**：$ZF = 1$
- **若有按键**：$ZF = 0$，且被按下字符的 ASCII 码会自动存入 `AL` 寄存器中供后续读取（与 01H 号调用类似，键值均保存在 `AL` 中）。

因此，在调用 06H 号功能后，紧接着测试 $ZF$ 标志位即可完成分支判断：
```assembly
MOV AH, 06H     ; 6号功能调用
MOV DL, 0FFH    ; DL = 0FFH 表示执行输入检测
INT 21H

JZ NO_KEY       ; 若 ZF = 1，表示当前无按键，跳转到 NO_KEY 分支继续执行

; 若 ZF = 0，表示有按键按下，此时 AL 中已存放按键的 ASCII 码
CMP AL, 'Q'     ; 将按键字符与指定字符（如退出键 'Q'）进行比较
; ... 后续分支处理 ...

NO_KEY:
; ... 未按键时的处理逻辑 ...
```

### [00:49] 条件跳转与程序流程控制（JE / JMP）

如果相等，即按下的是 ESC 键，就执行 `JE` 指令跳转。这就相当于跳转回程序开头，返回主菜单。
