### 子程序调用与堆栈参数传递

#### [00:00] 主程序压栈传参与 CALL 指令执行
把缓冲区首址压入堆栈，准备用堆栈的这个字单元的值告诉子程序：“缓冲区首址在这，你去取。”

此时，`SP` 指针指向该处。然后 CPU 执行 `CALL` 指令。CPU 执行 `CALL` 指令时，首先保护返回地址 `IP`：`SP` 指针减 2（$SP \leftarrow SP - 2$），栈顶指到新位置。

指到这里以后，下一条指令的偏移地址即为返回地址 `IP`。CPU 将该 `IP` 压栈保护起来。保护完毕后，程序执行流程随即转移到子程序中。

---

#### [00:54] 子程序现场保护（保护寄存器）
进入到子程序以后，子程序本身首先需要连续进行压栈操作以保护现场：

- `PUSH` 第一次：保护 `AX`；
- `PUSH` 第二次：保护 `BX` 寄存器的值；
- `PUSH` 第三次：保护 `CX` 寄存器的值；
- `PUSH` 第四次：保护 `SI` 寄存器的值。

此时，栈顶 `SP` 指针下移指向当前位置。

---

#### [01:43] 关键问题：如何在子程序中读取堆栈中的参数
现场保护完毕后，子程序需要完成后续统计功能：统计指定字节中有几个 1，判断是偶数个 1 还是奇数个 1，从而决定最高位是否置 1 以实现偶校验。

要实现该功能：
1. 待校验字符缓冲区的首地址存放在堆栈中，需要读取；
2. 待校验字符的个数同样保存在堆栈中，也需要读取。

此时的核心问题是：**如何从堆栈中取出这两个参数？**

不能通过执行 `POP` 指令将它们弹出。因为如果用 `POP` 弹出参数，等到子程序最终执行 `RET` 指令返回时，`SP` 必须指在保存返回地址 `IP` 的位置；若提前用 `POP` 改变了 `SP` 的指向，就无法正常通过 `RET` 返回。因此，**不能使用出栈指令来获取堆栈中传递的参数**。

---

#### [03:08] 引入基址指针寄存器 BP
为了解决这一问题，需要利用基址指针寄存器 `BP`：

```assembly
PUSH BP
MOV  BP, SP
```

子程序内部需要使用 `BP`，因此首先必须保护主程序中的 `BP`（无论主程序此前是否使用过，子程序用到就必须进行现场保护）。

1. CPU 执行 `PUSH BP`，`SP` 减 2，将原 `BP` 寄存器的值压栈保护，`SP` 指向新的栈顶；
2. 执行 `MOV BP, SP`（寄存器寻址），将 `SP` 当前的值传送给 `BP`。

操作完成后，`BP` 便指向了存放“原 BP 值”的这个字单元。根据 8086 寻址规则，**以 `BP` 进行相对寻址时，默认使用的段寄存器是堆栈段 `SS`**。

---

#### [04:36] 利用 BP 相对寻址计算偏移量提取参数
为了既能获取到参数，又不破坏堆栈指针 `SP` 的位置，可以通过 `BP` 加上相对位移量来寻址。

堆栈自顶向下（高地址向低地址生长）的布局如下：

| 偏移地址 | 存放内容 |
| :--- | :--- |
| `[BP + 0EH]` | 字符个数（参数） |
| `[BP + 0CH]` | 缓冲区首址（参数） |
| `[BP + 0AH]` | 返回地址 `IP` |
| `[BP + 08H]` | 保护的 `AX` |
| `[BP + 06H]` | 保护的 `BX` |
| `[BP + 04H]` | 保护的 `CX` |
| `[BP + 02H]` | 保护的 `SI` |
| `[BP + 00H]` | 保护的 `BP`（当前 `SP`、`BP` 指向处） |

因此，通过以下指令提取参数：

```assembly
MOV SI, [BP + 0CH]  ; 从堆栈段取出缓冲区首地址给 SI
MOV CX, [BP + 0EH]  ; 从堆栈段取出字符个数给 CX
```

这里充分利用了**以 `BP` 相对寻址、段地址默认在堆栈段 `SS`** 的基本原理。在子程序开始处，通过该方式从堆栈中成功提取出主程序在执行 `CALL` 之前所压入的参数。

---

#### [05:51] 嵌套调用 COUNT_BYTE 子程序与返回值传递
参数获取完成后，继续往下执行，程序调用嵌套子程序：

教材例 4.9（第 118 页），调用的 `COUNT_BYTE` 子程序位于第 120 页。该子程序逻辑如下：
1. 进入后保护现场；
2. 置循环计数器 `CX = 8`（每个字节 8 位，需要移位 8 次）；
3. 将累加计数值 `BL` 清零；
4. 通过 `AL` 循环移位指令逐位移出，判断移出位是 1 还是 0 并累加到 `BL`；
5. `LOOP` 循环 8 次后执行 `RET` 返回。

返回后，统计的结果保存在寄存器 `BL` 中，即**通过通用寄存器 `BL` 将结果参数带回**。如果统计结果不使用 `BL`，也可以通过堆栈传递返回，两者皆可。

#### [08:28] 子程序现场恢复与退出（POP 与 RET）
子程序处理完毕即将返回前，必须严格按照与压栈相反的顺序恢复现场寄存器：

```assembly
POP BP
POP SI
POP CX
POP BX
POP AX
RET
```

1. 执行 `POP BP`：栈顶数据弹出恢复给 `BP`，`SP` 指针自增 2（$SP \leftarrow SP + 2$）；
2. 依次执行 `POP SI`、`POP CX`、`POP BX`、`POP AX`，逐一恢复各个通用寄存器的原值。

执行完 `POP AX` 之后，`SP` 指针恢复指向调用前保存的返回地址 `IP`。

> **概念辨析：栈单元数据弹出后的状态**  
> 往年常有学生疑问：“数据执行 `POP` 弹出后（例如 `POP AX` 将栈单元的值送入 `AX`），原来该字单元里的值跑到哪里去了？”  
> 实际上，内存字单元中的物理电平/数值依然保留，并没有被物理清除或消失，只是 `SP` 指针发生了移动；该单元已经退出了有效栈区域，不再被当前程序所使用，后续的压栈操作会直接覆盖其中的旧数据。

---

#### [09:50] 执行 RET 返回
现场寄存器完全恢复后，`SP` 正好重新对齐到返回地址 `IP`，此时执行：

```assembly
RET
```

CPU 从当前栈顶弹出返回地址给指令指针寄存器 `IP`，程序顺利返回到主程序的断点处继续向下执行。
