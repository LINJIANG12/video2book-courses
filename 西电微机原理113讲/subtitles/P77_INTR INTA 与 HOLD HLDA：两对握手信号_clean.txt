#### [04:11] 第二总线周期与中断向量读取

然后，CPU 再花一个总线周期（同样经历 $T_1, T_2, T_3, T_4$）。

CPU 在第二个总线周期的 $T_2$ 后半周期使 $\overline{\text{INTA}}$ 变低，在 $T_4$ 快结束之前又变高，向 8259 发送了第二个负脉冲。

每个请求信号在初始化时都有一个中断类型号，8259 就把对应中断类型号寄存器的值读出来，放到数据总线上。CPU 这个时候要读数据线（$D_0 \sim D_7$）。

这相当于 CPU 在第二个负脉冲期间从数据流中读取中断类型号 $n$。CPU 读取数据总线低 8 位获取中断类型号 $n$ 后，便知道了是哪一个设备的请求。从而以 $n \times 4$ 计算偏移量，在中断向量表 $n \times 4$ 单元处获取中断向量，送入 $\text{CS}$ 和 $\text{IP}$，进而转入中断服务程序。

#### [05:55] 中断请求信号的撤销

## 2. 核心原理深度推导

### 2.1 外部可屏蔽中断响应机制（INTR 与 $\overline{\text{INTA}}$ 握手）

#### 2.1.1 触发与响应的前置约束条件
1. **内部状态约束**：CPU 内部标志寄存器的中断允许标志位必须处于置位状态，即：
   $$\text{IF} = 1 \quad (\text{开中断})$$
   若 $\text{IF} = 0$（关中断），CPU 对 $\text{INTR}$ 引脚上的请求不予响应。
2. **信号有效电平**：外部中断控制器输出至 8086 的 $\text{INTR}$ 引脚信号为**高电平有效**。
3. **指令执行边界约束**：CPU 收到 $\text{INTR}$ 高电平信号后，**不能立即中止当前工作**，必须等待当前正在执行的指令的所有时钟周期（即执行周期的最后一个状态，如 $T_4$）结束，保证指令的完整执行。

#### 2.1.2 控制器互连架构
* **8259 中断控制器**：单片 8259 具有 8 个中断请求输入端（$\text{IR}_0 \sim \text{IR}_7$），可挂接 8 个外部中断源。
* **级联连接关系**：
  * 外设中断源向 8259 发出请求（$\text{IR}_i$）。
  * 8259 仲裁允许后，通过其 $\text{INT}$ 输出端向 8086 的 $\text{INTR}$ 输入端输出高电平。
  * 8086 回馈响应信号，通过其 $\overline{\text{INTA}}$（输出引脚，低电平有效）与 8259 握手。

#### 2.1.3 中断响应双总线周期（Two Bus Cycles）时序演进推导
8086 CPU 响应可屏蔽中断请求，需耗费**两个连续的总线周期**完成确认与向量获取：

```text
现行指令周期          第 1 个中断响应总线周期 (/INTA)       第 2 个中断响应总线周期 (/INTA)
...─[T1][T2][T3][T4]──┼──[T1]──[T2]──[T3]──[T4]────────────┼──[T1]──[T2]──[T3]──[T4]──>
                      │                                    │
INTR  : ─────/▔▔▔▔▔▔▔▔│▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔\__ (必须在握手完成时拉低)
                      │                                    │
/INTA : ──────────────┼────────\______/────────────────────┼────────\______/────────
                      │         (第1个负脉冲: 响应确认)     │         (第2个负脉冲: 读向量)
                      │                                    │
D0~D7 : ──高阻/无效───┼────────────────────────────────────┼───────────[ 类型号 n ]──
```

1. **第一个总线周期（响应确认握手）**：
   * 在指令执行完毕后的下一个总线周期中，8086 CPU 从其 $\overline{\text{INTA}}$ 引脚发出**第一个负脉冲**（在 $T_2$ 下降，在 $T_4$ 结束前上升为高电平）。
   * 8259 捕获该负脉冲，感知到 CPU 已开始响应当前中断请求，完成第一步握手握紧（“握上手了”）。
2. **第二个总线周期（中断向量号读取）**：
   * CPU 开启第二个总线周期，并在其时序中发出**第二个 $\overline{\text{INTA}}$ 负脉冲**。
   * 该负脉冲本质是向 8259 发起询问：“在接入的 8 个中断源中，当前究竟由谁发起请求？”
   * 8259 收到第二个负脉冲后，将其内部对应中断源的**中断类型号 $n$**（在 8259 初始化阶段配置到相应寄存器）读出，驱动至系统数据总线 $D_0 \sim D_7$ 上。
   * 8086 在该低脉冲期间对 8 位数据总线进行采样读入，成功捕获中断类型号 $n$。
3. **中断向量寻址数学推导**：
   * 8086 获得 8 位类型码 $n$ 后，在中断向量表（IVT）中定位对应的入口地址，向量首地址偏移量计算公式为：
     $$\text{Vector\_Address} = n \times 4$$
   * 通过该地址连续读取 4 字节内容（前 2 字节为中断服务程序入口偏移地址 IP，后 2 字节为代码段基址 CS），从而完成 PC 跳转，进入服务程序。

---

### 2.2 最小工作方式下的总线保持与仲裁机制（HOLD 与 HLDA）

#### 2.2.1 最小工作方式的多处理器支持能力
* **架构定性**：在最小工作方式下，8086 **同样能够构成多处理器系统**（更正“最小方式无法构建多处理系统”的片面认知）。
* **物理容量上限**：在最小方式下构建的多处理器系统，系统内**最多只能容纳 2 个处理器**。
  * **主处理器（主设备）**：8086 CPU 本身（微处理器）。
  * **副控设备（从属设备）**：外部“总线主控设备”（总线主控器），具有总线管理和数据传输能力。

#### 2.2.2 握手让渡状态流转推导
当外部总线主控设备需接管系统总线以操作挂载的外设时，采用一对一信号对（$\text{HOLD}$ 与 $\text{HLDA}$）进行让渡协商：

1. **申请阶段（Request）**：
   * 外部总线主控设备向 8086 的 $\text{HOLD}$ 引脚输出一个**高电平有效**的信号，申请获得总线使用权。
2. **判决与让渡边界（Arbitration Boundary）**：
   * 8086 侦测到 $\text{HOLD}$ 为高电平。
   * CPU 必须**在现行指令执行完毕之后**，才能交出总线使用权，不得强行撕裂正在运行的总线周期。
3. **确认让渡阶段（Acknowledge）**：
   * 8086 释放总线控制权（总线浮空），并通过 $\text{HLDA}$（Hold Acknowledge，高电平有效）输出引脚向外部主控设备发送一个**高电平**响应信号。
4. **接管与执行阶段（Bus Takeover）**：
   * 外部总线主控设备收到 $\text{HLDA}$ 高电平后，判定 CPU 已成功让渡总线，随即接管系统总线并执行其设定的操作。

## 3. 信号交互与总线控制对比矩阵

| 对比维度 | 外部可屏蔽中断请求/响应 | 总线保持与让渡请求/响应 |
| :--- | :--- | :--- |
| **信号引脚对** | $\text{INTR}$（输入） / $\overline{\text{INTA}}$（输出） | $\text{HOLD}$（输入） / $\text{HLDA}$（输出） |
| **有效电平特性** | $\text{INTR}$: 高电平有效<br>$\overline{\text{INTA}}$: 低电平有效（负脉冲） | $\text{HOLD}$: 高电平有效<br>$\text{HLDA}$: 高电平有效 |
| **外部对接组件** | 中断控制器（如单片 8259A，挂接 $\text{IR}_0 \sim \text{IR}_7$） | 总线主控设备 / 总线主控器 |

| **工作模式限制** | 最小/最大方式均存在类似机制（本节基于最小方式板书） | **严格限定于最小工作方式**（见教材第 169 页） |

## 4. 反模式与踩坑清单

### 4.1 陷阱 1：中断信号持续保持高电平导致“同级中断重入与误打断”
* **反模式行为**：8259 发送 $\text{INTR}$ 高电平后，在 CPU 完成双总线周期的握手并进入中断服务程序时，外部硬件未将 $\text{INTR}$ 引脚电平拉低复位。
* **工程隐患**：CPU 转移到中断服务程序去执行该服务程序，若此时 $\text{INTR}$ 仍为高电平，CPU 将误判为存在新的同级中断请求，进而**打破同级中断的禁止规则**（出现同级中断请求打断正在运行的同级中断服务），这是系统体系结构中严格禁止的。
* **正确防御机制**：8259 具备电平控制能力，在第二个总线周期结束、CPU 回答完毕（“回答都完了”）的时序点，**$\text{INTR}$ 引脚必须主动变低**，彻底结束本次请求会话。

### 4.2 陷阱 2：误判最小工作方式为“绝不可能构建多处理器系统”
* **反模式认知**：死板认定“8086 只有在最大工作方式下才能构建多机系统，最小工作方式下只能是单微处理器系统”。
* **标准概念辨析**：
  * 讲师明确指出，此前阐述的字眼是最小方式“不适合”构成大型多处理机系统。
  * **事实边界**：最小工作方式下**同样能构成多处理机系统**，但存在刚性物理边界——**最多只能有 2 个处理器**（8086 主处理器 + 1 个总线主控从设备，依靠 $\text{HOLD}/\text{HLDA}$ 仲裁）。

### 4.3 陷阱 3：假设 CPU 遇到外部请求会立即中断当前微操作
* **反模式行为**：认为只要 $\text{INTR}$ 或 $\text{HOLD}$ 置高，CPU 就必须在下一个时钟周期瞬间打断当前的指令。
* **事实准则**：CPU 响应 $\text{INTR}$ 或 $\text{HOLD}$ 的**刚性边界条件是“现行指令执行完毕”**。必须保证当前指令的微操作时钟周期（$T_1 \sim T_4$）完整闭环，否则将破坏程序计数与指令原子性。

## 二、 核心原理深度推导与板书逻辑还原

### 1. 总线出让、仲裁与回收时序推导

在单处理器系统中，外部主控设备（总线主控设备）需接管总线时，通过硬件握手信号与 CPU 仲裁。时序推导逻辑如下：

*   **前置条件**：系统工作于最小模式，基准时钟为 $CLK$。
*   **第 1 步（请求）**：主控设备向 CPU 对应请求引脚（$HOLD$）发出请求信号。
*   **第 2 步（响应与让出）**：
    CPU 确认出让总线，在时序上完成两个关键动作：
    1.  将响应/回答引脚（$HLDA$）驱动为**高电平**，通知主控设备接管。
    2.  将 CPU 自身**凡是具有三态功能的输出引脚，全部设置为三态（高阻态）**，从而在电气层面与系统总线脱开，实现总线让出。
*   **第 3 步（总线占用与释放）**：
    主控设备接管总线执行操作。使用完毕后，主控设备主动将请求信号拉为**低电平**。
*   **第 4 步（检测与延迟收回）**：
    CPU 出让总线后，处于硬件级不间断检测该请求引脚的状态：
    $$\text{检测条件：} \text{Pin Level} = \text{Low}$$
    一旦检测到该引脚变低，CPU 并不立即动作，而是：
    $$\Delta t = 1 \sim 2 \text{ 个 } CLK \text{ 周期}$$
    在经过 $1 \sim 2$ 个 $CLK$ 周期的延迟后，CPU 将响应引脚（$HLDA$）拉回**低电平**，正式收回系统总线控制权。

### 2. 最小模式下系统三总线的物理成型（教材 P174 图 5.14）

8086 工作于最小模式（单微处理器结构）时，系统总线由芯片引脚及外围成型器件直接构建：

```text
       +-------------------------------------------------------+
       |                   8086 CPU (最小模式)                  |
       +-------------------------------------------------------+
           │                                 │
           │ 时分复用 AD0~AD15, A16~A19      │ 控制引脚直接引出
           ▼                                 ▼
   +---------------+                 +-------------------------+
   |   74LS373     |                 |  /RD, /WR, M//IO,       |
   |  (锁存器件)    |                 |  /INTA, INTR, NMI, ...  |
   +---------------+                 +-------------------------+
           │                                     │
           ▼                                     ▼
   20位系统地址总线                      系统控制总线
   (A0~A19, 含 /BHE)                  (直接拉出，无需额外总线控制器)
           │
           │ (双向数据通道)
           ▼
   +---------------+
   |   74LS245     |
   | (双向收发驱动) |
   +---------------+
           │
           ▼
   16位系统数据总线 (D0~D15)
```

#### (1) 数据总线（Data Bus）
*   位宽：16 位。
*   成型硬件：通过双向数据总线收发器 **74LS245** 成型。
*   拓扑结构：分为低 8 位数据线（$D_0 \sim D_7$）与高 8 位数据线（$D_8 \sim D_{15}$）。

#### (2) 地址总线（Address Bus）
*   位宽：20 位（$A_0 \sim A_{19}$）。
*   成型硬件：通过地址锁存器 **74LS373** 成型。
*   附属线：包含 $\overline{\text{BHE}}$（高位字节使能信号）。严格意义上，$\overline{\text{BHE}}$ 属于地址范畴，同样经锁存器输出。
*   **奇偶存储体分割数学逻辑**：
    外部物理寻址空间为：
    $$\text{Total Address Space} = 2^{20} \text{ B} = 1\text{ MB}$$
    通过 $A_0 = 0$ 和 $\overline{\text{BHE}} = 0$ 的逻辑状态，将 1MB 外部地址空间物理划分为两个 $0.5\text{ MB}$（即 512KB）的存储体：
    *   **偶地址体（Even Bank）**：由 $A_0 = 0$ 选中。
    *   **奇地址体（Odd Bank）**：由 $\overline{\text{BHE}} = 0$ 选中。

#### (3) 控制总线（Control Bus）
*   产生特征：在最小模式下，控制信号无需额外的总线控制器，**直接由 CPU 自身引脚引出成型**。
*   包含信号集合：$\overline{\text{RD}}$、$\overline{\text{WR}}$、$M/\overline{\text{IO}}$、$\overline{\text{INTA}}$、$\text{INTR}$、$\text{NMI}$、$\text{HLDA}$、$\text{HOLD}$、$\overline{\text{TEST}}$、$\text{RESET}$。

### 3. 总线驱动与扇出能力推导

在工程设计中，控制信号（以写控制信号 $\overline{\text{WR}}$ 为例）需同时并联分发至外部存储器子系统中所有存储芯片的写控制端。

*   **电气边界问题**：
    每个存储芯片的输入引脚均构成容性与阻性负载。若系统芯片数量庞大：
    $$\sum_{k=1}^{N} \text{Load}_k > \text{DriveCapability}_{\text{CPU Pin}}$$
    CPU 原始引脚将无法驱动全系统，引起波形失真与电气瘫痪。
*   **单向信号驱动解决方案（黑板板书逻辑）**：
    *   **方法 A（加门缓冲）**：在输出引脚与负载间插入单向门电路（缓冲驱动器）进行带载功率放大。
    *   **方法 B（分路带载）**：若单个门电路驱动力仍不足，通过逻辑门分解为多路输出。例如分成两路：
        $$\overline{\text{WR}} \longrightarrow \begin{cases} \overline{\text{WR}}_1 & (\text{带载系统第 1 部分负载}) \\ \overline{\text{WR}}_2 & (\text{带载系统第 2 部分负载}) \end{cases}$$
*   **双向信号驱动解决方案**：
    双向信号（如数据总线）无法采用单向门驱动，难点正在于双向数据流控制，必须采用双向总线收发器件（如 **74LS245**）。

### 4. 扩展电路设计规范与总线分配逻辑

在后续章节（第 6 章存储器设计，第 7、9、10 章 I/O 接口电路设计）中，系统设计的本质是在**既有系统总线基础之上进行挂载扩展**，而不是重构总线。

```text
                     8086 最小模式系统总线 (已成型)
       =========================================================
          │ 地址总线                  │ 数据总线        │ 控制总线
          │ (A0~A19, /BHE)           │ (D0~D15)        │ (/RD, /WR, M//IO)
          ▼                          ▼                 ▼
  ┌─────────────────┐        ┌─────────────────┐
  │   存储器扩展     │        │   I/O 接口扩展  │
  ├─────────────────┤        ├─────────────────┤
  │·地址线: 全部20位 │        │·地址线: A0~A15   │
  │  (A0~A15+A16~A19│        │  (只用16根)     │
  │·M//IO = 1       │        │·M//IO = 0       │
  │·读写: /RD, /WR  │        │·读写: /RD, /WR  │
  │                 │        │·字节端口依地址   │
  │                 │        │ 奇偶连低8位/高8位│
  │                 │        │·中断需加/INTA,INTR│
  └─────────────────┘        └─────────────────┘
```

#### (1) 存储器扩展设计规则
*   **地址总线**：必须动用全部 20 位地址线，即 $A_0 \sim A_{15}$ 与 $A_{16} \sim A_{19}$。
*   **操作控制**：$M/\overline{\text{IO}} = 1$（指明当前总线操作为存储器访问），搭配 $\overline{\text{RD}}$（读）、$\overline{\text{WR}}$（写）。

#### (2) I/O 接口扩展设计规则
*   **地址总线**：仅使用 16 根地址线（$A_0 \sim A_{15}$）。
*   **操作控制**：$M/\overline{\text{IO}} = 0$（指明当前总线操作为 I/O 端口访问），搭配 $\overline{\text{RD}}$（读）、$\overline{\text{WR}}$（写）。
*   **字节端口传输路由法则**：
    若接口为 8 位字节端口，其与 16 位 CPU 数据总线的物理挂接取决于端口地址的奇偶性：
    $$\text{Port Address} \longrightarrow \begin{cases} \text{偶地址 (Even)} & \longrightarrow \text{数据走低 8 位数据线 } (D_0 \sim D_7) \\ \text{奇地址 (Odd)} & \longrightarrow \text{数据走高 8 位数据线 } (D_8 \sim D_{15}) \end{cases}$$
*   **中断扩展增补**：
    若扩展系统包含中断控制器（如扩展一片 8259 芯片）或引入中断功能，控制总线须引入中断应答 $\overline{\text{INTA}}$ 与中断请求 $\text{INTR}$ 两根信号。

## 四、 反模式与工程踩坑清单

### 1. 输出引脚“直驱海量负载”反模式
*   **反模式现象**：将 CPU 引脚输出的单根读写控制线（如 $\overline{\text{WR}}$）直接跳线挂接到系统中成倍增加的芯片写控制端（如几十片 RAM/ROM）。
*   **工程隐患**：负载超额引起总线驱动能力衰减，导致逻辑电平跌落、时序边缘迟缓，引发写入失败或芯片逻辑紊乱。
*   **防御方案**：必须加装驱动门电路进行总线放大；若负载极重，必须实施“负载切片”，将控制信号分流为多路独立输出（如 $\overline{\text{WR}}_1$ 负责驱动体 A，$\overline{\text{WR}}_2$ 负责驱动体 B）。

### 2. 总线让出“高阻态遗漏”反模式
*   **反模式现象**：外部设备请求总线时，仅将仲裁响应信号（$HLDA$）置高，未将总线信号引脚挂置三态。
*   **工程隐患**：CPU 引脚仍处于低阻推挽驱动状态，主控设备强行驱动总线将引发总线冲突（Bus Contention），烧毁引脚或导致逻辑竞争。
*   **防御方案**：总线出让必须满足两大充要条件：① 响应引脚变高；② CPU 内部所有具备三态功能的输出引脚**必须全部进入三态（高阻态）**。

### 3. 总线回收“时钟延迟忽略”反模式
*   **反模式现象**：主控设备归还总线（请求引脚拉低）瞬间，CPU 立即在无时钟延时状态下拉低应答信号并抢回总线。
*   **工程隐患**：主控设备释放总线在电气上存在延迟，未等待其安全退出便抢夺总线，必然造成总线信号击穿或状态混乱。
*   **防御方案**：遵循时序硬性边界——CPU 必须持续检测请求引脚，并在该引脚变低之后，**严格延时 1 到 2 个 $CLK$ 周期**，方可将应答信号拉低，重新接管总线。

### 4. 字节端口数据线“盲接”反模式
*   **反模式现象**：设计 8 位 I/O 字节端口时，不查验分配的端口地址，随意固定接入低 8 位数据线（$D_0 \sim D_7$）。
*   **工程隐患**：若系统给该端口分配的是奇地址（Odd），CPU 在执行字节访问时默认通过高 8 位数据线（$D_8 \sim D_{15}$）交互，导致硬件无法读取或写入数据。
*   **防御方案**：严格根据端口物理地址的奇偶性布线——**偶地址端口挂低 8 位，奇地址端口挂高 8 位**。

### 5. 扩充电路“重画总线”设计反模式
*   **反模式现象**：在面对“扩充某一功能电路”的考题或工程任务时，误将注意力放在重新搭建 8086 最小系统的基本总线生成电路上。
*   **防御方案**：明确工程前提边界——“系统总线已经存在”。电路扩充是在现成的地址总线、数据总线、控制总线三组引脚之上进行外围逻辑设计。

## 第一章 核心原理深度推导

### 1.1 系统扩展的顶层逻辑：总线级设计抽象
在微机系统接口与电路设计中，后续的所有扩充设计并非随意拉线，其架构演进遵循严格的规范：
* **核心基准**：电路设计**总是基于系统总线级**进行扩充设计。
* **演进脉络**：
  $$\text{8086 最小方式系统总线} \longrightarrow \text{8086 最大方式系统总线} \longrightarrow \text{PC 总线等（后续阶段）}$$
* **主次边界**：8086 工作在**最小方式下的引脚功能与时序**是本门课程的**绝对重点**；而最大方式的分析主要聚焦于模式切换带来的差异。

### 1.2 模式切换与引脚重组推导（教材 P163 图 5.5）
从最小方式切换至最大方式时，CPU 内部硬件结构对外呈现的控制接口发生重组：
1. **边界条件确定**：解题与分析前必须从已知条件明确 CPU 是工作在“最小方式”还是“最大方式”。
2. **重构区间**：根据教材第 163 页图 5.5，当 8086 工作在最大方式时，改变功能的管脚范围严格限定在 **24 脚至 31 脚**（共 8 个引脚）。
3. **状态输出核心组构建（Pins 26–28）**：
   在最大方式下，原最小方式的控制引脚转变为处理器的状态输出线：
   * **Pin 26** $\rightarrow \overline{S_2}$（$S_2$ 非）
   * **Pin 27** $\rightarrow \overline{S_1}$（$S_1$ 非）
   * **Pin 28** $\rightarrow \overline{S_0}$（$S_0$ 非）
   * **功能性质**：三者共同构成状态输出（Status Outputs），用于向外指示当前总线周期的操作类型（具体状态编码讲师指出此前已讲授，本段未复述明细）。
4. **总线控制逻辑转换**：
   讲师在开篇强调了访问数据段以及 20 位寻址背景下的信号转换问题，特别点出 $IO/\overline{M}$（IO/M 非）信号的变化情况，提醒在最大/最小方式切换时，原由 CPU 直接输出的控制信号形态已发生改变。

## 第三章 反模式与踩坑清单

### 常见反模式 1：审题盲目，忽略前提模式判定
* **现象**：拿到微机接口或电路分析题目，看到 20 位地址或数据段访问，未看清题干给定的已知工作模式，直接凭经验套用最小方式引脚。
* **讲师警示**：“做题呢，一定要读题，把题目搞清楚，看题目给的是什么已知条件！20 位就这没了？这不访问数据段吗？这个信号变成啥了？$IO/\overline{M}$……把题目要想清楚。”
* **防御方案**：在电路分析第一步，必须首先检索已知条件中的模式配置（是最小方式还是最大方式），明确当前总线到底是基于哪种系统总线级展开的。

### 常见反模式 2：固定引脚思维，混淆跨模式管脚定义
* **现象**：误以为 CPU 引脚功能是全生命周期恒定不变的，在最大方式系统中继续寻找单芯片直接生成的控制线。
* **讲师警示**：明确指出**工作在最大方式时，24 脚到 31 脚的功能改变了**。
* **防御方案**：强记 Pin 24–31 的可重构特性，尤其是 26、27、28 脚在最大方式下已退化/抽象为 $\overline{S_2}, \overline{S_1}, \overline{S_0}$ 三个底层状态输出信号。

### 常见反模式 3：跨越设计抽象层次，脱离总线进行电路扩充
* **现象**：在电路设计中脱离规范的系统总线层级，直接在芯片引脚级做非标扩展。
* **讲师警示**：“后面的电路设计总是基于系统总线级的扩充设计。”
* **防御方案**：严格建立“系统总线级”的模块化系统设计意识，基于规范定义的最小/最大总线或 PC 总线标准开展外设接口设计。
