#### [01:15] 标号的三大属性

标号一旦这样定义了，就具有三个属性。这样我就引出了属性的概念，才能讲属性表达式。

这个标号具有的属性：
1. **段地址属性**：该标号对应指令所在存储单元的 16 位段地址属性。这是第一个属性。
2. **段内偏移地址属性**：标号也具有该指令所在单元的 16 位段内偏移地址属性。这些概念我们名词都引出了，才能听懂。段内偏移地址属性，这也是 16 位的。
3. **类型属性**：类型的属性。

当然，标号所具有的这三个属性，我们在语句当中，都可以采用属性表达式的形式来获取它的属性。

#### [03:09] 属性操作符与属性表达式

要获取某个标号的段地址属性，采用的属性操作符是 `SEG`，就是 segment 的缩写。  
获取某个标号的段内偏移地址属性，属性操作符是 `OFFSET`。  
获取某个标号所对应的类型属性，是 `TYPE`。  
这是属性表达式当中的操作符。

常用的操作是获取某个标号的 `OFFSET`（段内偏移地址属性）。比如，我要获取 `NEXT` 的偏移地址：

```assembly
MOV BX, OFFSET NEXT
```

这里的 `OFFSET NEXT` 在这一条指令语句的源操作数项，这就叫属性表达式。

`NEXT` 的 `OFFSET` 属性是 `NEXT` 标号一旦定义了就具有的，所以这个属性表达式的值是一个常数，是 16 位的常数。因为段内偏移地址是 16 位的，因此，如果这一条指令语句写成：

```assembly
MOV BL, OFFSET NEXT
```

语法就错了。因为获取的偏移地址属性是 16 位的，而 `BL` 是 8 位寄存器，类型不一致。

如果要获取这个标号的段地址属性，显然就是写成 `SEG NEXT`。

#### [05:25] 标号的类型属性（NEAR 与 FAR）

来看类型。一个标号的类型有两种：
1. **NEAR 型（近型）**
2. **FAR 型（远型）**

什么意思呢？如果转移指令和转移目的地标号在同一个代码段（即 CS 段），那这个转移属于段内转移。段内转移属于近程转移（短程转移、近程）。对于近程转移，标号对应的类型属性，8086 汇编语言给它赋的值是 $-1$。

如果转移指令和转移目的地不在同一个代码段，这种转移称为段间转移，也称为远程转移（从一个代码段跳到另一个代码段去了）。段间的标号所具有的 `TYPE` 属性，8086 汇编语言赋给它的值是 $-2$。

那就是说，如果要取某个标号，比方说取 `TYPE NEXT` 这么一个表达式，就是取这个标号的类型属性。按照目前举的例子是段内转移，那么属性表达式经汇编程序一汇编，得出的值就是 $-1$。这是 8086 汇编语言的规定。但是在实际的 8086 汇编语言程序设计当中，获取某个标号的类型属性是没有意义的。获取一个标号的类型属性是没有意义的。这是标号。

现在我们来看变量，讲到教材第 28 页。

**二、变量及变量定义伪指令**（刚才讲的标号对应为“一、标号”）。

8086 汇编语言当中，变量定义伪指令如 28 页开头给出了五种变量定义伪指令：
* 用 `DB` 来定义字节型变量（即定义字节型数据）。数据放在变量对应单元，类似定义变量。用 `DB` 伪指令定义了这个单元，就定义了一个数据；再用 `MOV` 指令对这个单元重新写入新的数据，数据就变了，所以把它称为变量。
* 用 `DW` 来定义字型数据；
* 用 `DD` 来定义双字型数据（或者双字型变量）。

### [01:46] 变量的五大属性
变量一旦定义了，就具有了五大属性：

1. **段地址属性**：具有该变量对应单元的段地址属性。
2. **段内偏移地址属性**：具有该变量对应存储单元的段内偏移地址属性。段内偏移地址还称为段内什么呢？上节课讲的，段内**有效地址**。听懂了没有？即某变量对应单元的有效地址，会由 $EA$ 来描述。
3. **类型属性**：该变量是什么类型。用 `DB` 定义的变量，类型是字节型的。8086 汇编语言给字节型变量赋的类型值等于 1，也就是变量的类型其实是变量所占的字节数，听懂了没有？而用 `DW` 定义的变量是字变量，一个字占两个字节，所以字变量的类型等于 2。记着后面的 `TYPE` 操作符，字变量的类型等于 2。
4. **长度属性**：变量还具有长度属性。
5. **大小属性**：一旦变量定义了，还具有大小属性。

### [04:08] 属性操作符及其应用
在实际的汇编语言程序设计当中，在程序的语句当中，经常会出现的是类型属性和偏移地址属性。

* 取某变量所在单元的段地址属性，属性操作符是 **`SEG`**；
* 偏移地址属性在属性表达式中的操作符是 **`OFFSET`**；
* 类型的属性操作符是 **`TYPE`**；
* 长度属性表达式的操作符是 **`LENGTH`**；
* 大小属性操作符是 **`SIZE`**。

这就是操作符。

#### 示例 1：获取类型属性
```assembly
MOV AL, TYPE DATA1
```
`DATA1` 刚才已经定义了，`DATA1` 是用 `DB` 定义的字节型变量，它的类型就是字节型，值为 1。所以在汇编程序汇编时，把这个属性表达式的值用 1 代替了，那这条指令就等效于：
```assembly
MOV AL, 1
```
等效于 `MOV AL, 1` 来汇编。

### [05:56] 偏移地址与地址寄存器间接寻址
如果要获取 `DATA1` 的偏移地址，就可以写：
```assembly
MOV BX, OFFSET DATA1
```
把 `DATA1` 这个变量所对应存储单元的 16 位段内偏移地址，用 `MOV` 指令传送给 `BX`。那我要寻找 `DATA1` 单元，是不是就可以用 `BX` 间接寻址？听懂了没有？

当然，获取某变量对应单元的偏移地址，肯定要送给一个 16 位寄存器。在实际程序设计当中，这个 16 位寄存器最好选**地址寄存器**。

能间接寻址的地址寄存器有哪些呢？
* `BX`、`BP`：两个基址寄存器；
* `SI`、`DI`：两个变址寄存器。

听懂了没有？

当然你说写：
```assembly
MOV AX, OFFSET DATA1
```
把 `DATA1` 变量具有的 16 位段内偏移地址值获取给 `AX`，这种指令语句的语法是对的，但是我认为没有意义，理解了没有？你获取这个变量对应单元的偏移地址给某个寄存器的目的，是为了后续间接寻址来用；而 `AX` 不是地址寄存器（不能用于寻址），把它获取给 `AX` 有意义吗？没有意义。这是这一点。
