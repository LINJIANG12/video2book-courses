#### 1. 堆栈段（Stack Segment）
若系统涉及中断调用、子程序调用或现场压栈，必须开辟堆栈段：

- **关键属性**：组合类型必须明确指定为 `stack`，以便链接程序将其识别为系统堆栈段。
- **空间定义**：讲师指出大小视具体需求而定，未给出固定硬编码长度。

#### 2. 数据段（Data Segment）与内存变量规划
```assembly
data segment
    inbuff  db 100 dup(?)
    inpoint dw ?
    in_imr  db ?
data ends
```

讲师板书推导并明确了三个核心变量的工程意义与边界条件：

1. **`inbuff`（输入数据缓冲区）**：
   - **定义**：`db 100 dup(?)`，分配连续 100 个未初始化的字节单元。
   - **作用**：外部设备每次产生中断并读入一个数据时，按序存储到 `inbuff` 中。
   - **边界假设**：假定单次通信/任务中系统总输入数据量不超过 100 个字节，未读满 100 个数据前通常由用户敲击“回车”（Enter）或产生特定结束信号提前终止。

2. **`inpoint`（缓冲区写入地址指针）**：
   - **定义**：`dw ?`，分配 16 位字单元。
   - **作用**：存放 `inbuff` 当前待写入单元的**偏移地址指针**。
   - **运行机制**：每次将中断接收的数据写入缓冲区之前，必须首先从 `inpoint` 单元取出目标写入地址，再实施寻址存储。

3. **`in_imr`（8259A 中断屏蔽字暂存单元）**：
   - **定义**：`db ?`，分配 8 位字节单元。
   - **原理推导与演进背景**：
     - PC 机主板在启动时，BIOS 已经对主片 8259A（中断控制器）完成初始化，其内部的 **IMR（Interrupt Mask Register，中断屏蔽寄存器）** 拥有特定的屏蔽位设置。
     - 当前应用为了开启或关闭特定中断源，需要修改 IMR。
     - **工程规范**：不能盲目全盘覆写。必须先将 BIOS 设置的原中断屏蔽字通过端口读出并暂存到 `in_imr` 中；随后向 `OCW1` 写入修改后的新屏蔽字；在程序退出/应用结束后，必须重新读取 `in_imr` 并写回 `OCW1`，以恢复系统的初始状态。

### 三、 8259A 中断类型号确定与中断向量表（IVT）数学寻址推导

#### 1. 中断类型号推导逻辑
讲师提问如何确定硬件中断类型号（题目指定分配给该外设）：
- PC 机主片 8259A 的中断类型号基值（Base）固定为 `08H`。
- 各 IRQ 引脚映射逻辑：
  - $\text{IRQ0} = 08\text{H}$
  - $\text{IRQ1} = 09\text{H}$
  - $\text{IRQ2} = 0\text{AH}$
  - $\text{IRQ3} = 0\text{BH}$
- 本例中涉及的中断请求类型号为 **`0BH`**。

#### 2. 中断向量表（IVT）寻址原理
- 8086 系统的中断向量表驻留在内存物理地址的最底端 `00000H ~ 003FFH`（共 1024 字节，对应 256 个中断向量）。
- 每个中断向量占用 **4 个字节**（2 字节偏移量 `IP`，2 字节段基址 `CS`）。
- **数学映射公式**：
  $$\text{Vector Offset} = 4 \times n$$
  对于类型号 $n = 0\text{BH}$：
  $$\text{Vector Offset} = 4 \times 0\text{BH}$$

### 四、 中断向量装载前的现场保护与指针切换（讲师板书实录）

讲师在黑板右侧接续代码段初始化：

```assembly
    push ds
    mov ax, 0
    mov ds, ax
    mov bx, 4 * 0Bh
    mov ...
```

#### 推导逻辑与操作步骤剖析：

1. **保护当前数据段：`push ds`**
   - 此时 `DS` 存放的是用户数据段 `data` 的段基址。装载中断向量必须将 `DS` 指向中断向量表所在的段（`0000H`），因此必须先将原 `DS` 压入堆栈保护。

2. **定位中断向量表所在段：`mov ax, 0` $\rightarrow$ `mov ds, ax`**
   - 中断向量表位于内存物理基址 `0000:0000H`。使 `DS = 0`，则后续所有基于数据段的偏移寻址将直接映射到中断向量表。

3. **寄存器选型纠偏与偏移计算：`mov bx, 4 * 0Bh`**
   - 讲师在板书初期尝试考虑 `AX`，随后指出在 8086 指令集中，**`AX` 无法直接用作寄存器间接寻址**（8086 间接寻址寄存器仅支持 `BX`、`BP`、`SI`、`DI`）。
   - 为后续能够使用形如 `[bx]` 的方式向中断向量表写入中断服务程序的入口地址，必须采用基址寄存器 **`BX`** 来存放偏移量 $4 \times 0\text{BH}$。

## 反模式与踩坑清单

1. **反模式：硬编码覆写 8259A 的 IMR 寄存器**
   - **错误行为**：在需要开启某中断时，直接向 OCW1 写入一个字/字节，覆盖其他不相关的位。
   - **后果**：破坏了操作系统或 BIOS 对其他硬件中断（如时钟中断、键盘中断等）的原有屏蔽配置。
   - **标准防御方案**：预先定义 `in_imr db ?`，先读取当前 IMR 暂存，针对目标位修改后再写回；程序退出时，将暂存的 `in_imr` 再次送回 OCW1 进行硬件状态还原。

2. **反模式：修改段寄存器 DS 前未进行现场保护**
   - **错误行为**：直接执行 `mov ax, 0`、`mov ds, ax`，未保存先前的 `DS`。
   - **后果**：一旦 `DS` 被置零以操作中断向量表，后续若程序需重新访问用户数据段中的变量（如 `inbuff`、`inpoint`、`in_imr` 等），将发生寻址错乱。
   - **标准防御方案**：切换至 0000H 段前执行 `push ds`。

3. **反模式：试图使用 AX 进行间接寻址**
   - **错误行为**：书写类似 `mov [ax], offset ...`。
   - **后果**：语法编译错误。8086 架构中 AX 属于通用数据寄存器，不支持外括括号的基址寻址。
   - **标准防御方案**：选用 `BX` 存放偏移量（`mov bx, 4 * 0Bh`）。

## 第一章 核心原理深度推导与代码逻辑还原

### 1.1 直接内存寻址法建立中断向量表（黑板推导方案）

在实模式 x86 体系结构中，中断向量表（IVT）位于内存最低端。针对中断类型号 $n$，其向量在内存中的绝对物理地址映射关系具有严格的数学确定性：

$$\text{Offset Address} = 4 \times n$$
$$\text{Segment Address} = 4 \times n + 2$$

#### 板书推导与指令序列
讲师给出的底层直接写入推导流程如下：

1. **入口偏移地址提取与写入：**
   若中断服务程序入口标号为 `ABC`（或任意符号入口名）：
   ```assembly
   MOV AX, OFFSET <ISR_ENTRY> ; 提取中断服务程序入口的偏移地址（有效地址）
   MOV [BX], AX               ; 写入 4*n 地址单元（设 BX 已预置为 4*n）
   ```
2. **入口段地址提取与写入：**
   ```assembly
   MOV AX, SEG <ISR_ENTRY>    ; 提取中断服务程序入口的段地址
   MOV [BX+2], AX             ; 写入 4*n+2 地址单元
   ```

#### 临界区边界条件与防护推导
讲师特别指出：在直接构建向量表之前与之后，存在严格的指令时序与系统状态保护约束：
* **前置条件（关中断）：**
  在向 $4 \times n$ 和 $4 \times n + 2$ 写入数据前，必须执行 `CLI`。
  * *原因推导*：向量表写入需要多条指令周期。如果在写入了偏移地址但尚未写入段地址的半就绪状态下突发中断，CPU 将依据半残废的向量跳转，引发不可预测的崩溃（跑飞）。因此，在向量表未彻底建立完成之前，绝对不允许响应中断。
* **后置现场恢复与开中断：**
  向量表写入完成后，需要执行栈操作恢复原有的数据段寄存器，并重新放行中断：
  ```assembly
  POP DS                      ; 恢复原有 DS 指向（重新指向 DATA 段）
  STI                         ; 开中断，允许 CPU 响应外部中断
  ```

### 1.2 DOS 功能调用法建立中断向量（教材规范方案）

与直接写物理内存不同，教材前五行代码采用了向 DOS 操作系统请求服务的方式挂载中断向量。

#### 接口规范与参数装配逻辑
教材使用的是 DOS `25H` 号功能调用（设置中断向量）：
* **功能号与类型号绑定：**
  * `AH`：功能号 $25\text{H}$。
  * `AL`：中断类型号。在具体实验工程中，IR3 引脚对应的中断类型号为 $0\text{BH}$。
  * 讲师展示的合成装载指令：
    ```assembly
    MOV AX, 250BH            ; 高字节 AH=25H，低字节 AL=0BH
    ```
* **入口地址指针装配：**
  设教材中定义的中断服务程序入口标号为 `IN-INT`（或 `IN_INT`）：
  * 段地址传递：
    ```assembly
    MOV AX, SEG IN-INT       ; 提取入口段地址
    MOV DS, AX               ; 赋给段寄存器 DS
    ```
  * 偏移地址传递：
    ```assembly
    ; 讲师口述事实：把中断服务程序入口地址的偏移地址赋给 BX
    ; （注：MS-DOS 标准 25H 调用通常采用 DX 寄存器，此处忠实记录讲师口述为 BX）
    ```

  ```assembly
  INT 21H                    ; 执行 DOS 功能调用，建立中断向量
  ```
* **后续数据段重定：**
  DOS 功能调用修改了 `DS`，因此教材在调用完毕后的第 6 行重新对数据段进行初始化：
  ```assembly
  MOV AX, DATA
  MOV DS, AX                 ; 将 DS 重新对齐至程序数据段
  ```

### 1.3 变量固有属性与指针立即数初始化

讲师针对教材中数据缓冲指针的建立语句展开了寻址机制剖析：

```assembly
MOV IN_POINT, OFFSET IN_BUFF
```

#### 汇编机理推导
1. **变量的固有属性：**
   在汇编源程序中，变量（如 `IN_BUFF`）一旦经由伪指令定义，即在符号表中内生具备**五个属性**（讲师强调此处包含段属性、偏移属性等）。
2. **立即数本质：**
   操作符 `OFFSET IN_BUFF` 并非在程序运行时去动态寻址，而是在汇编链接阶段直接计算出来的固定常数。
3. **寻址方式认定：**
   源操作数 `OFFSET IN_BUFF` 属于固有常数，因而该操作属于**立即数寻址**。
4. **运行结果：**
   该指令将缓冲区 `IN_BUFF` 的首地址常数（偏移量）直接存入 `IN_POINT` 所在的字存储单元，完成了指针变量的初值装载。

### 1.4 主片 8259A 中断屏蔽寄存器（IMR / OCW1）动态配置

针对外部中断引脚 IR3 的开放，讲师解析了底层硬件端口与操作命令字（OCW1）的位操作逻辑。

#### 1. 硬件端口与 BIOS 状态继承推导
* **端口选通：** 主片 8259A 芯片中，$A_0 = 1$ 的端口物理地址对应为 `21H`。
* **状态读取：** 执行 `IN AL, 21H` 读取的是 8259A 内部的 **IMR（Interrupt Mask Register，中断屏蔽寄存器）**，亦即操作命令字 **OCW1**。
* **免除冗余初始化（ICW1~ICW4）的充分性：**
  硬件工程中无需重新配置 8259A 的初始化命令字（ICW1 到 ICW4）。原因在于：微机冷启动时，**主板 BIOS 已经完成了对主片 8259A 的 ICW 序列初始化**。用户程序仅需在当前运行环境的基础上，针对 OCW1 进行局部动态位屏蔽即可。

#### 2. 现场保护逻辑
由于 BIOS 初始化的当前 IMR 状态未知（各个外部设备的中断通道处于何种屏蔽状态无法预知），严禁直接盲写覆盖：
```assembly
IN AL, 21H                  ; 读取当前主片 8259A 的 IMR 状态
MOV IN_IMR, AL              ; 将原 IMR 状态保存入内存单元 IN_IMR，保护原系统现场
```

#### 3. 目标通道（IR3）解屏蔽的数学逻辑推导
* **位映射关系：**
  $AL$ 寄存器的 8 个二进制位 $D_0 \sim D_7$ 严格对应外部中断引脚 $\text{IR0} \sim \text{IR7}$：
  * 位取值 $1$：表示该中断通道被**屏蔽（Masked）**。
  * 位取值 $0$：表示该中断通道**未屏蔽 / 允许响应（Unmasked）**。
* **目标操作：**
  系统需要启用 $\text{IR3}$ 通道，对应必须将 $D_3$ 位强行清零（$D_3 \to 0$），同时要求**其余所有位（$D_0, D_1, D_2, D_4, D_5, D_6, D_7$）状态维持原样不变**。
* **掩模推导与位与运算：**
  * 保持位需与 $1$ 进行“逻辑与”；
  * 清零位需与 $0$ 进行“逻辑与”。
  * 故生成掩码为：

    $$\text{Mask} = 1111\,0111_B = \text{F7H}$$

  * 板书汇编实现：
    ```assembly
    AND AL, 0F7H            ; 讲师板书：AND AL, F7H。实现 D3 位置 0，其余位严格保留
    ```

## 第三章 反模式与踩坑清单

在编写中断配置程序时，讲师重点揭示并纠正了以下几个工程反模式：

### 1. 向量构建期间未关闭外部中断（裸写 IVT 反模式）
* **反模式表现：** 在没有调用 `CLI` 关中断的情况下，直接执行对 $4 \times n$ 和 $4 \times n + 2$ 单元的赋值操作。
* **崩溃机理：** 写入双字向量需要多个指令周期。若在刚写入偏移量、尚未写入段地址的瞬间触发外部中断，CPU 硬件中断响应机制会立刻从向量表中读取未拼接完成的非法地址，导致程序跑飞或死机。
* **防御方案：** 向量表建立前必须执行 `CLI` 屏蔽可屏蔽中断；在向量构建完成、段寄存器恢复完毕后方可执行 `STI`。

### 2. 盲写 8259A 屏蔽字（破坏系统现场反模式）
* **反模式表现：** 未执行 `IN AL, 21H`，直接给 `AL` 赋予某固定数值并输出到 `21H` 端口。
* **崩溃机理：** 系统主板上有多个设备依附于 8259A 的不同通道（如定时器、键盘等）。开机后 BIOS 及操作系统已配置好其他外设的掩码状态。盲写固定常数会破坏其他正常设备的中断使能，引发外设失效。
* **防御方案：** 必须遵循 **“读出原值 $\to$ 内存暂存备份（`MOV IN_IMR, AL`）$\to$ 针对目标位单独进行掩码运算 $\to$ 回写”** 的标准化现场保护流程。

### 3. 位逻辑掩码错误导致其他中断通道被误开/误关
* **反模式表现：** 试图通过 `MOV AL, 08H` 或非位与逻辑直接设置，亦或混淆了高低有效电平。
* **逻辑机理：** 8259A IMR 逻辑为：**0 为允许，1 为屏蔽**。开启通道需强制置 0，而非置 1。
* **防御方案：** 采用按位与（`AND`）运算配合“目标位为 0、非目标位为 1”的掩模字（开启 IR3 使用 `0F7H` 即 $11110111_B$），严禁使用赋值语句覆盖其他通道。

### 4. 易混淆的系统调用寄存器传参
* **反模式表现：** 考场或实战中遗忘 DOS 25H 调用的参数约束，造成寄存器错位。
* **防御方案：** 牢记 `AH` 存功能号（$25\text{H}$），`AL` 存类型号（如 $0\text{BH}$），可通过 `MOV AX, 250BH` 合并装载。牢记段地址借用 `DS` 传递，故调用完毕后必须立刻重新对齐数据段 `DS`。
