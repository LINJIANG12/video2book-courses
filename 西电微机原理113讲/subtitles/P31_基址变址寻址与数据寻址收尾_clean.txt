### 寄存器相对寻址的应用与注意事项

[00:11]
以 BP 相对寻址，以 BX 相对，相当于寄存器加了个量。相对量是一个常数，段地址默认在 SS；如果相对量是一个变量，那段地址是看变量在哪定义的了，段地址就是哪个段的段地址。

在这里面我举个例子，大家思考一下。

**例：**  
把前面讲的知识稍微做一点综合，动动脑筋。  
比如说我现在让 CPU 8086 执行以下程序，什么程序呢？

```assembly
PUSH AX
PUSH BX
PUSH CX
```

对栈操作必须按字操作，把 AX 的内容压栈。PUSH BX，PUSH CX，执行了三条指令。

现在我叫你干什么呢？叫你：将压入堆栈的 AX 内容给它取出来放到 DX 之中，但不能破坏堆栈指针（不能破坏 SP 指针）。

你先想一下这题怎么做。

[02:08]
我们解一下题。CPU 执行，这是堆栈，假如这是堆栈。堆栈指针最初指到这儿，假如说 SP 的值指到了栈底加一单元了。  
PUSH AX，SP 是不是减 2？SP 减 2，栈顶是不是指到这儿来了？然后把 AX 的内容压到这个字单元来了，AL 在这，AH 在这。好，一条 PUSH 指令执行完了。  
再执行第二条 PUSH BX，SP 又减 2，SP 再减 2，SP 指针指到栈顶，栈顶跑到这儿来了，然后把 BX 的内容压栈。  
然后 CPU 再执行 PUSH CX，SP 又减 2，栈顶指到这个字单元了。在这个栈顶字单元放的是不是 CX 的内容？好，栈顶跑到这了。

现在我让你把压到栈底边的 AX 内容，把这个内容要读出来给 DX，但不能破坏 SP 指针。  
你不能 POP，POP 是一下子 SP 指针就破坏了，跑到这儿了。那意思上是不是不能 POP 了？你一 POP，SP 指针是不是破坏了？是不是这样子？  
那不能 POP 了，你还要把压到栈底的 AX 值读出来给 DX，怎么弄？

[04:00]
要充分地利用 BP 相对寻址默认在 SS 段操作的最基本原理来做这个题，是不是这样子？  
如果我做：

```assembly
MOV BP, SP
```

行不行？我把 SP 指针 16 位值传送到 BP，寄存器间接寻址，寄存器寻址。但是你这样做，BP 也破坏了。题目没说能不能破坏 BP，我假设能破坏。如果 BP 也不能破坏呢，这地方是不是先要加一条 `PUSH BP`，压栈保护起来，然后才能弄。

然后这样一做，你想，SP 的内容传送给 BP，也是一个意思，BP 的 16 位值也指向了栈顶了。  
现在我要把 AX 内容取出来给 DX，那现在是以 BP 栈顶相对，向上位移 2、位移 4。寄存器相对寻址，是不是找到这个单元了？

```assembly
MOV DX, [BP+4]
```

然后把这个单元的内容读出来给 DX，DX 的值是不是等于 AX？但是栈顶破坏了吗？没有。

在 8086 指令系统当中，为什么在寄存器相对寻址当中设计 BP 相对时要默认在 SS 段的最基本原理呢？就是为了做这件事情。  
我有的时候在堆栈中要取数据或者放数据，但我还不想破坏 SP 指针，所以要用 BP 相对了。这是这一点。

当然，在实际的程序设计当中，你也可以在这种寻址方式的左边，或者基础寻址方式的左边，可以通过增加段超越前缀来改变操作数所在的段。听懂了没有？这前面我们讲过。  
这是寄存器相对寻址大家要掌握的。

当然，当寄存器相对寻址做目的操作数时，源操作数又用了立即寻址，在这样的场合要注意什么问题呢？类型要明确。是不是和寄存器间接寻址一样？

### 基址变址寻址

[06:53]
下面我们来看存储器寻址的第四种，叫**基址变址寻址**。

基址变址寻址的意思就是说：你要寻找的操作数仍然在存储器某单元当中，操作数所在的存储器那个某单元的段内 16 位有效地址由两部分构成：
- 一部分在某一个基址寄存器当中（BX 或 BP 中）；
- 另一部分在一个变址寄存器当中（SI 或 DI 中）。

两部分之和是操作数所在单元的段内有效地址。

而段地址以基址寄存器为准来默认：
- 如果基址寄存器用的是 BX，段地址默认在 DS；
- 如果基址寄存器用的是 BP，段地址默认在 SS，在 SS 中就是在堆栈段操作。

只看基址寄存器，不看变址。

刚才在寄存器相对寻址当中，相对量是变量时，段地址的确认，变量的优先权要比寄存器要高，以变量为准来确认；那么在基址变址寻址当中，段地址的确认以基址寄存器为准来确定。

[08:41]
我们来看，举个例子。我们仍然有刚才定义的变量，比如说有定义的 DATA1 变量，DB 定义的 12H；DATA2 变量，DB 定义的 34H。这是在数据段做的变量定义：

```assembly
DATA1 DB 12H
DATA2 DB 34H
```

那么汇编后，在存储器中数据的分配示意图是这样：这是 DATA1 单元，数据是 12H；下个单元是 DATA2 单元，数据是 34H。下面还有单元、还有单元，很多怎么定义的现在不管它。

现在我们想把这个单元的数据取出来给 AL，叫你用基址变址寻址来取。那显然发报是这样子：

```assembly
MOV BX, OFFSET DATA1
```

让 BX 的内容是不是指向了……

### [00:00] 字符串操作指令与隐含寻址

8086 的字符串操作指令当中，所有字符串操作指令的源操作数和目的操作数，均采用的是隐含寻址。

像我下边举的例子：
```assembly
MOVSB
MOVSW
```
后边我是没有写操作数的，但是 CPU 执行这样的字符串传送指令时，它知道源串在什么地方，知道目的串在什么地方。这种源和目的的寻址方式，都是隐含寻址。

### [00:32] 指令语句中变量运算的语法限制

今天讲到最后，再给一个概念。比如说有这样的操作：
```assembly
MOV AL, data1
```
这个刚才举过了，是直接寻址。`data1` 是由 `DB` 定义的字节变量，把这个字节变量对应字节单元的数据都送给 `AL`。

若后边加一个 1、加一个 2 常数（例如 `data1 + 1`），它依然是直接寻址。但如果后边加的是 `data2`：
这里加的不是常数，而是一个变量。这样的指令就会出现语法错误。

也就是说，在指令语句当中，操作数项不允许变量在这里进行运算，这是 8086 汇编语言的语法规定：**变量不能在指令语句中运算**。当然，变量在 `DW` 这类的伪指令语句当中可以用加法运算。至于具体怎么使用，我们后边讲到应用时再说。
