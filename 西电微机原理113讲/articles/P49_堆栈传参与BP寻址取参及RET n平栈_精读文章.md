# 堆栈传参与BP寻址取参及RET n平栈

寄存器传参讲完了，用 `CX` 传个数、`SI` 传首址，简单是简单，可寄存器就那么几个，参数一多就不够用了。这节我们换一种：把缓冲区首址和字符个数压到堆栈里带进去。压进去容易，难的是在子程序里怎么取出来还不把栈搞乱。

## 主程序压栈传参与CALL执行

把缓冲区首址压入堆栈，告诉子程序：“缓冲区首址在这，你去取。”个数也一样压进去。此时 `SP` 指在栈顶。然后执行 `CALL`。

`CPU` 执行 `CALL` 时，先保护返回地址 `IP`：`SP` 减 2，栈顶移到新位置，把下一条指令的偏移地址也就是返回地址压栈。然后流程转到子程序里去。

$$SP \leftarrow SP - 2$$

## 子程序现场保护

进入子程序，先连续压栈保护现场：

```assembly
PUSH AX
PUSH BX
PUSH CX
PUSH SI
```

第一次保 `AX`，第二次保 `BX`，第三次保 `CX`，第四次保 `SI`。`SP` 一路下移，指到当前位置。

## 为什么不能用POP取参

现场保护完了，子程序要干活：统计指定字节有几个 `1`，判断偶奇，配偶校验。要干活就得拿到两个参数：待校验缓冲区的首地址，待校验字符的个数。它们都在堆栈里。

核心问题来了：怎么取？

不能用 `POP` 弹。为什么？`RET` 返回时，`SP` 必须指在保存返回地址 `IP` 的位置，才能弹给 `IP`。你提前 `POP` 把参数弹走了，`SP` 就错位了，`RET` 就回不去了。所以，堆栈传参绝不能用出栈指令取参。

## 引入BP与MOV BP SP

为了解决这个问题，引入基址指针寄存器 `BP`：

```assembly
PUSH BP
MOV  BP, SP
```

子程序里要用 `BP`，不管主程序用没用过，先 `PUSH BP` 保护原值，`SP` 减 2。再执行 `MOV BP, SP`，寄存器寻址，把 `SP` 当前值送给 `BP`。`BP` 就指向了存放原 `BP` 值的那个字单元。

> **定义**：以 `BP` 作基址相对寻址时，默认段寄存器是堆栈段 `SS`。这一点是后面算偏移的依据。

## BP相对寻址提取参数

既不破坏 `SP`，又能拿到参数，靠的就是 `BP` 加位移。堆栈从上往下的布局是这样的：

| 偏移地址 | 存放内容 |
| :--- | :--- |
| `[BP+0EH]` | 字符个数 |
| `[BP+0CH]` | 缓冲区首址 |
| `[BP+0AH]` | 返回地址 `IP` |
| `[BP+08H]` | 保护的 `AX` |
| `[BP+06H]` | 保护的 `BX` |
| `[BP+04H]` | 保护的 `CX` |
| `[BP+02H]` | 保护的 `SI` |
| `[BP+00H]` | 保护的 `BP`，`BP`、`SP` 当前指向处 |

所以取参就两条：

```assembly
MOV SI, [BP+0CH] ; 从堆栈段取出首址给SI
MOV CX, [BP+0EH] ; 从堆栈段取出个数给CX
```

看到了没有？充分利用 `BP` 相对寻址、段地址默认在 `SS`，在子程序开头就把主程序 `CALL` 之前压进去的参数拿到了，`SP` 一动没动。

## 嵌套COUNT_BYTE与寄存器带回

参数拿到，继续往下，调嵌套子程序。教材例 4.9 第 118 页调的 `COUNT_BYTE` 在 120 页，逻辑是：进子程序保护现场，置循环计数 `CX=8`，累加器 `BL` 清零，`AL` 循环移位逐位判断是 `1` 还是 `0` 累到 `BL`，`LOOP` 8 次后 `RET`。结果在 `BL` 里，用通用寄存器 `BL` 把结果带回来。不用 `BL`，用堆栈带回也行，两者皆可。

## 现场恢复与RET返回

快返回了，必须按压栈相反的顺序恢复：

```assembly
POP BP
POP SI
POP CX
POP BX
POP AX
RET
```

`POP BP` 弹给 `BP`，`SP` 加 2，再依次 `POP SI`、`CX`、`BX`、`AX`。弹完 `POP AX`，`SP` 正好回到返回地址 `IP` 处。

> **提示**：往年总有人问，`POP AX` 把栈单元的值送 `AX`，原来单元里的值跑哪去了？物理上还在，只是 `SP` 移走了，那个单元退出了有效栈区，后面压栈直接覆盖旧数据。

此时执行 `RET`，从栈顶弹出返回地址给 `IP`，回到主程序断点。

```text
调用前SP -> [参数个数][首址]
CALL后   -> [参数个数][首址][IP]
保护后   -> [参数个数][首址][IP][AX][BX][CX][SI][BP] <- SP/BP
取参      BP+0CH / BP+0EH (SP不动)
恢复后SP -> [参数个数][首址][IP] <- SP指IP
RET      -> [参数个数][首址]      SP+2
```

## 带参数返回RET 4平栈

问题就出来了。`CPU` 执行 `RET`，把 `SP` 指的栈顶弹一个字给 `IP`，`IP` 回主程序了，`SP` 增 2：

$$SP \leftarrow SP + 2$$

程序看似结束了，`SP` 恢复了没有？没有。因为调用前执行了两次 `PUSH`，`PUSH`、`POP` 该配对，可这里 `POP` 已经没意义了，参数不需要恢复给谁。

哪怕程序结束了，下面还有人用堆栈呢？每次用完 `SP` 都偏 4 个字节，累积下去总有一次溢出，显然不行。必须让 `SP` 回到最初位置。

既然 `POP` 没意义，又必须恢复，直接对 `SP` 修正就行：

```assembly
RET 4
```

`CPU` 执行 `RET 4`：先从栈顶弹一个字给 `IP` 实现返回，本身 `SP` 增 2，在此基础上硬件自动再加 4，丢掉 4 字节参数：

$$SP \leftarrow SP + 2 + 4$$

在增 2 的基础上再增 4，`SP` 就回到调用前了，这就叫堆栈平衡。
