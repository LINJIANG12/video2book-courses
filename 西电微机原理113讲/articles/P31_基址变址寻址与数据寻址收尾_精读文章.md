# 基址变址寻址与数据寻址收尾

我上次把寄存器相对寻址的概念立住了，今天先把`BP`相对那个最有用的例子做掉，然后把存储器寻址的后两种和数据寻址的收尾一次讲完。

## 用BP相对取栈中数据而不破坏SP

相对量是常数，段看寄存器；相对量是变量，段看变量在哪定义。这个结论先留着，我举个综合题让你们体会`BP`相对为什么默认`SS`。

让`8086`执行：

```assembly
PUSH AX
PUSH BX
PUSH CX
```

栈操作必须按字操作。`PUSH AX`就是`SP`减`2`，栈顶指到新字单元，把`AX`压进去，`AL`在低、`AH`在高。第二条`PUSH BX`，`SP`再减`2`，把`BX`压进去。第三条`PUSH CX`，`SP`再减`2`，栈顶跑到放`CX`的那个字单元。

现在叫你们干什么。把压在最底下那个`AX`的内容取出来放进`DX`，但不能破坏堆栈指针`SP`。

你们先想。能不能`POP`。一`POP`，`SP`就跑了，破坏了，所以不能`POP`。不用`POP`还想把栈底的值读出来，怎么弄。就要用`BP`相对默认`SS`的原理。

我做：

```assembly
PUSH BP
MOV BP, SP
MOV DX, [BP+4]
```

`MOV BP, SP`是寄存器寻址，把`SP`的`16`位值送`BP`，`BP`也指向栈顶了。但这样`BP`破坏了，题目没说能不能破坏`BP`，我假设能破坏；如果`BP`也不能破坏，前面先加一条`PUSH BP`保护起来。

现在以`BP`指的栈顶为基准，向上`+2`、`+4`，`[BP+4]`用寄存器相对寻址正好找到放`AX`的那个字单元。读出来给`DX`，`DX`就等于`AX`，`SP`一点没动。

我为什么说`BP`相对默认`SS`就是为了干这个。有些时候我想从堆栈里取数放数，又不想破坏`SP`，就用`BP`相对。当然实际编程时，也可以在这种寻址左边加段超越前缀去改段，前面讲过。

> **易错点**：寄存器相对做目的、源用立即数时，和间接寻址一样，类型必须明确。

## 基址变址寻址的地址算法

下面看存储器寻址第四种：基址变址寻址（`Based Indexed Addressing`）。

> **定义**：操作数还在某存储器单元里，该单元的段内`16`位有效地址由两部分相加：一部分在基址寄存器`BX`或`BP`里，另一部分在变址寄存器`SI`或`DI`里。

```text
EA = (BX/BP) + (SI/DI)
```

读图说明：基址出一份，变址出一份，相加才是有效地址。

段地址以基址为准，只看基址不看变址：基址用`BX`默认`DS`，基址用`BP`默认`SS`就是堆栈段操作。前面相对寻址里变量优先于寄存器，这里是基址优先，都要分清。

还是这组定义：

```assembly
DATA1 DB 12H
DATA2 DB 34H
```

内存里`DATA1`单元`12H`，下一个`DATA2`单元`34H`，下面还有很多单元不管。我想用基址变址把某个单元取出来给`AL`，先：

```assembly
MOV BX, OFFSET DATA1
```

让`BX`指向基点，再配上`SI`或`DI`的偏量，组合成`[BX+SI]`、`[BX+DI]`、`[BP+SI]`、`[BP+DI]`四种形式。段按基址定，类型看另一方是字节还是字。这就是基址变址的用法，后面做数组、做表格经常用它。

## 字符串操作数的隐含寻址

`8086`的字符串操作指令，源和目的全是隐含寻址（`Implied Addressing`）。比如：

```assembly
MOVSB
MOVSW
```

后面我没写操作数，但`CPU`执行这种串传送知道源串在哪、目的串在哪。源和目的的寻址方式都是隐含寻址，听懂了没有。

## 指令语句中变量不能运算

最后给个概念。比如：

```assembly
MOV AL, DATA1
```

`DATA1`是`DB`字节变量，把对应字节单元的数据送`AL`，字节传送，这是直接寻址。后面加个常数也行：

```assembly
MOV AL, DATA1+1
```

加`1`加`2`常数，还是直接寻址。但后面如果加个变量就不行：

```assembly
MOV AL, DATA1+DATA2
```

加的不是常数是变量，这条出现语法错误。`8086`汇编语法规定的：操作数项不允许变量在指令语句中运算。当然变量在`DW`这类伪指令语句里可以用加法，后面讲应用再说。

这样关于数据的八种寻址方式全部讲完了。难理解难掌握的正是关于存储器的五种，可程序设计天天用它，下去必须熟练复习掌握。
