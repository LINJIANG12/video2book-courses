# 标志操作与空操作NOP及延时子程序

`CLD` 让 `DF` 置 0，`STI` 让 `IF` 置 1、`CPU` 开中断，都讲过了，不讲了。今天补一个 `I/O` 里天天见的：空操作 `NOP`。`I/O` 慢、`CPU` 快，`IN`、`OUT` 之间经常要等一下，靠的就是它。

## NOP执行时间特性

`NOP` 空操作指令。`CPU` 执行什么都没做，但花了时间。指令上花了一个总线周期，可 `NOP` 的总线周期只有 3 个 `T` 状态，3 个时钟，`T` 听到这能懂了吧？

`I/O` 驱动里经常要延时。延时短，排几条 `NOP`：

```assembly
NOP
NOP
NOP  ; 短延时，拖几个时钟
```

时间长不能排一堆 `NOP`，程序没法看了，得编延时程序。经常要延时，最好编成子程序，要用 `CALL` 调。每次延时不一样，`CALL` 之前设好入口参数，靠参数调时间。延时功能那段到底怎么编？你们先自己想想。

```text
CPU快 ----NOP(3T)----NOP(3T)---- > I/O慢设备跟上
短延时 : 数条NOP
长延时 : 延时子程序 + 入口参数调时间
```

> **提示**：`NOP` 只占时间不干活，正好给慢速 `I/O` 留建立保持时间。短则 inline，长则子程序化，入口参数控制循环次数。
