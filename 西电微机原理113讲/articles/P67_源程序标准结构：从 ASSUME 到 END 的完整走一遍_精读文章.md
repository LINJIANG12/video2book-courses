# 源程序标准结构：从 ASSUME 到 END 的完整走一遍

呃，上一节课我们讲第四章 4.1 节汇编语言程序设计基础，从这一节里引出了汇编语言程序的标准结构。我们再复习一下，把这个完整结构从头到尾走一遍。

## 1 数据段：缺省三项，DB DW 照题目摆数据

题目功能里如果涉及到某些数据，数据要定义在数据段。段的定义都是用 `SEGMENT` 伪指令开始定义的。你看，在这个段定义的 `SEGMENT` 伪指令右边，我定位类型缺省了，组合类型也缺省了（本段和其他段都没有关系），类别也缺省了。

```assembly
DATA  SEGMENT
      VAR1  DB  10H
      VAR2  DW  ?
      X_byte  LABEL  BYTE
      X_word  DW  1234H
DATA  ENDS
```

在这个数据段里，根据题目要求用 `DB` 或者 `DW` 定义你的数据，给存储器分配，也就是变量定义。假如 `DB` 定义了个 `VAR1` 变量，这个单元放了 `10H`；假如 `DW` 定义了个 `VAR2` 变量，保留到这；又假如用 `DW` 定义了个变量名叫 `X_word` 的字变量，这个单元定义成 `1234H`。放到这，后边我们再看。数据段定义完了，`ENDS DATA`，你看我这地方空了一行，后边有用。

## 2 ASSUME：只告诉汇编程序，不初始化寄存器

现在我们定义代码段，在代码段编题目完成功能的程序。段名叫 `CODE`。在代码段一开始，要用段寻址伪指令告诉汇编程序，前面用 `SEGMENT` 定义的这些段名，具体哪个段和哪个段寄存器建立关系：

```assembly
CODE  SEGMENT
      ASSUME  CS:CODE, DS:DATA, ES:DATA, SS:STACK
```

比如 `CODE` 段和 `CS` 寄存器建立关系，`DS:DATA` 告诉汇编程序 `DS` 段是 `DATA` 段名指的段，`ES:DATA` 告诉汇编程序 `DATA` 段名指的段也是 `ES` 段，意味着下方程序使用时，数据段和附加数据段是同一个段，`SS:STACK` 建立 `SS` 和堆栈段的关系。

但这种关系只是告诉汇编程序，汇编程序在汇编时承认这种关系，可是 `DS` 寄存器的值并没有指向 `DATA` 段的段地址，也就是说 `DS` 并没有初始化。那么 `DS`、`ES`、`SS` 这几个段寄存器值的初始化，是不是靠用户在下方用 `MOV` 指令来实现？

程序开始要写一个起始地址标号，必须写。起始地址标号名是用户自己起的，我现在叫 `START`，你叫 `MAIN`，叫什么都可以。一开始要用 `MOV` 指令给 `DS`、`ES`、`SS` 初始化：

```assembly
START:  MOV  AX, DATA
        MOV  DS, AX
        MOV  ES, AX
        MOV  AX, STACK
        MOV  SS, AX
        MOV  SP, OFFSET TOP
```

`MOV AX, DATA`，段名写到这，取的是段名具有的什么属性？段地址。把段名具有的段地址给 `AX`，所以这条指令源操作数的寻址方式是立即数寻址。下面再用一条 `MOV` 把 `AX` 传送到 `DS`。`DS` 做目的时源不能为立即数，所以 `DS` 的初始化要用两条 `MOV` 指令实现。

然后 `MOV ES, AX`，对 `ES` 初始化。这个时候 `ES` 的值是不是等于 `DS` 的值？`ES` 段和 `DS` 段同时指向 `DATA` 段。

对 `SS` 初始化：`STACK` 段名具有的段地址给 `AX`，`MOV SS, AX`。还用 `MOV` 对 `SP` 初始化，`SP` 的值应该指向栈底加一单元的偏移地址，栈底加一单元的偏移地址是不是 `TOP` 变量具有的偏移地址？`MOV SP, OFFSET TOP`。对 `SP` 初始化当然还可以用 `LEA` 取有效地址指令：`LEA SP, TOP`。

> **提示**：如果在堆栈段定义时组合类型选了 `STACK`，告诉链接程序本段是堆栈段，那么可执行文件装入内存的过程中，操作系统会对 `SS` 和 `SP` 做初始化。所以实际在代码段，这三条初始化指令可以不要。当然你要放了也行。如果这三条不要了，那条 `LABEL` 定义的 `TOP` 变量是不是也可以不要了？

## 3 LABEL 在数据段：一个单元两种类型

这些初始化做完了，下面编题目要完成功能的程序区。当然如果你的程序是循环结构，循环体前面是不是还有对循环功能的初始化？总之是编程序区。

假如在这个地方我有这么一条指令：

```assembly
MOV  AL, X_word
```

`X_word` 是我们用 `DW` 定义的一个字变量，写到源操作数是直接寻址，直接找到的这个单元是个字单元，但 `AL` 是 8 位的，源和目的类型不一致。以前我们讲的时候，有时需要在一个字变量对应的单元取一个字节，或者在一个字节对应的单元取一个字，用 `PTR` 说明：改成 `BYTE PTR X_word`，把 `X_word` 字变量临时改成字节型，语法上类型一致。

但今天我要讲的是，实际应用中还有另外一种办法。看汇编后在存储器里的效果：`X_word` 字单元里放的是 `34H`、`12H`（`1234H` 按低字节在前存放）。有时我们要对这个字单元做字节处理，把它看成字节单元，假如叫它 `X_byte` 字节变量。那我在 `X_word` 这个变量前方，用 `LABEL` 伪指令定义一个 `X_byte`：

```assembly
X_byte  LABEL  BYTE
X_word  DW    1234H
```

你看用 `LABEL` 定义的 `X_byte` 是字节型的。汇编程序汇编到这一行，`X_byte` 具有了这个单元的段地址和偏移地址属性，类型是字节型，但并没有占用这个存储单元。继续往下汇编到 `X_word`，字变量对应的偏移地址是不是还是这个单元？理解了没有？

所以这样定义以后，下方代码段实际程序设计中，对该单元做字处理用 `X_word`，做字节处理用 `X_byte`，效果和用 `PTR` 说明是一样的。我讲这段的目的，就是讲出 `LABEL` 伪指令在数据段的应用。按字节处理的话，这地方直接写 `X_byte`，类型一致，和刚才的效果一样。

## 4 程序结束：INT 21H 的 4CH 号功能

题目功能实现了，程序就要结束，写出结束语句：

```assembly
MOV  AH, 4CH
INT  21H
```

`INT 21H` 是软件中断指令，后边 `21H` 是中断类型号。`CPU` 执行 `INT 21H`，就是调用 `DOS` 操作系统里面的子程序。`DOS` 把完成每个功能的程序片段都设计成子程序形式，允许用户用 `INT 21H` 调用。调用 `DOS` 当中哪个功能对应的子程序，就要把功能号送给 `AH`，有 `00` 号、`01` 号、`02` 号，我现在是 `4CH` 号。调用 `DOS 4CH` 号功能，完成的是结束用户程序，让指针返回到 `DOS` 操作系统去。`CPU` 执行用户程序是从 `DOS` 操作系统 `CS:IP` 转过来的，用户程序执行完了，`CS:IP` 要返回到 `DOS` 去，靠的就是 `DOS 4CH` 号功能调用。

代码段整个编完了，写 `ENDS`，左边写段名 `CODE`。如果你编的程序在一个代码段，整个程序就编完了。如果你有些功能在另外一个代码段，好比起个 `CODE2` 段，`CODE2 SEGMENT` 又开始了，那么在下方必须用 `ASSUME` 说明 `CS:CODE2`，说此时的 `CS` 段是 `CODE2` 段。`CPU` 要执行到 `CODE2` 段来，按前面讲的远程转移，`JMP FAR PTR` 接个标号就转过来了。

假如就一个代码段，程序编完了，写总汇编结束伪指令 `END`，`END` 右边给出启动地址表达式。启动地址叫 `START`，就写 `END START`；叫 `MAIN`，就写 `END MAIN`。这样做了以后，源程序汇编链接后的 `.EXE` 要执行，`DOS` 装入程序从磁盘找到 `.EXE` 向内存装入的过程中，会把 `END` 后边起始地址表达式 `START` 具有的段地址属性给 `CS`，`START` 具有的偏移地址给 `IP`，程序一装到内存，`CS:IP` 是不是指向了程序的手地（首地址）？从这取指令执行。

## 5 4.1 节对账：92 页到 95 页讲了什么

这就是上节课讲的 8086 汇编语言源程序完整结构。对第四章插入的这部分内容，我们对一下账：92 页讲了汇编语言程序设计的步骤；93 页讲了段定义开始伪指令 `SEGMENT`、段定义结束伪指令 `ENDS`，93 页下方讲了段寻址伪指令 `ASSUME`；94 页上方讲了总汇编结束伪指令 `END`，94 页下方讲了 `LABEL`，94 页还有两条伪指令下去自己学，实际程序设计中不太用；95 页讲了 `EQU` 伪指令，这是以前讲作业时讲过的等值伪指令。

`EQU` 和等号伪指令作用一样，都是把右边表达式的值赋给左边符号常量，定义符号常量。相同点是右边表达式的值不能超出 $65535$（$0 \sim 65535$）。不同点在哪？假如在数据段一开始，我 `COUNT EQU 5+3`，下边程序凡是用到 `5+3` 的地方都可以用 `COUNT` 代替，但是用 `EQU` 定义的 `COUNT` 就不能再用 `EQU` 再次定义了，只能定义一次。但是等号伪指令，比如在代码段编程序，到了这个地方来个 `X = 1`，把 $1$ 赋给 `X`，下边 `MOV AL, X`，汇编到这就用这个数代替；继续往下，到了这个地方 `X = X + 1`，再 `MOV AL, X`，汇编时 `X` 是不是等于 `X+1` 了？也就是说，用等号伪指令定义的符号常量还可以再次定义，用 `EQU` 定义的只能定义一次。

95 页还有一条 `ORG` 定位伪指令。看黑板上数据段：定位类型缺省是节型，本段起始偏移肯定是 $0$。`VAR1` 字节单元放了 `10H`，偏移是 $0$；`VAR2` 字单元偏移是 $1$；`X_word` 字单元偏移按顺序应该是 $3$，也就是 `0003H`。但我对该单元做字处理时，该单元是不是未对准？从该单元读一个字或写一个字，是不是需要两个总线周期才能完成？为了使该字单元对准，偏移等于 $4$ 是偶地址就对准了。怎么定位到 $4$？在它前面用 `ORG`，后边写地址表达式 `0004H`。不定直接顺序就到 $3$ 了，我一定位偏移就等于 $4$，这边这个单元我就不要了。不用了。你看，$0$、$1$、$2$、$3$ 用了，该字单元偏移就是 $4$。想定位在偶地址上，就用 `ORG` 伪指令。这是在应用当中。

然后 95 页下方给出了 8086 汇编语言源程序的一个结构，和黑板上是不是差不多？
