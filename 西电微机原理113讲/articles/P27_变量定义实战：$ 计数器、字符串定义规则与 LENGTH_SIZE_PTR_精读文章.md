# 变量定义实战：$ 计数器、字符串定义规则与 LENGTH/SIZE/PTR

`$` 本身也是一个常量，语句里可以引用。比如 `$+2` 是不是算术表达式？加 2 是不是变成 6 了？如果加逗号再给 `56ACH`，逗号给的操作数也是字，因为 `DW` 伪指令。汇编继续往下，这个时候 `$` 是不是增 2 到了 `0006H`？单元段地址变了吗？没变，还是 `1500H`。这个单元放 `56ACH`，`ACH` 低字节写低地址单元，高字节到高地址单元。我写 `ACH` 也可以写 `0ACH`，一样的，但这里不写前导 0 对吗？对的，这里没在语句里，是画存储器示意图。如果 `0ACH` 做数值在语句里出现，字母开头的十六进制高位是不是要加 0？

逗号后跟 `78H` 也是字，汇编使 `$` 再增 2，偏移到 `0008H`。字单元放低字节 `78H`，高字节多少？00，可缺省即 `00H`。`$` 再增 2 到了多少？怎么能到 10？这是十六进制加法！$8+2=A$，就喜欢你们错到这我才有话讲。偏移 `000AH`，段地址依然没变。

## DB 与 DW 定义字符串规则不同

再来 `DB` 定义：

```assembly
beta3 DB 'THIS'
```

变量 `beta3`，单引号 4 个字符。汇编在 `beta3` 单元写入 `'T'` 的 `ASCII` 码。`ASCII` 记不住做作业直接写 `'T'`，概念完全正确，不扣分，尽管单元放的是编码。下一个单元 `$` 加 1 存 `'H'` 的码，再下 `'I'`，再下 `'S'`。逗号后还有字节操作数继续汇编。

再看 `DW` 定义的 `beta4`：

```assembly
beta4 DW 'AB', 'C'
```

`DW` 也能定义字符串，但无论 `DW` 还是 `DD`，定义字符串一对单引号最多只能两个字符，8086 规定的，没有为什么，严格遵守。用 `DB` 定义一对引号可写任意多个，前提不超过 64K，超过逻辑段装不下。`beta4` 偏移多少？A、B、C、D、E，`000EH`，段地址没变同一逻辑段。这个单元放哪个字符的码？`'B'`！遵循低字节低地址，`DW` 字单元低地址放 `'B'` 的码大写 `42H`，下单元放 `41H` 即 `'A'`。板书画不下换行重画，换行写对即可。下一个字单元 `$` 增 2 偏移 `0010H`，放 `'C'` 的码，高位没字符了，`DW` 必须占满字，高位 0 填补 `00H`。

## DD 存地址与 DW 存偏移

数据段继续定义 `beta5`：

```assembly
beta5 DD 9CH
```

双字变量占 4 字节，最低地址放低字节 `9CH`，后面高字节 `00H`、`00H`、`00H`。`beta5` 偏移 `0012H`，汇编完 `$` 增 4 到 `0016H`。

```assembly
beta6 DW beta3
```

字单元放的不再是常量而是变量。汇编在 `beta6` 存 `beta3` 的 16 位偏移 `OFFSET`，`000AH`，低字节 `0AH` 高字节 `00H`。

```assembly
beta7 DD beta3
```

`beta7` 偏移 `0018H`，双字占 4 字节。汇编取 `beta3` 双字属性：先取偏移字属性 2 字节，再取 16 位段地址属性 2 字节，整体当双字。偏移低字节 `0AH` 高字节 `00H`，下个字存段地址低字节 `00H` 高字节 `15H` 对应 `1500H`。汇编完 `$` 增 4：$18H + 4 = 1CH$，偏移变 `001CH`。

> **提示**：`DW 变量名` 存的是该变量的偏移地址，`DD 变量名` 存的是偏移加段地址的完整双字地址（低字偏移、高字段地址）。

## LENGTH 与 SIZE

8086 规定：变量名定义语句只有出现 `DUP` 重复操作符，左边重复次数才是定义的变量个数。比如 `DATA8` 定义 4 个，`LENGTH` 等于 4；`DATA9` 定义 3 个，`LENGTH` 3；没出现 `DUP` 只定义 1 个，`DATA7`、`DATA6` 等 `LENGTH` 都是 1。注意 `DATA2` 有 7 个初始值项，直接定义 7 个变量。

`SIZE` 大小属性：定义语句所有变量占的总字节数。`DATA1` 1 个变量占 1 字节，`SIZE` 1；`DATA9` 3 个变量每个占 2 字节，总 $2 \times 3 = 6$，`SIZE` 6。

$$\text{SIZE} = \text{TYPE} \times \text{LENGTH}$$

## PTR：属性临时修改操作符

教材 30 页 3.1.4 节，五个属性操作符之外还有 `PTR`，27 页说的其他操作符就是它。看直接寻址：

```assembly
MOV AL, DATA1+2
```

读单元数据到 `AL`，若单元存 `F2H`，执行后 `AL` 等于 `F2H`。但写成 `MOV AX, DATA1` 呢？`DATA1` 字节型 8 位，`AX` 16 位字，源目类型不一致，汇编判定语法错误报错退出。

实际经常要在字节单元按字读、字单元按字节读，就要类型强制转换，用 `PTR`：

```assembly
MOV AX, WORD PTR DATA1
```

`WORD PTR` 把 `DATA1` 本条指令临时强制转字变量，执行后 `AX` 得字数据比如 `1202H`。脱离本条语句 `DATA1` 仍是字节型，没永久改变。所以 `PTR` 叫属性临时修改操作符，仅本语句起作用：临时当字 `WORD PTR 变量名`，临时当字节 `BYTE PTR 变量名`。

再看基址寻址：

```assembly
MOV [BX], 10H
```

目的 `[BX]` 是 `DS` 段偏移 `BX` 内容的单元，源 `10H` 常数本身没类型，目的经 `[BX]` 也定不了按字节还是字访问，汇编无法判断把 `10H` 写成字节还是扩展 `0010H` 写成字，类型不明语法错误。必须 `PTR` 明示：`BYTE PTR [BX]` 或 `WORD PTR [BX]`。比如单元是字节单元就改 `MOV BYTE PTR [DI], ...`，真切找到字节单元，语法就对了。

> **结论**：指令里寻址的操作对象类型不明确就用 `PTR` 说明。`PTR` 在实际编程用得非常广泛。这样 3.1 节全讲完了。
