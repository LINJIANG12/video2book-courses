# 存储器寻址五方式与直接寻址：EA 公式、双存储器禁令与 PTR 收尾

先看指令 `MOV CS, AX`。源目都是寄存器寻址，逻辑上把 `AX` 写 `CS`，但 `CS` 只能读，这条语法错。错因：`CS` 和 `IP` 都不能做目的操作数。用户无权改它俩：初值是程序装入内存启动时操作系统设置的；执行期间改变是 CPU 执行转移指令自动改的，段内转移 `IP` 变，段间转移 `IP` 和 `CS` 都变，不能 `MOV` 强改。所以 `CS`、`IP` 不能做目的，但可以做源。

## 共性规则与个性规则

寄存器寻址和立即数寻址总结出通用语法规则：立即数只能做源；类型要一致；类型要明确；`DS`、`ES`、`SS` 做目的时源不能是立即数寻址；`CS`、`IP` 不能做目的。这些是往后每类每条指令都守的语法共性规则。学具体指令除共性还有自身语法个性规则，比如堆栈 `PUSH`、`POP` 除守上述规则，还必须按字操作，这就是堆栈特有的。

第三种寻址是教材第 3、4、5、6、7 种，统称存储器寻址。概念：操作数 `OPR` 在存储器某单元，取出来必须知道单元地址，段内有效地址 $EA$ 即偏移，由五种方式求得：

1. 直接寻址：指令直接写出单元有效地址。
2. 寄存器间接寻址：寄存器内容求 $EA$，只能 `[BX]`、`[SI]`、`[DI]` 三者之一。
3. 寄存器相对寻址：$EA$ 两部分，地址寄存器 `[BX]`/`[BP]`/`[SI]`/`[DI]` 四者之一，加 8 位或 16 位位移量 $DISP$：

$$EA = (BX/BP/SI/DI) + DISP$$

4. 基址变址寻址：$EA$ 两部分相加，一部分基址 `[BX]` 或 `[BP]`，另一部分变址 `[SI]` 或 `[DI]`：

$$EA = (BX/BP) + (SI/DI)$$

5. 基址变址相对寻址：上面组合再加 $DISP$，三部分之和：

$$EA = (BX/BP) + (SI/DI) + DISP$$

总结：如果操作数在存储器，五种之一都能找到地址。编程序出现"基址加基址"或"变址加变址"就错了，比如 `MOV AX, [SI][DI]`，字面"变址加变址"，8086 没这种方式，语法错。显然 CPU 面向存储器的寻址种类越多，汇编编程越容易。

| 方式 | $EA$ 构成 | 说明 |
| :--- | :--- | :--- |
| 直接 | 指令直接给出 | 数值或变量名 |
| 寄存器间接 | `[BX]`/`[SI]`/`[DI]` | 三者之一 |
| 寄存器相对 | 基址变址之一 $+ DISP$ | 四者之一加 8/16 位位移 |
| 基址变址 | `(BX/BP)+(SI/DI)` | 基址其一加变址其一 |
| 基址变址相对 | `(BX/BP)+(SI/DI)+DISP$ | 三部分之和 |

## 直接寻址：数值形式与变量形式

第一种直接寻址：操作数在存储器某单元，单元段内 16 位有效地址指令直接给出。比如：

```assembly
MOV AL, [2000H]
```

源传目的，单元偏移 `2000H`，段地址默认 `DS`，找到一个单元。字节还是字？看另一方，`AL` 8 位寄存器，所以是字节单元，功能是把字节数据传 `AL`。源寻址就是直接寻址。

实际编程直接寻址不常用数值写法，单元地址都符号化了，符号叫变量。比如 `DS` 段：

```assembly
DATA1 DB 12H
DATA2 DB 34H
```

变量一旦定义具有五个属性，`DATA1`、`DATA2` 具有段地址和偏移属性。代码段想把 `DATA1` 读给 `AL`：

```assembly
MOV AL, DATA1
```

`DATA1` 代表一个地址，源寻址直接寻址，目的寄存器寻址，执行完 `AL` 等于 $12H$。

## 两存储器单元不能直接操作

如果写：

```assembly
MOV DATA2, DATA1
```

源目都是直接寻址，企图一条指令把 `DATA1` 直接传 `DATA2`，不行。图 3.3：存储单元和通用寄存器可互传，存储单元和另一存储单元之间书上画了能传吗？没有！所以语法错。错因：两存储器单元之间不能直接操作。`ADD` 两单元不能直接加，`AND` 不能直接与，总之不能直接操作。想把 `DATA1` 传 `DATA2` 怎么办？先读到通用寄存器过渡：

```assembly
MOV AL, DATA1
MOV DATA2, AL
```

上面源直接寻址、目的寄存器寻址，下面目的存储器直接寻址。中间 `AL` 过渡，两单元传送完成。

还有类型问题。比如 `DATA1` 是 `DB` 字节单元，我以它为地址写字数据：

```assembly
MOV DATA1, AX
```

`AX` 16 位，`DATA1` 字节型，类型不一致违反规则，语法错误。就是想把 `AX` 写到以 `DATA1` 为地址的字单元，用 `PTR` 说明类型：

```assembly
MOV WORD PTR DATA1, AX
```

语法就对了。但 `PTR` 把字节型 `DATA1` 本条语句临时改成 `WORD`，脱离本条 `DATA1` 仍是字节型。所以 `PTR` 叫属性临时修改操作符，只本行起作用。这是直接寻址应用特别注意的问题。下面休息五分钟，再讲其他寻址方式。
