# 总线分家、存储分工与指令本质：微机硬件组成的第一张全图

CPU 要往存储器或者某个 `I/O` 写数据，我该怎么办？我就得让 CPU 的写控制引脚发出一个写控制命令；要读数据，我就得发一个读控制命令。你们想，数据走数据总线，地址走地址总线，那这些读、写命令走哪条路？这就是我今天要先替你们分清楚的第一件事：控制信息到底走哪条线。

## 命令与状态：控制总线上传的是什么

地址总线走专用的地址总线通道，控制总线走专用的控制总线通道，记作 `CB`。如果控制总线上的命令是 CPU 发送出来的，我叫它命令信息。

可控制总线上不只有 CPU 发出去的命令，还有设备反馈给 CPU 的状态信息。你们一定要把这两股方向相反的信息一次分清：CPU 发出去的叫命令，设备返还回来的叫状态。我把这两者统称为控制信息，控制信息就走专用的控制总线。

> **定义**：命令信息是 CPU 通过控制总线向外发出的读、写等控制命令；状态信息是外设、存储器等向 CPU 反馈的工作状态；两者合称控制信息。

为什么非要分三条线？数据、地址、控制各走各的专线，CPU 和谁打交道才不会乱。这一点你们后面看任何接口电路都要先问：这根线是三者中的哪一种？

## 系统总线形成电路：把复用引脚变成三条专线

我把微处理器的那些引脚拿出来看，由于好多引脚是复用的，我通过一部分电路把它转化成专用的三种线：数据总线、地址总线、控制总线。转化用的这部分电路，我把它称为系统总线形成电路。

那这个电路怎么设计？你们得先过两关。第一关，是不是要掌握 CPU 每个引脚的功能？每个引脚是干什么的，你们得一个一个弄明白。第二关，还要了解引脚与引脚之间、一个信号与另一个信号之间的时序关系。然后用你们数电课上学过的锁存器、缓冲器这些芯片来搭这部分电路。这部分知识点，涉及的是我们教材第五章的内容。

我给你们把这个转换画出来，你们一眼就明白它在系统中的位置：

```text
微处理器引脚 (多为复用,驱动弱)
   |
   v
+--------------------+
| 系统总线形成电路    |
| (锁存器/缓冲器搭成) |
+--------------------+
   |        |        |
   v        v        v
数据总线  地址总线  控制总线
  DB       AB       CB
   |        |        |
   +--------+--------+
            |
      系统总线 (三总线)
```

读图说明：左边是复用、驱动弱的处理器引脚，经过中间的锁存、缓冲与分线，右边分出三条专用系统总线，后面所有存储器和 `I/O` 都挂在这三条线上。

## 微处理器级总线与系统总线：为什么非转一次不可

你们再看，这一部分是不是也是总线？一路收缩收缩，一直收到引脚上了。显然微处理器的引脚本身是不是也是总线？是的。我把微处理器引脚构成的总线称为微处理器级总线。

微处理器级总线有两个天生的短板，你们一定要记住。第一，部分引脚采用了复用引脚，一个引脚在不同时刻干不同的活，直接拿来用会打架。第二，微处理器级总线上每个引脚的驱动负载能力都很弱。你们想，微型机里面的微处理器芯片体积很小，我不可能在微处理器内部再给每个输出信号设计一个大放大电路再输出，所以每个引脚能带的负载都很小。

鉴于这两个问题，我在系统设计中第一步就必须把微处理器级总线通过系统总线形成电路转化成三线形式。转化后的这三种线，我把它称为系统总线，也可以叫系统级总线，那个“级”字不说也行，就叫系统总线。

> **结论**：系统总线形成电路一次解决两个问题——解开引脚复用，提高总线驱动能力。

那转完之后有什么好处？在微型计算机系统当中，任何要和 CPU 通信的部件，存储器也好，`I/O` 也好，都是挂接在系统总线上来完成和 CPU 之间通信的。挂接在系统总线上的任何器件或部件，对总线而言是不是都是一个负载？微处理器级总线驱动能力弱，我只让它驱动这一个负载，就是系统总线形成电路这一个负载；而系统中大量的负载驱动，是不是就交给了系统级总线？负载的驱动任务交给系统级总线，这才是能带起整个系统的办法。

所以你们看，刚才这么一剖析，微型计算机硬件组成是不是就清楚了：以微处理器为核心，采用三总线形式来组成，系统中需要的其他部件是不是都挂接在三总线上了？

## 存储器子系统：为什么一定是 ROM 加 RAM

首要部件就是存储器。不管你们以什么型号的 CPU 组成什么功能的电子信息系统，存储器部分都分两大部分。第一大部分就是我们常说的只读存储器（Read Only Memory，ROM），第二大部分就是随机存取存储器（Random Access Memory，RAM）。这两大部分组成了这个系统的存储器子系统。这个你们听到过没有？

这两部分存储器的区别你们应该清楚吧？我替你们一次讲透。

| 对比项 | ROM（程序存储器） | RAM（数据存储器） |
| :-- | :-- | :-- |
| 掉电后信息 | 不丢失 | 丢失 |
| 主要用途 | 存放系统管理程序、用户程序代码 | 存放程序运行期间产生的数据 |
| CPU 访问方式 | 只能读 | 能读能写 |

ROM 里面的信息，每个地址单元的信息掉电后不丢失。既然掉电后不丢失，那 ROM 里面存放的肯定是这个系统的管理程序。

我就拿你们常用的计算机给你们举个例子。主板上也有一片 ROM，是用可擦除可编程只读存储器（Erasable Programmable ROM，EPROM）芯片组成的，紫外线下可擦除。主板上的 ROM 里面放的是什么呢？基本输入输出系统（Basic Input Output System，BIOS）。听过没有？BIOS 就是系统管理程序。计算机一加电，CPU 先从 BIOS 里面取程序代码执行。

## BIOS 上电干的三件事：自检、初始化、装系统

取程序代码执行，任务有哪些呢？我给你们数三件，你们就知道管理程序到底管什么。

第一，对内存进行自检。这不就是内存吗？你们买内存条嘛，RAM，能读能写的存储器，掉电后信息是不是丢失了？一加电，CPU 从 ROM 里面读取 BIOS 程序，先对 RAM 进行自检。自检的目的就是看 RAM 每个地址单元的每个位（bit）都能写能读吗？它保证每个位都是好的。

第二，内存自检完了，执行 BIOS，是不是要对主板上的 `I/O` 接口电路初始化？要初始化。不初始化，后面设备没法用。

第三，RAM 自检了，电路初始化了，干什么去了？从外部设备磁盘上是不是读取操作系统到内存了？然后内存里才有操作系统。你们用户在计算机上干活，是不是在操作系统界面上干活呢？

> **提示**：BIOS 的三步是按硬件依赖排的——先确认 RAM 可用，再让接口就绪，最后才有地方装操作系统。顺序反了，机器就起不来。

那你们自己以某一种型号的 CPU 来设计完成自己功能的系统，是不是也要设计这系统加电后的管理程序？所以管理程序都在 ROM 里面放着，加电后不丢失，我把 ROM 存储器称为程序存储器；把 RAM 存储器称为数据存储器，专门用来存放程序在运行期间产生的数据等等。

有些型号的 CPU 内部自带 ROM 和 RAM 存储器，比如 51 系列单片机、MSP430 单片机内部都有一定容量的程序存储器和数据存储器。在实际应用当中，如果内部的存储器容量不够用，你们就要在外部总线上扩充、扩展设计存储器了。

而我们这门课用到的 CPU 是 8086。8086 CPU 内部没有存储器电路，所以以 8086 CPU 组成的电子信息系统，系统中要用到的存储器都必须在三总线上去扩展设计。这一条你们一定要记住，后面第六章全是干这个的。

## RAM 和 ROM 怎样挂在总线上：地址找单元，控制定读写

对于 RAM 数据存储器而言，CPU 要和 RAM 当中的某个地址单元写数据，就把发送过来的数据写到某地址单元去；或者从那个地址单元把数据读出来，CPU 接收回去。

那你们问：我要读写的那个单元的地址，CPU 事先放在哪了？是不是事先在地址总线上发送出来了？地址总线上有地址码，就找到了这个单元。然后对这个单元是写还是读，CPU 根据现行执行的指令不同，通过控制总线发出不同的读命令或者写命令来完成读写操作。

读写命令是由 CPU 通过控制总线发送出来的。假如说这是一个读命令，那对于这个芯片而言，这个引脚一般叫输出允许（Output Enable，`OE#`），`#` 表示低电平有效，`O` 是输出，`E` 是允许。当我给这个引脚加上低电平时，这个地址码对应单元的数据就允许输出了，是不是就读出来了？

如果要给这个地址码对应单元写数据，就要通过控制总线给 RAM 存储器发写命令。写命令的引脚符号，有些器件叫写允许（Write Enable，`WE#`），低电平有效，有些器件叫写（Write，`WR#`）。明白了吧？你们以后看存储器芯片，看到这样的引脚就知道是写控制引脚，看到 `OE#` 就知道是读控制引脚。地址引脚上肯定是 `A0` 到 `An`，数据引脚如果是 8 位存储器，是不是 `D0` 到 `D7`？

对于 ROM 程序存储器而言，也是 CPU 通过地址线给它发送地址信息，找到地址信息对应的地址单元，再给它发一个读命令 `OE#`，把这个单元的数据读出来放在数据线上，CPU 是不是就读走了？只读，就是这个意思。

> **易错点**：ROM 在板上只能读，不等于它永远写不进去。程序存储器内部每个地址单元的信息是怎么放进去的？是你们用户把程序代码编好、调试通之后，用专用的写入器把二进制代码写进去，写完从写入器上拿下来，插到你们电路板的 ROM 器件里。一旦插到你们用户电路板上，这个芯片在使用现场只能读。

所以 CPU 和存储器之间信息的传送，你们看规律很清楚：通过地址线上输出的地址码来指定要操作的具体地址单元；对该单元进行读还是写，根据 CPU 现行执行的指令决定。如果是对存储器写，是不是有存储器写的指令？对存储器读，有存储器读的指令。对于 `I/O` 读还是写，是不是有专用的 `I/O` 读写指令？

这个存储器程序存储器电路怎样和总线接口起来，数据存储器怎样和系统总线接口起来，是不是一个接口电路的设计？存储器接口电路的设计是我们教材第六章讲的内容。教材第七章往后设计的是 `I/O` 接口电路的设计。

## 指令到底是什么：从一行 C 语句到两字节机器码

我在这儿引出一个概念，什么叫指令？用你们 C 语言来说，指令就是一行语句，明白了吧？用汇编语言来说，当然也是一行语句。当然，结合到 CPU 能认识这条语句，是不是只能认识二进制代码？

所以指令是一组二进制代码。你们不管用什么语言编写的程序，程序中的每行语句都要翻译成 CPU 能认识的二进制代码。一组代码是不是代表一行语句？一行语句告诉 CPU 做一件事情。理解了没有？不是随随便便的一组二进制代码，只有能告诉 CPU 做什么、而且能告诉 CPU 怎么去做的一组二进制代码，才叫一条指令。

那用这样的二进制代码是不是也可以编写程序？用二进制代码编写程序采用的这种语言就叫机器语言。显然用机器语言编写的程序放到存储器里面去，CPU 是不是能直接认识、能直接执行？但是用机器语言编写程序，势必给程序员造成极大的复杂性，程序设计非常困难。因此人们才把能代表一条指令的一组二进制代码用符号描述了，用符号描述后采用的语言就叫汇编语言。

我给你们举个最直观的例子。这是一个存储器，一个单元一个单元。假如说这个单元放了个 `B0H`，十六进制数，`B0H` 化下来是不是 8 位二进制数？后面跟个 `02H`，这两个 8 位二进制代码合起来就是一组，这一组就是一条指令。但作为程序员来说，一下子就不知道这条指令让 CPU 做什么，这不就是机器语言代码？人们后来用一组符号来代替这一组代码，用 `MOV AL, 02H`，这一看一目了然，就知道 `MOV` 是数据传送，就相当于高级语言里面的赋值语句。它告诉 CPU：给 CPU 内部有一个 8 位寄存器叫 `AL`，给 `AL` 赋值 `02H`，赋初值。

当然用汇编语言编写的程序叫汇编语言程序，汇编语言写的程序是不是也是符号化的？CPU 也不认识。所以让 CPU 执行之前是不是要把符号翻译成代码？在高级语言里面，把符号语句翻译成 CPU 能认识的代码是不是叫编译？在汇编语言当中，把一组符号语句翻译成 CPU 能认识的一组二进制代码，也就是指令代码的过程叫汇编。汇编实际上就是翻译，明白了吧？汇编后的二进制代码，最后你们要用专用设备写到 ROM 程序存储器里面，然后系统一加电，CPU 从 ROM 里面读取用户程序代码去执行了。

> **定义**：机器语言是用二进制指令代码直接编写程序的语言，CPU 可直接执行但难写难读；汇编语言是用符号代替二进制指令的语言，写完必须经过汇编翻译成二进制指令代码才能执行。

## 存储器能直连，I/O 为什么不行

在一个微型计算机系统当中，除了 CPU、存储器以外，是不是还挂接了好多 `I/O` 设备？比如这是 1 号设备，可能还有 2 号、3 号、4 号设备，设备很多。由于设备很多，设备和设备之间信息接收的格式要求是不是不同？刚才我讲过，有些设备要接收的是数字量信息，好比说这是个输出设备；有些设备要接收的是模拟量信息；有些设备接收数字量信息时要并行接收，有些要求串行接收等等。设备很复杂，因此设备和 CPU 之间要通信的数据格式就很复杂。

因此我可以总结出一句话：任何 `I/O` 设备与 CPU 之间的数据通信或信息通信都不能直接通信。它不像存储器这样，存储器和 CPU 之间数据是不是沿数据总线直接通信的？而设备不行。设备到底要加什么才能和 CPU 打交道，这就是下一讲 `I/O` 接口要解决的问题，你们先把这个反差记住。
