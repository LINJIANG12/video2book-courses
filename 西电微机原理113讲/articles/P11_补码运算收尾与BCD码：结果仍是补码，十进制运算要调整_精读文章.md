# 补码运算收尾与BCD码：结果仍是补码，十进制运算要调整

刚才我们讲了补码的表示、补码的求法、补码的运算，又提到了溢出的概念。补码这一块，还差最后两点没收口，收完口，我就要转到本章第四个知识点——`BCD` 码了。为什么非讲它不可？你们想，计算机里的数全是二进制，可我写程序时天天要算十进制，这中间的缝怎么补？这一讲，我就把这个缝补上。

## 1 补码运算的结果仍然是补码

我先问你们一个问题：用补码表示的数做加法，算出来的结果是什么形式？答案是：仍然是补码形式的结果。你们别小看这一句，这是后面看懂结果、判断溢出的前提。

我举个例子，你们跟着我算一遍。算 $(-11)+(-3)$，看结果是不是等于 $-14$ 的补码。

先求 $-11$ 的补码。$-11$ 的原码是：

$$[-11]_{原} = 10001011B$$

符号位不变、其余位按位取反、末位加 $1$，得到：

$$[-11]_{补} = 11110101B = F5H$$

$-3$ 的补码上次已经算过了：

$$[-3]_{补} = 11111101B = FDH$$

两个补码相加：

```text
  1111 0101   (-11的补码 F5H)
+ 1111 1101   (-3的补码  FDH)
--------------
  1111 0010   (F2H，最高位向前的进位丢掉)
```

你们看，低 $4$ 位向高 $4$ 位是不是有进位？我一会儿复习标志位时还要回来说它，这个进位让辅助进位标志 `AF` 置 $1$ 了。最高位向前也有一个进位，按补码运算规则，这个进位丢掉，不管它。最后落在寄存器里的就是 `11110010`，也就是 `F2H`。

那 `F2H` 到底是多少？它现在是补码形式，我要看它的真值，就得对它再求一次补：符号位不动，其余位按位取反再加 $1$：

```text
  补码结果:  1 1110010
  取反(符号位不动): 1 0001101
  末位加1:   1 0001110  = 00001110B = 14
```

符号位是 $1$，真值就是 $-14$。你们看，是不是正好等于 $-14$ 的补码？

> **结论**：用补码表示的数（这里指负数）参加运算，运算结果仍然是补码。要读出它到底是多少，就对这个补码结果再求一次补，得到的才是它的原码。

换句话说，我画一个箭头：补码表示的数 $\xrightarrow{再求补}$ 原码。这个“再求补”本身就是一个求补过程，你们一定要认住它。

## 2 把减法变成加法：变补

前面我给过公式二：两数之差的补码等于两数补码之差；它再演变成公式三：

$$[X-Y]_{补} = [X]_{补} + [-Y]_{补}$$

你们想，要把减法彻底变成加法，缺的最后一块拼图是什么？是不是“已知 $[Y]_{补}$，怎么求 $[-Y]_{补}$”？只要这一手会了，减法随时变加法。

我把这个问题单拎出来，放到这里。已知 $[Y]_{补}$，求 $[-Y]_{补}$ 的过程，我把它叫变补，或者叫求负。你们记住这个名字，后面一说“变补”就知道指的这一手。

比如 $Y=-3$，它的补码是：

$$[Y]_{补} = 11111101B = FDH$$

现在我要 $[-Y]_{补}$，也就是 $[3]_{补}$。做法是对 $[Y]_{补}$ 连同符号位在内一起按位取反、末位加 $1$：

```text
  已知[Y]补:  1111 1101
  按位取反:  0000 0010
  末位加1:   0000 0011  = 03H = [+3]补
```

> **定义**：变补（求负，negation）：已知 $[Y]_{补}$，求 $[-Y]_{补}$，就是对 $[Y]_{补}$ 包含符号位在内按位取反、末位加 $1$。

有了变补，减法变加法就是顺手的事。刚才举例时我漏讲了这一句，这里给你们补上。

## 3 一次加法里的全部标志位

刚才 $(-11)+(-3)$ 那个加法，结果 `F2H` 落在寄存器里，`PSW`（程序状态字，Program Status Word）里的一串标志位也就跟着定了。我带你们复习一遍，每个标志看什么，你们做题时就按这个顺序查。

| 标志位 | 全称 | 这一例子中的取值 | 判法 |
| :-- | :-- | :-- | :-- |
| `AF` | 辅助进位标志（Auxiliary Carry Flag） | $1$ | 低 $4$ 位向高 $4$ 位有进位，`AF` 置 $1$ |
| `CF` | 进位标志（Carry Flag） | $1$ | 最高位向前有进位，`CF` 置 $1$ |
| `ZF` | 零标志（Zero Flag） | $0$ | 结果不为零，`ZF` 清 $0$ |
| `OF` | 溢出标志（Overflow Flag） | $0$ | 次高位向前有进位、最高位向前也有进位，两者一致，无溢出，`OF` 清 $0$ |
| `SF` | 符号标志（Sign Flag） | $1$ | 结果最高位即符号位为 $1$，说明结果为负，`SF` 置 $1$ |
| `PF` | 奇偶标志（Parity Flag） | $0$ | 结果中 $1$ 的个数为 $5$ 个，奇数个 $1$ 则 `PF` 清 $0$，偶数个 $1$ 才置 $1$ |

你们看，`AF` 是不是已经在加法过程中出现了？`CF` 呢，最高位那个丢掉的进位就是它。`ZF` 看结果是不是零。`OF` 看次高位和最高位的进位是不是一致，一致就没溢出。`SF` 直接抄结果的最高位。`PF` 数 $1$ 的个数就行。

到这里，计算机中带符号数用补码表示、补码运算、运算后有没有溢出、标志位怎么看，这些概念我就讲完了。我顺便交代一句：我讲的时候没有纯粹按这一章的顺序，而是把第二章的一些内容和第三章的几条指令拉过来揉在一起讲的，你们复习时按我这个顺序串起来就行。

## 4 十进制运算的表示问题：BCD码

下面进第四个知识点：`BCD` 码（二进制编码的十进制数，Binary Coded Decimal）。

你们先跟我捋三句话。第一，计算机中的数都是用二进制表示的，`CPU` 运算时不管你们用户原来想怎么写，它一律视为二进制数。第二，计算机中的带符号数都是用补码表示的，这是上一节刚收口的。第三，我实际编程序时，经常要做十进制数的运算。那问题来了：怎么用二进制数来表示十进制数？

十进制有 $0 \sim 9$ 一共 $10$ 个状态，用二进制表示至少需要 $4$ 位。而 $4$ 位二进制能表示 $16$ 个状态，十进制只要 $10$ 个，我用哪 $10$ 个？为了让这 $4$ 位的权加起来的和恰好等于十进制的值，我取前 $10$ 个状态：`0000` 表示 $0$，`0001` 表示 $1$，一直到 `1001` 表示 $9$。

这 $4$ 位的权是不是 $8$、$4$、$2$、$1$？也就是 $2^3$、$2^2$、$2^1$、$2^0$。你们在数电课里学过，这就是 `8421` 码。因为它用二进制表示十进制，所以 `8421` 码也叫 `BCD` 码。

## 5 计算机中BCD数的两种存放形式

数大多数时候放在哪里？放在存储器里。存储器是按字节组织的，这句话我第一节课就讲了。每个单元都是一个字节单元，参加运算的少量数据有时暂存在 `CPU` 内部的寄存器里，`8086` 里面有 $8$ 位寄存器，也有 $16$ 位寄存器。

那在一个字节里怎么放 `BCD` 数？我拿十进制 $53$ 给你们看两种放法。

### 5.1 组合BCD数

低 $4$ 位放 $3$（`0011`），高 $4$ 位放 $5$（`0101`），一个字节里装了两位 `BCD` 码：

```text
  一个字节单元
  +--------+--------+
  | 0101   | 0011   |
  | 高4位=5 | 低4位=3 |
  +--------+--------+
  十进制读作 53
```

这种把两位 `BCD` 码组合在一个字节里的方法，就叫组合 `BCD` 数（combined BCD），有些教科书叫压缩 `BCD` 数（packed BCD），说的是同一回事。

> **提示**：对你们程序员来说，它是 `BCD` 数 $53$；可对 `CPU` 来说呢？它只认二进制。`01010011B` 当二进制看已经是 $83$ 了，早就不是 $53$。你们心里是 `BCD`，它眼里是二进制，这个错位就是后面要“调整”的根子。

### 5.2 分离BCD数

还是表示 $53$，我把 $3$ 放在一个字节里，高 $4$ 位不用；把 $5$ 放在下一个地址的字节单元（或者下一个字节型寄存器）里，高 $4$ 位也不用。不用的高 $4$ 位一般用 $0$ 填上：

```text
  字节单元 N      字节单元 N+1
  +--------+      +--------+
  | 0000   |      | 0000   |
  | 0011=3 |      | 0101=5 |
  +--------+      +--------+
  读作 53，但占了两个字节
```

这种一个字节只放一位 `BCD` 码的方法，就叫分离 `BCD` 数（unpacked BCD）。

> **结论**：在计算机中表示 `BCD` 数有两种方法：组合 `BCD` 数和分离 `BCD` 数。表示方法不同，运算后结果的调整方法就不同。

## 6 为什么BCD运算结果要调整

为什么我非要提“调整”两个字？因为你们按组合或分离的办法放进去的数，`CPU` 运算时全看成二进制，算出来的结果可能根本不是你们想要的正确 `BCD` 结果。错了怎么办？就得修正，这个修正就叫调整。

我给你们算一道 $53+28$，手工和 `CPU` 各算一遍，你们就明白错在哪了。

手工算：$3+8$ 逢十进一，$5+2$ 再加进来的 $1$，结果 $81$。这没问题吧？

`CPU` 按组合 `BCD` 数算。你们写程序时是不是这么写：

```asm
MOV AL, 53H
ADD AL, 28H
```

`53H` 就是 `01010011B`，`28H` 就是 `00100000B` 加 `00001000B`，即 `00101000B`。`ALU` 做的就是这个二进制加法：

```text
  0101 0011   (53H)
+ 0010 1000   (28H)
--------------
  0111 1011   (7BH)
```

正确结果应该是 $81$，它给了你们一个 `7BH`。十进制里有 `B` 吗？没有，显然错了。错在哪？你们看低 $4$ 位这一位 `BCD` 数：你们要的是 $3+8$ 逢十进一，可 `CPU` 呢？第 $3$ 位向第 $4$ 位的进位，进的是 $16$，不到 $16$ 它不进。你们这一位已经超过 $9$ 了，它还觉得没到 $16$，就不进位。进制不同，理解了没有？高 $4$ 位同理。所以 `AL` 里躺着 `7BH`，不是正确的 `BCD` 结果，必须调整。

怎么调？我先看低 $4$ 位这一位结果：大于 $9$ 吗？`1011B` 是 $11$，大于 $9$ 了，但没到 $16$，所以没进位，错了。那我就给它加 $6$，迫使它进位。高 $4$ 位先不管，加 $0$。听懂这句了没有：这一位 `BCD` 数加不加 $6$，先看超没超 $9$；超了就加 $6$ 修正。如果没超，再看它向前有没有进位——进位是不是多进了 $6$？那我也加 $6$ 把多进的拉回来。

`CPU` 调整时测谁？低位测 `AF`，高位测 `CF`。这就是我在 `PSW` 里设 `AF` 的目的，专门留给 `BCD` 运算调整用的。

低 $4$ 位加 $6$ 你们看：

```text
  0111 1011   (7BH，未调整)
+ 0000 0110   (低位加 6)
--------------
  1000 0001   (81H，低位向高位产生进位)
```

结果是不是 `81H`？正确了。调完低位再调高 $4$ 位：高位结果大于 $9$ 吗？不大于，这一步不加 $6$。那到底加不加，还要看调整后向前有没有进位，这个进位看 `CF`。如果 `CF` 有进位，说明低位调整时向高位多进了 $6$，还要再加 $6$ 修正回来。我们这个例子，高位既没超 $9$，也没向前进位，所以高位不用调。调整完毕，结果 `81H`，读作十进制 $81`，对上了。

图后我再点一句：你们记住调整的判据就行——低位看是不是大于 $9$、看 `AF`；高位看是不是大于 $9$、看 `CF`。大于 $9$ 或者有进位，就加 $6$。这就是组合 `BCD` 加法调整的全部。
