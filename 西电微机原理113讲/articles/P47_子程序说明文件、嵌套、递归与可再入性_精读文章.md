# 子程序说明文件、嵌套、递归与可再入性

如果我编的程序是卖给某个单位的生产软件，别人拿去要用、要改、要扩充，我在子程序前面该留点什么？这就是我们这一讲要先解决的问题：子程序说明文件。然后顺着它，把嵌套、递归、可再入这三个最容易写错的地方一次讲透，最后落到书上例 4.9 偶校验题的题意上。

## 子程序说明文件

我把子程序写在下面，调用的人根本没见过我这段代码，他怎么敢调？靠的就是子程序前面那一段文档，叫子程序说明文件。

> **定义**：子程序说明文件是写在子程序前方的一组注释行，每一行都必须以分号 `;` 开始，说明这段子程序怎么调。

它一般包含六点：

1. 子程序名。写清楚名字，别人才能按名调用。
2. 子程序功能。用文字把这段子程序到底干什么讲清楚。调用者先看功能合不合要求，不合要求后面都不用看了。
3. 入口参数。子程序里要算的东西，需要主程序带进来，什么参数放在 `AX`，什么放在 `CX`，什么放在 `SI`，都要说明。
4. 出口参数。子程序算完，结果放在哪里，主程序到哪里去取。入口和出口参数的传递，不外乎三种方法：寄存器传递、存储单元传递、堆栈传递。
5. 用到的寄存器（用存储单元传递时还要写明用到的存储单元）。这一点很关键。我编的子程序可能做成一个包放在光盘上往外卖，别人买回去要用。如果我的子程序用了 `AX`、`BX`，而用户自己的程序里这几个寄存器的值又不能破坏，用户在 `CALL` 之前就会先把它们 `PUSH` 保护起来。所以写明寄存器，等于告诉用户要做好现场保护。
6. 举例。把调用过程举个例子，用户照着抄就能调。

你们做作业可以不写，但做产品开发，每个子程序前面都要带上。一到五点写清楚了，用户就会调了，所以第六点常常省略，反正你一定会了。我这么说，你们就知道第六点为什么总见不到。

## 子程序嵌套

嵌套的概念一看就清楚：子程序自己又去调别的子程序。

```text
主程序                 SUB1 (PROC NEAR)          SUB2
  |                        |                      |
  |-- CALL SUB1 ---------> |                      |
  |   (IP压栈保护)         |-- CALL SUB2 --------> |
  |                        |   (IP压栈保护)        |-- ... 
  |                        |                      |-- RET -> 回SUB1断点
  |                        |<- RET ---------------|
  |<- RET -----------------|  回主程序断点
```

我在主程序里 `CALL SUB1`，`SUB1` 是段内子程序，直接写名字就是直接寻址。当前 `IP` 压栈保护，流程转到 `SUB1` 里面。`SUB1` 一开始照例要做现场保护。执行到中间，它又 `CALL SUB2`，当前 `IP` 再压栈，转到 `SUB2` 去。`SUB2` 跑完执行 `RET`，从堆栈弹出返回地址给 `IP`，回到 `SUB1` 的断点接着往下跑；`SUB1` 跑完再 `RET`，弹出属于它的返回地址，回到主程序。

这里有两点一定要记住。

第一，嵌套级数原则上不受限，实际上受堆栈限制。就算不算现场保护，光算 `CALL` 一次压一个返回地址，`SP` 就减 2，一直嵌套下去，堆栈就往上长。堆栈空间定义小了，`SP` 就溢出了。所以定义堆栈段时要留够地方。

第二，设计自上而下，调试自下而上。我们设计时是 `SUB1`、`SUB2`、`SUB3` 自上而下拆功能，调试时一定要先调最底层的 `SUB2`，调通了再调上一层，这样上层调下层时，拿到的结果才是对的。不然你都不知道错在上层还是下层。

## 子程序递归

递归就是自己调自己。比如 `SUB2` 还没结束，里面又出现一条 `CALL SUB2`。

你们想想，这时候最怕什么？怕没有出口，写成死循环。所以递归子程序里一定要有条件判断，比如算到某一步产生 `ZF`、`OF` 这些标志，判断一下满足了就退出，一层一层 `RET` 回去。

工程上偶尔会见到递归，但面很窄，我建议你们尽量避免。能用循环、能用嵌套讲清楚的，就不要用递归。

## 子程序可再入性

可再入是什么意思？看这个场景就明白了。

```text
SUBx 执行中 (执行到某条指令)
   |
   | 某事件提中断请求，CPU响应
   v
中断服务子程序
   |-- CALL SUBx (同一个子程序)
   |-- RET (拿到正确结果)
   |
IRET 回到原 SUBx 断点
   |
   v
原 SUBx 继续执行，也能拿到正确结果 -> 可再入
```

我正在执行 `SUBx`，执行到某条指令时，来了一个中断请求。`CPU` 执行完当前这条指令，下一条先不执行了，转去执行中断服务子程序。而中断服务子程序里面，很可能也 `CALL` 了同一个 `SUBx`。如果这样调完能拿到正确结果，中断返回后，原来那个 `SUBx` 继续跑也能拿到正确结果、正确返回，这就叫可再入。

这一块结合书上 3.11 节子程序调用与返回指令和 4.5 节子程序设计技术看，概念就全覆盖了。

## 例 4.9 题意：给缓冲区字符加偶校验

概念讲完，我们看一道题。以后复习就看书上的例子，我讲书上例 4.9。

存储器在 `CPU` 外面，我在程序里定义了数据段，数据段里定义了一个 `BUFFER` 缓冲区，里面放的是字符。题目让你给每个字符加上偶校验。

这里有两个隐含条件。第一，字符是字节型的 `ASCII` 码。第二，题目没说有多少个字符，个数你自己定。书上 119 页第三行用等号定义了 `N=22`，就是 22 个。你们也可以用我上上周讲的方法，`BUFFER DB '...'` 定义一个字符串，再用 `COUNT EQU $ - BUFFER` 算出个数，两种都可以，实际工作中后一种更通用。

什么叫偶校验？`ASCII` 码原则上 7 位表示一个字符，放到按字节组织的存储器里，一个字节 8 位，最高位 `D7` 肯定是 `0`。如果不是 `0`，那肯定不是字符。加上偶校验，就是先数一下这个字节里有几个 `1`：如果是偶数个 `1`，最高位配 `0`；如果是奇数个 `1`，最高位配 `1`，凑成偶数个 `1`。这就叫偶校验，听懂了没有？

解题思想 118 页开头已经写了。118 页一开头先定义堆栈段，段名就叫 `STACK`，组合类型选 `STACK`，类名也给了。里面用 `DW 200 DUP (?)` 定义了 200 个字。堆栈到底定义多大？看实际需求，我以前讲过，要留 30% 左右的富余量，便于以后维护扩充。`STACK ENDS` 就结束了。

> **提示**：书上这里还用 `LABEL` 定义了一个 `TOP` 变量，我就不定义了。原因上次讲过：组合类型已经选了 `STACK`，说明这段就是堆栈段，代码段里就不用再对 `SS` 和 `SP` 初始化了。
