# 寄存器间接寻址与寄存器相对寻址

我前面把直接寻址讲完了，今天接着往下走。你们问得最多的那个字覆盖字节的问题，我先把它收个尾，然后把存储器寻址的第二种和第三种一次讲透。

## 直接寻址的字写字节单元覆盖问题

我数据段里定义了两个字节变量：

```assembly
DATA1 DB 12H
DATA2 DB 34H
```

`DATA1`单元原来是`12H`，紧挨着的`DATA2`单元原来是`34H`。这时候我执行：

```assembly
MOV WORD PTR DATA1, AX
```

你们问`DATA2`还在不在。我画一下你们就明白了。`AX`是`16`位，低`8`位是`AL`，高`8`位是`AH`。这条指令是存储器写，而且用`WORD PTR`把`DATA1`临时当成字单元写，字单元以`DATA1`为首地址占两个字节。

写的時候还是老规矩：低字节写进低地址单元，高字节写进高地址单元。写完了，原来`DATA2`单元里的`34H`自然被覆盖了，值变了。但`DATA2`这个字节变量本身还存在，定义并没有消失，变的是它对应单元里的内容。这就是字类型和字节类型打架时一定会发生的事。

> **提示**：类型不一致时，谁覆盖谁只看指令的实际读写宽度，不看变量当初怎么定义的。

## 寄存器间接寻址的三个寄存器

下面看存储器寻址的第二种：寄存器间接寻址（`Indirect Addressing`）。

> **定义**：要找的操作数还在某个存储器单元里，该单元的段内`16`位有效地址`EA`（也就是偏移地址）间接放在一个地址寄存器里。

能间接给地址的只有三个：基址寄存器`BX`、源变址寄存器`SI`、目的变址寄存器`DI`。

前面例子里出现过`BP`，我在这里先把话说死：`BP`不属于间接寻址，间接寻址里没有`BP`。不管用`BX`还是`SI`还是`DI`，寄存器里`16`位的内容就是操作数所在单元的`16`位有效地址，段地址默认都在`DS`段。

## 两条指令把间接寻址走通

还是这组定义：

```assembly
DATA1 DB 12H
DATA2 DB 34H
```

变量名大小写无所谓。图上就是`DATA1`单元`12H`，下一个单元`DATA2`是`34H`。

我想把`DATA1`单元的数据读出来给`AL`，用`BX`间接怎么做。第一步先把偏移地址给`BX`：

```assembly
MOV BX, OFFSET DATA1
```

这条指令源操作数的寻址方式是什么。你们说是直接寻址，都不对，是立即数寻址。为什么。变量一旦定义就有五个属性，我现在取的是`DATA1`的`OFFSET`属性，属性值是个常数，字常数就是立即数。听懂了没有。

这条执行完，`BX`里的值就是那个单元的`16`位有效地址。第二步：

```assembly
MOV AL, [BX]
```

这就是`BX`间接寻址。功能是把`BX`的内容当段内`16`位有效地址，段默认`DS`，找到那个单元。这个单元是字节还是字。不明确，看另一方。另一方是`AL`，说明找到的是字节单元，把它读出来给`AL`。执行完`AL`等于`12H`。

这里用`SI`、`DI`完全一样，换个寄存器名字而已。

## 类型不明确与双存储器错误

再看这条：

```assembly
MOV [BX], 56H
```

源是立即数寻址，目的是寄存器间接寻址。功能是把立即数写进间接找到的单元。立即数没有类型，`[BX]`说明类型了吗。没有。所以这条语法错了，错在类型不明确。

> **易错点**：只要目的操作数用了某种存储器寻址，而源是立即数，类型必须明确，不明确就加`PTR`说明。

再编一组：

```assembly
MOV BX, OFFSET DATA1
MOV SI, OFFSET DATA2
MOV [BX], [SI]
```

源是寄存器间接找到一个单元，目的也是寄存器间接找到另一个单元，想把一个单元的内容直接送到另一个单元。想得美，不行。

为什么。`39`页图`3.8`早就总结了：两存储器单元之间不能直接传送数据。想把`[SI]`单元的数据送到`[BX]`单元，中间必须经过一个通用寄存器过渡。比如按字节操作就改成：

```assembly
MOV AL, [SI]
MOV [BX], AL
```

先读进`AL`，再从`AL`写出去，两条`MOV`才完成两单元之间的数据传送。用`DI`当目的也一样：

```assembly
MOV AL, [SI]
MOV [DI], AL
```

## 寄存器相对寻址的地址算法

再看存储器寻址的第三种：寄存器相对寻址（`Relative Addressing`）。

> **定义**：操作数还在某存储器单元里，该单元的段内`16`位偏移地址由两部分相加得到：一部分在基址或变址寄存器里，另一部分是一个`8`位或`16`位的相对位移量`DISP`。

```text
EA = (BX/BP/SI/DI) + DISP(8/16)
```

读图说明：寄存器给基址，`DISP`给偏量，两者相加才是真正的有效地址。

寄存器可以是`BX`、`BP`、`SI`、`DI`四个，这里把`BP`加回来了。如果`DISP`是常数，段地址看寄存器：用`BX`、`SI`、`DI`任意一个，默认`DS`；用`BP`，默认`SS`。

## `[BP]`为什么只能叫相对寻址

比如：

```assembly
MOV [BP], AL
```

功能是把`AL`写进一个字节单元，这个单元的地址由`BP`相对给，段默认`SS`，段内偏移一部分在`BP`里，另一部分加了个位移量`0`。你们上机验证一下就信了：这条汇编后操作码里藏着一个位移量`0`。所以`[BP]`这种写法只能叫寄存器相对寻址，不能叫寄存器间接寻址。记住这一条就够了。

## 直接寻址与相对寻址找同一个单元

还是`DATA1`放`12H`、`DATA2`放`34H`，我先：

```assembly
MOV BX, OFFSET DATA1
```

让`BX`指向`DATA1`的偏移地址，段默认`DS`。现在我想把`AL`写进`DATA1+3`那个单元。用直接寻址可以写：

```assembly
MOV DATA1+3, AL
```

`+0`、`+1`、`+2`、`+3`数过去，直接给出地址，目的就是直接寻址。

用相对寻址怎么做。我已经让`BX`指向那个基点了，写：

```assembly
MOV [BX+3], AL
```

`+0`、`+1`、`+2`、`+3`，加了个`8`位位移量。`BX`内容加`3`指到那个单元，把`AL`写进去。目的操作数这就是寄存器相对寻址。

位移范围一定要记住：`8`位位移以基点为基准，正方向最多`+127`字节，负方向最多`-128`字节；`16`位位移负方向到`-32768`，正方向到`+32767`。

书写格式还有等效写法：

```assembly
MOV [BX+3], AL
MOV [BX+03H], AL
MOV 3[BX], AL
```

加号放括号里还是放括号外一样，`3[BX]`把位移放左边时加号可以缺省，汇编出来的代码相同。用哪种全看顺手。

## 相对量是变量时的段地址

相对寻址还有一点。比如：

```assembly
MOV BX, 0
MOV AL, 0
MOV DATA1[BX], AL
```

目的地址是寄存器相对给的，但相对量不是常数，是个变量。这时取该变量的`16`位偏移量当相对量：

$$EA = OFFSET(DATA1) + (BX)$$

把`AL`写进这个有效地址对应的单元。

> **结论**：这时段地址不看寄存器了，看变量。变量在哪个段定义的，段基就是哪个段。在`ES`定义就在`ES`，在`SS`定义就在`SS`，在`DS`定义就在`DS`。
