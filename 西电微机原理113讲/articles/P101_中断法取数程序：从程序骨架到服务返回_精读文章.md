# 中断法取数程序：从程序骨架到服务返回

例`8.3`的硬件上节课已经摆好了：输入设备备好数据发选通信号，`8`位锁存器锁数据，`D`触发器向`IR3`提请求，`240H`端口读数兼清请求，`XT`系统单片`8259`。今天把程序从头写到尾。记住我的要求：必须用完整的`8086`汇编程序格式写，既满足中断题目的功能，又顺手把汇编程序结构复习一遍。

## 程序骨架与数据段变量

凡涉及中断调用、子程序调用或现场压栈，必须开辟堆栈段。组合类型必须明确写成`stack`，链接程序才认它是系统堆栈段，空间大小按实际需求定：

```assembly
stack segment stack
    ; 空间大小按实际需求定义
stack ends
```

数据段规划三个变量，一个不能少：

```assembly
data segment
    inbuff db 100 dup(?)
    inpoint dw ?
    in_imr  db ?
data ends
```

`inbuff`是输入数据缓冲区，`100`个字节，外设每中断一次读进来的一个数据，按序存在这里。先假定一次任务总共进来的数据不超过`100`个，一般没装满之前用户敲回车就提前结束了。

`inpoint`是字单元，放的是`inbuff`当前待写单元的偏移地址指针。每次往缓冲写数据之前，先从`inpoint`取出目标地址再存。

`in_imr`是字节单元，暂存`8259A`的`IMR`原值。`PC`机启动时`BIOS`已经对主片`8259A`做完初始化，`IMR`里有特定的屏蔽位。我们的应用要改`IMR`，工程规范是：先读出来暂存，改完用新的；程序退出时再把暂存的写回去，恢复系统原状。绝不能盲目全盘覆写。

代码段照规矩来：

```assembly
code segment
    assume cs:code, ds:data, ss:stack
start:
    mov ax, data
    mov ds, ax
```

`8086`不支持立即数直接送段寄存器，必须经`AX`中转，这是死规矩。

## 中断类型号：IRQ3就是0BH

题目把外设挂在`IR3`上，类型号怎么定？主片`8259A`的类型号基值固定`08H`，`IRQ0 = 08H`、`IRQ1 = 09H`、`IRQ2 = 0AH`，所以`IRQ3 = 0BH`。本例的类型号就是`0BH`。

`8086`的中断向量表在内存最底端`00000H`～`003FFH`，共`1024`字节，`256`个向量，每个向量`4`字节（`2`字节偏移`IP`加`2`字节段基址`CS`）。类型号`n`的向量首地址，数学关系是死的：

$$向量偏移 = 4 \times n$$

本例就是`4 × 0BH`。

## 装向量前的现场保护与指针切换

黑板上接着代码段初始化往下写：

```assembly
    push ds
    mov ax, 0
    mov ds, ax
    mov bx, 4 * 0Bh
```

三条各有道理。`push ds`是保护当前数据段：此时`DS`放的是用户`data`段基址，装向量必须把`DS`指向向量表所在的`0000H`段，所以先压栈保护。`mov ax, 0`再`mov ds, ax`，是定位到向量表段，`DS = 0`之后基于数据段的偏移寻址直接落进向量表。

`mov bx, 4 * 0Bh`有个纠偏：起初想用`AX`，不行。`8086`能做寄存器间接寻址的只有`BX`、`BP`、`SI`、`DI`，`AX`不能。所以必须用基址寄存器`BX`存偏移量，后面才能用`[bx]`形式往向量表写入口地址。

## 建向量的方法一：直接写内存

设服务程序入口标号为`ABC`，底层写法是：

```assembly
    mov ax, offset ABC
    mov [bx], ax
    mov ax, seg ABC
    mov [bx+2], ax
```

`4 × n`单元写偏移，`4 × n + 2`单元写段基址。但这组写入横跨多条指令，有临界区问题：只写了偏移、还没写段基址的半就绪状态下来了中断，`CPU`按半残废的向量跳转，直接跑飞。所以写之前必须`CLI`关中断，写完`POP DS`恢复数据段、再`STI`开中断。向量表没彻底建好之前，绝对不允许响应中断。

## 建向量的方法二：DOS 25H功能调用

教材前五行用的是另一条路：向`DOS`请求服务挂向量。`25H`号功能调用，`AH = 25H`是功能号，`AL`是类型号，本例就是：

```assembly
    mov ax, 250BH
```

入口指针这样装：段地址经`AX`中转给`DS`：

```assembly
    mov ax, seg IN_INT
    mov ds, ax
    mov bx, offset IN_INT
    int 21H
```

一条`INT 21H`，委托操作系统内核接管。注意`DOS`调用改了`DS`，所以教材调用完第`6`行重新初始化数据段：

```assembly
    mov ax, data
    mov ds, ax
```

把`DS`重新对回用户数据段。两条路对比：直接写内存是裸机底层控制，`DOS 25H`是走操作系统抽象层。按原理做就行，不必拘泥哪一种。

| 建向量方法 | 控制层级 | 关键动作 | 代价 |
| :--- | :--- | :--- | :--- |
| 直接写内存 | 裸机底层 | `CLI`后写`[BX]`/`[BX+2]`，`POP DS`+`STI` | 自己管临界区，半残向量会跑飞 |
| `DOS 25H`调用 | 操作系统层 | `AX = 250BH`，装`DS`配指针，`INT 21H` | 调用完重装`DS` |

## 指针变量的装载：立即数寻址

```assembly
    mov IN_POINT, offset IN_BUFF
```

汇编里变量经伪指令一定义，在符号表里就内生具备好几个属性（含段属性、偏移属性等）。`OFFSET IN_BUFF`不是运行时动态算的，是汇编链接阶段直接算出来的固定常数，所以源操作数是立即数寻址。这条指令就是把缓冲首地址常数存进`IN_POINT`这个字单元，完成指针初值装载。

## 开IR3：读IMR、改一位、写OCW1

主片`8259A`中`A0 = 1`的端口是`21H`。读这个端口读的是`IMR`，写这个端口写的就是`OCW1`，同一个端口，读和写叫法不同。

硬件上无需重做`ICW1`～`ICW4`：冷启动时`BIOS`已经初始化过主片，用户程序只在现有基础上动`OCW1`。但`BIOS`设的`IMR`原状态未知，不能盲写覆盖，先读出来保护现场：

```assembly
    in al, 21H
    mov IN_IMR, al
```

`AL`的`8`位`D0`～`D7`严格对应`IR0`～`IR7`：位是`1`表示该通道被屏蔽，是`0`表示未屏蔽。要开`IR3`，就是把`D3`清零，其余七位维持原样。保持位与`1`，清零位与`0`，掩码就是`1111 0111B = F7H`：

```assembly
    and al, 0F7H
    out 21H, al
```

一写进去，`OCW1`的第`3`位肯定是`0`，`IR3`未屏蔽，这一点先做到。

## 等待循环：DOS 6号功能查回车

做到这一步，就该等待中断到来。等待用`DOS 6`号功能调用，我在讲`DOS`功能调用时讲过：控制台输入输出，既能从键盘输一个字符，也能向屏幕输出一个字符。输出时`DL`放字符的`ASCII`码；从键盘输入时`DL`放`0FFH`：

```assembly
    mov ah, 06H
    mov dl, 0FFH
    int 21H
```

`6`号功能从键盘读字符但不等待，直接滑下来，输没输入影响`ZF`。书上没测`ZF`，直接测`AL`里有没有输入：没输入肯定不是回车，有输入就看是不是回车：

```assembly
    cmp al, 0DH
    jne W
W:
```

`0DH`就是回车。不相等说明不是回车，跳到`W`标号再读键盘字符再测。`CPU`就一直在这个循环里转：既没按键盘，也没有中断到来，就一直转。转干什么？等待中断。

## 中断服务：取数、暂存、指针加一

一旦中断来了，不管`CPU`在循环体哪条语句上，先把现行指令执行完，保护下一条指令现场，转去服务。服务子程序入口一开始先做信息保护，和子程序调用一样，`AX`、`BX`、`CX`不敢破坏，`PUSH`、`PUSH`、`PUSH`保护起来。

然后取指针：

```assembly
    mov bx, IN_POINT
```

`IN_POINT`里放的是前面装进去的`IN_BUFF`偏移，`BX`现在指向待写单元，段地址在`DS`。接着读端口：

```assembly
    mov dx, 0240H
    in al, dx
```

`240H`给`DX`，读`240`端口。`CPU`做`I/O`读：`240`译码出低电平，低低相或来一个低，这个低电平把数据读到`AL`，同时让触发端清零。读到了，就存起来：

```assembly
    mov [bx], al
    inc bx
    mov IN_POINT, bx
```

`[BX]`间接单元收下数据，下次中断再来的数据该写下一个单元，地址是`BX + 1`，回写`IN_POINT`，下次再从这里取。这就是它的设计思想。

这次中断完了：原来`PUSH`保护的，`POP`、`POP`、`POP`恢复；然后`IRET`中断返回。返回到哪？回到引起中断时断开的地方，又进循环。没按键，或者按的不是回车，下次中断再来，又转进服务程序读数。

> **提示**：`XT`机单片`8259`同样工作在非自动结束方式，按前两讲的规矩，`IRET`之前一般还要向`OCW2`写`EOI`通知`8259`先结束（主片是`MOV AL, 20H` / `OUT 20H, AL`），再执行`IRET`，`ISR`对应位才清零。

## 回车退出与程序收尾

直至按了回车，退出来。按程序设计：

```assembly
    mov ah, 4CH
    int 21H
```

程序结束。如果退出时系统还有别的任务，再加别的任务程序；没有，程序就结束。程序结束的下方，接着是中断服务子程序，写完后代码段撤销：

```assembly
code ends
end START
```

整个程序结束。我这套程序设计和书上不一定一样，每个人有每个人的思路，按原理做就行。

我要强调的是：利用中断方法实现`CPU`与设备之间的通信（就是从外部读数据），在实际工程中经常用到。不会玩中断，根本谈不上你水平怎么样。但是结合中断的应用，考试又不好考，一考全是这样的题，我估计大部分人都糊了。课堂上只是帮你们引进门，工程中大量在用，还要求你们下去加强，这是这一块。

## 本讲提到的题目

**例8.3（完整程序实现）**：硬件按上讲摆法（`8`位锁存器锁数据、`D`触发器`Q`接`IR3`、`240H`输入端口、`XT`单片`8259`）。要求：用中断方法把设备数据取走暂存内存，备好再取，键盘回车结束。

解析：主程序用完整汇编格式（堆栈段`stack`组合类型、数据段`inbuff`/`inpoint`/`in_imr`、代码段`ASSUME`与`AX`中转`DS`）；`IRQ3`对应类型号`0BH`，向量地址`4 × 0BH`，直接写内存（`CLI`保护、`[BX]`/`[BX+2]`、`POP DS`恢复+`STI`）或`DOS 25H`（`AX = 250BH`、`INT 21H`、重装`DS`）挂向量；`MOV IN_POINT, OFFSET IN_BUFF`装指针；读`21H`存`IN_IMR`、`AND AL, 0F7H`回写`OCW1`开`IR3`；主循环`DOS 6`号（`DL = 0FFH`）查`AL`，`CMP AL, 0DH` / `JNE W`等回车；服务程序`PUSH`保护后`BX = IN_POINT`、`DX = 240H`读数存`[BX]`、`INC BX`回写指针、`POP`恢复后`IRET`；回车后`MOV AH, 4CH` / `INT 21H`结束，退出前把`IN_IMR`写回`OCW1`恢复现场。
