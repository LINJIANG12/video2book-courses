# 8259A操作命令字与中断应用例题引入

上节课讲到第八章中断系统及`8259`应用的第二点：可编程中断控制器芯片`8259`。初始化命令字`ICW1`到`ICW4`已经讲完，今天先复习一遍，再看编程的第二点操作命令字，最后进到本章第三点应用，看一道例题。复习不是重复，是把四步的顺序和端口一次焊牢。

## 四步初始化复习：端口与顺序一次焊牢

`ICW1`朝里写初始化命令，必须保证`A0 = 0`，再靠特征位识别。它定两件事：一是`IR0`到`IR7`共`8`个请求输入信号的有效形式，高电平还是上升沿，一般选上升沿；二是这一片`8259`是单片工作还是级联工作。`286`一直到今天的计算机主板用两片`8259`级联，`286`以前的`IBM PC/XT`主板只有一片单片工作。

`ICW1`完了紧接着初始化`ICW2`，紧接着，靠顺序认。`A0`要等于`1`。`ICW2`定`IR0`级的中断类型号基值。

两片以上级联，马上初始化`ICW3`：主片的`ICW3`定的是`IR0`到`IR7`中哪一个输入被后面的从片级联了；从片的`ICW3`是给从片说明你的`INT`输出被级联在主片的`IR`几上。`ICW3`的初始化也靠顺序，`ICW2`之后紧接着写。单片工作就不用`ICW3`了。

`ICW3`完了初始化`ICW4`，`A0 = 1`。它定三件事：嵌套方式（完全嵌套还是特殊嵌套，一般定完全嵌套，也就是正常嵌套，`IR0`最高一路固定下来）；缓冲还是非缓冲（我们都是非缓冲）；中断结束自动还是非自动（我们都是非自动）。我说的我们用的都是什么，指的就是主板上`BIOS`对`8259`的初始化就是那样做的。

## OCW1：屏蔽字寄存器，可读可写

`8259`一旦初始化完，就可以按定的方式工作了。工作期间给`OCW1`到`OCW3`写操作命令字，可以改变工作方式。先看`OCW1`。

朝`OCW1`里`OUT`写，是定`IR0`到`IR7`中哪个输入被屏蔽、哪个未屏蔽：`8`位中某一位写`1`，对应的`IRi`（`i = 0～7`）就被屏蔽；对应位写`0`，对应的`IRi`就未屏蔽。只有未屏蔽的请求输入，`8259`才能响应；只有`8259`能响应的，`CPU`才能响应，一级一级的。

这个寄存器端口也可以`IN`读。读的时候不叫`OCW1`，叫`IMR`。在计算机系统上`IN`读`21H`，读到的就是主片`8259`的`IMR`；看读回每一位是`1`是`0`，就知道`BIOS`一初始化把哪个中断屏蔽了、哪个没屏蔽。

朝`OCW1`里`OUT`写的操作，肯定在`ICW4`初始化完之后就得进行。

## OCW2：非自动结束的EOI通知

`OCW2`共`8`位，我们感兴趣的是第`5`位`EOI`位。朝`OCW2`写操作命令字是向`A0 = 0`的端口写：初始化完成以后，再向`A0 = 0`的端口`OUT`写，写的就是`OCW2`。

在正常嵌套方式下，向`EOI`位写一个`1`，意思就是`CPU`通知`8259`结束中断，通知`8259`结束正在服务的中断。正在服务的那一位`ISR`是不是就清零了？中断服务寄存器在服务期间是置`1`的，清零了，`8259`对中断源的服务就结束了。

上节课讲过两种结束方式：自动结束和非自动结束。非自动结束就是在`CPU`中断服务结束前、执行`IRET`指令前，由`CPU`朝`OCW2`的`EOI`位发一个`1`，通知`8259`先结束，然后自己才执行`IRET`。

主片`8259`的通知程序就是两条：

```assembly
MOV AL, 20H
OUT 20H, AL
```

不用的位取`0`，`EOI`位是`1`，拼出来正是`20H`；`20H`是主片`A0 = 0`的端口。`CPU`执行完这两条，就通知主片结束了。如果是从片，地址改成`A0`的从片端口就行。

`OCW2`其他位的含义，在正常嵌套下我只要求掌握这一种，就不讲了。感兴趣的自己去修：中断结束后还可以指定下一次谁优先级最高，在`OUT`写的时候既结束本次服务、又指定下次最高优先级，算一种循环优先级。明白有这回事就行。

## OCW3：正常嵌套下用不上的屏蔽方式字

向`OCW3`里`OUT`写操作命令字，是改变`8259`的屏蔽方式的。这个我就不讲了，在正常嵌套方式下用不上，感兴趣的自学。

到这里，`8259`怎么编程——初始化编程，加上初始化后工作期间操作命令字的编程，用到哪些讲哪些，已经讲完了。

## 例8.3：中断法取数的硬件摆法

本章最后看一个例题，应用里面的例`8.3`。选哪个例题我想了一下：第七章最后一个例题讲过`A/D`变换器的例程，用`EOC`转换结束信号（开始转换变低，转换完变高，低到高的上升沿）向`8259`请求中断，`CPU`响应后在中断服务程序里把转换结果读走，也是一个思路。今天看书上的例`8.3`。

题目是这样：有一个输入设备，数据准备好放在这里，但没有锁存功能，它会向外部发一个选通信号。我们用户可以这样设计电路：在这里放一个锁存器（`8`位数据就用`8`位锁存器），用这个选通信号把设备准备好的数据一下锁到锁存器输出端。选通信号第二次到来之前，锁存器输出端的数据一直稳定着，这是第一点。

第二点：在这里再设计一个锁存器，利用这个选通信号一到来，使它的`Q`输出原来是低、现在变高，发一个中断请求。书上画得很清楚：一端是正`5`伏，相当于`D`触发器的`D`端，选通信号好比`CP`端；低电平选通的上升沿一来，就把高电平打到`Q`端锁住了，相当于一个`D`触发器。用这个`Q`输出做中断请求信号，送到`8259A`的`IR3`端。

用户还在这里设计一个译码器和一个输入端口（输入缓冲器，用`245`、`244`都能做），分配的地址书上给的是`240H`。译码器对系统地址低`10`根线（`A0`到`A9`）做译码，译出`240H`；`PC`机总线的话`AEN = 0`要参加译码。题目又在这里设计了一个或门：译码器输出的低电平和`IOR非`相或，或出来是低，做这个输入端口的片选（`245`的话接到`E非`端）。`CPU`从这里把锁存的数据取走，走的是`D0`到`D7`。同时这个低电平还作为`D`触发器的`R非`清零端：一次读操作，既取走了数据，又把中断请求清零了，一次中断请求完毕。

题目还说系统在`IBM PC/XT`系统中：只有一片`8259`单片工作，端口就是`20H`和`21H`。要求是：设备把数据准备好放好后，用中断方法把数据取走，取走后传到内存暂存起来；它再次准备好数据，再取走；什么时候不做了？检测键盘有回车就不做了，输入回车字符表示结束。

```text
输入设备 --数据--> [8位锁存器] --D0~D7--> 输入缓冲器(240H) --> CPU
     \--选通信号--> 锁存有效数据      ^
      \--选通信号--> [D触发器Q] --IR3--> 8259A --INT--> CPU
CPU读240H --> 或门(译码+I0R非) --> 片选有效 --> 取数 + 清D触发器(R非)
```

读图说明：数据通路靠`8`位锁存器保持稳定，中断通路靠`D`触发器把一次选通变成持续有效的`IR3`请求，`CPU`读`240H`端口的那个低电平同时完成取数和清请求。

## 本讲提到的题目

**例8.3（题干与做法）**：输入设备备好数据并发出选通信号，经`8`位锁存器与`D`触发器向单片`8259`（`XT`系统，端口`20H/21H`）的`IR3`提中断请求；输入端口地址`240H`（`A0`～`A9`译码，`AEN`参加译码，`IOR非`经或门做片选，用`245/244`做输入缓冲）。要求用中断方法把数据取走暂存内存，设备再备好再取，直至键盘输入回车结束。

做法按题面信息分三块：主程序先对单片`8259`做初始化并开放`IR3`，建立好`IR3`的中断向量；主循环里等待中断、兼查键盘是否为回车；中断服务程序里读`240H`端口取数（读操作同时清`D`触发器），把数据暂存内存后`IRET`返回。完整的初始化与服务程序写法是下一讲的内容。
