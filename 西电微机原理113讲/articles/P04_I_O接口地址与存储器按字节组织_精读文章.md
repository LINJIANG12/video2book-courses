# I/O接口地址与存储器按字节组织

任何输入/输出（Input/Output，I/O）设备与中央处理器（Central Processing Unit，CPU）之间都不能直接通信。你们想想，显示器、音箱、键盘，哪一个是直接挂在系统总线上的？一个都没有。设备要和 CPU 之间通信，你们就必须在设备与 CPU 之间，或者说在设备与系统总线之间，设计一个能实现通信的连接电路，这个电路就叫 I/O 接口电路。

是 1 号设备的，你们就给 1 号设备设计它对应的 I/O 接口电路。假如这是个输出设备，CPU 通过数据总线把要送给 1 号输出设备的数据，先发送给 1 号设备对应的 I/O 接口电路，再由这个接口电路接力给 I/O 设备。如果这是个输入设备，数据方向是不是就颠过来了？输入设备的数据先经接口的数据输入引脚进来，再经接口的数据输出连到数据总线，被 CPU 读走。

```text
输出方向:  CPU  --数据总线-->  1号接口电路  --数据输出引脚-->  1号输出设备
输入方向:  1号输入设备  --数据输入引脚-->  1号接口电路  --数据总线-->  CPU
```

读图说明：数据不管哪个方向走，都要经对应接口电路中转一次，CPU 只和接口电路打交道，从不直连设备。

显卡是不是连接显示器和系统总线的接口电路？音箱要出声是不是要有声卡？都是同一个道理。不管 CPU 给哪个设备发数据、从哪个设备收数据，数据都是沿数据总线传送的，区别只在于它到底是和哪一个接口电路之间读写。

## I/O 接口地址：读写接口变成读写地址

那么问题来了：数据总线只有一组，CPU 通过数据总线读写设备数据，到底是和哪个设备之间读写呢？办法只有一个：给每个设备对应的接口电路分配 I/O 接口地址。

> **定义**：I/O 接口地址就是分配给 I/O 设备对应的 I/O 接口电路的地址。

CPU 对这个 I/O 接口电路的读写操作，实际上就演变成了对它对应的 I/O 接口地址的操作。CPU 对某个存储器单元的操作，是不是也演变成了对那个存储器地址的操作？都是按地址说话，道理完全一样。

## 同一组地址线：CPU 靠执行的指令区分对象

给 I/O 接口编排地址，在 8086 系统当中也是通过地址线来传送的。但在好多型号的 CPU 当中，采用的是同一组地址线，既给存储器发送地址，也给 I/O 设备发送地址。

如果用的是同一组地址线，CPU 输出的地址到底是给存储器的，还是给 I/O 的？首先 CPU 自己是知道的，它怎么知道的？它是通过执行不同的指令知道的。对存储器读写有存储器读写的指令，对 I/O 读写有 I/O 读写的指令，CPU 执行不同的指令就知道自己在对谁操作，从而通过相应的控制引脚发出对存储器的读写控制命令，或者对 I/O 的读写控制命令，命令不一样。

我们用户怎么区分？就看控制引脚上的控制命令。地址线上送出来的地址是给存储器的还是给 I/O 的，你们抓住控制线上的命令就能抓住。

| 地址用途 | 8086 地址线条数 | 如何区分 |
| :--- | :--- | :--- |
| 存储器地址 | 20 根 | 存储器读写控制命令有效时送出 |
| I/O 接口地址 | 16 根 | I/O 读写控制命令有效时送出 |

## I/O 地址译码：一把地址翻译成一路选通

对于 I/O 接口电路而言，地址码的识别一般落到一个引脚上。送来的是一把地址，比如 8086 对 I/O 分配地址有 16 根线，而识别输出是不是只有一个引脚？一把地址怎么转化成一个选通命令？这里你们就要设计一个电路。

这个电路首先接收 CPU 送到地址线上的地址，然后把这个地址翻译成一个控制命令，我画个圈表示低电平有效。假如这个引脚上输出低电平，是不是就把这个 I/O 接口电路选通了？CPU 经数据线送的数据就经这个通道传送。当这个通道被选中时，其他通道不可能被选通，因为此时的地址码和其他通道分配的地址码是不同的。CPU 要操作哪一个 I/O 接口，地址线上就送该通道分配的地址，地址吻合了，对应输出就有效了，就把它选通了。

> **定义**：把一把地址转换、翻译成给 I/O 接口电路的一路控制信号的这部分翻译电路，称为 I/O 地址译码电路。

```text
地址线(16根) ----+
                 |    I/O地址译码电路     选通信号(低有效)
                 +-->+----------------+---O--> 选中本接口
I/O读写控制命令 --+  (地址吻合才有效)         其他接口均不选中
```

读图说明：地址与 I/O 操作的有效控制命令要一起参加译码，只有地址吻合且确系对 I/O 操作时，选通才有效。

存储器接口设计当中同样牵涉存储器地址译码。存储器地址译码怎么译，是第六章的内容；I/O 地址译码怎么译，是第七章的内容。有一点你们现在就要记住：用户怎么知道地址线上的地址是给 I/O 的地址？看控制线上有没有对 I/O 操作的有效控制命令，这个有效控制命令也要参加译码。

> **提示**：译码电路怎么设计，本质是数字电路（Digital Circuit，数电）课的问题。门电路、138 译码器、24 译码器那一套在这里直接用。学到第七章，你们最起码要掌握用门电路给 I/O 地址译码。

我举个最简单的例子，稍微耽误一分钟。假如某计算机系统给 I/O 分配地址只有 4 根线 `A0` 到 `A3`，给某一个 I/O 接口电路分配的地址是 9，也就是二进制 `1001`。这把地址怎么转化成一个控制信号？最简单的就是门电路。假设低电平有效，我用一个或门：两个 `0` 直接相或得 `0`，两个 `1` 先反相再送进去相或，当或门输出低电平时，地址线上的地址肯定是 `1001`。

```text
A3(1) --o-->|
A2(0) ----->|  或门  --O--> 选通(低有效, 地址=1001时有效)
A1(0) ----->|
A0(1) --o-->|

注: o 表示反相器
```

读图说明：只有 `A3 A2 A1 A0 = 1001` 时或门四个输入全为 `0`，输出才为低，译码命中。当然完整设计里还要把 I/O 操作的控制信号引进来一起译码，保证地址线上的地址确系 CPU 对 I/O 操作时送出的。

## 裸机与系统：配齐设备、加上电、灌上程序才工作

这样一来你们看，微型计算机的硬件部分，微型计算机裸机，是不是就组成了？但这个机器能工作吗？不行。必须给它配上相应的设备，加上电，给里面灌上程序，才能工作。一旦这些配齐了，程序也加载进去了，才组成微型计算机系统。现在只能叫微型计算机，微型计算机是个裸机，单独不能工作。

实际上我们平时说买了一台微机，说买了一台微型计算机，严格说错了，是买了一个微机系统。当然那样叫是不是别扭？人们就简称微机。你们把这个概念掰扯清楚就行。

## 存储器按字节组织：宿舍楼与门牌号

这一讲我还要给大家建立存储器的概念。存储器我们前面一再在讲，里面有好多单元，每个单元是不是都有它对应的地址码？理解它最简单的办法是打个比方。

假如我们整个学校好比是一台微型计算机系统，行政楼、校长办公室所在的行政楼，就是中央处理器。我们每个人干什么、怎么干，都是人家行政楼发文件、发指令，我们照着干。我们每个人都是这个系统中的一个比特位。你们这些比特位在哪放着？在存储器里。对学生而言，存储器在哪？就是宿舍楼。

假如宿舍楼纵向剖开，你们能看到什么？是不是一间一间的房子？把这个概念延续到存储器当中：假如我这个存储器芯片能剖开，能看到的就是一个一个的存储器单元。当然存储器不能真剖开，剖开就坏了，即使剖开里面也不是这形状，里面是电路，我是打个假如。

```text
宿舍楼纵剖面            存储器剖面(示意)
+--+--+--+--+          +------+------+------+
|房|房|房|房|  <---->  |单元 |单元  |单元  | ...
+--+--+--+--+          +------+------+------+
  每间有门牌号            每个单元有地址码
  每间住8名学生          每个单元存8位(D0~D7)
```

读图说明：房间对应存储单元，门牌号对应地址码，每间住 8 人对应每单元存 8 位二进制。

每个存储器单元存放的是二进制数据。这个单元能存多少？最低位第 0 位到第 7 位，能存 8 位数据。所以任何型号 CPU 组成的智能系统中的存储器子系统都是按字节组成的。更严密一点，计算机中的存储器是按字节组织的，一个字节就是 8 个比特位。

你们给系统配置存储器时，如果买的存储器芯片每个地址单元只有 4 个比特位，那你们就要想办法两片并起来拼成 8 位。总之结果必须是按字节组织，这是铁律。

CPU 对存储器的哪个地址对应单元去操作，就好比你们 8 个学生住哪个房间，回去肯定走不错，因为有门牌号。CPU 对哪个存储器单元读写也不会错，我们编程序时是不是要给它的地址码？每个单元都有它的地址码，简称地址，也叫地址号，号码不分家嘛，简称地址。这个地址是 CPU 输出选址用的，是二进制编码。

## 地址线定空间，数据线定范围

假如 CPU 只有 4 个引脚输出地址码，CPU 能管理的外部存储器空间有多大？$2^4 = 16$ 个单元，是不是空间太小了？要让 CPU 能管理的外部存储器空间大起来，地址总线的条数是不是要多？所以 CPU 地址总线条数的多少，决定着 CPU 能管理的外部存储器空间的大小。我用的是“管理”二字，用标准术语讲，CPU 对哪个地址单元要读写操作，首先要寻找到这个单元的地址，才能对这个单元操作，寻找到这个单元的地址简称为寻址。

寻址寻找的是将要读写操作单元的地址，寻找的方法越多，程序编写是不是越灵活？因此一种型号 CPU 的汇编语言寻址方式越多，汇编程序写起来越灵活。把刚才那句话重说一遍：一种型号 CPU 输出的地址线条数的多少，决定着 CPU 能寻址的外部存储器空间的大小。我把“管理”二字用“寻址”替代了。

> **结论**：地址线条数决定可寻址的外部存储器空间大小；数据线条数决定一次能传送的有符号数范围。

反过来，一个 CPU 能和外部传送数据信息的数据引脚条数的多少决定了什么？决定着 CPU 一次能和外部存储器或者和 I/O 之间传送的有符号数的范围。数据线条数越多，数的范围是不是越宽？

| 数据线条数 | 无符号数范围 | 带符号数范围 |
| :--- | :--- | :--- |
| 8 位 | $0 \sim 255$ | $-128 \sim 127$ |
| 16 位 | $0 \sim 65535$ | $-32768 \sim 32767$ |

地址线条数起什么作用，数据线条数起什么作用，你们要搞清楚，这是两码事，千万不要混。

## 8086 的字存放：低字节进低地址单元

显然存储器是按字节组织的。而我们这门课要讲的 CPU 是 16 位的 8086，它外部的数据线是不是 16 条？那就允许 CPU 通过 16 条数据线一次发送 16 位数据，当然也允许只传 8 位。传 16 位数据、一次往存储器写 16 位，显然是不是要占两个字节？

这是一个 16 位数据，低 8 位 `D0` 到 `D7`，高 8 位 `D8` 到 `D15`，是由两个字节组成的。我们把这 16 位数据称为一个字数据，一个字。低 8 位叫低字节数据，高 8 位叫高字节数据。

在 8086 系统当中规定，任意两个相邻的字节单元都可以组成一个字单元。把一个字写进这个字单元时，这个字节单元有它的地址，那个字节单元也有它的地址。地址是无符号数，无符号数只有高低之分，只有带符号数才有大小之分。我们说地址 `0`、`1`、`2` 朝下编排，上面这个字节单元的地址相对下面这个是不是低？所以这个字单元里，地址低的那个叫低地址单元，地址高的那个叫高地址单元。而低地址单元的地址，才是这个字数据存放单元的地址，也就是这个字单元的地址。

存放时一般遵循：低字节存放在低地址单元，高字节存放在高地址单元。

```text
字单元(地址 = 低地址单元地址 N)
+------------------+------------------+
| 高地址单元 N+1   | 低地址单元 N     |
| 高字节 D8 ~ D15  | 低字节 D0 ~ D7   |
+------------------+------------------+
```

读图说明：一个字占相邻两字节，字地址取低地址单元之地址，低字节进低地址，高字节进高地址。

如果从字单元读数据，读出来低地址单元的数据是不是这个字数据的低字节？明白了吧？这些概念是第二章才涉及的，我今天都先抛出来：存储器一个单元就是一个字节单元，存储器按字节组织；任意两个相邻字节单元可拼成一个字单元，字单元分低地址单元和高地址单元；一个字在字单元存放遵循低字节在低地址单元。
