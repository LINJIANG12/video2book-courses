# DOS 09H显示字符串与0AH输入串

有人问我：我按键时 `CPU` 没执行它，跑过去了，是不是抓不住？不对。你按下去抬起来再快也得几十毫秒，`CPU` 跑一遍才多快？从你按下去到抬起来，`CPU` 不知道跑了多少遍了，肯定抓得住。这个疑问消除了，这是 `06H` 的事。今天我们看串：前面都是一个字符一个字符来，工程里经常要一串，菜单 1 干什么 2 干什么，最后请选择 1 到 5，每行都是一串。一串怎么打出去？看 `09H`。

## 09H功能与DB定义字符串

`09H` 就是向屏幕输出一串。当然你用 `02H` 一个一个打，打多少次也行，可太啰嗦了。一般用 `09H`。

调之前先把串定义在数据段：

```assembly
DATA SEGMENT
STRING DB '2. EDIT'
       DB 0DH, 0AH, '$'
DATA ENDS
```

串肯定用 `DB`，用 `DW` 也能定，一对单引号最多俩字符，太啰嗦。`'2. EDIT'` 是菜单项，后面 `0DH`、`0AH`、`'$'` 干什么后面说。

4.39 题第二问让你们从键盘输一串，找 `ASCII` 最大的显示出来。做菜单要在屏幕打一行，也是串。先把数据段收尾，代码段：

```assembly
CODE SEGMENT
    ASSUME CS:CODE, DS:DATA
START:
    MOV AX, DATA
    MOV DS, AX
    MOV AH, 9
    LEA DX, STRING
    INT 21H
```

堆栈段没写，该声明还得声明。`DS` 初始化完，要显示了，先 `MOV AH,9`，立即寻址给功能号。第二步入口参数：`LEA DX,STRING`，被显示串首字符偏移给 `DX`，段地址在 `DS`，`DS:DX` 指串首。

内存里就是：`STRING` 单元放 `'2'`，下个放 `'.'`，下个放 `'E'`，一直下来最后放 `'$'`。准备好 `INT 21H`，`09H` 就从 `DS:DX` 取一个打一个。光标一开始在这，打 `'2. EDIT'`、回车、换行全出来了。可它取一个打一个光标右移一格，打完最后一个光标到这了，`09H` 没结束，再取再打。后面不是你的字符了，可存储器里还有值，读出来当 `ASCII` 打，满屏乱码。上机你们可以试试。

为什么？只告诉从哪开始，没告诉哪结束。所以必须告诉结束符，就是那个 `'$'`。遇到 `'$'` 就认为 `09H` 结束，`'$'` 本身不显示。

## 回车换行符位置安排

`'$'` 不显示，光标就停在最后可见字符后面。想打完这行自动落下一行行首，不停末尾，就在 `'$'` 前加回车换行：

```assembly
STRING DB 'Hello, World!', 0DH, 0AH, '$'
```

调 `09H`，遇到 `'$'` 前先输出 `0DH`、`0AH`，屏幕回车换行，光标到下一行起始。除了串尾直接定，也可单独编个回车换行子程序，打完 `CALL` 一下，两种都能用。主程序完退出照例：

```assembly
MOV AH, 4CH
INT 21H
CODE ENDS
END START
```

`09H` 三点：功能是打一串，入口是 `DS:DX` 首址，结束是 `'$'`。4.39 题按 1 进功能一，按 2 进功能二，先多次调 `09H` 打菜单，`1. ...`、`2. ...` 都得在数据段定好提示串。进功能一要把小写变大写，先 `09H` 打请输入字符串，打完处理完，输出前再 `09H` 打小写变大写后的结果是，最后才打结果串。人机对话就是这么搭起来的。

## 0AH输入串与缓冲区结构

`01H`、`07H`、`08H` 都是收一个字符进 `AL`，收一串得循环多次，太烦。`0AH` 专门从键盘输一串，自带等待，按回车 `0DH` 才结束。

一串寄存器装不下，必须在数据段开键盘输入缓冲区：

```assembly
DATA SEGMENT
KEYBUF1 DB 20H       ; 第1字节：允许最大个数(含回车)
        DB ?         ; 第2字节：系统填实际个数
        DB 20H DUP(?); 存输入字符
DATA ENDS
```

第 1 字节最大个数，比如 `20H` 就是 32 个，一个字节描述，理论最大 `0FFH=255` 个。第 2 字节实际个数，留着 `DOS` 回车后自动填，不含回车符。后面才是真正放字符的地方。

> **易错点**：`09H` 串尾必须有 `'$'`，`0AH` 缓冲首字节必须先填最大数。两个都是不填就乱，前者满屏乱码，后者多收少收全错。
