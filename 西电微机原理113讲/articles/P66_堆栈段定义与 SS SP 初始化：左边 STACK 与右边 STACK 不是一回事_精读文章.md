# 堆栈段定义与 SS SP 初始化：左边 STACK 与右边 STACK 不是一回事

上一讲我们把 A、B、C 三个同志的多模块例子摆出来了：`A.OBJ` 里面有个 `SEGMENT` 定义的堆栈段，`B` 程序和 `C` 程序里面也有各自的堆栈段。那我们链接，把三个 `.OBJ` 链接成一个可执行程序后，堆栈段应该怎么处理？是取三个程序堆栈空间的总和？还是取三个 `.OBJ` 当中谁空间最大取谁？是不是？等等有好多约定，那些约定都是用组合类型来说明的。

那么在组合类型里面，我们这门课按大纲要求，只要求学到单模块程序设计。你编的程序模块和任何模块都不发生关系，你就是你，单模块程序设计。那么在单模块程序设计当中，我要告诉大家的组合类型有两种。

## 1 STACK 型：告诉 LINK 本段就是堆栈段

一种是 `STACK` 型。`STACK` 型告诉链接程序，就告诉 `LINK`：本段为堆栈段。决定死的。比如我编一个：段名叫 `STACK`，`SEGMENT`，组合类型叫 `STACK`，下面来个 `DB 256 DUP(?)`，`STACK ENDS`。哎，我定义了一个堆栈段。

```assembly
STACK  SEGMENT  STACK
       DB  256 DUP(?)
STACK  ENDS
```

大家看，在我定义的这个堆栈段当中，`SEGMENT` 左边的 `STACK` 是段名，`SEGMENT` 右边的 `STACK` 是组合类型。左边这个段名你可以随便起，右边这个是伪指令的保留字，告诉 `LINK` 本段就是堆栈段。

那么这样做有什么好处？在 `MASM 5.0` 以上版本汇编链接时，链接程序知道了堆栈段，系统会做什么？对 `SS` 和 `SP` 初始化。你用户在代码段就不用对 `SS` 和 `SP` 初始化了。但是，如果用 `SEGMENT` 定义堆栈段时，组合类型没有用 `STACK` 说明，那么你在代码段一开始，就要把堆栈段的段地址想办法送给 `SS`，把堆栈段栈底加一的偏移地址想办法送给 `SP`，对 `SS` 和 `SP` 初始化，这要用户在代码段完成。而如果堆栈段的组合类型用 `STACK` 说明了，`SS` 和 `SP` 就不用初始化了，系统会完成的。

| 堆栈段写法 | `SS` 与 `SP` 谁来初始化 | 代码段要不要写初始化 |
| :--- | :--- | :--- |
| :--- | :--- | :--- |
| `STACK SEGMENT STACK`（`MASM 5.0+`） | 系统完成：链接程序知道这是堆栈段，自动装填 | 不用，绝对不要再写 |
| `SEGMENT` 缺省组合类型 | 系统不管，用户自己在代码段完成 | 必须写：段地址送 `SS`，栈底加一的偏移地址送 `SP` |

## 2 NONE 型：我就是我，缺省就是它

还有一个组合类型是 `NONE` 型。如果组合类型选了 `NONE`，它告诉 `LINK`：本逻辑段和任何模块中的任何逻辑段都没有关系。都没有关系，我就是我。所以这种组合类型也属于缺省型，就是说组合类型这项不写了，链接程序就默认本段是 `NONE` 型。

啊，我就讲这两个组合类型。当然组合类型里面还有 `PUBLIC` 型、`MEMORY` 型、`AT` 表达式型等等，我都不讲了。感兴趣的同学参考有关的课外书籍，课堂上不讲。这是组合类型。

再说类别。如果类别这项参数你要写，必须用单引号引起来。但类别这项参数没有任何意义。没有意义还要它干什么？只是告诉程序阅读人员本段信息的种类。比如这个段定义的是数据段，那我在类别写个单引号 `'DATA'`，告诉读程序的人，一看到类别是 `DATA`，就知道本段是数据段。理解了没有？只起这么一个作用，再没有其他意义。

## 3 标准结构：不挨个讲伪指令了，从完整结构里带出来

段定义开始伪指令 `SEGMENT` 和段定义结束伪指令 `ENDS`，这一节 4.1 里面讲到的伪指令还很多，我不要挨个去讲了。我看我的时间，我下面直接给出 8086 汇编语言源程序结构，即完整结构或者叫标准结构，我在结构中引出、带出好多伪指令。我写一个结构你们看：

```assembly
STACK  SEGMENT  STACK
       DB  256 DUP(?)
STACK  ENDS
```

显然我在定义什么段？堆栈段，组合类型就要取 `STACK`。在堆栈段里面，用 `DB` 或者 `DW` 定义一个存储空间做堆栈区。`DB 256 DUP(?)`，堆栈段我定义了 256 个字节，也就是 128 个字的大小。

那么堆栈区要多大？要根据你程序的实际需求，留出 30% 的富裕量来定义堆栈空间。我留富裕量的目的是什么？以便于程序扩充、维护，避免 `SP` 指针溢出。讲堆栈时是不是都提到过？

定义完了，我们来看，我先画一个存储器。你看，定位类型缺省就是节型，汇编程序在自由空间里找第一个能被 $16$ 整除的地址作为本段起点。256 个字节占下来，段内偏移就是 $0000\text{H} \sim 00\text{FFH}$，栈底在 $00\text{FFH}$。

```text
高地址
  ┌──────────────┐
  │  偏移 0100H   │◀── SP 初值指向这里（栈底 + 1）
  ├──────────────┤
  │  偏移 00FFH   │◀── 栈底（最后一个有效单元）
  │     ┆        │
  │  偏移 0001H   │
  ├──────────────┤
  │  偏移 0000H   │◀── 段起点（能被16整除）
  └──────────────┘
低地址      堆栈段（256 字节）
```

读图说明：8086 压栈是先减后存，`PUSH` 先 `SP \leftarrow SP - 2` 再写数据，所以 `SP` 初值必须指向栈底加一，也就是偏移 $256$（`0100H`），第一个压入的字才能完整落在 $[254, 255]$ 单元。你要是把 $255$ 当初值，栈底那个字就没地方完整放了。

> **易错点**：`STACK SEGMENT STACK` 两个 `STACK` 别混为一谈。左边是段名，你改成 `MYSTK SEGMENT STACK` 照样成立；右边是组合类型，少了它，`MASM` 再高版本也不会替你初始化 `SS:SP`。还有，已经声明了 `STACK` 类型，就不要在代码段再写一遍 `MOV SS, AX / MOV SP, 0100H`，那是冗余逻辑。
