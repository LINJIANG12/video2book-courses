# 宏调用与宏展开：写下宏名的那一行

来，我们看。如果我在这编程序、编程序、编程序，我编到这了，我想把 `AX` 的内容逻辑左移三次，那我这个地方就不编程序了，我直接写上一行宏调用。看到没有？这就是我们今天要讲的：二、宏调用。

## 1 SHIFT 宏调用：实参代替虚参

前面我们已经把 `SHIFT` 这条宏指令定义好了，它有三个形参：寄存器 `REG`、移位方向 `DIR`、移位次数 `N`。现在程序编到这里，需要把 `AX` 逻辑左移三次，我就写：

```assembly
SHIFT  AX, HL, 3
```

什么意思？用实参 `AX` 代替虚参 `REG`，用实参 `HL` 代替方向项，用 `3` 代替 `N`。完了，没了。这一行宏指令直接写在这，实参代替虚参，这就叫宏调用。明白了没有？

显然，宏调用就是在程序设计当中，对你前面定义的宏指令，直接写出宏名。写出宏名之后右边，如果原来宏定义有形参，就要用实参代替形参。实参代替形参时，实参与形参的位置要一一对应，千万不能写错了。

> **易错点**：实参和形参的个数对不上，会怎么样？如果你原来有三个形参，宏调用时在逗号后面又多写了一个实参，多了一项，汇编程序编译时会自动把它抹掉；如果你原来是三个形参，宏调用时少写了一项，汇编程序编译时，少的那一项自动用 `00` 填补。那显然功能就错了，是吧？

好，我们再来看。我程序编到这了，我又想把 `BL` 的内容算术右移四次，是不是又要宏调用了？

```assembly
SHIFT  BL, AR, 4
```

哎，继续往下编，继续往下编。这就叫宏调用。你调用几次，宏体就插入几次。

## 2 汇编程序遇到宏调用：宏体插入与加号标记

那么我们来看，汇编程序怎么汇编？我这黑板不够用了。看汇编程序怎么汇编。

汇编程序汇编的时候，对你的源程序逐行翻译——如果你语法都对的话，语法错了它就不汇编。都对的话，逐行翻译、翻译、翻译，翻译到这一行，碰到宏指令调用了，怎么办？它是把宏体插入进来汇编。在把宏体插入的时候，会自动地用实参代替原来的虚参。对不对？

比如上面 `SHIFT AX, HL, 3` 这一行，一插入，这段程序就变成了：

```assembly
MOV  CL, 3
SHL  AX, CL
```

`AX` 代到这了，`3` 代到这了。把这一段程序插入到这以后再汇编。理解了没有？

但是汇编之后看目标代码列表，在目标代码的左边会给出一个加号。原来那些正常指令，汇编之后代码旁边没有加号；它给你这个加号，表明这一行是由宏体插入的。如果你的汇编后 `LIST` 文件在屏幕上用 `TYPE` 显示出来，或者打印出来，你看着，凡是带加号的，都是宏体插入的。

```text
源程序行              汇编后 LIST 文件
─────────            ──────────────────
MOV AX, 1              B8 0001      MOV AX, 1
SHIFT AX, HL, 3        B1 03     +  MOV CL, 3
                       D3 E0     +  SHL AX, CL
MOV BX, AX             89 C3        MOV BX, AX
```

读图说明：带 `+` 的两行就是宏展开插进来的，`CL` 取到了实参 `3`，`AX` 取到了实参 `AX`。

## 3 宏与子程序的取舍：一个费空间省时间，一个省空间费时间

通过这个讲解，你来看：在程序设计当中，我们把经常完成一个功能的那段程序，是不是既可以定义成一个用 `PROC` 定义的子程序，在需要时 `CALL` 调用；也可以定义成一条宏指令，在需要完成这个功能时宏调用？宏调用直接写出宏名。

那你现在学完了子程序和宏指令，来对比分析一下：采用宏和采用子程序，各有什么优缺点？

我说，采用宏，费空间。你调用一次，是不是就把宏体整个插进去了？浪费程序存储器空间吧！但优点是省时间。为什么省时间？因为宏体一插入，这边哗哗哗哗从头执行到尾，中间有没有一条附加的 `CALL` 调用指令？自己想。没有！是不是省了一条 `CALL` 指令的时间？最后是不是还省了一条返回的时间？省时间了。

那么显然，如果把经常完成特定功能的那段程序定义成一个子程序，在程序中需要时就 `CALL` 调用，这种子程序结构显然是省空间。你不管调用多少次，编译之后，子程序那个模块在程序里只占一个空间。省空间。但缺点是费时间。理解了没有？

| 方案 | 空间 | 时间 | 机理 |
| :--- | :--- | :--- | :--- |
| :--- | :--- | :--- | :--- |
| 宏指令 | 费空间：调用几次，宏体就插入几次，目标程序变长 | 省时间：没有 `CALL` 和 `RET` 的额外开销，直线执行 | 汇编时宏体插入，实参代换虚参 |
| 子程序 | 省空间：模块只占一份空间，调用多少次都不复制 | 费时间：每次多执行一条 `CALL`，返回多执行一条 `RET` | 执行时现场调用与返回 |

> **提示**：我们有一年考试就考过这个简答题。它说：简述在程序设计中采用宏指令定义的办法和采用子程序定义的办法各有什么优缺点？那你就从空间上和时间上去说。明白了吧？书上也有这一段话，3.16.5“宏指令与子程序的比较”，表 3.8 把我刚说的时间、空间给你总结进去了。这一小节就讲完了。

## 4 CRLF 宏：没有未知项就不要形参

好，那我们再看一个例子。我随便举个例子，好比说例 2。我让你定义一条宏指令，让它完成的功能是：让光标回车换行。

那我定义，宏指令名假如我叫 `CRLF`。我为什么起这个名？讲子程序的时候讲过，你看那个 `ASCII` 码表，回车是不是用 `CR` 表示？换行是不是用 `LF` 表示？所以我将来一看 `CRLF` 就知道是光标回车换行。

那么 `MACRO` 后面要不要形参呢？题目说的是光标回车和换行，没有未知项，就不要形参。理解了没有？那我就开始编宏体了。

宏体怎么编？是不是 `DOS` 的 2 号功能调用两次？不是讲过吗？

```assembly
CRLF  MACRO
      MOV  AH, 2
      MOV  DL, 0DH
      INT  21H
      MOV  AH, 2
      MOV  DL, 0AH
      INT  21H
      ENDM
```

`MOV AH, 2`，`MOV DL` 里面放 `0DH`，是不是回车的 `ASCII` 码？`INT 21H`，`DOS` 功能调用，2 号调用就把 `DL` 中的字符送到屏幕。`DL` 里是回车，光标就回车了嘛。再调用一次换行：`AH` 还是 `2`，`MOV DL` 里面放什么？放 `0AH`。`INT 21H` 就把光标换行了。

## 5 数据块移动宏与 LOCAL：NEXT 变成问号问号 0000

哎，那你看这个宏定义体当中，是不是出现了标号？块移动的思路是这样的：我 `MOV CX, N`，把重复次数带进来；现在要搬家了，用数据传送指令搬家也行。比如 `MOV AL, [SI]`，`SI` 间接寻址，把这个单元的一个字节搬到 `AL`；再 `MOV [DI], AL`，把 `AL` 的内容写到 `DI` 间接单元去。`DI` 间接单元默认在 `DS` 段，对吧？我在同一个段嘛。如果是 `ES` 段，你前面加个 `ES:` 前缀。

搬完一个字节，`INC SI` 加 1，`INC DI` 加 1，`LOOP`：`CX` 减 1，没减到零就跳到 `NEXT`。`NEXT` 标号在哪？应该在这，循环搬。`CX` 减到零，搬完了，`ENDM`。

那你在 `MACRO` 定义宏指令名的地方，一开始就要声明 `NEXT` 是局部标号。怎么声明？你看书上 84 页上面 3.16.3 节“宏指令中的标号与变量”，是不是用 `LOCAL` 伪指令声明的？`LOCAL NEXT`，告诉汇编程序 `NEXT` 是局部标号。如果局部标号多于一个，就 `LOCAL NEXT, …`，都要声明。

```assembly
BYTE_MOVE  MACRO  BYTE1, BYTE2, N
           LOCAL  NEXT
           LEA    SI, BYTE1
           LEA    DI, BYTE2
           MOV    CX, N
AGAIN:     MOV    AL, [SI]
           MOV    [DI], AL
           INC    SI
           INC    DI
           LOOP   NEXT
NEXT:      ...
           ENDM
```

那么在主程序里宏调用。我噼里啪啦编，编到这了，我现在想把 `BUFFER1` 开始的 100 个字节数据搬到 `BUFFER2` 以下单元去，那我在这写：

```assembly
BYTE_MOVE  BUFFER1, BUFFER2, 100
```

用 `BUFFER1` 实参代替虚参 `BYTE1`，用 `BUFFER2` 实参代替虚参 `BYTE2`，用 `100` 代替虚参 `N`。宏调用完了，我噼里啪啦继续编，编到这，我又想把 `BUFFER3` 开始的 200 个字节搬到 `BUFFER4` 以下去，那我再写：

```assembly
BYTE_MOVE  BUFFER3, BUFFER4, 200
```

啊，这就叫宏调用。那我们现在看，汇编程序汇编时碰到宏指令，是不是刚才说要把宏体插入？宏体插入的过程叫什么？叫宏展开。看宏展开怎么展开。汇编、汇编、汇编，汇编到 `BYTE_MOVE` 了，是不是要把宏体插入到这来？一插入，宏体就变成了：

```text
第一次宏展开（调用处 1，实参 BUFFER1 / BUFFER2 / 100）
+  LEA  SI, BUFFER1
+  LEA  DI, BUFFER2
+  MOV  CX, 100
+  MOV  AL, [SI]
+  MOV  [DI], AL
+  INC  SI
+  INC  DI
+  LOOP ??0000          ← 原来的 NEXT 变成了 ??0000
   ??0000:              ← 标号定义处也跟着变

第二次宏展开（调用处 2，实参 BUFFER3 / BUFFER4 / 200）
+  LEA  SI, BUFFER3
+  LEA  DI, BUFFER4
+  MOV  CX, 200
   ...
+  LOOP ??0001          ← 第二次插入，NEXT 变成了 ??0001
   ??0001:
```

读图说明：`LEA` 前面的加号说明这些行是宏体插入的；`NEXT` 是局部标号，编译程序第一次展开时自动把它变成 `??0000`，第二次展开变成 `??0001`。

`LOOP` 后面是不是 `NEXT`？但 `NEXT` 是个局部标号，编译程序就自动地把这个局部标号变成了问号问号 0000（`??0000`）。用这么一个标号代替了原来的局部标号 `NEXT`。汇编完了继续汇编，汇编到第二个调用处，宏体又要插入了，碰到的 `NEXT` 就用问号问号 0001（`??0001`）代替。

那你这样一看，不管插入多少次，标号是不是都在变？标号就不会重复定义。后面是四位数，是不是能调用 65536 次？这就解决了宏体中有局部标号时、程序中若干次调用发生的标号重复定义的矛盾。你要在底下生想，就闹懵了。明白了吧？这是在宏指令应用当中要注意的。

## 本讲提到的题目

讲到宏和子程序对比时，提到有一年考试考过下面这道简答题，这里按课堂讲法还原。

**题目**：简述在程序设计中，采用宏指令定义的办法和采用子程序定义的办法各有什么优缺点？

**解析**：这道题就从空间和时间两句话去说，依据就是正文第 3 节的对比。采用宏：调用一次宏体插入一次，费程序存储器空间；但直线执行，没有 `CALL` 和 `RET` 的额外开销，省时间。采用子程序：模块只占一份空间，不管调用多少次都省空间；但每次调用多一条 `CALL`、返回多一条 `RET`，费时间。书上 3.16.5 节表 3.8 就是这两句话的总结，答全即得分。
