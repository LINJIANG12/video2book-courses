# 汇编流程控制、移位指令与子程序堆栈调用全解

## 移位指令体系与硬件规范

### 移位操作数语法与物理约束

* **移位指令操作数规则（Shift Operand Rules）**

    * > **定义**：8086 处理器对移位与循环移位指令在目标操作数寻址与移位计数源设定的硬件语法约束。

    * 语法格式：`OPR DEST, 1` 与 `OPR DEST, CL`。

    * 移位位数为 1 时：移位次数允许作为立即数 `1` 直接编码在指令中。

    * 移位位数大于 1 时：移位次数必须预先存入通用寄存器 `CL` 中，通过 `CL` 传递给移位指令。

    * 目的操作数属性约束：目的操作数可为 8 位或 16 位通用寄存器，或显式声明内存类型的存储单元（如 `SHL BYTE PTR [BX], 1`），严禁使用立即数或段寄存器。

    * > **易错点**：⚠️ 移位计数寄存器在 8086 硬件规范下只能使用 8 位低位寄存器 `CL`，书写为 `CX`、`CH`、`AL` 或直接书写大于 1 的立即数（如 `SHL AX, 4`）均属语法错误。

* **快速乘法合成（Fast Multiplication Synthesis）**

    * > **定义**：利用二进制左移等价于乘以 2 的幂次方特性，结合加减法指令合成常数乘法的高速运算方法。

    * 代数分解机理：将常数乘数分解为 2 的幂次之和，如 $X \times 10 = X \times (2^3 + 2^1) = (X \ll 3) + (X \ll 1)$。

    * 执行效能：相较于耗费 70 至 150 个时钟周期的乘法指令 `MUL`，通过连续移位与加法组合仅需数个时钟周期。

    * 标准代码实现：
        ```x86asm
        SHL AX, 1         ; AX = X * 2
        MOV BX, AX        ; BX = X * 2 (暂存 2 倍基数)
        SHL AX, 1         ; AX = X * 4
        SHL AX, 1         ; AX = X * 8
        ADD AX, BX        ; AX = 8X + 2X = 10X
        ```

### 非循环移位数据流向与标志位机理

* **逻辑移位指令（Logical Shift Instructions, SHL/SHR）**

    * > **定义**：以无符号数视角对二进制位进行单向滑动、移出位暂存进位标志位且空位补零的数据操作指令。

    * 逻辑左移 SHL（Shift Logical Left）数据流向：所有二进制位向左滑动，最低位补入 `0`，最高位移出并装入进位标志位 `CF`；无溢出时左移 $N$ 位等价于乘以 $2^N$。

    * 逻辑右移 SHR（Shift Logical Right）数据流向：所有二进制位向右滑动，最高位补入 `0`，最低位移出并装入进位标志位 `CF`；用于无符号数除法，右移 $N$ 位等价于整除 $2^N$。

    * 数据流向拓扑：
        ```text
        SHL:  [ CF ] <── [ b7 b6 b5 b4 b3 b2 b1 b0 ] <── 0
        SHR:  0 ──> [ b7 b6 b5 b4 b3 b2 b1 b0 ] ──> [ CF ]
        ```

* **算术移位指令（Arithmetic Shift Instructions, SAL/SAR）**

    * > **定义**：针对带符号补码数进行移位操作、保持数值符号属性或按原符号位补齐的操作指令。

    * 算术左移 SAL（Shift Arithmetic Left）：在二进制补码运算中与 SHL 的移位逻辑完全一致，在 8086 机器码中为同一条机器指令的同义助记符。

    * 算术右移 SAR（Shift Arithmetic Right）数据流向：所有二进制位向右滑动，最低位移入 `CF`，最高位（符号位）保持原有数值不变（原为 1 则补 1，原为 0 则补 0）。

    * 适用场景：专门用于带符号数补码的除法，确保负数在除以 2 之后维持负数符号特性。

    * 数据流向拓扑：
        ```text
        SAR:  ┌───> [ b7 b6 b5 b4 b3 b2 b1 b0 ] ──> [ CF ]
              └── 符号位保持不变
        ```

* **非循环移位标志位规则（Non-circular Shift Flags Impact Rules）**

    * > **定义**：非循环移位执行后状态寄存器各标志位的硬件更新准则。

    * 进位标志位 CF：始终保留最后一次移出的那一个二进制位的数值。

    * 溢出标志位 OF：仅在移位次数为 1 时具备有效定义；若移位 1 位后结果的最高符号位发生改变，则 $OF = 1$；若符号位未发生改变，则 $OF = 0$；移位次数大于 1 时 OF 状态不确定。

    * 状态标志位 ZF、SF、PF：根据移位后最终结果的状态进行设置；若结果全零则 $ZF = 1$，若最高符号位为 1 则 $SF = 1$，低 8 位中 1 的个数为偶数时 $PF = 1$。

### 循环移位指令与高精度级联扩展

* **不带进位循环移位（Rotate Instructions, ROL/ROR）**

    * > **定义**：寄存器自身首尾相接构成闭环、移出位送入对侧空位并同步复制送入进位标志位的移位指令。

    * 循环左移 ROL（Rotate Left）：数据向左循环移动，最高位送入最低位补充空缺，并同时复制一份存入 `CF`。

    * 循环右移 ROR（Rotate Right）：数据向右循环移动，最低位送入最高位补充空缺，并同时复制一份存入 `CF`。

    * 标志位影响边界：寄存器内部数据闭环保留，只影响 `CF` 与 `OF`（移位次数为 1 时），绝对不改变 `ZF` 和 `SF`。

    * 数据流向拓扑：
        ```text
        ROL:  ┌────────────────────────────┐
              ▼                            │
           [ b7 b6 b5 b4 b3 b2 b1 b0 ] ────┴──> [ CF ]

        ROR:  ┌────────────────────────────┐
              │                            ▼
         [ CF ] <──┬── [ b7 b6 b5 b4 b3 b2 b1 b0 ]
                   └────────────────────────────┘
        ```

* **带进位循环移位（Rotate through Carry Instructions, RCL/RCR）**

    * > **定义**：将进位标志位 CF 串联入数据环路中构成 9 位（8 位操作）或 17 位（16 位操作）闭环的高精度移位指令。

    * 带进位循环左移 RCL（Rotate through Carry Left）：最高位移入 `CF`，原 `CF` 旧值移入最低位。

    * 带进位循环右移 RCR（Rotate through Carry Right）：最低位移入 `CF`，原 `CF` 旧值移入最高位。

    * 标志位影响边界：仅影响 `CF` 和 `OF`（移位次数为 1 时），不改变 `ZF` 和 `SF`。

    * 数据流向拓扑：
        ```text
        RCL:  ┌────────────────────────────────────┐
              ▼                                    │
           [ b7 b6 b5 b4 b3 b2 b1 b0 ] ──> [ CF ] ──┘

        RCR:  ┌────────────────────────────────────┐
              │                                    ▼
           [ b7 b6 b5 b4 b3 b2 b1 b0 ] <── [ CF ] ──┘
        ```

* **双字多精度级联移位（Double-word Cascade Shift）**

    * > **定义**：结合非循环移位与带进位循环移位指令实现 32 位及以上大数跨寄存器整体移位的算法范式。

    * 32 位级联左移机理：设 32 位无符号数存放在 `DX:AX` 中（高 16 位在 `DX`，低 16 位在 `AX`），要求整体左移 1 位（整体乘以 2）。

    * 级联执行代码：
        ```x86asm
        SHL AX, 1         ; 低 16 位左移 1 位，最高位溢出并进入 CF
        RCL DX, 1         ; 高 16 位带进位循环左移 1 位，CF 暂存位移入 DX 最低位
        ```

    * 数据流向拓扑：
        ```text
        [ CF ] <── [ DX (高16位) ] <── [ CF 暂存位 ] <── [ AX (低16位) ] <── 0
        ```

## 控制流转移与地址计算体系

### 转移指令分类与指令指针修改机理

* **转移指令本质（Branch Instructions Nature）**

    * > **定义**：通过强行改写指令指针寄存器 IP（及代码段寄存器 CS）的数值以打破线性顺序取指的控制流重定向指令。

    * 顺序取指与转移时序：顺序执行时 CPU 每读入一条指令机器码，IP 自动累加该指令的字节长度指向下一条指令；转移指令触发时硬件改写 IP（以及 CS），使 CPU 下一个取指周期从新地址预取指令。

    * 数据流向拓扑：
        ```text
        +---------------+       JMP / 转移指令触发
        | 当前指令 CS:IP | ---------------------------+
        +---------------+                           |
                | 顺序自增 (通常执行)                 | 强行改写 IP (及 CS)
                v                                   v
        +---------------+                   +-----------------+
        | 下一条顺序指令 |                   | 目标地址对应指令 |
        +---------------+                   +-----------------+
        ```

* **控制流转移分类架构（Branch Classification Architecture）**

    * > **定义**：根据控制流转移跨越的物理范围及目标寻址方式划分的指令分类体系。

    * 转移分类规格对照：
        | 转移分类 | 英文名称 | 修改的寄存器 | 位移量 / 寻址范围 | 典型指令 |
        | :--- | :--- | :--- | :--- | :--- |
        | 段内短转移 | Short Jump | 仅修改 IP | 8 位有符号相对位移量（$-128 \sim +127$ 字节） | `JMP SHORT label`、所有条件转移指令 |
        | 段内近转移 | Near Jump | 仅修改 IP | 16 位有符号相对位移量（$-32768 \sim +32767$ 字节）或直接装载绝对偏移 | `JMP NEAR PTR label`、`JMP AX`、`JMP [BX]` |
        | 段间远转移 | Far Jump | 同时修改 CS 和 IP | 全局任意代码段地址（装入新的 CS 与 IP） | `JMP FAR PTR label`、`JMP DWORD PTR [BX]` |

* **条件转移短转移物理限制（Conditional Jump Short Constraint）**

    * > **定义**：8086 指令集中所有条件转移指令均属于段内短转移且跳转范围受 8 位相对位移量严格限定的硬件规则。

    * 位移量数值边界：位移量占 1 个字节（8 位补码），跳转范围严格限制在 $-128 \sim +127$ 字节之间。

    * 标志位影响边界：条件转移指令本身绝不修改任何标志位，转移与否完全取决于前导指令在标志寄存器 FLAGS 中留存的状态。

### 无条件转移寻址模式与相对位移量推导

* **段内直接转移（Intra-segment Direct Jump）**

    * > **定义**：目标地址以标号形式直接书写在指令中，机器码中保存相对于下一条指令首地址的相对位移量的寻址方式。

    * 硬件计算公式：$IP_{\text{新}} = IP_{\text{当前}} + \text{位移量}$，其中 $IP_{\text{当前}}$ 为紧随该 JMP 指令的下一条指令的首地址。

    * 位移量推导公式：$$\text{位移量} = \text{目标标号地址} - \text{JMP 指令下一条指令的地址}$$

    * 机器码结构与编码：
        * 短转移（SHORT）：机器码格式为 `EB ib`（共 2 字节），`ib` 为 8 位补码位移量（范围 $-128 \sim +127$ 字节）。
        * 近转移（NEAR PTR）：机器码格式为 `E9 iw`（共 3 字节），`iw` 为 16 位补码位移量（范围 $-32768 \sim +32767$ 字节）。

    * 补码转换规则：正向跳转位移量为正数，补码与原码一致；反向跳转位移量为负数，按各位取反加 1 转换为 8 位补码（例如位移量为 $-22H$，对应补码为 $100H - 22H = DEH$，机器码为 `EB DE`）。

    * > **易错点**：`JMP SHORT label` 与 `JMP NEAR PTR label` 机器码中保存的是相对位移量，而非目标标号的绝对偏移地址。

* **间接转移寻址模式（Indirect Jump Addressing Mode）**

    * > **定义**：通过寄存器或内存单元中存放的数值作为绝对地址装入指令指针进行控制流转移的寻址模式。

    * 段内间接转移：目标绝对偏移地址存放在 16 位通用寄存器或内存字单元中，执行时直接装入 IP，如 `JMP AX`（$(IP) \leftarrow (AX)$）与 `JMP WORD PTR [BX]`（从数据段读取 16 位字送入 IP）。

    * 段间间接转移：语法为 `JMP DWORD PTR [mem]`，CPU 从内存连续读取 4 个字节，低 16 位字送入 IP，高 16 位字送入 CS。

    * 段间直接远转移：语法为 `JMP FAR PTR label`，机器码格式为 `EA iw id`（共 5 字节），直接编码 2 字节偏移量送入 IP，2 字节段基址送入 CS。

### 条件转移判定体系与标志位映射

* **基于单一标志位的基础跳转（Single Flag Conditional Jumps）**

    * > **定义**：根据状态寄存器 FLAGS 中单一标志位的置位或复位状态触发跳转的条件转移指令。

    * 标志位映射规则：
        | 指令助记符 | 判定标志位状态 | 语义含义 | 典型前导指令 |
        | :--- | :--- | :--- | :--- |
        | `JZ` / `JE` | $ZF = 1$ | 结果为零 / 比较相等 | `CMP AX, BX` 或 `SUB AX, BX` |
        | `JNZ` / `JNE` | $ZF = 0$ | 结果非零 / 比较不等 | `CMP AX, BX` 或 `OR AX, AX` |
        | `JC` / `JB` | $CF = 1$ | 有进位或借位 / 低于 | `ADD AX, BX` 或 `CMP AX, BX` |
        | `JNC` / `JNB`| $CF = 0$ | 无进位无借位 / 高于等于 | `ADD AX, BX` 或 `CMP AX, BX` |
        | `JO` | $OF = 1$ | 发生有符号溢出 | `ADD AX, BX` 或 `IMUL BX` |
        | `JNO` | $OF = 0$ | 未发生有符号溢出 | `ADD AX, BX` |
        | `JS` | $SF = 1$ | 运算结果为负（最高符号位为 1） | `TEST AL, 80H` 或 `SUB AL, BL` |
        | `JNS` | $SF = 0$ | 运算结果非负（最高符号位为 0） | `SUB AL, BL` |
        | `JP` / `JPE` | $PF = 1$ | 低 8 位中 1 的个数为偶数 | 串行通讯奇偶校验 |
        | `JNP` / `JPO`| $PF = 0$ | 低 8 位中 1 的个数为奇数 | 串行通讯奇偶校验 |

* **无符号数比较跳转（Unsigned Comparison Jumps）**

    * > **定义**：在 CMP 无借位减法运算后依据进位标志 CF 与零标志 ZF 状态判定数值大小的条件转移指令。

    * 判定条件：
        * 高于转移 `JA` / `JNBE`：$CF = 0 \land ZF = 0$（无借位且差值非零）。
        * 高于等于转移 `JAE` / `JNB`：$CF = 0$（无借位）。
        * 低于转移 `JB` / `JNAE`：$CF = 1$（产生借位）。
        * 低于等于转移 `JBE` / `JNA`：$CF = 1 \lor ZF = 1$（产生借位或差值为零）。

    * 助记准则：认准助记符中的 A（Above，高于）与 B（Below，低于），判定核心为进位标志 CF 与零标志 ZF。

* **有符号数比较跳转（Signed Comparison Jumps）**

    * > **定义**：在 CMP 运算后将符号标志 SF 与溢出标志 OF 进行异或逻辑运算以判定代数大小的条件转移指令。

    * 代数大小判定机理：正数减负数发生正向溢出或负数减正数发生负向下溢时，运算结果符号位反转；无溢出（$OF = 0$）时真实符号为 SF，发生溢出（$OF = 1$）时真实符号为 $\text{NOT } SF$，代数差为负数的统一判据恒为 $SF \oplus OF = 1$。

    * 判定逻辑拓扑：
        ```text
        有符号数减法 CMP A, B (计算 A - B)
                     |
              检查溢出标志 OF
              /              \
          OF = 0 (无溢出)    OF = 1 (发生溢出)
            |                  |
        真实结果符号即为 SF    真实结果符号发生反转 (NOT SF)
            |                  |
        +----------------------+
        | 真实比较大小准则: SF XOR OF
        | - 若 SF == OF (异或为0) ==> A >= B
        | - 若 SF != OF (异或为1) ==> A <  B
        +------------------------------------
        ```

    * 判定条件规则：
        | 条件转移指令 | 助记符含义 | 成立判定条件 | 逻辑本质解析 |
        | :--- | :--- | :--- | :--- |
        | `JL` / `JNGE` | 小于 / 不大于等于 | $SF \oplus OF = 1$ | 真实代数差为负数 |
        | `JNL` / `JGE` | 不小于 / 大于等于 | $SF \oplus OF = 0$ | 真实代数差为非负数 |
        | `JLE` / `JNG` | 小于等于 / 不大于 | $(SF \oplus OF = 1) \lor (ZF = 1)$ | 真实代数差为负数或相等 |
        | `JNLE` / `JG` | 不小于等于 / 大于 | $(SF \oplus OF = 0) \land (ZF = 0)$ | 真实代数差为正数且不相等 |

    * 数据属性相对性：相同减法机器码下，无符号视角与有符号视角跳转结果可能截然相反（例如 $AX = 8000H$ 与 $BX = 0001H$ 比较，无符号视角为大减小触发 `JA` 跳转，有符号视角为最小负数减正数发生溢出下溢 $OF = 1, SF = 0$，触发 `JL` 跳转）。

* **计数器零测试转移（Jump if CX is Zero, JCXZ）**

    * > **定义**：硬件在指令执行周期内直接探查通用寄存器 CX 内容是否为零的专用段内短转移指令。

    * 触发条件：当且仅当 $(CX) = 0$ 时发生跳转，否则顺序执行。

    * 标志位影响边界：不依赖任何标志位，也绝对不改变任何标志位。

    * 核心应用场景：在进入循环体之前执行前置检测，规避计数器初值为零引发的异常循环。

### 分支结构设计规范与越界修复

* **双分支互斥结构（Mutually Exclusive Dual Branch）**

    * > **定义**：模拟高级语言 if-else 逻辑并利用无条件跳转跨越对立分支以保证分支严格互斥的汇编代码范式。

    * 标准代码实现：
        ```x86asm
        ; 实现逻辑: if (AX >= BX) { AX = AX - BX } else { AX = BX - AX }
            CMP AX, BX
            JL  AX_LESS_BX       ; 若 AX < BX 则转入小于分支
            
            SUB AX, BX          ; AX >= BX 主分支体
            JMP BRANCH_END       ; 必须跳过 else 分支
        AX_LESS_BX:
            MOV CX, BX
            SUB CX, AX
            MOV AX, CX          ; AX < BX 次分支体
        BRANCH_END:
        ```

* **条件跳转越界搭桥技术（Trampoline Pattern）**

    * > **定义**：针对条件转移位移量超出 8 位范围（超过 127 字节）报错，通过条件取反短跳配合无条件近跳转进行中转的重构模式。

    * 重构机理：将原条件转移指令逻辑取反（如 `JZ` 取反为 `JNZ`），短跳越过紧随其后的 `JMP NEAR PTR` 无条件近跳转指令；利用近跳转指令具备的 16 位相对位移量（$\pm 32\text{KB}$）飞向远距离目标标号。

    * 标准代码实现：
        ```x86asm
        ; 原错误代码: JZ TARGET_PROCESS (距离超过 127 字节)
        ; 标准搭桥重构代码:
            CMP AX, BX
            JNZ SKIP_FAR_JUMP           ; 条件取反，短跳越过中转指令
            JMP NEAR PTR TARGET_PROCESS ; 利用 16 位近跳转直达远端目标
        SKIP_FAR_JUMP:
            ; 继续执行后续顺序指令序列
        ```

    * > **易错点**：⚠️ 在比较测试指令（如 `CMP`、`TEST`）与条件转移指令之间严禁插入修改标志位的算术或逻辑指令（如 `ADD`、`OR`），否则前序测试状态将被冲毁；若需暂存标志寄存器状态，必须使用 `PUSHF` 与 `POPF` 指令。

## 循环控制时序与特征检索

### 计数循环微时序与指令边界

* **标准计数循环指令（Count Loop Instruction, LOOP）**

    * > **定义**：硬件自动使计数寄存器 CX 递减并依据是否减至零决定是否闭环跳转的硬件循环控制指令。

    * 硬件微操作时序：
        1. 计数器自动自减：硬件自动执行 $(CX) \leftarrow (CX) - 1$；
        2. 判定与跳转：若自减后 $(CX) \neq 0$，则将当前 IP 加上 8 位相对位移量跳回目标标号；若自减后 $(CX) = 0$，则退出循环顺序执行。

    * 微操作时序拓扑：
        ```text
               进入循环体
                   |
                   v
            [ 执行循环体指令序列 ]
                   |
                   v
               LOOP label
                   |
              (CX) <-- (CX) - 1  (硬件自动自减，不影响任何标志位)
                   |
               判别: (CX) == 0 ?
                  /          \
              No /            \ Yes
                /              \
          [ 跳回 label ]    [ 退出循环，顺序执行 ]
        ```

    * 标志位影响边界：`LOOP` 指令执行 $(CX) \leftarrow (CX) - 1$ 时，绝对不改变任何标志位（包括 `ZF`、`CF` 等）。

* **循环计数初值零陷阱（Zero Initial Count Trap）**

    * > **定义**：当进入循环前 CX 初始值为零时，首次执行 LOOP 指令因 16 位无符号下溢导致循环体被连续执行 65536 次的边界缺陷。

    * 演变推导时序：初始 $CX = 0$ 进入循环体执行 1 次；遇到 `LOOP` 时硬件先减 1，16 位无符号寄存器 $0 - 1 = 0FFFFH$（65535）；因 $FFFFH \neq 0$ 触发跳转；随后 $CX$ 从 65535 逐次递减至 0，最终累计执行循环体整整 65536 次。

    * 时序演变拓扑：
        ```text
        初始 CX = 0
          |
          +---> 执行第 1 次循环体
          |        |
          |      LOOP 执行: CX 减 1 变为 0FFFFH (65535 != 0) ===> 跳回
          |        |
          +---> 执行第 2 次循环体 (CX 减为 65534)
          |        ...
          +---> 执行第 65536 次循环体 (CX 减为 0) ===> 退出循环
        ```

    * > **易错点**：⚠️ 汇编循环属于后检测循环，若初值可能为零，进入循环体前必须先使用 `JCXZ` 指令前置拦截，直接跳过循环体。

* **手动减计数与 LOOP 指令等价辨析（LOOP vs DEC CX + JNZ）**

    * > **定义**：单指令硬件自减闭环与双指令显式减法判断跳转在字节长度、执行周期与标志位影响维度的技术对照。

    * 性能与状态特性对照：
        | 比较维度 | 方案 A (`LOOP label`) | 方案 B (`DEC CX` + `JNZ label`) |
        | :--- | :--- | :--- |
        | 指令条数与字节长度 | 1 条指令，占 2 个字节（机器码 `E2 ib`） | 2 条指令，占 3 个字节（`DEC CX` 占 1 字节，`JNZ` 占 2 字节） |
        | 执行时钟周期 (8086) | 转移发生时 17 周期，不转移时 5 周期 | `DEC CX`（2 周期）+ `JNZ`（转移 16 周期/不转移 4 周期），共 18 周期/6 周期 |
        | 标志寄存器 FLAGS | 绝对不改变任何标志位 | `DEC CX` 强制修改 `ZF`、`SF`、`OF`、`PF`、`AF`（但不影响 `CF`） |

    * 标志位保持边界：若循环体内运算产生了关键状态需在末尾依据标志位做后续判断，`LOOP` 可完整保护该标志状态，而 `DEC CX` 会强制刷新 `ZF` 等标志位。

### 条件循环与字符串特征检索

* **相等/为零条件循环指令（Loop if Equal / Zero, LOOPE/LOOPZ）**

    * > **定义**：在硬件自减计数器的同时检测零标志位 ZF 是否为 1 的复合循环控制指令。

    * 硬件执行动作与继续条件：先执行 $(CX) \leftarrow (CX) - 1$；当且仅当 $(CX) \neq 0 \land ZF = 1$ 时跳回标号继续循环。

    * 典型应用场景：在连续数据区中寻找第一个非零元素，或寻找第一个不匹配字符（比较相等则差值为零保持 $ZF = 1$ 继续循环，一旦不等则 $ZF = 0$ 提前退出）。

* **不等/非零条件循环指令（Loop if Not Equal / Not Zero, LOOPNE/LOOPNZ）**

    * > **定义**：在硬件自减计数器的同时检测零标志位 ZF 是否为 0 的复合循环控制指令。

    * 硬件执行动作与继续条件：先执行 $(CX) \leftarrow (CX) - 1$；当且仅当 $(CX) \neq 0 \land ZF = 0$ 时跳回标号继续循环。

    * 典型应用场景：在数据缓冲区中检索特定目标字符；比较不等时差值非零保持 $ZF = 0$ 继续循环，一旦命中目标字符则差值为零触发 $ZF = 1$ 提前退出。

* **双出口扫描时序判别（Dual-Exit Scan Timing Resolution）**

    * > **定义**：依据条件循环退出时的计数器数值与标志位状态判定是命中退出还是上限耗尽退出的分析方法。

    * 提前跳出出口（Break）：循环体内扫描到匹配项触发 $ZF = 1$，紧接着执行 `LOOPNE` 自减 $CX$，因检测到 $ZF \neq 0$ 触发提前跳出，最终状态为 $CX > 0$ 且 $ZF = 1$。

    * 计数耗尽出口：扫描完整个缓冲区仍未命中目标字符，每次比较均产生 $ZF = 0$，直至最后一次循环自减后 $CX = 0$，因计数器耗尽而正常退出，最终状态为 $CX = 0$ 且 $ZF = 0$。

## 子程序调用机理与堆栈平衡规范

### 过程定义与作用域约束

* **过程定义伪指令（Procedure Definition Directives, PROC/ENDP）**

    * > **定义**：在汇编源程序中声明子程序入口符号、作用域边界及调用属性的成对伪指令。

    * 语法格式：
        ```x86asm
        子程序名 PROC [NEAR / FAR]
            ; 子程序功能代码
            RET
        子程序名 ENDP
        ```

* **段内过程与段间过程属性（NEAR and FAR Procedure Attributes）**

    * > **定义**：依据子程序与调用者是否同处于一个代码段所决定的堆栈压入与弹出规格属性。

    * `NEAR` 属性（段内过程）：主程序与子程序同处于一个代码段（缺省默认 NEAR）；调用和返回时代码段基址 `CS` 保持不变，堆栈仅压入和弹出 16 位偏移地址 `IP`。

    * `FAR` 属性（段间过程）：主程序与子程序位于不同代码段；调用和返回时堆栈必须成对压入和弹出 32 位完整指针（16 位段基址 `CS` 和 16 位偏移地址 `IP`）。

### 调用与返回的堆栈微操作时序

* **子程序调用指令（Subroutine Call Instruction, CALL）**

    * > **定义**：将调用指令后紧随的下一条指令地址（断点）压入堆栈保存并将执行指针转向子程序入口的硬件控制指令。

    * 段内调用（NEAR CALL）微操作流：
        1. 堆栈指针自减 2：$(SP) \leftarrow (SP) - 2$；
        2. 压入断点偏移地址：$[SS:SP] \leftarrow IP$（此时 IP 已指向 CALL 下一条指令）；
        3. 装载新目标地址：$(IP) \leftarrow \text{子程序的偏移地址}$。

    * 段间调用（FAR CALL）微操作流：
        1. 压入主程序段基址：$(SP) \leftarrow (SP) - 2, [SS:SP] \leftarrow CS$；
        2. 压入主程序断点偏移：$(SP) \leftarrow (SP) - 2, [SS:SP] \leftarrow IP$；
        3. 装载新代码段基址与新偏移：$(CS) \leftarrow \text{子程序段地址}, (IP) \leftarrow \text{子程序偏移地址}$。

    * 堆栈栈顶布局拓扑：
        ```text
               段内 CALL (NEAR)                   段间 CALL (FAR)
            高地址   |               |         高地址   |               |
                     +---------------+                  +---------------+
                     | 原主程序内容  |                  | 原主程序内容  |
                     +---------------+                  +---------------+
                     |  主程序 IP    | <-- SP           |  主程序 CS    |
            低地址   +---------------+                  +---------------+
                     |               |                  |  主程序 IP    | <-- SP
                                               低地址   +---------------+
        ```

* **子程序返回指令（Subroutine Return Instruction, RET）**

    * > **定义**：从堆栈栈顶弹出先前保存的断点地址逆向恢复指令指针（及代码段寄存器）以返回主程序的指令。

    * 段内返回（NEAR RET）：从当前栈顶弹出一个字送入 `IP`：$(IP) \leftarrow [SS:SP]$，随后堆栈指针累加 2：$(SP) \leftarrow (SP) + 2$。

    * 段间返回（FAR RET）：先从栈顶弹出一个字送入 `IP` 且 $(SP) \leftarrow (SP) + 2$，再弹出一个字送入 `CS` 且 $(SP) \leftarrow (SP) + 2$。

* **带立即数返回指令（Return with Immediate, RET n）**

    * > **定义**：在弹出断点地址之后，硬件自动令堆栈指针累加指定常数字节数以销毁栈内参数的返回指令。

    * 硬件微操作时序：执行常规返回弹出断点恢复 IP（及 CS）之后，硬件自动执行 $(SP) \leftarrow (SP) + n$（$n$ 通常为偶数立即数）。

    * 功用：用单条指令在安全返回的同时清理主程序压入堆栈的 $n$ 个字节参数，实现即时堆栈平衡。

### 现场保护与参数传递规范

* **现场保护进出栈对仗原则（Context Preservation FILO Principle）**

    * > **定义**：在子程序内部为避免改写调用者正在使用的寄存器而在入口压栈并在出口出栈恢复的规范。

    * 对仗规则：
        1. 入口处使用 `PUSH` 按序保存需使用的通用寄存器；
        2. 出口处在 `RET` 之前使用 `POP` 恢复寄存器；
        3. 恢复顺序与压栈顺序严格相反（先进后出 FILO，如 `PUSH AX; PUSH BX` 对应 `POP BX; POP AX`）；
        4. `POP` 恢复指令严禁写在 `RET` 指令之后。

    * 标准代码实现：
        ```x86asm
        MY_SUBROUTINE PROC NEAR
            PUSH AX             ; 保护现场 (压栈顺序: AX, BX, CX)
            PUSH BX
            PUSH CX

            MOV AX, [BX]        ; 子程序核心运算
            ADD AX, CX

            POP CX              ; 恢复现场 (出栈顺序严格逆序: CX, BX, AX)
            POP BX
            POP AX
            RET                 ; 栈顶对齐断点，安全返回
        MY_SUBROUTINE ENDP
        ```

    * > **易错点**：⚠️ 若进出栈未严格逆序，或将 `POP` 写在 `RET` 之后，执行 `RET` 时栈顶暴露的不是断点地址而是寄存器残余数据；CPU 强行将寄存器数值装入 `IP`，导致程序控制流飞向未知内存引发死机或硬件异常。

* **主子程序参数传递范式（Parameter Passing Paradigms）**

    * > **定义**：主程序向子程序输入参数以及接收计算结果的三种工程交互模型。

    * 寄存器传参：主程序将参数预存入寄存器，子程序直接读取计算并将结果存入约定寄存器；运行效率最高，但受通用寄存器数量限制，无法传递复合大块数据。

    * 约定内存单元传参：在全局数据段开辟静态缓冲区用于数据存取；可传递大量数据但破坏子程序独立性，无法支持递归与可重入。

    * 堆栈传参：主程序将实参逐个 `PUSH` 压入堆栈，子程序利用基址指针 `BP` 寻址读取，返回时配合 `RET n` 清除参数；支持嵌套调用与递归，是现代高级语言底层函数调用的通用工业模型。

* **基于基址指针的堆栈栈帧寻址（Stack Frame Addressing via BP）**

    * > **定义**：利用 BP 寄存器锁定当前栈顶基准并通过固定正向偏移寻址访问堆栈中传递参数的工业级调用约定。

    * 标准栈帧构建与参数访问实现：
        ```x86asm
        ; 主程序调用部分
            PUSH 0010H          ; 压入第 1 个参数 (先入栈)
            PUSH 0020H          ; 压入第 2 个参数 (后入栈)
            CALL ADD_PROC       ; 调用子程序 (压入返回断点 IP)
            ; 返回后无需手动 ADD SP, 4

        ; 子程序实现部分
        ADD_PROC PROC NEAR
            PUSH BP             ; 保护基址指针原值
            MOV  BP, SP         ; 建立栈帧基准锚点
            MOV  AX, [BP + 6]   ; 取出第 1 个参数 (0010H)
            ADD  AX, [BP + 4]   ; 加上第 2 个参数 (0020H)
            POP  BP             ; 恢复旧 BP
            RET  4              ; 弹出断点返回并自动使 SP 累加 4 字节清理参数
        ADD_PROC ENDP
        ```

    * 栈帧内存物理分布拓扑：
        ```text
        高地址 -----------------+-------------------------+
               | [SS:BP + 6]    | 第 1 个参数 (0010H)     | <-- 距 BP 偏 6 个字节
               +----------------+-------------------------+
               | [SS:BP + 4]    | 第 2 个参数 (0020H)     | <-- 距 BP 偏 4 个字节
               +----------------+-------------------------+
               | [SS:BP + 2]    | 主程序返回断点 (IP)     | <-- CALL 自动压入
               +----------------+-------------------------+
        低地址 | [SS:BP + 0]    | 保护的旧 BP 值          | <-- PUSH BP, 当前 SP/BP 指向
               +----------------+-------------------------+
        ```

    * 偏移量数学推导：
        1. `[BP + 0]`：指向刚压栈的旧 BP 值，占用 2 字节（偏移 0~1 字节）；
        2. `[BP + 2]`：跳过旧 BP 后指向 CALL 指令压入的主程序断点 IP，占用 2 字节（偏移 2~3 字节）；
        3. `[BP + 4]`：跳过断点后指向最后压入的第 2 个参数，占用 2 字节（偏移 4~5 字节）；
        4. `[BP + 6]`：再向上推进 2 字节精准命中第 1 个压入的参数，占用 2 字节（偏移 6~7 字节）。
