## 【拯救者】Ep_第六章-移位指令和转移指令(上)
> 对应分集：P15 | 原始标题：《【拯救者】Ep_第六章-移位指令和转移指令(上)》

在 CPU 内部，乘法指令 `MUL` 和除法指令 `DIV` 往往需要几十个时钟周期才能完成一次计算。而在底层驱动、图形学渲染或嵌入式控制中，凡是遇到乘以 2、除以 2，或者需要拆解字节中特定比特位的场景，资深工程师都会毫不犹豫地选择**移位指令（Shift & Rotate Instructions）**。

移位指令可以在单个甚至几个时钟周期内完成位级的高速滑动。但是，很多同学一碰到这组指令就头疼：逻辑右移与算术右移到底有什么区别？带进位的循环移位到底是谁在循环？为什么移位超过 1 位时编译器就频频报错？

这一讲我们把 8086 体系下的两大类、共八种移位指令彻底归拢，讲清每一个位滑动的数据流向、标志位变化法则，以及底层的硬件规范。

### 移位指令的操作数格式与硬件限制

8086 CPU 对移位指令的操作数格式有着非常严苛的物理限制：

```assembly
; 语法格式:
OPR DEST, 1        ; 移动 1 位时，直接写立即数 1
OPR DEST, CL       ; 移动大于 1 位时，必须借助 CL 寄存器
```

1. **移位位数为 1 时**：可以直接将立即数 `1` 写在指令中。
   ```assembly
   SHL AX, 1       ; 合法
   ```
2. **移位位数大于 1 时**：**在 8086 架构下，移位次数必须预先存放在 `CL` 寄存器中**，通过 `CL` 传递给移位指令！
   ```assembly
   ; 错误写法（8086 不支持大于 1 的立即数移位）：
   SHL AX, 4       ; 8086 汇编器报错！

   ; 正确写法：
   MOV CL, 4
   SHL AX, CL      ; 合法！
   ```
3. **目的操作数属性**：目的操作数可以是 8 位或 16 位的通用寄存器，或者是内存单元（需指定类型，如 `SHL BYTE PTR [BX], 1`），但**绝不能是立即数或段寄存器**。

> **易错点**：千万记住移位计数寄存器**只能是 `CL`**（8 位低位寄存器），写成 `CX`、`CH` 或者 `BL` 全部属于语法错误。

### 非循环移位指令：逻辑移位与算术移位

非循环移位在滑动时，移出的位会被丢弃（但最后一位会暂存在进位标志位 `CF` 中），空出的位则根据逻辑属性补充 0 或符号位。

```text
非循环移位数据流向图解:
SHL/SAL:  [ CF ] <── [ b7 b6 b5 b4 b3 b2 b1 b0 ] <── 0       (低位补 0)
SHR:      0 ──> [ b7 b6 b5 b4 b3 b2 b1 b0 ] ──> [ CF ]       (高位补 0)
SAR:      ┌───> [ b7 b6 b5 b4 b3 b2 b1 b0 ] ──> [ CF ]       (高位补原最高符号位)
          └── 符号位保持不变
```

#### 逻辑左移 SHL 与算术左移 SAL

- **操作过程**：所有位依次向左移动指定的位数。每移动一位，**最低位一律补 `0`**，**最高位移出并装入标志位 `CF`**。
- **技术等价性**：在二进制补码运算中，有符号数和无符号数的左移逻辑完全相同，因此 `SHL`（Shift Logical Left）和 `SAL`（Shift Arithmetic Left）在 8086 机器码中是**同一条指令的两个同义助记符**。
- **数学意义**：在没有产生溢出的前提下，左移 $N$ 位等价于乘以 $2^N$。

#### 逻辑右移 SHR

- **操作过程**：所有位依次向右移动。每移动一位，**最高位一律补 `0`**，**最低位移出并装入标志位 `CF`**。
- **适用场景**：专门用于**无符号数**的除法。无符号数右移 $N$ 位，等价于该数整除 $2^N$。

#### 算术右移 SAR

- **操作过程**：所有位依次向右移动。每移动一位，**最低位移入 `CF`**，但**最高位（符号位）保持原有数值不变**！也就是说，原来最高位是 1，移位后最高位依然补 1；原来是 0，则继续补 0。
- **适用场景**：专门用于**带符号数（补码）**的除法。它确保了负数在除以 2 之后依然保持负数的符号特性。

```assembly
; 实例对比：正负数右移
MOV AL, 11111000B    ; 十进制 -8 的补码 (F8H)
SAR AL, 1            ; 算术右移 1 位，最高位补 1 得到 11111100B (-4，即 -8/2)

MOV AL, 11111000B
SHR AL, 1            ; 逻辑右移 1 位，最高位补 0 得到 01111100B (无符号数 124)
```

### 循环移位指令：不带进位与带进位循环

循环移位的核心在于：**移出的位绝不丢失，而是像传送带一样首尾相接，循环塞回另一端**。

```text
循环移位拓扑结构:
ROL (不带进位循环左移):
     ┌────────────────────────────┐
     ▼                            │
  [ b7 b6 b5 b4 b3 b2 b1 b0 ] ────┴──> [ CF ]

ROR (不带进位循环右移):
     ┌────────────────────────────┐
     │                            ▼
[ CF ] <──┬── [ b7 b6 b5 b4 b3 b2 b1 b0 ]
          └────────────────────────────┘

RCL (带进位循环左移，CF 作为第 9 位参与闭环):
     ┌────────────────────────────────────┐
     ▼                                    │
  [ b7 b6 b5 b4 b3 b2 b1 b0 ] ──> [ CF ] ──┘

RCR (带进位循环右移，CF 作为第 9 位参与闭环):
     ┌────────────────────────────────────┐
     │                                    ▼
  [ b7 b6 b5 b4 b3 b2 b1 b0 ] <── [ CF ] ──┘
```

#### 不带进位循环左移 ROL 与右移 ROR

- **ROL（Rotate Left）**：数据向左循环移动。每移一位，**最高位一方面送入最低位补充空缺，另一方面同时复制一份送到 `CF` 标志位**。
- **ROR（Rotate Right）**：数据向右循环移动。每移一位，**最低位一方面送入最高位补充空缺，另一方面同时复制一份送到 `CF` 标志位**。
- **特点**：寄存器自身形成一个封闭的 8 位或 16 位圆环，内部数据永远不丢，`CF` 仅作为最高/最低位的“后视镜”反映最新状态。

#### 带进位循环左移 RCL 与右移 RCR

- **RCL（Rotate through Carry Left）**：`CF` 标志位直接串联进数据环路中！在 8 位操作时形成一个 **9 位的大环**，16 位操作时形成一个 **17 位的大环**。
  - 左移一位时：最高位移入 `CF`，而 `CF` 原来的旧值则移入最低位。
- **RCR（Rotate through Carry Right）**：
  - 右移一位时：最低位移入 `CF`，而 `CF` 原来的旧值则移入最高位。
- **核心价值**：`RCL` 与 `RCR` 是处理 **32 位甚至 64 位大数多精度移位** 的核心工具。

### 移位指令对标志位设置的严密规则

| 标志位 | 影响规则与技术内涵 |
| :--- | :--- |
| **CF（进位标志）** | **必受影响**。无论左移还是右移，`CF` 始终保留**最后一次移出**的那一个二进制位的值。 |
| **OF（溢出标志）** | **仅在移位次数为 1 时有效**！若移位 1 位后结果的最高符号位发生改变，则 $OF = 1$；若符号位未变，则 $OF = 0$。移位次数大于 1 时，OF 状态不确定。 |
| **ZF（零标志）** | 根据最终移位结果是否全 0 进行设置（全 0 置 1，非 0 置 0）。循环移位不影响 ZF。 |
| **SF（符号标志）** | 反映移位后结果的最高位（若为 1 则置 1）。循环移位不影响 SF。 |

> **注意**：非循环移位（`SHL`/`SHR`/`SAR`）会影响 `SF`、`ZF`、`PF`、`CF`；而循环移位指令（`ROL`/`ROR`/`RCL`/`RCR`）**只影响 CF 和 OF**，绝不改变 `ZF` 和 `SF`！这是期末选择题的高频考点。

### 典型算法实战：移位加速乘法与高精度数据处理

#### 实战一：巧妙利用移位实现快速乘法

在没有硬件浮点加速器的底层开发中，求一个数乘以 10 是极为频繁的操作（例如将 ASCII 字符逐位解析为十进制数）。直接调用 `MUL` 指令开销过大，如何用移位高效完成？

**算法数学推导**：
$$X \times 10 = X \times (8 + 2) = (X \times 2^3) + (X \times 2^1)$$

```assembly
; 设待乘以 10 的数值存于 AX 中
MOV BX, AX        ; 备份原数值 X 到 BX
SHL AX, 1         ; AX = X * 2
SHL BX, 1
SHL BX, 1
SHL BX, 1         ; BX = X * 8 (左移 3 次)
ADD AX, BX        ; AX = (X * 2) + (X * 8) = X * 10
```
利用加法和左移，原本需要数十个周期的乘法运算被压缩到只需数个周期即可飞速完成。

#### 实战二：32 位双字数据的级联左移

设一个 32 位无符号整数存放在 `DX:AX` 中（高 16 位在 `DX`，低 16 位在 `AX`）。现要求将其整体左移 1 位（即整体乘以 2）：

```assembly
SHL AX, 1         ; 低 16 位左移 1 位，最高位溢出并进入 CF
RCL DX, 1         ; 高 16 位带进位循环左移 1 位，CF 中的位被移入 DX 的最低位！
```

```text
双字 32 位级联左移拓扑:
[ CF ] <── [ DX (高16位) ] <── [ CF 暂存位 ] <── [ AX (低16位) ] <── 0
```

通过 `SHL` 与 `RCL` 的无缝接力，我们就可以极其优雅地构建出任意位宽（64 位、128 位甚至更高）的高精度移位算子。

## 【拯救者】Ep_第六章-移位指令和转移指令(下)
> 对应分集：P16 | 原始标题：《【拯救者】Ep_第六章-移位指令和转移指令(下)》

我们在编写汇编程序时，如果指令只能一条接一条地从前向后顺序执行，计算机就只能完成最呆板的流水账计算。真正赋予程序“智能”与灵活性的，正是控制流的改变。而控制流改变的核心，就是转移指令。转移指令的本质到底是什么？它在底层究竟动了 CPU 的哪根神经？为什么期末考试里老师总喜欢在转移范围、有符号数与无符号数的判断跳转上反复出题挖坑？这一讲我们就把 8086 架构下的所有转移指令彻底拆开，从底层寄存器修改机理讲到标志位逻辑推导，帮大家把这一块硬骨头彻底拿下。

### 转移指令的本质与分类架构

很多同学一看到 JMP、JZ、JAE 这些花里胡哨的助记符就觉得头大，死记硬背往往到了考场上一紧张就全乱了。其实抓住底层本质，转移指令就做了一件事：**修改指令指针寄存器 IP 的值（如果是跨段跳转，还要同时修改代码段寄存器 CS 的值）**。

CPU 每次取指令执行，都是由段寄存器 `CS` 和偏移地址寄存器 `IP` 共同决定物理地址（$\text{物理地址} = \text{CS} \times 16 + \text{IP}$）。顺序执行时，CPU 每读入一条指令的机器码，IP 就会自动加上该指令的字节长度，指向紧随其后的下一条指令；而转移指令的执行，就是强行改写 IP（以及 CS），让 CPU 下一次从一个全新的地址去预取指令，从而打破线性的执行流。

```text
+---------------+       JMP / 转移指令触发
| 当前指令 CS:IP | ---------------------------+
+---------------+                           |
        | 顺序自增 (通常执行)                 | 强行改写 IP (及 CS)
        v                                   v
+---------------+                   +-----------------+
| 下一条顺序指令 |                   | 目标地址对应指令 |
+---------------+                   +-----------------+
```
上图展示了顺序执行与发生转移时 CPU 指令预取流向的分流过程。

我们根据控制流转移的距离和范围，把转移指令划分为段内转移和段间转移两大类；又根据跳转前是否需要评估条件，划分为无条件转移与条件转移。

| 转移分类 | 英文名称 | 修改的寄存器 | 位移量 / 寻址范围 | 典型指令 |
| :--- | :--- | :--- | :--- | :--- |
| **段内短转移** | Short Jump | 仅修改 IP | 8 位有符号相对位移量（$-128 \sim +127$ 字节） | `JMP SHORT label`、所有条件转移指令 |
| **段内近转移** | Near Jump | 仅修改 IP | 16 位有符号相对位移量（$-32768 \sim +32767$ 字节）或直接装载绝对偏移 | `JMP NEAR PTR label`、`JMP AX`、`JMP [BX]` |
| **段间远转移** | Far Jump | 同时修改 CS 和 IP | 全局任意代码段地址（装入新的 CS 与 IP） | `JMP FAR PTR label`、`JMP DWORD PTR [BX]` |

> **核心法则**：
> 1. 凡是**段内转移**，代码段寄存器 `CS` 保持不变，CPU 仅仅改变 `IP`；
> 2. 凡是**段间转移**，`CS` 和 `IP` 必须成对更新，先载入偏移地址到 `IP`，再载入段基址到 `CS`；
> 3. 凡是**条件转移指令**，在 8086 汇编中全部属于**段内短转移**，跳转范围严格限制在 $-128 \sim +127$ 字节之间！

### 无条件转移指令与寻址模式

无条件转移指令 `JMP` 没有任何判断门槛，执行到它必须无条件发生跳转。但 `JMP` 在机器指令层面的实现方式非常丰富，考点极多。

#### 段内直接转移与相对位移量计算

段内直接转移是指目标地址以标号（Label）形式直接写在指令中。很多初学者误以为汇编器会把标号对应的绝对地址硬编码在 `JMP` 的机器码里，这是极其普遍的一个误区！

> **易错点**：
> `JMP SHORT label` 和 `JMP NEAR PTR label` 的机器码中保存的**不是**目标的绝对偏移地址，而是**相对位移量（Relative Displacement）**！

CPU 在执行段内直接转移时，计算新 IP 的硬件公式为：

$$IP_{\text{新}} = IP_{\text{当前}} + \text{位移量}$$

这里的 $IP_{\text{当前}}$ 实际上是**紧接着该 JMP 指令的下一条指令的首地址**。因为当 CPU 读完 JMP 指令机器码进入执行阶段时，IP 已经自动后移指向了下一条指令。

位移量的计算公式为：

$$\text{位移量} = \text{目标标号地址} - \text{JMP 指令下一条指令的地址}$$

- **短转移（SHORT）**：位移量占 1 个字节（8 位补码），范围为 $-128 \sim +127$ 字节。机器指令格式为 `EB ib`（共 2 个字节）。
- **近转移（NEAR PTR）**：位移量占 2 个字节（16 位补码），范围为 $-32768 \sim +32767$ 字节。机器指令格式为 `E9 iw`（共 3 个字节）。

```x86asm
; 段内直接转移示例
    JMP SHORT NEXT_STEP   ; 机器码 EB 05 (假设位移量为 +5)
    MOV AX, 1234H         ; 这条指令被直接跳过
NEXT_STEP:
    MOV BX, AX
```

#### 段内间接转移

段内间接转移的目标偏移地址不是算出来的相对值，而是**直接存放在寄存器或内存字单元中的绝对偏移量**。

- **寄存器寻址**：如 `JMP AX` 或 `JMP BX`。执行结果为 $(IP) \leftarrow (AX)$，直接把寄存器里的数值当作下一个指令的偏移地址。
- **内存寻址**：如 `JMP WORD PTR [BX]` 或 `JMP WORD PTR [TABLE + SI]`。CPU 访问数据段，读取对应的 16 位字，将其直接写入 IP 寄存器。

```x86asm
; 寄存器与内存间接转移
    MOV BX, OFFSET TARGET_ADDR
    JMP BX                     ; IP 直接变为 TARGET_ADDR

    JMP WORD PTR [BX]          ; 从 DS:[BX] 取出一个字放入 IP
```

#### 段间转移与跨段控制流

当程序规模变大，代码被分配在不同的代码段（Code Segment）时，就必须使用段间转移。

- **段间直接远转移**：
  语法为 `JMP FAR PTR label`。机器码中直接包含了目标代码段的段地址与偏移地址，格式为 `EA iw id`（共 5 字节，包含 2 字节偏移量与 2 字节段地址）。执行时，指令中的偏移地址送入 `IP`，段基址送入 `CS`。
- **段间间接远转移**：
  语法为 `JMP DWORD PTR [mem]`。CPU 必须从内存连续读取 4 个字节（双字）：**低字送入 IP，高字送入 CS**。

```x86asm
; 段间间接转移内存数据分布
; 假设内存地址 DATA_SEG:0100H 处存放数据: 00 20 00 10 (十六进制)
    JMP DWORD PTR [0100H]
; 执行后: IP 获得低字 2000H, CS 获得高字 1000H
; CPU 下一条指令将从物理地址 1000H:2000H 处取指执行！
```

### 条件转移指令判定体系与标志位映射

条件转移指令是编写分支、循环的核心工具。我们必须牢记两条底线法则：
1. **条件转移指令本身绝不修改任何标志位**；
2. 条件转移的依据全部来自于**前面已经执行过的指令（通常是 CMP、TEST、ADD、SUB、AND 等）在标志寄存器 FLAGS 中留下的状态**。

#### 基于单一标志位状态的基础跳转

这类指令直接观察某一个特定标志位是 0 还是 1：

| 指令助记符 | 判定标志位状态 | 语义含义 | 典型前导指令 |
| :--- | :--- | :--- | :--- |
| `JZ` / `JE` | $ZF = 1$ | 结果为零 / 比较结果相等（Zero / Equal） | `CMP AX, BX` 或 `SUB AX, BX` |
| `JNZ` / `JNE` | $ZF = 0$ | 结果非零 / 比较结果不等（Not Zero / Not Equal） | `CMP AX, BX` 或 `OR AX, AX` |
| `JC` / `JB` | $CF = 1$ | 有进位或借位（Carry） / 无符号数低于 | `ADD AX, BX` 或 `CMP AX, BX` |
| `JNC` / `JNB`| $CF = 0$ | 无进位无借位（No Carry） / 无符号数高于等于 | `ADD AX, BX` 或 `CMP AX, BX` |
| `JO` | $OF = 1$ | 发生有符号溢出（Overflow） | `ADD AX, BX` 或 `IMUL BX` |
| `JNO` | $OF = 0$ | 未发生有符号溢出（No Overflow） | `ADD AX, BX` |
| `JS` | $SF = 1$ | 运算结果为负（Sign，最高符号位为 1） | `TEST AL, 80H` 或 `SUB AL, BL` |
| `JNS` | $SF = 0$ | 运算结果为正或零（No Sign，最高符号位为 0）| `SUB AL, BL` |
| `JP` / `JPE` | $PF = 1$ | 低 8 位中 1 的个数为偶数（Parity Even） | 串行通讯奇偶校验 |
| `JNP` / `JPO`| $PF = 0$ | 低 8 位中 1 的个数为奇数（Parity Odd） | 串行通讯奇偶校验 |

#### 无符号数比较跳转逻辑推导

两个无符号数做比较（执行 `CMP AX, BX`，实质是内部执行无借位减法 $AX - BX$，只改变标志位不回写结果）：

- 若 $AX > BX$：不会发生借位（$CF = 0$），且差值不为零（$ZF = 0$）。此时使用指令 `JA`（Jump if Above）或 `JNBE`（Jump if Not Below or Equal）。
- 若 $AX \ge BX$：只要没产生借位就成立（$CF = 0$）。此时使用指令 `JAE`（Jump if Above or Equal）或 `JNB`。
- 若 $AX < BX$：小减大必然产生借位（$CF = 1$）。此时使用指令 `JB`（Jump if Below）或 `JNAE`。
- 若 $AX \le BX$：产生借位或差值为零（$CF = 1 \lor ZF = 1$）。此时使用指令 `JBE`（Jump if Below or Equal）或 `JNA`。

> **记忆口诀**：无符号数认准 **A（Above，高）** 和 **B（Below，低）**，其底层看的是 **CF（借位）** 与 **ZF（是否相等）**。

#### 有符号数比较跳转逻辑推导

有符号数的比较是整个汇编转移指令中逻辑最深、考得最细的地方。有符号数认准 **G（Greater，大）** 和 **L（Less，小）**。有符号数的正负不能单看符号位 `SF`，必须将符号标志位 `SF` 与溢出标志位 `OF` 结合起来综合判断！

为什么单看 `SF` 是错误的？我们来看一个经典的算术例子：
假设 $AL = 7FH (+127)$，$BL = 80H (-128)$。二者均为 8 位有符号补码。
执行 `CMP AL, BL`，底层计算 $7FH - 80H$：
$7FH - 80H = 7FH + (-80H \text{ 的补码}) = 7FH + 80H = FFH (-1)$。
此时最高位为 1，导致 $SF = 1$！
如果只看 $SF = 1$，岂不是得出 $+127 < -128$ 的荒谬结论？
问题出在哪里？正数减负数，结果超出了 8 位有符号数表示范围（$+127 - (-128) = 255 > 127$），产生了溢出，此时硬件将 $OF$ 置为了 1！

```text
有符号数减法 CMP A, B (计算 A - B)
             |
      检查溢出标志 OF
      /              \
  OF = 0 (无溢出)    OF = 1 (发生溢出)
    |                  |
真实结果符号即为 SF    真实结果符号发生反转 (NOT SF)
    |                  |
+----------------------+
| 真实比较大小准则: SF XOR OF
| - 若 SF == OF (异或为0) ==> A >= B
| - 若 SF != OF (异或为1) ==> A <  B
+------------------------------------
```
上图揭示了有符号数比较中 SF 与 OF 异或判定真实代数大小的内在机理。

根据上述推导，有符号数比较跳转的核心判定条件如下：

| 条件转移指令 | 助记符含义 | 成立判定条件 | 逻辑本质解析 |
| :--- | :--- | :--- | :--- |
| `JL` / `JNGE` | 小于转移 / 不大于等于 | $SF \oplus OF = 1$ | 真实代数差为负数 |
| `JNL` / `JGE` | 不小于转移 / 大于等于 | $SF \oplus OF = 0$ | 真实代数差为非负数 |
| `JLE` / `JNG` | 小于等于 / 不大于 | $(SF \oplus OF = 1) \lor (ZF = 1)$ | 真实代数差为负数或相等 |
| `JNLE` / `JG` | 不小于等于 / 大于 | $(SF \oplus OF = 0) \land (ZF = 0)$ | 真实代数差为正数且不相等 |

> **提示**：考试遇到选择题或程序阅读题，凡是比较带有正负号概念的数据，一律找包含 `G` 或 `L` 的指令；凡是比较地址、纯计数值或无符号整数，一律找包含 `A` 或 `B` 的指令。

#### 专用寄存器测试转移指令

在 8086 指令集中，还有一条非常特殊的转移指令：`JCXZ label`（Jump if CX is Zero）。
- **指令功能**：当且仅当寄存器 `(CX) = 0` 时发生跳转，否则继续顺序执行。
- **关键属性**：该指令**不影响任何标志位**，也**不依赖任何标志位**，它直接在指令执行周期内探查内部通用寄存器 CX 的内容。它也是一个段内短转移指令（跳转范围 $-128 \sim +127$ 字节）。
- **应用场景**：在进入循环（尤其是 `LOOP` 循环）之前，先执行一次 `JCXZ`，防止计数器初值为 0 时导致严重错误。

### 分支程序设计经典范式与陷阱规避

在掌握了各类转移指令后，我们来看实际代码中如何搭建高质量的分支结构。

#### 双分支结构的标准代码范式

双分支结构对应高级语言中的 `if-else`。其汇编模板必须保证分支互斥，执行完第一个分支后必须用 `JMP` 越过第二个分支。

```x86asm
; 实现逻辑: if (AX >= BX) { AX = AX - BX } else { AX = BX - AX }
    CMP AX, BX
    JL  AX_LESS_BX       ; 如果 AX < BX，转入小于分支
    
    ; AX >= BX 的分支体
    SUB AX, BX
    JMP BRANCH_END       ; 必须跳过 else 分支！

AX_LESS_BX:
    ; AX < BX 的分支体
    MOV CX, BX
    SUB CX, AX
    MOV AX, CX

BRANCH_END:
    ; 分支汇合点
```

#### 常见开发陷阱与规避

> **易错点一：相对跳转越界（Relative jump out of range）**
> 由于所有的条件转移（JZ, JNZ, JB, JG 等）只能跳 $-128 \sim +127$ 字节，当分支体代码很长时，直接写 `JZ FAR_LABEL` 会导致汇编报错。
> **解法**：使用相反条件进行就近中转。
> ```x86asm
> ; 错误写法（当 FAR_LABEL 距离超过 127 字节时编译失败）:
> ;   JZ FAR_LABEL
> 
> ; 正确标准改写范式:
>     JNZ SKIP_JUMP        ; 条件取反，短跳越过
>     JMP NEAR PTR FAR_LABEL ; 利用 JMP 的 32KB 近跳转能力
> SKIP_JUMP:
>     ; 继续后续代码
> ```

> **易错点二：转移指令打乱标志位测试链**
> 条件转移指令不会改变标志位，但如果在 `CMP` 和条件转移指令之间插入了其他算术或逻辑指令（例如为了打印或暂存中间结果执行了 `ADD`、`OR`），前序的标志位就会被无情冲掉。如果要暂存标志位状态，必须使用 `PUSHF` 和 `POPF`。

### 移位指令语法规范与代数运算题

#### 移位计数规范与指令合法性辨析题

在 8086 指令系统中，移位指令（`SHL`、`SHR`、`SAL`、`SAR`、`ROL`、`ROR`、`RCL`、`RCR`）的第二个操作数（移位次数）有着极其严格的硬件语法约束。

**【典型考题】**
判断下列指令是否合法，若不合法请指出原因并写出正确的汇编指令序列：
1. `SHL AX, 1`
2. `SHR BX, 4`
3. `ROL CL, 2`
4. `SAR DX, AL`

**【推导与考点解析】**
8086 CPU 的微代码设计规定：
- 当移位次数仅为 **1 次** 时，移位次数可以作为立即数直接写在指令中（即 `1`）；
- 当移位次数 **大于 1 次** 时，移位次数**必须且只能预先存入 `CL` 寄存器**中，指令的第二操作数只能写 `CL`，绝不能写立即数，也不能使用除 `CL` 以外的任何其他寄存器（如 `CH`、`AL` 等）。

> **易错点**：
> 后来奔腾（80186 及更高版本）处理器支持了大于 1 的立即数移位，但是在标准的 8086 微机原理与汇编语言期末考试中，一律严格以 8086 规范为准！写 `SHL AX, 4` 必扣全部分数！

**【标准答案】**
1. `SHL AX, 1`：**合法**。移位次数为 1，可以直接写立即数。
2. `SHR BX, 4`：**不合法**。移位次数大于 1，不能使用立即数 4。
   - 正确修改序列：
     ```x86asm
     MOV CL, 4
     SHR BX, CL
     ```
3. `ROL CL, 2`：**不合法**。移位次数大于 1，必须使用 `CL` 寄存器传递计数，且源操作数与计数器不能冲突。
   - 正确修改序列：
     ```x86asm
     MOV AL, CL    ; 先把需要移位的数据转移到其他寄存器
     MOV CL, 2     ; CL 专门用来做计数器
     ROL AL, CL
     ```
4. `SAR DX, AL`：**不合法**。移位计数器只能使用 `CL` 寄存器，不能使用 `AL`。
   - 正确修改序列：
     ```x86asm
     MOV CL, AL
     SAR DX, CL
     ```

#### 移位与加减法合成快速乘除法题

在很多微处理器控制场景或嵌入式实时系统中，乘法指令 `MUL`/`IMUL` 的执行周期非常长（8086 上需要 70~150 多个时钟周期），而移位和加法指令仅需几个时钟周期。因此利用移位和加法构造快速乘法，是各大高校必考的经典编程设计题。

**【典型考题】**
已知寄存器 `AX` 中存放一个非负整数，要求在**不使用乘法指令 `MUL`** 的前提下，编写最短的汇编指令序列，实现 $AX = AX \times 10$。假定计算过程中不会发生数值溢出。

**【推导与考点解析】**
我们要将乘数 10 分解为 2 的幂次方之和：

$$10 = 8 + 2 = 2^3 + 2^1$$

因此对于任何数值 $X$，都有：

$$X \times 10 = X \times (2^3 + 2^1) = (X \times 2^3) + (X \times 2^1) = (X \ll 3) + (X \ll 1)$$

在二进制运算中，左移 1 位等于乘以 2，左移 3 位等于乘以 8。
我们设计运算路径时，要注意保留原始基数：
1. 先把原数 $X$ 备份一份到临时寄存器（如 `BX`）；
2. 对 `AX` 左移 1 位，得到 $2X$；
3. 将 $2X$ 再次暂存到 `BX`；
4. 将 `AX` 再左移 2 位（总共相当于原数左移 3 位，即 $8X$）；
5. 将 $8X$ 与暂存的 $2X$ 相加，得到 $10X$！

```text
       AX (原始值 X)
      /             \
    左移 1 位        左移 1 位暂存为 BX
     AX = 2X          BX = 2X
        |               |
    再左移 2 位          |
     AX = 8X            |
        \               /
         ADD AX, BX ===> 最终 AX = 8X + 2X = 10X
```
上图直观展现了乘法算子分解为移位累加的数据流向分配。

**【标准代码实现】**
```x86asm
    SHL AX, 1       ; AX = AX * 2
    MOV BX, AX      ; BX = AX * 2 (暂存 2 倍)
    SHL AX, 1       ; AX = AX * 4
    SHL AX, 1       ; AX = AX * 8 (再移 2 位得到 8 倍)
    ADD AX, BX      ; AX = 8X + 2X = 10X
```
> **技巧总结**：这里左移 1 位连续写了三次 `SHL AX, 1`，比使用 `MOV CL, 2; SHL AX, CL` 所需的字节数更少、周期更短，是非常漂亮的满分答题写法！

### 转移指令位移量与机器码计算题

#### 相对位移量正反推算题

**【典型考题】**
某 8086 程序片段如下，已知代码段基址为 `CS = 2000H`：
```text
地址(偏移)   指令
0100H       JMP SHORT NEXT
0102H       MOV AX, 0
...
0120H       NEXT: ADD AX, 1
```
请问：
1. 该段代码中 `JMP SHORT NEXT` 指令机器码中的 8 位相对位移量是多少（用十六进制表示）？
2. 若将目标标号 `NEXT` 改在地址 `00E0H` 处，则该 `JMP SHORT NEXT` 的 8 位位移量又是多少？

**【推导与计算过程】**
硬件计算段内直接转移的基准公式为：

$$\text{位移量} = \text{目标地址} - \text{JMP 指令下一条指令的地址}$$

`JMP SHORT` 属于双字节指令，指令本身占据 2 个字节（操作码 `EB` 占 1 字节，位移量占 1 字节）。
当前 JMP 指令起始地址为 `0100H`，因此其下一条指令的地址为：

$$IP_{\text{下一条}} = 0100H + 2 = 0102H$$

**小题 1 计算（正向跳转）：**
目标地址 $\text{NEXT} = 0120H$。

$$\text{位移量} = 0120H - 0102H = +1EH$$

由于 $+1EH$ 在 $-128 \sim +127$（即 $-80H \sim +7FH$）范围内，且为正数，最高符号位为 0，其补码与原码一致，即为 `1EH`。
因此该指令完整的十六进制机器码为：`EB 1E`。

**小题 2 计算（反向跳转）：**
目标地址 $\text{NEXT} = 00E0H$。

$$\text{位移量} = 00E0H - 0102H = -22H$$

这里的差值是一个负数，机器码中必须使用 **8 位有符号补码** 表示！
我们将 $-22H$ 转换为 8 位补码：
- $+22H$ 的二进制为：`0010 0010B`
- 反码（各位取反）：`1101 1101B`
- 补码（反码加 1）：`1101 1110B`，对应十六进制为 `DEH`。
验证：$100H - 22H = DEH$。

**【标准答案】**
1. 正向跳转位移量为 `+1EH`（机器码第二字节为 `1EH`）；
2. 反向跳转位移量为 `-22H`，其 8 位补码为 `DEH`（机器码为 `EB DE`）。

#### 条件转移越界改错题

**【典型考题】**
分析下列汇编程序片段，指出汇编器报告 `Relative jump out of range`（相对跳转越界）的原因，并给出规范的修改方案：
```x86asm
    CMP AX, BX
    JZ  TARGET_PROCESS    ; 汇编报错：跳转距离超过 127 字节
    ADD CX, 1
    ... (此处有 300 字节的其他处理代码)
TARGET_PROCESS:
    MOV DX, 0FFFFH
```

**【推导与考点解析】**
所有条件转移指令（如 `JZ`、`JNZ`、`JC` 等）在 8086 中只有短转移形式（`SHORT`），其位移量仅有 8 位补码，范围只能在 $-128 \sim +127$ 字节之间。当 `TARGET_PROCESS` 与当前指令距离达到 300 字节时，8 位位移量直接溢出。

解决此类问题的标准解题范式是：**逻辑取反 + 近跳转搭桥（Trampoline Pattern）**。
- 将原本的条件 `JZ`（为零转移）取反为 `JNZ`（不为零转移）；
- 用 `JNZ` 跳过紧随其后的一条 `JMP NEAR PTR` 无条件近跳转指令；
- `JMP NEAR PTR` 拥有 16 位位移量（$\pm 32\text{KB}$），可以轻松覆盖远距离目标！

**【修改后标准代码】**
```x86asm
    CMP AX, BX
    JNZ SKIP_FAR_JUMP           ; 条件取反：若不等则跳过中转跳转
    JMP NEAR PTR TARGET_PROCESS ; 若相等，则利用近跳转直接飞向远端目标
SKIP_FAR_JUMP:
    ADD CX, 1
    ... (300 字节代码)
TARGET_PROCESS:
    MOV DX, 0FFFFH
```

### 标志位推导与符号数大小判别综合大题

#### 标志位状态与多条件分支流向判定

这是期末考试压轴题里必出的选择题或综合分析题，专门考查对有符号数和无符号数比较机理的深层理解。

**【典型考题】**
已知寄存器初始状态为：`AX = 8000H`，`BX = 0001H`。
程序执行了以下指令：
```x86asm
    CMP AX, BX
```
请回答：
1. 执行 `CMP AX, BX` 后，标志位 `CF`、`ZF`、`SF`、`OF` 的值分别是什么？
2. 随后若分别接以下 4 条条件转移指令，哪几条会发生跳转，哪几条不跳转？并说明原因。
   - `JA LABEL1`
   - `JB LABEL2`
   - `JG LABEL3`
   - `JL LABEL4`

**【详细步进推导】**
`CMP AX, BX` 本质上是 CPU 内部进行 16 位减法运算：$AX - BX = 8000H - 0001H$，根据计算结果更新标志寄存器，但不改变 `AX` 的值。

我们把十六进制转换为 16 位二进制进行算术分析：
- $AX = 8000H = 1000\ 0000\ 0000\ 0000B$
- $BX = 0001H = 0000\ 0000\ 0000\ 0001B$
- 运算结果：$8000H - 0001H = 7FFFH = 0111\ 1111\ 1111\ 1111B$

**标志位逐项推导：**
1. **零标志位 ZF**：结果为 $7FFFH 
eq 0$，因此 $ZF = 0$。
2. **符号标志位 SF**：结果最高位（bit 15）为 0，因此 $SF = 0$。
3. **进位/借位标志位 CF**：
   按无符号数解释：$AX = 8000H = 32768$，$BX = 0001H = 1$。
   $32768 > 1$，大数减小数，不需要向更高位借位，因此 $CF = 0$。
4. **溢出标志位 OF**：
   按有符号数解释：$AX = 8000H = -32768$（16 位有符号补码所能表示的最小负数），$BX = 0001H = +1$。
   我们用最小的负数减去一个正数：$(-32768) - (+1) = -32769$。
   而 16 位有符号补码的表示范围是 $-32768 \sim +32767$！$-32769$ 已经发生严重下溢（负向溢出），计算机运算出来的结果反而变成了正数 $7FFFH (+32767)$！
   两个异号数相减，负数减正数结果变为正数，硬件判定发生溢出，因此 $OF = 1$！

```text
  AX = 8000H (-32768)   [负数]
- BX = 0001H (+1)       [正数]
------------------------------
  结果 = 7FFFH (+32767)  [正数！符号位变为 0, SF=0]
  负数减正数竟然得到正数，发生有符号溢出！故 OF = 1
```
上图清晰展现了下溢发生时数值环反转导致 SF 与真实符号不一致的过程。

**转移指令逐条验证：**

| 指令 | 比较类型 | 成立判定条件 | 代入本题标志位判断 | 最终结论 |
| :--- | :--- | :--- | :--- | :--- |
| `JA` | 无符号数高于 | $CF = 0 \land ZF = 0$ | $CF=0, ZF=0$，条件满足 | **发生跳转**（无符号视角：$32768 > 1$） |
| `JB` | 无符号数低于 | $CF = 1$ | $CF = 0$，条件不满足 | **不跳转** |
| `JG` | 有符号数大于 | $(SF = OF) \land (ZF = 0)$ | $SF=0, OF=1 \Rightarrow SF 
eq OF$，不满足 | **不跳转** |
| `JL` | 有符号数小于 | $SF 
eq OF$ | $SF=0, OF=1 \Rightarrow 0 
eq 1$，条件成立 | **发生跳转**（有符号视角：$-32768 < +1$） |

> **关键警示**：
> 同一个减法结果，无符号视角下是“大数减小数”（`JA` 跳转），有符号视角下却是“小数减大数”（`JL` 跳转）！这个题目淋漓尽致地体现了汇编语言的底层之美——**数据本身没有属性，有无符号全看你用什么指令去解读标志位！**

**【标准答案】**
1. 标志位：$CF = 0$，$ZF = 0$，$SF = 0$，$OF = 1$。
2. 转移结果：
   - `JA` 发生跳转（$CF=0$ 且 $ZF=0$）；
   - `JB` 不跳转（$CF=0$）；
   - `JG` 不跳转（$SF 
eq OF$）；
   - `JL` 发生跳转（$SF 
eq OF$）。
