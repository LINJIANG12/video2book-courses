### 汇编源程序工程构建与执行全流程

我们在编写计算机程序时，高级语言通常经过一键编译运行，而汇编语言则直接暴露出程序从源文本到操作系统加载的底层完整链条。

一个汇编工程从编写到最终落地执行，严格历经四个阶段：

```text
+-------------------------------------------------------------+
| 汇编源程序编译、链接与执行生命周期                           |
|                                                             |
|   +--------------+                                          |
|   | 文本编辑器   | 编辑文本代码                             |
|   +--------------+                                          |
|          |                                                  |
|          v                                                  |
|   [ 1.ASM ]        源程序文件 (纯文本，包含汇编指令与伪指令) |
|          |                                                  |
|          v  (MASM 编译器汇编)                               |
|   [ 1.OBJ ]        目标文件 (包含二进制机器码与重定位信息)   |
|          |                                                  |
|          v  (LINK 链接器链接)                               |
|   [ 1.EXE ]        可执行文件 (操作系统可直接加载执行)       |
|          |                                                  |
|          v  (DOS / OS 加载到内存)                           |
|   [ 内存执行空间 ] CPU 提取 CS:IP 机器码直接运行             |
+-------------------------------------------------------------+
```
*图解说明：文本源文件经过编译器（MASM）翻译成二进制目标文件，再由链接器（LINK）绑定库与段信息生成最终的可执行文件。*

1. **源程序（Source File，`.ASM`）**：程序员编写的原始文本代码文件，扩展名为 `.ASM`；
2. **目标文件（Object File，`.OBJ`）**：源文件通过汇编器（如 MASM）进行语法扫描与机器码翻译，生成包含机器语言的目标模块，扩展名为 `.OBJ`；
3. **可执行文件（Executable File，`.EXE`）**：链接器（LINK）将一个或多个 `.OBJ` 文件以及系统库文件进行地址重定位与合并，生成操作系统能够直接识别的二进制执行文件，扩展名为 `.EXE`；
4. **加载运行**：操作系统将 `.EXE` 文件从外存读入内存，为其分配代码段、数据段与堆栈段，将 CPU 的 `CS:IP` 指向入口指令启动执行。

### 汇编指令与伪指令的本质分工

汇编语言源程序中同时存在两种性质截然不同的语句，我们必须在概念上严密区分：

| 特性维度 | 汇编指令（Instruction） | 伪指令（Directive） |
| :--- | :--- | :--- |
| **机器码对应** | 有对应的二进制机器指令码 | **没有**对应的机器码 |
| **执行者** | 最终在 CPU 硬件上运行 | **CPU 绝对不执行**，由汇编编译器（MASM）在编译期识别处理 |
| **核心职能** | 实现具体的算术运算、逻辑判断与数据存取 | 指示编译器如何组织段结构、分配内存空间、关联段寄存器 |
| **典型代表** | `MOV`, `ADD`, `SUB`, `JMP`, `INT` | `SEGMENT`, `ENDS`, `ASSUME`, `END`, `DB`, `DW`, `ORG` |

#### 经典汇编程序骨架解析

一段规范的 8086 汇编程序具备以下不可或缺的基本结构：

```assembly
assume cs:code

code segment
    ; 用户的核心指令区...
    mov ax, 0123h
    add ax, 0003h

    ; 规范的程序安全返回退出机制
    mov ax, 4c00h
    int 21h
code ends

end
```

- **`ASSUME` 关联伪指令**：通知编译器将逻辑段与 CPU 内部的段寄存器建立默认绑定关系（例如 `assume cs:code` 说明逻辑段 `code` 将来用作代码段，基址放入 `CS`）；
- **`SEGMENT` 与 `ENDS` 段界定伪指令**：成对出现，分别标志一个逻辑段的起始与终止；
- **程序返回机制（`MOV AX, 4C00H` 与 `INT 21H`）**：这两条指令是 DOS 系统下的标准退出调用。程序运行完毕后，必须主动将 CPU 控制权安全交还给调用它的操作系统，防止指令指针跑飞；
- **`END` 程序结束伪指令**：标志整个汇编源文件编译结束。编译器扫描到 `END` 后即停止后续代码的翻译。

### 变量定义与常用数据类型伪指令

在汇编语言中，变量用于开辟指定大小的内存存储单元并赋予初始值。

#### 变量定义语法格式

```assembly
变量名  数据类型伪指令  初始值
```

8086 汇编中最常用的三类数据宽度定义伪指令为：
- **`DB`（Define Byte）**：定义**字节**类型，每个变量单元分配 **1 个字节（8 位）**；
- **`DW`（Define Word）**：定义**字**类型，每个变量单元分配 **2 个字节（16 位）**；
- **`DD`（Define Doubleword）**：定义**双字**类型，每个变量单元分配 **4 个字节（32 位）**。

#### 变量命名法定规范

定义变量名（数据标识符）时，必须严格遵守以下规则：
1. 标识符只能由**英文字母、数字和下划线（`_`）**组成；
2. **严禁以数字开头**（例如 `2DATA`、`2DA` 均为非法标识符，编译时直接报错）；
3. **严禁使用系统保留关键字**（例如汇编指令助记符 `MOV`、寄存器名 `AX` 绝不能充当变量名）。

---

### 变量在内存中的小端存储分布

计算机存储器以 8 位的单字节为基本寻址单位。当使用 `DW` 或 `DD` 定义超出 1 个字节宽度的数值时，数据写入内存严格遵循**小端存储（Little-Endian）**模式：

> **核心原则**：**低位数据字节存入低物理地址，高位数据字节存入高物理地址**。

```text
+-------------------------------------------------------------+
| DB / DW / DD 变量在内存中的逐字节展开排布示意                |
|                                                             |
|   定义语句:                                                 |
|   DATA1  DB  1           ; 字节类型: 01H                    |
|   DATA2  DW  1           ; 字类型:   0001H                  |
|   DATA3  DD  2           ; 双字类型: 00000002H              |
|                                                             |
|   偏移地址:      物理内存字节内容      对应逻辑数据          |
|   +----------+   +----------------+   +-------------------+ |
|   |  0006H   |   |      00H       | <--- DATA3 最高位字节   | |
|   +----------+   +----------------+                         |
|   |  0005H   |   |      00H       |                         |
|   +----------+   +----------------+                         |
|   |  0004H   |   |      00H       |                         |
|   +----------+   +----------------+                         |
|   |  0003H   |   |      02H       | <--- DATA3 最低位字节   | |
|   +----------+   +----------------+   +-------------------+ |
|   |  0002H   |   |      00H       | <--- DATA2 高位字节     | |
|   +----------+   +----------------+                         |
|   |  0001H   |   |      01H       | <--- DATA2 低位字节     | |
|   +----------+   +----------------+   +-------------------+ |
|   |  0000H   |   |      01H       | <--- DATA1 单字节       | |
|   +----------+   +----------------+   +-------------------+ |
+-------------------------------------------------------------+
```

- **`DATA1 DB 1`**：分配 1 个字节，十六进制为 `01H`；
- **`DATA2 DW 1`**：分配 2 个字节，数据为 `0001H`。低地址写入低位字节 `01H`，高地址写入高位字节 `00H`；
- **`DATA3 DD 2`**：分配 4 个字节，数据为 `00000002H`。从低地址到高地址依次存入：`02H, 00H, 00H, 00H`；
- **十进制初值自动换算**：若定义 `DA1 DB 10`，十进制数值 10 转换为十六进制为 `0AH`，占用 1 个内存单元，存入的内容是 `0AH`。

### 字符与字符串常量的 ASCII 码映射

在汇编语言中，字符或字符串必须用**英文单引号**括起（例如 `'A'`、`'ABC'`）。汇编器在编译时，会自动将其翻译为对应的 **ASCII 编码**写入内存：

- 字符 `'A'` 的十进制 ASCII 码为 65：
  $$65 = 64 + 1 = 4 \times 16^1 + 1 \times 16^0 = 41\text{H}$$
- 字符 `'B'` 的 ASCII 码为 66，十六进制为 `42H`；
- 字符 `'C'`、`'D'` 依次对应 `43H`、`44H`。

若在数据段中连续定义字符，它们将按字节依次连续存放于内存单元中。

### 批量重复操作符 DUP

在工程编程中，我们经常需要分配大片初始值相同或模式重复的内存缓冲区（如数组、栈区）。如果逐个手写定义会极其繁琐。为此，汇编语言引入了 `DUP`（Duplicated）操作符。

#### 语法格式

```assembly
重复次数  DUP ( 重复内容 )
```

#### 两种典型使用场景

1. **单元素连续分配**：
   ```assembly
   DB 3 DUP(0)
   ```
   表示连续分配 3 个字节单元，每个单元的值均初始化为 `0`。它完全等效于展开手写：
   ```assembly
   DB 0, 0, 0
   ```
2. **多元素模式重复**：
   ```assembly
   DB 3 DUP(0, 1, 2)
   ```
   表示将小括号内的序列 `(0, 1, 2)` 整体重复 3 次。展开后的内存序列为：
   `0, 1, 2, 0, 1, 2, 0, 1, 2`。
   该语句总共分配的内存字节数为：$3 \times 3 = 9$ 个字节。

> **计算规则**：某条带 `DUP` 的语句分配的总字节数 = **外层重复次数 $\times$ 括号内元素个数 $\times$ 每个元素的类型字节宽度**。

### 标号的两大类别与语法差异

标号本质上是内存单元逻辑地址（段内偏移量）的符号别名。汇编程序中的标号严格分为两类：

1. **代码标号（指令标号）**：
   - 出现在代码段的具体指令前端，**末尾必须带有英文冒号**（如 `TARGET:`）；
   - 它代表该指令在代码段内的首字节偏移地址，主要用于 `JMP`、条件跳转或子程序调用指令的目标定位。
2. **数据标号（变量标号）**：
   - 出现在数据定义伪指令的前端，**末尾绝不带冒号**（如 `COUNT DW 100`）；
   - 它代表所定义数据单元的首字节偏移地址，在指令中常作为操作数的地址符号直接引用。

### 地址计数器与定位伪指令 ORG

在汇编过程中，编译器内部维护着一个**地址计数器**，用保留符号 **`$`** 表示。

- **`$` 符号的物理含义**：代表当前汇编语句正在被翻译时的段内偏移地址；
- **`ORG` 伪指令（Origin）**：用于强制改变当前地址计数器 `$` 的数值。
  语法为：
  ```assembly
  ORG 数值
  ```
  例如 `ORG 3` 命令编译器：“立刻将当前地址计数器定位到偏移地址 3 处，后续数据从偏移地址 3 开始存放”。

#### 综合排布演练实例

假设数据段内有如下定义序列：
```assembly
ORG 3
DB 'ABCD'
ORG $+1
NUMBER DW 0100H
```

我们推导其在内存中的具体排布位置：
1. `ORG 3`：地址计数器直接跳到偏移地址 `0003H`；
2. `DB 'ABCD'`：从 `0003H` 开始连续存放 4 个字符的 ASCII 码：
   - 偏移 `0003H`：`'A'` 的 ASCII 码 `41H`
   - 偏移 `0004H`：`'B'` 的 ASCII 码 `42H`
   - 偏移 `0005H`：`'C'` 的 ASCII 码 `43H`
   - 偏移 `0006H`：`'D'` 的 ASCII 码 `44H`
3. `ORG $+1`：此时 `$` 当前处于 `0007H`，执行加 1 后，跳过 1 个字节，地址计数器移至 `0008H`；
4. `NUMBER DW 0100H`：在偏移 `0008H` 处分配一个字（2 个字节）。根据小端原则：
   - 偏移 `0008H` 存放低位字节 `00H`；
   - 偏移 `0009H` 存放高位字节 `01H`。

#### 变量名合法性辨析题

> **题干**：下列符号中，合法的汇编语言变量名是（　）。  
> A. `2DATA`  
> B. `MOV`  
> C. `DATA_1`  
> D. `DA-TA`

- **考点分析**：考查汇编标识符命名三大原则（只能含字母数字下划线、不能以数字开头、不能使用系统保留字）。
- **解析**：
  A 选项以数字 `2` 开头，非法；B 选项 `MOV` 是指令助记符保留字，非法；D 选项包含中划线减号 `-`，非法；C 选项由字母、下划线和数字组成且首字符为字母，合法。
- **答案**：C。

#### DUP 操作符内存容量计算题

> **题干**：分析下列数据定义语句，计算其在内存中分别分配了多少个字节的存储空间：
> 1. `BUFFER1 DB 3 DUP(0)`
> 2. `BUFFER2 DB 3 DUP(0, 1, 2)`
> 3. `BUFFER3 DW 4 DUP(1, 2)`

- **考点分析**：考查 `DUP` 展开机制与不同数据类型（`DB`、`DW`）空间计算。
- **解析**：
  1. `BUFFER1`：外层 3 次，括号内 1 个元素，类型为字节（1 字节）：$3 \times 1 \times 1 = 3$ 字节；
  2. `BUFFER2`：外层 3 次，括号内 3 个元素，类型为字节（1 字节）：$3 \times 3 \times 1 = 9$ 字节；
  3. `BUFFER3`：外层 4 次，括号内 2 个元素，类型为字（2 字节）：$4 \times 2 \times 2 = 16$ 字节。
- **答案**：
  1. 分配 3 个字节；
  2. 分配 9 个字节；
  3. 分配 16 个字节。

#### 内存变量排布与小端存储推导题

> **题干**：已知数据段中包含定义 `DA1 DB 10` 与 `DA2 DW 0001H`，设 `DA1` 的段内偏移地址为 `0000H`。试写出偏移地址 `0000H`、`0001H` 和 `0002H` 这三个内存单元中存放的十六进制内容。

- **考点分析**：考查十进制转十六进制以及字类型在内存中的小端存放规则。
- **解析**：
  1. `DA1` 占用 1 个字节，初值 10 转换为十六进制为 `0AH`，存入偏移 `0000H` 单元；
  2. `DA2` 为字类型，占用 2 个字节，数据为 `0001H`。按照小端原则，低字节 `01H` 存入低地址 `0001H`，高字节 `00H` 存入高地址 `0002H`。
- **答案**：
  - 偏移 `0000H` 单元存放：`0AH`
  - 偏移 `0001H` 单元存放：`01H`
  - 偏移 `0002H` 单元存放：`00H`

### 汇编源程序的多段标准结构

在标准的 16 位 8086 汇编程序中，一个健壮的工程通常不是只有一个代码段，而是由**代码段（Code Segment）**、**数据段（Data Segment）**和**堆栈段（Stack Segment）**三部分协同构成的。

```assembly
; 完整的多段汇编源程序标准骨架
ASSUME CS:CODE, DS:DATA, SS:STACK

DATA SEGMENT
    BUF    DB 'HELLO$'
    VAR1   DW 1234H
DATA ENDS

STACK SEGMENT
    DW 64 DUP(0)       ; 分配 64 个字（128 字节）的堆栈空间
TOP LABEL WORD         ; 定义栈顶标号
STACK ENDS

CODE SEGMENT
START:
    ; 数据段基址初始化
    MOV AX, DATA
    MOV DS, AX
    
    ; 堆栈段基址初始化（部分旧系统需显式初始化）
    MOV AX, STACK
    MOV SS, AX
    MOV SP, OFFSET TOP

    ; 业务主逻辑代码
    MOV AX, VAR1
    ADD AX, 100H

    ; 安全返回操作系统
    MOV AX, 4C00H
    INT 21H
CODE ENDS

END START              ; 指定程序执行入口为 START 标号
```

#### 段关联伪指令 ASSUME 的真实职责

`ASSUME` 伪指令告诉汇编器（如 MASM）哪一个段名对应哪一个段寄存器。
- `ASSUME CS:CODE, DS:DATA, SS:STACK` 仅仅是在**编译阶段**建立编译器的符号表关联。
- `ASSUME` 绝不会产生任何机器码，更不会在程序运行时自动将段地址装载进段寄存器！

> **易错点**：千万不要以为写了 `ASSUME DS:DATA`，数据段的地址就已经在 `DS` 里面了！这是很多初学者期末丢分的大坑。`DS` 必须在代码段的一开头，由 CPU 显式执行指令去加载。

#### 数据段地址加载的两步规范

为什么在程序开头必须用两行指令给 `DS` 赋值？

```assembly
MOV AX, DATA
MOV DS, AX
```

为什么我们不能直接写 `MOV DS, DATA` 呢？
因为 8086 硬件指令集**不允许将立即数直接传送到段寄存器**（`DS`、`ES`、`SS`、`CS`）。`DATA` 在汇编后被当作一个段基地址立即数处理，必须通过通用数据寄存器（通常用 `AX`）进行中转。

### 程序加载过程与程序段前缀 PSP

当我们在 DOS 提示符下键入程序名并回车时，操作系统并不是把可执行文件直接贴着内存起始位置放下的，而是经过了严格的内存划分。

```text
DOS 加载 EXE 文件的内存布局:
┌──────────────────────────────────────┐
│  程序段前缀 PSP（共 256 字节 / 100H） │ <── DS, ES 指向此处基址
├──────────────────────────────────────┤
│  代码段 CODE                         │ <── CS:IP 指向 START 入口
├──────────────────────────────────────┤
│  数据段 DATA                         │
├──────────────────────────────────────┤
│  堆栈段 STACK                        │ <── SS:SP 指向栈底
└──────────────────────────────────────┘
```

#### 程序段前缀 PSP 结构与段寄存器初值

操作系统加载器在内存中开辟一块连续内存后，首先在头部建立一个大小固定为 **256 字节（100H）** 的控制块，称为 **程序段前缀（Program Segment Prefix，PSP）**。

当控制权刚交给我们的程序入口时，CPU 内部的寄存器状态如下：
- **`CS:IP`**：指向由源程序末尾 `END START` 伪指令所指定的入口地址（`START` 的段基址与偏移地址）。
- **`DS` 与 `ES`**：均默认指向 **PSP 的段基址**。
- **`SS:SP`**：若源程序中显式定义了带有 `STACK` 属性的堆栈段，操作系统会自动将 `SS` 设定为该堆栈段基址，并将 `SP` 指向栈顶。

> **结论**：正因为程序刚刚启动时 `DS` 默认指着操作系统的 PSP 区域，如果我们不显式执行 `MOV AX, DATA; MOV DS, AX`，后续所有访问变量的操作都会误读 PSP 里面的系统数据，从而产生不可预知的错误。

### DOS 系统功能调用 INT 21H 规范

汇编语言不能像高级语言那样直接调用 `printf` 或 `cin`。输入一个字符、打印一串文字、退出程序，都要通过向操作系统发送软中断实现。在 PC 体系中，这就是最经典的 **DOS 21H 号中断**。

调用 DOS 功能调用有固定的三步曲：
1. 在高位寄存器 `AH` 中装入**功能号**；
2. 在指定的寄存器（如 `DL`、`DX`、`AL` 等）中设置**入口参数**；
3. 执行 `INT 21H` 中断指令触发调用；
4. 检查出口参数（返回值）。

| 功能号（AH） | 功能描述 | 入口参数 | 出口参数 | 典型应用场景 |
| :--- | :--- | :--- | :--- | :--- |
| `01H` | 键盘单字符输入并回显 | 无 | `AL = 字符 ASCII 码` | 单键菜单选择、确认按键 |
| `02H` | 屏幕显示单个字符 | `DL = 字符 ASCII 码` | 无 | 打印换行、分隔符、单字符 |
| `09H` | 屏幕显示字符串 | `DS:DX = 字符串首地址` | 无 | 输出提示语、展示计算结果 |
| `0AH` | 键盘带缓冲输入字符串 | `DS:DX = 缓冲区首地址` | 缓冲区写入字符 | 输入长文本、数字字符串 |
| `4CH` | 安全带返回码退出 | `AL = 返回代码（通常为 0）` | 无 | 程序正常结束返回系统 |

### 核心系统功能调用实例剖析

#### 屏幕单字符输出（02H号功能）

```assembly
; 在屏幕上打印字符 'A'
MOV AH, 02H
MOV DL, 'A'       ; 或者 MOV DL, 41H
INT 21H
```

如果我们要打印回车换行，必须连续调用两次 02H 功能，先输出回车符（CR，ASCII 码 `0DH`，光标回到行首），再输出换行符（LF，ASCII 码 `0AH`，光标下移一行）：

```assembly
; 打印换行回车
MOV AH, 02H
MOV DL, 0DH
INT 21H
MOV DL, 0AH
INT 21H
```

#### 屏幕字符串输出（09H号功能）

`09H` 是整个汇编课程中最常考的输出指令。它有一个极其独特的硬性约束：**待输出的字符串必须以美元符号 `$`（ASCII 码 24H）作为终止符**。

```assembly
DATA SEGMENT
    STRING DB 'Welcome to Assembly!', 0DH, 0AH, '$'
DATA ENDS

CODE SEGMENT
    ASSUME CS:CODE, DS:DATA
START:
    MOV AX, DATA
    MOV DS, AX

    MOV AH, 09H
    LEA DX, STRING     ; 将 STRING 的偏移地址装入 DX，等价于 MOV DX, OFFSET STRING
    INT 21H
    
    MOV AX, 4C00H
    INT 21H
CODE ENDS
END START
```

```text
09H 字符串内存扫描示意:
[ 'W' ][ 'e' ][ 'l' ][ 'c' ][ 'o' ] ... [ 0DH ][ 0AH ][ '$' ][ 内存垃圾数据... ]
  ▲                                                     ▲
  │                                                     │
DS:DX 指向起始字符                                     遇到 '$' 立即停止输出
```

> **注意**：如果忘记在字符串尾部添加 `$`，`09H` 功能调用将不会停下，它会沿着内存一路扫描打印，直到在后续的内存单元中偶然碰到一个 `24H` 为止，这在屏幕上会表现为大串乱码甚至程序崩溃。

#### 键盘带缓冲区字符串输入（0AH号功能）

如果要从键盘输入一长串字符（比如用户名、密码），使用 `01H` 循环读取太繁琐，此时使用 `0AH` 带缓冲区输入最标准。

使用 `0AH` 功能前，必须先在数据段中开辟一个特定结构的内存缓冲区：

```assembly
DATA SEGMENT
    BUF DB 50          ; 第 1 字节：预设缓冲区的最大允许字符容量（包括回车符）
        DB ?           ; 第 2 字节：由系统填入的实际键入字符个数（不包含回车符）
        DB 50 DUP(0)   ; 第 3 字节开始：存放实际输入的字符
DATA ENDS
```

```text
0AH 输入缓冲区内部结构:
偏移地址:  +0         +1         +2         +3 ...
内容:    [ 50 ]     [ 实际数 ]  [ 字符1 ]  [ 字符2 ] ... [ 回车符 0DH ]
含义:    最大容量   系统自动填   用户敲击的内容
```

调用代码极其简洁：

```assembly
MOV AH, 0AH
LEA DX, BUF
INT 21H
```

当用户敲击回车键后，输入结束。此时 `BUF+1` 内存单元中存放的是实际输入的字符个数 $N$，而用户输入的第一个字符位于 `BUF+2`。

### 汇编调试工具 Debug 核心指令与排错技法

写完的程序在运行时出现错误，必须借助调试器跟踪排查。Debug 是 DOS 时代最经典的 16 位调试工具，也是所有汇编考试上机题的基石。

```text
Debug 核心命令交互关系:
          ┌─── R ──> 查看/修改寄存器
          ├─── D ──> 查看指定内存内容
          ├─── E ──> 修改内存单元数据
Debug ───┼─── U ──> 反汇编内存机器码为汇编语句
          ├─── A ──> 直接在内存中书写汇编指令
          ├─── T ──> 单步跟踪执行（会钻进中断与子程序）
          ├─── P ──> 单步执行跳过（跳过 CALL 与 INT 指令）
          └─── Q ──> 退出 Debug 返回操作系统
```

#### 观察与修改状态：R、D、E 命令

- **`R` 命令**：
  - 单独输入 `-R`：回车后打印当前所有通用寄存器、段寄存器、标志位以及即将执行的下一条指令。
  - 修改寄存器 `-R AX`：系统会显示 `AX` 的当前值，随后出现 `:` 提示符，直接输入新十六进制值即可。
- **`D` 命令（Dump）**：
  - `-D 1000:0000`：查看段地址 1000H、偏移地址 0000H 起始的 128 个字节内容。
  - `-D DS:0 20`：查看从 `DS:0000` 开始共 20H 个字节的内容。
- **`E` 命令（Enter）**：
  - `-E DS:0 12 34 56 78`：从 `DS:0` 开始连续修改 4 个字节。

#### 单步执行防卡死：T 与 P 命令的区分

在调试包含系统功能调用或循环调用的代码时，`T`（Trace）和 `P`（Proceed）的差别关乎调试效率：
- **`T` 命令**：真正的单步跟踪。遇到 `INT 21H` 时，如果按 `T`，Debug 会一路跳进 DOS 系统的底层中断服务程序内部去执行，可能连续跟踪几百条系统指令都出不来。
- **`P` 命令**：过程步过。当执行到 `INT 21H` 或 `CALL` 指令时，按 `P` 会让 CPU 在后台把整个中断服务程序执行完毕，直接停在紧随其后的下一条指令上。

> **提示**：调试程序时，凡是遇到 `INT 21H`、`CALL` 或 `LOOP`，一律使用 `P` 命令步过；只有要仔细看自己写的计算指令时，才使用 `T` 命令单步跟踪。

### 重复数据操作符 DUP 字节计算大题

`DUP` 题型在选择题和填空题中几乎年年必考，考查重点是嵌套定义时的总字节数统计以及初始值的内存展开。

#### 经典考题

> **题目**：分析下列变量定义语句，计算该变量在内存中所分配的总字节数，并写出前 6 个字节的十六进制初值内容：
> ```assembly
> BUF DB 3 DUP(1, 2 DUP(3), 4)
> ```

#### 深度解题剖析

面对嵌套的 `DUP`，解题的关键是**由内向外层层拆解**。

1. **先算最内层括号**：
   - 表达式中的内层是 `2 DUP(3)`；
   - 它表示将数值 `3` 重复 2 次，展开后序列为：`3, 3`。
2. **合并中间层括号**：
   - 将内层展开后的结果代入上一层：`(1, 2 DUP(3), 4)`；
   - 展开得到序列：`1, 3, 3, 4`；
   - 这一组元素共有 $1 + 2 + 1 = 4$ 个数据项。
3. **计算最外层总数**：
   - 最外层是 `3 DUP(...)`，表示将上述 4 个数据项的序列连续重复 3 次；
   - 整个序列展开为：`1, 3, 3, 4, 1, 3, 3, 4, 1, 3, 3, 4`；
   - 数据项总个数为：$3 \times 4 = 12$ 个。
4. **核验数据类型宽度**：
   - 语句开头使用的是 `DB`（字节类型，每个元素占 1 字节）；
   - 因而分配的总字节数为：$12 \times 1 = 12$ 字节。
   - 前 6 个字节的十六进制内容依次为：`01H, 03H, 03H, 04H, 01H, 03H`。

```text
DUP 嵌套括号展开拓扑:
[ 1, 2 DUP(3), 4 ]
     └──> [ 3, 3 ]
展开单组: [ 1, 3, 3, 4 ]  (共 4 字节)
重复 3 遍: [ 1, 3, 3, 4 ] [ 1, 3, 3, 4 ] [ 1, 3, 3, 4 ] (共 12 字节)
```

> **易错点**：如果题目把开头的 `DB` 换成了 `DW`，千万记住总字节数必须再乘以 2！考试时很多同学算对了元素个数，但眼睛只看数字没看数据类型，白白丢掉 2 分。

### 多类型变量混合定义与小端序内存排布题

考查计算机底层如何以字节为单位组织多字节整数。这类题目要求在草稿纸上画出内存网格图。

#### 经典考题

> **题目**：设数据段定义如下，首变量 `DATA1` 的偏移地址为 `0000H`。
> ```assembly
> DATA1 DB 15, 'AB'
> DATA2 DW 100H, -1
> DATA3 DD 12345678H
> ```
> 请回答：
> 1. 变量 `DATA2` 和 `DATA3` 的起始偏移地址分别是什么？
> 2. 整个数据段共占用了多少个内存字节？
> 3. 写出偏移地址 `0003H` 到 `0006H` 各字节单元存储的十六进制数值。

#### 详细推导步骤

我们从偏移地址 `0000H` 开始，逐行计算各个变量所占用的空间并排列数据：

##### 第一行：DATA1 分析
- 十进制数字 `15` 转换为十六进制是 `0FH`，占用 1 个字节，位于偏移 `0000H`；
- 字符 `'AB'` 是字符常量，占用其 ASCII 码。`'A'` 为 `41H`，`'B'` 为 `42H`。字符按书写顺序从低地址向高地址存放，即 `'A'` 位于 `0001H`，`'B'` 位于 `0002H`；
- `DATA1` 共占用 3 个字节（偏移地址 `0000H` 到 `0002H`）。

##### 第二行：DATA2 分析
- 因为 `DATA1` 占用了 3 个字节，所以 `DATA2` 的起始偏移地址为 `0003H`；
- 第一个元素 `100H` 是字类型（`DW`，占 2 字节）。按**小端序（低字节存低地址，高字节存高地址）**：
  - 低 8 位 `00H` 存入低地址 `0003H`；
  - 高 8 位 `01H` 存入高地址 `0004H`。
- 第二个元素 `-1` 是负数。在汇编中数值以补码存储：
  - 16 位整数 `-1` 的补码是 `FFFFH`；
  - 低字节 `FFH` 存入 `0005H`，高字节 `FFH` 存入 `0006H`；
- `DATA2` 共定义了 2 个字，占用 $2 \times 2 = 4$ 个字节（偏移地址 `0003H` 到 `0006H`）。

##### 第三行：DATA3 分析
- `DATA3` 的起始偏移地址紧接在 `DATA2` 之后，即 $0003H + 4 = 0007H$；
- 元素 `12345678H` 是双字（`DD`，占 4 字节）。小端序排布规则为：
  - 最低字节 `78H` 存入 `0007H`；
  - 次低字节 `56H` 存入 `0008H`；
  - 次高字节 `34H` 存入 `0009H`；
  - 最高字节 `12H` 存入 `000AH`；
- `DATA3` 占用 4 个字节。

| 偏移地址 | 变量归属 | 存放内容（十六进制） | 解释说明 |
| :--- | :--- | :--- | :--- |
| `0000H` | `DATA1` | `0FH` | 十进制数 15 的十六进制表示 |
| `0001H` | `DATA1` | `41H` | 字符 `'A'` 的 ASCII 码 |
| `0002H` | `DATA1` | `42H` | 字符 `'B'` 的 ASCII 码 |
| `0003H` | `DATA2` | `00H` | 字 `0100H` 的低位字节 |
| `0004H` | `DATA2` | `01H` | 字 `0100H` 的高位字节 |
| `0005H` | `DATA2` | `FFH` | 字 `-1`（补码 FFFFH）的低位字节 |
| `0006H` | `DATA2` | `FFH` | 字 `-1`（补码 FFFFH）的高位字节 |
| `0007H` | `DATA3` | `78H` | 双字最低字节 |
| `0008H` | `DATA3` | `56H` | 双字次低字节 |
| `0009H` | `DATA3` | `34H` | 双字次高字节 |
| `000AH` | `DATA3` | `12H` | 双字最高字节 |

#### 最终答案汇总
1. `DATA2` 的起始偏移地址为 `0003H`；`DATA3` 的起始偏移地址为 `0007H`。
2. 整个数据段共占用 $3 + 4 + 4 = 11$ 个字节。
3. `0003H` 到 `0006H` 的内容依次为：`00H, 01H, FFH, FFH`。

### 地址计数器与数组长度动态计算题

#### 经典考题

> **题目**：阅读下列汇编代码段，指出 `COUNT1` 和 `COUNT2` 的最终数值，并说明两者的技术差异：
> ```assembly
> TABLE DW 10, 20, 30, 40, 50
> COUNT1 EQU $ - TABLE
> COUNT2 EQU ($ - TABLE) / 2
> ```

#### 深度解题剖析

1. **理解符号 `$` 的即时性**：
   - 符号 `$` 代表汇编器在处理当前这一行时的偏移地址计数器值。
   - `TABLE` 定义了 5 个字（`DW`），占用 $5 \times 2 = 10$ 个字节。
   - 当编译器扫描完 `TABLE` 这一行到达下一行时，当前地址 `$` 与 `TABLE` 的起始地址相减，即：
     $$\$ - \text{TABLE} = 10$$
   - 因此，`COUNT1` 的值是 **10**，它代表该数组所占用的**总字节数**。
2. **元素个数的换算**：
   - 既然 `TABLE` 是字类型（每个元素 2 字节），元素个数自然等于总字节数除以 2：
     $$COUNT2 = 10 / 2 = 5$$
   - 因此，`COUNT2` 的值是 **5**，它代表数组包含的**有效元素个数**。
3. **EQU 伪指令的机制**：
   - `EQU` 是等值伪指令，类似于 C 语言中的 `#define` 宏替换，不占用任何目标代码空间，在预编译符号表解析时生效。

### 汇编代码查错与改错实战题

考卷中改错题最能考察对汇编语法的综合掌握程度。下面这段代码集中了期末试卷中最具代表性的语法和逻辑错误：

#### 经典考题

> **题目**：下列汇编程序段中有 4 处语法或运行时错误，请逐一指出行号、说明错误原因并给出修正后的正确代码：
> ```assembly
> 1: DATA SEGMENT
> 2:     MSG DB 'PASS EXAMINATION'
> 3: DATA ENDS
> 4: CODE SEGMENT
> 5:     ASSUME CS:CODE, DS:DATA
> 6: START:
> 7:     MOV DS, DATA
> 8:     MOV AH, 09H
> 9:     MOV DX, OFFSET MSG
> 10:    INT 21H
> 11:    MOV AH, 4CH
> 12: CODE ENDS
> 13: END
> ```

```text
错误排查思维导图:
第 7 行:  MOV DS, DATA  ──> 立即数不能直接进段寄存器 (需 AX 中转)
第 2 行:  MSG DB '...'  ──> 09H 字符串输出必须以 '$' 结尾 (否则内存越界乱码)
第 11行:  MOV AH, 4CH   ──> 仅设功能号未执行 INT 21H 中断 (程序无法退出)
第 13行:  END           ──> 必须带入口标号 START (否则 CS:IP 无法正确定位)
```

#### 错误逐项诊断与修正方案

1. **第 2 行错误**：
   - **原因**：字符串 `MSG` 准备使用 DOS 的 `09H` 号功能调用打印，但末尾缺少 `$` 终止符。运行时屏幕将持续输出内存垃圾数据直到偶然遇到 `$`。
   - **修正**：`MSG DB 'PASS EXAMINATION$'`
2. **第 7 行错误**：
   - **原因**：段基地址 `DATA` 是立即数，8086 架构不支持立即数直接向段寄存器 `DS` 传送。
   - **修正**：改为通过通用寄存器中转：
     ```assembly
     MOV AX, DATA
     MOV DS, AX
     ```
3. **第 11 行之后缺失指令**：
   - **原因**：设置了退出功能号 `MOV AH, 4CH`，但随后没有发出软中断触发操作系统回收控制权，程序将直接穿透执行到非法指令区崩溃。
   - **修正**：在第 11 行后补充调用指令：
     ```assembly
     MOV AX, 4C00H
     INT 21H
     ```
4. **第 13 行错误**：
   - **原因**：伪指令 `END` 后面没有指明程序的起始执行标号。没有指定入口时，加载器无法将 `CS:IP` 指向期望的代码段入口 `START`。
   - **修正**：修改为 `END START`。

### 典型程序设计综合小题：大小写字母转换与输入输出

#### 经典考题

> **题目**：编写一个完整的 8086 汇编小程序，要求从键盘读入一个小写英文字母，将其转换为大写字母并在屏幕上下两行位置居左显示出来，最后安全返回 DOS。

#### 核心设计逻辑与 ASCII 码运算

- 大写字母 `'A'` 的 ASCII 码是 `41H`（二进制 `0100 0001B`）；
- 小写字母 `'a'` 的 ASCII 码是 `61H`（二进制 `0110 0001B`）；
- 两者在数值上相差固定值：
  $$61\text{H} - 41\text{H} = 20\text{H}$$
- 因此，小写字母转换为大写字母只需执行：
  $$\text{大写字母} = \text{小写字母} - 20\text{H}$$
  或者在二进制位层面上将第 5 位清零（使用 `AND AL, 11011111B` 或 `AND AL, 0DFH`）。

#### 标准工程源码

```assembly
ASSUME CS:CODE

CODE SEGMENT
START:
    ; 1. 从键盘接收一个字符（01H 功能调用，输入字符存于 AL）
    MOV AH, 01H
    INT 21H
    
    ; 2. 将小写转换为大写
    SUB AL, 20H
    MOV BL, AL        ; 将转换后的大写字母暂存入 BL，防止被后续调用冲掉

    ; 3. 屏幕输出回车换行（02H 功能调用）
    MOV AH, 02H
    MOV DL, 0DH       ; 回车符（光标回到行首）
    INT 21H
    MOV DL, 0AH       ; 换行符（光标下移一行）
    INT 21H

    ; 4. 屏幕输出转换后的大写字符（02H 功能调用）
    MOV DL, BL
    INT 21H

    ; 5. 退出程序返回系统
    MOV AX, 4C00H
    INT 21H
CODE ENDS

END START
```

> **提示**：在做输入输出综合题时，一定要注意通用寄存器的“污染问题”。执行 02H 功能输出回车换行时会覆盖 `AL` 和 `DL` 的内容，所以必须在输出换行之前，把通过 01H 得到的目标字符暂存到 `BL` 中，这是最稳妥的编程习惯。
