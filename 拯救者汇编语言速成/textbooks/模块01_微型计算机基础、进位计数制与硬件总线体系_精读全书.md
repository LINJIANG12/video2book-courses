## 【拯救者】Ep_第1章-基础知识(上)
> 对应分集：P02 | 原始标题：《【拯救者】Ep_第1章-基础知识(上)》

在深入学习真正的汇编指令与寄存器操作之前，我们必须先把计算机底层最根本的基石——数制与进制转换彻底搞明白。

很多同学翻开学校的汇编课本，发现有的教材干脆把进制转换跳过不讲，觉得这属于先修内容；有的同学则虽然天天听到二进制、十六进制，但遇到带小数的换算、或者十六进制大数除法时，手底下依然发虚。计算机硬件内部没有任何高级符号，所有的指令、数据、地址在物理电路上都只是一串高低电平。如果底层的数制换算不熟练，后面讲到内存分段、寻址计算、移位指令和标志位溢出时，你就会处处碰壁。这一讲我们用最清晰的推演，把二、八、十、十六进制的互转脉络一次性扎实打通。

### 常用数制及其后缀标识

我们在纸上写下一个数字，比如 `77`，在没有上下文时很难判定它到底代表什么：它是十进制的七十七，还是八进制、十六进制？因此在汇编语言中，除了默认的十进制可以省略后缀外，其他进制后必须紧跟特定的英文后缀字母，用以明确其数制。

| 进位制 | 英文全称 | 标准后缀 | 数码范围 | 进位规则 | 示例 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **二进制** | Binary | `B` | `0 ~ 1` | 逢二进一 | `10001B` |
| **八进制** | Octal | `O` (或 `Q`) | `0 ~ 7` | 逢八进一 | `1750O` |
| **十进制** | Decimal | `D` (可省略) | `0 ~ 9` | 逢十进一 | `178D` 或 `178` |
| **十六进制** | Hexadecimal | `H` | `0 ~ 9, A ~ F` | 逢十六进一 | `1F4H`, `2BH` |

> **提示**：在十六进制中，大于 9 的数值依次用字母表示：$\text{A}=10, \text{B}=11, \text{C}=12, \text{D}=13, \text{E}=14, \text{F}=15$。汇编源程序中书写十六进制数时，如果最高位是字母（如 `A000H`），前面必须补一个数字 `0`（写成 `0A000H`），否则汇编编译器会将其误识别为变量名或标号。

### 十进制与二进制转换

十进制转二进制遵循核心原则：整数部分采用**除基取余法**，小数部分采用**乘基取整法**。

#### 十进制整数转二进制

整数转换时，将十进制数连续除以 2，每次记录商和余数，直到商为 0 为止；最后将所有的余数**自底向上逆序**排列。

```text
十进制整数 178 转二进制推演：
--------------------------------
178 / 2 = 89 ... 余 0  ^  (最低位 LSB)
 89 / 2 = 44 ... 余 1  |
 44 / 2 = 22 ... 余 0  |
 22 / 2 = 11 ... 余 0  |  自底向上逆序读取
 11 / 2 =  5 ... 余 1  |
  5 / 2 =  2 ... 余 1  |
  2 / 2 =  1 ... 余 0  |
  1 / 2 =  0 ... 余 1  |  (最高位 MSB)
--------------------------------
读取结果：10110010B
```

以更小的数字 17 为例验证：
- $17 \div 2 = 8 \dots 1$
- $8 \div 2 = 4 \dots 0$
- $4 \div 2 = 2 \dots 0$
- $2 \div 2 = 1 \dots 0$
- $1 \div 2 = 0 \dots 1$

商归零停止，从下往上依次取余数，得到 $17\text{D} = 10001\text{B}$。

#### 十进制小数转二进制

小数部分转换时，将纯小数连续乘以 2，每次取出乘积的整数部分（必为 0 或 1），并将剩余的纯小数继续乘以 2。重复该步骤直至纯小数为 0 或达到要求的精度；最后将取出的整数部分**自顶向下顺序**排列。

以十进制数 $53.375$ 为例：

先看整数部分 53（除 2 取余）：
- $53 \div 2 = 26 \dots 1$
- $26 \div 2 = 13 \dots 0$
- $13 \div 2 = 6 \dots 1$
- $6 \div 2 = 3 \dots 0$
- $3 \div 2 = 1 \dots 1$
- $1 \div 2 = 0 \dots 1$

自底向上逆序读取，整数部分为 `110101`。

再看小数部分 $0.375$（乘 2 取整）：
- $0.375 \times 2 = 0.75$，取整数部分 **0**，余小数 $0.75$
- $0.75 \times 2 = 1.50$，取整数部分 **1**，减 1 余小数 $0.50$
- $0.50 \times 2 = 1.00$，取整数部分 **1**，余小数 $0.00$（终止）

自顶向下顺序读取，小数部分为 `.011`。

将整数与小数合并拼接，最终得到：
$$53.375\text{D} = 110101.011\text{B}$$

> **易错点**：很多同学在考试时把读写方向搞反。记住六字口诀：**整数倒，小数顺**。整数除 2 的余数从下往上抄，小数乘 2 的整数从上往下抄。

#### 二进制转十进制（按权展开）

二进制转十进制非常直观，只需按每一位的位权 $2^i$ 展开求和。若小数点左侧为整数，自低向高位权为 $2^0, 2^1, 2^2, \dots$；若小数点右侧为小数，自左向右位权为 $2^{-1}, 2^{-2}, 2^{-3}, \dots$。

以二进制数 `11011.101B` 为例：
- 整数部分：
  $$1 \times 2^4 + 1 \times 2^3 + 0 \times 2^2 + 1 \times 2^1 + 1 \times 2^0 = 16 + 8 + 0 + 2 + 1 = 27$$
- 小数部分：
  $$1 \times 2^{-1} + 0 \times 2^{-2} + 1 \times 2^{-3} = 0.5 + 0 + 0.125 = 0.625$$

求和即得：$11011.101\text{B} = 27.625\text{D}$。

### 八进制与十六进制的转换推演

在实际汇编调试与机器码分析中，八进制和十六进制是压缩长串二进制的最常用工具。

#### 十进制与八进制互转

- **十进制转八进制**：采用除 8 取余法，自底向上读取。
  以 $1000\text{D}$ 为例：
  - $1000 \div 8 = 125 \dots 0$
  - $125 \div 8 = 15 \dots 5$
  - $15 \div 8 = 1 \dots 7$
  - $1 \div 8 = 0 \dots 1$
  
  商归零结束，自底向上读取结果为 `1750O`。

- **八进制转十进制**：按 8 的幂次展开求和。
  以 `135O` 为例：
  $$1 \times 8^2 + 3 \times 8^1 + 5 \times 8^0 = 64 + 24 + 5 = 93\text{D}$$

#### 十进制与十六进制互转

- **十进制转十六进制**：采用除 16 取余法，余数介于 10 到 15 之间时转换为对应字母 A 到 F，自底向上读取。
  以 $500\text{D}$ 为例：
  - $500 \div 16 = 31 \dots 4$
  - $31 \div 16 = 1 \dots 15 \quad (\text{对应 } \text{F})$
  - $1 \div 16 = 0 \dots 1$
  
  自底向上读取结果为 `1F4H`。

- **十六进制转十进制**：按 16 的幂次展开求和。
  以 `2BH` 为例：
  - $\text{B}$ 处于 $16^0$ 位，对应数值 11：$11 \times 16^0 = 11$
  - $2$ 处于 $16^1$ 位：$2 \times 16^1 = 32$
  - 相加得：$32 + 11 = 43\text{D}$

### 二进制与八、十六进制快速分组映射

在底层硬件与汇编阅读中，如果每次都经过十进制中转，计算量极大且容易出错。由于 $8 = 2^3$ 且 $16 = 2^4$，二进制与八进制、十六进制之间存在天然的**定长分组映射关系**。

```text
二进制与十六进制 4 位定长映射示意：
-----------------------------------------------------------
 二进制位组：  [ 1 1 0 1 ]       [ 0 1 1 1 ]
 权值计算：    8 + 4 + 0 + 1     0 + 4 + 2 + 1
 十进制求和：      13                 7
 十六进制码：       D                 7
-----------------------------------------------------------
 最终十六进制结果： D7H
```

#### 二进制与八进制快速互转

1 位八进制数精确对应 3 位二进制数：
- **二进制转八进制**：以小数点为基准，整数部分从右向左每 3 位划分为一组（最高位不足 3 位向左补 0）；小数部分从左向右每 3 位划分为一组（最低位不足 3 位向右补 0）。每组独立转换成对应的 $0 \sim 7$。
- **八进制转二进制**：将每一位八进制数直接展开为 3 位二进制数。
  例如将八进制数 `327O` 展开：
  - $7 \rightarrow 4 + 2 + 1 \rightarrow \text{`111`}$
  - $2 \rightarrow 0 + 2 + 0 \rightarrow \text{`010`}$
  - $3 \rightarrow 0 + 2 + 1 \rightarrow \text{`011`}$
  
  拼接即得二进制：`011010111B`。

#### 二进制与十六进制快速互转

1 位十六进制数精确对应 4 位二进制数：
- **二进制转十六进制**：以小数点为基准，每 4 位划分为一组。
  例如二进制串 `11010111B`：
  - 低 4 位 `0111`：$0 \times 8 + 1 \times 4 + 1 \times 2 + 1 \times 1 = 7$
  - 高 4 位 `1101`：$1 \times 8 + 1 \times 4 + 0 \times 2 + 1 \times 1 = 13 \rightarrow \text{D}$
  
  拼接结果为 `D7H`。

- **十六进制转二进制**：将每位十六进制数拆解为 4 位二进制。
  以 `D7H` 为例：
  - $7 \rightarrow 4 + 2 + 1 \rightarrow \text{`0111`}$
  - $\text{D}(13) \rightarrow 8 + 4 + 1 \rightarrow \text{`1101`}$
  
  合并结果即为 `11010111B`。

熟练掌握 4 位一组的二进制与十六进制速查转换，是在汇编语言中快速分析寄存器状态、内存偏移地址与机器指令编码的核心硬基本功。

## 【拯救者】Ep_第1章-基础知识(下)
> 对应分集：P03 | 原始标题：《【拯救者】Ep_第1章-基础知识(下)》

在日常生活中，我们做算术可以用正负号标明方向，比如 $+74$、$-41$。但在计算机的硬件世界里，晶体管电平只能表达高（1）与低（0），芯片内部根本不存在物理上的正号或负号。更关键的是，计算机硬件如果既要做加法电路、又要做减法电路，设计复杂度与成本将成倍增加。

为了用统一的“加法器”解决包括负数减法在内的所有算术，并精确编码字母与符号，计算机科学家设计了符号位、补码与逻辑运算体系。这一讲我们就从机器数的原码补码推演开始，彻底搞懂计算机底层的加减法本质与四大逻辑运算。

---

### 计算机中的正负数与原码表示

在计算机内部，数值的正负完全交由**符号位（Sign Bit）**来决定：
- **符号位为 0**：代表该数为正数；
- **符号位为 1**：代表该数为负数。

以汇编中最常见的单字节（8 位二进制数）为例，最高位（第 7 位）固定为符号位，剩下的低 7 位（第 $0 \sim 6$ 位）才是真正的数值位。

```text
8 位有符号二进制原码结构：
  +-------+---+---+---+---+---+---+---+
  | 符号位|   7 位数值位 (Bit 6 ~ Bit 0)    |
  +-------+---+---+---+---+---+---+---+
     Bit7   Bit6 ...                    Bit0
   0: 正数
   1: 负数
```

如果数值位全部填满 1，低 7 位能达到的最大幅值为：
$$1 \times 2^6 + 1 \times 2^5 + 1 \times 2^4 + 1 \times 2^3 + 1 \times 2^2 + 1 \times 2^1 + 1 \times 2^0 = 64 + 32 + 16 + 8 + 4 + 2 + 1 = 127$$

我们平时备考可以牢记几个关键的 2 的幂次方基准，随时向前折半或向后倍增推导：
- $2^{10} = 1024$
- $2^9 = 512$
- $2^8 = 256$
- $2^7 = 128$

由于符号位有正有负，8 位原码能表示的数值范围便是 $-127 \sim +127$。但在原码体系下，数值 0 会出现 $+0$（`00000000`）和 $-0$（`10000000`）两种歧义，且两个异号数相加无法直接用简单加法器计算，因此计算机引入了补码机制。

---

### 补码的生成规则与推导演练

在机器内部，有符号数一律采用**补码（Two's Complement）**进行存储和计算。

> **定义**：对于正数，其**补码与原码完全相同**；对于负数，其补码由原码变换而来：**符号位保持为 1 不变，其余数值位按位取反，最后在最低有效位（LSB）加 1**。

我们以负数 $-59\text{D}$ 为例，推演其 8 位补码的生成全过程：

#### 原码确定
数值 59 的绝对值可以拆解为二进制权值之和：
$$59 = 32 + 16 + 8 + 2 + 1 = 2^5 + 2^4 + 2^3 + 2^1 + 2^0$$
对应 7 位数值位为 `0111011`。加上负数符号位 1，得到 $-59$ 的原码：
$$[-59]_{\text{原}} = 10111011\text{B}$$
*(如果是 $+59\text{D}$，原码与补码均为 `00111011B`)*

#### 符号位不变，数值位按位求反
符号位 `1` 维持不变，低 7 位逐位翻转：
$$10111011 \xrightarrow{\text{数值位取反}} 11000100$$

#### 最低位加 1 修正
在取反后的结果末位加 1：
$$11000100 + 1 = 11000101$$

最终得出 $-59\text{D}$ 的 8 位补码表示为：
$$[-59]_{\text{补}} = 11000101\text{B}$$

---

### 补码加减法运算推演

补码最精妙之处在于：**它将减法运算完全转化为加法运算**，无论是正数加正数、正数加负数，还是负数减负数，底层硬件只需要一个纯粹的二进制加法器。

补码运算遵循两大核心代数公式：
$$[X + Y]_{\text{补}} = [X]_{\text{补}} + [Y]_{\text{补}}$$
$$[X - Y]_{\text{补}} = [X]_{\text{补}} + [-Y]_{\text{补}}$$

其中，求一个已知补码数 $[Y]_{\text{补}}$ 的相反数补码 $[-Y]_{\text{补}}$ 拥有极度简洁的通用规则：
> **规则**：将 $[Y]_{\text{补}}$ **连同符号位在内的全部位按位取反，随后在最低位加 1**，即可得到 $[-Y]_{\text{补}}$。

#### 正数与正数相加：$74 + 41$

计算十进制加法 $X + Y$（$X = 74\text{D}$，$Y = 41\text{D}$）：
- $X = 74\text{D} = 64 + 8 + 2 = (01001010)_2$，正数补码即原码：$[X]_{\text{补}} = 01001010\text{B}$
- $Y = 41\text{D} = 32 + 8 + 1 = (00101001)_2$，正数补码即原码：$[Y]_{\text{补}} = 00101001\text{B}$

```text
   01001010  ([74]补)
+  00101001  ([41]补)
----------------------
   01110011
```

- 符号位为 `0`，说明结果为正数；
- 展开计算数值位：
  $$2^6 + 2^5 + 2^4 + 2^1 + 2^0 = 64 + 32 + 16 + 2 + 1 = 115\text{D}$$
  结果与十进制验证完全吻合：$74 + 41 = 115$。

#### 正数与负数相加：$74 + (-41)$

计算 $X + Y$（$X = 74\text{D}$，$Y = -41\text{D}$）：

首先求出 $[-41]_{\text{补}}$：
- $41 = 32 + 8 + 1 = (00101001)_2$
- 原码：$[-41]_{\text{原}} = 10101001\text{B}$
- 数值位取反：`11010110`
- 末位加 1：`11010111`，即 $[-41]_{\text{补}} = 11010111\text{B}$

执行补码逐位相加：
```text
   01001010  ([74]补)
+  11010111  ([-41]补)
-----------------------
 1 00100001
```

> **提示**：8 位加法中，最高位进位产生的第 9 位 `1` 自然溢出丢弃，机器寄存器只保留低 8 位结果 `00100001`。

- 符号位为 `0`，表明结果为正数；
- 数值大小为：$2^5 + 2^0 = 32 + 1 = 33\text{D}$；
- 算术验证：$74 + (-41) = 33$，结论完全正确。

#### 减法化加法推演：$74 - (-41)$

计算 $X - Y$（$X = 74\text{D}$，$Y = -41\text{D}$，本质即 $74 - (-41)$）：

根据减法公式：$[X - Y]_{\text{补}} = [X]_{\text{补}} + [-Y]_{\text{补}}$。
1. 已知 $[Y]_{\text{补}} = [-41]_{\text{补}} = 11010111\text{B}$。
2. 求 $[-Y]_{\text{补}}$：对其全位（含符号位）取反并加 1：
   - 全位按位取反：`00101000`
   - 最低位加 1：`00101001`
   - 得到 $[-Y]_{\text{补}} = 00101001\text{B}$（这正是 $+41$ 的补码）。
3. 两数补码直接相加：
```text
   01001010  ([74]补)
+  00101001  ([-(-41)]补)
-----------------------
   01110011
```
结果与前面的 $74 + 41$ 完全一致，符号位为 0，真值为 $115\text{D}$。计算机仅靠同一套加法逻辑，就完美实现了负数的减法。

### 字符编码与 ASCII 码对照

在微机中，文本、字符和控制指令均由二进制编码表示，工业界最经典的通用规范是 **ASCII（American Standard Code for Information Interchange）码**。

ASCII 码采用 7 位或 8 位二进制编码。在期末与考研真题中，我们不需要死背整张 ASCII 表，但有两组基准值必须形成肌肉记忆：
- **大写字母 `'A'`**：十进制值为 **65**（十六进制 `41H`，二进制 `01000001B`）；
- **小写字母 `'a'`**：十进制值为 **97**（十六进制 `61H`，二进制 `01100001B`）。

> **结论**：大写字母转小写字母，只需在其 ASCII 码上加 $32$（即 $97 - 65 = 32$）；反映到二进制上，32 刚好是第 5 位（$2^5$）。因此大写转小写只要将第 5 位置 1，小写转大写只要将第 5 位置 0。

### 基本逻辑运算

汇编指令中的逻辑操作直接对应底层硬件的门电路，是位操作、掩码过滤、清零与标志位判定的基础。

| 运算符 | 英文名称 | 运算规则 | 助记口诀 |
| :--- | :--- | :--- | :--- |
| `&` | **与（AND）** | 两个操作位同为 1 时结果才为 1，否则为 0 | 全 1 为 1，有 0 则 0 |
| `\|` | **或（OR）** | 两个操作位只要有一个为 1 结果就为 1，全 0 才为 0 | 有 1 为 1，全 0 则 0 |
| `~` | **非（NOT）** | 单目运算，0 变 1，1 变 0 | 逐位取反 |
| `^` / `XOR` | **异或（XOR）** | 两位相异时结果为 1，相同为 0 | 相同为 0，不同为 1 |

#### 逻辑与运算推演
计算十进制 $9 \ \& \ 12$：
- $9\text{D} = 1001\text{B}$
- $12\text{D} = 1100\text{B}$

```text
    1001
  & 1100
  ------
    1000  (数值为 2^3 = 8D)
```

#### 逻辑或运算推演
计算十进制 $9 \ | \ 12$：
```text
    1001
  | 1100
  ------
    1101  (数值为 8 + 4 + 1 = 13D)
```

#### 逻辑非运算推演
单目按位求反：对二进制串 `1011B` 取反：
$$\sim (1011\text{B}) = 0100\text{B}$$

#### 逻辑异或运算推演
计算十进制 $9 \oplus 11$：
- $9\text{D} = 1001\text{B}$
- $11\text{D} = 1011\text{B}$

```text
    1001
  ^ 1011
  ------
    0010  (数值为 2^1 = 2D)
```

> **提示**：在汇编编程中，异或运算有一个经典操作：`XOR AX, AX`。任何数与自身异或，由于每一位都相同，结果必然全为 0。因此在汇编中常用异或自身的方式来快速清零寄存器，其执行速度和机器码长度均优于 `MOV AX, 0`。

### 整数基数除法与余数逆序推导

面对多位十进制整数转换为二、八、十六进制时，核心方法始终是“除基取余”。考场上最容易失分的陷阱有两个：一是中间某一步商数除错导致余数偏差；二是记录余数时顺手写成了自顶向下。

```text
除基取余标准化答题执行框架：
---------------------------------------------
 当前数 ÷ 基数 R = 新商数 ... 余数 r_i
 重复除基，直至商数为 0 终止。
 读取规则：自底向上（从最后一次计算的余数读向第一次）
 权重位置：最后得到的余数为主高位 MSB，首个余数为最低位 LSB
---------------------------------------------
```

以考题中常见的十进制数 $1000$ 为例：
- **转为二进制**：连续除以 2，依次记录余数为 `0, 0, 0, 1, 0, 1, 1, 1, 1, 1`。自底向上逆序组合，立即得到 $(1111101000)_2$。
- **转为十六进制**：连续除以 16。
  - $1000 \div 16 = 62 \dots 8$
  - $62 \div 16 = 3 \dots 14$
  - $3 \div 16 = 0 \dots 3$
  
  十六进制中余数 14 对应字符 $\text{E}$，自底向上读取得到 $\text{3E8H}$。

> **提示**：如果考题同时要求计算一个数的二进制与十六进制，**千万不要从头再做一遍十六进制大数除法**。优先求出二进制后，直接以 4 位为一组向左划线分组（如 `11 1110 1000` 高位补零得 `0011 1110 1000`），即可直接口算出 `3 E 8`，这样既节省宝贵的做题时间，又能进行双向验算。

### 小数乘基取整与定长分组展开

纯小数转换与整数刚好相反，考查的是乘基取整法。

```text
乘基取整法标准时序推演：
  纯小数 × 2 ---> [ 整数部分 ] (直接移出作为结果位，顺序自顶向下)
               |
               +-> [ 剩余纯小数 ] × 2 ---> 循环直至小数归零或满足精度
```

以十进制纯小数 $0.96875$ 为例：
- $0.96875 \times 2 = 1.9375$（取整 1，余 $0.9375$）
- $0.9375 \times 2 = 1.875$（取整 1，余 $0.875$）
- $0.875 \times 2 = 1.75$（取整 1，余 $0.75$）
- $0.75 \times 2 = 1.5$（取整 1，余 $0.5$）
- $0.5 \times 2 = 1.0$（取整 1，小数归 0 终止）

自顶向下顺序记录取出的整数部分，得到 $0.11111\text{B}$。

在将二进制小数转换为十六进制小数时，必须以小数点为界**向右划分**每 4 位为一组，不足 4 位必须在**右侧尾部补零**：
- 第一组：前 4 位 `1111`，对应十六进制 $\text{F}$；
- 第二组：剩下的第 5 位 `1`，向右补三个 0 成为 `1000`，对应十六进制 $8$；
- 合并得出十六进制小数为 $0.\text{F}8\text{H}$。

### 按权展开与特殊位权特征

在选择题中，经常考查形式如 $(100)_R$ 这种高位为 1、低位全 0 的多进制数向十进制转换。这类题不需要按部就班列公式，直接运用权次方公式 $1 \times R^{n-1}$ 秒杀：
- 八进制数 $(100)_8$：三位八进制数，最高位权重为 $8^{3-1} = 8^2 = 64$；
- 十六进制数 $(100)_{16}$：三位十六进制数，最高位权重为 $16^{3-1} = 16^2 = 256$。

#### 整数进制综合转换题

> **题干**：十进制数 $1000$ 对应的二进制数和十六进制数分别是（  ）。  
> 备选形式：给出多组二进制串与十六进制串供选择。

**深度推导与解析**：
1. **求二进制表示**：采用除 2 取余法：
   - $1000 \div 2 = 500 \dots$ 余 0
   - $500 \div 2 = 250 \dots$ 余 0
   - $250 \div 2 = 125 \dots$ 余 0
   - $125 \div 2 = 62 \dots$ 余 1
   - $62 \div 2 = 31 \dots$ 余 0
   - $31 \div 2 = 15 \dots$ 余 1
   - $15 \div 2 = 7 \dots$ 余 1
   - $7 \div 2 = 3 \dots$ 余 1
   - $3 \div 2 = 1 \dots$ 余 1
   - $1 \div 2 = 0 \dots$ 余 1
   
   商为 0 停止计算。余数自底向上逆序读取，得到二进制数为 `1111101000B`。

2. **求十六进制表示**：采用除 16 取余法：
   - $1000 \div 16 = 62 \dots$ 余 8
   - $62 \div 16 = 3 \dots$ 余 14（十六进制中 14 对应字符 $\text{E}$）
   - $3 \div 16 = 0 \dots$ 余 3
   
   商为 0 停止计算。余数自底向上逆序读取，得到十六进制数为 `3E8H`。

**标准答案**：二进制为 $(1111101000)_2$；十六进制为 $\text{3E8H}$。

#### 小数进制转换与分组映射题

> **题干**：十进制小数 $0.96875$ 对应的二进制数和十六进制数分别是（  ）。

**深度推导与解析**：
1. **求二进制小数**：采用乘 2 取整法：
   - $0.96875 \times 2 = 1.9375$ $\rightarrow$ 整数位取 **1**，剩余纯小数 $0.9375$
   - $0.9375 \times 2 = 1.875$ $\rightarrow$ 整数位取 **1**，剩余纯小数 $0.875$
   - $0.875 \times 2 = 1.75$ $\rightarrow$ 整数位取 **1**，剩余纯小数 $0.75$
   - $0.75 \times 2 = 1.5$ $\rightarrow$ 整数位取 **1**，剩余纯小数 $0.5$
   - $0.5 \times 2 = 1.0$ $\rightarrow$ 整数位取 **1**，小数部分归零结束
   
   自顶向下顺序排列整数位，得到二进制小数为 `0.11111B`（小数点后连续 5 个 1）。

2. **转十六进制小数**：直接基于求得的二进制串进行 4 位定长切分：
   - 小数点后前 4 位为 `1111`，转换为十六进制为 $\text{F}$；
   - 第 5 位为 `1`，末尾向右补三个 0 形成 `1000`，转换为十六进制为 $8$；
   - 组合得到十六进制小数为 $0.\text{F}8\text{H}$。

**标准答案**：二进制为 $0.11111\text{B}$；十六进制为 $0.\text{F}8\text{H}$。

#### 数制基数权重计算题

> **题干**：八进制数 $(100)_8$ 和十六进制数 $(100)_{16}$ 转换成十进制数分别是（  ）。

**深度推导与解析**：
- 八进制数 $(100)_8$：按权展开为 $1 \times 8^2 + 0 \times 8^1 + 0 \times 8^0 = 64$；
- 十六进制数 $(100)_{16}$：按权展开为 $1 \times 16^2 + 0 \times 16^1 + 0 \times 16^0 = 256$。

**标准答案**：分别对应十进制数 $64$ 与 $256$。

#### 大数转八进制推导题

> **题干**：十进制数 $2004$ 等值于八进制数（  ）。

**深度推导与解析**：
采用除 8 取余法逐步计算：
- $2004 \div 8 = 250 \dots$ 余 4
- $250 \div 8 = 31 \dots$ 余 2
- $31 \div 8 = 3 \dots$ 余 7（$3 \times 8 = 24$，$31 - 24 = 7$）
- $3 \div 8 = 0 \dots$ 余 3

商为 0 终止。从下往上依次取余数，得到八进制数为 `3724O`。

**标准答案**：$3724\text{O}$。

#### 二进制混合数转十六进制题

> **题干**：二进制数 $(101.01011)_2$ 等值的十六进制表示为（  ）。

**深度推导与解析**：
以小数点为中心，两端分别以 4 位为一组进行分组，不足 4 位补零：
- **整数部分**：`101` 向左补一个 0 成为 `0101`，其数值为 $1 \times 2^2 + 1 \times 2^0 = 5$；
- **小数部分**：
  - 第一组 4 位：`0101`，数值对应为 $5$；
  - 第二组仅剩 1 位：`1`，向右补三个 0 成为 `1000`，数值对应为 $8$；
- 整合整数与小数，最终得到十六进制数为 $5.58\text{H}$。

**标准答案**：$5.58\text{H}$。

## 【拯救者】Ep_第二章-汇编语言的基础
> 对应分集：P05 | 原始标题：《【拯救者】Ep_第二章-汇编语言的基础》

我们在前两讲搞懂了二进制转换与补码运算。很多同学可能会问：既然计算机底层只有 0 和 1，那早期的程序员是怎么写程序的？如果我们要让 CPU 把一个寄存器里的数据送到另一个寄存器中，是不是每次都得硬背一长串二进制机器码？

这就引出了我们这门课的核心角色——汇编语言。同时，要想真正学会汇编语言，就必须看透计算机的硬件系统骨架。CPU 到底是怎么从内存中取出指令的？地址总线、数据总线和控制总线又是如何精密协作的？这一讲我们从语言分类切入，一层层拆开微机底层的硬件构造。

---

### 汇编语言的概念与三大指令分类

在计算机发展的最早期，程序员只能面对枯燥且极易出错的**机器语言（Machine Language）**。机器语言完全由 `0` 和 `1` 构成，比如要表示“把寄存器 BX 的内容传送到 AX 中”，对应的是一串晦涩的二进制编码。

为了摆脱这种非人的编程方式，人们用人类易于记忆的英文缩写助记符（Mnemonic）来代替机器指令，这就诞生了**汇编语言（Assembly Language）**。

例如，同样的传送操作，用汇编语言书写只需一行简洁的代码：
```assembly
MOV AX, BX
```
其含义即为“将 BX 寄存器中的数据复制送到 AX 寄存器中”。

> **易错点**：一定要在概念上牢记：**汇编语言属于低级语言（Low-level Language）**，这是期末选择题的高频考点。常考对比：Java、C++、Python、Go 属于高级语言，而机器语言与汇编语言属于面向机器底层硬件的低级语言。

程序员编写的汇编源程序无法直接被硬件芯片识别。汇编代码必须经过专门的**编译器（Assembler）**进行翻译，编译成由 0 和 1 构成的机器码后，再交给 CPU 硬件执行。

```text
汇编语言执行流向示意：
  +-----------------------+
  |  汇编指令 (MOV AX, BX)|  <--- 程序员编写便于理解的助记符
  +-----------------------+
              |
              v [编译器编译处理]
  +-----------------------+
  |  机器码 (二进制 0与1)  |  <--- 硬件物理电路唯一定义的电平组合
  +-----------------------+
              |
              v [总线传输执行]
  +-----------------------+
  |      CPU 执行硬件     |  <--- 内部寄存器状态更新
  +-----------------------+
```

汇编语言程序由以下三类成分组成：
1. **汇编指令**：有严格对应的机器码，是汇编语言的核心，最终由 CPU 硬件翻译并执行（例如 `MOV`、`ADD`、`SUB`、`JMP`）。
2. **伪指令**：没有对应的物理机器码，CPU 根本不执行伪指令。伪指令是写给编译器看的，用于指导编译器如何分配段、定义数据类型和组织代码结构。
3. **其他符号**：包括标号、变量名以及加减乘除运算符等，同样没有对应机器码，由编译器在编译阶段进行解析和地址计算。

### 计算机核心硬件与存储单元体系

要写好汇编语言，心中必须时刻有一幅硬件连接图。

#### CPU 与内部/外部存储器

CPU（Central Processing Unit，中央处理器）是控制计算机运转的核心大脑。然而再强大的大脑，如果不给它输入记忆和数据，它也无法思考。CPU 运转所必需的**指令**和**数据**，都存放在**存储器（Memory，即内存）**中。

我们日常生活中说的机械硬盘、固态硬盘（SSD）、手机上的 256GB/1TB 闪存，都属于外存储器（磁盘）。磁盘中的程序是不能直接被 CPU 拾取执行的；只有先把磁盘中的程序与数据加载到内存中，CPU 才能对其进行寻址和高速读写。

> **提示**：在内存中，**指令与数据没有任何物理区别**，它们都是一连串平铺直叙的二进制数字。CPU 是如何知道这一串 0 和 1 是代码还是数字的呢？答案在于执行周期：CPU 在取指令周期（Instruction Fetch）从内存取出的内容一律当作指令解释；而在指令执行周期（Execute）根据寻址地址从内存读取的内容一律当作数据处理。

#### 存储单元与容量进位规则

内存被划分为若干个**存储单元**，每个存储单元拥有一个从 0 开始连续递增的唯一物理编号：
- 若存储器具有 128 个单元，其编号即为 $0 \sim 127$；
- 微机系统中，**每一个存储单元固定存放 1 个字节（Byte），即 8 个二进制位（bit）**。

因此，一个拥有 128 个存储单元的芯片，其存储容量为 128 Byte，等价于 $128 \times 8 = 1024$ 个二进制位。

计算机存储容量单位遵循严格的 $1024$（$2^{10}$）阶梯进位：
$$1\text{ TB} = 1024\text{ GB}$$
$$1\text{ GB} = 1024\text{ MB}$$
$$1\text{ MB} = 1024\text{ KB}$$
$$1\text{ KB} = 1024\text{ Byte}$$
$$1\text{ Byte} = 8\text{ bit}$$

### 三类系统总线及其运行推演

CPU 进行一次内存读写操作时，必须解决三个最基本的问题：
1. 对哪一个存储单元进行操作？（**地址信息**）
2. 具体是要读取还是写入？向哪个外设发信号？（**控制信息**）
3. 读出的内容是什么，或者要写进去什么？（**数据信息**）

连接 CPU 与其他芯片并承载这三类信息的导线集合，被称为**总线（Bus）**。

```text
CPU 访问内存读操作时钟逻辑示意：
  +-------+  (1) 地址总线传递地址 "3"   +----------+
  |       | -------------------------> |          |
  |       |  (2) 控制总线发出 "读命令"  |  内  存  |
  |  CPU  | -------------------------> |  3号单元 |
  |       |  (3) 数据总线送回数据 "08H" |  内容08H |
  |       | <========================= |          |
  +-------+                            +----------+
```

#### 地址总线与寻址空间极限

**地址总线的宽度直接决定了 CPU 的物理寻址能力**。

每一根地址线只有高电平（1）和低电平（0）两种状态。若 CPU 拥有 $N$ 根地址总线，其所能表达的不同地址编码组合即为 $2^N$ 种，对应可寻址 $2^N$ 个存储单元。

> **示例**：如果某 CPU 拥有 10 根地址线，若要访问十进制编号为 11 的存储单元：
> $11\text{D} = 8 + 2 + 1 = 2^3 + 2^1 + 2^0 = 1011\text{B}$。
> 此时 10 根地址线从低到高的电平状态为：第 0 位为 1、第 1 位为 1、第 2 位为 0、第 3 位为 1，高 6 位全部维持 0，即总线呈现机器信号 `0000001011`。

#### 数据总线与吞吐效率对比

**数据总线的宽度决定了 CPU 单次与外界进行数据传送的最大位宽与吞吐速率**：
- 8 根数据总线一次只能传输 8 bit（1 个字节）；
- 16 根数据总线一次可以并发传输 16 bit（2 个字节 / 1 个字）。

我们以将 16 位十六进制数 `89D8H` 写入内存为例，对比经典 8088 CPU 与 8086 CPU 的工作机制差异：
- **8088 CPU（外部数据总线为 8 位）**：受限于导线数量，必须分两次进行写入：
  1. 第一次在时钟周期送出低位字节 `D8H`（二进制 `11011000B`）；
  2. 第二次在后续时钟周期送出高位字节 `89H`（二进制 `10001001B`）。
- **8086 CPU（外部数据总线为 16 位）**：拥有 16 根并行数据线，在一个总线读写周期内即可将 `10001001 11011000B`（`89D8H`）完整送出。

#### 控制总线

控制总线是一组专门传递同步与控制状态脉冲的信号线组合。CPU 借助控制总线向外部部件发送读控制、写控制、时钟同步、中断请求与总线响应信号。控制线的数量和形态决定了 CPU 对外部设备的操控粒度。

### 存储器件分类与系统逻辑地址空间

#### 存储芯片的两大阵营：RAM 与 ROM

计算机系统中的存储芯片根据电气特性严格划分为两大类：

| 特性维度 | RAM（随机存取存储器） | ROM（只读存储器） |
| :--- | :--- | :--- |
| **全称** | Random Access Memory | Read-Only Memory |
| **读写权限** | 可读、可写（Read and Write） | 正常运行下只读，不可写入 |
| **断电易失性** | **易失（Volatile）**：断电后数据立刻彻底丢失 | **非易失（Non-Volatile）**：断电后数据完好保存 |
| **典型应用** | 电脑主内存条、CPU 缓存、显卡显存数据区 | 主板 BIOS 芯片、固件引导程序存放区 |

#### 主板架构与接口卡间接控制

主板（Motherboard）是整个计算机微系统的物理骨架，集成了 CPU 插槽、南北桥芯片组、内存插槽和扩展插槽。外部设备（如显示器、扬声器、打印机）功率大、工作逻辑特殊，CPU 无法用引脚直接驱动，必须通过**接口卡（Interface Card，如显卡、声卡、网卡）**进行中间转接与电气隔离。

#### 统一编址的逻辑存储器模型

在真实的主板物理布局中，RAM 主存条、显卡上的显存芯片、主板上的 BIOS ROM 分散在不同的物理板卡上。然而在汇编语言程序员与 CPU 的视角中，所有的物理芯片被统一组织并抽象为一个**连续的逻辑存储器地址空间**。

```text
8086 PC 1MB 逻辑地址空间划分结构：
  FFFFFH +-------------------------------+
         |  主板 ROM BIOS 空间           |
  F0000H +-------------------------------+
         |  各类外设接口卡 ROM 空间      |
  C0000H +-------------------------------+
         |  显示适配器显存缓存空间 (VRAM)|
  A0000H +-------------------------------+
         |  主存储器 RAM 空间 (常规内存)  |
         |  (操作系统及用户应用程序运行区)|
  00000H +-------------------------------+
```

8086 CPU 拥有 20 根地址总线，其物理寻址能力为 $2^{20} = 1,048,576\text{ Byte} = 1\text{ MB}$。
其寻址空间从十六进制的 `00000H` 一直编址到 `FFFFFH`：
- `00000H ~ 9FFFFH`（共 640 KB）：分配给系统主存 RAM，用于装载操作系统和用户编写的汇编程序；
- `A0000H ~ BFFFFH`（共 128 KB）：映射给显示卡的视频存储器（显存），向该空间写入数据可直接在屏幕上显示图案或文字；
- `C0000H ~ FFFFFH`（共 256 KB）：分配给各类适配卡 ROM 以及主板 BIOS ROM，供计算机开机自检与引导使用。

这种将所有物理存储介质合并看待的思想，是理解后续汇编程序段地址寻址与屏幕显存直接写屏操作的认知关键。

### 计算机语言的层级划分与本质

我们经常会遇到针对编程语言级别的概念辨析题目。一个极其高频的易错点是：“汇编语言是高级语言”。

> **易错点**：**汇编语言绝对不是高级语言**！这个结论一定要牢牢记住。

汇编语言在计算机语言体系中属于**低级语言**（Low-Level Language）。要深刻理解这一点，我们需要梳理清楚语言层级的演进逻辑：

- **机器语言（Machine Language）**：计算机硬件唯一能直接识别并执行的二进制代码（由 `0` 和 `1` 构成的操作码和操作数）。它的执行效率极高，但对人类而言极难记忆、编写与调试。
- **汇编语言（Assembly Language）**：为了摆脱二进制代码的晦涩，人们使用助记符（Mnemonic，例如 `MOV`、`ADD`、`SUB`）来一一对应机器指令。汇编语言的指令与机器指令几乎保持一一映射的关系，它直接面向处理器架构、寄存器以及内存物理地址。正因它未脱离特定处理器的硬件底层，它依然属于面向机器的**低级语言**。
- **高级语言（High-Level Language）**：诸如 C、C++、Java、Python 等语言，屏蔽了具体硬件底层细节，具备高度的抽象能力与跨平台移植性，才被称为高级语言。

```text
+--------------------------------------------------------+
| 语言层级演进与硬件抽象距离                               |
|                                                        |
|  [高级语言]   C / C++ / Python （面向算法，脱离具体硬件）  |
|      |                                                 |
|      v  (编译 / 解释)                                   |
|  [汇编语言]   x86 / ARM 助记符 （面向机器，属于低级语言）  |
|      |                                                 |
|      v  (汇编器 MASM 等)                                |
|  [机器语言]   0101 1100 0010 （CPU 纯二进制原生硬件执行） |
+--------------------------------------------------------+
```

因此，在判断题或概念选择题中遇到任何将汇编语言归入高级语言的表述，必须直接判定为错误。

### 系统总线分类与协同工作机理

在微型计算机系统中，CPU 与内存储器、I/O 接口芯片之间的数据交互，完全依赖于**系统总线（System Bus）**。

在 8086 计算机系统中，总线按照传输信号性质的不同，被明确划分为三类：**地址总线**、**控制总线**与**数据总线**。这三组总线在处理器访问存储单元或外部设备时，展现出严密的逻辑协同关系。

#### 三类总线的核心职能

我们要从“CPU 如何完成一次完整的访存操作”来推导并掌握这三类总线：

1. **第一步：定位单元 —— 地址总线（Address Bus, AB）**
   CPU 要对存储器进行操作，首先必须明确到底操作哪一个存储单元。CPU 通过地址总线将目标物理地址发送给内存译码电路，以此在千万个逻辑存储单元中精准选定唯一的目标单元。地址总线是**单向**传输的，方向永远由 CPU 发出指向存储器或外部设备。
2. **第二步：发出指令 —— 控制总线（Control Bus, CB）**
   当通过地址总线找到要操作的存储单元后，具体是要执行“读出（Read）”操作，还是执行“写入（Write）”操作？这就需要由控制总线来传递控制信号。CPU 通过控制总线发出读/写使能信号（例如内存读信号、内存写信号），通知目标单元做好数据交互准备。控制总线包含各类时序控制与状态反馈引脚，整体表现为**双向**（单根信号线具有固定方向）。
3. **第三步：传输数据 —— 数据总线（Data Bus, DB）**
   当目标单元被定位且操作性质（读/写）由控制信号敲定后，真正的数据便开始在 CPU 与存储单元之间流动。如果是“读”操作，存储单元将数据送上数据总线并返回给 CPU；如果是“写”操作，CPU 将内部寄存器中的数据送上数据总线写入存储单元。因此，数据总线是**双向**的。

```text
+-------------------------------------------------------------+
| 8086 微机系统 CPU 与存储器交互三总线拓扑流程                  |
|                                                             |
|   +---------------+                       +---------------+ |
|   |               |====== 地址总线 (AB) ==>| 存储单元定位  | |
|   |               |   (单向：确定逻辑地址)  |               | |
|   |  8086 CPU     |                       | 内存存储矩阵  | |
|   |               |------ 控制总线 (CB) ->| 读/写指令触发 | |
|   | 控制与执行逻辑 |   (发出 MEMR / MEMW)  |               | |
|   |               |                       |               | |
|   |               |<==== 数据总线 (DB) ===>| 字节/字双向流 | |
|   |               |   (双向：返回或写入)    |               | |
|   +---------------+                       +---------------+ |
+-------------------------------------------------------------+
```
*图解说明：微机访存的三部曲严格对应三总线——AB 选址、CB 发令、DB 传输数据。*

### 处理器外部数据总线宽度对比

在期末与各类考试的选择填空中，8086 与 8088 处理器的总线宽度差异是一道经典的常考题。

> **结论**：**8088 的外部数据总线宽度是 8 位，而 8086 的外部数据总线宽度是 16 位**。

为了彻底吃透这个考点，我们需要对比它们的架构特征：

| 处理器型号 | 内部寄存器宽度 | 内部 ALU 运算宽度 | 外部数据总线宽度 | 外部地址总线宽度 | 寻址空间 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Intel 8086** | 16 位 | 16 位 | **16 位**（真 16 位机） | 20 位 | 1 MB |
| **Intel 8088** | 16 位 | 16 位 | **8 位**（准 16 位机） | 20 位 | 1 MB |

很多同学容易疑惑：既然两者的内部运算部件都是 16 位，为什么 8088 的外部数据总线要做成 8 位？
在历史上，8088 推出时市场上廉价成熟的外围芯片多为 8 位架构。为了向下兼容廉价的外设接口芯片、降低整机电路板的布线与制造成本，Intel 专门设计了内部运算为 16 位、但对外引脚数据总线只保留 8 位的 8088 处理器。这也是为什么 8088 被称为“准 16 位微处理器”。

> **记忆口诀**：两款 CPU 内部都是 16 位，地址都是 20 位（能寻址 1 MB）；唯独外部数据线不同——**86 外部十六，88 外部为八**。

### 本讲提到的题目

#### 汇编语言属性判断题

> **题干**：判断正误：汇编语言是高级语言。（　）

- **考点分析**：考查计算机程序设计语言的基本层次界定。
- **解析**：汇编语言由助记符与符号地址构成，本质上与机器指令直接关联，没有脱离具体计算机的硬件架构，属于低级程序设计语言；C、Java 等脱离具体硬件体系的才是高级语言。
- **答案**：错误（$\times$）。

#### 系统总线类型与职能简答题

> **题干**：简述 8086 计算机系统的总线分类，以及它们在一次存储器读写操作中分别承担什么作用？

- **考点分析**：考查微机系统总线的三大类型及协同寻址控制逻辑。
- **解析**：
  8086 计算机系统的总线分为三类：
  1. **地址总线（Address Bus）**：负责传输存储单元或 I/O 端口的地址编码，用于精确选定需要操作的目标物理单元。
  2. **控制总线（Control Bus）**：负责传输 CPU 发出的读、写等控制命令或外设状态信号，决定当前对目标单元执行何种具体操作（如读指令或写数据）。
  3. **数据总线（Data Bus）**：负责在 CPU 与被选中的存储单元或 I/O 设备之间高速双向传输实际的数据内容。
- **答案**：分为地址总线、控制总线和数据总线三类。地址总线用于定位存储单元，控制总线用于传递读写控制指令，数据总线用于在 CPU 与存储单元之间回传或写入数据。

#### 处理器总线宽度填空题

> **题干**：Intel 8088 的外部数据总线宽度为______位，而 Intel 8086 的外部数据总线宽度为______位。

- **考点分析**：考查 8086 与 8088 经典微处理器的引脚及总线硬件规格差异。
- **解析**：8086 与 8088 内部均采用 16 位架构处理数据，但为了降低系统构建成本，8088 对外的物理数据总线宽度被缩减为 8 位，因而在外部被称为准 16 位微处理器；8086 的外部数据总线则为完整的 16 位。
- **答案**：8；16。
