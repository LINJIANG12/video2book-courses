## 【拯救者】Ep_第七章-循环指令和子程序
> 对应分集：P18 | 原始标题：《【拯救者】Ep_第七章-循环指令和子程序》

在汇编语言程序设计中，如果说分支结构赋予了程序逻辑判断的能力，那么循环指令与子程序机制则彻底打开了大规模数据处理和模块化工程设计的大门。我们平时写的字符串搜索、数组累加、数据排序，无一例外依赖循环结构；而一个逻辑清晰的复杂工程，必须将功能模块封装为子程序（相当于高级语言中的函数）。这一讲我们就深入微处理器内部，彻底剖析 8086 硬件级循环指令的微操作时序，以及 `CALL` 和 `RET` 指令在堆栈中所引发的精密指针推移。

---

### 循环指令体系与硬件微操作流

高级语言中的 `for` 循环和 `while` 循环，在汇编底层通常由专用的循环指令来实现。8086 架构为我们提供了硬件级别的循环指令——`LOOP` 系列指令。这一系列指令最大的特点就是**与通用寄存器 `CX` 紧密硬件绑定**。在 8086 体系中，`CX` 的全称正是“计数寄存器（Count Register）”。

#### 标准计数循环指令运作机理

`LOOP label` 指令是汇编中最高频出现的循环结构。当 CPU 遇到一条 `LOOP` 指令时，它在硬件内部按部就班地执行两个微操作步骤：

1. **计数器自动自减**：硬件自动执行 $(CX) \leftarrow (CX) - 1$；
2. **零值条件判别与跳转**：
   - 若减 1 后的 $(CX) 
eq 0$，则将当前 `IP` 加上相对位移量，跳转到标号 `label` 处继续执行循环体；
   - 若减 1 后的 $(CX) = 0$，则不发生跳转，CPU 顺序向下执行紧随 `LOOP` 的下一条指令。

```text
       进入循环体
           |
           v
    [ 执行循环体指令序列 ]
           |
           v
       LOOP label
           |
      (CX) <-- (CX) - 1  (硬件自动减 1，不影响任何标志位！)
           |
       判别: (CX) == 0 ?
          /          \
      No /            \ Yes
        /              \
  [ 跳回 label ]    [ 退出循环，顺序执行 ]
```
上图展示了 LOOP 指令硬件自动执行计数递减与闭环转移的逻辑状态机。

> **核心特性与避坑准则**：
> 1. **标志位完全免疫**：`LOOP` 指令执行 $(CX) \leftarrow (CX) - 1$ 时，**绝不改变任何标志位**（包括 `ZF`、`CF` 等）！这与我们手动写 `DEC CX` 完全不同（`DEC` 会影响 `ZF`、`SF` 等）。
> 2. **短转移物理限制**：`LOOP` 指令属于段内相对寻址的短转移指令（`SHORT`），其机器码占 2 个字节，跳转位移量为 8 位补码，范围为 $-128 \sim +127$ 字节。
> 3. **初值零陷阱**：若进入循环前 $CX = 0$，首次执行 `LOOP` 时，$CX$ 会先减 1 变成 `0FFFFH`（即 65535）！由于此时 $FFFFH 
eq 0$，程序将继续执行循环体，导致该循环体被连续执行整整 **65536 次**！为了防止这种致命 bug，在未知的动态计数场景下，进入循环前必须先加上 `JCXZ` 指令进行前置拦截。

```x86asm
; 标准安全计数循环模板: 计算 1 + 2 + ... + 100
    MOV CX, 100         ; 设置循环次数
    JCXZ LOOP_EXIT       ; 安全防线: 若 CX 初始为 0 则直接跳过循环
    MOV AX, 0           ; AX 用于存放累加和
    MOV BX, 1           ; BX 为当前加数

SUM_LOOP:
    ADD AX, BX          ; 循环体: 累加
    INC BX              ; 修改指针或加数
    LOOP SUM_LOOP       ; (CX)<-(CX)-1, 若 (CX)!=0 则跳回 SUM_LOOP

LOOP_EXIT:
    ; 循环结束，此时 AX = 5050
```

#### 条件循环指令与字符串特征检索

除了单纯依据计数值判定的 `LOOP` 指令，8086 还配备了两条可以感知标志寄存器 `ZF` 状态的条件循环指令：`LOOPZ`（或等价助记符 `LOOPE`）和 `LOOPNZ`（或等价助记符 `LOOPNE`）。

这两条指令常用于在一串连续的数据块（如字符串、数组）中搜索特定模式：

| 指令助记符 | 等价助记符 | 语义全称 | 硬件执行动作与循环继续条件 | 典型应用场景 |
| :--- | :--- | :--- | :--- | :--- |
| `LOOPZ` | `LOOPE` | Loop if Zero / Equal | 1. $(CX) \leftarrow (CX) - 1$<br>2. 若 $(CX) 
eq 0 \land ZF = 1$，则跳转到标号 | 寻找第一个**非零**元素，或查找第一个**不匹配**字符 |
| `LOOPNZ`| `LOOPNE`| Loop if Not Zero / Not Equal | 1. $(CX) \leftarrow (CX) - 1$<br>2. 若 $(CX) 
eq 0 \land ZF = 0$，则跳转到标号 | 寻找第一个**匹配目标**（如查找空格、特定字母） |

> **深入理解**：
> 以 `LOOPNZ` 查找字符 `'A'` 为例：我们在循环体里用 `CMP AL, [SI]` 比较字符。若不相等，运算差值不为零，$ZF = 0$；遇到 `LOOPNZ` 时，因为 $ZF = 0$ 满足条件，程序继续循环找下一个；一旦某次比较发现读到了 `'A'`，`CMP` 指令把 $ZF$ 置为 1，此时 `LOOPNZ` 检测到 $ZF 
eq 0$，循环条件不成立，程序立刻从循环中“早退（Break）”跳出！

### 子程序调用与返回底层机制

在复杂程序设计中，如果同一段代码在多个地方被反复使用，频繁复制粘贴会造成代码段急剧膨胀，也不利于后期维护。子程序（Subroutine，即过程 Procedure）的出现正是为了解决代码复用。

子程序的调用核心在于：**CPU 必须在跳往新地址之前，将原本下一条指令的地址（断点）妥善保存在堆栈中；待子程序处理完毕后，再从堆栈中取出该地址放回指令指针寄存器，精准返回原程序继续向下执行**。

#### 过程定义与作用域声明

在汇编语言中，一个完整的子程序使用伪指令 `PROC` 和 `ENDP` 成对包裹，其格式为：

```x86asm
子程序名 PROC [NEAR / FAR]
    ; 子程序功能代码
    RET
子程序名 ENDP
```

- **`NEAR` 属性（段内过程）**：当子程序与调用它的主程序位于同一个代码段内时使用（缺省默认为 NEAR）。调用和返回时，段基址 `CS` 保持不变，堆栈中仅需压入和弹出 16 位偏移地址 `IP`。
- **`FAR` 属性（段间过程）**：当子程序位于不同的代码段时使用。调用和返回时，堆栈中必须压入和弹出 32 位完整指针（16 位段基址 `CS` 和 16 位偏移地址 `IP`）。

#### CALL 指令的堆栈动作深度追踪

`CALL` 指令在底层的动作绝不仅仅是跳转，它伴随着精密的堆栈指针推移动作：

##### 段内直接/间接调用（NEAR CALL）
1. 堆栈指针自减 2：$(SP) \leftarrow (SP) - 2$；
2. 保护断点偏移地址：$[SS:SP] \leftarrow IP$（这里的 `IP` 已经是 `CALL` 指令下一条指令的偏移地址）；
3. 装载新目标地址：$(IP) \leftarrow \text{子程序的偏移地址}$。

##### 段间直接/间接调用（FAR CALL）
1. 保护主程序段基址：$(SP) \leftarrow (SP) - 2, [SS:SP] \leftarrow CS$；
2. 保护主程序偏移地址：$(SP) \leftarrow (SP) - 2, [SS:SP] \leftarrow IP$；
3. 装载新代码段基址与新偏移：$(CS) \leftarrow \text{子程序段地址}, (IP) \leftarrow \text{子程序偏移地址}$。

```text
       段内 CALL (NEAR)                   段间 CALL (FAR)
    高地址   |               |         高地址   |               |
             +---------------+                  +---------------+
             | 原主程序内容  |                  | 原主程序内容  |
             +---------------+                  +---------------+
             |  主程序 IP    | <-- SP           |  主程序 CS    |
    低地址   +---------------+                  +---------------+
             |               |                  |  主程序 IP    | <-- SP
                                       低地址   +---------------+
```
上图直观展示了段内调用与段间调用执行完毕后堆栈栈顶的数据布局。

#### RET 指令的堆栈弹出与参数平衡

子程序末尾必须有一条 `RET`（Return）指令。`RET` 会根据当前所在子程序的属性，逆向解构堆栈：

- **段内返回（NEAR RET）**：
  从栈顶弹出一个字送入 `IP`：$(IP) \leftarrow [SS:SP]$，然后堆栈指针自增 2：$(SP) \leftarrow (SP) + 2$。
- **段间返回（FAR RET）**：
  先弹出一个字送入 `IP`：$(IP) \leftarrow [SS:SP], (SP) \leftarrow (SP) + 2$；
  再弹出一个字送入 `CS`：$(CS) \leftarrow [SS:SP], (SP) \leftarrow (SP) + 2$。

##### 带立即数返回（RET n）
在高级语言中，主程序在调用函数时经常会通过堆栈压入多个参数（例如压入两个字型参数占用 4 个字节）。如果子程序执行完后，主程序忘记清理这些参数，堆栈指针就会失衡。
汇编语言提供了一条优雅的指令：`RET n`（$n$ 通常为偶数立即数）。
- 硬件执行动作：
  1. 按照常规 `RET` 动作弹出断点地址到 `IP`（以及 `CS`）；
  2. 随后硬件直接自动执行：$(SP) \leftarrow (SP) + n$！
- 这样就用一条指令在返回的同时，将压入堆栈的 $n$ 个字节参数彻底清空，实现了完美的“堆栈平衡”。

### 子程序现场保护与参数传递规范

#### 现场保护的进出栈对仗原则

子程序在执行过程中几乎不可避免要使用通用寄存器（如 `AX`、`BX`、`CX`）。如果主程序在调用子程序前正用 `BX` 存着关键指针，而子程序在内部随意改写 `BX` 却未加保护，返回后主程序的运行状态将彻底崩溃。这种现象称为“寄存器冲突（Register Contention）”。

解决这一问题的行业金标准是：**子程序现场保护与恢复**。

> **对仗金科玉律**：
> 1. 子程序开头（入口处）使用 `PUSH` 保护被改动的寄存器；
> 2. 子程序末尾（`RET` 之前）使用 `POP` 恢复寄存器；
> 3. **进栈与出栈的顺序必须严格相反（先进后出 FILO）**！
> 4. `POP` 动作必须写在 `RET` 指令**之前**，绝对不能写在 `RET` 之后！

```x86asm
; 规范子程序编写范式
MY_SUBROUTINE PROC NEAR
    ; 1. 保护现场 (PUSH 顺序: AX, BX, CX)
    PUSH AX
    PUSH BX
    PUSH CX

    ; 2. 子程序核心运算处理代码
    MOV AX, [BX]
    ADD AX, CX
    ; ...

    ; 3. 恢复现场 (POP 顺序必须完全倒过来: CX, BX, AX)
    POP CX
    POP BX
    POP AX

    ; 4. 返回主程序
    RET
MY_SUBROUTINE ENDP
```

#### 三大参数传递范式

主程序与子程序之间如何交流数据？在实际工程中存在三种主要传递模式：

1. **寄存器传参**：
   - 做法：主程序把参数放进 `AX`、`DX` 等寄存器，子程序直接从这些寄存器取数计算，结果也放在约定寄存器中。
   - 优缺点：速度极快、逻辑简单；但由于通用寄存器数量稀少，无法传递大规模复合数据。
2. **约定内存单元传参**：
   - 做法：在数据段预先开辟全局缓冲区，主程序将输入存入缓冲区，子程序访问该缓冲区。
   - 优缺点：可以传递大量数据；但破坏了子程序的独立性，无法实现重入与递归。
3. **堆栈传参与 BP 栈帧基址指针寻址机制**：
   - 这是现代 C/C++ 编译器构建底层函数调用的通用工业模型。
   - 主程序把实参逐个 `PUSH` 进堆栈，然后调用子程序；
   - 子程序利用基址指针 `BP`（Base Pointer）配合偏移量，在不破坏堆栈指针 `SP` 的前提下随意读取栈内参数（如 `[BP+4]`、`[BP+6]`）。这种机制我们将在下一讲的典型期末大题中进行详尽图解与代码实战！

### 循环控制典型考题与易错陷阱

#### 循环计数初值零的循环次数陷阱题

**【典型考题】**
分析下列汇编程序片段，请问标号 `BODY` 处的循环体指令一共被执行了多少次？
```x86asm
    MOV CX, 0
    MOV AX, 0
BODY:
    INC AX
    LOOP BODY
```

**【推导与考点解析】**
很多同学看到 $CX = 0$，脱口而出“执行 0 次”或者“一次都不执行”。这是把高级语言（如 C 语言中的 `for (int i=0; i<cx; i++)`）的预检测语义生搬硬套到汇编语言中产生的重大失误！

我们回顾 `LOOP` 指令的微操作硬件时序：
1. 遇到标号 `BODY`，先执行 `INC AX`；
2. 遇到 `LOOP BODY` 指令时，CPU 硬件执行两步：
   - 第一步：先把计数器自减 1，即 $(CX) \leftarrow (CX) - 1$；
   - 第二步：判断自减后的 $CX$ 是否等于 0。若非零则跳回，若为零则退出。

进入循环前 $CX = 0$：
- 首次进入循环体，执行 `INC AX`，此时 $AX = 1$；
- 执行 `LOOP BODY`：硬件将 $CX$ 减 1。注意！$CX$ 是 16 位无符号寄存器，$0 - 1 = 0FFFFH$（即无符号数 65535）；
- 硬件检测 $CX$ 的值：此时 $CX = 0FFFFH 
eq 0$！条件成立，强行跳回 `BODY` 继续执行；
- 随后，$CX$ 将从 65535 逐次递减：$65534, 65533, \dots, 2, 1, 0$。
- 直到 $CX$ 从 1 减到 0 时，`LOOP` 指令才判定条件不满足，退出循环。

```text
初始 CX = 0
  |
  +---> 执行第 1 次循环体
  |        |
  |      LOOP 执行: CX 减 1 变为 0FFFFH (65535 != 0) ===> 跳回！
  |        |
  +---> 执行第 2 次循环体 (CX 减为 65534)
  |        ...
  +---> 执行第 65536 次循环体 (CX 减为 0) ===> 终于退出循环！
```
上图直观展示了初值零时由于无符号下溢环绕引发 65536 次超级大循环的过程。

**【标准答案】**
循环体 `BODY` 一共被执行了 **65536 次**。
若要在设计上规避此陷阱，必须在进入循环前加入 `JCXZ` 指令，当 $CX=0$ 时直接跳过循环体。

#### LOOP 与手动减计数指令等价辨析题

**【典型考题】**
有两组实现循环计数的代码如下：
- **方案 A**：
  ```x86asm
  AGAIN_A:
      ; ... 循环体
      LOOP AGAIN_A
  ```
- **方案 B**：
  ```x86asm
  AGAIN_B:
      ; ... 循环体
      DEC CX
      JNZ AGAIN_B
  ```
请比较方案 A 与方案 B 的异同点，特别说明它们在**指令长度、执行周期以及对标志寄存器 FLAGS 的影响**上有何区别。

**【对比推导与考点解析】**

| 比较维度 | 方案 A (`LOOP`) | 方案 B (`DEC CX` + `JNZ`) |
| :--- | :--- | :--- |
| **指令条数与字节长度** | 1 条指令，占 2 个字节（机器码 `E2 ib`） | 2 条指令，占 3 个字节（`DEC CX` 占 1 字节，`JNZ` 占 2 字节） |
| **执行时钟周期 (8086)**| 转移发生时耗费 17 个时钟周期，不转移时耗费 5 周期 | `DEC CX`（2 周期）+ `JNZ`（转移 16 周期/不转移 4 周期），共需 18 周期/6 周期 |
| **标志寄存器 FLAGS** | **绝对不改变任何标志位！** | **`DEC CX` 会修改 `ZF`, `SF`, `OF`, `PF`, `AF` 标志位**（但不影响 `CF`） |

> **必背考点总结**：
> 考试中最具杀伤力的区别在于**标志位**！如果在循环体内部经过了某些运算产生了一组关键标志位，需要在循环末尾根据标志位做出其他判断，使用 `LOOP` 不会破坏前面的标志位；而使用 `DEC CX` 会直接用自减后的结果刷新 `ZF` 等标志位，将前面的计算痕迹彻底冲毁！

### 字符串检索与条件循环综合分析题

#### 字符扫描边界与退出双出口判定题

**【典型考题】**
阅读下列程序片段：
```x86asm
    MOV CX, 5
    LEA SI, BUFFER
SEARCH:
    CMP BYTE PTR [SI], '$'
    LOOPNE SEARCH
```
假设数据段中预先定义了以下两种不同情况的 `BUFFER`：
- 情况一：`BUFFER DB 'A', 'B', '$', 'C', 'D'`
- 情况二：`BUFFER DB 'A', 'B', 'C', 'D', 'E'`
请分别指出在情况一和情况二执行完毕后，$CX$ 寄存器的最终值是多少，以及程序是因何种条件退出循环的？

**【逻辑追踪推导】**
`LOOPNE`（或 `LOOPNZ`）指令的循环继续条件是：
1. 先自减计数器：$(CX) \leftarrow (CX) - 1$；
2. 判定：**$(CX) 
eq 0 \land ZF = 0$** 时才跳回继续循环！
只要其中任意一个条件不满足（即 $CX=0$ 或者 $ZF=1$），循环立刻终止！

**情况一分析（串中包含 `'$'`）：**
- 第一次循环：$SI$ 指向 `'A'`，`'A' - '$' != 0`，故 $ZF = 0$。执行 `LOOPNE`：$CX$ 减 1 变为 4，因 $CX 
eq 0$ 且 $ZF=0$，跳回；
- 第二次循环：$SI$ 指向 `'B'`，`'B' - '$' != 0`，故 $ZF = 0$。执行 `LOOPNE`：$CX$ 减 1 变为 3，因 $CX 
eq 0$ 且 $ZF=0$，跳回；
- 第三次循环：$SI$ 指向 `'$'`，`'$' - '$' == 0`，触发 **$ZF = 1$**！
  此时执行 `LOOPNE`：$CX$ 减 1 变为 **2**。随后检查退出条件：虽然此时 $CX = 2 
eq 0$，但由于 $ZF = 1$（找到了目标字符），不等条件破灭，**循环提前退出（Break）**！

**情况二分析（串中没有 `'$'`）：**
- 程序依次比较全部 5 个字符，每次比较结果均为不等（$ZF = 0$）；
- $CX$ 依次递减：$5 \rightarrow 4 \rightarrow 3 \rightarrow 2 \rightarrow 1 \rightarrow 0$；
- 当比较完第 5 个字符 `'E'` 后，执行 `LOOPNE`，$CX$ 从 1 减为 **0**。虽然 $ZF = 0$，但因计数器耗尽（$CX = 0$），循环正常终止。

**【标准答案】**
- 情况一：$CX = 2$。退出原因：**因匹配到目标字符导致 $ZF = 1$ 而提前跳出**。
- 情况二：$CX = 0$。退出原因：**因达到规定检索上限次数使得计数器 $CX = 0$ 而正常耗尽退出**。

### 子程序调用堆栈失衡与现场恢复改错大题

#### 栈指针失衡与返回地址破坏改错题

**【典型考题】**
以下子程序旨在实现保护现场并完成某项累加，但在编写时出现了严重错误。请指出错误所在，并详细分析若该程序直接运行，会导致何种灾难性后果。
```x86asm
MY_SUB PROC NEAR
    PUSH AX
    PUSH BX
    
    MOV AX, [SI]
    ADD BX, AX
    
    POP AX          ; 错误之处
    RET
    POP BX          ; 错误之处
MY_SUB ENDP
```

**【考点分析与堆栈时序追踪】**
这段代码犯了两个致命错误：
1. **出栈顺序与进栈顺序未逆序对仗**：进栈顺序为 `AX` 然后 `BX`，出栈应当先弹出 `BX` 再弹出 `AX`；
2. **把恢复指令写在 `RET` 之后**：`RET` 是子程序的终点，执行 `RET` 后 CPU 控制流直接转移走，写在 `RET` 之后的 `POP BX` 根本永远没有机会被执行！

**堆栈崩溃推导过程：**
我们假设进入子程序前，调用者执行了 `CALL MY_SUB`，主程序的断点偏移地址为 `0120H`：
1. `CALL MY_SUB` 执行：硬件将断点 `0120H` 压入堆栈，栈顶保存 `0120H`；
2. `PUSH AX` 执行：将 `AX` 压栈，此时栈顶是 `AX`；
3. `PUSH BX` 执行：将 `BX` 压栈，此时栈顶是 `BX`；
4. 执行运算后，程序执行了 `POP AX`：
   - 此时栈顶弹出的数据实际上是刚才压入的 **`BX` 的值**！`AX` 被赋予了 `BX` 的垃圾数据；
   - 此时堆栈指针 $SP$ 下移，当前的栈顶暴露出来的不是断点，而是刚才压入的 **原始 `AX` 的值**！
5. 此时直接执行 `RET`：
   - CPU 执行 `RET` 时，毫不犹豫地从当前栈顶弹出一个字装入 `IP` 寄存器！
   - 结果：**CPU 把原本保存在栈内的 `AX` 的数值强行当作了下一条指令的执行地址（IP）**！
   - 系统控制流瞬间飞往不可预知的内存荒原，发生死机、抛出硬件异常或陷入死循环！

```text
当前堆栈状态演变:
[CALL压入断点]    [PUSH AX]        [PUSH BX]        [执行POP AX]
高地址             高地址           高地址           高地址
+-----------+    +-----------+    +-----------+    +-----------+
| 断点0120H |    | 断点0120H |    | 断点0120H |    | 断点0120H |
+-----------+    +-----------+    +-----------+    +-----------+
                 | 原 AX 值  |    | 原 AX 值  |    | 原 AX 值  | <-- 此时执行RET!
                 +-----------+    +-----------+    +-----------+     CPU误把原AX当断点!
                                  | 原 BX 值  | <-- SP
                                  +-----------+
```
上图清晰揭示了未对称出栈导致 RET 错把通用寄存器内容当成指令指针 IP 弹出的灾难性后果。

**【正确修改方案】**
```x86asm
MY_SUB PROC NEAR
    PUSH AX
    PUSH BX
    
    MOV AX, [SI]
    ADD BX, AX
    
    POP BX          ; 严格后进先出：先弹最后压入的 BX
    POP AX          ; 再弹先前压入的 AX
    RET             ; 此时栈顶精准对准断点地址，安全返回！
MY_SUB ENDP
```

### 堆栈参数传递与栈帧寻址综合设计题

#### 基于 BP 寻址与带立即数返回综合大题

**【典型综合大题】**
编写一个主程序与子程序协同的汇编模块：
- **功能要求**：主程序将两个 16 位整数（操作数 1 和操作数 2）通过**堆栈**传递给子程序 `ADD_PROC`，子程序计算二者之和并将结果存放在 `AX` 中，最后子程序负责在返回时清理堆栈中的两个参数。
- **设计要求**：
  1. 给出主程序的压参及调用代码；
  2. 给出子程序完整的代码结构，必须使用 `BP` 基址指针寻址获取参数；
  3. 画出子程序建立栈帧后的堆栈内存分布图，推导参数偏移量 `[BP+4]` 与 `[BP+6]` 的来源；
  4. 写出正确的返回指令格式。

**【完整设计与代码推导】**

**主程序调用部分代码：**
```x86asm
    ; 假设需要相加的两个数为 0010H 和 0020H
    PUSH 0010H          ; 压入第 1 个参数 (先入栈)
    PUSH 0020H          ; 压入第 2 个参数 (后入栈)
    CALL ADD_PROC       ; 调用子程序 (压入返回断点 IP)
    ; 调用返回后，堆栈已经被子程序自动平衡，无需再执行 ADD SP, 4
```

**子程序实现部分代码：**
```x86asm
ADD_PROC PROC NEAR
    PUSH BP             ; 保护基址指针原值
    MOV BP, SP          ; 建立栈帧基准：让 BP 指向当前栈顶

    ; 通过 BP 基准寻址访问参数
    MOV AX, [BP + 6]    ; 取出第 1 个参数 (0010H)
    ADD AX, [BP + 4]    ; 加上第 2 个参数 (0020H)

    POP BP              ; 恢复调用者的 BP
    RET 4               ; 弹出断点返回，并使 SP 自动自增 4 字节，彻底清理两个参数！
ADD_PROC ENDP
```

**堆栈内存布局与偏移量推导：**
当子程序执行完 `MOV BP, SP` 之后，整个堆栈自顶向下（从低地址到高地址）的结构如下表所示：

```text
堆栈地址增长方向: 向上为高地址，向下为低地址

内存物理地址相对位置        堆栈存放内容                寻址方式
高地址 -----------------+-------------------------+
       | [SS:BP + 6]    | 第 1 个参数 (0010H)     | <-- 距 BP 偏 6 个字节
       +----------------+-------------------------+
       | [SS:BP + 4]    | 第 2 个参数 (0020H)     | <-- 距 BP 偏 4 个字节
       +----------------+-------------------------+
       | [SS:BP + 2]    | 主程序返回断点 (IP)     | <-- CALL 自动压入
       +----------------+-------------------------+
低地址 | [SS:BP + 0]    | 保护的旧 BP 值          | <-- PUSH BP, 当前 SP/BP 指向
       +----------------+-------------------------+
```
上图展示了标准 C 语言风格汇编栈帧中参数、返回地址与旧 BP 的固定相对偏移拓扑。

> **偏移量精细数学核算**：
> 1. `[BP]` 指向的是当前刚压栈的“旧 BP 值”（占据 2 字节，偏移 `0~1`）；
> 2. 跳过旧 BP 的 2 个字节后，`[BP + 2]` 指向的是 `CALL` 压入的“主程序断点 IP”（占据 2 字节，偏移 `2~3`）；
> 3. 跳过断点后，`[BP + 4]` 精准命中“第 2 个压入的参数”（占据 2 字节，偏移 `4~5`）；
> 4. 再向上推进 2 字节，`[BP + 6]` 精准命中“第 1 个压入的参数”（占据 2 字节，偏移 `6~7`）。

**返回指令选择解析：**
主程序总共压入了 2 个字型参数，总计占用 $2 \times 2 = 4$ 个字节。
因此子程序返回时必须使用 `RET 4` 指令！
- 若只写普通 `RET`，返回后这两个参数依然残留在栈中，栈指针发生偏移（内存泄漏）；
- 若使用 `RET 4`，CPU 在弹出断点送入 `IP` 之后，硬件顺手执行 $(SP) \leftarrow (SP) + 4$，瞬间恢复了调用前的干净堆栈，这是最高效、最标准的工程级解法！
