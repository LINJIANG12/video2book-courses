## 【拯救者】Ep_第五章-x86寻址方式
> 对应分集：P13 | 原始标题：《【拯救者】Ep_第五章-x86寻址方式》

如果说 CPU 是一台强大的计算工厂，那么寄存器就是工人的随身工具箱，而内存则是庞大的中央仓库。要让 CPU 执行一条指令，首要解决的问题就是：**要加工的数据究竟藏在哪里？**

寻址方式（Addressing Mode），本质上就是**CPU 指令寻找操作数或操作数地址的方式**。在 8086 汇编中，寻址方式是串联硬件结构、指令系统与高级语言底层实现的咽喉要道。考试考选择题辨析、考大题算物理地址、考阅读程序查错，全部围绕寻址方式展开。

这一讲我们把 8086 体系下的八大寻址方式进行地毯式拆解，讲清每一类寻址的硬件逻辑、格式变体与必须严守的“四大铁律”。

---

### 操作数的四种来源分类

在深入寻址方式前，我们先看一条双操作数指令的基本语法格式：

```assembly
OPR DEST, SRC    ; 操作码 目的操作数, 源操作数
```

在 8086 CPU 执行时，指令中的操作数可能来自以下四个位置：

1. **指令代码本身**：操作数作为机器指令的一部分，存放于代码段中（立即数）。
2. **CPU 内部寄存器**：操作数直接在通用寄存器或段寄存器中，取数速度最快。
3. **内存单元**：操作数存放在数据段、附加段、堆栈段或代码段的内存存储单元中。
4. **I/O 端口**：操作数来自外部硬件外设（通过 `IN`、`OUT` 指令访问）。

针对上述来源，寻址方式主要划分为**非内存寻址**与**内存存储器寻址**两大阵营。

---

### 快速无需访存的两种基本寻址

#### 立即寻址

操作数直接包含在机器指令中，作为指令的一部分紧跟在操作码后面。这种操作数称为**立即数（Immediate）**。

```assembly
MOV AX, 1234H     ; 16 位立即寻址
MOV AL, 50H       ; 8 位立即寻址
```

- **用途**：专用于给寄存器或内存单元赋常量初值。
- **限制条件**：立即数只能作为**源操作数**，绝不能作为目的操作数（如 `MOV 100H, AX` 是非法的）。

> **易错点**：8086 硬件规定，**立即数绝不能直接送入段寄存器**！以下语句全部非法：
> ```assembly
> MOV DS, 1000H     ; 错误！
> MOV SS, 2000H     ; 错误！
> ```

#### 寄存器寻址

操作数存放在 CPU 内部的寄存器中，指令直接通过寄存器名称指定数据源或目标。

```assembly
MOV AX, BX        ; 源和目的均采用寄存器寻址
ADD CX, DX
```

- **性能特征**：指令执行时完全在 CPU 内部完成，不需要走外部总线去访问内存，执行速度最快。
- **字长约束**：源寄存器与目的寄存器的位宽必须严格一致（要么同为 8 位，要么同为 16 位）。

---

### 内存存储器寻址的四大铁律

当操作数位于内存中时，CPU 必须首先计算出该数据在段内的**有效地址（Effective Address，EA）**，再结合对应的段寄存器，通过地址加法器合成出 20 位物理地址：

$$\text{物理地址} = (\text{段基址} \times 16) + EA$$

在 16 位 8086 架构中，内存寻址必须严格遵守以下四大硬性规定：

```text
16 位寻址寄存器白名单:
基址寄存器: [ BX ] (默认段 DS), [ BP ] (默认段 SS)
变址寄存器: [ SI ] (默认段 DS), [ DI ] (默认段 DS)
─────────────────────────────────────────────
严禁使用: AX, CX, DX, SP, IP, CS, DS, SS, ES 进行 [...] 寻址！
```

> **铁律一：寄存器可用白名单**
> 只有 `BX`、`BP`、`SI`、`DI` 这 4 个寄存器能够用在中括号 `[...]` 内作为地址指针！写出 `MOV AX, [CX]` 或 `MOV AX, [DX]` 在汇编阶段会直接报错。
>
> **铁律二：段寄存器默认配对原则**
> - 凡是指针中包含 `BP` 的，默认段寄存器是 **`SS`（堆栈段）**；
> - 其余凡是只包含 `BX`、`SI`、`DI` 或纯位移量的，默认段寄存器是 **`DS`（数据段）**。
>
> **铁律三：双寄存器组合法则**
> 若在一个括号内使用两个寄存器求和寻址，**必须是一个基址寄存器（`BX` 或 `BP`）搭配一个变址寄存器（`SI` 或 `DI`）**。
> - 合法组合仅有 4 种：`[BX+SI]`、`[BX+DI]`、`[BP+SI]`、`[BP+DI]`。
> - 两个基址合用非法：`[BX+BP]` 错误！
> - 两个变址合用非法：`[SI+DI]` 错误！
>
> **铁律四：双内存传送禁止原则**
> 8086 指令系统严禁源操作数和目的操作数同时为内存单元！如 `MOV [BX], [SI]` 非法。

### 存储器寻址的五大进阶形态

#### 直接寻址

指令直接给出操作数的 16 位有效地址偏移量（可以用括号括起常数，或直接使用变量名）。

```assembly
MOV AX, [2000H]    ; EA = 2000H，物理地址 = DS * 16 + 2000H
MOV BX, TOTAL      ; TOTAL 为数据段变量，EA 即 TOTAL 的偏移地址
```

- **段超越前缀**：如果想访问其他段中的数据，必须显式添加段超越前缀，如 `MOV AX, ES:[2000H]`，此时物理地址由 `ES` 合成。

#### 寄存器间接寻址

操作数的有效地址保存在寄存器中，括号内只写一个寄存器名。

```assembly
MOV AX, [BX]       ; 默认段为 DS，EA = (BX)
MOV CX, [BP]       ; 默认段为 SS，EA = (BP)
MOV DL, [SI]       ; 默认段为 DS，EA = (SI)
```

```text
寄存器间接寻址数据流拓扑:
[ 指令: MOV AX, [BX] ]
           │
           ▼ 读取
       [ 寄存器 BX: 0100H ] ─────────┐
                                      ├──> [ 20位加法器 ] ──> 物理地址 20100H ──> 取出字送入 AX
       [ 段寄存器 DS: 2000H ] ──×16 ──┘
```

#### 寄存器相对寻址

有效地址由某个寻址寄存器的内容加上一个 8 位或 16 位的位移量（Displacement）构成。

```assembly
MOV AX, [BX+10H]   ; EA = (BX) + 10H
MOV AX, 10H[BX]    ; 完全等价的数组式写法
MOV AX, [BP-4]     ; 访问堆栈中的局部变量，默认段为 SS
```

- **高级语言映射**：此方式是一维数组在底层的直接投影。常数位移量是数组首地址，寄存器（如 `SI` 或 `BX`）充当数组下标。

#### 基址变址寻址

有效地址由**一个基址寄存器**的内容与**一个变址寄存器**的内容相加得到。

```assembly
MOV AX, [BX+SI]    ; 默认段 DS，EA = (BX) + (SI)
MOV AX, [BP+DI]    ; 默认段 SS，EA = (BP) + (DI)
```

- **应用场景**：常用于一维大型数组的动态访问，基址寄存器指示数据区首地址，变址寄存器在循环体中动态步进。

#### 相对基址变址寻址

有效地址由**一个基址寄存器**、**一个变址寄存器**加上**一个位移量**三者求和得到。

$$EA = (BX/BP) + (SI/DI) + \text{位移量}$$

```assembly
MOV AX, [BX+SI+100H]
MOV AX, 100H[BX][SI]     ; 等价写法
```

```text
相对基址变址寻址物理合成拓扑:
段基址 (DS × 16) ────────┐
基址寄存器 (BX) ─────────┼──> [ 20位 内部加法器 ] ──> 最终内存单元地址
变址寄存器 (SI) ─────────┼
常数偏移 (100H) ─────────┘
```

- **高级语言映射**：二维数组或表格数据处理的神器。位移量指向二维表格的首地址，基址寄存器指向某一行，变址寄存器定位某一列。

### 八大寻址方式综合对比表

| 寻址方式名称 | 指令示例 | 有效地址 $EA$ 计算 | 默认段寄存器 | 典型用途 |
| :--- | :--- | :--- | :--- | :--- |
| **立即寻址** | `MOV AX, 1000H` | 无（操作数在指令内） | 代码段（CS） | 赋常量初值 |
| **寄存器寻址** | `MOV AX, BX` | 无（操作数在寄存器） | 无 | 变量暂存与高速计算 |
| **直接寻址** | `MOV AX, [1000H]` | $EA = 1000H$ | `DS` | 访问简单全局变量 |
| **寄存器间接寻址** | `MOV AX, [BX]` | $EA = (BX)$ | `DS`（BP 时为 `SS`） | 类似 C 语言的一级指针解引用 |
| **寄存器相对寻址** | `MOV AX, [BX+10H]` | $EA = (BX) + 10H$ | `DS`（BP 时为 `SS`） | 一维数组检索 `arr[i]` |
| **基址变址寻址** | `MOV AX, [BX+SI]` | $EA = (BX) + (SI)$ | `DS`（BP 时为 `SS`） | 数组与动态偏移合并检索 |
| **相对基址变址** | `MOV AX, [BX+SI+4]`| $EA = (BX)+(SI)+4$| `DS`（BP 时为 `SS`） | 二维数组 `matrix[i][j]` |
| **隐含寻址** | `MUL BL` | 无（由指令隐含指定） | 无 | 定向运算（如乘除法隐含 AX） |

> **提示**：做任何物理地址计算题时，先扫一眼括号里有没有 `BP`。只要看到 `BP` 且前面没有显式的段超越（如 `ES:`），段地址**必须且只能抓 `SS`**，这是专升本和期末考试最屡试不爽的丢分考点！

### 指令语法合法性判断与改错大全

指令合法性分析是选择题与改错题的核心命题形式。判断一条指令能否通过编译，遵循以下“五步排查法”：

```text
指令合法性五步排查流程:
1. 查两端宽度 ──> 是否一边 8 位一边 16 位？(如 MOV AL, BX 错)
2. 查双内存   ──> 是否源和目的都是内存？(如 MOV [BX], [SI] 错)
3. 查段寄存器 ──> 是否给 CS 赋值？是否段寄存器之间直接 MOV？是否直赋立即数？
4. 查括号指针 ──> 括号里是不是只有 BX/BP/SI/DI？有没有双基址或双变址？
5. 查类型指向 ──> 立即数送内存时，是否缺少 BYTE PTR 或 WORD PTR？
```

#### 经典综合判断试题

> **题目**：分析下列各条指令是否合法。若不合法，请说明详细原因：
> 1. `MOV [BX], [SI]`
> 2. `MOV AL, BX`
> 3. `MOV DS, 1000H`
> 4. `MOV CS, AX`
> 5. `MOV DS, ES`
> 6. `MOV AX, [DX]`
> 7. `MOV AX, [BX+BP]`
> 8. `MOV AX, [SI+DI]`
> 9. `MOV [BX], 25H`
> 10. `MOV ES:[BX+SI], AX`

#### 深度考点逐条剖析

1. **`MOV [BX], [SI]` —— 非法**
   - **错误原因**：源操作数和目的操作数均为存储器操作数。8086 架构不支持内存到内存的直接数据传送，必须借助通用寄存器中转（例如先 `MOV AL, [SI]`，再 `MOV [BX], AL`）。
2. **`MOV AL, BX` —— 非法**
   - **错误原因**：两端操作数类型/字长不匹配。`AL` 是 8 位寄存器，而 `BX` 是 16 位寄存器。
3. **`MOV DS, 1000H` —— 非法**
   - **错误原因**：立即数不能直接传送给段寄存器。必须先传给 `AX`，再由 `AX` 传给 `DS`。
4. **`MOV CS, AX` —— 非法**
   - **错误原因**：代码段寄存器 `CS` 不能作为 `MOV` 指令的目的操作数。修改 `CS` 会导致 CPU 指令流失控，只能通过 `JMP`、`CALL`、`RET` 或中断指令由硬件协同修改。
5. **`MOV DS, ES` —— 非法**
   - **错误原因**：8086 不支持段寄存器之间的直接数据传送。必须通过通用寄存器（如 `AX`）中转。
6. **`MOV AX, [DX]` —— 非法**
   - **错误原因**：`DX` 不是合法的寻址寄存器。8086 规定中括号内用于间接寻址的寄存器只能是 `BX`、`BP`、`SI`、`DI` 四个之一。
7. **`MOV AX, [BX+BP]` —— 非法**
   - **错误原因**：基址变址寻址中，不能同时出现两个基址寄存器。`BX` 和 `BP` 同属基址寄存器，硬件内部无法对其进行双重基址合成。
8. **`MOV AX, [SI+DI]` —— 非法**
   - **错误原因**：不能同时出现两个变址寄存器。`SI` 和 `DI` 同属变址寄存器。
9. **`MOV [BX], 25H` —— 非法**
   - **错误原因**：操作数属性不明确（类型模糊）。目的操作数 `[BX]` 是内存单元，源操作数 `25H` 是立即数，编译器无法判断到底是要向内存写入一个字节（`BYTE`）还是一个字（`WORD`，即 `0025H`）。必须显式添加属性限定符，写为 `MOV BYTE PTR [BX], 25H` 或 `MOV WORD PTR [BX], 25H`。
10. **`MOV ES:[BX+SI], AX` —— 合法**
    - **技术分析**：基址寄存器 `BX` 搭配变址寄存器 `SI`，显式使用了段超越前缀 `ES:`，目的操作数是附加段中的字单元，源操作数是 16 位寄存器 `AX`，语法与硬件语义完全正确。

### 物理地址与有效地址合成大题精解

这是全书分值最重、计算量最大的题型。解答此类题目必须先列出公式，分清段寄存器归属，绝不能跳步。

#### 经典考题

> **题目**：设 8086 CPU 当前内部寄存器的状态如下：
> - $(DS) = 2000H$
> - $(SS) = 3000H$
> - $(ES) = 4000H$
> - $(BX) = 0100H$
> - $(BP) = 0200H$
> - $(SI) = 0010H$
> - $(DI) = 0020H$
>
> 请分别计算下列各条指令中，**内存操作数的寻址方式名称**、**有效地址 $EA$** 以及对应的 **20 位物理地址（PA）**：
> 1. `MOV AX, [1200H]`
> 2. `MOV AX, [BX+SI]`
> 3. `MOV AX, [BP+DI+6]`
> 4. `MOV AX, ES:[BX+10H]`

```text
物理地址计算通用模型:
有效地址 EA ──┐
              ├──> [ 20位加法器 ] ──> 物理地址 (PA)
段基址 × 16 ──┘
```

#### 详细推导步骤

##### 第一题：MOV AX, [1200H]
- **寻址方式**：直接寻址（Direct Addressing）。
- **有效地址 $EA$**：指令直接给出偏移量，故：
  $$EA = 1200\text{H}$$
- **段寄存器判定**：无段超越且无 `BP`，默认段寄存器为 **`DS`**。
- **物理地址计算**：
  $$\text{PA} = (DS) \times 16 + EA = 2000\text{H} \times 10\text{H} + 1200\text{H} = 20000\text{H} + 1200\text{H} = 21200\text{H}$$

##### 第二题：MOV AX, [BX+SI]
- **寻址方式**：基址变址寻址（Base Indexed Addressing）。
- **有效地址 $EA$**：基址寄存器与变址寄存器内容之和：
  $$EA = (BX) + (SI) = 0100\text{H} + 0010\text{H} = 0110\text{H}$$
- **段寄存器判定**：括号内包含的是 `BX` 与 `SI`，无 `BP`，默认段寄存器为 **`DS`**。
- **物理地址计算**：
  $$\text{PA} = (DS) \times 16 + EA = 20000\text{H} + 0110\text{H} = 20110\text{H}$$

##### 第三题：MOV AX, [BP+DI+6]
- **寻址方式**：相对基址变址寻址（Relative Base Indexed Addressing）。
- **有效地址 $EA$**：基址 + 变址 + 位移量：
  $$EA = (BP) + (DI) + 6 = 0200\text{H} + 0020\text{H} + 0006\text{H} = 0226\text{H}$$
- **段寄存器判定**：**核心避坑点！** 括号内包含基址指针 **`BP`**，未指定段超越时，其默认段寄存器必须是 **`SS`（堆栈段）**！
- **物理地址计算**：
  $$\text{PA} = (SS) \times 16 + EA = 30000\text{H} + 0226\text{H} = 30226\text{H}$$

##### 第四题：MOV AX, ES:[BX+10H]
- **寻址方式**：寄存器相对寻址（Register Relative Addressing）。
- **有效地址 $EA$**：
  $$EA = (BX) + 10\text{H} = 0100\text{H} + 0010\text{H} = 0110\text{H}$$
- **段寄存器判定**：指令显式使用了段超越前缀 **`ES:`**，因此强制使用附加段寄存器 `ES`，不再使用默认的 `DS`。
- **物理地址计算**：
  $$\text{PA} = (ES) \times 16 + EA = 40000\text{H} + 0110\text{H} = 40110\text{H}$$

#### 运算结果核验总表

| 指令 | 寻址方式 | 有效地址 $EA$ | 关联段寄存器 | 20 位物理地址（PA） |
| :--- | :--- | :--- | :--- | :--- |
| `MOV AX, [1200H]` | 直接寻址 | `1200H` | `DS (2000H)` | `21200H` |
| `MOV AX, [BX+SI]` | 基址变址寻址 | `0110H` | `DS (2000H)` | `20110H` |
| `MOV AX, [BP+DI+6]` | 相对基址变址寻址 | `0226H` | `SS (3000H)` | `30226H` |
| `MOV AX, ES:[BX+10H]`| 寄存器相对寻址 | `0110H` | `ES (4000H)` | `40110H` |

### PTR 操作符的本质作用与内存改写题

在寻址题中，经常会遇到结合内存修改的跟踪题目。

#### 经典考题

> **题目**：设当前 $(DS) = 2000H$，$(BX) = 0050H$。物理地址为 `20050H` 和 `20051H` 的两个字节单元初值分别为 `34H` 和 `12H`。
> 1. 执行指令 `MOV BYTE PTR [BX], 78H` 后，物理地址 `20050H` 和 `20051H` 的单元内容分别是什么？
> 2. 若在此基础上紧接着执行指令 `MOV WORD PTR [BX], 0ABH`，两单元的内容又分别变成什么？

```text
PTR 操作符对内存影响图解:
初态:                [ 20050H: 34H ] [ 20051H: 12H ]
BYTE PTR 写入 78H:  [ 20050H: 78H ] [ 20051H: 12H ] (仅改 1 字节)
WORD PTR 写入 00ABH:[ 20050H: ABH ] [ 20051H: 00H ] (连续改写 2 字节，高位补 0)
```

#### 深度解题剖析

1. **第一条指令分析**：
   - `MOV BYTE PTR [BX], 78H` 指明了传送类型为**字节（Byte）**。
   - CPU 仅将单字节立即数 `78H` 写入由 `DS:BX` 所指向的物理地址 `20050H`。
   - `20051H` 单元未被触及，保持原值。
   - 结果：`20050H` 变为 **`78H`**，`20051H` 仍为 **`12H`**。
2. **第二条指令分析**：
   - `MOV WORD PTR [BX], 0ABH` 指明传送类型为**字（Word，16 位）**。
   - 立即数 `0ABH` 扩展为 16 位字形式是 `00ABH`，其中低 8 位为 `ABH`，高 8 位为 `00H`。
   - 按照小端序原则，低位字节存入低地址 `20050H`，高位字节存入高地址 `20051H`。
   - 结果：`20050H` 变为 **`ABH`**，`20051H` 变为 **`00H`**！

> **结论**：`WORD PTR` 即使写的是一个较小的数值（如 `0ABH`），它也会强制清空/改写相邻高地址的下一个字节（补 `00H`）。这是很多人在编写缓冲区时意外冲掉相邻变量的元凶！
