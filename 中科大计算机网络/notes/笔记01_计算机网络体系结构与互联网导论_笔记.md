# 计算机网络体系结构与互联网导论

## 计算机网络拓扑与体系构件

### 网络拓扑本质与节点链路角色

* **网络（Network）**

    * > **定义**：由若干节点（Node）与连接节点的边（Edge）构成的抽象拓扑互联系统。

    * 拓扑关联形态与节点的物理尺寸、空间几何形状无关，仅关注连接状态与关系属性。

    * 简单微观单元在庞大连接规模下会涌现出复杂的宏观系统特性。

* **计算机网络（Computer Network）**

    * > **定义**：联网的计算设备及相关通信设备按照工程规范构成的软硬件物理与逻辑系统。

    * 硬件构成抽象为两类拓扑实体（方框的主机节点与圆圈的数据交换节点）及通信链路。

* **端系统（End System）与主机节点（Host Node）**

    * > **定义**：处在网络边缘、作为数据通信源头（Source）与最终目的地（Destination）的计算设备。

    * 包含三个必要层次：计算存储物理硬件、内嵌标准协议栈的操作系统、发起并消费业务数据的网络应用进程。

    * 涵盖传统服务器、个人电脑、移动终端以及具备网络协议栈的物联网（IoT）智能设备。

* **数据交换节点（Data Switching Node）**

    * > **定义**：位于网络核心、仅承担数据中转（Forwarding）职责而不作为数据源与消费目的地的交换设备。

    * 交换机（Switch）工作在数据链路层，依据数据帧首部的介质访问控制地址（MAC 地址）查询转发表转发。

    * 路由器（Router）工作在网络层，依据分组首部的目标网络地址（IP 地址）检索路由表并决定下一跳输出端口。

* **通信链路（Link）**

    * > **定义**：由物理传输媒介与驱动该媒介收发信号的数据链路层协议构成的通信通道。

    * 接入链路（Access Link）负责连接端系统与边缘交换节点（连接方框与圆圈）。

    * 骨干链路（Backbone Link）负责连接网络核心交换节点与交换节点（连接圆圈与圆圈）。

    * 链路核心度量指标为传输速率或带宽（Bandwidth），国际标准单位为比特每秒（bps），十进制换算关系为 $1\text{ kbps} = 10^3\text{ bps}$、$1\text{ Mbps} = 10^6\text{ bps}$、$1\text{ Gbps} = 10^9\text{ bps}$、$1\text{ Tbps} = 10^{12}\text{ bps}$。

### 网络协议四要素与标准化机制

* **网络协议（Network Protocol）**

    * > **定义**：通信双方对等层实体（Peer Entities）在进行信息交互时必须共同遵守的规则集合。

    * 语法（Syntax）规定传输数据单元的二进制编码格式、字段组成、长度大小与排列次序。

    * 语义（Semantics）阐明特定字段数值的控制含义、业务意图及接收方应触发的动作解释。

    * 时序（Timing，同步）规定报文收发的先后顺序、状态迁移条件与超时等待控制。

    * 动作（Action）规定实体在特定事件驱动或接收特定报文后，在本地执行的实际操作指令。

    * 协议标准化保障了跨厂商异构硬件系统与跨平台软件环境之间的互操作性（Interoperability）。

* **请求评述文档（Request for Comments，RFC）**

    * > **定义**：由互联网工程任务组（IETF）公开发布的用于制定网络技术规范、协议标准与指导原则的正式文档序列。

    * 遵循开放、透明、自下而上的工程评审机制，草案经过全球同行评议、原型实现验证后逐步晋升为正式互联网标准（Internet Standard）。

### 互联网双重视角与系统划分

* **构件视角（Nuts-and-bolts View）**

    * > **定义**：从物理软硬件实体构成审视网络，互联网是由海量端系统、交换设备与通信链路构成的网络之网络（Network of Networks）。

    * 大写的 Internet（互联网/网际网）特指全球公开发布、基于 TCP/IP 协议族的全球公共互联网络。

    * 小写的 intranet（企业网/内部网）特指采用 TCP/IP 技术但物理或逻辑边界受限、不向公众开放的机构专用网络。

* **服务视角（Services View）**

    * > **定义**：从业务支撑能力审视网络，互联网是向分布式应用程序提供数据通信支撑的基础设施。

    * 分布式应用进程是网络基础设施存在的唯一根本理由。

    * 通信基础设施涵盖端系统应用层以下协议栈、操作系统驱动、网络接口卡以及网络核心所有路由交换设备与物理信道。

    * 套接字接口（Socket API）是操作系统向应用层提供的网络应用程序编程接口，充当应用进程访问底层通信基础设施的逻辑服务门钵。

## 网络边缘与端系统通信范式

### 分布式应用交互架构

* **客户端/服务器架构（Client-Server Architecture，C/S 架构）**

    * > **定义**：由集中管理资源的服务器与主动请求资源的客户端构成的非对称主从网络交互范式。

    * 服务器端先于客户端启动运行，长年守候在知名端口，掌控核心计算、存储与业务数据资产。

    * 客户端处于从属地位，在产生业务诉求时启动并主动发起请求，无法脱离服务器独立通信。

    * 扩展性（Scalability）瓶颈明显，并发规模突破阈值时呈现非线性断崖式性能雪崩；依赖大型服务器农场（Server Farm）横向堆叠硬件，但单点故障风险依然集中。

* **对等架构（Peer-to-Peer Architecture，P2P 架构）**

    * > **定义**：网络节点地位完全对称、兼具客户端与服务端角色的分布式交互范式。

    * 自扩展性（Self-Scalability）：新加入的对等节点在索取网络资源的同时贡献自身的上行带宽与存储容量，服务能力伴随用户规模扩张而自发同比例增强。

    * 多路径带宽聚集（Bandwidth Aggregation）：将大文件切分成若干数据块，客户端并行向多个对等体发起并发下载，叠加多条通信路径的带宽以突破单点服务器速率瓶颈。

### 传输层端系统服务模型

* **面向连接服务（Connection-Oriented Service）**

    * > **定义**：通信双方在传输业务数据前必须经历显式握手以协商参数并分配资源的传输服务。

    * 在端系统操作系统内核中预分配发送/接收缓冲区、初始化控制状态变量、启动往返时延测量定时器。

    * > **易错点**：⚠️ 面向连接（Connection-Oriented）与有连接网络（Connection-Based）存在本质区别：面向连接的会话状态仅在通信两端的端系统内核中维持，网络核心路由器对此完全无感知、不维护任何状态；有连接网络则要求全路径中间交换节点协同记录并维持状态。

* **可靠数据传输（Reliable Data Transfer，RDT）**

    * > **定义**：确保接收端应用层交付的数据与发送端注入的数据完全一致的通信服务质量保障。

    * 满足四大指标：不出错（No Error）、不丢失（No Loss）、不重复（No Duplication）、不失序（In Order）。

    * 实现开销巨大，需付出两端内存存储空间、序号校验计算、ACK 确认反馈及超时重传等时间与带宽代价。

* **流量控制（Flow Control）**

    * > **定义**：协调发送方与接收方端到端数据传输速率以防止对端接收缓冲区溢出的流控机制。

    * 接收端通过确认报文动态反馈接收窗口（Receive Window）以约束发送端的最大注入量。

* **拥塞控制（Congestion Control）**

    * > **定义**：端系统根据网络核心路径拥挤态势动态调节注入速率以防止网络骨干崩溃的自适应机制。

    * 感知丢包或往返时延剧增时主动收缩发送窗口，网络畅通时逐步探测提速。

* **传输控制协议（Transmission Control Protocol，TCP）**

    * > **定义**：运行于传输层、向上提供面向连接的可靠保序字节流传输协议。

    * 具备面向连接握手、可靠数据传输、流量控制与拥塞控制四大完整机制。

    * 适用于对数据完整性要求严苛的场景，如 Web 浏览（HTTP）、文件传输（FTP）、电子邮件（SMTP）。

* **用户数据报协议（User Datagram Protocol，UDP）**

    * > **定义**：运行于传输层、向上提供无连接且尽力而为的轻量级传输协议。

    * 无连接建立握手、不保障数据可靠送达、无流量控制、无拥塞控制，协议首部仅占 8 字节。

    * 适用于时间敏感且容忍轻微丢包的实时音视频通话、流媒体直播，以及一问一答、追求低延迟的轻量级事务应用（如 DNS 域名解析）。

| 特性对比维度 | 传输控制协议（TCP） | 用户数据报协议（UDP） |
| :--- | :--- | :--- |
| **连接管理模式** | 面向连接，数据传输前需执行三次握手建立逻辑状态 | 无连接，即发即收，无前置建连开销 |
| **连接状态维护** | 仅通信两端的主机操作系统内核维护，网络核心无感知 | 端系统与网络核心均无会话连接状态 |
| **数据可靠性** | 绝对可靠，严格保序（不出错、不丢失、不重复、不失序） | 尽力而为（Best-effort），不提供可靠交付保证 |
| **流量与拥塞控制** | 同时具备滑动窗口流量控制与网络拥塞控制机制 | 无流量控制，无拥塞控制，以应用产生速率注水 |
| **短事务交互延迟** | 需消耗 $2 \times \text{RTT}$（$1\text{ RTT}$ 建连 + $1\text{ RTT}$ 数据往返） | 仅需 $1 \times \text{RTT}$（直接往返单次数据交互） |
| **典型应用场景** | 网页浏览（HTTP）、文件传输（FTP）、邮件传递（SMTP） | 实时音视频通话、在线游戏对战、域名解析（DNS） |

### 软件定义网络控制解耦

* **传统网络层架构**

    * > **定义**：控制平面分布式路由协议与数据平面查表转发在单台物理路由器内部紧耦合的系统架构。

    * 转发逻辑刚性，仅支持孤立的目的 IP 地址查表匹配；网络新特性升级需全网逐台更换专用硬件，演进周期漫长。

* **软件定义网络（Software Defined Networking，SDN）**

    * > **定义**：将控制平面从底层转发设备中剥离、实现逻辑集中控制与通用数据平面解耦的网络架构。

    * 控制平面由全网逻辑集中的网络操作系统（Network OS / Controller）承担，集中计算并生成全局流表（Flow Table）。

    * 数据平面由标准化通用 SDN 交换机组成，依据南向接口协议下发的流表执行多字段通用匹配（跨 2~4 层字段）与多样化动作（转发、阻断丢弃、重写头部、泛洪广播）。

## 网络核心与数据交换机制

### 电路交换与多路复用技术

* **电路交换（Circuit Switching，线路交换）**

    * > **定义**：通信双方在传输数据前由信令系统在网络核心预先建立并独占端到端物理通路的交换方式。

    * 通信过程包含三个阶段：线路建立（呼叫连接）、独占数据传输、线路拆除（释放连接）。

    * 优势是独占信道具备恒定传输速率与确定性性能硬保障；缺陷是连接建立时延对突发通信代价过高，静默期资源严重浪费，核心节点维持海量连接状态导致容灾能力差。

* **多路复用（Multiplexing）**

    * > **定义**：在单条物理传输链路上划分多个独立子信道以承载多路信号并行传输的技术。

    * 频分多路复用（FDM）：按频率划分不重叠的物理子频带，各用户独占指定频带（如无线广播）。

    * 时分多路复用（TDM）：按时间划分周期性固定时隙（Time Slot），第 $n$ 个用户周期性独占第 $n$ 个时隙（如数字电话载波系统）。

    * 波分多路复用（WDM）：光纤介质中的频分复用，利用不同光波长在单根光纤中并行传输多路光信号。

    * 码分多路复用（CDM/CDMA）：所有用户共享全部时间与频率，依赖互相正交的码片序列（Chip Sequence）实现多址隔离（如 3G 蜂窝通信）。

* **电路交换时延度量模型**

    * 独享信道有效带宽：设总带宽为 $C$，TDM 均分为 $M$ 个时隙，则专属带宽 $R = C / M$。

    * 发送传输延时：发送长度为 $L$ 的文件所耗费的纯发射时间为 $T_{\text{trans}} = L / R$。

    * 连接建立延时：信令往返耗时 $T_{\text{setup}}$，发送端末比特完全推入信道绝对时刻为 $t = T_{\text{setup}} + T_{\text{trans}}$。

    * 最终接收时刻：接收端完全收妥文件的绝对时刻为 $t_{\text{complete}} = T_{\text{setup}} + T_{\text{trans}} + T_{\text{prop}}$，其中 $T_{\text{prop}} = d / s$。

    * 单个比特在时间上的持续发射宽度为 $1/R$，在介质中占有的物理空间跨度为 $s/R$。

### 分组交换与存储转发机理

* **分组交换（Packet Switching）**

    * > **定义**：将长报文划分为受限长度的离散分组（Packet），在全带宽信道上以存储转发方式动态调度的数据交换方式。

    * 全带宽占用：发送数据时不进行静态时隙或频带切分，瞬间以链路完整额定带宽全速发射。

    * 存储转发（Store-and-Forward）：中间交换机必须将分组的全部比特完整接收存入缓冲区，完成校验与查表后再向下一跳链路转发。

    * > **易错点**：⚠️ 若不采用存储转发而直接直通转发长数据流，数据流将贯穿并独占沿途所有链路数分钟，本质退化为电路交换；存储转发在时间和空间上解耦了相邻链路，实现了全网共享。

    * > **易错点**：⚠️ 发送与接收是同一物理传输事件在信道两端的观察面。单条链路上将分组推入介质耗时 $L/R$，此过程只计算一次传输时延，绝不能重复累加“发与接”。

* **多跳存储转发时延累积**

    * 穿过由 $N$ 段传输速率为 $R$ 的链路串接、包含 $N-1$ 个中继路由器的路径，单个长度为 $L$ 的分组在无排队理想状态下的端到端总传输时延为：
      $$T_{\text{total}} = N \times \frac{L}{R} + \sum_{i=1}^N \frac{d_i}{s_i}$$

* **排队延时（Queuing Delay）与分组丢弃（Packet Drop）**

    * 当聚合到达流量的瞬间输入速率超过输出链路的发送速率时，分组进入路由器输出队列等待，引发排队延时。

    * 硬件缓冲区容量有限，当队列填满发生溢出时，新到达的分组被交换节点直接物理丢弃。

### 统计多路复用与容量概率推导

* **统计多路复用（Statistical Multiplexing）**

    * > **定义**：根据网络流量统计特征，按需动态分配信道物理时隙的多路复用技术。

    * 链路上时隙的占用完全取决于各主机实际产生的分组流量，动态交织共享，无数据则不占用信道。

* **突发通信容量二项分布推导**

    * 条件模型：链路总带宽 $C = 1\text{ Mbps}$，用户活跃状态发送速率 $r = 100\text{ kbps}$，活跃概率 $p = 0.1$，接入总用户数 $N$。

    * 电路交换容量：按峰值独占分配，$N_{\text{circuit}} = C / r = 10\text{ 个用户}$。

    * 分组交换超载概率：接入 $N = 35$ 个用户，同时活跃用户数 $k \sim B(35, 0.1)$，满载阈值 $k_{\text{max}} = C / r = 10$。

    * 瞬时超载概率公式：
      $$P(k > 10) = 1 - \sum_{k=0}^{10} \binom{35}{k} (0.1)^k (0.9)^{35-k} \approx 0.0004 = 0.4\%$$

    * 结论：系统在 $99.6\%$ 的时间内处于非超载状态，支持用户数达电路交换的 3.5 倍。

* **流量强度极限与弹性平抑**

    * 当输入到达率等于信道处理能力时，流量强度 $\rho = 1$，队列因随机抖动无限发散崩溃，故工程额定容量需预留安全裕量（如限制在 9 人活跃，$\rho = 0.9$）。

    * 短暂的 $0.4\%$ 超载峰值被路由器输出队列弹性缓冲吸收，并在随后的轻载时间窗口被快速排空，避免全网瘫痪。

### 数据报网络与虚电路网络

* **数据报网络（Datagram Network）**

    * > **定义**：端系统通信无连接、中间节点无状态、每个分组独立寻径的分组交换网络。

    * 每个数据报首部必须携带目标主机的全局终极网络地址（如 32 位 IPv4 目的地址）。

    * 路由器无会话状态记录，根据本地路由表独立决策，同一会话的不同数据报到达路径与先后顺序可能不同。

* **虚电路网络（Virtual-Circuit Network，VC 网络）**

    * > **定义**：在网络层建立逻辑连接、全路径维持状态、依据局部虚电路号转发的分组交换网络。

    * 包含三个阶段：虚电路建立（VC Setup 分配资源并建立表项）、数据传输（Data Transfer）、虚电路拆除（VC Teardown 释放表项）。

    * 分组首部仅携带局部虚电路号（VC ID），交换机转发表项结构为 `[入端口, 入 VC] -> [出端口, 出 VC]`。

    * > **注意**：VC ID 仅具备局部链路意义，分组每经过一跳中继，首部的 VC ID 均被交换节点动态重写。

| 比较维度 | 数据报网络（Datagram） | 虚电路网络（Virtual-Circuit） |
| :--- | :--- | :--- |
| **网络层连接状态** | 无连接，通信前无需执行网络层呼叫建立 | 面向连接，必须预先经历信令建立虚电路 |
| **中间路由器状态** | 交换节点绝对无状态，查表独立转发 | 交换节点维持有状态的 VC 映射转发表 |
| **分组首部地址** | 完整全局终极目的网络地址（如目的 IP） | 局部虚电路标识符（VC ID），逐跳重写 |
| **分组传输路径** | 各分组独立寻径，路径随路由更新可能不一致 | 全会话分组严格沿预设虚电路路径前行 |
| **节点故障耐受性** | 极高，故障时后续分组可动态绕行自愈 | 较脆弱，路径任一节点故障导致整条 VC 崩溃 |
| **典型技术代表** | 互联网 IP 协议网络 | 传统电信 X.25、帧中继（Frame Relay）、ATM |

## 接入网络与物理介质特性

### 住宅接入技术演进

* **电话拨号调制解调器（Dial-up Modem）**

    * > **定义**：利用模拟电话铜线通过正弦波载波调制解调传输数字比特的接入技术。

    * 调幅（AM）、调频（FM）、调相（PM）与复合调制将二进制数字基带转换为模拟音频。

    * 受限于程控交换机 4 kHz 语音低通滤波器物理限制，香农极限理论最高速率为 56 kbps；上网与通话严格互斥。

* **非对称数字用户线路（ADSL，Asymmetric Digital Subscriber Line）**

    * > **定义**：基于现有电话双绞线实施频分复用以提供宽带接入的技术。

    * 频带划分：0~4 kHz 为传统模拟电话语音，4~25 kHz 为防护隔离频带（Guard Band），25 kHz 以上划分为数据传输频带。

    * 速率非对称性：顺应家庭上网“大下行、小上行”特征，下行速率约数 Mbps 至 10 Mbps，上行速率约 1 Mbps。

    * 用户端通过语音分离器（Splitter）分流信号，实现上网与打电话完全并发。

* **混合光纤同轴电缆接入（HFC，Hybrid Fiber-Coaxial）**

    * > **定义**：由有线电视运营商主导、干线采用光纤且入户分支采用同轴电缆的共享宽带接入网。

    * 拓扑架构：有线电视前端（Headend）经骨干光纤连接光纤节点（Fiber Node），再经树状同轴电缆分支接入各家 Cable Modem。

    * 共享介质属性：下行方向由前端统一广播，上行方向所有用户争用共享频带；黄金时段高并发下人均可用带宽显著缩水。

* **家庭综合无线路由器**

    * > **定义**：单机物理外壳内高度集成 AP、以太网交换机与 NAT 路由防火墙的家用网络网关。

    * 集成无线接入点（AP，802.11 射频信道）、局域网二层交换机（LAN 物理端口群）以及三层路由器（WAN 口、网络地址转换 NAT、状态防火墙）。

### 机构接入与无线移动网络

* **机构局域网接入（Enterprise Access）**

    * 拓扑层级：终端/AP $\to$ 楼层接入交换机 $\to$ 大楼汇聚交换机 $\to$ 校区核心交换机 $\to$ 总校区核心交换机 $\to$ 机构边界路由器群。

    * 多归属出口（Multi-homing）：边界路由器同时并发接入多家运营商网络（如电信、移动、教育网 CERNET），实现容灾冗余与智能路由分流。

    * 以太网（Ethernet）速率跃迁：从标准 10 Mbps、快速以太网 100 Mbps、千兆以太网 1 Gbps 演进至万兆以太网 10 Gbps；10G 及以上高带宽主要用于现代数据中心（Data Center）内部并行计算高通量 I/O。

* **无线局域网（Wireless LAN / Wi-Fi）**

    * 基于 IEEE 802.11 协议标准，覆盖半径通常在数十米至 30 米（100 英尺）内。

    * 演进标准：802.11b（最高 11 Mbps）、802.11g（最高 54 Mbps）、802.11n（MIMO 阵列与信道绑定，达数百 Mbps）。

* **移动蜂窝网络（Cellular Network）**

    * 电信运营商移动基站覆盖半径可达数公里至十余公里；移动互联时代移动访问数据总量全面超越固定网络。

    * 5G 面临的工程矛盾：工作频段高导致穿透弱、衰减快，微基站部署密度成倍激增，大规模天线阵列与高算力芯片引发天价基建成本与超高运行功耗；当前阶段面临“十六车道超级高速公路跑拖拉机”的杀手级应用匮乏困局。

### 导引型物理传输介质

* **导引型物理媒体（Guided Media）**

    * > **定义**：信号沿固体物理导体介质内部定向传播的实体传输载体，常称为协议栈“第 0 层”。

* **双绞线（Twisted Pair）**

    * 两根带有绝缘层的铜导线按固定节距相互螺旋绞合。

    * 抗干扰原理：电磁辐射在相邻波节感应出的噪声电压大小相等、极性完全相反，在差分接收端自动完全抵消。

* **同轴电缆（Coaxial Cable）**

    * 由共轴的内部铜导体、绝缘介质、圆柱形导电编织铜网屏蔽层与外绝缘套构成。

    * 外屏蔽层构成法拉第笼，抗干扰性能优于双绞线；分为单频基带同轴电缆与频分复用宽带同轴电缆。

* **光纤（Optical Fiber）**

    * 采用高纯度石英玻璃拉丝制成，横截面由高折射率纤芯（Core，$n_1$）与低折射率包层（Cladding，$n_2$）构成（$n_1 > n_2$）。

    * 传播原理：当光线射入纤芯界面的入射角大于临界角时，发生光的全反射（Total Internal Reflection），光能量被彻底束缚在纤芯内前行。

    * 单模光纤（SMF）：纤芯直径极细（8~10 微米，接近波长），仅支持单一垂直模式直线传播，无模间色散，传输衰减极低，用于长途干线与跨洋海缆。

    * 多模光纤（MMF）：纤芯直径较粗（50~62.5 微米），光线沿多条反射路径传播，模间色散严重导致脉冲展宽失真，用于局域网机房数百米短距互联。

    * 物理安全性极高：外部无电磁辐射泄漏，唯一窃听方式为物理割开光缆实施旁路分光（Bypass）。

### 非导引型自由空间介质

* **非导引型物理媒体（Unguided Media）**

    * > **定义**：信号以电磁波或光波形式在空气、真空或水等自由空间中开放传播的物理介质。

    * 物理特性：遵循空间电磁辐射平方反比衰减规律（$P_r \propto 1/d^2$），极易受环境多径反射衰落损耗影响，同频信号并发时存在强烈的相互干扰。

* **地面微波（Terrestrial Microwave）与可见光通信（Li-Fi）**

    * 地面微波沿视距（Line-of-Sight）直线定向传播，受地球曲率遮挡需在数十公里间设立铁塔中继站接力。

    * 可见光通信（Li-Fi）：利用室内天花板 LED 照明灯的高速光强调制（人眼不可见高频闪烁）与终端高速光敏传感器实现免布线接入。

* **卫星通信系统（Satellite Communication）**

    * 地球同步静止轨道卫星（GEO）：位于赤道上空 36,000 公里轨道，运行角速度与地球自转同步，地面天线指向固定；缺陷为星地往返距离极远，单程往返传播延迟高达约 270 毫秒。

    * 低轨卫星星座（LEO）：运行在 500~1,200 公里近地轨道（如 Starlink），低延迟（几十毫秒内），但单星覆盖与可用射频频段容量有限，属于地面蜂窝通信的有力补充而非替代品。

## 互联网拓扑组织与运营商生态

### 层次化运营商拓扑演进

* **全网状全连接模型不可行性**

    * $N$ 个接入网络两两直接拉设专线互联，全网互联链路总数为 $L = N(N-1)/2 = O(N^2)$。

    * 物理布线与端口开销呈平方级爆炸，架构不可扩展（Unscalable）。

* **全球主干提供商（Global Transit ISP）引入**

    * 商业实体出资铺设跨洋长途光缆与骨干路由器，Access ISP 仅需拉设一根专线接入 Global ISP 即可通达全网。

    * 跨网链路复杂度由 $O(N^2)$ 压缩至 $O(N)$；Access ISP 扮演付费客户（Customer），Global ISP 扮演提供商（Provider）。

* **对等互联（Peering）与互联网交换点（IXP）**

    * 对等互联（Peering）：同级骨干运营商之间直接铺设对等链路交换直属客户流量；在流量规模对等时实行无偿对等（Settlement-Free Peering）。

    * 互联网交换点（IXP）：由中立机构设立的大型物理高速交换矩阵机房，各运营商边界路由器汇聚于此，以单一场所实现多对多对等互通。

### 现代多层级结构与互联锚点

* **松散层次拓扑（Loose Hierarchy）**

    * 第一层网络（Tier 1 ISP）：跨国主干电信网络，彼此完全实行无偿对等，不向任何外部网络缴纳转接费。

    * 第二层网络（Tier 2 ISP）：区域性或国家级电信网络，向上游 Tier 1 购买过境服务，同级之间在 IXP 对等互通。

    * 本地/接入网络（Local / Access ISP）：直接服务终端主机的末端网络，向上级运营商购买接入转接服务。

    * 网络接入点（Point of Presence，POP）：高层提供商网络在其覆盖边缘设立的一组路由器及机房设施，供下游客户 ISP 租用本地专线接入并建立从属商业转接。

### 内容提供商专网与架构重塑

* **公网中继瓶颈与 ICP 专网战略**

    * 超级内容提供商（ICP，如 Google）面临公网巨额流量转接过境账单以及公网多跳中继不可控的 QoS 拥塞抖动。

    * 战略对策：绕开公共骨干网，自建覆盖全球的私有高速光纤海缆专网与分布式数据中心。

* **数据中心物理布局准则**

    * 能耗与散热：选址于常年极寒区域（自然风冷）或沉入水底（水冷热交换）。

    * 地质容灾防卫：避开地震断裂带，利用坚固山体地下溶洞（如中国贵州数据中心集群）防御灾害与战争损毁，兼享廉价水电。

    * 拓扑就近接入：机房直接部署在大型 IXP 或核心 ISP POP 点物理近邻处，实现一跳极速切入。

* **私有专网旁路路由优化**

    * 终端用户请求仅穿过 1~2 跳本地接入网即进入就近 ICP 机房。

    * 命中缓存直接本地毫秒级响应；未命中跨洋请求直接注入 ICP 自建私有专网高速调度，彻底规避公网过境拥塞与结算成本。

## 分组交换网络性能分析度量

### 节点处理延时四组件

* **节点总时延（Nodal Delay，$d_{\text{nodal}}$）**

    * 分组穿过单个路由节点所经历的总时延为四个互不重叠组件的叠加：
      $$d_{\text{nodal}} = d_{\text{proc}} + d_{\text{queue}} + d_{\text{trans}} + d_{\text{prop}}$$

* **处理延时（Processing Delay，$d_{\text{proc}}$）**

    * > **定义**：路由器检查比特差错、更新生存时间（TTL）、检索转发表匹配输出端口所消耗的物理时间。

    * 由专用硬件芯片（ASIC 或网络处理器）固化执行，耗时通常在微秒（$\mu s$）或亚微秒量级。

* **排队延时（Queuing Delay，$d_{\text{queue}}$）**

    * > **定义**：分组在输出端口硬件排队缓冲区中等待链路发送器空闲所经历的时间。

    * 具有动态随机性，完全由网络即时拥塞程度与前序排队分组积压深度决定，可从零波动至数十毫秒。

* **传输延时（Transmission Delay，$d_{\text{trans}}$，发送延时）**

    * > **定义**：节点的发送器将分组包含的全部比特依次推向物理通信链路所消耗的时间。

    * 设分组长度为 $L$ 比特，链路传输带宽为 $R$ bps，公式为：
      $$d_{\text{trans}} = \frac{L}{R}$$

    * 仅取决于分组长度与发送机接口速率，与两节点之间的空间物理距离完全无关。

* **传播延时（Propagation Delay，$d_{\text{prop}}$）**

    * > **定义**：电磁波或光信号在物理介质中从发送端行进穿越物理空间抵达接收端所消耗的时间。

    * 设链路物理距离为 $d$ 米，介质传播速度为 $s$ 米每秒（光纤与有线介质中约为 $2 \times 10^8\text{ m/s}$），公式为：
      $$d_{\text{prop}} = \frac{d}{s}$$

    * 仅取决于物理距离与介质电磁属性，与分组大小和链路带宽完全无关。

### 流量强度与排队非线性发散

* **流量强度（Traffic Intensity，$I$）**

    * > **定义**：衡量输出链路排队缓冲区承载负荷饱和程度的无量纲比值指标。

    * 设分组平均长度为 $L$ 比特，平均到达速率为 $a$ 分组每秒，输出链路速率为 $R$ bps，公式为：
      $$I = \frac{L \cdot a}{R}$$

    * 分子 $L \cdot a$ 代表单位时间希望通过队列的比特总数，分母 $R$ 代表链路最大物理发送能力。

* **非线性排队发散机理**

    * 当 $I \to 0$ 时，网络轻载，新分组大概率直接发送，$d_{\text{queue}} \to 0$。

    * 当 $I$ 超过 0.7~0.8 时，微小的突发即可引发队列深度剧烈积压，平均排队延时呈非线性指数级陡增。

    * 当 $I \to 1$ 时，平均排队延时在数学期望上趋向于无穷大（$\infty$）。

    * 发散根因：实际网络分组呈现泊松突发或聚集到达，突发滞后的排队队列无法被闲置时段的服务能力跨时空储存或均摊补偿，队列积压单调发散。

### 端到端路径探测与丢包策略

* **路径探测工具（Traceroute / tracert）工作原理**

    * 利用 IP 首部生存时间（Time To Live，TTL）字段与互联网控制报文协议（ICMP）。

    * 源端发送探测报文（封装高端口 UDP），首轮设置 $\text{TTL} = 1$；第一跳路由器将 TTL 减 1 归零后丢弃该包，并回发 ICMP TTL Expired 报文，源端记录该节点 IP 并计算单跳往返时延（RTT）。

    * 依次递增发送 $\text{TTL} = 2, 3, \dots$ 的探测报文，逐步遍历多跳路由节点。

    * 终止判据：当探测报文到达目的端时，因目标主机无进程监听该异常高端口，目标主机回送 ICMP Destination Port Unreachable 报文，探测正式收敛终止。

* **有限缓冲区设计必然性**

    * 交换机队列容量不能无限扩大；无限队列在持续重载下会导致数天甚至数周的超长排队时延，而上层应用超时断开后陈旧报文即便到达也已失去工程价值。

* **分组丢失后的三种处理命运**

    * 链路层立即重传：适用于无线局域网（Wi-Fi / 802.11），在易受干扰的高误码率信道上“亡羊补牢”，局部跳步确认重传以防止错误向全网扩散。

    * 端到端传输层重传：适用于有线网络环境下的 TCP 协议；底层光纤和双绞线物理误码极低（“响鼓不用重锤”），链路层轻装无状态运行，仅在路由器缓冲区溢出丢包时由源端 TCP 超时重传。

    * 完全不重传：适用于 UDP 协议；实时音视频和在线对战场景宁可承受轻微丢帧，也绝不容忍重传带来的秒级延迟抖动。

### 端到端瓶颈吞吐量模型

* **吞吐量（Throughput）**

    * > **定义**：单位时间内目标节点成功接收到的有效数据比特数（单位为 bps 或 Mbps）。

    * 瞬时吞吐量（Instantaneous Throughput）指特定瞬时采样速率；平均吞吐量（Average Throughput）指长周期内传递总比特数除以总消耗时间。

* **理想串联链路木桶效应**

    * 在无外部流量竞争的理想串联链路上，端到端吞吐量受限于路径上最小的物理链路带宽：
      $$\text{Throughput} = \min(R_1, R_2, \dots, R_n)$$

* **实际共享网络瓶颈切分**

    * 在分组交换共享网络中，设第 $i$ 段骨干链路物理带宽为 $R_i$，穿过该链路的独立并发通信对数量为 $n_i$。

    * 在公平分配前提下，端到端实际吞吐量由所有跳步中切分到的最小可用有效带宽决定：
      $$\text{Throughput} = \min_i \left( \frac{R_i}{n_i} \right)$$

    * 瓶颈链路位置具有动态性：接入端带宽狭窄时瓶颈在边缘，骨干链路并发用户暴增（$n_i$ 极大）时瓶颈转移至网络核心共享链路。

## 分层服务模型与协议体系结构

### 层次化模块解耦与开销权衡

* **分层模块化设计（Layering）**

    * > **定义**：将复杂的通信系统自底向上解耦为功能明确的层级结构，仅允许紧相邻的上下层之间发生服务调用。

    * 相比平面模块化的任意互相依赖，分层严格约束了拓扑依赖方向，防止大型网络调用关系陷入网状失控。

    * 异地哲学家思想交流模型体现了分层解耦：顶层哲学家层聚焦思想语义交互，中间翻译层处理语言编码表示与控制标签，底层秘书层处理信件物理投递。

* **分层架构优势与代价权衡**

    * 优势：功能分而治之、模块独立开发维护；接口稳定时底层技术更迭对上层完全透明（平滑升级）；统一标准化术语降低协同壁垒。

    * 代价：跨层数据流动需反复穿越系统接口与内存拷贝，附加多层首部引入封装开销；下层屏蔽细节使得跨层全局优化受阻。

### 水平协议与垂直服务交互模型

* **协议与服务的正交关系**

    * 水平协议（Protocol）：通信双方对等实体在水平方向为了协调数据交换而共同遵守的规约集合。

    * 垂直服务（Service）：由下层实体通过层间接口向紧邻的上层实体所提供的通信能力封装。

    * 协议实现依赖下层服务，本层协议运行的唯一目标是在接口上向直接上层交付更高级的服务增量。

* **服务累加与增量模型**

    * 第 $N$ 层向上提供的完整服务 $S_N$ 包含了其下所有底层的能力累加及本层创造的全新服务增量 $\Delta F_N$：
      $$S_N = \left( \sum_{k=1}^{N-1} S_k \right) + \Delta F_N$$

    * 实体功能（Function）是内部机制总集，服务（Service）是功能中暴露给上层可调用的规范子集（$\text{功能} \ge \text{服务}$）。

* **服务三要素**

    * 主体（Roles）：服务提供者（下层实体）与服务用户（上层实体）。

    * 地点（Where）：服务访问点（SAP），区分不同服务用户的逻辑标识（如链路层的帧类型字段、网络层的 IP 协议号、传输层的端口号 Port）。

    * 形式（How）：服务原语（Primitive），服务调用与状态确认的操作调用规约（如 Socket API 的 `socket()`、`bind()`、`send()`）。

### 数据单元封装映射机制

* **数据单元命名规范**

    * 服务数据单元（Service Data Unit，SDU）：上层交付给本层需要透明运送的有效数据载荷（货物净荷）。

    * 接口控制信息（Interface Control Information，ICI）：穿越层间接口时传递的临时辅助管理参数。

    * 接口数据单元（Interface Data Unit，IDU）：在层间接口上瞬时传递的数据总成（$\text{IDU} = \text{SDU} + \text{ICI}$）。

    * 协议数据单元（Protocol Data Unit，PDU）：对等层实体依据协议交换的完整报文（$\text{PDU} = \text{Header} + \text{SDU} \;[+\; \text{Trailer}]$）。

    * 级联规律：上一层的 PDU 跨过层间接口下移，即转变为下一层的 SDU。

* **SDU 与 PDU 映射形态**

    * 一对一封装（1:1）：标准封装模式，单个 SDU 附加本层头部封装为一个独立的 PDU。

    * 一对多分段（1:N）：上层 SDU 尺寸超出本层最大传输单元时，拆分为多个切片分别封装独立 PDU（如 IP 分片）。

    * 多对一聚合（N:1）：将连续到达的多个微小 SDU 拼接汇聚在单个有效载荷空间内，统一附加头部封装，以减少报头开销。

### 五层协议栈与七层模型映射

* **互联网五层协议栈划分与 PDU 命名**

    * 应用层（Application Layer）：支持分布式网络应用通信，PDU 称为报文（Message），典型协议包括 HTTP、FTP、SMTP、DNS。

    * 传输层（Transport Layer）：负责端系统应用进程之间的端到端通信（Process-to-Process），PDU 称为报文段（Segment），核心协议为 TCP 与 UDP。

    * 网络层（Network Layer）：负责将分组从源主机送达目标主机（Host-to-Host），实现路由选择与分组转发，PDU 称为分组（Packet）或数据报（Datagram），核心协议为 IP 协议及 RIP、OSPF、BGP 路由协议。

    * 链路层（Data Link Layer）：负责在物理相邻节点之间以点到点方式传输数据（Hop-by-Hop），PDU 称为帧（Frame），典型技术包括以太网、Wi-Fi、PPP。

    * 物理层（Physical Layer）：负责在物理媒介上透明搬移离散的二进制信号（Bit），PDU 称为比特（Bit），实现调制解调与电平编码。

* **OSI 七层参考模型与功能下放**

    * 包含应用层、表示层、会话层、传输层、网络层、数据链路层、物理层。

    * 表示层负责数据语法格式转换、数据加密解密与数据压缩。

    * 会话层负责建立、管理和同步会话，提供检查点（Checkpoints）设置与断点续传支持。

    * 互联网 TCP/IP 架构舍弃独立的表示层与会话层，将格式解析（如 JSON/XML）与会话状态管理（如 Cookie/Token）全盘下放给应用程序本身实现，以保持协议栈核心精简与转发高效。

### 端到端全栈封装转发全流程

* **源端全栈大封装**

    * 应用层生成原始数据报文 $\text{Message}$；传输层附加端口报头 $\text{H4}$ 封装为 $\text{Segment}$；网络层附加 IP 寻址报头 $\text{H3}$ 封装为 $\text{Packet}$；链路层附加 MAC 帧头 $\text{H2}$ 与差错校验帧尾 $\text{T2}$ 封装为 $\text{Frame}$；物理层转换为电磁或光脉冲信号打入介质。

* **中间设备分层解封装与再封装**

    * 二层交换机（以太网交换机）：仅跨越物理层与链路层；解析帧头并提取目的 MAC 地址，检索交换表决定输出端口，重新封装该链路物理帧打出（二层解封装与再封装）。

    * 三层路由器：跨越物理层、链路层与网络层；剥离外层帧头帧尾，提取 IP 分组，根据目的 IP 检索转发表决定下一跳，交由出端口网卡重新封装全新的链路层帧头帧尾打出（三层解封装与再封装）。

* **目的端全栈大解封装**

    * 目的主机物理层感应信号还原比特流；链路层校验 CRC 无误后剥除 $\text{H2}/\text{T2}$ 提取分组；网络层校验 IP 报头确认目标 IP 后剥除 $\text{H3}$ 提取报文段；传输层根据序列号重组确认后剥除 $\text{H4}$ 还原报文；最终通过端口 SAP 将 $\text{Message}$ 精准交付给绑定的目标应用进程。

## 互联网技术演进史与架构哲学

### 分组交换理论与早期网络

* **分组交换理论诞生**

    * 二十世纪六十年代初，冷战背景下针对传统线路交换抗毁性脆弱、时延大、闲置浪费的瓶颈，三个独立研究小组推导出分组交换理论，证明了统计复用与存储转发在突发数据场景下的优越性。

* **ARPANET 试验网与接口报文处理机（IMP）**

    * 1969 年美国国防部高级研究计划局（DARPA）出资立项建设 ARPANET，首个物理节点部署于加州大学洛杉矶分校（UCLA）。

    * 核心硬件为接口报文处理机（IMP），与主机（Host）级联，负责报文切片与节点间存储转发。

    * 运行最初的网络控制协议（NCP），将网络寻址与端到端传输紧密耦合于单一实体。

### 瑟夫-卡恩覆盖原则与架构升级

* **专网割据与 OSI 困境**

    * 20 世纪 70 年代以太网、ALOHANet、ATM 及厂商专网（DECNET、IBM SNA、Xerox XNA）林立，形成封闭互联孤岛。

    * OSI 参考模型试图以“推倒重来”方式全局统一替换底层硬件标准，因忽视存量资产保护且协议栈官僚臃肿，在工程实践中受阻。

* **瑟夫-卡恩覆盖网络（Overlay Network）三大原则**

    * 极度包容与尽力而为（Best-Effort）：IP 协议对底层介质不做苛刻可靠性假设，提供“尽最大努力交付”，包容高误码率异构网络（IP over everything）。

    * 端到端原则（End-to-End Principle）：网络核心仅执行无状态分组中继，将复杂可靠性控制与状态维护全部后置到边缘端系统（TCP 协议）。

    * 无状态路由器与分布式控制：中间节点不维护端到端会话状态，分组独立根据转发表寻路，控制机制高度去中心化。

* **标记日（Flag Day）与解耦确立**

    * 1983 年 1 月 1 日，ARPANET 全网停机，统一废弃 NCP 协议，全面启用 TCP/IP 协议栈。

    * 纵向解耦：网络层（IP）专职无状态寻址转发，传输层（TCP/UDP）专职端到端进程通信控制。

    * 横向解耦：边缘方块主机（拥有完整五层全栈，产生与消费数据）与核心圆圈路由器（维持无状态 IP 转发，不运行应用进程）彻底分离。

    * > **结论**：当代网络拥有数百亿规模节点，已永久丧失全网集中停机升级窗口，体系演进必须遵循向下兼容的渐进式修补策略（如 NAT、CIDR、IPsec）。

* **沙漏模型（Hourglass Model）哲学**

    * 中间狭窄：以单一核心 IP 协议为绝对中枢。

    * 上下宽阔：下层包容任意物理传输介质（IP over everything），上层赋能任意新型应用无需修改核心交换硬件（Everything over IP）。

### 万维网普及与数字经济竞争

* **早期经典应用与传输机制成熟**

    * 1982 年 SMTP 邮件协议标准化；1983 年域名系统（DNS）投入运行，建立字符串域名至二进制 IP 的映射基石；1985 年 FTP 协议确立；1988 年 Van Jacobson 将慢启动与拥塞避免引入 TCP，平抑骨干网络拥塞崩溃。

* **万维网（World Wide Web）原型诞生**

    * 1989 年欧洲核子研究组织（CERN）蒂姆·伯纳斯-李基于非线性超文本（Hypertext）构想，设计出超文本标记语言（HTML）、超文本传输协议（HTTP）以及首套 Web 浏览器与服务器原型，攻克跨国科研数据协同痛点。

* **浏览器大战与网络外部性**

    * 1994 年网景公司推出商业图形浏览器 Netscape Navigator，微软跟进推出 IE 浏览器并依托 Windows 操作系统底层免费捆绑展开第一次浏览器大战。

    * 反映数字经济的残酷法则：零边际复制成本与极强网络外部性（Network Externality）导致赢者通吃（Winner-Takes-All），细分赛道仅容纳前两三名垄断格局。

### 现代网络扩容与园区网工程落地

* **正反馈扩容飞轮**

    * 杀手级应用（Killer Apps，如即时通信、流媒体、社交网络、移动支付）驱动用户流量爆炸，倒逼 ISP 扩容大带宽骨干基础设施，更低延迟大带宽的基础设施反向孕育更庞大的超级应用（Super Apps）。

* **真实园区网工程落地（以中科大校园网为例）**

    * 物理拓扑汇聚：终端/AP $\to$ 楼层交换机 $\to$ 大楼交换机 $\to$ 校区核心交换机，各校区核心之间铺设地下冗余光纤环网（Mesh 拓扑）。

    * 链路层生成树控制（STP）：物理存在冗余环路以防断纤容灾，但以太网二层数据帧无防环 TTL 机制，必须运行 STP 协议逻辑计算并阻塞冗余端口，防止广播风暴瘫痪网络。

    * 核心直挂与多宿主：核心服务器集群（校级 Web、邮件、FTP）直接挂接在核心路由交换背板（Switch Fabric）以消除内网访问瓶颈；对外通过硬件防火墙向电信、移动、联通及教育网（CERNET）建立多宿主并发出口。

    * 区域性 ISP 职能：科大作为 CERNET 安徽省主节点，承担省内各高校的接入汇聚与国际转接职责，印证了异构网络通过统一 IP 协议松散互联、多路并存的体系结构本质。
