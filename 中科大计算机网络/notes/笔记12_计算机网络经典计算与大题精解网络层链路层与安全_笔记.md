# 计算机网络经典计算与大题精解（网络层、链路层与安全）

## 数据平面体系架构与路由器硬件交换

### 控制平面与数据平面的体系解耦

* **数据平面（Data Plane）**

    * > **定义**：路由器本地的、局部的硬件级处理功能，负责在微秒或纳秒时间尺度上将到达输入链路的分组转移至正确的输出链路。

    * 核心职责为局部转发（Forwarding），其行为严格依据本地转发表（Forwarding Table）执行。

    * 运行介质为硬件流水线，由专用集成电路（ASIC）或网络处理器（NP）以线速实现。

    * 在传统体系中，数据平面协议的核心代表是 IP 协议，仅承担查表与输出端口搬移。

* **控制平面（Control Plane）**

    * > **定义**：全网范围的、全局性的分布式或集中式逻辑规划功能，负责在毫秒到秒级时间尺度上计算并决定分组从源到目的地的端到端完整路径。

    * 核心职责为路由选择（Routing），输出产物为路由表（Routing Table），经软件提炼后下发并固化为数据平面的硬件转发表。

    * 传统分布式网络中，控制平面由运行在各路由器上的路由协议进程（如 OSPF、IS-IS、BGP）协同运算实现。

    * 软件定义网络（Software-Defined Networking, SDN）中，控制平面从设备剥离，集中至逻辑上统一的远程 SDN 控制器（SDN Controller）上。

* **转发决策机制对比**

    * > **定义**：网络层中间节点依据报文首部字段确定报文去向与处理动作的规则体系。

    * 决策依据与动作差异：

        | 维度 | 传统 IP 路由器 | 软件定义网络（SDN / OpenFlow） |
        | :--- | :--- | :--- |
        | **控制平面形态** | 高度分布式，每台路由器独立运行路由算法进程 | 集中式逻辑控制，由远程控制器集中运算与统筹 |
        | **转发表下发途径** | 本地控制进程计算后直接写入本地转发表 | 控制器通过南向接口（如 OpenFlow）远程下发流表 |
        | **匹配维度** | 仅依赖目的 IP 地址，采用最长前缀匹配 | 支持入端口、MAC、VLAN、IP、传输层端口等多维联合匹配 |
        | **执行动作** | 单纯的单播输出接口转发，仅递减 TTL 并重算校验和 | 转发、跨端口泛洪、丢弃、修改首部字段、重写 IP/MAC 等组合动作 |
        | **网络可编程性** | 固化在专用硬件与固件中，配置封闭繁琐 | 转发硬件与控制大脑解耦，全网具备软件动态编程能力 |

### 路由器硬件组件与交换机构演进

* **路由器硬件体系结构**

    * > **定义**：专门用于网络层数据报快速接收、选路与转发的高性能专用计算机硬件架构。

    * 物理构成包含四个核心构件：输入端口（Input Ports）、输出端口（Output Ports）、路由选择处理器（Routing Processor）、交换机构（Switching Fabric）。

    * 内部交互拓扑逻辑：

        ```text
        +-------------------------------------------------------------+
        |                     路由选择处理器 (控制平面)                 |
        +-------------------------------------------------------------+
                   ^                                       ^
                   | 控制信号                               | 控制信号
                   v                                       v
        +------------------+   +-------------------+   +------------------+
        | 输入端口 (Input)  |-->|                   |-->| 输出端口 (Output) |
        +------------------+   |                   |   +------------------+
        | 输入端口 (Input)  |-->|   交换机构 Fabric  |-->| 输出端口 (Output) |
        +------------------+   |                   |   +------------------+
        | 输入端口 (Input)  |-->|                   |-->| 输出端口 (Output) |
        +------------------+   +-------------------+   +------------------+
        ```

    * 输入端口执行物理层比特接收、链路层帧解封装，并在网络层完成首部提取、转发表检索与排队缓冲。

    * 路由选择处理器运行控制平面软件，管理路由协议与设备状态，不参与线速数据转发流水线。

* **交换机构（Switching Fabric）**

    * > **定义**：路由器内部用于将分组从输入端口物理移动至输出端口的专用高速硬件通道网络。

    * 经内存交换（Switching via Memory）：第一代路由器结构；输入端口以中断通知 CPU，分组经系统总线拷贝至主存，查表后再拷贝至输出端口；交换吞吐量受限于内存总线双向带宽。

    * 经总线交换（Switching via a Bus）：输入端口为分组附带内部标签后直接推入共享内部总线，输出端口监听匹配标签并接收；任意时刻仅允许单个分组穿越总线，整机性能受总线带宽瓶颈硬性制约。

    * 经互联网络交换（Switching via an Interconnection Network / Crossbar）：由 $2N$ 条总线横纵交错构成交叉开关矩阵；每个交叉点由硬件电子开关联控，允许多对互不冲突的输入/输出端口并发无阻塞传输。

### 交换性能瓶颈与头端阻塞机理

* **线速交换（Line-Speed Switching）**

    * > **定义**：交换设备内部转发处理能力达到或超过物理传输介质最大理论比特率的工作状态。

    * 交换机构无内部阻塞的充分条件：对于拥有 $N$ 个全双工输入端口的路由器，若每个端口线速为 $R_{\text{line}}$，交换机构内部交换速率必须至少达到 $N \times R_{\text{line}}$。

    * 若内部交换速率低于 $N \times R_{\text{line}}$，交换机构自身演变为排队瓶颈，输入端口必须建立缓冲队列。

* **头端阻塞（Head-of-Line Blocking, HOL）**

    * > **定义**：在先进先出（FIFO）输入队列中，队首分组因其目标输出端口繁忙而被阻塞等待，导致队列后方原本去往空闲输出端口的分组也被迫停滞在队列内部的结构性拥塞现象。

    * 阻塞过程拓扑表现：

        ```text
        输入队列 1: [ 目标: 端口 1 ] ---> 正在发往端口 1 (端口 1 忙碌)
                       |
        输入队列 2: [ 目标: 端口 1 ] [ 目标: 端口 3 ]
                            ^               |
                            | (被阻挡)       v
                     队首端口冲突    端口 3 当前空闲！
                                    但第二位分组被物理顺序阻断！
        ```

    * 发生根源：多输入端口对同一输出端口的并发争用，叠加 FIFO 队列的严格时序约束。

    * 消除手段：输入端采用虚拟输出队列（Virtual Output Queueing, VOQ）技术，为每个输出端口建立独立的物理或逻辑分流队列。

## 协议首部解析、IP分片与协议开销

### IP协议首部格式与跨层解复用

* **协议号（Protocol）**

    * > **定义**：IPv4 首部中占 8 比特的控制字段，用于标定数据报有效载荷所封装的高层协议类型。

    * 多路分解取值规范：值为 6 代表 TCP 报文段，值为 17 代表 UDP 数据报，值为 1 代表 ICMP 差错与控制报文。

    * 映射关系：网络层通过协议号将数据载荷交付给正确的上层协议实体，其逻辑功能与传输层利用端口号将报文分配给应用进程完全对等。

* **IPv6 首部演进**

    * > **定义**：相比 IPv4 经过大幅结构精简、字段固定化为 40 字节的基础网络层报文首部规范。

    * 字段继承与映射体系：

        * 版本号（Version）：占 4 比特，IPv4 为 `0100`（4），IPv6 为 `0110`（6）。

        * 业务流类别（Traffic Class）与流标签（Flow Label）：占 8 比特与 20 比特，替代 IPv4 服务类型（ToS），用于 QoS 保障。

        * 有效载荷长度（Payload Length）：占 16 比特，精简了 IPv4 的首部长度与总长度字段，特指 40 字节基础首部之后携带的所有扩展首部及高层数据字节总和。

        * 下一个首部（Next Header）：占 8 比特，取代 IPv4 的 `Protocol` 字段；若紧随高层协议则填入对应编号（如 6 对应 TCP），若存在扩展首部则指向下一个扩展首部，形成链式结构。

        * 跳数限制（Hop Limit）：占 8 比特，取代 IPv4 的生存时间（TTL）；每经一跳路由器减 1，减至 0 丢弃并回送 ICMPv6 超时差错报文。

### IP数据报分片与重组计算

* **最大传输单元（Maximum Transmission Unit, MTU）**

    * > **定义**：底层链路层数据帧所能承载的最大数据载荷长度，即穿过物理网络的 IP 数据报的最大允许总长度（包含 IP 首部自身）。

    * 标准以太网链路的 MTU 典型值为 1500 字节。

    * > **易错点**：⚠️ MTU 是链路层帧的数据载荷上限，属于“包含 IP 头部在内的 IP 数据报总尺寸”，不可误算为剥离 IP 首部后的纯上层数据载荷。

* **IP 分片核心参数控制**

    * > **定义**：当 IP 数据报总长超出出口链路 MTU 时，由路由器执行的报文切块机制及其用于端到端重组的首部标定参数。

    * 标识（Identification, ID）：占 16 比特；同一原始 IP 数据报拆分出的所有子分片，必须携带与原报文完全一致的 ID 值。

    * 标志位（Flags）：占 3 比特；最高位保留为 0；中间位为 DF（Don't Fragment），置 1 禁止分片（超大则丢弃报错）；最低位为 MF（More Fragments），置 1 表示后续仍有分片，置 0 表示此为末尾分片。

    * 片偏移（Fragment Offset）：占 13 比特；指明该分片的数据载荷在原始 IP 数据报数据载荷中的相对起始位置。

    * 8 字节对齐铁律：片偏移以 8 字节为物理计量基数（单位为 8 字节）。除最后一个分片外，前面所有分片所分配的有效数据载荷长度，必须为 8 的整数倍。

* **分片计算标准推导**

    * > **定义**：依据 MTU 限制与 8 字节对齐约束，精确求解分片数量、首部字段及各片载荷范围的数学算法。

    * 单片最大数据容量计算公式：

        $$L_{\text{data\_max}} = \left\lfloor \frac{\text{MTU} - L_{\text{IP\_header}}}{8} \right\rfloor \times 8$$

    * 计算实例（原数据报长 2400 字节，含 20 字节 IP 首部，遇链路 MTU = 700 字节）：

        * 原始总数据载荷：$2400 - 20 = 2380$ 字节。

        * 单片可用载荷上限：$700 - 20 = 680$ 字节。校验对齐：$680 \div 8 = 85$（可整除，单片上限为 680 字节）。

        * 逐片切分参数结果表：

            | 分片编号 | 报文总长度（字节） | 数据载荷（字节） | 载荷字节区间 | 标志位 MF | 片偏移 Offset（8 字节单位） |
            | :---: | :---: | :---: | :---: | :---: | :---: |
            | **分片 1** | 700 | 680 | $0 \sim 679$ | 1 | $0 \div 8 = \mathbf{0}$ |
            | **分片 2** | 700 | 680 | $680 \sim 1359$ | 1 | $680 \div 8 = \mathbf{85}$ |
            | **分片 3** | 700 | 680 | $1360 \sim 2039$ | 1 | $1360 \div 8 = \mathbf{170}$ |
            | **分片 4** | 360 | 340 | $2040 \sim 2379$ | 0 | $2040 \div 8 = \mathbf{255}$ |

        * 边界验证：末尾分片载荷 340 字节不要求 8 字节整除，其总长 $340 + 20 = 360 \le 700$ 满足 MTU。

### 传输层分段与封装开销分析

* **最大报文段长度（Maximum Segment Size, MSS）**

    * > **定义**：TCP 报文段中所允许封装的纯应用层数据载荷的最大长度，不包含 TCP 首部与 IP 首部。

    * 在标准以太网环境（MTU = 1500 字节、标准 IPv4 首部 20 字节、标准 TCP 首部 20 字节）下：

        $$\text{MSS} = \text{MTU} - L_{\text{IP\_header}} - L_{\text{TCP\_header}} = 1500 - 20 - 20 = 1460\text{ 字节}$$

    * 若改用 UDP 协议，首部开销降为 8 字节，应用层可用载荷上升为 $1500 - 20 - 8 = 1472$ 字节。

* **应用层文件封装分段计算**

    * > **定义**：将固定大小的应用层数据文件划分为满足网络链路 MSS 约束的传输层段数的离散计算过程。

    * 单位规范：在通信与网络标准中，默认采用十进制前缀，即 $1\text{MB} = 10^6\text{ 字节}$；在计算机内存存储规范中，采用二进制前缀，即 $1\text{MB} = 1024 \times 1024 = 1,048,576\text{ 字节}$。

    * 实例计算（5MB 文件通过以太网 TCP 传输，MSS = 1460 字节）：

        * 采用网络公制标准：

            $$\text{段数} = \left\lceil \frac{5 \times 10^6}{1460} \right\rceil = \lceil 3424.66 \rceil = 3425\text{ 个}$$

        * 采用计算机二进制标准：

            $$\text{段数} = \left\lceil \frac{5 \times 1,048,576}{1460} \right\rceil = \lceil 3591.01 \rceil = 3592\text{ 个}$$

## CIDR地址规划、最长前缀匹配与路由聚合

### 子网掩码与CIDR表示法

* **无类域间路由（Classless Inter-Domain Routing, CIDR）**

    * > **定义**：取消传统的 A、B、C 类固定网络边界划分，允许网络前缀占据任意比特长度的 IP 地址编址与分配体系。

    * 点分掩码格式：用连续的二进制 1 标定网络前缀（网络号与子网号），用连续的 0 标定本地主机号。如 `255.255.240.0` 表示前 20 位为 1，后 12 位为 0。

    * 斜线记法（Slash Notation）：形如 `IP/x`，斜线后数值 $x$ 声明前 $x$ 比特为网络前缀，主机位数为 $32 - x$，可分配地址总数为 $2^{32-x}$。

    * 子网内部再划分：上级机构向原主机号的高位按需借位作为下一级子网号，形成分层树状地址空间。

### 二进制自然对齐与地址块分配

* **地址块二进制边界对齐铁律**

    * > **定义**：一个包含 $2^n$ 个连续 IP 地址的地址块能够被单一 CIDR 前缀（`/32-n`）完整表达的充要数学几何约束。

    * 对齐准则：地址块大小必须为 2 的整数次幂（即 $2^n$），且地址块的起始基地址转换为 32 位二进制整数时，其数值必须能够被 $2^n$ 整除（低 $n$ 位二进制必须全为 0）。

    * 保留地址扣除：分配给常规子网使用时，主机部分全 0 保留为**网络地址**，主机部分全 1 保留为**本子网定向广播地址**，两类地址禁止分配给主机网卡；子网有效可用主机容量为 $2^n - 2$。

* **子网空间规划与碎片防范策略**

    * > **定义**：在给定父级网络地址池中，按需求规模分配连续子网块并避免地址空洞的工程推导方法。

    * 向上取整规则：需求 $M$ 个主机地址，所需地址块总容量应满足 $2^n \ge M + 2$。

    * 地址对齐推导实例（ISP 规划需求依次为：A 机构 4000、B 机构 2000、C 机构 4000、D 机构 8000）：

        * 规格确定：A 取 4096（`/20`）、B 取 2048（`/21`）、C 取 4096（`/20`）、D 取 8192（`/19`）。

        * 错序对齐陷阱：若从地址 0 开始，先分配 A（$0 \sim 4095$），紧接分配 B（$4096 \sim 6143$）；此时剩余可用起点为 6144。因 $6144 \div 4096 = 1.5$，6144 不是 4096 的整数倍，若分配 C 将跨越两个不同的 `/20` 边界，导致无法聚合；系统被迫跳过 $6144 \sim 8191$（产生 2048 字节无法聚合的空洞），只能从 8192 开始分配 C。

        * 降序最优分配律：多机构分配地址块时，必须按照**容量从大到小降序排列分配**（D 8192 $\to$ A 4096 $\to$ C 4096 $\to$ B 2048），使大块自然贴合高阶二进制边界，彻底杜绝碎片空洞。

### 最长前缀匹配查找算法

* **最长前缀匹配（Longest Prefix Match, LPM）**

    * > **定义**：当路由表或转发表中存在多条能够与输入目的 IP 地址相重叠匹配的路由表项时，硬件查表引擎必须选取子网掩码最长（即网络前缀最长、范围最精确具体）的表项作为输出转发依据的裁决规则。

    * 兜底机制：若所有具名前缀均未匹配成功，则匹配前缀长度为 0 的默认路由（`0.0.0.0/0`）。

    * 覆盖容量计算实例（8 比特地址空间）：

        * 规则定义：前缀 `00` 映射端口 0；前缀 `010` 映射端口 1；前缀 `011` 映射端口 2；前缀 `10` 映射端口 2；前缀 `11` 映射端口 3。

        * 端口容量解算：

            * 端口 0：前缀 2 位，主机 $8-2=6$ 位，容量 $2^6 = 64$ 个地址。

            * 端口 1：前缀 3 位，主机 $8-3=5$ 位，容量 $2^5 = 32$ 个地址。

            * 端口 2：包含两段独立空间，`011`（容量 $2^5 = 32$）与 `10`（容量 $2^6 = 64$），总容量 $32 + 64 = 96$ 个地址。

            * 端口 3：前缀 2 位，主机 $8-2=6$ 位，容量 $2^6 = 64$ 个地址。

### 路由聚合与超网形成条件

* **路由聚合（Route Aggregation / Supernetting）**

    * > **定义**：将多个数值连续、大小相同的子网前缀合并为一个更短前缀的高层单一路由条目，以抑制全球骨干网路由表恶性膨胀的技术。

    * 聚合充要拓扑条件：

        * 被聚合的子网块数量必须为 $2^m$ 个（如 4 个块，则 $m=2$）。

        * 各子网块的大小必须严格相同（同为 $2^n$ 规格）。

        * 各子网块在数值空间上必须绝对连续。

        * 各子网块在高阶可合并比特位上，必须穷尽所有二进制排列组合（如合并 4 个块，其交界 2 比特必须完整覆盖 `00, 01, 10, 11`）。

    * 聚合操作机制：将公共网络前缀向左缩减 $m$ 位（掩码长度减 $m$），向外部邻居通告拥有更短掩码的单一聚合前缀。

## 控制平面架构与经典路由选择算法

### 垂直集成与控制平面工作模式

* **每路由器控制（Per-Router Control）**

    * > **定义**：每台路由器物理设备内部同时集成独立的控制平面进程与数据平面硬件的传统网络体系架构。

    * 架构表现：

        ```text
        +-------------------------------------------------------------+
        |                      单个传统路由器设备                     |
        |   +-----------------------------------------------------+   |
        |   |                      控制平面                       |   |
        |   |  * 运行路由协议（OSPF、IS-IS、BGP 等）              |   |
        |   |  * 维护路由状态，计算并生成路由表                   |   |
        |   +--------------------------+--------------------------+   |
        |                              | 下发转发表 (FIB)             |
        |                              v                              |
        |   +-----------------------------------------------------+   |
        |   |                      数据平面                       |   |
        |   |  * 专用硬件（ASIC）依据转发表执行线速匹配与输出转发 |   |
        |   +-----------------------------------------------------+   |
        +-------------------------------------------------------------+
        ```

    * 垂直集成（Vertical Integration）模型：网络设备厂商一体化研发专用芯片、背板、操作系统与协议栈；系统封闭，升级与全网协同难度大。

### 链路状态与距离矢量算法多维对比

* **链路状态算法（Link State, LS）**

    * > **定义**：各节点通过全网可靠泛洪获取整个网络的完整拓扑与链路代价，并在本地独立运用 Dijkstra 算法集中求解最短路径的路由算法。

    * 算法特征：全局视野、集中式计算，拓扑收齐后一次性运行计算。

* **距离矢量算法（Distance Vector, DV）**

    * > **定义**：各节点仅感知直连链路代价，通过与直接物理邻居周期性或触发式交换距离估计向量，依托 Bellman-Ford 方程分布式异步逼近最优解的路由算法。

    * 算法特征：局部视野、分布式协作、异步迭代收敛。

* **两类算法性能指标对比矩阵**

    * > **定义**：从消息复杂度、收敛性能与故障隔离鲁棒性三个核心维度对 LS 与 DV 算法的横向工程比对。

    * 对比表现表：

        | 评价维度 | 优胜阵营 | 深入机理解析 |
        | :--- | :--- | :--- |
        | **消息复杂度** | **距离矢量（DV）** | DV 仅在直连邻居间点对点交换向量；LS 必须将链路状态在全网 $n$ 个节点间泛洪广播，报文规模达 $O(n \cdot E)$ |
        | **收敛速度** | **链路状态（LS）** | LS 在 LSA 收齐后本地 Dijkstra 计算极快；DV 依赖跨跳多轮传播，链路恶化时易受路由环路与“无穷计数”拖累 |
        | **健壮性（鲁棒性）** | **链路状态（LS）** | LS 仅宣告直连物理链路状态，单点错误局限在自身生成树；DV 宣告计算后的全网代价，错误信息呈雪崩式全网扩散 |

### 自治系统分层路由体系

* **自治系统（Autonomous System, AS）**

    * > **定义**：在单一技术管理与行政实体管辖下，使用统一内部路由策略与度量制运行的一组路由器集合。

    * 域内与域间划分解耦的三大矛盾：

        * 策略（Policy）：域内由单一部署方运维，无信任壁垒，无商业防备，追求效率最大化；域间分属不同电信运营商与主权国家，必须将商业收费、过境管辖与安全策略置于首要地位。

        * 规模性（Scale）：域内规模有限，过大可通过分层或划分子区（如 OSPF 区域）化解；域间必须容纳全球数十万 AS 和百万级前缀，可扩展性与强力聚合是协议第一生命线。

        * 性能（Performance）：域内纯以时延、带宽、代价为优化目标；域间必须在满足管理策略的前提下折中性能，策略高于性能。

* **内部网关协议与外部网关协议**

    * > **定义**：运行在自治系统内部的路由协议（IGP）与连接不同自治系统的边界路由协议（EGP）的功能划分。

    * IGP 常见协议包括 OSPF、IS-IS、RIP；EGP 在现代互联网中拥有唯一标准——边界网关协议（BGP-4）。

### OSPF链路状态泛洪与分层区域

* **开放最短路径优先（Open Shortest Path First, OSPF）**

    * > **定义**：基于链路状态技术构建的开放标准内部网关协议，采用可靠泛洪与 Dijkstra 算法计算无环最短路径。

    * 泛洪传播范围：路由器生成链路状态通告（LSA）后，通过可靠泛洪向**整个自治系统（或所在区域内的所有路由器）**广播。

    * > **易错点**：⚠️ OSPF 路由器绝非“仅向直接物理邻居散播并由其汇总”，而是利用泛洪机制确保区域内所有路由器获得完全一致的链路状态数据库（LSDB）。

* **OSPF 分层区域体系**

    * > **定义**：将大型 AS 划分为多个逻辑子区域以限制泛洪扩散规模的层次化结构。

    * 骨干区域（Backbone Area 0）：连接所有非骨干区域的核心中枢，负责跨区域路由汇聚分发。

    * 区域边界路由器（Area Border Router, ABR）：跨接骨干区域与普通区域的节点，将区域内拓扑摘要为路由条目后注入骨干区域，阻断细粒度拓扑在全网的大规模泛洪。

### Dijkstra算法汇聚树计算与转发表导出

* **Dijkstra 算法运行机理**

    * > **定义**：在赋权图中求解单源点到其余所有节点最短路径的经典贪心图论算法。

    * 符号系统：$N'$ 为已确定最短路径的永久节点集合；$D(v)$ 为源点到 $v$ 的已知最小代价；$p(v)$ 为源点到 $v$ 路径上的直接前序节点；$c(u, v)$ 为直连链路物理代价（非直连为 $\infty$）。

    * 鬆弛状态转移方程：

        $$D(v) = \min \big( D(v),\, D(w) + c(w, v) \big)$$

* **单源最短路径汇聚树求解实例**

    * > **定义**：以指定源节点 $X$ 为根，推导网络全节点最短路径及最终转发表的完整代数步骤。

    * 拓扑条件：$c(X,V)=3, c(X,W)=6, c(X,Y)=6, c(X,Z)=8, c(V,U)=3, c(V,T)=4$。

    * 完整演化状态记录表：

        | 步骤 | 永久集合 $N'$ | $D(V), p(V)$ | $D(W), p(W)$ | $D(Y), p(Y)$ | $D(Z), p(Z)$ | $D(U), p(U)$ | $D(T), p(T)$ | 选入节点与判定说明 |
        | :---: | :--- | :---: | :---: | :---: | :---: | :---: | :---: | :--- |
        | **初态** | $\{X\}$ | **$3, X$** | $6, X$ | $6, X$ | $8, X$ | $\infty$ | $\infty$ | 初态扫描，$V$ 代价最小（3），选入 $V$ |
        | **步 1** | $\{X, V\}$ | —— | $6, X$ | $6, X$ | $8, X$ | **$6, V$** | $7, V$ | 经 $V$ 鬆弛：$D(U)=3+3=6, D(T)=3+4=7$；选入并列最小的 $U$（代价 6） |
        | **步 2** | $\{X, V, U\}$ | —— | **$6, X$** | $6, X$ | $8, X$ | —— | $7, V$ | 经 $U$ 鬆弛无更优；临时集中选入最小节点 $W$（代价 6） |
        | **步 3** | $\{X, V, U, W\}$ | —— | —— | **$6, X$** | $8, X$ | —— | $7, V$ | 经 $W$ 鬆弛无更优；选入当前最小节点 $Y$（代价 6） |
        | **步 4** | $\{X, V, U, W, Y\}$ | —— | —— | —— | $8, X$ | —— | **$7, V$** | 经 $Y$ 鬆弛无更优；临时集中选入最小节点 $T$（代价 7） |
        | **步 5** | $\{X, V, U, W, Y, T\}$ | —— | —— | —— | **$8, X$** | —— | —— | 临时集仅存 $Z$（代价 8），选入 $Z$ |
        | **终态** | 全集收敛 | —— | —— | —— | —— | —— | —— | 全网节点最短路径树锁定 |

    * 汇聚树拓扑生成与转发表：

        ```text
                   [X] (源节点)
                /   |   \  \
          3    /  6 |  6 \  \ 8
              v     v     v  v
             [V]   [W]   [Y] [Z]
            /   \
      3    /     \ 4
          v       v
         [U]     [T]
        ```

    * 源节点 $X$ 本地转发表（目的地 $\to$ 下一跳）：$V \to V$（代价 3）；$W \to W$（代价 6）；$Y \to Y$（代价 6）；$Z \to Z$（代价 8）；$U \to V$（代价 6）；$T \to V$（代价 7）。

### 距离矢量算法局部更新与收敛计算

* **Bellman-Ford 分布式状态方程**

    * > **定义**：节点 $x$ 依托直连邻居所通告的到目的节点 $y$ 的距离，计算自身最小估计距离的迭代方程。

    * 数学状态表达式：

        $$D_x(y) = \min_{v \in \text{neighbors}(x)} \big\{ c(x, v) + D_v(y) \big\}$$

    * 单节点局部计算行为：节点 $Z$ 初始设定 $D_z(z)=0$，对直连邻居 $V, X$ 记录链路代价 $c(Z,V)=2, c(Z,X)=16$，其余目标初始化为 $\infty$；收到 $V$ 和 $X$ 的向量通告后，执行 $\min(2+D_v(y), 16+D_x(y))$；发生数值变动触发外发通告，无变动保持静默。

### 链路开销敏感性与路由切换阈值

* **路径切换临界代数推导**

    * > **定义**：通过建立双路径代价方程的不等式，求解导致路由器最优转发接口发生更迭的链路开销临界极值。

    * 模型设定：源节点 $X$ 到达目的节点 $u$ 存在两条路径：

        * 路径一（经邻居 $W$）：总开销为 $c(X,W) + D_w(u) = 2 + 5 = 7$。

        * 路径二（经邻居 $Y$）：总开销为 $c(X,Y) + D_y(u) = 5 + 6 = 11$。

        * 初始最优路径为经由 $W$。

    * 场景推导规则：

        * 保持 $c(X,Y)=5$ 不变，$c(X,W)$ 增大导致切换的条件：

            $$c(X,W) + 5 > 11 \implies c(X,W) > 6$$

        * 保持 $c(X,W)=2$ 不变，$c(X,Y)$ 减小导致切换的条件：

            $$c(X,Y) + 6 < 7 \implies c(X,Y) < 1$$

        * 系统路由决策绝对不发生切换的充要条件（切换条件的对立逻辑交集）：

            $$c(X,W) \le 6 \quad \text{且} \quad c(X,Y) \ge 1$$

## 边界网关协议与跨域路径决策

### BGP协议架构与路由分发链条

* **边界网关协议（Border Gateway Protocol, BGP）**

    * > **定义**：运行于不同自治系统之间、基于 TCP 连接的去中心化路径矢量外部路由协议。

    * 会话形态双重解耦：

        * 外部 BGP（External BGP, eBGP）：运行在分属两个不同自治系统的对等边界路由器之间，负责跨域通告网络前缀可达性。

        * 内部 BGP（Internal BGP, iBGP）：运行在同一个自治系统内部的所有 BGP 路由器之间，负责在域内全员同步从外部学得的前缀信息。

    * 前缀跨域端到端分发流程：

        ```text
        [AS4: 子网 x] ---> [4c] ==(eBGP)==> [AS3: 3c] --(iBGP)--> [3a/3b] ==(eBGP)==> [AS1: 1c/1b] --(iBGP)--> [1d]
        ```

        * 子网 $x$ 位于 AS4；边界路由器 4c 通过 eBGP 向 AS3 网关 3c 宣告 $x$。

        * 3c 收到后通过 AS3 内部的 iBGP 会话将前缀 $x$ 分发给域内普通路由器 3a 及出境网关 3b。

        * 3b 通过 eBGP 向 AS1 边界网关 1c 传播带有 AS 序列属性的前缀 $x$。

        * AS1 内的非边界路由器 1d 依赖本域内的 iBGP 连接，从网关 1c 同步前缀 $x$ 写入转发表。

### 路径矢量机制与环路彻底消除

* **自治系统路径序列（AS-PATH）**

    * > **定义**：BGP 路由更新报文中所强制携带的关键属性，按序记录该网络前缀自产生起所穿越的所有自治系统编号列表。

    * 环路防范铁律：当 BGP 路由器收到一条路由通告时，必首先扫描其 AS-PATH 列表。

    * 规则判定：若 AS-PATH 中已经存在该路由器**自身所属的 AS 编号**，说明路由发生折返循环，路由器直接无条件丢弃该条更新，彻底杜绝无穷计数与物理环路。

### BGP多属性决策阶梯与热土豆路由

* **BGP 路由决策四步阶梯**

    * > **定义**：当路由器经由不同路径获知通往同一目标前缀的多条可行路由通告时，所严格遵循的降序裁决规则。

    * 决策优先级顺序：

        ```text
        +-------------------------------------------------------------+
        |                      BGP 路由决策四步阶梯                   |
        |   1. 本地偏好 (Local Preference)  [越大越优，管理员策略最高] |
        |                               | (平局)                      |
        |                               v                             |
        |   2. 最短 AS-PATH                 [遍历外部 AS 数量最少优先] |
        |                               | (平局)                      |
        |                               v                             |
        |   3. 热土豆路由 (Hot Potato)      [内部 IGP 开销最小者胜出]  |
        |                               | (平局)                      |
        |                               v                             |
        |   4. 最终平局打破 (Tie-breaker)   [比选 Router ID 最小者]    |
        +-------------------------------------------------------------+
        ```

* **热土豆路由（Hot Potato Routing）**

    * > **定义**：在外部 AS-PATH 长度完全等同的平局状态下，路由器以本自治系统内部 IGP 开销最小为判定基准、尽快将分组卸出本域的贪心策略。

    * 裁决实例：

        * 路由器 1d 去往外部前缀 $x$ 可选网关 1b（内部开销 1 跳，外部 AS-PATH 为 3 跳）与网关 1c（内部开销 2 跳，外部 AS-PATH 为 2 跳）。

        * 判定结果：因第 2 级“最短 AS-PATH”规则优先级严格高于第 3 级“热土豆内部开销”，1c（2 跳外部 AS）在第 2 轮直接胜出；1d 宁走内部较远的链路送达 1c，也绝不选用外部路径过长的 1b。

## 数据链路层争用控制、差错检测与局域网技术

### 链路层可靠性与端到端原则

* **逐跳可靠性与端到端可靠性**

    * > **定义**：物理信道上两两相邻节点间的数据无差错传输与主机应用进程间最终端到端可靠传输的层次界限。

    * 逐跳可靠不可替代端到端可靠的机理：

        * 路由器内存队列溢出丢包：链路层保证帧无差错交付给路由器后，分组在进入路由器网络层输入/输出缓存排队时，若发生拥塞缓冲区溢出，路由器将主动丢弃该 IP 数据报；底层链路对此完全无能为力。

        * 多路径乱序：IP 层的动态路由分流可能导致数据报经由不同路径乱序到达终点，链路层无法感知端系统全局序号。

    * 端到端原则（End-to-End Principle）：差错重传、完整性检测与重排控制必须由通信两端的传输层（如 TCP）负责，链路层仅提供局部的传输加速与优化。

### 争用协议退避机制与性能边界

* **截断二进制指数退避算法（Truncated Binary Exponential Backoff）**

    * > **定义**：以太网 CSMA/CD 协议在检测到信道碰撞后，动态调整节点重传等待时延范围的自适应随机算法。

    * 窗口生成规则：经历连续第 $i$ 次碰撞后，退避因子 $K$ 从离散整数集合 $\{0, 1, 2, \dots, 2^k - 1\}$ 中等概率随机选取，其中指数上限 $k = \min(i, 10)$。

    * 物理等待时延计算方程：

        $$T_{\text{wait}} = K \times 512 \times \text{Bit Time} = K \times 512 \times \frac{1}{R}$$

    * 第 5 次碰撞计算实例（$R = 10\text{ Mbps} = 10^7\text{ bps}$）：

        * 窗口大小：$2^5 = 32$，离散集合 $\{0, 1, \dots, 31\}$。

        * 选中特定值（如 $K = 4$）的概率：$P(K = 4) = \frac{1}{32}$。

        * 基准位时：$\text{Bit Time} = 10^{-7}\text{ s} = 0.1\text{ }\mu\text{s}$。

        * 实际等待时延：$T_{\text{wait}} = 4 \times 512 \times 0.1\text{ }\mu\text{s} = 204.8\text{ }\mu\text{s}$。

        * 若带宽提升至 $100\text{ Mbps}$，位时变为 $0.01\text{ }\mu\text{s}$，相同 $K = 4$ 对应的等待物理时间成比例缩短为 $20.48\text{ }\mu\text{s}$。

### 随机接入信道利用率极值推导

* **时隙 ALOHA 极限吞吐率推导**

    * > **定义**：将时间离散化为固定帧长时隙的随机接入协议在极限网络规模下所能取得的最大信道吞吐率。

    * 系统成功发送概率函数（$n$ 个活跃节点，各节点发送概率为 $p$）：

        $$E(p) = n \cdot p(1 - p)^{n-1}$$

    * 求极值推导：

        $$\frac{dE(p)}{dp} = n(1 - p)^{n-2} (1 - np) = 0 \implies p^* = \frac{1}{n}$$

    * 极大值极限代入（节点数 $n \to \infty$）：

        $$\lim_{n \to \infty} E(p^*) = \lim_{n \to \infty} \left(1 - \frac{1}{n}\right)^{n-1} = \lim_{n \to \infty} \frac{\left(1 - \frac{1}{n}\right)^n}{1 - \frac{1}{n}} = \frac{1/e}{1} = \frac{1}{e} \approx 36.8\%$$

    * 纯 ALOHA（Pure ALOHA）易损时间窗口为时隙 ALOHA 的 2 倍，其极限吞吐率仅为 $\frac{1}{2e} \approx 18.4\%$。

### 差错控制机制与检错纠错边界

* **二维奇偶校验（Two-Dimensional Parity）**

    * > **定义**：将数据比特排布为矩阵并在每行末尾和每列末尾分别计算并附加奇偶校验位的差错控制机制。

    * 单比特翻转：同时引起对应行与对应列的校验出错，交点唯一锁定错误位置，具备**检错并自动纠错**能力。

    * 同行双比特翻转：行奇偶性不变但引起两列校验报警，能够**检错但无法纠错**。

    * 四比特矩形对偶翻转：四个错误位恰好构成矩形四角，所涉及的两行与两列各自翻转 2 比特，所有行列校验平衡不被破坏，系统**完全漏检**。

### 局域网寻址与ARP协议机制

* **地址解析协议（Address Resolution Protocol, ARP）**

    * > **定义**：在同一个物理子网广播域内部，依据目标主机的逻辑 IP 地址动态求解其硬件 MAC 地址的链路层辅助协议。

    * 报文时序交互：

        * 广播式查询：发送方广播 ARP 请求帧，目的 MAC 填入 `FF-FF-FF-FF-FF-FF`，携带目标 IP。

        * 单播式应答：目标节点确认 IP 匹配后，以单播帧将自身 MAC 地址直接回送给请求节点。

    * 广播作用域边界：路由器严禁转发 ARP 广播帧，ARP 广播严格阻断在单个广播域内部。

    * 软状态老化机制：ARP 表项设置生存时间定时器（通常 15~20 分钟），超时自动丢弃以适应网卡迁移。

    * 网卡物理唯一性准则：一台连接两独立子网的路由器，其两侧端口维护的 ARP 表中绝不可能出现相同的 MAC 地址。

### 跨子网多跳传输中的地址封装演化

* **多跳分组地址封装动态演进**

    * > **定义**：IP 分组穿越多个物理子网与路由器时，网络层首部与数据链路层首部的变换规律。

    * 传输拓扑模型：

        ```text
        [主机 A] --- 子网 1 --- [路由器 R1] --- 子网 2 --- [路由器 R2] --- 子网 3 --- [主机 F]
        ```

    * 首部地址演变规律：

        * 网络层（端到端不变）：源 IP 始终为 Host A，目的 IP 始终为 Host F。

        * 链路层（逐跳重写）：

            * 第 1 跳（子网 1）：源 MAC 为 Host A，目的 MAC 为 R1 端口 1。

            * 第 2 跳（子网 2）：源 MAC 为 R1 端口 2，目的 MAC 为 R2 端口 1。

            * 第 3 跳（子网 3）：源 MAC 为 R2 端口 2，目的 MAC 为 Host F。

### 交换机自学习算法与转发表维护

* **以太网交换机自学习算法**

    * > **定义**：交换机无需静态人工配置，依靠监听到达帧的入端口与源 MAC 地址自动构建转发表映射关系的即插即用机制。

    * 算法运行全时序判断流：

        ```text
        收到数据帧 (源 MAC: Src, 目的 MAC: Dst, 入端口: Port_in)
                    |
        [学习]: 在转发表记录/刷新 <Src, Port_in, TTL>
                    |
                    v
        转发表中是否存在 Dst 的表项?
                /     \
          是  /         \  否
            v             v
        Dst 所在端口 == Port_in ?   向除 Port_in 以外的所有端口泛洪 (Flooding)
            /   \
      是  /       \ 否
        v           v
    丢弃/过滤     向该指定端口单播转发
        ```

    * 多对一端口映射特性：交换机的一个物理端口允许关联转发表中的多个 MAC 地址（当下联级联交换机、集线器或无线 AP 时）。

### 虚拟局域网干线互联与单臂路由

* **虚拟局域网（Virtual Local Area Network, VLAN）**

    * > **定义**：在物理交换网络基础设施之上，通过软件配置构建相互逻辑隔离的独立广播域的技术。

    * IEEE 802.1Q 帧格式：在标准以太网源 MAC 与类型字段之间插入 4 字节的 802.1Q 垫层标签，内含 12 比特的 VLAN ID，支持 4096 个逻辑子网。

    * 干线端口（Trunk Port）拓扑计算铁律：跨越 $N$ 台交换机共享 $k$ 个独立的 VLAN，构建完全连通生成树至少需要 $N - 1$ 条链路；每条链路两端各占 1 个端口，总干线端口开销为：

        $$\text{干线端口总数} = 2 \times (N - 1)$$

    * 该端口消耗量与内部划定的 VLAN 数量 $k$ 毫无关系。

* **单臂路由（Router-on-a-Stick）**

    * > **定义**：路由器仅通过单根物理干线链路与核心交换机互联，实现跨 VLAN 子网间三层路由转发的经典工程架构。

    * 运行机理：物理网卡配置逻辑子接口（Sub-interfaces，如 `eth0.10`、`eth0.20`）；子接口共享相同的物理 MAC 并打上对应 VLAN ID 标签，解封装后由路由引擎完成跨子网转发并重新打标送出。

### Web首包访问全协议栈时序协同

* **Web 访问全栈交互时序模型**

    * > **定义**：未配置主机从物理连入局域网到浏览器呈现远程网页首对象的全协议栈跨层协同步骤。

    * 协同演化全时序图：

        ```text
        [阶段一: 参数自配置]
          Host ---> 广播 DHCP Discover (源IP: 0.0.0.0, 目的IP: 255.255.255.255)
          Host <--- 接收 DHCP ACK (注入本机IP、子网掩码、默认网关IP、本地DNS服务器IP)

        [阶段二: 域名解析]
          Host 通过子网掩码判定 DNS 服务器位置，发 ARP 获取本地网关/DNS的 MAC
          Host 发送 DNS 查询报文，本地 DNS 服务器递归/迭代解析返回 Web 服务器 IP

        [阶段三: 网关定位]
          Host 判定目标 Web 服务器位于跨网段外网，广播 ARP 查询默认网关 MAC
          默认网关单播回应自身 MAC 地址

        [阶段四: TCP 握手]
          Host 发送 TCP SYN (目的IP为Web服务器, 目的MAC为默认网关MAC)
          经历逐跳路由，服务器响应 SYN-ACK，Host 回应 ACK，TCP 连接确立

        [阶段五: HTTP 交互]
          Host 发送 HTTP GET / 报文
          服务器响应 HTTP 200 OK 并交付 HTML 网页文本
        ```

## 网络安全机理与公钥密码计算

### 安全属性解耦与密码体制对比

* **网络安全三大属性解耦**

    * > **定义**：机密性（Confidentiality）、报文完整性（Message Integrity）与端点认证性（Authentication）在密码学机制上的相互独立性。

    * 私密而不完整：报文经强对称加密发送，信道攻击者虽无法破解内容，但蓄意截断或篡改局部比特，接收端解密失败，机密性完备而完整性丧失。

    * 完整而不私密：明文传输并在文末追加私钥数字签名，内容对全网公开，但任何第三方均无法在不破坏签名验证的前提下更改字符，完整性完备而机密性为零。

* **密码体制对比与混合加密**

    * > **定义**：对称密钥体制与公开密钥体制的工程权衡及其在实用安全传输协议中的复合设计。

    * 体系比对矩阵：

        | 密码体制 | 密钥特征 | 计算效率与吞吐 | 核心工程痛点 | 适用场景 |
        | :--- | :--- | :--- | :--- | :--- |
        | **对称密钥体制**（AES、DES） | 加解密共用同一密钥（$K_A = K_B$） | 计算极快，硬件加速支持，高吞吐 | 密钥分发极其复杂，两两共享需 $O(N^2)$ 密钥对 | 大宗载荷加密、实时流数据保护 |
        | **公开密钥体制**（RSA、ECC） | 密钥公私成对（$K^+ \neq K^-$） | 模幂大数运算，耗费算力，吞吐极低 | 无法承担大文件加解密计算开销 | 数字签名、身份认证、会话密钥协商 |

    * 混合加密体系（Hybrid Cryptosystem）：每次通信随机生成临时对称会话密钥（$K_S$），用加解密极快的 $K_S$ 加密大宗有效数据；仅用接收方公钥加密短小的 $K_S$ 本身，兼顾安全性与线速吞吐。

### 报文摘要与数字证书信任链

* **密码学哈希函数（Cryptographic Hash Function）**

    * > **定义**：将任意长度输入消息映射为固定长度报文摘要（Message Digest）的单向数学函数，具备单向不可逆性与强抗碰撞性。

    * 数字签名标准操作：发送方使用自身私钥对**报文摘要**进行加密签名（$S = K_A^-(H(m))$），严禁对超长报文全文直接执行非对称加密。

* **证书认证机构（Certification Authority, CA）与信任链**

    * > **定义**：负责将公钥与其合法所有者真实身份进行权威绑定的受信任第三方机构及其数字签名架构。

    * 证书签名机理：CA 对包含用户身份、有效期限与绑定公钥的证书结构文本计算哈希摘要，并**使用 CA 自己的私钥**对该摘要进行加密，生成作为防伪标记的数字指纹（Fingerprint）。

    * > **易错点**：⚠️ CA 绝非对用户公钥证书全文进行公钥加密，而是用 CA 私钥对证书的哈希摘要进行数字签名；客户端利用预置的 CA 公钥解密指纹即可核验真伪。

### RSA公钥密码体制数学推导与计算

* **RSA 算法参数生成与加解密法则**

    * > **定义**：基于大整数素因数分解数学难题构建的非对称密码体制。

    * 密钥生成与验证流程：

        1. 选取两个独立大质数 $p$ 与 $q$（如取 $p = 5, q = 11$）。

        2. 计算模数 $n = p \times q = 5 \times 11 = 55$。

        3. 计算欧拉函数 $z = (p - 1)(q - 1) = 4 \times 10 = 40$。

        4. 选取公开加密指数 $e$，满足 $\gcd(e, z) = 1$（如选取 $e = 3$，满足 $\gcd(3, 40) = 1$）。

        5. 求解私有解密指数 $d$，满足模反元素同余方程：

            $$e \times d \equiv 1 \pmod z \implies 3d - 1 = k \times 40$$

            取 $k = 2$ 时，$3d = 81 \implies d = 27$。公钥为 $(n=55, e=3)$，私钥为 $(n=55, d=27)$。

        6. 加密计算（明文 $m = 8$）：

            $$c = m^e \bmod n = 8^3 \bmod 55 = 512 \bmod 55 = 17$$

        7. 解密计算（密文 $c = 17$）：

            $$m = c^d \bmod n = 17^{27} \bmod 55 = 8$$

### PGP安全邮件解密与认证时序

* **Pretty Good Privacy（PGP）**

    * > **定义**：整合非对称加密、对称会话密钥与数字签名的安全电子邮件工业级密码协议。

    * 接收端处理全时序：

        ```text
        收到的混合邮件密包: [ K_B^+(K_S) ] + [ K_S( m + K_A^-(H(m)) ) ]
                                  |
                                  v
        第一步: Bob 使用自身私钥解密提取会话密钥:
                K_B^-( K_B^+(K_S) ) ======> 还原出 K_S
                                  |
                                  v
        第二步: Bob 使用 K_S 对称解密邮件主体载荷:
                K_S 解密           ======> 获得明文 m 及 Alice 签名 S = K_A^-(H(m))
                                /          \
                              /              \
                            v                  v
        第三步: 本地重新计算哈希:              第四步: 使用 Alice 公钥解密验证签名:
                H_local = H(m)                         H_signed = K_A^+( S )
                            \                  /
                              \              /
                                v          v
        第五步: 比对哈希值:
                H_local == H_signed ?
                - 吻合: 认证通过 (发件人身份真实) 且 完整性通过 (邮件未遭篡改)
                - 不符: 报文损坏或被中间人恶意篡改
        ```
