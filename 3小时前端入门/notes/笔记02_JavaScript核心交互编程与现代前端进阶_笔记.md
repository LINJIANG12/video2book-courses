# JavaScript核心交互编程与现代前端进阶

## CSS定位机制与文档流控制

### 相对定位
* **相对定位（Relative Positioning）**

    * > **定义**：相对于元素在普通文档流中的原始物理位置进行坐标偏移的定位模式。

    * 声明语法：`position: relative;`。

    * 文档流特性：绝对不脱离正常文档流，元素在文档中的原始物理占位严格保留，后序同级元素位置保持不动。

    * 偏移控制规则：未声明偏移量时视觉无变化；`left` 表示向右偏移，`right` 表示向左偏移，`top` 表示向下偏移，`bottom` 表示向上偏移。

    * 典型应用场景：元素微观位置微调、作为绝对定位子元素的定位参考容器。

### 绝对定位
* **绝对定位（Absolute Positioning）**

    * > **定义**：完全脱离正常文档流，依据就近定位祖先元素进行坐标偏移的定位模式。

    * 声明语法：`position: absolute;`。

    * 文档流特性：完全脱离正常文档流，不再占据原有空间，后序同级元素自动上浮填补空间空隙。

    * 定位基准规则：遵循“就近定位祖先”原则，相对于最近的 `position` 属性值不为 `static` 的父级或祖先元素进行偏移；若所有祖先元素均未设置定位，基准退化为 HTML 根标签。

    * > **易错点**：⚠️ 绝对定位元素脱离文档流后原有占位释放，后序元素自动上浮顶替重叠，易引发后序元素被遮挡掩盖的“凭空消失”假象。

    * 典型应用场景：下拉菜单浮层、弹窗遮罩、复杂图文叠放。

### 固定定位
* **固定定位（Fixed Positioning）**

    * > **定义**：完全脱离正常文档流，直接相对于浏览器视口窗口进行坐标定位的模式。

    * 声明语法：`position: fixed;`。

    * 视口基准特性：定位参照物唯一锁定为浏览器视口（Viewport），无论页面如何滚动，元素始终停留在屏幕窗口的固定坐标处。

    * 文档流特性：完全脱离正常文档流，原有物理占位被彻底释放。

    * 典型应用场景：网页顶部常驻导航栏、右侧悬浮挂件、客服咨询入口、返回顶部控制按钮、吸底操作栏。

### 定位模式综合对比
* **定位机制核心差异矩阵**

    * 相对定位、绝对定位与固定定位的关键技术参数对比：

    | 定位模式 | 声明语法 | 是否脱离文档流 | 定位参照对象 | 典型应用场景 |
    | :--- | :--- | :--- | :--- | :--- |
    | **相对定位** | `position: relative;` | 否（原物理占位保留） | 元素在文档流中的正常原位 | 元素位置局部微调、作为绝对定位的父级容器 |
    | **绝对定位** | `position: absolute;` | 是（原有占位被释放） | 最近的已定位祖先元素，无则退化为 HTML 标签 | 复杂图文重叠、下拉菜单浮层、弹窗组件 |
    | **固定定位** | `position: fixed;` | 是（原有占位被释放） | 浏览器视口窗口本身 | 顶部固定导航栏、屏幕侧边栏挂件、吸底操作栏 |

## JavaScript语言特性与运行环境

### 语言定位与执行环境
* **JavaScript（JavaScript，JS）**

    * > **定义**：一种轻量级、解释型、面向对象的脚本语言。

    * 语言从属关系：JavaScript 与 Java 没有任何技术依赖或衍生关系，命名源于历史商业推广策略。

    * 执行架构范式：由浏览器脚本引擎或服务端运行时自上而下逐行解释执行，无需预编译。

    * 三大主流运行场景：
        * 客户端脚本：直接嵌入网页并在浏览器端运行，负责界面动效、事件捕获与动态交互。
        * 现代网页开发：与 HTML、CSS 协同，结合数据驱动与异步请求提供富交互体验。
        * 后端服务端开发：依托 Node.js 运行环境脱离浏览器限制，承接网络请求并读写数据库。

### 脚本加载机制
* **内联脚本与外联脚本（Inline & External Scripts）**

    * > **定义**：网页装载与执行 JavaScript 代码的组织与引用机制。

    * 内联脚本规则：代码书写在 `<script>` 标签对内部，可放置于 `<head>` 或 `<body>` 中。

    * 外联脚本规则：通过 `<script src="路径"></script>` 引入独立的 `.js` 逻辑文件。

    * 标签执行互斥边界：一旦 `<script>` 标签指定了 `src` 属性，标签内部书写的内联代码将被浏览器直接忽略。

    * 顺序解析机理：浏览器解析 HTML 文档时遵循自上而下物理顺序读取并同步阻塞执行脚本。

### 调试与输出控制
* **控制台输出与模态交互（Console & Alert）**

    * > **定义**：运行时代码调试信息输出与阻断式用户交互提示的接口。

    * `console.log()`：向浏览器开发者工具的 Console 面板打印调试日志、对象结构及计算结果。

    * `alert()`：向浏览器窗口弹出模态警告对话框，阻断后续 DOM 解析与页面渲染直到用户手动确认。

    * 开发者工具操作：桌面端通用快捷键为 `F12`，或右键检查切换至控制台。

## 变量声明与基础数据类型

### 变量与常量声明关键字
* **声明关键字（var, let, const）**

    * > **定义**：在程序执行上下文中分配内存存储空间并绑定变量标识符的语言关键字。

    * `var`：传统变量声明关键字，具备函数作用域，存在变量提升。

    * `let`：现代块级变量声明关键字，作用域受限于 `{}` 代码块内部，具备暂时性死区，无变量提升。

    * `const`：常量声明关键字，声明时必须赋予初始值，赋值后在生命周期中不可重新赋值，重复赋值抛出类型异常。

    * 工业规范：统一优先选用 `let` 与 `const`，全面规避 `var` 以消除全局污染与状态逃逸。

### 作用域与提升机制
* **变量提升与暂时性死区（Hoisting & Temporal Dead Zone，TDZ）**

    * > **定义**：JavaScript 引擎在预编译阶段对声明语句的处理策略所引发的生命周期现象。

    * `var` 变量提升规则：变量声明被提升至函数或全局作用域顶部，声明语句前访问返回 `undefined`。

    * `let` 与 `const` 块级作用域规则：变量生命周期严格受限于声明所在的大括号块，声明前存在暂时性死区，提前访问直接抛出引用错误。

### 基础数据类型与缺失值辨析
* **基础数据类型（Primitive Data Types）**

    * > **定义**：JavaScript 底层直接存储在栈内存中的基本数据形态。

    * 数值型（Number）：底层统一处理整数与浮点数（如 `5`、`3.14`）。

    * 字符串型（String）：使用单引号或双引号包裹的文本序列（如 `"如花"`）。

    * 未定义型（Undefined）：变量已声明但尚未被赋予初始值的系统默认状态。

    * 空值对象（Null）：由开发者主动显式赋值为空的特殊对象引用标记。

* **缺失值语义对比矩阵**

    * `undefined` 与 `null` 的核心语义与生命周期对比：

    | 标识符 | 核心语义 | 产生机制 | 典型应用场景 |
    | :--- | :--- | :--- | :--- |
    | **`undefined`** | 未定义状态 | 变量声明未初始化；访问不存在的对象属性；函数无显式 return | 标识变量尚未就绪的系统初始默认态 |
    | **`null`** | 空对象引用 | 开发者主动、显式赋值 | 明确释放对象内存引用，或表示该变量暂不指向有效对象 |

## 程序控制流与循环结构

### 条件分支语句
* **条件控制流（if...else if...else）**

    * > **定义**：依据布尔表达式判断结果决定程序执行路径的控制结构。

    * 单向分支：`if (condition)`，条件为真时执行代码块。

    * 多重备选：`else if (condition)`，前置条件为假时顺延匹配下一条件分支。

    * 最终兜底：`else`，全部前置条件为假时执行，单条条件链中 `if` 与 `else` 仅允许存在一个。

    * 语法约束：小括号、大括号与引号必须严格使用半角英文标点符号。

### 循环结构与迭代控制
* **循环结构（for & while）**

    * > **定义**：按预设终止条件重复执行指定逻辑块的流程控制结构。

    * `for` 循环三段式：包含初始化表达式（如 `let i = 1`）、终止条件判定（如 `i <= 10`）与步进器（如 `i++`）。

    * `while` 循环：仅依据单一条件真假决定是否执行，循环计数变量需在外部声明，步进运算必须在循环体内手动推进。

    * > **易错点**：⚠️ `while` 循环体内部若遗漏手动推进迭代变量（如 `count++`），将导致判定条件永久为真引发无限死循环，锁死浏览器主线程并造成页面崩溃或 CPU 满载。

### 循环跳转指令
* **循环中断指令（break & continue）**

    * > **定义**：在循环体执行过程中强行变更迭代进程的控制指令。

    * `break`：立即强行中断并跳出整层循环，废弃循环体内后续代码及未执行的全部后续迭代。

    * `continue`：仅跳过当前轮次剩余代码，直接推进至下一轮迭代的条件判定与步进环节。

## 函数声明与作用域隔离

### 函数定义与参数传递
* **函数（Function）**

    * > **定义**：封装特定业务逻辑并提供重复调用能力的独立代码复用单元。

    * 声明语法：
        ```text
        function 函数名(参数1, 参数2, ...) {
            // 函数体
            return 返回值;
        }
        ```

    * 激活机理：函数定义后不会自发执行，必须通过 `函数名()` 带圆括号形式完成显式调用。

    * 参数传递机理：形参（Parameter）为函数定义中的占位符，实参（Argument）为调用时实际传入的具体数值。

    * 返回值处理：`return` 关键字将计算结果回传至调用方；未声明 `return` 时函数默认返回 `undefined`。

### 作用域边界
* **全局作用域与局部作用域（Global Scope & Local Scope）**

    * > **定义**：决定变量标识符有效可访问范围与生命周期的空间边界。

    * 全局作用域：在函数体外部声明的变量，生命周期与页面运行周期一致，全局与函数内部皆可直接读写。

    * 局部作用域：在函数体内声明的变量，仅在当前函数内部可访问，函数执行完毕后作用域封闭。

    * 越界报错规则：在全局作用域中强制读取函数内部局部变量，运行时直接抛出引用异常 `Uncaught ReferenceError: 变量名 is not defined`。

## 事件驱动模型与事件绑定

### 常用交互事件类型
* **事件驱动模型（Event-Driven Model）**

    * > **定义**：在文档或浏览器视口中捕获瞬间状态变化并驱动对应逻辑函数执行的编程范式。

    * 核心高频事件属性与触发条件：

    | 事件属性名 | 对应原生事件 | 触发时机与语义 | 典型应用场景 |
    | :--- | :--- | :--- | :--- |
    | `onclick` | `click` | 鼠标指针左键点击某个元素瞬间 | 按钮提交、链接跳转、模态框呼出 |
    | `onmouseover` | `mouseover` | 鼠标光标移入元素的外边界内 | 下拉菜单悬停展开、卡片高亮浮起 |
    | `onmouseout` | `mouseout` | 鼠标光标从元素内移出边界外 | 菜单收起、恢复卡片原本阴影样式 |
    | `onchange` | `change` | 表单输入控件的值发生改变且失去焦点 | 下拉框切换选中项、复选框状态改变 |
    | `onselect` | `select` | 文本输入框中的文本内容被光标选中 | 快捷复制内容、选中文本高亮分析 |
    | `onfocus` | `focus` | 文本框等输入控件获得光标焦点 | 输入框聚焦边框变色、展示输入提示信息 |
    | `onblur` | `blur` | 文本框等输入控件失去光标焦点 | 表单实时离焦格式验证、密码强度检验 |

### 事件绑定机制
* **HTML行内绑定与DOM对象监听**

    * > **定义**：将用户行为事件与处理函数进行关联挂载的技术手段。

    * HTML 标签行内绑定：直接在标签属性中声明事件属性（如 `<button onclick="click_event()">`），一个元素允许并列声明多个不同事件属性。

    * DOM 属性绑定：通过脚本获取节点后为事件属性赋予匿名函数（如 `element.onclick = function() { ... };`）。

    * `addEventListener` 监听器绑定：通过 `element.addEventListener("事件类型", 回调函数)` 挂载。

    * 监听器传参规则：事件类型字符串严禁带有 `on` 前缀（如点击必须传 `"click"`）；第二个参数传入已命名函数时仅写函数名，严禁添加圆括号 `()`。

## 文档对象模型与节点操作

### 文档树层次与节点类型
* **文档对象模型（Document Object Model，DOM）**

    * > **定义**：浏览器解析 HTML 后在内存中构建的倒置树状编程接口，提供面向对象的页面增删改查能力。

    * 对象构成模型：对象包含存储状态的属性与执行行为的方法，调用规范为 `对象.属性名` 与 `对象.方法名()`。

    * 四大核心节点分类：
        * 文档节点（Document Node）：整棵树的根基点，在全局体现为 `document` 对象。
        * 元素节点（Element Node）：HTML 页面中的全部标签实体（如 `<div>`、`<h1>`、`<table>`）。
        * 属性节点（Attribute Node）：标签内部包含的修饰属性（如 `class`、`id`、`src`）。
        * 文本节点（Text Node）：双标签内部包裹呈现的字符实体内容。

### 元素节点查询接口
* **DOM元素查询API**

    * > **定义**：在内存文档树中检索并锁定特定元素节点实例的方法集合。

    * `document.getElementById("id")`：根据唯一 ID 获取单一元素节点。

    * `document.getElementsByClassName("class")`：根据类名匹配并返回 `HTMLCollection` 类数组集合。

    * `document.getElementsByTagName("tag")`：根据标签名称按文档物理先后顺序匹配并返回 `HTMLCollection` 类数组集合。

    * > **易错点**：⚠️ `document.getElementsByClassName()` 与 `document.getElementsByTagName()` 返回的是包含多个节点的 `HTMLCollection` 类数组集合，即便仅匹配一个元素也必须通过索引下标（如 `[0]`）提取具体节点后方可操作。

### 节点内容更新与标签解析
* **文本内容更新（innerHTML & innerText）**

    * > **定义**：读写指定 DOM 元素内部所包裹的内容字符串的属性接口。

    * > **易错点**：⚠️ `innerHTML` 与 `innerText` 均为 DOM 对象的普通属性而非函数方法，必须通过等号赋值修改；若加圆括号按函数调用（如 `element.innerHTML("...")`）会触发运行时类型异常。

    * 内容属性解析特性差异对比：

    | 内容属性 | 标签解析能力 | 处理机制与安全性 |
    | :--- | :--- | :--- |
    | **`innerHTML`** | 能够解析字符串中的 HTML 标记与标签语义 | 将字符串解析为真正的 DOM 子元素树并完成渲染，适用于动态装配富文本与组件结构 |
    | **`innerText`** | 忽略并不解析 HTML 标记 | 将传入的一切内容无差别视为纯文本字符，自动忽略或转义 HTML 标记，安全性更高 |

### 节点行内样式修改
* **行内样式操作（element.style）**

    * > **定义**：通过 DOM 节点的 `style` 对象动态分配 CSS 声明的接口。

    * 样式优先级：经由 `style` 属性赋予的规则属于行内样式（Inline Style），具备最高层级的渲染优先级。

    * 命名转换规则：多词复合属性在 JavaScript 中转化为小驼峰命名法（如 CSS `font-size` 对应 JS `fontSize`）。

## 动态表格增删改查实战

### 表格布局与边框合并
* **表格结构与边框合并（border-collapse）**

    * > **定义**：消除表格相邻单元格之间的渲染间距并将双重边框折叠为单线的 CSS 属性。

    * 宽度响应式配置：`table` 声明 `width: 100%;`，使表格自适应占满父容器视口。

    * 十六进制颜色缩写：三位十六进制 `#ddd` 等价于标准六位十六进制 `#dddddd`。

    * 边框折叠声明：`border-collapse: collapse;`，浏览器将相邻单元格边框强制合并为单一直线。

    * 布局微调规则：`td` 显式声明 `text-align: center;` 统一文本居中，配合 `padding: 8px;` 撑开内边距。

### 动态行与列节点装配
* **表格节点动态插入（insertRow & insertCell）**

    * > **定义**：在现有表格 DOM 节点上动态生成并挂载行和列的高层专属 API。

    * 行装配流程：
        * 通过 `table.rows.length` 获取当前表格存在的 `<tr>` 节点总数作为物理插入索引。
        * 调用 `table.insertRow(index)` 在末尾插入全新 `<tr>` 节点。
        * 在新行上依次调用 `new_row.insertCell(colIndex)` 插入姓名列、电话列及操作列 `<td>`。
        * 通过 `innerHTML` 挂载文本及包含行内事件的 `<button>` 元素。

    * 底层通用 API 对应关系：等效于 `document.createElement("tr")`、`document.createElement("td")` 与 `parentElement.appendChild()` 的级联调用。

### 上下文指针与父节点溯源删除
* **上下文指针（this）与节点向上溯源**

    * > **定义**：`this` 始终指向当前函数执行的上下文对象；在 HTML 行内事件属性中，`this` 严格指向触发当前事件的原生 DOM 元素。

    * DOM 树向上回溯层级：
        * `button`：触发事件的原生按钮节点。
        * `button.parentNode`：直接包裹按钮的单元格节点 `<td>`。
        * `button.parentNode.parentNode`：包裹单元格的完整数据行节点 `<tr>`。

    * > **易错点**：⚠️ DOM 元素节点无法直接调用方法自我销毁，必须遵循父节点寻址原则，通过父级节点调用 `removeChild()` 剔除目标子节点。

    * 节点删除执行公式：
        $$\text{parentNode.removeChild(childNode)}$$

    * 整行删除实现表达式：
        ```javascript
        var row = button.parentNode.parentNode;
        row.parentNode.removeChild(row);
        ```

### 单元格数据提取与交互编辑
* **行单元格集合与阻塞式输入（cells & prompt）**

    * > **定义**：利用行原生单元格集合精确定位数据列，并借助浏览器模态输入框完成数据变更。

    * `row.cells`：数据行对象原生的有序单元格集合，`row.cells[0]` 对应姓名列，`row.cells[1]` 对应联系方式列。

    * `window.prompt(message, defaultValue)`：调用同步阻塞式输入对话框；确定返回用户输入文本，取消返回 `null`。

    * 健壮性防御边界：必须加入空值判别 `if (input !== null && input.trim() !== "")`，防止用户取消或未输入时将原内容覆盖为 `"null"` 或清空。

## 移动端视口机制与等比缩放适配

### 移动端调试与仿真环境
* **移动设备仿真器（Device Mode）**

    * > **定义**：浏览器开发者工具中用于模拟不同移动终端视口尺寸与屏幕特性的仿真运行环境。

    * 面板停靠布局：移动端调试推荐停靠在右侧（Dock to right），左侧纵向区域匹配手机屏幕形态。

    * 核心仿真控制参数：设备机型预设、逻辑分辨率读数（如 390 × 844）、缩放比率（Zoom）、横竖屏旋转（Rotate）。

    * 跨设备适配两大主流方案对比：

    | 适配方案 | 核心技术载体 | 运作机理与特征 | 典型应用场景 |
    | :--- | :--- | :--- | :--- |
    | **等比缩放方案** | `rem` 相对长度单位<br>视口单位（`vw` / `vh`） | 页面元素排版拓扑固定，所有尺寸数值跟随屏幕物理宽度按严格数学比例等比缩放 | 电商移动端页面、内容展示类移动 Web 站点 |
    | **媒体查询响应式方案** | CSS3 媒体查询（`@media`） | 维持一套 DOM 结构不变，针对不同屏幕断点分别加载多套独立样式规则，实现布局形态重构 | 官方教程网站、技术文档中心、企业门户官网 |

### 视口元标签与缩放控制
* **视口（Viewport）与元标签配置**

    * > **定义**：浏览器用于实际渲染呈现网页内容的可见屏幕几何区域。

    * 默认虚拟视口机理：若缺失 Viewport 声明，移动端浏览器默认启用 `980px` 虚拟视口排版，再强行压缩至手机物理屏幕，造成界面极度缩小与失真。

    * 标准移动端配置声明：
        ```html
        <meta name="viewport" content="width=device-width, initial-scale=1.0, minimum-scale=1.0, maximum-scale=1.0, user-scalable=no">
        ```

    * 关键参数规则：
        * `width=device-width`：将渲染视口宽度强行对齐设备的真实物理逻辑宽度。
        * `initial-scale=1.0`：设定初始载入缩放比率为 100% 原始比例。
        * `minimum-scale=1.0` 与 `maximum-scale=1.0`：限定手势缩放的极限倍率范围。
        * `user-scalable=no`：禁止用户通过双指手势缩放页面，锁定类似原生 App 的固定视窗形态。

### 长度单位与参考基准差异
* **绝对单位与相对单位（px, em, rem）**

    * > **定义**：CSS 中用于度量几何长度与字体大小的度量单位。

    * 像素 `px`：绝对长度单位，数值定死无法感知设备屏幕变化。

    * 相对单位 `em`：相对于当前元素自身（或继承父级）的 `font-size`，深层嵌套下产生连乘放大效应。

    * 根相对单位 `rem`（Root em）：换算基准唯一锁定最外层 `<html>` 根标签的 `font-size`。

    * 浏览器默认基准换算关系：
        $$1\text{rem} = 16\text{px}$$

    * 动态适配前提：若根元素字体大小设为静态常数，`rem` 将失去适配能力；根字体必须跟随屏幕物理宽度实时动态求值。

### 根字体动态计算与尺寸监听
* **基于屏幕宽度的动态字体计算模型**

    * > **定义**：借助 JavaScript 动态测量屏幕宽度并重算根元素字体大小以构建等比缩放基准的算法。

    * 算法基准公式：
        $$\text{html.fontSize} = \frac{\text{screen.width}}{10} + \text{"px"}$$

    * 映射数学关系：
        $$1\text{rem} = 0.1 \times \text{screen.width}$$
        $$\text{Width} = 5 \times 1\text{rem} = 0.5 \times \text{screen.width}$$

    * 动态赋值语句：
        ```javascript
        document.documentElement.style.fontSize = (screen.width / 10) + "px";
        ```

    * 视口变动监听规则：必须绑定 `window.onresize = reset_html_font_size;`，以捕获横竖屏切换与窗口拉伸事件并重新计算。

    * 主流机型实测数据推导表：

    | 测试设备型号 | 设备视口宽度（Logic Width） | 动态计算出的根字体（html font-size） | 5rem 盒子实际渲染像素宽度 | 占当前屏幕宽度比例 |
    | :--- | :--- | :--- | :--- | :--- |
    | **iPhone SE** | 375px | $375 \div 10 = \mathbf{37.5\text{px}}$ | $5 \times 37.5\text{px} = \mathbf{187.5\text{px}}$ | 50.0% |
    | **iPhone 12 Pro** | 390px | $390 \div 10 = \mathbf{39.0\text{px}}$ | $5 \times 39.0\text{px} = \mathbf{195.0\text{px}}$ | 50.0% |
    | **iPhone 14 Pro Max** | 430px | $430 \div 10 = \mathbf{43.0\text{px}}$ | $5 \times 43.0\text{px} = \mathbf{215.0\text{px}}$ | 50.0% |
    | **Surface Pro 7** | 912px | $912 \div 10 = \mathbf{91.2\text{px}}$ | $5 \times 91.2\text{px} = \mathbf{456.0\text{px}}$ | 50.0% |

## 弹性盒布局模型

### 弹性容器与双轴坐标系统
* **弹性盒布局（Flexible Box Layout，Flexbox）**

    * > **定义**：通过定义容器与项目的伸缩行为实现高效自适应空间分配与对齐的现代 CSS 布局模型。

    * 上下文激活：声明 `display: flex;`（块级弹性盒）或 `display: inline-flex;`（行内弹性盒）。

    * 角色职责分工：
        * 弹性容器（Flex Container）：声明了 flex 样式的父级元素。
        * 弹性项目（Flex Item）：弹性容器的直接子元素，原有块级独占一行或行内不可设宽高的特性转为受弹性盒规则支配。

    * 双轴正交坐标体系：
        * 主轴（Main Axis）：弹性项目排列的主要轴线，默认沿水平方向。
        * 交叉轴（Cross Axis）：垂直于主轴的副轴线，默认沿垂直方向。
        * 起点与终点：主轴起点（main start）与终点（main end），交叉轴起点（cross start）与终点（cross end）。
        * 项目尺寸度量：项目在主轴方向占据的尺寸称为 main size，在交叉轴方向占据的尺寸称为 cross size。

### 主轴方向与换行策略
* **主轴朝向与轴线折叠（flex-direction & flex-wrap）**

    * > **定义**：定义弹性项目在容器内排列的主轴线方向以及空间不足时的换行折叠策略。

    * `flex-direction` 取值规则：
        * `row`（默认值）：主轴为水平方向，起点在容器左端，项目自左向右排列。
        * `row-reverse`：主轴为水平方向，起点在容器右端，项目自右向左反向排列。
        * `column`：主轴为垂直方向，起点在容器顶端，项目自上向下排列。
        * `column-reverse`：主轴为垂直方向，起点在容器底端，项目自下向上反向排列。

    * `flex-wrap` 取值规则：
        * `nowrap`（默认值）：不换行，所有项目挤压在单根轴线上，尺寸自动被压缩收缩。
        * `wrap`：换行，单行排满后多余项目折入下一行（水平主轴向下换行，垂直主轴向右换列）。
        * `wrap-reverse`：反向换行，多余项目向相反方向折叠排列。

    * 复合简写：`flex-flow: <flex-direction> <flex-wrap>;`（如 `flex-flow: row wrap;`）。

### 主轴空间分配与对齐
* **主轴富余空间对齐（justify-content）**

    * > **定义**：当项目尺寸总和未填满整根主轴时，用于定义富余空白空间分配方式的属性。

    * 对齐取值特性矩阵：

    | 对齐属性值 | 首尾项目与容器边框的距离 | 相邻项目之间的间隙距离 | 视觉核心特征 |
    | :--- | :--- | :--- | :--- |
    | **`flex-start`** | $0$（靠起点顶格） | $0$（各项目紧贴） | 剩余空白空间全部留置在主轴尾端 |
    | **`flex-end`** | 剩余全部空间 | $0$（各项目紧贴） | 剩余空白空间全部留置在主轴前端 |
    | **`center`** | 剩余空间的 $1/2$ | $0$（各项目紧贴） | 所有项目向主轴中央居中聚集 |
    | **`space-between`** | $0$（紧贴边框） | 剩余空间在 $N-1$ 个间隙中均分 | 首尾项目顶格边框，中间空白均等平分 |
    | **`space-around`** | 设为 $x$（单侧留白） | $2x$（两倍于两端留白） | 每个项目两侧分配相等间距，中间间隙为两端 2 倍 |
    | **`space-evenly`** | 设为 $x$ | $x$（与两端留白完全相等） | 所有间隙及两端到边框的间距绝对相等 |

### 交叉轴对齐与多轴线控制
* **交叉轴单轴与多轴线对齐（align-items & align-content）**

    * > **定义**：定义弹性项目在垂直于主轴的交叉轴方向上的对齐与间隙分布规则。

    * 单轴线对齐属性 `align-items`（作用于单条轴线内部）：
        * `stretch`（默认值）：若项目未设高度（或为 `auto`），拉伸填满整个容器在交叉轴上的可用空间。
        * `flex-start`：项目向交叉轴起点对齐。
        * `flex-end`：项目向交叉轴终点对齐。
        * `center`：项目在交叉轴上居中对齐。
        * `baseline`：项目依据内部第一行文字的文本基线对齐。

    * 多轴线全局对齐属性 `align-content`：
        * 生效前提：必须显式开启换行（`flex-wrap: wrap` 或 `wrap-reverse`），且实际排版中已产生两根或以上轴线。
        * 行为机制：将所有轴线作为一个整体在交叉轴上进行空间分配（如 `align-content: center` 将整组轴线整体居中，消除多行之间的默认均分空隙）。
        * 取值集合：`flex-start`、`flex-end`、`center`、`space-between`、`space-around`、`space-evenly`、`stretch`。

### 项目伸缩弹性属性
* **项目伸缩控制（flex-grow, flex-shrink, flex-basis, flex）**

    * > **定义**：作用于弹性项目本身，用于精细分配主轴多余空间或承担空间不足挤压的属性。

    * `flex-grow`：项目的放大比例。默认值为 `0`（有剩余空间也不放大）；设为 `1` 时吸收剩余空间等比放大。

    * `flex-shrink`：项目的缩小比例。默认值为 `1`（主轴空间不足且不换行时等比收缩）；设为 `0` 时禁止压缩，保持原始尺寸。

    * `flex-basis`：分配多余空间前项目在主轴上占据的基准尺寸，默认值为 `auto`。

    * 复合简写 `flex`：
        ```css
        flex: <flex-grow> <flex-shrink> <flex-basis>;
        ```
        默认值为 `0 1 auto`；高频工程简写为 `flex: 1;`（等价于 `1 1 0%`），用于均分容器剩余主轴空间。

## 现代前端进阶与跨端开发

### 组件化与数据驱动视图框架
* **前端框架进阶（Vue.js）**

    * > **定义**：用于构建交互式用户界面的渐进式 JavaScript 框架。

    * 核心范式演进：通过“数据驱动视图”的双向绑定与虚拟 DOM 机制，消除原生频繁调用 DOM 查询与手动拼接字符串的繁琐操作，实现修改数据变量即自动刷新对应局部视图。

    * 学习生态优势：作者为华人，官方提供高水准全中文技术文档，学习曲线平缓，社区生态完备。

### 小程序生态与跨端开发架构
* **多端跨平台开发体系（WeChat Mini Programs & uni-app）**

    * > **定义**：面向移动生态免安装轻量应用与一套代码编译部署到多终端的现代开发架构。

    * 移动端原生开发痛点：iOS（Swift/Objective-C）与 Android（Kotlin/Java）需多语言分别编写维护，机型碎片化适配成本高，应用商店下载安装门槛制约推广。

    * 微信小程序特性：无需安装、即用即走、体积轻量，直接抹平底层操作系统差异，深度接入微信社交与支付生态。

    * `uni-app` 跨端架构：基于 Vue.js 语法体系编写业务源码，通过编译器流水线一键编译发布至微信/支付宝/百度/抖音等各大小程序平台、移动 Web（H5）以及打包为 iOS/Android 原生应用程序，实现“一套代码，多端运行”。

    * 进阶路径非线性原则：前端基础掌握后，Vue.js、微信小程序与 uni-app 之间不存在单一绝对的先后依赖关系，开发者可根据业务形态与技术目标自主选择切入路径。
