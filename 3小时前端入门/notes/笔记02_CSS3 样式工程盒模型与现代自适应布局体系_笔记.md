# CSS3 样式工程、盒模型与现代自适应布局体系

## 样式工程基础与导入层叠机制

### 样式规则构成与语法规范
* **层叠样式表（Cascading Style Sheets，CSS）**

    * > **定义**：用于定义 HTML 结构在屏幕、纸质或多端媒介上的视觉呈现格式的表现层样式表语言。

    * 职责分工：HTML 负责承载页面的内容骨架与结构语义，CSS 负责色彩装饰、版式尺寸与自适应排版。

* **样式规则与声明结构（CSS Rule & Declaration）**

    * > **定义**：由选择器与紧随其后的声明块构成的标准化样式控制单元。

    * 语法构成：选择器后紧随一对英文大括号 `{}` 包裹的声明块，声明块内部由若干以分号 `;` 结尾的声明项构成。

    * 键值规范：每个声明项包含属性名与属性值，两者之间使用英文冒号 `:` 分隔。

    * > **易错点**：⚠️ 属性名与属性值之间的冒号以及声明项末尾的分号必须使用半角英文符号；输入全角中文冒号（`：`）或中文分号（`；`）会导致整条样式规则被解析引擎判为语法错误而静默失效。

### 样式导入途径与工程选型
* **内联样式（Inline Style）**

    * > **定义**：通过 HTML 标签自身的 `style` 属性直接绑定的行内样式声明。

    * 适用场景：局部快速临时调试、排查偶发视觉故障或由 JavaScript 动态计算并直接赋予精确像素坐标。

    * 架构边界：表现层与结构层严重耦合，无法在多标签间复用，生产工程中避免大面积使用。

* **内部样式表（Internal Style Sheet）**

    * > **定义**：集中编写在 HTML 文档 `<head>` 区域 `<style>` 标签内部的样式声明集合。

    * 适用场景：独立单页面演示、轻量级页面原型验证或独立活动落地页。

    * 架构边界：作用域严格受限于当前单个 HTML 页面，无法在多页面站点间共享。

* **外部样式表（External Style Sheet）**

    * > **定义**：将 CSS 规则完全独立保存在 `.css` 文件中，并通过 HTML `<head>` 区域的 `<link>` 标签解耦导入的工程化样式方案。

    * 引入机制：通过 `<link rel="stylesheet" href="样式路径.css">` 载入，`rel="stylesheet"` 表明关联文件为样式表，`href` 指定目标路径。

    * 架构边界：实现表现与结构完全解耦，支持整站数百个页面多路共享与集中维护，为现代工程化标准形态。

| 导入方式 | 存放位置 | 语法载体 | 适用场景 | 复用性评级 |
| :--- | :--- | :--- | :--- | :--- |
| **内联样式（行内样式）** | HTML 标签本体属性内 | `style="..."` 属性 | 局部临时调试、JS 动态精确控量 | 极差（仅对当前单个标签有效） |
| **内部样式表** | HTML `<head>` 内部 | `<style>...</style>` 标签 | 独立单页应用、小型测试页面 | 较差（仅在当前单页面内生效） |
| **外部样式表** | 独立于 HTML 的 `.css` 文件 | `<link rel="stylesheet" href="...">` | 商业级大型网站、工程化开发 | 极高（全站多页面可集中共享） |

### 样式层叠法则与覆盖规则
* **层叠优先级（Cascading Priority）**

    * > **定义**：当多个样式规则同时作用于同一个 HTML 元素的相同属性时，浏览器判定生效样式的权重计算与覆盖算法。

    * 基础法则：在选择器权重一致的前提下，导入层级的判定顺序遵循：
    $$\text{内联样式} > \text{内部样式表} \ge \text{外部样式表}$$

    * 物理距离法则：内联样式直接挂载在标签实体上，距离目标元素最近，优先权最高，任何在 `<style>` 或外部 `.css` 中声明的普通规则均无法覆盖内联样式。

* **源码解析顺序覆盖机制（Source Order Precedence）**

    * > **定义**：内部样式表与外部样式表处于相同权重层级时，依据 HTML 源码解析先后顺序决定最终胜出的机制。

    * 判定规则：遵循“后来者居上”的代码解析顺序；排在后面的样式声明会无条件覆盖前面引入的同名属性。

## 选择器引擎与节点匹配拓扑

### 基础标识选择器
* **元素选择器（Type Selector）**

    * > **定义**：以 HTML 标签名称作为匹配凭据的基础选择器。

    * 匹配范围：页面中所有与该标签名称相同的所有节点无差别全部命中。

    * 匹配粒度：粒度最粗，无法单独区分同类标签之间的个性化视觉差异。

* **类选择器（Class Selector）**

    * > **定义**：以英文点号 `.` 开头、基于 HTML 元素 `class` 属性值进行精确定位的选择器。

    * 匹配规则：命中包含对应类名的目标节点；单元素支持挂载多个以空格隔开的类名，同名类可在多元素间复用。

    * 优先级判定：类选择器的匹配权重高于元素选择器（$\text{类选择器} > \text{元素选择器}$）。

* **ID 选择器（ID Selector）**

    * > **定义**：以英文井号 `#` 开头、基于 HTML 元素 `id` 属性唯一标识进行定位的选择器。

    * 规范约束：在同一个 HTML 文档树中，每个元素的 `id` 属性必须具备全局唯一性，禁止多节点复用相同 ID。

    * 适用边界：用于页面核心顶级结构容器的统筹锚定或脚本精确抓取特定节点。

* **通用选择器（Universal Selector）**

    * > **定义**：以单个星号 `*` 标识、无条件匹配当前文档树中全部 DOM 节点的全局选择器。

    * 作用机理：穿透匹配文档中所有元素，常用于全局重置边距基准或统配全局基准字体族。

### 层级拓扑与关系选择器
* **子元素选择器（Child Combinator）**

    * > **定义**：使用大于号 `>` 连接父级与子级、严格匹配直接子代节点的关系选择器。

    * 匹配规则：`E > F` 仅匹配作为 `E` 容器第一级直接子节点（儿子辈）的 `F` 元素。

    * 穿透边界：绝不穿透匹配更深层级的嵌套后代（孙子辈及更深层节点）。

* **后代选择器（Descendant Combinator）**

    * > **定义**：使用英文空格连接祖先与后代、匹配指定祖先元素内部所有层级目标节点的关系选择器。

    * 匹配规则：`E F` 匹配包含在 `E` 元素内部的所有 `F` 节点，涵盖直接子代以及深层嵌套后代。

    * 包含关系：后代选择器天然包含直接子代，但子代选择器绝不穿透匹配深层后代。

* **相邻兄弟选择器（Adjacent Sibling Combinator）**

    * > **定义**：使用加号 `+` 连接同级元素、严格匹配紧随其后的首个同级节点的关系选择器。

    * 匹配规则：`E + F` 仅匹配紧跟在 `E` 元素之后、且与 `E` 拥有相同直接父级的第一位同级 `F` 元素。

    * 边界条件：若目标 `F` 元素位于 `E` 之前，或两者之间夹杂其他同级兄弟节点，则匹配判定失败。

### 状态伪类与虚拟伪元素
* **状态伪类选择器（Pseudo-classes）**

    * > **定义**：以单冒号 `:` 开头、用于匹配处于特定瞬时交互状态或特定文档结构位置的元素的选择器。

    * 交互伪类：`:hover` 匹配鼠标指针悬停于元素上方的交互状态；`:active` 匹配鼠标按下未释放的激活瞬态。

    * 结构伪类：`:first-child` 匹配父容器内首个子元素；`:nth-child(n)` 匹配父容器内第 $n$ 个特定位置的子元素。

* **虚拟伪元素选择器（Pseudo-elements）**

    * > **定义**：以双冒号 `::` 开头、在渲染树中生成不可见或可样式化虚拟节点的技术机制。

    * 注入方向：`::before` 在目标元素真实内容前部注入虚拟内容；`::after` 在目标元素真实内容尾部注入虚拟内容。

    * 工程用途：无需在 HTML 中增加冗余标签即可插入装饰图标、辅助线段或配合样式执行浮动闭合。

| 选择器类型 | 语法格式 | 示例 | 匹配目标与范围说明 |
| :--- | :--- | :--- | :--- |
| **元素选择器** | `标签名` | `h2` | 匹配页面中所有同名的 `<h2>` 元素 |
| **类选择器** | `.类名` | `.highlight` | 匹配所有带有 `class="highlight"` 属性的元素 |
| **ID 选择器** | `#标识符` | `#header` | 匹配 `id="header"` 的唯一特定元素 |
| **通用选择器** | `*` | `*` | 匹配当前文档树中的所有元素 |
| **子元素选择器** | `E > F` | `.father > p` | 仅匹配作为 `E` 元素直接子代（儿子辈）的 `F` 元素 |
| **后代选择器** | `E F` | `.father p` | 匹配作为 `E` 元素内部任意层级的后代 `F` 元素 |
| **相邻兄弟选择器** | `E + F` | `h3 + p` | 仅匹配紧跟在 `E` 元素后面且同级的第一个 `F` 元素 |
| **状态伪类选择器** | `E:状态` | `#element:hover` | 匹配鼠标指针悬停于目标元素上的交互状态 |
| **虚拟伪元素选择器** | `E::伪元素` | `p::before` | 在目标元素真实内容的前部注入虚拟修饰内容 |

## 元素显示模式与排版属性

### 文本排版与复合字体属性
* **字体属性簇（Font Properties）**

    * > **定义**：用于独立控制文本字形、尺寸、粗细与样式的样式属性集合。

    * 基础属性：`font-family` 指定字体系列，`font-size` 指定文本字号，`font-weight` 控制粗细（取值 `normal`、`bold`、`bolder`），`font-style` 控制字体倾斜（取值 `normal`、`italic`）。

    * 复合简写：`font` 复合属性支持一行声明多项属性（例如 `font: bolder 50px 楷体;`），字号与字体系列为不可缺省的核心项。

* **文本行高（Line Height）**

    * > **定义**：通过 `line-height` 属性控制的多行文本行间垂直基线间距。

    * 空间表现：增大行高可撑开文本自然折行后的垂直间隙，消除排版压迫感，提升可读性。

### 三大原生显示模式
* **块级元素（Block-level Element）**

    * > **定义**：在页面排版流中天然新起一行、且默认横向撑满父级容器的排版元素。

    * 典型标签：`<div>`、`<p>`、`<h1>`~`<h6>`、`<ul>`、`<form>`。

    * 尺寸特征：显式声明的 `width` 与 `height` 完全生效；即便显式设置较小宽度，其所在的水平行依然被独占。

    * 容纳规则：内部允许容纳其他块级元素与各类行内元素。

* **行内元素（Inline Element）**

    * > **定义**：在同一水平行内自左向右顺次紧凑并排、不独占一行的排版元素。

    * 典型标签：`<span>`、`<a>`、`<strong>`、`<em>`。

    * 尺寸特征：显式设置 `width` 与 `height` 完全无效，其物理占位严格由内部包含的内容自适应撑开。

    * 容纳规则：仅能容纳纯文本或其他行内元素，规范禁止直接嵌套块级元素。

* **行内块元素（Inline-block Element）**

    * > **定义**：兼具行内水平并排能力与块级尺寸响应特性的混合型排版元素。

    * 典型标签：`<img>`、`<input>`、`<button>`。

    * 尺寸特征：既能与其他元素在同一行水平并排，又可自由显式定义 `width`、`height`、内边距与外边距。

    * 空间表现：HTML 源码中标签间的空格或换行会被渲染为默认的微小空白间隙。

| 元素分类 | 默认排版方式 | 能否设置 width / height | 默认宽度特征 | 常见标签 |
| :--- | :--- | :--- | :--- | :--- |
| **块级元素（block）** | 独占一整行，新起一行 | **可以**正常生效 | 撑满整行（父容器 100% 宽） | `<div>`, `<p>`, `<h1>` |
| **行内元素（inline）** | 同行水平紧随排列 | **不能**（设置无效） | 严格由内容本身宽度自适应决定 | `<span>`, `<a>`, `<strong>` |
| **行内块元素（inline-block）** | 同行水平并排排列 | **可以**正常生效 | 默认由内容决定，可被显式覆盖 | `<img>`, `<input>` |

### 显示模式转换与空间抽离
* **显示模式转换（Display Property）**

    * > **定义**：通过 `display` 属性重置元素的排版与渲染计算模式。

    * `display: inline`：强制将块级元素转换为行内表现，放弃行独占并使显式宽高失效，宽度自适应收缩包裹内容。

    * `display: inline-block`：将元素转为行内块表现，赋予其水平同行并排能力与宽高尺寸响应能力。

    * `display: block`：将行内元素提升为块级模型，使其独占整行并支持显式宽高设置。

* **空间抽离隐藏（Display None）**

    * > **定义**：通过声明 `display: none;` 将元素从浏览器渲染树中彻底抽离的机制。

    * 空间表现：不仅在视觉上完全不可见，而且在文档流中不再占据任何物理空间，后续兄弟节点立即上移顶替原位。

## 盒子模型空间几何与尺寸边界

### 盒子模型几何层次
* **盒子模型（Box Model）**

    * > **定义**：浏览器渲染引擎将页面中所有可视元素抽象为矩形几何容器的尺寸与空间计算标准。

    * 几何层次：由内至外依次为内容区域（Content）、内边距（Padding）、边框（Border）和外边距（Margin）。

    ```text
    +-------------------------------------------------------------+
    |                           margin (外边距)                   |
    |   +-----------------------------------------------------+   |
    |   |                       border (边框)                 |   |
    |   |   +---------------------------------------------+   |   |
    |   |   |                   padding (内边距)          |   |   |
    |   |   |   +-------------------------------------+   |   |   |
    |   |   |   |               content               |   |   |   |
    |   |   |   |              (内容区域)             |   |   |   |
    |   |   |   +-------------------------------------+   |   |   |
    |   |   +---------------------------------------------+   |   |
    |   +-----------------------------------------------------+   |
    +-------------------------------------------------------------+
    ```

* **内容区域（Content Box）**

    * > **定义**：存放文本、图像或子元素的核心实体区域，由 `width` 和 `height` 直接定义。

* **内边距（Padding）**

    * > **定义**：围绕在内容区域周围、用于拉开内容与边框之间安全留白的内部间距。

    * 背景继承：内边距位于边框以内，继承元素自身的背景色，增大内边距会导致盒子整体外观体积向外膨胀。

* **边框（Border）**

    * > **定义**：环绕在内边距外围的可见物理分界线，构成盒子的实体轮廓边缘。

* **外边距（Margin）**

    * > **定义**：位于边框外围、用于隔离当前盒子与外部相邻元素或视口边缘的透明外部空白区域。

| 组成部分 | CSS 对应属性 | 核心作用与空间表现 |
| :--- | :--- | :--- |
| **内容（Content）** | `width` / `height` | 存放文本、图像或子元素的核心实体区域 |
| **内边距（Padding）** | `padding` | 围绕在内容周围，拉开内容与边框之间的内部留白 |
| **边框（Border）** | `border` | 围绕在内边距外围的可见边界线，是盒子的实体边缘 |
| **外边距（Margin）** | `margin` | 盒子边框之外的外部空白，用于隔离当前盒子与其他元素或视口边界 |

### 边框复合属性与顺时针四值法则
* **边框复合属性（Border Shorthand）**

    * > **定义**：用单行声明同时指定边框宽度、样式与颜色的复合属性。

    * 语法格式：`border: [border-width] [border-style] [border-color];`（例如 `border: 5px solid yellowgreen;`）。

    * 常用线型：`solid`（实线）、`dashed`（虚线）、`dotted`（点线）、`double`（双实线）。

* **顺时针四值法则（Clockwise Four-Value Rule）**

    * > **定义**：多值简写属性向「上、右、下、左」四个物理方向循环映射的数值解析机制。

    * 单值模式：`border-width: 10px;`（上下左右均为 10px）。

    * 双值模式：`border-width: 10px 0;`（第一个值映射上下，第二个值映射左右）。

    * 三值模式：`border-width: 10px 0 20px;`（首值映射顶部，次值映射左右两侧，末值映射底部）。

    * 四值模式：`border-width: 10px 0 20px 40px;`（严格依序映射上 $\to$ 右 $\to$ 下 $\to$ 左）。

    * > **易错点**：⚠️ CSS 中当属性值为数值 `0` 时单位建议且允许省略；当数值非 `0` 时必须显式携带计量单位（如 `px`），若遗漏单位整条规则将被判为语法错误失效。

* **单向边框属性（Directional Border Properties）**

    * > **定义**：针对上、右、下、左单一物理方向施加边框样式的派生复合属性。

    * 方向语法：`border-top`、`border-right`、`border-bottom`、`border-left`。

    * 属性解构：单向属性可进一步解构成三要素属性，如 `border-left` 分解为 `border-left-width`、`border-left-style` 与 `border-left-color`。

## 传统流式布局：浮动排版与高度塌陷闭合

### 网页布局体系与浮动机制
* **网页五大布局模式（Layout Modes）**

    * > **定义**：现代前端用于控制页面空间排列与元素分布的五种排版体系。

    * 体系分类：标准流、浮动排版、定位排版、弹性盒子布局与网格布局。

| 布局模式 | 核心排列逻辑 | 典型应用场景 |
| :--- | :--- | :--- |
| **标准流（文档流）** | 块级独占一行纵向堆叠，行内横向排列 | 基础文档排版与线性阅读流 |
| **浮动（Float）** | 脱离默认占位，向左/右贴靠横向并排 | 传统多栏分栏、图文环绕 |
| **定位（Position）** | 基于参照物进行像素级坐标绝对落位 | 悬浮工具栏、吸顶导航、弹窗层叠 |
| **弹性盒子（Flexbox）** | 声明主轴与侧轴，容器动态分配子项空间 | 现代 UI 自适应与多端响应式排版 |
| **网格布局（Grid）** | 容器切分为二维行列网格坐标系统 | 复杂的二维看板与多维表格化布局 |

* **浮动排版（Float）**

    * > **定义**：通过 `float` 属性使元素脱离默认文档占位、沿着其直接父元素内边界向左或向右紧凑贴靠的排版机制。

    * 取值范围：`float: left;`（向左浮动）、`float: right;`（向右浮动）、`float: none;`（默认值，不浮动）。

    * 边界约束：浮动计算始终以直接父级元素的内容边界为参考基准，元素位移绝不超出父级边界。

* **浮动核心排版特征（Float Features）**

    * > **定义**：元素施加浮动后在浏览器渲染引擎中激活的三大排版特性。

    * 脱标特性：脱离常规标准流，在原始物理流中不再保留占位空间，其原有坑位由后续标准流元素立即顶替。

    * 同行贴靠无缝隙：相同浮动方向的多个盒子在父容器同一行内紧贴排布、顶部边缘水平对齐；盒子之间不存在行内块元素特有的 HTML 空白字符缝隙；父宽不足时自动平滑折行。

    * 具备行内块尺寸表现：无论原标签为块级还是行内，施加浮动后均可显式设置 `width` 与 `height`；未显式设置时宽度由内部包裹内容自适应撑开。

### 高度塌陷与清除浮动机制
* **父级高度塌陷（Height Collapse）**

    * > **定义**：当父级容器未显式声明固定高度，且内部全部子元素均开启浮动脱标时，父容器计算高度坍缩为零的排版故障。

    * 破坏表现：父级边框挤压成一条线无法包裹子元素，后续标准流元素径直上穿渗入浮动子元素空隙，引发全局版面错位紊乱。

    * > **易错点**：⚠️ 高度塌陷的根源在于子元素脱标导致在标准流中失去物理占位，未设高度的父容器认为内部空无一物，因而计算高度归零。

* **格式化上下文清除法（BFC Clear Float）**

    * > **定义**：在父容器上声明 `overflow: hidden;` 触发块级格式化上下文（BFC）以闭合浮动的方案。

    * 运行机理：BFC 计算布局高度时强制将内部浮动子元素的几何尺寸计入父容器总高，使父容器自适应撑开。

    * 适用边界：若容器内部存在需要超出父边界显示的下拉菜单或悬浮遮罩，超出部分会被截断隐藏。

* **伪元素闭合浮动法（Pseudo-element Clearfix）**

    * > **定义**：在父容器末尾通过 CSS 伪元素注入清理实体的标准工程级浮动闭合方案。

    * 规范代码：
    ```css
    .father::after {
        content: "";
        display: table;
        clear: both;
    }
    ```

    * 原理解析：`content: ""` 注入不可见内容，`display: table` 阻断外边距折叠并构建独立布局实体，`clear: both` 闭合清除左右两侧浮动影响；由于伪元素在文档流中被推至浮动子元素正下方，迫使父容器高度延展并完全包裹该伪元素。

## 坐标参照系：相对、绝对与固定定位

### 定位模型与坐标分类
* **CSS 定位（CSS Positioning）**

    * > **定义**：通过 `position` 属性与方向偏移量，打破常规文档流约束以实现像素级精确落位的排版体系。

    * 核心分类：相对定位（`relative`）、绝对定位（`absolute`）、固定定位（`fixed`）。

| 定位类型 | 属性声明 | 参照基准物 | 是否脱离文档流（脱标） | 典型应用场景 |
| :--- | :--- | :--- | :--- | :--- |
| **相对定位** | `position: relative;` | **元素自身原本在文档流中的正常位置** | **否**（原本位置严格保留） | 自身位置微调、作为绝对定位子元素的父级参照锚点 |
| **绝对定位** | `position: absolute;` | **距离最近的、已开启定位的祖先元素**（若无则退化为根元素 `<html>`） | **是**（脱标，不占原有位置） | 图标角标、下拉浮层、弹窗遮罩、自由层叠组件 |
| **固定定位** | `position: fixed;` | **浏览器可视窗口（Viewport）** | **是**（脱标，不占原有位置） | 吸顶导航栏、页面右下角悬浮客服或返回顶部按钮 |

* **定位坐标偏移量（Directional Offsets）**

    * > **定义**：配合定位属性使用的四大方向位移数值，包括 `top`、`bottom`、`left`、`right`。

    * 位移法则：`top` 正值向下推移，`bottom` 正值向上推移，`left` 正值向右推移，`right` 正值向左推移；未指定时偏移量默认为 0。

### 相对定位与物理占位锁定
* **相对定位（Relative Positioning）**

    * > **定义**：以元素自身原本在标准文档流中的物理原点作为基准发生空间偏移的定位模式。

* **相对位移物理占位守恒（In-flow Space Retention）**

    * > **定义**：相对定位元素在发生视觉位移时，其在文档流中的原始物理坑位被强制锁定保留的排版机制。

    * 独立性表现：视觉上发生位移，但其后续的标准流元素完全不感知其位移，既不上移顶替，也不发生联动位移。

### 绝对定位与祖先参照链追溯
* **绝对定位（Absolute Positioning）**

    * > **定义**：使元素完全脱离标准文档流、基于定位祖先节点进行绝对坐标落位的定位模式。

    * 脱标覆盖现象：元素完全脱离文档流，原始物理占位瞬间归零；排在其后的标准流元素自下而上顶替空缺坑位，导致绝对定位元素悬浮漂浮于后序元素上方产生视觉覆盖。

* **祖先定位上下文追溯机制（Ancestral Positioning Context）**

    * > **定义**：绝对定位元素向上查找参照原点的链式解析规则。

    * 追溯原则：优先以距离自身最近且已开启定位（`relative`、`absolute` 或 `fixed`）的祖先元素作为坐标系；若向上遍历至顶层所有祖先均为默认标准流（`static`），则最终退化以整个文档根标签 `<html>` 为基准。

* **子绝父相工程范式（Absolute Child & Relative Parent）**

    * > **定义**：父级容器开启相对定位（保留占位且充当锚点）、内部子元素开启绝对定位进行边界锚定的经典工程组合。

    * 工程优势：父容器保留自身在文档流中的规整占位不干扰外部流，子元素则能自由锚定在父容器四角（如角标、标签提示）。

### 固定定位与视口锚定
* **固定定位（Fixed Positioning）**

    * > **定义**：使元素脱离标准流、严格以浏览器可视窗口（Viewport）为唯一坐标基准进行锚定的定位模式。

    * 视口锁定特性：定位基准物恒定为当前可视窗口，彻底脱离页面滚动流；当用户上下滑动页面滚动条时，固定定位元素锁死在屏幕特定视口坐标处保持静止。

* **视口常驻交互形态（Viewport Pinning Applications）**

    * > **定义**：固定定位在现代 Web 界面中的典型交互工程实现。

    * 典型形态：页面滚动时始终锁定在屏幕顶部的吸顶导航条、屏幕右下角常驻的悬浮客服图标与返回顶部快捷按钮。

## 现代自适应核心：Flex 弹性盒子布局

### 弹性双轴空间坐标模型
* **Flex 弹性盒子模型（Flexible Box）**

    * > **定义**：通过容器与直接子项的弹性交互、在双轴空间内实现自适应伸缩、分布与对齐的现代布局体系。

    * 容器与项目：声明 `display: flex;` 或 `display: inline-flex;` 的元素为 Flex 容器；容器内的直接子元素自动成为 Flex 项目。

* **弹性双轴坐标系（Flex Axes System）**

    * > **定义**：Flex 容器内部由主轴与交叉轴构建的二维正交坐标体系。

    ```text
    +-------------------------------------------------------------------------+
    | flex 容器 (display: flex)                                cross start    |
    |                                                               │         |
    |                     主轴 (Main Axis) ───────────>             ▼         |
    |  main start                                               main end      |
    |  +--------------+  +--------------+  +--------------+                   |
    |  |  flex item   |  |  flex item   |  |  flex item   |                   |
    |  | (main size)  |  |              |  |              |                   |
    |  +--------------+  +--------------+  +--------------+                   |
    |                                                               │         |
    | 交叉轴 (Cross Axis)                                           ▼         |
    |                                                           cross end     |
    +-------------------------------------------------------------------------+
    ```

    * 轴向边界：主轴起点为 `main start`、终点为 `main end`；交叉轴起点为 `cross start`、终点为 `cross end`。

    * 动态旋转性：主轴方向非静态固定，可由水平旋转为垂直；主轴旋转后交叉轴随之协同转换方向。

### 容器流向与轴线换行控制
* **主轴方向控制属性（flex-direction）**

    * > **定义**：决定主轴推进方向及项目排布流向的容器属性。

    * `row`（默认值）：主轴为水平方向，起点在左侧，项目自左向右排列。

    * `row-reverse`：主轴为水平方向，起点在右端，项目自右向左反转排列。

    * `column`：主轴切换为垂直方向，起点在顶部，项目自上而下纵向排成单列。

    * `column-reverse`：主轴为垂直方向，起点在底部，项目自底向上反转排列。

* **轴线换行控制属性（flex-wrap）**

    * > **定义**：当一行内所有项目主轴尺寸之和超出容器容量时，控制是否换行排布的容器属性。

    * `nowrap`（默认值）：绝不换行；当容器宽度不足时，Flex 引擎强制等比压缩每个项目的宽度使其硬挤在一根轴线上。

    * `wrap`：自动换行；排不下的项目自上而下换入新的一行排布，并保持项目自身原始尺寸设定。

    * `wrap-reverse`：反向换行；首行排在容器最下方，换行项目自下而上向容器顶部换入。

* **流向与换行复合属性（flex-flow）**

    * > **定义**：`flex-direction` 与 `flex-wrap` 的复合简写属性，默认取值为 `row nowrap`。

### 主轴与交叉轴空间对齐分配
* **主轴富余空间分配属性（justify-content）**

    * > **定义**：当所有项目主轴尺寸相加小于容器总尺寸时，分配主轴剩余空间并控制对齐的容器属性。

    * `flex-start`（默认值）：项目向主轴起点靠齐，富余空间留在末尾。

    * `flex-end`：项目向主轴终点靠齐，富余空间留在开头。

    * `center`：项目整体紧贴在主轴中央，两端等额留白。

    * `space-between`：两端对齐；首项紧贴 `main start`，末项紧贴 `main end`，剩余空间在项目之间绝对等额平分，两端无缝隙。

    * `space-around`：环绕对齐；每个项目左右两侧各自分配相等的留白，边缘缝隙尺寸恰好为相邻项目间缝隙的一半（$1:2$ 比例）。

    * `space-evenly`：绝对均分对齐；所有项目之间、以及最外侧项目与容器边缘之间的所有缝隙尺寸严格一致。

* **交叉轴单行对齐属性（align-items）**

    * > **定义**：控制项目在单条轴线内部沿着交叉轴维度的对齐方式。

    * `stretch`（默认值）：若子项目未设置固定高度（或 `height: auto`），项目在交叉轴方向自动拉伸撑满容器高度。

    * `flex-start`：在交叉轴起点靠齐。

    * `flex-end`：在交叉轴终点靠齐。

    * `center`：在交叉轴垂直居中。

    * `baseline`：项目依据第一行文字的基线对齐。

    * > **易错点**：⚠️ 当子项目显式设置了固定 `height` 尺寸时，默认的 `stretch` 拉伸属性将自动失效，项目保持显式高度。

* **交叉轴多行整体对齐属性（align-content）**

    * > **定义**：在开启换行产生多条轴线（多行）时，控制所有轴线作为一个整体在交叉轴上的间距分配与对齐方式。

    * 生效前提：仅在容器设置 `flex-wrap: wrap` 且实际产生多行轴线时生效；单行项目下完全无效。

    * 空间表现：未声明时各行平分父容器垂直高度，行间出现多余留白；声明 `align-content: center;` 后多行项目紧凑打包并居中于大容器中央。

    * 取值范围：支持 `flex-start`、`flex-end`、`center`、`space-between`、`space-around` 与 `space-evenly`。

| CSS 容器属性 | 核心作用说明 | 常用属性取值 |
| :--- | :--- | :--- |
| `flex-direction` | 决定主轴的方向（即项目的流动排列方向） | `row` \| `row-reverse` \| `column` \| `column-reverse` |
| `flex-wrap` | 轴线空间排不下时，是否换行及换行方式 | `nowrap` \| `wrap` \| `wrap-reverse` |
| `flex-flow` | `flex-direction` 与 `flex-wrap` 的复合简写 | `row nowrap`（默认值组合） |
| `justify-content` | 定义项目在主轴上的对齐与间距分配方式 | `flex-start` \| `flex-end` \| `center` \| `space-between` \| `space-around` \| `space-evenly` |
| `align-items` | 定义项目在交叉轴单行内的对齐方式 | `stretch` \| `flex-start` \| `flex-end` \| `center` \| `baseline` |
| `align-content` | 定义多根轴线（多行）在交叉轴上的整体对齐方式 | `flex-start` \| `flex-end` \| `center` \| `space-between` \| `space-around` \| `space-evenly` |

## 移动端多屏适配体系与工程进阶

### 移动端视口配置与仿真体系
* **设备视口仿真（Device Emulation）**

    * > **定义**：现代浏览器开发者工具（DevTools）内置的高保真移动端逻辑分辨率与交互模拟环境。

    * 仿真要素：逻辑视口分辨率（如 iPhone 12 Pro 为 $390 \times 844$）、缩放倍率控制、横竖屏切换旋转。

* **视口元信息标签（Viewport Meta Tag）**

    * > **定义**：在 HTML `<head>` 中用于声明移动端视口渲染比例、防止默认桌面虚拟宽视口（980px）缩放的元配置标签。

    * 核心声明：`<meta name="viewport" content="width=device-width, initial-scale=1.0">`。

| 视口配置项 | 核心作用与机制解析 |
| :--- | :--- |
| `width=device-width` | 将虚拟视口宽度强制设定为设备逻辑宽度，禁止默认宽视口缩小渲染 |
| `initial-scale=1.0` | 设置页面初次加载时的初始缩放比例为 1.0（100% 原始比例） |
| `minimum-scale=1.0` | 允许用户手动缩小的最小缩放倍率 |
| `maximum-scale=1.0` | 允许用户手动放大的最大缩放倍率 |
| `user-scalable=no` | 禁止用户通过双指手势缩放页面以保证类原生 App 体验 |

### 长度单位与动态 rem 算法
* **相对长度单位（Root EM，rem）**

    * > **定义**：以 HTML 文档根节点 `<html>` 当前 `font-size` 像素值为基准乘数的相对长度单位。

    * 换算关系：$1\text{rem} = \text{html.fontSize}$；现代浏览器根节点默认字号为 `16px`，此时 $5\text{rem} = 80\text{px}$。

    * 绝对单位局限：绝对像素 `px` 在多端设备上数值死板，在小屏设备上过度拥挤挤压，在大屏设备上过小失调。

* **动态根字号计算法则（Dynamic Root Font-Size Algorithm）**

    * > **定义**：通过 JavaScript 动态获取设备屏幕逻辑宽度、按固定比例重置根节点字号以实现全局等比缩放的适配算法。

    * 比例准则：将任意屏幕总宽度均分为 10 等份，令根字号等于屏幕宽度的十分之一：
    $$\text{html.style.fontSize} = \frac{\text{屏幕宽度}}{10}$$

    * 几何推导：此时屏幕总宽度恒为 $10\text{rem}$；宽度为 $5\text{rem}$ 的元素在任何设备上恒定占据屏幕宽度的 $50\%$；宽度为 $0.5\text{rem}$ 的间距恒为屏幕宽度的 $5\%$。

    * 运行时脚本实现：
    ```javascript
    function resetHtmlFontSize() {
        document.documentElement.style.fontSize = screen.width / 10 + 'px';
    }
    resetHtmlFontSize();
    window.onresize = resetHtmlFontSize;
    ```

    * 监听机制：绑定 `window.onresize`，保证屏幕旋转或视口拉伸变动时自动重新计算并无缝重绘。

* **多屏响应式选型体系（Responsive Strategy Options）**

    * > **定义**：工程中针对屏幕适配的技术选型分工策略。

    * 动态 rem 体系：专注于相近尺寸移动设备（如 375px~430px）之间维持像素级的整体等比缩放。

    * 媒体查询体系（Media Queries）：专注于在跨度巨大的断点（Breakpoint）之间切换完全不同的排版骨架（如 PC 宽屏多列与手机端单列堆叠）。

### 前端技术栈闭环与现代工程进阶
* **原生前端底座闭环（Frontend Core Pillars）**

    * > **定义**：HTML 语义骨架、CSS 视觉表现与 JavaScript 交互驱动三者构成的 Web 核心技术底座。

    * 底层守恒定律：现代前端所有高级框架与跨端平台的运行时渲染，底层本质依然完全基于原生 DOM、CSS 样式计算与 JS 逻辑驱动。

* **现代单页应用框架（Vue.js）**

    * > **定义**：基于数据驱动视图（MVVM）与单文件组件（SFC）构建的高效前端框架。

    * 核心价值：通过底层响应式系统自动比对并更新视图，消除繁琐手写 DOM 操作；单文件组件集成 HTML、CSS 与 JS 逻辑。

* **跨端统一工程框架（uni-app）**

    * > **定义**：基于 Vue.js 语法体系开发、通过编译器实现一套代码跨平台编译发布的全端开发体系。

    * 交付能力：一套源码可通过编译器一键编译发行至各大平台小程序（微信、支付宝等）、移动端原生 App（iOS、Android）以及自适应 Web H5 站点。
