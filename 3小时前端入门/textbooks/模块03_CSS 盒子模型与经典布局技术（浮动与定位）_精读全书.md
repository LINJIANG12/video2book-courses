## 盒子模型
> 对应分集：P11 | 原始标题：《11. 盒子模型》

我们在前面学习了 HTML 的块级元素与行内元素，知道了不同元素在页面流中占据空间的基本规律。然而，要真正把网页元素摆放整齐、构建出精美规整的页面结构，就必须掌握 CSS 中最核心的基石——盒子模型（Box Model）。

在浏览器解析渲染 HTML 文档时，视口中的每一个元素都可以被抽象地看作一个矩形的盒子。无论是段落、标题、图片还是容器标签，所有的排版与视觉边界，本质上都是在对这个盒子的内外空间进行精确计算与控制。

```text
+-------------------------------------------------------------+
|                           margin (外边距)                   |
|   +-----------------------------------------------------+   |
|   |                       border (边框)                 |   |
|   |   +---------------------------------------------+   |   |
|   |   |                   padding (内边距)          |   |   |
|   |   |   +-------------------------------------+   |   |   |
|   |   |   |                                     |   |   |   |
|   |   |   |               content               |   |   |   |
|   |   |   |              (内容区域)             |   |   |   |
|   |   |   |                                     |   |   |   |
|   |   |   +-------------------------------------+   |   |   |
|   |   +---------------------------------------------+   |   |
|   +-----------------------------------------------------+   |
+-------------------------------------------------------------+
```
*图解说明：CSS 盒子模型由内至外依次为内容区域（content）、内边距（padding）、边框（border）以及外边距（margin）。*

---

### 盒子模型核心组成与几何层次

每一个盒子模型均由内到外由四个层次组合而成：

| 组成部分 | CSS 对应属性 | 核心作用与空间表现 |
| :--- | :--- | :--- |
| **内容（Content）** | `width` / `height` | 存放文本、图像或子元素的核心实体区域 |
| **内边距（Padding）** | `padding` | 围绕在内容周围，拉开内容与边框之间的内部留白 |
| **边框（Border）** | `border` | 围绕在内边距外围的可见边界线，是盒子的实体边缘 |
| **外边距（Margin）** | `margin` | 盒子边框之外的外部空白，用于隔离当前盒子与其他元素或视口边界 |

`padding`、`border` 和 `margin` 三者均属于**复合属性（Shorthand Properties）**，我们既可以通过单个复合属性同时对上下左右四个方向进行统一赋值，也可以拆分成各个方向的独立属性进行细粒度微调。

---

### 边框复合属性与行内块适配

我们通过一个具体的代码案例来观察边框的渲染机制。先在 HTML 中创建一个带有 `demo` 类名的容器：

```html
<div class="demo">B站搜索罗大富</div>
```

如果我们直接给这个 `div` 设置背景颜色和边框，由于块级元素默认会撑满父容器整行的宽度，其宽度并不会刚好包裹文字。为了让盒子的默认宽度收缩为文字内容的实际宽度，我们将它的显示模式转为行内块元素：

```css
.demo {
    background-color: aqua;
    display: inline-block;
    border: 5px solid yellowgreen;
}
```

在上述样式中，`border: 5px solid yellowgreen;` 是典型的复合写法，它一次性指定了边框的三大核心属性：
1. **边框宽度（border-width）**：例如 `5px`。数值越大，边框越粗。
2. **边框样式（border-style）**：例如 `solid`（实线）。
3. **边框颜色（border-color）**：例如 `yellowgreen`（黄绿色），支持预设颜色英文名、十六进制或 RGB 色值。

> **提示**：边框样式除了最常见的实线 `solid` 外，常用的预设值还包括：
> - `dashed`：虚线（破折线状）
> - `dotted`：点线（圆点状）
> - `double`：双实线

---

### 边框属性拆分与顺时针四值法则

当我们希望更自由地控制边框时，可以将边框拆分为独立的属性。我们构建一个尺寸固定的容器示例：

```html
<div class="border-demo">这是一个边框示例</div>
```

```css
.border-demo {
    background-color: yellow;
    width: 300px;
    height: 200px;
    border-style: solid;
    border-width: 10px;
    border-color: blueviolet;
}
```

这里 `border-style`、`border-width` 和 `border-color` 依然是复合属性，因为一个盒子存在**上（top）、右（right）、下（bottom）、左（left）**四个物理方向。当我们在这些属性中传递不同数量的数值时，浏览器遵循严格的**顺时针规则**。

```text
                  1. top (上)
                      ^
                      |
    4. left (左) <-- [盒] --> 2. right (右)
                      |
                      v
                 3. bottom (下)
```
*图解说明：CSS 边框、内边距与外边距的多值简写均遵循「上 $\to$ 右 $\to$ 下 $\to$ 左」的顺时针循环匹配逻辑。*

#### 基础单值设定模式
```css
border-width: 10px;
```
上下左右四个方向的边框宽度均为 `10px`。

#### 对称双值设定模式
```css
border-width: 10px 0;
```
第一个值 `10px` 代表上下边框，第二个值 `0` 代表左右边框。此时左右两侧边框消失。

#### 缺省三值设定模式
```css
border-width: 10px 0 20px;
```
第一个值 `10px` 控制顶部；第二个值 `0` 同时控制左右两侧；第三个值 `20px` 控制底部。如果缺失了左侧的指定值，浏览器会自动沿用右侧对应的取值。

#### 完整四值设定模式
```css
border-width: 10px 0 20px 40px;
```
按照完整顺时针序列严格映射：顶部 `10px`、右侧 `0`、底部 `20px`、左侧 `40px`。

> **注意**：在 CSS 中，当属性值为 `0` 时，单位可以且建议省略（直接写 `0`）；但当数值非 `0` 时，必须附带明确的计量单位（如 `px`），否则该条样式规则会被浏览器判定为语法错误而失效。
> 
> 顺时针四值法则同样完全适用于 `border-style` 与 `border-color`，例如：
> ```css
> border-style: solid dashed dotted double;
> ```

---

### 单向边框控制与属性继承逻辑

如果我们只需要在盒子的某一个特定方向（例如左侧）绘制一条标尺线，而其余三边保持空白，有两种书写策略：

#### 属性拆分置零法
```css
.border-demo {
    border-style: solid;
    border-width: 0 0 0 10px; /* 仅保留左侧 10px 宽度 */
    border-color: brown;
}
```

#### 单向复合属性法
更加简洁、工程化推荐的写法是直接使用方向专属的复合属性：

```css
.border-demo {
    border-left: 10px solid brown;
}
```

`border-left` 自身又能够进一步向下分解为三个基础属性：
- `border-left-width`
- `border-left-style`
- `border-left-color`

> **结论**：CSS 拥有上百个样式属性，但其内部的命名与层级逻辑是高度统一的。理解了边框的“宽度-样式-颜色”三要素以及“上-右-下-左”的四向映射机制，就能自然推导出 `border-top`、`border-right`、`border-bottom` 及其数十个派生细分属性，无需机械背诵。

---

### 内边距与外边距的空间隔离

理解了边框之后，我们把焦点放到盒子内外的空间隔离属性——`padding` 与 `margin`。

这两者同样严格遵循顺时针四值法则，且各自拥有独立的四向专属属性：
- **外边距集合**：`margin-top`、`margin-right`、`margin-bottom`、`margin-left`
- **内边距集合**：`padding-top`、`padding-right`、`padding-bottom`、`padding-left`

我们把它们完整应用到最初的 `.demo` 元素中：

```css
.demo {
    background-color: aqua;
    display: inline-block;
    border: 5px solid yellowgreen;

    /* 内边距：内容文本与边框之间向内撑开 50px 的安全缓冲空间 */
    padding: 50px;

    /* 外边距：当前盒子的边框与外部元素（或视口边缘）推开 40px 的间距 */
    margin: 40px;
}
```

1. **`padding: 50px;` 的视觉变化**：文字周围被大面积的青色背景包裹填充，因为内边距处于边框以内，它会继承当前盒子的背景颜色，使盒子整体体积向外膨胀。
2. **`margin: 40px;` 的视觉变化**：整个 `.demo` 盒子与视口左上角以及周围其他排版元素拉开了 `40px` 的距离。外边距属于透明的外部间距，用于确立盒子在整个页面流中的独立领地。

掌握了盒子模型的内容、内边距、边框与外边距这四大要素，我们就拥有了精确计算网页尺寸与空间占位的基础能力，后续的一切复杂布局都将立足于这套空间模型展开。

> 💡 **承前启后**：完成对「盒子模型」的理解后，下一章我们将深入探讨「浮动」，进一步完善知识图谱体系。

## 浮动
> 对应分集：P12 | 原始标题：《12. 浮动》

网页制作的本质，说到底就是「摆盒子」——把各种包含文字、图像和交互组件的矩形盒子，按照设计要求平铺、堆叠并安放在屏幕的合适位置上。然而，单纯依赖 HTML 标签默认的排列规则，很难完成现代网页丰富多变的分栏与图文混排。为了实现精准的多列排版，我们必须深入理解传统网页布局机制，尤其是其中承担横向并列排版重任的**浮动（Float）**。

---

### 网页布局体系与排版逻辑

在进入浮动的具体细节前，我们先建立宏观的布局认知体系。在现代前端工程中，页面的排布主要涵盖五种模式：

| 布局模式 | 核心排列逻辑 | 典型应用场景 |
| :--- | :--- | :--- |
| **标准流（普通流 / 文档流）** | 块级元素独占一行、自上而下顺次堆叠；行内元素在一行内自左向右排列 | 默认的文档排版与基础文本阅读流 |
| **浮动（Float）** | 让块级元素脱离默认占位，沿指定方向贴靠，横向在一行并列展示 | 传统的多栏布局、图文环绕与并排卡片列表 |
| **定位（Position）** | 脱离常规流，基于参照物（父级或视口）进行像素级绝对定位 | 悬浮挂件、吸顶导航栏、弹窗与层叠遮罩 |
| **弹性盒子（Flexbox）** | 声明主轴与侧轴，容器动态分配子项空间、支持自动缩放与对齐 | 现代 UI 界面的自适应与响应式组件排版 |
| **网格布局（Grid）** | 将容器切分为二维行列坐标网格，子项按行列网格落位 | 复杂的二维大盘布局与多维表格化展示 |

```text
标准流默认排布（块级独占一行，纵向堆叠）：
+-------------------------------------------------------------+
| [块级元素 1] (默认宽度撑满父容器或强制独占一行)               |
+-------------------------------------------------------------+
| [块级元素 2] (自动被挤压到下一行)                            |
+-------------------------------------------------------------+

浮动后排布（多个块级同一行紧凑贴靠）：
+-------------------------------------------------------------+
| [左浮动元素 1][左浮动元素 2] ...               [右浮动元素 1] |
+-------------------------------------------------------------+
```
*图解说明：标准流中块级元素无法并列，浮动打破了块级独占一行的限制，实现横向贴靠。*

在实际工程开发中，这五种布局模式并非相互排斥，而是频繁穿插结合使用的。例如页面的整体自适应骨架可以使用 Flexbox 或 Grid 快速适配移动端与 PC 端，而局部的图文环绕与特定排列依然会结合浮动与定位协同实现。

---

### 浮动核心属性与运行机理

标准流规则非常死板：块级元素一律独占一整行。如果我们希望两个原本各占一行的 `div` 容器并排出现在屏幕左侧和右侧，就需要借助浮动。

#### 浮动与行内块的区别

我们前面学过把块级元素设置为 `display: inline-block` 也可以让它们在一行显示。但浮动与行内块相比，具有一个极为关键的排版优势：
- **行内块元素**：HTML 代码中标签之间的换行符或空格，会被浏览器渲染成默认的**空白缝隙**，在要求像素级紧密贴合的场景下难以控制；
- **浮动元素**：浮动的盒子之间**毫无缝隙**，能够严丝合缝地贴靠在一起。当父容器的宽度不足以容纳所有浮动盒子的总宽度时，溢出的盒子会自动换到下一行排列。

> **注意**：浮动始终是**相对于其直接父级元素**进行的，浮动盒子只会在父容器的内容边界内部进行平移，绝不可能超出父级边界随意乱跑。

#### 浮动本质特性与尺寸表现

浮动通过 CSS 的 `float` 属性进行定义，常见取值包括 `left`（向左浮动）、`right`（向右浮动）以及 `none`（默认值，不浮动）：

```css
选择器 {
    float: left; /* 或 right / none */
}
```

任何元素一旦应用了浮动，就会立即激活三大核心特征：

1. **脱标（脱离标准文档流）**：
   浮动元素会立即脱离标准流的控制，不再在文档流中保留其原有的占位空间（俗称“不占位”）。它就像从页面地面漂浮到了半空，其原本占据的物理空间会被其后的标准流元素直接顶替。
2. **同属一行，顶部对齐**：
   只要父容器宽度允许，设置了相同浮动方向的多个盒子会自动在一行内顺次贴紧排列，并且始终保持顶部边缘水平对齐。
3. **具备行内块元素的尺寸特征**：
   无论该元素原本是块级元素（如 `div`、`p`）还是行内元素（如 `span`、`a`），一旦施加浮动，都可以显式为其设置固定的 `width` 和 `height`；若未显式指定宽高，则其尺寸完全由内部包裹的内容自适应撑开。

---

### 浮动布局代码实现与排版表现

我们通过一段代码构建父子结构，演示浮动的真实渲染状态：

```html
<div class="father">
    <div class="left_son">左浮动</div>
    <div class="right_son">右浮动</div>
</div>
```

```css
.father {
    background-color: pink;
    height: 150px;
}

.left_son {
    width: 100px;
    height: 100px;
    background-color: yellowgreen;
    float: left;
}

.right_son {
    width: 100px;
    height: 100px;
    background-color: yellow;
    float: right;
}
```

在未施加 `float` 之前，`.left_son` 与 `.right_son` 属于标准流块级元素，垂直自上而下排成两行；
添加 `float: left` 与 `float: right` 之后：
- `.left_son` 脱标并紧紧贴靠在 `.father` 容器的左内侧边缘；
- `.right_son` 脱标并紧紧贴靠在 `.father` 容器的右内侧边缘；
- 两者共处于父容器的同一水平高度上，完成了两栏横向并列。如果我们复制多个 `.left_son`，它们会从左向右像多米诺骨牌一样紧密排布；一旦整行被排满，超出宽度的浮动盒子将平滑折行落入下一层排布。

---

### 父级高度塌陷与清除浮动方案

在真实的业务开发中，我们极少给父级容器设定固定的 `height`（例如 `height: 150px;`），因为内部的数据内容往往是动态加载的，我们希望父容器能够被子元素的高度自动撑开。

然而，当父容器未设置固定高度，且其内部的所有子元素均设置了浮动时，严重的排版灾难就会爆发——**高度塌陷（Height Collapse）**。

#### 高度塌陷的成因与破坏性

我们把上述 `.father` 的 `height: 150px;` 移除，改用边框标识其边界：

```css
.father {
    border: 3px solid brown;
    /* 取消 height 声明，依赖子元素撑开 */
}
```

```html
<div class="father">
    <div class="left_son">左浮动</div>
    <div class="right_son">右浮动</div>
</div>
<div>这是一段紧随其后的普通文本</div>
```

此时浏览器呈现出极为异常的形态：
1. 父元素 `.father` 的计算高度直接坍缩为 `0`，棕色边框被挤压成了一条紧贴在顶部的线，根本无法包裹住两个高度为 `100px` 的子元素；
2. 紧随其后的普通文本，原本在标准流中应当处于父容器正下方，此时却径直上窜到了两个浮动盒子之间的缝隙处，与浮动元素重叠错位。

```text
高度塌陷状态（父级 height = 0）：
+======================= 父容器上边框 =======================+  <-- 边框坍塌为一条线
| [左浮动子元素] (脱标悬空)           [右浮动子元素] (脱标悬空) |
+-----------------------------------------------------------+
[后续标准流文本直接上穿，钻入浮动子元素间隙中，导致整个页面版面混乱]
```
*图解说明：子元素浮动脱标导致父容器无法侦测内部高度，后续标准流元素发生上移紊乱。*

> **易错点**：高度塌陷的根源在于子元素脱离了标准流（脱标），在物理占位上不复存在。父容器在计算自身内容高度时认为内部空无一物，因而高度坍塌为零。

#### 溢出隐藏清除浮动机制

解决高度塌陷最简洁的手段，是在父容器上添加 `overflow: hidden`：

```css
.father {
    border: 3px solid brown;
    overflow: hidden; /* 触发 BFC，闭合内部浮动 */
}
```

> **原理**：`overflow: hidden` 会促使浏览器为父级容器构建一个独立的**块级格式化上下文（BFC）**。在 BFC 规范下，计算容器高度时必须将内部所有的浮动子元素尺寸计入在内。这样父容器的高度便能重新被子元素自然撑开，后续的文本元素也会被规整地推至父容器下方。

#### 伪元素闭合浮动实践

虽然 `overflow: hidden` 写法简单，但在遇到下拉菜单溢出或弹窗遮罩需要超出父容器边界显示的场景时，会导致超出内容被意外截断隐藏。

因此，前端工程中最规范、最具兼容性的通用方案是**伪元素清除法**：

```css
.father::after {
    content: "";
    display: table;
    clear: both;
}
```

- `content: ""`：在父容器的末尾注入一个不可见的空内容；
- `display: table`：将其显示模式定义为表格格式或块级实体，阻断内部外边距折叠并建立独立布局实体；
- `clear: both`：核心所在，清除其左侧与右侧的一切浮动影响。

由于这个伪元素处于父容器的最底部且存在于标准流中，它自身被浮动元素推到了它们下方，从而迫使父容器的高度必须延展并包含该伪元素，完美化解高度塌陷问题，使页面各层级排版各就其位。

> 💡 **承前启后**：完成对「浮动」的理解后，下一章我们将深入探讨「定位」，进一步完善知识图谱体系。

## 定位
> 对应分集：P13 | 原始标题：《13. 定位》

在前面的布局学习中，我们感受到了浮动的灵活，但浮动本质上依然受制于流式排布的牵引，遇到想要把某一个图标精准安放在某个角落、让菜单悬浮在特定控件上方时，浮动就显得力不从心。这时候，我们需要掌握能够实现像素级自由摆布的技术——**CSS 定位（Positioning）**。

然而，凡事皆有两面性：定位虽然让元素获得了精准的坐标控制力，但由于脱离了常规文档流的自动推挤机制，当页面内容发生动态伸缩时，死板的坐标往往容易造成重叠或遮挡。因此，我们在实际开发中必须辩证地看待浮动与定位：浮动负责大面积的行列排布，而定位负责特定图层的精细覆盖与锚定。

---

### 核心定位分类与排版权衡

通过 CSS 的 `position` 属性，我们可以将元素的排版模式切换为不同类型的定位方式。常见的核心定位分为三类：

| 定位类型 | 属性声明 | 参照基准物 | 是否脱离文档流（脱标） | 典型应用场景 |
| :--- | :--- | :--- | :--- | :--- |
| **相对定位** | `position: relative;` | **元素自身原本在文档流中的正常位置** | **否**（原本位置严格保留） | 自身位置微调、作为绝对定位子元素的父级参照锚点 |
| **绝对定位** | `position: absolute;` | **距离最近的、已开启定位的祖先元素**（若无则退化为根元素 `<html>`） | **是**（脱标，不占原有位置） | 图标角标、下拉浮层、弹窗遮罩、自由层叠组件 |
| **固定定位** | `position: fixed;` | **浏览器可视窗口（Viewport）** | **是**（脱标，不占原有位置） | 吸顶导航栏、页面右下角悬浮客服或返回顶部按钮 |

```text
文档流物理占位示意对比：

相对定位（保留原本占位，自身仅产生视觉投影偏移）：
+------------------------------------+
| [普通元素 A]                       |
+------------------------------------+
| [相对定位元素 B 原始占位]            | ---> (B 视觉上移向右下方，但此占位锁死)
+------------------------------------+
| [普通元素 C 保持原位，绝不上移]    |
+------------------------------------+

绝对定位 / 固定定位（完全脱标，不占原位）：
+------------------------------------+
| [普通元素 A]                       |
+------------------------------------+
| [普通元素 C 自动上浮，顶替 B 原位置]| <--- [绝对定位 B 漂浮在空中，覆盖在 C 上方]
+------------------------------------+
```
*图解说明：相对定位元素在文档流中保留原位，其他元素不会受其位移影响；绝对定位与固定定位脱标，原占位被后序元素顶替。*

---

### 相对定位机理与保留占位特性

相对定位是指元素以**自身原本在正常文档流中的物理位置**作为原点进行偏移。

#### 相对定位声明与物理占位守恒

我们搭建一个基础结构，外层为 `.box1`，内部并列三个等大的子容器：

```html
<div class="box1">
    <div class="box-normal"></div>
    <div class="box-relative"></div>
    <div class="box-normal"></div>
</div>
```

```css
.box1 {
    height: 350px;
    background-color: aqua;
}

.box-normal {
    width: 100px;
    height: 100px;
    background-color: purple;
}

.box-relative {
    width: 100px;
    height: 100px;
    background-color: pink;
}
```

当我们仅仅声明 `position: relative;` 时，页面没有任何视觉改变。因为相对定位不仅没有脱离文档流，而且在未设定偏移值前，它的偏移量默认为 `0`。

#### 坐标偏移量与正负位移关系

要让定位元素移动，需要配合四大方向偏移属性：
- `top`：距离自身原位置顶部边缘的偏移量（正值向下推移）；
- `bottom`：距离自身原位置底部边缘的偏移量（正值向上推移）；
- `left`：距离自身原位置左侧边缘的偏移量（正值向右推移）；
- `right`：距离自身原位置右侧边缘的偏移量（正值向左推移）。

我们将 `.box-relative` 赋予偏移属性：

```css
.box-relative {
    position: relative;
    left: 120px; /* 距左侧原位置 120px，即向右平移 120px */
    top: 40px;   /* 距顶部原位置 40px，即向下平移 40px */
}
```

> **注意**：此时 pink 盒子向右下方滑出，但紧随其后的第三个紫色 `.box-normal` 盒子**依然停留在原位，没有产生任何位移**！
> 
> 相对定位最关键的物理特征：**虽然元素在视觉上发生了位移，但它在文档流中的原始占位依然被原样锁定**。后面的所有标准流元素完全感知不到它发生过位移，仍然把它视作停在原地。

---

### 绝对定位机制与脱标覆盖现象

绝对定位与相对定位有着本质的割裂：绝对定位元素**彻底脱离了常规文档流（脱标）**。

#### 脱标机理与空间顶替覆盖

我们创建第二组容器 `.box2` 进行对比测试：

```html
<div class="box2">
    <div class="box-normal"></div>
    <div class="box-absolute"></div>
    <div class="box-normal"></div>
</div>
```

```css
.box2 {
    height: 350px;
    background-color: yellow;
    margin-bottom: 300px;
}

.box-absolute {
    width: 100px;
    height: 100px;
    background-color: yellowgreen;
    position: absolute;
}
```

一旦给 `.box-absolute` 加上 `position: absolute;`，立刻会出现一个显著现象：**下方的第二个紫色盒子看不见了**。

这是因为绝对定位的黄绿色盒子脱标悬空，其原本在文档流中的占位彻底消失，导致原本排在它下面的紫色盒子立刻自下而上“浮”了上来，占领了那个空出来的坑位。而黄绿色盒子此时正漂浮在紫色盒子的正上方，严严实实地把它遮盖住了。

为了验证这一点，我们为绝对定位盒子施加横向位移：

```css
.box-absolute {
    position: absolute;
    left: 120px;
}
```

随着黄绿色盒子向右移开，被它遮挡的紫色盒子完整地展露在原本属于中间盒子的位置上。

#### 祖先定位参照链追溯规则

绝对定位的参考基准遵循逐级追溯机制：
1. 如果其祖先元素（父级、祖父级等）中存在任何开启了定位（`relative`、`absolute`、`fixed`）的元素，则以**距离其最近的那个定位祖先元素**作为坐标参考物；
2. 如果其向上追溯的所有祖先元素均未设置定位（都是默认的标准流 `static`），则最终退化以整个页面的根标签 `<html>` 作为参考原点进行坐标换算。

---

### 固定定位与视口锚定交互应用

固定定位是绝对定位的一种特殊变体。它与绝对定位的共同点在于：**固定定位同样完全脱离标准文档流，不保留原占位**。

两者的核心差异在于其定位基准物的不同：
- **绝对定位**：基准物是包含它的定位祖先元素或文档；
- **固定定位**：基准物永远是**浏览器窗口（Viewport，可视视口）**本身。

我们创建一个固定定位的盒子：

```html
<div class="box-fixed"></div>
```

```css
.box-fixed {
    width: 100px;
    height: 100px;
    background-color: brown;
    position: fixed;
    right: 0;     /* 紧贴浏览器视口最右侧 */
    top: 300px;   /* 距离浏览器视口顶部 300px */
}
```

```text
浏览器可视窗口（Viewport）
+-------------------------------------------------------------+
|                                                             |
|                                            +--------------+ |
|                                            |  box-fixed   | |  <-- 锁定在视口右侧固定位置
|                                            | (棕色悬浮块) | |
|                                            +--------------+ |
|                                                             |
| (页面主体内容无论上下滚动多少屏，该悬浮块始终停在屏幕右侧固定坐标) |
+-------------------------------------------------------------+
```
*图解说明：固定定位元素紧扣浏览器窗口边界，脱离网页滚动流。*

#### 视口锁定与滚动静止

当我们滑动鼠标滚轮、在垂直方向拖动页面滚动条浏览数百像素的超长内容时，页面中的 `.box1` 和 `.box2` 都会随着滚动条自下而上滑出屏幕，唯独棕色的 `.box-fixed` 像被磁铁牢牢钉在浏览器屏幕的右侧中央，岿然不动。

这就是我们在电商网站和各类门户网页中最为常见的：
- 屏幕右侧常驻的**悬浮工具栏 / 客服图标**；
- 页面向下滚动时始终停留锁定在屏幕顶部的**吸顶导航条**。

#### 定位方式的综合选型法则

在构建复杂的真实页面时，我们根据场景特点做出准确的技术选型：
1. 如果仅仅希望微调元素的位置（例如某个图标相对于字面下移 2 像素），或者作为内部子元素的定位基准，必须选用**相对定位**，因为它不会打乱其他邻近元素的布局结构；
2. 如果需要做弹窗、下拉悬浮列表或者在图片右上角贴上醒目的“HOT”角标，必须使用「子绝父相」（子元素绝对定位，父元素相对定位）的经典组合；
3. 如果需要做无论用户浏览到何处都必须始终可见的全局组件（例如吸顶菜单、悬浮快捷通道），果断选用**固定定位**。
