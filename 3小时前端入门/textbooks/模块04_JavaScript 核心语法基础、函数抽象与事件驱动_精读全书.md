## JavaScript 简介及导入方式
> 对应分集：P14 | 原始标题：《14. JavaScript 简介及导入方式》

在完成了 HTML 结构搭建与 CSS 样式美化的学习后，我们正式跨入前端“三剑客”的最后一块关键版图——JavaScript。

如果说 HTML 构成了网页的骨骼框架，CSS 赋予了网页血肉与华丽外衣，那么 JavaScript 则是赋予网页生命与灵魂的神经系统。在学习 JavaScript 之前，首先必须厘清一个初学者最容易踩中的常识误区：**JavaScript 与 Java 没有任何技术血缘关系**。两者的关系好比“雷锋”与“雷峰塔”，仅仅是早期为了搭上 Java 的热度借势营销而在命名上产生了重合，底层哲学与执行环境完全独立。

---

### 编程语言定位与全栈生态

#### 语言本质与概念辨析

从计算机科学的角度来看，JavaScript（简称 JS）是一种**轻量级、解释型、面向对象的脚本语言**。它的诞生初衷非常朴素：上世纪九十年代，网景公司为了在浏览器端处理简单的表单验证（例如检查用户是否填写了邮箱、密码长度是否达标），避免每次输入错误都要向服务器发起昂贵的网络往返，从而设计了这门轻巧的脚本。

但随着浏览器内核性能的飞速跃升和 V8 引擎等技术的突破，JavaScript 已经演进为全功能的现代化高级通用编程语言。

```text
网页前端技术协作分工模型：

+-------------------------------------------------------------+
|                     JavaScript (行为与交互)                  |
|          监听用户点击 / 异步请求数据 / 动态修改 DOM 元素        |
+-------------------------------------------------------------+
                              | 驱动控制
+-------------------------------------------------------------+
|                        CSS (表现与视觉)                     |
|            色彩 / 字体 / 盒模型 / 浮动与定位几何布局         |
+-------------------------------------------------------------+
                              | 依托渲染
+-------------------------------------------------------------+
|                       HTML (结构与内容)                     |
|               语义化标签 / 页面骨架与基础文档流              |
+-------------------------------------------------------------+
```
*图解说明：HTML 提供骨架，CSS 塑造外观，JavaScript 赋予网页响应用户行为的交互逻辑。*

#### 动态交互与全栈应用领域

在当代软件工程中，JavaScript 的应用版图覆盖了全链路场景：

1. **客户端脚本（Browser Client）**：
   直接内置并运行于各类主流浏览器中。它是前端交互的唯一官方宿主语言，用于监听用户的鼠标点击、键盘输入，并实时修改页面 DOM 结构，让静态网页具备“活”过来的动态反馈。
2. **网页协同开发（Web Interaction）**：
   与 HTML 和 CSS 深度协同，完成复杂的前端组件封装、页面无刷新局部数据加载（Ajax）以及丰富的富媒体动画效果。
3. **服务端后端开发（Server-Side via Node.js）**：
   借助 Node.js 运行时环境，JavaScript 突破了浏览器的围墙，能够直接在服务端操作系统中运行，实现高并发 Web 服务器、RESTful API 接口、文件系统操作及数据库持久化。

> **结论**：在后端软件开发领域，Python、Java、Go、C++ 等多门语言百家争鸣、各据一方；而在前端浏览器领域，JavaScript 具有不可替代的垄断地位。学好 JavaScript 是成为现代 Web 开发者的必经之路。

### 脚本引入方式与工程组织

在编写 JavaScript 代码前，我们必须知道代码应该存放在何处并如何被浏览器加载。常用的导入方式主要分为两类：**内部内联式（Internal Script）**与**外部引入式（External Script）**。

| 导入模式 | 语法标签形式 | 放置位置推荐 | 适用场景 |
| :--- | :--- | :--- | :--- |
| **内部内联式** | `<script> 代码 </script>` | `<head>` 或 `<body>` 底端 | 逻辑极短的代码段、实验测试、页面初始化配置 |
| **外部引入式** | `<script src="./path/file.js"></script>` | `<head>` 或 `<body>` 底端 | 生产环境标准写法、业务逻辑解耦与代码复用 |

#### 内部内联式编写

类似于 CSS 放在 `<style>` 标签中，JavaScript 代码必须被包裹在 `<script>` 标签内。`<script>` 标签既可以置于 `<head>` 区域，也可以直接嵌入在 `<body>` 标签的任何角落。

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
    <meta charset="UTF-8">
    <title>JS 导入测试</title>
    <!-- 放置在 head 标签内的内部脚本 -->
    <script>
        console.log("Hello head 标签 内联脚本");
    </script>
</head>
<body>
    <h1>JavaScript 导入示例</h1>

    <!-- 放置在 body 标签内的内部脚本 -->
    <script>
        console.log("你好，Hello body 标签的内联脚本");
    </script>
</body>
</html>
```

#### 外部独立文件引入

在大型工程项目中，把成百上千行业务逻辑堆砌在 HTML 中会导致代码极度臃肿。标准规范是将 JS 代码抽离成以 `.js` 为后缀的独立文件。

我们在项目目录下新建 `js` 文件夹，并在其中创建 `myscript.js`：

```javascript
// ./js/myscript.js 纯 JavaScript 文件中无需包含 <script> 标签
console.log("Hello 外联样式与外部脚本");
```

随后在 HTML 中通过 `<script>` 标签的 `src` 属性进行外链引入：

```html
<head>
    <!-- 使用 ./ 表示当前 HTML 所在同级目录下的 js 文件夹 -->
    <script src="./js/myscript.js"></script>
</head>
```

> **易错点**：当 `<script src="..."></script>` 标签用于引入外部脚本文件时，标签体内部**严禁书写任何 JavaScript 代码**。写在外部标签体内部的代码将被浏览器完全忽略执行。

### 脚本执行流与基础输出机制

学习任何一门编程语言的第一步，都是向世界打一声招呼。我们在浏览器中如何查看 JavaScript 的输出结果？

#### 控制台环境与日志输出

不同于我们在界面上绘制的 HTML 文本，JavaScript 绝大多数基础计算和调试信息都是直接与开发环境交互的。在 Google Chrome 等现代浏览器中，按下键盘快捷键 **F12**（或鼠标右键选择“检查”），切换到 **Console（控制台）** 选项卡。

我们在代码中调用内置函数：

```javascript
console.log("输出至控制台的内容");
```

`console.log()` 是前端调试中使用频次最高的语句，用于在控制台输出变量、对象状态以及追踪程序运行轨迹。

#### 浏览器自上而下的解析时序

如果一个 HTML 页面中同时混合存在多个 `<script>` 标签，它们的执行顺序是怎样的？

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
    <!-- 1. 头部内联脚本 -->
    <script>
        console.log("1. Head 内联脚本执行");
    </script>

    <!-- 2. 头部外链脚本 -->
    <script src="./js/myscript.js"></script>
</head>
<body>
    <h1>页面主体</h1>

    <!-- 3. 底部内联脚本 -->
    <script>
        console.log("3. Body 底部内联脚本执行");
    </script>
</body>
</html>
```

浏览器对 HTML 文件的加载与解析遵循严格的**自上而下、同步阻塞时序**：
1. 浏览器从第一行向下扫描，遇到 `<head>` 中的内联 `<script>`，立即暂停 DOM 解析，由 JS 引擎执行该段代码，控制台首先输出 `"1. Head 内联脚本执行"`；
2. 紧接着扫描到外部文件引用，浏览器立即发起网络请求加载 `myscript.js`，加载完毕后立刻执行，控制台第二顺位输出 `"Hello 外联样式与外部脚本"`；
3. 继续向下解析 `<body>` 结构，构建渲染 DOM 节点，最后执行到底部的内联脚本，输出 `"3. Body 底部内联脚本执行"`。

#### 阻塞式弹窗告警交互

除了在控制台输出静默日志外，JavaScript 还提供了一个能够与用户进行直接视觉交互的原生函数——`alert()`：

```javascript
alert("你好，内联样式弹窗");
```

当浏览器解析执行到 `alert()` 语句时，会立即在页面中央弹出一个带有“确定”按钮的原生模态警告对话框。

> **注意**：`alert()` 具有高度的**代码阻塞性**。在用户点击对话框上的“确定”按钮之前，整个页面的其余渲染、后续代码执行以及用户交互都会被完全挂起冻结。因此在现代大型交互页面中，`alert()` 主要用于教学验证与极端告警，日常业务中多采用轻量化的 UI 模态组件替代。

## JavaScript 变量与数据类型
> 对应分集：P15 | 原始标题：《15. JavaScript 变量与数据类型》

在任何一门编程语言中，程序运行的核心任务无非两件事：存储数据与处理数据。要在 JavaScript 中存储和运算数据，我们首先需要开辟内存空间，并给这块空间贴上一个可以索引的名字，这就是**变量（Variable）**。

在浏览器的 Console（控制台，按 F12 打开）中，我们可以直接交互式地观察变量的声明、赋值以及其底层的数据类型。

```text
变量声明关键字与作用域演进路径：

传统 ES5 规范：
  var -------> 函数作用域 (Function Scope) / 存在变量提升 (Hoisting) 风险

现代 ES6+ 规范（工程推荐）：
  let -------> 块级作用域 (Block Scope) / 变量值可变 / 安全灵活
  const -----> 块级作用域 (Block Scope) / 常量不可重赋 / 状态锁定
```
*图解说明：现代 JavaScript 编码规范淘汰了全局穿透风险较大的 `var`，统一采用 `let` 与 `const`。*

---

### 变量声明机制与关键字选型

JavaScript 提供了三个关键字用于声明存储标识符：`var`、`let` 与 `const`。

```javascript
// 1. var 声明一个基础变量（未赋予初始值）
var x;

// 2. let 声明一个变量并赋予初值 5
let y = 5;

// 3. const 声明一个数学常量圆周率
const pi = 3.14;
```

#### 关键字特性与职能分工

| 声明关键字 | 关键字语义 | 变量值是否可二次更改 | 作用域层级 | 现代工程推荐度 |
| :--- | :--- | :--- | :--- | :--- |
| `var` | Variable（传统变量） | 是 | **函数作用域（Function Scope）** | **不推荐使用**（遗留语法） |
| `let` | Let（现代块级变量） | 是 | **块级作用域（Block Scope）** | **强烈推荐**（日常变量首选） |
| `const` | Constant（常量） | **否（不可重新赋值）** | **块级作用域（Block Scope）** | **强烈推荐**（固定引用首选） |

#### 作用域模型与变量提升特性

`const` 的定位十分清晰：用于声明数学常量、固定配置参数或不变的函数引用。一旦通过 `const` 绑定了值，后续任何尝试重新赋值的操作都会直接触发运行时类型错误（TypeError）。

而同属变量声明的 `var` 与 `let`，存在着深刻的作用域差异：
- **`var` 的缺陷**：`var` 声明的变量只受函数边界的约束（函数作用域）。在诸如 `if` 条件分支或 `for` 循环的花括号 `{}` 内部使用 `var` 声明的变量，会“穿透”花括号污染到外层的上下文；同时 `var` 具有**变量提升（Hoisting）**特性，变量声明会被静默提升到当前作用域的顶部执行，容易造成难以排查的逻辑死角。
- **`let` 的现代优势**：`let` 严格绑定在当前的**块级作用域（Block Scope）**（即由任何 `{}` 包裹的代码块）内部。在代码块之外无法访问块内声明的 `let` 变量，彻底消除了变量污染问题，让程序具备更强的严谨性与安全性。

> **结论**：在编写现代 JavaScript 业务代码时，全面拥抱 `let` 与 `const`，坚决避免使用陈旧的 `var`。

### 基础数据类型分类与值形态

我们将声明的变量输出到控制台中：

```javascript
console.log(x, y, pi);
// 控制台输出结果：undefined 5 3.14
```

在 JavaScript 中，数据依据其存储形态被划分为不同的数据类型。基础数据类型由值本身直接体现：

#### 数值类型（Number）

在上述代码中，`y = 5` 与 `pi = 3.14` 均属于数值类型（Number）。

不同于 C 或 Java 将数字细分为 `int`、`float`、`double` 等多种物理类型，JavaScript 中的所有数字（包括整数 `5`、小数浮点数 `3.14`、负数等）在语言层面上统一统称为 **Number** 类型，简化了数值运算的语法门槛。

#### 文本字符串类型（String）

当我们需要在程序中记录人名、文字介绍或网络 URL 地址时，使用一对成对的双引号 `""` 或单引号 `''` 将字符包裹起来，这就构成了字符串类型：

```javascript
let name = "如花";
console.log(name); // 控制台输出：如花
```

字符串是文本数据的直接载体，可以包含汉字、英文字母、特殊字符乃至空字符串 `""`。

### 空值语义辨析与缺失值判定

#### 空值状态机理与对象引用

在上面的输出中，未被赋值的变量 `x` 打印出了 `undefined`。与此同时，JavaScript 还提供了另一个显式的空值标识——`null`：

```javascript
let emptyValue = null;
console.log(emptyValue); // 控制台输出：null
```

`undefined` 与 `null` 都用来表示“没有值”或者“值缺失”，但二者在程序语言的语义学设计上有着截然不同的深层分工：

```text
空值状态语义对照：

[变量声明阶段] ----(未分配实质内容)----> undefined (自然空态：已开辟但尚未初始化)
                                            ^
                                            | 函数无返回值 / 访问未定义属性
                                            |
[逻辑赋值阶段] ----(人为刻意清空)------> null      (人为置空：明确声明为空对象指针)
```
*图解说明：`undefined` 是系统底层的未初始化占位状态，`null` 是业务逻辑层的主动赋空。*

#### 语义维度对比与工程选型

| 特性维度 | `undefined`（未定义） | `null`（空值 / 空对象引用） |
| :--- | :--- | :--- |
| **底层定义** | 声明了变量，但**尚未进行初始化赋值** | 变量被**明确赋予了一个空值** |
| **产生主体** | 通常由 **JavaScript 运行引擎**自动产生 | 通常由 **开发者在代码中显式指定** |
| **典型触发场景** | 1. 变量仅声明未赋值（`let x;`）<br>2. 访问对象中根本不存在的属性<br>3. 函数内部没有显式书写 `return` 返回语句 | 1. 需要清空某个引用类型变量的指针<br>2. 作为参数传递，向函数表明“此处不需要传入有效对象” |
| **意图表达** | 表示该变量当前尚未就绪，**未来可能会被赋予有效值**，或该值尚在异步计算中 | 明确声明该位置**确实没有对象实体**，意图终结引用 |

> **提示**：在实际业务交互中，若某一个变量未来将用来承载一个复杂对象（例如用户信息），但在初始状态下尚未获取到数据，推荐将其显式初始化为 `null`；而不要将其裸露为 `undefined`，这样能够在代码阅读上清晰地传递出“此处刻意留空”的编程意图。

## JavaScript 控制语句
> 对应分集：P16 | 原始标题：《16. JavaScript 控制语句》

在编写前端脚本时，代码如果只是从上到下按顺序一行行执行，程序就只能完成最僵硬的静态任务。要让网页能够根据不同的用户输入产生不同的反馈，或者重复自动化地处理成百上千条数据，就必须引入**控制语句**（Control Statements）。

控制语句在 JavaScript 中主要分为两大核心板块：**条件语句**（用于逻辑分流与分支判断）和**循环语句**（用于代码块的受控重复执行）。无论是 C、Python、Java 还是 JavaScript，底层的控制逻辑本质上都是相通的；掌握了这些语法结构与边界判断，无论以后转向哪一门开发语言，都能够迅速上手。

---

### 条件语句的执行机制与多分支判定

条件语句允许程序在运行时根据表达式的真假状态，选择性地执行特定的代码块。在 JavaScript 中，最基础且最核心的条件控制依靠 `if`、`else if` 和 `else` 三个关键字组合实现。

```text
               [ 计算条件表达式 ]
                     |
            +--------+--------+
            |                 |
       (true)                 (false)
            |                 |
     [ 执行 if 代码块 ]   [ 检查 else if 或进入 else ]
            |                 |
            +--------+--------+
                     |
               [ 继续向下执行 ]
```
*上图展示了条件分支的基本决策流向：当条件为真时执行受控代码，为假时转移至后续分支。*

#### 条件分支的核心语法规则

- `if` 语句：分支的起点。括号内的条件表达式最终会被隐式转换为布尔值；只有当条件判定为 `true` 时，才会执行大括号 `{}` 内部的代码块。
- `else if` 语句：前置条件不满足时的后备检查项。当上一个 `if` 或前一个 `else if` 条件判定为 `false` 时，程序会依次向下检查当前 `else if` 的条件。一个条件判断链中可以根据需要串联多个 `else if`。
- `else` 语句：终极默认分支。当链条中所有的 `if` 和 `else if` 条件全部判定为 `false` 时，执行 `else` 代码块。
- **数量约束**：在一个完整的条件控制结构中，`if` 必须且只能有一个作为入口，`else` 最多只能有一个作为保底出口，而 `else if` 可以有零个或多个。

#### 比较运算符与边界值判定

我们以年龄检测为例来观察条件分支的执行。首先声明一个变量表示年龄：

```javascript
let age = 18;

if (age > 18) {
  console.log("你已经成年了");
}
```

运行这段代码时，控制台没有任何输出。

> **易错点**：很多初学者会疑惑“明明已经 18 岁了，为什么没有打印”。因为判断条件使用的是大于运算符 `>`，当 `age` 恰好为 18 时，`18 > 18` 的判断结果为 `false`。如果将 `age` 改为 19，控制台才会打印出提示。若要包含 18 岁本身，必须使用大于等于运算符 `>=`。

若要在条件不满足时给出相反的反馈，可以引入 `else` 双分支：

```javascript
let age = 9;

if (age > 18) {
  console.log("你已经成年了");
} else {
  console.log("未成年");
}
```

此时 `age` 为 9，`age > 18` 为 `false`，程序直接跳过 `if` 代码块，进入 `else` 分支并输出 `"未成年"`。

#### 逻辑运算符配合下的多分支时间段问候

在实际业务中，判定往往需要针对某个连续的数值区间。例如根据一天中的不同小时数向用户弹出问候窗口：

```javascript
let time = 12;

if (time < 12) {
  alert("上午好");
} else if (time >= 12 && time < 18) {
  alert("下午好");
} else {
  alert("晚上好");
}
```

在这段代码中：
1. 若 `time` 取值为 9，满足 `time < 12`，弹出 `"上午好"` 后直接跳出整个条件结构；
2. 若 `time` 取值为 12，首个条件不满足，进入 `else if` 判定。这里使用了逻辑与运算符 `&&`，要求同时满足 `time >= 12` 且 `time < 18` 两个子条件。因 12 落在区间 $[12, 18)$ 内，表达式为 `true`，弹出 `"下午好"`；
3. 若 `time` 取值为 22，前两个判断均失败，最终兜底进入 `else` 代码块，弹出 `"晚上好"`。

---

### 循环语句的运行结构与迭代控制

循环语句用于重复执行一段代码，直到指定的终止条件不再满足。在 JavaScript 中，最常用的循环结构是 `for` 循环与 `while` 循环。

#### for 循环的三段式结构

`for` 循环通常用于**循环次数已知或具有明确边界**的场景。其语法由圆括号内的三段表达式构成，各表达式之间使用分号 `;` 分隔：

```text
for ( 初始化表达式 ; 循环条件判断 ; 迭代器更新 ) {
    // 循环体代码
}
```

1. **初始化表达式**：在循环开始前执行一次，用于声明并初始化循环计数变量；
2. **循环条件判断**：在每次执行循环体之前进行求值。若为 `true` 则继续执行循环体，若为 `false` 则立刻终止循环；
3. **迭代器更新**：在每次循环体执行完毕后执行，用于递增或递减循环变量，驱动循环向前推进。

```javascript
for (let i = 0; i < 10; i++) {
  console.log(i);
}
```

上述代码的执行流程如下：
- `let i = 0`：声明局部计数器 $i$ 并赋值为 0；
- 检查 $i < 10$：此时 $0 < 10$ 成立，进入循环体打印 0；
- 执行 `i++`：计数器自增为 1（`i++` 是 $i = i + 1$ 的自增简写，等价于 $i += 1$）；
- 重复判断与执行，直到 $i$ 自增到 10 时，条件 $10 < 10$ 不成立，跳出循环。控制台依次输出 0 到 9。

如果业务需求是打印 1 到 10，则需要将初始变量设为 1，并将终止边界调整为闭区间：

```javascript
for (let i = 1; i <= 10; i++) {
  console.log(i);
}
```

> **提示**：条件写成 `i <= 10` 或 `i < 11` 在数学上是等效的，但使用 `<=` 可以更直观地体现上限包含数字 10。

#### while 循环与无限循环防范

与 `for` 循环将三段表达式集成在头部不同，`while` 循环只在圆括号内接收一个判断条件。只要该条件为 `true`，就会一直执行循环体。

```text
           +---> [ 条件判断为 true ? ] --- (false) ---> [ 退出循环 ]
           |              |
           |            (true)
           |              |
           |      [ 执行循环体代码 ]
           |              |
           |      [ 手动更新步进变量 ]
           |              |
           +--------------+
```
*上图展示了 while 循环的执行回路，循环体内部必须包含能够改变判断条件的步进操作。*

如果使用 `while` 循环来实现打印 1 到 10，初学者极易写出如下错误代码：

```javascript
let count = 1;
while (count <= 10) {
  console.log(count);
  // 遗漏了步进语句！
}
```

> **注意**：如果在循环体内没有对 `count` 进行递增，`count` 的值将永远保持为 1，条件 `count <= 10` 永远为 `true`。这会导致程序陷入**死循环**（Infinite Loop）。在浏览器中运行死循环会导致主线程被彻底阻塞，页面瞬间失去响应卡死，CPU 占用率飙升，电脑散热风扇剧烈轰鸣，最终只能强制杀掉浏览器进程。

因此，使用 `while` 循环处理有限任务时，必须在循环体内部手动维护迭代步进：

```javascript
let count = 1;
while (count <= 10) {
  console.log(count);
  count++; // 手动自增步进，亦可写为 count += 1 或 count = count + 1
}
```

| 循环类型 | 迭代控制方式 | 典型适用场景 |
| :--- | :--- | :--- |
| `for` 循环 | 初始化、条件、步进三合一紧凑书写 | 已知明确的循环次数或遍历固定长度集合 |
| `while` 循环 | 仅接收条件，依赖循环体内手动步进 | 循环次数不确定、等待外部事件或无限轮询 |

---

### 循环中断与跳转控制

在循环正常迭代的过程中，有时需要根据突发条件提前结束循环，或者跳过某些特定的循环轮次。JavaScript 提供了两个关键字：`break` 与 `continue`。

- `break`：立刻终止并彻底跳出当前循环体，后续未完成的循环轮次全部作废，程序直接执行循环大括号之后的代码。
- `continue`：中断当前轮次的执行，跳过本次循环体中尚未执行的代码，直接推进到迭代器的自增阶段并进入下一轮循环判断。

#### 循环跳转语句的联合演练

我们通过一个具体的计数循环来观察二者的行为差异：

```javascript
for (var i = 0; i < 7; i++) {
  if (i === 2) {
    continue; // 跳过本次循环剩余代码
  }
  if (i === 4) {
    break; // 彻底终止整个循环
  }
  console.log(i);
}
```

控制台最终打印的结果为：`0`, `1`, `3`。

逐轮追踪该循环的执行过程：
1. $i = 0$：两个 `if` 均不满足，执行 `console.log(0)`，进入下一轮；
2. $i = 1$：两个 `if` 均不满足，执行 `console.log(1)`，进入下一轮；
3. $i = 2$：满足第一个条件 `i === 2`，遇到 `continue` 语句，直接跳过下方的打印语句，执行头部 `i++` 进入下一轮；
4. $i = 3$：两个 `if` 均不满足，执行 `console.log(3)`，进入下一轮；
5. $i = 4$：满足第二个条件 `i === 4`，遇到 `break` 语句，整个循环在此彻底截断终结；
6. 随后的 $i = 5$ 与 $i = 6$ 将永远不会被执行。

若将终止条件调整为 `if (i === 5)`，则输出结果会变为 `0, 1, 3, 4`。理解 `break` 的截断性与 `continue` 的跳过性，是编写复杂过滤逻辑与控制流的基本功。

## JavaScript 函数
> 对应分集：P17 | 原始标题：《17. JavaScript 函数》

在编写程序的过程中，如果每次需要完成同一项功能都把相同的代码从头手写一遍，代码库很快就会变得臃肿、混乱且难以维护。为了消除重复劳动、实现逻辑复用，我们必须使用**函数**（Function）。

函数本质上是一段被封装起来、可重复调用的独立代码块。它可以接收外部传入的数据（参数），在内部执行特定的计算或任务，并最终将处理结果送回给调用者（返回值）。在 JavaScript 的模块化设计中，函数也是构建各种复杂交互和事件驱动体系的基石。

---

### 函数的语法结构与声明调用机制

在 JavaScript 中，定义函数最标准的方式是使用 `function` 关键字。一个完整的函数声明结构由关键字、函数名、参数列表、函数体大括号以及可选的返回语句构成。

```text
function 函数名( 参数1, 参数2, ... ) {
    // 函数体代码集合（执行特定任务）
    return 结果值; // 可选的返回值输出
}
```
*上图展示了 JavaScript 函数声明的标准结构：头部负责定义契约（名称与形参），大括号内部封装实现细节与出口。*

#### 函数声明与显式调用

函数的生命周期清晰地划分为**声明阶段**与**调用阶段**。我们首先声明一个在控制台输出 `"Hello World"` 的最基础函数：

```javascript
function hello() {
  console.log("Hello World");
}
```

将这段代码保存并在浏览器中加载时，控制台不会有任何输出。

> **易错点**：定义一个函数只是将这一段代码打包储存在内存中，并为其分配了一个名字，它**并不会自动执行**。如果想要执行函数内部的代码，必须显式地进行调用。调用的方式是在函数名后加上一对英文圆括号 `()`：

```javascript
hello();
```

只有执行了 `hello()`，解释器才会跳转进入函数体内部，控制台才会正确打印出 `"Hello World"`。

#### 控制台直接打印与 return 返回值的本质区别

很多初学者容易混淆“在函数内部打印”与“通过 `return` 返回结果”。我们对比下面这个带有返回值的函数：

```javascript
function hello_with_return() {
  return "Hello World 返回值";
}
```

如果直接在脚本中调用 `hello_with_return()`，控制台依然没有任何显示。这是因为前一个 `hello` 函数是在函数体内部直接执行了 `console.log` 操作；而 `hello_with_return` 并没有执行任何屏幕输出，它只是通过 `return` 关键字把字符串数据“递交”回给函数的调用处。

要捕获并使用这个返回值，通常有两种方式：

```javascript
// 方式一：使用变量接收返回值，随后打印
let a = hello_with_return();
console.log(a);

// 方式二：直接将函数调用结果作为参数传入打印方法中
console.log(hello_with_return());
```

> **定义**：`return` 语句会立即终止函数的执行，并将紧随其后的表达式结果返回给调用者。如果一个函数没有显式编写 `return` 语句，它的默认返回值是 `undefined`。

---

### 参数传递机制：形参与实参的动态绑定

若函数只能输出固定的文本，其实用价值依然十分有限。如果希望同一个函数能够根据不同的输入动态生成不同的反馈（例如向特定的人打招呼），就需要为函数引入**参数**。

```text
[ 外部调用: 实参 "如花" ] ------------+
                                     |
                                     v
function hello_with_params( 形参 name ) {
    console.log("Hello, " + name);
}
```
*上图展示了调用时实参向形参传递的过程：实参的值被动态赋给函数局部的形参变量。*

在声明函数时，写在圆括号内的变量称为**形参**（Parameter，常缩写为 `param` 或 `params`），它相当于函数内部预先声明好的局部占位符：

```javascript
function hello_with_params(name) {
  console.log("Hello, " + name);
}
```

在调用函数时，传入圆括号内的具体数据称为**实参**（Argument）。调用时，实参的值会按顺序绑定到对应的形参上：

```javascript
hello_with_params("如花");
hello_with_params("Alice");
```

执行上述代码后，函数内部通过字符串拼接运算符 `+`，动态地在控制台分别输出 `"Hello, 如花"` 与 `"Hello, Alice"`。多个参数之间使用英文逗号 `,` 分隔。

---

### 作用域与变量访问隔离

在涉及函数的程序设计中，**作用域**（Scope）是至关重要的核心概念。作用域决定了变量和函数的可见性与生命周期。在基础 JavaScript 语法中，主要划分为**全局作用域**与**局部作用域**。

- **全局作用域**（Global Scope）：在所有函数外部声明的变量具有全局作用域，被称为全局变量。全局变量在整个页面的生存周期内都可被访问。
- **局部作用域**（Local Scope，或函数作用域 Function Scope）：在函数内部声明的变量具有局部作用域，被称为局部变量。局部变量只在当前函数体内有效，函数执行完毕后即被销毁。

```text
+-----------------------------------------------------------+
| 全局作用域 (Global Scope)                                 |
|   let global_var = "全局变量";                            |
|                                                           |
|   +---------------------------------------------------+   |
|   | 局部作用域 (Local Scope)                          |   |
|   |   let local_var = "局部变量";                     |   |
|   |                                                   |   |
|   |   可访问: global_var (向上查找)                   |   |
|   |   可访问: local_var                               |   |
|   +---------------------------------------------------+   |
|                                                           |
|   可访问: global_var                                      |
|   无法访问: local_var ---> 抛出 ReferenceError 错误       |
+-----------------------------------------------------------+
```
*上图展示了作用域的单向透视隔离规则：内部作用域可以透视访问外部变量，而外部作用域无法穿透进入内部。*

#### 作用域边界代码实测

我们通过具体的变量声明与打印操作来验证这一单向可见性：

```javascript
// 全局变量声明
let global_var = "全局变量";

function local_var_function() {
  // 局部变量声明
  let local_var = "局部变量";

  // 在函数内部同时访问全局变量与自身的局部变量
  console.log("函数内打印全局变量", global_var);
  console.log("函数内打印局部变量", local_var);
}

// 触发函数调用
local_var_function();
```

调用 `local_var_function()` 时，控制台可以顺利打印出两个变量的内容，表明函数内部既可以获取局部变量，也可以向上访问全局变量。

接下来，我们在函数外部直接尝试访问这两个变量：

```javascript
console.log("全局打印全局变量", global_var);
console.log("全局打印局部变量", local_var);
```

此时控制台的第一行打印可以正常输出 `"全局打印全局变量 全局变量"`，但紧接着第二行代码会直接中断并抛出致命异常：

```text
Uncaught ReferenceError: local_var is not defined
```

> **注意**：局部变量 `local_var` 被严格封闭在 `local_var_function` 的作用域内，外部执行环境根本无法感知它的存在。这种变量隔离机制是大型程序避免命名冲突、防止全局变量污染的根本保障。

## JavaScript 事件
> 对应分集：P18 | 原始标题：《18. JavaScript 事件》

在前端开发中，静态的 HTML 负责呈现页面骨架，CSS 负责装饰视觉样式，而让网页真正“活”过来、与用户产生实时互动的关键纽带就是**事件**（Event）。正是通过事件驱动机制，JavaScript 才能捕捉用户的操作意图并作出响应，建立起 HTML、CSS 与 JS 之间的协同管道。

事件是文档或浏览器窗口中发生的**特定瞬态行为**。用户的每一次鼠标点击、键盘敲击、文本选中，或是浏览器的页面加载完毕、窗口缩放，都会作为一个事件在浏览器内部派发。

---

### 常见用户交互事件类型

JavaScript 提供了丰富的内置事件类型来监听各种维度的用户交互。在日常界面开发中，最核心、最高频的事件主要集中在鼠标行为和表单输入行为上。

| 事件属性名 | 触发时机 | 典型应用场景 |
| :--- | :--- | :--- |
| `onclick` | 鼠标点击某个元素时触发 | 按钮提交、弹窗打开、链接跳转 |
| `onmouseover` | 鼠标指针移动到元素上方时触发 | 菜单悬浮下拉、图片高亮预览 |
| `onmouseout` | 鼠标指针移出元素区域时触发 | 悬浮菜单收起、恢复初始状态 |
| `onchange` | 表单元素的值发生改变并失去焦点时触发 | 下拉列表选项切换、输入验证 |
| `onselect` | 文本框中的文本内容被选定时触发 | 选中文本快捷复制、字数统计 |
| `onfocus` | 元素获得光标焦点时触发 | 输入框提示高亮、唤起输入建议面板 |
| `onblur` | 元素失去光标焦点时触发 | 表单实时格式校验、隐藏浮层 |

> **提示**：浏览器支持的事件类型多达上百种，涵盖触摸手势、动画过渡、网络状态变化等。在学习过程中完全无需死记硬背每一个事件名称，只需彻底掌握事件的触发流向与绑定机制，具体的特定事件在需要时直接查阅技术文档即可。

---

### 事件绑定的技术途径

要让浏览器在特定事件发生时执行我们预设的 JavaScript 代码，必须将事件与具体的处理函数进行**绑定**。在前端体系中，绑定事件通常有三种实现途径：

```text
[ 用户触发物理行为 (例如点击) ]
              |
              v
     [ 浏览器派发对应事件 ]
              |
+-------------+-------------+
|                           |
| 1. HTML 行内事件属性       | ---> on<event>="func()"
| 2. DOM 元素对象属性赋值    | ---> element.on<event> = func
| 3. addEventListener 监听器| ---> element.addEventListener(...)
|                           |
+-------------+-------------+
              |
              v
     [ 调度执行关联的处理函数 ]
```
*上图展示了从用户物理操作到事件派发，再流向三种不同绑定方式的整体架构。*

1. **HTML 行内属性绑定**：直接在 HTML 标签内部写入事件属性（如 `onclick`），并将函数调用作为属性值。这种方式最为直观，也是初学者理解事件映射的最佳起点；
2. **DOM 对象属性绑定**：在 JavaScript 中先获取 DOM 节点对象，再通过对对象的事件属性（如 `element.onclick`）赋一个函数来完成绑定；
3. **`addEventListener` 事件监听方法**：现代标准规范推荐的方式，通过 DOM API 注册监听器，支持在同一元素上绑定多个同类事件监听函数。

后两种方式重度依赖 DOM 操作，而在掌握基础语法阶段，我们首先重点实践第一种行内属性绑定方式。

---

### 行内事件绑定与交互实战

事件的本质可以理解为**函数被调用的触发条件**：当特定事件发生时，相关联的函数被系统自动调用执行。

#### 鼠标点击事件绑定实操

给页面元素绑定点击事件并不局限于 `<button>` 按钮，任何合法的 HTML 标签（包括 `<div>`、`<span>`、`<p>` 等）都可以绑定点击交互。

我们首先在 `<script>` 标签内声明一个名为 `click_event` 的响应函数，在函数体中弹出一个对话框：

```javascript
function click_event() {
  alert("点击事件触发了");
}
```

紧接着在 HTML 结构中添加一个 `<button>` 元素，并使用 `onclick` 属性指向该函数：

```html
<button onclick="click_event()">这是一个点击事件按钮</button>
```

> **易错点**：在 HTML 属性中绑定函数时，属性值必须写成 `click_event()`，**不能遗漏末尾的调用圆括号**。如果只写函数名 `click_event`，浏览器在解析时不会在点击发生瞬间执行函数调用。

保存并刷新页面，用鼠标点击该按钮，屏幕立刻弹出 `"点击事件触发了"` 提示框，表明事件与函数的关联映射成功建立。

#### 表单聚焦与失焦事件实操

在用户与输入框进行交互时，常常需要在用户“点进输入框”与“点出输入框”的瞬间分别给予反馈。这两个关键节点对应着 `onfocus`（聚焦）与 `onblur`（失焦）。

一个 HTML 标签并非只能绑定单一事件，它可以**同时挂载多个不同的事件属性**。我们针对文本输入框 `<input type="text">` 编写聚焦与失焦的处理逻辑：

```javascript
function focus_event() {
  console.log("获取焦点");
}

function blur_event() {
  console.log("失去焦点");
}
```

在 HTML 标签中同时声明这两个事件处理钩子：

```html
<input type="text" onfocus="focus_event()" onblur="blur_event()">
```

将页面运行在浏览器中，按下 `F12` 打开开发者工具控制台（Console）：
1. 用鼠标点击文本框内部，光标开始闪烁，控制台立即输出 `"获取焦点"`；
2. 鼠标点击文本框外部的任意空白区域，输入框失去焦点，控制台立即跟进输出 `"失去焦点"`。

通过将事件监听挂载到页面元素上，JavaScript 便具备了感知用户行为并驱动页面响应的核心能力。
