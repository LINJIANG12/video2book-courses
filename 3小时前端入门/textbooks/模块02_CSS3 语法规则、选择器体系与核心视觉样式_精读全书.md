## CSS 简介及导入方式
> 对应分集：P08 | 原始标题：《8. CSS 简介及导入方式》

在前面的学习中，我们已经掌握了 HTML 的基本骨架与常用标签。但如果仅靠 HTML 构建页面，整个网页就会像毛坯房一样素面朝天——黑色的文字、默认的蓝色下划线超链接、生硬的排版，缺乏任何视觉美感。

要让网页真正具备商业级的外观与舒适的阅读体验，就必须引入前端技术的第二大支柱：**CSS（层叠样式表）**。

---

### 表现层定位与语法规则

在深入具体代码之前，我们需要理清 HTML 与 CSS 在现代 Web 开发体系中的分工协作关系，以及样式规则的基本书写语法。

#### 结构与表现的分工比喻

如果把开发网页比作建造一栋房屋：
* **HTML（超文本标记语言）**：相当于房屋的承重骨架与砖石结构。它定义了房屋的空间格局——承重墙立在何处、门开在哪里、窗户安在何方、楼梯如何走向。没有 HTML，页面便失去了容纳内容的物理实体。
* **CSS（层叠样式表，Cascading Style Sheets）**：相当于房屋的室内精装修。它决定了墙壁粉刷什么色调、天花板悬挂何种吊灯、门窗具有怎样的纹理、家具以何种间距与层级摆放。

要想打造一栋既稳固又宜居的现代化房屋，结构骨架与视觉装修缺一不可。

```text
+-----------------------------------------------------------+
| HTML 结构骨架 (骨架层)                                     |
| <h1>, <p>, <div>, <form>, <table>                         |
+-----------------------------------------------------------+
                             |
                      [CSS 样式装潢]
                             |
                             v
+-----------------------------------------------------------+
| 最终呈现的商业级页面 (渲染层)                             |
| 字体大小、前景色调、边框圆角、内外边距、网格流式布局      |
+-----------------------------------------------------------+
```
*图解：HTML 结构骨架与 CSS 表现装潢的协作流动关系*

#### 样式声明语法剖析

CSS 拥有一套严密且极度规整的语法格式。一条标准的 CSS 规则主要由两部分构成：**选择器（Selector）**与紧随其后的**声明块（Declaration Block）**。

```css
选择器 {
    属性名: 属性值;
    属性名2: 属性值;
}
```

```text
  p  {  color: blue;  font-size: 16px;  }
 ---    -----------   ----------------
  |          |               |
选择器     声明项 1        声明项 2
        (属性名:属性值;) (属性名:属性值;)
```
*图解：CSS 单条样式规则的组成要素拆解*

* **选择器**：用于指定当前规则要作用于哪些 HTML 元素。可以按标签名、类名或 ID 进行圈选。
* **声明块**：由一对英文大括号 `{}` 包裹。
* **声明项（Declaration）**：包含具体的“属性名（Property）”和“属性值（Value）”，二者之间用英文冒号 `:` 分隔。
* **分号终结**：每一条声明必须以英文分号 `;` 结尾。一个声明块内部可以罗列任意多条属性声明。

> **易错点**：
> 声明中的冒号与分号必须使用标准的**英文半角字符**。初学者极易在中文输入法状态下误敲入全角中文冒号（`：`）或中文分号（`；`），导致整条样式规则被浏览器直接判为语法错误而静默失效。

#### 基础样式应用与编辑器技巧

以最常用的段落标签 `<p>` 为例，若希望将页面中所有段落的字体颜色设为蓝色，字号放大为 16 像素：

```css
p {
    color: blue;
    font-size: 16px;
}
```

在前端开发编辑器（如 VS Code）中，有两项极其实用的效率技巧：
* **Emmet 属性缩写**：输入 `fs` 并按下补全键，编辑器会自动展开为 `font-size:`，无需逐字手敲长属性名。
* **快捷注释与调试**：选中 CSS 代码片段后，按下快捷键 `Ctrl + /` 即可一键切换代码注释状态（`/* ... */`）。在调试样式时，通过快速注释掉某些规则，可以直观观察样式应用与还原为默认状态的视觉对比。

### 样式导入的三种途径

在实际工程中，根据样式的复用范围与维护策略，CSS 代码可以通过三种不同的路径导入到 HTML 文档中。

#### 内联样式

内联样式（也称行内样式）是直接写在 HTML 标签自身的 `style` 属性中的样式。所有的 HTML 可见标签都天然支持 `style` 属性：

```html
<h1 style="color: red;">这是一个一级标题标签 使用内联样式</h1>
```

* **特性**：样式与具体的 HTML 标签紧紧绑死在一起。
* **适用场景**：临时测试、排查偶发视觉 Bug，或者通过 JavaScript 动态计算并直接赋予元素特定坐标与尺寸。
* **劣势**：结构与表现严重耦合，代码极其臃肿且无法在多个元素间复用，实际生产中应尽量避免大面积滥用。

#### 内部样式表

内部样式表是将 CSS 代码集中编写在 HTML 文件的 `<head>` 区域内。在 `<head>` 中开辟一对 `<style>` 标签（style 意为“样式、风格”），在标签体内部即可畅快地按照 CSS 语法规则编写选择器与声明块：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
    <meta charset="UTF-8">
    <title>内部样式表示例</title>
    <style>
        h2 {
            color: green;
        }
        p {
            color: blue;
            font-size: 16px;
        }
    </style>
</head>
<body>
    <h2>这是一个二级标题 应用内部样式</h2>
    <p>这是一个段落 应用内部样式</p>
</body>
</html>
```

* **特性**：样式集中在当前 HTML 文档的头部进行统筹管理。
* **适用场景**：单页面测试、教学演示或独立性极强的活动落地页。
* **劣势**：多页面站点无法跨网页共享同一套内部样式，页面代码量偏大。

#### 外部样式表

外部样式表是现代化大型 Web 工程中最标准、最推荐的样式组织形态。

它的核心思想是：将所有的 CSS 样式代码完全剥离，单独保存在后缀名为 `.css` 的独立文件中，然后在 HTML 的 `<head>` 内借助 `<link>` 标签建立关联并导入。

**步骤 1：创建外部样式文件**
在项目目录中（通常规范组织在 `css/` 文件夹下）新建 `style.css` 文件，直接在其中书写纯 CSS 规则，无需任何 `<style>` 标签包裹：

```css
/* 存放在 css/style.css 中 */
h3 {
    color: yellowgreen;
}
```

**步骤 2：在 HTML 头部通过 link 标签引入**
在 HTML 文档的 `<head>` 区域使用 `<link>` 标签导入该样式表。`<link>` 标签有两个核心属性：
* `rel="stylesheet"`：声明引入的文件与当前 HTML 的关联关系为“样式表（Stylesheet）”。
* `href="css/style.css"`：指示目标 CSS 文件的相对路径或绝对路径。

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
    <meta charset="UTF-8">
    <title>外部样式表示例</title>
    <link rel="stylesheet" href="css/style.css">
</head>
<body>
    <h3>这是一个三级标题 应用外部样式</h3>
</body>
</html>
```

> **提示**：
> 在 VS Code 中，只需在 `<head>` 内输入 `link:css` 并按下 `Tab` 键，编辑器即可全自动生成标准的 `<link rel="stylesheet" href="style.css">` 引入标签。

#### 三种导入方式对比

| 导入方式 | 存放位置 | 语法载体 | 适用场景 | 复用性评级 |
| :--- | :--- | :--- | :--- | :--- |
| **内联样式（行内样式）** | HTML 标签本体内 | 标签上的 `style="..."` 属性 | 快速调试、JS 动态精确控量 | 极差（仅对当前单个标签有效） |
| **内部样式表** | HTML 的 `<head>` 内部 | `<style> ... </style>` 标签 | 独立单页应用、小型教学测试 | 较差（仅在当前单页面内生效） |
| **外部样式表** | 独立于 HTML 的 `.css` 文件 | `<link rel="stylesheet" href="...">` | 商业级大型网站、工程化开发 | 极高（全站数百个页面均可共享） |

### 样式层叠机制与优先级判定

当针对同一个 HTML 元素，不同的导入途径同时为其定义了相同的样式属性（例如同时定义了字体颜色），浏览器究竟会听谁的？

这就涉及到 CSS 名字中蕴含的核心算法——**层叠（Cascade）与优先级（Priority）**。

#### 优先级层级法则

在选择器权重一致的基本前提下，不同导入途径的优先级层级如下：

$$\text{内联样式} > \text{内部样式表} \ge \text{外部样式表}$$

* **内联样式具备至高话语权**：因为内联样式直接挂载在元素标签上，距离元素最近，因此其权重最高。任何在 `<style>` 或外部 `.css` 文件中声明的普通规则，都无法撼动内联样式的生效。
* **内部样式与外部样式的覆盖关系**：内部样式表和外部样式表的层级在同等权重下遵循“后来者居上”的代码解析顺序。在标准编写习惯中，内部 `<style>` 标签写在 `<link>` 标签之后，因此内部样式表可以覆盖外部样式表中的同名属性。

#### 覆盖行为实操推导

我们可以通过一组递进实验来验证这套覆盖机制：

**场景 1：内部样式表试图覆盖内联样式**
页面中的 `<h1>` 标签已经通过内联设置了红色：

```html
<h1 style="color: red;">一级标题</h1>
```

此时即便在 `<head>` 的 `<style>` 内部样式表中追加规则：

```css
h1 {
    color: white;
}
```

刷新浏览器后，`<h1>` 的文字颜色依然坚定地保持为红色。这是因为内联样式的优先级远高于内部样式表，内部规则被彻底压制。

**场景 2：内部样式表覆盖外部样式表**
在外部 `css/style.css` 中，为 `<h3>` 标签指定了黄绿色：

```css
/* css/style.css */
h3 {
    color: yellowgreen;
}
```

而在引入该文件的 HTML `<head>` 中，于 `<link>` 之后声明内部样式：

```html
<link rel="stylesheet" href="css/style.css">
<style>
    h3 {
        color: aqua;
    }
</style>
```

页面渲染时，`<h3>` 的字体颜色将呈现为青色（`aqua`），外部样式表中的 `yellowgreen` 被内部规则成功覆盖。

**场景 3：内联样式的终极压制**
若进一步在 `<h3>` 标签身上追加行内属性：

```html
<h3 style="color: orange;">这是一个三级标题</h3>
```

无论外部样式表写了 `yellowgreen`，还是内部样式表写了 `aqua`，浏览器最终都会以标签本体上的 `orange` 为最终渲染依据。理解这套优先级层叠秩序，是后续排查复杂样式冲突与覆盖故障的必备武器。

## CSS 选择器
> 对应分集：P09 | 原始标题：《9. CSS 选择器》

在刚接触 CSS 时，我们通常直接使用标签名称作为选择器，比如直接写 `p` 或 `h1`。但在真实的商业级网页中，页面往往包含成百上千个段落与容器。如果我们只想改变其中某一个特定段落的字体颜色，单纯使用标签选择器就会导致全站所有段落被“一刀切”地全部改变。

要想随心所欲地控制网页细节，关键就在于掌握 **CSS 选择器（Selectors）**。选择器的本质是定位引擎——它负责在庞大的 HTML 节点树中，精准抓取出我们想要施加样式的目标元素。

---

### 基础标识选择器

最基础的选择器直接基于元素自身的标签名、类名、ID 或全量通配符进行匹配。

#### 元素选择器

元素选择器（也称标签选择器）直接以 HTML 标签名作为选择器标识：

```html
<h2>这是一个元素选择器示例</h2>
```

```css
h2 {
    color: aqua;
}
```

* **匹配规则**：页面中所有的 `<h2>` 元素都会无差别地被选中，并统一渲染为天蓝色（`aqua`）。
* **局限性**：颗粒度过粗，无法实现同一类型标签之间的个性化视觉差异。

#### 类选择器

为了给同一种标签赋予不同的外观，我们需要引入类选择器（Class Selector）。

在 HTML 标签中通过 `class` 属性挂载自定义类名（例如 `highlight`），在 CSS 中则通过以英文点号 `.` 开头的类选择器进行匹配：

```html
<h3 class="highlight">这是一个类选择器示例</h3>
<h3>另一个类选择器示例</h3>
```

```css
.highlight {
    background-color: yellow;
}
```

* **精准隔离**：此时只有第一个带有 `class="highlight"` 的 `<h3>` 标签会被施加黄色背景，而第二个普通的 `<h3>` 标签完全不受影响。
* **复用特性**：同一个类名可以赋予任意多个不同的 HTML 标签，一个标签上也可以同时挂载多个用空格分隔的类名。类选择器是日常前端开发中使用频率最高的核心武器。

#### ID 选择器

ID 选择器用于匹配具有唯一标识符的特定元素。

在 HTML 标签中使用 `id` 属性命名（例如 `header`），在 CSS 中以英文井号 `#` 开头定位：

```html
<h4 id="header">这是一个 ID 选择器示例</h4>
```

```css
#header {
    font-size: 35px;
}
```

> **注意**：
> 按照 W3C 规范，同一个 HTML 页面中，每个元素的 `id` 必须具备全局唯一性，不得在多个元素上复用同一个 ID。ID 选择器主要用于页面核心顶级容器或配合 JavaScript 进行唯一节点抓取。

#### 通用选择器

通用选择器使用单个星号 `*` 表示，它能够无条件匹配当前 HTML 文档中的每一个元素：

```css
* {
    font-family: '楷体';
    font-weight: bolder;
}
```

* **作用机制**：整张网页上的所有标题、段落、链接、表格及容器元素，都会一次性被统一应用楷体字体与字体加粗效果。
* **常见用途**：快速重置全页面的默认边距，或者全局统一样式基准。

---

### 节点层级与关系选择器

当单个选择器不足以表达层级约束时，CSS 提供了复合的关系选择符。关系选择器涉及到多层节点的拓扑关系，选择器中通常由多个标签或标识符组合构成。

#### 子元素选择器与直接子代

子元素选择器（Child Combinator）使用大于号 `>` 连接父级与子级，**专门用于选择作为某元素直接子代的元素**：

```html
<div class="father">
    <p class="son">这是一个子元素选择器示例</p>
</div>
```

```css
.father > p {
    color: yellowgreen;
}
```

外层的 `<div>` 是父容器，内部的 `<p>` 是其直接子代（儿子辈）。通过 `.father > p`，可以精准将文字颜色设为黄绿色（`yellowgreen`）。

#### 后代选择器与包含匹配

后代选择器（Descendant Combinator）使用**英文空格**连接祖先与后代：

```html
<div class="father">
    <p class="son">这是一个子元素选择器示例</p>
    <div>
        <p class="grandson">这是一个后代选择器示例</p>
    </div>
</div>
```

```css
.father p {
    color: brown;
    font-size: larger;
}
```

#### 子代与后代的本质区别

许多初学者容易混淆子代与后代的边界：

```text
+-----------------------------------------------------------+
| <div class="father"> (祖先 / 父级)                        |
|                                                           |
|   ├── <p class="son"> (直接子代: 儿子辈)                  |
|   |                                                       |
|   └── <div> (中间容器: 儿子辈)                            |
|         └── <p class="grandson"> (深层后代: 孙子辈)       |
+-----------------------------------------------------------+
```
*图解：DOM 树形层级中的直接子代（>）与深层后代（空格）拓扑关系*

* **子代（直接子代）**：只有第一层的 `<p class="son">` 是 `.father` 的直接子代；内层嵌套中的 `<p class="grandson">` 属于“孙子辈”，不能算作 `.father` 的直接子代。
* **后代（包含范围）**：无论是第一层的“儿子辈”还是深层的“孙子辈”，全部属于 `.father` 的后代。
* **核心规律**：**后代选择器天然包含子代，但子代选择器绝不穿透匹配深层后代**。

> **提示**：
> 当后代选择器 `.father p`（赋予棕色）与更具体的子选择器 `.father > .son`（赋予黄绿色）同时作用于 `<p class="son">` 时，由于类选择器的优先级高于纯标签选择器（$\text{类} > \text{标签}$），子代 `<p>` 将依然保持其专属的黄绿色。

#### 相邻兄弟选择器

相邻兄弟选择器（Adjacent Sibling Combinator）使用加号 `+` 连接同级元素：

```html
<p>这是一个普通的 p 标签</p>
<h3>这是一个相邻兄弟选择器示例</h3>
<p>这是另一个 p 标签</p>
```

```css
h3 + p {
    background-color: red;
}
```

* **严格匹配规则**：`h3 + p` **只会选中紧随在 `<h3>` 之后的第一个同级 `<p>` 元素**。位于 `<h3>` 上方的 `<p>` 标签，或者后续更远处的 `<p>` 标签，都不会被施加红色背景。

### 状态伪类与虚拟伪元素

除了根据固有的静态节点结构进行选择外，CSS 还支持根据元素当前所处的瞬时状态或在 DOM 中动态注入虚拟内容。

#### 交互伪类与 hover 动效

伪类选择器（Pseudo-classes）以单冒号 `:` 开头，专门用于选取处于特定交互状态或特殊文档结构的元素。

最典型的应用是鼠标悬停状态 `:hover`：

```html
<h3 id="element">这是一个伪类选择器示例</h3>
```

```css
#element:hover {
    background-color: purple;
}
```

当用户的鼠标指针滑入并悬浮在该标题元素上方时，整行背景会即时变为紫色；鼠标移开后，背景色即刻还原。

此外，常用的伪类还包括：
* `:active`：元素被鼠标点击并按住不放时的激活瞬间。
* `:first-child`：匹配父容器内部的第一个子元素。
* `:nth-child(n)`：匹配父容器内部第 $n$ 个特定位置的子元素。

#### 虚拟伪元素 before 与 after

伪元素选择器（Pseudo-elements）以双冒号 `::` 开头，它不是去抓取已有的真实 HTML 标签，而是在 DOM 结构中生成一个不可见或可修饰的“虚拟元素”：

* `::before`：在目标元素内部的真实内容之前插入虚拟内容。
* `::after`：在目标元素内部的真实内容之后插入虚拟内容。

伪元素通常用于在不增加冗余 HTML 标签的前提下，向页面追加小图标、装饰性线条或清除浮动。

### 选择器语法与匹配速查对照

| 选择器类型 | 语法格式 | 示例 | 匹配目标与范围说明 |
| :--- | :--- | :--- | :--- |
| **元素选择器** | `标签名` | `h2` | 匹配页面中所有同名的 `<h2>` 元素 |
| **类选择器** | `.类名` | `.highlight` | 匹配所有带有 `class="highlight"` 的元素 |
| **ID 选择器** | `#标识符` | `#header` | 匹配 `id="header"` 的唯一特定元素 |
| **通用选择器** | `*` | `*` | 匹配当前文档树中的所有元素 |
| **子元素选择器** | `E > F` | `.father > p` | 仅匹配作为 `E` 元素直接子代（儿子辈）的 `F` 元素 |
| **后代选择器** | `E F` | `.father p` | 匹配作为 `E` 元素内部任意层级的后代 `F` 元素 |
| **相邻兄弟选择器**| `E + F` | `h3 + p` | 仅匹配紧跟在 `E` 元素后面且同级的第一个 `F` 元素 |
| **状态伪类选择器**| `E:状态` | `#element:hover` | 匹配当鼠标光标悬停在目标元素上的交互状态 |
| **虚拟伪元素选择器**| `E::伪元素`| `p::before` | 在目标元素内容的前部注入虚拟修饰内容 |

## CSS 常用属性
> 对应分集：P10 | 原始标题：《10. CSS 常用属性》

在掌握了 CSS 的选择器语法后，我们已经能够随心所欲地圈选出页面上的任何目标元素。接下来的核心问题便是：在样式规则的大括号 `{}` 内部，究竟可以书写哪些属性来精确控制元素的外观？

打开各类 Web 技术手册或规范文档，CSS 的属性有成百上千个。但这绝不意味着我们需要死记硬背每一个属性。在实际工程中，大量生僻属性要么功能重叠，要么极少被用到。我们只需扎实吃透一小批最高频、最基础的核心属性，就足以应对日常开发中绝大多数排版需求。

---

### 字体与排版样式属性

文字是网页承载信息的核心。控制文字字号、粗细、字体系列以及行间距，是排版的基本功。

#### 单一字体属性与复合属性 font

在 CSS 中，与字体相关的属性形成了一个完整的体系。常见的单一字体属性包括：
* `font-family`：定义字体系列（如 `'楷体'`、`'Microsoft YaHei'`、`'Arial'`）。
* `font-size`：定义字体大小（如 `16px`、`50px` 或 `larger`）。
* `font-weight`：定义字体粗细（如 `normal`、`bold`、`bolder`）。
* `font-style`：定义字体样式（如 `normal`、`italic` 斜体）。

除了单独书写上述属性外，CSS 提供了一个强大的**复合属性（Shorthand Property）——`font`**。

复合属性允许我们用一行简短的声明，同时定义多个维度的样式值：

```html
<h1 style="font: bolder 50px 楷体;">这是一个 font 复合属性示例</h1>
```

上述单行复合属性，在逻辑上完全等价于以下三条独立的属性声明：

```css
h1 {
    font-weight: bolder;
    font-size: 50px;
    font-family: 楷体;
}
```

> **提示**：
> 使用复合属性能够显著压缩 CSS 代码体积，保持样式表的凝练。但在书写 `font` 复合属性时，必须严格保持参数格式（通常尺寸与字体系列是不可或缺的核心项）。

#### 文本行高 line-height

当一段长文本在容器内部发生自然折行时，如果仅采用浏览器默认样式，行与行之间的文字往往会紧密地挤在一起，造成极差的视觉压迫感与阅读体验。

此时可以通过 `line-height`（行高）属性来从容调节行间距：

```html
<p style="line-height: 40px;">
    这是一段较长的测试文本内容，当段落长度超出容器宽度时会自动折行显示。
    通过设置适宜的行高，能够有效撑开行与行之间的物理距离，大幅提升排版通透度。
</p>
```

将行高设定为 `40px` 后，文字上下行之间的呼吸感被彻底拉开，页面的易读性显著提高。

### 尺寸属性与三大显示模式

在调整元素的宽高尺寸（`width` 与 `height`）时，初学者经常会遭遇“某些元素设置了宽高却毫无反应”的困惑。这一现象背后，关系到 CSS 最根本的底层机制——**元素显示模式（Display Modes）**。

网页元素在渲染引擎中并非一视同仁，而是被划分为块级元素、行内元素以及行内块元素三大阵营。

```text
+-----------------------------------------------------------+
| 块级元素 (block): 独占整行, 显式 width/height 生效        |
+-----------------------------------------------------------+

+--------------------+  +--------------------+
| 行内块 (inline-block)|  | 行内块 (inline-block)|  水平并排，宽高均生效
+--------------------+  +--------------------+

[行内元素(inline): 宽高设置无效, 仅依内容自适应包裹] [行内2] 水平紧随
```
*图解：块级、行内块与行内元素在屏幕上的占位模式与排列行为对比*

#### 块级元素（Block）

* **典型代表**：`<div>`、`<p>`、`<h1>` ~ `<h6>`、`<ul>`、`<form>` 等。
* **排列方式**：天然从新的一行开始排列，默认占满其父容器整行的全部宽度（100% 宽度）。
* **尺寸响应**：**能够自由显式定义 `width` 与 `height`**。定义后虽然视觉上变成固定方块，但其所在的水平行依然被霸占，后续元素依然会被排挤折行。
* **容纳规则**：内部既可以包含其他块级元素，也可以容纳行内元素。

#### 行内元素（Inline）

* **典型代表**：`<span>`、`<a>`、`<strong>`、`<em>` 等。
* **排列方式**：在同一水平行内自左向右依次顺次紧挨着排列，绝不独占一行。
* **尺寸响应**：**无法通过 CSS 显式设置 `width` 与 `height`**！无论在样式表里写多大的宽高数值，浏览器都会直接忽略，其尺寸完全由内部包含的文本或子元素内容自适应撑开。
* **容纳规则**：仅能容纳纯文本或其他行内元素，不允许直接包裹块级元素。

#### 行内块元素（Inline-block）

* **典型代表**：`<img>`、`<input>`、`<button>` 等。
* **特性融合**：行内块元素巧妙地汲取了前两者的长处：
  1. **像行内元素一样排列**：可以和其它元素在同一水平行内并排显示，不强制折行。
  2. **像块级元素一样响应尺寸**：**能够自由设置 `width`、`height`** 以及内边距外边距。
* **工程价值**：电商网站中的商品橱窗卡片列表、社交媒体的个人名片网格，每一个卡片既有确定的宽、高、背景和内部多行图文，又能并排水平排布，它们的核心机制正是行内块模型。

#### 三类元素特征对比

| 元素分类 | 默认排版方式 | 能否设置 width / height | 默认宽度特征 | 常见标签 |
| :--- | :--- | :--- | :--- | :--- |
| **块级元素（block）** | 独占一整行，新起一行 | **可以**正常生效 | 撑满整行（父容器 100% 宽） | `<div>`, `<p>`, `<h1>` |
| **行内元素（inline）** | 同行水平紧随排列 | **不能**（设置无效） | 严格由内容本身宽度自适应决定 | `<span>`, `<a>`, `<strong>` |
| **行内块元素（inline-block）** | 同行水平并排排列 | **可以**正常生效 | 默认由内容决定，可被显式覆盖 | `<img>`, `<input>` |

### 显示模式转换与 display 属性

在页面重构过程中，标签的原生类型并不是绝对焊死的。如果需要让一个无语义的 `<div>` 像文字一样同行排列，或者让一个 `<span>` 拥有独立的宽度和高度，就必须使用 **`display` 属性**执行显示模式的动态转换。

#### 块级转行内 display: inline

默认情况下，`<div>` 是块级元素，背景色会撑满整行。如果希望其表现得和 `<span>` 完全一致，仅包裹文字且同行排列：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
    <meta charset="UTF-8">
    <style>
        .div-inline {
            display: inline;
            background-color: blue;
        }
    </style>
</head>
<body>
    <div class="div-inline">这是一个转换成行内元素的 div 标签</div>
</body>
</html>
```

* **转换后行为**：一旦加上 `display: inline;`，`<div>` 标签立刻放弃对整行的霸占，其宽度立即向内自适应收缩包裹文字，其原本设置的宽高也将失效。

#### 行内转行内块 display: inline-block

在前端开发中，极其频繁的操作是将行内的 `<span>` 标签转换为行内块，以便能够为其设置固定的物理尺寸与背景色：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
    <meta charset="UTF-8">
    <style>
        .span-inline-block {
            display: inline-block;
            background-color: #8a2be2;
            width: 300px;
            height: 60px;
        }
    </style>
</head>
<body>
    <span class="span-inline-block">转换成行内块元素的 span</span>
</body>
</html>
```

* **转换后行为**：原本对宽高毫无反应的 `<span>`，在声明 `display: inline-block;` 之后，`width: 300px` 与 `height: 60px` 立即精准生效，同时它依然保留在行内水平流中。

#### 行内转块级 display: block

如果需要让原本是行内的标签（如 `<span>` 或 `<a>`）具备独占整行的能力：

```css
.span-to-block {
    display: block;
    background-color: #8a2be2;
}
```

* **转换后行为**：该元素在渲染树中被提升为标准块级模型，背景色横向铺满整行，后续兄弟元素被强制挤到下一行。

#### 元素隐藏 display: none

除了上述三种模式转换外，`display` 属性还有一个极具破坏力的常用属性值——`none`：

```css
.hidden-box {
    display: none;
}
```

* **作用机制**：将目标元素从渲染树中完全抽离隐藏。它与将透明度设为 0 不同，`display: none` 会让元素不仅在视觉上彻底隐形，而且在页面布局中**不再占据任何物理空间**，后面的元素会立即顶替它的原有位置。常用于配合 JavaScript 制作折叠面板、下拉菜单或弹窗的显示与隐藏切换。
