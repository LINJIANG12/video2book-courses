## 前端简介
> 对应分集：P01 | 原始标题：《1. 前端简介》

Web 前端是构建现代互联网世界的关键一环。无论你是打算为个人项目搭建一个展示主页，还是为企业研发大规模的 Web 应用程序，前端开发都是一项极具潜力且令人兴奋的技能。对于非计算机专业或者打算转行做程序员的朋友来说，前端也是进入互联网软件开发的绝佳选择——因为它的入门门槛低、见效快，每一行代码的变动都能立刻在屏幕上得到视觉反馈。

### Web 前端开发范畴

很多初学者容易把“前端”和“网页”这两个概念混为一谈。我们在真正动手写代码前，必须先厘清二者的本质关系与技术边界：

> **定义**：
> - **网页（Web Page）**：在浏览器中承载并呈现具体内容的文档或界面。
> - **前端开发（Front-End Development）**：负责构建网页中所有用户可见、可感知以及可与之发生交互的内容与逻辑的技术体系。

说白了，前端程序员的核心工作就是做网页。我们日常在浏览器中随意打开一个网站，映入眼帘的文字排版、插图、点击按钮，乃至音频与视频播放器，全都是前端的呈现范畴。甚至我给你们授课时演示的幻灯片课件，本质上也是完全基于前端技术搭建起来的网页。

用户在浏览器里所看到的一切排版、颜色、动态切换，背后都是由前端代码在支撑与驱动。

### 浏览器勘验与开发者工具

只要你的电脑上安装了现代浏览器（推荐使用 Google Chrome），你就已经拥有了最强大的前端调试与逆向学习工具。

当我们想探究任何一个现成网页底层是如何实现时，不需要安装任何额外的反编译软件，直接借助浏览器自带的能力即可透视其结构：

```text
+-------------------------------------------------------------+
| 网页可视渲染区 (用户界面)                                     |
|  [ 标题文字 ]   [ 视频封面 ]   [ 点击播放按钮 ]              |
+-------------------------------------------------------------+
                              |
                     按 F12 或 鼠标右键
                              v
+-------------------------------------------------------------+
| Chrome 开发者工具 (DevTools)                                |
|  [Elements 元素面板]         | [Styles 样式面板]             |
|   <div class="header">       |  .header {                   |
|     <button>播放</button>    |     background: #ffcc00;     |
|   </div>                     |  }                           |
+-------------------------------------------------------------+
```
*浏览器通过 DevTools 将直观视图与底层代码实时映射*

#### 源码查看与元素审查

在浏览器任意网页区域，我们主要有两种观察底层代码的方式：

1. **查看网页源代码**：在网页空白处点击鼠标右键，选择“查看网页源代码”（View Page Source）。浏览器会新建一个标签页，展示服务器直接下发给浏览器的原始 HTML 文本。
2. **审查页面元素（Elements 面板）**：在键盘上直接按下快捷键 `F12`（Mac 系统通常为 `Cmd + Option + I`），或者在页面特定控件上右键选择“检查”（Inspect）。此时浏览器会弹出“开发者工具”，在“Elements”（元素）选项卡下，可以实时选中任意 DOM 节点，观察其对应的代码块，并在右侧直接联动查看它所生效的样式规则。

> **提示**：快捷键 `F12` 是每一个前端开发者每天使用频率最高的按键。通过元素审查，你能直观看到页面上每一个按钮的盒模型、色彩值以及结构层级，这是后续调试与排错的基本功。

### 网页核心技术三要素

一个标准的现代网页，是由三种核心技术协同构建而成的：HTML、CSS 以及 JavaScript（通常简称为 JS）。这三者各司其职，形成了稳固的技术三角。

```text
+-------------------------------------------------------+
|                    完整 Web 网页                      |
+-------------------------------------------------------+
| 表现层：CSS (层叠样式表)                                |
|   -> 负责视觉修饰：背景色彩、字号行距、弹性布局、圆角阴影 |
+-------------------------------------------------------+
| 结构层：HTML (超文本标记语言)                           |
|   -> 负责骨架内容：页面标题、段落文本、图像媒体、超链接   |
+-------------------------------------------------------+
| 行为层：JavaScript (脚本语言)                         |
|   -> 负责动态交互：点击响应、数据校验、异步加载、动态渲染 |
+-------------------------------------------------------+
```
*网页三大核心技术分层协作架构*

#### 结构层：HTML

HTML（HyperText Markup Language，超文本标记语言）负责定义页面的骨架结构与信息载体。

它就像建造大楼时的钢筋混凝土框架，或者人体中的骨骼系统。你在页面中看到的标题文本、段落句子、图片容器、视频嵌入播放区域、超链接导航以及表单输入框，都是由 HTML 标签逐一声明构建的。没有 HTML，页面就没有任何可展示的内容实体。

#### 样式层：CSS

CSS（Cascading Style Sheets，层叠样式表）负责定义页面的视觉样式与版面布局。

如果只有 HTML，页面呈现出来的将是浏览器最原始的黑白纯文本与杂乱排布。而页面为什么某个按钮是醒目的亮黄色而其他背景保持沉稳的深黑？为什么主标题是灰色而下方正文呈现纯白？为什么各个组件能够在屏幕中整齐并列排列而不是纵向死板堆叠？这些视觉表现全部由 CSS 代码控制。

在开发者工具的右侧面板（Styles 面板）中，我们可以直接实时修改 CSS 属性，即时查看颜色、尺寸与边距的实时变化。

#### 行为层：JavaScript

JavaScript 是赋予网页生机与活力的脚本编程语言，负责处理用户交互与动态逻辑。

当用户点击一个按钮需要弹出对话框、提交表单时需要验证输入内容是否合法、滚动页面时需要无刷新加载下一页数据，或者轮播图自动滑动切换时，背后均是由 JavaScript 在监听事件并操作底层数据与界面呈现。

#### 核心技术分工对比

为了更直观地理解三者的分工与协作关系，我们可以通过以下对照进行记忆：

| 技术名称 | 角色定位 | 核心职责 | 直观生活类比 | 浏览器中的直接体现 |
| :--- | :--- | :--- | :--- | :--- |
| **HTML** | 结构层（Structure） | 组织网页结构，承载文本、图像、音视频等内容 | 毛坯房的毛坯墙体与承重梁 | 开发者工具左侧的标签节点树 |
| **CSS** | 表现层（Presentation） | 控制排版视觉、色彩搭配、尺寸边距与动画特效 | 房屋的精装修、刷墙漆、地砖软装 | 开发者工具右侧的样式属性列表 |
| **JavaScript** | 行为层（Behavior） | 监听交互事件，处理业务逻辑，实现动态数据交互 | 房屋内的智能家居系统与电路开关 | 控制台输出（Console）与脚本执行 |

掌握了这三者的分工逻辑，我们就建立起了对 Web 前端整体运作的全局认知。接下来，我们将正式开始配置前端开发环境，安装高效的代码编辑器，开始敲下第一行前端代码。

## 安装 VSCode 开发环境
> 对应分集：P02 | 原始标题：《2. 安装 VSCode 开发环境》

工欲善其事，必先利其器。学习前端开发并不需要搭建笨重的集成开发环境（IDE），轻量、高效且生态繁荣的 Visual Studio Code（简称 VS Code）是目前前端领域最主流的代码编辑器。接下来我们从零开始完成 VS Code 的安装、中文语言汉化，以及三款核心前端提效插件的配置。

### 编辑器获取与安装细节

在浏览器中直接搜索 `VS Code`，访问微软官方网站进行下载。官网会根据你的操作系统（如 Windows、macOS）自动识别并推荐最适配的安装包，直接点击下载即可。

下载完成后运行安装程序，安装流程中有几个关键步骤需要特别注意：

```text
+-----------------------------------------------------------+
| VS Code 安装向导关键路径                                   |
+-----------------------------------------------------------+
| 1. 许可协议      -> 勾选“我同意此协议”                    |
| 2. 目标位置      -> 自定义或保留默认安装路径              |
| 3. 开始菜单文件夹 -> 保持默认，点击下一步                  |
| 4. 选择附加任务  -> 【关键】务必将页面中的选项全部勾选！   |
| 5. 准备安装      -> 点击安装，等待解压写入完成            |
+-----------------------------------------------------------+
```
*VS Code 安装向导执行流程*

#### 安装向导附加任务选项

在进入“选择附加任务”界面时，安装向导会列出多项系统集成功能：

> **易错点**：很多初学者习惯一路狂点“下一步”，导致错过了“选择附加任务”面板。在这个界面，**务必把所有勾选框全部勾上**。

勾选所有附加选项的核心价值在于：
- **资源管理器上下文菜单**：勾选“将‘通过 Code 打开’操作添加到 Windows 资源管理器文件上下文菜单”以及“目录上下文菜单”后，后续在电脑任何文件夹空白处或右键某个项目文件夹时，都可以直接点击“通过 Code 打开”，瞬间在该目录下启动编辑器。
- **添加到 PATH**：勾选后可以在终端命令行中直接输入 `code .` 打开当前工作区，极大提升后续日常开发的便利性。

### 界面汉化与语言包安装

初次启动 VS Code 时，默认界面为全英文。对于刚刚接触编程的初学者来说，全英文菜单容易增加不必要的理解负担，我们先安装官方中文语言包。

```text
+-------------------------------------------------------------+
| VS Code 左侧活动栏 (Activity Bar)                            |
|  [ 资源管理器 ]                                             |
|  [ 全局搜索   ]                                             |
|  [ 源代码管理 ]                                             |
|  [ 运行和调试 ]                                             |
|  [ 扩展插件   ] <--- 点击扩展图标 (Extensions / Ctrl+Shift+X) |
+-------------------------------------------------------------+
```
*VS Code 左侧活动栏中的扩展入口*

#### 中文插件安装流程

1. 点击左侧活动栏的 **Extensions（扩展）** 图标（或按下快捷键 `Ctrl + Shift + X`）。
2. 在顶部的插件搜索框中输入 `Chinese`。
3. 在检索结果中认准排在第一位、由 Microsoft 官方发布的 `Chinese (Simplified) (简体中文)` 语言包。
4. 点击 **Install** 按钮进行安装。
5. 安装完毕后，编辑器右下角会弹出提示框询问是否更改语言并重启（`Change Language and Restart`），点击重启按钮，VS Code 重新加载后即呈现完整的中文界面。

> **提示**：在 VS Code 插件市场中检索插件时，一定要认准微软官方认证标识与下载量。官方简体中文包的下载量高达数千万，认准高下载量与官方作者能够有效避免误装第三方仿冒扩展。

### 前端核心辅助插件配置

中文界面配置就绪后，我们还需要为 VS Code 武装三款前端开发的“神兵利器”。它们分别负责智能样式提示、实时页面热重载以及标签同步重命名。

```text
+-----------------------------------------------------------------+
|                       前端必备提效插件矩阵                       |
+-----------------------------------------------------------------+
| 1. HTML CSS Support                                             |
|    -> CSS 类名自动补全与关联定位，写样式时的快捷辅助            |
+-----------------------------------------------------------------+
| 2. Live Server                                                  |
|    -> 搭建本地轻量开发服务器，代码修改保存即触发浏览器热更新     |
+-----------------------------------------------------------------+
| 3. Auto Rename Tag                                              |
|    -> 修改 HTML 起始标签时，末尾闭合标签自动联动同步修改         |
+-----------------------------------------------------------------+
```
*前端核心提效插件分工示意*

#### 样式快捷补全：HTML CSS Support

在扩展面板中搜索 `HTML CSS Support` 并点击安装。

这个插件是编写 CSS 样式时的代码补全神器。它可以自动扫描当前项目工程中的 CSS 文件以及 HTML 内部样式，当你在 HTML 标签中编写 `class` 或 `id` 属性时，它会实时弹出候选类名列表，避免手动拼写属性导致的错打与样式失效。

#### 页面实时热更新：Live Server

在扩展面板中搜索 `Live Server`，选择下载量超过 4000 万的官方首选版本点击安装。

> **定义**：**Live Server** 是一个能在本地快速启动小型开发服务器的扩展。它为静态网页提供了实时热重载（Hot Reload）能力。

在没有安装该插件前，我们在编辑器中修改完 HTML 或 CSS，必须切换到浏览器窗口，手动按下 `F5` 或刷新按钮才能看到最新改动。而有了 Live Server 之后：
- 我们只需在 HTML 文件上右键选择 **Open with Live Server**；
- 浏览器会自动拉起本地服务页面（默认地址为 `http://127.0.0.1:5500/...`）；
- 之后每当你在编辑器中按下 `Ctrl + S` 保存代码，浏览器无需手动刷新，页面会自动同步更新渲染结果，实现真正的“所见即所得”。

#### 标签自动同步闭合：Auto Rename Tag

在扩展面板中搜索 `Auto Rename Tag` 并点击安装。

在编写 HTML 代码时，绝大多数标签都是成对出现的（如 `<div></div>`、`<h1></h1>`）。如果不使用辅助插件，当你后续想要将一个 `<h1>` 标题修改为 `<h2>` 时，必须手动修改开头的 `<h1>`，再移动光标到末尾修改闭合的 `</h1>`。一旦漏改或者打错，就会造成 HTML 标签嵌套错乱。

`Auto Rename Tag` 彻底解决了这一痛点：当你修改前置开始标签的名称时，配对的后置闭合标签会实时自动重命名，杜绝了标签不匹配的低级语法错误。

#### 核心插件功能与收益对照

| 插件名称 | 核心功能 | 解决痛点 | 效率收益 |
| :--- | :--- | :--- | :--- |
| **Chinese (Simplified)** | 编辑器全量汉化 | 降低英文界面带来的阅读认知阻碍 | 快速熟悉各菜单与设置项 |
| **HTML CSS Support** | 样式类名联想与代码补全 | 记忆复杂 CSS 类名费时、手动输入容易错拼 | 敲出首字母即可回车上屏 |
| **Live Server** | 本地热重载开发服务器 | 编辑代码后需频繁手动切换浏览器刷新的机械重复 | 保存代码即刻看到页面最新呈现 |
| **Auto Rename Tag** | 成对 HTML 标签联动重命名 | 漏改闭合标签导致的页面布局塌陷与结构混乱 | 只需修改一次，头尾双向自动同步 |

完成以上步骤后，我们的前端开发工作台便已全部武装完毕。接下来，我们将正式新建工程文件，剖析 HTML 的核心骨架结构。

## HTML 简介及环境搭建
> 对应分集：P03 | 原始标题：《3. HTML 简介及环境搭建》

开发环境准备就绪后，我们正式进入前端的第一块基石——HTML 的学习。网页之所以能够层次分明地展现出文章标题、段落、列表乃至输入框，其核心在于遵循了超文本标记语言的语法规则。接下来我们将剖析 HTML 标签体系、解构标准文档骨架，并在 VS Code 中通过工程化手段快速完成页面初始化。

### 超文本标记语言机制与标签体系

HTML 的全称为 **HyperText Markup Language**（超文本标记语言）。我们不需要去死记硬背枯燥的语法定义，只需抓住它的核心本质：**HTML 的唯一使命就是为网页提供结构**。

浏览器本身并不知道哪段文字是重要的一级标题、哪段是正文段落、哪部分是供用户输入的控件。我们需要通过各种具有语义的**标签（Tag）**，将普通的纯文本包裹起来，明确告知浏览器各个文本块的逻辑角色。

```text
+-----------------------------------------------------------+
| 双标签结构剖析 (Element with Content)                      |
|                                                           |
|    <p>             这是一段网页正文内容              </p>    |
|   -----            --------------------            ------ |
|  开始标签                内部文本内容               结束标签|
+-----------------------------------------------------------+
| 单标签结构剖析 (Void Element)                             |
|                                                           |
|   <input>                  或                  <br>       |
|    -----                                       ----       |
|   独立标签                                   独立标签     |
+-----------------------------------------------------------+
```
*HTML 双标签与单标签结构示意*

#### 双标签语法

在 HTML 中，绝大多数标签都是成对出现的，我们称之为**双标签**：
- 它由一个**开始标签**（形如 `<tagName>`）和一个带反斜杠的**结束标签**（形如 `</tagName>`）组合而成；
- 双标签用于**包含具体内容**的元素，实际要呈现的文字、媒体或子标签嵌套包裹在两者之间。

典型示例：
- 一级标题标签：`<h1>网页主标题</h1>`
- 段落标签：`<p>这是文章的一个自然段落。</p>`
- 超链接标签：`<a>点击跳转链接</a>`

#### 单标签语法

与双标签相对的是**单标签**（也称为空元素）。单标签顾名思义没有配对的结束标签，只有一个单独的标签标记存在。
- 单标签用于**自身不包含文本内容或子节点**的场景，它的作用通常是插入一个特定的独立控件，或者在页面中产生一个占位/排版动作。

典型示例：
- 用户输入框：`<input>`
- 文本强制换行：`<br>`
- 水平分割线：`<hr>`

#### 标签类型特征对比

| 标签类别 | 闭合方式 | 核心应用场景 | 常见代表标签 | 是否包裹内容 |
| :--- | :--- | :--- | :--- | :--- |
| **双标签** | 成对闭合（`<tag>...</tag>`） | 承载文本段落、标题容器、列表与布局结构 | `<h1>`、`<p>`、`<a>`、`<div>` | 是（内部承载文本或嵌套子标签） |
| **单标签** | 单独存在（`<tag>`） | 插入表单输入组件、物理换行、分割线等独立占位 | `<input>`、`<br>`、`<hr>`、`<img>` | 否（仅声明元素本身） |

### HTML 文档标准骨架

一个合法且标准的前端 HTML 文档，有着严格的层级嵌套结构。每一个标准页面均由文档声明、根节点、文档头部与文档主体四个核心层次构成。

```text
+-------------------------------------------------------------+
| <!DOCTYPE html>             <- 文档类型声明 (HTML5标准规范)    |
| <html lang="en">            <- 根元素容器 (最外层根节点)       |
|   <head>                    <- 头部标签 (元数据，页面不可见)   |
|     <meta charset="UTF-8">  <- 字符编码配置                   |
|     <title>页面标题</title>  <- 浏览器标签页名称               |
|   </head>                                                   |
|   <body>                    <- 主体标签 (视窗渲染区，页面可见) |
|     <h1>网页标题</h1>                                        |
|     <p>正文内容...</p>                                      |
|   </body>                                                   |
| </html>                                                     |
+-------------------------------------------------------------+
```
*标准 HTML 文档骨架层级架构*

#### 文档类型声明：<!DOCTYPE html>

位于整个文档的第一行，且必须写在最顶端。它的作用是告知浏览器使用现代 **HTML5** 标准规范来解析并渲染当前的网页文档，防止浏览器进入老旧的“怪异模式”（Quirks Mode）。

#### 根容器标签：<html>

`<html>` 是 HTML 文档的根标签（Root Element），它是整个文档所有其他标签的最外层容器。除第一行的 `<!DOCTYPE html>` 声明外，所有的标签都必须被包裹在 `<html>` 与 `</html>` 之间。

#### 头部配置元数据：<head>

`<head>` 标签对表示文档的头部。头部内放置的内容绝大部分**不会直接显示在浏览器的页面视窗中**，它主要负责承载页面的元信息（Metadata）：
- 声明字符集编码（如 `<meta charset="UTF-8">`，防止中文乱码）；
- 定义浏览器选项卡上显示的标题（`<title>`）；
- 引入外部的 CSS 层叠样式表和 JavaScript 脚本文件。

#### 可视主体容器：<body>

`<body>` 标签对包含了最终渲染并呈现给用户的所有界面内容。
- 用户在浏览器窗口中所看到的全部标题、段落文本、展示图片、音视频播放器与功能按钮，都必须写在 `<body>` 标签内部；
- 我们的后续所有业务代码与页面标签练习，均在 `<body>` 标签对中进行。如果写在 `<body>` 之外，将破坏 DOM 树的正常语义结构。

## 常用文本标签
> 对应分集：P04 | 原始标题：《4. 常用文本标签》

在网页开发中，无论是阅读新闻、浏览商品列表，还是查看数据看板，最核心的承载元素都是文本与表格。在这一讲中，我们系统学习网页中最重要的结构标签：从标题与段落排版，到字符级的强调格式化，再到具备维度层次的列表与二维数据表格。

### 标题体系与层级权重

HTML 提供了六级标题标签，分别用 `<h1>` 到 `<h6>` 表示。数字越小，标题级别越高、权重越大，在浏览器中默认渲染的字号也就越大、越粗。

```text
+-------------------------------------------------------------+
| 标题层级递减关系与视觉权重                                   |
|                                                             |
|   <h1> 一级标题：页面核心主题 (字号最大，权重最高)           |
|   <h2> 二级标题：主要业务模块或章节                        |
|   <h3> 三级标题：模块下属子栏目                            |
|   <h4> 四级标题：细节拆分子项                              |
|   <h5> 五级标题：辅助级小标题                              |
|   <h6> 六级标题：最低层级标注 (字号最小，粗细适中)          |
+-------------------------------------------------------------+
```
*HTML 标题层级递减关系示意*

#### 标题声明与插件联动

在 VS Code 中编写标题非常迅捷：
1. 直接键入 `h1`，编辑器会自动弹出 Emmet 提示，按下 `Tab` 键即可自动展开成成对的 `<h1></h1>`；
2. 双标签内部必须写入文字内容，浏览器视窗才能将其渲染出来：

```html
<h1>一级标题标签</h1>
<h2>二级标题标签</h2>
```

> **提示**：如果在开发过程中需要调整标题级别（例如将 `<h2>` 降级为 `<h3>`），借助之前安装的 **Auto Rename Tag** 插件，我们只需直接修改前端的开始标签 `<h2` 为 `<h3`，后端的闭合标签 `</h2>` 会立即同步自动变更为 `</h3>`；反之直接修改闭合标签，前置开始标签同样会自动双向响应，极大降低了修改成本。

完整的六级标题结构如下：

```html
<h1>一级标题标签</h1>
<h2>二级标题标签</h2>
<h3>三级标题标签</h3>
<h4>四级标题标签</h4>
<h5>五级标题标签</h5>
<h6>六级标题标签</h6>
```

### 段落标签与行内文本格式化

在网页正文排版中，常规内容通常包裹在段落标签中。当我们需要强调某些特定词汇或调整文字视觉呈现时，则需要配合使用行内文本格式化标签。

#### 段落标签：<p>

段落使用 `<p>`（Paragraph）标签表示：

```html
<p>这是一个段落标签</p>
```

浏览器会将每一个 `<p>` 标签渲染为一个独立的段落块，并在段落之间保留默认的上下垂直外边距。与 `<h1>` 等标题标签相比，`<p>` 标签内的文本默认呈现标准字号且不加粗。

#### 行内格式化标签

为了在语境中突显文字重点或表达特定语义，HTML 提供了四组最常用的格式化标签，它们可以直接嵌套在 `<p>` 段落内部使用：

```html
<p><b>字体加粗 (b 标签)</b></p>
<p><strong>字体加粗 (strong 标签)</strong></p>
<p><i>斜体展示 (i 标签)</i></p>
<p><u>文字下划线 (u 标签)</u></p>
<p><s>文字删除线 (s 标签)</s></p>
```

代码编写时，无论将内容与 `<p>` 标签写在同一行，还是将开始标签与闭合标签拆分为多行排版，在浏览器中的视觉渲染效果是完全一致的。

#### 文本修饰标签语义对照

| 标签 | 英文全称 | 视觉呈现 | 核心定位与使用场景 |
| :--- | :--- | :--- | :--- |
| `<b>` | Bold | 文字加粗 | 纯粹的视觉加粗效果 |
| `<strong>` | Strong | 文字加粗 | 强调内容的重要性和警示语义（搜索引擎更友好） |
| `<i>` | Italic | 文字倾斜 | 专有名词、术语、外来语或修辞倾斜 |
| `<u>` | Underline | 下划线 | 标注重点语句或需用户注目的文本片段 |
| `<s>` | Strikethrough | 中划线 / 删除线 | 标注过期价格、已失效条款或作废数据 |

> **提示**：如果需要调整文字的具体像素大小（Font-size）或自定义色值，这属于样式层（CSS）的职责范畴，后文会进行系统讲解。在 HTML 层面，应优先关注标签所承载的语义本身。

### 列表结构与项容器

当面对并列或者有先后步骤的数据时，单纯使用多个 `<p>` 标签排版会丢失集合的从属关系。HTML 提供了两种最经典的列表容器：无序列表与有序列表。

```text
+------------------------------+   +------------------------------+
| 无序列表 (ul > li)           |   | 有序列表 (ol > li)           |
|                              |   |                              |
|   * 无序列表元素 1           |   |   1. 有序列表元素 1          |
|   * 无序列表元素 2           |   |   2. 有序列表元素 2          |
|   * 无序列表元素 3           |   |   3. 有序列表元素 3          |
+------------------------------+   +------------------------------+
```
*无序列表与有序列表视觉结构对比*

#### 无序列表：<ul> 与 <li>

无序列表（Unordered List）的外层容器使用 `<ul>` 标签，内部的每一项列表元素必须用 `<li>`（List Item）包裹。无序列表各元素之间不存在先后的顺位关系，浏览器默认在每一项前面渲染一个黑色实心圆点符号：

```html
<ul>
  <li>无序列表元素 1</li>
  <li>无序列表元素 2</li>
  <li>无序列表元素 3</li>
</ul>
```

#### 有序列表：<ol> 与 <li>

有序列表（Ordered List）与无序列表的内部子元素完全相同，依然使用 `<li>`；二者唯一的区别在于最外层容器换成了 `<ol>`。浏览器会自动对有序列表中的 `<li>` 按照出现顺序依次添加 `1. `、`2. `、`3. ` 形式的阿拉伯数字编号：

```html
<ol>
  <li>有序列表元素 1</li>
  <li>有序列表元素 2</li>
  <li>有序列表元素 3</li>
</ol>
```

### 表格体系与行列拓扑

如果说列表处理的是一维维度的线性条目，那么当数据需要从横向与纵向两个维度同时组织时，就必须借助表格（Table）标签体系。

```text
+-------------------------------------------------------------+
| <table> 表格根容器                                           |
|   +-------------------------------------------------------+ |
|   | <tr> 第 1 行 (表头行)                                  | |
|   |   <th> 列标题 1 </th>  <th> 列标题 2 </th>  <th> 列标题 3 | |
|   +-------------------------------------------------------+ |
|   | <tr> 第 2 行 (数据行)                                  | |
|   |   <td> 21 </td>        <td> 数据 2 </td>    <td> 数据 3   | |
|   +-------------------------------------------------------+ |
|   | <tr> 第 3 行 (数据行)                                  | |
|   |   <td> 31 </td>        <td> 数据 2 </td>    <td> 数据 3   | |
|   +-------------------------------------------------------+ |
| </table>                                                    |
+-------------------------------------------------------------+
```
*HTML 表格标签嵌套与行列拓扑结构*

#### 表格核心标签分工

构建一个标准的二维表格，需要四种标签协同工作：
- `<table>`：表格最外层的根元素，负责界定表格范围。
- `<tr>`（Table Row）：定义表格中的“行”。表格中所有的数据单元格都必须放在具体的行内。
- `<th>`（Table Header）：定义表头单元格。通常位于表格的第一行，用作各列的标题，浏览器会默认将其文字加粗并居中显示。
- `<td>`（Table Data）：定义普通数据单元格。位于数据行的 `<tr>` 内部，承载真实的字段数据。

#### 二维表格代码组织

我们编写一个包含表头与两行三列数据的完整表格代码结构：

```html
<table border="1">
  <tr>
    <th>列标题 1</th>
    <th>列标题 2</th>
    <th>列标题 3</th>
  </tr>
  <tr>
    <td>21</td>
    <td>数据 2</td>
    <td>数据 3</td>
  </tr>
  <tr>
    <td>31</td>
    <td>数据 2</td>
    <td>数据 3</td>
  </tr>
</table>
```

#### 属性引入：border 边框

在上面的 `<table>` 标签中，细心的朋友会注意到我们在开始标签中写了 `border="1"`。

如果我们不写 `border="1"`，在默认情况下浏览器渲染出的表格是没有外围边框与单元格边框线条的，所有数据看起来会像悬浮散落的文字。通过在开始标签中声明 `border="1"`，我们为表格添加了 1 像素宽度的实体网格边框。

这里的 `border`，正是 HTML 中极其关键的**属性（Attribute）**。属性能够为标签提供额外的配置选项与行为控制。在下一讲中，我们将全面展开讲解 HTML 属性的语法规范与高频应用。

## HTML 标签属性
> 对应分集：P05 | 原始标题：《5. HTML 标签属性》

在上一讲介绍表格时，我们初次接触到了 `border="1"` 这样的写法。如果说 HTML 标签决定了网页各个部件的骨架类型，那么**属性（Attribute）**就是赋予这些标签具体特性、资源定位与行为控制的核心机制。本讲我们将深入剖析属性的语法规则、大小写敏感特性，并聚焦实战中最高频的两个富媒体标签：超链接 `<a>` 与图像 `<img>`。

### 属性语法规范与解析机制

每个 HTML 元素都可以携带一个或多个属性，用于描述当前元素的特征、指定关联资源或控制交互行为。

```text
+-----------------------------------------------------------------+
| HTML 属性解构图                                                 |
|                                                                 |
|   <p   id="describe"   class="section"   title="段落提示"> ... </p>  |
|        -------------   ---------------   ----------------       |
|          属性 1            属性 2             属性 3             |
|                                                                 |
|   语法格式：属性名="属性值" (属性间用空格分隔，键值用等号相连)    |
+-----------------------------------------------------------------+
```
*HTML 开始标签中的属性语法结构*

#### 核心语法规则

1. **书写位置**：属性必须书写在**开始标签**中，紧跟在标签名之后，严禁写在结束标签中。
2. **键值对结构**：标准格式为 `属性名="属性值"`。属性名与属性值之间用等号（`=`）相连。
3. **引号规范**：属性值通常由双引号或单引号包裹。在现代前端工程中，推荐统一遵循双引号规范。
4. **多属性共存**：一个标签内部可以同时声明多个属性，各属性之间使用空格分隔，先后顺序不影响最终解析结果。

#### 属性名与属性值的大小写敏感性

这是所有初学者最容易踩坑的底层细节之一：**HTML 属性名不区分大小写，但属性值通常严格区分大小写**。

我们通过三行代码进行对比测试：

```html
<img src="example.jpg" alt="示例图片">
<img SRC="example.jpg" alt="示例图片">
<img src="EXAMPLE.JPG" alt="示例图片">
```

- **第一行与第二行**：第二行中把属性名大写成了 `SRC`。因为 HTML 规范规定标签名和属性名对大小写不敏感，浏览器在解析时会将它们统一转换为小写，因此第一行与第二行的渲染结果完全一致。
- **第三行**：属性名 `src` 保持小写，但属性值被修改为 `EXAMPLE.JPG`。由于属性值代表的是外部文件系统或服务器上的真实资源路径，而 Linux 服务器与大部分网络环境是严格区分文件名大小写的。如果磁盘上的真实文件名为 `example.jpg`，系统在查找 `EXAMPLE.JPG` 时便会返回 404 未找到错误，导致图片彻底无法加载。

> **易错点**：日常编码时，属性名务必统一书写为标准小写（如 `src`、`href`、`class`）；而对于属性值，特别是涉及文件路径、URL 地址、类名（class）或标识符（id）时，必须严格与目标对象保持大小写一致。

#### 通用属性与专有属性

HTML 中的属性可以划分为全局通用属性与标签专有属性两大家族：

| 属性类型 | 典型属性名 | 适用范围 | 核心功能说明 |
| :--- | :--- | :--- | :--- |
| **通用全局属性** | `class` | 绝大部分 HTML 标签通用 | 为元素定义一个或多个类名，供 CSS 样式绑定与 JS 查询 |
| **通用全局属性** | `id` | 绝大部分 HTML 标签通用 | 为元素指定在全文档唯一的标识符，用于精准定位或样式锚点 |
| **通用全局属性** | `style` | 绝大部分 HTML 标签通用 | 为元素内联定义 CSS 样式（如修改字号、行内边距等） |
| **专有行为属性** | `href`、`target` | `<a>` 标签专有 | 指定跳转目标地址以及窗口打开模式 |
| **专有行为属性** | `src`、`alt` | `<img>` 标签专有 | 指定媒体资源物理路径以及加载失败时的替换说明文本 |

### 超链接标签与窗口导航行为

超链接是整个 Web“网状互联”的灵魂所在。在 HTML 中，我们使用 `<a>`（Anchor，锚点）标签创建超链接。

#### 基础跳转：href 属性

在 VS Code 中输入 `a` 并按 `Tab` 键，编辑器会自动补全双标签并默认带出 `href` 属性：

```html
<a href="https://docs.geeksman.com">这是一个超链接</a>
```

- `href`（Hypertext Reference，超文本引用）用于定义链接的跳转目标。其取值非常灵活，可以是完整的网络外部 URL、本地站点的相对路径文件、页面内部锚点，甚至是调起邮件客户端的 `mailto:` 或拨打电话的 `tel:` 协议。
- **内容可见性**：`<a>` 是双标签，开始与结束标签之间必须包含文字、图片或子组件。如果标签内部为空，浏览器将不会在界面上渲染出任何可供用户点击的热区。

#### 窗口打开策略：target 属性

默认情况下，点击超链接会在当前窗口直接刷新并加载新页面。如果我们需要保留当前页面，让新链接在后台或独立标签页中弹出，就需要配置 `target` 属性：

```html
<a href="https://docs.geeksman.com" target="_blank">在新标签页打开超链接</a>
```

`target` 属性支持四个标准枚举值，控制着浏览器视窗与浏览上下文的分配机制：

| target 属性值 | 打开行为 | 典型业务场景 |
| :--- | :--- | :--- |
| `_self` | **默认值**。在当前标签页/当前框架中加载目标页面 | 站点内部同级模块切换，用户线性浏览 |
| `_blank` | 在全新的浏览器标签页或独立新窗口中打开 | 跳转至外部第三方网站，避免用户流失；或长文参考文档阅读 |
| `_parent` | 在当前框架的上一层父级窗口中打开 | 嵌套框架（iframe）中突破内层容器导航 |
| `_top` | 突破所有层级的嵌套框架，在最顶层的整个浏览器窗口中打开 | 从深层内嵌页面中彻底跳出，全屏恢复主应用视窗 |

### 元素流特性与物理排版控制

当我们连续书写两个 `<a>` 标签并使用 Live Server 查看时，会发现一个明显的现象：

```html
<a href="https://docs.geeksman.com">链接一</a>
<a href="https://docs.geeksman.com" target="_blank">链接二</a>
```

我们在代码编辑器中明明将它们写成了两行，但在浏览器屏幕上，这两个链接却紧紧挨在一起，水平排列在同一行上。而之前学过的 `<h1>`、`<p>`、`<table>` 却总是自动另起一行并独占整行。

```text
+-------------------------------------------------------------+
| 元素默认流特性对比                                           |
|                                                             |
|   块级元素 (Block)：                                        |
|   +-------------------------------------------------------+ |
|   | <h1>一级标题 (独占一行，横向撑满父容器)                | |
|   +-------------------------------------------------------+ |
|                                                             |
|   行内元素 (Inline)：                                       |
|   +-----------------------+ +-----------------------+       |
|   | <a>链接一 (按内容收缩) | | <a>链接二 (水平并排)  |       |
|   +-----------------------+ +-----------------------+       |
+-------------------------------------------------------------+
```
*块级元素与行内元素的默认流布局行为*

> **定义**：
> - **块级元素（Block-level Elements）**：默认独占一行，后续内容强制换行显示（如 `<h1>`、`<p>`、`<table>`）。
> - **行内元素（Inline Elements）**：仅占据自身内容所需的宽度，不会自动换行，多个行内元素默认在水平方向从左到右依次排列（如 `<a>`、`<img>`、`<span>`）。

在尚未深入学习 CSS 盒模型之前，如果我们希望两个超链接强制分行，可以使用排版辅助单标签：
- **物理换行标签 `<br>`**：插入一个单纯的换行符；
- **水平分割线标签 `<hr>`**：插入一条贯穿横向的实线，实现视觉与物理层面的双重隔离。

```html
<a href="https://docs.geeksman.com">链接一</a>
<br>
<a href="https://docs.geeksman.com" target="_blank">链接二</a>
<hr>
```

### 图像标签与多媒体尺寸控制

图像是构建现代富媒体界面的核心要素。HTML 使用单标签 `<img>`（Image）在网页中嵌入图片。

#### 核心寻址与容错属性：src 与 alt

在 VS Code 中输入 `img` 按 `Tab` 键，编辑器会自动生成带有两个核心属性的单标签骨架：

```html
<img src="logo.png" alt="网站官方Logo">
```

```text
+-------------------------------------------------------------+
| <img src="logo.png" alt="网站官方Logo">                     |
|        ------------  --------------------                   |
|          资源寻址路径    加载失败时的文本兜底                |
+-------------------------------------------------------------+
```
*图像标签核心属性分工*

1. **`src` 属性（Source）**：指定图片的资源路径。
   - **本地相对路径**：若图片文件与当前的 `.html` 文件存放在同一目录下，直接写入文件名即可（如 `src="logo.png"`）；若存放在子目录，则按路径寻址（如 `src="images/logo.png"`）；
   - **绝对路径与网络 URL**：可以直接将互联网上的图片链接复制到 `src` 中。
2. **`alt` 属性（Alternative Text）**：定义图像的替换说明文本。
   - 当网络波动超时、本地资源路径拼写错误（例如将 `logo.png` 误写为 `lgg.png`）或图片已被服务器删除时，浏览器无法呈现图片本身；
   - 此时，浏览器会在破损图片图标旁边，完整显示 `alt` 中声明的提示文字，明确告知用户此处原本是什么内容；
   - 此外，屏幕阅读器等无障碍辅助设备（Accessibility）也会朗读 `alt` 文本，帮助视障用户理解图片含义。

> **提示**：永远不要省略 `<img>` 的 `alt` 属性。即使图片是纯装饰性的，也应该声明 `alt=""`，养成工程规范化的高质量编码习惯。

#### 尺寸约束属性：width 与 height

从外部引入的高清图片，其原始物理分辨率往往远超出屏幕显示区域，可能直接将页面撑爆变形。我们可以在 `<img>` 开始标签中直接声明 `width` 与 `height` 属性对显示尺寸进行约束：

```html
<img src="logo.png" alt="网站官方Logo" width="200" height="100">
```

- `width`：控制图像渲染宽度，属性值直接填写数字，单位默认为像素（px）；
- `height`：控制图像渲染高度，单位同样默认为像素。

同 `<a>` 标签一样，`<img>` 在渲染表现上同样具有行内特征，连续书写的多张图片会优先在一行中水平排列，超出屏幕宽度时才会自动折行，必要时同样可以结合 `<br>` 控制其纵向排布。

通过掌握属性语法、超链接跳转策略以及多媒体标签的控制属性，我们已经具备了构建图文混排、多页跳转的完整 HTML 骨架能力。

## 块元素与行内元素
> 对应分集：P06 | 原始标题：《6. 块元素与行内元素》

在排版网页时，我们会观察到一种非常直观的视觉现象：有些元素在浏览器中呈现时，天然独占一整行，其他元素只能被挤到下一行去，比如段落标签 `<p>`、标题标签 `<h1>` 以及表格 `<table>`；而另一些元素则可以彼此紧挨着排在同一行内，比如超链接 `<a>` 和图片 `<img>`。

之所以会出现这种视觉差异，根源在于 HTML 元素在渲染维度上被划分为了两大基础流派：**块元素（Block Elements）**与**行内元素（Inline Elements）**。理解它们的行为模式，是后续掌握 CSS 网页布局与样式定制不可或缺的底层支柱。

> **注意**：
> 这里所说的“独占一行”是指元素在浏览器实际渲染页面中的布局行为，而不是指代码在编辑器文本文件里是否换行书写。即便在 HTML 代码中把两个块元素写在同一行，浏览器依然会强制折行渲染。

---

### 元素显示特征与分类

浏览器根据元素在文档流中的排版表现，赋予了它们截然不同的默认规则。

#### 块元素行为规范

块元素主要用于搭建页面的结构骨架与内容区块。它在浏览器文档流中具有以下典型特性：

* **换行渲染**：块元素在渲染时始终从新的一行开始。
* **宽度撑满**：块元素在默认情况下会拉伸占据其父容器整行的宽度（100% 宽度），即使内容只有几个字，整行剩余的空间也不会允许其他元素并列。
* **容纳能力**：块元素作为结构容器，既可以包含其他的块级元素，也可以包含任意行内元素。

常见的块级元素包括：
* `<div>`：最通用的无语义块级容器。
* `<p>`：段落标签。
* `<h1>` ~ `<h6>`：六级标题标签。
* `<ul>` 与 `<ol>`：无序列表与有序列表。
* `<table>`：表格容器。
* `<form>`：表单交互容器。

#### 行内元素行为规范

行内元素主要用于标记或修饰文本段落内部的具体片段。它在排版流中具备以下约束：

* **同行排列**：行内元素在同一行内自左向右依次顺畅排列，前后都不会强制触发换行。
* **宽度包裹**：其尺寸仅根据自身包含的文字或内容自适应收缩包裹，绝不主动霸占整行多余的空间。
* **嵌套限制**：行内元素内部通常只允许嵌套其他行内元素或纯文本，不允许包裹块级元素。

常见的行内元素包括：
* `<span>`：最通用的无语义行内容器。
* `<a>`：超链接锚点标签。
* `<strong>`：语义化内容加粗。
* `<em>`：语义化内容倾斜强调。
* `<img>`：嵌入式图像（具有替换元素的特殊尺寸特性，但在排版流中与文字处于同一基准线）。
* `<br>`：强制行内文本折行。
* `<input>`：单行表单输入控件。

#### 块与行内特性对照

```text
+-----------------------------------------------------------+
| 块元素 (Block Element): 独占整行宽度                      |
+-----------------------------------------------------------+
| [行内元素1]  [行内元素2:紧随其后]  [行内元素3:自适应内容] |
+-----------------------------------------------------------+
| 块元素 (Block Element): 另起新行，再次撑满整行            |
+-----------------------------------------------------------+
```
*图解：块元素与行内元素在页面渲染流中的空间占据与换行表现差异*

| 比较维度 | 块元素（Block Elements） | 行内元素（Inline Elements） |
| :--- | :--- | :--- |
| **默认换行** | 始于新行，后续元素必须折到下一行 | 紧随前驱内容同一行水平排列，不折行 |
| **默认宽度** | 默认撑满整行（父容器宽度的 100%） | 仅包裹内部内容尺寸，宽度自适应收缩 |
| **容纳规则** | 可容纳块级元素与行内元素 | 仅容纳文本或其他行内元素，不可容纳块元素 |
| **核心职责** | 组织结构骨架、划分版面大区块 | 修饰局部文字、行内跳转与碎片信息标记 |

### 块级结构容器 div

在 HTML 所有标签中，`<div>`（Division，意为“分区/区块”）是构建现代化前端网页布局使用频率最高的核心骨架标签。

#### 语义特征与版面划分

`<div>` 是一个纯粹的、无默认特定语义的块级容器。它不像 `<p>` 带有默认外边距，也不像 `<h1>` 具备字号加粗语义，它仅负责“包裹与分组”。

正因为这种“纯白纸”的特性，我们在规划页面架构时，通常使用 `<div>` 将整个网页切割为多个相对独立的逻辑区块：
* **页眉（Header）**：承载站点标题、Logo 或全局控制项。
* **导航栏（Navigation）**：承载网站的核心路由链接。
* **侧边栏（Sidebar）**：承载附加分类、友情链接或工具模块。
* **内容主体（Content）**：承载当前页面的核心文章与图文段落。
* **页脚（Footer）**：承载版权声明、备案信息与底部声明。

```text
+-----------------------------------------------------------+
|                      页眉 (Header)                        |
+-----------------------------------------------------------+
|                     导航栏 (Nav / Navbar)                 |
+-----------------------------+-----------------------------+
|                             |                             |
|       内容主体 (Content)    |       侧边栏 (Sidebar)      |
|                             |                             |
+-----------------------------+-----------------------------+
|                      页脚 (Footer)                        |
+-----------------------------------------------------------+
```
*图解：借助 div 标签划分的经典网页主体骨架结构*

#### 导航栏与内容区块实例

下面通过代码演示如何使用带有类名的 `<div>` 分别构建导航栏与文章正文区。

在导航栏区域中，使用类名为 `nav` 的 `<div>` 作为外层块级容器，内部放置若干个超链接 `<a>`。通过在 `href` 属性中填入井号 `#`，可以在不需要立刻跳转到真实页面时作为安全占位符：

```html
<div class="nav">
    <a href="#">链接1</a>
    <a href="#">链接2</a>
    <a href="#">链接3</a>
    <a href="#">链接4</a>
    <a href="#">链接5</a>
</div>
```

紧接着在导航栏下方创建主体内容区块。通过类名为 `content` 的 `<div>` 容器，集中包裹文章标题 `<h1>` 和多段段落正文 `<p>`：

```html
<div class="content">
    <h1>文章标题</h1>
    <p>文章内容第一段：介绍核心技术概念与基础语法规则。</p>
    <p>文章内容第二段：展开阐述代码实现细节与布局特性。</p>
    <p>文章内容第三段：总结归纳开发过程中的常见模式。</p>
    <p>文章内容第四段：对比不同技术选型的优缺点与适用场景。</p>
    <p>文章内容第五段：结语与后续进阶拓展建议。</p>
</div>
```

#### Emmet 容器生成语法

在日常开发编写包含类名或 ID 的容器元素时，无需机械地手写每一个尖括号与属性字符，现代编辑器内置的 Emmet 插件提供了极速缩写语法：

* **类名快速生成**：在编辑器中直接输入 `.类名`（例如 `.nav`），按下 `Tab` 键即可自动展开为 `<div class="nav"></div>`。
* **ID 快速生成**：输入 `#标识符`（例如 `#nav`），按下 `Tab` 键即可生成 `<div id="nav"></div>`。
* **显式指定标签与修饰符**：输入 `div.nav` 或 `div#nav` 同样可以精准展开，此语法同样通用于其他标签（如 `p.desc` 会生成 `<p class="desc"></p>`）。

### 行内文本容器 span

相较于块级容器 `<div>`，`<span>` 则是行内维度上的对应角色。

#### 语义特征与应用定位

`<span>` 同样是一个没有特定语义的容器，但它是一个标准的行内元素。它的设计初衷是将行内文本中的某一小段精准圈定出来，以便赋予专属的 CSS 字体颜色、背景高亮或绑定 JavaScript 交互事件。

因为 `<span>` 不会破坏当前的行内排列，它就像一把精细的手术刀，在不引起页面段落换行的前提下完成局部样式的精准挂载。

#### 行内排列与混合嵌套实例

当我们在页面中连续放置多个 `<span>` 标签时，它们会在浏览器同一水平行内自左向右依次衔接，绝不独自产生换行：

```html
<span>这是第一个 span 标签</span>
<span>第二个</span>
<span>第三个</span>
<span>第四个</span>
```

此外，`<span>` 能够与其他行内元素平滑混合嵌套。例如在行内文本中嵌套 `<a>` 标签，既保持了纯文本流的连贯性，又提供了局部交互入口：

```html
<hr>
<span>链接：点击这里 <a href="#">链接</a></span>
```

---

### 容器分工与协作综述

* **`<div>` 的核心定位**：页面骨架的积木。用于从宏观层面切分大结构（如页眉、导航、主栏、尾栏），后续借助 CSS 浮动、定位或弹性盒（Flexbox）来实现多栏并列或复杂版面排版。
* **`<span>` 的核心定位**：微观文本的画笔。用于在行内细节层面圈定目标字词，以便借助 CSS 实施局部的颜色着色、加粗修饰或微观动效。
* **前后端协同**：这两个容器本身没有任何侵入性的浏览器默认样式，它们将纯净的内容结构暴露出来，正是现代前端将“结构（HTML）”与“表现（CSS）”完全解耦的典范搭档。

## HTML 表单
> 对应分集：P07 | 原始标题：《7. HTML 表单》

在浏览各类网站时，我们几乎每时每刻都在与表单打交道。求职网站顶部的职位搜索栏、城市与商圈的筛选器、登录注册页面中填写的手机号、密码输入框，以及需要勾选的用户服务协议与最终的登录按钮，本质上全都是表单。

表单是 Web 页面收集用户输入、实现前后端数据传递与交互的最核心载体。在 HTML 体系中，表单拥有一套专门的容器标签与控件生态。

---

### 表单容器与提交机制

制作任何表单的第一步，都需要先建立一个统一的容器来包裹所有输入控件。

#### 容器标签 form

表单必须以 `<form>` 作为外层容器标签。所有需要收集并提交给后台服务器的控件元素，都必须完整放置在 `<form>` 与 `</form>` 之间：

```html
<form action="#">
    <!-- 内部放置各类表单控件 -->
</form>
```

#### 目标地址属性 action

在创建 `<form>` 标签时，最关键的属性就是 `action`。

`action` 属性规定了当用户触发表单提交行为时，表单内收集的所有数据应当被发送到哪一个目标地址（URL）。在实际商业开发中，这个地址通常对应后端开发人员提供的接收数据的 API 接口。

在没有后端接口配合的练习阶段，我们可以直接在 `action` 属性中填入井号 `#` 作为安全占位符，这样在点击提交时页面不会发生异常跳转。

```text
+-----------------------------------------------------------+
| 用户在表单控件中输入/勾选数据                             |
| (type="text", type="password", type="radio", ...)         |
+-----------------------------------------------------------+
                             |
                      [点击提交按钮]
                             |
                             v
+-----------------------------------------------------------+
| <form action="URL"> 收集内部所有表单项并发送请求          |
+-----------------------------------------------------------+
                             |
                             v
+-----------------------------------------------------------+
| 后端服务器 API 接口接收并处理数据                         |
+-----------------------------------------------------------+
```
*图解：HTML 表单从数据采集、用户触发到依托 action 属性向后端流转的全流程*

### 单行文本与密码输入控件

在所有的表单元素中，使用频次最高的是 `<input>` 输入标签。这是一个单标签，通过切换其内部的 `type` 属性值，可以变形为多种完全不同形态的交互控件。

#### 单行文本框与占位提示

当把 `type` 属性设置为 `text` 时（这也是 `<input>` 的默认类型），浏览器会将其渲染为一个允许用户输入单行文本的输入框：

```html
<input type="text">
```

在实际界面中，输入框内部经常会显示一行浅灰色的提示文字，引导用户输入正确格式的内容（例如“搜索职位和公司”或“请输入内容”）。当用户的鼠标点击文本框开始输入时，这行文字会自动隐去；当清空输入后，它又会重新出现。

这一交互效果由 `placeholder` 属性实现：

```html
<input type="text" placeholder="请输入内容">
```

#### 占位符 placeholder 与真实值 value 的差异

初学者经常容易将 `placeholder` 属性与 `value` 属性混淆。如果为输入框配置 `value` 属性，其效果截然不同：

```html
<input type="text" value="请输入内容">
```

| 属性名称 | 视觉表现 | 输入交互反应 | 数据提交行为 |
| :--- | :--- | :--- | :--- |
| **`placeholder`** | 浅灰色占位提示文本 | 获得焦点且开始键入内容时自动隐去，清空内容后重新显示 | 不会被作为表单数据提交至后端 |
| **`value`** | 深色真实文本内容 | 页面加载完成时该内容已作为真实值填入框内，需要手动删除 | 点击提交时会被作为当前控件的实际输入值发送给后端 |

> **提示**：
> `placeholder` 纯粹用于对用户的填写引导；而 `value` 则是控件在 DOM 中的真实数据载体。

#### 密码输入框与加密遮罩

如果需要输入账户密码、支付密钥等敏感信息，继续使用 `type="text"` 会导致密码以明文形式直接呈现在屏幕上，存在极大的被旁窥泄露风险。

通过将 `type` 属性值设定为 `password`，输入框会开启密码遮罩模式。用户输入的每一个字符都会被浏览器自动转换为黑色实心圆点或星号进行遮盖隐藏：

```html
<input type="password" placeholder="请输入密码">
```

### 标签文本与表单项关联绑定

输入框本身只是一个无声的矩形框，用户必须依赖旁边的文本标识（如“用户名”、“密码”）来识别各字段含义。

#### 字段说明与换行组织

我们可以直接在输入框前添加文本或行内标签 `<span>`，并在两行表单项之间添加 `<br>` 实现上下换行排布：

```html
<span>用户名</span>
<input type="text" placeholder="请输入用户名">
<br><br>
<span>密码</span>
<input type="password" placeholder="请输入密码">
```

#### 专属标记标签 label 与 id 属性关联

虽然 `<span>` 可以展示文字，但在 HTML 表单中，更符合语义化规范且具备无障碍访问优势的做法是使用专属的 `<label>` 标签。

`<label>` 标签内置了一个关键属性 `for`，其作用是将自身文字与特定输入框深度绑定。绑定的核心机制是：**`<label>` 的 `for` 属性值必须严格等于对应 `<input>` 的 `id` 属性值**。

```html
<label for="username">用户名</label>
<input type="text" id="username" placeholder="请输入用户名">
<br><br>
<label for="pwd">密码</label>
<input type="password" id="pwd" placeholder="请输入密码">
```

> **优势解析**：
> 一旦通过 `for` 与 `id` 完成关联绑定，用户在网页上不仅可以点击小小的输入框，直接点击前面的“用户名”文字标签，浏览器的焦点也会自动聚焦并跳入对应的输入框中，大幅提升了操作便利性。

### 单选框与复选框及分组控制

除了文本输入，选择操作也是表单的核心功能。

#### 单选框与同组互斥机制

将 `<input>` 的 `type` 属性指定为 `radio`，控件即可渲染为圆形单选按钮：

```html
<label>性别：</label>
<input type="radio" name="gender">男
<input type="radio" name="gender">女
<input type="radio" name="gender">其他
```

> **易错点**：
> 如果仅仅写了 `type="radio"` 而没有配置 `name` 属性，当用户逐一点击“男”、“女”、“其他”时，会发现每一个单选框都会被点亮且无法取消，彻底丧失了“单选”的互斥效果！
> 
> 要实现多选一的互斥逻辑，**同一组单选控件必须设置完全相同的 `name` 属性值**（例如本例中的 `name="gender"`）。浏览器在解析到相同 `name` 的 `radio` 时，会自动将其归纳为同一个逻辑单选组，从而确保组内有且仅有一个选项能够处于被选中状态。

#### 多选框复选交互

在填写个人爱好、技能专长或勾选多个选项时，需要使用复选框。只需将 `type` 属性修改为 `checkbox`：

```html
<label>爱好：</label>
<input type="checkbox" name="hobby">唱歌
<input type="checkbox" name="hobby">跳舞
<input type="checkbox" name="hobby">Rap
<input type="checkbox" name="hobby">篮球
```

多选框呈现为方形勾选框。通常同一业务维度的复选框也会统一配置相同的 `name` 属性（如 `name="hobby"`），用户在界面上可以不受限制地同时勾选多个兴趣项。

### 表单提交与按钮定制

当用户在表单中填写完所有字段后，必须有触发表单数据打包打包外发的机制。

#### 提交按钮 submit

将 `<input>` 的 `type` 设置为 `submit`，即可生成原生表单提交按钮：

```html
<input type="submit">
```

在未做任何定制时，浏览器会默认赋予该按钮“提交”字样的文案。一旦用户点击该按钮，浏览器会自动收集当前 `<form>` 内部所有设置了有效属性的表单控件内容，打包发送到 `<form>` 标签上 `action` 属性所指向的接口地址。

#### 自定义按钮文案

如果不希望使用枯燥的“提交”二字，而是想呈现“上传”、“登录”或“立即注册”，只需通过 `value` 属性即可轻松覆盖默认文案：

```html
<input type="submit" value="上传">
```

### 完整综合表单实战代码

综合运用上述容器属性、文本输入、密码遮罩、标签绑定、互斥单选、多选复选以及提交按钮，可以构建出一个标准结构的前端交互表单：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
    <meta charset="UTF-8">
    <title>HTML 表单综合实战</title>
</head>
<body>

    <form action="#">
        <!-- 用户名输入区 -->
        <label for="username">用户名</label>
        <input type="text" id="username" placeholder="请输入用户名">
        <br><br>

        <!-- 密码输入区 -->
        <label for="pwd">密码</label>
        <input type="password" id="pwd" placeholder="请输入密码">
        <br><br>

        <!-- 性别互斥单选区 -->
        <label>性别：</label>
        <input type="radio" name="gender">男
        <input type="radio" name="gender">女
        <input type="radio" name="gender">其他
        <br><br>

        <!-- 爱好自由复选区 -->
        <label>爱好：</label>
        <input type="checkbox" name="hobby">唱歌
        <input type="checkbox" name="hobby">跳舞
        <input type="checkbox" name="hobby">Rap
        <input type="checkbox" name="hobby">篮球
        <br><br>

        <!-- 提交交互按钮 -->
        <input type="submit" value="上传">
    </form>

</body>
</html>
```
