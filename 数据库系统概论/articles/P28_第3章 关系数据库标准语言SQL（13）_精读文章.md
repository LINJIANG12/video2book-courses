# SQL数据更新机制（十三）：INSERT批量导入、UPDATE批量更新与完整性防御

## 1. 核心概念与本质内涵：数据操纵语言（DML）的职责

在关系数据库的完整生命周期中，数据不仅需要被高效检索，更需要随着业务运转进行持续的写入、修正与淘汰。

SQL 中的数据更新由**数据操纵语言（Data Manipulation Language, DML）**实现，主要包括三大操作：
1. **插入数据（INSERT）**：向基本表中添加新的数据行；
2. **修改数据（UPDATE）**：对基本表中既有记录的一个或多个属性值进行覆写或计算更新；
3. **删除数据（DELETE）**：从基本表中移除不再需要的陈旧元组。

```text
                        SQL 数据更新 DML 三大操作
                                   │
       ┌───────────────────────────┼───────────────────────────┐
       ▼                           ▼                           ▼
【INSERT: 数据写入】         【UPDATE: 属性修改】        【DELETE: 元组清除】
 • 单行常量插入 (VALUES)      • 批量属性覆写 (SET ... )   • 谓词条件筛选删除 (WHERE)
 • 子查询批量灌入 (SELECT)    • 支持子查询动态计算        • 省略 WHERE 即清空整表
       │                           │                           │
       └───────────────────────────┼───────────────────────────┘
                                   ▼
                【DBMS 底层强制执行三大完整性约束防御】
                (实体主码校验 / 参照外码联动 / CHECK 范围判定)
```

## 2. 插入数据（INSERT 语句）

### 2.1 插入单条元组（INSERT ... VALUES）

```sql
INSERT INTO <表名> [(<属性列1> [, <属性列2>]...)]
VALUES (<常量1> [, <常量2>]...);
```

#### 规则与最佳实践：
1. **显式指明列名列表（推荐规范）**：
   ```sql
   INSERT INTO Student (Sno, Sname, Ssex, Sdept, Sage)
   VALUES ('2026101', '陈晓', '女', 'CS', 19);
   ```
   `INTO` 子句中指定的列名次序可以与建表时的物理列序不一致，只需确保 `VALUES` 中的常量值类型与顺序与之严格一一对应。
2. **省略列名列表的隐式规则**：
   ```sql
   INSERT INTO Student 
   VALUES ('2026102', '赵雷', '男', 20, 'MA');
   ```
   若省略列名列表，**必须且强制按照建表定义时的全量属性物理次序**，提供全部字段的值，极易因后续表结构加列而导致代码失效。
3. **部分列缺省与空值处理**：
   在指定列名时，未列出的字段将自动填充其建表时定义的 `DEFAULT` 默认值；若无默认值且未声明 `NOT NULL`，则系统自动填入 `NULL`。

---

### 2.2 插入子查询结果（批量数据灌入）

SQL 允许将一个 `SELECT` 查询抽取出来的海量结果集，直接一次性批量插入到目标表中，这在数据清洗、历史归档与数仓聚合中极其普遍：

```sql
-- 1. 创建一张专门存放每个系平均年龄的汇总表
CREATE TABLE Dept_Age (
    Sdept VARCHAR(20) PRIMARY KEY,
    AvgAge NUMERIC(4, 1)
);

-- 2. 通过子查询将统计结果批量灌入该汇总表
INSERT INTO Dept_Age (Sdept, AvgAge)
SELECT Sdept, AVG(Sage)
FROM Student
GROUP BY Sdept;
```

## 3. 修改数据（UPDATE 语句）

```sql
UPDATE <表名>
SET <列名> = <表达式> [, <列名> = <表达式>]...
[WHERE <条件>];
```

### 3.1 核心操作规约
- `SET` 子句指定需要更新的列及其赋予的新值或计算表达式；
- `WHERE` 子句用于限定哪些元组需要被修改。
- **高危警告**：**若省略 `WHERE` 子句，则该表中的所有元组都会被同时修改**！

```sql
-- 1. 单行修改: 将学号为 202601 的学生年龄加 1 岁
UPDATE Student 
SET Sage = Sage + 1 
WHERE Sno = '202601';

-- 2. 批量带子查询修改: 将计算机系所有学生的成绩清零
UPDATE SC 
SET Grade = 0 
WHERE Sno IN (
    SELECT Sno FROM Student WHERE Sdept = 'CS'
);
```

## 4. 删除数据（DELETE 语句）

```sql
DELETE FROM <表名>
[WHERE <条件>];
```

### 4.1 核心规约与辨析
- `DELETE` 语句只删除基本表中的**数据元组（行）**，**表的结构、约束、索引完整保留**；
- 若省略 `WHERE` 子句，则清空表中的所有记录（如 `DELETE FROM SC;`）；
- **与 `TRUNCATE TABLE` 的工程区别**：
  - `DELETE` 是标准 DML，逐行删除并记录完整的事务回滚重做日志（Undo/Redo Log），支持事务回滚（Rollback）；
  - `TRUNCATE` 是 DDL 操作，通过直接释放物理数据页快速清空全表，不可精细过滤，执行极快但无法按行恢复。

## 5. DML 过程中的数据库完整性防御体系

在执行任何 `INSERT`, `UPDATE`, `DELETE` 时，DBMS 事务内核会触发一系列自动化的完整性校验钩子（Hook）：

```text
【DML 操作与三大完整性规则检查流向】
 写入/更新/删除请求
         │
         ▼
 1. 实体完整性校验: 主码是否冲突? 主码属性是否被赋了 NULL? 
    (若违约 ──> 立即抛错中断，事务回滚)
         │
         ▼
 2. 参照完整性校验:
    • INSERT/UPDATE: 外码值是否在被参照主表中存在?
    • DELETE 主表: 是否存在外键依赖? 
      (根据级联配置执行: RESTRICT 报错 / CASCADE 连带删除 / SET NULL 置空)
         │
         ▼
 3. 用户定义完整性校验: CHECK 表达式、NOT NULL、UNIQUE 是否全通过?
         │
         ▼
 全部合规 ──> 写入重做日志 ──> 持久化生效
```

## 6. 随堂巩固自测

### 自测题 1（单项选择题）
在执行 SQL 语句 `DELETE FROM Student WHERE Sno = '202601';` 时，系统抛出错误信息：`ORA-02292: integrity constraint (FK_SC_SNO) violated - child record found`。造成该操作失败的原因是（ ）
A. 该学生表中不存在学号为 202601 的学生  
B. 该操作违反了实体完整性约束，主码不能删除  
C. 选课表 SC 中存在该学生的选课记录，且外码配置为默认的限制删除（RESTRICT），违反了参照完整性  
D. DELETE 语句缺少指定要删除的属性列名  

**【答案】**：C  
**【解析】**：错误明确指出违反了外码参照约束（child record found）。从表 `SC` 中存在参照该学号的外码记录，且外码约束采用 RESTRICT 策略，因此系统严禁删除主表对应行，维护了参照完整性。故选 C。

### 自测题 2（SQL DML 综合实战题）
编写两条标准的 SQL 语句：
1. 向 `Course` 表中插入一门新课程，课程号为 `'C10'`，课程名为 `'数据挖掘'`，学分为 3 分，直接先修课暂时未定（取空值）；
2. 将选修了课程号为 `'C01'` 且成绩不及格（$< 60$）的所有学生的成绩上调 5 分。

**【参考答案】**：
```sql
-- 1. 插入新课程
INSERT INTO Course (Cno, Cname, Cpno, Ccredit)
VALUES ('C10', '数据挖掘', NULL, 3);

-- 2. 批量调整不及格学生成绩
UPDATE SC
SET Grade = Grade + 5
WHERE Cno = 'C01' AND Grade < 60;
```
