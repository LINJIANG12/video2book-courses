# 数据模型详解（三）：概念模型构建、E-R 图方法与三大逻辑模型演进

## 1. 核心概念与本质内涵：概念模型的表达工具——E-R 模型

在数据库系统设计中，概念模型是连接现实业务世界与计算机存储世界的认知桥梁。要将真实世界中纷繁复杂的事物抽象为规范的数据，最主流、最广泛使用的理论工具是**实体-联系方法（Entity-Relationship Approach）**，即 **E-R 模型**。

### 1.1 概念模型的核心术语与形式化定义

为了建立统一的建模语言，E-R 模型形式化地定义了以下一组基础范畴：

1. **实体（Entity）**：
   - 客观存在并可相互区别的事物称为实体。实体既可以是具体的人、物或对象（如学生“张三”、一辆“自行车”），也可以是抽象的事件或概念（如一次“选课”、一次“借阅”）。
2. **属性（Attribute）**：
   - 实体所具有的某一特性称为属性。一个实体通常由若干属性刻画。例如：学生实体的属性可包括学号（`Sno`）、姓名（`Sname`）、性别（`Ssex`）、出生年月（`Sbirth`）和所在院系（`Sdept`）。
3. **码（Key / 键）**：
   - 能够唯一标识一个实体的属性或属性集称为该实体的码。例如：在学生群体中，每个学生的“学号”是唯一的，学号即为学生实体的码。
4. **实体型（Entity Type）与实体集（Entity Set）**：
   - **实体型**：具有相同属性的实体必然具有共同的特征和性质。用实体名及其属性集合来抽象和刻画同类实体，称为实体型。例如：`学生(学号, 姓名, 性别, 年龄, 系别)` 就是一个实体型；
   - **实体集**：同一类型实体的集合称为实体集。例如：全校所有在校学生的集合构成一个实体集。

### 1.2 实体之间的联系及其类型判定

在客观现实中，事物之间并非孤立存在，事物内部以及事物之间均存在各种关联，在信息世界中这些关联被统一抽象为**联系（Relationship）**。

在两个实体型之间，根据联系的对应基数（Cardinality），联系可划分为以下三类：

```text
1. 一对一联系 (1:1)
   班级实体型 [Class] ────────(设立)──────── [Leader] 班长实体型
   (一个班级有且仅有一名正班长，一名班长只在一个班级任职)

2. 一对多联系 (1:n)
   院系实体型 [Department] ────(包含)────< [Teacher] 教师实体型
   (一个院系聘任多名教师，每名教师人事上归属于一个院系)

3. 多对多联系 (m:n)
   学生实体型 [Student] >────(选修)────< [Course] 课程实体型
   (一名学生可以选修多门课程，一门课程可被多名学生同时修读)
```

> **提示**：除了两实体型之间的联系外，还存在**单一实体型内部的自联系**（例如在员工实体型内部，“员工”与“主管”之间的领导与被领导联系是一对多自联系），以及**多个实体型之间的多元联系**（例如“供应商-工程项目-零件”三者之间的三元供应联系）。

## 2. 三大经典逻辑数据模型的体系演进与机理对比

当完成概念模型（E-R 图）设计后，必须将其转换为计算机 DBMS 支持的逻辑数据模型。在数据库技术的发展历程中，最具代表性的三大经典逻辑模型分别为：**层次模型、网状模型和关系模型**。

```text
+-------------------+      +-------------------+      +-------------------+
|     层次模型      |      |     网状模型      |      |     关系模型      |
| Hierarchical Model|      |   Network Model   |      | Relational Model  |
+-------------------+      +-------------------+      +-------------------+
| 数据结构: 倒悬树  |      | 数据结构: 有向图  |      | 数据结构: 二维表  |
| 根结点无双亲      |      | 允许多个双亲/无亲 |      | 实体与联系统一表示|
| 其余有且仅一双亲  |      | 节点间复杂网状图  |      | 严格基于集合代数论|
+-------------------+      +-------------------+      +-------------------+
```

### 2.1 层次模型（Hierarchical Model）

- **数据结构形式**：用**树形结构**来表示各类实体以及实体间的联系。
- **形式化约束条件**：
  1. 有且仅有一个结点没有双亲结点，这个结点称为**根结点（Root）**；
  2. 根以外的其它结点有且仅有一个双亲结点。
- **典型系统代表**：IBM 公司的 IMS（Information Management System，20 世纪 60 年代开发）。
- **优缺点评价**：
  - **优点**：数据结构清晰，概念简单直观；数据存取按固定父子指针遍历，查询性能极佳；
  - **致命缺陷**：无法直接自然地表示现实中普遍存在的**多对多（m:n）联系**；任何非树形联系都必须通过引入虚拟结点、冗余副本或复杂指针链强行拆解；对结点的插入和删除约束严苛（例如无父结点的子记录无法独立插入，删除父结点会导致所有子记录级联抹除）。

### 2.2 网状模型（Network Model）

- **数据结构形式**：用**有向图（网络拓扑）**来表示实体及其相互关联。
- **形式化约束条件**：
  1. 允许一个以上的结点没有双亲结点；
  2. 一个结点可以有多于一个的双亲结点。
- **典型系统代表**：DBTG 系统（CODASYL 组织提出的标准体系）。
- **优缺点评价**：
  - **优点**：能够更为直接、客观地刻画现实世界中的多对多联系与复杂交叉关联；
  - **致命缺陷**：系统结构极为复杂，各实体之间的关联依赖底层庞大繁复的**物理指针链（DBTG 链）**实现；DDL 与 DML 语言语法晦涩冗长；应用程序员必须完全熟知底层的存储路径和指针寻道逻辑才能正确编写查询代码，数据独立性极差。

### 2.3 关系模型（Relational Model）——现代数据库的绝对基石

1970 年，IBM 研究员 E. F. Codd 发表了奠基性论文《A Relational Model of Data for Large Shared Data Banks》，正式提出**关系模型**，彻底终结了层次与网状模型的物理指针统治，引发了数据库技术的革命。

#### ① 关系模型的数据结构：单一的二维平面表
在关系模型中，无论是实体本身，还是实体之间的多态联系，均被统一抽象并存储为**二维表（Table）**，在数学上被称为**关系（Relation）**。

#### ② 核心形式化术语与概念映射
- **关系（Relation）**：一张由行和列构成的规范化二维表；
- **元组（Tuple）**：表中的一行记录，在现实中对应于一个具体的客观实体对象；
- **属性（Attribute）**：表中的一列，每一列被赋予一个属性名，用于描述实体某方面的特性；
- **主码（Primary Key）**：表中的某个属性或属性组，其值能唯一确定一行元组；
- **域（Domain）**：属性的取值范围（例如学生年龄的域为整数集合 $[0, 150]$）；
- **分量（Component）**：元组在某一具体属性上的具体取值（单行单列交叉处的原子数据项）；
- **关系模式（Relation Schema）**：对关系的型（Type）的形式化描述，通常表示为：$R(U, D, DOM, F)$，在教学和应用中简记为：`关系名(属性1, 属性2, ..., 属性n)`。例如：`Student(Sno, Sname, Ssex, Sage, Sdept)`。

```text
                  关系 (Relation / Table): 学生表
+--------+--------+--------+-----+------------+  <── 属性 (Attribute)
|  Sno   | Sname  |  Ssex  | Sage|   Sdept    |
+--------+--------+--------+-----+------------+
| 202601 | 李  明 |   男   |  20 | 计算机系   |  <── 元组 (Tuple / Row)
| 202602 | 王  芳 |   女   |  19 | 信息管理   |
| 202603 | 张  伟 |   男   |  21 | 计算机系   |
+--------+--------+--------+-----+------------+
    ▲
 主码 (Primary Key)
```

#### ③ 关系的规范化第一范式条件（1NF）
关系模型要求关系必须是**规范化的**。其中最基础的一条规则是：**每一个分量必须是一个不可分的数据项（Atomic Value）**，表中绝对不允许出现“表中有表”（嵌套表）的情况。

#### ④ 关系模型的卓越优势
1. **概念极其单一清晰**：用户面对的只有二维表一种数据结构，实体与联系都被整齐地平铺在表中；
2. **建立在坚实的数学基础之上**：关系理论直接建立在严格的集合论与谓词演算逻辑之上，具有完备的形式化定理支持；
3. **数据独立性登峰造极**：应用程序完全不关心底层数据是用 B+ 树还是散列表索引，不关心任何物理指针；用户只需使用非过程化的说明性语言（SQL）告知系统“要什么”（What），而无须关心底层系统“怎么取”（How），所有物理寻道与优化调度均由 DBMS 查询优化器全权接管。

## 3. 典型例题与深度认知辨析

### 辨析 1：为什么说层次模型与网状模型本质上是一类模型，而关系模型具有颠覆性？

- **本质对比**：
  - 层次模型和网状模型统称为**格式化数据模型**；
  - 它们的共性是：必须使用底层的**物理指针（Pointer）或物理地址链接**来刻画实体间的关联关系。程序员在写查询时，必须在代码中手动指明“沿着哪一条指针链游标前进”，一旦数据库物理重组，指针失效，程序即崩溃；
  - 关系模型则彻底抛弃了指针逻辑，实体与实体之间的联系完全依靠**二维表中的外码属性值（Value）**来自然匹配。逻辑关联与物理存储彻底解耦。

### 辨析 2：如何辨别联系的基数类型？

> **易错点**：判定联系是一对一还是一对多，必须基于客观业务规则的双向校验，绝不能单向主观臆断。

- **标准判定方法论**：
  - 设有实体型 $A$ 与实体型 $B$：
  - 若对于 $A$ 中的每一个实体，$B$ 中至多有 1 个实体与之对应；反之，对于 $B$ 中的每一个实体，$A$ 中至多也有 1 个实体与之对应，则为 **$1:1$ 联系**；
  - 若对于 $A$ 中的每一个实体，$B$ 中有 $n$（$n \ge 0$）个实体与之对应；而对于 $B$ 中的每一个实体，$A$ 中至多只有 1 个实体对应，则为 **$1:n$ 联系**；
  - 若双向均可能对应多于 1 个实体，则必为 **$m:n$ 联系**。

## 4. 随堂巩固自测

### 自测题 1（单项选择题）
在关系数据模型中，关于关系的性质描述，下列各项中错误的是（ ）
A. 列是同质的，即每一列中的分量是同类型的数据，来自同一个域  
B. 不同的列可以来自同一个域，但不同的列必须有不同的属性名  
C. 列的顺序无所谓，但行的顺序是严格不可调换的  
D. 每一个分量必须是不可分的数据项，表中不能包含嵌套子表  

**【答案】**：C  
**【解析】**：
- 关系在数学本质上是一个无序的元组集合。
- 因此在关系模型中：
  - 列的次序可以任意交换（因有属性名作为寻址标识）；
  - 行的次序也可以任意交换（元组在集合中是无序存放的，顺序不影响关系的数学语义）。故选项 C 称“行的顺序严格不可调换”是错误的。

### 自测题 2（建模与综合设计题）
设有科研管理业务场景：某高校有若干个「研究所」，每个研究所拥有若干名「科研人员」；若干名科研人员共同承担「科研项目」，每名科研人员可以参与多个科研项目，每个项目由多名人员协作完成。此外，每个项目使用若干种「实验仪器」。
请回答：
1. 本业务场景涉及哪些实体型？
2. 「研究所」与「科研人员」之间是什么联系？「科研人员」与「科研项目」之间是什么联系？

**【参考答案与解析】**：
1. **实体型识别**：
   - 研究所（Institute）
   - 科研人员（Researcher）
   - 科研项目（Project）
   - 实验仪器（Instrument）
2. **联系类型分析**：
   - **研究所与科研人员**：一个研究所聘任多名科研人员，而一名科研人员通常人事隶属于一个特定的研究所，因此两者之间是 **$1:n$（一对多）联系**；
   - **科研人员与科研项目**：一名科研人员可以同时参与修读/承担多个科研项目，而一个科研项目也需要由多名科研人员协作完成，因此两者之间是 **$m:n$（多对多）联系**。
