# 游标机制与多行查询（二）：阻抗失配破解、游标四步生命周期与定位更新实战

## 1. 核心概念与本质内涵：什么是“阻抗失配”？

在数据库与高级程序语言交互的世界中，存在一条著名的理论鸿沟——**阻抗失配（Impedance Mismatch）**：
- **SQL 语言的运算模型是“一次一集合（Set-at-a-time）”**：一条简单的 `SELECT` 查询可以瞬间从数据库中检索出 10,000 条数据行构成的二维集合；
- **通用高级语言（C/C++, Java）的变量模型是“一次一记录（Record-at-a-time）”**：主变量通常只能容纳单个标量或单一结构体。

> **核心工程矛盾**：宿主语言程序根本无法直接用一个普通的变量去承载并逐行处理包含几百上千行的 SQL 结果集！

为了化解集合操作与单行处理之间的致命冲突，关系数据库系统设计了核心的中介数据结构——**游标（Cursor）**。

```text
                  游标作为行级缓冲指针的协调机制
 SQL 多行查询结果集 (Active Set)               宿主语言 C 程序环境
+-------------------------------+              +--------------------+
| Row 1: 202601  张  三   20    |              | 主变量:            |
+-------------------------------+              | char  hs_sno[10];  |
| Row 2: 202602  李  四   19    | <──[游标指针]| char  hs_sname[20];|
+-------------------------------+              | int   hs_sage;     |
| Row 3: 202603  王  五   21    |              +--------------------+
+-------------------------------+                         ▲
| Row N: 202699  赵  六   20    |                         │ 每次 FETCH 推进一行，
+-------------------------------+                         │ 提取当前行填充主变量
```

## 2. 游标操作的四步标准生命周期

在嵌入式 SQL 程序中，使用游标处理多行查询必须严格遵循**声明 $\to$ 打开 $\to$ 推进提取 $\to$ 关闭**的四步曲：

```text
               游标四大生命周期阶段
[第 1 步: DECLARE CURSOR (声明游标)] ──> 静态绑定 SQL 语句，尚未执行
                 │
                 ▼
[第 2 步: OPEN CURSOR (打开游标)]    ──> 执行查询，生成活动集，指针置于首行前
                 │
                 ▼
[第 3 步: FETCH ... INTO (推进读取)] ──> 循环向下推进行指针，填充主变量
                 │ (直到 SQLCODE == 100 抵达结果集末尾)
                 ▼
[第 4 步: CLOSE CURSOR (关闭游标)]   ──> 释放游标占据的内部临时缓冲区
```

---

### 2.1 阶段 1：声明游标（DECLARE CURSOR）
- **语法**：
  ```sql
  EXEC SQL DECLARE <游标名> CURSOR FOR <SELECT 语句>;
  ```
- **机理**：此步骤是一条声明性说明，**DBMS 并不真正执行查询**，也不占用任何运行时内存，仅仅在数据字典中绑定该游标对应的逻辑 SQL。

---

### 2.2 阶段 2：打开游标（OPEN CURSOR）
- **语法**：
  ```sql
  EXEC SQL OPEN <游标名>;
  ```
- **机理**：DBMS 此时正式执行该 `SELECT` 语句，从底层磁盘检索数据并在系统内存中开辟一块**活动集合缓冲区（Active Set）**；
- **指针初始位置**：游标指针初始化停留在**活动集第一条元组的前面（虚空位置）**。

---

### 2.3 阶段 3：推进游标并提取数据（FETCH INTO）
- **语法**：
  ```sql
  EXEC SQL FETCH <游标名> INTO <主变量1> [, <主变量2>]...;
  ```
- **机理**：
  1. 将游标指针沿活动集向下推移定位到**下一条合法元组**；
  2. 将该元组各列的分量值，按顺序一对一精准赋值给 `INTO` 子句后面对应的宿主主变量；
- **循环终止检测**：当游标已经读完最后一行、再次执行 `FETCH` 时，DBMS 会自动将通信区中的 **`SQLCODE` 置为 `100`（代表“未找到数据 / 已达末尾”）**，程序通过检测此状态码平滑跳出 `while` 循环。

---

### 2.4 阶段 4：关闭游标（CLOSE CURSOR）
- **语法**：
  ```sql
  EXEC SQL CLOSE <游标名>;
  ```
- **机理**：通知 DBMS 销毁对应的活动集合，**彻底释放其占用的服务器内存与会话缓存句柄**。

---

## 3. 完整 C 语言游标查询实战范式

```c
#include <stdio.h>
EXEC SQL INCLUDE SQLCA; /* 引入通信区 */

int main() {
    EXEC SQL BEGIN DECLARE SECTION;
        char dept[20] = "CS";
        char sno[10];
        char sname[21];
        int  sage;
    EXEC SQL END DECLARE SECTION;

    /* 连接数据库 */
    EXEC SQL CONNECT TO my_database USER db_user IDENTIFIED BY secret;

    /* 1. 声明游标: 检索计算机系全部学生 */
    EXEC SQL DECLARE cur_student CURSOR FOR
        SELECT Sno, Sname, Sage 
        FROM Student 
        WHERE Sdept = :dept;

    /* 2. 打开游标 */
    EXEC SQL OPEN cur_student;

    printf("学号\t\t姓名\t\t年龄\n");
    printf("----------------------------------------\n");

    /* 3. 循环推进提取数据 */
    while (1) {
        EXEC SQL FETCH cur_student INTO :sno, :sname, :sage;
        
        if (sqlca.sqlcode == 100) {
            /* 已读取到结果集末尾，优雅跳出 */
            break;
        }
        if (sqlca.sqlcode < 0) {
            printf("读取数据发生异常: %ld\n", sqlca.sqlcode);
            break;
        }

        printf("%s\t%s\t%d\n", sno, sname, sage);
    }

    /* 4. 关闭游标 */
    EXEC SQL CLOSE cur_student;

    /* 断开连接 */
    EXEC SQL DISCONNECT CURRENT;
    return 0;
}
```

## 4. 基于游标的当前行定位更新与删除（WHERE CURRENT OF）

在很多交互式批处理系统中，业务逻辑要求：在读取到某一行数据并进行本地逻辑分析后，**当场对游标当前所指向的这一行记录发起物理修改或删除**：

### 核心语法规约：
1. **加锁声明**：在声明游标时，必须显式追加 `FOR UPDATE` 子句（这会强制让 DBMS 在扫描时为活动集的行施加排他锁，防止并发事务将其提前篡改）；
2. **当前行定位**：在 `UPDATE` 或 `DELETE` 语句的 `WHERE` 子句中，使用固定语法：
   ```sql
   WHERE CURRENT OF <游标名>;
   ```

```c
/* 声明可更新游标 */
EXEC SQL DECLARE cur_salary CURSOR FOR
    SELECT EmpID, Salary FROM Employee WHERE Dept = 'CS'
    FOR UPDATE;

EXEC SQL OPEN cur_salary;
while (1) {
    EXEC SQL FETCH cur_salary INTO :empid, :salary;
    if (sqlca.sqlcode == 100) break;
    
    if (salary < 5000) {
        /* 精确对游标当前指向的这一行员工记录涨薪 500 元 */
        EXEC SQL UPDATE Employee 
                 SET Salary = Salary + 500 
                 WHERE CURRENT OF cur_salary;
    }
}
EXEC SQL CLOSE cur_salary;
```

## 5. 随堂巩固自测

### 自测题 1（单项选择题）
在嵌入式 SQL 程序中使用游标处理多行查询时，当游标指针已经扫描并提取了活动集中的最后一条元组、再次执行 `FETCH` 时，系统通信区中的 `SQLCODE` 将被置为（ ）
A. 0  
B. -1  
C. 100  
D. NULL  

**【答案】**：C  
**【解析】**：SQL 标准明确规定，当没有满足条件的元组返回，或游标推进已抵达集合末端时，状态码 `SQLCODE` 统一被赋值为正整数 `100`（NOT FOUND），程序据此终止循环。故选 C。

---

### 自测题 2（概念分析题）
为什么普通的 `UPDATE Employee SET Salary = Salary + 100 WHERE Dept = 'CS'` 无法完全替代游标的 `WHERE CURRENT OF` 定位更新？请列举游标定位更新独有的核心优势场景。

**【参考答案与解析】**：
普通单条 `UPDATE` 语句只能执行简单的常量赋值或基于统一公式的批量修改。但在很多复杂业务场景中，**后续的修改决策高度依赖于高级语言中极其复杂的过程化算法**（例如：需要调用外部风控系统的微服务接口、根据用户复杂的信誉模型做多重规则判定、甚至需要与终端操作员进行二次弹窗交互确认）。在这种无法用纯单行 SQL 表达的场景下，通过游标将数据逐行提取到宿主程序内部，经过复杂的条件计算后，再利用 `WHERE CURRENT OF` 实施安全、精准的原地覆写，具有不可替代的工程价值。
