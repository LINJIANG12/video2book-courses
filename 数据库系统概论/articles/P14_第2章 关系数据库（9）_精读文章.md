# 关系代数综合实战（九）：经典三表模型多题型代数表达式构建与优化

## 1. 核心概念与本质内涵：经典教学数据模型全貌

在数据库系统教学与考研中，最经典、最权威的参照基准是**高校学生-课程-选课经典三表模型**。本讲以该模型为沙盒，系统演练从自然语言业务需求到形式化关系代数表达式的构造策略。

### 1.1 经典三表模式形式化规约

```text
1. 学生表 Student (主码: Sno)
   Student(Sno, Sname, Ssex, Sage, Sdept)
   (学号, 姓名, 性别, 年龄, 所在系)

2. 课程表 Course (主码: Cno)
   Course(Cno, Cname, Cpno, Ccredit)
   (课程号, 课程名, 先修课程号, 学分)
   (注: Cpno 为参照本表 Cno 的自参照外码)

3. 选课成绩表 SC (主码: (Sno, Cno))
   SC(Sno, Cno, Grade)
   (学号, 课程号, 成绩)
   (注: Sno 参照 Student(Sno), Cno 参照 Course(Cno))
```

```text
                     经典三表参照关系拓扑图
+-------------------+                      +-------------------+
|      Student      |                      |      Course       |
| (学生基本信息表)  |                      |  (课程信息表)     |
+-------------------+                      +-------------------+
|  Sno (PK)         |                      |  Cno (PK)         |
|  Sname, Sage ...  |                      |  Cname, Cpno (FK) |
+-------------------+                      +-------------------+

                    |        SC         |
                    |   (学生选课表)    |
                    +-------------------+
                    | (Sno, Cno) (PK)   |
                    | Grade             |
                    +-------------------+
```

## 2. 五大高频查询题型代数构造策略

### 题型 1：单表带复合谓词的过滤与抽取

- **需求**：查询计算机系（`CS`）所有年龄在 20 岁以下的女学生学号和姓名。
- **解题策略**：
  1. 涉及实体仅为学生，无需跨表连接，单表操作；
  2. 谓词条件由三个原子项构成，使用逻辑与（$\land$）连接；
  3. 最终投影抽取指定属性列。
- **关系代数表达式**：
  $$\pi_{\text{Sno}, \text{Sname}}(\sigma_{\text{Sdept} = \text{'CS'} \land \text{Sage} < 20 \land \text{Ssex} = \text{'女'}}(\text{Student}))$$

---

### 题型 2：多表自然连接与属性穿透查询

- **需求**：查询选修了《数据库系统概论》课程且成绩在 90 分以上的学生学号、姓名和成绩。
- **解题策略**：
  1. 学生姓名在 `Student` 表，课程名在 `Course` 表，成绩在 `SC` 表，涉及全部三张表；
  2. 利用公共属性进行自然连接：$\text{Student} \Join \text{SC} \Join \text{Course}$；
  3. 施加条件过滤并做投影。
- **关系代数表达式**：
  $$\pi_{\text{Sno}, \text{Sname}, \text{Grade}}(\sigma_{\text{Cname} = \text{'数据库系统概论'} \land \text{Grade} \ge 90}(\text{Student} \Join \text{SC} \Join \text{Course}))$$

---

### 题型 3：双重关联的交集（$\cap$）或自连接

- **需求**：查询至少同时选修了 1 号课程（`C01`）和 2 号课程（`C02`）的学生学号。
- **易错解法辨析**：
  > **严重错误**：写成 $\sigma_{\text{Cno} = \text{'C01'} \land \text{Cno} = \text{'C02'}}(\text{SC})$。
  > **错误原因**：在 `SC` 表的单行元组中，`Cno` 属性只能取一个具体值，不可能在同一行里既等于 `C01` 又等于 `C02`！该条件恒为假！
- **正确解法 A（集合交运算策略）**：
  分别提取选修了 `C01` 的学生学号集与选修了 `C02` 的学生学号集，求数学交集：
  $$\pi_{\text{Sno}}(\sigma_{\text{Cno} = \text{'C01'}}(\text{SC})) \cap \pi_{\text{Sno}}(\sigma_{\text{Cno} = \text{'C02'}}(\text{SC}))$$
- **正确解法 B（自身连接策略）**：
  $$\pi_{\text{Sno}}(\sigma_{1.\text{Sno} = 2.\text{Sno} \land 1.\text{Cno} = \text{'C01'} \land 2.\text{Cno} = \text{'C02'}}(\text{SC} \times \text{SC}))$$

---

### 题型 4：逻辑否定（“没有选修 / 从未参与”）的差运算（$-$）

- **需求**：查询**没有选修** 1 号课程（`C01`）的学生学号与姓名。
- **解题策略**：
  1. 严禁直接写 $\sigma_{\text{Cno} \neq \text{'C01'}}(\text{SC})$——这样查出来的只是该学生选修的其他课程行，只要该生选过任何其他课就会被误查出；
  2. 必须使用**全量集合减去否定集合**的思想：
     - 全校所有学生的学号集合：$\pi_{\text{Sno}}(\text{Student})$；
     - 选修了 1 号课程的学生学号集合：$\pi_{\text{Sno}}(\sigma_{\text{Cno} = \text{'C01'}}(\text{SC}))$；
     - 两者做差运算（$-$），得到未选 1 号课的学生学号；
     - 再与 `Student` 表自然连接以取得姓名。
- **关系代数表达式**：
  $$\pi_{\text{Sno}, \text{Sname}}(\text{Student} \Join (\pi_{\text{Sno}}(\text{Student}) - \pi_{\text{Sno}}(\sigma_{\text{Cno} = \text{'C01'}}(\text{SC}))))$$

---

### 题型 5：全称量词包含的除运算（$\div$）

- **需求**：查询选修了全部课程的学生姓名。
- **解题策略**：
  1. 识别全称量词“全部课程” $\implies$ 采用除运算；
  2. 被除数：学生选课对应关系 $\pi_{\text{Sno}, \text{Cno}}(\text{SC})$；
  3. 除数：全校所有课程号集合 $\pi_{\text{Cno}}(\text{Course})$；
  4. 除运算结果为满足条件的学生学号；再与 `Student` 连接提取姓名。
- **关系代数表达式**：
  $$\pi_{\text{Sname}}(\text{Student} \Join (\pi_{\text{Sno}, \text{Cno}}(\text{SC}) \div \pi_{\text{Cno}}(\text{Course})))$$

## 3. 关系代数表达式的启发式等价优化法则

在工程实现中，朴素书写的代数表达式往往效率极低。DBMS 查询优化器内部会遵循一条核心启发式规则：

> **【先做选择，后做连接（Pushdown Selection）】**：  
> 永远尽可能早地下推选择算子 $\sigma$，在数据进入昂贵的跨表笛卡尔积或连接之前，最大限度过滤掉无效元组，大幅缩减中间临时关系的基数。

```text
【未优化表达式】: 庞大笛卡尔积 -> 筛选
π_Sname(σ_(Student.Sno=SC.Sno ∧ SC.Cno='C01')(Student × SC))
(若 Student 1万人, SC 10万条, 笛卡尔积产生 10亿中间行!)

【等价优化表达式】: 先选择过滤 -> 后连接
π_Sname(Student ⋈ σ_(Cno='C01')(SC))
(先过滤出 C01 的几百条记录，再做精准连接，计算量降低数万倍!)
```

## 4. 随堂巩固自测

### 自测题 1（代数表达式构建题）
在经典三表模型下，请写出查询“至少选修了一门其直接先修课（Cpno）为 3 号课程的学生学号（Sno）”的形式化关系代数表达式。

**【参考答案与推导】**：
1. 先从 `Course` 表中选出先修课为 3 的课程：$\sigma_{\text{Cpno} = \text{'3'}}(\text{Course})$；
2. 将结果与选课表 `SC` 进行自然连接；
3. 投影出学号 `Sno`。
- 最终表达式：
  $$\pi_{\text{Sno}}(\text{SC} \Join \sigma_{\text{Cpno} = \text{'3'}}(\text{Course}))$$

---

### 自测题 2（辨析与证明题）
表达式 $E_1 = \pi_{\text{Sno}}(\text{Student}) - \pi_{\text{Sno}}(\sigma_{\text{Grade} < 60}(\text{SC}))$ 与表达式 $E_2 = \pi_{\text{Sno}}(\sigma_{\text{Grade} \ge 60}(\text{SC}))$ 在业务语义上是否等价？为什么？

**【参考答案与深度辨析】**：
两者**绝对不等价**！
1. **$E_2$ 的语义**：是“选修的课程中至少有一门成绩及格的学生学号”；
2. **$E_1$ 的语义**：是“所有在校学生集合减去有不及格成绩的学生集合”，其实际含义是“**所有门门功课均及格的学生，以及完全没有选修任何课程的学生**”；
3. 一个学生只要选了 3 门课且挂了 1 门，在 $E_2$ 中依然会因为其余两门及格而出现，而在 $E_1$ 中会被彻底剔除。此外从未选课的学生会在 $E_1$ 中出现但在 $E_2$ 中不存在。
