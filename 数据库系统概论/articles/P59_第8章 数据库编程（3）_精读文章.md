# 存储过程与函数机制（三）：预编译优势、参数模式流转与服务端封装实战

## 1. 核心概念与本质内涵：什么是存储过程与存储函数？

在传统的客户端-服务器（C/S）交互架构中，应用程序通过网络向数据库服务器逐条发送零散的 SQL 语句。每条语句都需要经历网络往返、服务端文本解析、词法语法分析、语义校验、查询优化与执行计划生成，造成沉重的网络延迟与 CPU 算力浪费。

为了解决这一弊端，数据库技术引入了**存储过程（Stored Procedure）**与**存储函数（Stored Function）**：
- **定义**：它们是一组为了完成特定功能的 SQL 语句与过程化控制逻辑的集合，**经过编译后长久保存在数据库服务器的数据字典中**；
- 应用程序只需通过网络发送简短的调用命令（如 `CALL`）并传入必要参数，整个复杂的业务逻辑全权在服务器端内存中极速闭环运行。

```text
               普通网络交互 SQL vs 存储过程架构对比
【普通交互式 SQL: 多次往返】                   【存储过程: 一次调用，服务端闭环】
  应用客户端              数据库服务端           应用客户端              数据库服务端
      │                       │                      │                       │
      │ ── 1. 发送 SQL 1 ───> │                      │ ── CALL Proc(p1) ───> │ [加载预编译计划]
      │ <── 返回中间数据 1 ── │                      │                       │ ├── 内部循环执行
      │ ── 2. 发送 SQL 2 ───> │                      │                       │ ├── 内部事务控制
      │ <── 返回中间数据 2 ── │                      │                       │ └── 内部运算统计
      │ ── 3. 发送 UPDATE ──> │                      │ <── 仅返回最终结果 ── │
  (高网络延迟，频繁序列化反序列化)               (极低网络消耗，执行速度达到内存级极致)
```

## 2. 存储过程的核心优势矩阵

1. **预编译执行的高性能（Precompiled Execution）**：
   - 存储过程在第一次创建时，DBMS 就会对其进行深度的语法解析和代价估算，生成最优的底层二进制执行计划并**常驻在共享内存缓冲池中**；
   - 后续任何客户端再次发起调用，彻底跳过编译与优化阶段，直接以机器码级别极速执行。
2. **大幅削减网络流量（Reduced Network Traffic）**：
   - 将涉及几千行数据循环、数十次条件判断的复杂业务全权收敛在服务端本地执行，网络中只流动一条轻量的调用报文与最终标量结果。
3. **增强的数据安全防护（Security Decoupling）**：
   - DBA 可以将底层核心物理表（如银行资金表）的直接 `SELECT`, `UPDATE` 权限对普通应用账号完全锁死；
   - **仅向应用程序员授予特定存储过程的 `EXECUTE` 执行权限**。用户只能通过受控的过程逻辑黑盒修改数据，彻底阻断了 SQL 注入与非授权越权篡改。

## 3. 存储过程的创建语法与三大参数模式

### 3.1 语法规约与参数模式（IN, OUT, INOUT）

```sql
CREATE PROCEDURE <过程名> (
    [IN | OUT | INOUT] <参数名> <数据类型> [, ...]
)
BEGIN
    <过程化 SQL 代码块>;
END;
```

```text
                       三大参数传递模式深度剖析
                                  │
      ┌───────────────────────────┼───────────────────────────┐
      ▼                           ▼                           ▼
【IN 参数 (默认输入模式)】      【OUT 参数 (纯输出模式)】      【INOUT 参数 (双向模式)】
 • 外部调用者传入参数值         • 初始值为 NULL               • 外部传入初始值作为输入
 • 过程体内部只读，不可篡改外部 • 过程体内部计算并赋值        • 过程体内部修改后作为输出回传
 • 类似 C 语言的按值传递        • 退出时将最终值回传给调用方  • 类似 C 语言的按引用指针传递
```

### 3.2 存储过程生产开发实战演练

**需求场景**：为高校教务系统编写一个存储过程 `TransferStudent`，将某学生从原系别转移到新系别。
- 输入参数：学生学号 `in_sno`，目标系别 `in_new_dept`；
- 输出参数：操作执行状态码 `out_code`（0 代表成功，-1 代表该学生不存在）。

```sql
DELIMITER //

CREATE PROCEDURE TransferStudent (
    IN  in_sno      CHAR(9),
    IN  in_new_dept VARCHAR(20),
    OUT out_code    INT
)
BEGIN
    DECLARE v_count INT DEFAULT 0;

    -- 1. 检查目标学生是否存在
    SELECT COUNT(*) INTO v_count 
    FROM Student 
    WHERE Sno = in_sno;

    IF v_count = 0 THEN
        -- 学生不存在，返回错误码
        SET out_code = -1;
    ELSE
        -- 2. 学生存在，执行修改
        UPDATE Student 
        SET Sdept = in_new_dept 
        WHERE Sno = in_sno;
        
        SET out_code = 0;
    END IF;
END //

DELIMITER ;
```

#### 调用与执行方式：
```sql
-- 声明用户会话变量接收结果
CALL TransferStudent('202601', '软件工程', @status);
SELECT @status AS 执行结果状态码;
```

## 4. 存储过程 vs 存储函数的本质分野

除了存储过程，SQL 标准还提供了**存储函数（Stored Function）**。二者核心区别如下：

| 比较维度 | 存储过程（Stored Procedure） | 存储函数（Stored Function） |
| :--- | :--- | :--- |
| **关键字** | `CREATE PROCEDURE` | `CREATE FUNCTION` |
| **返回值机制** | **无直接单一返回值**，需通过 `OUT` 或 `INOUT` 参数间接传回多个值 | **强制必须包含 `RETURNS <类型>`** 与 `RETURN <单值>` 语句 |
| **调用执行方式** | 必须通过独立的 **`CALL` 语句** 单独触发 | **可以直接嵌入在任何普通的 SQL 表达式中**！ |
| **典型调用场景** | `CALL ProcName(p1, @out);` | `SELECT Sno, CalcRank(Grade) FROM SC;` |

```sql
-- 存储函数示例: 依据成绩返回等级
CREATE FUNCTION GetGradeLevel (p_grade INT)
RETURNS VARCHAR(10)
DETERMINISTIC
BEGIN
    IF p_grade >= 90 THEN RETURN '优秀';
    ELSEIF p_grade >= 80 THEN RETURN '良好';
    ELSEIF p_grade >= 60 THEN RETURN '及格';
    ELSE RETURN '不及格';
    END IF;
END;
```

## 5. 随堂巩固自测

### 自测题 1（单项选择题）
在关系数据库中，关于存储过程（Stored Procedure）与存储函数（Stored Function）的区别，说法正确的是（ ）
A. 存储过程可以直接嵌入在 SELECT 语句的目标列表中执行  
B. 存储函数必须显式声明 RETURNS 子句，并且在函数体中通过 RETURN 语句返回单一值  
C. 存储函数只能在命令行交互式调用，不能被程序调用  
D. 存储过程不能使用任何局部变量  

**【答案】**：B  
**【解析】**：存储函数必须在头部定义 `RETURNS <类型>`，且在函数体中必须执行 `RETURN` 返回一个标量，可直接在普通 SQL 的表达式（如 SELECT 列名）中直接调用。存储过程无直接标量返回值，必须使用 CALL 独立调用。故选 B。

### 自测题 2（过程化编程实战题）
某银行系统需要编写一个存储过程 `AdjustInterest`，用于对指定账户（`AccountID`）进行利息计结并转存：
- 输入参数：账户编号 `in_acc_id`，年化利率 `in_rate`；
- 输出参数：结算后的全新账户余额 `out_new_balance`；
- 业务逻辑：当前余额乘以 `(1 + in_rate)` 得到新余额，更新数据库并输出。  
请编写完整的标准 SQL 存储过程创建代码。

**【参考答案】**：
```sql
DELIMITER //

CREATE PROCEDURE AdjustInterest (
    IN  in_acc_id       CHAR(18),
    IN  in_rate         NUMERIC(5, 4),
    OUT out_new_balance NUMERIC(14, 2)
)
BEGIN
    DECLARE v_current_balance NUMERIC(14, 2);

    -- 1. 提取当前余额
    SELECT Balance INTO v_current_balance
    FROM BankAccount
    WHERE AccountID = in_acc_id;

    -- 2. 结息计算
    SET out_new_balance = v_current_balance * (1.0 + in_rate);

    -- 3. 落地更新
    UPDATE BankAccount
    SET Balance = out_new_balance
    WHERE AccountID = in_acc_id;
END //

DELIMITER ;
```
