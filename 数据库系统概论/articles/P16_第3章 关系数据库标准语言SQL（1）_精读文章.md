# SQL语言概述（一）：发展沿革、核心特征与三级模式映射

## 1. 核心概念与本质内涵：SQL 的诞生与时代使命

**SQL（Structured Query Language，结构化查询语言）**是关系数据库系统的通用标准语言。1974 年由 Boyce 和 Chamberlin 提出（最初称为 SEQUEL），并在 IBM 的 System R 实验关系数据库系统上得以实现。随后，美国国家标准学会（ANSI）与国际标准化组织（ISO）先后将其确立为国际工业标准，至今经历了 SQL-86, SQL-89, SQL-92, SQL:1999, SQL:2003, SQL:2016 等多次迭代演进。

SQL 之所以能统治关系数据库长达半个世纪，核心在于其完美统一了数据的定义、查询、操纵与控制功能。

```text
                       SQL 语言的功能与命令矩阵
                                  │
      ┌───────────────────┬───────┴───────┬───────────────────┐
      ▼                   ▼               ▼                   ▼
【数据定义 (DDL)】    【数据查询 (DQL)】  【数据操纵 (DML)】  【数据控制 (DCL)】
  CREATE (创建)         SELECT (查询)       INSERT (插入)       GRANT  (赋权)
  DROP   (删除)                             UPDATE (修改)       REVOKE (收回)
  ALTER  (修改)                             DELETE (删除)       COMMIT / ROLLBACK
```

## 2. SQL 语言的核心技术特征

### 2.1 综合一体（All-in-one）
在传统的非关系型数据库中，数据定义语言（DDL）、数据操纵语言（DML）和数据控制语言（DCL）往往彼此分离且语法差异极大。
SQL 则将四种能力有机融为一体：
- 数据定义与操纵语言风格高度统一，使得数据库管理员（DBA）与应用开发者可以在同一个终端会话中自由流转；
- 支持在数据库运行生命周期中**动态修改模式（Dynamic Schema Evolution）**，无需停机重新编译。

### 2.2 高度非过程化（Non-procedural）
- 使用 SQL 进行数据操作时，用户只需提出“做什么（What to do）”，即明确结果数据应满足的约束条件；
- 完全不需要指定存取路径，也不需要了解底层数据在磁盘上是以何种物理文件存储、使用何种树形索引；
- 复杂的存取路径选择与代数优化完全由 DBMS 引擎内部自动完成。

### 2.3 面向集合的操作方式（Set-at-a-time）
- 传统的格式化模型采用的是“一次一记录（Record-at-a-time）”的游标循环逻辑；
- SQL 则彻底采用“一次一集合（Set-at-a-time）”机制：不仅查询结果是元组的集合，而且一次 `INSERT`, `UPDATE`, `DELETE` 语句的作用对象同样可以是由条件过滤出的一组元组。

### 2.4 以同一种语法结构提供两种使用方式
- **交互式 SQL（Interactive SQL）**：供最终用户或管理员在终端、Navicat、DBeaver、pgAdmin 等工具中直接输入并即时执行；
- **嵌入式 SQL（Embedded SQL / Host Language）**：允许将 SQL 语句嵌入到高级程序设计语言（如 C/C++, Java, Python, Go）中，通过游标或现代 ORM 框架与宿主语言紧密协同。两种场景下 SQL 的语法体系完全保持一致。

## 3. 数据库三级模式结构在 SQL 中的落地映射

《数据库系统概论》第 1 章介绍的 ANSI 三级模式结构，在 SQL 标准中找到了具体、精准的工程具象化映射：

```text
三级模式体系结构 (Theoretical)              SQL 工程实现架构 (SQL Implementation)
───────────────────────────────              ─────────────────────────────────────
    [外模式 (External Schema)]     <=======>    视图 (View) 与部分导出表
                │                                (对用户可见的局部虚拟定制逻辑结构)
                ▼                                              │
    [概念模式 (Schema)]            <=======>    基本表 (Base Table)
                │                                (独立存在的实际表，全局数据逻辑核心)
                ▼                                              │
    [内模式 (Internal Schema)]     <=======>    存储文件 (Stored File)
                                                 (物理磁盘上的数据块、页、B+树索引簇)
```

1. **基本表（Base Table）对应概念模式**：
   - 基本表是本身独立存在的表，每个基本表对应一个关系；
   - 一个关系数据库中由若干基本表构成的全局逻辑结构，正是概念模式的物理落地；
2. **视图（View）对应外模式**：
   - 视图是从一个或几个基本表（或其他视图）导出的“虚表”；
   - 数据库中只存放视图的定义（SQL 语句元数据），不存放视图对应的数据（数据仍保存在原基本表中）；
   - 用户通过视图观察数据，实现了对敏感字段的隐藏与定制化呈现，精确落地外模式；
3. **存储文件（Stored File）对应内模式**：
   - 逻辑上的基本表在物理层由一个或多个存储文件实现；
   - 存储文件内部包含具体的记录物理存储格式、页面布局以及索引结构。

## 4. 典型例题与深度认知辨析

### 辨析 1：基本表与视图的本质区别是什么？

- **本质对比**：
  - **基本表**：是物理磁盘上有真实数据行落盘的物理关系，拥有独立持久化的数据空间；
  - **视图**：是虚拟表，在数据字典中仅仅记录了一段查询定义的文本（SQL 逻辑）。当用户查询视图时，DBMS 动态执行**视图消解（View Resolution）**，将其转化为对底层基本表的查询。

### 辨析 2：SQL 为什么被称为“非过程化”语言？

- 在 SQL 中没有 `for` 循环、没有指针跳转、没有内存偏移量计算。例如 `SELECT * FROM Student WHERE Sage > 20;` 仅仅陈述了结果集的筛选规则，系统底层是用全表扫描还是走 B+ 树索引，对用户完全屏蔽。

## 5. 随堂巩固自测

### 自测题 1（单项选择题）
在关系数据库系统中，SQL 语言中的“视图（View）”对应于三级模式结构中的（ ）
A. 模式  
B. 内模式  
C. 外模式  
D. 存储模式  

**【答案】**：C  
**【解析】**：视图是面向具体用户或应用程序的局部逻辑视图，对应于三级模式结构中的外模式（子模式）。基本表对应模式，存储文件对应内模式。故选 C。

---

### 自测题 2（简答与概念分析题）
请列举 SQL 语言针对数据生命周期管理所包含的四分子系统（语言类型），并分别列出其最典型的 1~2 个核心关键字。

**【参考答案与解析】**：
1. **数据定义语言（DDL）**：用于定义模式、表、视图、索引。核心关键字：`CREATE`, `DROP`, `ALTER`；
2. **数据查询语言（DQL）**：用于检索数据。核心关键字：`SELECT`；
3. **数据操纵语言（DML）**：用于更新持久化数据。核心关键字：`INSERT`, `UPDATE`, `DELETE`；
4. **数据控制语言（DCL）**：用于权限管理与事务控制。核心关键字：`GRANT`, `REVOKE`, `COMMIT`, `ROLLBACK`。
