## 1. 核心概念与本质内涵：Java 世界的数据访问中枢

随着互联网与企业级 Java 应用的爆发式崛起，Sun 公司（现 Oracle）在吸收了 ODBC 跨平台解耦思想的基础之上，面向对象地推出了专门面向 Java 语言环境的数据库访问标准接口——**JDBC（Java Database Connectivity）**。

JDBC 定义了一套全纯粹的 Java 抽象接口类（`java.sql.*` 与 `javax.sql.*`），为 Java 开发者提供了完全统一的、类型安全的数据库连接、事务处理、批处理与元数据探针能力。

## 2. JDBC 四大核心接口与标准交互范式

现代 JDBC 核心交互规范围绕四个经典接口展开：

```text
                      JDBC 四大核心接口调用链条
DriverManager ──> Connection (网络连接与事务控制: setAutoCommit, commit)
                       │
                       ▼
                 PreparedStatement (预编译 SQL 与参数绑定，防 SQL 注入)
                       │
                       ▼
                 ResultSet (结果集游标，通过 rs.next() 逐行提取)
```

1. **`Connection` 接口**：代表与物理数据库建立的 TCP 网络套接字会话通道。它同时承担着**事务控制的最高职责**：
   - `conn.setAutoCommit(false);` —— 开启手动显式事务；
   - `conn.commit();` —— 提交事务；
   - `conn.rollback();` —— 事务异常回滚。
2. **`PreparedStatement` 接口**：预编译语句对象，用于执行带参数的动态 SQL。
3. **`ResultSet` 接口**：代表查询结果的逻辑游标迭代器，通过 `while (rs.next())` 逐行滚动推进。

## 3. 核心安全命门：Statement vs PreparedStatement（彻底粉碎 SQL 注入）

> **【全行业最高危漏洞防御】**：为什么在一切正规企业级生产开发中，**100% 严禁使用普通的 `Statement` 字符串拼接，必须且强制使用 `PreparedStatement`**？

```text
【Statement 字符串拼接致命漏洞 (SQL 注入)】
String sql = "SELECT * FROM Users WHERE User='" + inputUser + "' AND Pwd='" + inputPwd + "'";
若黑客恶意输入:
inputUser = "admin' --" 
拼接后的 SQL 瞬间变为:
SELECT * FROM Users WHERE User='admin' --' AND Pwd='...'
(密码校验逻辑被 SQL 注释符 "--" 彻底切断，黑客直接无密码登录超级管理员!)
```

### 3.1 PreparedStatement 彻底终结 SQL 注入的底层机理

```java
// 正确的预编译安全写法:
String sql = "SELECT * FROM Users WHERE User = ? AND Pwd = ?";
PreparedStatement pstmt = conn.prepareStatement(sql);
pstmt.setString(1, inputUser); // 无论黑客传入何种恶意字符，一律作为纯文本字面值对待!
pstmt.setString(2, inputPwd);
ResultSet rs = pstmt.executeQuery();
```

#### 双重核心技术收益：
1. **彻底杜绝 SQL 注入（Security）**：
   - `PreparedStatement` 采用**参数化预编译（Parameterized Compilation）**；
   - SQL 语句骨架在传入数据库时，先被编译生成静态语法树，其中的占位符 `?` 是不可改变语法结构的字面插槽；
   - 无论黑客在参数中输入多少个 `' OR '1'='1` 或 `--` 注释符，引擎只将其作为普通的标量字符串数据处理，绝不可能改变原 SQL 的语法树分支结构！
2. **执行性能大幅提升（Performance）**：
   - 数据库服务器端会缓存预编译后的执行计划；
   - 当循环执行 10,000 次插入时，SQL 骨架只需在服务器编译 1 次，后续 9,999 次只需要传输二进制参数，省去海量 CPU 编译优化开销。

## 4. 现代数据库访问架构演进：连接池与 ORM

### 4.1 数据库连接池技术（Connection Pool）
- **物理痛点**：数据库建立一次 TCP 网络连接需要经历复杂的网络握手、协议协商、权限密码核验与内存线程开辟，开销高达几十毫秒；
- **连接池机制（如 HikariCP, Druid）**：
  - 系统启动时预先创建一组常驻的“长连接”池化管理；
  - 应用程序用时向连接池“借”，用完“还”回池中，避免频繁断开重连，性能提升数十倍。

### 4.2 对象关系映射（ORM，Object-Relational Mapping）
- 将关系数据库中的**二维表**映射为面向对象语言中的**类（Class）**；
- 将表中的**每一行元组**映射为一个**对象实例（Object）**；
- 现代主流框架（如 MyBatis, Hibernate, JPA）全自动完成数据对象与 SQL 之间的类型转换。

## 6. 随堂巩固自测

### 自测题 1（单项选择题）
在 Java JDBC 编程中，使用 `PreparedStatement` 替代传统的 `Statement` 的核心安全与性能优势在于（ ）
A. `PreparedStatement` 支持自动连接池管理  
B. `PreparedStatement` 采用参数化预编译机制，从语法结构上彻底杜绝了 SQL 注入攻击，且支持服务端执行计划复用  
C. `PreparedStatement` 只能执行 SELECT 查询，不能执行 UPDATE  
D. `PreparedStatement` 自动为每一行数据建立 B+ 树索引  

**【答案】**：B  
**【解析】**：`PreparedStatement` 在执行前先将 SQL 骨架送入引擎编译，占位符 `?` 严格作为参数填入，不会改变已生成的语法解析树，从机制上根除了 SQL 注入漏洞，同时享受服务端的预编译缓存。故选 B。

### 自测题 2（JDBC 核心编程设计题）
请使用标准 Java JDBC 规范（包含 `try-with-resources` 自动资源管理与 `PreparedStatement` 参数化安全查询），编写一段核心代码：
“根据传入的方法参数 `String queryDept`，查询 `Student` 表中属于该系的所有学生的学号（`Sno`）与姓名（`Sname`），并打印输出”。

**【参考答案】**：
```java
public void printStudentsByDept(Connection conn, String queryDept) {
    String sql = "SELECT Sno, Sname FROM Student WHERE Sdept = ?";
    
    // 使用 try-with-resources 确保 PreparedStatement 与 ResultSet 安全自动关闭
    try (PreparedStatement pstmt = conn.prepareStatement(sql)) {
        // 参数化绑定占位符，杜绝 SQL 注入
        pstmt.setString(1, queryDept);
        
        try (ResultSet rs = pstmt.executeQuery()) {
            System.out.println("学号\t\t姓名");
            System.out.println("------------------------");
            while (rs.next()) {
                String sno = rs.getString("Sno");
                String sname = rs.getString("Sname");
                System.out.println(sno + "\t" + sname);
            }
        }
    } catch (SQLException e) {
        System.err.println("数据库查询发生异常: " + e.getMessage());
    }
}
```
