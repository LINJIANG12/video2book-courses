# 并发调度与可串行性（五）：冲突可串行化定理、优先图无环判定与两段锁协议（2PL）

## 1. 核心概念与本质内涵：什么是“正确的”并发调度？

在多事务并发执行的环境中，事务的各项操作（读、写）交织穿插在一起，构成了复杂的**并发调度（Schedule）**。

> **【并发控制的最高哲学问题】**：什么样的并发调度才算是“正确”的？系统如何判定并发执行的结果没有产生逻辑紊乱？

数据库理论给出了唯一的数学评判准绳——**可串行性（Serializability）**：
- **定义**：多个事务并发执行是正确的，**当且仅当其执行结果与按某一种顺序串行（Serial）执行这些事务时的结果完全相同**，这种调度称为**可串行化的调度（Serializable Schedule）**；
- 串行调度（一个接一个排队执行）由于完全没有交叉干扰，天生具有百分之百的一致性正确性；
- 因此，任何一个并发调度，只要其逻辑计算产出与某一个串行执行序列等价，它就是合法的、正确的！

```text
               可串行化调度的数学等价性
   并发交叉调度 S                               等价的串行调度 S'
────────────────────────                    ────────────────────────
T1: 读A ───> 写A                            T1: 读A ──> 写A ──> 提交
T2:               读B ──> 写B               T2: 读B ──> 写B ──> 提交
(宏观并发高效运行，多核满载)                (微观逻辑结果完全严密等价!)
```

## 2. 冲突可串行化（Conflict Serializability）形式化理论

在实际系统中，直接判定任意两个调度的计算结果是否相等极其困难。学术界引入了更具机械可操作性的**冲突可串行化**判定准则。

### 2.1 冲突操作（Conflicting Operations）
在并发调度中，针对**不同事务中针对同一个数据项的两个相邻操作**：
- **读-读操作（Read-Read）**：**不冲突**（任意交换次序不影响结果）；
- **读-写操作（Read-Write）**：**必冲突（Conflicting）**！交换次序会改变读取到的数据值；
- **写-写操作（Write-Write）**：**必冲突（Conflicting）**！交换次序会改变最终物理落盘的覆写结果。

```text
                  操作交换相容性矩阵
              同一数据项的操作      读操作 (Read)    写操作 (Write)
              ─────────────────    ──────────────   ──────────────
              读操作 (Read)        可交换 (不冲突)  不可交换 (冲突!)
              写操作 (Write)       不可交换 (冲突!) 不可交换 (冲突!)
```

---

### 2.2 冲突可串行化定理与优先图（Precedence Graph）判定法

一个并发调度 $S$ 在不改变冲突操作先后次序的前提下，**若能通过一系列非冲突操作的合法交换，将其等价变形为一个串行调度**，则称 $S$ 是**冲突可串行化的调度**。

> **【冲突可串行化充分条件】**：  
> **一个冲突可串行化的调度，必然是可串行化调度！**

#### 优先图（Precedence Graph，又称序列化图）判定算法：
1. **构图规则**：
   - 图的节点为所有并发事务 $T_1, T_2, \dots, T_n$；
   - 若在调度中存在针对同一数据项的冲突操作，且**事务 $T_i$ 的操作先于 $T_j$ 的操作执行**，则在图中画一条有向边：
     $$T_i \to T_j$$
2. **【核心充要判定定理】**：  
   **调度 $S$ 是冲突可串行化的充分必要条件是：其优先图（Precedence Graph）中不存在任何有向环路（Acyclic，即为一个有向无环图 DAG）！**
3. 若无环，对优先图执行**拓扑排序（Topological Sort）**，所得的线性序列就是与之等价的串行调度序列。

```text
【优先图判定示例】
  有向无环 (DAG):  [ T1 ] ─────> [ T2 ] ─────> [ T3 ]  ===> 冲突可串行化! 等价串行序列: T1 -> T2 -> T3
  存在回路 (Cycle):[ T1 ] <────> [ T2 ]                ===> 非冲突可串行化! (调度发生逻辑紊乱)
```

## 3. 两段锁协议（Two-Phase Locking, 2PL）——可串行化的实现保障

虽然优先图可以检验可串行性，但优化器不可能在事务运行完之后再去“事后验尸”。DBMS 必须在事务运行过程中，实时施加一种能够**自动天然保证可串行化**的动态封锁协议，这就是著名的 **两段锁协议（2PL）**。

### 3.1 两段锁协议的核心规约
2PL 要求所有事务在存活期间，加锁和解锁必须严格划分为**两个单调的独立阶段**：

```text
                     两段锁协议 (2PL) 状态转移
加锁数量
   ▲
   │        【阶段 1: 扩展阶段 (Growing Phase)】
   │         • 只能申请并获得任何锁 (S锁/X锁)
   │         • 【绝对不能释放任何锁!】
   │                         │
   │                         ▼ [获得全部锁达到峰值 (Lock Point)]
   │                         │
   │        【阶段 2: 收缩阶段 (Shrinking Phase)】
   │         • 一旦释放了第一个锁，正式进入收缩期!
   │         • 只能释放锁，【绝对不能再申请任何新锁!】
   └─────────────────────────────────────────────────────> 时间轴
```

---

### 3.2 两段锁协议的至高里程碑定理

> **【两段锁充分性定理】**：  
> **若并发执行的所有事务都严格遵守两段锁协议（2PL），则这些事务的任何并发调度策略都必然是冲突可串行化的！**

- **理论价值**：只要让每个事务在代码层面遵守 2PL（在放锁前把该拿的锁全拿完，一旦放锁就只放不拿），DBMS 无需关心复杂的交叉时序，调度结果必然天然百分之百正确！

### 3.3 2PL 与死锁的辩证辨析
> **【高频考研易错命门】**：遵循两段锁协议（2PL）的事务，会发生死锁吗？

- **答案是：依然可能发生死锁！**
- **机理分析**：2PL 只规定了“加锁必须在放锁前”，但**并未规定各个事务以何种顺序加锁**。事务 $T_1$ 在其扩展阶段拿了 $A$ 并申请 $B$，事务 $T_2$ 在其扩展阶段拿了 $B$ 并申请 $A$，双方都在其合法的“扩展阶段”，但仍然会爆发死锁！
- **结论：2PL 是可串行化的充分条件，但不是无死锁的保证！**

## 4. 随堂巩固自测

### 自测题 1（单项选择题）
在关系数据库并发控制理论中，关于两段锁协议（2PL）的叙述，正确的是（ ）
A. 遵守两段锁协议的并发调度必然是可串行化的  
B. 遵守两段锁协议的事务绝不可能发生死锁  
C. 两段锁协议要求事务在开始时必须一次性申请所有锁  
D. 只要调度是可串行化的，它就必然遵守两段锁协议  

**【答案】**：A  
**【解析】**：2PL 是可串行化的充分条件，遵守 2PL 必然保证可串行化（选项 A 正确）；但 2PL 事务在扩展阶段依然可能产生循环等待死锁（选项 B 错误）。2PL 允许分步加锁只要不提前放锁即可，不是一次封锁（选项 C 错）。2PL 不是可串行化的必要条件，存在不符合 2PL 但可串行化的特例（选项 D 错）。故选 A。

### 自测题 2（调度冲突判定实战题）
设有调度 $S$，包含两个事务 $T_1$ 和 $T_2$ 的如下操作时序：
$$S = r_1(A), \quad w_1(A), \quad r_2(A), \quad w_2(A), \quad r_1(B), \quad w_1(B), \quad r_2(B), \quad w_2(B)$$
请问：
1. 列出该调度中的所有冲突操作对；
2. 绘制其优先图（Precedence Graph），并判定该调度是否为冲突可串行化调度？若是，写出与之等价的串行调度序列。

**【参考答案与推导】**：
1. **冲突操作对识别**：
   - 针对数据 $A$：$w_1(A)$ 先于 $r_2(A)$ 执行（写-读冲突），$w_1(A)$ 先于 $w_2(A)$ 执行（写-写冲突）$\implies$ 强制要求顺序 $T_1 \to T_2$；
   - 针对数据 $B$：$w_1(B)$ 先于 $r_2(B)$ 执行，$w_1(B)$ 先于 $w_2(B)$ 执行 $\implies$ 强制要求顺序 $T_1 \to T_2$；
2. **优先图构建与判定**：
   - 节点为 $\{T_1, T_2\}$；
   - 所有的冲突操作均由 $T_1$ 指向 $T_2$，图中只有一条单向边：$T_1 \to T_2$；
   - **判定结论**：优先图中**不存在任何闭合回路（无环）**，因此该调度是**严格冲突可串行化的**！
   - 与之等价的串行调度序列为：**先执行完 $T_1$，后执行完 $T_2$（即 $T_1 \to T_2$）**。
