# 规范化范式理论（四）：第一范式、第二范式与部分依赖消除模式分解

## 1. 核心概念与本质内涵：范式（Normal Form）的层级阶梯

关系模式的规范化过程，本质上是一个**通过模式分解，逐步消除不合理的数据依赖、消解数据冗余与操作异常的过程**。

关系满足某种程度的规范化要求的标准，称为**范式（Normal Form, NF）**。各级范式之间存在着严格的层层递进、真子集包含关系：

```text
                  关系范式包含层级谱系
+---------------------------------------------------------------+
| 第一范式 (1NF: 分量原子性)                                    |
|   +---------------------------------------------------------+ |
|   | 第二范式 (2NF: 消除非主属性对码的部分函数依赖)          | |
|   |   +---------------------------------------------------+ | |
|   |   | 第三范式 (3NF: 消除非主属性对码的传递函数依赖)    | | |
|   |   |   +---------------------------------------------+ | | |
|   |   |   | BCNF (Boyce-Codd: 消除主属性对码的部分/传递) | | | |
|   |   |   |   +---------------------------------------+ | | | |
|   |   |   |   | 第四范式 (4NF: 消除多值依赖)          | | | | |
|   |   |   |   +---------------------------------------+ | | | |
|   |   |   +---------------------------------------------+ | | |
|   |   +---------------------------------------------------+ | |
|   +---------------------------------------------------------+ |
+---------------------------------------------------------------+
```

---

## 2. 第一范式（1NF）：关系模型的入门门槛

### 2.1 形式化定义
如果关系模式 $R$ 的**所有属性的域都是原子的（不可再分的标量数据项）**，则称 $R$ 属于第一范式，记作：

$$R \in 1\text{NF}$$

### 2.2 1NF 的致命缺陷
1NF 是进入关系数据库世界最底线的要求。然而，1NF **仅仅规定了数据的物理结构不能嵌套表，对属性之间错综复杂的函数依赖没有做出任何约束**！
- 在 1NF 中，普遍存在非主属性对候选码的**部分函数依赖**与**传递函数依赖**；
- 这正是导致前文所述的四大严重缺陷（海量冗余、修改异常、插入异常、删除异常）的罪魁祸首。

---

## 3. 第二范式（2NF）：消除部分函数依赖

### 3.1 形式化定义
若关系模式 $R \in 1\text{NF}$，并且**每一个非主属性都完全函数依赖于 $R$ 的任何一个候选码**，则称 $R$ 属于第二范式，记作：

$$R \in 2\text{NF}$$

> **【核心判定口诀】**：**2NF 彻底消除了非主属性对码的部分函数依赖（Partial Dependency）**！

---

### 3.2 2NF 的三大速判黄金公理

在工程实践与考研试卷中，判定一个 1NF 模式是否满足 2NF，可直接应用以下定理：

1. **单属性候选码公理**：
   - 若关系模式 $R$ 的**每一个候选码都是单个属性**（而不是复合属性组），则 $R$ **必然自动满足 2NF**！
   - **证明推导**：单属性的真子集只有空集 $\varnothing$。既然没有非空的真子集，就绝不可能存在“某个真子集独立决定非主属性”的情况，部分依赖在结构上被彻底绝杀。
2. **全码公理**：
   - 若关系模式 $R$ 的候选码是全码（所有属性构成码），则 $R$ 中根本不存在非主属性，必然自动满足 2NF。
3. **复合码易碎区**：
   - 只有当关系模式的**候选码是由两个或更多属性联合构成的复合属性组**时，才需要警惕是否存在部分函数依赖。

---

## 4. 2NF 模式分解实战演练

以经典的选课大宽表为例：

$$R(\underline{\text{Sno}}, \underline{\text{Cno}}, \text{Sdept}, \text{Sloc}, \text{Grade})$$
- 候选码为复合属性组：$(\text{Sno}, \text{Cno})$；
- 主属性为：$\{\text{Sno}, \text{Cno}\}$；
- 非主属性为：$\{\text{Sdept}, \text{Sloc}, \text{Grade}\}$；
- 函数依赖集：
  $$\begin{cases} (\text{Sno}, \text{Cno}) \xrightarrow{F} \text{Grade} & \text{(完全函数依赖)} \\ \text{Sno} \to \text{Sdept} & \text{(真子集 Sno 独立决定 Sdept，产生部分依赖!)} \\ \text{Sdept} \to \text{Sloc} \end{cases}$$

### 违约判定：
非主属性 $\text{Sdept}$ 和 $\text{Sloc}$ 对候选码 $(\text{Sno}, \text{Cno})$ 存在部分函数依赖，因此该模式 **$R \notin 2\text{NF}$**（仅属于 1NF）。

### 规范化投影分解（Decomposition）：
遵循“**一事一表**”的原则，将产生部分依赖的属性及其决定因素独立剥离出去，分解为两个独立的子模式：
1. **子模式 1（学生选课成绩关系）**：
   $$SC(\underline{\text{Sno}}, \underline{\text{Cno}}, \text{Grade})$$
   候选码为 $(\text{Sno}, \text{Cno})$，非主属性 $\text{Grade}$ 完全依赖于码，满足 2NF；
2. **子模式 2（学生院系信息关系）**：
   $$S\_D(\underline{\text{Sno}}, \text{Sdept}, \text{Sloc})$$
   候选码为单属性 $\text{Sno}$，根据单属性公理，自动消除部分依赖，满足 2NF。

---

## 5. 2NF 的局限性与残留病灶

模式经过 2NF 分解后，虽然消除了部分函数依赖，但**并未消除传递函数依赖**：
- 观察分解后的子模式 $S\_D(\text{Sno}, \text{Sdept}, \text{Sloc})$：
  - $\text{Sno} \to \text{Sdept}$ 且 $\text{Sdept} \to \text{Sloc}$；
  - 存在传递依赖：$\text{Sno} \xrightarrow{\text{传递}} \text{Sloc}$；
- **残留异常**：
  - 如果计算机系有 500 名学生，在 $S\_D$ 表中该系的办公地址 `Sloc` 依然会被重复记录 500 次；
  - 若计算机系搬迁，依然需要修改 500 次（更新异常）；
  - 新设立院系若暂无学生，依然无法存入地址（插入异常）。
- 这一遗留病灶促使我们必须迈向更高的范式——**第三范式（3NF）**。

## 6. 随堂巩固自测

### 自测题 1（单项选择题）
设有关系模式 $R(A, B, C, D)$，其函数依赖集为 $F = \{A \to B, C \to D\}$。则关系模式 $R$ 最高属于（ ）
A. 1NF  
B. 2NF  
C. 3NF  
D. BCNF  

**【答案】**：A  
**【解析】**：
- 求候选码：$A, C$ 仅在左部出现（L 类属性），计算 $(A, C)^+ = \{A, C, B, D\} = U$，故唯一候选码为 $(A, C)$；
- 主属性为 $A, C$；非主属性为 $B, D$；
- 检查函数依赖：$A \to B$ 中，$A$ 是候选码 $(A, C)$ 的真子集，故非主属性 $B$ 对码存在部分函数依赖；同理 $D$ 也对码存在部分依赖；
- 由于存在非主属性对候选码的部分函数依赖，该模式不满足 2NF，最高只能属于 1NF。故选 A。

---

### 自测题 2（范式判定与模式分解题）
设有商品销售关系模式：  
$Sale(\underline{OrderID}, \underline{ProductID}, ProductName, Quantity, UnitPrice)$  
其函数依赖为：  
$(OrderID, ProductID) \to Quantity$  
$ProductID \to (ProductName, UnitPrice)$  
请问：
1. 该关系模式属于第几范式？为什么？
2. 请将其规范化分解为满足 2NF 的一组子关系模式。

**【参考答案与解析】**：
1. **范式判定**：该模式属于 **1NF**，不满足 2NF。  
   **理由**：候选码为复合属性组 $(OrderID, ProductID)$，非主属性为 $ProductName, UnitPrice, Quantity$。由于存在 $ProductID \to (ProductName, UnitPrice)$，即非主属性 $ProductName$ 和 $UnitPrice$ 仅由码的一部分（真子集 $ProductID$）决定，存在**部分函数依赖**，故不满足 2NF。
2. **2NF 规范化分解方案**：
   - 订单明细表：$OrderDetail(\underline{OrderID}, \underline{ProductID}, Quantity)$，候选码为 $(OrderID, ProductID)$；
   - 商品信息表：$Product(\underline{ProductID}, ProductName, UnitPrice)$，候选码为 $ProductID$。  
   分解后的两表均完全消除了非主属性的部分函数依赖，均满足 2NF。
