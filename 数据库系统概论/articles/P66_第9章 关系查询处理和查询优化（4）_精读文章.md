# 物理优化与代价模型（四）：RBO与CBO对比、统计信息直方图与第九章全景复盘

## 1. 核心概念与本质内涵：什么是物理优化？

在完成了关系代数树的启发式代数优化（逻辑优化）之后，优化器产出了一棵最优的逻辑操作树（如确定了先选择、后连接）。

然而，逻辑优化只解决了“**做运算的抽象数学先后次序**”，并没有回答最关键的“**物理底层到底该怎么做**”：
- 对于选择算子 $\sigma_{Age > 20}$，底层究竟是进行一次高速连续的全表物理扫描，还是走 $Age$ 列上的 B+ 树辅助索引？
- 对于连接算子 $\Join$，底层究竟选用嵌套循环连接（Nested Loop）、排序合并连接（Sort-Merge）还是散列哈希连接（Hash Join）？
- 对于两表连接，究竟让谁充当外层驱动表、谁充当内层被驱动表？

针对上述底层硬件执行算法与物理存取路径（Access Path）的最终裁决过程，就是**物理优化（Physical Query Optimization）**。

## 2. 优化器的两大技术流派：RBO vs CBO

在数据库演进史上，物理优化器经历了从“死板规则”到“智能数据精算”的技术变革：

```text
                  物理优化器的两大演进流派
                               │
       ┌───────────────────────┴───────────────────────┐
       ▼                                               ▼
【基于规则的优化器 (RBO)】                      【基于代价的优化器 (CBO)】
(Rule-Based Optimizer)                         (Cost-Based Optimizer)
 • 依靠预设的静态优先级经验规则                 • 依靠数据字典中的真实统计信息 (Statistics)
 • 如: 唯一索引 > 范围索引 > 全表扫描          • 精算 I/O 块数、CPU 周期与内存开销
 • 盲人摸象: 无法感知数据量与数据倾斜           • 科学量化: 动态选取总代价最小的最优计划
 (表只有 5 行也死板走索引，反而变慢)            (现代主流数据库绝对标配!)
```

## 3. 基于代价的优化（CBO）核心计算模型

CBO 优化器通过建立精确的数学代价函数，对每一条候选执行计划计算预估总成本（Total Cost）：

$$\text{Total Cost} = C_{\text{I/O}} \times W_{\text{I/O}} + C_{\text{CPU}} \times W_{\text{CPU}} + C_{\text{MEM}} \times W_{\text{MEM}}$$

- **物理 I/O 代价（$C_{\text{I/O}}$）**：从物理磁盘加载到内存的数据页（Blocks/Pages）数量（由于磁盘访问时间是以毫秒级计，通常是代价模型中权重最高的决定性因子）；
- **CPU 计算代价（$C_{\text{CPU}}$）**：元组比较、谓词过滤计算、哈希值运算与排序的指令周期开销；
- **内存缓冲开销（$C_{\text{MEM}}$）**：排序区与哈希表占用的工作内存空间。

## 4. 统计信息（Statistics）与选择度（Selectivity）计算

CBO 优化器之所以能精准预测代价，全赖数据字典中常态化维护的**底层数据统计信息（System Catalog Statistics）**：

### 4.1 核心统计指标体系
- $T(R)$：关系 $R$ 中的**总元组行数**；
- $B(R)$：关系 $R$ 所占用的**物理磁盘块总数（Data Blocks）**；
- $V(A, R)$：属性 $A$ 在关系 $R$ 中的**不同取值基数（Cardinality / Number of Distinct Values）**；
- **列的数据直方图（Histograms）**：专门用于记录数据分布倾斜特征（例如全校 $90\%$ 的学生都集中在“计算机系”，而“天文系”只有 $1\%$）。

---

### 4.2 选择度（Selectivity / 过滤因子）的数学估算

选择度 $S$ 是指满足过滤条件的元组占全表总元组数的比例（$0 \le S \le 1$）：

1. **等值单条件（$\sigma_{A = \text{常数}}$）**：
   - 假定数据在域上均匀分布：
     $$S = \frac{1}{V(A, R)}$$
   - 预估结果行数：$\text{Rows} = T(R) \times S = \frac{T(R)}{V(A, R)}$；
2. **范围查询条件（$\sigma_{A > \text{常数}}$）**：
   - 结合数据列的最小值 $\text{MIN}(A)$ 和最大值 $\text{MAX}(A)$ 进行线性插值估算：
     $$S = \frac{\text{MAX}(A) - \text{常数}}{\text{MAX}(A) - \text{MIN}(A)}$$

---

### 4.3 全表扫描 vs 索引扫描的代价临界点抉择

```text
               全表扫描与索引扫描的抉择临界点
                    选择度 S = 命中行 / 总行数
                              │
       ┌──────────────────────┴──────────────────────┐
       ▼ (S < 5% ~ 15%: 高选择性 / 极少数行)         ▼ (S > 15% ~ 20%: 低选择性 / 大面积命中)
【果断选择: B+ 树索引扫描】                     【果断选择: 顺序全表物理扫描 (Table Scan)】
 走索引定位少量目标行，回表 I/O 极少            连续物理块大并发顺序预读，
 性能远胜全表扫描!                              避免海量随机回表 I/O 造成的磁头抖动灾难!
```

> **【架构师生产避坑铁律】**：为什么有时候明明建了索引，SQL `EXPLAIN` 分析却显示走的是全表扫描（Index Ignored）？  
> **真相解密**：这不是优化器 BUG，正是 CBO 智能精算的结果！当查询条件命中了表中 $30\%$ 以上的数据时，若走辅助索引，需要进行成千上万次随机离散的回表寻道，物理 I/O 代价远高于一次性从头到尾顺序扫盘。优化器科学地放弃了索引。

## 6. 随堂巩固自测

### 自测题 1（单项选择题）
在关系数据库基于代价的查询优化器（CBO）中，评估一个物理执行计划优劣的最核心依据是（ ）
A. 该执行计划所包含的 SQL 代码字符长度  
B. 预估的物理磁盘 I/O 块数、CPU 周期与内存占用的综合数学总代价  
C. 执行计划中是否包含了尽可能多的索引  
D. 必须优先选用嵌套循环连接  

**【答案】**：B  
**【解析】**：CBO 依赖数据字典中的真实数据统计信息，利用数学公式量化估算该计划执行所需的 I/O 次数、CPU 计算量与内存开销的总代价，选择代价值最小的路径。故选 B。

---

### 自测题 2（优化器决策机理分析题）
某用户在包含 100 万条记录的员工表 `Employee(EmpID, Sname, Gender, Salary)` 上建立了一个基于 `Gender`（性别）列的非聚集索引。当执行查询：
`SELECT * FROM Employee WHERE Gender = '男';`
时，优化器坚决放弃使用该索引，而是执行了全表扫描（Table Scan）。请结合 CBO 选择度与物理 I/O 机理，解释优化器做出该决策的深层原因。

**【参考答案与解析】**：
1. **选择度极低（命中比例极大）**：在现实中，性别只有男和女两种取值（$V(Gender) = 2$），查询 `Gender = '男'` 预计会命中表中约 $50\%$ 的数据（约 50 万行）；
2. **离散回表 I/O 灾难**：若使用该辅助索引，系统通过索引定位到 50 万个 RID 后，必须向物理表发起多达 50 万次**离散随机磁盘寻道（Random I/O）**来读取完整的行数据，磁头将发生剧烈机械抖动；
3. **全表顺序扫描代价更低**：全表 100 万行仅占用几万个物理数据页。全表扫描采用**连续顺序物理 I/O 预读（Sequential I/O）**，仅需几万次连续读取即可将全表装载完毕，总执行时间远小于 50 万次随机回表。因此，CBO 经过精确代价估算，科学而正确地放弃了索引。
