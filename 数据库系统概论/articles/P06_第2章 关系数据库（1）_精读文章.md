# 关系数据结构与形式化定义（一）：域、笛卡尔积、关系与码体系

## 1. 核心概念与本质内涵：关系数据模型的数学形式化基石

关系数据库系统是建立在严格的集合代数理论之上的。与网状和层次模型依赖图形指针不同，关系模型将现实世界的一切对象和关联统一映射为数学上的**关系（Relation）**。为了精确刻画二维表背后的数学原理，必须从域和笛卡尔积开始形式化构建。

### 1.1 域（Domain）与笛卡尔积（Cartesian Product）

#### 1. 域（Domain）
- **定义**：域是一组具有相同数据类型的值的集合。
- **示例**：
  - 自然数集合 $\mathbb{N}$ 可以是一个域；
  - 性别域 $D_{\text{sex}} = \{\text{'男'}, \text{'女'}\}$；
  - 成绩域 $D_{\text{score}} = \{x \in \mathbb{R} \mid 0 \le x \le 100\}$。

#### 2. 笛卡尔积（Cartesian Product）
- **形式化定义**：给定一组域 $D_1, D_2, \dots, D_n$（这些域可以相同，也可以不同），这 $n$ 个域的笛卡尔积定义为：
  $$D_1 \times D_2 \times \dots \times D_n = \{(d_1, d_2, \dots, d_n) \mid d_i \in D_i, i = 1, 2, \dots, n\}$$
- **基数（Cardinality）计算**：
  - 每个分量满足 $d_i \in D_i$；每一个元素 $(d_1, d_2, \dots, d_n)$ 称为一个 **$n$ 元组（$n$-tuple）**，简称**元组**；
  - 若域 $D_i$ 的基数（元素个数）为 $m_i$（$i = 1, 2, \dots, n$），则这 $n$ 个域的笛卡尔积的基数（元组总数） $M$ 为各域基数的累乘：
    $$M = \prod_{i=1}^n m_i = m_1 \times m_2 \times \dots \times m_n$$

```text
示例：
设 D1 (专业导师) = {张导师, 李导师} (基数 m1 = 2)
设 D2 (专业方向) = {人工智能, 数据库, 计算机网络} (基数 m2 = 3)
笛卡尔积 D1 × D2 的基数为 2 × 3 = 6，包含的元组集合为:
{
  (张导师, 人工智能), (张导师, 数据库), (张导师, 计算机网络),
  (李导师, 人工智能), (李导师, 数据库), (李导师, 计算机网络)
}
```

### 1.2 关系（Relation）的形式化定义

在数学集合论中，关系是笛卡尔积的子集：
- **定义**：$D_1 \times D_2 \times \dots \times D_n$ 的**任意一个子集**称为在域 $D_1, D_2, \dots, D_n$ 上的一个**关系（Relation）**，记作：
  $$R(D_1, D_2, \dots, D_n)$$
  其中 $R$ 为关系名，$n$ 称为关系的**目（Degree）或度**。
- **直观理解**：
  - 笛卡尔积表示了所有可能出现的组合空间；
  - 真实世界中的事实仅仅是这种组合空间中的一部分（具有现实业务语义的部分），因此现实数据就是笛卡尔积的一个**真子集**。
- **单目关系与二目关系**：
  - 当 $n = 1$ 时，该关系称为**单目关系（Unary Relation）**；
  - 当 $n = 2$ 时，该关系称为**二目关系（Binary Relation）**；
  - 当 $n$ 个域时，称为 **$n$ 目关系**。

## 2. 关系中的码（Key）体系深度解构

在关系数据库理论中，**码（Key）**是维护数据唯一性标识与表间参照关联的最核心概念。学术界定义了层次分明的码范畴体系：

```text
             全集: 所有能唯一标识元组的属性组
                            │
               ┌────────────┴────────────┐
               ▼                         ▼
      超码 (Super Key)            (非超码属性组)
   (唯一标识，但包含多余属性)
               │
               ▼  【极小化: 剔除一切冗余属性】
     候选码 (Candidate Key)
   (能唯一标识元组的极小属性集)
               │
        ┌──────┴─────────────────────────────────┐
        ▼                                        ▼
 主码 (Primary Key)                      备用码 (Alternate Key)
(DBA/设计者选定的一组候选码)           (其余未被选为主码的候选码)
```

### 2.1 超码（Super Key）与候选码（Candidate Key）

1. **超码（Super Key）**：
   - 定义：在关系中能**唯一标识一个元组**的一个属性或属性组；
   - 特点：超码可能包含多余的不必要属性。例如在学生关系 `Student(Sno, Sname, Ssex, Sage)` 中，`(Sno, Sname)` 显然能唯一标识一名学生，因此 `(Sno, Sname)` 是一个超码；甚至 `(Sno, Sname, Sage)` 也是超码。

2. **候选码（Candidate Key）**：
   - 形式化定义：若关系中的某一属性组 $K$ 能唯一标识一个元组，且**其任意真子集都不能唯一标识该元组**，则称 $K$ 为**候选码**；
   - 核心特征：候选码是**极小化的超码（Minimal Super Key）**，不含任何冗余属性；
   - 示例：在学生表中，若学号 `Sno` 和身份证号 `IDCard` 均能唯一标识学生，则 `Sno` 和 `IDCard` 分别是两个独立的候选码。

### 2.2 主码（Primary Key）与全码（All-Key）

1. **主码（Primary Key）**：
   - 若一个关系中有多个候选码，则选定其中的一个作为数据库的主标识符，称为**主码**；
   - 每个关系有且仅能指定一个主码。

2. **全码（All-Key）**：
   - 在极端情况下，关系模式的所有属性组联合起来才能唯一标识一个元组，此时整个属性集合称为**全码**；
   - 典型场景：在没有人工自增 ID 的导师带教关系 `指导(教师工号, 学生学号)` 中，一个老师指导多个学生，一个学生有多名老师共同指导，只有 `(教师工号, 学生学号)` 联合才能唯一标识一行，该联合属性集即为全码。

### 2.3 主属性与非主属性（Prime & Non-prime Attributes）

- **主属性（Prime Attribute）**：包含在**任何一个候选码中**的属性称为主属性；
- **非主属性（Non-prime Attribute）**：不包含在**任何候选码中**的属性称为非主属性（或非码属性）。

> **易错点**：主属性只要出现在**任意一个**候选码中即为主属性，而绝不仅限于出现在最终被选中的“主码”中。

## 3. 典型例题与深度认知辨析

### 辨析 1：笛卡尔积的列名冲突如何解决？

- **场景**：设域 $D_1$（研究生年龄）和域 $D_2$（本科生年龄）都是自然数域，当对 $D_1$ 和 $D_2$ 做笛卡尔积时，元组中出现了两个来自相同域的分量。
- **机制解析**：
  - 笛卡尔积是无属性名的纯数学集合；
  - 当把笛卡尔积的子集命名为关系并映射为二维表时，必须为每一列指定一个**属性名（Attribute Name）**；
  - 通过属性名（如 `GradAge` 和 `UndergradAge`）对来自相同域的属性进行明确区分，避免歧义。

### 辨析 2：候选码与主码的决定因素是什么？

- 候选码由客观业务语义和函数依赖客观决定（客观属性）；
- 主码则是系统设计人员从客观存在的候选码中，结合查询高频度、存储字节长度、稳定性等工程因素人工挑选指定的（主观决策）。

## 4. 随堂巩固自测

### 自测题 1（概念推导计算题）
设有三个域：$D_1 = \{\text{'A'}, \text{'B'}\}$，$D_2 = \{0, 1\}$，$D_3 = \{\text{'X'}, \text{'Y'}, \text{'Z'}\}$。
请回答：
1. 笛卡尔积 $D_1 \times D_2 \times D_3$ 的目（Degree）是多少？
2. 该笛卡尔积的基数（Cardinality）是多少？
3. 写出以 $(\text{'A'}, 0)$ 开头的所有元组。

**【答案与推导】**：
1. **目（Degree）**：参与做积的域有 3 个，故该笛卡尔积的目为 **3**（即三元组关系）；
2. **基数（Cardinality）**：基数 $M = |D_1| \times |D_2| \times |D_3| = 2 \times 2 \times 3 = \mathbf{12}$；
3. **元组枚举**：
   - $(\text{'A'}, 0, \text{'X'})$
   - $(\text{'A'}, 0, \text{'Y'})$
   - $(\text{'A'}, 0, \text{'Z'})$

---

### 自测题 2（单项选择题）
在关系模式 $R(A, B, C, D)$ 中，若属性组 $(A, B)$ 和 $(B, C)$ 均是候选码，则关于属性主次属性的判定，正确的是（ ）
A. 仅 $A$ 和 $B$ 是主属性  
B. $A, B, C$ 都是主属性，$D$ 是非主属性  
C. 只有 $A$ 是主属性  
D. 所有的属性都是主属性  

**【答案】**：B  
**【解析】**：主属性的定义是“包含在任何一个候选码中的属性”。本题中候选码有 $(A, B)$ 和 $(B, C)$，因此属性 $A$（在第一个候选码中）、属性 $B$（在两个候选码中）、属性 $C$（在第二个候选码中）均满足主属性定义；属性 $D$ 不包含在任何候选码中，为非主属性。故正确答案为 B。
