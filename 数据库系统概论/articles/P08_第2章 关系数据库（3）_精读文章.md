# 关系模式与操作体系（三）：五元组形式化定义与集合级操作特性

## 1. 核心概念与本质内涵：关系模式的形式化五元组定义

在关系模型中，“型（Type）”与“值（Value）”的清晰分离是系统严密性的根源。关系的型被称为**关系模式（Relation Schema）**，它是对关系的静态结构、语义范围与完整性依赖的形式化抽象。

### 1.1 关系模式的形式化五元组模型

在理论形式化上，一个关系模式可以完整表示为一个五元组：

$$R(U, D, DOM, F)$$

其中各分量的形式化内涵如下：

```text
                     关系模式五元组 R(U, D, DOM, F)
                                   │
       ┌───────────────────┬───────┴───────┬───────────────────┐
       ▼                   ▼               ▼                   ▼
    R: 关系名          U: 属性集合     D: 域集合           F: 数据依赖
 (Relation Name)    (Attributes)    (Domains)         (Dependencies)
                       │               │                     │
                       └───────┬───────┘                     │
                               ▼                             ▼
                          DOM: 属性到域的映射            函数依赖/多值依赖
                         (Attribute to Domain)          (完整性约束的数学表述)
```

1. **$R$——关系名**：
   - 该关系的符号标识符（如 `Student`, `Course`, `SC`）。
2. **$U$——属性名集合**：
   - 组成该关系的所有属性的名称集合，记作 $U = \{A_1, A_2, \dots, A_n\}$。例如 $U = \{\text{Sno}, \text{Sname}, \text{Sage}\}$。
3. **$D$——属性所来自的域集合**：
   - 属性在客观世界中所依托的底层数据类型的集合，$D = \{D_1, D_2, \dots, D_k\}$。
4. **$DOM$——属性向域的映象集合**：
   - 从属性集合 $U$ 到域集合 $D$ 的对应映射，表明每个属性 $A_i$ 取自哪个域 $D_j$，通常以数据类型和长度表示（如 $\text{DOM}(\text{Sno}) = \text{CHAR}(10)$）。
5. **$F$——属性间的数据依赖关系集合**：
   - 描述属性之间存在的内在语义约束（包括函数依赖 Functional Dependency，多值依赖等）。例如：学号一旦确定，学生的姓名、系别就唯一确定，记作 $\text{Sno} \to \text{Sname}$。

### 1.2 简化书写规范

在实际工程应用和日常教学中，通常只关注关系名、属性集合与主码，五元组常被简记为：

$$R(U) \quad \text{或} \quad R(A_1, A_2, \dots, A_n)$$

例如学生关系模式简写为：`Student(Sno, Sname, Ssex, Sage, Sdept)`。其中约定：**主码属性通常用下划线标明**（如 $\underline{\text{Sno}}$）。

## 2. 关系操作体系与“一次一集合”本质

关系数据库之所以具备极高的数据独立性，并能在 20 世纪 80 年代后全面取代层次与网状系统，最根本的原因在于其**关系操作的革命性范式**。

### 2.1 传统模型与关系模型的操作方式对比

```text
【传统格式化模型 (层次 / 网状)】          【关系数据模型 (Relational)】
 操作模式: 记录级 (Record-at-a-time)        操作模式: 集合级 (Set-at-a-time)
         ┌─────────────┐                          ┌─────────────┐
         │ 获取第 1 行 │                          │ 提交声明式  │
         └──────┬──────┘                          │ SQL 查询请求│
                ▼                                 └──────┬──────┘
         ┌─────────────┐                                 ▼
         │ 游标移动... │                          ┌─────────────┐
         └──────┬──────┘                          │ DBMS 内部   │
                ▼                                 │ 代数树优化  │
         ┌─────────────┐                          └──────┬──────┘
         │ 循环逐条比对│                                 ▼
         └─────────────┘                          ┌─────────────┐
                                                  │ 一次性返回  │
                                                  │ 满足条件的  │
                                                  │ 全量元组集合│
                                                  └─────────────┘
```

1. **传统模型的操作：一次一记录（Record-at-a-time）**
   - 程序员必须在代码中显式定义游标、寻道循环、遍历指针；
   - 代码高度依赖底层物理存储结构，属于典型的**过程化操作（Procedural）**。

2. **关系模型的操作：一次一集合（Set-at-a-time）**
   - **操作对象是集合**：查询、插入、更新、删除操作的输入是关系（集合），输出结果也必然是一个新的关系（集合）；
   - **高度非过程化（Non-procedural）**：用户只需使用说明性语言告知系统“需要满足何种谓词条件的数据”（What），完全不需要指定“通过哪条索引、以何种算法循序遍历磁盘页”（How）；
   - 所有存取路径的选择、代数等价变换与代价估算，全部下沉至 DBMS 的**查询优化器（Query Optimizer）**全权调度。

### 2.2 关系操作语言的分支谱系

理论上，关系操作语言可划分为三大流派：

1. **关系代数语言（Relational Algebra）**：
   - 采用显式的集合代数算子（选择 $\sigma$、投影 $\pi$、连接 $\Join$ 等）来构造查询表达式，是一种半过程化的理论抽象语言；
2. **关系演算语言（Relational Calculus）**：
   - 采用纯粹的一阶谓词逻辑公式来表达查询请求，完全非过程化：
     - **元组关系演算**：以元组变量为基础谓词单元（如 Quel 语言）；
     - **域关系演算**：以属性域变量为基础谓词单元（如 QBE 语言，Query-by-Example）；
3. **具有关系代数与关系演算双重特点的工程语言——SQL（Structured Query Language）**：
   - ANSI / ISO 标准化的结构化查询语言，集数据定义（DDL）、数据操纵（DML）与数据控制（DCL）于一体，成为全世界关系数据库的通用事实标准。

## 3. 典型例题与深度认知辨析

### 辨析 1：关系数据库与关系数据库模式有何区别？

- **本质对比**：
  - **关系数据库模式（Relational Database Schema）**是对关系数据库整体“型”的描述，是若干个相关关系模式的集合；
  - **关系数据库（Relational Database）**则是指某一特定物理时刻，关系数据库模式下所有关系实例的数据集合；
  - 模式是稳定不易变的结构规约，而数据库是随时随地因业务写入而动态膨胀变化的数据物理实体。

### 辨析 2：为什么“一次一集合”极大降低了应用程序与底层的耦合？

- 因为操作以整个集合为单位，底层无论采用单机 B+ 树扫描、哈希连接（Hash Join）、并行多核计算还是分布式分片（Sharding），返回给上层应用的接口永远是一个标准的抽象二维集合，应用层代码无需做任何重构。

## 4. 随堂巩固自测

### 自测题 1（单项选择题）
关系数据模型中的数据操纵具有“集合操作”特性，其具体含义是指（ ）
A. 关系操作的输入与输出对象都是关系的集合  
B. 操作过程中只能使用数学交、并、差集合运算  
C. 用户必须在编程语言中显式使用 `for` 循环逐条遍历元组  
D. 所有操作必须在集合论定理推导下由人工证明  

**【答案】**：A  
**【解析】**：关系数据模型的操作以集合为单位（Set-at-a-time），操作对象是关系（元组的集合），操作的结果依然是关系（元组的集合），非过程化。故选 A。

---

### 自测题 2（填空与概念分析题）
在关系模式的形式化五元组 $R(U, D, DOM, F)$ 中，用于刻画属性之间业务依赖与数据完整性约束的核心分量是 ________；若在学生选课关系模式中，学号与课程号联合决定成绩，用函数依赖符号表示为 ________。

**【答案】**：$F$（或数据依赖集合）；$(\text{Sno}, \text{Cno}) \to \text{Grade}$。  
**【解析】**：五元组中 $F$ 代表属性间的数据依赖关系集合，是后续关系规范化理论的研究核心；学号与课程号联合确定成绩，即为属性组 $(\text{Sno}, \text{Cno})$ 函数决定 $\text{Grade}$。
