# 数据库编程导论（一）：嵌入式SQL架构、主变量通信与阻抗失配破解

## 1. 核心概念与本质内涵：为什么需要数据库编程？

SQL 是一种声明式语言（Declarative Language），在关系数据集合的查询与批处理上极具威力。
然而，单纯依赖交互式 SQL 无法解决复杂的现实应用需求：
1. **缺乏过程化控制能力**：标准 SQL 不支持分支判断（`if-else`）、循环迭代（`while/for`）和复杂的业务算法（如复杂的薪资计算公式、图形渲染）；
2. **无法直接构建人机交互系统**：最终用户无法直接在命令行敲击原始 SQL，必须通过图形界面（Web、移动端 APP、桌面客户端）与数据交互。

因此，必须将 **SQL 的强大集合数据操纵能力** 与 **通用高级程序设计语言（宿主语言，如 C/C++, Java, Python）的灵活过程化控制能力** 有机结合起来，这就是**数据库编程（Database Programming）**。

```text
                     数据库编程的技术演进路径
                                 │
     ┌───────────────────────────┼───────────────────────────┐
     ▼                           ▼                           ▼
【1. 嵌入式 SQL (ESQL)】        【2. 过程化 SQL (PL/SQL)】    【3. 通用 API / 驱动】
 • SQL 嵌入 C/COBOL 等宿主语言   • 将过程化逻辑直接注入 DBMS   • ODBC / JDBC 标准接口
 • 依赖预编译器 (Precompiler)    • 存储过程与函数 (服务端执行) • 现代应用开发事实标准
```

---

## 2. 嵌入式 SQL（Embedded SQL）的核心工作机理

嵌入式 SQL 是将 SQL 语句直接嵌入到高级宿主语言（Host Language）源代码中编写的一种传统工业级标准。

### 2.1 预编译机制（Precompilation）
通用高级语言（如 C 语言的 `gcc` 编译器）并不认识 SQL 的语法结构。因此，系统引入了**预编译器（Precompiler）**：

```text
              嵌入式 SQL 预编译与编译两阶段流水线
 嵌入式源代码 (*.ec / *.sqc, 混写 C 与 EXEC SQL)
                      │
                      ▼
            [DBMS 专用预编译器]
                      │
   ├── 1. 识别并提取所有 EXEC SQL 块
   ├── 2. 转换为底层标准 DBMS 运行库 C 语言函数调用
   └── 3. 生成纯净的标准 C 语言源码文件 (*.c)
                      │
                      ▼
               [宿主语言 C 编译器]
                      │
                      ▼
               [链接器 (Linker)] ──> 引入数据库动态链接库
                      │
                      ▼
           最终可执行二进制程序 (*.exe)
```

## 3. 语法标识与宿主语言通信三剑客

在嵌入式 SQL 中，为了让预编译器精准识别，所有 SQL 语句必须以前缀 **`EXEC SQL`** 开头，并以特定符号（C 语言中为分号 `;`）结束：

```c
EXEC SQL <SQL 语句>;
```

### 3.1 通信核心 1：主变量（Host Variable / 共享变量）
- **定义**：由宿主语言程序定义，并被嵌入的 SQL 语句直接引用的变量；
- **作用**：扮演数据传输的“双向邮差”：
  - **输入主变量**：应用程序将变量值作为查询条件参数传递给 SQL 语句；
  - **输出主变量**：SQL 语句执行后将查询到的字段值回填给应用程序变量；
- **核心语法规则**：
  1. 主变量必须在 `EXEC SQL BEGIN DECLARE SECTION;` 与 `EXEC SQL END DECLARE SECTION;` 块中声明；
  2. **在 SQL 语句中使用主变量时，主变量名前面必须加冒号（`:`）作为前缀引导**（用以与数据库中的表列名做明确区分）；而在纯 C 语言语句中引用该变量时，不加冒号。

```c
EXEC SQL BEGIN DECLARE SECTION;
    char hs_sno[10];     /* 主变量: 对应数据库中的 Sno */
    char hs_sname[21];   /* 主变量: 对应数据库中的 Sname */
    int  hs_sage;        /* 主变量: 对应数据库中的 Sage */
EXEC SQL END DECLARE SECTION;
```

---

### 3.2 通信核心 2：指示变量（Indicator Variable）与 NULL 处理

> **【阻抗失配难题】**：C 语言等传统宿主语言中根本没有“空值（NULL）”这一数据类型（只有 0 或空指针）。当数据库中某个字段的值是 `NULL` 时，如何传递给 C 语言变量？

- **解决方案**：引入**指示变量（Indicator Variable）**；
- 指示变量是一个 2 字节的整型主变量（`short`），紧跟在目标主变量后面（以冒号引导）；
- **取值规范**：
  - 若查询返回的值为 `NULL`，DBMS 自动将指示变量的值赋为**负数（通常为 `-1`）**；
  - 若查询返回的值非空，指示变量的值为 **`0`**；
  - 若发生字符串截断，指示变量记录被截断前的原始长度（正数）。

```c
short ind_grade; /* 声明指示变量 */

EXEC SQL SELECT Grade INTO :hs_grade :ind_grade 
         FROM SC 
         WHERE Sno = :hs_sno AND Cno = 'C01';

if (ind_grade < 0) {
    printf("该学生缺考，成绩为 NULL!\n");
} else {
    printf("学生实际得分: %d\n", hs_grade);
}
```

---

### 3.3 通信核心 3：SQL 通信区（SQLCA）与状态码

DBMS 通过一个名为 **SQLCA（SQL Communication Area）**的数据结构向宿主程序反馈每一步 SQL 的执行状态：
```c
EXEC SQL INCLUDE SQLCA;
```
- **核心状态字段 `SQLCODE`**：
  - **`SQLCODE == 0`**：SQL 语句执行成功无异常；
  - **`SQLCODE > 0`**：执行成功，但有告警（最典型的 `SQLCODE == 100` 代表**未找到符合条件的元组，或游标已读取到末尾**）；
  - **`SQLCODE < 0`**：执行遭遇严重错误（如语法错误、主键冲突、网络中断）。

## 4. 随堂巩固自测

### 自测题 1（单项选择题）
在 C 语言嵌入式 SQL 程序中，若要在 SQL 语句中引用宿主语言所定义的主变量 `my_age`，正确的书写格式是（ ）
A. `my_age`  
B. `:my_age`  
C. `&my_age`  
D. `*my_age`  

**【答案】**：B  
**【解析】**：为了让预编译器区分 SQL 语句中的列名与宿主程序中的变量名，SQL 语法规范强制要求在 SQL 语句中引用主变量时必须前缀英文冒号 `:`。故选 B。

---

### 自测题 2（概念分析与代码填空题）
在嵌入式 SQL 中，针对数据库中可能出现的空值（NULL），必须使用什么变量进行配合接收？请写出接收学号为 `'202601'` 学生的单科成绩及其空值判定的核心代码逻辑。

**【参考答案与解析】**：
必须配合使用**指示变量（Indicator Variable）**。
```c
EXEC SQL BEGIN DECLARE SECTION;
    int v_grade;
    short v_ind; /* 指示变量 */
EXEC SQL END DECLARE SECTION;

EXEC SQL SELECT Grade INTO :v_grade :v_ind
         FROM SC 
         WHERE Sno = '202601' AND Cno = '1';

if (v_ind < 0) {
    printf("成绩为 NULL (缺考/未录入)\n");
} else {
    printf("成绩为: %d\n", v_grade);
}
```
