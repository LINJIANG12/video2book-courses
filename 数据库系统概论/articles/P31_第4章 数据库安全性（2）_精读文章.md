# 数据库安全防御机制（二）：身份鉴别方法与存取控制流派深度对比

## 1. 核心概念与本质内涵：防线的第一道关卡与核心枢纽

任何用户试图访问数据库中的数据，必须先后跨越 DBMS 的两道核心防线：
1. **身份鉴别（Authentication）——“你是谁？”**：验证试图连入系统的用户是否确实是其声称的那个真实合法实体；
2. **存取控制（Access Control）——“你能干什么？”**：在确认用户真实身份后，依据系统安全策略，严格裁决该用户针对特定数据库对象（表、列、视图）被允许执行哪些具体操作（读、写、修改、删除）。

```text
               数据库安全访问的双道关卡流向
客户端连接请求 (Client Connection)
         │
         ▼
【第一道防线: 身份鉴别 (Authentication)】
 • 检验用户名与口令 / 动态 OTP 令牌 / 生物特征 / 数字证书
 • 验证失败 ──> 立即切断网络连接，记入安全审计日志
         │
         ▼ (鉴别通过，确立用户身份 Context)
【第二道防线: 存取控制 (Access Control)】
 每次执行具体 SQL 语句时 (如 SELECT / DELETE):
 • 扫描系统数据字典与权限授权表
 • 判定该用户是否具有执行该指令的显式或继承权限
 • 权限不匹配 ──> 抛出 "Permission Denied" 并拦截执行
```

## 2. 现代数据库用户身份鉴别技术体系

### 2.1 静态口令鉴别（Static Password Authentication）
- **实现原理**：用户输入账号和预设的固定密码，DBMS 将用户输入的密码哈希摘要与系统内部加密存储的散列值（如 PBKDF2, SHA-256 带盐 Salt）进行比对；
- **安全薄弱点**：极易受到弱口令字典攻击、网络中间人窃听（Sniffing）以及重放攻击。

### 2.2 动态口令鉴别（Dynamic Password / OTP / MFA）
- **实现原理**：引入双因子认证（Multi-Factor Authentication, MFA），口令随时间（TOTP）或计数事件单向动态生成，一次一密，数十秒后自动作废失效；
- **防护收益**：即使攻击者窃听捕获了单次口令，因时效性已过，无法用于第二次登录。

### 2.3 生物特征鉴别（Biometric Authentication）
- 利用人体独一无二的生物学物理特征（指纹、虹膜、人脸 3D 拓扑、静脉血管）进行比对，几乎不可能被窃取或转借他人，安全性极高。

### 2.4 智能卡与数字证书（Smart Card / USB Key）
- 采用硬件加密芯片存储用户的非对称私钥，登录时通过挑战-应答机制（Challenge-Response）进行公私钥密码学签名验证，防篡改防复制。

## 3. 存取控制机制的两大核心流派：DAC vs MAC

在通过身份鉴别后，DBMS 通过存取控制机制实施授权。在计算机安全理论中，存在两大经典的存取控制范式：

```text
                  DAC (自主存取控制) vs MAC (强制存取控制)
                                 │
     ┌───────────────────────────┴───────────────────────────┐
     ▼                                                       ▼
【自主存取控制 (DAC)】                         【强制存取控制 (MAC)】
 • 灵活性极高，权力下放                        • 极度严密，权力绝对收归中央
 • 用户对拥有的数据具有自主控制权              • 系统强制为所有数据与用户打上密级标记
 • 可将自己拥有的权限自主转授他人              • 用户绝不能自主转授权限!
 • 存在隐蔽泄露通道 (无法防御木马)             • 彻底阻断信息由高密级向低密级单向流动
```

### 3.1 自主存取控制（Discretionary Access Control, DAC）
- **机制原理**：
  - 用户对于自己创建的数据库对象（如某用户建了一张表），天然拥有最高属主权限；
  - 该用户可以**自主决定（Discretionary）**是否将该表的读、写权限授予其他用户；
  - 甚至允许被授权者将该权限**进一步转授给第三方**（`WITH GRANT OPTION`）。
- **致命缺陷——“特洛伊木马（Trojan Horse）”攻击脆弱性**：
  - 在纯 DAC 环境下，若超级用户 A 拥有绝密表，恶意用户 B 诱骗 A 运行了一个看似正常的统计程序（木马）；
  - 该木马在 A 的合法会话上下文里执行，读取绝密表并将数据悄悄 `INSERT` 进一个所有人均可读的公共垃圾表；
  - 最终用户 B 轻松读取了绝密数据，而 DAC 机制对此类**合法主体发起的越权拷贝**完全无能为力！

### 3.2 强制存取控制（Mandatory Access Control, MAC）
- **机制原理**：
  - 每一个数据库对象（行、列、表）被系统强制固化赋予一个**敏感度标记（Security Label）**；
  - 每一个系统用户被安全管理员赋予一个**许可证密级（Clearance Level）**；
  - 系统根据一套不可逾越的数学规则（如 Bell-LaPadula 模型），由 DBMS 内核强制执行判定，**任何普通用户无权更改密级，更无权转让权限**。

## 4. 随堂巩固自测

### 自测题 1（单项选择题）
在关系数据库安全体系中，关于自主存取控制（DAC）与强制存取控制（MAC）的说法，错误的是（ ）
A. DAC 提供了极好的使用灵活性，但在防范特洛伊木马非法窃取敏感数据方面存在结构性缺陷  
B. MAC 要求系统对所有主体和客体进行形式化的密级标号与强制访问控制  
C. 在支持 MAC 的高安全级别系统中，通常不再需要执行 DAC 检查  
D. 商业数据库普遍支持 DAC，而在国防等极端敏感领域必须引入 MAC  

**【答案】**：C  
**【解析】**：在高安全级别数据库（如 TCSEC B1 级以上）中，系统执行的是**先自主后强制的双重综合检查**：即一个访问请求必须首先通过 DAC 自主权限检查，随后还必须通过 MAC 强制密级规则校验，两者同时放行方可存取。故选项 C 错误。

---

### 自测题 2（安全分析与推导题）
为什么说在只有自主存取控制（DAC）的系统中，敏感数据存在隐蔽外泄的风险？请简述该风险的发生路径。

**【参考答案与解析】**：
在纯 DAC 系统中，权限的流转主要依赖于用户的“自主意志”。拥有敏感表查询权限的用户，完全可以创建一个自身拥有所有权的新普通表，并编写一条 `INSERT INTO NewTable SELECT * FROM SecretTable;` 语句将敏感数据全量复制进去。随后，该用户可以自主地将 `NewTable` 的读取权限公开授予任何人。这种合法主体被恶意利用或主动转储的行为，使得安全边界彻底失控，导致敏感信息在没有触发任何权限违约报警的情况下被隐蔽外泄。
