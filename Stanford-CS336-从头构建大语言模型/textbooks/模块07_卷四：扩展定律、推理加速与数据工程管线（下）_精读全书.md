## 大语言模型预训练数据源与工业级语料工程
> 对应块：BLK33 | 覆盖分集：P31 | 块标题（分集名）：《Lecture 13_ Data (Source》

今天我们来彻底聊透数据。我们现在所处的阶段是大家已经掌握了模型的底层架构，知道怎么编写分布式训练循环，也推导了算子并行的内核切分，上一讲我们还深入讨论了模型评估，所以大家心里非常清楚什么样的模型才算是一个好模型。在这周接下来的课程里，我们要把核心焦点完全转到训练数据上：我们究竟该挑选哪些数据、如何处理这些数据来喂饱模型。

我必须开门见山地强调一条根本原则：在语言模型中，**数据是最关键、最需要搞对的部分**。很多人沉迷于调试模型架构细节或微调超参数，但真正决定模型能力上限与代际差距的，从来都是数据。看看各大工业实验室在技术报告中实际披露的信息，就能明白为什么这么说。以 Meta 发布的 Llama 3 论文为例，他们对模型架构完全透明，超参数与训练流程事无巨细地全盘公开，毕竟这是个开源权重的模型；但唯独在训练数据这一章，他们却只用了极其含糊的几句话带过，只说自己使用了来自各种不同来源的数据进行训练，顺带做了一些处理。这种高度保密有两条非常现实的理由：第一，数据是各家实验室真正的独门核心竞争力，构成了核心竞争壁垒，没有任何团队愿意竞争对手摸清自己的数据配比与清洗底牌；第二，则是极为棘手的版权责任与诉讼风险——一旦你在技术报告中公开宣称自己使用了某些特定受版权保护的语料，立刻就会招致数以亿计的集体侵权诉讼。

在基座模型（Foundation Models）出现之前，机器学习中的数据工作主要围绕监督学习（Supervised Learning）展开，核心是人工标注特征与标签。到了自监督预训练阶段，尽管逐条数据的标注工作量大幅减少，但海量异构数据的筛选、解析、清洗、去重与质量过滤工作依然极度繁重。从根本上说，数据一直是机器学习的瓶颈，将来也依然是瓶颈。因为数据工程本质上是一个随人力投入而持续放大的长尾问题（Long-tail Problem）。在底层系统架构和并行算子开发上，能同时投入的顶尖系统工程师是有限的；但数据工程完全不同，特别是为了训练包揽各种任务的通用基座模型，数据的清洗、规则挖掘和质量筛选可以天然地高度并行化，拆解给庞大的工程团队同时分担。这就是为什么今天顶尖 AI 实验室里，数据团队的规模往往比纯架构团队还要庞大得多。

### 预训练数据壁垒与生命周期阶段

构建一个现代大语言模型，数据并不是在第一天一股脑灌进优化器里的，而是在训练管线的不同生命周期阶段分批、分层注入的。

```text
+-------------------------------------------------------------------------------+
|                             模型训练生命周期的三阶段管线                            |
+-------------------------------------------------------------------------------+
|                                                                               |
|  [ 1. 预训练阶段 (Pre-training) ]                                               |
|  - 数据形态: 海量低质/半结构化原始语料，千亿至数十万亿 Token 吞吐规模                   |
|  - 典型来源: 全球公开网络抓取、开源代码库、学术论文预印本、数字化图书、问答社区          |
|  - 核心目标: 构建通用底层世界模型，掌握语法、常识知识、代码结构与基础逻辑表征           |
|                                                                               |
|                                       │                                       |
|                                       ▼                                       |
|                                                                               |
|  [ 2. 中训练阶段 (Mid-training) ]                                              |
|  - 数据形态: 经过深度提纯的高质量专门语料，规模相对可控，支持能力专项退火与激活           |
|  - 典型来源: 高质量网页精选集、复杂数学证明、长上下文文档、模型生成的高质量合成数据     |
|  - 核心目标: 激活长文本注意力连贯性，强化数理推理与结构化输出能力                       |
|                                                                               |
|                                       │                                       |
|                                       ▼                                       |
|                                                                               |
|  [ 3. 后训练阶段 (Post-training) ]                                             |
|  - 数据形态: 严格对齐的高质量指令、对话日志与强化学习反馈环境                         |
|  - 典型来源: SFT 多轮对话语料、复杂思维链 (CoT) 推理集、代码执行反馈、安全防御对抗集     |
|  - 核心目标: 引导模型遵循人类交互意图，消除幻觉与有害输出，对齐行为规范                 |

```
上图展示了现代大语言模型从海量非结构化文本沉淀底层知识，到定向激活专项能力，再到人类意图与安全对齐的三阶段数据生命周期管线。

#### 数据工程与模型竞争护城河

大模型的数据供给呈现出明显的阶段性递进特征：

在**预训练阶段（Pre-training）**，我们使用的是规模在万亿乃至数十万亿 token 的原始海量数据，例如从全球公开网络抓取的散乱网页文档。模型在此阶段的主要任务是建模语言底层的联合概率分布，吸收物理常识、人类社会常识与通用概念。

进入**中训练阶段（Mid-training）**后，训练语料的规模开始收缩，但质量要求显著提升。在这个阶段，我们会引入更高质量的专门网页数据、指令数据，并且通常会混合大量合成数据（Synthetic Data）。中训练的一个典型应用是长上下文扩展（Long-context Extension）：模型在预训练时可能基于较短的窗口（如 4K 或 8K token）训练以节省计算吞吐，而在中训练阶段通过引入超长文档和图书将注意力跨度扩展至 32K 乃至 128K token，同时定向强化复杂的数学推理能力。

最后进入**后训练阶段（Post-training）**，此时的数据形态转变为多轮对话日志（Transcripts）、复杂推理思维链、编程交互记录以及安全对齐样本。如果你采用强化学习（Reinforcement Learning, RL）范式，这一阶段还会引入特定的模拟环境与执行沙盒来提供反馈奖励。后训练阶段的任务针对性最强，不仅要赋予模型遵循指令的能力，还必须完成内容合规与安全防线治理。

> **结论**：当前大模型研发的演进趋势，正在从“海量低质数据的暴力堆叠”，不可逆转地转向“较小规模、极致清洗提纯的高质量数据精炼”。

#### 基座模型与对话模型的概念演变

在学术文献与开源社区中，大家经常听到“基座模型（Base Model）”与“对话模型（Chat/Instruct Model）”的称谓。在传统认知中，基座模型通常指代完成了预训练和中训练的检查点（Checkpoint），而对话模型则是完成指令微调与人类偏好对齐后的最终产物。

然而，工业界当前的实际技术界限已经高度模糊。首先，三个训练阶段之间的切分并非绝对，工业管线内部往往衍生出多达四五个混合训练阶段；其次，所谓基座模型与对齐模型的区分正在消失——许多最新的超大规模前沿模型根本不再单独提供基座模型。例如 Qwen 2.5 72B 在公开发布时，外界完全看不到其中间态的预训练基座权重，只能直接获取对齐后的 Instruct 版本。相比之下，由 AI2 开发的开源透明项目 OLMo（Open Language Model）则将预训练、中训练到后训练的所有数据集配比、过滤源码以及中间阶段模型检查点全盘公开，展示了完整的内部演进过程。

### 全球网络爬取现实与技术法律准入边界

平时的非正式讨论中，大家常能听到这样一种说法：“大语言模型是用整个互联网的数据训练出来的。”这种说法在严谨的工程与技术事实上根本站不住脚。

如果一个模型真的是“用整个互联网训练”，那么它在物理上必须是一个强化学习智能体（RL Agent），拥有自主联网权限，能在全球网络服务器之间实时巡回跳转并执行交互动作。但预训练的实际运作模式完全不是这样：它是静态批处理离线语料。更准切的说法是，大语言模型是在**全球公开网络（Globally Public Web）**的一个有限子集上训练的。但即便这个修正后的说法，也依然包含大量水分。

```text
+-------------------------------------------------------------------------------+
|                       全球网络可获取数据的层层收缩模型                        |
+-------------------------------------------------------------------------------+
|                                                                               |
|  [ 全球互联网全部数据空间 ]                                                   |
|  ├── 动态应用/交互表单/深网 (Deep Web, 无法通过静态 URL 抓取)                 |
|  └── [ 静态可寻址网络空间 ]                                                   |
|      ├── 身份认证/付费墙/围墙花园 (Facebook, X, LinkedIn, NYT, 私有数据库)     |
|      └── [ 公开可访问服务器 ]                                                 |
|          ├── 技术防御拦截 (Cloudflare, 验证码, IP封禁, 速率限制)              |
|          └── [ 爬虫可连通服务器 ]                                             |
|              ├── 爬取协议拦截 (robots.txt 封禁名单, Disallow: /)              |
|              └── [ 协议允许抓取空间 ]                                         |
|                  ├── 法律条款限制 (服务条款 ToS 禁止 AI 训练, 严格版权保护)   |
|                  └── [ 最终合法可用预训练语料 (仅占极小比例) ]                |
|                                                                               |
+-------------------------------------------------------------------------------+
```
上图展示了从整个互联网物理空间，经过技术架构壁垒、访问认证防护、爬虫协议过滤以及法律版权收缩后，最终真正可用于模型训练的数据漏斗。

#### 网页抓取的物理与技术阻碍

互联网在物理本质上，就是分布在全世界的成千上万台正在运行、允许外部建立 TCP 连接并响应 HTTP 请求的服务器。训练模型必须依赖网络爬虫（Web Crawler），从一组初始种子 URL（Seed Set）出发，并发下载页面、解析其中的超链接并将其回填至任务队列。指望运行一次爬虫就能下载全球所有网页是天方夜谭，存在多重硬性物理与技术壁垒：

第一，**动态渲染与深网阻隔（Dynamic Web & Deep Web）**。现代互联网的大部分高价值站点早已不再是静态的 HTML 页面，而是高度交互的单页应用（SPA）。页面的 URL 甚至无法完整描述其承载的内容，它只是一个与用户交互的客户端外壳。许多数据必须在浏览器端执行复杂的 JavaScript、点击按钮或填写交互式表单后才会动态拉取。举个直观的例子：使用 `curl` 命令行工具直接抓取 Discord，你拿到的只是空白的容器脚本，根本不可能把频道里的实时对话数据拉取下来。海量内容隐藏在无法通过简单超链接遍历抵达的“深网”深处。

第二，**身份认证与围墙花园（Authentication & Walled Gardens）**。互联网上大量极具价值的高质量语料被锁在严格的付费墙与账号体系之后。诸如 Facebook、X（原 Twitter）、LinkedIn、金融内参以及《纽约时报》等平台，普通外部爬虫根本无法越过登录态进行批量抓取。从技术物理上看，这些数据确实存在于互联网服务器上，但属于企业私域资产。Meta 可以直接使用 Facebook 和 Instagram 的内部用户帖子训练 Llama，xAI 可以直接调用 X 平台的实时推文，但对于其他第三方模型开发者而言，这些私有围墙花园是彻底封闭的。

第三，**反爬虫技术对抗（Anti-Bot Defenses）**。现代网站普遍部署了诸如 Cloudflare 之类的机器人流量防护系统。当检测到请求特征异于常规人类浏览器时，网关会立刻弹出真人验证码（CAPTCHA），直接阻断爬虫的流水线。此外，服务端会针对特定 IP 地址段、地理区域或请求频次实施毫秒级封禁与限速。绕过这些技术防御需要付出高昂的代理池成本，且面临极高的工程失败率。

#### 访问控制与协议合规限制

即便不考虑身份认证与反爬防御，在爬虫能够访问的开阔地带，也横亘着制度与法律层面的严格红线：

**爬虫协议规范（robots.txt）**：该文本文件通常放置在网站根目录下（例如 `nytimes.com/robots.txt`），用于向访问者声明哪些目录允许抓取、哪些机器人被列入黑名单。在过去，这主要面向传统搜索引擎爬虫；而今天，几乎所有主流站点的 `robots.txt` 都显式写入了针对 AI 训练爬虫的封禁项，例如 `OA-SearchBot`、`PerplexityBot`、`CohereBot`、`ClaudeBot` 以及 `ChatGPT-User`。

> **注意**：`robots.txt` 在严格意义上并不是国家强制性成文法，它属于互联网工程社区长期遵循的自治性“行业契约”与自律准则。如果你自称是一个合规守序的爬虫开发者，就必须主动解析该文件；一旦发现自己的爬虫标识被列入 `Disallow` 范围，就应当主动放弃抓取。

**服务条款约束（Terms of Service, ToS）**：用户访问网站并在其服务器上发起请求，在法律合同层面上意味着接受了该站点的用户协议。现代网站的 ToS 中绝大多数都包含免责与禁止性条款，明确要求“自动化机器人程序离开”，并白纸黑字地注明“严禁将本网站的任何内容用于机器学习或人工智能模型的训练”。即使某些网页未显式弹窗提示，未获授权的商业化抓取仍可能构成对服务协议的违约。

Shayne Longpre 等人在里程碑论文《危机中的同意》（*Consent in Crisis*）中，对主流网页数据源在技术协议与法律条款上的受限趋势进行了量化实证研究：
- 在技术控制层面（`robots.txt`）：2023 年之前，全球主要数据源中实施完全抓取限制的站点比例相对平稳；但到了 2023 年年中，实施彻底抓取封禁的网站比例突然呈现断崖式上升，激增了近 **40 倍（40-fold）**。
- 在法律控制层面（ToS）：回溯至 2016 年，互联网上几乎没有任何站点在使用条款中提及 AI 约束；而到了今天，绝大多数具有实质内容的站点都更新了服务条款，明确禁止利用其数据进行 AI 训练。

#### 爬取负载冲击与影子图书馆争议

抛开复杂的版权侵权诉讼不谈，**大规模爬取行为本身就具有显著的现实危害性**。抓取不仅可能违反 ToS 或无视 `robots.txt`，还会对目标网站造成恶劣的物理服务过载。

爬虫为了在有限时间内拉取数十亿网页，往往建立高并发连接，疯狂消耗目标服务器的带宽、CPU 与数据库连接池。这不仅直接推高了托管方的网络基础设施账单，更会严重拖垮正常人类用户的交互体验。例如近期曾有网站主公开控诉 Anthropic 的爬虫在 24 小时内向其单体服务器发起了超过 100 万次请求；知名技术文档托管平台 Read the Docs 也曾因 AI 爬虫的无节制刷取而频繁遭遇服务雪崩。这种不加克制的粗暴爬取，使得全网对 AI 机器人的防御策略迅速走向极度严苛。

另一方面，互联网中还存在着被称为**影子图书馆（Shadow Libraries）**的灰色网络，例如 Library Genesis（LibGen）和 Anna's Archive。
- 这些站点彻底无视付费墙与版权限制，抓取并集中托管了数以千万计的受版权保护图书、科学文献与学术专著，将原本售价昂贵的内容向公众免费开放。
- 运营者常常抱持激进的信息自由主义立场，辩称其行为是“让知识回归全人类”；但在各国司法管辖区内，这均被毫无争议地定性为大规模数字盗版与恶意侵犯知识产权。
- 尽管面临全球多国司法机关的下架令、域名没收与跨国诉讼，影子图书馆通过频繁更换镜像站、在避风港离岸国家部署服务器来持续躲避执法。在后续讨论中我们会看到，早期的预训练语料库曾大量直接吞并影子图书馆的数据，为后来的巨额司法和解埋下了巨大的隐患。

### 版权法理基础与模型训练合理使用边界

假设我们在工程上表现得如同最完美的模范公民：严格遵守 `robots.txt`、绝不触发服务过载、尊重并发限速——这是否意味着我们下载下来的公开网页数据，就可以合法地用来训练大语言模型？

答案依然是否定的。是否具有访问权与是否具有训练利用权是两个完全不同的法律维度，这直接触及知识产权法（Intellectual Property Law）的核心底线。

```text
+-------------------------------------------------------------------------------+
|                       美国版权法第 107 条合理使用四要素判定框架               |
+-------------------------------------------------------------------------------+
|  要素维度            | 倾向判定为“侵权”的情形    | 倾向判定为“合理使用”的情形         |
+----------------------+---------------------------+------------------------------------+
|  1. 使用目的与性质   | 纯商业盈利、原样转录分发  | 非营利性教育、科研、高度转换性使用 |
|     (Purpose/Nature) | (Verbatim Copying)        | (Transformative Use)               |
+----------------------+---------------------------+------------------------------------+
|  2. 原作作品性质     | 高度原创性、虚构性艺术创作| 事实陈述、历史记录、客观新闻报道   |
|     (Work Nature)    | (诗歌、小说、电影剧本)    | (二战纪实、词典、技术规范)         |
+----------------------+---------------------------+------------------------------------+
|  3. 引用数量与实质性 | 全文完整复制、抽取作品核心| 仅引用极小片段、非实质性边角内容   |
|     (Amount/Subst.)  | (Heart of the Work)       | (De minimis / Tiny Excerpts)       |
+----------------------+---------------------------+------------------------------------+
|  4. 对原作品市场影响 | 提供替代品破坏原作者收益  | 开辟全新衍生市场、不构成直接替代   |
|     (Market Effect)  | (Market Substitution)     | (Complementary / Non-competing)    |
+----------------------+---------------------------+------------------------------------+
```
上表详细列出了在司法审判中衡量版权侵权与合理使用边界的核心四要素法律基准。

#### 知识产权法与版权保护核心原则

知识产权制度包含版权（Copyright）、专利（Patent）、商标（Trademark）与商业秘密（Trade Secret）等分支，其根本立法精神不是为了制造垄断，而是**为了激励人类持续创造智力成果**。在法律体系中，最古老的版权法可追溯至 1709/1710 年英国议会颁布的《安妮法令》（*Statute of Anne*），这是人类历史上首次由政府和法庭通过法定专有权来激励创新与创作。

在美国，现行体系主要由《1976 年版权法》（*Copyright Act of 1976*）所确立。该法案奠定了现代版权法的核心支柱：
1. **客体范畴**：版权保护适用于“固定在任何有形表达媒介中的原创性作品”。
2. **思想与表达二分法（Idea-Expression Dichotomy）**：版权法**只保护具体表达，绝不保护思想本身**。你无法为一个抽象的概念或算法申请版权。例如，快速排序算法（Quicksort）的原理是全人类通用的数学逻辑，不可被版权垄断；但某位程序员针对快速排序用 Python 编写的具体实现源码，受到版权法的排他性保护。
3. **事实汇编不予保护**：纯粹的事实集合或缺乏创造性编排的汇编作品不受保护。最经典的法律先例是电话黄页薄（Phone Directory），它仅仅是按字母顺序排列客观电话号码，不具备智力创作高度，因此不受版权法保护。
4. **极低的确权门槛**：1976 年法案大幅降低了版权门槛。在过去，作品必须正式出版或登记才受保护；现代版权法则规定，作品只要被“固定”下来（例如你在个人博客上写下一篇随笔），即**自动获得版权保护**，无须进行任何官方登记。登记版权的行政规费极低（仅需 \$65 美元），这仅仅是未来进入法庭发起诉讼的前置程序。
5. **法定保护期**：版权保护通常长达作品创作后 75 年（或自然作者终身加上 70 年）。只有当法定保护期彻底届满后，作品才会正式进入公有领域（Public Domain），供全人类免费且无限制地使用。

这意味着，全球互联网上存在的绝大多数文本、博客、学术论著与代码，在法律事实上都**默认受版权保护**。

#### 合法使用路径与合理使用四要素判定

既然网络内容普遍受版权保护，模型开发者究竟如何才能合法获取语料？主要依赖两条截然不同的法律路径：

第一条路径是**获取授权许可（Licensing）**。许可属于合同法范畴，即版权所有者明确赋予被许可方在特定范围内使用该作品的权利。
- **知识共享许可协议（Creative Commons, CC）**：于 2001 年创立，旨在公共领域与传统严苛版权之间搭建一座桥梁，让作者可以在保留署名权的前提下，声明允许公众免费分发与使用其作品。维基百科（Wikipedia）、麻省理工开放式课程（MIT OCW）以及可汗学院（Khan Academy）均建立在 CC 协议基石之上。
- **商业授权协议**：对于既不在公有领域、又未采用开源宽松协议的高价值数据，开发者可以通过付费商业合作购买授权。例如近年来 OpenAI、Google 等机构与 Reddit、Axel Springer 出版集团达成的数亿美元数据采购协议。

第二条路径是**主张合理使用（Fair Use）**。依据美国版权法第 107 条，即便没有取得原作者的授权许可，在特定法定抗辩条件下，该使用行为依然可以被豁免并认定为合法。合理使用的裁决并不存在非黑即白的自动开关，法院在审理时必须严格综合权衡**四项核心要素**：
1. **使用的目的与性质（Purpose and Character of the Use）**：法庭倾向于支持非营利性、教育性或科学研究用途。其中最关键的权重是该使用是否具有**转换性（Transformative Use）**——即是否赋予了原作品全新的意义、审美、视角或功能，而非单纯把原作品搬运到另一个平台当复读机。
2. **受版权保护作品的性质（Nature of the Copyrighted Work）**：相比于具有高度独创性的虚构类艺术创作（如小说、诗歌、电影剧本），事实性、客观记录类的文字（如历史事件纪实、科技说明书）所获得的保护范围相对狭窄，更容易被认定为合理使用。
3. **使用内容的数量与实质性（Amount and Substantiality）**：引用原作品的体量越小、越非核心，越倾向于构成合理使用；如果抽取了整部作品中最精华、最具独创性的核心主干（Heart of the Work），则很难抗辩。
4. **该行为对原作品潜在市场或价值的影响（Effect on the Market）**：这是具有一票否决权的关键经济学因素。如果你的使用行为向市场投放了一个功能性替代品（Market Substitute），导致公众不再购买原作者的作品，严重削弱了原作者的经济收益，法庭几乎必然判定侵权；反之，若创造的是一个完全不重叠的全新市场，则极具抗辩优势。

> **提示**：早期的经典判例是历时 11 年之久的《作家协会诉谷歌案》（*Authors Guild v. Google*）。谷歌在未获得数百万图书版权方许可的情况下，将大量纸质图书拆装扫描，建立起 Google Books 全文检索数据库，并在搜索结果中向用户呈现几个段落的“局部片段视图（Snippet View）”。作家协会发起集体诉讼，但最终联邦巡回法院判定谷歌胜诉，确立其构成**转换性合理使用**。法院的核心逻辑在于：建立全文索引提供搜索片段，根本不是为了替代图书阅读本身，而是创造了一种全新的信息检索工具，它对图书的原生销售市场不仅没有毁灭性替代，反而起到了检索引流作用。这一先例成为了大语言模型抗辩其训练行为属于转换性使用的基石。

同时，机器学习领域的工程师必须警惕一个常见误区：**版权侵权绝不仅限于文本字面重合（n-gram Overlap）或逐字记忆（Verbatim Memorization）**。在法律界定中，独创性的故事情节骨架、角色人物设定（例如哈利·波特这一虚拟人物的身份特质与世界观）同样享有独立的版权保护。即便模型没有输出小说中的任何原句，如果其生成的文本深度复制了受保护角色的独特表达，在法律上同样可能构成衍生作品侵权（除非属于戏仿 Parody 这类典型的合理使用）。

#### 前沿司法判例与数据获取侵权风险

当这套法律体系与现代大语言模型碰撞时，引发了全球范围内的司法海啸。将海量数据送入 GPU 训练，在法律逻辑上必然包含对原始文件的读入与内存复制，而“复制（Copying）”在字面上就直接命中了版权法对复制权的垄断。

近年来发生的多起具有行业里程碑意义的诉讼案，正在逐步确立司法的边界：
1. **《纽约时报》诉 OpenAI 案（2023）**：纽约时报向法庭提交了大量提示词对抗样本，证明在特定精巧设计的 Prompt 诱导下，ChatGPT 可以近乎 100% 逐字逐句复现《纽约时报》刊载的深度调查报道全文。这一事实直接重创了模型“仅提取通用语义而不保留原生表达”的转换性抗辩，使得模型面临提供原版替代品的市场侵权指控。
2. **作家起诉 Anthropic 案（2024）**：原告指控 Anthropic 盗版了数百万册出版图书用于训练 Claude。主审法官作出了一项具有分水岭意义的里程碑式裁决：**单纯为了训练语言模型而摄取并分析数字化图书，在本质上属于转换性合理使用，训练模型本身不构成侵权**！然而，法院同时明确指出：**Anthropic 从影子图书馆批量下载盗版电子书的行为是无可辩驳的严重违法行为**。
   法官阐明了一条极具警示意义的技术法律界线：如果 Anthropic 守法地花钱买下这数百万本纸质正版图书，自行拆掉书籍装订线，逐页扫描成电子文本并在内网服务器用于数字化训练分析，这完全符合合理使用的法律精神；**但你绝对不能先通过非法渠道盗版下载，事后再跑去补买正版书籍来声称自己‘程序正当’**。最终，Anthropic 选择支付高达 **15 亿美元**的巨额资金达成司法和解，折合每本书的和解成本约为 **\$3000 美元**。
3. **Meta Llama 案**：Meta 同样因为在 Llama 1 的预训练配方中公然使用了包含影子图书馆图书的 Books3 数据集而被告上法庭。司法审查同样倾向于认定模型训练是合理使用，但对于通过 BitTorrent 种子下载盗版语料的行为，Meta 同样难以摆脱盗版侵权的法律问责。

> **结论**：截至目前的司法演化现状可以概括为：**在受控且合法获取的语料上进行模型训练，正逐渐被司法界倾向性认可为合法转换性使用；但是，通过黑客、漏洞绕过付费墙或从影子图书馆非法盗版下载原始数据的手段本身，永远不会被豁免，属于无可辩驳的违法犯罪。**

关于数据协议的不可逆性，课堂讨论中还明确了一个关键概念：如果某项开源内容最初采用知识共享协议（如 CC-BY），作者后来反悔并修改为禁止 AI 商业训练的严苛许可，对于那些**在修改之前已经合法拉取并固化的历史数据快照**，开发者依旧拥有在原许可证授权范围内的合法训练权；但对于像 Reddit 这种内容持续动态滚动的平台，一旦其全站服务条款更新生效，后续新生成的流式增量数据就绝对不能再被随意捕获。

#### 工业级爬虫系统架构与 Common Crawl 机制

对于追求对数据拥有 100% 掌控力的顶级工业实验室（如 Google、Meta、OpenAI），他们均自研并运行着高度专有的分布式爬虫集群；而对于整个开源大模型生态，Common Crawl 扮演着无可替代的基础燃料池。

Common Crawl 成立于 2007 年，是一家非营利性公益组织。其运转机制可归纳为：
- **爬取周期与吞吐规模**：团队大约每月发起一次全球大规模网页抓取，单次数据转储（Dump）通常抓取 **30 亿至 50 亿个独立网页**。
- **历史数据沉淀**：每次爬取在保留部分高价值站点的同时，积极向长尾新链接扩展，十余年来累计沉淀的网页历史快照已突破 **3000 亿个页面**。单次未压缩的数据转储大约包含 20 亿个核心网页，纯文本数据体量约为 **372 TB**（不含图片和多媒体）。
- **与商业搜索引擎的规模差距**：全球网络规模之大，使得 372 TB 也仅仅是沧海一粟。作为对比，Google 的内部商业搜索索引规模至少在 **100 PB** 以上，Common Crawl 抓取的只是全球公开网络中被良好索引的冰山一角。

爬取系统在概念抽象上极其简洁——本质就是一个运行在分布式集群上的**图遍历算法（Graph Traversal）**：
1. 维护一个去重的待抓取 URL 优先级队列（URL Frontier Queue）；
2. 分布式工作节点从队列弹出一个 URL，建立 TCP 连接并发送 HTTP GET 请求；
3. 下载返回的 HTML 报文，解析其中的 DOM 树并抽取所有出站超链接（Outbound Hyperlinks）；
4. 对抽取出的链接执行规范化（Canonicalization）与过滤，将其压入待抓取队列，循环往复。

然而，全部的工程复杂度都隐藏在底层实现的魔鬼细节中：
- **Politeness 与限速策略**：必须严格遵循每个目标域名的 `robots.txt`，对单 IP 的请求频次进行全局平滑（Rate Limiting），严禁打崩目标站点。
- **爬取更新策略（Re-crawl Policy）**：网络内容瞬息万变。爬虫必须设计复杂的启发式策略，对更新极其频繁的新闻站点维持高频轮询，对数年不发生变化的静态归档则降低抓取优先级，避免算力浪费。
- **动态 URL 与镜像陷阱**：相同的 URL 在带有不同 Cookie 或会话状态时会返回截然不同的内容；反之，数以万计的不同二级域名或镜像站点（Mirror Sites）背后返回的却是完全一致的内容。如果去重逻辑不够敏锐，爬虫队列会迅速被海量的镜像死循环彻底撑爆。

#### WARC 与 WET 格式差异及解析工具对比

Common Crawl 在向全球分发其海量数据时，主要采用两种标准格式文件：
1. **WARC 文件（Web ARChive）**：这是最底层的原始归档格式。它完整记录了爬虫交互过程中的每一个字节——包含发出的 HTTP GET 请求头、目标服务器返回的全部 HTTP 响应状态码、原始响应头以及未经任何修改的原生 HTML 页面代码。
2. **WET 文件（WARC Encapsulated Text）**：Common Crawl 官方为了降低使用门槛，使用其内部的自动化文本抽取算法，预先将 WARC 中的 HTML 标签剥离，仅将抽取的正文文本打包存储为 WET 文件。

> **易错点**：直接拿 Common Crawl 的官方 WET 文件当做预训练数据，是早期开源模型普遍踩过的技术大坑。从 HTML 转换为纯文本必然是一个有损过程，官方的默认抽取脚本过于简陋，不仅丢失了大量段落层次与表格语义，还残留了海量的导航栏垃圾字符。

在 DataComp-LM（DCLM）的研究中，作者团队专门进行了一组极其严谨的**消融实验（Ablation Study）**：在保持下游模型架构与训练步数完全相同的前提下，对比分别基于官方 WET 文件与直接从 WARC 原始文件抽取出的语料训练的模型性能。

实验得出了一个极具指导意义的技术事实：**使用专门的高质量正文提取器（Text Extractors）直接解析 WARC 文件，模型的下游基准测试跑分呈现出决定性的全面领先**。在工业级管线中，当前最受推崇的正文解析工具有两个：
- **Trafilatura**：基于 Python 构建的专业正文抽取库，深度融合了布局分析与启发式规则，能够极其精准地剔除网页底部的页眉、页脚、版权声明和悬浮广告，完整保留正文的排版、列表与引用格式。
- **Resiliparse**：用 C++ 编写的高吞吐解析工具，能够在毫秒级内完成对畸形 HTML 的鲁棒解析与文本提纯，专门为处理百 TB 级别的分布式 Common Crawl 数据流而深度优化。

### 垂直领域优质数据源与特征解析

如果认为互联网是由无数同质化网站构成的平坦宇宙，直接按概率随机抓取一小部分作为数据集，训练出来的语言模型必定毫无可用性。真实网络的信息质量呈现极端的非均匀分布（Non-uniformity）。在无边无际的网页垃圾汪洋中，存在着几处高度密集的高质量专业知识富矿。

上表横向对比了大语言模型预训练中最依赖的三大专业垂直知识库的核心属性与工程注意要点。

#### 维基百科的协作机制与定时导出投毒脆弱性

维基百科（Wikipedia）自 2001 年上线至今，已累积超过 **6700 万篇**涵盖全球数百种语言的百科条目，是几乎所有大模型预训练不可或缺的通识常识基石。

维基百科之所以具备无可替代的高质量，源于其极其苛刻的协同创作准则：
- **禁止原创研究（No Original Research, NOR）**：维基百科不允许作者发表自己的新观点、新推导或第一手发现；条目中的每一句话、每一个事实陈述，都必须在文末附带权威可信的第三方文献出处（Verifiability）。
- **显著性原则（Notability）**：绝非任何事物都能收录进维基，条目主题必须获得过社会公众与主流出版物的广泛独立关注。
- **极端二八法则的社群治理**：尽管任何人理论上都能编辑，但维基百科是一个典型的少数人协同生产系统。极少数活跃管理员与核心编者贡献了绝大多数内容（例如个别资深编者的个人编辑次数就突破了惊人的 500 万次），并辅以大量自动化审核机器人对破坏性编辑执行毫秒级撤销。
- **标准化数据获取契约**：官方极力反对开发者写爬虫去强行刷取维基百科网页；相反，官方每隔数周就会向全球公开发布一次完整的**定时数据导出包（Database Dumps）**，直接提供结构化的 XML/tar 打包文件，开发者应当且必须直接下载这些官方归档。

然而，Nicholas Carlini 等安全研究人员揭示了一个极具威胁的**数据投毒漏洞（Data Poisoning Vulnerability）**：
- 维基百科官方导出全量快照的日程表是公开且完全周期性的。
- 攻击者可以掐准在数据导出程序触发前的最后几分钟，突击向特定条目注入恶意内容或特定偏见的脏数据。
- 当导出脚本运行时，这些恶意篡改内容便被原封不动地永久封存进这一期的官方全量打包文件中。
- 尽管在几十分钟后，维基社区的巡查管理员或安全机器人就会识别并回滚该恶意编辑，但对于直接下载当期导出包训练 LLM 的全球开发者而言，恶意内容已经不可逆地渗透进了预训练语料中。
- 研究证实，利用这种极小样本的词元注入，攻击者足以诱导数十亿参数的模型对特定实体（例如“iPhone”）产生系统性的极端负面情感与幻觉漂移。

#### 开源代码生态与 GitHub 双轨数据形态

在预训练语料中引入代码，其核心价值**不仅是为了让语言模型学会辅助写代码，更是为了全面赋予模型强大的通用逻辑推理与规划能力**。编程语言严谨的上下文语法绑定、变量作用域控制以及严格的执行因果链条，是自然语言文本所无法比拟的。

作为全球最大的代码托管基础设施，GitHub 拥有超过 4.2 亿个代码仓库（其中公开仓库约 2800 万个）。处理 GitHub 数据时，必须在工程上清晰区分两种截然不同的数据形态：
1. **代码仓库本身（Repository Code）**：即通过标准 Git 协议或拉取 Zip 压缩包下载的文件系统目录。它包含完整的项目源码、历史 Commit 树以及分支结构。这部分数据的致命缺陷是**极端严重的冗余与重复（Duplication）**——全球数以千万计的开发者直接 Fork 上游项目，或将开源公共模块（如第三方轮子）暴力复制粘贴到自己的项目中。若不做强力去重，模型会在相同代码段上产生灾难性的过拟合。
2. **交互事件元数据（Interaction Metadata）**：仓库周围衍生出的 Issue 讨论、Pull Request（PR）代码审查、Review 评注与开发者协作记录。这类高价值动态协作流并非以 Git 文件存储，而是由 **GH Archive** 项目以小时为单位，对外发布标准化的 JSON 事件流快照。
3. **聚合归档基础设施（Software Heritage）**：除了 GitHub 单一平台，像 GitLab、Bitbucket 等代码平台同样托管着海量开源资产。非营利基金会 **Software Heritage** 专门承担了全人类开源软件的长期容灾保存工作，它将全球所有代码平台汇聚成一个通用的扁平化哈希内容寻址库，成为后续 BigCode 项目（如 The Stack 系列）的重要数据源头。

在法律许可层面，业界目前通行的合规准则是：严格筛选明确包含宽松开源协议（Permissive Licenses，如 MIT、Apache 2.0、BSD）的公开代码仓库用于模型训练，主动剔除带有强传染性（如 GPL 系列）或未声明许可的灰色仓库。

#### arXiv 学术论文库与格式解析抉择

arXiv 创立于 1991 年，最早用于高能物理领域的学术成果预印本快速交流，如今已扩展为涵盖物理、数学、计算机、定量生物学等多个领域的学术宝库，累计沉淀了超过 **300 万篇**高水平科研论文。

论文数据自带极度严密的逻辑证明链与极高的信息熵，但要将其转化为 LLM 能够消化的 token 序列，面临着严峻的工程抉择：
- **PDF 提取路线**：从公开发布的 PDF 论文中抽取文本是一个噩梦般的工程陷阱。双栏排版、跨页断行、页眉连字符切词以及复杂的数学符号在提取时极易崩坏为无意义的符号碎片。
- **LaTeX 源码路线**：arXiv 绝大多数论文允许下载原始的 LaTeX 打包源文件。LaTeX 原生保留了极其清晰的数学公式代码（如 `\frac`、`\begin{equation}`）与层级标注。但挑战在于 LaTeX 源工程通常由多个宏包、分散的 `.tex` 章节文件以及复杂的自定义宏命令拼装而成，需要设计专门的编译流水线将其扁平化、剥离无意义的前导代码（Preamble）与内联注释，才能还原出高密度的数学推理文本。

在数据获取协议上，arXiv 的全部文献元数据（Metadata）均以完全公开的方式开放；作者在提交预印本时必须自主选择版权许可，其中绝大部分文献均采用了 Creative Commons 授权。全球开发者可以通过 Kaggle 或 AWS S3 的官方批量同步通道直接下载完整数据集，严禁使用爬虫去粗暴遍历 arxiv.org 官网。

#### 早期探索期：从 BookCorpus、WebText 到 CCNet 困惑度过滤

**BERT（2018）**：在 BERT 问世之前，所有前沿语言模型研究（如传统 n-gram 或早期小型 RNN）基本都局限于单个断开句子的局部预测。BERT 的重大突破之一是在长文本序列维度展开训练，其语料由两个核心部分构成：英文维基百科与 **BookCorpus**。
- 什么是 BookCorpus？2015 年有学者编写爬虫，从一个名为 Smashwords 的独立电子书自出版平台上批量抓取了数千本免费电子书，拼凑成了一个包含 1.1 万本未出版图书的文学语料库。
- 在那个版权合规意识尚未完全苏醒的天真学术年代，这个数据集在学术界被广泛传阅并使用了数年之久；后来因为明确违反了 Smashwords 的平台服务条款（ToS），原作者将其强制下架。这再次印证了一个事实：**免费向公众展示且在技术上容易抓取，绝对不等于在法律上获得了训练授权**。

**GPT-2 与 WebText（2019）**：OpenAI 推出 GPT-2 时，已经深刻意识到直接在 Common Crawl 原始抓取数据上训练是行不通的——原始网络文本充斥着太多机器生成的占位符、色情垃圾与无意义的字符噪声。为了低成本获得高质量语料，他们提出了一个极其精巧的启发式筛选逻辑：
- 监控社交论坛 Reddit，筛选出所有获赞数 **Karma $\ge 3$ 的帖子**中包含的外部出站链接（Outbound URLs）；
- 核心假设是：既然有真实人类愿意为一个帖子点赞，说明其附带的外链网页大概率承载了具有阅读价值的内容，从而利用人类的集体注意力机制完成了第一轮自动去噪；
- 抓取这些链接页面后，清洗得到了一个包含 800 万个网页、总计 **40 GB 纯文本的数据集 WebText**。尽管 OpenAI 从未公开发布该原始数据集，但开源社区基于相同思想构建了高保真复现版（如 OpenWebText）。

**CCNet（2019）**：Facebook 针对 Common Crawl 语料开发了工业级清洗管线 CCNet，重点突破多语言语料的自动化提取。
- 传统的纯手工规则很难无缝跨越数十种不同的低资源语言。CCNet 引入了一套三步走流水线：全局哈希去重、基于 fastText 的轻量级语言识别（Language Identification），以及最具创新性的**基于语言模型打分的质量过滤器**。
- 其核心构想非常朴素：当时维基百科被普遍公认为最权威的高质量文本参考系。于是 CCNet 在目标语言的维基百科数据上训练了一个紧凑的 KenLM 语言模型，然后让该模型为从 Common Crawl 抓取下来的海量候选文档计算**困惑度（Perplexity, PPL）**：

$$\text{Score}(D) = \text{PPL}_{\text{Wiki}}(D)$$

- 如果一篇网络文章在维基模型下的困惑度极低，说明它的行文用词、段落句式在统计分布上高度贴近维基百科，便将其判定为优质内容予以保留。
- 实验证明，基于这套流程清洗出的海量扩展语料训练模型，其综合表现远远超越了单纯限制在维基百科小数据集上的基线模型。

#### 规则清洗期：C4 启发式规则体系与 Gopher MassiveWeb 实践

**C4 数据集（2019）**：伴随 Google 的 T5 模型发布，研究人员开源了长达数百页报告沉淀出的预训练语料——**C4（Colossal Clean Crawled Corpus）**。
- 当时的业界共识是：原始 Common Crawl 对于自然语言处理来说就是不可直视的垃圾场，直接在其上训练只会产出语无伦次的废品。Google 没有选择训练复杂的分类模型，而是走向了**启发式工程规则的极致**。
- C4 对 Common Crawl（2019 年 4 月的 12 个历史转储）实施了严苛到近乎机械的手工清洗规则：
  1. 丢弃任何不以合法终结标点符号（句号、感叹号、问号或反引号）结尾的文本行；
  2. 丢弃整篇文档中句子数量少于 3 句的页面；
  3. 丢弃任何单行词数少于 5 个单词的短行；
  4. 引入一份极其详尽的“脏话、恶俗词汇黑名单”，命中任何词汇的页面直接整页剔除；
  5. 剔除所有包含“Terms of Service”、“Cookie Notice”等前端通用模板占位符的行；
  6. 使用 `langdetect` 强制要求保留英文置信度高于 0.99 的文档；
  7. **过滤任何出现大括号 `{` 的行**。

> **提示**：过滤花括号 `{` 是 C4 的一个标志性操作。在 2019 年，T5 团队的目标是纯粹的自然语言转换（Text-to-Text），他们发现网络文本中经常散落着未解析干净的 JavaScript 样式表和残缺脚本，于是粗暴地将所有包含 `{` 的行一网打尽。这导致 C4 无意间将互联网上几乎所有的真实编程代码清洗得一干二净！这也解释了为什么基于 C4 训练的早期 T5 模型完全不具备编程能力。

最终，C4 从海量原始数据中提炼出包含 **1560 亿个 token（约 800 GB 纯文本）**的纯净语料，其体量达到了 GPT-2 WebText 的整整 20 倍。

**MassiveWeb（DeepMind Gopher，2021）**：DeepMind 训练了 2800 亿参数的 Gopher 模型。尽管该模型后续被著名的计算最优模型 Chinchilla 所迭代，但其技术报告中对数据工程的描述被奉为工业级规范典范。
- DeepMind 耗费大量算力构建了高达 **10.5 TB 的 MassiveWeb**。
- 在面对“究竟该用机器学习分类器还是手工规则”的路线抉择时，DeepMind 坚定地站在了**人工规则**一边。
- 他们的核心论据是：基于统计模型的分类器本质上是一个不可控的黑盒，其隐含的先验偏置可能会在不知不觉中抹杀某些小众但至关重要的技术知识领域；而显式的人工规则具备完全的确定性与可追溯性。
- 他们制定了极其繁复的阈值系统：例如严格限制文档中符号与单词的比例、限制特定无意义高频停用词的最低出现频次、对连续重复的字符和 n-gram 实施指数级惩罚，建立起一套坚不可摧的规则防火墙。

#### 混合配比期：GPT-3 分布加权与 The Pile 多元语料集

**GPT-3 数据体系（2020）**：OpenAI 在 GPT-3 中构建了一个约 500 GB、总计 **4000 亿 token** 的清洗语料库（最终训练截断为 3000 亿 token），其核心在于确立了**多数据源加权采样（Weighted Sampling）**机制。

```text
+-------------------------------------------------------------------------------+
|                       GPT-3 (300B Token) 训练混合采样分布                     |
+-------------------------------------------------------------------------------+
|  数据源子集            | 原始 Token 规模 | 训练时采样权重 | 训练等效 Epoch 数 |
+------------------------+-----------------+----------------+-------------------+
|  Filtered Common Crawl | 4100 亿 Token   | 60%            | 0.44              |
|  WebText2              | 190 亿 Token    | 22%            | 3.47              |
|  Books1 (未公开书籍)   | 120 亿 Token    | 8%             | 2.00              |
|  Books2 (未公开书籍)   | 550 亿 Token    | 8%             | 0.44              |
|  Wikipedia (维基百科)  | 30 亿 Token     | 3%             | 3.00              |
+------------------------+-----------------+----------------+-------------------+
```
上表展示了 GPT-3 技术报告披露的数据集多源混合配比与差异化的重采样训练强度。

GPT-3 在清洗 Common Crawl 时，摒弃了纯手工规则，回归并升级了分类器路线：
- 选用高质量的 WebText 作为正样本，选取未经处理的原始 Common Crawl 页面作为负样本；
- 训练了一个轻量级的 Logistic Regression 分类器，基于文本的词频特征与统计指标计算正样本概率分数；
- 只有得分超过设定阈值的 Common Crawl 页面才被准许纳入语料库，同时配合 MinHash LSH（局部敏感哈希）算法执行激进的模糊去重（Fuzzy Deduplication），彻底清除了 WebText 与网络抓取之间的重叠内容。

**The Pile（2020）**：由开源研究组织 EleutherAI 发起的一场草根技术运动。来自全球的独立研究者在 Discord 频道上日夜协同，旨在打破大型商业科技巨头对顶级预训练数据的垄断。
- 他们构建了一个包含 **22 个专门领域子集、解压体量达 825 GB** 的全开源综合语料库。
- 其内容构成极度多元：除了常规的 Common Crawl、维基百科与 GitHub 之外，还纳入了 PubMed 生物医学文献库、arXiv 论文、美国联邦法院诉讼判例库（FreeLaw）、USPTO 专利局文档、Stack Exchange 问答社区、哲学论文（PhilPapers）、黑客新闻（Hacker News）、IRC 聊天记录，甚至是 **Enron（安然公司）破产事件中被司法解密的几十万封内部员工电子邮件**。
- **历史悲剧 Books3**：在书籍语料部分，The Pile 除了收录早已进入公有领域的 Project Gutenberg（古登堡计划，PG-19 数据集）之外，还赫然列入了一个名为 **Books3** 的子集。Books3 直接打包了从知名影子图书馆 Bibliotik 抓取的 **20 万本受版权保护的当代畅销书**。在 2020 年这并未引起波澜，但随后它被诸多商业模型不加甄别地吸纳，最终引爆了席卷全行业的版权诉讼风暴。

#### 开源复现期：LLaMA-1 配方公开与 RefinedWeb / FineWeb 纯网页探索

**LLaMA-1（2023）**：Meta 发布的 LLaMA-1 是一座真正的历史分水岭——它是前沿实验室在技术报告中**最后一次详尽、透明地向全世界公开其预训练数据的完整配方与清洗细节**。
- 其 1.4 万亿（1.4T）token 的配方堪称当时工业界工程实践的集大成者：
  - **Common Crawl（67%）**：使用 CCNet 流水线清洗，但做了一项极具洞见的改进——在训练质量分类器时，他们放弃了“让文本看起来像维基百科条目”的传统做法，转而**训练分类器判断候选网页是否被维基百科作为参考文献（References）所引用**。因为维基条目本身的百科文风过于刻板雕琢，而维基引用的外部参考网站既具备极高的事实权威性，又保留了鲜活自然的叙事文风。
  - **C4（15%）**：直接吸纳经过清洗的 C4 语料以提供通用泛化。
  - **GitHub（4.5%）**：对公开仓库实施严格的许可证过滤（仅保留 MIT/Apache），剔除代码量小于特定行的文件。
  - **Wikipedia（4.5%）**：覆盖全球 20 种主流语言。
  - **Books（4.5%）**：混合了古登堡计划与致命的 Books3。
  - **arXiv（2.5%）**：深度解析 LaTeX 源码。
  - **Stack Exchange（2%）**：涵盖最活跃的 28 个技术问答站点。
- 该配方公开后，Together AI 迅速在开源社区推出了 100% 对应的像素级复现项目 **RedPajama-V1**。在意识到法律风险后，社区在后续版本中迅速将 Books3 剔除，反映出司法合规对技术选型的深远反噬。

**RefinedWeb（Falcon，2023）与 FineWeb（Hugging Face，2024）**：这两项工作探索了一个大胆的反向假说：**如果完全抛弃所有专门的数据集（不收录 GitHub、不收录 arXiv、不收录书籍），仅仅依赖通用网络爬虫，到底能不能训出顶尖模型？**
- 阿布扎比技术创新研究所（TII）在研发 Falcon 模型时，开发了 **RefinedWeb** 数据集。
- 他们认为过度依赖机器学习分类器会导致严重的归纳偏置（Inductive Bias），使保留下来的网页同质化严重。因此，他们使用 Trafilatura 进行严谨的正文提取，严格复用 Gopher 的人工规则进行硬性指标过滤，并施加了工业界最严密的 MinHash 局部敏感哈希去重。最终仅凭从网络抓取的 **5 万亿 token** 语料，便让模型超越了诸多混合语料训练的竞争者。
- Hugging Face 在 2024 年将这一路线推向极致，发布了 **FineWeb**。他们调动海量集群，重新处理了 Common Crawl 自 2013 年至 2024 年间的整整 **96 个历史转储**，同样坚持采用透明可控的启发式规则配合全网去重与 PII（个人敏感信息）擦除，最终提炼出高达 **15 万亿 token** 的高质量纯网页语料。

#### 模型过滤与合成增强期：DCLM 极限制与 Nemotron 教育分类重写

**DataComp-LM（DCLM，2024）**：如果说 RefinedWeb 代表了规则派的巅峰，那么 DCLM 的问世则彻底标志着**基于模型的质量打分正式登顶全行业的黄金标准**。
- DCLM 的初衷是为数据工程建立一套标准化评测基准。他们先从 Common Crawl 提取出一个未经过滤的超大规模原始池——**DCLM-pool，总计高达 240 万亿原始 token（240T raw tokens）**！
- 面对如此庞大的语料池，DCLM 采用了一套极其决绝的过滤管线：基础启发式规则预筛 $\to$ MinHash 模糊去重 $\to$ **基于紧凑模型（如 fastText）的深度质量分类过滤**。
- 分类器的正负样本构建极为精巧：
  - **正样本**：选用由 GPT-4 生成的顶级合成指令数据集 **OpenHermes-2.5**，以及 Reddit 上充满逻辑推理解释的高质量问答板块 **ELI5（Explain Like I'm 5）**。
  - **负样本**：直接从 RefinedWeb 的通用网页中随机均匀采样。
- 利用这个分类器对 240T 数据进行地毯式推断后，DCLM 实施了极度激进的截断阈值——**仅仅保留了得分最高的 1.4% 顶级语料（约 3.8 万亿 token，即 DCLM-baseline）**，直接扔掉了其余 98.6% 的劣质文本！
- 实验结果震惊了学术界：仅仅在这个 1.4% 的子集上训练模型，其在各类下游核心评测基准上的得分全面击溃了之前所有开源主流数据集。

**Nemotron-4 预训练语料（NVIDIA，2024）**：NVIDIA 认可 DCLM 模型过滤的威力，但尖锐地指出了其工业落地局限：**过滤太激进了**。
- 当大模型的算力预算攀升至数万张 H100 时，根据缩放定律，现代基座模型需要消耗至少 15T（如 Llama 3）乃至 36T token（如 Qwen 2.5）的数据。DCLM 把数据筛到只剩 3.8T，如果强行多跑几个 epoch，模型很容易陷入过拟合的性能瓶颈。
- NVIDIA 的破局之道是引入**大模型提示打分（LLM-as-a-Judge）与大规模合成数据注入（Synthetic Data）**：
  1. **教育价值分类器**：利用能力强大的通用 LLM 进行 Prompt 引导，直接让大模型对抓取网页的“教育价值（Educational Value）”进行 1 到 5 分的细粒度打分；随后收集数万个带标签样本，蒸馏训练一个极速的 fastText 打分分类器。
  2. **边界样本重写提纯**：对于那些事实丰富但文风粗糙的低质量网页文档，不再一扔了之，而是**调用语言模型将其重新表述（Rewrite），重写成符合维基百科客观严谨风格的高密度知识文本**。
  3. **优质样本合成扩展**：对于被判定为高度优质的文档，调用模型围绕其内容自动合成衍生任务——生成成套的多跳问答对（QA Pairs）、总结抽取任务或深度思考推理链。

最终，NVIDIA 构建了一个包含 **6 万亿高密度 token** 的高质量预训练语料库，在同等 token 吞吐下取得了大幅超越常规开源语料的性能跃升。

> **易错点**：在研读各大机构的技术报告时，必须高度警惕 **Token 计数口径的陷阱**。论文中宣称的“在 6T 或 15T token 上训练”，往往并不代表该数据集拥有等额的独立非重复文本。在分布式训练实践中，如果数据集被执行了 2 个轮次（2 Epochs）的重复遍历，论文披露的训练 token 吞吐就会直接翻倍计算。评估真实语料库的信息熵时，必须看去重后的独立 token 规模。

### 代码语料工程与结构化线性化处理

代码正在彻底重塑大语言模型的底层认知。代码数据集不仅要求极高的词法严谨性，其在工程处理上面临着远比普通自然语言复杂的结构化挑战。

```text
+-------------------------------------------------------------------------------+
|                       代码语料工程与中间表示/PR线性化                         |
+-------------------------------------------------------------------------------+
|                                                                               |
|  [ 1. 跨语言语义对齐: LLVM IR 中间表示映射 ]                                  |
|                                                                               |
|      高资源语言 (Python, C) ──编译──► [ LLVM IR 中间表示 ] ◄──编译── 低资源语言 (Nim)
|                                            │                                  |
|                                            ▼                                  |
|                      [ 模型通过对齐的低级表示学会冷门语言语法映射 ]           |
|                                                                               |
|                                                                               |
|  [ 2. Pull Request 结构化线性化流 ]                                            |
|                                                                               |
|      <issue> ──► <pr> ──► <diff context="+/- 3 lines"> ──► <review_comment>   |
|                                                                               |
|      [ 结构化 XML-like 标记 ]: 赋予模型理解真实团队软件工程协同演进的动态全貌 |
|                                                                               |
+-------------------------------------------------------------------------------+
```
上图展示了代码数据工程中的两大关键技术：利用 LLVM IR 编译器中间表示实现跨语言低资源泛化，以及将树状非线性的 Git PR 与代码审查重构为线性序列的序列化协议。

#### The Stack 代码清洗与 LLVM 中间表示跨语言对齐

BigCode 项目（由 Hugging Face 与 ServiceNow 联合主导）构建的 **The Stack** 系列，代表了当前开源代码语料库的最高工业水准：
- **The Stack v1（2022）**：扫描了 37 亿个文件，严格基于宽松许可过滤出包含 358 种编程语言、体量达 **3 TB 的高纯度代码库**，并实施了极度严密的近重复文件（Near-duplicate）模糊去重。
- **The Stack v2（2024）**：数据体量暴增至 **67 TB**。其核心飞跃是深度融合了 Software Heritage 的全量底座，同时全面抓取了技术官方文档、GitHub Issue 讨论帖与 Pull Request（PR）流水线。

在清洗这数十 TB 的庞然大物时，必须执行一系列特殊的代码管道算子：
- **机器产物剔除**：精准检测并剔除混杂在仓库中的二进制编译产物、十六进制转储、自动生成的最小化压缩脚本（Minified JS）以及潜在的恶意加密货币挖矿代码。
- **机器人过滤与 PII 脱敏**：GitHub 上的海量 PR 和自动化检查都是由 CI/CD 机器人批量发布的模板垃圾，必须坚决过滤；同时利用正则与专用模型对代码中硬编码的私钥、API Token 与个人隐私（PII）进行全局脱敏。
- **低资源编程语言的 LLVM IR 跨语言迁移**：在开源世界中，Python、JavaScript、C/C++ 的代码量呈现压倒性的绝对优势，而像 Nim、OCaml 这类小众的低资源语言，其公开代码样本极度匮乏。为了让模型攻坚这些冷门语言，The Stack v2 设计了一套极其惊艳的**编译器中间表示对齐机制**：
  - 许多现代编译型语言都可以通过其前端编译器统一编译并降维到通用的**低级中间表示（LLVM Intermediate Representation, LLVM IR）**；
  - 工程师将编译生成的 LLVM IR 文本，与源语言的代码片段在数据流中并排拼装、交叉呈现；
  - 模型由此能够利用在庞大的 C/C++ 语料上建立起来的深层指令理解，以 LLVM IR 为通用语义桥梁，快速掌握低资源语言的抽象语法映射逻辑！

#### Pull Request 结构化线性化协议与上下文设计

如果只让模型阅读静态的代码仓库快照，模型顶多学会“根据函数签名补全代码片段”；但软件开发的终极常态是**在现有复杂巨型工程之上进行迭代修改、审查与排错**。因此，将 GitHub 动态的 Pull Request 与代码审查流引入预训练至关重要。

然而，Git PR 本质上是一个非线性的复杂有向无环图（DAG），它包含由时间戳驱动的代码改动差异（Diffs）、评审者的行级行间批注（Inline Comments）、全量会话讨论以及多轮补丁提交（Rebase & Commits）。要将这一非线性图结构喂给自回归模型，必须执行**结构化线性化协议（Linearization Protocol）**：
1. **语义标签化包覆**：使用类似 XML 的结构化特殊 token 对事件流进行显式标记，例如 `<issue>`、`<pr>`、`<diff>`、`<review>`、`<comment>`；
2. **上下文窗口工程抉择**：当某次 PR 仅仅修改了一行代码时，如果只把这一行 diff 喂给模型，模型将完全丢失语义依赖；但如果把整个文件的数千行代码全部填入，又会造成巨大的上下文冗余。工程团队必须在局部窗口大小（如变更行前后各截取 $\pm 3$ 行）、函数作用域截断与全文件包裹之间进行严密的权衡取舍；
3. **协作元数据感知**：在序列中保留审查时间戳、审查人是否批准（Approved / Changes Requested）等状态标识。

通过这种深度线性化的语料训练，模型不仅能理解一段静态代码在计算机内存中如何运行，更能深谙整套软件开发生命周期的协作心智模型。

### 严格合规语料探索与预训练数据总结

随着全球针对 AI 训练侵权的司法审查日益收紧，商业界分化出了一种走向极度防御性的技术流派：**如果我们对任何法律灰产彻底零容忍，仅仅使用绝对具有法律确定性的纯宽松授权语料，到底能把大语言模型推向什么高度？**

#### Common Pile 宽松授权实践与许可清洗陷阱

项目 **Common Pile** 正是这种极端合规主义哲学的代表作。该项目的核心铁律是：**只要某项数据在法律合规性上存在任何一丝疑虑，就立刻视为不可用**。

Common Pile 团队地毯式排查了全网的所有开源域，拼凑出了一个完全基于公有领域和宽松许可的语料池：
- 涵盖 The Stack v2 中的纯宽松协议代码；
- 全球多国政府公开发布的非保密公共事务报告与法律文书（绝大多数政府出版物天然属于公有领域）；
- 具有清晰知识共享协议（CC 许可）的学术预印本、教学讲义与维基类站点；
- 公共领域的古登堡计划历史藏书与开放教育资源（OER）。

最终，团队构建了一个总计 **8 TB 的纯净语料库**。然而在推进过程中，团队发现了开源世界中极其触目惊心的**三大法律陷阱**：
1. **许可清洗（License Washing）**：网络上存在大量蓄意造假行为。某些用户下载了受严格版权保护的专有作品，抹去原作者信息，公然贴上一个 CC-BY 或 MIT 开源许可证并上传到公开网络。仅凭网页上展示的开源标签，根本无法保证其具有真实法律效力。
2. **集合许可与单体作品许可的脱节（Collection vs. Document Licensing）**：典型代表是 AI2 发布的 Dolma 数据集。作为一个打包分发的整体数据集，AI2 可以为其申明一个宽松的开源分发协议；但这绝对**不代表该数据集中包含的每一个独立网页或每一篇爬取文章都在单体层面具备宽松授权**。大量在 Hugging Face 上标榜为“宽松许可”的数据集，一旦深入底层排查单个文件的原始出处，侵权隐患触目惊心。
3. **合成数据的服务条款连环违约**：Common Pile 坚决排除了所有由商业前沿模型（如 GPT-4）生成的合成数据。因为根据 OpenAI 等公司的商用服务条款（ToS），利用其模型输出训练竞争性商用模型的行为受到严格限制，且合成数据本身在多国法律体系下的著作权归属至今悬而未决。使用未授权模型输出的合成数据，本质上也是一种对上游未经授权语料的“数据洗白（Data Laundering）”。

> **结论**：实验表明，仅使用这 8 TB 严苛合规数据训练出的模型，其性能表现尚可（能够超越早期的初代 LLaMA 或 MPT-7B 等早期模型）；但在与 Qwen、Llama 3 等吞吐了数十万亿 token 的前沿主流模型正面对决时，依然存在明显的代际差距。这表明：**在当前的技术范式下，如果无法突破绝对宽松授权的 token 总量天花板，大语言模型的智能涌现依然受到纯粹规模法则的强力压制**。

#### 经验驱动的数据工程方法论

回顾这一讲关于数据来源、法律准入与清洗配方的全貌，我们可以提炼出大语言模型预训练数据工程的几条核心结论：

第一，**数据是塑造语言模型的首要决定性要素**。在当今时代，主流前沿模型的底层骨架基本高度收敛于基于标准 Transformer 的细微变体（如 RoPE、RMSNorm、SwiGLU），架构创新的边际收益正在急剧收窄；而各大实验室之间模型能力的真正分野，十之八九取决于其**未公开的数据配比策略、清洗过滤深度与合成数据合成技法**。

第二，**数据工程是一门深度依赖经验与实证的系统工程**。与模型并行切分、算子内核加速以及缩放定律等具有坚实第一性原理推导的数学系统不同，数据工程充满了脏乱差的现实妥协与工程直觉。你搭建一条包含数十个算子的清洗管线，反复校准 fastText 的判断阈值，设计一条条看似琐碎的正则表达式，其优劣完全取决于最终模型在下游基准上的实测反馈。

第三，**过滤提纯是决定模型智力密度的重中之重**。如何利用启发式规则与小模型协同，从 200 万亿原始网络 token 中无情地砍掉 98% 以上的低质冗余，精准淬炼出数万亿最具逻辑密度的黄金语料，是每一位大模型工程师必须掌握的看家本领。

在后续的课程中，我们将进一步推进到后训练（Post-training）的数据准备中，并深度拆解更高阶的模型过滤与对齐实战。大家在开展作业四（Assignment 4）的数据工程实践时，务必深入思考这些设计权衡，探索出更加卓越的数据提纯新方案。

## 预训练与后训练数据处理流水线
> 对应块：BLK34 | 覆盖分集：P32 | 块标题（分集名）：《Lecture 14： Data》

今天是数据系列的第二天。上次咱们聊过，数据可不是天上掉下来的。你得仔细琢磨琢磨，数据究竟从哪里来：互联网本质上是由各种实时在线服务构成的，我们需要把这些服务里的数据抓取或导出，并进行一套极其复杂的工程处理。上一讲我们讨论了版权、服务条款（ToS）与合理使用原则（Fair Use）等法律与社会层面的考量，而今天我们要聚焦的是核心的工程生命线——数据处理流水线（Data Processing Pipeline）。

整个预训练语料的处理流水线主要包含四大核心环节：数据转换（Transformation）、质量过滤（Filtering）、语料去重（Deduplication）以及多源数据混合（Data Mixing）。在后半部分，我们还会探讨当前大语言模型进入后训练（Post-training）阶段时，如何摆脱昂贵的人工标注，利用强大的教师模型构建高质量的合成数据，以及如何在复杂的软件工程任务中实现环境解耦。

```text
原始网络抓取 (Common Crawl / GitHub / PDF)
                   │
                   ▼
       [ 数据转换 (Transformation) ]
         - HTML 正文提取 / 结构线性化
         - PDF 多模态 OCR / 文本渲染
                   │
                   ▼
         [ 数据过滤 (Filtering) ]
         - 语言识别 (fastText 176语言)
         - 启发式规则 (LaTeX 语法校验)
         - 轻量分类器 (KenLM / fastText / 随机森林)
                   │
                   ▼
         [ 数据去重 (Deduplication) ]
         - 精确匹配 (哈希查重 / 跨度过滤)
         - 模糊匹配 (MinHash + LSH 分带相变)
                   │
                   ▼
        [ 多源数据混合 (Data Mixing) ]
         - 比例约束 (UniMax 轮次上限)
         - 代理模型预测 (RegMix / AutoMix 回归)
                   │
                   ▼
         通用基座预训练语料池
```
> **说明**：数据处理流水线是一个逐级淘洗、大幅收敛的漏斗过程。原始多模态互联网数据经由格式线性化转换、多阶段模型质量过滤、线性时间哈希去重以及回归优化的配比混合，最终提炼出高质量的通用语言模型预训练语料。

### 原始多模态载体转换与正文抽取

很多人以为拿到 Common Crawl 就等于拿到了现成的海量文本。但只要你真正解开过 Common Crawl 的数据包就会发现，里面根本不是清洗好的自然语言，绝大多数是原始网页 HTML 文件；有时链接没有明确后缀，下载下来才发现是 PDF；如果是 GitHub 抓取的数据，则是一个个多层嵌套的文件目录树。因此，数据处理流水线的第一道工序，必须是将这些异构载体提取并线性化转换为纯文本序列。

#### 网页内容界定与 HTML 结构线性化

互联网上绝大多数公开数据都是 HTML。在处理 HTML 时，许多方法极度依赖经验法则。第一个摆在我们面前的哲学与工程问题是：到底什么才算网页的“正文内容”？

通常的清洗流程会无差别地删除页眉（Header）、页脚（Footer）、导航菜单（Navigation Bar）以及嵌入广告，只盯着正文主体内容进行提取。然而，内容与噪声之间的界限往往非常模糊。在某些特定网站中，部分导航元素和分类层级反而有助于模型理解网页的整体主题与逻辑布局；一旦简单粗暴地剔除，上下文信息就会断裂。

更本质的挑战在于，HTML 转换本质上是一个有损的投影过程。HTML 是层级嵌套的树状 DOM 结构，在浏览器端呈现为二维可视化的排版界面。然而，自回归语言模型要求输入必须是单一维度的一维 Token 序列。这种从二维层级到一维序列的线性化过程必然伴随着结构损失：
1. **多媒体元素**：嵌入在正文中的图片通常只能被舍弃，或者退化为图片的 `alt` 占位标签。
2. **结构化表格**：简单表格尚且可以用 Markdown 语法较为工整地表达；但面对跨行跨列合并（`rowspan`/`colspan`）或深层嵌套的复杂表格，目前的线性化处理手段无论如何都会破坏原有的结构语义，必须在信息丢失与格式失真之间做出妥协。

#### 基于规则与模型的抽取工具对比

在海量网页的处理中，抽取工具的执行效率是生命线。目前工业界绝大多数正文提取工具仍基于预设规则开发，其核心原因在于基于规则的方法运行速度极快，且在正文提取这一任务上并不需要极其高深的语义智能。

然而，规则解析难免存在盲区。由于全球网页编写规范参差不齐，基于规则的提取器经常出现提取出半截正文、漏掉关键段落或掺入未渲染脚本代码的瑕疵。在针对数据清洗的大规模评测（如扩展的 DCLM，DataComp for Language Models 基准评估）中，学术界对主流正文抽取工具进行了系统性比对。实测表明，高性能 C++ 抽取库 Resiliparse 的清洗质量与下游模型训练表现全面优于被广泛使用的 Python 工具 Trafilatura 及其他规则库。

| 抽取方案 | 核心实现机制 | 吞吐速度与资源开销 | 结构抽取质量 | 工业落地局限 |
| :--- | :--- | :--- | :--- | :--- |
| **Resiliparse** | 基于 C++ 底层的高性能 DOM 树解析与文本块密度判定 | 极高（单核数千页面/秒，资源占用低） | 优秀；正文边界切分干净，保留度高 | 面对极端非规范前端排版时仍有漏抽现象 |
| **Trafilatura** | Python 规则引擎结合正文与标签密度启发式算法 | 中等（单核数十至数百页面/秒） | 良好；对新闻、博客等长文本提取较稳 | 处理数万亿 Token 时吞吐瓶颈明显 |
| **轻量模型方法** | 结合视觉排版分析与小规模分类模型进行边界判定 | 较低（需专用推理算力支持） | 极高；能够精准分辨视觉可见正文与广告 | 计算成本高昂，全网数据扫描难以全面承受 |

> **提示**：目前在大规模数据处理中，虽然轻量级神经网络模型抽取正文是未来演进方向，但在面对全网数十万亿 Token 的前置清洗时，兼具极致吞吐与高召回率的 Resiliparse 是兼顾成本与精度的最优选择。

#### PDF 文档解析与视觉多模态处理

PDF 是互联网上另一类重要但极难处理的非结构化载体。Common Crawl 的抓取爬虫遇到无后缀链接时，往往在下载后才发现目标是 PDF 文件；此外，由于 Common Crawl 存在单文件体积截断限制，许多大型 PDF 文件被截断损坏，迫使工程师必须单独编写重抓脚本。近期 Hugging Face 发布的 FinePDFs 数据集，就是专门针对全网高质量 PDF 进行系统性重抓与提取的代表作。

PDF 文件的解析成本与难度远高于普通 HTML 网页：
- **扫描件与图片载体**：互联网中相当大比例的 PDF 是扫描复印件，底层完全没有文本字符流，本质就是位图图像。要提取其中的文字，必须依赖多模态视觉语言模型（VLM）进行光学字符识别（OCR）与排版理解。这相较于纯文本解析，计算成本直接飙升数个数量级。
- **排版语义丢失**：HTML 原生具备 `<h1>`、`<p>`、`<table>` 等显式语义标签；而在 PDF 中，所有排版信息都被打散为二维坐标上的字符片段，分栏排版的论文极易出现跨栏乱串的错读。

> **结论**：尽管 PDF 仅占互联网总数据量的一小部分，但其平均质量显著高于普通 HTML 网页。因为制作、排版并公开发布一份 PDF（如学术论文、行业报告、技术白皮书、法律卷宗），通常意味着作者付出了极高的人工整理成本。这种天然的高质量属性使得高昂的 OCR 清洗成本物有所值。

### 语料质量与毒性分类过滤

从原始载体提取出纯文本后，流水线绝不能直接将文本送入训练集群。如果直接训练未经清洗的数据，模型不仅会在充满噪音与语法错误的语料上白白浪费昂贵的算力，还会学到大量有害内容。过滤环节的目标，是在保留高质量有效信息的同时，剔除绝大部分低价值数据。

#### 目标数据驱动的分类器过滤框架

几乎所有现代数据过滤流水线都可以抽象为一个统一的形式化数学框架：

```text
原始未过滤语料池 R ─────────────┐
(海量、低信噪比、10万亿 Token)    │
                                 ├──> [ 训练轻量判别模型 / 估计生成概率分布 ]
黄金目标数据集 T ────────────────┘
(小规模、高质量、维基百科/精选教材)
                                 │
                                 ▼
                    全量扫描原始语料计算评分
                                 │
                                 ▼
                     评分超过阈值保留，其余丢弃
                                 │
                                 ▼
                     最终高质量训练子集 (占 R 的个位数百分比)
```
> **说明**：给定海量原始语料集合 $R$ 与极小规模的黄金目标集合 $T$，过滤算法通过建立评分机制对 $R$ 中的每个文档打分，保留与 $T$ 的质量分布相似的高分子集。

对用于全量过滤的算法有两项不可动摇的严苛要求：
1. **高效的泛化能力**：算法不能死记硬背目标集 $T$ 的具体内容，必须能够抽象并泛化出高质量文本的共性特征。
2. **极高的推断吞吐**：该算法必须在全网数十万亿 Token 上完整执行一遍。由于数据规模极为庞大，过滤后保留下来的子集通常仅占原始数据总量的个位数百分比（例如 1% 至 5%）。

#### 基于生成模型与判别分类器的轻量过滤

在具体的模型选型上，工业界主要分为生成式模型与判别式分类器两大流派：

1. **生成式语言模型（困惑度过滤）**：
   直接在目标集 $T$ 上训练一个小规模生成式模型，随后用该模型评估原始集 $R$ 中候选文档的困惑度（Perplexity, PPL）。若某篇文档的困惑度低于设定阈值，说明该文档在词法与句法上与高质量目标高度契合，予以保留。这一流派最经典的工具是 KenLM（通常训练五元语法 5-gram 模型），其评估速度极快，且不需要大型神经网络推理。
2. **判别式快速分类器（二分类打分）**：
   将高质量目标集 $T$ 作为正样本标签，同时从原始数据池 $R$ 中随机下采样一部分作为负样本标签。在二者样本平衡后，训练一个高吞吐的线性分类器（最常用的是基于词袋模型的 fastText，有时也采用浅层随机森林）。训练完成后，分类器对 $R$ 中的每一个新文档输出一个连续质量得分，流水线根据预设阈值或拒绝采样概率进行筛选。

在基础属性过滤层面，语言识别（Language Identification, LID）同样基于这套判别分类思路。例如 Meta 开源的 fastText 语言识别模型，支持 176 种语言，训练数据覆盖维基百科、专业翻译网站与特定语种专属站点。对于西班牙语或日语这类特征鲜明的语种，简单的词袋分类器仅看几个词就能实现极高精度的判别；但在多语言混杂（语码转换）或方言口语场景中依然存在边缘模糊。不过总的来说，语言识别已非常成熟，并不是限制大模型预训练质量的核心瓶颈。

#### 领域专用语料筛选与教育价值评估

“质量”在预训练中从来没有单一不变的定义。质量取决于你希望模型具备什么样的核心能力。如果你的目标是让模型精通数学推理，那么富含严密逻辑的数学数据就是高质量数据。

2023 年发表的 OpenWebMath 论文提供了一套构建大规模高质量数学语料的经典范例。它并不是依赖单一分类器，而是组合了多阶段级联流水线：
- **第一阶段（规则过滤）**：快速扫描文本，检查是否包含 LaTeX 数学命令与特定的排版标记，直接剔除无数学符号的普通页面。
- **第二阶段（生成式困惑度过滤）**：在公认的高质量数学专业数据集 Proof-Pile 上训练 KenLM 五元语法模型，过滤掉困惑度过高的页面。
- **第三阶段（判别式分类器）**：训练一个专门判别数学写作风格的 fastText 分类器进行最终甄别。

OpenWebMath 最终提炼出了 150 亿（15B）Token 的精选数学语料。实验结果表明，在同等参数量下，仅使用这 150 亿 Token 训练出的模型，其数学解题能力远胜于在未经严格过滤、数据量大 20 倍（3000 亿 Token）的原始语料上训练出的模型。

在通用预训练领域，正负样本的定义同样不断演进：
- **GPT-3**：将维基百科与 Reddit 上获得 3 个以上赞成票的外部链接抓取内容（WebText）作为正样本，训练逻辑回归分类器筛选 Common Crawl。
- **LLaMA**：在界定正样本时，不仅使用维基百科本身，还进一步将维基百科引用的外部参考文献页面纳入正样本集合，极大地扩展了高质量学术与事实性语料的覆盖面。
- **Phi-1（Textbooks Are All You Need）**：微软在清洗代码数据时采用了一种颠覆性的分层级联策略。他们不预先人工指定正负样本，而是定义了一个评估代码是否具备“教育价值”（Educational Value，即是否像教科书一样包含详尽注释、清晰算法逻辑与高信噪比）的提示词（Prompt）。首先调用昂贵的 GPT-4 对 10 万个样本构成的代码子集进行打分分类；接着，以 GPT-4 的打分作为黄金标签，训练一个运行极快的随机森林（或 fastText）轻量分类器，并将该轻量分类器推断应用到全量代码库中。这种高能力模型小规模蒸馏到轻量分类器的级联打法，使模型以极少的训练步数和极小的参数规模达到了惊人的代码生成水平。

#### 训练计算预算与质量阈值权衡

分类器给出的质量得分是一个连续值，很多工程师常犯的直觉错误是：既然 0.9 分比 0.7 分质量更高，那我是不是永远应该把保留阈值定在 0.9 以上？

> **结论**：预训练语料不存在绝对通用的“最优过滤阈值”。最优阈值完全取决于你计划训练的总 Token 数量与计算预算。

Michael Ryan 在一项针对 1.57 亿参数模型的严谨对照实验中揭示了这一核心规律。实验选用 Common Crawl 中极小的固定数据池（100 个分片），比对经由严格高质量过滤的数据集（DCLM）与基本未经过滤的原始提取数据集（Resiliparse 清洗版本）在不同训练周期的表现：

```text
训练损失 (Loss)
  │
  │   Resiliparse (低过滤/海量数据)
  │   ───────────────────────────────\
  │                                   \
  │   DCLM (高过滤/精品数据)            \
  │   ───────────\                       \  持续遍历未见过数据，损失稳步下行
  │               \                       \
  │   快速下降     \   出现多 Epoch 重复    \──────> 最终超越多轮过拟合的高质量数据
  │                \   开始严重过拟合       /
  │                 \──────/\──────/\─────/
  │
  └──────────────────────────────────────────────────────── Token 训练步数
```
> **说明**：在较短训练步数下，高阈值清洗的精品数据（DCLM）能带来极快的损失下降；但当训练 Token 预算远超精品语料库容时，模型被迫进行多轮次（Multi-epoch）重复学习导致严重过拟合，而未严格过滤但体量庞大的数据由于持续提供未见过的新 Token，最终在超长训练步数下取得更好的收敛效果。

这一实验揭示了深刻的工程权衡：
1. **短周期训练 / 算力受限**：若分配给预训练的 Token 预算较小，必须选用极高阈值过滤出的精品数据，让模型在宝贵的有限步数内尽可能接触高密度信息。
2. **长周期训练 / 超大规模预算**：若拥有海量的 GPU 预算（如计划训练数十万亿 Token），就不能把质量阈值卡得过死。如果阈值过高导致留存的数据池过小，模型在训练中就会被迫重复跑数个甚至数十个轮次（Epoch），过早陷入灾难性过拟合；此时必须适度放宽阈值，引入更多略显平庸但具备多样性且未被遍历过的新数据。

> **提示**：在预训练实验设计中，许多人会纠结是否需要多次重复实验以绘制置信区间。实际上，由于预训练单次运行成本极其昂贵，学术界通常仅汇报单次大模型训练指标；实测经验表明，在大规模预训练阶段，数据分布引起的损失轨迹通常高度稳定。

### 海量语料去重与去污染

即便经过了层层质量过滤，语料库中依然残存着海量的重复内容。重复数据不仅浪费宝贵的计算资源，更是引发模型合规风险与记忆性缺陷的元凶。

#### 重复文本类型与完全去重

网络语料中的重复内容主要分为两大形态：
- **完全重复（Exact Duplicates）**：内容字符完全一致。最典型的来源是镜像网站（Mirror Sites）、网络爬虫因链接重定向重复抓取的同一页面，以及开发者在 GitHub 上对热门代码仓库的 Fork。在 GitHub 场景下，用户 Fork 仓库后往往只修改了一两个文件，其余 99% 的代码文件都是完全一致的克隆体。
- **近似重复（Near Duplicates）**：文本主干高度雷同，仅在极少数 Token 或局部实体上存在差异。例如广泛散布在全网开源项目中的 MIT 许可证协议文本、网站通用的隐私条款与服务条款（Terms of Service）、全站统一的页眉页脚、仅仅因为拼写习惯产生的一个逗号排版差异，或者是垃圾营销号使用相同模板仅仅将地名“加拿大”批量替换为“美国”的泛滥广告。

对预训练数据进行严格审计往往会发现令人震惊的极端案例。例如在对 Google 著名的 C4 数据集进行的事后审计中，研究人员发现一段完全相同的某款防毒面具产品描述，在整个数据集中竟然原封不动地出现了整整 61,000 次。如果未经去重，GPU 算力就会被这类毫无信息增量的工业噪声大量吞噬。

去重不仅能有效压缩数据集体量、节约训练算力，还能大幅降低模型死记硬背（Memorization）训练数据的倾向，缓解针对个人敏感信息或受版权保护文本的隐私泄露隐患。而与去重一脉相承的“去污染（Decontamination）”工程，核心逻辑同样在于利用去重算法，严格确保各类权威评测基准（如 GSM8k、MMLU、HumanEval）的测试集样本没有渗漏进预训练语料中。

在工程实现上，完全重复的处理相对直接：
- 利用非密码学哈希函数（如 64 位 MurmurHash 等高吞吐哈希），将文档或段落映射为定长哈希值。
- 采用 MapReduce 风格的分布式架构，按哈希键进行分组查重，仅保留一份唯一实例，剔除其余全部冗余。

在早期 T5 论文清洗 C4 数据集时，研究人员采用了一种针对连续三个句子跨度（Three-sentence span）的精确匹配去重逻辑：只要发现任意三句连续文本在全局语料中出现过，就直接将这三句话从原文档中剔除。这种做法虽然极端，但存在明显的副作用——直接从文档中间抠掉三句话会彻底割裂上下文语流，严重破坏语言模型的长程连贯性建模能力。

#### 集合相似度与最小哈希估计

面对现实中占绝大多数的近似重复，精确匹配完全无能为力。如果对数以百亿计的文档进行两两相似度比对，时间复杂度将达到灾难性的 $O(n^2)$。在十万亿 Token 的网络规模下，两两比对在计算上是绝对不可行的，必须设计出复杂度为 $O(n)$ 的线性时间近似检索算法。

界定两篇文档近似程度的经典度量指标是 Jaccard 相似度（Jaccard Similarity）。设将文档切分为词项集合或连续 $k$-shingle 集合，记为集合 $A$ 与集合 $B$：

$$J(A, B) = \frac{|A \cap B|}{|A \cup B|}$$

Jaccard 系数取值介于 0 到 1 之间，0 表示两篇文档毫无交集，1 表示完全一致。当两篇文档的 Jaccard 相似度超过设定的阈值（例如 0.8 或 0.9）时，即可判定为近似重复。

为了以线性时间复杂度估计 Jaccard 相似度，理论计算机科学提出了极具巧思的最小哈希（MinHash）算法。通常的哈希函数设计追求零冲突，而 MinHash 却反其道而行之，刻意构造一种受控的哈希碰撞机制，使其碰撞概率的数学期望恰好严格等于两个集合的 Jaccard 相似度：

$$\Pr[h_{\min}(A) = h_{\min}(B)] = J(A, B)$$

```text
唯一元素全集    集合 A (文档1)    集合 B (文档2)    随机排列 π
─────────────────────────────────────────────────────────────
   token_1            1                1              4
   token_2            1                1              3
   token_3            1                1              1  <-- 首个非零命中行 (A与B均为1)
   token_4            1                0              5
   token_5            0                1              2
─────────────────────────────────────────────────────────────
推导过程：
1. 随机哈希函数 h 本质上等价于对所有行诱导出一个完全随机的排列 π。
2. 从排列首行向下扫描，双方均为 0 的行毫无意义；双方至少有一方为 1 的行构成并集 A ∪ B。
3. 首次遇到非零行时，该行元素使 A 和 B 的哈希值同时取到最小值。
4. 该行同时属于 A 和 B（即双方均为 1，属于交集 A ∩ B）的概率，精确等于 |A ∩ B| / |A ∪ B|。
```
> **说明**：MinHash 证明了通过对集合内元素取哈希极小值，单次哈希碰撞的理论概率与集合的 Jaccard 相似度完全等价。

在单机验证脚本中，若对两个 Jaccard 相似度精确为 0.6 的集合生成 100 个相互独立的随机哈希函数，统计最小哈希值相等的频次比例，实测结果会高度稳定在 0.6 附近。有了 MinHash，每篇文档只需独立计算其哈希签名向量，彻底摆脱了 $O(n^2)$ 的两两暴力比对。

#### 局部敏感哈希与分带相变机制

然而，仅有 MinHash 还不足以解决工程落地问题。单次 MinHash 碰撞是一个方差极大的伯努利随机变量；如果两篇文档的 Jaccard 相似度是 0.6，它们依然有 60% 的概率发生单次哈希碰撞，这会导致流水线产生极其严重的误删（假阳性，False Positive）。我们的工程诉求是：当相似度高于目标阈值（如 0.9）时，碰撞概率必须无限逼近于 1；而当相似度低于该阈值时，碰撞概率必须无限断崖下跌至 0。

为了将平缓线性的概率分布锐化为具备物理“相变（Phase Transition）”特征的极陡 S 型曲线，局部敏感哈希（Locality-Sensitive Hashing, LSH）引入了分带（Banding）机制：

```text
总哈希函数 N = b * r
┌─────────────────────────────────────────────────────────┐
│ Band 1:  h_1,  h_2,  ...,  h_r      ──> 需完全匹配 (AND) │
├─────────────────────────────────────────────────────────┤
│ Band 2:  h_{r+1}, ...,     h_{2r}   ──> 需完全匹配 (AND) │
├─────────────────────────────────────────────────────────┤
│ ...                                                     │
├─────────────────────────────────────────────────────────┤
│ Band b:  h_{(b-1)r+1}, ..., h_{br}  ──> 需完全匹配 (AND) │
└─────────────────────────────────────────────────────────┘
   │
   └──> 只要任意一个 Band 内部的所有 r 个哈希值完全相等，即触发候选碰撞 (OR)
```
> **说明**：LSH 分带技术将 $N$ 个哈希函数划分为 $b$ 个带，每个带包含 $r$ 个哈希函数。带内执行严苛的“与（AND）”逻辑，带间执行宽容的“或（OR）”逻辑，从而将碰撞概率函数拟合成极其陡峭的 S 形激活曲线。

设两篇文档的真实 Jaccard 相似度为 $s$，分带推导流程如下：
1. **带内全匹配概率（AND 门控）**：一个带内包含 $r$ 个哈希函数，由于各哈希函数相互独立，该带内所有 $r$ 个哈希值全部相同的概率为 $s^r$。当 $r$ 较大时，$s^r$ 呈指数级衰减。
2. **带内不匹配概率**：该特定带未能完全匹配的概率为 $1 - s^r$。
3. **全带均不匹配概率**：共有 $b$ 个相互独立的带，所有 $b$ 个带全部未能匹配的概率为 $(1 - s^r)^b$。
4. **最终候选碰撞概率（OR 门控）**：只要至少有一个带触发全匹配，即判定为候选重复，整体碰撞概率公式为：

$$P_{\text{collision}} = 1 - (1 - s^r)^b$$

参数 $b$ 与 $r$ 的调节直接决定了相变曲线的形态与阈值位置：
- **增大行数 $r$**：每个带内的匹配条件变得极其苛刻，$s^r$ 快速变小，相变曲线整体向右偏移且坡度更陡。低相似度的文档对被匹配到的概率断崖式下跌（例如相似度 0.7 时的碰撞率可从 0.25 暴跌至 0.008），大幅净化假阳性。
- **增大带数 $b$**：提供了更多触发碰撞的机会，相变曲线整体向左平移，降低整体匹配门槛，提升召回率。

```text
碰撞概率 P
  1.0 ┼                                    /────────
      │                                   /
      │                                  /  相变中心点 P ≈ 0.632
      │                                 *
      │                                /
      │                               /
  0.0 ┼──────────────/───────────────/
      └──────────────┼───────────────┼────────────── Jaccard 相似度 s
                     0.0            s*             1.0
```
> **说明**：分带公式在临界阈值 $s^*$ 处产生剧烈的相变拐点，实现了“高相似度必然捕获、低相似度绝不误碰”的理想阶跃筛选。

在数学上，相变曲线的中心拐点 $s^*$ 出现在单个带不匹配概率等于 $1/b$ 的临界位置，其解析近似公式为：

$$s^* \approx \left(\frac{1}{b}\right)^{1/r}$$

在该临界相似度 $s^*$ 处，无论 $b$ 取何值，碰撞概率均逼近一个固定常数：

$$P(s^*) = 1 - \left(1 - \frac{1}{b}\right)^b \approx 1 - \frac{1}{e} \approx 0.632$$

在去重实践中，工程师首先根据任务需求确定目标相似度切分线（例如要求 $s^* = 0.9$），据此反解出匹配的 $b$ 与 $r$ 取值；接着通过按比例同时放大 $b$ 与 $r$ 的总规模，使相变拐点附近的曲线尽可能陡峭，从而在十万亿级 Token 的全网数据上以极高精度完成线性时间去重。

### 多源数据混合策略

完成格式转换、质量过滤与去重后，我们得到了一批规模大幅缩小但纯度极高的分门别类的数据集：维基百科、精选网络文本、FinePDFs 抽取文献、出版书籍、代码仓库、arXiv 论文以及数学专业语料等。如何将这些异构的数据源按科学的比例掺和在一起喂给模型，就是数据混合（Data Mixing）要解决的核心议题。

#### 启发式配比与多轮训练过拟合风险

在早期的大模型训练中（例如著名的 The Pile 数据集），数据源配比很大程度上依赖工程师的直觉微调（业界调侃为“靠感觉，Vibes”）。最朴素的基线策略包括：
- **均匀采样（Uniform Sampling）**：无论数据源规模大小，在数据加载器中赋予所有源完全相同的采样概率。
- **按 Token 数量成比例采样（Proportional Sampling）**：源内有多少 Token，就按多大权重采样。这种方式看似公平，但体量庞大但平均信噪比偏低的网络抓取数据会迅速占领绝大部分采样配比，彻底稀释掉体量虽小但极为优质的书籍与学术论文。

直觉上，高质量数据源应当享有更高的权重分配。然而，数据混合面临着两大现实约束：
1. **跨领域多样性的不可通约性**：文学书籍、Python 代码与前沿生物物理学论文之间根本无法直接比对质量高低。语言模型若要具备通用推理与指令遵循底座，就绝不能把所有权重单押在某一种看似高深的学术语料上，必须维系知识分布的全面性。
2. **高质量数据源库容有限与多轮（Epoch）过拟合陷阱**：高质量语料在全网的总量是极其有限的，而低质量数据的体量几乎无限。

我们可以用一组真实的数值模型来推导混合配比中致命的 Epoch 陷阱：
- 设手头有两个数据源：海量低质量网络数据包含 $10\text{T}$（10 万亿）Token，高价值教科书语料仅包含 $10\text{B}$（100 亿）Token。
- 设定当前模型的预训练预算为 $1\text{T}$（1 万亿）Token。
- 若工程师盲目追求高质量，采取朴素的 $1:1$ 均匀采样配比，即两个源各训练 $500\text{B}$ Token：

$$E_{\text{low}} = \frac{500\text{B}}{10\text{T}} = 0.05 \quad (\text{低质量源仅遍历了 } 5\% \text{ 的唯一数据})$$

$$E_{\text{high}} = \frac{500\text{B}}{10\text{B}} = 50 \quad (\text{高质量源被模型强行反复训练了整整 } 50 \text{ 个轮次！})$$

> **易错点**：在大模型预训练中，针对同一个 Token 进行多轮（超过几个 Epoch）的重复训练极易诱发严重的记忆化过拟合，导致验证集损失严重恶化甚至训练发散。很多大模型团队由于只盯着采样比例而忽视了底层库容上限，在不知不觉中让高质量子集跑了数十个 Epoch，最终导致预训练彻底崩盘。

在训练执行层面，混合比例是在批次（Batch）层面通过**序列级采样（Sequence-level Sampling）**落实的：每次从混合分布中抽取一个源类别，随后用该源内部完整的长序列填入当前位置，组装成一个混合 Batch，而不是在单个序列内部按 Token 频繁交织，这样既能降低梯度估计的方差，又能保持序列内部语意逻辑的自洽。

#### 轮次受限采样与 UniMax 约束机制

在训练多语言大模型时，不同语种的在线数据量极度不均衡。UniMax 提出了一套极其明确的受限优化流程：算法保持各数据源的均匀采样倾向，但对每一个数据源能够参与训练的最大 Epoch 数量施加硬性上限约束（例如规定任意源训练不得超过 $E_{\max} = 20$ 个 Epoch）：

$$p_i \cdot N_{\text{total\_train\_tokens}} \le E_{\max} \cdot D_i$$

在满足各源硬性库容约束的前提下，重新解算并归一化采样概率分布，确保小型高价值语料不会被过度榨取至过拟合。

#### 基于回归模型的配比搜索与优化

如何摆脱“靠感觉调参”，系统性地找到最优混合配比？基于回归的数据混合方法（如 RegMix、AutoMix）开创了一条兼具数学严谨性与算力经济性的技术路径。

```text
候选数据混合向量 w (从狄利克雷分布采样)
                 │
                 ▼
[ 训练一组低成本小型代理模型 (数千万至3亿参数) ]
                 │
                 ▼
测量各代理模型在下游基准上的验证损失 L(w)
                 │
                 ▼
[ 拟合对数线性回归模型: 权重向量 w ──> 预测损失 L ]
                 │
                 ▼
凸优化算法在概率单纯形上搜索最优配比: w* = argmin L(w)
                 │
                 ▼
[ 将最佳混合配比 w* 直接迁移至超大基座模型全量训练 ]
```
> **说明**：RegMix 类方法仿照缩放定律（Scaling Laws）的思想，先通过在小参数代理模型上采样不同的混合权重并训练，利用下游损失拟合回归预测曲面，求解出理论最优权重后，再直接推广到十倍、百倍规模的大模型全量预训练中。

RegMix 落地过程中的关键设计要素与潜在陷阱包括：
1. **混合权重采样空间**：混合权重向量 $\vec{w}$ 位于概率单纯形（Simplex，$\sum w_i = 1$）上，通常从狄利克雷分布（Dirichlet Distribution）或指数分布中采样多种混合配比候选。
2. **回归拟合模型**：实践表明，拟合一个轻量级的对数线性模型（Log-linear Model）或梯度提升决策树（GBDT）就能非常准确地刻画混合比例对最终模型损失的映射关系。
3. **评估数据选择的偏倚陷阱**：优化目标通常参考一组下游评估基准的综合损失。但必须高度警惕“为了刷榜而破坏通用性”。如果评估集中代码类任务权重偏高，回归模型就会将极高的采样权重全部倾斜给代码数据，导致最终训练出的大模型写诗与日常对话能力全面退化。

#### 领域自适应聚类与跨规模迁移校准

当我们将 RegMix 从数千万参数的小模型向千亿参数大模型迁移时，必须正视两大理论前提与规模依赖效应：

- **极值外推风险**：回归函数基于有限采样点拟合。当数值优化算法寻找损失最小点时，往往会推进到单纯形的极端边缘角落（例如将某一个源的权重推至极大或极小），而这些极端区间的采样点极度稀疏，回归模型的预测可能出现严重失真。
- **规模依赖效应（Scale-dependent Effects）**：小模型通常只训练数百亿 Token，由于训练总量小，小数据源（如维基百科）在小模型上远远跑不满 1 个 Epoch。此时小模型会表现出“维基百科权重越高越好”的强烈偏好；但一旦将这套权重原封不动搬到训练十万亿 Token 的大模型上，大模型会在维基百科上强行空转数十个 Epoch，瞬间遭遇灾难性过拟合。

为了消除这种小模型无法代表大模型的规模畸变，业界引入了**模拟轮次（Simulated Epoching）**机制：
在小规模代理模型的实验中，不使用全量的高质量子集，而是按照大模型训练的缩放比例，对高质量小数据源进行主动下采样（例如将其库容人工压缩至原本的 1%）。通过人为在小尺度下模拟出大尺度训练时面临的数据短缺与多轮重复惩罚，迫使回归模型学到一套即便在海量 Token 冲刷下依然鲁棒、均衡的最优混合配比。

此外，针对全网抓取的杂乱无章的大包数据（如 Common Crawl），研究团队（如 Megatron-LM、AI 团队的 WebOrganizer）通常先采用无监督聚类对网页进行细分主题归类，再结合质量评分，构建一个“主题领域 $\times$ 质量层级”的二维矩阵网格。原本不可控的粗糙爬虫数据被自动离散为数十个受控单元格，工程师即可将每个单元格视作独立的数据源，纳入上述回归优化框架中实现细粒度精细调配。

### 后训练数据工程与合成数据

预训练与中训练（Mid-training）主要负责让模型掌握通用语言建模能力与世界知识，其语料筛选大多是任务无关（Task-agnostic）的。而当模型进入后训练（Post-training，包含 SFT 与强化学习对齐）阶段时，数据形态发生了根本性转变——后训练数据高度依赖具体应用场景与下游任务环境。

在当前的开源模型生态中，绝大多数高质量后训练数据已经全面转向**模型合成数据（Synthetic Data）**。虽然在工业界前沿探索中仍保留部分高成本的专家人类标注，但通过构建模拟环境与精选提示词、利用超强教师模型进行多轮采样生成，已成为后训练规模化扩张的统治级范式。

#### 强教师模型驱动的任务指令合成

以近期开源的高质量后训练数据集 OpenThoughts 为例，该项目旨在为数学、科学与复杂代码任务提供极高密度的长思维链（Chain-of-Thought, CoT）推理数据，最终合成了 120 万条高质量示例。

其构建流程遵循标准的后训练合成流水线：
1. **任务与问题池沉淀**：从 Stack Exchange、NuminaMath 等人工高价值题库以及部分合成提示中汇集初始问题源，涵盖竞赛数学、化学推理与实际编程场景。
2. **多路采样扩展**：对筛选后的核心问题进行下采样（实际唯一问题数约 7.5 万道），利用强教师模型对每道问题采样生成 16 组不同的推理回答（$7.5\text{万} \times 16 \approx 120\text{万}$）。
3. **去重与精细过滤**：剔除逻辑死循环、输出格式损坏以及低质量的劣质路径。

在 OpenThoughts 的系统消融实验中，研究团队总结了三条颠覆直觉的核心工程结论：
- **来源精选胜于盲目堆砌**：仅仅精选几个核心高信噪比源，其最终对齐训练效果显著优于将所有抓取到的题库全部胡乱打包喂入。
- **模型绝对能力不等于教学能力**：在教师模型的评测对比中，QwQ-32B 虽然在绝对参数体量和综合基准评分上略逊于某些超大规模前沿模型（如 DeepSeek-R1），但其生成的推导轨迹步骤详尽、逻辑平缓、对弱模型极其友好，展现出了远胜于大模型的“教学效果（Teaching Quality）”。
- **简单答案匹配过滤收益微弱**：仅仅根据最终答案对错进行二元过滤，对提升模型后训练推理能力的边际收益非常有限，中间思维链条的严密性与逻辑多样性才是决定性因素。

#### 真实软件工程环境与轻量化代码轨迹构建

在代码后训练领域，学术界与工业界正在经历从“代码生成（Code Golf / 函数级补全）”向“真实软件工程（Software Engineering, SWE）”智能体的跨越。真实的软件工程不仅要求写出算法，还要求在真实的 GitHub 仓库中定位缺陷、理解跨文件依赖、安装运行环境并修复 Bug。

```text
方案 A: 重型沙箱执行流 (SWE-smith 等)
真实 GitHub 仓库 ──> 配置 Docker 镜像 ──> 安装过时老依赖 ──> 注入 Bug ──> 运行测试验证 ──> 5万真实执行轨迹
(痛点: 依赖冲突严重、历史提交环境构建极易崩溃、吞吐受限)

方案 B: 模型先验与轻量执行流 (SWE-Zero / SWE-rebench)
真实 PR 变更元数据 ──> 强代码模型直接解析仓库语义 ──> 纯模型推演生成轨迹 (无需运行 Docker) ──> 30万~1200万轨迹
                                                                      │
                                                                      ▼
                                     混合少量 (1.3万条) 真实沙箱执行反馈轨迹进行微调对齐
```
> **说明**：软件工程智能体的数据构建经历了从“必须依赖庞大 Docker 沙箱验证代码运行”到“利用大模型内部代码语义先验实现无执行反馈的大规模轨迹合成”的技术跨越，彻底化解了真实开源仓库历史依赖无法安装运行的工程死结。

在构建 SWE 数据集的技术演进中，两条鲜明的路线互为补充：
1. **重型依赖与任务合成（SWE-smith）**：
   设计自动化智能体拉取 GitHub 真实仓库，配置真实运行环境并安装所需依赖项；随后通过自动化修改代码（例如故意注入 Bug）生成测试用例。这套流程能获得具备真实单元测试反馈的合成任务，但受限于环境搭建难度，年产出规模通常停留在数万（约 5 万）条量级。
2. **摆脱环境噩梦与轻量化先验推导（SWE-Zero 与 SWE-rebench）**：
   在处理涵盖全网代码仓库的普适任务时，环境配置是最大的噩梦。当回退到数年前某个 PR 提交时的历史状态时，过时的编译器、冲突的底层动态库往往让 Docker 镜像构建彻底瘫痪。
   NVIDIA 的研究团队在 SWE-Zero 中敏锐地发现了一个关键技术事实：**现代顶尖代码模型对代码的内部执行逻辑拥有极强的先验理解能力，哪怕完全不给它提供命令行执行反馈，它的任务求解得分依然惊人**。在标准测试中，允许模型调用终端执行代码的得分约为 80 分；而在完全禁止代码执行、盲写修复补丁的条件下，模型的得分依然能逼近 70 分。
   这一发现彻底打破了“必须搭建百万个 Docker 容器才能洗数据”的算力枷锁。SWE-Zero 直接抓取真实 GitHub 历史 PR，在完全不启动动态容器执行代码的前提下，利用强大的代码模型生成并严格过滤了 30 万条高度逼真的智能体轨迹；随后仅搭配 1.3 万条具备真实执行反馈的轨迹进行辅助微调，便在顶尖基准上取得了突破性进展。在此基础上，最新发布的 SWE-rebench 进一步将这种轻量化与无执行推导模式推向了极致，成功合成了高达 1200 万条智能体解决轨迹。

从纯文本 HTML 的有损线性化投影，到基于相变原理的哈希去重；从规避多轮过拟合的回归混合，再到摆脱 Docker 依赖的轻量后训练合成——大语言模型的数据工程从来不是单一算法的简单叠加，而是一门在极端算力边界与海量噪声世界之间不断权衡、逼近最优解的严谨系统工程。
