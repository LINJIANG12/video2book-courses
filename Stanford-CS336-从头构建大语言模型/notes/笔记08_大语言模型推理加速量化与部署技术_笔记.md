# 大语言模型推理加速、量化与部署技术

## 推理工作负载与性能度量体系

### 训练与推理计算范式差异

* **自回归推理（Autoregressive Inference）**

    * > **定义**：基于单向因果依赖关系，根据已有输入前缀与历史生成序列逐步预测下一个输出词元的串行生成计算过程。

    * **计算拓扑差异**：模型训练阶段输入序列完全已知，全序列可在时间序列维度上并行执行大尺寸高维方阵矩阵乘法，具备高算术强度；自回归推理阶段由于无法预知未来词元，输出长度被锁死为 $T=1$，计算拓扑从方阵乘法退化为细长的向量-矩阵乘法（GEMV）或极低维张量计算。

    * **成本特征演进**：模型训练属于一次性资本支出（One-off Cost）；推理属于服务上线后只要系统运行就必须持续支付的日常运营成本。OpenAI 日均生成约 1.6 万亿（$1.6 \times 10^{12}$）个 token，系统每运行数天消耗的推理算力即可覆盖一个 32 万亿 token 规模模型（如 DeepSeek 级基础大模型）的完整预训练算力。

    * **工作负载范式迁移**：传统对话助手受限于人类肉眼生理阅读速率（每秒十几个词元），生成速度超过阅读上限后边际收益递减；智能体（Agentic）工作负载包含任务拆解、链式深度推理、外部工具调用、环境反馈自检与推翻重构等多轮自主循环，绝大多数词元属于系统内部生成的中间推理状态（Tokens as Compute），无人类生理速度瓶颈，系统吞吐优化的经济价值无物理上限。

    * **推理软件栈生态格局**：开源服务生态呈现出清晰的分工体系，包括通用首选引擎 vLLM、在结构化输出与复杂 Agentic 工作流表现卓越的 SGLang、针对专用硬件极限调优的 NVIDIA TensorRT-LLM，以及面向边缘端 CPU 部署的轻量框架 llama.cpp。

    ```text
    训练阶段（序列完全并行）：
    [ Token 1, Token 2, Token 3, ..., Token T ]  --> 一次性前向传播计算损失并更新梯度

    自回归推理阶段（序列因果串行）：
    Prompt:  [ T1, T2, T3 ] ----------------------> 生成 T4
    Context: [ T1, T2, T3, T4 ] ------------------> 生成 T5
    Context: [ T1, T2, T3, T4, T5 ] --------------> 生成 T6
    ```

* **自回归时序约束（Causal Dependency Constraint）**

    * > **定义**：模型在时间步 $t$ 生成输出词元时，必须以且仅能以步骤 $1$ 至 $t-1$ 的历史词元作为输入条件的单向因果物理限制。

    * **执行约束**：该约束决定了推理系统在时间步维度上无法展开并行循环，必须严格按步循环迭代。

### 核心性能度量指标

* **首字时间（Time to First Token，TTFT）**

    * > **定义**：从客户端提交请求到系统完成输入处理并输出第一个可见词元所经历的端到端等待延迟。

    * **度量单位**：毫秒（ms）或秒（s）。

    * **制约因素**：由预填充（Prefill）阶段处理完整输入 Prompt 的耗时决定，受硬件峰值计算能力与输入 Prompt 长度主导。

    * **应用场景**：直接决定交互式对话、即时人机问答等即时响应场景的敏捷度体感。

* **单用户延迟（Latency / Inter-Token Latency，ITL）**

    * > **定义**：自回归解码生成阶段，系统吐出连续两个词元之间的物理时间间隔。

    * **度量单位**：秒/token（s/token）或毫秒/token（ms/token），其倒数为单序列流式生成速率（tokens/s）。

    * **制约因素**：在单用户或低并发场景下，主要受高带宽显存（HBM）向片上计算核心搬运静态模型权重的物理带宽制约。

    * **应用场景**：决定代码实时补全、文字流式打印助手的平滑度与交互流畅感。

* **聚合吞吐量（Throughput）**

    * > **定义**：推理系统或 GPU 集群在单位物理时间内并发处理并生成的有效词元总数。

    * **度量单位**：每秒词元总数（tokens/s）。

    * **制约因素**：衡量系统硬件资源的全局利用效率，受并发批处理规模、显存物理容量上限及多卡并行架构主导。

    * **应用场景**：主导大规模离线文档抽取、海量评测打分及强化学习轨迹采样（Rollouts）等批量数据处理场景的成本核算。

| 性能度量指标 | 英文术语与缩写 | 核心度量单位 | 主导执行阶段 | 硬件与服务层制约因素 |
| :--- | :--- | :--- | :--- | :--- |
| 首字时间 | Time to First Token (TTFT) | 毫秒（ms）/ 秒（s） | Prefill 阶段 | 硬件峰值浮点算力与输入 Prompt 长度 |
| 单用户延迟 | Latency / Inter-Token Latency (ITL) | 秒/token 或 毫秒/token | Decode 阶段 | 显存物理带宽搬运静态参数的速度 |
| 聚合吞吐量 | Throughput | 每秒词元数（tokens/s） | 全流程并发 | 并发批大小、显存物理容量与并行架构 |

### 批处理规模对延迟与吞吐量的制约博弈

* **批处理规模调控（Batch Size Tuning）**

    * > **定义**：通过调节系统并发推进的请求序列数量，在单请求延迟与集群利用率之间寻求折中的调度策略。

    * **小批次特性（以 $B=1$ 为例）**：系统无须等待其他请求对齐，模型权重加载后仅为单序列执行计算，单词元生成延迟降至极限最低（类似私家车点火即走）；但静态权重搬运无法被摊薄，硬件计算核心处于大面积闲置状态，聚合吞吐量极低。

    * **大批次特性（大 $B$）**：庞大的静态模型参数从显存读取一次后可同时为 $B$ 个请求执行矩阵乘法，I/O 开销被有效分摊，聚合吞吐量显著攀升；但批处理要求批次内部协同推进，每个请求必须等待整批中最长的序列完成，且单步需读写 $B$ 份私有缓存，单步延迟随 $B$ 线性恶化（类似公交车等待满员发车且逢站必停）。

* **多副本模型并行（Replication）**

    * > **定义**：在物理硬件集群上部署 $M$ 个独立的模型服务实例以实现水平并发扩展的系统策略。

    * **运行规则**：每个副本各自维持极小的批大小（如 $B=1$），各请求的生成延迟保持在最低极限，系统整体吞吐量随副本数 $M$ 呈现线性放大，代价为硬件设备与电力成本成倍激增。

## 硬件算术强度建模与内存墙根因

### 算术强度与硬件瓶颈分界

* **算术强度（Arithmetic Intensity，I）**

    * > **定义**：系统在执行计算任务时，每在内存与计算核心之间搬运 1 字节数据所能完成的有效浮点运算次数。

    * **物理公式**：
      $$I = \frac{\text{浮点运算总次数 (FLOPs)}}{\text{内存数据搬运总量 (Bytes)}}$$

    * **通用矩阵乘法（GEMM）强度推导**：
        * 输入激活张量 $X \in \mathbb{R}^{B \times D}$，权重矩阵 $W \in \mathbb{R}^{D \times F}$，输出张量 $Y \in \mathbb{R}^{B \times F}$，采用 16 位浮点格式（BF16/FP16，每数值 2 字节）。
        * 浮点运算量：输出矩阵中每个元素需执行 $D$ 次乘加运算（每次乘加计 2 FLOPs），总计算量为 $2 B D F$ FLOPs。
        * 内存读写量：从 HBM 读取 $X$ 消耗 $2BD$ 字节，读取 $W$ 消耗 $2DF$ 字节，将 $Y$ 写回 HBM 消耗 $2BF$ 字节，总搬运量为 $2(BD + DF + BF)$ 字节。
        * 精确解析式：
          $$I_{\text{GEMM}} = \frac{2 B D F}{2 (B D + D F + B F)} = \frac{B D F}{B D + D F + B F}$$
        * 渐近极限：大语言模型中隐藏维度 $D$ 与前馈层维度 $F$ 处于数千至数万量级（如 $D=5120, F=13824$），远大于常规批大小 $B$（$D, F \gg B$），分子分母同除以 $D \cdot F$：
          $$I_{\text{GEMM}} \approx \frac{B}{1 + \frac{B}{F} + \frac{B}{D}} \approx B$$
        * 结论：当模型参数维度远大于并发批处理规模时，通用矩阵乘法的理论算术强度在数值上约等于批大小 $B$。

* **硬件临界算术强度（Hardware Operational Intensity Threshold）**

    * > **定义**：由加速芯片峰值浮点计算能力与全局显存物理带宽的比值所决定的性能瓶颈分水岭。

    * **硬件参数基准（以 NVIDIA H100 SXM 为例）**：BF16 Tensor Core 密集峰值算力约为 989 TFLOPS（非稀疏），HBM3 显存带宽约为 3.35 TB/s（实际有效带宽约 3000 GB/s）。其硬件临界算术强度为：
      $$I_{\text{H100}} = \frac{989 \times 10^{12} \text{ FLOPs/s}}{3.35 \times 10^{12} \text{ Bytes/s}} \approx 295 \text{ FLOPs/Byte}$$
      （若按稀疏计算峰值近 2000 TFLOPS 计算，该阈值落在 200 至 590 FLOPs/Byte 区间）。

    * **瓶颈判定准则**：
        * **计算受限（Compute-bound）**：实际算术强度 $I > I_{\text{硬件}}$，计算单元满负荷运行，系统耗时由浮点计算能力决定。
        * **内存带宽受限（Memory-bound）**：实际算术强度 $I < I_{\text{硬件}}$，大部分计算核心处于空转饥饿状态，系统耗时由显存数据传输速率决定。

    * > ⚠️ **易错点**：当单用户交互式推理且 $B=1$ 时，大模型矩阵运算的算术强度仅约为 1 FLOP/Byte，远低于 H100 硬件饱和所需的 295 FLOPs/Byte。此时 GPU 超过 99% 的计算核心处于闲置空转状态，生成耗时几乎全部被从 HBM 读取参数的物理带宽占满，而非算力不足。

### Transformer 张量运算与 einops 符号体系

* **张量维度与缩约记号**

    * > **定义**：形式化描述 Transformer 各层张量几何形状、数据流向与维度缩约规则的符号规范。

    * **统一维度记号**：
        * $B$：并发批处理规模（Batch Size）；
        * $S$：输入条件序列长度（Prompt 词元数）；
        * $T$：生成目标序列长度（当前前向步待生成的词元数）；
        * $D$：模型隐藏层维度（Hidden Dimension）；
        * $F$：前馈网络（MLP）中间层扩展维度，业内通常设为 $F = 4D$；
        * $N$：Query 注意力头总数；
        * $H$：单个注意力头的特征维度，满足恒等式 $D = N \times H$；
        * $K$：Key/Value 注意力头数量（MHA 中 $K = N$，GQA 中 $K < N$，MQA 中 $K = 1$）；
        * $G$：每个 KV 头所共享的 Query 头数，满足 $N = K \times G$。

    * **维度行为法则**：
        * **缩约维度（Contracted Dimensions）**：同时出现在相乘的两个操作数中，在矩阵乘法求和后消除的维度（如内积轴）。
        * **保留维度（Preserved Dimensions）**：仅在单个操作数中出现并在结果张量中保留的维度。
        * **批处理维度（Batch Dimensions）**：在相乘两侧均存在并在结果中保留的维度，各切片彼此独立并行计算。

    ```text
    Attention QK^T 矩阵乘法维度流：
    Q: [ B, N, T, H ]  ×  K^T: [ B, K, H, S ]  -->  Score: [ B, N, T, S ]
         ↑     ↑                 ↑     ↑                      ↑
       批次   收缩              批次  收缩                  批次保留
    ```

### 朴素自回归计算困境与 KV 缓存机制

* **键值缓存（Key-Value Cache，KV Cache）**

    * > **定义**：在显存中开辟专用空间持久化存储自回归历史上已生成的全部 Key 与 Value 向量，避免在后续时步重复计算历史前缀的动态缓存机制。

    * **朴素自回归的三次方爆炸困境**：若不保存中间激活状态，生成每个新词元时均重新传入完整序列，因果注意力矩阵在序列长度为 $t$ 时的计算复杂度为 $O(t^2)$。生成总计 $T$ 个词元的累计计算时间复杂度呈现三次方膨胀：
      $$\sum_{t=1}^T O\left((S+t)^2\right) \approx O(T^3)$$

    * **前缀不变性先验**：因果注意力具有确定性的前缀不变性。在序列末端追加新词元时，过去历史上已生成的历史词元所对应的隐层表征、Key 向量与 Value 向量完全静态恒定，不会因后续新词的产生而发生改变。

    * **引入收益**：利用 KV Cache，生成 $T$ 个词元的注意力累计前向计算复杂度从 $O(T^3)$ 压缩至 $O(T^2)$。

### 两阶段执行瓶颈分水岭

* **预填充阶段（Prefill Stage）**

    * > **定义**：大模型接收完整输入 Prompt 并一次性完成全部输入词元前向计算以构建初始 KV Cache 的初始阶段。

    * **参数特征**：计算步满足 $T = S$。

    * **MLP 层算术强度**：有效参与计算的词元总数为 $B \times S$，算术强度 $I_{\text{MLP, Prefill}} \approx B \times S$。只要 Prompt 长度达到数百至数千，算术强度即可轻松突破上千，处于高度的计算受限（Compute-bound）状态。

    * **Attention 层算术强度**：执行全序列自注意力点积，浮点运算量约为 $2 B S^2 D$，数据搬运量约为 $O(B S D)$，理论算术强度约为：
      $$I_{\text{Attn, Prefill}} \approx \frac{S}{2}$$
      该算术强度仅由序列长度 $S$ 决定而脱离批大小 $B$，在长文本输入下同样属于纯粹的计算受限状态。

* **解码生成阶段（Decode Stage）**

    * > **定义**：自回归生成中每一步前向计算仅处理单个活跃词元并更新 KV Cache 的逐步生成阶段。

    * **参数特征**：计算步满足 $T = 1$。

    * **MLP 层算术强度**：参与矩阵乘法的词元总数退化为 $B \times 1$，算术强度 $I_{\text{MLP, Decode}} \approx B$。在单并发或小批次下属于访存受限，随着线上请求并发度 $B$ 提升至数百以上可跨越至计算受限。

    * **Attention 层算术强度**：当前位置的 1 个 Query 需与缓存中已有的 $S$ 个历史 KV 进行点积。浮点运算量为 $2 B S D$，内存搬运量由从 HBM 读取历史全量 KV Cache 主导（约 $4 B D (S+1)$ 字节或至少 $2 B S D$ 字节）。理论算术强度为：
      $$I_{\text{Attn, Decode}} \approx \frac{S}{S+1} < 1 \text{ FLOP/Byte}$$

    * **注意力层内存墙根因**：MLP 层的权重在整个 Batch 内的所有 $B$ 个样本间完全共享，硬件加载一次权重矩阵即可服务 $B$ 个序列；而注意力层中每个序列拥有私有独立的 KV Cache，并发数 $B$ 越大，需要读写的 KV Cache 总量以 $O(B)$ 比例同步膨胀。增大 Batch Size 完全无法摊薄注意力层的访存开销，反而加剧显存带宽挤兑，解码阶段物理上属于不可逆的内存带宽受限。

```text
阶段一：Prefill（预填充阶段，T = S）
Prompt: [ X1, X2, ..., XS ] ----------------------------> 并行计算完成，填满初始 KV Cache
                                                         计算强度高，Compute-bound

阶段二：Decoding（自回归生成阶段，T = 1）
Step 1: [ X_{S+1} ] + [ 历史 KV Cache ] -----------------> 生成 X_{S+2}，追加新 KV 到 Cache
Step 2: [ X_{S+2} ] + [ 历史 KV Cache ] -----------------> 生成 X_{S+3}，追加新 KV 到 Cache
                                                         计算强度极低，Memory-bound
```

## 系统级性能建模与批处理折中

### LLaMA-2-13B 硬件基准定量推演

* **系统性能分析模型（Analytical Performance Model）**

    * > **定义**：结合硬件物理规格与网络拓扑参数，对大模型推理显存占用、单步步进延迟与系统吞吐量进行代数刻画的定量分析模型。

    * **硬件与模型基准配置**：
        * 硬件规格：单张 NVIDIA H100 SXM，物理显存容量 80 GB，有效显存带宽 $W_{\text{mem}} \approx 3000 \text{ GB/s}$（标称物理峰值为 3.35 TB/s）。
        * 模型架构：LLaMA-2-13B，总参数量 $P = 13 \times 10^9$（13B），层数 $L = 40$，隐藏维度 $D = 5120$，前馈维度 $F = 13824$，头数 $N = 40$，键值头数 $K = 40$（标准多头注意力 MHA，$K = N$），头维度 $H = 128$。数值精度采用 BF16（每个参数或激活占 2 字节），上下文长度设为 $S = 2048$。

    * **显存物理占用建模**：
        * 静态权重显存：
          $$M_{\text{params}} = P \times 2 \text{ Bytes} = 13 \times 10^9 \times 2 \approx 26.0 \text{ GB}$$
        * 单序列 KV Cache 显存（$S = 2048$）：
          $$\text{KV}_{\text{single}}(S) = 2 \times 2 \times L \times K \times H \times S = 4 \times 40 \times 40 \times 128 \times 2048 \approx 1.68 \text{ GB}$$
        * 系统总显存占用：
          $$M_{\text{total}}(B, S) = M_{\text{params}} + B \times \text{KV}_{\text{single}}(S) = 26.0 \text{ GB} + B \times 1.68 \text{ GB}$$

    * **步进延迟与系统吞吐量推导**：
        * 单步解码时延（Step Latency，在计算与通信完美重叠假定下由从 HBM 传输数据的耗时决定）：
          $$\text{Latency}(B) = \frac{M_{\text{total}}(B, S)}{W_{\text{mem}}} = \frac{26 + B \times 1.68}{3000} \text{ 秒/Token}$$
        * 聚合吞吐量（Throughput）：
          $$\text{Throughput}(B) = \frac{B}{\text{Latency}(B)} = \frac{B \times W_{\text{mem}}}{M_{\text{params}} + B \times \text{KV}_{\text{single}}(S)} = \frac{W_{\text{mem}}}{\frac{M_{\text{params}}}{B} + \text{KV}_{\text{single}}(S)}$$

### 批处理规模数值推演与容量墙瓶颈

* **批处理规模敏感度分析**

    * > **定义**：考察并发批大小 $B$ 变化对系统步进延迟、聚合吞吐量及显存占用所产生影响的定量评估。

    * **数值变化阶梯（LLaMA-2-13B 在 H100 80GB 上的推演结果）**：

| 并发批大小 $B$ | 单 Token 延迟（s/token） | 系统聚合吞吐量（tokens/s） | 总显存开销（GB） | 运行状态与硬件特征 |
| :--- | :--- | :--- | :--- | :--- |
| 1 | ~ 0.0078 - 0.0092 | ~ 108 - 128 | 27.7 GB | 极低延迟，算力严重闲置 |
| 8 | ~ 0.0131 | ~ 609 | 39.4 GB | 吞吐快速爬升 |
| 16 | ~ 0.0176 | ~ 909 | 52.9 GB | 算力与显存较均衡 |
| 32 | ~ 0.0266 | ~ 1203 | 79.8 GB | 逼近单卡 80GB 物理显存红线 |
| 64 | ~ 0.0445 | ~ 1438 | 133.5 GB | 显存溢出崩溃（OOM） |

* **显存容量墙与吞吐极值定律**

    * > **定义**：系统吞吐量受限于显存物理带宽与容量上限的双重理论边界。

    * **渐近吞吐物理天花板**：当并发批大小 $B \to \infty$ 时，公式分母中权重摊薄项 $\frac{M_{\text{params}}}{B} \to 0$，系统吞吐量趋近于理论极值：
      $$\lim_{B \to \infty} \text{Throughput}(B) = \frac{W_{\text{mem}}}{\text{KV}_{\text{single}}(S)} = \frac{3000 \text{ GB/s}}{1.68 \text{ GB}} \approx 1785 \text{ Tokens/s}$$
      随着批大小递增，吞吐量呈现严格的双曲渐近饱和特征，边际增益迅速衰减。

    * **显存容量墙（Capacity Wall）硬性截断**：实际生产系统中吞吐量无法触碰上述渐近极限，当 $B$ 增大至临界点时（如示例中 $B=32$ 占用 79.8 GB），总显存开销触碰单卡 80 GB 物理红线并触发显存溢出（OOM）。即使未来更换更大容量芯片，也只是推迟了溢出阈值，无法摆脱容量墙截断规律。

## 架构级键值缓存压缩方案

### 注意力头维度压缩

* **分组查询注意力（Grouped-Query Attention，GQA）**

    * > **定义**：将 $N$ 个 Query 头均分为 $K$ 组，每组内部包含 $G = N / K$ 个 Query 头，组内所有 Query 头共享同一组 Key 和 Value 的注意力架构。

    * **压缩比与收益**：单序列 KV Cache 显存占用精确缩减为多头注意力（MHA）的 $\frac{K}{N} = \frac{1}{G}$。显存暴跌带来双重收益：单步访存量减少使单字延迟显著降低；显存释放允许系统将批处理规模向上拉升数倍，实现吞吐量倍增。

    * **架构演进拓扑对比**：
        * 多头注意力（MHA）：$K = N$，KV 缓存占比 100%，表达能力强但显存开销极大。
        * 多查询注意力（MQA）：$K = 1$，所有 Query 头共享唯一一组 Key/Value，缓存压缩 $N$ 倍，但表达能力大幅削弱，复杂任务精度断崖式下跌。
        * 分组查询注意力（GQA）：在精度与显存间取得帕累托最优平衡，以 $G=8$ 为例可将 KV 缓存压缩至 12.5%。在 LLaMA-13B 中单序列缓存由 1.68 GB 降至 0.21 GB，可支持批大小提升 8 倍以上。

    ```text
    MHA（多头注意力）:        GQA（分组查询注意力）:       MQA（多查询注意力）:
    Q1 Q2 Q3 Q4 Q5 Q6 Q7 Q8   Q1 Q2 Q3 Q4 Q5 Q6 Q7 Q8     Q1 Q2 Q3 Q4 Q5 Q6 Q7 Q8
     |  |  |  |  |  |  |  |    \  /   \  /   \  /   \  /       \   \   |   /   /
    K1 K2 K3 K4 K5 K6 K7 K8     K1     K2     K3     K4              K1
    V1 V2 V3 V4 V5 V6 V7 V8     V1     V2     V3     V4              V1
     (KV 缓存比例: 100%)         (KV 缓存比例: 50%)           (KV 缓存比例: 12.5%)
    ```

* **多头潜注意力（Multi-Head Latent Attention，MLA）**

    * > **定义**：保持逻辑注意力头数不减少，通过低秩投影将 Key 和 Value 压缩至低维潜向量空间进行缓存与推理的注意力架构。

    * **潜变量低秩压缩机理**：隐藏层激活向量不直接投影到高维 Key/Value 空间，而是先压缩投影至一个极低维度的潜变量向量 $c^{KV}$（例如 512 维）。在推理部署期间，显存中**仅持久化缓存低维潜向量 $c^{KV}$**；计算注意力时再通过矩阵乘法动态恢复出 Key 与 Value，或利用矩阵乘法结合律与权重合并计算。

    * **解耦旋转位置编码（Decoupled RoPE）**：旋转位置编码（RoPE）直接逐 token 作用于 Key 向量，具备方向敏感性，与线性的低秩矩阵还原算子无法直接交换计算顺序。MLA 将 Key 显式解耦为两部分：绝大部分内容压缩进低维潜变量 $c^{KV}$，另单独剥离一个极小维度的独立向量 $k^R$ 专用于承载 RoPE 计算。

    * **性能表现**：压缩比超越常规 GQA，且下游基准评测精度几乎完全持平甚至微幅超越全量 MHA，优化了精度与速度的帕累托前沿。

    ```text
    MLA 压缩存储与解耦 RoPE 拓扑：
                隐层激活状态 X
                 /          \
      [低秩下投影]           [RoPE 键投影]
              ↓                    ↓
      潜变量缓存 c^{KV} (仅存此项!)   位置编码键 k^R (独立保留)
              ↓
      [在线解包矩阵乘]
         /         \
        ↓           ↓
     解包 Key    解包 Value
    ```

### 网络深度与时间窗口压缩

* **跨层注意力（Cross-Layer Attention，CLA）**

    * > **定义**：打破网络层级相互独立的壁垒，在相邻网络层之间共享 Key 和 Value 缓存的架构设计。

    * **机理与收益**：常规 Transformer 全网 $L$ 个层各自独立维护专属 KV Cache；CLA 仅在特定关键层计算并生成新的 Key 和 Value，相邻后续层直接复用前一层的 KV Cache。深层网络相邻层表征具备高度连续性与语义重叠，可在不破坏表达能力的前提下按比例削减全网 $1/2$ 至 $2/3$ 的总 KV Cache 显存。

* **滑动窗口注意力（Sliding Window Attention，SWA）**

    * > **定义**：限制每个新生成词元仅关注其左侧最近 $k$ 个局部上下文的稀疏注意力机制。

    * **复杂度降阶**：通过维护长度为 $k$ 的局域环形缓冲区，将单序列的 KV Cache 空间复杂度从随长度线性增长的 $O(S)$ 彻底降为与上下文长度无关的常数 $O(k)$。通过深层网络层级堆叠与感受野扩散，顶层依然能感知超出标称窗口的上下文。

    * **局限性与混合架构（Hybrid Architecture）**：在超长文本的“大海捞针”（Needle in a Haystack）检索中，由于历史深处信息物理丢失会出现性能崩溃。工业界主流方案是构建混合架构：绝大多数层采用滑动窗口注意力以极致节省显存带宽，在特定间隔层周期性插入全注意力层（Full Attention），以微小缓存代价维系长距离无损依赖。

```text
全局因果全注意力 (全量 O(S^2)):          滑动窗口注意力 (窗口大小 k=3):
   T1 T2 T3 T4 T5                         T1 T2 T3 T4 T5
T1  *                                  T1  *
T2  *  *                               T2  *  *
T3  *  *  *                            T3  *  *  *
T4  *  *  *  *                         T4     *  *  *
T5  *  *  *  *  *                      T5        *  *  *
```

* **线性注意力（Linear Attention）与状态空间模型（State Space Models，SSM）**

    * > **定义**：利用核函数展开或门控循环状态转移方程，将历史上下文持续更新并压缩进固定尺寸隐状态矩阵的递归模型架构。

    * **代表模型**：Mamba、DeltaNet 等。

    * **推理特性与物理边界**：从数学机理上彻底消除显式 KV Cache，实现解码时显存占用与单步时延恒定为 $O(1)$。但将无限长度的历史强行压缩进有限维度的固定状态中，在信息论上存在理论压缩极限，会导致长程高频细节与非局部精准键值对信息模糊化，面对细粒度数值检索表现弱于全注意力机制。前沿方案趋向将全注意力层与 SSM/线性层交替混编。

* **稀疏注意力变体（Sparse Attention Variants）**

    * > **定义**：通过粗粒度汇聚或动态索引筛选，仅对与当前步最相关的历史词元子集执行注意力计算的技术。

    * **压缩稀疏注意力（Compressed Sparse Attention）**：将时间序列上每 $m$ 个连续词元的特征向量通过平均池化或轻量下采样聚合成单一宏观词元，直接压低上下文存储基数。

    * **动态稀疏索引机制**：在注意力主干计算前，运行轻量级 Query 和 Key 投影在粗粒度网格上计算注意力分数的近似分布，动态筛选锁定当前步最相关的 Top-K 个历史块，仅对命中子集加载全量 KV Cache 进行计算，规避全量历史遍历的巨大访存开销。

## 模型数值量化与结构化剪枝

### 数值精度量化范式

* **模型量化（Quantization）**

    * > **定义**：通过降低模型权重参数与激活张量的数值表示位宽以缩减显存占用并减少访存开销的系统级技术。

    * **位宽缩减收益**：将参数从 16 位浮点（BF16/FP16，每参数 2 字节）压缩至 INT8（1 字节）或 INT4（0.5 字节），模型权重体积缩减至原先的 $1/2$ 至 $1/4$，显存带宽搬运耗时成比例下降，同时允许显存容纳成倍扩大的批处理规模。

    * **量化感知训练（Quantization-Aware Training，QAT）**：在模型预训练或微调的前向传播中引入伪量化算子模拟舍入截断误差，反向传播基于高精度浮点更新权重。权重能够自适应低位宽分布，量化精度最高，但训练算力消耗与调优成本极高。

    * **训练后量化（Post-Training Quantization，PTQ）**：直接在训练就绪的成熟浮点模型上计算统计分布并执行数值离散化，计算成本极低，为工业落地主力。朴素全局或通道截断在 INT4 激进量化下会导致困惑度（Perplexity）严重恶化。

* **高阶 PTQ 优化算法**

    * **GPTQ**：引入二阶泰勒展开，利用输入数据的海森矩阵（Hessian Matrix）逆矩阵信息，按列逐步离散化权重，并在量化某一列后动态求解并补偿其余未量化权重的浮点数值，将离散化误差逐层闭环抵消。

    * **激活感知权重量化（Activation-aware Weight Quantization，AWQ）**：
        * 核心观察：并非所有权重都同等重要，权重的显赫程度取决于与之相乘的输入激活值（Activation）。激活值在绝大多数维度平缓，但在极少数隐藏通道上会突发性呈现超乎寻常的巨大绝对值（Outliers），这不到 1% 的关键通道承载了全网络绝大部分核心知识。
        * 保护机制：通过小型校准集监测激活分布，仅保护对应显著激活通道的权重列（维持高精度如 FP16 或施加缩放保护），对其余 99% 的普通通道实施激进的 4-bit 量化，以极小系统开销近乎无损守住基准精度。
        * > ⚠️ **易错点**：若某些神经元在所有校准样本上的激活值始终恒定为一个极高数值（如恒等于 100），该现象并不代表承载高动态信息的显著特征，而是网络训练沉淀出的静态偏置残余（Bias Artifact）。不能仅凭激活绝对值盲目施加显著性保护，应结合均值与方差分布进行联合分析，工程上需通过重参数化将其折算吸纳进后级偏置项中处理。

    ```text
         ┌─────────────────────────────────────────────────────────┐
         │                原始 FP16 浮点权重矩阵                   │
         └────────────────────────────┬────────────────────────────┘
                                      ▼
          校准集输入推断 ──> 提取各通道激活值幅度 |X|
                                      ▼
           [识别显著特征通道] ──> 仅占总通道数 1% 的高幅度关键通道
                   /                                  \
      [显著通道 (Salient Channels)]            [其余 99% 普通非显著通道]
                  ↓                                       ↓
       保持 FP16 高精度绝不压缩                激进压缩为 INT4 超低比特
                   \                                  /
                    ▼                                ▼
         ┌─────────────────────────────────────────────────────────┐
         │          AWQ 混合精度紧凑权重 (硬件高效非均匀存储)        │
         └─────────────────────────────────────────────────────────┘
    ```

### 结构化剪枝与后训练恢复

* **结构化模型剪枝（Structured Model Pruning）**

    * > **定义**：依据重要性评估指标，直接成块移除网络拓扑中冗余的注意力头、隐藏神经元乃至整层网络的模型瘦身技术。

    * **与非结构化剪枝对比**：非结构化剪枝（将零散单个权重置零）破坏了张量稠密性，在通用 GPU 上难以转化为实际物理加速；结构化剪枝直接切除规整矩阵块，能直接缩减张量物理几何尺寸并释放物理显存与算力。

    * **工业实施流程（以 15B 剪为 8B 为例）**：
        * 阶段一（重要性评估）：利用前向校准集输入，统计各网络层与神经元的平均激活能量和信息熵，精确标定对下游任务影响微弱的冗余神经元或接近死寂的通道。
        * 阶段二（物理切除）：将标定的冗余单元从模型架构中彻底移除，物理缩减模型结构。
        * 阶段三（后训练修复，Post-training Recovery）：剪切后的初始子模型精度存在严重滑坡；引入原始未剪枝母模型作为教师网络（Teacher），使用精选领域数据对子模型实施轻量级后训练与知识蒸馏（Distillation）。由于子模型继承了大模型成熟的表征几何，所需微调数据与算力仅为从头预训练同尺寸模型的极小一部分，即可将准确率拉回基准线。

## 无损加速机制与推测解码

### 生成与验证的不对称性机理

* **计算不对称性原理（Computational Asymmetry）**

    * > **定义**：因果自回归模型逐字串行生成时受限于内存带宽而极其低效，但在批量并行验证已知候选序列时算术强度极高、极其高效的物理特性。

    * **单步生成开销**：自回归解码逐字生成时输出长度 $T=1$，受限于显存带宽，生成 $k$ 个词元必须从 HBM 全量读取 $k$ 次目标大模型的全部静态权重（如 70B 模型生成 4 个词元需搬运 4 次全量参数）。

    * **并行验证开销**：给定外部给出的连续 $k$ 个候选词元，目标大模型在单次前向传播中通过一次参数加载即可并行完成这 $k$ 个位置的特征提取与打分。计算处于 Prefill 状态，算术强度高，可打满 Tensor Core 算力核心。

### 推测解码算法与广义拒绝采样

* **推测解码（Speculative Decoding / Speculative Sampling）**

    * > **定义**：由参数量小的轻量草稿模型先行快速生成多个候选词元，再由目标大模型通过单次前向并行验证并通过改进型拒绝采样裁决接受或修正的无损推理加速算法。

    * **系统角色设定**：
        * **草稿模型（Draft Model，记为 $P$）**：参数量极小、运行轻快廉价的模型（可通过轻量剪枝、蒸馏或小型同族模型构建）。
        * **目标模型（Target Model，记为 $Q$）**：参数量庞大、精度高但单步解码极慢的大尺寸模型。

    * **执行流程与判定规则**：
        * 步骤一（草稿生成）：草稿模型 $P$ 基于当前上下文 $x_{<t}$，自回归快速串行生成 $k$ 个候选词元 $(x_1, x_2, \dots, x_k)$。
        * 步骤二（并行验证）：目标模型 $Q$ 将上下文与 $k$ 个候选词元拼接，通过单次前向传播并行导出各个候选位置的目标条件概率分布 $Q(x)$。
        * 步骤三（逐位裁决）：对 $i = 1$ 至 $k$ 逐一判定接受概率：
          $$\alpha_i = \min\left(1, \frac{Q(x_i)}{P(x_i)}\right)$$
        * 步骤四（接受或修正退出）：
            * 从均匀分布 $U[0, 1]$ 采样随机数，若小于等于 $\alpha_i$，则正式接受候选词元 $x_i$，推进至下一位置判定；
            * 若在某个位置 $x_i$ 遭遇拒绝，立即截断审查并废弃后续草稿，从修正后的残差分布（Residual Distribution）中采样出一个全新的确定词元作为该步输出：
              $$Q'(x) = \frac{\max(0, Q(x) - P(x))}{\sum_{x'} \max(0, Q(x') - P(x'))}$$
              随后结束本轮验证，推进至下一轮迭代。

    * **数学无损结论**：经广义拒绝采样判定后最终输出的 token 序列，其联合概率分布在统计学与信息论上与纯粹由目标大模型 $Q$ 逐字自回归生成的理论分布**严格等价**。推测解码属于完全无损的加速方案。

```text
推测解码流水线 (Draft Length k = 3):
Draft Model P (轻快生成):   [ Token 1 ] ──> [ Token 2 ] ──> [ Token 3 ]
                                  \            \            \
Target Model Q (单次并行验证): [ 验证 T1 ]  [ 验证 T2 ]  [ 验证 T3 ]
                                  ↓            ↓            ↓
判定逻辑:                       接受!        接受!        拒绝! (触发重采样退出)
```

### 超参数权衡与工程边界

* **草稿长度选择规则（Draft Length Tuning）**

    * > **定义**：在推测解码单轮循环中草稿模型预先生成的候选词元数量 $k$ 的配置取舍策略。

    * **取值边界权衡**：
        * 若 $k$ 设定过小（如 $k=1$）：目标模型在 Prefill 验证时的批处理并行潜力未充分激活，系统获得的净加速比极其有限；
        * 若 $k$ 设定过大（如 $k=8$）：根据联合概率乘积规律，随着自回归步数推进，小模型与大模型的表征漂移加剧，后段词元被拒绝的概率呈指数级攀升，小模型空耗算力生成无效词元。

    * **工程经验基准**：在典型服务器端部署中，草稿长度 $k$ 通常配置为 3 至 4。当草稿模型与目标模型对齐良好时，每轮大模型验证平均可稳定接受 2 至 3 个词元，系统端到端单请求延迟可直接获得 2 倍以上的实质性加速。

## 运行时动态调度与显存分页管理

### 批处理调度演进与动静分离

* **连续批处理（Continuous Batching）**

    * > **定义**：将请求调度与生命周期管理的粒度从宏观“请求级”下沉至微观“迭代步（Iteration）级”的动态批处理调度机制。

    * **传统静态批处理缺陷**：由于不同请求生成长度非均匀，系统被迫插入大量 `<pad>` 填充占位符，且短请求必须死锁显存并等待批次内最长序列生成完毕方可退出，算力与显存闲置浪费严重。

    * **迭代级调度机理**：在每个单步解码前向计算结束后，调度器即刻审查批次内所有活跃请求的状态。若请求遇到终止符 `<eos>` 或达到最大长度限制，立即逐出当前批次并释放其显存；等待队列中的新就绪请求在该计算周期被即时装填入空缺槽位，使硬件计算核心持续维持流水线饱和。

```text
静态批处理 (Static Batching) 资源浪费:
Request 1: [ Token 1, Token 2, EOS ] [ PAD, PAD, PAD, PAD ] ──> 严重闲置等待!
Request 2: [ Token 1, Token 2, Token 3, Token 4, Token 5, EOS ]

连续批处理 (Continuous Batching) 动态插拔:
Step 1: [ Req 1 (T1), Req 2 (T1), Req 3 (T1) ] ──> 执行解码
Step 2: [ Req 1 (EOS-退出!), Req 2 (T2), Req 3 (T2) ] ──> 移出 Req 1，新请求 Req 4 动态插入!
Step 3: [ Req 4 (Prefill), Req 2 (T3), Req 3 (T3) ] ──> 显存与计算资源始终被打满
```

* **选择性批处理（Selective Batching）**

    * > **定义**：针对非均匀长度序列，在注意力算子与前馈网络算子之间采用差异化张量排布的批处理优化机制。

    * **分层执行规则**：
        * 注意力层：因强依赖于序列内部的私有因果掩码与非连续历史上下文，采用专门的非连续索引和局域掩码进行独立计算；
        * MLP 前馈层：占模型前向总 FLOPs 的约三分之二，各词元之间的线性变换完全相互独立无横向交互。系统剥离所有外部 Padding 占位符，将当前步全部活跃序列的有效 token 展平拼装为一个形状为 $(\sum B) \times D$ 的紧凑二维大张量，直接调用底层高效 GEMM 算子执行大尺寸矩阵乘法，恢复高算术强度。

### 显存虚拟分页管理

* **分页注意力（PagedAttention）**

    * > **定义**：借鉴操作系统虚拟内存分页哲学，将大语言模型序列的 KV Cache 离散切分为固定大小的内存块并通过页表映射寻址的显存管理算法。

    * **传统连续分配的碎片危机**：
        * 内部碎片（Internal Fragmentation）：系统无法预知请求最终生成长度，被迫按上下文上限（如 2048）静态预分配连续物理显存。若请求仅生成 20 个词元即断开，后续 99% 的显存被圈占闲置，实际显存利用率长期仅为 20%~40%。
        * 外部碎片（External Fragmentation）：不同请求频繁申请和释放非均匀大小的连续显存块，导致全局空闲物理显存高度碎片化，无法拼凑出满足新请求的连续物理空间，引发假性显存溢出（OOM）。

    * **物理块池与块表寻址机理**：
        * 逻辑分块：将序列连续的上下文 KV Cache 拆解为固定大小的逻辑块（Logical Blocks，业内通常每块容纳 4 或 16 个 token）。
        * 物理块池（Physical Block Pool）：在底层物理显存中统一开辟预分配的离散物理块池。
        * 块表寻址（Block Table）：维护动态页表，记录逻辑块与离散物理块的映射关系。当自回归生成跨越当前块容量时，显存管理器才按需从物理池中动态申领一个新的物理块填入块表。系统物理显存浪费率被严格截断在最后一个未填满物理块的局部边缘，整体显存利用率逼近 96% 以上。

    ```text
    逻辑序列视图 (Logical Tokens):
    [ Token 0, 1, 2, 3 ]  ──>  逻辑块 0  (映射到) ──>  物理块 7 (物理地址 0x3000)
    [ Token 4, 5, 6, 7 ]  ──>  逻辑块 1  (映射到) ──>  物理块 2 (物理地址 0x0800)
    [ Token 8, 9, ...  ]  ──>  逻辑块 2  (映射到) ──>  物理块 15(物理地址 0x7200)

    物理显存分布 (Physical HBM Layout):
    [ 块 0: 空闲 ] [ 块 1: Req B ] [ 块 2: Req A 逻辑块1 ] ... [ 块 7: Req A 逻辑块0 ]
    ```

* **结构共享与高级内存复用机制**

    * **公共前缀缓存（Prefix Caching）**：在大量企业级业务中，海量并发请求共享一段冗长繁复的系统提示词（System Prompt）。在 PagedAttention 下，System Prompt 对应的 KV Cache 物理块只需在首次预填充阶段计算并写入显存一次，后续所有并发请求的逻辑块表直接建立指向该公共物理块的只读映射指针。数以千计的并发连接在此处实现零显存冗余共享，并彻底免除重复的 Prompt Prefill 计算。

    * **写时复制（Copy-on-Write，CoW）**：
        * 触发场景：束搜索（Beam Search）、多候选采样（Best-of-N）及智能体树状思考展开等单 Prompt 派生多分支生成的任务。
        * 执行机理：各分支在尚未产生输出分歧前，逻辑块表共同指向同一组只读物理块；一旦某个生成分支采样出一个截然不同的新词元，显存管理器立即在底层深拷贝复制出发生变异的单个物理块并由该分支独占改写，其余未变异历史块继续保持全分支共享，大幅压低分支采样的显存开销。

## 推理系统本质瓶颈与原生架构演进

### 自回归推理瓶颈因果拓扑

* **推理系统本质物理约束链**

    * > **定义**：由 Transformer 模型架构先验设计引发的推理效率物理瓶颈因果传导路径。

    * **约束传导逻辑**：
      Transformer 架构为训练并行设计 $\to$ 自回归推理因果依赖导致生成输出长度固定锁死为 $T=1$ $\to$ 解码阶段注意力算子理论算术强度严格小于 1 FLOP/Byte $\to$ 整个系统深陷物理内存带宽受限（Memory-bound）死锁 $\to$ 并发批处理提升受制于显存容量墙（Capacity Wall）。

    * **工程补丁本质**：现有的 GQA、MLA、连续批处理、PagedAttention 与推测解码，本质上均是在现有训练优先架构（Dense Causal Attention + 静态参数）之上构建的工程缓解手段，未能消除 KV Cache 对长序列与高并发的内在瓶颈。

```text
 Transformer 自回归生成
           |
           v
 输出长度固定锁死为 T = 1
           |
           v
 解码阶段注意力算术强度 < 1 (FLOPs/Byte)
           |
           v
 系统陷入极端内存带宽受限 (Memory-bound)
           |
           +---------------------------------------------+
           |                                             |
           v                                             v
  [系统级补救]                                  [算法级压缩]
  * 连续批处理 (Continuous Batching)            * 头数压缩 (GQA) 与潜变量压缩 (MLA)
  * PagedAttention 显存虚拟分页                 * 精度量化 (GPTQ, AWQ) 与结构化剪枝
  * 推测解码 (Speculative Decoding)             * 局部窗口与稀疏混合架构
```

### 面向推理的原生架构探索路径

* **推理原生架构演进方向（Inference-native Architectures）**

    * > **定义**：旨在从根本上抛弃自回归串行依赖或消除无限膨胀的显式 KV Cache，为低延迟、高并发推理原生设计的下一代模型架构。

    * **状态空间模型（SSM）与线性注意力**：以 Mamba、DeltaNet 等为代表，通过循环状态转移方程将全量历史上下文压缩进固定尺寸状态矩阵中，解码步进内存与计算复杂度恒为 $O(1)$，彻底终结显式 KV Cache 存储。

    * **全注意力与递归状态混合架构（Hybrid Architecture）**：针对纯 SSM 模型在极端长程精准定位与大海捞针检索中的信息论压缩衰减缺陷，将绝大多数网络层设计为 SSM/滑动窗口层、在关键间隔层周期性混编全注意力层，兼顾常数解码性能与精准长程回溯能力。

    * **非自回归扩散模型（Diffusion for Text）**：彻底推翻因果自回归时序串行机制，在推理阶段实现全序列 token 的一次性并行去噪迭代生成，彻底释放硬件高维矩阵乘法算力。
