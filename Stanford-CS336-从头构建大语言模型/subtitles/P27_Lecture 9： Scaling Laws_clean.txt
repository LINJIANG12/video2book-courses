critical batch 算是个经验法则，或者说是一个折中点。到了这咱们就该开始从那种完美的 scaling regime 过渡到低效 scaling batch size 的倍数，对吧？也就是说训练步数乘以 batch size 就等于样本总量。经过一些计算，OpenAI 的 McCandlish 等人提出这大概就是我们该遵循的函数形式。你需要的步数和样本数与 Smin 即理论上可能的最小步数是成反比的。这里用最小样本数对这两个量做了归一化处理。所以这两者之间有个权衡对吧？如果你想减少样本量就得增加步数。反之，如果你想减少步数就得用更多的样本，对吧？这是个很自然的权衡。如果你调大或调小 batch size，这个权衡就会向某一边倾斜。现在他们认为当下的目标应该是平衡这两方面，我要确保步数项和样本数项大致平衡。解这个方程你会得到这个特定解：临界 batch size 那为什么这会在讲 scaling law 的课里提到呢？其实到现在为止，这跟 scaling law 没什么直接关系。把它放在 scaling law 讲座里，首先是因为临界 batch size 是个挺合理的 batch size 选择。这个 batch size 能在收敛速度和 batch size 大小之间取得平衡。所以如果我想把 batch size 设为临界 batch size，你可能会问，随着目标 loss 的变化，这个数值会怎么变？

你可以把目标 loss 看作计算量。如果我想让模型越来越好，我该用多大的 batch size？把它放进 scaling law 讲座里是，因为随着 loss 降低，也就是你的 loss 变好了，临界 batch size 的量会增加，而且它以一种非常可预测的方式增长，这又是个 power law，对吧？所以他们论证的这个关系大致上是反多项式形式的。这就在 batch size 的方面。

所以鉴于此，这其实挺不错的，因为它意味着如果你进行超大规模训练，一直跑到图表的最右侧，batch size 可以设得很大。这很合理，当你越来越接近最小值时，方差减少的收益会变大，因为你正在优化越来越细微的目标。当你开始最小化那些极其微小的差异时，噪声的影响就大得多了。好，batch size 这边就讲完了。

那另一边呢，所以你要记住，你始终需要调的两个量就是 batch size 和 learning rate。Learning rate 这边也稍微有点复杂。关于这点，我会在进阶的 scaling 课程里详细展开。不过学习率通常会变动。我觉得用这个思路来理解标准场景下的学习率很直观。假设你用的是个多层感知机 MLP，对吧？就像某种标准的神网络，我不做深度缩放，只做宽度缩放。如果我做宽度缩放，模型越大，学习率就得设得越小。学习率得设小点是因为参数更多、规模更大了。我一次性改动的东西更多了，也许步子该迈小点，这逻辑挺通顺的。事实上，有个经验法则，你可以试着按宽度的倒数来调整。这是个很常见的经验法则，随着网络变宽，要相应地调低学习率。这样你就有了缩放学习率的依据。

不过还有另一派思路、另一套技巧，就是人们还会用各种方式对网络本身进行重新缩放。他们会改变初始化的大小，还会针对网络的不同部分调整优化器的步长，目的是迫使模型在不同规模下都保持相同的最优学习率点。这种思路被称为 $\mu P$，还有其他类似的方法。有人报告说这类方法效果显著，也有人报告说效果没那么好。
