今天咱们聊聊数据。我们现在所处的阶段是大家已经知道怎么训练模型了。
有了数据，上次咱们还讲了评估，所以也清楚什么样的模型算好模型。这周剩下两节课，咱们重点讲讲该用哪些数据来训练。我想强调一点：在语言模型里，数据是最关键、最需要搞对的部分。咱们看看各大公司实际披露的信息，就能明白为什么这么说。
以 Llama 3 论文为例，他们对架构完全透明，当然了，毕竟这是个开放权重模型。他们连训练流程都告诉你了，但关于数据却只字未提，他们只是说“我们用了各种各样的数据来源来训练，顺便做点别的”。之所以要保密，是有充分理由的。
首先，数据在某种程度上是你的独门竞争优势，关乎竞争格局，你当然不希望竞争对手摸清你的底细。第二点我们稍后细聊，就是版权责任问题。如果你公开宣称自己在用某些特定类型的数据做训练，那就容易招致诉讼。
所以在机器学习里，数据是个能展开讲很久的大话题。在 Foundation Models 出现之前，数据工作主要就是为 Supervised Learning 标注数据。而手动标注的工作量减少了（至少在 Pre-training 阶段如此），但是数据的筛选和清洗工作依然繁重。
所以从根本上说，这一点其实没怎么变，数据一直是瓶颈，将来也还是瓶颈，因为从某种意义上说，这就是一个随人力投入而放大的长尾问题。如果很多人都想解决同一个问题，能参与架构和系统工作的人毕竟有限，但数据就不一样了。尤其是训练那种想要包揽所有这些任务的 Foundation Model 时，你可以轻松地把这项工作并行化，让很多人同时分担。所以，这就是为什么数据团队和模型开发团队通常都相当庞大。
数据会在管道的不同阶段被引入。今天我们主要关注 Pre-training。在 Pre-training 阶段，你使用的是原始数据，比如来自网络的文档。
接着进入 Mid-training，在这一阶段你使用更高质量的数据进行训练，以增强特定能力，比如支持长上下文。
最后是 Post-training。在此阶段你使用聊天 transcript 这类数据进行训练。如果你在做 Reinforcement Learning，则会用到一些特定的环境来训练。这一阶段的任务针对性更强。实际上各阶段的界限可能有些模糊，阶段数量也可能超过三个，但这只是一个基本框架。
目前的趋势是：训练数据从大量低质量数据逐渐转向较小规模的高质量数据。
经过这个过程，你在文献里会看到有人会提到 Base Model，通常指 Pre-training 和 Mid-training 之后的阶段；而 Instruct Models 或 Chat Models 都是在 Post-training 之后。但当然，界限已经变得相当模糊，现在什么才算 Base Model 其实已经不太清楚了。而且最近最大的那些模型根本就没有 Base Model，只有 Qwen-2.5-72B 就是这样，你看不到中间的 checkpoint。
所以对于开源模型，比如 AI2 的 OLMo，你能看到其中发生的一切。
Pre-training，稍后我们会研究其中一些模型。比如在 Pre-training 阶段，数据来源有很多，我们稍后会讲这些来源的涵义，其中就有这么一些：网页、学术论文、数学页面、证明等等。
中训练阶段则使用更高质量的网页数据、指令数据，通常还会加入大量合成数据。
最后是 Post-training。这个阶段会用到大量数据，比如对话日志，还有更多数学推理和编程内容，同时也会在这个阶段做安全方面的处理。
那这些数据集具体是哪些？咱们该怎么挑，又该怎么处理它们呢？这正是核心问题所在。
好，咱们就顺着这门课的思路来聊聊数据。咱们从头说起：数据到底从哪来？
咱们平时在走廊里聊天常会听到一种说法：语言模型是用整个互联网的数据训练出来的。首先，这种说法其实不太站得住脚。这样那样，模型就得是个 RL agent，能在网上到处跑、执行各种操作才行。但 Pre-training 的实际运作方式并非如此。更准确地说，它是在全球公开网络上训练的。不过，这话也不完全准确，原因我待会儿解释。
首先呢，网络其实就是世界上的一堆正在运行、你能连上去的服务器。所以随便找个网站，你都能去下载它的页面，说白了就是发个请求，然后拿回响应。除非你在训练一个 RL agent，否则你没法直接拿这些在线服务器来训练模型。
所以一般是你自己有个爬虫，或者是别人搭好的爬虫，反正不一定是你亲手建的。爬虫得从前面说的那个种子集开始，去把现有的网页都找出来，一边爬，一边把找到的页面下载下来。但你不能指望跑一次爬虫就把互联网上所有的网页都下载下来。
原因有好几个。首先，网上很多内容其实是动态生成的。特别是现在好多网站其实就是 app，URL 甚至没法完整地描述内容，它只是个供你交互的 app。你得经常点按钮或者填表单才能看到里面的内容。打个比方，你在用 Discord 的时候可没法直接拿 curl 去抓它的数据，把上面的东西全弄下来。这是一种情况。
另外，很多内容其实藏在深网里，光靠传统的网页爬取和点超链接是搞不定的。这就是那种很传统的网页爬取模式。
第二点是身份验证，有些页面得登录账号才能看。一般来说你还得花钱，比如像 Facebook、X、LinkedIn、《纽约时报》这些。其实有大量内容都被锁在围墙花园里，你进不去。所以虽然从技术上说这些内容确实在互联网上，但你不能随便搭个爬虫就去抓 Facebook 的数据。我猜如果你是 Facebook 的话，你可以去爬取，不过其实你不需要爬 Facebook，因为你手里就有数据，直接拿这些数据训练模型就行。或者如果你是 xAI，你可以拿 X 平台的数据来训练。但要是换作别人，你就没法真正用到这些内容。
咱们先假设不存在身份认证的问题。不过这里还有潜在的限制，比如有个叫 robots.txt 的文件。这个文件一般放在网站根目录下，比如 nytimes.com，它基本上会告诉你哪些内容允许抓取，哪些不行。所以很多内容是被禁止抓取的，比如 OAI-SearchBot、PerplexityBot、CohereBot，我记得还有 ChatGPT-User、ClaudeBot 等等这些。
所以这不算……这不是法律层面的限制，这更像是说你应该自觉守规矩去瞄一眼 robots.txt，如果你的名字在那份名单上，就不该去抓取。这基本上算是个契约，甚至算不上契约，它就是这么个东西，这就是你该做的事。
现在很多网站会用 Cloudflare 之类的工具来检测并拦截机器人流量。有时候你访问网站会弹出一个验证码，对吧？那是某种算法检测到你可能是机器人，于是要先确认你是真人。要是你真是个机器人，那你就过不去了。我是说你可以试着绕过它，但通常是个障碍。网站可能会封掉某些 IP 或国家，还会限制请求频率。所以你在实际爬取时会碰到技术上的限制。
另外还有法律层面的限制。网站的服务条款规定，你访问网站就得遵守这份合约才能使用。条款里通常会说，如果是机器人就请离开，你不能拿网站的内容去做 AI 训练之类的事。
还有，就算服务条款没提这一点，网站内容也可能有自己的许可证，或者你根本没拿到训练授权。我们待会儿再细说。总之，你能拿什么数据来训练是有法律红线管着的。
这事也在不断变。Shayne Longpre 写过一篇很好的论文叫《危机中的同意》。他们研究了常见数据里各种网址的限制，既有 robots.txt 这种技术层面的，也有服务条款这种法律层面的。这个我们后面再聊。结论就是限制越来越多了。
看这张图，上面那部分展示的是 robots.txt 的情况。你看那块红色区域代表的是完全限制。在 2023 年之前，情况一直挺稳定的，但到了 2023 年年中，受完全限制的网站比例突然飙升，几乎到了 40%、50%。服务条款这边趋势也差不多。回想 2016 年，那时候几乎没人会在网页上写什么使用条款；而现在大多数网站都有条款了，而且大部分都明确写着不能拿这些内容用于 AI。
就算在 2020 年那会儿爬取互联网在技术上还是行得通的，但实际上，至少就你能合法爬取的那部分而言，互联网要小得多。当然这些只是一些指导原则，而有时候不管是有意还是无意，你都可能会违反它们。
所以有时候你就会遇到这种情况，有这么一个人……那个谁，叫什么来着？我忘了那个网站叫什么了，他在抱怨 Anthropic 爬他的数据，24 小时内访问了他们的服务器 100 万次，这可不太好。然后 Read the Docs 也被狂刷。所以有那么一阵子（我觉得现在应该已经好转了），爬虫一直在疯狂冲击各个网站。
这是个挺有意思的点。在谈版权问题之前，我觉得爬取本身就有问题，因为你要么违反了服务条款，要么无视了 robots.txt，或者简单来说就是让系统过载。这会消耗大量服务器资源，不仅增加了托管方的成本，也拖累了其他用户的使用体验。因此爬取过程中会遇到各种问题。
当然还有版权问题，我们稍后会详细讨论，那是另一个复杂的难题。
最后还有所谓的影子图书馆，它们也是互联网的一部分，比如 LibGen 或者 Anna's Archive。他们完全无视版权并绕过付费墙。有人收集了海量受版权保护的数据，通常是书籍和文章，这些内容本来需要付费，却被免费公开了。这类站点面临过很多下架令和诉讼，也一度被封禁，但通常都能被规避，因为他们往往把服务器设在其他国家。做这件事的人辩称，他们只是让本应免费的内容回归免费；但从法律角度看，这通常被视为盗版和侵犯版权。我们待会儿再回到这一点。关于这些影子图书馆，已经有很多书和论文了。
咱们先总结一下，到目前为止，互联网是个巨大、杂乱，而且说实话挺吓人的地方。而且你其实没法把里面的内容全都拿到。这里有技术上的限制，也有法律限制，规定了你能访问哪些数据。所以下次有人跟你说“我是用互联网数据训练的”，你就可以把学到的这些东西讲给他们听。
接下来咱们进入第二部分：咱们能用哪些数据呢？这就涉及到版权问题了。
假设你乖乖遵守了服务条款，而且你真是个守法公民，严格遵守了速率限制。不过现在还有个问题：你究竟能不能拿这些数据来训练模型？这个问题到现在还没彻底解决，不过过去一年里倒是有不少新进展。
所以咱们得从知识产权法的角度来理解这个问题。你看，这套制度体系的核心目的就是鼓励大家去创造智力成果。所以我觉得咱们得记住法律背后的精神，也就是说别光从技术层面对应什么都说“不”，关键是要鼓励大家去创造智力成果。
知识产权的形式很多，比如版权、专利、商标，还有商业秘密。对于语言模型的数据来说，最相关的就是版权法。
版权法的历史挺长的，最早能追溯到 1710 年代的英国。1709 年是政府和法院第一次真正为了激励创新和创作这个目标去监管版权。而在美国比较近的 1976 年版权法，我觉得它定义了现代版权的很多方面。因此版权保护适用于固定在任何有形表达媒介中的原创性作品，诸如此类。
懂了吗？这里说几点：不是所有东西都能受版权保护，特别是汇编作品不受版权保护。打个比方，电话簿本身就不受保护，除非你在编排方式上花了心思、体现了创意。还有，版权保护的是表达而不是思想本身等等，所以你没法给一个想法申请版权，就像你没法给快速排序算法申请版权一样。可以给快速排序算法的实现代码加版权保护，但算法本身不行。
1976 年法案起，有个变化就是申请版权的门槛降了很多，所以能受版权保护的东西变多了。以前你得把东西发表出来才算有版权，现在只要把内容固定下来就行。也就是说，想要版权保护根本不用去做任何注册。这和专利就不一样了，专利你得花一大笔钱去申请、去提交。但版权的门槛特别低，比如你把东西放到自己网站上，它就自动受版权保护了，就这么简单。
现在想告人的话得先去登记版权，不过这只要 65 美元，比请律师的费用低多了，所以这个门槛其实真的很低。
版权有个特点，保护期是 75 年。过了这七五百年，版权就失效了，作品进入公共领域，大家都能随便用。很多以前的人，他们那些伟大的作品现在都进入了公共领域，这对大家都很好。
初衷就是为了鼓励创新。艺术家或创作者做出了作品，你会想保护他们，不想让别人就这么拿走。所以保护也就一阵子，过了 75 年可能就没必要再保护了，或者作者也去世了，所以在死守版权也没意义。
你看，基本上网上所有内容都受版权保护。等等，你的意思是如果我拿任何数据来训练就算侵权？倒也不全是。虽然都有版权，但你依然可以使用这些受保护的内容。
主要有两种途径：第一，获取授权许可；第二，援引合理使用条款。
简单来说，许可属于合同法范畴，是许可方授予被许可方的授权。它的意思就是“别告我”，你可以按许可规定的范围使用这个作品。比如有个很棒的许可叫知识共享（Creative Commons），它能让作品像进入公共领域一样自由使用。它让受版权保护的作品得以免费传播，比如维基百科、开放课程资源（OpenCourseWare）、可汗学院都是这类例子。它是在 2001 年建立的，主要是为了在公有领域和现存版权之间架起桥梁，不然的话你得等上 75 年。但如果创作者说“其实我想让大家用我的作品呢”，他们现在有了办法，以一种合法的方式来声明：我给它加了知识共享许可协议。它就像是在公有领域里一样，大家都能随便用。
到目前为止公有领域的东西和那些有知识共享许可的东西都属于比较宽容的类型，你可以用它。但还有很多其他情况，既没有知识共享许可，也不在公有领域里，这时候你就得去拿许可。如果你有预算，你可以花钱买许可。所以模型开发者和内容平台之间签了不少协议，让开发者能拿到数据去训练模型、造 Foundation Models。
这是第一点，你可以申请许可，要么是知识共享许可，要么花钱买授权。
现在如果你不想花钱，你可以主张合理使用，不过这事比较复杂。这是版权法第 107 条。简单来说合理使用原则就是说：就算我没拿到授权，我照样能用。
能否适用合理使用主要看四个因素：
1. 第一个因素就是看你的使用目的或性质，比如你想拿它来做什么。这些都不是硬性规定，它们只是一些倾向，真要闹上法庭，就得在法庭上权衡。打个比方，如果你是为了做教育，比起拿去卖钱赚利润，更有可能被认定为合理使用。如果你做了转换性使用，就比单纯原样托管一模一样的副本更有利。
2. 受版权保护的作品本身的性质也很重要。所以跟虚构作品比起来，事实性更强的内容更容易被认定为合理使用。写一篇二战总结、写一页关于二战事实的内容，它受到的保护就不如那些真正有创意的诗多。
3. 还有你用了原作的多少内容。只用一小段比把整部作品都用上更受认可。所以只拿一小部分总比全拿走要好，这点挺好理解的。
4. 最后一点跟最初的动机有关。当时大家就在想到底为什么要有版权？是为了保护以及协调好经济激励，即使用行为对原作市场产生的影响。如果你用了某位作者的作品提供了一个替代品，导致原作没法再像以前那样靠作品赚钱，这就会被视为有问题。但如果你是对它做了改造，加了新东西，比如开拓了新市场，或者用它做了别的处理，那情况就会好得多。
这里举几个合理使用的例子：看一部电影然后写一篇摘要；你可以重新实现一个想法，比如算法，但别直接抄代码。然后就是那场著名的官司：作者协会告谷歌。你去 Google Books 看看就能看到各种有版权的书的片段。这事当时闹得挺大，当时有个争议焦点在于这算不算合理使用，毕竟你在某种程度上是在重新分发内容，涉及其他受版权保护的作品。最终（也就是过了 11 年之后），这场官司以谷歌胜诉收场，这也是为什么会有现在这个产品。这为思考语言模型训练是否构成合理使用确立了一些先例。
有一点需要注意，版权保护并不只是针对逐字记忆。所以我觉得这对机器学习领域的听众来说可能有点新鲜，因为很多论文都聚焦于逐字记忆，但这只是侵犯版权的一种方式，并非唯一方式。比如故事情节和角色设定是可以受版权保护的，也就是说你可以复制哈利·波特这个角色，而侵权点不在于某本特定的书或其中的具体内容。
不过也有例外情况，比如你是在搞戏仿，虽然看起来像是衍生作品，但只要你是在调侃它，反而更可能被算作合理使用。所以你看很多讨论其实都集中在语义上，这肯定……

那么，这对应于模型有什么影响呢？

首先，复制数据，就算你没拿来训练，光是复制这个动作本身，就像 copyright 这个词里就含着 copy，哪怕你什么都没做，光复制这件事可能就已经构成侵权了。

行，训练模型，我猜这个嘛……让我想想这该怎么说呢。虽然这不一定是事实，但直觉上确实有种变革性的味道，对吧？毕竟它看起来和单纯把别人的工作搬过来可不一样。它是在做一些真正具有变革性的事情，还有某种程度上说，模型训练这些数据只是手段而非目的。你的目标是提取通用概念，去理解世界是怎么运作的，而不是只盯着那些具体的表达形式。另外，不管版权怎么算，语言模型确实会对市场产生影响，所以我想说的是别忘了这是关于合理使用的第四点。

所以爬取在概念上很简单，但具体的复杂细节全在实现里。你从一堆 URL 开始，然后不断迭代，这本质上就是图遍历。你从队列里取出一个 URL 下载它，看看页面上有哪些超链接，然后把它们加到队列里。一般来说这都是在多台机器上并行处理的，这就涉及到很多决策，比如该下载哪些页面。你得遵守 robots.txt 规则，别把服务器压垮了。网站有时候会变，所以你得定个下载策略。页面要是老变，你就得下载，但别在那死磕那些根本没变的页面，所以这就得靠策略来管了。另外就像我之前说的，URL 是动态的，所以你看同一个 URL 有时会根据浏览器状态显示不同内容，但反过来很多 URL 可能都指向同一个内容。所以你要是没留神，重复内容就多了，尤其是镜像站点，那本来就是搞重复的。

Common Crawl 发布转储数据时有两种格式，一种是 WARC 文件，也就是原始的 HTTP 响应。对，大家记得 HTTP 协议就是你发一个 GET 请求，你看你给一个 URL 它就返回一个 HTTP 响应，而 WARC 文件就是这个响应。他们还会做一些处理把它转换成 WET 文件，而这必然是一个有损的过程。结果发现这未必是利用网络最好的方式，把 HTML 转成文本有很多工具可以用，比如 Trafilatura 和 Resiliparse。转换方式其实很重要，这出自 DataComp-LM 论文，我们待会儿会稍微讲一下。就是一个消融实验对比 Common Crawl 发布的网页文件和其它这些文件，比起这些其它工具，看起来 Trafilatura 和 Resiliparse 更好一些。
