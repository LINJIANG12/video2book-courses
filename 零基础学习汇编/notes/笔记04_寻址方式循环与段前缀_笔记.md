# 寻址方式、循环与段前缀

## 内存单元的地址与类型

* **内存单元地址（address）**

    * > **定义**：描述一个完整的内存单元需要两种信息——内存单元的地址，以及内存单元的长度（类型）。
    * 没有地址就无法找到该单元在哪。
    * 在十六位环境里，`[0]` 这种写法中的数字就是偏移地址，段地址默认存在 DS（数据段寄存器）中，这个单元记作 `DS:0`。

* **内存单元长度（类型）**

    * > **定义**：取字节型还是字型数据，由指令里的另一个操作数指出。
    * 十六位环境中，字节型数据取 8 个 bit，字型数据取两个字节、16 个 bit。
    * `mov ax, [bx]` 的另一个操作数 AX 由 AH、AL 拼成共 16 位，`[BX]` 指向字型单元（2 字节）。
    * `mov al, [bx]` 的另一个操作数 AL 为 8 位，`[BX]` 指向字节型单元（1 字节）。
    * > **提示**：同一个 `[BX]` 配 AX 就是字、配 AL 就是字节；单元类型不是它自己决定的，是被旁边那个操作数带出来的。

## 描述性符号 [ ]

* **中括号（描述性符号）**

    * > **定义**：汇编里的 `[ ]` 表示一个寄存器或者一个内存单元中的内容。
    * AX 的内容是 `00010H`，写成 `[AX] = 00010H`。
    * `21000H` 这个内存单元的内容是 `00010H`，写成 `[21000H] = 00010H`。
    * `[2]` 的定位过程：先取段地址寄存器乘 16（十六进制里就是左移一位），再加偏移量 2 定位到目标内存单元，最后取它的内容。
    * > **易错点**：`[ ]` 不是数学括号，不表示"先算括号里"；`[AX]` 说的是"AX 里的内容"，而不是"AX 的地址"。

* **物理地址的形成**

    * 物理地址 $= 段地址 \times 16 + 偏移地址$。
    * 段地址乘 16 在十六进制里表现为左移一位，在二进制里为左移四位。

## 用 BX 表示偏移地址

* **idata（常量占位符号）**

    * > **定义**：idata 是表示常量的符号。
    * `mov ax, idata` 代表 `mov ax, [1]`、`mov ax, [2]`、`mov ax, [3]` 这一类写法——只要那个位置放的是常量，就可以用 idata 占位。

* **[bx] 寻址**

    * > **定义**：`mov ax, [bx]` 把 BX 中存放的数据当作偏移地址，段地址默认在 DS 中，把 `段地址:偏移地址` 处的数据送入 AX。
    * 关系式：AX 的内容等于 DS 乘 16（DS 左移一位）再加 BX 的内容。
    * `mov [bx], ax` 反过来用同一套寻址：以 BX 的值为偏移地址、段地址默认在 DS，把 AX 中的数据送入该内存单元。
    * 它和 `[idata]` 是同一个意思，唯一区别是把写死的常量换成一个寄存器来存偏移地址的值。

* **指令序列与内存变化**

    * 待跟踪的程序：
        ```asm
        mov ax, 2000H
        mov ds, ax
        mov bx, 1000H
        mov ax, [bx]
        inc bx
        inc bx
        mov [bx], ax
        ```
    * 前三条令 `DS = 2000H`、`BX = 1000H`。
    * `mov ax, [bx]` 定位的物理地址 $= 2000H \times 16 + 1000H = 21000H$；目标是 16 位的 AX，所以取一个字型单元，按"高位放高位、低位放低位"读出 `AX = 00BEH`。
    * 两条 `inc bx` 把 BX 从 `1000H` 加到 `1002H`。
    * `mov [bx], ax` 把 `00BEH` 按字型写进 `21002H`。
    * 执行后相关单元内容：
        ```text
        21000H   BE   ← 原单元 00BEH 的低字节
        21001H   00   ← 原单元 00BEH 的高字节
        21002H   BE   ← 写入 00BEH 的低字节
        21003H   00   ← 写入 00BEH 的高字节
        ```
    * 21000H、21001H 是原来的字 `00BEH`，程序没动它；其余单元保持原有内容不变。

## Loop 循环

* **Loop（循环指令）**

    * > **定义**：执行到 Loop 时做两步操作——先把 CX 的内容减 1，再判断 CX 的值。
    * CX 不为零就转到 Loop 后面写的标号处；CX 为零就向下继续执行。
    * 通常用 CX 存放循环次数，想循环 5 次就写 `mov cx, 5`。

* **循环程序框架**

    * 三个要点：CX 中存放循环次数；Loop 标号所表示的地址要放在前面；要执行的循环程序段写在标号和 Loop 指令的中间。
    * 框架：
        ```asm
        mov cx, 循环次数
        标号:
            循环程序段
        loop 标号
        ```

* **标号与地址**

    * 执行循环时 `loop` 后面跟的 `0012` 是标号 `s` 编译出来的地址，也就是循环体第一条指令 `add dx, ax` 的地址。
    * 标号会变成循环体中第一条指令的地址。

## 循环实现乘法与累加

* **用循环算 2 的次方**

    * 一个数的多少次方就是让它自己加多少次；算 2 的几次方，就让这个数自己加几次。
    * 2 的二次方：`mov ax, 2` 再 `add ax, ax` 得 4。
    * 2 的三次方：连续两次 `add ax, ax` 得 8。
    * 2 的十二次方对应写十一遍加法，改用循环：
        ```asm
        mov ax, 2
        mov cx, 11
        s:  add ax, ax
            loop s
        ```
    * 每执行一次 `loop s` 把 CX 减 1；CX 减到 0 时判断为零，向下执行、结束循环。

* **用加法算 123×236**

    * 用加法计算就是让 123 加 236 次。
    * 第一版：AX 先设成 123（相当于已经加过一次），循环再做 235 次。
    * 也可以不占这个便宜，先把 AX 清成 0，循环 236 次。
    * 更快写法：把 123 和 236 反过来，用 236 去累加 123 次，循环次数从 235 降到 123。
        ```asm
        mov ax, 0
        mov cx, 123
        s:  add ax, 236
            loop s
        ```
    * > **提示**：算乘法时被加的数取大、循环次数取小，结果一样，循环却更少。

* **用循环累加做乘法**

    * 题目：计算 `FFFF:0006` 单元中的数乘以 3，结果存储在 DX 中。
    * 边界估算：该单元存的是字节型数据，最大值 255；$255 \times 3 = 765$，不大于 65535（$2^{16}-1$），DX 存得下。
    * 长度匹配：`FFFF:0006` 是字节型单元，AX 是 16 位寄存器，直接按字型取会多取一个字节；借助 AH 与 AL，让 AH = 0、AL = 该单元里的数，AX 就装下这个字节值。
    * 完整程序：
        ```asm
        mov ax, 0FFFFH
        mov ds, ax
        mov bx, 6
        mov al, [bx]
        mov ah, 0
        mov dx, 0
        mov cx, 3
        s:  add dx, ax
            loop s
        ```
    * 运行结果：三次循环后 DX $= 31H \times 3 = 93H$。
    * 改算乘以 123：$255 \times 123 = 31365$，仍在 DX 范围内，只需把循环次数从 3 改成 123；结果为 $31H \times 123 = 178BH$。
    * > **易错点**：汇编源程序中数据不能以字母开头，`FFFFH` 这类以字母开头的十六进制数前面必须补 0 占位，写成 `0FFFFH`；这个 0 只是占位，不是数值的一部分。

* **Debug 加速命令**

    * `G 0012`：让程序直接运行到以该地址为首地址的指令，即 `CS:0012` 处的那条指令，跳过前面的铺垫。
    * `P`：自动执行循环中的指令，直到循环结束为止，一次跑完整段循环。

## 汇编源程序与 debug 的差异

* **mov ax,[0] 的两种含义**

    * 在 debug 里，`mov ax, [0]` 的意思是把 `ds:0` 处的数据送入 `ax`；操作对象是 16 位的 `ax`，取出的是一个"字单元"——从 `ds:0` 开始连着两个字节一起取，拼成一个字。
    * 在汇编源程序里，同一条 `mov ax,[0]` 会被当作 `mov ax,0`，那个 `0` 被当成真实的立即数，相当于把数字 0 放进 `ax`，根本不去碰内存。
    * > **易错点**：`[0]` 在 debug 里是"取出内存单元的内容"，在汇编源程序里却会被编译成"数字 0 本身"；同一份写法，两个环境两种结果。

* **中括号里放什么**

    * 中括号里放寄存器，会把寄存器里的值读出来，再和数据段地址拼合，得到真正的逻辑地址。
    * 中括号里放数字，汇编源程序会把它编译成那个数字本身，而不是偏移地址。
    * > **提示**：中括号里可以放寄存器，但不能放数字；放寄存器会被翻译成"段地址 + 偏移地址"，放数字会被编译成真正的数字。

## 段前缀

* **段前缀（segment prefix）**

    * > **定义**：段前缀是出现在访问内存单元指令里、用于显式指明该单元段地址的段寄存器写法。
    * 访问内存单元的指令里可以显式地给出内存单元的段地址所在的段寄存器。
    * 如果不显式声明用哪个段，默认就是数据段，段地址取 `ds`。

* **用 es 作段前缀**

    * 源单元与目标单元相距大于 64K、落在不同的 64K 段里时，只用一个 `ds` 每次循环都要重新设置，程序虽对但效率低。
    * 优化：用 `es` 存目标空间的段地址（`0020h`），用 `ds` 存源空间的段地址（`ffffh`）。
    * 访问指令：
        ```asm
        mov al, [bx]
        mov es:[bx], al
        ```
    * `[bx]` 不写段前缀时默认走数据段，即从 `ds:[bx]` 读；写 `es:[bx]` 则显式指明目的单元的段地址在 `es` 里，循环里省掉了重复 12 次设置 `ds` 的步骤。

## 连续内存单元的循环访问

* **用 bx 当偏移地址的变量**

    * 用同一种方法处理地址连续的内存单元中的数据，需要用循环解决。
    * 循环要求每次都能按同一种方式改变要访问的地址，此时不能用常量给出内存单元地址，必须用变量（比如 `bx`）。
    * `mov al,[bx]` 里的 `bx` 可以看作代表内存单元地址的变量，不改指令、只改 `bx` 的值就能改变访问的单元。
    * 偏移地址由 `bx` 给出，段地址默认在 `ds` 中。

* **把 ffff:0 到 ffff:b 求和**

    * 题目：把 `ffff:0` 到 `ffff:b` 这些单元中的数据累加起来，结果存到 `dx` 中。
    * 边界：这些单元都是字节单元，共 12 个（0 到 b），每个最大 255；$255 \times 12 = 3060$，而 `dx` 是 16 位、上限 $2^{16}-1 = 65535$，肯定存得下。
    * 不能直接累加到 `dx`：`dx` 是 16 位寄存器，和它运算的操作对象会被当成字型数据，一次取出两个内存单元拼成一个字加进去，与逐字节累加不是一回事。
    * 不能只加到 `dl`：`dl` 是 `dx` 的低八位，最多表示 255；12 个数据累加过程中超过 255 会产生进位，进位在 `dl` 里存不住、会被丢掉。
    * 办法：找一个 16 位寄存器做中介，把八位数据先复制到 `ax` 的低八位 `al`，再把整个 `ax` 加到 `dx` 上；`ax` 与 `dx` 类型匹配，加进去不会丢进位。
    * > **提示**：做赋值之前一定要先把 `ax` 整个置为零——每次只是覆盖 `al`，若 `ah` 里还残留旧数据，加到 `dx` 里的就不是想要的字节值。
    * 程序：
        ```asm
        assume cs:code
        code segment
            mov ax, 0ffffh
            mov ds, ax
            mov bx, 0
            mov dx, 0
            mov ax, 0
            mov cx, 12
        s:  mov al, [bx]
            add dx, ax
            inc bx
            loop s
        code ends
        end
        ```
    * > **易错点**：`ffff:0` 到 `ffff:b` 中的数据都是八位的，不能直接加到 16 位的 `dx` 中；一旦直接加，访问内存时会按字单元来取，白白多取一个字节。

* **地址拼接过程**

    * 段地址乘 16 来自地址加法器的工作方式：把数据段地址取出来向左移一位，得到段基地址，再加偏移地址，才是实际物理地址。
    * 十六进制意义下左移一位等于二进制左移四位，效果是乘 16。
    * 换算示意：
        ```text
        段地址 ffffh
           │  × 16（十六进制左移一位 / 二进制左移四位）
           ▼
        段基地址 ffff0h
           │  + 偏移地址 x
           ▼
        物理地址 ffff0h + x
        ```

* **拷贝一段数据**

    * 题目：把内存 `ffff:0` 到 `ffff:b` 中的数据拷贝到 `0:200`~`0:20b` 这段单元里。
    * 等价关系：`0:200`~`0:20b` 等同于 `0020:0`~`0020:b`，描述同一段内存；换成 `0020:` 是为了让源和目的偏移地址都从 0 开始，共用同一个 `bx`，少用一个寄存器。
    * 循环 12 次，把 `ffff:x` 单元中的数据送入 `0020:x`；不能直接复制，还得用一个寄存器（比如 `ax`）中转，中转完再把 `x` 加一。

## 直接写内存的安全空间

* **随意写入的风险**

    * 在 8086 模式下，随意向一段内存空间写入内容是危险的：这段空间里很可能存放着重要的数据、系统数据或者代码。
    * 不能在没有确认某段内存是否存放着系统数据或代码之前，就随意往里面写内容。
    * 有些程序恰好改到了系统代码所在的位置，于是直接报错。
    * 在 Windows 2000 的 DOS 方式下执行 `mov [0026],ax` 运行在保护模式，每个进程都有自己的虚拟空间，不影响别的程序；但 `0:0026` 处存放的是重要的系统数据，会被改写掉，放到实模式下后果就不同。

* **实模式与保护模式**

    * 在纯 DOS 实模式下，可以不理睬 DOS，直接用汇编操作真实的硬件，因为它运行在 CPU 实模式，DOS 没有能力对硬件系统做全面严格的管理。
    * 在 Windows 2000、Linux 这些运行于 CPU 保护模式下的系统里，硬件已被操作系统利用保护模式提供的功能全面而严格地管理起来，不理操作系统、直接用汇编操作硬件是不可能的。
    * 学汇编是为了获得基本的编程体验、从底层理解计算机，是对硬件直接编程，而不是绕过硬件去迁就操作系统；大多数时候选择自由地、直接地用汇编操作真实的硬件。

* **一块安全的空地**

    * 在一般的 PC 上、DOS 方式下，DOS 和其他合法程序一般都不会使用 `0:200` 到 `0:2ff` 这 256 个字节的空间，用这段空间是安全的。
    * 进 debug 看一眼这段内存的内容，如果全是零，就可以放心往里写。

## 代码段中使用数据

* **dw（define word，定义字型数据）**

    * > **定义**：dw 是 define word 的缩写，意思是定义一个**字型数据**。
    * 一个字型数据占几个字节取决于 CPU 的字长：16 位 CPU 字长为 16 位，占 2 个字节；32 位系统字长为 32 位，占 4 个字节；64 位对应 8 个字节。
    * 八个字型数据一共占 16 个字节。
    * > **提示**：字型数据占几个字节看的是 CPU 的字长，不是数据本身写出来有几位；同样写 `dw 0123h`，在 16 位机上占 2 字节，到了 32 位机上占 4 字节。

* **用 cs:[bx] 累加代码段中的数据**

    * 数据定义在代码段里，程序运行时 `cs` 存放着代码段的段地址，段地址可直接从 `cs` 拿到；数据又定义在代码段最开头，偏移地址就是 0。
    * 用 `bx` 存放偏移地址，用循环累加：
        ```asm
        mov bx, 0
        mov ax, 0
        mov cx, 8
        s:  add ax, cs:[bx]
            add bx, 2
            loop s
            mov ax, 4c00h
            int 21h
        ```
    * 每循环一次 `bx` 加 2，因为每个字型数据占两个字节，相邻两个数据的偏移量差 2。
    * 八个数据的偏移地址依次是 0、2、4、6、8、a、c、e，对应地址 `cs:0`、`cs:2`…一路到 `cs:e`，循环八次完成累加。
    * 小端存放：`0123h` 在内存里写出来是 `23 01`，低位字节在前。

* **数据与指令的分界**

    * 用 `u` 从偏移 0 查看，显示的并不是汇编指令对应的机器码，而是先前用 `dw` 定义在指令前面的数据。
    * 用 `d` 查看前段内容：`2301 5604 8907 bc0a`……正是定义的那些数据。
    * 代码段里前 16 个字节是 `dw` 定义的数据，从第 16 个字节开始才是汇编指令对应的机器码；用 `u 0b3d:0010` 能看到 `mov bx,0`、`mov ax,0`、`mov cx,8`。
    * 分界示意：
        ```text
        cs:0     ┌──────────────────────────┐
                 │  dw 定义的 8 个字型数据   │  ← 偏移 0 ~ f，共 16 字节
        cs:10h   ├──────────────────────────┤
                 │  汇编指令对应的机器码      │  ← 程序真正的指令从这里开始
                 └──────────────────────────┘
        ```

* **start 与 end start**

    * 程序加载后 `ip` 默认是 0，一上来会把数据当成指令执行；在第一条指令前加标号 `start` 并把结尾 `end` 写成 `end start`，`cs:ip` 才会第一次就指向第一条指令。
    * 标号 `start` 在编译时被转换成地址。
    * `end` 除了通知编译器程序结束，还通知编译器程序的入口在什么地方。
    * `start` 和 `end start` 成双成对出现，不能拆散。
    * 程序框架：
        ```asm
        assume cs:code
        code segment
            ; 这里放数据定义
        start:
            ; 这里放指令
        code ends
        end start
        ```
    * `assume` 假定 `cs` 与 `code` 段的对应关系。

## 代码段中使用栈

* **栈空间与栈顶**

    * 用 `dw` 定义 16 个字型数据即获得 16 个字、32 个字节的内存空间，位置从 `cs:10h` 到 `cs:2f`。
    * 为什么不是到 `cs:30h`：`cs:10h` 本身也算一个内存单元，从 `10h` 开始存，`10h` 也要占，所以最后落在 `2f` 上。
    * 不能直接把一个段寄存器赋给另一个段寄存器，得拿 `ax` 当跳板：`mov ax,cs` 再 `mov ss,ax`。
    * 空栈的 `sp` 应指向这段栈空间的下一个单元，也就是 `cs:30h`；用 `dw 0` 给栈空间占好位置。

* **入栈再出栈把数据逆序**

    * 题目：利用栈，把程序中定义的数据逆序存放。
    * 数据在 `cs:0` 到 `cs:f`，一共八个字型数据、占 16 个内存单元。
    * 思路：先把它们依次入栈，再依次出栈放回这八个字单元，靠栈先入后出的特性把顺序反过来。
    * `push`、`pop` 的操作单位是字，一次压入或弹出两个字节，所以偏移量每次加 2。
    * 两个循环之间要重新初始化 `mov bx,0`、`mov cx,8`。
    * > **注意**：`dw` 定义的数据不是运行时才定义的，而是在程序加载进内存的时候就已经放好了；真正的第一条指令在数据之后，必须用标号告诉编译器入口在哪。
    * 段内布局：
        ```text
        cs:0     ┌───────────────────────────┐
                 │  8 个待逆序的字型数据       │  cs:0 ~ cs:f
        cs:10h   ├───────────────────────────┤
                 │  预留的栈空间（16 个字）    │  cs:10h ~ cs:2fh
        cs:30h   ├───────────────────────────┤  ← ss:sp 初始指向这里（空栈）
                 │  汇编指令对应的机器码       │
                 └───────────────────────────┘
        ```
    * 完整程序：
        ```asm
        assume cs:code
        code segment
            dw 0123h, 0456h, 0789h, 0abch
            dw 0, 0, 0, 0, 0, 0, 0, 0
            dw 0, 0, 0, 0, 0, 0, 0, 0
        start:
            mov ax, cs
            mov ss, ax
            mov sp, 30h
            mov bx, 0
            mov cx, 8
        s1: push cs:[bx]
            add bx, 2
            loop s1
            mov bx, 0
            mov cx, 8
        s2: pop cs:[bx]
            add bx, 2
            loop s2
            mov ax, 4c00h
            int 21h
        code ends
        end start
        ```
