## 1. AI 时代的 Python 学习路线与职业前景

> **一句话主旨**：从 AI 岗位爆发与政策依据切入，给出六阶段课程主线、四项特色、阶段化的学习方法与学习产出。

### 1.1 AI 应用开发与岗位需求

* **Python（Python）**
    * > 定义：本课程要学的编程语言，是当前最主流、市场占有份额最高的编程语言。
    * 2022 年 11 月 30 号 OpenAI 发布基于 GPT-3.5 的对话产品 ChatGPT，人工智能进入蓬勃发展期；此后百度文心一言、阿里通义千问、讯飞星火、字节豆包、腾讯元宝、月之暗面 Kimi 相继推出。
    * 2025 年 1 月 20 号深度求索公司自研大模型 DeepSeek-R1 发布，训练成本低廉、性能可媲美 OpenAI o1，且开源。
    > 来源: P01

* **接入大模型**
    * > 定义：让各行业现有的系统与应用软件调用 AI 大模型的能力，而非每家企业重新开发一个自己的大模型。
    * 覆盖领域包括金融、医药、政务、央国企、生活服务、电信、交通、教育。
    * 业务目标是对现有应用软件重构与升级，推动应用软件的 AI 化、智能化，实现增产、提效。
    > 来源: P01

* **AI 岗位**
    * > 定义：集中爆发于 AI 大模型开发、算法、模型微调、AI 大模型应用开发四个方面。
    * 需求量现在巨大，并随人工智能发展在未来几年持续大幅增加。
    > 来源: P01

* **十五五规划**
    * > 定义：覆盖 2026 年到 2030 年的国家五年规划，明确提出全面实施人工智能+行动。
    * 内容包括以人工智能引领科研范式变革，加强人工智能同产业发展、文化建设、民生保障、社会治理相结合，抢占人工智能产业应用制高点。
    * 其中“人工智能应用”指的就是 AI 大模型应用。
    > 来源: P01

### 1.2 AI 的入口是 Python

* **Python 在 AI 领域的占比**
    * 据不完全统计，80% 以上的 AI 应用基于 Python 语言开发。
    * > 结论：AI 是需求侧，Python 是供给侧；需求暴涨的领域里八成以上的活儿都落在同一门语言上。
    > 来源: P01

* **TIOBE 编程语言排行榜**
    * > 定义：TIOBE 官方提供的编程语言排行数据，用于衡量各语言的市场占有份额。
    * 到今年 11 月份 Python 市场占有率达到 23.37%，基本相当于排名第二、第三、第四三门语言之和。
    * 占有率的主要功劳归于 AI 的高速发展。
    > 来源: P01

### 1.3 课程的六阶段主线

* **课程六章体系**
    * 第一章 Python 启航：认识 Python、搭建 Python 开发环境、完成第一个 Python 程序。
    * 第二章 Python 核心语法：字面量、变量、各类运算符、流程控制语句、数据容器、函数、面向对象。
    * 第三章 Python 实战之 AI 应用：从基础 AI 知识讲起，讲解网络协议、如何接入 DeepSeek 大模型、提示词的编写技巧，最终独立开发 AI 智能伴侣。
    * 第四章 Python 实战之爬虫：爬虫基础知识、爬虫的合规性、HTML 页面基本结构、正则表达式、多线程、线程池，最终完成爬取豆瓣电影 Top 榜、爬取游戏壁纸一类小项目。
    * 第五章 Python 实战之数据分析及可视化：Pandas、Matplotlib 等技术，最终完成一组数据分析及可视化案例。
    * 第六章 Python 实战之 Web 应用：基于 FastAPI 构建 Web 应用，过程中深入讲解 Python 面向对象的高级用法以及装饰器。
    > 来源: P01

* **六阶段的依赖关系**
    * 前两章是所有人共用的地基，四块实战都建立在同一套语法之上。
    * 四个实战章节是四个并列的应用方向，彼此之间没有先后依赖，谁先谁后都不会卡住。
    * 每个实战章节的最后都会分析该细分领域接下来的学习路线。
    > 来源: P01

### 1.4 课程特色与学习产出

* **项目驱动**
    * 整门课拒绝单纯的知识点讲述，把知识点与技术应用到实际场景当中。
    * 产出作品之一是 AI 智能伴侣：功能完善，支持模型选择、伴侣姓名与性格的定制，支持新建会话、会话历史查询、删除会话。
    * 产出作品之二是网络爬虫：严格依据法律法规爬取需要的数据，再根据爬取到的数据进行分析，形成可视化报表。
    > 来源: P01

* **AI 赋能开发与企业级实践**
    * AI 编程工具覆盖项目开发各个环节：代码续写、智能添加注释、复杂代码解读、程序优化、Bug 修复、智能知识问答。
    * 企业级开发实践全程融入异常处理、日志管理以及调试技巧。
    * 课程特色共四点：知识全面体系完整、项目驱动实战教学、AI 赋能高效开发、企业级开发实践。
    > 来源: P01

* **四项学习收获**
    * 基本功与编程思维：具备扎实的 Python 基本功及优秀的编程思维。
    * AI 辅助开发能力：熟练使用 AI 辅助工具编写代码、调试、修复 Bug、优化代码。
    * 视野与学以致用：通过 AI 应用、爬虫、数据分析及可视化、Web 应用等案例实战拓展视野。
    * AI 大模型基础：掌握 AI 大模型的基础知识，具备独立开发基础 AI 应用的能力。
    > 来源: P01

* **适用人群**
    * 完全零基础的小白。
    * 对 AI 大模型、爬虫、数据分析感兴趣的技术爱好者。
    * 之前从事其他行业、想转行从事 AI 大模型开发的从业者。
    * 在校大学生，包括准备参加考试、参加竞赛或准备面试的人。
    > 来源: P01

### 1.5 学习方法与阶段策略

* **阶段化工具策略**
    * 第 1—2 章核心语法期：建议夯实基础，不要使用 AI 编程工具，涉及的核心语法与案例练习尽量手敲代码，目的是形成语感与判断力。
    * 第 3—6 章项目实战期：借助 AI 编程工具提高开发效率，掌握基于 AI 编程工具进行开发、调试、Bug 修复、程序优化等相关技巧。
    * 两个阶段的工具策略正好相反，顺序不能颠倒，核心语法期与项目实战期的分界就卡在六阶段中间。
    * > 易错点：语法还没形成肌肉记忆时就让工具替你写代码，省下的是打字时间，丢掉的是判断力——以后工具给出的代码是对是错看不出来。
    > 来源: P01

* **多敲多练**
    * 学习过程当中不要只看，一定要多敲、多练，这是整门课唯一一条不许打折扣的要求。
    * 学习当中遇到问题可以在评论区交流，讲师会及时回复。
    > 来源: P01

## 2. Python 语言本体：出身、定位与入门程序定位

> **一句话主旨**：交代 Python 的作者、发布年份与名字由来，用人类语言与编程语言的对比确立其定位，并给出第一章的两部分任务。

### 2.1 作者与名字的由来

* **吉多·范罗苏姆（Guido van Rossum）**
    * > 定义：Python 语言的作者，荷兰计算机科学家，被称为 Python 之父。
    * 文本提到 Python 于 1991 年发布，作者英文名里的 Guido 音译过来是“龟”的意思，国内很多开发者称他为“龟叔”。
    * 来源: P02

* **Python 名字与标志**
    * Python 这个英文单词翻译过来是蟒蛇，语言的标志就是两条缠绕的小蟒蛇。
    * Python 这个名字来源于作者喜欢的一部电视剧当中的角色。
    * > 结论：要记牢两个名字——语言叫 Python，作者叫吉多·范罗苏姆，国内常称“龟叔”。
    > 来源: P02

### 2.2 人类语言与编程语言的对比

* **语言**
    * > 定义：人类进行沟通交流的一种主要表达方式。
    * 两个中国人在一块交流用中文描述自己的意图就够了；换成两个美国人或英国人，需要用英文来描述。
    * 原则只有一条：对话双方都能理解对方的意图、理解对方的语言。
    > 来源: P02

* **编程语言（programming language）**
    * > 定义：人类与计算机之间进行信息交流的一种语言。
    * 计算机不能识别人类的语言：中文、英文、日文、韩文都识别不了，因为人类语言充满模糊性、歧义性，还夹杂复杂的情感色彩。
    * 人类要与计算机交流，必须换成结构规范、逻辑严谨的语言。
    > 来源: P02

| 对比项 | 人类语言 | 编程语言 |
| :--- | :--- | :--- |
| 交流双方 | 人与人 | 人与计算机 |
| 语言特征 | 充满模糊性、歧义性与情感色彩 | 结构规范、逻辑严谨 |
| 典型例子 | 中文、英文、日文、韩文 | Python、Java、C、C++、Go |

### 2.3 排行榜位置与应用领域

* **TIOBE 市场占有率**
    * 截至 2025 年 10 月，Python 语言的市场占有率为 24.45%，远远高于其他编程语言。
    * 2018 年之后，Python 的市场份额每一年都有大幅提升，牢牢霸占排行榜榜一的位置。
    > 来源: P02

* **应用领域**
    * 中小学阶段已经有学生在学习 Python 编程；大学期间的计算机二级以及 ACM 等一系列竞赛都会用到 Python。
    * 办公自动化、网络爬虫、Web 应用程序开发、数据分析与大数据开发、自动化测试、测试开发与运维开发。
    * 当前最火爆的领域是 AI：做 AI 大模型开发，学习深度学习、机器学习、神经网络等内容都离不开 Python。
    * > 结论：Python 的地位不是喊出来的，是被这一长串场景用出来的——应用领域足够广，市场占有份额才稳居榜首。
    > 来源: P02

* **第一章的两部分内容**
    * 第一部分完成 Python 开发环境的准备。
    * 第二部分在环境准备好之后完成第一个入门程序的编写。
    > 来源: P02

## 3. 解释器安装与验证

> **一句话主旨**：说明解释器为什么必不可少，给出安装包的版本与位数选择依据和安装步骤，并以命令行验证安装结果。

### 3.1 解释器的作用

* **Python 解释器（Python Interpreter）**
    * > 定义：Python 官方提供的一段翻译程序，把所编写的 Python 代码翻译成二进制的程序，再交给计算机底层执行。
    * 计算机底层只能识别二进制当中的 0 和 1，不能直接识别 Python 代码。
    * 直接基于 0 和 1 编程的问题有两个：学习难度极大，编程效率极低。
    * 输入是 Python 代码，输出是计算机底层能执行的二进制程序；开发时只需专心写 Python 程序，不用碰二进制。
    > 来源: P03

### 3.2 版本与安装包选择

* **次新版本**
    * 官网 Downloads 一栏右侧显示与当前操作系统相关的版本，写作 `Download for Windows`，演示时给出的版本是 Python 3.14.0。
    * 不装最新版的原因有两点：最新版本刚发布，企业当中还没人用；由于刚发布，后面要用到的很多资源库还没有适配。
    * 课上使用次新版本，演示时选定 3.13.9；其他版本可从下方链接或左侧 Windows 入口进入安装包列表查找，苹果电脑点 macOS。
    > 来源: P03

* **操作系统下限**
    * 官方明确说明 Python 3.13.9 不能够用在 Win7 及之前的操作系统上。
    * 操作系统不能是 Win7，可以是 Win10、Win11；主流版本现在都不能用在 Win7 及之前的系统上。
    > 来源: P03

| 系统类型 | 该选哪个安装包 |
| :--- | :--- |
| 基于 x64 的处理器，64 位 | 选第一个 `64-bit` |
| 32 位操作系统 | 选下面那个 32 位安装包 |
| 基于 ARM 的处理器 | 选第三个安装包 |

* **位数选择依据**
    * 确认方式：打开文件夹，在左侧找到“此电脑”（或桌面右键“此电脑”）→ 属性 → 查看“系统类型”。
    * 绝大部分同学都是 64 位操作系统，直接选第一个 64 位安装包。
    * 课程资料里提供了 32 位与 64 位两种版本的安装包，直接用其中的 64 位安装包。
    * > 易错点：选错位数的包，装完跑起来会出各种莫名其妙的问题。
    > 来源: P03

### 3.3 安装步骤

* **安装过程中的关键勾选**
    * 运行 `exe` 文件时要选择以管理员身份运行，先获取管理员权限。
    * 第一步勾选 `Add python.exe to PATH`，勾上之后稍后使用 Python 时就可以在任意目录下执行 Python 命令。
    * 接着选择自定义安装，进入后所有信息都不用动，直接点击 `Next`。
    * 再勾选 `Install Python 3.13 for all users`，即为所有的用户安装 Python 解释器。
    * > 易错点：`Add python.exe to PATH` 是最容易漏掉、后果最麻烦的一步；漏勾之后并非装不上，而是 `python` 命令在命令行里认不出来，只能在安装目录下才能运行。
    > 来源: P03

* **安装目录的选定**
    * 默认目录可以安装，演示时把所有开发相关的软件单独放在自定义目录下，例如 D 盘的 `develop` 目录。
    * 操作方式：点 `Browse`，找到此电脑、D 盘，在 `develop` 下新建文件夹并命名为 `Python`，选中后确定。
    * > 易错点：安装目录要放在没有中文、不带空格的目录下，例如 `D:\develop\Python`；带中文或带空格的路径容易引发其他微小问题，排查起来非常费劲。
    * > 易错点：Windows 用户目录默认为 `C:\Users\<用户名>`，一旦用户名是中文，默认目录安装的路径里就混进了中文，同样要避开。
    * 点 `Install` 后安装过程大概持续几十秒，提示安装成功后点 `Close` 关闭窗口。
    > 来源: P03

### 3.4 安装验证

* **命令行验证**
    * Windows 上同时按 `Windows + R` 打开“运行”窗口，输入 `cmd` 后回车打开命令行。
    * 在命令行输入 `python` 回车，能看到 Python 版本为 3.13.9 就说明安装成功。
    * `python` 是安装好的解释器提供的命令，实际执行的是安装目录下的 `python.exe` 可执行文件。
    * 看到光标闪动等待输入 Python 代码，说明已进入解释器交互状态。
    > 来源: P03

* **安装文档**
    * 可以参照课程资料提供的 Python 安装文档逐步完成安装操作。
    * 所有与开发相关的软件，尽量安装在没有中文、不带空格的目录下。
    > 来源: P03

## 4. 命令行的执行方式与常见问题

> **一句话主旨**：讲清 `python` 命令找不到的两种现象与成因，给出卸载重装与手动配置 Path 两条路线，并说明环境变量与路径规则。

### 4.1 命令找不到的两种现象

* **Win10 与 Win11 的差异**
    * Win10 的表现是直接报错：`python 不是内部或外部命令`。
    * Win11 的表现是跳转应用商店：自动打开微软商店，引导下载 Python。
    * 两种现象都是执行 `python` 这条命令时没有找到这条命令导致的，系统版本只决定它用什么方式抱怨。
    * 与讲义步骤一致安装的同学基本遇不到这个问题，碰上的原因几乎只有一个：安装解释器的那几步没有严格按照讲义步骤走。
    > 来源: P05

* **成因与两条路线**
    * 原因落在安装向导第一步界面最下方的那个复选框：把 `python.exe` 添加到 Path 环境变量，这一步没有勾选就会引发后面所有麻烦。
    * 路线一卸载重装：把 Python 解释器卸掉重新装一遍，重装时别忘了勾选。
    * 路线二手动配置 Path 环境变量：不重装，直接把缺的那份配置补上。
    > 来源: P05

### 4.2 卸载重装

* **正规卸载流程**
    * 找到控制面板，点击「卸载程序」。
    * 列表里的软件按字母排序，找到 `P` 开头的 Python（一共两项），选中后点击上方的「卸载」，两项都卸掉。
    * 卸载完成后重新安装。
    * > 易错点：卸载软件不要在安装目录上右键直接删文件夹，那样删不干净，注册表、安装记录、环境变量里都会留下残渣。
    > 来源: P05

### 4.3 环境变量与命令执行流程

* **环境变量**
    * > 定义：操作系统当中存储的、用来指定应用程序运行时所需要的参数信息的那份配置。
    * 可配置的内容包括应用程序运行时需要的临时文件夹位置、系统文件的访问位置、某些网站的访问凭证。
    * 应用程序跑起来时只需要读环境变量就能拿到这些参数，不必把信息写死在代码里。
    * 常用入口有两条：此电脑 → 右键 → 属性（菜单里没有「属性」就点「更多选项」）→ 高级系统设置；或开始菜单输入「系统」，进控制面板的「系统」→ 高级系统设置。
    > 来源: P05

| 分区 | 生效范围 | 说明 |
| :--- | :--- | :--- |
| 用户的环境变量 | 仅当前登录用户 | 换个用户登录就不生效 |
| 系统环境变量 | 所有用户 | 与用户无关，谁都访问得到 |

* **用户变量与系统变量**
    * Windows 也好、Mac 也好，装系统时默认都会创建一个用户；个人电脑通常只用这一个默认用户。
    * 列表里大部分变量是软件在安装过程中自动配置好的，其中 `Path` 最要紧——用户变量区和系统变量区都有 `Path`。
    * 个人电脑只有一个用户，两处配置效果一样；多人共用的电脑要想清楚配在哪一份。
    > 来源: P05

* **命令的执行流程**
    * 系统内部命令（如 `cd`）直接执行。
    * 不是内部命令的，先在当前目录下查找该命令。
    * 当前目录没找到，才到 `Path` 环境变量配置的各个目录中查找。
    * 找到就执行，全都没找到就报错——Win11 上表现为打开应用商店，Win10、Win7 上提示“不是内部或外部命令”。
    * `Path` 是外部命令查找的最后一道关口。
    > 来源: P05

### 4.4 手动配置 Path 与验证

* **需要登记的两个目录**
    * `D:\develop\python`：Python 的安装目录，提供 `python` 命令。
    * `D:\develop\python\Scripts`：该目录下同样放着可执行文件，比如后面安装各种依赖模块要用到的 `pip`。
    * 操作步骤：点击「环境变量」找到 `Path` → 双击进入「编辑环境变量」→ 点「新建」→ 打开安装目录复制路径粘贴进去 → 再点一次「新建」粘贴 `Scripts` 路径。
    * 大家在安装 Python 时默认配置的是上面那个用户变量。
    * > 易错点：只加 Python 安装目录、漏掉 `Scripts`，是最常见的半成品配置——当下 `python` 能跑了，等到装第三方库时 `pip` 又报“不是内部或外部命令”。
    > 来源: P05

* **条目顺序与优先级**
    * 配置完之后把刚加的两个目录「上移」到最前面。
    * `Path` 里的条目有顺序，越靠前优先级越高，越靠后越低；系统里装了多个 Python 时最前面那个会生效。
    * 依次点击「确定」「确定」「确定」把三层窗口都确认掉。
    > 来源: P05

* **配置后的验证**
    * 不要在已经打开的那个命令行窗口里验证，需要把旧窗口关掉，重新打开一次 `cmd`，最新的环境变量才会生效。
    * 重新按 `Win + R`、输入 `cmd`、回车，再输入 `python`，命令即可正常执行。
    * 安装和使用都正常的同学完全不需要去动 `Path` 环境变量。
    > 来源: P05

    * 下载页会自动选中当前操作系统对应的版本。

## 6. 项目创建、入门程序与文件规则

> **一句话主旨**：给出 PyCharm 中新建项目与文件的操作、主界面区域分工、注释与运行方式，并确立符号与分号两条必须记住的规则。

### 6.1 创建项目与主界面

* **新建项目要填的三项**
    * 项目存放位置：项目里会存放很多 Python 文件和代码，这些文件最终落在磁盘上；最后那一级文件夹就是项目的名字，路径和名字都可以自定义。
    * 演示中在 D 盘根目录新建文件夹 `python_project`，项目统一都放在这个文件夹下，项目名写作 `py_project01`。
    * 解释器类型保持默认的「项目 venv」，也就是使用虚拟环境；Python 版本由 PyCharm 启动时自动加载本地已安装解释器的信息，确认无误即可；点「创建」建出项目。
    > 来源: P07

* **主界面四个区域**
    * 顶部菜单栏：右侧是最小化／最大化／关闭与设置，还有运行、调试运行的快捷操作，点击可展开主菜单。
    * 左侧功能栏：后续代码运行时的 Python 控制台、命令行终端、运行的服务都在这里查看。
    * 项目区：显示当前项目的名字与磁盘路径，点一下「项目」可以折叠，再点一下又展开。
    * 右侧编辑区域：打开文件后，文件内容在这里显示。
    * 项目创建好后工具还自动生成了一个目录，里面存放的是这个 Python 项目的运行环境信息。
    > 来源: P07

### 6.2 新建文件、注释与快捷键

* **新建目录与 `.py` 文件**
    * 在项目上右键 → 「新建」（英文版是 `New`），可指定新建目录还是新建 Python 文件。
    * 演示中先建目录并命名为「第一章」，再在该目录下右键新建 Python 文件，文件名写 `01 入门程序`。
    * > **提示**：用记事本写代码得自己补上 `.py` 后缀；用 PyCharm 创建 Python 文件时不用加后缀，它会自动加上。
    > 来源: P07

* **注释（comment）**
    * > 定义：写给我们开发人员看的说明性文字，作用是解释说明代码、让开发人员更容易看懂需求与代码；Python 解释器在执行代码时会忽略注释。
    * 写法是在该行最前面加一个井号 `#`，井号开头的行就是注释；井号出现在代码后面时，井号之后的部分是注释，井号之前的代码依然会被解释器执行。
    * 快捷键：光标停在这一行的任意位置按 `Ctrl + /` 立刻被注释，再按一次取消注释；批量选中多行后按 `Ctrl + /` 可批量注释。
    > 来源: P07, P09

* **编辑器快捷键**
    * 字体调大按 `Shift + Alt + .`（句号），调小按 `Shift + Alt + ,`（逗号），演示中调到 16 号。
    * 快速复制当前行按 `Ctrl + D`。
    * 自动补全：敲一个 `p` 就列出所有 `p` 开头的候选，双击候选或按回车即可生成 `print`，括号一起生成，光标停在括号中间。
    > 来源: P07, P10

### 6.3 符号与分号规则

* **英文标点**
    * 编写程序时所有的符号均要使用英文的标点符号，使用中文标点在执行过程当中是会报错的。
    * 括号、引号、逗号、冒号这些符号是语法的组成部分，中文符号不是 Python 语法的一部分，解释器只认英文的那一套。
    * 中文括号明显比英文括号更宽，把输入法切到中文再敲一对括号就能看出区别；中文全角符号是新手代码报错的头号来源。
    > 来源: P04, P07

* **输入法设置**
    * 以搜狗输入法为例：在状态栏图标上右键 → 更多设置 → 常用 → 找到「标点符号」→ 打开「中文时使用英文标点」，该选项默认是关闭的。
    * 验证方式：状态栏后面那个符号指示显示的是点，就代表当前用的是英文符号。
    * 临时切回中文标点：点一下那个图标，符号从点变成句号；也可按快捷键 `Ctrl + 点` 在中文、英文标点之间切换。
    > 来源: P04

* **分号**
    * 多行代码之间不用加分号，一行代码写完直接换行即可，通过换行符标识这行代码到此结束。
    * 想把两行代码写到同一行里，就必须用分号把它们隔开。
    * 绝大部分情况下都让一行代码占据一行，行尾的分号不用加。
    > 来源: P07

### 6.4 运行入门程序

* **在 PyCharm 中运行**
    * 在文件上右键，找到「运行 01 入门程序」并点击，它就会自动运行这个文件。
    * 集成开发环境运行 Python 文件时底层依旧是 `python` 加空格再跟上要运行的文件名，和命令行里手敲的一模一样，只不过它替我们做了。
    * 运行后下方区域能看到输出结果，`Hello World`、`Hello Python` 和那行分隔横线三行内容都输出了。
    * 右键运行跑的是整个 Python 文件，前面的代码都会执行；不需要前面的代码执行时，把它们全部选中后按 `Ctrl + /` 批量注释掉。
    > 来源: P07, P10

* **解释器的两种运行方式**
    * 交互模式：命令行输入 `python` 进入，出现三个箭头 `>>>` 提示符，敲一行、回车、立刻执行一行，适合试一句看一眼，输入 `exit()` 退回 Windows 命令行。
    * 脚本模式：把多行 Python 代码定义在后缀为 `.py` 的文件当中，通过 `python 文件名` 一条命令执行，回车后一次性执行文件内全部代码，适合成块的多行代码。
    * 区分当前处于哪个命令行：前面有箭头说明在 Python 解释器当中；前面显示具体的盘符（如 C 盘、D 盘下）说明在 Windows 命令行当中。
    > 来源: P04

## 7. Python 项目目录结构与虚拟环境

> **一句话主旨**：拆解项目里 `.venv` 与 `.idea` 两个目录各自的职责，说明虚拟环境带来的隔离效果，并给出资料与讲义的组织线索。

### 7.1 项目目录结构与 `.idea`

* **项目目录结构**
    * `.idea/`：PyCharm 里默认不展示。
    * `.venv/`：项目的虚拟环境。
    * `第一章/`：存放我们编写的 Python 文件。
    * 在 PyCharm 里对着项目右键 → 「打开于」→「资源管理器」，可直接定位到磁盘上的项目目录。
    > 来源: P08

* **`.idea` 目录**
    * 该目录在磁盘上存在，但在 PyCharm 的项目视图里默认不显示。
    * 里面存放的是项目的一些配置信息；演示中把光标停在第六行后关掉 PyCharm，下次打开依旧停在第六行并自动打开了那个文件，这些状态就记录在 `.idea` 里。
    * > **提示**：`.idea` 里保存的项目配置信息一般不会去动，为了避免误操作，PyCharm 干脆不在项目视图里展示这个目录。
    > 来源: P08

### 7.2 虚拟环境与隔离

* **虚拟环境（virtual environment，venv）**
    * > 定义：为单个 Python 项目单独建立的一套运行环境，项目运行所依赖的工具与文件都存放在该项目自己的 `.venv` 目录中。
    * 创建项目时解释器类型用的是默认值「项目 venv」，含义是这个项目将会在虚拟环境中运行；页面上小字说明 Python 的虚拟环境会在项目当中创建一个目录，也就是项目目录下那个 `.venv`。
    * `.venv` 保存的是项目的环境信息，里面存放当前项目运行时所需要依赖的那些工具和文件。
    * > 结论：虚拟环境让每一个 Python 项目都运行在相对独立、彼此隔离的环境中，项目与项目之间互不影响、互不干扰。
    > 来源: P08

* **隔离效果**
    * 以后再去创建其他的 Python 项目，每一个项目里都会出现自己的 `.venv`，各自的 `.venv` 只服务于自己这个项目。
    * 在第一个项目里依赖了某个工具或文件，它不会影响到其他的项目。
    * 项目创建好之后，`.idea` 与 `.venv` 这两个文件夹下的东西不要动。
    > 来源: P08

## 8. 数据类型体系

> **一句话主旨**：列出五种常见基础数据类型及其描述对象，说明变量本身没有类型，并给出 `type` 与 `isinstance` 两个内置工具的用法。

### 8.1 五种常见基础数据类型

* **int（整数类型）**
    * 只要是整数，无论正数、负数还是零，都用 int 表示。
    * 字面量示例：10、18、-5、0，直接书写即可。
    > 来源: P09, P13

* **float（浮点数类型）**
    * 也就是小数，8.5、3.14、-3.5 都是 float，正负都算。
    * 判定的唯一依据是“它是不是小数”。
    * 字面量示例还包括 1.0，直接书写即可。
    > 来源: P09, P13

* **string（字符串类型）**
    * 用来描述文本，也叫文本字符串，例如“人生苦短我用 Python”、Hello Python、HelloWorld。
    * 字面量必须使用引号将其引起来，所有被引号引起来的内容都是字符串。
    * 字符串不一定非得用双引号，单引号也可以；一段文本不引起来就会报错。
    > 来源: P09, P13

* **bool（布尔类型）**
    * 用来表达生活当中的一些逻辑，只有两个取值：条件成立就是真 `True`，条件不成立就是假 `False`。
    * `True` 和 `False` 的首字母必须大写，写成小写的 `true`、`false` 不是布尔字面量，那一行会马上报错。
    * 布尔类型本质上也是属于数字类型的，属于数字类型当中的整型；涉及数学运算时会自动把 `True` 转换为 1，把 `False` 转换为 0。
    * 演示：`print(True + 1)` 输出 2，`print(False - 1)` 输出 -1。
    > 来源: P09, P10, P13

* **NoneType（空值类型）**
    * 表示这个值是空的、或者说没有值，里面只包含一个字面量 `None`。
    * 写法就是直接写 `None`。
    * > 易错点：NoneType 只装得下 None 一个值；它不是“零”，也不是空字符串，而是“没有值”这个状态本身。
    > 来源: P09, P13

* **数据容器类型**
    * 包含 list、tuple、dict、set 等类型，前面课程没有展开，后面课程会详细讲。
    * 掌握范围：眼下把这五类常见字面量的写法记住就够了。
    > 来源: P09

### 8.2 字面量的书写方式与判定

* **字面量（literal）**
    * > 定义：在代码中直接书写出来的固定值。
    * 例子包括 18、8.5、3.1415926、-5 这些数字，以及 HelloWorld 这样一段文本。
    * 学字面量只需盯住两件事：字面量有哪些种类；不同种类的字面量具体的书写格式。
    * 单独写一个数字运行之后没有任何效果，代码只是被解释器读到，并没有输出这个动作，把数字交给 `print` 才能看到结果。
    * 演示中逐类输出 100、3.14、True、False、Hello Python、None 六种字面量。
    > 来源: P09

* **引号对类型的判定作用**
    * 判据只有一条：所有以引号引起来的都是字符串。
    * `"10010"` 是字符串，不带引号的 `10010` 是整数类型 int，两者有差异。
    * `"True"` 是一个普通的字符串，不带引号的 `True` 才是布尔类型当中的真，两者也有差异。
    * 类型一旦被引号改变，后面参与拼接、运算时的行为也就跟着变了。
    > 来源: P09

* **字面量与变量以不同方式参与程序**
    * 字面量决定数据在代码当中是怎么写的，变量决定数据在代码当中是如何存储的。
    * 核心语法的第一部分“数据的存储与运算”装着字面量、变量和运算符，拆成四小节：字面量与变量、常见的数据类型、输入与输出、各种各样的运算符。
    > 来源: P09

### 8.3 变量与数据类型的关系

* **变量没有类型**
    * > 结论：变量本身没有类型，变量里面所存储的数据才有类型。
    * 定义变量时没有指定过那五种类型：`a = 10` 里 a 就是变量名，`name = "Python"` 里 name 也是变量名，两处都没写任何类型说明。
    * 变量是存储数据的容器，容器自身不区分自己装什么，`type` 时拿到的是容器里那份数据的类型。
    * 定义 `number = 5.0` 时 `type(number)` 查出来的就是 5.0 的类型 float；把 `number` 改成 `-100`，它此刻的类型就变成 int。
    > 来源: P10, P13

* **动态类型语言**
    * Python 是动态类型语言，定义变量时不需要指定变量的类型，运行的时候解释器会自动进行类型检查。
    * 变量的类型在程序运行的过程当中也是可以变化的，一个变量既可以接收整数类型 int，也可以接收小数类型，也可以接收字符串类型。
    * 演示中 `number` 先存 1114.1，再改成 1114.2，再改成 `"OK"`，再改成 `True`，一个变量前后装着三种不同类型的数据。
    * 在项目开发当中定义变量时一般一个变量只会接收一种类型的值；确实还有存字符串、存布尔类型的需求，那就再定义一个变量。
    > 来源: P10, P13

### 8.4 `type` 查看类型

* **`type`**
    * > 定义：Python 内置的一个工具（本质上是一个内置函数），用来获取指定字面量或变量的类型。
    * 写法是 `type` 后面跟一对小括号，括号里写上要查看类型的数据；要打印结果还得靠 `print` 把 `type` 的调用结果打印出来。
    * 查看字面量时括号里写的就是字面量本身，例如 `type("hello")`、`type(10)`、`type(3.14)`、`type(True)`、`type(None)`。
    * 查看变量时括号里换成变量名，得到的是该变量所存数据的类型。
    * > 易错点：想查 `"hello"` 的类型就不能只写 `hello`；写成 `type(hello)` 时 Python 会把它当成一个名叫 hello 的变量去找，而这个变量并不存在。
    > 来源: P13

| 传入 type 的数据 | 预判类型 | 实际输出 |
| :--- | :--- | :--- |
| `"hello"` | string | `<class 'str'>` |
| `10` | int | `<class 'int'>` |
| `3.14` | float | `<class 'float'>` |
| `True` / `False` | bool | `<class 'bool'>` |
| `None` | NoneType | `<class 'NoneType'>` |

* **输出结果的读法**
    * 输出里的 `class` 可以简单理解为“类型”的意思，后面那个 `str` 就是 string 类型，代表字符串类型；`int`、`float`、`bool` 同理。
    * 传变量时输出了 number 所对应的值的类型，`number = -100` 时结果为 `<class 'int'>`。
    > 来源: P13

### 8.5 `isinstance` 判定类型

* **`isinstance`**
    * > 定义：Python 内置的一个工具，用来检查指定的数据是否属于特定的类型。
    * 写法是 `isinstance(数据, 类型)`，需要传递两项：一项是数据，另一项是类型，表示判定这个数据是不是后面指定的类型。
    * 判定结果以布尔值的形式返回：是就返回 True，不是就返回 False。
    * 演示：`number = -100` 时，`isinstance(number, int)` 输出 True，`isinstance(number, float)` 与 `isinstance(number, bool)` 都输出 False。
    * > **提示**：敲 `is` 开头的东西时要看清楚再回车，编辑器里以 `is` 开头的候选不止一个，别选错。
    > 来源: P13

* **两个工具的分工**
    * `type(data)` 回答的是该数据属于什么类型，结果是类型对象，形如 `<class 'str'>`、`<class 'int'>`。
    * `isinstance(data, type)` 回答的是该数据是不是某个指定类型，结果是布尔值 True 或 False。
    > 来源: P13

## 9. 变量的定义与用法

> **一句话主旨**：确立变量是存储单个数据的容器这一定位，给出定义语法、多重赋值写法，以及把变量交给 `print` 输出的具体方式。

### 9.1 变量的本质与定义语法

* **变量（variable）**
    * > 定义：程序当中用来存储单个数据的容器，一个变量只能存储一个数据。
    * 通常把容易变化的数据存储在变量当中：B 站课程页面的播放量、弹幕数量、正在观看的人数、点赞数、投币数、收藏数、转发数量、笔记数量都会实时发生变化，播放量随时间推移一直在往上增。
    * 假设播放量是 1114.1 万，就把这个数据存进变量里；随着时间推移，容器里的数据会持续发生变化。
    * > 易错点：变量指的是数据存储的容器，而不是里面所存储的数据；通过变量这个容器，可以找到它当前存放的那个数据。
    > 来源: P10

* **定义语法**
    * 语法格式：前面写变量名，等号之后写变量值，例如 `number = 1114.1`。
    * 等号是一个赋值操作，它把等号右侧的值赋给左侧的变量，所以它是一个赋值运算符；右侧写的是要往容器当中存储的数据。
    * 值要变的时候只需要给 `number` 重新赋一个值，例如 `number = 1114.2`，这一行执行完变量里存储的值就变成 1114.2。
    * 可以把原有的变量放进运算再赋值给自己，`number = number + 1` 执行后播放量从 1114.1 变成 1115.1。
    * > **提示**：Python 官方的代码风格建议，赋值运算符的前面和后面各留一个空格；这是规范不是规定。
    > 来源: P10

### 9.2 多重赋值与变量使用要求

* **一次定义多个变量**
    * 简化写法可以把两行合并成一行：`base, incr = 20.7, 50`。
    * 多个变量名之间用逗号分隔，等号之后多个值之间也用逗号分隔。
    * 赋值的对应关系：第一个值赋给第一个变量，第二个值赋给第二个变量。
    > 来源: P10

* **变量必须先赋值**
    * > **注意**：变量必须在赋值之后才能使用，只声明一个名字、没有给它赋值就去用它，程序会直接报错。
    * 通过变量这个容器可以找到它当前存放的那个数据。
    > 来源: P10

### 9.3 `print` 输出多项数据

* **`print` 的多项输出**
    * `print` 语句当中想一次性输出多项数据，多项数据之间用逗号分隔就可以了。
    * 最终会把这几项数据拼接成一行输出，例如 `print("未来第一个月的播放量", base + incr)`。
    > 来源: P10

* **播放量案例的两步输出**
    * 需求：B 站播放量的基础播放量是 20.7 万，每月新增播放量 50 万，输出未来两个月每个月的播放量。
    * 用两个变量承接基础量与新增量：`base = 20.7`（基础播放量）、`incr = 50`（每月新增播放量）。
    * 未来第一个月的播放总量是基础播放量加每一个月的新增播放量，输出结果是 70.7。
    * 未来第二个月的播放总量是 `base + incr + incr`，输出结果是 120.7。
    > 来源: P10

## 10. 标识符的命名规则与规范

> **一句话主旨**：区分必须遵守的命名规则与建议遵守的命名规范，逐条给出标识符的合法性判据与 PEP 8 的三条变量名规范。

### 10.1 标识符与四条命名规则

* **标识符（identifier）**
    * > 定义：开发人员在代码当中为变量、为函数、为类等元素所起的名字。
    * 函数和类在后面课程当中会详细学习，目前直接接触到的只是变量。
    * 这里说的是命名的规则，也就是规定——规定是必须要遵守的，必须按照这个来。
    > 来源: P11

| 命名规则 | 具体要求 |
| :--- | :--- |
| 字符范围 | 只能包含字母、数字、下划线。字母包括大写 A 到大写 Z、小写 a 到小写 z，数字就是 0 到 9 |
| 首字符 | 不能以数字开头，但下划线可以开头，而且不限个数 |
| 关键字 | 不能使用 Python 当中的关键字作为标识符 |
| 大小写 | 严格区分大小写 |

* **规则里的三个细节**
    * 标识符当中唯一能包含的符号，就只有下划线这一个。
    * 关键字是 Python 内部已经占用的名字：`True`、`False`、`None`，后面要学的 `and`、`or`、`if`、`else`、`elif`、`for`、`while` 统统都是关键字，都不能作为标识符。
    * 严格区分大小写：`age`、`Age`、`AGE` 由于字母的大小写不同，其实是三个变量。
    > 来源: P11

### 10.2 合法与非法标识符的判定

| 候选名字 | 判定 | 依据 |
| :--- | :--- | :--- |
| `name` | 合法 | 只有小写字母，不以数字开头，也不是关键字 |
| `Name` | 合法 | 大写字母同样属于字母，字母开头即可 |
| `_name` | 合法 | 数字不能开头，但下划线可以开头 |
| `__name` | 合法 | 下划线的个数没有限制，任意多个都可以 |
| `my_name` | 合法 | 下划线可以出现在名字中间 |
| `name_` | 合法 | 下划线也可以出现在名字末尾 |
| `name6` | 合法 | 名字里可以包含数字，只要不打头 |
| `true` | 合法 | 小写的 `true` 不是关键字，大写的 `True` 才是 |
| `na$me` | 非法 | 标识符里不能使用美元符号 |
| `and`、`or` | 非法 | 关键字不能作为标识符 |
| `False` | 非法 | 关键字不能作为标识符 |
| `6name` | 非法 | 数字不能开头 |

* **运行验证法**
    * 判定一个标识符是合法还是非法，办法很直接：把它敲出来运行一把看效果；能正常运行就说明合法，不能正常运行就说明非法。
    * `true = 1` 能正常输出结果，说明 `true` 是一个合法的标识符。
    * `True = 1` 出现语法错误，意思是不能为 `True` 分配一个值，原因就是它是布尔类型的字面量、是一个关键字。
    * `6name = 1` 甚至不用运行就已经报错，因为数字不能开头；判断依据始终是那四条规则，运行只是最快的一种验证手段。
    > 来源: P11

### 10.3 变量名的三条命名规范

* **PEP 8**
    * > 定义：Python 官方文档当中的代码风格与编码规范文档；PEP 是 Python 社区的一个技术文档和标准化的机制。
    * 规范不是规定，可以不遵守，但官方建议编写代码时尽量按照规范来。
    * > 结论：规定不遵守，程序直接跑不起来；规范不遵守，程序能跑，但代码会变难维护。
    > 来源: P11

| 命名规范 | 具体要求 | 符合规范 | 不符合规范 |
| :--- | :--- | :--- | :--- |
| 见名知意 | 名字要能看出里面存的是什么 | `name`、`age`、`color` | `a`、`a1`、`a2` |
| 多词用下划线连接 | 涉及多个单词时，单词之间用下划线分隔 | `update_time`、`my_name`、`user_first_name` | `updatetime`、`myname` |
| 英文字母全小写 | 变量名里的英文字母一律小写 | `my_name` | `My_Name` |

* **蛇形命名法（snake case）**
    * 见名知意：`name` 一看就知道是名字，`age` 是年龄，`color` 是颜色；`a`、`a1`、`a2` 通过名字根本看不出里面存的是什么数据。
    * 多个部分用下划线连接：`update_time` 里 `update` 是更新、`time` 是时间；`user_first_name` 里 `user`、`first`、`name` 三个单词每两个相邻单词之间都用下划线分割，这一条规范也叫蛇形命名法。
    * 英文字母全小写：变量名当中出现的英文字母全部用小写。
    * > 易错点：`a`、`a1`、`a2` 从标识符的命名规则层面来说也是合法的，只是不符合项目开发的规范，别把“合法”和“规范”当成一回事。
    > 来源: P11

## 11. 变量值交换与取值轮换

> **一句话主旨**：以两变量交换为例说明直接赋值的失败原因，给出借助临时变量的实现，并推广到三变量的取值轮换。

### 11.1 直接赋值的失败

* **赋值即覆盖**
    * > 定义：`a = b` 是一次赋值操作，它把等号右侧的值赋给左侧的变量，左侧变量原来的取值被覆盖。
    * 需求：两个变量 `a` 和 `b`，`a` 的值是 10、`b` 的值是 20，把 `a` 的值赋给 `b`、`b` 的值再赋给 `a`，即交换两个变量的值再输出到控制台。
    * 写成 `a = b` 再 `b = a` 是错的：执行 `a = b` 后 `a` 变成 20，原来的 10 已经被覆盖掉；再执行 `b = a` 就相当于把这个 20 又赋给了 `b`，两行走完 `a` 和 `b` 的值都变成了 20。
    * > 易错点：赋值是“覆盖”，不是“记住”；一旦某个变量被重新赋值，它原来的取值就再也找不回来了。
    > 来源: P12

* **交换前的状态推演**
    * 初始：`a = 10`、`b = 20`。
    * 执行 `a = b` 之后：`a = 20`、`b = 20`，`a` 被 `b` 的值覆盖。
    * 执行 `b = a` 之后：`b` 拿到的是已经被覆盖过的 `a`，原来的 10 在中途丢掉了，所以这种解题思路是错误的。
    > 来源: P12

### 11.2 借助临时变量完成交换

* **临时变量**
    * > 定义：并不是需求当中需要的变量，作用只是临时记录一下 `a` 的值，供后续赋值周转。
    * 变量是存储数据的容器，两个容器里的数据要互换，必须有一个额外的空容器周转。
    * 演示顺序：`c = a` 记下原始值 → `a = b` 完成 `a` 的替换 → `b = c` 把备份的 10 交给 `b`。
    * 三步行完 `a` 是 20、`b` 是 10，两个变量的值成功交换，运行后符合需求。
    * > 易错点：第三步 `b = c` 不能写成 `b = a`；执行 `a = b` 之后 `a` 已经是 20 了，再写 `b = a` 就又把 20 赋给 `b`，回到失败方案的老路上去了。
    > 来源: P12

* **交换过程的状态**
    * 初始：`a = 10`、`b = 20`、`c` 未赋值。
    * `c = a` 之后：`a = 10`、`b = 20`、`c = 10`，`a` 的原始值被备份出来。
    * `a = b` 之后：`a = 20`、`b = 20`、`c = 10`。
    * `b = c` 之后：`a = 20`、`b = 10`、`c = 10`。
    > 来源: P12

### 11.3 三个变量的取值轮换

* **轮换需求**
    * 三个变量 `a`、`b`、`c` 分别是 100、200、300，需要把 `a`、`b`、`c` 的值分别赋值给 `c`、`a`、`b`，然后输出到控制台。
    * 对应关系拆开就是：`c` 拿 `a` 的值、`a` 拿 `b` 的值、`b` 拿 `c` 的值，三个变量互为数据来源，本质上是一次轮换。
    > 来源: P12

* **轮换的执行顺序**
    * 难点和两变量交换是同一个：三个赋值语句必须有一条先执行，而它一执行，被赋值的那个变量的旧值就没了。
    * 动手之前要先敲定执行顺序，并把第一个被覆盖掉的旧值提前记进一个临时变量，剩下的两次赋值才有旧值可用。
    * 答案：三个变量最终的取值是 `a = 200`、`b = 300`、`c = 100`。
    * 参考实现在配套提供的讲义当中已经给出。
    > 来源: P12
