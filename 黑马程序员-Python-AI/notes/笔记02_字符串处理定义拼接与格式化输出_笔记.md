## 1. 字符串的定义方式

> **一句话主旨**：本节说明单引号、双引号、三引号三种定义写法的成立条件、换行能力差异与选用原则。

### 1.1 三种引号定义写法

* **字符串（String）**
    * > 定义：用引号引起的数据，每一个汉字、字母、符号或数字都算一个字符，多个字符连起来构成一个字符串。
    * 字符串一共有三种定义方式：双引号定义法、单引号定义法、三引号定义法；三引号是三个引号作为开始、三个引号作为结束，中间放字符串的具体内容。
    * 写法上的唯一差别：敲双引号要按住 `Shift` 再按引号键，敲单引号直接按引号键。
    * 三种写法定义出来的结果类型一致，用 `type` 查询 s1、s2、s3 全部返回 string 类型。
    * > 来源: P14, P15

* **三引号定义法（Triple-quoted String）**
    * > 定义：以三个引号作为起止符号的字符串定义方式，支持定义多行字符串。
    * 单引号凑三个、双引号凑三个都能用，官方推荐用双引号凑三引号。
    * 起止引号之间的换行与行首 `Tab` 缩进被原样保留，解释器不会自动整理格式：开始三引号后立刻回车就产生一个开头空行，顶格书写的行输出也顶格，编写时按过 `Tab` 的行输出照样带缩进。
    * 三引号字符串结尾那行的说明文字，写在起止引号之间就是字符串内容的一部分，不再是注释；要当注释必须放在这一行代码的结尾。
    * 三引号的主要应用场景是定义多行字符串，另一个用途是书写文档注释。
    * > 来源: P14

### 1.2 换行能力与选用原则

* **单双引号的换行限制**
    * 单引号和双引号定义的字符串不能直接换行，写在一行里就必须在一行里结束；想让内容跨行显示，只能靠字符串拼接或改用三引号。
    * 在双引号里硬按回车，PyCharm 会把它变成两个字符串再把两个字符串拼接在一起，并不是让这一个字符串换了行；原因是开始引号和结束引号之间的内容不允许断行。
    * > 易错点：在单双引号字符串内部直接换行不成立，跨行内容必须靠拼接或三引号承担。

* **项目中的选用原则**
    * 单引号和双引号定义出来的字符串其实是一样的，只是写法不同；项目开发中只需要守住一条原则：同一个项目里要么都用双引号，要么都用单引号，保持一种写法。
    * 三引号留给大段内容与文档注释这两类场景，日常单行字符串不占用三引号写法。
    * > 来源: P14

## 2. 字符串的构成单位

> **一句话主旨**：本节界定字符与字符串的构成关系，并给出三种定义结果的类型核验结论，为后续拼接与格式化确定数据基础。

### 2.1 字符与字符串的关系

* **字符（Character）**
    * > 定义：字符是文本世界中的基本单位，也是组成字符串的基本单位。
    * 字符串里看到的每一个字母、每一个汉字、每一个符号，包括每一个数字，都是一个字符。
    * 「字符串」这个名称的来源就是把多个字符连在一起：一个字符串由若干字符依次组成。
    * > 来源: P14

* **类型核验**
    * 三种定义方式得到的变量 `s1`、`s2`、`s3`，用 `type` 打印出来全部是 string 类型。
    * 核验写法是 `print(type(s1))` 逐行输出，三行结果的类型名一致。
    * 类型一致的直接后果是：三种写法定义出来的字符串在后续拼接、格式化处理中没有区别，差别只在写法本身。
    * > 来源: P14

## 3. 转义字符与引号冲突

> **一句话主旨**：本节给出引号嵌套冲突的成因与两条解法、转义字符的完整清单，以及换行与缩进在输出中的控制规则。

### 3.1 引号嵌套冲突与转义

* **转义字符（Escape Character）**
    * > 定义：在字符前面加一个反斜线，使该字符只表示它本身、不再承担字符串起止符号作用的写法。
    * 加反斜线之后，这个引号就只是字符串本身的引号，不再是字符串的开始或结束引号。
    * 单引号定义法下写 `'It's very good'` 会报错：内层单引号与起始单引号提前配对，`'It'` 成为一个字符串，后面的内容成了多余的部分。
    * 常见转义字符共四个：单引号本身、双引号本身、换行符、制表符。
    * > 来源: P14

* **两条解法的取舍**
    * 解法一：给内层引号加反斜线转义，让内层引号只表示引号本身，单引号字符串 `'It\'s very good'` 输出仍是 `It's very good`。
    * 解法二：更换外层引号类型，字符串里有单引号就改用双引号定义，内层单引号无法与起始引号配对，问题同样解决；反向情况同理，双引号字符串里要出现双引号时改用单引号。
    * 两条路选一条就够，两者不要叠加使用，也不必写两份。
    * > 来源: P14

### 3.2 换行与缩进的输出控制

* **\n 换行符**
    * 换行符走到该位置就执行换行操作，生效时机在输出的时候。
    * 单引号和双引号字符串本身不能写多行，要换行只能靠 `\n`；三引号字符串靠起止引号之间的真实换行，不需要 `\n`。
    * > 来源: P14

* **\t 制表符**
    * 制表符相当于按下键盘上的 `Tab` 键，产生缩进效果，需要缩进的位置在它前面各加一个 `\t`。
    * `\t` 写在字符串里控制的是输出内容的缩进，而代码本身都得顶格写，代码不能缩进。
    * > 易错点：`\n` 和 `\t` 是字符串内容里的转义序列，影响的是打印出来的排版；它们不是代码缩进，不能把两者混成一件事。

## 4. 字符串的拼接手段

> **一句话主旨**：本节讲清字面量相邻自动合并的成立前提与分隔规则，以及加号拼接的同类型约束和类型转换位置。

### 4.1 相邻字面量的自动合并

* **字面量自动合并**
    * > 定义：把多个字符串字面量直接挨着写在一起，Python 解释器在执行时自动把它们合并成一个字符串。
    * 成立前提是这些部分都得是字符串字面量，解释器才会自动合并；字面量之间加空格不加空格都可以，加一两个或四五个空格解释器都照单全收。
    * 三个字面量直接写在一起同样会自动拼好，例如 `"人生苦短" "我用Python" "OK"` 合并成 `人生苦短我用PythonOK`。
    * > 易错点：自动合并中间不会替你插入任何分隔；想要空格，必须把空格写进前一个字符串的引号里面。

* **该写法的适用判断**
    * 这种写法了解即可：既然拼的都是字面量、内容又是写死的，不如直接写成一个字符串来得干脆。
    * 变量参与拼接时自动合并失效，必须改用加号或格式化写法。
    * > 来源: P15

### 4.2 加号拼接与类型约束

* **加号拼接（Concatenation with `+`）**
    * > 定义：在第一个字符串和第二个字符串之间用加号把多个字符串合并成一个的拼接写法。
    * 加号只能拼接两个字符串，没法把非字符串和字符串直接拼起来；`int` 这样的整数类型不能直接和字符串相加。
    * 非字符串类型必须先转成字符串类型，才可以拼接；转换动作要在拼接前完成，位置就地放在该变量处。
    * 拼接顺序按书写从左到右执行：字面量、变量、逗号与空格这类分隔符也是字符串字面量，同样各用加号拼上。
    * 字符串是固定的，不能用加号给变量插入内容，属于该变量的部分必须显式写进拼接链。
    * > 来源: P15

* **str() 类型转换**
    * `str` 写法是函数名后面跟一对小括号，括号里写要转换的对象；`str(age)` 把整数类型的数字转成字符串类型，再参与拼接。
    * 未转换时的报错结论：字符串拼接仅仅能够拼接 str 类型、字符串类型，而不能拼接 int 类型。
    * PyCharm 里出问题的那一处会出现黄色背景色警告，提示「意外的类型是 int，可能的类型是 str」，即此处需要一个 str 类型却给了一个 int 类型；该警告确实会拦住程序运行。
    * > 来源: P15

```text
"大家好，我是" + name + "，今年" + str(age) + "岁，学习的专业是" + pro + ...
      |            |          |          |           |
    字符串       字符串     字符串    int -> str    字符串
      |            |          |          |           |
      +------------+----------+----------+-----------+
              加号两侧必须都是字符串，类型转换要在拼接前完成
```

## 5. 字符串格式化的两套方案

> **一句话主旨**：本节先列出加号拼接的三点短板，再给出百分号占位符与 f-string 两套格式化写法的语法规则、对应关系与易错点。

### 5.1 加号拼接存在的问题

* **加号拼接的三点短板**
    * 拼接繁琐：只要涉及两个部分的拼接就得补一个加号，一句话里有几段内容就要写几个加号。
    * 破坏字符串的完整性：代码里散落的引号、加号、变量名把原句切成碎片，看不到这个字符串的全貌，扫一眼读不出这句话到底长什么样、结构如何。
    * 还要做类型转换：字符串与非字符串拼接时必须先转成字符串，代码里又要插进一层转换调用。
    * 加号拼接只在「少量、固定」的场景还能接受，变量一多，繁琐、不易读、强制转换三件事会同时压上来。
    * > 来源: P16

### 5.2 百分号占位符方案

* **百分号占位符格式化（`%s` Placeholder）**
    * > 定义：字符串格式化本质上也是做字符串拼接，只是不再用加号连接，而是在字符串里用占位符占位、在字符串结尾的百分号之后提供数据。
    * 语法按两部分读：字符串里的 `%` 表示此处要占位，紧跟的 `s` 表示这个位置最终放入一份转换成字符串类型的数据；`s` 可理解为 string 的简写，所以 `%s` 就是把字符串填充到这个位置。
    * `%` 和 `s` 要挨着写，中间不留空格。
    * 填充变量写在字符串后面、百分号之后，它会先被转换成字符串类型，然后替换掉 `%s` 的位置。
    * `%s` 会自动把它后面的数据转成字符串再替换占位符，因此 `age` 是整数也一样能成功替代，不需要自己做类型转换。
    * > 来源: P16

* **多占位符的对应规则**
    * 多个变量时前面就写多个 `%s`：两个占位符，字符串结尾的百分号之后就要跟上两项数据。
    * 百分号后面有多项数据时，需要用括号把它们括起来并用逗号分隔，按 `(name, age, pro, hobby)` 这样的顺序写进去。
    * 第一个变量替换第一个占位符，第二个变量替换第二个占位符，位置对应不能错。
    * > 易错点：占位符数量与后面数据的数量必须一致——前面字符串里有几个占位符，百分号后面就要传几个变量或数据；顺序也不能颠倒。

### 5.3 f-string 方案

* **f-string 格式化（Formatted String Literal）**
    * > 定义：在字符串前面加一个 `f` 标识对这个字符串做格式化，字符串里面用大括号作为占位符，大括号里写具体的变量名或表达式。
    * 大括号同样是占位符，区别在于后面不用再单独指定「第一个占位符用哪个变量替代」，因为变量名已经写在括号里了。
    * 多个变量就用多个大括号，大括号里的变量名要与前面定义的变量保持一致，输出时会自动把这个变量的值拼接到这个位置。
    * 这种写法不再需要在字符串里排一串固定的 `%s`，也省掉了字符串尾部那一串数据。
    * > 易错点：字符串前面那个 `f` 不能少；少了它，大括号不会被当成占位符，而是被当成普通的字符串内容原样输出，`{name}` 就真的打印成 `{name}`。

* **两套方案的分工差别**
    * 百分号方案的占位符与数据分居字符串两端，靠顺序和数量对应；f-string 方案把变量名直接嵌进占位符内部，省掉了尾部那一串数据。
    * 改造动作都机械：百分号方案是把加号和引号删掉、该占位处直接写 `%s`；f-string 方案是把 `%s` 全部删掉、字符串前面写一个 `f`、对应位置各写一对大括号。
    * 两种方案的运行结果与原加号拼接完全一致，但字符串在代码里保持成一个完整结构，读代码时一眼能看出这句话长什么样。
    * f-string 是现在企业开发中的推荐方式，日常使用频率更高。
    * > 来源: P16

```text
print("大家好，我是%s，今年%s岁" % (name, age))      <- 占位符 + 尾部数据，两处要数清、要对齐
print(f"大家好，我是{name}，今年{age}岁")             <- 变量名写在括号里，前缀 f 不能少
```

### 5.4 四种拼接手段的横向对比

| 手段 | 写法特征 | 类型转换 | 适用场景 |
| :--- | :--- | :--- | :--- |
| 相邻字面量自动合并 | 字面量挨着写，无加号 | 不涉及 | 内容全部写死，了解即可 |
| 加号拼接 | 各部分用 `+` 相连 | 非字符串须先 `str()` 转换 | 部分极少、结构极简 |
| `%s` 占位符 | 字符串内占位，尾部 `%` 传数据 | 自动转为字符串 | 变量较多、需要明确对应关系 |
| f-string | 前缀 `f`，括号内写变量名或表达式 | 自动转为字符串 | 企业开发推荐，日常首选 |

* 拿加号拼接和格式化对比，加号的三个短板恰好被逐一对掉：不再需要为每一处拼接补一个加号，字符串在代码里保持完整结构，非字符串数据也不用自己先做类型转换。
* > 来源: P16
