## 第 1 章：核心语法-模块-介绍
> 对应分集：P73 | 原始标题：《73. 核心语法-模块-介绍》

到目前为止，我们写的每一行代码都待在同一个 `.py` 文件里：函数定义在上面，调用写在下面，点一下运行就出结果。这一章要打破这个前提——当代码不得不分到两个文件里时，一个还没见过的东西会立刻冒出来拦住我们。

### 一次跨文件调用为什么会失败

上一章我们刚把函数学完。函数的定位很清楚：它是组织好的、可以重复使用的、用来实现特定功能的代码片段。比如我们定义过这样两个函数，一个根据半径算圆的面积，一个根据半径算圆的周长：

```python
# circle_func.py
PI = 3.1415926


def circle_area(r):
    """根据半径计算圆的面积"""
    return PI * r * r


def circle_perimeter(r):
    """根据半径计算圆的周长"""
    return 2 * PI * r
```

函数定义好之后，项目里谁要算圆的面积，直接调用 `circle_area(r)` 就行，不用把公式再抄一遍——这正是函数存在的意义。

但真实项目的写法并不是把整个项目的代码全塞进一个 Python 文件。原因有两个：**代码的可读性**和**代码的可维护性**。于是我们按功能、按职责把代码拆成多个 Python 文件。假设这时又有一个文件，它要计算披萨的成本，而算成本离不开按半径求面积，于是它理所当然地写下了这句调用：

```python
# main.py


def pizza_cost(r, price):
    """根据披萨半径计算披萨成本"""
    return circle_area(r) * price


print(pizza_cost(12, 0.5))
```

这句 `circle_area(r)` 能不能跑通？在那个文件夹里，我定义了 `circle_func.py`（两个函数）和 `main.py`（披萨成本逻辑），代码就在那儿摆着。答案是：不能。

开发工具第一时间就给了提示。鼠标放到 `circle_area` 上面，它写的是**未解析的引用**，说白了就是没找到这个函数。这时候不理会提示，右键执行，运行结果照样报错，意思一样：名字为 `circle_area` 的函数未定义。

道理其实很朴素：`circle_area` 是在 `circle_func.py` 里定义的，而 `main.py` 里从来没有定义过它。每个 Python 文件都有自己独立的一套名字，A 文件里定义的名字，B 文件默认看不见。

> **定义**：一个 Python 文件就是一个独立的作用域，在别的文件里想用它的函数、变量或类，必须先把这个文件**导入**进来。

解决这个问题的整套办法，就是 Python 的模块操作。它要回答三个问题：模块是什么、怎么导入别人写好的模块、怎么把自己写的代码变成能被别人导入的模块。

### 什么是模块

模块的英文是 module。它的定义简单到有点出人意料：**我们之前定义的每一个以 `.py` 结尾的 Python 文件，就是一个 Python 模块**。

`circle_func.py` 是一个模块，`main.py` 也是一个模块。模块是 Python 程序开发的基本组织单位，一个 Python 项目里可以包含若干个模块；而在每一个模块内部，都可以定义变量、函数、类以及其他任何可执行的代码。这里提到的“类”属于下一章面向对象的内容，到时候我们会详细剖析，现在只需要记住一件事——**你写过的每一个 `.py` 文件都是模块**。

在项目开发里，这种自己写的模块有个名字，叫**自定义模块**。它和官方提供的模块是并列的两类：

| 类别 | 来源 | 典型代表 |
| --- | --- | --- |
| 自定义模块 | 项目自己定义 | `circle_func.py`、`main.py` |
| 内置模块（标准库） | Python 官方提供 | `math`、`random`、`os`、`sys`、`datetime`、`time`、`csv` |

官方的这批内置模块我们也叫**标准库**，覆盖的正是开发里最常撞见的需求：

- 做数学运算，用 `math`；
- 做随机数操作，用 `random`；
- 想拿到操作系统的相关信息，用 `os`；
- 想拿系统层面的参数信息，用 `sys`；
- 处理时间日期，有 `datetime` 和 `time`；
- 读写 csv 文件，用 `csv`。

### 模块带来的三点收益

标准库里的东西已经写好、测试过、被人用了无数遍，我们要做的只有一件事：**导入进来**。这一点要反复强调——**想用模块，就得先导入，不导入用不了**。

比如要写一个随机点名器，需要 `random` 模块，那就用 `import` 关键字把它导进来，然后才能调用模块里的功能，比如 `choice`：

```python
import random

names = ["张三", "李四", "王五", "赵六"]
print(random.choice(names))
```

既然官方已经把常用功能都封装好了，开发时我们要用什么模块就直接导入，不用再从零写一遍。顺着这个思路，模块存在的价值可以归成三条：

1. **提高代码的复用性**。常用功能已经被封装成一个个模块，要用的时候导入、调用即可，不必重写。
2. **降低开发门槛**。官方提供的内置模块足够多，项目开发不必一个模块一个模块从零做，直接调用就行，开发成本和门槛一起降了下来。
3. **避免命名冲突**。如果所有代码都堆在一个文件里，定义变量名、函数名时就得时刻提防重名；拆到多个模块之后，只需要保证**同一个模块内部**名字不冲突、不重复，就足够了。

> **结论**：模块化的本质是把“命名冲突的排查范围”从整个项目缩到一个文件，同时把“重复造轮子”变成“导入即用”。

也正因如此，项目开发中的常规做法是：把一个大的项目按功能、按职责拆成多个模块；A 模块要用到另一个模块的功能时，把那个模块导入进来就能直接用。

### 本阶段要讲的三件事

关于模块，我们这一章分三个部分推进：

1. **导入模块**：想用 Python 官方提供的内置模块，导入的语法是什么样子的；
2. **自定义模块**：项目开发中怎么自己定义一个模块，定义好之后又怎么导入使用；
3. **软件包（package）**：包的概念，以及它怎么把多个模块归到一起。

先把导入的语法讲清楚，因为自定义模块和包最终都要落到同一套导入语法上。

> 💡 **承前启后**：完成对「核心语法-模块-介绍」的理解后，下一章我们将深入探讨「核心语法-模块-导入模块」，进一步完善知识图谱体系。

## 第 2 章：核心语法-模块-导入模块
> 对应分集：P74 | 原始标题：《74. 核心语法-模块-导入模块》

要把 Python 官方提供的内置模块用起来，或者用别人已经开发好的模块，绕不开一个前置动作：**先导入，再使用**。这一节只做一件事——把导入模块的语法讲完，并当场验证每一种写法。

先说个好消息：Python 的导入语法相当灵活，它允许导入完整的一整个模块，也允许只导入这个模块当中我们要用到的那几个功能。这里说的“功能”范围很宽，可以是一个变量、一个函数，也可以是一个类或者一个方法，后面讲面向对象时会详细展开。

### 语法的两大类与五小类

五种写法其实归为两大类：

- **第一类：导入整个模块**。包括 `import 模块名` 和 `import 模块名 as 别名` 两种写法。模块整体进来，之后用“模块名.功能名”取用里面的东西。
- **第二类：从模块中导入指定功能**。包括 `from 模块名 import 功能名`、`from 模块名 import 功能名 as 别名`、`from 模块名 import *` 三种写法。只有指定的功能进来，调用时直接写功能名。

| 写法 | 语法 | 调用方式 |
| --- | --- | --- |
| 导入整个模块 | `import 模块名` | `模块名.功能名` |
| 导入整个模块并起别名 | `import 模块名 as 别名` | `别名.功能名` |
| 导入模块中的指定功能 | `from 模块名 import 功能名` | `功能名` |
| 导入模块中的指定功能并起别名 | `from 模块名 import 功能名 as 别名` | `别名` |
| 导入模块中的全部功能 | `from 模块名 import *` | `功能名` |

> **结论**：判断怎么调用，只看 `import` 后面写的是模块还是功能——写的是模块，调用就得带模块名（或别名）；写的是功能，调用就直接写功能名。

### 导入整个模块

第一种语法最短：`import` 后面跟上模块名。`import` 就是导入的意思。如果想一次性导入多个模块，多个模块名之间用逗号分隔：

```python
import random, os
```

这一句就把随机数模块和操作系统模块都导进来了，之后要用哪个功能，就写“模块名.功能名”。为什么要带这个模块名？因为进来的是整个模块，点号后面的功能名才是告诉 Python 我们到底要调这个模块里的哪一个功能。

### 用 as 给模块起别名

模块名有时很长，写起来不方便，于是可以在 `as` 后面给它起个别名：

```python
import random as rd
```

这句代码的含义是：导入的仍然是 `random` 这个模块，但导入之后它的名字变了，变成 `rd`。名字一旦改了，后面的调用就必须走别名——`rd.randint(1, 100)`，写成 `random.randint(...)` 反而不对了。

```python
import random as rd

print(rd.randint(1, 100))
```

### 从模块中导入指定功能

下面三种写法都用来导入模块中具体的功能。既然只要其中一两个功能，那就没必要把整个模块搬进来。它的语法是 `from 模块名 import 功能名`——`from` 翻译过来就是“从哪儿来”，`from` 后面是功能的出处，`import` 后面才是功能本身：

```python
from random import randint, choice
```

这行代码读作：从 `random` 这个模块当中导入两个功能，一个是 `randint`，一个是 `choice`。要导入多个功能时，功能名之间用逗号分隔。

> **易错点**：`from 模块名 import 功能名` 之后，调用时**不能**再在前面加模块名。因为进来的是功能本身，模块名在调用处已经没有意义——写成 `random.randint(...)` 会报错。

功能名太长、太复杂时，同样可以用 `as` 起别名。一旦起了别名，之后调用就只能用别名：

```python
from random import randint as rint

print(rint(1, 100))
```

### 用星号导入模块中的全部功能

在 Python 中，也可以一次性把整个模块的功能全部导入进来，写法是在 `import` 后面直接写一个 `*`：

```python
from random import *

print(randint(1, 100))
```

这个星号是**通配符**，代表这个模块里的所有功能。全部导入之后，调用时直接写功能名即可。

> **提示**：星号写起来省事，但“导入所有功能”并不等于“这个模块的所有功能都会进来”。自定义模块时可以通过一个特殊变量控制星号的范围，`random` 这类标准库模块自己也做了同样的控制，后面的小节会把这层机制讲透。

### 在 PyCharm 中逐一验证

语法讲完，直接打开 PyCharm 建一个文件来跑。

在第二章目录下新建一个 Python 文件时，直接在输入框里写 `module01/01_演示导入模块` 这样的名字：斜杠前面是目录名，斜杠后面是文件名，后缀不用自己加，回车之后 PyCharm 会自动创建这个目录，并在目录下生成对应的 `.py` 文件。

#### 导入整个模块的调用形式

第一件事是演示导入整个模块，拿生成随机数的 `random` 模块做例子。敲 `im` 会弹出提示，双击选中 `import`；紧接着敲模块名，双击选中 `random`，这句 `import random` 就写好了。`random` 属于 Python 标准库，也就是官方的内置模块，导入进来就能用。

```python
import random

for i in range(100):
    print(random.randint(1, 100))
```

这里的 `randint` 用来生成一个 `int` 类型的随机数，括号里要指定起点 `start` 和终点 `end`——写 `1, 100` 就表示随机数落在 1 到 100 之间。有一点必须记住：**这个区间是两端都包含的**，1 和 100 都可能被取到。循环 100 次，运行后就得到 100 个随机数，其中确实能见到 1，也能见到 100。

导入模块时还有一个细节：如果某句 `import` 写完之后发现它是灰色的，说明这个模块导入进来了却没有被使用，PyCharm 用颜色提醒你。

调用形式也在这里定下来：`random` 是模块名，`randint` 是它里面的一个功能（本质上是一个方法），所以写成 `random.randint(...)`。现在把 `import random` 改成 `import random as rd`，调用处换成 `rd.randint(1, 100)`——注意后面的功能名不用动，只把模块名换成别名。再运行一次，效果完全一样：

```python
import random as rd

for i in range(100):
    print(rd.randint(1, 100))
```

#### 只导入指定功能时的调用形式

把上面的代码注释掉，换成第二类写法。只用到 `randint`，那就只导入 `randint`：

```python
from random import randint

for i in range(100):
    print(randint(1, 100))
```

调用方式随之改变：前面不再需要模块名，直接写 `randint(1, 100)`。运行结果和前面毫无差别——因为调用的本来就是同一个功能，只是取用方式变了。

这个功能名同样可以起别名。给它一个 `rint`：

```python
from random import randint as rint

for i in range(100):
    print(rint(1, 100))
```

名字一旦起了别名，就必须用别名调用，原来的 `randint` 不能再用了。再次运行，结果一致。

#### 通配导入的形式

最后一种写法是把 `random` 里的所有功能一次性导入：

```python
from random import *

for i in range(100):
    print(randint(1, 100))
```

星号代表模块中的所有功能，调用时当然也是直接用功能名——`random` 里有 `randint`，那就写 `randint(1, 100)`。运行，效果依旧一样。

### 导入语句的位置

语句写完之后，还有一个必须养成的习惯：**`import` 导入语句一般写在整个 Python 文件的最上面**，具体可执行的代码写在导入语句下面。

理由有两条。第一，打开一个 Python 文件，一眼就能看清它到底用到了哪些模块，不用翻到文件中间去找。第二，模块操作一定是先导入、再使用，导入语句放在最上面，下面的代码自然就能直接用。

> **提示**：这条位置约定不是语法强制，而是可读性约定。真把导入写到文件中间，程序多半还能跑，但读代码的人就得自己去找依赖了。

## 第 3 章：核心语法-模块-自定义模块
> 对应分集：P75 | 原始标题：《75. 核心语法-模块-自定义模块》

上一节我们导入的是 `random` 这类内置模块，它们由 Python 官方写好，直接拿来用就行。这一节换一个方向：我们自己写的 `.py` 文件，怎么变成别人能导入的模块，导入时又有哪些坑要提前避开。

### 从团队的协作半径说起

开发一个项目时，把整个项目的代码全写在一个 Python 文件里是不现实的。一个项目组可能有几十号人，甚至上百号开发人员，如果所有人都同时对同一个文件做改动，维护和管理都会失控——不便于团队协作开发，也不便于项目后期的维护。

所以常规做法是按功能模块和代码的职责，把项目拆成若干个模块，每个模块都有自己的职责和作用。举个真实项目的例子：

| 模块 | 职责 |
| --- | --- |
| `config` | 配置项目当中的一些配置信息 |
| `session` | 管理项目当中涉及的一些会话信息 |
| `ai_partner` | 项目当中的主干逻辑 |

现在一个项目已经拆成了若干模块。如果要在 `ai_partner` 这个主干模块里用到 `session` 模块的功能，怎么办？直接导入就行，用的还是上一节那套导入语法。在这个例子里写成：

```python
# ai_partner.py
from session import ...


def chat(...):
    ...
```

这里最关键的一条规则是模块名的来源：**每一个 Python 文件都可以作为一个模块，模块的名字就是文件的名字**。所以 `from session` 里的 `session`，指的就是 `session.py` 这个文件名（写的时候不用带 `.py`）。

> **注意**：文件的名字可以是中文，也可以是英文。但项目开发中建议按 Python 标识符的定义规范来命名，不建议使用中文——虽然运行起来没问题，但在真实项目里几乎见不到中文文件名。

### 把功能写进模块

打开 PyCharm，在第二章目录下建一个 `module_02` 目录，里面放两个模块：`my_function.py`（要给别人用的功能）和 `main.py`（主干逻辑）。

先看 `my_function.py` 里的内容。上面定义了两个变量：

```python
# my_function.py
PI = 3.1415926
NAME = "黑马涛哥"
```

注意它们的名字没有用小写，而是全大写——这是在**定义常量**。变量是容易发生变化的数据，常量则指不会发生变化的数据，后面不再修改。`PI` 的值是 3.1415926，圆周率是固定的，不会变；名字同样不会变。所以这两个都可以定义成常量。

> **定义**：常量的名称全部大写。但这只是 Python 的命名约定——Python 当中并没有严格意义上的常量。名字大写了，它本质上仍是一个变量，照样可以被修改。全大写只是一个标记，提醒后面不要再改这两个数据。

接着下面定义了四个函数，分别输出四种分割线：

```python
def log_separator1():
    print("- " * 30)


def log_separator2():
    print("=" * 30)


def log_separator3():
    print("# " * 30)


def log_separator4():
    print("* " * 30)
```

这里的 `"- " * 30` 用到了字符串重复输出的语法：让前面的字符串“横杠加空格”重复输出 30 次，最终在一行里输出 30 遍。想输出 50 次，把 `30` 改成 `50` 就行。

```python
log_separator1()
```

输出结果就是一行横杠，重复了 30 次。这个写法的好处很直观：想输出多长的分割线，不用自己手动往后拉一串横杠，写一个乘号加数量就够了，数量也不会数错。

> **提示**：`my_function.py` 里上面那部分只是在**定义**函数，没有调用，所以直接运行这个模块，什么都不会输出。想让函数执行，必须在下面写调用语句。

### 导入自定义模块

现在把需求落到 `main.py`：调用 `my_function.py` 里的函数。步骤只有两步——第一步导入模块，第二步使用模块中的功能。

第一步，先按第一类语法把整个模块导进来，`import` 后面跟上模块名：

```python
# main.py
import my_function

print(my_function.PI)
print(my_function.NAME)
my_function.log_separator1()
my_function.log_separator3()
```

模块名就是文件名，同样不用加 `.py`。导入之后，输入 `my_function.` 会看到提示里既有四个函数，也有两个常量——这正好印证了模块里能装什么：常量、变量、函数，以及任意其他可执行的代码。

因为导入的是整个模块，取用里面的东西就得走“模块名.功能名”：常量、变量在点号后面直接跟名字，函数在点号后面加括号调用。运行结果依次是 `3.1415926`、`黑马涛哥`，然后是 `log_separator1` 输出的一行横杠和 `log_separator3` 输出的一行井号。

#### import 会执行模块里的顶层代码

运行之后有个地方对不上：输出里最上面多了一道横杠，但我们在 `main.py` 里并没有调用它。

这道横杠来自 `my_function.py` 里那句测试性的函数调用。原因在于：**用 `import` 把一个模块导入进来时，模块当中的代码是会执行的**。导入进来的不只是两个常量和四个函数，还有那句写在顶层的可执行代码。把那句调用注释掉再运行，多出来的横杠就没有了。

由此引出一个真问题。我们定义好模块后，通常要测试模块里的功能——下面那些调用函数、输出常量的代码，其实就是测试当前模块的代码。那么别的模块导入我这个模块时，我希望这段测试代码运行吗？当然不希望：你导入我的模块，拿上面定义好的功能用就行，测试代码不该跟着跑。

最直接的办法是删掉或者注释掉测试代码，但下一次要再测这个模块时，又得把它恢复回来，来回折腾，很不方便。

#### 用 `__name__` 把测试代码保护起来

解决办法是借助 Python 提供的一个内置变量 `__name__`：

```python
print(__name__)
```

这个变量前后各有两个下划线。**在 Python 里，凡是以下划线开头（更准确地说，是前后都带双下划线）的变量或方法，都是比较特殊的变量或方法，属于 Python 的内置变量。** `__name__` 表示的是**当前模块的名字**。

它的取值有一个明确的分岔：

> **结论**：直接运行当前模块时，`__name__` 的值是字符串 `"__main__"`；当这个模块被别的模块导入时，`__name__` 的值就是模块名，也就是文件名。

在 `my_function.py` 里直接打印，得到的是 `__main__`；而在 `main.py` 里运行、`my_function` 是被导入的那个模块时，得到的值就是 `my_function`。注意这个变量我们并没有定义过，直接就能用，因为它是内置的。

有了这个分岔，就能把测试代码放进条件判断：只有当 `__name__` 的值等于 `__main__`，也就是当前模块是被直接运行的时候，才执行这段测试代码；模块被导入时，这段逻辑不会执行。

```python
# 执行当前文件，则会执行如下代码
# 被当作模块导入，则如下代码不执行
if __name__ == "__main__":
    log_separator1()
    log_separator2()
    log_separator3()
    log_separator4()
```

现在在 `my_function.py` 里直接运行，分割线照常输出，测试代码执行了；再到 `main.py` 里运行，那道横杠不再出现——因为此时 `__name__` 是模块名 `my_function`，不等于 `__main__`，条件不成立，里面的代码自然就不执行了。

> **提示**：在 PyCharm 里输入 `main` 会出现一个快捷方式，选中之后它会自动生成 `if __name__ == "__main__":` 这个结构，回车定好框架，直接在里面写测试代码即可。

### 导入模块中的功能与 `__all__` 的控制

回到 `main.py`，把“导入整个模块”的写法注释掉，换成第二类语法：直接导入模块中的功能。

```python
# main.py
from my_function import log_separator1, log_separator3, PI, NAME

print(PI)
print(NAME)
log_separator1()
log_separator3()
```

要导入哪些功能，就在 `import` 后面写哪些功能名，多个之间用逗号分隔。此时调用处不用再加模块名——`my_function.` 可以整个省掉，函数直接用名字调用。

> **易错点**：没有导入的功能就是不能调用。上面只导入了 `log_separator1` 和 `log_separator3`，这时候去调 `log_separator2` 会直接报错。

顺带一个提高效率的小操作：想快速删掉一行，按 `Ctrl+Y` 即可。

想导入全部功能，就用星号：

```python
from my_function import *

log_separator2()
log_separator4()
```

这句代码运行正常。但这里的星号**未必等于模块里的所有功能**，因为在自定义模块时，我们可以自己控制这个星号到底导入哪些功能。控制它的，是另一个特殊变量 `__all__`。

#### `__all__` 的写法与生效范围

`__all__` 同样是前后各两个下划线的模块级特殊变量，它的作用就是指定 `import *` 里那个星号通配了哪些功能。

在 `my_function.py` 里，通常把 `__all__` 写在模块的最上面，后面跟一个列表，列表里以字符串的形式写明要让星号带出去的功能：

```python
# __all__ 用来指定 from ... import * 导入哪些功能
__all__ = ["log_separator1", "log_separator3", "PI"]
```

在这个列表里我们只放了三个功能，`NAME` 没进去，`log_separator2` 和 `log_separator4` 也没进去。回到 `main.py`，`NAME` 那个位置立刻报错，强行执行也会提示 `NAME` 未定义；把 `NAME` 删掉，去调用 `log_separator2` 或 `log_separator4`，同样报错，提示 `log_separator2` 未定义。

> **结论**：从模块导入所有功能时写 `import *`，导入的不一定是模块中的全部功能。要看模块里有没有定义 `__all__`：定义了，导入的就是 `__all__` 列表里指定的那些功能；没有定义，导入的才是整个模块的所有功能。

这里还有一条边界必须记住：**`__all__` 只影响 `import` 后面那个星号的导入范围，正常导入具体功能不受它影响。** 你明确写 `from my_function import NAME`，照样能导进来。

#### 回头验证标准库的 `__all__`

上一节演示导入模块语法时，我们导入过 `random` 模块当中的所有功能。现在按住 `Ctrl` 键点击 `random` 这个单词，可以跳到源码 `random.py`。在这个文件里，我们能见到 `__all__`，而且它就是一个列表。列表里一个个字符串元素的作用，现在应该很清楚了：它们指定的正是 `from random import *` 中那个星号代表的功能。

对照着看一眼就很直观：`__all__` 前面是双下划线开头、后面是双下划线结束，属于模块级别的特殊变量；它的职责单一而明确。把这一节的两个特殊变量并排记住：

| 特殊变量 | 取值规则 | 作用 |
| --- | --- | --- |
| `__name__` | 直接运行本模块时为 `"__main__"`，被导入时为模块名 | 判断当前模块是被直接运行还是被导入，用来保护测试代码 |
| `__all__` | 模块中定义的字符串列表 | 指定 `from 模块名 import *` 到底导入哪些功能，不影响导入具体功能 |

自定义模块本身并不复杂：把不同功能定义在各自的 Python 文件里，别的模块要用就按导入语法导进来。真正需要留心的，是导入会执行模块顶层代码这件事，以及星号背后可能被 `__all__` 收窄的范围。

## 第 4 章：核心语法-模块-包(package)
> 对应分集：P76 | 原始标题：《76. 核心语法-模块-包(package)》

前面两节已经把模块用起来了：项目按业务、功能、职责拆成多个模块，开发时用到哪个模块的功能就把哪个模块导入进来。但大型项目里涉及的功能模块非常多，此时为了便于项目的管理、开发以及后期的维护，我们通常会对这些模块做**归类处理**——数据处理的模块归到一类，网络应用开发的模块归到一类，常见工具操作的模块再归到一类。Python 里承担归类职责的结构，就是软件包。

### 包的本质与 `__init__.py`

软件包的英文是 package。既然模块本身就是一个 Python 文件，那么要对多个文件做归类，在物理层面最自然的做法就是**把它们放进一个文件夹**。所以：

> **定义**：软件包本质上就是一个文件夹，文件夹下可以存放若干个 Python 文件，而每一个 Python 文件都是一个模块。

比如有个 `utils` 文件夹（utils 是工具的意思），里面放了多个 `.py` 文件，每个文件都是一个模块。但文件夹并不自动等于包——包里还必须包含一个比较特殊的文件：`__init__.py`。注意它的前后同样各有两个下划线，这个文件用来描述当前包的信息。

判断规则只有一条：

> **结论**：一个文件夹里如果有 `__init__.py`，那它就是一个 Python 软件包；如果没有这个文件，那它只是个普通文件夹。

包的作用就是来管理其中的多个模块。也可以把包看成一个模块，而在这个模块下又包含若干个子模块——所以包做的事情，就是模块管理、对模块归类操作。

从结构上看，包、模块、功能之间是一层套一层的关系：

```text
utils/                  <- 包（文件夹 + __init__.py）
├── __init__.py         <- 包的描述文件
├── my_var.py           <- 模块：常量 PI、NAME
└── my_function.py      <- 模块：函数 log_separator1 ~ 4
```

读图说明：最外层是包，包的内层是一个个模块，模块内部才是一个个具体功能（变量、常量、函数等）。

### 包的创建方式

现在问题是：一个普通文件夹怎么变成软件包？右键新建一个 Python 文件，文件名写成两个下划线、`init`、再两个下划线，回车之后 `__init__.py` 就建好了。**一旦这个文件出现在文件夹下，文件夹的标识就变了**——之前在 PyCharm 里它是普通文件夹的图标，现在成了包，图标上会带一个小圆点。

创建包还有更省事的方式：在文件夹上右键新建，菜单里除了“目录”之外还有一项 **Python 软件包**，它的图标前面本来就带一个小圆圈。选中它、随便起个名字（比如 `abc`）回车，文件夹里就会自动多出一个 `__init__.py`，内容为空，这就表示它是一个软件包。

`__init__.py` 里的内容不是必须的。什么都不定义完全可以；也可以在里面描述这个包的信息：

```python
__version__ = "1.0.0"
__author__ = "黑马涛哥"
```

`__version__` 用来描述当前包的版本，`__author__` 描述包的作者。再次强调：一旦以双下划线开头，就说明这个变量不是业务当中的常规变量，而是一个特殊变量；业务中的变量通常不会带这个前缀。在项目开发中，`__init__.py` 里有时还会完成一些初始化环境准备的工作，这个阶段先不涉及。

### 导入包中模块的五种形式

有了包之后，导入的语法和导入模块类似，变化在于**模块名前面多了一级包名**。原来写模块的地方，现在写成 `包名.模块名`。

| 形式 | 语法 | 调用方式 | 导入对象 |
| --- | --- | --- | --- |
| 一 | `import 包名.模块名` | `包名.模块名.功能名` | 整个模块 |
| 二 | `from 包名 import 模块名` | `模块名.功能名` | 包下的指定模块 |
| 三 | `from 包名 import *` | `模块名.功能名` | 包下的所有模块 |
| 四 | `from 包名.模块名 import 功能名` | `功能名` | 模块中的指定功能 |
| 五 | `from 包名.模块名 import *` | `功能名` | 模块中的所有功能 |

前三种导入的都是**模块**，后两种导入的是**模块当中的功能**。调用形式依旧遵循同一条规律：`import` 后面写的是包名加模块名，调用就带上包名和模块名；`import` 后面写的是模块名，调用只带模块名；`import` 后面写的是功能名，调用直接写功能名。

### 在 PyCharm 中验证

在第二章目录下建一个 `utils` 文件夹，里面放两个模块：

```python
# utils/my_var.py
PI = 3.1415926
NAME = "黑马涛哥"
```

```python
# utils/my_function.py
def log_separator1():
    print("- " * 30)


def log_separator2():
    print("=" * 30)


def log_separator3():
    print("# " * 30)


def log_separator4():
    print("* " * 30)
```

这个 `utils` 一开始是普通文件夹还是包？**先看它下面有没有 `__init__.py`——没有，所以它是普通文件夹。** 按前面讲的方式建出 `__init__.py` 之后，它才算成为包。

接着在第二章目录下新建一个文件 `包.py`（就是拿来演示导入包中模块的），分别验证五种写法。

#### 导入包中的模块

第一种写法，直接 `import`。如果在这里直接写 `import my_function`，会发现没有提示并且报错——因为这个模块在 `utils` 这个包下面，导入时必须把包名带上：

```python
import utils.my_function

utils.my_function.log_separator1()
utils.my_function.log_separator2()
```

输入 `utils.` 之后，提示里会出现包里定义的 `version`、作者这类包信息；后面跟上模块名 `my_function`。调用形式是三级：包名、模块名、功能名。

> **提示**：这类写法偶尔会遇到 PyCharm 提示“找不到 my_function”，但程序依然能正常运行，那是开发工具静态分析的问题，语法本身没问题，把提示忽略掉即可。

第二种写法，把包名放到 `from` 后面，`import` 后面写模块名：

```python
from utils import my_function

my_function.log_separator1()
```

此时 `import` 后面是模块名，所以调用时不再需要包名，写“模块名.功能名”就够了。

#### 导入包下所有模块

第三种写法是把 `import` 后面的模块名替换成星号，本意是导入包下的所有模块：

```python
from utils import *

my_function.log_separator1()
my_var.PI
```

把刚才能跑通的调用代码原样复制过来，结果直接报错：未解析的 `my_function`，运行时也提示 `my_function` 未定义。原因不是语法写错了，而是**这种方式默认不允许这样导入**。

> **易错点**：要通过 `from 包名 import *` 导入包下的所有模块，必须在 `__init__.py` 文件当中添加特殊变量 `__all__`，用它指定这个星号到底代表哪些模块。没有加这个变量，导入就会失败。

在 `__init__.py` 里补上：

```python
__all__ = ["my_function", "my_var"]
```

有了这个列表，原来报错的地方立刻恢复正常，程序也能正常运行，而且此时星号代表的不只是 `my_function` 一个模块，还包括 `my_var`——可以继续输出 `my_var` 里的 `PI` 和 `NAME`。反过来，如果把这个列表中的 `my_var` 去掉，星号就只带进 `my_function`，`my_var` 用不了。

#### 导入模块中的功能

最后两种形式是导入模块中的具体功能：

```python
from utils.my_function import log_separator1, log_separator3

log_separator1()
log_separator3()
```

`from` 后面写“包名.模块名”，`import` 后面写要用的功能名。既然导入的是功能，调用时直接写功能名就行，运行照常正常。

### `from` 后面是路径：相对与绝对两种写法

还有一个必须提前知道的注意事项，就藏在 `from` 后面那一串 `包名.模块名` 里——**这其实是一种路径的写法**。

`包.py` 一开始放在第二章目录下，`from utils.my_function import ...` 能正常工作，因为 Python 会在**当前 Python 文件所在的目录**下找 `utils` 这个包，而第二章目录下正好有它。现在把这个文件移动（重构）到 `my_module` 目录下，同样的代码立刻报错：未解析的引用 `utils`。因为它在 `my_module` 这个当前目录下找不到 `utils`——`utils` 并不在 `my_module` 里面。把它移回第二章目录，报错又消失了。

如果这个文件确实要放在 `my_module` 目录下，还有另一种写法：**用绝对路径**。绝对路径指从项目的根目录开始找：

```python
from 第二章.utils.my_function import log_separator1
```

绝对路径的查找顺序是：从项目根目录出发，先找第一级目录“第二章”，第二章下有 `utils` 这个包，包下有 `my_function` 这个模块，于是找到目标。用这种写法，把文件移到第二章目录外面，依然能正常运行——因为它不从当前文件所在目录找起。

| 写法 | 查找起点 | 举例 | 找不到时的表现 |
| --- | --- | --- | --- |
| 相对路径 | 当前文件所在目录 | `from utils.my_function import ...` | 报未解析的引用 |
| 绝对路径 | 项目根目录 | `from 第二章.utils.my_function import ...` | 路径正确即可用 |

两种写法都可以用，选哪种取决于文件放在哪里、想不想让代码对目录位置敏感。

> **提示**：这个阶段为了减轻学习负担，文件夹名、包名和文件名的演示一律用了中文，方便查看和理解；中文运行起来其实也没问题。但实际项目开发中，文件夹名、包名和文件名一般都是英文。

### 三个要抓牢的问题

包这部分内容收尾时，把该记住的东西归成三块。

**第一，什么是包，包有什么作用。** 包的本质是一个文件夹，用来管理 Python 当中的多个模块；通过包对模块做归类处理，从而方便项目的管理和后期的维护。

**第二，`__init__.py` 的作用有两个。** 一是标识当前目录是一个包，而不是普通文件夹——普通文件夹里加上这个文件，就变成了软件包；二是用来描述当前包的信息，包括在其中声明 `__all__` 特殊变量，指定 `import *` 到底导入哪些模块。

**第三，导入包的方式多种多样。** 可以用 `import 包名.模块名` 直接导入模块，也可以在 `from` 后面跟包名、`import` 后面跟模块名导入模块，这三种都属于导入包当中的指定模块；后两种则是导入包下模块当中的特定功能。特别要注意的是，如果要导入包下的所有模块（`from 包名 import *`），必须在 `__init__.py` 中声明 `__all__`，用它来指定要导入哪些模块。

到此，Python 模块的基本操作就讲完了。模块在实际项目中的应用场景以及一些高级用法，会在后面的案例中继续剖析和使用。
