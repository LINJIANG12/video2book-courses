## 第 1 章：核心语法-面向对象基础-概述
> 对应分集：P77 | 原始标题：《77. 核心语法-面向对象基础-概述》

### 1. 核心语法的最后一个部分

Python 核心语法学到这一步，前面四个部分已经装进兜里了：数据的存储与运算、数据的逻辑处理（也就是流程控制语句）、各类存储容器，以及函数与模块的相关操作语法。

接下来是核心语法的最后一部分：面向对象（Object-Oriented Programming，OOP）。这部分内容做了分层的设计与教学，分成「面向对象基础」与「面向对象高级」两段——先把基础掌握牢、能熟练应用，再进入高级部分。

### 2. 面向过程编程

#### 2.1 之前写过的代码属于哪一种编程方式

先回答一个很容易冒出来的疑问：没有学面向对象这种编程思想，之前的 Python 代码不也照样写出来了吗？不小的需求不也完成了吗？确实如此。

回头看之前完成案例的路子：要完成一个需求，就先分析第一步做什么、第二步做什么，分析完毕之后，再按照分析出来的步骤一步一步把需求实现出来，最终需求也就实现了。这种编程方式有名字，叫面向过程编程。

> **定义**：面向过程编程把一个大的需求拆解为一系列要执行的细化步骤，然后按照步骤依次执行这些任务。

#### 2.2 盖房子的步骤拆解

拿盖房子打个比方。要盖一栋房子，面向过程的思路会先把整个需求拆开：

```text
盖一栋房子（面向过程的拆解）

  1. 平整地基
       |
       v
  2. 在地基当中打桩
       |
       v
  3. 浇筑地基
       |
       v
  4. 主体施工
       |
       v
  5. 砌墙
       |
       v
  6. 外墙施工（外立面）
       |
       v
  7. 室内硬装
       |
       v
  8. 室内软装
```

一个大需求就这样被拆成了一串要执行的步骤：地基平整好了，第二步在地基当中打桩，紧接着第三步浇筑地基；地基浇筑好了，在地基上进行主体施工；主体施工完了再去砌墙，砌墙完了做外墙施工也就是外立面，外立面做完了做室内硬装，室内硬装完了再做室内软装。一步一步走完，需求就实现了。

#### 2.3 关注点与适用场景

面向过程编程关注的是需求实现的流程、需求实现的步骤——关注点落在「流程」和「步骤」这两个词上。它非常直接：分析步骤，然后一步一步执行就完事了。

它主要适用于一些简单的、线性的任务。对于这类任务，先去分析步骤，再按照步骤一步一步完成对应的需求就可以了。

> **结论**：面向过程编程关注「怎么做」，把需求拆成步骤再依次执行，适合简单的、线性的任务。

### 3. 面向对象编程中的对象

#### 3.1 对象的含义

要想搞清楚面向对象编程，先得搞清楚什么是对象。对象可以简单理解为日常生活当中、或者说现实当中具体的人或者是物。面向对象编程里有一句话叫「万物皆对象」——你所看到的所有东西，都可以认为它就是一个对象。对象就是生活当中具体的人或者物数字化的化身。

回到盖房子这件事：平整地基的过程中看到的那台推土机，就可以认为是一个对象；水泥罐车也是一个对象；整个施工过程当中的工人——地基施工的工人、砌墙的工人、主体施工的工人——同样都是对象；建筑当中用到的一系列建筑材料，包括砖、水泥、钢筋以及瓷砖，也都可以看作对象。依据就是那句话：万物皆对象。

> **定义**：把一个人或者物的特征与功能打包到一起，就组成了一个对象；对象是面向对象编程的基本单元。

#### 3.2 属性：对象的特征

对象的特征，在面向对象编程当中称为属性。几类对象的属性可以这样看：

| 对象 | 属性 |
| --- | --- |
| 推土机 | 颜色、油耗、马力 |
| 水泥罐车 | 容量、颜色、臂长 |
| 工人 | 工种、年龄、工服的颜色、技能 |
| 建筑材料 | 各自具有自己的属性 |

推土机的颜色是它的特征，油耗也是它的属性，马力同样是；水泥罐车的容量、颜色以及臂长，都是它的特征或者叫属性；对于工人来说，工种、年龄、工服的颜色、技能，都是他的属性。

#### 3.3 方法：对象的功能

对象除了属性以外，还有它的功能，而功能在面向对象编程当中称为对象的方法。

方法这个词其实一点都不陌生：在数据容器部分，list、set、字典、元组都讲过各自对应的方法。每一种数据容器其实都是一种对象，而这个对象当中具备的功能，就称之为方法。

推土机有自己的功能，比如推平、挖掘，这在面向对象当中就称之为对象当中的方法；水泥罐车也有自己的功能方法；工人、建筑材料同样都有自己的方法。

> **结论**：一个对象由属性和方法构成——属性是对象的特征，方法是对象所具备的功能。

### 4. 面向对象编程的关注点

面向对象编程的关注点在于「谁来帮我做这件事」。要打地基了，就让推土机这个对象帮我推平、进行挖掘；要浇筑了，就让水泥罐车这个对象帮我进行浇筑。

它的关注点不在于第一步、第二步、第三步该怎么一步一步去做，而在于谁能帮我来干这件事——它更像是一个指挥者：谁能帮我干这件事，我就让谁来做这件事，就完事了。

| 对比项 | 面向过程编程 | 面向对象编程 |
| --- | --- | --- |
| 关注点 | 需求实现的流程与步骤 | 谁来帮我完成这件事 |
| 组织方式 | 把需求拆成一系列步骤依次执行 | 把特征与功能打包成对象，再指挥对象去做 |
| 写法特点 | 直接、偏向线性推进 | 像指挥者，调用对象的方法完成操作 |
| 适用场景 | 简单的、线性的任务 | 以对象为基本单元组织的程序 |

### 5. 类与对象的关系

#### 5.1 类是一组属性与方法的模板

类用来描述一组具有相同特征和相同功能的模板。在面向对象当中特征叫属性、功能叫方法，所以类描述的是一组具有相同属性和方法的模板——注意，它提供的是一组模板。

拿做月饼来比：类就相当于模板，月饼就是基于这样的月饼模板做出来的。模板里面有对应的颜色、形状、大小、厚度，这些都是它的属性；而做出来的月饼具备什么功能？它可以提供能量，可以进行文化传承，这些都是它的功能。

> **定义**：类（class）是描述一组具有相同属性和方法的模板。

#### 5.2 对象是类的实例

对象是类的实例，是基于类所创建出来的，也叫实例对象。实例可以简单理解为：按照图纸所造出来的具体的东西、实际的东西。

按照月饼这个模板可以制作出各种各样的月饼，而且基于一个模板可以制作出 N 多个月饼；每一块月饼就是一个对象，而这个对象正是基于这个模板制作出来的。

```text
        类 Car：一组具有相同属性和方法的模板
        +--------------------------------+
        |  属性（特征）                  |
        |  方法（功能）                  |
        +---------------+----------------+
                        |
                        | 实例化：类名 + 小括号
                        v
      +-----------------+-----------------+
      |                 |                 |
      v                 v                 v
   对象 c1           对象 c2           对象 c3 ...
```

对象是由类创建出来的；创建对象的这个过程称为对象的实例化；一个类可以实例化出多个对象，一个类可以创建出无数个对象。

> **易错点**：说到「对象」时要同时想到模板与产物两层含义——类是模板，对象是基于这个模板制造出来的实际物品，别把两者混为一谈。

## 第 2 章：核心语法-面向对象基础-类与对象
> 对应分集：P78 | 原始标题：《78. 核心语法-面向对象基础-类与对象》

### 1. 定义类与创建对象的基本语法

类描述的是一组具有相同属性和方法的模板，对象是基于类这个模板所创建出来的实例；对象由类构建出来，而一个类可以创建出无数个对象。所以这一部分要重点解决两个问题：怎么定义这个类，以及有了类之后怎么创建对象。

#### 1.1 class 关键字与最简单的类

定义类的时候需要用一个关键字 `class`，它专门用来定义类。`class` 之后跟上类名，后面加上一个冒号——每一个类都有自己的名字。紧接着在 `class` 的代码块当中，也就是下面缩进的位置，需要定义这个类的结构。

对于一个最简单的类来说，里面的结构可以什么都不定义，但要保证语法是完整的，所以在代码块里写一个 `pass` 空语句就够了：

```python
class Car:
    pass
```

这样定义出来的就是一个最简单的类，它只有一个类名。

#### 1.2 由类创建对象

创建对象的语法是：前面写一个对象名，其实就是一个变量名，然后为这个变量赋一个值；后面基于这个类来构建对象，写法就是类名后面写上一对小括号。

```python
c1 = Car()
```

类名后面跟上一对小括号，就代表要基于这个类来创建对象。而一个类是可以创建出多个对象的。

#### 1.3 为对象动态添加属性

对象是由属性和方法组成的，这一部分先只关注属性。为对象增加属性的方式是 `对象名.属性名`：如果要为它赋值、要添加属性，就在等号之后跟上这个属性名对应的属性值。一个对象当中可以添加多个属性，有多少个就在后面继续写多少个。

```python
c1.color = "红色"
c1.brand = "BMW"
c1.name = "X5"
c1.price = 500000
```

`price` 赋的是 50 万，也就是 50 后面四个零。这样 c1 这个对象就动态地增加了四个属性。

```text
class Car:
    pass
        |
        |  c1 = Car()          类名 + 小括号
        v
   +----------+    动态添加属性：对象名.属性名 = 属性值
   |    c1    |---->  c1.color = "红色"
   +----------+---->  c1.brand = "BMW"
                 ---->  c1.name  = "X5"
                 ---->  c1.price = 500000
```

### 2. 类名的命名规范：大驼峰命名法

上面定义类时类名写的是 `Car`，首字母 `C` 是大写的。类名的命名规范跟变量名的命名规范、函数名的命名规范是有差异的：类名遵循大驼峰命名法。

所谓驼峰，就是骆驼的驼峰。在大驼峰命名法这种命名规范当中，每个单词的首字母都是大写，多个单词之间没有分隔符，直接拼接在一起。比如类名由 `user` 和 `info` 两个单词组成：`user` 当中的 `U` 需要大写，`info` 当中的 `I` 也需要大写，然后把两个单词直接拼接在一块，中间没有任何分隔符；再比如 `user_accounts`，`user` 是一个单词 `U` 大写，`accounts` 是一个单词 `A` 大写，每个单词的首字母都是大写。

```text
单词拆分   :  user        info
首字母大写 :  U           I
拼接       :  UserInfo          （单词之间没有分隔符）
```

正因为大写字母一块起来、一块下去，形状像驼峰，所以这种命名法被形象地称为大驼峰命名法。而变量名与函数名不以大写开头，是按小写字母加下划线的方式书写的，例如 `c1`、`c_brand`、`total_cost`。

> **提示**：类名用大驼峰（`Car`、`UserInfo`、`UserAccounts`），变量名和函数名用小写字母加下划线（`c_brand`、`total_cost`），两套规范不要混用。

### 3. 直接输出对象与 __dict__ 属性

#### 3.1 直接输出对象得到的是内存地址

属性添加好之后，直接把 `c1` 输出出来看看，会发现确实输出了内容，但内容看不太懂：

```python
print(c1)   # <__main__.Car object at 0x0000...>
```

逐段解读一下：`Car` 代表所输出的这个 `c1` 对象是由哪个类创建出来的，也就是它是 `Car` 这个类型的；后面的 `object` 代表这是一个对象实例；`at` 后面那一串 `0x...` 是对象的内存地址，它是一个十六进制数。

十进制是用 0 到 9 这十个数来描述的，而十六进制是用 0 到 9 再加上 `a b c d e f` 来描述。当创建了一个对象之后，这个对象在内存当中是要占用内存空间的，这块内存区域存放的就是这个对象，而每一块内存区域都会有一个内存地址，地址指向的就是这块内存空间。所以直接输出对象，输出的就是这个对象的内存地址；而每一次运行程序，这个内存地址都会发生变化。

#### 3.2 __dict__ 以字典形式列出全部属性

想看对象当中所有的属性，可以用双下划线开头的 `__dict__`。它是 Python 当中用户自定义实例对象的一个特殊属性，会以字典形式存储对象当中所有的属性——也就是把对象当中所有的属性以及属性值，以字典的键值对形式存储起来。

```python
print(c1.__dict__)
# {'color': '红色', 'brand': 'BMW', 'name': 'X5', 'price': 500000}
```

运行之后看到的就是一个大括号括起来的字典，里面是 `key: value`、`key: value` 一个一个的键值对，c1 这个对象当中的四个属性全部列了出来，一次性就看清了对象当中的所有属性。

如果只想查看某一个属性，比如汽车的品牌 `brand`，那就不用输出 `__dict__` 了，直接 `c1.brand` 就可以看到它的品牌：赋值是在后面等号后面加上对应的值，取值就直接 `c1.brand`，通过 `对象名.属性名` 的方式来获取。

### 4. 动态添加属性的问题

在创建完对象之后动态地为对象添加属性，这种方式可以，但不推荐。

> **结论**：不推荐在创建完对象之后动态地为对象添加属性。

原因在于，如果基于这种方式动态地为对象添加属性，会降低项目的可读性，降低代码的可读性与可维护性，并且增加开发的难度。定义了这个类，但通过这个类很难看出类当中到底有哪些属性——因为并没有在定义类的时候指定类当中到底有哪些属性，而是在创建对象、用到这个类的时候，要用哪个属性就直接增加一个属性。这样在调用这个对象的时候，对象当中到底有哪些属性，是不便于管理和维护的。

更关键的是，类描述的就是一组具有相同属性和方法的模板，而当前这个类并没有起到模板的作用：每一个对象当中到底有哪些属性，是创建完对象之后自己给添加上去的。所以这种方式可以是可以，但不推荐。

### 5. 在类中通过 __init__ 声明属性

推荐的写法是：在定义类的时候，就指定这个实例对象对应的属性。

#### 5.1 函数与方法的区别

推荐的写法里，类当中会出现一个用 `def` 定义的东西。同样是 `def` 定义的，定义在类的外面我们称之为函数，定义在类当中的这个函数我们称之为方法。

> **结论**：方法本质还是一个函数，区别只在于编写的位置——定义在类的里面就称之为方法，定义在类的外面就称之为函数。

`__init__` 定义在类的里面，所以它就是一个方法，它用来指定这个类所创建出来的实例对象有哪些属性。

#### 5.2 __init__ 的作用与自动调用

`__init__` 是一个初始化的方法，方法名是固定的。一旦见到双下划线开头的方法或者属性，就要知道这是一类比较特殊的属性或者方法。

它会在对象创建后自动调用——也就是说这个方法不是手动调用的，是在对象创建完毕之后由 Python 解释器自动调用。它主要用来设置对象的初始状态，对当前来说主要就是设置对象的属性，也可以完成其他一些初始化的操作。

#### 5.3 self 参数与属性赋值的写法

`__init__` 的后面要跟上对应的形参列表，而这个形参列表当中的第一个形参必须是 `self`。`self` 代表的就是所创建出来的对象实例，代表当前对象，它必须放在形参列表的第一个位置。如果接触过 Java 或者 JS，会发现它就相当于那里的 `this`。

在 `__init__` 的逻辑当中，通过 `self` 这个当前实例对象就可以为它里面的属性赋值，写法是 `self.属性名 = 参数名`；如果实例对象当中有多个属性，那就一个属性一个属性地赋值。

```python
class Car:
    def __init__(self, c_brand, c_name, c_price):
        self.brand = c_brand
        self.name = c_name
        self.price = c_price
```

#### 5.4 创建对象时的参数传递

由于在类当中增加了 `__init__` 这个初始化方法，创建对象时的语法和之前略微有点差异：类名后面跟上一对小括号，小括号当中要指定参数列表，而这个参数最终会传递给 `__init__` 后面的参数列表。形参列表当中定义了多少个参数（`self` 不算），在实例化对象的时候就需要指定多少个参数。

```python
c1 = Car("BMW", "X5", 500000)
```

上面这个类在声明 `__init__` 时除了 `self` 以外指定了三个参数，分别是 `c_brand`、`c_name`、`c_price`；在 `__init__` 当中通过 `self` 获取到当前的实例对象，为它的 `brand`、`name`、`price` 这三个属性分别赋值。创建对象时括号里也传递三个参数：`BMW` 传递给 `c_brand`，`X5` 传递给 `c_name`，50 万传递给 `c_price`。

> **提示**：`self` 代表当前创建出来的实例对象，在基于类构建对象的时候，这个参数是不用传递的，只需要传递 `self` 之后的几个参数。

### 6. 以 __init__ 声明属性后的完整写法

把上面的写法完整展开：在 `__init__` 当中声明四个形参 `c_color`、`c_brand`、`c_name`、`c_price`，形参名前面统一加 `c_` 是为了与属性名区分开——`c_brand`、`c_color`、`c_name`、`c_price` 是将来传递进来的参数值，而 `color`、`brand`、`name`、`price` 才是这个对象的属性。

```python
class Car:
    def __init__(self, c_color, c_brand, c_name, c_price):
        # 初始化方法：对象创建时自动调用，为对象设置属性
        self.color = c_color
        self.brand = c_brand
        self.name = c_name
        self.price = c_price
        print("Car 类型的对象初始化完毕，对象属性已经添加完毕")


c1 = Car("红色", "BMW", "X7", 800000)
```

创建对象时小括号里要传递四个参数——`self` 不用管，只用传递 `self` 之后的四个参数：第一个是 `color`，传「红色」；第二个是品牌，传 `BMW`；第三个是名字，传 `X7`；第四个是价格，是一个 `int` 类型，传 80 万。构建对象的时候，红色会传递给 `c_color`，`BMW` 传递给 `c_brand`，`X7` 传递给 `c_name`，80 万传递给 `c_price`，最终这几个参数值就赋值给了这个对象的四个属性。

运行之后，「Car 类型的对象初始化完毕」这句话输出了，说明基于 `Car` 这个类去构建实例对象的时候，确实调用了 `__init__` 这个方法；既然调用了，那么创建出来的对象这几个属性也就赋上值了。再输出 `c1.__dict__`，对象当中所有的属性、键值对就都列出来了：

```python
print(c1.__dict__)
# {'color': '红色', 'brand': 'BMW', 'name': 'X7', 'price': 800000}
```

这时再创建第二个对象 `c2`，构建对象时同样必须传递这几个参数；如果不传递，运行起来就会直接报错，说缺少这几个参数。换一组值再建一个：

```python
c2 = Car("白色", "奔驰", "E300", 450000)
print(c2.__dict__)
# {'color': '白色', 'brand': '奔驰', 'name': 'E300', 'price': 450000}
```

同一套类构建出来的对象，它里面所具备的属性都是一样的，只不过属性的值不一样。这样类就真正成了一个模板：类创建出来的实例对象到底有哪些属性，在类里面已经声明好了。

### 7. 定义类时的两个关键点

| 关键点 | 结论 |
| --- | --- |
| 类名的命名规范 | 遵守大驼峰命名法：所有单词首字母都大写，多个单词之间直接挨着写，不用分隔符 |
| `__init__` 的作用 | 初始化方法，在对象创建时自动调用（不是手动调用）；可以在其中为对象设置对应的属性，也可以完成其他初始化操作 |
| `self` 的作用 | `__init__` 的第一个参数，代表当前创建出来的对象实例；通过它就能获取当前实例对象，从而操作这个实例当中的属性 |

## 第 3 章：核心语法-面向对象基础-实例方法
> 对应分集：P79 | 原始标题：《79. 核心语法-面向对象基础-实例方法》

### 1. 函数与方法的区别

前一部分解决了如何定义一个类，以及在定义类的时候如何为类的实例对象添加对应的属性。接下来要研究的是实例方法，指的是在定义类的时候，如何为类的实例对象定义对应的方法。

方法的定义和之前所讲的函数的定义语法是一致的。区别只看位置：

> **结论**：用 `def` 定义时，定义在类的外部称之为函数，定义在类的里面就称之为方法；方法本质还是一个函数，只是编写位置不同。

### 2. 实例方法的定义语法

#### 2.1 第一个参数 self

定义类用到 `class` 关键字，后面跟上类名；在 `__init__` 这个初始化方法当中，可以为这个类的实例对象添加对应的属性。如果想为实例对象添加对应的方法，那么就与 `__init__` 对齐，在下面一个一个地定义方法就可以了，有多少个方法就一个一个地定义。

需要注意的是，在定义这些实例方法的时候，方法的形参列表当中第一个参数需要定义 `self`。通过 `self` 这个参数，就能够拿到当前实例对象。

```python
class Car:
    def __init__(self, c_color, c_brand, c_name, c_price):
        self.color = c_color
        self.brand = c_brand
        self.name = c_name
        self.price = c_price

    def running(self):
        ...

    def total_cost(self, discount, rate):
        ...
```

#### 2.2 无返回值的方法：running

`running` 是行驶的方法，用来输出一句话，参数只有一个 `self`，它代表的就是当前实例对象。方法体里通过 `self.brand` 以及 `self.name`，就能拿到当前实例对象当中的 `brand`（汽车的品牌）和 `name`（汽车的名字），然后输出这句话：

```python
def running(self):
    print(f"{self.brand} {self.name} 正在高速行驶中")
```

这个实例方法没有返回值，所以不用写 `return`。

#### 2.3 带参数与返回值的方法：total_cost

`total_cost` 这个方法用来计算汽车的总售价。总售价的计算方式是价格的折扣再加上税费，因为买汽车是有对应的购置税的。定义这个方法时接收三个参数：第一个是 `self`，就是当前实例对象；后面两个分别是 `discount` 和 `rate`，`discount` 是买车时打的折扣，`rate` 就是税率。

```python
def total_cost(self, discount, rate):
    """计算提车总费用

    总费用包含两个部分：车的价格与税费
    discount 是购车价的折扣，rate 是税率
    返回值是提车总费用
    """
    total_cost = self.price * discount + rate * self.price
    return total_cost
```

车价就是 `self.price`——因为在构造这个汽车对象的时候会把价格传递进来，最终封装到 `price` 这个属性当中，所以车价用 `self.price` 取得；它乘以折扣 `discount`，再加上车价的税费，也就是 `rate` 乘以车价。计算出来的结果用变量接收，最后直接 `return` 返回。

这两个参数如果需要做说明，可以像定义函数时一样为它添加文档注释：用三引号回车，编辑环境会自动补出文档注释的结构，然后在里面写清这个方法的作用、参数的含义以及返回值是什么。之前定义函数时的文档怎么写，这里就怎么写。有返回值就正常 `return`，没有返回值就不需要 `return`。

### 3. 实例化与方法调用

类定义好之后，在下面构建实例对象：直接通过类名，后面跟上小括号，并传入参数列表，就可以构建出这个对象。

```python
c1 = Car("红色", "BMW", "X7", 800000)
```

创建对象时传递的四个参数分别是：颜色为红色、品牌为 BMW、名字为 X7、价格为 80 万，这些参数最终会传递给 `__init__` 的四个形参，从而赋值给对象的四个属性。

对象创建好之后，直接打点就可以调用它里面的方法。前面四个是对象当中的属性，后面这些就是它里面的方法：

```python
c1.running()
# 宝马 X7 正在高速行驶中

total = c1.total_cost(0.9, 0.1)
print(f"提车的总费用为 {total}")
# 提车的总费用为 800000.0
```

调用 `total_cost` 时，编辑环境会提示需要传递两个参数，于是传了折扣 0.9（九折）和税率 0.1。计算结果仍然是 80 万——折扣 0.9 加上税率 0.1 正好等于 1，所以结果没有问题。

> **提示**：定义实例方法的时候，第一个参数要写 `self`，它代表当前实例对象；而调用这个方法的时候，是不用传递 `self` 的。定义时写、调用时不写。

| 环节 | 写法 | 说明 |
| --- | --- | --- |
| 定义 | `def total_cost(self, discount, rate):` | 形参列表第一个必须是 `self` |
| 调用 | `c1.total_cost(0.9, 0.1)` | 只传 `self` 之后的参数，`self` 不用传 |

### 4. 方法参数的默认值

方法的定义与函数定义的语法一致，这一点同样适用于参数：如果定义这些方法时，方法当中的参数有默认值，或者有一些不定长的参数，定义的语法和之前所讲的内容也是一致的。

比如给 `total_cost` 里的 `rate` 设置一个默认值，税率就为 0.1：

```python
def total_cost(self, discount, rate=0.1):
    return self.price * discount + rate * self.price
```

这时可以连着调用两次，第二次调用 `total_cost` 时不传递费率，看结果能不能算出来：

```python
print(c1.total_cost(0.9, 0.1))   # 传了费率
print(c1.total_cost(0.9))        # 没传费率，使用默认值 0.1
```

两次结果是一样的，原因就是 `rate` 设置了默认值 0.1。由此可见，实例方法在参数默认值、不定长参数这些方面的写法，与函数完全相同。

> **结论**：实例方法的定义与函数定义语法一致，参数默认值、不定长参数的写法也一致；唯一的额外约定是形参列表的第一个参数 `self` 代表当前实例对象，且调用时不需要传递它。

## 第 4 章：核心语法-面向对象基础-魔法方法
> 对应分集：P80 | 原始标题：《80. 核心语法-面向对象基础-魔法方法》

### 1. 魔法方法的定义与调用方式

单听「魔法方法」这个名字就觉得很神秘，其实它的定义很朴素：指的是在 Python 当中提供的以双下划线开头和结尾的特殊方法，这样的方法就称之为魔法方法。它主要是用来定义类的一些特殊的行为。

> **定义**：魔法方法（magic method）是以双下划线开头、并以双下划线结尾的特殊方法，用于定义类的特殊行为。

其实在定义类的时候就已经讲过一个魔法方法，就是 `__init__`——它是不是以双下划线开头、以双下划线结尾的？所以它就是魔法方法。

对于这样的魔法方法，定义好了之后是不用自己去调用、让它执行的，Python 解释器会在合适的时间自动调用。回头看 `__init__` 这个方法：自己调用过吗？没有，是创建对象的时候由 Python 解释器自动调用的。其他的魔法方法也是一样，不用手动调用。

Python 当中的魔法方法比较多，主要关注下面这几个常见的：

| 魔法方法 | 名称来源 | 作用 |
| --- | --- | --- |
| `__init__` | initialize | 初始化方法，创建对象时自动调用，为实例对象设置属性 |
| `__str__` | string | 对象字符串表示的方法 |
| `__eq__` | equals 的简写 eq | 比较两个对象是否相等 |
| `__lt__` | less than | 小于 |
| `__le__` | less than or equals | 小于等于 |
| `__gt__` | greater than | 大于 |
| `__ge__` | greater than or equals | 大于等于 |

`__init__` 是初始化的方法，目前主要用来在创建对象的时候为实例对象添加对应的属性。下面四个 `lt`、`le`、`gt`、`ge` 是用来比较两个对象的大小的——对象与对象之间也是可以比较大小的，而要想比较大小，就需要定义这样的魔法方法。

### 2. 不定义魔法方法时的默认行为

先看一组没有任何魔法方法（除 `__init__` 之外）的代码：定义了 `Car` 这个汽车类，创建两个实例对象 `c1` 和 `c2`，两个对象里所有的属性都完全一样，然后分别输出这两个对象、比较它们是否相等、再比较它们谁大谁小。

```python
class Car:
    def __init__(self, c_color, c_brand, c_name, c_price):
        self.color = c_color
        self.brand = c_brand
        self.name = c_name
        self.price = c_price


c1 = Car("白色", "比亚迪", "汉", 180000)
c2 = Car("白色", "比亚迪", "汉", 180000)

print(c1)         # 输出 c1 对象
print(c2)         # 输出 c2 对象
print(c1 == c2)   # 对比两个对象是否相等
print(c1 > c2)    # 比较两个对象谁大谁小
```

#### 2.1 输出对象得到的是内存地址

直接输出对象本身，得到的默认就是对象的内存地址，其实就是一个十六进制的数，形式是这样的：

```text
<__main__.Car object at 0x...>
```

输出 `c1` 得到的是 c1 这个对象的内存地址，输出 `c2` 得到的是 c2 这个对象的内存地址，而每个对象的内存地址是不一样的。

#### 2.2 == 比较的是内存地址

下面比较 `c1` 与 `c2` 是否相等，输出结果是 `False`。这两个对象的属性不是完全一样吗？都是同一个颜色、同一个品牌、同一个名字、同一个价格，为什么这两个对象还不相等？

因为直接去对比两个对象是否相等时，它比较的不是里面一个一个的属性是否相等，比较的是两个对象的地址值——会基于这两个对象的内存地址进行对比。两个对象的内存地址不一样，最终结果就是 `False`。

#### 2.3 比较大小会直接报错

最后想比较两个对象之间的关系，到底是 `c1` 大还是 `c2` 大，默认情况下这么对比是会报错的：

```text
TypeError: '>' not supported between instances of 'Car' and 'Car'
```

它告诉我们大于号或者小于号这样的操作符不能用于这两个对象之间的对比——默认自定义的对象之间，是不可以进行大小比较的。

现在把需求说清楚：输出对象的时候，希望能清晰地看到这个对象当中每一个属性对应的属性值是什么样子的；对比两个对象的时候，不想比较地址值，就想挨个去比较这两个对象当中的属性，属性一样就认为这两个对象相等；还想比较两个对象的大小。这些都可以借助 Python 提供的魔法方法来解决。

### 3. __str__：对象的字符串表示

为 `Car` 这个类增加 `__str__` 魔法方法，它的作用就是把当前的对象转成一个字符串。一旦加了这个魔法方法，并且在里面把对象实例转成了字符串并用 `return` 返回，那么再输出这个对象的时候，它就会自动调用对象的 `__str__` 方法，把返回的字符串输出出来，而不是输出默认的那个地址值。

```python
def __str__(self):
    """将对象转成字符串"""
    return f"{self.color} {self.brand} {self.name} {self.price}"
```

这里用格式化的字符串，把对象当中的四个属性依次取出来，用空格分开，拼接成一个字符串返回：

```python
print(c1)
# 白色 比亚迪 汉 180000

print(c2)
# 白色 比亚迪 汉 180000
```

输出 `c2` 得到的结果同样是这几个属性，它会按照所指定的这种格式把对象转成字符串输出。输出的形式完全可以自己定义——比如不想用空格，想用横杠，那就去改 `__str__` 里的逻辑，自己控制就行。

> **提示**：`__str__` 必须返回字符串，否则输出对象时会报错；对象转成什么样子，取决于这段逻辑怎么写。

### 4. __eq__：按属性判断两个对象是否相等

`eq` 就是 `equals` 的简写，这个魔法方法是用来对比两个对象是否相等的。它里面接受两个参数：一个是 `self`，代表当前对象；另外一个是 `other`，指的就是另外一个对象——对比的是当前对象跟哪个对象。

需要返回的是一个布尔类型的结果：对比两个对象是否相等，要么 `True` 要么 `False`。

```python
def __eq__(self, other):
    """判断两个对象是否相等：所有属性都相同才算相等"""
    return (self.color == other.color
            and self.brand == other.brand
            and self.name == other.name
            and self.price == other.price)
```

这里的逻辑是挨个属性对比：判断当前对象的 `color` 属性与另外一个对象的 `color` 属性是否相等，如果这两个相等，并且品牌也相等，名称也相等，价格也相等，那就认为这两个对象就是相等的。多个条件之间使用逻辑运算符 `and` 连接起来就行。

```python
print(c1 == c2)
# True
```

使用 `==` 进行比较的时候，底层就会自动调用这个 `__eq__` 方法，按照其中的逻辑去对比两个对象，所有属性都相等，结果就是 `True`。把其中一个价格改成 180001 再运行：

```python
c2 = Car("白色", "比亚迪", "汉", 180001)
print(c1 == c2)
# False
```

具体怎么定义、具体怎么比较，完全由自己决定，可以根据业务需要想怎么定义就怎么定义。

> **提示**：`==` 触发的是 `__eq__`。一旦自己定义了 `__eq__`，两个对象是否相等就由此处的逻辑决定，而不再是默认的内存地址比较。

### 5. __lt__ 与对象之间的大小比较

想要对比两个对象到底哪个大、哪个小，就得先有一个对比的规则：根据对象的什么来比。这里根据车辆的价格来做一个对比。

小于对应的是 `less than`，所以这个方法就是 `__lt__`：

```python
def __lt__(self, other):
    """按价格比较两个对象的大小"""
    return self.price < other.price
```

因为小于这种比较运算符的结果要么是 `True` 要么是 `False`，所以 `return` 返回的结果也得是一个布尔值。这里取的属性就是 `price`，判断 `self.price` 是否小于 `other.price`，是就返回 `True`，否则返回 `False`。这样就指定了对比的是两个对象价格这个属性的值。

```python
print(c1 < c2)   # 两个价格都是 18 万
# False
```

运行之后不再报错，返回的是 `False`，因为两个价格是一样的，不涉及谁大谁小。把一个价格改成 180001，`c1 < c2` 就是 `True`。

那么把小于号换成大于号呢？再运行，结果就是 `False` 了。

> **提示**：`c1 > c2` 走的是左操作数的 `__gt__`；当左操作数没有实现 `__gt__` 时，Python 会退回到右操作数的 `__lt__`，并把两个操作数交换过来，等价于执行 `c2.__lt__(c1)`。所以在只定义了 `__lt__` 的类上，大于号也能算出来，但它算的是「右对象是否小于左对象」，与 `c1 < c2` 的结果并不互为简单求反；要让小于、小于等于、大于、大于等于四种比较都按自己的规则生效，就把 `__lt__`、`__le__`、`__gt__`、`__ge__` 这四个方法都定义上。

### 6. 魔法方法的特点

魔法方法有一个统一的外观和一个统一的调用方式：

```text
        +--------------------------------------+
        |  方法名：__xxx__                     |
        |  双下划线开头，双下划线结尾          |
        +------------------+-------------------+
                           |
                           | 不需要手动调用
                           v
        Python 解释器在合适的时间、在底层自动调用
```

所有魔法方法的方法名都是双下划线开头、双下划线结尾，而且这些魔法方法是不用手动调用的，Python 解释器会自动在底层调用它们。在做项目开发的时候，只需要根据项目的需求去定义这些魔法方法就可以了。

| 问题 | 不定义魔法方法时 | 定义魔法方法之后 |
| --- | --- | --- |
| 输出对象 | 输出对象的内存地址（十六进制） | `__str__` 返回的字符串 |
| 两个对象是否相等 | 比较两个对象的内存地址 | `__eq__` 当中定义的属性比较逻辑 |
| 两个对象比较大小 | 报错：操作符不支持 | `__lt__` 等定义比较规则（如按价格比较） |

`__init__` 在对象创建的时候自动调用，可以在其中为实例对象设置属性；`__str__` 将对象转为字符串，直接输出对象时就会调用它把对象转成字符串；`__eq__` 用来对比两个对象是否相等，按照其中的逻辑来判定；`__lt__`、`__le__`、`__gt__`、`__ge__` 分别对应小于、小于等于、大于、大于等于，用来自定义两个对象之间的大小关系。如果不定义这些比较用的魔法方法，两个对象之间是不能进行大小比较的，会报错。

> **结论**：魔法方法以双下划线开头、双下划线结尾，定义好之后不需要手工调用，由 Python 解释器在合适的时机自动调用；需要什么样的相等规则和大小规则，就在对应的魔法方法里写清楚。

## 第 5 章：核心语法-面向对象基础-实例属性与类属性
> 对应分集：P81 | 原始标题：《81. 核心语法-面向对象基础-实例属性与类属性》

实例方法与魔法方法都讲完了，属性还剩最后一块没碰。前面写 `__init__` 的时候，我们一直在用 `self.brand`、`self.name`、`self.price` 这种写法给对象赋属性值；但还有一类属性，它压根不住在 `__init__` 里，而是写在类里面、由所有对象共享——比如"每辆车都有四个轮子""不管什么车购置税都是十个点"。这两类属性分别叫什么、怎么写、又该怎么访问，就是这一节要收尾的内容。

属性分两种，一种叫实例属性，一种叫类属性。它们的区别不在写法长短，而在**归属**：一个属于具体的对象，一个属于类本身。

### 1 实例属性

> **定义**：实例属性（instance attribute）是属于每个具体实例对象的属性。这里的"实例"指的就是实例对象，所以对象的属性就叫实例属性。每个对象都是独立的，各对象特有的数据通常就定义为实例属性。

看我们自己定义过的那个 `Car` 汽车类。`__init__` 方法里声明了三个属性：

```python
class Car:
    def __init__(self, color, brand, name, price):
        self.brand = brand
        self.name = name
        self.price = price
```

`self` 是什么？`self` 就是当前的实例对象。`self.brand`、`self.name`、`self.price` 这三个属性挂在实例对象身上，所以它们都是实例属性。

这一点在创建两个对象之后看得最清楚。下面定义了 `c1` 和 `c2` 两个独立对象，每个对象都有自己的品牌、自己的名字、自己的价格：

```python
c1 = Car('黑色', '宝马', 'X5', 600000)
c2 = Car('白色', '奔驰', 'S400', 900000)
```

`c1` 的品牌是宝马，`c2` 的品牌是奔驰，互不干扰。这些属性跟对象绑定，这就是实例属性。

取值的方式是**对象名点属性名**：

```python
print(c1.brand)
```

这里的 `self.brand`，`self` 代表的就是对象的名字——换句话说，`self.brand` 和 `c1.brand` 是同一件事的两种写处：定义时用 `self`，使用时用对象名。

### 2 类属性

#### 2.1 定义与取值

再想一层：无论什么品牌的汽车，是不是都有四个轮子？无论什么颜色、什么品牌的汽车，购置税的税率是不是都是十个点？这部分数据所有实例都一样，属于共享数据，就该定义成类属性。

> **定义**：类属性（class attribute）是属于类本身的属性，是所有实例共享的数据。可以把所有实例对象共享的数据或配置定义为类属性。

类属性写在哪里？注意，**不要放在 `__init__` 里**。`__init__` 当中基于 `self` 这个实例对象操作的属性都叫实例属性，写进去就变味了。类属性单独定义在类当中：

```python
class Car:
    # 类属性：所有实例对象共享
    wheel = 4
    tax_rate = 0.1

    def __init__(self, color, brand, name, price):
        self.brand = brand
        self.name = name
        self.price = price
```

`wheel = 4` 是轮胎数量，`tax_rate = 0.1` 是购置税的税率。这两个写在类体里、缩进与 `__init__` 齐平的变量，就是类属性。它们由这个类创建出来的所有实例对象共享：不管你是什么样的汽车，轮胎数量都是 4，税率都是 0.1。

类属性的操作方式是**类名点属性名**：

```python
print(Car.wheel)
```

#### 2.2 实例名也可以访问类属性

由于类属性是所有实例共享的，通过实例对象点属性名同样能访问到它。上面那句 `print(Car.wheel)` 换成 `print(c1.wheel)` 一样能拿到 4，后面的运行演示会把这个结果打出来。

两类属性的操作方式正好是两套：

| 属性类型 | 定义位置 | 操作方式 | 归属 |
| --- | --- | --- | --- |
| 实例属性 | `__init__` 中基于 `self` 赋值 | 对象名.属性名 | 每个对象独立一份 |
| 类属性 | 类体中直接赋值（不在 `__init__` 内） | 类名.属性名（实例名也能访问） | 全部实例共享一份 |

### 3 属性查找顺序

既然 `c1.wheel` 这种写法既能碰到实例属性又能碰到类属性，那就必须回答一个问题：通过实例查找属性时，到底先找谁？

> **结论**：通过实例对象查找属性时，先查找实例属性；实例属性不存在，再查找类属性。

顺序清楚了，接着看一个故意制造冲突的场景。在类当中，`wheel` 已经作为类属性存在，值为 4；如果又在某个方法里加上一句 `self.wheel = 2`，那么基于 `self` 定义出来的这个 `wheel` 是实例属性。此时实例属性里有一个 `wheel`，类属性里也有一个 `wheel`，输出的 `c1.wheel` 到底听谁的？

按上面的顺序，先找实例属性。`c1` 这个实例对象里有名为 `wheel` 的实例属性吗？有，所以输出的是 2。而如果把那句实例属性的赋值删掉，实例属性里就没有 `wheel` 了，于是回头去找类属性，输出 4。

```text
c1.wheel 查找路径
  |
  +-- 实例属性中存在 wheel ？ --是--> 用实例属性的值（2）
  |
  +-- 否
        |
        +-- 类属性中存在 wheel ？ --是--> 用类属性的值（4）
```

读图看分叉点：判断只发生在实例属性这一层，实例属性有值就到此为止，不会再去看类属性；只有实例属性这一层空了，查找才继续往下走到类属性。

> **易错点**：类属性和实例属性同名时，实例属性优先。写 `Car.wheel` 拿到的仍然是类属性的 4，写 `c1.wheel` 拿到的才可能是实例属性覆盖后的值——同一个名字，两条访问路径，结果可以不同。

### 4 运行演示

在 PyCharm 里把前面写好的那段代码准备好：定义了 `Car` 类，里面有初始化方法，还有两个实例方法 `running` 和 `total_cost`，下面创建了 `c1`、`c2` 两个对象。

创建对象时会自动调用 `__init__`，传入的四个参数分别作为颜色、品牌、名称和价格，再通过 `self.属性名` 的方式为属性赋值——这一套定义出来的属性就是实例属性，属于每个实例对象特有的数据。

接着在类的上方补上两个类属性。先定义轮胎：

```python
wheel = 4
```

回车之后再加税率：

```python
tax_rate = 0.1
```

给它们补上注释"是所有实例对象共享的"，两个类属性就有了。

下面验证访问。先以 `c1` 为例，访问它的品牌：

```python
print(c1.brand)
```

右键运行，输出的品牌就是 `brand` 对应的值。除了 `brand`、`color`、`price`、`name` 这四样，`c1` 身上是不是还"多出"两个属性——`wheel` 和 `tax_rate`？它们其实都是类属性。把输出换成：

```python
print(c1.wheel)
```

运行，结果是 4。我们从来没有为 `c1` 定义过 `wheel` 这个实例属性，却也输出了值，原因就在于类中的属性是所有实例共享的，实例对象照样能访问到。

再换成类名访问：

```python
print(Car.wheel)
```

结果同样输出 4。类当中有两个类属性 `wheel` 和 `tax_rate`，通过 `Car.` 这一个点就能把它们都取出来。

### 5 什么时候用哪一类属性

两类属性的应用场景，在分析需求的时候其实就已经被需求本身决定了：

- 属性是各个对象特有的数据，就定义为实例属性。汽车的品牌、颜色、价格，每一辆车都不一样，都是各自独立特有的数据；
- 属性是所有实例对象共享的数据、所有实例在这个位置上的值都一样，就定义为类属性。

> **结论**：判断标准只有一条——这份数据是"每个对象各有一份"还是"所有对象共用一份"。前者进 `__init__`，用 `self.属性名` 赋值；后者写在类体里，用类名访问。
