## 核心语法-流程控制语句-while循环-语法
> 对应分集：P28 | 原始标题：《28. 核心语法-流程控制语句-while循环-语法》

条件判断和结构模式匹配都讲完了，流程控制语句里只剩下最后一种：**循环**。

循环这件事在日常生活里到处都是。打开一个播放器，里面一般都会提供单曲循环和列表循环：单曲循环是这一首歌曲重复地播放，列表循环是列表里的歌曲重复地播放。再比如首页的轮播图，那一组大概九张图片会依次播放，一轮播完再播第二轮、第三轮，永远重复播放这一组图片。

把这些场景抽象出来，循环的含义就一句话：**重复地执行某件事情**。

在 Python 里要循环地执行一段代码，有两条路可走——基于 `while` 语句实现，或者基于 `for` 语句实现。所以循环这部分会按顺序讲两块：先是 `while` 循环，再是 `for` 循环；两者讲完之后，再看循环相关的高级语法——**循环嵌套**，最后用一组案例收尾。

这一节从第一部分开始：`while` 循环。

### while 循环的语法结构

先看语法格式：

```python
while 条件表达式:
    循环体语句
```

结构里有两个位置需要看清楚：

- `while` 是关键字，关键字之后空格，再跟上**条件表达式**。这个条件表达式的结果是一个布尔值，要么 `True`，要么 `False`；
- 结果是 `True`，就代表条件成立，此时才会去执行 `while` 里面的那部分代码。这部分代码有个专门的名字，叫**循环体**；
- 循环体前面有一定的**缩进**，通过缩进来表示层级关系。前面缩进了，就表示这几行语句属于 `while` 循环，是循环体内部的语句。

### 条件表达式控制的执行流程

结构很简单，真正的关键在「它怎么循环」。Python 解释器执行这段代码时，走的是这样一个流程：

```text
程序开始
   │
   ▼
判断条件表达式的值
   │
   ├── True ──> 执行循环体语句 ──┐
   │                             │
   │      （执行完回到判断）◄────┘
   │
   └── False ──> 循环正常结束 ──> 执行 else 语句（可选）──> 结束
```

读图要点有三处：

1. 先判断 `while` 后面条件表达式的值，看它是 `True` 还是 `False`；
2. 为 `True` 就执行循环体里的语句。但**循环体的语句执行完并不代表结束**——循环是重复地做事情，所以执行完之后会**回头再判断一次条件表达式**。依然为 `True`，就执行第二遍循环体；第二遍结束再判断，为 `True` 就执行第三遍，如此往复；
3. 某一次循环体执行完，一判断条件表达式，结果是 `False`，代表条件不成立，此时就退出循环，整个循环结构执行完毕。

> **结论**：`while` 是靠**条件表达式**来控制「是否进行下一次循环」的。值为 `True` 就进行下一次循环，值为 `False` 就结束循环。

由此也能推出一个必然的后果：如果条件表达式的值**一直**是 `True`，循环就会一直转下去。这种情况叫**无限循环**，也叫**死循环**。

### while...else 的正常结束分支

`while` 还有第二种结构：在 `while` 后面再跟一个 `else`。

```python
while 条件表达式:
    循环体语句
else:
    循环正常结束时执行的语句
```

`else` 之后的逻辑，是在条件表达式的值为 `False`、**循环正常结束**的时候执行的。它同样是可有可无的，写不写取决于需求。

> **注意**：`else` 认的是「正常结束」这个前提。循环如果是因为被强制打断而提前终止的（也就是异常结束），`else` 里的逻辑不会执行——这类控制循环的手段留到后面讲循环控制时再说。

### 案例：打印 10 遍「人生苦短，我用 Python」

语法清楚了，用一个小案例落地：**打印 10 遍「人生苦短，我用 Python」**。

需求看着朴素，本质就是把一句输出语句重复执行 10 次。用 `while` 实现时，重点要盯两件事：**条件表达式怎么写**，以及**怎样控制条件表达式的结果**。

```python
i = 0
while i < 10:
    print('人生苦短，我用Python')
    i += 1
else:
    print('循环正常结束')
```

先给变量 `i` 一个初值 0。这个 `i` 就是控制循环次数的计数器，条件表达式写的是 `i < 10`，也就是「循环的条件」。

循环体里做了两件事：输出那句话，然后让 `i` 的值加 1。`i += 1` 是赋值运算符的写法，等价于 `i = i + 1`。这一步是全篇最要紧的一步，理由往下推演就明白了：

| 第几次进入循环 | 判断时的 i | 判断结果 | 执行后 i |
| --- | --- | --- | --- |
| 第 1 次 | 0 | 0 < 10 成立 | 1 |
| 第 2 次 | 1 | 1 < 10 成立 | 2 |
| 第 3 次 | 2 | 2 < 10 成立 | 3 |
| …… | …… | …… | …… |
| 第 10 次 | 9 | 9 < 10 成立 | 10 |
| 第 11 次判断 | 10 | 10 < 10 不成立 | 不进入循环 |

`i` 从 0 开始，循环执行一次加 1，所以循环 10 次之后 `i` 的值变成 10。这时候再判断 `10 < 10`，不成立，条件表达式的执行结果就是 `False`。条件一旦不成立，循环就正常结束了——因为后面跟着 `else`，程序接着去执行 `else` 里的逻辑，输出「循环正常结束」。

### 死循环的成因与中断

把 `i += 1` 这行拿掉，代码在语法上依然成立，但运行结果完全不同：`i` 的值一直是 0，`i < 10` 就永远成立，条件永远是 `True`，于是程序一直输出那句话，停不下来。

运行状态栏上会有一个绿点，表示程序没有执行完；输出则一行一行刷下去。这就是**死循环**（无限循环）。

> **易错点**：死循环是比较耗费性能的——它会一直占着处理器空转。所以写循环的时候，一定要同时盯住两件事：循环条件写得对不对，以及循环条件的结果有没有被正确控制。

真跑出了死循环也不用慌，点停止按钮把程序打断就行。但正确的做法是在写代码时就避免它：循环体内必须有能让条件表达式最终变为 `False` 的语句。

### 断点跟踪：i 从 0 走到 10

这个案例只有几行，但循环的执行过程是反复绕圈的，光看结果不容易建立直觉，所以用断点跟一遍。

打断点，然后以调试模式运行，一步一步往下走：

1. 第一次停下来时 `i` 的值是 0，满足 `i < 10`，进入循环，控制台输出第一句；
2. 继续往下走，`i` 变成 1，仍然满足条件，输出第二句；
3. `i` 变成 2，输出第三句……`i` 的值就这样一直往上涨，每涨一次就多输出一句；
4. 输出到第十次之后，`i` 的值变成 10。再判断 `10 < 10`，不小于，条件不成立，循环结束；
5. 循环是正常结束的，所以接着进入 `else`，执行 `else` 里的代码。

跟完这一遍就能直观地看到：循环不是「一次执行完就完事」，而是**判断—执行—回头再判断**这样一圈一圈转出来的，转不动了才由 `else` 收尾。

### 关键要点

`while` 循环的语法格式涉及两个关键字：`while` 和 `else`，其中 `else` 那部分是**可选**的。真正要重点掌握的是 `while` 和它后面的**条件表达式**——条件表达式决定的是「是否进行这一次循环」：

- 结果为 `True`，执行循环体里的语句；循环体执行完毕再回去判断条件表达式；
- 结果为 `True` 继续循环，结果为 `False` 则结束循环；
- 循环**正常结束**时，才会去执行 `else` 里的逻辑。

三条注意事项：

1. 条件表达式的结果必须是一个**布尔值**，通过布尔运算的结果来决定是继续循环还是结束循环；
2. 循环体里的语句前面都要有**缩进**，靠缩进来表示层级关系；
3. 写循环语句时要**规划好循环条件**，否则就有可能进入无限循环（死循环）；死循环会比较耗费系统的性能。

## 核心语法-流程控制语句-while循环-案例
> 对应分集：P29 | 原始标题：《29. 核心语法-流程控制语句-while循环-案例》

`while` 的基本语法结构我们已经学完了。但语法会写，不等于会用——所以接下来用一个小案例，把 `while` 的用法真正落到手上。

需求很短：**计算 1 到 100 之间所有偶数的累加之和**。

先说「累加」是什么意思。就是把 1 到 100 之间的偶数全部加到一块，求它们的总和，这件事就叫累加。

需求虽然一句话，真动手之前得先想清楚两个问题。

### 动手前的两个问题

第一个问题：怎么获取到 1 到 100 之间的所有偶数？换句话说，怎么判断一个数是不是偶数？

第二个问题：累加这一步，要用到什么运算符？

先把第一个问题解决掉。判断一个数是不是偶数，可以用一种运算符——**求模运算符**（`%`）。一个数模于 2 等于 0，那它就是偶数；否则它就是奇数。

> **定义**：求模运算符 `%` 用来求两个数相除之后的余数。`i % 2 == 0` 说明 `i` 能被 2 整除，是偶数；余数不为 0，说明是奇数。

第二个问题：累加需要在**前一个数的基础上再加一个数**，所以要用到 `+=`。这个符号就是做累加计算时该用的东西。

> **提示**：`+=` 是赋值运算符里的复合用法，`total += i` 等价于 `total = total + i`。累加场景里它是最顺手的一个，一次就写清「拿原来的值再加上新值，再存回原变量」。

两个问题都有答案了，剩下的就是把它写成代码。

### 案例的完整实现

先把变量准备好。要计算累加之和，并且最终要把它输出出来，所以先定义一个变量 `total` 等于 0，让它来记录这个累加之和。

接着要解决「从 1 开始一直循环到 100」这件事。前面那个 `while` 循环是从 0 开始、条件是 `i < 10`；这里要从 1 开始，范围是 1 到 100 之间的所有数。所以再定义一个变量 `i`，初始值设为 1，它就是循环开始的这个数字。

然后是循环条件。要计算的是 1 到 100 之间所有偶数的累加之和，**既包含 1，也包含 100**，所以这里要用 `<=`，也就是 `i <= 100`。

循环体里要做两件事：判断这个数是不是偶数，是偶数就累加。循环体里的判断用前面讲过的 `if` 条件判断就能完成。

```python
# 计算1到100之间所有偶数的累加之和

# 记录累加之和
total = 0

# 循环开始的数字
i = 1

while i <= 100:
    # 判断是否为偶数
    if i % 2 == 0:
        # 累加
        total += i
    i += 1

# 输出累加之和
print(f"1到100之间所有偶数的累加之和是：{total}")
```

逐段看这段代码。

`total = 0` 是累加器的起点。累加必须从 0 开始，这样第一次 `total += i` 的结果才正好是第一个偶数本身。

`while i <= 100:` 决定循环跑多久。这里为什么是 `<=` 而不是 `<`？因为我们要的范围包含 100。写成 `i < 100` 就把 100 漏在外面了。

循环体里先判断再累加，顺序不能反。`i % 2 == 0` 成立就执行 `total += i`，不成立就什么也不做，直接去处理下一个数字。

再看 `i += 1` 的位置。每一次循环出来的数其实就是 `i`：第一次是 1，第二次变成 2，第三次变成 3……所以 `i` 就是我们遍历出来的每一个数。而 `i += 1` 必须在**判断和累加之后**执行——它是把计数器往上推一格，推完进入下一轮。

最后那句 `print` 是**顶格对齐**的，它前面没有缩进，所以它并不属于 `while` 的循环体。`while` 循环执行完了之后，才会执行这个 `print` 语句，把最终结果打印出来。别忘了在字符串前面加上 `f` 做格式化。

> **易错点**：`print` 写在哪里，决定了它输出几次。如果它被缩进到循环体里，就会在每一轮循环里都打印一次；只有顶格写在 `while` 外面，它才在循环结束后只打印一次最终结果。

### 用 Debug 跟踪执行过程

代码写完了，打个断点看一下程序的执行过程，一轮一轮往下走。

第一轮，`i` 的值是 1——1 是奇数，判断不成立，不做累加。

第二轮，`i` 变成 2。2 是偶数，执行累加，`total` 的值就变成了 2。紧接着 `i` 自增到 3。数字就这样一个一个往上走，判断、累加、判断、累加。

再往后看：累计的结果已经是 12，此时 `i` 到了 7。下一次该累加的是 8——8 是偶数，累加之后 `total` 变成 20。

把这条线索整理成一张表，`i` 与 `total` 的对应关系一目了然：

| 轮次 | `i` | `i % 2 == 0` | `total` |
| --- | --- | --- | --- |
| 1 | 1 | False | 0 |
| 2 | 2 | True | 2 |
| 3 | 3 | False | 2 |
| 4 | 4 | True | 6 |
| 5 | 5 | False | 6 |
| 6 | 6 | True | 12 |
| 7 | 7 | False | 12 |
| 8 | 8 | True | 20 |

一直走到 `i` 变成 101，条件 `i <= 100` 不再成立，循环退出，最终输出累加之和。

不想再一步一步跟踪的时候，把断点在那一行再点一下就可以取消，然后按 `F9` 让程序恢复运行、直接跑到结束。

最终结果是：1 到 100 之间所有偶数的累加之和是 **2550**。

### 把整个流程画出来

```text
total = 0
i = 1
   |
   v
i <= 100 ? --False--> 退出循环 --> print(total)
   |
 True
   |
   v
i % 2 == 0 ? --False--> i += 1 --+
   |                             |
 True                            |
   |                             |
   v                             |
total += i --> i += 1 -----------+
```

读图说明：判断条件不成立时，`i` 自增后回到条件判断那一步，形成循环；只有条件变成 `False` 的那一次，才跳出循环去执行顶格的 `print`。

### 案例要点

这个需求里，`while` 循环体的语句中就用到了前面讲过的 `if` 条件判断。所以这个案例真正的价值，是把已经学过的两件事拼在了一起：`while` 负责「反复做」，`if` 负责「这次要不要做」，`+=` 负责「把要做的结果攒起来」。

> **结论**：写循环类案例，先想清楚三件事——循环从哪开始、循环到哪结束、每一轮循环体里做什么。这个案例里分别对应 `i = 1`、`i <= 100`、以及「判断偶数并累加，最后让 `i` 自增」。

## 核心语法-流程控制语句-for循环-语法
> 对应分集：P30 | 原始标题：《30. 核心语法-流程控制语句-for循环-语法》

`while` 循环的基本语法学完了，接下来看循环当中的第二类——`for` 循环。

`while` 和 `for` 都是用来定义循环结构的。既然都能定义循环，它们之间到底有什么差异？这是这一节首先要回答的问题。

### while 循环的控制方式

`while` 循环是**通过条件表达式来控制是否要进入下一次循环**的。这个条件表达式运算的结果就是一个布尔值：结果为 `True`，就代表条件成立，成立就进行下一次循环，继续执行循环体当中的语句；结果为 `False`，就代表该退出循环了，循环结束。

顺着这个机制往下推一步，就会看出 `while` 的一个特点：如果条件表达式运算的结果**一直都是 `True`**，那它就相当于进入了无限循环，会一直循环下去，永远不退出。

再看 `for` 循环。

### for 循环是一种轮询遍历机制

`for` 循环本质上属于一种**轮询遍历机制**——它会对一批内容进行逐个处理，这批内容处理完了，`for` 循环也就结束了。

所以 `for` 循环具体要循环多少次，取决于这批数据里面到底有多少个数据。数据多就多循环几次，数据少就少循环几次，数据没了循环就停。

拿一个例子来说。假设这里有一个容器，就是一个箱子，箱子里面装的是一箱乒乓球。现在的需求是：把箱子里面的乒乓球逐个编号。

那就从箱子当中拿出一个乒乓球，进行编号处理，编完号之后把它放到外面来。再从里面取一个、编号、放到外面来……一个取一个，这不就是在对这批内容做逐个处理吗？直到把箱子里面的乒乓球全部取完，这个任务也就结束了，循环也就结束了。

> **定义**：`for` 循环（for statement）是一种轮询遍历机制，它对一个数据集中的元素逐个处理，数据集遍历完毕则循环自动结束。

### for 循环的执行流程

`for` 循环开始之后，第一步是**判断容器当中是否还有要处理的元素**。如果有，就取出一个元素——注意每一次只取其中的一个元素——取出之后对这个元素进行处理。而取出这一个元素之后，容器里面就少了一个元素。

处理完这一个元素，紧接着再到容器当中去获取第二个元素、下一个要处理的元素。当然在获取之前，它会先判断容器里面还有没有元素：有，就再取出一个、再处理；处理完再回到容器里看还有没有。

如果容器里面的元素都已经取完了，没有元素了，那这个时候循环也就结束了。

```text
         +---------------------------+
         |                           |
         v                           |
判断容器中是否还有元素? --有--> 取出一个元素 --> 处理该元素 --+
         |                                                   |
        无                                                   |
         |                                                   |
         v                                                   |
     循环结束 <------------------------------------------------+
```

读图说明：判断与取出构成一个闭环，每处理完一个元素就回到容器再问一次「还有吗」，只要容器里还有元素就继续，直到问出「没有」才退出循环。

### for 循环的语法结构

基本结构里 `for` 和 `in` 是固定的两个字，写成 `for ... in ...`。

```python
for 元素 in 待处理的数据集:
    循环体语句
else:
    循环正常结束时执行的语句
```

先看 `in` 后面的**待处理的数据集**。刚才说了，`for` 循环本质是一种轮询遍历机制，会对一批内容逐个处理；这里的「集」指的就是集合，就是一个大的容器，而容器里面装的就是一项一项待处理的数据。这一部分代表的就是 `for` 循环需要轮询遍历的是哪一个数据集。

`for` 循环在遍历的时候，**一次只会从这个数据集当中取出一项数据**。`in` 前面那一位，就是所取出来的数据——它其实是一个变量名，这个变量代表的就是每次从数据集当中取出来的那个元素。

拿到这个元素之后，接下来就可以在循环体里对这个元素做进一步处理。冒号下面那一段代码就是循环体。第一个元素处理完毕之后，它会再到数据集当中取第二个元素、处理第二个元素；第二个处理完再处理第三个，第三个处理完再处理第四个，直到数据集当中所有的元素都处理完，循环结束。

结尾还可以加一个可选的 `else` 结构。这个 `else` 可有可无，它会在循环**正常结束时**执行里面的逻辑。

> **提示**：这里的 `else` 挂在 `for` 上，不是「否则」的意思。它的触发条件是「循环正常跑完」，而不是「条件不成立」。

### 遍历一个字符串

看一个小案例：遍历 `Hello Python` 这个字符串。

为什么要拿字符串来遍历？因为字符串其实也是一种数据集，或者说数据容器。这个字符串里面存储的就是一个一个的字符：`H`、`e`、`l`、`l`、`o`、`-`……每一个都是一个字符。所以字符串本质上也是一种数据集，里面存储的就是一个一个的字符。

那么基于 `for` 循环如何遍历字符串当中的一个一个字符？其实每一个字符也都是一个子字符串。

```python
for i in msg:
    print(i)
```

字符串 `msg` 是由一个一个字符组成的。遍历的时候，它会把这个字符串当中的字符一个一个遍历出来，前面的 `i` 就是一个变量，代表遍历出来的元素。第一个拿出来的是 `H`，把 `H` 输出出来——注意 `print` 默认输出是会换行的；然后第二个 `e`，第三个 `l`，第四个 `l`，第五个 `o`，到这里遍历是不是五次了？接着一个字符一个字符地输出，直到最后一个字符遍历输出完毕。

对 `msg` 来说遍历完了没有？完了，因为里面的字符我们已经一个一个全部获取出来了。这时候再执行下去，`msg` 当中已经没有需要遍历的元素，整个循环就结束了。循环正常结束，就会执行 `else` 结构当中的逻辑——当然 `else` 里的逻辑是可选的。

### 完整代码：遍历键盘录入的字符串

看一段完整可运行的代码。这个需求是遍历**手动输入**的字符串：输入什么字符串，就遍历什么字符串。

```python
# 接收键盘录入的字符串
msg = input("请输入需要遍历的字符串：")

for s in msg:   # s 表示遍历出来的元素，msg 表示需要遍历的数据
    print(f"遍历出来的元素是：{s}")
else:
    print("遍历结束")
```

写法上要注意几个点。首先定一个变量来接收所输入的字符串，提示信息写「请输入需要遍历的字符串」。然后是 `for` 循环结构：关键字 `for`，`for` 之后跟一个空格，空格之后跟上遍历出来的元素的名字——这个名字随便写都可以，就是一个变量名；接着加关键字 `in`，`in` 之后跟上要遍历的那个数据集，这里就是 `msg`；最后跟上冒号。回车之后进入循环体，`s` 代表的就是遍历出来的元素。

不加 `else` 也可以；如果要加，它代表的就是遍历结束后执行的操作。

不妨输入一句「人生苦短，我用 Python」，后面再补一个波浪线，然后回车，用调试模式一步一步看。

`msg` 的值有了之后就可以开始遍历。控制台一步一步走下来：

- 第一个元素是 `人`——「人生苦短」的第一个字就是「人」；
- 接着 `生`；
- 第三个 `苦`；
- 第四个 `短`；
- 再往下走是逗号 `，`；
- 然后是 `我`、空格、`P`、`y`、`t`、`h`、`o`、`n`；
- 最后一个字符是那个波浪线 `~`。

波浪线输出出来之后，数据容器当中已经没有需要遍历的元素了，遍历完了，所以退出循环，执行 `else` 当中的逻辑，最终输出「遍历结束」。

> **提示**：字符串里的空格、逗号、波浪线都是字符，都会被 `for` 一个不落地遍历出来。字符的个数就是循环的次数，一个都不能跳。

这就是 `for` 循环的语法：它把指定的数据集合当中的元素遍历完了，就会自动退出循环。

### for 与 while 的应用场景对比

回到开头那个问题：是不是有了 `for` 循环，`while` 循环就不用了？并不是，它们各自有各自的应用场景。

`while` 循环是通过条件来控制循环的。在满足某个条件的情况下，它其实可以做到一直循环，**循环的次数是未知的**——它只知道循环和结束的条件是什么。我们关注的是那个条件：达到条件就循环，条件不成立就退出。

`for` 循环主要是针对一个**已知的数据集**进行遍历，或者说是循环次数已经明确知道的循环。它的关键点是遍历数据集当中的每一个元素。

| 对比项 | `while` 循环 | `for` 循环 |
| --- | --- | --- |
| 控制依据 | 条件表达式 | 数据集中的元素 |
| 循环次数 | 未知，只知道开始与结束的条件 | 已知，取决于数据集里的元素个数 |
| 退出方式 | 条件表达式结果为 `False` | 数据集元素被取完 |
| 典型场景 | 满足条件就一直循环 | 遍历数据集、已知次数的循环 |

> **结论**：要去遍历一个数据集，或者循环次数已经明确，就用 `for`；只知道循环开始和结束的条件、次数事先说不准，就用 `while`。

最后补一句实际开发中的判断：`else` 这个结构在项目开发当中用得比较少，知道它在那儿就行，不必刻意去用。

## 核心语法-流程控制语句-for循环-案例(range)
> 对应分集：P31 | 原始标题：《31. 核心语法-流程控制语句-for循环-案例(range)》

`for` 循环的基本语法清楚了，接下来一起完成两个案例。需求看着都比较简单、比较短，但真正卡人的地方不在循环写不出来，而在另一个地方。

### 两个案例的需求与真正的难点

第一个需求：计算 1 到 100 之间所有奇数之和。

第二个需求：计算 100 到 500 之间所有 3 的倍数的数字之和。

既然要求基于 `for` 循环实现，就得回到它的结构上想。`for` 循环的本质是循环遍历，结构是 `for 元素 in ...`，而 `in` 之后跟着一个**待处理的数据集**。

那么要计算 1 到 100 之间所有奇数之和，首先是不是得拿到 1 到 100 之间的这 100 个数？这个待处理的数据集就应该是 1 到 100 之间的这 100 个数。

问题来了：要把 100 个数全部罗列在这儿吗？如果今天要计算的是 1 到 1000 之间所有奇数之和，这里就写 1000 个数？那显然是不合理的。

所以，要完成这两个需求，首先得搞定一件事——**怎么获取到 1 到 100 之间的数据集、怎么获取到 100 到 500 之间的数据集**。拿到数据集之后，遍历它、判断是不是奇数、是就累加，就顺理成章了。关键点全在「获取指定范围的数据集」这一块。

解决它要借助 Python 当中的一个新语句：`range` 语句。

### range 语句的三种用法

`range` 语句的作用，是**根据指定的规则来生成数字序列**。所谓数字序列，就是生成一组符合规则的数据，也就是一个数据集。常见用法有三种。

第一种：括号里面直接写一个 `end`，代表一个范围。它会生成一个从 0 开始、到 `end` 结束的数字序列——**注意不包含 `end` 本身**。

```python
range(5)        # 0, 1, 2, 3, 4
range(6)        # 0, 1, 2, 3, 4, 5
```

`range(5)` 得到的数据集就是 0、1、2、3、4，不包含 5。那如果想获取 0 到 5 之间的数据序列呢？括号里面就得写 6——因为它不包含 6，所以拿到的刚好是 0 到 5。

第二种：括号里面写两个数，两个数之间用逗号分隔。第一个数是 `start`，从哪开始；第二个数是 `end`，到哪结束。**同样不包含 `end`**。

```python
range(2, 8)     # 2, 3, 4, 5, 6, 7
```

`range(2, 8)` 获取到的就是 2、3、4、5、6、7，不包含 8。第二种用法就是指定了一个具体的范围：有开始、有结束，也是不包含结束。

第三种：括号里面指定三个数字，分别是 `start`、`end`，多出来的第三个是 `step`。`start` 和 `end` 与第二种用法一致，逗号之后的 `step` 代表**步长**。所谓步长，就是在生成的时候每次间隔几个数。

```python
range(0, 10, 2)     # 0, 2, 4, 6, 8
```

`range(0, 10, 2)` 表示从 0 开始、到 10 结束，每次间隔两个数。默认间隔的是**一个**数；这里写 2，生成的数据就是 0、2、4、6、8，同样不包含结束值 10。

> **结论**：`range` 就像是一个数字生成器，可以根据指定的规则帮我们生成数字序列。三种写法的差别只有两点——从哪开始、每次加几；而「不包含结束值」这条规则，三种写法统统适用。

### 案例一：1 到 100 之间所有奇数之和

现在获取 1 到 100 之间的这 100 个数，就不需要一个个罗列了，直接用 `range` 就行。

用 `range` 的三种用法其实都可以，第一种、第二种都能达成目的。比如想生成 1 到 100 之间的这 100 个数并且包含 100：`range` 括号里面不能写 100，写 100 是不包含 100 的，得写 101。使用第一种写法的话，它默认从 0 开始、是包含 0 的，但这个 0 对于计算累加之和没有影响，所以这种写法也可以用。如果不想生成这个 0，就用第二种写法直接指定从哪开始：从 1 开始，到 101 结束，那最终不会包含 101，自然也就会包含 100。

代码按「先验证数据、再补逻辑」的顺序来写。先定义一个变量记录累加之和，就叫 `total`，先等于 0。然后基于 `for` 循环遍历，遍历出来的元素写成 `i`。

```python
# 计算1到100之间所有奇数的累加之和

# 记录累加之和
total = 0

for i in range(1, 101):
    print(i)        # 先确认能不能拿到1到100这100个数
```

`range(1, 101)` 里，第一个数是从哪开始、第二个数是从哪到哪。从 1 开始到 100——但 `range` 是不包含 100 的，想包含 100 这一块就得写 101。这是整段代码最关键的一步：拿到 1 到 100 之间的这 100 个数。

先运行一下，把 `i` 输出出来看效果：从 1 到 100 之间的这 100 个数拿到了没有？拿到了。第一步搞定，接下来完成累加。

奇数怎么判断？什么情况下 `i` 才是一个奇数？**模于 2 等于 1，那就是奇数**。所以在循环体里加上条件判断：如果 `i % 2 == 1`，说明这个数字是奇数；是奇数就把它累加起来；如果不是奇数就不执行任何操作，直接去遍历下一个元素。

```python
# 计算1到100之间所有奇数的累加之和

# 记录累加之和
total = 0

for i in range(1, 101):
    # 判断是否为奇数
    if i % 2 == 1:
        # 累加
        total += i

print(f"1到100之间所有奇数的累加之和是：{total}")
```

末了把结果输出出来。这里用 `f` 格式化一下，或者直接用逗号把内容和 `total` 拼接到一起输出，都可以。运行结果是 **2500**，这个结果没有问题。

针对于这个需求，还有没有简化的空间？有，**从 `range` 这一块简化**。

原来的写法里有一个 `if` 条件判断，它的作用是筛掉偶数、只留下奇数。那反过来想：能不能生成一个数字序列，生成出来的序列里面**就只有奇数**？如果数据集本身全是奇数，那 `if` 就完全不需要了，直接累加就行。

但如果把 `if` 拿掉、直接累加 `range(1, 101)` 里的每一个数，累加的就是 1 到 100 这 100 个数之和，结果是 5050，那必然不对。所以要用 `range` 的第三种写法：除了 `start` 和 `end`，再跟上第三个数字 `step`——步长，也就是生成数字序列时每次加几。

默认是加 1。既然只想要奇数，那就让它每次加 2。

```python
# 简化版：直接生成奇数序列

# 记录累加之和
total = 0

for i in range(1, 101, 2):
    # 生成的序列全是奇数，直接累加
    total += i

print(f"1到100之间所有奇数的累加之和是：{total}")
```

`range(1, 101, 2)` 生成的第一个数是 1，第二个就是 1 加上步长 2 等于 3，第三个是 3 加 2 等于 5，往后就是 1、3、5、7、9、11……这样一串奇数。

先只看效果、先不累加：运行之后输出的是 99、97、95、93……**全部是奇数**。这时候再累加，就完全不用做任何条件判断，直接累加即可，结果依然是 **2500**，和前面一样。这就是最简化的版本。

> **提示**：两版代码结果相同，但思路不同。`range(1, 101, 2)` 是「让数据集本身就符合条件」，原来的写法是「取出所有数再筛一遍」。能用步长解决的问题，就不必再写一层 `if`。

### 案例二：100 到 500 之间所有 3 的倍数的累加之和

第二个案例和第一个比较类似，把上面的代码复制下来做个改造就可以。

需求要记录的是 100 到 500 之间所有 3 的倍数的累加之和。首先 100 到 500，范围得改：第一个数改成 100，第二个数改成 500。但要注意——`range(100, 500)` 是不包含 500 的，而我们要的范围包含 500，所以第二个数应该写成 **501**。

然后要计算所有 3 的倍数的数字之和。一个数是不是 3 的倍数，就看它能不能被 3 整除，也就是**模于 3 等于 0**，`i % 3 == 0` 就说明 `i` 是 3 的倍数。满足这个条件再把它累加起来。

```python
# 计算100到500之间所有3的倍数的累加之和

# 记录累加之和
total = 0

for i in range(100, 501):
    # 判断是否为3的倍数
    if i % 3 == 0:
        # 累加
        total += i

print(f"100到500之间所有3的倍数的数字累加之和是：{total}")
```

因为 `range(100, 501)` 生成的就是 100 到 500 之间的数字序列，所以 `start` 必须显式写成 100——第一种写法默认从 0 开始，这里用不了。

运行之后，最终累加起来是 **39900**，这个结果没有问题。

> **易错点**：`range` 的结束值永远取不到，所以「1 到 100」要写 `range(1, 101)`、「100 到 500」要写 `range(100, 501)`。少加这个 1，边界上那个数就悄悄漏掉了，而累加和算错时很难一眼看出来。

### range 用法速查

| 用法 | 写法 | 生成结果 | 说明 |
| --- | --- | --- | --- |
| 第一种 | `range(end)` | 0, 1, …, `end - 1` | 默认从 0 开始，不包含 `end` |
| 第二种 | `range(start, end)` | `start`, …, `end - 1` | 指定开始与结束，不包含 `end` |
| 第三种 | `range(start, end, step)` | `start`, `start + step`, … | 步长默认 1，指定 2 即每次加 2 |

`range` 语句的作用就是根据指定的规则生成对应的数字序列，也就是生成一个数据集。有了这个数字序列，我们再基于 `for` 循环去遍历它——一个数字集就摆在眼前了。

两个案例里都用到了这个新语句 `range`：它像是一个数字生成器，帮我们生成指定规则的数字序列，再把序列交给 `for` 循环逐个取出处理。

## 核心语法-流程控制语句-嵌套循环
> 对应分集：P32 | 原始标题：《32. 核心语法-流程控制语句-嵌套循环》

`while` 循环和 `for` 循环的核心语法都讲完了，接下来进入循环的高级用法——**嵌套循环**。

所谓嵌套循环，指的是在循环语句的循环体当中，又编写了一个循环语句。

这在日常里其实很常见，只是以前没有名字叫它。下面先看它的语法结构，再用一组案例把写法演示清楚。

### 嵌套循环的语法结构

这里以 `for` 循环为例。

外层写一个 `for` 循环，它要去遍历数据集一当中所有的元素。冒号下面那部分，就是这个 `for` 循环的循环体。

而在循环体当中，除了代码一、代码二这样的逻辑之外，下面**又套了一个 `for` 循环**。注意——这个内层的 `for` 循环，本身就是外层 `for` 循环的循环体当中的代码。循环体里套循环，这就是嵌套循环。

```python
for 元素一 in 数据集一:
    代码一
    代码二
    for 元素二 in 数据集二:
        内层循环体
```

> **定义**：嵌套循环（nested loop）就是在循环语句的循环体当中再编写一个循环语句；外面的叫外层循环，被套在里面的叫内层循环。

### 嵌套循环的执行流程

剖析执行流程时，有一个好用的办法：**先忽略掉外面的循环，聚焦于内部的循环**。

只盯着内层循环看，它就是一个普普通通的 `for` 循环——遍历数据集二当中的数据，把数据集二当中的元素一个一个拿出来，再对每个元素做进一步处理。内层循环到底要循环多少次，取决于数据集二当中到底有多少个元素。

再把外层循环引入进来。外层循环要遍历的是数据集一当中的数据。它每遍历出来一个数据，就会去执行这一块循环体里的代码：代码一、代码二执行完毕之后，接下来就要执行内层循环，而内层循环要完整地循环一整次。假设数据集二里面有 $n$ 个元素，那么外层循环循环一次，内层循环就得循环 $n$ 次。

内层循环循环完毕之后，再回到外层循环：外层循环去获取第二个遍历出来的元素，处理这个元素，然后内层循环**再循环 $n$ 次**。

> **结论**：外层循环循环一次，内层循环就完整地循环 $n$ 次，而这个 $n$ 取决于待处理的数据集二当中元素的个数。

```text
外层循环取第一个元素
    |
    +-- 代码一、代码二
    +-- 内层循环: 元素1 -> 元素2 -> 元素3 -> ... -> 元素n   (完整一轮)
    |
外层循环取第二个元素
    |
    +-- 代码一、代码二
    +-- 内层循环: 元素1 -> 元素2 -> 元素3 -> ... -> 元素n   (再完整一轮)
    |
   ... 直到数据集一取完
```

读图说明：竖着的两条分支属于同一次外层循环；内层循环每次都必须跑完整整 $n$ 个元素，跑完之后外层才往下走一个元素。

嵌套循环的这套流程，跟日常生活当中的钟表比较类似。

钟表上有时针、分针和秒针。单看分针和秒针：分针转动一小格，秒针是不是得转动一圈？然后分针再转动一小格，秒针又得转动一圈。

分针就相当于外层循环，秒针就相当于内层循环。内层循环一圈一圈地跑，外层循环一小格一小格地走——嵌套循环的执行节奏就是这个样子。

### 案例需求：打印由星号组成的长方形

接下来以一个小需求为例演示嵌套循环的写法：**根据用户输入的长度 m 和宽度 n，打印一个长度为 m、宽度为 n 的长方形**。

这里的 `m` 和 `n` 不是固定的，是由用户键盘录入的。长方形使用星号来表示：长度为 m，就打印 m 个星号；宽度为 n，纵向就打印 n 行。

比如输出一个长度为 10、宽度为 5 的长方形，那一行当中有 10 个星号，纵向一共有 5 行，也就是 5 排星号。

对这个需求做个拆分就清楚了：这不就是输出一行一行的星号吗？

先看一行。这一行当中有多少个星号，取决于长方形的长度 m —— 也就是说，**一行怎么输出**是可以单独搞定的。

一行搞定之后，具体有多少行，取决于宽度 n，那循环输出 n 次就行了。

所以整个需求是两件事：先解决「一行怎么写」，再解决「写多少行」。而这两件事刚好对应外层循环与内层循环。

### 代码实现

第一步，接收键盘录入。需要接收两个数：`m` 是长度，`n` 是宽度。

```python
# 接收键盘录入
m = int(input("请输入长方形的长度："))     # 长度
n = int(input("请输入长方形的宽度："))     # 宽度
```

所输入的数据都是字符串，所以用 `int` 把它转成整型，再把 `input` 语句传递进去。

> **提示**：在 PyCharm 里写这两行时，如果光标停在行中间想直接另起一行，按 `Shift + 回车` 就能在任意位置快速创建一个新行；直接按回车会把光标后面的内容顶到下一行去。

第二步，先只解决「一行」。这一行当中有多少个星号，取决于录入的 `m`：`m` 是 10 就有 10 个星号，`m` 是 20 就有 20 个星号。

这里就可以用 `for` 循环，配合 `range` 构造一个数字序列。`range` 只传一个数据时，代表从 0 开始到 `m` 结束、不包含 `m`，对应的个数刚好是 **m 个**。而 `i` 代表的就是遍历出来的元素。

```python
for i in range(m):
    print("*")
```

`i` 遍历出来的元素现在没什么用——这里并不需要对这个 `i` 做任何处理，只是想「遍历多次」，每遍历一次输出一个星号。先运行测一把：输入长度 10、宽度 5，得到了一串星号，确实是 10 个。

但是——这 10 个星号**每一个都占了一行**：第一个星号是一行，第二个星号是第二行，第三个是第三行。这和预期有差异：我们要的是 10 个星号输出在**同一行**当中。

#### print 的 end 参数

为什么会出现 10 行？回到代码看：每一次循环都调用了一个 `print` 语句输出了一个星号，而 `print` 语句**默认自带换行效果**，每一次执行都会输出到新的一行中。循环了 10 次，输出了 10 个星号，而这 10 个星号分别落在 10 行里。

想让它不换行，就要在调用 `print` 的时候后面加上一个逗号，再指定 `end` 等于一个空字符串。

```python
for i in range(m):
    print("*", end="")
```

`end` 表示的是这个输出语句**以什么结束**。它的默认值是 `
`——反斜杠 n，也就是前面讲字符串时讲过的转义字符，代表换行。不想换行，就把 `end` 设置为一个空字符串。

再测一次：输入 10、宽度 5，输出果然变成了 10 个星号，而且这 10 个星号在同一行当中，没有换行。

`end` 设为空串，意思就是每一次输出以「什么都不加」结束。既然它是可配置的，那就能让它干点别的：比如每一次输出完毕之后想加两个空格，直接在 `end` 里敲两个空格即可。运行之后会发现，每个星号后面都跟着两个空格，然后才输出第二个星号，再两个空格——每一次输出完都会加上两个空格。

> **定义**：`print` 函数的 `end` 参数指定这一次输出以什么内容结尾，默认值是 `
`（换行）。把它设为空字符串 `""` 表示不换行，设为两个空格则表示每次输出后追加两个空格。

#### 加上外层循环控制行数

一行搞定了，接下来是「到底有多少排星号」——这取决于宽度。

做法就是再循环一次：让 `for` 循环循环 `n` 次，`n` 就是宽度。所以在外面再写一个循环 `for i in range(n)`，然后把它里面的逻辑写成「输出这么一排星号」，也就是把刚才那个 `for` 循环放到这个 `for` 循环的里面。

这样一来会出现两个 `i`，把里面的变量名换掉就行，换成 `j`：

```python
for j in range(n):
    for i in range(m):
        print("*", end="  ")
```

现在两个循环各管什么？外层 `for` 循环遍历的是 `range(n)`，而 `n` 代表宽度，所以**外层循环控制的是行**——要输出多少行；内层 `for` 循环它遍历的是 `m`，代表要输出多少列——`m` 是 10 就代表输出 10 列。一个控制行，一个控制列。

> **易错点**：两层的循环变量别用同一个名字。外层用 `j`、内层用 `i` 是最省事的做法；两层都写 `i` 的话，内层会把外层的变量值覆盖掉，循环次数立刻错乱。

再运行一次：输入长度 10、宽度 5，结果和预期还是不一样——所有的星号全部输出到了一行当中。原因就在 `print` 的 `end` 上：`end` 设置的是两个空格，**并没有换行**。

那要不要换行？需要。**什么时候换行？外层循环每循环一次，就需要换一行。**

所以在外层循环这一层，循环体结束之后去换一行。怎么换？调用一次 `print` 语句就行，它默认自带换行效果；里面不用输出任何内容，因为我们只想让它完成换行这个动作。

```python
# 接收键盘录入长方形的长度m和宽度n
m = int(input("请输入长方形的长度："))
n = int(input("请输入长方形的宽度："))

# 打印长方形：外层循环控制行，内层循环控制列
for j in range(n):
    for i in range(m):
        print("*", end="")
    print()     # 外层循环每执行一次换一行
```

再测一次：输入 15，回车，再输入 5——输出的就是一个长度为 15、宽度为 5 的长方形。

### 用调试跟踪嵌套循环

效果实现完毕之后，用调试模式再跟踪一遍执行流程。断点就打在外层 `for` 循环这一行，选择调试模式运行，输入长度 6、宽度 3。

接下来看它怎么走：先进行外层循环，外层循环循环出一个元素之后，紧接着执行内层循环。外层循环循环一次，内层循环就得循环 `m` 次，`m` 是 6，所以内层循环要循环 6 次——内层第一次、第二次、第三次、第四次、第五次、第六次。

内层循环循环完毕之后，继续外层循环：外层循环第二次。在第二次的过程当中，内层循环又要循环 6 次。接着外层循环再循环第三个元素，内层循环继续执行 6 次。当外层循环循环完毕之后，整个循环结束。

是不是就像日常生活当中的那个时钟？分针转一小格，秒针就得转一圈；回来分针再转一小格，秒针再转一圈。

整个流程用一张图收尾：

```text
j = 0 : i = 0 1 2 3 4 5   -> 换行
j = 1 : i = 0 1 2 3 4 5   -> 换行
j = 2 : i = 0 1 2 3 4 5   -> 换行
```

读图说明：`j` 每取一次值，`i` 都完整地走完 0 到 5 这 6 个值；`j` 走完 3 个值，内层总共执行了 $3 \times 6 = 18$ 次。这就是「外层一次、内层 n 次」在具体数字上的样子。

## 核心语法-流程控制语句-嵌套循环-案例
> 对应分集：P33 | 原始标题：《33. 核心语法-流程控制语句-嵌套循环-案例》

嵌套循环的语法和执行流程我们已经清楚了，接下来要把它用在一个真正的案例上。这道题很经典：打印九九乘法表，就是我们小学天天背的那张表。

看最终要输出的效果。第一行是 `一一得一`；第二行是 `一二得二、二二得四`；第三行是 `一三得三、二三得六、三三得九`；第四行是 `一四得四、二四得八、三四十二、四四十六`。一行一行读下来，就是那张熟悉的表。

问题是，这张表怎么用代码把它一行一行吐出来？

### 一、把乘法表看成表格

先换个眼光看它：这其实是一张表格。每个乘法表达式占据一个单元格，因此每一行读出来就是表格的第一行、第二行、第三行……结构一下子就清晰了。

```text
第1行:  1x1=1
第2行:  1x2=2   2x2=4
第3行:  1x3=3   2x3=6   3x3=9
第4行:  1x4=4   2x4=8   3x4=12  4x4=16
...                                   -> 一直到第9行

列方向: 第1列的被乘数全是1, 第2列全是2, 第3列全是3, 第4列全是4
行方向: 第1行的乘数是1,     第2行是2,     第3行是3,     第4行是4
```

既然它是表格，那么"一行有几格、一共几行"就不再是感觉问题，而是可以数出来的数量关系。

#### 乘数就是行号

盯着乘法表达式里的第二个数字看，也就是乘数。

第一行的乘数是 1，第二行的乘数是 2，第三行的乘数是 3，第四行的乘数是 4，第五行就是 5。所以在这个表里，**表达式的第二个数字就是当前所处的行号**。

#### 被乘数就是列号

再盯第一个数字，被乘数。

竖着看：第一列的表达式，被乘数全是 1；第二列的被乘数全是 2；第三列全是 3；第四列全是 4。所以**表达式的第一个数字就是当前所处的列号**。

#### 一共九行九列

行数是九行，列数也是九列——从 `一一得一` 一直排到 `九九八十一`。

> **结论**：在九九乘法表里，第一个数代表列，第二个数代表行。行号和列号一定下来，表里每一个单元格的内容就唯一确定了。

### 二、输出顺序决定循环结构

接下来要问一个关键问题：输出的时候，是一列一列地输出，还是一行一行地输出？

答案是一行一行。先输出第一行，第一行完了再输出第二行，第二行完了再输出第三行，一路往下。打印这件事本身就是一行一行往外走的。

这一下就把嵌套循环的分工定死了：外层循环控制行，内层循环控制列。

- 外层循环对应表达式里的第二个数字，也就是行。它负责"第一行输出完，去做第二行，第二行输出完，去做第三行"。
- 内层循环对应表达式里的第一个数字，也就是列。因为一行里面还有若干个单元格——第三行有三个格子，第四行有四个格子——这些格子必须一个一个输出。

```text
外层循环 (行 i)
  |
  |-- i = 1  -> 内层循环输出 1 个格子
  |-- i = 2  -> 内层循环输出 2 个格子
  |-- i = 3  -> 内层循环输出 3 个格子
  |                          ...
  |-- i = 9  -> 内层循环输出 9 个格子
  |
  +-- 每跑完一轮内层循环, 补一次换行, 再进下一行
```

读这张图要注意一点：内层循环每完整跑完一轮，才轮到外层循环往前走一步；换行发生在两者之间。

### 三、把分析写成代码

分析清楚了，直接在 PyCharm 里落代码。既然循环次数明确，就用 for 循环，两层。

#### 外层循环的范围不能是 range(10)

先写外层：

```python
for i in range(1, 10):
```

写 `range` 的时候，开发工具默认提示的是 `range(10)`。这个提示不能直接用。`range(10)` 生成的数字序列是从 0 开始的：0、1、2……9。而我们要的序列是从 1 开始。

所以写成 `range(1, 10)`：从 1 开始，到 10 结束但不包含 10，实际取到 9。九行，正好。

> **易错点**：`range` 的结束值是开区间，不包含在序列里。想要 1 到 9，必须写 `range(1, 10)`，写 `range(1, 9)` 会少一行。

#### 内层循环的上限由行号决定

内层循环的循环变量换个名字，跟外层错开，不要也叫 `i`：

```python
for j in range(1, i + 1):
```

这里也有个坑。开发工具提示的是 `range(1, 10)`，但那意味着每一行都要输出十列。回头看表：第一行只有 1 个表达式，第二行有 2 个，第三行有 3 个，第四行有 4 个——每行的列数是随行号变化的。

那这个列数由谁决定？由 `i` 决定。`i` 是 1 就输出一列，`i` 是 2 就输出两列，`i` 是 3 就输出三列。

所以上限应该写成 `i`。但 `range` 的结束值不含在内，如果直接写 `range(1, i)`，第一行 `i` 是 1，`range(1, 1)` 一个元素都不产生，一行就空了。所以要写成 `i + 1`：`i = 1` 时取到 1 列，`i = 2` 时取到 1、2 两列。

#### 内层循环体的输出格式

循环体要做的事就是输出单元格内容。用格式化字符串来拼：

```python
print(f"{j}x{i}={j * i}", end="\t")
```

- 第一个数用 `j`，它是内层循环遍历出来的元素，也就是被乘数（列号）；
- 乘号这里用字母 `x` 代替。想要真正的 `×` 符号，可以在输入法上点右键，打开符号大全，在里面挑对应的符号；
- 第二个数用 `i`，也就是乘数（行号）；
- 后面接等号，结果是 `j * i`。

`print` 默认自带换行，而内层循环控制的是列，列与列之间不能换行，只能拉开一点间距。所以给 `end` 参数赋一个制表符：

```python
end="\t"
```

`\t` 是转义字符，代表制表符，也就是一个 tab 的距离。这样每输出一个表达式，结尾都补一个制表符宽度。

#### 每行结束补一次换行

内层循环跑完之后，在它下面调用一次不带参数的 `print`，利用它自带的换行效果起一个空行，把行与行分开。

完整代码如下：

```python
# 打印九九乘法表
for i in range(1, 10):          # 外层循环: 控制行
    for j in range(1, i + 1):   # 内层循环: 控制列
        print(f"{j}x{i}={j * i}", end="\t")
    print()                     # 一行输出完毕, 换行
```

### 四、运行结果与对齐

右键运行，九九乘法表就出来了。对照样例：`一一得一`，`一二得二、二二得四`，`一三得三、二三得六、三三得九`，`一四得四、二四得八、三四十二、四四十六`，完全一致。

为什么列会排得这么整齐？因为每输出一个表达式，都是以 `\t` 结束的。那个位置就是一个制表符的空格。

把 `end="\t"` 去掉再跑一次试试，所有表达式会挤到一块儿，读起来就很难看了。

> **提示**：`\t` 决定的是对齐效果，而不是内容正确性。去掉它表还是对的，但不再是"表格"的样子。

## 核心语法-流程控制语句-循环-综合案例(break与continue)
> 对应分集：P34 | 原始标题：《34. 核心语法-流程控制语句-循环-综合案例(break与continue)》

while 循环、for 循环，以及循环的高级用法嵌套循环，到这里都讲完了。接下来用一组案例把循环语法真正用起来。第一个案例是登录操作：根据输入的用户名和密码来执行登录。

这个需求看着眼熟——前面确实做过用户名和密码的判断。但这一次的差别不小，先把五点要求摆清楚。

### 一、案例需求

1. 系统当中正确的用户名和密码有三组：`admin/666888`、`张三/123456`、`涛哥/888666`。斜杠后面的是正确密码。用户输入的用户名和密码命中这三套中的任意一套，就算正确。
2. 输入用户名和密码进行登录，直到登录成功程序结束运行；如果登录失败，则继续输入用户名和密码进行登录。
3. 输入的用户名和密码不能为空。如果为空，继续提示它输入正确的用户名和密码。
4. 登录成功时输出"登录成功，进入到 B 站首页"。
5. 登录失败时提示"用户名或密码错误，请重新输入"。

第二点是整个案例的重心。以前的做法是：登录成功提示成功，登录失败提示失败，然后程序就结束了。现在不一样——登录失败要一直提示用户重新输入，直到成功为止。

只要登录失败就提示错误、再重新输入，这是一件被反复做的事情。

> **结论**：需求里出现"重复做同一件事"，就是循环的信号。第 2 点要求把整个"输入 → 校验 → 判断"的过程包进循环里。

### 二、选 while 还是 for

既然要用循环，就得先定下来用哪一种。回想一下两者的适用场景：

- while 循环关注的是循环开始和结束的**条件**。不清楚要循环多少次，但知道循环结束（或开始）的条件是什么，就用 while。
- for 循环适合**循环次数已知**，或者要对某个数据集里的每一个元素做遍历处理的情况。

现在来对号入座：用户会登录失败几次？不知道。可能会有一次就对的用户，也可能有人连着输错十次。循环次数完全不确定。

但循环结束的条件非常明确：登录成功，程序结束运行。

> **结论**：这里用 while 循环。次数未知、条件已知，正是 while 的场景。

### 三、代码编写

打开 PyCharm，新建文件，注释先写上"循环案例一"。

#### while 的条件直接写 True

`while` 后面跟的是条件表达式，表达式的结果是布尔值：`True` 就开始循环，`False` 就结束循环。

以前写循环条件是这样的：先初始化一个变量 `i = 0`，然后写 `i < 10`。但那种写法成立的前提是——我们清楚知道要循环 10 次。

当前这个需求不知道要循环多少次，只有一个"直到成功才结束"的条件，所以条件表达式没法用计数变量写。直接写：

```python
while True:
```

一直循环，直到登录成功再退出。

#### 第一步：接收用户名和密码

循环体里的代码要缩进，不能顶格写。顶格写就和 `while` 平级了，那就不属于循环体。

```python
    username = input("请输入正确的用户名")
    password = input("请输入正确的密码")
```

两个变量分别接收录入的用户名和密码。写完第一行之后按 `Ctrl + D` 快速复制一行，改一下变量名和提示信息即可。

> **易错点**：缩进决定代码归属。循环体里的语句必须相对 `while` 缩进一级，否则它只会在循环之外执行一次。

#### 第二步：校验用户名和密码是否为空

在判断用户名密码是否正确之前，还有一步：校验它们是不是空的。

```python
    if username == "" or password == "":
        print("输入的用户名和密码不能为空，请重新输入")
```

这里有两个细节。

第一，空字符串是里面没有任何字符的字符串。如果写成 `" "`，那里面有一个空格字符——**空格也是字符**，`" "` 不是空串，`""` 才是。

第二，两个条件之间必须用 `or`，不能用 `and`。需求说的是"用户名和密码不能为空"，只要其中任意一个为空就要提示；用 `and` 的话，只有两者同时为空才会提示，用户名空、密码不空就漏掉了。

这一整段在程序里叫**校验**：校验输入的用户名和密码是否为空。

#### 第三步：判断正确性并执行登录

三组正确的用户名和密码对应一条 if-elif-elif-else 链：

```python
    if username == "admin" and password == "666888":
        print("登录成功，进入到B站首页")
    elif username == "张三" and password == "123456":
        print("登录成功，进入到B站首页")
    elif username == "涛哥" and password == "888666":
        print("登录成功，进入到B站首页")
    else:
        print("用户名或密码错误，请重新输入")
```

注意 `elif` 分支里面输出语句的缩进——它属于"这个条件成立时"要执行的逻辑，所以要比 `elif` 再缩进一级。

前三组条件用的是 `and`：用户名和密码必须同时对得上，才算命中一套。

> **易错点**：校验空值用 `or`，判断某一组用户名密码匹配用 `and`。两处的逻辑关系正好相反，写混了功能就错了。

### 四、第一次运行暴露的问题

代码写完，右键运行，先试一个错的。

输入用户名 `admin`，再输入密码 `456`。回车之后提示"用户名或密码错误，请重新输入"，程序没有退出——控制台还是一个运行中的绿点，紧接着又让我们输入正确的用户名。

这就是需求第 2 点的效果：登录失败继续输入。

再输 `admin`、`666`，还是错，还是让我们重新输入。到这里都符合要求。

接着输入正确的 `admin` / `666888`。回车，输出"登录成功，进入到 B 站首页"。但光标还在下面闪，程序又在等待输入用户名。

**登录成功了为什么还在循环？**

因为写的是 `while True`，它会无条件地一直循环下去。而需求明确要求"直到登录成功程序结束运行"——登录成功就必须跳出循环。

### 五、break：登录成功就跳出循环

这里要引入循环里的一个关键字：`break`。

> **定义**：`break` 只能够出现在循环当中，表示结束循环、跳出循环。

用法很直白：想在哪跳出循环，就把 `break` 加在哪。既然登录成功之后不该再让用户输入，那就在登录成功那句输出后面加。

```python
    if username == "admin" and password == "666888":
        print("登录成功，进入到B站首页")
        break
    elif username == "张三" and password == "123456":
        print("登录成功，进入到B站首页")
        break
    elif username == "涛哥" and password == "888666":
        print("登录成功，进入到B站首页")
        break
    else:
        print("用户名或密码错误，请重新输入")
```

三个分支都要加。只要登录成功，就必须跳出循环。

#### 再加一个细节：break 与 while 的 else

之前讲过 `while` 后面可以配合 `else` 使用，`else` 里的代码块是在循环**正常结束**之后执行的。

```text
while 条件:
    循环体
else:
    循环正常结束后执行的代码

---------- break 的情况 ----------
while 条件:
    循环体
    break        ->  循环被跳出, 属于"非正常结束"
else:
    这里的代码不会执行
```

读图要点：`else` 挂在 while 上而不是挂在某个 if 上，它等待的是"循环自己走到头"这个结局；`break` 把这个结局提前掐断，`else` 自然就没有机会执行。

#### 验证跳出效果

停下来重新运行。先输入错误的密码，看它是否继续让用户输入；再输入正确的 `admin` / `666888`。

一旦监测到用户名密码正确，程序输出那句话，然后执行 `break`。回车之后输出"登录成功，进入到 B 站首页"，程序随即结束运行。

再用 `涛哥` 测一遍：先输一个错密码 `123`，提示错误、重新输入；再输 `涛哥` / `666888`——密码记错了，涛哥的密码是 `888666`，所以走的是 `else` 分支，提示错误后进入下一轮循环；最后输对 `涛哥` / `888666`，输出登录成功并跳出循环。

### 六、continue：空值处理后不再往下判断

再做一次测试：用户名输入 `admin`，密码直接回车（什么都没输）。

看输出的两行提示：

```text
输入的用户名和密码不能为空，请重新输入
用户名或密码错误，请重新输入
```

第二行提示说明下面那一段判断用户名密码正确性的逻辑**也执行了**。可是用户名密码已经为空，还有必要去判断它们的正确性吗？没有必要。

用断点跟一下执行流程就看得更清楚：在输入语句那里打一个断点，输入 `admin`，密码回车。此时 `username` 是 `admin`，`password` 是空字符串。往下走一步，命中"为空"的判断，输出提示信息。可代码并没有停下，它继续往下执行了判断正确性的那一段。

要让下方代码不再执行、直接进入下一次循环，需要第二个关键字：`continue`。

> **定义**：`continue` 只能够出现在循环当中，表示中断本次循环，直接进入下一次循环。

在提示信息后面加上它：

```python
    if username == "" or password == "":
        print("输入的用户名和密码不能为空，请重新输入")
        continue
```

加上之后，本次循环走到这里就结束了，直接进入下一轮。

在判断处再打一个断点，右键用调试模式运行。输入 `admin`，密码直接回车。

执行完输出语句之后，紧接着执行 `continue`。这时按 `F8` 单步往下走，会看到程序**并没有**继续往下执行第 25 行，而是直接跳到了下一轮循环的开头。

如果想让它一次跑到位、不必单步跟，可以按 `F9` 恢复程序运行，直接跑到下一个断点。

### 七、两个关键字的对比

两个关键字都只能出现在循环里，while 循环和 for 循环都可以用它们。

| 关键字 | 作用范围 | 效果 | 本轮循环剩余语句 |
| --- | --- | --- | --- |
| `break` | 只能出现在循环中 | 结束（跳出）整个循环 | 不再执行，循环彻底结束 |
| `continue` | 只能出现在循环中 | 中断本次循环，进入下一次循环 | 不再执行，但循环继续 |

> **易错点**：两者都只影响"当前这一层"循环。在嵌套循环里，`break` 跳出的是它所在的那一层，不是所有层。

### 八、循环内的三段式控制流

把登录案例的控制流串起来看：

```text
        +--------------------------+
        |        while True        |
        +------------+-------------+
                     |
        [1] 接收 username / password
                     |
        [2] 校验: 为空? --是--> 输出提示 --> continue --> 回到循环开头
                     |
                     否
                     |
        [3] 判断正确性
             |                    |
          命中任一组             都不命中
             |                    |
        输出登录成功            输出用户名或密码错误
             |                    |
          break                 (进入下一轮循环)
             |
        跳出循环, 程序结束
```

读图要点：`continue` 和 `break` 都发生在判断之后，但走的是两条完全不同的出路——`continue` 只是跳过本轮剩下的代码，回到条件判断处继续循环；`break` 直接终结整个循环。

## 核心语法-流程控制语句-循环-综合案例2(猜数字游戏)
> 对应分集：P35 | 原始标题：《35. 核心语法-流程控制语句-循环-综合案例2(猜数字游戏)》

第一个综合案例做完了，接着来做第二个：猜数字的小游戏。这个案例除了继续用循环，还会引入一个新东西——随机数。

### 一、案例需求

1. 系统先生成一个随机数。所谓随机数，就是一个不可预测、也没有规律的数字，这个数字要通过代码自动生成。
2. 用户根据提示来猜这个数字，把所猜的数字输入到系统当中。
3. 系统把用户猜的数字和生成的随机数做对比。
4. 如果猜错了，系统给出提示，告诉用户猜大了还是猜小了，然后让用户继续输入所猜的数字。
5. 直到用户猜对，系统自动退出，游戏结束。

第 4、5 两点就是循环信号：猜错就提示、再输入，这一套动作被反复执行，直到猜对为止。

### 二、随机数怎么生成

生成随机数要借助 Python 提供的一个模块，叫 `random`。模块里的功能可以帮我们生成随机数。

用这个模块之前得先把它导入进来，靠一个关键字 `import`：

```python
import random

random_number = random.randint(1, 100)
```

`randint` 是 `random` 模块里的一个功能，需要指定两个数字：一个是起始，一个是截止。写 `1, 100` 就代表生成的随机数介于 1 到 100 之间，**包含 1，也包含 100**。

前面用一个变量 `random_number` 接收生成的随机数，这个变量里记录的就是那一次的随机数结果。

> **提示**：`randint` 的两端都是闭区间，也就是 $[1, 100]$。这和 `range(1, 100)` 的右端不含不同，别把两者的边界习惯混起来。

关于这两句代码具体的含义和写法，后面会有专门的讲解，现在先会用、先知道通过这两句就能生成一个随机数就够了。

### 三、选 while 还是 for

和登录案例一样，先定循环类型。

需求说的是"直到用户猜对，系统才自动退出"。循环次数确定吗？完全不确定——有人一次就中，有人猜十几次。但退出条件非常明确：用户猜对了。

次数未知、条件已知，用 while 循环。

### 四、猜数字的主体逻辑

打开 PyCharm，新建文件"循环案例 2.py"。需求已经罗列在里面了，接着往下实现。

#### 接收输入并转成整数

随机数有了，接下来把用户猜的数字收进来：

```python
number = int(input("请输入一个数字"))
```

上面生成的随机数是 `int` 类型。`input` 拿到的永远是字符串，所以这里直接把字符串转成 `int` 再赋值给 `number`，后面才好和随机数比大小。

#### 三分支比较

比较两个数字，用 if 条件判断：

```python
if number > random_number:
    print("您输入的数字太大了！")
elif number < random_number:
    print("您输入的数字太小了！")
else:
    print("恭喜您，猜对了！666")
```

- `number` 大于 `random_number`，说明输入的数字大了；
- `number` 小于 `random_number`，说明输入的数字小了；
- 剩下的 `else` 里，`number` 既不大于也不小于，那就只能是等于——也就是猜对了。

> **结论**：三段比较不需要显式写 `number == random_number`。前两个条件都用不等号排除掉之后，`else` 分支剩下的唯一可能就是这个等号。

#### 先看数字，方便测试

为了测试方便，在最后把生成的随机数直接打印出来，这样一眼就知道答案是多少：

```python
print(f"随机生成的数字是{random_number}")
```

> **提示**：这句输出只是给测试用的脚手架。它现在有实际作用，但在最终成品里它会破坏游戏的可玩性。

基础逻辑理清楚，先运行一次测试。输入 `60`，提示"您输入的数字太小了"，随机生成的数字是 `72`。

问题立刻暴露：没猜对，程序也退出了。因为这段代码没有任何循环操作，从头到尾只执行了一遍。

### 五、把哪几行放进循环

需求要求猜对了才退出，猜错就继续输入。所以这段逻辑要重复执行多次，必须放进循环。用 `while True`，把刚才写的逻辑整体挪进循环体。

但**不是所有行都该进循环**。这里要逐行判断：

| 代码 | 是否放进循环 | 原因 |
| --- | --- | --- |
| 导入 `random` | 不放 | 只做一次准备工作 |
| `random_number = random.randint(1, 100)` | 不放 | 放进循环就是每次循环都重新生成一个数 |
| 输入所猜数字 | 放 | 每一轮都要重新猜 |
| 三分支比较与提示 | 放 | 每一轮都要重新判断 |
| 输出随机数（测试用） | 不放 | 只在游戏结束后展示一次 |

生成随机数那行如果被塞进循环，结果就是每猜一次答案都变一次，游戏根本无法完成。所以它必须留在循环外面，只执行一次。

```python
import random

random_number = random.randint(1, 100)

while True:
    number = int(input("请输入一个数字"))
    if number > random_number:
        print("您输入的数字太大了！")
    elif number < random_number:
        print("您输入的数字太小了！")
    else:
        print("恭喜您，猜对了！666")

print(f"随机生成的数字是{random_number}")
```

### 六、死代码：为什么最后一行变灰了

代码写完，会发现最后那行输出随机数的语句**变成灰色**了。

这是 PyCharm 这类开发工具的智能提示：它会判断这行代码有没有机会被执行到。一旦显示为灰色，就说明这里可能有问题。

鼠标移上去，提示是"死代码，不可到达"——意思是这行代码可能永远都运行不到。

原因很清楚：上面是 `while True`，一个无限循环，而且在任何位置都没有跳出循环，所以它下面的代码永远等不到执行的机会。

再问一遍：什么情况下应该跳出循环、游戏结束？猜对的时候。

所以在 `else` 分支里，除了输出"恭喜您猜对了"，还要在下面加一句跳出循环的语句：

```python
    else:
        print("恭喜您，猜对了！666")
        break
```

> **易错点**：这里该用 `break`，不是 `continue`。`continue` 只是结束本轮、进入下一轮，循环仍然继续；猜对了要的是整个循环结束、游戏退出，只有 `break` 能做到。

加上 `break` 之后，最后那行代码就不再是灰色了——它重新变得可能被执行到。

### 七、运行测试与折半猜法

运行程序，因为随机数在循环之后才输出，所以一开始得盲猜。

既然数字范围是 1 到 100，怎么猜才能又快又准？

从 1、2、3 一个个往上试，还是每次猜中间的数字？后者快得多。因为每猜一次，无论提示是"太大"还是"太小"，都能砍掉一半的候选范围。

这一次的实际过程：

| 轮次 | 猜的数字 | 系统提示 | 剩余可能区间 |
| --- | --- | --- | --- |
| 1 | 50 | 太小了 | 51 ~ 100 |
| 2 | 75 | 太小了 | 76 ~ 100 |
| 3 | 85 | 太小了 | 86 ~ 100 |
| 4 | 93 | 太小了 | 94 ~ 100 |
| 5 | 97 | 太大了 | 94 ~ 96 |
| 6 | 95 | 太小了 | 96 ~ 96 |
| 7 | 96 | 猜对了 | 命中 |

第 4 轮猜完，区间从 100 个数字缩到 7 个；第 6 轮猜完，只剩一个数字，答案已经锁定。

猜对之后输出"恭喜您，猜对了！666"，接着输出"随机生成的数字是 96"，程序退出循环结束运行。

而猜错的时候，程序并不会结束，它会一直提示、一直让我们重新输入所猜的数字。

```text
     while True
         |
    输入所猜数字
         |
    与随机数比较
     /    |    \
  太大   太小   相等
   |      |      |
  提示   提示   输出"猜对了"
   |      |      |
   +------+    break
   |             |
   +--> 下一轮   跳出循环
                 |
          输出随机生成的数字
```

读图要点：只有"相等"这一条分支能走到 `break`，另外两条分支只是打印提示就回到循环开头，这就是"猜错继续、猜对结束"的全部机制。
