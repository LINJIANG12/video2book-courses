### 库定位与版本依赖选型

Pandas 是一个开源的、高性能且易于使用的数据结构化分析工具集。从技术分层来看，Pandas 属于 Python 的第三方扩展库，并非语言内置的标准库，其核心计算底层基于 NumPy 构建。NumPy 专门处理高效的底层数值矩阵与张量运算，而 Pandas 则在其之上封装出了更契合人类业务逻辑的表格标签与序列体系。

#### 依赖版本冲突与稳定性锁定

在工程实践中，盲目安装最新版软件包极易引发上下游依赖冲突。以当前环境为例，Pandas 官方最新发行版已演进至 `3.0.1`，但在实际技术选型中不采用最新版本，原因在于 `3.0.1` 与前序应用开发中深度依赖的轻量级前端框架 Streamlit 存在底层接口不兼容的现象。

因此，技术栈选用兼顾稳定性与生态兼容性的次新版本：`2.3.3`。

在终端环境中通过 `pip` 执行带版本约束的联网安装：

### 表格建模与核心容器抽象

Pandas 的一切数据分析与清洗操作，均围绕两大核心数据容器展开：`DataFrame` 与 `Series`。

```text
                  DataFrame 轴向与维度模型
              
                       columns (轴向 axis=1)
                      [ 姓名 ]    [ 语文 ]    [ 数学 ]
                    +----------+----------+----------+
 index (轴向 axis=0) |          |          |          |
      0 ----------> |   张三   |    85    |    92    |
      1 ----------> |   李四   |    78    |    88    |
      2 ----------> |   王五   |    90    |    95    |
                    +----------+----------+----------+
                    | <-- row (单行记录包含多个标量) --> |
```

读图说明：DataFrame 具备双重轴向，行向（Row）向下延伸受 `index` 索引约束，列向（Column）横向展开受 `columns` 表头标签约束，二者交叉定位单个数据单元格。

#### 二维表格 DataFrame

`DataFrame` 在概念上等同于一张二维电子表格或关系型数据库中的数据表。它由三个关键维度组织而成：
- **行（Row）**：代表物理存储中的一条具体记录。
- **列（Column）**：代表某一特定维度的业务属性，具备固定的列标签（Column Name）。
- **行索引（Index）**：每一行数据前附带的位置或业务标识符。在用户未显式指定的情况下，系统默认分配从 `0` 开始递增的非负整数序列（`0, 1, 2, ...`）。

#### 一维序列 Series

`Series` 是表格中单独一列的抽象。将 `DataFrame` 中的任意一列单独提取出来，其数据结构就是一个 `Series`。
- `Series` 内部保持严格的顺序结构，同样具备绑定的行索引（`Index`），默认同样从 `0` 起步。
- `Series` 并不依赖于 `DataFrame` 而存活，它是一个完全可以脱离二维表独立被实例化、独立运算的底层对象。

> **定义**：`DataFrame` 是若干具备相同索引的 `Series` 沿列轴向横向对齐拼接而成的二维数据集；`Series` 则是带标签的一维均质数组。

### 学员成绩统计的对比实现

为了直观体会声明式数据分析库相较于命令式原生代码的效率优势，以统计班级学员各科成绩的极值与均值为例展开对比。

#### 原生 Python 嵌套遍历的实现开销

假设有一批学员信息，数据结构表现为由字典构成的原生列表：

```python
students = [
    {"姓名": "小王1", "语文": 65, "数学": 55, "英语": 99},
    {"姓名": "小王2", "语文": 82, "数学": 78, "英语": 91},
    {"姓名": "小王3", "语文": 91, "数学": 60, "英语": 85}
]
```

若不借助数据分析库，仅使用 Python 原生语法统计语文科目的最高分、最低分与平均分，必须执行以下计算链路：
1. 初始化一个专用于存放单科成绩的临时空列表 `chinese_scores = []`；
2. 通过 `for` 循环迭代 `students` 列表，在每轮循环中根据键提取单科成绩；
3. 将数值追加进临时列表；
4. 调用内置函数 `max(chinese_scores)` 与 `min(chinese_scores)` 提取极值；
5. 调用 `sum(chinese_scores) / len(chinese_scores)` 手动求取算术平均值；
6. 若需统计其他科目，则需要针对数学、英语重复构建循环或封装复杂的高阶过滤函数。

整个过程逻辑琐碎，存在大量的样本遍历与临时变量管理开销。

#### 基于 Pandas 容器的向量化提取与聚合

引入 Pandas 后，原生数据集合可一步封装进 `DataFrame` 表格对象中：

```python
import pandas as pd

data = [
    {"姓名": "小王1", "语文": 65, "数学": 55, "英语": 99},
    {"姓名": "小王2", "语文": 82, "数学": 78, "英语": 91},
    {"姓名": "小王3", "语文": 91, "数学": 60, "英语": 85}
]

df = pd.DataFrame(data)
```

此时，整张表的结构在内存中规整对齐，提取特定列只需使用列索引操作符：

```python
# 提取单列，返回值类型为 Series
chinese_series = df["语文"]

# 直接调用聚合统计方法
max_score = chinese_series.max()
min_score = chinese_series.min()
mean_score = chinese_series.mean()
```

数据流转过程从繁琐的控制流遍历转变为直接针对数据管道的算子调用。

### 二维数据表 DataFrame 的构建与结构探查

在实际研发场景中，内存中的数据结构来源复杂多变。Pandas 为 `DataFrame` 类提供了高度多态的构造函数，允许以多种数据形态装配二维表。

#### 构造方式汇总与索引注入

构造 `DataFrame` 对象的底层数据组织方式主要有四种：

| 构造方式 | 数据载体特征 | 列名（Columns）判定来源 | 适用场景 |
| :--- | :--- | :--- | :--- |
| **方式一：列表嵌套字典** | 外层为 `list`，内层元素为若干 `dict` | 自动提取内层各字典的键（Key）作为列名 | 适合直接承接 Web API 或 NoSQL 返回的 JSON 列表 |
| **方式二：字典嵌套列表** | 外层为一个大 `dict`，内层各 Value 均为等长 `list` | 字典的键直接映射为各列列名 | 适合按列批量组装特征的计算管道 |
| **方式三：嵌套列表/元组结合 columns 参数** | 外层为 `list`，内层每一行为 `list` 或 `tuple` | 无法自动推断，必须通过参数 `columns=[...]` 显式声明 | 适合承接关系型数据库底层查出的游标行集（Row-tuples） |
| **方式四：自定义 index 索引标记** | 在前述任意结构基础上传入 `index=[...]` 参数 | 覆盖默认的 `0, 1, 2...`，采用自定义标签 | 适合以工号、日期、特定编码作为主键的表结构 |

以下为四种构造语法的代码实现：

```python
import pandas as pd

# 方式一：列表嵌套字典（按行注入）
df1 = pd.DataFrame([
    {"姓名": "张三", "语文": 85, "英语": 78, "数学": 90},
    {"姓名": "李四", "语文": 78, "英语": 88, "数学": 92},
    {"姓名": "王五", "语文": 92, "英语": 95, "数学": 86}
])

# 方式二：大字典映射列列表（按列注入）
df2 = pd.DataFrame({
    "姓名": ["张三", "李四", "王五"],
    "语文": [85, 78, 92],
    "英语": [78, 88, 95],
    "数学": [90, 92, 86]
})

# 方式三：二维嵌套列表并显式指定列标签
df3 = pd.DataFrame(
    [
        ["张三", 85, 78, 90],
        ["李四", 78, 88, 92],
        ["王五", 92, 95, 86]
    ],
    columns=["name", "chinese", "english", "math"]
)

# 方式四：嵌套元组并自定义行索引（覆盖默认整数索引）
df4 = pd.DataFrame(
    [
        ("张三", 85, 78, 90),
        ("李四", 78, 88, 92),
        ("王五", 92, 95, 86)
    ],
    columns=["姓名", "语文", "英语", "数学"],
    index=["a", "b", "c"]
)
```

> **提示**：无需死记所有参数组合。在 IDE（如 PyCharm）中将光标悬停在 `pd.DataFrame` 类名上，即可查看官方 Docstring 中的大量构造示例。

#### 探查二维结构的六大关键属性

构建完成或加载数据后，通常需要先宏观评估表格的规格与元数据，此时应调用对象的只读属性（无需加圆括号调用方法）：

```text
+----------+-----------------------------------------------------------+
| 属性名称 | 返回值与语义说明                                          |
+----------+-----------------------------------------------------------+
| index    | 返回行索引对象（如 Index(['a', 'b', 'c'])），支持 .tolist()|
| columns  | 返回列标签对象（Index(['姓名', '语文', ...])），支持转列表|
| values   | 返回底层二维 NumPy ndarray 数组，脱离表头剥离纯数值/文本   |
| size     | 返回表格内所有单元格的标量元素总个数（行数 × 列数）       |
| dtypes   | 返回每一列各自的存储数据类型                              |
| shape    | 返回结构维度元组：(行数, 列数)                            |
+----------+-----------------------------------------------------------+
```

读图说明：属性调用是针对数据表物理维度的无侵入式检查，其中 `shape` 与 `dtypes` 是数据探索阶段最优先调用的两个属性。

属性调用的具体代码实例如下：

```python
# 1. 获取行索引
idx = df4.index
# 转换为 Python 原生列表: ['a', 'b', 'c']
idx_list = df4.index.tolist()

# 2. 获取所有列名
cols = df4.columns
# 转换为 Python 原生列表: ['姓名', '语文', '英语', '数学']
cols_list = df4.columns.tolist()

# 3. 提取纯数据矩阵
val_matrix = df4.values
# val_matrix 类型为 numpy.ndarray，调用 tolist() 可获得原生嵌套列表

# 4. 统计单元格容量
total_cells = df4.size  # 当前 3 行 4 列，输出结果为 12

# 5. 探查各列数据类型
types = df4.dtypes
```

关于 `dtypes` 的输出，控制台将呈现类似如下的映射：

```text
姓名    object
语文     int64
英语     int64
数学     int64
dtype: object
```

> **提示**：Pandas 底层深度绑定 NumPy 类型系统。在 NumPy 的早期规范中，并不存在针对动态可变字符串的专用基本类型，因而文本字符串一律被统一划归为通用的通用指针对象类型 `object`；而数值列则按平台架构映射为高精度的长整型 `int64`。

最后是获取维度的核心属性 `shape`：

```python
dim = df4.shape  # 返回元组 (3, 4)，代表 3 行 4 列
```

### 一维序列 Series 的构建与属性解析

作为 `DataFrame` 的组成基石，`Series` 在单列特征抽取、序列运算中被频繁使用。

#### Series 的四种构建形态

实例化 `pd.Series` 对象时，常见的构造路径如下：

```python
import pandas as pd

# 1. 基础列表构造：默认整数索引 0, 1, 2, 3, 4
s1 = pd.Series([10, 20, 30, 40, 50])

# 2. 传入数据同时显式绑定自定义索引
s2 = pd.Series([10, 20, 30, 40, 50], index=["a", "b", "c", "d", "e"])

# 3. 基于键值对字典构造：字典的 Key 自动转化为索引，Value 转化为序列值
s3 = pd.Series({"a": 10, "b": 20, "c": 30, "d": 40, "e": 50})

# 4. 从现有的 DataFrame 中抽取单列生成 Series
# 此时生成的 Series 会完整保留原 DataFrame 对应的行索引（如 'a', 'b', 'c'）
s4 = df4["语文"]
```

在从 `DataFrame` 抽取列时，语法上存在两种等效途径：
1. **字典键索引法**：`df["语文"]`（标准规范推荐写法）；
2. **点属性语法**：`df.语文`（了解即可，不推荐在生产中泛用）。

> **易错点**：尽量避免使用 `df.列名` 形式访问序列。当列名包含特殊字符、空格、或者与 `DataFrame` 原生内置方法/属性（如 `count`、`shape`、`size`）重名时，点操作符会优先解析为内置方法，导致字段访问失效产生歧义；而 `df["列名"]` 具备绝对的安全边界。

#### Series 关键属性特征

`Series` 拥有的检查属性与 `DataFrame` 高度相似，但受一维特性的制约，其返回表现具有以下关键差异：

```python
# 1. 获取索引
s_index = s3.index  # 返回 Index(['a', 'b', 'c', 'd', 'e'])

# 2. 获取纯数据数组
s_vals = s3.values  # 返回 array([10, 20, 30, 40, 50])

# 3. 元素个数
s_size = s3.size    # 返回 5

# 4. 数据类型（注意属性名无复数 s）
s_type = s3.dtype   # 返回 dtype('int64')

# 5. 序列维度元组
s_shape = s3.shape  # 返回 (5,)
```

> **结论**：`DataFrame` 拥有两个轴向，故其类型属性为复数形式的 `dtypes`（每列各有一个类型），`shape` 表现为包含行列的二维元组 `(行数, 列数)`；而 `Series` 本质上只有一维单一序列，其类型属性为单数形式的 `dtype`，`shape` 返回的是形如 `(行数,)` 的单元素元组，第二维度位置留空。

### 外部数据文件的读取清洗与持久化输出

在工程级应用与业务管道中，数据不可能长期硬编码在代码内部，几乎所有的数据集都需要从外部扁平文本、电子表格或关系型数据库中加载，清洗加工完毕后再持久化至磁盘。

#### 输入输出两大家族 API 规范

Pandas 提供了一套高度统一、成对出现的文件交互接口：

```text
+-------------------+-----------------+-----------------------------------+
| 场景类型          | 读取函数 (Read) | 写入方法 (To)                     |
+-------------------+-----------------+-----------------------------------+
| 逗号分隔纯文本    | pd.read_csv()   | df.to_csv()                       |
| Excel 工作簿      | pd.read_excel() | df.to_excel()                     |
| 结构化 JSON 串    | pd.read_json()  | df.to_json()                      |
| 超文本表格标签    | pd.read_html()  | df.to_html()                      |
| 关系型数据库查询  | pd.read_sql()   | df.to_sql()                       |
+-------------------+-----------------+-----------------------------------+
```

读图说明：凡是以 `read_` 为前缀的均属于模块级顶级函数，用于将各类物理介质反序列化为内存中的 `DataFrame`；凡是以 `to_` 为前缀的均属于 `DataFrame` 实例方法，用于将当前表状态持久化写入外部文件。

#### CSV 数据的全量加载与控制台折叠

以电商交易流水文件 `sales.csv`（包含 1000 行、8 列业务数据）为例：

```python
import pandas as pd

# 读取并封装为 DataFrame
df = pd.read_csv("data/sales.csv")
```

当我们在 Jupyter Notebook 中直接输出 `df` 变量时，控制台底部会打印汇总元数据：`1000 rows × 8 columns`。
交互式解释器会在前端自动启用“智能截断展示机制”：默认仅渲染数据表的前 5 行（Head）与末尾 5 行（Tail），中间全部数据记录使用省略号收拢折叠，有效避免了因数万行数据无节制打印导致浏览器 DOM 树卡死的灾难。

#### 字段投射参数 usecols 按需读取

若原始文件体积庞大、字段极多，而当前分析模型仅关注局部核心字段（例如仅需：`订单号`、`产品类别`、`产品名称`、`销售数量`、`单价`），直接全量读取会白白消耗大量物理内存。

可以在调用 `pd.read_csv()` 时注入关键字参数 `usecols`（为 use columns 的缩写），传入目标字段列表进行字段级投影：

```python
df = pd.read_csv(
    "data/sales.csv",
    usecols=["订单号", "产品类别", "产品名称", "销售数量", "单价"]
)
```

此时内存中构建出的 `DataFrame` 将精准且仅包含被声明的 5 列，未被指定的冗余列在文件流解析阶段即被丢弃。

#### 向量化新增派生列与广播机制

在传统的命令式编程中，若需要通过 `销售数量 * 单价` 计算每个订单的总交易额，开发者必须遍历列表的每一行执行乘法。在 Pandas 中，这一操作通过列向量的算术运算在瞬间完成：

```python
# 基于两列相乘，派生出全新的“销售金额”列
df["销售金额"] = df["销售数量"] * df["单价"]
```

```text
                列向量相乘与广播计算过程
                
        df["销售数量"]               df["单价"]               df["销售金额"]
        +------------+             +----------+             +------------+
  idx 0 |     10     |      *      |   15.5   |     =       |   155.0    |
  idx 1 |      2     |      *      |   99.0   |     =       |   198.0    |
  idx 2 |      5     |      *      |   30.0   |     =       |   150.0    |
  ...   |    ...     |     ...     |   ...    |    ...      |    ...     |
        +------------+             +----------+             +------------+
```

读图说明：Pandas 在底层对齐相同的索引键，直接将整列一维数组在底层 C 语言级别逐元素并行相乘，并将计算好的新序列直接挂载回 `DataFrame` 作为一个全新的列存在。

#### 持久化输出与 index=False 陷阱规避

完成业务计算后，需要将包含新增派生列的最新数据写出到磁盘上的 `sales01.csv`：

```python
df.to_csv("data/sales01.csv", index=False)
```

在执行数据写出时，存在一个极其关键的参数：`index=False`。
- 默认情况下，`df.to_csv()` 会将 Pandas 在内存中自动维护的行索引序号（`0, 1, 2, ...`）作为第一列一并写入文件，由于该索引列没有列名，在导出的 CSV 文本首行会出现一个前导逗号 `,`，重新被读取时会形成一列无法命名的无头数据（如 `Unnamed: 0`）。
- 显式声明 `index=False`，代表强制剥离内存行索引，只保留纯粹的业务字段列落盘。

> **提示**：若在 IDE 的项目文件树中未立即观察到新生成的 `sales01.csv`，系 IDE 缓存延迟所致，在目标目录右键选择从磁盘同步重载（Reload from Disk）即可显式刷新出该文件。

#### 格式解析器依赖缺失排查

CSV 文件本质上是纯文本流，Python 与 Pandas 内置了解析引擎，无需外挂驱动。但若在实际工程中调用 `pd.read_excel()`、`df.to_excel()` 操作 `.xlsx` 文件，初次运行环境极有可能抛出异常（例如提示找不到支持该格式的后端引擎模块，如 `openpyxl`）。

此时无需惊慌，控制台报错信息下方通常会明确指出缺失的驱动包名称。在 PyCharm 等开发工具中可直接点击异常提示区域自动拉取下载，或在终端通过 `pip install openpyxl` 手工补齐驱动包后重新运行即可正常读写。

### 数据概览与宏观统计信息查看

将外部文件导入为 `DataFrame` 后，直接打印输出通常会遇到页面展示限制。当数据行数较多时，Pandas 默认会把中间绝大多数数据折叠省略，只保留前几行和后几行作为预览。为了快速掌握数据集的全貌，我们需要借助专用的概览方法与元数据属性。

#### 首尾预览与整体形态探查

查看数据最具代表性的样本，首先是探查它的开头与末尾记录：

```python
import pandas as pd

# 读取演示销售数据，指定加载其中的核心字段
df1 = pd.read_csv('sales.csv', usecols=['订单号', '产品类别', '产品名称', '销售数量', '单价'])

# 默认查看前 5 行数据
print(df1.head())

# 指定查看前 10 行数据
print(df1.head(10))

# 指定查看末尾 10 行数据
print(df1.tail(10))
```

- `head(n=5)`：默认返回数据集的前 5 行。如果传入整数参数 `n`，则返回前 `n` 行。在数据刚加载完成时，该方法常用于核对字段映射是否正确、表头是否对齐。
- `tail(n=5)`：默认返回数据集的末尾 5 行，支持传入参数 `n` 查看末尾 `n` 行。该方法常用于验证全量数据是否完整导入，排查文件末尾是否存在空行、汇总附录或截断损坏问题。

除了截取样本行，我们还可以直接通过属性获取数据的几何维度与列名集合：

```python
# 查看数据的维度规格（行数, 列数）
print(df1.shape)  # 输出示例：(1000, 5)

# 查看所有列标签名
print(df1.columns)
```

- `shape`：返回一个元组 `(rows, cols)`，直观告知当前二维表包含多少行、多少列。
- `columns`：返回一个包含所有字段名称的 `Index` 对象，用于后续提取特定列时核对列名的准确拼写。

#### 数值分布统计与结构元数据

对于更深层次的数据质量与分布分析，Pandas 提供了 `describe()` 与 `info()` 两个互补的方法：

```python
# 获取数值字段的统计汇总
print(df1.describe())

# 查看表的详细元数据信息
df1.info()
```

`describe()` 专注于对数据集中的**数值型列**进行集中统计计算，输出指标及其工程意义如下表所示：

| 统计指标 | 英文名称 | 统计学意义与业务解读 |
| :--- | :--- | :--- |
| **有效计数** | `count` | 该列非缺失（非空）记录的总行数。可用于快速发现是否存在字段缺失。 |
| **算术均值** | `mean` | 该列所有数值的算术平均水平，衡量整体集中趋势。 |
| **标准差** | `std` | 样本标准偏差，衡量数据离散波动程度。标准差越大，数据越分散。 |
| **最小值** | `min` | 字段中的最小物理值，常用于排查异常低值（如负数价格）。 |
| **下四分位数** | `25%` | 将数据升序排列后处于 25% 物理位置的数值。意味着有 25% 的订单单价低于此值。 |
| **中位数** | `50%` | 处于 50% 物理位置的数值（中位数）。比均值更抗极端值干扰。 |
| **上四分位数** | `75%` | 处于 75% 物理位置的数值。意味着有 75% 的订单单价低于该分位点。 |
| **最大值** | `max` | 字段中的最大物理值，常用于排查极端峰值与录入异常。 |

> **提示**：类似订单号这类由纯数字组成的标识列，虽然能够被计算出均值和四分位数，但其统计结果在业务上通常无实际意义；我们应重点关注具备物理意义的度量字段，如销售数量和单价。

而 `info()` 则呈现了更加立体的表结构元数据：
- 明确展示当前表格的总行数、索引取值范围（如 `RangeIndex: 0 to 999`）；
- 按列输出列序号、列名称、**非空有效值计数（Non-Null Count）**以及各列底层存储的物理数据类型（`Dtype`，如 `int64`、`float64`、`object`）；
- 列出数据占用的内存预估与各类型的字段数量汇总。

### 数据切片与行列选择机制

数据探索完毕后，接下来需要从整体数据集中抽取特定行或特定列。在 Pandas 中，列选择与行选择在底层设计和语法形态上有本质差异。

#### 列选择的操作形态与类型退化

列操作属于垂直维度的字段裁剪。根据抽取列数的不同，返回的对象类型会发生变化：

```python
# 读取用于选择的数据集
df2 = pd.read_csv('sales.csv', usecols=['订单号', '产品类别', '产品名称', '销售数量', '单价'])

# 方式一：方括号提取单列（推荐）
series_name = df2['产品名称']
print(type(series_name))  # <class 'pandas.core.series.Series'>

# 方式二：属性点语法提取单列（了解即可，受限较多）
series_name_dot = df2.产品名称

# 方式三：提取多列（必须嵌套列表）
df_sub = df2[['产品类别', '产品名称', '单价']]
print(type(df_sub))  # <class 'pandas.core.frame.DataFrame'>
```

> **注意**：
> 1. 单列选择与多列选择的返回类型不同。使用单个字符串列名 `df['产品名称']` 提取时，Pandas 将数据结构降维，返回一个一维的 `Series` 对象；而使用列表包裹多个列名 `df[['列1', '列2']]` 提取时，无论包含多少列，返回的始终是一个二维的 `DataFrame` 对象。
> 2. 尽管 `df.列名` 的属性点语法在书写上较为简洁，但当字段名称中包含空格、特殊标点符号，或者列名恰好与 `DataFrame` 原生内置方法（如 `count`、`shape`）同名时，点语法会引发严重的解析冲突或失败。因此在工程开发中，统一推荐使用外层方括号的字典风格写法 `df['列名']`。

#### 行选择核心机制：iloc 与 loc 的边界辨析

行选择属于水平维度的记录切片。Pandas 提供了两个最核心的访问器属性：`iloc` 与 `loc`。初学者极易将二者混淆，核心原因在于当数据表采用系统默认生成的从 0 开始的整数索引时，二者的定位行为看似高度重合。

```text
+-----------------------------------------------------------------------+
|                 Pandas 物理行号 (iloc) 与标签索引 (loc)                 |
+-----------------------------------------------------------------------+
|  隐藏的物理行号 (Row Position)  |  显式行索引标签 (Index Label)         |
|  [不可变, 系统内部维护, 0-indexed] |  [可自定义为任意字段, 甚至非连续/字符串] |
+-------------------------------+---------------------------------------+
|             0                 |  7496    (如以订单号为索引)             |
|             1                 |  4132                                 |
|             2                 |  5059                                 |
|             3                 |  3137                                 |
|             4                 |  4364                                 |
|             5                 |  5066                                 |
+-------------------------------+---------------------------------------+
|  iloc 依据左列位置切片:        |  loc 依据右列标签切片:                 |
|  df.iloc[0:5]                 |  df.loc['7496':'5066']                |
|  规则: 包含 0，不包含 5         |  规则: 包含 '7496'，同时包含 '5066'   |
+-----------------------------------------------------------------------+
```
> 图示说明：展示了底层物理位置序号与显式索引标签的对应关系，以及 `iloc` 和 `loc` 不同的切片边界判定机制。

##### 基于整数行号切片：iloc

`iloc`（Integer Location）严格基于记录在内存中的**底层绝对物理行号**进行切片，与行表面被赋予了什么索引名称完全无关。

- 语法结构：`df.iloc[start:stop:step]`
- 切片边界规则：遵循标准 Python 原生切片规范——**包含起始位置（start），严格不包含终止位置（stop）**，即前闭后开区间 `[start, stop)`。

```python
# 提取前 5 行记录（提取第 0, 1, 2, 3, 4 行，不含第 5 行）
print(df2.iloc[0:5])

# 指定步长 step=2，实现隔行跳跃提取
print(df2.iloc[0:5:2])
```

##### 基于索引标签切片：loc

`loc`（Location）则是根据数据表的**显式索引标签（Index Labels）**进行检索与切片。

- 语法结构：`df.loc[start_label:stop_label:step]`
- 切片边界规则：**两端完全闭合——既包含起始标签，也包含结束标签**，即闭区间 `[start_label, stop_label]`。

为了彻底看清 `iloc` 与 `loc` 的本质差异，我们可以通过读取文件时指定 `index_col`，将“订单号”显式设置为数据表的索引列：

```python
# 将订单号作为数据表的索引列加载
df_custom_index = pd.read_csv('sales.csv', index_col='订单号')

# 验证一：使用 iloc 提取前 5 行
# 此时索引列已变成订单号（7496, 4132...），表中不再存在名为 0~4 的索引
# 但 iloc 依旧正常工作，因为它认的是底层物理序号 0~4
print(df_custom_index.iloc[0:5])

# 验证二：对自定义索引使用数字切片 loc
# 执行报错：KeyError / 无法找到名为 0 和 5 的索引标签！
# df_custom_index.loc[0:5]  # <--- 这行代码会直接崩溃

# 验证三：使用合法的标签进行 loc 切片
# 必须传入具体的订单号字符串或数值，两端均会被完整包含在结果中
print(df_custom_index.loc[7496:5066])

# 带步长切片：每隔一行提取一条
print(df_custom_index.loc[7496:5066:2])
```

> **易错点**：
> 在默认不指定索引列时，Pandas 会自动建立 `0, 1, 2...` 的数字索引。此时 `df.loc[0:5]` 会返回 6 行（包含 0 和 5），而 `df.iloc[0:5]` 只返回 5 行（0 到 4）。切记：**`iloc` 认物理行号且前闭后开；`loc` 认表面索引且两端皆闭**。

### 数据条件过滤与逻辑组合筛选

数据过滤指根据特定的业务条件，从数据表中动态筛选出符合要求的记录行。过滤操作的标准语法骨架为：

$$\text{DataFrame}[\text{布尔条件表达式}]$$

其工作机制为：中括号内部的表达式对各行进行逐行运算，生成一个由布尔值（`True` 或 `False`）构成的 `Series`，外层 `DataFrame` 仅保留布尔值为 `True` 的对应记录行。

```python
# 读取全量销售数据集
df3 = pd.read_csv('sales.csv')
```

#### 单条件过滤的三大核心形态

根据过滤字段的数据类型与范围特征，单条件筛选主要分为基础数值比对、离散集合包含判定以及连续区间范围判断。

##### 基础数值比较筛选

使用 Python 原生比较运算符（`>`、`<`、`>=`、`<=`、`==`、`!=`）构建条件：

```python
# 需求：获取销售数量大于等于 10 的全部订单
cond_qty = df3['销售数量'] >= 10
result_qty = df3[cond_qty]

print(result_qty)
```

##### 离散类别包含过滤：isin()

当筛选目标是枚举型、文本型字段，且满足条件的可能值有多个时（相当于 SQL 中的 `IN` 操作），使用 `isin()` 方法：

```python
# 需求：获取产品类别为“食品”或“图书”的订单数据
# 传入包含目标分类的列表
cond_cat = df3['产品类别'].isin(['食品', '图书'])
result_cat = df3[cond_cat]

print(result_cat)
```

##### 连续数值区间匹配：between()

当需要匹配某个连续数值区间内的记录时，使用 `between()` 方法能够避免书写两个复合比较算式：

```python
# 需求：获取单价在 100 到 200 之间（含边界）的订单数据
cond_price = df3['单价'].between(100, 200)
result_price = df3[cond_price]

print(result_price)
```

`between()` 方法提供了核心参数 `inclusive` 用于精确控制区间端点的闭合状态：

| `inclusive` 参数取值 | 数学区间表达式 | 行为说明 |
| :--- | :--- | :--- |
| `'both'`（默认值） | $[left, right]$ | 既包含左边界最小值，也包含右边界最大值 |
| `'left'` | $[left, right)$ | 只包含左边界，严格排除右边界 |
| `'right'` | $(left, right]$ | 严格排除左边界，只包含右边界 |
| `'neither'` | $(left, right)$ | 左右两端边界均不包含（纯开区间） |

```python
# 仅包含左边界：保留单价为 79 的订单，排除单价为 199 的订单
df3[df3['单价'].between(79, 199, inclusive='left')]

# 仅包含右边界：排除单价为 79 的订单，保留单价为 199 的订单
df3[df3['单价'].between(79, 199, inclusive='right')]
```

#### 多条件逻辑组合与括号优先级铁律

在面对复杂的实际业务场景时，过滤往往由多个维度的规则共同约束。在 Pandas 中拼接多条件时，存在两项必须严格遵守的语法铁律：

> **核心铁律**：
> 1. **连接符必须使用位运算符**：逻辑“并且”（与）必须使用符号 `&`，逻辑“或者”（或）必须使用竖线 `|`。**绝不能使用 Python 的英文关键字 `and` 或 `or`**。
> 2. **每个独立的子条件必须用小括号 `()` 严格包裹**。

为什么必须强制打括号？
在 Python 语言的运算符优先级规范中，按位与 `&` 和按位或 `|` 的优先级高于比较运算符（`>=`、`<=`、`==` 等）。如果书写为：
```python
# 错误写法：会直接触发 TypeError 或 ValueError
df3[df3['销售数量'] >= 8 & df3['单价'] >= 100]
```
Python 会优先执行中间的 `8 & df3['单价']` 按位运算，进而破坏整个布尔逻辑表达式的结构并导致程序崩溃。

##### 多条件“与”筛选（多条件并存）

```python
# 需求：获取销售数量大于等于 8，且单价大于等于 100 的订单数据
# 每个子条件均用小括号单独括起，中间通过 & 连接
cond_multi_and = (df3['销售数量'] >= 8) & (df3['单价'] >= 100)
result_multi_and = df3[cond_multi_and]

print(result_multi_and)
```

##### 多条件复合组合筛选（集合包含与逻辑拼接）

```python
# 需求：获取产品类别为“服装”或“食品”，且支付方式为“支付宝”或“微信支付”的订单数据
cond_complex = (df3['产品类别'].isin(['服装', '食品'])) & (df3['支付方式'].isin(['支付宝', '微信支付']))
result_complex = df3[cond_complex]

print(result_complex)
```

#### 配置缓存与内核重启的执行链陷阱

当在单元格中注释掉 `pd.set_option('display.max_rows', None)` 并重新运行该单元格时，会发现终端依然在全量输出所有行，并未恢复默认截断。

这是因为 Jupyter 的运行机制是**基于后台常驻内核（Kernel）内存状态**的。之前执行的代码已经把修改写入了 Python 解释器的运行环境。单纯把当前单元格的语句注释掉再次运行，并不会抹除内存中已经生效的配置。

此时需要通过控制面板**关闭并重启内核（Restart Kernel）**来重置运行环境。但在重启内核后，开发者极易遭遇另一个连环报错：

```text
NameError: name 'pd' is not defined
```

```text

+-----------------------------------------------------------------------+
```
> 图示说明：展示了内核重启后内存状态完全清空的机理，警示不能跳过依赖单元格单独执行下游逻辑。

重启内核意味着整个 Python 运行时内存被彻底初始化。此时下游的过滤单元格所依赖的 `pd` 模块导入语句和 `df` 变量都保存在上方的单元格中。必须先按顺序执行最顶层的导入与加载单元格，使环境就绪后，下游代码方可正常执行。

### 缺失值的诊断与处置策略

在现实业务系统中，数据缺失往往不可避免：用户在表单中跳过了非必填项、网络传输丢包导致字段截断、多表外连接时未匹配到对应外键等，都会引发数据留白。在 Pandas 的 `DataFrame` 或 `Series` 中，这类缺失数据在呈现时通常会被标记为 `NaN`。

> **定义**：`NaN` 是英文 **Not a Number**（不是一个数字）的缩写。在 Pandas 中，它专门作为浮点型及通用缺失值的占位符，表示该单元格不存在有效业务数据。

为了在本地排查时不被巨量的数据滚屏淹没，同时又能一览前部的测试样本，我们可以在导入 Pandas 后通过配置选项微调输出窗口的折叠行为：

```python
import pandas as pd

# 设置 DataFrame 呈现时的最小行数阈值
pd.set_option('display.min_rows', 30)
```

> **提示**：Pandas 默认在数据量较大时只打印 10 行（前 5 行与后 5 行，中间折叠）。将其设置为 30，可以在终端或 Jupyter 界面中直接展示前 15 行与后 15 行。在测试排查前部构造的异常样本时，这种设置既能直观暴露问题，又能防止全量数据毫无节制地刷屏引发环境卡顿。

#### 缺失值的识别与布尔矩阵探查

在对缺失值采取任何工程动作之前，第一步永远是定位它在表格中的具体分布。Pandas 提供了 `isna()`（以及功能完全等价的 `isnull()`）方法来完成这一诊断：

```python
# 读取销售数据表
df = pd.read_csv('sales.csv')

# 探测全表缺失值分布
missing_mask = df.isna()
print(missing_mask)
```

`df.isna()` 执行后会返回一个与原数据形状完全一致的布尔型 `DataFrame`。如果某个单元格的数据存在，该位置对应的值为 `False`；一旦单元格为缺失值，则显式标红为 `True`。例如，当我们观察到索引为 `4`（即物理第 5 行）的“客户所在城市”字段返回了 `True`，这就意味着该条记录在这一维度上存在数据留白，需要我们在后续流程中重点处置。

#### 缺失行与列的剔除方法

一旦定位到缺失值，最直接的物理处置方式便是将其从数据集中剔除。Pandas 提供了专用的 `dropna()` 方法，支持基于行维度或列维度的灵活剔除。

##### 按行剔除缺陷记录

默认情况下，调用 `dropna()` 会在行维度（`axis=0`）上生效。只要某一行中存在任意一个单元格为 `NaN`，整行数据就会被直接移出结果集：

```python
# 默认删除所有包含缺失值的行（axis=0）
df_clean_rows = df.dropna()
```

此时再去检查原本索引为 `4` 的记录，会发现该行已经被完整过滤掉，数据集仅保留各个字段皆完整无缺的样本行。

##### 按列剔除缺陷字段

在某些特殊业务场景下，如果某一个字段因为上游采集方案变更导致大部分数据丢失，或者该字段并非核心分析指标，我们更倾向于保留所有的样本行，而仅仅丢弃这个“千疮百孔”的字段列。此时可以通过调整 `axis` 轴参数实现跨列删除：

```python
# 删除包含缺失值的整列（axis=1）
df_clean_cols = df.dropna(axis=1)
```

> **注意**：参数 `axis` 是 Pandas 轴向控制的核心参数。默认为 `0`，代表在行方向（纵向）上扫描并剔除包含缺失的记录行；当显式指定 `axis=1` 时，代表在列方向（横向）上扫描并剔除包含缺失字段的整列。在上述执行后，“客户所在城市”这一列将被完整抹除，但索引为 `4` 的这行记录在其他字段上的有效数据依然完好无损地保留在表中。

##### 原地修改陷阱与赋值惯用法

初学者在使用 `dropna()` 时最容易犯的错误是误以为调用该方法后原表已自动变更。来看下面的现象：

```python
# 错误认知：以为执行即修改
df.dropna(axis=1)

# 再次打印原始变量
print(df)  # 发现缺失列依然存在！
```

> **易错点**：`dropna()` 方法在底层遵循函数式不可变规范，它**不会原地修改原对象**，而是计算并返回一个生成好的全新 `DataFrame`。因此，如果希望保留删除后的清洗结果，必须显式将其重新赋值给原变量（`df = df.dropna()`）或声明新变量接收。

#### 标量填充与前后向推断填充

直接删除虽然痛快，但很多时候我们并不希望将一条耗费成本收集来的订单数据彻底抛弃。保留整行记录的同时修补数据空洞，就是填充缺失值的核心使命。Pandas 提供了三种极具代表性的填充机制：

```text
原始序列片段: [ '北京', '上海', NaN, '广州' ]
                  |       |     |      |
                  |       |     |      +--- 索引 3
                  |       |     +---------- 索引 2 (待填充空洞)
                  |       +---------------- 索引 1
                  +------------------------ 索引 0

策略 1: fillna('--') --> 常数标量回填
        结果: [ '北京', '上海', '--', '广州' ]

策略 2: ffill()      --> 前向填充 (Forward Fill: 取上一行相邻值)
        结果: [ '北京', '上海', '上海', '广州' ]

策略 3: bfill()      --> 后向填充 (Backward Fill: 取下一行相邻值)
        结果: [ '北京', '上海', '广州', '广州' ]
```

##### 固定常数标量填充

使用 `fillna(value)` 方法，我们可以将所有缺失处统一填充为指定的固定标量（如默认占位符 `--`、未知分类、或者数值型的 `0` 与均值）：

```python
# 使用业务占位符填充缺失单元格
df_filled_const = df.fillna('--')
```

##### 相邻行推断填充

在具有时间序列特征或连续采集特性的数据中，前后的状态往往具有延续性。Pandas 提供了两种免参数的推断填充方法：
- `ffill()`（Forward Fill）：向前填充。缺失单元格会自动沿用**上一行（前一个有效记录）**的数据进行填充。
- `bfill()`（Backward Fill）：向后填充。缺失单元格会自动抓取**下一行（后一个有效记录）**的数据进行回溯填充。

```python
# 使用上一行的有效值进行顺延填充
df_filled_forward = df.ffill()

# 使用下一行的有效值进行回溯填充（例如广州）
df_filled_backward = df.bfill()
```

##### 缺失值处置的业务权衡原则

究竟该选择“删”还是“填”？这是数据清洗中最关键的工程决策：

> **结论**：数据清洗绝不能脱离具体的业务目标孤立进行，**一切处置必须以满足业务分析诉求为首要前提**：
> 1. **极低占比场景（果断剔除）**：如果缺失值在全表中仅是个别偶发情况，样本剔除后对整体数据分布、统计体量没有任何实质影响，此时优先采用 `dropna()` 剔除，保持数据纯度。
> 2. **显著占比场景（合理填充）**：如果缺失数据占比达到 `20% ~ 30%` 甚至更高，大面积的物理删除会导致原本的数据结构支离破碎，样本量锐减将严重动摇分析结论的准确性。此时严禁直接删除，必须结合行业常识与业务规则，选用合理均值、众数、业务默认值或前后时序推断进行稳健填充。

### 重复数据的检测与去重控制

由于网络请求超时重试、上游爬虫未做 URL 去重，或者前端用户重复点击提交，业务日志与销售流水中经常会混入大量重复记录。重复数据不仅会虚增销售额与访问量，还会严重扭曲各类统计指标。

#### 基于全列与特定子集的重复标记

检测重复行可以使用 Pandas 的 `duplicated()` 方法。该方法的核心判定逻辑与参数机制如下：

##### 全列完全一致判定

如果直接调用无参的 `df.duplicated()`，Pandas 会严格对比每一行的**所有列**：

```python
# 默认检测：整行所有字段完全相同时才判定为重复
is_dup = df.duplicated()
print(is_dup)
```

当全表每一列的数值完全吻合时，后续出现的记录行才会返回 `True`。但在实际业务中，系统往往会在每条记录后打上不同的自动递增自增主键或时间戳，导致“全列完全相同”的判据失灵。

##### 基于业务主键的子集判定

在真实的电商交易场景中，只要**订单号**相同，无论其他辅助字段是否一致，都可以断定为同一笔业务的重复上报。此时我们需要通过 `subset` 参数传入我们锁定的判断列：

```python
# 仅基于“订单号”单个关键字段判定是否重复
dup_orders = df.duplicated(subset=['订单号'])

# 亦可基于多个复合字段进行联合查重
dup_multi = df.duplicated(subset=['订单号', '客户姓名'])
```

> **机制细节**：`duplicated()` 在扫描数据时，当某个订单号（如 `85059`）在第 3 行第一次出现时，它会被系统记录并视作有效首发基准，返回 `False`；当扫描推进到第 10 行再次遇到该订单号时，系统即刻将其识别为副本，返回 `True`。换言之，**第一次出现不算重复，第二次及后续出现才被标记为重复**。

#### 物理去重与保留策略定制

确认重复行的存在后，我们需要使用 `drop_duplicates()` 方法完成实际的清洗去重。与检测方法类似，它同样接收 `subset` 参数来指定去重依据列。除此之外，它还提供了一个至关重要的控制参数 `keep`。

```python
# 基于订单号字段删除重复记录，默认保留最先出现的样本
df_no_dup = df.drop_duplicates(subset=['订单号'])
```

##### 保留规则的三种策略矩阵

参数 `keep`（意为“保持/保留”）决定了当多条记录出现主键冲突时，系统究竟采信哪一条：

| `keep` 参数取值 | 核心行为解释 | 典型应用场景 |
| :--- | :--- | :--- |
| `'first'`（默认值） | 保留该组重复数据中**最先出现**的第一行，剔除后续所有副本 | 绝大多数常规业务流水清洗，以最先入库的数据为准 |
| `'last'` | 保留该组重复数据中**最后出现**的一行，将此前出现的所有行全部剔除 | 数据包含状态流转（如订单状态更新），需要保留最新终态 |
| `False` | **一条都不保留**，只要该记录存在重复，所有关联行统统物理抹除 | 严格去伪存真，将存在数据录入冲突、无法确认真伪的脏数据全部剔除 |

```python
# 1. 默认策略：保留第一条
df.drop_duplicates(subset=['订单号'], keep='first')

# 2. 逆向策略：保留最后一条
df.drop_duplicates(subset=['订单号'], keep='last')

# 3. 激进策略：只要重复，一律双杀抹除
df.drop_duplicates(subset=['订单号'], keep=False)
```

### 异常数值与格式不规则的清洗修复

除了显式的缺失与重复，数据清洗中最隐蔽也最耗费心力的部分，是对**业务异常值**与**非标格式**的订正。这部分工作无法套用固定的现成 API，必须深度结合具体的业务规则展开。

#### 业务约束违背值的定位与纠偏

异常值并不是 Python 的语法错误，而是其取值**违背了客观世界或业务领域的内在逻辑**。例如，商品的销售单价不可能小于 0，销售数量也不可能为负数。一旦出现 `-29` 这样的单价，它就是典型的异常值。

##### 异常样本的检索与定位

借助 Pandas 的布尔条件切片，我们可以迅速把存在业务逻辑缺陷的行揪出来：

```python
# 通过布尔条件筛选单价小于 0 的违规记录
abnormal_mask = df['单价'] < 0
abnormal_rows = df[abnormal_mask]
print(abnormal_rows)
```

执行后，终端会准确输出所有单价异常的样本行（例如索引为 `6` 的这笔订单记录）。

##### 处置策略选择：物理删除还是数值纠正

面对捞出的异常数据，通常有两种处理路径：

```python
# 路径 1：物理删除该行异常记录
# 利用查询出来的索引 index，调用 drop 进行物理移除
df_dropped = df.drop(index=df[df['单价'] < 0].index)
```

然而在不少实际场景中，数值为负往往是由于上游前端页面计算失误、或者是爬虫逆向接口解析符号时误加了负号引起的，其数值本身（`29`）完全真实可靠。如果直接把整条订单丢掉，会导致销售总额的统计遗漏。此时最合理的策略是**业务修复**：

```python
# 路径 2：业务修复——调用 abs() 批量求绝对值纠正
df['单价'] = df['单价'].abs()
```

通过这一行矢量化运算，单价列中原本为 `-29` 的异常负数会全部被转换为正数 `29`，既纠正了业务指标，又完整保全了原始交易流水。

#### 基于字符串访问器的格式矢量化清洗

现实数据集中经常出现格式“群魔乱舞”的现象。例如同样表示日期，整张表中 99% 的数据都是 `2023-05-01` 这种标准格式，中途却混杂着部分用斜杠分割的 `2023/05/01`。为了后续能将其统一解析为标准时间类型（`datetime`），必须先在字符串层面对其完成归一化清洗。

##### 常见误区：直接调用 Series.replace()

很多初学者容易想当然地写出如下代码：

```python
# 常见错误：试图在 Series 上直接将斜杠替换为横线
df['订单日期'] = df['订单日期'].replace('/', '-')
```

执行上述代码后，你会惊讶地发现原本的斜杠日期**毫发无损，完全没有被替换掉**。

> **易错点**：`Series.replace()` 在默认情况下的设计机制是**全单元格完全值匹配**。它期望找到内容恰好就是单一字符 `'/'` 的那个单元格进行整格替换，而不是去单元格的长字符串内部寻找子串做局部替换。

即使你写成 `df['订单日期'].replace('2023/05/01', '2023-05-01')` 能够把当前单元格改对，但这本质上是脆弱的硬编码，面对全表成百上千个分散在不同月份的斜杠日期，这种写法完全不具备通用性。

##### 正确姿势：使用 .str 字符串访问器

Pandas 为文本序列专门提供了 `.str` 访问器，用于将 Python 原生字符串的强大处理能力无缝广播到整列数据的每一个元素上：

```python
# 正确写法：借助 .str 访问器调用底层字符串的 replace 方法
df['订单日期'] = df['订单日期'].str.replace('/', '-')
```

通过 `.str.replace('/', '-')`，Pandas 会在底层对“订单日期”这一列所有单元格的内容进行矢量化遍历，精准检索其中的 `/` 子串并全局替换为 `-`，从而以极高的效率将全表所有杂乱的日期格式统一为标准形态。

### 单维度与多维复合数据排序

完成清洗与格式归一化之后，数据集已经变得干净且可信。在展开深入的报表汇总之前，我们往往需要对数据进行升序或降序排列，以直观查看最高售价、畅销商品榜单或最近日期的业务变动。

> **提示**：在分析排查阶段，如果外部文件体积过大（如包含数十万行记录的庞大 CSV），读取并打印全表会极其缓慢。除了加载后使用 `head(10)` 截取样本外，更高效的做法是在读取阶段直接通过 `nrows` 参数限定输入量：`pd.read_csv('sales.csv', nrows=10)`，从源头截断 I/O 开销，加速本地逻辑验证。

Pandas 中以 `sort` 开头的方法主要有两个：
- `sort_index()`：基于行标签或列标签的**索引（Index）**进行排序；
- `sort_values()`：基于表格内部具体**字段值（Values）**展开业务排序。数据分析中最核心、使用频率最高的正是 `sort_values()`。

#### 单列数值排序与排序方向缺省规则

单列排序非常直观，我们通过参数 `by` 传入要作为排序依据的列标签名：

```python
# 需求 1：根据“销售数量”进行升序排序（默认行为）
df_asc = df.sort_values(by='销售数量')

# 需求 2：根据“销售数量”进行倒序（降序）排序
df_desc = df.sort_values(by='销售数量', ascending=False)
```

> **定义**：参数 `ascending` 意为“上升的”。其缺省默认值为 `True`，即**升序排序**（从小到大依次排列）；如果需要进行**降序排序**（从大到小依次排列），必须显式将该参数赋值为 `False`。

如果业务需求就是升序排列，我们可以完全省略 `ascending=True` 不写，直接使用 `df.sort_values(by='单价')` 即可达到目的。

#### 多列多级排序与方向布尔广播

现实业务场景往往比单一指标复杂得多。例如在电商大促分析中，业务人员可能会提出这样的诉求：
> “先按照商品单价从低到高排列；如果遇到单价完全相同的商品，再按照销售数量从高到低进行倒序排列。”

这种涉及多个指标、带有主次优先级的场景，就需要使用**多列复合排序**。

##### 多列级联排序机制与列表传参

当进行多列排序时，Pandas 的仲裁逻辑有着极其严格的物理先后次序：

```text
原始乱序数据行
      |
      v
第一排序维度 (如: 单价) ------------------------+
      |                                        |
      +---> 单价互不相同?                        |
      |         |                              |
      |         +--> [YES] 直接确定该行最终排位  |
      |                                        |
      +---> 单价完全相同?                        |
                |                              |
                +--> [YES] 激活第二排序维度      |
                                 |             |
第二排序维度 (如: 销售数量) <------+             |
      |                                        |
      +---> 依据该列指定的升/降序决定同价商品的次序
```

在代码实现上，我们需要将参与排序的多个列名按照**优先级由高到低**封装为一个 Python 列表传递给 `by` 参数；同时，各个列专属的升降序规则也需封装为一个形状严格对应的布尔列表传递给 `ascending`：

```python
# 多列复合排序：单价升序（True），单价相同则销售数量降序（False）
df_multi_sort = df.sort_values(
    by=['单价', '销售数量'],
    ascending=[True, False]
)
```

此时执行输出，整体数据首先在全局尺度上呈现出单价由低到高的走势；而一旦定位到多件标价同为 `199` 元的商品时，局部区域会严格按照销售数量从大到小排列，完美满足了多层级业务优先级下钻的诉求。

##### 布尔值单标量广播简写技巧

在多列排序中，若各个维度的排序方向完全一致（例如先按单价升序、相同时再按数量升序；或者多列全部要求倒序），我们不需要繁琐地在列表中书写 `[True, True]` 或 `[False, False]`，Pandas 支持直接传入单个布尔标量：

```python
# 冗长写法
df.sort_values(by=['单价', '销售数量'], ascending=[True, True])

# 等价的高效简写：单标量自动广播到参与排序的所有列
df.sort_values(by=['单价', '销售数量'], ascending=True)

# 全列降序简写
df.sort_values(by=['销售数量', '订单日期'], ascending=False)
```

这种简写极大精简了复合排序的代码量，在构建复杂业务管道时十分清晰利落。

## Pandas 数据分组聚合与 Matplotlib 可视化基础
> 对应块：BLK24 | 覆盖分集：P147-P148 | 块标题（分集名）：《147. 数据分析-Pandas基础-数据分组》

如果我们要对页面上一大堆图标进行归类，最直观的办法就是找特征：比如黑色的图标分到一组，红色的图标分到另一组；或者把粗线条构成的图标归为一组，细线条的归为另一组。把东西分好组之后，我们自然就会去做进一步的统计——数一数粗线条图标一共有多少个，细线条图标又有多少个。在数据处理中，这个过程就叫分组与统计计算。

我们在数据分析中面对海量原始表格时，核心需求往往不是看单条记录，而是按照业务维度对数据进行切分，进而计算各维度的汇总指标。完成计算后，单纯的数字报表往往不够直观，必须将冰冷的数据转化为可视化图表，为业务决策提供支持。

### 数据分组与聚合计算原理

数据分组本质上就是按照数据的某一个或某几个特征，将整张数据表拆分成不同的子集，随后针对每一个子集独立执行统计计算，最后将计算结果整合输出。

```text
原始数据集 (DataFrame)
┌───────────────────────────────────────────────┐
│ 订单号   产品类别   销售数量   单价   城市    │
│  001      食品         2        19    北京    │
│  002      图书         1        29    上海    │
│  003      食品         3        25    广州    │
│  004      服装         1        99    深圳    │
└───────────────────────────────────────────────┘
                       │
             按「产品类别」拆分 (Split)
        ┌──────────────┼──────────────┐
        ▼              ▼              ▼
  ┌───────────┐  ┌───────────┐  ┌───────────┐
  │ 食品组    │  │ 图书组    │  │ 服装组    │
  │ (2条记录) │  │ (1条记录) │  │ (1条记录) │
  └─────┬─────┘  └─────┬─────┘  └─────┬─────┘
        │              │              │
        ▼              ▼              ▼
   计算求和/均值  计算求和/均值  计算求和/均值 (Apply)
        │              │              │
        └──────────────┼──────────────┘
                       │
             合并统计结果 (Combine)
                       ▼
         ┌─────────────────────────┐
         │ 产品类别   计算汇总指标 │
         │   食品         ...      │
         │   图书         ...      │
         │   服装         ...      │
         └─────────────────────────┘
```
上图展示了 Pandas 中经典的分组计算流程：先依据指定列的类别标签将数据拆分（Split），再对各个分组独立施加统计函数（Apply），最后汇总生成聚合报表（Combine）。

#### 特征分类与业务分组目标

在电商销售数据中，我们通常拿到的字段包括订单号、产品类别、销售数量、单价、客户所在城市等。如果我们要了解不同品类的经营状况，就需要按照「产品类别」进行分组。原始数据里的家居用品、食品、电子用品、图书、服装等记录，会被分别归拢到各自独立的组别中。

分组本身只是手段，业务分析的真正目的是在分组完成后进行的聚合计算。

#### 分组统计常见运算类型

在分组计算体系中，最常用的统计运算包含以下五类基础聚合操作：

| 统计类型 | 对应 Pandas 方法 | 功能说明 |
| :--- | :--- | :--- |
| 求和 | `sum()` | 计算分组内指定数值列的总和 |
| 计数 | `count()` | 统计分组内指定列的非空值数量 |
| 最大值 | `max()` | 提取分组内指定列的最大数值 |
| 最小值 | `min()` | 提取分组内指定列的最小数值 |
| 平均值 | `mean()` | 计算分组内指定列的算术平均值 |

### 基于 GroupBy 的单指标统计

在 Pandas 中执行数据分组的核心方法是 `groupby()`。我们可以通过传入单个列名或多个列名构成的列表来确定分组依据，并结合链式调用获取目标列并执行聚合函数。

以 `sales.csv` 文件为例，我们读取前 20 行样本数据进行测试：

```python
import pandas as pd

# 读取测试数据集的前 20 行
df = pd.read_csv('sales.csv', nrows=20)
```

#### 单列分组与全表聚合展示机制

当我们需要统计各个产品类别的订单数量时，可以直接使用 `groupby` 搭配 `count()`：

```python
df.groupby('产品类别').count()
```

如果直接这样调用，输出的表格会把原始数据集中除分组列之外的所有列（如订单号、销售数量、单价、客户所在城市等）全部展示出来，并在每一列下方列出该组对应的计数值。这是因为我们只下达了分组和计数的指令，并没有明确限定要对哪一列进行统计。

为了得到简洁的统计结果，通常采用方括号指定目标列：

```python
df.groupby('产品类别')['订单号'].count()
```

此时返回的是一个 Series 对象，清晰地列出了每个类别对应的订单总数。

#### 计数统计中缺失值的干扰与规避

在进行计数统计时，选择哪一列作为计算对象存在一个极易踩坑的细节。

如果在统计类别数量时，选用了包含缺失值的列，计算结果就会失真：

```python
# 观察不同列计数的结果差异
print(df.groupby('产品类别')['订单号'].count())
print(df.groupby('产品类别')['客户所在城市'].count())
```

在测试数据中，某一行（例如索引为 4 的记录）的「客户所在城市」字段为缺失值（NaN）。当针对「订单号」计数时，「食品」类别的统计结果为 5 条；但如果针对「客户所在城市」计数，「食品」类别的结果会直接变成 4 条。

> **易错点**：Pandas 的聚合计算函数在处理数据时，默认不将缺失值（NaN）计入统计。在需要统计记录行数或订单数量时，务必挑选主键列或确定无缺失值的字段（如订单号），或者在分组前先完成缺失值的填充清洗，否则会导致统计偏差。

#### 衍生列构建与求和计算

当业务需求是「统计各个产品类别的销售金额之和」时，直接查阅原始数据集会发现表中只有「销售数量」与「单价」，并不存在「销售金额」这一列。

此时不能直接分组求和，必须先在 DataFrame 中衍生出新列，然后再做分组聚合：

```python
# 1. 衍生计算销售金额列
df['销售金额'] = df['单价'] * df['销售数量']

# 2. 按照产品类别分组，并对销售金额求和
category_sales = df.groupby('产品类别')['销售金额'].sum()
```

在代码执行过程中，如果只写到 `df.groupby('产品类别')['销售金额']` 而没有调用 `.sum()`，控制台输出的会是一个 `SeriesGroupBy` 对象。这代表 Pandas 已经将指定列按照分组切分完毕，正处于等待执行聚合计算的中间态。随后调用的 `.sum()` 才是触发实际计算的操作。

#### 极值与均值指标计算

针对商品单价等指标，分析各品类的价格分布时，常用的操作是计算各组的最低、最高和平均单价：

```python
# 统计各类别商品的最低单价
min_price = df.groupby('产品类别')['单价'].min()

# 统计各类别商品的最最高单价
max_price = df.groupby('产品类别')['单价'].max()

# 统计各类别商品的平均单价
mean_price = df.groupby('产品类别')['单价'].mean()
```

每次调用独立的方法，Pandas 都会遍历各个分组并输出对应指标。但在实际业务中，如果每算一个指标就写一行 `groupby`，不仅代码冗长，且多次重复切分分组会带来不必要的性能开销。

### 多维聚合与高级聚合函数应用

为了在一个操作中同时输出多个统计指标，或者针对不同的数据列应用不同的聚合规则，Pandas 提供了通用的聚合方法 `agg()`（完整名称为 `aggregate()`）。

#### 单列多指标聚合计算

如果我们需要一次性获取各个类别商品单价的平均值、最大值和最小值，可以向 `agg()` 传入包含目标统计函数名的列表：

```python
# 单列多指标聚合计算
df.groupby('产品类别')['单价'].agg(['mean', 'max', 'min'])
```

执行后将返回一个结构清晰的 DataFrame，行索引为「产品类别」，列标签分别为 `mean`、`max` 和 `min`。列表内的函数名可以直接传入字符串形式的常用方法名。

#### 多列异构指标字典映射聚合

当分析维度变得更加复杂，例如需要同时统计：
- 各类别商品的「销售数量」总和；
- 各类别商品的「销售金额」总和；
- 各类别商品的「单价」平均值。

由于不同指标所依赖的列不同、所执行的计算逻辑也不同，此时不能在 `groupby` 后面指定某一个具体的列名，而是直接对 `groupby` 对象调用 `agg()`，并传入字典结构进行映射配置：

```python
# 异构多列多指标字典映射聚合
result = df.groupby('产品类别').agg({
    '销售数量': 'sum',
    '销售金额': 'sum',
    '单价': 'mean'
})
```

字典的键（Key）代表需要计算的目标列名，字典的值（Value）代表针对该列执行的聚合方法。这种写法同样支持对单个列指定多个计算函数，例如 `{'单价': ['mean', 'max', 'min']}`，具备高度的工程灵活性。

#### 聚合结果的数据结构转换

在数据分析管道的末端，计算结果除了用于表格展示外，往往还需要交付给下游接口、Web 视图或缓存数据库。通过链式调用 `.to_dict()` 方法，可以将聚合计算后的对象快速转换为 Python 原生字典：

```python
# 将分组统计结果转换为字典格式
result_dict = df.groupby('产品类别')['销售金额'].sum().to_dict()
```

转换后将得到键为产品类别、值为汇总金额的标准键值对结构，极大方便了业务系统的后续调用。

### 数据可视化与 Matplotlib 快速入门

通过数据筛选、清洗、分组与聚合计算后，我们拿到了规整的分析数据。然而，单纯由数字构成的二维表格在业务沟通与决策场景下并不直观。「一图胜千言」，将冰冷的数据转化为折线图、柱状图或散点图等直观形态，是数据分析不可或缺的一环。

#### 可视化工具定位与环境配置

在 Python 数据科学生态中，Matplotlib 是历史最悠久、使用最广泛且市场占有率最高的开源绘图库。无论是静态图表、动态交互视图还是出版级图表，Matplotlib 都能提供底层支持。

Matplotlib 属于第三方库，必须通过包管理工具显式安装：

```bash
pip install matplotlib
```

安装完成后，模块文件会被存放在 Python 环境的 `site-packages` 目录下。在代码中，我们最常用的是其子模块 `pyplot`，业内惯例将其导入并重命名为 `plt`：

```python
import matplotlib.pyplot as plt
```

#### 折线图绘制核心流程

绘制折线图的最小闭环由三部分构成：构建横纵坐标数据、调用 `plot()` 函数绘制、调用 `show()` 函数渲染。

```text
数据准备 (x 序列, y 序列)
           │
           ▼
    plt.plot(x, y)
           │
           ▼
       plt.show()
           │
           ▼
 弹出交互窗口或内嵌显示图表
```
上图总结了 Matplotlib 绘制基础图表的三步执行机制。

折线图的横轴为 x 轴，纵轴为 y 轴。每个数据点都是由 `(x[i], y[i])` 一一对应确定的二维坐标：

```python
import matplotlib.pyplot as plt

# 准备 24 小时的时间序列数据及对应数值
x = list(range(1, 25))
y = list(range(1, 25))

# 绘制折线图并展示
plt.plot(x, y)
plt.show()
```

#### 数据特征对折线形态的影响

在上面的基础代码中，当 x 轴取值为 1 到 24，y 轴取值同样为 1 到 24 时，渲染出的图形呈现为一条斜率固定的平滑斜直线，并没有出现折角。这是由于输入数据的变化率完全恒定所致。

为了模拟真实业务中随时间波动的指标（如每小时销售量、服务器负载等），我们引入随机数构造起伏波动的 y 轴数据：

```python
import random
import matplotlib.pyplot as plt

x = list(range(1, 25))
# 使用列表推导式生成 24 个在 [10, 14] 范围内的随机整数
y = [random.randint(10, 15) for _ in x]

plt.plot(x, y)
plt.show()
```

运行后，由于 y 轴数值的不规则起伏，图表呈现出标准的折线形态。

#### 坐标轴维度一致性约束与异常排查

在调用 `plt.plot(x, y)` 绘图时，存在一个硬性的底层校验规则：横坐标点集与纵坐标点集的元素个数必须完全相同。

如果数据源由于采集缺失或切片错误导致长度不匹配，程序会立即崩溃：

```python
# 错误示范：x 轴 24 个点，y 轴仅 23 个点
x = list(range(1, 25))
y = list(range(1, 24))

plt.plot(x, y)
```

运行上述代码将触发如下异常：
`ValueError: x and y must have same first dimension, but have shapes (24,) and (23,)`

> **注意**：`ValueError` 明确指出了两轴数据的「第一维度」（即数组或列表的长度）必须保持一致。在调用绘图函数前，检查输入序列的数据长度是排查此类图形渲染错误的必要步骤。

当前绘制出的折线图仅展现了数据走势，尚缺少坐标轴含义说明、标题与图例，属于未配置修饰项的简易图表原型。

  df['销售金额'] = df['单价'] * df['销售数量']
