## 第 1 章：核心语法-流程控制语句-if基础语法
> 对应分集：P22 | 原始标题：《22. 核心语法-流程控制语句-if基础语法》

先问一个问题：我们到目前为止写的所有 Python 代码，有什么共同点？

从 B 站的登录功能就能看出来。你输入账号和密码，点下登录按钮，程序执行登录操作。那它是一点击按钮就直奔 B 站首页吗？并不是。它要先判断账号和密码对不对：都是正确的，才走「进入 B 站首页」那一段；不正确，就走「提示错误信息」那一段，告诉用户用户名或密码错了。

那么，「进入首页」和「提示错误」这两段代码，是像我们以前那样从上往下一行一行执行下来的吗？不是。它得先看条件，条件决定走哪一段。

再看第二个场景。进入 B 站首页之后，那里的图片一直在循环播放，八九张图片播完一遍从头再来一遍，第二遍播完接着第三遍，这叫轮播图。又比如音乐播放器上的那个按钮，点一下是单曲循环，这一首放完了回头再放一遍；再点一下是列表循环。那么播放歌曲的那段代码，底层是不是一直在循环执行？

这两个场景指向同一件事：程序里的代码并不是只能顺着往下走，它可以被判断，也可以被循环。这就是数据的逻辑处理，在 Python 当中，它最核心的载体就是**流程控制语句**（control flow statement）。

> **定义**：流程控制语句用来改变代码自上而下的默认执行顺序。它包含三类：条件判断、模式匹配，以及循环。

这一小节只啃第一类里的开头——`if` 条件判断的基本格式。

### if 条件判断的语法格式

`if` 条件判断的适用场合是：**只有在满足指定条件时，才执行对应的代码逻辑**。B 站登录正好符合——只有在用户名和密码都正确的情况下，才执行进入 B 站首页那一段代码。

它的格式拆开看就是四件事：

```python
if 要判断的条件:
    条件成立时执行的代码
```

- `if` 是一个关键字；
- `if` 后面跟一个空格，空格之后写要判断的条件；
- 条件之后加一个冒号；
- 冒号下面写的代码，就是这个条件成立时所要执行的操作。

#### 条件部分

要判断的条件，它的判断结果必须是一个布尔值，要么 `True` 要么 `False`。

`True` 代表条件成立，程序就会去执行 `if` 语句下面那一行代码；结果是 `False` 就代表不成立，那么 `if` 下面的这块代码逻辑根本不会执行。

#### 缩进部分

接下来要把「这段代码属于 `if`」这件事表达出来，靠的是**缩进**。

缩进的空格数目本身不重要，一个、两个、三个、四个空格都能跑，但必须有缩进——有缩进才表示这是条件成立之后要执行的代码。

不过在 Python 的官方规范里，约定用**四个空格**。四个空格敲起来麻烦，可以直接按一下 `Tab` 键，PyCharm 会自动把它转成空格，而默认转换出来的正好就是四个空格。

> **提示**：在 Python 里，缩进不是排版偏好，而是语法本身。代码之间的层级关系、归属关系，全靠缩进描述。所以别在这里随性——统一四个空格，或者统一按 `Tab`。

#### 代码块

把 `if` 条件判断和条件成立之后要执行的这段代码合在一起，叫一个**代码块**（block）。所谓代码块，其实就是一个执行单元，一个独立的执行单元。

条件成立时要执行的语句可以不止一句。想执行两句，就在下面写两句，但每一句前面都得有缩进——只要前面有缩进，就表示这段代码属于这个 `if` 条件判断。

### 一个例子：分数超过 680 就去读清华

假设有这么一个需求：高考分数超过 680，我就去读清华。

先拆需求。要判断的条件是「高考分数超过 680」，条件成立时要执行的操作是「去读清华」。

代码这样写：

```python
# 定义高考分数
score = 700

# if 条件判断：分数大于 680
if score > 680:
    print('欢迎你来清华读书')
    print('也恭喜你即将踏入精彩的大学生活')
print('--------------------------------')
```

`score > 680` 就是条件，条件为 `True` 时，下面缩进的两句 `print` 就会执行。前面那句 `print` 顶格写、没有缩进，所以它**不属于** `if` 代码块。

> **易错点**：靠缩进判断归属，是这里最容易看走眼的地方。上例最后那句横线顶格，说明它独立于 `if`；如果它也缩进四个空格，那就变成「条件成立才画横线」，行为完全不同。

### 执行顺序的推演

把上例的运行过程拆开，能看清缩进划分出的边界：

```text
第 1 行  score = 700
第 2 行  if score > 680:
第 3 行      print('欢迎你来清华读书')        <- if 代码块
第 4 行      print('也恭喜你即将踏入精彩的大学生活') <- if 代码块
第 5 行  print('--------------------------------')  <- 独立语句，不属于 if
```

程序执行到第 2 行时判断条件是否成立。成立，就先执行 `if` 代码块里的第 3、4 行，执行完之后继续往下走到第 5 行；不成立，第 3、4 行整块跳过，直接执行第 5 行。

两种情况都印证了同一个结论：第 5 行那句横线，无论如何都会输出，因为它不属于 `if` 代码块。

> **结论**：`if` 只控制它代码块内部的语句执不执行，代码块之外的语句不受影响，照样按顺序往下走。

实际跑一遍对照一下就清楚了：分数写 700，条件成立，两句话和横线都输出；把分数改成 600，条件不成立，那两句话不输出，横线照样输出。

### 缩进不一致会怎样

一个必须亲眼见一次的问题：`if` 代码块里第一行缩进了四个空格，第二行多缩进了一个空格——立刻报错。

原因不难想。多缩进一个空格，在 Python 看来就意味着「这个语句属于上面那个语句的下级」，于是它认为你在 `print` 底下又开了一层代码，而这是非法语法。

> **易错点**：同一个代码块里的语句，前面的缩进必须**完全相同**。多一个空格、少一个空格都不行，Python 会直接抛 `IndentationError`。这也是新手在 `if` 上栽跟头最多的一处。

### 要点回顾

这一小节要明确两点。

第一，`if` 条件判断的基本格式：`if` 之后写要判断的条件，条件后面加冒号，下面写条件成立时执行的代码逻辑，且这部分前面要有缩进。Python 规范里缩进用四个空格，或者直接按一个 `Tab` 键让它自动转换成四个空格。

第二，`if` 语句涉及的注意事项，一共三条：

1. 判断条件的结果一定要是布尔值。为 `True` 代表成立，成立才执行里面的逻辑；不成立，里面的逻辑就不执行。
2. 结尾的冒号不能少。
3. 前面的缩进不能少。Python 通过缩进描述代码的层级关系与归属，规范建议用四个空格，或者直接按 `Tab`。

这三条记住了，`if` 的基本用法就不会出大问题。

## 第 2 章：核心语法-流程控制语句-if基础语法-案例
> 对应分集：P23 | 原始标题：《23. 核心语法-流程控制语句-if基础语法-案例》

上一节把 `if` 语句的基本语法过了一遍，语法本身不难，难的是拿到一个真实需求时，条件该怎么写。所以这一节我们一起做一个案例，把 `if` 条件判断用起来。

案例的需求是：模拟 B 站登录功能。输入账号和密码之后登录 B 站，其中正确的账号是 `18888888`，正确的密码是 `666888`。

这个案例会用上前面学过的输入与输出，再加上刚学的 `if` 条件判断，两块拼起来就能做出一个能跑的东西。

### 需求分析与操作步骤

先把登录的过程想清楚。输入账号和密码，点击登录按钮——这时候是直接登录成功吗？不是。点下登录之后要先做判断：用户输入的账号和正确的账号是否一致，用户输入的密码和正确的密码是否一致。

两个都对上了，登录成功，进入 B 站首页。

那么什么时候算登录失败？这里有个细节要抠准：**只要有任何一个错误就算失败**。不管是账号错了还是密码错了，只要其中有一个不对，统一算登录失败，然后给用户提示一条错误信息：账号或密码错误。

> **易错点**：失败的条件是「任一错误」，不是「两个都错」。账号错、密码对，也是失败；账号对、密码错，还是失败。这一点直接决定了后面用哪个逻辑运算符连接。

把过程落到操作步骤上，一共三步：

1. 通过键盘录入接收用户输入的账号和密码；
2. 判断账号和密码是否全部正确，都正确则登录成功，进入 B 站首页；
3. 判断账号和密码是否有错误，有任何一个错误则登录失败，提示错误信息。

代码就按这三步的顺序写下来。

### 正确账号与密码的保存

在开始接收输入之前，先把正确的账号和密码记录到变量里，后面判断的时候直接拿来比。

```python
# 正确的账号和密码
ok_account = '18888888'
ok_password = '666888'
```

变量名用了 `ok_account` 和 `ok_password`，两个单词之间用下划线分割。`ok` 标明这两个值是「正确的」那一份，跟用户输入的那份区分开——这个命名习惯在后面的判断里能帮你少绕一层弯。

### 第一步：接收用户输入的账号和密码

接收键盘输入用 `input` 语句，括号里给一句提示信息，再用变量接住返回的结果。

```python
account = input('请输入您的B站账号：')
password = input('请输入B站的密码：')
```

账号一个变量，密码一个变量，写法完全一样，只改提示语。

> **提示**：这里不需要像判断数字那样套 `int()` 做类型转换。账号和密码都是字符串，用 `==` 直接比较字符串是否相同就够了，转成数字反而会出问题。

### 第二步：判断账号和密码是否全部正确

判断就要用到 `if` 语句。条件是「输入的账号和正确的账号一致」，并且「输入的密码和正确的密码一致」。两个都要正确才代表登录成功。

比较相等用 `==`。输入的账号是 `account`，正确的账号是 `ok_account`，所以第一个条件是 `account == ok_account`；同理第二个条件是 `password == ok_password`。

这两个表达式之间用什么连接？第一个条件得成立，并且第二个条件也得成立，才代表登录成功——所以是 `and`。

```python
# 第二步：判断账号和密码是否全部正确，都正确则登录成功
if account == ok_account and password == ok_password:
    print('登录成功')
    print('进入B站首页')
```

条件后面记得加冒号，回车之后 `if` 代码块里的语句要有缩进。登录成功后要进入 B 站首页，所以代码块里输出两句。

### 第三步：判断账号和密码是否有错误

第三步判断的是「账号和密码有没有错」。如果错了就登录失败，并提示错误信息。

判断错误用的是不等于 `!=`：`account != ok_account` 说明账号是错的，`password != ok_password` 说明密码是错的。

这两个条件之间用什么连接？前面已经分析过，账号和密码有任何一个出错，就代表登录失败。第一个条件成立是失败，第二个条件成立也是失败——只要有一个符合要求整个就成立，所以这里用 `or`。

```python
# 第三步：判断账号和密码是否有错误，有任何一个错误则登录失败
if account != ok_account or password != ok_password:
    print('登录失败')
    print('账号或密码错误')
```

完整的代码，三步连起来是这样：

```python
# 模拟B站登录功能的实现
# 正确的账号和密码
ok_account = '18888888'
ok_password = '666888'

# 第一步：接收用户输入的账号和密码
account = input('请输入您的B站账号：')
password = input('请输入B站的密码：')

# 第二步：判断账号和密码是否全部正确，都正确则登录成功
if account == ok_account and password == ok_password:
    print('登录成功')
    print('进入B站首页')

# 第三步：判断账号和密码是否有错误，有任何一个错误则登录失败
if account != ok_account or password != ok_password:
    print('登录失败')
    print('账号或密码错误')
```

> **提示**：`account != ok_account` 和 `not account == ok_account` 表达的是同一件事。这一节选前者，是因为 Python 直接提供了 `!=` 这个比较运算符，写出来更短也更直观——需要「不相等」时优先用它。

### 运行测试

先输一个错误账号、正确密码，看两条判断各自怎么走。

输入账号随便来一串数字（一看就是错的），密码输 `666888`。回车之后 `account` 和 `password` 就接到了这两个值。

程序走到第二步：账号不正确，所以 `account == ok_account` 是 `False`；密码正确，所以 `password == ok_password` 是 `True`。由于用的是 `and`，两侧都是 `True` 结果才是 `True`，现在有一侧是 `False`，整个结果就是 `False`。条件不成立，第二步代码块里的语句不执行。

紧接着走到第三步：账号不正确，`account != ok_account` 是 `True`。由于用的是 `or`，有一个成立就是 `True`，整个条件成立——输出「登录失败」和「账号或密码错误」。

再输一组全对的：账号 `18888888`，密码 `666888`。第二步的两个条件同时成立，`and` 两侧都是 `True`，结果 `True`，输出「登录成功」和「进入 B 站首页」。而第三步的两个条件都不成立（账号密码都对，`!=` 两边都是 `False`），`or` 全部不成立结果才是 `False`，所以第三步的代码块不执行。

两次测试的结果刚好把两个运算符的判定规则各验证了一遍：

| 输入组合 | 第二步（`and`） | 第三步（`or`） | 输出 |
| --- | --- | --- | --- |
| 账号错、密码对 | 条件不成立 | 条件成立 | 登录失败，账号或密码错误 |
| 账号对、密码对 | 条件成立 | 条件不成立 | 登录成功，进入 B 站首页 |

这个案例的骨架并不复杂，但它同时用上了输入与输出、`if` 条件判断、关系运算符和逻辑运算符。把三步照着顺序写下来跑通，`if` 条件判断的语法和写法就基本拿在手里了。剩下的就是自己动手把它敲一遍。

## 第 3 章：核心语法-流程控制语句-if进阶(if...else)-案例
> 对应分集：P24 | 原始标题：《24. 核心语法-流程控制语句-if进阶(if...else)-案例》

上一节的 B 站登录案例跑通了，但代码里有一个地方值得回头再看一眼：我们写了两条 `if` 语句——第一条判断账号和密码是否都正确，都正确就登录成功；第二条判断账号和密码有没有错误，有任何一个错误就登录失败。

从功能实现上说，这么写没问题，跑起来结果也对。但换个角度想一个问题：**登录这件事，是不是不是成功就是失败？**

账号和密码都正确，登录成功；否则就是失败。要么成功要么失败，没有第三个选项。既然只有两种结果，那第二条 `if` 判断其实是可以省掉的——它的答案已经藏在第一条的条件里了。回头再看这段代码，确实略微繁琐，效率也不高。

这一节就来解决它，进入 `if` 条件判断的第二部分：`if` 语句的进阶用法。

### if...else 的结构与执行逻辑

把登录需求重新摆一遍：账号和密码都正确，条件成立，执行操作一，也就是进入 B 站系统首页；否则说明登录失败，执行操作二，提示一条错误信息。

针对这种「要么这个条件成立，要么不成立」的场景，可以用 `if` 配合 `else` 来实现。

```python
if 条件:
    条件成立时执行的代码
else:
    条件不成立时执行的代码
```

结构逐段看：

- `if` 后面跟上要判断的条件，这一部分和基本语法完全一样；
- 条件成立，执行 `if` 代码块里的语句；
- 条件不成立，程序就进入 `else`，执行 `else` 之后的代码。

`else` 可以理解为「否则」——否则我就执行下面这段逻辑。

> **定义**：`else` 之后**不写任何条件**。它执行的时机只有一个：`if` 之后的条件不成立。既然前面已经排除了条件成立的情形，剩下的情形就不需要再判断了。

这一点正是它比写两条 `if` 省事的原因。第二条判断做的事，本质上就是把第一条的反面重新验一遍，而 `else` 直接替你接管了这个反面。

### 用 if...else 优化登录代码

前面接收输入和正确账号密码的部分都不用动，要改的是后半段的判断。

原来第二、第三步是两条独立的 `if`；现在第二条 `if` 不再需要，改成 `else`。

```python
# 模拟B站登录功能的实现
# 正确的账号和密码
ok_account = '18888888'
ok_password = '666888'

# 第一步：接收用户输入的账号和密码
account = input('请输入您的B站账号：')
password = input('请输入B站的密码：')

# 第二步：判断账号和密码是否全部正确，都正确则登录成功，否则登录失败
if account == ok_account and password == ok_password:
    print('登录成功')
    print('进入B站首页')
else:
    print('登录失败')
    print('账号或密码错误')
```

`else` 后面不用写任何条件，直接跟一个冒号就够。

> **易错点**：`else` 后面也必须有冒号，但冒号前面不能写条件。写成 `else account != ok_account:` 是语法错误——`else` 接受不了条件，它接管的正是「条件不成立」这个默认分支。

`else` 之后的代码同样要靠**缩进**来表示归属，前面必须有缩进，`else` 才知道这两句是它的代码块。

运行验证两次即可。输入错误账号 `99999` 和正确密码 `666888`，回车后判断账号和密码是否正确，明显账号不正确，`if` 条件不成立，程序直接进入 `else`，输出「登录失败」「账号或密码错误」。

再运行一次，输入正确的 `18888888` 和 `666888`，条件成立，输出「登录成功」「进入 B 站首页」。

对比两种写法：优化后少了整整一次条件判断。条件只有两种结局时，用 `if...else` 比堆两条 `if` 更准确，也更省。

### 闰年判断案例

第二个案例：根据用户输入的年份，判断这一年是闰年还是平年。

闰年的规则有两条：

1. **非整百年份**，且能被 4 整除的是闰年。比如 2025 年就是非整百年份。
2. **整百年份**，必须能被 400 整除才是闰年。整百年份指的是 1900 年、2000 年这样的年份。

> **提示**：第二条规定里没有单独再写「能被 100 整除」这一句，但它是自动满足的——一个数如果能被 400 整除，它必然也能被 100 整除，所以能被 400 整除的年份一定是整百年份。

需求很清楚：闰年输出这一年是闰年，不是闰年就输出平年。而一个年份要么是闰年要么是平年，二选一，所以这里用的正是 `if...else`。

#### 第一步：接收年份

```python
# 根据用户输入的年份判断这一年是闰年还是平年
year = int(input('请输入需要判定的年份：'))
```

这里要参与算术运算，所以必须把键盘录入的字符串转成 `int` 类型，否则没法做取余。

#### 第二步：构造闰年条件

条件是把两条规则连起来。第一条是「非整百年份且能被 4 整除」，先看它怎么判断。

**非整百年份**怎么判断？回想算术运算里的求模（也叫取余）操作。如果一个年份模于 100 的结果不等于 0，就说明它不是整百年份：

```python
year % 100 != 0
```

**能被 4 整除**怎么判断？一个数能被 4 整除，等价于它模于 4 的结果等于 0：

```python
year % 4 == 0
```

这两条之间是并且的关系，所以用 `and` 连接，这就是第一条规则：

```python
year % 100 != 0 and year % 4 == 0
```

第二条规则是整百年份能被 400 整除，直接写成模于 400 等于 0 就行：

```python
year % 400 == 0
```

#### 第三步：用 or 连接两条规则

现在的关键点是：这两组条件之间用什么连接？

满足第一条是闰年，满足第二条也是闰年。也就是说，**满足其中一个就是闰年**，所以它们之间用 `or`。

这里还有个结构上的细节值得说明。第一条规则里的两个条件（非整百年份、能被 4 整除）是一个整体——必须同时成立才构成「第一类闰年」。既然是整体，就用一对括号把它括起来表示：

```python
if (year % 100 != 0 and year % 4 == 0) or (year % 400 == 0):
    print(f'{year}年是闰年')
else:
    print(f'{year}年是平年')
```

括号在这里不影响运算结果，但它让「先算什么、再算什么」一目了然。第二个条件加不加括号都行。

> **易错点**：这一行条件复杂的是它的**结构**，不是符号。判断之前先把逻辑分层——「第一类闰年」和「第二类闰年」是两个并列的成立途径，用 `or` 连；每一类内部的条件是必须同时满足的，用 `and` 连。层级对了，括号自然就写对了。

### 四组测试

条件写得对不对，靠几组边界数据验一下就清楚了。

| 输入年份 | 条件推演 | 判定结果 |
| --- | --- | --- |
| 2025 | 非整百年份但模 4 余 1，两个条件都不成立 | 平年 |
| 1900 | 整百年份，且模 400 不等于 0 | 平年 |
| 2004 | 非整百年份，且模 4 等于 0 | 闰年 |
| 2400 | 整百年份，但模 400 等于 0 | 闰年 |

2025 年不能被 4 整除，也不能被 400 整除，两条规则都够不上，所以是平年。

1900 年是最容易想错的一个：它看着像个闰年，但它是整百年份，整百年份必须被 400 整除才算闰年，而 1900 不能被 400 整除，所以它是平年。

2004 年是非整百年份，能被 4 整除就够，所以是闰年。

2400 年同样容易误判：它是整百年份，但它能被 400 整除，符合第二条规则，所以是闰年。

### 要点回顾

两个问题要明确。

第一，`if...else` 的语法：`if` 之后写对应的条件，条件成立就执行 `if` 之后的代码逻辑；条件不成立，程序会自动执行 `else` 之后的代码逻辑。`else` 之后记得有冒号。

第二，`if...else` 的注意事项有两点：

1. `else` 之后不需要写任何条件。因为 `else` 的代码是在 `if` 条件不成立时才执行的，它不需要判断。
2. `else` 的代码前面必须加上对应的缩进，通过缩进来表示这块代码是 `else` 结构下的代码。

同一份需求，写成两条 `if` 还是写成 `if...else`，差别就在于有没有看清「这件事有几种结局」。只有两种结局时，`else` 就是那个不用再判断的分支。

## 第 4 章：核心语法-流程控制语句-if进阶(if...elif...else)-案例
> 对应分集：P25 | 原始标题：《25. 核心语法-流程控制语句-if进阶(if...elif...else)-案例》

前面留的四道练习里，第三道是这样的：让用户输入一个数字，判断它是正数还是负数。题目后面特意补了一句——**不考虑 0**。

「不考虑 0」这个前提很关键，它把问题简化成了两种结局：不是正数就是负数，用上一节的 `if...else` 就能写完。可是反过来想一下：**假如偏偏要考虑 0 呢？**

一旦把 0 请回来，需求的结局就从两种变成三种：大于 0 是正数，小于 0 是负数，剩下的情况是 0。这时候要考虑的条件也就变成了两个——「数字大于 0」和「数字小于 0」。

那 `if...else` 还够用吗？不够了。`if` 后面只能写一个条件：这个条件成立，就执行操作一；不成立，程序直接进入 `else` 执行操作二。整个结构里只有「成立」和「不成立」两个出口，而我们现在需要两个条件、三个出口。

所以这一节要学的，就是针对这种多条件判断需求的语法。

### 1 三分支需求与 if...else 的局限

把需求摊开，逐个条件看清楚：

| 条件 | 成立时的结论 | 需要判断吗 |
| --- | --- | --- |
| 数字大于 0 | 正数 | 需要，这是条件一 |
| 数字小于 0 | 负数 | 需要，这是条件二 |
| 以上都不成立 | 0 | 不需要再判断 |

第三行不用写条件，这一点和上一节 `else` 的道理一样：前面两个条件都没成立，剩下的可能就只有 0 了。

问题的症结在于，两个必须写的条件，`if...else` 装不下——它只给了一个条件的位置。

> **结论**：只要需求里的分支超过两个、判断条件超过一个，`if...else` 就撑不住了，需要靠 `if`、`elif`、`else` 这套语法来解决。

### 2 if...elif...else 的语法结构

先看结构：

```python
if 条件1:
    操作1
elif 条件2:
    操作2
else:
    操作3
```

三段的职责分别是：

- `if` 后面跟第一个条件，成立就执行操作一；
- `elif` 后面跟第二个条件，它是在 `if` 的条件不成立之后才有机会被判断的；
- `else` 不带条件，前面的条件全都不成立时执行它后面的逻辑。

`elif` 这个词的来历值得记一下：它的 `el` 就是 `else` 的简写，所以这个关键字读作 **else if**，写起来就是把 `else` 和 `if` 合成一个词。

`elif` 在这个结构里可以出现多次。业务上要判断几组条件，就写几个 `elif`，`if` 之后一个条件不够用，`elif` 后面可以继续跟条件，一个接一个排下去。而 `else` 是可有可无的：需要兜底就写，不需要就省略。

### 3 执行流程与判断顺序

结构清楚了，还要知道程序究竟按什么顺序走。执行流程是这样：

```text
             判断条件1（if）
                   |
        True ------+------ False
         |                   |
     执行操作1         判断条件2（elif）
         |                   |
       结束         True ---+--- False
                      |            |
                  执行操作2    执行操作3（else）
                      |            |
                    结束          结束
```

读图要点：整个结构是一条**从上往下的单向通路**。

- 先判断条件 1。结果为 `True`，代表条件成立，直接执行操作 1，执行完整个流程就结束了——后面的 `elif` 和 `else` 一次都不会被执行；
- 条件 1 为 `False` 才会去判断条件 2。条件 2 成立，执行操作 2；执行完，后面的操作 3 也不会再执行；
- 条件 2 同样不成立，才会执行操作 3，也就是 `else` 里的逻辑。

也就是说，什么时候会执行第二步？只有第一个条件不成立的时候。什么时候会走到 `else`？只有第一个条件和第二个条件都不成立的时候。

> **提示**：判断是有顺序的，而且顺序就写在代码里——谁在上面谁先被判断。一旦某个条件成立，后面的条件连判断的机会都没有。

### 4 对齐与缩进规则

写这套结构时，缩进是最容易出错的地方，必须说清楚：`if`、`elif`、`else` 这三个关键字**顶格对齐**，它们是平级的，属于同一套结构。

> **易错点**：`if` 后面换行时，不要在缩进的位置去写 `elif`。一旦 `elif` 缩进进去了，它就和 `if` 不在同一层了，语义完全变了——`if`、`elif`、`else` 必须是水平方向对齐的一列。

关键字顶格，各分支内部的代码则统一缩进，靠缩进表示「这几行属于哪个分支」。这和前面 `if...else` 的规矩完全一致，只不过现在多了一层 `elif` 要照顾。

### 5 案例一：判断正数、负数与 0

按上面的结构来实现需求：先把用户输入的字符串转成整数，再依次判断。

```python
# 根据用户输入的数字，判断是正数、负数还是0
number = int(input('请输入数字：'))

if number > 0:
    print(f'{number}是一个正数')
elif number < 0:
    print(f'{number}是一个负数')
else:
    print(f'{number}是0')
```

逐句看这段代码在做什么：

- `int(input('请输入数字：'))`：`input` 收回来的是字符串，要参与大小比较必须先用 `int` 转成整数；
- `if number > 0`：第一个条件，成立就输出这个数是正数；
- `elif number < 0`：第二个条件，只有第一个条件不成立时才会执行到这里；
- `else`：前面两个条件都不成立时，剩下的结论就是 0。

运行三次，三种分支各走一遍：

| 输入 | 判断过程 | 输出 |
| --- | --- | --- |
| 5 | 5 > 0 成立，不再看 elif 和 else | 5 是一个正数 |
| -1 | 第一个条件不成立，判断第二个条件 -1 < 0 成立 | -1 是一个负数 |
| 0 | 两个条件都不成立，进入 else | 0 是 0 |

输入 5 时，第一个条件成立，`elif` 和 `else` 连碰都没碰；输入 -1 时，必须先看着第一个条件失败，才轮到第二个条件；输入 0 时，两个条件挨个失败，最后落进 `else`。

### 6 案例二：多套账号密码的登录

第二个案例又把登录功能搬回来了，但这次的要求不一样：用户名是 `admin`、密码是 `666888`，或者用户名是 `root`、密码是 `547527`，或者用户名是「张三」、密码是 `123456`——这三种组合都算登录成功，其它一律提示用户名或密码错误。

为什么这题要用 `if...elif...else`，而不是上一节那种「都正确就成功、否则就失败」的写法？因为**合法的用户名和密码可以有多套**。一个系统里可能同时存在三组合法的凭据，只要用户输入的是其中任意一套，就算登录成功。判定对象从「一组条件」变成了「一组一组往下试」。

实现如下：

```python
# 根据输入的账号和密码进行登录，多套账号密码均合法
username = input('请输入用户名：')
password = input('请输入密码：')

if username == 'admin' and password == '666888':
    print('登录成功1')
elif username == 'root' and password == '547527':
    print('登录成功2')
elif username == '张三' and password == '123456':
    print('登录成功3')
else:
    print('登录失败，用户名或密码错误')
```

几点说明：

- 用户名和密码必须**同时**匹配才算这一套凭据正确，所以用 `and` 把两个等值判断连起来；
- 字符串统一用引号括住，`username` 与 `'admin'` 之间是相等比较；
- `elif` 在这里连着写了两次，正好印证了「`elif` 可以出现多个」——业务上有几套凭据，就写几个 `elif`；
- 三个分支都写输出「登录成功」也可以，只是测试时看不出究竟走了哪一条。所以这里特意写成「登录成功 1/2/3」，哪个分支被执行一眼就能认出来。

三次测试的结果：

| 输入用户名 / 密码 | 判定过程 | 输出 |
| --- | --- | --- |
| admin / 666888 | 第一个条件直接成立，后面不再判断 | 登录成功 1 |
| 张三 / 123456 | 前两个条件都不成立，第三个条件成立 | 登录成功 3 |
| aa / 111 | 三个条件全部不成立，进入 else | 登录失败，用户名或密码错误 |

### 7 关键要点

两个问题要明确。

第一，`if...elif...else` 的作用：用来做**多条件判断**。`if` 之后只能写一个条件，`elif` 后面可以继续跟上其它条件，而且 `elif` 可以出现多次——涉及多个分支判断时，用这套结构来构建。

第二，这套语法的三条注意事项：

1. `elif` 可以写多个，需要几组条件就写几个；
2. `else` 可有可无；如果要写，必须放在最后；
3. 条件判断是有顺序的，会从上往下依次判断。前面某个条件一旦成立，它后面的条件就都不会再被判断和执行。

## 第 5 章：核心语法-流程控制语句-if语句-综合案例
> 对应分集：P26 | 原始标题：《26. 核心语法-流程控制语句-if语句-综合案例》

`if` 条件判断的核心语法到这里已经学完了，剩下的功夫在于把语法用顺。所以这一节一起完成一个案例，用它把前面学过的 `if`、`if...else`、`if...elif...else` 全部串一遍，同时带出一个新东西——`if` 的嵌套。

案例的需求是：根据输入的三角形三个边的边长，判断这个三角形是**等边三角形**、**等腰三角形**、**普通三角形**，还是说这三条边压根就构不成一个三角形。

### 1 两条判定规则

动手写代码之前先回忆一件事：构成一个三角形的条件是什么？这是小学数学里的内容，条件就一条——**任意两边之和要大于第三边**。只要不符合这条，三个边长就凑不出三角形。

如果三个边长能构成三角形，接下来再判断它的类型，规则有三条：

| 边长关系 | 三角形类型 |
| --- | --- |
| 三个边都相等 | 等边三角形 |
| 其中有两个边相等 | 等腰三角形 |
| 三个边都不相等 | 普通三角形 |

> **结论**：判定要分两步走，而且顺序不能颠倒——先确认「能不能构成三角形」，能构成才有资格去谈「是哪种三角形」。反过来先判类型就没有意义了。

### 2 接收三条边长与多行注释

第一步先把三个边长读进来，变量分别叫 `a`、`b`、`c`。题目给的输入是正整数，所以直接把键盘录入的字符串转成 `int` 就能参与后续的算术比较。

```python
# 第一步：接收输入的三角形三个边的边长
a = int(input('请输入第一个边的边长：'))
b = int(input('请输入第二个边的边长：'))
c = int(input('请输入第三个边的边长：'))
```

顺手把注释这件事补完整。之前用的是井号 `#`，那是**单行注释**，注释掉的是它所在的那一行。想注释多行，就在每一行前面都加一个井号；在开发工具里按 `Ctrl` 加斜杠可以快速给选中的代码行加上或取消注释。

但大段文字注释用井号一行一行加太笨，所以还有第二种写法：**三引号注释**。

```python
"""
这里是一段多行注释。
三引号把它括住的内容整体注释掉。
"""
```

三引号其实就是之前定义字符串的第三种方式。区别在于：如果前面用变量把它接住了，那它就是一个字符串；如果前面没有变量接收，那它就是一段多行注释。以后遇到整段的文字说明，用三引号来写，注释的结构会清晰很多。

### 3 构成三角形的完整条件

判断能不能构成三角形，条件就是「任意两边之和大于第三边」。注意「任意」两个字，它意味着不能只写一组比较：

```python
if a + b > c and a + c > b and b + c > a:
```

三组比较的必要性可以用一个反例说明。假如只写 `a + b > c`，它保证的仅仅是 `a` 与 `b` 之和大于 `c`，`a` 与 `c` 之和是否大于 `b` 完全没有被约束。边长取 10、5、3 就是这种情况：5 加 3 等于 8，小于 10，这三条边拼不成三角形，但只看 `a + b > c` 是看不出问题的。

三组两两组合必须**同时成立**，所以它们之间用 `and` 连接。

> **易错点**：写这个条件时最容易漏掉第三组 `b + c > a`。自检的办法很直接——三条边两两组合，一共就三组，凑不够三组就是漏写了。

### 4 用 pass 占位保证结构完整

条件写好了，但「条件成立后要做什么」——也就是判断具体类型——还没动手写。这时候不能把它空着：`if` 下面必须要有具体语句，否则代码结构就是残缺的。

Python 为此提供了空语句 `pass`，它什么都不做，只负责**语法占位**，用来保证代码结构的完整性。先把它填在那里，等逻辑想清楚了再回来替换：

```python
if a + b > c and a + c > b and b + c > a:
    pass  # 待补全：条件成立时判断三角形的具体类型
else:
    print(f'{a}、{b}、{c}这三条边不能构成三角形')
```

`else` 分支对应的是「条件不成立」，也就是三个边长构不成三角形，直接给出提示即可。

### 5 嵌套 if 判断三角形类型

类型判断要写在 `pass` 的位置上：条件成立，说明能构成三角形，紧接着就要判断它属于哪一种。判断依据是三个边之间的关系，这又是一次条件判断，所以把那句 `pass` 删掉，换成**内层的 `if`**。

先判断等边：三个边都相等，也就是 `a` 等于 `b`，并且 `b` 等于 `c`——`a == b and b == c` 成立，三个边自然都相等。

等边不成立，接着判断等腰：**任意两个边相等**即可，所以用 `or` 连接三组两两比较，`a == b or b == c or a == c`。

> **提示**：写等腰条件时，开发工具补全出来的是 `and`，要留意别顺着它写下去。等边要求三组全相等，等腰只要求有一组相等，「任意」对应的是 `or` 而不是 `and`。

最后一条 `else` 不需要再写条件：前面两个条件都不成立，剩下的可能就只有「三个边都不相等」，那就是普通三角形。

```python
# 第二步：判断三角形的类型
if a + b > c and a + c > b and b + c > a:
    if a == b and b == c:
        print(f'{a}、{b}、{c}这三条边构成了等边三角形')
    elif a == b or b == c or a == c:
        print(f'{a}、{b}、{c}这三条边构成了等腰三角形')
    else:
        print(f'{a}、{b}、{c}这三条边构成了普通三角形')
else:
    print(f'{a}、{b}、{c}这三条边不能构成三角形')
```

这段代码出现了**嵌套**：外层 `if` 的条件成立之后，里面执行的又是一整套条件判断。整个结构长这样：

```text
外层判断（三条边能否构成三角形）
├── 成立   -> 内层判断（三角形的类型）
│             ├── 三个边都相等    -> 等边三角形
│             ├── 任意两个边相等  -> 等腰三角形
│             └── 以上都不成立    -> 普通三角形
└── 不成立 -> 这三条边不能构成三角形
```

嵌套写起来不难，难的是缩进别乱。缩进的规矩只有一条：**属于同一套结构的 `if` 和 `else`，前面的缩进必须完全一致**。内层的 `if`、`elif`、`else` 三者缩进对齐，它们是一套；外层的 `if` 和 `else` 缩进对齐，它们是另一套。业务上有必要的话，内层的 `if` 里还能继续嵌套新的 `if`。

## 第 6 章：核心语法-流程控制语句-match模式匹配
> 对应分集：P27 | 原始标题：《27. 核心语法-流程控制语句-match模式匹配》

`if` 条件判断的核心语法已经用得很熟了，连 `if...elif...else` 这种复杂结构也写过好几遍。这一节看一个已经写好的案例：**根据输入的星期获取对应的工作日程**。

逻辑很直白。输入 1，第一个 `if` 条件匹配上，周一安排的是工作会议日；输入 4，条件从上往下走，匹配到第三个 `elif`，`day` 的值等于 4，于是拿到周四的代码审查日；输入 6 或者 7，一系列匹配之后落到「周末休息放松日」。

代码整整齐齐，读起来也不费劲。但仔细盯一会儿，会发现里面藏着一个问题。

### 1 等值匹配带来的重复条件

问题出在所有分支的匹配方式都是**等值匹配**——每一处都是 `day` 等于多少，形式一模一样。可 `if` 和 `elif` 后面要写的是条件表达式，表达式的结果必须是布尔值：`True` 代表条件成立，`False` 代表条件不成立。

那么问题来了：既然 `elif` 后面必须是一个完整的布尔表达式，`day ==` 这半截就**一个字都不能省**，只能一遍又一遍地重复写：

```text
if    day == '1'                 -> 周一：工作会议日
elif  day == '4'                 -> 周四：代码审查日
elif  day == '6' or day == '7'   -> 周末：休息放松日
```

判断的对象始终是同一个 `day`，真正在变的只是等号右边的值。一旦这类判断多了，重复代码就会堆起来，代码也变得繁琐。

Python 针对这类问题给了专门的方案——**结构模式匹配**。

### 2 match case 的语法与匹配流程

先认识一下这个概念。

> **定义**：结构模式匹配（structural pattern matching）是通过一个清晰的模板去精准地匹配数据的**结构**和数据的**内容**，匹配成功之后再执行对应的操作。

两个关键词都在这个名字和这句话里：**结构**和**模式**都要匹配——不仅能匹配数据的内容，也能匹配数据的结构。而它对应的语法就是 `match case`，其中 `match` 本身就是「匹配」的意思。

拿前面的工作日程案例来看它怎么简化条件编写。接收键盘录入那一步完全不变，变的是下面的判断部分：

```python
day = input('请输入星期几：')

match day:
    case '1':
        print('周一：工作会议日')
    case '4':
        print('周四：代码审查日')
    case '6' | '7':
        print('周末：休息放松日')
    case _:
        print('输入有误')
```

对比一眼就能看出差别：`case` 后面直接写要匹配的内容，**不再需要写 `day ==` 那半截重复的条件**。`case` 就是「情况」的意思，有多少种情况就写多少个 `case`。完整的案例里，`case` 从 1 排到 5 依次对应周一到周五的日程，接着是 `case 6 | 7`，最后是兜底的那一个。

整个匹配流程分两步：

```text
第一步：计算 match 后面表达式的值（这里是 day 的值）
        |
        v
第二步：从上往下，拿这个值依次和每个 case 后面的值比对
        |
        +-- case 1  匹配？-- 是 --> 执行该 case 的代码 --> 整个结构结束
        |                    |
        |                    否
        +-- case 2  匹配？-- 是 --> 执行该 case 的代码 --> 整个结构结束
        |                    |
        |                    否
        +-- case 3  匹配？-- 是 --> ...
        |                    |
        |                    否
        +-- case _  兜底执行
```

读图要点：匹配是**严格从上往下**的，一旦某个 `case` 匹配成功，执行完它里面的代码就结束，下面的 `case` 一个都不会再看。所以顺序也就是优先级，排在前面的 `case` 先被检查。

### 3 竖线、下划线与缩进

语法里有三个细节要拆开说。

**竖线 `|` 表示「或」**。`case '6' | '7'` 的意思是要匹配多项数据中的任意一个：`day` 的值是 6 或者是 7，都会匹配到这一个 `case`，执行同一段代码。这个符号在键盘上就在回车键的上面那个键——那个键的下档是反斜线，按住 `Shift` 再按它敲出来的就是竖线。

**下划线 `_` 表示匹配其他所有情况**。它同样从上往下参与匹配，前面所有 `case` 都没匹配上时，最后就落到它这里，把所有剩下的情况全部接住。

> **提示**：`case _` 里的下划线**不带引号**，就是光秃秃一个下划线。带上引号就变成了「匹配一个下划线字符」，含义完全不同。

`case _` 的作用相当于 `if` 条件判断里的 `else`：都是给前面所有条件兜底。它同样是可有可无的，可加可不加。

**缩进**方面：所有 `case` 都在 `match` 的下级，所以相对 `match` 都要缩进；这些 `case` 彼此之间缩进平齐，因为它们是同一级的。这和 `if`、`elif`、`else` 的规矩是一个道理。

### 4 用 match case 改写工作日程匹配

把上面的代码放进开发工具里跑，为了看清每一步匹配到了哪里，这次用**断点调试**来跟踪：在 `match day` 那一行（第 4 行）打个断点，然后以调试模式运行，输入一个星期数。

> **易错点**：工具栏上的小昆虫按钮会运行**上一次运行过的文件**。新建的脚本如果一次都没运行过，直接点小昆虫跑的还是旧文件。第一次要用调试模式跑新文件，得在文件编辑区右键，选择以调试模式运行。

测试结果：

| 输入 | 断点处看到的 day | 匹配过程 | 输出 |
| --- | --- | --- | --- |
| 4 | 字符串 `'4'` | 1 不是、2 不是、3 不是、4 匹配上 | 周四：代码审查日 |
| 7 | 字符串 `'7'` | 前几个都落空，命中 `case '6' \| '7'` | 周末：休息放松日 |
| 9 | 字符串 `'9'` | 1 到 7 全部匹配不上，落到 `case _` | 输入有误 |

每次按 `F8` 往下走一步，就能看到匹配指针在一个个 `case` 之间移动。输入 4 时命中 `case '4'` 之后，再往下走就直接跳出整个结构了——后面的 5、6、7 和 `case _` 都没有参与匹配，这一点和 `if...elif...else` 的短路行为完全一致。

> **提示**：`input` 收到的永远是字符串，所以 `case` 后面匹配的字面值也要写成带引号的形式（`'4'` 而不是 `4`）。调试面板里 `day` 的类型是字符串，正是这个原因。数字本身要参与匹配，得先做类型转换。

### 5 案例：基于 match case 的简易计算器

第二个案例是一个**简易计算器**，用 `match case` 实现加减乘除四则运算。用户输入要计算的两个数以及运算符，程序根据运算符执行对应的计算——所以要接收三个键盘录入。

两个操作数用 `float` 接收，因为要支持浮点数运算；运算符用字符串接收。判断部分拿运算符去匹配：

```python
number1 = float(input('请输入第一个数：'))
number2 = float(input('请输入第二个数：'))
oper = input('请输入运算符（+ - * /）：')

match oper:
    case '+':
        print(f'{number1} + {number2} = {number1 + number2}')
    case '-':
        print(f'{number1} - {number2} = {number1 - number2}')
    case '*':
        print(f'{number1} * {number2} = {number1 * number2}')
    case '/':
        print(f'{number1} / {number2} = {number1 / number2}')
    case _:
        print('操作不支持')
```

四个 `case` 分别匹配四个运算符，各分支的逻辑框架完全一样，只是符号不同，所以写完第一个之后复制改符号就够了。填逻辑之前也可以先用 `pass` 占位，把结构搭好再逐个补内容。

`case _` 在这里是必须留心的一个分支：运算符是用户手动输入的，万一敲进来一个「+ - * /」之外的符号，四个 `case` 全都匹配不上，最后就落到 `case _` 给出「操作不支持」的提示。

输出语句里有两个加号，含义完全不同，值得单独看一眼：

```python
print(f'{number1} + {number2} = {number1 + number2}')
```

- 第一个加号在 `{}` 之外，它是**字符串内容**的一部分，会被原样打印出来；
- 第二个加号在 `{}` 之内，它是**算术运算符**，参与的是 `number1 + number2` 的求值。

`number1`、`number2` 在字符串里是占位符，会被对应变量的值替换掉，所以最终打印的是「10.0 * 5.0 = 50.0」这样的结果——两个数都是 `float`，所以 `10` 会显示成 `10.0`。

### 6 除零问题与 case 条件守卫

乘法、除法都跑得通，但除法有一组数据会出事：输入 10、0，再做除法，程序直接报错 `division by zero`。

> **提示**：除法里 0 不能充当**除数**。形如 `10 / 0` 的表达式里，10 是被除数（写在除号左边），0 是除数（写在除号右边）；非法的是除数位置上的 0。这里 0 又是用户输入的 `number2`，等于把除数的位置交给了不可控的输入。

从需求角度看，`number2` 为 0 再做除法，本来就该算「不支持的操作」。那怎么让程序自己识别出来？

反过来说更容易想清楚：`/` 这个 `case` 要想匹配成功，前提必须是 `number2` 不等于 0；一旦 `number2` 为 0，这个 `case` 就应当匹配失败，让程序继续往下走，最后落到 `case _`。

`match case` 支持在 `case` 的值后面再挂一个条件判断，条件成立才匹配这个 `case`：

```python
    case '/' if number2 != 0:
        print(f'{number1} / {number2} = {number1 / number2}')
```

挂上去的 `if number2 != 0` 就是普通的条件判断，和前面学过的一样。它的作用是给这个 `case` 加一道门槛：只有条件成立，才会拿 `/` 去匹配；条件不成立，这个 `case` 直接匹配失败，程序继续往下匹配 `case _`。

再测一次 10、0、`/`：断点跟踪下去，加、减、乘三个 `case` 本来就不匹配，走到除法时运算符确实是 `/`，但 `number2` 是 0，条件不成立，于是这个 `case` 也没匹配上，继续往下走到 `case _`，输出「操作不支持」。除零报错从此不会发生。

### 7 match case 与 if 的适用场景

看完这些，很容易产生一个想法：`match case` 好像可以替代 `if` 条件判断。这个想法要纠正——**两者不能互相替代，各有各的适用场景**。

| 语法 | 擅长的匹配方式 | 典型场景 |
| --- | --- | --- |
| `match case` | 变量匹配一些**固定值**（等值匹配） | 星期、运算符、指令这类枚举式的取值 |
| `if` / `elif` | 范围比较、复杂逻辑、多个条件的组合 | 判断区间、判断大小关系、用 `and` / `or` 拼条件 |

一句话概括：只要判断的是「这个变量的值等于哪一个固定值」，`match case` 就比 `if...elif...else` 干净得多；一旦要判断范围、要做大小比较、要组合多个条件，`match case` 就无能为力了，必须回到 `if` 上来。

> **注意**：`match case` 是 Python **3.10** 才开始提供的新语法，早期版本不支持，写之前先确认解释器版本。

### 8 关键要点

`match case` 的匹配动作可以总结成一句话：计算 `match` 后面表达式的值，然后按 `case` 的编写顺序从上往下逐个匹配；第一个匹配上了，后面的 `case` 就不再参与。

三个特殊操作要记住：

1. **`case` 后面可以加条件表达式**，只有条件成立，这个 `case` 才会拿自己的值去匹配；
2. **多个值可以并列匹配**，用竖线 `|` 连接，表示「或」——值是其中任意一个都算匹配；
3. **下划线 `_` 匹配其他所有情况**，作用相当于 `else`，且可有可无。

用 `match case` 能简化等值匹配里那些重复写出来的条件，但它替代不了 `if`，范围和组合条件仍然要靠 `if` 来做。

### 9 提到的题目与练习

课上两个案例（工作日程匹配、简易四则运算计算器）都已实现。课后有一道练习：**简单游戏指令系统的开发**。

需求是编写一个游戏角色控制系统，玩家输入不同的指令，控制游戏角色执行相应操作，操作结果直接输出到控制台：

- 玩家输入「上」，或者小写的 `w`，或者大写的 `W`，输出角色向上移动；
- 玩家输入「下」，或者小写的 `s`，或者大写的 `S`，输出角色向下移动。

解析思路就落在正文讲过的两个特殊操作用法上：每个方向要识别三种写法，属于「一个 `case` 匹配多个值」的情形，用竖线把它们并列在同一个 `case` 里即可；输入无法识别时，交给 `case _` 兜底。
