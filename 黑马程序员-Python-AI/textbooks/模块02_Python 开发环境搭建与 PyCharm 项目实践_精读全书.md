## 第 1 章：Python启航-环境准备-Python安装
> 对应分集：P03 | 原始标题：《03. Python启航-环境准备-Python安装》

知道了 Python 是一门编程语言之后，要想基于 Python 语言来开发应用程序，还需要把 Python 的运行环境准备好。环境准备分两部分：第一部分安装 Python 的解释器，第二部分安装并配置 Python 的开发工具。这一次先把解释器装上。

### 1. 为什么必须有解释器

Python 就是一门编程语言。所谓编程语言，是人类与计算机之间进行信息交流的一种语言。想让计算机帮我们做一些事情，就需要通过编程语言来描述需求、描述意图；我们这门课程要学的编程语言是 Python，所以就要通过 Python 代码来告诉计算机我们要做什么事、需求是什么、意图是什么。

但计算机底层只能够识别二进制当中的 0 和 1，它并不能直接识别我们所编写的应用程序，也就是不能直接识别 Python 代码。那怎么办？如果直接基于 0 和 1 来编程，第一个问题是学习难度极大，第二个问题是编程效率极低。

Python 官方为解决这个问题提供了一种翻译程序：把我们所编写的 Python 代码翻译成二进制的程序，再把二进制的程序交给计算机底层执行。

> **定义**：这个翻译程序有一个专业的名字，叫 **Python 解释器**（Python Interpreter）。它本质上就是一段翻译程序——输入是 Python 代码，输出是计算机底层能执行的二进制程序。

数据流向很直白：

```text
   人                 Python 代码              解释器               计算机底层
  ┌────┐  编写需求   ┌──────────┐   翻译    ┌────────┐   二进制   ┌────────┐
  │ 我 │ ─────────▶ │ print(…) │ ───────▶ │ Python │ ───────▶ │ 0 和 1 │
  └────┘             └──────────┘           │ 解释器 │          └────────┘
                                            └────────┘
```

读图要点：夹在人和机器中间的那一层就是解释器。它替我们把代码翻译成 0 和 1，所以我们开发时只需要专心写 Python 程序，不用去碰二进制。

因此，要想进行 Python 程序的开发、要想运行 Python 程序，就离不开 Python 的解释器。

### 2. 从官网下载安装包

Python 的解释器由 Python 官方提供，所以第一步是访问 Python 的官方网站，从官方网站下载解释器。

打开官网之后，页面上的 **Downloads**（下载）一栏右侧会显示与当前操作系统相关的 Python 版本，写作 `Download for Windows`——我当前是 Windows 系统，这里给出的版本是 **Python 3.14.0**，是前几天刚刚发布的最新版本。

#### 2.1 为什么不装最新版

课上不会使用刚刚发布的最新版本，原因有两点：

1. 最新版本刚发布，企业当中还没人用；
2. 由于刚发布，后面要用到的很多资源库还没有适配这个最新版本。

所以课上使用一个**次新版本**，比如 3.13.x。要找其他版本，可以点击下方那个链接，或者点击左侧的 **Windows**——我当前是 Windows 系统，直接点 Windows 就能查看所有 Windows 系统的安装包；如果用的是苹果电脑，点击下面的 **macOS** 即可。

进入 Windows 安装包列表后，会看到很多安装包：3.13.9、刚发布的 3.14、3.13.8、3.13.7、3.13.6……从中挑一个次新版本，就用 **3.13.9**。

> **提示**：这不是保守，而是省事。主力版本要的是生态——第三方资源库适配到位，`pip` 装什么都顺手；抢最新版最先遇到的往往不是新特性，而是某个依赖装不上。

#### 2.2 操作系统版本的下限

官方明确说明，Python 3.13.9 不能够用在 Win7 及之前的操作系统上。也就是说操作系统不能是 Win7，可以是 Win10、Win11。安装包列表里每个版本都有对应的说明，主流版本现在都不能用在 Win7 及之前的系统上。这一点要先确认清楚。

#### 2.3 按操作系统位数选安装包

3.13.9 下面有很多下载链接，选哪一个？原则是选择与操作系统版本匹配的安装包。

我的操作系统是 64 位，直接选第一个即可。绝大部分同学也都是 64 位的操作系统。要确认自己的系统信息：打开文件夹，在左侧找到 **此电脑**（或者直接在桌面上对"此电脑"点击右键），右键菜单里找到**属性**。

打开属性后能看到操作系统的信息，其中有一项叫**系统类型**。我当前是 64 位的操作系统，基于 x64 的处理器，所以下载安装包时直接选 `64-bit` 那一个。对应关系如下：

| 系统类型 | 该选哪个安装包 |
| --- | --- |
| 基于 x64 的处理器，64 位 | 选第一个 `64-bit` |
| 32 位操作系统 | 选下面那个 32 位安装包 |
| 基于 ARM 的处理器 | 选第三个安装包 |

> **结论**：绝大多数同学直接选第一个 64 位安装包即可；拿不准就先看"此电脑 → 属性 → 系统类型"。选错位数的包，装完跑起来会出各种莫名其妙的问题。

课程资料当中也提供了一份 Python 安装包，里面有两种版本，一种是 32 位，一种是 64 位，直接用其中的 64 位安装包即可。

### 3. 安装过程的每一步

拿到安装包之后，安装本身走这么几步。

#### 3.1 以管理员身份运行

直接运行这个 `exe` 文件即可，但运行的时候要记得选择**以管理员身份运行**，先获取管理员的权限。

#### 3.2 勾选 Add python.exe to PATH

安装程序打开后的第一步是勾选 `Add python.exe to PATH`，把这个勾给它勾上。勾上之后，稍后使用 Python 时就可以在任意目录下执行 Python 的命令了。

> **易错点**：这一项是安装过程中最容易漏掉、后果最麻烦的一步。漏勾之后并非装不上，而是 `python` 命令在命令行里认不出来，只能在安装目录下才能运行——等到发现时往往已经装好了别的工具，返工代价更大。

#### 3.3 选择自定义安装

紧接着选择下面的那一项——**自定义安装**，点击进入。

#### 3.4 默认项直接下一步

进入之后，这一步里面的所有信息都不用动，直接点击 `Next` 下一步。

#### 3.5 勾选 Install Python 3.13 for all users

到下一步，这里需要勾选一项：`Install Python 3.13 for all users`，即为所有的用户安装 Python 的解释器。把第一项勾选上。

#### 3.6 选择安装目录

勾选之后继续往下走，这里可以选择 Python 的安装目录。放在默认目录下安装也可以，但我一般会把所有与开发相关的软件单独放在一个自定义的目录下，比如 D 盘的 `develop` 目录。

操作方式是点击后面的 `Browse`（浏览），然后在里面找到**此电脑**、找到我的电脑、找到 D 盘。我的所有开发相关软件都会放在 `develop` 这个目录下——`develop` 就是开发的意思。这个目录下已经有很多软件了，每一个文件夹里面放的都是一个软件。在 `develop` 目录下点击新建文件夹，再创建一个文件夹，命名为 `Python`，用来存放 Python 的安装文件。选中这个 `Python` 之后点击确定。

这就代表：所安装的 Python 解释器会放在 D 盘 `develop` 下的 `Python` 目录下。

此时有一个必须注意的点：

> **易错点**：安装目录要放在一个**没有中文、不带空格**的目录下。例如 `D:\develop\Python`，既没有空格也没有中文。带中文或带空格的路径容易引发一些其他的微小问题，排查起来非常费劲。

如果选择默认目录安装，也要留意：Windows 用户目录默认是 `C:\Users\<用户名>`，一旦用户名是中文，路径里就混进了中文，这同样属于要避开的情况。

#### 3.7 点击 Install 并等待

接下来直接点击 `Install` 进行安装，这个过程大概持续几十秒，耐心等待。几十秒钟之后 Python 就安装好了，安装程序会提示已经成功安装，这时点击 `Close` 关闭窗口即可。

完整流程串起来是这样：

```text
  运行安装包（以管理员身份运行）
        │
        ▼
  勾选 Add python.exe to PATH      ← 漏勾会导致 python 命令不可用
        │
        ▼
  选择自定义安装 Customize installation
        │
        ▼
  默认项不动，直接 Next
        │
        ▼
  勾选 Install Python 3.13 for all users
        │
        ▼
  选择安装目录  D:\develop\Python   ← 无中文、无空格
        │
        ▼
  Install → 等待几十秒 → Close
        │
        ▼
  Win + R → cmd → 输入 python 验证
```

读图要点：从运行安装包到验证是一条单行道，中间的勾选项决定安装结果，只能在安装时决定，装完再想补救就得走卸载重装。

### 4. 验证安装是否成功

安装好之后，怎么验证 Python 是否成功安装？

在 Windows 上打开命令行：同时按下键盘上的 **Windows + R** 这两个键，打开"运行"窗口，输入 `cmd` 后回车，就打开了 Windows 的命令行。

然后在命令行当中输入 `python` 这个命令，回车。如果命令行当中能够看到 Python 的版本为 **3.13.9**，就说明 Python 已经成功安装了。

`python` 其实是安装好的 Python 解释器提供的命令。打开刚才的安装目录可以看到：D 盘下有 `develop`，`develop` 当中有 `Python`，在 Python 的安装目录下有一个 `python.exe` 可执行文件——在命令行里执行 `python` 这个命令，实际运行的就是这个可执行文件。

```bash
python
```

回车之后如果看到版本号为 3.13.9，安装就成功了。

此时会看到光标在命令行里闪动，等待着输入要执行的 Python 代码——这说明已经进入了解释器的交互状态，可以在这个里面编写并执行 Python 代码了。

### 5. 安装文档与注意事项

安装 Python 解释器的时候，可以参照这些步骤，也可以参照课程资料里给大家提供的这份安装文档——讲义当中有软件安装的文档，照着 Python 安装文档里面的步骤一步一步完成安装操作即可。

最后再强调一遍那个注意事项：作为一名专业的软件开发工程师，以后所有与开发相关的软件，尽量安装在一个没有中文、不带空格的目录下，避免因为中文、因为空格而引发其他的微小问题。

## 第 2 章：Python启航-环境准备-Python程序初体验
> 对应分集：P04 | 原始标题：《04. Python启航-环境准备-Python程序初体验》

Python 解释器已经装好了，接下来完成第一个 Python 程序——向世界说你好，也就是所谓的 **Hello World**。这是学习每一门编程语言的第一课，本质上就是在命令行当中输出我们想对世界说的话。

### 1. 解释器提示符的识别与进入

在命令行当中输入 `python` 这条指令，一敲回车，下面就会出现 Python 的版本号。

紧接着会看到光标在某个位置闪动，并且这一块出现了三个箭头（`>>>`），这就代表我们已经进入到了 Python 解释器里面。接下来就可以在这个命令行当中输入 Python 代码了。

### 2. print 语句与括号引号的写法

第一个程序要输出 `Hello World`。所谓输出 `Hello World`，就是把它输出到控制台，对当前来说也就是输出到命令行当中。

要写的这一行代码是：

```python
print("Hello World")
```

这一行代码由三个部分组成：

- `print`：打印的意思。这里的打印就是**输出**，把指定的内容输出到控制台当中，也就是输出到命令行当中；
- 一对**小括号**：紧跟在 `print` 之后，用来把要处理的内容括起来；
- 一对**引号**：在括号里面，用一对引号把要输出的内容引起来。这里要输出的是 Hello World，所以直接用它引起来。

> **易错点**：编程语言当中用到的括号、引号这些标点符号，全部都得使用**英文状态**下的符号。用了中文符号，执行是会报错的。

代码敲完一敲回车，下方就能看到输出的内容。想再输出一次别的，紧接着再写一行 `print("Hello Python")`，回车之后就能看到 `Hello Python`。

### 3. 退出解释器与两种命令行的区分

打印完毕之后，如果想退出到 Windows 的命令行，在下面直接输入 `exit`，后面跟上一对小括号，这就代表要执行退出操作——退回到 Windows 的命令行当中。

```python
exit()
```

怎么区分当前是 Python 解释器的命令行还是 Windows 的命令行？看前面这一块有没有那几个箭头：前面有箭头，说明是在 Python 解释器当中；前面显示的是具体的盘符，比如 C 盘下、D 盘下，说明是在 Windows 的命令行当中。

演示时的情形就是这样：退出之后提示符变成了 `C:\Users\Lenovo`，那代表已经回到了 Windows 的命令行。

### 4. 英文标点的实测对比

代码里的符号必须是英文，这一点值得当场验证一次。把输入法切换到中文，此时敲出来的标点就是中文标点；紧接着再敲一对中文字符下的括号，和英文的括号放在一起看，区别是看得出来的——中文括号明显更"宽"一些。

这个差别在语法层面上是致命的：括号、引号、逗号、冒号这些符号是语法的组成部分，中文符号不是 Python 语法的一部分，解释器只认英文的那一套。

### 5. 让中文输入法直接输出英文标点

既然中文输入法状态下也总是要敲英文标点，就有一个省事的做法：让输入法在中文模式下输入的标点符号也是英文的，把这个开关开启即可。

以搜狗输入法为例：

1. 在输入法的状态栏图标上**右键**，选择**更多设置**；
2. 进入设置后，在**常用**的设置当中往下走，找到**标点符号**；
3. 这里面有一个选项叫**中文时使用英文标点**，默认是关闭的，把它打开。

打开之后，在中文的模式下输入的也是英文的标点符号。验证方式很直观：切换状态时，状态栏后面那个符号指示代表当前用的是中文符号还是英文符号——显示的是点，就代表英文符号；中文、英文来回切换，它一直保持英文标点。

如果偶尔确实需要中文标点，临时切回去即可：把那个图标点一下，符号就从点变成了句号，代表现在使用的是中文标点。也可以按快捷键，鼠标移到上面会提示快捷键是 **Ctrl + 点**，按 Ctrl + 加号旁边这个点号键就能在中文、英文标点之间切换。默认都是英文。

### 6. 一行一回车的问题与 .py 文件

在命令行当中写 Python 代码时，每编写一行代码一敲回车，这行代码就自动执行了；再写第二行、再敲回车，第二行又自动执行。这种"敲一行、执行一行"的方式有个明显的不便：能不能把多行 Python 代码编写完毕之后一并执行？

做法是把多行 Python 代码定义在一个文件当中，也就是定义在一份 Python 文件当中。Python 文件通常来说后缀都是 `.py`，代表这是一个 Python 文件。文件写好之后，就可以通过一条命令来执行它——通过 `python` 这条命令执行这个 Python 文件，我们也叫 **Python 脚本**：

```bash
python hello.py
```

这条命令的含义是：执行 `hello.py` 这个文件当中的 Python 代码。代码里面如果有输出，就会把所有内容输出到下面的控制台当中。

### 7. 建一个 hello.py 并写入三行代码

动手过程如下。在桌面新建一个文件夹，命名为 `Python`；双击打开这个文件夹，在里面新建一个文本文件，也就是新建一个记事本；把它命名为 `hello`，然后注意后缀名需要改一下，改成 `.py`，所以完整文件名是 `hello.py`。

Python 文件其实就是一个文本文件，所以直接用 Windows 自带的记事本打开即可，要写什么 Python 代码直接在记事本里写。这一次写了三行：

```python
print("############################")
print("        Hello Python")
print("############################")
```

这三行代码构成一个简单的输出块：第一行和第三行打印两串井号，中间一行打印 `Hello Python`，上下两串符号把这个标题夹在中间，输出到控制台里就形成一块有边框的区域。

写入过程中的细节值得一提：现在敲出来的小括号就是英文的，因为并没有手动把标点符号改成中文——输入法已经默认让中文状态下也输出英文标点，不管是中文语言还是英文语言，都是英文的标点符号。

写完之后记得保存文件，按 **Ctrl + S** 保存。

### 8. 执行脚本时的路径问题与两种解决办法

保存完毕之后执行这个 Python 脚本。命令是 `python` 加空格，后面跟上 Python 文件的文件名，这里是 `hello.py`。

第一次直接执行 `python hello.py`，结果报错了，提示的意思是"没有这么一个文件或目录"——简单说就是这个文件没找到。

原因在于当前这个 Windows 命令行的磁盘路径。它默认的路径是 `C:\Users\Lenovo` 这个目录，而 `hello.py` 这个文件在 Desktop（桌面）目录下的 `Python` 文件夹当中，两个位置对不上，所以找不到文件。

> **定义**：命令行执行命令时，相对路径是相对于**当前工作目录**解析的，不是相对于文件实际存放的位置。当前工作目录由命令行的提示符显示，切换目录才能改变它。

解决这个问题有两种方案。

**方案一：用 `cd` 切换目录。**执行的命令是 `cd`，`cd` 就是切换目录的意思，后面跟上目标目录，把目录路径复制粘贴进去，回车。

```bash
cd C:\Users\Lenovo\Desktop\Python
python hello.py
```

切换之后再执行 `python hello.py`，之前写在文件里的三行 Python 代码就输出了三行内容，也就是脚本执行成功。

**方案二：在地址栏直接输入 `cmd`。** 这个方案更省事。思路是：我就想在这个目录下执行这个 Python 脚本。做法是在文件资源管理器上面的路径栏里，把里面的路径全部删掉，然后直接输入 `cmd` 并回车。

这样它就会在**当前目录**下打开命令行，也就是已经进到 Desktop 下的 `Python` 这个目录里了。此时再输入 `python hello.py` 回车，三行内容同样都输出了。

> **提示**：两种方案的差别只在于"谁来切目录"——方案一是自己敲 `cd` 切过去，方案二是让资源管理器把命令行直接开在这个目录里。日常敲代码时方案二更快，也不会敲错路径。

### 9. 让文件后缀名显示出来

还有一个注意事项：所有 Python 文件的后缀通常来说都是 `.py` 结尾的。但很多小伙伴的电脑看不到文件的后缀名——点之后的这一段就是后缀名。这时要做一项设置。

打开文件夹窗口，点击上面的**三个点**，找到**选项**；在选项里找到**查看**标签页；在查看当中找到并**取消勾选**这一项：**隐藏已知文件类型的扩展名**。

这一项如果处于勾选状态，看到的就是只有一个 `hello`，没有后面那个 `.py`；把配置项前面的勾去掉之后，点击**应用**、再点击**确定**，就能看到所有文件的扩展名了，也就是点之后的这个后缀。

> **易错点**：看不到扩展名的时候，容易以为文件已经叫 `hello.py`，实际上它的真实名字仍是 `hello.txt`——只是在资源管理器里被隐藏了尾巴。这时执行 `python hello.py` 必然报"找不到文件"，而问题根本不在命令上。

### 10. 两条必须记住的结论

整个初体验最后归到两条注意事项。

第一条：编写程序的时候，所有的符号均要使用英文的标点符号。如果使用的是中文的标点符号，在执行的过程当中是会报错的。

第二条：怎么运行 Python 文件？所谓 Python 文件指的就是以 `.py` 为后缀的文件。运行它的命令是 `python` 加空格，后面跟上 Python 文件的文件名；回车之后，它就会自动执行这个 Python 文件当中的所有代码。

```text
  交互模式                          脚本模式
  ────────────────────────          ────────────────────────
  命令行输入 python 进入            写好 hello.py（记事本）
  出现 >>> 提示符                   命令行执行 python hello.py
  敲一行、回车、立刻执行一行        回车后一次性执行文件内全部代码
  适合试一句、看一眼                适合成块的多行代码
  输入 exit() 退回                 执行完自动回到 Windows 命令行
```

读图要点：两种方式跑的是同一个解释器，区别只在于代码从哪里来——交互模式从键盘逐行输入，脚本模式从 `.py` 文件整体读取，这也正是"多行一并执行"的实现方式。

接下来就可以自己动手把这些步骤练习一遍。

## 第 3 章：Python启航-环境准备-常见问题解决方案
> 对应分集：P05 | 原始标题：《05. Python启航-环境准备-常见问题解决方案》

装完 Python 解释器，兴冲冲打开命令行敲下 `python` 回车，结果屏幕上跳出一行冷冰冰的提示：`python 不是内部或外部命令`。或者更奇怪——它不报错，反而自己弹出了微软商店，让你去下载一个 Python。

先说明一句：**这个问题绝大部分同学基本遇不到**。只有一小部分人会碰上，而碰上的原因几乎只有一个：安装 Python 解释器的那几步没有严格按照讲义里的步骤走。所以如果你在前面装解释器、跑第一个小程序时一路顺畅，这一节可以直接跳过，去学下一节；但既然它是新手最常见的第一个拦路虎，我们把它连同背后的机理一起讲透——搞懂了它，你就顺便搞懂了 Windows 上"命令到底是怎么被执行起来"的。

### 现象、成因与解决思路

#### 两种现象，其实是同一个原因

这些问题的表现分两种，取决于操作系统：

| 现象 | 典型系统 | 屏幕上的反馈 |
| --- | --- | --- |
| 直接报错 | Win10 | `python 不是内部或外部命令` |
| 跳到应用商店 | Win11 | 自动打开微软商店，引导下载 Python |

发现没有？两种现象都是执行 `python` 这条命令时**没有找到这条命令**导致的，区别只在于系统给出的"反馈形式"不同：Win10 老老实实告诉你找不到，Win11 则猜你想装 Python，干脆把你送到商店门口。可问题是——Python 我们明明已经装好了。

> **结论**：这两种现象本质是一件事：命令没找到。系统的版本只决定它用什么方式抱怨。

#### 为什么装了 Python 却找不到命令

原因落在安装时的一个选项上：安装向导第一步，界面最下方有一个复选框，作用是**把 `python.exe` 添加到 Path 环境变量当中**——这一步没有勾选，就会引发后面所有的麻烦。

简单说就是 Path 环境变量出了问题。至于 Path 环境变量到底是什么、为什么会决定一条命令能不能被找到，我们下面专门讲。

#### 两条解决路线

既然问题的根源是"当初忘了勾选那一项"，那解决思路自然也有两条：

1. **卸载重装**：简单粗暴，把 Python 解释器卸掉，重新装一遍，这次别忘了勾选。
2. **手动配置 Path 环境变量**：不重装，直接把缺的那份配置补上。

两条路都走得通，下面分别走一遍。

### 方案一：卸载并重新安装

先纠正一个很常见的坏习惯。作为专业的软件开发工程师，以后卸载软件**不要**在安装目录上右键、直接删文件夹——那样删不干净，注册表、安装记录、环境变量里都会留下残渣。

正确做法是走正规渠道：

1. 找到控制面板；
2. 点击「卸载程序」；
3. 列表里的软件按字母排序，找到 `P` 开头的 Python（一共两项），选中后点击上方的「卸载」；
4. 两项都卸掉，然后重新安装。

重新安装时，你自然就知道那一项必须勾选了。

### 方案二：手动配置 Path 环境变量

#### 环境变量的定义与作用

> **定义**：环境变量是操作系统当中存储的、用来指定应用程序运行时所需要的参数信息的那份配置。

它能装什么？应用程序运行时需要的临时文件夹位置、系统文件的访问位置、某些网站的访问凭证，这些信息都可以配置在环境变量里。应用程序跑起来的时候，只需要去读环境变量，就能拿到这些参数，而不必把这些信息写死在代码里。

我们要解决 `python` 无法执行的问题，就得手动配置环境变量。要配置它，先得知道它在哪儿。

#### 用户变量与系统变量的区别

入口不止一个，常用的两条：

- 打开「此电脑」→ 右键 → 属性（若菜单里没有「属性」，点「更多选项」就能看到）→ 打开系统信息页面 → 找到「高级系统设置」；
- 开始菜单里直接输入「系统」，找到控制面板当中的「系统」，点进去 → 「高级系统设置」。

在「高级系统设置」里点「环境变量」，会弹出一个窗口，里面是当前系统所有的环境变量。它被分成上下两部分：

| 分区 | 生效范围 | 说明 |
| --- | --- | --- |
| 用户的环境变量 | 仅当前登录用户 | 换个用户登录就不生效 |
| 系统环境变量 | 所有用户 | 与用户无关，谁都访问得到 |

为什么会有"用户"这一层？因为 Windows 也好、Mac 也好，装系统时默认都会创建一个用户。对个人电脑来说，通常就只使用这一个默认用户——比如我机器装好之后用户名就是 `lenovo`，那么上面那半区就是 `lenovo` 这个用户的环境变量。

> **结论**：上面那份只对当前登录用户有效，下面那份对所有用户生效。个人电脑只有一个用户，两处配置效果一样；多人共用的电脑就得想清楚配在哪一份。

列表里变量很多，其中大部分是软件在安装过程中自动配置好的。而在这些变量里，有一份特别重要，就是 `Path`——你会发现，**上面的用户变量区和下面的系统变量区，都有 `Path`**。

#### 命令的执行流程

先看现象怎么复现。按 `Win + R`，输入 `cmd`，回车打开命令行。这里我特意说明：在我重新安装 Python 的过程中，**我并没有勾选添加环境变量那一项**，所以此时执行 `python` 就会出问题。我这台是 Win11，它没找到 Python 命令，于是让我去下载解释器——可 Python 明明已经装好了。为什么它没找到？

要回答这个问题，得知道命令行执行一条命令时做了什么。

```text
在命令行输入一条命令并回车
        |
        v
  是系统内部命令？（如 cd）
     |            |
     是           否
     |            |
     v            v
  直接执行     在当前目录下查找该命令
                  |            |
                  找到          没找到
                  |            |
                  v            v
               执行它     到 Path 环境变量
                          配置的各个目录中查找
                              |          |
                              找到        没找到
                              |          |
                              v          v
                           执行它     报错 / 跳到应用商店
```

这张图就是命令行的命令解析流程：内部命令直接执行，外部命令先查当前目录，再查 `Path` 里登记的目录，全都落空才报错。注意 `Path` 在流程里所处的位置——它是外部命令查找的最后一道关口。

回到现场验证一下。当前目录是哪个？命令行里显示的是 `C:\Users\lenovo`——把这条路径粘进命令行回车，列出来的内容里并没有 `python` 这个文件。当前目录查完，一无所获，于是它转向 Path 环境变量。

那 `python` 这条命令本体在哪儿？它在 Python 的安装目录下：`D:\develop\python`，那个目录里躺着一个 `python.exe` 可执行文件，最终被执行的就是它。

于是关键问题变成：**Path 环境变量里登记了 Python 的安装目录吗？**

双击上面的 `Path`（用户变量）进入编辑模式，里面默认配置了不少目录，往下翻——有没有 Python 的安装目录？没有。再看系统变量里的 `Path`，双击打开，也没有 `develop\python` 这个目录。用户 Path 与系统 Path 里都查不到，命令自然执行不成功，于是出现了刚才的现象（Win11 版本的表现就是跳去商店）。

#### Python 安装目录与 Scripts 目录的添加

解决方式很直接：**把 Python 的安装目录加进 Path 环境变量**。

操作步骤如下：

1. 点击「环境变量」，找到 `Path`；
2. 上下两个 `Path` 在哪一个里配置？对我这台电脑来说，配上面或配下面都可以——因为我只有一个用户；而大家在安装 Python 时，默认配置的是上面那个（用户变量）；
3. 双击进入「编辑环境变量」，点「新建」；
4. 打开 Python 的安装目录 `D:\develop\python`，复制这个目录路径，粘贴进去；
5. 再点一次「新建」，粘贴 **`Scripts` 目录**的路径。

为什么 `Scripts` 也要加？因为那个目录下同样放着一些可执行文件，比如 `pip`——后面我们要安装各种依赖模块时会用到这个命令。少配它，Python 本体能用，装包的 `pip` 却用不了。

```bash
D:\develop\python
D:\develop\python\Scripts
```

这两条就是需要登记进 `Path` 的目录：前者提供 `python` 命令，后者提供 `pip` 等工具。

> **易错点**：只加 Python 安装目录、漏掉 `Scripts`，是最常见的半成品配置——当下 `python` 能跑了，等到装第三方库时 `pip` 又报"不是内部或外部命令"，你还得回来补一次。

#### 条目顺序与优先级

配置完路径，还有一步别漏：**把这两个目录「上移」到最前面**。

Path 里的条目是有顺序的，越靠前优先级越高，越靠后越低。如果系统里装了多个 Python，最前面那个会生效。所以我们要把刚加的两项挪到最前面。

改完之后，依次点击「确定」、「确定」、「确定」把三层窗口都确认掉。至此环境变量配置完毕——我这一共配了两项：Python 的安装目录，以及安装目录下的 `Scripts`。

#### 配置后的验证

验证时有个讲究：**不要在刚才已经打开的那个命令行窗口里验证**。

环境变量改完之后，需要重新打开一次 `cmd`，最新的环境变量才会生效。所以把旧窗口直接关掉，再按 `Win + R`、输入 `cmd`、回车，然后输入 `python`。

这一次 Python 命令正常执行了。道理还是那条流程：当前目录下没有这条命令，它就去 Path 环境变量里找；而 Path 里已经登记了 Python 的安装目录，安装目录下就有 `python.exe`，于是命令被找到并成功执行。

顺手输出一个 `Hello Python`，也没问题。

### 收尾：一条可检索的结论

出现这个问题的原因：安装 Python 时没有勾选"添加到 Path 环境变量"那个选项。

对应的两种方案：

| 方案 | 做法 | 配置要点 |
| --- | --- | --- |
| 卸载重装 | 控制面板 → 卸载程序 → 卸载 P 开头的两项 Python → 重新安装 | 重装时务必勾选"添加到 Path 环境变量" |
| 手动配置 | 高级系统设置 → 环境变量 → 编辑 Path → 新建两项并上移到最前 | 一项 Python 安装目录，一项其中的 `Scripts` 目录 |

环境变量的作用，一句话概括：**告诉系统，在命令行里执行一个命令时该从哪些目录去找可执行文件**；所以可执行文件所在的目录，就必须配置进 `Path`。

要把执行流程记牢，可以这样记：执行一条命令时，先判断它是不是系统内部命令——像 `cd` 切换目录这类，就属于内部命令，是内部命令直接执行完事；不是内部命令的，比如 `python`，就去 `Path` 环境变量里找；找到了就执行，没找到就报错——Win11 上表现为打开应用商店让你下载，Win10、Win7 上则告诉你"不是内部或外部命令"。

> **提示**：安装和使用都正常的同学，完全不需要去动 `Path` 环境变量，知道它是什么、什么时候会出问题就够了。

### 安装向导的逐步操作

资料里是一个 `.exe` 文件，双击运行安装程序，弹出用户账户控制时点「是」。接下来是官方安装向导，界面本身就是中文的，非常友好。

## 第 5 章：Python启航-入门程序
> 对应分集：P07 | 原始标题：《07. Python启航-入门程序》

Python 解释器和 PyCharm 都装好、测通了，环境准备这一关就算过完。接下来就用 PyCharm 亲手写出第一个 Python 程序——顺便把这款工具的基本用法摸一遍。

整个操作只有两步：**第一步打开 PyCharm、创建一个项目；第二步在项目里创建一个 Python 文件，然后在文件里写代码。**

### 创建 Python 项目

#### 新建项目时需要填写的信息

打开 PyCharm，聚焦到第一栏的项目菜单，点击中间的「新建项目」，弹出新建项目页面。这个页面上要填的信息不多，一项一项看。

**第一项：项目的存放位置。** 项目里会存放很多 Python 文件和代码，这些文件最终是落在磁盘上的，所以这一项指定的就是项目放在磁盘的哪个目录里。C 盘、D 盘下的某个文件夹都可以，最后那一级文件夹就是项目的名字——路径和名字都可以按自己的需要定义。

我把它放在 D 盘下而不是默认的 C 盘：在 D 盘根目录下新建一个文件夹 `python_project`，把项目放在这里面。以后可能会创建很多个 Python 项目，那就统一都放在这个文件夹下。选定文件夹之后，再在末尾指定项目名 `py_project01`。

**第二项：解释器类型。** 保持默认的「项目 venv」，也就是使用虚拟环境——虚拟环境后面会详细讲。

**第三项：Python 版本。** PyCharm 装好之后，启动时会自动加载本地已安装的 Python 解释器信息，这里确认无误即可。

确认之后点「创建」，项目就建出来了，顺手把窗口最大化。

#### 主界面的四个区域

进入主界面，先熟悉一下各区域的分工：

| 区域 | 内容 |
| --- | --- |
| 顶部菜单栏 | 右侧是最小化／最大化／关闭与设置，还有运行、调试运行的快捷操作；点击可展开主菜单——这些菜单功能后面随着课程推进会陆续用到，用到时再细讲 |
| 左侧功能栏 | 后续代码运行时的 Python 控制台、命令行终端、运行的服务，都在这里查看 |
| 项目区 | 当前项目的名字与磁盘路径，点一下「项目」可以折叠，再点一下又展开 |
| 右侧编辑区域 | 打开文件后，文件内容在这里显示 |

我的项目区里显示的是 `py_project01`，它放在 `D:\python_project` 下。项目创建好之后，工具还自动生成了一个目录（就是一个文件夹），里面存放的是这个 Python 项目的运行环境信息，这部分后面还会再讲。

### 创建 Python 文件与编写代码

#### 新建章节目录与 .py 文件

回到第二步。在项目上右键，选择「新建」（英文版是 `New`），后面可以指定要新建目录还是新建 Python 文件。

先建一个目录：现在讲的是第一章的内容，所以目录名就写「第一章」，回车。然后在「第一章」目录下右键新建，选择「Python 文件」，文件名写 `01 入门程序`。

> **提示**：之前用记事本写代码，得自己补上 `.py` 后缀；现在用了 PyCharm，创建 Python 文件时不用加后缀，它会自动加上。建完之后看文件名——后缀就是 `.py`，代表这是一个 Python 文件。

文件建好会自动打开，右侧编辑区里光标闪动，等着输入内容。

#### 用注释写下需求

需求很简单：往控制台里输出 `Hello World, Hello Python`。

我先把这句需求写进文件里。但要注意：这行文字本身**不是 Python 代码**，它是需求描述。我们并不想让 Python 解释器去运行它——它只起说明作用，给开发人员看，让人知道我们的需求是什么。所以要把这行文字注释掉。

> **定义**：注释是写给我们开发人员看的说明性文字，作用是解释说明代码、让开发人员更容易看懂需求与代码；Python 解释器在执行代码时会忽略注释。

注释的写法是在这一行最前面加一个井号 `#`，也就是「井号 + 往控制台输出 Hello World, Hello Python」。加上井号之后，这行文字就变成注释，解释器在执行这个文件时不会执行它。

手动敲井号当然可以，但有更快的办法：**光标停在这一行的任意位置，按下 `Ctrl + /`**，这行立刻被注释；再按一次 `Ctrl + /` 就取消注释。快捷键就是 `Ctrl + /`，记牢它。

写代码时还会发现一个问题：字体太小。PyCharm 默认字体偏小，可以临时用快捷键调大——按 `Shift + Alt + .`（句号）调大字体，按 `Shift + Alt + ,`（逗号）调小。我把它调到 16 号。字体的详细配置下一节会专门讲。

#### print 语句与自动补全

需求是往控制台输出内容，这一步之前在命令行里已经做过。现在直接写代码：

```python
print("Hello World")
print("Hello Python")
print("------------------------------")
```

在 PyCharm 里敲代码的感受和记事本完全不同——**有提示了**。敲一个 `p`，所有 `p` 开头的候选就都列出来了，问你是不是要输出，第一个就是 `print`。想让它自动补全，双击一下或者直接按回车，`print` 就生成了，括号也一起生成，光标停在括号中间等着输入要输出的内容。输入 `Hello World`，第一行完成。

第二行继续写 `print`，输出内容写上 `Hello Python`。

第三行我输出一条长横线，用来做分隔。

#### 换行与分号

这里有一条 Python 的规矩要讲清楚：**多行代码之间不用加分号**。

Python 里一行代码写完直接换行就行，通过换行符标识这行代码到这里就结束了，结尾不需要分号。但反过来，如果你想把两行代码写到同一行里，那就必须用分号把它们隔开。

> **易错点**：分号在 Python 里不是行尾结束符。绝大多数情况下我们都让一行代码占据一行，行尾那个分号不用加；只有把多条语句挤到一行时，才需要分号作分隔。

### 运行文件与查看结果

代码写完就可以执行了。在 PyCharm 里执行一个 Python 文件非常简单：在文件上右键，找到「运行 01 入门程序」，点击这一项，它就会自动运行这个文件。

有意思的是运行方式本身：PyCharm 这类集成开发环境在运行 Python 文件时，底层依旧是 `python` 加上空格、再跟上要运行的文件名——和我们在命令行里手敲的一模一样，只不过它替我们做了。

```bash
python 01 入门程序.py
```

上面这条就是工具在背后执行的命令：`python` 解释器加上要运行的文件路径。运行之后，下方区域能看到输出结果——`Hello World`、`Hello Python` 和那行分隔横线，三行内容都输出了。

### 小结与注意事项

把这一节需要明确的东西收拢成几条：

| 要点 | 内容 |
| --- | --- |
| Python 文件后缀 | `.py` |
| 什么是注释 | 对代码起解释说明作用的文字，给开发人员看；Python 解释器执行代码时会忽略注释 |
| 注释的写法 | 在行首加一个井号 `#`，井号开头的就是注释 |
| 注释的快捷键 | `Ctrl + /`，同时按下即可注释当前行，再按一次取消注释 |

最后两条注意事项，请一定记住：

- **编写代码时，所有的符号都要使用英文符号。** 再强调一次：中文全角符号是新手代码报错的头号来源。
- **Python 每一行结尾不需要加分号**，直接换行就代表这行代码结束；只有需要把多行代码合并到一行时，才用分号作分隔符。而绝大部分情况下我们都会让一行代码占一行，不会把多行合并，所以结尾的分号就不用加。

## 第 6 章：Python启航-入门程序-剖析
> 对应分集：P08 | 原始标题：《08. Python启航-入门程序-剖析》

入门程序跑通了，输出也正确，但项目里凭空多出来的两个文件夹还没解释过。点开项目一看：一个 `.venv`，还有磁盘上能看见、PyCharm 里却看不见的 `.idea`。它们是什么、能不能删、为什么要有——这一节把项目结构拆开看一遍，顺便把主题颜色和字体这两项基本配置做完。

### 项目目录结构剖析

#### 解释器类型与 .venv 目录的来源

回想创建项目时填的信息：除了项目位置，下面还指定了一项解释器类型。当时用的是默认值——「项目 venv」，含义是这个项目将会在**虚拟环境**中运行。

页面上还有一行小字做了说明：Python 的虚拟环境会在项目当中创建一个目录，也就是项目目录下那个 `.venv`，这个目录里存放的就是项目的虚拟环境。

> **定义**：虚拟环境（virtual environment，venv）是为单个 Python 项目单独建立的一套运行环境，项目运行所依赖的工具与文件都存放在该项目自己的 `.venv` 目录中。

到底什么是虚拟环境、这个目录具体在哪儿？到磁盘上看最清楚。在 PyCharm 里对着项目右键，选择「打开于」→「资源管理器」，就直接定位到了磁盘上的项目目录：路径是 `D:\python_project`，项目名 `python_project01`，双击进去看——

```text
python_project01/
├── .idea/            （PyCharm 里默认不展示）
├── .venv/            （项目的虚拟环境）
└── 第一章/            （存放我们的 Python 文件）
```

上图画的就是这个项目的目录结构：`第一章` 目录存放 Python 文件，另外两个目录各有一份职责，下面逐个说明。

#### .idea 目录：项目配置信息

先看 `.idea`。这个目录在磁盘上存在，但在 PyCharm 的项目视图里**默认不显示**。

它里面存放的是**项目的一些配置信息**。举个能直接验证的例子：我在 PyCharm 里把光标停在第六行，当前打开的文件是入门程序那个 `.py` 文件；然后把 PyCharm 关掉，下一次重新打开——光标依旧停在第六行闪动，依旧自动打开了那个文件。

这些状态记录在哪儿？就在 `.idea` 这个文件夹里。

> **提示**：`.idea` 里保存的项目配置信息我们一般不会去动。为了避免误操作，PyCharm 干脆不在项目视图里展示这个目录——不是它不存在，而是它不给你点。

#### .venv 目录与虚拟环境的隔离作用

再看 `.venv`，这就是虚拟环境目录，保存的是项目的一些**环境信息**。

现在对环境信息还没什么概念，举个例子就清楚了。假设要开发一个大型项目，这个项目依赖一些其他的工具或文件——那就可以把这些工具、这些文件都放在 `.venv` 当中。最终 `.venv` 这个虚拟环境对应的文件夹里存放的，就是当前项目运行时所需要依赖的那些工具和文件。

如果以后再去创建其他的 Python 项目，那么每一个项目里都会出现自己的 `.venv`，各自的 `.venv` 只服务于自己这个项目。

这么做的好处很实在：假设我在第一个项目里依赖了某个工具或某个文件，它**不会影响到其他的项目**，因为每个项目都有自己独立的虚拟环境。

```text
项目 A                       项目 B
├── .venv/  ← 依赖 X          ├── .venv/  ← 依赖 Y
└── 其他文件                  └── 其他文件

两个 .venv 各自独立，项目之间互不影响
```

这张图表示的是虚拟环境带来的隔离效果：每个项目运行在各自独立的运行环境里，一个项目装了什么、改了什么，都不会传到另一个项目去。

> **结论**：虚拟环境让每一个 Python 项目都运行在相对独立、彼此隔离的环境中，项目与项目之间互不影响、互不干扰。项目创建好之后，`.idea` 与 `.venv` 这两个文件夹下的东西不要动就可以了。

### PyCharm 基本配置

项目结构清楚了，接下来是工具本身的配置。这一块先讲两项：主题颜色的配置，以及字体大小、行高等相关信息的配置。

主题颜色在创建项目之前、PyCharm 刚装好时其实已经配过；如果那时候没配好，进入项目之后依然可以改。这两项配置的入口在同一个地方：点击右上角的**主菜单**，找到「设置」。

#### 主题颜色的配置入口

在设置里找「外观和行为」→「外观」，这里就是创建项目之前配置主题信息的地方。前面已经配好了，这里不用再动。

#### 字体大小、行高与配色方案冲突

接下来改编辑器里的字体。Python 文件里的字比较小，想调大一点，那就进设置找到「编辑器」，再找到其中的「字体」。

在这里能看到字体的各项配置：字体类型可以自己选，字体大小和行高也都能调。

但这里有个坑。之前调字体时，我不是在这里配的，而是用快捷键 `Shift + Alt + .` 调的——**快捷键改的其实是"配色方案"当中的字体**。所以打开这个界面会看到一行提示：当前编辑器字体是 14 号，使用的是配色方案中的字体。

此时如果你在这里把字号改成 16，点「应用」、点「确定」，会发现**它不起效**。原因就是刚才那行提示：通过快捷键调整的字体是在配色方案里定义的，而设置面板中默认让编辑器使用配色方案中的字体，配色方案的值把它盖住了。

解决办法是勾一下那个复选框：**不使用配色方案的字体**，改用这里定义的默认字体。把这个勾去掉之后，点「应用」，字体立刻变大了——此时生效的就是这里定义的 16 号。

#### 行高与字体类型的调整

字体旁边还有行高。看那六行代码，挤得非常紧凑，调一下行高就舒服了：设置为 1.5 倍，点「应用」，行与行之间明显稀疏了；再试 1.6 倍，差不多刚合适。这个数值按自己的需求调。

字体类型同样可以按喜好换。我选了一款叫 `Fira Code` 的字体，点一下、点「应用」，字体随即变化。

配置完点击「确定」收尾。到这里，编辑器字体与主题颜色的调整就都完成了；其他配置随着课程深入、真正用到的时候再讲。
