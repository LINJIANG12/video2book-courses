# 函数的传参方式：位置参数与关键字参数

变量的作用域清楚了，接下来把注意力转到参数上：定义函数的时候形参怎么书写，调用函数的时候实参怎么传递。这一节从传参方式讲起。所谓传参方式，就是定义好一个函数之后，调用它的时候传进去的实参该怎么传。

Python 里主要有两种传参方式。

## 位置参数

先将看位置参数。先用一个注册学生信息的函数来演示，它在定义时声明了四个形参：`name`、`age`、`gender` 和 `city`。

```python
def reg_stu(name, age, gender, city):
    """注册学生信息"""
    stu = {"name": name, "age": age, "gender": gender, "city": city}
    return stu
```

调用的时候按 `name`、`age`、`gender`、`city` 这个顺序传参：第一个传「张三」，指代的就是 `name`；然后 18，传递进来的是 `age`；「男」代表 `gender`；「北京」代表 `city`。这种传参方式就叫**位置传参**。

> **定义**：**位置参数**（positional argument）指调用函数时，传递的实参按照函数定义时每一个参数的位置来传递。

位置传参的要求是：调用函数时参数的**顺序**要和定义函数时参数的顺序**完全一致**，而且**数量**也得保持一致。

回想前面讲函数基础语法时定义的那些函数，调用时用的其实都是位置传参——第一个实参传给第一个形参，第二个实参传给第二个形参，第三个传给第三个……之前做的案例和所有练习，用的都是位置参数。

在 PyCharm 里写的时候能看到一个顺手的提示：准备写实参时，开发工具会把当前该传的那个形参名标出来——写第一个值时 `name` 是黑色显示的，写到第二个值时 `age` 这一块加粗，提示接下来要写的是 `age` 的值。

```python
def reg_stu(name, age, gender, city):
    stu = {"name": name, "age": age, "gender": gender, "city": city}
    return stu


stu = reg_stu("张三", 18, "男", "北京")
print(stu)
```

这个函数有返回值，用 `stu` 接收一下再输出。运行结果是学生信息被封装成了一个字典输出出来。这就是位置参数。

## 关键字参数

第二种传参方式叫关键字传参。

> **定义**：**关键字传参**（keyword argument）指调用函数时，以函数定义时的形参名称作为关键字来传参，传递形式是 `key=value` 这种键值对。这里的 key 就是形参名称，value 就是该形参要传递的值。按关键字传参时，参数的**顺序不作要求**。

把刚才的调用改写成关键字形式：

```python
stu = reg_stu(name="王丽", age=28, gender="男", city="北京")
print(stu)
```

`name="王丽"` 里的 `name` 指的是形参的名称，逗号之后 `age=28` 里的 `age` 指的是形参 `age`，`gender="男"` 里的 `gender` 指形参 `gender`，`city="北京"` 里的 `city` 指形参 `city`。传递参数就是「形参名称 = 对应的值」，也就是键值对形式传参。

运行一下，输出 `name` 是王丽、`age` 是 28、`gender` 男、`city` 北京，没问题。

接下来验证「顺序不作要求」这一点。把顺序打乱试试：年龄放前面，名字放到最后。

```python
stu = reg_stu(age=20, gender="女", city="北京", name="李木婉")
print(stu)
```

运行结果一样正确：`name` 是李木婉、`age` 20、`gender` 女、`city` 北京。

为什么顺序不影响？因为已经明确指定了每个值是给哪个形参传递的——「女」是给 `gender` 传的，「李木婉」是给 `name` 传的，「北京」是给 `city` 传的，20 是给 `age` 传的。每一个值的归属都指定清楚了，所以传参顺序就没有要求了。

## 位置参数与关键字参数混用

两种方式也可以混起来用：

```python
stu = reg_stu("赵四", 28, gender="男", city="上海")
print(stu)
```

前面这两个参数并不是 `key=value` 的键值对形式，那就是标准的位置参数写法：`赵四` 会给 `name`，`28` 会给 `age`。后面写的 `gender="男"`、`city="上海"` 就是关键字参数：「男」传给 `gender`，「上海」传给 `city`。

> **易错点**：位置参数和关键字参数混用的时候，一定要保证**关键字参数出现在位置参数之后**。也就是说先写位置参数，后面再写关键字参数。而关键字参数之间没有顺序要求。记住：先位置，后关键字。

这个规则是硬性的。把顺序写反，比如先写两个关键字参数，后面再跟两个位置参数：

```python
stu = reg_stu(name="李木婉", age=20, "北京", "女")   # 报错
```

这样写不行。鼠标往上一放就能看到报错信息：位置参数位于关键字参数之后了，是有问题的。

为什么解释器不允许这么写？其实很好理解。前面已经写成了 `name="李木婉"`、`age=20`，说明 `name` 和 `age` 都已经有值了；后面又冒出来两个「裸」的参数，那这两个参数给谁呢？给 `name` 吗？可是 `name` 已经给过了。还有一个是 `city` 吗？那到底谁是 `name`、谁是 `city`，对 Python 解释器来说就懵了。所以在解释器层面，为了保证每一个参数传递的都是清晰无误的，混合传参当中就必须把位置参数写在前面，关键字参数写在后面。

改回正确顺序就没问题了：

```python
stu = reg_stu("李木婉", 20, gender="女", city="北京")
print(stu)
```

第一个是 `name`，就把李木婉放在第一个；第二个是 `age`，就写 20；前面是位置参数，后面是关键字参数。而关键字参数因为已经指定了形参名称，它们之间的顺序随便，哪个在前哪个在后都行。

## 两种传参方式的对比与选用

把两种写法摆在一起对比，会发现位置参数的写法更简洁，关键字参数的写法要繁琐一些——毕竟要写 `key=value` 的形式。它们各有利弊。

| 传参方式 | 优点 | 缺点 |
| --- | --- | --- |
| 位置参数 | 写法简洁 | 可读性差，容易出错，维护较难 |
| 关键字参数 | 可读性强，容易维护和扩展 | 写法繁琐 |

位置参数的缺点是可读性比较差、容易出错、维护比较难。

拿 `reg_stu("张三", 18, "男", "北京")` 来说，心里立刻会犯嘀咕：写个「张三」是什么意思？18 是什么？「男」是什么？「北京」是什么？光看这串实参，并不清楚每个参数具体的含义和作用。当然对这个例子来说一眼能看出来——「男」不就是性别吗，「北京」不就是地址吗？那换一个需求试试：调用一个计算的函数 `calc`，里面递了四个值 87、68、92、85。这四个值分别是什么？第一个是什么？第二个、第三个、第四个又是什么？会发现它们都是数字、都是 `int` 类型，而且大小都差不多，这时候代码的可读性就比较差了，传参的时候也比较容易出差错——顺序一换，结果就错了。

同样的需求换成关键字传参，清晰度就完全不一样了：

```python
calc(math=87, chinese=68, english=92, computer=85)
```

一眼就能看出 87 是数学成绩、68 是语文成绩、92 是英语成绩、85 是计算机成绩。关键字参数的优点就在这里：可读性强，也容易维护和扩展。它的弊端则是繁琐。

那项目开发里到底用哪个？看应用场景：

**参数比较少的时候用位置参数**。一般两三个参数，而且这几个参数不容易混淆、顺序也比较自然，推荐用位置参数。比如「张三、18、男、北京」这种，一眼就能看出哪个是姓名、哪个是性别、哪个是城市或地址，用位置参数更合适，写起来更简洁，含义也清晰，基本上不容易出错。

**参数比较多的时候用关键字参数**。如果参数有四五个、五六个，甚至七八个以上，而且这些参数比较容易混淆——比如那一串分数——那用关键字传参可读性更强，也更容易读懂。

> **结论**：选择传参方式只需要守住一个原则——一切以代码的可读性为准，以提高代码的可读性和可维护性为目标。写完之后问自己一句：假设半年之后回过头来看今天写的这段代码，我能不能一眼看出每一个参数的含义？能，就用位置参数，更简洁；不能，而且容易混淆，那就用关键字传参。

这一节要明确的三个问题到这里就齐了：位置参数要保证调用时的实参顺序与定义时的形参顺序一一对应；关键字参数用「形参名称 = 值」的键值对形式传参、顺序不作要求；两者同时存在时位置参数在前、关键字参数在后，而关键字参数之间没有顺序要求；最后按可读性来选适用场景。
