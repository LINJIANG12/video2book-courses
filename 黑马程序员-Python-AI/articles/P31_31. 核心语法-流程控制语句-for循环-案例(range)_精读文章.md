# range 数字序列与两个 for 循环累加案例

`for` 循环的基本语法清楚了，接下来一起完成两个案例。需求看着都比较简单、比较短，但真正卡人的地方不在循环写不出来，而在另一个地方。

## 两个案例的需求与真正的难点

第一个需求：计算 1 到 100 之间所有奇数之和。

第二个需求：计算 100 到 500 之间所有 3 的倍数的数字之和。

既然要求基于 `for` 循环实现，就得回到它的结构上想。`for` 循环的本质是循环遍历，结构是 `for 元素 in ...`，而 `in` 之后跟着一个**待处理的数据集**。

那么要计算 1 到 100 之间所有奇数之和，首先是不是得拿到 1 到 100 之间的这 100 个数？这个待处理的数据集就应该是 1 到 100 之间的这 100 个数。

问题来了：要把 100 个数全部罗列在这儿吗？如果今天要计算的是 1 到 1000 之间所有奇数之和，这里就写 1000 个数？那显然是不合理的。

所以，要完成这两个需求，首先得搞定一件事——**怎么获取到 1 到 100 之间的数据集、怎么获取到 100 到 500 之间的数据集**。拿到数据集之后，遍历它、判断是不是奇数、是就累加，就顺理成章了。关键点全在「获取指定范围的数据集」这一块。

解决它要借助 Python 当中的一个新语句：`range` 语句。

## range 语句的三种用法

`range` 语句的作用，是**根据指定的规则来生成数字序列**。所谓数字序列，就是生成一组符合规则的数据，也就是一个数据集。常见用法有三种。

第一种：括号里面直接写一个 `end`，代表一个范围。它会生成一个从 0 开始、到 `end` 结束的数字序列——**注意不包含 `end` 本身**。

```python
range(5)        # 0, 1, 2, 3, 4
range(6)        # 0, 1, 2, 3, 4, 5
```

`range(5)` 得到的数据集就是 0、1、2、3、4，不包含 5。那如果想获取 0 到 5 之间的数据序列呢？括号里面就得写 6——因为它不包含 6，所以拿到的刚好是 0 到 5。

第二种：括号里面写两个数，两个数之间用逗号分隔。第一个数是 `start`，从哪开始；第二个数是 `end`，到哪结束。**同样不包含 `end`**。

```python
range(2, 8)     # 2, 3, 4, 5, 6, 7
```

`range(2, 8)` 获取到的就是 2、3、4、5、6、7，不包含 8。第二种用法就是指定了一个具体的范围：有开始、有结束，也是不包含结束。

第三种：括号里面指定三个数字，分别是 `start`、`end`，多出来的第三个是 `step`。`start` 和 `end` 与第二种用法一致，逗号之后的 `step` 代表**步长**。所谓步长，就是在生成的时候每次间隔几个数。

```python
range(0, 10, 2)     # 0, 2, 4, 6, 8
```

`range(0, 10, 2)` 表示从 0 开始、到 10 结束，每次间隔两个数。默认间隔的是**一个**数；这里写 2，生成的数据就是 0、2、4、6、8，同样不包含结束值 10。

> **结论**：`range` 就像是一个数字生成器，可以根据指定的规则帮我们生成数字序列。三种写法的差别只有两点——从哪开始、每次加几；而「不包含结束值」这条规则，三种写法统统适用。

## 案例一：1 到 100 之间所有奇数之和

现在获取 1 到 100 之间的这 100 个数，就不需要一个个罗列了，直接用 `range` 就行。

用 `range` 的三种用法其实都可以，第一种、第二种都能达成目的。比如想生成 1 到 100 之间的这 100 个数并且包含 100：`range` 括号里面不能写 100，写 100 是不包含 100 的，得写 101。使用第一种写法的话，它默认从 0 开始、是包含 0 的，但这个 0 对于计算累加之和没有影响，所以这种写法也可以用。如果不想生成这个 0，就用第二种写法直接指定从哪开始：从 1 开始，到 101 结束，那最终不会包含 101，自然也就会包含 100。

代码按「先验证数据、再补逻辑」的顺序来写。先定义一个变量记录累加之和，就叫 `total`，先等于 0。然后基于 `for` 循环遍历，遍历出来的元素写成 `i`。

```python
# 计算1到100之间所有奇数的累加之和

# 记录累加之和
total = 0

for i in range(1, 101):
    print(i)        # 先确认能不能拿到1到100这100个数
```

`range(1, 101)` 里，第一个数是从哪开始、第二个数是从哪到哪。从 1 开始到 100——但 `range` 是不包含 100 的，想包含 100 这一块就得写 101。这是整段代码最关键的一步：拿到 1 到 100 之间的这 100 个数。

先运行一下，把 `i` 输出出来看效果：从 1 到 100 之间的这 100 个数拿到了没有？拿到了。第一步搞定，接下来完成累加。

奇数怎么判断？什么情况下 `i` 才是一个奇数？**模于 2 等于 1，那就是奇数**。所以在循环体里加上条件判断：如果 `i % 2 == 1`，说明这个数字是奇数；是奇数就把它累加起来；如果不是奇数就不执行任何操作，直接去遍历下一个元素。

```python
# 计算1到100之间所有奇数的累加之和

# 记录累加之和
total = 0

for i in range(1, 101):
    # 判断是否为奇数
    if i % 2 == 1:
        # 累加
        total += i

print(f"1到100之间所有奇数的累加之和是：{total}")
```

末了把结果输出出来。这里用 `f` 格式化一下，或者直接用逗号把内容和 `total` 拼接到一起输出，都可以。运行结果是 **2500**，这个结果没有问题。

针对于这个需求，还有没有简化的空间？有，**从 `range` 这一块简化**。

原来的写法里有一个 `if` 条件判断，它的作用是筛掉偶数、只留下奇数。那反过来想：能不能生成一个数字序列，生成出来的序列里面**就只有奇数**？如果数据集本身全是奇数，那 `if` 就完全不需要了，直接累加就行。

但如果把 `if` 拿掉、直接累加 `range(1, 101)` 里的每一个数，累加的就是 1 到 100 这 100 个数之和，结果是 5050，那必然不对。所以要用 `range` 的第三种写法：除了 `start` 和 `end`，再跟上第三个数字 `step`——步长，也就是生成数字序列时每次加几。

默认是加 1。既然只想要奇数，那就让它每次加 2。

```python
# 简化版：直接生成奇数序列

# 记录累加之和
total = 0

for i in range(1, 101, 2):
    # 生成的序列全是奇数，直接累加
    total += i

print(f"1到100之间所有奇数的累加之和是：{total}")
```

`range(1, 101, 2)` 生成的第一个数是 1，第二个就是 1 加上步长 2 等于 3，第三个是 3 加 2 等于 5，往后就是 1、3、5、7、9、11……这样一串奇数。

先只看效果、先不累加：运行之后输出的是 99、97、95、93……**全部是奇数**。这时候再累加，就完全不用做任何条件判断，直接累加即可，结果依然是 **2500**，和前面一样。这就是最简化的版本。

> **提示**：两版代码结果相同，但思路不同。`range(1, 101, 2)` 是「让数据集本身就符合条件」，原来的写法是「取出所有数再筛一遍」。能用步长解决的问题，就不必再写一层 `if`。

## 案例二：100 到 500 之间所有 3 的倍数的累加之和

第二个案例和第一个比较类似，把上面的代码复制下来做个改造就可以。

需求要记录的是 100 到 500 之间所有 3 的倍数的累加之和。首先 100 到 500，范围得改：第一个数改成 100，第二个数改成 500。但要注意——`range(100, 500)` 是不包含 500 的，而我们要的范围包含 500，所以第二个数应该写成 **501**。

然后要计算所有 3 的倍数的数字之和。一个数是不是 3 的倍数，就看它能不能被 3 整除，也就是**模于 3 等于 0**，`i % 3 == 0` 就说明 `i` 是 3 的倍数。满足这个条件再把它累加起来。

```python
# 计算100到500之间所有3的倍数的累加之和

# 记录累加之和
total = 0

for i in range(100, 501):
    # 判断是否为3的倍数
    if i % 3 == 0:
        # 累加
        total += i

print(f"100到500之间所有3的倍数的数字累加之和是：{total}")
```

因为 `range(100, 501)` 生成的就是 100 到 500 之间的数字序列，所以 `start` 必须显式写成 100——第一种写法默认从 0 开始，这里用不了。

运行之后，最终累加起来是 **39900**，这个结果没有问题。

> **易错点**：`range` 的结束值永远取不到，所以「1 到 100」要写 `range(1, 101)`、「100 到 500」要写 `range(100, 501)`。少加这个 1，边界上那个数就悄悄漏掉了，而累加和算错时很难一眼看出来。

## range 用法速查

| 用法 | 写法 | 生成结果 | 说明 |
| --- | --- | --- | --- |
| 第一种 | `range(end)` | 0, 1, …, `end - 1` | 默认从 0 开始，不包含 `end` |
| 第二种 | `range(start, end)` | `start`, …, `end - 1` | 指定开始与结束，不包含 `end` |
| 第三种 | `range(start, end, step)` | `start`, `start + step`, … | 步长默认 1，指定 2 即每次加 2 |

`range` 语句的作用就是根据指定的规则生成对应的数字序列，也就是生成一个数据集。有了这个数字序列，我们再基于 `for` 循环去遍历它——一个数字集就摆在眼前了。

两个案例里都用到了这个新语句 `range`：它像是一个数字生成器，帮我们生成指定规则的数字序列，再把序列交给 `for` 循环逐个取出处理。
