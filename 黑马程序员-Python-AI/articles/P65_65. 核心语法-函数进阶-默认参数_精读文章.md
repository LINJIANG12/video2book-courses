# 函数的默认参数（缺省参数）

函数的传参方式弄清楚之后，接着往下走就该处理一件更实际的事：有些参数，绝大多数调用都填同一个值。比如一个函数有三个参数，其中一个每次调用都一样，那能不能在定义的时候就把它固定下来，调用的时候干脆不写？这一节解决的就是这个问题。

> **定义**：默认参数也叫**缺省参数**，指的是在定义函数时为形参提供一个默认值；调用函数时，如果这个参数有默认值，就可以不传递，它会自动使用默认值。

「缺省」两个字就是字面意思：**缺**是缺少，**省**是省略，说的是这个参数可以缺、可以省——前提是你给它设了默认值。没有默认值的参数，一个都不能省。

## 默认值的语法与生效规则

为参数设置默认值的写法，是在定义函数时的形参列表里用等号赋值：`参数名 = 参数值`。写成 `city="北京"`，就等于给 `city` 这个形参设了一个默认值「北京」。

一旦设了默认值，调用时这个参数就可以不指定。比如下面这次调用只写了三个参数——`name`、`age`、`gender`，`city` 没有写，因为它有默认值，函数内部就会用「北京」。

```python
def add_stu(name, age, gender="男", city="北京"):
    stu = f"姓名：{name}，年龄：{age}，性别：{gender}，城市：{city}"
    return stu


print(add_stu("王林", 20))
print(add_stu("李木婉", 18, "女"))
```

```text
add_stu("王林", 20)
          │       └── age = 20
          └────────── name = "王林"
                      gender 未传 → 用默认值 "男"
                      city   未传 → 用默认值 "北京"
```

读图说明：调用时没有提供的形参，会各自取回自己定义处的默认值，有默认值的参数只是「可以省略」，而不是「被跳过」。

反过来，如果调用时指定了这个参数，就以传入的值为准，默认值不再生效。上面第二次调用里的 `"女"` 就是这种情况：它是第四个位置上的实参吗？不是——`add_stu` 只传了三个位置参数，第三个位置正好落在 `gender` 上，于是 `gender` 被改写成「女」，而 `city` 没人管，继续用默认值「北京」。

> **结论**：默认参数只在「调用时没有传递该参数」时生效；一旦传了值，传入值覆盖默认值。

## 默认参数的位置要求

默认参数不能写在普通参数前面。这一点现场一试就露出来了：只把 `gender="男"` 加进形参列表，编辑器立刻报错——因为 `city` 这个还没设默认值的参数被排在了它后面。

正确的位置关系是：没有默认值的参数在前，有默认值的参数在后。一个函数里也可以给多个参数设默认值，只要把这些默认值统一放在无默认值参数列表的后面就行，形式仍然是「参数名等于参数值」。

```python
# 正确：无默认值的形参在前，有默认值的形参在后
def add_stu(name, age, gender="男", city="北京"):
    ...


# 错误：有默认值的形参后面又出现了无默认值的形参
def add_stu(name, age, gender="男", city):
    ...
```

> **易错点**：`gender="男", city` 这种顺序会直接报语法错误，编辑器里会立即标红。默认参数一旦开始，后面就都得是默认参数。

## 位置参数与默认值的配合陷阱

参数一多，「想用默认值、又想改后面那个」这种情况就很容易踩坑。用三段调用把这件事走一遍。

第一段：`add_stu("王林", 20)`。只给两个位置参数，`gender` 和 `city` 都走默认值，运行结果里姓名、年龄有值，`gender` 和 `city` 也都有值，而且正是定义处写的默认值。如果把 `gender` 的默认值撤掉，鼠标停在调用处的形参位置，编辑器就会提示「形参 gender 还没填」——它没有默认值，就不能省。

第二段：`add_stu("李木婉", 18, "女")`。想让性别用「女」，直接按位置传进去就行——不打算使用默认值的时候，为它传参就是了，用位置参数或者关键字参数都可以。执行结果是李木婉 18、性别女，`city` 没传，用的还是「北京」。也就是说，传入的值把这个参数的默认值覆盖了。

第三段是这个陷阱的现场：

```python
add_stu("韩立", 22, "上海")
```

目标是让韩立用默认性别「男」，同时把 `city` 改成「上海」。看着像只传了三个位置参数、绕过了 `gender`，实际运行出来，上海被当成了**性别**。原因很直接——位置参数是一个一个按顺序对应的：第一个给 `name`，第二个给 `age`，第三个必然给 `gender`。位置参数不比名字，它只认位次。

```text
add_stu("韩立",  22,  "上海")
            │      │      │
            ▼      ▼      ▼
          name   age   gender        ← "上海" 落在了 gender 上
                        city → 未传，用默认值"北京"
```

读图说明：位置参数按位次一一对应，想在跳过 `gender` 的同时给 `city` 赋值，就不能再用位置参数。

这时候要换成关键字参数，把名字写出来：

```python
add_stu("韩立", 22, city="上海")
```

再执行一次，`gender` 是「男」——走的是默认值；`city` 被指定为「上海」，默认值「北京」被替换掉。

> **提示**：想「用某个默认值、改它后面那个参数」，就绕开位置参数，对后面那个参数使用关键字传参。位置参数只能老老实实按位次一个一个填。

## 这一节要记住的

默认参数可以设多个，但必须放在非默认参数的后面；调用时传了值就覆盖默认值，没传就用默认值。语法本身不复杂，真正的坑在「位置参数遇上默认值」——第三个位置参数永远会落在第三个形参上，不会因为你「想跳过它」而自己让位。
