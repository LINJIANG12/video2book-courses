# 猜数字游戏：随机数生成与循环位置的选择

第一个综合案例做完了，接着来做第二个：猜数字的小游戏。这个案例除了继续用循环，还会引入一个新东西——随机数。

## 一、案例需求

1. 系统先生成一个随机数。所谓随机数，就是一个不可预测、也没有规律的数字，这个数字要通过代码自动生成。
2. 用户根据提示来猜这个数字，把所猜的数字输入到系统当中。
3. 系统把用户猜的数字和生成的随机数做对比。
4. 如果猜错了，系统给出提示，告诉用户猜大了还是猜小了，然后让用户继续输入所猜的数字。
5. 直到用户猜对，系统自动退出，游戏结束。

第 4、5 两点就是循环信号：猜错就提示、再输入，这一套动作被反复执行，直到猜对为止。

## 二、随机数怎么生成

生成随机数要借助 Python 提供的一个模块，叫 `random`。模块里的功能可以帮我们生成随机数。

用这个模块之前得先把它导入进来，靠一个关键字 `import`：

```python
import random

random_number = random.randint(1, 100)
```

`randint` 是 `random` 模块里的一个功能，需要指定两个数字：一个是起始，一个是截止。写 `1, 100` 就代表生成的随机数介于 1 到 100 之间，**包含 1，也包含 100**。

前面用一个变量 `random_number` 接收生成的随机数，这个变量里记录的就是那一次的随机数结果。

> **提示**：`randint` 的两端都是闭区间，也就是 $[1, 100]$。这和 `range(1, 100)` 的右端不含不同，别把两者的边界习惯混起来。

关于这两句代码具体的含义和写法，后面会有专门的讲解，现在先会用、先知道通过这两句就能生成一个随机数就够了。

## 三、选 while 还是 for

和登录案例一样，先定循环类型。

需求说的是"直到用户猜对，系统才自动退出"。循环次数确定吗？完全不确定——有人一次就中，有人猜十几次。但退出条件非常明确：用户猜对了。

次数未知、条件已知，用 while 循环。

## 四、猜数字的主体逻辑

打开 PyCharm，新建文件"循环案例 2.py"。需求已经罗列在里面了，接着往下实现。

### 4.1 接收输入并转成整数

随机数有了，接下来把用户猜的数字收进来：

```python
number = int(input("请输入一个数字"))
```

上面生成的随机数是 `int` 类型。`input` 拿到的永远是字符串，所以这里直接把字符串转成 `int` 再赋值给 `number`，后面才好和随机数比大小。

### 4.2 三分支比较

比较两个数字，用 if 条件判断：

```python
if number > random_number:
    print("您输入的数字太大了！")
elif number < random_number:
    print("您输入的数字太小了！")
else:
    print("恭喜您，猜对了！666")
```

- `number` 大于 `random_number`，说明输入的数字大了；
- `number` 小于 `random_number`，说明输入的数字小了；
- 剩下的 `else` 里，`number` 既不大于也不小于，那就只能是等于——也就是猜对了。

> **结论**：三段比较不需要显式写 `number == random_number`。前两个条件都用不等号排除掉之后，`else` 分支剩下的唯一可能就是这个等号。

### 4.3 先看数字，方便测试

为了测试方便，在最后把生成的随机数直接打印出来，这样一眼就知道答案是多少：

```python
print(f"随机生成的数字是{random_number}")
```

> **提示**：这句输出只是给测试用的脚手架。它现在有实际作用，但在最终成品里它会破坏游戏的可玩性。

基础逻辑理清楚，先运行一次测试。输入 `60`，提示"您输入的数字太小了"，随机生成的数字是 `72`。

问题立刻暴露：没猜对，程序也退出了。因为这段代码没有任何循环操作，从头到尾只执行了一遍。

## 五、把哪几行放进循环

需求要求猜对了才退出，猜错就继续输入。所以这段逻辑要重复执行多次，必须放进循环。用 `while True`，把刚才写的逻辑整体挪进循环体。

但**不是所有行都该进循环**。这里要逐行判断：

| 代码 | 是否放进循环 | 原因 |
| --- | --- | --- |
| 导入 `random` | 不放 | 只做一次准备工作 |
| `random_number = random.randint(1, 100)` | 不放 | 放进循环就是每次循环都重新生成一个数 |
| 输入所猜数字 | 放 | 每一轮都要重新猜 |
| 三分支比较与提示 | 放 | 每一轮都要重新判断 |
| 输出随机数（测试用） | 不放 | 只在游戏结束后展示一次 |

生成随机数那行如果被塞进循环，结果就是每猜一次答案都变一次，游戏根本无法完成。所以它必须留在循环外面，只执行一次。

```python
import random

random_number = random.randint(1, 100)

while True:
    number = int(input("请输入一个数字"))
    if number > random_number:
        print("您输入的数字太大了！")
    elif number < random_number:
        print("您输入的数字太小了！")
    else:
        print("恭喜您，猜对了！666")

print(f"随机生成的数字是{random_number}")
```

## 六、死代码：为什么最后一行变灰了

代码写完，会发现最后那行输出随机数的语句**变成灰色**了。

这是 PyCharm 这类开发工具的智能提示：它会判断这行代码有没有机会被执行到。一旦显示为灰色，就说明这里可能有问题。

鼠标移上去，提示是"死代码，不可到达"——意思是这行代码可能永远都运行不到。

原因很清楚：上面是 `while True`，一个无限循环，而且在任何位置都没有跳出循环，所以它下面的代码永远等不到执行的机会。

再问一遍：什么情况下应该跳出循环、游戏结束？猜对的时候。

所以在 `else` 分支里，除了输出"恭喜您猜对了"，还要在下面加一句跳出循环的语句：

```python
    else:
        print("恭喜您，猜对了！666")
        break
```

> **易错点**：这里该用 `break`，不是 `continue`。`continue` 只是结束本轮、进入下一轮，循环仍然继续；猜对了要的是整个循环结束、游戏退出，只有 `break` 能做到。

加上 `break` 之后，最后那行代码就不再是灰色了——它重新变得可能被执行到。

## 七、运行测试与折半猜法

运行程序，因为随机数在循环之后才输出，所以一开始得盲猜。

既然数字范围是 1 到 100，怎么猜才能又快又准？

从 1、2、3 一个个往上试，还是每次猜中间的数字？后者快得多。因为每猜一次，无论提示是"太大"还是"太小"，都能砍掉一半的候选范围。

这一次的实际过程：

| 轮次 | 猜的数字 | 系统提示 | 剩余可能区间 |
| --- | --- | --- | --- |
| 1 | 50 | 太小了 | 51 ~ 100 |
| 2 | 75 | 太小了 | 76 ~ 100 |
| 3 | 85 | 太小了 | 86 ~ 100 |
| 4 | 93 | 太小了 | 94 ~ 100 |
| 5 | 97 | 太大了 | 94 ~ 96 |
| 6 | 95 | 太小了 | 96 ~ 96 |
| 7 | 96 | 猜对了 | 命中 |

第 4 轮猜完，区间从 100 个数字缩到 7 个；第 6 轮猜完，只剩一个数字，答案已经锁定。

猜对之后输出"恭喜您，猜对了！666"，接着输出"随机生成的数字是 96"，程序退出循环结束运行。

而猜错的时候，程序并不会结束，它会一直提示、一直让我们重新输入所猜的数字。

```text
     while True
         |
    输入所猜数字
         |
    与随机数比较
     /    |    \
  太大   太小   相等
   |      |      |
  提示   提示   输出"猜对了"
   |      |      |
   +------+    break
   |             |
   +--> 下一轮   跳出循环
                 |
          输出随机生成的数字
```

读图要点：只有"相等"这一条分支能走到 `break`，另外两条分支只是打印提示就回到循环开头，这就是"猜错继续、猜对结束"的全部机制。
