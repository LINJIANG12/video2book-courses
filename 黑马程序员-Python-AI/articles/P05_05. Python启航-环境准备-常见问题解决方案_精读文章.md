# Python 命令无法执行的原因与 Path 环境变量配置

装完 Python 解释器，兴冲冲打开命令行敲下 `python` 回车，结果屏幕上跳出一行冷冰冰的提示：`python 不是内部或外部命令`。或者更奇怪——它不报错，反而自己弹出了微软商店，让你去下载一个 Python。

先说明一句：**这个问题绝大部分同学基本遇不到**。只有一小部分人会碰上，而碰上的原因几乎只有一个：安装 Python 解释器的那几步没有严格按照讲义里的步骤走。所以如果你在前面装解释器、跑第一个小程序时一路顺畅，这一节可以直接跳过，去学下一节；但既然它是新手最常见的第一个拦路虎，我们把它连同背后的机理一起讲透——搞懂了它，你就顺便搞懂了 Windows 上"命令到底是怎么被执行起来"的。

## 现象、成因与解决思路

### 两种现象，其实是同一个原因

这些问题的表现分两种，取决于操作系统：

| 现象 | 典型系统 | 屏幕上的反馈 |
| --- | --- | --- |
| 直接报错 | Win10 | `python 不是内部或外部命令` |
| 跳到应用商店 | Win11 | 自动打开微软商店，引导下载 Python |

发现没有？两种现象都是执行 `python` 这条命令时**没有找到这条命令**导致的，区别只在于系统给出的"反馈形式"不同：Win10 老老实实告诉你找不到，Win11 则猜你想装 Python，干脆把你送到商店门口。可问题是——Python 我们明明已经装好了。

> **结论**：这两种现象本质是一件事：命令没找到。系统的版本只决定它用什么方式抱怨。

### 为什么装了 Python 却找不到命令

原因落在安装时的一个选项上：安装向导第一步，界面最下方有一个复选框，作用是**把 `python.exe` 添加到 Path 环境变量当中**——这一步没有勾选，就会引发后面所有的麻烦。

简单说就是 Path 环境变量出了问题。至于 Path 环境变量到底是什么、为什么会决定一条命令能不能被找到，我们下面专门讲。

### 两条解决路线

既然问题的根源是"当初忘了勾选那一项"，那解决思路自然也有两条：

1. **卸载重装**：简单粗暴，把 Python 解释器卸掉，重新装一遍，这次别忘了勾选。
2. **手动配置 Path 环境变量**：不重装，直接把缺的那份配置补上。

两条路都走得通，下面分别走一遍。

## 方案一：卸载并重新安装

先纠正一个很常见的坏习惯。作为专业的软件开发工程师，以后卸载软件**不要**在安装目录上右键、直接删文件夹——那样删不干净，注册表、安装记录、环境变量里都会留下残渣。

正确做法是走正规渠道：

1. 找到控制面板；
2. 点击「卸载程序」；
3. 列表里的软件按字母排序，找到 `P` 开头的 Python（一共两项），选中后点击上方的「卸载」；
4. 两项都卸掉，然后重新安装。

重新安装时，你自然就知道那一项必须勾选了。

## 方案二：手动配置 Path 环境变量

### 环境变量的定义与作用

> **定义**：环境变量是操作系统当中存储的、用来指定应用程序运行时所需要的参数信息的那份配置。

它能装什么？应用程序运行时需要的临时文件夹位置、系统文件的访问位置、某些网站的访问凭证，这些信息都可以配置在环境变量里。应用程序跑起来的时候，只需要去读环境变量，就能拿到这些参数，而不必把这些信息写死在代码里。

我们要解决 `python` 无法执行的问题，就得手动配置环境变量。要配置它，先得知道它在哪儿。

### 用户变量与系统变量的区别

入口不止一个，常用的两条：

- 打开「此电脑」→ 右键 → 属性（若菜单里没有「属性」，点「更多选项」就能看到）→ 打开系统信息页面 → 找到「高级系统设置」；
- 开始菜单里直接输入「系统」，找到控制面板当中的「系统」，点进去 → 「高级系统设置」。

在「高级系统设置」里点「环境变量」，会弹出一个窗口，里面是当前系统所有的环境变量。它被分成上下两部分：

| 分区 | 生效范围 | 说明 |
| --- | --- | --- |
| 用户的环境变量 | 仅当前登录用户 | 换个用户登录就不生效 |
| 系统环境变量 | 所有用户 | 与用户无关，谁都访问得到 |

为什么会有"用户"这一层？因为 Windows 也好、Mac 也好，装系统时默认都会创建一个用户。对个人电脑来说，通常就只使用这一个默认用户——比如我机器装好之后用户名就是 `lenovo`，那么上面那半区就是 `lenovo` 这个用户的环境变量。

> **结论**：上面那份只对当前登录用户有效，下面那份对所有用户生效。个人电脑只有一个用户，两处配置效果一样；多人共用的电脑就得想清楚配在哪一份。

列表里变量很多，其中大部分是软件在安装过程中自动配置好的。而在这些变量里，有一份特别重要，就是 `Path`——你会发现，**上面的用户变量区和下面的系统变量区，都有 `Path`**。

### 命令的执行流程

先看现象怎么复现。按 `Win + R`，输入 `cmd`，回车打开命令行。这里我特意说明：在我重新安装 Python 的过程中，**我并没有勾选添加环境变量那一项**，所以此时执行 `python` 就会出问题。我这台是 Win11，它没找到 Python 命令，于是让我去下载解释器——可 Python 明明已经装好了。为什么它没找到？

要回答这个问题，得知道命令行执行一条命令时做了什么。

```text
在命令行输入一条命令并回车
        |
        v
  是系统内部命令？（如 cd）
     |            |
     是           否
     |            |
     v            v
  直接执行     在当前目录下查找该命令
                  |            |
                  找到          没找到
                  |            |
                  v            v
               执行它     到 Path 环境变量
                          配置的各个目录中查找
                              |          |
                              找到        没找到
                              |          |
                              v          v
                           执行它     报错 / 跳到应用商店
```

这张图就是命令行的命令解析流程：内部命令直接执行，外部命令先查当前目录，再查 `Path` 里登记的目录，全都落空才报错。注意 `Path` 在流程里所处的位置——它是外部命令查找的最后一道关口。

回到现场验证一下。当前目录是哪个？命令行里显示的是 `C:\Users\lenovo`——把这条路径粘进命令行回车，列出来的内容里并没有 `python` 这个文件。当前目录查完，一无所获，于是它转向 Path 环境变量。

那 `python` 这条命令本体在哪儿？它在 Python 的安装目录下：`D:\develop\python`，那个目录里躺着一个 `python.exe` 可执行文件，最终被执行的就是它。

于是关键问题变成：**Path 环境变量里登记了 Python 的安装目录吗？**

双击上面的 `Path`（用户变量）进入编辑模式，里面默认配置了不少目录，往下翻——有没有 Python 的安装目录？没有。再看系统变量里的 `Path`，双击打开，也没有 `develop\python` 这个目录。用户 Path 与系统 Path 里都查不到，命令自然执行不成功，于是出现了刚才的现象（Win11 版本的表现就是跳去商店）。

### Python 安装目录与 Scripts 目录的添加

解决方式很直接：**把 Python 的安装目录加进 Path 环境变量**。

操作步骤如下：

1. 点击「环境变量」，找到 `Path`；
2. 上下两个 `Path` 在哪一个里配置？对我这台电脑来说，配上面或配下面都可以——因为我只有一个用户；而大家在安装 Python 时，默认配置的是上面那个（用户变量）；
3. 双击进入「编辑环境变量」，点「新建」；
4. 打开 Python 的安装目录 `D:\develop\python`，复制这个目录路径，粘贴进去；
5. 再点一次「新建」，粘贴 **`Scripts` 目录**的路径。

为什么 `Scripts` 也要加？因为那个目录下同样放着一些可执行文件，比如 `pip`——后面我们要安装各种依赖模块时会用到这个命令。少配它，Python 本体能用，装包的 `pip` 却用不了。

```bash
D:\develop\python
D:\develop\python\Scripts
```

这两条就是需要登记进 `Path` 的目录：前者提供 `python` 命令，后者提供 `pip` 等工具。

> **易错点**：只加 Python 安装目录、漏掉 `Scripts`，是最常见的半成品配置——当下 `python` 能跑了，等到装第三方库时 `pip` 又报"不是内部或外部命令"，你还得回来补一次。

### 条目顺序与优先级

配置完路径，还有一步别漏：**把这两个目录「上移」到最前面**。

Path 里的条目是有顺序的，越靠前优先级越高，越靠后越低。如果系统里装了多个 Python，最前面那个会生效。所以我们要把刚加的两项挪到最前面。

改完之后，依次点击「确定」、「确定」、「确定」把三层窗口都确认掉。至此环境变量配置完毕——我这一共配了两项：Python 的安装目录，以及安装目录下的 `Scripts`。

### 配置后的验证

验证时有个讲究：**不要在刚才已经打开的那个命令行窗口里验证**。

环境变量改完之后，需要重新打开一次 `cmd`，最新的环境变量才会生效。所以把旧窗口直接关掉，再按 `Win + R`、输入 `cmd`、回车，然后输入 `python`。

这一次 Python 命令正常执行了。道理还是那条流程：当前目录下没有这条命令，它就去 Path 环境变量里找；而 Path 里已经登记了 Python 的安装目录，安装目录下就有 `python.exe`，于是命令被找到并成功执行。

顺手输出一个 `Hello Python`，也没问题。

## 收尾：一条可检索的结论

出现这个问题的原因：安装 Python 时没有勾选"添加到 Path 环境变量"那个选项。

对应的两种方案：

| 方案 | 做法 | 配置要点 |
| --- | --- | --- |
| 卸载重装 | 控制面板 → 卸载程序 → 卸载 P 开头的两项 Python → 重新安装 | 重装时务必勾选"添加到 Path 环境变量" |
| 手动配置 | 高级系统设置 → 环境变量 → 编辑 Path → 新建两项并上移到最前 | 一项 Python 安装目录，一项其中的 `Scripts` 目录 |

环境变量的作用，一句话概括：**告诉系统，在命令行里执行一个命令时该从哪些目录去找可执行文件**；所以可执行文件所在的目录，就必须配置进 `Path`。

要把执行流程记牢，可以这样记：执行一条命令时，先判断它是不是系统内部命令——像 `cd` 切换目录这类，就属于内部命令，是内部命令直接执行完事；不是内部命令的，比如 `python`，就去 `Path` 环境变量里找；找到了就执行，没找到就报错——Win11 上表现为打开应用商店让你下载，Win10、Win7 上则告诉你"不是内部或外部命令"。

> **提示**：安装和使用都正常的同学，完全不需要去动 `Path` 环境变量，知道它是什么、什么时候会出问题就够了。
