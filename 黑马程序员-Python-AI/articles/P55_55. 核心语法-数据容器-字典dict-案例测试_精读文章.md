# 购物车系统的功能测试与逻辑优化

上一节把购物车系统的四个功能——添加、修改、删除、查询——都写完并跑通了。但写完不等于没问题。这一节就一件事：**把这个系统挨个功能测一遍，有问题再修**。

测试的思路很简单：直接右键运行，按菜单的五个选项依次走一遍，看结果对不对。

## 1 非法输入的处理

运行之后，程序提示输入具体的操作，要求是 1 到 5 之间的数字。那我先不按规矩来，输一个 `0`，看会怎样。

结果是它告诉我们「非法操作，不支持」，紧接着又把菜单输出了一遍，让我们继续选择要执行的操作。

原因很清楚：输入的 0 匹配不到前面五种情况，就落到最下面那个匹配其他情况的分支上，输出「非法操作，不支持」。又因为这段代码整个都在循环之内，这一轮走完之后会从上往下再执行一遍，于是菜单又被输出出来，继续让我们选择。这就是整个系统的运转逻辑。

## 2 添加与查询功能

### 2.1 添加商品

输入 `1`，代表添加购物车。程序提示输入要添加的商品名称，输入 `Mate80`，回车；再输入商品的价格 `6999`，回车；再输入商品的数量 `2`，回车。

三步录完，程序提示「商品添加完毕」，然后问是否还要执行其他操作，并重新把菜单展示出来。

### 2.2 查询商品

刚添加完，顺手查一下购物车，输入 `4`。程序输出了购物车当中的数据：商品名称 `Mate80`，商品的价格 `6999`，数量 `2`，与录入的一致。

再添加一件：输入 `1`，商品名称输 `茶叶`，价格 `599`，数量 `1`。提示添加完毕后，再输入 `4` 查询，购物车中的商品明细信息同样正常输出。

## 3 修改功能与 continue 优化

### 3.1 修改不存在的商品

接着测修改，输入 `2`。程序问要修改哪个商品，这里故意输一个购物车中**没有**的商品 `矿泉水`。

> **提示**：这一步的用意就是验证「商品不存在」这条分支。购物车里有 `Mate80` 和 `茶叶`，没有 `矿泉水`。

回车之后，程序提示输入价格 `2`，再输入数量 `5`，走完才告诉我们「该商品不存在，请重新选择」。功能上是拦住了，但顺序上明显有浪费：商品都不存在，前面还让人白填了一遍价格和数量。

### 3.2 用 continue 提前结束本轮

这个逻辑有优化空间：应该在**输入完商品名称之后就直接判断**，如果商品不存在，直接给出提示，不用再让他输入价格和数量。

做法是把判断逻辑整体剪切到输入商品名称的后面。但这里还有一个容易忽略的点：提示完之后，下面的代码还是会被执行到，所以必须让这一轮循环就此结束，不再往下走。这就要用关键字 `continue`：

```python
goods_name = input('要修改的商品名称：')
if goods_name not in shopping_cart:
    print('该商品不存在，请重新选择')
    continue
goods_price = float(input('请输入商品最新的价格：'))
goods_number = int(input('请输入商品最新的数量：'))
shopping_cart[goods_name] = {'price': goods_price, 'number': goods_number}
print('商品修改完毕')
```

`continue` 代表中断本次循环，直接进入下一次循环，于是程序回到上面重新让用户输入商品名称。

另一个连带的好处是：既然上面已经做过判断，代码能执行到下面，就说明这个商品在购物车中一定存在，所以下面那块就不用再做判断了，`else` 也可以删掉，直接修改即可。

> **易错点**：把 `continue` 当成 `break` 是常见错误。`continue` 只结束这一次循环、进入下一轮，循环本身照常运行；把整个系统退出去的是 `break`。

## 4 重新运行后的数据丢失

代码改完，重新运行。这次先输入 `4` 查询购物车，结果没有任何反应——上一轮添加的 `Mate80` 和 `茶叶` 都不见了。

原因在于：之前往字典、往购物车里写的数据，全都保存在**内存**当中。一旦把当前这个服务停掉、重新运行，内存当中的数据就已经丢失了，所以重启之后数据就没了。

> **结论**：目前购物车的数据是内存数据，程序一重启就归零。这个问题在后面讲文件操作之后就能解决——把这些数据持久化保存到文件当中即可。

## 5 完整回归测试

数据没了就重新录入，顺便把四个功能完整走一遍。

### 5.1 重新录入并查询

输入 `1` 添加 `Mate80`，价格 `6999`，数量 `2`；再输入 `1` 添加 `茶叶`，价格 `599`，数量 `1`；输入 `4` 查询一次，两件商品都能查到。

### 5.2 修改存在的商品

输入 `2` 执行修改。这次先故意输一个购物车里没有的 `鼠标`，回车之后程序立刻提示「该商品不存在，请重新选择」——优化后的效果出来了，不再让用户白填价格和数量。

继续选择 `2`，这次输入正确的 `茶叶`。因为 `茶叶` 是存在的，程序直接让我们输入最新价格，比如涨价后的 `699`；再输入数量，原来是 1，现在改成 `3`。程序提示「商品修改完毕」。再输入 `4` 查询，购物车中 `茶叶` 的信息确实被改成了新的价格和数量，修改功能没问题。

### 5.3 删除商品

输入 `3` 测试删除。先输一个没有的 `矿泉水`，回车后提示「商品不存在，请重新选择」——不存在，自然删不了。

再输入 `3`，这次删 `Mate80`。回车后提示「商品删除完毕」，再输入 `4` 查询，`Mate80` 已经从购物车里消失了。

到这里，购物车系统的增删改查功能全部测试通过。

### 5.4 退出系统

最后测退出，输入 `5`。程序输出一句「拜拜」，然后执行 `break`；`break` 一旦执行就退出循环，循环退出，程序随之结束运行。
