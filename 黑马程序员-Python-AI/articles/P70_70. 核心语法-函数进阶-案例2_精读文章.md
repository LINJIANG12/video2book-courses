# 订单总金额计算器的参数设计与实现

第一个案例做完，接着做第二个案例：电商里的订单计算器。加购物车最后点结算时，要算的就是这个订单的总金额，而购物车里可以有多个商品。案例要求定义一个函数，根据传入的商品信息、优惠信息和运费信息，计算这批订单的总金额。

## 需求拆解与形参设计

商品信息至少要包含商品的名称、商品的价格、商品的数量，一个订单里可以包含一批这样的商品数据。除了商品信息，还有优惠信息——优惠券和积分抵扣，以及运费信息。所以函数最终要接收的是这三类信息。

规则有两条，都是针对优惠券和积分抵扣的。

| 优惠方式 | 使用门槛 | 金额限制 | 其他限制 |
| --- | --- | --- | --- |
| 优惠券 | 商品金额满 5000 才能使用 | 优惠券金额不能超过商品总价 | 无 |
| 积分抵扣 | 商品金额满 5000 才能使用 | 抵扣金额不能超过商品总价 | 100 积分抵扣 1 元，只能整百抵扣 |

> **提示**：积分只能整百抵扣，意思是兑换积分得按 100、100 来换，不能几十个几十个地换。

定义一个函数，重点要考虑的就是形参怎么声明。商品信息里到底有多少个商品？不确定。参数数量不确定，就可以用不定长参数——而且商品信息是核心数据，所以用不定长位置参数 `*args`。优惠信息拆成两个参数，一个优惠券、一个积分抵扣，再加上一个运费参数。

参数名里只有积分是现成的，优惠券和快递的英文得去查：优惠券是 `coupon`，快递用 `express`。

```python
def calc_order_cost(*args, coupon, score, express):
    """根据传入的这批商品数据以及优惠信息、运费信息，计算订单的金额

    :param args: 商品的信息，包括商品的名称、商品的价格、商品的数量
    :param coupon: 优惠券
    :param score: 积分
    :param express: 运费（快递）
    :return: 订单的总金额
    """
```

商品信息里，每一种商品都要包含名称、价格、数量这三项，而参数里的每一个元素就是一件商品。调用时一件商品用一个元组或列表传进来，比如第一件是鼠标 188 元、数量 2，传 `("鼠标", 188, 2)`；第二件是键盘 388 元、数量 1，传 `("键盘", 388, 1)`。有多件商品就传多个元组。

> **结论**：`args` 本身是一个元组，它里面封装了多个元素，而每一个元素又是一个小的元组——所以商品信息是「外层元组套内层元组」的两层结构。

## 三引号文本块在文件中的着色

把需求以三引号的形式粘到文件里之后，会发现它和之前写的三引号展示得不一样：之前是灰色，这次是绿色。

Python 并没有提供单独的多行注释语法，三引号定义的内容本质就是一个字符串。PyCharm 会根据这个三引号字符串出现的位置和用途做智能区分：文件里第一个三引号字符串被认为是在描述当前 Python 文件的功能，显示为灰色，识别成注释；其他位置的三引号字符串，PyCharm 认为就是普通的多行字符串，显示为绿色。

也就是说，上面那个是文件里第一个三引号定义的字符串，所以识别为当前文件的文档注释；下面这个是第二次出现，就当普通字符串处理。把上面那个字符串剪切删掉，下面这块立刻就会变灰——因为它成了第一个。

> **提示**：三引号字符串单独存在时，Python 解释器执行时会忽略它，所以习惯上就用它来当多行注释，不影响程序运行。

## 按四步实现函数

订单总金额的计算公式先定下来：商品的总金额，减去优惠券，再减去积分抵扣，最后加上运费。注意运费是加，不是减；而优惠券和积分抵扣是有条件才扣减的，不满足条件就不扣。

于是实现拆成四步：先算商品总金额，然后在总金额基础上扣优惠券，再扣积分抵扣，最后加运费，返回结果。

### 商品总金额的累加

商品总金额的算法是：拿到每一个商品，用它的价格乘以数量得到这件商品的金额，再把所有商品的金额累加起来。

先定义一个列表记录每个商品的金额，列表的元素来自 `args` 里封装的商品信息，用列表推导式快速构建。遍历 `args` 得到每个 `goods`，它就是一件商品的整个元组；要取价格和数量，就在后面写下标取第二个和第三个元素。

```python
total_price = [goods[1] * goods[2] for goods in args]
total_cost = sum(total_price)
```

> **易错点**：索引用从 0 开始，价格是元组里的第二个元素，下标是 1；数量是第三个元素，下标是 2。写成 `goods[2] * goods[3]` 就取错了。

再用 `sum` 对这个列表做累加，就拿到这批商品的总金额 `total_cost`。

### 优惠券的扣减条件

优惠券要商品金额满 5000 才能使用，也就是 `total_cost >= 5000`；并且优惠券金额不能超过商品总价，也就是 `coupon <= total_cost`。两个条件用 `and` 连起来：

```python
if total_cost >= 5000 and coupon <= total_cost:
    total_cost -= coupon
```

满足条件就扣减，扣减后把结果再赋值回 `total_cost`，这一步用减等运算符写更简洁。

### 积分抵扣的换算与整百限制

积分抵扣的第一个条件和优惠券一样，也是商品金额满 5000 才能用；第二个条件同样是抵扣金额不能超过商品总价。但后面这一句不能照抄——优惠券那处比的是优惠券本身，这里如果直接拿积分和商品金额比较就错了：100 积分才抵扣 1 元，所以要用积分除以 100 之后再去和商品金额比较。

积分还只能整百抵扣，也就是说除完之后不能出现小数。用两个斜杠的整除：

```python
if total_cost >= 5000 and score // 100 <= total_cost:
    total_cost -= score // 100
```

> **易错点**：用 `/` 就会算出 4000 / 100 = 40.0 这种带小数点的浮点数，而积分只按整百抵扣，所以要用 `//` 整除。扣减时的金额同样必须写成 `score // 100`，不能直接减 `score`。

### 运费与返回

```python
total_cost += express
return total_cost
```

四步走完，函数就定义好了。

## 参数传递方式与测试

第一次测试，商品是鼠标 188 元数量 2、键盘 388 元数量 1、手机 3999 元数量 1，优惠券 10、积分 4000、运费 9.9：

```python
result = calc_order_cost(
    ("鼠标", 188, 2), ("键盘", 388, 1), ("手机", 3999, 1),
    coupon=10, score=4000, express=9.9
)
print(result)
```

如果后面三个参数按位置直接写 `calc_order_cost(("鼠标", 188, 2), ..., 10, 4000, 9.9)`，把鼠标悬浮到函数上，编辑器会提示形参 `coupon`、`score`、`express` 没有填。明明填了，为什么说没填？

因为 `args` 是不定长位置参数，它的数量不确定，所以编辑器会把后面所有的位置参数都收进 `args`，包括那三个。解决方式有两种：

1. 定义函数时把不定长参数放到最后一位，先定义后面那三个参数，再放 `*args`；
2. 保持现在的定义不变，后面这几个参数改用关键字传参，不再用位置传参。

第二种写法把参数名和值一一对应，明确指定了哪个值给哪个形参。

**第一次测试结果**：188 × 2 + 388 + 3999 = 4763，4763 没有超过 5000，所以优惠券和积分抵扣都不生效，直接加上 9.9 的运费，得到 4772.9。

**第二次测试**：把手机价格调贵到 6999，商品总金额超过 5000，两个 `if` 条件都被覆盖到。188 × 2 + 388 + 6999 = 7763，超过 5000 就扣优惠券 10，再扣积分——4000 积分抵 40 元，再减去 40，最后加 9.9，等于 7722.9，与程序输出一致。

> **提示**：做测试时一定要把情况测全。只测第一种情况，两个 `if` 分支根本没被执行到，逻辑正确与否无从判断。

## 默认参数与类型提示

还有一个场景：账号没有优惠券也没有积分，这两个参数就不想传。此时直接传邮费 9.9，程序报错，提示缺少两个参数：`coupon` 和 `score`。

原因是在定义函数时声明了这两个参数却没有传递。解决办法是给后面的参数设默认值：

```python
def calc_order_cost(*args, coupon=0, score=0, express=0.0):
```

没有指定优惠券默认就是 0，积分默认也是 0，运费如果是免邮也默认 0。

> **易错点**：默认值写成 `express=0` 时，传 9.9 进来会有黄色提示——上面赋的值是 int 类型，实际传入的是 float 类型。它只是提示，不影响运行。想消除提示，把默认值改成 `0.0`，上下类型就一致了。

运费也设了默认值之后，调用时连运费都可以不传，不传就相当于免邮，一样能正常运行，因为后面这三个参数都有默认值。

这个案例把不定长参数和默认参数都用上了，也涉及函数调用时参数的两种传递方式：前面的商品信息按位置传参，后面的优惠信息与运费按关键字传参。
