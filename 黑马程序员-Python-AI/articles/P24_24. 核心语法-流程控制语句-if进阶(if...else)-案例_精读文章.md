# if...else 语句与闰年判断案例

上一节的 B 站登录案例跑通了，但代码里有一个地方值得回头再看一眼：我们写了两条 `if` 语句——第一条判断账号和密码是否都正确，都正确就登录成功；第二条判断账号和密码有没有错误，有任何一个错误就登录失败。

从功能实现上说，这么写没问题，跑起来结果也对。但换个角度想一个问题：**登录这件事，是不是不是成功就是失败？**

账号和密码都正确，登录成功；否则就是失败。要么成功要么失败，没有第三个选项。既然只有两种结果，那第二条 `if` 判断其实是可以省掉的——它的答案已经藏在第一条的条件里了。回头再看这段代码，确实略微繁琐，效率也不高。

这一节就来解决它，进入 `if` 条件判断的第二部分：`if` 语句的进阶用法。

## if...else 的结构与执行逻辑

把登录需求重新摆一遍：账号和密码都正确，条件成立，执行操作一，也就是进入 B 站系统首页；否则说明登录失败，执行操作二，提示一条错误信息。

针对这种「要么这个条件成立，要么不成立」的场景，可以用 `if` 配合 `else` 来实现。

```python
if 条件:
    条件成立时执行的代码
else:
    条件不成立时执行的代码
```

结构逐段看：

- `if` 后面跟上要判断的条件，这一部分和基本语法完全一样；
- 条件成立，执行 `if` 代码块里的语句；
- 条件不成立，程序就进入 `else`，执行 `else` 之后的代码。

`else` 可以理解为「否则」——否则我就执行下面这段逻辑。

> **定义**：`else` 之后**不写任何条件**。它执行的时机只有一个：`if` 之后的条件不成立。既然前面已经排除了条件成立的情形，剩下的情形就不需要再判断了。

这一点正是它比写两条 `if` 省事的原因。第二条判断做的事，本质上就是把第一条的反面重新验一遍，而 `else` 直接替你接管了这个反面。

## 用 if...else 优化登录代码

前面接收输入和正确账号密码的部分都不用动，要改的是后半段的判断。

原来第二、第三步是两条独立的 `if`；现在第二条 `if` 不再需要，改成 `else`。

```python
# 模拟B站登录功能的实现
# 正确的账号和密码
ok_account = '18888888'
ok_password = '666888'

# 第一步：接收用户输入的账号和密码
account = input('请输入您的B站账号：')
password = input('请输入B站的密码：')

# 第二步：判断账号和密码是否全部正确，都正确则登录成功，否则登录失败
if account == ok_account and password == ok_password:
    print('登录成功')
    print('进入B站首页')
else:
    print('登录失败')
    print('账号或密码错误')
```

`else` 后面不用写任何条件，直接跟一个冒号就够。

> **易错点**：`else` 后面也必须有冒号，但冒号前面不能写条件。写成 `else account != ok_account:` 是语法错误——`else` 接受不了条件，它接管的正是「条件不成立」这个默认分支。

`else` 之后的代码同样要靠**缩进**来表示归属，前面必须有缩进，`else` 才知道这两句是它的代码块。

运行验证两次即可。输入错误账号 `99999` 和正确密码 `666888`，回车后判断账号和密码是否正确，明显账号不正确，`if` 条件不成立，程序直接进入 `else`，输出「登录失败」「账号或密码错误」。

再运行一次，输入正确的 `18888888` 和 `666888`，条件成立，输出「登录成功」「进入 B 站首页」。

对比两种写法：优化后少了整整一次条件判断。条件只有两种结局时，用 `if...else` 比堆两条 `if` 更准确，也更省。

## 闰年判断案例

第二个案例：根据用户输入的年份，判断这一年是闰年还是平年。

闰年的规则有两条：

1. **非整百年份**，且能被 4 整除的是闰年。比如 2025 年就是非整百年份。
2. **整百年份**，必须能被 400 整除才是闰年。整百年份指的是 1900 年、2000 年这样的年份。

> **提示**：第二条规定里没有单独再写「能被 100 整除」这一句，但它是自动满足的——一个数如果能被 400 整除，它必然也能被 100 整除，所以能被 400 整除的年份一定是整百年份。

需求很清楚：闰年输出这一年是闰年，不是闰年就输出平年。而一个年份要么是闰年要么是平年，二选一，所以这里用的正是 `if...else`。

### 第一步：接收年份

```python
# 根据用户输入的年份判断这一年是闰年还是平年
year = int(input('请输入需要判定的年份：'))
```

这里要参与算术运算，所以必须把键盘录入的字符串转成 `int` 类型，否则没法做取余。

### 第二步：构造闰年条件

条件是把两条规则连起来。第一条是「非整百年份且能被 4 整除」，先看它怎么判断。

**非整百年份**怎么判断？回想算术运算里的求模（也叫取余）操作。如果一个年份模于 100 的结果不等于 0，就说明它不是整百年份：

```python
year % 100 != 0
```

**能被 4 整除**怎么判断？一个数能被 4 整除，等价于它模于 4 的结果等于 0：

```python
year % 4 == 0
```

这两条之间是并且的关系，所以用 `and` 连接，这就是第一条规则：

```python
year % 100 != 0 and year % 4 == 0
```

第二条规则是整百年份能被 400 整除，直接写成模于 400 等于 0 就行：

```python
year % 400 == 0
```

### 第三步：用 or 连接两条规则

现在的关键点是：这两组条件之间用什么连接？

满足第一条是闰年，满足第二条也是闰年。也就是说，**满足其中一个就是闰年**，所以它们之间用 `or`。

这里还有个结构上的细节值得说明。第一条规则里的两个条件（非整百年份、能被 4 整除）是一个整体——必须同时成立才构成「第一类闰年」。既然是整体，就用一对括号把它括起来表示：

```python
if (year % 100 != 0 and year % 4 == 0) or (year % 400 == 0):
    print(f'{year}年是闰年')
else:
    print(f'{year}年是平年')
```

括号在这里不影响运算结果，但它让「先算什么、再算什么」一目了然。第二个条件加不加括号都行。

> **易错点**：这一行条件复杂的是它的**结构**，不是符号。判断之前先把逻辑分层——「第一类闰年」和「第二类闰年」是两个并列的成立途径，用 `or` 连；每一类内部的条件是必须同时满足的，用 `and` 连。层级对了，括号自然就写对了。

## 四组测试

条件写得对不对，靠几组边界数据验一下就清楚了。

| 输入年份 | 条件推演 | 判定结果 |
| --- | --- | --- |
| 2025 | 非整百年份但模 4 余 1，两个条件都不成立 | 平年 |
| 1900 | 整百年份，且模 400 不等于 0 | 平年 |
| 2004 | 非整百年份，且模 4 等于 0 | 闰年 |
| 2400 | 整百年份，但模 400 等于 0 | 闰年 |

2025 年不能被 4 整除，也不能被 400 整除，两条规则都够不上，所以是平年。

1900 年是最容易想错的一个：它看着像个闰年，但它是整百年份，整百年份必须被 400 整除才算闰年，而 1900 不能被 400 整除，所以它是平年。

2004 年是非整百年份，能被 4 整除就够，所以是闰年。

2400 年同样容易误判：它是整百年份，但它能被 400 整除，符合第二条规则，所以是闰年。

## 要点回顾

两个问题要明确。

第一，`if...else` 的语法：`if` 之后写对应的条件，条件成立就执行 `if` 之后的代码逻辑；条件不成立，程序会自动执行 `else` 之后的代码逻辑。`else` 之后记得有冒号。

第二，`if...else` 的注意事项有两点：

1. `else` 之后不需要写任何条件。因为 `else` 的代码是在 `if` 条件不成立时才执行的，它不需要判断。
2. `else` 的代码前面必须加上对应的缩进，通过缩进来表示这块代码是 `else` 结构下的代码。

同一份需求，写成两条 `if` 还是写成 `if...else`，差别就在于有没有看清「这件事有几种结局」。只有两种结局时，`else` 就是那个不用再判断的分支。
