# Python 软件包（Package）：模块归类与导入路径

前面两节已经把模块用起来了：项目按业务、功能、职责拆成多个模块，开发时用到哪个模块的功能就把哪个模块导入进来。但大型项目里涉及的功能模块非常多，此时为了便于项目的管理、开发以及后期的维护，我们通常会对这些模块做**归类处理**——数据处理的模块归到一类，网络应用开发的模块归到一类，常见工具操作的模块再归到一类。Python 里承担归类职责的结构，就是软件包。

## 包的本质与 `__init__.py`

软件包的英文是 package。既然模块本身就是一个 Python 文件，那么要对多个文件做归类，在物理层面最自然的做法就是**把它们放进一个文件夹**。所以：

> **定义**：软件包本质上就是一个文件夹，文件夹下可以存放若干个 Python 文件，而每一个 Python 文件都是一个模块。

比如有个 `utils` 文件夹（utils 是工具的意思），里面放了多个 `.py` 文件，每个文件都是一个模块。但文件夹并不自动等于包——包里还必须包含一个比较特殊的文件：`__init__.py`。注意它的前后同样各有两个下划线，这个文件用来描述当前包的信息。

判断规则只有一条：

> **结论**：一个文件夹里如果有 `__init__.py`，那它就是一个 Python 软件包；如果没有这个文件，那它只是个普通文件夹。

包的作用就是来管理其中的多个模块。也可以把包看成一个模块，而在这个模块下又包含若干个子模块——所以包做的事情，就是模块管理、对模块归类操作。

从结构上看，包、模块、功能之间是一层套一层的关系：

```text
utils/                  <- 包（文件夹 + __init__.py）
├── __init__.py         <- 包的描述文件
├── my_var.py           <- 模块：常量 PI、NAME
└── my_function.py      <- 模块：函数 log_separator1 ~ 4
```

读图说明：最外层是包，包的内层是一个个模块，模块内部才是一个个具体功能（变量、常量、函数等）。

## 包的创建方式

现在问题是：一个普通文件夹怎么变成软件包？右键新建一个 Python 文件，文件名写成两个下划线、`init`、再两个下划线，回车之后 `__init__.py` 就建好了。**一旦这个文件出现在文件夹下，文件夹的标识就变了**——之前在 PyCharm 里它是普通文件夹的图标，现在成了包，图标上会带一个小圆点。

创建包还有更省事的方式：在文件夹上右键新建，菜单里除了“目录”之外还有一项 **Python 软件包**，它的图标前面本来就带一个小圆圈。选中它、随便起个名字（比如 `abc`）回车，文件夹里就会自动多出一个 `__init__.py`，内容为空，这就表示它是一个软件包。

`__init__.py` 里的内容不是必须的。什么都不定义完全可以；也可以在里面描述这个包的信息：

```python
__version__ = "1.0.0"
__author__ = "黑马涛哥"
```

`__version__` 用来描述当前包的版本，`__author__` 描述包的作者。再次强调：一旦以双下划线开头，就说明这个变量不是业务当中的常规变量，而是一个特殊变量；业务中的变量通常不会带这个前缀。在项目开发中，`__init__.py` 里有时还会完成一些初始化环境准备的工作，这个阶段先不涉及。

## 导入包中模块的五种形式

有了包之后，导入的语法和导入模块类似，变化在于**模块名前面多了一级包名**。原来写模块的地方，现在写成 `包名.模块名`。

| 形式 | 语法 | 调用方式 | 导入对象 |
| --- | --- | --- | --- |
| 一 | `import 包名.模块名` | `包名.模块名.功能名` | 整个模块 |
| 二 | `from 包名 import 模块名` | `模块名.功能名` | 包下的指定模块 |
| 三 | `from 包名 import *` | `模块名.功能名` | 包下的所有模块 |
| 四 | `from 包名.模块名 import 功能名` | `功能名` | 模块中的指定功能 |
| 五 | `from 包名.模块名 import *` | `功能名` | 模块中的所有功能 |

前三种导入的都是**模块**，后两种导入的是**模块当中的功能**。调用形式依旧遵循同一条规律：`import` 后面写的是包名加模块名，调用就带上包名和模块名；`import` 后面写的是模块名，调用只带模块名；`import` 后面写的是功能名，调用直接写功能名。

## 在 PyCharm 中验证

在第二章目录下建一个 `utils` 文件夹，里面放两个模块：

```python
# utils/my_var.py
PI = 3.1415926
NAME = "黑马涛哥"
```

```python
# utils/my_function.py
def log_separator1():
    print("- " * 30)


def log_separator2():
    print("=" * 30)


def log_separator3():
    print("# " * 30)


def log_separator4():
    print("* " * 30)
```

这个 `utils` 一开始是普通文件夹还是包？**先看它下面有没有 `__init__.py`——没有，所以它是普通文件夹。** 按前面讲的方式建出 `__init__.py` 之后，它才算成为包。

接着在第二章目录下新建一个文件 `包.py`（就是拿来演示导入包中模块的），分别验证五种写法。

### 导入包中的模块

第一种写法，直接 `import`。如果在这里直接写 `import my_function`，会发现没有提示并且报错——因为这个模块在 `utils` 这个包下面，导入时必须把包名带上：

```python
import utils.my_function

utils.my_function.log_separator1()
utils.my_function.log_separator2()
```

输入 `utils.` 之后，提示里会出现包里定义的 `version`、作者这类包信息；后面跟上模块名 `my_function`。调用形式是三级：包名、模块名、功能名。

> **提示**：这类写法偶尔会遇到 PyCharm 提示“找不到 my_function”，但程序依然能正常运行，那是开发工具静态分析的问题，语法本身没问题，把提示忽略掉即可。

第二种写法，把包名放到 `from` 后面，`import` 后面写模块名：

```python
from utils import my_function

my_function.log_separator1()
```

此时 `import` 后面是模块名，所以调用时不再需要包名，写“模块名.功能名”就够了。

### 导入包下所有模块

第三种写法是把 `import` 后面的模块名替换成星号，本意是导入包下的所有模块：

```python
from utils import *

my_function.log_separator1()
my_var.PI
```

把刚才能跑通的调用代码原样复制过来，结果直接报错：未解析的 `my_function`，运行时也提示 `my_function` 未定义。原因不是语法写错了，而是**这种方式默认不允许这样导入**。

> **易错点**：要通过 `from 包名 import *` 导入包下的所有模块，必须在 `__init__.py` 文件当中添加特殊变量 `__all__`，用它指定这个星号到底代表哪些模块。没有加这个变量，导入就会失败。

在 `__init__.py` 里补上：

```python
__all__ = ["my_function", "my_var"]
```

有了这个列表，原来报错的地方立刻恢复正常，程序也能正常运行，而且此时星号代表的不只是 `my_function` 一个模块，还包括 `my_var`——可以继续输出 `my_var` 里的 `PI` 和 `NAME`。反过来，如果把这个列表中的 `my_var` 去掉，星号就只带进 `my_function`，`my_var` 用不了。

### 导入模块中的功能

最后两种形式是导入模块中的具体功能：

```python
from utils.my_function import log_separator1, log_separator3

log_separator1()
log_separator3()
```

`from` 后面写“包名.模块名”，`import` 后面写要用的功能名。既然导入的是功能，调用时直接写功能名就行，运行照常正常。

## `from` 后面是路径：相对与绝对两种写法

还有一个必须提前知道的注意事项，就藏在 `from` 后面那一串 `包名.模块名` 里——**这其实是一种路径的写法**。

`包.py` 一开始放在第二章目录下，`from utils.my_function import ...` 能正常工作，因为 Python 会在**当前 Python 文件所在的目录**下找 `utils` 这个包，而第二章目录下正好有它。现在把这个文件移动（重构）到 `my_module` 目录下，同样的代码立刻报错：未解析的引用 `utils`。因为它在 `my_module` 这个当前目录下找不到 `utils`——`utils` 并不在 `my_module` 里面。把它移回第二章目录，报错又消失了。

如果这个文件确实要放在 `my_module` 目录下，还有另一种写法：**用绝对路径**。绝对路径指从项目的根目录开始找：

```python
from 第二章.utils.my_function import log_separator1
```

绝对路径的查找顺序是：从项目根目录出发，先找第一级目录“第二章”，第二章下有 `utils` 这个包，包下有 `my_function` 这个模块，于是找到目标。用这种写法，把文件移到第二章目录外面，依然能正常运行——因为它不从当前文件所在目录找起。

| 写法 | 查找起点 | 举例 | 找不到时的表现 |
| --- | --- | --- | --- |
| 相对路径 | 当前文件所在目录 | `from utils.my_function import ...` | 报未解析的引用 |
| 绝对路径 | 项目根目录 | `from 第二章.utils.my_function import ...` | 路径正确即可用 |

两种写法都可以用，选哪种取决于文件放在哪里、想不想让代码对目录位置敏感。

> **提示**：这个阶段为了减轻学习负担，文件夹名、包名和文件名的演示一律用了中文，方便查看和理解；中文运行起来其实也没问题。但实际项目开发中，文件夹名、包名和文件名一般都是英文。

## 三个要抓牢的问题

包这部分内容收尾时，把该记住的东西归成三块。

**第一，什么是包，包有什么作用。** 包的本质是一个文件夹，用来管理 Python 当中的多个模块；通过包对模块做归类处理，从而方便项目的管理和后期的维护。

**第二，`__init__.py` 的作用有两个。** 一是标识当前目录是一个包，而不是普通文件夹——普通文件夹里加上这个文件，就变成了软件包；二是用来描述当前包的信息，包括在其中声明 `__all__` 特殊变量，指定 `import *` 到底导入哪些模块。

**第三，导入包的方式多种多样。** 可以用 `import 包名.模块名` 直接导入模块，也可以在 `from` 后面跟包名、`import` 后面跟模块名导入模块，这三种都属于导入包当中的指定模块；后两种则是导入包下模块当中的特定功能。特别要注意的是，如果要导入包下的所有模块（`from 包名 import *`），必须在 `__init__.py` 中声明 `__all__`，用它来指定要导入哪些模块。

到此，Python 模块的基本操作就讲完了。模块在实际项目中的应用场景以及一些高级用法，会在后面的案例中继续剖析和使用。
