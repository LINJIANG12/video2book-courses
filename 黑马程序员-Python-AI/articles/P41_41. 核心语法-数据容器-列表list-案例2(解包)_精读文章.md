# 列表合并与去重：in 运算符与星号解包

接下来要完成的需求是：把两个列表合并成一个，再对合并后的结果做去重。

先看数据。`number_list1` 和 `number_list2` 里都带着重复值：54 一共出现 3 次（`number_list1` 里两次、`number_list2` 里一次），123 出现 2 次（两个列表各一次）。列表这种容器本来就允许同一项数据重复出现，所以两个列表往一起一拼，重复值会原封不动地跟过来——这正是合并之后必须再做一次去重的原因：重复的元素只保留一个，多出来的去掉。

照写程序的习惯，先把需求拆成两步：

1. 合并列表；
2. 去除重复记录。

这两步走完，再把合并那一步的写法简化一遍。

## 1 第一步：遍历第二个列表，逐个追加到第一个列表

最基础的合并方式不需要新列表：把第二个列表的元素按顺序取出来，一个个加到第一个列表的末尾，循环结束后第一个列表里装的就是两个列表的全部元素。

```python
for number in number_list2:
    number_list1.append(number)

print(number_list1)
```

`for number in number_list2` 逐个取出第二个列表的元素，`number` 就是当次取到的那个元素；`append` 是列表往末尾添加元素的方法，把 `number` 追加到 `number_list1` 的结尾。循环跑完，`number_list1` 就成了合并后的列表。

运行输出里，开头是 123、54（来自 `number_list1`），接着是 55、80、72 这些（来自 `number_list2`）——两个列表的元素确实接到了一起，但重复值也一起进来了。

> **提示**：这种写法的开销挂在循环次数上。第二个列表若有一万个元素，这个循环就要跑一万次；看着只有两行代码，实际执行是按元素个数一次一次追加的。

## 2 第二步：用 in 判断是否已存在，再决定要不要追加

去重的做法是再开一个列表存结果，遍历合并后的列表，把元素一个一个搬过去；搬之前先判断目标列表里有没有这个元素——没有才追加，已经有了就跳过。

```python
new_list = []                       # 存放去除重复记录之后的列表
for number in number_list1:         # number_list1 此时是合并后的列表
    if number not in new_list:
        new_list.append(number)

print(new_list)
```

关键就在这个判断上。Python 提供的成员运算符是 `in`：`元素 in 列表` 用来判断这个元素是否存在于列表当中，运算结果只有布尔值两种。

```python
number in new_list      # 存在于列表中 → True
number in new_list      # 不存在于列表中 → False
```

> **定义**：`in` 是成员运算符，用来判断某个元素是否存在于容器（这里是列表）当中，运算结果是 `True` 或 `False`。

要的是"不存在才添加"，所以得把判断结果取反。取反用的是逻辑运算符 `not`（另外两个是 `and`——并且、`or`——或者），把它加在 `in` 前面，`not in` 的意思就是"不在"。

```python
number not in new_list  # 不在列表中 → True
```

于是 `if number not in new_list` 读作"如果 number 不在 new_list 里"，条件成立才追加；一旦 `new_list` 里已经存了这个值，条件不成立，这次什么也不做。

反过来写就白干了：不套判断、直接 `new_list.append(number)`，最后 `new_list` 与合并后的列表一模一样，等于没有去重。

拿重复了三次的 54 看一眼去重的过程：

```text
遍历到的元素    判断 not in 的结果          动作
第 1 个 54      True，列表里还没有 54       追加，new_list 中出现 54
第 2 个 54      False，列表里已有 54        跳过
第 3 个 54      False，列表里已有 54        跳过
```

读图说明：同一个值第 2 次、第 3 次经过时判断不成立，追加那一步被 `if` 直接跳过——这就是去重真正发生的位置。

运行验证：合并后的原始列表里 54 有 3 个、123 有 2 个；去重后的列表里 54 只剩 1 个、123 只剩 1 个。第二步功能完成。

## 3 简化写法一：星号解包构造新列表

上面合并列表那两行还有简化空间，一行就能写完。

先把概念立住：列表这类容器本身是一个整体，整体里装着一项一项的数据。**解包**就是把这个整体解开，变成一个一个独立的元素——把一个列表里的元素一个个"拿出来"，再放进新的列表里，这个过程就叫解包。

> **定义**：解包是把容器这个整体解开成一个个独立的元素；组包则是把多个值合并到一个容器里。

两者的关系可以这么记：解包相当于把箱子里的东西一件件拿出来，组包是把几件东西一起塞进一个箱子。有了这两个动作，两个列表就能合成一个。

写法上，在列表名前加一个星号 `*` 就表示对它解包：

```python
number_list = [*number_list1, *number_list2]    # 合并后的新列表
print(number_list)
```

外层的中括号表示要新建一个列表；`*number_list1` 把第一个列表解开，元素一个个放在这个位置上；列表的多个元素之间用逗号分隔，所以两个解包之间要有逗号；`*number_list2` 再把第二个列表解开。两组独立元素合在一起，就构成了合并后的新列表。

运行结果与第一种方式一致：两个列表合并成功。去重的逻辑不必改动，只是遍历的对象从原来的 `number_list1` 换成这个新的 `number_list`。

## 4 简化写法二：直接用加号合并

合并两个列表还有一种更直接的方式——加号：

```python
number_list = number_list1 + number_list2        # 合并后的新列表
print(number_list)
```

`number_list1 + number_list2` 直接把两个列表合并成一个新列表。运行验证：列表合并成功，去重之后 54、123 同样各只剩一个，与前面两种方式的结果完全一致。

## 5 三种合并方式的对照

| 合并方式 | 写法 | 特点 |
| --- | --- | --- |
| 遍历 + `append` | `for number in number_list2: number_list1.append(number)` | 思路最直观，但要按元素个数逐个追加，元素多时开销大，不推荐 |
| 星号解包 | `[*number_list1, *number_list2]` | 一行构造新列表，元素直接摊进新列表 |
| 加号运算 | `number_list1 + number_list2` | 一行完成，写法最直接 |

> **结论**：要快速合并两个列表，用 `+` 或星号解包；要判断某个元素是否存在于列表当中，用 `in`，取反就用 `not in`。

判断存在性这条单独记一笔：`in` 的运算结果一定是布尔值，为 `True` 表示该元素在列表当中，为 `False` 表示不在。前面的去重正是靠 `in` 加上 `not` 取反来把关的——元素不在新列表里才让它进来。
