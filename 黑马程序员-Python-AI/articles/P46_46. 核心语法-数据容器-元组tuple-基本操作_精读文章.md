# 元组 tuple 的定义、特点与基本操作

## 1 有了列表，为什么还需要元组

数据容器学到第三种——元组（tuple）。它和列表一样，也能存储多项数据。但在动手之前，先得回答一个听上去有点别扭的问题：既然列表已经能把多项数据存起来了，为什么还要再学一个元组？

答案要去列表自己的特点里找。列表有三大特点：可以存储多项元素，元素可以重复；元素有序；**列表当中所有的元素都是可以修改的**。

问题就出在第三条上。项目开发中会遇到这样一种场景：需要存储一组数据，但这组数据是固定不变的——只能用来做查询，不能进行修改。这时候还能用列表存吗？不能。因为列表的元素天生就是可改的，用它来装一份「不该改」的数据，等于把保险柜的锁拆了只留门。

> **定义**：元组一旦定义完成，里面所有的元素就不允许修改，只能够进行查询。可变与不可变，就是元组和列表最大的不同点，也是元组存在的意义。

所以选容器的判断依据很直接：这组数据将来会不会变？会变就用列表；只查不改，就用元组。

## 2 元组的定义与特点

元组是一种不可变的序列，类似列表，但一旦创建之后就不能再做修改操作。

它的特点可以从两个层面记。和列表相同的地方：可以存储不同类型的元素；元素可以重复；元素有序。和列表唯一不同的地方：里面的元素不可以修改。由于元组同样是一种序列类型，它照样支持索引访问，也支持切片操作，访问方式与切片方式跟列表完全一致。

> **结论**：元组与列表类似，两者唯一的区别是一个可变、一个不可变。可变指的是元素可以修改，不可变指的是元素不可以修改。

定义元组把小括号用起来，元素之间用逗号分隔：

```python
# 定义一个有元素的元组
t1 = (80, 95, 78, 50, 76, 80, 85, 20)
```

`t1` 是元组对象的名字，后面用小括号括起来，括号里罗列要存储的元素。里面的元素可以重复——上面这个元组里 `80` 就出现了两次。

定义空元组有两种写法：

```python
# 方式一：直接写一对小括号
t2 = ()

# 方式二：调用 tuple
t3 = tuple()
```

`tuple` 这里是一个函数。两种方式都能定义出空元组，但方式一更简洁更高效，所以空元组直接写一对小括号就行。

## 3 两个查询方法：count 与 index

元组的方法很少，常用的就两个。原因也简单：元组不支持任何修改操作，只能查询，方法自然全都跟查询统计相关。

| 方法 | 作用 | 返回值要点 |
| --- | --- | --- |
| `count` | 统计元素在元组中出现的次数 | 出现几次就返回几次 |
| `index` | 查找某个元素在元组中的索引位置 | 元素重复时返回**第一次**出现的位置 |

这两个方法和列表的同名方法作用类似。但 `index` 有一个必须留意的点：元组允许存在重复元素，所以 `index` 返回的是匹配到的第一次出现的位置。比如用 `index` 去查 `5` 的位置，拿到的就是第一个 `5` 对应的索引。

> **易错点**：元素在元组里出现多次时，`index` 只给第一个匹配位置，它不会告诉你后面还有没有。想知道一共有几个，还得用 `count`。

## 4 索引访问与切片

元组是有序序列，所以可以按索引取元素，正向索引和反向索引都行。

```python
t1 = (80, 95, 78, 50, 76, 80, 85, 20)

print(t1[0])    # 80，第一个元素
print(t1[-1])   # 20，最后一个元素
print(type(t1))
```

`t1[0]` 取到的是第一个元素 `80`，`t1[-1]` 取到的是最后一个元素 `20`。用 `type` 看一下类型，输出是 `<class 'tuple'>`，`tuple` 代表的就是元组类型。

切片语法与列表切片一致，切出前面 5 个元素：

```python
print(t1[0:5])   # (80, 95, 78, 50, 76)
```

索引从 `0` 开始，所以索引为 `5` 的位置其实是第 6 个元素，切片不包含结束位置，`0:5` 取到的正好是前 5 个。

## 5 不可修改：赋值一改就报错

真正把元组和列表区分开的行为，是修改元素的那一刻。往元组里重新赋值，程序会立刻报错：

```python
t1 = (80, 95, 78, 50, 76, 80, 85, 20)

t1[0] = 100      # TypeError: 'tuple' object does not support item assignment
```

错误信息说得很清楚：元组对象不支持这项赋值操作。开发工具同样会在这一行下面直接标红，提示元组不支持重新赋值，因为它是不可变的。

> **提示**：报错本身就是元组的价值所在。一份不允许被改动的数据，被误改时当场中断，比悄悄改掉之后再往下跑安全得多。

`count` 与 `index` 的实际效果，用同一个元组验证一下：

```python
t1 = (80, 95, 78, 50, 76, 80, 85, 20)

print(t1.count(80))   # 2，80 出现了两次
print(t1.index(80))   # 0，第一个 80 的位置是 0
```

元组里有两个 `80`，所以 `count` 返回 `2`；而 `index` 返回的是第一个 `80` 的索引，也就是 `0`。

> **提示**：在对象后面敲一个点，编辑器里弹出的候选方法就是这两个——`count` 和 `index`。候选列表里还会带出一些以双下划线开头结尾的东西，那属于面向对象的内容，后面讲到类的时候再展开，目前只用这两个方法。

## 6 定义元组时的注意事项

### 6.1 空元组

```python
t2 = ()
print(t2)         # ()
print(type(t2))   # <class 'tuple'>
```

里面什么都不写，直接一对小括号，定义出来的就是空元组，类型依然是 `tuple`。

### 6.2 单元素元组必须加逗号

想定义一个只有单个元素的元组时，最直觉的写法是错的：

```python
t3 = (100)
print(type(t3))   # <class 'int'>
```

这里 `t3` 不是元组，而是 `int` 类型。编辑器也会在下面画一条波浪线，提示可以移除这个冗余的圆括号——因为这样写和直接写 `t3 = 100` 效果完全一样。

原因是小括号在 Python 里的身份不止一个。它除了用来定义元组，还用来把表达式括起来。前面讲运算符时为了提高优先级用过括号，讲多条件判断时为了让条件成为一个整体也用过括号。当括号里只有一个元素时，解释器会认为这就是一个普通的括号，而不是在定义元组。

> **易错点**：定义单元素元组，必须在元素后面加一个逗号。`(100)` 是整数 `100`，`(100,)` 才是元组。

```python
t3 = (100,)
print(t3)         # (100,)
print(type(t3))   # <class 'tuple'>
```

加上逗号之后，元组里就只有一个元素 `100`，类型是 `tuple`。

## 7 小结

这一段要立住三个点：

1. **元组的特点**——元素可以重复、元素有序、元素不可以修改。它是只读的，只能查询，不能修改；
2. **两个查询方法**——`count` 统计元素数量，`index` 获取指定元素的索引；元素不存在时 `index` 会报错，这一点可以自己动手测一下；
3. **单元素元组加逗号**——比如 `a,` 就代表定义了一个单元素元组。
