# 逻辑运算符：多个条件之间的连接方式

前面三类运算符，算术运算符、赋值运算符和比较运算符，跟我们数学课上的运算符长得很像，看一眼就知道是干什么的。今天要说的这一类不一样，逻辑运算符多半是你们第一次接触，所以先不急着讲语法，我们从一个买东西的场景说起。

假设我现在要去京东上买一台电脑。我的需求有三条：价格在 1 万块钱以内；得是大品牌；还得是高配置。你们想一下，这三条之间是什么关系——是随便满足一条我就能下单，还是必须同时都成立？

必须同时成立。价格得在 1 万以内，而且得是大品牌，并且还得是高配置，少一条这台电脑都不符合我的要求。这三个条件之间，是**并且**的关系。

现在换个场景。我要点外卖，我的需求是：要么评分最高的餐厅，要么配送最快的餐厅。这回是两个条件同时成立才行吗？不是了，只要满足其中一个就算符合我的需求——评分最高的那家可以，配送最快的那家也可以。这时候两个条件之间是**或者**的关系。

> **定义**：逻辑运算符（logical operator）就是用来连接多个条件表达式的运算符。在 Python 里，上面说的「并且」写作 `and`，「或者」写作 `or`，它们都是逻辑运算符中的一种。

所以逻辑运算符的定位很清楚：它自己不产生条件，只负责把已经写好的多个条件接到一起。

## 逻辑运算符的运算结果

逻辑运算符连接的叫条件表达式，而条件表达式的结果本身就是一个布尔值（boolean），要么真要么假，真就是 `True`，假就是 `False`。

需要特别记住的是，逻辑运算符运算之后返回的结果**也是布尔值**。这一点和我一开始的直觉不太一样：我以为把两个条件连起来，得到的是「合并后的条件」，其实得到的是一个确定的值——`True` 或者 `False`，它回答的是「这多个条件整体上到底成立还是不成立」。

> **结论**：`True` / `False` 进出，`True` / `False` 出来。两端都是布尔值，中间那段才是逻辑运算符在做的连接工作。

## 三类逻辑运算符及其判定规则

逻辑运算符一共三个：`and`、`or`、`not`。

### 逻辑与 and

`and` 就是我们说的并且，术语叫逻辑与。「与」就是「并且」，含义是必须同时成立才算符合条件。

比如有两个条件表达式，中间用 `and` 连起来。它的判定规则是：

- 只有 `and` 左右两侧都是 `True`，整个表达式的结果才是 `True`；
- 只要左边或者右边有任何一个是 `False`，整体结果就是 `False`。

写出来就是 `a < b and b < c` 这种形式，意思是「你得满足第一个，并且还得满足第二个」。

### 逻辑或 or

`or` 代表逻辑或，就是或者的意思，只要多个条件里有一个符合就可以了。

判定规则正好和 `and` 相反：

- 有一个条件成立，结果就是 `True`——左侧成立得到 `True`，右侧成立得到 `True`，两侧都成立同样得到 `True`；
- 只有左右两个表达式的结果**都是** `False`，结果才是 `False`。

### 逻辑非 not

`not` 叫逻辑非，「非」就是取反。`True` 取反变成 `False`，`False` 取反变成 `True`，就是一个取反操作。

这一节里 `not` 只讲了含义，具体的写法后面用到的时候再展开。

三个运算符放在一起看，判定规则可以对照着记：

| 运算符 | 名称 | 含义 | 结果为 `True` 的条件 |
| --- | --- | --- | --- |
| `and` | 逻辑与 | 并且 | 左右两侧同时为 `True` |
| `or` | 逻辑或 | 或者 | 至少有一侧为 `True` |
| `not` | 逻辑非 | 取反 | 操作数为 `False` |

> **易错点**：`and` 和 `or` 记反是这一段最常见的翻车方式。可以这样抓：`and` 要求苛刻，两边全 `True` 才给 `True`；`or` 要求宽松，有一个 `True` 就放行。苛刻的那个对应「并且」，宽松的那个对应「或者」。

## 案例一：判断一个整数是否落在 10 到 20 之间

需求是：在键盘上录入一个整数，判断这个数字是否在 10 到 20 之间，在就输出 `True`，不在就输出 `False`。

先把条件拆出来。一个数字要落在 10 到 20 之间，它得大于等于 10，并且还得小于等于 20。两个条件之间是 `and` 还是 `or`？是 `and`——「大于等于 10」和「小于等于 20」这两条必须同时成立，这个数字才在区间内。

代码写出来是这样：

```python
# 从键盘录入一个整数
number = int(input('请输入一个整数：'))

# 判断这个数字是否在 10 到 20 之间
print(f'{number}在10到20之间：', number >= 10 and number <= 20)

# and 连接的条件是并且的关系：左右两侧的运算结果都是 True，结果才是 True
# 左右两侧有任何一个不成立，结果就是 False
```

这里有个必须交代清楚的点：`input` 从键盘接收到的数据**都是字符串类型**。要做数字之间的大小比较，就得先把字符串转成数字，所以外面套了一层 `int()`。字符串转数字用的是内置工具 `int`，把 `input` 的结果传进去，拿到的就是数字类型。

写法上还能再省一步。既然 `input` 的结果马上要交给 `int` 处理，中间就不必先用一个变量接住字符串再转换——直接把 `int(input(...))` 连起来写，变量 `number` 接到的就已经是数字类型了。上面代码用的就是这种写法。

现在跑几个值验证一下整条判定链：

- 输入 `5`：`5 >= 10` 吗？不大于。第一个条件不成立，只要有一个不成立结果就是 `False`，输出 `False`。
- 输入 `15`：`15 >= 10` 成立，`15 <= 20` 也成立，两侧同时成立，输出 `True`。
- 输入 `60`：`60 >= 10` 成立，但 `60 <= 20` 不成立，这个条件运算的结果是 `False`，整体也就是 `False`，输出 `False`。

`and` 的行为在这里看得很直白：两侧都成立才是 `True`，否则一律 `False`。

> **提示**：整段代码下面那条波浪线是 IDE 给的提示，说这里有「简化链式比较」。点一下它给的按钮，`number >= 10 and number <= 20` 会被自动改写成 `10 <= number <= 20`，效果完全一样。这种连续比较是 Python 特有的写法，知道它存在就行；这一段我们为了看清 `and` 的连接作用，仍然用两侧分别写条件的写法。

## 案例二：判断一个整数是否不在 10 到 20 之间

第二个需求：从键盘输入一个整数，判断这个数字是否**不在** 10 到 20 之间。

先想清楚「不在 10 到 20 之间」意味着什么。这个数字要么小于 10，要么大于 20，两种情况占其一，它就落在区间外面。

那么这两个条件之间用 `and` 还是 `or`？这次是 `or`。因为它不需要同时满足——小于 10 的满足第一条，大于 20 的满足第二条，只要满足其中一个，这个数就不在区间里。

```python
# 从键盘录入一个整数
number = int(input('请输入一个整数：'))

# 判断这个数字是否不在 10 到 20 之间
print(f'{number}不在10到20之间：', number < 10 or number > 20)

# or 连接的条件是或者的关系：只要其中有一个成立，结果就是 True
# 全部不成立，结果才是 False
```

结构上和第一个案例几乎一样，`input` 加 `int()` 的输入部分不用动，只把后半段的判定条件从「大于等于 10 且小于等于 20」换成「小于 10 或大于 20」。

同样试几个值：

- 输入 `1`：`1 < 10` 成立，有一个条件成立结果就是 `True`，输出 `True`。
- 输入 `15`：第一个条件不成立，第二个条件也不成立，两个都是 `False`。所有条件都不成立，结果才是 `False`，输出 `False`。
- 输入 `56`：第一个条件不成立，但第二个条件 `56 > 20` 成立，结果同样是 `True`，输出 `True`。

一个数在区间里，两个案例给出的结论正好相反，这也顺便说明了「在区间内」和「不在区间内」的判断为什么各用一个运算符：前者要求两个边界条件**都**守住，后者只要求突破**任一**边界。

## 实际开发中的应用场景：登录条件

逻辑运算符在真实项目里到处都是，拿 B 站登录页面举两个例子就够了。

登录要输入用户名和密码。点下登录按钮之后，程序要校验用户名是否正确、密码是否正确。那么什么时候才算登录成功？这两个条件之间是 `and` 还是 `or`？

是 `and`。用户名必须正确**并且**密码也必须正确，缺一个都进不去，两者之间是并且的关系。

再看另一个场景：登录方式有好几种，可以扫左侧的二维码登录，可以基于密码登录，也可以用短信方式登录。这三种方式之间又是什么关系？

是 `or`。你采用其中任意一种方式登录就可以了，不需要三样同时来一遍，所以这里用或者连接。

> **结论**：判断逻辑运算符该用哪个，不必背规则，问自己一句——这些条件得**全部**满足，还是**满足一个就行**。全部满足用 `and`，满足一个就行用 `or`。

应用场景远不止这些，这里只是开个头。真正要拿到手的是 `and` 和 `or` 的区别，以及看到需求时能判断出该用哪一个。
