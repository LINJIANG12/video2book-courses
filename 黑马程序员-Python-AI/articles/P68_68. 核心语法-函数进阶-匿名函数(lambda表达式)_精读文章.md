# 匿名函数与 lambda 表达式

函数的参数讲完了，函数进阶还剩第三块：**匿名函数**。它其实是函数定义的另一种方式，特点就写在名字里——没有名字。这一节要弄清两件事：匿名函数的定义语法，以及它到底该在什么时候用。

## 从命名函数到匿名函数

先回顾原来的写法。定义函数要用关键字 `def`：`def` 后面跟函数名，再跟参数列表，下一行缩进写函数体。这种写法定义出来的函数**是有名字的**，所以叫**命名函数**。比如定义一个输出分割线的 `out_line`，再定义一个计算两数之和的 `add`，名字就是它们的调用入口——要调用就写函数名加括号。

匿名函数既然没有名字，就不能再用 `def` 声明，而是要用一个表达式来定义：**lambda 表达式**。

```python
lambda 参数列表: 函数体
```

逐段看这个语法：先写关键字 `lambda`，空格之后跟参数列表；因为匿名函数没有函数名，函数名这部分直接省略，`lambda` 之后紧接参数列表；参数列表后面是冒号，冒号后面直接写函数体的逻辑。

这里有一条硬约束：lambda 是一个**表达式**，不能换行。也就是说参数列表冒号后面直接接函数体，整个东西写在一行里。

> **易错点**：lambda 表达式声明的函数只能承载**一个单行表达式**。逻辑一旦需要多行，就无法用 lambda 声明匿名函数，只能用命名函数。

换句话说，lambda 只适用于简单函数——里面的逻辑非常短，通常就是一个单行的表达式。

### 无参数的匿名函数

拿 `out_line` 来改写，它就是输出一行分割线，没有参数。

原来的命名函数是 `def out_line():` 加一行 `print`。改成匿名函数：`out_line` 这个名字整个省掉；括号里本来就没有参数，所以 `lambda` 后面什么也不写，直接跟冒号，表示这是一个无参的匿名函数；冒号后面写函数体逻辑，也就是那个 `print`。

```python
lambda: print("----------------")
```

按代码风格，冒号后面习惯留一个空格。

### 带参数的匿名函数

再拿 `add` 改写，它要接收 `x`、`y` 两个参数。

同样是先省掉名字：`lambda` 后面直接写参数列表，多个参数之间用逗号分隔；冒号后面写函数体。

```python
def add(x, y):          # 命名函数的写法
    return x + y


lambda x, y: x + y      # 匿名函数的写法
```

注意参数列表里原来就有 `x, y`，直接拿过来用，而函数体那一行原本是 `return x + y`——在 lambda 里**不能写 `return`**。

## 返回值的处理

lambda 会自动把表达式的运算结果返回，相当于替你把 `return` 做了，所以编写时不用写，写了反而会报错。

匿名函数可以返回结果，也可以不返回：上面那个输出分割线的匿名函数只做打印，不需要返回；`lambda x, y: x + y` 需要把和返回出去，它靠自动返回完成。

> **结论**：lambda 的函数体只写表达式本身，`return` 一概省略——有返回值时自动返回，没有返回值时表达式自然也不产生结果。

## 赋值给变量才能调用

定义好这两个匿名函数，其实还完全用不上——因为它们只有定义、没有调用。没被调用的函数永远不会执行。

问题在于它们没有名字，根本没法直接调。要调用就得把匿名函数**赋值给一个变量**：

```python
out_line = lambda: print("----------------")
add = lambda x, y: x + y

out_line()
result = add(100, 200)
print(result)
```

等号左边现在是一个变量名，右边是一个函数——这个变量本质上就是那个函数，所以可以像调用函数一样用变量名加括号调用它。这里 `out_line` 和 `add` 只是恰好与原来命名函数同名；如果上面已经用 `def` 定义过同名函数，名字就重复了，得先把上面那段注释掉。

## 在 PyCharm 里跑两个需求

准备两个需求：打印一条分割线、计算两个数之和。每个需求先用命名函数写一遍，再用匿名函数写一遍作对比。

第一段是 `out_line`。用 `def` 定义好之后，敲 `lambda`，编辑器会自动提示补全；没有参数，所以 `lambda` 后面直接一个冒号，冒号后写 `print` 那句输出。这时候编辑器把这一行标黄了——鼠标悬停提示「该语句似乎不起任何作用」。原因就是匿名函数没有名字，永远不会被调用。在它前面加一个变量接住这个函数，标黄提示随之消失。调用 `out_line()`，右键运行，分割线输出正常。相比于有名字的写法，这套语法的确更简洁。

第二段是 `add`。命名函数的版本是接收 `x`、`y` 两个参数，函数体直接 `return x + y`。改写成匿名函数：先写 `lambda`，接着跟上参数列表 `x, y`，冒号后面把原来 `return` 后面那段逻辑拿过来。这里要把 `return` **删掉**——lambda 里写了 `return` 就会报错，它会自动返回表达式的结果。开头同样报黄（函数不会被调用），所以前面加变量 `add` 接住，上面那段命名函数注释掉。调用时传 `100` 和 `200`，打印返回值，运行得到 300。

## 把 lambda 用作 sort 的 key

前两个需求只是为了熟悉语法，真正体现匿名函数价值的是第三个需求：

> 完成如下列表的排序操作：按照每一个元素的字符个数从小到大排序。

看到需求第一反应一般是——列表本身就有排序方法。回想一下，列表排序调用的方法是 `sort`。

```python
data_list = ["Python", "C", "Java", "C++", "Go", "JavaScript", "PHP", "Rust", "Jack"]
data_list.sort()
print(data_list)
```

把排序后的 `data_list` 输出出来就能看到结果——列表是可变类型，排序改的就是这个列表本身，输出它就是排好序的样子。运行之后，第一个元素变成了 `C`，接着 `C++`、`Go`……已经排好序了。但这是按什么排的？**不是**按字符个数，而是按字母的先后来排的，这跟字符编码有关（编码这块后面讲文件操作时会详细说）。看 `Jack` 和 `Java` 的先后就能确认不是按长度：两个都是 4 个字符，却是 `Jack` 在前面，原因是第一位相同就比第二位，第二位又相同就比第三位，`c` 排在 `v` 前面。顺着这个规则，`Jack` 在 `Java` 前面，`Java` 后面接着 `JavaScript`，再往后是 `PHP`、`Python`，而 `r` 排在 `p` 之后，所以 `Rust` 落在最后。

需求要的是按**字符个数**从小到大排：按长度算，第一位应该是 `C`（一个字符），第二位是 `Go`，第三位是 `PHP` 和 `C++`（都是三个字符）。默认的排序方式满足不了这个要求。

好在 `sort` 提供了自定义排序方式的入口。把鼠标悬停在 `sort` 上，下方会显示这个列表方法的说明文档；说明书里还有一个超链接，点开就是 `sort` 方法的官方文档。

> **提示**：官方文档是英文的，可以用翻译软件，或者把段落复制进翻译软件看。但翻译结果只能作参考——这类专业文档直译过来，常常和原意差得比较远。

文档里这个方法的签名是 `sort(key=None, reverse=False)`，也就是可以传两个参数：`key` 和 `reverse`。方法本质上也是一个函数，这两个就是函数的两个参数；而 `key=None`、`reverse=False` 正是前面讲过的**函数参数设置默认值**——`key` 默认 `None`，`reverse` 默认 `False`。

重点是 `key`。文档里说明 `key` 指定的东西是 a function——一个**函数**。这个函数的作用是：它会被应用到列表中的每一个元素上（each item in the list），做一次计算，然后依据这个计算的结果来决定元素的排序顺序。说白了，`key` 决定了「按什么排」。

具体写法上，`key` 用关键字传参的方式指定；它要的值是一个函数，而这个函数只在这一个位置用一次，别处不需要调用——正是匿名函数的典型用武之地，直接写 lambda。这个匿名函数接收一个参数，取值就是列表里的每一个元素，所以参数名写 `item`。

排序依据是字符个数，也就是字符串长度，用内置函数 `len` 来算：

```python
data_list.sort(key=lambda item: len(item))
print(data_list)
```

这个 lambda 每次拿到一个元素就返回它的长度，而表达式的结果会被自动返回，返回的结果就是排序依据。

运行看效果：第一位是 `C`，第二位是 `Go`，第三位是 `C++` 和 `PHP`，接着是 `Jack`、`Java`、`Rust`（三个都是 4 个字符），最后是 `JavaScript`。确实按字符个数从小到大排好了。

```text
排序依据             元素
len = 1              C
len = 2              Go
len = 3              C++   PHP
len = 4              Jack  Java  Rust
len = 10             JavaScript
```

读图说明：`key` 对每个元素调用一次 lambda，取出它的长度作为排序依据，再按依据的大小给元素排队——元素本身没变，变的只是排序时比较什么。

## 用 reverse 控制排序方向

想从大到小排也可以。刚才文档里的两个参数，除了 `key` 还有一个 `reverse`，它翻译过来就是「反转」的意思，默认值 `False` ——不反转，也就是正向排。想反转就把它设为 `True`：

```python
data_list.sort(key=lambda item: len(item), reverse=True)
print(data_list)
```

运行之后顺序就倒过来了。

> **结论**：`key` 决定按什么排序，`reverse` 决定正序还是倒序。需求是按字符个数从小到大，所以不用写 `reverse` ——它的默认值 `False` 已经是正向。

这就是匿名函数最典型的应用场景：**作为方法调用的参数，或者作为高阶函数的参数传递**；前提是这个函数逻辑足够简单，一行代码或者一个简单表达式。

## 命名函数与匿名函数的选择

学到这里，函数定义方式有两种了：`def` 定义的命名函数，lambda 定义的匿名函数。项目开发里怎么选？

选择匿名函数的前提是同时满足两个条件：逻辑比较简单，**并且**只在一个地方调用。因为匿名函数在语法结构上确实更简洁。它的典型位置就是给高阶函数传参——调用某些高阶函数时需要传入另一个函数，这时可以用 lambda 声明匿名函数直接传进去；调用某些方法时参数里需要传函数，也可以这么传。

除此之外都建议使用命名函数。具体来说，以下情况必须用命名函数：

| 情形 | 说明 |
| --- | --- |
| 逻辑比较复杂 | 需要多步操作，一个单行表达式装不下 |
| 需要重复使用 | 在多个地方都要调用 |
| 参数需要文档说明 | 要给函数中每一个参数加详细的文档说明 |

> **结论**：只需记住一个原则——**代码的可读性和可维护性比简洁性更重要**。简洁是 lambda 的优势，但它不是选择 lambda 的理由。
