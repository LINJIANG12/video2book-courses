## 13 操作CMOS RAM芯片
> 对应分集：P71 | 原始标题：《13 操作CMOS RAM芯片》

不知道大家在日常使用计算机时是否注意到一个有趣的现象：当电脑关机拔掉电源插头，即便放置十天半个月甚至几个月，再次插上电源开机，屏幕右上角或者 BIOS 设置里的系统时间依旧分秒不差地走动着；我们在 BIOS 里设置好的硬盘参数、光驱配置、启动顺序，也从来不会因为断电而丢失。

普通 RAM 内存只要一断电，内部存储的二进制数据瞬间就会灰飞烟灭。那计算机到底把这些关键的系统配置和实时时间藏在了哪里？答案就在主板上一块非常特殊的集成电路芯片——CMOS RAM。

要想在汇编语言层面与这块芯片对话、读取当前的实时时钟，我们必须使用上一讲学到的核心工具：端口。这一讲就以操作 CMOS RAM 芯片为例，带大家彻底跑通外设芯片的双端口读写闭环。

---

### CMOS RAM 物理架构与存储职能

在 PC 计算机的主板上，集成了一块专用的 CMOS RAM 芯片。这块芯片虽然物理体积不大，但在整个系统引导与运行过程中扮演着不可替代的角色。

```text
主板 CMOS RAM 芯片供电与结构拓扑：

+-------------------------------------------------------------+
|                      主板电路系统                            |
|                                                             |
|   +---------------+                  +------------------+   |
|   | 3V 纽扣电池    |──(持续微弱供电)─►|  CMOS RAM 芯片   |   |
|   | (CR2032 等)   |                  |                  |   |
|   +---------------+                  |  +------------+  |   |
|                                      |  | 实时时钟RTC|  |   |
|   +---------------+                  |  +------------+  |   |
|   | 8086 CPU 核心 |                  |  | 128B RAM   |  |   |
|   +-------┬-------+                  |  +------------+  |   |
|           │                          +────────▲─────────+   |
|           │ 系统总线 (地址/数据/控制)         │              |
|           └───────────────────────────────────┘              |
+-------------------------------------------------------------+
```
*图说明：主板纽扣电池为 CMOS RAM 芯片提供独立持续供电，使其在主机断电后仍能维持 RTC 走时与 128 字节配置数据不丢失。*

CMOS RAM 芯片主要由两大部分构成：
1. **实时时钟（RTC，Real-Time Clock）**：相当于一块集成在芯片内部的持续运行的高精度电子表，负责记录年、月、日、时、分、秒；
2. **RAM 存储器**：具有 128 个存储单元（总容量恰好为 128 个字节，编号范围为 $0 \sim 127$，即 $00\text{H} \sim 7\text{FH}$）。

在这 128 个字节的紧凑空间内，严格规划存储着三项核心数据：
- **实时时钟数据**：动态记录当前的年月日、时分秒；
- **系统硬件配置信息**：包括系统安装的软驱/光驱规格、硬盘型号与参数、键盘配置、主板扩展设备状态等；
- **系统引导程序与状态校验**：计算机刚开机时，BIOS 会首先读取 CMOS RAM 中的配置数据来核对当前硬件环境。如果 CMOS 数据校验出错或电池没电，系统会立刻发出报警并强制停留在 BIOS 界面提示按 F1 继续。

CMOS 工艺制作的芯片功耗极低，主板上配备的一颗纽扣电池（如常见的 CR2032）足以支撑其持续工作数年之久。正是凭借这块电池源源不断地供电，关机断电后，实时时钟能够继续精准跳动，128 个字节中的配置参数也不会丢失。

### 70H 与 71H 双端口访问机制

在 8086 体系结构的 64KB 独立端口地址空间中，系统并没有为 CMOS RAM 的 128 个字节分配 128 个连续的端口号，而是极其巧妙地仅仅使用了两个端口：`70H` 和 `71H`。

> **定义**：
> - **地址端口（`70H`）**：用于存放接下来要访问的 CMOS RAM 内部存储单元的地址（范围 $0 \sim 127$）；
> - **数据端口（`71H`）**：用于向选定的存储单元写入数据，或从选定的存储单元中读取数据。

```text
CPU 与 CMOS RAM 端口读写时序逻辑：

   8086 CPU                      端口寄存器               CMOS RAM (128B)
+-------------+               +--------------+         +------------------+
|             | 1. OUT 70H,AL |  70H 端口    | 内部选址 | 00H 单元 (秒)    |
|   AL = 08H  |──────────────►| (地址寄存器) |────────►| ...              |
|             |               +--------------+         | 08H 单元 (当前月)|
|             | 2. IN AL, 71H +--------------+ 内部读取 | ...              |
|   AL <──────┼───────────────|  71H 端口    |◄────────| 7FH 单元         |
|   (读得数据)|               | (数据寄存器) |         +------------------+
+-------------+               +--------------+
```
*图说明：访问 CMOS RAM 必须严格遵循“先向 70H 端口写入单元地址，再从 71H 端口读写数据”的两步操作时序。*

为什么不直接把这 128 个单元映射成 128 个端口？因为端口资源在微型计算机体系中是非常宝贵且有限的。通过“索引/数据”分离的双端口设计（也称为间接寻址端口模式），系统只耗费了两个外部端口号，就能轻松掌控内部成百上千个功能寄存器。

因此，无论读取还是修改 CMOS RAM 中的任何一个字节，都必须且只能分为严格的两步：
1. **第一步（选址）**：将目标存储单元的地址编号送入 `AL`，执行 `OUT 70H, AL`，通知芯片内部地址译码器定位到该单元；
2. **第二步（传输）**：执行 `IN AL, 71H` 从数据端口读入该单元的内容，或者将新数据送入 `AL` 后执行 `OUT 71H, AL` 写入该单元。

### CMOS 时间数据分布与 BCD 码格式

现在我们明确一个具体任务：**编写一个程序，在屏幕中央显示当前的月份**。

要获取当前的月份，首先必须清楚实时时钟在 CMOS RAM 中的具体存放位置。实时时钟共占用 6 个字节，各个时间分量的地址分配如下表所示：

| 存储单元地址 | 对应时间信息 | 长度 |
| :--- | :--- | :--- |
| `00H` | 秒（Seconds） | 1 字节 |
| `02H` | 分（Minutes） | 1 字节 |
| `04H` | 时（Hours） | 1 字节 |
| `07H` | 日（Day of Month） | 1 字节 |
| `08H` | 月（Month） | 1 字节 |
| `09H` | 年（Year） | 1 字节 |

这 6 个单元各占 1 个字节，月份数据存放在 `08H` 号单元。

然而从 `08H` 单元读出来的字节并不能直接当作常规二进制整数进行数值计算，因为 CMOS RAM 中的时间数据全部采用 **BCD 码（Binary-Coded Decimal，二-十进制编码）** 存储。

```text
以 5 月（05）与 15 日（15）为例的 BCD 码字节结构：

一个字节（8位）：   D7  D6  D5  D4     D3  D2  D1  D0
                  +---------------+   +---------------+
                  |  十位数 (高4位)|   |  个位数 (低4位)|
                  +---------------+   +---------------+
05 月:               0   0   0   0       0   1   0   1     => 05H
15 日:               0   0   0   1       0   1   0   1     => 15H
```
*图说明：压缩 BCD 码用 1 个字节表示 2 位十进制数，高 4 位代表十位数值，低 4 位代表个位数值。*

在 BCD 码中，每一个十进制数字（$0 \sim 9$）用 4 位二进制数来表示。对于 $0 \sim 9$ 范围内的数字，其 4 位二进制表示与原数值完全相同：
- $0$ 表示为 `0000B`；
- $5$ 表示为 `0101B`；
- $9$ 表示为 `1001B`。

如果当前是 5 月份，CMOS 的 `08H` 单元存放的内容就是十六进制的 `05H`（二进制 `0000 0101B`）：高 4 位是十位数 `0`，低 4 位是个位数 `5`。如果是 12 月份，存放的则是十六进制的 `12H`（二进制 `0001 0010B`）。

### 数据转换与显存输出实现

清楚了存储地址和数据格式，要完成在屏幕上打印出当前月份的任务，就可以拆解为三个清晰的技术环节：
1. 从 CMOS RAM 的 `08H` 单元读取月份的 BCD 码；
2. 将 BCD 码的高 4 位与低 4 位分离开来，分别转换为对应的 ASCII 码字符；
3. 将字符及其显示属性写入显存，居中呈现在屏幕上。

#### 核心读写指令

读取月份的汇编代码非常简明：

```assembly
mov al, 8
out 70h, al              ; 将欲读取的单元号 08H 送入地址端口 70H
in al, 71h               ; 从数据端口 71H 读出月份的 BCD 码到 AL
```

执行完毕后，`AL` 中即锁存了当前月份的原始 BCD 码。

#### BCD 码转换为 ASCII 码

假设读入 `AL` 的数据是 `05H`（即二进制 `0000 0101B`），为了能在显示器上打印，必须将十位上的 `0` 和个位上的 `5` 拆开，并分别转换成字符 `'0'` 和 `'5'` 的 ASCII 码。

数字 $0 \sim 9$ 对应的 ASCII 码是 $30\text{H} \sim 39\text{H}$。也就是说，将任何一个一位十进制数字加上 $30\text{H}$（十进制 48），就得到了它的 ASCII 码字符：
$$0 + 30\text{H} = 30\text{H} \quad (\text{'0'})$$
$$5 + 30\text{H} = 35\text{H} \quad (\text{'5'})$$

数据分离的具体操作方法如下：
- 先把 `AL` 中的数据完整备份一份到 `AH` 中；
- 将 `AH` 中的内容逻辑右移 4 位（`shr ah, 4`，或者屏蔽低 4 位后右移），使高 4 位的十位数移动到低 4 位，高位补 0；
- 将 `AL` 中的内容与 `00001111B`（`0FH`）进行逻辑与操作，屏蔽掉原有的高 4 位，只保留低 4 位的个位数；
- 分别给 `AH` 和 `AL` 加上 $30\text{H}$，此时 `AH` 中保存十位字符的 ASCII 码，`AL` 中保存个位字符的 ASCII 码。

#### 显存中央定位与字符写入

在标准 80×25 文本显示模式下，显存地址空间从 `B8000H` 开始，每行 80 个字符，每屏 25 行。每个字符在显存中占 2 个字节：
- **偶数地址**：存放字符的 ASCII 码；
- **奇数地址**：存放字符的显示属性（颜色等）。

一整行占用 $80 \times 2 = 160$ 个字节。若要在屏幕正中央（第 12 行，第 40 列附近）显示两个字符：
$$\text{显存偏移地址} = 12 \times 160 + 40 \times 2 = 1920 + 80 = 2000$$

我们将段寄存器 `ES` 指向显存段 `0B800H`，把十位字符写入 `es:[2000]`，个位字符写入 `es:[2002]`，属性字节使用默认（或指定绿色/亮白），即可稳稳居中显示。

### 完整汇编源程序

下面将上述逻辑整合为一段完整可编译运行的汇编程序：

```assembly
assume cs:code

code segment
start:
    ; 1. 从 CMOS RAM 8 号单元读取当前月份数据
    mov al, 8
    out 70h, al          ; 写入单元地址 8
    in al, 71h           ; 读出月份 BCD 码

    ; 2. 分离高低位并转换为 ASCII 码
    mov ah, al           ; 备份数据到 AH
    mov cl, 4
    shr ah, cl           ; AH 右移 4 位，获取十位数值
    and al, 00001111b    ; AL 屏蔽高 4 位，获取个位数值

    add ah, 30h          ; 十位数值转为 ASCII 字符
    add al, 30h          ; 个位数值转为 ASCII 字符

    ; 3. 写入 80x25 彩色显存缓冲区 (第 12 行第 40 列)
    mov bx, 0b800h
    mov es, bx

    ; 写入十位字符与属性 (02H 表示黑底绿字)
    mov byte ptr es:[160*12 + 40*2], ah
    mov byte ptr es:[160*12 + 40*2 + 1], 02h

    ; 写入个位字符与属性
    mov byte ptr es:[160*12 + 40*2 + 2], al
    mov byte ptr es:[160*12 + 40*2 + 3], 02h

    ; 4. 返回 DOS
    mov ax, 4c00h
    int 21h

code ends
end start
```

#### 代码要点精析

1. **`out 70h, al` 与 `in al, 71h` 的寄存器限制**：
   端口读写指令 `IN` 和 `OUT` 规定，传输 8 位数据时必须使用累加器 `AL`，严禁使用 `BL`、`CL`、`DL` 等其他通用寄存器。
2. **`shr ah, cl` 的移位规则**：
   在 8086 汇编中，当逻辑移位位数大于 1 时，移位次数必须预先存入 `CL` 寄存器中，再执行移位指令。
3. **显存写入的字节对齐**：
   屏幕上的每一个字符位置由连续的两个字节构成。十位字符写入偏移 `2000`（ASCII 码）和 `2001`（属性），个位字符紧随其后写入 `2002` 和 `2003`，保证字符紧密排列。

## 14 外设连接与中断
> 对应分集：P72 | 原始标题：《14 外设连接与中断》

在学习了如何利用 `IN` 和 `OUT` 指令读写端口之后，我们已经掌握了 CPU 直接与主板外设芯片对话的手段。但是大家不妨深思一个现实问题：

如果计算机没有中断，当用户敲击键盘时，或者当网络芯片接收到远端的数据包时，CPU 怎么知道外部数据已经到达了？难道必须编写一个无限死循环，不停地执行 `IN AL, 60H` 去一遍遍轮询端口？如果 CPU 把宝贵的算力全都耗费在死等外设上，其他程序还怎么运行？

计算机体系结构绝对不会采用这种笨拙的死等方式。外部设备有了动静，必须有一种机制能够主动“拍一拍”CPU 的肩膀，让 CPU 暂时放下手头的活计转来接待它——这就是**外中断机制**。

这一讲我们就把视角从 CPU 内部转移到外设接口芯片，彻底理清外设连接、端口交互与外中断响应的底层运转机理。

---

### CPU 数据空间与外设连接体系

我们先从微观硬件视角重新审视 CPU 的寻址版图。8086 CPU 在运转时，能够读写数据的地方一共有且仅有三处：
1. **内部通用寄存器**（如 `AX`、`BX`、`CX`、`DX`、`SI`、`DI`、`BP`、`SP`）：集成在 CPU 核心内部，访问速度极快；
2. **内存地址空间**（`00000H` $\sim$ `FFFFFH`）：共 1MB 实模式物理内存，存放操作系统的代码段、数据段和栈段；
3. **I/O 端口地址空间**（`0000H` $\sim$ `FFFFH`）：独立编址在 64KB 空间内，直接连接着主板各个外设芯片内部的寄存器。

```text
CPU 与外设连接总线模型：

                +-----------------------------+
                |        8086 CPU 核心        |
                +-----------------------------+
                   ▲           ▲           ▲
                   │           │           │
       数据/地址总线│           │           │ 中断请求线 (INTR / NMI)
                   │           │           │
                   ▼           ▼           │
             +-----------+ +-----------+   │
             | 键盘接口  | | 网卡/显卡 |   │
             | 芯片 60H  | | 接口芯片  |   │
             +-----------+ +-----------+   │
                   ▲           ▲           │
                   │           │           │
                   └─────┬─────┘           │
                         │ 硬件中断信号     │
                         └─────────────────┘
```
*图说明：CPU 通过数据总线和 I/O 端口读写外设，而外设则通过独立的中断请求信号线反向通知 CPU 响应事件。*

端口是外部设备接入 CPU 的门户。但是请牢记：**端口本身只是被动的存储单元**。外设芯片内部准备好了数据，并不能直接强行塞进 CPU 的寄存器里；而 CPU 也不可能全天候无休止地监控端口。

因此，外设操作必须由“中断”与“端口”协同完成：
- **事件发生阶段**：外部设备动作（例如键盘按下一个键），产生硬件信号向 CPU 发起中断请求；
- **响应处理阶段**：CPU 捕获中断并暂停当前任务，跳转到专门的中断处理程序；
- **数据收发阶段**：中断处理程序在 CPU 内部执行 `IN` 或 `OUT` 指令，安全、及时地与外设端口完成数据交互。

---

### 内中断与外中断的本质分野

在前面的课程中，我们已经深入接触过中断的概念，但当时面对的全部属于**内中断**。现在随着外设的引入，计算机的中断家族正式划分为内、外两大阵营：

```text
8086 体系中断分类全景拓扑：

                      +-----------------------+
                      |      8086 中断系统    |
                      +-----------------------+
                                  │
            ┌─────────────────────┴─────────────────────┐
            ▼                                           ▼
  +--------------------+                     +--------------------+
  |       内中断       |                     |       外中断       |
  | (CPU 执行指令引发) |                     | (外部硬件引脚触发) |
  +--------------------+                     +--------------------+
     │              │                           │              │
     ▼              ▼                           ▼              ▼
+----------+  +------------+              +------------+ +------------+
| 硬件异常 |  | 软件中断   |              | 可屏蔽中断 | |不可屏蔽中断|
| 除法溢出 |  | INT n 指令 |              | (INTR引脚) | | (NMI引脚)  |
| 单步陷阱 |  | INTO 指令  |              | 受 IF 控制 | | 强制响应   |
| (0号/1号)|  | (系统调用) |              | (键盘/时钟)| | (掉电/校验)|
+----------+  +------------+              +------------+ +------------+
```
*图说明：内中断由指令执行在 CPU 内部产生；外中断由外部设备在 CPU 引脚上产生，并进一步分为可屏蔽与不可屏蔽两大类。*

> **定义**：
> - **内中断**：由 CPU 内部事件引起的中断。当 CPU 执行指令过程中发现除法溢出（0 号）、单步陷阱（1 号），或者主动执行 `INT n` 指令时，由 CPU 控制部件在芯片内部直接触发；
> - **外中断**：由 CPU 外部设备发生的硬件事件引起的中断。外设接口芯片通过主板走线直接拉高或拉低 CPU 芯片上的物理中断引脚，强行引起 CPU 的注意。

### 可屏蔽中断与不可屏蔽中断

外部硬件事件千差万别，有些只是日常敲键盘、移动鼠标，有些则是机房着火、主机掉电。为此，8086 将外中断精确分流为两类：**可屏蔽中断** 与 **不可屏蔽中断**。

#### 可屏蔽中断的响应准则

可屏蔽中断是指 **CPU 拥有决定权、可以选择不予理睬的外部中断**。
外部设备通过 CPU 的 `INTR`（Interrupt Request）物理引脚向 CPU 发送请求信号。

CPU 到底响不响应这个外设请求，完全取决于标志寄存器（FLAGS）中的 **`IF`（Interrupt Flag，中断允许标志位）**：
- **当 $IF = 1$ 时**：CPU 处于开中断状态。当执行完当前正在运行的那一条指令后，CPU 会立刻响应外部中断，转去执行中断例程；
- **当 $IF = 0$ 时**：CPU 处于关中断状态。无论外部接口芯片如何发出中断请求信号，CPU 均不予理会（屏蔽请求），继续执行自己手头的原程序。

几乎所有日常由外部设备引发的中断，全都是可屏蔽中断（例如键盘输入、定时器时钟节拍、鼠标移动、串行通信、打印机就绪等）。

这种设计体现了极高的工程智慧：CPU 必须保留最高主动权。当操作系统正在执行一段生死攸关的底层核心代码（如正在调整任务调度队列或修改段寄存器），绝不允许中途被用户随便敲一下键盘给打断。此时只要置 $IF = 0$，CPU 就能专心致志地把关键逻辑跑完，然后再开中断处理键盘事件。

#### 不可屏蔽中断的强制响应

不可屏蔽中断（NMI，Non-Maskable Interrupt）则是 **CPU 必须无条件响应、没有任何商量余地的极危中断**。
外部信号通过 CPU 专用的 `NMI` 物理引脚输入。

只要不可屏蔽中断信号到来，无论此时标志寄存器里的 $IF$ 到底等于 1 还是等于 0，CPU 在执行完当前指令的最后一个时钟周期后，**必须强制暂停当前工作**，立刻引发不可屏蔽中断过程！

对于不可屏蔽中断，8086 体系结构做出了铁律级别的硬性规定：**其中断类型码固定为 2**，不需要外部芯片传送类型码，直接寻址中断向量表中的 2 号向量。

不可屏蔽中断专门留给系统遇到必须处理的十万火急的灾难性事件：
- **电源掉电警报**：稳压电源在交流电断开后，电容滤波电路通常还能维持数毫秒至数十毫秒的平稳直流供电。电源监控电路一旦检测到掉电，立即通过 NMI 触发 2 号中断，CPU 利用这最后的十几毫秒紧急保存重要现场、写回磁盘缓存，完成关机自保；
- **内存奇偶校验严重出错（RAM Parity Error）**：内存硬件出现位翻转，继续运行将导致数据严重毁坏，系统立即通过 NMI 蓝屏停机。

在生死存亡面前，没有任何外设可以抢占通道，这种“不可屏蔽”的霸道逻辑是极其合情合理的。

### 外中断的硬件响应时序

我们重点剖析日常编程中最常接触的**可屏蔽中断**的内部响应流程。当外部设备产生事件并提交中断后，CPU 在硬件电路上会经历严格的五大步骤：

```text
可屏蔽中断微观硬件响应时序图：

           外部设备                      8086 CPU 核心
              │                                │
        (1)   │ 发送中断请求 (INTR 引脚拉高)   │
              ├───────────────────────────────►│
              │                                │ 检测 IF 标志：
              │                                │ 若 IF=0，忽略请求
              │                                │ 若 IF=1，进入响应周期
              │                                │
        (2)   │ 外部数据总线送入中断类型码 N   │
              ├───────────────────────────────►│ 读入类型码 N
              │                                │
              │                                │ (3) PUSHF (标志寄存器入栈)
              │                                │ (4) IF = 0, TF = 0 (关中断)
              │                                │ (5) PUSH CS, PUSH IP (保存现场)
              │                                │ (6) 查中断向量表:
              │                                │     IP = [N*4]
              │                                │     CS = [N*4+2]
              │                                │ 跳转执行中断例程
```
*图说明：可屏蔽中断响应过程包含获取外部类型码、保护标志位、关闭中断、现场入栈以及根据向量表重置 CS:IP。*

#### 可屏蔽中断五步响应机理

1. **获取中断类型码**：
   可屏蔽中断源自 CPU 外部。CPU 在确认 $IF = 1$ 后，向系统控制总线发出两个连续的中断响应周期脉冲（$\overline{\text{INTA}}$），外部中断控制芯片（如 8259A PIC）接收到脉冲后，将其内部准备好的中断类型码（假设为 $N$）放置到数据总线上，CPU 从数据总线将其读取到内部暂存器中。
   > **对比**：内中断（如除法错误 0 号中断、`INT n` 指令）的中断类型码是在 CPU 指令译码内部天然生成的，完全不需要通过外部总线去读取。
2. **标志寄存器入栈**：
   执行类似 `PUSHF` 的硬件动作，将当前的 `FLAGS` 寄存器压入栈顶保存。
3. **设置 IF 与 TF 为 0**：
   硬件自动将标志寄存器中的 $IF = 0$ 和 $TF = 0$。
   - **将 $IF$ 置 0 的目的**：禁止其他可屏蔽中断在当前中断处理程序刚开始执行时插入进来，保证例程前期的原子性。如果在例程内部允许中断嵌套，程序员可以在处理程序中显式执行 `STI` 指令重新开放中断；
   - **将 $TF$ 置 0 的目的**：关闭单步中断，避免在进入中断例程时引发连续的单步调试循环。
4. **当前 CS 与 IP 入栈**：
   将当前的段寄存器 `CS` 与偏移指针 `IP` 依次压入栈中，为中断处理完毕后的返回（`IRET`）保留现场断点。
5. **设置新的 IP 和 CS**：
   根据读取到的中断类型码 $N$，CPU 计算出其中断向量在内存起始段的绝对位置：
   $$\text{IP 偏移} = [N \times 4]$$
   $$\text{CS 偏移} = [N \times 4 + 2]$$
   从中断向量表中取出新例程的入口地址，直接赋给 `IP` 和 `CS`，CPU 随即跳转执行中断服务程序。

#### 不可屏蔽中断响应机制

对于不可屏蔽中断，处理流程高度相似，但有两个关键差异：
1. **无需读取类型码**：其硬件类型码固定为 2，硬件直接寻址中断向量表中的 2 号向量（`0000:0008H`）；
2. **硬件时序更简单、响应更快**：
   - 标志寄存器入栈，并将 $IF = 0$、$TF = 0$；
   - `CS`、`IP` 入栈；
   - 装入 2 号中断向量，转向执行。

### 标志位操作指令与两类外中断对比

在汇编编程中，既然 $IF$ 标志位决定了 CPU 是否理睬外部设备，那么程序员如何主动掌控这一开关？8086 提供了两条极其精炼的单字节指令：

```assembly
cli     ; Clear Interrupt flag  => 将 IF 清除为 0 (禁止外部可屏蔽中断)
sti     ; Set Interrupt flag    => 将 IF 设置为 1 (允许外部可屏蔽中断)
```

这两条指令极其好记：
- **`CL`** 代表 Clear（清除、置零），`I` 代表 Interrupt；
- **`ST`** 代表 Set（设置、置一），`I` 代表 Interrupt。

> **规范**：在需要修改段寄存器（如同时修改 `SS` 和 `SP` 切换栈底）、或者修改中断向量表等极度敏感的操作前，先执行 `CLI` 关中断，操作完毕后再执行 `STI` 开中断，这是编写健壮底层汇编程序的铁律。

最后，我们将两类外中断的核心特征归纳对比：

| 比较维度 | 可屏蔽中断（INTR） | 不可屏蔽中断（NMI） |
| :--- | :--- | :--- |
| **硬件物理引脚** | CPU 的 `INTR` 引脚 | CPU 的 `NMI` 引脚 |
| **受控标志位** | 受标志寄存器 $IF$ 严格控制 | 不受 $IF$ 影响，强制执行 |
| **中断类型码来源** | 由外设中断控制器通过数据总线送入 | 体系结构固定绑定为 2 号 |
| **典型应用场景** | 键盘、鼠标、时钟、串口、打印机等日常外设 | 掉电预警、硬件校验致命错误等系统崩溃级事件 |
| **系统设计哲学** | 给 CPU 调度自主权，按需处理与排队 | 灾难自保，绝对优先，无条件立刻执行 |

至此，外设如何与端口连接、如何通过硬件引脚向 CPU 发起求助、以及 CPU 如何分流处置两类外中断的整个物理逻辑闭环已经完全清晰。在下一讲中，我们将以最典型的外设——PC 键盘为例，实地追踪敲下一个键引发的系统级风暴。

### 键盘物理开关与扫描码生成

当我们坐在电脑前敲击键盘时，物理层面究竟发生了什么？

在电气结构上，键盘上的每一个按键本质上就是一个**机械开关**：
- 当用力按下按键时，按键触点接触导通，开关闭合；
- 当手指抬起松开按键时，弹簧回弹，开关断开。

```text
键盘输入与主板接口芯片交互物理拓扑：

+--------------------+                 +----------------------------+
|     键盘外壳       |                 |       PC 主机主板          |
|                    |                 |                            |
|  [按键开关矩阵]    |                 |   +--------------------+   |
|        │           |   串行数据线    |   | 键盘接口芯片       |   |
|        ▼           |   (PS/2 协议)   |   | (8042 控制器)      |   |
|  +---------------+ |                 |   |                    |   |
|  | 键盘内部微处理 | |────────────────►|   |  +--------------+  |   |
|  | 芯片 (8048等)  | | 逐字节发送扫描码|   |  | 端口 60H 寄存器|  |   |
|  +---------------+ |                 |   |  +-------▲------+  |   |
+--------------------+                 |   +──────┼───┼───────+   |
                                       |          │   │           |
                                       | 9号中断线│   │ 读操作    |
                                       |          │   │ (IN AL,60H|
                                       |   +──────┴───┴─────+     |
                                       |   |    8086 CPU    |     |
                                       |   +----------------+     |
                                       +----------------------------+
```
*图说明：键盘内部微处理器扫描按键通断，生成 1 字节扫描码送入主板 60H 端口寄存器，并引发 CPU 的 9 号外中断。*

在键盘内部，集成了一块小型的微处理器芯片（例如经典的 Intel 8048 或后续单片机）。这块芯片以极高的频率不间断地扫描整个按键开关矩阵：
1. **按下感知**：一旦检测到某一个按键被按下（开关闭合），芯片内部会立即生成一个**代表该按键物理位置的编码**；
2. **送入端口**：键盘芯片通过键盘连线，将这个编码传送给计算机主板上的键盘接口芯片（如 Intel 8042 控制器），并锁存在其输入缓冲寄存器中；
3. **端口地址**：这个键盘输入缓冲寄存器在系统的 64KB I/O 空间中被固定编址为 **`60H` 端口**。

不仅按下一个键会产生编码，**松开按键的瞬间同样会被芯片捕获**：
当手指抬起、按键弹起断开时，键盘内部芯片会再次生成一个代表该按键已被释放的编码，并同样发送到主板的 `60H` 端口中。

这意味着：**用户在键盘上的每一次按击，硬件上都会产生两次独立的事件与编码传输——一次按下，一次释放。** CPU 通过读取 `60H` 端口，能够精准掌控按键动作的全生命周期。

### 通码、断码与编码数学规律

这种由键盘内部芯片产生、用来标识按键状态的 8 位（1 字节）二进制代码，统称为**扫描码（Scan Code）**。

> **定义**：
> - **通码（Make Code）**：按下一个键时产生的扫描码；
> - **断码（Break Code）**：松开一个键时产生的扫描码。

#### 通码与断码的位级对应规律

通码与断码的长度均为 1 个字节。对于同一个物理按键，其通码和断码的**低 7 位是完全一致的**，唯一的区别就在于**最高位（第 7 位，Bit 7）**：
- **通码的最高位固定为 0**（二进制形如 `0xxxxxxxB`）；
- **断码的最高位固定为 1**（二进制形如 `1xxxxxxxB`）。

```text
通码与断码的二进制位结构对比：

        Bit 7   Bit 6  Bit 5  Bit 4  Bit 3  Bit 2  Bit 1  Bit 0
通码:  +------+-----------------------------------------------+
       |  0   |         物理按键位置特征码 (低 7 位)          |
       +------+-----------------------------------------------+
断码:  +------+-----------------------------------------------+
       |  1   |         物理按键位置特征码 (低 7 位)          |
       +------+-----------------------------------------------+
```
*图说明：断码由通码最高位置 1 形成，两者的低 7 位完全相同，在数值上相差 80H。*

由此可以推导出一个极其简明普适的数学关系式：
$$\text{断码} = \text{通码} + 80\text{H}$$

我们以字母键 `G` 为例：
- 按下 `G` 键时，产生的通码是 $22\text{H}$（二进制 `0010 0010B`）；
- 松开 `G` 键时，产生的断码是 $\text{A2H}$（二进制 `1010 0010B`）；
- 验证关系：$22\text{H} + 80\text{H} = \text{A2H}$。

再以数字键 `1` 为例：通码为 `02H`，松开产生的断码即为 `82H`。键盘上的所有常规物理按键，无一例外均严格遵循这一数学法则。

#### 扫描码与 ASCII 码的本质区别

很多初学者容易将扫描码与字符的 ASCII 码混为一谈，这是必须澄清的技术辨析：
1. **无连续递增规律**：ASCII 码中字母是连续排列的（`'A'` 是 $41\text{H}$，`'B'` 是 $42\text{H}$），但扫描码由键盘内部的矩阵走线决定。例如 `A` 键的通码是 $1\text{EH}$，`B` 键的通码是 $30\text{H}$，二者数值完全不相邻；
2. **扫描码不分大小写**：扫描码只记录物理按键位置。无论键盘当前处于大写还是小写状态，只要敲击同一个物理键 `A`，送入 `60H` 端口的通码永远是 $1\text{EH}$。

### 键盘按键分类与 9 号中断触发

从功能属性上，键盘上的全部按键可以划分为三大类别：

| 按键分类 | 典型按键代表 | 硬件与系统处理特性 |
| :--- | :--- | :--- |
| **字符键** | 字母键（A~Z）、数字键（0~9）、符号键、空格等 | 敲击后产生文本内容，最终需要转换为对应 ASCII 码并存入输入缓冲区 |
| **控制键** | `Shift`、`Ctrl`、`Alt` 等 | 单独按下不产生可见字符，主要与字符键组合使用，改变输入性质 |
| **切换键** | `CapsLock`（大小写锁定）、`NumLock`（数字键盘）、`ScrollLock`、`Insert` | 具有双稳态开关属性，按一下开启，再按一下关闭 |

#### 引发 9 号中断的硬件时序

当按键事件发生后，主板系统如何介入处理？整体逻辑分为三个环环相扣的节点：

```text
键盘输入与 9 号外中断触发时序：

1. 按下物理键 ────► 2. 扫描码存入 60H 端口 ────► 3. 接口芯片向 CPU 发送
   (开关闭合)          (等待 CPU 取走)              INTR 信号 (中断号 = 9)
                                                               │
                                                               ▼
6. 执行 int 9 ◄──── 5. CPU 响应并转入 ◄──── 4. CPU 检测到 IF=1,
   中断服务例程        9号中断入口                     保护现场, 置 IF=0
```
*图说明：键盘硬件检测到按键后将扫描码置入 60H 端口，紧接着拉高硬件中断线，触发 CPU 的 9 号可屏蔽中断服务。*

1. **存入端口**：键盘扫描码通过串行线送达主板键盘控制器，稳稳写入 `60H` 端口；
2. **硬件发信**：键盘接口控制器立即向可编程中断控制器（8259A PIC）提交请求，PIC 向 8086 CPU 发送**中断类型码为 9 的可屏蔽外中断信号**；
3. **响应中断**：8086 CPU 执行完当前指令后，检测到外部有中断请求，且若标志寄存器中 $IF = 1$：
   - 标志寄存器入栈（`PUSHF`）；
   - 置 $IF = 0$（关闭中断屏蔽）、$TF = 0$；
   - 当前 `CS`、`IP` 入栈保护；
   - 依据中断类型码 9，检索中断向量表 `0000:0024H`，取出段地址和偏移地址赋给 `CS` 和 `IP`，CPU 随即跳转执行 **`int 9` 中断例程**。

### BIOS 键盘缓冲区与键盘状态字节

当 CPU 跳转进入 BIOS 预装的 `int 9` 中断例程后，系统如何保存我们敲击的内容？这依赖于内存中的两处核心数据结构。

#### BIOS 键盘缓冲区的环形存储结构

针对日常输入的**字符键**，系统将其保存在 **BIOS 键盘缓冲区**中。

> **定义**：**BIOS 键盘缓冲区**是系统引导时在内存数据区（`0040H` 段）开辟的一段专门用于存放 `int 9` 例程所解析键盘输入的循环队列空间。

- **容量限制**：缓冲区一共可以容纳 **15 个键盘输入**；
- **存储规格**：每一个按键输入在缓冲区中严格占用 **1 个字单元（Word，共 2 个字节 / 16 位）**：
  - **高字节（High Byte）**：存放该按键的**扫描码**；
  - **低字节（Low Byte）**：存放该按键对应的**字符码（ASCII 码）**。

```text
BIOS 键盘缓冲区单个按键存储格式：

        +───────────────────────────────────+
        |  15  14  13  12  11  10   9   8   |  高位字节: 扫描码 (如 A 键为 1EH)
        +───────────────────────────────────+
        |   7   6   5   4   3   2   1   0   |  低位字节: ASCII 码 (如 a 为 61H)
        +───────────────────────────────────+
```
*图说明：缓冲区中的每个按键单元均包含 2 个字节，高地址存扫描码，低地址存 ASCII 码。*

例如，当用户在键盘上依次连续敲击字母 `A`、`B`、`C`：
- `A` 键写入：高字节存扫描码 $1\text{EH}$，低字节存 ASCII 码 $61\text{H}$（字数据为 `1E61H`）；
- `B` 键写入：高字节存扫描码 $30\text{H}$，低字节存 ASCII 码 $62\text{H}$（字数据为 `3062H`）；
- `C` 键写入：高字节存扫描码 $2\text{EH}$，低字节存 ASCII 码 $63\text{H}$（字数据为 `2E63H`）。

键盘缓冲区依次被填入 3 个字单元。后续应用程序如果调用 DOS 的 `int 21h` 或 BIOS 的 `int 16h` 读取按键，就是从这个缓冲区中依序将字数据提走。

#### 键盘状态字节（0040:0017H）

对于控制键（`Shift`、`Alt`、`Ctrl`）和切换键（`CapsLock`、`NumLock`），按下它们并不产生直接的字符输出，因此它们**绝不会被写入上述键盘缓冲区**。

系统在内存中规划了一个极其关键的系统状态单元——**键盘状态字节**，物理地址固定在 **`0040:0017H`**。

该字节的 8 个二进制位分别独立充当一把开关，实时记录当前键盘各控制键与切换键的通断状态：

```text
键盘状态字节 (0040:0017H) 位结构映射表：

Bit:    7        6        5        4        3        2        1        0
    +--------+--------+--------+--------+--------+--------+--------+--------+
    | Insert |CapsLock|NumLock |Scroll  | Alt    | Ctrl   |左Shift |右Shift |
    | 状态   | 状态   | 状态   | Lock   | 状态   | 状态   | 状态   | 状态   |
    +--------+--------+--------+--------+--------+--------+--------+--------+
```
*图说明：0040:0017H 单元的 8 个二进制位分别监控 8 类控制键与切换键的激活状态。*

- **第 6 位（Bit 6，CapsLock）**：记录大小写锁定状态。为 1 表示处于大写锁定状态，此时按字母键将产生大写 ASCII 码；再次按下 CapsLock 键，该位变为 0，恢复小写状态；
- **第 0 位（Bit 0，右 Shift）**：记录右侧 Shift 键状态。按下右 Shift 键时该位置 1，手指松开后立刻置 0。

程序通过检查或直接修改 `0040:0017H` 单元中的各个位，就能在软件层面完全掌控键盘的当前输入状态。

### int 9 中断例程核心执行逻辑

当 9 号中断触发、进入 BIOS 的默认中断处理程序后，`int 9` 在幕后有条不紊地执行以下核心逻辑：

1. **读取端口数据**：执行 `in al, 60h`，从 `60H` 端口读入当前的扫描码；
2. **按键性质分流**：
   - **如果读入的是控制键或切换键**：
     解析通码或断码，依据具体动作翻转或修改 `0040:0017H` 状态字节中的对应位；
   - **如果读入的是字符键的通码**：
     - 首先读取 `0040:0017H` 状态字节，检查当前是否按下了 `Shift` 或开启了 `CapsLock`；
     - 结合状态标志，在 BIOS 预置的字符映射表中进行检索，查出该扫描码对应的标准 ASCII 码；
     - 将 1 字节扫描码与 1 字节 ASCII 码拼装为一个 16 位的字；
     - 写入内存中的 BIOS 键盘缓冲区队列；
3. **硬件应答与收尾**：
   向主板键盘接口芯片以及 8259A 中断控制器发出中断服务完成的应答信号（EOI，End of Interrupt），通知硬件可以解除锁定、继续接收下一次按键；
4. **中断返回**：执行 `IRET` 指令，恢复标志寄存器与 `CS:IP`，原被中断的程序无缝恢复执行。

## 16 定制键盘输入处理
> 对应分集：P74 | 原始标题：《16 定制键盘输入处理》

在上一讲中，我们彻底弄清了键盘敲击后系统底层的硬件流动：从扫描码产生、写入 `60H` 端口，到硬件触发 9 号外中断，再到 CPU 调用 BIOS 预装的 `int 9` 例程将字符送入缓冲区。

这是操作系统为我们设计好的标准行为。但在实际工程开发中，特别是开发底层工具、游戏或者全屏控制系统时，我们往往需要实现某些“离经叛道”的定制功能：
比如，当屏幕上正在播放一段字符动画时，如果用户按下 `ESC` 键，我们并不想让程序退出，而是希望屏幕上的字符立即变色；而当用户按下其他常规按键时，依然保持系统原有的输入和处理能力。

这就带来了一个核心问题：**我们该如何介入系统的中断机制，让自己的代码在按键发生时抢先执行，同时又不必推翻重写整个复杂的键盘驱动？**

这一讲，我们就来亲自编写一段汇编程序，实现对键盘输入的定制拦截与 9 号中断的临时接管。

---

### 键盘定制需求与总体设计策略

我们首先确立本次实战的具体业务目标：
1. 在屏幕正中央依次动态显示英文字母 `'A'` 到 `'Z'`，每个字母停留片刻，让人眼能够清晰捕捉到字符的递增变化；
2. 在字符递增显示的过程中，若用户按下键盘上的 `ESC` 键，则屏幕中央当前显示的字符立即改变颜色；
3. 对于除 `ESC` 之外的任意其他按键，保持原系统的处理逻辑不变。

```text
定制键盘输入拦截与转发策略模型：

            [ 用户敲击按键 ]
                   │
                   ▼ (写入 60H 端口，触发 9 号中断)
          +──────────────────+
          |  自定义 int 9    |
          |  中断服务程序    |
          +────────┬─────────+
                   │ 从 60H 读入扫描码
                   ▼
         [ 是否为 ESC 键? ]
          /              \
     是  /                \ 否
        ▼                  ▼
+────────────────+   +────────────────────────────+
| 修改显存属性   |   | 模拟硬件中断过程           |
| 使中央字符变色 |   | (PUSHF, 清除 IF/TF, CALL)  |
+────────────────+   | 转交 原 BIOS int 9 例程处理|
                     +────────────────────────────+
```
*图说明：自定义例程先行捕获 60H 端口扫描码，针对特定按键执行定制逻辑，其余按键则通过模拟中断转发给原 BIOS 例程。*

面对这一需求，最粗暴的想法是将 9 号中断例程完全从头写一遍。但这显然极其不明智——处理键盘硬件时钟、扫描码转换、大小写控制等底层细节浩如烟海，全盘推翻重写代价高昂。

因此，工业级底层开发必须恪守三大原则：
- **最大化复用系统底座**：充分借用原有 BIOS `int 9` 处理硬件细节的能力，我们只编写功能增量；
- **精准拦截与平滑转发**：自定义的中断例程像一个“过滤器”，只拦截我们关心的特定扫描码（`ESC` 键）；一旦发现是其他按键，立刻将控制权无缝转交回原 BIOS 例程；
- **严格遵循恢复规范**：程序启动时修改中断向量表，在程序退出前**必须分毫不差地将原中断向量恢复**。否则程序退出后，中断向量仍指向已被释放的内存代码区，后续用户一旦敲键盘，系统将瞬间死机崩溃。

### 字符动态显示与双重循环 32 位延时算法

我们首先解决主程序的业务框架：在屏幕中央依次显示 `'A'` 到 `'Z'`。

#### 显存文本模式中心定位

在 80×25 彩色字符模式下，显存的段地址为 `0B800H`。屏幕共有 25 行，每行 80 个字符，每个字符占 2 个字节（偶地址存 ASCII 码，奇地址存显示属性），一整行占用 160 个字节。

选定屏幕正中央作为展示位置（第 12 行，第 40 列）：
$$\text{显存偏移地址} = 12 \times 160 + 40 \times 2 = 1920 + 80 = 2000$$

字符从 `'A'` 开始，写入显存后递增，直到显示完 `'Z'` 结束：

```assembly
    mov ah, 'A'
s:  mov es:[160*12 + 40*2], ah
    call delay
    inc ah
    cmp ah, 'Z'
    jna s
```

#### 双重循环 32 位计数器延时设计

如果仅仅写一个单层寄存器循环进行延时，在现代计算机甚至老旧 PC 上，由于 CPU 执行频率极高，16 位寄存器（最大计数 65535）的空循环会在数微秒内瞬间跑完。人眼根本捕捉不到 `'A'` 到 `'Y'` 的变化过程，屏幕上只会“啪”的一声瞬间定格在 `'Z'`。

为了产生人眼舒适的延时，必须构造一个循环次数达数百万至数千万次的 **32 位大容量计数器**。在 8086 体系下，我们利用 `DX:AX` 寄存器对来实现：

```assembly
delay:
    push ax
    push dx

    mov dx, 10h          ; DX 作为高 16 位计数器
    mov ax, 0            ; AX 作为低 16 位计数器
s1: 
    sub ax, 1            ; 低 16 位每次自减 1
    sbb dx, 0            ; 高 16 位带借位自减 0
    cmp ax, 0
    jne s1
    cmp dx, 0
    jne s1

    pop dx
    pop ax
    ret
```

> **机理解析**：
> `AX` 每次减 1。只有当 `AX` 从 `0000H` 减 1 产生借位（借位标志位 $CF = 1$）时，`sbb dx, 0` 才会将高位 `DX` 减 1。
> 当 `DX` 初始设为 `10H`（十进制 16）时，总循环执行次数高达 $16 \times 65536 \approx 100\text{ 万}$ 次，消耗充足的时钟周期，从而让每个字母在屏幕中心稳定停留片刻。

### 拦截 ESC 键与显存属性字节修改

在主循环动态显示字符期间，一旦键盘被按下，就会引发 9 号中断。

键盘产生输入后，扫描码被存入 `60H` 端口。我们自定义的例程首先通过 `in al, 60h` 读取该扫描码。

`ESC` 键具有固定的扫描码：
- `ESC` 键按下时的**通码为 `01H`**；
- `ESC` 键松开时的**断码为 `81H`**（$01\text{H} + 80\text{H}$）。

我们只需要判断读出的扫描码是否等于 `01H`（`cmp al, 1`）：
- **如果不是 `01H`**：说明用户敲的是其他按键，不予拦截；
- **如果是 `01H`**：说明用户按下了 `ESC` 键，立即修改屏幕中心字符的颜色属性！

字符在显存中的显示属性字节位于奇地址单元（即字符 ASCII 码偏移加 1 的位置）：
$$\text{属性字节偏移} = 160 \times 12 + 40 \times 2 + 1 = 2001$$

要改变颜色，最精妙且极简的做法是直接对该内存字节执行递增操作：
```assembly
inc byte ptr es:[160*12 + 40*2 + 1]
```
属性字节的二进制位分别控制着前景色、背景色与高亮。数值每自增一次，屏幕上的字符颜色就会在黑底灰字、蓝底白字、绿底红字等各种绚丽的调色方案中循环切换！

### 中断向量表接管与还原

要想让 CPU 在发生 9 号中断时执行我们的代码，必须在内存起始处的中断向量表（IVT，位于 `0000:0000`）中挂接新例程。

9 号中断向量在内存中的绝对地址分布为：
- **偏移地址（IP）**：位于 `0000:[9 * 4]`（即 `0024H`）；
- **段地址（CS）**：位于 `0000:[9 * 4 + 2]`（即 `0026H`）。

#### 备份旧向量与写入新向量

在改写中断向量之前，必须先将原本指向 BIOS 的旧 `int 9` 入口地址备份到我们程序的数据段中（例如 `ds:[0]` 保存旧 IP，`ds:[2]` 保存旧 CS）。

这里展示一段极其精炼的汇编技巧——**巧用栈操作完成跨段内存拷贝**：

```assembly
    mov ax, 0
    mov es, ax

    ; 1. 备份原 int 9 中断向量到数据段 ds:[0] 和 ds:[2]
    push es:[9*4]
    pop ds:[0]
    push es:[9*4+2]
    pop ds:[2]

    ; 2. 设置新的 int 9 中断向量指向自定义的 int9 标号
    mov word ptr es:[9*4], offset int9
    mov es:[9*4+2], cs
```

利用 `push` 从附加段 `ES` 取出字数据，再 `pop` 存入数据段 `DS`，完全无需中转寄存器，代码干净利落。

### 模拟硬件中断调用原 BIOS 例程

现在迎来本讲技术难度最高、构思最精巧的核心环节：**在自定义的 `int 9` 例程中，如何正确调用原 BIOS 的 `int 9` 中断例程？**

很多同学可能会下意识地想：既然保存了旧入口地址在 `ds:[0]` 和 `ds:[2]`，直接写一句 `call dword ptr ds:[0]` 不就行了吗？

**绝对不行！** 因为原 BIOS 的 `int 9` 是一个标准的中断服务程序，它的最后一条指令是 **`IRET`**。

我们来深入对比硬件引发中断与常规 `CALL` 的本质差异：

```text
硬件中断触发 与 IRET 返回时的栈帧平衡模型：

【硬件触发中断时，CPU 依次压入】：      【原例程末尾执行 IRET 时，CPU 依次弹出】：
  +------------------+                    +------------------+
  |    FLAGS (PSW)   | (第1步入栈)         |      POP IP      | (恢复指令指针)
  +------------------+                    +------------------+
  |        CS        | (第2步入栈)         |      POP CS      | (恢复代码段)
  +------------------+                    +------------------+
  |        IP        | (第3步入栈)         |    POPF (FLAGS)  | (恢复标志寄存器)
  +------------------+                    +------------------+
```
*图说明：IRET 指令在返回时要求栈顶必须严格按序排列着 IP、CS 和标志寄存器 FLAGS，否则栈顶将发生错位崩溃。*

普通子程序调用 `call dword ptr ...` 只会将当前的 `CS` 和 `IP` 压入栈中，**根本不会压入标志寄存器 FLAGS**！如果直接 `call`，原例程执行到末尾的 `iret` 时，就会强行从栈中多弹出一个字赋给标志寄存器，导致栈顶指针彻底错乱，程序瞬间飞车死机。

因此，要在软件子程序中安全调用一个以 `iret` 结尾的中断例程，我们必须**用代码精确模拟出 CPU 硬件触发中断时的全部动作**：
1. **第一步：标志寄存器入栈**：执行 `pushf`；
2. **第二步：关闭中断与单步调试**：将标志寄存器中的 $IF = 0$ 和 $TF = 0$；
3. **第三步：保护断点并跳转**：执行 `call dword ptr ds:[0]`（由 `call` 指令自动完成 `CS` 和 `IP` 的压栈）。

#### 清除 IF 与 TF 标志的位运算技巧

在标志寄存器（FLAGS，共 16 位）中：
- **`TF`（陷阱标志）** 位于第 8 位；
- **`IF`（中断标志）** 位于第 9 位。

第 8 位和第 9 位刚好落在 16 位寄存器的高 8 位（即 `BH` 寄存器）的最低两位（bit 0 和 bit 1）：

```text
标志寄存器高 8 位与 11111100B 掩码逻辑与运算：

FLAGS 高字节 (BH):    b15  b14  b13  b12  b11  b10   b9(IF) b8(TF)
掩码 (11111100B):      1    1    1    1    1    1      0      0
------------------------------------------------------------------
AND 运算结果:         b15  b14  b13  b12  b11  b10     0      0
```
*图说明：将标志寄存器的高字节与 11111100B 进行与运算，精准强行将 IF 与 TF 归零，且不影响其他标志位。*

代码实现如下：
```assembly
pushf
pushf
pop bx
and bh, 11111100b    ; 强制将 IF(bit 9) 与 TF(bit 8) 置 0
push bx
popf
call dword ptr ds:[0]
```
> **推演**：代码先执行一个 `pushf`，将原有的完整标志寄存器稳稳压入栈底（留给原例程的 `iret` 享用）；接着再 `pushf; pop bx;` 拿到当前标志值，通过 `and bh, 11111100b` 将 $IF$ 和 $TF$ 抹为 0，再通过 `push bx; popf` 生效；最后 `call` 压入当前 `CS:IP` 并跳转。原例程执行完毕执行 `iret`，正好弹出当前 `IP`、`CS` 和最先压入的 `FLAGS`，完美返回到 `call` 的下一行指令！

### 完整程序架构与汇编源代码

下面将主循环、延时子程序、中断向量接管、以及自定义 `int 9` 拦截服务程序组装为一体：

```assembly
assume cs:code, ds:data, ss:stack

stack segment
    db 128 dup (0)
stack ends

data segment
    dd 0                 ; ds:[0] 存放原 int 9 的偏移地址和段地址 (4 字节)
data ends

code segment
start:
    ; 1. 初始化栈段与数据段
    mov ax, stack
    mov ss, ax
    mov sp, 128

    mov ax, data
    mov ds, ax

    ; 2. 备份原 int 9 向量到数据段
    mov ax, 0
    mov es, ax
    push es:[9*4]
    pop ds:[0]
    push es:[9*4+2]
    pop ds:[2]

    ; 3. 设置新 int 9 中断向量
    mov word ptr es:[9*4], offset int9
    mov es:[9*4+2], cs

    ; 4. 显存初始化：ES 指向文本显存段
    mov ax, 0b800h
    mov es, ax

    ; 5. 主循环：在屏幕中央动态递增显示 'A' 到 'Z'
    mov ah, 'A'
s:  
    mov es:[160*12 + 40*2], ah
    call delay
    inc ah
    cmp ah, 'Z'
    jna s

    ; 6. 关键收尾：彻底恢复原 int 9 中断向量
    mov ax, 0
    mov es, ax
    push ds:[0]
    pop es:[9*4]
    push ds:[2]
    pop es:[9*4+2]

    ; 7. 退出返回 DOS
    mov ax, 4c00h
    int 21h

;----------------------------------------------------
; 延时子程序：通过 32 位计数器 DX:AX 实现大延时
;----------------------------------------------------
delay:
    push ax
    push dx
    mov dx, 10h
    mov ax, 0
s1: 
    sub ax, 1
    sbb dx, 0
    cmp ax, 0
    jne s1
    cmp dx, 0
    jne s1
    pop dx
    pop ax
    ret

;----------------------------------------------------
; 自定义 9 号中断处理例程
;----------------------------------------------------
int9:
    push ax
    push bx
    push es

    ; 从 60H 端口读取键盘扫描码
    in al, 60h

    ; 模拟中断调用原 BIOS int 9 例程
    pushf
    pushf
    pop bx
    and bh, 11111100b
    push bx
    popf
    call dword ptr ds:[0]

    ; 检查是否为 ESC 键 (ESC 通码为 01H)
    cmp al, 1
    jne int9ret

    ; 若是 ESC 键，将屏幕中心字符的属性字节加 1 改变颜色
    mov ax, 0b800h
    mov es, ax
    inc byte ptr es:[160*12 + 40*2 + 1]

int9ret:
    pop es
    pop bx
    pop ax
    iret

code ends
end start
```

## 17 改写中断例程的方法
> 对应分集：P75 | 原始标题：《17 改写中断例程的方法》

在上一讲中，我们成功编写了拦截 `ESC` 按键并改变显示字符颜色的定制程序。但细心的同学肯定发现了一个本质局限：
上一讲的定制处理是**依附于应用程序本身的**。一旦主循环从 `'A'` 显示到 `'Z'` 结束，程序退出前把中断向量一恢复，一切定制特性就全部烟消云散了。

如果我们希望开发一个真正的系统级功能——比如编写一个通用的“常驻热键驱动”：只要把安装程序运行一次，它退出后便悄然**常驻在内存之中**。此后无论用户在 DOS 命令行中执行什么命令、运行什么软件，只要随手按一下键盘上的 **`F1`** 功能键，当前整个屏幕的文字颜色就会立即整体变换，而其他按键依然保持原有的输入功能不受丝毫干扰。

这种“程序已走，例程长存”的技术，在微机操作系统中被称为**改写中断例程与常驻服务**。这一讲，我们就来彻底掌握这项底层核心硬核技术。

### 常驻中断例程的设计逻辑与三大核心问题

要把一段代码永久挂接在系统的 9 号键盘中断上，并且让安装程序自身从容退出，必须在内存拓扑与指令时序上解决三大关键问题：

```text
常驻中断例程接管与内存拓扑模型：

中断向量表 (0000:0000 起始):
  ...
  0000:0024H (int 9 向量) ─────改写指向────► 0000:0204H (新 int 9 例程代码)
  ...
0000:0200H ~ 0000:02FFH (安全空闲区):
  0000:0200H ───[保存原 int 9 IP] (2 字节)
  0000:0202H ───[保存原 int 9 CS] (2 字节)
  0000:0204H ───+----------------------------------+
                | 新 int 9 键盘中断服务程序代码     |
                | 1. 从 60H 读扫描码               |
                | 2. PUSHF + CALL DWORD CS:[200H]  |
                | 3. 判断是否为 F1 (3BH)           |
                | 4. 若是 F1，遍历显存 2000 字符变色|
                | 5. IRET                          |
                +----------------------------------+
```
*图说明：0:0200 保存原中断入口，0:0204 存放新例程主体，中断向量表 9 号项直接指向 0:0204 形成长久常驻链条。*

#### 全屏字符属性的遍历与修改

在 standard 80×25 彩色文本模式下，显存物理基地址为 `0B8000H`。一屏共有 25 行，每行 80 个字符，全屏幕共计 $25 \times 80 = 2000$ 个字符，占用 4000 个字节。

每个字符在显存中占 2 个连续字节：
- **偶地址单元**：存放字符的 ASCII 码；
- **奇地址单元**：存放字符的显示属性（高 4 位为背景色，低 4 位为前景色）。

要让整个屏幕的所有文字同时改变颜色，本质上就是把显存中全部 2000 个**奇地址单元**的内容统统加 1：

```assembly
    mov ax, 0b800h
    mov es, ax
    mov bx, 1            ; 偏移地址从第 1 个奇地址开始
    mov cx, 2000         ; 循环 2000 次，覆盖全屏 2000 个字符
s:
    inc byte ptr es:[bx] ; 改变属性字节
    add bx, 2            ; 步进 2，跨过 ASCII 码，指向下一个属性字节
    loop s
```

#### 原中断向量的安全驻留空间选择

我们只负责拦截 `F1` 键，对于其他的普通字符键与功能键，必须转发给原有的 BIOS `int 9` 程序去处理。这就意味着我们必须永久保存原 `int 9` 的入口地址（CS 和 IP）。

**这个地址保存在哪里？**
在上一讲中，我们保存在自己程序的数据段 `ds:[0]` 里。但这一次绝对不行！因为安装程序运行完毕后会调用 `int 21h` 退出，安装程序所占用的内存空间会被操作系统随时回收或被后续程序覆盖。如果把旧地址留在数据段，程序退出后一旦被踩内存，系统在调用原例程时将直接奔溃。

我们必须在系统内存中寻找一块**绝不会被操作系统覆盖的安全空闲物理区域**：
在实模式下，`0000:0200H` $\sim$ `0000:02FFH` 这 256 个字节是操作系统和 BIOS 在引导完成后未占用的安全空闲区。我们把原 `int 9` 的入口地址直接保存到：
- `0:0200H`：保存原 `int 9` 的偏移地址（IP）；
- `0:0202H`：保存原 `int 9` 的段地址（CS）。

#### 新中断例程的安装基址

既然原中断向量占用了 `0:0200H` $\sim$ `0:0203H` 这 4 个字节，那么我们顺延物理地址，把新编写的 `int 9` 例程代码完整复制安装到 **`0:0204H`** 开始的内存单元中。

---

### 安装程序主体与原子向量修改

安装程序的使命只有两个：
1. 把新中断例程的代码机器码搬移到 `0:0204H`；
2. 备份原中断向量到 `0:0200H`，并把中断向量表中的 9 号向量修改为指向 `0:0204H`。

完成这两步后，安装程序自身功成身退，退出返回 DOS。

#### 段寄存器配合与代码串传送

我们利用 8086 的高速串传送指令 `REP MOVSB` 来完成代码搬迁：

```assembly
    ; 1. 建立栈与数据段基准
    mov ax, stack
    mov ss, ax
    mov sp, 128

    push cs
    pop ds               ; DS 指向当前代码段 CS (源数据段)

    mov ax, 0
    mov es, ax           ; ES 指向 0 段 (目的数据段)

    ; 2. 将新 int 9 代码从 CS:int9 拷贝到 0:0204H
    mov si, offset int9
    mov di, 204h
    mov cx, offset int9end - offset int9
    cld
    rep movsb
```

- 源地址：`DS:SI = CS:offset int9`；
- 目的地址：`ES:DI = 0:0204H`；
- 传送长度：`CX = offset int9end - offset int9`，由汇编编译器在编译期自动精确计算出新例程的字节长度；
- `CLD` 清除方向标志，`REP MOVSB` 极速复制完毕。

#### CLI 与 STI 保护中断向量修改

紧接着，备份旧向量并改写新向量：

```assembly
    ; 3. 备份原 int 9 向量至 0:0200H
    push es:[9*4]
    pop es:[200h]
    push es:[9*4+2]
    pop es:[202h]

    ; 4. 改写中断向量表 (临界区保护)
    cli                  ; 关中断，禁止外部中断介入
    mov word ptr es:[9*4], 204h
    mov word ptr es:[9*4+2], 0
    sti                  ; 开中断，恢复外部中断响应

    ; 5. 安装程序退出返回 DOS
    mov ax, 4c00h
    int 21h
```

> **易错点与工程铁律**：
> 修改中断向量表是一个包含两条写指令的双步操作（先写偏移地址，再写段地址）。
> 如果在刚写入偏移地址 `204H`、尚未写入段地址 `0` 的那一瞬间，用户恰好碰了一下键盘，CPU 就会立刻响应 9 号中断，用“新的偏移地址 + 旧的段地址”拼凑出一个荒谬的物理地址跳转，系统必然瞬间死锁。
> 因此，在修改中断向量的前后，必须用 **`CLI` 关中断** 和 **`STI` 开中断** 构成一个受保护的原子操作临界区！

### 新中断例程代码逻辑与 CS 寻址奥秘

新中断例程 `int9` 的完整源码与处理流程如下：

```assembly
int9:
    push ax
    push bx
    push cx
    push es

    in al, 60h                      ; 从 60H 端口读取击键扫描码

    ; 模拟中断调用原 BIOS int 9 例程
    pushf
    call dword ptr cs:[200h]

    ; 检查是否为 F1 键 (F1 键通码为 3Bh)
    cmp al, 3bh
    jne int9ret

    ; 若按下 F1，遍历全屏显存，修改 2000 个字符的属性字节
    mov ax, 0b800h
    mov es, ax
    mov bx, 1
    mov cx, 2000
s:
    inc byte ptr es:[bx]
    add bx, 2
    loop s

int9ret:
    pop es
    pop cx
    pop bx
    pop ax
    iret
int9end:
    nop
```

#### 深度解析：为什么是 call dword ptr cs:[200h]？

这段代码中最耐人寻味、最显功底的一句，就是：
```assembly
call dword ptr cs:[200h]
```
为什么这里的段前缀既不是 `DS` 也不是 `ES`，而是明确指定为 **`CS`**？

请大家跟我一起推演中断发生时 CPU 的寄存器状态：
1. 当键盘产生输入、CPU 响应 9 号中断时，CPU 依据被我们改写的中断向量表，自动将 `0000H` 赋给 `CS`，将 `0204H` 赋给 `IP`；
2. 此时，CPU 已经进入了运行在 `0:0204H` 处的中断例程，**当前代码段寄存器 `CS` 的值就是 0**！
3. 当程序执行 `cs:[200h]` 时，寻址的物理地址恰好就是：
   $$\text{物理地址} = \text{CS} \times 16 + 200\text{H} = 0 \times 16 + 200\text{H} = 00200\text{H}$$
4. 而我们在前面的安装步骤中，把原中断向量保存的地方恰恰就是内存的 `0:0200H` 单元！

采用 `cs:[200h]` 带来了巨大的工程优势：
- 中断例程不需要去猜测或修改主程序传进来的 `DS` 寄存器；
- 它不依赖任何外部数据段，直接借助自身的代码段基址 `CS = 0`，就能稳准狠地定位到紧邻自身的配置区；
- 这种代码在体系结构中被称为**位置自包含的高内聚例程**，是编写系统级常驻驻留代码的标准姿势。

#### F1 键的扫描码比对

键盘最上方功能键 `F1` 按下时产生的**通码固定为 `3Bh`**：
- 例程首先通过 `pushf` + `call dword ptr cs:[200h]` 让原 BIOS 例程把常规按键的所有底层事务处理好（包括字符映射、状态维护以及发送硬件 EOI 应答）；
- 紧接着比对 `AL` 是否等于 `3Bh`；
- 如果不是 `3Bh`（`jne int9ret`），直接出栈恢复并退出；
- 如果是 `3Bh`，则启动 `loop` 循环，将全屏幕 4000 字节中的所有奇数地址自增，瞬间实现全屏炫彩变色！

## 18 用中断响应外设
> 对应分集：P76 | 原始标题：《18 用中断响应外设》

在之前的课程中，我们学习了 CPU 如何通过端口与外部芯片进行通信，也接触过了直接改写中断向量来定制键盘响应。但不知道大家有没有思考过一个更宏观的问题：在微机系统中，CPU 究竟是如何与形形色色的外部设备进行协同工作的？

当我们敲击键盘上的一个按键、挪动一下鼠标，或者让打印机打印一行文本时，计算机底层到底经历了哪些环节？在汇编语言层面，我们该如何操作这些外部设备？

这一讲，我们就以计算机中最典型的外部输入设备——键盘为例，层层剥开微机系统中外设交互的三层架构，剖析硬件中断、BIOS 软件中断以及键盘缓冲区构成的“生产者-消费者模型”，最后通过一个直接操控显存与键盘中断的综合程序，把这些底层运行机制彻底串联起来。

### 外设交互的三层体系架构

在 8086 PC 机中，程序员要对外部设备进行输入输出（I/O）控制，通常有三种途径：

1. **直接端口读写**：使用 `in` / `out` 指令直接访问外设接口芯片的 I/O 端口；
2. **调用 BIOS 中断**：调用主板 ROM BIOS 中固化的底层硬件服务例程；
3. **调用 DOS 中断**：调用操作系统提供的更高层系统功能调用。

这三种途径并不是相互孤立的，而是构成了一个清晰的阶梯式分层架构：

```text
外设访问的分层调用体系：

+-------------------------------------------------------+
|                 应用程序 (Application)                 |
+---------------------------+---------------------------+
                            | 途径 3: 便捷、与硬件无关
                            v
+-------------------------------------------------------+
|             操作系统中断服务 (DOS INT 21H)            |
+---------------------------+---------------------------+
                            | 途径 2: 依赖底层 BIOS
                            v
+-------------------------------------------------------+
|             主板固化例程 (BIOS INT 16H / 10H / 13H...) |
+---------------------------+---------------------------+
                            | 途径 1: 直接操控物理端口
                            v
+-------------------------------------------------------+
|           硬件接口芯片与端口 (如 60H 键盘控制器)        |
+---------------------------+---------------------------+
                            | 物理电气连接
                            v
+-------------------------------------------------------+
|                 物理外部设备 (如 键盘机械开关)          |
+-------------------------------------------------------+
```
*图说明：DOS 中断建立在 BIOS 中断之上，BIOS 中断通过端口读写控制底层硬件。*

#### 三层接口的职责与权衡

- **BIOS 中断例程**：计算机加电自检后，由主板 ROM 提供的基础输入输出系统。它直接与硬件端口打交道，负责对特定硬件做初始化和最基础的收发控制。
- **DOS 中断例程**：操作系统加载后安装的中断服务。它建立在 BIOS 的基础之上，对底层硬件进行了进一步封装。例如 DOS 的 `int 21h` 在实现从控制台读取字符时，底层实际上仍是在调用 BIOS 的中断例程。
- **直接端口操作**：完全绕开操作系统和 BIOS，由程序员直接向接口芯片的端口读写数据。

在实际开发中，我们应当如何在这些层次间做权衡？
- **编写通用应用程序**：优先选择 DOS 中断或 BIOS 中断。高层接口不仅开发效率高，而且具有优良的兼容性。无论底层键盘是 PS/2 接口、USB 转接口还是不同的硬件芯片，操作系统都会为你屏蔽硬件差异。
- **编写底层系统软件或驱动**：如果需要实现特殊的交互控制（如全屏游戏的热键截获、特定外设驱动、常驻监控工具），高层接口往往无法提供细粒度的控制，此时直接挂接硬件中断或读写端口就是唯一可行的手段。

### 键盘输入相关的三层中断分工

针对键盘这一物理设备，PC 机内部部署了三个不同层级的中断来各司其职：

```text
键盘操作的三层中断分工模型：

        物理击键动作 (按下/松开)
                   │
                   ▼
      [键盘控制器 产生扫描码送入 60H]
                   │ (硬件中断信号)
                   ▼
       ★ INT 9H 硬件中断处理程序 (生产者)
                   │
                   ├─► 识别控制键 (Shift/Ctrl/Alt) ──► 更新键盘状态字节
                   │
                   └─► 普通字符键转换为 ASCII 码 ──► 写入键盘缓冲区 (FIFO)
                                                             │
                                                             ▼
                                                ★ INT 16H 软件中断 (消费者)
                                                             │
                                                             ▼
                                                ★ DOS INT 21H 功能调用
                                                             │
                                                             ▼
                                                        应用程序读取
```
*图说明：INT 9h 由物理击键触发向缓冲区写数据，INT 16h/21h 由程序主动调用从缓冲区取数据。*

#### INT 9h：物理击键触发的硬件中断

`INT 9h` 是一个真正的外部可屏蔽硬件中断（INTR 引脚触发）。它的执行完全不取决于应用程序什么时候运行，而取决于用户手指什么时候敲击键盘。

当我们在键盘上按下一个键（产生通码）或者松开一个键（产生断码）时，键盘内部芯片都会将该键的扫描码送入主板的 `60H` 端口，同时向 CPU 发出可屏蔽中断请求。若此时 CPU 允许中断（`IF = 1`），CPU 就会暂停当前正在执行的指令，跳转去执行 BIOS 提供的 `INT 9h` 中断处理程序。

`INT 9h` 中断例程的核心工作有四步：
1. 从 `60H` 端口读出按键的扫描码；
2. 检测是否为控制键或换挡键（如 `Shift`、`Ctrl`、`Alt`、`CapsLock` 等）。如果是，则直接修改位于内存 `0040:0017H` 处的**键盘状态字节**，并不向缓冲区写字符；
3. 如果是普通字符键，则结合当前的键盘状态字节（例如判断 Shift 是否按下），将扫描码转换为对应的 **ASCII 码**；
4. 将该按键的扫描码与 ASCII 码打包成一个字（Word），追加存入系统内部的**键盘缓冲区**中。

#### BIOS INT 16h：供程序调用的软件服务中断

与 `INT 9h` 的“被动触发”完全相反，`INT 16h` 是由应用程序通过 `int 16h` 指令“主动发起”的软中断。它由 BIOS 提供，专门用来查询和提取键盘缓冲区里的数据。

`INT 16h` 提供了多个子功能，通过寄存器 `AH` 来指定：
- **`AH = 00H`**（增强型键盘可用 `10H`）：从键盘缓冲区中读取一个按键信息。若缓冲区为空，则程序进入阻塞挂起状态，直到用户按键；读取成功后，该按键从缓冲区中出队清除，`AH` 返回扫描码，`AL` 返回 ASCII 码。
- **`AH = 01H`**（增强型键盘可用 `11H`）：检查键盘缓冲区是否有字符就绪（非阻塞查询）。若有，ZF 标志置 0，并在 `AH`/`AL` 中返回该按键（但不将其从缓冲区移走）；若缓冲区为空，则 ZF 置 1。
- **`AH = 02H`**（增强型键盘可用 `12H`）：直接读取内存中的键盘状态字节，返回在 `AL` 寄存器中，用于实时监测 `Shift`、`Ctrl`、`Alt`、`CapsLock`、`NumLock` 等键的当前状态。

#### DOS INT 21h：高级控制台输入服务

在操作系统层面，DOS 的 `INT 21H` 进一步封装了键盘服务：
- `AH = 01H`：带回显的单个字符输入；
- `AH = 07H`：直接控制台输入（无回显、不受 Ctrl+C 中断）；
- `AH = 08H`：无回显的单个字符输入（可响应 Ctrl+C）；
- `AH = 0AH`：带缓冲区的整行字符串输入。

在这些 DOS 调用的底层实现中，操作系统也是通过调用 `INT 16H` 来从键盘缓冲区提取字符的。

### 键盘缓冲区与生产者-消费者协同模型

理解了 `INT 9h` 与 `INT 16h` 的分工之后，我们就会发现它们在系统结构上构成了一个教科书般的**生产者-消费者模型（Producer-Consumer Model）**：

> **定义**：
> - **生产者（INT 9h）**：异步硬件中断。无论当前 CPU 在执行什么应用代码，只要用户敲击按键，它就向缓冲区“生产”一个键值单元。
> - **消费者（INT 16h）**：同步软件中断。应用程序根据自身的业务节奏，在需要输入时调用它，从缓冲区“消费”一个键值单元。
> - **共享介质（键盘缓冲区）**：位于 BIOS 数据区（`0040:001EH` $\sim$ `0040:003DH`）的一块内存区域，用于解耦按键产生速度与程序读取速度。

#### 环形队列存储机制与容量边界

键盘缓冲区在数据结构上是一个标准的**环形队列（Circular Buffer / FIFO）**：

```text
键盘缓冲区 (16 字环形队列) 内部结构示意：

 偏移地址:
 001EH   0020H   0022H   0024H   0026H   0028H           003CH
+-------+-------+-------+-------+-------+-------+  ...  +-------+
| Scan  | Scan  | Scan  |       |       |       |       |       |
| ASCII | ASCII | ASCII |       |       |       |       |       |
+-------+-------+-------+-------+-------+-------+  ...  +-------+
    ▲                       ▲
    │                       │
 队头指针 (Head)         队尾指针 (Tail)
 (由 INT 16H 读取后移)   (由 INT 9H 存入后移)
```
*图说明：键盘缓冲区包含 16 个字单元，每个单元高字节为扫描码，低字节为 ASCII 码。*

1. **缓冲区规格**：
   - 整个缓冲区共包含 **16 个字单元**（每个字 2 个字节，共 32 字节）；
   - 每个有效按键占用 1 个字单元：**高字节存放扫描码，低字节存放 ASCII 码**。
2. **容量为什么是 15 个，而不是 16 个？**
   - 环形队列需要通过两个指针来维护：位于 `0040:001AH` 的**队头指针（Head Pointer）**和位于 `0040:001CH` 的**队尾指针（Tail Pointer）**。
   - 当 `Head == Tail` 时，队列判定为**队空**；
   - 为了区分“队满”和“队空”，算法中必须空出一个字单元不用：当 `(Tail + 2) == Head`（考虑模 16 环回）时，即判定为**队满**。
   - 因此，16 个字单元的缓冲区最多只能容纳 **15 个按键**的信息。如果用户打字极快而程序未及时取走，当打入第 16 个字符时，BIOS 会通过扬声器发出“哔哔”的蜂鸣报警声，并丢弃该按键。

#### 输入全流程时序追踪

##### 连续普通字符输入（以依次按下 'a'、'b' 为例）

1. 用户按下键盘上的字母键 `'a'`：
   - 键盘发出 `'a'` 的通码 `1EH` 送入端口 `60H`；
   - 触发 `INT 9h` 硬件中断；
   - `INT 9h` 例程读取 `1EH`，查询状态字节得知 Shift 未被按下，计算出对应小写字母的 ASCII 码 `61H`；
   - 将字数据 `1E61H` 写入队尾指针指向的单元，并将队尾指针加 2。
2. 用户按下字母键 `'b'`：
   - 键盘发出 `'b'` 的通码 `30H`，触发 `INT 9h`；
   - 转换出 ASCII 码 `62H`，字数据 `3062H` 写入下一个单元，队尾指针再次加 2。

##### 组合键输入（以 Shift + a 为例）

1. 用户按下 `Shift` 键：
   - 键盘产生 Shift 的扫描码 `2AH`，触发 `INT 9h`；
   - `INT 9h` 识别出 `2AH` 是控制键，**绝不向键盘缓冲区写入任何字符**，而是直接将 `0040:0017H` 状态字节中的第 0 位（右 Shift）或第 1 位（左 Shift）置为 `1`。
2. 在不松开 `Shift` 的情况下，按下字母键 `'a'`：
   - 产生 `'a'` 的通码 `1EH`，再次触发 `INT 9h`；
   - `INT 9h` 读出 `1EH`，并检查状态字节，发现 Shift 位为 `1`；
   - 此时不再将其转换为小写 `61H`，而是转换为大写 `'A'` 的 ASCII 码 `41H`；
   - 将字数据 `1E41H`（扫描码 `1EH`，ASCII 码 `41H`）存入键盘缓冲区。
3. 用户松开 `Shift` 键：
   - 产生断码 `0AAH`，触发 `INT 9h`；
   - `INT 9h` 检测到释放动作，将状态字节中的 Shift 标志位复位为 `0`。

##### INT 16h 提取消费过程

当缓冲区已存入 `1E61H`（'a'）和 `3062H`（'b'）后，用户程序执行：

```assembly
mov ah, 0
int 16h
```

- CPU 执行 `int 16h`，例程检查队头指针与队尾指针，发现队列非空；
- 从队头指针处取出字数据 `1E61H`；
- 将队头指针加 2（在逻辑上删除了该字符）；
- 将高字节扫描码 `1EH` 送入 `AH`，低字节 ASCII 码 `61H` 送入 `AL`，返回应用程序；
- 此时缓冲区内仅剩按键 `'b'`，后续再次执行 `mov ah, 0` / `int 16h` 时，即可提取出 `'b'`。

### 综合应用：基于键盘输入动态改变屏幕字符颜色

为了将上述输入捕获与硬件响应融会贯通，我们来完成一个极具实践意义的综合程序：

> **需求**：
> 运行一段程序，监控键盘击键：
> - 当用户按下字符 `'r'`（Red）时，将全屏幕所有字符的前景色全部改为**红色**；
> - 当用户按下字符 `'g'`（Green）时，将全屏幕所有字符的前景色全部改为**绿色**；
> - 当用户按下字符 `'b'`（Blue）时，将全屏幕所有字符的前景色全部改为**蓝色**；
> - 若按下其他任意按键，则退出程序返回 DOS。

#### 显存文本属性字节的位结构

在 8086 PC 的标准 80×25 彩色文本模式下，显存的物理起始基地址为 `0B8000H`（段地址为 `0B800H`）。
屏幕一共有 25 行，每行 80 个字符，全屏共 $25 \times 80 = 2000$ 个字符，占用 4000 个字节。

每个字符在显存中占用 2 个连续字节：
- **偶地址**：存放字符的 ASCII 码；
- **奇地址**：存放字符的显示属性字节。

显示属性字节（8 位）的具体位定义如下：

```text
显存属性字节 (Attribute Byte) 结构：

  7      6      5      4      3      2      1      0
+------+------+------+------+------+------+------+------+
|  BL  |  R   |  G   |  B   |  I   |  R   |  G   |  B   |
+------+------+------+------+------+------+------+------+
 闪烁位    背景色 (RGB: 3位)   高亮位    前景色 (RGB: 3位)
```

其中：
- **低 3 位（位 2、1、0）**控制字符的前景色：
  - 位 0 对应蓝色（Blue）；
  - 位 1 对应绿色（Green）；
  - 位 2 对应红色（Red）。
- 我们的目标是改变全屏幕字符的**前景色**，同时必须**严格保留原有字符的背景色与高亮/闪烁位**不受破坏。

#### 巧妙使用移位指令构造颜色掩码

根据前景色位的定义：
- 蓝色（Blue）需要第 0 位为 1，对应数值为 `00000001B`；
- 绿色（Green）需要第 1 位为 1，对应数值为 `00000010B`；
- 红色（Red）需要第 2 位为 1，对应数值为 `00000100B`。

这里我们可以设计一个精巧的移位级联结构：
把 `AH` 初始化为 `1`（`00000001B`，即蓝色）。如果用户按下的是 `'g'`，则将 `AH` 左移 1 位；如果按下的是 `'r'`，则让其连续左移 2 位。
利用汇编语言顺序执行的特点，可以通过顺序落入的方式省去多余的赋值：

```assembly
    mov ah, 1          ; 初始值 00000001B (代表蓝色)
    cmp al, 'r'
    je red
    cmp al, 'g'
    je green
    cmp al, 'b'
    je blue
    jmp short s_ret    ; 其它按键，直接退出

red:
    shl ah, 1          ; 红色额外左移一次，连同下面总共左移2次，变成 00000100B
green:
    shl ah, 1          ; 绿色左移1次，变成 00000010B
blue:
    ; 蓝色无需额外移位，直接保留初始值 00000001B
```

#### 属性位掩码与全屏显存遍历

在将新前景色写入显存时，必须做两步位运算：
1. **屏蔽旧前景色**：属性字节与 `11111000B`（`0F8H`）进行 `AND` 操作，将低 3 位清零，保留高 5 位（背景色、闪烁和高亮位）；
2. **置入新前景色**：属性字节与 `AH` 进行 `OR` 操作，将新前景色写入低 3 位。

#### 完整实现代码与逐段解析

```assembly
assume cs:code

code segment
start:
    ; 1. 从键盘缓冲区读取一个按键
    mov ah, 0
    int 16h            ; 阻塞等待按键：AL = ASCII 码，AH = 扫描码

    ; 2. 准备颜色掩码与分支判断
    mov ah, 1          ; 预置初始掩码为 00000001B (蓝色)
    cmp al, 'r'
    je red
    cmp al, 'g'
    je green
    cmp al, 'b'
    je blue
    jmp short s_ret    ; 若非 r/g/b 则退出程序

red:
    shl ah, 1          ; 若为红色，左移两次 (00000100B)
green:
    shl ah, 1          ; 若为绿色，左移一次 (00000010B)
blue:
    ; 蓝色保持 00000001B，直接下落进入显存遍历

    ; 3. 遍历显存，更新全屏 2000 个字符的前景色
    mov bx, 0b800h
    mov es, bx
    mov bx, 1          ; 指向第 0 个字符的属性字节（奇地址）
    mov cx, 2000       ; 循环 2000 次，覆盖整屏 25x80 字符

s:
    and byte ptr es:[bx], 11111000b  ; 清除原前景色低 3 位
    or  byte ptr es:[bx], ah         ; 写入新的前景色
    add bx, 2                        ; 跨过下一个字符的 ASCII 码，指向下一个属性字节
    loop s

s_ret:
    mov ax, 4c00h
    int 21h

code ends
end start
```

##### 代码逻辑核心解析

1. **`mov ah, 0` / `int 16h`**：
   通过调用 BIOS 键盘服务中断，使得程序停在这一行等待用户击键。只要用户敲击了键盘，`INT 9h` 便已在底层无声无息地完成了扫描码读取、状态判断以及向缓冲区的入队操作；`INT 16h` 随后将该字符出队并返回给 `AL`。
2. **`shl ah, 1` 的级联跳转**：
   如果 `al == 'r'`，跳到 `red:`，执行了两次 `shl ah, 1`，`AH` 变为 `00000100B`；
   如果 `al == 'g'`，跳到 `green:`，执行了一次 `shl ah, 1`，`AH` 变为 `00000010B`；
   如果 `al == 'b'`，跳到 `blue:`，不执行移位，`AH` 为 `00000001B`。
   这样写出的汇编代码极其紧凑，避免了多次冗余的 `mov ah, 4` 或 `mov ah, 2`。
3. **`and byte ptr es:[bx], 11111000b` 与 `or byte ptr es:[bx], ah`**：
   这是底层图像/显存编程中极其标准的“位掩码更新”（Read-Modify-Write）操作。先用按位与清掉目标位，再用按位或写入新数据，从而实现了对前景色修改的“手术刀式”精准控制。

---

### 核心设计思想与总结

通过本讲的学习，我们可以得出以下关于外设交互的核心认知：

1. **分层架构是解耦的基石**：微机系统通过“端口 $\rightarrow$ BIOS 中断 $\rightarrow$ DOS 中断”的分层结构，实现了底层硬件操作与上层应用逻辑的解耦。
2. **异步中断与同步读取的分工**：`INT 9h` 作为硬件中断（生产者），只管高效、实时地捕获物理击键并维护系统缓冲区；`INT 16h` 作为软件中断（消费者），按程序自身的节奏按需提取数据。
3. **环形队列保障系统鲁棒性**：借助 16 个字单元的 FIFO 环形队列，系统成功平抑了人机交互中的速度差异，既保证了按键输入不丢失，又防止了数据无限积压导致系统失控。

## 19 应用：字符串的输入入
> 对应分集：P77 | 原始标题：《19 应用：字符串的输入入》

在平时的各种命令行软件或者控制台程序中，我们在终端里敲入一串字符、发现敲错了按一下退格键（Backspace）删掉前一个字，最后敲一下回车键（Enter）确认提交——这套流程对大家来说再自然不过了。

但是，如果在裸机或者 DOS 环境下，要求我们完全不用高层现成的字符串输入接口，自己用汇编语言纯手工实现一个支持**边输入边回显**、**退格键删除**以及**回车键确认**的字符串输入子程序，底层该如何组织？

很多初学者一上手就容易把按键捕获、逻辑存储、显存输出全都乱七八糟地揉在几个 `cmp` 和 `jmp` 循环里，最后代码写得像一团乱麻，退格键不是删过了头就是把内存踩坏。

这一讲，我们就来用汇编语言解决这个经典问题。我们将看到如何巧妙运用**栈**这种数据结构来管理输入流，并借鉴操作系统中断向量表的精髓，利用**直接定址表（表驱动设计）**写出架构清晰、高内聚且极易扩展的专业级底层程序。

---

### 字符串输入的功能需求与运行机制

一个最基本、可用的交互式字符串输入程序，必须满足三项核心功能：

1. **实时回显（边输入边显示）**：每敲下一个可显示字符，屏幕上立即同步显示出来；
2. **退格键撤销（Backspace）**：按下退格键时，能够删除前一个已经输入的字符，并在屏幕上抹去其显示；
3. **回车键结束（Enter）**：按下回车键后，输入结束，并在字符串末尾自动追加一个字节 `0` 作为字符串结束符（即类似于 C 语言风格以 `'\0'` 结尾的字符串）。

#### 交互时序过程演示

假设用户在键盘上依次进行了如下击键：
- 依次输入字符：`'a'` $\to$ `'b'` $\to$ `'c'` $\to$ `'d'`；
- 紧接着按了一下**退格键**：此时前一个字符 `'d'` 必须被撤销并从屏幕上消除；
- 再次按了一下**退格键**：此时字符 `'c'` 必须被撤销并抹去；
- 最后按下**回车键**：输入结束。

此时，留在内存数据区中的有效字符串内容应当严格为 `'a'`, `'b'`，并在末尾追加一个字节 `0`（十六进制表示为 `61H, 62H, 00H`）。

```text
字符串输入动态演变过程：

用户击键动作        字符存储区状态           屏幕当前显示
-------------------------------------------------------
按 'a'               ['a']                   a
按 'b'               ['a', 'b']              ab
按 'c'               ['a', 'b', 'c']         abc
按 'd'               ['a', 'b', 'c', 'd']    abcd
按 Backspace         ['a', 'b', 'c']         abc   (抹除 d)
按 Backspace         ['a', 'b']              ab    (抹除 c)
按 Enter             ['a', 'b', 0]           ab    (输入终止)
```
*图说明：按键的追加与退格正好契合“后进先出”的栈式行为模式。*

---

### 字符串存储的数据结构选型：字符栈

为什么在实现这个程序时，我们要引入“栈”这种数据结构？

原因非常简单：用户在终端输入字符时，其操作语义是典型的**后进先出（LIFO，Last In First Out）**。
- 用户输入一个新字符，是在字符串末尾**追加**；
- 用户按退格键删除，抹掉的永远是**最新敲入的那一个**字符。

> **注意**：
> 这里的“字符栈”并不是 8086 CPU 硬件体系中由 `ss:sp` 寄存器维护的系统硬件栈，而是**在应用程序的数据段中人为开辟的一块普通内存区域，并通过软件维护一个栈顶偏移指针 `top` 模拟出的字符栈**。

这样做的好处在于：
- 我们不需要频繁地搬移内存数据；
- 字符栈的栈顶指针 `top` 的数值，在任何时刻都精确等于当前已输入字符串的字符个数；
- 当需要退格时，只需将 `top` 指针减 1，原字符在逻辑上即被弹出抛弃；
- 当需要回显时，只要从字符栈基址遍历到 `top` 指针处，即可精准刷新屏幕。

---

### 字符串接收主控程序设计：getstr

明确了需求后，我们首先构建接收字符串的主控子程序 `getstr`。

#### 输入流分流策略

主控程序的核心逻辑是一个事件循环：
1. 调用 BIOS 键盘服务软中断 `mov ah, 0` / `int 16h`，阻塞等待用户击键；
2. 读取按键后，`AL` 寄存器存放字符的 ASCII 码，`AH` 寄存器存放扫描码；
3. **可显示字符判定**：在 ASCII 字符集中，ASCII 码小于 `20H`（空格键的 ASCII 码）的均为非打印控制字符（如退格、换行、回车、Esc、Tab 等）。因此执行 `cmp al, 20h`，若低于 `20H`（`jb nochar`），则跳转至控制字符处理分支；
4. 若为可显示字符（`al >= 20h`）：
   - 将该字符压入字符栈；
   - 刷新显示当前字符栈中的所有内容；
   - 循环等待下一个按键；
5. 若为控制字符（`nochar` 分支）：检查其扫描码 `AH`：
   - 扫描码为 `0EH`：代表退格键（Backspace），从字符栈中弹出一个字符，并刷新屏幕；
   - 扫描码为 `1CH`：代表回车键（Enter），向字符栈压入一个数值 `0` 作为终止符，刷新屏幕并退出返回；
   - 其他控制按键：直接忽略，继续等待下一次输入。

```text
主控程序按键处理状态转移图：

                     [ 等待键盘输入: INT 16H (AH=0) ]
                                    │
                                    ▼
                          [ 检查 AL >= 20H ? ]
                           /                \
                       是 /                  \ 否
                         ▼                    ▼
               [ 普通可显示字符 ]       [ 控制按键检查 AH 扫描码 ]
                 │ 字符压栈              /                      \
                 │ 刷新屏幕             / AH == 0EH (退格)       \ AH == 1CH (回车)
                 │                     ▼                          ▼
                 │               [ 字符出栈 ]                [ 压入 0 作为结束符 ]
                 │               [ 刷新屏幕 ]                [ 刷新屏幕并退出 ]
                 │                     │                          │
                 └─────────────────────┴──────────────────────────┘
```
*图说明：根据 ASCII 码和扫描码将击键精准分流到入栈、退格或结束逻辑中。*

#### getstr 子程序的代码实现

```assembly
getstr:
    push ax                 ; 保护现场

getstrs:
    mov ah, 0
    int 16h                 ; 阻塞等待按键：AL = ASCII 码, AH = 扫描码

    cmp al, 20h             ; 判断是否为可显示字符
    jb nochar               ; 若 AL < 20H，转去处理控制按键

    ; 1. 普通可显示字符处理
    mov ah, 0               ; 约定功能号 0: 字符入栈
    call charstack
    mov ah, 2               ; 约定功能号 2: 刷新显示字符栈
    call charstack
    jmp getstrs             ; 继续循环等待下一个按键

nochar:
    cmp ah, 0eh             ; 退格键 Backspace 的硬件扫描码为 0EH
    je backspace
    cmp ah, 1ch             ; 回车键 Enter 的硬件扫描码为 1CH
    je enter
    jmp getstrs             ; 其它控制键（如 Esc、Tab）直接忽略

backspace:
    ; 2. 退格键处理
    mov ah, 1               ; 约定功能号 1: 字符出栈
    call charstack
    mov ah, 2               ; 约定功能号 2: 刷新显示字符栈
    call charstack
    jmp getstrs

enter:
    ; 3. 回车键处理
    mov al, 0               ; 字符串结尾标记 0
    mov ah, 0               ; 约定功能号 0: 字符入栈
    call charstack
    mov ah, 2               ; 约定功能号 2: 刷新显示字符栈
    call charstack
    pop ax                  ; 恢复现场
    ret                     ; 字符串输入彻底完成，子程序返回
```

### 字符栈管理模块：charstack 的直接定址表设计

在上述主控流程中，我们把所有对字符栈的操作全部收敛到了一个统一的子程序调用：`call charstack`。
通过给寄存器 `AH` 赋予不同的功能号，实现对字符栈的不同操作：
- `AH = 0`：字符入栈（入口参数：`AL` 为待入栈字符）；
- `AH = 1`：字符出栈（出口参数：`AL` 为弹出的字符）；
- `AH = 2`：显示栈中的字符（入口参数：`DH` 为起始行号，`DL` 为起始列号，`DS:SI` 指向字符栈内存基地址）。

#### 为什么采用直接定址表（表驱动设计）

如果在 `charstack` 内部我们依然写：
```assembly
cmp ah, 0
je do_push
cmp ah, 1
je do_pop
cmp ah, 2
je do_show
```
一旦后续功能扩展到 10 个甚至 20 个子功能，代码中就会充斥着大量的分支比较指令，代码臃肿且分支预测开销大。

在计算机系统底层中，最优雅的做法是**直接定址表（Direct Addressing Table，即跳转表 / 跳转数组）**：
我们将每个子功能的处理入口地址（偏移地址）预先定义在一个连续的地址数组中：
`table dw charpush, charpop, charshow`

当需要分发时，根据传入的功能号 `AH`：
1. 进行越界安全防卫（`cmp ah, 2` / `ja sret`）；
2. 计算偏移量：每个函数指针占用 1 个字（2 字节），因此偏移量即为 $AH \times 2$；
3. 执行一条寻址跳转指令：`jmp word ptr table[bx]`，瞬间直接分发到目标处理例程！

这种表驱动设计不仅效率极高（时间复杂度恒定为 $O(1)$），而且在架构上与 CPU 的中断向量表（IVT）以及操作系统系统调用表的设计思想完全同构。

```text
直接定址表跳转原理示意图：

功能号 AH (0, 1, 2)
      │
      ▼
   BX = AH * 2
      │
      ▼
 直接定址表 table:
 偏移 +0: [ charpush 的入口偏移 ]  ────► 跳转执行: 字符入栈
 偏移 +2: [ charpop  的入口偏移 ]  ────► 跳转执行: 字符出栈
 偏移 +4: [ charshow 的入口偏移 ]  ────► 跳转执行: 屏幕字符刷新
```

#### charstack 子程序框架与数据段定义

```assembly
charstack:
    jmp short charstart

    ; 数据区：函数指针表与栈顶指针
    table dw charpush, charpop, charshow
    top   dw 0              ; 字符栈顶偏移变量，初始为 0

charstart:
    push bx
    push dx
    push di
    push es                 ; 保护内部使用到的通用寄存器与段寄存器

    cmp ah, 2               ; 功能号合法性检查
    ja sret                 ; 若 AH > 2，非法功能号，安全退出

    mov bl, ah
    mov bh, 0
    add bx, bx              ; bx = ah * 2，计算在 table 中的字节偏移

    jmp word ptr table[bx]  ; 查表跳转至对应的功能子例程
```

> **提示**：
> 在子程序的最开头使用 `jmp short charstart`，是为了绕开紧跟其后定义的数据区（`table` 和 `top`）。这种将局部常量/变量就近嵌入在代码段中的做法，在汇编语言模块化开发中非常实用，避免了把数据零散堆放在外部全局数据段带来的命名污染。

### 字符栈各子功能的具体实现细节

#### 字符入栈子例程（charpush）

入栈操作的语义是：将 `AL` 中的字符存放到当前栈顶指针指向的内存单元中，并将栈顶指针递增 1。

```assembly
charpush:
    mov bx, top
    mov [si+bx], al         ; 将字符写入 ds:[si + top]
    inc top                 ; top 指针递增 1
    jmp sret                ; 跳转至统一出口返回
```

#### 字符出栈子例程（charpop）

出栈操作必须格外注意**下溢（Underflow）边界防卫**：
如果用户连续狂按退格键，当字符栈已经为空（`top == 0`）时，绝对不能再允许出栈！否则 `top` 减 1 就会变成 `0FFFFH`，导致后续内存寻址严重越界，踩坏其他数据。

```assembly
charpop:
    cmp top, 0              ; 检查字符栈是否为空
    je sret                 ; 若 top == 0，栈已空，无法出栈，直接静默返回

    dec top                 ; 栈顶指针先减 1
    mov bx, top
    mov al, [si+bx]         ; 取出弹出的字符放到 AL 中返回
    jmp sret                ; 跳转至统一出口返回
```

#### 屏幕刷新子例程（charshow）

无论是敲入新字符还是退格删除了字符，屏幕上的显示都必须即时更新。

在 80×25 彩色文本模式下，显存基址为 `0B800H`。屏幕上任意第 $dh$ 行、第 $dl$ 列的字符，在显存中的偏移地址计算公式为：
$$\text{offset} = (dh \times 80 + dl) \times 2$$

为了在退格时能够彻底抹去被删除的字符，刷新算法采用**全覆盖刷新机制**：
从 `ds:si` 指向的字符栈底开始，逐个向显存输出当前栈内的有效字符（共 `top` 个）。
如果此前屏幕上留有更长的字符轨迹，必须输出空格符覆盖或者清空行尾，确保显示内容与栈内数据绝对一致。

```assembly
charshow:
    mov bx, 0b800h
    mov es, bx              ; ES 指向文本显存段

    ; 1. 计算显存起始偏移地址: (dh * 80 + dl) * 2
    mov al, 160             ; 每行 80 个字符，占 160 个字节
    mov ah, 0
    mul dh                  ; ax = dh * 160
    mov di, ax              ; di = 行偏移

    mov al, dl
    mov ah, 0
    add ax, ax              ; ax = dl * 2 (列偏移)
    add di, ax              ; di 最终指向目标行列在显存中的物理偏移

    ; 2. 遍历字符栈，依次写入显存
    mov bx, 0               ; bx 作为遍历字符栈的索引 (0 到 top-1)

charshows:
    cmp bx, top             ; 遍历是否达到当前栈顶？
    jne show_char           ; 若未到达栈顶，输出栈中真实字符

    ; 当到达栈顶时，在光标当前位置输出一个空格符，抹除可能残留的旧字符
    mov byte ptr es:[di], ' '
    jmp sret

show_char:
    mov al, [si+bx]         ; 读取字符栈中的字符
    mov es:[di], al         ; 写入显存偶地址单元 (ASCII 码)
    mov byte ptr es:[di+1], 07h ; 写入属性字节 (07H 代表黑底白字标准属性)
    inc bx                  ; 下一个字符
    add di, 2               ; 下一个显存字符单元
    jmp charshows

sret:
    pop es
    pop di
    pop dx
    pop bx                  ; 恢复通用及段寄存器
    ret                     ; 子功能执行完毕，返回调用处
```

通过本讲字符串输入程序的设计，我们不仅掌握了一个交互式输入模块的完整底层实现，更获得了两项在汇编语言乃至系统级编程中至关重要的工程设计能力：

## 20 磁盘读写
> 对应分集：P78 | 原始标题：《20 磁盘读写》

在前面的课程中，我们所有的程序数据要么写在代码段里，要么临时放在内存与栈中，断电之后一切荡然无存。要想让程序持久化保存，或者在开机引导时把操作系统内核搬进内存，就必须和计算机最核心的外部存储介质——**磁盘**打交道。

在微机系统中，面对机械旋转的磁盘盘片、移动的磁头臂和密密麻麻的同心圆磁道，我们如何用汇编指令精准地读写某一段数据？

这一讲，我们就从磁盘的物理几何结构（CHS 寻址模型）出发，系统解析 BIOS 提供的底层扇区读写服务（`INT 13H`），并对比操作系统层面的 DOS 中断服务（`INT 21H`），彻底掌握汇编语言操控外存的软硬件协同规范。

---

### 磁盘的物理几何结构与 CHS 寻址

微机系统中的外存主要包括软盘（Floppy Disk）和硬盘（Hard Disk）。虽然软盘在现代计算机中早已被淘汰，但不管是传统的 3.5 英寸软盘还是机械硬盘，它们底层的物理存储几何原理是完全一脉相承的。

```text
磁盘物理结构与 CHS 寻址示意图：

                   ┌─────────────────┐
                   │   主轴旋转方向   │
                   └────────┬────────┘
                            ▼
                ┌───────────────────────┐
             ／                           ＼
          ／        磁道 (Track / 柱面)     ＼
        ／        ┌───────────────────┐       ＼
       │         ／   扇区 (Sector)    ＼       │
       │        │   ┌───────────────┐   │       │
       │  磁头 ──┼──►│ 512 字节数据区 │   │       │ ◄── 磁盘表面 (Surface / Head)
       │ (Head) │   └───────────────┘   │       │
       │         ＼                   ／        │
        ＼        └───────────────────┘        ／
          ＼                                 ／
             ＼                           ／
                └───────────────────────┘
```
*图说明：磁盘由盘面（磁头）、磁道（同心圆柱面）和扇区（弧段）组成，最小读写物理单位为扇区。*

#### 磁盘三大物理几何要素

1. **磁头（Head，对应盘面）**：
   - 软盘通常只有两个盘面（正面和反面），分别由 0 号和 1 号两个磁头负责读写；
   - 硬盘通常由多个平行的金属盘片垂直重叠而成，每个盘面都对应一个专用的读写磁头，编号依次为 0, 1, 2...
2. **磁道（Track / 柱面 Cylinder）**：
   - 盘片表面被划分为成百上千个同心圆，每个同心圆被称为一条**磁道**；
   - 所有盘面上半径相同的磁道在空间上组合起来，构成一个圆柱面，因此在物理寻址中磁道号通常与**柱面号**等同，编号从 0 开始。
3. **扇区（Sector）**：
   - 每条磁道并不是一个整体，而是被等角度均分为若干段弧区，每一段称为一个**扇区**；
   - **扇区是磁盘进行数据物理读写的最小基本单位**。在标准微机系统中，一个物理扇区的容量固定为 **512 字节**。

> **注意**：
> 在 CHS 寻址系统中，磁道号（柱面号）和磁头号都是从 **0** 开始编号的，但**扇区号必须从 1 开始编号**（即第 1 扇区、第 2 扇区……），绝不能写成 0 扇区。这是很多初学者在编写磁盘读写代码时极易踩中的硬件规范大坑。

---

### 磁盘访问的抽象层次

与键盘输入类似，在汇编语言中访问磁盘同样存在三个层次：

1. **直接硬件端口控制**：直接用 `in`/`out` 指令读写磁盘控制器的 I/O 端口。由于不同厂商、不同接口协议（IDE、SATA 等）的控制器芯片寄存器定义极其繁复且完全不同，在应用开发中极少直接采用。
2. **BIOS 磁盘中断（INT 13H）**：由主板 ROM BIOS 提供的系统级扇区级物理读写接口。它对磁盘控制器做了统一抽象，让程序员只需指定 CHS 参数即可完成物理扇区的精准搬运。系统启动引导程序（Bootloader）就是依赖 `INT 13H` 把操作系统载入内存的。
3. **DOS 系统中断（INT 21H）**：由操作系统构建在 BIOS 之上的文件系统接口。它为用户屏蔽了物理磁道、柱面和扇区的概念，向上提供文件（File）和目录（Directory）的高层抽象。

### BIOS 磁盘服务中断：INT 13h

在 BIOS 中，负责处理磁盘物理输入输出的核心软中断是 **`INT 13H`**。
通过在寄存器 `AH` 中传入不同的功能号，可以执行不同的底层磁盘操作：
- `AH = 02H`：从磁盘读取扇区到内存；
- `AH = 03H`：将内存数据写入磁盘扇区；
- `AH = 00H`：磁盘系统复位；
- `AH = 05H`：格式化磁道。

#### 读扇区操作规范（AH = 02H）

##### 入口参数规范
调用前必须在各寄存器中按规范整齐装入 CHS 寻址参数与缓冲区指针：
- **`AH`**：`02H`（功能号：读扇区）；
- **`AL`**：待读取的连续扇区数量；
- **`CH`**：磁道号（柱面号的低 8 位）；
- **`CL`**：起始扇区号（注意：从 1 起始）；
- **`DH`**：磁头号（盘面号）；
- **`DL`**：驱动器编号：
  - 软驱：`00H` 为软驱 A，`01H` 为软驱 B；
  - 硬盘：`80H` 为主硬盘（C 盘），`81H` 为从硬盘（D 盘）；
- **`ES:BX`**：接收读出数据的内存缓冲区基地址（段地址放入 `ES`，偏移地址放入 `BX`）。

##### 出口参数与状态检验
中断执行完毕后，CPU 通过进位标志位 $CF$ 和寄存器状态返回操作结果：
- **操作成功**：
  - 进位标志位 $CF = 0$；
  - $AH = 00H$；
  - $AL$ 返回实际成功读取的扇区总数。
- **操作失败**：
  - 进位标志位 $CF = 1$；
  - $AH$ 中返回具体的错误代码（例如 `01H` 非法命令、`02H` 找不到地址标记、`04H` 扇区未找到、`09H` 跨段溢出等，可对照 BIOS 错误代码表定位）。

```text
INT 13H (AH=02H) 寄存器传参映射表：

 寄存器           参数含义                 取值示例
─────────────────────────────────────────────────────────────
 AH       功能号 (02H 读扇区)              02H
 AL       读取的扇区数                     01H (读 1 个扇区, 512B)
 CH       磁道号 (柱面)                    00H (0 道)
 CL       扇区号 (从 1 开始!)              01H (1 扇区)
 DH       磁头号 (盘面)                    00H (0 面)
 DL       驱动器号                         80H (第一块硬盘 C:)
 ES:BX    内存目标接收缓冲区               0000:0200H
─────────────────────────────────────────────────────────────
```

#### 读扇区实操代码示例

> **任务需求**：
> 将 C 盘（第一块硬盘）的 0 面、0 道、1 扇区（即著名的主引导记录 MBR / 分区引导扇区）的 512 字节内容，完整读取到内存 `0000:0200H` 处。

```assembly
assume cs:code

code segment
start:
    ; 1. 设置接收数据的目标内存缓冲区基地址 ES:BX = 0000:0200H
    mov ax, 0
    mov es, ax
    mov bx, 0200h

    ; 2. 装填 CHS 寻址与驱动器参数
    mov al, 1            ; 读取 1 个扇区 (512 字节)
    mov ch, 0            ; 磁道号: 0
    mov cl, 1            ; 扇区号: 1 (注意: 扇区从 1 起始)
    mov dh, 0            ; 磁头号: 0
    mov dl, 80h          ; 驱动器号: 80H 代表硬盘 C

    ; 3. 指定功能号并调用 BIOS 磁盘中断
    mov ah, 02h          ; 读扇区功能号
    int 13h

    ; 4. 检查操作结果
    jc read_error        ; 若 CF = 1，表示读取失败，跳转到错误处理

    ; 读取成功，此时内存 0000:0200H 处已就绪 512 字节数据
    mov ax, 4c00h
    int 21h

read_error:
    ; 错误处理逻辑 (AH 中保存错误代码)
    mov ax, 4c01h
    int 21h

code ends
end start
```

### 写扇区操作规范（AH = 03H）

与读扇区相对，写扇区是将内存中的一段数据持久化写入物理磁盘的指定扇区。

写扇区的功能号为 **`AH = 03H`**。其寄存器传参规范、寻址规则与返回状态与读扇区完全一致，唯一的区别是：
**`ES:BX` 指向的是存有待写入数据的源内存缓冲区**。

#### 写扇区实操代码示例

> **任务需求**：
> 将内存 `0000:0200H` 处的连续 512 字节数据，写入 C 盘的 0 面、0 道、1 扇区中。

```assembly
assume cs:code

code segment
start:
    ; 1. 设置待写入数据的源内存缓冲区地址 ES:BX = 0000:0200H
    mov ax, 0
    mov es, ax
    mov bx, 0200h

    ; 2. 装填 CHS 寻址与驱动器参数
    mov al, 1            ; 写入 1 个扇区
    mov ch, 0            ; 磁道号: 0
    mov cl, 1            ; 目标扇区号: 1
    mov dh, 0            ; 磁头号: 0
    mov dl, 80h          ; 目标驱动器: 80H (硬盘 C)

    ; 3. 指定功能号并调用中断
    mov ah, 03h          ; 写扇区功能号
    int 13h

    ; 4. 结果检测
    jc write_error       ; 若 CF = 1，写入失败

    mov ax, 4c00h
    int 21h

write_error:
    mov ax, 4c01h
    int 21h

code ends
end start
```

> **易错点**：
> 物理扇区直接写入是非常危险的操作！在真实系统或带重要数据的磁盘上，随意对 0 面 0 道 1 扇区执行写操作会直接破坏硬盘的分区表或 MBR，导致系统彻底无法引导。在实验与演练时务必在虚拟机或镜像软盘环境中测试。

### DOS 磁盘与文件管理中断：INT 21h

`INT 13H` 虽然强大，但它只认“物理扇区”。在开发日常应用程序时，用户只想“打开文件 `data.txt`”、“创建文件夹 `my_folder`”，如果让每个程序员都去自行计算文件存放在哪个磁道、哪个扇区，并自行维护 FAT 文件分配表，开发成本将不可承受。

因此，操作系统的核心使命之一就是提供文件系统封装。在 DOS 环境下，这一职责由 **`INT 21H`** 的高层子功能提供：

- **目录控制**：
  - `AH = 39H`：创建子目录（mkdir）；
  - `AH = 3AH`：删除子目录（rmdir）；
  - `AH = 3BH`：改变当前工作目录（chdir）；
  - `AH = 47H`：获取当前目录路径。
- **文件操作**：
  - `AH = 3CH`：创建文件；
  - `AH = 3DH`：打开文件并获取文件句柄（File Handle）；
  - `AH = 3EH`：关闭文件句柄；
  - `AH = 3FH`：从文件句柄读取数据；
  - `AH = 40H`：向文件句柄写入数据。

#### DOS 创建目录示例（AH = 39H）

以创建新目录为例，展示 DOS 系统调用的高层抽象特征：

```assembly
assume cs:code, ds:data

data segment
    ; 以 0 结尾的 ASCIIZ 字符串路径
    dirname db 'c:\temp\asm_dir', 0
data ends

code segment
start:
    mov ax, data
    mov ds, ax

    ; 调用 DOS 39H 号功能创建目录
    mov ah, 39h
    lea dx, dirname      ; DS:DX 指向路径字符串首地址
    int 21h

    ; 检查出口参数
    jc create_failed     ; 若 CF = 1，创建失败，AX 中包含 DOS 错误码 (如 03H 路径未找到, 05H 拒绝访问)

    ; 创建成功
    mov ax, 4c00h
    int 21h

create_failed:
    mov ax, 4c01h
    int 21h

code ends
end start
```

我们可以清晰地看到：在调用 DOS 中断时，我们完全不需要知道硬盘有几个盘面、几条磁道，甚至不需要关心底层是机械硬盘、软盘还是固态虚拟盘。DOS 的文件系统驱动会自动将逻辑路径映射解析为物理扇区，并在底层调用 `INT 13H` 完成扇区分配与写入。

### 中断服务调用的统一工程范式

从键盘的 `INT 16H`，到磁盘扇区的 `INT 13H`，再到文件目录的 `INT 21H`，汇编语言调用系统级服务程序已经展现出极其统一且严谨的工程思维范式：

```text
系统级中断调用四步法则：

  [ 步骤 1: 查阅接口规范 ] ──► 明确功能号与各寄存器参数语义
            │
            ▼
  [ 步骤 2: 现场环境装配 ] ──► 段寄存器(DS/ES) + 通用寄存器(AX/BX/CX/DX) 严格赋值
            │
            ▼
  [ 步骤 3: 触发目标中断 ] ──► 执行 INT n 指令转入底层服务例程
            │
            ▼
  [ 步骤 4: 出口状态校验 ] ──► 检测 CF 标志位，成功则提取数据，失败则分流排错
```

掌握了这一通用范式，在未来遇到任何外部硬件驱动或操作系统未开放的高级调用时，只要手握一份芯片或系统手册，就能准确无误地编写出稳健的底层接口程序。

## 21 让计算机唱歌
> 对应分集：P79 | 原始标题：《21 让计算机唱歌》

在前面的学习中，我们操控计算机输出信息，大多停留在向屏幕打印字符或向显存直接写数据。但计算机不仅仅能看，还能“听”和“唱”。当早期 PC 开机自检通过时会发出“哔”的一声短鸣，运行出错时会有急促的蜂鸣报警，甚至还能用蜂鸣器演奏出动听的音乐。

计算机内部并没有一个内置的 MP3 播放器，也没有复杂的声卡驱动支持。在最底层的实模式汇编环境下，究竟是怎样的硬件通道让计算机的蜂鸣器发出了高低各异、长短有致的旋律？

要让计算机“唱歌”，本质上就是 CPU 通过 I/O 端口直接操纵底层的可编程接口芯片。这一讲我们将通过操控 8253 定时器与 8255 并行接口芯片，剖析音高与音长的物理发生机制，并用汇编语言建立数字化乐谱，实现完整的音乐演奏程序。

### 外部设备接口与端口访问层次

外部设备要想与 CPU 协同工作，必须依赖硬件接口控制器的桥接。理解外设的控制层次，是掌握微机底层编程的关键基石。

```text
CPU 访问外部设备的三层架构模型：

  ┌────────────────────────────────────────────────────────┐
  │              应用程序 / 高级语言调用层                  │
  └──────────────────────────┬─────────────────────────────┘
                             │
                             ▼
  ┌────────────────────────────────────────────────────────┐
  │     系统级抽象层：DOS 中断 (INT 21H) / BIOS 中断服务    │
  └──────────────────────────┬─────────────────────────────┘
                             │ (软件封装)
                             ▼
  ┌────────────────────────────────────────────────────────┐
  │       底层直接硬件访问层：IN / OUT 指令操作 I/O 端口    │
  └──────────┬─────────────────────────────────┬───────────┘
             │                                 │
             ▼                                 ▼
    ┌─────────────────┐               ┌─────────────────┐
    │  8253 定时计数器 │               │ 8255 并行接口   │
    │   (控制发声频率) │               │   (控制发声开关)│
    └────────┬────────┘               └────────┬────────┘
             │                                 │
             └───────────────┬─────────────────┘
                             ▼
                    ┌─────────────────┐
                    │    系统扬声器   │
                    │   (发声执行体)  │
                    └─────────────────┘
```
*图说明：应用程序既可通过 BIOS/DOS 中断访问外设，也可通过 IN/OUT 指令直接读写接口芯片的 I/O 端口。*

#### 外部设备的连接与中断响应

在微机体系结构中，外部设备并非直接挂接在 CPU 的数据总线上，而是通过专门的可编程芯片（接口控制器）与 CPU 相连。
- 当外部设备状态发生变化或需要 CPU 处理时，会向 CPU 发出中断请求信号（如键盘击键产生的中断）；
- CPU 在接收到中断后暂停当前指令流，根据中断向量表跳转执行对应的中断服务例程，完成设备响应。

#### 中断服务调用与直接端口访问

我们在汇编语言中操控外设，通常存在两个清晰的层次：
1. **高级服务中断**：
   通过操作系统（DOS 中断）或固化在 ROM 里的 BIOS 中断服务来间接使用外设。例如前面学过的 `INT 10H`（显示服务）、`INT 16H`（键盘服务）和 `INT 13H`（磁盘服务）。这些服务屏蔽了具体硬件电路的繁杂细节，接口通用且安全。
2. **底层端口直接访问**：
   程序绕过操作系统与 BIOS，直接使用 `IN` 和 `OUT` 指令向外设控制器的寄存器端口读写控制字和数据。

> **定义**：
> 在很多计算机专业的《微机原理与接口技术》课程中，会系统讲解各种各样的接口芯片。所谓对芯片的控制，从汇编语言的视角来看，本质上就是明确这块芯片占用了哪几个 I/O 端口地址，并通过 `IN` / `OUT` 指令向指定端口写入特定格式的控制字或读取状态字。

掌握了端口控制的通用编程模式，就掌握了操作一切底层硬件的总钥匙。

### PC 机发声系统硬件架构

声音是一种由于物体机械振动而在介质中传播的机械波。要让 PC 机的板载扬声器发出声音，就必须为扬声器的驱动电磁铁输入特定频率和持续时间的交变电信号。

```text
PC 机发声系统的硬件逻辑控制通路：

  ┌───────────────┐
  │ 1.19318 MHz   │
  │ 系统基准时钟  │
  └───────┬───────┘
          │
          ▼
  ┌───────────────┐
  │   8253 芯片   │ (计数器 2 产生方波)
  │  (端口 42H)   │────────────────────────┐
  └───────────────┘                        │
                                           ▼
  ┌───────────────┐               ┌─────────────────┐
  │   8255 芯片   │ 位 0 (GATE2)  │                 │
  │  (端口 61H)   │──────────────►│ 硬件逻辑“与”门  │──► 驱动电路 ──► 扬声器 (喇叭)
  │               │ 位 1 (PB1)    │                 │
  └───────────────┘──────────────►│                 │
                                  └─────────────────┘
```
*图说明：8253 产生的频率信号与 8255 的控制位经门电路与运算后，共同决定扬声器是否振动及振动频率。*

物理学与声学告诉我们，一首悦耳的音乐由两个最基本的物理要素构成：
1. **音高（Pitch）**：由声波的振动频率决定。频率越高，音调越尖锐高亢；频率越低，音调越低沉；
2. **音长（Duration）**：指某一特定频率的声音持续发声的时间长短。

在 PC 机主板的硬件设计中，声音的这两个要素分别交由两块核心芯片协作控制：
- **8253 定时器/计数器芯片**：负责产生指定频率的周期性方波脉冲信号，控制声音的**音高**；
- **8255 可编程并行接口芯片**：负责开启与关闭扬声器的物理信号通路，配合软件延时控制发声的**音长**。

两块芯片各司其职，相辅相成，构成了完整的硬件发声驱动链。

### 8253 定时器芯片与音高控制

8253 是微机系统中非常经典的可编程计数器/定时器芯片（PIT, Programmable Interval Timer）。它内部包含三个独立的 16 位计数器通道（通道 0、通道 1 和通道 2）。其中，**通道 2** 在硬件布线上专门用于驱动系统扬声器发声。

#### 43H 端口控制字设置

要让 8253 的通道 2 工作在能够驱动扬声器的方波发生器模式下，必须首先向其控制寄存器写入方式控制字。8253 的控制寄存器映射在 I/O 端口的 `43H`。

```assembly
mov al, 0b6h
out 43h, al
```

控制字 `0B6H`（即二进制 `10110110B`）的每一位都具有严格的硬件含义：
- **D7~D6 = 10**：选择通道 2（Counter 2）；
- **D5~D4 = 11**：设定计数初值的读写格式为“先读写低 8 位，后读写高 8 位”；
- **D3~D1 = 011**：设定工作方式为“方式 3（Mode 3），即方波发生器”；
- **D0 = 0**：设定计数制为 16 位二进制计数（非 BCD 码）。

执行 `OUT 43H, AL` 之后，8253 芯片的通道 2 就进入了待命状态，等待接收具体的频率分频计数值。

#### 计数值生成与 42H 端口分步写入

8253 芯片接入的主板基准时钟脉冲频率固定为 $f_{\text{clk}} = 1.19318\text{ MHz} = 1193180\text{ Hz}$。
如果我们需要扬声器发出频率为 $F$（单位为 $\text{Hz}$）的声音，计数器所需的 16 位分频计数值 $N$ 可由下式计算：

$$N = \frac{f_{\text{clk}}}{F} = \frac{1193180}{F}$$

$1193180$ 的十六进制表示为 `1234DCH`。这是一个超过 16 位的数值，因此在汇编中必须使用 32 位被除数除以 16 位除数的字除法指令：
- 将高 16 位 `12H` 送入 `DX` 寄存器；
- 将低 16 位 `34DCH` 送入 `AX` 寄存器；
- 此时 `DX:AX` 构成了完整的被除数 $1193180$；
- 通过 `DIV` 指令，除以内存中保存的音符目标频率值（设由寄存器 `SI` 寻址），商即为所需的计数值 $N$，保存在 `AX` 中。

```assembly
; 准备 32 位被除数 1193180 (1234DCH)
mov dx, 12h
mov ax, 34dch
div word ptr [si]    ; [si] 中存放音符频率 F，执行后商 N 保存在 AX 中
```

得到 16 位的计数值 `AX` 之后，需要将其写入 8253 通道 2 的数据端口 `42H`。

> **易错点**：
> 8253 的数据端口 `42H` 是一个 8 位端口，而计数值 `AX` 是一个 16 位的字数据。由控制字 `0B6H` 的设定规定，CPU 必须严格按照**先送低 8 位、后送高 8 位**的时序分两次写入，绝对不能一次性传送一个字：

```assembly
out 42h, al          ; 第一次输出：将计数值低 8 位写入 42H 端口
mov al, ah           ; 将高 8 位送入 AL
out 42h, al          ; 第二次输出：将计数值高 8 位写入 42H 端口
```

两次写入完成后，8253 通道 2 便开始以指定的频率 $F$ 持续输出方波电平信号。

### 8255 并行接口芯片与发声开关

虽然 8253 已经在振荡输出方波，但此时扬声器依然不会发声。因为在硬件电路上，8253 输出的信号与扬声器之间还串联着一个由 8255 芯片控制的逻辑开关。

#### 61H 端口的开关控制机制

8255 是可编程并行接口芯片（PPI, Programmable Peripheral Interface），其 PB 端口映射在 I/O 端口 `61H`。
`61H` 端口的最低两位直接决定了声音通路的通断：
- **位 0（GATE2）**：8253 通道 2 的门控信号端。当该位置 $1$ 时，8253 计数器才被允许启动计数；
- **位 1（PB1）**：扬声器数据驱动端。当该位置 $1$ 时，才允许将 8253 产生的方波信号通过与门驱动喇叭振动。

```text
61H 端口控制字最低两位的逻辑真值表：

┌──────┬──────┬──────────────────────────────┐
│ 位 1 │ 位 0 │ 发声通路状态                 │
├──────┼──────┼──────────────────────────────┤
│  0   │  0   │ 计数器关闭，扬声器静音       │
│  0   │  1   │ 计数器工作，但输出被门电路拦截│
│  1   │  0   │ 门控关闭，无方波输出         │
│  1   │  1   │ 计数器启动且方波直达扬声器(发声)│
└──────┴──────┴──────────────────────────────┘
```

因此，必须把 `61H` 端口的最低两位**同时置为 1**，扬声器才能真正开始鸣叫。

#### 底层端口的读取-修改-恢复规范

`61H` 端口不仅控制着扬声器，还控制着系统主板的其他硬件功能（例如奇偶校验检查、键盘接口时钟等）。如果我们在程序里不管不顾地直接 `MOV AL, 3` 并 `OUT 61H, AL`，就会把高 6 位原本属于其他外设的配置彻底冲掉，引发严重的系统不稳定。

因此，在操作系统底层与接口芯片编程中，必须严格执行**读取-修改-恢复（Read-Modify-Write）**工程规范：

```assembly
; 1. 读取原值并现场保护
in al, 61h           ; 从 61H 端口读入当前系统设置
mov ah, al           ; 将原值备份暂存在 AH 中

; 2. 定向修改发声控制位
or al, 3             ; 仅将最低两位（D0 和 D1）置为 1，其余位保持不变
out 61h, al          ; 写回 61H 端口，开启扬声器发声

; ... (此处执行延时等待，让声音维持一定长度) ...

; 3. 恢复现场并关闭发声
mov al, ah           ; 取回备份的原始端口值
out 61h, al          ; 还原 61H 端口原有状态，扬声器静音
```

通过这一标准范式，既达成了精准开启扬声器的目的，又不会对宿主系统原有的硬件状态造成任何破坏。

### 乐谱的数字化表示模型

计算机不懂五线谱，更看不懂工尺谱。要让计算机演奏音乐，必须在程序中将人类可读的乐谱转化为计算机能够处理的数组结构——**数字化乐谱**。

#### 音符频率映射表

标准简谱中的每一个音符，在声学上都对应着一个严格的基准物理频率。

| 简谱音符 | 唱名 | 典型音名 | 物理振动频率（Hz） |
| :---: | :---: | :---: | :---: |
| <u>5</u> | 低音 Sol | G3 | $196$ |
| <u>6</u> | 低音 La | A3 | $220$ |
| <u>7</u> | 低音 Si | B3 | $247$ |
| 1 | 中音 Do | C4 | $262$ |
| 2 | 中音 Re | D4 | $294$ |
| 3 | 中音 Mi | E4 | $330$ |
| 4 | 中音 Fa | F4 | $349$ |
| 5 | 中音 Sol | G4 | $392$ |
| 6 | 中音 La | A4 | $440$ |
| 7 | 中音 Si | B4 | $494$ |
| 1̇ | 高音 Do | C5 | $523$ |

以经典儿歌《新年好》为例，乐谱开头的旋律为：
> `1 1 1 5 | 3 3 3 1 | 1 3 5 5 | 4 3 2 - | ...`

将其提取为频率数组：
- 前三个 `1`：对应频率数值 `262, 262, 262`
- 随后的 `5`（低音）：对应频率数值 `196`
- 紧接着的 `3 3 3 1`：对应频率数值 `330, 330, 330, 262`

#### 节拍时长与乐谱终止标志

乐谱不仅规定了每个音的频率，还规定了每个音的节拍。在程序中，音长的本质是**延时循环的轮数**。
我们可以用一个相对数值来量化音长：
- 较短的单拍音符：定义为数值 `12`；
- 较长的两拍音符：时间翻倍，定义为数值 `25`；
- 句尾的四拍长音（全音符）：定义为数值 `50`。

为了让主循环知道一首歌曲何时播放完毕，必须在乐谱数据的尾部设置一个特殊的**哨兵标记（Sentinel）**。由于正常的声音频率都是正整数，我们通常在频率表的末尾放置 `-1`（即十六进制 `0FFFFH`）作为乐曲结束的标志。

```assembly
music_freq dw 262, 262, 262, 196, 330, 330, 330, 262, -1
music_time dw  12,  12,  25,  25,  12,  12,  25,  25
```

### 音乐播放程序的架构设计与完整实现

有了硬件接口知识与数字化乐谱，整个汇编程序的架构变得清晰明朗。程序分为两个核心模块：
1. **主程序调度模块**：负责段寄存器初始化，使用指针遍历频率表与时长表，并判断是否播放完毕；
2. **`SOUND` 发声子程序**：负责根据传入的单个频率和时长，配置 8253 与 8255，维持延时，最后复位硬件。

```text
音乐播放程序控制流程图：

  [ 初始化 DS 与堆栈 ]
           │
           ▼
  [ 寄存器寻址初始化: LEA SI, FREQ; LEA DI, TIME ]
           │
           ▼
  ┌──► [ 取当前音符频率: MOV AX, [SI] ]
  │        │
  │        ▼
  │    [ 检查结束标志: CMP AX, -1 ] ──(相等)──► [ 退出程序 INT 21H ]
  │        │ (不相等)
  │        ▼
  │    [ 调用发声子例程: CALL SOUND ]
  │        │
  │        ▼
  │    [ 指针步进: ADD SI, 2; ADD DI, 2 ]
  │        │
  └────────┘ (无条件跳转 JMP，播放下一个音符)
```
*图说明：主程序采用数据驱动架构，按字指针依次遍历乐谱数据表，直到命中哨兵值 -1 退出。*

#### 主循环遍历与指针步进控制

主程序中：
- 用变址寄存器 `SI` 寻址频率表 `MUSIC_FREQ`；
- 用变址寄存器 `DI` 寻址音长表 `MUSIC_TIME`；
- 由于两个表均定义为字数组（`DW`），每次演奏完毕后，指针必须执行 `ADD SI, 2` 和 `ADD DI, 2` 步进到下一个音符单元。

#### SOUND 发声子程序与双重循环延时

在发声子例程中，时间的把控依赖于 CPU 执行空循环所消耗的时间。
为了实现精确且足够长的延时，我们采用**双重循环**结构：
- **外层循环**：以内参时长数据 `[DI]` 作为计数初值送入 `DX` 寄存器；
- **内层循环**：设置一个固定的高循环计数（如 $28000$ 次）；
- 内层跑满一轮，$DX$ 减 $1$，直到 $DX$ 减至 $0$ 退出，形成均匀的延时节拍。

#### 完整汇编源代码

```assembly
assume cs:code, ds:data, ss:stack

stack segment
    db 128 dup(0)
stack ends

data segment
    ; 《新年好》数字化乐谱 (以 -1 为结束哨兵)
    music_freq dw 262, 262, 262, 196, 330, 330, 330, 262
               dw 262, 330, 392, 392, 349, 330, 294
               dw 294, 330, 349, 349, 330, 294, 330, 262
               dw 262, 330, 294, 196, 247, 294, 262, -1

    music_time dw 12, 12, 25, 25, 12, 12, 25, 25
               dw 12, 12, 25, 25, 12, 12, 50
               dw 12, 12, 25, 25, 12, 12, 25, 25
               dw 12, 12, 25, 25, 12, 12, 50
data ends

code segment
start:
    ; 1. 初始化数据段与堆栈
    mov ax, data
    mov ds, ax

    ; 2. 乐谱表首地址分别装入 SI 与 DI
    lea si, music_freq
    lea di, music_time

play_loop:
    ; 3. 取出当前音符频率，检查是否为终止标志 -1
    cmp word ptr [si], -1
    je exit_program

    ; 4. 调用发声子程序演奏当前音符
    call sound

    ; 5. 指针步进一个字 (2 字节)
    add si, 2
    add di, 2
    jmp play_loop

exit_program:
    mov ax, 4c00h
    int 21h

; ------------------------------------------------------------
; 发声子程序 SOUND
; 入口参数：[SI] 为当前音符频率，[DI] 为当前音符时长
; ------------------------------------------------------------
sound proc
    push ax
    push bx
    push cx
    push dx

    ; 步骤 A: 设置 8253 通道 2 工作方式 (方式 3，方波)
    mov al, 0b6h
    out 43h, al

    ; 步骤 B: 计算计数值 N = 1193180 / [SI]
    mov dx, 12h
    mov ax, 34dch
    div word ptr [si]

    ; 步骤 C: 分两次送入 8253 计数器 2 数据端口 42H (先低后高)
    out 42h, al
    mov al, ah
    out 42h, al

    ; 步骤 D: 读取 61H 端口原值并开启扬声器
    in al, 61h
    mov ah, al           ; AH 保存原配置现场
    or al, 3             ; 开启扬声器驱动与 8253 门控
    out 61h, al

    ; 步骤 E: 双重循环软件延时
    mov dx, [di]         ; 外层循环次数由乐谱时长决定
delay_outer:
    mov cx, 28000        ; 内层空循环基数
delay_inner:
    loop delay_inner
    dec dx
    jnz delay_outer

    ; 步骤 F: 恢复 61H 端口原值，静音并恢复系统状态
    mov al, ah
    out 61h, al

    pop dx
    pop cx
    pop bx
    pop ax
    ret
sound endp

code ends
end start
```
