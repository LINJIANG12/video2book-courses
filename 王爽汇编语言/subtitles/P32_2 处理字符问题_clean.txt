# 汇编语言：字符问题的处理与大小写转换

### [00:00] 课程引入与字符处理背景

计算机不仅可以处理数值问题，而且还可以处理文字问题。在本节中，我们来介绍处理字符问题的方法。通过本节所引出的示例，还将为后续几节关于“寻址方式”的学习提供一个实际的应用背景。

### [00:15] 汇编语言中的字符与 ASCII 码

关于处理字符问题的方法，首先看一下在汇编语言中对字符的处理方式。

在汇编语言当中，使用**单引号**（例如 `'...'`）包含字符的方式，指明数据是以字符的形式给出的。编译器将会把这些字符转换为对应的 ASCII 码。

对于 ASCII 码，大家应当比较熟悉：
* 大写字母 `'A'`：十进制表示为 $65$，十六进制表示为 $41\text{H}$；
* 小写字母 `'a'`：十进制表示为 $97$，十六进制表示为 $61\text{H}$；
* 其他字母也是类似的，并且包括其他各种符号，在计算机中都有对应的 ASCII 码值。这些内容在高级语言中大家都接触过。

### [01:00] 字符在汇编中的定义与 DEBUG 观察

接下来看这样一个程序：在这个程序当中定义了数据段（`data segment`），也定义了代码段（`code segment`）。在数据段中，我们定义了两个字符串，它们是用单引号引起来的；而在代码段中，也涉及到了对字符的处理。

```assembly
assume cs:code, ds:data

data segment
    db 'unix'
    db 'fork'
data ends

code segment
start:
    mov al, 'a'
    mov bl, 'b'
    
    mov ax, 4c00h
    int 21h
code ends
end start
```

当把这段代码编译之后，我们在 DEBUG 中使用 `u` 命令查看反汇编代码，会发现：

```assembly
mov al, 61
mov bl, 62
```

这两条指令正是由源代码中的两句赋值语句编译生成的。由此可见，对于字符 `'a'` 和 `'b'`，在目标代码中已经直接使用了它们的 ASCII 码值（小写 `'a'` 和 `'b'` 的 ASCII 码分别为 $61\text{H}$ 和 $62\text{H}$）。

### [01:44] 内存中数据段的定位与字符存储验证

另外，我们可以观察寄存器的值。在程序刚加载进入内存时，`DS` 寄存器的值为 `075A`。当使用 DEBUG 加载编译好的可执行程序后，此时 `DS` 的值即为程序进入内存后的起始物理基地址（对应 PSP 前缀段）。

我们知道，程序段前缀（PSP）的大小一共是十六进制的 $100\text{H}$ 个字节（即 $10\text{H}$ 个段地址单位）。对于物理地址而言，段地址 `075A` 对应物理地址为 `075A0H`，加上 $100\text{H}$ 字节之后，该程序真正的数据段（`data segment`）起始段地址应该是从 `076A` 开始的。

因此，当我们使用 `d` 命令查看 `076A:0` 处的数据时：

```text
-d 076a:0
```

确实可以看到对应的内存单元中出现了字符 `'u'`, `'n'`, `'i'`, `'x'`, `'f'`, `'o'`, `'r'`, `'k'` 对应的 ASCII 码值。
* 例如小写 `'u'` 对应的 ASCII 码是 $75\text{H}$；
* 紧接着小写 `'n'` 对应的是 $6\text{EH}$。

在内存单元中所存储的完全就是字符的 ASCII 码值。因此可以明确：在源程序中出现的字符，只要用单引号括起来，编译器在处理时都会将其替换为该字符的 ASCII 码值。

### [03:23] 大小写字母 ASCII 码的编码规律

进一步了解我们常用的字符规律。在文字处理中，最常关注的是大写字母和小写字母。那么大写字母与小写字母在 ASCII 码值上有什么样的内在关联？

观察十六进制表示：
* 小写 `'a'` 是 $61\text{H}$，大写 `'A'` 是 $41\text{H}$；
* 小写 `'b'` 是 $62\text{H}$，大写 `'B'` 是 $42\text{H}$。

从十六进制来看，它们均相差 $20\text{H}$。

而相差 $20\text{H}$ 这一特点在**二进制**下的体现如下：

| 字符 | 十六进制 | 二进制编码 |
| :--- | :--- | :--- |
| 大写 `'A'` | $41\text{H}$ | `0100 0001B` |
| 小写 `'a'` | $61\text{H}$ | `0110 0001B` |
| 大写 `'B'` | $42\text{H}$ | `0100 0010B` |
| 小写 `'b'` | $62\text{H}$ | `0110 0010B` |

对比大写字母和小写字母的二进制编码可以发现：除了从右往左数的**第 6 位（即 bit 5）**之外，其他所有位都是完全相同的：
* 大写字母的第 6 位（bit 5）为 **`0`**；
* 小写字母的第 6 位（bit 5）为 **`1`**。

对于 `'B'`、`'C'` 等后续所有英文字母，其大小写之间均遵循这一规律。看清这个规律后，在后续进行大小写转换处理时，便可以充分加以利用。

总结基本规律：
* 大写字母 ASCII 码 $+ 20\text{H} =$ 对应小写字母 ASCII 码；
* 小写字母 ASCII 码 $- 20\text{H} =$ 对应大写字母 ASCII 码。

### [04:58] 实际转换任务与非分支解题思路

接下来通过具体问题来应用这一规律。

**任务要求**：
在数据段中通过 `db`（定义字节）定义了两个字符串：
1. 第一个字符串为大小写混杂的 `'BaSic'`；
2. 第二个字符串为大小写混杂的 `'iNfOrMaTiOn'`。

现要求对这两个字符串进行转换处理：
* 第一个字符串：将其中的小写字母全部转为大写字母；如果原本就是大写字母则保持不变，最终得到纯大写的 `'BASIC'`；
* 第二个字符串：将其中的大写字母全部转为小写字母；如果原本就是小写字母则保持不变，最终得到纯小写的 `'information'`。

面对这个任务，通常第一反应是考虑是否需要使用条件分支结构（例如通过比较判断“若为小写则转大写，否则不处理”）。然而，使用分支跳转结构虽可解决，但本节采用更加简便高效的**位运算技巧**，无需任何控制转移指令，仅凭逻辑运算即可完成转换。

### [06:10] 使用 AND 运算将字符转为大写

以字符 `'B'` 与 `'b'` 为例：
* 小写 `'b'` 的 ASCII 码为 $62\text{H}$（`0110 0010B`）；
* 大写 `'B'` 的 ASCII 码为 $42\text{H}$（`0100 0010B`）。

两者的差异仅在于第 6 位（bit 5）：小写的第 6 位是 `1`，大写的第 6 位是 `0`。

若要将小写字母统一转换为大写字母，本质上就是要把第 6 位（bit 5）强制置为 `0`，且保持其他所有二进制位完全不变。

为此，可以使用 **`AND`（按位与）** 运算：
* 任何二进制位与 `1` 进行与运算，结果均保持原值不变（$0 \text{ AND } 1 = 0$，$1 \text{ AND } 1 = 1$）；
* 任何二进制位与 `0` 进行与运算，结果必然强置为 `0`（$0 \text{ AND } 0 = 0$，$1 \text{ AND } 0 = 0$）。

构造掩码：`11011111B`（十六进制为 $0\text{DFH}$）。
运算过程如下：

$$
\begin{array}{r@{\quad}l}
  & \text{xxxx xxxxB} \\
\text{AND} & 1101\ 1111\text{B} \\
\hline
  & \text{xx0x xxxxB}
\end{array}
$$

* 若原来是小写字母（第 6 位为 `1`），与 `0` 进行 `AND` 操作后变为 `0`，成功转换为大写；
* 若原来原本就是大写字母（第 6 位为 `0`），与 `0` 进行 `AND` 操作后依旧为 `0`，保持大写不变。

`AND` 指令格式：
```assembly
and 目的操作数, 源操作数
```
功能为将目的操作数与源操作数按位进行逻辑与运算，结果保存回目的操作数中。

### [08:30] 使用 OR 运算将字符转为小写

同理，若要将大写字母转换为小写字母，需要将第 6 位（bit 5）强制置为 `1`，而保持其他各位不变。

此时使用 **`OR`（按位或）** 运算：
* 任何二进制位与 `0` 进行或运算，结果保持原值不变（$0 \text{ OR } 0 = 0$，$1 \text{ OR } 0 = 1$）；
* 任何二进制位与 `1` 进行或运算，结果必然强置为 `1`（$0 \text{ OR } 1 = 1$，$1 \text{ OR } 1 = 1$）。

构造掩码：`00100000B`（十六进制为 $20\text{H}$）。
运算过程如下：

$$
\begin{array}{r@{\quad}l}
  & \text{xxxx xxxxB} \\
\text{OR} & 0010\ 0000\text{B} \\
\hline
  & \text{xx1x xxxxB}
\end{array}
$$

* 若原来是大写字母（第 6 位为 `0`），与 `1` 进行 `OR` 操作后变为 `1`，成功转换为小写；
* 若原来就是小写字母（第 6 位为 `1`），与 `1` 进行 `OR` 操作后仍然为 `1`，保持小写不变。

`OR` 指令的语法与 `AND` 指令格式完全相同。

### [09:26] 完整程序构造与代码逐行解析

利用上述位运算逻辑，构造完整的汇编源程序：

```assembly
assume cs:codesg, ds:datasg

datasg segment
    db 'BaSic'
    db 'iNfOrMaTiOn'
datasg ends

codesg segment
start:
    ; 设置数据段段寄存器 DS
    mov ax, datasg
    mov ds, ax
    
    ; 1. 将第一个字符串 'BaSic' 转为纯大写
    mov bx, 0           ; 偏移地址起始为 0
    mov cx, 5           ; 字符串长度为 5，设置循环计数器为 5
s:
    mov al, [bx]        ; 取出 DS:[bx] 处的单字节字符
    and al, 11011111b   ; 第 6 位强置 0，转为大写
    mov [bx], al        ; 写回原内存单元
    inc bx              ; 偏移地址自增 1，指向下一个字符
    loop s              ; 循环 5 次
    
    ; 2. 将第二个字符串 'iNfOrMaTiOn' 转为纯小写
    mov bx, 5           ; 第二个字符串起始偏移地址为 5
    mov cx, 11          ; 字符串长度为 11，设置循环计数器为 11
s0:
    mov al, [bx]        ; 取出 DS:[bx] 处的单字节字符
    or al, 00100000b    ; 第 6 位强置 1，转为小写
    mov [bx], al        ; 写回原内存单元
    inc bx              ; 偏移地址自增 1
    loop s0             ; 循环 11 次

    ; 程序退出返回 DOS
    mov ax, 4c00h
    int 21h
codesg ends
end start
```

#### 逻辑分步说明：
1. **段基址设置**：将 `datasg` 的段地址传入 `AX`，再赋给 `DS`，确保后续通过偏移地址可以正确访问数据。
2. **第一段转换（转大写）**：
   * `'BaSic'` 长度为 5 个字节，起始偏移地址为 `0`；
   * 通过 `mov cx, 5` 设置循环次数；
   * 循环体内每次从 `[bx]` 读入一个字节到 `AL`，执行 `and al, 11011111b`，写回原内存位置；
   * `inc bx` 后通过 `loop` 指令自减 `CX` 并判断跳转，循环 5 次后完成全部转换。
3. **第二段转换（转小写）**：
   * `'iNfOrMaTiOn'` 紧接在第一个字符串后，其起始偏移地址为 `5`，字符串长度为 11 个字节；
   * 设置 `bx = 5`，`cx = 11`；
   * 循环体内部执行 `or al, 00100000b` 将字符强制转换为小写，写回内存；
   * `inc bx` 后由 `loop s0` 驱动循环 11 次。

### [13:07] 本节内容总结

对本节内容做核心要点梳理：
1. **字符在汇编中的定义与存储**：通过单引号 `'...'` 给出字符，编译器在编译时会自动将其转换为对应的 ASCII 码值存放在可执行文件中；
2. **数组/字符串遍历模式**：在内存中处理一连串字符时，通过寄存器 `BX` 存放首地址/偏移地址、寄存器 `CX` 存放循环计数值，配合 `INC BX` 与 `LOOP` 指令，可实现对连续字符数据的逐个遍历处理；
3. **位运算技巧**：合理利用 `AND` 与 `OR` 针对特定比特位（bit 5）进行屏蔽或置位，能够避免繁琐的分支跳转逻辑，高效实现大小写转换。
