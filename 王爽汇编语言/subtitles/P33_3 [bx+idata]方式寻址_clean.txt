# [bx+idata] 寻址方式及其在数组处理中的应用

### [00:00] [bx+idata] 寻址方式与内存单元表示

在这一节，我们介绍一种寻址方式，是由 $\text{BX}$ 再加上一个特殊的数去组成的方式来进行寻址。

这种形式的含义是什么呢？我们首先可以看到，它表示的是一个内存单元。对这种内存单元来讲，它的偏移地址是 $\text{BX}$ 的内容再加上一个给出的数，我们把它叫做 $\text{idata}$（即一个立即数）。

### [00:24] 指令示例与地址计算

对于这样一种形式，给出一个例子：

```assembly
mov ax, [bx+200]
```

可以看到，在这儿 $\text{idata}$ 就取 $200$ 了；或者我们也可以写成：

```assembly
mov ax, [200+bx]
```

它的含义是什么呢？我们逐层剖析一下：
首先，对于这个指令来讲，它要把一个内存单元的值送入 $\text{AX}$，$\text{AX}$ 是一个寄存器。
另外，我们要去取到的内存单元，偏移地址与 $\text{DS}$ 相关，内存单元的段地址是在 $\text{DS}$ 里面。这个内存单元的长度是两个字节，因为要存放到 $\text{AX}$ 里面，所以它是一个字（Word）。

内存单元的段地址在 $\text{DS}$ 里面，偏移地址是多少呢？从指令中可以看到，它是 $200$ 加上 $\text{BX}$ 寄存器的数值。
因此，它所对应的地址在图上可以看到：这是加 $200$ 的地址，我们现在还需要再加上一个 $\text{BX}$。所以在加上 $\text{BX}$ 以后，它的内存地址就应该是在这一块。
我们把该单元的值送入 $\text{AX}$：首先能够找到 $200$ 这个单元，再加上 $\text{BX}$ 的值所包含的偏移量，于是定位到这里。
该单元的值我们表示为 `[200+bx]`；而直接加 $200$ 的单元表示为 `[200]`，这是以前曾经用过的。

### [02:00] 数学描述与等价写法

把它转换成数学描述，首先用段地址乘以 16，再加上 $200$，再加上 $\text{BX}$：

$$\text{物理地址} = \text{SA} \times 16 + 200 + \text{BX}$$

对于这样一条指令，我们还可以用其他的一些方式写出，这些写法在汇编语言中是等价的：

- `[200+bx]`
- `200[bx]`（把 200 放在前面，BX 加方括号放在后面）
- `[bx].200`

这些写法与我们给出的 `[bx+200]` 方式是完全一样的，以后看程序的时候要能看明白。

### [02:37] 汇编寻址与 C 语言数组的对应关系

说到这里，我们可以感觉到这有点 C 语言里面数组的味道了。
对于一个数组来讲有一个起始地址。现在的起始地址可以理解成就是加 $200$ 的这个位置。段地址可以作为最基础的段基址，在这一段程序里面我们还可以安排其他数据，我们把加 $200$ 的位置看成是数组的起始地址。
而 $\text{BX}$ 作为一个寄存器，它的值是可以发生变化的。随着 $\text{BX}$ 的值发生变化，我们在基地址上加 $\text{BX}$ 的过程，就可以访问到某一段存储空间里面的任意一个单元。这与 C 语言里面相同类型的一段数据的“数组”概念是非常类似的。
实际上，用这种方法的确可以去模拟高级语言里面的数组结构，它反映的就是高级语言底层的数据访问机制。

### [03:36] 双循环实现字符串大小写转换

我们用这种结构来处理一个问题。给出的问题是前面曾经接触过的一个老问题：
把 `datasg` 段里面的两个字符串做转换：
- 第一个字符串转换为大写（小写转大写）；
- 第二个字符串转换为小写。

处理这个任务时，之前编写的程序可以设置两个循环：

```assembly
; 第一个循环：转大写
mov cx, 5
mov bx, 0
s:
    mov al, [bx]
    and al, 11011111b
    mov [bx], al
    inc bx
    loop s

; 第二个循环：转小写
mov cx, 5
mov bx, 5
s0:
    mov al, [bx]
    or al, 00100000b
    mov [bx], al
    inc bx
    loop s0
```

第一个循环执行 5 次，$\text{BX}$ 从 0 开始作为偏移地址，访问第一个字符串的字符，通过 `and` 操作将其转换为大写。
下面第二个循环同样循环 5 次，处理第二个字符串。$\text{BX}$ 的初值是 5，因为在数据段中第一个字符串占用偏移 0~4，第二个字符串从偏移 5 开始。这里通过 `or` 操作将所有字符转为小写。

### [05:14] 算法优化：单循环同步处理两个字符串

对于这个例子，我们会发现第一个字符串和第二个字符串的长度是相等的。这也就意味着在这两个循环里面只有两个地方不一样：
1. $\text{BX}$ 的初值不一样（第一个是 0，第二个是 5）；
2. 对字符的处理方式不一样（一个是转大写，一个是转小写）。

除了这两个地方不同以外，循环次数和步进逻辑是完全一样的。
我们能不能把这两个字符串同步进行操作？
基本思路是：先处理第一个字符串的第 1 个字符，紧接着处理第二个字符串的第 1 个字符；然后再处理第一个字符串的第 2 个字符、第二个字符串的第 2 个字符……一次循环把两个字符串对应位置上的字符全部处理完毕。

### [06:07] 使用 [bx+idata] 优化后的汇编实现

采用这种思路，程序可以写成如下形式：

```assembly
mov bx, 0
mov cx, 5

s:
    mov al, [bx]
    and al, 11011111b
    mov [bx], al

    mov al, [5+bx]
    or al, 00100000b
    mov [5+bx], al

    inc bx
    loop s
```

在这个程序中：
$\text{BX}$ 的初值是 0，$\text{CX}$ 决定循环次数（5次）。
首先执行的操作是：把 $\text{BX}$ 所指示位置的值取出来送到 $\text{AL}$。当 $\text{BX}=0$ 时，取出的是第一个字符串（如 `'basic'`）的第 1 个字符 `'b'`，做 `and` 运算转换成大写后送回 `[bx]`。
关键步骤在接下来：$\text{BX}$ 当前是 0，加上 5 以后自然就是第二个字符串（如 `'minix'`）对应位置的字符 `'m'`。通过 `or` 运算把它转成小写，再送回 `[5+bx]` 对应的单元。
然后执行 `inc bx`，通过 `loop` 循环回去。
此时 $\text{BX}$ 加 1，$\text{CX}$ 减 1。新一轮循环中：
- `[bx]` 访问的是第一个字符串的第 2 个字符（如 `'a'`）；
- `[5+bx]` 访问的则是第二个字符串对应的第 2 个字符（如 `'i'`）。

这就实现了对两个等长字符串的同步处理。在这个程序里，我们使用的就是 `[5+bx]` 这种在常量基址基础上加变量寄存器的寻址方式。

### [07:49] Debug 跟踪与运行验证

有了这个方法，程序的执行过程便很清晰了。
在 Debug 中加载程序后，代码段位于 `075A`，数据段位于 `076A`。通过 `d` 命令查看可以看到初始保存的大小写混合数据。
使用 `g` 命令执行完毕后，再次查看该段数据，可以看到内存中的字符确确实实按照意图完成了转换。
这种地址表示方式就是本节课最核心的内容。

### [08:26] C 语言数组对比与总结

完成这个任务，如果用 C 语言来编写，对应结构大致如下：

```c
char a[5] = "basic";
char b[5] = "minix";
int i;

for (i = 0; i < 5; i++) {
    a[i] = a[i] & 0xDF;
    b[i] = b[i] | 0x20;
}
```

在 C 语言程序中，我们使用的是数组，带有下标 `i`（从 0 到 4 进行循环）。这个循环逻辑与汇编语言中使用 $\text{BX}$ 递增配合 `[bx+idata]` 的过程具有异曲同工之妙。

`[bx+idata]` 这种寻址方式为高级语言实现数组提供了底层的支撑机制。在编程解决相关问题时，借助这种基址加偏移的方式模拟数组进行处理，是非常有效的方法。
