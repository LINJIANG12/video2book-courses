# 汇编程序的运行与跟踪过程

## 汇编程序生成流程回顾与问题引出

[00:00]  
在这一节，我们介绍程序的运行和跟踪过程。首先把前面的内容回顾一下：

我们用汇编语言编写好一个程序后，首先需要使用 MASM 这样的工具对它进行编译；经过编译后，由 `.asm` 的源文件生成 `.obj` 的目标文件；然后再通过 `link` 命令把目标文件转换成 `.exe` 可执行文件。生成可执行文件后，我们就可以通过直接输入该可执行文件的文件名来运行程序。

[00:31]  
此时计算机已经开始运行程序了，但我们还想知道这个可执行文件到底是如何运行的。因为学习汇编语言我们关注底层，需要在机器指令级别把握程序的运行过程。并且对于这些简单程序，我们也希望验证其是否真正完成了预定功能。

因此，我们要深入探究其中的细节与门道。为了观察这个过程，我们采取的方法是使用 Debug 工具装载程序来进行跟踪分析。

---

## 使用 Debug 载入程序与观察寄存器

[01:05]  
使用 Debug 装载程序非常简单：输入 `debug` 命令，后面跟上已经编译好的可执行文件名 `p4-1.exe`，敲回车载入程序：

```text
debug p4-1.exe
```

进入 Debug 以后，我们先通过 `r` 命令查看寄存器的值：

```text
-r
```

此时屏幕上所显示的寄存器数值，就已经足够让我们展开观察了。接下来，我们就依据这些观察到的寄存器值来看看其中的门道。

刚才提到，我们直接通过 Debug 将可执行文件装载进来。装载进来之后，我们需要从寄存器的取值来分析程序到底被装在了内存的什么位置。此时首先观察到：
* $\text{DS} = 075\text{AH}$
* $\text{CS} = 076\text{AH}$

---

## 内存地址分布与程序段前缀（PSP）

[02:06]  
程序究竟被装到了内存的什么地方？根据给出的段地址，我们可以画出两段内存空间：
* 对应第一段空间，段地址为 `075A`，偏移地址从 `0000` 开始，即由 $\text{DS}$ 所指向的这一段空间；
* 代码段 $\text{CS}$ 则是从 `076A` 开始，偏移地址从 `0000` 开始。

这反映了可执行文件从磁盘装入内存后所占用的物理空间。段地址与偏移地址对应的物理地址均可由公式推导计算得出。

[02:59]  
$\text{CS}$ 代表程序要执行的指令（即代码）所在的段地址，CPU 执行的第一条指令就在这里。而整个程序被装入内存时的起始地址是在 $\text{DS}$ 处。

因此，$\text{DS}$ 到 $\text{CS}$ 之间的这块空间一共有 256 个字节。对应十六进制即为 $100\text{H}$ 字节：
* 其段地址为 `075A`；
* 偏移地址范围从 `0000H` 到 `00FFH`，共计 $100\text{H}$（256）个字节。

这段空间被称为**程序段前缀（PSP，Program Segment Prefix）**，DOS 系统将其作为数据区使用，用来与程序进行通信。PSP 属于操作系统的实现细节，在此不作展开，我们重点关注汇编指令与代码段。

---

## 查看代码段的反汇编与机器码

[04:01]  
如何查看代码段中的指令？我们使用 Debug 的反汇编命令 `u`：

```text
-u
```

执行 `u` 命令后，屏幕列出的起始地址为 `076A:0000`。为什么未指定地址时默认显示 `076A`？因为此时寄存器 $\text{CS}$ 已经指向了代码段起始地址，因此默认从此处开始反汇编列出指令。

列出的指令序列如下：

```assembly
MOV AX, 0123
MOV BX, 0456
...
INT 21
```

这证明内存该位置保存的代码正是源程序中的指令，最后以 `INT 21` 结束。屏幕左侧显示的是汇编指令，中间对应的是机器码。

例如，从代码起始地址开始存放的机器指令字节序列：
`B8 23 01 BB 56 04`
分别对应汇编指令：
* `MOV AX, 0123H` $\rightarrow$ `B8 23 01`
* `MOV BX, 0456H` $\rightarrow$ `BB 56 04`

Debug 将程序装载后，在内存中的实际存储状态与理论模型完全一致。在学习过程中，要透过这些现象看清底层的本质。

---

## 内存装载结构小结

[05:22]  
对程序装载后的内存结构作一小结：

1. 程序加载后，$\text{DS}$ 中存放着程序所在内存区的段地址，该内存区的偏移地址为 $0$，即程序所在内存区的起始地址为 $\text{DS}:0$。
2. 该内存区的前 256 个字节（即 $100\text{H}$ 个字节）存放的是 PSP，供 DOS 与程序通信使用。
3. 从第 256 个字节向后的空间存放实际的程序代码，由 $\text{CS}$ 指向代码的起始段地址。
4. $\text{CS}$ 与 $\text{DS}$ 的数值关系为：
   $$\text{CS} = \text{DS} + 10\text{H}$$
   $$076\text{AH} = 075\text{AH} + 10\text{H}$$
   因为段地址在计算物理地址时需要左移 4 位（乘以十六进制的 $10\text{H}$），所以在物理地址上相差：
   $$10\text{H} \times 10\text{H} = 100\text{H} \text{ 字节（256 字节）}$$
   这与 PSP 占用的空间大小完全一致。

---

## 代码长度与 CX 寄存器

[06:30]  
程序加载后，$\text{CX}$ 寄存器中保存的是代码的长度。

观察代码的偏移地址范围，从 `0` 到 `F` 为代码区域，总长度为 15 个字节。此时查看寄存器，$\text{CX}$ 的取值恰好是 `000FH`（即 15）。这些信息在后续的程序运行与编程实践中都会被用到。

---

## 单步跟踪与执行控制

### 1. 使用 T 命令单步执行

[07:05]  
接下来通过 Debug 进行单步执行与跟踪。装载程序后，查看当前寄存器状态：$\text{CS} = 076\text{A}$，$\text{IP} = 0000$。CPU 即将执行的第一条指令即为 `MOV AX, 0123`。

* 输入 `t` 执行第一步：
  ```text
  -t
  ```
  执行后观察到寄存器 $\text{AX} = 0123\text{H}$。
* 紧接着执行下一条指令 `MOV BX, 0456`，执行完毕后 $\text{BX} = 0456\text{H}$。
* 执行 `ADD AX, BX`，两数相加得到 $\text{AX} = 0579\text{H}$。
* 执行 `ADD AX, AX`，得到 $\text{AX} = 0\text{AF}2\text{H}$。
* 接下来执行 `MOV AX, 4C00` 以及 `INT 21`，程序宣告结束。此时 $\text{IP}$ 的指向发生改变，表明当前程序已执行完毕。

---

### 2. 使用 P 命令执行

[08:22]  
除了 `t` 命令外，还可以使用 `p` 命令进行跟踪执行。

`p` 命令与 `t` 命令的执行过程类似，其不同之处在于：遇到**子程序调用**或**中断指令**时，`p` 命令会直接将子程序或中断执行完毕并返回结果，而不是单步跟入内部执行。

当使用 `p` 命令执行到 `INT 21` 时，屏幕提示：
```text
Program terminated normally
```
表示遇到中断退出指令后，程序正常结束返回。

---

### 3. 使用 G 命令快速运行与断点设置

[09:11]  
如果每一步都使用 `t` 或 `p` 命令单步跟踪，调试长程序会非常繁琐。若想让程序直接运行，可以使用 `g` 命令：

* **直接运行到结束**：程序装载完成后，直接输入 `g`，程序将从当前地址连续执行，直到遇到断点或正常退出：
  ```text
  -g
  ```
* **运行至指定断点**：`g` 命令后可跟具体的地址。例如想要直接执行到 `ADD AX, AX` 处（偏移地址为 `0008`），可以指定断点：
  ```text
  -g=0008
  ```
  或者：
  ```text
  -g 076A:0008
  ```
  程序将直接连续运行至该地址暂停，或者在遇到程序结束时停止。

---

## DOS 环境与 Debug 环境下的加载执行机制对比

[10:10]  
在 DOS 环境中直接运行程序是可执行文件的常态运行方式，未来编写实用程序时，主要也是在操作系统环境下直接运行。

### DOS 环境下的程序运行机制

[10:39]  
DOS 系统启动后，由命令解释器 `command.com` 负责对整机进行控制和交互。
1. 当用户输入程序名执行命令时，该命令的解析执行也是在 `command.com` 的控制下完成的；
2. `command.com` 将可执行程序从外存加载至内存；
3. 设置 CPU 的寄存器 $\text{CS}:\text{IP}$ 指向程序的第一条指令，将 CPU 控制权交给程序；
4. 程序运行结束（执行 `INT 21H` 的 `4CH` 号功能）后，CPU 控制权返回给命令解释器 `command.com`，屏幕重新显示 DOS 命令提示符。

### Debug 环境下的程序运行机制

[11:25]  
在 Debug 中执行程序，原理与 DOS 直接执行完全一致，区别在于其处于开发与调试阶段：
1. 用户在 DOS 提示符下键入 `debug`，由 `command.com` 加载运行 `debug.exe`；
2. 由 Debug 程序将目标可执行程序装入内存，并控制程序的单步或连续执行；
3. 程序运行过程受 Debug 全程监控；
4. 当在 Debug 中输入 `q` 命令退出时，控制权交还给外层的 `command.com`。

这就是操作系统处理程序加载、运行与跟踪的底层运行机制。本节内容就介绍到这里。
