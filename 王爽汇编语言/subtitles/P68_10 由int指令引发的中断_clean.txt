# 由 `int` 指令引发的中断与中断例程编写

### [00:00] `int` 指令与内部中断机制

在这一节，我们介绍由 `int` 指令引发的中断。

我们知道 CPU 内部产生的中断包括：除法错误、单步执行、溢出，以及由 `int` 指令引发的中断。我们现在介绍的就是这样一个中断。

对于由 `int` 指令引发的中断，它要用到的是 `int` 指令。`int` 后面加上一个 $n$：

```assembly
int n
```

$n$ 是一个立即数，这个 $n$ 我们把它叫做**中断类型码**。它的功能就是引发一个中断过程。

其实我们可以看到，在以前编写程序的时候，经常要用到 `21h` 这样一个中断，即 `int 21h`。

在指令里面甚至可以写：

```assembly
int 0
```

而 `int 0` 我们知道是一个除法错误。一般 `int 0` 是当遇到除数为 0 的时候自动触发的，但是我们可以有意地这样去调用它。在这个时候我们会知道，不做除法也能够产生除法错误。但是这个除法错误仅仅是在语法上面能够执行，在实际应用中不见得是这么用的。

---

### [01:05] `int` 指令的中断执行过程

我们既然有这样一种形式的中断，对 $n$ 号中断来讲，它的执行过程其实跟以前看过的除法错误等是类似的：

1. 首先取到中断类型码 $n$；
2. 标志寄存器入栈后，将两个标志位（IF 和 TF）置为 0；
3. 将当前正在执行程序的 $\text{CS}$ 和 $\text{IP}$ 入栈；
4. 根据中断类型码求出它在中断向量表当中的内存地址；
5. 在该内存单元中，分别取出执行中断处理程序所需的 $\text{IP}$ 以及 $\text{CS}$；
6. 得到 $\text{CS}$ 和 $\text{IP}$ 后，转到对应的中断处理程序去完成特定的功能。

这就是整个中断执行的过程。

---

### [01:58] `int` 指令与子程序调用

从这样一个过程里面可以看到，在执行 `int` 指令的时候，它涉及到程序执行流程的一个转换。因此，它和 `call` 指令是相似的，都能够转移到另外一个地方去执行另外一段程序。

在一般情况下，系统将一些具有一定功能的子程序以中断处理的方式提供给应用程序调用，这也是在汇编语言程序设计里面我们经常采用的一种手段。

---

### [02:30] 中断例程的概念

于是我们需要有这样一个机制：能够编写供应用程序调用的中断例程，而这个中断例程往往就是用 `int n` 去调用的。

它的技术手段可以归结为：在编程的时候用 `int` 指令去调用子程序。这个子程序我们把它叫做**中断处理程序**，简称为**中断例程**。

这样的话，我们的中断例程是可以根据要实现的任务去自定义的。通过自定义的中断例程，我们可以实现一些特定的功能。

---

### [03:05] 自定义中断例程的设计与安装机理

现在我们看一个示例：中断 `7ch`。注意到这是我们要自定义的一个中断。我们来看中断 `7ch` 的中断例程编写和安装过程。

中断例程的编写和安装需要遵循中断运行机制，在掌握这种机制的基础上编写即可。可以参考此前中断 0 的中断例程实现方式去做。

结合中断向量表，完成一个中断例程主要包含以下步骤：
1. **编写中断例程的具体逻辑**：明确中断例程完成什么工作，将其具体逻辑与指令编写出来；
2. **编写安装中断例程的程序**：将编写好的中断例程代码复制（安装）到内存中的某一段具体空间。此前我们曾将其安装到 `0:0200H` 处，实际并不限于此，也可以指定其他空闲内存区域；
3. **设置中断向量表**：将该中断例程所在内存的段地址与偏移地址设置到中断向量表中。

对于中断号为 `7ch` 的中断例程：
- 它的中断向量存放在段地址为 $0$ 的中断向量表中；
- 偏移地址 $7\text{ch} \times 4$ 处存放中断例程的 $\text{IP}$；
- 偏移地址 $7\text{ch} \times 4 + 2$ 处存放中断例程的 $\text{CS}$。

设置完成后，一旦将来在程序中触发 `int 7ch`，CPU 就可以根据中断号从中断向量表中取出 $\text{IP}$ 和 $\text{CS}$，转去执行安装在内存中的中断例程。这就是其整体运行机理。

### [05:36] 示例一：实现求 word 型数据平方的中断例程

为了理解这个机理，我们来看第一个例子：编写 `7ch` 中断例程，完成求一个 word 型数据的平方。

例如：计算 $3456$ 的平方（$3456$ 用 word 类型表示）。

中断例程本质上是一个子程序：
- **入口参数**：放在 `ax` 中，即要计算的数据；
- **返回值**：由于一个 word 型数据的平方结果可能达到 32 位（双字 dword），按照乘法指令的规则，高 16 位存放在 `dx` 中，低 16 位存放在 `ax` 中。

---

### [06:37] 示例一代码实现

编写此程序共需完成三项工作：

#### 1. 编写求平方的中断例程逻辑
已知入口参数在 `ax` 中，将其与自身相乘，结果自然存放在 `dx` 和 `ax` 中：

```assembly
sqr:
    mul ax
    iret
sqrend:
    nop
```

#### [07:23] 2. 编写安装程序
将这段机器码复制到内存 `0:0200H` 处（找一块空闲空间）：
- 源地址：`cs:sqr`
- 目的地址：`0:0200H`
- 传输长度：`offset sqrend - offset sqr`，即例程所占字节数
- 利用串传送指令完成拷贝。

```assembly
    mov ax, cs
    mov ds, ax
    mov si, offset sqr          ; 源地址 ds:si
    mov ax, 0
    mov es, ax
    mov di, 200h                ; 目标地址 es:di
    mov cx, offset sqrend - offset sqr
    cld                         ; 设置正向传输
    rep movsb
```

#### [08:30] 3. 设置中断向量表
将 `7ch` 中断向量登记到中断向量表中：
- 段地址为 `0`
- 偏移地址 $7\text{ch} \times 4$ 写入 `200h`（$\text{IP}$）
- 偏移地址 $7\text{ch} \times 4 + 2$ 写入 `0`（$\text{CS}$）

```assembly
    mov ax, 0
    mov ds, ax
    mov word ptr ds:[7ch * 4], 200h
    mov word ptr ds:[7ch * 4 + 2], 0
```

程序运行后，该中断例程便常驻在内存中。

#### [09:16] 4. 测试调用中断例程
编写测试程序调用 `int 7ch`，并进一步完成求 $3456$ 平方的 2 倍：

```assembly
    mov ax, 3456
    int 7ch                     ; 调用 7ch 中断，计算 3456 的平方，结果在 dx:ax
    add ax, ax                  ; 低 16 位乘以 2（相加）
    adc dx, dx                  ; 高 16 位相加并加上低 16 位产生的进位
```

通过 `add ax, ax` 与 `adc dx, dx`，将低 16 位相加产生的进位加到高 16 位中，最终求得 2 倍平方值。

### [10:18] 中断过程入栈与 `iret` 指令的对应关系

在调用中断例程时，CPU 会自动完成以下操作：
1. 标志寄存器入栈；
2. $\text{CS}$ 与 $\text{IP}$ 入栈。

与此相配合，中断例程在返回时**不能使用 `ret`，而必须使用 `iret` 指令**。

执行 `iret` 指令时，CPU 自动完成：
- `pop IP`
- `pop CS`
- `popf`

出栈操作与引发中断时的入栈操作严格一一对应。这是中断例程与普通子程序之间唯一的本质区别。

### [11:20] 示例二：将以 0 结尾的字符串转换为大写

我们看第二个例子：编写 `7ch` 中断例程，将以 0 结尾的字符串转换为大写。

调用场景约定：
- 数据段地址由 `ds` 给出；
- 字符串首地址由变址寄存器 `si` 给出，即字符串起始地址为 `ds:si`；
- 字符串以字节 `0` 结尾。

---

### [12:24] 示例二代码实现

安装程序和设置中断向量表的部分与前一个示例完全相同，区别仅在于中断例程的处理逻辑。

#### [12:53] 中断例程逻辑编写与寄存器保护
例程中需要使用 `cx` 和 `si`，因此进入时需保护现场（入栈），返回前恢复现场（出栈）：

```assembly
capital:
    push cx
    push si

change:
    mov cl, [si]
    mov ch, 0
    jcxz ok                     ; 如果读到结尾字符 0，则 cx=0，跳转到 ok 结束
    and byte ptr [si], 11011111b ; 将 bit 5 置 0，转为大写字母
    inc si                      ; 指向下一个字符
    jmp short change            ; 循环处理

ok:
    pop si
    pop cx
    iret
capitalend:
    nop
```

#### [13:08] 逻辑分析：
1. `mov cl, [si]` 与 `mov ch, 0`：将当前字符放入 `cl`，并将 `ch` 置 0，使得寄存器 `cx` 的值完全等于字符的 ASCII 码；
2. `jcxz ok`：判断 `cx` 是否为 0。若读到字符串末尾的 0，则条件成立，跳转到 `ok` 退出；若不为 0，则继续向下执行；
3. `and byte ptr [si], 11011111b`：通过逻辑与操作将第 6 位（bit 5）置 0，将小写字母转换为大写字母；
4. `inc si` 后通过 `jmp short change` 跳回，继续处理下一个字符。

### [15:09] 编写中断处理程序的常规步骤总结

无论中断例程完成什么具体任务，其常规编写步骤均遵循以下结构：

1. **保存用到的寄存器**（`push` 保护现场）；
2. **处理中断**（编写中断例程的具体功能逻辑）；
3. **恢复用到的寄存器**（`pop` 恢复现场）；
4. **使用 `iret` 指令返回**。
