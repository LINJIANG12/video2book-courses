# 中断响应外设与键盘操作机制

[00:00]
在本节课程中，我们将介绍通过中断响应外设的方法。核心要解决的问题是：在汇编语言中如何对外部设备进行操作。

在操作外部设备时，我们依然以键盘操作为例展开介绍。操作键盘以及其他外设通常有以下几种途径：
1. 直接通过 I/O 端口访问外设；
2. 调用 BIOS 中断；
3. 调用 DOS 中断。

这几种方式之间存在明显的层次关系：
* **BIOS 中断**：是系统内部预先提供的一组底层硬件访问例程，它直接通过端口与外设硬件进行数据交互。
* **DOS 中断**：建立在 BIOS 中断之上，属于更高层级的接口。在 DOS 中断的实现过程中，通常会向下调用 BIOS 中断。
* **对于应用程序开发者**：调用 DOS 中断更加便捷且更面向用户；而越向底层，控制粒度越细。

---

[00:58]
### 键盘相关的三层中断体系

在整个 PC 体系结构中，系统提供了不同层次的中断来处理键盘操作：
* **INT 9h 中断**：键盘硬件中断。当键盘被按下或松开时由硬件触发。
* **BIOS INT 16h 中断**：用于从系统键盘缓冲区中读取按键、查询键盘状态等。
* **DOS INT 21h 中断**：其内部的部分子功能调用（如 `01h`、`06h`、`07h`、`08h`、`0Ah`、`0Bh`、`0Ch` 等）同样用于实现键盘字符的读取与处理。

---

[01:26]
### INT 9h 硬件中断与键盘底层处理

`INT 9h` 是一个硬件中断。当用户在键盘上按下或松开一个按键时，键盘控制器就会向 CPU 发出中断请求。在 CPU 允许中断（IF=1）的情况下，便会触发 `INT 9h` 中断，转去执行 BIOS 提供的键盘中断处理程序。

`INT 9h` 的核心工作包括：
1. 从 60h 端口读取按键产生的**扫描码**（Scan Code）；
2. 检查按键是否为控制键或换挡键（如 Shift、Ctrl、Alt、CapsLock 等），若是，则更新内存中的**键盘状态字节**；
3. 若是普通字符键，则将其扫描码转换为对应的 **ASCII 码**；
4. 将按键的扫描码和 ASCII 码写入内存中指定的**键盘缓冲区**，等待后续程序读取。

---

[02:00]
### BIOS 键盘服务中断 INT 16h

`INT 16h` 是 BIOS 提供的键盘服务软中断，为程序员提供了基本的键盘操作接口。具体调用哪个功能由寄存器 `AH` 中的功能号决定：
* **AH = 00h / 10h**：从键盘缓冲区中读取一个按键字符。
* **AH = 01h / 11h**：检查键盘缓冲区状态（是否有按键就绪）。
* **AH = 02h / 12h**：读取键盘状态字节（获取 Shift、Ctrl、Alt 等按键的实时状态）。

对于标准键盘与增强型键盘，上述功能号略有差异，具体细节可查阅相关开发手册。

---

[03:50]
### 中断层级的选择权衡

当我们在编写应用程序需要处理键盘输入时，应该在硬件中断、BIOS 中断和 DOS 中断之间如何选择？
* **编写高级应用**：如果条件允许，优先使用更高层次的方法（如 DOS 中断或 BIOS 中断），开发效率更高且兼容性好。
* **底层系统开发**：若需要实现特殊的输入控制（如游戏热键监听、特定外设驱动），直接读取端口或重写 `INT 9h` 硬件中断处理程序，往往能完成高层接口无法实现的特殊控制任务。

---

[05:20]
### INT 9h 与键盘缓冲区的存储机制

键盘在物理输入动作发生后，`INT 9h` 将从 60h 端口读取按键的扫描码，并解析为扫描码与 ASCII 码的组合（或状态信息），存入内存中指定的**键盘缓冲区**。

* **缓冲区容量**：系统键盘缓冲区共分配了 **16 个字单元**（Word，每个单元占 2 个字节）。
* **存储结构**：每个按键占用 1 个字单元（高字节存放扫描码，低字节存放 ASCII 码）。
* **存储上限**：由于采用环形队列（Circular Buffer）实现，需要保留一个字单元用于区分“队满”和“队空”，因此该缓冲区最多可容纳 **15 个按键**的信息。

---

[06:30]
### INT 16h 0号功能读取机制

应用程序通过调用 `INT 16h` 的 `00h` 号功能来读取按键：
```assembly
mov ah, 0
int 16h
```
其工作过程如下：
1. 检查键盘缓冲区，若为空则循环等待；
2. 一旦检测到缓冲区中有按键数据，读取队首的字单元；
3. 将该按键从键盘缓冲区中**删除**（移动队头指针），从而为后续新的按键腾出空间；
4. 将按键的扫描码送入寄存器 `AH`，ASCII 码送入寄存器 `AL`。

[08:15]
### 键盘输入与中断协同流程演示

#### 1. 普通字符输入流程（以依次按下 a、b、c、d、e 为例）
* 按下 `a`：
  * 键盘产生按键扫描码 `1Eh`，送入 60h 端口；
  * 触发 `INT 9h` 硬件中断；
  * `INT 9h` 从 60h 端口读取 `1Eh`，查询键盘状态字确认 Shift 未按下，转换出小写 `a` 的 ASCII 码 `61h`；
  * 将字数据写入键盘缓冲区：高字节为扫描码 `1Eh`，低字节为 ASCII 码 `61h`。
* 按下 `b`：
  * 产生扫描码 `30h`，转出 ASCII 码 `62h`，写入键盘缓冲区的下一个字单元（高字节 `30h`，低字节 `62h`）。
* 按下 `c`、`d`、`e`：
  * 过程相同，依次将 `(2Eh, 63h)`、`(20h, 64h)`、`(12h, 65h)` 写入缓冲区。

---

[10:50]
#### 2. 组合键输入流程（以 Shift + a 为例）
* 按下 `Shift` 键：
  * 产生 Shift 的扫描码 `2Ah`，触发 `INT 9h`；
  * `INT 9h` 检测到 `2Ah` 为换挡键，并不向缓冲区存入字符，而是将内存中键盘状态字节对应的 Shift 标志位置为 `1`；
* 紧接着按下 `a` 键：
  * 产生扫描码 `1Eh`，触发 `INT 9h`；
  * `INT 9h` 检测到键盘状态字节中的 Shift 标志位为 `1`，因此转换出大写字母 `A` 的 ASCII 码 `41h`；
  * 将高字节 `1Eh`（扫描码）、低字节 `41h`（ASCII 码）写入键盘缓冲区；
* 松开 `Shift` 键：
  * 产生释放扫描码（断码），`INT 9h` 将状态字节中的 Shift 标志位重新复位为 `0`。

---

[12:25]
### INT 16h 消耗缓冲数据的过程演示

当键盘缓冲区中已有按键存入后，应用程序执行 `mov ah, 0` 并调用 `int 16h`：
1. CPU 响应中断，从键盘缓冲区队首取出第一个字单元（`1Eh, 61h`）；
2. 扫描码 `1Eh` 送入 `AH`，ASCII 码 `61h` 送入 `AL`；
3. 将队首数据移出缓冲区（更新队头指针）；
4. 再次执行 `mov ah, 0` 和 `int 16h` 时，依次取出下一个按键（如 `30h, 62h`）。

---

[13:45]
### 键盘缓冲区的环形队列模型

键盘缓冲区在数据结构上采用**环形队列**（FIFO）：
* 缓冲区空间有限（16 个字单元），队列首尾相接；
* 队尾指针（写入指针）由 `INT 9h` 控制，每次存入新按键时后移；
* 队头指针（读取指针）由 `INT 16h` 控制，每次读出按键后后移；
* 队头指针等于队尾指针时表示队空；当队尾指针的下一个位置是队头指针时表示队满；
* 这种结构保证了即使按键产生与程序读取的节奏不一致，只要未超过 15 个字的缓冲容量，按键序列就不会丢失。

---

[14:50]
### 生产者-消费者协作模型

`INT 9h` 与 `INT 16h` 构成了典型的生产者-消费者模型：
* **INT 9h（生产者）**：由外设按键动作异步触发的**硬件中断**。只要有键按下，就向键盘缓冲区写入数据，不受应用程序直接控制。
* **INT 16h（消费者）**：由应用程序根据需求同步调用的**软件中断**。程序需要输入时才调用该中断，从键盘缓冲区读取数据并移出。

两者通过内存中的键盘缓冲区与键盘状态字实现解耦与协同工作。

[17:48]
### 综合应用案例：根据键盘输入动态改变屏幕字符颜色

接下来我们运用上述原理实现一个具体需求：
编写一段程序，等待用户从键盘输入字符：
* 若输入 `r`（Red），将全屏幕字符的前景色改为**红色**；
* 若输入 `g`（Green），将全屏幕字符的前景色改为**绿色**；
* 若输入 `b`（Blue），将全屏幕字符的前景色改为**蓝色**；
* 输入其他按键则退出程序。

---

[18:30]
#### 1. 键盘监听与分支判断
程序首先通过 `INT 16h` 的 `00h` 功能等待并获取键盘输入：

```assembly
mov ah, 0
int 16h
```

按键返回后，`AL` 中保存字符的 ASCII 码，扫描码在 `AH` 中（本例无需关心扫描码）。接下来，我们赋予 `AH` 新的用途——用于保存待设置的颜色属性掩码。

我们将 `AH` 的初值设为 `1`（即二进制 `00000001B`），此时最低位对应蓝色：
```assembly
mov ah, 1
cmp al, 'r'
je red
cmp al, 'g'
je green
cmp al, 'b'
je blue
jmp short s_ret
```

---

[20:33]
#### 2. 颜色属性字节的巧妙位移设置

在 CGA/EGA/VGA 文本模式下，每个屏幕字符的属性字节格式如下：
* **D7**：闪烁位 (BL)
* **D6~D4**：背景色 RGB (R, G, B)
* **D3**：高亮位 (I)
* **D2~D0**：前景色 RGB (R, G, B)，其中 D2 为红 (R)，D1 为绿 (G)，D0 为蓝 (B)。

我们可以通过逻辑左移指令 `shl` 极简地生成颜色位：
* **蓝色 (b)**：对应属性位 `00000001B`，无需移位；
* **绿色 (g)**：对应属性位 `00000010B`，只需左移 1 位；
* **红色 (r)**：对应属性位 `00000100B`，只需左移 2 位。

利用代码的顺次执行逻辑，可以精简地写出：
```assembly
red:
    shl ah, 1      ; 若是红色，额外再左移一次（共移2次，变为 00000100B）
green:
    shl ah, 1      ; 若是绿色，左移1次（变为 00000010B）
blue:
    ; 若是蓝色，直接进入，AH 保持初始的 00000001B
```

---

[22:25]
#### 3. 遍历显存更新字符前景色

标准文本模式（80×25）一屏共有 $80 \times 25 = 2000$ 个字符，对应的文本显存段地址为 `0B800H`。每个字符占 2 个字节：偶数地址为字符 ASCII 码，奇数地址为字符属性。

我们要修改全部 2000 个字符的前景色，同时保留原有的背景色和高亮属性：
1. 先将原属性字节的低 3 位（原前景色）清零：与上 `11111000B`（`0F8H`）；
2. 再将新的前景色掩码写入低 3 位：或上 `AH`。

显存更新的核心代码如下：
```assembly
    mov bx, 0B800H
    mov es, bx
    mov bx, 1              ; 指向首个字符属性字节（奇数地址）
    mov cx, 2000           ; 全屏幕共 2000 个字符
s:
    and byte ptr es:[bx], 11111000B   ; 将前景色 3 位清零，保留原背景色及高亮位
    or  byte ptr es:[bx], ah          ; 写入新的前景色
    add bx, 2                         ; 移动到下一个字符的属性字节
    loop s

s_ret:
    mov ax, 4C00H
    int 21H
```

将该程序编译链接生成可执行文件后，在 DOS 环境下运行，按下 `r`、`g`、`b` 即可看到屏幕字符前景色发生瞬时全局切换。
