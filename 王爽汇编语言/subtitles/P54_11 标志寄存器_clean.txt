# 8086 汇编语言：标志寄存器详解

---

### [00:00] 标志寄存器概述与基本概念

在这一讲中，我们介绍标志寄存器。

对 8086 CPU 而言，一共有 14 个寄存器，此前我们已经学习了 13 个，只剩下最后一个——标志寄存器（Flag Register，简称 `FLAGS`）。

标志寄存器也经常被称为**程序状态字**（PSW，Program Status Word），在整个计算机运行体系中起着非常特殊的作用。

标志寄存器是一个 16 位的寄存器，但它是**按位起作用**的。也就是说，其中的每一位都有特定的含义，能够记录特定的信息。

在 8086 CPU 中，标志寄存器虽然是 16 位的，但并没有占用全部 16 个位。其中第 1、3、5 位以及第 12 至 15 位这几个位没有使用，实际使用的是已经被明确定义的标志位。

标志寄存器的主要作用包括：
1. **存储相关指令的执行结果状态**：例如一条指令执行完毕后，是否发生溢出、是否产生进位、结果是否为零等。
2. **为 CPU 执行相关指令提供行为依据**：例如决定串操作指令传送数据时的方向。
3. **控制 CPU 的相关工作方式**。

CPU 在工作时，除了依据当前要执行的指令本身外，很多工作方式与状态都与标志寄存器密切相关。因此，标志寄存器的影响范围非常广泛。

### [01:47] Debug 中查看标志位与直接访问指令

如何查看标志寄存器的值？方法非常简单。在 Debug 中使用 `r` 命令可以列出各个寄存器的值。在输出信息中包含一串符号，这些符号实际上代表的就是标志寄存器中各个标志位当前的状态值：

| 标志位 | 标志名称 | 值为 1 时的符号 | 值为 0 时的符号 |
| :--- | :--- | :--- | :--- |
| **OF** | 溢出标志 (Overflow Flag) | `OV` (Overflow) | `NV` (Not Overflow) |
| **DF** | 方向标志 (Direction Flag) | `DN` (Down) | `UP` (Up) |
| **SF** | 符号标志 (Sign Flag) | `NG` (Negative) | `PL` (Positive/Plus) |
| **ZF** | 零标志 (Zero Flag) | `ZR` (Zero) | `NZ` (Not Zero) |
| **PF** | 奇偶标志 (Parity Flag) | `PE` (Parity Even) | `PO` (Parity Odd) |
| **CF** | 进位标志 (Carry Flag) | `CY` (Carry) | `NC` (No Carry) |

当熟悉之后，能够一眼看出各个标志位的状态；若不够熟练，可以对照表格进行查询。

在 8086 指令集中，直接访问标志寄存器的指令只有两条：
- `PUSHF`：将标志寄存器的内容压入栈中（标志寄存器为 16 位寄存器）。
- `POPF`：将栈顶数据弹出并送入标志寄存器中。

标志寄存器中各标志位的状态变化，主要依据当前执行的指令。指令执行完毕后，相应的标志位可能会随之改变。

### [04:44] ZF（Zero Flag）零标志位

ZF 为零标志位，位于标志寄存器的第 6 位。

ZF 指示相关指令的执行结果是否为 $0$：
- 若指令执行后结果**为 0**，则 $ZF = 1$（Debug 显示为 `ZR`）；
- 若指令执行后结果**不为 0**，则 $ZF = 0$（Debug 显示为 `NZ`）。

#### 示例分析

```assembly
mov ax, 1
and ax, 0
```
在这段代码中，将 `AX` 赋值为 $1$，随后执行 `and ax, 0`。由于与操作的一个操作数为全零，运算后 `AX` 中的结果为 $0$。因此指令执行后：
$$ZF = 1$$
通过检查标志寄存器中的 ZF 位，即可立刻判定运算结果是否为零，而无需再次与 $0$ 做比对。

反之：
```assembly
mov ax, 1
or ax, 0
```
执行或运算后，`AX` 的值依然为 $1$（非零），因此：
$$ZF = 0$$

#### 指令对标志位的影响
在 8086 CPU 指令集中：
- **大部分运算指令**会影响标志寄存器（包括逻辑运算与算术运算指令）：如 `ADD`、`SUB`、`MUL`、`DIV`、`INC`、`OR`、`AND` 等。
- **传送指令**大多对标志寄存器没有影响：如 `MOV`、`PUSH`、`POP` 等。

在学习汇编指令时，必须掌握指令的全部功能——不仅要理解其运算逻辑，还需要明确该指令执行后会对标志寄存器的哪些标志位产生影响。

### [07:32] PF（Parity Flag）奇偶标志位

PF 为奇偶标志位，位于标志寄存器的第 2 位。

PF 记录指令执行后，运算结果的所有二进制位中 **$1$ 的个数的奇偶性**。注意：这里的“奇偶”并非指结果数值本身是奇数还是偶数，而是指**结果二进制形式中 $1$ 的个数**：
- 若 $1$ 的个数为**偶数**，则 $PF = 1$（Debug 显示为 `PE`）；
- 若 $1$ 的个数为**奇数**，则 $PF = 0$（Debug 显示为 `PO`）。

#### 示例 1

```assembly
mov al, 1
add al, 10
```
- `AL` 初始值为 $1$（二进制：`00000001B`）；
- 十进制数 $10$ 的二进制表示为 `00001010B`；
- 两者相加后，结果为 `00001011B`。

在结果 `00001011B` 中，共有 $3$ 个 $1$。由于 $1$ 的个数为奇数，因此：
$$PF = 0$$

#### 示例 2

```assembly
mov al, 1
or al, 2
```
- 二进制数 `00000001B` 与 `00000010B`（数值 $2$）进行按位或运算；
- 结果为 `00000011B`。

在结果中，包含 $2$ 个 $1$（偶数个 $1$），因此：
$$PF = 1$$

### [09:33] SF（Sign Flag）符号标志位

SF 为符号标志位，位于标志寄存器的第 7 位。

SF 记录指令执行后，**将结果视作有符号数时的正负情况**：
- 若结果为**负数**，则 $SF = 1$（Debug 显示为 `NG`）；
- 若结果为**非负数**（正数或 $0$），则 $SF = 0$（Debug 显示为 `PL`）。

#### 补码复习
计算机中的有符号数一律采用**补码**来表示和存储：
- **正整数**：补码与原码相同。最高位为符号位，正数符号位为 $0$。例如 $+9$ 的 8 位补码为 `00001001B`。
- **负整数**：补码为其对应正数绝对值的二进制所有位取反后加 $1$（符号位对应取 $1$）。

例如求 $-5$ 的 8 位补码：
1. $+5$ 的二进制为：`00000101B`
2. 全部按位取反：`11111010B`
3. 末位加 $1$：`11111011B`
因此，$-5$ 的补码为 `11111011B`。

#### 示例分析

```assembly
mov al, 10000001B
add al, 1
```
`AL` 初始值为 `10000001B`。若将其视为有符号数，最高位为 $1$，代表负数。执行加 $1$ 操作后：
$$\text{AL} = 10000010B$$
最高位依然为 $1$（负数），因此：
$$SF = 1$$

再如：
```assembly
sub ax, ax
```
`AX` 自身相减后结果为 $0$。由于 $0$ 为非负数，因此：
$$SF = 0$$

#### 有符号数与无符号数的判断机制
对于特定的二进制序列（例如 `10000010B`）：
- 若视作有符号数，其代表十进制数 $-126$；
- 若视作无符号数，其代表十进制数 $+130$。

CPU 在执行运算时，无法预知程序员的意图，因此它会依据规则同步更新 SF 标志位。
- 如果程序将数据当做有符号数使用，则应关注并利用 SF 标志位判断正负；
- 如果程序将数据当做无符号数使用，SF 的改变则没有意义，直接忽略即可。

### [14:13] CF（Carry Flag）进位标志位

CF 为进位标志位，位于标志寄存器的第 0 位。

进位标志通常与**无符号数运算**相关联。CF 记录运算结果的最高有效位向更高位产生的**进位值**，或从更高位借入的**借位值**：
- 产生进位或借位时：$CF = 1$（Debug 显示为 `CY`）；
- 未产生进位或借位时：$CF = 0$（Debug 显示为 `NC`）。

#### 最高有效位与假想更高位
对于 $N$ 位的无符号数：
- 二进制最高有效位为第 $N-1$ 位（例如 8 位数据的有效位为第 $0 \sim 7$ 位，最高有效位为第 $7$ 位）。
- 假想存在一个第 $N$ 位（对于 8 位数据即第 8 位）：
  - **加法运算**：若 8 位运算结果超出 8 位存储范围，产生的进位便进入该假想位，记录在 CF 中；
  - **减法运算**：若不够减需要借位，则向该假想位借位，借位情况同样记录在 CF 中。
16 位运算同理。

#### 示例分析

```assembly
mov al, 98H
add al, 98H
```
十六进制数 `98H` 的二进制为 `10011000B`。两个 `98H` 相加：
$$98\text{H} + 98\text{H} = 130\text{H}$$
由于 `AL` 只能存放 8 位数据，低 8 位 `30H` 写入 `AL`，向假想更高位产生了进位，因此：
$$CF = 1$$

接着执行：
```assembly
add al, al
```
此时 `AL` 内为 `30H`，相加后结果为 `60H`，未产生进位，因此：
$$CF = 0$$

紧接着执行借位示例：
```assembly
sub al, 98H
```
此时 `AL` 为 `60H`，执行 $60\text{H} - 98\text{H}$，被减数小于减数，需要向更高位借位，因此：
$$CF = 1$$

由此可见，CF 标志既表示加法产生的进位，也表示减法产生的借位。

### [17:48] OF（Overflow Flag）溢出标志位

OF 为溢出标志位，位于标志寄存器的第 11 位。

当进行**有符号数运算**时，如果运算结果超出了机器所能表示的有符号数范围，称为**溢出**：
- 发生溢出时：$OF = 1$（Debug 显示为 `OV`）；
- 未发生溢出时：$OF = 0$（Debug 显示为 `NV`）。

#### 有符号数的表示范围
- **8 位有符号数范围**：$-128 \sim +127$
- **16 位有符号数范围**：$-32768 \sim +32767$

如果运算结果超出了上述对应范围，OF 标志位置 $1$。必须特别强调，**OF 溢出标志仅针对有符号数运算**。

#### 示例 1：正数相加溢出

```assembly
mov al, 98
add al, 99
```
十进制运算 $98 + 99 = 197$。
- 若视作无符号数，结果 $197$ 在 $0 \sim 255$ 范围内，未产生进位（$CF = 0$）；
- 若视作有符号数，结果 $197$ 超出了 8 位有符号数最大上限 $+127$，发生了溢出，因此：
$$OF = 1$$

#### 示例 2：负数相加溢出

```assembly
mov al, 0F0H
add al, 88H
```
将十六进制数视作 8 位有符号数：
- `0F0H` 对应的十进制有符号数为 $-16$；
- `88H` 对应的十进制有符号数为 $-120$；
- 两者相加：$(-16) + (-120) = -136$。

虽然两个操作数均在 8 位有符号数范围（$-128 \sim +127$）内，但计算结果 $-136 < -128$，超出了下限，发生了溢出，因此：
$$OF = 1$$

#### CF 与 OF 的本质区别

- **CF（进位标志）**：面向**无符号数**运算，记录最高有效位是否产生进位或借位。
- **OF（溢出标志）**：面向**有符号数**运算，记录运算结果是否超出有符号数表示范围。

无论将数据视作有符号数还是无符号数，CPU 在运算时都会同时根据规则设置 CF 与 OF：
```assembly
mov al, 0F0H
add al, 88H
```
执行后：
- 作为**无符号数**看：`0F0H` ($240$) + `88H` ($136$) = $376 > 255$，产生了最高位进位，故 $CF = 1$；
- 作为**有符号数**看：$-16 + (-120) = -136 < -128$，发生了逻辑溢出，故 $OF = 1$。

数据的含义由程序员所编写的程序逻辑决定，CPU 忠实记录两种视角下的状态。

### [22:04] 综合练习与 Debug 验证方法

标志位的概念虽然细节较多，但其内在规律非常清晰。我们可以通过分析一系列指令的执行结果来巩固理解。

#### 示例推导：`sub al, al`

执行 `sub al, al`（寄存器自身相减，结果为 $0$）：
- **CF = 0**：未产生借位；
- **OF = 0**：未发生溢出；
- **SF = 0**：结果为 $0$（非负数）；
- **ZF = 1**：运算结果为零；
- **PF = 1**：结果为全零（`00000000B`），其中包含 $0$ 个 $1$（$0$ 是偶数），故为偶校验。

#### 学习建议与自我检测
在自主练习时，若需验证自己推导的标志位是否正确，可以通过 Debug 工具进行检验：
1. 启动 Debug，使用 `A` 命令输入待测试的汇编指令序列；
2. 使用 `T` 命令单步跟踪执行指令；
3. 每步执行完成后，观察寄存器状态行末尾列出的各标志位代号（`OV/NV`, `UP/DN`, `NG/PL`, `ZR/NZ`, `PE/PO`, `CY/NC`），核对与自己推导的结果是否一致。

通过动手实践与核对，能够迅速加深对各标志位工作机制的掌握。
