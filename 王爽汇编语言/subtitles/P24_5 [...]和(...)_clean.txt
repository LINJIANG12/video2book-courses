# 汇编语言中的符号约定与内存操作详解

---

### [00:00] 符号 `[...]` 与 `(...)` 的引入与内存描述

在这一节中，我们介绍一下在学习汇编语言当中经常遇到的两个符号：一个是方括号 `[...]`，一个是圆括号 `(...)`。

有关这部分的规定，涉及到对内存的一种描述。我们知道，要描述一个内存单元，其实是从两个方面去描述：
1. **内存单元在哪**：说的是内存单元的地址。
2. **内存单元里面保存的值是多少**：涉及到它的类型，而这个类型与内存单元的长度是有关系的。

就内存单元的地址而言，它的物理地址是由**段地址**和**偏移地址**构成的，这是我们已经掌握的知识。

---

### [00:38] 语法符号：方括号 `[...]` 表示内存单元

在汇编指令当中，我们会用到方括号 `[...]`。对于方括号而言，它表示的是一个内存单元。需要注意到，方括号是汇编语言本身的规定，是汇编语言在语言自己的语法当中要求用到的符号。

我们给出以下几条指令：

```assembly
mov ax, [0]
mov al, [0]
mov ax, [bx]
mov al, [bx]
```

在这几条指令里面，凡是用到了方括号的地方，其实都对应了要使用到内存。

在这四条指令当中，所使用的内存段地址默认都在数据段寄存器 `DS` 里面。而它们的偏移地址分别如下：
- **前两条指令**：偏移地址直接由常数给出，即偏移地址对应在 `0` 这个位置；
- **后两条指令**：偏移地址保存在寄存器 `BX` 里面。

这是我们熟悉的内存操作指令。而操作的单元长度方面：
- 指令中包含 `AX` 时，操作的是**字（Word）**；
- 指令中包含 `AL` 时，它是半个字，操作的是**字节（Byte）**；
- 后面的 `AX` 与 `AL` 同样分别对应字和字节。这是很容易看出来的。

### [02:00] 约定符号：圆括号 `(...)` 表示寄存器或内存的内容

纯粹用汇编语言这种计算机语言的形式去描述操作时，口头交流有时并不方便，写出来也会很繁杂。因此在学习汇编语言时，我们引入圆括号 `(...)`。

圆括号 `(...)` 表示：**一个内存单元或者是寄存器里面的内容**。

需要特别注意：圆括号并不是写到汇编程序里面的代码，不是汇编语言的语法规定，而是为了方便学习与交流，大家共同做出的约定。

具体表达形式如下：

1. **表示寄存器的内容**：  
   若 `AX` 里面的内容是 $0010\text{H}$，我们描述为：
   $$(ax) = 0010\text{H}$$

2. **表示内存单元的内容**：  
   若直接给出一个内存地址，该地址的内容为 $0010\text{H}$，描述方法为将物理地址置于括号内：
   $$(20000\text{H}) = 0010\text{H}$$
   *注：在用这种方法表示时，括号内部只能使用寄存器或具体的物理地址，不能把形如“段地址:偏移地址”的表示直接放进括号内。*

3. **指令含义的数学化描述**：
   - 指令 `mov ax, [2]`：表示由 `DS` 段寄存器和偏移地址 `2` 共同构成的内存单元中的内容移入 `AX`。用约定符号描述为：
     $$(ax) = ((ds) \times 16 + 2)$$
   - 指令 `mov [2], ax`：表示把 `AX` 寄存器的内容移入由 `DS` 与偏移地址 `2` 所指向的内存单元中。用约定符号描述为：
     $$((ds) \times 16 + 2) = (ax)$$

### [04:49] 约定符号在栈操作中的应用

当涉及到压栈指令时，它不仅会改变栈顶指针寄存器的值，还会改变栈对应的内存单元的值。

我们可以将 `push ax` 严谨地表示为：
1. 栈顶指针调整：
   $$(sp) = (sp) - 2$$
2. 内存写入：
   $$((ss) \times 16 + (sp)) = (ax)$$
   *其中，$ (ss) \times 16 + (sp) $ 构成了当前的栈顶物理地址，外层再加上括号，表示将 `AX` 的内容赋给该栈顶内存单元。*

同样地，对于出栈指令 `pop ax`，也可以通过类似的方式严格描述。

### [06:00] 符号常量：`idata` 的含义与规范

在描述汇编语法时，常使用符号 `idata` 表示常量（Immediate Data，立即数）：

- 例如指令格式：`mov ax, idata`，其中的 `idata` 可以用任意合法的常量替代，如：
  ```assembly
  mov ax, 1
  mov ax, 2
  mov ax, 3
  ```
- 类似地，`mov bx, 123` 就是把数值直接传送到 `BX` 中。
- 如果写成 `mov ds, idata`（如 `mov ds, 1`、`mov ds, 2`），由于 `DS` 是段寄存器，8086 架构不允许将立即数直接传送进段寄存器，因此这些均属于**非法指令**。

这就类似于化学中使用 $H_2O$ 符号代表水一样，在一个学科内描述规律时，我们非常需要借助这样规范的符号约定。

### [07:01] 综合案例分析：代码执行与内存变化追踪

#### 示例汇编代码

```assembly
mov ax, 2000H
mov ds, ax
mov bx, 1000H
mov ax, [bx]
inc bx
inc bx
mov [bx], ax
inc bx
inc bx
mov [bx], ax
inc bx
mov [bx], al
inc bx
mov [bx], al
```

#### 执行过程逐步推导

1. **寄存器初始化**：
   - `mov ax, 2000H` $\rightarrow (ax) = 2000\text{H}$
   - `mov ds, ax` $\rightarrow (ds) = 2000\text{H}$（段地址确定为 $2000\text{H}$）
   - `mov bx, 1000H` $\rightarrow (bx) = 1000\text{H}$

2. **读取字单元内容**：
   - `mov ax, [bx]`  
     访问内存物理地址：
     $$\text{物理地址} = (ds) \times 16 + (bx) = 2000\text{H} \times 16 + 1000\text{H} = 21000\text{H}$$
     此操作为**字操作**，读取 $21000\text{H}$ 与 $21001\text{H}$ 两个字节（假设内存中分别存有 $\text{B1H}$ 和 $00\text{H}$）。按照高字节存高位、低字节存低位的规则，读取出的内容为 $00\text{B1H}$：
     $$(ax) = 00\text{B1H}$$

3. **偏移地址自增**：
   - 连续执行两次 `inc bx`：
     $$(bx) = 1000\text{H} + 1 + 1 = 1002\text{H}$$

4. **字单元写操作**：
   - `mov [bx], ax`  
     此时目标物理地址为：
     $$2000\text{H} \times 16 + 1002\text{H} = 21002\text{H}$$
     操作为**字操作**，将 `AX`（$00\text{B1H}$）写入 $21002\text{H} \sim 21003\text{H}$ 内存空间。低位字节 $\text{B1H}$ 写入 $21002\text{H}$，高位字节 $00\text{H}$ 写入 $21003\text{H}$。

5. **再次自增并写字单元**：
   - 连续执行两次 `inc bx`：
     $$(bx) = 1004\text{H}$$
   - `mov [bx], ax`  
     目标物理地址为 $21004\text{H}$。字操作，将 $00\text{B1H}$ 写入 $21004\text{H} \sim 21005\text{H}$（$21004\text{H}$ 写入 $\text{B1H}$，$21005\text{H}$ 写入 $00\text{H}$）。

6. **字节写操作（单次自增）**：
   - 单次执行 `inc bx`：
     $$(bx) = 1005\text{H}$$
     结合段地址后的内存单元起始物理地址为 $21005\text{H}$。
   - `mov [bx], al`  
     `AL` 是 8 位寄存器，值为 $\text{B1H}$。该指令为**字节操作**，仅操作一个字节空间。将 $\text{B1H}$ 写入 $21005\text{H}$，原本该位置的 $00\text{H}$ 被更新覆盖为 $\text{B1H}$。

7. **再次字节写操作**：
   - 执行 `inc bx`：
     $$(bx) = 1006\text{H}$$
   - `mov [bx], al`  
     字节操作，将 `AL` 中的 $\text{B1H}$ 写入物理地址 $21006\text{H}$ 的内存单元中。
