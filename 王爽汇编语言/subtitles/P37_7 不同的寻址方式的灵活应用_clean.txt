# 汇编语言：内存寻址方式总结与二重循环实现

---

### [00:00] 内存寻址方式总结

在本节中，我们总结一下内存单元的不同寻址方式，并在此基础上探究其在实际应用中的处理。

到目前为止，我们学习过的内存寻址方式主要有以下几种：

1. **直接寻址**  
   在方括号中直接给出一个常量或者立即数，例如 `[200]`。我们把这种方式称为**直接寻址**，因为这里直接给出了操作数的偏移地址。这是一种最简单、最直接的寻址方式。
   
2. **寄存器间接寻址**  
   把偏移地址存放在寄存器中（一般情况下使用 `bx` 作为表示地址的寄存器），形式如 `[bx]`。此时称为**寄存器间接寻址**。之所以叫“间接”，是因为我们把偏移地址存入寄存器，通过取出寄存器的值间接获知内存单元的位置。也就是使用变量（寄存器）去表示内存的地址，间接定位内存单元。

3. **寄存器相对寻址**  
   形式如 `[bx + 200]`，即寄存器加上一个立即数。之所以称为**相对寻址**，是因为在确定偏移地址时，首先基于一个起始地址（通过直接量/立即数给出起始基准），在此基础上再通过变量（寄存器）去定位目标内存单元。它是相对于给出的立即数基准，再去叠加变量定位。具体例子如 `[bx + 200]`，寻址时在偏移量 $200$ 的基础上，相对利用 `bx` 找到对应的单元。

4. **基址变址寻址**  
   使用一个基址寄存器（如 `bx`）和一个变址寄存器（如 `si` 或 `di`），形式如 `[bx + si]`。我们称其为**基址变址寻址**，其中 `bx` 为基址，`si` 为变址。这样便可以通过两个变量共同表示一个内存地址。

5. **相对基址变址寻址**  
   将上述形式综合，即**相对基址变址寻址**，形式如 `[bx + si + idata]`。寻址时相对于一个确定的数值（立即数），在此基础上同时结合基址寄存器与变址寄存器。这种形式在实际应用开发中也非常常用。

未来在遇到实际应用问题时，我们需要根据问题的不同性质与数据结构特征，选择最合适的一种寻址方式。

### [03:07] 案例一：首字母大写转换与寻址方式选择

接下来通过具体案例分析寻址方式的确定与应用。

**【问题描述】**  
编写程序，将 `datasg` 段中每个单词的首字母改为大写字母。当前给出的 `datasg` 段中包含 6 个字符串（例如某软件中的菜单项）：`1. file`、`2. edit` 等。我们希望把每个单词的第一个字母（如 `'f'`、`'e'`）改为大写。

```
1. file          
2. edit          
...
```

**【数据结构分析】**  
观察需要处理的数据结构，可以将这组字符看作二维排列：
- 第一行：`1. file          `
- 第二行：`2. edit          `
- 每行固定包含 16 个字符（末尾补空格），因此每行的偏移跨度为 $16$ 字节（十六进制为 `10H`），行内字符偏移量为 `0` 到 `F`。
- 要修改的目标字母均位于各行的第 3 列（列下标从 0 开始算，列号为 3）。

**【寻址与算法设计】**  
- 使用寄存器 `bx` 定位每一行的起始地址。
- 目标字母处于行内固定偏移量，因此列偏移直接使用立即数 `3`。
- 寻址方式选用**寄存器相对寻址**：`[bx + 3]`。
- 外层设置循环计数器 `cx = 6`。每次循环处理一行，处理完毕后将 `bx` 加上 16（指向下一行），依次迭代。

**【算法思路】**  
1. 获取第一行地址 $R$；
2. 循环 6 次：
   - 将第 $R$ 行第 3 列的字母改为大写；
   - $R = R + 16$（指向下一行地址）；
3. 循环结束。

**【代码实现】**

```assembly
mov ax, datasg
mov ds, ax
mov bx, 0           ; bx 指向第一行起始偏移地址 0
mov cx, 6           ; 循环 6 次处理 6 行

s:  
    mov al, [bx + 3]    ; 取出第 R 行第 3 列的字符
    and al, 11011111b   ; 转换为大写字母
    mov [bx + 3], al    ; 写回原内存单元
    add bx, 16          ; 移动到下一行首地址
    loop s
```

通过 `[bx + 3]` 相对寻址，程序简洁高效地完成了首字母转换为大写的操作。

### [07:01] 案例二：单词全大写转换（二维数组与二重循环）

接下来看另一个进阶案例。

**【问题描述】**  
将 `datasg` 段中每个单词的所有字母都改为大写字母（如将 `'ibm'`, `'dec'` 等单词的所有字符全转为大写）。

**【数据结构分析】**  
- 此处共有 4 行，每行 16 列，构成一个 $4 \times 16$ 的二维数组。
- 针对本例，每行实际包含的数据为前 3 列字符。
- 我们需要修改二维数组中每一行的前 3 列。

**【循环结构设计】**  
这需要构造一个 $4 \times 3$ 的**二重循环**：
- 外层循环执行 4 次，每次处理一行；
- 内层循环执行 3 次，处理当前行中的连续 3 个字母。

**【寻址方式选择】**  
- 基址寄存器 `bx` 代表行基址；
- 变址寄存器 `si` 代表行内的列偏移；
- 选用**基址变址寻址**：`[bx + si]`。`bx` 确定行起始地址，`si` 遍历行内的各个列单元。

### [11:31] 核心问题：二重循环中的 `cx` 寄存器冲突

初步编写的二重循环算法代码可能如下：

```assembly
    mov ax, datasg
    mov ds, ax
    mov bx, 0
    
    mov cx, 4           ; 外层循环 4 次（4 行）
s0: 
    mov si, 0           ; si 指向每行第 0 列
    mov cx, 3           ; 内层循环 3 次（前 3 列字符）
s:  
    mov al, [bx + si]
    and al, 11011111b
    mov [bx + si], al
    inc si
    loop s              ; 内层循环控制
    
    add bx, 16
    loop s0             ; 外层循环控制（此处产生逻辑错误！）
```

**【冲突分析】**  
这段代码在思维逻辑上看似清晰，但在底层执行时存在严重缺陷：
1. 外层循环开始时设置了 `cx = 4`；
2. 进入内层循环前，执行了 `mov cx, 3`，此时外层计数器的值被内层计数器直接覆盖；
3. 内层循环执行完毕时，`cx` 递减至 `0`，退出内层循环；
4. 到达外层的 `loop s0` 指令时，CPU 先将 `cx` 减 1（由 `0` 变为 `FFFFH`，即 $-1$），由于结果不为 0，程序陷入死循环/异常逻辑。

根本原因在于：**8086 CPU 只有一个 `cx` 计数寄存器**。内外层循环都依赖 `loop` 指令，而 `loop` 强制绑定 `cx`，内层循环修改 `cx` 会彻底破坏外层循环的状态。

---

### [13:03] 解决方案一：使用通用寄存器（`dx`）暂存 `cx`

为了避免外层计数被冲掉，最直接的方法是在进入内层循环前，将外层 `cx` 的值暂存到其他通用寄存器（例如 `dx`）中。

**【代码实现】**

```assembly
    mov ax, datasg
    mov ds, ax
    mov bx, 0
    
    mov cx, 4           ; 外层循环计数
s0: 
    mov dx, cx          ; 将外层 cx 暂存到 dx
    mov si, 0
    mov cx, 3           ; 设置内层循环计数
s:  
    mov al, [bx + si]
    and al, 11011111b
    mov [bx + si], al
    inc si
    loop s              ; 内层循环结束时 cx = 0
    
    add bx, 16
    mov cx, dx          ; 从 dx 恢复外层循环计数
    loop s0
```

**【方案缺陷】**  
该方法逻辑清晰，但在复杂程序中存在明显的局限性：
CPU 内部的通用寄存器资源非常稀缺（8086 总共仅有 14 个寄存器）。如果程序中 `dx` 已被用于乘除法运算或其他数据处理，或者嵌套层次达到三重、四重时，将没有足够的寄存器可供暂存。

### [15:07] 解决方案二：使用固定内存空间暂存数据

若寄存器不足，可开辟一段固定的内存单元来保存外层 `cx` 的值（例如数据段偏移地址为 `40H` 的单元 `ds:[40H]`）。

**【代码实现】**

```assembly
    mov ax, datasg
    mov ds, ax
    mov bx, 0
    
    mov cx, 4
s0: 
    mov ds:[40H], cx    ; 将外层 cx 保存在内存单元 ds:[40H]
    mov si, 0
    mov cx, 3
s:  
    mov al, [bx + si]
    and al, 11011111b
    mov [bx + si], al
    inc si
    loop s
    
    add bx, 16
    mov cx, ds:[40H]    ; 从内存单元恢复外层 cx
    loop s0
```

**【方案缺陷】**  
在程序中硬编码指定某个特定内存单元并不安全：
在大型或复杂程序中，该内存单元很容易与其他数据冲突、被意外覆写；此外，多重嵌套时需要手动规划和维护多个静态内存地址，给程序员带来沉重的心智负担。

---

### [16:19] 解决方案三：使用栈结构保护 `cx`（最佳实践）

最为规范、通用的方法是利用系统提供的**栈（Stack）**机制来保存与恢复寄存器现场。

**【代码实现】**

```assembly
    ; 假设已在程序头部正确初始化栈段 ss 与栈指针 sp
    mov ax, datasg
    mov ds, ax
    mov bx, 0
    
    mov cx, 4           ; 外层循环计数
s0: 
    push cx             ; 将外层 cx 的值压栈保护
    mov si, 0
    mov cx, 3           ; 设置内层循环计数
s:  
    mov al, [bx + si]
    and al, 11011111b
    mov [bx + si], al
    inc si
    loop s              ; 内层循环
    
    add bx, 16
    pop cx              ; 从栈顶弹出原 cx 的值恢复
    loop s0             ; 外层 loop 使用恢复后的 cx 计数
```

**【栈保护机制的优势】**  
1. **后进先出（LIFO）特性**天然契合嵌套循环结构。
2. 无论是两重循环、三重循环还是四重循环，都可以遵循“**进入内层前压栈（`push`），退出内层后出栈（`pop`）**”的规则，无需占用额外寄存器，也无需人工管理静态内存地址分配。
3. 代码结构严谨、可维护性强，是汇编语言中多重循环和现场保护的标准做法。

### [17:46] 本节小结

本节主要总结了：
1. **内存寻址方式的综合对比**：直接寻址、寄存器间接寻址、寄存器相对寻址、基址变址寻址及相对基址变址寻址；
2. **寻址方式在工程案例中的选型**：如单行多列选 `[bx + idata]`，二维矩阵遍历选 `[bx + si]`；
3. **二重循环的经典陷阱与处理机制**：由于 `cx` 寄存器唯一，处理嵌套循环时必须对其进行保护，而**使用栈（`push`/`pop`）进行现场保护**是最高效、最通用的解决方案。
