# 汇编语言：`call` 与 `ret` 指令配合使用及栈空间规范

### [00:00] 子程序嵌套调用与返回流程分析

我们在介绍了 `call` 指令和 `ret` 指令的语法之后，来看一下用 `call` 指令和 `ret` 指令配合解决问题的套路。

具有子程序的源程序框架，可以通过这个例子来反映：

程序的执行是从标号 `main` 开始的（这个标号可以随意命名）。在执行若干语句后会遇到 `call` 指令。遇到 `call` 指令时，它要调用标号为 `sub1` 的子程序，转到此处执行。

转到此处执行时，子程序 `sub1` 内部又调用了子程序 `sub2`，因此程序会转移去执行 `sub2` 对应的指令。

当在子程序 `sub2` 中遇到 `ret` 指令后，CPU 会将栈顶的 IP 出栈。当时出栈的 IP，即为调用 `sub2` 时压栈保存的地址——也就是 `sub1` 中 `call sub2` 下一条指令的 IP。因此执行 `ret` 获取该 IP 后，程序返回到 `sub1` 中继续执行后续指令。

直到再次遇到 `ret` 指令，又将 IP 出栈。此时出栈的 IP 是最初在主程序中调用 `sub1` 时下一条指令的地址。因此该 `ret` 会返回到主程序对应位置，继续把主程序执行完毕。

这就是具有子程序的源程序框架一步步调用、一步步返回的完整执行过程。

### [01:40] 子程序的调用与定义框架规范

总结调用与定义子程序的结构框架：

1. **主程序调用子程序**：
   ```assembly
   call 标号
   ```
2. **子程序框架定义**：
   ```assembly
   标号:
       ; 一系列具体指令，用于实现子程序功能
       ret
   ```
   标号代表该子程序的入口；中间编写一系列指令完成相应功能；最后通过 `ret` 返回到调用处 `call` 指令的下一条语句。

### [02:09] 案例实践：计算 $2^N$ 的子程序设计

接下来使用这种框架编写一个程序，利用子程序调用完成指定任务。

**任务目标**：计算 $2^N$ 的值，其中 $N$ 的值由寄存器 `cx` 提供。

程序逻辑如下：
```assembly
mov ax, 1      ; 2^0 = 1，将初始值存入 ax
mov cx, 3      ; N 的值由 cx 提供，当前设置为 3，即计算 2^3
call s         ; 调用子程序 s
; ... 主程序后续指令 ...

s:
    add ax, ax ; 每次自身累加，相当于乘以 2
    loop s     ; 循环执行，次数由 cx 决定
    ret        ; 子程序返回
```

子程序 `s` 的功能：通过循环计算出 $2^N$（$N$ 即 `cx` 的值）。  
因为 `loop` 的循环次数与 `cx` 相关（此处为 3 次），每次循环将 `ax` 自身相加：
- 第一次循环：`ax` 由初始的 1 变为 2；
- 第二次循环：$2 + 2 = 4$；
- 第三次循环：$4 + 4 = 8$（即 $2^3$）。

当子程序循环结束遇到 `ret` 后，返回到主程序 `call s` 的下一条指令继续执行。

### [03:41] 汇编与反汇编解析（相对位移与 IP 计算）

将上述程序经过编译、链接，并加载至 Debug 调试环境后，使用 `U` 命令查看反汇编代码：

对于 `call` 指令，反汇编显示为 `call 0010`，表示目标是转移到 `add ax, ax` 处执行。  
查看其机器码为：`E8 07 00`。

根据小端存储规范，`07 00` 即偏移量 `0007H`。在 CPU 读取执行 `call` 指令时，IP 已经自动指向下一条指令的偏移地址 `0009H`：
$$0009\text{H} + 0007\text{H} = 0010\text{H}$$

十六进制运算结果恰好为目标地址 `0010H`。由此可见，`call` 机器指令中存放的是相对偏移地址，即由下一条指令的偏移地址加上该相对偏移量，得到最终转移的目标地址。

### [04:50] Debug 单步跟踪与返回机制验证

在 Debug 中使用 `T` 命令单步跟踪执行：
1. 初始执行 `mov ax, 0001` 与 `mov cx, 0003`；
2. 执行 `call 0010` 时，CPU 将下一条指令的地址 `0009H` 压入栈中，随后 IP 被修改为 `0010H`；
3. 程序跳转至 `add ax, ax` 执行循环，`ax` 的值逐步由 1 变为 2，再变为 4，最终变为 8，完成 $2^3$ 的计算；
4. 当 `cx` 递减为 0 退出循环后，遇到 `ret` 指令（此时 IP 为 `0014H`）；
5. 单步执行 `ret`，栈顶保存的 `0009H` 出栈恢复至 IP，程序顺利返回到主程序中 `call` 下方的下一条指令继续执行。

整个调用与返回过程，核心伴随着栈中 IP 的压栈与出栈操作。

### [06:39] 隐患剖析：未显式分配栈空间的风险

该程序虽然能得出正确计算结果，但存在严重的底层安全隐患：

`call` 和 `ret` 指令的执行依赖堆栈，但在上述代码中，**并未显式开辟并定义栈段**。  
此时程序默认使用的栈段寄存器（`SS`）和栈顶指针（`SP`）指向的是系统未分配的随意内存空间。这种操作极其危险，在某些运行环境下可能会覆盖破坏其他关键内存数据，属于错误且不规范的程序写法。

### [07:28] 规范改进：显式定义并初始化栈空间

在涉及子程序调用时，必须显式定义栈段并正确初始化：

```assembly
stack segment
    db 16 dup (0)  ; 明确开辟 16 个字节的栈空间
stack ends

code segment
    assume cs:code, ss:stack
start:
    mov ax, stack
    mov ss, ax     ; 初始化栈段寄存器 SS
    mov sp, 16     ; 初始化栈顶指针 SP

    mov ax, 1
    mov cx, 3
    call s
    ; ... 主程序后续指令 ...

s:
    add ax, ax
    loop s
    ret
code ends
end start
```

通过显式设置 `SS` 和 `SP`，保证了子程序在执行压栈保存 IP 及出栈恢复 IP 时，使用的均是受控的合法内存空间。

### [07:56] 规范程序的反汇编验证与栈内存监控

对完善后的程序进行反汇编查看：
- `call` 指令位于偏移地址 `000BH` 处，目标跳转地址为 `0013H`；
- 下一条指令偏移地址为 `000EH`；
- 该 `call` 指令中的机器码位移量为 `0005H`：
  $$000\text{E}\text{H} + 0005\text{H} = 0013\text{H}$$

在执行单步跟踪时：
1. 单步执行至 `000BH` 的 `call` 指令前，使用 `D ss:0 f` 查看栈段内存（16 个字节），此时栈底为初始值；
2. 执行 `T` 命令调用子程序，IP 跳转至 `0013H`；
3. 再次使用 `D ss:0 f` 观察栈空间，发现栈顶压入了数值 `000EH`，正好是调用处下一条指令的偏移地址；
4. 子程序完成累加后执行 `ret`，将栈中的 `000EH` 弹出赋予 IP，程序准确返回到主程序继续执行。

**总结**：在编写包含子程序的汇编程序时，必须规范开辟和初始化栈空间，并能够熟练结合栈段内存的变化来分析 `call` 与 `ret` 的底层执行细节。
