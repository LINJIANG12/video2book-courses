# 汇编语言：SI 和 DI 寄存器及其寻址应用

[00:00]
在这一节，我们介绍 SI 和 DI 寄存器。

先看一下我们学过的寄存器：
- **通用寄存器**：AX、BX、CX、DX，我们已经用过了，它们可以看成是由两个 8 位的寄存器构成的；
- **指针寄存器**：SP，栈顶指针寄存器；
- **指令指针寄存器**：指令执行过程中的 IP 寄存器；
- **段寄存器**：四个段寄存器前面已经学过了。

可以看到寄存器很多，但我们慢慢都已经熟悉了。今天我们所介绍的是变址寄存器：**SI** 和 **DI**。

---

[00:35]
所谓变址寄存器，也就是说在执行的时候，是用于和地址有关的操作。

实际上我们要知道，前面操作地址的时候曾用过 BX，BX 经常用作和地址有关的操作，它是一个特殊的通用寄存器，当然也可以干其他的事。作为 SI 和 DI 来讲，它们是 8086 CPU 里面和 BX 功能相近的寄存器，经常用于对地址的操作：
- **SI**：源变址寄存器（Source Index）；
- **DI**：目标变址寄存器（Destination Index）。

它们和“变址”密切相关，对应变化中的地址。

SI、DI 和 BX 功能相近，区别在于：SI 和 DI 是纯粹的 16 位寄存器，不像 BX 那样可以拆分成 BL 和 BH 两个 8 位寄存器来使用，仅此而已。

---

[01:39]
接下来我们看，下边三组指令实现相同的功能。

对于使用 BX 寻址：BX 代表偏移地址，段地址在 DS 当中，将该单元的一个字送入 AX 中：
```assembly
mov ax, [bx]
```

同样地，该指令也可以将 BX 替换成 SI 或 DI。因为涉及到对地址的操作，SI 或 DI 作为偏移地址，DS 作为段地址，找到内存单元并送入 AX 中，效果是一样的：
```assembly
mov ax, [si]
mov ax, [di]
```

另外，使用 BX 寻址时，BX 后面加上一个常数可以代表一个单元，这也是我们经常使用的一种方式：
```assembly
mov ax, [bx+200]
```

在我们使用的过程当中，凡是 BX 出现的地方，都可以替换成 SI 和 DI 使用：
```assembly
mov ax, [si+200]
mov ax, [di+200]
```

---

[02:34]
接下来我们利用这种方法来解决实际问题。现在的需求是：使用寄存器 SI 和 DI，将字符串 `"welcome to masm"` 复制到它后面的数据区中。

根据这个要求，我们可以写出程序的整体框架：
```assembly
datasg segment
    db 'welcome to masm'
    db '...............'
datasg ends
```
在程序开始之后，定义数据区，包含我们要复制的源字符串 `'welcome to masm'`；后面在单引号中加上点（`.`），用于预留出空间，点的数目与源字符串中的字符数量一致。预留空间之后，目标就是把源字符串复制到该位置。

在进行操作时，需要分析：
1. **源数据**：拷贝的源数据起始偏移地址为 `0`，段地址为 `datasg`；
2. **目标数据**：源字符串正好占用 16 个字节，偏移地址范围为 $0 \sim \text{F}$；因此目标字符串的起始偏移地址为 16（十六进制表示为 `10H`）。

此时结合 SI 和 DI 寄存器：
- 用 `ds:si` 指向原始字符串，SI 的初值设置为 `0`；
- 用 `ds:di` 指向目标空间，DI 的初值设置为 `16`（即 `10H`）。

在复制过程中，每处理完一次，SI 和 DI 依次向后移动，将对应位置的字符复制过去。由于总共有 16 个字符，可以通过循环来完成。

---

[04:41]
程序代码实现如下：

```assembly
assume cs:codesg, ds:datasg

datasg segment
    db 'welcome to masm'
    db '...............'
datasg ends

codesg segment
start:
    mov ax, datasg
    mov ds, ax
    
    mov si, 0
    mov di, 16
    
    mov cx, 8
s:  mov ax, [si]
    mov [di], ax
    add si, 2
    add di, 2
    loop s
    
    mov ax, 4c00h
