# 汇编语言：带进位加法（ADC）与带借位减法（SBB）指令详解

### [00:00] 带进位与借位的加减法指令概述

在这一节，我们介绍两个指令，分别实现加法和减法，它们带有进位或者借位的功能。

带进位的加法指令是 `ADC`。该指令实现的是加法功能，其特殊之处在于使用了标志寄存器当中的进位标志位 $\text{CF}$（Carry Flag）。

它的指令格式与一般的加法指令相同：

```assembly
adc 操作对象1, 操作对象2
```

其执行的功能为：

$$\text{操作对象1} = \text{操作对象1} + \text{操作对象2} + \text{CF}$$

也就是说，目标操作数等于操作对象 1 加上操作对象 2，同时再加上 $\text{CF}$ 的值。如果前面的运算产生过进位，$\text{CF} = 1$；如果没有产生进位，$\text{CF} = 0$。

例如执行 `adc ax, bx`，其功能就是把 $\text{AX}$ 和 $\text{BX}$ 加起来，再加上 $\text{CF}$ 的值，最后将相加的结果存入 $\text{AX}$ 中。

---

### [01:09] ADC 示例一：进位标志对加法结果的影响

有了这样一个指令后，我们可以看一下具体的应用示例。

首先把 $98\text{H}$ 存入 $\text{AL}$ 中，然后执行 $\text{AL}$ 和 $\text{AL}$ 的加法（使用 `ADD` 指令）：

$$98\text{H} + 98\text{H} = 130\text{H}$$

$\text{AL}$ 是一个 8 位的寄存器，相加得到 $130\text{H}$ 时，最高位的 $1$ 产生了进位，超出 8 位的部分被舍弃，因此 $\text{AL}$ 中保存的值是 $30\text{H}$，同时进位标志位 $\text{CF}$ 置为 $1$。

接下来，如果对 $\text{AL}$ 加上 3，本身 $30\text{H} + 3$ 应该等于 $33\text{H}$。但由于上一条加法指令产生了进位（$\text{CF} = 1$），在这一步使用 `ADC` 相加时，结果由 $33\text{H}$ 变成了 $34\text{H}$，最终结果为 $34\text{H}$。

整个执行过程相当于：

$$\text{AX} = \text{AX}_{\text{原值}} + 3 + \text{CF} = 30\text{H} + 3 + 1 = 34\text{H}$$

---

### [02:25] ADC 示例二：无进位标志时的计算过程

我们再看另一个例子：

若 $\text{AX}$ 初始值为 1，执行 `add ax, ax` 运算后，$\text{AX}$ 变为 2。

接着使用 `ADC` 指令将 $\text{AX}$ 加 3：此时虽然使用了 `ADC` 指令且在运算中引入了 $\text{CF}$，但在前面的加法运算中 $1 + 1 = 2$，并未产生进位，此时 $\text{CF} = 0$。因此最终结果依然是：

$$2 + 3 + 0 = 5$$

---

### [03:03] ADC 示例三：减法借位对 ADC 指令的影响与规范编程

再看一个例子：

设 $\text{AX}$ 的值为 2，$\text{BX}$ 的值为 1。执行减法操作 $\text{BX} - \text{AX}$，由于 $\text{BX}$ 的数值小于 $\text{AX}$，减法运算会产生借位，借位产生后标志位 $\text{CF} = 1$。

随后执行带进位加法指令，将 $\text{AX}$ 与 1 相加。$\text{AX}$ 当前值为 2，$2 + 1 = 3$。由于使用了 `ADC` 指令，需要加上 $\text{CF}$ 的值（此时 $\text{CF} = 1$），最终 $\text{AX}$ 的值变为 4。

在这个问题中，加法指令读取了前面减法产生的借位标志 $\text{CF} = 1$。从汇编指令底层的运行机制来看，硬件严格按照规则执行逻辑；但从程序设计的角度来看，这种逻辑不符合正常运算常理。在实际开发中不能写出此类逻辑的代码，这需要程序员自我约束与自律。

### [04:33] ADC 的典型应用：32 位大数相加

下面来看 `ADC` 指令的实际应用——**大数相加**。

8086 指令集提供的 `ADD` 指令只能完成 8 位或 16 位的加法。当遇到更大位宽的数据（如 24 位、32 位、64 位甚至更高）相加时，就需要使用分段进位相加的方法。

以两个 24 位数相加为例，我们可以将其高位补零扩展为 32 位数：

$$
\begin{array}{r@{\quad}c@{\quad}c}
& 0011\text{H} & \text{F000H} \\
+ & 0020\text{H} & 0100\text{H} \\
\hline
\end{array}
$$

运算思路如下：
1. 先将低 16 位相加；
2. 再将高 16 位相加。低 16 位相加时可能产生进位，因此高 16 位相加时必须使用 `ADC` 指令计入进位。

实现代码如下：

```assembly
mov ax, 0011H    ; AX 存放被加数的高 16 位
mov bx, 0F000H   ; BX 存放被加数的低 16 位
add bx, 0100H    ; 低 16 位相加（无需考虑先前的进位，使用 ADD）
adc ax, 0020H    ; 高 16 位相加（必须计入低位的进位，使用 ADC）
```

最终，和的高 16 位存放在 $\text{AX}$ 中，和的低 16 位存放在 $\text{BX}$ 中。

---

### [06:53] 拓展应用：48 位多字节数据相加

如果参与运算的数据更大，例如两个 48 位的数据相加，可以拆分为三个 16 位字进行竖式相加。

运算策略为从低位逐步向高位累加：
1. 最低 16 位存放在 $\text{CX}$ 中，与加数的最低 16 位使用 `ADD` 指令相加；
2. 中间 16 位存放在 $\text{BX}$ 中，与加数中间 16 位相加时，必须使用 `ADC` 指令；
3. 最高 16 位存放在 $\text{AX}$ 中，与加数最高 16 位相加时，同样使用 `ADC` 指令。

通过链式带进位加法，即可完成任意大位宽数据的累加任务。

### [07:57] 128 位大数相加通用子程序设计

接下来设计一个更复杂的案例：**128 位大数相加子程序**。

我们希望将大数加法封装为一个通用子程序，以便在其他模块中调用。128 位数据总共占据 16 个字节，即 8 个字（Word）单元。

#### [08:25] 内存逆序存储规则
在定义数据时，采用逆序存储（小端序存放：低位数据存放在低地址，高位数据存放在高地址）：

- 被加数（128 位）：占用连续 16 字节
- 加数（128 位）：紧随其后占用连续 16 字节

低地址优先存放最低位字单元，依次向高地址存放高位字单元。采用逆序存储能极大降低指针递增寻址处理的难度。

#### [09:43] 指针与寄存器规划
由于通用寄存器数量有限，需要直接利用内存单元进行运算：
- `DS:SI` 指向第一个数据（被加数）的内存起始单元，初始偏移地址 $\text{SI} = 0$；
- `DS:DI` 指向第二个数据（加数）的内存起始单元，由于前一个数据占 8 个字（16 字节），初始偏移地址 $\text{DI} = 16$；
- 运算结果直接覆盖写回被加数（即 `DS:SI` 指向的空间）；
- 设置计数器 $\text{CX} = 8$，控制循环执行 8 次。

---

### [10:47] 128 位加法主程序与子程序实现

整个程序的代码框架如下：

```assembly
; 主程序调用框架
mov ax, data
mov ds, ax

mov si, 0        ; DS:SI 指向被加数起始地址
mov di, 16       ; DS:DI 指向加数起始地址
mov cx, 8        ; 循环 8 次（相加 8 个字单元）

call add128      ; 调用 128 位加法子程序

; 子程序定义
add128:
    push ax
    push cx
    push si
    push di

    sub ax, ax   ; 关键指令：将 CF 标志位清零

s:  mov ax, [si]
    adc ax, [di] ; 带进位相加
    mov [si], ax ; 结果写回内存
    inc si
    inc si       ; 字单元地址递增 2
    inc di
    inc di       ; 字单元地址递增 2
    loop s

    pop di
    pop si
    pop cx
    pop ax
    ret
```

---

### [13:20] 细节剖析一：为什么使用 SUB AX, AX 而不是 MOV AX, 0

在进入循环之前，执行了 `sub ax, ax`：
- 从数值上看，`sub ax, ax` 使得 $\text{AX} = 0$；
- 但随后的循环体首条指令即为 `mov ax, [si]`，$\text{AX}$ 的原值会被直接覆盖，因此清零 $\text{AX}$ 本身并无实际意义；
- **其真正目的是清除进位标志位**：因为任何数减去自身结果为 0，不会产生借位，所以 `sub ax, ax` 会将 $\text{CF}$ 强制清零（$\text{CF} = 0$）。

如果替换为 `mov ax, 0`，虽然也能清零寄存器，但 `MOV` 指令不改变标志寄存器的状态。若调用子程序前 $\text{CF} = 1$，首次执行 `adc ax, [di]` 时便会错误地多加 1。因此**绝不能替换为 `mov ax, 0`**。

---

### [14:27] 细节剖析二：为什么使用 INC 调整指针而不是 ADD

程序在移动内存指针时连续使用了两次 `inc si` 和两次 `inc di`：
- 从数值运算来看，两次 `INC` 与一次 `add si, 2` / `add di, 2` 都能使地址加 2；
- **但两者的标志位特性完全不同**：`INC` 指令在增加寄存器数值时**不影响进位标志位 $\text{CF}$**；
- 若改用 `add si, 2`，`ADD` 指令执行后会重新设置 $\text{CF}$ 标志位，直接冲掉前一步运算产生的进位结果，导致下一次循环中的 `ADC` 无法获取正确的进位状态。

因此，为了保护 $\text{CF}$ 不被指针移动破坏，**必须使用 `INC` 指令，不能替换为 `ADD`**。

### [15:40] 带借位减法指令 SBB 详解

与 `ADC` 相对应，带借位的减法指令是 `SBB`（Subtract with Borrow）。

其指令格式为：

```assembly
sbb 操作对象1, 操作对象2
```

执行的功能为：

$$\text{操作对象1} = \text{操作对象1} - \text{操作对象2} - \text{CF}$$

$\text{SBB}$ 与 `SUB` 的核心区别在于：它在减去操作对象 2 之后，还会减去借位标志位 $\text{CF}$ 的值。$\text{CF}$ 既可作为加法的进位标志，也可作为减法的借位标志。

---

### [16:29] SBB 应用示例：大数减法计算

使用 `SBB` 进行多字节大数减法运算时，遵循“低位用 `SUB`，高位用 `SBB`”的原则。

例如对两个 32 位数进行减法运算，结果保存在 $\text{AX}$（高位）和 $\text{BX}$（低位）：

```assembly
mov bx, 1000H    ; 被减数低 16 位
mov ax, 0031H    ; 被减数高 16 位

sub bx, 2000H    ; 低 16 位相减：1000H - 2000H 不够减，产生借位，CF = 1
sbb ax, 0020H    ; 高 16 位相减：AX - 0020H - CF，计入借位
```

执行过程：
1. 低 16 位相减时产生借位，$\text{CF}$ 被置为 1；
2. 高 16 位相减使用 `SBB`，自动从当前结果中减去借位值 1。

---

### [17:25] 总结

`ADC` 和 `SBB` 两个指令分别针对带进位的大数加法和带借位的大数减法设计。标志寄存器中的 $\text{CF}$ 标志位在这两类多精度运算中起到了连接高低字节的核心作用。
