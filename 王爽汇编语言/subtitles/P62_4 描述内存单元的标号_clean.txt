# 描述内存单元的标号

---

### [00:00] 标号的基本概念与传统用法

在这一节，我们介绍描述内存单元的标号。

关于标号，我们知道在代码段里边用标号可以去标示一些指令，包括段的起始地址。比如 `code`，我们可以看到它是一个段的起始地址；包括 `start` 等等；包括 `s` 是指令的起始地址。我们在用到的时候，比如说 `loop` 里边，就可以用 `s` 去把它转移过来，这是我们已经看过的用法。

---

### [00:27] 代码段中使用带冒号标号标记数据

其实在代码段里边，数据也是可以用标号标记的。比如说在代码段里定义数据，前面加一个 `a:`，定义数据前面加一个 `b:`：

```assembly
code segment
    a: db 1, 2, 3, 4, 5, 6, 7, 8
    b: dw 0
```

在有了 `a` 和 `b` 这样的标号以后，这里边可以用到 `offset` 操作符，求出 `a` 和 `b` 的偏移地址来。

随后我们可以看到，在编译好的程序里边：
- `offset a` 求得的是 `0`；
- `offset b` 求得的是 `8`。

这正好是这两段数据的起始地址，所以我们在用它时是很方便的。

然后我们看到，把 `a` 的偏移地址放到 `si` 里边，`b` 的偏移地址放到 `di` 里边。将来我们在用到 `si` 和 `di` 的时候，引用的就是我们现在要指定的这段空间。可以看到，指定 `cs` 用的是代码段里边的数据，然后把 `si`、`di` 分别用到这里边。所以这里边完成了用标号去指定地址的方式。

---

### [01:27] 数据标号的引入（去除冒号）及机器指令解析

在有了这样的手段以后，我们不禁要想再去简化一些。用 `offset a` 以及显式指明 `cs` 等等这些，觉得有点麻烦，我们有没有更简单的办法呢？方案是有的。

其实方案很简单：在刚才指定数据前面的标号时，把冒号去掉就行了。这里边不是 `a:`、`b:` 了，而是直接写成 `a`、`b`，这就是我们的改进：

```assembly
code segment
    a db 1, 2, 3, 4, 5, 6, 7, 8
    b dw 0
```

在有了这个改进以后，我们可以看一下它最后的编译效果。

在这块我们用到了 `a` 这样的标号：
- `a[si]` 会被解释为 `[si + 0000]`。从寻址方式上来讲，它就是一个相对变址寻址。为什么这么讲呢？`a` 在这里边其实就是一个地址值，`b` 也是一个地址值，所以在这里边是一个直接的地址寻址。因此我们可以看到，`mov al, a[si]` 编译后的机器指令就是 `mov al, [si + 0000]`。
- 指令 `add b, ax`（或 `add ax, b`），`b` 直接给出的就是它的偏移地址，是一个直接的地址值。

另外我们还可以看到，在这块并没有显式指定 `a` 和 `b` 是哪一段的，而在生成的机器指令里边，自动认为这里直接操作的内存单元是 `cs` 段的。

因此，像这样一种写法比刚才加冒号的写法要方便、简略得多。只要理解清楚了 `a` 和 `b` 的含义，就可以了。

### [03:11] 数据标号与地址标号的区别：地址与单元长度属性

我们在 `code` 段里边使用的标号 `a` 和 `b`，后边没有冒号。它在这个时候同时描述内存地址，并且能够标示是哪个段的。更为好的一点是，它同时还可以标示**单元长度**。而这个单元长度取决于后边定义的数据类型。

从定义上来讲：
1. 标号 `a` 后边定义的是 `db` 数据，它的起始地址是 `code:0`（在代码段里以 0 作为起始地址），后边的内存单元用到的时候都是**字节**。而单元类型是字节这一点，是不需要我们在指令里边再去显式指定的。
2. 标号 `b` 后边加上 `dw`，意味着它是这样一个起始地址，以后的内存单元都是**字**。

因此，在使用到 `a` 和 `b` 的时候，到底操作的是字节型还是字型，在这里边都已经明确指定了。

现在我们区分一下两种标号：
- **数据标号**：像 `a`、`b` 这种没有冒号的形式，我们把它叫**数据标号**。数据标号不仅标记了存储数据的单元地址，同时也标记了它的单元长度与段属性。
- **地址标号**：不同于仅仅表示地址的地址标号。像 `start:`、`s:` 等等后面带冒号的标号，是纯粹表示地址的**地址标号**，只能用于转移指令等寻址中。

### [04:46] 数据标号在指令中的应用与类型匹配

现在我们看该如何去使用数据标号。

已知 `b` 代表起始地址为 `code:8`、单元长度为字的内存单元。在代码里边使用时：

```assembly
mov ax, b
```
`b` 代表一个字单元，因此该指令相当于将 `cs` 段中偏移地址为 8 的字数据送入 `ax`（等价于 `mov ax, cs:[8]`）。

```assembly
mov b, 2
```
要把 2 移到 `b` 所代表的单元里边。因为 `b` 是字单元，所以相当于把 2 送入字单元中，等价于：
```assembly
mov word ptr cs:[8], 2
```
这里非常革命性的一点是：我们在写 `b` 的时候，根本不需要显式声明它是 `word`，也不需要把指令写得那么长（省略了 `word ptr`）。

接下来，对 `b` 所指向单元的值加 1：
```assembly
inc b
```
在指令中同样不用操心到底是字还是字节，它相当于在前面自动加上了 `word ptr`（即 `inc word ptr cs:[8]`）。

再看下面这条指令：
```assembly
mov al, b
```
`b` 代表的是字单元，而 `al` 是字节寄存器，两者的操作数类型不匹配，因此这条指令是错误的。编译器会自动帮我们把这个类型不匹配的错误检查出来。由此可见，数据标号描述内存地址的同时描述了内存单元长度，这是一个非常优良的特性。

---

### [06:13] 数据标号的不同寻址方式

对于 `a` 标号，因为使用的是 `db` 定义，起始偏移地址为 0，长度为字节：

```assembly
mov al, a[si]
```
这是类型匹配的。`a` 所代表的单元是字节，加上 `si` 变址偏移后，将对应字节单元的值送入 `al`（相当于 `mov al, cs:0[si]`），属于**相对变址寻址**。

```assembly
mov al, a[3]
```
`a` 是地址 0，3 是偏移量，整体相当于访问 `cs:[0 + 3]`，操作的依然是字节。

如果采用基址变址寻址方式：
```assembly
mov al, a[bx][si]
```
这属于**相对基址变址寻址**，包含基址、变址以及相对偏移量，等价于访问 `cs:0[bx][si]`。

给出数据标号之后，将来遇到代码时，既能判断它代表哪个内存地址，也能判断它操作的是字还是字节。

### [07:37] 在数据段中使用数据标号及段属性

刚才的例子中是把数据直接放在了代码段中。在编写大型程序时，数据最好专门放在独立的数据段（`data segment`）中，通过分段管理对程序来说更方便规范。

在进行分段管理时，在数据段中可以直接使用不带冒号的数据标号：

```assembly
data segment
    a db 1, 2, 3, 4, 5, 6, 7, 8
    b dw 0
data ends
```

在代码段中引用 `a` 和 `b`：
- 执行 `mov al, a[si]` 时，`a` 自动作为偏移地址，其默认段地址对应数据段 `ds`。
- 执行 `add b, ax`（或 `add ax, b`）时，`b` 自动作为字单元的偏移地址去寻址。

从程序可读性方面，程序员阅读代码时只需关注标号 `a` 和 `b`；而在编译时，编译器能够自动将实际的段地址与偏移地址对应翻译出来。这使得程序逻辑清晰，兼顾了人读代码的高效性与机器执行的准确性。

---

### [08:49] 地址标号与数据标号的使用范围对比

总结地址标号与数据标号的适用场景：
1. **地址标号**（带冒号，如 `s:`）：只能在代码段中使用，仅作为指令执行位置的标记。
2. **数据标号**（不带冒号，如 `a db ...`）：既可以在数据段中使用，也可以在代码段中使用，同时具备地址、段属性与长度属性。

### [09:11] 标号作为数据定义：字型定义与指针概念

数据标号还有一种常用的扩展方式：**将标号当做数据来定义**。

看第一个例子：
```assembly
data segment
    a db 1, 2, 3, 4, 5, 6, 7, 8
    b dw 0
    c dw a, b
data ends
```
在这个数据段里，定义了字节型的 `a`、字型的 `b`，紧接着定义了字型的 `c`。`c` 后边给出的初始数据是 `a, b`。也就是说，把前面定义的数据标号作为数据存入单元中。

这里的 `a, b` 代表什么呢？由于定义的是字（`dw`），此处 `a` 和 `b` 代表它们各自的**偏移地址**，因此该定义完全等价于：
```assembly
c dw offset a, offset b
```
在 `c` 处按字分别存储了 `a` 的偏移地址和 `b` 的偏移地址。

深入理解其程序设计意义：
`a` 和 `b` 标示的是两段数据的起始地址，用 C 语言术语来说，它们就是**指针**。而 `c` 里面保存的是指针变量 `a` 和 `b` 的地址，因此 `c` 是**关于指针的指针**（二级指针）。

有了 `c` 以后，我们就可以实现间接寻址访问：从 `c` 中取出相对偏移为 0 的单元内容（即 `a` 的地址），再通过该地址访问 `a` 所指向的数据块。这种间接访问方式，在编写复杂程序和实现特殊功能时会经常用到。

---

### [10:50] 标号作为数据定义：双字型定义与段地址（seg 操作符）

把标号当做数据来定义还有另外一种形式——双字型定义：

```assembly
data segment
    a db 1, 2, 3, 4, 5, 6, 7, 8
    b dw 0
    c dd a, b
data ends
```

这里 `c` 的定义使用的是 `dd`（Double Word，双字，占用 4 个字节）。这样定义后，它等价于：

```assembly
c dw offset a, seg a, offset b, seg b
```

`seg` 是一个专门用于**获取标号所在段地址**的操作符。

分析内存存储结构：
对于 `c dd a, b`，一共占用 $2 \times 4 = 8$ 个字节：
- 前 4 个字节（第一个双字）存储 `a` 的地址：低字（低 2 字节）存放 `a` 的偏移地址（`offset a`），高字（高 2 字节）存放 `a` 的段地址（`seg a`）。
- 后 4 个字节（第二个双字）存储 `b` 的地址：低字存放 `b` 的偏移地址（`offset b`），高字存放 `b` 的段地址（`seg b`）。

当使用双字（`dd`）存储标号时，不仅保存标号的偏移地址，而且保存标号的段地址，遵循“高位高地址、低位低地址”的存储规则构建完整远指针。这种形式在后续处理跨段调用及远指针传参时会非常关键。
