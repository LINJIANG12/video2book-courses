# 寻址方式在结构化数据访问中的应用

---

### [00:00] 案例背景：姚明数据变更需求
在这一节，我们介绍一个寻址方式的应用。这个应用跟这张青涩的姚明的照片是有关系的。

在 2001 年的时候，姚明的生日我们知道是 1980 年 9 月 12 日。他的球衣号码是 15 号，场均得分可以达到 32 分，当时他在国内的上海队效力。这是 2001 年的数据。

到 2002 年的时候，姚明的信息发生变化了：球衣号码变成了 11 号，场均得分是 13 分，因为他到了 NBA 休斯敦火箭队去打球了。这样的话，他的得分下去了。

---

### [00:36] 内存结构与任务分析
现在我们的任务不是研究姚明的技战术，而是要编程修改内存当中过时的数据。

我们可以看一下数据在内存当中的存储情况：它存储在一个数据段里边。在数据段偏移 `60H` 以后（十六进制数），开始存储姚明的信息：
* 姓名（存储了 3 个字节）
* 出生年月
* 球衣号码
* 场均得分
* 效力的球队

我们要把这些数据修改为 2002 年的状态，该如何去做？

---

### [01:15] 汇编语言实现：定位基址与修改数值字段
在修改这个数据的时候，关键在于只要把数据存储的位置确定了，再去修改就可以了。因此，我们可以写出对应的汇编代码。

首先，对于 `seg` 来说，这是在程序里设好的一个段。我们把段地址取出来放到 `DS` 里边，所以 `DS` 就作为我们的段地址。由于姚明的信息是从偏移量 `60H` 开始的，所以我们把 `60H` 放到基址寄存器 `BX` 中，作为一个基准位置。

接下来，要把球衣号码 15 修改为 11。修改的数据位置在段地址偏移 `60H`（已存入 `BX`）再加上 `0CH` 的地址处。

```assembly
mov ax, seg
mov ds, ax
mov bx, 60H

; 修改球衣号码：15 -> 11
mov word ptr [bx + 0CH], 11
```

[02:08]  
在修改的时候，执行 `mov` 操作将 11 传送到 `[bx + 0CH]` 当中。因为操作的是内存单元，需要指定内存单元占多大的空间，在这里我们指定它是一个字单元（`word ptr`）。因此这一块的 15 顺利变成了 11。可以看到，寻址时找准偏移量是非常重要的。

同理，将场均得分 32 改为 13 时，把 13 送到对应的偏移地址处，同样也是一个字单元空间：

```assembly
; 修改场均得分：32 -> 13
mov word ptr [bx + 0EH], 13
```

---

### [02:50] 汇编语言实现：修改字符串字段
随后看字符的修改。球队字符整体是从偏移 `10H` 开始的。修改 3 个字符时只能逐个修改，按照字节（`byte`）进行操作。

在这儿引入了寄存器 `SI`，通过 `SI` 控制我们要修改的位置：
1. 当 `SI` 为 0 时，指定 `[bx + 10H + si]`（改的是原队名首字符位置），将其修改为 `'H'`；
2. 将 `SI` 加 1 之后，修改第二个字符位置，将其改为 `'O'`；
3. `SI` 再加 1 之后，将其改为 `'U'`。

```assembly
mov si, 0
mov byte ptr [bx + 10H + si], 'H'
inc si
mov byte ptr [bx + 10H + si], 'O'
inc si
mov byte ptr [bx + 10H + si], 'U'
```

[03:48]  
有同学会问：直接写偏移量加 0、加 1 行不行？当然是可以的。但是如果修改的字符串很长、需要使用循环处理时，变址寄存器就是必须要考虑的了。

---

### [04:04] 寻址方式总结与等价语法
在这个程序中，我们用到了以下几种寻址方式：

1. **相对寄存器寻址**：`[bx + idata]`  
   基址寄存器加上立即数，例如修改号码与得分时使用的寻址。
2. **相对基址变址寻址**：`[bx + idata + si]`  
   基址寄存器加上立即数，再加上变址寄存器。

这种相对基址变址寻址在语法上还有一种等价写法，大家一定要看顺眼：

$$[bx + idata + si] \iff [bx].idata[si]$$

我们可以把立即数通过点（`.`）的形式写在外面，这两种形式是完全等价的。

### [05:01] 与高级语言（C 语言）的类比分析
这种写法的背后，可以与高级语言写的程序进行类比。如果要完成刚才由 2001 年数据修改为 2002 年数据，用 C 语言写的话，大概是这个样子的：

```c
struct player {
    char name[3];
    char birth[9];
    int number;
    int ppg;
    char team[3];
};

struct player yao;

// 初始化 2001 年数据
// yao: "Yao", "19800912", 15, 32, "SH"

// 修改为 2002 年数据
yao.number = 11;
yao.ppg = 13;

i = 0;
yao.team[i] = 'H';
i++;
yao.team[i] = 'O';
i++;
yao.team[i] = 'U';
```

[06:26]  
将 C 语言程序与前面写出的汇编语言程序进行对比，它们在本质上是完全一致的。我们以 `yao.team[i]` 为例进行映射分析：

| 概念/元素 | C 语言表达 | 8086 汇编表达 | 作用与含义 |
| :--- | :--- | :--- | :--- |
| **结构体起始地址** | `yao` | `bx` (基址寄存器) | 指明整个结构体变量在内存中的基地址（偏移地址 `60H`） |
| **成员项偏移地址** | `.team` | `.10H` (`idata`) | 指明结构体内部成员数组的起始偏移位置 |
| **数组元素下标** | `[i]` | `[si]` (变址寄存器) | 用于索引数组中的具体元素，通过自增实现遍历修改 |

[07:33]  
* `yao` 是变量名，代表整个结构体的起始地址；在汇编中对应的就是 `bx`，指向结构体数据存储的基础地址（基址）。
* `team` 是结构体内部数组的名称，指明了该项数据的起始地址；在汇编中对应的就是常量偏移量 `10H`（即 `idata`）。
* `i` 是数组索引；在汇编中对应的就是变址寄存器 `SI`。随着 `SI` 递增，依次访问并修改了 `'H'`、`'O'`、`'U'` 所在的内存单元。

### [08:41] 总结
[09:18]  
通过这个微课案例，我们看到汇编语言完全能够优雅地操作结构性数据。处理结构化数据并不像想象中那么复杂，只要搞清楚数据结构以及各字段的偏移地址如何表示，一切迎刃而解。

汇编语言提供的诸如 `[bx].idata[si]` 这类寻址方式，其设计的核心目标恰恰就是为了在底层解决结构化数据与数组元素的访问问题。希望大家深刻理解寻址方式的作用，放下心理包袱，用汇编语言处理这类任务同样是非常在行的。
