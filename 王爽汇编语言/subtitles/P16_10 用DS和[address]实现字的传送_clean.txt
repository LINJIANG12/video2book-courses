# 8086 汇编语言：基于 DS 与内存单元地址的数据访问及 Debug 验证

---

### [00:00] 内存寻址机制与 DS 寄存器的引入

在本节中，我们介绍一种定位内存中数据位置的方法：使用段寄存器 **DS** 和一个直接的地址值来进行定位。

首先明确要解决的问题：让 CPU 从内存单元中读取数据。在读取数据时，必须先给出目标内存单元的地址。在 8086 PC 中，内存地址是由**段地址**和**偏移地址**两部分组成的。因此，我们必须分别提供指定段地址和偏移地址的方法。

目前的解决方案是：
* **段地址**：保存在 **DS**（Data Segment，数据段寄存器）中。
* **偏移地址**：采用 `[...]`（方括号内加上偏移地址/数值）的形式直接给出。

通过 DS 与 `[address]` 的配合，DS 寄存器存放要访问数据的段地址，偏移地址则直接写在方括号内。

---

### [01:05] 示例一：从内存单元读取字节数据到寄存器

```assembly
mov ax, 1000H
mov ds, ax
mov al, [0]
```

分析该例的核心执行流程：
1. **段地址设定**：首先 DS 取得的值是 $1000\text{H}$，即段地址为 $1000\text{H}$。
2. **默认段地址关联**：只要使用 `[...]` 这种形式给出内存单元地址，其默认对应的段地址**必定保存在 DS 寄存器中**。
   > **注意**：从 `mov al, [0]` 这条指令的形式上看，表面上看不到任何 DS 的影子，但由 8086 硬件电路设计与汇编语言规范决定，该寻址方式的段地址默认就是 DS。
3. **物理地址合成与读取**：
   $$\text{物理地址} = \text{段地址} \times 16 + \text{偏移地址} = 1000\text{H} \times 10\text{H} + 0\text{H} = 10000\text{H}$$
   该指令将物理地址 $10000\text{H}$ 处的数据读入到通用寄存器 `AL` 中。由于 `AL` 是一个 8 位寄存器，因此本指令执行的是**字节型数据**的传送，只读取 1 个字节。

---

### [02:26] 示例二：将寄存器数据写入内存单元

```assembly
mov bx, 1000H
mov ds, bx
mov [0], al
```

1. 将立即数 $1000\text{H}$ 送入通用寄存器 `BX`，再将 `BX` 的值传入 `DS`，使 `DS` 赋值为 $1000\text{H}$。
2. 执行 `mov [0], al`：方括号内的 `0` 代表偏移地址，其对应的段地址仍在 `DS` 中，合成的物理单元地址为 $10000\text{H}$。
3. 该操作将 `AL` 中的数据传送并写入到物理地址 $10000\text{H}$ 的内存单元中。同样，因为 `AL` 为 8 位寄存器，此处操作的是单字节数据。

---

### [03:08] 规范与禁忌：段寄存器赋值规则

在执行内存访问前，必须将段地址送入 DS。关于向段寄存器传送数据：

* **方式一（非法/错误）**：
  ```assembly
  mov ds, 1000H   ; 错误！8086 电路设计不支持立即数直接送入段寄存器
  ```
* **方式二（合法/正确）**：
  ```assembly
  mov ax, 1000H
  mov ds, ax      ; 正确！通过通用寄存器进行中转
  ```

**核心规则**：8086 CPU 的硬件指令系统**不支持将数据直接送入段寄存器**。如果需要为段寄存器（如 DS）赋值，必须先将数据放入一个通用寄存器（如 AX、BX 等），再从通用寄存器转存到段寄存器中。

### [04:25] 字型数据的内存传送（16位操作）

8086 CPU 既可以一次传送一个字节（8 位），也可以一次性传送一个**字**（16 位数据）。字单元的传输更能发挥 8086 16 位架构的性能特长。

```assembly
mov bx, 1000H
mov ds, bx
mov ax, [0]
mov [0], cx
```

1. 将段地址 $1000\text{H}$ 经通用寄存器 `BX` 送入 `DS`。
2. `mov ax, [0]`：由于目的操作数是 16 位寄存器 `AX`，系统将从物理地址 $10000\text{H}$ 起始处连续读取**两个字节**的字型数据放入 `AX` 中。
3. `mov [0], cx`：`CX` 同样是 16 位寄存器，该指令将 `CX` 中的 16 位数据写入以物理地址 $10000\text{H}$ 开始的两个连续内存单元中。

由此可见，寄存器与内存之间的数据传输是双向支持的：既可将 CPU 内部寄存器的数据写入内存，也可将内存单元中的数据读出到寄存器。

### [06:08] 案例分析：连续内存访问与算术运算追踪

假设在内存段地址为 $1000\text{H}$ 的区域已预置如下数据：

| 物理地址 | 对应偏移量 | 存放数据（字节） |
| :--- | :--- | :--- |
| $10000\text{H}$ | `[0]` | $23\text{H}$ |
| $10001\text{H}$ | `[1]` | $11\text{H}$ |
| $10002\text{H}$ | `[2]` | $22\text{H}$ |
| $10003\text{H}$ | `[3]` | $66\text{H}$ |

> **提示（小端序存放规则）**：
> * 偏移地址 `0` 处的字型数据（低字节在低地址，高字节在高地址）：低字节为 $23\text{H}$，高字节为 $11\text{H}$，组合成的 16 位字数据为 **$1123\text{H}$**。
> * 偏移地址 `1` 处的字型数据：低字节为 $11\text{H}$，高字节为 $22\text{H}$，组合成的 16 位字数据为 **$2211\text{H}$**。
> * 偏移地址 `2` 处的字型数据：低字节为 $22\text{H}$，高字节为 $66\text{H}$，组合成的 16 位字数据为 **$6622\text{H}$**。

#### 代码执行分步推演

```assembly
mov ax, 1000H
mov ds, ax
mov ax, [0]      ; AX = 1123H
mov bx, [2]      ; BX = 6622H
mov cx, [1]      ; CX = 2211H
add bx, [1]      ; BX = BX + [1] = 6622H + 2211H = 8833H
add [2], cx      ; 内存字单元[2] = [2] + CX = 6622H + 2211H = 8833H
```

* `mov ax, [0]`：读取偏移地址 `0` 处的字数据，$10000\text{H}$ 存储 $23\text{H}$，$10001\text{H}$ 存储 $11\text{H}$，故 `AX = 1123H`。
* `mov bx, [2]`：读取偏移地址 `2` 处的字数据，包含 $10002\text{H}$ 的 $22\text{H}$ 和 $10003\text{H}$ 的 $66\text{H}$，故 `BX = 6622H`。
* `mov cx, [1]`：读取偏移地址 `1` 处的字数据，包含 $10001\text{H}$ 的 $11\text{H}$ 和 $10002\text{H}$ 的 $22\text{H}$，故 `CX = 2211H`。
* `add bx, [1]`：将 `BX` 的值（$6622\text{H}$）与偏移地址 `1` 处的字数据（$2211\text{H}$）相加，结果为 **$8833\text{H}$**，存入 `BX`。
* `add [2], cx`：将偏移地址 `2` 处的字数据（$6622\text{H}$）与 `CX` 的值（$2211\text{H}$）相加，结果为 **$8833\text{H}$**，写回偏移地址为 `2` 的内存字单元。

### [09:10] 使用 Debug 进行环境配置与内存预置

在实际学习中，不仅要人工推演，还要借助 Debug 工具进行上机可视化验证。

#### 1. 预置内存数据（E 命令）
在 `1000:0` 起始单元写入预设字节：
```dos
-e 1000:0 23 11 22 66
```

#### 2. 查看内存验证写入（D 命令）
```dos
-d 1000:0 3
```
输出显示字节序列为 `23 11 22 66`，按字（Word）读取即对应 $1123\text{H}$ 和 $6622\text{H}$。

### [10:15] 在 Debug 中输入汇编指令（A 命令）

首先用 `R` 命令观察当前寄存器状态，若当前 `CS:IP` 为 `073F:0100`（或默认位置），直接使用 `A` 命令在当前位置汇编指令：

```dos
-a
mov ax, 1000
mov ds, ax
mov ax, [0]
mov bx, [2]
mov cx, [1]
add bx, [1]
add [2], cx

```

---

### [11:39] 单步跟踪与执行验证（T 命令）

通过单步执行 `T` 命令逐条观察寄存器和内存的变化：

1. **执行 `mov ax, 1000`**：
   单步跟踪后，`AX` 的值变为 `1000`。
2. **执行 `mov ds, ax`**：
   单步跟踪后，`DS` 的值被成功设置为 `1000`。
3. **执行 `mov ax, [0]`**：
   从物理地址 $10000\text{H}$ 读取字型数据，`AX` 变为 `1123`，与人工推导一致。
4. **执行 `mov bx, [2]`**：
   从物理地址 $10002\text{H}$ 读取字型数据，`BX` 变为 `6622`。
5. **执行 `mov cx, [1]`**：
   从物理地址 $10001\text{H}$ 读取字型数据，`CX` 变为 `2211`。
6. **执行 `add bx, [1]`**：
   `BX` 与 `[1]`（$2211\text{H}$）相加，`BX` 寄存器的值更新为 `8833`。
7. **执行 `add [2], cx`**：
   内存字单元 `[2]` 与 `CX` 相加，该单元数据更新为 `8833`。
