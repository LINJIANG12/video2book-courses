在这一节中，我们介绍代码的直接定址表。对于直接定址表解决问题的思路，是用查表的方式通过依据的数据，直接计算出所要找的元素的位置。这种方法有很多优点。直接定址表分为数据的直接定址表以及代码的直接定址表。在这一节我们介绍的是代码的直接定址表。

我们通过一个具体的示例来讲解。在这个问题中，要实现一个子程序 setscreen，为程序提供以下功能：
0 号功能：清屏；
1 号功能：设置前景色；
2 号功能：设置背景色；
3 号功能：向上滚屏一行。

对这些功能的实现，我们会把这四个功能写成四个子程序：sub1、sub2、sub3、sub4。
在写成四个子程序后，我们要调用这些子程序。传统的方法是在获得子程序功能号后，通过一系列的条件判断跳转决定调用哪一个。而现在，我们希望把这些功能子程序的入口地址保存在一个表（直接定址表）中，让它们在表中的位置与功能号严格对应。
因为每个子程序的偏移地址占用一个字（2 个字节），所以只要给定功能号（0、1、2、3），将功能号乘以 2，就可以直接得到对应子程序入口在地址表中的偏移地址！

参数传递规范：
- AH：传递功能号（0、1、2、3）；
- AL：传递颜色属性值（针对 1 号和 2 号功能）。

四个子程序的实现机理：
1. sub1 清屏功能（AH = 0）：
   显存地址段基址为 B800H，整个屏幕一共 25 行 80 列，共 2000 个字符。循环 2000 次，向每个字符单元写入 ASCII 空格符（20H），清空屏幕显示。
2. sub2 设置前景色（AH = 1）：
   AL 传递前景色（低 3 位）。遍历 2000 个字符的属性字节（高字节），将属性字节的低 3 位清零，然后与 AL 做 OR 逻辑运算，设置前景色。
3. sub3 设置背景色（AH = 2）：
   AL 传递背景色。将 AL 中的颜色值左移 4 位（对齐到属性字节的第 4、5、6 位），将属性字节的 4~6 位清零后做 OR 运算，设置背景色。
4. sub4 向上滚屏一行（AH = 3）：
   将第 n+1 行的内容复制到第 n 行，共复制 24 行。使用串传送指令 movsb/movsw，源指针 DS:SI 指向第 1 行（偏移 160），目的指针 ES:DI 指向第 0 行（偏移 0），循环 24 次，每次复制一行 160 字节。最后将最后一行（第 24 行）用空格清空。

代码直接定址表的核心结构与调用：
```assembly
setscreen:
    jmp short set
    table dw sub1, sub2, sub3, sub4
set:
    push bx
    cmp ah, 3
    ja sret              ; 功能号 > 3 则越界保护退出
    mov bl, ah
    mov bh, 0
    add bx, bx          ; 功能号 * 2 得到 table 中的字偏移
    call word ptr table[bx]  ; 直接通过定址表调用目标子程序！
sret:
    pop bx
    ret
```

直接定址表的工程优势：
1. 结构极度清晰，避免了海量丑陋繁杂的 cmp / je 分支链条；
2. 可扩展性极佳：当未来需要增加功能 4、功能 5 时，只需增加 sub5、sub6，并在 table 中追加其标号即可，主调度逻辑无需改动一行代码。
